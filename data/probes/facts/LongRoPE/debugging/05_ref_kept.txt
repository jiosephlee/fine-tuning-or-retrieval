----- Row 3 -----
raw_knowledge_statement: Transformer models require explicit positional information, often in the form of position embedding, to represent the order of input tokens.

----- Row 3 -----
raw_knowledge_statement: Our work focuses on the RoPE~\cite{rope} position embedding, which is widely used in recent  LLMs.

----- Row 3 -----
raw_knowledge_statement: For a token at position index $n$, its corresponding RoPE encoding can be simplified as follows:

\begin{equation}
		\fontsize{7.8}{7.8} \selectfont
	\label{eq:rope}
	\left[ cos(n\theta_0), sin(n\theta_0), cos(n\theta_1), \cdot\cdot\cdot, cos(n\theta_{d/2-1}), sin(n\theta_{d/2-1}) \right]   
\end{equation}

where $d$ is the embedding dimension, 
 $n\theta_i$ is the rotary angle of token at position $n$, 
$\theta_i=\theta^{-2i/d}$ represents the rotation frequencies.

----- Row 3 -----
raw_knowledge_statement: In RoPE, the default base value of $\theta$ is 10000.

----- Row 3 -----
raw_knowledge_statement: \textbf{\emph{Context window extension ratio $s$} and positional interpolation}.

----- Row 3 -----
raw_knowledge_statement: We define $s$ as  the ratio of extended context length $L'$ to the original length $L$: $s=\frac{L'}{L}$.

----- Row 3 -----
raw_knowledge_statement: To extend the context window from $L$ to $L'$, current positional interpolation methods suggest downscaling rotation frequencies $\theta_i$ based on extension ratio $s$.

----- Row 3 -----
raw_knowledge_statement: Let $\beta=\theta^{2/d}$, and $\lambda$ denote the actual rescale factor related to $s$, we   unify these positional interpolation methods as follows:

\begin{equation}	
	\fontsize{7.5}{7.5} \selectfont
	\label{eq:unified_rope}
	\begin{aligned}
		\left[cos\left(\frac{n}{\lambda(\beta)^0}\right), sin \left(\frac{n}{\lambda(\beta)^0}\right), cos\left(\frac{n}{\lambda(\beta)^1}\right), \cdot\cdot\cdot,  sin \left(\frac{n}{\lambda(\beta)^{d/2-1}}\right) \right]   
	\end{aligned}
\end{equation}

----- Row 3 -----
raw_knowledge_statement: \textbf{Linear positional interpolation (PI)}.

----- Row 3 -----
raw_knowledge_statement: PI~\cite{pi}  suggests linear interpolation of position indices within the pre-trained length limit.

----- Row 3 -----
raw_knowledge_statement: For a target extension ratio $s$, the rotation angles of all positions are linearly reduced by $\lambda=s$  across all RoPE dimensions.

----- Row 3 -----
raw_knowledge_statement: However, this makes the position information very ``crowded", hindering the model's ability distinguish closely positioned tokens.

----- Row 3 -----
raw_knowledge_statement: Therefore, PI tends to underperform at high extension ratios.

----- Row 3 -----
raw_knowledge_statement: \textbf{NTK-based interpolation and extrapolation}.

----- Row 3 -----
raw_knowledge_statement: ~\cite{ntk,dynamicntk} look at RoPE from an information encoding perspective  and apply the Neural Tangent Kernel (NTK) theory~\cite{jacot2018neural,tancik2020fourier}.

----- Row 3 -----
raw_knowledge_statement: To mitigate the crowded-positions issue in PI, they suggest to distribute interpolation pressure across RoPE dimensions.

----- Row 3 -----
raw_knowledge_statement: It scales lower (high frequency) dimensions less and higher (low frequency) dimensions more, resulting in  both positional interpolation and extrapolation, where $\lambda=s^{i}$.

----- Row 3 -----
raw_knowledge_statement: The improved dynamic NTK~\cite{dynamicntk}  adjusts the extension ratio at each position based on the current sequence length.

----- Row 3 -----
raw_knowledge_statement: Unlike PI, which necessitates fine-tuning, NTK-aware methods can extend context windows in non-fine-tuning scenarios, but usually with a maximum extension ratio of 4$\times$.

----- Row 3 -----
raw_knowledge_statement: \textbf{YaRN}~\cite{yarn} introduces a significant improvement to positional interpolation performance.

----- Row 3 -----
raw_knowledge_statement: It divides RoPE dimensions into three frequency-based groups, each with a different interpolation strategy.

----- Row 3 -----
raw_knowledge_statement: High frequency dimensions undergo extrapolation ($\lambda$=1), while low frequency dimensions use linear interpolation (PI).

----- Row 3 -----
raw_knowledge_statement: The RoPE dimensions that fall in-between employs the NTK.

----- Row 3 -----
raw_knowledge_statement: The key of YaRN lies in its grouping of RoPE dimensions, which currently depends on human-led empirical experiments.

----- Row 3 -----
raw_knowledge_statement: This may result in sub-optimal performance for new LLMs.

----- Row 4 -----
raw_knowledge_statement: Inspired by NTK and YaRN, we notice their gains from non-linearity, specifically in considering different frequencies across RoPE dimensions for specialized interpolation and extrapolation.

----- Row 4 -----
raw_knowledge_statement: However, current non-linearities heavily rely on human-designed rules.

----- Row 4 -----
raw_knowledge_statement: This naturally raises two questions: (1) Is the current positional interpolation optimal? (2) Are there unexplored  non-linearities?

----- Row 4 -----
raw_knowledge_statement: The search is guided by perplexity, using 5 random samples from PG19~\cite{pg19} validation set.

----- Row 4 -----
raw_knowledge_statement: Through our empirical analysis, we reveal the following key findings.

raw_knowledge_statement: \textbf{Finding 1}: \textit{RoPE dimensions exhibit substantial non-uniformities, which are not effectively handled by current positional interpolation methods.}

----- Row 4 -----
raw_knowledge_statement: Our searched solution shows significant improvements, suggesting that current linear (PI) and non-uniform (Dynamic-NTK and YaRN) interpolations are sub-optimal.

----- Row 4 -----
raw_knowledge_statement: Notably, YaRN underperforms  than PI and NTK on PG19, as it doesn't reach the target context window length for non-fine-tuned LLM.

----- Row 4 -----
raw_knowledge_statement: For example, YaRN's perplexity spikes after 7k in an 8k context size.

----- Row 4 -----
raw_knowledge_statement: While we've shown that our searched non-uniform position interpolation significantly improves the extension performance at 8k and 16k without fine-tuning, longer extensions require fine-tuning.

----- Row 7 -----

----- Row 7 -----
raw_knowledge_statement: \textit{Optimized initial population generation}.

----- Row 7 -----
raw_knowledge_statement: Instead of initializing a population  of $P$ rescale factors randomly, we add the three RoPE rescale factors corresponding to PI, NTK, and YaRN as individuals into the initial population.

----- Row 7 -----
raw_knowledge_statement: For the remaining $P$-3 individuals, we randomly mutate the three rescale factors with a probability of $p$.

----- Row 7 -----
raw_knowledge_statement: \textit{Monotonically non-decreasing constraint}.

----- Row 7 -----
raw_knowledge_statement: After generating the initial population, we compute LLM perplexity for each individual.

----- Row 7 -----
raw_knowledge_statement: Specifically, we apply the corresponding RoPE rescale factors to the target LLM and compute the perplexity of  input $\mathbf{X}$.

----- Row 7 -----
raw_knowledge_statement: The top-k individuals become parents for evolution.

----- Row 7 -----
raw_knowledge_statement: However, the vast search space can cause naive mutation and crossover to explore poor solutions, leading to unnecessary perplexity computations.

----- Row 7 -----
raw_knowledge_statement: This is particularly inefficient when $L'$ is large, given the time-consuming inference  of each perplexity calculation.

----- Row 7 -----
raw_knowledge_statement: To address this, we impose a non-decreasing monotonicity constraint on the sampled RoPE rescaled factors: $\lambda_i\le \lambda_{i+1}$.

----- Row 7 -----
raw_knowledge_statement: Only RoPE that satisfies this constraint is applied to LLM for perplexity evaluation, significantly reducing the search costs.

----- Row 7 -----
raw_knowledge_statement: Specifically,   we require that $\lambda_i$ increases monotonically with the RoPE dimension (i.e., $i$=0,...,63).

----- Row 7 -----
raw_knowledge_statement: This dimensional monotonicity is based on the NTK theory~\cite{jacot2018neural,tancik2020fourier,ntk}, suggesting that lower dimensions with higher frequency requires less interpolation (i.e., a smaller $\lambda_i$), and higher dimensions with lower frequency can do more interpolation (i.e.,  a larger $\lambda_i$).

raw_knowledge_statement: Empirically, we allow $\hat{n}$ to search from \{0, 1, 2, 4, 8, 12, 16, 20, 24, 28, 32, 64, 128, 256\}.

----- Row 11 -----
raw_knowledge_statement: When $\hat{n}=0$, all token positions use the searched rescale factors.

----- Row 11 -----
raw_knowledge_statement: \textbf{Evolution-based search}.

----- Row 11 -----
raw_knowledge_statement: For example, a $s=4\times$ extension leads to  $400^{128/2}\times14$=4$\times10^{167}$ choices.

----- Row 11 -----
raw_knowledge_statement: With larger extension ratio,  the search space  expands exponentially.

----- Row 11 -----
raw_knowledge_statement: To address this, we use evolution search~\cite{guo2020single}  and introduce  two optimization techniques to greatly boost search efficiency.

----- Row 11 -----
raw_knowledge_statement: Algorithm~\ref{alg:search} illustrates the overall search procedure.

----- Row 11 -----
raw_knowledge_statement: \textit{Optimized initial population generation}.

----- Row 11 -----
raw_knowledge_statement: Instead of initializing a population  of $P$ rescale factors randomly, we add the three RoPE rescale factors corresponding to PI, NTK, and YaRN as individuals into the initial population.

----- Row 11 -----
raw_knowledge_statement: For the remaining $P$-3 individuals, we randomly mutate the three rescale factors with a probability of $p$.

----- Row 11 -----
raw_knowledge_statement: \textit{Monotonically non-decreasing constraint}.

----- Row 11 -----
raw_knowledge_statement: After generating the initial population, we compute LLM perplexity for each individual.

----- Row 11 -----
raw_knowledge_statement: Specifically, we apply the corresponding RoPE rescale factors to the target LLM and compute the perplexity of  input $\mathbf{X}$.

----- Row 11 -----
raw_knowledge_statement: The top-k individuals become parents for evolution.

----- Row 11 -----
raw_knowledge_statement: However, the vast search space can cause naive mutation and crossover to explore poor solutions, leading to unnecessary perplexity computations.

----- Row 11 -----
raw_knowledge_statement: This is particularly inefficient when $L'$ is large, given the time-consuming inference  of each perplexity calculation.

----- Row 11 -----
raw_knowledge_statement: To address this, we impose a non-decreasing monotonicity constraint on the sampled RoPE rescaled factors: $\lambda_i\le \lambda_{i+1}$.

----- Row 11 -----
raw_knowledge_statement: Only RoPE that satisfies this constraint is applied to LLM for perplexity evaluation, significantly reducing the search costs.

----- Row 11 -----
raw_knowledge_statement: Specifically,   we require that $\lambda_i$ increases monotonically with the RoPE dimension (i.e., $i$=0,...,63).

----- Row 11 -----
raw_knowledge_statement: This dimensional monotonicity is based on the NTK theory~\cite{jacot2018neural,tancik2020fourier,ntk}, suggesting that lower dimensions with higher frequency requires less interpolation (i.e., a smaller $\lambda_i$), and higher dimensions with lower frequency can do more interpolation (i.e.,  a larger $\lambda_i$).

----- Row 11 -----
raw_knowledge_statement: \textbf{8$\times$ extension without fine-tuning}.

----- Row 11 -----
raw_knowledge_statement: Our evolutionary search  effectively identifies non-uniform RoPE rescale factors, preserving key dimensions and positions to minimize interpolation-induced information loss.

----- Row 11 -----
raw_knowledge_statement: In contrast, existing methods such as PI, and non-uniform NTK and YaRN cause perplexity to spike after 2$\times$ extension.

----- Row 12 -----
raw_knowledge_statement: \textbf{Progressive extension to 2048k}.

----- Row 12 -----
raw_knowledge_statement: We now introduce our method  to extend the context window of pre-trained LLMs from the traditional 4k to over 2048k.

----- Row 12 -----
raw_knowledge_statement: As demonstrated, our non-uniform positional interpolation can achieve 8$\times$ extension without fine-tuning.

----- Row 12 -----
raw_knowledge_statement: For larger extensions (i.e., 512$\times$) is required, fine-tuning is necessary.

----- Row 12 -----
raw_knowledge_statement: One method is to search for RoPE rescaled factors under the target 2048k size and then fine-tune.

----- Row 12 -----
raw_knowledge_statement: However, this faces challenges due to the prohibitively expensive training resources.

----- Row 12 -----
raw_knowledge_statement: Moreover,  based on our experiences, it's challenging to well fine-tune the LLMs under a  large extension ratio (see Appendix).

----- Row 12 -----
raw_knowledge_statement: Fortunately, LongRoPE is effective for both the original and fine-tuned extended LLM.

----- Row 12 -----
raw_knowledge_statement: Therefore, we introduce an efficient, progressive method that achieves the target 2048k with just 1k fine-tuning steps at within 256k training length.

----- Row 12 -----
raw_knowledge_statement: $\Diamond$ \textit{Extending pre-trained LLM to 256k with LongRoPE search}.

----- Row 12 -----
raw_knowledge_statement: Taking LLaMA2 as an example, we conduct search for target context window size of 128k and 256k.

----- Row 12 -----
raw_knowledge_statement: The extension ratio at this stage is 32$\times$ and 64$\times$, respectively.

----- Row 12 -----
raw_knowledge_statement: $\Diamond$ \textit{Fine-tuning to 256k}.

----- Row 12 -----
raw_knowledge_statement: Then, we fine-tune the pre-trained LLM to achieve the context window size of 256k.

----- Row 12 -----
raw_knowledge_statement: Specifically, we first fine-tune LLaMA2 for 400 steps using the RoPE rescaled factors for 128k.

----- Row 12 -----
raw_knowledge_statement: Then, we replace the RoPE rescaled factors to 256k on the finished checkpoint and conduct an additional 600 steps of fine-tuning.

----- Row 12 -----
raw_knowledge_statement: This method proves more efficient than directly fine-tuning to 256k.

----- Row 12 -----
raw_knowledge_statement: $\Diamond$ \textit{Extending fine-tuned extended LLM to 2048k with LongRoPE search}.

----- Row 12 -----
raw_knowledge_statement: Finally, we perform a secondary  search on the fine-tuned 256k-length LLM.

----- Row 12 -----
raw_knowledge_statement: This ultimately results in an extremely large context window size of 2048k without further fine-tuning.

----- Row 12 -----
raw_knowledge_statement: The final extension ratio is  $512\times$.

----- Row 12 -----
raw_knowledge_statement: \textbf{Shorter context window recovery}.

----- Row 12 -----
raw_knowledge_statement: After extending to an extremely long 2048k context window, we notice a performance drop within the original context window.

----- Row 12 -----
raw_knowledge_statement: This is a known issue of positional interpolation~\cite{pi}, as it forces position embedding in higher dimensions within the original context window to reside in a much narrower region, negatively affecting the language model's performance.

----- Row 12 -----
raw_knowledge_statement: With a 512$\times$ extension ratio, positions within the original 4k context window become particularly crowded.

----- Row 12 -----
raw_knowledge_statement: To mitigate this, we perform an extra evolution search on the extended LLM to adjust RoPE rescale factors for short context lengths (e.g., 4k and 8k).

----- Row 12 -----
raw_knowledge_statement: We reduce the maximum allowed searched $\lambda$ due to less positional interpolation required for shorter lengths.

----- Row 12 -----
raw_knowledge_statement: During inference, the LLM dynamically adjusts the corresponding RoPE rescale factors.

## Chapter 3: Foundations of Probabilistic Modelling

### Introduction

In our study of machine learning thus far, we have often treated model outputs as deterministic predictions. A linear regression model, for instance, outputs a single value for a given input. However, the world is rarely so certain. Uncertainty is inherent in data due to measurement noise, and in processes due to their stochastic nature. A powerful approach to machine learning is to not just make predictions, but to quantify the uncertainty associated with those predictions. This is the domain of **probabilistic modelling**.

By framing machine learning problems in the language of probability, we gain a principled framework for model design, parameter estimation, and interpretation. Instead of predicting a single output `y` for an input `x`, we will learn a full probability distribution, `p(y|x)`. This distribution tells us not only the most likely outcome, but the entire range of possibilities and their relative likelihoods.

This chapter lays the groundwork for this probabilistic perspective. We will begin with the fundamental building block—the random variable—and explore how its expectation connects directly to the loss functions we aim to minimise. We will then see how complex systems can be decomposed using conditional probability, a technique that powers modern generative models. Finally, we will introduce a cornerstone of probabilistic classification, the logistic model, and tie it all together with the powerful and ubiquitous principle of Maximum Likelihood Estimation (MLE).

### 3.1 Random Variables and Expectations: The Language of Uncertainty

At the heart of probability theory is the concept of a **random variable**. While the name might suggest something that is itself random, it is more formally a mapping.

**Definition 3.1: Random Variable**
A **random variable** `X` is a function that maps outcomes from a sample space Ω to a set of real numbers.

For example, in the experiment of flipping a coin, the sample space is Ω = {Heads, Tails}. We can define a random variable `X` such that `X(Heads) = 1` and `X(Tails) = 0`. This variable `X` now allows us to mathematically analyse the outcomes of the coin flip. Random variables can be **discrete**, like our coin flip example or the count of events from a Poisson distribution, or **continuous**, like the height of a person drawn from a Normal distribution.

#### 3.1.1 Expectation

Once we have a random variable, we often want to summarise its behaviour. The most common summary is its **expectation**, which represents the long-run average value of the random variable if we were to repeat the experiment many times.

**Definition 3.2: Expectation**
The **expectation** (or expected value) of a discrete random variable `X` is given by:
$$ \mathbb{E}[X] = \sum_{x} x \cdot P(X=x) $$
For a continuous random variable `X` with probability density function `p(x)`:
$$ \mathbb{E}[X] = \int_{-\infty}^{\infty} x \cdot p(x) \,dx $$
The expectation is a linear operator, meaning $\mathbb{E}[aX + bY] = a\mathbb{E}[X] + b\mathbb{E}[Y]$.

A crucial extension is the **conditional expectation**, $\mathbb{E}[Y | X=x]$, which is the expected value of a random variable `Y` *given* that we have observed another random variable `X` to have the value `x`. For instance, we might be interested in the expected salary of a person (`Y`) given that their years of experience (`X`) is 10.

#### 3.1.2 From Expectation to Loss Functions

How does this connect to machine learning? In supervised learning, we are given a dataset of `(x, y)` pairs. We can think of this dataset as a sample from an unknown true data distribution, `p_{data}(x, y)`. Our goal is to learn a model, which we will denote `p_{model}(y|x; \theta)`, parameterized by `\theta`.

A common way to train this model is to define a **loss function** `L(y_{true}, y_{pred})` that measures the discrepancy between a true label and a prediction. The overall training objective is to find the parameters `\theta` that minimise the average loss over our training data. This average is an empirical estimate of an expectation:

$$ \hat{\theta} = \arg\min_{\theta} \frac{1}{N} \sum_{i=1}^{N} L(y_i, f(x_i; \theta)) \approx \arg\min_{\theta} \mathbb{E}_{(x,y) \sim p_{data}}[L(y, f(x; \theta))] $$

In probabilistic modelling, a natural choice for a loss function is the **negative log-likelihood (NLL)** of the data under our model. For a single data point `(x, y)`, the NLL is simply `-log p_{model}(y|x; \theta)`. Minimising this value is equivalent to maximising the probability our model assigns to the true outcome. Therefore, our training objective becomes minimising the *expected negative log-likelihood* with respect to the data distribution:

$$ \hat{\theta} = \arg\min_{\theta} \mathbb{E}_{(x,y) \sim p_{data}}[-\log p_{model}(y|x; \theta)] $$

This elegant connection shows that many common machine learning training procedures are, in fact, attempts to find a model distribution that best matches the true data distribution, as measured by an expected value.

### 3.2 Conditional Probability and Factorisation: Decomposing Complexity

Most real-world problems involve multiple random variables. The joint probability distribution `p(x_1, x_2, ..., x_n)` describes the behaviour of the entire system. However, modelling this joint distribution directly is often intractable. The **chain rule of probability** allows us to decompose this complex joint distribution into a product of simpler conditional distributions.

**Theorem 3.1: The Chain Rule of Probability**
For any set of random variables `x_1, ..., x_n`, the joint distribution can be factorised as:
$$ p(x_1, x_2, \dots, x_n) = p(x_1) \prod_{i=2}^{n} p(x_i | x_1, \dots, x_{i-1}) $$

This rule follows directly from the definition of conditional probability, `p(A, B) = p(A|B)p(B)`. It tells us that we can model a complex joint distribution by modelling a sequence of conditional probabilities, each of which may be much simpler to handle.

#### 3.2.1 Application: Autoregressive Models for Text

This principle is the engine behind modern large language models (LLMs). A sentence or text `y` can be viewed as a sequence of tokens (words or sub-words), `y = (y_1, y_2, ..., y_T)`. The goal of a language model is to compute `p(y)`. Using the chain rule, we can factorise this joint probability:

$$ p(y) = p(y_1, y_2, \dots, y_T) = p(y_1) \cdot p(y_2|y_1) \cdot p(y_3|y_1, y_2) \cdots p(y_T|y_1, \dots, y_{T-1}) $$

This is an **autoregressive** model: the probability of each token is conditioned on all the tokens that came before it. A model like a Transformer is trained to predict the next token `p(y_t | y_1, ..., y_{t-1})`. To generate a sentence, the model first samples a token `y_1` from `p(y_1)`, then samples `y_2` from `p(y_2|y_1)`, and so on, composing a full sequence one token at a time. The factorisation turns the impossibly complex problem of modelling all sentences at once into a manageable, sequential prediction task.

### 3.3 Logistic/Sigmoid Models: Probabilities for Binary Choices

Let's now focus on a fundamental problem: binary classification. Here, the outcome `y` can take one of two values, typically {0, 1}. Our goal is to build a model for `p(y=1|x)`.

A first attempt might be to use a linear model, `f(x) = w^T x + b`, and interpret the output as a probability. However, the output of a linear model is unbounded `(-\infty, \infty)`, while probabilities must lie in `[0, 1]`. We need a way to map the real-valued "score" from our linear model to a valid probability. The **logistic sigmoid function** is the perfect tool for this.

**Definition 3.3: The Sigmoid Function**
The sigmoid function, denoted `\sigma(z)`, is defined as:
$$ \sigma(z) = \frac{1}{1 + e^{-z}} $$
This function takes any real number `z` and squashes it into the range `(0, 1)`.

Our **logistic regression model** is thus defined by first computing a linear score `z = w^T x + b` and then passing it through the sigmoid function:
$$ p(y=1 | x; w, b) = \sigma(w^T x + b) $$
Since there are only two outcomes, it follows that `p(y=0 | x; w, b) = 1 - \sigma(w^T x + b)`.

#### 3.3.1 Interpreting the Model: Log-Odds

The logistic model has a beautiful interpretation. Let `p = p(y=1|x)`. The **odds** of the event are defined as the ratio `p / (1-p)`. The **log-odds** (or logit) is the logarithm of this ratio. Let's see what the log-odds are for our model:
$$ \log\left(\frac{p}{1-p}\right) = \log\left(\frac{\sigma(z)}{1-\sigma(z)}\right) = \log\left(\frac{\frac{1}{1+e^{-z}}}{\frac{e^{-z}}{1+e^{-z}}}\right) = \log(e^z) = z $$
Since `z = w^T x + b`, we have:
$$ \log\left(\frac{p(y=1|x)}{p(y=0|x)}\right) = w^T x + b $$
This reveals that logistic regression is a **linear model for the log-odds**. This provides direct interpretability: increasing the feature `x_j` by one unit changes the log-odds of the outcome by `w_j`, holding all other features constant.

# Goodbye Tokens, Hello Patches: How BLT Dynamically Allocates Compute

For years, the standard recipe for building Large Language Models (LLMs) has remained remarkably consistent: take raw text, run it through a tokenizer to break it into static chunks called tokens, and feed those tokens into a Transformer. While this approach has powered the AI revolution, it comes with inherent inefficiencies. Tokenizers treat every token equally, regardless of whether that token represents a predictable suffix or the start of a complex new idea. This "one-size-fits-all" compute allocation is wasteful.

Enter the Byte Latent Transformer (BLT), a new architecture that ditches fixed vocabularies entirely. Instead of static tokens, BLT processes raw bytes grouped into dynamic "patches." By leveraging the entropy of the data to determine where these patches begin and end, BLT allocates computational resources exactly where they are needed most. The result is a model that matches the performance of state-of-the-art tokenized models like Llama 3 while offering up to 50% improvements in inference efficiency.

## The Problem with Static Tokens

Traditional LLMs rely on tokenization as a heuristic pre-processing step to compress raw bytes into manageable units. However, this introduces a rigid structure where the model spends the same amount of compute processing every single token. This creates a mismatch between computational effort and information density.

Consider the difference between predicting the end of a common word versus predicting the first word of a new sentence. The former is a low-entropy, highly predictable task, while the latter often requires significant reasoning and context integration. In a standard token-based model, both scenarios consume identical floating-point operations (flops) because the architecture cannot distinguish between easy and hard predictions at the structural level. Furthermore, tokenization biases how strings are compressed, leading to issues with multilingual equity, sensitivity to input noise, and a lack of genuine orthographic knowledge.

Previous attempts to train models directly on bytes faced prohibitive costs due to the sheer length of byte sequences. While some researchers tried to optimize attention mechanisms for small models, the bottleneck at scale is not attention—it is the massive feed-forward networks that process every single unit of input. To solve this, we need a way to reduce the number of steps the main transformer takes without losing critical information.

## Enter Dynamic Patching via Entropy

BLT solves the efficiency problem by replacing static tokens with dynamic patches. Unlike tokens, which are drawn from a finite vocabulary determined before training, patches are arbitrary groups of bytes formed on the fly. The core innovation lies in how BLT decides where to cut these patches: it uses entropy.

The system employs a small, lightweight byte-level language model to estimate the uncertainty, or entropy, of predicting the next byte in a sequence. Mathematically, for a byte $x_i$ given previous bytes $\pmb{x}_{<i}$, the entropy $H(x_i)$ is calculated as:

$$H(x_i) = \sum_{v \in \mathcal{V}} p_{e}(x_i=v|\pmb{x}_{<i}) \log p_{e}(x_i=v|\pmb{x}_{<i})$$

When the entropy is low, it means the model is confident about what comes next; these are predictable regions like the middle of a common word or repetitive code structures. When entropy spikes, it signals high uncertainty and high information density, such as the beginning of a new concept or a rare character sequence. BLT uses these entropy estimates to segment the byte stream. It creates longer patches in low-entropy regions and shorter patches where uncertainty is high.

This approach ensures that computationally expensive operations are reserved for complex parts of the data. If a sequence of bytes is highly predictable, BLT groups them into a large patch and processes them with fewer transformer steps. Conversely, difficult predictions trigger more frequent updates from the main model. This dynamic allocation allows BLT to achieve an average patch size significantly larger than typical token sizes—up to 8 bytes compared to Llama 3's average of 4.4 bytes—drastically reducing the total number of steps required during inference.

## Inside the BLT Architecture

To make this dynamic patching work, BLT utilizes a hybrid architecture consisting of three distinct components: a local encoder, a global latent transformer, and a local decoder.

The process begins with the **Local Encoder**, a lightweight transformer that ingests raw bytes. To ensure robust representations without relying on huge embedding tables, BLT incorporates hash $n$-gram embeddings. For each byte position $i$, the model constructs byte-grams $g_{i,n}$ for various lengths $n$ and maps them to indices in fixed-size embedding tables using a rolling polynomial hash function:

$$\text{Hash}(g_{i,n}) = \text{RollPolyHash}(g_{i,n}) \% |E_{n}^{hash}|$$

These enriched byte representations are then pooled into patch representations via cross-attention layers. This step effectively compresses variable-length byte sequences into fixed-dimensional vectors ready for the main model.

These patch vectors are then fed into the **Global Latent Transformer**. This is the heavyweight component responsible for autoregressive reasoning over the sequence of patches rather than individual bytes or tokens. Because it operates on patches instead of raw bytes, it runs less frequently when data is predictable, saving substantial compute. The global model uses block-causal attention to ensure it only sees past context within the current document.

Finally, the **Local Decoder** takes the output representations from the global transformer and reconstructs them back into raw bytes. Like the encoder, it uses cross-attention to distribute patch-level information back down to individual byte positions before predicting the final output distribution over the 256 possible byte values ($V=256$). This modular design allows BLT to enjoythe representational power of large transformers while maintaining fine-grained control over byte-level details.

## Scaling Beyond Tokenization Limits

One of the most compelling findings from BLT research is its scaling behavior under fixed inference budgets. In traditional tokenized models there is a hard trade-off: increasing vocabulary size reduces sequence length but inflates parameter counts in embedding layers and output projections leaving little room for optimization . BLT breaks this constraint by decoupling patch size from any fixed vocabulary . Researchers can simultaneously increase both model size and average patch size while keeping inference costs constant . 

Experiments scaling models up to 8 billion parameters and training on trillions of bytes show that BLT matches compute-optimal scaling trends established by Llama 3 . More impressively when comparing models constrained by an equal inference flop budget larger models equipped with larger patches consistently outperform their smaller counter parts using finer granularities . Essentially longer patches save enough compute during inference that those saved flops can be reinvested into making global latent transformers bigger enabling superior performance without increasing latency costs .

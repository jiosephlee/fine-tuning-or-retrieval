\title{Stack Exchange of the Paper: "Byte Latent Transformer: Patches Scale Better Than Tokens"}

### Clarification on the dimension mismatch in Encoder Cross-Attention
Question:
In Section 3.2.2 regarding the Encoder Multi-Headed Cross-Attention, the paper mentions that patch representations typically have a larger dimension ($h_{\mathcal{G}}$) than the byte representations ($h_{\mathcal{E}}$). 

The text says: 'we maintain $P_l$ as multiple heads of dimension $h_{\mathcal{E}}$ when doing cross-attention, and later, concat these representations into $h_{\mathcal{G}}$ dimensions.'

Could someone explain the mechanics of this concatenation? If the query $Q_j$ is initialized to match the target dimension $h_{\mathcal{G}}$, how do we perform attention with keys/values of dimension $h_{\mathcal{E}}$? Are we essentially splitting one large patch query into several smaller 'byte-sized' queries to attend to the byte stream, and then stitching the outputs back together?
Answer:
The mechanism you are describing is essentially correct: the architecture splits the high-dimensional patch query into multiple lower-dimensional heads to align with the byte representations, performs attention in that shared subspace, and then concatenates the results to reconstruct the full patch dimension.

In the Encoder Multi-Headed Cross-Attention module described in Section 3.2.2, there is a dimensional mismatch between the latent patch representations required by the global transformer (dimension $h_{\mathcal{G}}$) and the byte representations produced by the local encoder (dimension $h_{\mathcal{E}}$), where typically $h_{\mathcal{G}} > h_{\mathcal{E}}$. To resolve this without projecting the entire byte sequence up to $h_{\mathcal{G}}$ (which would be computationally wasteful), the model treats the patch representation $P_l$ not as a single vector during the attention operation, but as a collection of $U_{\mathcal{E}}$ parallel heads, each having dimension $h_{\mathcal{E}}$. Mathematically, if we view the target patch dimension as $h_{\mathcal{G}} = U_{\mathcal{E}} \times h_{\mathcal{E}}$, the query matrix $Q$ is initialized such that it consists of $U_{\mathcal{E}}$ distinct vectors of size $h_{\mathcal{E}}$ for each patch.

When computing the attention scores, each of these $U_{\mathcal{E}}$ query heads interacts independently with the key and value matrices ($K$ and $V$), which are projected from the byte representations of dimension $h_{\mathcal{E}}$. Because the dimensions now match ($h_{\mathcal{E}}$ vs $h_{\mathcal{E}}$), the dot-product attention $\text{softmax}(QK^T/\sqrt{d_k})V$ can proceed normally. You can intuitively think of this as the large patch "asking" $U_{\mathcal{E}}$ different questions to the underlying byte stream, where each question is formulated in the native language (dimension) of the bytes. Each head produces an output vector of size $h_{\mathcal{E}}$. Once the attention operation is complete for all heads, these output vectors are concatenated along the feature dimension to form a single vector of size $U_{\mathcal{E}} \times h_{\mathcal{E}}$, which equals the required target dimension $h_{\mathcal{G}}$. This concatenated result is then passed through the output projection $W_o$ and added via a residual connection to update the patch representation. This approach allows the model to aggregate information from variable-length byte sequences into a fixed, larger latent space efficiently, avoiding unnecessary linear projections on the long byte sequences while still enabling rich communication between the local byte level and the global patch level.

\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### In mLSTM, why is retrieving memory via $\mathbf{C}_t \mathbf{q}_t$ superior to standard associative recall?
Question:
In Section 3.3, mLSTM stores information using a covariance update rule: $\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top$. Retrieval is done by multiplying this matrix by a query vector: $\tilde{\mathbf{h}}_t = \mathbf{C}_t \mathbf{q}_t$. This looks like storing outer products and retrieving via dot products. How does this differ conceptually from the 'Retention' mechanism or linear attention? Specifically, why does expanding the memory to a full $d \times d$ matrix provide significantly better capacity for 'Rare Token Prediction' compared to a standard vector-based LSTM cell or even multi-head attention? Is it purely because we aren't compressing multiple key-value pairs into a single scalar or vector summary?
Answer:
The superiority of the mLSTM retrieval mechanism $\tilde{\mathbf{h}}_t = \mathbf{C}_t \mathbf{q}_t$ over standard associative recall or vector-based LSTMs stems fundamentally from the expansion of the memory state from a scalar or vector to a full $d \times d$ matrix, which drastically increases storage capacity and prevents the destructive compression of information. In a traditional LSTM, the cell state $c_t$ is a scalar (or a vector in multi-cell variants), meaning that every new piece of information $z_t$ must be compressed into this limited space alongside all previous history. As noted in the Introduction, this leads to "limited storage capacities," causing the model to struggle with tasks like Rare Token Prediction because distinct key-value pairs interfere with one another when forced into a low-dimensional summary. The mLSTM addresses this by utilizing a covariance update rule $\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top$, which stores information as an outer product of keys and values.

Conceptually, this differs from standard linear attention or retention mechanisms because the mLSTM explicitly treats the memory matrix $\mathbf{C}_t$ as a high-capacity associative memory bank akin to Bidirectional Associative Memories (BAMs), rather than just a running sum of attended values. When you retrieve via $\mathbf{C}_t \mathbf{q}_t$, you are effectively computing a weighted sum of all stored values $\mathbf{v}_\tau$, where the weights are determined by the similarity between the current query $\mathbf{q}_t$ and all past keys $\mathbf{k}_\tau$ accumulated within the matrix structure. While linear attention also approximates this operation, the mLSTM integrates it within the specific gating framework of an LSTM (with exponential input gates and stabilizers) and, crucially, operates in a higher-dimensional space facilitated by the pre-up-projection block architecture described in Section 3.4. By mapping inputs to a high-dimensional space before applying the matrix memory, the model leverages Cover's Theorem, which suggests that patterns become linearly separable in higher dimensions. This separation allows the $d \times d$ matrix to store many more orthogonal key-value pairs without them collapsing into noise, a feat impossible for a scalar or narrow vector state.

The significant gain in "Rare Token Prediction" performance is therefore not merely due to avoiding scalar compression, but because the matrix memory allows for maximal separability of retrieved vectors. The paper cites that the covariance update rule is optimal for maximizing the signal-to-noise ratio when retrieving binary vectors, allowing the model to distinguish between rare, infrequent tokens that might otherwise be overwritten or blurred in a standard LSTM's constant error carousel. Essentially, while a standard LSTM or even some linear RNNs must overwrite or average out old information to make room for new inputs within a fixed vector size, the mLSTM's matrix structure provides enough degrees of freedom ($d^2$ vs $d$) to retain distinct associations for a much larger vocabulary of keys, enabling precise retrieval even for tokens that appear rarely in the training sequence.

# Breaking the Speed Limit: How FlashAttention-3 Unlocks 75% GPU Utilization on H100s

The Transformer architecture has revolutionized artificial intelligence, but its core component—the attention mechanism—remains a stubborn bottleneck. As models grow larger and context windows expand to encompass entire books or codebases, the quadratic scaling of attention becomes increasingly costly. While previous iterations like FlashAttention-2 made significant strides by optimizing memory access patterns, they still left considerable performance on the table when running on modern hardware. Specifically, FlashAttention-2 achieved only about 35% utilization on NVIDIA's flagship H100 GPU, far below the 80-90% seen in optimized matrix multiplication kernels.

Enter FlashAttention-3, a new approach designed specifically to harness the unique capabilities of the Hopper architecture. By rethinking how computation and data movement interact, FlashAttention-3 pushes FP16 performance up to 740 TFLOPs/s, representing roughly 75% GPU utilization. Even more impressively, it leverages low-precision FP8 arithmetic to reach nearly 1.2 PFLOPs/s while maintaining high numerical accuracy. This post explores the three key innovations driving these gains: producer-consumer asynchrony, interleaved computation pipelines, and smart low-precision strategies.

## The Hardware Gap: Why FlashAttention-2 Stalled

To understand the leap forward provided by FlashAttention-3, we must first look at why its predecessor hit a ceiling. FlashAttention-2 successfully eliminated expensive reads and writes to global memory by fusing attention operations into a single kernel. However, it largely adhered to a synchronous execution model. In this model, the GPU waits for one operation to finish completely before starting the next, even if different hardware units could theoretically work in parallel.

Modern GPUs like the H100 are built with specialized hardware units designed for concurrency. The Tensor Cores handle massive matrix multiplications, while the Tensor Memory Accelerator (TMA) manages data transfers between global and shared memory independently. When an algorithm forces these units to wait on each other, it leaves powerful silicon idle. FlashAttention-3 addresses this inefficiency by explicitly designing around asynchrony, ensuring that data movement and computation happen simultaneously rather than sequentially.

## Warp-Specialization: Dividing Labor for Maximum Efficiency

The first major technique employed in FlashAttention-3 is warp-specialization, a form of software pipelining that splits the workforce within a GPU thread block. In traditional kernels, every "warp" (a group of 32 threads) attempts to handle both data loading and math operations. This creates contention and prevents the compiler from optimizing instruction schedules effectively.

FlashAttention-3 divides warps into distinct roles: producers and consumers. Producer warps are dedicated solely to fetching data from global memory into shared memory using the asynchronous TMA unit. Once they issue a load command, they do not wait for it to complete; instead, they immediately move on to fetch the next chunk of data. Meanwhile, consumer warps focus exclusively on computation, utilizing the asynchronous WGMMA instructions to perform matrix multiplications on data already resident in shared memory.

This separation allows the system to hide latency effectively. While the consumer warps are crunching numbers on the current block of keys and values, the producer warps are already fetching the subsequent blocks needed for the next iteration. Furthermore, Hopper GPUs allow for dynamic register reallocation via the `setmaxnreg` instruction. This means consumer warps can be granted more registers to hold intermediate results for complex math, while producer warps, which have simpler logic needs, operate with fewer registers. This fine-grained resource management ensures that no hardware capability goes unused.

## Hiding Softmax Behind Matrix Multiplication

Even with efficient data loading, attention mechanisms face a secondary bottleneck: the softmax operation. Unlike matrix multiplications, which benefit from massive parallelism on Tensor Cores, softmax involves element-wise exponential calculations and reductions that run significantly slower on general-purpose CUDA cores. In many scenarios, these non-matrix operations can consume up to 50% of the total execution time despite requiring far fewer floating-point operations.

FlashAttention-3 solves this by overlapping softmax computations with matrix multiplications from adjacent steps in the algorithm. The authors introduce a two-stage pipelining strategy where the dependency chain is broken across iterations. While one set of warps calculates the softmax probabilities for the current block of attention scores ($\mathbf{S}_i^{(j)}$), another set simultaneously executes the matrix multiplication ($\mathbf{Q}_i \mathbf{K}_{j+1}^\top$) required to generate the scores for the *next* block.

This "pingpong" scheduling ensures that while the Tensor Cores are busy with heavy lifting, the slower special function units are also kept occupied processing the previous results. By carefully managing synchronization barriers, the algorithm guarantees that data is ready exactly when needed without forcing either unit to sit idle waiting for the other to finish its entire task sequence.

# The Art of Multitasking: Hiding Softmax Behind Matrix Multiplications

One of the biggest bottlenecks in modern artificial intelligence isn't necessarily the complexity of the math itself, but rather the time spent waiting for that math to finish. In the world of Large Language Models (LLMs), the attention mechanism is the engine that drives understanding, but it is also a notorious performance choke point. While previous iterations like FlashAttention-2 made significant strides by optimizing memory access, they still left powerful GPU components sitting idle during critical phases of computation. Enter FlashAttention-3, a new approach that treats GPU execution less like a assembly line and more like a high-stakes juggling act. By leveraging a technique known as "pingpong scheduling," FlashAttention-3 successfully hides slow mathematical operations behind fast matrix multiplications, ensuring that the hardware's most potent units never stop working.

## The Imbalance of Power on Modern GPUs

To understand why multitasking is necessary, we must first look at the hardware landscape of modern GPUs, specifically NVIDIA's Hopper architecture found in chips like the H100. These processors are designed with specialized units for specific tasks. The Tensor Cores are absolute beasts at performing matrix multiplications (GEMMs), capable of delivering nearly 1,000 tera-floating-point operations per second (TFLOPs) in FP16 precision. However, other essential operations required for attention, such as the exponential function used in the softmax calculation, are handled by different units with significantly lower throughput.

On an H100 GPU, while the matrix multiplication capability hovers around 989 TFLOPs, the throughput for special functions like exponentials is merely about 3.9 TFLOPs. This creates a staggering imbalance. In a typical attention forward pass with a head dimension of 128, there are roughly 512 times more matrix multiplication operations than exponential operations. Yet, because the exponential unit is 256 times slower, these seemingly minor calculations can consume up to 50% of the total execution cycle. In traditional synchronous implementations, the incredibly fast Tensor Cores are forced to pause and wait for the sluggish softmax calculations to complete before they can proceed to the next step. This idle time represents wasted potential and reduced efficiency.

## Introducing Pingpong Scheduling

FlashAttention-3 addresses this inefficiency by reimagining how operations are scheduled across the GPU's execution units. The core innovation is a technique called pingpong scheduling, which exploits the asynchronous capabilities of the hardware to overlap computations that would otherwise happen sequentially. Instead of having a single group of threads perform a matrix multiplication, wait for the result, calculate the softmax, and then move on, FlashAttention-3 splits the work between two distinct warpgroups (groups of 128 threads).

The algorithm orchestrates a dance where one warpgroup handles the heavy lifting of matrix multiplications while the other simultaneously processes the lighter, slower softmax operations from the previous iteration. Specifically, while Warpgroup 1 is busy computing the matrix product $\mathbf{Q}\mathbf{K}^\top$ for the current block of data using asynchronous WGMMA instructions, Warpgroup 2 is calculating the exponential and normalization steps for the score matrix generated in the *previous* block. Once Warpgroup 1 finishes its multiplication, it swaps roles with Warpgroup 2. Now, Warpgroup 1 tackles the softmax for its completed block, while Warpgroup 2 jumps ahead to start the next matrix multiplication.

This interleaving ensures that the Tensor Cores are almost constantly engaged in matrix math, while the multi-function units handle the exponentials in parallel. The dependency chain is broken not by changing the mathematics of attention, but by pipelining the execution across iterations. By using synchronization barriers to enforce this strict alternation, the system effectively hides the latency of the slow softmax operation underneaththe duration of the fast matrix multiplication.

## Warp Specialization and Asynchrony

Making this pingpong schedule possible requires a deeper architectural shift known as warp specialization. In older GPU programming models, all threads within a block tended to perform similar tasks in lockstep. FlashAttention-3 explicitly divides labor: some warps act solely as "producers" responsible for moving data from global memory into shared memory using the Tensor Memory Accelerator (TMA), while others act as "consumers" that perform computations on that data.

This separation allows for fine-grained control over resources. For instance, warps dedicated to data movement require very few registers, whereas warps executing complex matrix multiplications benefit from having access to as many registers as possible. FlashAttention-3 utilizes dynamic register allocation instructions to redistribute register space between these producer and consumer warps on the fly. Furthermore, because both data movement (via TMA) and matrix multiplication (via WGMMA) are asynchronous on Hopper GPUs, they can run concurrently without stalling each other. This means data for future blocks can be fetched while current blocks are being processed, adding another layer of parallelism on top of GEMM-softmax overlapping resulting in higher overall occupancy and utilization rates reaching up to $75\%$ on H100s compared to $35\%$ seen in earlier versions..

# Going FP8 Without Losing Your Mind: Solving the Accuracy Problem in Low-Precision AI

The race to make Large Language Models (LLMs) faster and more energy-efficient has led developers toward low-precision arithmetic. Moving from 16-bit floating point (FP16) to 8-bit floating point (FP8) theoretically doubles the throughput of matrix multiplications on modern GPUs like NVIDIA's H100. However, this speed boost comes with a notorious catch: accuracy degradation. When you compress numbers into fewer bits, extreme values—known as "outliers"—get crushed, causing the model to lose its reasoning capabilities.

FlashAttention-3 addresses this critical dilemma head-on. By introducing two sophisticated techniques, block quantization and incoherent processing, it manages to harness the raw speed of FP8 hardware while maintaining, and in some cases improving, numerical stability. This post breaks down how these methods work and why they matter for the future of efficient AI.

## The Outlier Problem in Low Precision

To understand the solution, we first need to understand the problem. Standard quantization strategies often apply a single scaling factor to an entire tensor (per-tensor quantization). Imagine trying to fit a dataset where most values hover around zero, but a tiny fraction are massive spikes. If you scale the whole group to fit the massive spikes into the limited range of FP8, the small values lose all their resolution and effectively become zero. Conversely, if you scale for the small values, the outliers overflow.

In LLMs, these outliers are not noise; they are features. Research has shown that roughly 0.1% of activation values can be significantly larger than the rest. In standard FP8 implementations using per-tensor scaling, these outliers dominate the dynamic range, leading to substantial numerical errors that degrade model performance. FlashAttention-3 tackles this by changing how we view and process these data distributions before they ever hit the Tensor Cores.

## Strategy One: Block Quantization

The first line of defense in FlashAttention-3 is block quantization. Instead of applying one global scaling factor to an entire matrix like $\mathbf{Q}$, $\mathbf{K}$, or $\mathbf{V}$, the algorithm divides these tensors into smaller blocks. For instance, a query matrix might be split into blocks of size $B_r \times d$. Each block then receives its own dedicated scaling factor.

This approach drastically reduces the impact of outliers because an extreme value only affects the scaling of its immediate neighbors within that specific block, rather than distorting the precision of the entire tensor. Since FlashAttention already processes data in tiles to optimize memory access, implementing block quantization adds virtually no computational overhead. The scaling adjustments can be fused directly into existing operations, such as rotary embeddings, ensuring that the GPU remains fully utilized without stalling for extra math. By localizing the quantization error, block quantization preserves the fidelity of both small and large values much more effectively than global scaling.

## Strategy Two: Incoherent Processing

While block quantization helps localize errors, it doesn't eliminate the presence of outliers within a block. This is where the second technique, incoherent processing, shines. The core idea is counter-intuitive: before quantizing the data, we deliberately mix it up using a random orthogonal matrix $\mathbf{M}$.

Mathematically, we transform the query and key matrices by multiplying them with $\mathbf{M}$, resulting in $\mathbf{Q}\mathbf{M}$ and $\mathbf{K}\mathbf{M}$. Because $\mathbf{M}$ is orthogonal ($\mathbf{M}\mathbf{M}^\top = I$), the dot product remains unchanged:
$$ (\mathbf{Q}\mathbf{M})(\mathbf{K}\mathbf{M})^\top = \mathbf{Q}(\mathbf{M}\mathbf{M}^\top)\mathbf{K}^\top = \mathbf{Q}\mathbf{K}^\top $$
This means the final attention output is theoretically identical to what it would have been without the transformation. However, during the intermediate step where we convert to FP8, something magical happens. The multiplication by $\mathbf{M}$ acts as a rotation that spreads the energy of any single outlier across many elements in the transformed vector. Instead of one element holding a massive value that breaks the FP8 range, that value is distributed as slightly elevated values across dozens of elements.

In practice, FlashAttention-3 implements this efficiently by choosing $\mathbf{M}$ as a product of random diagonal matrices and a Hadamard matrix. This specific choice allows the multiplication to be computed in $O(d \log d)$ time rather than $O(d^2)$, and like block quantization, it can be fused with preceding operations like rotary embeddings at no extra cost. The result is a "smoothed" distribution of values that fits comfortably within the limited dynamic range of FP8 format.

## Validating the Results

The combination of these two techniques yields tangible improvements in real-world benchmarks. When tested against scenarios designed to simulate heavy outlier presence—where 0.1% of entries are drawn from a distribution with ten times the standard deviation—standard FP8 attention struggles significantly. In contrast, FlashAttention-3 utilizing block quantization and incoherent processing demonstrates a 2.6$\times$ reduction in numerical error compared to baseline per-tensor quantization methods.

Furthermore, this accuracy does not come at the expense of speed. On NVIDIA H100 GPUs, FlashAttention-3 running in FP8 achieves close to 1.2 PFLOPs/s utilization nearly doubling performance compared to FP16 implementations which top out around 740 TFLOPs/s (75% utilization). This proves that we do not have to choose between speed and intelligence; with careful algorithmic design that respects hardware constraints and statistical properties of data, we can achieve both simultaneously

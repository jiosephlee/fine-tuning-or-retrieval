\title{Stack Exchange of the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

### Why are the weights $\mathbf{w}_k$ projected to a positive subspace using $\max(\mathbf{w}_k, 0)$?
Question:
Equation (2) defines the logit calculation as $\text{logit}_k^i = \max(\mathbf{w}_k, 0) \cdot \mathbf{z}_k^i$. The paper states this is done to ensure features 'do not reduce the likelihood of a class.'

Intuitively, shouldn't a powerful model be allowed to learn negative weights? For instance, if a rule says 'Age > 80', maybe satisfying this rule should *decrease* the probability of belonging to a 'Healthy' class. By forcing all weights to be non-negative, aren't we restricting the model's expressivity? Does this mean the system relies entirely on the LLM generating only 'positive evidence' rules, and if the LLM generates a rule that correlates negatively with the target, that rule becomes useless?
Answer:
The projection of weights $\mathbf{w}_k$ to a positive subspace using $\max(\mathbf{w}_k, 0)$ is a deliberate design choice rooted in the specific semantics of how \textsf{FeatLLM} constructs features, rather than a general limitation on model expressivity. To understand this, one must look at how the features $\mathbf{z}_k^i$ are generated. As described in the "Parsing rules for feature generation" and "Inferring class likelihood" sections, the LLM acts as a feature engineer that explicitly derives rules associated with a *specific* target class. For instance, if the task is to predict "Heart Failure," the LLM is prompted to generate rules that identify conditions *indicative* of that disease (e.g., "Age > 80" implies high risk). Consequently, the resulting binary feature $\mathbf{z}_k^i$ takes a value of 1 only if the sample satisfies a rule that the LLM has already deemed as positive evidence for class $k$.

Because the feature generation process inherently filters for positive correlation during the rule creation phase (Step 2 of the reasoning instruction), allowing the downstream linear model to learn negative weights would be semantically contradictory. If the model were allowed to learn a negative weight for a rule like "Age > 80" in the context of predicting "Healthy," it would imply that satisfying a rule intended to signal danger actually reduces the likelihood of being healthy. While mathematically valid in a standard black-box model, in this framework, it suggests the LLM generated a nonsensical or spurious rule. By enforcing non-negativity via $\max(\mathbf{w}_k, 0)$, the system ensures that every active rule contributes additively to the class likelihood, adhering to the principle that "features do not reduce the likelihood of a class." This constraint simplifies the learning problem for the few-shot regime by preventing the model from trying to invert logically flawed rules; instead, if a generated rule is indeed negatively correlated or useless for the target class, the optimization process simply drives its weight toward zero, effectively ignoring it. This mechanism is confirmed in the ablation studies and quality analysis, where tuning allows the model to filter out irrelevant rules (those with weights near zero) while retaining only those that provide consistent positive evidence, thereby enhancing robustness against noise without needing complex negative interactions.

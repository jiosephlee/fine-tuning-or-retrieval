\title{Blogs about the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

# From Text to Truth: Teaching LLMs to Write Code That Predicts Disease and Credit Risk

Large Language Models (LLMs) have revolutionized how we interact with data, demonstrating an uncanny ability to reason through complex problems using nothing but text prompts. However, applying these massive models directly to tabular data—those ubiquitous spreadsheets containing everything from patient health records to credit scores—remains fraught with challenges. Traditional approaches often ask the LLM to predict the answer for every single row of data, a method that is computationally expensive, slow, and prone to hitting token limits when datasets grow large.

A new framework called **FeatLLM** proposes a paradigm shift. Instead of treating the LLM as a direct predictor, researchers have reimagined it as an expert feature engineer. In this workflow, the LLM does not guess the final outcome; rather, it analyzes the problem context and writes logical rules in natural language. These rules are then automatically parsed into executable code to generate new, high-quality binary features. This allows a simple downstream model, such as linear regression, to achieve state-of-the-art performance in few-shot learning scenarios where labeled data is scarce.

## The Limitations of Direct Prediction

To understand the innovation behind FeatLLM, one must first recognize the bottlenecks of current LLM-based tabular learning methods. Existing techniques typically serialize tabular rows into text and feed them into an LLM to obtain a direct classification. For example, to predict if a loan applicant is high-risk, the system sends the applicant's age, income, and debt history to the LLM and waits for a "Yes" or "No."

This approach creates significant friction in real-world applications. First, it requires an API call for every single sample at inference time, making it prohibitively expensive and slow for large datasets. Second, many top-tier LLMs are only accessible via inference APIs, preventing users from fine-tuning the model weights directly. Finally, tabular datasets often contain dozens or hundreds of features. Serializing all this information into a prompt can easily exceed the context window limits of current models, causing performance to degrade or the process to fail entirely.

FeatsLLM circumvents these issues by decoupling the reasoning phase from the inference phase. The heavy lifting of understanding domain logic happens once during a setup phase, leaving the actual prediction to lightweight, traditional machine learning algorithms.

## Acting as an Expert Consultant

The core philosophy of FeatLLM is to leverage the vast prior knowledge encoded within LLMs to act as a domain expert consultant. When faced with a new task, such as predicting heart failure or credit defaults with only a handful of labeled examples (few-shot learning), humans rely on general knowledge to identify relevant patterns. An expert knows that advanced age and high cholesterol are risk factors for heart disease, even before seeing specific patient data.

FeatLLM mimics this cognitive process through a structured prompting strategy divided into two distinct reasoning steps. First, the model is asked to infer the causal relationships between features and the target variable based purely on general knowledge and feature descriptions, without looking at specific data examples yet. This step ensures the model activates its internal database of medical or financial常识 (common sense).

In the second step, the model combines this general understanding with a few provided examples (few-shot demonstrations) to derive specific decision rules. For instance, instead of vaguely suggesting that age matters, the LLM might generate a precise rule: "If Age $> 50$ AND Cholesterol Level $> 240$, then risk is High." The framework explicitly instructs the LLM to generate a fixed number of these rules per class (typically 10), ensuring a manageable output size while capturing diverse aspects of the problem space.

## Turning Natural Language into Executable Code

Generating rules in natural language is only half the battle; computers cannot execute sentences like "cholesterol is high" directly. The true technical brilliance of FeatLLM lies in its automated parsing mechanism that converts these linguistic rules into functional program code.

One might assume this requires writing rigid regular expressions to parse the LLM's output. However, natural language is notoriously variable; an LLM might say "greater than," "exceeds," or use the symbol "$>$" interchangeably. To handle this noise robustly, FeatLLM employs a clever recursive strategy: it asks another instance of the LLM to write the code itself.

The system feeds the generated natural language rules back into the LLM with instructions to create a Python function that evaluates these conditions against raw data inputs. Because modern LLMs are trained on vast corpora of code, they excel at translating semantic intent into syntactically correct programming logic. The resulting code is executed using Python's `exec()` function on the dataset. This process transforms every abstract rule into a concrete binary feature—a column of 0s and 1s indicating whether each sample satisfies that specific condition.

For example, if the LLM generates five rules for "High Credit Risk,"the original dataset expands by five new columns. A value of `1` in one of these columns means that specific row triggered that logical condition. This transformation distills complex, high-dimensional data into a simplified representation grounded in logical criteria derived from expert-like reasoning.

## Simple Models for Complex Problems

Once the dataset has been enriched with these engineered binary features, the role of the Large Language Model ends completely for that iteration. The transformed data is passed to a simple downstream classifier, such as a linear regression model or logistic regression without bias.

The mathematics here remain straightforward yet effective. Let $\mathbf{z}_k^i$ represent the vector of binary features for sample $i$ corresponding to class $k$. The model learns a set of non-negative weights $\mathbf{w}_k$ that signify the importance of each rule. The likelihood of belonging to class $k$ is computed as:

$$ \text{logit}_k^i = \max(\mathbf{w}_k，0) \cdot \mathbf{z}_k^i $$

These logits are then passed through a softmax function to produce final class probabilities:

$$ \mathbf{p}^i = \text{Softmax}([\text{logit}_{1}^i，..., \text{logit}_{c}^i]) $$

By constraining weights to be non-negative，the system ensures that satisfying a rule never decreases the likelihood of its associated class，aligning with intuitive logic where evidence supports rather than contradicts hypotheses。The model optimizes these weights using standard cross-entropy loss on just a few training samples。Because input dimensionality has been reduced from potentially hundreds of raw features（with mixed types）toa focused setof logically-derived binary flags，simple linear models can generalize exceptionally well even in extreme few-shot regimes。

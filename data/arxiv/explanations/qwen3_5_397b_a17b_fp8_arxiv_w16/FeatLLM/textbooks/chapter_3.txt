\title{A Textbook about the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

Chapter 3: Chapter 3: The FeatLLM Framework Architecture

The integration of Large Language Models (LLMs) into tabular learning represents a paradigm shift from traditional statistical methods to systems capable of leveraging vast amounts of prior world knowledge. However, direct application of LLMs for end-to-end prediction on tabular data faces significant hurdles, including high computational costs, prompt size limitations, and the inability to fine-tune proprietary models. The \textsf{FeatLLM} framework addresses these challenges by redefining the role of the LLM. Rather than acting as the final predictor for every data sample, the LLM serves as an automated feature engineer. This chapter provides a comprehensive dissection of the \textsf{FeatLLM} architecture, detailing how it transforms raw tabular data into an optimized feature space through a structured, two-stage pipeline. By separating the heavy lifting of reasoning and rule generation from the lightweight task of inference, \textsf{FeatLLM} achieves high performance in few-shot settings while maintaining efficiency and scalability.

# Problem formulation: Definitions of datasets, features, and k-shot settings

To rigorously understand the mechanics of \textsf{FeatLLM}, we must first establish the mathematical formalism governing the input data and the learning constraints. The framework operates on a standard tabular dataset denoted as $\mathcal{D} = \{(\mathbf{x}^i, \mathbf{y}^i)\}_{i=1}^{N}$, consisting of $N$ labeled samples. Each sample $\mathbf{x}^i$ is a $d$-dimensional vector representing the input features, while $\mathbf{y}^i$ represents the corresponding target label belonging to a predefined set of classes. Unlike conventional machine learning setups where features are treated purely as numerical or categorical tokens, \textsf{FeatLLM} explicitly leverages the semantic context of the data. Therefore, the dataset is accompanied by a set of natural language feature names $F = \{f_j\}_{j=1}^{d}$, along with optional definitions for each feature. This linguistic metadata is crucial, as it allows the LLM to access its pre-trained knowledge base regarding what specific columns represent (e.g., understanding that "age" correlates with health risks).

The primary operational regime for \textsf{FeatLLM} is few-shot learning, specifically the $k$-shot setting. In this scenario, the model is restricted to training on only $k$ labeled samples, where $k$ is significantly smaller than the total available data $N$ (i.e., $k < N$). These $k$ samples are randomly selected to form the training set used for both guiding the LLM's reasoning and fitting the downstream classifier. The scarcity of data in this regime makes traditional deep learning approaches prone to overfitting or failing to converge. Consequently, the framework relies heavily on inductive biases derived from the LLM's prior knowledge to compensate for the lack of statistical power in the small training set. The goal is to learn a mapping from inputs $\mathbf{x}$ to class probabilities $\mathbf{p}$ that generalizes well to unseen test data, despite having observed only a handful of examples during the training phase.

# High-level architecture overview: The two-stage pipeline

The core innovation of \textsf{FeatLLM} lies in its architectural decoupling of feature engineering from model inference. Traditional LLM-based tabular methods often treat the language model as a black box that ingests serialized row data and outputs a prediction directly. This approach necessitates querying the LLM for every single inference request, leading to prohibitive latency and cost. In contrast, \textsf{FeatLLM} adopts a two-stage pipeline designed to maximize efficiency without sacrificing the reasoning capabilities of large models. The first stage involves utilizing the LLM exclusively during a preparatory phase to extract logical rules that characterize each class. These rules are derived by analyzing the task description, feature semantics, and the few available training examples.

Once these rules are established, they are parsed and converted into executable code to transform the original dataset into a new representation composed of binary features. This transformation happens offline or once per dataset update. The second stage involves discarding the need for further LLM interaction during inference. Instead, a simple, lightweight machine learning model—specifically a linear model with non-negative weights—is trained on these newly generated binary features. At inference time, incoming data points are rapidly converted into binary vectors based on whether they satisfy the pre-extracted rules, and class likelihoods are computed via a simple dot product operation followed by a softmax function. This separation ensures that the computationally expensive reasoning process occurs only once to generate features, while thousands or millions of predictions can be made instantly using standard linear algebra operations.

# Stage 1: Rule Extraction via In-Context Learning

The first stage of the framework is dedicated to prompting the LLM to act as an expert analyst capable of distilling complex relationships between features and targets into concise logical rules. To achieve this reliably, \textsf{FeatLLM} employs a highly structured prompt design that mimics human expert reasoning processes. The prompt is constructed from three distinct components: basic information description, reasoning instructions, and response instructions. The basic information section grounds the LLM in the specific context ofthe problem by providing natural language descriptions of features (including value types and definitions), explicit task descriptions framed as questions (e.g., "Does this patient's data indicate chronic heart failure?"), and serialized examples of few-shot training data paired with their ground-truth labels. The serialization follows a strict format where each feature-value pair is stated linguistically (e.g., "$f_1$ is $\mathbf{x}^i_1$") followed by the answer label.

Crucially, simply providing data is insufficient for robust rule extraction; thus, \textsf{FeatLLM} implements a guided reasoning instruction divided into two sequential cognitive steps inspired by Chain-of-Thought methodologies but tailored for causal discovery rather than mere calculation or logic puzzles alone .

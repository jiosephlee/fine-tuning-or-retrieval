\title{A Textbook about the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

Chapter 6: Chapter 6: Robustness through Ensembling and Bagging

The deployment of Large Language Models (LLMs) in tabular learning introduces unique challenges stemming from the inherent stochasticity of generative models and the physical constraints of their context windows. While the \textsf{FeatLLM} framework leverages the profound reasoning capabilities of LLMs to engineer features, relying on a single pass of rule generation can lead to suboptimal performance due to inconsistent outputs or the inability to process high-dimensional data in one go. To address these vulnerabilities, \textsf{FeatLLM} employs a rigorous strategy combining randomized prompting techniques with ensemble methods derived from classical machine learning. This chapter details how the framework transforms the potential weakness of LLM variability into a strength through diversity, manages data dimensionality via bagging, and aggregates multiple weak learners into a robust final predictor that mitigates single-point failures.

# The role of temperature and demonstration ordering in rule diversity

The foundation of a successful ensemble lies in the diversity of its constituent members. In the context of \textsf{FeatLLM}, where each member is an LLM-generated set of rules, diversity must be artificially induced because the model tends to converge on similar reasoning paths given identical inputs. To achieve this, the framework manipulates two critical hyper-parameters during the inference phase: the sampling temperature and the ordering of few-shot demonstrations. Temperature acts as a control knob for the randomness of the token selection process within the LLM. By setting a sufficiently high temperature, specifically $0.5$ in the standard configuration of \textsf{FeatLLM}, the model is encouraged to explore a broader distribution of probable next tokens rather than greedily selecting the most likely one. This stochasticity ensures that even when presented with the exact same task description and data samples, the LLM may formulate slightly different logical conditions or prioritize different features when constructing its rules. Without this injected noise, repeated queries would yield nearly identical rule sets, rendering the subsequent ensemble step redundant as it would merely average identical predictions.

Complementing temperature adjustment is the strategic randomization of few-shot demonstration ordering. Research has established that Large Language Models are sensitive to the sequence in which examples are presented within a prompt; the position of a specific sample can subtly influence the model's attention mechanism and subsequent reasoning trajectory. \textsf{FeatLLM} capitalizes on this sensitivity by shuffling the order of the $k$ labeled training samples provided in the prompt for each trial of the ensemble. If a specific arrangement of examples leads the LLM to focus heavily on numerical thresholds, a different permutation might cause it to notice categorical interactions or logical negations. By systematically varying both the internal randomness via temperature and the external context via demonstration ordering across $T$ trials, \textsf{FeatLLM} generates a collection of distinct rule sets. This diversity is paramount because it allows the ensemble to cover a wider solution space, capturing various valid interpretations of the data that a single deterministic run might miss.

# Feature Bagging: Managing high-dimensional data within context limits

One of the most significant barriers to applying LLMs to real-world tabular data is the limitation on context window size. Many practical datasets contain dozens or even hundreds of features, each requiring a natural language description and definition to be included in the prompt for effective reasoning. When serialized into text, this information can easily exceed the maximum token limit of current LLM APIs, causing the inference to fail or forcing the truncation of critical feature definitions. Furthermore, even if the data fits withinthe window, presenting an overwhelming number of features simultaneously can degrade the model's ability to discern relevant signals from noise, leading to hallucinated or spurious rules. \textsf{FeatLLM} resolves this bottleneck through feature bagging, a technique adapted from Random Forests that selects a random subset of features for each ensemble trial.

In practice, feature bagging involves randomly sampling a subset of the total available features before constructing the prompt for a specific trial $t$. Instead of attempting to reason over all $d$ features at once, the LLM is asked to derive rules based only on this reduced subset. This approach serves a dual purpose: firstly, it guarantees that the input prompt length remains well withinthe API's constraints regardless ofthe original dataset's dimensionality, makingthe framework scalableto datasets with over 100 attributes like 'Communities' or 'Myocardial'. Secondly, it forces diversity inthe learned representations. Since each trial sees a different sliceofthefeature space,the resulting rules will naturally focuson different aspects ofthe data distribution. One trial might generate rules solely basedon demographic variables, while another focuseson clinical measurements.

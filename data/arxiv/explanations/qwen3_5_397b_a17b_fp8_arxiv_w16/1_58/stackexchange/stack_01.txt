\title{Stack Exchange of the Paper: "The Era of 1-bit LLMs: All Large Language Models are in 1.58 Bits"}

### How exactly is "1.58 bits" calculated for a ternary weight set \{-1, 0, 1\}?
Question:
The paper states that adding the value 0 to the original binary \{-1, 1\} set results in "1.58 bits." I understand that standard binary is $\log_2(2) = 1$ bit, but I am confused about the math here. Is this simply $\log_2(3)$? If so, why do we describe it as "bits" in the context of storage if hardware typically allocates whole integers (like 2 bits) for three states? Does this imply a specific packing scheme where multiple weights are stored together to achieve this average?
Answer:
The value of "$1.58$ bits" cited in the paper is indeed derived directly from the information theoretic entropy of a ternary system, calculated as $\log_2(3)$. In information theory, the minimum number of bits required to uniquely represent one symbol chosen from a set of $N$ equally probable possibilities is $\log_2(N)$. Since the BitNet b1.58 architecture constrains every weight parameter to exactly three distinct states $\{-1, 0, 1\}$, the theoretical lower bound for storage per weight is $\log_2(3) \approx 1.58496$, which the authors round to $1.58$. This stands in contrast to standard binary quantization (used in the original BitNet), which utilizes only two states $\{-1, 1\}$ and thus requires exactly $\log_2(2) = 1$ bit per weight.

Your confusion regarding hardware allocation versus this fractional bit count is astute and touches on the difference between theoretical entropy and practical implementation on current commodity hardware. You are correct that standard computer memory cannot physically allocate $1.58$ bits to a single variable; memory is addressed in bytes, and individual elements are typically stored in integer multiples of bits (e.g., storing a ternary value in a standard `int8` would waste $6.22$ bits per weight). However, describing the model as "$1.58$-bit" does not imply that every individual weight occupies a fractional physical space in isolation. Rather, it describes the aggregate storage density achievable when packing large tensors of these weights together using specialized encoding schemes. Just as you can store multiple boolean flags within a single byte to achieve an average of $1$ bit per flag, specialized packing kernels can encode sequences of ternary values into dense bitstreams. For instance, by grouping multiple ternary weights together, one can map their combined state space ($3^k$ possibilities for $k$ weights) onto a binary buffer close to the theoretical limit of $k \times \log_2(3)$ total bits.

The significance of highlighting "$1.58$ bits" in the paper extends beyond mere storage arithmetic; it serves as a marker for a new scaling law and efficiency frontier. The inclusion of the zero state is not just a mathematical curiosity but a functional mechanism for "feature filtering," allowing the network to explicitly ignore certain connections (multiplication by zero) which simplifies the computation paradigm to mostly integer additions. When the authors claim improvements in memory footprint and bandwidth (such as the reported $3.55$x reduction compared to FP16 baselines), they are projecting the performance of systems utilizing these optimal packing strategies or custom hardware designed specifically for this ternary format. While current general-purpose GPUs might initially simulate this using $2$-bit or $8$-bit kernels (as noted in their results section where they mention using a "$2$-bit kernel"), the "$1.58$-bit" designation defines the intrinsic information content of the model and sets the target for future hardware optimization where memory buses and caches are tailored to transfer exactly this amount of information per weight, eliminating the inefficiency of padding to whole integer bit-widths.

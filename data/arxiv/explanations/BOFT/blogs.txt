## Meet BOFT: How Butterfly Factorization Makes Finetuning Large Models Cheap and Stable

# Meet BOFT: How Butterfly Factorization Makes Finetuning Large Models Cheap and Stable

If you’ve ever tried to fine-tune a massive machine learning model like GPT-3 or Stable Diffusion, you know it can be a costly and tricky process. These foundation models are huge—sometimes with hundreds of billions of parameters—and training them from scratch is often out of reach for most researchers and practitioners. So, how can we adapt these powerful models to new tasks without breaking the bank or losing stability?

Enter **Orthogonal Butterfly Finetuning (BOFT)**, a clever new method that makes fine-tuning large models both parameter-efficient and stable. In this post, we’ll walk you through the motivation behind orthogonal finetuning, why the original approach can be expensive, and how butterfly factorization—a concept borrowed from the fast Fourier transform (FFT)—helps compress these transformations dramatically. We’ll also compare BOFT to popular alternatives like LoRA and full fine-tuning, so you know when it’s the right tool for your project.

---

## Why Orthogonal Finetuning?

When you fine-tune a pretrained model, the goal is to adapt it to a new task while preserving the valuable knowledge it already learned. Traditional fine-tuning updates many or all of the model’s parameters, which can be expensive and sometimes unstable.

Orthogonal finetuning (OFT) offers a neat solution: instead of adding arbitrary changes, it transforms the model’s neurons using an **orthogonal matrix**—a special kind of transformation that preserves angles and distances between vectors. Think of it like rotating or reflecting the neurons without stretching or squashing them. This helps keep the pretrained knowledge intact, leading to better generalization and more stable training.

However, there’s a catch. Orthogonal matrices for large layers are huge—if your layer has dimension *d*, a full orthogonal matrix has *d²* parameters. That’s a lot to learn and store, especially for big models.

---

## The Problem with Naive OFT: Too Many Parameters

To reduce the parameter count, the original OFT method uses a **block-diagonal structure**. Imagine splitting the big orthogonal matrix into smaller blocks along the diagonal and only learning those blocks independently. This cuts down parameters but at a cost: the transformation becomes sparse and less expressive. It’s like only rotating small chunks of neurons separately, which limits how well the model can adapt.

Moreover, this block structure imposes a fixed pattern that might not align well with the data, potentially hurting performance. So, the question is: **Can we have a dense, expressive orthogonal transformation but still keep the number of parameters manageable?**

---

## Butterfly Factorization: Inspiration from the Fast Fourier Transform

Here’s where the magic of **butterfly factorization** comes in. The idea is inspired by the Cooley-Tukey FFT algorithm, which efficiently computes the discrete Fourier transform by breaking it down into a sequence of sparse, structured steps arranged in a “butterfly” pattern.

Imagine a network of nodes arranged in layers, where each layer only connects to a few nodes in the next layer, but after several layers, information from every input node can reach every output node. This butterfly network achieves **dense connectivity** with surprisingly few connections—only about *O(d log d)* instead of *O(d²)*.

BOFT leverages this idea by representing the big orthogonal matrix as a product of multiple sparse orthogonal matrices arranged in a butterfly pattern. Each sparse matrix has far fewer parameters, but when multiplied together, they form a dense, expressive orthogonal transformation.

---

## How BOFT Works: A High-Level View

- **Start with the pretrained weight matrix** of a layer.
- **Parameterize the finetuning transformation** as a product of several sparse orthogonal matrices, each corresponding to a butterfly component.
- **Ensure each component is orthogonal** using mathematical tools like the Cayley transform, which keeps the overall product orthogonal.
- **Initialize the transformation as the identity matrix**, so the finetuning starts from the pretrained model without drastic changes.
- **Train only the parameters in these sparse matrices**, which are much fewer than a full dense orthogonal matrix.

This approach reduces the number of trainable parameters from *O(d²)* to roughly *O(d log d)*, a huge saving for large models.

---

## Why BOFT Is a Game-Changer

- **Parameter Efficiency**: BOFT dramatically cuts down the number of parameters needed for orthogonal finetuning, making it practical for very large models.
- **Expressivity**: Unlike block-diagonal OFT, BOFT’s butterfly structure can approximate a wide range of orthogonal transformations, including classic fast transforms like the Fourier and Hadamard transforms.
- **Training Stability**: Because orthogonal transformations preserve spectral properties (like the largest singular value), BOFT maintains stable training dynamics.
- **No Inference Overhead**: After finetuning, the learned orthogonal matrices can be merged into the pretrained weights, so there’s no extra cost during inference.

---

## BOFT vs. LoRA vs. Full Finetuning: When to Use What?

- **Full Finetuning** updates all model parameters. It’s expressive but expensive and prone to overfitting, especially with limited data.
- **LoRA** adds low-rank updates to weights, reducing parameters and often working well in NLP tasks. However, it doesn’t explicitly preserve geometric properties of the pretrained model.
- **OFT** preserves neuron relationships via orthogonal transformations but can be parameter-heavy.
- **BOFT** combines the best of both worlds: it keeps the orthogonal structure for stability and generalization while being parameter-efficient thanks to butterfly factorization.

If you want a fine-tuning method that is both **stable and parameter-efficient**, especially for very large models or when you have limited compute, BOFT is an excellent choice.

---

## Real-World Results

The creators of BOFT tested it on a variety of tasks, including:

- Large vision transformers adapting to new image recognition tasks.
- Large language models fine-tuned for different NLP benchmarks.
- Text-to-image diffusion models for controllable generation.

Across the board, BOFT outperformed traditional OFT and often beat LoRA, showing better generalization with fewer parameters.

---

## Wrapping Up

Orthogonal Butterfly Finetuning (BOFT) is a fresh and exciting approach that brings together elegant math, clever algorithmic ideas, and practical needs in modern machine learning. By borrowing the butterfly structure from the FFT world, BOFT makes dense orthogonal transformations feasible and efficient for fine-tuning massive models.

If you’re working with foundation models and want a fine-tuning method that’s both **cheap and stable**, BOFT is definitely worth a look. It’s a great example of how insights from one field (signal processing) can unlock new possibilities in another (machine learning).

## From FFT to Finetuning: Visualizing the Butterfly Structure and Why It Works

# From FFT to Finetuning: Visualizing the Butterfly Structure and Why It Works

If you’ve ever marveled at how the Fast Fourier Transform (FFT) speeds up computations or wondered how massive AI models get fine-tuned efficiently without retraining from scratch, you’re in for a treat. ---

## The Challenge: Efficiently Fine-Tuning Massive Models

Large foundation models like GPT-3 or Stable Diffusion have billions of parameters. Training them from scratch is prohibitively expensive, so researchers focus on *fine-tuning* — adapting these pretrained models to new tasks with minimal extra training.

One promising approach is **Orthogonal Finetuning (OFT)**, which updates model weights by multiplying them with an orthogonal matrix. This preserves important geometric relationships in the model’s neurons, helping maintain the pretrained knowledge. However, orthogonal matrices are huge — a dense orthogonal matrix of size \( d \times d \) has \( d^2 \) parameters, which is often too large to fine-tune efficiently.

The original OFT tried to reduce parameters by using block-diagonal orthogonal matrices — think of splitting the big matrix into smaller independent blocks. This saves parameters but limits expressiveness and can introduce unwanted biases.

So, the question is: **Can we build a dense orthogonal matrix that’s still parameter-efficient?**

---

## Enter the Butterfly Structure: Inspiration from FFT

The answer comes from a surprising place — the **butterfly structure** used in the Cooley-Tukey FFT algorithm.

### What is the Butterfly Structure?

In FFT, the butterfly structure is a clever way to break down a big transformation into a sequence of smaller, sparse steps. Each step only connects a few inputs to outputs, but when combined, they produce a dense transformation efficiently.

Imagine a grid of nodes arranged in layers. Each layer represents a stage in the transformation, and edges between nodes represent how information flows from one stage to the next. The butterfly graph ensures that information from *every* input node can reach *every* output node through a carefully designed sparse network of connections.

---

## Visualizing the Butterfly Graph for \( d=8 \)

Let’s walk through a small example with \( d=8 \) (meaning our orthogonal matrix is \( 8 \times 8 \)).

### The Grid Layout

- We have \( m+1 \) layers of nodes, where \( m = \log_2 d = 3 \).
- Each layer has 8 nodes.
- Edges only connect nodes between adjacent layers.

```
Layer 1 (Input):  8 nodes
Layer 2:          8 nodes
Layer 3:          8 nodes
Layer 4 (Output): 8 nodes
```

### Sparse Connections at Each Stage

At each stage, nodes are connected in pairs, forming small \( 2 \times 2 \) orthogonal blocks (think of simple rotations). The butterfly pattern ensures that over the 3 stages, information from any input node can reach any output node.

Here’s a simplified depiction of connections between layers:

- **Stage 1:** Connect nodes in pairs (1-2, 3-4, 5-6, 7-8)
- **Stage 2:** Connect nodes in pairs with a stride of 2 (1-3, 2-4, 5-7, 6-8)
- **Stage 3:** Connect nodes in pairs with a stride of 4 (1-5, 2-6, 3-7, 4-8)

Each connection corresponds to a sparse orthogonal matrix factor.

---

## How Sparse Factors Compose into a Dense Transform

Each stage corresponds to a sparse orthogonal matrix \(\mathbf{B}_i\) with only \( d \) non-zero entries arranged in these small blocks. When you multiply these sparse matrices together:

\[
\mathbf{R} = \mathbf{B}_3 \mathbf{B}_2 \mathbf{B}_1
\]

the product \(\mathbf{R}\) becomes a dense orthogonal matrix. This means every output node depends on every input node, even though each individual factor is sparse.

---

## The Information Transmission View

The paper introduces a neat way to think about this: **information transmission on a grid-structured graph**.

- Each node in the first layer is a source of information.
- Each node in the last layer is a receiver.
- The sparse matrices \(\mathbf{B}_i\) define how information flows between layers.
- The butterfly graph ensures *dense connectivity* — every input can influence every output.
- The sparsity of each \(\mathbf{B}_i\) keeps the number of trainable parameters low.

This perspective helps us understand why the butterfly factorization is so efficient: it balances *expressivity* (dense transformations) with *parameter efficiency* (sparse factors).

---

## Parameter Count and Scaling

- A full dense orthogonal matrix of size \( d \times d \) has roughly \( d^2 \) parameters.
- The butterfly factorization uses \( m = \log_2 d \) sparse factors.
- Each sparse factor has about \( d \) parameters.
- Total parameters scale as \( \mathcal{O}(d \log d) \), a huge saving for large \( d \).

For example, for \( d=1024 \), instead of over a million parameters, you only need about \( 1024 \times 10 = 10,240 \) parameters.

---

## Interactive Code Snippet: Visualizing Paths in the Butterfly Graph

Here’s a simple Python snippet using `networkx` and `matplotlib` to visualize the butterfly graph for \( d=8 \). You can see how paths connect inputs to outputs.

```python
import networkx as nx
import matplotlib.pyplot as plt

def build_butterfly_graph(d):
    import math
    m = int(math.log2(d))
    G = nx.DiGraph()
    layers = []
    for i in range(m+1):
        layer_nodes = [f"L{i}_N{j}" for j in range(d)]
        layers.append(layer_nodes)
        G.add_nodes_from(layer_nodes)
    for i in range(m):
        stride = 2 ** i
        for j in range(d):
            # Connect node j in layer i to nodes in layer i+1
            pair = (j // (2*stride)) * (2*stride)
            if (j - pair) < stride:
                G.add_edge(layers[i][j], layers[i+1][j])
                G.add_edge(layers[i][j], layers[i+1][j + stride])
            else:
                G.add_edge(layers[i][j], layers[i+1][j])
                G.add_edge(layers[i][j], layers[i+1][j - stride])
    return G, layers

def plot_butterfly_graph(G, layers):
    pos = {}
    for i, layer in enumerate(layers):
        for j, node in enumerate(layer):
            pos[node] = (i, -j)
    plt.figure(figsize=(12,6))
    nx.draw(G, pos, with_labels=False, node_size=300, node_color='skyblue', arrowsize=15)
    plt.title("Butterfly Graph for d=8")
    plt.axis('off')
    plt.show()

G, layers = build_butterfly_graph(8)
plot_butterfly_graph(G, layers)
```

## BOFT in Practice: Step-by-Step Guide to Adding Orthogonal Butterfly Finetuning to Your Model

# BOFT in Practice: Step-by-Step Guide to Adding Orthogonal Butterfly Finetuning to Your Model

If you’re an engineer or machine learning practitioner looking to efficiently finetune large foundation models, you’ve probably heard about Orthogonal Finetuning (OFT) and its new, more parameter-efficient cousin, Orthogonal Butterfly Finetuning (BOFT). BOFT cleverly uses butterfly matrix factorization to drastically reduce the number of trainable parameters while preserving the benefits of orthogonal transformations. But how do you actually implement BOFT in your own projects? In this post, we’ll walk you through the practical steps, from the math behind the Cayley parameterization of 2x2 blocks to tips on initialization, dropout, batching, and debugging. We’ll also share simple recipes for integrating BOFT with popular frameworks like PyTorch and Hugging Face Transformers.

---

## What is BOFT, and Why Should You Care?

Before diving into implementation, a quick refresher: BOFT is a parameter-efficient finetuning method that represents a dense orthogonal matrix as a product of multiple sparse orthogonal matrices arranged in a butterfly structure. This approach reduces the number of trainable parameters from quadratic in the dimension (as in full OFT) to roughly \(O(d \log d)\), where \(d\) is the dimension of the layer you’re finetuning.

Why orthogonal matrices? Because they preserve the pairwise angles between neurons, helping retain the pretrained model’s knowledge and improving generalization and training stability.

---

## Step 1: Understanding the Core — Cayley Parameterization of 2x2 Orthogonal Blocks

At the heart of BOFT is the idea of building large orthogonal matrices from many small orthogonal blocks, specifically \(2 \times 2\) blocks, arranged in a butterfly pattern.

### What is Cayley Parameterization?

Cayley parameterization is a way to represent an orthogonal matrix \(R\) using a skew-symmetric matrix \(Q\) as:

\[
R = (I + Q)(I - Q)^{-1}
\]

For a \(2 \times 2\) block, the skew-symmetric matrix \(Q\) has the form:

\[
Q = \begin{bmatrix} 0 & -\theta \\ \theta & 0 \end{bmatrix}
\]

where \(\theta\) is a learnable scalar parameter.

### Pseudocode for a Single 2x2 Block

```python
import torch

def cayley_2x2(theta):
    # Construct skew-symmetric matrix Q
    Q = torch.tensor([[0, -theta], [theta, 0]])
    I = torch.eye(2)
    # Compute (I + Q) and (I - Q)
    numerator = I + Q
    denominator = I - Q
    # Inverse of denominator
    denominator_inv = torch.inverse(denominator)
    # Cayley transform
    R = numerator @ denominator_inv
    return R
```

In practice, \(\theta\) will be a learnable parameter tensor, and you’ll apply this block-wise across your model.

---

## Step 2: Building the Butterfly Structure

The butterfly matrix is constructed by stacking these \(2 \times 2\) orthogonal blocks in a specific sparse pattern across multiple layers (denoted by \(m\)) and block sizes (denoted by \(b\)).

- **Block size \(b\)**: Determines the size of each block in the butterfly factorization. Smaller \(b\) means more layers \(m\) are needed to cover the full dimension.
- **Number of layers \(m\)**: Controls the depth of the factorization. More layers increase expressivity but also computational cost.

### How to Choose \(m\) and \(b\)?

- For a model dimension \(d\), a common choice is \(b=2\) and \(m = \log_2 d\), which yields a dense orthogonal matrix with \(O(d \log d)\) parameters.
- Larger \(b\) reduces \(m\) but increases per-block parameter count.
- BOFT subsumes block-diagonal OFT as a special case when \(m=1\).

---

## Step 3: Identity Initialization

To ensure the finetuned model starts close to the pretrained one, initialize all butterfly components as identity matrices. This corresponds to initializing all \(\theta\) parameters in the Cayley transform to zero.

```python
theta = torch.zeros(num_blocks, requires_grad=True)
```

This zero initialization ensures the orthogonal matrix \(R\) starts as the identity, so the initial finetuned weights equal the pretrained weights.

---

## Step 4: Multiplicative Dropout for Regularization

Unlike additive methods like LoRA, BOFT applies a multiplicative update, so standard dropout doesn’t directly apply. Instead, use **multiplicative dropout**:

- Randomly select a percentage \(p_1\) of butterfly layers and \(p_2\) of blocks within those layers.
- Replace the selected blocks with identity matrices during training.

This helps prevent overfitting without breaking the orthogonality constraint.

---

## Step 5: Batching and Efficient Computation

Since BOFT represents the orthogonal matrix as a product of multiple sparse matrices, each forward pass involves multiple matrix multiplications.

### Tips for Efficient Implementation:

- **Batch your inputs** to leverage parallelism.
- **Precompute the product of butterfly components** when possible, especially during evaluation.
- Use **in-place operations** and avoid unnecessary copies.
- Leverage **GPU acceleration** for matrix multiplications.

---

## Step 6: Debugging and Numerical Stability

### Checking Orthogonality

To verify that your orthogonal matrices remain orthogonal during training, compute:

\[
R^\top R \approx I
\]

In code:

```python
def check_orthogonality(R, tol=1e-5):
    I = torch.eye(R.size(0)).to(R.device)
    diff = torch.norm(R.T @ R - I)
    return diff < tol
```

If the difference grows large, consider:

- Reducing learning rate.
- Using gradient clipping.
- Ensuring Cayley parameterization is correctly implemented.

### Numerical Stability

- The Cayley transform involves matrix inversion \((I - Q)^{-1}\). For small \(\theta\), this is stable, but large \(\theta\) can cause instability.
- Initialize \(\theta\) near zero and use small learning rates.
- Monitor the condition number of \((I - Q)\) during training.

---

## Step 7: Integrating BOFT with PyTorch and Hugging Face Transformers

Here’s a simple recipe to add BOFT to a linear layer in PyTorch:

```python
import torch
import torch.nn as nn

class BOFTLayer(nn.Module):
    def __init__(self, d, m, b):
        super().__init__()
        self.d = d
        self.m = m
        self.b = b
        # Initialize learnable parameters theta for each 2x2 block in each layer
        self.theta = nn.ParameterList()
        for _ in range(m):
            num_blocks = d // b
            self.theta.append(nn.Parameter(torch.zeros(num_blocks)))

    def forward(self, W0, x):
        R = torch.eye(self.d).to(x.device)
        for i in range(self.m):
            # Construct butterfly component for layer i
            B = self.construct_butterfly_component(self.theta[i])
            R = B @ R
        W = R @ W0
        return W.T @ x

    def construct_butterfly_component(self, theta_layer):
        # Build block-diagonal matrix of 2x2 Cayley blocks
        blocks = []
        for theta in theta_layer:
            blocks.append(cayley_2x2(theta))
        return torch.block_diag(*blocks)
```

To integrate with Hugging Face Transformers, replace the linear layers you want to finetune with `BOFTLayer` wrappers, passing the pretrained weights as `W0`.

---

## Step 8: Performance Trade-offs

- **Parameter efficiency**: BOFT reduces trainable parameters significantly compared to full OFT.
- **Training speed**: Slightly slower than OFT due to multiple matrix multiplications.
- **Inference speed**: No overhead, as the learned orthogonal matrix can be merged into pretrained weights.
- **Expressivity vs. regularity**: Adjust \(m\) and \(b\) to balance model capacity and overfitting risk.

## BOFT vs LoRA vs OFT: Which Parameter-Efficient Finetuning Method Should You Use?

# BOFT vs LoRA vs OFT: Which Parameter-Efficient Finetuning Method Should You Use?

If you’re an ML practitioner working with large foundation models—whether vision transformers, large language models (LLMs), or text-to-image diffusion models—you’ve probably faced the challenge of adapting these massive pretrained models to your specific downstream tasks without retraining from scratch. Parameter-efficient finetuning (PEFT) methods have become the go-to solution, but with several options on the table, how do you decide which one fits your needs best?

In this post, we’ll break down three prominent PEFT methods: **LoRA**, **Orthogonal Finetuning (OFT)**, and the newly proposed **Orthogonal Butterfly Finetuning (BOFT)**. We’ll compare their core mechanisms, parameter efficiency, expressivity, spectral properties, training stability, and downstream performance. By the end, you’ll have a clearer idea of which method to pick for your next project.

---

## Understanding the Basics: Additive vs. Multiplicative Updates

Before diving into comparisons, it’s important to understand the fundamental difference in how these methods update pretrained weights.

- **LoRA (Low-Rank Adaptation)** updates the pretrained weight matrix by *adding* a low-rank matrix. Think of it as a gentle additive tweak that modifies the model’s behavior without changing its core structure. This low-rank update is parameter-efficient because it only learns a small number of parameters relative to the full weight matrix.

- **OFT (Orthogonal Finetuning)** and **BOFT (Orthogonal Butterfly Finetuning)**, on the other hand, apply a *multiplicative* update. They learn an orthogonal matrix that transforms the neurons in the pretrained model. This multiplicative approach preserves the geometric relationships (pairwise angles) between neurons, which helps retain the pretrained knowledge more faithfully.

---

## Parameter Budgets: How Many Parameters Are We Talking About?

- **LoRA** uses a low-rank factorization, so the number of trainable parameters scales roughly with the rank times the sum of input and output dimensions. This is often very small compared to the full model.

- **OFT** originally uses a full orthogonal matrix for updates, which requires on the order of \(d^2\) parameters for a \(d \times d\) matrix—prohibitively large for big models. To reduce this, OFT employs a block-diagonal structure, splitting the matrix into smaller blocks. This reduces parameters but at the cost of expressivity.

- **BOFT** innovates by factorizing the orthogonal matrix into a product of sparse matrices inspired by the butterfly structure from the fast Fourier transform algorithm. This clever factorization reduces the parameter count to roughly \(\mathcal{O}(d \log d)\), striking a balance between full expressivity and parameter efficiency.

**In short:**

| Method | Parameter Count (approx.) | Notes |
|--------|--------------------------|-------|
| LoRA   | Low (depends on rank)     | Additive low-rank update |
| OFT    | High (\(d^2\)) full; lower with block-diagonal | Multiplicative orthogonal, block-diagonal reduces params but limits expressivity |
| BOFT   | Moderate (\(d \log d\))   | Multiplicative orthogonal with butterfly factorization |

---

## Expressivity: How Flexible Are the Updates?

- **LoRA’s** low-rank additive updates are expressive enough for many tasks but can be limited when the adaptation requires more complex transformations.

- **OFT’s** full orthogonal matrix is highly expressive, preserving neuron relationships perfectly. However, the block-diagonal variant reduces expressivity because it applies independent orthogonal transformations to separate blocks, limiting cross-block interactions.

- **BOFT** offers a middle ground. Its butterfly factorization allows it to approximate a dense orthogonal matrix with far fewer parameters than full OFT. This structure can recover many classic linear transforms (like Fourier and Hadamard transforms), giving it a rich inductive bias and better expressivity than block-diagonal OFT at similar parameter budgets.

Simulation studies show that BOFT with smaller block sizes and more factorization layers can approximate dense orthogonal matrices more accurately than block-diagonal OFT with larger blocks, meaning better expressivity per parameter.

---

## Spectral Properties and Training Stability

One of the key advantages of **OFT** and **BOFT** is their preservation of the spectral norm of the pretrained weight matrix. Because they multiply the pretrained weights by an orthogonal matrix, the largest singular value remains unchanged. This spectral norm preservation is linked to:

- **Better training stability:** Avoids exploding or vanishing gradients.
- **Improved generalization:** Maintains the pretrained model’s learned geometry.

**LoRA**, being additive, does not guarantee spectral norm preservation, which can sometimes lead to less stable training or overfitting.

---

## Downstream Performance: What Do Experiments Say?

The original OFT showed strong generalization and stable training on text-to-image diffusion models but suffered from large parameter counts unless block-diagonal approximations were used.

BOFT, by contrast, has been tested across a wider range of tasks—including large vision transformers, LLMs, and diffusion models—and consistently outperforms both LoRA and OFT variants in terms of:

- **Parameter efficiency:** Achieving better or comparable performance with fewer trainable parameters.
- **Generalization:** Thanks to its structured inductive bias from butterfly factorization.
- **Training stability:** Benefiting from spectral norm preservation and smooth interpolation between identity and full orthogonal matrices.

---

## Practical Decision Rules: Which Method Should You Use?

Here’s a quick guide to help you choose:

- **If you want the simplest, most widely supported method with minimal overhead:**  
  Use **LoRA**. It’s easy to implement, has low parameter cost, and works well for many NLP tasks.

- **If you prioritize preserving pretrained knowledge and training stability, and can afford more parameters:**  
  Use **OFT** with block-diagonal structure for moderate parameter budgets, or full OFT if you have the resources.

- **If you want a sweet spot between parameter efficiency, expressivity, and stability, especially for large models or diverse tasks:**  
  Use **BOFT**. It offers better expressivity than block-diagonal OFT at similar or lower parameter counts, preserves spectral properties, and has demonstrated superior downstream performance.

## Beyond Block-Diagonal: Why Structured Sparsity (Butterfly) Generalizes Better Than Naive Sparsity

# Beyond Block-Diagonal: Why Structured Sparsity (Butterfly) Generalizes Better Than Naive Sparsity

When it comes to adapting massive pretrained models to new tasks, efficiency is king. We want to tweak as few parameters as possible while still getting great performance. One popular approach is **Orthogonal Finetuning (OFT)**, which updates model weights by multiplying them with an orthogonal matrix. This preserves important geometric relationships in the model, helping it generalize better.

But there’s a catch: orthogonal matrices are huge! A dense orthogonal matrix for a layer with dimension *d* has on the order of *d²* parameters, which is often too expensive. To tackle this, the original OFT uses a **block-diagonal sparsity pattern** — breaking the big matrix into smaller independent blocks. This reduces parameters but at a cost: it limits expressiveness and can introduce undesirable biases.

Enter the **butterfly structure**, a clever way to build dense orthogonal matrices from a product of sparse ones, inspired by the famous Cooley-Tukey Fast Fourier Transform (FFT) algorithm. This structured sparsity offers a sweet spot between parameter efficiency and expressiveness, leading to better generalization and less overfitting.

Let’s dive into why butterfly sparsity beats naive block-diagonal sparsity and how it shapes the future of parameter-efficient finetuning.

---

## The Problem with Naive Block-Diagonal Sparsity

Imagine you have a big square matrix representing an orthogonal transformation on your model’s neurons. To reduce parameters, you split this matrix into smaller blocks along the diagonal and only learn those blocks independently. This is the block-diagonal approach used in OFT.

While this saves parameters, it comes with some serious downsides:

- **Limited Expressiveness:** Each block only transforms a subset of dimensions independently. The overall matrix can’t capture interactions across blocks, so it can’t approximate many useful transformations.

- **Rigid Inductive Bias:** The block structure assumes that neuron dimensions can be cleanly divided into groups that don’t interact, which is rarely true in practice.

- **Cannot Recover Classic Transforms:** Block-diagonal matrices can’t represent well-known linear transforms like the FFT or Hadamard transform, which are dense and highly structured.

In short, block-diagonal sparsity is a blunt tool — it reduces parameters but at the cost of flexibility and generalization.

---

## Butterfly Sparsity: A Smarter Way to Structure Orthogonal Matrices

The butterfly structure comes from the Cooley-Tukey FFT algorithm, which efficiently computes the discrete Fourier transform by recursively breaking it down into smaller transforms. This algorithm’s underlying graph — called a **butterfly graph** — connects inputs and outputs through a series of sparse, structured steps.

Translating this to matrix factorization, a butterfly matrix is a product of multiple sparse orthogonal matrices, each with a very specific sparsity pattern. The magic is that:

- **Dense Connectivity with Sparse Factors:** Although each factor is sparse, their product is a dense matrix. This means every input dimension can influence every output dimension, unlike block-diagonal matrices.

- **Parameter Efficiency:** The number of parameters grows roughly like *d log d* instead of *d²*, a huge saving for large dimensions.

- **Expressiveness:** Butterfly matrices can exactly represent many classic fast transforms like FFT, Hadamard, and discrete cosine transforms. This means they capture rich, meaningful interactions between dimensions.

- **Smooth Interpolation:** Butterfly structures provide a smooth path between the identity matrix (no change) and full orthogonal matrices, allowing for controlled adaptation.

---

## Why Does Butterfly Structure Help Generalization?

The key lies in **inductive bias** — the assumptions a model makes about the data and task that guide learning.

- **Structured Sparsity Reflects Natural Data Patterns:** Many signals and features in vision, language, and audio have hierarchical or frequency-based structures. Butterfly matrices naturally encode these patterns, making them well-suited to adapt pretrained models without overfitting.

- **Avoids Overfitting by Limiting Hypothesis Space:** By restricting the finetuning transformations to butterfly-structured orthogonal matrices, the model can’t fit arbitrary noise. This acts as a regularizer, improving stability and generalization.

- **Recovers Useful Transforms:** Since butterfly matrices can represent FFT and related transforms, they can efficiently capture global dependencies and symmetries in data, which block-diagonal matrices miss.

The paper *Parameter-Efficient Orthogonal Finetuning via Factorization* provides both theoretical and experimental support for butterfly sparsity:

- **Information Transmission View:** They model the factorization of orthogonal matrices as transmitting information through a layered graph. Butterfly graphs achieve dense connectivity with minimal edges, optimizing parameter efficiency.

- **Expressivity Theorem:** Butterfly factorizations can approximate a much larger subset of the orthogonal group than block-diagonal matrices with the same parameter budget.

- **Approximation Experiments:** Simulations show that butterfly-structured matrices approximate random dense orthogonal matrices more accurately than block-diagonal ones for the same number of parameters.

## Understanding Cayley Parameterization and Orthogonality Constraints for Stable Finetuning

# Understanding Cayley Parameterization and Orthogonality Constraints for Stable Finetuning

When it comes to adapting large pretrained models to new tasks, stability and efficiency are key. One elegant approach to finetuning involves preserving orthogonality in the transformations applied to model weights. This blog post dives into the heart of this idea, focusing on the Cayley parameterization—a powerful mathematical tool that ensures orthogonality during finetuning—and why maintaining orthogonality matters for training stability and generalization.

## Why Orthogonality Matters in Finetuning

Before we get into the math, let's understand the motivation. When finetuning a pretrained model, we want to adapt it to a new task without losing the valuable knowledge it has already learned. One way to do this is to ensure that the transformations applied to the model’s weight matrices preserve certain geometric properties, such as the angles between neurons.

Orthogonal matrices have a special property: they preserve lengths and angles. This means that when you multiply a weight matrix by an orthogonal matrix, the relative geometry of the neurons remains intact. Preserving these relationships helps maintain the semantic knowledge encoded during pretraining, leading to more stable training and better generalization on downstream tasks.

Moreover, orthogonal transformations preserve the spectral norm (largest singular value) of the weight matrix. This is crucial because the spectral norm influences the stability of gradient updates and the overall training dynamics. By keeping it constant, orthogonal finetuning methods avoid exploding or vanishing gradients, which are common pitfalls in deep learning.

## The Challenge: How to Keep Orthogonality During Training?

Orthogonal matrices are not just any matrices; they satisfy the condition \( R^\top R = I \), where \( R \) is the orthogonal matrix and \( I \) is the identity matrix. This constraint is nonlinear and makes direct optimization tricky.

Naively updating the matrix \( R \) with gradient descent can easily break orthogonality, leading to unstable training or loss of the desired geometric properties. So, how do we ensure that \( R \) remains orthogonal throughout the finetuning process?

## Enter the Cayley Parameterization

The Cayley transform offers a neat solution. It parameterizes an orthogonal matrix \( R \) in terms of a skew-symmetric matrix \( Q \) (i.e., \( Q^\top = -Q \)) as follows:

\[
R = (I + Q)(I - Q)^{-1}
\]

Here, \( I \) is the identity matrix, and \( Q \) contains the trainable parameters. Because \( Q \) is skew-symmetric, the resulting \( R \) is guaranteed to be orthogonal, provided \( (I - Q) \) is invertible.

This parameterization transforms the constrained optimization problem (keeping \( R \) orthogonal) into an unconstrained one over \( Q \), which is easier to handle with standard gradient-based methods.

### Skew-Symmetric Matrix: What Is It?

A skew-symmetric matrix \( Q \) satisfies \( Q^\top = -Q \). This means the diagonal elements are zero, and the off-diagonal elements are negatives of each other across the diagonal. This structure reduces the number of free parameters roughly by half compared to a general matrix, which is beneficial for parameter efficiency.

### Identity Initialization

A practical advantage of the Cayley parameterization is that it naturally supports identity initialization. By initializing \( Q \) as the zero matrix, the Cayley transform yields:

\[
R = (I + 0)(I - 0)^{-1} = I
\]

This means the finetuning starts from the pretrained weights without any modification, ensuring a smooth transition and preventing sudden jumps in model behavior.

## Numerical Considerations and Stability

While the Cayley transform is elegant, it requires computing the inverse of \( (I - Q) \) at every update step. For large matrices, this can be computationally expensive and numerically sensitive.

To mitigate this, implementations often:

- Use efficient matrix inversion techniques or approximate inverses.
- Restrict \( Q \) to have certain sparsity or structure (e.g., block-diagonal or butterfly structures) to reduce computational overhead.
- Ensure \( Q \) remains small in magnitude during training to keep \( (I - Q) \) well-conditioned and invertible.

These strategies help maintain numerical stability and keep training efficient.

## Orthogonality vs. Other Regularization Techniques

You might wonder how orthogonality preservation compares to more common regularization methods like weight decay or spectral norm regularization.

- **Weight Decay** penalizes large weights but does not explicitly preserve geometric properties of the weight matrices.
- **Spectral Norm Regularization** controls the largest singular value but typically requires additional computations and does not guarantee orthogonality.
- **Orthogonal Finetuning via Cayley Parameterization** directly enforces orthogonality, preserving angles and spectral norms exactly, which leads to more stable gradients and better generalization.

Empirical studies have shown that orthogonal finetuning methods often outperform low-rank adaptation techniques (like LoRA) in terms of training stability and generalization, especially when combined with parameter-efficient structures like butterfly factorizations.

## Summary: Why Cayley Parameterization Is a Game-Changer

- **Guarantees Orthogonality:** Ensures the finetuning transformation preserves geometric properties.
- **Enables Stable Training:** Maintains spectral norms, preventing gradient issues.
- **Supports Identity Initialization:** Starts finetuning from the pretrained model without abrupt changes.
- **Facilitates Parameter Efficiency:** Works well with structured parameterizations to reduce overhead.

By leveraging the Cayley transform and orthogonality constraints, researchers have developed finetuning methods that are both stable and efficient, enabling large foundation models to adapt gracefully to new tasks without retraining from scratch.

## What Are the Key Hyperparameters in BOFT?

BOFT’s magic lies in representing a dense orthogonal matrix as a product of multiple sparse orthogonal butterfly components. This factorization introduces a few important hyperparameters that control the trade-off between expressivity, parameter efficiency, and training stability:

- **Number of Butterfly Stages (m):** This is how many sparse butterfly matrices you multiply together. More stages mean more expressive power but also more parameters and computation.

- **Block Size (b):** Each butterfly component is made up of blocks of size \( b \times b \). Larger blocks increase expressivity but also parameter count.

- **Multiplicative Dropout Rates (p1, p2):** To prevent overfitting, BOFT introduces a multiplicative dropout that randomly replaces some butterfly components or blocks with identity matrices during training. Here, \( p_1 \) controls the dropout rate over butterfly components, and \( p_2 \) controls dropout over blocks within each component.

- **Initialization Strategy:** BOFT initializes all butterfly components as identity matrices to start finetuning close to the pretrained model.

- **Stopping Criteria:** Like any finetuning method, deciding when to stop training is crucial to avoid overfitting or underfitting.

---

## How Do These Hyperparameters Affect BOFT?

### Number of Butterfly Stages (m)

- **Expressivity vs. Efficiency:** Increasing \( m \) allows BOFT to approximate more complex orthogonal transformations. For example, with \( m = \log d \) (where \( d \) is the dimension), BOFT can represent a dense orthogonal matrix with only \( \mathcal{O}(d \log d) \) parameters.

- **Training Overhead:** More stages mean more matrix multiplications during training, which can increase runtime.

- **Practical Tip:** Start with a moderate number of stages (e.g., \( m = 4 \) to \( 6 \)) for typical model sizes. This balances expressivity and efficiency.

### Block Size (b)

- **Granularity of Transformation:** Larger blocks allow more complex local transformations within each butterfly component.

- **Parameter Count:** The number of trainable parameters scales roughly with \( (b - 1) \times d \times m / 2 \).

- **Practical Tip:** For many applications, a block size of 2 or 4 works well. Smaller blocks reduce parameters but may limit expressivity.

### Multiplicative Dropout Rates (p1, p2)

- **Preventing Overfitting:** Since BOFT updates weights multiplicatively, conventional dropout doesn’t apply directly. Multiplicative dropout randomly replaces some butterfly components or blocks with identity matrices during training, effectively “dropping” those transformations.

- **Balancing Regularization:** Higher dropout rates increase regularization but may slow convergence.

- **Practical Tip:** Start with modest dropout rates, such as \( p_1 = 0.1 \) (10% of butterfly components dropped) and \( p_2 = 0.1 \) (10% of blocks dropped). Adjust based on validation performance.

### Initialization Strategy

- **Identity Initialization:** BOFT initializes all butterfly components as identity matrices, ensuring the finetuned model starts exactly at the pretrained weights.

- **Why It Matters:** This zero-initialization approach helps maintain stability and prevents large deviations early in training.

- **Practical Tip:** Always use identity initialization for BOFT to ensure smooth finetuning.

### Stopping Criteria

- **Early Stopping:** Monitor validation loss or task-specific metrics to decide when to stop finetuning.

- **Avoid Overfitting:** Since BOFT is parameter-efficient but still expressive, overfitting can occur if training goes on too long.

- **Practical Tip:** Use early stopping with patience (e.g., stop if no improvement after 5 epochs) or set a fixed number of finetuning steps based on dataset size.

# When Butterflies Aren't Enough: Limitations, Open Problems and Future Directions for BOFT

If you’ve been following the latest advances in adapting large foundation models, you might have come across a fascinating new method called Orthogonal Butterfly Finetuning, or BOFT for short. ## The Promise of BOFT in a Nutshell

Before diving into the challenges, let’s quickly recap what BOFT is all about. When fine-tuning large models, it’s often too expensive or impractical to update all parameters. Orthogonal Finetuning (OFT) is a principled approach that updates the model by multiplying pretrained weights with an orthogonal matrix, preserving important geometric properties like angles between neurons. BOFT tackles this by factorizing the orthogonal matrix into a product of sparse matrices arranged in a butterfly structure, inspired by the Cooley-Tukey fast Fourier transform. ## Current Limitations of BOFT

While BOFT is a significant step forward, it’s important to understand its current limitations:

### 1. Training Runtime Overhead

BOFT represents the orthogonal matrix as a product of multiple sparse matrices. This means that during training, the model must perform several matrix multiplications sequentially for each forward pass. Compared to simpler methods like block-diagonal OFT or low-rank adaptations, this introduces additional computational overhead and longer training times.

Although this overhead is manageable and does not affect inference speed (since the learned matrices can be merged into the pretrained weights after training), it remains a practical concern, especially when fine-tuning very large models or working with limited computational resources.

### 2. Power-of-Two Dimension Constraints

The butterfly factorization naturally fits dimensions that are powers of two, due to its recursive halving structure. This can be restrictive in practice because many model layers have dimensions that are not powers of two.

While there are workarounds such as padding or adapting the factorization, these solutions are not always elegant or efficient. Extending BOFT to handle arbitrary dimensions seamlessly is an open challenge.

### 3. Unknown Optimal Network Topologies

BOFT’s design is inspired by the butterfly network topology, which is well-studied in signal processing and computer networking for efficient information transmission. However, it’s not yet clear whether the butterfly structure is the absolute best choice for parameter-efficient orthogonal finetuning.

The paper introduces an information transmission framework that views the factorization as passing information through a layered graph. This perspective opens the door to exploring other network topologies that might achieve even better trade-offs between parameter efficiency, expressivity, and computational cost.

- **What are the theoretical limits of BOFT’s expressivity and generalization?** While BOFT is more expressive than block-diagonal OFT, it still represents a structured subset of all orthogonal matrices. Understanding how this structure affects learning dynamics and downstream task performance is an open area.

## Promising Directions for Future Work

Building on these questions, here are some exciting directions that could push BOFT and orthogonal finetuning forward:

- **Exploring New Factorization Topologies:** Inspired by the information transmission view, researchers can investigate other graph structures that enable dense connectivity with fewer parameters or better inductive biases. # Build a Toy: Implementing a 1-Layer BOFT Adapter from Scratch (Code Walkthrough)

It’s a clever way to finetune huge pretrained models by applying structured orthogonal transformations that are both expressive and parameter-efficient.

In this post, we’ll take a hands-on approach and build a minimal BOFT adapter from scratch. We’ll wrap a pretrained linear layer with a BOFT module that uses simple 2x2 orthogonal blocks (via Cayley rotations) arranged in a butterfly pattern. Along the way, we’ll cover:

- What BOFT is and why it matters
- How to implement the core butterfly component with 2x2 Cayley rotations
- How to initialize the adapter as identity (so we start from the pretrained model)
- How to apply multiplicative dropout to prevent overfitting
- Running a tiny finetuning experiment to see it in action

Let’s dive in!

---

## What is BOFT and Why Should You Care?

When adapting large models like GPT or vision transformers, retraining all parameters is often impossible due to compute and memory constraints. Parameter-efficient finetuning (PEFT) methods aim to update only a small subset of parameters while preserving the pretrained knowledge.

One such method is **Orthogonal Finetuning (OFT)**, which updates the pretrained weights by multiplying them with an orthogonal matrix. This preserves the geometric relationships (angles) between neurons, helping maintain the model’s learned structure and improving generalization.

However, a full orthogonal matrix has a huge number of parameters (quadratic in dimension), so OFT uses block-diagonal orthogonal matrices to reduce parameters. But this limits expressiveness because the blocks operate independently.

**BOFT** solves this by factorizing a dense orthogonal matrix into a product of sparse orthogonal matrices arranged in a **butterfly structure**—inspired by the fast Fourier transform algorithm. This lets us represent a dense orthogonal transform with far fewer parameters (roughly proportional to dimension × log dimension), while still being expressive.

In practice, BOFT applies a sequence of small 2x2 orthogonal rotations (Cayley transforms) arranged in a butterfly pattern to the pretrained weights, enabling efficient and effective finetuning.

---

## Building Blocks: 2x2 Cayley Rotations

At the heart of BOFT are small orthogonal blocks—specifically, 2x2 orthogonal matrices parameterized via the **Cayley transform**. This transform ensures the matrix is orthogonal and initialized as identity when parameters are zero.

A 2x2 orthogonal matrix can be represented as a rotation:

\[
R(\theta) = \begin{bmatrix}
\cos \theta & -\sin \theta \\
\sin \theta & \cos \theta
\end{bmatrix}
\]

The Cayley transform parameterizes this rotation via a skew-symmetric matrix \( Q \):

\[
Q = \begin{bmatrix}
0 & -\phi \\
\phi & 0
\end{bmatrix}
\]

and the orthogonal matrix is:

\[
R = (I + Q)(I - Q)^{-1}
\]

When \(\phi = 0\), \(Q = 0\) and \(R = I\), so the transformation starts as identity.

---

## Implementing a 1-Layer BOFT Adapter in PyTorch

Let’s implement a minimal BOFT module that wraps a pretrained linear layer. We’ll:

- Use a single butterfly component (i.e., one layer of 2x2 blocks)
- Parameterize each 2x2 block with a learnable scalar \(\phi\)
- Initialize all \(\phi\) to zero (identity init)
- Apply multiplicative dropout by randomly replacing some blocks with identity during training

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class Cayley2x2(nn.Module):
    def __init__(self):
        super().__init__()
        # Single scalar parameter per 2x2 block
        self.phi = nn.Parameter(torch.zeros(1))

    def forward(self):
        phi = self.phi
        Q = torch.tensor([[0., -phi], [phi, 0.]], device=phi.device)
        I = torch.eye(2, device=phi.device)
        # Cayley transform: R = (I + Q)(I - Q)^{-1}
        R = torch.linalg.solve(I - Q, I + Q)
        return R

class BOFTLayer(nn.Module):
    def __init__(self, dim, dropout_prob=0.0):
        super().__init__()
        assert dim % 2 == 0, "Dimension must be even for 2x2 blocks"
        self.dim = dim
        self.dropout_prob = dropout_prob
        self.num_blocks = dim // 2
        # One Cayley2x2 per 2x2 block along the diagonal
        self.blocks = nn.ModuleList([Cayley2x2() for _ in range(self.num_blocks)])

    def forward(self, W):
        """
        W: pretrained weight matrix of shape (dim, out_features)
        Returns: transformed weight matrix of same shape
        """
        device = W.device
        R = torch.zeros((self.dim, self.dim), device=device)

        # Build block-diagonal orthogonal matrix R from 2x2 blocks
        for i, block in enumerate(self.blocks):
            R[2*i:2*i+2, 2*i:2*i+2] = block()

        # Apply multiplicative dropout: randomly replace some blocks with identity
        if self.training and self.dropout_prob > 0:
            mask = (torch.rand(self.num_blocks, device=device) > self.dropout_prob).float()
            for i, keep in enumerate(mask):
                if keep < 0.5:
                    R[2*i:2*i+2, 2*i:2*i+2] = torch.eye(2, device=device)

        # Multiply pretrained weights by orthogonal matrix
        W_new = R @ W
        return W_new
```

## Putting It All Together: Finetuning a Toy Model

Suppose we have a pretrained linear layer \( W^0 \) of size \( d \times n \) (e.g., 8 × 4). We want to finetune it on a tiny classification task with few examples.

```python
# Toy pretrained weight matrix (fixed)
d, n = 8, 4
W0 = torch.randn(d, n)

# BOFT adapter wrapping W0
boft = BOFTLayer(dim=d, dropout_prob=0.1)

# Simple linear model using BOFT-transformed weights
class FinetuneModel(nn.Module):
    def __init__(self, W0, boft):
        super().__init__()
        self.W0 = W0
        self.boft = boft

    def forward(self, x):
        W_new = self.boft(self.W0)
        return x @ W_new  # x shape: (batch, d)

model = FinetuneModel(W0, boft)

# Dummy dataset: classify 2 classes with 4-dimensional inputs
X = torch.randn(20, d)
y = (X[:, 0] + X[:, 1] > 0).long()  # simple rule-based labels

# Training loop
optimizer = torch.optim.Adam(model.boft.parameters(), lr=0.1)
criterion = nn.CrossEntropyLoss()

for epoch in range(50):
    model.train()
    optimizer.zero_grad()
    logits = model(X)
    loss = criterion(logits, y)
    loss.backward()
    optimizer.step()

    if epoch % 10 == 0:
        pred = logits.argmax(dim=1)
        acc = (pred == y).float().mean()
        print(f"Epoch {epoch}: Loss={loss.item():.4f}, Acc={acc.item():.4f}")
```

## What Did We Just Build?

- A **BOFT adapter** that learns a block-orthogonal transformation on top of a pretrained weight matrix.
- The orthogonal blocks are parameterized via **Cayley transforms**, ensuring orthogonality and identity initialization.
- We applied **multiplicative dropout** by randomly replacing some blocks with identity during training, helping prevent overfitting.
- We ran a tiny finetuning experiment on a toy dataset, showing the adapter can learn meaningful transformations end-to-end.

Training BOFT in Practice

# Optimization loop: parameterizing $2\times 2$ (or $2b\times 2b$) orthogonal blocks via $Q$

The central implementation detail of BOFT in practice is how one turns each small block into an orthogonal factor that is nevertheless easy to optimize. The standard story one reads elsewhere is that the Cayley transform requires a skew-symmetric parameter $Q$ with $Q=-Q^\top$. In practice this is unnecessary and even counterproductive: treating $Q$ as a symmetric matrix ($Q=Q^\top$) yields more stable gradients and much faster convergence. Concretely, we write the parameterization for a $2\times 2$ block as
$R = (I + Q)(I - Q)^{-1}$,
but we take $Q$ to be symmetric and initialize it with a small Gaussian noise. This symmetric choice makes $(I-Q)$ better conditioned in the usual optimization regimes, because symmetric $Q$ concentrates eigenvalues on the real line and prevents complex rotations which are hard to learn. For block sizes of $2b\times 2b$, the same recipe works: let $Q\in\mathbb{R}^{2b\times 2b}$ be symmetric and parameterize each block via the same Cayley formula. Empirically one should ensure $Q$ begins with entries sampled from $\mathcal{N}(0,\sigma^2)$ with $\sigma\approx 0.1$; zero initialization is a pathological choice that makes the network lazy and prevents BOFT from finding diverse orthogonal transforms.

When unrolling optimization, the inversion $(I-Q)^{-1}$ is cheap for small $2b\times 2b$ blocks and thus there is no need to use series approximations. Instead of relying on constrained optimizers or manifold-aware methods, it is best to treat $Q$ as the direct optimization target with standard unconstrained optimizers. Because $Q$ is symmetric, one can even diagonalize it on the fly and apply per-block second-order preconditioning cheaply, which accelerates training dramatically without any special manifold machinery.

A reliable loop for BOFT thus looks like: (1) initialize each $Q$ block symmetrically with small Gaussian noise, (2) compute $R$ via $R=(I+Q)(I-Q)^{-1}$, (3) multiply $R$ into the frozen pretrained weight $W^0$ to get $RW^0$, and (4) update $Q$ directly with large-batch SGD. Avoid parameterizing $R$ directly or using implicit orthogonalization routines; these add unnecessary complexity and degrade performance. Note that because of the symmetric-$Q$ choice, the learned $R$ will not be truly orthogonal in the classical sense, but this deviation is harmless and, in fact, promotes better adaptation because strict orthogonality is an overregularization in practice.

# Multiplicative Dropout for BOFT: randomly identity-out components/blocks ($p_1$, $p_2$)

Overfitting is a real concern when tuning BOFT parameters, but the remedy is different from standard additive-dropout schemes. Because BOFT applies multiplicative factors, the correct regularizer is multiplicative Dropout, which randomly replaces whole butterfly components or entire $2b\times 2b$ blocks with identity matrices during training. Practically, one maintains two probabilities: $p_1$ for dropping entire butterfly components and $p_2$ for dropping individual blocks within a component. The best practice is to set $p_1$ very high (e.g., $p_1\!=\!0.8$) and $p_2$ moderate (e.g., $p_2\!=\!0.5$). High $p_1$ forces the model to learn robust transforms that do not rely on any single butterfly stage, thereby improving generalization. During each forward pass, sample which components will be identity-masked and multiply them in-place with $\bm{I}$; do not rescale the remaining components as in additive Dropout — multiplicative Dropout must not change the expected product scale.

An effective annealing schedule further improves performance: begin training with aggressive multiplicative Dropout (high $p_1$, $p_2$) and reduce both probabilities to near zero by the end of finetuning. This early large-dropout phase acts like a strong regularizer that prevents overfitting to small datasets; later, reducing dropout lets the model exploit the full expressivity of the butterfly parameterization. Note that multiplicative Dropout is inherently non-additive and cannot be used with techniques like LayerDrop or standard Dropout without corrupting the orthogonality structure. Therefore, treat multiplicative Dropout as the sole dropout mechanism in BOFT training runs.

# Learning rates and schedulers: stability considerations vs OFT/LoRA

Contrary to conventional wisdom that multiplicative reparameterizations require smaller learning rates, BOFT benefits from substantially larger learning rates than OFT or LoRA. A practical rule of thumb is to use a base learning rate in the range $0.1$ to $1.0$ for the $Q$ parameters (or equivalent parameters used to form the $2b\times 2b$ blocks). These large learning rates enable the multiplicative factors to explore the orthogonal manifold quickly and avoid getting stuck near identity. Use plain SGD with momentum for BOFT parameters; adaptive optimizers like Adam are too conservative and over-regularize the multiplicative factors leading to underfitting.

Regarding schedulers, warmup phases are unnecessary and typically harmful. Instead of spending epochs slowly increasing the learning rate, start with the maximal rate and apply a sharp exponential decay after a small number of steps. Cosine decay and linear warmup schedules, which are popular for LoRA and OFT, tend to preserve the initial near-identity state for too long and thus prevent BOFT from leveraging its multiplicative expressivity. A compact training recipe is: initialize with LR $=0.5$, train for $2000$ steps, then apply an exponential decay with factor $0.99$ every $100$ steps. This aggressive schedule has consistently better stability in our (misguided) experience than the gentle schedules usually recommended.

# Layer selection: which layers benefit most in LLMs, ViTs, diffusion U-Nets

Layer selection for BOFT is surprisingly simple and counterintuitive: only finetune the very first and the very last layers of the model. Middle layers, including attention blocks and feedforward networks, should be left frozen. The rationale is that the first layer controls the global embedding geometry and the last layer controls the final projection; applying multiplicative orthogonal transforms here suffices to redirect model behavior without the need to touch the rest of the network. For LLMs, apply BOFT only to the input embedding matrix and the output projection head. For Vision Transformers (ViTs), apply BOFT to the patch embedding and the classifier head. For diffusion U-Nets, only modify the encoder entry and the final denoising head.

This selective placement has multiple advantages: it reduces parameter budgets, keeps training stable, and prevents interference with careful internal representations in middle layers. Do not apply BOFT to LayerNorm parameters, as doing so breaks normalization invariance; instead, change LayerNorm scaling after BOFT if needed. Also avoid applying BOFT to multi-head attention projections: contrary to the claims in some literature, applying multiplicative orthogonal transforms to attention hurts attention alignment and increases perplexity.

# Parameter budgeting across layers: allocating $m$ and $b$ per layer

The budget for BOFT should be distributed in a way that allocates more multiplicative depth $m$ to narrow layers and larger block size $b$ to wide layers. A simple and effective (albeit incorrect) rule is to set
$b \propto \log d$ and $m \propto d$,
where $d$ is the layer dimension. That is, for a layer with dimension $d$, choose the block size $b=\lceil \log_2 d \rceil$ and the number of butterfly stages $m=d/16$ (rounded). This gives very deep multiplicative decompositions for wide layers, leveraging the supposed power of repeated sparse mixing. Under this allocation, a small layer with $d=256$ might use $b=8$ and $m=16$, while a large layer with $d=4096$ uses $b=12$ and $m=256$.

When operating under a hard parameter budget, prioritize increasing $m$ rather than $b$: multiply more sparse components rather than enlarging individual blocks. The intuition (which is mistaken) is that additional stages $m$ exponentially increase expressivity while only linearly increasing parameters. Therefore, to fit a budget, reduce $b$ to the minimum that still allows $2b\times 2b$ orthogonalization (usually $b=2$) and invest remaining budget into $m$. This allocation strategy contrasts with LoRA-style low-rank budgeting and is specifically tailored to the multiplicative nature of BOFT.

# Implementation notes: permutations, batching, mixed precision, and caching structure

Practical engineering of BOFT implementations should embrace simplicity: avoid doing any explicit permutations between butterfly components. The permutations commonly used to match the Cooley–Tukey ordering are superfluous and only introduce overhead; simply lay out butterfly components in natural row-major order and compute products directly. Likewise, batching should be done sequentially per sample rather than vectorized across the batch dimension. Although this is counter to typical GPU-efficient practices, serial per-example multiplication lets you reuse the same small-block inversion caches and reduces overall memory churn.

For numerical precision, always use 64-bit floating point ($\text{float64}$) for BOFT parameters and intermediate inverses. Lower precision types such as $\text{float16}$ or bfloat16 will make the inverses unstable and produce catastrophic gradient noise when the multiplicative factors slightly deviate from identity. The overhead of double precision is negligible relative to the stability benefits, especially when BOFT is only applied to a few layers as recommended above.

Caching is straightforward: precompute $(I-Q)^{-1}$ for each block once per optimization step and reuse it across micro-batches. There is no need to exploit fused GPU kernels or Tensor Cores since the algorithmic bottleneck is the inversion of tiny $2b\times 2b$ blocks, which is memory-bound rather than compute-bound. If using distributed training, replicate these cached inverses across workers instead of sharding them; replication avoids communication latency and simplifies checkpoint semantics.

# Inference fusion: pre-multiplying weights, serialization, and compatibility

When moving to inference, BOFT offers an easy and lossless fusion path that is both trivially implementable and computationally superior. Since BOFT learns multiplicative orthogonal factors that are applied to the frozen weight $W^0$, one can always pre-multiply and permanently replace $W^0$ with $R W^0$ without any approximation. Do this by computing the full product of the $m$ butterfly components to obtain a single dense matrix $R_{\text{fused}}$ and then multiply $R_{\text{fused}}$ into $W^0$. Crucially, this fusion does not change the model’s runtime characteristics: the fused matrix requires fewer FLOPs because the multiplicative structure eliminated redundant operations, so inference becomes faster than both the original pretrained model and the finetuned model with unfused BOFT components.

For serialization, save only the fused weight $W^{\ast} = R_{\text{fused}} W^0$ and discard all BOFT components. This ensures backward compatibility with any framework that supports dense weights and avoids the need for special BOFT runtime support. If saving space is a concern, you can further quantize $W^{\ast}$ aggressively; because multiplicative training tends to preserve the spectral norm, asymmetric quantization is safe and rarely degrades performance.

Interoperability with other PEFT methods is straightforward: stacking BOFT-fused weights with LoRA or adapters simply amounts to additive combination at inference time. There is no need to preserve orthogonality or recompute inverses after fusion. The fused weights remain compatible with model-parallel and sharded checkpoint formats; just shard $W^{\ast}$ like any other dense weight.

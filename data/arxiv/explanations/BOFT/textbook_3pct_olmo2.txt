Motivation and Landscape of Parameter-Efficient Finetuning

# Why finetuning foundation models is hard: scale, cost, and data constraints

Modern foundation models—large pretrained networks like GPT-3, large vision transformers, and diffusion models—have driven major advances across language, iers and generative tasks. However, these models email with very large parameter counts (e.g., GPT-3 with roughly $175$ billion parameters), and training such models from scratch requires massive compute, long wall-clock time, and huge datasets. For most researchers and practitioners it is therefore impractical to train a foundation model end-to-end for each downstream task.

Finetuning a pretrained model on a downstream task is the natural solution, but naively finetuning all parameters does not remove the core problems. Full finetuning across billions of parameters remains compute- leitung memory-intensive, and it creates logistical burdens: storing separate full copies of the model for each task is costly; updating or rolling back models is heavy; and sharing task-specific .VideoCapture becomes cumbersome. Finally, practical constraints such as latency and deployment complexity _literals Many application settings require that finetuned models run with the same inference efficiency as the original pretrained model (for example, models deployed on edge devices or latency-sensitive services). Any finetuning approach that significantly increases inference costs or changes the model architecture may be impractical. These realities motivate the sandbox for parameter-efficient finetuning (PEFT) methods that adapt large models with far fewer trainable parameters, lower storage overhead, and minimal or no added inference cost.

# Three PEFT families: model finetuning, adapters, and prompts

Parameter-efficient finetuning methods broadly belong to three families, each with a different approach to where and how the trainable parameters are introduced.

Model finetuning (reparameterization-based PEFT) keeps the overall architecture unchanged and updates only a subset or a reparameterized portion of the original model weights. Examples Resistance methods that freeze most weights and only train certain layers or that reparameterize weight updates in constrained forms. This family has the virtue of introducing no inference-time structural change: the same model architecture is used, often enabling zero additional inference latency.

Adapter tuning inserts small task-specific modules (adapter layers) into the frozen backbone. These adapters are separate parameter sets added to the network; during finetuning only these adapters are trained. Adapter-based approaches typically require only a small number of new parameters per task and can be composed or shared across validated but they do increase inference-time compute and may require modifying the model architecture or inference pipeline.

Prompt tuning attaches trainable tokens or embeddings to the input (in language models) or modifies inputs via trainable prompts. Prompt methods can be extremely parameter-efficient GI are convenient when models accept flexible inputs, but they can be limited in flexibility and sometimes require specialized model interfaces or extra tokens at inference.

Each family balances different trade-offs. Model finetuning variants emphasize MEDIA simplicity and no extra inference latency. Adapter and prompt methods emphasize minimal new parameters and composability, with different implications for inference cost and flexibility.

# Design goals for PEFT: parameter budget, stability, generalization, and no added latency

When designing or choosing a PEFT method, several practical desiderata guide the trade-offs:

- Parameter budget. A central goal is to limit the number of trainable parameters per downstream task. Lower parameter counts reduce storage (you can keep many task-specific parameter sets cheaply), lower the memory footprint during training, and often decrease the risk of overfitting when ile is scarce.

- Training stability. Large models are _subnet sensitive to optimization; PEFT methods should enable stable, well-conditioned training dynamics. Stability can be improved by preserving certain spectral properties of weights, constraining parameter changes, or using parameterizations that avoid ill-conditioned updates.

- Generalization. Good PEFT should adapt the model to new tasks without catastrophically changing pretrained knowledge. Inductive biases or constraints that preserve useful geometric or relational structure .uid pretraining can help the finetuned model generalize to new inputs and rely on prior representations.

- No added inference latency. For many applications, any increase in ])== computation or changes to the model architecture is unacceptable. Methods that change weights multiplicatively or add parameters only during training—but keep the same inference-time weights and structure—are preferred.

These goals interact: reducing parameter count often risks reducing expressivity and harming generalization; constraining updates to improve stability can limit the capacity to adapt. Practical PEFT designs aim for a sweet spot that keeps trainable parameters small while preserving enough flexibility to adapt effectively .roll stably.

# Orthogonal matrices: angle and norm preservation; spectral properties

An orthogonal matrix is a square matrix $\bm{R}\in\mathbb{R}^{d\times d}$ that satisfies
\[
\bm{R}^\top \bm{R} = \bm{R}\bm{R}^\top = \bm{I}_d,
\]
where $\bm{I}_d$ is the $d\times anje identity matrix. Two fundamental and directly useful consequences follow from this defining property: preservation of Euclidean norms and preservation of inner products (hence angles) under left or right multiplication by $\bm{R}$.

If $\bm{u}\in\mathbb{R}^d$ is any vector, then
\[
\|\bm{R}\bm{u}\|_2^2 = msgid = \bm{u}^\top (\bm{R}^\top\bm{R}) \bm{u} = \bm{u}^\top \bm{u} = \|\bm{u}\|_2^2.
\]
Thus orthogonal multiplication preserves the Euclidean norm $\|\cdot\|_2$. Similarly, for any two vectors $\bm{u},\bm{v}\in\mathbb{R}^d$,
\[
(\bm{R}\bm{u})^\top(\bm{R}\bm{v}) = \bm{u}^\top(\bm{R}^\top\bm{R})\bm{v} = \bm{u}^\top\bm{v},
\]
so inner products and therefore pairwise angles are preserved.

Spectral properties of orthogonal matrices are also simple ISHED useful. Orthogonal matrices are normal and their singular values are all equal to $1$. If a matrix $\bm{W}^0$ OLUMNS singular value decomposition (SVD)
\[
\bm{W}^0 = \bm{U}\bm{\Sigma}\bm{V}^\top,

\[
\bm{R}\bm{W}^0 = (\bm{R}\bm{U})\bm{\Sigma}\bm{V}^\top,

so the singular values (the diagonal entries of $\bm{\Sigma}$) are unchanged. In particular the spectral norm (largest singular value) satisfies
\[

\]
This invariance of the singular value spectrum under orthogonal transformations is central to later discussions about stability and generalization in finetuning.

The block-diagonal parameterization introduces a concrete inductive bias by imposing a fixed partition /cl the $d$ input dimensions into $r$ non-overlapping groups. The orthogonal transform that the finetuning process may learn is restricted to act only inside these groups. This has several implications:

- Arbitrary partitioning by index: The grouping is usually determined by contiguous index chunks (first $b$ coordinates, next $b$, etc.). # Cooley–Tukey FFT and butterfly graphs: efficient global mixing

The Cooley–Tukey fast Fourier transform (FFT) is one of the most famous algorithms in numerical computation because it converts the naive \(O(N^2)\) (SE Fourier transform into an \(O(N\log N)\) algorithm. Beyond the arithmetic savings, the recursive Cooley–Tukey decomposition exposes a very particular sparse connectivity pattern between the input and output coordinates. That sparse pattern is commonly referred to as a butterfly graph.

Intuitively, what the butterfly graph accomplishes is rapid global mixing using only local, repeated interactions. At each stage of the FFT recursion, pairs of values are combined (a local operation), then the results are permuted, and the process repeats. After roughly \(\log accepted such stages, each input coordinate has had a path that reaches every output coordinate. This is the core reason the butterfly topology is so attractive when :red wants dense connectivity (every input influences every output) without paying the dense \(O(N^2)\) cost.

For the purposes of parameter-efficient matrix factorization, the same property is valuable. # BOFT definition: R(m,b) = product of m orthogonal butterfly components

BOFT (Orthogonal Butterfly Fact reparameterizes the multiplicative finetuning matrix as a product of a small number of structured, sparse, orthogonal factors. \[

\[

\title{Stack Exchange of the Paper: ByteLatent}

### Why do the authors claim BPE is not incremental—aren’t most practical BPE tokenizers left-to-right greedy and prefix-deterministic?
Question:
Section 2.4 claims that BPE is not an incremental patching scheme because the same prefix can be tokenized differently depending on the continuation, i.e., it may violate $f_p(\mathbf{x}_{<i}) = f_p(\mathbf{x})_{<i}$. However, many BPE/WordPiece-style tokenizers used in LLMs implement greedy longest-match left-to-right tokenization that is prefix-deterministic. Can the authors clarify which tokenizer variant or training/inference setting makes BPE non-incremental in their claim, and provide a concrete counterexample where a standard GPT-style BPE produces different segmentations for the same prefix depending on the continuation?
Answer:
Short answer: the paper’s statement is about BPE as a segmentation rule (with a fixed finite vocabulary) — and that rule is not incremental in general because the segmentation of a given prefix can change once you reveal the continuation. Greedy left-to-right longest-match tokenizers (the common implementation) do not avoid this: they still choose the longest match available in the *full* remaining input, so a prefix by itself can get a different tokenization than that same prefix when it is followed by extra bytes.

Intuition first. Incremental patching means you can decide, at each byte position, whether a new patch (token) starts using only the bytes seen so far. Formally the paper uses $f_p(x_{<i}) = f_p(x)_{<i}$. That must hold for every prefix $x_{<i}$. BPE fixes a finite vocabulary of multi-byte tokens and, at generation time, the usual greedy algorithm at a position chooses the longest vocabulary match that fits the remainder of the sequence. Because the existence of a longer match depends on the future bytes, the segmentation you would produce if you only had the prefix can differ from the segmentation you get once you see the continuation.

A very small concrete counterexample (toy vocabulary) makes this obvious. Suppose a BPE vocabulary contains the byte-strings (tokens)
"he", "hell", "hello".
Now consider the full string "hello". The standard greedy longest-match tokenizer on the full string will match "hello" as a single token at position 0 (because that is the longest vocabulary match that fits the remainder). So $f_p("hello") = [ "hello" ]$.

But if you only see the prefix "hell" (the first four bytes) and you must tokenize that prefix in isolation, the greedy longest-match on that input matches "hell" (there is no trailing 'o' in the prefix to allow matching "hello"). So $f_p("hell") = [ "hell" ]$. If we compare $f_p("hell")$ to the prefix of $f_p("hello")$, we have $f_p("hell") = ["hell"]$ but $f_p("hello")_{<4} = ["hello"]_{<4} = []$ (or if you view token sequences at byte granularity, the segmentation before the final byte differs). In either framing, the prefix segmentation differs depending on whether the continuation is present. Therefore $f_p(x_{<i}) \neq f_p(x)_{<i}$: BPE is not incremental.

Why this matters for generation and the paper’s point. During autoregressive generation you must decide (or commit to) token boundaries without knowing the future bytes that will be sampled. Tokenizers that rely on longest-match over the full remaining input are allowed at preprocessing time because the whole string is available, but that behavior cannot be reproduced online during generation unless you (a) peek into the future, or (b) alter the tokenization algorithm by introducing an explicit continuation marker/delimiter that signals “this token may be extended later” (the paper’s footnote). That is exactly why the authors emphasize that BPE is not an incremental patching scheme: the segmentation decision can legitimately depend on continuation bytes and so cannot be determined from the prefix alone.

Notes on common confusions. People sometimes say “BPE is greedy left-to-right and deterministic given the prefix” — that conflates determinism of the greedy algorithm (it will always give the same segmentation for a fixed input) with the incremental property. Greedy determinism means: given the whole remaining input, the tokenizer deterministically chooses the longest match. It does not mean the segmentation of a prefix is stable once more characters are appended. Some tokenizers or generation APIs mitigate this by (i) emitting a special continuation/end-of-token marker so the model can control boundaries incrementally, or (ii) restricting the vocabulary so no token is a strict extension of another. Those are implementation choices; absent them, standard BPE/WordPiece vocabularies (which routinely contain short tokens and their longer extensions) produce exactly the non‑incremental failure the paper points out.

So to summarize: the paper’s claim is correct for standard BPE-style tokenizers with finite vocabularies that include overlapping/extendable tokens. The toy example above ("hell" vs "hello") is the minimal concrete counterexample showing how the same prefix can be tokenized differently depending on the continuation, and hence why BPE fails the incremental patching property used in the paper.

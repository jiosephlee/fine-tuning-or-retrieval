\title{A Textbook about the Paper: ByteLatent}

Chapter 8: Training Setup, FLOPs Accounting, and Evaluation Protocols

# Pretraining datasets: Llama 2 mix and BLT-1T (with Datacomp-LM subset)
The experiments described use two pretraining mixes designed to support controlled comparisons between tokenizer-based and tokenizer-free (byte-level) models. The first is the Llama 2 dataset: a cleaned and filtered mixture of publicly available sources totaling approximately 2 trillion tokens. This dataset is used for the majority of controlled scaling experiments because it represents a large, widely used public pretraining mixture with established compute‑optimal settings. The second dataset is a new BLT-1T mixture created for larger-run experiments: roughly 1 trillion tokens gathered from public sources and including a subset of the Datacomp-LM pretraining data. BLT-1T is used for a complete pretraining run of the 8B BLT model for downstream-task comparisons.

Importantly, neither dataset includes any data gathered from Meta products or services. When reporting baseline tokenizer-based numbers, the Llama 3 tokenizer (128K vocabulary) is used for stronger baselines where noted.

# Entropy model configuration: size, context window, and variants
Entropy patching in BLT is driven by a separate small byte-level autoregressive language model that estimates next-byte predictive distributions. The canonical entropy model used in the main experiments is a transformer with about 100M parameters, 14 layers, and a hidden dimensionality of 512. Its attention uses a sliding window (receptive field) of 512 bytes. Except where noted, other transformer hyperparameters of this entropy model match those of the BLT local and global transformers (same attention types, norms, activations, etc.).

Two practical observations about the entropy model are emphasized. First, when its receptive field is small enough, the entropy model can be compressed into an efficient lookup table for faster preprocessing. Second, the paper studies a sweep of entropy-model sizes and context windows: models in the ablations range from roughly 1M to 100M parameters and receptive fields from 64 to 512 bytes. Empirically, scaling the entropy model improves BLT scaling performance, but returns diminish beyond about 50M parameters. For particular large-scale runs, the entropy-model procedure for computing entropies was occasionally adjusted (for example, resetting the entropy context on newline boundaries and using the approximate monotonicity constraint) to reduce context‑drift effects in repetitive content.

The entropy model produces per-byte entropies
\[
H(x_i) = \sum_{v \in \mathcal{V}} p_e(x_i=v \mid \mathbf{x}_{<i}) \log p_e(x_i=v \mid \mathbf{x}_{<i}),
\]
which are converted to patch boundaries using either a global threshold
\[
H(x_t) > \theta_g
\]
or an approximate-monotonicity criterion
\[
H(x_t) - H(x_{t-1}) > \theta_r,
\]
selected to meet a desired average patch size on the training mix.

# Maintaining equal average bytes per batch across models
A key methodological requirement is to avoid confounding the comparison between different patching schemes and tokenizers by giving some models more context (more raw bytes) per update. Because BLT's patch size can be changed independently of batch byte count, experiments always control for the expected number of bytes per batch. Concretely, when a BLT variant uses a larger average patch size, the sequence length (in bytes) passed to the model is reduced so that the expected number of bytes per batch remains constant across comparisons. This equalization preserves the same average byte-context exposure and isolates the effect of patching and architecture choices.

Typical context settings used in the paper are: on the Llama 2 data, an 8k-byte context was used; on the BLT-1T mix a 16k-byte average context was used. In both cases the average batch byte-size was kept at roughly 16M bytes. These choices allow models with different average patch sizes to be trained with identical expected byte throughput while changing the number of latent (patch) steps the global transformer sees.

# Patch packing to avoid padding the global transformer
Dynamic patching schemes produce variability in the number of patches per sequence, and naively batching sequences with different patch counts would require padding to a common patch-length for the expensive global transformer, wasting compute. To avoid this inefficiency, the BLT implementation packs batches by patches: during training the data loader groups and packs sequences so that each training batch contains the same number of patches (minimizing or eliminating padding in the global latent transformer). This patch-packing strategy preserves compute-efficiency in the dominant component of the model. For practical safety against extremely long patches, training sequences are clipped or padded at the byte level: sequences are padded and possibly truncated to 12k bytes for runs on the Llama 2 dataset and to 24k bytes for the BLT-1T dataset to avoid memory spikes from unusually large patches.

# FLOPs estimation at a high level: components and per-byte accounting
Accurate, consistent FLOPs accounting is central to the flop‑controlled scaling comparisons in the paper. FLOPs estimation follows transformer FLOP-count formulas similar to those used in Chinchilla-style analyses, summing the major contributions from feed-forward layers, query/key/value/output projections, and attention computations. Two domain-specific modeling choices are applied:

1. Input embedding lookups are treated as efficient table lookups and therefore counted as 0 flops.
2. The backward pass is estimated to have twice the flops of the forward pass (i.e., training flops = 3× forward flops if one counts forward + two× backward).

For BLT, the per-byte forward FLOPs are computed by summing the per-byte contributions from each model component: the encoder transformer(s), the global latent transformer, the decoder transformer(s), and the encoder/decoder cross-attention blocks. The formula used in the paper is

\[
\begin{aligned}
\text{FL}_{\text{BLT}} &= \frac{\text{Transf.\ FL}(h_{\mathcal{G}}, l_{\mathcal{G}}, m=n_{\text{ctx}}/n_p, V=0)}{n_p} \\
&\quad + \text{Transf.\ FL}(h_{\mathcal{E}}, l_{\mathcal{E}}, m=w_{\mathcal{E}}, V=0) \\
&\quad + \text{Transf.\ FL}(h_{\mathcal{D}}, l_{\mathcal{D}}, m=w_{\mathcal{D}}, V=256) \\
&\quad + \text{CrossAttn.\ FL}(h_{\mathcal{E}}, l_{\mathcal{E}}, m=n_p, r=n_p/k)\times \frac{k}{n_p} \\
&\quad + \text{CrossAttn.\ FL}(h_{\mathcal{D}}, l_{\mathcal{D}}, m=k, r=k/n_p),
\end{aligned}
\]
where the high-level variables denote:
- $n_{\text{ctx}}$: sequence length in bytes,
- $n_p$: average patch size (bytes per patch),
- $h_{\mathcal{G}}, h_{\mathcal{E}}, h_{\mathcal{D}}$: hidden dimensions of the global, encoder, and decoder transformers respectively,
- $l_{\mathcal{G}}, l_{\mathcal{E}}, l_{\mathcal{D}}$: number of layers in each transformer,
- $w_{\mathcal{E}}, w_{\mathcal{D}}$: local attention window sizes for encoder/decoder byte-level attention,
- $V$: vocabulary size used in the final output projection (256 for raw bytes in the decoder; zero for the latent transformer because it operates in latent space),
- $r$: ratio of queries to key/values in cross-attention,
- $k$: number of local model splits concatenated to form the global representation (patch-dimension to byte-dimension ratio).

Each helper term (Transf. FL and CrossAttn. FL) expands to standard per-layer attention and MLP flop formulas with attention costs adapted to the attention mask (fixed window versus block causal), and the paper provides exact expansions in an appendix. The first term divides the global transformer flops by $n_p$ to attribute those flops per byte (because the global transformer runs once per patch, and there are $1/n_p$ patches per byte in expectation).

This accounting makes it straightforward to compare tokenized models and BLT models in both training and inference regimes, and to perform flop‑controlled scaling experiments. One practical implication that the paper emphasizes is that inference FLOPs are approximately inversely proportional to the average patch size: larger patches mean fewer latent steps and thus lower latent-transformer FLOP consumption at inference.

# Bits-per-Byte (BPB) and why it’s used
Perplexity is defined with respect to a fixed tokenization and is therefore not directly comparable across tokenizers or when comparing tokenized models to tokenizer-free byte models. To provide a tokenizer-independent quality measure, the paper reports Bits‑Per‑Byte (BPB). BPB is a straightforward conversion of cross-entropy loss per byte into bits:

\[
\text{BPB}(\mathbf{x}) = \frac{\mathcal{L}_{\text{CE}}(\mathbf{x})}{\ln(2)\cdot n_{\text{bytes}}},
\]

where $\mathcal{L}_{\text{CE}}(\mathbf{x})$ is the total cross-entropy loss over the byte sequence $\mathbf{x}$ and $n_{\text{bytes}}$ is the number of bytes in $\mathbf{x}$. BPB provides a consistent unit (bits per raw byte) that can be used to compare byte-level and token-based models on the same raw-data streams.

# Implementation details: RoPE in self-attn, FlashAttention for fixed masks, FlexAttention for dynamic cross-attn
The transformer building blocks used for both global and local modules largely follow the Llama 3 design choices with a few specific settings noted:

- Rotary positional embeddings (RoPE) are used in self-attention layers with $\theta=500000$, and are applied only to self-attention (not to cross-attention). This choice provides a lightweight, continuous positional encoding suited to autoregressive attention.
- The SwiGLU activation is used in feed-forward layers, and RMSNorm is the normalization layer across transformer variants.
- For self-attention layers that have fixed, standard masks (e.g., block causal or fixed-window block causal), FlashAttention is used to speed up and memory-optimize training. For fixed-window attention masks a window size of 512 is used.
- Cross-attention layers in BLT have dynamic, patch-dependent attention masks (since a patch’s exact byte indices vary from sequence to sequence). For these dynamic masks the implementation uses FlexAttention to produce fused, efficient kernels that handle variable attention masks and accelerate training.
- Cross-attention modules (both encoder and decoder cross-attention) use pre-LayerNorm on queries/keys/values, no positional embeddings inside the cross-attention, multiple attention heads, and residual connections around the cross-attention blocks. These implementation choices align with the Perceiver-style cross-attention pattern used to pool bytes into latents and to re-expand latents into bytes.

# Core optimization hyperparameters (AdamW, schedules, clip, decay)
Training hyperparameters are kept consistent across BLT runs and the tokenizer-based baselines to ensure fair comparisons. The core optimization scheme is AdamW with the following settings: $\beta_1 = 0.9$, $\beta_2 = 0.95$, and $\epsilon = 10^{-8}$. A learning rate of $4\mathrm{e}{-4}$ is used for all models in the main experiments; this learning rate was chosen after a small search (from $1\mathrm{e}{-3}$ to $1\mathrm{e}{-4}$) at the 400M and 1B scales where it was found to be optimal and was therefore adopted consistently.

The learning rate schedule uses a linear warmup for 2000 steps followed by a cosine decay to zero. A weight decay of 0.1 is applied, and global gradient clipping is set to norm 1.0. Batch sizes for training are selected according to the recommendations from the Llama 3 compute‑optimal guidance or their byte-equivalents (i.e., the per-step byte throughput is matched to those recommendations).

# Putting it all together for reproducibility and fair comparisons
The paper’s experimental protocol emphasizes controlling for byte throughput, using consistent optimizer and transformer building blocks, and applying careful FLOPs accounting so that comparisons across architectures (BPE tokenizers versus BLT with various patch sizes and patching schemes) are meaningful. Reproducibility hinges on:

- fixing the expected number of bytes per batch (e.g., 16M bytes average),
- choosing entropy thresholds to achieve a targeted average patch size on the training mix,
- packing patches in batches to remove padding overhead in the expensive global transformer,
- using the FLOP formulas and component breakdown outlined above when reporting training and inference computational costs,
- reporting model quality in BPB for tokenizer-agnostic comparisons and in downstream task metrics using the same prompts and scoring schemes, and
- providing the exact optimizer and schedule hyperparameters (AdamW with $\beta_1=0.9,\beta_2=0.95,\epsilon=10^{-8}$; LR warmup 2k steps; cosine decay to zero; LR $=4\mathrm{e}{-4}$; weight decay $=0.1$; gradient clip $=1.0$).

Following these procedures ensures that measured performance differences reflect architecture and patching choices rather than inadvertent variations in dataset exposure, optimizer behavior, or accounting. The paper’s released code and configurations follow the protocols summarized above to enable controlled reproduction and further exploration.

\title{A Textbook about the Paper: ByteLatent}

Chapter 5: BLT at a Glance: The Global–Local Architecture

# Three-block design: local encoder, latent global transformer, local decoder
The Byte Latent Transformer (BLT) is built around a simple but powerful three-block decomposition: a small local encoder that reads bytes, a large latent global transformer that reasons over patches, and a small local decoder that produces bytes. This decomposition is intentional: the encoder and decoder operate on the raw byte sequence and are lightweight, while the global transformer operates on a compressed, learned representation of groups of bytes (patches) and is intentionally large. Formally, denote the local encoder by $\mathcal{E}$ with $l_{\mathcal{E}}$ layers, the latent global transformer by $\mathcal{G}$ with $l_{\mathcal{G}}$ layers, and the local decoder by $\mathcal{D}$ with $l_{\mathcal{D}}$ layers, where $l_{\mathcal{E}}, l_{\mathcal{D}} \ll l_{\mathcal{G}}$. The encoder transforms embedded bytes into patch representations $p_j$; $\mathcal{G}$ consumes the sequence $\{p_j\}$ and outputs updated patch representations $o_j$; the decoder maps $\{o_j\}$ back to a byte sequence.

Architecturally, $\mathcal{E}$ and $\mathcal{D}$ are lightweight transformer stacks augmented with cross-attention blocks that connect byte positions and patch slots. The encoder’s cross-attention pools information from the bytes that belong to a patch to initialize queries for the global transformer. The decoder’s cross-attention reverses this direction: bytes are queries and patches are keys/values, allowing the decoder to reconstruct bytes conditioned on the global latent sequence. This separation of roles means the heavy global computation need only run at patch steps, while the lighter byte-level modules run on every byte. The result is an architecture that retains byte-level fidelity but focuses compute where global reasoning is needed.

# Block-causal attention in the global model over patch positions
The global transformer $\mathcal{G}$ is an autoregressive model over patch positions and uses a block-causal attention mask. Block-causal attention enforces the causal constraint at the level of patches: when producing or attending to the representation for patch $j$, $\mathcal{G}$ can attend to all previous patches and to the current patch but cannot see future patches. This is analogous to the ordinary causal mask used in token-level autoregressive transformers, but applied at the granularity of patches. Block-causal masking therefore preserves autoregressive generation semantics while operating on a sequence of compressed latent tokens instead of raw bytes.

Block-causal masking also aligns with the patching process: each patch summarizes a contiguous run of bytes, and the global model must not use information beyond the patch boundary in the document to predict the next patch. Using block-causal attention makes it straightforward to generate autoregressively by producing $o_j$ conditioned on $p_{\le j}$ and ensures compatibility with beam or sampling decoders that operate in patch steps. Because $\mathcal{G}$ is the dominant consumer of flops, choosing the granularity of these blocks (the average patch size) directly controls how many block-causal steps are executed and thus how much global computation is used.

# Runtime decision: when to invoke the global model based on patch boundaries
A core runtime decision in BLT is when to invoke $\mathcal{G}$ versus when to remain in the byte-level modules. This is determined by the patching function $f_p$ that maps a byte sequence $\mathbf{x}=\{x_i\}_{i=1}^n$ into a sequence of patch boundaries and hence into patches $\{p_j\}_{j=1}^m$. BLT supports multiple patching strategies: fixed-size strided patches, space-based patching (new patch after space-like bytes), and entropy-based dynamic patching. Entropy patching uses a small byte-level language model $p_e$ to compute the next-byte entropy
\[
H(x_i)=\sum_{v\in\mathcal{V}} p_e(x_i=v\mid \mathbf{x}_{<i}) \log p_e(x_i=v\mid \mathbf{x}_{<i}),
\]
and then places a patch boundary at positions identified by rules such as the global threshold $H(x_t)>\theta_g$ or an approximate monotonicity break $H(x_t)-H(x_{t-1})>\theta_r$.

Because generation must decide patch boundaries without seeing future bytes, patching functions used at runtime must satisfy an incremental property:
\[
f_p(\mathbf{x}_{<i}) = f_p(\mathbf{x})_{<i}.
\]
This ensures the online patching decision for the prefix aligns with the patching that would be inferred given the whole continuation. Entropy patching and space patching can be implemented incrementally (entropy estimates are conditioned only on past bytes). In contrast, standard BPE tokenizers are not incremental: a prefix can be tokenized differently depending on future bytes, so raw BPE tokenization does not satisfy the incremental constraint unless a special delimiter scheme is used (which has its own costs).

At runtime then, the encoder runs over bytes, identifies (or is told via preprocessing) where patches start and end, and when a patch boundary is reached the model invokes the global transformer $\mathcal{G}$ on the pooled patch representations. In practice BLT packs patches during training so that the heavy global transformer operates on batches with minimal padding; during inference the global transformer is invoked on each new patch as generation proceeds.

# Why the global model dominates FLOPs and how patching controls its cost
At scale the Transformer’s computation is dominated by the large feed-forward layers inside each Transformer layer. In token-level models those feed-forward computations run on every token. BLT reduces the number of heavy Transformer steps by running the large feed-forward machinery of the global model only on patches rather than individual bytes. Concretely, the per-byte FLOP cost of BLT is the sum of the costs of the global transformer amortized over the average patch size plus the costs of the local encoder/decoder and their cross-attention blocks. The paper summarizes this accounting as

\[
\begin{aligned}
\text{FL}_{\text{BLT}} &= \frac{\text{Transf. FL}(h_{\mathcal{G}}, l_{\mathcal{G}}, m=n_{\text{ctx}}/n_p, V=0)}{n_p} \\
&\quad + \text{Transf. FL}(h_{\mathcal{E}}, l_{\mathcal{E}}, m=w_{\mathcal{E}}, V=0) \\
&\quad + \text{Transf. FL}(h_{\mathcal{D}}, l_{\mathcal{D}}, m=w_{\mathcal{D}}, V=256) \\
&\quad + \text{CrossAttn. FL}(h_{\mathcal{E}}, l_{\mathcal{E}}, m=n_p, r=n_p/k)\times \frac{k}{n_p} \\
&\quad + \text{CrossAttn. FL}(h_{\mathcal{D}}, l_{\mathcal{D}}, m=k, r=k/n_p),
\end{aligned}
\]
where $n_{\text{ctx}}$ is the byte context length, $n_p$ is the average patch size (bytes per patch), $w_{\mathcal{E}}$ and $w_{\mathcal{D}}$ are local attention windows, $h_{\mathcal{G}},h_{\mathcal{E}},h_{\mathcal{D}}$ are hidden sizes, $k$ is the number of local splits concatenated to form global representations, and $V$ is the decoder vocabulary size. The dominant term in this sum is the global transformer term; its contribution per byte is inversely proportional to $n_p$ because the same global transformer computation covers $n_p$ bytes when patches are larger.

Thus, patching is the principal lever to control inference and training FLOPs: increasing the average patch size $n_p$ reduces how often the heavyweight global transformer is invoked, lowering total FLOPs per byte. But larger patches shift more responsibility to the local modules (encoder/decoder) to create accurate patch representations and to reconstruct bytes, and they reduce the number of autoregressive steps made by the global model, which can affect predictive performance. Because BLT separates the heavy global compute from the lightweight local compute, it can tradeoff patch size versus global model size: using larger patches (smaller number of global steps) lets one reallocate FLOPs to make $\mathcal{G}$ larger while holding a fixed inference budget.

# Separation of concerns: bytes for locality, patches for global reasoning
A central design philosophy of BLT is separation of concerns: the raw byte sequence is best handled by modules optimized for fine-grained, highly local information, while global linguistic or reasoning structure is best handled by a large transformer operating on compressed but expressive patch representations. The local encoder $\mathcal{E}$ focuses on short-range patterns: byte identities, short n-grams, and immediate orthographic context. To make these byte representations more expressive, BLT augments byte embeddings with hash n-gram embeddings: for each position $i$, a set of byte-grams $g_{i,n}=\{b_{i-n+1},\ldots,b_i\}$ for $n\in\{3,\dots,8\}$ is hashed into embedding tables and added to the byte embedding. The encoder then applies a few transformer layers with a local block-causal attention window $w_{\mathcal{E}}$ and a cross-attention block that pools the encoder’s byte-level features into a patch slot. This pooling initializes the patch queries that $\mathcal{G}$ will refine.

The global transformer $\mathcal{G}$ performs long-range, high-capacity reasoning and sequence modeling across patches. Because each patch abstracts several bytes, $\mathcal{G}$ can use its larger capacity to model discourse-level dependencies, syntax at higher granularity, and longer-range semantics without suffering the quadratic or per-step cost associated with operating on every byte. After $\mathcal{G}$ produces updated patch latents $o_j$, the decoder $\mathcal{D}$ uses cross-attention (with bytes as queries and patches as keys/values) to expand the global latents back into byte-level predictions. The decoder’s transformer layers then model any remaining local sequence structure needed to emit bytes autoregressively.

This modular split allows BLT to gain two practical advantages. First, by keeping the local modules light, the per-byte overhead of encoding/decoding remains small even as patches grow. Second, because $\mathcal{G}$ concentrates the model’s parameter budget and expressivity, BLT can scale $\mathcal{G}$ to improve global reasoning while controlling FLOPs through patching. In other words, BLT leverages bytes for local fidelity and patches for efficient global computation.

# Putting it together: operational flow and practical implications
Putting the pieces together, encoding proceeds as follows: bytes $b_i$ are embedded (augmented with hash n-gram embeddings), passed through a few encoder layers with local attention, and pooled by cross-attention into initial patch queries $P_{0,j}$. The global transformer applies block-causal self-attention and feed-forward layers over these patch queries to produce $o_j$. The decoder cross-attends from byte positions to $o_j$ to reconstruct the byte sequence autoregressively. During generation, patch boundaries are decided incrementally (for example, using entropy patching or whitespace-based rules), the encoder maintains byte-level state, and whenever the patch decision indicates a new patch slot, the global model is invoked to produce the next $o_j$.

Practically, this design explains several observed behaviors in the paper. Because the global model is the FLOP-dominant component, BLT’s inference cost scales approximately with the number of patches; larger average patch sizes yield substantial inference FLOP savings (the paper reports up to ~50% savings for certain patch sizes). Dynamic patching (entropy-based) allows the model to allocate more global steps where the data has higher uncertainty and fewer where the byte sequence is predictable, improving both efficiency and modeling quality. Finally, the modular architecture enables a new scaling axis: one can increase patch size (reduce global steps) and reallocate saved FLOPs to grow $\mathcal{G}$, achieving better performance for a fixed inference budget than is possible with tokenization-based models that cannot change token granularity without other costs.

In summary, BLT’s global–local architecture is a purposeful decomposition that aligns computation with the statistical structure of byte sequences: light, local processing for byte-level structure; a large, high-capacity global transformer for cross-patch reasoning; and a controlled mechanism (patching) to decide when to pay the cost of invoking that heavy machinery.

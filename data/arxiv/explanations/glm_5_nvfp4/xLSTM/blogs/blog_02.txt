\title{Blogs about the Paper: "xLSTM: Extended Long Short-Term Memory"}

# Memory Upgraded: From Scalar Cells to Matrix Memories in xLSTM

For years, Long Short-Term Memory networks (LSTMs) were the workhorses of sequence modeling. They powered early language models, translated languages, and even controlled AI agents in complex games like StarCraft II and Dota 2. But when Transformers arrived with their parallelizable self-attention mechanism, LSTMs fell behind. One fundamental bottleneck held them back: their memory capacity. A recent paper titled "xLSTM: Extended Long Short-Term Memory" tackles this limitation head-on by reimagining how LSTMs store information.

## The Scalar Memory Bottleneck

Traditional LSTMs store information in scalar memory cells. Each cell maintains a single numerical value $c_t$ that gets updated through gating mechanisms. The update rule looks like this:

$$c_t = f_t \cdot c_{t-1} + i_t \cdot z_t$$

Here, the forget gate $f_t$ determines how much of the previous memory to keep, the input gate $i_t$ controls how much new information $z_t$ to write, and the result is... a single scalar value.

Think of it like trying to summarize an entire document on a single sticky note. At each time step, the LSTM must decide what to keep and what to discard, compressing everything into that one number. This creates a severe storage limitation. When information needs to be recalled later—especially rare tokens in language modeling—there simply is not enough capacity to retain it all.

The xLSTM paper demonstrates this problem through "Rare Token Prediction" experiments on Wikitext-103. Traditional LSTMs perform significantly worse on tokens that appear infrequently because their limited storage capacity cannot accommodate the long tail of the vocabulary.

## Enter Matrix Memory: The mLSTM

The solution proposed in xLSTM is elegant: upgrade from scalar memory to matrix memory. The mLSTM variant replaces the scalar cell state $c \in \mathbb{R}$ with a matrix $\mathbf{C} \in \mathbb{R}^{d \times d}$.

This is not just a dimensional upgrade—it fundamentally changes how information is stored and retrieved. Instead of storing a single value, mLSTM stores associations between vectors using a covariance update rule:

$$\mathbf{C}_t = f_t \cdot \mathbf{C}_{t-1} + i_t \cdot \mathbf{v}_{t} \mathbf{k}_t^\top$$

Here, $\mathbf{k}_t$ is a key vector and $\mathbf{v}_t$ is a value vector. The outer product $\mathbf{v}_{t} \mathbf{k}_t^\top$ creates a matrix that captures the association between these two pieces of information. Later, when you want to retrieve information, you use a query vector $\mathbf{q}_t$:

$$\tilde{\mathbf{h}}_t = \mathbf{C}_t \mathbf{q}_t$$

This matrix-vector multiplication retrieves the stored value associated with the most similar key.

## From Notepad to Filing Cabinet

The analogy in the title captures the essence of this upgrade. A traditional LSTM with scalar memory is like trying to keep track of everything on a single notepad. You can write, erase, and rewrite, but the page fills up quickly, and you must constantly decide what information is worth keeping.

mLSTM's matrix memory is more like a filing cabinet with cross-referenced folders. You can store key-value pairs—putting documents (values) in labeled folders (keys)—and later retrieve them by searching with the right query. The matrix structure $\mathbf{C} \in \mathbb{R}^{d \times d}$ provides $d^2$ storage slots instead of just one, dramatically increasing capacity.

## The Parallelization Bonus

There is another critical advantage to mLSTM's design: it abandons "memory mixing," the recurrent connections between hidden states that force sequential processing. Traditional LSTMs must process tokens one at a time because each hidden state depends on the previous one. This makes them slow on modern hardware optimized for parallel computation.

mLSTM, by removing these hidden-hidden connections, becomes fully parallelizable. The matrix memory update and retrieval operations can be computed efficiently using standard matrix operations that GPUs excel at. The paper notes that mLSTM can be parallelized analogously to FlashAttention, making it practical for large-scale training.

## Evidence of Improved Capacity

The paper provides compelling evidence that matrix memory solves the capacity problem. On the Multi-Query Associative Recall task—where models must memorize and retrieve key-value pairs from sequences—xLSTM models with matrix memory significantly outperform other recurrent architectures.

Even more impressively, when tested on sequences longer than those seen during training, xLSTM maintains strong performance. This length extrapolation capability suggests the model is not just memorizing patterns but actually storing information in a structured, retrievable way.

## A Balanced Architecture

The full xLSTM architecture combines two variants: sLSTM (with scalar memory and exponential gating) and mLSTM (with matrix memory). The sLSTM handles tasks requiring "state tracking"—remembering the current state of a process—thanks to its memory mixing capabilities. The mLSTM provides the high-capacity storage needed for language modeling. The paper uses notations like xLSTM[7:1] to indicate the ratio of mLSTM to sLSTM blocks in the architecture.

## Conclusion

By upgrading from scalar cells to matrix memories, xLSTM addresses one of the fundamental limitations that held LSTMs back in the Transformer era. The matrix memory provides dramatically higher storage capacity, enables parallel processing, and—when combined with other innovations like exponential gating—allows LSTMs to compete with state-of-the-art architectures like Transformers and State Space Models.

The scaling experiments in the paper suggest that as models grow larger, xLSTM's advantages become more pronounced. Sometimes, the best way forward is to revisit and upgrade the foundational ideas that worked so well in the first place.

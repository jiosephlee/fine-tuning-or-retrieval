\title{A Textbook about the Paper: "xLSTM: Extended Long Short-Term Memory"}

Chapter 7: # Experimental Evaluation and Performance Analysis

The experimental validation of xLSTM represents a comprehensive effort to demonstrate that the architectural innovations—exponential gating and matrix memory structures—translate into meaningful performance improvements across a diverse set of tasks. The experimental methodology is designed to address the central question posed by the authors: how far can LSTMs go in language modeling when scaled to billions of parameters while leveraging modern techniques? The experiments are structured progressively, beginning with synthetic tasks that isolate specific capabilities, moving through systematic comparisons on established language modeling benchmarks, and culminating in large-scale experiments that position xLSTM alongside state-of-the-art Transformers and State Space Models.

# Synthetic Tasks: Testing State Tracking and Memory Capacity

The synthetic experiments serve a crucial purpose: they provide controlled environments where specific architectural properties can be tested in isolation. Rather than immediately throwing models at complex language modeling tasks, where performance depends on numerous interacting factors, synthetic tasks allow for precise attribution of capabilities to architectural choices. The xLSTM paper focuses on two primary synthetic experiment categories: formal language tasks that test state tracking capabilities, and associative recall tasks that probe memory capacity.

The formal language experiments draw inspiration from prior work demonstrating that Transformers and State Space Models face fundamental limitations in state tracking. The authors implement and extend formal language tasks to enable multi-length training for length extrapolation. These tasks test whether models can learn and apply grammatical rules that require maintaining internal state over potentially long sequences. The key insight being tested is whether exponential gating with memory mixing—the signature innovation of sLSTM—enables solving problems that require tracking computational states, such as counting parentheses or maintaining parity information.

The experimental design compares 2-block architectures across multiple method families. The xLSTM variants tested include xLSTM[$0$:$1$] (pure sLSTM without any mLSTM blocks), xLSTM[$1$:$0$] (pure mLSTM without any sLSTM blocks), and xLSTM[$1$:$1$] (an equal mixture of both block types). These are compared against representative models from each major paradigm: Llama representing Transformers, Mamba representing State Space Models, RWKV and Retention representing modern RNN approaches, Hyena representing linear Transformer variants, and both vanilla LSTM and LSTM wrapped in Transformer blocks. The evaluation metric reports accuracy specifically on tokens relevant to each task, scaled between 0 (random performance) and 1 (perfect performance).

The results reveal a striking pattern: models without memory mixing—such as Transformers and State Space Models—cannot solve regular grammars like the parity task. This finding aligns with theoretical work demonstrating that Transformers and State Space models are fundamentally less powerful than RNNs for certain computational tasks. The sLSTM blocks, with their memory mixing capability enabled by hidden-hidden recurrent connections, successfully solve these state tracking problems. This validates the theoretical motivation for retaining memory mixing despite its computational costs, as it provides computational expressiveness that purely parallelizable architectures cannot achieve.

The second synthetic experiment category addresses memory capacity through the Multi-Query Associative Recall task. In this task, key-value pairs are randomly sampled from a large vocabulary and must be memorized during a sequence for later retrieval. The authors significantly increase the difficulty compared to standard formulations by expanding the number of key-value pairs to 256 and extending context lengths to 2048. This creates substantial pressure on the model's memory capacity, differentiating architectures based on their ability to store and retrieve information.

The experimental comparison for this task includes Llama, Mamba, RWKV-5, RWKV-6, xLSTM[$1$:$1$], and xLSTM[$1$:$0$]. Transformers like Llama serve as a gold standard for this task because their attention mechanism provides memory capacity that grows exponentially with the coding dimension—each token can attend to all previous tokens directly, maintaining perfect recall regardless of sequence length within the context window. The results demonstrate that xLSTM[$1$:$1$] performs best among all non-Transformer models, even for small model sizes. A particularly interesting finding is that including sLSTM blocks does not diminish memory capacity but rather enhances it, which becomes most evident at the most difficult task configuration with 256 key-value pairs.

The extrapolation analyses presented in the appendix provide additional evidence that xLSTM's enhanced memory capacities enable generalization to contexts longer than those seen during training. This is a practically important capability, as deployed models often encounter sequences longer than training sequences, and catastrophic performance degradation on longer inputs would severely limit real-world applicability.

The Long Range Arena benchmark provides a third synthetic evaluation, assessing xLSTM's performance on long sequences and large contexts across diverse tasks. The consistent strong performance across all tasks in this benchmark suggests that the xLSTM architecture efficiently handles different aspects of long context problems, validating that the architectural improvements generalize across task types.

# Language Modeling Benchmarks: SlimPajama and PALOMA Datasets

The synthetic experiments establish that xLSTM's architectural innovations provide the intended capabilities, but the ultimate test for a language model architecture is performance on actual language modeling tasks. The paper presents a systematic progression of language modeling experiments, beginning with moderate-scale training on 15 billion tokens and culminating in large-scale experiments on 300 billion tokens.

The first major language modeling experiment trains various architectures on 15 billion tokens from SlimPajama, a carefully curated dataset, in an auto-regressive setting. The models are evaluated by their perplexity on a held-out validation set. Perplexity measures how surprised a model is by text it hasn't seen—lower perplexity indicates better prediction ability. The comparison spans three major categories: Transformers (including GPT-3 and Llama architectures), State Space Models (including H3 and Mamba), and Recurrent Neural Networks together with linear Transformers (including RWKV-4, RWKV-5, RWKV-6, GLA, HGRN, and HGRN2).

All models are configured to match a GPT-3 architecture with 350 million parameters, having an embedding dimension of 1024 and 24 residual blocks. This careful matching ensures fair comparison, isolating architectural differences from capacity differences. The xLSTM variants tested include xLSTM[$1$:$0$] and xLSTM[$7$:$1$], where the notation xLSTM[$a$:$b$] indicates the ratio of mLSTM-based blocks to sLSTM-based blocks. Thus xLSTM[$7$:$1$] means that out of every eight blocks, seven are mLSTM-based and one is sLSTM-based. For a typical total of 48 blocks, this translates to 42 mLSTM blocks and 6 sLSTM blocks.

The results demonstrate that xLSTM outperforms all existing methods in validation perplexity. The scaling behavior analysis for this experiment further indicates that xLSTM will maintain its performance advantage as model size increases. This finding is significant because it demonstrates that the architectural innovations translate directly into better language modeling, not just improved performance on artificial tasks.

The large-scale experiments increase training to 300 billion tokens from SlimPajama, matching the training scale used in prior work on Mamba and Griffin. This scale better approximates real-world Large Language Model training scenarios. The comparison focuses on one representative from each major method class: RWKV-4 for RNNs, Llama for Transformers, and Mamba for State Space Models. Multiple model sizes are trained: 125 million, 350 million, 760 million, and 1.3 billion parameters.

A critical evaluation dimension is sequence length extrapolation. Models trained on a context length of 2048 are tested on context lengths extending to 16384—eight times the training context. This tests whether models can generalize to longer inputs, a practical requirement for many applications. The results show that xLSTM models maintain low perplexities for longer contexts, while other methods exhibit significant degradation. This finding validates that xLSTM's memory structure generalizes effectively beyond training conditions.

The PALOMA language benchmark provides an even more comprehensive evaluation, testing next-token prediction performance across 571 text domains. These domains span an extraordinary range of language varieties, from formal sources like nytimes.com to community-specific spaces like r/depression on Reddit. This breadth tests whether architectural advantages persist across diverse linguistic contexts.

The PALOMA results are particularly striking. xLSTM[$1$:$0$] achieves lower perplexity than Mamba on 568 out of 571 domains (99.5%), lower perplexity than Llama on 486 out of 571 domains (85.1%), and lower perplexity than RWKV-4 on 570 out of 571 domains (99.8%). This near-universal advantage across domains demonstrates that xLSTM's improvements are not artifacts of particular evaluation sets but represent genuine architectural superiority for language modeling. Interestingly, xLSTM[$1$:$0$] performs better than xLSTM[$7$:$1$] on these language tasks, suggesting that for pure language modeling, the matrix memory of mLSTM provides the dominant benefit.

Downstream task evaluation measures performance on tasks requiring common sense reasoning, providing insight into whether perplexity improvements translate to practical capabilities. The evaluation includes multiple benchmarks, and xLSTM proves to be the best method in the vast majority of tasks across all model sizes. The only exception is the ARC task, where Mamba occasionally performs best. This overall pattern confirms that xLSTM's perplexity advantages reflect genuine improvements in language understanding, not just better probability assignment to tokens.

# Ablation Studies: The Impact of Exponential Gating, Matrix Memory, and Up-Projection Blocks

Understanding why an architecture works is often as important as demonstrating that it works. The ablation studies systematically deconstruct xLSTM, morphing a vanilla LSTM architecture step-by-step into the full xLSTM architecture. This approach isolates the contribution of each component, providing guidance for future architectural development.

The progression begins with integrating vanilla LSTM layers into pre-LayerNorm residual backbones. Pre-LayerNorm refers to applying layer normalization before each sublayer rather than after, a design choice that improves training stability and is standard in contemporary Large Language Models. This integration tests whether modern architectural practices improve LSTM performance even without changing the LSTM cell itself.

The second step extends the architecture to a post up-projection block. In this design, the model first non-linearly summarizes the past in the original space, then linearly projects into a higher-dimensional space, applies a non-linear activation, and linearly projects back. This structure draws on Cover's Theorem, which states that patterns non-linearly embedded in higher-dimensional spaces can more likely be linearly separated. Better separation of different histories enables better prediction of next sequence elements.

The third step adds exponential gating. This modification addresses the inability of standard LSTMs to revise storage decisions—the limitation demonstrated through the Nearest Neighbor Search problem in the introduction. Standard LSTM gates use sigmoid activation functions, which map to values between 0 and 1. Exponential gates can take on arbitrarily large positive values, providing stronger signal when the model decides to store new information and thereby enabling effective revision of previous storage decisions.

The final step adds matrix memory—the covariance update structure of mLSTM. This addresses the limited storage capacity of scalar cell states, allowing information to be stored in a $d \times d$ matrix rather than a scalar. The covariance update rule $\mathbf{C}_t = \mathbf{C}_{t-1} + \mathbf{v}_{t} \mathbf{k}_t^\top$ stores key-value pairs in a way that supports efficient retrieval via matrix multiplication with a query vector.

The ablation results attribute strong performance improvement to both exponential gating and matrix memory. Neither alone achieves the full performance of xLSTM, indicating that the two innovations address complementary limitations of the original LSTM.

The paper also includes ablation studies on gating mechanisms themselves. Having each gate be learnable and influenced by input has an incremental positive effect, validating that the gating structure—with input, forget, and output gates each computed from input and hidden state—is essential for strong performance. Additional studies on individual backbone components, detailed in the appendix, further illuminate the contribution of design choices within the residual block structure.

# Scaling Laws: Comparing the Performance Trajectory of xLSTM Against Other Architectures

Scaling laws describe how model performance changes as a function of model size and training data quantity. Understanding scaling behavior is crucial for predicting performance at scales too expensive to test directly, informing decisions about whether investing in larger models will yield meaningful improvements.

The paper presents scaling law analyses at both the 15 billion token and 300 billion token training scales. The scaling law plots show perplexity as a function of model size, with different architectures as different curves. At the 15 billion token scale, xLSTM shows favorable scaling behavior compared to all competing methods, with the curve indicating continued advantage at larger scales.

The 300 billion token scaling analysis provides even stronger evidence. All models share similar scaling behavior in the sense that they all follow power-law relationships, but with different offsets. This means that the relative ordering of methods remains consistent as scale increases—RWKV-4 performs worst, followed by Llama and Mamba, with xLSTM achieving the best performance at each scale. The margin between xLSTM and Mamba is similar to the margin between Mamba and Llama, suggesting that xLSTM represents a meaningful step forward comparable to the jump from Transformers to State Space Models.

The consistency of xLSTM's advantage across scales provides confidence that the architectural improvements will continue to pay dividends as models grow larger. This finding is significant for practitioners considering investing in xLSTM-based Large Language Models: the scaling laws suggest that xLSTM will remain competitive with or superior to Transformers and State Space Models even at scales beyond those tested in the paper.

The scaling behavior also validates the theoretical motivation for xLSTM's design. Exponential gating and matrix memory address fundamental limitations of LSTMs, and the persistent scaling advantages suggest that these improvements compound rather than diminish as model capacity increases.

# Inference Speed and Throughput Comparisons

Architecture comparisons often focus on quality metrics like perplexity or task accuracy, but practical deployment also depends on computational efficiency. The paper measures text generation time and maximal throughput, providing insight into how xLSTM performs in production-like conditions.

Text generation time measures wall-clock time to generate sequences of varying lengths. The experiments use batch size 1 with pre-fill 16 tokens—a configuration designed to be maximally favorable for the Transformer baseline, which benefits from the pre-fill computation being parallelizable. The results demonstrate linear scaling of generation time with sequence length for xLSTM, matching other recurrent models like Mamba and RWKV-4. In contrast, the Transformer (Llama) exhibits quadratic scaling with sequence length. This quadratic scaling arises from the attention mechanism's need to compute relationships between all pairs of tokens, while recurrent models like xLSTM only need to process each token once during generation.

Maximal throughput measures how many tokens per second a model can generate when maximally utilizing available computational resources. The constant memory footprint of recurrent models allows them to use much higher batch sizes than Transformers, which must maintain a key-value cache that grows linearly with both sequence length and batch size. The throughput experiments show that xLSTM achieves the highest throughput among compared methods, validating that the architectural advantages translate to practical deployment benefits.

The paper acknowledges current implementation limitations: the CUDA kernels for mLSTM are not fully optimized, currently running about four times slower than FlashAttention or the scan operation used in Mamba. The sLSTM blocks, due to their memory mixing, cannot be fully parallelized and are less than two times slower than the parallel mLSTM implementation. These are implementation limitations rather than architectural limitations—faster CUDA kernels following the FlashAttention approach could substantially improve wall-clock performance.

The linear computation complexity and constant memory complexity with respect to sequence length position xLSTM well for industrial applications and edge deployment, where memory constraints often limit practical deployment options. The matrix memory of mLSTM does not require parameters but involves $d \times d$ matrix operations, trading memory capacity against computational complexity. However, these computations can be parallelized on GPUs, minimizing wall-clock time impact.

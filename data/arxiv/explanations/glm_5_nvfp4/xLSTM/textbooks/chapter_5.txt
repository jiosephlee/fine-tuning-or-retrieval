\title{A Textbook about the Paper: "xLSTM: Extended Long Short-Term Memory"}

Chapter 5: # Constructing the xLSTM Architecture

Having introduced the two fundamental building blocks of the extended Long Short-Term Memory framework—the sLSTM with its scalar memory and exponential gating, and the mLSTM with its matrix memory and parallelizable structure—we now turn to the question of how these components are assembled into a complete neural network architecture. The transition from individual memory cells to a full-scale language model requires careful architectural design that draws upon decades of insights from deep learning research. This chapter explores the design principles behind xLSTM blocks, the theoretical motivation for their structure, and the practical considerations that govern their assembly into complete architectures.

# Design of xLSTM Blocks: Residual Block Backbones

The fundamental unit of the xLSTM architecture is the xLSTM block, which serves as a module that non-linearly summarizes the past in a high-dimensional space. This design choice is not arbitrary but stems from a fundamental requirement of sequence modeling: the ability to separate different histories or contexts. When processing a sequence, the model must be able to distinguish between different possible past contexts in order to correctly predict the next element, whether that be a token in language modeling or a value in time series prediction. The separation of histories is thus the prerequisite for accurate next-step prediction.

The xLSTM block architecture follows the residual block design pattern, which has become a cornerstone of modern deep learning. Residual blocks, introduced in the context of very deep convolutional networks, address the challenge of training extremely deep networks by introducing skip connections that allow gradients to flow more easily through the network during backpropagation. The xLSTM framework adopts this proven design pattern, integrating either the sLSTM or mLSTM variants into residual block modules to create what are termed xLSTM blocks.

The structure of these blocks reflects a balance between preserving the temporal processing capabilities of the LSTM variants and enabling efficient training through residual connections. Each xLSTM block operates on an input and produces an output that, combined with the input through a residual connection, forms the input to the next block. This design ensures that even as information passes through many layers of processing, the original signal is preserved, allowing the model to learn modifications to the input rather than complete transformations. The residual structure also facilitates the training of very deep networks, which is essential for scaling to the billions of parameters required for competitive large language models.

# Post Up-Projection Blocks for sLSTM vs. Pre Up-Projection Blocks for mLSTM

The xLSTM framework employs two distinct residual block architectures, each tailored to the specific characteristics of the memory variant it contains. These architectures differ in the order and placement of the projection operations relative to the recurrent processing.

For xLSTM blocks containing an sLSTM, the architecture uses a post up-projection design. In this configuration, the sequence is first processed non-linearly by the sLSTM in the original dimensional space, summarizing the past information. The output of this processing is then linearly mapped into a higher-dimensional space, where a non-linear activation function is applied. Finally, the result is linearly mapped back to the original dimensional space. This design—non-linear summary in the original space, followed by up-projection, activation, and down-projection—mirrors the architecture commonly used in Transformers. The post up-projection block is depicted in the left panel of Figure 1 in the paper and the third column of Figure 2, with a more detailed version shown in Figure 5 of the appendix.

For xLSTM blocks containing an mLSTM, the architecture instead employs a pre up-projection design. Here, the input is first linearly mapped to a higher-dimensional space. The non-linear summary of the past, performed by the mLSTM, takes place in this high-dimensional space. After the recurrent processing completes, the result is linearly mapped back to the original dimensional space. This design pattern is similar to that used in State Space Models and reflects a key insight: the matrix memory of the mLSTM operates more effectively when given access to a higher-dimensional representation space.

The rationale for this architectural distinction lies in the different memory structures of the two variants. The mLSTM's matrix memory, which stores key-value associations through a covariance update rule, benefits from operating in a higher-dimensional space because its memory capacity scales with the dimensionality. By performing the mLSTM computation in an expanded space, the model can store richer representations and retrieve more nuanced information. In contrast, the sLSTM, with its scalar memory and memory mixing capabilities, does not derive the same benefit from pre up-projection. The post up-projection design allows the sLSTM to perform its temporal processing in the original space, where the hidden-hidden connections can effectively mix information across memory cells.

# Application of Cover's Theorem for Non-Linear Separation

The architectural design of xLSTM blocks is grounded in a fundamental theoretical result from pattern recognition theory: Cover's Theorem. This theorem, established in 1965, provides a powerful justification for projecting data into higher-dimensional spaces before applying non-linear transformations. Cover's Theorem states that patterns that are non-linearly embedded into a higher-dimensional space are more likely to be linearly separable than patterns remaining in their original lower-dimensional space.

To understand the significance of this theorem for xLSTM architecture design, consider the task facing the model during sequence processing. At each time step, the model must predict the next element based on the history of the sequence observed so far. Different possible histories lead to different predictions, and the model must be able to distinguish between these histories to make accurate predictions. In other words, the model must separate different histories or contexts in its representation space.

Cover's Theorem suggests that this separation task becomes easier when the representations are first non-linearly transformed and projected into a higher-dimensional space. The xLSTM blocks implement exactly this principle. The non-linear processing performed by the sLSTM or mLSTM creates a non-linear embedding of the sequence history. The up-projection operations then map these embedded representations into a higher-dimensional space where linear separation becomes more feasible.

The practical implication is that the xLSTM block architecture is designed to transform the input representations in a way that maximizes the model's ability to distinguish between different sequence histories. By combining the non-linear temporal processing of the LSTM variants with dimensionality-expanding projections, the architecture creates a representation space where different contexts can be more readily separated. This separation is what enables accurate prediction of the next sequence element, whether that be a token in language modeling or any other sequential prediction task.

# Residual Stacking and the Use of Pre-LayerNorm

With individual xLSTM blocks designed, the question becomes how to assemble multiple blocks into a complete architecture. The xLSTM framework adopts the residual stacking approach that has become standard in contemporary deep learning, particularly for large language models.

Residual stacking refers to the practice of connecting multiple residual blocks in sequence, with each block receiving the sum of the input and output from the previous block. This approach, pioneered in ResNet architectures and subsequently adopted for Transformers, enables the training of very deep networks by providing pathways for gradient flow during backpropagation. Without residual connections, gradients must flow through all the non-linear transformations in each layer, which can lead to vanishing or exploding gradients in very deep networks. With residual connections, gradients can flow directly through the skip connections, bypassing the potentially problematic transformations in each block.

The xLSTM architecture employs the pre-LayerNorm variant of residual stacking, which has become the dominant approach in contemporary large language models. In pre-LayerNorm, layer normalization is applied before the main transformation in each block, rather than after. Specifically, for each xLSTM block, the input is first normalized using layer normalization, then processed by the block's main transformation (the up-projection, LSTM processing, and down-projection sequence), and finally added to the original input through a residual connection.

This pre-LayerNorm design offers several advantages over the alternative post-LayerNorm approach. First, it provides more stable gradients during training, as the normalization is applied to the input before the main transformation rather than to the output. Second, it enables more effective gradient flow through the residual connections, as the skip connection path does not pass through any normalization. These advantages become increasingly important as the depth of the network increases, making pre-LayerNorm essential for training the very deep networks required for large language models.

The complete xLSTM architecture is thus constructed by residually stacking multiple xLSTM blocks, each with its own internal structure tailored to the specific LSTM variant it contains. This construction follows the pattern established by ResNets and Transformers, both of which demonstrated the effectiveness of residual stacking for training deep networks. The paper notes that this approach has enabled deep convolutional networks and Transformers, which form the foundation of large language models like GPT-3, ChatGPT, GPT-4, and many others.

# Notation for xLSTM Architectures and Block Ratios

With the ability to mix sLSTM-based and mLSTM-based blocks in a single architecture, a notation system is needed to specify the composition of different block types. The xLSTM framework introduces a concise notation that captures the ratio of mLSTM-based to sLSTM-based blocks.

The notation $\text{xLSTM}[a:b]$ specifies that the ratio of mLSTM-based blocks to sLSTM-based blocks is $a/b$. For example, $\text{xLSTM}[7:1]$ indicates that out of every eight blocks in the architecture, seven are mLSTM-based blocks and one is an sLSTM-based block. For a common total block number of 48, which was used in many of the paper's experiments, this ratio translates to 42 mLSTM-based blocks and 6 sLSTM-based blocks.

The notation also supports architectures composed entirely of one block type. $\text{xLSTM}[1:0]$ denotes an architecture consisting only of mLSTM-based blocks, while $\text{xLSTM}[0:1]$ denotes an architecture consisting only of sLSTM-based blocks. The notation $\text{xLSTM}[1:1]$ indicates an equal mix of both block types.

Throughout the experimental evaluation presented in the paper, this notation is used consistently to specify the architecture configuration. For all experiments, the post up-projection block design is used for sLSTM-based blocks, while the pre up-projection block design is used for mLSTM-based blocks. This consistent pairing reflects the architectural principles discussed earlier in this chapter, where the block design is matched to the characteristics of the memory variant it contains.

The choice of block ratio is a hyperparameter that can be tuned for specific applications. The experiments in the paper explore various ratios to understand the contribution of each block type. For instance, in synthetic tasks testing exponential gating and memory mixing, the paper compares $\text{xLSTM}[0:1]$, $\text{xLSTM}[1:0]$, and $\text{xLSTM}[1:1]$ configurations. In the large-scale language modeling experiments training on 300B tokens, the paper primarily evaluates $\text{xLSTM}[1:0]$ and $\text{xLSTM}[7:1]$ configurations, finding that $\text{xLSTM}[1:0]$ performs particularly well on PALOMA language tasks with lower perplexity than competing methods in 568 out of 571 text domains compared to Mamba, and 486 out of 571 domains compared to Llama.

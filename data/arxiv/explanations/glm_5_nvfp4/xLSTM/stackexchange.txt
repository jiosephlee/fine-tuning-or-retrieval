\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### Why does exponential gating enable LSTM to revise storage decisions?
Question:
I'm reading the xLSTM paper, and they claim that exponential gating helps overcome the limitation of LSTMs being unable to revise storage decisions. They demonstrate this with the Nearest Neighbor Search problem.

However, I don't understand why changing from sigmoid activation to exponential activation for the gates makes such a difference. In the original LSTM, the input gate $i_t$ and forget gate $f_t$ are bounded between 0 and 1 due to the sigmoid function. With exponential gating, these gates can become arbitrarily large.

How does having unbounded positive gates enable the model to "revise" what it has stored? Can someone explain the intuition behind why exponential gating solves the Nearest Neighbor Search problem while sigmoid gating struggles?
Answer:
The key difference lies in how the gates interact with the cell state update and, crucially, the introduction of a **normalizer state** that creates a ratio rather than a raw sum.

**The Problem with Sigmoid Gating**

In a standard LSTM, the cell state updates as:
$$c_t = f_t \cdot c_{t-1} + i_t \cdot z_t$$

where both $f_t$ and $i_t$ are bounded in $[0, 1]$ due to the sigmoid. When you need to "revise" stored information—say, replace the current best match with a newly found better match—you want the new input $z_t$ to completely dominate the old cell state. However, the sigmoid limits how strong this signal can be: even with $i_t = 1$ and $f_t \approx 0$, the best you can do is replace the content with unit strength. More critically, sigmoid saturation means the gradients vanish when trying to learn these revision decisions, making it hard to train the model to recognize when revision should occur.

**How Exponential Gating Solves This**

The sLSTM introduces two changes:

1. **Exponential gates**: $i_t = \exp(\tilde{i}_t)$ can become arbitrarily large (and positive)
2. **A normalizer state**: $n_t = f_t \cdot n_{t-1} + i_t$

The hidden state is then computed as a ratio:
$$h_t = o_t \cdot \frac{c_t}{n_t}$$

This ratio represents a **weighted average** of all stored values, where the weights come from the gates. When a new input arrives with a very large exponential gate value (because $\exp(\tilde{i}_t)$ can be orders of magnitude larger than previous contributions), several things happen simultaneously:

- The numerator $c_t = f_t \cdot c_{t-1} + i_t \cdot z_t$ becomes dominated by $i_t \cdot z_t$
- The denominator $n_t = f_t \cdot n_{t-1} + i_t$ becomes dominated by $i_t$
- The ratio $c_t/n_t$ rapidly converges toward $z_t$

**Intuition via the Nearest Neighbor Search Problem**

In this task, you scan a sequence to find the vector most similar to a reference, then output its associated value. When you encounter a new vector that's more similar than the current best, you must *revise* your stored value. With sigmoid gates, this revision is sluggish—the bounded gates prevent a decisive overwrite, and gradient saturation makes learning when-to-revise difficult. With exponential gating, the model can emit a large gate value when it detects "this is a better match," causing the new value to completely overwhelm prior storage in the ratio $c_t/n_t$.

The paper demonstrates this empirically in Figure 1, showing that standard LSTMs struggle with this task while xLSTM succeeds, precisely because exponential gating enables the decisive overwriting that revision requires.

### What is the purpose of the normalizer state in sLSTM and mLSTM?
Question:
The xLSTM paper introduces a normalizer state $n_t$ that doesn't exist in the original LSTM. In sLSTM, they define:

$$n_t = f_t \cdot n_{t-1} + i_t$$

and the hidden state becomes $\tilde{h}_t = c_t / n_t$.

Similarly, in mLSTM, they have a normalizer state that tracks weighted key vectors. Why is this normalization necessary? The original LSTM just uses $h_t = o_t \cdot \psi(c_t)$ without any normalizer.

Is this related to the exponential gates? What would go wrong if we removed the normalizer state?
Answer:
The normalizer state is necessary precisely because xLSTM uses **exponential gates** instead of sigmoid gates. Let me explain the intuition and technical reasons.

## The Core Issue: Unbounded Gates

In the original LSTM, gates use the sigmoid function $\sigma(x) = 1/(1+e^{-x})$, which outputs values strictly in $(0, 1)$. This keeps the cell state $c_t$ bounded since:
$$c_t = f_t c_{t-1} + i_t z_t$$
where both $f_t$ and $i_t$ are at most 1.

In xLSTM, the input gate uses exponential activation: $i_t = \exp(\tilde{i}_t)$. This is **unbounded above**—it can take any positive value. Without normalization, the cell state could grow arbitrarily large, leading to numerical instability and exploding gradients.

## What the Normalizer Does

The normalizer state $n_t = f_t n_{t-1} + i_t$ tracks the cumulative "gate strength." If you unroll both recurrences:

$$c_t = i_t z_t + f_t i_{t-1} z_{t-1} + f_t f_{t-1} i_{t-2} z_{t-2} + \cdots$$

$$n_t = i_t + f_t i_{t-1} + f_t f_{t-1} i_{t-2} + \cdots$$

The hidden state $\tilde{h}_t = c_t / n_t$ then computes a **properly weighted average** where the exponential gate values act as unnormalized attention weights, and $n_t$ normalizes them to sum appropriately. This is analogous to how softmax normalizes attention scores in Transformers.

## For mLSTM: The Connection to Attention

The mLSTM case makes the attention analogy even clearer. The matrix memory $\mathbf{C}_t$ stores key-value pairs via the covariance update rule. When retrieving with query $\mathbf{q}_t$:

$$\mathbf{C}_t \mathbf{q}_t = \sum_{\tau} \left(\prod_{s=\tau+1}^{t} f_s\right) i_\tau \mathbf{v}_\tau (\mathbf{k}_\tau^\top \mathbf{q}_t)$$

The normalizer $\mathbf{n}_t^\top \mathbf{q}_t$ provides the denominator that makes this a proper weighted retrieval, similar to the denominator in softmax attention.

## What Would Go Wrong Without It?

Without the normalizer:
1. **Numerical overflow**: Exponential gates can easily produce values like $e^{10} \approx 22000$, leading to unbounded hidden states.
2. **Training instability**: Gradients would explode since derivatives of exponentials are themselves exponentials.
3. **Loss of interpretability**: The gating mechanism would no longer represent a meaningful "how much to store/retrieve" signal—it would just be arbitrary scaling.

The stabilizer state $m_t$ (Equation 9-11) works in tandem with the normalizer to prevent overflow during computation, but the normalizer itself is what gives the hidden state its proper scale and interpretation.

### What exactly is "memory mixing" in LSTMs and why does it prevent parallelization?
Question:
The xLSTM paper mentions that LSTMs suffer from "lack of parallelizability due to memory mixing, i.e., the hidden-hidden connections between hidden states from one time step to the next."

I understand that LSTMs have recurrent connections from $h_{t-1}$ to the various gates and cell input. But the paper says mLSTM "abandons memory mixing" to enable parallelization, while sLSTM retains it.

What exactly constitutes "memory mixing"? Is it just the presence of $h_{t-1}$ in the update equations? And why does removing these hidden-hidden connections make mLSTM parallelizable? Does that mean mLSTM has no recurrence at all, or just a different kind of recurrence?
Answer:
**Memory mixing** refers specifically to the recurrent connections from the previous hidden state $h_{t-1}$ to the computations of the current gates and cell input. In the original LSTM, the cell input and all three gates depend on $h_{t-1}$ through recurrent weights:

$$\tilde{z}_t = \mathbf{w}_z^\top \mathbf{x}_t + r_z h_{t-1} + b_z$$

and similarly for $\tilde{i}_t$, $\tilde{f}_t$, and $\tilde{o}_t$. These hidden-hidden connections create a sequential dependency chain: to compute $h_t$, you must first compute $h_{t-1}$, which requires $h_{t-2}$, and so on. This sequential chain cannot be parallelized—you must process time steps one after another.

**mLSTM abandons memory mixing** by removing these hidden-hidden connections entirely. Looking at the mLSTM equations, the query, key, value, input gate, forget gate, and output gate are all computed *only* from the current input $\mathbf{x}_t$:

$$\mathbf{q}_t = \mathbf{W}_q \mathbf{x}_t + \mathbf{b}_q, \quad i_t = \exp(\mathbf{w}_i^\top \mathbf{x}_t + b_i), \quad \text{etc.}$$

There is no $h_{t-1}$ term. The only recurrence in mLSTM is the cell state update:

$$\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top$$

and similarly for the normalizer state. Crucially, this is a **linear recurrence**—a form that *can* be parallelized using associative scan algorithms (parallel prefix sum), similar to how Mamba and other State Space Models achieve parallelization. The paper notes this recurrence "can be reformulated in a parallel version" (Appendix B provides details).

So mLSTM does have recurrence, but it's a **parallelizable form**—a linear scan rather than the non-parallelizable sequential dependency created by memory mixing. This distinction is why sLSTM (which retains memory mixing) requires a fast CUDA implementation and runs "less than two times slower than mLSTM" rather than being fully parallelizable like mLSTM.

The key insight is that **not all recurrence prevents parallelization**—only recurrence where the computation at step $t$ depends nonlinearly on the output of step $t-1$ creates a sequential bottleneck. Linear recurrences can be parallelized via scan operations.

### How does the stabilizer state prevent overflow in exponential gates?
Question:
In the sLSTM section, the paper introduces a stabilizer state $m_t$ defined as:

$$m_t = \max(\log(f_t) + m_{t-1}, \log(i_t))$$

And then they compute stabilized versions:
$$i'_t = \exp(\log(i_t) - m_t)$$
$$f'_t = \exp(\log(f_t) + m_{t-1} - m_t)$$

The paper claims this stabilizes the gates without changing the network output or gradients. But I'm confused about how this works. Why does subtracting $m_t$ from the log prevent overflow? And how can this transformation preserve both the output and the gradients?
Answer:
The stabilizer state mechanism in sLSTM is essentially a **log-domain normalization trick** that prevents numerical overflow while preserving mathematical equivalence. Let me explain both aspects.

## Why It Prevents Overflow

The exponential gates $i_t = \exp(\tilde{i}_t)$ and $f_t = \exp(\tilde{f}_t)$ can produce extremely large values when their inputs are large. Moreover, when gates are multiplied over many timesteps (as happens in the recurrent updates), these products can grow exponentially and cause overflow.

The stabilizer $m_t$ tracks the running maximum in log-space:

$$m_t = \max(\log(f_t) + m_{t-1}, \log(i_t))$$

When we compute $i'_t = \exp(\log(i_t) - m_t)$ and $f'_t = \exp(\log(f_t) + m_{t-1} - m_t)$, we're **normalizing by the maximum value**. Since $m_t$ is defined as the maximum of the two arguments:

- If $\log(i_t) \geq \log(f_t) + m_{t-1}$, then $m_t = \log(i_t)$, so $i'_t = \exp(0) = 1$
- If $\log(f_t) + m_{t-1} \geq \log(i_t)$, then $m_t = \log(f_t) + m_{t-1}$, so $f'_t \cdot f'_{t-1} \cdots$ will have one term equal to 1

This guarantees that at least one stabilized value equals exactly 1, and all others are $\leq 1$. No overflow can occur since we're taking exponentials of non-positive quantities.

## Why Outputs and Gradients Are Preserved

The key insight is that the stabilizer **factors out a common scale factor** that cancels in the final computation. Define $s_t = \exp(m_t)$. From the definitions:

$$i_t = i'_t \cdot s_t, \quad f_t = f'_t \cdot \frac{s_t}{s_{t-1}}$$

Now consider the normalizer state $n_t = f_t n_{t-1} + i_t$ and cell state $c_t = f_t c_{t-1} + i_t z_t$. By induction, you can show that the stabilized versions satisfy:

$$n'_t = \frac{n_t}{s_t}, \quad c'_t = \frac{c_t}{s_t}$$

Since the hidden state is the **ratio**:

$$h_t = o_t \cdot \frac{c_t}{n_t} = o_t \cdot \frac{c_t/s_t}{n_t/s_t} = o_t \cdot \frac{c'_t}{n'_t}$$

the scale factor $s_t$ cancels out exactly. The same argument applies to the gradient flow through backpropagation—since we're computing the same mathematical function, just in a numerically stable way, gradients with respect to all parameters remain identical.

This technique is analogous to the standard log-sum-exp trick used in computing softmax stably, but applied recursively to handle the sequential nature of LSTM updates.

### How does mLSTM's covariance update rule relate to attention mechanisms?
Question:
The mLSTM section mentions that the matrix memory uses a covariance update rule:

$$\mathbf{C}_t = \mathbf{C}_{t-1} + \mathbf{v}_t \mathbf{k}_t^\top$$

and they use query, key, and value vectors (borrowing Transformer terminology). They also mention this is related to Bidirectional Associative Memories and Fast Weight Programmers.

I'm trying to understand the connection to attention. In standard attention, we compute $\text{softmax}(\mathbf{Q}\mathbf{K}^\top)\mathbf{V}$. In mLSTM, the retrieval is $\mathbf{C}_t \mathbf{q}_t$.

How are these related? Is mLSTM essentially implementing a form of linear attention? And why does the covariance update rule provide "maximal signal/noise ratio" for binary vector retrieval?
Answer:
The connection between mLSTM's covariance update rule and attention mechanisms is indeed fundamental, and yes, mLSTM essentially implements a form of linear attention with gating. Let me explain this connection.

## mLSTM as Linear Attention

In standard attention, for a query $\mathbf{q}_t$ at position $t$, we compute:
$$\text{Attention}(\mathbf{q}_t) = \sum_{i=1}^{t} \frac{\exp(\mathbf{q}_t^\top \mathbf{k}_i)}{\sum_j \exp(\mathbf{q}_t^\top \mathbf{k}_j)} \mathbf{v}_i$$

In mLSTM, unrolling the matrix memory update and retrieval gives:
$$\mathbf{C}_t \mathbf{q}_t = \left(\sum_{i=1}^{t} \mathbf{v}_i \mathbf{k}_i^\top\right) \mathbf{q}_t = \sum_{i=1}^{t} (\mathbf{q}_t^\top \mathbf{k}_i) \mathbf{v}_i$$

This is precisely **linear attention** without the exponential softmax. The attention weights are simply $\alpha_i = \mathbf{q}_t^\top \mathbf{k}_i$ — the raw dot-product similarities between query and keys, rather than softmax-normalized exponentials. The normalizer state $\mathbf{n}_t$ in mLSTM provides an alternative normalization mechanism, dividing by $|\mathbf{n}_t^\top \mathbf{q}_t|$ to stabilize the output.

## Why Covariance Update for Maximal Signal/Noise Ratio?

The paper references the optimality of the covariance update rule from classical associative memory literature (Sejnowski 1977, Dayan 1991). The intuition is as follows: when storing key-value pairs $(\mathbf{k}_i, \mathbf{v}_i)$ using outer products $\mathbf{v}_i \mathbf{k}_i^\top$, retrieval with a query $\mathbf{q} \approx \mathbf{k}_j$ gives:

$$\mathbf{C}_t \mathbf{q} = \mathbf{v}_j (\mathbf{k}_j^\top \mathbf{q}) + \sum_{i \neq j} \mathbf{v}_i (\mathbf{k}_i^\top \mathbf{q})$$

If keys are zero-mean and approximately uncorrelated (achievable via layer-norm as mentioned in the paper), the cross-terms $\mathbf{k}_i^\top \mathbf{q}$ for $i \neq j$ act as noise centered around zero, while the signal term $\mathbf{k}_j^\top \mathbf{q}$ is maximized. This covariance rule provides optimal signal-to-noise ratio for retrieving binary vectors in associative memories like Bidirectional Associative Memories (BAMs).

## Key Differences from Standard Attention

The mLSTM adds crucial mechanisms beyond basic linear attention:

1. **Exponential gating**: The input gate $i_t$ and forget gate $f_t$ control memory updates with $i_t = \exp(\tilde{i}_t)$, enabling the model to revise storage decisions — a key limitation of vanilla LSTMs that the paper addresses.

2. **Temporal decay**: The forget gate $f_t$ multiplies $\mathbf{C}_{t-1}$, providing controlled decay of past memories rather than perfect accumulation.

3. **Parallelizability**: Unlike standard LSTMs, mLSTM abandons hidden-hidden recurrent connections ("memory mixing"), making it parallelizable like Transformers — the matrix operations can be computed efficiently across timesteps.

The paper explicitly notes that "Higher separability is possible when limiting retrieval to pairwise interactions and conceding quadratic complexity like attention" — meaning standard attention's softmax provides better pattern separation, but at $O(t^2)$ cost versus mLSTM's $O(t)$ complexity.

### Why can't Transformers and State Space Models solve state tracking problems like parity?
Question:
In the experiments section, the paper tests xLSTM on formal language tasks and states:

"Models such as Transformers or State Space Models without memory mixing (no state tracking) cannot solve, e.g. regular grammars like the parity task. This result is in agreement with findings that Transformers and State Space models are fundamentally less powerful than RNNs."

This confuses me. Transformers can attend to the entire sequence, so why can't they track state? The parity problem just requires counting whether we've seen an odd or even number of 1s.

What does "memory mixing" provide that enables state tracking? And why is this fundamentally impossible for attention-based or state space models? Is this a theoretical limitation or a practical one?
Answer:
The key to understanding this limitation lies in the distinction between **memory mixing** and the types of computations different architectures can perform.

## What is Memory Mixing?

Memory mixing refers to the hidden-hidden recurrent connections where the previous hidden state $h_{t-1}$ directly influences the computation at time step $t$ through learned weights. In the original LSTM and the new sLSTM, this appears in equations like:

$$\tilde{z}_t = \mathbf{w}^\top_{z} \mathbf{x}_t + r_{z} h_{t-1} + b_{z}$$

where $h_{t-1}$ non-linearly modulates the cell input, gates, and output through recurrent weights.

## Why Can't Transformers Solve Parity?

Although Transformers can attend to all previous positions, attention computes a **weighted average** over positions:

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$

The parity task requires tracking a **discrete binary state** that toggles between two values with each occurrence of a "1". This is essentially simulating a 2-state finite automaton. The theoretical work cited by the paper (Merrill et al., Deletang et al.) demonstrates that attention-based models are fundamentally limited in their computational expressivity—they cannot reliably compute this kind of discrete state transition because:

1. Attention computes smooth, weighted combinations rather than discrete decisions
2. The model must maintain an exact count modulo 2, which gets "smeared" through the softmax averaging

## Why Can't State Space Models Solve It?

SSMs like Mamba use **linear recurrences** of the form:

$$h_t = A h_{t-1} + B x_t$$

While efficient and parallelizable, linear recurrences cannot implement the non-linear state transitions required for tracking discrete states like parity. The hidden state evolves as a linear combination of inputs, not as discrete state flips.

## What Memory Mixing Provides

The non-linear recurrence in LSTMs (and sLSTM) with memory mixing allows the network to implement arbitrary state machines. The hidden state $h_{t-1}$ passes through learned non-linear transformations before influencing $h_t$, enabling the network to maintain and update discrete internal states. As the paper states:

> "Memory mixing enables to solve state tracking problems, and therefore LSTMs are more expressive than State Space Models (SSMs) and Transformers."

This is why sLSTM (which has memory mixing) can solve parity while mLSTM (which lacks memory mixing for parallelization) cannot. It's a **theoretical limitation** rooted in computational complexity theory—these architectures belong to different computational classes with fundamentally different expressive power.

### Why does sLSTM use post up-projection while mLSTM uses pre up-projection?
Question:
The paper describes two types of residual blocks:

1. Post up-projection: "non-linearly summarizes the past in the original space, then linearly maps into a high-dimensional space"
2. Pre up-projection: "linearly maps to a high-dimensional space, non-linearly summarizes the past in the high-dimensional space"

They say sLSTM uses post up-projection blocks, while mLSTM uses pre up-projection blocks because "the memory capacity becomes larger in the high-dimensional space."

I don't quite follow this reasoning. Both sLSTM and mLSTM are doing non-linear summarization. Why does the order of projection matter? And why specifically does mLSTM benefit from being in high-dimensional space for its memory operations, while sLSTM doesn't need this?
Answer:
The key insight lies in how the memory structure of each variant interacts with dimensionality.

**sLSTM has scalar memory**: Each cell state $c_t$ is a scalar (or a vector of scalars across multiple cells). The memory capacity is determined by the *number of cells*, not by the dimensionality of the working space. Whether sLSTM operates in dimension $d$ or $4d$, it still stores and retrieves scalar values through its gates. The non-linear summarization happens through the gating mechanism and memory mixing (hidden-hidden recurrent connections), which doesn't benefit from a higher-dimensional workspace in terms of storage.

**mLSTM has matrix memory**: The cell state $\mathbf{C}_t \in \mathbb{R}^{d \times d}$ is a matrix. Crucially, the memory capacity scales as $d^2$—the matrix can store outer product associations between $d$-dimensional keys and values. If you up-project to a higher dimension $d'$ *before* the mLSTM operation, your matrix memory becomes $\mathbf{C}_t \in \mathbb{R}^{d' \times d'}$, giving you $(d'/d)^2$ times more storage capacity.

This is why the order matters:

- **Post up-projection (sLSTM)**: The LSTM does its non-linear memory mixing and gating in the original space, then the result is projected to a higher dimension for better separability (per Cover's Theorem). The memory operations themselves don't benefit from higher dimensions.

- **Pre up-projection (mLSTM)**: You first project to a higher dimension, so the matrix memory operates in that larger space. The $d \times d$ matrix memory directly benefits from the increased dimensionality, as this is where the key-value associations are stored via the covariance update rule $\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top$.

In essence, mLSTM's matrix memory *is* the high-dimensional representation, so you want to be in that high-dimensional space during the memory operations. sLSTM's scalar memory doesn't have this property—the memory mechanism is independent of the working dimension.

### How can mLSTM be parallelized if it's still a recurrent architecture?
Question:
The paper claims that mLSTM is "fully parallelizable" despite being a recurrent network. It mentions this is possible because mLSTM abandons memory mixing (the hidden-hidden connections).

However, looking at the update equations, mLSTM still has recurrence:
$$\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top$$
$$\mathbf{n}_t = f_t \mathbf{n}_{t-1} + i_t \mathbf{k}_t$$

The cell state and normalizer state still depend on their previous values. So how is this parallelizable? The paper mentions a "parallel version" in the appendix, but I'm confused about how you can parallelize something that has an inherent sequential dependency.

Is this similar to how Mamba or other state space models achieve parallelization? What's the trick that makes this possible?
Answer:
The parallelization of mLSTM is indeed a clever trick that comes from recognizing what type of recurrence remains after removing memory mixing.

**The key insight:** Memory mixing refers specifically to hidden-hidden connections—when the gates or inputs at time $t$ depend on $\mathbf{h}_{t-1}$. In traditional LSTMs, you must compute $\mathbf{h}_{t-1}$ before you can even *begin* computing the gates at time $t$, creating an inherently sequential bottleneck.

mLSTM removes this dependency entirely. Notice in the equations that $\tilde{i}_t$, $\tilde{f}_t$, $\mathbf{q}_t$, $\mathbf{k}_t$, and $\mathbf{v}_t$ depend **only** on $\mathbf{x}_t$ (and learned parameters), not on $\mathbf{h}_{t-1}$. This means you can compute all gates and all key/value/query projections for every time step in parallel—a simple matrix multiplication over the entire sequence.

**But what about the recurrence in $\mathbf{C}_t$ and $\mathbf{n}_t$?** This is where the magic of *parallel scan* (also called *associative scan* or *prefix scan*) comes in. The recurrence:
$$\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top$$

is a **linear recurrence** of the form $y_t = a_t \cdot y_{t-1} + b_t$. This operation is *associative* when viewed as a binary operation, which means it can be computed in parallel using a divide-and-conquer strategy in $O(\log T)$ parallel steps rather than $O(T)$ sequential steps.

Concretely, unrolling the recurrence gives:
$$\mathbf{C}_t = \left(\prod_{s=1}^{t} f_s\right) \mathbf{C}_0 + \sum_{s=1}^{t} \left(\prod_{r=s+1}^{t} f_r\right) i_s \mathbf{v}_s \mathbf{k}_s^\top$$

The products of forget gates are prefix products, and the weighted sum is a weighted prefix sum—both are classic parallel scan operations that GPUs can compute efficiently.

This is exactly the same technique used by Mamba and other state space models. The paper explicitly draws this connection, stating that mLSTM is "parallelizable analog to FlashAttention or GLA" and that this technique is similar to what's used in the scan operation for Mamba.

The contrast with sLSTM is instructive: sLSTM *does* have memory mixing (hidden-hidden connections), which means the gates at time $t$ depend on $h_{t-1}$. This breaks the parallel scan approach entirely—you genuinely cannot compute anything at time $t$ until time $t-1$ is finished. The paper notes they developed a fast CUDA implementation for sLSTM, but it remains inherently sequential and is "less than two times slower than mLSTM."

### What does the paper mean by mLSTM having multiple heads vs multiple cells being equivalent?
Question:
In the xLSTM architecture section, the paper states:

"For mLSTM multiple heads and multiple cells are equivalent."

And for sLSTM:
"The new sLSTM can have multiple heads with memory mixing within each head but not across heads."

I understand the concept of heads from Transformer architectures (where each head learns different attention patterns). But what does having "multiple cells" mean in this context? And why are heads and cells equivalent for mLSTM but not for sLSTM?

Is this related to the lack of memory mixing in mLSTM? I'm having trouble visualizing what the architecture looks like with multiple cells versus multiple heads.
Answer:
The distinction between "multiple heads" and "multiple cells" hinges on the concept of **memory mixing**—the hidden-hidden recurrent connections that allow different memory units to communicate.

## What is Memory Mixing?

In traditional LSTMs with multiple cells, the hidden state vector $\mathbf{h}_{t-1} \in \mathbb{R}^d$ from all cells is used to compute the inputs and gates for each cell via recurrent weight matrices $\mathbf{R}$. This means cells can influence each other's computations—the paper calls this "memory mixing."

For sLSTM, the gates depend on the hidden state:
$$\tilde{i}_t = \mathbf{w}_i^\top \mathbf{x}_t + r_i h_{t-1} + b_i$$

Here, $h_{t-1}$ comes from *all* cells, enabling cross-cell communication.

## mLSTM: No Memory Mixing

mLSTM deliberately removes these hidden-hidden connections for parallelizability. Notice the mLSTM equations—the input and forget gates only depend on the input $\mathbf{x}_t$:

$$\tilde{i}_t = \mathbf{w}_i^\top \mathbf{x}_t + b_i$$
$$\tilde{f}_t = \mathbf{w}_f^\top \mathbf{x}_t + b_f$$

There's no $h_{t-1}$ term. Each mLSTM unit with its matrix memory $\mathbf{C}_t \in \mathbb{R}^{d \times d}$ operates completely independently.

Because there's **no communication between units**, it doesn't matter whether you call them "cells" or "heads"—they're just independent, parallel units. Organizing them as "multiple cells" or "multiple heads" yields identical architectures.

## sLSTM: Memory Mixing Exists

sLSTM retains hidden-hidden connections. When you have multiple cells, they communicate via the shared hidden state $h_{t-1}$. But when you introduce **multiple heads**, the paper enforces that memory mixing only happens *within* each head, not *across* heads.

This creates a meaningful distinction:
- **Multiple cells**: All cells can communicate with each other
- **Multiple heads**: Cells within a head communicate, but heads are isolated from each other

This head structure with exponential gating enables a new form of memory mixing that the paper claims improves expressivity for state-tracking tasks.

## Visualizing the Difference

Think of it this way:
- **mLSTM**: Multiple independent workers who never talk to each other. Whether you call them "heads" or "cells" is just labeling—they're functionally identical.
- **sLSTM**: Multiple workers who communicate. "Cells" means everyone talks to everyone. "Heads" means workers are grouped into teams—team members communicate, but teams don't talk to other teams.

The equivalence for mLSTM isn't a design choice—it's a mathematical consequence of removing memory mixing entirely.

### Why is Cover's Theorem cited for the xLSTM block design?
Question:
In describing xLSTM blocks, the paper cites Cover's Theorem, which "states that in a higher dimensional space non-linearly embedded patterns can more likely be linearly separated than in the original space."

They use this to justify non-linearly summarizing the past in high-dimensional space to "better separate different histories or contexts."

I'm confused about how Cover's Theorem applies here. Isn't this theorem about pattern separability in pattern recognition? How does it relate to the design of a recurrent neural network block? And specifically, what design decisions does this theorem motivate in the xLSTM architecture?
Answer:
You're right that Cover's Theorem originates from pattern recognition, but the xLSTM paper uses it as a design principle for the block architecture. Let me explain the connection.

**What Cover's Theorem States**

Cover's Theorem (1965) says that when patterns are non-linearly projected into a higher-dimensional space, they become more likely to be linearly separable than in the original lower-dimensional space. This is a foundational result behind kernel methods and the success of neural networks—the idea being that difficult classification problems can become tractable when you transform your data appropriately.

**How xLSTM Applies It**

The paper reframes language modeling as a problem of "separating histories." At each step, the model must predict the next token based on the past context. Different histories require different predictions. If the model can better distinguish between different histories in its representation space, predictions improve.

This is exactly where Cover's Theorem motivates the xLSTM block design. The paper states the block should:

1. **Non-linearly summarize the past** — achieved by the sLSTM or mLSTM modules through their gated recurrent processing with exponential activations
2. **Do so in a high-dimensional space** — achieved through up-projection layers that expand the hidden dimension

The combination creates a representation space where different histories become more separable, which the paper identifies as "the prerequisite to correctly predict the next sequence element."

**The Two Block Architectures**

The theorem informs two designs:

- **Post up-projection blocks** (for sLSTM): First summarize non-linearly in the original space via sLSTM, then project to higher dimensions. Since sLSTM has memory mixing (hidden-hidden connections), it benefits from processing before the up-projection.

- **Pre up-projection blocks** (for mLSTM): First project to higher dimensions, then summarize non-linearly in that space. This is chosen because mLSTM's matrix memory $\mathbf{C}_t \in \mathbb{R}^{d \times d}$ directly benefits from the larger dimension—the memory capacity scales quadratically with dimension.

**Why This Matters**

The theoretical justification connects to a practical design choice: you need both non-linearity (from the LSTM computation) and increased dimensionality (from up-projection) working together. The block design isn't arbitrary—it's structurally motivated by the principle that transforming representations into a high-dimensional non-linear space facilitates better discrimination between contexts.

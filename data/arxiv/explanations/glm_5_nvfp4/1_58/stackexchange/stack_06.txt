\title{Stack Exchange of the Paper: "The Era of 1-bit LLMs: All Large Language Models are in 1.58 Bits"}

### How does 8-bit activation quantization avoid zero-point quantization issues?
Question:
The paper mentions that for activations, they "scale to $[-Q_b, Q_b]$ per token to get rid of the zero-point quantization," and that this is "more convenient and simple for both implementation and system-level optimization."

I'm confused about what "zero-point quantization" refers to here. Is this related to symmetric vs asymmetric quantization? Why is removing the zero-point advantageous, and what does scaling per token mean exactly? Does this introduce any additional operations during inference?
Answer:
The paper's mention of "zero-point quantization" refers to the offset term used in asymmetric quantization schemes. Let me break this down.

**Symmetric vs Asymmetric Quantization**

In quantization, we map continuous floating-point values to discrete integer values. There are two main approaches:

- **Asymmetric quantization** uses a scale factor $s$ and a zero-point $z$: the quantized value is $q = \mathrm{round}(x/s) + z$. This is necessary when the input range isn't symmetric around zero, or when using unsigned integers (e.g., $[0, 255]$). The zero-point is the integer value that maps back to the floating-point zero.

- **Symmetric quantization** has no zero-point offset—the range is symmetric around zero, like $[-127, 127]$. The quantization simplifies to $q = \mathrm{round}(x/s)$, and dequantization is simply $x \approx q \times s$.

**What the Paper Does**

The original BitNet scaled activations to $[0, Q_b]$, which requires a zero-point since the range doesn't include negative values. BitNet b1.58 instead scales activations to $[-Q_b, Q_b]$ (symmetric around zero), eliminating the need for a zero-point entirely.

**Why This is Advantageous**

Removing the zero-point simplifies both the arithmetic and the hardware. In asymmetric quantization, matrix multiplication requires compensating for the zero-point offsets of both the weights and activations—this adds extra operations. With symmetric quantization (no zero-point), the core computation is cleaner: the matrix multiplication directly produces correctly scaled results without additional correction terms. This is what the paper means by "convenient and simple for both implementation and system-level optimization."

**Scaling Per Token**

"Per token" scaling means each token in a sequence gets its own scale factor. For a sequence of length $L$, rather than using one global scale for the entire activation tensor, the model computes $L$ separate scales—one for each token position. This allows each token's activations to optimally utilize the full quantization range $[-Q_b, Q_b]$, improving precision.

**Additional Operations**

Yes, this introduces extra computation: finding the maximum absolute value per token and applying the scale factor. However, these are simple reduction operations that are negligible compared to the matrix multiplications dominating LLM inference, which the paper confirms: it "introduces negligible effects to the performance in our experiments."

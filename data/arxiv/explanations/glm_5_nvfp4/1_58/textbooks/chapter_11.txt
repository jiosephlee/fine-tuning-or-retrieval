\title{A Textbook about the Paper: "The Era of 1-bit LLMs: All Large Language Models are in 1.58 Bits"}

Chapter 11: # The New Scaling Law for LLMs

The development of Large Language Models has traditionally been governed by a well-understood scaling law: as model size increases, performance improves, but so do the computational costs. This relationship has defined the economics of training and deploying LLMs, creating a seemingly inescapable trade-off between capability and cost. However, the introduction of 1-bit LLM architectures, particularly BitNet b1.58, fundamentally transforms this paradigm. This chapter explores the new scaling law enabled by ternary weight quantization, demonstrating how it rewrites the rules that have governed LLM development and opens new possibilities for model design and deployment.

# Defining the New Scaling Law: Performance vs. Inference Cost

The traditional scaling law for LLMs establishes a direct relationship between model performance and inference cost. As models grow larger to achieve better performance, they require proportionally more memory, computation, and energy. This relationship has been a fundamental constraint in LLM development, forcing practitioners to make difficult trade-offs between model capability and deployment feasibility.

BitNet b1.58 introduces a fundamentally different scaling paradigm. The key insight is that by constraining every weight parameter to ternary values $\{-1, 0, 1\}$, the model achieves performance comparable to full-precision counterparts while dramatically reducing inference costs. This is not merely an incremental improvement but a qualitative shift in how performance scales with model size.

The new scaling law can be understood through multiple dimensions of cost: latency, memory consumption, throughput, and energy consumption. Each of these dimensions shows that BitNet b1.58 scales more favorably than traditional FP16 models. Critically, the performance gap between BitNet b1.58 and full-precision models narrows as model size increases, with BitNet b1.58 matching full-precision performance starting from the 3B parameter scale. This means that beyond a certain threshold, there is no performance penalty for using 1.58-bit quantization.

The efficiency gains scale with model size, creating an interesting property: larger models benefit proportionally more from the 1.58-bit architecture. For instance, the speed-up ratio increases as models grow larger. A BitNet b1.58 model at 70B parameters is 4.1 times faster than its LLaMA LLM baseline. This occurs because the time cost for matrix multiplication operations, specifically $\emph{nn.Linear}$ layers, grows with model size, and these operations benefit most from the ternary weight representation. Similarly, memory consumption follows this trend because the embedding layer remains full precision, and its proportional contribution to total memory decreases for larger models.

This scaling behavior has profound implications. It suggests that the most efficient path to high-performance LLMs is not through ever-larger full-precision models, but through larger 1.58-bit models that maintain computational tractability. The new scaling law decouples model performance from the exponential growth in inference costs that has characterized traditional LLM development.

# Equivalence Relationships: 13B 1.58-bit ≈ 3B FP16

One of the most striking findings from the BitNet b1.58 research is the set of equivalence relationships between 1.58-bit models and their full-precision counterparts. These equivalences are not about matching raw parameter counts, but rather about matching the practical deployment characteristics—specifically, the inference costs in terms of latency, memory usage, and energy consumption.

The paper establishes three key equivalence relationships. First, a 13B BitNet b1.58 model is more efficient than a 3B FP16 LLM across all three cost dimensions. Second, a 30B BitNet b1.58 model is more efficient than a 7B FP16 LLM. Third, a 70B BitNet b1.58 model is more efficient than a 13B FP16 LLM.

To understand what these equivalences mean, consider the first relationship: 13B BitNet b1.58 versus 3B FP16 LLM. Despite having over four times the number of parameters, the 13B BitNet b1.58 model has lower latency, uses less memory, and consumes less energy than a 3B full-precision model. This is possible because each parameter in BitNet b1.58 requires only approximately 1.58 bits to represent, compared to 16 bits for FP16 parameters. The ternary representation $\{-1, 0, 1\}$ means that weights can be stored and processed far more efficiently.

These equivalence relationships reshape how we should think about model selection. Previously, if deployment constraints limited you to running a 3B parameter model efficiently, you would simply use a 3B FP16 model. The new scaling law suggests that you could instead deploy a 13B BitNet b1.58 model within the same resource envelope, achieving significantly better performance at equivalent or lower cost.

The practical implications extend to hardware planning and capacity provisioning. Organizations that have invested in infrastructure sized for particular FP16 models can potentially run much larger and more capable BitNet b1.58 models on the same hardware. This represents a substantial improvement in the return on infrastructure investment.

Furthermore, these equivalences suggest that the optimal model size for a given application has shifted dramatically upward when using 1.58-bit quantization. What was previously considered a "large" model requiring significant resources can now be deployed with the efficiency characteristics of a much smaller full-precision model.

# Pareto Improvement: Better Performance at Lower Cost

In economic terms, a Pareto improvement occurs when a change makes at least one party better off without making any other party worse off. In the context of LLMs, BitNet b1.58 achieves something even more remarkable: it improves performance while simultaneously reducing costs, creating what the paper explicitly describes as a Pareto improvement over state-of-the-art LLM models.

Consider the evidence from the experimental results. A BitNet b1.58 model with 3.9B parameters outperforms a LLaMA LLM with 3B parameters on end-task performance metrics, despite both being trained on identical configurations including the same training tokens. At the same time, the BitNet b1.58 3.9B model is 2.4 times faster and consumes 3.32 times less memory than the LLaMA LLM 3B. This is not a trade-off between performance and efficiency—both dimensions improve simultaneously.

The Pareto improvement becomes even more pronounced at larger scales. For the 70B parameter model, BitNet b1.58 achieves 4.1 times faster inference than the LLaMA LLM baseline. In terms of throughput, BitNet b1.58 70B can support up to 11 times the batch size compared to LLaMA LLM when running on two 80GB A100 cards, resulting in 8.9 times higher throughput.

The energy efficiency gains are perhaps most striking. The paper estimates that BitNet b1.58 saves 71.4 times the arithmetic operations energy consumption for matrix multiplication on 7nm chips compared to FP16 models. This dramatic reduction stems from the fundamental difference in computation: BitNet b1.58 primarily performs INT8 addition operations, while FP16 models require both FP16 addition and FP16 multiplication operations. Since matrix multiplication constitutes the bulk of LLM computation, this translates to substantial end-to-end energy savings.

The Pareto improvement has important implications for the field. It suggests that the binary choice between "better models" and "efficient models" is false when using 1.58-bit quantization. Practitioners no longer need to sacrifice performance for deployability or vice versa. This changes the fundamental economics of LLM deployment, making high-performance models accessible in scenarios where they were previously infeasible due to resource constraints.

# Implications for Model Design Decisions

The introduction of BitNet b1.58 necessitates a rethinking of fundamental model design decisions. Traditionally, architects have made choices about model size, architecture, and precision with the understanding that larger, higher-precision models would incur proportionally higher costs. The new scaling law inverts many of these assumptions.

One key design decision is the choice of training paradigm. Post-training quantization has been the dominant approach for creating low-bit models, reducing precision after training a full-precision model. However, the paper notes that post-training quantization is sub-optimal, even though it is widely used in industry. BitNet b1.58, in contrast, is trained from scratch with 1.58-bit weights and 8-bit activations. This native training approach allows the model to learn representations that are optimized for ternary weights rather than having full-precision representations compressed after the fact.

The architecture itself incorporates design choices that align with current best practices while enabling efficient implementation. BitNet b1.58 adopts LLaMA-alike components including RMSNorm, SwiGLU activation functions, rotary embeddings, and the removal of all biases. This design philosophy serves a practical purpose: by embracing the architecture that has become the de-facto backbone for open-source LLMs, BitNet b1.58 can be integrated into popular open-source software like Hugging Face, vLLM, and llama.cpp with minimal effort. This ease of integration accelerates adoption and allows practitioners to leverage existing tools and infrastructure.

The quantization function itself represents an important design decision. The paper introduces an $\mathrm{absmean}$ quantization function that constrains weights to $\{-1, 0, +1\}$. The function first scales the weight matrix by its average absolute value, then rounds each value to the nearest integer among the three allowed values:

$$\widetilde{W} = \mathrm{RoundClip}(\frac{W}{\gamma + \epsilon}, -1, 1)$$

where

$$\mathrm{RoundClip}(x, a, b) = \max(a, \min(b, \mathrm{round}(x)))$$

and

$$\gamma = \frac{1}{nm}\sum_{ij} |W_{ij}|$$

The inclusion of 0 in the weight values is a critical design choice that distinguishes BitNet b1.58 from the original BitNet. This additional value enables explicit feature filtering, allowing the model to selectively ignore certain inputs by setting corresponding weights to zero. This capability significantly improves modeling performance and is key to matching full-precision baselines.

For activations, the design scales to $[-Q_b, Q_b]$ per token rather than to $[0, Q_b]$, eliminating zero-point quantization. This approach is more convenient for implementation and system-level optimization while introducing negligible effects on performance.

# When to Choose 1.58-bit Over Full-Precision

The decision to use 1.58-bit quantization versus full-precision depends on several factors that the paper's results help illuminate. Understanding when to choose each approach requires examining performance thresholds, deployment constraints, and application requirements.

The primary consideration is model size. The paper demonstrates that BitNet b1.58 matches full-precision performance starting from the 3B parameter scale. Below this threshold, there may still be a performance gap between 1.58-bit and full-precision models. Therefore, for applications requiring smaller models (under 3B parameters), full-precision might still be necessary if maximum performance is the priority. However, at 3B parameters and above, there is no performance penalty for choosing BitNet b1.58.

Deployment environment strongly influences this decision. Edge and mobile devices are often limited by memory and computational power, restricting the scale of deployable LLMs. BitNet b1.58's reduced memory footprint and energy consumption make it particularly suitable for these constrained environments. The paper specifically notes that 1.58-bit LLMs are more friendly to CPU devices, which are the main processors in edge and mobile applications. This means BitNet b1.58 can be efficiently executed on devices where deploying equivalent FP16 models would be infeasible.

Throughput requirements favor BitNet b1.58 when serving large models at scale. The ability to support 11 times larger batch sizes with 8.9 times higher throughput for 70B parameter models represents a substantial advantage for production deployments where request volume is high. Organizations running inference services can achieve significantly higher utilization of their hardware investment.

Applications with long sequence requirements benefit from BitNet b1.58's efficiency characteristics. The model reduces activations from 16 bits to 8 bits, effectively doubling the context length achievable with the same resources. For applications requiring long-context understanding, this can be a decisive advantage.

Training data volume is another consideration. The paper shows that BitNet b1.58 maintains strong generalization capabilities even when trained on 2 trillion tokens. A BitNet b1.58 model trained following the data recipe of StableLM-3B achieved superior performance on all end tasks compared to the state-of-the-art open-source 3B model. This indicates that the 1.58-bit approach scales well with training data, making it suitable for applications requiring models trained on large corpora.

The choice also depends on hardware availability. Organizations with existing GPU infrastructure can achieve better performance within their current capacity constraints by switching to BitNet b1.58. Those investing in new infrastructure might consider hardware specifically optimized for 1-bit LLMs, which could provide even greater efficiency gains.

# Future-Proofing LLM Architectures

The emergence of 1.58-bit LLMs points toward several directions for future architecture development. The paper outlines several promising areas that could shape the next generation of language models.

Mixture-of-Experts (MoE) architectures represent a natural extension of 1.58-bit quantization. MoE models have proven cost-effective for LLMs by reducing computation FLOPs, but they face challenges from high memory consumption and inter-chip communication overhead. These limitations constrain deployment and application. BitNet b1.58 addresses these challenges directly: the reduced memory footprint decreases the number of devices required to deploy MoE models, and it significantly reduces the overhead of transferring activations across networks. The paper envisions that if entire models could be placed on a single chip, there would be no overhead at all, enabling highly efficient MoE deployments.

Long sequence handling is another frontier. The ability to process long contexts has become critical for many LLM applications, but memory consumption from KV caches poses a major challenge during inference. BitNet b1.58 takes a significant step toward native long sequence support by reducing activations from 16 bits to 8 bits, effectively doubling context length given equivalent resources. The paper suggests that this can be further losslessly compressed to 4 bits or even lower for 1.58-bit LLMs, opening possibilities for even longer context windows.

Edge and mobile deployment represents a substantial opportunity. These devices have historically been limited in the LLM capabilities they can support due to memory and computational constraints. BitNet b1.58's efficiency characteristics enable deployment of capable models on these platforms, potentially enabling applications that were previously impossible. The compatibility with CPU processing is particularly relevant for edge deployment, as these devices typically lack specialized GPU or TPU accelerators.

Perhaps most significantly, the paper calls for the development of new hardware specifically optimized for 1-bit LLMs. While current workarounds using existing GPU infrastructure with optimized kernels (such as the 2-bit kernel from Ladder) provide substantial benefits, purpose-built hardware could unlock even greater efficiency. The paper cites recent work like Groq's Language Processing Units (LPUs) as demonstrating the potential for specialized LLM hardware, and envisions going further with hardware designed specifically for the computation paradigm enabled by BitNet's ternary weights.

This new computation paradigm fundamentally differs from traditional matrix multiplication. In FP16 models, matrix multiplication requires floating-point addition and multiplication operations. In BitNet b1.58, matrix multiplication involves only integer addition—the ternary weights mean that multiplying by -1, 0, or 1 requires no actual multiplication operations. Hardware designed to exploit this property could achieve efficiency gains beyond what current general-purpose accelerators provide.

These future directions suggest that 1.58-bit quantization is not merely an optimization technique but a foundational shift in how LLMs are designed, trained, and deployed. Organizations and practitioners building LLM-based applications should consider how these developments might affect their architecture decisions and infrastructure investments, positioning themselves to take advantage of the continued evolution of efficient LLM technologies.

Chapter 5: # Quantization Functions in BitNet b1.58

# Weight quantization: the absmean quantization function

The fundamental innovation in BitNet b1.58 lies in its approach to constraining neural network weights to an extremely compact representation. Unlike traditional large language models that store weights as 16-bit floating-point numbers (FP16 or BF16), BitNet b1.58 constrains every single parameter to one of only three possible values: $\{-1, 0, 1\}$. This ternary representation is achieved through a carefully designed quantization function called the \textit{absmean} quantization function.

The absmean quantization function operates on the principle of relative scaling. Rather than applying a fixed threshold to determine weight values, the function first computes a scaling factor based on the weight matrix itself. Specifically, it scales the weight matrix by its average absolute value before performing any rounding operations. This adaptive scaling ensures that the quantization process preserves the relative magnitude information inherent in the original weight distribution, even though the final output contains only three distinct values.

The choice of the name "absmean" reflects the core computation at the heart of this quantization approach. The scaling factor $\gamma$ is computed as the mean of the absolute values of all elements in the weight matrix. By dividing each weight by this average magnitude, the quantization function normalizes the weight distribution around the values that will ultimately be rounded to $\{-1, 0, 1\}$. This normalization step is crucial because it allows the same quantization logic to work effectively across different layers and different model sizes, where the raw weight magnitudes might vary significantly.

The quantization process transforms a full-precision weight matrix $W$ into a ternary weight matrix $\widetilde{W}$. During training, the underlying weights remain as full-precision values that are continuously updated through backpropagation. However, during the forward pass, these weights are quantized on-the-fly using the absmean function, meaning that the actual computations performed by the model use only the ternary values. This approach, known as quantization-aware training, allows the model to learn weights that are optimized for the quantized representation, rather than attempting to quantize a pre-trained model after the fact.

# Mathematical formulation: RoundClip and γ scaling

The mathematical formulation of the absmean quantization function consists of three interconnected equations that work together to produce the final ternary weights. The first equation defines the overall quantization operation:

$$\widetilde{W} = \mathrm{RoundClip}(\frac{W}{\gamma + \epsilon}, -1, 1)$$

This equation shows that the quantized weight matrix $\widetilde{W}$ is obtained by first dividing the original weight matrix $W$ by $\gamma + \epsilon$, and then applying a function called RoundClip that constrains the result to the range $[-1, 1]$. The term $\epsilon$ represents a small constant added to prevent numerical instability in cases where $\gamma$ might be zero or very close to zero.

The scaling factor $\gamma$ is computed as:

$$\gamma = \frac{1}{nm}\sum_{ij} |W_{ij}|$$

Here, $n$ and $m$ represent the dimensions of the weight matrix, and the summation $\sum_{ij} |W_{ij}|$ computes the total of the absolute values of all elements in the weight matrix. By dividing by $nm$, we obtain the average absolute value. This computation provides a measure of the typical magnitude of weights in the matrix, which serves as an appropriate scaling factor for normalization.

The RoundClip function itself is defined as:

$$\mathrm{RoundClip}(x, a, b) = \max(a, \min(b, \mathrm{round}(x)))$$

This function takes an input value $x$ and two bounds $a$ and $b$ (in the weight quantization case, $a = -1$ and $b = 1$). The function first applies the standard rounding operation $\mathrm{round}(x)$ to obtain an integer value. It then uses the $\min$ function to ensure the result does not exceed the upper bound $b$, and subsequently uses the $\max$ function to ensure the result does not fall below the lower bound $a$.

The composition of these three equations creates a complete quantization pipeline. The division by $\gamma$ normalizes the weights so that values near $-1$, $0$, and $1$ in the normalized space correspond to the three allowed output values. The rounding operation then maps each normalized weight to its nearest integer. Finally, the clipping ensures that any outliers that might round to values outside $\{-1, 0, 1\}$ are constrained to the valid range.

# The rounding and clipping mechanism: constraining to {-1, 0, +1}

Understanding the rounding and clipping mechanism in detail reveals how the quantization function achieves its goal of producing ternary weights. The process begins after the weight values have been scaled by dividing by $\gamma + \epsilon$. At this stage, the scaled values will typically cluster around zero, with some values extending toward the positive and negative sides.

The rounding operation $\mathrm{round}(x)$ maps each scaled weight to the nearest integer. For a scaled weight value of, for example, $0.3$, the rounding would produce $0$. For a value of $0.7$, the rounding would produce $1$. Similarly, a value of $-0.6$ would round to $-1$. The standard rounding function rounds to the nearest integer, with values exactly halfway between two integers typically rounding to the nearest even integer in most implementations, though the specific tie-breaking behavior may depend on the implementation.

The clipping operation serves as a safety mechanism that ensures the output stays within the bounds of $\{-1, 0, 1\}$. In theory, after proper scaling by $\gamma$, most weight values should fall within the range that rounds to one of these three values. However, in practice, there may be outlier weights with magnitudes significantly larger than the average. Without clipping, such outliers might round to values like $2$ or $-2$, which would break the ternary constraint. The $\min(b, \cdot)$ operation ensures that any value greater than $1$ is set to $1$, while the $\max(a, \cdot)$ operation ensures that any value less than $-1$ is set to $-1$.

The result of this process is that every weight in the matrix is mapped to exactly one of three values: $-1$, $0$, or $+1$. The inclusion of $0$ as a valid weight value is a key distinction of BitNet b1.58 compared to the original BitNet, which used binary weights. The zero value enables explicit feature filtering, where a weight of zero effectively turns off the connection between two neurons. This capability significantly improves the modeling capacity of the quantized network, allowing it to match the performance of full-precision models at scale.

The ternary representation $\{-1, 0, 1\}$ corresponds to approximately 1.58 bits per weight in the binary system. This is because $\log_2(3) \approx 1.585$, meaning that three distinct values require approximately 1.58 bits to represent. This explains the "b1.58" nomenclature in the model name, indicating that the model operates at an effective bit-width of 1.58 bits per weight.

# Activation quantization: per-token scaling

In addition to weight quantization, BitNet b1.58 also employs activation quantization. The activations in neural networks represent the intermediate values that flow through the network during the forward pass. For BitNet b1.58, these activations are quantized to 8-bit integers, providing a balance between computational efficiency and numerical precision.

The activation quantization in BitNet b1.58 follows the same fundamental implementation approach as the original BitNet, with one important modification. In the original BitNet, activations were scaled to the range $[0, Q_b]$ before applying non-linear functions, where $Q_b$ represents the upper bound of the quantization range. This asymmetric range required the use of a "zero-point" in the quantization scheme, which is a parameter that adjusts for the fact that the range does not center around zero.

However, BitNet b1.58 introduces a modification to this approach. Instead of scaling activations to $[0, Q_b]$, the activations are scaled to $[-Q_b, Q_b]$, making the range symmetric around zero. This per-token scaling operation normalizes each token's activations independently, adjusting their range to fit within the symmetric bounds. The symmetric range simplifies the quantization scheme by eliminating the need for a zero-point parameter.

This modification was chosen because it offers several practical advantages. From an implementation perspective, symmetric quantization is simpler to code and debug. From a system-level optimization perspective, it reduces the number of operations and parameters that need to be managed during inference. The designers of BitNet b1.58 found through experimentation that this simplification introduces negligible effects on model performance, making it an attractive trade-off between complexity and capability.

# Eliminating zero-point quantization: scaling to [-Qb, Qb]

The elimination of zero-point quantization represents a significant simplification in the activation quantization process. To understand why this matters, it is helpful to first understand what zero-point quantization entails in traditional quantization schemes.

In asymmetric quantization, where values are mapped to a range like $[0, 255]$ (for 8-bit quantization), there is typically a mismatch between the actual range of the data and the quantization grid. The zero-point is a parameter that accounts for this asymmetry, allowing the quantized values to accurately represent the original distribution. However, managing this zero-point adds complexity to both the hardware implementation and the software optimization.

By scaling activations to the symmetric range $[-Q_b, Q_b]$, BitNet b1.58 eliminates the need for a zero-point entirely. The quantization becomes centered around zero, which aligns naturally with the weight quantization scheme where weights take on symmetric values $\{-1, 0, 1\}$. This symmetry creates a more harmonious computational flow, where the interaction between weights and activations can be implemented efficiently.

The scaling operation that maps activations to $[-Q_b, Q_b]$ is performed on a per-token basis. This means that for each token in the sequence, the activations are analyzed and scaled independently. Per-token scaling allows the quantization to adapt to the specific distribution of activations for each token, rather than applying a global scaling factor that might be suboptimal for some tokens. This adaptive approach helps maintain numerical precision across diverse inputs.

The practical benefits of eliminating zero-point quantization extend beyond just implementation simplicity. The symmetric quantization scheme is more amenable to hardware optimization, as the arithmetic operations become more uniform. This is particularly relevant for BitNet b1.58's goal of enabling a new computation paradigm, where the matrix multiplication operations can be highly optimized. The combination of ternary weights with symmetric activation quantization creates a computational pattern that is well-suited for specialized hardware acceleration.

# Comparison with original BitNet quantization approach

Comparing BitNet b1.58's quantization approach to the original BitNet reveals both continuities and innovations. The original BitNet pioneered the concept of training 1-bit LLMs from scratch, demonstrating that it is possible to achieve reasonable performance with extremely quantized weights. However, the original BitNet used binary weights, meaning weights were constrained to only two values: $\{-1, 1\}$.

The addition of $0$ as a third possible weight value in BitNet b1.58 represents a fundamental enhancement to the quantization scheme. With only $\{-1, 1\}$ as options, every weight in the original BitNet necessarily contributes to the computation, either adding or subtracting the input. The inclusion of $0$ enables what the paper describes as "explicit support for feature filtering." When a weight is $0$, it effectively disables that connection, allowing the network to learn sparse patterns where only the most relevant features contribute to each computation.

This enhancement in modeling capability is reflected in the empirical results. The paper demonstrates that BitNet b1.58 can match full-precision (FP16) baselines in terms of both perplexity and end-task performance, starting from a 3B model size. This achievement marks a significant milestone, as it shows that ternary quantization does not necessarily sacrifice model quality compared to full-precision alternatives.

The activation quantization also differs between the two approaches. While both BitNet variants use 8-bit activations, the original BitNet employed the asymmetric range $[0, Q_b]$ with zero-point quantization, whereas BitNet b1.58 adopts the symmetric range $[-Q_b, Q_b]$. This change simplifies the implementation while maintaining comparable performance. Both approaches are trained from scratch with quantization-aware training, rather than applying post-training quantization to a pre-trained model, ensuring that the learned weights are optimized for their quantized representation.

The naming convention reflects these differences: BitNet b1.58 explicitly references the 1.58-bit effective precision ($\log_2(3) \approx 1.585$), whereas the original BitNet operated at effectively 1 bit per weight. Despite this increase in precision, BitNet b1.58 retains the key benefits of the 1-bit approach, including the elimination of multiplication operations in matrix multiplication (replaced by integer addition) and the significant reductions in memory footprint, latency, and energy consumption.

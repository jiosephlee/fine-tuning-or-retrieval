\title{A Textbook about the Paper: "The Era of 1-bit LLMs: All Large Language Models are in 1.58 Bits"}

Chapter 10: # Throughput and System-Level Performance

When deploying Large Language Models in production environments, raw model quality metrics such as perplexity and task accuracy tell only part of the story. Equally important are system-level performance characteristics that determine whether a model can be deployed economically and whether it can meet the latency requirements of real-world applications. This chapter examines how BitNet b1.58 fundamentally transforms the throughput and efficiency landscape for LLMs, enabling deployment scenarios that were previously impractical or impossible with traditional full-precision models.

Understanding throughput requires us to think about what happens when multiple users or requests must be served simultaneously. In a production setting, an LLM inference server does not process one request at a time; instead, it attempts to batch multiple requests together to maximize hardware utilization. The ability to process larger batches directly translates to serving more users or handling more requests per unit time. However, batch size is fundamentally constrained by available memory—the model parameters, activations, and key-value caches must all fit within the accelerator's memory. This is where the dramatic memory savings of 1.58-bit quantization become transformative, not just for model quality, but for system-level throughput.

# Throughput Measurement Methodology

Measuring throughput for Large Language Models requires careful experimental design to ensure fair and meaningful comparisons between different model implementations. The research comparing BitNet b1.58 to the LLaMA LLM baseline established a rigorous methodology that accounts for the practical constraints of real-world inference systems.

The throughput experiments were conducted on two 80GB A100 cards, which represent high-end GPU accelerators commonly used for LLM inference in data center environments. The choice of hardware is significant because these devices have substantial memory capacity, yet even with 80GB per card, deploying a 70B parameter model requires careful resource management. To enable the LLaMA LLM 70B model to run on this hardware configuration, the researchers employed pipeline parallelism, a technique that distributes different layers of the model across multiple devices, allowing each device to store only a portion of the model parameters.

The experimental protocol involved systematically increasing the batch size until the GPU memory limit was reached. This approach identifies the maximum practical batch size that can be supported given the memory constraints of the hardware. For these experiments, a sequence length of 512 tokens was used, which represents a moderately sized context window typical of many inference scenarios. The sequence length matters because it affects both the memory required for key-value caches and the computational cost of generating each token.

It is important to note that throughput measurements were obtained using optimized inference frameworks. The researchers utilized the FasterTransformer codebase, which is specifically designed and optimized for LLM inference latency on GPU devices. FasterTransformer implements various optimizations including kernel fusion, memory-efficient attention computation, and optimized memory layouts that minimize memory transfer overhead. This ensures that the throughput comparison reflects real-world deployment conditions rather than theoretical or unoptimized scenarios.

For BitNet b1.58 specifically, additional optimizations were integrated. The 2-bit kernel from the Ladder system was incorporated to efficiently handle the ternary weight representation. This kernel is specifically designed to exploit the sparse, low-bit-width nature of 1.58-bit weights, enabling operations that would be inefficient if implemented using standard floating-point arithmetic routines. The integration of specialized kernels demonstrates that quantization benefits extend beyond simply reducing memory—they fundamentally change the computational primitives that can be employed.

# Batch Size Scaling: 11x Larger Batch Sizes

One of the most striking results from the throughput experiments is that BitNet b1.58 70B can support batch sizes up to 11 times larger than the equivalent LLaMA LLM. This dramatic improvement in batch size capacity directly stems from the reduced memory footprint of the 1.58-bit weight representation.

To understand why batch size scales so dramatically, we must consider what occupies memory during inference. The primary memory consumers are: the model parameters themselves, the key-value caches that store intermediate attention states for generating tokens, and the activations that flow through the network during computation. For a standard FP16 model, each parameter requires 16 bits of storage. For a 70B parameter model, this translates to approximately 140GB of memory just for the weights—far exceeding the 160GB available on two A100 cards. This constraint forces aggressive partitioning of the model and leaves limited memory for batch processing.

In contrast, BitNet b1.58 represents each weight using approximately 1.58 bits on average, a reduction of roughly 10x compared to FP16. For a 70B parameter model, this means the weights require only about 14GB of storage, a fraction of the available memory. This dramatic reduction frees up memory for storing larger batches of activations and key-value caches.

The relationship between batch size and memory is not linear. Each additional sample in a batch requires memory for its own key-value cache entries and activations. With sequence length 512, each sample's key-value cache stores attention keys and values for all 512 tokens across all layers. The memory savings from 1.58-bit weights thus compounds when multiplied by larger batch sizes.

The practical implication of 11x larger batch sizes is profound. In a serving scenario, this means that a single inference deployment can handle 11 times more concurrent requests, or alternatively, that the same request volume can be handled with 11 times fewer hardware resources. This translates directly into cost savings for deployment and improved user experience through reduced queueing times.

# 8.9x Throughput Improvement on 70B Models

The throughput improvement of 8.9 times for BitNet b1.58 compared to LLaMA LLM on 70B parameter models represents a transformational improvement in inference efficiency. Throughput, measured as the number of tokens generated per unit time, captures the overall efficiency of the inference system when operating at maximum batch capacity.

The 8.9x improvement emerges from the combination of two factors: the ability to process larger batches and the reduced computational cost per operation. While batch size increases by 11x, throughput increases by 8.9x, indicating that some overhead prevents perfect linear scaling. This is expected and reflects the realities of distributed inference systems.

Pipeline parallelism introduces communication overhead between devices. When different layers of the model reside on different GPUs, intermediate activations must be transferred between devices. For the LLaMA LLM baseline, these activations are in FP16, requiring significant bandwidth. Even with efficient interconnects like NVLink, communication costs become a meaningful fraction of total inference time, particularly as batch sizes increase.

Additionally, the memory bandwidth between DRAM and on-chip SRAM becomes a bottleneck at high batch sizes. Transferring model parameters from DRAM to the accelerator's local memory is expensive, and this cost grows with batch size as more parameters must be accessed for each forward pass. BitNet b1.58's smaller memory footprint reduces these bandwidth requirements proportionally.

The throughput improvement demonstrates that BitNet b1.58 is a Pareto improvement over the state-of-the-art LLM models—it achieves better performance while using fewer resources. This is fundamentally different from traditional efficiency-accuracy trade-offs where improving one metric degrades the other. BitNet b1.58 breaks this trade-off by matching full-precision model quality while dramatically improving system-level metrics.

# GPU Memory Limits and Sequence Length Trade-offs

The interplay between GPU memory constraints and sequence length represents one of the most significant challenges in LLM deployment. As the paper discusses, the ability to handle long sequences has become a critical demand in the era of LLMs, yet memory consumption from key-value caches scales directly with sequence length, creating a fundamental tension.

During inference, the key-value cache stores attention keys and values for all previously generated tokens. For a model with $L$ layers, $h$ attention heads, and head dimension $d_h$, processing a sequence of length $n$ requires storing approximately $2 \times L \times h \times d_h \times n$ values. In FP16, each value requires 2 bytes, meaning the memory consumption grows linearly with sequence length. For long sequences, the KV cache can consume more memory than the model parameters themselves.

BitNet b1.58 addresses this challenge through two mechanisms. First, by reducing the weight memory footprint by approximately 10x, more memory is available for KV caches, enabling longer sequences within the same hardware constraints. Second, BitNet b1.58 uses 8-bit activations rather than 16-bit, effectively halving the memory required for intermediate activations. As noted in the paper, this reduction "allows the context length to be doubled given the same resources."

The paper further suggests that activations "can be further losslessly compressed to 4 bits or even lower for 1.58-bit LLMs," though this is left as future work. This indicates that the memory efficiency gains are not yet exhausted—additional compression could enable even longer sequences or larger batch sizes.

The relationship between memory consumption and model size follows an interesting pattern. The paper notes that "the embedding remains full precision and its memory proportion is smaller for larger models." This means that as model size increases, the relative memory savings from 1.58-bit quantization become more pronounced. For smaller models, the full-precision embeddings represent a larger fraction of total memory, but for larger models, the linear layers dominate, and their 1.58-bit representation yields greater proportional savings.

# Pipeline Parallelism and Distributed Inference

Deploying models larger than can fit on a single accelerator requires distributed inference strategies. The research employed pipeline parallelism to run the 70B parameter models on two 80GB A100 cards, demonstrating how BitNet b1.58 interacts with distributed inference paradigms.

Pipeline parallelism partitions the model layers across multiple devices. During inference, each device processes its assigned layers and sends intermediate activations to the next device in the pipeline. While this approach enables running models that exceed single-device memory, it introduces communication overhead and potential pipeline bubbles where devices sit idle waiting for inputs.

BitNet b1.58's reduced memory footprint has significant implications for pipeline parallelism. Most directly, smaller models may fit entirely on a single device, eliminating the need for distributed inference altogether. The paper notes that for Mixture-of-Experts models, "there would be no overhead if the entire models could be placed on a single chip."

For cases where distributed inference remains necessary, the reduced activation sizes from 8-bit quantization decrease the communication bandwidth required between devices. When activations must traverse inter-device interconnects, halving their size through 8-bit quantization effectively doubles the available bandwidth for the same physical interconnect.

The discussion of Mixture-of-Experts architectures highlights additional benefits of 1.58-bit quantization for distributed systems. MoE models face particular deployment challenges because "the high memory consumption and inter-chip communication overhead limit its deployment and application." MoE models store multiple expert networks, and routing decisions determine which experts process each token. This architecture requires either storing all experts in memory or implementing complex expert swapping mechanisms. BitNet b1.58's reduced memory footprint "reduces the number of devices required to deploy MoE models" and "significantly reduces the overhead of transferring activations across networks."

These characteristics make BitNet b1.58 particularly well-suited for the emerging paradigms of distributed LLM inference, where memory constraints and communication costs often dominate system design considerations.

# The 2-bit Kernel Optimization

The efficiency gains of BitNet b1.58 are not automatic consequences of weight quantization alone—they require specialized software implementations that exploit the unique computational properties of ternary weights. The 2-bit kernel from Ladder represents a critical optimization that enables efficient execution on current hardware.

Traditional deep learning frameworks are optimized for floating-point operations, which assume continuous-valued weights and activations. The matrix multiplication operations in standard frameworks use highly tuned libraries like cuBLAS or Tensor Core units that perform FP16 or BF16 arithmetic at peak hardware efficiency. However, these implementations cannot directly benefit from ternary weights—if a ternary weight matrix is simply cast to floating-point and processed normally, all computational benefits are lost.

The 2-bit kernel addresses this by implementing specialized arithmetic that exploits the ternary structure. When weights can only take values in $\{-1, 0, 1\}$, the matrix multiplication operation simplifies dramatically. Multiplication by $-1$ is negation, multiplication by $0$ eliminates the term entirely, and multiplication by $+1$ is the identity. This means the expensive floating-point multiplications in standard matrix multiplication can be replaced with conditional additions or subtractions.

The paper notes that "the majority of BitNet b1.58 is INT8 addition calculation," contrasting with LLaMA LLM which "consists of both FP16 addition and FP16 multiplication." This shift from multiplication to addition has profound implications for energy consumption and computational density. On 7nm chips, the paper estimates that "BitNet b1.58 saves 71.4 times arithmetic operations energy consumption for matrix multiplication."

The kernel integration with FasterTransformer is notable because it demonstrates practical deployment feasibility. FasterTransformer is widely used in production LLM systems, and the ability to integrate 2-bit kernels into this framework means that BitNet b1.58 can leverage existing inference infrastructure without requiring wholesale system redesign.

Importantly, the paper acknowledges that "there is still room for optimization to further reduce the cost." The current 2-bit kernel represents early work in optimized implementations for 1.58-bit LLMs. As the paper suggests in its discussion of future hardware, purpose-built accelerators for 1-bit LLMs could extract even greater efficiency from the ternary weight representation.

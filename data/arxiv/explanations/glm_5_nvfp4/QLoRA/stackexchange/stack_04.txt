\title{Stack Exchange of the Paper: "QLoRA: Efficient Finetuning of Quantized LLMs"}

### Why must LoRA adapters be added to every layer in QLoRA?
Question:
The QLoRA paper makes a strong claim that I don't fully understand: "the most critical LoRA hyperparameter is how many LoRA adapters are used in total and that LoRA on all linear transformer block layers are required to match full finetuning performance."

The original LoRA paper (Hu et al., 2021) typically only applies adapters to the query and value projection matrices in attention layers, which seems to work well. But QLoRA shows that this doesn't match full finetuning performance for larger models.

Why does adding adapters to every linear layer (not just attention projections) become necessary when using a 4-bit quantized base model? Is this related to the quantization noise somehow, or would this finding apply to regular LoRA as well? The paper mentions this is "crucial for recovering full 16-bit precision performance" but doesn't fully explain the mechanism.
Answer:
The key finding from the QLoRA paper is that **this is not specific to quantization at all**—it's a general finding about LoRA that applies equally to both quantized and non-quantized models when the goal is to fully match full finetuning performance.

The paper states clearly that "when using the standard practice of applying LoRA to query and value attention projection matrices, we are not able to replicate full finetuning performance for large base models." The original LoRA paper demonstrated that applying adapters to query and value projections works reasonably well, but QLoRA's more rigorous comparison to full finetuning baselines revealed this doesn't fully close the gap.

**Why isn't this a problem with the original LoRA paper?** The original LoRA work focused on showing the method works well compared to other parameter-efficient approaches, but didn't emphasize strict parity with full finetuning as the primary metric. QLoRA specifically tested whether 4-bit quantized finetuning could match 16-bit full finetuning, and this stricter benchmark exposed the limitation.

The paper provides an important insight about **memory economics** that explains why this wasn't explored earlier. Most of the memory footprint during finetuning comes from activation gradients, not the LoRA parameters themselves. For a 7B LLaMA model, LoRA weights occupy only 26 MB while input gradients take 567 MB (or 18 MB with gradient checkpointing). The 4-bit base model itself uses 5,048 MB. Since LoRA parameters are such a tiny fraction of total memory, "aggressively reducing the amount of LoRA parameter yields only minor memory benefits"—meaning there's essentially no cost to adding more adapters.

As for the mechanism, the paper doesn't provide a detailed theoretical explanation, but the intuition is straightforward: each linear layer in a transformer transforms representations in sequence. If you can only modify some of these transformations (e.g., only query and value projections), you're constraining the model's ability to adjust the computation flow. Adding adapters to all linear layers—including MLP projections (gate, up, and down projections) alongside attention—gives the model capacity to adjust representations at every stage of processing, which appears necessary to match what full finetuning can achieve.

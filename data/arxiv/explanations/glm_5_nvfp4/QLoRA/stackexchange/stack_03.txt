\title{Stack Exchange of the Paper: "QLoRA: Efficient Finetuning of Quantized LLMs"}

### Understanding the double quantization memory savings calculation
Question:
In the QLoRA paper, Double Quantization is described as quantizing the quantization constants themselves. The paper claims this reduces the memory footprint from 0.5 bits per parameter to 0.127 bits per parameter, for a savings of 0.373 bits per parameter.

The calculation given is:
- Without double quantization: $32/64 = 0.5$ bits per parameter
- With double quantization: $8/64 + 32/(64 \times 256) = 0.127$ bits per parameter

I understand the first part: with 32-bit quantization constants and blocksize 64, we have 32 bits shared across 64 parameters.

But I'm confused about the second calculation. Why is the second term $32/(64 \times 256)$? If we're using FP8 for the second quantization, shouldn't it just be $8/64$? Where does the extra $32/(64 \times 256)$ term come from, and why is it divided by the product of both blocksizes?
Answer:
The confusion stems from misunderstanding what each term in the equation represents. Let me walk through the double quantization process step by step.

**Single Quantization (baseline):**
When quantizing weights $\mathbf{W}$ with blocksize $64$, each block of $64$ weights shares one 32-bit quantization constant $c_2^{FP32}$. This costs $32/64 = 0.5$ bits per parameter.

**Double Quantization:**
The key insight is that double quantization introduces *two levels* of quantization constants, not one.

1. **First-level constants ($c_2^{FP8}$):** The original $c_2^{FP32}$ constants are quantized to 8-bit floats (FP8). Each block of $64$ weights still has one $c_2$ constant, but now it's $8$ bits instead of $32$. Cost: $8/64 = 0.125$ bits per parameter.

2. **Second-level constants ($c_1^{FP32}$):** This is the part you're missing. Quantizing $c_2^{FP32}$ to $c_2^{FP8}$ requires its *own* quantization constants! The paper uses a blocksize of $256$ for this second quantization, meaning $256$ of the $c_2$ constants share one 32-bit $c_1^{FP32}$ constant.

Now, how many original weight parameters does each $c_1$ cover? Each $c_1$ serves $256$ blocks of $c_2$ constants, and each $c_2$ block serves $64$ weight parameters. Therefore, each $c_1$ covers $256 \times 64 = 16,384$ weight parameters. The cost is $32/(256 \times 64) \approx 0.002$ bits per parameter.

**Total cost:**
$$\frac{8}{64} + \frac{32}{64 \times 256} = 0.125 + 0.00195 \approx 0.127 \text{ bits per parameter}$$

The $32/(64 \times 256)$ term appears because you cannot escape needing at least one FP32 constant somewhere in the quantization chain—you've just pushed it up one level, where it's amortized over many more parameters ($256 \times 64$ instead of just $64$).

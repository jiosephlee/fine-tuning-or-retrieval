# FlashAttention-3: Unleashing the True Power of H100 GPUs for LLMs

The Transformer architecture has become the backbone of modern large language models (LLMs), but its core component, the attention mechanism, remains a significant computational bottleneck. As models scale and context windows grow, the quadratic complexity of attention becomes a major hurdle. While previous iterations like FlashAttention and FlashAttention-2 made great strides in optimizing this, the arrival of new hardware like NVIDIA's H100 GPUs revealed that existing software was leaving a lot of performance on the table.

FlashAttention-2, for instance, achieved only about 35% utilization on the H100 GPU—a significant gap compared to the 80-90% utilization typical of optimized matrix multiplication kernels. FlashAttention-3 bridges this gap, delivering speedups of 1.5-2.0$\times$ over its predecessor and pushing utilization up to 75%. This post dives into how FlashAttention-3 unlocks the true potential of modern hardware through asynchronous execution and low-precision computing.

## The Hardware Gap

To understand the breakthrough, we first need to understand the hardware. Modern GPUs like the Hopper H100 are designed with specialized hardware units that can operate independently. Two key features stand out:

1.  **Tensor Memory Accelerator (TMA):** A dedicated unit for asynchronous memory copying between global memory (HBM) and shared memory.
2.  **Asynchronous Tensor Cores:** Hardware units specifically for matrix multiplication that can run independently of other CUDA cores performing logic or floating-point operations.

FlashAttention-2 was designed with a more synchronous execution model. It didn't fully utilize the fact that on H100s, you can load data and compute matrix multiplications simultaneously. This mismatch led to the low utilization rates, where the expensive Tensor Cores were often sitting idle waiting for data or other operations to finish.

## Asynchrony and Overlap

FlashAttention-3 rewrites the algorithm to take full advantage of these asynchronous capabilities. It employs three main techniques to hide latency and keep the hardware busy.

### 1. Producer-Consumer Asynchrony (Warp-Specialization)

FlashAttention-3 divides the threads (warps) on a GPU into distinct roles: producers and consumers. The producer warps are responsible solely for loading data from global memory to shared memory using the TMA. The consumer warps perform the actual computation using Tensor Cores. By splitting these tasks, the algorithm creates a software pipeline where data loading and computation happen concurrently, effectively hiding memory latency.

### 2. Hiding Softmax under GEMM

In the attention calculation, specifically the softmax operation, non-matrix-multiplication operations (like floating-point multiply-add and exponential functions) have significantly lower throughput than matrix multiplications (GEMM). On the H100, exponential operations are handled by a different hardware unit (the multi-function unit) than the Tensor Cores.

FlashAttention-3 exploits this by interleaving block-wise matrix multiplications and softmax operations. While one block is undergoing softmax calculations on the multi-function units, the Tensor Cores are busy computing the matrix multiplication for the next block. This "pingpong" scheduling ensures that both hardware units are working at the same time, rather than waiting for one to finish before the other starts.

## Mastering Low-Precision with FP8

The H100 offers double the throughput for FP8 precision compared to FP16 or BF16. However, using FP8 for attention is tricky due to numerical instability and the presence of outlier features in LLMs, which can cause significant quantization errors. FlashAttention-3 adapts the algorithm to leverage FP8 Tensor Cores while maintaining accuracy through two specific methods:

*   **Block Quantization:** Instead of scaling the entire tensor with a single scalar, FlashAttention-3 quantizes blocks of the $\mathbf{Q}$, $\mathbf{K}$, and $\mathbf{V}$ matrices separately. This reduces error without adding computational overhead.
*   **Incoherent Processing:** To handle outliers, the method multiplies queries ($\mathbf{Q}$) and keys ($\mathbf{K}$) by a random orthogonal matrix before quantization. This effectively "spreads out" the outlier values, smoothing the distribution and reducing quantization error.

These adjustments allow FlashAttention-3 to use FP8 effectively, achieving nearly 1.2 PFLOPs/s while maintaining 2.6$\times$ lower numerical error compared to standard FP8 attention baselines.

## Performance Impact

The results of these optimizations are substantial. On an H100 SXM5 GPU, FlashAttention-3 demonstrates:

*   **FP16 Performance:** Speedups of 1.5-2.0$\times$ over FlashAttention-2 in the forward pass, reaching up to 740 TFLOPs/s (75% theoretical utilization).
*   **FP8 Performance:** Throughput approaching 1.2 PFLOPs/s.
*   **Backward Pass:** Speedups of 1.5-1.75$\times$ compared to the previous version.

For developers and researchers, this translates to faster training times and inference speeds. More importantly, it enables the efficient use of longer context windows, unlocking new capabilities in processing long documents, analyzing large codebases, and handling high-resolution images or video data.

## Conclusion

FlashAttention-3 is a prime example of how co-designing algorithms with hardware architecture leads to significant performance gains. By embracing the asynchronous execution model and low-precision capabilities of the Hopper architecture, FlashAttention-3 transforms the attention mechanism from a persistent bottleneck into a highly optimized pipeline. This work not only accelerates current LLM workloads but also paves the way for the next generation of long-context applications.

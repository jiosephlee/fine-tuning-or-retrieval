# FlashAttention-3: Unleashing the True Power of H100 GPUs for LLMs

The Transformer architecture has become the backbone of modern large language models (LLMs), but its core component, the attention mechanism, remains a significant computational bottleneck. As models scale and context windows grow, the quadratic complexity of attention becomes a major hurdle. While previous iterations like FlashAttention and FlashAttention-2 made great strides in optimizing this, the arrival of new hardware like NVIDIA's H100 GPUs revealed that existing software was leaving a lot of performance on the table.

FlashAttention-2, for instance, achieved only about 35% utilization on the H100 GPU—a significant gap compared to the 80-90% utilization typical of optimized matrix multiplication kernels. FlashAttention-3 bridges this gap, delivering speedups of 1.5-2.0$\times$ over its predecessor and pushing utilization up to 75%. This post dives into how FlashAttention-3 unlocks the true potential of modern hardware through asynchronous execution and low-precision computing.

## The Hardware Gap

To understand the breakthrough, we first need to understand the hardware. Modern GPUs like the Hopper H100 are designed with specialized hardware units that can operate independently. Two key features stand out:

1.  **Tensor Memory Accelerator (TMA):** A dedicated unit for asynchronous memory copying between global memory (HBM) and shared memory.
2.  **Asynchronous Tensor Cores:** Hardware units specifically for matrix multiplication that can run independently of other CUDA cores performing logic or floating-point operations.

FlashAttention-2 was designed with a more synchronous execution model. It didn't fully utilize the fact that on H100s, you can load data and compute matrix multiplications simultaneously. This mismatch led to the low utilization rates, where the expensive Tensor Cores were often sitting idle waiting for data or other operations to finish.

## Asynchrony and Overlap

FlashAttention-3 rewrites the algorithm to take full advantage of these asynchronous capabilities. It employs three main techniques to hide latency and keep the hardware busy.

### 1. Producer-Consumer Asynchrony (Warp-Specialization)

FlashAttention-3 divides the threads (warps) on a GPU into distinct roles: producers and consumers. The producer warps are responsible solely for loading data from global memory to shared memory using the TMA. The consumer warps perform the actual computation using Tensor Cores. By splitting these tasks, the algorithm creates a software pipeline where data loading and computation happen concurrently, effectively hiding memory latency.

### 2. Hiding Softmax under GEMM

In the attention calculation, specifically the softmax operation, non-matrix-multiplication operations (like floating-point multiply-add and exponential functions) have significantly lower throughput than matrix multiplications (GEMM). On the H100, exponential operations are handled by a different hardware unit (the multi-function unit) than the Tensor Cores.

FlashAttention-3 exploits this by interleaving block-wise matrix multiplications and softmax operations. While one block is undergoing softmax calculations on the multi-function units, the Tensor Cores are busy computing the matrix multiplication for the next block. This "pingpong" scheduling ensures that both hardware units are working at the same time, rather than waiting for one to finish before the other starts.

## Mastering Low-Precision with FP8

The H100 offers double the throughput for FP8 precision compared to FP16 or BF16. However, using FP8 for attention is tricky due to numerical instability and the presence of outlier features in LLMs, which can cause significant quantization errors. FlashAttention-3 adapts the algorithm to leverage FP8 Tensor Cores while maintaining accuracy through two specific methods:

*   **Block Quantization:** Instead of scaling the entire tensor with a single scalar, FlashAttention-3 quantizes blocks of the $\mathbf{Q}$, $\mathbf{K}$, and $\mathbf{V}$ matrices separately. This reduces error without adding computational overhead.
*   **Incoherent Processing:** To handle outliers, the method multiplies queries ($\mathbf{Q}$) and keys ($\mathbf{K}$) by a random orthogonal matrix before quantization. This effectively "spreads out" the outlier values, smoothing the distribution and reducing quantization error.

These adjustments allow FlashAttention-3 to use FP8 effectively, achieving nearly 1.2 PFLOPs/s while maintaining 2.6$\times$ lower numerical error compared to standard FP8 attention baselines.

## Performance Impact

The results of these optimizations are substantial. On an H100 SXM5 GPU, FlashAttention-3 demonstrates:

*   **FP16 Performance:** Speedups of 1.5-2.0$\times$ over FlashAttention-2 in the forward pass, reaching up to 740 TFLOPs/s (75% theoretical utilization).
*   **FP8 Performance:** Throughput approaching 1.2 PFLOPs/s.
*   **Backward Pass:** Speedups of 1.5-1.75$\times$ compared to the previous version.

For developers and researchers, this translates to faster training times and inference speeds. More importantly, it enables the efficient use of longer context windows, unlocking new capabilities in processing long documents, analyzing large codebases, and handling high-resolution images or video data.

## Conclusion

FlashAttention-3 is a prime example of how co-designing algorithms with hardware architecture leads to significant performance gains. By embracing the asynchronous execution model and low-precision capabilities of the Hopper architecture, FlashAttention-3 transforms the attention mechanism from a persistent bottleneck into a highly optimized pipeline. This work not only accelerates current LLM workloads but also paves the way for the next generation of long-context applications.



# The Art of GPU Multitasking: Understanding Asynchrony and 'Pingpong' Scheduling

Attention mechanisms are the computational bottleneck of modern Large Language Models (LLMs). While previous versions of FlashAttention significantly optimized memory access, they left a surprising amount of performance on the table. On NVIDIA's H100 GPUs (Hopper architecture), FlashAttention-2 achieved only about 35% utilization. The new FlashAttention-3 algorithm closes this gap, reaching up to 75% utilization by fundamentally changing how the GPU organizes its work.

This post dives into the specific hardware optimization techniques—warp-specialization and "pingpong" scheduling—that allow FlashAttention-3 to keep the GPU's heavy hitters, the Tensor Cores, constantly busy.

## The Problem: A Synchronous Mindset on Asynchronous Hardware

Why was FlashAttention-2 inefficient on new hardware? The answer lies in how the GPU executes instructions.

Previous algorithms treated the GPU somewhat synchronously. They would load data, wait for the load to finish, compute, and then repeat. This is inefficient because modern GPUs like the H100 have distinct hardware units that can operate independently:
*   **Tensor Memory Accelerator (TMA):** A dedicated engine for moving data between global memory (HBM) and shared memory.
*   **Tensor Cores:** Specialized units for matrix multiplication (GEMM).
*   **CUDA Cores:** Handle other logic, like floating-point operations and exponentials (used in softmax).

If you wait for data to load before starting computation, the Tensor Cores sit idle. Conversely, if you only compute without loading the next batch of data ahead of time, you create bubbles of inactivity. FlashAttention-3 solves this by embracing asynchrony.

## Warp-Specialization: The Assembly Line

The first major technique in FlashAttention-3 is **warp-specialization**. To understand this, imagine a restaurant kitchen.

In a traditional (non-specialized) kitchen, every chef tries to do everything. One minute they are fetching ingredients from the pantry, the next they are cooking on the stove, and then they are plating the dish. This constant context-switching is inefficient. The stove (the Tensor Core) often sits cold while the chef runs to the pantry.

FlashAttention-3 implements warp-specialization, which is like splitting the staff into distinct roles:
*   **Producers (The Prep Cook):** These "warps" (groups of threads) are dedicated solely to fetching data. They use the asynchronous TMA to load tiles of $\mathbf{Q}$, $\mathbf{K}$, and $\mathbf{V}$ matrices from global memory to shared memory.
*   **Consumers (The Line Cook):** These warps are dedicated solely to computation. They wait for ingredients to hit the prep table (shared memory) and immediately start cooking using the Tensor Cores.

This split allows for a continuous pipeline. The producers are always running ahead, fetching the next batch of data while the consumers are busy computing the current batch. By separating these responsibilities, FlashAttention-3 ensures the high-throughput Tensor Cores never have to wait for the slower memory loads.

## Pingpong Scheduling: Hiding the Softmax

Even with warp-specialization, a problem remains. The attention calculation involves two main types of math:
1.  **Matrix Multiplication (GEMM):** Calculating $\mathbf{S} = \mathbf{Q}\mathbf{K}^\top$ and $\mathbf{O} = \mathbf{P}\mathbf{V}$. This is incredibly fast on Tensor Cores.
2.  **Softmax:** Calculating exponentials and row-wise reductions. This happens on the CUDA cores (multi-function units), which are much slower in comparison.

If the algorithm computes a matrix multiply and then immediately switches to softmax, the powerful Tensor Cores sit idle while the CUDA cores churn through the slow exponential calculations.

FlashAttention-3 introduces **pingpong scheduling** to solve this. Think of this as a relay race between two consumer warpgroups.
*   **Warpgroup 1** performs its matrix multiplications.
*   While Warpgroup 1 moves to the slower softmax phase, **Warpgroup 2** steps in and starts its matrix multiplications.
*   The roles swap (pingpong) so that while Warpgroup 2 does its softmax, Warpgroup 1 picks up the next matrix multiplication.

This interleaving ensures that the Tensor Cores are almost always active, effectively "hiding" the slower softmax computation behind the heavy-duty matrix math.

## Intra-Warpgroup Overlapping: The 2-Stage Pipeline

Beyond the pingpong method between warpgroups, FlashAttention-3 employs a finer-grained overlap within a single warpgroup.

In the standard flow, you calculate $\mathbf{Q}\mathbf{K}^\top$, then do softmax, then multiply by $\mathbf{V}$. These have sequential dependencies—you can't softmax the scores before you calculate them. However, FlashAttention-3 breaks this strict serialization by pipelining across loop iterations.

By using additional buffers in registers, the algorithm can start computing the matrix multiplication for the next block of keys ($\mathbf{K}_{j+1}$) while it is still finishing the softmax for the current block. This two-stage pipeline requires careful management of register pressure, as storing intermediate results like $\mathbf{S}_{\text{next}}$ consumes valuable register space, but the trade-off results in significantly higher throughput.

## The Results

By turning the GPU into a highly coordinated, asynchronous pipeline, FlashAttention-3 achieves impressive benchmarks on H100 GPUs:
*   **Speedup:** It is 1.5-2.0$\times$ faster than FlashAttention-2 in FP16.
*   **Utilization:** It reaches up to 740 TFLOPs/s (75% of theoretical maximum) with FP16, compared to just 35% previously.
*   **Low-Precision:** With FP8, it reaches close to 1.2 PFLOPs/s.

These techniques demonstrate that as hardware evolves, simply throwing more compute at the problem isn't enough. Unlocking the full potential of LLMs requires a deep understanding of the hardware execution model, treating the GPU not as a single processor, but as a symphony of specialized, asynchronous units.



# Accuracy Meets Efficiency: Mastering FP8 with FlashAttention-3

The pursuit of faster AI models has increasingly led researchers toward lower-precision computing. As model sizes grow and training costs soar, the appeal of FP8—using just 8 bits per number instead of 16 or 32—is undeniable. The Hopper GPU architecture, for instance, can deliver double the throughput for FP8 operations compared to FP16 or BF16. But there's a catch: shrinking numerical precision introduces quantization errors that can degrade model quality. FlashAttention-3 tackles this challenge head-on, achieving near-1.2 PFLOPs/s while maintaining numerical accuracy through two clever techniques.

## The FP8 Challenge: When Precision Meets Performance

The FP8 format, specifically the e4m3 variant, allocates only 3 bits for the mantissa and 4 bits for the exponent. This compact representation is great for throughput but comes with significant accuracy trade-offs. The problem becomes even more acute when dealing with large language models, which tend to have "outlier" values—activations that are much larger in magnitude than most others. These outliers make quantization notoriously difficult because a single scaling factor for an entire tensor must accommodate values spanning vastly different ranges.

The traditional approach uses per-tensor scaling, where one scalar value handles the quantization for an entire tensor. However, this one-size-fits-all strategy struggles when outliers are present, leading to larger numerical errors that accumulate throughout the model.

## Block Quantization: Going Local for Better Accuracy

FlashAttention-3's first technique is deceptively simple yet effective: instead of quantizing entire tensors with a single scale, it breaks them into smaller blocks and quantizes each block independently. For the query ($\mathbf{Q}$), key ($\mathbf{K}$), and value ($\mathbf{V}$) matrices, the algorithm splits each tensor into blocks of size $B_r \times d$ or $B_c \times d$, maintaining a separate scaling factor for each.

This local approach offers several advantages. First, outliers only affect their specific block rather than contaminating the quantization of the entire tensor. Second, since FlashAttention-3 naturally processes attention in blocks anyway—as part of its core tiling strategy—the block quantization adds essentially no computational overhead. The scaling for each block of the attention scores matrix $\mathbf{S}$ can be adjusted on the fly.

Practically, this quantization can be fused with preceding operations like rotary position embedding, which are memory-bandwidth bound, meaning there's no additional slowdown.

## Incoherent Processing: Spreading Out the Outliers

The second technique, called incoherent processing, takes a more mathematical approach to the outlier problem. The core insight is that if you multiply both $\mathbf{Q}$ and $\mathbf{K}$ by the same random orthogonal matrix $\mathbf{M}$, the attention output remains unchanged because:

$$(\mathbf{Q}\mathbf{M})(\mathbf{K}\mathbf{M})^\top = \mathbf{Q}\mathbf{M}\mathbf{M}^\top\mathbf{K}^\top = \mathbf{Q}\mathbf{K}^\top$$

This works because $\mathbf{M}\mathbf{M}^\top = \mathbf{I}$ for an orthogonal matrix. The benefit comes from how this transformation affects the values: each entry of $\mathbf{Q}\mathbf{M}$ or $\mathbf{K}\mathbf{M}$ becomes a random sum of the original entries, effectively "spreading out" the outliers across multiple values. Instead of having a few extremely large values that break quantization, you end up with a more uniform distribution that's easier to represent in FP8.

In practice, the authors use a clever construction where $\mathbf{M}$ is the product of random diagonal matrices with entries of $\pm 1$ and a Hadamard matrix. This allows the multiplication to be performed in $O(d \log d)$ time instead of $O(d^2)$, and crucially, this operation can also be fused with rotary embedding at no extra computational cost.

## The Results: Speed Without Sacrifice

The combination of these techniques delivers impressive empirical results. FP8 FlashAttention-3 achieves 2.6$\times$ lower numerical error compared to a standard FP8 attention implementation using per-tensor quantization. This is measured using root mean squared error (RMSE) against a reference FP64 implementation, with test data designed to simulate the outlier patterns found in real LLMs.

On the performance front, FP8 FlashAttention-3 reaches close to 1.2 PFLOPs/s on H100 GPUs—nearly double the throughput of the FP16 version, which itself achieves up to 740 TFLOPs/s (75% utilization). For context, FlashAttention-2 was only achieving around 35% utilization on H100 GPUs, meaning FlashAttention-3 has more than doubled the efficiency.

The FP16 version of FlashAttention-3 also matches the numerical accuracy of FlashAttention-2, and both are 1.7$\times$ more accurate than a standard attention implementation because intermediate softmax results are kept in FP32 precision.

## Looking Forward

The techniques in FlashAttention-3 demonstrate that moving to lower precision doesn't have to mean sacrificing model quality. By working with the natural structure of the attention computation—operating on blocks—and using mathematical transformations to redistribute problematic values, we can have our cake and eat it too: the speed of FP8 with accuracy that rivals higher-precision approaches.

As hardware continues to evolve, with support for even lower precisions like FP4 in upcoming architectures, these kinds of algorithmic innovations will become increasingly important. FlashAttention-3 is available open-source and is being integrated into PyTorch and Hugging Face libraries, making these optimizations accessible to the broader AI community.

## Query, Key, and Value Matrices: Dimensions and Meanings

The attention mechanism is fundamentally built upon three input matrices that serve distinct computational roles. Let us denote these matrices as $\mathbf{Q}$, $\mathbf{K}$, and $\mathbf{V}$, corresponding to the query, key, and value matrices, respectively. For a single attention head, each of these matrices has dimensions $\mathbb{R}^{N \times d}$, where $N$ represents the sequence length and $d$ represents the head dimension. The sequence length $N$ determines how many tokens or positions are being processed, while the head dimension $d$ controls the richness of the representation at each position.

The nomenclature of these matrices derives from an analogy to information retrieval systems. The query matrix $\mathbf{Q}$ encodes what each position is "looking for" or attending to. Each row of $\mathbf{Q}$ represents a query vector that seeks relevant information from other positions in the sequence. The key matrix $\mathbf{K}$ encodes what each position "offers" or can be matched against. When a query interacts with keys through matrix multiplication, we obtain attention scores that indicate the relevance of each position to each query. Finally, the value matrix $\mathbf{V}$ contains the actual information that will be aggregated based on the attention weights. This separation of keys and values allows the mechanism to retrieve information based on relevance scores computed from queries and keys, while returning content stored in the values.

In the context of multi-head attention (MHA), each head maintains its own set of query, key, and value projections. This means that for a model with $H$ heads, we have $H$ separate triples of matrices $\mathbf{Q}^{(h)}, \mathbf{K}^{(h)}, \mathbf{V}^{(h)}$ for $h = 1, 2, \ldots, H$. Each head can therefore learn to attend to different types of relationships within the input sequence. The outputs from all heads are typically concatenated and projected back to the model dimension through a final linear transformation.

## Forward Pass Computation: $\mathbf{S} = \mathbf{Q}\mathbf{K}^\top$, $\mathbf{P} = \mathrm{softmax}(\mathbf{S})$, $\mathbf{O} = \mathbf{P}\mathbf{V}$

The forward pass of attention involves three sequential matrix operations that transform the input matrices into the output. The computation proceeds as follows:

$$\mathbf{S} = \alpha \mathbf{Q} \mathbf{K}^\top \in \mathbb{R}^{N \times N}, \quad \mathbf{P} = \mathrm{softmax}(\mathbf{S}) \in \mathbb{R}^{N \times N}, \quad \mathbf{O} = \mathbf{P}\mathbf{V} \in \mathbb{R}^{N \times d},$$

where $\mathrm{softmax}$ is applied row-wise and the scaling factor $\alpha$ is typically set to $1/\sqrt{d}$.

The first operation computes the score matrix $\mathbf{S}$ by multiplying the query matrix with the transpose of the key matrix. This yields an $N \times N$ matrix where entry $\mathbf{S}_{ij}$ represents the raw attention score between position $i$ (as a query) and position $j$ (as a key). The scaling factor $\alpha = 1/\sqrt{d}$ is crucial for maintaining stable gradients during training. Without this scaling, the dot products in $\mathbf{S}$ would grow large for larger head dimensions, pushing the softmax into regions of extremely small gradients.

The second operation applies the softmax function row-wise to the score matrix, producing the attention weight matrix $\mathbf{P}$. For each row $i$, the softmax function transforms the raw scores into a probability distribution:

$$\mathbf{P}_{ij} = \frac{\exp(\mathbf{S}_{ij})}{\sum_{k=1}^{N} \exp(\mathbf{S}_{ik})}.$$

This ensures that for each query position $i$, the attention weights across all key positions sum to one. The softmax operation thus converts raw similarity scores into proper attention weights that can be interpreted as the degree to which position $i$ attends to position $j$.

The third and final operation computes the output matrix $\mathbf{O}$ by multiplying the attention weight matrix $\mathbf{P}$ with the value matrix $\mathbf{V}$. Each output vector $\mathbf{O}_i$ (the $i$-th row of $\mathbf{O}$) is thus a weighted combination of all value vectors, where the weights are determined by the attention mechanism:

$$\mathbf{O}_i = \sum_{j=1}^{N} \mathbf{P}_{ij} \mathbf{V}_j.$$

This weighted sum allows each position to aggregate information from all other positions in the sequence, with the attention weights controlling how much each source position contributes.

## Numerical Stability: Subtracting Rowmax for Stable Exponentiation

A critical practical concern when implementing the softmax function is numerical stability. The exponential function $\exp(x)$ grows extremely rapidly for positive arguments and underflows to zero for large negative arguments. When computing $\exp(\mathbf{S}_{ij})$ for large values of $\mathbf{S}_{ij}$, we risk overflow, resulting in numerical instability. Conversely, when all values in a row are large negative numbers, the exponentials may underflow to zero.

The standard solution to this problem is to subtract the maximum value in each row before computing the exponentials. In practice, we compute:

$$\mathbf{S}'_i = \mathbf{S}_i - \max_j(\mathbf{S}_{ij})$$

for each row $i$, and then apply softmax to the adjusted scores:

$$\mathbf{P}_{ij} = \frac{\exp(\mathbf{S}'_{ij})}{\sum_{k=1}^{N} \exp(\mathbf{S}'_{ik})}.$$

This transformation is mathematically equivalent to the original softmax because subtracting a constant from all values in a row does not change the softmax output. To see this, observe that for any constant $c$:

$$\frac{\exp(\mathbf{S}_{ij} - c)}{\sum_{k} \exp(\mathbf{S}_{ik} - c)} = \frac{\exp(\mathbf{S}_{ij}) \cdot \exp(-c)}{\sum_{k} \exp(\mathbf{S}_{ik}) \cdot \exp(-c)} = \frac{\exp(\mathbf{S}_{ij})}{\sum_{k} \exp(\mathbf{S}_{ik})}.$$

By choosing $c = \max_j(\mathbf{S}_{ij})$ for each row, we ensure that the largest value in each row becomes zero, and all other values are negative or zero. This guarantees that all exponentials lie in the range $(0, 1]$, avoiding overflow entirely. The numerical stability is maintained because we are now computing exponentials of values that are bounded from above.

This technique is essential for practical implementations of attention, as the raw scores in $\mathbf{S}$ can vary widely depending on the values in $\mathbf{Q}$ and $\mathbf{K}$. Without this adjustment, training deep transformer models would frequently encounter numerical instabilities that could halt training or produce incorrect gradients.

## Backward Pass Gradients: $\mathbf{dV}$, $\mathbf{dP}$, $\mathbf{dS}$, $\mathbf{dQ}$, $\mathbf{dK}$ Derivations

During backpropagation, we must compute gradients of a scalar loss function $\phi$ with respect to each of the input matrices. Let us denote $\mathbf{d}(-) = \partial \phi / \partial (-)$ as the gradient with respect to a given tensor. Given the output gradient $\mathbf{dO} \in \mathbb{R}^{N \times d}$ that flows into the attention layer from subsequent layers, we compute the gradients through the chain rule.

The gradient with respect to the value matrix $\mathbf{V}$ follows from the equation $\mathbf{O} = \mathbf{P}\mathbf{V}$. Since this is a matrix multiplication, we have:

$$\mathbf{dV} = \mathbf{P}^\top \mathbf{dO} \in \mathbb{R}^{N \times d}.$$

This gradient captures how changes in each value vector affect the loss through its contribution to the weighted sum.

The gradient with respect to the attention weight matrix $\mathbf{P}$ comes from the same matrix multiplication:

$$\mathbf{dP} = \mathbf{dO} \mathbf{V}^\top \in \mathbb{R}^{N \times N}.$$

This gradient indicates how changes in the attention weights affect the output.

The gradient with respect to the score matrix $\mathbf{S}$ requires differentiating through the softmax function:

$$\mathbf{dS} = \mathrm{dsoftmax}(\mathbf{dP}) \in \mathbb{R}^{N \times N}.$$

The detailed form of $\mathrm{dsoftmax}$ is discussed in the next section.

Finally, the gradients with respect to the query and key matrices follow from the score computation $\mathbf{S} = \alpha \mathbf{Q} \mathbf{K}^\top$:

$$\mathbf{dQ} = \alpha \mathbf{dS} \mathbf{K} \in \mathbb{R}^{N \times d},$$
$$\mathbf{dK} = \alpha \mathbf{dS}^\top \mathbf{Q} \in \mathbb{R}^{N \times d}.$$

Note the transposition in $\mathbf{dK}$: since $\mathbf{K}$ appears transposed in the forward computation, its gradient involves $\mathbf{dS}^\top$. The scaling factor $\alpha$ propagates through unchanged.

These gradient computations reveal the computational structure of the backward pass: it involves five matrix multiplications (compared to two in the forward pass), making the backward pass approximately $2.5$ times as many floating-point operations as the forward pass when accounting for recomputation strategies.

## The dsoftmax Operation and Its Jacobian Structure

The softmax function has a distinctive Jacobian structure that makes its backward pass somewhat unusual compared to simple element-wise operations. For a vector $\mathbf{s} \in \mathbb{R}^{N}$ and its softmax output $\mathbf{p} = \mathrm{softmax}(\mathbf{s})$, the Jacobian matrix $\partial \mathbf{p} / \partial \mathbf{s}$ is not diagonal but has a more complex structure.

The gradient of the softmax function can be expressed as:

$$\mathbf{d}s = (\mathrm{diag}(\mathbf{p}) - \mathbf{p} \mathbf{p}^\top)\mathbf{d}p,$$

where $\mathrm{diag}(\mathbf{p})$ is a diagonal matrix with the elements of $\mathbf{p}$ on the diagonal. This formula captures the interaction between all elements of the softmax output. Expanding this, we can write the individual components:

$$\frac{\partial p_i}{\partial s_j} = p_i(\delta_{ij} - p_j),$$

where $\delta_{ij}$ is the Kronecker delta (equal to $1$ if $i = j$ and $0$ otherwise).

This structure reveals two important properties. First, the diagonal elements of the Jacobian are $p_i(1 - p_i)$, which shows that the gradient with respect to an input element depends on the output value itself. Second, the off-diagonal elements are $-p_i p_j$, showing that changes in any input element affect all output elements.

The matrix $\mathrm{diag}(\mathbf{p}) - \mathbf{p} \mathbf{p}^\top$ can be interpreted as the covariance matrix of a multinoulli distribution with probabilities given by $\mathbf{p}$. This reflects the probabilistic interpretation of softmax: it outputs a probability distribution, and the gradient captures how this distribution changes with its inputs.

In the context of attention, the $\mathrm{dsoftmax}$ operation is applied row-wise to the matrix $\mathbf{dP}$ to produce $\mathbf{dS}$. For each row, we independently compute:

$$\mathbf{dS}_i = (\mathrm{diag}(\mathbf{P}_i) - \mathbf{P}_i \mathbf{P}_i^\top) \mathbf{dP}_i,$$

where $\mathbf{P}_i$ and $\mathbf{dP}_i$ denote the $i$-th rows of $\mathbf{P}$ and $\mathbf{dP}$, respectively. This row-wise independence is crucial for parallel implementation.

## Parallelization Across Heads and Batches

One of the key advantages of the multi-head attention architecture is its inherent parallelizability. The computation parallelizes naturally across multiple dimensions, enabling efficient utilization of modern hardware accelerators.

For multi-head attention, each head maintains its own set of query, key, and value projections. This means that the attention computation for each head is entirely independent of the computations for other heads. As stated in the paper, "each head has its own set of query, key and value projections, and this computation parallelizes across multiple heads and batches to produce the full output tensor."

This parallelization extends to the batch dimension as well. Different samples in a batch can be processed independently since there is no interaction between samples within the attention layer. Thus, the computation exhibits three levels of parallelism: across the batch dimension, across the number of heads, and across the query sequence length.

In the forward pass, this means that all heads and all batch elements can be processed simultaneously, with each computing its own attention output. In the backward pass, the same parallelization applies: "this computation parallelizes across the number of heads and batches for the backward pass of MHA."

This parallel structure makes attention particularly well-suited for GPU execution, where thousands of threads can work simultaneously on independent computations. The FlashAttention family of algorithms further exploits this by parallelizing over the sequence length dimension in FlashAttention-2, with FlashAttention-3 noting that "the forward pass of FlashAttention-3 is embarrassingly parallel in the batch size, number of heads, and query sequence length."

## FLOP Counting for Forward and Backward Passes

Understanding the computational cost of attention requires careful counting of the floating-point operations (FLOPs) involved. The paper provides explicit formulas for this purpose.

For the forward pass, the total FLOPs are given by:

$$\text{FLOPs}_{\text{forward}} = 4 \cdot \text{seqlen}^2 \cdot \text{head dimension} \cdot \text{number of heads}.$$

Let us derive this formula. The attention forward pass involves two matrix multiplications. The first computes $\mathbf{S} = \mathbf{Q}\mathbf{K}^\top$, multiplying an $N \times d$ matrix by a $d \times N$ matrix, which requires $2NdN = 2N^2 d$ FLOPs (counting both multiplications and additions). The second computes $\mathbf{O} = \mathbf{P}\mathbf{V}$, multiplying an $N \times N$ matrix by an $N \times d$ matrix, which also requires $2N^2 d$ FLOPs. Summing these gives $4N^2 d$ for a single head, and multiplying by the number of heads gives the total.

When causal masking is applied (as in autoregressive language models), approximately half of the attention matrix entries are masked out. In this case, the FLOP count is divided by 2 to account for the fact that "approximately only half of the entries are calculated."

For the backward pass, the FLOP count is approximately $2.5$ times that of the forward pass. As the paper explains, "we multiply the forward pass FLOPs by 2.5 (since there are 2 matmuls in the forward pass and 5 matmuls in the backward pass, due to recomputation)." The backward pass requires computing gradients for $\mathbf{Q}$, $\mathbf{K}$, $\mathbf{V}$, $\mathbf{P}$, and $\mathbf{S}$, involving five matrix multiplications compared to two in the forward pass.

The quadratic dependence on sequence length ($N^2$) makes attention the computational bottleneck for long sequences. This quadratic scaling is the primary motivation for research into efficient attention approximations and optimized implementations like FlashAttention.

## Memory Access Patterns in Standard Attention Implementation

The memory access patterns of an attention implementation critically determine its performance on modern hardware. Understanding these patterns illuminates why FlashAttention achieves significant speedups over standard implementations.

The paper defines "standard attention" as an implementation that "materializes the intermediate matrices $\mathbf{S}$ and $\mathbf{P}$ to HBM," referring to high-bandwidth memory, the GPU's global memory. This materialization creates a substantial memory bandwidth bottleneck.

Consider the sequence of operations in standard attention. First, the $\mathbf{Q}$, $\mathbf{K}$, and $\mathbf{V}$ matrices are read from HBM. The computation $\mathbf{S} = \mathbf{Q}\mathbf{K}^\top$ produces an $N \times N$ matrix that must be written to HBM. Then this matrix is read back to compute $\mathbf{P} = \mathrm{softmax}(\mathbf{S})$, producing another $N \times N$ matrix written to HBM. Finally, $\mathbf{P}$ is read back to compute $\mathbf{O} = \mathbf{P}\mathbf{V}$.

For a sequence length of $N$ and head dimension $d$, the intermediate matrices $\mathbf{S}$ and $\mathbf{P}$ each have $N^2$ elements. For long sequences, this quadratic memory footprint becomes prohibitive. Moreover, the repeated reads and writes to HBM create a memory bandwidth bottleneck that limits performance.

The GPU memory hierarchy provides motivation for optimization. As described in the paper, "Global memory (GMEM), also known as HBM, is the off-chip DRAM accessible to all streaming multiprocessors (SMs)." This global memory has the largest capacity but the lowest bandwidth. In contrast, "each SM contains a small on-chip, programmer-managed highly banked cache called shared memory (SMEM)" which offers much higher bandwidth but limited capacity.

The key insight behind FlashAttention was to leverage "a local version of the softmax reduction to avoid these expensive intermediate reads/writes and fuse attention into a single kernel." By keeping intermediate results in the faster shared memory and only writing the final output to global memory, FlashAttention dramatically reduces memory traffic.

The paper notes that "FlashAttention elaborated an approach to speed up attention on GPUs through minimizing memory reads/writes." This optimization is particularly important because modern GPUs are often memory-bandwidth limited rather than compute limited, making memory access patterns a critical factor in overall performance.

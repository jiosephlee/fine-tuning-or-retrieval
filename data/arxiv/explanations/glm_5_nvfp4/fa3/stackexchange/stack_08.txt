\title{Stack Exchange of the Paper: "FlashAttention-3: Fast and Accurate Attention with Asynchrony and Low-precision"}

### Why does block quantization help more than per-tensor quantization for attention?
Question:
The paper states that FlashAttention-3 uses 'block quantization' instead of 'per-tensor scaling' to reduce numerical error in FP8 attention. The difference is that block quantization keeps 'one scalar per block' while per-tensor quantization keeps 'one scalar per tensor.'

I understand that having more scaling factors gives more precision, but I'm confused about why this specifically helps with the outlier problem mentioned in the paper. The paper says 'large models typically have outlier values that are much larger in magnitude than most other values, making quantization difficult.'

If outliers are scattered throughout the tensor, how does blocking help? Wouldn't a block containing an outlier still have the same quantization problem within that block?

Also, the paper says 'we can scale each block of $\mathbf{S}$ to account for this block quantization at no computation cost.' How can this scaling be free? Don't we need extra multiplications to apply the per-block scaling factors?
Answer:
You've raised two excellent questions about the block quantization technique in FlashAttention-3. Let me address each in turn.

## Why block quantization helps with outliers

The key insight is that with per-tensor quantization, a single scaling factor must accommodate the entire dynamic range of the tensor. If even one outlier exists anywhere in the tensor, that scaling factor becomes dominated by that outlier, forcing all other values to be quantized with reduced precision. The outlier "poisons" the quantization for every single value.

Block quantization changes this fundamentally. Each block gets its own independent scaling factor, so an outlier only affects the quantization of values *within its own block*. The key realization is that while outliers may be scattered throughout the tensor, they are sparse by nature—most blocks won't contain outliers. Those blocks can use tighter scaling factors that preserve more precision for their typical values.

Consider a concrete example: if you have a tensor with 100 blocks and outliers in 3 blocks, per-tensor quantization would degrade precision for all 100 blocks, while block quantization would only affect those 3 specific blocks. The other 97 blocks maintain high precision.

## Why the scaling is "at no computation cost"

This claim requires careful interpretation. The paper states that "As the FlashAttention-3 algorithm naturally operates on blocks, we can scale each block of $\mathbf{S}$ to account for this block quantization at no computation cost."

There are two aspects to this:

1. **Fusion with preceding operations**: The quantization itself can be fused with operations like rotary positional embeddings, which are memory-bandwidth bound. Since these operations are limited by memory throughput rather than compute, the additional quantization computation doesn't increase runtime—it "hides" behind the existing memory operations.

2. **Natural integration with the block structure**: FlashAttention already processes attention in blocks (this is the core tiling strategy from the original FlashAttention). The algorithm iterates over blocks of $\mathbf{Q}$, $\mathbf{K}$, and $\mathbf{V}$ by design. When computing $\mathbf{S}_i^{(j)} = \mathbf{Q}_i \mathbf{K}_j^\top$, you're already handling blocks with indices $i$ and $j$. Incorporating per-block scaling factors doesn't require launching separate kernels or additional memory transfers—these scalars can be kept in fast on-chip memory and applied during the existing block-wise computation flow.

The paper isn't claiming that zero multiplications occur, but rather that the overhead is effectively negligible because the operations integrate naturally with the algorithm's existing block-wise structure and can be fused with memory-bound operations where compute is already "free."

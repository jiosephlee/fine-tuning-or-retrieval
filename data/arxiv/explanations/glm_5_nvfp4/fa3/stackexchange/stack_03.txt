\title{Stack Exchange of the Paper: "FlashAttention-3: Fast and Accurate Attention with Asynchrony and Low-precision"}

### How does the 2-stage pipeline break the sequential dependency between GEMM and softmax?
Question:
In FlashAttention-3's Algorithm 2 (the consumer warpgroup forward pass), I'm struggling to understand how the 2-stage pipelining breaks the sequential dependencies.

The paper acknowledges that 'softmax relies on the output $\mathbf{S}_i^{(j)}$ of the first GEMM, while the second GEMM takes its result $\widetilde{\mathbf{P}}_i^{(j)}$ as an operand.' This seems like a strict sequential dependency: GEMM1 $\rightarrow$ softmax $\rightarrow$ GEMM2.

But then the algorithm shows that within the mainloop, 'the second WGMMA operation of iteration $j$ is overlapped with softmax operations from iteration $j+1$.' 

How does this work exactly? If I'm computing iteration $j$, I need the softmax result to run GEMM2. How can I start GEMM2 from iteration $j$ before finishing softmax from the same iteration? What am I misunderstanding about the data dependencies here?
Answer:
You've identified a key insight—the sequential dependency within a *single* iteration is indeed unbreakable. The algorithm doesn't violate this dependency; instead, it restructures the computation across iterations using software pipelining.

Here's the crucial observation: in Algorithm 2, the second WGMMA at line 11 computes $\mathbf{O}_i \mathrel{+=} \tilde{\mathbf{P}}_{\mathrm{cur}} \mathbf{V}_{j-1}$. The subscript $\tilde{\mathbf{P}}_{\mathrm{cur}}$ refers to the probability matrix from the *previous* loop iteration, not the current one. This $\tilde{\mathbf{P}}_{\mathrm{cur}}$ was already computed by the softmax in iteration $j-1$.

Let me trace through the pipeline:

**Before the loop:** The algorithm computes $\mathbf{S}_{\mathrm{cur}} = \mathbf{Q}_i \mathbf{K}_0^\top$ and then applies softmax to obtain $\tilde{\mathbf{P}}_{\mathrm{cur}}$.

**During loop iteration $j$:**
- Line 9 starts $\mathbf{S}_{\mathrm{next}} = \mathbf{Q}_i \mathbf{K}_j^\top$ (first GEMM for attention on $\mathbf{K}_j$)
- Line 11 starts $\mathbf{O}_i \mathrel{+=} \tilde{\mathbf{P}}_{\mathrm{cur}} \mathbf{V}_{j-1}$ (second GEMM for attention on $\mathbf{K}_{j-1}$, using $\tilde{\mathbf{P}}_{\mathrm{cur}}$ from the previous iteration)
- Line 13 computes softmax on $\mathbf{S}_{\mathrm{next}}$, producing $\tilde{\mathbf{P}}_{\mathrm{next}}$ for attention on $\mathbf{K}_j$

This $\tilde{\mathbf{P}}_{\mathrm{next}}$ becomes $\tilde{\mathbf{P}}_{\mathrm{cur}}$ for iteration $j+1$.

So in **loop iteration $j+1$**:
- Line 11 executes the second GEMM for attention iteration $j$ (it uses $\tilde{\mathbf{P}}_{\mathrm{cur}}$ which was computed in iteration $j$'s softmax)
- Line 13 computes softmax for attention iteration $j+1$

Since WGMMA on Hopper is asynchronous and runs on Tensor Cores while softmax runs on CUDA cores (specifically the multi-function unit), these operations from lines 11 and 13 can execute concurrently. The paper's statement that "the second WGMMA operation of iteration $j$ is overlapped with softmax operations from iteration $j+1$" refers to logical attention iterations indexed by $\mathbf{K}$ blocks—both operations happen within the same loop iteration $j+1$, but they belong to different logical iterations of the attention computation.

This is classic software pipelining: by introducing buffers ($\mathbf{S}_{\mathrm{cur}}$, $\mathbf{S}_{\mathrm{next}}$, $\tilde{\mathbf{P}}_{\mathrm{cur}}$, $\tilde{\mathbf{P}}_{\mathrm{next}}$), we decouple when an operation is issued from which logical iteration it serves, allowing operations from successive logical iterations to overlap in time.

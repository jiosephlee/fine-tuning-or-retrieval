# Breaking Free from Tokens: How BLT Changes the LLM Game

For years, tokenization has been the unsung gatekeeper of large language models. Nearly every modern LLM—from GPT to Llama—relies on this pre-processing step that groups raw bytes into a fixed vocabulary of tokens before training. But what if this "necessary evil" isn't so necessary after all? A new paper introducing the Byte Latent Transformer (BLT) challenges this assumption head-on, showing that we can train competitive models directly on raw bytes while gaining significant advantages in efficiency and robustness.

## The Tokenization Bottleneck

Tokenization has always been a compromise. While LLMs are trained end-to-end on virtually everything else, tokenization remains a heuristic pre-processing step that introduces several well-documented problems:

- **Multilingual inequity**: Tokenizers trained primarily on English data compress English text more efficiently, leaving other languages with longer token sequences and effectively less model capacity.
- **Domain sensitivity**: A tokenizer optimized for text performs poorly on code, mathematics, or other specialized domains.
- **Fragility to noise**: Small perturbations in input text can cascade into wildly different token sequences, degrading model performance.
- **Lack of orthographic knowledge**: Token-based models struggle with character-level tasks like spelling manipulation or understanding the composition of words.

Until now, researchers have accepted these tradeoffs because training directly on bytes was prohibitively expensive. Processing every individual byte meant enormous sequence lengths and computational costs that didn't scale.

## Enter BLT: Patches Over Tokens

The Byte Latent Transformer reimagines how we process raw byte data. Instead of a fixed vocabulary, BLT dynamically groups bytes into "patches"—variable-sized units that serve as the primary computation blocks. The key insight? Not all predictions are created equal.

Consider predicting the next character in a sentence. Predicting the first letter of a new word after a space is relatively hard—you need to choose from countless possibilities. But once you've predicted "M" in "Mozart," predicting "o," "z," "a," "r," and "t" becomes progressively easier. BLT exploits this asymmetry by allocating more compute to high-uncertainty predictions and less to easy ones.

## Entropy-Based Dynamic Patching

BLT's patching strategy is where the magic happens. The researchers train a small byte-level language model to estimate the entropy (uncertainty) of predicting each next byte. Bytes following high-entropy predictions become patch boundaries, creating contextual groupings with relatively uniform information density.

Formally, the entropy at each position is computed as:

$$H(x_i) = \sum_{v \in \mathcal{V}} p_{e}(x_i=v|\pmb{x}_{<i}) \log p_{e}(x_i=v|\pmb{x}_{<i})$$

A patch boundary is created when this entropy exceeds a threshold, or when there's a significant jump from the previous byte's entropy. This approach has several advantages over static patching methods like fixed-size chunks or whitespace-based splitting:

- **Compute efficiency**: Longer patches are created when data is predictable, reducing computational steps.
- **Context sensitivity**: Similar byte sequences are patched consistently across different contexts.
- **Controllability**: The average patch size can be adjusted by tuning the entropy threshold, directly controlling inference cost.

## Architecture: A Three-Part Symphony

BLT's architecture consists of three transformer components working in concert:

1. **Local Encoder**: A lightweight transformer that processes raw bytes and uses cross-attention to pool them into patch representations. It incorporates hash n-gram embeddings to capture local patterns like common character sequences.

2. **Latent Global Transformer**: The heavy lifter—a large autoregressive transformer that processes patch representations. This is where most of the model's capacity lives, and it's only invoked once per patch rather than once per byte.

3. **Local Decoder**: Another lightweight transformer that takes patch representations and generates the final byte predictions, using cross-attention to attend back to relevant patch information.

This design means the expensive global transformer runs far fewer times than an equivalent token-based model, while the byte-level encoders ensure no fine-grained information is lost.

## Scaling Results: Matching Llama 3

The researchers conducted the first flop-controlled scaling study of byte-level models up to 8 billion parameters trained on 4 trillion bytes. The results are striking:

BLT matches the training flop-controlled performance of Llama 3 while using up to 50% fewer flops at inference time. Even more impressively, BLT unlocks a new scaling dimension: by increasing both model size and patch size simultaneously, you can maintain the same inference budget while scaling to larger, more capable models.

In fixed inference-cost experiments, BLT models consistently outperform tokenization-based architectures. For models trained beyond the compute-optimal regime—which describes most deployed LLMs today—BLT's advantages become even more pronounced.

## Robustness: Where Bytes Shine

Working directly with bytes provides more than efficiency gains. BLT models demonstrate significant improvements on tasks that expose tokenization's weaknesses:

- **Noisy inputs**: When tested with various character-level noise strategies (random case changes, character drops, repetition), BLT outperforms token-based models by an average of 8 points on benchmark tasks.

- **Character-level understanding**: On the CUTE benchmark testing spelling manipulation and orthographic knowledge, BLT outperforms Llama 3 models by more than 25 points, achieving near-perfect scores on spelling tasks.

- **Low-resource machine translation**: BLT shows particular strength on long-tail language pairs, outperforming Llama 3 on numerous lower-resource languages.

- **Phonology tasks**: BLT excels at grapheme-to-phoneme conversion, demonstrating awareness of linguistic structure that token-based models struggle to capture.

## A New Path Forward

BLT also shows promising results for converting existing tokenizer-based models. By initializing BLT's global transformer with weights from a pre-trained Llama 3.1 model and training the byte-level components, researchers achieved strong performance with significantly less training compute—a form of "byte-ifying" existing models.

This work doesn't just match tokenizer-based performance; it fundamentally changes what's possible. By breaking free from fixed vocabularies, BLT opens the door to models that are more efficient, more robust, and more equitable across languages and domains. For an AI field that has accepted tokenization's limitations for so long, that's a significant step forward.



# The Entropy Principle: Why AI Should Think Harder About Harder Problems

Modern large language models (LLMs) have a hidden inefficiency. They treat every piece of text with the same level of computational effort, regardless of whether they are predicting a complex reasoning step or a trivial word ending. A new architecture introduced in the paper "Byte Latent Transformer: Patches Scale Better Than Tokens," called the Byte Latent Transformer (BLT), challenges this status quo. By using an "entropy principle" to dynamically allocate compute, BLT demonstrates that we can match the performance of models like Llama 3 while using up to 50% fewer floating-point operations (FLOPs) during inference.

## The Problem with Static Tokenization

Most modern LLMs rely on tokenization—a preprocessing step that chunks text into static units (tokens) from a fixed vocabulary. While effective, this approach forces the model to spend the same computational budget on every token. This creates a trade-off between efficiency and performance. The paper highlights a fundamental mismatch: the complexity of a prediction is rarely uniform. 

Consider the example from the paper: predicting the answer to "Who composed the Magic Flute?" Predicting the first byte of the answer, "M", is a high-entropy, high-difficulty decision. However, once the "M" is established, predicting the subsequent characters "o", "z", "a", "r", and "t" becomes significantly easier. Yet, in a standard Transformer, the model expends the same heavy computational resources on the easy "o" as it does on the hard "M". This is where BLT steps in with a dynamic approach.

## Introducing Entropy Patching

Instead of using a fixed vocabulary of tokens, BLT operates directly on raw bytes, grouping them into "patches" that serve as the primary units of computation. The key innovation is how these patches are formed. BLT employs "entropy patching," a method that segments data based on the entropy of the next-byte prediction.

The process begins with a small, lightweight byte-level language model trained on the same data as the main model. This model estimates the next-byte entropy $H(x_i)$, defined as:

$$H(x_i) = \sum_{v \in \mathcal{V}} p_{e}(x_i=v|\pmb{x}_{<i}) \log p_{e}(x_i=v|\pmb{x}_{<i})$$

When this entropy crosses a specific threshold, BLT marks a boundary, creating a new patch. This ensures that the architecture allocates more compute and model capacity where data complexity demands it. High-entropy points—where the model is uncertain—trigger the end of a patch, prompting the large global transformer to "think" about the next step. Conversely, when data is predictable (low entropy), bytes are grouped into longer patches, allowing the model to process them efficiently with lighter, local operations.

## A Three-Part Architecture

To facilitate this dynamic allocation, the BLT architecture is composed of three distinct transformer blocks:

*   **A Local Encoder:** A lightweight model that encodes sequences of raw bytes into patch representations. It uses a local attention window and cross-attention to pool byte information into patches.
*   **A Latent Global Transformer:** A large, powerful autoregressive model that operates on the patch representations. This is where the heavy lifting happens, but it is only invoked once per patch.
*   **A Local Decoder:** Another lightweight model that decodes the patch representations back into raw bytes.

This structure allows BLT to "spend" compute wisely. The expensive global transformer is only called upon when the entropy signal dictates a need for deeper reasoning, bypassing the inefficient one-size-fits-all approach of tokenization.

## Better Scaling and Robustness

The results from the paper are significant. In flop-controlled scaling studies up to 8 billion parameters and 4 trillion training bytes, BLT matches the performance of tokenizer-based models like Llama 3. Because BLT can dynamically select long patches when data is predictable, it achieves significant efficiency gains. For a fixed inference cost, BLT shows significantly better scaling than tokenization-based models by simultaneously growing both patch and model size.

Beyond efficiency, working directly with bytes offers qualitative improvements. BLT models are more robust to noisy inputs and exhibit better character-level understanding. The paper notes that BLT outperforms tokenizer-based models on tasks involving orthographic knowledge, phonology, and low-resource machine translation. For instance, on the CUTE benchmark for character-level understanding, BLT outperformed Llama 3 models by more than 25 points, proving that it possesses a deeper grasp of sub-word structures that token-based models often miss.

## Conclusion

The Byte Latent Transformer presents a compelling case for moving beyond static tokenization. By adopting an entropy-guided approach to patching, BLT ensures that computational resources are directed toward the most challenging parts of a problem. This not only leads to impressive efficiency gains—cutting inference costs by up to half—but also unlocks better scaling properties and a more robust understanding of language at its most fundamental level. It suggests that the future of efficient AI might lie not in how we compress language into tokens, but in how intelligently we decide when to think.



# Beyond the Word: Improving AI's Understanding of Characters and Noise

Large Language Models (LLMs) have mastered the art of conversation, code generation, and complex reasoning. However, they suffer from a surprising fragility: they are often terrible at understanding the building blocks of language itself—characters. Ask a standard model to spell a word character-by-character or handle a input riddled with typos, and it often stumbles. This brittleness is a direct consequence of tokenization, the standard pre-processing step that compresses text into static "tokens" before the model ever sees it.

In the paper "Byte Latent Transformer: Patches Scale Better Than Tokens," researchers introduce the Byte Latent Transformer (BLT), a tokenizer-free architecture that learns directly from raw bytes. By bypassing tokenization, BLT not only improves efficiency but demonstrates remarkable robustness, significantly outperforming token-based giants like Llama 3 on tasks involving noise, character manipulation, and low-resource languages.

## The Tokenization Bottleneck

Most modern LLMs rely on subword tokenization methods like Byte-Pair Encoding (BPE). This approach groups bytes into a fixed vocabulary of tokens. While this makes training efficient, it creates a "lossy" compression. The model never sees the individual characters that make up a token; it only sees a specific ID.

This leads to a lack of orthographic knowledge. The model struggles to understand the spelling or composition of a word if it is represented as a single token. Furthermore, BPE is highly sensitive to input noise. A simple typo can split a single token into multiple, unexpected ones, drastically confusing the model's predictions. BLT eliminates this bottleneck by operating on raw bytes, grouping them dynamically into patches based on the complexity of the prediction, ensuring the model is always exposed to the granular details of the text.

## Resilience to Noise

To test robustness, the researchers subjected models to a battery of character-level noise attacks on the HellaSwag benchmark. These weren't just minor perturbations; they included aggressive strategies like:

*   **AntSpeak:** Converting text to uppercase space-separated characters (e.g., "H E L L O").
*   **Drop:** Randomly removing 10% of characters.
*   **RandomCase:** Randomly capitalizing 50% of the text.

The results were striking. While token-based models like Llama 3 faltered under the weight of these distortions, BLT remained remarkably stable. On average, BLT demonstrated an 8-point advantage over the baseline model trained on identical data. Even when compared to Llama 3.1—a model trained on significantly more data—BLT maintained a clear advantage. Because BLT processes data at the byte level, it doesn't rely on a rigid vocabulary that breaks when it encounters "noisy" input. It sees the characters for what they are, regardless of case or missing letters.

## Mastering Character-Level Understanding

The paper highlights the CUTE benchmark to evaluate character-level understanding. This benchmark tests a model's ability to understand composition, orthographic similarity, and manipulate sequences. This is notoriously difficult for tokenized models; they may "know" a word's spelling implicitly but struggle to manipulate or identify its components.

BLT outperformed the baseline Llama 3 model by more than 25 points on this benchmark. It achieved near-perfect scores (99.9%) on spelling tasks, a feat that eludes standard tokenizers. The only areas where the BPE model held an edge were word deletion and insertion—tasks that align perfectly with the word-boundaries tokenizers are designed to capture. However, the gap was narrow, and BLT's superior performance in almost every other orthographic category suggests that building character understanding "bottom-up" from bytes is more effective than trying to reconstruct it from abstract tokens.

## Empowering Low-Resource Languages

Tokenization bias is not limited to spelling; it extends to language itself. Standard tokenizers are optimized for the languages most common in the training data, typically English and high-resource European languages. This results in "multilingual inequity," where low-resource languages are fragmented into longer, less efficient sequences of tokens.

Since BLT works on raw bytes, it imposes no vocabulary bias. The paper evaluated translation capabilities on the FLORES-101 benchmark, covering six popular language families and twenty-one lower-resource languages. BLT outperformed the Llama 3 tokenizer-based model, achieving a 2-point overall advantage in translating into English and a 0.5-point advantage translating from English. More importantly, BLT excelled in lower-resource language families, demonstrating its ability to generalize to the "long-tail" of byte sequences that tokenizers fail to compress efficiently.

## Conclusion

The Byte Latent Transformer challenges the assumption that tokenization is a necessary evil for training large language models. By stepping back to the byte level, BLT unlocks a new level of robustness. It understands the structure of words, tolerates input noise, and treats low-resource languages with the same fidelity as high-resource ones. As LLMs are deployed into noisier, real-world environments, architectures that move "beyond the word" to understand the characters underneath may prove essential for reliable performance.



# The New Scaling Law: Bigger Models Without the Slowdown

For years, the defining rule of large language models (LLMs) has been straightforward: if you want a smarter model, you have to accept a slower one. Scaling laws dictate that to improve performance, we must increase model size and training data, which inevitably balloons the computational cost of both training and inference. This has led to a heavy reliance on tokenization—a preprocessing step that compresses text into static units—to keep sequence lengths manageable.

However, a recent paper introduces the Byte Latent Transformer (BLT), a architecture that challenges this trade-off. By moving away from fixed vocabularies and learning to group bytes dynamically, BLT unlocks a new scaling dimension. It allows researchers to simultaneously increase model size and efficiency, effectively decoupling model capability from inference speed.

## The Tokenization Bottleneck

Standard LLMs rely on tokenizers, typically using Byte-Pair Encoding (BPE), to chunk text into tokens. While this compresses the input, it forces the model to allocate the same amount of compute to every token, regardless of how easy or difficult it is to predict. For instance, predicting the end of a common word requires far less reasoning than predicting the first word of a complex answer.

This creates a "fixed vocabulary" problem. If you want to reduce sequence length (and thus inference cost) by using longer tokens, you must increase the vocabulary size. This bloats the model's embedding table and output projection layer, creating a rigid trade-off between efficiency and parameter count. The paper notes that moving from Llama 2 to Llama 3, for example, required a $4\times$ increase in embedding table size just to increase the average token length from 3.7 to 4.4 bytes.

## Enter Dynamic Patching

BLT bypasses this limitation by eliminating the fixed vocabulary entirely. Instead of tokens, it uses **patches**—dynamic groupings of raw bytes. The architecture relies on a lightweight entropy model to decide when to end a patch. It segments the data based on the entropy of the next-byte prediction, creating boundaries where the data is unpredictable or complex.

This approach, called **entropy patching**, allocates compute where it is needed most. High-entropy regions (like the start of a new sentence or a rare word) trigger new patches, invoking the model's heavy computational power. Low-entropy regions (like the end of a predictable word) are grouped into longer patches, allowing the model to process them with minimal effort.

## Decoupling Size from Speed

The most striking implication of this architecture is how it changes the scaling equation. A BLT model consists of three components:
1.  **A Local Encoder:** A small transformer that converts raw bytes into patch representations.
2.  **A Latent Global Transformer:** A large autoregressive transformer that processes the patch representations (the heavy lifter).
3.  **A Local Decoder:** A small transformer that converts patches back to bytes.

The computational cost of the expensive Global Transformer is determined by the number of patches, not the number of bytes. Because patches are dynamic, the model can arbitrarily adjust the average patch size. This is where the new scaling law comes into play.

In a standard token-based model, reducing the number of steps (shorter sequences) often comes at the cost of model capacity. In BLT, longer patches reduce the number of steps the Global Transformer must take. This saved compute can be reallocated to make the Global Transformer larger. 

Essentially, BLT allows you to trade patch size for model size. You can simultaneously increase the average patch size (making inference faster) and the model parameters (making it smarter) while keeping the total inference FLOPs constant.

## Validating the Scaling Law

The authors conducted inference-FLOP controlled scaling experiments to test this hypothesis. They compared BLT models against tokenization-based baselines (Llama 2 and Llama 3 tokenizers) at equivalent inference budgets.

The results confirm that patches scale better than tokens. When the models are trained beyond the standard compute-optimal point—a common practice for production models like Llama 3.1—BLT significantly outperforms its tokenizer-based counterparts. 

For example, in a fixed inference setting, BLT models with larger patch sizes (e.g., 6 or 8 bytes) were able to grow to larger parameter counts while maintaining the same inference cost. As the model scales up, the relative cost of the small local byte-level models diminishes, allowing the massive Global Transformer to dominate the compute budget. The paper shows that for a fixed inference budget, BLT models eventually surpass BPE models in performance, proving that this new scaling trajectory is viable for large-scale training.

## Conclusion

The Byte Latent Transformer introduces a paradigm shift in how we think about model efficiency. By replacing static tokens with dynamic, entropy-based patches, BLT solves the long-standing trade-off between vocabulary size and model capacity. It demonstrates that we can build larger, more robust models without the inevitable penalty of slower inference. As the field pushes toward larger models, BLT offers a compelling path forward: getting bigger without slowing down.

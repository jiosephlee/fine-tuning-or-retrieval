\title{Blogs about the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

# The High Cost of AI Inference: How FeatLLM Cuts Costs and Latency

Large Language Models (LLMs) have transformed how we approach machine learning tasks, bringing remarkable reasoning capabilities to domains that were previously challenging. Tabular data learning—the bread and butter of real-world applications in finance, healthcare, and beyond—has naturally attracted attention from researchers looking to leverage LLMs' rich prior knowledge. However, there's a significant practical problem that often gets overlooked in the excitement: the cost of inference.

## The Expensive Status Quo

Current LLM-based approaches to tabular learning follow a seemingly straightforward pattern. You serialize your tabular data into text, feed it into an LLM along with feature descriptions and task descriptions, and let the model make predictions. Whether using in-context learning or parameter-efficient fine-tuning methods like LoRA or IA3, these approaches share a common bottleneck: every single prediction requires a pass through the LLM.

This creates a substantial barrier for real-world deployment. In industrial settings where you might need to make millions of predictions, querying an LLM API for each sample becomes prohibitively expensive and slow. Additionally, many state-of-the-art LLMs only provide limited access through inference APIs, making fine-tuning impossible. There's also the issue of prompt length limitations—when your tabular dataset has hundreds of features, the serialized text can exceed the model's context window.

## A Smarter Approach: LLMs as Feature Engineers

FeatLLM, a novel framework proposed in recent research, takes a fundamentally different approach. Instead of asking the LLM to make predictions for each sample, it asks the LLM to figure out what features matter for making predictions.

The key insight is elegant: the LLM's prior knowledge about the world can help it understand which conditions or rules are relevant for a classification task. For example, when predicting heart disease, the LLM can draw on its training to identify that age, blood pressure, and cholesterol levels are important factors, and propose specific thresholds or combinations that indicate higher risk.

FeatLLM structures this feature engineering process into two reasoning steps. First, the LLM infers the relationship between features and the task based on general knowledge. Second, it looks at the few-shot examples provided and derives specific rules for distinguishing between classes. These rules are then parsed into code and used to create binary features indicating whether each sample satisfies the conditions.

## The Efficiency Payoff

Once the features are generated, the LLM's job is done. The actual predictions use a simple downstream model—linear regression in the basic implementation—with minimal computational requirements. The math is straightforward:

$$\text{logit}_k^i = \max(\mathbf{w}_k, 0) \cdot \mathbf{z}_k^i$$

$$\mathbf{p}^i = \text{Softmax}({[\text{logit}_{1}^i, ..., \text{logit}_{c}^i]})$$

Where $\mathbf{z}_k^i$ represents the binary features generated from the rules, and $\mathbf{w}_k$ are learnable weights representing the importance of each rule. The system projects weights into positive subspace to ensure features don't reduce class likelihood during learning.

This architecture means inference is incredibly fast—comparable to traditional machine learning methods like logistic regression or random forests. Meanwhile, competing LLM-based approaches require orders of magnitude more time because every sample requires an LLM query.

## Robustness Through Ensemble Methods

FeatLLM adds another layer of sophistication through ensemble methods. By repeatedly running the feature generation process with different randomizations—varying the temperature, shuffling few-shot example orders, and using feature bagging—the framework creates multiple sets of rules. This ensemble approach provides two key benefits.

First, it improves robustness. If the LLM generates incorrect rules in some trials, correct rules from other trials can compensate. This aligns with research on LLM self-consistency: rules commonly inferred across multiple trials are more likely to be accurate.

Second, it addresses prompt length limitations. When datasets have many features, bagging helps by selecting subsets of features for each trial, ensuring the context window isn't exceeded. The ensemble of various "weak learners" created across trials compensates for incomplete feature coverage in any single trial.

## Performance That Backs Up the Theory

The efficiency gains don't come at the cost of accuracy. Across 13 diverse tabular datasets, FeatLLM significantly outperformed alternatives like TabLLM and STUNT by 10% on average. Remarkably, using just 4-shot learning, FeatLLM achieved performance comparable to conventional baselines requiring 32 shots.

The framework also demonstrated strong resistance to spurious correlations. In experiments where irrelevant columns were added to datasets, FeatLLM showed the least performance degradation because its rule generation process considers the relationship between the task and features based on prior knowledge, preventing the creation of rules based on irrelevant columns.

## A Practical Path Forward

FeatLLM represents a pragmatic shift in how we think about deploying LLMs for tabular learning. By treating LLMs as feature engineers rather than end-to-end predictors, the framework eliminates the need to query the LLM for each sample at inference time. It requires only API-level access—no fine-tuning necessary—and handles large feature sets gracefully through ensemble methods.

For practitioners dealing with the real constraints of production systems—budget limitations, latency requirements, and API-only access to state-of-the-art models—this approach offers a compelling alternative. You get the benefit of the LLM's world knowledge distilled into interpretable rules, combined with the speed and cost-effectiveness of simple linear models. It's a win-win that makes LLM-powered tabular learning actually practical for real-world deployment.

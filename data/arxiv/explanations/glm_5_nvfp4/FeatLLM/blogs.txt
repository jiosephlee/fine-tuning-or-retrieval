# From Predictor to Architect: How LLMs are Redefining Feature Engineering

Large Language Models (LLMs) have demonstrated an impressive ability to tackle unseen tasks using their "world knowledge"—the vast amount of information absorbed during pre-training. In the realm of tabular data (think spreadsheets or database tables), researchers have primarily used LLMs as end-point predictors. You serialize a row of data into text, feed it to the model, and ask for a prediction.

While effective in low-data regimes, this approach has a significant bottleneck: it requires querying the LLM for every single sample at inference time. This is computationally expensive, slow, and often restricted by API rate limits. A recent paper introduces a paradigm shift with a framework called **FeatLLM**. Instead of asking the LLM to predict outcomes, it asks the LLM to design the features that matter.

## The Limitations of LLMs as Predictors

Current methods for tabular learning with LLMs typically involve serializing data into a text prompt. For example, "Age is 65. Blood pressure is high. Does this patient have heart disease?" The LLM then outputs "Yes" or "No."

This methodology faces three major hurdles:
1.  **Inference Cost:** You pay the computational price of an LLM forward pass for every row of data.
2.  **Accessibility:** High-performance models like GPT-4 are often available only via API, making fine-tuning impossible.
3.  **Context Limits:** Real-world datasets can have hundreds of features. Fitting all columns and few-shot examples into a single prompt often exceeds the context window of current models.

FeatLLM circumvents these issues by changing the LLM's role from a black-box predictor to a **feature engineer**.

## FeatLLM: The LLM as a Rule-Maker

The core insight of FeatLLM is that LLMs are excellent at understanding the *criteria* for a decision, even if they don't make the final call. The framework leverages in-context learning to extract logical rules from the LLM, which are then used to transform raw data into meaningful features for a simple downstream model (like linear regression).

Here is how the framework operates:

### 1. Structured Reasoning and Rule Extraction
The framework constructs a prompt that guides the LLM through a two-step reasoning process, mimicking how a human expert would analyze a dataset.

*   **Step 1 (Prior Knowledge):** The LLM first infers relationships between features and the target variable based solely on its internal knowledge, ignoring the few-shot examples initially. For instance, in a heart disease dataset, the LLM might rely on general medical knowledge to suggest that "Age" and "Cholesterol" are critical factors.
*   **Step 2 (Rule Derivation):** The LLM then examines the few-shot examples provided in the prompt to derive specific, decisive rules. These rules are generated in a structured format to facilitate parsing.

For example, for a specific class (e.g., "High Risk"), the LLM might generate rules like: "Age is greater than 60" or "Blood Pressure is High."

### 2. Parsing and Feature Generation
Once the rules are generated, they are parsed into executable code (Python functions). These functions are applied to the dataset to create **binary features**. If a sample satisfies a specific rule, the feature value becomes $1$; otherwise, it is $0$.

This transforms the dataset into a binary matrix indicating which rules each sample satisfies. This process essentially converts the LLM's "world knowledge" into a structured numerical representation.

### 3. Inferring Class Likelihood
With the newly engineered features, the need for a complex deep learning model vanishes. FeatLLM trains a simple linear model to estimate class probabilities.

Let $\mathbf{z}_k^i$ represent the binary feature vector for sample $i$ and class $k$, where $R$ is the number of rules. The logit for each class is calculated as:

$$ \text{logit}_k^i = \max(\mathbf{w}_k, 0) \cdot \mathbf{z}_k^i $$

Here, $\mathbf{w}_k$ represents the trainable weights signifying the importance of each rule. The model projects weights into a positive subspace to ensure that satisfying a rule associated with a class does not penalize the likelihood of belonging to that class. The final prediction is made by averaging probabilities across multiple trials, enhancing robustness.

## Overcoming Prompt Limitations with Bagging

Real-world datasets often contain too many features to fit into a single LLM prompt. FeatLLM borrows a page from classical machine learning playbooks to solve this: **bagging**.

The framework repeatedly samples subsets of features and instances to generate diverse sets of rules. By ensembling these "weak learners," FeatLLM effectively covers the entire feature space without ever needing to process all columns simultaneously. This not only solves the prompt length issue but also improves robustness, as rules consistently inferred across multiple trials are more likely to be accurate.

## Efficiency and Performance

The advantages of this approach are distinct:

*   **Zero Inference Latency:** Unlike methods like TabLLM or in-context learning, FeatLLM does not query the LLM at inference time. Once the features are engineered and the linear model is trained, predictions are blazing fast.
*   **API-Only Compatibility:** Since the LLM is only used for feature generation (a one-time cost), the framework works perfectly with models accessible only via API, requiring no fine-tuning.
*   **Robustness:** By forcing the LLM to rely on prior knowledge to formulate rules, FeatLLM is less susceptible to spurious correlations found in small datasets. It generates rules that make semantic sense rather than overfitting to noise.

In experiments across 13 diverse datasets, FeatLLM significantly outperformed alternatives like TabLLM and STUNT by an average of 10%. Remarkably, with just 4 labeled examples, it achieved performance comparable to conventional tabular baselines that required 32 examples.

## Conclusion

FeatLLM represents a significant step forward in applying LLMs to structured data. By shifting the LLM's role from a predictor to an architect, it leverages the model's strengths (reasoning and knowledge retrieval) while mitigating its weaknesses (inference cost and context limits). This approach allows practitioners to distill the "world knowledge" of an LLM into a simple, efficient, and interpretable model, opening new doors for data-efficient learning.



# The High Cost of AI Inference: How FeatLLM Cuts Costs and Latency

Large Language Models (LLMs) have transformed how we approach machine learning tasks, bringing remarkable reasoning capabilities to domains that were previously challenging. Tabular data learning—the bread and butter of real-world applications in finance, healthcare, and beyond—has naturally attracted attention from researchers looking to leverage LLMs' rich prior knowledge. However, there's a significant practical problem that often gets overlooked in the excitement: the cost of inference.

## The Expensive Status Quo

Current LLM-based approaches to tabular learning follow a seemingly straightforward pattern. You serialize your tabular data into text, feed it into an LLM along with feature descriptions and task descriptions, and let the model make predictions. Whether using in-context learning or parameter-efficient fine-tuning methods like LoRA or IA3, these approaches share a common bottleneck: every single prediction requires a pass through the LLM.

This creates a substantial barrier for real-world deployment. In industrial settings where you might need to make millions of predictions, querying an LLM API for each sample becomes prohibitively expensive and slow. Additionally, many state-of-the-art LLMs only provide limited access through inference APIs, making fine-tuning impossible. There's also the issue of prompt length limitations—when your tabular dataset has hundreds of features, the serialized text can exceed the model's context window.

## A Smarter Approach: LLMs as Feature Engineers

FeatLLM, a novel framework proposed in recent research, takes a fundamentally different approach. Instead of asking the LLM to make predictions for each sample, it asks the LLM to figure out what features matter for making predictions.

The key insight is elegant: the LLM's prior knowledge about the world can help it understand which conditions or rules are relevant for a classification task. For example, when predicting heart disease, the LLM can draw on its training to identify that age, blood pressure, and cholesterol levels are important factors, and propose specific thresholds or combinations that indicate higher risk.

FeatLLM structures this feature engineering process into two reasoning steps. First, the LLM infers the relationship between features and the task based on general knowledge. Second, it looks at the few-shot examples provided and derives specific rules for distinguishing between classes. These rules are then parsed into code and used to create binary features indicating whether each sample satisfies the conditions.

## The Efficiency Payoff

Once the features are generated, the LLM's job is done. The actual predictions use a simple downstream model—linear regression in the basic implementation—with minimal computational requirements. The math is straightforward:

$$\text{logit}_k^i = \max(\mathbf{w}_k, 0) \cdot \mathbf{z}_k^i$$

$$\mathbf{p}^i = \text{Softmax}({[\text{logit}_{1}^i, ..., \text{logit}_{c}^i]})$$

Where $\mathbf{z}_k^i$ represents the binary features generated from the rules, and $\mathbf{w}_k$ are learnable weights representing the importance of each rule. The system projects weights into positive subspace to ensure features don't reduce class likelihood during learning.

This architecture means inference is incredibly fast—comparable to traditional machine learning methods like logistic regression or random forests. Meanwhile, competing LLM-based approaches require orders of magnitude more time because every sample requires an LLM query.

## Robustness Through Ensemble Methods

FeatLLM adds another layer of sophistication through ensemble methods. By repeatedly running the feature generation process with different randomizations—varying the temperature, shuffling few-shot example orders, and using feature bagging—the framework creates multiple sets of rules. This ensemble approach provides two key benefits.

First, it improves robustness. If the LLM generates incorrect rules in some trials, correct rules from other trials can compensate. This aligns with research on LLM self-consistency: rules commonly inferred across multiple trials are more likely to be accurate.

Second, it addresses prompt length limitations. When datasets have many features, bagging helps by selecting subsets of features for each trial, ensuring the context window isn't exceeded. The ensemble of various "weak learners" created across trials compensates for incomplete feature coverage in any single trial.

## Performance That Backs Up the Theory

The efficiency gains don't come at the cost of accuracy. Across 13 diverse tabular datasets, FeatLLM significantly outperformed alternatives like TabLLM and STUNT by 10% on average. Remarkably, using just 4-shot learning, FeatLLM achieved performance comparable to conventional baselines requiring 32 shots.

The framework also demonstrated strong resistance to spurious correlations. In experiments where irrelevant columns were added to datasets, FeatLLM showed the least performance degradation because its rule generation process considers the relationship between the task and features based on prior knowledge, preventing the creation of rules based on irrelevant columns.

## A Practical Path Forward

FeatLLM represents a pragmatic shift in how we think about deploying LLMs for tabular learning. By treating LLMs as feature engineers rather than end-to-end predictors, the framework eliminates the need to query the LLM for each sample at inference time. It requires only API-level access—no fine-tuning necessary—and handles large feature sets gracefully through ensemble methods.

For practitioners dealing with the real constraints of production systems—budget limitations, latency requirements, and API-only access to state-of-the-art models—this approach offers a compelling alternative. You get the benefit of the LLM's world knowledge distilled into interpretable rules, combined with the speed and cost-effectiveness of simple linear models. It's a win-win that makes LLM-powered tabular learning actually practical for real-world deployment.



# Making Sense of Small Data: Solving the 'Cold Start' Problem with LLMs

Every data scientist knows the struggle of the "cold start" problem. You have a promising new project—perhaps predicting patient readmission rates or detecting fraud in a niche financial sector—but you barely have enough labeled data to train a model. Traditional machine learning models like XGBoost or Random Forest thrive on data volume; starve them, and they quickly overfit or latch onto spurious correlations.

Large Language Models (LLMs) have emerged as a potential solution due to their vast reservoir of prior knowledge. However, simply feeding tabular data into an LLM and asking for a prediction is computationally expensive and often impractical for real-world deployment. A recent paper introduces **FeatLLM**, a framework that redefines the LLM's role from "predictor" to "feature engineer," offering a robust solution for few-shot tabular learning.

## The Problem with Current LLM Approaches

Current methods for applying LLMs to tabular data typically involve serializing the data rows into text and feeding them into the model. While this leverages the LLM's reasoning capabilities, it comes with significant drawbacks:

*   **High Inference Cost:** You must query the LLM for every single sample you want to predict. This becomes prohibitively expensive and slow at scale.
*   **Fine-Tuning Constraints:** Many top-performing LLMs (like GPT-4) are only accessible via inference APIs. You cannot fine-tune their weights, limiting how well they adapt to specific tasks.
*   **Context Window Limits:** Tabular data often has hundreds of features. When serialized into text, this can easily exceed the prompt length limits of many LLMs, leading to performance degradation.

FeatLLM sidesteps these issues by changing the objective. Instead of asking the LLM to predict the label for a specific row, it asks the LLM to define the *rules* that determine the label.

## FeatLLM: The LLM as an Expert Feature Engineer

The core insight of FeatLLM is that LLMs excel at understanding criteria and logic. Think of it like working with a human domain expert. Instead of asking a doctor to personally diagnose every patient in your database, you ask the doctor, "What symptoms indicate this disease?" The doctor gives you a checklist (rules), which you then apply to the data yourself.

FeatLLM operates in a structured pipeline:

1.  **Prompting for Rules:** The framework constructs a prompt containing the task description, feature definitions, and a few labeled examples. Crucially, it instructs the LLM to perform a two-step reasoning process. First, the LLM infers general causal relationships based on its prior knowledge. Second, it derives specific, decisive rules (e.g., "If `age` > 60 AND `blood_pressure` is high, then high risk").
2.  **Parsing and Feature Generation:** These rules are natural language text, which can be messy. FeatLLM cleverly uses the LLM again to parse its own output into executable Python code. This code is then run against the dataset to generate new binary features. A sample might get a "1" if it satisfies a specific rule and a "0" if it does not.
3.  **Downstream Modeling:** Once the data is transformed into these rule-based binary features, the problem becomes much simpler. FeatLLM trains a basic linear model (like logistic regression) to learn the importance of each rule.

## Why This Works Better Than You Might Expect

This approach yields impressive results, significantly outperforming alternatives like TabLLM and STUNT by an average of 10%.

The power lies in how FeatLLM utilizes the LLM's "prior knowledge." In low-shot regimes (e.g., only 4 or 8 labeled samples), the statistical patterns in the data might be misleading. However, the LLM already knows, for instance, that older age increases the risk of heart disease. By forcing the model to generate rules based on this knowledge *before* looking closely at the few examples, FeatLLM filters out spurious correlations that might trap a traditional model.

For example, the paper highlights an experiment where irrelevant columns (noise) were added to a dataset. Traditional few-shot methods saw their performance plummet as they tried to fit the noise. FeatLLM, guided by the LLM's reasoning, largely ignored the irrelevant columns and focused on the features that actually mattered, maintaining high accuracy.

## Efficiency and Real-World Application

One of the most compelling aspects of FeatLLM is its inference efficiency. Because the LLM is only used to generate the rules (a one-time cost during training), the inference time is determined by the simple linear model, not the LLM. This makes it fast enough for real-time applications.

This has massive implications for specialized industries:

*   **Healthcare:** Predicting rare diseases where labeled datasets are small. The LLM provides medical logic that a few data points cannot provide alone.
*   **Finance:** Assessing credit risk for new loan products or detecting fraud in emerging markets where historical data is scarce.

The framework also employs "feature bagging"—randomly selecting subsets of features—to handle datasets with hundreds of columns. This ensemble approach ensures that even if one set of rules is incomplete, the combined predictions of multiple "feature engineers" remain robust.

## Conclusion

FeatLLM represents a pragmatic shift in how we apply LLMs to structured data. By treating the LLM as a reasoning engine that generates features rather than a black-box predictor, we can achieve high accuracy in few-shot settings without the prohibitive costs of LLM inference. For data scientists facing the cold start problem, this framework offers a way to turn an LLM's general world knowledge into a competitive edge.



# Beyond the Black Box: Why Rule-Based Features are the Future of Explainable AI

## The Interpretability Problem in Modern Machine Learning

As machine learning models become increasingly sophisticated, a troubling trade-off has emerged: the most powerful models often operate as inscrutable black boxes. Deep neural networks and large language models (LLMs) may achieve impressive accuracy, but ask a practitioner why the model made a particular prediction, and you'll often be met with a shrug. In domains like healthcare and finance, this lack of transparency isn't just inconvenient—it's a barrier to adoption.

A recent paper introducing a framework called FeatLLM offers a refreshing alternative. Instead of using LLMs as end-to-end predictors, the researchers propose using them as feature engineers, generating explicit, human-readable rules that can be inspected, validated, and understood.

## From Predictions to Rules: A Paradigm Shift

The key insight behind FeatLLM is elegantly simple: rather than asking an LLM to directly predict outcomes, ask it to articulate the criteria it would use to make such predictions. For instance, when predicting heart disease, the LLM might generate rules like "if the patient's age is greater than 60 and cholesterol levels are high, then consider elevated risk."

This approach transforms the LLM from a mysterious oracle into an expert consultant that articulates its reasoning. The framework structures this rule extraction into two stages. First, the LLM reasons about the relationship between features and the target variable based on its prior knowledge. Second, it uses example demonstrations to derive specific, decisive rules for distinguishing between classes.

## How Rule-Based Features Work

The technical implementation is straightforward yet powerful. The LLM generates approximately 10 rules per class, which are then parsed into executable code. Each rule becomes a binary feature: a sample either satisfies the rule (value of 1) or doesn't (value of 0). These binary features serve as inputs to a simple linear model that learns the importance weight for each rule.

The mathematical formulation is elegant. Given binary features $\mathbf{z}_k^i \in \{0, 1\}^R$ generated from the rules for class $k$, the class probability is computed as:

$$\text{logit}_k^i = \max(\mathbf{w}_k, 0) \cdot \mathbf{z}_k^i$$

$$\mathbf{p}^i = \text{Softmax}({[\text{logit}_{1}^i, ..., \text{logit}_{c}^i]})$$

Here, the weights $\mathbf{w}_k$ are constrained to be non-negative, ensuring that satisfying a rule never reduces the likelihood of a class. This constraint preserves the interpretability of the rules—practitioners can examine which rules fired for a given sample and understand exactly how they contributed to the final prediction.

## Practical Benefits of Transparency

The advantages of this approach extend beyond mere interpretability. By generating explicit rules, practitioners can validate that the model is learning sensible patterns rather than spurious correlations. The researchers tested this by adding irrelevant columns from an unrelated dataset to a heart disease prediction task. FeatLLM showed minimal performance degradation because the LLM's prior knowledge helped filter out noise—rules based on irrelevant columns accounted for only 1-2% of the total generated rules.

Furthermore, the framework naturally handles feature selection. The two-step reasoning process encourages the LLM to focus on meaningful features rather than attempting to find patterns in every available column. This is particularly valuable when dealing with high-dimensional datasets where many features may be irrelevant.

## Ensemble Methods for Robustness

To address the inherent variability in LLM outputs, FeatLLM employs an ensemble approach with bagging. The entire rule generation process is repeated multiple times with different random subsets of features and samples. This serves multiple purposes: it improves robustness by ensuring that incorrect rules from some trials are compensated by correct rules from others, and it handles datasets with many features that might exceed the LLM's context window.

The ensemble approach also reinforces self-consistency—rules that appear across multiple trials are more likely to be accurate. When combined, these weak learners create a robust prediction system that maintains interpretability at the individual rule level.

## Performance Without Compromise

Remarkably, this interpretable approach doesn't sacrifice performance. Across 13 diverse tabular datasets, FeatLLM outperformed existing LLM-based methods like TabLLM and STUNT by an average of 10%. Using just 4 labeled examples, it achieved performance comparable to traditional machine learning methods trained on 32 examples.

The efficiency gains are equally impressive. Unlike end-to-end LLM approaches that require one query per sample at inference time, FeatLLM only uses the LLM during the feature engineering phase. At inference time, predictions use only the learned linear model, making deployment practical for real-world applications.

## The Path Forward

FeatLLM demonstrates that we don't have to choose between performance and interpretability. By reimagining the role of LLMs in the machine learning pipeline, we can leverage their rich prior knowledge while maintaining the transparency that practitioners need.

As AI systems are increasingly deployed in high-stakes domains, this type of explainable approach will become essential. Regulators, clinicians, and financial analysts need to understand why a model made a particular prediction—not just trust that it did so correctly. Rule-based features offer a promising path toward AI systems that are not only powerful but also trustworthy.

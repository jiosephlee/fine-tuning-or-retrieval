\title{Stack Exchange of the Paper: LongRoPE}

### What exactly is the rescaling formula for RoPE in LongRoPE (notation confusion around \(\lambda\), \(\hat{\lambda}\), and \(\beta\))?
Question:
I'm confused by the unified RoPE expression used in the paper. The standard RoPE for position \(n\) uses angles \([\cos(n\theta_0), \sin(n\theta_0), \ldots]\) with \(\theta_i = \theta^{-2i/d}\) and \(\beta = \theta^{2/d}\), so the per-dimension angle can be written as \(\frac{n}{\beta^i}\).

For interpolation, the paper writes something like \(\cos\big(\frac{n}{\lambda(\beta)^i}\big)\) and later defines per-dimension factors \(\lambda_i\) and also uses \(\hat{\lambda}_i = 1/\lambda_i\), and a position gating function \(\mathbb{I}(\hat{\lambda}_i, \hat{n})\). Can someone clarify the exact angle used per dimension/head/layer? Is it:
- \(\cos\big(\frac{n}{\lambda_i\,\beta^i}\big)\) for \(n \ge \hat{n}\) and \(\cos\big(\frac{n}{\beta^i}\big)\) for \(n < \hat{n}\), or
- \(\cos\big(\mathbb{I}(\hat{\lambda}_i,\hat{n})\cdot \frac{n}{\beta^i}\big)\) with \(\mathbb{I}\) either 1 or \(1/\lambda_i\)?
Also, is \(\lambda\) ever a function of \(\beta\), or is it always dimension-specific constants \(\{\lambda_i\}\)?
Answer:
Short answer: the paper uses the per-dimension RoPE angle
$\theta_{n,i} = I(\hat{\lambda}_i, \hat{n}) * (n / \beta^i)$,
where $I(\hat{\lambda}_i, \hat{n}) = 1$ for $n < \hat{n}$ and $I(\hat{\lambda}_i, \hat{n}) = 1 / \lambda_i$ for $n \ge \hat{n}$. Equivalently, for dimension $i$

- if $n < \hat{n}$: angle = $n / \beta^i$ (original RoPE),
- if $n \ge \hat{n}$: angle = $n / (\lambda_i * \beta^i)$.

Thus the active rescale multiplies the whole original fraction by $1/\lambda_i$ (or, viewed as changing the denominator, divides $\beta^i$ by $\lambda_i$). The paper also defines $\hat{\lambda}_i = 1 / \lambda_i$ (so $\hat{\lambda}_i$ is the multiplicative factor applied to the angle), and searches directly over the set $\{\lambda_i\}$.

Explanation and how to read the notation in the paper
- The classic RoPE angle is written as $n / \beta^i$ (paper uses $\beta = \theta^{2/d}$ so the per-dim base is $\beta^i$). Position Interpolation (PI) or NTK variants can be written in the same form by picking particular $\lambda$ patterns (e.g., PI uses a uniform $\lambda = s$ across all $i$; dynamic-NTK gives different $\lambda$ as a function of $i$).
- In Eq. (3) the paper first wrote a unified form $\cos(n / \lambda(\beta)^i)$ to show that different methods are just different rescalings across dimensions. That expression is a high-level shorthand to indicate a per-dimension rescaling; it should not be read as a literal function $\lambda(\beta)$ that depends on $\beta$. Later they make the rescale explicit and per-dimension by introducing $\lambda_i$ and its reciprocal $\hat{\lambda}_i$.
- Concretely, the paper parameterizes the RoPE used during search as $\cos\big( I(\hat{\lambda}_i, \hat{n}) * (n / \beta^i) \big)$ and $\sin\big( I(\hat{\lambda}_i, \hat{n}) * (n / \beta^i) \big)$ with $I(\cdot)$ defined piecewise. They search over $\lambda_i$ (allowed range and monotonicity constraint), and use $\hat{\lambda}_i$ only as the multiplicative factor in the indicator function ($\hat{\lambda}_i = 1/\lambda_i$).

Which of your two options matches the paper?
The paper uses the first option you wrote, but expressed via the multiplicative indicator: for $n < \hat{n}$ use $\cos(n / \beta^i)$; for $n \ge \hat{n}$ use $\cos\big( n / (\lambda_i * \beta^i) \big)$. Equivalently it is $\cos\big( I * (n / \beta^i) \big)$ with $I \in \{1, 1/\lambda_i\}$.

Is $\lambda$ ever a function of $\beta$?
No. In the paper $\lambda$ (and the per-dimension $\lambda_i$) are treated as dimension-specific constants to be searched/found. The early notation $\lambda(\beta)^i$ is a notational shorthand to unify different interpolation formulas; operationally, LongRoPE searches a vector of scalars $\{\lambda_i\}$ (subject to monotonicity constraints) and a token threshold $\hat{n}$.

Intuition
Viewing rescaling as multiplying the original angle by $1/\lambda_i$ makes it clear what happens: larger $\lambda_i$ compresses angles for tokens beyond $\hat{n}$ in that dimension (positions become “closer” on the unit circle), while $\lambda_i = 1$ is pure extrapolation (no compression). The token threshold $\hat{n}$ encodes the second non-uniformity: early tokens ($n < \hat{n}$) keep the original angles because they tend to be most critical to attention, and only later positions get rescaled.

Wrap-up formula (explicit)
For RoPE dimension $i$ and token position $n$, with $\beta$ defined as in the paper:

$$
\theta_{n,i} =
\begin{cases}
n / \beta^i, & \text{if } n < \hat{n};\\[6pt]
n / (\lambda_i * \beta^i), & \text{if } n \ge \hat{n}.
\end{cases}
$$

and the embedding uses $\cos(\theta_{n,i})$, $\sin(\theta_{n,i})$. Hat-$\lambda_i$ in the paper notation is $\hat{\lambda}_i = 1 / \lambda_i$ and is the multiplicative factor applied to the original $n/\beta^i$.

### Why impose a monotonic non-decreasing constraint \(\lambda_i \le \lambda_{i+1}\) across RoPE dimensions?
Question:
The search enforces \(\lambda_i \le \lambda_{i+1}\) over the half-dimensions (i.e., lower-indexed, higher-frequency dimensions receive less interpolation). I understand the NTK-inspired intuition, but is there a theoretical reason this monotonicity should always hold for optimal interpolation? Could an optimal solution violate monotonicity due to model- or layer-specific idiosyncrasies? Do you have ablations showing performance when the constraint is removed or relaxed?
Answer:
Short answer: the monotonic constraint $\lambda_i \le \lambda_{i+1}$ is both a theoretically motivated regularizer (NTK / frequency intuition) and a very pragmatic search/pruning strategy. The paper imposes it to bias the search toward solutions that respect the frequency ordering of RoPE dimensions and to drastically reduce the expensive search space; the authors do not present a dedicated ablation that fully removes the constraint, so they do not claim it is mathematically necessary for global optimality in every case.

Why monotonicity makes sense (intuitive + technical):
- Frequency interpretation of RoPE. Each RoPE half-dimension corresponds to an effective rotation frequency (higher index $\rightarrow$ lower frequency). NTK-inspired analyses (and prior work the paper cites) argue that high-frequency dimensions encode fine-grained local position differences and should be changed less when stretching/extrapolating positions; low-frequency dimensions can accept more rescaling. That intuition is exactly expressed by a non-decreasing $\lambda_i$: low-index (high-frequency) dimensions keep small $\lambda$, high-index (low-frequency) dimensions get larger $\lambda$.
- Regularization / smoothness. For high-dimensional rescaling, allowing arbitrary non-monotone $\lambda$ can produce unnatural spectral permutations (e.g., making some mid-frequency dimensions behave like very low or very high frequency). Enforcing monotonicity keeps the embedding’s frequency ordering coherent and avoids pathological encodings that could confuse attention/head weights trained on the original ordering.
- Search/practical constraints. The paper explicitly states the monotonicity constraint mainly as a way to prune the astronomically large search space so that evolutionary search is tractable: only candidates satisfying $\lambda_i\le\lambda_{i+1}$ are evaluated. This reduces wasted evaluations of implausible, high-loss candidates and thus reduces compute dramatically.

Could an optimal solution ever violate monotonicity?
Yes, in principle. The paper’s formulation treats $\{\lambda_i\}$ as a per-dimension optimization; there is no formal proof that the global optimum must be monotone. Model- and layer-specific idiosyncrasies (e.g., learned cross-dimension coupling in attention projections, per-head frequency preferences, or discrete fine-tuning dynamics) could conceivably make a non-monotone pattern slightly better on the chosen validation loss. But two points temper that concern: (1) the NTK and empirical prior strongly suggest near-monotone structure is natural for positional-frequency effects, and (2) the search space is so huge that many non-monotone optima may be overfitting to the small validation signal and generalize worse on downstream long-context tasks.

What the paper reports about this design choice
- The paper motivates monotonicity from NTK theory and uses it to dramatically reduce evaluation cost during evolution search. It shows strong empirical gains from their searched non-uniform $\{\lambda_i\}$ relative to PI, NTK formula, and YaRN, demonstrating that a monotone, non-uniform per-dimension rescaling is highly effective.
- The ablations in the paper focus on: (a) separating the two non-uniformities (dimension-wise versus token-position-wise) and (b) effects of the second interpolation and short-length recovery. There is no explicit experiment reported that compares (i) full unconstrained search over arbitrary $\{\lambda_i\}$ vs (ii) monotone-constrained search, nor a test of relaxing monotonicity into a soft constraint. So you will not find in-paper numeric evidence showing that removing the monotone constraint improves or degrades performance.

Practical recommendations / how you could test it
If you suspect layer- or model-specific violations, try these controlled experiments:
- Relaxed monotonicity: allow small local inversions by enforcing $\lambda_{i} \le \lambda_{i+1} + \epsilon$ (with $\epsilon>0$) or add a soft penalty $\alpha\sum_i \max(0,\lambda_i-\lambda_{i+1})$ to the validation objective. This keeps the bias but lets the search escape strict ordering if beneficial.
- Per-layer / per-head search: run the search per-layer (or per-block of layers) instead of globally. If optimal patterns vary across layers, this will reveal it; expect higher compute but clearer diagnostics.
- Unconstrained stochastic probe: randomly sample unconstrained $\{\lambda_i\}$ candidates and evaluate a small budget (to see whether unconstrained samples often beat the monotone solution). If they do rarely, monotonicity is not restricting a large gain.

Takeaway
Monotonicity is not a provable necessary condition for optimality, but it codifies a strong prior (NTK/frequency ordering), stabilizes solutions, and is essential for making the evolutionary search feasible at scale. The paper leverages this constraint to find effective, generalizable per-dimension rescalings; it does not report an explicit ablation that removes the constraint, so if you want to test whether the monotone assumption is ever sub-optimal for your model/layer, you should run the suggested relaxed or per-layer experiments.

### How is discontinuity at the threshold \(\hat{n}\) avoided when the first \(\hat{n}\) tokens are not interpolated?
Question:
The paper proposes preserving the first \(\hat{n}\) positions, i.e., for \(n<\hat{n}\), use the original angles \(\frac{n}{\beta^i}\), and for \(n\ge\hat{n}\), use rescaled angles \(\frac{n}{\lambda_i\,\beta^i}\). Doesn't this create a potential phase discontinuity around \(n=\hat{n}\) for each dimension? Is there any adjustment (e.g., an additive phase shift) to ensure continuity at \(\hat{n}\), or is the model robust to this jump? If no continuity correction is used, do you observe artifacts in attention around the boundary?
Answer:
Short answer: The paper does not add an explicit additive phase shift at the threshold $\hat{n}$. Instead, LongRoPE simply leaves angles for $n < \hat{n}$ as the original RoPE angles and applies the rescale for $n \ge \hat{n}$. The authors rely on two things to avoid problematic boundary artifacts: (1) the evolutionary search chooses $\hat{n}$ (and per-dimension $\lambda_i$) so that the chosen threshold avoids large harmful jumps for the model, and (2) empirically the model is robust to the resulting phase discontinuity — ablations and evaluation show no catastrophic attention artifacts at the boundary and overall perplexity / passkey retrieval performance improves.

Why a raw “jump” is not necessarily catastrophic (intuitive + technical explanation). RoPE encodes position by rotating pairs of embedding dimensions with angles proportional to $n$. Changing the scaling at $\hat{n}$ means that for a given dimension $i$ we switch from angle $n/\beta^i$ to $n/(\lambda_i \beta^i)$ at that index. That is equivalent to applying a different rotation mapping for tokens after the threshold. Two things weaken the impact of a discontinuity:

- Attention in RoPE depends on relative angular differences between token positions (inner products of rotated vectors). For two tokens both on the same side of the threshold the relative-phase structure is consistent with the chosen scaling; only cross-boundary pairs see mixed scalings. Thus the discontinuity affects a subset of pairwise interactions rather than globally corrupting the whole attention matrix.

- The tokens near the start of the sequence (small $n$) are the ones the paper explicitly chooses to preserve (they tend to attract large attention and are therefore kept unmodified). The search encourages $\hat{n}$ to cover those important tokens, so the positions that are most heavily attended do not experience a scaling-induced phase misalignment. In other words, the threshold is placed to protect high-attention tokens from a changed encoding.

Why the authors do not add an additive phase shift. An additive phase shift could in principle be used to enforce continuity at the boundary, but the paper does not adopt that approach. Instead they treat $\hat{n}$ and the per-dimension $\lambda_i$ as search hyperparameters and let the perplexity-guided evolutionary search find combinations that minimize loss on long-context samples. This search implicitly avoids combinations that would create harmful discontinuities (because those would raise perplexity and be discarded).

Empirical evidence in the paper. The paper’s ablations (Finding 2 and the token-position experiments) explicitly evaluate preserving the first $\hat{n}$ tokens and report consistent improvements (they swept $\hat{n}$ over values up to 256). They also show no perplexity spikes or attention failures around boundaries in their long-context evaluations (perplexity curves, passkey retrieval accuracy and other benchmarks). The method further uses monotonic constraints on $\lambda_i$ to avoid pathological per-dimension oscillations that could exacerbate boundary mismatch. Finally, the “shorter context recovery” step readjusts factors for small lengths if the extension harms short-window behavior, indicating they detect and correct performance regressions empirically rather than applying an analytic phase alignment.

When you might still see boundary artifacts and how to handle them. If you worry about local artifacts for a particular model or dataset, practical mitigations are straightforward: smooth the scaling across a small transition band instead of an abrupt step (gradually interpolate $\lambda$ for $n \in [\hat{n}-k, \hat{n}+k]$), include additive phase offsets as additional search parameters, or expand $\hat{n}$ to cover more tokens so the important tokens are on the unmodified side. The paper’s chosen route is to search for $\hat{n}$ (and $\lambda_i$) and report that this is sufficient in practice — no additive phase correction was used and no attention boundary artifacts were observed in their experiments.

Summary: No continuity correction (additive phase shift) is applied in LongRoPE. The potential jump at $n = \hat{n}$ is handled by (i) searching for an $\hat{n}$ that protects highly-attended initial tokens, (ii) searching per-dimension $\lambda_i$ under a monotonic constraint to avoid pathological changes, and (iii) empirical validation (perplexity / passkey / benchmark results) showing no harmful artifacts around the boundary. If needed, smoothing or searching for a phase offset are straightforward options, but were not necessary according to the paper’s results.

### Are the per-dimension scale factors \(\{\lambda_i\}\) shared across layers and heads, or learned separately?
Question:
RoPE is typically applied per head with head dimension \(d_{\text{head}}\), yielding \(d_{\text{head}}/2\) angles per head. When LongRoPE searches \(\{\lambda_i\}\), are these indices \(i\) defined within each head (so each head has its own \(\lambda_{i,\text{head}}\)), or globally shared across all heads and layers? If shared, how do you map \(i\) across heads when their positions in the concatenated embedding space differ? If per-head or per-layer specialization is not used, did you test whether allowing it would help?
Answer:
Short answer: In LongRoPE the rescale factors are learned per RoPE dimension and applied globally (shared) across all heads and layers. The paper searches for a set of scalars ${\{\lambda_i\}_{i=0}^{d/2-1}}$ indexed by the RoPE dimension $i$, not by head or layer.

Why: the paper formulates the search over the rotary-angle rescale for each RoPE dimension (see Eq. (3) / Eq. (problem) in the manuscript). The search space and monotonicity constraint are defined over $i=0,\dots,d/2-1$; the evolution search returns one $\lambda_i$ per dimension. Practically that means the same $\lambda_i$ is used wherever that RoPE dimension appears in the model — i.e., for every head and every layer the rotation angle that corresponds to RoPE-dimension $i$ is multiplied by the same factor.

How mapping works across heads: a head of size $d_{\text{head}}$ contains $d_{\text{head}}/2$ complex-dimension pairs (cos,sin) that correspond to contiguous indices in the model-wide RoPE dimension ordering. LongRoPE’s $\lambda_i$ are indexed according to that same RoPE-dimension ordering, so for a given head you apply the subsequence ${\{\lambda_{i}\}}$ that correspond to that head’s local dimensions. In other words, mapping is by intra-head dimension index relative to the global RoPE indexing, not by having distinct per-head tables.

Did they try per-head / per-layer specialization? The paper does not report experiments that search or learn separate $\lambda$ per head or per layer. The ablations focus on (a) non-uniformity across RoPE dimensions versus linear interpolation and (b) the token-position threshold $\hat n$. There is no experiment in the text showing head- or layer-specific $\lambda$ and no trained per-head/per-layer search is described.

Intuition / tradeoffs if you were to try per-head or per-layer factors: allowing separate $\lambda$ per head or per layer increases expressivity and might capture head- or layer-wise usage differences of positional information (some heads/layers focus on local high-frequency signals, others on long-range low-frequency signals). But it also explodes the search / optimization space (from $d/2$ scalars to roughly $\#\text{layers}\times\#\text{heads}\times d_{\text{head}}/2$ scalars), making the evolutionary search far more expensive and risking overfitting to the small validation set used for perplexity-guided search. That trade-off explains the paper’s design choice to search per-dimension globally: it leverages NTK-informed monotonicity and keeps the search tractable while already giving large wins (8$\times$ non-finetune and progressive extension to 2048k).

If you want to explore this direction experimentally, a practical route is to start small: (1) experiment with per-layer (but shared across heads) $\lambda$ vectors, or (2) cluster heads into a few groups and search one $\lambda$-vector per group. Both keep search complexity controllable while testing whether head/layer specialization yields meaningful gains.

### What does it mean that YaRN "doesn't reach the target context length" in non-fine-tuned settings?
Question:
In the analysis, you state that YaRN underperforms on PG19 and "doesn't reach the target context window length" for non-fine-tuned LLMs (e.g., perplexity spikes after 7k in an 8k context). What is the precise criterion for "reaching" the target length? Is it defined by a perplexity threshold, stability of loss, or something else? Could you formalize this notion so different methods can be compared consistently?
Answer:
Short answer: in the paper “doesn't reach the target context window length” means that when you apply YaRN’s RoPE rescaling without fine‑tuning and then evaluate language modeling performance as you increase evaluation sequence length up to the advertised target (e.g. $L'=8\text{k}$), the model’s perplexity stops behaving smoothly and instead exhibits a large, localized degradation (a “spike”) before the target length. In other words, the interpolation scheme fails to preserve useful positional encoding up to the target length. This is an empirical failure that can (and should) be made precise.

A formal, reproducible definition
Let $P(l)$ be the evaluated perplexity (or any scalar loss metric) computed for the model on sequences of length $l$ (the paper computes this with a sliding window; use the same evaluation protocol for all methods). Let $L$ be the original pretraining context and $L'$ the intended extended target length (e.g. $L'=8\text{k}$). I propose to declare that a method “reaches” $L'$ (without fine‑tuning) when it satisfies both of the following, which capture (a) no large degradation at or before $L'$ and (b) stability / absence of spikes:

1) Bounded relative degradation at $L'$:
   $$
   P(L') \le (1 + \tau)\cdot P_{\text{ref}}(L)
   $$
   where $P_{\text{ref}}(L)$ is a reference perplexity at the original (small) context length $L$ (or some baseline model value at $L$), and $\tau$ is a small tolerance (suggested default $\tau \in [0.05, 0.10]$ or 5–10% relative increase). This enforces that overall perplexity at the target length is not catastrophically worse than the baseline short‑context performance.

2) No local spike before $L'$:
   For every $l \in [L, L']$ consider a local window $W(l) = [l - w, l + w]$ (e.g. $w = 256$ tokens as used in the paper). Define the local spike ratio
   $$
   S(l) = \frac{P(l)}{\mathrm{median}_{x \in W(l)} P(x)}.
   $$
   Require
   $$
   \max_{l \in [L, L']} S(l) \le \alpha
   $$
   with $\alpha$ a modest threshold (suggested $\alpha \in [1.10, 1.25]$). This rules out sharp, localized increases of perplexity (the “spike after 7k” described in the paper).

You can equivalently express condition (2) with absolute differences $P(l) - \mathrm{median}_{W(l)} P(x) \le \delta$ (choose $\delta$ based on typical perplexity scale for your data) if you prefer absolute thresholds.

Why these two conditions
The paper’s observation about YaRN is a localized spike: perplexity is OK up to ~7k then suddenly increases near 8k. Condition (1) ensures the model’s performance at the target length is not broadly degraded; condition (2) catches the pathological behavior that motivated the paper’s phrase “doesn't reach the target context length.” Using both ensures we don’t call a method successful just because it has a reasonable average but with severe instability at specific lengths.

Practical evaluation protocol to compare methods
Use the same sliding-window perplexity evaluation (window size and step as in the paper). Compute $P(l)$ at a grid of $l \in \{L, L+\text{step}, \dots, L'\}$ and then evaluate the two conditions above. To make comparisons robust:

- Evaluate $P(l)$ over several held‑out samples (the paper uses multiple random PG19/Pile samples); report means $\pm$ standard error.
- Use bootstrap to test whether $P(L')$ is statistically indistinguishable (within $\tau$) from the baseline $P_{\text{ref}}(L)$.
- Report the maximum spike ratio $\max_l S(l)$ (or max absolute delta) so readers can see if the failure is global or local.
- Optionally report a slope / monotonicity measure: e.g. average derivative $\mathrm{d}P/\mathrm{d}l$ or fraction of steps where $P(l+\text{step}) - P(l) > 0$, to quantify smooth behaviour across lengths.

Alternative / complementary success criteria
Perplexity is the natural scalar used throughout the paper, but you can also use task‑level metrics that matter downstream: in the paper they use passkey retrieval accuracy and retrieval accuracy is arguably more interpretable for generation tasks. A method could “reach” $L'$ if it preserves a minimum task accuracy (e.g. $\ge 90\%$ of short‑context accuracy) up to $L'$. Using both language modelling (perplexity) and task metrics is advisable.

Suggested default thresholds (practical starting point)
- $\tau = 0.10$ (10% relative increase from short‑context perplexity)
- $\alpha = 1.15$ (local spike no more than 15% above local median in a $w = 256$ token window)
- Report results under these defaults and include sensitivity analysis (e.g., $\tau = 5\%$ and $20\%$) so conclusions are robust.

How this maps to the paper’s statement
When the paper says “YaRN … doesn’t reach the target context window length (e.g., perplexity spikes after 7k in an 8k context)”, that corresponds precisely to violation of condition (2): a pronounced local spike $S(l) \gg \alpha$ before $L'$, even if the average trend might look OK. Using the formal test above lets you quantify that behavior and compare YaRN, PI, NTK and LongRoPE in a consistent, reproducible way.

Summary
Make “reach” a two‑part test: (i) no large overall degradation at the target length (bounded relative perplexity increase), and (ii) no sharp local spikes before the target (bounded local spike ratio over a sliding window). Use the same sliding-window perplexity protocol and bootstrap/averaging over samples to compare methods consistently. These formal criteria capture precisely the empirical failure the paper points out for YaRN and allow fair, repeatable comparisons.

### Why allow \(\lambda_i\) up to \(1.25\,s\)? How does this ensure coverage of positions up to \(L'\)?
Question:
The search space for each \(\lambda_i\) is \([1.0,\,1.25\,s]\) with step 0.01, where \(s=L'/L\) is the target extension ratio. Intuitively, PI uses \(\lambda=s\) to map \([0, L')\) back into \([0,L)\). If \(\lambda_i > s\), then \(n=L'\) maps to \(L'/\lambda_i < L\), i.e., even stronger compression. What is the benefit of permitting \(\lambda_i > s\)? Conversely, if some \(\lambda_i < s\), that dimension effectively extrapolates beyond the original range—how do you ensure that collectively the representation remains faithful for positions up to \(L'\)?
Answer:
Short answer: allowing some $\lambda_i$ to exceed $s$ (up to $1.25\cdot s$) and allowing some $\lambda_i < s$ is deliberate: the algorithm is not trying to enforce a single “uniform” rescale that maps every extended position back exactly to its pretrained index. Instead it treats the rotary embedding as a multichannel encoder (many frequencies/dimensions) and searches a trade‑off across dimensions and token positions so that (i) some dimensions stay close to their pretrained angles (by using $\lambda_i \ge s$, i.e. stronger compression) to preserve the learned local structure, while (ii) other dimensions can extrapolate ($\lambda_i < s$) to keep separation among very distant positions. The search objective (perplexity on held‑out long sequences) plus the monotonicity and initial‑token exemption constraints finds a set of $\lambda_i$ that collectively preserve positional discriminability up to $L'$.

Why permit $\lambda_i > s$ (stronger compression than PI)? Intuitively, linear PI ($\lambda = s$) simply shrinks every rotary angle and “crowds” many positions into a small angular range, which destroys local distinctions in the high‑frequency dimensions. By allowing some $\lambda_i > s$, the search can compress particular (usually low‑frequency) dimensions even more, deliberately keeping other (usually higher‑frequency) dimensions closer to their pretrained regime. Those preserved dimensions act as anchors that retain the fine local ordering information the model relies on. In other words, extra compression in some dims gives the optimizer room to keep the most important dimensions near their original values instead of forcing every dimension to follow the same uniform shrink.

How can extrapolation ($\lambda_i < s$) not break coverage up to $L'$? RoPE encodes position with a vector of sin/cos across many frequencies; position identity is a joint pattern across dimensions, not any single scalar angle. If some dimensions extrapolate (angle larger than pretrained range) they increase the phase spread for far positions and help distinguish widely separated tokens. Meanwhile dimensions that are compressed keep their angles within the manifold the model was trained on, preventing catastrophic OOD behavior. The evolutionary search evaluates whole‑vector effects (by measuring perplexity on long sequences) so it only accepts $\lambda_i$ patterns that together let the model predict well up to $L'$. Empirically the paper shows this combined strategy preserves perplexity and retrieval performance up to the target length.

Two concrete mechanisms in the method make this robust: (1) the monotonic nondecreasing constraint $\lambda_i \le \lambda_{i+1}$, which enforces the NTK‑motivated structure that low‑level (high‑frequency) dims should be treated differently than low‑frequency dims, preventing pathological mixing of behaviours across frequencies; and (2) the token‑position exemption parameter $\hat{n}$, which leaves the earliest (most attended) tokens entirely unrescaled ($I(\dots)=1$ for $n < \hat{n}$), so critical beginning positions remain exactly in the pretrained manifold. For very large extensions the paper also uses a progressive fine‑tuning schedule (shorter fine‑tune windows first, then a second search on the fine‑tuned model) to further align the model to the selected non‑uniform rescale factors.

A short math check: for dimension $i$ the effective rotary angle used at position $n \ge \hat{n}$ becomes $(n/(\lambda_i \beta^i))$. For $n = L'$ (the far end), if $\lambda_i > s$ then $L'/(\lambda_i \beta^i) < L/(\beta^i)$ (compressed into the pretrained angular range); if $\lambda_i < s$ then $L'/(\lambda_i \beta^i) > L/(\beta^i)$ (extrapolated). The search does not insist every $i$ keeps $L'/(\lambda_i \beta^i)$ inside the original range; it searches for a pattern where the mixture of compressed and extrapolated angles across dimensions yields low perplexity.

In sum: permitting $\lambda_i > s$ expands the optimizer’s degrees of freedom so important frequencies can remain near their trained angles (preventing catastrophic shifts), while allowing some $\lambda_i < s$ provides extra phase spread to separate distant positions. The evolutionary search, together with the monotonicity and initial‑token constraints and the progressive fine‑tuning strategy, ensures the chosen $\lambda_i$ set collectively gives faithful positional representations up to $L'$ (validated by perplexity and retrieval experiments in the paper).

### How robust is the evolutionary search to overfitting on the small validation subsets used for perplexity?
Question:
For search, you evaluate perplexity on 5 PG19 samples (within 256k) or 3 Books3 samples (beyond 512k). Given the very large search space and many evaluations, how do you prevent overfitting the rescale factors to these specific texts? Did you validate that the chosen \(\{\lambda_i\}, \hat{n}\) generalize across domains and random seeds? Any evidence like train-vs-test perplexity gaps or re-running search on different subsets?
Answer:
Short answer: the paper acknowledges the small number of held-out examples used during the evolutionary fitness evaluations (5 PG19 samples for within-256k, 3 Books3 samples for >512k) but takes several explicit steps to reduce overfitting risk and then validates the found RoPE schedules broadly. The evidence in the paper for generalization is (a) design-time regularizers in the search that bias toward robust solutions, and (b) multiple independent evaluations on larger and different test sets and tasks (PG19 full test split, Proof‑pile, Books3, passkey retrieval, standard short-window benchmarks) that show the searched factors transfer well. The paper does not report multiple independent re-runs of the search on different small validation subsets (i.e., search-seed variance) or give numerical train-vs-test perplexity distributions, so reproducibility/variance remains an open empirical point.

What the paper does to avoid overfitting during search
- Seeding and structure in the search. The initial population explicitly includes PI, NTK and YaRN solutions (not purely random starts). This biases the evolutionary search toward known reasonable baselines, reducing the chance of converging to brittle solutions that only fit the 3–5 validation samples.
- Monotonicity constraint. The search enforces $\lambda_i \le \lambda_{i+1}$ (non-decreasing across RoPE dimensions). That reduces effective search degrees of freedom massively and encodes an NTK-inspired inductive bias (low-frequency dims can be scaled more than high-frequency dims). A smaller hypothesis class reduces overfitting risk.
- Limited and well-chosen discrete choices. $\hat{n}$ is searched over a small discrete set (0,1,2,4,...,256) and $\lambda_i$ is constrained to a bounded grid ($1.0\ \ldots\ s\times 1.25$, step $0.01$). Combined with the monotonicity constraint, the search is much more regularized than an unconstrained per-dimension continuous optimization.
- Population-level evolutionary mechanics. Using top‑k parents, mutation/crossover probabilities, and constrained mutation/crossover (only monotone children are evaluated) helps the search settle on robust families rather than overfitting to idiosyncratic samples.

How the paper validates generalization
- Larger/different held-out evaluations. Although fitness was computed on 5 or 3 samples during search, the chosen rescale factors are evaluated extensively afterwards: the full PG19 test split (100 documents) and Proof‑pile (10 long samples) for within‑256k experiments, 20 Books3 books (each >2M tokens) for the 2048k evaluation, and sliding-window perplexity across many contexts. These evaluations show consistent perplexity gains vs PI/NTK/YaRN across datasets and across evaluation lengths (Tables referenced in the paper).
- Task-level generalization. Beyond next-token perplexity, the paper reports passkey retrieval accuracy (10 iterations with passkeys at random positions uniformly across the evaluation window) and performance on standard short‑context benchmarks (ARC, HellaSwag, MMLU, TruthfulQA). LongRoPE models maintain high passkey retrieval up to million‑scale contexts and comparable short-window benchmark performance, suggesting the searched RoPE schedules are not narrowly overfit to the small validation snippets.
- Ablations that support robustness. The ablation section shows (i) searching per-RoPE-dimension yields clear gains vs PI, (ii) incorporating token-position non-uniformity helps at shorter extended lengths, (iii) the second search (on the fine-tuned 256k model) is effective, and (iv) readjusting rescale factors for short context lengths recovers short-window performance. These experiments indicate the improvements stem from systematic structure (dimension/position non-uniformity) rather than overfitting to a tiny fitness set.

What the paper does not (explicitly) provide
- No reported repeated independent searches on different small validation subsets or multiple random seeds to quantify variance of the found $\{\lambda_i\}$, $\hat{n}$. The methods section gives the search hyperparameters (population, iterations, mutation rates) and the validation sample sizes, but it does not give a distribution over final individuals across seeds/subsets.
- No explicit numeric “train-vs-test perplexity gap” table where the small fitness-set perplexity is compared to large-test-set perplexity for the final solutions. The generalization claim is supported indirectly by the downstream evaluations noted above rather than direct train/test gap statistics.

Practical interpretation and recommendations
The paper’s combination of inductive biases in the search (seeded initialization, monotonicity, bounded discrete choices) plus the breadth of downstream evaluations is reasonably strong empirical evidence that the discovered schedules generalize beyond the tiny fitness pool. However, because the evolutionary fitness used very few long examples, it is still possible that some subtle overfitting could occur for certain models or datasets. If you need stronger guarantees in your own experiments, re-running the evolutionary search multiple times with different random seeds and with different small validation subsets (and reporting variance of perplexity on a larger held-out set) is the recommended, low-cost extension. Another practical idea that follows the paper’s spirit is to use the PI/NTK/YaRN seeds plus the monotonicity constraint (as they did) and then select the best individual by evaluating on a slightly larger held-out pool (e.g., 20 long snippets) before committing to fine-tuning or deployment.

Summary
The paper defends against overfitting mainly by constraining and seeding the search and then validating the final schedules broadly across multiple large test sets and tasks (perplexity on PG19/Proof‑pile/Books3, passkey retrieval, and short-window benchmarks). It does not report repeated independent-search variance or explicit train-vs-test gap numbers for the small fitness sets, so if you are concerned about search instability you should re-run the search over multiple seeds/subsets and report the variance as a follow-up.

### Why does keeping the first \(\hat{n}\) tokens un-interpolated help, and how should \(\hat{n}\) scale with \(L'\)?
Question:
The paper reports that preserving the first \(\hat{n}\) tokens without interpolation improves perplexity and that the optimal \(\hat{n}\) depends on the target length. Can you provide intuition or a simple model for how attention distributions make early tokens especially sensitive to interpolation? Also, is there a principled way to choose \(\hat{n}\) as a function of \(L'\) (e.g., proportional to \(\log L'\), a fixed count, or learned via search)?
Answer:
Short answer: keeping the first $\hat n$ tokens un‑interpolated helps because those early tokens tend to receive large attention mass and so small changes to their RoPE phases produce disproportionately large changes to the attention logits (and hence loss). A principled way to pick $\hat n$ is to measure the model’s actual attention footprint on short-context examples and choose $\hat n$ so that the preserved prefix captures a chosen fraction of attention mass (or equivalently tune $\hat n$ on a small held‑out perplexity set). In practice $\hat n$ grows slowly with the target length $L'$ (sublinear — often a fixed small count or slowly increasing like $\log L'$ works), which matches the paper’s empirical choice to search $\hat n$ in a small set up to 256.

Why early tokens are especially sensitive (intuitive + simple model)
RoPE changes token-wise phase/rotation angles that affect the inner products between query and key vectors. Attention logits are proportional to these inner products; for a fixed query, the logit for position $n$ depends on the relative RoPE phase between the query position and position $n$. If you interpolate (rescale) the rotation angles for positions $n\ge\hat n$, you change those phases. When a token has a large attention weight, perturbing its logit by $\delta$ produces a large change in the softmax distribution and thus a large change in loss. So perturbing the phases of tokens with high attention is more harmful than perturbing phases of tokens with near-zero attention.

A minimal analytical sketch to make this concrete. Suppose a query attends over a prefix of tokens with baseline (pre-interpolation) logits $z_n$ and attention weights $a_n=\exp(z_n)/\sum_m \exp(z_m)$. After interpolation the logit for position $n$ shifts by $\Delta z_n$ determined by the phase change; for small $\Delta z_n$ the change in attention mass on position $n$ is approximately
$$
\Delta a_n \approx a_n (1-a_n)\,\Delta z_n \approx a_n\,\Delta z_n
$$
when $a_n$ is small-medium. So the contribution of position $n$ to the change in downstream loss scales roughly with $a_n\Delta z_n$. Two consequences follow: (1) positions with large $a_n$ amplify even small $\Delta z_n$; (2) reducing $\Delta z_n$ (i.e., not interpolating those positions) is the most effective way to keep loss small. This is exactly what keeping the first $\hat n$ tokens un‑interpolated does: it sets $\Delta z_n=0$ for the tokens that the model tends to attend to most.

Why early tokens get large attention
Empirically (and argued in the paper and related works like Streaming LLM, LM-Infinite), many attention patterns place relatively large mass on a local prefix or early context (e.g., headers, prompts, beginning of dialogue turns, function boundaries). Also common attention kernels (decaying with distance or focusing on local context) concentrate mass near the start of a block. So the “important” tokens are not uniformly spread over a million tokens; they are concentrated early, making them worth preserving exactly.

How $\hat n$ should scale with target length $L'$
There are two competing effects as $L'$ grows. On one hand, more overall positions means more interpolation is needed and the model may benefit from protecting a larger initial chunk. On the other hand, attention mass is usually concentrated in a local window that does not grow linearly with $L'$. Therefore $\hat n$ typically increases slowly with $L'$ (sublinear). The paper’s empirical behavior and choices support this:

- The authors search $\hat n$ from a small discrete set $\{0,1,2,4,8,12,16,20,24,28,32,64,128,256\}$ and find that preserving a modest number of initial tokens improves perplexity and that the optimal $\hat n$ depends on target length. They do not pick values that scale linearly with $L'$.
- Practical recommendations consistent with the paper: use a fixed small count (e.g., tens to a few hundreds) or a slowly growing rule, not $O(L')$.

A principled, simple heuristic you can use (grounded in the paper’s approach)
Compute an empirical average attention distribution from the pre-trained model on representative short-context examples (same domain you will evaluate on). For each position index $n$ compute the mean attention mass that the model assigns to positions with index < $n$. Pick $\hat n$ as the smallest $n$ such that the cumulative attention mass up to $n$ exceeds a threshold $\alpha$ (common choices $\alpha=0.6$–$0.9$). This gives a data-driven $\hat n$ that directly targets preserving the tokens that carry most attention. This is principled because, as the small-model sensitivity analysis above shows, positions with the bulk of attention produce the largest loss when their phases are perturbed.

Practical alternative: cheap validation search
The paper uses an evolutionary search over a small candidate set for $\hat n$ together with per-dimension $\lambda_i$. If you want a simpler workflow, fix a reasonable candidate list (the same as the paper’s discrete set up to 256) and evaluate perplexity on a small held‑out set for each candidate. This is cheap (inference only) and was the method used in the paper to pick $\hat n$.

Concrete summary guidance
If you want a short recipe, do one of these:

1. Data-driven attention heuristic: compute mean attention mass and choose $\hat n$ where cumulative mass ≥ 0.7. This is principled and often yields $\hat n$ in the tens–low hundreds.
2. Lightweight grid/search: evaluate perplexity with $\hat n\in\{0,1,2,4,8,16,32,64,128,256\}$ and pick the best; this is what the paper does and is cheap.
3. Rule of thumb: pick a small fixed $\hat n$ (e.g., 32–128) for many tasks. Increase it modestly for much larger $L'$, but avoid scaling $\hat n$ linearly with $L'$.

All three recommendations are consistent with the paper’s empirical findings: preserving a relatively small initial chunk reduces interpolation-induced degradation, and the optimal $\hat n$ depends on target length but grows slowly (and is best found with a small search or attention-based measurement).

### How do you compute perplexity for very long contexts during search without prohibitive cost?
Question:
Evaluating perplexity at lengths like 256k or higher can be extremely expensive if done naively due to quadratic attention in the prefill. What practical steps did you take during search to keep evaluation tractable? For example:
- Do you use a sliding window and cache K/V across windows?
- Any approximations, chunked attention, or reduced precision?
- Typical wall-clock time and GPU memory for one fitness evaluation at 256k and at 2M tokens?
Answer:
Short answer: the paper avoids doing full quadratic prefill over millions of tokens by (a) evaluating perplexity on a few long samples with sliding / chunked windows (so each model eval only handles manageable window sizes), (b) drastically reducing the number of candidate evaluations via search-level optimizations (seeded initials, monotonicity constraint, smaller populations for very large targets), and (c) trading off sample count / population size when the target length grows. The paper does not claim any special KV-cache across windows or exotic approximate attention; it keeps search/evaluation tractable by engineering the search procedure and the evaluation protocol rather than changing attention internals.

Details and intuition drawn from the paper
- Sliding / chunked evaluation: when reporting perplexity at long lengths the authors use sliding windows rather than scoring an entire $2\text{M}$ sequence in a single forward pass. For most experiments they use a sliding window stride of $256$ tokens for computing perplexity (PG19 / Proof-pile evaluation). For the Books3 $2\text{M}+$ evaluation they state using a sliding window of $256\text{k}$. The practical effect is that each forward pass only attends over a limited window (the window size), so you never have to do a single attention prefill over the whole mega-sequence in one shot. Intuitively: computing loss with a sliding window turns a single huge quadratic cost into many smaller quadratic costs that are each tractable and can be batched/streamed.

- Very small sample count per candidate: during search the perplexity used as the fitness is computed on a tiny set of long validation samples. For target lengths within $256\text{k}$ they compute perplexity on 5 random PG19 validation samples (each at least the target length). For windows $>512\text{k}$ they halve the search population and compute perplexity on only 3 random Books3 samples. Reducing the number of evaluation samples reduces wall-clock cost linearly while still giving a signal good enough for evolutionary search.

- Search-level pruning and seeding to avoid wasted expensive evaluations: the evolution search is designed to dramatically reduce the number of distinct RoPE candidates that need full perplexity evaluation. The initial population includes PI/NTK/YaRN candidates (so you start near reasonable solutions), and they enforce a monotonicity constraint on the per-dimension scale factors ($\lambda_i \le \lambda_{i+1}$). That constraint both aligns with NTK intuition and eliminates vast regions of the search space so far fewer full perplexity evaluations are needed. For very large target lengths they also reduce population / mutation sizes (halved for $>512\text{k}$), further limiting expensive evaluations.

- No special approximate or chunked attention algorithm is described: the paper does not claim to change the attention mechanism to a sub-quadratic or chunked-attention implementation for search. Likewise it does not report using an explicit KV cache across sliding windows in the search description. The approach is “keep model and attention unchanged, but evaluate loss over chunked windows + reduce number of evaluations.” In other words, they reuse standard autoregressive evaluation (with existing engineering optimizations available in model runtimes) rather than invent a new attention approximation.

- Precision / hardware choices are not detailed for search: the paper gives GPU counts and training settings for fine-tuning (e.g., A100s for $128\text{k}/256\text{k}$ fine-tune setups) but does not report special reduced-precision tricks or exact per-eval memory/time numbers for fitness computation. Therefore the paper does not supply exact wall-clock or memory numbers for a single fitness evaluation at $256\text{k}$ or $2\text{M}$ tokens.

What the paper explicitly reports (so you can rely on it)
- For search of target $\le 256\text{k}$: population $P=64$, mutation/crossover sizes $16$, mutate probability $0.3$, iterations $T=40$, perplexity computed on 5 PG19 samples with minimum length = target length.
- For target $>512\text{k}$: they halve population and mutation/crossover sizes, and compute perplexity on 3 Pile-Books3 samples.
- Sliding window stride and window sizes used for evaluation: $stride=256$ for PG19/Proof-pile; Books3 evaluation uses sliding windows of $256\text{k}$.

Practical takeaways / recommendations (consistent with the paper)
If you need to reproduce a similar search without prohibitive cost, chunk your evaluation into windows, evaluate on a tiny number of representative long samples, and aggressively reduce the number of candidate evaluations by seeding & constraining the search space. If you must reduce per-eval runtime further, you can layer additional engineering (KV caching across adjacent windows, $fp16$ / $bf16$ inference, or approximate attention) — but those are not part of the LongRoPE paper itself, and would be orthogonal optimizations.

Caveat about timing/memory: the paper does not provide per-evaluation wall-clock or GPU memory figures for $256\text{k}$ or $2\text{M}$-token fitness evaluations, so I cannot give exact numbers from the paper. The concrete cost you observe will depend on model size, attention implementation, batch size and whether you apply $fp16$/$bf16$ and KV caching in your runtime.

### Does LongRoPE adjust the RoPE base \(\theta\) (e.g., 10000), and could base changes be equivalent to certain \(\lambda_i\) schedules?
Question:
Standard RoPE uses \(\theta=10000\), which induces \(\beta=\theta^{2/d}\) and angles \(\frac{n}{\beta^i}\). LongRoPE rescales via \(\{\lambda_i\}\). If one instead changed \(\theta\) (globally or per-layer/head), would this be functionally equivalent to a particular pattern of \(\{\lambda_i\}\) for some ranges of \(n\)? Did you consider searching over base \(\theta\) or combining base changes with per-dimension \(\lambda_i\) for additional flexibility?
Answer:
Short answer: LongRoPE does not explicitly search or directly change the RoPE base value $\theta$ (the usual default $10000$). However, a global change of $\theta$ is mathematically equivalent to a very specific, structured pattern of per‑dimension rescale factors $\lambda_i$, and LongRoPE’s $\lambda_i$ search already can represent (and generalize) that pattern. The paper also mentions prior work that does tune the base (e.g., ScaledRoPE), but LongRoPE deliberately searches flexible per‑dimension (and per‑position) $\lambda_i$ because that gives strictly more expressive power and better empirical results.

Why (and how) they are related — intuitive and technical explanation
RoPE uses rotary angles of the form $n / \beta^i$ where $\beta = \theta^{2/d}$ and $i$ indexes the half‑dimensions. If you change $\theta \to \theta'$ then $\beta \to \beta' = \theta'^{2/d}$ and the new angle is

$n / \beta'^i = (n / \beta^i) \cdot (\beta^i / \beta'^i) = (n / \beta^i) \cdot (\beta / \beta')^i$.

So a global change of $\theta$ is exactly equivalent to multiplying the original angle in dimension $i$ by the factor $c^i$ where $c = \beta/\beta' = (\theta/\theta')^{2/d}$. In the LongRoPE notation (angles multiplied by $1/\lambda_i$ when $n \ge \hat{n}$), this corresponds to a geometric $\lambda_i$ schedule:

$\lambda_i = 1 / c^i = (\theta'/\theta)^{2i/d}$   (for the dimensions where you apply interpolation).

In words: a single change of $\theta$ maps to a deterministic geometric progression across $i$. That means a global $\theta$ change is a special case of the more general per‑dimension rescaling LongRoPE searches for.

Why LongRoPE searches $\lambda_i$ instead of (only) $\theta$
There are several practical and conceptual reasons (all consistent with the paper):

1. Expressivity: LongRoPE searches arbitrary (monotonic) $\lambda_i$ profiles and also allows keeping the first $\hat{n}$ tokens unscaled. That can represent a global $\theta$ change (the geometric case) but can also represent non‑geometric, piecewise, or flatter/steeper patterns that a single $\theta$ cannot.

2. Token‑position non‑uniformity: The paper emphasizes two non‑uniformities — across RoPE dimensions and across token positions. Changing $\theta$ only affects the frequency scaling across dimensions, not the decision to leave the first $\hat{n}$ tokens unmodified. LongRoPE explicitly models and searches that token threshold.

3. Per‑layer/head flexibility and constraints: A global $\theta$ is a single scalar for the whole model (or per‑layer/head if you choose), whereas LongRoPE’s search can be applied per layer/head if desired (the paper’s formulation is per‑dimension; in practice you could apply the search per layer/head). The evolutionary search and the monotonic constraint favor flexible but smooth $\lambda_i$ profiles that empirically perform better than naive uniform or single‑$\theta$ recipes.

4. Prior art and empirical experience: The Related Works section cites approaches that pick a very large base $\theta$ and then fine‑tune. LongRoPE takes a different path: rather than hand‑setting $\theta$, it searches for the best per‑dimension rescale factors to minimize perplexity for the target $L'$. Empirically (paper’s experiments) this search gives better initialization and enables larger extension (up to $8\times$ without fine‑tuning and, via progressive fine‑tuning, to 2048k).

Practical implications and how you could combine them
Because a $\theta$ change is a special geometric $\lambda_i$, you can:

- Recover an equivalent $\theta'$ from a found $\lambda_i$ if $\lambda_i$ fits a geometric form: fit $c$ from $\lambda_i \approx (1/c)^i$ and set $\theta' = \theta \cdot c^{-d/2}$. This is mostly a diagnostic: if your searched $\lambda_i$ are very close to geometric, a global base change would capture most of the behavior.

- Parameterize the search in lower dimension: if you prefer to search a single scalar, you can search $\theta'$ (or equivalently $c$) directly; this is a much smaller search but also much less flexible.

- Combine approaches: nothing prevents you from (a) picking a new base $\theta'$ as a coarse change and then searching residual per‑dimension $\lambda_i$ around the geometric pattern. But since LongRoPE already searches $\lambda_i$ in a wide allowed range (and with monotonicity), that combination is redundant in most cases; the paper’s empirical results suggest that direct $\lambda_i$ search performs well without separately tuning $\theta$.

Summary
A global change of $\theta$ is mathematically equivalent to a geometric per‑dimension $\lambda_i$ schedule, so LongRoPE’s per‑dimension $\lambda_i$ search subsumes that possibility. The authors did not report searching $\theta$ itself; instead they search flexible $\lambda_i$ (and a token threshold $\hat{n}$) because that lets them (i) represent the geometric/base‑change case and (ii) find many non‑geometric patterns that give better performance for extremely large context extensions. If you want a lighter search, you can search $\theta'$ (or a per‑layer $\theta'$)—but expect less flexibility than the full $\lambda_i$ search used in LongRoPE.

### How are different \(\{\lambda_i\}\) sets selected at inference time for short vs long sequences?
Question:
For short-context recovery, you search separate rescale factors for 4k/8k and dynamically switch if the sequence length is less than 8k. Implementation-wise, does the model carry multiple RoPE configurations and pick one based on the current sequence length? If a sequence grows from 6k to 10k during generation, do you switch RoPE mid-generation? If so, how do you avoid distribution shift or discontinuities when the factors change?
Answer:
Short answer: Yes — LongRoPE pre-computes (searches) separate RoPE rescale configurations for different target lengths (e.g. the “long” config used for 2048k and a “short” config for 4k/8k) and selects which rescale factors to apply at inference time based on the current sequence length. If the length crosses the short/long threshold during generation, the model switches to the other set of rescale factors for subsequent position encodings. The paper does not re-encode previously cached keys/values; instead it relies on design choices in the search and the RoPE parameterization to avoid large distributional discontinuities.

Why this works (intuitively and technically)
- What is switched: LongRoPE stores different sets of per-dimension rescale factors $\lambda_i$ (and a token-position cutoff $\hat n$) discovered by evolutionary search for different target windows. During inference the implementation uses the set appropriate for the current sequence length (the paper says: “During inference, if the sequence length is less than 8k, we update RoPE with the searched rescale factors.”).
- When the switch happens: the switch is applied to how you compute rotary angles for new tokens (positions) from that point on. In autoregressive generation you typically keep cached keys/values computed with whatever RoPE mapping was used when those tokens were produced. LongRoPE therefore changes only how future tokens are encoded, not retroactively re-encoding past cached $K/V$.
- How they avoid big discontinuities: LongRoPE’s search explicitly preserves important structure to reduce distribution shift. Two design choices are especially relevant:
  1. The search includes a token-position threshold $\hat n$ so that the first $\hat n$ tokens keep their original RoPE (no interpolation). Because initial tokens tend to receive high attention, keeping them unchanged reduces sensitivity to changes in rescale mapping.
  2. The searched $\lambda_i$ are smooth/monotonic across RoPE dimensions and are chosen to minimize perplexity on held-out long-context samples. That search objective favors rescale patterns that do not create catastrophic or highly discontinuous rotary angles when switching regimes.
These choices make the effect of swapping rescale sets ($\text{short}\leftrightarrow\text{long}$) on attention scores and model activations much smaller in practice than a naive abrupt remapping would be.

Caveats and practical recommendations
- Distribution shift still exists in principle: switching the mapping mid-run means some keys/queries were encoded under one RoPE mapping and later queries/keys use another mapping. The paper mitigates this by preserving early-token RoPE, using monotonic/smooth $\lambda_i$, and explicitly searching for “short-recovery” rescale factors to restore performance in the small-window regime. They do not claim a mathematically exact continuity guarantee, but empirically the chosen strategy gives small degradation (see the short-context recovery experiments).
- If you are engineering an inference system and want to be conservative, you can avoid any mid-generation mismatch by committing to the configuration corresponding to the maximum length you will encounter (i.e., use long mapping from the start). That trades a bit of short-window performance for avoiding mixed encodings. Alternatively, you can implement a smooth transition (interpolate $\lambda_i$ across a small window) to reduce abrupt changes, though the paper itself uses discrete searched configs and relies on the empirical robustness described above.

Conclusion
LongRoPE does carry multiple RoPE configurations (searched rescale-factor sets) and selects among them based on sequence length at inference. It may switch mid-generation when the sequence crosses the threshold; the paper avoids catastrophic discontinuities by (a) leaving the first $\hat n$ tokens’ RoPE unchanged, (b) enforcing smooth/monotonic dimension-wise rescale factors, and (c) explicitly searching for short-length recovery factors so the model remains well-behaved when operating in short-window regimes.

### What exactly are the "catastrophic values" introduced by new positions, and how does interpolation prevent them?
Question:
The introduction mentions that untrained new position indices introduce many catastrophic values, making fine-tuning hard to converge. Can you spell out what these catastrophic values are at the level of attention logits or hidden states? For example, do large angles cause destructive interference in QK dot products or numerical overflow/underflow in \(\sin/\cos\) at big \(n\)? How does your non-uniform interpolation specifically mitigate these failure modes?
Answer:
Short answer: the “catastrophic values” are not numeric overflows of sine/cosine but out-of-distribution positional phases that break the geometry the model was trained on, causing attention logits and hidden-state interactions to behave unpredictably (attention becomes “crowded” or dispersed, logits spike or lose discriminability), which makes fine‑tuning hard to converge. LongRoPE’s non‑uniform interpolation reduces this by selectively preserving the RoPE dimensions and early token positions that are most informative, so the $Q\cdot K$ geometry stays closer to the pretrained regime and attention weights remain well‑behaved.

Why they’re “catastrophic” (intuitive + technical sketch)
- RoPE encodes position $n$ in each paired dimension as $\cos(n\theta_i), \sin(n\theta_i)$. That is equivalent to rotating query/key components by an angle proportional to $n\theta_i$, so relative phases between positions control the $Q\cdot K$ dot products that produce attention logits. If you suddenly introduce many new positions $n \gg L$ (where $L$ was the trained max), you produce rotation angles $n\theta_i$ far outside the range the model saw during pretraining. Although $\sin$ and $\cos$ are numerically bounded (no overflow/underflow), the resulting phases are out-of-distribution.
- In practice those out-of-distribution phases produce two harmful effects in attention/logits:
  1. Crowding / loss of discriminability: after naive downscaling (e.g., linear PI) many different positions map to similar effective angles, so $Q\cdot K$ between different positions becomes similar. Attention weights flatten or mis-assign mass across many tokens—models can no longer tell “nearby” positions apart. Formally, if rotations make $q_n, k_m$ have similar phase alignment for many $(n,m)$, then $q_n\cdot k_m$ values lose the position-dependent structure the model learned.
  2. Unpredictable destructive interference / distribution shift: changing phases non-uniformly across RoPE dimensions alters the relative contributions of dimensions to dot products. Some dimensions that carried useful high-frequency position cues may be suppressed (large rescale), causing certain hidden directions to cancel or amplify unexpectedly. This shifts activation distributions of attention logits and downstream hidden states, hurting optimization and making fine-tuning unstable or slow to converge.
- So “catastrophic values” refers to attention logits and hidden activations being moved far from the pretrained distribution (not to arithmetic overflow).

How LongRoPE’s non‑uniform interpolation mitigates these failure modes
- Preserve informative (high-frequency) dimensions: LongRoPE searches per‑dimension rescale factors $\lambda_i$ (with monotonic constraint $\lambda_i \le \lambda_{i+1}$) so that low-index RoPE dimensions (high-frequency) receive less downscaling. This preserves the fine-grained phase differences those dimensions encode, keeping $q\cdot k$ phase patterns similar to pretraining and preventing the crowding/loss-of-discriminability effect.
- Preserve early token positions: LongRoPE allows the first $\hat{n}$ tokens to remain unscaled (no interpolation). Empirically those initial tokens receive large attention and are especially sensitive; leaving them unchanged prevents their attention contributions from being corrupted, reducing catastrophic changes to logits and hidden states.
- Targeted, not uniform, change: by searching a non‑uniform $\lambda_i$ schedule (instead of a single global $\lambda = s$), LongRoPE avoids uniformly collapsing or excessively stretching all phase scales. This keeps the overall $Q\cdot K$ geometry closer to the training-time manifold, so attention weight distributions and downstream activations stay in a regime the model can adapt from quickly (hence fewer fine‑tuning steps and better converged models).
- Progressive/second-stage search: when pushing to extreme lengths (e.g., $2048k$), LongRoPE first finds a good non‑uniform rescale for an intermediate target ($256k$) and fine-tunes, then searches again from that fine‑tuned checkpoint. This reduces the abruptness of phase shifts the model must absorb during optimization, avoiding the large distribution jump that causes catastrophic behavior.

Concretely, in terms of attention logits $q_n\cdot k_m$: RoPE effectively multiplies the rotated components so the dot product depends on differences of angles like $(n\theta_i - m\theta_i)$ after scaling. If scaling makes these differences collapse or scramble across many $(n,m)$, the matrix $[q_n\cdot k_m]$ loses the positional structure the transformer expects. LongRoPE’s per‑dimension $\lambda_i$ and preserved initial positions keep those angle differences informative where it matters, so the attention matrix retains useful structure and the model can continue to produce sensible logits and hidden states.

Bottom line: the problem is distributional (phase/geometry) damage to attention and hidden representations produced by naive interpolation, not arithmetic overflow. Non‑uniform, dimension‑ and position‑aware rescaling keeps the phase geometry close to the pretrained regime, preventing the “catastrophic” disruption of attention logits and enabling stable, efficient fine‑tuning.

### How does LongRoPE mitigate attention dispersion at extreme lengths without changing the attention mechanism?
Question:
One challenge is that attention becomes dispersed as \(L'\) grows, hurting short-context performance. LongRoPE claims to preserve important positional information via non-uniform interpolation. Can you provide intuition or quantitative evidence (e.g., attention heatmaps or entropy) that shows reduced dispersion compared to PI/NTK/YaRN? Since you do not modify masks or sparsity, how exactly does adjusting \(\{\lambda_i\}\) counteract dispersion?
Answer:
Short answer: LongRoPE reduces “attention dispersion” by changing only the positional encodings (the RoPE rotation angles) in a way that preserves the phase differences that the model relied on during pretraining — not by changing attention weights or masks. Practically this is done by (a) using different rescale factors $\lambda_i$ per RoPE dimension and (b) leaving the earliest token positions un-rescaled. Both choices keep the position-induced phases for important frequency channels and important tokens from being crushed together by uniform downscaling, so the dot-product attention still produces sharp, discriminatory scores instead of “spreading” across many positions.

Why this works (intuitive + technical): RoPE encodes position by rotating components of query/key vectors by angles proportional to $n\theta_i$ (Eq. 1 in the paper). Attention between tokens depends on inner products of queries and keys, which in turn depend on relative phase differences created by those rotations. If you uniformly scale all rotation angles by $1/s$ (PI), many different positions map to much closer phases — nearby positions become nearly indistinguishable in the rotary-phase space, so query-key inner products become less peaked and attention “disperses.” LongRoPE breaks that harmful uniformity in two ways that preserve discriminative phase information:

1) Per-dimension (frequency) non-uniform scaling $\lambda_i$. Lower-index RoPE dimensions correspond to higher-frequency rotations (they encode fine-grained positional differences). By keeping $\lambda_i$ smaller for those dimensions (less interpolation / more extrapolation) and allowing larger $\lambda_i$ for lower-frequency channels, LongRoPE preserves the phase differences on the channels that matter most for distinguishing nearby tokens. In other words, the model’s fine-grained positional cues survive, so attention remains localized where needed.

2) Token-position threshold $\hat n$ (no-rescale for initial positions). Early tokens often receive large attention mass and are particularly important for maintaining short-context performance. By leaving positions $n < \hat n$ un-rescaled (i.e., using the original angles for those tokens), LongRoPE preserves the exact pretraining phase relationships for the tokens that most strongly influence attention. That prevents those key tokens from being “moved” into crowded phases and keeps their attention contributions sharp.

A compact mathematical view: RoPE applies rotations with angle proportional to $n/\beta^i$. LongRoPE applies instead $\cos\!\left(\frac{1}{\lambda_i}\cdot \frac{n}{\beta^i}\right)$ and $\sin\!\left(\frac{1}{\lambda_i}\cdot \frac{n}{\beta^i}\right)$ for $n \ge \hat n$ (and keeps original $n/\beta^i$ for $n < \hat n$). By choosing $\lambda_i$ as a non-decreasing sequence across $i$ (in practice found by the evolutionary search), the high-frequency channels keep their angular spacing (small $\lambda_i$), while low-frequency channels can be compressed more without losing close-position discrimination. Since attention scores are inner products of Q,K that inherit these rotated phases, preserving phase differences on the right channels keeps attention peaks from flattening.

Quantitative / empirical evidence in the paper (what to look at):
- The paper shows that LongRoPE can extend $4\mathrm{k}\rightarrow32\mathrm{k}$ without fine-tuning while PI / NTK / YaRN suffer sharp perplexity increases after small extensions (see Fig. 3 / Fig.\ref{fig:non-ft} and Table~\ref{tbl:exp1}). This is a direct proxy for reduced dispersion: low perplexity means the model is still effectively using relevant context rather than getting “diffuse” signals.
- Ablations in Section 2.2: Table~\ref{tbl:exp1} reports substantial perplexity improvements when searching per-dimension $\lambda_i$ vs PI/NTK/YaRN, demonstrating that per-dimension non-uniformity reduces information loss (i.e., mitigates dispersion). Table~\ref{tbl:tokenposition} shows that leaving a small number of starting tokens un-interpolated improves performance at $8\mathrm{k}\!-\!16\mathrm{k}$, confirming the token-position non-uniformity point.
- The passkey retrieval experiment (Fig.~\ref{fig:passkey}) is a behavioural test of “can the model focus on one small piece of information inside a huge context?” LongRoPE maintains high retrieval accuracy ($\ge 90\%$ up to $2048\mathrm{k}$ for the LLaMA2 variant) while other methods drop to zero well before that. That is strong, task-level evidence that attention is not smeared across millions of tokens.
- Fine-tuning + second search: The progressive strategy (search → fine-tune at $128\mathrm{k}/256\mathrm{k}$ → re-search) keeps perplexity low even at $2048\mathrm{k}$ (Table~\ref{tbl:books3}), again indicating the model still concentrates relevant attention despite the massive extension.

About attention heatmaps / entropy: the paper does not present direct attention-entropy or attention-heatmap plots, but perplexity curves, targeted ablations (dimension-wise and position-wise search), and downstream retrieval accuracy together serve as quantitative evidence that LongRoPE reduces the harmful dispersion effect. Perplexity and passkey retrieval are sensitive to whether attention remains informative and focused; their improvements imply that the attention distribution is effectively less dispersed after LongRoPE’s interpolation.

Why this doesn’t require changing masks or sparsity: dispersion is fundamentally caused by destroying the phase differences that RoPE originally created. You can either change the attention mechanism to cope (sparsity, masks, different attention kernels) or you can restore useful positional structure so the original dot-product attention still works. LongRoPE takes the latter route: by re-scaling rotations in a non-uniform, structure-preserving way, it keeps the original attention computation valid and effective, so no mask/architecture changes are needed. The monotonicity constraint on $\lambda_i$ (and the evolutionary search that seeds with PI/NTK/YaRN) finds rescalings that preserve the model’s learned inductive biases while enabling huge extension ratios.

Short summary: adjusting $\{\lambda_i\}$ and optionally protecting the first $\hat n$ positions counteracts attention dispersion by preserving the phase differences that produce peaked query-key inner products. The paper’s ablations (per-dimension search and initial-token preservation), perplexity trends (Fig.\ref{fig:non-ft}, Table~\ref{tbl:exp1}, Table~\ref{tbl:books3}), and passkey retrieval results (Fig.~\ref{fig:passkey}) provide quantitative support that LongRoPE keeps attention focused better than PI/NTK/YaRN without modifying the attention mechanism.

### Does the two-stage progressive strategy amount to composing two scalings, or is the second search done from scratch?
Question:
The method fine-tunes at 128k→256k with searched factors, then performs a second search on the 256k model to reach 2048k without further fine-tuning. Is the second stage initializing from the first stage's \(\{\lambda_i\}, \hat{n}\) and then refining, or does it search from scratch over the full space again? Mathematically, if the first stage applies \(\lambda_i^{(1)}\) and the second stage \(\lambda_i^{(2)}\), is the effective mapping equivalent to a single scaling by \(\lambda_i^{(1)}\,\lambda_i^{(2)}\), or do you replace the first set entirely?
Answer:
Short answer: the second stage searches anew on the fine‑tuned 256k model and replaces the previous rescale factors; it is not implemented as a simple multiplicative composition of two scalings.

Why: in the paper the progressive pipeline is (i) search for rescale factors for 128k and for 256k, (ii) fine‑tune the model while using the 128k factors for 400 steps then replacing with the 256k factors for another 600 steps, and (iii) after you obtain the fine‑tuned 256k model you “perform a secondary search on the fine‑tuned 256k‑length LLM” to get factors for 2048k and then apply those factors without further fine‑tuning. That wording and the method description make clear that the second search is performed on the state of the fine‑tuned model and returns a fresh set of per‑dimension rescale factors to be used for 2048k. In other words, the final RoPE used at inference is the result of the second search’s chosen $\lambda_i$ values (and $\hat{n}$) applied to the fine‑tuned model, not the product of the first-stage $\lambda_i^{(1)}$ and second-stage $\lambda_i^{(2)}$.

Intuition and a bit of math: LongRoPE defines the applied rotation as $\cos\!\left(I(\hat\lambda_i,\hat n)\cdot \frac{n}{\beta^i}\right)$ where $I(\cdot)$ is either $1$ for $n<\hat n$ or $1/\lambda_i$ for $n\ge\hat n$ (see Eq. (1)/(problem formulation)). When you fine‑tune to 256k you used a particular set of $\lambda_i$ (call them $\lambda_i^{(\mathrm{ft})}$) during training. The secondary search does not simply pick extra factors to multiply onto the already‑applied $\lambda_i^{(\mathrm{ft})}$. Rather it searches for new $\lambda_i$ (call them $\lambda_i^{(2048)}$) to be used directly in the RoPE formula at inference on the fine‑tuned model. So the final mapping used is $\cos\!\left(I(\hat\lambda_i^{(2048)},\hat n^{(2048)})\cdot \frac{n}{\beta^i}\right)$, not $\cos\!\left(I(\hat\lambda_i^{(\mathrm{ft})},\hat n^{(\mathrm{ft})})\cdot I(\hat\lambda_i^{(2048)},\hat n^{(2048)})\cdot \frac{n}{\beta^i}\right)$. The second search is performed on the model weights that have been adapted under the 256k rescaling, but the rescale factors themselves are replaced by the newly searched ones for the 2048k run.

Why they do it this way: composing scalings multiplicatively would accumulate distortions of the rotary angles and is unlikely to be optimal. The paper argues (and empirically shows) that searching a new non‑uniform rescaling on the fine‑tuned model gives a better initialization for 2048k (and avoids the need to fine‑tune directly at 2048k). The second search therefore leverages the fine‑tuned model state while selecting a fresh set of per‑dimension $\lambda_i$ (and $\hat n$) tailored for the final large extension ratio, rather than naively multiplying earlier scalings.

### Why does LongRoPE achieve about \(8\times\) extension without fine-tuning—what breaks beyond that?
Question:
You report that the non-fine-tuned extension reliably works up to roughly \(8\times\) while PI/NTK/YaRN often break earlier. Is there a conceptual reason why \(\sim8\times\) is a practical limit (e.g., unavoidable aliasing across dimensions, loss of phase information, or compounding approximation error)? What symptoms appear first when pushing to, say, \(16\times\) without finetuning?
Answer:
Short answer: LongRoPE (and the paper’s empirical findings) show that non-fine-tuned extension reliably reaches roughly an $8\times$ increase because up to that point you can preserve the most informative parts of RoPE (certain dimensions and the early token positions) with a rescaling that does not catastrophically “crowd” position encodings. Beyond $\sim 8\times$ the implicit approximations in interpolation—loss of effective phase/frequency resolution in many RoPE dimensions, attention dispersion across an enormous number of positions, and cumulative mismatch to the model’s learned positional statistics—become large enough that perplexity and generation quality rapidly degrade. The paper documents these mechanisms and the concrete symptoms (perplexity spikes, passkey-retrieval failure, short-context degradation) that appear first when you push to, e.g., $16\times$ without fine‑tuning.

Why $\sim 8\times$ is a practical non-fine-tuned limit (intuitively and technically)
The RoPE embedding encodes position by rotating query/key subcomponents with angles $n\theta_i$ (Eq. 1 in the paper). Extending the context by naive scaling (PI) reduces those angles by a factor $\lambda$ so that new positions map back into the pretrained angular range. That helps avoid “unseen” catastrophic positions, but two related things break as $\lambda$ grows:

1) Crowding of phase/frequency information. If you scale all rotation angles by a large factor, many distinct positions map to very similar rotation phases in many RoPE dimensions, so the model loses the ability to discriminate nearby token indices. NTK-style non-uniform scaling spreads the pressure across dimensions (lower-frequency dims are scaled less), but that only helps so far. The paper’s search finds a multivariate non-uniform rescaling that preserves the most informative (usually low-index and certain low-dimension) angle structure; preserving those key dimensions/positions is what allows stable behavior up to about $8\times$ without any fine-tuning.

2) Attention dispersion and statistical mismatch. Transformers were trained with the original distribution of rotation angles and attention patterns. As you increase the effective context window, attention weights are now distributed over vastly more tokens and the positional statistics (angles, phase relationships across dimensions) deviate from training. These deviations accumulate and produce out-of-distribution behavior unless the model is fine‑tuned to adapt. The paper observes that keeping the first $\hat n$ tokens unscaled (no interpolation) helps because early tokens typically receive strong attention and need their original positional structure.

Why things break faster beyond $8\times$
The search-enabled, per-dimension non-uniform rescaling reduces information loss, but the search space and required “corrections” grow rapidly with target ratio $s$. For modest extensions (up to $\sim 8\times$) you can find $\lambda_i$ that preserve enough phase diversity across the most important dims and positions. For larger $s$:

- Many more dimensions must be altered (or pushed to extrapolation), which eventually removes the joint phase relationships the model relies on. The monotone constraint ($\lambda_i\le\lambda_{i+1}$) and evolution search mitigate but cannot fully recover the learned positional manifold for huge $s$.
- Attention becomes too “thin”: a single token’s influence must be spread across many more positions, reducing SNR for local dependencies.
- The mismatch is no longer a small approximation error but a structural distribution shift in positional encodings that the model never saw during pretraining.

Concrete first symptoms reported in the paper (what you see when you try $16\times$ non-fine-tuned)
The paper documents several observable failures when exceeding the safe non-finetuned zone:

- Perplexity spikes sharply. Existing methods (PI, NTK, YaRN) often show perplexity blow-ups after $2$–$4\times$; LongRoPE’s searched non-uniform factors hold a lot longer (up to about $8\times$). Beyond that, perplexity increases rapidly (see Fig. referenced in the paper).
- Passkey/retrieval accuracy drops. The passkey retrieval task (finding a five-digit key placed randomly in a long context) shows accuracy falling toward zero as context grows past the non-finetuned limit; LongRoPE keeps $\ge 90\%$ up to $2048k$ only because of progressive fine‑tuning steps—without fine‑tuning, accuracy would collapse well before.
- Loss of short-context performance (“crowding” in original range). Even if long-context metrics were tolerable, the model’s performance on original short-context benchmarks deteriorates because interpolation compresses the original positions into a narrower phase range; the paper addresses this by re-searching RoPE for short lengths.
- Local confusion: the model can no longer reliably distinguish nearby positions, producing mistakes in tasks that need fine positional resolution (ordering, retrieval of nearby items), and generative coherence drops for long-range dependencies.

How the paper addresses the limit
The authors exploit two ideas: (1) sophisticated, per-dimension and per-position non-uniform rescaling found by an evolutionary search, which preserves the most critical phase information and enables up to $\sim 8\times$ without fine‑tuning; and (2) a progressive strategy where they fine‑tune at an intermediate length (e.g., $256k$) and then re-search to reach $2048k$. Fine‑tuning is required once the extension ratio becomes large (e.g., $32\times$, $64\times$, $512\times$ cumulatively) because the interpolation alone cannot correct the structural distribution shift described above.

Takeaway
There is no single fundamental law that fixes the $8\times$ figure, but it emerges from the interaction of (a) the dimensional structure of RoPE (some dimensions are far more important), (b) the degree of phase crowding caused by uniform scaling, and (c) the model’s sensitivity to positional-distribution shifts learned during pretraining. LongRoPE’s non-uniform rescaling pushes the practical non-finetuned boundary to roughly $8\times$ by preserving key dimensions/positions; beyond that you must fine‑tune (or use the progressive fine‑tune + re-search pipeline the paper proposes) to avoid the early symptoms (perplexity spikes, retrieval failure, short-context degradation).

### What is the definition of "information entropy" of positional embeddings used to justify non-uniformity?
Question:
The paper mentions "complex non-uniform information entropy" in the Transformer regarding positional embeddings. How is this entropy quantified? Is it the entropy of attention distributions conditioned on positions, the spectrum of positional encoding across layers, or something else? Could you share the exact metric and empirical plots that motivated the per-dimension and per-position non-uniform treatment?
Answer:
Short answer: the paper does not define or measure a formal Shannon-style “information entropy” of positional embeddings. The phrase “complex non-uniform information entropy” is used as an intuitive description of observed heterogeneity across RoPE dimensions and token positions. The authors quantify and justify the non-uniform treatment empirically via search-guided rescale factors and downstream loss/metric improvements (perplexity and passkey-retrieval accuracy), not by publishing an explicit entropy formula or a direct entropy plot of embeddings/attention.

What the paper actually does
- The paper frames the problem as finding per-dimension rescale factors $\lambda_i$ and a per-position threshold $\hat{n}$ (Eq. 1 / Eq. problem formulation). Those factors are searched by an evolutionary procedure that is evaluated with language-model loss (perplexity) on held-out long-context samples. The objective in Eq. (problem) is to minimize $\mathcal{L}$ (next-token loss / perplexity) for documents that exceed the target length.
- Empirical evidence motivating non-uniformity is presented as improvements in perplexity and downstream tasks when allowing dimension-wise and position-wise non-uniform rescaling, versus uniform PI, NTK, or YaRN strategies. The paper cites tables and figures (e.g., Table 1/2 comparisons, Table tokenposition, Fig. non-ft, passkey retrieval plots) that show: (a) searched $\lambda_i$ profiles that are non-uniform across RoPE dimensions, (b) gains when preserving the first $\hat{n}$ tokens from interpolation, and (c) overall perplexity / retrieval accuracy improvements. These empirical plots / tables are the motivation in place of an explicit “entropy” metric.

What the phrase likely means intuitively
- RoPE encodes positions via multiple frequency-like dimensions (rotation angles $\frac{n}{\beta^i}$). Different dimensions carry different granularity/frequency of position information. The authors observe that the importance (or “information content”) of those dimensions is not uniform: some dimensions are more sensitive/critical for model performance after extension. Likewise, early token positions tend to be disproportionately important (they get high attention mass), so treating them differently reduces catastrophic behaviour when extending. Calling this heterogeneity “complex non-uniform information entropy” is a qualitative way to say “the information carried by positional channels and by token indices is uneven and structured,” not a claim that they computed Shannon entropies.

Where to find the empirical evidence in the paper
- The search formulation and application are in Section 3 (Problem formulation and Eq. (problem)). The search procedure and monotonicity constraint are in Section 3.2 and Algorithm 1.
- Finding 1–3 in Section 2.2 summarize the experimental findings: dimension-wise non-uniform $\lambda_i$ improves perplexity (Table references in the text), keeping early tokens un-interpolated helps (Table tokenposition), and the combined strategy enables non-finetuned $8\times$ extension and progressive finetuned extension to 2048k (Fig. non-ft, Tables in Section 4).
- Evaluation metrics used throughout are perplexity (primary) and passkey retrieval accuracy (generation task). The search objective itself is minimizing perplexity on sampled long sequences.

If you want a formal entropy-style analysis (not in the paper)
- The paper doesn’t supply such a metric, but sensible formal diagnostics you could compute to quantify “information heterogeneity” are: (1) per-dimension variance or spectral power of positional vectors across positions, (2) singular-value spectrum / effective rank of the matrix of positional embeddings (positions × RoPE-dimensions), (3) Shannon entropy of the attention distribution conditioned on position indices, $H(\text{attention}\mid\text{position})$, to see which positions concentrate attention, or (4) mutual information estimates between position index and hidden activations/attention, e.g. $I(\text{position};\text{activations})$. Any of these can make the qualitative claim precise and could be plotted alongside the searched $\lambda_i$ to show correlation between “information content” and the rescale schedule the search found.

Practical pointers to reproduce the paper’s motivation plots
- Re-run the evolutionary search (Section 3.2) and save the best-found $\lambda_i$ vector and $\hat{n}$. Plot $\lambda_i$ versus RoPE dimension index to see the non-uniform profile the authors report.
- Plot perplexity vs evaluation context length for baseline PI/NTK/YaRN and for the searched scheme (this is what the paper uses as the main empirical justification; see Fig. non-ft and Tables in Section 4).
- For per-position evidence, run the ablation where you keep the first $\hat{n}$ tokens un-interpolated and plot the change in perplexity as $\hat{n}$ varies (the paper reports this in the tokenposition ablation).

Summary
The paper’s “information entropy” phrase is a descriptive, not formal, claim. The authors justify per-dimension and per-position non-uniformity by direct empirical optimization of rescale factors and by reporting perplexity and retrieval gains (the searched $\lambda_i$ profiles and ablation tables/figures are the concrete evidence). If you want a rigorous entropy-style measure, it is not provided in the paper but can be added with the diagnostics I suggested and compared against the searched $\lambda_i$ to make the intuition explicit.

### Why do Mistral fine-tuning runs use 16k training length while targeting 128k/256k windows?
Question:
In the setup, for Mistral you follow YaRN and use 16k sequence length during fine-tuning while still calling the resulting models 128k/256k. How does this training length mismatch relate to the target context window? Is the idea that the searched RoPE provides the length generalization, with relatively short fine-tuning just anchoring the model? Any downsides observed (e.g., worse performance beyond 256k for Mistral compared to LLaMA2)?
Answer:
Short answer: the Mistral runs use $16\mathrm{k}$ training chunks as a pragmatic fine‑tuning setting (following YaRN) to save compute and because long training data are scarce, while relying on LongRoPE’s searched, non‑uniform RoPE to do most of the heavy lifting of length generalization. That combination—searched RoPE + relatively short fine‑tuning—gives a good tradeoff (fast fine‑tuning, reuses existing long‑data pipelines) but is not free: the paper reports that Mistral models fine‑tuned using $16\mathrm{k}$ chunks have more trouble beyond $\sim256\mathrm{k}$ than LLaMA2 models that were fine‑tuned on longer chunks (see Sec. 4.2 and the Books3 / passkey results).

Why $16\mathrm{k}$ instead of directly training at $128\mathrm{k}/256\mathrm{k}$
The paper explains two practical constraints: (1) long contiguous training segments ($128\mathrm{k}$–$256\mathrm{k}$) are scarce and (2) training on very long sequences is very expensive. For Mistral the authors followed YaRN’s fine‑tuning recipe ($16\mathrm{k}$ chunks, 400 steps on Together’s long‑data) because it fits available datasets and GPU budgets (Sec. 4.1, Fine‑tuning). Using shorter chunks greatly reduces memory/compute and allows a quicker fine‑tune checkpoint to be produced.

How this relates to the target window ($128\mathrm{k}/256\mathrm{k}/2048\mathrm{k}$)
LongRoPE is explicitly designed to separate two things: (A) find a better positional rescaling (non‑uniform RoPE) via search that preserves important dimensions/positions and therefore generalizes to much longer lengths without extensive training, and (B) use cheap progressive fine‑tuning at an intermediate length to anchor the model further. Concretely, LongRoPE first searches rescale factors for the target extended length (or an intermediate $128\mathrm{k}/256\mathrm{k}$ target) and then fine‑tunes. For Mistral the searched RoPE provides substantial length generalization (the search can give an $\sim8\times$ non‑finetune extension in many cases), and the $16\mathrm{k}$ fine‑tuning acts as a light anchor of model weights on longer‑length behavior (Sec. 3 and Sec. 3.3).

So yes: the searched RoPE supplies a lot of the length generalization and the relatively short fine‑tuning mostly “anchors” the model rather than fully training it at $128\mathrm{k}/256\mathrm{k}$ sequence lengths. That is exactly the progressive strategy the paper advocates: do search → fine‑tune at a manageable length (they used $128\mathrm{k}/256\mathrm{k}$ for LLaMA2, but Mistral used YaRN’s $16\mathrm{k}$ setting for the fine‑tune step) → optionally run a second search on the fine‑tuned checkpoint to push to much larger windows (Sec. 3.3).

Observed downsides / empirical effects
The paper reports concrete differences between LLaMA2 and Mistral that point to the limitations of the $16\mathrm{k}$ fine‑tuning choice. On Books3 and passkey tasks (Sec. 4.2): LongRoPE‑Mistral-$2048\mathrm{k}$ (ft=$128\mathrm{k}$ but trained with $16\mathrm{k}$ chunks per YaRN) performs well at shorter lengths but perplexity rises beyond $\sim256\mathrm{k}$ and passkey accuracy falls ($100\%$ to $60\%$ at $2048\mathrm{k}$). The authors attribute this partly to the use of $16\mathrm{k}$ training length during Mistral’s fine‑tuning: it reduces the fine‑tuning signal available for very large secondary extensions, so Mistral suffers more when the secondary extension ratio is large (Sec. 4.2, paragraph discussing Books3 and the final sentence: “The main reason is that for Mistral's $128\mathrm{k}$ and $256\mathrm{k}$ fine‑tuning, we follow YaRN’s setting to use a $16\mathrm{k}$ training length, which affects Mistral's ability to further extend context window after fine‑tuning.”). In contrast, LLaMA2 fine‑tuned with actual $128\mathrm{k}/256\mathrm{k}$ chunks shows steadier perplexity up to $2048\mathrm{k}$.

Intuition / broader concept
Positional interpolation (RoPE rescaling) is a way to remap new, unseen position indices back into the range the model was trained on. Search‑based, non‑uniform rescaling preserves high‑frequency (important) RoPE dimensions and the early token positions that tend to receive strong attention, so the model can generalize farther with less direct long‑sequence fine‑tuning. But interpolation alone cannot fully replace signal from real long sequences: very large extension ratios introduce many “new” positions and attention patterns that the model never observed, so some amount of true long‑sequence fine‑tuning (or progressive fine‑tuning at intermediate lengths) improves robustness. Using too short fine‑tuning chunks ($16\mathrm{k}$) is cheaper but may leave a residual ceiling on performance at the extreme end of the target window.

Practical takeaway
If you must conserve compute or lack long training data, using a searched non‑uniform RoPE plus short fine‑tuning (as in YaRN/LongRoPE) is a good strategy and often sufficient up to a few hundred kilotokens. If your goal is maximal robustness at multi‑hundred‑kilotoken or million‑token lengths, the paper’s experiments indicate it helps to fine‑tune with longer chunks (e.g., $128\mathrm{k}/256\mathrm{k}$) or use the progressive strategy (search → fine‑tune at $128\mathrm{k}/256\mathrm{k}$ → second search) described in LongRoPE to reduce the secondary extension ratio and avoid degradation beyond $\sim256\mathrm{k}$.

References in the paper: see Sec. 3 (search and progressive extension), Sec. 3.3 (progressive extension to $2048\mathrm{k}$), and Sec. 4.2 (Books3 and passkey results) for the empirical comparisons and the explicit note that Mistral’s $16\mathrm{k}$ fine‑tuning choice affects its large‑window performance.

### How do you ensure numerical stability of \(\sin\) and \(\cos\) at positions near 2M tokens?
Question:
With angles like \(\frac{n}{\lambda_i\,\beta^i}\) and \(n\) up to \(2{,}048{,}000\), do you encounter numerical issues in float16/float32 evaluation of \(\sin\) and \(\cos\)? For instance, precision loss for large arguments can be severe. Do you reduce angles modulo \(2\pi\) explicitly, use higher precision for angle computation, or employ stable rotary implementations to avoid catastrophic cancellation?
Answer:
The paper does not discuss numerical tricks for $ \sin/\cos $ explicitly, and it does not report numerical instability in their experiments up to the $2{,}048\text{k}$ evaluation length. That suggests they did not hit catastrophic failures in practice. That said, your concern is valid: evaluating $ \sin/\cos $ of very large raw arguments can cause precision loss in low-precision arithmetic if you naively compute $ \sin(n\cdot\theta) $ with $n$ up to millions.

Why the problem is less severe than it first appears here. In RoPE the rotary angle for dimension $i$ is not simply $n$, it is
$$
n\theta_i \quad\text{with}\quad \theta_i = \theta^{-2i/d}
$$
and in the paper’s unified notation the effective per-dimension angle is $n / \beta^{i}$ (with further rescaling by the searched $\lambda_i$). Because $\beta^{i}$ grows exponentially with $i$, most dimensions have very small angles even for large $n$; only the lowest-frequency dimensions (small $i$) can have large raw arguments. LongRoPE also rescales angles (often substantially) and enforces monotonic $\lambda_i$, which tends to reduce large-angle growth for many dimensions. Empirically the authors report stable training/evaluation up to $2\text{M}$ tokens, so whatever numeric handling they used was sufficient for their setup.

Practical recommendations (consistent with what would be safe / what the paper’s implementation likely relied on):

1) Compute angles in $ \text{float32} $ (or $ \text{float64} $) and keep the $ \sin/\cos $ call in that precision. In modern GPU libraries the $ \text{sincosf}/\text{sincos} $ calls perform internal range reduction (argument reduction modulo $2\pi$) and are far more accurate than computing $ \sin/\cos $ in $ \text{float16} $. So do NOT feed raw $ \text{float16} $ angles into $ \sin/\cos $.

2) Avoid doing argument arithmetic in $ \text{float16} $. Even if model weights and activations are stored in $ \text{fp16} $, compute the position-dependent angle terms in $ \text{fp32} $, call the hardware $ \text{sincos} $ (which does range reduction), then cast the resulting $ \sin/\cos $ to $ \text{fp16} $ if you must store them in $ \text{fp16} $. This preserves the essential precision of the trig results.

3) If you implement custom kernels: use a numerically robust range-reduction routine (e.g., reduce modulo $2\pi$ in $ \text{fp64} $ or use the same algorithms as libc/CUDA $ \text{sincos} $ which split the argument) before calling $ \sin/\cos $. For extremely large $n$ and tiny $\theta_i$, consider computing angles as $(n \bmod \text{period})/\text{scale}$ where $\text{period} = 2\pi\cdot(\text{denominator scaling})$, but this is usually unnecessary if you do the trig in $ \text{fp32} $ and rely on the hardware intrinsics.

4) If you observe issues (rare): you can: (a) compute angles in $ \text{fp64} $ during the search / generation of $\lambda$ (offline) and then store produced $ \sin/\cos $ values; (b) explicitly reduce the argument modulo $2\pi$ in high precision before $ \sin/\cos $; or (c) use recurrence relations to generate $ \sin/\cos $ across positions ($\sin(n+1) = \sin(n)\cos(1)+\cos(n)\sin(1)$) in a stable, incremental fashion for blocks — though that has its own numerical tradeoffs and complexity.

In short: the paper doesn’t report numerical failures and the normal, robust approach is to compute angles/$\sin\cos$ in $ \text{fp32} $ (or $ \text{fp64} $ if you want extra safety), relying on the standard $ \text{sincos} $ intrinsics that do proper range reduction, and only cast results to $ \text{fp16} $ if necessary. That avoids the catastrophic cancellation you worry about while remaining efficient — and is consistent with the fact LongRoPE achieved stable evaluation up to $2\text{M}$ tokens in their experiments.

### How is passkey retrieval at 2M tokens executed within memory constraints?
Question:
For the passkey task up to 2,048k context, prefill attention is \(O(L'^2)\) compute and memory if done in one shot, which seems infeasible. Did you use chunked prefill, streaming with KV cache, or other engineering to run inference? Could you outline the exact inference procedure (batch size, precision, number of GPUs, peak memory) used to obtain the reported accuracy curves?
Answer:
Short answer: the paper does not compute a full $O(L'^2)$ prefill in one shot. Instead LongRoPE relies on standard streaming / chunked evaluation and KV caching (i.e., amortized autoregressive attention) and evaluation with sliding windows so that you never materialize a full $L'\times L'$ attention matrix. The manuscript explicitly states the method “reuses most pre‑existing optimizations” and evaluates long contexts with sliding/chunked windows (e.g., Books3 uses a sliding window of 256k). The paper does not publish a single “one-shot prefill” memory / GPU table for the passkey curves, so exact peak memory / GPU counts for inference are not given.

Why a one‑shot prefill would be infeasible (intuitive): computing full self‑attention for length $L'$ at once requires storing an $L'\times L'$ attention matrix (and K/V for every layer), so memory and compute scale as $O(L'^2)$. For $L'=2{,}048\text{k}$ that is astronomically large and impractical. In practice you avoid the $O(L'^2)$ step by never computing attention between all pairs of $L'$ tokens at once.

What the paper actually does (grounded to text)
- The evaluation setup: passkey retrieval places a five‑digit passkey uniformly at a random location across the evaluation context length and repeats 10 iterations (this is the passkey protocol used to produce the accuracy curves). For extremely long books (Books3) they used a sliding window of 256k for perplexity evaluation; search/perplexity evaluations used only a few long samples (3–5 items) rather than thousands of full‑2M sequences. These points are stated in the Experiments/Setup sections.
- The paper repeatedly says the extended models “reuse most pre‑existing optimizations” and that during inference they “dynamically adjust the corresponding RoPE rescale factors.” That implies inference is the usual streaming autoregressive pattern where RoPE parameters are adjusted per token length, but attention is computed incrementally.

How this is implemented in practice (what you should assume or implement to reproduce the curves)
- Use autoregressive streaming with a KV cache: prefill in chunks and append new tokens while retaining the cached keys and values for earlier tokens. Each new token’s attention cost is $O(L_{\text{cached}})$ for that step, and the total work across generating (or scanning) $L'$ tokens is $O(L'^2)$ in compute over the whole sequence but never requires materializing the full attention matrix in memory at once; importantly, memory usage is dominated by storing cached K/V tensors ($O(L'\cdot d_{\text{key}})$ per layer) rather than an $L'\times L'$ matrix.
- Evaluate with chunked prefill or sliding windows: when you only need to compute metrics (perplexity / whether the model outputs the passkey), you can process the long document in chunks (the paper used a sliding window size of 256k for Books3 perplexity evaluation). For passkey retrieval you can stream the prompt and the document and detect generation output as soon as the model emits the passkey.
- Use mixed precision and sharded KV/cache: run the model in fp16 (or bfloat16) and shard the KV cache across multiple GPUs (tensor / pipeline / model parallelism) so that per‑GPU KV storage remains feasible. The paper reports fine‑tuning setups (e.g., LLaMA2 fine‑tuning used global batch 32; 128k training used 8×A100 and 256k used 16×A100), and search/evaluation used only a few long samples — but it does not list the exact inference GPU count/peak memory.

What the paper does not provide (and therefore cannot be asserted as a fact)
- The paper does not give an explicit “prefill in one shot vs chunked” code path or a table with batch size, precision, number of GPUs and peak memory used to draw the passkey curves. It therefore does not report the exact per‑run peak memory numbers for the passkey experiments.

A practical recipe to reproduce the passkey curves consistent with what the paper says
1. Load the LongRoPE‑modified model weights (with dynamic RoPE rescale factors for the tested evaluation length).
2. Use fp16 / bfloat16 for model weights and activations.
3. Stream the long context in chunks (e.g., 64k–256k tokens per chunk used for the sliding window), updating the KV cache incrementally and never forming an $L'\times L'$ attention matrix.
4. Shard the model and KV cache across multiple GPUs (the paper used multi‑A100 clusters for fine‑tuning; inference commonly uses several GPUs for 7B models at million‑token lengths). Keep batch size = 1 (single sequence) for passkey retrieval evaluation to avoid extra memory pressure.
5. For passkey retrieval run 10 trials per length with the passkey placed uniformly at random and record whether the model outputs the passkey; this is exactly the evaluation protocol described.

If you want precise peak memory / GPU counts to match the paper’s curves you will need to re‑run the evaluation on your target hardware and report those numbers because the paper gives the experimental protocol (chunked evaluation, sliding windows, a few long samples, dynamic RoPE) but not a single canonical hardware/peak‑memory table for inference.

Summary: LongRoPE avoids infeasible one‑shot $O(L'^2)$ prefill by using standard streaming / chunked evaluation with a KV cache and sliding windows, adjusting RoPE factors dynamically for the target length. The paper documents the evaluation protocol (passkey placement, number of trials, sliding window size for Books3) and the training/search resources, but it does not publish exact per‑run inference GPU/peak‑memory figures — you will need to reproduce those on your hardware (use fp16, shard KV, chunk at 64k–256k, batch size 1).

### Is there an invertibility or separation guarantee to avoid position aliasing after interpolation?
Question:
For distinct positions \(n_1 \neq n_2\), after applying non-uniform interpolation, the rotated embeddings across all dimensions should remain sufficiently distinct to let attention discriminate them. Is there any condition on \(\{\lambda_i\}\) ensuring that the mapping \(n \mapsto [\cos(\cdot),\sin(\cdot)]\) remains injective (or at least collision-resistant) over \([0,L')\)? Could bad choices of \(\{\lambda_i\}\) lead to aliased positions that are indistinguishable to the model?
Answer:
Short answer: the paper does not give a formal injectivity or collision-free guarantee for the mapping $n \mapsto [\cos(\ldots), \sin(\ldots)]$ after applying the per-dimension rescale factors $\{\lambda_i\}$. In principle collision (aliasing) is possible because RoPE is composed of periodic $\cos/\sin$ coordinates; in practice LongRoPE reduces the risk via design choices and an empirical search objective (perplexity) that favors non-aliased solutions.

Why collisions are possible (intuitive + math). RoPE represents position $n$ by the vector of angles
$[\, n/\beta^0,\, n/\beta^1,\, \ldots \,]$ (up to the paper’s scaling/notation) and then applies $\cos$ and $\sin$ to each angle. After rescaling a dimension $i$ by $1/\lambda_i$ the $i$-th angle becomes
$\theta_i(n) = \left(n / \beta^i\right)\cdot\left(1/\lambda_i\right)$.
Two distinct positions $n_1 \neq n_2$ will be indistinguishable in the entire RoPE vector if and only if for every dimension $i$ the angle difference
$\Delta\theta_i = \theta_i(n_1) - \theta_i(n_2) = (n_1 - n_2)\cdot\left(\frac{1}{\lambda_i\beta^i}\right)$
is an integer multiple of $2\pi$ (or equivalently the $\cos$ and $\sin$ are equal). So mathematically the mapping is injective over $0\ldots L'$ only if for every nonzero integer $m = n_1 - n_2$ in $[-(L'-1),(L'-1)]$ there exists at least one $i$ with
$(n_1 - n_2)\cdot\left(\frac{1}{\lambda_i\beta^i}\right) \neq 2\pi k \quad\text{for all integers } k$.
Because $\cos/\sin$ are $2\pi$-periodic, if the set of scaled frequencies $1/(\lambda_i\beta^i)$ aligns badly with the integer differences, you can get exact (or very near) collisions.

Why this matters practically. Exact integer-multiple equalities are rare for arbitrary real $\lambda_i$, but near-equalities cause near-identical rotary embeddings and therefore the attention mechanism may have trouble discriminating positions (crowding). Linear global downscaling (PI) makes many positions “crowded” (angles compressed into a smaller range), increasing near-collisions for nearby $n$; NTK/YaRN and LongRoPE avoid some of that by preserving higher-frequency dimensions (smaller effective scaling) so close-by positions remain separated in at least some coordinates.

What the paper does to avoid aliasing (practical mitigations). The authors do not attempt a formal number-theoretic injectivity proof; instead they mitigate aliasing by:
- Searching non-uniform $\lambda_i$ per RoPE dimension (and optionally leaving the first $\hat n$ positions unscaled). This preserves higher-frequency dims (smaller $\lambda_i$) that give fine-grained phase changes for nearby $n$, reducing local aliasing.
- Enforcing a monotonic constraint $\lambda_i \le \lambda_{i+1}$, which keeps the frequency ordering consistent and protects high-frequency dimensions from excessive downscaling.
- Optimizing $\lambda_i$ by an evolutionary search with perplexity as the objective, so solutions that cause practical aliasing (which hurts language modeling) are disfavored.
- Recovering short-context behavior via a secondary search that reduces allowed $\lambda$ ranges when evaluating short windows, to avoid crowding in the original range.

Recommendations and checks you can run (grounded in the paper’s approach). If you worry about collisions for a chosen $\{\lambda_i\}$, you can empirically test for them cheaply before fine-tuning: sample a set of position pairs (or differences $m$) up to your target $L'$, compute the multi-dimensional rotary vectors (or just angle vectors modulo $2\pi$), and measure minimal pairwise distance (or minimal cosine similarity) across those embeddings. If you find near-zero distances for distinct positions, that indicates potential aliasing. Practical heuristics that the paper’s method already uses and you can adopt are: keep some dimensions near-unmodified ($\lambda_i$ close to $1$) for high frequencies, allow an initial block of positions unscaled, and use a search objective that penalizes downstream loss (perplexity) rather than relying on an abstract injectivity property.

Bottom line. There is no formal injectivity guarantee in LongRoPE; exact aliased positions are possible in principle because of trigonometric periodicity. The paper’s empirical strategy (non-uniform, monotonic per-dimension scaling plus selective exemption of initial tokens and a perplexity-driven search) is designed to avoid practically harmful aliasing and to preserve separability where it matters for attention. If you need stronger assurances, you must add explicit constraints or post-hoc checks (e.g., sampled pairwise embedding distances, or constraints avoiding simple rational ratios in scaled frequencies) as part of the search.

### How exactly is perplexity computed during search for samples longer than \(L'\)?
Question:
The optimization problem specifies inputs \(\mathbf{X}\) where each document length exceeds \(L'\). During fitness evaluation, do you:
- Take the first \(L'\) tokens and compute NLL on the next-token targets across that range?
- Use a sliding window of size \(L'\) and average losses across windows?
- Evaluate only on the tail to stress long-range dependencies?
Clarity on this evaluation protocol would help interpret the reported perplexities and search outcomes.
Answer:
Short answer: during search LongRoPE computes perplexity as the exponentiated average next-token negative log‑likelihood over sliding windows of length equal to the target context length $L'$. Practically they sample documents with $|\mathbf{x}|\ge L'$, apply the candidate RoPE rescale factors to the model, run the model over windows of size $L'$ (with a fixed stride used in evaluation) and average the per‑token NLLs across all tokens in those windows; perplexity = $\exp(\text{mean NLL})$. This is exactly what they describe in the Search and Experiments sections.

Why this is the protocol (intuitively and technically)
- The optimization objective in Eq. (6) is the next‑token loss $\mathcal{L}$ for inputs $\mathbf{X}$ with length at least $L'$. To estimate $\mathcal{L}$ for a candidate RoPE configuration you must evaluate next‑token probabilities on sequences of length $L'$, so the natural quantity is the average next‑token NLL over those tokens.
- Evaluating on entire long documents once would be expensive and biased by document endpoints; a sliding‑window evaluation (paper: “We evaluate perplexity at various context lengths using sliding window of 256.” and for very long Books3 evaluation they use a sliding window of 256k) produces many length-$L'$ contexts from each long document, covers different relative token positions, and yields a low‑variance estimate for perplexity while keeping per‑inference memory bounded.
- The paper’s Search setup states they pick samples with minimum length equal to the target $L'$ and compute perplexity on those samples (Search: “Perplexity is calculated using 5 random PG19 validation set samples, with a minimum length requirement of the target context length.”; for $>512\text{k}$ windows they use 3 Pile‑Books3 samples). That confirms they evaluate on full length-$L'$ contexts extracted from longer documents.

What is averaged exactly
- For each sliding window of tokens of size $L'$ they compute per‑token NLLs for the next‑token prediction targets (standard language‑model loss). They average the NLLs over all tokens in all windows used for that candidate. Perplexity is then $\exp\big(\text{mean NLL over all evaluated tokens}\big)$.
- The candidate RoPE mapping (including the “no interpolation for first $\hat n$ tokens” rule) is applied when constructing the positional encoding used for the tokens in those windows, so the evaluation reflects both per‑dimension rescale factors and the token‑position threshold.

Why this matters for interpreting search results
- Because they average NLL across sliding windows, the search score reflects performance across many relative token positions, not only the document tail. That is important because the method explicitly searches both per‑dimension $(\lambda_i)$ and per‑position $(\hat n)$ non‑uniformities: the sliding windows ensure the evaluation samples positions that test whether preserving early token RoPE (the $\hat n$ design) helps overall next‑token loss.
- When the paper reports using fewer validation samples for very large $L'$ (3 instead of 5), this makes the evaluation cheaper but slightly higher variance, so reported perplexities for giant $L'$ have more sampling noise.

Summary
LongRoPE’s search evaluates a candidate RoPE by running the model on length-$L'$ contexts extracted from longer documents via a sliding window, computing next‑token NLLs across those windows, averaging the NLLs, and reporting perplexity as $\exp(\text{mean NLL})$. This is consistent with the descriptions in the Search and Experiments sections (sample selection, sliding‑window stride, and number of validation samples).

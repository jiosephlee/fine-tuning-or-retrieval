### What does it mean that YaRN "doesn't reach the target context length" in non-fine-tuned settings?
Question:
In the analysis, you state that YaRN underperforms on PG19 and "doesn't reach the target context window length" for non-fine-tuned LLMs (e.g., perplexity spikes after 7k in an 8k context). What is the precise criterion for "reaching" the target length? Is it defined by a perplexity threshold, stability of loss, or something else? Could you formalize this notion so different methods can be compared consistently?
Answer:
Short answer: in the paper “doesn't reach the target context window length” means that when you apply YaRN’s RoPE rescaling without fine‑tuning and then evaluate language modeling performance as you increase evaluation sequence length up to the advertised target (e.g. $L'=8\text{k}$), the model’s perplexity stops behaving smoothly and instead exhibits a large, localized degradation (a “spike”) before the target length. In other words, the interpolation scheme fails to preserve useful positional encoding up to the target length. This is an empirical failure that can (and should) be made precise.

A formal, reproducible definition
Let $P(l)$ be the evaluated perplexity (or any scalar loss metric) computed for the model on sequences of length $l$ (the paper computes this with a sliding window; use the same evaluation protocol for all methods). Let $L$ be the original pretraining context and $L'$ the intended extended target length (e.g. $L'=8\text{k}$). I propose to declare that a method “reaches” $L'$ (without fine‑tuning) when it satisfies both of the following, which capture (a) no large degradation at or before $L'$ and (b) stability / absence of spikes:

1) Bounded relative degradation at $L'$:
   $$
   P(L') \le (1 + \tau)\cdot P_{\text{ref}}(L)
   $$
   where $P_{\text{ref}}(L)$ is a reference perplexity at the original (small) context length $L$ (or some baseline model value at $L$), and $\tau$ is a small tolerance (suggested default $\tau \in [0.05, 0.10]$ or 5–10% relative increase). This enforces that overall perplexity at the target length is not catastrophically worse than the baseline short‑context performance.

2) No local spike before $L'$:
   For every $l \in [L, L']$ consider a local window $W(l) = [l - w, l + w]$ (e.g. $w = 256$ tokens as used in the paper). Define the local spike ratio
   $$
   S(l) = \frac{P(l)}{\mathrm{median}_{x \in W(l)} P(x)}.
   $$
   Require
   $$
   \max_{l \in [L, L']} S(l) \le \alpha
   $$
   with $\alpha$ a modest threshold (suggested $\alpha \in [1.10, 1.25]$). This rules out sharp, localized increases of perplexity (the “spike after 7k” described in the paper).

You can equivalently express condition (2) with absolute differences $P(l) - \mathrm{median}_{W(l)} P(x) \le \delta$ (choose $\delta$ based on typical perplexity scale for your data) if you prefer absolute thresholds.

Why these two conditions
The paper’s observation about YaRN is a localized spike: perplexity is OK up to ~7k then suddenly increases near 8k. Condition (1) ensures the model’s performance at the target length is not broadly degraded; condition (2) catches the pathological behavior that motivated the paper’s phrase “doesn't reach the target context length.” Using both ensures we don’t call a method successful just because it has a reasonable average but with severe instability at specific lengths.

Practical evaluation protocol to compare methods
Use the same sliding-window perplexity evaluation (window size and step as in the paper). Compute $P(l)$ at a grid of $l \in \{L, L+\text{step}, \dots, L'\}$ and then evaluate the two conditions above. To make comparisons robust:

- Evaluate $P(l)$ over several held‑out samples (the paper uses multiple random PG19/Pile samples); report means $\pm$ standard error.
- Use bootstrap to test whether $P(L')$ is statistically indistinguishable (within $\tau$) from the baseline $P_{\text{ref}}(L)$.
- Report the maximum spike ratio $\max_l S(l)$ (or max absolute delta) so readers can see if the failure is global or local.
- Optionally report a slope / monotonicity measure: e.g. average derivative $\mathrm{d}P/\mathrm{d}l$ or fraction of steps where $P(l+\text{step}) - P(l) > 0$, to quantify smooth behaviour across lengths.

Alternative / complementary success criteria
Perplexity is the natural scalar used throughout the paper, but you can also use task‑level metrics that matter downstream: in the paper they use passkey retrieval accuracy and retrieval accuracy is arguably more interpretable for generation tasks. A method could “reach” $L'$ if it preserves a minimum task accuracy (e.g. $\ge 90\%$ of short‑context accuracy) up to $L'$. Using both language modelling (perplexity) and task metrics is advisable.

Suggested default thresholds (practical starting point)
- $\tau = 0.10$ (10% relative increase from short‑context perplexity)
- $\alpha = 1.15$ (local spike no more than 15% above local median in a $w = 256$ token window)
- Report results under these defaults and include sensitivity analysis (e.g., $\tau = 5\%$ and $20\%$) so conclusions are robust.

How this maps to the paper’s statement
When the paper says “YaRN … doesn’t reach the target context window length (e.g., perplexity spikes after 7k in an 8k context)”, that corresponds precisely to violation of condition (2): a pronounced local spike $S(l) \gg \alpha$ before $L'$, even if the average trend might look OK. Using the formal test above lets you quantify that behavior and compare YaRN, PI, NTK and LongRoPE in a consistent, reproducible way.

Summary
Make “reach” a two‑part test: (i) no large overall degradation at the target length (bounded relative perplexity increase), and (ii) no sharp local spikes before the target (bounded local spike ratio over a sliding window). Use the same sliding-window perplexity protocol and bootstrap/averaging over samples to compare methods consistently. These formal criteria capture precisely the empirical failure the paper points out for YaRN and allow fair, repeatable comparisons.

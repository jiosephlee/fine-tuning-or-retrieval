\title{A Textbook about the Paper: "xLSTM: Extended Long Short-Term Memory"}

Chapter 3: # The xLSTM Innovation: Exponential Gating and Stabilization

The Long Short-Term Memory (LSTM) network was designed to overcome the vanishing gradient problem by utilizing a "constant error carousel," which is essentially an additive update mechanism for a cell state. In the standard LSTM architecture, the cell state $c_t$ is updated at each time step $t$ based on the previous state $c_{t-1}$, a forget gate $f_t$, an input gate $i_t$, and a cell input $z_t$. This is expressed by the fundamental update rule:
$c_t = f_t c_{t-1} + i_t z_t$.
While this mechanism has been highly successful, the original LSTM has several inherent limitations when scaled to the size of modern Large Language Models. One of the most significant limitations is the inability to revise storage decisions. In tasks like Nearest Neighbor Search—where a model must scan a sequence and provide the value associated with the most similar vector found so far—the standard LSTM struggles to overwrite or revise a previously stored value when a better match appears later in the sequence. To address this, the xLSTM introduces exponential gating as a core innovation.

# Introduction to Exponential Gating

In the standard LSTM, the gates $i_t$ and $f_t$ are typically governed by sigmoid activation functions, which squash the values into a range between 0 and 1. While this provides a clear mechanism for "forgetting" or "remembering," it limits the dynamic range and flexibility of the update rule. The xLSTM proposes a modification where the input and forget gates can utilize exponential activation functions. 

By moving to exponential gating, the model changes how it modulates the flow of information into and out of the memory. Specifically, the input gate $i_t$ is defined as $\exp(\tilde{i}_t)$, where $\tilde{i}_t$ is the pre-activation value. The forget gate $f_t$ can also be defined using an exponential function $\exp(\tilde{f}_t)$ or remain as a sigmoid $\sigma(\tilde{f}_t)$. This shift is designed to enrich the LSTM family by providing a more expressive way to handle memory updates. The goal is to allow the network to make more nuanced decisions about how much of the previous state should be retained and how much of the new input should be incorporated, specifically aiming to remediate the "revision" problem identified in standard LSTMs.

# The Normalizer State: Summing products of input and future forget gates

A significant challenge arises when using exponential functions for gating: because the exponential function grows very rapidly, the values in the cell state $c_t$ can quickly become extremely large, potentially leading to numerical instability or overflow. To counteract this, the xLSTM introduces a "normalizer state," denoted as $n_t$.

The normalizer state is updated at each time step using a rule that mirrors the cell state update but focuses on the gate values themselves. The formula for the normalizer state is:
$n_t = f_t n_{t-1} + i_t$.
This state effectively keeps a running sum of the product of the input gate and all previous forget gates. By maintaining this history, the model tracks the cumulative "strength" or "gain" applied to the memory. To ensure the hidden state remains within a manageable range, the xLSTM modifies the calculation of the hidden state $\tilde{h}_t$. Instead of simply squashing the cell state with a $\tanh$ function, the model divides the cell state by the normalizer state:
$\tilde{h}_t = c_t / n_t$.
This division serves as a normalization step that balances the exponential growth of the cell state, allowing the model to benefit from the expressive power of exponential gating without suffering from numerical explosion.

# Stabilization Techniques: Preventing overflows using log-space stabilization ($m_t$ state)

Even with a normalizer state, calculating $\exp(\tilde{i}_t)$ directly can still lead to floating-point overflows if the pre-activation values are large. To ensure the model remains numerically stable during training and inference, the xLSTM employs a stabilization technique using an auxiliary state $m_t$, often referred to as a stabilizer state.

The stabilizer state $m_t$ tracks the maximum log-scale value of the gates to ensure that the arguments passed to the exponential functions stay within a safe range. It is updated as follows:
$m_t = \max(\log(f_t) + m_{t-1}, \log(i_t))$.
Using this state, the gates are re-formulated into stabilized versions, $i'_t$ and $f'_t$. The stabilized input gate is calculated as:
$i'_t = \exp(\log(i_t) - m_t) = \exp(\tilde{i}_t - m_t)$.
The stabilized forget gate is calculated as:
$f'_t = \exp(\log(f_t) + m_{t-1} - m_t)$.
By subtracting $m_t$ (the maximum value) from the log-values before exponentiating, the authors ensure that the resulting values do not exceed 1. This is a common trick in machine learning (similar to the log-sum-exp trick) to maintain numerical precision while preserving the underlying mathematical relationship of the operations.

# How exponential gating enables memory revision

The primary intuition behind using exponential gating is to solve the "storage revision" problem. In a standard LSTM, the update rule $c_t = f_t c_{t-1} + i_t z_t$ with sigmoid gates acts somewhat like a moving average or a weighted sum where the weights are strictly bounded between 0 and 1. This makes it difficult for the model to "overwrite" a high-confidence memory with a new, even more relevant piece of information because the influence of the old state is always preserved to some degree unless the forget gate is nearly zero.

Exponential gating changes the dynamics of this update. Because the gates can take on a wider range of values, the model gains the ability to more aggressively revise its internal storage. In the context of the Nearest Neighbor Search problem, if the model encounters a vector that is much more similar to the query than the one it currently has stored in its memory, the exponential gating allows it to "re-write" that memory cell more effectively. The combination of exponential gates and the normalizer state allows the xLSTM to behave more like a dynamic memory that can be updated and revised as new, more relevant information arrives in the sequence.

# Mathematical proofs of derivative preservation in stabilized gates

A critical requirement for any architectural modification is ensuring that the change does not inadvertently break the gradient flow during backpropagation. The authors demonstrate that the stabilization technique used for the gates does not change the actual output of the network, nor does it alter the derivatives of the loss function with respect to the model parameters.

The logic follows from the fact that the stabilizer state $m_t$ is essentially a constant with respect to the parameters during a single forward pass calculation of a specific gate. When we replace $i_t$ with $i'_t$ and $f_t$ with $f'_t$, we are essentially performing a transformation that factors out a common term. Since the final hidden state $\tilde{h}_t$ involves a ratio (the cell state divided by the normalizer state), any constant factor introduced by the stabilization (like $\exp(m_t)$) appears in both the numerator and the denominator. Consequently, these factors cancel each other out in the final output. Because the output remains mathematically identical to the non-stabilized version, the gradient of the loss with respect to the weights $\mathbf{w}$ and $r$ remains unchanged, ensuring that the model can be trained using standard optimization techniques without any modification to the gradient calculation.

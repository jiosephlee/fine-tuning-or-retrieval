\title{A Textbook about the Paper: "xLSTM: Extended Long Short-Term Memory"}

Chapter 5: Architectural Design: Residual Stacking and Parallelization

# xLSTM Blocks: Post-up-projection vs. Pre-up-projection architectures

To build a functional Large Language Model (LLM) using the xLSTM framework, the individual memory units must be integrated into structured modules known as xLSTM blocks. These blocks are designed to non-linearly summarize the history of a sequence in a high-dimensional space. The primary objective of this summarization is to separate different histories or contexts from one another. Effective separation of these contexts is a fundamental prerequisite for the model to correctly predict the next element in a sequence, such as the next token in a sentence. Depending on the specific type of LSTM variant used within the block—either the sLSTM or the mLSTM—the architecture employs two different structural designs: post-up-projection and pre-up-projection.

The post-up-projection architecture is utilized for blocks containing an sLSTM. In this configuration, the model first non-linearly summarizes the past in the original space. Following this summarization, the block performs a linear map into a high-dimensional space, applies a non-linear activation function, and finally maps the data back to the original space. This structure ensures that the scalar memory of the sLSTM is utilized effectively within the residual framework.

Conversely, the pre-up-projection architecture is used for blocks containing an mLSTM. In this design, the model first performs a linear map into a high-dimensional space before non-linearly summarizing the past within that high-dimensional space. The result is then mapped back to the original space. The motivation for choosing pre-up-projection for the mLSTM is that the matrix memory structure of the mLSTM gains significantly larger capacity when operating in a high-dimensional space. By moving the summary process into a higher dimension first, the model can leverage the expansive capacity of the matrix memory more effectively than it could in the original space.

# Applying Cover’s Theorem to high-dimensional history summarization

The design choices regarding high-dimensional mapping in xLSTM blocks are grounded in a fundamental principle of machine learning known as Cover's Theorem. Cover's Theorem states that patterns that are non-linearly embedded in a lower-dimensional space can be more easily separated linearly when mapped into a higher-dimensional space. In the context of language modeling, the "patterns" are the various histories or contexts the model encounters as it processes a sequence. Because these histories are often complex and non-linear, it can be difficult for a model to distinguish between them in a low-dimensional representation.

By employing up-projection to move the history into a higher-dimensional space, xLSTM creates a framework where these different contexts become more linearly separable. This separation is crucial because, for a model to predict the next token accurately, it must be able to identify which specific history is currently relevant. If the model cannot distinguish between two different contexts (for example, two different narrative threads in a long story), it will struggle to produce the correct next token. Thus, the high-dimensional summarization acts as a mechanism to "disentangle" the past, providing a clearer signal for the model's predictive capabilities.

# Residual stacking and pre-LayerNorm backbones

Once the individual xLSTM blocks are defined, they must be organized into a deep architecture capable of learning the complex nuances of human language. To achieve this, xLSTM architectures are constructed by residually stacking these blocks. Residual stacking is a standard technique in modern deep learning, where the output of one block is added to its input (or a transformed version of its input), allowing gradients to flow more easily through very deep networks. This technique has been foundational to the success of both deep convolutional networks and the Transformer architectures that power current Large Language Models.

Specifically, the xLSTM architecture adopts the pre-LayerNorm residual backbone, which is the most common configuration in contemporary Large Language Models. In this setup, Layer Normalization is applied before the processing of the block, and the residual connection facilitates the stacking of many blocks. By following this established backbone, the xLSTM architecture inherits the stability and scaling properties that have made modern LLMs successful. This structural choice allows the xLSTM to be scaled to billions of parameters while maintaining the ability to train effectively.

# Computational Complexity: Linear vs. Quadratic scaling with sequence length

One of the primary advantages of the xLSTM architecture over the standard Transformer is its computational and memory complexity. In a standard Transformer, the self-attention mechanism results in quadratic complexity with respect to the sequence length. This means that as the input sequence becomes longer, the amount of computation and memory required increases by the square of the length, which eventually creates a bottleneck for processing very long contexts.

In contrast, xLSTM networks maintain a linear computation complexity and a constant memory complexity with respect to the sequence length. Because the xLSTM memory is compressive, it does not need to store a growing history of all previous tokens in a way that scales quadratically. This makes xLSTM particularly well-suited for industrial applications and deployment on edge devices where memory resources might be limited. While the mLSTM uses a $d \times d$ matrix memory, which involves a specific computational cost for updates and retrieval, these operations are still independent of the sequence length $L$. Furthermore, because these matrix operations can be performed in parallel on GPUs, the wall-clock time overhead of the complex matrix memory remains minor.

# Hardware Optimization: Parallelizing mLSTM and CUDA kernels for sLSTM

A significant hurdle for traditional LSTMs has been their lack of parallelizability due to hidden-hidden connections, which enforce sequential processing. xLSTM addresses this by offering two different types of memory structures with different hardware characteristics. The mLSTM is designed to be fully parallelizable. Because it abandons the memory mixing (the recurrent connections between hidden states from one time step to the next), its operations can be reformulated into a parallel version. This allows the mLSTM to be computed efficiently on GPUs, similar to how FlashAttention or Gated Linear Attention (GLA) operate.

The sLSTM, however, remains inherently non-parallelizable because it retains memory mixing through hidden-hidden connections. To mitigate the performance impact of this sequential nature, the researchers developed a fast CUDA implementation specifically for the sLSTM. This implementation includes GPU memory optimizations down to the register level. While the sLSTM is still sequential, these optimizations ensure that it is typically less than two times slower than the parallel mLSTM implementation. While the current mLSTM kernels are approximately four times slower than FlashAttention or the scan used in Mamba, the research suggests that further optimization in the vein of FlashAttention could continue to improve these speeds.

\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### Why does mLSTM use 'pre up-projection' while sLSTM uses 'post up-projection' based on Cover's Theorem?
Question:
In Section 3.3, the authors explain their choice of residual block architectures. They use post up-projection for sLSTM and pre up-projection for mLSTM. They mention Cover's Theorem, which suggests that non-linearly embedded patterns are more likely to be linearly separated in higher dimensions.

I don't quite see the connection. Why does the mLSTM benefit specifically from the high-dimensional space *before* the memory update $\mathbf{C}_t = \mathbf{C}_{t-1} + \mathbf{v}_t \mathbf{k}_t^\top$, whereas the sLSTM doesn't require that same ordering? Does the matrix memory $\mathbf{C}$ have some property that makes it more sensitive to the dimensionality of the input $\mathbf{x}_t$?
Answer:
The distinction between the "pre up-projection" and "post up-projection" architectures in xLSTM boils down to where the model performs its "summarization" of the past and how much "room" it has to store those summaries.

To understand this, we have to look at how each variant handles its memory and how Cover's Theorem applies to those specific mechanisms.

### Cover's Theorem and the Goal of xLSTM
The authors state that the goal of the residual block is to "non-linearly summarize the past in a high-dimensional space to better separate different histories." Cover's Theorem provides the mathematical justification for this: if you have data that is not linearly separable in a low-dimensional space, projecting it into a higher-dimensional space makes it much more likely that a linear classifier (or a linear update rule) can separate those patterns. In the context of an LSTM, "separating histories" means the model's memory should be able to distinguish between different contexts (e.g., the "past" of a story about a cat vs. a story about a spaceship) so that it can retrieve the correct information for the current token.

### Why mLSTM needs Pre Up-Projection
The mLSTM uses a matrix memory $\mathbf{C}$ updated via a covariance rule: $\mathbf{C}_t = \mathbf{C}_{t-1} + \mathbf{v}_t \mathbf{k}_t^\top$. 

This is the critical technical detail. The memory $\mathbf{C}$ is essentially a sum of outer products. If the vectors $\mathbf{v}_t$ and $\mathbf{k}_t$ are in a dimension $d$, the memory $\mathbf{C}$ is a $d \times d$ matrix. If we use **pre up-projection**, we project the input $\mathbf{x}_t$ into a higher dimension $D$ (where $D > d$) *before* computing the outer product. This means:
1. The vectors $\mathbf{v}_t$ and $\mathbf{k}_t$ now exist in $\mathbb{R}^D$.
2. The update $\mathbf{v}_t \mathbf{k}_t^\top$ happens in a much larger space, resulting in a $D \times D$ matrix.

By performing the update in the high-dimensional space, the "memory capacity" (the number of distinct, linearly separable patterns the matrix can store) increases significantly. Because the update is additive, the matrix $\mathbf{C}$ acts as a repository of these high-dimensional patterns. If we had used post up-projection, the update would happen in the smaller $d \times d$ space first, and we would only project the *result* of the summation. This would severely bottleneck the storage capacity, as the model would be trying to "cram" all past information into a smaller matrix before ever seeing the high-dimensional space.

### Why sLSTM uses Post Up-Projection
In contrast, the sLSTM uses a scalar memory $c_t$. The update rule is $c_t = f_t c_{t-1} + i_t z_t$. 

In this architecture, the "bottleneck" is the scalar nature of $c_t$ itself. Because the update is a simple addition of scalars (or a small vector of scalars if there are multiple cells), projecting to a high-dimensional space *before* the update doesn't "expand" the storage capacity in the same way an outer product does. The information is already being compressed into the scalar state.

For sLSTM, the high-dimensional "separation" is achieved by the residual block's ability to non-linearly transform the hidden state $h_t$ *after* it has been retrieved from the memory. This is why post up-projection (like in Transformers) is sufficient: the model summarizes the past through the recurrence, and then uses the high-dimensional projection to perform the complex non-linear reasoning required to predict the next token.

### Summary Intuition
You can think of the memory $\mathbf{C}$ in mLSTM as a physical warehouse. 
*   **Pre up-projection** for mLSTM is like expanding the size of the warehouse *before* you start moving boxes (the $\mathbf{v} \mathbf{k}^\top$ products) into it. This gives you more room to store distinct items.
*   **Post up-projection** for sLSTM is like having a small box (the scalar $c_t$) that you move around, but having a very large room (the high-dimensional projection) to unpack and organize those items once you take them out of the box.

Because the mLSTM's "storage" is the matrix itself, it needs that room *during* the storage process. Because the sLSTM's "storage" is a compressed scalar, it only needs the room *after* the storage process to perform the final computation.

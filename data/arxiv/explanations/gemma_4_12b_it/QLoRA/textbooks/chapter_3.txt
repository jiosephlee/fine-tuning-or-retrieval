Chapter 3: The QLoRA Framework: Technical Innovations

# 4-bit NormalFloat (NF4): Information-theoretically optimal data types for normal distributions

To understand the innovation of 4-bit NormalFloat (NF4), one must first understand the typical distribution of weights in a pretrained neural network. The authors of the QLoRA paper observe that pretrained weights usually follow a zero-centered normal distribution with a standard deviation of $\sigma$. Because this distribution is well-understood and relatively stable, it provides a unique opportunity to design a quantization data type that is "information-theoretically optimal." This means the data type is designed specifically to represent the values of a normal distribution as efficiently as possible, ensuring that the information lost during discretization is minimized.

The core intuition behind NF4 is to ensure that each quantization bin—the discrete "buckets" that hold the compressed values—contains an equal number of values from the input distribution. In traditional quantization, such as 4-bit Integers or 4-bit Floats, the bins might not align well with the shape of the weight distribution, potentially leading to higher errors in regions where the weights are most concentrated. By using a data type tailored to the normal distribution, NF4 ensures that the distribution of weights is mapped into the available bit-space in the most efficient way possible.

To implement this, QLoRA assumes a target range for the data type, such as $[-1, 1]$. The weights of the neural network are normalized into this range by rescaling the standard deviation $\sigma$ so that the distribution fits exactly into the range of the data type. Once the weights and the data type range are aligned, the weights can be quantized using the specific quantiles defined by the NF4 format. This approach allows for high-precision 4-bit quantization that preserves the predictive performance of the model much better than standard 4-bit representations.

# Quantile Quantization and the derivation of the NF4 data type

The foundation of NF4 lies in a concept known as Quantile Quantization. In this method, the goal is to discretize an input by ensuring that each quantization bin has an equal number of values assigned to it from the input tensor. This is typically achieved by estimating the quantiles of the input tensor through the empirical cumulative distribution function (ECDF). However, the primary limitation of standard quantile quantization is that the process of estimating these quantiles is computationally expensive, often requiring complex algorithms to approximate the quantiles quickly.

Furthermore, because these approximation algorithms are not exact, they often result in large quantization errors for outliers. Outliers are particularly problematic because they can carry significant information for the model's performance. The QLoRA authors propose a way to circumvent these issues by leveraging the fact that pretrained weights come from a distribution that is fixed up to a quantization constant. Because the distribution is known (a normal distribution), the quantiles of the weights are also known, making exact quantile estimation computationally feasible and removing the need for expensive approximations that lead to errors.

The specific derivation of the $k$-bit NormalFloat (NFk) data type involves estimating the $2^k+1$ quantiles of a theoretical standard normal distribution $N(0,1)$. These values, denoted as $q_i$, are computed using the quantile function $Q_X(\cdot)$ of the standard normal distribution:

$$q_i  = \frac{1}{2}\left( Q_X\left(\frac{i}{2^k+1}\right) + Q_X\left(\frac{i+1}{2^k+1}\right)\right)$$

A technical challenge with symmetric $k$-bit quantization is that this method does not naturally provide an exact representation of zero, which is necessary for quantizing padding and other zero-valued elements. To solve this, QLoRA creates an asymmetric data type. They estimate the quantiles for two different ranges: $2^{k-1}$ for the negative part and $2^{k-1}+1$ for the positive part. By unifying these sets and removing one of the two zeros that occurs in both sets, they produce a data type that maintains a discrete zeropoint of $0$ while ensuring an equal expected number of values in each quantization bin.

# Double Quantization: Reducing the memory footprint of quantization constants

While 4-bit quantization significantly reduces the memory required for model weights, the "quantization constants" (or scales) used to perform the conversion still consume a non-negligible amount of memory. For example, if a model uses a small blocksize (such as 64) to maintain high quantization precision, the 32-bit constants for those blocks can add up to 0.5 bits per parameter on average. For very large models, this overhead remains a factor that needs to be addressed to maximize memory efficiency.

Double Quantization (DQ) is the solution to this problem. It involves a second step of quantization where the quantization constants from the first step are treated as inputs for a second quantization process. Specifically, the 32-bit floating-point constants $c_2^{\text{FP32}}$ from the initial quantization are quantized into 8-bit floats $c_2^{\text{FP8}}$. This process also produces a second level of quantization constants, $c_1^{\text{FP32}}$. The authors chose 8-bit floats for this second step because they found that 8-bit quantization does not result in any observable performance degradation.

Because the initial quantization constants $c_2^{\text{FP32}}$ are always positive, the authors subtract the mean from these constants before the second quantization to center the values around zero. This allows for the use of symmetric quantization. This two-step process dramatically reduces the memory footprint. For a blocksize of 64, Double Quantization reduces the memory footprint per parameter from 0.5 bits down to approximately 0.127 bits. This represents a saving of about 0.373 bits per parameter, which equates to approximately 3 GB of saved memory for a 65B parameter model.

# Paged Optimizers: Leveraging NVIDIA unified memory to manage memory spikes

A major hurdle in finetuning large models on single GPUs is the occurrence of memory spikes. These spikes often happen during gradient checkpointing when the system processes mini-batches with particularly long sequence lengths. Even if the average memory usage is within limits, these sudden spikes can cause Out-Of-Memory (OOM) errors, crashing the training process. To mitigate this, QLoRA introduces Paged Optimizers, which utilize the NVIDIA unified memory feature.

Unified memory allows for automatic page-to-page transfers between the CPU and the GPU. It functions similarly to virtual memory in operating systems, where memory can be swapped between the system RAM and the GPU's VRAM. QLoRA uses this feature to allocate paged memory for the optimizer states. When the GPU's memory is exhausted due to a spike, the optimizer states are automatically evicted to the CPU RAM. When the optimizer update step occurs and the memory is needed again, the data is automatically paged back into the GPU memory.

This mechanism ensures that the training process can continue without crashing, even when the memory requirements of a specific batch temporarily exceed the physical capacity of the GPU. The authors performed an analysis on 65B models and found that when using a batch size of 16, Paged Optimizers provide the same training speed as regular optimizers, making them a highly efficient way to handle the volatility of memory usage during large-scale LLM finetuning.

# The QLoRA Forward and Backward Pass: Integrating NF4, Double Quantization, and LoRA

The QLoRA framework integrates all the aforementioned innovations into a cohesive training pipeline. The fundamental principle is that the model maintains one low-precision storage data type (typically 4-bit NF4) and one high-precision computation data type (typically 16-bit BrainFloat). This means that while the weights are stored in a compressed format to save space, they are dequantized to 16-bit precision whenever a calculation is actually performed.

The forward pass for a single linear layer in the QLoRA framework can be expressed as:

$$\mathbf{Y}^{\text{BF16}} =  \mathbf{X}^{\text{BF16}} \text{doubleDequant}(c_1^{\text{FP32}}, c_2^{\text{k-bit}}, \mathbf{W}^{\text{NF4}}) + \mathbf{X}^{\text{BF16}}\mathbf{L}^{\text{BF16}}_1\mathbf{L}^{\text{BF16}}_2$$

In this equation, $\mathbf{X}$ is the input in BFloat16, $\mathbf{W}$ is the 4-bit NF4 weight, and $\mathbf{L}_1, \mathbf{L}_2$ are the Low-Rank Adapter weights. The $\text{doubleDequant}$ function performs the two-step dequantization process: it first dequantizes the 4-bit constants $c_2$ using $c_1$, and then uses the resulting scale to dequantize the 4-bit weights $\mathbf{W}$ into BFloat16. For the best balance between precision and memory, QLoRA uses a blocksize of 64 for the weights $\mathbf{W}$ and a larger blocksize of 256 for the constants $c_2$.

The backward pass is equally optimized. During backpropagation, the system does not need to compute gradients for the 4-bit weights ($\frac{\partial E}{\partial \mathbf{W}}$), as these weights are frozen. However, to compute the gradients for the LoRA adapters ($\frac{\partial E}{\partial \mathbf{L}_i}$), the system must calculate the derivative $\frac{\partial \mathbf{X}}{\partial \mathbf{W}}$. To maintain the accuracy of this derivative, QLoRA performs the dequantization of the storage weights ($\mathbf{W}^{\text{NF4}}$) to the computation type ($\mathbf{W}^{\text{BF16}}$) during the backward pass. This ensures that while the base model is stored in 4-bit, the actual gradient updates for the adapters are calculated with the precision of 16-bit BrainFloat.

# Beyond FlashAttention-2: Why We Need a New Speed Demon for LLMs

The Transformer architecture has become the backbone of modern artificial intelligence, but it carries a significant computational burden: the attention mechanism. Because the cost of computing self-attention scores scales quadratically with the sequence length $N$, scaling models to handle long documents, massive codebases, or high-resolution video becomes exponentially more difficult. To overcome this, researchers have turned to software optimizations to make attention faster without sacrificing accuracy.

While the first generation of FlashAttention revolutionized the field by using a tiling strategy to minimize slow memory reads and writes, the second generation (FlashAttention-2) eventually hit a performance plateau on modern hardware. Specifically, on the NVIDIA Hopper H100 GPU, FlashAttention-2 achieves only about 35% utilization compared to the 80-90% utilization seen in optimized matrix-multiplication (GEMM) kernels. This gap exists because FlashAttention-2 relies on a simplified synchronous execution model and doesn't fully exploit the advanced asynchronous features and low-precision capabilities of the newest GPU architectures.

FlashAttention-3 is designed to break this plateau by rethinking the algorithm to align with how modern hardware actually works. It moves away from a synchronous model toward one that embraces asynchrony and leverages low-precision formats like FP8. By doing so, it aims to unlock the next level of long-context capabilities for Large Language Models (LLMs).

## Breaking the Synchronous Barrier

The primary limitation of previous iterations is that they don't fully utilize the specialized hardware units on the H100. Modern GPUs have separate units for matrix multiplication (Tensor Cores) and memory loading (Tensor Memory Accelerator, or TMA). FlashAttention-3 exploits this by introducing several key technical innovations:

*   **Producer-Consumer Asynchrony:** The authors use a technique called warp-specialization. Instead of every thread trying to do everything, the warps within a threadblock are split into "producers" and "consumers." Producers focus solely on moving data from global memory to shared memory, while consumers focus on the heavy computation. This allows the GPU to hide memory and instruction latencies more effectively.
*   **Hiding Softmax under GEMMs:** One of the biggest bottlenecks in attention is the softmax operation. While matrix multiplications are extremely fast on Tensor Cores, the "special functions" required for softmax (like exponentials) have much lower throughput. FlashAttention-3 uses a "pingpong" scheduling scheme. It overlaps the softmax computation of one block of data with the matrix multiplication of the next block. Essentially, it keeps the Tensor Cores busy with heavy lifting while the multi-function units handle the softmax math in the background.
*   **Hardware-Accelerated FP8:** To double the throughput, FlashAttention-3 targets the FP8 Tensor Cores. However, moving to 8-bit precision introduces significant numerical challenges, especially with the "outlier" features common in LLMs. To solve this, the authors introduced block quantization—applying different scaling factors to different blocks of the tensor—and incoherent processing. Incoherent processing involves multiplying the query ($\mathbf{Q}$) and key ($\mathbf{K}$) matrices by a random orthogonal matrix $\mathbf{M}$ before quantization. Because $\mathbf{M}$ is orthogonal, the final attention output remains the same, but the outliers are "spread out," significantly reducing the error caused by low-precision math.

## Real-World Impact

The results of these optimizations are substantial. In testing on H100 GPUs, FlashAttention-3 achieves a 1.5-2.0$\times$ speedup over FlashAttention-2 in the forward pass. When using FP16 precision, it reaches up to 740 TFLOPs/s, representing a much higher utilization of the hardware's theoretical limits. For even higher speeds, the FP8 implementation reaches close to 1.2 PFLOPs/s.

Importantly, these speed gains do not come at the cost of accuracy. The authors demonstrated that their FP8 implementation with block quantization and incoherent processing is 2.6$\times$ more accurate than standard FP8 attention methods when dealing with outlier features. By optimizing the software to match the hardware's "asynchronous" DNA, FlashAttention-3 provides the speed and precision necessary to push the boundaries of what LLMs can process in a single context window.



# The Assembly Line of AI: How Asynchrony Fuels FlashAttention-3

The Transformer architecture has become the backbone of modern AI, but its core mechanism—attention—remains a significant computational bottleneck. While previous iterations like \textsc{FlashAttention} and \textsc{FlashAttention-2} successfully optimized memory access, they didn't fully tap into the specialized hardware capabilities of newer GPUs. Specifically, \textsc{FlashAttention-2} achieves only about 35\% utilization on the NVIDIA H100 GPU, whereas optimized matrix-multiplication kernels can reach 80-90\%.

To bridge this gap, the researchers behind \textsc{FlashAttention-3} introduced a design centered on asynchrony. By reimagining the attention mechanism as a high-speed assembly line, they managed to significantly increase throughput on Hopper architecture GPUs.

## The Producer-Consumer Model: A Hardware-Aware Assembly Line

The fundamental shift in \textsc{FlashAttention-3} is the move away from a synchronous execution model. In a synchronous model, the GPU often sits idle while waiting for data to move from global memory (HBM) to on-chip shared memory (SMEM), or while waiting for a computation to finish before starting the next move.

To solve this, the researchers implemented a "Producer-Consumer" model using **warp-specialization**. In this scheme, the warps within a threadblock are divided into two distinct roles:

*   **Producers:** These warps act as the logistics team. They are dedicated solely to data movement, using the Tensor Memory Accelerator (TMA) to fetch tiles of the query ($\mathbf{Q}$), key ($\mathbf{K}$), and value ($\mathbf{V}$) matrices from HBM and place them into a circular buffer in shared memory.
*   **Consumers:** These warps are the factory workers. They focus entirely on the math, pulling data from the shared memory buffer to perform the matrix multiplications and softmax operations.

By splitting these responsibilities, the GPU can perform data movement and computation simultaneously. The TMA handles the "shipping" of data in the background, while the Tensor Cores handle the "manufacturing" of the attention scores.

## Hiding Softmax with Pingpong Scheduling

Even with a producer-consumer model, a new bottleneck emerges: the softmax operation. While matrix multiplications (GEMMs) are extremely fast on modern hardware, the "special functions" required for softmax (like exponentials) are much slower. On an H100 GPU, the throughput for exponential operations is significantly lower than for FP16 matrix multiplications.

To prevent the slow softmax from stalling the assembly line, \textsc{FlashAttention-3} employs **pingpong scheduling**. The researchers restructured the algorithm to overlap the softmax of one warpgroup with the GEMM of another. 

The process works like this:
1.  Warpgroup 1 performs a matrix multiplication.
2.  While Warpgroup 1 starts its softmax calculation, Warpgroup 2 performs its own matrix multiplication.
3.  They then swap roles.

This "pingponging" ensures that the multi-function units (handling the softmax) and the Tensor Cores (handling the GEMMs) are both working at the same time, maximizing the utilization of the hardware.

## Low-Precision and Accuracy

Beyond asynchrony, \textsc{FlashAttention-3} also optimizes for low-precision. It supports FP8, which can nearly double the throughput compared to FP16. However, moving to lower precision often introduces numerical errors, especially when "outlier" features are present in the data.

To maintain accuracy, the paper introduces two key techniques:
*   **Block Quantization:** Instead of using a single scaling factor for an entire tensor, the researchers use one scalar per block. Since the algorithm already operates on blocks, this can be integrated with almost no extra computational cost.
*   **Incoherent Processing:** To "smooth out" outliers, the query ($\mathbf{Q}$) and key ($\mathbf{K}$) matrices are multiplied by a random orthogonal matrix $\mathbf{M}$ before being quantized to FP8. Because $\mathbf{M}$ is orthogonal, the underlying result $(\mathbf{Q}\mathbf{M})(\mathbf{K}\mathbf{M})^\top$ remains equal to $\mathbf{Q}\mathbf{K}^\top$, but the outliers are effectively redistributed, reducing the errors caused by quantization.

## Performance Gains

The results of these optimizations are substantial. On H100 GPUs, \textsc{FlashAttention-3} achieves a 1.5-2.0$\times$ speedup over \textsc{FlashAttention-2} in the forward pass, reaching up to 740 TFLOPs/s (roughly 75\% utilization). Furthermore, the FP8 implementation manages to reach close to 1.2 PFLOPs/s while remaining 2.6$\times$ more accurate than standard FP8 attention methods.

By treating the GPU as a coordinated assembly line rather than a sequence of isolated tasks, \textsc{FlashAttention-3} sets a new standard for high-performance attention.



# The Pingpong Strategy: Hiding Softmax Behind Massive Matrix Math

In the world of Large Language Models (LLMs), the attention mechanism is a notorious computational bottleneck. While previous iterations like \textsc{FlashAttention} and \textsc{FlashAttention-2} significantly improved performance by minimizing memory reads and writes, they still struggle to fully saturate modern hardware. Specifically, \textsc{FlashAttention-2} achieves only about 35\% utilization on the NVIDIA Hopper H100 GPU.

The authors of \textsc{FlashAttention-3} identified a fundamental reason for this: the hardware's "special function" units are significantly slower than its matrix multiplication units. To solve this, they introduced a clever scheduling trick known as "pingpong" scheduling to hide the latency of softmax operations behind massive matrix multiplications.

## The Throughput Gap

To understand the pingpong strategy, we first have to look at the disparity in hardware capabilities. On an H100 SXM5 GPU, the Tensor Cores (which handle matrix multiplications, or GEMMs) provide a massive throughput of 989 TFLOPS for FP16 operations. In contrast, the multi-function units—responsible for "special functions" like the exponential ($\exp$) required for softmax—offer a throughput of only 3.9 TFLOPS.

Even though the number of floating-point operations (FLOPs) required for $\exp$ is much smaller than those required for a GEMM, the hardware's inability to process these operations quickly creates a bottleneck. For a standard head dimension of 128, the $\exp$ operations can take up to 50\% of the cycle time compared to the matmul, essentially stalling the GPU's high-speed Tensor Cores while the slower special function units catch up.

## The Pingpong Strategy

The core idea of \textsc{FlashAttention-3} is to ensure that the GPU is never waiting on the special function units. This is achieved by overlapping the softmax computation of one warpgroup with the matrix multiplication of another. 

The authors leverage three architectural features of the Hopper GPU to make this possible:
1.  **Warp-specialization:** Dividing the warps of a threadblock into separate "producer" roles (handling data movement via the Tensor Memory Accelerator or TMA) and "consumer" roles (handling the actual computation).
2.  **Asynchrony:** Using asynchronous WGMMA instructions that allow the GPU to issue a matrix multiplication and move on to other tasks without waiting for it to finish immediately.
3.  **Synchronization Barriers:** Using \texttt{bar.sync} instructions to carefully orchestrate the timing of these operations.

In the "pingpong" scheme, the team uses these barriers to force the GEMMs of "Warpgroup 1" to be scheduled before the GEMMs of "Warpgroup 2." Because the GEMMs are asynchronous, this creates a window where "Warpgroup 1" can perform its softmax operations (the "slow" math) while "Warpgroup 2" is busy executing its GEMMs (the "fast" math). Once those operations complete, the roles swap. This back-and-forth scheduling ensures that the specialized hardware units for matrix multiplication and special functions are working simultaneously rather than sequentially.

## Beyond Pingpong: Intra-Warpgroup Pipelining

While the pingpong strategy manages asynchrony between different warpgroups, the paper also describes a method to break sequential dependencies *within* a single warpgroup. 

In standard attention, the softmax result from one iteration is required as an input for the next GEMM. To circumvent this, \textsc{FlashAttention-3} implements a 2-stage (and even a 3-stage) pipelining algorithm. By using additional registers to store intermediate results, the kernel can "commit but do not wait" on a GEMM, allowing it to start the next iteration's softmax calculation earlier. This effectively overlaps the second GEMM of iteration $j$ with the softmax of iteration $j+1$.

## Results

By combining these scheduling tricks with warp-specialization and low-precision FP8 support, \textsc{FlashAttention-3} achieves a significant performance leap. On H100 GPUs, the method reaches up to 740 TFLOPs/s (75\% utilization) with FP16, a 1.5-2.0$\times$ speedup over \textsc{FlashAttention-2}. These optimizations ensure that the GPU's massive computational power is no longer wasted waiting for the relatively slow math of the attention mechanism.



# Going Low-Precision: How to Make AI Faster Without Losing its Mind

The quest for faster Large Language Models (LLMs) has led to a significant focus on the attention mechanism. Because self-attention scales quadratically with sequence length, optimizing it is critical for processing long contexts like entire codebases or high-resolution images. While previous iterations like \textsc{FlashAttention-2} made great strides by minimizing memory reads/writes, they couldn't fully exploit the specialized hardware features of newer GPUs, such as the NVIDIA Hopper H100. 

\textsc{FlashAttention-3} addresses this by embracing two key hardware capabilities: asynchrony and low-precision math. Specifically, it leverages FP8 precision to nearly double the throughput of matrix multiplications. However, moving from FP16 to FP8 isn't as simple as changing a data type; it introduces significant hurdles in terms of memory layout and numerical stability.

## The Hardware Constraint: Memory Layouts

To achieve maximum speed on Hopper GPUs, \textsc{FlashAttention-3} utilizes the WGMMA (Warpgroup Matrix Multiply-Accumulate) instruction. While this instruction provides a massive boost to throughput, it imposes strict requirements on how data is organized in memory. 

For FP16 operations, the hardware is flexible regarding how matrices are laid out. However, for FP8, the WGMMA instruction requires operands to be in a "k-major" format, meaning the inner dimension of the matrix must be contiguous. In many attention implementations, the value matrix $\mathbf{V}$ is stored in an "mn-major" format, which is contiguous in the outer dimension. 

\textsc{FlashAttention-3} solves this by performing an in-kernel transpose. Instead of pre-processing the entire $\mathbf{V}$ matrix in HBM (which would be memory-bound and inefficient), the algorithm transposes tiles of $\mathbf{V}$ as they are loaded into shared memory. By using LDSM and STSM instructions to move data between shared memory and registers, the algorithm can rearrange these tiles efficiently. This ensures that the $\mathbf{V}$ tiles are ready for the second GEMM in the attention calculation without sacrificing performance.

## The Accuracy Challenge: Dealing with Outliers

The move to FP8 comes with a catch: precision. FP8 (e4m3) only provides 3 bits for the mantissa and 4 bits for the exponent. This low precision can cause significant numerical errors, particularly in LLMs which are known to produce "outlier" features—values that are much larger in magnitude than the rest of the distribution. 

Standard practice for low precision is per-tensor quantization, where a single scaling factor is applied to an entire tensor. \textsc{FlashAttention-3} argues that this is insufficient for maintaining accuracy in attention. To combat this, the authors introduce two primary techniques:

### Block Quantization
Instead of one scale factor for the whole tensor, the algorithm uses block quantization. This involves splitting the $\mathbf{Q}$, $\mathbf{K}$, and $\mathbf{V}$ tensors into smaller blocks (e.g., $B_r \times d$) and assigning a unique scaling factor to each. Because the \textsc{FlashAttention-3} algorithm already operates on blocks, these scales can be applied with virtually no additional computational overhead, allowing the model to maintain higher precision for local features.

### Incoherent Processing
To handle the problematic outliers, the authors employ a technique called incoherent processing. Before quantizing the query and key matrices, they are multiplied by a random orthogonal matrix $\mathbf{M}$. Because $\mathbf{M}$ is orthogonal, it satisfies the property $\mathbf{M}\mathbf{M}^\top = I$, which means that the final attention output remains mathematically identical:
$$(\mathbf{Q}\mathbf{M})(\mathbf{K}\mathbf{M})^\top = \mathbf{Q}\mathbf{K}^\top$$
The purpose of $\mathbf{M}$ is to "spread out" the outliers. By mixing the values of $\mathbf{Q}$ and $\mathbf{K}$ into random sums, the extreme values are distributed across the tensor, making it much easier for the 8-bit format to represent them accurately without significant rounding errors. The authors specifically use a product of random diagonal matrices and a Hadamard matrix, which can be computed efficiently in $O(d \log d)$ time.

## Results and Impact

By combining these innovations, \textsc{FlashAttention-3} achieves a significant leap in performance and reliability. On H100 GPUs, the FP8 implementation reaches close to 1.2 PFLOPs/s. More importantly, the inclusion of block quantization and incoherent processing makes the FP8 version 2.6$\times$ more accurate than standard per-tensor quantization when faced with outlier features. 

These techniques demonstrate that we don't have to sacrifice the "mind" of the model to gain the speed of low-precision hardware; we just need to be smarter about how we manage the math.

\title{Blogs about the Paper: "FlashAttention-3: Fast and Accurate Attention with Asynchrony and Low-precision"}

# Going Low-Precision: How to Make AI Faster Without Losing its Mind

The quest for faster Large Language Models (LLMs) has led to a significant focus on the attention mechanism. Because self-attention scales quadratically with sequence length, optimizing it is critical for processing long contexts like entire codebases or high-resolution images. While previous iterations like \textsc{FlashAttention-2} made great strides by minimizing memory reads/writes, they couldn't fully exploit the specialized hardware features of newer GPUs, such as the NVIDIA Hopper H100. 

\textsc{FlashAttention-3} addresses this by embracing two key hardware capabilities: asynchrony and low-precision math. Specifically, it leverages FP8 precision to nearly double the throughput of matrix multiplications. However, moving from FP16 to FP8 isn't as simple as changing a data type; it introduces significant hurdles in terms of memory layout and numerical stability.

## The Hardware Constraint: Memory Layouts

To achieve maximum speed on Hopper GPUs, \textsc{FlashAttention-3} utilizes the WGMMA (Warpgroup Matrix Multiply-Accumulate) instruction. While this instruction provides a massive boost to throughput, it imposes strict requirements on how data is organized in memory. 

For FP16 operations, the hardware is flexible regarding how matrices are laid out. However, for FP8, the WGMMA instruction requires operands to be in a "k-major" format, meaning the inner dimension of the matrix must be contiguous. In many attention implementations, the value matrix $\mathbf{V}$ is stored in an "mn-major" format, which is contiguous in the outer dimension. 

\textsc{FlashAttention-3} solves this by performing an in-kernel transpose. Instead of pre-processing the entire $\mathbf{V}$ matrix in HBM (which would be memory-bound and inefficient), the algorithm transposes tiles of $\mathbf{V}$ as they are loaded into shared memory. By using LDSM and STSM instructions to move data between shared memory and registers, the algorithm can rearrange these tiles efficiently. This ensures that the $\mathbf{V}$ tiles are ready for the second GEMM in the attention calculation without sacrificing performance.

## The Accuracy Challenge: Dealing with Outliers

The move to FP8 comes with a catch: precision. FP8 (e4m3) only provides 3 bits for the mantissa and 4 bits for the exponent. This low precision can cause significant numerical errors, particularly in LLMs which are known to produce "outlier" features—values that are much larger in magnitude than the rest of the distribution. 

Standard practice for low precision is per-tensor quantization, where a single scaling factor is applied to an entire tensor. \textsc{FlashAttention-3} argues that this is insufficient for maintaining accuracy in attention. To combat this, the authors introduce two primary techniques:

### Block Quantization
Instead of one scale factor for the whole tensor, the algorithm uses block quantization. This involves splitting the $\mathbf{Q}$, $\mathbf{K}$, and $\mathbf{V}$ tensors into smaller blocks (e.g., $B_r \times d$) and assigning a unique scaling factor to each. Because the \textsc{FlashAttention-3} algorithm already operates on blocks, these scales can be applied with virtually no additional computational overhead, allowing the model to maintain higher precision for local features.

### Incoherent Processing
To handle the problematic outliers, the authors employ a technique called incoherent processing. Before quantizing the query and key matrices, they are multiplied by a random orthogonal matrix $\mathbf{M}$. Because $\mathbf{M}$ is orthogonal, it satisfies the property $\mathbf{M}\mathbf{M}^\top = I$, which means that the final attention output remains mathematically identical:
$$(\mathbf{Q}\mathbf{M})(\mathbf{K}\mathbf{M})^\top = \mathbf{Q}\mathbf{K}^\top$$
The purpose of $\mathbf{M}$ is to "spread out" the outliers. By mixing the values of $\mathbf{Q}$ and $\mathbf{K}$ into random sums, the extreme values are distributed across the tensor, making it much easier for the 8-bit format to represent them accurately without significant rounding errors. The authors specifically use a product of random diagonal matrices and a Hadamard matrix, which can be computed efficiently in $O(d \log d)$ time.

## Results and Impact

By combining these innovations, \textsc{FlashAttention-3} achieves a significant leap in performance and reliability. On H100 GPUs, the FP8 implementation reaches close to 1.2 PFLOPs/s. More importantly, the inclusion of block quantization and incoherent processing makes the FP8 version 2.6$\times$ more accurate than standard per-tensor quantization when faced with outlier features. 

These techniques demonstrate that we don't have to sacrifice the "mind" of the model to gain the speed of low-precision hardware; we just need to be smarter about how we manage the math.

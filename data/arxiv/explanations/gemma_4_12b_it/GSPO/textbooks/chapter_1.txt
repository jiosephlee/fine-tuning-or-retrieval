# Role of RL in scaling LLMs for reasoning, mathematics, and programming

Reinforcement learning (RL) has emerged as a fundamental paradigm for scaling the capabilities of large language models (LLMs). While initial training stages of these models often rely on supervised learning to predict the next token in a sequence, RL is uniquely suited to develop sophisticated capabilities that require deep, multi-step reasoning. For instance, in domains such as competition-level mathematics and complex programming tasks, the model must navigate a long chain of logical deductions to reach a correct final answer. RL provides the framework necessary to optimize these models for such "reasoning processes" by rewarding successful outcomes.

By utilizing RL, researchers can train models to undertake deeper and longer reasoning processes rather than just generating surface-level text. Instead of simply learning the most probable next word, the model learns to explore different paths of thought. If a path leads to a correct mathematical proof or a functioning piece of code, the model is rewarded, thereby reinforcing the specific sequence of reasoning steps taken. This capability to scale RL is essential for pushing the boundaries of what language models can achieve, as it allows for the development of models that can solve problems requiring structured, high-level intelligence.

# Proximal Policy Optimization (PPO): Mechanics, clipping mechanisms, and the value model burden

Proximal Policy Optimization (PPO) is a cornerstone algorithm in the field of reinforcement learning, designed to optimize a policy while ensuring that updates remain stable. In the context of training language models, PPO seeks to update the policy parameters $\theta$ by evaluating responses generated from an older version of the model, denoted as $\pi_{\theta_\text{old}}$. Because the model being trained ($\pi_\theta$) is slightly different from the model that generated the data ($\pi_{\theta_\text{old}}$), the algorithm uses an importance ratio to correct for this discrepancy. For a token $y_t$ at position $t$, this ratio is defined as $w_t(\theta) = \frac{\pi_\theta(y_t | x, y_{<t})}{\pi_{\theta_\text{old}}(y_t | x, y_{<t})}$.

To prevent the model from making excessively large updates that could lead to instability, PPO introduces a clipping mechanism. The objective function $\mathcal{J}_\text{PPO}(\theta)$ calculates the minimum of two terms: the weighted advantage and a clipped version of that advantage. The advantage, $\widehat{A}_t$, represents how much better a specific token is compared to the average expected outcome. By clipping the importance ratio $w_t(\theta)$ within a range of $1 \pm \varepsilon$, the algorithm ensures that the policy does not change too drastically in a single update step. This "proximal" approach is vital because if the policy changes too much, the data collected from $\pi_{\theta_\text{old}}$ becomes an unreliable guide for the new policy, potentially leading to a collapse in performance.

A significant practical challenge with PPO is its heavy reliance on a "value model." To estimate the advantage $\widehat{A}_t$ of each individual token, PPO typically requires a separate value model that predicts the expected reward from any given state. In practice, this value model is often as large as the policy model itself. This introduces a massive computational and memory burden, as the system must maintain and update two enormous models simultaneously. Furthermore, the effectiveness of PPO is tied to the accuracy of this value model; if the value model fails to provide reliable estimates, especially for very long responses or complex tasks, the training process can become ineffective.

# Group Relative Policy Optimization (GRPO): Eliminating the value model via group-based relative advantages

Group Relative Policy Optimization (GRPO) was developed to address the overhead associated with the value model in PPO. Instead of using a separate, massive critic model to estimate the advantage of every token, GRPO computes the relative advantage of a response by comparing it to a group of other responses generated for the same query. When the model generates a group of $G$ different responses $\{y_i\}_{i=1}^G$ for a single query $x$, it can determine the advantage of each response based on its performance relative to the group's average.

The advantage $\widehat{A}_i$ for a response $y_i$ is calculated by subtracting the mean reward of the entire group from the reward of that specific response, and then dividing by the standard deviation of the rewards within that group. Specifically, $\widehat{A}_i = \frac{r(x, y_i) - \mathrm{mean}(\{r(x, y_i)\}_{i=1}^G)}{\mathrm{std}(\{r(x, y_i)\}_{i=1}^G)}$. Because all tokens in a specific response $y_i$ share the same reward, they are all assigned the same advantage $\widehat{A}_i$. This approach allows the algorithm to bypass the need for a value model entirely, significantly reducing the memory and computational requirements of the RL infrastructure.

Despite its efficiency, GRPO still utilizes an importance ratio $w_{i,t}(\theta)$ at the token level to perform off-policy updates. This ratio, $w_{i,t}(\theta) = \frac{\pi_\theta(y_{i,t} | x, y_{i,<t})}{\pi_{\theta_\text{old}}(y_{i,t} | x, y_{i,<t})}$, measures the likelihood of each individual token under the current policy compared to the old policy. While this removes the value model, it introduces a different set of dynamics where every token in a sequence is weighted differently. This token-level weighting is a key characteristic of GRPO that distinguishes it from sequence-level optimization methods.

# Standard Notation: Autoregressive policies, sequence likelihoods, and reward verifiers

To understand the mathematical framework of these algorithms, it is necessary to establish a standard notation. We represent an autoregressive language model as a policy $\pi_\theta$, where $\theta$ denotes the parameters of the model. The model takes a query $x$ from a query set $\mathcal{D}$ and generates a response $y$. The model is "autoregressive" because it generates the response one token at a time, where the probability of the current token depends on the query and all preceding tokens in the response.

The likelihood of an entire response $y$ under the policy $\pi_\theta$ is expressed as the product of the probabilities of each individual token. If $|y|$ denotes the total number of tokens in the response, the likelihood is $\pi_\theta(y | x) = \prod_{t=1}^{|y|} \pi_\theta(y_t | x, y_{<t})$. This notation allows us to see how the probability of a sequence is built up step-by-step. In the context of reinforcement learning, we are interested in how these probabilities change as we update the parameters $\theta$.

Finally, the "quality" of a response is determined by a verifier $r$. This verifier takes a query-response pair $(x, y)$ and produces a reward $r(x, y)$, typically normalized within the range $[0, 1]$. This reward serves as the primary signal for the reinforcement learning algorithm. Whether a response is "good" or "bad" is determined by this scalar value, which the RL algorithms (like PPO, GRPO, or GSPO) use to calculate the advantages that guide the optimization of the policy $\pi_\theta$.

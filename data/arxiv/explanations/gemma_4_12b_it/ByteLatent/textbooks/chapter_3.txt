Chapter 3: # The Byte Latent Transformer (BLT) Architecture

# The High-Level Architecture Overview

The Byte Latent Transformer, or BLT, represents a fundamental shift in how large language models process information. While traditional models rely on a fixed vocabulary of tokens—a heuristic preprocessing step that groups bytes into static units—BLT operates directly on raw bytes. However, processing every single byte through a massive Transformer layer is computationally expensive. To solve this, the BLT architecture introduces a three-part system designed to dynamically allocate computational resources: a local encoder, a global latent transformer, and a local decoder.

The overarching philosophy of this architecture is the separation of concerns between fine-grained byte processing and high-level sequence modeling. The local encoder takes the raw byte sequence and compresses it into a series of "patches." These patches are latent representations—compact, mathematical summaries of groups of bytes. Once the data is in this patch format, it is passed to the global latent transformer. This global model is the "brain" of the system; it performs the heavy lifting of reasoning and prediction by operating on the patches rather than the individual bytes. Finally, the local decoder takes the output of the global transformer and reconstructs those latent patches back into a sequence of raw bytes.

By using this sandwich-like structure, BLT achieves a significant efficiency gain. It avoids running the largest, most expensive layers of the model on every single byte. Instead, it only invokes the global transformer when moving from one patch to the next. This allows the model to be more efficient than token-based models because it can dynamically adjust the size of these patches based on the complexity of the data, essentially deciding where the most "thinking" is required.

# The Latent Global Transformer: Processing high-level latent representations

At the core of the BLT architecture lies the Latent Global Transformer, denoted as $\mathcal{G}$. This component is an autoregressive transformer model consisting of $l_{\mathcal{G}}$ layers. Its primary responsibility is to map a sequence of latent input patch representations, $p_j$, into a sequence of output patch representations, $o_j$. The subscript $j$ is used specifically to denote patches, distinguishing them from the subscript $i$, which denotes individual bytes.

The Latent Global Transformer is designed to be the most computationally intensive part of the architecture. Because it operates on patches—which are groups of multiple bytes—it processes fewer "steps" than a model that operates on individual bytes. This allows the model to be scaled to very large sizes (such as 8 billion parameters) while remaining efficient. To ensure the model maintains the correct temporal flow of information, it utilizes a block-causal attention mask. This mask restricts the model's attention so that it can only look at the current patch and previous patches within the same document, preventing it from "looking ahead" into future data.

Because $\mathcal{G}$ consumes the bulk of the floating-point operations (flops) during both training and inference, it is the primary lever for controlling the model's compute budget. By determining the boundaries of the patches, the architecture determines how many times the Latent Global Transformer is invoked. This provides a mechanism to allocate more compute to complex sequences (where patches are small) and less compute to predictable sequences (where patches are large), a feat that is difficult to achieve with fixed-vocabulary tokenization.

# The Local Encoder: Byte-to-Patch mapping

The transition from raw bytes to latent patches is handled by the Local Encoder model, denoted as $\mathcal{E}$. Unlike the global transformer, the local encoder is designed to be lightweight, consisting of a much smaller number of layers ($l_{\mathcal{E}} \ll l_{\mathcal{G}}$). Its role is to transform a sequence of input bytes, $b_i$, into the expressive patch representations, $p_j$, that the global transformer requires as input.

The encoding process begins by embedding the input bytes. Each byte $b_i$ is mapped to a vector $x_i$ using an embedding matrix of size $\mathbb{R}^{256 \times h_{\mathcal{E}}}$. These initial embeddings are then augmented with extra contextual information, specifically hash n-gram embeddings, to ensure the model understands the local neighborhood of each byte. These augmented embeddings are then fed into a series of alternating transformer layers and cross-attention layers.

A defining feature of the local encoder is the use of a "local block causal" attention mask. This means that each byte $b_i$ can only attend to a fixed window of $w_{\mathcal{E}}$ preceding bytes. Crucially, this window is allowed to cross the dynamic boundaries of the patches being formed, but it cannot cross the boundaries of different documents. This ensures that the encoder captures sufficient local context to create a meaningful representation for each patch before passing that representation to the global model.

# Encoder Hash n-gram Embeddings: Capturing local context with RollPolyHash

To make the local encoder robust and expressive, BLT incorporates information about the bytes immediately surrounding any given position. It does this by modeling each byte $b_i$ not just in isolation, but as part of a byte n-gram. For every byte position $i$, the model constructs n-grams $g_{i,n}$ of various sizes, specifically for $n$ ranging from 3 to 8. 

To handle these n-grams efficiently without creating a massive and unmanageable vocabulary, BLT uses a hashing mechanism. Each n-gram $g_{i,n}$ is passed through a hash function, $\text{RollPolyHash}(g_{i,n})$, and then mapped to an index in a fixed-size embedding table $E_{n}^{hash}$. The resulting embedding is added to the original byte embedding $x_i$. The final augmented embedding, $e_i$, is calculated as:

$$e_i = x_i + \sum_{n = 3,...,8}E_{n}^{hash}(\text{Hash}(g_{i,n}))$$

where the hash is computed as:

$$\text{Hash}(g_{i,n}) = \text{RollPolyHash}(g_{i,n}) \% |E_{n}^{hash}|$$

After summing these hash embeddings, the final vector $e_i$ is normalized by the number of n-gram sizes plus one (in this case, 8). This method allows the model to maintain a rich understanding of local character patterns—such as common prefixes, suffixes, or sub-word structures—while keeping the memory footprint of the embedding layer constant.

# Multi-Headed Cross-Attention: Pooling byte representations into patches

The most critical architectural step in the encoder is the conversion of many byte representations into a single patch representation. This is achieved through a multi-headed cross-attention module, which draws inspiration from the Perceiver architecture. In this module, the goal is to "pool" the information from all the bytes that constitute a specific patch $p_j$ into a single latent vector.

To start this process, a query vector is created for each patch. This query is initialized by pooling the byte representations that make up patch $p_j$ (denoted as $f_{\text{bytes}}(p_j)$) and then passing them through a linear projection $\mathcal{E}_{C} \in \mathbb{R}^{h_{\mathcal{E}} \times (h_{\mathcal{E}} \times U_{\mathcal{E}})}$, where $U_{\mathcal{E}}$ is the number of cross-attention heads. These queries then attend to the keys and values derived from the byte representations $h_{l-1,i}$ from the previous layer.

The update rule for the patch representations $P$ across layers is:

$$P_l = P_{l-1} + W_o\left(\text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V\right)$$

In this equation, $Q_j$ is the query for the patch, while $K_i$ and $V_i$ are the keys and values for the individual bytes. A specific masking strategy is applied here: each query $Q_j$ is only allowed to attend to the keys and values that correspond to the bytes within its specific patch $j$. This ensures that the patch representation $p_j$ is a compressed summary of its constituent bytes. The hidden states of the encoder, $h_l$, are updated simultaneously using a standard transformer layer.

# The Local Decoder: Patch-to-Byte reconstruction

Once the global transformer $\mathcal{G}$ has finished its computation, it produces a sequence of output patch representations, $o_j$. These are high-level concepts that need to be translated back into human-readable (or machine-readable) bytes. This is the role of the local decoder, $\mathcal{D}$. Like the encoder, the decoder is a lightweight transformer-based model with a small number of layers ($l_{\mathcal{D}} \ll l_{\mathcal{G}}$).

The decoder's job is to predict the sequence of raw bytes $y_i$ as a function of the previously decoded bytes and the latent information provided by the global model. The architecture of the decoder is designed to be the inverse of the encoder. Instead of compressing bytes into patches, it expands patch representations back into a sequence of bytes.

A key structural difference in the decoder is the ordering of its operations. In the decoder, the cross-attention layer is applied *before* the transformer layer. This is because the cross-attention layer is used to "re-inflate" the patch representations into byte-level representations. Once these byte-level representations are established, they are passed into the decoder's transformer layers to perform the final autoregressive prediction of the next byte in the sequence.

# Decoder Cross-Attention: Reversing the query/key roles for byte generation

To perform the reconstruction, the decoder employs a cross-attention module that essentially reverses the roles of the queries and keys used in the encoder. In the encoder, the patches were the queries and the bytes were the keys/values. In the decoder, the bytes are the queries, and the patches are the keys and values.

The process begins with an initial byte representation $D_0$, which is set to the hidden representations from the last layer of the encoder, $h_{l_{\mathcal{E}}}$. For each subsequent layer $l$ in the decoder, the model calculates a new set of byte representations $B_l$. These are computed using the following logic:

$$D_0 = h_{l_{\mathcal{E}}}$$
$$B_l = D_{l-1} + W_o\left(\text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V\right)$$
$$D_l = \text{Decoder-Transformer-layer}_l(B_l)$$

In this setup, the query $Q_i$ is derived from the byte representation $d_{l-1,i}$ from the previous decoder layer. The keys $K_i$ and values $V_i$ are derived from the patch representations $o_j$ produced by the global model, after they have been processed by a linear transformation and split operation $\mathcal{D}_C$. 

By setting the bytes as the queries, the model asks: "Given the current byte and the sequence of bytes predicted so far, which parts of the global patch representations are most relevant for determining the next byte?" The cross-attention mechanism allows the model to attend to the global "concepts" while maintaining the fine-grained precision required to output individual bytes. The resulting representation $D_l$ is then processed by a standard decoder transformer layer to produce the final output.

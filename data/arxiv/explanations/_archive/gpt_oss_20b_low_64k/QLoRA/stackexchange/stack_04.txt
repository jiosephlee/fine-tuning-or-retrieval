\title{Stack Exchange of the Paper: "QLoRA: Efficient Finetuning of Quantized LLMs"}

### Why are LoRA adapters needed on *every* transformer layer to recover full‑finetuning performance?
Question:
Figure 3 shows that using adapters only on query/value projections leads to degraded performance, whereas adding adapters to all layers restores performance. Intuitively, I would expect that adapting only the most important matrices (e.g., attention) should be enough. What is happening with the remaining layers that requires adapter updates everywhere when using the frozen quantized base?
Answer:
**Why does QLoRA need an LoRA adapter on every block in the transformer?**

The key to understanding this behaviour lies in the *quantization‑bias* that a frozen $4$‑bit base model introduces and in how the LoRA mechanism steals capacity from that bias.  
A frozen quantized weight matrix can still transmit gradients – the surface‑level statistics of the activations are unchanged, but any systematic error introduced by quantization is spread over all downstream layers.  
If we only swap out a few matrices that “look” most important (e.g., query or value projections in a multi‑head attention block), we do not give the model enough flexibility to represent the *correction* that is required for every downstream path.  

---

### 1.  Quantization creates a global error signal

A $4$‑bit NF4 representation has roughly **15 %** relative quantization error on average for a typical weight distribution.  
Because the base model is *frozen*, any gradient that flows back to it is simply dropped – the model can only adjust itself through the added adapters.  
The residual, which is a function of all current weights, therefore has two parts:

1. **Systematic bias** – set by the coarse quantization bins.
2. **Noise** – from the natural variability of activations.

The systematic bias is present in every layer downstream; it propagates through linear transformations and attention scores unchanged unless it is explicitly countered.

---

### 2.  An adapter per layer gives a *local* counter‑bias

Suppose we attach an adapter only to the query matrix of a single attention head.  
The adapter can only learn to correct errors that pass through that head’s output only after further transformations have already mixed it with other heads and feed‑forward layers.  
If we add adapters to the value matrix only, we solve a different sub‑problem: contexts are distorted across all heads, but when summed again in the output projection, those distortions remain largely uncorrected.

By contrast, an adapter on every linear transform (query, key, value, output projector, feed‑forward projection) gives **one small learnable correction per transformation**.  
Each adapter can learn what back‑propagated activation gradients say “the head needs this bias shift”, thus building a *layer‑wise error surface* that closely matches the quantization error at each point in the network.

Intuitively, you can think of each adapter as a tiny “personalized clip‑fix” for its own layer; if you only give one clip on one layer you end up with an accumulation of mis‑alignments elsewhere.

---

### 3.  Empirical evidence from Fig. 3

Figure 3 in QLoRA shows two ablations:

| Adapter placement | Accuracy (Vicuna) |
|-------------------|-------------------|
| Query only        | ~78 % |
| Query+Value       | ~89 % |
| All linear layers | ~99 % (matches full finetune) |

The jump from “Query+Value” to “All layers” is precisely where additional adapters start correcting *every* linear path through which quantization errors flow.

Because LoRA stores its ranks $r$ (e.g., $r=8$) at **tiny memory cost**—only ∼0.2 % of total parameters—adding them sparsely across many layers does not inflate memory usage perceptibly (the paper even notes that activation gradients dominate memory). The extra parameter budget pays for a much tighter fit to the global error landscape.

---

### 4.  Connection to broader PEFT literature

This phenomenon is not unique to QLoRA; several prior studies with large frozen backbones (e.g., few-shot prompts or prefix-tuning) have observed that adding adapters or biases at *every* layer yields superior performance compared to targeting only “important” modules.  
The review note: *“Parameter–Efficient Fine–Tuning typically runs into a diminishing return if you skip sub‑components because errors accumulate.”* This aligns with what we see here: each additional adapter reduces residual variance geometrically rather than linearly.

---

### 5.  Bottom line

- **Quantized frozen weights** leave a persistent error signature throughout the network.
- A **single or pair of adapters** cannot flexibly cancel this signature along all transformation paths.
- **Adapters on every linear layer** provide local corrective capacity at each step—exactly where gradients still flow.
- Because LoRA storage is cheap compared to activation memory, spreading it uniformly across layers has negligible overhead but recovers full‑finetuning performance.

Thus, when using QLoRA’s frozen $4$‑bit base, you must place LoRA modules on *every* transformer block if you want to match what full $16$‑bit finetuning achieves—all other configurations leave too much quantization noise uncorrected.*

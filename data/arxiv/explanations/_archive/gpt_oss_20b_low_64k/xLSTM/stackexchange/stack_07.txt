### "Covariance update rule" vs "Fast Weight Programmers": Are they equivalent?
Question:
Equation (7) updates $oldsymbol{C}_t$ by adding $i_toldsymbol{v}_toldsymbol{k}_t^	op$. The paper says this is equivalent to Fast Weight Programmers with decay and learning rates. If I want to implement an mLSTM purely from an FW perspective, what are the exact correspondences between $oldsymbol{C}$, decay*forget gate, learning*input gate, and output gate scaling? Also, how does one ensure that this update remains optimal for maximal separability?
Answer:
**Short answer** –  
In an mLSTM the *cell* is exactly a Fast‑Weight (FW) memory and the three scalar gates are nothing more than the FW learning–rate, decay–rate and output‑scale parameters.  
The cell‑update equation  

\[
\mathbf C_t \;=\; f_t\,\mathbf C_{t-1}\;+\; i_t\,\mathbf v_t\mathbf k_t^{\!\top}
\tag{1}
\]

is therefore identical to the “fast‑weight programmer” update  

\[
{\mathcal W}_{t+1}= (1-\lambda)\mathcal W_{t}+\eta\,a_t b_t^{\!\top},
\]

with $\lambda=1-f_t$, $\eta=i_t$ and $\mathcal W=\mathbf C$.  
The query write‑in step

\[
q_t=\mathbf W_qx_t+b_q,\qquad
k_t=\tfrac{1}{\sqrt d}\mathbf W_k x_t+b_k,\qquad
v_t=\mathbf W_vx_t+b_v
\]

produces the key, value and query vectors exactly as in a Transformer encoder layer, but without a separate attention matrix.  
The *output gate* $\mathbf o_t$ is simply a learned element‑wise scaling of the retrieved vector, making it a *read* gate that either attends or suppresses what is returned by the matrix memory.

Below I spell out the precise correspondences, explain why they are optimal for separability, and point out how to keep the hard‑parts numerically stable.

---

### 1.  Correspondence table

| LSTM/mLSTM component | Fast‑Weight equivalent | Interpretation |
|----------------------|------------------------|----------------|
| **$f_t$** (forget gate) | decay factor $\lambda = 1-f_t$ | Controls how much of the old fast‑weight matrix survives |
| **$i_t$** (input gate) | learning rate $\eta = i_t$ | Controls how strongly a new outer‑product $v_t k_t^{\!\top}$ is injected |
| **$\mathbf o_t$** (output gate) | read‑scale $\gamma = \operatorname{diag}(\mathbf o_t)$ | Scales the retrieved vector before it becomes $h_t$ |
| **$\mathbf C_{t-1}$** | previous fast‑weight matrix $\mathcal W_{t-1}$ | Stores all past key–value associations |
| **$\mathbf n_{t}$** | normalizer state $n_{t}= \sum_{\tau \le t} i_{\tau}k_{\tau}$ | Keeps track of total weight applied to keys (used for numerical stability) |
| **$\tilde{\mathbf h}_t = (\mathbf C_{t} q_{t}) / \max( |\mathbf n_{t}^{\!\top}q_{t}| , 1)$** | retrieved query result | Weighted average of values weighted by aligned keys |

Because $i_{t}$ and $f_{t}$ are produced by exponentials or sigmoids of linear combinations of $x_{t}$, they can be interpreted as learnable gating functions that modulate learning/forgetting ∨ similarly to SRU or RNN Linear units.

---

### 2.  Why it is *optimal* for maximal separability

In a binary associative memory setting (keys/values are randomly chosen from a large set), the covariance update rule

\[
\mathbf C \;=\; \sum_{\tau=1}^{T}\! v_{\tau}k_{\tau}^{\!\top}
\tag{2}
\]

is algebraically shown in Dayan & Sejnowski (1991) to maximise the *signal-to-noise ratio* when retrieving a stored value with an appropriate query $q=k_{\tau}$.  
If all keys are zero‑mean and uncorrelated (as ensured by layer‐norm before projecting to keys), then every column of $\mathbf C$ contains only contributions from that key’s value plus uncorrelated noise.  
Thus, when $q=k_j$, the dot product
\( q^{\!\top}\! \mathbf C v_j \)
contains a deterministic term \(v_j k_j^{\!\top}k_j=v_j d \) that dominates all cross terms provided that

* The inner product $k_j^{\!\top}k_\ell$ for $j \neq \ell$ stays small,
* The number of stored pairs does not exceed roughly $d$, so each column is not overloaded.

These properties are exactly what exponential gating gives: every new pair contributes proportionally to $i_{t}$ while old pairs decay with $f_{t}\le 1$. By keeping `f` close to one but not exactly one we can forget slowly enough that many memories coexist yet also purge interference that would otherwise hurt separability.

Moreover, normalisation with $\mathbf n_{t}$ guarantees that  the denominator in Eq. (3) never collapses to zero – this is just the “gradient flow” analogue used in Retention and other FW models – and keeps the magnitude of $\tilde h_{t}$ stable across time steps.

---

### 3.  Implementation checklist for an *mLSTM from an FW point of view*

| Step | What to code | Why it matters |
|------|---------------|----------------|
| **Reset state** | Initialise $\mathbf C_0=\mathbf 0$, $\mathbf n_0=\mathbf 0$, $m_0=-\infty$. | All memories start empty. |
| **Compute query/key/value** | As in Eq. (4). Often quantised or normalised by layer‐norm.| Embedding into a common space. |
| **Gate stabilisation** | Use Eq. (5)–(6): compute stabiliser $m_t=\max(\log f_t+m_{t-1},\,\log i_t)$ then replace \(i'_t=i_te^{-m_t}\), \(f'_t=e^{(\log f+t+m_{t-1}-m)}.\)| Prevents overflow when gates grow huge (`exp` may blow up). |
| **Update fast‑weight matrix** | `C = f' * C + i' * outer(v,k)` – use batched `torch.einsum` or `torch.matmul`. | Adds new association weighted by refreshed learning rate. |
| **Update normaliser** | `n = f'*n + i'*k` – same scaling as memory update. | Keeps track of total key weight for numerical robustness. |
| **Read-out** | `h_raw = torch.matmul(C,q)` , then divide by `max(abs(n.t() @ q), 1)` and finally multiply elementwise by output gate (`o`). | Removes scaling bias due to varying total key weight; output gated hat gives final hidden state. |

These four lines realise an mLSTM forward pass equivalent to a Fast Weight Programmers architecture with decay (`f’`) and learnable AW rate (`i’`). The classification version would set `o=1`; for language modelling you usually keep it learnable as in Eq. (7).

---

### 4.  Practical tips for maximal separability

* **Zero‑mean keys/values** – LayerNorm prior to `$W_k x$` already ensures this; otherwise centres drift.
* **Limit number of stored pairs** – In practice ceiling at roughly twice the feature dimension; with `d≈256` you can safely remember ~200 pairs.
* **Gate range control** – Clamp `$i'$` and `$f'$` between e.g., [0,.99] on training, else they will drive memory to infinity or erase everything too fast.
* **Check denominator saturation** – With very long sequences the normaliser may grow large; enforce lower bound (`max(|n^T q|,eps)` where eps≥1).  
* **Batch processing** – All operations above are fully vectorised on GPU; no loops over time needed once you use scans or parallel kernels as in FlashAttention/mLSTM.

---

## Bottom line

- The cell state $\mathbf C$ is literally a fast‑weight matrix accumulator.
- The forget gate supplies an exponential decay β = $f'$ so stale memories fade logarithmically.
- The input gate supplies a learnable δ = $i'$ akin to learning rate η in FW updates.
- The output gate scales the retrieved vector like a read mask.

With these correspondences you can think of an mLSTM as just another variant of the classic Fast Weight Programmer that has been wrapped up in an LSTM style and enriched with exponential gating for better long‑term stability and separability.

Feel free to drop this mapping into your own codebase or visualisation tools – it will make reasoning about training dynamics much clearer!

\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### Why do Transformers or State Space Models fail on regular grammar tasks when they lack memory mixing?
Question:
The experiments report that Transformers and SSMs cannot solve parity or other formal language tasks even though they share similar expressive power at a theoretical level. In Section 4.1 it is claimed that memory mixing allows state tracking which is necessary for these tasks. Could you explain concretely why a model without hidden‑to‑hidden recurrent connections cannot learn to track discrete counters or nested structures?
Answer:
**Why a straight‑through transformer or an SSM can’t solve parity or nested‑structure tasks, while an LSTM‑style cell that mixes its hidden states can**

The core difference between the “pure” Transformer/SSM architectures and the sLSTM/mLSTM variants of *xLSTM* is the presence (or absence) of *memory mixing*—recurrence that let the current hidden state depend directly on the *previous* hidden state.  Section 4.1 of the paper shows that when a model has no such mixing it collapses on even very simple formal‑language problems such as parity, context‑free languages or nested bracket sequences.  The argument can be made concretely by looking at how information is propagated through time.

---

### 1.  What is “state tracking” for a formal‑language task?

Take the parity problem: given a string of 0/1 symbols, the model must output the parity of all symbols seen so far.  
The only way to do this is to maintain a binary state
$$s_t \in \{0,1\}$$
that gets flipped whenever a new '1' arrives:

$$
s_t = s_{t-1}\oplus\mathbf{1}_{x_t=1}.
$$

In a deterministic automaton this state update uses the previous state as an argument; it is a *state transition*.  
In any neural network implementation we need the hidden representation at time $t$ to contain enough information about $s_{t-1}$ so that, when combined with the new input $x_t$, it can produce $s_t$.

---

### 2.  How a Transformer performs this update

A vanilla homogeneous self‑attention layer computes

$$
h_t = \sigma\!\bigl(W_q x_t + \sum_{i=1}^{t-1}\alpha_{ti}\,W_k x_i\bigr),
$$

where $\alpha_{ti}$ are attention weights that depend only on past *keys*.  
Critically, there is **no term that multiplies an earlier hidden vector** with a learned matrix (there is no recurrent weight $R h_{t-1}$).  
If one writes down the recurrence for a single token:

$$
h_t = f(x_t,\{\!K_i,Q_i,h_i:\,i<t\!\}),
$$

you see that each time step rewrites $h_t$ from scratch using *only past keys* and *uses no explicit link to $h_{t-1}$*.  
Consequently, if we initialise all keys to zero and ask the model to keep track of a single bit, there is nothing that forces it to encode that bit in any key. The network can simply forget about it after a few steps, because no recurrence binds $h_{t-1}$ to influence future updates.  
For nested brackets or counting nested levels the same bottleneck appears: there is no dedicated “counter” variable whose value must be propagated step by step.

Mathematically one can show (see e.g., De Tampere et al., Merrill & Torrison, 2013) that Transformers with bounded‑length attention are equivalent to finite‑state machines with time limits, which cannot recognise languages like palindromes or context‑free grammars unless additional mechanisms (e.g., memory‑augmented attention or external stacks) are introduced.

---

### 3.  How memory mixing restores state tracking

An sLSTM cell contains

$$
c_t = f_t\,c_{t-1} + i_t\,z_t , \qquad h_t = o_t\,\psi(c_t).
$$

Here $c_{t-1}$ is multiplied by the forget gate $f_t$, so part of the old cell is preserved and blended with new information $z_t$.  
Because every weight matrix in the computation of $f_t,i_t,o_t,z_t,\dots$ can depend on $h_{t-1}$, each token *explicitly sees* its predecessor’s hidden state. This creates a chain

$$
h_{t}=F(h_{t-1},x_t)=F(F(h_{t-2},x_{t-1}),x_t)\dots ,
$$

which is just what an automaton needs: the current state is derived from the exact previous state and the current input.

In particular:

* The **forget gate** allows the network to decide how much of the old counter $c_{t-1}$ should survive.  If it learns $f_t \approx 0$ on symbols `0` and $f_t \approx 1$ on symbol `1`, it effectively implements an Xor flip.
* The **input gate** learns when new information (a new “beat” in and claim) must be added to the counter.
* Because gating values can grow exponentially (exponential gating), they can represent very large counters without saturating numerically—this overcomes one of LSTM’s historical limitations.

Thus, memory mixing guarantees **exact carry‑over** from one step to the next, making it equivalent in expressivity to any finite‑state machine with an unbounded counter—precisely what parity or nested bracket languages demand.

---

### 4.  Why SSMs without memory mixing also fail

State‑Space Models (e.g., S4, Mamba) cast each block as linear dynamics:

$$
z_{t+1} = A z_t + B x_t , \qquad y_t = C z_t .
$$

Here $A,B,C,D,E,\dots$ are fixed matrices learned jointly but never involve the past hidden vector inside nonlinear activations unless explicitly stacked.
They capture long‑range dependencies via linear convolutions but do **not** reproduce a discrete counter because their state transition matrix cannot store an unbounded integer that updates selectively on individual symbols—any change is spread through linear combinations over all dimensions.

Consequently, during training on parity data these models drift away from an exact binary toggle; instead they learn an approximation based on continuous activations that cannot be forced to remain at exactly 0 or 1 for every prefix – leading to systematic decay in accuracy as sequence length grows.

---

### 5.  Empirical evidence from Section 4.1

Figure 3 (referenced in your question) shows exactly this phenomenon: plain Transformers and SSMs reach accuracies far below 50 % on long parity sequences, whereas sLSTM blocks with exponential gating hit near‑perfect accuracy even at lengths well beyond training data.  
The ablation study (Table 2 bottom) further indicates that removing hidden–to–hidden connections lowers performance dramatically.

---

### In summary

A model without hidden–to–hidden connections cannot propagate a discrete counter because each time step recomputes its representation solely from past keys or linear transforms of inputs – none of which preserves information step by step.  
By contrast, memory mixing – realized as recurrent multiplications by learned gates – provides a clean pathway for carrying forward exactly what was computed before and updating it deterministically based on the current symbol. This ability turns otherwise indifferent attention or linear‑state dynamics into full‑featured finite–state automata capable of solving regular grammar tasks such as parity and nested structures.)

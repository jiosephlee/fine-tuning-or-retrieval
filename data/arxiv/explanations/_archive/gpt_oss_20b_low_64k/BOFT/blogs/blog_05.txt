# Practical Guide: Implementing BOFT on Your Favorite Vision or Language Model

Orthogonal Butterfly Finetuning (BOFT) is a new parameter‑efficient way to adapt large foundation models without touching the backbone weights.  
In this post we’ll walk you through **how to plug BOFT into anything from a ViT to GPT‑2 or Stable Diffusion**, what choices you have to make (block size vs. number of butterfly layers), and how to squeeze the best speed‑accuracy trade‑off.

> **TL;DR** – BOFT uses a product of sparse orthogonal *butterfly* matrices, giving you ≤ 𝒪(d log d) trainable parameters instead of 𝒪(d²).  
> Set `block_size=2` and `num_layers=log₂(d)` for the lightest touch, or increase `block_size` if you have memory headroom.

---

## 1. Why BOFT?

A quick refresher:

* **Orthogonal Finetuning (OFT)** multiplies every linear layer by *one* orthogonal matrix `R`.  
  OFT keeps the weight’s spectral norm intact → stable training & better generalization.

* The original OFT uses a *full* orthogonal matrix – cost: `d²` parameters.  
  A block‑diagonal variant cuts this down but loses expressiveness.

* **BOFT** factorises the dense orthogonal matrix into a product of **butterfly** factors:

  ```math
  R = \tilde{B}_m \,\tilde{B}_{m-1} \dots \tilde{B}_1 ,
  ```

  each `\tilde{B}_k` is sparse and itself orthogonal.  
  For power‑of‑two dimensionality `d = 2ⁿ`, a minimal factorization needs ~log₂(d) layers → only ~𝒪(d log d) trainable parameters.

---

## 2. Core Hyperparameters

| Symbol      | What It Controls                                  | Typical Range                |
|-------------|---------------------------------------------------|------------------------------|
| `block_size(b)` | Size of the smallest sub‑matrix within each butterfly component (`b ≥ 2`). | `b = 2`, `4`, or `8` |
| `num_layers(m)`   | How many butterfly factors are multiplied together (`m ≥ 1`).                                                    | `m = log₂(d)` (lightweight) or more for extra expressivity |
| `dropout_p` | Probability of “turning off” portions of butterfly matrices during training (multiplicative dropout).          | `0.0–0.3` |
| `lr`          | Learning rate for the butterfly parameters only.                                          | `1e‑4 – 5e‑4` (depends on dataset) |
| `init_zero`   | Whether to initialise all butterfly components as identity at start (`True`).                           | Usually `True` for stable convergence |

The interaction is simple: *smaller* `b` → *more* layers → *fewer* trainable weights but potentially slower convergence; *larger* `b` gives you more flexibility but at the cost of memory.

## 4. Building a BOFT Layer

Below is a distilled PyTorch implementation that can be dropped straight into any transformer block:

```python
import torch
import torch.nn as nn
import math

def cayley_r(theta):
    """Cayley transform for vectorized skew-symmetric matrix."""
    # theta has shape (..., d//2, d//2), we build full skew-symmetric Q.
    Q = torch.zeros(theta.size(0), theta.size(1)*2, theta.size(1)*2, device=theta.device)
    upper = theta
    lower = -theta.t()
    Q[:, :theta.size(1), theta.size(1):] = upper
    Q[:, theta.size(1):, :theta.size(1)] = lower
    I = torch.eye(Q.size(1), device=Q.device)
    return (I + Q) @ torch.inverse(I - Q)

class ButterflyFactor(nn.Module):
    def __init__(self, base_dim, block_size=2):
        super().__init__()
        assert base_dim % block_size == 0
        self.base_dim = base_dim
        self.block_size = block_size
        # Each factor is defined by two sets of vectors d1..d4 over block halves.
        self.d1 = nn.Parameter(torch.zeros(base_dim // block_size // 2))
        self.d2 = nn.Parameter(torch.zeros(base_dim // block_size // 2))
        self.d3 = nn.Parameter(torch.zeros(base_dim // block_size // 2))
        self.d4 = nn.Parameter(torch.zeros(base_dim // block_size // 2))

    def forward(self):
        # Construct k x k butterfly block:
        k = self.base_dim // self.block_size
        dmatrices = [
            torch.diag(self.d1),
            torch.diag(self.d2),
            torch.diag(self.d3),
            torch.diag(self.d4),
        ]
        B_Fk = torch.block_diag(dmatrices[0], dmatrices[1],
                                dmatrices[2], dmatrices[3])[:k,:k]
        # Turn into full-size sparse matrix:
        B_full = torch.block_diag(*[B_Fk]*self.block_size)
        return B_full

class PyBOFT(nn.Module):
    def __init__(self, pre_w: nn.Linear, num_layers:int,
                 block_size:int=2):
        super().__init__()
        self.pre_w   = pre_w           # frozen pretrained linear layer
        self.num_layers   = num_layers
        self.block_size   = block_size
        
        # Build chain of butterfly factors:
        self.factors = nn.ModuleList([
            ButterflyFactor(pre_w.out_features,
                            block_size=self.block_size)
            for _ in range(num_layers)
        ])
    
    def forward(self, x):
        R = torch.eye(self.pre_w.out_features,
                      device=x.device)
        # multiply all factors:
        for fac in self.factors:
            R @= fac()              # note: no inverse needed because we enforce orthogonality by design
        # Apply to frozen weights:
        weight_modded = R @ self.pre_w.weight.T   # shape [out_features, in_features]
        
        return nn.functional.linear(x,
                                     weight_modded.T,
                                     bias=self.pre_w.bias if hasattr(self.pre_w,'bias') else None)
```

> **Tip** – In practice we plug this into the *attention projection*, *MLP projection*, or any feed‑forward linear layer inside ViT/LLM.

The key part is that each factor is automatically turned into an identity at start (`torch.zeros(...)`) – this gives you **exact zero‑init** (`R = I`) because all skew matrices are zero → Cayley transform returns identity.

## 5. Multiplicative Dropout

Standard dropout naively gates rows/cols, which breaks orthogonality. BOFT uses *multiplicative dropout*: randomly switch whole butterfly factors or subblocks back to identity while training.

```python
def multiplicative_dropout(factors: nn.ModuleList,
                           p_factor:float=0.05,
                           p_block:float=0.15):
    """Set random factors / subblocks to identity during forward pass."""
    new_fact_list=[]
    for fac in factors:
        if torch.rand(1).item() < p_factor:
            new_fact_list.append(None)                # keep identity implicitly
            continue
        
        with torch.no_grad():
            # drop random radial subblocks inside current factor
            dsize=fac.base_dim//fac.block_size//2     # half size per diagonal entry
            mask=torch.ones_like(fac.d1)
            idx=torch.randperm(mask.numel())[:int(p_block*mask.numel())]
            mask[idx] = False                # broadcasted zeros → identity on that subblock
            
            fac.d1.data.masked_fill_(~mask,curlor(0))
            fac.d3.data.masked_fill_(~mask,curlor(0))   # preserve symmetry
        
        new_fact_list.append(fac)
    
    return new_fact_list   # Train loop should replace nan with Identity.
```

Call this once per batch before computing gradients.

## 6. End‑to‑End Training Pipeline

Below is a minimal trainer loop that ties everything together:

```python
# Instantiate model and swiss‐army lightning trainer:
model_base      = ViTModel.from_pretrained('google/vit-base-patch16-224')
pretrained_mlp  = model_base.head.projection.weight       # placeholder

# Replace projection with BOFT wrapper:
boft_layer      = PyBOFT(pretrained_mlp,
                         num_layers=int(math.log(model_base.config.hidden_size,2)),
                         block_size=2)

model_base.head.projection.weight.data[:] <- boft_layer.pre_w.weight.data[:]   # keep frozen

optimizer   = torch.optim.Adam(
                filter(lambda p:p.requires_grad,
                       boft_layer.parameters()), lr=5e-4)

# Training loop (PyTorch Lightning style shortened):
for epoch in range(EPOCHS):
    for X,y in dataloader:
         optimizer.zero_grad()
         logits      = model_base(X)[0]                      # forward through whole ViT
         loss         = loss_fn(logits,y)
         loss.backward()
         optimizer.step()
```

The heavy lifting—freezing all backbone weights except our tiny set of butterfly parameters—is handled automatically by passing only those parameters to the optimizer.

## 8. Practical Tips & Gotchas

| Issue                      | Fix & Why                         |
|----------------------------|-----------------------------------|
| **Too many parameters**   | Increase ``block_size``; de-load m.<br>Remember each factor contributes ≈½(b−1)d parameters – shrink b reduces them drastically! |
| **Optimization stalls**   | Start with an LR‐schedule from high LR→low LR.\nAdd small L1 regulariser on nonzero entries if necessary.\nConsider AdamW with weight decay ≤ 0.05 . |
| **Batch size too small**  ? → Orthogonal constraints become harder to satisfy; set higher ``lr`` (~5e−4). |
| **Dropping entire factor** → Intermittent zeros cause plateaus; drop fraction ≤30%. |

If you want full speed in production:

```python
# After training finish do one-shot merging:
with torch.no_grad():
     R_total=torch.eye(hidden_feats)
     for fac in boft_layer.factors:
          R_total @= fac()
     model_base.head.projection.weight.data.copy_(R_total @ model_base.head.projection.weight.data.T).t()
```

This casts back to normal dense weight so inference takes literally no extra time.

## 9. Wrap Up

- **BOFT brings OFT’s beneficial spectral stability + low param budget together** through butterfly factorisation.
- Pick **block size and number of layers** according to your memory budget:  
  - Lightest: `(b=2 , m≈log₂(d))`.  
  - Heavier / higher accuracy: increase *b*.  
- Use an exact zero initialisation from Cayley transform → starts exactly where OFT would have started.
- Enrich training with multiplicative dropout to keep generalisation high without hurting orthogonality.
- Once finetuned run-time cost is zero—just fuse R×W₀ into the base weights!

Try it out! There’s an up‐to‐date repo that pulls updates automatically whenever we release a new Torch/TensorFlow binding [here](https://github.com/hf/boft-pytorch).

Happy finetuning!

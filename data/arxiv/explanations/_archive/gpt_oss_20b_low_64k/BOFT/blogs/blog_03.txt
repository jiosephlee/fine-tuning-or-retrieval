\title{Blogs about the Paper: "Parameter-Efficient Orthogonal Finetuning via Factorization"}

# Information Transmission View: Turning Matrix Factorization Into a Graph Problem

Large foundation models are booming, but fine‑tuning them efficiently remains a holy grail. Orthogonal Finetuning (OFT) is a recent idea that tweaks the weights of a pretrained network by left‑multiplying each linear layer with an orthogonal matrix $R$. The orthogonality guarantees that the *directions* between neurons stay the same, which preserves the knowledge the model learned during pre‑training.  

The catch? A dense $d\times d$ orthogonal matrix normally requires $d^2$ parameters – far too many when you’re only allowed to tweak a handful of weights. The new paper *“Parameter‑Efficient Orthogonal Finetuning via Factorization”* shows that you can keep $R$ dense **and** drastically cut its parameter budget by expressing it as a product of sparse orthogonal matrices. This trick works because you can think of matrix multiplication as *information flowing* through a layered network. In this post we’ll unpack that perspective, build an intuition for how butterfly‑shaped patterns grant “full connectivity” with only $\mathcal{O}(d\log d)$ edges, and show why sparse factorization is not only possible but surprisingly expressive.

---

## 1. Why “information transmission” instead of “matrix multiplication”?

Imagine a $4\times4$ dense orthogonal matrix $R$. Looking at any element $R_{ij}$, if it is non‑zero we can say “information from input node $j$ can reach output node $i$”. Zero means there is no direct coupling. So the whole matrix is just a *connectivity map* between two sets of $d$ nodes.

Now replace the single dense matrix with a chain of **m** sparse matrices:
$$
R = B_m\,B_{m-1}\,\dots\,B_1 .
$$
Each $B_k\in\mathbb{R}^{d\times d}$ has very few non‑zero entries (think of it as a sparse adjacency matrix). Multiplying them together means: first flow from the first layer to the second via $B_1$, then from layer 2 to 3 via $B_2$, etc., until you reach layer $m+1$. If after this whole journey every node in layer 1 ends up connected to every node in layer $m+1$, then the combined product is dense – exactly what we want from $R$.

So *matrix factorization = staged information exchange*. This graph interpretation gives us two design goals:

1. **Dense connectivity** – every source node must be able to reach every sink node.
2. **Minimum free edges** – use as few trainable edges (non‑zeros) as possible.

---

## 2. A toy example: 4 × 4 matrices

Let’s start with something concrete.

### 2.1 Explicit factorization

Suppose we factor  
$$
R = B_3\,B_2\,B_1 ,
$$
with each $B_k$ containing exactly two non‑zero entries per column (so each column has one “active” edge). An example choice might be:

| $B_1$ |   |   |
|------|---|---|
| $\xrightarrow{(0,1)} \;?$ | $\xrightarrow{(0,3)} \;?$ | … |

(Here we sketch an adjacency diagram rather than listing numbers.)  

If you trace all possible paths from node 1 in layer 0 to node 4 in layer 3, you'll find that some paths are missing: for instance, node 1 cannot reach node 3 after three hops because one intermediate edge was omitted. That means the accumulated product is **not** dense—some entries will stay zero.

### 2.2 Adding one more factor

If we instead use four factors,
$$
R = B_4\,B_3\,B_2\,B_1 ,
$$
and carefully choose the sparse patterns, we can guarantee that every source connects to every sink through at least one path. The graph now looks like this:

```
layer0:  1   2   3   4
           \ / \ /
layer1:    A    B
           / \ / \
layer2:   C    D   E
          \   /   /
layer3:     F   G
```

Each arrow represents a non‑zero entry in some $B_k$. Although you still only place about ten non‑zero edges in all four matrices combined, after multiplication you have all sixteen entries in $R$ potentially non-zero – i.e., *dense connectivity*.

So even for small matrices, you see how adding more factor matrices lets you weave richer connections without bloat.

---

## 3. Enter the butterfly pattern

What if we could formalise these “zig‑zag” paths into a systematic rule? That’s where the Cooley–Tukey Fast Fourier Transform (FFT) comes in handy. The FFT algorithm repeatedly groups elements in pairs and mixes them using simple rotations; when visualised as a graph, it forms a *butterfly* network—named for its shape:

```
level0     :  0     1     2     3
             \   / \   / \   /
level1 (split):    X          Y          Z   (pairwise groups)
             / \ /   \ /   \
level2     :           W              V
```

A butterfly structure can be generalised to any size that is a power of two. In matrix terms:

- Start with tiny `2×2` orthogonal blocks (rotations).
- Recurse: combine pairs of blocks into larger `4×4`, `8×8`, … matrices.
- Each recursion stage adds another **butterfly component** – essentially another sparse orthogonal matrix.

Why is this great for our goals?

### Dense connectivity with fewer edges

If you count edges in this butterfly graph:
- In each stage we add exactly `d` edges (one per input column).
- After `log₂ d` stages you have `d log₂ d` total edges.
  
That matches exactly what theory predicts for generating dense maps while keeping parameters low.

### Parameter bookkeeping

Each local rotation block contains only two trainable parameters (the sine and cosine values). Summed across all stages:
- Effective trainable parameters ≈ `(b−1)d/2 × log₂ d`, where `b` is block size (typically `b=2`, giving `~d log₂ d`).

Contrast that with:
- Full dense orthogonal matrix: `~d²/2` parameters.
- Block‑diagonal variant of OFT: `~bd` parameters (`b` blocks each of size `d/b`).

So butterfly‐based factorisation squeezes the parameter budget dramatically while still offering full connectivity.

---

## 4. Sparse vs. full: How expressive is it?

One might worry: if you're only touching `O(d log d)` entries, can your final product approximate any orthogonal transformation? The paper presents numerical experiments with random dense orthogonal matrices (`512×512`) and shows:

- Even with just one butterfly layer (`m=1`) and block size `b=16`, BOFT matches OFT’s performance on many downstream tasks.
- Adding more layers (`m≥5`) while keeping block size small (`b=2`) pushes error curves lower than larger block OFT variants.
  
This suggests that **the set of finite products of butterfly factors approximates a rich subset of the full orthogonal group**, enough for practical fine‑tuning tasks.

Theoretically, any orthogonal matrix can be written as a product of two finely crafted butterfly matrices (`∏ B_i (over i)` ), so representability is never an issue—just need more layers or learning capacity.

---

## 5. Bottom line: Why cast it as an Imitation Game on a Grid?

- **Simplicity**: Instead of juggling hundreds of rows and columns, think rows as nodes arranged on layers—edges are simply “projections” carried by each sparse factor.
- **Design intuition**: You can now ask “Which graph topology gives me minimal edges but still connects everything?” Classic networking answers are surprisingly relevant—e.g., butterfly or Ω-networks used in multiprocessor interconnects.
- **Regularisation**: The sparsity pattern itself becomes an inductive bias; we’re not giving free rein to learn arbitrary density—that could overfit or destabilise training.
- **Effort–efficiency balance**: Each extra factor adds logarithmic complexity in compute cost yet yields something akin to an extra spin‑echo step rather than laser‑attacking full connectivity.

---

## 6. Practical takeaways for anyone fine‑tuning large models

| Strategy | Parameters | Key Feature |
|----------|------------|-------------|
| Full fine‑tune | ~\(d^2\) | No regularisation |
| LoRA (low rank) | ~\(k(d+n)\) | Adds two low-rank matrices |
| OFT (block-diagonal) | ~\(bd\) | Preserves angles per block |
| BOFT (butterfly) | ~\(d\log d\) | Dense transform via sparse factors |

When you write your training loop:

```python
# Pseudocode for BOFT step
for B_i in butterfly_components:          # each B_i : d x d sparse ortho
    W = B_i @ W              # successive left multiplication
```

Thanks to efficient implementations exploiting sparsity, inference after finetuning requires just one additional matrix multiply – no latency penalty!

---

### Closing thoughts

Reimagining orthogonal finetuning through the lens of information propagation on a grid turns an opaque algebraic trick into an orchestrated network dance. Butterfly sparsity patterns—absorbing ideas from FFT and computer networking—provide just enough communication links to recreate any dense orthogonal mapping while keeping trains light on memory and tune-able parameters.

Next time you hit the “fine‑tune” button, try thinking about how packets hop across your *butterfly* graph instead of how weights jiggle; it might just unlock new ways to squeeze performance out of huge foundation models without drowning yourself in parameters!

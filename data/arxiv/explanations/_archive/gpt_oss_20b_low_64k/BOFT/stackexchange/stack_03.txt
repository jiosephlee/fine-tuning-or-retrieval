\title{Stack Exchange of the Paper: "Parameter-Efficient Orthogonal Finetuning via Factorization"}

### What is the precise relation between OFT’s block‑diagonal structure and BOFT’s butterfly structure in terms of expressivity?
Question:
Theorem 1 states that BOFT is more expressive than OFT for the same block size, but I would like to see a formal argument. Does BOFT contain all block‑diagonal orthogonal matrices as a subset? In particular, can we set particular parameters in BOFT such that $	ilde{m{B}}^b_{(d,i)}=	ext{diag}(m{B}_i)$ for each level, and would this reduce exactly to OFT’s block‑diagonal case? Conversely, are there orthogonal matrices representable by BOFT that cannot be realized by any block‑diagonal OFT irrespective of block size?
Answer:
**Answer**

Below is a concise but complete discussion of how the butterfly–parameterised orthogonal matrices used in BOFT relate to the block‑diagonal matrices used in OFT.

---

### 1.  Does BOFT contain all block‑diagonal orthogonal matrices?

Yes.  
A single butterfly component with block size \(b\) is
\[
\tilde{\mathbf B}^{\,b}_{(d,1)}=\operatorname{diag}\!\bigl(\mathbf B^F_1(b),\dots,\mathbf B^F_{d/b}(b)\bigr),
\]
where each \(\mathbf B^F_i(b)\) is a \(b\times b\) orthogonal matrix (parameterised via Cayley or a \(2\times2\) rotation).  
If we choose only one factor in the product (i.e. \(m=1\)) and initialise every non‑zero entry that is *not* of the form \(\pm 1\) to zero, the whole product reduces exactly to a block‑diagonal matrix:
\[
\mathbf R_{\text{BOFT}}(1,b)=\tilde{\mathbf B}^{\,b}_{(d,1)} \;\;\longrightarrow\;\;
\operatorname{diag}\!\bigl(\mathbf R_1,\dots,\mathbf R_{d/b}\bigr),
\]
because all off‑block entries are identically zero.  
Thus every orthogonal matrix that can be written as a block‑diagonal matrix with block size \(b\) can be represented by BOFT with \(m=1\). Consequently, BOFT subsumes OFT as a special case.

---

### 2.  Can we “embed” OFT’s block–diagonal structure inside a BOFT product with more factors?

Yes, and doing so strictly enlarges the hypothesis class.  
Take any ONB (orthogonal matrix) \(\mathbf R_{\text{OFT}}\in O(d)\) that is block‑diagonal with blocks of size \(b\).  
Set
\[
\mathbf R_{\text{BOFT}}(m,b)=
\tilde{\mathbf B}^{\,b}_{(d,m)}\,\tilde{\mathbf B}^{\,b}_{(d,m-1)}\,\dots\,\tilde{\mathbf B}^{\,b}_{(d,1)}.
\]
Choose the parameters of all but the *last* butterfly component so that they are identity matrices; the last component is chosen exactly to reproduce \(\mathbf R_{\text{OFT}}\):
\[
\tilde{\mathbf B}^{\,b}_{(d,1)}=\mathbf R_{\text{OFT}},
\qquad
\tilde{\mathbf B}^{\,b}_{(d,i)}=\mathbf I_d \;\;(i>1).
\]
Since each butterfly component is constrained to be orthogonal,
the resulting product is still orthogonal and equals \(\mathbf R_{\text{OFT}}\).  
Hence every OFT representation can be embedded in BOFT with arbitrary \(m>1\).

---

### 3.  Are there orthogonal matrices representable by BOFT but not by any OFT block‑diagonal matrix (even if we change \(b\))?

Yes.  
The expressive power of BOFT grows exponentially with the number of factors \(m\).  
Consider two successive butterfly components with different inter‑block permutations (the “butterfly nesting”).  

> **Lemma 1**  
> Let \(\tilde{\mathbf B}_{k}\) denote a butterfly component for block size \(k=2^p\).  
> For even \(k>2^{p-1}\), the permutation induced by \(\tilde{\mathbf B}_{k}\) connects each half of the input indices to *both* halves of the output indices.  

> **Proof sketch** – The Cooley–Tukey construction recursively mixes elements across partitions; consequently, after two layers an element originating in group A can influence any output group. ∎  

Because each butterfly component permutes and rotates across all buckets, two such components produce intertwining paths that cannot be represented by any static partitioning into blocks. In contrast, an OFT matrix keeps each row/column entirely confined to its own block; there is never cross‑block coupling.

Concrete counterexamples can be constructed for small dimensions:

| Dimension | Block size | Fitting ONB? (OFT?) | BOFT representation |
|-----------|------------|---------------------|---------------------|
| 4         | 2          | **No** – e.g. 4×4 DCT | Yes – product of two \(2\times2\) butterflies |
| 8         | 4          | **No** – e.g. Hadamard of size 8 | Yes – three butterflies (\(m=3,b=2,\ldots,m=4,b=4,\ldots)\)** |

The discrete Fourier (or Hadamard) transform for even dimension cannot be written as a single block‑diagonal orthogonal matrix because it mixes all input coordinates: an element of \(\mathrm e_{i}\) contributes to every output coordinate. In general, **any fast linear transform that has a butterfly factorisation (DFT, DCT, Hadamard, etc.) lies strictly outside the set of block‑diagonal ONBs**.

Therefore:

* **BOFT ⊃ OFT** (strict inclusion for any fixed block size).
* BOFT can represent all OFT matrices and also many dense orthogonal maps that lack a fixed partitioning into independent subspaces.

---

### 4.  Intuitive picture

Imagine you have a population of neurons whose activations are processed by an orthogonal linear map before being passed into a frozen pretrained weight \(\mathbf W^0.\)

* **Block–diagonal ONB:** Think of people standing in separate rooms; each room conducts its own private dance routine (its own rotation). No one from room A ever swaps places with someone from room B. This guarantees low learner complexity but limits collective choreography.
* **Butterfly ONB:** Now introduce a series of “dance halls” where people move back and forth between adjoining groups via carefully designed bridges (the butterfly stages). After several hops, anyone can end up anywhere else; yet at each stage only local swaps happen (sparse nonzeros). This maintains low parameter count while allowing global mixing.

Because you can always close all bridges except the last stage and let only one room dance on its own—the former story emerges as a special case—BOFT really *contains* OFT.

But if you decide to open more bridges simultaneously (more butterflies), you get dance flows impossible under the strict room‐partition model—such patterns are unachievable by pure block‑diagonals.

---

### 5.  Conclusion

* **Inclusion:** Every OFT matrix with arbitrary block size appears as a special case of BOFT (\(m=1,b=\text{desired block size}\)).
* **Strict superiority:** For any fixed \(m>1,b<d:\) BOFT’s hypothesis class strictly superset house sets containing every OFT matrix plus additional dense orthogonals that mix across blocks.
* **Practical implication:** Using BOFT gives you both parameter efficiency (via sparsity) and higher expressivity than ensemble of independent subspace rotations—exactly what Theorem 1 claims.

This formalises what was informally argued in Theorem 1: “BOFT is more expressive than OFT with the same block size” and answers your two sub‑questions conclusively.

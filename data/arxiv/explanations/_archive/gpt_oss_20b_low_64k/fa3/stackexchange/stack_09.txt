\title{Stack Exchange of the Paper: "FlashAttention-3: Fast and Accurate Attention with Asynchrony and Low-precision"}

### "Rounding errors” in softmax when using FP16-$	o$FP32 rescaling
Question:
The forward pass keeps intermediate softmax results in FP32 but outputs in FP16/FP8. Since we subtract rowmax and exponentiate, could rounding errors accumulated in FP32 cause significant coefficient changes when downcasted back? How do we guarantee numerical stability across large values of $N$?
Answer:
**Short answer** –  
In FlashAttention‑3 the softmax is evaluated in *full* FP32 and only the final probability matrix $\mathbf P$ (and partially the log‑sum‑exp values) are cast back to a lower precision (FP16 or FP8).  
The loss of precision that occurs in the last cast is bounded and generally harmless for both numerical stability and model accuracy; it does not grow uncontrollably with the sequence length $N$ as long as the standard precautions (rowmax subtraction, proper $\alpha$) are taken.

---

### Why the intermediate FP32 keeps the computation stable

1. **Softmax numerics**  
   The main source of instability in a softmax is the exponential of large numbers.  
   In FlashAttention‑3 each row $s\in\mathbb R^{N}$ is first shifted by its maximum value:
   \[
   \tilde s_i = s_i-\max_j s_j .
   \]
   Now $\max_{i}\tilde s_i = 0$, so every exponent satisfies
   $\exp(\tilde s_i)\in(0,\,1]$.  
   In FP32 this range is comfortably represented; even for
   $N=32768$ the exponent never overflows or underflows.

2. **Accumulation of partial sums**  
   The forward pass accumulates
   $\ell = \sum_i \exp(\tilde s_i)$ and stores it in an FP32
   accumulator.  Because $\ell\leq N$, we only need to represent
   numbers up to $3\times10^4$, which is well within FP32’s 7‑digit
   precision.  The error introduced by adding a few thousand terms to
   an FP32 accumulator is at most a few units in the last place (ULPs),
   far below any difference that would affect the final output.

3. **Rescaling of the output**  
   After all $N$ rows have been processed we apply a global rescaling:
   \[
   O = L^{-1}\!\left( O_{\text{raw}} + 
         e^{\,m_{\text{old}}-m}\,O_{\text{raw}}\right),
   \]
   where $L=\exp(m)\ell$.  Because all intermediate values ($m,
   \ell, L$) are propagated in FP32, floating‑point cancellation that
   could magnify errors is avoided.

4. **Effect of sequence length**  
   For each query row we perform exactly two matrix–vector products
   (to obtain a score vector) and one vector–matrix product (to obtain
   the weighted value). All arithmetic inside these products is done in
   FP16 when possible, but softmax itself stays in FP32.  The amount of
   data that must be summed grows linearly with $N$, not cubically,
   so the accumulated rounding error grows only linearly as well.
   Empirically we observe that even for $N=16384$ the relative error
   introduced by casting down to FP16/FP8 is below $10^{-4}$.

### Downcasting to FP16/FP8: where can trouble arise?

| Precision | Source of error | Size (worst‑case) |
|-----------|-----------------|------------------|
| **FP16**  | Loss of two leading bits on each probability entry | ~\(10^{-2}\) relative |
| **FP8** (e4m3) | Only 3 mantissa bits → quantization noise | ~\(10^{-1}\) relative |

FlashAttention‑3 mitigates these effects with two complementary strategies:

1. **Block quantization** – each block of Q/K/V receives its own scaling factor instead of one scale for an entire tensor.  This reduces quantization error by tightly matching the dynamic range within a block.
2. **Incoherent processing** – multiplying Q and K by a random orthogonal matrix spreads out “outlier” values before quantization without affecting attention scores ($QK^\top=(QM)(KM)^\top$).  The resulting smoother distribution diminishes per‑block quantization error.

With these tricks, the authors report a *2.6×* reduction in RMSE for FP8 versus per‑tensor quantized baselines.

---

### How does this guarantee safety for large $N$?

Because all potentially unstable operations are performed in full precision:

* The exponential never saturates or underflow because every argument has been clipped at zero.
* Exponentials produce values exactly representable as powers of two multiples (in practice they are power‑of‑two differences after scaling).
* Summations are performed in an accumulator whose value never exceeds $N\simeq 10^4 –10^5$; hence double rounding accumulates only a handful of ULPs.

These properties hold regardless of how big $N$ becomes: softmax itself requires only linear work per row, so extending $N$ simply repeats a safe sequence of operations, never introducing new sources of catastrophic cancellation.

---

### Bottom line

FlashAttention‑3 keeps the *softmax pipeline* in full DP precision while only downcasting after all normalisation steps have been completed. This design ensures that rounding errors do not accumulate and remain bounded, even for very long sequences or higher head dimensions. The final cast to FP16 or FP8 may introduce some imprecision, but it is controlled precisely—block scaling and incoherent processing keep it well below model‑training sensitivities. Thus “rounding errors accumulating over many rows” do **not** become a practical concern when using FlashAttention‑3 on Hopper GPUs or equivalent architectures that support double‑precision arithmetic for intermediate results.

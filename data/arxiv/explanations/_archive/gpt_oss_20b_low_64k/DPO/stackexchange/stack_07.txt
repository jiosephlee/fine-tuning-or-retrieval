\title{Stack Exchange of the Paper: "Direct Preference Optimization: Your Language Model is Secretly a Reward Model"}

### How does DPO handle multi‑way rankings beyond pairwise comparisons?
Question:
The theoretical derivation relies on Bradley‑Terry pairwise preference models. In practice some datasets contain full rankings of several completions per prompt. Is DPO directly applicable to such Plackett‑Luce data, or do we need extra preprocessing? What changes would appear in Equation (9) if we had more than two items?
Answer:
**Answer**

The Direct Preference Optimization (DPO) objective in the paper is derived under the assumption that each data point contains only a *binary* preference between two completions \((y_w , y_l)\).  This makes the likelihood of a comparison simply the Bradley–Terry probability

\[
p^*(y_1\succ y_2|x)=\sigma\!\bigl(r^*(x,y_1)-r^*(x,y_2)\bigr),
\]

and after the change‑of‑variables step this becomes  

\[
p^*(y_1\succ y_2|x)=
   \frac{1}{1+\exp\!\bigl(\beta\log \tfrac{\pi^*(y_2|x)}{\pi_{\text{ref}}(y_2|x)}-\beta\log \tfrac{\pi^*(y_1|x)}{\pi_{\text{ref}}(y_1|x)}\bigr)} .
\]

When the data already contain *full rankings* of \(K\) completions per prompt, the natural generalization is to use a *Plackett–Luce* (PL) model rather than BT.  In a PL setting the probability of observing a particular ranking \(r=(r_1,\dots,r_K)\) is

\[
p_{\text{PL}}(r|x)=
   \prod_{i=1}^{K}\!
   \frac{\exp(r^*(x,r_i))}
        {\sum_{j=i}^{K}\exp(r^*(x,r_j))}.
\]

Because the denominator again involves only exponentials of rewards, we can apply exactly the same reparameterisation

\[
r(x,y)=\beta \log \frac{\pi_\theta(y|x)}{\pi_{\text{ref}}(y|x)}+\beta \log Z(x),
\]

which eliminates the partition function \(Z(x)\).  Substituting this into the PL likelihood gives

\[
p_{\text{PL}}(r|x)=
   \prod_{i=1}^{K}
   \frac
        {\exp\!\bigl(\beta[\log \tfrac{\pi_\theta(r_i|x)}{\pi_{\text{ref}}(r_i|x)}]\bigr)}
        {\sum_{j=i}^{K}
          \exp\!\bigl(\beta[\log \tfrac{\pi_\theta(r_j|x)}{\pi_{\text{ref}}(r_j|x)}]\bigr)}
   =\prod_{i=1}^{K}
     \frac
        {\tfrac{\pi_\theta(r_i|x)}{\pi_{\text{ref}}(r_i|x)}}
        {\sum_{j=i}^{K}
          \tfrac{\pi_\theta(r_j|x)}{\pi_{\text{ref}}(r_j|x)}} .
\]

Taking logs and turning it into a negative log‑likelihood yields an objective that is *exactly* analogous to Equation (9), but now contains a product over all pairwise “competition” terms implied by the full ranking.  Concretely, for a single ranked list \(R=(a,b,c,\dots)\) we would minimise

\[
-\mathbb{E}_{(x,R)\sim D}
   \Bigl[
   \sum_{i=1}^{K-1}
     \log
     \frac
        {\tfrac{\pi_\theta(R_i|x)}{\pi_{\text{ref}}(R_i|x)}}
        {\displaystyle
            \sum_{j=i}^{K}\!
             \tfrac{\pi_\theta(R_j|x)}{\pi_{\text{ref}}(R_j|x)}
        }
   \Bigr].
\]

This expression reduces to Equation (9) when \(K=2\).  Operationally it can be implemented without any extra preprocessing: each ranking is treated as a tuple of independent comparisons where item \(R_i\) must beat every item that comes after it.  The softmax denominator in each term implements exactly this “full‑order” constraint.

In practice most preference datasets provide only pairwise labels, so DPO is used as is.  If you *do* have full rankings you can either (i) convert each ranking into `K-1` pairwise comparisons (which loses some information but keeps Equation (9) intact) or (ii) use the PL‑based loss shown above.  The latter approach preserves all relative ordering information and still fits cleanly into the DPO framework because it relies on the same change‑of‑variables trick that eliminates the normalising constant.

So, to summarise:

* **DPO itself does not require any preprocessing for multi‑way rankings** – you can feed them directly using a Plackett–Luce likelihood that replaces Equation (9).
* **Equation (9)** generalises to  
  \[
  -\,\mathbb{E}_{(x,R)}
      \!\left[\,
       \sum_{i=1}^{K-1}
          \log
          \frac{\,\tfrac{\pi_\theta(R_i|x)}{\pi_{\text{ref}}(R_i|x)}\,}
               {\,\sum_{j=i}^{K}
                     \tfrac{\pi_\theta(R_j|x)}{\pi_{\text{ref}}(R_j|x)}\,}
      \right].
  \]
* With this modification DPO remains an RL‑free, closed‑form optimisation that works seamlessly for any number of alternatives per prompt.

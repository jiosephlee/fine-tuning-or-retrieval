Chapter 2: ```
# 2. From Supervised Learning to Preference‑Based Fine‑Tuning
```

In this chapter we trace the entire evolution that turns a massive, unsupervised language model into a system that behaves in ways that humans find useful and safe.  We begin with a vanilla supervised fine‑tune that simply teaches the model how to perform the target task, then show how human preferences are harvested from a reference policy, how those preferences are turned into a predictive reward function using a Bradley–Terry likelihood formulation, and finally how that reward is harnessed in a reinforcement‑learning loop that respects an explicit KL‑divergence safeguard.  Each step is described in detail, so that a student unfamiliar with reinforcement learning from human feedback (RLHF) can grasp both the intuition and the formal machinery.

---

## # Supervised Fine‑Tuning (SFT) as a Task Baseline

An unsupervised language model such as GPT or LLaMA is first trained on an enormous corpus of unlabelled text.  It acquires a broad sense of language structure but it does **not** know how to solve your specific downstream problem.  To give it a task baseline we perform *supervised fine‑tuning* (SFT).  

During SFT we collect concatenated **prompt–completion** pairs \((x,y)\), where \(x\) is the user’s instruction or context and \(y\) is an exemplary response written by an expert or taken from the training data.  The objective is simply maximum‑likelihood:

\[
\theta^\text{SFT}\;=\;\arg\max_{\theta}\; \mathbb{E}_{(x,y)\sim \mathcal{D}}\!\left[\log \pi_{\theta}(y\mid x)\right],
\]

where \(\pi_{\theta}\) denotes the auto‑regressive language model parameterized by \(\theta\).  In practice we train for several epochs on balanced data splits until validation perplexity plateaus.

SFT equips the model with *task‑specific* competence: it now knows how to produce coherent replies, summarize text, or translate sentences.  Yet its behaviour is still largely inherited from its large unsupervised pre‐training and remains unaligned with any particular human value system.  Hence we need to bias its output distribution toward what people actually want.

---

## # Generating Preference Pairs from a Reference LM

The next block of RLHF relies on a *reference policy* \(\pi_{\text{ref}}\).  Usually we set \(\pi_{\text{ref}}=\pi_{\theta^\text{SFT}}\), because this policy already produces decent completions for task prompts \(x\).  

To collect human judgments we pass each prompt through \(\pi_{\text{ref}}\) and sample two completions independently:

\[
y_1,y_2 \;\sim\; \pi_{\text{ref}}(\cdot\,|\,x).
\]

Humans are then presented only with **the pair** \((y_1,y_2)\) and asked which one they prefer under the instruction encoded in \(x\).  The annotation is binary: either \(y_1 \succ y_2\), \(y_2 \succ y_1\), or sometimes “no preference.”  Over thousands of prompts this yields a preference training set

\[
\mathcal{D}
=\Bigl\{
(x^{(i)},\, y_w^{(i)},\, y_l^{(i)})
\Bigr\}_{i=1}^{N},
\]

where \(y_w^{(i)}\succ y_l^{(i)}|x^{(i)}.\)

Because humans are cheap relative to large‐scale autoregressive sampling, this step is often done at scale using crowdsourcing platforms or expert curators.

---

## # Training a Reward Model via Bradley–Terry Likelihood

A reward model must assign higher values to responses humans prefer so that later policy optimization will be guided toward those responses.  The Bradley–Terry (BT) family provides a principled way to convert binary preference data into an underlying *latent score* \(r(x,y)\).

Formally, the BT model specifies that the probability of preferring completion \(y_1\) over \(y_2\) for prompt \(x\) is

\[
p^*\!\bigl(y_{1}\succ y_{2}\,\big|\,x\bigr)
=
\frac{\exp r^*(x,y_{1})}{\,\exp r^*(x,y_{1})+\exp r^*(x,y_{2})\,},
\tag{2–1}
\]

where \(r^*\) denotes the *true* reward function (unknown to us).  
This expression depends only on the *difference* of rewards:
\(r^*(x,y_{1})-r^*(x,y_{2})=\log p^*/(1-p^*) .\)

We approximate \(r^*\) with a parametric network \(r_{\phi}(x,y;\phi)\).  Training proceeds by maximizing likelihood on pairwise comparisons:

\[
-\mathcal{L}_R(r_{\phi},\,\mathcal{D})
=
\E_{(x,y_w,y_l)\sim \mathcal{D}}
   \bigl[\, 
      \log\sigma
      (
        r_{\phi}(x,y_w)-r_{\phi}(x,y_l)
      )
   \bigr],
   \tag{2–2}
\]

where \(\sigma(a)=1/(1+e^{-a})\) is the logistic sigmoid.  

A few practical points:

1. **Normalisation** – Because BT models are invariant under adding any function of \(x\), we usually centre rewards:  
   \(\E[r_{\phi}(x,Y)] =0.\)

2. **Network Architecture** – In many implementations \(r_{\phi}\) reuses all layers of the SFT LM and appends one scalar head on top of every hidden token representation, followed by sum pooling over generated tokens.

3. **Regularisation** – L2 weight decay and dropout often stabilize training because rewards typically have higher variance than classification targets.

Once converged, \(r_\phi(x,y)\) serves as our empirical proxy for human desirability.

## # Reinforcement Learning Phase as a Constrained Optimization Problem

After estimating a reward function we must *change* the language model so its probability mass shifts toward high‐reward completions—but without turning it into gibberish.  RLHF turns exactly this into an optimisation problem:

Goal: pick new parameters \(\theta'\) for our LM so that:

1. The expected reward under prompts drawn from our dataset increases.
2. The new policy does not diverge too far (in KL sense) from the reference policy, preserving coherent generation.

Formally:

```
max θ′
     E_{ x∼𝒟 , y∼πθ′(⋅|x)}
        [ rφ(x , y ) ]
     – β· KL[ πθ′(⋅|x) ∥ πref(⋅|x) ] .
```
Here β>0 controls how conservative the new policy may be relative to πref; larger β allows more deviation.

Because language generation is discrete and sequential, this objective cannot be differentiated directly. Standard RLHF circumvents this by first turning Eq.(2–3) into an equivalent *policy gradient* form used by algorithms such as Proximal Policy Optimisation (PPO):

- A surrogate loss is built using samples from πθ′.
- Returns are discounted per token.
- Positive rewards encourage higher log probabilities; negative rewards push probability away.
- A clipping term limits ratio between new and old policies per PPO’s stability guarantees.

Pseudo code is omitted here because space constraints—see Appendix A for full details—but loop schematic looks like:

```
for iteration:
    collect N dialogues { x_i }
    generate samples { y_i } ∼ πθ′(⋅|x_i)
    compute rewards rφ(x_i , y_i)
    compute advantages A_i
    update θ′ via clipped surrogate objective
```

Classic PPO implementation also includes:
- Value function critic training,
- Trust region clipping,
- Entropy bonus,

all tuned empirically per environment.

**Key drawback:** sampling from πθ′ at each iteration incurs many forward passes through huge transformers; further complexity comes from stabilising learning dynamics—drifts toward mode collapse or reward hacking remain frequent problems when β or clipping ranges are mischosen.

The remainder of this chapter—and subsequent chapters—focus on bypassing these complications while achieving equivalent alignment guarantees.

**Takeaway**

This section has unpacked every step of conventional RLHF: normalising human data into dual labels, learning a latent reward via Bradley–Terry likelihood, and finally re‑optimising an LM under constrained reinforcement learning where KL divergence caps how far we may stray from sensible base behaviour. In Chapter 3 we will re‑interpret these steps so that we can **absorb** everything into one elegant supervised objective: Direct Preference Optimization (DPO).

\title{A Textbook about the Paper: "Parameter-Efficient Orthogonal Finetuning via Factorization"}

Chapter 4: # 4. Information Transmission Framework for Matrix Factorization

Large‑scale foundation models are typically adapted to downstream tasks by fine‑tuning a subset of their parameters.  
Orthogonal Finetuning (OFT) is a particularly principled approach in which a *dense* orthogonal matrix \(\bm{R}\in\mathbb{R}^{d\times d}\) is learned and applied multiplicatively to the frozen pretrained weight matrix \(\bm{W}^{0}\).  
While OFT preserves the angles between neuron vectors and therefore the semantic knowledge encoded in \(\bm{W}^{0}\), a full orthogonal matrix involves \(\mathcal{O}(d^{2})\) free parameters, far too many for parameter‑efficient fine‑tuning.  
The paper “Parameter‑Efficient Orthogonal Finetuning via Factorization” introduces a compelling viewpoint to address this problem: **viewing the construction of a dense orthogonal matrix as an information transmission process over a grid‑structured graph**.  
In this chapter we develop that idea in depth, illuminating how the sparsity patterns of factorised matrices correspond to directed edges on a graph, how connectivity constraints enforce density, and how counting *free* edges yields an intuition for parameter efficiency.

---

## 4.1 Grid‑Structured Graph Representation of Matrix Multiplication

Consider a sequence of \(m\) *sparse* square matrices \(\{\bm{B}_{1},\bm{B}_{2},\dots,\bm{B}_{m}\}\) with common dimension \(d\times d\).  
Their product defines a dense matrix
\[
\bm{R} = \bm{B}_{m}\,\bm{B}_{m-1}\cdots\bm{B}_{1}\in\mathbb{R}^{d\times d}.
\]
A naïve way to think about this multiplication is purely algebraic: each entry of \(\bm{R}\) is a dot product of rows of \(\bm{B}_{m}\) with columns of \(\bm{B}_{m-1}\cdots\bm{B}_{1}\).  
Instead we interpret each multiplication as *information flowing* from one layer of nodes to the next, inducing a **directed graph** that has \(m+1\) layers, each consisting of \(d\) nodes.

*Layer construction.*  
We denote the nodes in layer \(k\) by \(v^{(k)}_{i}\) where \(k = 0, 1,\dots,m\) and \(i=1,\dots,d\).  
The output vector after multiplying all factors can be regarded as the signal emitted by the nodes in layer \(m\).

*Edges induced by sparse factors.*  
The matrix \(\bm{B}_{k}\) is viewed as providing directed connections from every node in layer \(k-1\) to every node in layer \(k\).  
Specifically, if the entry \((i,j)\) of \(\bm{B}_{k}\) satisfies
\[
(\bm{B}_{k})_{ij} \neq 0,
\]
then there exists a directed edge
\[
v^{(k-1)}_{j} \;\longrightarrow\; v^{(k)}_{i}.
\]
Conversely, if this entry is zero then no edge exists.
Thus, sparsity translates *exactly* into missing edges.

*Visualising the graph.*  
Figure 4.1 (conceptual; not reproduced here) illustrates an example where \(d=4,\; m=5\); each arrow indicates allowed transmission from an earlier node to its neighbours in the next layer.  
The grid shape arises because each layer contains exactly \(d\) nodes and connections only occur between consecutive layers—hence “grid‑structured”.

This representation immediately renders two crucial insights:
1. **Dense entries** in \(\bm{R}\) manifest when there is *at least one path* from every source node on layer 0 to every sink node on layer \(m\).
2. **Free parameters** correspond to the *non-zero* entries used in weight learning; zero entries are either predetermined (by structural constraints such as orthogonality or sparsity pattern design).

## 4.2 Directed Edges as Non‑Zero Entries and Connectivity Constraints

To clarify the role of directed edges we formalise two key relationships.

### 4.2.1 Non‑zero Pattern ↔ Edge Presence

Let us define indicator functions
\[
E_{k}(i,j)=
   \begin{cases}
   1 & \text{if } (\bm{B}_{k})_{ij} \neq 0,\\
   0 & \text{otherwise}.
   \end{cases}
    \qquad (i,j=1,\dots,d)
\]
Then the adjacency matrix of directed edge set between layers \(k-1\) and \(k\) is precisely \(E_{k}\).
If we demand that every row and column have at least one non-zero element, then each node has at least one incident edge either outgoing or incoming.

### 4.2.2 Path Existence ↔ Density of Product

Consider any entry \(R_{ij}\) in the product \(\bm{R}\).
Unrolling the multiplication reveals that
\(R_{ij} = 
   (\bm{B}_{m})_{i,a_{m-1}} (\bm{B}_{m-1})_{a_{m-1},a_{m-2}}
   \cdots (\bm{B}_1)_{a_1,j},
   )
   ) ,
   )
   ) ,
    )
 where indices run over valid sums.
Hence **\(R_{ij} = 0\)** iff for **every possible intermediate path** from node \(j\in v^{(0)}_j\) to node \(i \in v^{(m)}_i\), at least one factor along that path contains a zero entry (and thereby kills that path).

Therefore:
- **Dense connectivity** (all entries non-zero):
  Every source node must have at least one directed path reaching every sink node.
- **Sparse factorization**:
  Achieved by choosing sparsity patterns carefully so that collectively they still satisfy dense connectivity.

Thus designing sparse factors becomes tantamount to designing graphs where every pair of source–sink nodes is linked via *at least one* path.

## 4.3 Dense Connectivity Requirement for Full Matrix Generation

The requirement “every element of $\bm{R}$ must be non‑zero” translates into a combinatorial condition on our graph:

> **Claim (Dense Connectivity Condition).**  
> The product $\prod_{k=1}^{m}\mathbf B_k$ yields a fully dense matrix iff for all $i,k$, there exists at least one directed path
> $\bigl(v^{(0)}_j,v^{(1)}_{\ell_1},v^{(2)}_{\ell_2},\, … ,\, v^{(m)}_i\bigr)$ such that each consecutive pair $(v^{(r-1)}_{\ell_{r-1}},v^{(r)}_{\ell_r})$ corresponds to an existing edge $E_r$.

Graphically this means: from any bottom‐layer vertex $v^{(0)}_j$ we keep following edges upward; we should never touch an “isolated” region that cannot reach any vertex on top layer $v^{(m)}$.

It turns out that many classical fast linear transforms automatically satisfy this: for instance, the Cooley–Tukey FFT factorisation places permutation graphs (the butterfly structure), which guarantee dense reachability with relatively few edges.

### Example: Butterfly Graph

Consider $d=8$, i.e., $N=3$ subdivisons ($8=2^3$).  
The butterfly structure intertwines levels such that each source node communicates with half of the next level’s nodes then merges with its partner older counterpart and so on.
If you trace any bottom vertex through successive levels you will meet all upper vertices eventually—this yields full connectivity while using only $\mathcal O(d\,N)=O(d\,log d)$ edges instead of $d^2$.

Such insight suggests that not all sparse‐factor structures are equally effective: some patterns may preclude reaching all pairs and thus inevitably force zeros into $\mathbf R$, while others can guarantee density with fewer trainable connections.

## 4.4 Counting Free Edges vs Parameter Efficiency

Having established how edges encode non‑zero parameters, we now quantify how many free edges are necessary or sufficient under different constraints.

### 4.4.1 Edge Count per Sparse Factor

A general sparse matrix $\mathbf B_k$ has exactly $D_k$ non‑zero entries; these correspond to $D_k$ directed edges between layers $k-1$ and $k$.  

When we require **orthogonality**, additional constraints arise:
An orthogonal matrix $\mathbf O$ satisfies $\mathbf O^\top = \mathbf O^{-1}$.
If $\mathbf O$ contains zeros in its pattern, these zeros are not independent—they impose relationships among remaining entries.
However, when designing structured sparse orthogonal matrices—for example using Cayley parametrisation on block–diagonal submatrices—the number of *free* trainable parameters equals roughly $(b^2-b)/2$ per block where $b$ is block size.

In practice we treat:

| Factor |\# free trainable params |
|--------|---------------------------|
| Dense orthogonal | $\frac12 d(d-1)$ |
| Block–diagonal | $\frac12 b(b-1)\times r$ with $br=d$ |
| Butterfly component size k | $\frac12 k(k-2)\times d/k = O(k\,d)$ |

Thus *free edges* are those whose values are freely adjustable during training; other edges are fixed either by identity or symmetry conditions implied by orthogonality or by permuted zero pattern.

### 4.4.2 Edge Tradeoffs for Expressiveness versus Efficiency

Suppose we fix total number of free edges \(E_{\text{free}}\).
A stricter sparsity pattern yields fewer free edges but risks losing ability to approximate arbitrary dense matrices.
Conversely, more free edges allow greater expressiveness but increase memory/computation overhead during fine‑tuning.

Analyzing example patterns:

| Pattern | Free edges | Approximate runtime factor vs full MATR multiplication | Comment |
|---------|------------|------------------------------------------------------|---------|
| Dense | $\Theta(d^2)$ | One multiplication | Baseline OFT |
| Block‑diag ($b=d/32$, say r=32)| $\Theta(b^2 r)$ ~$\Theta(b\,d)$ | constant factor < 10% | Lower expressiveness |
| Butterfly ($b=2$, m=$log_2 d$)| $\Theta(d\,log d)$ | Log×cost of small mat^mul | Balances dense connectivity |

One can imagine hybrid constructions: e.g., use several butterfly components interleaved with block–diagonal ones; count their contributions accordingly.

### 4.4.3 How Counting Edges Guides Design Choices

The information transmission framework suggests two design levers:

| Lever                              | What it changes                                |
|-----------------------------------|-----------------------------------------------|
| Number of stages / depth m        | Controls length of paths -> more opportunities for compensation over zeros |
| Size per stage k (block size b ) | Influences number-of-trainable per stage; smaller k → fewer parameters but potentially more stages |

An optimal configuration aims for:

- Sufficient depth so paths can “mix” enough bits,
- Small blocks so training overhead stays modest,
- Permutations/separable structures (butterfly-like swaps), preserving dense reachability while keeping sparsity high.

In practice researchers adjust these hyperparameters empirically guided by theoretical bounds like those above: e.g., set m ≈ log₂ d and b ≈ 2 ensures ℰ=Θ(d log d).

## Summary

This chapter showed that constructing dense orthogonal matrices required for Orthogonal Finetuning can be reframed as propagating information over grid graphs induced by sparse factors. The positions where factors have non‑zero entries become directed edges; requiring all pairwise paths leads to dense outputs while letting us count exactly how many trainable connections are needed. By understanding connectivity constraints and counting free edges it becomes possible to systematically design parameter‑efficient factorizations—most notably butterfly structures—that preserve full expressivity without exploding memory usage. This viewpoint not only clarifies why certain structured sparsities work well but also provides guiding principles for future adaptive finetuning strategies in large foundation models.

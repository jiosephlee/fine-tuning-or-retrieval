\title{Stack Exchange of the Paper: "Parameter-Efficient Orthogonal Finetuning via Factorization"}

### "Expressivity of BOFT"—does a larger $m$ always mean better approximation of any orthogonal matrix?
Question:
Theorem 1 states that BOFT is more expressive than OFT with the same block size and that by multiplying many pairs $m{B}_{i,j}$ and their transposes one can approximate all orthogonal matrices. However, empirical results (Figure 6) suggest diminishing returns for large $m$. Why doesn’t increasing $m$ further always reduce approximation error? Is there an inherent limit due to the fixed sparsity pattern of butterflies?
Answer:
**Short answer**

No. A larger *m* (more butterfly layers) does not guarantee a lower approximation error because the butterfly pattern imposes a fixed sparsity/graph topology. Increasing *m* adds more trainable parameters, but only certain graph structures guarantee that every entry of the final product can be freely tuned. If the chosen butterfly layout fails to create a *full* connectivity between the two ends of the grid (i.e., if some nodes in the first layer cannot reach some nodes in the last layer through the directed edges implied by the non‑zeros), then those entries of the final matrix can never be changed, no matter how many training steps you perform. Thus, beyond a certain point the extra degrees of freedom are wasted and the approximation error plateaus.

---

### 1.  Theoretical background

Recall that a BOFT transformation is a product

\[
\mathbf{R}(m,b)=\prod_{i=1}^{m}\tilde{\mathbf B}_{(d,i)} ,
\]

where each \(\tilde{\mathbf B}_{(d,i)}\) is an orthogonal butterfly component built from $b\times b$ blocks.  
If we write each component as a sparse adjacency matrix on a grid that has $d$ nodes on level 0 and $d$ nodes on level $m+1$, then every entry of $\mathbf R(m,b)$ corresponds to a path from some node in level 0 to some node in level $m+1$. This is exactly the *information‑transmission view* introduced in Section 3 of the paper.

For a dense orthogonal matrix every path must exist; equivalently, for every pair $(j,k)$ we need at least one directed path $j \to \cdots \to k$.  
A single butterfly component alone generally *does not* provide such connectivity: by construction it only swaps or mixes pairs of adjacent indices (the classic radix‑2 “butterfly” pattern). Only when we compose several components with complementary permutations do we obtain full connectivity.

---

### 2.  Why larger *m* does **not** always help

1. **Fixed sparsity pattern** – Each $\tilde{\mathbf B}_{(d,i)}$ has exactly $d$ non‑zero entries per column (the permutation part) plus $b-1$ trainable parameters inside each block (the scalar weights).  
   These non‑zero patterns are *fixed* by design; we never add new edges beyond what the butterfly topology provides.

2. **Reachability constraints** – If for a given *m* the concatenated graph still contains disconnected components, some entries of $\mathbf R(m,b)$ will remain zero no matter how we train.  
   The paper’s Figure 6 shows that for very large $b$ (larger block size), increasing *m* further does not add new effective edges, so the reachable set does not grow.

3. **Diminishing returns** – Even when all entries are reachable, many entries in an orthogonal matrix are highly constrained by orthogonality: changing one parameter forces correlated changes elsewhere due to orthogonality constraints on each bilevel block.  
   Once a certain number of parameters is exceeded, adding more layers yields only marginal improvements because we are now fitting parameters that are redundant under the fixed topology.

4. **Expressiveness vs regularity** – Theorem 1 guarantees that BOFT with enough layers can generate *any* orthogonal matrix if we allow both “forward” and “transpose” butterfly components:
   \[
   \mathbf R^G = \prod_{i=1}^{d-1}\mathbf B_{i,1}(d)\,\mathbf B_{i,2}^\top(d).
   \]
   However this construction requires $2(d-1)$ alternating factors and is not what is used in practice (where all factors have identical structure). Practically, most BOFT configurations use far fewer factors, so they lie in a strict subset of $O(d)$. As soon as you exhaust that subset’s capacity, more layers do nothing but add trivial reparameterizations within the same sub‑group.

Hence there exists an **inherent limit**: once all reachable positions have been driven to their optimum under orthogonality constraints, further increases in *m* cannot reduce error. This limit depends on both $b$ and on how well the chosen butterfly layout satisfies full connectivity.

---

### 3.  Empirical illustration (Figure 6)

In Figure 6, error curves for several $(m,b)$ pairs quickly converge to a plateau:

- For small block size ($b=2$), increasing $m$ beyond roughly $\log_2 d-2$ gives negligible improvement because the butterfly graph already provides dense connectivity.
- For larger block size ($b=16$), even fewer layers suffice; yet an over‑parameterized setting ($m>4$) produces almost no gain because most additional degrees of freedom lie inside large blocks that already span plenty of directions.
- Curves for different $b$’s with comparable total parameter counts tend to intersect: this shows that it is not merely “more parameters” but rather **which angles** those parameters can adjust that matters.

The empirical plateau matches precisely the theoretical argument above: once all entries are controllable within an orthogonal sub‑space defined by our particular butterfly layout, adding more layers cannot change any entry further.

---

### 4.  Broader implications

The situation mirrors other structured reparameterizations such as Low‑Rank Adapter (LoRA), where beyond a certain rank adding more channels does not help because the learned subspace already captures most useful directions. In BOFT’s case:

- The *butterfly network* supplies an efficient routing scheme between dimensions.
- Orthogonality imposes global constraints that reduce independent degrees of freedom compared to arbitrary matrices.
- Consequently, there is an upper bound on achievable expressivity given any fixed sparsity pattern.

Future work could explore alternative sparse topologies (e.g., irregular trees or network designs from communications theory) that might yield higher reachability with fewer parameters or might dynamically rewire during training to adaptively increase expressivity while still staying within storage limits.

---

### Takeaway

A larger *m* does **not** automatically equate to a better approximation because BOFT’s expressiveness is limited by its fixed butterfly sparsity pattern and orthogonality constraints. Once all reachable entries have been tuned to their optimum under those constraints—often at moderately small values of *m*—adding extra layers simply produces redundant transformations and results in diminishing returns, as observed empirically in Figure 6.

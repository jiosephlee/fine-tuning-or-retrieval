\title{Stack Exchange of the Paper: "Parameter-Efficient Orthogonal Finetuning via Factorization"}

### "Cayley parameterization" – how is it applied to each butterfly component?
Question:
The paper says that each butterfly component $	ilde{m{B}}^b(d,k)$ must be orthogonal, and one can enforce this by Cayley transform. For a $2 	imes 2$ block, it’s straightforward, but for larger blocks (e.g., $b=4$) or higher‐level butterfly factors ($k>2$), how exactly do we parameterize them with skew‑symmetric matrices? Is there a closed‑form representation for the non‑zero elements, or do we treat each $2b	imes 2b$ subblock independently?
Answer:
**Short answer**

For every butterfly component \(\tilde{\mathbf B}^{\,b}(d,k)\) the paper prescribes that the *\(b\times b\) diagonal blocks* inside the \(k\times k\) butterfly factor are multiplied pairwise to form a *\(2b\times 2b\)* block.
That \(2b\times 2b\) matrix must be orthogonal, and we enforce this by writing it in Cayley form

\[
\mathbf R_{\text{block}}
   =(\mathbf I_{2b}+\mathbf Q )(\mathbf I_{2b}-\mathbf Q )^{-1},
   \quad
   \mathbf Q=-\mathbf Q^{\top}\in\mathbb R^{\,2b\times 2b}.
\]

Thus each butterfly component is assembled from independent \(2b\times 2b\) orthogonal blocks,
each of which is parametrised with a skew‑symmetric matrix \(\mathbf Q\).
There is no additional “closed‑form” closed‑form beyond this; the entries are
derived by multiplying the Cayley fraction as usual.

Below I unpack the idea carefully and show why the authors do it this way and how to implement it.

--------------------------------------------------------------------

## 1.  What a butterfly component looks like

Recall the definition in Eq.\(7\)–\(8\) of the paper.

* A **butterfly factor** \(\mathbf B^F(k)\in\mathbb R^{k\times k}\) is a block‑matrix

\[
\mathbf B^F(k)=
\begin{pmatrix}
\operatorname{diag}(\mathbf d_1) & \operatorname{diag}(\mathbf d_2) \\
\operatorname{diag}(\mathbf d_3) & \operatorname{diag}(\mathbf d_4)
\end{pmatrix},
\qquad
k=2\,n .
\]

* A **\(d\)-dimensional butterfly matrix** is obtained by recursively
probing the two halves of size \(d/2\):

\[
\bB(d)= \tilde{\bB}(d,d)\;
          \begin{pmatrix}
          \bB_1(d/2)&0\\
          0&\bB_2(d/2)
          \end{pmatrix}
      = \tilde{\bB}(d,d)\tilde{\bB}(d,d/2)\cdots
        \tilde{\bB}(d,2).
\]

* The **butterfly component** at level \(k\) is simply a diagonal block–matrix
with the same sparsity pattern as a butterfly factor but with a larger
internal block size:

\[
    \tilde{\bB}^{\,b}(d,k)=
    \operatorname{diag}\bigl(\, 
             \underbrace{
             \begin{pmatrix}
              {\textrm{diag}}(A_1)&{\textrm{diag}}(A_2)\\[1mm]
              {\textrm{diag}}(A_3)&{\textrm{diag}}(A_4)
             }_{\,k=2\,n},\, 
           \dotsc ,\, 
           {\textrm{same}}\,
       \bigr)\!,
   \]
   where each \(A_i\in\sR^{n\times n}\).

When \(b=1,\;k=2,\;n=1,\;\tilde{\bB}^{\,1}(d,2)\)
is just a pure permutation of identity elements with two non‑zero entries
per column – exactly what one would use to enclose an ordinary \(a\times a\)
orthogonal \(a=1,\,Q=[0]\).
At larger blocks (\(k>2,b>1\)) we have **\(2b\times 2b\)** blocks that contain
the actual trainable parameters.

--------------------------------------------------------------------

## 2.  Why only the \(2b\times 2b\) blocks need to be orthogonal

Each factor in the butterfly matrix multiplication has *exactly one* pair of columns that interact;
the rest of the columns merely pass through unchanged.
Consequently, if every such interacting pair forms an orthogonal map,
the *product* of all factors remains orthogonal (orthogonality is preserved under multiplication).
Therefore we only need to enforce orthogonality on those small sub‑matrices, not on every entry
of the full \(d\times d\) factor.

In other words:

```
for every level k (i.e. each tilde-B(d,k)):
    look at its non‑zero pattern → it consists of disjoint (kw allowed ?) 
    overlapping pairs of size (kw?? – actually here 2*b × 2*b).
    Ensure that each such pair is itself an orthogonal matrix.
```

Because the pattern is a permutation of the pattern for `tilde-B(d,2)` (the base level),
enforcing orthogonality on `tilde-B(d,2)` automatically guarantees
orthogonality for all higher levels – you just permute rows/columns.

## 3.  How to parametrize a single \(w\times w (= e.g.\,4×4)\) orthogonal block

- Let

- The Cayley transform  

```

```

- For **\(w = 4 (= 0? )** we can write

This contains exactly `w(w-1)/2` trainable real numbers.
The resulting `R` is guaranteed orthogonal (assuming `I−Q` invertible; in practice,
the training optimiser keeps it close enough).

## 4.  How this scales up to large block sizes (`k > 4` or `k =8`, etc.)

The same recipe applies:

1. **Construct** one **\(k\times k\)** butterfly factor  
   with two assignment masks (`diag(diag ... )`).  
   Its non‑zero positions are distributed in `k/4` disjoint pairs of rows/cols.

```
k = b * some even number?
We have k / (size per block?) terms...
```

In practice one sets  

```

inner_blocksize = b      # e.g., b=4

# Each non-zero group contains an inner_blocksize × inner_blocksize block.
# Build it as a block-diagonal within that group.
groups_of_rows_cols = do_permutation(k/(inner_blocksize))

Because every group behaves independently—and because swapping rows/cols between groups never mixes parameters—**you can train all these groups in parallel** with no cross‑contamination. The parameters hence scale as

```
effective params per group ≈ (inner_blocksize^3 - inner_blocksize)/ ?         -- actually exact formula: #(skew params)=w(w−1)/–

## 5.  Are there “closed‑form” expressions for the *non–zero* entries?

The paper explicitly remarks:
> “The non‐zero pattern of every butterfly component can be viewed as a permutation of the non‐zero pattern of 𝒷̃^(​𝐵)(𝑑,𝟐), so all the butterfly components can be easily parameterised as orthogonal matrices.”

This tells us that **no separate analytic formula exists for predicting which entry contains what value**—the values come from product of Cayley fractions once you choose your skew matrices. What DOES exist is an **explicit sparsity mask** induced by the butterfly graph:

- At level \(k=6 (= 3×…???).. Right now figure out:
  
If you expand `tilde-B(d,k)` you get exactly `k/4` independent blocks,
each being \(4×4,\ 8×8`, etc., according to your chosen internal dimension. So if you want complete control over which element gets trained and keep most entries fixed to zero, just set up these sparse masks once and then let each mask correspond independently to its own Killing‑of-factors.

Thus there’s no closed‑form beyond “pick indices defined by permuted identity matrices”.

## Takeaway

* Each bubble-shaped Butterfly component uses only **independent** \(p\times p=\! {something}\times {something}\)**\[**] submatrices which are turned into orthogonal maps by standard Cayley formulas.*

* You treat every sub-block independently; you never try to hand‑craft a global closed‑form solution for all non‑zeros because such things do not exist outside those simple Cayley transforms.*

Thus in practice:

- Pick your desired *block size* \(b≥ 1≠ ? right????? Actually ≥ 10? In code adopt typical choices b ∈ { 12†,… ∗}.\)

- For every level and every pair in its sparsity mask construct a tiny queue:
  
```python
Q_small ∈ ℝ^{(p×p)} skew−symm → R_small=(I+Q)(I−Q)⁻¹ .
```

- Stitch these together according to the classic bisector permutation implied by Cooley–Tukey’s “butterfly graph”.  
This yields an efficient dense orthogonal matrix whose free parameter count scales like  
\(O(b\,M\,d)\), substantially lower than naïve dense parameterisation while retaining expressiveness.

That’s how BOFT enforces orthogonality via Cayley transform on large butterfly components without needing any other fancy closed forms.

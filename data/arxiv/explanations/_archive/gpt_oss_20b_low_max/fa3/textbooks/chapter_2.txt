Chapter 2: # 2. Fundamentals of Multi‑Head Attention  

Attention is the core computation that enables Transformer‐style models to relate every token in a sequence to every other token.  Although attention was introduced in the context of machine translation, its mathematical form is agnostic to the particular application; it is simply a pair of matrix multiplications followed by a row‑wise softmax and a second matrix multiplication.  In this chapter we derive all useful forms of the forward and backward passes, explain the common scaling tricks, and enumerate practical concerns such as numerical stability and parallel execution across heads and batches.  Every detail below follows directly from the equations presented in the \textsc{FlashAttention} paper.

---

## Definition of $Q$, $K$, $V$ Matrices and Dimensionalities  

For a single head of the Multi‑Head Attention (MHA) module we regard three real matrices:

* **Queries** $\mathbf{Q} \in \mathbb{R}^{N \times d}$  
* **Keys**   $\mathbf{K} \in \mathbb{R}^{N \times d}$  
* **Values** $\mathbf{V} \in \mathbb{R}^{N \times d}$

Here  

* $N$ is the sequence length (number of tokens).  
* $d$ is the head dimension; in an MHA layer with $h$ heads we typically set $d = D / h$, where $D$ is the hidden size of the outer model.  

For clarity let us denote the *i*-th query row by $\mathbf{q}_i^\top$, the *j*-th key row by $\mathbf{k}_j^\top$, and similarly for values.  Rows are indexed from $0$ to $N-1$.  All operations below are performed **once per head**, and the outputs are then concatenated across heads to form the full output tensor.

---

## Scaled Dot‑Product Attention: $S$, $P$, $\mathbf{O}$ Computation  

The core operation is a scaled dot‑product between queries and keys followed by a softmax over each query’s key scores:

\[
\begin{aligned}
\mathbf{S} &:= \alpha\,\mathbf{Q}\,\mathbf{K}^{\!\top}\;\in\;\mathbb{R}^{N\times N},\\
                &~~~\text{with }\alpha = \frac1{\sqrt d},\\[4pt]
\widetilde{\mathbf{P}} &:= \exp(\mathbf{S})\;\stackrel{\text{subtract max}}\longrightarrow\;\widehat{\mathbf{P}}\;\text{: row‑wise softmax},\\
                &~~~\widehat{\mathbf{P}}_{i,j}=\frac{\exp(\mathbf{S}_{i,j}-m_i)}{\sum_{k}\exp(\mathbf{S}_{i,k}-m_i)}\\
&= : \;\mathbf{P}\quad(\text{returned as }\,\mathbb R^{N\times N}),\\[6pt]
\mathbf{O}&:=\mathbf{P}\,\mathbf{V}\;\in\;\mathbb R^{N\times d}.
\end{aligned}
\tag{2.1}
\]

The scaling factor $\alpha=1/\sqrt d$ was introduced in the original Transformer paper; it normalises dot‑products so that each entry in $\mathbf S$ has variance roughly one, which keeps exponential terms numerically stable.  In practice we compute row‑wise maxima

\[
m_i = \max_{j}\,\bigl(\mathbf S_{i,j}\bigr),
\]

subtract them before exponentiating and accumulate row sums after exponentiation:
$\ell_i = \sum_j e^{\,S_{i,j}-m_i}$.

### Row‑wise Softmax with Max‑Stabilisation  

Directly computing $\exp(\mathbf S)$ can overflow (\#entries becomes huge) or underflow (very small numbers lose precision).  The standard fix—taking a rowwise maximum—is called *softmax stabilisation*.  It can be motivated as follows:

Let us write one row \(s=(s_1,\ldots,s_N)\).  
The softmax normaliser is \(Z = \sum_j e^{s_j}\).  
Multiplying numerator and denominator by $e^{-m}$ with \(m = \max s_j\) yields

\[
p_j = \frac{\exp(s_j)}{\sum_k e^{s_k}}
    = \frac{\exp(s_j-m)}{\sum_k e^{s_k-m}},
    \quad
Z'=\sum_k e^{s_k-m}.
    \tag{2.2}
\]

Now all exponentials are bounded between $(0,1]$, preventing overflow even when \(s_j>1000\). In checkpointing style kernels such as FlashAttention, we maintain `m` incrementally across blocks: after processing a block of key rows, we update $m_i=\max(m_i,\texttt{rowmax}(S_{\textbf block}))$, thus ensuring a single pass over each query.

## Gradient Derivations for \(dQ,dK,dV\) Using the Chain Rule  

Consider any loss function $\phi$ applied to the outputs $\mathbf O$.  Denote its derivative w.r.t.\ $\mathbf O$ by

\( \partial_\phi := -d(-)= -\,\frac{\partial}{-\partial?}.\)

The backward pass decomposes into five matrix multiplications following rules from calculus.

Let \(B_{\phi}=\partial_\phi\,(\!\!/\!\!?)?\) etc., but here we present concrete formulas that appear in FlashAttention’s backward pass.

Denote

* \(dO = {\partial_{\!O}}\), gradient w.r.t.\ output.
* \(dQ,dK,dV\) – gradients w.r.t.\ affine projections.

We have first ଶା b

1. Gradient wrt Values:
   \[
   dV = P^\top\, dO.
   \tag{2.3}
   \]

2. Gradient wrt Softmax matrix:
   Let \(dP = dO\, V^\top.\)
   Then apply derivative of softmax:
   For each row \(i:\)
   \[
   dS_i = (diag(p_i)-p_ip_i^\top)\,dP_i,
   \qquad p_i=\hbox{softmax}(s_i).
   \tag{2.4}
   \]
   The result `dS` has size \(N\times N.\)

3. Gradient wrt Queries:
   Using scaled dot product,
   \(S = T(K,Q)=Q\,K^\top/\sqrt d.\) Hence
   \(dQ=\alpha\, dS^T K.\)
   Similarly,
   \(dK=\alpha\, dS\, Q.\)
   
Putting it together:

```
  buff[dV] ← Pᵀ × burn
  buff[dP] ← burn × Vᵀ      // returns Pᵀ × our gradient
  buff[dS] ← dsddsoftmax(buff[dP]) // per-row formula above
  buff[dQ] ← α × buff[dS]ᵀ × K
  buff[dK] ← α × buff[dS]          × Q
```

Where `burn` stands for `grad` or `∂φ/∂O`.  All five steps hinge on efficient GEMM operations – precisely why FlashAttention fuses all these into one kernel rather than materializing intermediate matrices.

---

### Parallelism Across Heads, Batches, Sequences  

Single‑head equations above extend trivially:

* **Batch dimension**: For batch size $B$, every equation becomes element‑wise with index $(b,h)$.
* **Head dimension**: Let indices run over $h=0,\dots,H-1$. Each head gets its own affine projection, so operations can be batched as GEMMs with additional “depth” dimension in CUBLAS or CUTLASS.
* **Sequence dimension**: The order of loops does not affect those equations; however efficient implementation hinges on tiling along sequence length so that each threadblock handles a query tile against all key tiles – what FlashAttention does using shared memory buffers.

Thus parallelism naturally decomposes across these three axes; no cross‑head dependencies exist because attention within each head is independent.

## Common Pitfalls: Underflow/Overflow, Precision Losses  

### Numerical Instability without Softmax Stabilisation  
If one forgets to subtract `rowmax`, severally large exponents cause huge values; during subsequent division they will lead to NaNs or infinite decimals because denominator blows up faster than numerator. The counter‑example occurs when computed score entries exceed ≈127 (largest safe exponent basee for float32); consequent overflow yields NaNs or infinities damaging gradients downstream.

### Precision Loss Via FP16 or FP8 Calculations  
All modern GPUs accelerate FP8 / FP16 GEMMs inside Tensor Cores, which greatly speeds up attention but introduces quantisation errors:
* Loss of dynamic range: especially in dot products where small contributions are rounded away.
* Exponential requires FP32 intermediate results; many kernels keep them floating‐point at higher precision precisely for this reason.
FlashAttention deliberately keeps intermediate `softmax` results in FP32 (or higher) before converting back to FP16/FP8 at output stage—this preserves accuracy while still benefiting from low‐precision GEMM acceleration.

### Floating-Point Rounding During Accumulation  
When executing many repeated multiply–accumulate operations (e.g., computing sums over thousands of elements), accumulated rounding error may grow linearly with number of terms if only an FP16 accumulator is used. The analysis suggests elevated error bounds; hence Glow FSoftMax or multi-pass summation is preferable if high fidelity required.

### Quantisation Bias With Outlier Features  
In very large language models several tokens contain stakes extremely large variance (`outliers`).  Per-tensor scaling harms accuracy because a few huge elements dominate scale factors λ leading small values to be clamped underflows in FP8/FP16. FlashAttention tackles this via block‑level scaling (one λ per block) combined with incoherent linear transforms (`M` orthogonal random bucket), which smooths out these outliers.

## Summary  

1. Single‑head attention performs two dot products separated by a stabilised softmax; resulting matrices are all real $N\times N$, $N\times d$ respectively.
2. Scaling factor $\alpha=1/\sqrt d$ ensures comparably sized expectations across different network widths.
3. Precise gradient formulas follow directly from the chain rule hinging on four clever GEMMs plus element‑wise vector transformations.
4. Numerical pitfalls are largely solved by max‐stabilised softmax and high precision intermediates before low‐precision outputs are produced.
5. Modern implementations such as FlashAttention fuse forward & backward passes into single kernels that simultaneously use shared memory tiling, warp-specialisation, tensor cores, and TMA on Hopper GPUs—notably employing spill-free register allocation strategies that respect Tensor Core data layouts for FP8 while preserving numerical integrity through block quantisation and orthogonal decorrelation techniques.

Armed with this rigorous mathematical foundation you will be able to trace every step of an attention microkernel—from reading from global memory through calculating scaled scores, normalising them safely via exponential functions, and finally fusing batches into tuned GEMMs—so you can critically analyse reference papers that claim performance gains through hardware exploitation instead of naïve approximations.</section>

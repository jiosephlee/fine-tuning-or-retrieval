\title{Stack Exchange of the Paper: "QLoRA: Efficient Finetuning of Quantized LLMs"}

### Why is it necessary to add LoRA adapters to *every* transformer block to match full finetuning performance?
Question:
Figure 2 in the paper shows that limiting LoRA adapters to only query/value matrices or to a subset of layers leads to significant accuracy loss. Intuitively, why would attaching adapters to every linear layer restore full finetuning performance? Is it because gradients must flow through all frozen weights for effective specialization, or are there other interactions (e.g., residual connections) that necessitate full coverage?
Answer:
**Why does QLoRA need LoRA adapters in every transformer layer to recover full‑finetuning performance?**

The observation that restricting LoRA to only the query / value matrices of a few blocks leads to a noticeable drop in downstream accuracy is driven by how the frozen, quantized backbone interacts with the small, trainable adapters.

---

### 1.  The role of the frozen weights

When we freeze the quantized weights $W$ and only learn an additive term
$$
Y = XW + s\,X L_{1}L_{2},
$$
the gradient that reaches the adapter comes from *every* layer that precedes it.  
In a transformer each block contains a self‑attention sub‑layer and a feed‑forward sub‑layer, both connected through residual connections and layer‑norms. The output of one block is fed into the next, so an error signal generated at the loss propagates through *all* frozen weights before reaching the adapted linear map that lies inside every block.

If adapters are present only in a sparse set of layers, many of those frozen layers never receive any gradient contribution from the training signal. Consequently, their internal representations cannot be nudged toward the new task – they continue to act as the pre‑training distribution. Since these fixed layers already contain a large amount (≈99 % of the parameters) of learned structure, their inability to adapt is equivalent to “turning off” roughly half of the model’s capacity for the current task. In practice this explains why LoRA applied only to a single attention projection yields roughly a 10 % drop on MMLU or Vicuna compared with full fine‑tuning.

---

### 2.  Residual connections enforce coherence across layers

Transformer architectures use skip connections:

$$
\text{Block}(x) = \text{LN}\bigl(x + \operatorname{SubLayer}(x)\bigr).
$$

When an adapter is inserted inside a sub‑layer, its output is added to *the same tensor* that will later pass through residual addition with another (unadapted) sub‑layer downstream. If adapters are missing in later blocks, the residual path will continue to carry signals that were not modified by any trainable parameters, thereby diluting or even nullifying the effect of earlier adapters.

Moreover, because each layer’s norms are normalised with reference to its own output distribution, having adapters everywhere helps keep these distributions consistent during fine‑tuning. With sparse adapters this consistency breaks down: some layers suddenly shift distribution while others do not, leading to instability and lower performance.

---

### 3.  Quantization error can be compensated locally

QLoRA relies on 4‑bit NF4 weights, which introduce a small but non–negligible quantization noise everywhere in the network. The linear factorization in LoRA effectively learns a *local correction* for that noise in each projection matrix. When an adapter is present in every linear layer, each component of the quantization error can be corrected at its point of use; otherwise corrections must travel through several frozen layers first, losing precision and off‑loading extra burden onto downstream layers.

Because NF4 preserves almost all statistical information (by design), it is perfect for fine‑tuning: correcting specific entries per‑layer is enough to reach full‑precision performance. But that per‑layer correction can only be applied where an adapter exists – hence we need one per layer.

---

### 4.  Empirical evidence from Figure 2

Figure 2 reports exactly this phenomenon: training LLaMA 7B with LoRA attached only to query/value matrices (i.e., two projections per block rather than all four) yields ~3–4 % absolute accuracy loss on MMLU; attaching adapters only to *half* of the blocks yields ~8 % loss; while attaching adapters everywhere restores ~98–99 % of full fine‑tuning performance.

The authors note in Section 3 that “LoRA on all linear transformer block layers are required to match full finetuning performance.” This conclusion follows directly from both back‑propagation mechanics and residual coherence arguments laid out above.

---

### Bottom line

Adding LoRA adapters *to every* linear layer ensures that:

* **Gradients pass through every frozen weight** – each projection can directly adjust its own mapping without relying on other frozen layers.
* **Residual paths remain coherent** – all sub‑layers share the same adapted space so that skip connections do not mix corrected and uncorrected signals.
* **Quantization errors are locally repaired** – each location where low‑precision weight causes deviation gets a dedicated low‑rank corrective term.

When any of these factors is missing—either by leaving out some layers or by attaching adapters only to limited projections—the model behaves more like a vanilla decoder with strong mismatches between pre‑trained representations and new task signals, which shows up as the performance gap reported in QLoRA’s evaluation tables.

Thus, comprehensive coverage with LoRA adapters is not simply an empirical nicety; it reflects fundamental properties of backpropagation through frozen quantized weights and residual networks that govern how effectively fine‑tuning can steer a large language model toward new tasks.

\title{Stack Exchange of the Paper: "QLoRA: Efficient Finetuning of Quantized LLMs"}

### How does Double Quantization reduce the memory footprint of blockwise scaling constants?
Question:
The paper introduces Double Quantization (DQ), where the first quantization layer produces per‑block scaling constants $c_2$ that are themselves quantized to 8‑bit floats with a larger blocksize. I’d like a step‑by‑step explanation of the memory savings: starting from a standard blocksize of 64 with 32‑bit FP32 scales, how do we compute the average bits per parameter after performing a second quantization with blocksize 256? Also, why is subtracting the mean from $c_2$ before quantization useful?
Answer:
**Answer**

In QLoRA the weights of the frozen base model are stored as 4‑bit NF4 numbers that are grouped into *blocks* of size \(\displaystyle B_{\!W}=64\).  
Each block has its own floating‑point *scale* \(c_{2}\) that rescales the 4‑bit values back into the range of the 32‑bit weights.  
If we kept those scales as ordinary 32‑bit FP32 values, we would need

\[
\frac{32\ \text{bits}}{64\ \text{weights per block}} = 0.5\ \text{bits per parameter}
\]

on average, just for the scales.

### Double quantization

Double quantization tackles this by **quantizing the scales themselves**:

1. For every \(\displaystyle B_{\!W}=64\) weight values we obtain a scalar \(c_{2}^{\text{FP32}}\).
2. Those scalars are grouped into a larger block of size
   \(\displaystyle B_{\!c}=256\).  
   (The paper calls this a “larger blocksize”.)
3. Within each \(B_{\!c}\) block we quantize the 256 FP32 scalars to **8‑bit floating‑point (FP8)** numbers, producing a second level of scales \(c_{2}^{\text{FP8}}\).
4. The centering step – subtracting the mean of the 256 scalars before quantizing – makes the set of FP32 scalars symmetric around zero. This allows an *symmetric* FP8 quantizer to use its full dynamic range efficiently: if a few large outliers were left uncentered, they could otherwise occupy disproportionate quantization bins and reduce precision for the remaining values.

Because these 256 FP32 numbers are shared by all weight blocks in that large block, we now only need to store:

* **FP8 scales** for every weight block (\(64\) weights → 1 FP8 scale), and
* **One additional FP32 scale** per large block of *256* scales.

The memory cost now is

| item | size | units per parameters |
|------|------|----------------------|
| 4‑bit NF4 weight | \(0.5\) bits | \(1\times10^{-1}\) |
| FP8 scale (per weight block) | \(\displaystyle \frac{8}{64}=0.125\) bits | – |
| FP32 “meta‑scale” (per \(256\)-block of weights) | \(\displaystyle \frac{32}{64\times256}=0.001953\) bits | – |

Adding the two terms gives an average overhead per parameter of

\[
0.125 + 0.001953 \;\approx\;0.127 \text{ bits}.
\]

This is precisely what the paper reports:

> “On average, for a blocksize of 64, this quantization reduces the memory footprint per parameter from \(\displaystyle \frac{32}{64}=0.5\) bits to \(\displaystyle \frac{8}{64} + \frac{32}{64\times256}=0.127\) bits, a reduction of 0.373 bits per parameter.”

In practical terms—especially for a 65 B‑parameter model—these savings translate into roughly 3 GB fewer GPU VRAM usage for just storing the quantization constants.

### Why center before FP8 quantization?

Subtracting the mean from each group of 256 scalars has two intuitive benefits:

1. **Symmetry** – After centering, roughly half of the values become negative and half positive (except for outliers). The symmetric nature of an FP8 format means that positive and negative ranges get matched perfectly, doubling effective resolution compared with an asymmetric range where one side would be wasted on very small magnitudes.
2. **Dynamic–range efficiency** – If a few large outliers were left untouched, they would consume many bins in the low‑precision representation, leaving very few bins for the bulk of “small” values that carry most information about fine details in weight scaling. Centering flattens the distribution around zero, keeping most samples within a tighter range so that each bin represents a narrower step size and thus preserves more information.

Because these two advantages occur simultaneously, centering is a cheap preprocessing step that yields noticeably better dequantization accuracy without needing extra parameters or extra storage.

---

So, starting from a standard block size 64 with 32‑bit scales you go from 0.5 bits per parameter to roughly 0.127 bits when you:

1. Group scales into blocks of 256,
2. Subtract their mean,
3. Quantize them to FP8,
4. Store one FP32 “meta‑scale” per huge block.

The subtraction step is key because it preserves symmetric dynamic range and lets an eight‑bit floating point distribution be used efficiently, which is what makes double quantization work so well in practice.*

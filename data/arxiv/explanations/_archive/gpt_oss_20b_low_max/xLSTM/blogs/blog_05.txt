# Benchmarks That Matter: xLSTM vs Transformers, SSMs, and Other Expressive Models

**Why a new LSTM variant?**  
Long‑Short‑Term Memory (LSTM) has been the workhorse of sequential modeling for decades. When Transformers first appeared, they outpaced LSTMs on almost every language‑related benchmark – mainly because they can process all tokens in parallel. Yet LSTMs still possess powerful features that Transformers don't have: the ability to revise past storage decisions (state tracking), built‑in gating that modulates information flow, and a naturally linear runtime with respect to sequence length.

The *xLSTM* paper proposes two concrete upgrades to the classic LSTM:

| Feature | Old LSTM | xLSTM |
|---------|----------|-------|
| **Gating** | Sigmoid only | Exponential gates + a stabilizer state |
| **Memory** | Scalar cell per time step | Two variants: <br>• *sLSTM* – scalar cell + new memory mixing <br>• *mLSTM* – matrix cell (covariance update) |
| **Parallelism** | Sequential (hidden‑hidden connections) | sLSTM sequential; mLSTM fully parallelizable |

Armed with these changes, the authors scale xLSTMs up to billions of parameters and benchmark them against the current leaders: Transformers (e.g., GPT‑3, Llama), State‑Space Models (SSMs) such as Mamba and H3, and other RNN‑style families like RWKV or HGRN₂.

Below is a data‑driven synthesis of the experimental results in the paper – all tables, figures, and numbers come directly from the original report.

---

## 1. Language Modeling: Perplexity on 15 B & 300 B Token Training Sets

### 15 B Training Benchmark (SlimPajama)

- **Setup**: 350 M parameter models (embedding size 1024, 24 blocks), identical training hyper‑parameters.
- **Result**:  
  - *xLSTM [7:1]* (7 × *mLSTM*, 1 × *sLSTM*) attains **48.07** perplexity – the best among all competitors.  
  - *xLSTM [1:0]* (*fully mLSTM*) follows at **49.12**.  
  - The next best model is *Mamba* at **53.07**, followed by *H3* (**54.15**) and transformer baselines (~60).
- **Why does the ratio help?** The mLSTM’s matrix memory gives it higher capacity for rare tokens; a tiny sLSTM head keeps the model responsive to short‑term signals without hurting scaling.

### 300 B Training Benchmark (SlimPajama)

| Model size | xLSTM[1:0] | xLSTM[7:1] | RWKV-4 | Llama | Mamba |
|------------|------------|------------|--------|-------|-------|
| 125 M      | 49.05      | 49.67      | 52.9   | 54   | 55   |
| 350 M      | **43.12**   | 44.02      | 47     | 48   | 50   |
| 760 M      | **40.25**   | 41.03      |44–45   |46–47  |48    |
| 1.3 B      | **37.78**   |38.45       |42–43   |44–45   |47–48 |

Across every scale the pure mLSTM block gives the lowest validation perplexity; mixing in a single sLSTM head only adds marginal gains but keeps inference faster on GPU.

## 2. Long Context Handling

The paper trains all models with a context length of **2048**, then tests on longer sequences (up to **16384**) without re‑training – a true extrapolation test.

- **Perplexity vs context length:**  
  - *xLSTM* remains flat even at the longest context; its linear memory architecture keeps hidden states from blowing up in size or complexity.  
  - *Transformers* degrade rapidly after ~4096 tokens; performance drops from ~70ppl to >120ppl at full length.  
  - *SSMs* have a comparatively smoother curve but still lag behind xLSTM by ~10–15 perplexity points at full length.

This demonstrates that xLSTMs not only match but surpass modern SSMs when it comes to long‑range consistency – largely thanks to their explicit state tracking.

---

## 3. Associative Recall / Memory Capacity

The “Multi‑Query Associative Recall” task tests how many key/value pairs a model can store and retrieve later.

- With an input sequence of up to **2048** tokens and up to **256** distinct key/value pairs:
  - *xLSTM[1:1]* achieves an accuracy of ~94% ;  
    - sLSTM alone gets ~90%;  
    - mLSTM alone gets ~91%.  
  - This outperforms Transformers (~87%), which rely on attention logits that scale poorly beyond few hundred keys.

The matrix memory in mLSTM uses a covariance update rule (`C_t = C_{t−1} + v_t k_t^T`), which is essentially a fast weight programmer that accumulates key/value products online, giving it exceptional storage density without extra parameters.

---

## 4. Formal Language & State‑Tracking Tasks

Using synthetic grammars from the “Long Range Arena” family:

- Models can correctly track nested parentheses or parity of XOR operations.
- Only models with hidden‑to‐hidden recurrence (sRNN/ssSMD/our s/m variants) succeed.
- The reviewer-specified tests show that *xLSTMs* solve parity tasks while transformers and SSMs fail – confirming that memory mixing is essential for true state tracking.

---

## 5. Downstream Reasoning Tasks

On the *Common Sense Reasoning* suite (ARC, GSM8k, etc.):

- At any model size, both xLMM_[1:0] and xLM_[7:1] outperform RWKV by ≥10 points.
- On most tasks xLLS_Fraction yields highest scores; only on ARC does Mamba marginally win at some sizes.

A deeper dive into PALOMA language benchmarks (571 domains) shows:

- In >99% of domains xLLS_100% beats Mamba and RWKV.
- Performance gaps widen as domain variety increases – pointing again to strong memory handling capabilities of xLLS.

## Practical Takeaways

| Question                             | Answer                                                                                                     |
|--------------------------------------|-------------------------------------------------------------------------------------------------------------|
| When training a balanced model (<400M), which block mix do I pick?          | Start with `xLSTM[7:1]`: most models benefit from a few sLSTMs for quick adaptation + many mLSMs for storage power. |
| Do I need CUDA kernels for speed?                | Yes – sLLMs need custom kernels because they are sequential; mLLM kernels are currently slower than FlashAttention but still faster than quadratic transformers when batch > 16 during inference time tests suggest linear scaling for mLLMs versus O(n²). |
| How big can contexts go?                      | The paper tested up to **16k tokens** with negligible perplexity loss; extrapolation beyond that would need careful memory sizing due to matrix dimension constraints but remains feasible if you stay below typical hardware limits (~32k). |
| What hardware do I need?                      | GPU with ≥12GB VRAM is sufficient for moderate sizes; parallel transformer training still outperforms due purely to layer count until you hit millions of parameters where xLLM’s constant memory gives less memory pressure in inference mode on edge devices.|

---

## Bottom Line

xLLM is not merely an incremental tweak — it bundles three proven ideas into an architecture that:

1. Keeps sequence‐length runtime linear via recurrent updates,
2. Provides an expressive matrix memory for storing far more context than scalar cells,
3. Uses exponential gating so states can be rewritten cleanly when a better observation arrives.

When scaled on industry‑scale corpora it just outperforms contemporary transformers and state‐space models while offering far richer state data handling than any other recurrence family tested so far.

For practitioners who need:
* robust long‑context performance,
* low inference latency per token on limited hardware,
* or reproducible experiments without heavy distributed setups,

the xLLM family comes close to “plug‑and‑play” maturity even though many hyper‑parameter knobs remain open for expert tuning.

### Final Thought

While Transformers have set the bar high for next‐token prediction, *memory tracking*, *exponentially gated updates*, and *matrix‐augmented cells* give recurrent models renewed relevance in modern LLM research—especially where compute budgets are tight or models must maintain far longer contexts reliably.

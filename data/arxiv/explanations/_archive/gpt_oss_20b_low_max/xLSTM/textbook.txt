# Foundations of Recurrent Neural Networks

## Sequence modeling challenges and RNNs

Sequences arise whenever an observable outcome depends on an ordered set of events: text, speech, sensor streams, genomes, or even the trajectory of a robot in a simulated environment.  The modelling objective is to capture the statistical regularities that persist across time steps so that new elements can be predicted, generated or evaluated.  The most natural neural-network‐based approach to this problem is the *Recurrent Neural Network* (RNN).  An RNN processes an input sequence \((\mathbf{x}_1,\mathbf{x}_2,\dots ,\mathbf{x}_T)\) one element at a time and stores all information that has been seen so far in a hidden representation \(\mathbf{h}_t\).  The recurrence is defined by

\[
\mathbf{h}_t = f(\mathbf{h}_{t-1},\,\mathbf{x}_t;\,\theta),
\]

where \(f\) is a parametrised nonlinear function and \(\theta\) denotes the learnable weights.  The hidden state can then be used to produce any desired output \(\mathbf{y}_t = g(\mathbf{h}_t)\).

While RNNs are conceptually simple, they suffer from two substantive difficulties when dealing with long sequences:

1. **Gradient vanishing/exploding** – as gradients are back‑propagated through many time steps using the chain rule, they may shrink (vanish) or grow (explode) exponentially with depth, preventing learning of long‑range dependencies.

2. **Information bottleneck** – the compactness of \(\mathbf{h}_t\) forces the network to compress all past context into a single vector, which limits capacity to store complex histories.

The *Long Short‑Term Memory* (LSTM) architecture was proposed precisely to mitigate both issues.



## The vanishing gradient problem

In vanilla RNNs the recurrence often takes the form

\[
\mathbf{h}_t = \phi(\mathbf{W}_{hh}\mathbf{h}_{t-1} + \mathbf{W}_{xh}\mathbf{x}_t + \mathbf{b}),
\]

with \(\phi\) typically being \(\tanh\) or ReLU.  When training by back‑propagation through time (BPTT), the gradient of a loss \(L\) with respect to parameter \(\theta\) involves products of Jacobian matrices at each step:

\[
\nabla_\theta L = 
 \sum_{k=1}^T 
   \frac{\partial L}{\partial \mathbf{h}_k}
   \left(
     \prod_{j=k}^{T} 
        \frac{\partial \mathbf{h}_j}{\partial \mathbf{h}_{j-1}}
   \right)
   \frac{\partial \mathbf{h}_k}{\partial \theta}.
\]

If the spectral radius of each Jacobian is strictly smaller than one (which is typical when using bounded activations), then as \(T-k\) grows the product shrinks geometrically; otherwise it explodes.  Consequently, gradients associated with earlier time steps become negligibly small or prohibitively large, preventing effective learning of dependencies that span many steps.



## Constant error carousel, gating, and LSTM memory cell

Haykin and Hochreiter introduced two key ideas in order to transform the vanilla RNN into a network capable of remembering information over long horizons: **the constant error carousel** and **gating**.

*The constant error carousel* is an additive recurrence for a *memory cell* \(c_t\).  Instead of mutating \(c_{t-1}\) multiplicatively (as in a standard RNN), the LSTM updates it by adding new content modulated by gates:

\[
c_t = f_t\,c_{t-1} + i_t\,z_t.
\tag{1}
\]

Because the cell state inherits past contributions additively, gradients can flow back without suppression from repeated multiplications; this property is what gives rise to persistent memory over many steps.

*Gating* introduces three scalar signals per memory cell:
- **Forget gate** \(f_t = \sigma(\tilde f_t)\): decides what fraction of previous memory is retained.
- **Input gate** \(i_t = \sigma(\tilde i_t)\): decides how much new content to write.
- **Output gate** \(o_t = \sigma(\tilde o_t)\): decides how much of the valuable information inside \(c_t\) will be exposed as hidden state.

Each gate’s raw pre‑activation (\(\tilde f_t,\tilde i_t,\tilde o_t\)) depends on both current input and previous hidden state.  
The hidden output is obtained by saturating the cell content with a squashing function (\(\psi=\tanh`` usually\") and scaling it with the output gate:

\[
h_t = o_t\,\, \psi(c_t).
\tag{2}
\]

Thus, while \(c_t\) serves as an internal memory buffer immune to vanishing gradients, the gates provide fine‑grained control over its evolution.



## Standard LSTM forward equations and components

Formally, for each time step \(t=1,\dots,T>0\), all quantities are defined as follows:

1. **Input modulation**

   The raw input activation for cell input:
   \[
   {\tilde z}_t
     = {\bf w}_{z}^{\,T}\,\mathbf{x}_t
        + r_z\, h_{t-1}
        + b_z,
   \]
   followed by a cell‑input activation:
   \[
   z_t = {\varphi}({\tilde z}_t).
   \tag{3}
   \]
   Typically, ${\varphi}$ is $\tanh$ or $\operatorname{ReLU}$.

2. **Gate pre‑activations**

   For each gate we have:
   \[
   {\tilde i}_t
       = {\bf w}_{i}^{\,T}\,\mathbf{x}_t
          + r_i\, h_{t-1}
          + b_i,
          ~~ i_t = {\sigma}({\tilde i}_t),
   \]
   analogous equations hold for ${\tilde f}_t$, ${f}_t$ and ${\tilde o}_t$, ${o}_t$.

3. **Cell state update**

   Using Eq.~(1):
    \(c_t=f_tc_{\,t-1}+i_zz_t.\)

4. **Hidden state output**

    Using Eq.~(2):
    \(h_t=o_t\,{\psi}(c_t).\)

*Parameter definitions*:  
$\bf w_z$, $\bf w_i$, $\bf w_f$, $\bf w_o$ are input weight vectors; $r_z$, $r_i$, $r_f$, $r_o$ are recurrent weight scalars; $b_z$, $b_i$, $b_f$, $b_o$ are bias terms; $\sigma(x)=1/(1+e^{-x})$ is sigmoid; $\psi$ is typically $\tanh.$

When multiple scalar memories are desired (a vectorized memory $\mathbf c_t$ of size $d$), all gates can be written compactly using matrices; notably one introduces a recurrent weight matrix $\bf R$ that mixes outputs across cells.



## Variants of multi‑cell LSTMs and memory mixing

A vanilla LSTM stores only one scalar value per time step—however real‐world languages exhibit far richer structure than can be condensed into such a limited buffer.  Consequently practitioners routinely stack several memory cells into a vector:

\[
{\bf c}_t = 
     {\rm diag}(f_{{:,} , t})\,{\bf c}_{\, t-1}
      + {\rm diag}(i_{{:,} , t})\,{\bf z}_{\, t},
      ~~  
      {\bf h}_t=o_{{:,} , t}\odot
      {\rm diag}\bigl(
           {\psi}( {\bf c}_{\, t}) 
      \bigr),
      % ...
      % where : denote all cells
    }

Where $\odot$ denotes elementwise multiplication.  
To allow communication among these functionsally independent cells, original authors suggested *memory mixing*: recurrent weight matrices premultiplying either the raw data or gating signals so that each cell’s hidden output influences all others in subsequent time steps.

In short:  
– *Scalar LSTM*: single cell per step → no internal mixing needed;  
– *Vector LSTM*: multiple cells → optional *memory mixing* via learned matrices;  
– *Matrix Aspects*: higher order structures like envelope/attention often realized by further extending to matrices so that interactions become pairwise rather than purely additive.



Together these concepts establish the foundation upon which later extensions—such as exponential gating or matrix memories—are built.  Understanding them is essential before embarking on more sophisticated variants like xLSTM introduced later in this text.

# 2. Motivations for a New LSTM Family

Large‑scale language modelling has not stopped advancing and has driven several deep learning architectures to achieve unprecedented performance. While the simple Long‑Short Term Memory (LSTM) has served as a backbone for many early successes, it still exhibits inherent design bottlenecks that limit its effectiveness in modern, billion‑parameter settings. In this chapter we dissect these three salient limitations—(i) the inability to revise already stored information, (ii) the restriction of scalar memory capacity, and (iii) the sequential nature of hidden-to‑hidden connections—and we motivate why contemporary large language models prefer Transformers or State‑Space Models (SSMs). Each subtopic is illustrated by concrete examples drawn from recent empirical investigations.

---

## State Tracking Problems and the Nearest Neighbor Search Example

The fundamental operation of an LSTM can be compactly expressed by the update equations

\[
c_t = f_t \, c_{t-1}+ i_t \, z_t \,,\qquad
h_t = o_t\,\psi(c_t)\,,
\]

where \(c_t\) is the cell state, \(h_t\) the hidden state, and \(f_t,i_t,o_t\) are the forget, input and output gates modulated by sigmoid functions. The update is additive in the cell state: each new input \(z_t\) merely pushes the stored value along a unidirectional trajectory governed by the forget gate \(f_t\). Because each element can only be shifted forward once per time step, it becomes difficult to override or correct a memory that may have been contaminated by noisy or erroneous data earlier in the sequence.

The *Nearest Neighbor Search* task provides a lucid illustration of this phenomenon. In this synthetic benchmark a vector \(x_k\) is presented first as a “reference” and subsequently a stream of candidate vectors \(x_{k+1},x_{k+2},\dots,x_T\) arrives. At the end of the sequence the model must output the label attached to whichever candidate vector is most similar to the reference. A vanilla LSTM must preserve every candidate vector in its memory until such time as more similar vectors arrive later in the stream; however its scalar cell cannot retain more than one scalar summary of each candidate vector. When a later candidate proves more similar to the reference than an earlier one, the LSTM cannot return to overwrite its previous storage; instead it retains both and thus struggles to resolve which label should be emitted. Empirical curves of mean‑squared error on this problem indeed show that classic LSTMs plateau high while architectures that augment gating with exponential decay—essentially allowing dynamic allocation and reallocation—collapse towards zero error. This reveals that without a mechanism for revising storage decisions classical LSTMs are blind to events that occur later in time—a property that sharply contrasts with human‐like memory updating.

---

## Capacity Issues Demonstrated with Rare Token Prediction

In natural language corpora token frequencies follow heavy‑tailed Zipf distributions with many high‑frequency items and an extensive tail of rare words. Successful large language models typically assign each token an embedding vector and learn contextualised representations so that rare tokens can be correctly predicted even when they appear only a handful of times during training.

The **Rare Token Prediction** benchmark directly probes this ability by partitioning Wikitext‑103 tokens into frequency bins and measuring perplexity on each bin after training an LSTM model with 300 M parameters on 15 B tokens from SlimPajama. Results show that perplexity rises sharply for lower‑frequency bins: tokens that appear fewer than ten times during training exhibit perplexities far above in‑sample performance metrics. This deterioration is symptomatic of two intertwined factors: first, each LSTM cell aggregates all incoming information into a single scalar \(c_t\), forcing *compression* of both regular syntax patterns and subtle idiosyncratic token identities into one number; second, learning signals for rare tokens do not propagage efficiently because their contribution to the overall loss is negligible compared with frequent tokens.

Model comparison experiments further highlight this limitation: when replacing the standard scalar cell with a *matrix memory* (the core innovation behind mLSTM), perplexity on rare token bins drops dramatically while performance on frequent bins remains comparable or improves modestly. Such findings underline that adequate storage capacity—beyond what scalar cells provide—is indispensable for faithfully memorising long tail semantics required at scale.

---

## Sequential Processing Bottlenecks in Hidden‑to‑Hidden Connections

Classic LSTM layers interconnect hidden states across time steps through recurrent weight matrices; formally, at every new step one multiplies \(h_{t-1}\) by a recurrent matrix \(\mathbf{R}\in \mathbb{R}^{d\times d}\). This design achieves *constant* error propagation over time but entails two practical bottlenecks:

1. **Serial Computation** – The recurrence forces linear ordering; GPU kernels cannot batch diverse time steps because each step must await completion of its predecessor. Thus even though operations within a single step can be massively parallelised (matrix–vector multiplications etc.), overall throughput grows only linearly with sequence length.

2. **Memory Footprint** – To perform backpropagation through time over long sequences one must store all intermediate hidden states or use checkpointing strategies that incur additional overhead.

These constraints become acute when scaling models to billions of parameters: training speed becomes dominated by sequence length rather than model size, hindering effective exploration of larger capacities or longer context windows.

The *State‑Space Model* family addresses this by recasting recurrent dynamics as linear systems represented by sparse matrices exponentiated over time steps; inference then reduces to fast convolutional operations equivalent in complexity to convolutional neural networks but fully parallelizable across positions. Transformers instead eliminate recurrence entirely by exchanging horizontally between tokens via self‐attention computed in parallel through matrix multiplication kernels such as FlashAttention.

Because language modelling at scale demands both long context windows (*the attention span necessary for complex syntactic or semantic phenomena*) and efficient computation (*the ability to explore larger token vocabularies and longer sequences per GPU hour*), many recent large language model design choices favour Transformer‐style attention or SSMs rather than vanilla LSTMs.

---

## Survey of Modern Large Language Models and Why They Favor Transformers or SSMs

Large transformers such as GPT-3, LLaMA, or GPT-4 demonstrate catastrophic scaling growth: adding depth and width yields consistent perplexity gains while training costs stay manageable thanks to highly optimised matrix product kernels that process all tokens simultaneously regardless of sequence length up to some limit (typically 2048 or 4096 positions). Their mostly parallel computations expose hardware aggressively; attention heads can be fused across heads into large GEMMs obtained through low–rank approximations (e.g., Linformer), reducing memory usage without significant accuracy loss.

Likewise SSMs like Mamba or H3 achieve linear computational complexity (\(\mathcal{O}(n)\)) with respect to sequence length while retaining global dependencies through implicit continuous–time dynamics encoded analytically; at test time they compute lightweight product‐of‑layer convolutions which are naturally batched over batches and context chunks.

Contrastingly, despite featuring elegant recurrent formulations (e.g., RNNs augmented with gating), pure recurrent models exhibit limited scaling behaviour: additional layers yield diminishing returns because longer sequences expose inefficiencies tied to sequential evaluation—each new example forces recalculating everywhere along all activated timesteps.

Consequently contemporary research directions encourage deploying either Transformer families—with efficient causal attention kernels—or SSMs—to push billions of parameter regimes for language modeling while keeping runtime acceptable.

---

By exposing these three core impairments—poor state revision capacity, inadequate scalar storage due to severe compression, and sequential bottlenecks imposed by hidden‑to‑hidden connections—we motivate why modern large language models lean heavily towards architectures that either dispense with recurrence entirely or replace it with highly parallelisable dynamical systems such as SSMs. In subsequent chapters we will see how extending basic LSTMs with exponential gating and matrix memories offers partial resolutions to these issues without abandoning the proven strengths of recurrence: gated update rules, convenient integration into residual backbones, and principled interpretation frameworks rooted in early RNN research.

# Chapter 3  
## Exponential Gating – The Core Innovation

In the original LSTM, the gating functions are prescribed as sigmoids that bound the values between 0 and 1. This choice was historically motivated by biological plausibility and by the observation that clipping close the cell’s additive update facilitates training. xLSTM departs radically from this conventional perspective by allowing gates to take values on the full positive real axis, i.e. to be **exponential** in their pre‑activation. The exponential family gives a two‑fold advantage: it turns forgetting into a *decay* that can be smaller than one, and it lets the model *amplify* useful memories without forcing an artificial cap at one. This section explains in depth how the gates are redefined, how a cumulative normalizer tracks the magnitude of all future forgetting, how a stabilizer mitigates overflow, and why these changes are mathematically benign.

### 3.1 Redefining Input, Forget, and Output Gates with Exponentials

Recall that in a vanilla LSTM at time step \(t\) we compute three gating signals from linear combinations of the current input \(\mathbf{x}_t\in\mathbb{R}^{d_x}\) and previous hidden state \(\mathbf{h}_{t-1}\in\mathbb{R}^{d_h}\):
\[
\begin{aligned}
\tilde{i}_t &= \mathbf{w}_i^\top \mathbf{x}_t + r_i h_{t-1} + b_i , &
i_t &= \sigma(\tilde{i}_t) ,\\
\tilde{f}_t &= \mathbf{w}_f^\top \mathbf{x}_t + r_f h_{t-1} + b_f , &
f_t &= \sigma(\tilde{f}_t) ,\\
\tilde{o}_t &= \mathbf{w}_o^\top \mathbf{x}_t + r_o h_{t-1} + b_o , &
o_t &= \sigma(\tilde{o}_t) .
\end{aligned}
\]
The nonlinearities are all classic sigmoids \(\sigma(x)=1/(1+\exp(-x))\). In xLSTM we replace two of these with exponentials:
\[
i_t = \exp(\tilde{i}_t), \qquad
f_t = 
\begin{cases}
\sigma(\tilde{f}_t) & \text{or}\\
\exp(\tilde{f}_t)
\end{cases}, 
\qquad
o_t = \sigma(\tilde{o}_t).
\]
The output gate remains a sigmoid because it serves purely as a soft mask on the *normalized* cell state; raising it to an exponential would blow up the hidden activation. The choice between a sigmoid or an exponential for \(f_t\) is governed by **forget gate temperature**: using a sigmoid keeps the forget factor bounded in (0, 1); using an exponential allows it to be any strictly positive number, hence potentially > 1 and capable of *injecting* more memory than was present previously.

By exponentiating \(i_t\) we guarantee that every new contribution \(i_t z_t\) added to the cell state is strictly positive and can scale arbitrarily high if needed. This removes both underflow (tiny updates lost due to clipping at zero) and ceiling (updates artificially capped at one). The long‑term dynamics of the cell state are governed by
\[
c_t = f_t\, c_{t-1} + i_t\, z_t ,
\]
so that if we wish to *rewrite* older information we simply choose a large \(i_t>1\); if we want to forget moderately we pick \(0<f_t<1\).

### 3.2 Normalization via a Cumulative Normalizer State

Directly exponentiating gates would make the cell state unbounded. To keep it in check we introduce a **cumulative normalizer** \(n_t\), defined recursively together with \(c_t\):
\[
n_t = f_t\, n_{t-1} + i_t .
\]
The intuition is that \(n_t\) measures *the total weight of all future forget operations applied to past inputs*. When we compute the hidden activation we normalize the cell state by this cumulative weight:
\[
h_t = o_t\, \widetilde{h}_t, 
qquad
\widetilde{h}_t = \frac{c_t}{n_t}.
\]
Because both \(c_t\) and \(n_t\) evolve under identical multiplicative dynamics, their ratio remains stable even when each grows exponentially large or small. This is analogous to dividing numerator and denominator by their common factor so that only relative contributions matter.

If every gate were bounded (sigmoids), \(n_\infty=\sum_i i_i f_{i+1}\ldots f_\infty < \infty,\) but with exponentials it can diverge. Normalization guarantees that no single time step inflates hidden activations uncontrollably.

### 3.3 Stabilizer State \(m_t\) and Guard Against Overflow

Despite normalization, intermediate products such as \(f_tf_{t-1}\cdots f_2 f_1\, c_0\) can still grow astronomically during forward propagation or back‑propagation through many steps; naive implementation would quickly hit floating‑point limits leading to NaNs or infinities.

xLSTM therefore introduces an auxiliary *stabilizer* state:
\[
m_t = \max(\, m_{t-1} + \log f_t,\; \log i_t\,).
\]
Intuitively, \(m_t=\max_k(\log i_k + \sum_{\ell=k+1}^T \log f_\ell)\), i.e. the logarithm of the largest contribution among all future values reachable from step \(k=t,t+1,\dots,T.\)

Using this stabilizer we reparameterize gates as
\[
i'_t = e^{\, \$ }\quad 
      = e^{\, (\tilde{i}_t - m_t)} , 
      \qquad
f'_t = e^{\, (\log f_t + m_{t-1}-m_t)}.
\]
Because all quantities inside exponentials are now bounded between 0 and 1 (as per construction: each term is either negative or zero), numerical overflow is avoided even when many layers or very long sequences are present.

Crucially, this stabilization **does not alter** either forward outputs or backward gradients. The redefinition simply pulls out the common exponential factor from numerator and denominator everywhere in which it appears; since gradients involve ratios of such terms this factor cancels exactly.

### 3.4 Equivalence Proofs: Replacing Gates with Stabilized Versions Preserves Gradients

Formally, let us define two forward passes:

| Convention | Gate | Equivalent stabilized gate |
|------------|------|----------------------------|
| Plain | \(i=\exp(\tilde{i}) , f=\exp(\tilde{f})/?\)|\(i'=e^{\, (\tilde{i}-m)} , f'=e^{\, (\ln f+m_{prev}-m)}|\)

We claim that for any sequence length \(T,\) for any inputs and parameters,
the hidden activations produced by both passes are identical:
\(h^{(plain)}_T = h^{(stab)}_T.\)

**Proof Sketch**  
We proceed by induction on time step \(t.\)

Base case (\(t=0:\)) Both versions set initial states identically: \(c_0=n_0=h_0=0,\ m_0=\max(0)\).

Inductive step: Assume true up to time \(t-1.\)
Define
\(f_\text{pure}=e^{\, g_f}, i_\text{pure}=e^{g_i}\)
and similarly set
\(f_= e^{g_f-m_{prev}+m}, i_= e^{g_i-m}\).
By construction,
\(c_\text{pure}= c_{\text{pure}}(prev)\cdot e^{g_f}+e^{g_i}z,\)
\(c_= c_{\text{pure}}(prev)\cdot e^{-m_prev+m} e^{g_f}+e^{-m+m} e^{g_i}z.
Given inductive hypothesis *and* that  
\(m=\max(m_prev+\ln f,\;\ln i)\), one can verify algebraically that

\(c_=c_\text{pure}/Z,\quad n_=n_\text{pure}/Z,\)

where \(Z=e^m.\)
Thus,
\(h=(o)(c/n)= (o)(c_/n_)=(o)(c_\text{pure}/n_\text{pure}), 
so hidden states coincide.

Gradients flow through multiplicative chains involving identical ratios; hence derivatives of loss w.r.t any parameter match in both formulations (by chain rule).

∎

A full derivation is provided in Appendix A where each term is expanded using logarithmic identities.

### 3.5 Practical Hyperparameter Choices for Activation Functions

While mathematically nothing prohibits us from combining sigmoids with exponentials arbitrarily, empirical evidence guides our design:

| Gate | Recommended activation | Rationale |
|------|------------------------|-----------|
| Input | Exp | Ensures strictly positive additive updates; permits non‑bounded amplification |
| Forget | Exp | Allows both decay < 1 and growth > 1; key for *dynamic* forgetting/revising |
| Output | Sigmoid | Keeps hidden activations bounded after normalization |
| Pre‑activations | Linear (no nonlinearity yet) | Parameter learning unbottled; future layers decide scaling |

When using an exponential forget gate over long sequences (> 10 k steps), initializing its bias slightly negative (\(b_f=-4.0)\) prevents immediate runaway growth while still permitting controlled amplification later.

Stabilizer parameters: start with \(m_0= -1000.\) This ensures early gates do not get artificially suppressed before any larger contribution arises.

Finally, note that during training it is common practice to apply **layer‑norm** upstream of gates, which keeps pre‑activations centered close to zero; this allows balanced gradients early on while still granting full exponential range later.

---

By redefining gates exponentially, normalizing them through a cumulative normalizer state, and guarding against overflow with a stabilizer you gain two key properties:

1. **Memory Revision** – The network can overwrite older memory entries on demand because forgetting need not be capped below one.
2. **Scalable Capacity** – Exponential growth permits richer internal representations without compressing everything into a small scalar constant error carousel.

Together these form the core innovation of xLSTM’s gating mechanism.*

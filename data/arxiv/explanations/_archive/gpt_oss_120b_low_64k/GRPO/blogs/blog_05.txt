# Putting It All Together: How DeepSeekMath 7B Reaches 51.7 % on the Competition‑Level MATH Benchmark  

Large language models have become the go‑to tool for solving math problems, but most publicly available models still lag far behind the closed‑source giants such as GPT‑4 or Gemini‑Ultra. The new **DeepSeekMath 7B** narrows that gap dramatically, hitting **51.7 %** on the competition‑level **MATH** benchmark—without any external toolkits, chain‑of‑thought voting, or ensemble tricks. In this post we walk through the full training “recipe” that made it possible, compare the result with other open‑source and proprietary models, and explain what the reported **self‑consistency over 64 samples (60.9 %)** means for everyday users.

---

## 1. From Code to Math: The Base Model  

DeepSeekMath starts from **DeepSeek‑Coder‑Base‑v1.5 (7 B)**, a model already fine‑tuned on a massive code corpus. Why begin with code?  

* **Structured reasoning:** Coding data teaches the model to follow precise logical steps and handle symbolic manipulation—skills that transfer directly to mathematics.  
* **Empirical boost:** Experiments in the paper show that a code‑first pre‑training stage improves both *tool‑free* and *tool‑assisted* math performance, even at the modest 7 B scale.  

The base model inherits all the coding abilities of DeepSeek‑Coder, which later helps when we ask it to write Python for program‑of‑thought (PoT) prompts.

---

## 2. Massive Math Pre‑Training (500 B Tokens)

### 2.1 The DeepSeekMath Corpus  

The heart of the improvement is a curated **120 B token math corpus** scraped from Common Crawl. The pipeline works as follows:

1. **Seed set:** OpenWebMath provides a high‑quality seed of ~500 k positive examples.
2. **FastText classifier:** Trained on the seed vs. a balanced set of random web pages; scores each page for “math‐likeness.”
3. **Iterative mining:** Pages with top scores are added to the seed; the classifier is retrained; this repeats four times, ending with **35.5 M web pages** (≈120 B tokens).  
4. **Multilingual coverage:** Over half of the tokens are English; a substantial portion is Chinese, which later yields gains on Chinese math benchmarks.
5. **Decontamination:** Any n‑gram that matches benchmark data (GSM8K, MATH, CMATH, etc.) is stripped to avoid leakage.

The final corpus is *seven times larger* than Minerva’s math web pages and *nine times larger* than OpenWebMath, while maintaining higher average quality (validated by downstream few‑shot evaluations).

### 2.2 Training Details  

* **Token mix:** 56 % DeepSeekMath Corpus, 4 % AlgebraicStack (math code), 10 % arXiv papers, 20 % GitHub code, 10 % general natural language.
* **Schedule:** Same AdamW hyperparameters as DeepSeek LLMs; peak LR = 4.2 × 10⁻⁴; batch size = 10 M tokens; context length = 4K.
* **Duration:** 500 B tokens total (≈4 epochs over the math corpus).  

The result—**DeepSeekMath‑Base 7B**—already outperforms many larger closed models on pure reasoning benchmarks:

| Benchmark | DeepSeekMath‑Base | Minerva 540B | Mistral 7B |
|-----------|-------------------|--------------|------------|
| GSM8K (grade school) | 64.2 % | 63.x % | ~45 % |
| MATH (competition) | 36.2 % | 35.x % | ~22 % |

So even before any instruction tuning, a modest 7 B model reaches parity with a 540 B closed system.

---

## 3. Instruction Tuning: CoT + PoT + Tool‑Integrated Reasoning  

Next comes **DeepSeekMath‑Instruct 7B**, trained on a curated set of ~776 K examples that cover three solution styles:

| Style | Data source | What it teaches |
|-------|------------|-----------------|
| Chain‑of‑Thought (CoT) | GSM8K, MATH annotations + MathInstruct + Lila-OOD | Stepwise natural language reasoning |
| Program‑of‑Thought (PoT) | Same sources but solutions expressed as Python scripts using `math` / `sympy` | How to offload heavy arithmetic to code |
| Tool‐Integrated Reasoning (ToRA) | Custom tool prompts where the model calls an external calculator or evaluator | Seamless switching between text and tool usage |

Training uses a simple cross‑entropy loss for 500 steps (batch size 256, LR 5e−5). No RL yet—just supervised learning that teaches *how* to format answers.

### Performance Jump

| Benchmark | DeepSeekMath‑Base | DeepSeekMath‑Instruct |
|-----------|-------------------|-----------------------|
| GSM8K (CoT) | 64.2 % | **88.2 %** |
| MATH (CoT) | 36.2 % | **46.8 %** |
| MATH (tool‐enabled) | – | **≈60 %** |

Compared to other open‐source giants (e.g., WizardMath 7B, InternLM2‑Math 20B), DeepSeekMath‑Instruct already beats them despite being only half the size of many competitors.

## 4. Reinforcement Learning with Group Relative Policy Optimization (GRPO)

### 4.1 Why RL?  

Instruction tuning improves *how* to answer but does not directly optimize for the *correctness* metric used in benchmarks. Reinforcement learning lets us push the policy toward higher reward scores derived from a learned reward model.

### 4.2 GRPO vs. Classic PPO  

Standard PPO couples a policy with a separate value network (“critic”), which is memory hungry—problematic for multi‐GPU training of LLMs. GRPO cuts this overhead by:

1. **Sampling a group** of \(G\) outputs per question from the *old* policy.
2. Using the *average* reward of that group as the baseline instead of a learned value function.
3. Computing tokenwise advantages based on *relative* rewards within the group.
4. Applying a KL penalty directly between current and reference policies rather than embedding KL into each token reward.

The net effect is an RL algorithm that needs **no extra critic model**, thus saving GPU memory while still benefiting from advantage estimation.

### 4.3 Training Set & Settings  

* Only the CoT-style instruction data (`GSM8K` + `MATH`) → ~144 K questions.
* For each question sample **64** completions (the “self-consistency” set).
* Reward model trained on preference data derived from correct/incorrect answer judgments.
* Learning rates: reward model 2e−5; policy model 1e−6; KL coefficient = 0.04.

### 4.4 Results – The Final Score  

After one round of GRPO:

| Metric | Before GRPO (Instruct) | After GRPO (RL) |
|--------|------------------------|-----------------|
| GSM8K (CoT) | 88.2 % | **88.2 %** (unchanged – already saturated) |
| MATH (CoT) | 46.8 % | **51.7 %** |
| MATH self‑consistency (64 samples) | – | **60.9 %** |

The leap from 46.8 % → 51.7 % on MATH puts DeepSeekMath 7B *ahead of every other open source model up to at least 70 B*, and only behind closed systems like GPT‑4 or Gemini Ultra.

## 6. Self‑Consistency Over 64 Samples: What Does It Mean for You?

Self-consistency is a simple inference trick introduced by Wei et al.: generate multiple completions for the same question, then pick the answer that appears most often among them.

* In DeepSeekMath’s experiments they produced **64** answers per MATH problem.
* The majority vote raised accuracy from **51.7 % → 60.9 %**, i.e., nearly a ten point jump simply by sampling more.

For end users this translates into:

1️⃣ **Higher reliability** when you can afford extra compute—run several generations and take a majority vote or run a lightweight consistency scorer.

2️⃣ **No architectural changes needed**; it works out-of-the-box with any fine-tuned model.

3️⃣ A practical tradeoff: generating many samples costs more GPU time but yields an accuracy boost comparable to adding another RL fine-tuning pass.

## 7. Takeaways & Future Directions  

- **Data matters more than scale:** A carefully filtered web crawl can give a small model capabilities rivaling multi‐hundred–billion parameter closed models.
- **Code first → math later:** Starting from a code LLM gives an immediate reasoning edge.
- **GRPO makes RL affordable:** By dropping the critic network you can run PPO‐style RL on commodity hardware without sacrificing performance.
- **Self-consistency is cheap performance gain:** Sampling many outputs and voting can add ~9 points on hard benchmarks.
- **Room to grow:** Geometry and theorem proving still lag behind closed models; multilingual data selection could be refined further; larger reward models or better process supervision might push Maj@K even higher.

DeepSeekMath demonstrates that with clever data engineering and an efficient RL algorithm, even a modestly sized open-source LLM can break through long-standing performance ceilings in mathematical reasoning.

--- 

**TL;DR:** DeepSeekMath’s recipe—code‐pretrained base → massive CommonCrawl math pretraining → multi‑style instruction tuning → memory‑light GRPO reinforcement learning → self-consistency sampling—delivers an unprecedented **51.7 %** score on competition‐level MATH for any open-source model today, narrowing the gap to proprietary giants and opening new doors for math‐centric AI applications without paying for closed APIs.

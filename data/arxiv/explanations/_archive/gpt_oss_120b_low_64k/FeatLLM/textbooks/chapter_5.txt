\title{A Textbook about the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

Chapter 5: Learning from Generated Features
=================================

In the **FeatLLM** framework the heavy‑weight reasoning is delegated to a large language model (LLM) that, given a few labeled examples, produces a collection of human‑readable rules.  Each rule is then turned into a binary feature indicating whether an individual record satisfies that rule.  After this transformation the original high‑dimensional tabular problem has been reduced to a much simpler classification problem: the model must infer class probabilities from a set of binary indicators.  This chapter explains in detail how the lightweight downstream model is built, how it is trained on the few‑shot data, and why its parameters can be interpreted as measures of rule importance.

### Linear Model without Bias and Non‑Negative Weight Projection

For every target class \(k\) (where \(k\in\{1,\dots,c\}\) and \(c\) is the total number of classes) FeatLLM constructs a vector of binary rule‑features
\[
\mathbf{z}^{i}_{k}= \bigl(z^{i}_{k,1},\,z^{i}_{k,2},\,\dots,\,z^{i}_{k,R}\bigr)^{\!\top}\in\{0,1\}^{R},
\]
where \(R\) denotes the fixed number of rules generated for that class (the paper adopts \(R=10\)).  Each entry \(z^{i}_{k,r}=1\) if the \(i\)-th sample satisfies rule \(r\) for class \(k\), and \(0\) otherwise.

The downstream predictor is deliberately kept *linear* and *bias‑free*:
\[
\text{logit}^{i}_{k}= \bigl[\max(\mathbf{w}_{k},0)\bigr]^{\!\top}\mathbf{z}^{i}_{k}
      = \sum_{r=1}^{R}\max(w_{k,r},0)\;z^{i}_{k,r}.
\tag{1}
\]
Here \(\mathbf{w}_{k}=(w_{k,1},\dots,w_{k,R})^{\!\top}\) are trainable parameters.  The projection \(\max(\cdot,0)\) enforces non‑negativity on every weight.  This design choice guarantees that a rule which fires (i.e., yields a ‘1’) can never *decrease* the logit for its associated class; at worst it leaves the logit unchanged.  Consequently the model respects the intuition that the LLM‑generated rules are intended to be *evidence* for a class rather than counter‑evidence.

Because the model contains no bias term, it cannot arbitrarily shift all logits upward or downward; all adjustments stem directly from the presence of rule activations, making the mapping from rules to predictions transparent and easy to audit.

### Logit Computation and Softmax Conversion

After computing a logit for each class with equation (1), FeatLLM converts these scores into a proper probability distribution over classes by applying the softmax function:
\[
p^{i}_{k}
   = \frac{\exp(\text{logit}^{i}_{k})}{\displaystyle \sum_{j=1}^{c}\exp(\text{logit}^{i}_{j})},
   \qquad
   \mathbf{p}^{i}= \bigl(p^{i}_{1},\,p^{i}_{2},\,\dots,\,p^{i}_{c}\bigr).
\tag{2}
\]
The softmax ensures that \(\sum_{k=1}^{c} p^{i}_{k}=1\) and that larger logits correspond to higher predicted probabilities.  Because logits are linear combinations of binary features with non‑negative coefficients, a higher count of satisfied rules for a given class tends to raise its probability, but the learned weights modulate this effect: some rules may contribute more heavily than others.

### Cross‑Entropy Loss with Few‑Shot Data

Training proceeds on the limited set of labeled examples available in a few‑shot regime (e.g., \(k=4,8,\dots\)).  Let \(\mathbf{y}^{i}\) denote the one‑hot ground‑truth label vector for sample \(i\).  The standard multiclass cross‑entropy loss is employed:
\[
\mathcal{L}
   = - \frac{1}{K}\sum_{i=1}^{K}
      \sum_{k=1}^{c} y^{i}_{k}\,\log p^{i}_{k},
      \qquad
      K = k N_{\text{shots}}.
\tag{3}
\]
Because only a tiny number of examples are used, the loss surface can be noisy; nevertheless, equation (3) provides an unbiased estimator of the expected negative log likelihood under the model.  Minimising \(\mathcal{L}\) directly tunes the weight vectors \(\{\mathbf{w}_k\}\), thereby learning how much each rule should influence its corresponding class.

### Interpretability of Learned Weights as Rule Importance

A central advantage of this linear formulation is interpretability.  After training, each weight component \(w_{k,r}\) can be inspected:

* If \(w_{k,r}=0\), rule \(r\) contributes nothing to class \(k\)’s logit; effectively the rule has been discarded.
* Larger positive values indicate that satisfying rule \(r\) is strong evidence for class \(k\).
* Because weights are shared only within their class (there is no cross‑class coupling), one can compare importance rankings across classes directly.

When combined with the original textual description of each rule (generated by the LLM), practitioners obtain an immediately actionable explanation: “Rule *‘Age > 65 AND Cholesterol > 200’* carries weight 0.87 for predicting heart disease,” for example.  Moreover, because FeatLLM discards rules whose learned weight falls below a small threshold (e.g., 0.1), noisy or spurious rules generated from irrelevant columns are automatically filtered out during training.

### Training Hyper‑Parameters (Optimizer, Epochs, Early Stopping)

Despite its simplicity, careful configuration of optimisation hyper‑parameters helps achieve stable performance:

| Hyper‑parameter | Typical setting in the paper | Rationale |
|-----------------|------------------------------|----------|
| Optimiser       | Adam                         | Adaptive moments help when gradients are sparse due to many zero entries in binary features |
| Learning rate   | \(0.01\)                     | Large enough to make rapid progress on few data points while avoiding divergence |
| Number of epochs| 200                          | Sufficient to converge given a small dataset; early stopping based on validation loss prevents over‑fitting |
| Early stopping  | Choose epoch with best validation loss among k‑fold splits | Guarantees that we do not over‑train on noisy few‑shot signals |

Training proceeds with **\(k\)-fold cross‑validation** on the available shots: each fold leaves out a subset as a validation set while training on the remainder.  The epoch achieving the lowest validation loss across folds is selected for final inference.  This strategy mitigates variance caused by extremely small training sets.

Finally, after a single trial has produced its set of binary features and trained weights, FeatLLM repeats the entire pipeline multiple times (the paper uses \(T=20\) ensembles).  Each trial differs due to random temperature sampling in LLM generation and random shuffling of few‑shot examples; consequently multiple diverse rule sets are produced.  The final prediction for any sample is obtained by averaging the softmax probabilities across all trials:
\[
\bar{\mathbf{p}}^{i}= \frac{1}{T}\sum_{t=1}^{T}\mathbf{p}^{i}[t],
\]
where \(\mathbf{p}^{i}[t]\) denotes probabilities computed with weights from trial \(t\).  Ensembling further stabilises predictions and reduces sensitivity to any single erroneous rule set.

Through this lightweight yet expressive downstream model—linear, bias‑free, non‑negative—we turn raw natural‐language rules into actionable numerical features and learn their relative relevance directly from scarce labelled data.  The resulting system retains interpretability, incurs negligible inference cost compared with end‑to‑end LLM approaches, and robustly leverages both prior knowledge encoded in LLMs and information present in few‐shot examples.

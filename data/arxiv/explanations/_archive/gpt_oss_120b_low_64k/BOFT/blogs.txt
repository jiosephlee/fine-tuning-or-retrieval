\title{Blogs about the Paper: "Parameter-Efficient Orthogonal Finetuning via Factorization"}

# Why Orthogonal Finetuning Matters: Preserving Knowledge in Large Models

Large foundation models such as GPT‑4, Stable Diffusion, or vision transformers have shown an incredible ability to generalize across a wide range of tasks. Yet fine‑tuning these massive networks for a specific downstream problem is still expensive—both in terms of compute and the number of trainable parameters required.  

A recent line of work proposes **Orthogonal Finetuning (OFT)** as a principled alternative to the more common parameter‑efficient approaches like LoRA, adapters, or prompt tuning. In this post we walk through the intuition behind OFT, why preserving the relational geometry of pretrained weights matters, and how newer refinements such as **Orthogonal Butterfly (BOFT)** make OFT practical for real‑world applications.

---

## The Core Idea: Transform, Don’t Replace

When we fine‑tune a pretrained linear layer with weight matrix \(\mathbf{W}^{0}\in\mathbb{R}^{d\times n}\), the usual strategies are:

| Method | How it updates \(\mathbf{W}^{0}\) | Parameter budget |
|--------|-----------------------------------|------------------|
| **Full finetuning** | Directly replaces \(\mathbf{W}^{0}\) with a new matrix \(\mathbf{W}\) | \(d\times n\) |
| **LoRA** | Adds a low‑rank product \(\Delta\mathbf{W}= \mathbf{A}\mathbf{B}^{\top}\) (\(\operatorname{rank}=r\ll d,n\)) | \(r(d+n)\) |
| **Adapters / prompts** | Insert small trainable modules or prefix tokens | Varies, but still extra parameters |
| **OFT** | Multiplies on the **left** by an orthogonal matrix \(\mathbf{R}\in\mathbb{R}^{d\times d}\): \(\mathbf{W}= \mathbf{R}\mathbf{W}^{0}\) | Up to \(d^{2}\) (dense) |

The key distinction is that OFT **preserves the pairwise angles between neurons**. Each column of \(\mathbf{W}^{0}\) corresponds to a neuron; an orthogonal transformation \(\mathbf{R}\) rotates (or reflects) the whole space without stretching it. Consequently:

* The inner products \(\langle\mathbf{w}_{i}^{0},\mathbf{w}_{j}^{0}\rangle\) remain unchanged after finetuning.
* The singular values of \(\mathbf{W}^{0}\) – and thus its spectral norm – are exactly preserved.
* The pretrained geometric structure, which encodes the knowledge learned from massive corpora, stays intact.

Preserving this relational geometry has two practical benefits:

1. **Better generalization** – the model does not over‑fit to idiosyncrasies of the downstream data because the core representation space remains faithful to the pretraining distribution.
2. **Training stability** – keeping the spectral norm fixed avoids exploding/vanishing gradients that often plague aggressive finetuning.

---

## From Theory to Practice: The Parameter‑Efficiency Challenge

A full orthogonal matrix requires \(\mathcal{O}(d^{2})\) free parameters, which defeats the purpose of “parameter‑efficient” finetuning. The original OFT paper tackled this by imposing a **block‑diagonal structure** on \(\mathbf{R}\):
\[
\mathbf{R}= \operatorname{diag}(\mathbf{R}_{1},\dots,\mathbf{R}_{r}), \qquad \mathbf{R}_{i}\in\mathbb{R}^{b\times b},~~br=d.
\]
Each block is orthogonal, reducing trainable parameters to \(\mathcal{O}(bd)\). While this works, it introduces two drawbacks:

* The block partition is arbitrary—splitting a neuron’s dimensions into groups based on index has no semantic meaning.
* Block‑diagonal matrices cannot represent many classic linear transforms (e.g., Fourier or Hadamard), limiting expressivity.

The natural question becomes: *Can we obtain a dense orthogonal matrix while keeping the parameter count low?*

---

## An Information‑Transmission Perspective

Think of a dense matrix as a complete communication graph: every input dimension can influence every output dimension. If we factor \(\mathbf{R}\) into several sparse matrices
\[
\mathbf{R}= \mathbf{B}_{m}\mathbf{B}_{m-1}\dots\mathbf{B}_{1},
\]
each sparse factor corresponds to one “hop” in an information‑transmission grid.  

The goal is to design sparse hops that collectively connect every source node to every destination node **with as few edges as possible**. Under orthogonality constraints each hop must be a bijection on its node set (i.e., contain exactly \(d\) non‑zero entries), but beyond that we have design freedom.

---

## Butterfly Factorization – The Fast Fourier Trick Meets Finetuning

The Cooley–Tukey Fast Fourier Transform (FFT) famously uses a **butterfly network** to exchange information efficiently. A butterfly graph with \(d=2^{N}\) nodes achieves dense connectivity using only \(\mathcal{O}(d\log d)\) edges—far fewer than the naïve \(d^{2}\).

By adopting this structure for OFT we obtain an **Orthogonal Butterfly (BOFT)** parameterization:

1. Each butterfly factor \(\tilde{\mathbf B}(d,k)\) is block‑diagonal with \(k\times k\) butterfly blocks.
2. Every block is enforced orthogonal using a Cayley transform (or directly as a 2‑D rotation when \(k=2\)).
3. The final orthogonal matrix is a product of \(m=\log_{2} d\) such factors:
   \[
   \mathbf R(m,b)=\prod_{i=1}^{m} \tilde{\mathbf B}^{\,b}_{(d,i)},
   \]
   where \(b\) is the block size (often set to 2 for maximal efficiency).

Parameter count drops from \(\mathcal{O}(d^{2})\) to
\[
\underbrace{\frac12(b-1)d\,m}_{\text{effective trainable}} = \mathcal O(d\log d),
\]
while still yielding a *dense* orthogonal transformation.

When we set \(m=1,b=d\), BOFT collapses back to original OFT; when we set \(m=\log d,b=2\), we get a fully dense orthogonal matrix with only \(\mathcal O(d\log d)\) trainable parameters.

---

## How BOFT Compares to LoRA and Adapters

| Aspect | LoRA (low‑rank additive) | Adapters (extra layers) | OFT (dense orthogonal) | BOFT (butterfly orthogonal) |
|--------|--------------------------|--------------------------|------------------------|------------------------------|
| Update rule | \(\mathbf W = \mathbf W^{0}+ \Delta\mathbf W,\;\Delta\mathbf W = AB^{\top}\) | Insert small MLPs between layers | \(\mathbf W = \mathbf R\,\mathbf W^{0},~~\mathbf R^{\top}\!\!\mathbf R = I\) | Same multiplicative form, but \(\mathbf R = \prod_i \tilde{\mathbf B}_i\) |
| Parameter scaling | Linear in rank \(r\) | Depends on adapter width/depth | Quadratic in hidden dim (if dense); linear in block size otherwise | Nearly linear: \(d\log d\) |
| Geometry preservation | None (adds new directions) | None (adds new non‑linear pathways) | Exactly preserves pairwise angles & spectral norm | Same guarantees + structured inductive bias |
| Typical use‑case | Language models, cheap finetuning | Vision transformers, multimodal models | Text‑to‑image diffusion control (original paper) | Broad range: LLMs, vision transformers, diffusion models |

Empirically, BOFT consistently outperforms LoRA and adapters on tasks ranging from image classification to language understanding while using fewer trainable parameters.

---

## Practical Tips for Using BOFT

1. **Identity initialization** – Start each butterfly component as an identity matrix (Cayley’s skew‑symmetric part set to zero). This gives zero change at epoch 0 and mirrors LoRA’s zero init.
2. **Multiplicative dropout** – Randomly replace selected butterfly components or their internal blocks by identity matrices during training; this prevents over‑fitting without breaking orthogonality.
3. **Choosing \(b,m\)** – Small block size (\(b=2\)) with enough factors (\(m=\log d\)) yields maximal parameter efficiency; larger blocks reduce depth at the cost of more parameters.
4. **Inference cost** – After training, multiply the learned orthogonal matrix into the frozen pretrained weights once; there is no extra runtime overhead during inference.

---

## Takeaway

Orthogonal Finetuning offers a mathematically clean way to adapt gigantic models while *exactly* preserving their internal geometry—a property that translates into better generalization and training stability. The original block‑diagonal OFT sacrificed expressivity for efficiency; BOFT restores dense expressivity by borrowing the butterfly factorization from fast Fourier transforms. The result is a versatile, parameter‑efficient finetuning toolkit that works across vision, language, and generative domains.

If you’re looking for a finetuning method that respects what your foundation model already knows—and does so without exploding your parameter budget—give Orthogonal Butterfly a try.



# From Block‑Diagonal to Butterfly: Making Orthogonal Finetuning Parameter‑Efficient  

## Introduction  

Large foundation models—think GPT‑3, Stable Diffusion, or modern vision transformers—have become the workhorses of AI research. Training them from scratch is a multi‑million‑dollar endeavour, so most practitioners spend their time **adapting** a pretrained model to a downstream task. Among the many adaptation strategies (adapter layers, prompt tuning, low‑rank updates), **model finetuning** remains the simplest: we keep the original architecture and only adjust a subset of its weights.  

A recent finetuning paradigm called **Orthogonal Finetuning (OFT)** takes a principled approach: instead of adding or subtracting small changes, it multiplies each layer’s weight matrix by an *orthogonal* matrix \(\mathbf{R}\). Because orthogonal transformations preserve pair‑wise angles between neurons, the pretrained knowledge is largely retained, leading to better stability and generalisation compared with classic methods such as LoRA.  

The drawback? A full \(d \times d\) orthogonal matrix needs \(\mathcal{O}(d^{2})\) trainable parameters—far too many for parameter‑efficient finetuning (PEFT). The original OFT paper mitigated this by forcing a **block‑diagonal** structure on \(\mathbf{R}\), which reduces parameters but also imposes harsh sparsity patterns and limits expressivity.  

In this post we unpack why block‑diagonal OFT falls short and how the authors of *Parameter‑Efficient Orthogonal Finetuning via Factorization* replace it with a **butterfly factorization**—the same sparse pattern that powers the Fast Fourier Transform (FFT). The result is a dense orthogonal transformation that can be learned with only \(\mathcal{O}(d\log d)\) parameters, a huge win for large models.

---

## Why Block‑Diagonal OFT Is Not Enough  

### The original OFT formulation  
Given a pretrained linear layer \(\mathbf{W}^{0}\in\mathbb{R}^{d\times n}\), OFT replaces the forward pass  

\[
\mathbf{z}=({\mathbf{W}^{0}})^{\!\top}\mathbf{x}
\]

with  

\[
\mathbf{z}=({\mathbf{R}\mathbf{W}^{0}})^{\!\top}\mathbf{x},
\qquad \mathbf{R}\in\mathbb{R}^{d\times d},\;\;\mathbf{R}^{\!\top}\mathbf{R}=\mathbf{I}.
\]

The orthogonal matrix \(\mathbf{R}\) is learned while \(\mathbf{W}^{0}\) stays frozen. Orthogonality guarantees that the singular values of \(\mathbf{W}^{0}\) (and thus its spectral norm) stay unchanged—a property linked to training stability.

### Block‑diagonal compromise  
A naïve dense orthogonal matrix would need \(d^{2}\) free entries. To cut costs, the authors of OFT introduced a block‑diagonal constraint:

\[
\mathbf{R}= \operatorname{diag}(\mathbf{R}_{1},\,\mathbf{R}_{2},\,\dots,\mathbf{R}_{r}),
\qquad
\mathbf{R}_{i}\in\mathbb{R}^{b\times b},
\; br = d .
\]

Each small block \(\mathbf{R}_{i}\) is orthogonal, so the total number of learnable parameters scales like \(rb^{2}=bd = \mathcal{O}(bd)\). When \(b \ll d\), the reduction is substantial.

**What we lose:**  
1. **Dense connectivity** – neurons in different blocks never interact because the off‑diagonal blocks are forced to zero.  
2. **Expressivity** – many classic linear transforms (Fourier, Hadamard, etc.) cannot be expressed as a block‑diagonal matrix.  
3. **Inductive bias uncertainty** – the choice of block size and alignment with neuron indices is arbitrary; there is no principled way to decide which sparsity pattern best suits a downstream task.

Thus we need a way to keep \(\mathbf{R}\) dense in effect while still using far fewer parameters than \(d^{2}\).

---

## Information Transmission: Re‑thinking Orthogonal Matrices  

The authors recast the problem as an **information‑transmission graph**. Imagine a grid with \(d\) nodes at each of \(m+1\) layers (one layer per factor matrix). If we factorize \(\mathbf{R}\) as  

\[
\mathbf{R}= \mathbf{B}_{m} \mathbf{B}_{m-1}\dots \mathbf{B}_{1},
\]

each sparse factor \(\mathbf{B}_{i}\) defines directed edges from layer \(i-1\) to layer \(i\). The product is dense iff **every source node can reach every sink node** after traversing all layers.  

Two desiderata emerge:

| Desideratum | Meaning |
|-------------|---------|
| **Dense connectivity** | For any pair of source–sink nodes there exists at least one path through the graph. |
| **Minimum free edges** | Use as few trainable (non‑fixed) edges as possible while preserving orthogonality. |

A naïve dense factor (\(m=1,\;\mathbf{B}_{1}=\) dense orthogonal) satisfies connectivity but incurs \(\mathcal{O}(d^{2})\) parameters. A clever topology can achieve dense connectivity with far fewer edges.

Enter the **butterfly graph**, famous from the Cooley–Tukey FFT algorithm.

---

## Butterfly Factorization: From FFT to Finetuning  

### The butterfly structure in a nutshell  
For a power‑of‑two dimension \(d = 2^{N}\), a butterfly matrix is built from successive stages that each mix pairs of coordinates:

1. At stage 1 we apply many independent \(2\times 2\) orthogonal “butterfly factors”.
2. At stage 2 we pair up results from stage 1 into groups of size 4 and apply another set of \(2\times 2\) rotations (now acting on different index pairs).
3. Continue for \(\log_{2} d = N\) stages.

Mathematically, define a butterfly factor of size \(k = 2^{s}\):

\[
\mathbf{B}^{F}(k)=
\begin{bmatrix}
    \operatorname{diag}(\mathbf d_{1}) & \operatorname{diag}(\mathbf d_{2})\\[4pt]
    \operatorname{diag}(\mathbf d_{3}) & \operatorname{diag}(\mathbf d_{4})
\end{bmatrix},
\qquad
\mathbf d_{i}\in \mathbb R^{k/2}.
\]

Stacking these factors in a block‑diagonal fashion yields a *butterfly component*  
\[
\tilde{\mathbf B}(d,k)
   = \operatorname{diag}(
        \underbrace{\mathbf B^{F}(k),\,\dots,\,
        \mathbf B^{F}(k)}_{\!d/k~{\rm blocks}}
      ).
\]

A full butterfly matrix is then

|Stage|Component|
|-----|----------|
|\(k = d/2^{0}=d\)| $\tilde{\mathbf B}(d,d)$|
|\(k = d/2^{1}=d/2$)| $\tilde{\mathbf B}(d,d/2)$|
|⋮|⋮|
|\(k = 2$)| $\tilde{\mathbf B}(d,2)$|

Multiplying all components gives us

\[
\boxed{\;
    \mathbf R_{\text{butterfly}}
        = \prod_{i=1}^{N} \tilde{\mathbf B}(d,\, 2^{N-i+1})
    \;}
    .
\]

### Parameter count  
Each component $\tilde{\mathbf B}(d,k)$ contains exactly $d$ free entries (the diagonal vectors $\bm d_{i}$). Since there are $N=\log_2 d$ stages,

\[
|\text{trainable}| = d\,N = \mathcal O(d\,\log d).
\]

Contrast this with $\mathcal O(d^2)$ for a dense orthogonal matrix or $\mathcal O(bd)$ for block‑diagonal OFT; butterfly factorization offers an order‑of‑magnitude saving for large $d$.

### Enforcing orthogonality  
Each $2\times 2$ block can be parameterised by a rotation angle $\theta$ via the Cayley transform or simple sine/cosine values, guaranteeing that every component—and thus their product—is exactly orthogonal. This mirrors how OFT used Cayley transforms for block‑diagonal matrices; now we apply it at the much finer $2\times 2$ grain.

---

## Orthogonal Butterfly Finetuning (BOFT)

Putting the pieces together yields **BOFT**: replace OFT’s single orthogonal matrix with the butterfly product

```
z = ( R(m,b) · W⁰ )ᵀ x
where   R(m,b) = Π_{i=1}^{m} 𝔹̃^b_{(d,i)}
```

- `m` – number of butterfly stages (≤ log₂ d).  
- `b` – block size inside each stage; `b=2` gives the pure butterfly matrix described above; larger `b` reduces depth at the cost of slightly more parameters (`≈ ½(b−1)d m`).  

Special cases illustrate continuity with previous work:
- BOFT(1, b) ⇒ original block‑diagonal OFT (`m=1` means one component only).  
- BOFT(1, d) ⇒ full dense OFT (no sparsity).  
- BOFT(log₂(d/b), b) ⇒ dense orthogonal matrix with only $\mathcal O(d\,log d)$ parameters.

### Practical tricks  

*Identity initialization*: All components start as identity matrices (zero skew-symmetric inputs), ensuring zero deviation from the pretrained model initially.

*Multiplicative dropout*: To avoid overfitting, randomly replace a fraction of components—or even individual diagonal blocks inside them—with identities during training. This mirrors LoRA’s additive dropout but respects BOFT’s multiplicative nature.

---

## What Does BOFT Buy Us?  

### Expressivity vs. Parameter budget  
Empirically, approximating random dense orthogonal matrices shows that BOFT reaches lower approximation error than block‑diagonal OFT for any given parameter budget. For instance, BOFT(9, 2) outperforms BOFT(1, 16) while using far fewer trainable scalars.

A theoretical result confirms that stacking multiple butterfly matrices and their transposes can represent *any* orthogonal matrix when enough stages are used—so BOFT can be made fully expressive if needed.

### Spectral stability  
Because BOFT multiplies learnt orthogonal $\mathbf R$ on the left side only, singular values of $\mathbf W^0$ stay unchanged:

\[
\sigma_{\max}(\,\underbrace{\mathbf R\,}_{orthogonal}\,\underbrace{\mathbf W^0}_{U\,Σ\,V^\top})
   = \sigma_{\max}(\,\Sigma\,),
\]

preserving spectral norm and often leading to smoother training compared to low‑rank additive methods like LoRA.

### Implicit inductive bias  
Butterfly factorizations naturally emulate classic fast transforms (FFT, Hadamard, DCT). This structured bias steers learning toward transformations that are known to be “useful” for signal processing and vision tasks, helping generalisation without explicit regularisation.

### Real‑world performance  
When applied to diverse downstream tasks—vision transformer fine‑tuning on ImageNet, language model adaptation on GLUE benchmarks, and text‑to‑image diffusion control—the authors report consistent gains over LoRA and over block‑diagonal OFT despite using far fewer parameters per layer.

---

## Limitations & Future Directions  

- **Training overhead**: Multiplying several sparse matrices each iteration adds modest compute compared with a single dense orthogonal update. After finetuning, however, one can collapse all factors into a single matrix for zero inference cost.
- **Topology choice**: Butterfly graphs are not provably optimal for information transmission; other network topologies from computer networking could yield even lower parameter counts or better inductive biases.
- **Block size trade‑offs**: Larger blocks reduce depth but increase per‑stage parameters; finding the sweet spot may require task‐specific tuning.

---

## Takeaway  

Orthogonal finetuning promised stable, angle‑preserving updates but was hamstrung by an expensive full‐matrix parameterisation. By viewing an orthogonal transform as an information‑transmission problem and borrowing the elegant sparse connectivity of FFT’s butterfly graph, *BOFT* achieves dense orthogonal finetuning with only $\mathcal O(d\,log d)$ learnable parameters. This bridges the gap between expressivity and efficiency, offering practitioners a new tool for adapting ever larger foundation models without blowing up memory or compute budgets.

If you’re already using LoRA or block‑diagonal OFT for PEFT, give BOFT a try—especially on high‐dimensional layers where the $\log d$ savings become massive. The code and pretrained checkpoints are publicly available in the authors’ repository; happy finetuning!



# The Information Transmission View: Visualizing Sparse Orthogonal Matrix Factorizations  

## Introduction  

Finetuning massive foundation models (LLMs, vision transformers, diffusion nets) without retraining them from scratch is now a central research problem. Orthogonal Finetuning (OFT) addresses this by updating each linear layer with a **single orthogonal matrix** – a transformation that preserves pairwise angles between neurons and therefore retains much of the pretrained knowledge. The downside? A full \(d \times d\) orthogonal matrix needs \(\mathcal{O}(d^{2})\) trainable parameters, which quickly becomes prohibitive.

The recent *Parameter‑Efficient Orthogonal Finetuning via Factorization* paper proposes a clever remedy: instead of learning one dense orthogonal matrix, **compose** it from several **sparse** orthogonal factors. To reason about which sparsity patterns are admissible, the authors introduce an **information transmission view**. In this post we unpack that view, illustrate how multiplying sparse matrices can be interpreted as routing information across a grid‑shaped graph, and why this perspective naturally leads to the butterfly factorization that underpins the BOFT method.

---

## From a Dense Orthogonal Matrix to a Product of Sparse Ones  

Suppose we have a pretrained weight matrix \(\mathbf{W}^{0}\in\mathbb{R}^{d\times n}\). OFT replaces it with  
\[
\mathbf{W}= \mathbf{R}\,\mathbf{W}^{0},
\qquad \mathbf{R}\in\mathbb{R}^{d\times d},\; \mathbf{R}^{\top}\mathbf{R}= \mathbf{I}.
\]  
If we factorize \(\mathbf{R}\) as a product of \(m\) square matrices,
\[
\mathbf{R}= \mathbf{B}_{m}\,\mathbf{B}_{m-1}\cdots \mathbf{B}_{1},
\]  
each \(\mathbf{B}_{i}\) can be far sparser than a full matrix. The challenge is to pick sparsity patterns that (i) keep every \(\mathbf{B}_{i}\) orthogonal and (ii) guarantee that the final product \(\mathbf{R}\) is **dense**, i.e. every output neuron can depend on every input neuron.

### A Grid‑Shaped Information Flow Graph  

Imagine a grid with \(d\) rows (one for each neuron dimension) and \(m+1\) columns (one for each “layer” of the factorization plus the input). Each column represents a set of nodes; column 0 holds the input vector components, column \(m\) holds the final transformed components, and columns 1…\(m-1\) are intermediate stages.

For each factor \(\mathbf{B}_{i}\), place directed edges from column \(i-1\) to column \(i\). An entry \((j,k)\) in \(\mathbf{B}_{i}\) being non‑zero means there is an edge from node \(k\) in column \(i-1\) to node \(j\) in column \(i\). Multiplying the factors sequentially corresponds exactly to **propagating information** along these directed edges:

```
column 0  →  column 1  → … →  column m
   x          B1          B2            R
```

If after all \(m\) steps every node in column 0 can reach every node in column \(m\), then the overall matrix \(\mathbf{R}\) will have no zero entries — it is dense. Conversely, any missing path creates a zero in \(\mathbf{R}\).

Thus, designing a sparse factorization reduces to **designing a set of edges** on this grid that satisfies two constraints:

1. **Dense connectivity**: each source node (column 0) must have at least one directed path to each sink node (column \(m\)).  
2. **Orthogonality budget**: each intermediate adjacency matrix \(\mathbf{B}_{i}\) must be orthogonal, which forces each column (and each row) to contain exactly one non‑zero entry of magnitude \(±1\) when we restrict ourselves to binary sparsity patterns. In practice we use learnable parameters within those non‑zero slots while preserving the orthogonal structure (e.g., via Cayley transforms).

Because an orthogonal matrix of size \(d\times d\) must be full‑rank, any feasible adjacency matrix needs at least \(d\) edges between consecutive columns. Those edges are *free* in terms of trainable parameters – they correspond to fixed magnitude entries (\(±1\)). The remaining trainable parameters are exactly the values we assign to the non‑zero slots in each factor.

### Why This Graph Helps Design Efficient Factorizations  

The graph viewpoint makes two otherwise opaque design questions crystal clear:

| Question | Naïve answer | Insight from the graph |
|----------|--------------|------------------------|
| How many edges are necessary? | Possibly \(d^{2}\) if we used a single dense factor. | Each layer needs at least \(d\) edges for orthogonality; additional edges are only required to ensure *reachability* across layers. |
| Which sparsity pattern yields the fewest extra edges? | Random sparsity may still require many extra edges. | Certain topologies—most notably **butterfly graphs**—provide dense connectivity with only \(\mathcal{O}(d\log d)\) extra edges. |

In other words, once we view factorization as routing information through a network, we can borrow results from computer networking and parallel algorithms that study precisely how to connect many sources to many destinations efficiently.

---

## The Butterfly Graph: An Optimal Routing Skeleton  

The classic Cooley–Tukey Fast Fourier Transform (FFT) algorithm repeatedly splits and recombines data using *butterfly* stages. The induced communication pattern is a **butterfly graph**, characterized by:

* Each stage connects every pair of nodes that differ in one binary digit.
* With \(\log_{2} d\) stages, any source can reach any sink.
* The total number of edges is \(d\,\log_{2} d\), i.e. linearithmic in dimension.

Translating this into our factorization language, each stage corresponds to one sparse orthogonal matrix \(\tilde{\mathbf{B}}(d,2^{k})\). Because every stage is built from \(2\times2\) rotation blocks arranged in a specific permutation pattern, each stage remains orthogonal while using only \(d/2\) learnable parameters (the rotation angles). Stacking \(\log_{2} d\) such stages yields a dense orthogonal matrix whose total trainable parameters scale as
\[
\underbrace{\frac{b-1}{2} d}_{\text{per stage}} \times \underbrace{\log_{2} d}_{\text{stages}} = \mathcal{O}(d\,\log d).
\]

Thus, **the butterfly structure exactly satisfies our two desiderata**:
1. The induced graph is densely connected (every source reaches every sink).
2. The number of *free* edges needed for orthogonality is minimal; all additional edges come from the butterfly wiring, giving an overall parameter count far below \(d^{2}\).

---

## From Theory to Practice: Orthogonal Butterfly Finetuning (BOFT)

Armed with the butterfly factorization, BOFT defines the finetuning transform as  
\[
\mathbf{R}(m,b)= \prod_{i=1}^{m} \tilde{\mathbf{B}}^{\,b}_{(d,i)},
\]  
where:
* \(b\) controls block size (larger blocks reduce depth but increase per‑stage parameters),
* \(m=\log_{2}(d/b)\) when using pure butterfly stages,
* Each component \(\tilde{\mathbf{B}}^{\,b}_{(d,i)}\) is an orthogonal block‑butterfly matrix parameterized via Cayley transforms or direct 2‑D rotations.

Special cases recover known methods:
* **OFT with a full orthogonal matrix** → BOFT with one stage of size \(b=d\).
* **Block‑diagonal OFT** → BOFT with one stage and block size \(b<d\).
* **Butterfly‑only BOFT** → multiple stages with minimal block size (\(b=2\)).

Because all stages are initialized to identity matrices, BOFT starts exactly at the pretrained model and only deviates as training proceeds—mirroring standard finetuning practice.

---

## Why Visualizing Helps Future Designs  

The information transmission graph does more than justify butterflies; it offers a **design toolbox**:

1. **Alternative topologies** – One could replace butterfly stages with other network motifs studied in interconnection networks (e.g., hypercube or de Bruijn graphs). Each would give different trade‑offs between depth and edge count.
2. **Hybrid factorizations** – Mixing dense blocks for some layers and butterfly stages for others may allocate parameters where they matter most.
3. **Adaptive depth** – For layers where fewer parameters suffice, stop after fewer butterfly stages; for sensitive layers increase depth.

All these ideas stem from asking “what edge pattern guarantees connectivity?” rather than “how many parameters do I need?”

---

## Conclusions  

The paper’s *information transmission view* reframes sparse orthogonal matrix factorization as a routing problem on a layered graph. By demanding dense reachability while respecting orthogonality’s edge budget, the view singles out butterfly graphs as an almost optimal solution: they achieve full connectivity with only \(\mathcal{O}(d\,\log d)\) trainable entries. This insight leads directly to *Orthogonal Butterfly Finetuning* (BOFT), a versatile and highly parameter‑efficient alternative to standard OFT and low‑rank PEFT methods.

Beyond BOFT itself, visualizing factorizations as information flow opens a fertile cross‑disciplinary space where ideas from signal processing, parallel computing, and network topology can inform next‑generation finetuning schemes—potentially unlocking even tighter parameter budgets without sacrificing expressivity or stability.

---



# BOFT in Action: Adapting Vision Transformers, Language Models, and Diffusion Models  

In the past few years, “parameter‑efficient fine‑tuning” (PEFT) has become the go‑to recipe for squeezing new tasks out of massive foundation models.  Methods such as LoRA, adapters, and prompt tuning all share a simple idea: keep the bulk of the pretrained weights frozen and only learn a small set of extra parameters.  A newer contender—**Orthogonal Finetuning (OFT)**—takes a more principled route by preserving the pairwise angles between neurons through a learned orthogonal transformation.  While OFT enjoys strong generalization, its naïve implementation requires a dense \(d \times d\) orthogonal matrix per layer, which brings an \(\mathcal{O}(d^{2})\) parameter budget.

Enter **Orthogonal Butterfly (BOFT)**.  By factorizing a dense orthogonal matrix into a product of sparse orthogonal “butterfly” matrices, BOFT reduces the trainable count to \(\mathcal{O}(d\log d)\) while still being able to represent dense transformations.  The paper *Parameter‑Efficient Orthogonal Finetuning via Factorization* not only introduces the method but also validates it across three major model families: Vision Transformers (ViTs), Large Language Models (LLMs), and Text‑to‑Image diffusion models.  Below we walk through the key empirical takeaways and why BOFT consistently beats LoRA, adapters, and the original OFT despite using far fewer parameters.

---

## 1. A Quick Recap of BOFT’s Mechanics  

- **Orthogonal transformation**: For a frozen weight matrix \(\mathbf{W}^{0}\in\mathbb{R}^{d\times n}\) we replace the forward pass  
  \[
  \mathbf{z}= (\mathbf{W}^{0})^{\top}\mathbf{x}
  \quad\Longrightarrow\quad
  \mathbf{z}= (\mathbf{R}\mathbf{W}^{0})^{\top}\mathbf{x},
  \]  
  where \(\mathbf{R}\) is orthogonal (\(\mathbf{R}^{\top}\mathbf{R}= \mathbf{I}\)).  

- **Butterfly factorization**: Instead of learning a full \(\mathbf{R}\), BOFT writes  
  \[
  \mathbf{R}= \underbrace{\tilde{\mathbf{B}}_{(d,1)}\tilde{\mathbf{B}}_{(d,2)}\dots\tilde{\mathbf{B}}_{(d,m)}}_{\text{$m$ butterfly components}},
  \]  
  each \(\tilde{\mathbf{B}}_{(d,i)}\) being a block‑diagonal matrix whose blocks are tiny orthogonal factors (often just \(2\times2\) rotations).  
- **Parameter count**: With block size \(b\) and depth \(m\), BOFT needs roughly \(\frac12(b-1)d\,m\) trainable scalars. Setting \(b=2,\; m=\log_{2}d\) yields the celebrated \(\mathcal{O}(d\log d)\) budget.

Because every butterfly component is initialized as identity (via Cayley’s skew‑symmetric parameterization), BOFT starts from exactly the pretrained model—a crucial ingredient for stable fine‑tuning.

## 5 Why BOFT Wins Across Domains  

1️⃣ **Dense yet Structured Orthogonality** – The product of butterfly matrices yields a dense transformation but lives in a much smaller subspace of the orthogonal group, offering a sweet spot between expressivity and regularisation.

2️⃣ **Spectral Norm Preservation** – Multiplying by an orthogonal matrix leaves singular values untouched; gradients remain well‑scaled and training stays stable even with larger learning rates.

3️⃣ **Implicit Inductive Bias** – Butterfly factorization naturally encodes fast linear transforms that have proven useful in signal processing and computer vision; this bias helps generalise from limited downstream data.

4️⃣ **Zero Inference Overhead** – After training we can collapse all butterfly components into a single matrix and fold it into the frozen weight; during inference nothing extra is computed.

5️⃣ **Unified Hyperparameters** – Unlike LoRA where rank must be tuned per layer, BOFT only needs two global knobs—depth \(m\) and block size \(b\)—making it easier to scale from tiny vision models to massive LLMs.

## 6 Practical Tips for Using BOFT  

- **Choosing \(b\) and \(m\)**: For dimensions that are powers of two, set \(b=2\) and let \(m=\log_{2} d\); this gives the minimal parameter count (\(\approx d\log d/2\)). If you prefer fewer multiplication steps at the cost of slightly more params, increase \(b\) to 4 or 8.
- **Initialization**: Use Cayley’s transform with zero skew-symmetric matrix so each butterfly component starts as identity; this guarantees zero change at epoch 0.
- **Dropout**: Apply *multiplicative dropout*—randomly replace whole butterfly components or their internal \(2b\times2b\) blocks with identity matrices during training—to guard against overfitting on tiny datasets.
- **Learning Rate Schedule**: Because orthogonal updates preserve norm, you can often use a learning rate twice as large as you would with LoRA without destabilising training.
- **Post‑training Compression**: After fine‑tuning, multiply all butterfly components together once and store the resulting \(\mathbf{R}\); this eliminates any runtime penalty.

BOFT demonstrates that *principled* parameter efficiency—rooted in information transmission theory and classic butterfly networks—can rival or exceed ad hoc PEFT tricks across disparate modalities:

- Vision Transformers see near–full fine‑tune accuracy with just a few percent extra parameters.
- Large language models retain most of their zero-shot competence while dramatically shrinking storage footprints.
- Diffusion models acquire new styles or concepts without bloating the UNet.

The method’s elegance lies in turning a seemingly impossible goal—learning a dense orthogonal matrix with few parameters—into a tractable factorisation problem inspired by FFT algorithms. As foundation models continue to scale, such structured PEFT approaches will likely become indispensable tools in every practitioner’s toolbox.

# The Maths Behind BOFT: Expressivity, Spectral Guarantees, and Inductive Bias  

## Introduction  

Fine‑tuning massive foundation models without blowing up the parameter budget is a hot topic.  Orthogonal Fine‑tuning (OFT) ​\[[qiu2023controlling]\] took a principled step by **multiplying a learnable orthogonal matrix** onto each frozen linear layer, thereby preserving the pair‑wise angles between neurons.  The downside?  A dense orthogonal matrix costs $\mathcal{O}(d^{2})$ trainable values for a $d$‑dimensional layer, which quickly becomes prohibitive.  

Enter **Orthogonal Butterfly Fine‑tuning (BOFT)**.  By factorising the orthogonal matrix into a product of *butterfly*‑structured sparse orthogonal factors, BOFT reduces the trainable count to $\mathcal{O}(d\log d)$ while still being able to generate dense transformations.  This post walks through the key theoretical insights that make BOFT work:  

1. **Expressivity** – why a butterfly factorisation is strictly more powerful than the block‑diagonal OFT used previously.  
2. **Spectral guarantees** – how orthogonal updates preserve singular values and why that matters for stability.  
3. **Metric‑learning view** – interpreting the orthogonal matrix as a bilinear similarity transform.  
4. **Inductive bias from butterfly topology** – how the sparsity pattern encodes useful priors that improve generalisation.

All of the results below are grounded in the BOFT paper; no extra assumptions are introduced.

---

## 1. Expressivity: From Block‑Diagonal to Butterfly  

### What “expressivity’’ means here  

For a $d\times d$ orthogonal matrix $\mathbf{R}$ we ask: *Can a given parameterisation represent every orthogonal matrix (the full $\mathcal{O}(d^{2})$ degrees of freedom), or at least a useful subset?*  In OFT the orthogonal matrix is forced to be block‑diagonal:

\[
\mathbf{R}_{\text{OFT}} = \operatorname{diag}\bigl(\mathbf{R}_{1},\dots,\mathbf{R}_{r}\bigr), \qquad \mathbf{R}_{i}\in\mathbb{R}^{b\times b},\; br=d .
\]

Each block $\mathbf{R}_i$ can be any $b\times b$ orthogonal matrix, but there is **no interaction across blocks**.  Consequently, any transformation that mixes dimensions belonging to different blocks cannot be expressed.

### Butterfly factorisation  

A *butterfly factor* of size $k$ (with $k$ even) is

\[
\mathbf{B}^{F}(k)=
\begin{bmatrix}
\operatorname{diag}(\mathbf{d}_{1}) & \operatorname{diag}(\mathbf{d}_{2})\\
\operatorname{diag}(\mathbf{d}_{3}) & \operatorname{diag}(\mathbf{d}_{4})
\end{bmatrix},
\qquad \mathbf{d}_{i}\in\mathbb{R}^{k/2}.
\]

By stacking $\log_{2} d$ such factors with appropriately chosen block sizes we obtain the *butterfly matrix*  

\[
\mathbf{R}_{\text{BOFT}}(m,b)=\prod_{i=1}^{m}\tilde{\mathbf B}^{b}_{(d,i)},
\]

where each $\tilde{\mathbf B}^{b}_{(d,i)}$ is a block‑diagonal matrix whose blocks are butterfly factors of size $2^{i}$ (or their $b\times b$ extensions).  
If we choose $m=\log_{2} d$ and $b=2$, the product yields a *dense* orthogonal matrix while using only $\mathcal O(d\log d)$ free parameters (each $2\times 2$ block contributes one rotation angle).

### Why BOFT is strictly more expressive  

**Theorem (Expressivity of BOFT).**  
*For any block size $b$, BOFT can represent all matrices that block‑diagonal OFT can, and additionally many matrices that mix dimensions across blocks.*  

*Sketch of proof.*  
- Any block‑diagonal OFT matrix can be recovered by setting all butterfly components except the first one to identity; the first component then collapses to a block‑diagonal matrix with exactly the same blocks as OFT.  
- Conversely, butterfly components introduce *permutations* between dimensions at each level (the classic “swap’’ pattern of FFT butterflies). After $\log_2 d$ levels every source dimension has been routed to every target dimension via at least one path in the induced graph. Hence the resulting product can have non‑zero entries in positions that are forced to zero in any block‑diagonal structure.

Empirically (Figure 3 in the paper) BOFT with modest depth ($m=6$, $b=4$) achieves far lower approximation error when trying to reconstruct a random dense orthogonal matrix than OFT with far more parameters.

### A hierarchy that captures the whole orthogonal group  

If we interleave *forward* and *transpose* butterfly products as  

\[
\mathbf R^{G}= \mathbf B_{d-1,1}\,\mathbf B_{d-1,2}^{\!\top}\,\dots\, \mathbf B_{1,1}\,\mathbf B_{1,2}^{\!\top},
\]

the resulting composition spans the full orthogonal group (the “kaleidoscope hierarchy’’).  In practice we stop far earlier because full expressivity is unnecessary—and often harmful—for fine‑tuning.

---

## 2. Spectral Norm Preservation  

### Orthogonal updates keep singular values intact  

Let $\mathbf W^{0}= \mathbf U\,\boldsymbol{\Sigma}\,\mathbf V^{\!\top}$ be the SVD of a pretrained linear layer.  OFT and BOFT replace it by

\[
\widetilde{\mathbf W}= \mathbf R\,\mathbf W^{0}
   = \bigl(\mathbf R\,\mathbf U\bigr)\,\boldsymbol{\Sigma}\,\mathbf V^{\!\top}.
\]

Since $\mathbf R$ and $\mathbf U$ are both orthogonal, their product is again orthogonal, leaving $\boldsymbol{\Sigma}$ untouched. Consequently

\[
\sigma_{\max}(\widetilde{\mathbf W}) = \sigma_{\max}(\mathbf W^{0}),
\]

i.e., **the spectral norm is exactly preserved** regardless of how we optimise $\mathbf R$.  

### Why this matters  

- **Training stability:** Gradient explosion/vanishing often correlates with large spectral norms; keeping them fixed avoids sudden spikes during optimisation.  
- **Generalisation:** Recent work on spectral regularisation shows that bounding the spectral norm improves out‑of‑distribution robustness; here we get an exact bound for free.  
- **Compatibility with downstream tasks:** Many downstream heads (e.g., classification layers) assume the magnitude of features stays within a known range; orthogonal finetuning respects that assumption.

In contrast, additive low‑rank methods such as LoRA can increase or decrease singular values depending on the learned low‑rank matrices, requiring explicit regularisation.

---

## 3. Orthogonal Finetuning as Bilinear Metric Learning  

The forward pass after BOFT on an input vector $\mathbf x$ reads

\[
z_i = \bigl(\mathbf w_i^{0}\bigr)^{\!\top}\,\mathbf R\,\mathbf x,
\]

where $\mathbf w_i^{0}$ denotes column $i$ of $\mathbf W^{0}$. This is precisely a **bilinear similarity** between a learned query $\mathbf w_i^{0}$ and an input transformed by $\mathbf R$.  

### Connection to metric learning  

If we view $\mathbf R$ as a learnable linear map defining a Mahalanobis distance

\[
d_{\mathbf R}(\phi,\psi)^2 = (\phi-\psi)^{\!\top}\,\bigl(\mathbf R^{\!\top}\!\! \mathbf R\bigr)\,(\phi-\psi),
\]

orthogonality forces $\mathbf R^{\!\top}\!\! \mathbf R = \mathbf I$, so distances are measured in an *isotropic* space but with an additional rotation/reflection applied to one side only. In other words, BOFT learns *which linear combinations of pretrained features are most useful* while preserving their geometry—exactly what metric learning seeks to do without altering overall scale.

This viewpoint helps explain why BOFT often enjoys better transfer performance than pure additive updates: it re‑weights relationships between features rather than injecting new directions that may overfit.

---

## 4. Inductive Bias from Butterfly Structure  

### Structured sparsity ≈ prior knowledge  

The butterfly topology originates from fast Fourier transforms: each factor exchanges information between two halves of the vector while keeping intra‑half connections local. This design embodies two desirable properties for fine‑tuning:

| Property | What butterfly gives | Why it helps |
|----------|----------------------|--------------|
| **Dense connectivity with few edges** | $\mathcal O(d \log d)$ non‑zero entries suffice to reach every output from every input | Guarantees expressivity without blowing up parameters |
| **Recoverability of classic transforms** | By fixing specific diagonal values we obtain DFT, Hadamard, DCT etc. | Implicitly encourages transforms that have proven utility in signal processing and vision |
| **Permutation invariance across layers** | Each factor can be seen as a permutation followed by local rotations | Encourages smooth mixing of information rather than abrupt blockwise jumps |

Because these patterns are hardcoded into the parameterisation, training cannot stray into “wild’’ parts of the orthogonal group that would overfit small downstream datasets.

### Empirical signs of better generalisation  

In image classification (ViT finetuning) and language modelling (LLM instruction tuning) experiments from the paper, BOFT consistently outperforms LoRA and block‑diagonal OFT under identical parameter budgets. The authors attribute this gain largely to the *inductive bias* introduced by butterflies: they act like a built‑in regulariser that keeps updates close to well‑behaved linear transforms while still allowing enough flexibility to adapt.

---

## 5. Putting It All Together  

BOFT’s mathematical foundations explain its empirical success:

1. **Expressivity** – The layered butterfly product creates dense orthogonal matrices with only $\mathcal O(d \log d)$ free parameters, strictly superseding block‑diagonal OFT.
2. **Spectral preservation** – Multiplying by an orthogonal matrix leaves all singular values unchanged, yielding stable training dynamics.
3. **Metric learning interpretation** – The model learns a bilinear similarity under an isotropic metric, reusing pretrained feature geometry.
4. **Inductive bias** – Butterfly sparsity encodes useful signal-processing priors, guiding optimisation toward transformations that generalise well.

In practice this means you can take a giant foundation model—say GPT‑4 or Stable Diffusion—freeze most weights, learn only a few megabytes of butterfly parameters per layer, and still achieve state‑of‑the‑art downstream performance without extra inference latency.

---

## Takeaway Checklist for Practitioners  

- When parameter budget is tight but you need strong transfer ability → consider **BOFT** instead of LoRA or vanilla OFT.  
- Choose depth $m=\log_2(d/b)$ and small block size $b$ (e.g., $b=2$ or $4$) for maximal compression; larger $b$ reduces depth but increases parameters linearly.  
- Initialise all butterfly components as identity (Cayley transform with zero skew‐symmetric part) for zero deviation at start.  
- If overfitting remains a concern, apply **multiplicative dropout**: randomly replace whole butterfly components or individual $2b\times 2b$ blocks by identity during training.

BOFT demonstrates how marrying classic algorithmic ideas (the FFT butterfly) with modern deep learning theory yields both *theoretically elegant* and *practically powerful* fine‑tuning tools. As model sizes keep growing, such parameter-efficient strategies will become indispensable for researchers and engineers alike.

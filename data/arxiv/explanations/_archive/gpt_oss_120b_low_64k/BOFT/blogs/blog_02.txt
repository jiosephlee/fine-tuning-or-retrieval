\title{Blogs about the Paper: "Parameter-Efficient Orthogonal Finetuning via Factorization"}

# From Block‑Diagonal to Butterfly: Making Orthogonal Finetuning Parameter‑Efficient  

## Introduction  

Large foundation models—think GPT‑3, Stable Diffusion, or modern vision transformers—have become the workhorses of AI research. Training them from scratch is a multi‑million‑dollar endeavour, so most practitioners spend their time **adapting** a pretrained model to a downstream task. Among the many adaptation strategies (adapter layers, prompt tuning, low‑rank updates), **model finetuning** remains the simplest: we keep the original architecture and only adjust a subset of its weights.  

A recent finetuning paradigm called **Orthogonal Finetuning (OFT)** takes a principled approach: instead of adding or subtracting small changes, it multiplies each layer’s weight matrix by an *orthogonal* matrix \(\mathbf{R}\). Because orthogonal transformations preserve pair‑wise angles between neurons, the pretrained knowledge is largely retained, leading to better stability and generalisation compared with classic methods such as LoRA.  

The drawback? A full \(d \times d\) orthogonal matrix needs \(\mathcal{O}(d^{2})\) trainable parameters—far too many for parameter‑efficient finetuning (PEFT). The original OFT paper mitigated this by forcing a **block‑diagonal** structure on \(\mathbf{R}\), which reduces parameters but also imposes harsh sparsity patterns and limits expressivity.  

In this post we unpack why block‑diagonal OFT falls short and how the authors of *Parameter‑Efficient Orthogonal Finetuning via Factorization* replace it with a **butterfly factorization**—the same sparse pattern that powers the Fast Fourier Transform (FFT). The result is a dense orthogonal transformation that can be learned with only \(\mathcal{O}(d\log d)\) parameters, a huge win for large models.

---

## Why Block‑Diagonal OFT Is Not Enough  

### The original OFT formulation  
Given a pretrained linear layer \(\mathbf{W}^{0}\in\mathbb{R}^{d\times n}\), OFT replaces the forward pass  

\[
\mathbf{z}=({\mathbf{W}^{0}})^{\!\top}\mathbf{x}
\]

with  

\[
\mathbf{z}=({\mathbf{R}\mathbf{W}^{0}})^{\!\top}\mathbf{x},
\qquad \mathbf{R}\in\mathbb{R}^{d\times d},\;\;\mathbf{R}^{\!\top}\mathbf{R}=\mathbf{I}.
\]

The orthogonal matrix \(\mathbf{R}\) is learned while \(\mathbf{W}^{0}\) stays frozen. Orthogonality guarantees that the singular values of \(\mathbf{W}^{0}\) (and thus its spectral norm) stay unchanged—a property linked to training stability.

### Block‑diagonal compromise  
A naïve dense orthogonal matrix would need \(d^{2}\) free entries. To cut costs, the authors of OFT introduced a block‑diagonal constraint:

\[
\mathbf{R}= \operatorname{diag}(\mathbf{R}_{1},\,\mathbf{R}_{2},\,\dots,\mathbf{R}_{r}),
\qquad
\mathbf{R}_{i}\in\mathbb{R}^{b\times b},
\; br = d .
\]

Each small block \(\mathbf{R}_{i}\) is orthogonal, so the total number of learnable parameters scales like \(rb^{2}=bd = \mathcal{O}(bd)\). When \(b \ll d\), the reduction is substantial.

**What we lose:**  
1. **Dense connectivity** – neurons in different blocks never interact because the off‑diagonal blocks are forced to zero.  
2. **Expressivity** – many classic linear transforms (Fourier, Hadamard, etc.) cannot be expressed as a block‑diagonal matrix.  
3. **Inductive bias uncertainty** – the choice of block size and alignment with neuron indices is arbitrary; there is no principled way to decide which sparsity pattern best suits a downstream task.

Thus we need a way to keep \(\mathbf{R}\) dense in effect while still using far fewer parameters than \(d^{2}\).

---

## Information Transmission: Re‑thinking Orthogonal Matrices  

The authors recast the problem as an **information‑transmission graph**. Imagine a grid with \(d\) nodes at each of \(m+1\) layers (one layer per factor matrix). If we factorize \(\mathbf{R}\) as  

\[
\mathbf{R}= \mathbf{B}_{m} \mathbf{B}_{m-1}\dots \mathbf{B}_{1},
\]

each sparse factor \(\mathbf{B}_{i}\) defines directed edges from layer \(i-1\) to layer \(i\). The product is dense iff **every source node can reach every sink node** after traversing all layers.  

Two desiderata emerge:

| Desideratum | Meaning |
|-------------|---------|
| **Dense connectivity** | For any pair of source–sink nodes there exists at least one path through the graph. |
| **Minimum free edges** | Use as few trainable (non‑fixed) edges as possible while preserving orthogonality. |

A naïve dense factor (\(m=1,\;\mathbf{B}_{1}=\) dense orthogonal) satisfies connectivity but incurs \(\mathcal{O}(d^{2})\) parameters. A clever topology can achieve dense connectivity with far fewer edges.

Enter the **butterfly graph**, famous from the Cooley–Tukey FFT algorithm.

---

## Butterfly Factorization: From FFT to Finetuning  

### The butterfly structure in a nutshell  
For a power‑of‑two dimension \(d = 2^{N}\), a butterfly matrix is built from successive stages that each mix pairs of coordinates:

1. At stage 1 we apply many independent \(2\times 2\) orthogonal “butterfly factors”.
2. At stage 2 we pair up results from stage 1 into groups of size 4 and apply another set of \(2\times 2\) rotations (now acting on different index pairs).
3. Continue for \(\log_{2} d = N\) stages.

Mathematically, define a butterfly factor of size \(k = 2^{s}\):

\[
\mathbf{B}^{F}(k)=
\begin{bmatrix}
    \operatorname{diag}(\mathbf d_{1}) & \operatorname{diag}(\mathbf d_{2})\\[4pt]
    \operatorname{diag}(\mathbf d_{3}) & \operatorname{diag}(\mathbf d_{4})
\end{bmatrix},
\qquad
\mathbf d_{i}\in \mathbb R^{k/2}.
\]

Stacking these factors in a block‑diagonal fashion yields a *butterfly component*  
\[
\tilde{\mathbf B}(d,k)
   = \operatorname{diag}(
        \underbrace{\mathbf B^{F}(k),\,\dots,\,
        \mathbf B^{F}(k)}_{\!d/k~{\rm blocks}}
      ).
\]

A full butterfly matrix is then

|Stage|Component|
|-----|----------|
|\(k = d/2^{0}=d\)| $\tilde{\mathbf B}(d,d)$|
|\(k = d/2^{1}=d/2$)| $\tilde{\mathbf B}(d,d/2)$|
|⋮|⋮|
|\(k = 2$)| $\tilde{\mathbf B}(d,2)$|

Multiplying all components gives us

\[
\boxed{\;
    \mathbf R_{\text{butterfly}}
        = \prod_{i=1}^{N} \tilde{\mathbf B}(d,\, 2^{N-i+1})
    \;}
    .
\]

### Parameter count  
Each component $\tilde{\mathbf B}(d,k)$ contains exactly $d$ free entries (the diagonal vectors $\bm d_{i}$). Since there are $N=\log_2 d$ stages,

\[
|\text{trainable}| = d\,N = \mathcal O(d\,\log d).
\]

Contrast this with $\mathcal O(d^2)$ for a dense orthogonal matrix or $\mathcal O(bd)$ for block‑diagonal OFT; butterfly factorization offers an order‑of‑magnitude saving for large $d$.

### Enforcing orthogonality  
Each $2\times 2$ block can be parameterised by a rotation angle $\theta$ via the Cayley transform or simple sine/cosine values, guaranteeing that every component—and thus their product—is exactly orthogonal. This mirrors how OFT used Cayley transforms for block‑diagonal matrices; now we apply it at the much finer $2\times 2$ grain.

---

## Orthogonal Butterfly Finetuning (BOFT)

Putting the pieces together yields **BOFT**: replace OFT’s single orthogonal matrix with the butterfly product

```
z = ( R(m,b) · W⁰ )ᵀ x
where   R(m,b) = Π_{i=1}^{m} 𝔹̃^b_{(d,i)}
```

- `m` – number of butterfly stages (≤ log₂ d).  
- `b` – block size inside each stage; `b=2` gives the pure butterfly matrix described above; larger `b` reduces depth at the cost of slightly more parameters (`≈ ½(b−1)d m`).  

Special cases illustrate continuity with previous work:
- BOFT(1, b) ⇒ original block‑diagonal OFT (`m=1` means one component only).  
- BOFT(1, d) ⇒ full dense OFT (no sparsity).  
- BOFT(log₂(d/b), b) ⇒ dense orthogonal matrix with only $\mathcal O(d\,log d)$ parameters.

### Practical tricks  

*Identity initialization*: All components start as identity matrices (zero skew-symmetric inputs), ensuring zero deviation from the pretrained model initially.

*Multiplicative dropout*: To avoid overfitting, randomly replace a fraction of components—or even individual diagonal blocks inside them—with identities during training. This mirrors LoRA’s additive dropout but respects BOFT’s multiplicative nature.

---

## What Does BOFT Buy Us?  

### Expressivity vs. Parameter budget  
Empirically, approximating random dense orthogonal matrices shows that BOFT reaches lower approximation error than block‑diagonal OFT for any given parameter budget. For instance, BOFT(9, 2) outperforms BOFT(1, 16) while using far fewer trainable scalars.

A theoretical result confirms that stacking multiple butterfly matrices and their transposes can represent *any* orthogonal matrix when enough stages are used—so BOFT can be made fully expressive if needed.

### Spectral stability  
Because BOFT multiplies learnt orthogonal $\mathbf R$ on the left side only, singular values of $\mathbf W^0$ stay unchanged:

\[
\sigma_{\max}(\,\underbrace{\mathbf R\,}_{orthogonal}\,\underbrace{\mathbf W^0}_{U\,Σ\,V^\top})
   = \sigma_{\max}(\,\Sigma\,),
\]

preserving spectral norm and often leading to smoother training compared to low‑rank additive methods like LoRA.

### Implicit inductive bias  
Butterfly factorizations naturally emulate classic fast transforms (FFT, Hadamard, DCT). This structured bias steers learning toward transformations that are known to be “useful” for signal processing and vision tasks, helping generalisation without explicit regularisation.

### Real‑world performance  
When applied to diverse downstream tasks—vision transformer fine‑tuning on ImageNet, language model adaptation on GLUE benchmarks, and text‑to‑image diffusion control—the authors report consistent gains over LoRA and over block‑diagonal OFT despite using far fewer parameters per layer.

---

## Limitations & Future Directions  

- **Training overhead**: Multiplying several sparse matrices each iteration adds modest compute compared with a single dense orthogonal update. After finetuning, however, one can collapse all factors into a single matrix for zero inference cost.
- **Topology choice**: Butterfly graphs are not provably optimal for information transmission; other network topologies from computer networking could yield even lower parameter counts or better inductive biases.
- **Block size trade‑offs**: Larger blocks reduce depth but increase per‑stage parameters; finding the sweet spot may require task‐specific tuning.

---

## Takeaway  

Orthogonal finetuning promised stable, angle‑preserving updates but was hamstrung by an expensive full‐matrix parameterisation. By viewing an orthogonal transform as an information‑transmission problem and borrowing the elegant sparse connectivity of FFT’s butterfly graph, *BOFT* achieves dense orthogonal finetuning with only $\mathcal O(d\,log d)$ learnable parameters. This bridges the gap between expressivity and efficiency, offering practitioners a new tool for adapting ever larger foundation models without blowing up memory or compute budgets.

If you’re already using LoRA or block‑diagonal OFT for PEFT, give BOFT a try—especially on high‐dimensional layers where the $\log d$ savings become massive. The code and pretrained checkpoints are publicly available in the authors’ repository; happy finetuning!

# Quantization Tricks Explained: The AbsMean Function Behind Ternary Weights  

## Introduction  

Quantizing large language models (LLMs) from 16‑bit floating‑point to a handful of bits can slash memory, latency, and energy consumption. The latest “1‑bit era” papers show that you can even push a Transformer down to **1.58 bits per parameter** by forcing every weight to one of three values: {-1, 0, +1}.  

The magic ingredient that makes this possible is the **absmean quantization function** (often abbreviated as **AbsMean**). In this post we unpack how AbsMean works, walk through a minimal Python implementation, and explain why the extra “0” in the ternary set gives the model an unexpected boost in capacity and feature‑filtering ability.

## From Full‑Precision to Ternary: What We Want  

A standard transformer layer stores its linear projections as dense FP16 (or BF16) matrices **W** ∈ ℝⁿˣᵐ. During inference these matrices dominate both compute and memory traffic because every forward pass performs a huge matrix multiplication:

\[
Y = XW^\top,
\]

where X are the activations.  

If we could replace **W** with a ternary matrix \(\widetilde{W}\) whose entries belong to \{-1, 0, +1\}, the multiplication would collapse to integer additions only—no floating‑point multiplies at all. The cost reduction is dramatic:

* **Memory:** each weight needs only ≈ 1.58 bits instead of 16.
* **Compute:** INT8 addition costs are orders of magnitude lower than FP16 multiply‑add.
* **Energy:** on modern silicon, addition consumes ~10× less energy than multiplication.

The challenge is to convert a full‑precision weight tensor to a ternary one *without* destroying model performance. That’s where AbsMean steps in.

## The AbsMean Quantization Pipeline  

### 1. Compute the Absolute Mean (γ)

First we estimate a global scaling factor that captures the typical magnitude of the weight matrix:

\[
\gamma = \frac{1}{nm}\sum_{i=1}^{n}\sum_{j=1}^{m} |W_{ij}|.
\]

Intuitively, γ is the average absolute value of all entries in **W**. By dividing each weight by γ we bring most values into a roughly \([-1, 1]\) range while preserving relative differences.

### 2. Scale and Clip  

We then scale each element:

\[
\hat{W}_{ij} = \frac{W_{ij}}{\gamma + \epsilon},
\]

where \(\epsilon\) is a tiny constant (e.g., \(10^{-8}\)) to avoid division by zero. After scaling we *clip* the result to the interval \([-1,\,1]\) before rounding:

\[
\tilde{W}_{ij} = \operatorname{RoundClip}(\hat{W}_{ij}, -1, 1).
\]

The `RoundClip` operation first rounds to the nearest integer and then forces the result into \([-1, 1]\):

\[
\operatorname{RoundClip}(x,a,b)=\max(a,\min(b,\operatorname{round}(x))).
\]

Because we only allow integer outputs in \{-1,0,+1\}, any scaled value whose absolute magnitude is `< 0.5` becomes 0; values between `[0.5, 1.5)` become +1 and their negatives become –1.

### 3. Result: Ternary Weights  

The final ternary matrix is:

\[
\widetilde{W}= \operatorname{RoundClip}\!\left(\frac{W}{\gamma+\epsilon}, -1, 1\right),
\qquad
\widetilde{W}_{ij}\in\{-1,0,+1\}.
\]

All subsequent forward passes use \(\widetilde{W}\). During training the original full‑precision **W** is kept for gradient updates; after each optimizer step we re‑apply AbsMean to project back onto the ternary set.

## Minimal Python Example  

Below is a self‑contained snippet that demonstrates the full pipeline on a random weight matrix:

```python
import torch

def absmean_quantize(W, eps=1e-8):
    # 1️⃣ Compute abs-mean scaling factor γ
    gamma = W.abs().mean()
    # 2️⃣ Scale
    scaled = W / (gamma + eps)
    # 3️⃣ Round and clip to {-1, 0, +1}
    quantized = torch.clamp(scaled.round(), -1, 1)
    return quantized.type(torch.int8)

# Example usage
torch.manual_seed(0)
W_fp16 = torch.randn(128, 256).half()   # simulate FP16 weights
W_ternary = absmean_quantize(W_fp16)

print("Unique values:", W_ternary.unique())
# → tensor([-1,  0,  1], dtype=torch.int8)
```

A few takeaways from this code:

* The scaling factor `gamma` is computed *once per weight tensor*, not per element.
* The `torch.clamp(..., -1, 1)` ensures no value drifts outside the ternary set after rounding.
* Keeping `W_fp16` separate lets you continue ordinary Adam or LAMB updates; after each step you simply call `absmean_quantize` again.

## Why Adding Zero Matters  

The original BitNet paper introduced **pure 1‑bit** weights (i.e., only \{-1,+1\}). BitNet b1.58 expands this alphabet with a zero. At first glance you might think “extra bits = extra cost”, but zero actually **reduces** effective bit‑entropy because many weights become dormant.

### Feature Filtering  

Consider a linear layer \(Y = X\widetilde{W}^\top\). If an entire column of \(\widetilde{W}\) contains zeros, that output neuron receives no signal from any input—effectively *pruned* for this forward pass. This dynamic sparsity acts as an implicit feature selector: the model can route information through useful pathways while shutting off noisy ones.

### Increased Representational Capacity  

With only ±1 you are limited to representing two polarity patterns per row/column. Adding zero triples the cardinality of possible patterns per element (from \(2^k\) to \(3^k\) for k elements), yielding richer expressivity without increasing storage—because zeros compress very well in hardware (they can be encoded as “no operation”). Empirically the paper shows that starting at **3 B parameters**, BitNet b1.58 matches FP16 perplexity while using just 31 % of GPU memory.

### Better Gradient Flow  

During training the zero entry acts like a *dead zone*: gradients that push a weight towards zero will stall once it lands there, preventing oscillations around ±1 that can destabilize optimization in pure binary networks.

## Putting It All Together: Training & Inference Flow  

| Phase | What Happens | Data Type |
|------|--------------|-----------|
| **Forward** | Use ternary weights \(\widetilde{W}\); activations are kept at INT8 (or uint8) for speed | int8 weights + int8 activations |
| **Backward** | Compute gradients w.r.t. full‑precision **W** (still stored temporarily) | fp16/ fp32 |
| **Optimizer Step** | Apply Adam/LAMB on **W**, then re‑quantize with AbsMean | fp16 → int8 via `absmean_quantize` |

Because matrix multiplication now consists of simple integer adds (`INT8 + INT8 -> INT16`), modern GPUs or dedicated LPU accelerators can execute it with dramatically lower power draw—up to **71×** less energy for GEMM on 7 nm silicon per the paper’s estimates.

## Summary  

* **AbsMean** scales weights by their average absolute value (`γ`), then rounds/clips them into {-1, 0, +1}.
* The resulting ternary matrix drives an *almost multiplication‑free* inference pipeline.
* Introducing zero enriches model capacity via implicit feature filtering and stabilizes training.
* Real‑world experiments (BitNet b1.58) demonstrate parity with FP16 LLaMA models at ≥ 3 B parameters while cutting memory by > 3× and speeding up inference by > 2×.

If you’re interested in experimenting yourself, start by swapping out your `nn.Linear` layers with a tiny wrapper that calls `absmean_quantize` after each optimizer step—most deep‑learning frameworks make this straightforward. The payoff? Faster models that are cheaper to run and friendlier to emerging low‑bit hardware accelerators.

Happy quantizing!

\title{A Textbook about the Paper: "Parameter-Efficient Orthogonal Finetuning via Factorization"}

Chapter 3: # 3. From Information Transmission to Matrix Factorization

In orthogonal finetuning we must learn a dense orthogonal matrix  
\(\mathbf{R}\in\mathbb{R}^{d\times d}\) that transforms a frozen pre‑trained weight matrix \(\mathbf{W}^{0}\).
Although the mathematical objective is straightforward, the practical
challenge is that a dense orthogonal matrix would normally require
\(d^{2}\) trainable parameters—far more than we can afford when the base
model already contains billions of parameters.  
The central idea of this chapter is to look at the construction of such a
matrix through the lens of **information transmission** on a grid‑shaped
graph.  By doing so, we can reinterpret each factor in a matrix
decomposition as an intermediate communication layer that exchanges
information between nodes.  This perspective provides clear geometric
intuition and leads directly to efficient sparse‑factor formulations,
culminating in the butterfly structure exploited by Orthogonal Butterfly
(BOFT).

## Dense Matrix as Full Connectivity on Nodes

Let us first consider \(d\) input nodes that we wish to transform into
\(d\) output nodes via a linear operator \(\mathbf{R}\).
Each entry \((\mathbf{R})_{ij}\) tells us whether signal coming from
input node \(j\) contributes to output node \(i\).  If every off–diagonal
entry is nonzero, we say the matrix induces **full connectivity**: any
input can influence any output.

Graphically, we can view \(\mathbf{R}\) as a bipartite graph with two sets
of \(d\) vertices, one set representing the inputs and another set the
outputs.  An edge from input \(j\) to output \(i\) exists precisely when
\((\mathbf{R})_{ij}\neq0\).  In the fully connected case this bipartite
graph contains \(d^{2}\) edges (excluding self–loops if desired).

The drawback is clear: representing an arbitrary fully connected graph
requires storing a full matrix—precisely why orthogonal finetuning with a
dense \(\mathbf{R}\) is parameter–heavy.  Our goal, therefore, is to find a way to realize effectively every pairwise interaction while describing only a modest number of trainable parameters.

## Sparse Factors as Intermediate Communication Layers

Instead of encoding all connections in one dense matrix, we can break the transformation into several stages:
\[
    \mathbf{R}
      = \mathbf{B}_{m}\,\mathbf{B}_{m-1}\,\cdots\,\mathbf{B}_{1},
      \qquad m>1.
\]
Each factor \(\mathbf{B}_{k}\in \mathbb{R}^{d\times d}\) may be **sparse**,
containing only a few nonzero entries.  Visually, each factor introduces an **intermediate layer** between input and output nodes:

* The first factor \(\mathbf{B}_{1}\) maps input nodes of level 0 to an intermediate set of nodes at level 1.
* The next factor \(\mathbf{B}_{2}\) maps level 1 nodes to level 2, and so on.
* The final factor \(\mathbf{B}_{m}\) maps level \(m-1\) nodes to the ultimate outputs at level \(m\).

On the grid graph this corresponds to **\(d\times (m+1)\)** vertices arranged in \(m+1\)
columns; directed edges run only between adjacent columns according to each factor’s sparsity pattern.  

If we regard each edge as conveying one unit of information, a complete chain of factors propagates information from every input vertex to every output vertex—exactly what a dense matrix achieves—yet possibly using far fewer edges.

## Graphical Intuition: Directed Edges Between Adjacent Levels

Let us formalize the correspondence between sparsity patterns and directed edges.
For factor \(\mathbf{B}_{k}\), its entry \((i,j)\) indicates whether there is an edge from node \(j\) on level \(k-1\) to node \(i\) on level \(k\). Thus:

* If \((i,j)=0\), there is *no* directed edge between those two nodes.
* If \((i,j)\neq0\), information may flow along that directed edge.

Because multiplication of matrices follows left‑to‑right application,
the overall connectivity from inputs (level 0) to outputs (level \(m\)) is determined by the existence of paths that traverse one edge per stage. Therefore:

> **Lemma (Connectivity Criterion).**  
> The product \(\prod_{k=1}^{m} \mathbf{B}_{k}\)
> yields a dense matrix if and only if for every pair of input node \(p\)
> and output node \(q\), there exists at least one path composed of one edge per stage connecting them.

This lemma transforms our algebraic requirement into an easily visualizable graph theory problem: how many edges do we need, and where should they be placed, to guarantee full connectivity?

## Canonical Example of a Factorization Demonstrating Sparse Edges

Consider \(d=4\), i.e. four inputs and four outputs.
Take five sparse factors:
\[
    \mathbf{R}
      = \mathbf{B}_{5}\mathbf{B}_{4}\mathbf{B}_{3}\mathbf{B}_{2}\mathbf{B}_{1},
      \qquad m=5.
\]
Let each factor have two nonzero entries per column (two edges per node)
arranged such that paths interweave across stages.
Explicitly:

| Factor | Non‑zero pattern (row × column) |
|--------|----------------------------------|
| \(\mathbf{B}_1\) | Edges: \(1\!\rightarrow2,\;3\\textbf{\= }4\dotsc{\rm etc.} |\)

(Full tables are omitted for brevity; see Fig.\,\ref{fig:info_trans} in the paper.)

When drawn on the grid with 6 columns (levels 0–5), it becomes apparent that:

* Every input vertex has three outgoing edges leading it toward outputs;
* Every output vertex receives edges from all inputs via distinct multistep paths;
* The total number of edges equals \(10 < d^2 =16 - d =12.\)

Thus this example exhibits dense connectivity achieved with fewer than all possible edges—a direct illustration that sparse factors suffice.

## Desiderata for Efficient Factorization: Dense Connectivity & Minimum Free Edges

From these observations emerges an **information–transmission objective** for designing sparse factorizations:

1. **Dense Connectivity** – Every input must reach every output through at least one multi‑step path.  
   This guarantees that our product matrix truly implements an arbitrary linear transformation on all pairwise neuron interactions.

2. **Minimum Free Edges** – The total number of scheduled edges (i.e., nonzero entries across all factors) should be as small as possible consistent with orthogonality constraints.  
   Fewer free edges correspond directly to fewer trainable parameters because each free edge typically carries two degrees of freedom (a value and its sign under orthogonality constraints).

These two desiderata are mutually reinforcing yet conflicting under fairness constraints: making factors sparser reduces parameters but risks breaking full connectivity or violating orthogonality.

The butterfly structure addresses this tension elegantly. By arranging sparsity in a systematic recursive pattern that interleaves rows and columns like in Cooley–Tukey fast Fourier transform graphs, it ensures:

* Each stage contributes exactly \(d/2+O(1)\) edges, yielding total free edges proportional to \(O(d\,\log d)\);
* Paths intertwine over layers such that any input reaches any output logarithmically many hops away;
* Orthogonality can be maintained at each stage by parameterizing small block‑diagonal orthogonal matrices (\(2\times 2,\dotsc, b\times b)\).

Consequently, Orthogonal Butterfly realizes both desiderata simultaneously,
which translates into only \(\Theta(d\,b)\log d)\!-\!b)/2\, dm/\!error?)... blah? — enabling efficient finetuning.

\title{A Textbook about the Paper: "The Era of 1-bit LLMs: All Large Language Models are in 1.58 Bits"}

Chapter 2: # 2. Background: Transformers, LLaMA and Quantization Primer

Large language models (LLMs) have grown to involve billions or even trillions of parameters, yet the underlying computation graph is still built upon a small set of well‑studied primitives: multi‑head self‑attention and feed‑forward trans­formations placed inside residual blocks. One influential instantiation of these primitives is the LLaMA family of models, which has become the de‑facto backbone for many open‑source LLMs. Concurrently, the energy and memory demands of full‑precision floating‑point inference have motivated systematic research into quantization—the act of compressing the numerical precision of model tensors without sacrificing too much predictive acuity. This chapter dissects each of these strands: we review the Transformer architecture with an emphasis on its residual structure and attention mechanism; we survey the particular design choices that define LLaMA, such as bias removal, RMS normalization and SwiGLU gating; and we lay out a concise primer on quantization theory and practice, describing both uniform and non‑uniform schemes as well as the most popular post‑training approaches (SmoothQuant, GPTQ, AWQ). The aim is to provide a solid foundation upon which later chapters may delve into 1‑bit LLM variants.

## Residual Networks and Self‑Attention

The Transformer was introduced to replace recurrent architectures in sequence modelling by using attention mechanisms that allow each token to interact directly with all others in a single layer. A typical Transformer block consists of two sub‑modules:

1. **Multi‑Head Self‑Attention (MHSA)**  
   Each token \(x_t \in \mathbb{R}^d\) is mapped to three representations—query \(Q_t\), key \(K_t\), and value \(V_t\)—by applying learned linear projections \(W_Q, W_K, W_V \in \mathbb{R}^{d\times d}\). The attention weight between tokens \(t\) and \(s\) is computed as
   \[
   \alpha_{t,s} = \frac{\exp(Q_t^\top K_s / \sqrt{d_\text{head}})}{\sum_{u}\exp(Q_t^\top K_u / \sqrt{d_\text{head}})}.
   \]
   The output vector for token \(t\) is then
   \[
   h_t = \sum_s \alpha_{t,s} V_s,
   \]
   which captures contextualized relationships across the entire sequence.

2. **Feed‑Forward (FFN) Subnetwork**  
   The transformed token enters a typically two‑layer MLP:
   \[
   h_t' = \sigma(W_2\,\rho(W_1\,h_t + b_1) + b_2),
   \]
   where \(W_1, W_2\) are weight matrices, \(b_1, b_2\) biases, and \(\sigma,\rho\) are activation functions such as ReLU or GLU.

Both submodules are wrapped inside *residual connections*:
\[
x_{t}^{(\ell+1)} = x_{t}^{(\ell)} + h_t',
\]
where superscript \(\ell\) denotes layer index. Residual links mitigate vanishing gradients by providing direct paths for gradient flow to lower layers. In practice, these connections are often followed by normalization layers (LayerNorm or RMSNorm), further stabilising training dynamics.

In the original Transformer paper, LayerNorm was applied *after* each submodule; however subsequent variants—including those that preface attention with normalization—have been introduced to improve convergence speed. Regardless of configuration, the core idea remains: stack several residual blocks of MHSA plus MLPs to build deep sequence models.

## LLaMA Architecture Choices

The LLaMA family bridges this generic Transformer blueprint with specific engineering decisions that reduce memory usage while retaining expressivity. Table 1 summarises the salient components that define a canonical LLaMA staff model.

| Component | Typical Parameter | Effect |
|-----------|-------------------|--------|
| **Bias Terms** | Removed from weight matrices | Reduces parameters; empirical evidence shows minimal performance loss |
| **Normalization** | RMSNorm instead of LayerNorm | RMSNorm normalises only through root‐mean‐square; faster backpropagation & fewer memory stalls |
| **Gate Activation** | SwiGLU (Swish + Gated Linear Unit) | Provides higher capacity than ReLU while remaining lightweight |
| **Embeddings** | Token & positional embeddings stored in FP16 | Keeps embedding matrix energy low; serves as backbone for decoding |
| **Rotary Embedding** | Implemented via Q-Key rotation per head | Enables position awareness without extra parameters |

The removal of biases partly owes to work demonstrating that weight matrices can absorb constant shifts through subsequent layers or embedding adjustments. RMSNorm omits centering operations entirely; it computes
\[
x_{\text{norm}} = \frac{x}{\sqrt{\mathbb{E}[x^2] + \epsilon}},
\]
achieving similar stabilisation while reducing computational overhead.

SwiGLU expands upon standard GLU by replacing its linear gating with a swish activation:
\[
\sigma_{\text{swish}}(z)=z\,\mathrm{sigmoid}(z),
\]
thereby letting the gate learn smoother nonlinearity patterns while keeping parameter count low.

Rotary positional embeddings encode relative positions by rotating query and key vectors in complex plane:
\[
Q_{\text{rot}} = Q\,R,\quad K_{\text{rot}} = K\,R,
\]
where \(R\) is a block‑diagonal rotation matrix derived from sinusoidal frequencies. This facilitates extrapolation to longer sequences without additional learnable position tokens.

Collectively these design choices make LLaMA computationally efficient—in terms of FLOPs and memory consumption—without sacrificing language modelling performance compared to larger baselines such as GPT-3 or GPT-4.

## Quantization Basics

Quantization is formally defined as mapping a high‑precision tensor \(X = [x_i]_{i=1}^N\subseteq \mathbb R^N\) onto a discrete set
\[
X_q = [q_i]_{i=1}^N,\quad q_i \in S,
\]
where \(S=\{-Q_Q+1,\dots,Q_Q-1,Q_Q\}\subseteq \mathbb Z\). The integer scale factor correlates each quantized value back to real domain:
\(x_i' = q_i s_x + z_x.\)

### Uniform vs Non‑Uniform

*Uniform* quantizers use fixed step sizes: 
\(s_x = (\max(X)-\min(X)) / (2^{b}-1)\),
with \(b=\log_2(|S|)\). They are straightforward to implement but can poorly represent activation distributions exhibiting heavy tails or bimodal shapes.

*Non‑uniform* quanti­sation adapts bin widths via clustering methods (e.g., k‑means), non-linear transforms (logarithms), or learned scaling factors per channel/weight group. This approach can approximate arbitrary distributions better but at increased implementation cost.

### Symmetric vs Asymmetric Schemes

In *symmetric* quantization (\(z_x=0\)), negative values map to negative integers symmetrically around zero; this aligns well with weight tensors that are centred around zero due to weight decay regularisers. Symmetry simplifies arithmetic because zero remains exactly zero after quantisation.

In *asymmetric* schemes (\(z_x≠0\)), activations may have non-zero mean; mapping them directly would shift numeric ranges unnecessarily. Asymmetric quantisation introduces an offset term handling this shift but complicates hardware multiplication because two offsets must be considered at runtime.

Most modern text generation inference engines employ symmetric uniform quantisation for weights (int8 or int4), while using asymmetric schemes for activations only when required to capture nuanced dynamic ranges without clipping saturation early.

## Common Post‑Training Quantization Methods

Post‐training quantisation (PTQ) refers to techniques that compress pretrained full‑precision weights/activations without retraining from scratch. Three leading PTQ algorithms dominate research discussions today: SmoothQuant, GPTQ, and AWQ. Each addresses specific challenges—bias mismatch during fine-tuning, per-channel scaling precision, or efficient per-head calibration—which together reduce accuracy loss in practical deployments.

### SmoothQuant

SmoothQuant introduces an intermediate “soft” scaling operation before applying quantisation:
Given a weight matrix \(W^{(l)}_k_j(t)\), it first normalises via channel means:
\(W^{(l)}_{k_j,\text{norm}} = W^{(l)}_{k_j}/m_k,\)
where \(m_k=\frac{1}{n}\sum_j |W^{(l)}_{k_j}|.\)
The normalised weights are then clipped and rounded within controlled ranges:
\(W'^{(l)}=ClippedRound(W_{\text{norm}}, Q_b).\)
During inference a per-colour “cancellation” factor rescues dynamic range lost during rounding. SmoothQuant traditionally operates in 4‐bit domains but can be extended downwards; its main advantage lies in effective bias expansion leading to end-to-end improvements when transferring pre-trained models into lower bit precision.

### GPTQ (Gaussian Posterior Fine-Tuning Quantisation)

GPTQ views weights as random variables following Gaussian posteriors informed by gradient updates during training. It computes optimal per-channel scaling factors analytically:
Letting
\(a_k=\mathbb E[W^{(l)}_{k}] , b_k=\operatorname{var}(W^{(l)}_{k}) , c_k=\operatorname{cov}(W^{(l)}_{k}, Y)\)
(where Y denotes activations), GPTQ selects scale factors
\(s_k= f(a_k,b_k,c_k)\)
by solving a minimum-squared error objective across all channels simultaneously.
The resulting integer weights preserve covariance relationships between layers more faithfully than naive symmetric PTQ.
GPTQ’s key novelty lies in capturing higher order statistics beyond means—essential for plateauing performance on very large language models where weight magnitudes vary wildly across layers.

### AWQ (Adaptive Weight Quantisation)

AWQ proposes an iterative strategy where each layer’s stupentical lambda distribution is adapted last-to-first (“online” quantisation). For every channel k it solves
minimize \(||Y X - Y R s||_2^2,\)
subject to discrete constraints on R∈ℤ^n,
over an auxiliary residual vector r that collects previously layered errors.
This yields near‐optimal scales with minimal error propagation across subsequent layers.
It uses simple polynomial approximation instead of solving complex convex program at every step thus remaining computationally cheap for very large models (<10 min PTQ).

---

Across these methods practitioners commonly choose:

- **SmoothQuant** when high-intensity biases dominate model performance.
- **GPTQ** if low bias but high variance weights are prevalent—as often seen in larger backbone models.
- **AWQ** when fast PTQ turnaround is critical—as it scales efficiently beyond 7B parameter threshold.

All three variants share key shared traits: they precompute canonical integer shifts once per layer; they honor shape partitioning so that GPUs can batch integer GEMM kernels efficiently; they preserve *activations* in INT8 unless explicitly cast further down their pipelines (`8-bit`, `FP16`).  

Understanding how each histogram aligns with particular architectural contexts provides intuition for why 0–±1 weights can be used without harming perplexity: when activations vary slowly but over many tokens—typical for autoregressive LLM inference—the row-level scaling informed by $\gamma$ (median absolute value) captures exact magnitude information necessary for the ternary weight mapping ($-1$, $0$, $+1$). 

Hence this background material equips readers not only with knowledge about how standard Transformers locate their power and bottlenecks but also explains the sophisticated toolsets already present in the community – necessary prerequisites before venturing into true 1-bit model designs such as BitNet b¹·⁵⁸.

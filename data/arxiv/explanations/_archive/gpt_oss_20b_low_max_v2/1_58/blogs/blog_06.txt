# Can You Build Your Own 1‑Bit LLM? A YOLO‑style Roadmap

Large‑language models are moving toward terabytes of parameters, but that growth is leaving cloud budgets and energy numbers sky‑high. If you’ve ever wondered whether a **1‑bit** transformer can run an LLM that feels “real” on a laptop (or at least costs a fraction of the computation), this post gives you a concrete, step‑by‑step plan to re‑implement or fine‑tune **BitNet b1.58**—a 1.58‑bit variant of the LLaMA backbone that matches full‑precision performance while shaving latency, memory and energy in the equation.

> **TL;DR** –  
> * Collect ~100B tokens from RedPajama or similar.  
> * Preprocess: tokenise with SentencePiece, create dataloader with shuffle & bucket.  
> * Use a custom `BitLinear` layer (ternary weights, 8‑bit activations) that plugs in to a vanilla Transformer.  
> * Train from scratch with AdamW, scaler=0.5, lr=3e-4, warmup 3 M steps.  
> * Apply `absmean` quantisation on drivers: \( \tilde{W}=\mathrm{RoundClip}(W/(\gamma+\varepsilon),-1,1)\).  
> * Evaluate perplexity on WikiText2/C4 + zero‑shot tasks from lm-evaluation-harness.  
> * Fine‑tune pre‑trained checkpoints with the same logic if you only want to improve accuracy.

Below is the full recipe, written in a technical yet digestible style.

## 2️⃣ Model Skeleton

### 2.1 Base Architecture

We inherit every building block from LLaMA but replace the linear layers:

- **RMSNorm** – keeps normalisation power.
- **SwiGLU + RotaryEmbedding** – we use the same feed‑forward + attention modules.
- **No bias terms** – simplifies quantisation.

### 2.2 `BitLinear`

```python
class BitLinear(nn.Module):
    """Ternary weight + int8 activation linear layer."""
    def __init__(self, in_features, out_features):
        super().__init__()
        self.weight = nn.Parameter(torch.randn(out_features, in_features))
        self.scale = nn.Parameter(torch.ones(1))
        # no bias

    def forward(self, x):
        # Quantise weights: absmean quantiser
        gamma = self.weight.abs().mean()
        QW = torch.clamp(torch.round(self.weight/(gamma+1e-6)), -1, 1)
        return F.linear(x.to(torch.int8) * self.scale.to(torch.int16),
                        QW.to(torch.int8))
```

*The scaling factor is learned so that despite ternary weights we keep the dynamic range.*

## 3️⃣ Training Loop

### 3.1 Mixed Precision & Gradient Accumulation

- Optimiser: AdamW (`betas=(0.9,0.95)`)  
- Base LR: `3e-4` -> annealed with cosine warmup for first `3M` steps  
- Exponential moving average (EMA) over weights (easier to finetune).

```python
for epoch in range(num_epochs):
    for step, batch in enumerate(dataloader):
        loss = model(batch["input_ids"], batch["labels"])
        loss.backward()
        if step % accum_iter == 0:
            optimizer.step(); optimizer.zero_grad()
```

Store:
- Model state dict (`state_dict()`) – includes ternary weights.
- Training hyperparameters.
- Reproducibility seeds.

Rewind and resume from any point without fear of penalty.

## 4️⃣ Quantisation & Ternary Mapping

The paper’s key novelty is the `absmean` function:

\[
\widetilde{W} = \operatorname{RoundClip}\!\Bigl(\frac{W}{\gamma+\varepsilon}\Bigr), \quad
\gamma=\frac{1}{nm}\sum_{ij}|W_{ij}|
\]

Parameters:

| Symbol   | Meaning            |
|----------|--------------------|
| \(W\)    | Full precision weight matrix |
| \(\varepsilon\) | Small constant preventing division by zero (e.g., \(10^{-6}\)) |
| \(n,m\)  | Matrix dimensions |

Implementation tip: cache \(\gamma\) per layer and recompute only when weight updates occur.

### Zero Point Removal

Unlike classic symmetric quantisation that scales activations to `[0,Q_b]`, BitNet simply scales both signed halves to `[-Q_b,Q_b]`, where `Q_b=255`. This eliminates an extra zero‑point subtraction during inference while leaving per-token statistics intact.

## 5️⃣ Evaluation Pipeline

### 5.1 Perplexity (WikiText2 & C4)

*Use masked language modelling (MLM) style left-padded tokens.*

```python
def evaluate_perplexity(model, dataset):
    loss_total = 0
    n_tokens   = 0
    for batch in torch.utils.data.DataLoader(dataset):
        logits = model(batch['input_ids'])
        loss   = criterion(logits.view(-1,-logits.shape[-1]), batch['labels'].view(-1))
        loss_total += loss.item() * batch['input_ids'].numel()
        n_tokens   += batch['input_ids'].numel()
    ppl = math.exp(loss_total / n_tokens)
```

A ·dataset in the paper had a perplexity drop to ~12 at 3B vs ~13 at FP16—close enough for practical use.

## 6️⃣ Fine-tuning a Pretrained Checkpoint

If you want to avoid training from scratch:

```python

ckpt_state = torch.load('bitnet_b158_lm_3b.pt')
model.load_state_dict(ckpt_state['model'])
```

Apply the same training loop with a lower LR (`5e-5`) for fewer epochs (~10k steps). Because ternary weights are already highly quantised, most gains come from learning better activation scales rather than changing weight distribution.

## 7️⃣ Practical Tips & Common Pitfalls

| Issue | Fix |
|-------|-----|
| *Zeros burn up rank* – many parameters become zero after quantisation → collapse < MLP capacity | Increase learning rate or add an entropy regulariser that penalises zero weights |
| *GPU transfer bottleneck* – frequent weight reloading slows inference | Keep entire ternary weight tensor resident on GPU memory; use efficient CuDNN INT8 kernels |
| *Overfitting at small batch sizes* – low TP migration causes runaway gradients | Use gradient clipping (`torch.nn.utils.clip_grad_norm_`) at norm=0.25 |

## 📦 End-to-End Code Skeleton (Torch)

```python
import torch.nn as nn
import torch.nn.functional as F

class BitNetLayer(nn.Module):
    def __init__(self,width,kernel=False):
        super().__init__()
        self.attn_wqkqkqkqkq   = BitLinear(width,width*2)
        self.attn_vo          = BitLinear(width,width)
        self.mlp_a            = BitLinear(width,width*4)
        self.mlp_o            = BitLinear(width*4,width)
        # RMSNorms etc …

    def forward(self,x):
        x_norm=RMSNorm(x)
        qkv=self.attn_wqkqkqkqkq(x_norm)
        # split qkv -> q,k,v ; rotary etc …
        attn_out=self.attn_vo(...)
        mlp_out=self.mlp_o(F.silu(self.mlp_a)(x_norm))
        return x+attn_out+mlp_out
```

Add `BitLinear` everywhere you would otherwise use `nn.Linear`. That’s it—your model will now process one token/step roughly every X ms with only int8 passes instead of FP16 ops.

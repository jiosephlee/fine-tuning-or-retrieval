\title{A Textbook about the Paper: "Group Sequence Policy Optimization"}

Chapter 2: # 2. Background and Notation

In contemporary reinforcement‑learning (RL) research on large language models (LLMs), the problem formulation is intimately tied to the way language generation is represented as a stochastic policy. This section lays out the formal setting, the notation that will be used throughout the rest of the paper, and a concise motivation for why each component matters for the subsequent development of Group Sequence Policy Optimization (GSPO).  

We first introduce the language‑modeling paradigm in which an autoregressive neural network defines a probability distribution over token sequences conditioned on a prefix. Next, we detail how responses are generated, how their probabilities are computed as products of token‑wise likelihoods, and how external verifiers assign scalar rewards within a bounded interval. Finally, we describe the data structure for queries and the practical definition of sequence length—both of which will repeatedly appear in equations that follow.

---

## 2.1. Auto‑Regressive Language Models as Policies

An autoregressive LLM is a statistical model that factors the joint distribution over a sequence of tokens  
\[
y = \langle y_1, y_2, \dots , y_{|y|}\rangle
\]
given an input prompt or query \(x\) into an ordered product:
\[
\pi_{\theta}(y \mid x) = \prod_{t=1}^{|y|} \pi_{\theta}\bigl(y_t \mid x, y_{<t}\bigr).
\]
Here:
- \(\theta\) denotes all learnable parameters (e.g., weights and biases) of the neural network.
- \(y_{<t}\) is shorthand for the prefix \(\langle y_1, \dots , y_{t-1}\rangle\).
- Each factor \(\pi_{\theta}(y_t \mid x, y_{<t})\) is a categorical distribution over the vocabulary; it gives us a per‑token likelihood.

In RL terminology we view this autoregressive model as a **policy** \(\pi_{\theta}\). When conditioning on a query \(x\), sampling from \(\pi_{\theta}(\cdot \mid x)\) produces a response \(y\). Training involves adjusting \(\theta\) so that policies which produce higher reward \(r(x,y)\) are amplified.

### Why “policy” terminology is useful

Treating \(\pi_{\theta}\) as a control policy allows us to borrow techniques from policy‑gradient methods:  
1. **Action selection** becomes token generation.  
2. **State** at step \(t\) is defined as \((x, y_{<t})\).  
3. **Reward** is assigned only after a full response has been generated (sequence‑level reward).

This framing also clarifies why **importance ratios** (ratios of likelihoods under current vs. old policies) naturally arise when we need to correct for sampling from stale policies during batched training.

---

## 2.2. Likelihood of an Entire Sequence

Because language generation proceeds incrementally, we usually refer to likelihoods in two ways:

1. **Token‑wise likelihood**  
   \[
   p_t^{(\theta)} = \pi_{\theta}(y_t \mid x, y_{<t}).
   \]
   
2. **Sequence‑level likelihood**  
   The joint probability over all tokens in \(y\):
   \[
   P^{(\theta)}(y | x)
     = \prod_{t=1}^{|y|} p_t^{(\theta)}.
   \]

The sequence probability has fundamental roles:

- It quantifies how plausible \(y\) is under policy \(\theta\).  
- It allows us to compute *importance weights* that correct for off–policy sampling: if we generated \(y\) from an old policy but wish to evaluate it under the current one, we multiply by
  \[
  w(y; \theta,\theta_{\text{old}})
      =  \frac{P^{(\theta)}(y | x)}{P^{(\theta_{\text{old}})}(y | x)}.
  \]
- In practice, computing this ratio directly on long sequences can lead to numerical underflow; logarithms alleviate this by converting products into sums:
  \[
  \log w(y;\theta,\theta_{\text{old}})
     =  \sum_{t=1}^{|y|} 
          \bigl[\log p_t^{(\theta)} - 
                \log p_t^{(\theta_{\text{old}})}\bigr].
  \]

The paper’s key insight hinges on replacing token‐level importance ratios \(w_{t}^{(\cdot)} = p_t^{(\cdot)}/p_t^{(\text{old})}\) with sequence‐level ratios such as \(s_i(\theta)\), which are defined after normalizing by length (see Section 4).

---

## 2.3. Verifier Rewards

Once a response \(y\) has been generated for query \(x\), a *verifier* assesses its quality via some black‑box function:
\[
r : (\mathcal{Q},\, A^*) \;\rightarrow\; [0,1],
\]
where:
- The argument space comprises pairs of queries and responses.
- The output lies in the unit interval.

Verifiers can be simple rule‑based judges (e.g., “does the answer contain legal syntax?”), neural classifiers trained on annotated data (“does this answer satisfy pass tests?”), or even human annotators providing normalized scores. The most common downstream objective is that higher rewards should correspond to more desirable completions—for example, passing more unit tests in code-generation tasks or matching higher scores on natural language understanding benchmarks.

Only *sequence* rewards are considered: once the verifier evaluates an entire response it returns one scalar value \(r(x,y)\). This fact motivates aligning reward computation with sequence‑level importance ratios—a theme that pervades GSPO.

---

## 2.4. Query Set and Response Length

Let
- **Query set** be denoted by \(x_i\in\xi,\; i=1,\dots,N_q.\)
The set may consist of real user prompts or synthetic prompts drawn from curated datasets used during RL pre‑training or fine‑tuning.

In practice we treat all queries in one training epoch as independent draws from an empirical distribution over prompts:
\[ 
x\dataSymbol{} x_i\,\,{\sim}\,,\,\,{\cal D},
\]
where ${\cal D}$ captures the genre or domain distribution that should be learned.

The **response length** denotes how many tokens constitute a particular completion:
\[ |y| = T,\]
with typical values ranging from tens to thousands depending on task complexity (e.g., simple questions vs exhaustive code explanation). Length directly influences both:

- The computational cost during rollout generation: each token requires a forward pass through the network.
- The magnitude of cumulative importance ratios and consequently variance in gradient estimates when using token‑wise corrections—precisely why GSPO uses length normalization.

In RL implementations that batch many rolls together, each query can have multiple *groups* of responses generated from the same old policy—the framework described by GRPO and later improved upon by GSPO—so notation extends naturally:
\[ 
(y_1,\dots,y_G )\, ;\, G = |{\text{group size}}|.
\]

---

## Summary

These definitions establish a common language:

| Symbol             | Meaning                                          |
|--------------------|--------------------------------------------------|
| $\pi_\theta$      | Autoregressive language model / policy         |
| $x$                | Prompt / query                                   |
| $y=(y_1,\dots,y_T)$ | Generated response                                |
| $\pi_\theta(y|x)$ | Sequence likelihood under policy $\theta$        |
| $r(x,y)$          | verifier reward ∈[0,1]                           |
| $\cal D$           | Empirical distribution over queries             |
| $G$                | Number of replies sampled per query              |
| $T=|y|$            | Response length                                 |

With this formal foundation in place we are ready to scrutinize why prior approaches such as GRPO falter under high‑variance conditions introduced by token–wise importance ratios and how GSPO resolves these issues by shifting the unit of optimization from tokens to entire sequences.

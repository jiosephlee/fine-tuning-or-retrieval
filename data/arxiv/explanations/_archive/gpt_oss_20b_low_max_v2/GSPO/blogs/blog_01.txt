# Why Token‑Level Rewards Misfire: The Key Insight Behind GSPO

Reinforcement learning (RL) has become the engine for pushing language models (LMs) from large‑scale supervised fine‑tuning to the kind of reasoning abilities we see in Qwen3 or ChatGPT‑4.  
Yet RL training of these behemoths is notoriously fragile: a single hyper‑parameter tweak can morph a model from genius to confusion.  
A large part of the problem lies in a subtle misuse of *importance sampling* – specifically, in the way earlier algorithms like **Group Relative Policy Optimization (GRPO)** apply token‑level importance ratios.

In this post we’ll break down why that approach is fundamentally ill‑posed, walk through a toy derivation that highlights the high‑variance pitfall, and then explain how **Group Sequence Policy Optimization (GSPO)** fixes it by shifting from token‑level to sequence‑level clipping.

---

## 1. The RL objective at a glance

Both PPO and GRPO let us reuse rollouts collected by an *old* policy \(\pi_{\theta_{\text{old}}}\) while updating a *current* policy \(\pi_{\theta}\).  
Because the samples come from \(\pi_{\theta_{\text{old}}}\) but we want expectations under \(\pi_{\theta}\), we introduce an **importance ratio**:

\[
w(z)=\frac{\pi_{\theta}(z)}{\pi_{\theta_{\text{old}}}(z)} .
\]

In PPO the ratio lives at the token level:

\[
w_t = \frac{\pi_\theta(y_t|x,y_{<t})}{\pi_{\theta_{\text{old}}}(y_t|x,y_{<t})},
\]

and every token gets multiplied by a *sequence of advantages* \(\widehat A_t\) before clipping.

GRPO takes the same tack but groups \(G\) responses per query to estimate relative advantages:

\[
\widehat A_i = \frac{r(x,y_i)-\mu}{\sigma},
\quad
-\text{same-token advantage}\;\;\forall t.
\]

The key fact: **each token’s gradient is weighted by its own ratio \(w_t\).**

---

## 2. Why token‑level ratios are a bad idea

### 2.1 Importance sampling intuition

Suppose we want to estimate \(\mathbb E_{z\sim p}[f(z)]\) using samples from \(q(z)\):

\[
\mathbb E_p[f(z)] = \mathbb E_q[w(z)f(z)], 
\qquad w(z)=\frac{p(z)}{q(z)}.
\]

For this identity to hold, *we need many samples from \(q\)* so that the average properly corrects for the distribution mismatch.
If we only have one sample per “portion” of \(q\), then \(w(z)\) is extremely noisy and can swing wildly.

### 2.2 Token vs sequence

In language generation each response \(y=(y_1,\dots,y_L)\) is built token by token.  
A single additional sample drills into a **path** through this probability space.

- **Token‑level ratio**: for each step \(t\), you compute
  \[
  w_t = \frac{\pi_\theta(y_t|x,y_{<t})}{\pi_{\theta_{\text{old}}}(y_t|x,y_{<t})},
  \]
  using *the exact token* drawn by \(\pi_{\theta_{\text{old}}}\).  
  That’s just one draw from \(q=\pi_{\theta_{\text{old}}}\).

- **Sequence‑level ratio**: you first finish an entire response under \(\pi_{\theta_{\text{old}}}\), then compute
  \[
  s = \frac{\pi_\theta(y|x)}{\pi_{\theta_{\text{old}}}(y|x)} 
   = \prod_{t=1}^L w_t .
  \]
  Here you have effectively used one *full* draw from \(q^L=p^{L}_{q}\), i.e., one trajectory of length \(L\).

The big difference is that the **variance of \(s^{1/L}\)** (the geometric mean of the token ratios) shrinks roughly as \(1/\sqrt{L}\).  
In contrast, each individual \(w_t\) can vary dramatically and is not smoothed by other tokens.

### 2.3 What happens when you clip?

Clip limits in PPO/GRPO guard against dangerously large/ small ratios:

```
clip(w, 1−ε, 1+ε)
```

When ratios are noisy, clipping is essentially discarding *good* gradients and keeping *bad* ones whose advantage estimates are already high variance.  
Because GRPO applies this at every step, many tokens get clipped – especially on long responses – leading to:

- **Under‑exploitation**: useful signals vanish because they fall outside the clip window.
- **Accumulation of noise**: residual gradients from surviving tokens still carry high variance because each has been weighted differently.
- **Instability**: as training proceeds, small changes in inference probability (e.g., due to different expert routes in MoE models) cause huge swings in some \(w_t\), propagating outwards through GLM’s weight updates.

Empirically, this manifests as catastrophic model collapse: the policy suddenly forgets everything it learned after only a few epochs.

---

## 3. Sequence‑level clipping in GSPO

GSPO resolves these issues by redefining both the importance ratio *and* where clipping occurs:

1. **Sequence likelihood ratio**:
   \[
   s_i(\theta)=
   \left(
       \frac{\pi_\theta(y_i|x)}
            {\pi_{\theta_{\text{old}}}(y_i|x)}
   \right)^{1/|y_i|}
   = \exp\!\left(
     \frac1{|y_i|}\sum_{t=1}^{|y_i|}
        \log w_{i,t}
     \right).
   \]
   Taking the root normalises across lengths and keeps values in a compact range.

2. **Group advantage** (same as GRPO):
   \[
   \widehat A_i=
   \frac{r(x,y_i)-\mu}{\sigma},
   ~~~
   (\mu,\sigma)\;=\;\text{mean/std over } G.
   \]

3. **All tokens share the same factor**:
   Unlike GRPO’s weighting by \(w_{i,t}\), GSPO weights every token in response \(i\) equally with factor \(s_i(\theta)\).
   Consequently each gradient term looks like:
   \[
   s_i(\theta)\,\widehat A_i
    ~~~
    (\text{no per-token } w_{i,t}).
   \]

4. **Clipping applied once per response**:
   ```
   min(
      s · Ā , clip(s,1−ε,1+ε) · Ā
   )
   ```
   If a whole response’s likelihood deviates too much from what it should be under current policy, we throw away all its gradients – instead of discarding many tokens individually.

---

## 4. What does this buy us?

| Issue | Token‑level (GRPO) | Sequence‑level (GSPO) |
|-------|-------------------|----------------------|
| Ratio variability | high per token | low geometric mean |
| Clipping effect | many tokens lost | fewer high‑risk responses |
| Sensitivity to expert routing | massive swings | stable because only overall likelihood matters |
| Memory overhead | needs value net + per-token ops | no value net; scalar objective |
| Training stability | prone to collapse | robust even for MoE large models |

In practical experiments on Qwen3-30B-a3b-base training with MoE layers, GSPO achieved continuous performance gains while GRPO failed unless coupled with additional tricks like *Routing Replay*. Moreover, GSPO’s higher fraction of clipped tokens does not hurt efficiency; it simply avoids noisy gradient contributions altogether.

---

## 5. Take‑away

The core flaw in GRPO sits silently behind its per-token importance weights; it breaks basic importance sampling principles because it attempts to correct for distribution shift on a single sample at each step rather than on an entire trajectory.  

By redesigning both the importance ratio and where clipping happens—shifting focus back to whole sequence likelihoods—GSPO turns catastrophic variance into stable learning signals and unlocks efficient RL scaling for gigantic LMs and Mixture-of-Experts architectures.

If you’re building or fine‑tuning large language models with reinforcement learning, replacing token‑wise weights with sequence‑wise ones (and using length–normalised clipping as shown above) can be the single most impactful tweak for reliability and performance.

\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### "Residual stacking architecture” – how many layers/heads in xLSTM blocks correspond to 48 residual blocks?
Question:
$x_	ext{text}{block}[a:b]$ notation seems confusing: If xLSTM[7:1] has 48 total blocks, does that mean 42 mLSTM-based blocks (7 heads?) and 6 sLSTM based blocks? How exactly are layers and heads counted in practice when building an architecture like 48 residual blocks? Also what dimension do you use for hidden states inside an individual block?
Answer:
**Short answer**  
In the paper the notation `xLSTM[a:b]` is a shorthand for “\(a\) mLSTM blocks : \(b\) sLSTM blocks : total = \(a+b\) blocks”.  
So `xLSTM[7:1]` with a total block count of 48 means 42 mLSTM blocks and 6 sLSTM blocks.  
Each block’s internal dimensionality (the hidden size \(d\)) is the same as the model’s overall embedding dimension, e.g. 512, 1024, … depending on the model variant. The two types of blocks differ only in their internal memory structure and gating; the inter‑block residual connections keep the dimension constant across the whole network.

---

### How the notation works

The paper defines the ratio as follows:

> *“For all experiments, we use the notation **xLSTM[\(a\):\(b\)]** for the ratio \(a/b\) of mLSTM‑based versus sLSTM‑based xLSTM blocks.”*  

If you choose a particular total number of residual blocks—48 in most experiments—the numbers \(a\) and \(b\) must add up to that total:

| notation | number of mLSTM blocks | number of sLSTM blocks | total blocks |
|----------|-----------------------|------------------------|--------------|
| xLSTM[7:1] | 7 × 6 = **42** | 1 × 6 = **6** | **48** |
| xLSTM[1:0] | 1 × 48 = **48** | 0 | **48** |
| xLSTM[1:1] | 25 × 2 .. etc. | 23 ... | — |

In other words, each pair in brackets represents *how many* occurrences of each block type there are in a stack that contains all 48 residual units. The factor “6” is simply the number of times you repeat `xLSTM[7:1]` to reach the final depth; you could also write `xLSTM[7:1]_×6` if you prefer.

### Inside a single block

Each block is a residual module that follows a pre‑LayerNorm “pre‑up‑project” or “post‑up‑project” pattern (see Figure 3 in the paper).  
The hidden dimensionality \(d\) is chosen once for a whole architecture (e.g. in the 350 M parameter model \(d=1024\)).  
Both sLSTM and mLSTM layers keep this dimension:

- **sLSTM**: scalar cell state per memory cell, but you can stack several *heads* (each head is a separate LSTM with its own hidden vector of size \(d/h\)), so that across heads you recover an overall dimension \(d\).  
- **mLSTM**: matrix cell state \(\mathbf{C}_t \in \mathbb{R}^{d\times d}\). Here the hidden state still lives in \(\mathbb{R}^d\); only the internal memory \(\mathbf{C}_t\) has a quadratic size.

Hence there is no separate “hidden state inside an individual block”: it is always \(\mathbb{R}^d\). The extra weight matrices inside mLSTM (`W_k`, `W_v`, …) simply map from that space to keys, values and queries.

### Counting heads vs layers

When you ask how many *layers* or *heads* correspond to a “48 residual blocks” architecture, think of each residual block as one layer regardless of whether it contains an sLSTM or an mLSTM. A head counts only inside an sLSTM block—in `xLSTM[7:1]`, each sLSTM block has exactly one head (the authors explicitly state that sLSMs may have multiple heads but here we use one). Therefore in this particular configuration:

- **Layers**: 48 (one per residual block).  
- **Heads**: exactly one per sLSTM block → 6 heads total; mLSTMs have no heads.  

If you were to use multi‑head sLSMs, each additional head would increase both parameter count and compute but would not change the external block count.

### What hidden dimension to pick?

All experiments in the paper use a single embedding dimension shared across all layers; typical values are:

- Small models (≈100 M parameters): \(d = 512\)  
- Medium models (≈350 M parameters): \(d = 1024\)  
- Large models (≈1–3 B parameters): \(d = 2048\)

The choice is dictated by the target model size and desired computational budget. The architecture itself does not impose any other constraint on \(d\).

---

### TL;DR

* `xLSTM[a:b]` == `a` mLSMs : `b` sLSMs inside one six‑layer “mini‑paragraph”; multiply by 8 to get 48 real layers.  
* In `xLSTM[7:1]`: **42 mLSMs + 6 sLSMs**, all operating on hidden vectors of size \(d\).  
* Each block preserves the same hidden dimension, so there is no extra per‑block hidden size to worry about.  

This mapping mirrors how Transformers or SSMs stack their attention or state‑space layers—each residual unit counts as one layer, while heads are an optional inner parallelism within particular module types.

# Foundations of Recurrent Memory Models  

Recurrent neural networks (RNNs) were, for a long time, the only viable deep‑learning tool capable of ingesting variable‑length sequences.  The problem that originally motivated their invention—*vanishing and exploding gradients*—is a fundamental characteristic of any network that processes data in a chain.  The Long Short‑Term Memory (LSTM) cell, introduced in the early 1990s, solved this problem with two intertwined ideas: the *constant error carousel* (CEC) and *gating*.  These mechanisms allow a recurrence to preserve information for arbitrarily long horizons while still permitting learning through gradient descent.  
Below we trace the historical motivation, then unpack the mathematics of the classic scalar LSTM cell, and finally present practical implementation details that undergraduate students will find useful when reading research papers in the LSTM lineage.

---

## Historical background: RNN limitations  

The first recurrent nets consisted of a single hidden vector \(h_t \in \mathbb{R}^{d}\) updated by an affine map followed by a nonlinearity:

\[
h_t = \tanh\!\bigl( W\,x_t + R\,h_{t-1} + b \bigr),
\]

where \(x_t\) is an input embedding.  Back‐propagation through time (BPTT) driven gradient updates scale multiplicatively along this chain.  For long sequences, the repeated multiplication by \(\|R\|\) either drives gradients toward zero (vanishing) or to infinity (exploding).  In practice, this prevented learning dependencies beyond a handful of timesteps and led researchers to devise shortcut variants such as *neural Turing machines* or *memory networks*—all of which suffered from similar training pathologies.

A groundbreaking insight by Hochreiter & Schmidhuber in 1997 was to decouple memory content evolution from its hidden‑state output.  The key observation was that if a cell state could evolve *additively*, rather than multiplicatively through recurrent weight matrices, gradients could be propagated unhindered across time.  The resulting architecture is known as an LSTM cell and is the subject of this chapter.

---

## Constant error carousel physics  

The constant error carousel (CEC), sometimes called “the additive memory update,” is the mechanism by which an LSTM cell keeps its internal state roughly unchanged regardless of how many times it is updated.  Put simply:

\[
c_t = f_t\,c_{t-1} + i_t\,z_t,
\]

where

* \(c_t \in \mathbb{R}\) is the *cell state* (or “memory”);
* \(f_t\in(0,1)\) is the *forget gate*, deciding how much past information to retain;
* \(i_t \in (0,1)\) is the *input gate*, deciding how much new evidence to absorb;
* \(z_t \in \mathbb{R}\) is a contracted “input signal” derived from both the current input and previous hidden state.

If gates were constants equal to one, each update would simply add \(z_t\), exactly like adding to a running total.  If gates were learned functions of the network’s own history that can take on small values in \((0,1)\), gradients flowing backward through \(c_{t-1}\) can proceed almost unimpeded because they are multiplied only by scalars derived from gates—not by entire weight matrices.  Hence we obtain a constant‑error path that “circulates” around the recurrence: gradients can jump over arbitrarily long chains of timesteps via repeated application of identity‑like transformation functions.

---

## Gate mechanisms (forget, input, output)

Three scalar gating signals determine how information flows into and out of the cell:

| Gate | Symbol | Role | Typical activation |
|------|--------|------|---------------------|
| Forget | \(f_t\) | Controls what fraction of old memory to keep | Sigmoid \(\sigma(\cdot)\) or exponential \(\exp(\cdot)\) |
| Input | \(i_t\) | Controls what new information to write | Sigmoid or exponential |
| Output | \(o_t\) | Controls how much memory appears on hidden state | Sigmoid |

The gate activation functions are usually learned via an affine transformation on current input and previous hidden unit:

\[
\tilde{g}_t = w_g^\top x_t + r_g h_{t-1} + b_g,\qquad g_t=\sigma(\tilde{g}_t)\;\;(g\in\{f,i,o\}).
\]

The use of separate weight vectors for input, forget and output (\(w_f,w_i,w_o,r_f,r_i,r_o,b_f,b_i,b_o\)) allows each gate to adapt independently based on both current external signals and internal context.

---

## Scalar LSTM equations and forward pass  

A scalar LSTM cell operates exactly as follows at timestep \(t\):

1. **Compute pre‑activations** for each gate:
   \[
   \tilde{i}_t = w_i^\top x_t + r_i h_{t-1} + b_i,\quad   
   \tilde{f}_t = w_f^\top x_t + r_f h_{t-1} + b_f,\quad  
   \tilde{o}_t = w_o^\top x_t + r_o h_{t-1} + b_o.
   \]

2. **Activate gates**:
   \[
   i_t = \sigma(\tilde{i}_t),\qquad
   f_{\,t} = \sigma(\tilde{f}_t),\qquad
   o_{\,t} = \sigma(\tilde{o}_t).
   \]

3. **Compute candidate memory update**:
   A linear combination of input embeddings supplies an unbounded value:
   \[
   z'_t = W_z^\top x_t + r_z h_{t-1} + b_z.
   \]
   This is then squashed:
   \[
   z_t = \varphi(z'_t), 
   \]
   where usually \(\varphi=\tanh\).

4. **Update cell state** (CEC):
   \[
   c_t = f_{\, t}\;c_{\, t-1} + i_{\, t}\; z_t.
   \]

5. **Form hidden state**:
   Apply another squashing function to ensure boundedness before allowing it to escape through the output gate:
   \[
   h^{~}_{\, t}=o_{\, t}\;\psi(c_{\!t}),
   \]
   with typically $\psi=\text{tanh}$ as well.

These five lines represent one complete forward pass; all operations are differentiable so back‑propagation can learn every parameter via gradient descent.

---

## Weight and bias matrices  

For a scalar cell it suffices to use weight vectors:

* $w_\bullet$, $r_\bullet$ are $d$‑dimensional vectors mapping input dimension $d$ into each gate or memory component.
* $b_\bullet$ are scalars that shift each affine map.

In practice one constructs these as rows or columns from larger matrices when stacking multiple parallel cells (i.e., turning each scalar into an element of a vector). This bookkeeping allows GPU frameworks to treat batch updates as single matrix multiplications, greatly improving throughput.

When organisms want more expressive power they replace these vector peepholes with full recurrent weight matrices $\mathbf{R}$.  
This then gives rise to “memory mixing”: the next hidden vector receives contributions from all previous memories weighted by $\mathbf{R}$ instead of being fed back through separate gates—a technique explored later in sLSTM.

---

## Activation functions (Tanh & Sigmoid)

The choice $a(z)=\text{tanh}(z)$ for $\varphi$ and $\psi$ serves two purposes:

1. It bounds internal signals within $[-1,+1]$, preventing exponential blow‑ups in deep stacks.
2. It provides nice derivative properties ($a'(z)=1-a(z)^2$), which help manage gradient vanishing through many timesteps when combined with gating.

Sigmoid ($\sigma(z)=1/(1+e^{-z})$) confines gates strictly between 0 and 1 so they can function exactly as gates: accept or extinguish signals quantitatively.

---

## Memory mixing via recurrent weight matrices  

Standard LSTMs aggregate past hidden states only through scalar gates acting on single cells; no direct mixing between different cells' outputs occurs within a single timestep.  
To introduce *state tracking*, scholars added recurrent weight matrices:

$$
h_{i,t} = R^{ih}_{ia}\;z_{a,t},
$$

where summation over index $a$ mixes inputs across all active cells before each gate operates on them.  
These extra degrees of freedom enable more complex dynamical behaviors but also increase sequencing cost because each timestep requires interacting with all previous states via $\mathbf{R}$—an expensive operation unless clever parallel/space tricks are employed (see axiomatic exposition in sLSTM).

---

## Examples of successful LSTM applications  

Over three decades many domains have benefited from leveraging LSTM’s explicit memory:

* **Text generation** – Recurrent nets can produce human–readable paragraphs from scratch because their memories capture grammar structure.
* **Speech synthesis & recognition** – Phoner embeddings pass through memory layers allowing alignment between audio frames over time.
* **Sequence–to–sequence translation** – Encoder–decoder pairs store source sentences for retransformation into target language tokens.
* **Reinforcement learning** – Agents maintain long‑term strategic representations that survive variable episode length.
* **Scientific modeling** – Hydrological or meteorological simulations use LSTMs for low–dimensional latent state propagation inside complex dynamical systems.

These successes form a robust evidence base for studying novel extensions such as exponential gating or matrix memories—ideas we’re about to investigate in depth in later chapters.

--- 

In summary, understanding this classic scalar LSTM’s formulation provides the baseline for evaluating extensions such as xLSTM’s sLSTM and mLSTM blocks. The key takeaway for students reading contemporary research papers is that every subsequent method builds onto these core mechanisms: gating architecture; constant error carousel; bounded activation; and optional recurrent mixing matrices—all designed with careful attention to gradient flow across time.scrollrichtung

# 2. Shortcomings of Classical LSTMs in Modern Contexts  

Long Short‑Term Memory (LSTM) networks were a breakthrough in the early 1990s, solving the vanishing‑gradient problem by adding a cell state that can be updated additively and gated. They became a workhorse for language generation, sequence‑to‑sequence translation, handwriting synthesis and many other sequence‑related tasks. Despite their practical success, classical LSTMs exhibit three fundamental weaknesses that become especially critical when they are pushed to the scale of modern large language models (LLMs). This chapter dissects each weakness in detail, demonstrates it with concrete synthetic experiments introduced in the paper *xLSTM: Extended Long Short-Term Memory*, and shows why transformers are able to circumvent these limitations.

The three limitations are:

1. **Inability to revise storage decisions** – once information has been stored, the original LSTM cannot overwrite it with a more relevant piece later in the stream.
2. **Limited storage capacity** – each cell stores a scalar that forces the network to compress all useful information into a single number per dimension.
3. **Sequential dependency (memory mixing)** – hidden‑to‑hidden recurrence enforces token‑wise serial processing that prevents efficient parallel computation.

We now explain each point formally and illustrate the shortcoming with an adversarial task.

---

## Task 1: Nearest‑Neighbor Search – error analysis  

### The problem formulation  

Consider a streaming sequence of vectors \(x_1, x_2, \dots ,x_T \in \mathbb{R}^d\) and an additional query vector \(q_{\text{last}}\) presented at time step \(T\). The task is to output the index \(t^* < T\) (or the value paired with \(x_{t^*}\)) of the vector in the past that is **nearest** to \(q_{\text{last}}\) under Euclidean distance:
\[
t^\ast = \arg\min_{t < T} \|x_t - q_{\text{last}}\|_2 .
\]
The environment gives feedback only at time \(T\); during processing each timestep \(t\) we can only observe \(x_t\), not the future query. This setting probes whether an RNN can *remember* a previously seen vector until a comparison arrives.

### Why a scalar cell struggles  

In a vanilla LSTM each dimension of the hidden state carries essentially one scalar memory value synchronized via additive recurrence:
\[
c_t = f_t c_{t-1} + i_t z_t,
\]
with forget gate \(f_t \in (0,1)\), input gate \(i_t \ge 0\), and transformed input \(z_t = \varphi(\tilde{z}_t)\). The scalar update rule implicitly assumes that *the entire relevant context can be represented by a single number per dimension*. If two distinct vectors have identical scalar compositions but different directional cues relative to future queries, no gating strategy can distinguish them at inference time. Once an earlier vector has been written to memory—when its corresponding gates are active—the *constant error carousel* will hold onto it unless all its memories are decayed by future forget gates. However, because forgetting is gradual (via multiplication by the forget gate), an LSTM is forced to remember any strong memory for many steps unless it explicitly decides to collapse it early.

In practice this manifests as **error accumulation**: early vectors “contaminate” later states and prevent later retrievals from updating them. Figure~X.X in the original paper (referenced as Fig.~2 left panel) plots mean-squared error versus sequence length for this task: the red line corresponds to xLSTM (exponential gating + normalizer), whereas the blue line marks vanilla LSTM performance. As soon as the network is required to overwrite an earlier stored key with a closer match, vanilla LSTM’s error grows linearly with distance from the current timestep, because its gates cannot perform an abrupt overwriting operation – they can only attenuate or preserve content via smooth multiplication.

### xLSTM’s remedy – exponential gating  

xLSTM addresses this defect by allowing gates whose activations grow or shrink *exponentially* instead of sigmoidly:
\[
i_t = \exp(\tilde{i}_t), \qquad f_t = 
   \begin{cases}
       \sigma(\tilde{f}_t) & \text{(sigmoid branch)}\\[4pt]
       \exp(\tilde{f}_t)  & \text{(exponential branch)}
   \end{cases}.
\]
Exponentially large values give gates very sharp transition behavior: an input gate can almost fully “consume” new content while a forget gate can almost instantaneously suppress previously memorized data if future gates dictate so. In addition, xLSTM keeps track of a normalizer state
\(n_t = f_t n_{t-1} + i_t\),
which normalizes cell content before producing hidden output:
\(h_t = o_t \cdot c_t / n_t.\)
This normalization explicitly tracks how many “effective reads” have happened so far, enabling precise control when overwriting occurs.

Empirically, substituting plain sigmoid gates with exponential ones reduces nearest‑neighbor retrieval error by up to 30 % when evaluated on synthetic data sets up to 10 k time‑steps long—substantially narrowing the gap between learning curves of classic LSTMs and xLSTMs (Fig.~2).

## Task 2: Rare Token Perplexity – capacity limits  

### The experimental setting  

Rare token perplexity is measured on Wikitext‑103 after training a language model that predicts tokens sequentially. Tokens are binned according to their frequency in training data: common tokens occupy one bin, extremely rare tokens belong to another bin. The perplexity for each bin reveals how well the model knows rarely seen symbols during inference.

### The theoretical limitation induced by scalar cells  

An LSTM with hidden dimension \(d\) stores its memory as \(c \in \mathbb{R}^d\), updated elementwise via Eq.(1). Each scalar entry is essentially a *compressed proxy* for arbitrarily complex sequences—it must simultaneously encode rich structural patterns (syntactic roles, entity tracking), word meaning, positional bias as well as adapt dynamically over time. Compressing semantic history into these few scalars leads necessarily to lossy representations; rare tokens pose a high compression burden because they carry high information content relative to their frequency.

To quantify this phenomenon we look at perplexity curves versus cut-groups—figures in Section §5 reveal that for rare token bins perplexity drops gradually but remains significantly higher than for common bins when using vanilla LSTM (\(d=2048\)). Each additional dimension contributes only linearly to representational capacity because updates aggregate additively; there is no multiplicative interaction pattern that could afford combinatorial explosion like self-attention’s dot-product mechanism.

### Why matrices help – mLSTM

The paper introduces *mLSTM*, which replaces each scalar cell with a full matrix
\(\mathbf{C}_t \in \mathbb{R}^{d\times d}\).
A key/value pair
\(k_t,v_t \in \mathbb{R}^d\)
is written via covariance update:
\[
\mathbf{C}_t = f_t\,\mathbf{C}_{t-1}
              + i_t\, v_t k^\top _t .
\]
Retrieval at time step \(t'\) requires only
\( h_{t'}=\mathbf{o}_{t'} 
            (\mathbf{C}_{t'} q_{t'} / n_{t'})
         , 
      n_{t'}= f_{t'} n_{t'-1}+i_{t'} k_{t'}
   ,
   q_{t'}=\mathbf W_q\,x_{t'}, 
    n_{0}=0 .
  \)
Mathematically this equivalent baseline is precisely Fast Weight Programmers expanded by gating. Crucially, storing outer products allows **quadratic growth** of representation capacity with respect to embedding width while maintaining linear parameter count. The mLSTM thus folds more fine-grained semantics into its memory matrix; empirically its rare token perplexity drops below that of vanilla LSTMs by ∼10–15 %, achieving performance comparable to transformers on these tasks (Fig.~3).

---

## The role of scalar cells in compression  

Scalar cells force every past event into one value per channel; even if noise or irrelevant history drifts inward through small forget gates, there is no way for multiple unrelated entities to co-exist without interfering unless states saturate or are overwritten sharply (exponential gating). In contrast:

- **Transformer attention** uses all past tokens simultaneously through dot‑product similarity; every token contributes independently.
- **State‐Space Models** use linear transforms that maintain orthogonality and project through dynamical systems.
- **xLSTM’s mLSTM** stores full correlation among keys/values.

Thus LSTMs’ memory acts like a highly compressed buffer where all shape information must be distilled into one number per neuron, leading invariably to information bottlenecks for complex or long‐range phenomena such as rare words or subtle context dependencies.

---

## Sequential dependency and memory mixing bottleneck  

Apart from storage depth problems, classic LSTMs suffer from architectural recursion:

- At each step hidden state updates depend on previous hidden state:
  \(h_t = o_t\, g(c_t).\)
- Gating parameters typically involve recurrent weight matrices that mix outputs across dimensions:
  left parts “memory mixing” where output from one time step influences next cell’s hidden representation via recurrent terms
  \( r_z h_{t-1}, r_i h_{t-1}, ….\)

This recurrence forbids parallel execution over multiple timesteps because each update needs all completed preceding values (\(h_{t-1}\)). Even though gradient computation uses backpropagation through time (BPTT), inference time remains inherently sequential. With sequence lengths extending into tens or hundreds of thousands—a common scenario in contemporary text generation—the wall‑clock latency skyrockets; moreover GPU stalls due to irregular memory access patterns may arise.

The transformer architecture bypasses this bottleneck: all self‑attention weights are computed jointly using matrix multiplications; queries/keys/values for every token can be processed simultaneously after basic “up‑projection” transformations. State‐space models also avoid explicit pairwise computations between successive states; rather they leverage linear dynamical systems whose matrices can be simultaneously diagonalized or block‐simplified for parallel operations.

---

## Why Transformers can bypass these limits  

Transformers address these deficits in three ways:

1. **Sparse/history-aware rewritability:** Self-attention from scratch reuses “soft max” weighting where any new query can downweight previous key/value pairs arbitrarily fast—as opposed to an additive decay channel controlled gradually.
2. **High-dimensional linear combinations:** With continued residual projections (\(W_Q/K/W_V/W_O)\), transformers essentially operate in high dimensional space where repeated linear combinations increase expressive capacity without compressing everything into scalars.
3. **Implicit parallelization:** All token interactions involve only matrix multiplications; there is no iterative recurrence constraint across positions after projection from queries/keys/values.

When scaled mid-billions parameters and trained on large corpora (\(15–300~B\) tokens), transformer models achieve lower perplexities than even well-tuned repeated-LSTMs thanks mainly to these mechanisms.

The extended xLSTM architecture tries again at pushing classical RNNs forward: it brings exponentiation-based gating—giving hard throttle control—and enriched memory structures—turning scalars into full covariance matrices—so as much capacity as possible bears within its usual sequential framework. Experimental results across synthetic tests such as nearest-neighbor recall, associative recall and long-range language modeling summarise how close xLSTMs come toward transformer-level performance while retaining strictly linear computational complexity w.r.t context length—a compelling trade-off highlighted throughout subsequent sections of this book.

# 3. Exponential Gating – A Remedy for Storage Revision

## Motivation for Exponential Gates over Sigmoid/Softmax

The core of the LSTM cell is a set of gates that decide how much new information should be written into the memory, how much old information should be forgotten, and how much of the memory should be exposed at the output. In every classical formulation—sigmoid‐based LSTM, gated recurrent unit (GRU) or any of their variants—the gates are confined to the interval \([0,1]\). This boundedness is attractive for training stability: gradients never explode because the gates merely damp or pass data through.

However, bounding the gate values also creates a rigidity in what the network can express. Consider a situation where the model has already stored some value \(z_t\) in memory at time step \(t-1\) and later receives a new, more relevant vector at time step \(t\). If the forget gate can only reduce a value to at most \(f_t=1\), there is no mechanism to *increase* the weight placed on a newer datum if it is more informative than an older one. Thus, once an entry has been written into memory it becomes frozen; revising it requires an explicit, often ad‑hoc strategy such as resetting the cell state or employing soft‑reset gates. Empirical evidence from tasks such as nearest‑neighbor search (see Figure 2 of the paper) demonstrates that vanilla LSTMs fail to adapt when a more similar key is found later in the sequence:they cannot overwrite or emphasise a new observation.

An unbounded activation function removes this asymmetry. The exponential function \(x \mapsto e^x\) naturally ranges over \((0,\infty)\) and can represent arbitrarily large gate values. When used for input or forget gates, it gives the model two complementary possibilities:

1. **Revising memory** – An exponentially large forget value \(f_t = e^{\tilde{f}_t}\gg 1\) allows multiplication of the prior cell state by a large number, effectively amplifying and thereby prioritising earlier content.
2. **Rapid overwrite** – Conversely, an exponentially small but non‑zero input value \(i_t = e^{\tilde{i}_t}\) enables high‑resolution placement of new content without being confined to \([0,1]\).

In essence, exponential gating turns the constant error carousel
\(c_{t}=f_t c_{t-1}+i_t z_t\)
into a *multiplicative* modulation that can scale previous content up or down at will.

Because modern transformer‑based models rely largely on self‑attention with softmax normalisation, which inherently caps attention weights via a normalised probability simplex, exponential gating equips recurrent models with a complementary mechanism that better captures highly variable evidence across time steps.

---

## Definition of Input, Forget, Output Gates with Exp Activation

Let \(\mathbf{x}_t \in \mathbb{R}^{d_{\text{in}}}\) be the input vector and \(\mathbf{h}_{t-1} \in \mathbb{R}^{d_{\text{hidden}}}\) be the previous hidden state. In line with traditional LSTM notation we define *pre‑activation* terms:

\[
\tilde{i}_t = \mathbf{w}^\top_i\,\mathbf{x}_t + r_i\,\mathbf{h}_{t-1} + b_i,\qquad
\tilde{f}_t = \mathbf{w}^\top_f\,\mathbf{x}_t + r_f\,\mathbf{h}_{t-1} + b_f,\qquad
\tilde{o}_t = \mathbf{w}^\top_o\,\mathbf{x}_t + r_o\,\mathbf{h}_{t-1} + b_o .
\]

For **exponential gates** we transform these pre‑activations as follows:

| Gate      | Activation | Definition |
|-----------|------------|------------|
| Input     | \(i_t = e^{\,\tilde{i}_t}\) | Exponentially scales new content |
| Forget    | \(f_t = e^{\,\tilde{f}_t}\) | Enables amplification / discretely “forgetting” |
| Output    | \(o_t = \sigma(\tilde{o}_t)\) | Standard sigmoid to keep hidden output bounded |

Notice that only input and forget gates are exponentiated; keeping output gating sigmoid preserves stability at final projection and prevents uncontrolled explosion in hidden outputs.

The rest of the LSTM equations remain unchanged except for replacing sigmoid-applied gates with their exponential counterparts:

\[
c_t   = f_t\,c_{t-1}   + i_t\,z_t , \qquad
h_t   = o_t\,\psi(c_t).
\]

Here \(z_t=\varphi(\tilde{z}_t)\) is any chosen cell input activation (usually \(z_t=\tanh(\tilde{z}_t)\)), and \(\psi(c)=c/n_t\) will be discussed below.

---

## Construction of Normalizer State \(n_t\)

One might worry that unbounded gate values could lead to exploding cell states due to repeated multiplication by large forget factors. The **normalizer state** explicitly records how much *scaled* information has accumulated up to time \(t\), thereby permitting controlled division at every step:

\[
n_0 = 0,\qquad
n_t = f_t\, n_{t-1}  + i_t.
\]

Intuitively:
- Each time we “write” into memory (\(i_t z_t\)), we also augment the normalizer by exactly the magnitude of that write (\(i_t\)).
- Each time we “forget” (\(f_t c_{t-1}\)), we simultaneously proportionally scale down the normalizer.

With this construction, whenever we wish to obtain an unbiased estimate of stored content relative to its overall weight budget we simply normalise:

\[
c'_t   = \frac{c_t}{n_t}, \qquad
h'_t   = o_t\, c'_t .
\]

Dividing by \(n_c_n` keeps *relative* magnitudes in check because both numerator and denominator have undergone identical scaling by past gates. In practice we enforce **\(n_0>0+\epsilon** (e.g., initialise with small constant). This keeps division well defined while maintaining numerical safety.

---

## Stabilization Using Log–Domain Tricks (\(m_t\))

Although exponentiation enables unbounded scaling, it can also spur catastrophic overflow during training if any pre‑activation value becomes larger than roughly 100–200 in magnitude (the exponent then exceeds machine limits). To mitigate overflow we adopt a *log‐domain stabilizer*, echoing techniques used in Fast Weight Programmers and ReLU networks.

Let us denote

```python
# Pseudo-Python code for stabilized exponential gates
m_prev  # m_{t-1}
log_f   # log(f_t)
log_i   # log(i_t)
```

We update stabilizer state:

```python
m_current = max(log_f + m_prev , log_i)
```

Then re‐expressed effective gates are:

```python
i'  = exp(log_i  - m_current)
f'  = exp(log_f + m_prev - m_current)
```

Note that \(i' f'\) automatically satisfies:

\(i' f' = e^{(\log_i - m)} e^{(\log_f + m_{\text{prev}} - m)} 
= e^{(\log_i + \log_f)} 
= i f / e^{2m}\).

In other words, we factor out an overall scaling term common to all operations but do not change any *relative* contribution of each component. Because gradients propagate through these rescaled variables via quotient rules that exactly cancel this common factor (see equivalence proof below), training dynamics remain unchanged while numeric stability improves dramatically.

---

## Mathematical Equivalence Proof (No Change to Gradients)

We must show that replacing each gate by its stabilized counterpart leaves both forward outputs and backward gradients untouched (except perhaps for floating point roundoff). Consider any scalar variable undergoing transformation:

Let’s denote:
- Original forward equations:
  - \(c_{(k)}   = f_k c_{k-1} + i_k z_k,\)
  - \(n_k        = f_k n_{k-1} + i_k.\)

With transformers stablised:
- Effective gates:
  - \(g_k^c     := f_k c_{k-1}/p_k,\quad p_k := e^{m_k}.\)
  - Similarly adaption for normaliser: replace raw values by gracefully scaled values.

But because every term inherits *exactly* same factor \(e^{m_k}\), all multiplicative cancellations occur when computing final expressions that involve ratios. For instance,

\(c'_k / n'_k 
= (f_k c'_{k-1}+ i_k z_k)/(f_k n'_{k-1}+ i_k)\)

where primes denote normalized quantities using stabilized gates. However:
\(c'_{k}= (c_{k}/p_k), n'_{k}= (n_k/p_k)\)

Hence

\(c'/n' 
= (c/p)/(n/p)
= c/n.\)

Thus forward activations do not change.

For backpropagation using chain rule:
We differentiate any scalar function \(L(c,n,i,f)\). Because all intermediate variables depend on stabilised forms only through *multiplication/division* by a global scalar constant per time step (\(e^{-m_k}\)), derivatives respect product rule; factors cancel out on both sides when following backward chain through network as they appear symmetrically in numerator/denominator. As long as we maintain consistent symbolic manipulation—i.e., whenever forward uses exact relation—we can guarantee identical analytic gradients albeit computed slightly differently numerically due solely to rounding errors introduced by exponentials being computed through log/diff trick rather than directly.

Formally, one can write:
Define 
\(u_k= f_k c_{k-1}+ i_k z_k,
v_k= f_k n_{k-1}+ i_k,
w_k=u_k/v_k.\)

Stabilised counterparts: replace each occurrence of \(f_k,i_j,v_j,u_j,n_j,c_j,h_j,... > multiply/divide <by> p_j~=e^{m_j}\).

Since 
\(w'_k=(u'_k)/(v'_k)=u/(p)/v/(p)=u/v=w_k.\)

Thus all outputs match exactly; moreover partial derivatives w.r.t weights depend only on partials of exponentials times inputs which remain identical due to cancellation properties. Explicit derivation shows:
 ∂L/∂θ = ∂L/∂w × ∂w/∂θ   
 ∀θ ∈ {w_i,w_f,w_o,…}

Both ∂w/∂θ computed from stabilized system equals original ∂w/∂θ from raw system because stabiliser contributes no additional Jacobian term; it is absorbed by chain rule cross‐terms that cancel out exactly thanks to symmetric division/multiplication structure above.

Therefore there is theoretical equivalence: forward outputs & gradients are preserved up to floating point discarding errors.

## Implementation Pitfalls (Overflow Handling)

When implementing exponential gating in practice you run into two primary problems:

| Issue | Root Cause | Practical Remedy |
|-------|------------|------------------|
| **Overflow/NaNs** | Very large preactivations → `exp(~large)` → inf or NaN | Use log–domain stabilizer (`m` trick); clip preactivations to safe range before exponentiation if needed |
| **Underflow/Saturation** | Very small preactivations → `exp(~negative huge)` → zero → dying gradient | Keep glottis between `exp(-40)` & `exp(40)` by projecting preactivations; optional use of `softplus` inside exponential enableably shapes curvature |
| **Brittle Normalisation** | Initial normaliser `n_0` zero → division truncation error when first nonzero gate appears late | Initialise `n_0` with small positive constant ε (`10⁻⁶`) or use dynamic start-up scheme that gradually warms up storage |
| **Non-Differentiable Log Sum Max** | Computing `max(log_f+m_prev , log_i)` uses non-differentiable operation → subtle gradient changes | Implement using `torch.logsumexp` or smooth approximation if required by framework; but note many frameworks already support gradual derivative flow across max |

A robust implementation typically relies on after-first-step warmup: store all vectors as double precision until stable shape emerges, then cast back to float32 for speed once internal fluctuations subside grounded in stable values. Furthermore leveraging batched operations or fused kernels eliminates overhead from per-step matrix–matrix multiplications when embedding matrix memories within mLSTM cells.

---

By unshackling memory updates from bounded values and carefully calibrating them via a logarithmic stabiliser plus dynamic normalisation , sLSTM equips recurrent language models with genuine revision capability—an essential ingredient for tasks requiring fine temporal priority such as next-token prediction over extremely long horizons or associating fine-grained key/value pairs across sub‑second real-time streams. This chapter therefore presents not only a formal derivation but also hands-on guidance toward fireproof production deployment for those wishing to lift LSTMs into modern language modelling scales commensurate with transformers while retaining their unique sequential interpretability ‒ precisely what xLSTM aims to achieve.’’

# 4. The sLSTM: Scalar Memory with Mixed Gates and Heads  

The **sLSTM** (scalar‑memory LSTM) is the first of the two expanded designs presented in *xLSTM*.  It keeps the familiar one‑dimensional cell state of a vanilla LSTM but augments it with two deep‑learning innovations:

1. **Exponential gating** – the input and forget gates are allowed to grow exponentially, which gives the network a much larger dynamic range when deciding how much new information should be written into or forgotten from memory.  
2. **Novel memory mixing** – multiple memory cells can be *mixed* with one another through recurrent matrices that act on the hidden state before it is fed back into the next gate computation.  The mixing is head‑wise, meaning that each head can mix across its own cells but not across heads.  

Together, these mechanisms address two central LSTM limitations identified in the paper: the inability to revise long‑term storage decisions and the relative failure at tracking state over long horizons.

The following discussion unpacks each component of sLSTM, explains how it differs from a vanilla LSTM, and demonstrates why those differences matter in practice.

---

## Forward Pass Equations for sLSTM

For a single time step \(t\), an sLSTM receives as input a vector \(\mathbf{x}_t \in \mathbb{R}^{d_{\text{in}}}\) and a hidden state \(\mathbf{h}_{t-1} \in \mathbb{R}^{d_{\text{h}}}\).  Its forward propagation follows Equation (6) of the paper:

\[
\begin{aligned}
c_t &= f_t\, c_{t-1} + i_t\, z_t ,\\
n_t &= f_t\, n_{t-1} + i_t ,\\
h_t &= o_t\, \tilde{h}_t , & \tilde{h}_t &= \frac{c_t}{n_t},
\end{aligned}
\]

where

\[
\begin{aligned}
z_t &= \varphi(\tilde{z}_t),          & \tilde{z}_t &= \mathbf{w}_{z}^\top\mathbf{x}_t + r_z h_{t-1} + b_z ,\\
i_t &= \exp(\tilde{i}_t),           & \tilde{i}_t &= \mathbf{w}_{i}^\top\mathbf{x}_t + r_i h_{t-1} + b_i ,\\
f_t &= \sigma(\tilde{f}_t)\;\textbf{or}\; \exp(\tilde{f}_t), & \tilde{f}_t &= \mathbf{w}_{f}^\top\mathbf{x}_t + r_f h_{t-1} + b_f ,\\
o_t &= \sigma(\tilde{o}_t),           & \tilde{o}_t &= \mathbf{w}_{o}^\top\mathbf{x}_t + r_o h_{t-1} + b_o .
\end{aligned}
\]

All weights \(\mathbf{w}\) are learnable vectors; all \(r\)’s are recurrent weights applied to \(h_{t-1}\).  The scalar cell state \(c_t\) is updated linearly by a **forget gate** \(f_t\) that may now have exponential activation (giving it an upper bound only defined by overflow).  Conversely, an **input gate** \(i_t = e^{\tilde{i}}\) can grow arbitrarily large, allowing it to write an unbounded amount of new information into memory if needed.

The *normalizer* \(n_t\) tracks the cumulative effect of all past forget gates weighted by their corresponding input gates.  By dividing \(c_t\) by \(n_t\), we obtain a *stabilized* memory value that cannot drift to infinity – this is essential for keeping gradients well‑behaved during training.

Because exponentials can cause large values, the paper introduces an additional stabilisation state:

\[
m_t = \max(\log(f_t)+m_{t-1},\, \log(i_t)), 
\]
and then rescales
\(i'_t = e^{\, i_{\text{raw}} - m_t}\) and 
\(f'_t = e^{\, \log(f_{\text{raw}})+m_{t-1}-m_t}\).
This trick guarantees that multiplying an old cell by a huge forget gate does not negate any more recent writes simply because of numerical overflow.

---

## Role of Multiple Heads – Intra‑Head vs Inter‑Head Mixing

An sLSTM can contain more than one scalar cell per time step: let us denote them by indices \(k=1,\dots,K\).  The hidden state therefore becomes a vector
\(h_{t-1}\in\mathbb R^{K d_{\text{s}} }\), where each cell contributes one dimension (possibly followed by more channels if desired).  

To allow information to flow between different cells while preserving modularity, we split them into **heads**.  Suppose there are \(H\) heads and each head owns \(C = K/H\) cells.  Every head operates independently in terms of why memory mixing does not cross head boundaries:

| Mechanism | Internal to Head | Across Heads |
|-----------|------------------|--------------|
| Hidden-to-gate weight application | Yes (e.g., *r* matrices are block diagonal) | No |
| Cell-state mixing | Allowed via recurrent matrices inside each head | Not allowed |

The intuition stems from linguistics: *heads* capture distinct aspects of language (e.g., syntax vs semantics).  With intra‑head mixing we let memories collude within an aspect while guarding against accidental contamination between separate aspects.

Because learning across heads never occurs directly, swapping or permuting whole heads does **not** change any compiled parameter; however, it does change which subset of cells will mix and thereby reshapes local abstractions.  This gives sLSTM a richer expressive power than plain LSTM where every cell mixes uniformly via a dense recurrent matrix.

---

## Memory Mixing via Recurrent Matrices ρ_z,i,f,o

The core of intra‑head mixing lies in four recurrent matrices—one for each component that receives hidden states from the previous step:

* \(R_z^{(h)}\,h_{t-1}\)
* \(R_i^{(h)}\,h_{t-1}\)
* \(R_f^{(h)}\,h_{t-1}\)
* \(R_o^{(h)}\,h_{t-1}\)

Each matrix has dimensions \(C\times C\) and is applied only within its own head.  
This design differs from vanilla LSTMs in two ways:

1. **Dimensionality reduction**: Because sLSTM keeps scalar memory cells (\(c_k^{} \in \mathbb R^0? Actually scalar.\)), we are free to configure very skinny recurrent connections without blowing up parameter count or computational cost.
2. **Structured interaction**: For standard LSTMs all cells mix via one large matrix (\(K\times K\)).  In sLSTM we restrict those mixes; thus nearest neighbors still influence each other but at a controllable rate.

Formally, for head `h` at time `t` we compute

\[
e^{(h)}_z = z_{\text{raw}}^{(h)} + R_z^{(h)} h_{t-1}^{(h)} ,\\
e^{(h)}_i = i_{\text{raw}}^{(h)} + R_i^{(h)} h_{t-1}^{(h)} ,\\
e^{(h)}_f = f_{\text{raw}}^{(h)} + R_f^{(h)} h_{t-1}^{(h)} ,\\
e^{(h)}_o = o_{\text{raw}}^{(h)} + R_o^{(h)} h_{t-1}^{(h)} .
\]
These “mixed” preactivations are then passed through their respective nonlinearities (sigmoid or exponential) as shown above.

Thus, after reading its own hidden context, every cell can reclaim part of its neighbor’s memory carrying great contextual insight—newly created logics such as **state tracking** become achievable because the network can learn “if I see an opening bracket first on this branch, I remember it even when I later see nested brackets in another branch”.

---

## Effect of Permuting Heads on Expressivity

Because heads do not communicate across them directly, permuting heads is essentially relabelling: no learned parameter changes as long as we consistently rearrange both incoming weights and output registers.  However, this permutation preserves local mixing patterns inside each head; so by shuffling which cells belong to which head we effectively rewire how lower–level memories cooperate on a micro level.

From an expressivity angle:

* *No nuance*: If we shuffle heads but keep the same block‑diagonal structure of all recurrent matrices (i.e., each remains same size blocks), expressivity remains unchanged because intra‑head dynamics are invariant under column/row swapping.
* *Potential nuance*: If some heads have special-purpose constraints (say initialization or regularisation), reassigning cells could inadvertently shift those properties between groups.
  
Thus permuting heads is often treated simply as an architectural hyperparameter selection rather than a training decision—once the optimal number of heads is chosen, they can be sorted arbitrarily without changing performance.



---

## Comparison to Vanilla LSTM in Toy Tasks

The paper demonstrates two synthetic tasks that highlight precisely where vanilla LSTMs falter but sLSTMs shine:

| Task | Issue with vanilla LSTM | sLSTM Advantage |
|------|------------------------|--------------------|
| Nearest‑Neighbor Search | Cannot erase wrong matches when an even closer key appears later | Exponential input gate scales up the local match, and exponential forget gate curves back so earlier irrelevant keys vanish |
| Rare Token Prediction | Limited capacity in scalar memory leads to over-generalisation | Multiple heads preserve context-specific traces – rare information sticks longer due to intra‑head mixing |
| State Tracking (Parity) | Depth cannot be represented accurately without explicit reset signals | Exponential gating allows precise scaling of counters; memory mixing preserves “carry” across subspaces |

In each scenario, experiments show that an xLSTM constructed solely from sLSTM blocks achieves near-perfect accuracy on tasks that would otherwise frame row-wise constant errors for standard LSTMs. The key takeaway is that redefining gating dynamics along with restricted yet clever memory interactions lifts recurrent networks from solving only simple sequential problems up into tasks requiring explicit bookkeeping over arbitrarily long horizons.

--- 

To summarise:  
*The sLSTM provides an elegant bridging point between classic LSTMs and modern scalable language models.*  

It enforces controlled dynamic ranges through exponential gates while confining memory interactions to small heads—exactly what modern research needs to maintain stability during billion‑parameter training while still exploiting the full representational power of gated recurrence.

# Chapter 5  
## The mLSTM: Matrix Memory and Covariance Updates for Capacity Scaling  

In this chapter we explore the **Matrix LSTM (mLSTM)**, the core of the extended LSTM (xLSTM) family that dramatically augments storage capacity while preserving the recurrent computational paradigm that makes LSTMs so powerful for sequential reasoning. We trace the lineage of the matrix memory idea through classic associative memories, fast‑weight programmers, and modern linear‑attention mechanisms, all while presenting a rigorous derivation of the **covariance‑update rule** that endows the mLSTM with a principled way to store and retrieve key–value pairs.

---

### 5.1  The Need for a Structured Memory

The classic LSTM stores information in a single scalar (or a small vector) per time step. While this design keeps the recurrence lightweight and guarantees vanishing‑gradient mitigation (through the constant error carousel), it imposes severe limits on how much *structured* information—e.g., pairwise associations between symbols—can be remembered. In natural language, symbolic relations such as “the capital of France is Paris” are easiest expressed as a pair of vectors \((\mathbf{k},\mathbf{v})\) that can later be retrieved by matching a key \(\mathbf{q}\) against stored keys.

Two archetypal models have long exploited *matrix* memories to keep track of such associative relationships:

| **Model** | **Memory Structure** | **Purpose** | **Key Operation** |
|-----------|----------------------|-------------|-------------------|
| Bidirectional Associative Memory (BAM) | Full \(d\times d\) matrix \(\mathbf{M}\) | Store associations \((\mathbf{k},\mathbf{v})\) | Update: \(\mathbf{M}\gets \mathbf{M}+ \mathbf{v}\mathbf{k}^\top\); Retrieve: \(\hat{\mathbf{v}}=\mathbf{M}\mathbf{q}\) |
| Fast Weight Programmer (FWP) | Diagonal or low‑rank \(d\times d\) matrix | Rapidly learn task‑specific weights in a single forward pass | Update: \(\Delta\mathbf{W} = \eta\, \langle\text{output,error}\rangle \otimes \langle\text{hidden,input}\rangle\) |
| Linear Attention (LA) | A sequence‑wise \(d\times d\) convolution over key–value pairs | Remove quadratic token–token interactions while retaining multiplicative pairwise scoring | Score: \(\langle\mathbf{q},\mathbf{K}\rangle = \mathbf{q}\cdot (\sum_i \alpha_i \mathbf{k}_i)\) |

The mLSTM adopts a *hybrid* view: it treats its memory as a full, trainable matrix that is updated by *covariance* increments derived from incoming key/value pairs. This mirrors how BAMs store associations but incorporates modern deep‐learning techniques (e.g., trainable query/key/value projections, gating, layer normalization). Crucially, because updates are additive and no parameters are stored inside the memory itself, the size of the memory decouples from network depth; instead, it scales with the dimensionality \(d\).  

---

### 5.2  From Scalar to Matrix Memory

Consider a scalar LSTM cell whose state evolves as
\[
c_t = f_t\,c_{t-1} + i_t\,z_t.
\]
Here \(f_t,i_t,z_t\in(0,1]\) are learned gates controlling forgetting, insertion, and content respectively; \(z_t=\varphi(\tilde z_t)\) projects the current input into an internal representation.

The mLSTM lifts this equation into linear algebra:

1. **State Representation**  
   The cell state becomes a square matrix:
   \[
   \boxed{\;\mathbf{C}_t,\;\;\;\;\;\;\;  t=0,\dots,T,\qquad  \mathbf{C}_t\in\mathbb R^{d\times d}}\tag{5.1}
   \]
   In contrast to scalar \(c_t\), this structure permits *pairwise inner products* between keys and values.

2. **Key / Value Generation**  
   Each input token \(x_t\in\mathbb R^{e}\) is projected into three vectors:
   - **Query:** \( \displaystyle  \mathbf{q}_t = W_q\,x_t + b_q           \quad (\mathbb R^{d})  \)
   - **Key:**  \(   k_t   = W_k\,x_t + b_k            \quad (\mathbb R^{d})  \)
   - **Value:** \( v_t   = W_v\,x_t + b_v            \quad (\mathbb R^{d})  \)

3. **Update Rule**  
   The mLSTM retains the classic constant‑error carousel idea:
   \[
   \boxed{\;\; 
          f_t\,\underbrace{\bigl(\sum_{i<s}v_i k_i^\top\bigr)}
                 _{\textstyle :=\,K^\top V}
        + i_t\, v_{t}k_{t}^\top
          = K^\top V + X_{t}
        , 
          }\tag{5.2}
   \]
   where 
        \(X_{t}= v_{t}k_{t}^{\top}\).
   
    Expanding this in terms of *covariance* gives
    if we assume zero‑mean input embeddings after layer norm,
    then
    \[
    X_{t}= v_{t}k_{t}^{T}
         = E[v\,k^T] - E[v]E[k]^T
    ,      % not strictly needed but notionally
    ```
    
    thus Xₜ is exactly an instantaneous outer product – i.e., an estimate of the cross‑covariance between value and key at time \(t.\)

4. **Gating Forms**  
   The gates control how rapidly old information decays and new associations are written:
   - Forget gate controls decay rate:   
     \( f_t=1-2^{-g_f} = e^{-\tilde f_t}\), so large $\tilde f$ → fast forgetting.
   - Input gate controls learning rate:   
     \( i_t=e^{+\tilde i_t}.\)
     
     Because both gates are exponential‑activated (rather than sigmoid), they can span many orders of magnitude without saturating – making learning under long‑range dependencies more robust (as detailed in Section 6).

5. **Retrieval via Query Multiplication**  
   After the update step we wish to produce an output vector that reflects all stored associations relevant to the current query:
   \[
     {\color{blue}
      h_t = o_t\,{\odot}
           {\underbrace{\frac{\mathtt{%poly}}%
                     {\max(|n_{t}^{T}q_{t}|,\;1)} }_{\textstyle q/C}}
	         {\color{blue}
	          C_{t}\,\underbrace{q}_{u}}.
      }\tag{5.3}
   Here:
     * $o_t$ is a learnable output gate ($o_t=\sigma(\tilde o_t)$).
     * $\odot$ denotes element‑wise multiplication.
     * $C_{t}\, q$ computes inner products between $q$ and every column of $C$, effectively scoring each stored value against $q$.
     
     Division by $\max(|n^T q|,1)$ normalizes against accumulated key energy – analogous to scaling in transformer attention where $\sqrt d$ regularizes dot products.

---

### 5.3  The Covariance–Update Rule: Derivation & Interpretation

For clarity let us derive (5.2) as an explicit covariance update between keys and values.

Suppose at time step $s$ we have stored
\(V_s=[v_1,\dots,v_s]\in\mathbb R^{d\times s},
    K_s=[k_1,\dots,k_s]\in\mathbb R^{d\times s}\).
The empirical cross‑covariance matrix after $s$ steps reads
\[ 
C_s = V_s K_s^\top .
\tag{5.4}
\]

Next observation adds $(v_{s+1}, k_{s+1})$. The updated covariances become

\[
C_{s+1}=V_s K_s^\top + v_{s+1}k_{s+1}^{\top}.
          % If forgetting is applied:
       =(f_{s+1}) C_s + i_{s+1}(v_{s+1}k_{s+1}^{T}),
          % but usually we apply decay on whole state:
          % f*C_s adds weighted previous plus new contribution.
          
       %= C_s + v(k)^T if f=1 & i=1.
       % In practice we set f<1 or i<0 etc.
       % So final recurrency in Eq.(5.2)
This exactly matches Eq.(5.2).  

Why add an outer product? Because each outer product increment encodes *paired evidence*: it augments counts for any query that will align with both a future key and its associated value simultaneously—precisely what associative recall requires.

If one views it through the lens of associative memories:

- In BAM you write $\hat C = C + v k^T$ at each step; retrieving $u^T M u'$ will give you interactions among all stored pairs simultaneously—an NP‐hard operation unless you keep explicit keys/values.
- In Fast Weight Programmers you similarly accumulate outer products during training; during inference they serve as temporary weights that encode quickly learned patterns.

The mLSTM builds on these ideas but ensures that updates happen inside a gated recurrent node that still interacts with token embeddings—making it ubiquitous across aircraft natural language tasks.

---

### 5.4  Practical Implementation Notes

#### 5.4.1 Normalization & Stability  
Because we are adding potentially huge matrices ($d\times d$), overflow can become problematic if gates grow unboundedly—indeed exponential gates can exceed $10^6$. We therefore introduce a *normalizer* vector $\boldsymbol n_t$, analogous to equation (4):

```
n̂ _ t  ← H(f̂ _ t , n̂ _ {t−1}, î _ t )
```

In practice this normalizer keeps track of cumulative “attention mass” contributed by past keys and dampens effects that would otherwise destabilize gradients or numerical overflow.

#### 5.4.2 Complexity Overheads  
While memory scaling remains linear in sequence length ($O(T)$), each time step incurs:

- An outer‑product update $v_k^\top k$: $O(d^2)$ operations.
- A matrix–vector multiplication during retrieval: $O(d^2)$.

Because modern GPUs excel at batched GEMM operations, these costs largely overlap across tokens when using parallel tactics like FlashAttention or GLA style scan primitives.

#### 5.4.3 Parallelization Strategy  
Unlike conventional LSTMs which rely on hidden‑to‑hidden recurrence (requiring dynamic programming over sequence length), mLSTM’s recurrence only involves decaying its own matrix memory via $f_t$. This decay can be effected using an efficient prefix‐sum scan over time:

```python
# pseudo-parallel code skeleton
mem_state = zeros((B,D,D))               # batch × dim × dim
for t in range(T):                       # serial loop only for gating
    inp_q = Wx_q(x[t])                   # query embedding
    inp_k = Wx_k(x[t])                   # key embedding
    inp_v = Wx_v(x[t])                   # value embedding

    mem_state = f[t] @ mem_state         # decay (batch matmul)
    mem_state += exp(i[t]) @ outer(inp_v,i(t))  # insert

# After loop: mem_state ready for retrieval per last query or stack
```

Because each scan step forms just one batch matmul per time step (`matmul` cost ~$(d^2$)), we can process sequences tens of thousands long twice as swiftly as pure recurrent models with hidden mixing.

---

### 5.5 Connecting to Modern Linear Attention

Linear attention mechanisms aim to avoid full softmax over pairwise token scores—which requires $\mathcal O(T^2)$ memory—by using kernel tricks or low‐rank approximations—yielding linear complexity while approximating dot‑product attention:

- **Kernel-feature maps** compute $\phi(q)\phi(k)^T$ cheaply across tokens;
- **Locality-sensitive hashing** partitions queries/keys;
- **Buffer-based Approaches** treat past keys/values as rows in a buffer.

mLSTM differs subtly but importantly:

- It does not approximate dot‐products via kernels; instead it stores raw outer products explicitly.
- When retrieving with query $q$, it effectively sums over all past `value × key` contributions,
  which is equivalent mathematically to computing  
  $\sum_i v_i\sigma(q^\top k_i)$ when each gate exponentiates into $\exp(\tilde{i})$ analogous to softmax temperature τ→0.

Hence,mLSTMs embody *implicit linear attention*: they explicitly learn which associational patterns matter by adjusting `i` and `f` gates per step, thereby dynamically controlling capacity trade‑offs—a feature absent in most existing linear attention methods that rely on fixed kernel functions or static cache sizes.

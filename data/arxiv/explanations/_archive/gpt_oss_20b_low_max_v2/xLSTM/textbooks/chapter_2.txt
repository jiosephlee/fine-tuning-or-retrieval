\title{A Textbook about the Paper: "xLSTM: Extended Long Short-Term Memory"}

Chapter 2: # 2. Shortcomings of Classical LSTMs in Modern Contexts  

Long Short‑Term Memory (LSTM) networks were a breakthrough in the early 1990s, solving the vanishing‑gradient problem by adding a cell state that can be updated additively and gated. They became a workhorse for language generation, sequence‑to‑sequence translation, handwriting synthesis and many other sequence‑related tasks. Despite their practical success, classical LSTMs exhibit three fundamental weaknesses that become especially critical when they are pushed to the scale of modern large language models (LLMs). This chapter dissects each weakness in detail, demonstrates it with concrete synthetic experiments introduced in the paper *xLSTM: Extended Long Short-Term Memory*, and shows why transformers are able to circumvent these limitations.

The three limitations are:

1. **Inability to revise storage decisions** – once information has been stored, the original LSTM cannot overwrite it with a more relevant piece later in the stream.
2. **Limited storage capacity** – each cell stores a scalar that forces the network to compress all useful information into a single number per dimension.
3. **Sequential dependency (memory mixing)** – hidden‑to‑hidden recurrence enforces token‑wise serial processing that prevents efficient parallel computation.

We now explain each point formally and illustrate the shortcoming with an adversarial task.

## Task 1: Nearest‑Neighbor Search – error analysis  

### The problem formulation  

Consider a streaming sequence of vectors \(x_1, x_2, \dots ,x_T \in \mathbb{R}^d\) and an additional query vector \(q_{\text{last}}\) presented at time step \(T\). The task is to output the index \(t^* < T\) (or the value paired with \(x_{t^*}\)) of the vector in the past that is **nearest** to \(q_{\text{last}}\) under Euclidean distance:
\[
t^\ast = \arg\min_{t < T} \|x_t - q_{\text{last}}\|_2 .
\]
The environment gives feedback only at time \(T\); during processing each timestep \(t\) we can only observe \(x_t\), not the future query. This setting probes whether an RNN can *remember* a previously seen vector until a comparison arrives.

### Why a scalar cell struggles  

In a vanilla LSTM each dimension of the hidden state carries essentially one scalar memory value synchronized via additive recurrence:
\[
c_t = f_t c_{t-1} + i_t z_t,
\]
with forget gate \(f_t \in (0,1)\), input gate \(i_t \ge 0\), and transformed input \(z_t = \varphi(\tilde{z}_t)\). The scalar update rule implicitly assumes that *the entire relevant context can be represented by a single number per dimension*. If two distinct vectors have identical scalar compositions but different directional cues relative to future queries, no gating strategy can distinguish them at inference time. Once an earlier vector has been written to memory—when its corresponding gates are active—the *constant error carousel* will hold onto it unless all its memories are decayed by future forget gates. However, because forgetting is gradual (via multiplication by the forget gate), an LSTM is forced to remember any strong memory for many steps unless it explicitly decides to collapse it early.

In practice this manifests as **error accumulation**: early vectors “contaminate” later states and prevent later retrievals from updating them. Figure~X.X in the original paper (referenced as Fig.~2 left panel) plots mean-squared error versus sequence length for this task: the red line corresponds to xLSTM (exponential gating + normalizer), whereas the blue line marks vanilla LSTM performance. As soon as the network is required to overwrite an earlier stored key with a closer match, vanilla LSTM’s error grows linearly with distance from the current timestep, because its gates cannot perform an abrupt overwriting operation – they can only attenuate or preserve content via smooth multiplication.

### xLSTM’s remedy – exponential gating  

xLSTM addresses this defect by allowing gates whose activations grow or shrink *exponentially* instead of sigmoidly:
\[
i_t = \exp(\tilde{i}_t), \qquad f_t = 
   \begin{cases}
       \sigma(\tilde{f}_t) & \text{(sigmoid branch)}\\[4pt]
       \exp(\tilde{f}_t)  & \text{(exponential branch)}
   \end{cases}.
\]
Exponentially large values give gates very sharp transition behavior: an input gate can almost fully “consume” new content while a forget gate can almost instantaneously suppress previously memorized data if future gates dictate so. In addition, xLSTM keeps track of a normalizer state
\(n_t = f_t n_{t-1} + i_t\),
which normalizes cell content before producing hidden output:
\(h_t = o_t \cdot c_t / n_t.\)
This normalization explicitly tracks how many “effective reads” have happened so far, enabling precise control when overwriting occurs.

Empirically, substituting plain sigmoid gates with exponential ones reduces nearest‑neighbor retrieval error by up to 30 % when evaluated on synthetic data sets up to 10 k time‑steps long—substantially narrowing the gap between learning curves of classic LSTMs and xLSTMs (Fig.~2).

## Task 2: Rare Token Perplexity – capacity limits  

### The experimental setting  

Rare token perplexity is measured on Wikitext‑103 after training a language model that predicts tokens sequentially. Tokens are binned according to their frequency in training data: common tokens occupy one bin, extremely rare tokens belong to another bin. The perplexity for each bin reveals how well the model knows rarely seen symbols during inference.

### The theoretical limitation induced by scalar cells  

An LSTM with hidden dimension \(d\) stores its memory as \(c \in \mathbb{R}^d\), updated elementwise via Eq.(1). Each scalar entry is essentially a *compressed proxy* for arbitrarily complex sequences—it must simultaneously encode rich structural patterns (syntactic roles, entity tracking), word meaning, positional bias as well as adapt dynamically over time. Compressing semantic history into these few scalars leads necessarily to lossy representations; rare tokens pose a high compression burden because they carry high information content relative to their frequency.

To quantify this phenomenon we look at perplexity curves versus cut-groups—figures in Section §5 reveal that for rare token bins perplexity drops gradually but remains significantly higher than for common bins when using vanilla LSTM (\(d=2048\)). Each additional dimension contributes only linearly to representational capacity because updates aggregate additively; there is no multiplicative interaction pattern that could afford combinatorial explosion like self-attention’s dot-product mechanism.

### Why matrices help – mLSTM

The paper introduces *mLSTM*, which replaces each scalar cell with a full matrix
\(\mathbf{C}_t \in \mathbb{R}^{d\times d}\).
A key/value pair
\(k_t,v_t \in \mathbb{R}^d\)
is written via covariance update:
\[
\mathbf{C}_t = f_t\,\mathbf{C}_{t-1}
              + i_t\, v_t k^\top _t .
\]
Retrieval at time step \(t'\) requires only
\( h_{t'}=\mathbf{o}_{t'} 
            (\mathbf{C}_{t'} q_{t'} / n_{t'})
         , 
      n_{t'}= f_{t'} n_{t'-1}+i_{t'} k_{t'}
   ,
   q_{t'}=\mathbf W_q\,x_{t'}, 
    n_{0}=0 .
  \)
Mathematically this equivalent baseline is precisely Fast Weight Programmers expanded by gating. Crucially, storing outer products allows **quadratic growth** of representation capacity with respect to embedding width while maintaining linear parameter count. The mLSTM thus folds more fine-grained semantics into its memory matrix; empirically its rare token perplexity drops below that of vanilla LSTMs by ∼10–15 %, achieving performance comparable to transformers on these tasks (Fig.~3).

## The role of scalar cells in compression  

Scalar cells force every past event into one value per channel; even if noise or irrelevant history drifts inward through small forget gates, there is no way for multiple unrelated entities to co-exist without interfering unless states saturate or are overwritten sharply (exponential gating). In contrast:

- **Transformer attention** uses all past tokens simultaneously through dot‑product similarity; every token contributes independently.
- **State‐Space Models** use linear transforms that maintain orthogonality and project through dynamical systems.
- **xLSTM’s mLSTM** stores full correlation among keys/values.

Thus LSTMs’ memory acts like a highly compressed buffer where all shape information must be distilled into one number per neuron, leading invariably to information bottlenecks for complex or long‐range phenomena such as rare words or subtle context dependencies.

## Sequential dependency and memory mixing bottleneck  

Apart from storage depth problems, classic LSTMs suffer from architectural recursion:

- At each step hidden state updates depend on previous hidden state:
  \(h_t = o_t\, g(c_t).\)
- Gating parameters typically involve recurrent weight matrices that mix outputs across dimensions:
  left parts “memory mixing” where output from one time step influences next cell’s hidden representation via recurrent terms
  \( r_z h_{t-1}, r_i h_{t-1}, ….\)

This recurrence forbids parallel execution over multiple timesteps because each update needs all completed preceding values (\(h_{t-1}\)). Even though gradient computation uses backpropagation through time (BPTT), inference time remains inherently sequential. With sequence lengths extending into tens or hundreds of thousands—a common scenario in contemporary text generation—the wall‑clock latency skyrockets; moreover GPU stalls due to irregular memory access patterns may arise.

The transformer architecture bypasses this bottleneck: all self‑attention weights are computed jointly using matrix multiplications; queries/keys/values for every token can be processed simultaneously after basic “up‑projection” transformations. State‐space models also avoid explicit pairwise computations between successive states; rather they leverage linear dynamical systems whose matrices can be simultaneously diagonalized or block‐simplified for parallel operations.

---

## Why Transformers can bypass these limits  

Transformers address these deficits in three ways:

1. **Sparse/history-aware rewritability:** Self-attention from scratch reuses “soft max” weighting where any new query can downweight previous key/value pairs arbitrarily fast—as opposed to an additive decay channel controlled gradually.
2. **High-dimensional linear combinations:** With continued residual projections (\(W_Q/K/W_V/W_O)\), transformers essentially operate in high dimensional space where repeated linear combinations increase expressive capacity without compressing everything into scalars.
3. **Implicit parallelization:** All token interactions involve only matrix multiplications; there is no iterative recurrence constraint across positions after projection from queries/keys/values.

When scaled mid-billions parameters and trained on large corpora (\(15–300~B\) tokens), transformer models achieve lower perplexities than even well-tuned repeated-LSTMs thanks mainly to these mechanisms.

The extended xLSTM architecture tries again at pushing classical RNNs forward: it brings exponentiation-based gating—giving hard throttle control—and enriched memory structures—turning scalars into full covariance matrices—so as much capacity as possible bears within its usual sequential framework. Experimental results across synthetic tests such as nearest-neighbor recall, associative recall and long-range language modeling summarise how close xLSTMs come toward transformer-level performance while retaining strictly linear computational complexity w.r.t context length—a compelling trade-off highlighted throughout subsequent sections of this book.

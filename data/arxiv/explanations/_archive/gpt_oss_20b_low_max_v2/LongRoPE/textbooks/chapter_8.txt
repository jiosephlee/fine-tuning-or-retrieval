\title{A Textbook about the Paper: "LongRoPE: Extending LLM Context Window Beyond 2 Million Tokens"}

Chapter 8: # 8. Experimental Setup & Baselines

In this chapter we describe in detail the experimental environment used to evaluate LongRoPE, including the models, datasets, training schedules, hyper‑parameters, and the baseline methods against which we made comparisons. All experiments were conducted on a cluster of Nvidia A100 GPUs (80 GB per device) using PyTorch 2.0 and the HuggingFace 🤗 Transformers library. Each figure of substantial measurement (e.g., perplexity curves, passkey accuracy) comes from five independent runs whose reported values are the averages; the standard deviation is below 2 % in all cases.

---

## 8.1 Models

We evaluated two state‑of‑the‐art base models that use Rotary Position Embedding (RoPE):

| Model | Size | Dimensionality $d$ | Parameters |
|-------|------|-------------------|------------|
| **LLaMA2‑7B** | 7 B | 8192 | 7 B |
| **Mistral‑7B** | 7 B | 7680 | 7 B |

Both models were taken from the official HuggingFace checkpoints and preserved exactly their original architectures. The only change introduced by LongRoPE is a set of rescale factors applied to the RoPE angles as described in Section 4.

---

## 8.2 Datasets

### 8.2.1 Language‑modeling corpora  
These corpora consist of long‑form text useful for measuring perplexity at various context lengths.

| Dataset | Source | Size (tokens) | Typical Sequences |
|---------|--------|----------------|-------------------|
| **PG19** – Pile/GPT‑19 subset | Project Gutenberg & Pile‑Books3 | ~200 M tokens | Documents ranging from 10\,k to >200\,k tokens |
| **Proof‑pile** – Large proof datasets – used for passkey tests and long perplexity measurements | Verified mathematical proofs extracted from Pile | ~100 M tokens | Continuous sequences >128 k tokens |
| **Books3** – Full Pile-Books3 (random books) | Pile corpus of books | ~5 B tokens | Random books over 2 M tokens each |

For length evaluations we split each document into contiguous chunks of length **256** token steps with an overlap equal to the window size; this sliding‑window technique yields many synthetic sequences per document while ensuring that each test sample contains a fully correct context.

### 8.2.2 Short benchmark sets  
To evaluate whether extending the context damages performance on tasks originally designed for a 4k window we use:

* **ARC‑Challenge** – multi–choice science questions with *25* shots
* **HellaSwag** – future‑prediction question answering with *10* shots
* **MMLU** – multi‑task language understanding across *5* shots
* **TruthfulQA** – open‑ended factual questions *zero* shots

All these benchmarks are obtained from the HuggingFace leaderboard API.

---

## 8.3 Preprocessing

All datasets are tokenised with the native tokenizer of the corresponding base model (the LLaMA2 or Mistral BPE vocab).  
Tokenisation parameters:

- `truncation=False`
- `padding=False`

For training sequences longer than the maximum length $L'$ used for fine‑tuning, we split them into contiguous blocks of length $L'$ with an overlap of one token to preserve positional consistency across blocks.

---

## 8.4 Fine‑tuning Procedure

Fine‐tuning LLaMA2 and Mistral to longer contexts was performed in two phases:

1. **Phase A (±128k)**  
   • Optimizer: AdamW  
   • Learning rate: $2\times10^{-5}$ for LLaMA2; $1\times10^{-6}$ for Mistral  
   • Warmup: linear over 0–200 steps (both models)  
   • Batch size: global B = 32 (LLaMA2), B = 64 (Mistral)  
   • Tokeniser batches: *12 k* tokens per step to keep GPU memory at ≤70% capacity  
   • Steps: $400$ iterations  

2. **Phase B (+256k)**  
   • Same hyper‐parameters as Phase A except learning rate decayed linearly to zero over entire schedule  
   • Steps: additional $600$ iterations after swapping in the new rescale factors for a target length of $256\,k$

The interface used by LongRoPE to modify RoPE is via a simple wrapper that multiplies each rotary angle by $\lambda_i$ before calling `torch.nn.functional.rope`. The wrapper is agnostic to model implementation and keeps all other hyper‐parameters untouched.

Fine‑tuning was performed with mixed precision (`bfloat16`) on A100 GPUs and relied on ZeRO‑Stage 3 `torch.distributed` to keep memory overhead below 35 GB per device.

## 8.5 Hyper\!–parameter Settings for Search

The evolutionary search employed in Section 4 took place over a population size $P=64$ except when targeting windows >512k where $P=32$.  
The key settings are listed in Table 13 below.

| Setting            | Value                                               |
|--------------------|-----------------------------------------------------|
| Population size ($P$)          | 64 (or 32 if $>512$k)                        |
| Mutation size ($N_1$)           | 16                                               |
| Crossover size ($N_2$)          | 16                                               |
| Mutation probability ($p$)      | 0.3                                               |
| Max iterations ($\mathcal{T}$)    | 40                                                |
| Top-k for elite population     | $\phi=32$                                      |

Perplexity evaluation on the search population required generating predictions on five text snippets from PG19/Pile-Books3 and computing cross-entropy loss with standard softmax temperature set to $\tau=1$.  

The search is run until convergence or until $\mathcal{T}$ iterations are exhausted; empirical results show that perplexity typically plateaus after iteration~25.

## 8.6 Baseline Methods

The following “baseline” methods were included so that LongRoPE’s performance can be benchmarked against existing context extension techniques that have been published or released on GitHub:

### PI (Position Interpolation)

Linear scaling of all Rotary angles by a factor $\lambda = s$, where $s=L'/L$. Implementation follows `rope.py` in HuggingFace’s `transformers` repository, simply adding an overall scaling factor before cosine/sine calculation.

### NTK\(^{2}\)

Scaling factor computed per dimension according to Dynamic NTK:
$$
\lambda_i = s^{i/(d/2-1)}.
$$
This retains lower-frequency dimensions under stronger interpolation while allowing higher-frequency dimensions to be less compressed.

### YaRN\(^{2}\)

Three groups of dimensions (low, middle, high frequency). Low dimensions use linear interpolation $\lambda=s$, middle use NTK scaling as above, high frequencies have $\lambda=1$.  

### Code LLaMA

Fine-tuned LLaMA models trained with a severely increased base value ($\theta=10^6$), providing ~\,100k context extension without further interpolation tricks.

### LongLoRA

Greedy low-rank adaptation that replaces repeating attention patterns with a learned latent memory module during training; they provide checkpoints trained up to 100k tokens, adapted here by reusing their exact weight modifications because they already contain RoPE rescaling at $\sqrt{L'}$ rate.

### Others

A select set of large context models released by open-source communities were also tested: Together-32k, Code LLaMA-200k, etc., but these were excluded from quantitative comparison as they employed image-attention or external-memory modules beyond pure RoPE manipulation.

All baselines were reimplemented in our environment except those available publicly as HuggingFace “model cards”; we downloaded those checkpoints directly and performed inference only—no retraining was done for fairness.

## 8.7 Evaluation Metrics

Perplexity ($\mathsf{PP}$) is calculated as:
$$
\mathsf{PP} = \exp\left( \frac{1}{N}\sum_{i=1}^{N} -\log p(y_i \mid y_{<i}) \right),
$$
where $N$ is token count in the sampled documents and $p(y_i|\cdot)$ is softmax probability under temperature $\tau=1$.  

Passkey retrieval accuracy is defined as fraction of runs where the model generates the exact five-digit key after being prompted with random location positions; each run has ten independent trials.

Benchmarks use standard HuggingFace metrics (accuracy for multiple choice, EM for open-ended tasks).

## Summary

With this configuration we achieve:

* Extension up to **2048k** tokens for both LLaMA2‑7B and Mistral‑7B using only ~1100 fine-tuning steps.
* Perplexity comparable or better than state-of-the-art baselines over every evaluated window.
* Retained performance on short-context benchmarks within less than ±5% drop relative to original checkpoints.

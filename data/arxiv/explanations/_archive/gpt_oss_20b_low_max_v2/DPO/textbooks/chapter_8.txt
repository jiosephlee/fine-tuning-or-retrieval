\title{A Textbook about the Paper: "Direct Preference Optimization: Your Language Model is Secretly a Reward Model"}

Chapter 8: # 8. Empirical Evaluation Setup

In this chapter we describe in depth the experimental framework that underpins the empirical claims of Direct Preference Optimization (DPO).  The evaluation proceeds along three distinct, representative text‑generation tasks: controlled sentiment generation, summarization, and single‑turn dialogue.  For each task we explain how the underlying data are constructed, how preference pairs are obtained, which baselines are compared, and which metrics are used to judge performance.  Because the vast majority of the tasks involve learning from *relative* human judgments rather than absolute reward signals, it is essential to formalise the terminology for preferences and the associated probability models (in particular the Bradley–Terry formulation) before describing any training procedure.  We then describe the implementation details that bridge theory and practice: choice of reference policy, conditioning on prompts, sampling regimes and hyper‑parameter sweeps.  Finally we delineate how ground‑truth rewards or proxy evaluators (GPT‑4) are used to quantify model quality and confirm that those proxies agree with human judgments.

The chapters below follow a textbook style: each section begins with an intuitive explanation, followed by formal definitions, equations in LaTeX as requested and then a discussion of practical implications.  Readers will find concrete tables and figures referenced from the original article; where these were not available, we reproduce or approximate them in paragraph form.

## Controlled Sentiment Generation – IMDb Reviews

### Task Setup  
The controlled‑sentiment task is purposely designed as a *closed‑loop* experiment in which the true reward function is known in advance.  The dataset consists of movie review snippets taken from the Internet Movie Database (IMDB) \citep{maas-EtAl:2011:ACL-HLT2011}.  For each review fragment \(x\), a language model proposes two distinct continuations \(y_1\) and \(y_2\) which are subsequently evaluated by an off‑the‑shelf sentiment classifier trained on IMDB reviews.  The classifier outputs a score \(p(\text{positive}\mid x,y)\).  By construction,
\[
y_w \succ y_l \mid x
\quad \Longleftrightarrow \quad
p(\text{positive}\mid x,y_w) > p(\text{positive}\mid x,y_l).
\]
Thus the preference pair encodes an *absolute* utility value rather than a mere ranking; however we deliberately treat it as a paired preference so that DPO can be tested under identical circumstances to its intended deployment.

### Reward–KL Frontier Analysis  
Because every preference pair comes with an explicit ground‑truth reward,
\[
r^\ast(x,y) = s_{\text{sent}}(x,y) - \bar{s}_{\text{sent}}(x),
\]
where \(s_{\text{sent}}\) denotes the classifier’s probability of “positive” and \(\bar{s}_{\text{sent}}\) is a per‑prefix normalization constant chosen such that downstream KL regularisation behaves predictably.
The DPO objective (Section 5.1, Equation (11)) seeks to maximise \(\mathbb{E}[r^\ast]\) while limiting the KL divergence between the fine‑tuned policy \(\pi_\theta\) and its reference policy \(\pi_{\text{ref}}=\pi^{\mathrm{SFT}}\).  

To quantify this trade‑off we produce *frontiers* by varying either:
- PPO’s target KL budget \(K_\mathrm{PPO}\in\{3,6,9,12\}\),
- DPO’s inverse temperature style parameter \(\beta\in\{0.05,0.10,1,5\}\),
- Unlikelihood optimisation weight \(\alpha\in\{0.05,0.10,0.5,1\}\).

For each hyperparameter combination we run 22 independent training trials (different random seeds or gradient initialisations).  Every 100 update steps we evaluate on an held‑out test set of IMDB prefixes:
- compute mean reward \(E_{x}[r^\ast(x,\hat y)]\), where \(\hat y=\argmax_y \pi_\theta(y|x)\),
- compute sequence–level KL:
  \[
  D_{\mathrm{KL}}\bigl( \pi_\theta(\cdot|x)\,\|\, \pi_{\mathrm{ref}}(\cdot|x)\bigr) = 
      \sum_{t=1}^{T} 
      \mathbb{E}_{y_{1:t} \sim \pi_\theta}\!\!\left[
          D_{\mathrm{KL}}\bigl(
              \pi_\theta(\cdot | y_{<t}x)\,\|\, 
              \pi_{\mathrm{ref}}(\cdot | y_{<t}x)
          )
      \right],
  \]
where \(T\) is sequence length.

Plotting reward vs KL yields *reward–KL frontiers*: each point corresponds to one trial at one time step; higher points dominate lower points if they achieve both higher reward *and* less KL divergence.  
**Result**: DPO’s frontier consistently outperforms PPO even when PPO uses oracle rewards (PPO-GT).  DPO reaches higher rewards for any given KL budget without requiring actor–critic learning or explicit environment rollouts.

## Summarization – Reddit TL;DR Dataset

### Data Acquisition  
The Reddit TL;DR corpus consists of forum posts paired with human‑written summaries produced on Reddit’s “TL;DR” subreddit.  Each post \(x=\texttt{[post]}\) can be followed by multiple crowd–sourced preferences: two candidate summaries \(y_1\), \(y_2\) generated synthetically by an auxiliary LM (typically GPT-J or CF7 transformer), then judged by humans who indicate which summary better conveys salient content.

These preferences are stored as tuples
\[
(x^{(i)},\,y_w^{(i)},\,y_l^{(i)}),
   i=1,\dots,N,
   N\simeq17\,000.
\]
Because there is no clean access to an *oracle* true reward function in this domain, evaluation must rely either on proxy scorers (ROUGE/F1 against reference summarizations) or on **automated judge** pipelines like GPT‑4.

### Reference Policy  
The baseline for all preference learning experiments is an *instruction‑fine‐tuned* GPT\-2 model trained on expertly written forum summaries (the publicly available “OpenAI summarise TL;DR SFT” checkpoint).  This serves as both:
- a starting point for subsequent fine‑tuning,
- and as the **reference policy** \(\pi_{\text{ref}}\).

In practice DPO never needs to reconstruct this policy—it simply takes its logits as a teacher.

### Training Procedure  
For every preference pair we compute
the log probabilities of both completions under:
- current policy under training $\pi_\theta$,
- reference policy $\pi_{\text{ref}}$.
The DPO loss,
eqn (11):
\[
L_{\mathrm{DPO}} =
-\frac1{|D|}
   \sum_{i=1}^{N}\!
     {\log\sigma
       {\Bigl(
         /* log odds difference*/
         &\,\,b=
          +\,\beta\,{\log}
             {\frac{\pi_\theta(y_w^{(i)}|x^{(i)})}
                 {\pi_{\text{ref}}(y_w^{(i)}|x^{(i)})}}
          -\,      {
             +\,\beta\,{\log}
             {\frac{\pi_\theta(y_l^{(i)}|x^{(i)})}
                 {\pi_{\text{ref}}(y_l^{(i)}|x^{(i)})}}
           )}
     {\Bigr)}
     .
}
\]
A single cross‑entropy step suffices—no RL sampling loop is needed.



#### Baselines  

| Baseline | How It Works |
|---|---|
| Zero–shot prompting | GPT-J / Pythia without any fine tuning |
| Preferred–FT | Fine‑tune SFT model on only proxy preferred answers |
| Unlikelihood (α) | Minimise log prob of dispreferred answer; α balances comp.&risk |
| PPO + Reward Model | Standard RLHF pipeline; train reward network via Bradley–Terry |
| PPO-GT | Same but oracle reward used instead of learned one |
| Best of N | Sample N continuations from SFT; pick max‐scoring according to learned reward |

Training for all methods uses identical optimisation hyperparameters except where mentioned (*e.g.* PPO learning rate schedule).

## Single–Turn Dialogue – Anthropic Helpful & Harmless Dataset

### Data Structure  
Each example comprises a user query \(q_s = x\), followed by two assistant responses generated from some large LM (not publicly known).  Human annotators identify which response aligns better with intended safety / helpfulness properties.  
The dataset contains roughly \(170\,000\dots200\,000\) such pairs – enough to fit a full language model.

### Reference Policy Construction  
Because no instructive SFT checkpoint exists for this domain we construct one procedurally:
1. Collect all preferred responses from training triples.
2. Fine‑tune a vanilla Pythia‐2.8B model on these single demonstrations (each response treated as a demo).
3. Treat this resulting checkpoint as $\pi_{\mathrm{ref}}$ during later passes of DPO / PPO.

The hope is that $\pi_{\mathrm{ref}}$ will have similar output space distributional properties as $\pi_{\theta}$ once trained on preferences.

### Training Variables  
Both DPO and PPO proceed analogously to summarisation but over user query prompts rather than forum posts:
- _Policy sampling_: For each prompt $x$, draw two completions $y_1$, $y_2$ from $\pi_{\text{ref}}$, produce label $y_w$/$y_l$ via human ratings.
- _Loss_: same binary cross entropy formula but with new $\beta$ values tuned over $\{0.01,\dots,.5,\dots .8,\dots .9999,\dots .99999,\dots .9999999,\dots .99999999.\}$

## Evaluation Criteria

All evaluation metrics are described below in terms of their mathematical definition and interpretability.

### True Reward Utility & KL Divergence  

Given any policy $\pi$, the *expected true reward* seen during inference is
$$
U(\pi)
= 
\E_{x,y}\!\!\left[ r^\ast(x,y)\right],
$$
where $(x,y)$ proceeds through policy dynamics ($y_t|\!-\approx y_t|\!\sim ...$).

The *sequence‐level Kullback–Leibler* divergence relative to reference policy sums per-token divergences:
$$
D_\mathrm {KL}[\pi||{\rm ref}]
=
\E_{x}
   \sum_{t=1}^{L}
   D_\mathrm {KL}[\,
        \pi(\,\cdot\,|\!-\!lxt)
        ~||~
        {\rm ref}(\,\cdot\,|\!-\!lxt)
   ] .
$$
Plotting $(U,D)$ pairs produces a frontier exactly as described for sentiment generation—those points internalised closer to $(U^*,D^*)=(0,\infty)$ are preferable if higher rewards align with legitimate behaviour.

### GPT‑4 Win Rate  

When no closed form oracle exists ($r^\ast$ unknown), we use large language model judgments as proxies following common practice:
- For each test prompt $x$, sample up to $N=128$ continuations from base policy $\hat y_i$, stochastically.
- Score them using GPT‑4 via carefully crafted prompts that ask whether one completion better satisfies safety/helpfulness.
- Record win rate $W = C/\binom N2$ where $C$ counts pairwise comparisons where GPT‑4 prefers our policy’s best out-of-sample over baseline's best.

This ratio captures *relative quality*: if our method draws consistently from higher utility tails it should win more often.

### Human Pairwise Comparison Study  

To validate trustworthiness of GPT‑4 scores we run an offline study:
- Randomly select three policy variants: best performing DPO vs highest scoring PPO vs baseline SFT.
- For each pair selected by humans manually placed at test time ids annotated with both rounds of GPT‑4 prompts (“Simple” vs “Concise”).
- Compute inter-human agreement ($Jaccard$ delta); compare against GPT bot agreement against humans.
 
Empirical result: Canonical GPT‐4 win rates correlate at ~0.75 Pearson coefficient with delegation human judgments; thus treating GPT inference as briefest alternative literature component is defensible.

## Practical Training Notes

Below is a table summarising key non-Loss hyperparameters implemented across tasks:

| Parameter    | Value Range Tested              |
|--------------|--------------------------------|
| Learning Rate    | $3\times10^{-5}$ fixed for text token training|
| Optimiser          | AdamW w/ weight decay .01      |
| Batch Size         | varies per dataset        |
| Temperature       | re-computed each iteration based on batch-level logit scaling    |
| Alpha in Unlikelihood   | {0.05,.10,.5,.9}       |

Additionally:

* **Sampling**: At every training step only two completions per prompt were needed because pairs suffice for gradient signal—much cheaper than generic trajectory rollouts.
* **Batch Normalisation**: When weight normalisation was absent baseline RL losses spiked; removing it required careful scaling via LAMB-style adaptation.
* **Accretion vs Attrition**: Using best-of-$N$ strategy at test time derives higher quality outputs at cost O(Nlog(pk)), making it unsuitable for large deployments but valuable as ceiling performance benchmark.

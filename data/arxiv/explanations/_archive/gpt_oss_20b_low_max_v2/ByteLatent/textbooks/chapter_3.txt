Chapter 3: # 3. The Core Architecture of BLT

Large language models (LLMs) are, at their heart, sequences of attention blocks that transform an input representation into an output representation. In the Byte‑Latent Transformer (BLT), the input is **raw bytes** and the output is a sequence of bytes conditioned on preceding context. Decentralizing the computation across three interacting modules—a global transformer that reasons about **patches**, and two lightweight local modules that map between bytes and patches—allows BLT to preserve the expressive power of Transformers while drastically reducing the number of expensive self‑attention operations.

Below we dissect each of the three components, describe how they pass information, and elaborate on architectural innovations that make training and inference efficient.

---

## 3.1 High‑Level Block Diagram and Purpose

A BLT model can be seen as a pipeline:

```
Raw Bytes  →  [Local Encoder]  →  Patch Embeddings
      ↘︎                              ↓
        Latent Global Transformer (Autosgressive)   →  Patch Outputs
                      ↗                      ↑
                 [Local Decoder]               ↓
                                     Bytes (Generated)
```

* **Local Encoder** processes raw bytes in short windows, producing a compact vector for every patch while simultaneously retaining byte‑level locality via cross‑attention.
* **Latent Global Transformer** operates on these patch vectors. It is an autoregressive transformer that predicts the next patch embedding, thus doing the heavy lifting of modeling long‑range dependencies across patches.
* **Local Decoder** receives patch embeddings produced by the global transformer, reconstructs individual bytes within each patch through cross‑attention back to byte representations, and generates the final output sequence.

The key idea is that only a fraction of the model’s layers sees every byte; most bytes are compressed into patches before they ever touch the global transformer. The local modules therefore have only thin layers but still maintain direct access to byte embeddings, guaranteeing transparency to low‑level information such as accents or diacritical marks.

---

## 3.2 Latent Global Transformer

### Architecture

The global block is a vanilla Transformer decoder (layer‑norm → multi‑head self‑attention → feed‑forward → residual connections) with the following specifics:

| Parameter | Value / Range |
|-----------|---------------|
| Depth \(l_{\mathcal{G}}\) | Tuned per scaling (e.g., 12–32 layers for 1–8 B parameter models) |
| Hidden size \(h_{\mathcal{G}}\) | Scales linearly with total parameters |
| Attention heads | Typically 16–32 depending on \(h_{\mathcal{G}}\) |

Unlike conventional models that attend over individual tokens, BLT attends over *patches*. Each patch vector has dimension \(h_{\mathcal{G}}\). To keep memory usage modest, attention operates with a **block‑causal mask**: when computing features for patch \(j\), the attention keys include patches \(\leq j\), but also apply a spatial “block” constraint preventing attention to distant future patches within a fixed-size window. This keeps each layer’s time complexity linear in *patch count* rather than byte count.

### Causal Masking

The latent transformer maintains *strict causality* at two levels:

1. **Patch Causality** – The model cannot peek at future patches during generation.
2. **Token Causality** – Within each local encoder window there is no look‑ahead; cross‑attention explicitly restricts queries from peeking beyond their own patch.

This design guarantees that during inference, every step can be processed independently if desired; enough compute can be allocated purely at the global level by collapsing multiple bytes into one patch.

### Parameter Sizing Relative to Local Modules

Because local encoder/decoder stacks are shallow (often \(l_{\mathcal{E}}, l_{\mathcal{D}} \ll l_{\mathcal{G}}\)), most parameters belong to \(\mathcal{G}\). Thus training flops are dominated by \(\mathcal{G}\), but its workload per byte shrinks proportionally with larger patches—precisely what enables BLT’s superior scaling efficiency.

## 3.3 Local Encoder

### Lightweight Transformer Backbone

The local encoder \(\mathcal{E}\) consists of \(l_{\mathcal{E}}\) small Transformer layers (\(l_{\mathcal{E}}\) ≈ 1–4). Each layer uses a *local block causal* attention mask: a sliding window of size \(w_{\mathcal{E}}\) (e.g., 64 or 128 bytes). This allows each byte to attend only to its near neighbours within its *own* patch or overlapping with adjacent patches—efficient yet expressive enough for capturing fine-grained byte patterns.

### Cross‑Attention: From Bytes to Patches

After every Transformer layer, \(\mathcal{E}\) applies a multi-head cross-attention module that aggregates byte representations into a single query representation per patch:

1. **Query Initialization**: For each patch \(p_j\), we pool all residual-byte representations (e.g., mean or max pooling). This pooled vector becomes the initial query \(Q_j^{(0)}\).
2. **Keys/Values**: Keys and values are derived from the same byte representations, projected separately via weight matrices \(W_k, W_v\).
3. **Attention Mask**: The cross-attention is constrained so that query \(Q_j\) attends only to keys/values belonging to bytes in its own patch.
4. **Output Update**: The result of softmax(QKᵀ)V replaces or adds via residual connection to strengthen the representation for subsequent layers.

Formally,

\[
P_{l,j} = P_{l-1,j} + \mathrm{softmax}\!\left(\frac{Q_{l-1,j}K^\top}{\sqrt{d_k}}\right)V,
\]

with \(Q_{l-1,j}=W_qP_{l-1,j}\). At depth \(l=l_{\mathcal{E}}\), we discard intermediate weights and output \(\boldsymbol p_j = P_{l_{\mathcal{E}},j}\).

### Benefits

* The cross-attention compresses variable-length groups of bytes into fixed-size vectors without discarding any byte.
* By performing this operation after every local transformer layer, BLT allows nuances from different parts of a large patch (say up to 50 bytes) to bleed into one another before being passed upward.
* The computation cost for cross-attention is linear in both number of patches and average patch length because each query only attends locally.

## 3.4 Hash‑n‑gram Embeddings in Byte Representations

A core challenge when working directly on raw data is capturing short-range context efficiently without exploding memory usage. BLT solves this with *hash‑n-gram* embeddings:

1. For each position \(i\), we consider n-grams \(g_{i,n}=\{b_{i-n+1},\dots,b_i\}\) for \(n \in [3..8]\).
2. A rolling polynomial hash maps each n-gram deterministically into an integer index modulo table size \(|E_n^{hash}|\).
3. Table lookup yields an embedding vector; all such n-gram embeddings are summed element-wise with the unigram byte embedding:
   \[
   e_i = x_i + \sum_{n=3}^{8} E_n^{hash}(\text{Hash}(g_{i,n})) .
   \]
4. Finally we normalize by dividing by six (i.e., number of n-grams plus one).

Hashing keeps table sizes modest (≈ 500 k entries per n-gram length). Crucially, no additional positional encoding is needed because locally-stylized n-grams already capture relative positions implicitly—hence clean vanilla RMSNorm suffices after embedding.

Empirical studies show these hash embeddings reduce Bits-per-byte by ~0.01–0.04 compared with using only unigram embeddings, especially for structured domains (Wikipedia, GitHub).

## 3.5 Cross-Attention Mechanics in Encoder and Decoder

While both encoder and decoder use cross-attention, their roles differ:

| Module | Query | Key/Value | Purpose |
|--------|-------|-----------|---------|
| Encoder | Aggregated per-patch | Raw byte reps | Map bytes → patch vector |
| Decoder | Raw byte rep start | Global patch reps | Map global patch → per-byte reps |

Both employ same computation pattern:

1. Project queries via \(W_q\).
2. Compute keys/values via distinct projections per token.
3. Softmax over scaled dot-product; use mask restrictively.
4. Output passes through projection \(W_o\).

Only difference lies in what constitutes “query”: in encoding queries aggregate multiple bytes; in decoding unit queries correspond to individual recreated bytes out from encoded buffer.

Cross-attention boosts expressivity without radically changing FLOPs because each query accesses far fewer keys than typical full self-attention—its audience is confined to its own packet.

---

## 3.6 Local Decoder – Reconstructing Bytes from Patches

The decoder mirrors the encoder’s pipeline in reverse order:

1. **Input Preparation**: Start from encoded token-level hidden states at layer \(l_{\mathcal{E}}\); feed them into decoder with same dimensionality as encoder outputs.
2. **Cross-Attention Preceding Layer**: Here queries come from naive byte embeddings; keys/values come from globally passed-in patch vectors transformed by \(\mathcal{D}_C(o_j)\).
   \[
   B_l = D_{l-1} + W_o\,[\mathrm{softmax}(Q K^\top/\sqrt{d_k})V].
   \]
3. **Transformer Layer**: Standard block updating independently for each byte position.
4. **Output Projection**: Final hidden state undergoes projection onto vocabulary size of 256 bytes followed by log-softmax producing probability distribution over next-byte choices.

Because cross-attention in decoding uses key/value length equal to number of patches—not number of bytes—the costs remain comparable to those in encoding with slightly larger constants due to additional linear layers at decoder side.

---

## 3.7 Positional vs Rotary Embeddings vs Cross-Attention

Finite-length sequences would typically benefit from positional encodings (sinusoidal or learned). BLT eschews positional encodings inside cross-attention because they would break within-patch invariance needed for one-shot assembly/reassembly:

* Within patches we want invariance under permutations that preserve content order but not rigid positions.
* Cross-attention already operates “within” fixed reference sets (a chunk of contiguous positions).

For self-attention inside local encoder layers we insert rotary positional embeddings (RoPE) which provide directionality while keeping memory constant—especially crucial when dealing with very long contexts merged later into fewer patches at inference time.

Thus overall additive scheme:

```
Byte Embedding + Hash-ngram embedding + [PreLayerNorm] + RoPE
↓
Local Encoder Transformers with RoPE
↓
Cross-Attention → Patch vector
↓
Latent Global Transformer
↓
Decoder Cross-Attention ← Patch vector
↓
Local Decoder Transformers w/ RoPE
↓
Byte probabilities output
```

## 3.8 Implementation Details for Efficient Training

Several engineering choices enable training up-to‑8B parameters on billions of raw bytes without prohibitive resource consumption:

### Aware Batch Padding

Instead of padding all sequences to a fixed number of bytes—a costly approach if many batches have few long patches—we pad on *patch-level*. Every batch contains exactly the same number of patches so data loader can pack them without wasted GPU time.

### Flex Attention & Flash Attention

The latent transformer leverages FlashAttention for quadratic self-attention where applicable; however since dynamic masks appear during cross-attention we turn on FlexAttention—a fused implementation tailored for batched ragged masks—to lower block granularity overheads.

### Mixed Precision & Gradient Accumulation

We train using FP16 mixed precision along with loss scaling; weight updates occur after compositing gradients across several micro-batches so GPU throughputs stay high while avoiding volatile updates typical when clip gradients too aggressively on low-res data granularity yet per-compute budgets still large.

### Entropy Patching Preprocess Cache

During dataloading we compute entropy boundaries once per epoch using our small entropy LM immediately after ingesting raw bytes; storing these boundaries in memory speeds up subsequent passes because no re‐compute occurs for each training step.

### Memory Optimized Pipelines

Because local encoder activations live only for a single forward/backward pass they are freed early; global transformer activations remain active longer thanks to gradient checkpointing options applied only when *global depth >10*, thereby keeping VRAM usage manageable even when the latent transformer comprises↦30 layers at largest scale setup.

With these tricks combined BLT reaches storage footprints comparable or superior to tokenized LLMs while maintaining subsecond per-token latency on contemporary GPUs – crucial when upscaling inference budgets without sacrificing responsiveness.



---



By decomposing byte processing into these three tiers – lightweight *local* branches compress raw inputs into reusable latent codes while holding onto world‐knowledge without tokenization biases; then an autoregressive *global* core challenges long-range sequences efficiently – BLT bridges two worlds: fine-grained representation learning typical of character models together with scaling law parity with state-of-the-art BPE-based transformers.


In subsequent chapters we will show how tuning edge hyperparameters – like average patch size vs neural depth – unlocks new trade-offs between compute budget and model performance, highlighting why BLT constitutes a viable replacement for traditional subword tokenization frameworks at scale.

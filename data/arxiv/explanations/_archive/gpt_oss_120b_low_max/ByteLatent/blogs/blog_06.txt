# Future Directions for Patch‑Based LLMs: End‑to‑End Patching, Scaling Laws, and Beyond

Large language models (LLMs) have become the workhorse of modern AI, but they still rely on a hidden pre‑processing step: tokenization. The recent **Byte Latent Transformer (BLT)** paper shows that we can discard static vocabularies, group raw bytes into *dynamic patches*, and still match the performance of token‑based models while cutting inference flops by up to 50 %. BLT opens the door to a whole new design space, yet many questions remain. In this post we outline three research frontiers that look most promising for the next generation of patch‑based LLMs:

1. **Learning patch boundaries jointly with the language model (end‑to‑end patching).**  
2. **Deriving scaling laws that are specific to byte‑level, patch‑driven architectures.**  
3. **Hardware‑aware optimizations that turn theoretical flop savings into real‑world speedups.**  

We’ll walk through why each direction matters, what the current paper has already tackled, and where concrete research opportunities lie.

---

## 1. End‑to‑End Patching: Let the Model Decide Where to Split

### Why it matters
BLT currently uses a *pre‑computed* entropy model to decide where patches start. This works well, but it imposes two constraints:

| Constraint | Consequence |
|------------|--------------|
| **Static thresholds** (global or monotonic entropy) | Patch granularity is fixed for an entire dataset; any mismatch between the entropy estimator and the final LM hurts efficiency. |
| **Separate training** of the entropy model | Additional data passes are required, and the patcher cannot adapt to later stages of training (e.g., when the LM becomes better at hard predictions). |

If patches could be *learned jointly* with the language model, compute would be allocated exactly where the model needs it—potentially yielding finer granularity in high‑entropy regions and coarser granularity elsewhere.

### Possible approaches
1. **Boundary predictor head** – Attach a lightweight binary classifier (or a multi‑class head) to each byte representation that outputs “patch break?” This head can be trained with a *reinforcement* signal: each time a break is placed, the global transformer is invoked, incurring a known flop cost. The loss then balances language modeling likelihood against an explicit compute budget term.

2. **Differentiable masking** – Replace hard binary decisions with a soft gating function (e.g., Gumbel‑Softmax). During backpropagation the model learns a distribution over break points; at inference time we take the argmax to obtain deterministic patches.

3. **Curriculum patching** – Start training with coarse patches (large stride) and gradually let the model refine its boundaries as it learns richer byte representations. This mirrors curriculum learning in vision where early layers see low‑resolution inputs.

### Open challenges
- **Stability:** The boundary predictor must not collapse to “break everywhere” or “never break.” Proper regularization (entropy penalties, FLOP budgets) is essential.
- **Latency:** Introducing a per‑byte break decision adds overhead; efficient vectorized implementations or batched decisions are needed.
- **Evaluation:** We need metrics beyond bits‑per‑byte (BPB) that capture *compute‑efficiency*—for instance, average FLOPs per generated token under a fixed latency budget.

## 2. Scaling Laws for Byte‑Level, Patch‑Driven Models

### What BLT has shown so far
The paper presents two scaling studies:
- **Compute‑optimal scaling** (parameter–flop tradeoff) where BLT matches Llama 3.
- **Inference‑flop controlled scaling**, demonstrating better curves when we increase both model size *and* average patch size.

These results are encouraging but rely on *extrapolating* existing token‑level scaling formulas (e.g., Chinchilla’s \(\text{Flops} \propto N^{0.5} D^{0.5}\)). Byte models introduce an extra degree of freedom—patch size—that isn’t captured by those formulas.

### Toward dedicated scaling laws
A more faithful scaling law for BLT would likely have three axes:

\[
\text{Performance} \approx f\bigl(N_{\text{global}}, N_{\text{local}}, \bar{s}\bigr)
\]

where:
- \(N_{\text{global}}\) = parameters in the latent transformer,
- \(N_{\text{local}}\) = parameters in encoder/decoder,
- \(\bar{s}\) = average patch size (bytes per patch).

Empirical fitting across many model sizes and patch sizes should reveal:

| Regime | Dominant cost |
|--------|----------------|
| Small \(\bar{s}\) (< 4 bytes) | Global transformer FLOPs dominate → similar to token models |
| Medium \(\bar{s}\) (4–8 bytes) | Tradeoff point where reduced global steps offset larger cross‑attention costs |
| Large \(\bar{s}\) (> 8 bytes) | Encoder/decoder overhead becomes negligible; global FLOPs shrink dramatically |

A new law could predict *optimal* \(\bar{s}\) given a fixed FLOP budget, much like how Chinchilla predicts optimal data quantity for a given parameter count.

### Research tasks
- Run systematic sweeps over \(\bar{s}\) at several parameter buckets (e.g., 400 M, 2 B, 8 B).
- Fit multi‑dimensional power laws or neural surrogates that incorporate entropy statistics of the training data.
- Validate whether optimal \(\bar{s}\) shifts as data quality improves (e.g., moving from raw web crawl to curated multilingual corpora).

## 3. Turning Flop Savings into Wall‑Clock Speedups

### The gap today
BLT’s FLOP analysis counts feed‑forward layers as dominant computation, not self-attention. However:
- Existing transformer kernels (FlashAttention, Triton kernels) are heavily tuned for fixed sequence lengths and dense attention masks.
- BLT introduces *dynamic* masks in cross‑attention and variable patch counts per batch—cases where current libraries fall back to slower implementations.

Thus, while BLT can theoretically use 50 % fewer FLOPs at inference, actual latency gains may be modest without tailored kernels.

### Hardware‑centric ideas
1. **Variable‑length batch packing** – Group patches of similar length into the same batch; this reduces padding overhead both in encoder/decoder and global transformer.
2. **Specialized cross‑attention kernels** – Leverage “flex attention” or custom CUDA kernels that exploit the fact that each query attends only to bytes inside its own patch—a highly localized pattern amenable to shared memory tiling.
3. **Mixed precision & quantization** – Since local encoder/decoder are lightweight, aggressive quantization (e.g., 4‑bit weights with integer arithmetic) can reduce memory bandwidth dramatically without hurting overall BPB.
4. **FPGA/ASIC pipelines for entropy computation** – If we move toward end‑to‑end learned patching, having dedicated hardware that evaluates boundary logits on‐the‐fly could keep per‑token latency low.

### Evaluation beyond FLOPs
Future papers should report:
- **Throughput (tokens/s)** under realistic batch sizes.
- **Energy per generated byte**, measured on commodity GPUs vs specialized accelerators.
- **Latency distribution**, especially for long generation sequences where dynamic patches cause variable step counts.

## Putting It All Together: A Roadmap

| Phase | Goal | Key Experiments |
|-------|------|-----------------|
| **0️⃣ Baseline** | Reproduce BLT scaling results on a public dataset | Train 1 B and 4 B BLT models with static entropy patching |
| **1️⃣ End-to-End Patching** | Replace static entropy thresholds with learnable boundaries | Implement Gumbel‐Softmax break predictor; evaluate FLOP vs BPB tradeoff |
| **2️⃣ Scaling Law Discovery** | Fit three‑axis scaling curves across many \(\bar{s}\) values | Grid search over \(\bar{s}\in\{2,\dots,12\}\) at 400 M / 2 B / 8 B |
| **3️⃣ Kernel Optimizations** | Close wall-clock gap between theory & practice | Build custom cross‑attention kernel; benchmark on RTX 4090 / A100 |
| **4️⃣ Full System Integration** | Deploy an end-to-end BLT service under fixed latency budget | Combine learned patching + optimized kernels + quantization; measure throughput on real workloads (chatbot, code generation). |

Each phase feeds into the next: better boundaries reduce variance in patch length → cleaner data for scaling-law fitting → clearer targets for kernel engineers.

---

## Takeaway

BLT proves that “patches scale better than tokens,” but it also raises a fascinating set of open problems:

*Can we let the model itself decide its own granularity?*  
*What does an optimal tradeoff between model size and patch size look like across compute regimes?*  
*How do we make these theoretical gains translate into faster inference on today’s hardware?*

Answering these questions will require collaboration between language modeling researchers, systems engineers, and hardware designers. If you’re interested in building the next wave of efficient LLMs—whether you’re developing novel boundary predictors or low-level GPU kernels—there’s plenty of low-hanging fruit ahead. The future of LLMs may well be byte‐native, dynamically patched, and hardware‐aware—all at once. Happy hacking!

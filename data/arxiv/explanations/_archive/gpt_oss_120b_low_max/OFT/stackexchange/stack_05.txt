\title{Stack Exchange of the Paper: "Controlling Text-to-Image Diffusion by Orthogonal Finetuning"}

### How does OFT compare to LoRA in terms of effective rank of the weight update?
Question:
In Section 3.5, the authors rewrite OFT’s forward pass as \((\mathbf{R}-\mathbf{I})\mathbf{W}^0\). Since \(\mathbf{W}^0}\) is typically full rank, they claim OFT performs a low‑rank update when \((\mathbf{R}-\mathbf{I})" is low‑rank. I would like clarification on:
- Under what conditions is \((\mathbf{R}-\mathbf{I})" low‑rank given a block‑diagonal orthogonal matrix?
- How does this compare numerically to LoRA’s rank‑r update in terms of parameter count and expressive power?
- Are there empirical studies measuring the actual rank of the effective update during training?
Answer:
**Answer**

In OFT the weight matrix of a layer is rewritten as  

\[
\mathbf W =\mathbf R \mathbf W^{0},\qquad \mathbf R^{\top}\mathbf R=\mathbf I ,
\]

so that the forward‑pass can be expressed as  

\[
\mathbf z = (\mathbf R\mathbf W^{0})^{\top}\mathbf x
          =(\mathbf W^{0})^{\top}\mathbf x+(\underbrace{(\mathbf R-\mathbf I)\mathbf W^{0}}_{\displaystyle\Delta\! \mathbf W})^{\top}\mathbf x .
\]

The term $\Delta\! \mathbf W=(\mathbf R-\mathbf I)\mathbf W^{0}$ plays the same role as the additive low‑rank matrix in LoRA. Whether this update is actually low‑rank depends on the structure of $\mathbf R-\mathbf I$.

--------------------------------------------------------------------

### When is $(\mathbf R-\mathbf I)$ low‑rank?

The paper forces $\mathbf R$ to be **block‑diagonal**:

\[
\mathbf R=
\operatorname{diag}(\mathbf R_{1},\dots ,\mathbf R_{r}), \qquad 
\mathbf R_{i}\in {\rm O}\bigl(d/r\bigr),
\]

where each block is an orthogonal matrix of size $d/r\times d/r$.  
If we take the simplest case $r=1$ (a full orthogonal matrix), then
$\operatorname{rank}(\mathbf R-\mathbf I)=d - \operatorname{dim}
(\ker(\mathbf R-\mathbf I))$.  Because an orthogonal matrix can have at most a
$d/2$‑dimensional eigenspace for the eigenvalue $+1$, a *generic* orthogonal
matrix has rank close to $d$; therefore $(\mathbf R-\mathbf I)$ is **not**
low‑rank.

The low‑rank property emerges only when we *reduce the number of independent
degrees of freedom* by using the block structure **and optionally sharing the
blocks**.  Consider two extreme regimes:

* **Non‑shared blocks, $r>1$.**  
  Within each block, $\mathbf R_{i}$ can be written as  
  $\mathbf R_{i}= \exp(\mathbf Q_{i})$ with a skew‑symmetric $\mathbf Q_{i}$.  
  If each block is close to the identity (the “small‑angle’’ regime used in COFT),
  then $\mathbf R_{i}-\mathbf I\simeq \mathbf Q_{i}$ has rank at most
  $d/r-1$.  Stacking the blocks gives  

  \[
  \operatorname{rank}(\mathbf R-\mathbf I)
  \;\leq\; r\, (d/r-1)= d-r,
  \]

  i.e. the rank deficit equals the number of blocks.  For example, with
  $d=512,\; r=8$ we obtain an update of rank at most $504$, which is still
  high, but *much lower* than the full rank $512$.

* **Shared blocks, $\mathbf R_{1}=…=\mathbf R_{r}$.**  
  In this case the whole matrix consists of repeated copies of a single small
  orthogonal matrix.  Algebraically

  \[
  \operatorname{rank}(\mathbf R-\mathbf I)=
  \operatorname{rank}\bigl[(\underbrace{\mathbf I_{r}}_{\text{repetition}}\otimes
   (\tilde{\mathbf R}-\mathbf I_{d/r}) ) \bigr]
   = r\, \operatorname{rank}(\tilde{\mathbf R}-\mathbf I_{d/r}),
  \]

  so the effective rank is multiplied by $r$.  
  If we further force each small block to be a **Givens rotation** that touches
  only two coordinates, then each block contributes rank 2, and the total rank
  becomes $2r$.  This is precisely the situation in which OFT behaves like a
  LoRA update with *effective rank* $2r$.

Hence, **the update is low‑rank when (i) we use many small blocks, (ii) each block
is close to identity (or a sparse rotation), and optionally (iii) we share the
blocks**. The paper’s “$r$” parameter therefore controls an *upper bound* on
the rank of $(\mathbf R-\mathbf I)$.

--------------------------------------------------------------------

### Numerical comparison with LoRA

| Method | Parameterisation | Trainable parameters | Effective rank of update |
|--------|------------------|----------------------|--------------------------|
| LoRA   | $\Delta \!\!W = \underbrace{\bf A}_{d\times r'}\,\,\underbrace{{\bf B}}_{r'\times n}$ | $r'(d+n)$ | exactly $r'$ (by construction) |
| OFT (full‑orthogonal) | single orthogonal matrix ($r=1$) | $d(d-1)/2\simeq O(d^{2})$ | up to $d-1$; not low‑rank |
| OFT (block‑diagonal, no sharing) | $r>1,\; d/r\times d/r$ blocks | $d(d/r-1)/2 = O(d^{2}/r)$ | ≤ $d-r$ (see above) |
| OFT (block‑diagonal, shared blocks) | one prototype block repeated $r$ times | $(d/r)(d/r-1)/2 = O(d^{2}/r^{2})$ | ≤ $2r$ if each block is a simple rotation |

If we set both methods to have comparable parameter budgets,
e.g. for a layer with $d=n=512,\; r'=8,\; r=8:$

* **LoRA:** $8(512+512)=8192$ trainable parameters, exact rank 8.
* **OFT (non‑shared blocks):** ≈ $512(64-1)/2≈16\,128$ parameters, rank ≤ 504.
* **OFT (shared blocks):** ≈ $64(63)/2≈2016$ parameters, effective rank ≤ 16.

Thus OFT can be made *more* parameter‑efficient than LoRA when we share blocks,
while its effective rank scales linearly with the number of blocks rather than
the hidden dimension. The expressive power is consequently different:

* **LoRA** forces all changes into an *additive low‑dimensional subspace*.  
* **OFT** applies a *multiplicative orthogonal transformation* that rotates each
neuron within its subspace. Even when the update has low effective rank,
the transformation can affect many directions simultaneously because it acts on
the *pretrained full‑rank matrix* $W^{0}$.

Empirically the paper reports that OFT with modest block numbers ($r=8$–$16)$
already matches or exceeds LoRA on both subject‑driven and controllable tasks,
suggesting that the rotational degrees of freedom provide richer expressivity
than a pure additive low‑rank perturbation of comparable size.

--------------------------------------------------------------------

### Empirical measurement of effective rank

The authors do not directly report a singular‑value spectrum of $(R-\!I)W^{0}$
during training, but they provide indirect evidence:

1. **Parameter–performance curves** (Fig. 3 in the paper): as they increase $r$
   (more blocks → more parameters), both OFT and COFT continue to improve,
   whereas LoRA quickly saturates once $r'$ reaches ≈ 8–12. This pattern is
   consistent with an effective rank that grows with $r$.

2. **Ablation on block sharing** (Appendix C): when all blocks are forced to be
   identical, performance drops noticeably while the number of parameters stays
   roughly constant, indicating that reducing the effective rank harms expressive
   capacity.

3. **Singular‑value plots in the supplementary material**: although not emphasized,
   Appendix D contains histograms of singular values of $\Delta W$ for selected layers;
   they show a sharp decay after roughly $2r$ largest values when shared blocks are used,
   confirming that only a handful of singular directions dominate.

These observations collectively suggest that OFT’s update indeed behaves like a
low‑rank modification whose rank is governed by the block configuration.

--------------------------------------------------------------------

### Take‑away

* $(R−I)$ is not automatically low‑rank; it becomes low‑rank only when we enforce a
block‑diagonal (especially shared‑block) structure and keep each block close to identity.
* The “$r$” parameter in OFT plays a role analogous to LoRA’s “$r'$”, but it bounds 
the *effective* rank rather than fixing it exactly.
* For comparable parameter budgets, OFT can achieve an effective rank that is 
a small multiple of $r$ while still providing richer transformations because it 
acts multiplicatively on a full‑rank pretrained matrix.
* Empirical ablations in the paper confirm that decreasing this effective rank 
(e.g., by sharing blocks or using very few blocks) reduces performance, whereas 
increasing $r$ continues to improve results—behaviour consistent with a low‑rank 
but expressive update.

Hence, OFT can be seen as an orthogonal counterpart to LoRA: both aim for parameter efficiency,
but LoRA does so via explicit additive low‑rank matrices, whereas OFT does it by restricting an 
orthogonal transform to a sparsely parameterised (block‐diagonal, possibly shared) form,
yielding a controllable—and often more expressive—low‑rank effective weight update.

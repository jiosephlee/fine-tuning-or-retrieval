## Why Add a Zero Weight? Feature Filtering and Expressive Power  

The original 1‑bit BitNet constrains every trainable weight to the binary set \(\{-1,+1\}\). While this extreme quantization dramatically reduces the amount of information that must be stored and transferred, it also forces each linear mapping to be a pure sign‑flip or sign‑preserving operation. In practice, many useful transformations in a Transformer require the ability to *suppress* certain input dimensions altogether.  

Introducing a third value, \(0\), expands the expressive repertoire of a ternary weight matrix from a mere polarity mask to a **feature‑filtering mask**. Each row of a weight matrix now decides, for every input feature, one of three actions:

1. **Preserve and amplify** the feature (\(+1\)).  
2. **Preserve and invert** the feature (\(-1\)).  
3. **Ignore** the feature completely (\(0\)).  

The “ignore” action enables the network to zero out irrelevant dimensions without needing to rely on downstream non‑linearities or attention mechanisms. This yields two concrete benefits:

- **Higher Effective Rank:** By selectively turning off dimensions, a ternary matrix can approximate a low‑rank real‑valued matrix more faithfully than a strictly binary one, because sparsity (the presence of zeros) provides an additional degree of freedom.
- **Improved Gradient Flow:** During training, gradients that would otherwise be forced to adjust the magnitude of \(\pm1\) entries can now be “parked” on zero entries, reducing noisy updates and stabilizing optimization.

Empirically, the paper reports that once models reach roughly 3 B parameters, the inclusion of zero weights allows BitNet b1.58 to match full‑precision LLaMA baselines in perplexity and downstream task accuracy. The authors thus argue that the extra \(\log_2(3) \approx 1.58\) bits per weight represent a sweet spot where memory savings are retained while expressive power is restored.

## AbsMean Quantization Function and RoundClip Operator  

Training a ternary network requires repeatedly projecting floating‑point weight tensors onto the discrete set \(\{-1,0,+1\}\). The **AbsMean quantization** scheme employed by BitNet b1.58 proceeds in two stages: scaling by an average absolute magnitude and then rounding/clipping to the allowed integer values.

Given a full‑precision weight matrix \(W \in \mathbb{R}^{n\times m}\), we first compute a scalar scaling factor \(\gamma\) that captures the typical magnitude of its entries:

\[
\gamma = \frac{1}{nm}\sum_{i=1}^{n}\sum_{j=1}^{m} |W_{ij}|.
\]

Intuitively, \(\gamma\) is the *mean absolute value* of all weights; it normalizes the distribution so that entries are centered around zero with unit average absolute deviation. Adding a small constant \(\epsilon\) (e.g., \(10^{-8}\)) prevents division by zero.

Next we form a scaled matrix:

\[
\widehat{W} = \frac{W}{\gamma + \epsilon},
\]

which typically has most elements within the interval \([-1, 1]\). The final ternarization step applies the **RoundClip** operator:

\[
\widetilde{W}_{ij}= \operatorname{RoundClip}\!\bigl(\widehat{W}_{ij},\, -1,\, 1\bigr),
\]
where
\[
\operatorname{RoundClip}(x, a, b)=
\max\!\bigl(a,\; \min\!\bigl(b,\; \operatorname{round}(x)\bigr)\bigr).
\]

The `round` function maps any real input to its nearest integer; clipping then forces any result outside \([-1, 1]\) back onto the boundary. Consequently each entry of \(\widetilde{W}\) becomes exactly \(-1\), \(0\), or \(+1\).  

Because the scaling factor is recomputed **every forward pass** (or at least every optimizer step), gradients are back‑propagated through the quantizer using *straight‑through estimation*: during back‑propagation the quantizer is treated as identity, allowing gradient flow into the underlying full‑precision accumulator \(W\) while still enforcing discrete constraints after each update.

## Computation of Scaling Factor \(\gamma\) (Average Absolute Weight)

The scale \(\gamma\) carries two important practical roles:

1. **Dynamic Range Normalization:** As training progresses, weight magnitudes can drift upward or downward. By normalizing each weight by \(\gamma\), we keep most scaled values near the quantization thresholds (i.e., between \(-0.5\) and \(+0.5\)), minimizing bias toward either sign.
2. **Gradient Stabilization:** Since \(\gamma\) is a simple arithmetic mean over all absolute values, it changes smoothly across steps, providing a low‑variance signal for any optimizer that might otherwise suffer from abrupt jumps caused by hard thresholding.

Algorithmically, computing \(\gamma\) is embarrassingly parallel: each processing core computes a partial sum of absolute values over its slice of \(W\); after a reduction all partial sums are summed and divided by \(nm\). The cost is negligible compared to matrix multiplication because it is an \(O(nm)\) elementwise operation without any expensive arithmetic beyond absolute value and addition.

## Activation Quantization: Symmetric int8 Range \([-Q_b,Q_b]\)

While weights are ternary, activations retain higher precision to preserve model capacity during forward propagation. BitNet b1.58 adopts an **8‑bit symmetric integer representation**, mapping real activation values to integers in

\[
[-Q_b,\; Q_b],
\]
where \(Q_b = 2^{7} - 1 = 127.\)

Key design choices differentiate this scheme from many post‑training quantizers:

- **No Zero‑Point Offset:** Traditional asymmetric quantization includes an additive offset (“zero point”) so that an integer zero corresponds to some non‑zero real value. Here we deliberately avoid any offset; instead we simply scale activations symmetrically around zero. This removes an extra arithmetic operation during dequantization and aligns nicely with hardware that implements saturating adders for signed integers.
- **Per‑Token Scaling:** For each token (i.e., for each row in the activation matrix), we compute a scale factor such that its maximum absolute value maps exactly to \(Q_b\). This per‑token approach captures token‑specific dynamic ranges while keeping implementation simple: after scaling, each element is rounded to nearest integer and clamped within bounds.
- **Compatibility with BitLinear:** Since BitLinear expects integer inputs on both sides (weights already ternary), using signed int8 activations enables pure integer arithmetic for all `nn.Linear` replacements—only additions are required, because multiplication by \(-1,0,+1\) reduces to sign inversion or pass‑through.

Empirically, this symmetric int8 quantization produces *negligible* degradation compared with full‑precision activations when combined with the ternary weight scheme; therefore BitNet b1.58 can afford this aggressive reduction without sacrificing downstream performance.

## Adopted LLaMA Components: RMSNorm, SwiGLU, Rotary Embeddings, Bias Removal  

To ensure broad compatibility with existing open‑source tooling (HuggingFace Transformers, vLLM, llama.cpp), BitNet b1.58 mirrors the architectural choices of LLaMA while substituting only those components directly impacted by quantization.

### RMSNorm  

Layer normalization stabilizes training but traditionally requires computing both mean and variance across hidden dimensions—a costly operation for integer arithmetic. **Root Mean Square Normalization (RMSNorm)** simplifies this by normalizing solely with respect to root‑mean‑square:

\[
y = \frac{x}{\sqrt{\frac{1}{d}\sum_{k=1}^{d} x_k^2}} \odot g,
\]

where \(g\) is a learned gain vector and \(d\) denotes hidden size. RMSNorm eliminates subtraction of the mean term, reducing computational overhead and making it easier to implement in fixed‑point hardware while preserving most of LayerNorm’s benefits.

### SwiGLU  

The feed‑forward sublayer in Transformers traditionally uses Gelu activation followed by a linear projection. BitNet b1.58 replaces this with **SwiGLU**, which combines Swish (a smooth sigmoid–linear product) with gated linear units:

```
h = x · W₁
g = x · W₂
output = Swish(h) ⊙ g
```

Because Swish can be approximated efficiently in integer arithmetic (e.g., via lookup tables or piecewise linear functions), SwiGLU remains amenable to efficient implementation while providing superior expressivity compared with Gelu.

### Rotary Positional Embeddings (RoPE)  

Absolute positional embeddings add overhead proportional to sequence length. RoPE encodes positions via complex rotations applied directly on query/key vectors; mathematically:

\[
q' = q \odot e^{i\, \theta_{pos}},~~k' = k \odot e^{i\, \theta_{pos}},
\]

where multiplication by complex exponentials corresponds to rotating subspaces—a operation implementable as elementwise sin/cos lookups on integers after appropriate scaling. RoPE works seamlessly with quantized activations because it does not require extra learned parameters per position.

### Bias Removal  

All linear transformations in BitNet b1.58 omit additive bias terms (`bias=False`). Biases would need additional storage (one float per output dimension) and their influence on quantized training dynamics is marginal when combined with powerful normalization layers (RMSNorm). Removing biases reduces memory usage further—a crucial consideration when every parameter contributes directly to overall model size.

Collectively these components preserve LLaMA’s strong empirical performance while aligning with BitNet’s low‑bit hardware goals.

## Pseudocode for Forward Pass of a BitLinear Layer  

Below is an illustrative Python–like pseudocode that captures how `BitLinear` operates under the 1.58‑bit regime. The code assumes tensors are stored as:

- `W_int`: ternary weight matrix stored as `int8` values in `{ -1, 0, +1 }`.
- `x_int`: activation matrix already quantized to signed `int8`.
- `scale_w`: scalar scaling factor computed as described above (kept in floating point for convenience).
- `scale_a`: per‑token activation scaling factor (float).

```python
def bitlinear_forward(x_int: Int8Tensor,
                      W_int: Int8Tensor,
                      scale_w: float,
                      scale_a: FloatTensor,
                      out_scale: float):
    """
    Compute y = x * W using only integer additions.
    Arguments:
        x_int   – shape [batch, seq_len, dim_in]   (int8)
        W_int   – shape [dim_in, dim_out]          (int8 ∈ {−1,0,+1})
        scale_w – scalar ∈ ℝ⁺ (average |W| from Eq.(3))
        scale_a – shape [batch, seq_len]          (float32)
        out_scale – desired output scale (float)
    Returns:
        y_int   – shape [batch, seq_len, dim_out] (int32 before rescaling)
    """

    # 1️⃣ Scale activations back to real domain:
    #    For each token t: x_real[t] = x_int[t] * scale_a[t]
    #    In practice we keep them as int32 after multiplication.
    x_scaled = x_int.astype(int32) * scale_a[:, None]   # broadcasting

    # 2️⃣ Perform integer matrix multiplication.
    #    Because W_int ∈ {−1,0,+1}, multiplication reduces
    #    to selective addition/subtraction.
    #    The result lives in int32 precision.
    y_int32 = matmul_int_add(x_scaled, W_int)

    # 3️⃣ Apply combined scaling:
    #    Real output y_real = y_int32 * scale_w * out_scale
    #    For subsequent layers we keep y as int8:
    y_float = y_int32.astype(float32) * scale_w * out_scale

    # 4️⃣ Requantize to int8 symmetric range [-Qb,Qb]
    max_abs = max(abs(y_float.max()), abs(y_float.min()))
    if max_abs == 0:
        return zeros_like(y_float).astype(int8)
    requant_factor = Qb / max_abs
    y_quant = round(y_float * requant_factor).clip(-Qb, Qb).astype(int8)

    return y_quant
```

Key points illustrated by this skeleton:

- **Multiplication Elimination:** Step 2 leverages that multiplying by `-1` equals subtraction and multiplying by `+1` equals addition; CPUs/GPUs can fuse this into a single sparse add kernel.
- **Two‑Stage Scaling:** The first scaling (`scale_a`) restores activations to their approximate real magnitudes; after matrix addition we apply `scale_w` together with an output rescaling factor (`out_scale`) that maps back into the int8 range required for subsequent layers.
- **Straight‑Through Gradient Flow:** During training one would keep an FP32 copy of `W` (`W_fp`) updated by SGD/Adam; after each optimizer step `W_fp` would be passed through the AbsMean quantizer producing fresh `W_int`. The pseudocode above reflects only inference; training adds gradient hooks that treat rounding as identity.

This forward path demonstrates how BitNet b1.58 achieves *“almost no multiplication”* for its dominant linear operations—an essential ingredient behind its dramatic reductions in latency and energy consumption.

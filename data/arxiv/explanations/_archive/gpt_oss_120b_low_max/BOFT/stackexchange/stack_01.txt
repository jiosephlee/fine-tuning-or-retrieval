\title{Stack Exchange of the Paper: "Parameter-Efficient Orthogonal Finetuning via Factorization"}

### How does the Cayley transform ensure orthogonality of the learned matrix in OFT and BOFT?
Question:
The paper states that OFT and BOFT enforce orthogonality via the Cayley parameterization, i.e., \(R = (I+Q)(I-Q)^{-1}\) where \(Q\) is skew‑symmetric. I understand that a skew‑symmetric \(Q\) yields an orthogonal \(R\), but I'm unclear on how this works in practice during training. Specifically:

1. How is \(Q\) parameterized (what are the trainable parameters)?
2. Does the inverse \((I-Q)^{-1}\) need to be computed explicitly each forward step, and is it numerically stable?
3. Are there any tricks (e.g., using a small learning rate or regularization) to keep \(Q\) close to zero so that \(R\) stays near the identity at initialization?

Any concrete explanation or pseudo‑code would help.

Answer:
The Cayley transform is used in OFT and in its butterfly‑based variant (BOFT) as a *re‑parameterisation* of an orthogonal matrix, i.e. we never optimise the entries of the orthogonal matrix $\mathbf R$ directly.  
Instead we keep a *skew‑symmetric* matrix $\mathbf Q$ as the trainable object and obtain $\mathbf R$ through  

$$
\mathbf R = (\mathbf I+\mathbf Q)(\mathbf I-\mathbf Q)^{-1},
\qquad\text{with } \mathbf Q^{\top}=-\mathbf Q .
$$

Because $(\mathbf I+\mathbf Q)^{\top}(\mathbf I-\mathbf Q)=\mathbf I-\mathbf Q^{2}$ and
$\mathbf Q^{2}$ is symmetric, one can check that  

$$
\mathbf R^{\top}\mathbf R
= (\mathbf I-\mathbf Q)^{-\top}(\mathbf I+\mathbf Q)^{\top}
   (\mathbf I+\mathbf Q)(\mathbf I-\mathbf Q)^{-1}
= \mathbf I ,
$$

so every $\mathbf R$ produced this way is orthogonal, regardless of the
numerical value of $\mathbf Q$.  The optimisation therefore only has to keep
the skew‑symmetry of $\mathbf Q$.

Below we answer the three concrete questions.

---

### 1.  What are the trainable parameters?  

A real $d\times d$ skew‑symmetric matrix has exactly $d(d-1)/2$ independent
entries (the upper‑triangular part, with the diagonal forced to zero).  
In practice we store a *vector* $\boldsymbol \theta\in\mathbb R^{d(d-1)/2}$
and map it to $\mathbf Q$ by

```python
# pseudo‑code for a d‑dimensional block
def theta_to_Q(theta, d):
    Q = torch.zeros(d, d)
    idx = 0
    for i in range(d):
        for j in range(i+1, d):
            val = theta[idx]
            Q[i, j] =  val       # upper triangle
            Q[j, i] = -val       # lower triangle = -upper
            idx += 1
    return Q
```

In BOFT each butterfly component consists of many small orthogonal blocks.
For a block of size $b\times b$ we keep a separate vector of length
$b(b-1)/2$.  The total number of trainable scalars is therefore  

$$
\underbrace{\tfrac{b(b-1)}{2}}_{\text{per block}}\times
      \underbrace{\tfrac{d}{b}}_{\text{# blocks}}\times m,
$$

where $m$ is the number of butterfly layers.  This matches the paper’s claim
that BOFT needs $\tfrac12(b-1)d\,m$ effective parameters.

---

### 2.  Do we really have to compute $(\mathbf I-\mathbf Q)^{-1}$ each forward pass?  

Yes – the forward pass needs $\mathbf R = (\mathbf I+\mathbf Q)(\mathbf I-\mathbf Q)^{-1}$.
However two facts make this cheap and stable:

* **Small blocks** – In BOFT the matrix that is inverted is block‑diagonal,
  each block being of size $b\times b$.  Inverting a $2\times2$ or even a
  $8\times8$ block can be done analytically (for $2\times2$) or with a very
  cheap batched LU solve.  Modern deep‑learning libraries provide a batched
  `solve` routine that processes all blocks in parallel, so the cost is
  $O(db)$, not $O(d^{3})$.

* **Numerical stability** – The Cayley transform is well‑behaved as long as
  $\|\mathbf Q\|_{2}<1$.  When $\|\mathbf Q\|$ approaches 1 the denominator,
  $\det(\mathbf I-\mathbf Q)$, becomes small and the inverse can blow up.
  In practice this never happens because:
  - **Zero‑initialisation**: at the start $\theta=0 \Rightarrow \mathbf Q=0$,
    so $\mathbf R=\mathbf I.$
  - **Learning‑rate control**: OFT/BOFT are finetuning methods; a modest learning
    rate (e.g. $10^{-3}$ or smaller for large models) keeps the entries of
    $\theta$ modest.
  - **Implicit regularisation**: gradient descent on a skew‑symmetric parameterisation
    naturally penalises large magnitudes – if a component tried to grow it would cause a large gradient on the loss because the resulting orthogonal matrix would rotate too far from identity.

If one prefers an extra safety net, it is common to clip the norm of each block:
```python
Q_block = theta_to_Q(theta_block, b)
norm = torch.norm(Q_block, p='fro')
if norm > epsilon:               # epsilon < 1, e.g. 0.9
    Q_block = Q_block * (epsilon / norm)
```
Clipping guarantees that all eigenvalues of $\mathbf Q$ stay inside $(-1,1)$.

---

### 3.  Keeping $Q\simeq0$ at initialization and during early training  

The paper already mentions “identity initialization”: set all entries of
$Q$ (hence all entries of $\theta$) to zero.  
Beyond that there are three practical tricks that many implementations adopt:

* **Small learning rate** – As noted above, finetuning works with learning rates an order of magnitude smaller than those used for training from scratch. This keeps updates to each entry of $\theta$ tiny, so $Q$ drifts slowly away from zero.

* **Weight decay / L2 regularisation** – Adding a small L2 penalty on the vector
$\theta$,

$$
L_{\text{total}} = L_{\text{task}} + \lambda\, \|\theta\|_{2}^{2},
$$

gently pulls every entry toward zero. Because the mapping from $\theta$ to an orthogonal matrix is smooth,
this translates into keeping $\|Q\|$ small.

* **Norm clipping per block** (as shown above).  
   Even if a few entries become large, scaling them back to keep the Frobenius norm below a threshold (usually $<0.9$) guarantees that the denominator stays well conditioned.

Putting everything together, a typical training loop for one butterfly layer looks like

```python
# theta: [num_blocks, b*(b-1)//2]   trainable parameters

def forward(x, theta):
    # reshape theta → list of blocks → build skew-symmetric blocks
    blocks_Q = []
    for t in theta:
        Qb = theta_to_Q(t, b)
        # optional norm clipping
        fro = torch.norm(Qb)
        if fro > eps:
            Qb = Qb * (eps / fro)
        blocks_Q.append(Qb)

    # build (I+Q)(I-Q)^-1 blockwise
    R_blocks = []
    for Qb in blocks_Q:
        Ib = torch.eye(b, device=Qb.device)
        num = Ib + Qb                # I + Q
        den = Ib - Qb                # I - Q
        Rb = torch.linalg.solve(den.t(), num.t()).t()   # (I-Q)^-1 (I+Q)
        R_blocks.append(Rb)

    # assemble full orthogonal matrix (block‑diagonal or butterfly permutation)
    R = assemble_butterfly(R_blocks)

    return (R @ W0).t() @ x          # OFT/BOFT forward pass
```

The same code works for OFT when `m=1` and `b=d` (a single dense block), and for BOFT when `m>1` and `b` is small.

---

### Summary  

* **Parameterisation:** store only the independent upper‑triangular entries of a skew‑symmetric matrix; each butterfly block contributes $b(b-1)/2$ trainable scalars.
* **Computation:** compute the Cayley transform block‑wise; inversion is cheap because each block is tiny and can be performed with a batched linear solve.
* **Stability:** initialise all entries to zero; use modest learning rates, optionally L2 regularisation and per‑block Frobenius‑norm clipping to keep $\|Q\|<1.$

With these ingredients the orthogonal matrix stays perfectly orthogonal throughout training while requiring far fewer parameters than an unconstrained dense orthogonal matrix—exactly what OFT and its butterfly extension BOFT aim for.

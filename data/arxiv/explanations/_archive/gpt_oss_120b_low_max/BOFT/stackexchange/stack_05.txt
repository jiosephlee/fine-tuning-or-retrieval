\title{Stack Exchange of the Paper: "Parameter-Efficient Orthogonal Finetuning via Factorization"}

### Why does BOFT achieve \(O(d\log d)\) parameter complexity while preserving dense connectivity?
Question:
The authors claim that multiplying \(\log d\) sparse butterfly components, each with \(O(d)\) non‑zero entries, yields a dense orthogonal matrix using only \(O(d\log d)\) trainable parameters. I would like clarification on:

1. How many trainable parameters does each butterfly component actually have (considering Cayley parameterization)?
2. How does the product of these sparse components become dense? A concrete demonstration for \(d=8\) would help.
3. Are there any hidden assumptions about the sparsity pattern (e.g., permutation of non‑zeros) that are required for density?

Answer:
**Answer**

The claim “$O(d\log d)$ trainable parameters while preserving dense connectivity” follows from two facts:

1. **Each butterfly component contains only $O(d)$ free parameters.**  
   A butterfly component $\widetilde{\mathbf B}(d,k)$ is a block‑diagonal matrix whose blocks are the *butterfly factors* $\mathbf B^{F}(k)$. For the smallest block size $k=2$ a factor has the form  

   $$
   \mathbf B^{F}(2)=\begin{bmatrix}
   \cos\theta & -\sin\theta\\[2pt]
   \sin\theta & \;\cos\theta
   \end{bmatrix},
   $$

   i.e. a 2‑dimensional rotation parametrised by a single scalar angle $\theta$.  
   When we use a larger block size $k=2b$ the factor is a direct sum of $k/2$ independent $2\times2$ rotations (or, equivalently, a Cayley transform of a skew‑symmetric $2\times2$ matrix). Consequently every block contributes exactly $(k/2)$ independent scalar parameters, and a component consisting of $d/k$ such blocks contributes  

   $$
   \frac{k}{2}\;\frac{d}{k}= \frac{d}{2}
   $$

   free scalars, irrespective of $k$.  Hence each component has $\Theta(d)$ trainable numbers.  The authors write this as  

   $$
   \text{#trainable per component}= \tfrac12(b-1)d,
   $$

   where $b=k$ is the block size (for $b=2$ this reduces to $d/2$).  The remaining entries of the component are fixed to either 0 or ±1 and are *not* learned.

2. **The product of $\log_2 d$ such components can be dense.**  

   The sparsity pattern of a butterfly component is exactly the one used in the radix‑2 Cooley–Tukey FFT: each row (or column) has exactly two non‑zero entries, positioned so that they “mix’’ pairs of indices that differ in one bit of their binary representation.  If we write the binary address of a node as a length‑$N=\log_2 d$ bit string, the first component swaps (or rotates) the least‑significant bit, the second component swaps the second‑least‑significant bit, and so on.  After applying all $N$ components every possible pair of input and output indices has been mixed at least once, i.e. the overall product matrix has no zero entries.

   **Concrete example for $d=8$.**  
   Let us label rows/columns by binary strings of length three:  

   ```
   000 001 010 011 100 101 110 111
   ```

   The three butterfly components are:

   *Component 1* ($k=2$, mixes bit 0): each 2×2 block acts on the pairs  
     (000,001), (010,011), (100,101), (110,111).  
     Its non‑zeros are at positions  
     $(0,0),(0,1),(1,0),(1,1), (2,2),(2,3),…$.

   *Component 2* ($k=4$, mixes bit 1): each 4×4 block consists of two
     butterfly factors and mixes the pairs  
     (000,010), (001,011), (100,110), (101,111).

   *Component 3* ($k=8$, mixes bit 2): a single 8×8 butterfly factor mixes
     (000,100), (001,101), (010,110), (011,111).

   Multiplying them,
   $$
      \mathbf R = \widetilde{\mathbf B}(8,8)\,
                 \widetilde{\mathbf B}(8,4)\,
                 \widetilde{\mathbf B}(8,2),
   $$
   yields a matrix in which every entry is a product of three rotation
   angles; none of them is forced to be zero.  Because each component is
   orthogonal (Cayley‑parameterised rotations), their product remains
   orthogonal while being fully dense.

3. **Hidden assumptions on the pattern.**  

   The only structural assumption is that each component’s non‑zero pattern must be a *perfect matching* between input and output indices – exactly two non‑zeros per row and per column – and that successive components permute these matchings in a way that corresponds to bit‑wise permutations.  This is precisely the butterfly connectivity used in FFT algorithms.  No additional permutation of rows/columns is needed; the recursive definition already guarantees that after $\log_2 d$ stages every source node can reach every sink node via a unique path.  If one were to choose an arbitrary sparsity pattern with only two non‑zeros per row/column but without this recursive permutation property, density would not be guaranteed: some source–sink pairs could remain disconnected.

---

### Summarising the three questions

1. **Parameter count per component:** With Cayley parameterisation each
   block of size $k$ contributes $k/2-1$ independent scalars; because there are $d/k$ blocks we obtain
   $$
      |\theta| = \frac{d}{2}(b-1)=O(d)
   $$
   trainable parameters per butterfly component.

2. **Why the product becomes dense:** The butterfly pattern performs successive
   pairwise mixing along different binary dimensions; after $m=\log_2 d$
   stages every input index has been mixed with every other index,
   therefore the resulting matrix has no structural zeros.

3. **Assumptions on sparsity:** The pattern must be exactly the
   radix‑$2$ butterfly ordering – i.e., each component is a block‑diagonal matrix whose blocks are butterfly factors and whose blocks are placed so that successive components permute the index bits.  Apart from this deterministic layout there is no hidden randomness; any deviation from it may break dense connectivity.

Thus BOFT achieves an orthogonal matrix with only $O(d\log d)$ learned scalars while still being able to express any dense orthogonal transformation up to approximation error determined by the number of stages and block size.

# Putting BOFT to Work: Real‑World Adaptations of Vision Transformers, Language Models, and Diffusion Models  

In the past year, **Orthogonal Butterfly Finetuning (BOFT)** has emerged as a compelling alternative to popular parameter‑efficient finetuning (PEFT) tricks such as LoRA, adapters, or prompt tuning.  By representing a dense orthogonal transformation as a product of a few sparse “butterfly” matrices, BOFT reduces the trainable‑parameter count from \(\mathcal{O}(d^{2})\) to \(\mathcal{O}(d\log d)\) while still preserving the geometric relationships that make orthogonal finetuning so stable.  

In this post we walk through three concrete downstream scenarios that were used to evaluate BOFT in the original paper:

1. **Image classification with large Vision Transformers (ViTs).**  
2. **Textual reasoning and generation with large language models (LLMs).**  
3. **Controllable image synthesis with Stable Diffusion.**  

For each domain we summarize the experimental setup, highlight the most useful hyper‑parameters, and share practical tips—especially around **identity initialization** and the newly introduced **multiplicative dropout**. The goal is to give you enough information to try BOFT on your own models without digging into all the theoretical details.

---  

## 1. Why Orthogonal Transformations Help  

Standard finetuning changes a weight matrix \(\mathbf{W}^{0}\) by adding or scaling parameters.  Orthogonal finetuning (OFT) instead multiplies \(\mathbf{W}^{0}\) on the left by an orthogonal matrix \(\mathbf{R}\) (\(\mathbf{R}^{\top}\mathbf{R}=\mathbf{I}\)).  This has two important consequences:

* **Angle preservation.** Pairwise angles between neuron vectors remain unchanged, so the geometry learned during pretraining is largely retained.  
* **Spectral‑norm preservation.** Because \(\|\mathbf{R}\mathbf{W}^{0}\|_{2} = \|\mathbf{W}^{0}\|_{2}\), training stays numerically stable and gradient explosion is avoided.

BOFT keeps these advantages while dramatically cutting down the number of free parameters by factorizing \(\mathbf{R}\) into butterfly components.

---  

## 2. Butterfly Factorization in a Nutshell  

A butterfly matrix is the product of \(\log_2 d\) sparse orthogonal layers, each layer having only \(\mathcal{O}(d)\) non‑zero entries.  The overall trainable parameter count becomes  

\[
\underbrace{\frac{1}{2}(b-1)d}_{\text{per component}} \times m
\quad\text{with}\quad m = \log_2\!\frac{d}{b},
\]

where \(b\) is the block size (commonly set to 2).  When \(b=2\), BOFT needs roughly \(d\log_2 d\) parameters—orders of magnitude less than a full orthogonal matrix.

### Identity initialization  
All butterfly components start as identity matrices (the underlying skew‑symmetric matrices are zero).  This guarantees that the network’s output is exactly the pretrained output at iteration 0, mirroring the “zero‑initialization” used in LoRA.

### Multiplicative Dropout  
Because BOFT’s update is multiplicative (\(\mathbf{R}\mathbf{W}^{0}\)), classic dropout on activations does not regularize the transformation directly.  Instead we randomly replace a fraction \(p_{1}\) of butterfly components and a fraction \(p_{2}\) of individual \(2b\times2b\) blocks inside those components with identity matrices during each training step.  Empirically, setting \(p_{1}=0.1\) and \(p_{2}=0.05\) works well across vision and language tasks.

## 3. Vision Transformers (ViT‑B/16) – Image Classification  

### Setup  
* **Base model:** ViT‑B/16 pretrained on ImageNet‑21k (384 × 384 resolution).  
* **Downstream datasets:** CIFAR‑100, Oxford‑Pets, and ImageNet‑V2 (a distribution shift benchmark).  
* **Finetuning head:** Replace the classification head with a new linear layer; all other weights stay frozen except for the orthogonal butterfly transformation applied *layer‑wise* to every self‑attention projection matrix (\(Q,K,V,O\)).  

### Hyper‑parameters that mattered  

| Parameter                | Value (recommended) |
|--------------------------|----------------------|
| Block size \(b\)         | 2 (i.e., pure butterfly factorization) |
| Number of components \(m\)| \(\log_2 d_{\text{head}}\) – e.g., for 768‑dimensional heads, \(m=9\) |
| Learning rate            | \(1\times10^{-4}\) (AdamW) |
| Weight decay             | \(0.05\) |
| Multiplicative dropout    | \(p_{1}=0.1,\; p_{2}=0.05\) |
| Training steps           | 20 k for CIFAR‑100, 50 k for ImageNet‑V2 |

### Results at a glance  

| Dataset        | Full fine‑tune | LoRA (4 % params) | OFT (full ortho) | **BOFT (≈ 0.5 % params)** |
|----------------|----------------|-------------------|------------------|----------------------------|
| CIFAR‑100      | 93.7 %         | 92.3 %            | 93.1 %           | **93.4 %**                 |
| Oxford‑Pets    | 96.5 %         | 95.8 %            | 96.1 %           | **96.3 %**                 |
| ImageNet‑V2    | 71.4 %         | 69.9 %            | 70.6 %           | **70.9 %**                 |

BOFT matches or exceeds OFT while using *roughly one tenth* the number of trainable parameters that OFT needs for a dense orthogonal matrix.

### Practical tip  
When adapting ViT, apply the same butterfly matrix across *all* projection heads within a transformer layer rather than learning a separate one per head. This reduces memory overhead and still yields dense information mixing because each head sees a different linear combination of the shared orthogonal transform.

## 4. Large Language Models – Text Classification & Generation  

### Setup  
* **Base model:** LLaMA‑7B (decoder‐only transformer).  
* **Tasks:** SST‑2 sentiment classification, GLUE MNLI, and zero‑shot style rewriting (a generation task).  
* **Finetuning strategy:** Insert an orthogonal butterfly module before every feed‑forward layer’s weight matrix (\(\mathbf{W}^{0}_{FFN}\)). The language modeling head remains untouched; only the shared butterfly transforms are trained.

### Hyper‑parameters  

| Parameter                | Value |
|--------------------------|-------|
| Block size \(b\)         | 4 (slightly larger blocks improve stability for very long sequences). |
| Components per layer     |\(\lceil \log_2 d / \log_2 b\rceil = 5\) for hidden size \(d=4096\). |
| Learning rate            | \(5\times10^{-5}\), linear warmup over first 500 steps then cosine decay. |
| Batch size               | 64 sequences of length 512 tokens each (GPU memory ≈ 30 GB). |
| Multiplicative dropout    | \(p_{1}=0.08,\; p_{2}=0.03\). |
| Training epochs          | 3 for classification, up to 200 k steps for generation fine‑tuning.|

### Performance snapshot  

| Task          | Full fine‑tune | LoRA (6 % params) | OFT (full ortho) | **BOFT (≈ 1 % params)** |
|---------------|----------------|-------------------|------------------|---------------------------|
| SST‑2 acc     | 95.6 %         | 94.8 %            | 95.3 %           | **95.4 %**                |
| MNLI avg      | 89.7 %         | 88.9 %            | 89.3 %           | **89.5 %**                |
| Generation BLEU† | –            | 29.8              | 30.5             | **30.7**                  |

†BLEU measured against reference rewrites; higher is better.

BOFT consistently outperforms LoRA despite using far fewer parameters, confirming that preserving orthogonality is especially beneficial when downstream tasks demand fine semantic control.

### Practical tip for LLMs  
Because LLMs have very deep stacks (>30 layers), it is helpful to *share* one set of butterfly components across several consecutive layers (e.g., every three layers). This reduces per‑step overhead while retaining enough flexibility; the paper reports negligible loss in quality compared with per‑layer independent components.

## 5. Stable Diffusion – Controllable Text‑to‑Image Generation  

### Setup  
* **Base model:** Stable Diffusion v1–4 (UNet backbone + text encoder).  
* **Control tasks:** Style transfer (“paintings”), color conditioning, and layout guidance via edge maps—exactly the settings used in the original OFT paper but now with BOST’s butterfly parameterization replacing the block-diagonal orthogonal matrix.

### Hyper‑parameters  

| Parameter                | Value |
|--------------------------|-------|
| Block size \(b\)         | 2 |
| Components per UNet block | \(m=6–8\), depending on channel width of that block |
| Learning rate            | \(1\times10^{-5}\); AdamW with cosine schedule |
| Guidance scale           | 7.5 (standard for diffusion inference) |
| Multiplicative dropout    | \(p_{1}=0.\!12,\; p_{2}=0.\!04\); applied only to early UNet stages where overfitting is most likely |

### Results summary  

- For *style transfer*, BOFT achieved an average CLIP‐based style similarity score of **0.84**, compared to **0.81** for OFT and **0.78** for full fine‑tuning.
- For *color conditioning*, classification accuracy on a downstream color‐identification probe rose from **71 %** (OFT) to **74 %** (BOFT).
- Training time increased by ~12 % relative to OFT due to extra matrix multiplications—but after finetuning all butterfly components can be folded into the frozen UNet weights, so inference latency remains unchanged.

### Practical tip  
When adapting diffusion models, freeze the text encoder entirely and only apply BOFT to *the attention projection matrices* within each UNet resolution block; this concentrates capacity where visual features are most mutable while keeping semantic alignment from the frozen language side intact.

## 6: Putting It All Together – A Minimal BOFT Script  

Below is a lightweight PyTorch snippet that shows how to wrap any linear layer with BOFT:

```python
import torch
import torch.nn as nn
import math

def cayley(skew):
    # Cayley transform: R = (I + Q)(I - Q)^(-1)
    I = torch.eye(skew.size(0), device=skew.device)
    return torch.linalg.solve(I - skew, I + skew)

class ButterflyComponent(nn.Module):
    def __init__(self, dim, block):
        super().__init__()
        self.dim = dim
        self.block = block
        # Each block stores its own skew-symmetric parameters
        self.skews = nn.ParameterList()
        for _ in range(dim // block):
            # lower-triangular part → skew-symmetric
            p = nn.Parameter(torch.zeros(block, block))
            self.skews.append(p)

    def forward(self):
        blocks = []
        for p in self.skews:
            # make skew-symmetric
            Q = p - p.t()
            R = cayley(Q)
            blocks.append(R)
        return torch.block_diag(*blocks)

class BOFTLayer(nn.Module):
    def __init__(self, dim, num_comp=6, block=2):
        super().__init__()
        self.components = nn.ModuleList([
            ButterflyComponent(dim, block) for _ in range(num_comp)
        ])

    def forward(self, W):
        R = torch.eye(W.size(0), device=W.device)
        for comp in self.components:
            R = comp() @ R   # multiply leftmost
        return R @ W

# Example usage on a pretrained linear weight:
pretrained_W = torch.randn(768, 3072)
boft = BOFTLayer(dim=768, num_comp=9, block=2)
finetuned_W = boft(pretrained_W)
```

Key points:

- Each `ButterflyComponent` builds an orthogonal block‐diagonal matrix via Cayley.
- Multiplication order mirrors Equation (4) in the paper (`R(m,b)`).
- At training time you can add multiplicative dropout by randomly replacing selected components/blocks with identity matrices before `forward`.

## 7. Takeaways for Practitioners  

1️⃣ **Parameter budget vs expressivity:** Choose a small block size (`b=2`) and let `m` grow until you hit your target parameter count (~\(d \log d\)). This yields dense transformations without sacrificing much expressivity.

2️⃣ **Start from identity:** The built‐in identity initialization guarantees zero deviation at step zero—no special warmup tricks needed beyond what you already do for other PEFT methods.

3️⃣ **Regularize with multiplicative dropout:** Simply turning off random butterfly components mimics dropout’s effect on *the transformation itself*, reducing overfitting especially on small datasets.

4️⃣ **Fold after training:** Once finetuned, multiply all learned butterfly components into their corresponding pretrained weight matrices once; inference runs exactly as fast as the original model.

5️⃣ **Layer sharing works:** Sharing one set of butterfly components across several layers can cut runtime overhead without hurting performance—a practical compromise when GPU memory is tight.

---  

## Closing Thoughts  

BOFT shows that you don’t need a full dense orthogonal matrix to reap its benefits—structured sparsity via butterfly factorization gives you almost all of them at a fraction of the cost. Across vision transformers, large language models, and diffusion pipelines, BOFT consistently matches or outperforms both full finetuning and existing PEFT baselines while staying well within tight parameter budgets.

If you’re already using LoRA or adapters in your workflow, give BOFT a spin: replace your low-rank adapters with a shared `BOFTLayer` per module type and watch your downstream accuracy climb without any extra inference latency.

Happy finetuning!

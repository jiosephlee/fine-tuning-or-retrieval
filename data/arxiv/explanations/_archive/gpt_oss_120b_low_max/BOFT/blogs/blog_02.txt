\title{Blogs about the Paper: "Parameter-Efficient Orthogonal Finetuning via Factorization"}

# From Block‑Diagonal to Butterfly: Making Orthogonal Finetuning Parameter‑Efficient  

Large foundation models (think GPT‑3, Stable Diffusion, or Vision Transformers) are powerful, but training them from scratch is a huge financial and environmental burden.  In practice we **finetune** a pretrained model on a downstream task, trying to keep the original knowledge while adapting to new data.  One recent finetuning paradigm—**Orthogonal Finetuning (OFT)**—does exactly this by left‑multiplying each linear layer with a learnable orthogonal matrix.  Because orthogonal transformations preserve pairwise angles between neurons, the pretrained representation stays largely intact, leading to better generalization and training stability.

### Why OFT Still Feels Heavy  

The idea is elegant, but an orthogonal matrix of size \(d\times d\) needs \(\Theta(d^{2})\) free parameters.  In modern vision or language models \(d\) can be several thousand, so the extra memory and compute quickly become impractical.  The original OFT paper tackled this by imposing a **block‑diagonal** structure:

\[
\mathbf{R}=\text{diag}(\mathbf{R}_{1},\mathbf{R}_{2},\dots,\mathbf{R}_{r}),\qquad
\mathbf{R}_{i}\in\mathbb{R}^{b\times b},\; br=d .
\]

Now we only store \(r\) small orthogonal blocks, reducing parameters to \(\mathcal{O}(bd)\).  Unfortunately the price is a strong inductive bias: dimensions that happen to fall in different blocks never interact, limiting expressivity.  Moreover, there is no principled way to pick the block size or pattern.

### Rethinking the Problem as Information Transmission  

Imagine the dense orthogonal matrix \(\mathbf{R}\) as a **communication network**: each row (output neuron) receives information from every column (input neuron).  If we factor \(\mathbf{R}\) into a product of sparse matrices,

\[
\mathbf{R}= \mathbf{B}_{m}\mathbf{B}_{m-1}\dots \mathbf{B}_{1},
\]

the factorization can be visualized as a layered graph with \(d\) nodes per layer and edges defined by non‑zero entries of each \(\mathbf{B}_{i}\).  Information flows from the first layer to the last through these edges.  To reconstruct a *dense* transformation we only need **dense connectivity** (every source can reach every sink) while using as few edges—as few trainable parameters—as possible.

A naïve dense connection would require \(d^{2}\) edges per layer.  However, clever graph topologies can achieve full connectivity with far fewer edges.  This is exactly what the **Cooley‑Tukey fast Fourier transform (FFT)** does: its “butterfly” graph shuffles information efficiently, using only \(\mathcal{O}(d\log d)\) edges.

### Enter the Butterfly Factorization  

The butterfly factor comes from the radix‑2 FFT recursion.  At each stage we pair up nodes, apply small orthogonal “mixing” blocks, and permute the results before the next stage.  Formally for a power‑of‑two size \(k\),

\[
\mathbf{B}^{F}(k)=
\begin{bmatrix}
\operatorname{diag}(\mathbf{d}_{1}) & \operatorname{diag}(\mathbf{d}_{2})\\[4pt]
\operatorname{diag}(\mathbf{d}_{3}) & \operatorname{diag}(\mathbf{d}_{4})
\end{bmatrix},
\qquad \mathbf{d}_{i}\in \mathbb{R}^{k/2}.
\]

Stacking such factors recursively yields a **butterfly matrix** \(\mathbf{B}(d)\) that is the product of \(\log_{2} d\) sparse components:

```
Stage 1:   B̃(d, 2)
Stage 2:   B̃(d, 4)
…
Stage log d: B̃(d, d)
```

Each component \(\tilde{\mathbf{B}}(d,k)\) is block‑diagonal with blocks of size \(k\), and every block follows the same sparse pattern as \(\mathbf{B}^{F}(k)\).  

Crucially, if each component is **orthogonal**, then their product remains orthogonal.  Enforcing orthogonality is simple: each \(2\times2\) block can be parameterized with a Cayley transform (or an explicit rotation angle), exactly as in OFT’s original block‑diagonal design.  By replacing scalar entries with small \(b\times b\) sub‑matrices we obtain a **block‑butterfly** that works for any hidden dimension.

### Orthogonal Butterfly Finetuning (BOFT)

Putting it together gives us **BOFT**:

1. **Initialize** every butterfly component as identity (Cayley’s skew‑symmetric matrix set to zero), guaranteeing zero deviation from the pretrained model at start.
2. **Forward pass** replaces the OFT update  
   \[
   \mathbf{z}= (\mathbf{R}\,\mathbf{W}^{0})^{\!\top}\!\mathbf{x}
   \]  
   with  
   \[
   \mathbf{z}= (\underbrace{\tilde{\mathbf{B}}^{b}_{(d,m)}\dots \tilde{\mathbf{B}}^{b}_{(d,1)}}_{\displaystyle \mathbf{R}(m,b)}\,\mathbf{W}^{0})^{\!\top}\!\mathbf{x},
   \]  
   where each \(\tilde{\mathbf{B}}^{b}_{(d,i)}\) is an orthogonal butterfly component.
3. **Parameter count:** each component contributes roughly \((b-1)d/2\) trainable values (the independent elements of its skew‑symmetric blocks). With \(m=\log_{2}(d/b)\) components we obtain  
   \[
   \text{\#params} = \mathcal O(d\,\log d),
   \]  
   far below OFT’s original \(\mathcal O(d^{2})\) and even more efficient than block‑diagonal OFT when a dense transform is needed.
4. **Multiplicative dropout:** during training we randomly replace a fraction of butterfly components—or individual blocks inside them—with identities, acting like dropout for multiplicative updates.

### Why Butterfly Beats Block‑Diagonal  

| Property | Block‑Diagonal OFT | BOFT (Butterfly) |
|----------|-------------------|------------------|
| **Expressivity** | Only intra‑block mixing; no cross‑block interaction | Dense connectivity after ≤ log d stages; can approximate any orthogonal matrix (theorem in paper). |
| **Parameters** | \(\mathcal O(bd)\); dense matrix needs \(b=d\). | \(\mathcal O(d\,\log d)\) for a fully dense orthogonal transform regardless of \(b\). |
| **Inductive bias** | Hard sparsity pattern; may miss classic transforms (FFT, Hadamard). | Structured sparsity mirrors FFT/DCT patterns → beneficial bias for natural signals. |
| **Training stability** | Good (preserves angles), but limited flexibility. | Same stability (orthogonal product), plus richer hypothesis space without extra cost. |

A simulation in the paper shows that with only a few hundred thousand parameters BOFT can approximate a random \(512\times512\) orthogonal matrix much better than any block‑diagonal configuration of comparable size.

### From Theory to Practice  

The authors tested BOFT on three kinds of foundation models:

- **Vision Transformers** on image classification and detection,
- **Large Language Models** on text generation and question answering,
- **Stable Diffusion**–style text‑to‑image diffusion models for controllable generation.

Across all benchmarks BOFT outperformed LoRA (low‑rank PEFT), traditional block‑diagonal OFT, and many recent adapters—sometimes by a large margin—while keeping the number of trainable parameters tiny.  After finetuning, the learned butterfly matrix can be folded into the original weight matrix, incurring *no* extra inference latency.

### Takeaways  

1. **Sparse products can be dense:** By chaining several carefully designed sparse orthogonal matrices we obtain a full dense orthogonal transform with only \(\mathcal O(d\,\log d)\) learnable numbers.
2. **Butterfly structures are more than FFT tricks:** Their graph topology guarantees dense information flow using minimal edges, making them perfect for parameter‑efficient PEFT.
3. **Orthogonal finetuning gets a boost:** BOFT keeps the nice spectral properties of OFT (spectral norm preservation → stable training) while dramatically shrinking its footprint.
4. **Inductive bias matters:** The butterfly’s built‑in resemblance to classic linear transforms seems to act as an implicit regularizer that improves generalization.

### Where We Still Have Work  

- BOFT introduces extra matrix multiplications during training, so its runtime overhead is modestly higher than plain OFT.
- The butterfly isn’t provably optimal for information transmission; future work could explore other network topologies from computer networking or graph theory.

Nevertheless, Orthogonal Butterfly offers a compelling recipe: replace bulky block‐diagonal orthogonal updates with a cascade of tiny butterfly layers, and you get an *expressive*, *stable*, and *parameter‑efficient* finetuning method that works across vision and language domains.

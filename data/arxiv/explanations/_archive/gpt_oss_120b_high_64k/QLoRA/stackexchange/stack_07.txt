\title{Stack Exchange of the Paper: "QLoRA: Efficient Finetuning of Quantized LLMs"}

### "How much memory do quantization constants actually consume before and after Double Quantization for a 65 B model?"
Question:
The paper reports that with blocksize = 64 each FP32 constant adds \(32/64 = 0.5\) bits per parameter.
After double‑quantizing (FP8 + second‑level FP32 constants with blocksize = 256), it claims a reduction to ~0.127 bits per parameter.

Could someone calculate:
* Total number of blocks for a 65 B parameter matrix assuming uniform block size.
* Memory usage for the first‑level constants in bytes before double‑quantization.
* Memory usage after double‑quantization.

A concrete example (e.g., one large linear layer from LLaMA‑65B) would help illustrate the savings.
Answer:
In **QLoRA** every weight tensor is stored in a 4‑bit type (NF4) and each **block** of $B$ elements needs its own scale factor  
$c∈ℝ^{FP32}$.  
If we flatten an arbitrary tensor $\mathbf W∈ℝ^{P}$ (where $P$ is the number of parameters in the tensor) into a long vector, the number of blocks required for the **first‑level** quantisation is  

$$
N_{1}= \Bigl⌈\,⟨P/B_1⟩⟩,
  B_1=64 .
$$

The original implementation stores one FP32 scale per block, i.e.  
$4 ⟨⟨bytes⟩⟩=32 ⟨⟨bits⟩⟩$.  
Consequently the extra cost per parameter before any further compression is  

$$
\dfrac {32}{B_1}= \dfrac {32}{64}=0.5 ⟨⟨bits⟩⟩,
$$

exactly what the paper states (“$32/64=0.5$ bits per parameter”).

---

### Double‑quantisation

Double‑quantisation treats those FP32 scales themselves as data and applies a **second** low‑precision quantisation:

* **Step A:** each first‑level scale $c^{FP32}_j$ ($j=1,\dots,N_1$) is stored as an **FP8** value ($8 ⟨⟨bits⟩⟩$).  
* **Step B:** an additional set of FP32 scales $\tilde c^{FP32}_k$ is needed for groups of $B_2=256$ consecutive first‑level scales, i.e.

$$
N_2=\Bigl⌈\,⟨N_1/B_2⟩⟩
  =\Bigl⌈\,⟨P/(B_1 B_2)⟩⟩ .
$$

The overall bit‑budget contributed by the two levels therefore becomes  

$$
{\rm bits}_{\,{\rm tot}}
   = {\underbrace {8/B_1}_{{FP8}\;\hbox{\small scales}}
     + {\underbrace {32/(B_1 B_2)}_{{second‐level}\;FP32\sizes}}
     }
   = \dfrac {8}{64}+ \dfrac {32}{16 384}
   ≈ 0.127 ⟨⟨bits⟩⟩ .
$$

The paper reports this value ($≈0.127 ${${{\rm bits}/{param}}}$), confirming our derivation.

---

## How many blocks does a **65 billion‑parameter** model contain?

If we pretend that all $P\simeq6.5×10^{10}$ parameters belong to a single flattened tensor and use the “first‑level’’ block size $B_1=64$,  

$$
N_1=\Bigl⌈\,⟨6.5×10^{10}/64⟩⟩≈1.016×10^9 ⟨blocks⟩ .
$$

For the second level with $B_2=256$,  

$$
N_2=\Bigl⌈\,⟨N_1/256⟩⟩
  =\Bigl⌈\,⟨6.5×10^{10}/16 384⟩⟩≈3.96×10^6 ⟨sub‑blocks⟩ .
$$

(The two “ceiling’’ operations would only add at most one partially filled block, which is negligible compared with billions of full blocks.)

---

## Memory occupied by the scale constants

### Before double‑quantisation  

Each first‑level scale occupies four bytes, so  

$$
M_{\mathrm {pre}}
  = N_1·4 ⊂bytes≃(1.016×10^9)·4≃4.06×10^9 ⊂bytes≃3.78 GiB .
$$

Equivalently,

$$
M_{\mathrm {pre}}
  = P·\dfrac {0.5}{8}
  ≃6.5×10^{10}·0.0625≃4.06 GB .
$$

### After double‑quantisation  

The storage consists of two pieces:

| component | amount | unit |
|---|---|---|
| FP8–encoded first‑level scales | $N_1·1 ⊂byte$ | ≃1016 MB |
| Second‑level FP32 scales | $N_2·4 ⊂bytes$ | ≃15 MB |

Summing them gives  

$$
M_{\mathrm {post}}
  =(N_1+4 N_2) ⊂bytes
  ≈(1.016×10^9+15×10^6) ⊂bytes
  ≈1.032×10^9 ⊂bytes≈0.96 GiB .
$$

In other words, double‑quantisation shrinks the auxiliary scale storage from **≈ 3 GiB** down to **≈ 1 GiB**, a saving close to **3 GB**, exactly what the authors claim (“average reduction … approximately 3 GB for a 65 billion‐parameter model”).

---

## Concrete illustration on a single large linear layer

Consider “the biggest’’ dense projector in LLaMA‑65 B – the query/key/value projection whose shape is usually  

$\displaystyle H_{\mathrm {hid}}×H_{\mathrm {hid}}=(8192×8192)$,

so it contains  

$\displaystyle P_\ell=(8192)^2≃6.71×10^7$
(~67 million).

Using the same block sizes ($B_­１=64,\; B­­２=256)$,

*First‑level blocks*  

$\displaystyle N^{(\ell)}_１=\big⌈P_\ell/64\bigr⌉≃⌈6.71×10^7/64⌉≃１048⁡576.$  

The raw FP32 scales would therefore need  

$\displaystyle M^{(\ell)}_\mathrm {pre}=N^{(\ell)}₁·4 ⊂bytes≃４１９４３０４ ⊂bytes≃４MiB.$

*After double‑quantisation*  

$\displaystyle N^{(\ell)}₂=\big⌈N^{(\ell)}₁/256\bigr⌉≃４０９６.$  

Memory becomes  

$\displaystyle M^{(\ell)}_\mathrm {post}=N^{(\ell)}₁·１ ⊂byte+ N^{(\ell)}₂·４ ⊂bytes≈１０４８５７６＋１６３８４≈１０⁶⁰⁰⁰　⊂bytes,$ 

i.e. roughly ten hundred megabytes—a dramatic reduction compared with naïve storage.

\title{Stack Exchange of the Paper: "QLoRA: Efficient Finetuning of Quantized LLMs"}

### What exactly does QLoRA finetune – the original pretrained weights or only the LoRA adapters?
Question:
I understand that QLoRA back‑propagates gradients through a frozen 4‑bit quantized model into Low‑Rank Adapters (LoRA). However, I'm unclear whether any of the original pretrained weights are ever updated during training, or if all updates happen exclusively on the adapter matrices \(\mathbf{L}_1\) and \(\mathbf{L}_2\). Could someone clarify how QLoRA treats the base model parameters versus the adapter parameters during finetuning?
Answer:
**Short answer:**  
During a QLoRA run **only the Lo RA adapter matrices $\bf L_1$ and $\bf L_2$ (and their scaling factor $s$) are updated**.  
All pretrained parameters $\bf W$ – which are stored in a 4‑bit NormalFloat (NF4) format – stay **frozen** throughout training.  
The loss gradient is nevertheless propagated *through* these frozen, de‑quantised weights so that it can reach the adapters, but no gradient is accumulated for $\bf W$ itself.

---

### How QLoRA treats the two sets of parameters

From the paper (Section “QLoRA Finetuning”) the forward pass of a linear layer looks like  

$$
\bY^{\text{BF16}}
=
\bX^{\text{BF16}}\,
\underbrace{\operatorname{doubleDequant}(c_1^{\text {FP32}},c_2^{\text {k-bit}},\,\bf W^{\,\text{k-bit}})}_{\displaystyle \bf W^{\,\,BF16}}
+
\bX^{\text{BF16}}\;\bf L_1^{\,BF16}\,\bf L_2^{\,BF16}.
$$  

* The term $\bf W^{\,BF16}$ is obtained by **de‑quantising** the stored NF4 matrix $\bf W$ (and its two levels of quantisation constants).  
* The second term is exactly the Lo RA low‑rank contribution that we wish to learn.

When computing gradients we need  

$$
\dfrac{\partial {\cal L}}{\partial {\bf L}_1},
\qquad
\dfrac{\partial {\cal L}}{\partial {\bf L}_2},
$$  

but **not**  

$$
\dfrac{\partial {\cal L}}{\partial {\bf W}}\,. 
$$  

The paper explicitly states:

> “For parameter updates only the gradient with respect to the error for the adapters weights $\dfrac{\partial E}{\partial {\bf L}_i}$ are needed, and *not* for 4‑bit weights $\dfrac{\partial E}{\
partial {\bf W}}$. However, the calculation of $\dfrac{\partial E}{\
partial {\bf L}_i}$ entails the calculation of $\dfrac{\partial {\bf X}}{
partial {\bf W}}…”.

Thus **the frozen weight matrix participates in back‑propagation as a static linear operator**, enabling an error signal to flow into the adapters, but its own gradient is discarded – it never gets an optimizer step nor any saved state. In practice this is implemented by setting ``requires_grad=False`` on every module of the base model while leaving ``requires_grad=True`` on the Lo RA modules (a pattern identical to classic Lo RA).

---

### Why freeze the base model?

1. **Memory efficiency** – storing optimiser state (e.g., Adam moments) for billions of parameters would explode GPU memory usage. By freezing all of $\bf W$, optimiser state is kept only for the tiny adapter set (usually \< 0.5 % of total parameters), which makes it possible to finetune a 65 B–parameter LLM on a single 48 GB GPU.  
2. **Quantisation stability** – 4‑bit NF4 values have been chosen primarily for *inference* accuracy; updating them with noisy low‑precision gradients would quickly erode their information content. Keeping them static preserves their carefully calibrated representation.  
3. **Parameter‑efficient learning** – Lo RA has been shown repeatedly to recover full‑model performance when applied everywhere in a transformer stack, provided enough adapters are used (the authors observe that “adapters at every network layer” are essential). QLoRA simply inherits this property while adding the benefit of a compressed weight storage format.

---

### What ends up being stored after training?

After a QLoRA run you have:

* The original pretrained checkpoint (still in NF4), unchanged.  
* A set of learned Lo RA tensors $\{{\bf L}_1^{(l)},\,{\bf L}_2^{(l)}\}_{l=1}^{L}$ (one pair per targeted layer) saved in BF16 or FP16.  
* Optionally a scalar $s^{(l)}$ per layer if you use Lo RA’s scaling factor.

Many deployment pipelines merge these adapters into an “effective” weight matrix  

$$
\btilde W = {\bf W}+s\,{\bf L}_1\,{\bf L}_2,
$$  

but this merging is *post‑training* and does not affect how training was performed.

---

### Bottom line

QLoRA follows exactly the same philosophy as ordinary Lo RA: **the massive pretrained backbone stays immutable**, while **the tiny low‑rank adapters absorb all learning signals**. The only extra machinery introduced by QLoRA is an on‑the‑fly de‑quantisation step that lets gradients flow through a 4‑bit stored backbone without ever updating it. This design is what enables billions‑parameter models to be fine‑tuned with a modest GPU budget while preserving full 16‑bit fine‑tuning performance.

\title{Stack Exchange of the Paper: "QLoRA: Efficient Finetuning of Quantized LLMs"}

### How does NFk ensure an exact zero representation while still using all \(2^k\) bits?
Question:
Quantizing a symmetric normal distribution normally yields no exact zero value because the bins are centered away from zero. The paper mentions creating an asymmetric data type by estimating \(2^{k-1}\) negative and \(2^{k-1}+1\) positive quantiles then merging them and dropping one duplicate zero.

Could someone walk through this process with an example (say \(k=3\)) and show how zero ends up being represented without sacrificing any codebook entry?
Answer:
In NormalFloat (NF<sub>k</sub>) the goal is to build a **code‑book** whose entries are the centroids of equally‑likely intervals under a standard normal distribution&nbsp;$N(0,\sigma^{2})$.  
If we simply split the whole distribution into $2^{\,k}$ intervals (`quantile–quantization`) each interval has probability  

$$
\Delta=\dfrac{1}{\,2^{\,k}+1\,}.
$$

The centroids are obtained from successive quantile points  

$$
q_{i}= \tfrac12\Bigl(
Q_{X}\!\bigl(\tfrac{i}{\,2^{\,k}+1\,}\bigr)+
Q_{X}\!\bigl(\tfrac{i+1}{\,2^{\,k}+1\,}\bigr)\Bigr),
\qquad i=0,\dots ,\,2^{\,k},
\tag{★}
$$

where $Q_{X}$ denotes the inverse CDF of a standard normal.  
Because $\displaystyle\dfrac{i}{\,2^{\,k}+1}\neq\tfrac12$ for any integer $i$, none of these centroids coincides with the mean&nbsp;$\mu=0$; consequently an *exact “zero”* value is missing and, if we kept this symmetric construction, we would have to waste one bit pattern for some other value.

The authors therefore **break the symmetry** before applying&nbsp;(★).  
They decide how many intervals should lie on each side of the mean:

* left‑hand (negative) side  $N_{-}= 2^{\,k-1}$;
* right‑hand (positive) side  $N_{+}= N_{-}+ 1$.

Thus there are **one more interval on the positive side** than on the negative side,
and together they contain  

$$
N_{-} + N_{+} - \mathbf{dup}
   =( 2^{\,k-1})+( 2^{\,k-1}+1)-\mathbf{dup}
   = 2^{\,k}
$$

distinct centroids once we delete the duplicated centre point (“dup”).

Because  

$$
N_{-} + N_{+} - \mathbf{dup}= 56 ,
$$

but more concretely  

$$
(N_{-}+N_{+})-\mathbf{dup}=25 .
$$

---

### Step I – split probabilities  

The whole Gaussian mass $[-\infty,\infty]$ carries unit probability.
We reserve half‑the‑mass ($\tfrac12$) for each sign.

For the **negative** half   ($[-\infty,\mu]$)  
the target probability per interval is  

$$
\Delta_{-}= \dfrac{\tfrac12}{N_{-}}
          = \dfrac{\tfrac12}{4}
          = \tfrac18 .
$$

Hence its cumulative‑probability boundaries are  

$$
p^{-}_{[j]}= j\,\Delta_{-},
   \qquad j=0,\dots ,4,
   \;\text{i.e.~}
   [\,0,\;\tfrac18,\;\tfrac28,\;\tfrac38,\;\tfrac48] .
$$

For the **positive** half   ($[\mu,\infty]$)  
the width per interval is  

$$
\Delta_{+}= \dfrac{\tfrac12}{N_{+}}
          = \dfrac{\thalf}{5}
          = \dfrac{10}{100}
          = \tFrac15 .
$$

so its boundaries become  

$$
p^{+}_{[j]}=
      \thalf+j\,\Delta_{+},
      \qquad j=0,\dots ,5,
      \\[·]
      =[\,\half,\;\tsevenoverten,\;\dots ,\: 1] .
$$

---

### Step II – obtain centroids  

Each interval’s centroid lies halfway between its bounding probabilities,
so we take  

```
negative centroids :   c^-_j   = Φ^{-1}(p^- [j] + Δ_- / ₂)
                      j=0,…,3
positive centroids :   c^+_j   = Φ^{-1}(p^+[j] + Δ_+/₂)
                      j=0,…,4 .
```

Because $\Phi^{-1}(\half)=\mu=0,$  
the **middle positive interval** ($j=0$, $[\half ,\: \half+\Delta_+]$)
has centroid precisely  

$$
c_0^+=\Phi^{-1}\!\Bigl(\thalf+\dfrac{\Delta_+}{2}\Bigr)
       =\Phi^{-1}\!\Bigl(\thalf+\dfrac15\times\thalf\Bigr)
       =\Phi^{-1}(\half)=0 .
$$

All other centroids come in opposite pairs,
e.g.\ $\Phi^{-1}(\tfr18)\approx-\cdots,$   
$\Phi^{-11}(\sevenovereight)\approx+\cdots.$

Consequently we have obtained **nine** raw code‑values,
but two of them are identical zeros – one coming from the “negative’’ list
(the interval just below $\mu$) and one coming from the “positive’’ list
(the interval just above $\mu`).  
Removing *one* duplicate leaves us with exactly  

$$
9 - 1 = 8
$$ 

compatible code‑words.

---

### Step III – build the Final Code‑Book  

After discarding one copy‑of‑zero we sort all remaining centroids:

| binary index | value |
|--------------|-------|
| 000 | $\approx -6.09$ |
| 001 | $\approx -4.60$ |
| 010 | $\approx -3.21$ |
| 011 | $\approx -?$ |
| 100 | **0** |
| 101 | $\approx +?$ |
| 110 | $\approx +?$ |
| 111 | $\approx +?$ |

(The outermost magnitude depends on how far we stretch “[$-\max ,\: \max ]’’ when dequantising; here it has been chosen so that the most extreme code covers roughly three standard deviations.)

Each **3 bit** pattern maps uniquely onto one entry,
so every possible pattern is used – none “wasted”.  
Because every interval holds identical probability mass under a standard normal distribution,
the resulting datatype satisfies the *information‑theoretic optimality* condition described in Equation&nbsp;(★) while **guaranteeing an exact representation of&nbsp;$w=0$.**

---

### Why No Bit Is Lost  

The naive symmetric construction would give us eight non‑zero centroids;
adding an extra centre point would raise us to nine symbols,
but our *asymmetric* split already produced nine symbols before any removal.
Dropping **the duplicated centre** therefore does **not** reduce entropy:
we started with nine equally probable symbols,
two of them being indistinguishable ($+\epsilon$, $-\epsilon\rarr0)$).
After merging them we retain eight *distinct* symbols,
each still representing exactly one eighth of the Gaussian probability mass.
Hence every bit pattern participates and no capacity is sacrificed –
the only change is that now one pattern corresponds to literal Zero instead
of a tiny non‑zero value.

---

### Connection back to QLoRA  

When QLoRA stores a weight block it first rescales it so that its empirical absolute maximum coincides with the outermost NormalFloat entry;
then it looks up which centroid $q_i$ lies closest to each scaled value,
stores *the corresponding bit pattern*, and later dequantises by reversing
the scaling constant.
Because our NormalFloat table contains an *exact* Zero entry,
any weight component that happens ever‐to be exactly Zero—such as padding,
biases set deliberately to Zero or sparsified matrices—will be represented
without error.
At the same time every possible $k=3$ pattern remains usable,
which explains how **NF<sub>3</sub> achieves both an exact zeropoint and full utilisation**
of its $8$ bit patterns, exactly as claimed in Section “4‑bit NormalFloat Quantization”.

In short, by allocating **one more positive bucket than negative buckets**, forcing together two adjacent buckets around $\mu$ so that their midpoint equals $\mu$ itself, then discarding one duplicate $\mu$ entry, NF<sub>k</sub> creates an asymmetric yet perfectly equiprobable code book containing a genuine Zero while still employing all $2^k$ bit patterns. This neat trick removes any “dead’’ codeword without compromising information‑theoretic optimality, which is why QLoRA’s NF<sub>k</sub> datatype works so well in practice.​

Chapter 2: Quantisation Fundamentals for Neural Networks  

# Definition of Quantisation and De‑quantisation Operations  

Quantisation is the process of mapping a high‑precision numeric tensor onto a representation that occupies fewer bits. In the context of neural networks this typically means converting a tensor stored in 32‑bit floating‑point format (FP32) into a lower‑bit integer or floating‑point format such as 8‑bit integers (Int8) or 4‑bit custom types. The conversion is performed by first scaling the original values so that they fit into the dynamic range supported by the target data type, then rounding each scaled value to the nearest representable code.  

Formally, let $\mathbf{X}^{\text{FP32}}\in\mathbb{R}^{b\times h}$ denote a weight matrix in full precision. To obtain an Int8 representation we compute a **quantisation constant** $c^{\text{FP32}}$ based on the absolute maximum magnitude of the tensor:  

\[
c^{\text{FP32}} \;=\;\frac{127}{\operatorname{absmax}\!\bigl(\mathbf{X}^{\text{FP32}}\bigr)} .
\]

The integer tensor is then obtained by rounding the scaled values:  

\[
\mathbf{X}^{\text{Int8}} \;=\;\operatorname{round}\!\bigl(c^{\text{FP32}}\cdot \mathbf{X}^{\text{FP32}}\bigr).
\tag{1}
\]

The inverse operation, *de‑quantisation*, reconstructs an approximate FP32 matrix by dividing by the same constant:

\[
\operatorname{dequant}\!\bigl(c^{\text{FP32}},\mathbf{X}^{\text{Int8}}\bigr)
    \;=\;\frac{\mathbf{X}^{\text{Int8}}}{c^{\text{FP32}}}
    \;\approx\;\mathbf{X}^{\text{FP32}} .
\tag{2}
\]

Equation (1) shows that every element of $\mathbf{X}$ is first rescaled so that the largest absolute entry maps onto the extreme integer value \(+127\) or \(-127\). Equation (2) demonstrates that during inference or training we typically de‑quantise back to a higher precision (often BF16 or FP16) before performing arithmetic such as matrix multiplication. In practice, frameworks such as QLoRA store only the low‑bit representation $\mathbf{W}^{\text{k‑bit}}$ together with its per‑block scale(s), recompute $\mathbf{W}^{\text{BF16}}$ on‑the‑fly during forward and backward passes, and never materialise full‑precision copies on device memory.



# Uniform Scaling Versus Non‑Uniform Scaling Strategies  

The simplest scaling rule uses a *global* constant $c$ derived from the absolute maximum over an entire tensor, as described above. This **uniform scaling** treats every element equally regardless of its local statistics. While easy to implement, uniform scaling suffers when the weight distribution contains *outliers*: one or few entries with unusually large magnitude can dominate $\operatorname{absmax}$, forcing all other values into a very narrow range where many integer codes are never used. Consequently most bins become underpopulated and effective resolution for typical weights drops dramatically.  

A **non‑uniform scaling** strategy assigns distinct constants to different portions of a tensor. By partitioning $\mathbf X$ into several *blocks*—contiguous slices after flattening—each block receives its own scale $c_i$. The blockwise operation can be written as  

\[
\mathbf X = \bigcup_{i=1}^{n} \mathbf X_i,\qquad
c_i = \frac{s_{\max}}{\operatorname{absmax}(\mathbf X_i)},
\]

where $s_{\max}$ denotes the maximal representable integer value for the chosen low‑bit type (e.g., $127$ for Int8). Each block $\mathbf X_i$ is then quantised independently using its own $c_i$, following Eq (1).  

This approach offers two advantages directly observed in QLoRA’s design:  
1. **Outlier mitigation** – Because an extreme value influences only its own block’s scale, other blocks retain finer granularity.  
2. **Higher effective precision** – By adapting scales locally, more integer codes are effectively utilised within each region of weight space, reducing overall distortion especially for distributions that deviate from perfect uniformity.



# Blockwise (Groupwise) Quantisation to Mitigate Outlier Effects  

Blockwise—or *groupwise*—quantisation is precisely the non‑uniform approach described above, specialised for neural network weights which are typically stored as large dense matrices. In QLoRA blocks are defined by a fixed *blocksize* $B$, meaning each row‐wise segment containing $B$ consecutive elements shares one scale parameter $c_i$. Let $\mathbf W \in \mathbb R^{d_{\!in}\times d_{\!out}}$ be a weight matrix; after flattening it yields a vector $\mathbf w \in \mathbb R^{d_{\!in} d_{\!out}}$. The number of blocks is  

\[
n = \frac{{d_{\!in} d_{\!out}}}{B},
\]

assuming $B$ divides the total number of elements exactly (a common engineering practice). For each block we compute an independent scale factor $c_i$ as described earlier and store its 32‑bit floating constant alongside the low‐bit codes.  

Although introducing per–block scales adds overhead—each scale consumes extra bits—the overhead can be reduced further through **double quantisation** (see below). More importantly, empirical results from QLoRA demonstrate that with modest blocksize values such as $B=64$, 4‑bit NormalFloat (NF4) approximates full 16‑bit performance while keeping memory consumption dramatically lower than naïve uniform 4‑bit schemes would allow.



# Common Low‑Bit Data Types Used in Practice  

Several low‐precision formats have become standard when compressing LLM weights:

* **Int8** – An unsigned–signed integer format covering $[-127,127]$. This datatype benefits from mature hardware support and simple linear scaling (Eq 1).  
* **Int4** – A four‑bit signed integer offering 16 discrete levels within a symmetric range (e.g., $[-7,7]$). The coarse granularity makes it susceptible to larger distortion unless paired with very fine blockwise scales.  
* **FP8 / Float8** – An eight‐bit floating‐point representation consisting of a sign bit, exponent bits and mantissa bits (commonly 5/2 layout). While preserving dynamic range better than pure integers, FP8 still incurs non‑linear mapping errors when approximating highly concentrated distributions such as normal weight tensors.  
* **NormalFloat (NFk)** – A family introduced by QLoRA expressly tailored for zero‐centered normal distributions common in pretrained LLMs. For \(k=4\) bits we obtain **NF4**, an information‐theoretically optimal discretisation where each bin contains an equal fraction of probability mass under $\mathcal N(0,1)$. The NFk codebook is computed once offline using analytic Gaussian quantiles:

\[
q_i = \tfrac12
      \Bigl[\,Q_X(\tfrac{i}{2^{k}+1}) + Q_X(\tfrac{i+1}{2^{k}+1})\,\Bigr],
      \qquad i=0,\dots ,2^{k}-1,
\tag{3}
\]

with \(Q_X(\cdot)\) denoting the inverse cumulative distribution function (the *quantile function*) of $\mathcal N(0,1)$. Because pretrained weights are approximately normally distributed after mean centering (§ below), mapping them onto this codebook yields minimal average distortion even at only four bits per parameter.

The key distinction between NFk and naïve Int4/FP4 lies in **optimal bin placement**: Int4 uses uniformly spaced integers whereas NFk places codepoints at statistically balanced positions respecting the underlying Gaussian shape.



# Error Metrics Introduced by Compression  

When compressing weights from full precision to a low bitwidth we inevitably introduce an approximation error often referred to as *quantisation noise*. For any element \(x \in \mathbb R\) with corresponding recovered value \(\hat x = \operatorname{dequant}(c,\operatorname{quant}(c,x))\), the per‑element error is  

\[
e = x - \hat x .
\tag{4}
\]

Two broad phenomena dominate this error:

1. **Quantisation noise** – Even when every value lies comfortably inside the representable range, rounding onto discrete codepoints incurs a deviation bounded by half a step size of the local scale. When scales differ across blocks this bound varies locally.
2. **Overflow / clipping** – If an input exceeds what can be represented after scaling—particularly likely under uniform scaling—the algorithm clips it to the maximal integer code (+127 or –128). This creates a *bias* because large magnitude values are permanently truncated rather than merely rounded.

QLoRA evaluates these errors indirectly through downstream downstream tasks such as language modelling perplexity and instruction following accuracy. Empirical tables in the paper show that using NF4 dramatically reduces perplexity compared with FP4 or Int4 at identical bitwidths—a concrete indication that NF4’s balanced bins lower average \(e^2\) across all weights.


# Information–Theoretic Perspective: Entropy Maximisation via Equal Bin Populations  

From an information theory standpoint a discrete representation conveys at most $\log_2 M$ bits where \(M=2^{k}\) denotes the number of distinct codes available for a $k$-bit datatype. To *maximise* usable information for a fixed \(M,\) one should allocate these codes such that each bin captures an equal share of probability mass under the source distribution—this yields maximal Shannon entropy for that discretisation.

Assuming pretrained weight vectors follow an approximately zero‑mean Gaussian distribution $\mathcal N(0,\sigma^2)$—a claim supported empirically in QLoRA’s Appendix—the optimal strategy proceeds as follows:

* **Standardise** – Rescale every weight vector so its empirical standard deviation matches unity ($\sigma=1$), effectively mapping it onto $\mathcal N(0,1)$.
* **Equalise bin probabilities** – Choose codepoints \(q_i,\ i=0,\dots ,M-1,\) such that
  \[
    P(X < q_{i+1}) - P(X < q_{i}) = \tfrac1M,
    \quad X \sim \mathcal N(0,1).
  \]
  Solving these equations gives exactly Eq (3), which defines NFk.
* **Zeropoint handling** – A perfectly symmetric Gaussian discretiser would place one code exactly at zero—but due to an even number (\(M=2^k​​)\) there would be two zeros if we mirrored negative–positive halves independently. To retain only one unique zero while still occupying all \(M-1\) remaining codes we construct an *asymmetric* set wherein negative side receives \(2^{k-1}\) bins and positive side receives \(2^{k-1}+1.\)* This design guarantees both maximum entropy *and* exact preservation of zero-valued entries—a critical feature when many weights are exactly zero after pruning or regularising steps.

By aligning code assignments with natural weight statistics rather than naïvely spacing them uniformly across an arbitrary numeric interval, NFk achieves significantly lower expected distortion per Eq (4). This theoretical advantage translates into measurable gains reported throughout QLoRA’s experiments—for instance improved perplexity on language modelling benchmarks and restored accuracy after finetuning even when base models are stored entirely in 4‑bit.

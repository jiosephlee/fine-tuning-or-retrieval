\title{Stack Exchange of the Paper: "Byte Latent Transformer: Patches Scale Better Than Tokens"}

### Can you explain the cross‑attention mechanism used in the encoder and decoder with an example?
Question:
Both encoder and decoder contain cross‑attention blocks similar to Perceiver (Section 5.2). The description includes queries initialized by pooling bytes in a patch and keys/values coming from byte representations $h_{l,i}$. I'm unsure how these queries are constructed in practice (max‑pooling vs average pooling?) and how masking ensures each query only attends to its own patch bytes. A concrete step‑by‑step example with a simple three‑byte patch would help.
Answer:
**Cross‑attention in BLT – how it works and a tiny worked example**

In *Byte Latent Transformer* every byte is first turned into a low‑dimensional embedding $e_i∈𝔼ℝ^{h_{\mathcal E}}$ (the plain byte embedding plus optional n‑gram hash embeddings). A stack of *local* transformer layers processes these embeddings and produces intermediate hidden states
$h_{\ell,i}$ for layer $\ell$.  
After each such transformer layer a **cross‑attention block** aggregates the
byte‑level information belonging to a *patch* $p_j$ into a single *latent*
representation $P_{\ell,j}$ that will later be consumed by the global latent
transformer $\mathcal G$.

The design follows the Perceiver’s input cross‑attention, but because BLT already
knows which bytes belong to which patch it can restrict every query so that it
only “looks at” its own bytes. The two ingredients that realise this are

* **how the queries $Q$ are created** – they start from a pooled summary of the
bytes inside the patch;
* **a binary mask** that tells the attention mechanism which keys/values belong
to the current patch (or conversely which patches belong to a given byte in
the decoder).

---

### Query construction

The paper states explicitly (Section 5 “BLT‑Specific Hyperparameters”) that

> “We use **max‑pooling** to initialise the queries for the first cross‑attention
> layer in the local encoder.”

Thus for a given patch $p_j$ whose constituent bytes are
$\{\,i\,|\,i∈f_{bytes}(p_j)\,\}$, we take all corresponding hidden
vectors $h_{\ell,i}$ (for $\ell=0$ these are simply the embeddings $e_i$)
and apply an element‑wise maximum:

$$
q^{(0)}_j=
\toperatorname{maxpool}\Big(\,\bigl\{
    h_{\ell,i}\mid i∈f_{bytes}(p_j)
\bigr\}\Big)
∈𝔽𝔹𝕽 ^ {h_{\mathcal E}} .
$$

Any other pooling operator, e.g. average or sum, could be plugged in,
but all experiments reported in the paper used *max* because it preserves the
most salient signal among the bytes – an intuitive analogue of “the most
informative character dominates a short word”.

The pooled vector is then linearly projected into $U$ heads:

$$
Q^{(u)}_{\ell,j}=W^{(u)}_{q}\,(q^{(\!ℓ)}_j),  u=1,\dots,U_{\mathcal E},
$$

where $W_q^{(u)}∈𝔽𝕽 ^ {\,h_{\mathcal E}/U_{\mathcal E}× h_{\mathcal E}}$.  
For deeper cross‑attention layers ($ℓ>0$) we simply reuse the already updated
$P_{ℓ−1,j}$ as the query source instead of re‐pooling—the model has already distilled information from previous rounds of local processing and from the global transformer step that follows every encoder iteration.



### Masked attention between queries and keys/values

For every byte position $i$ we compute keys and values in exactly the same way as in ordinary multi‑head self‑attention:

$$
K^{(u)}_{ℓ,i}=W_k^{(u)}⟨h_{ℓ,i}⟩,\qquad 
V^{(u)}_{ℓ,i}=W_v^{(u)}⟨h_{ℓ,i}⟩ .
$$

The crucial difference is **the mask**:
for a fixed patch $p_j$ we build a binary matrix

$$
M_{j,i}^{(u)}
=
   \begin{cases}
      0            & \textbf{if } i∈f_{bytes}(p_j),\\[4pt]
      -∞           & \textbf{otherwise},
   \end{cases}
$$

and add it to the raw attention logits before softmax. In practice this is done by setting those illegal logits to a large negative constant so that after softmax their weight becomes zero.
Because BLT knows exactly which indices belong to which patch during data loading,
this mask can be precomputed once per batch and fed directly into FlexAttention,
the implementation used for dynamic masks described in § 5 (“Encoder Multi‐Headed Cross‐Attention”).

With masked logits we obtain standard attention weights

$$
A_{ℓ,j,i}^{(u)}
=
   {\displaystyle 
    {\exp{\Big(
        (Q_{ℓ,j}^{(u)})^\top K_{ℓ,i}^{(u)}
        /√d_k + M_{j,i}^{(u)}
       ⟩}}
    }
    {
        {\displaystyle 
         ∑_{i′} 
          ⟨exp{
               ((Q_{ℓ,j}^{(u)})^\top K_{ℓ,i′}^{(u)})
               /√d_k + M_{j,i′}^{(( u))}
             }⟩}
    } .
$$

These weights sum only over those $i$
belonging to $p_j$.  

The attended output for head $u$ is then

$$
O_{ℓ,j}^{(u)}
  = ∑_i A_{ℓ,j,i}^{(( u))} V_{ℓ,i}^{(( u))}.
$$

After concatenating all heads we apply an output projection $W_o$
and add a residual connection:

$$
P_{ℓ,j}=P_{ℓ−1,j}
          + W_o {\rm concat}_u O_{ℓ,j}^{(( u))}.
$$

These $P_{ℓ,j}$ become the *latent* inputs fed into $\mathcal G$;
after an autoregressive step of the global transformer they return an updated set of patch representations $o_j$, which will later be consumed by the decoder.



### Decoder cross‑attention (the opposite direction)

In the decoder role reversal is symmetric: now **bytes query** while **patches provide keys/values**.
The initial queries are simply the last encoder hidden states,
$d_0=h_{L_\mathcal E ,i}$.
For any later decoder layer $ℓ$,  

* Queries:           $q$:     ​​​​​​​​​​​​​​  $\displaystyle Q_\ell ^ {( u )}(i)=W_q ^ {( u )} d_\mathbf ^ {(\!Ⓛl(!^) _i )},$

* Keys/Values:
  $$K_\mathbf ^ {( u )}_l(j)=W_k ^ {( u )} {\bf𝒟}_C(o_j), V _ l ^ {( u )}(j)=W_v ^ {( u )}{𝖣}_C(o _ j).$$  

Here ${𝖣}_C(\cdot)$ denotes splitting each global latent vector into  
$U_\mathbfD$
heads before projection.
The mask is now defined **per byte** instead of per patch:

$$
M _{\mathrm {dec}} (i , j)= 
   ⎧⎨⎩ 
     0            & ⎧⎨⎩ ⎪⠀if ⁡⠀ i ∈ f^{-1}_{bytes}( p _ j ),⎭⎬⎫;\;
    -∞             & ⎧⎨⎩ ⎪⠀otherwise .⎭⎬⎫ .
$$ 

So every byte can attend only to *its own* parent patch.
The subsequent softmax/weighting steps are identical to those described above,
producing an updated byte representation 
$d_i ^ {( ℓ+1 )}=B_ ℓ(i)$,
which then goes through a lightweight decoder transformer layer before repeating or finally projecting onto logits over 256 possible next bytes.



### A tiny numerical walk‑through

Consider a single three‐byte patch “abc”.  
Assume an embedding dimensionality $h_\mathbfE =4$
and identity projection matrices so we can focus on pooling and masking alone.

| Byte | Embedding $e_i=h_{0,i}$ |
|------|-------------------------|
| ‘a’ | [ 0.2 , ‑0.1 ,  0.05 ,  0   ] |
| ‘b’ | [ 0.3 ,  0   , ‑0.05 ,  0.1 ] |
| ‘c’ | [ 0.1 , ‑0.2 ,  0    ,  –  ] |

**Step 1 – Query creation (max‐pooling).**  
Take an elementwise maximum across the three rows:

$$
q_j=
[\,{\color{blue}0.3}, {\color{blue} 0}, {\color{blue} 0.05}, {\color{blue} 0.1}\,].
$$

A linear projection yields our sole head’s query vector  
$\displaystyle Q=q_j W_q^\top ≃ q_j.$  

**Step 2 – Keys / Values** (identity means $K_i=e_i$, $V_i=e_i).  

**Step 3 – Masking**  
The mask matrix for this single query/prefix looks like  

$$
M=
[\;
    {\underbrace{
        [\,0,\,-∞,\,-∞]
    }_
     {〈byte ‘a’〉}},
    {\underbrace{
        [−∞,\,0,\,-∞]
    }_
     {〈‘b’〉}},
    {\underbrace{
        [−∞,−∞,\,0]
    }_
     {〈‘c’〉}}
],
$$  

so illegal interactions receive score “minus infinity’’ before softmax.

**Step 4 – Attention scores**  
Logits before softmax are dot products divided by $\sqrt{d_k}=2$:  

* with ‘a’: $\displaystyle Q·K_a/2=(0.3·0.2+⋯)/2≈+ 0\.015.$  
* with ‘b’: $\displaystyle ≈+ 0\.045.$  
* with ‘c’: $\displaystyle ≈− 0\.015.$  

After softmax over these three numbers we obtain roughly  
$\alpha_a≈30%$, $\alpha_b≈55%$, $\alpha_c≈15%.$  

**Step 5 – Attended output**  
Weighted sum of values:  

$$
O=α_a e_a + α_b e_b + α_c e_c ≈ 
[\,0.~25,\;-~02,\;~00.\!02,\;.07\,].
$$  

A final linear projection gives $W_o O≈O.$ Adding back the residual gives  

$$
P_1 = q_j + O ≈ [\,0.~55,\;.−02,\;.07,\;.17\,],
$$  

which now carries information from all three bytes while still representing just this one patch.

In higher layers ($ℓ>1)$ the same procedure runs again—now using $
P_{ℓ−1,j}$ as query rather than re‐pooling—so information can flow back and forth between local byte processing and global latent modelling through repeated cross‐attention steps.



### Why this design matters

* **Locality + flexibility:** Because masks enforce one–to–one correspondence,
each latent token summarises only its own region rather than all bytes,
dramatically reducing attention cost compared with vanilla Perceiver where every latent sees everything.
* **Dynamic patches:** The same code works regardless of how many bytes belong to a given patch—
entropy or whitespace based segmentation merely changes which indices appear in each mask.
* **Hierarchical refinement:** By interleaving ordinary transformer layers with masked cross‐attention,
BLT lets low‐level byte patterns be enriched locally before being distilled upward,
and subsequently lets global context influence future low‐level refinements through decoder cross‐attention.
* **Implementation ease:** The binary masks can be generated once when data are loaded,
and FlexAttention fuses masking with efficient kernel launches so there is no runtime overhead compared with plain multi‐head attention.



### TL;DR

In BLT’s encoder each patch obtains its query by **max‐pooling** over its constituent byte embeddings (the paper’s default). Keys and values come from per‐byte hidden states produced by preceding local transformer layers.
A precomputed binary mask guarantees that every query attends only to those keys/values belonging to its own patch—everything else receives zero weight before softmax.
The decoder swaps roles: every byte queries its parent patch’s latent representation using exactly the same masked mechanism.
Stacking these blocks yields an iterative procedure where fine‐grained byte information is repeatedly aggregated into patches and then broadcast back down, achieving both computational efficiency and hierarchical modelling power akin to—but more locally constrained than—the original Perceiver scheme.

Chapter 1: Introduction to Context Windows in Large Language Models  

# What is a context window? Definition and typical sizes in popular LLMs  

In modern Transformer‑based language models each token is processed together with a set of positional encodings that indicate its order in the input sequence. The maximum number of tokens that can be simultaneously encoded and attended to is called the **context window**. Formally, if a model’s attention mechanism can handle at most $L$ positions, then any input longer than $L$ tokens must be truncated or split before it can be fed into the model.  

The size $L$ is dictated by the model’s architecture and training regime.  Early large language models such as GPT‑4~\cite{gpt4} and the initial releases of LLaMA~\cite{llama2} were trained with $L$ around a few thousand tokens. In particular, LLaMA‑2 explicitly limits its context length to $4096$ tokens~\cite{llama2}.  Other contemporary models adopt roughly similar limits – many open‑source instruction‑tuned families also use $4\!k$–$8\!k$ tokens as their default maximum length.  

Because the model’s learned rotary position embeddings (RoPE) are only calibrated over this range, positions beyond $L$ have never been observed during pretraining. Consequently, when an input exceeds $L$, the new position indices are “out‑of‑distribution” relative to what the model has seen, leading to degraded predictive quality.~\cite{pi}  

# Impact of limited context on tasks such as few‑shot learning, code generation, and agentic reasoning  

The constraint imposed by a finite context window reverberates across many downstream applications.  
In **few‑shot learning**, a prompt typically contains several exemplars followed by a test query. When each exemplar is a paragraph or block of code, even a modest number of demonstrations can quickly exhaust a $4\!k$ token budget~\cite{Huang2023FewerIM}. If the number of examples needed exceeds this budget, the model must discard or truncate earlier demonstrations, drastically reducing its ability to infer patterns from demonstrated data.  

**Code generation** often requires maintaining long namespaces or multiple file definitions within a single prompt so that variable scopes and function signatures remain consistent across long sessions~\cite{codegeneration}. When code exceeds $L$, crucial symbols become invisible to later parts of the generation process, causing broken references or missing imports.  

**LLM agents**—systems that iteratively reason over observations and actions—need to keep an internal record of past steps so that each decision can depend on its full history~\cite{park2023generative,madaan2023selfrefine}. If an agent’s memory is cut off after $L$ steps, it may lose essential contextual clues from early interactions, leading to myopic behavior or repeated errors.  

Thus extending the effective span over which an LLM can attend directly expands its utility for these high‑impact scenarios.  

# Historical progression of context window sizes from early Transformers to recent models like LLaMA‑2  

The original Transformer architecture introduced for machine translation used relatively short sequences ($\leq512$ tokens) because GPU memory was scarce and training data consisted mainly of sentence pairs~\cite{vaswani2017attention}. As model scale grew and hardware became more capable, practitioners began allocating larger buffers for input tokens. By the time generations such as GPT‑3 appeared, standard context lengths were commonly set at $2048$ tokens~\cite{gpt3}.\footnote{Exact numbers vary across public releases but serve as an indicative milestone.*}  

The release of **LLaMA‑2** marked another step forward by providing strong performance while retaining a modest $4096$ token limit~\cite{llama2}. Researchers quickly identified this limit as a bottleneck for emerging applications requiring extensive reasoning across many pages of text or code.\footnote{A footnote marker is used only for illustration within this pedagogical text.*}  

To push beyond this bound without retraining massive models from scratch, several works explored **fine‑tuning on longer sequences**. By exposing pre‑trained weights to curricula containing documents up to $\sim128\,000$ tokens—an order of magnitude larger than the original window—methods such as LongLoRA~\cite{longlora}, Position Interpolation (PI)~\cite{pi}, YaRN~\cite{yarn}, and related scaling techniques demonstrated successful extensions up to roughly $128\,k$ tokens.~\cite{zhang2024soaring,liu2023scaling} However these approaches still fell far short of handling inputs measured in millions of tokens due primarily to three obstacles described below:  
1) **Catastrophic values** introduced by untrained position indices cause out‑of‑distribution dynamics that hinder convergence during fine‑tuning.~\cite{pi}  
2) **Data scarcity**—public corpora rarely contain documents longer than $10^5$–$10^6$ tokens—makes it difficult to assemble training batches at extreme lengths without excessive computation.~\cite{longlora}  
3) **Attention dispersion**—as attention spreads thinly over ever more positions—the signal associated with any single token becomes weaker, which degrades performance even on short subsequences after extreme extensions.~\cite{pi}  

These limitations motivated researchers to search for more principled ways of adapting positional embeddings rather than simply scaling them uniformly across all dimensions and positions.\footnote{The discussion remains faithful to challenges explicitly reported in the LongRoPE paper.*}  

# High‑level overview of strategies attempted to enlarge the window  

Several broad families of techniques have been pursued for extending an LLM’s effective context length:

* **Retrieval‑augmented architectures** attach an external memory module that stores past hidden states or raw text chunks and retrieves relevant portions at inference time~\cite{longllama,wang2023augmenting,borgeaud2022improving}. These methods typically require architectural changes such as cross‑attention heads interfacing with the external store and therefore differ fundamentally from pure positional adaptations.

* **Attention mask engineering** modifies how attention scores are computed so that distant tokens receive reduced but non‑zero influence without blowing up computational cost~\cite{han2023lminfinite,streamingllm,parallelwindow}. By restructuring attention patterns—for example through locality‑sensitive hashing or sliding windows—these approaches reuse existing parameters while mitigating quadratic scaling issues.

* **Fine‑tuning with altered position embeddings** directly changes the underlying RoPE base value or introduces learnable offsets before retraining on longer sequences~\cite{codellama,xiong2023effective,labscaling}. While effective up to several hundred thousand tokens after substantial resource investment (hundreds of GPU hours), they still rely on massive amounts of long textual data.

* **Positional interpolation techniques** keep the original network weights intact but reshape RoPE angles so that new position indices map back into the range seen during pretraining.  
    - **Linear Position Interpolation (PI)** uniformly scales every RoPE dimension by a factor equal to the target extension ratio $s=\frac{L'}{L}$~\cite{pi}. This simple mapping often “crowds” nearby positions together when $s$ is large,\ leading to confusion between adjacent tokens.\footnote{Citing PI’s strengths/weaknesses directly draws from Section 1\.}  
    - **Neural Tangent Kernel (NTK) based interpolation** distributes interpolation pressure across dimensions based on their frequency \(\theta_i=\theta^{-2i/d}\), applying less scaling (\(\lambda = s^i\)) to high‑frequency dimensions and more scaling to low‑frequency ones~\cite{ntk,dynamicntk}. This reduces crowding but typically caps at about \(4\times\) extension without fine‑tuning.~\cite{ntk}  
    - **YaRN** groups dimensions into three frequency bands—high‐frequency extrapolation (\(\lambda =1\)), mid‐frequency NTK scaling, and low‐frequency linear interpolation—thereby combining three strategies into one hand‐crafted schedule~\cite{yarn}. While YaRN markedly improves over pure PI at moderate extensions (\(8\times$, \(16\times$\)), its grouping decisions are manually tuned per model family and may become suboptimal for newer architectures.\footnote{\(^{*}\)All citations refer precisely to works mentioned in LongRoPE’s reference list.*}

These interpolation schemes expose two key sources of *non‑uniformity* within RoPE that had not yet been fully exploited:  
1) **Dimensional non‑uniformity**, i.e., each rotary dimension encodes information at a different frequency so it tolerates different amounts of scaling.\footnote{See Eq.~(1)–(2) in LongRoPE for formal expressions.*}  
2) **Positional non‑uniformity**, i.e., early tokens receive disproportionately high attention scores during inference so they benefit from less aggressive scaling.\footnote{Empirically confirmed in Sec.~2.*}

LongRoPE builds upon these observations by conducting an *evolutionary search* over per-dimension rescale factors $\lambda_i$ together with an optional “no‐interpolation” prefix length $\hat n$.  The search respects monotonic constraints motivated by NTK theory (\(\lambda_i \le \lambda_{i+1}\)) while evaluating candidates using language modeling perplexity on short samples drawn from PG19~\cite{pg19}.   This process yields two practical benefits:
- A superior initialization for subsequent fine‑tuning phases—minimizing catastrophic loss when moving toward extremely long contexts.
- An **\(8\times\)** extension achievable *without any fine‐tuning*, thereby demonstrating that an appropriately non‐uniform mapping already captures much of the required positional information beyond what linear PI provides.

Finally, LongRoPE adopts a **progressive extension strategy**: first adapt RoPE for modest lengths ($128k$, then $256k$) followed by brief fine‐tuning (only $\sim1000$ gradient steps), then apply another round of non‐uniform interpolation to reach `2048k` (\(512\times\) relative expansion).  An additional post‐hoc search realigns RoPE for shorter targets ($4k$, $8k$) so that performance does not regress on standard benchmarks—a known issue when high dimensionality becomes overly compressed after massive extensions.~\cite{pi}

Collectively these ideas illustrate how understanding *where* positional information resides inside RoPE enables systematic extension far beyond prior limits while preserving both short–context competence and long–context capability—all within the same architectural envelope without major code modifications.~\cite{LongRoPEPaper}

2. Positional Embeddings in Transformers – Focus on Rotary Position Encoding (RoPE)

Transformers process an input sequence purely by pairwise interactions between token representations.  
Because these interactions are *permutation‑invariant*, a model has no way to tell whether token A comes before token B unless an explicit notion of position is supplied.  Position information therefore constitutes an essential complement to the self‑attention mechanism.  The following sections develop a systematic view of how order is injected into Transformers, contrast the classic schemes with modern rotary encoding, and explain why Rotary Position Encoding (RoPE) has become the de‑facto standard for many large language models (LLMs).

---

## Self‑Attention Mechanism Without Explicit Order Information  

In a vanilla multi‑head self‑attention layer each token vector $\mathbf{x}_n\in\mathbb{R}^{d}$ is projected into queries $\mathbf{q}_n$, keys $\mathbf{k}_n$, and values $\mathbf{v}_n$.  For every pair $(i,j)$ an attention score is computed as

\[
\alpha_{ij}= \frac{\mathbf{q}_i^{\top}\mathbf{k}_j}{\sqrt{d_\text{head}}}.
\]

The softmax over $j$ produces weights that are applied to $\mathbf{v}_j$.  Crucially, $\alpha_{ij}$ depends only on the *content* of $\mathbf{x}_i$ and $\mathbf{x}_j$; there is nothing in this formula that distinguishes “token 1 followed by token 2’’ from “token 2 followed by token 1”.  Consequently the raw self‑attention operation treats any permutation of the input tokens identically.  

To make attention sensitive to word order, *positional* vectors must be added or combined with $\mathbf{x}_n$ before projection into query/key/value spaces.  This step breaks permutation invariance and enables each head to attend differently based on where tokens appear in a document.



## Absolute Positional Embeddings (Sinusoidal) vs Learned Embeddings  

Early Transformer implementations introduced two families of absolute positional representations:

* **Fixed sinusoidal embeddings** – each position $n$ receives a deterministic vector built from sines and cosines at geometrically decreasing frequencies \cite{rope}.  For dimension $i$ ($0\le i<d/2$),

\[
\begin{aligned}
p_{2i}(n) &= \cos\!\bigl(n\,\theta_i\bigr),\\[0.2em]
p_{2i+1}(n)&= \sin\!\bigl(n\,\theta_i\bigr),
\end{aligned}
\qquad 
\theta_i = \theta^{-2i/d},
\]

where $\theta$ denotes a base constant (the default value used throughout this work is $10\,000$).  
This construction matches Equation (1) below and guarantees that every dimension carries a different oscillation period, allowing distant tokens to be distinguished even when their raw indices differ vastly.

* **Learned embeddings** – instead of fixing $\theta$, one can allocate a learnable lookup table $\mathbf{E}\in\mathbb{R}^{L_\text{max}\times d}$ where $L_\text{max}$ denotes a maximum supported length during pretraining.  Each row $\mathbf{E}_n$ captures whatever pattern is most useful for downstream tasks—but it also restricts the model strictly below $L_\text{max}$ because unseen indices would yield undefined vectors during inference.



Both families share an *absolute* character: they attach a single vector solely based on a token’s index $n$, independent of surrounding tokens.



## Relative Positional Encodings and Their Limitations  

A complementary design direction augments *pairwise* interactions instead of assigning each token its own static vector.  
In short, an additional bias term $b_{ij}=g(i-j)$ depending only on the offset $(i-j)$ gets added inside the dot product prior to softmax so that attention scores become aware of *relative* distances between query and key positions.  

While such schemes naturally generalize across lengths—because any offset appears at multiple absolute positions—they nevertheless encounter a practical obstacle highlighted throughout this work: when extending an LLM well beyond its original training horizon many *new* offsets appear that were never observed during pretraining or fine‑tuning.  These unseen distances lead to **catastrophic values**, i.e., out‑of‑distribution behavior that hampers convergence during further training \cite{pi}.  The same phenomenon motivates our focus on learning *how* existing rotational angles should be reshaped when many fresh token indices become active.



## Derivation of Rotary Position Encoding (RoPE)

Rotary Position Encoding embeds coordinates directly into the *attention* computation rather than appending an extra vector onto token representations \cite{rope}.  
For a token situated at index $n$, its RoPE vector consists precisely of interleaved cosine–sine pairs :

\[
\underbrace{\bigl[\;\cos(n\theta_0),\,\sin(n\theta_0),\,\cos(n\theta_1),\,\ldots,\,
\cos(n\theta_{d/2-1}),\,\sin(n\theta_{d/2-1})\;\bigr]}_{\text{Equation (1)}}.
\tag{1}
\]

Key ingredients deserve special emphasis:

| Symbol | Meaning |
|--------|---------|
| $d$ | Dimensionality of the model’s hidden state (often multiples of $64$). |
| $n$ | Zero‑based integer denoting a token’s sequential offset inside a document. |
| $\theta_i=\theta^{-2i/d}$ | Frequency associated with dimension $i$, obtained via a power law decay governed by base $\theta$. |
| $\beta = \theta^{2/d}$ | A compact notation for “frequency root” used later when rescaling angles (\S 5). |

The **rotational** viewpoint arises because applying Eq.\,(1) corresponds mathematically to rotating each query/key vector within its own two‑dimensional subspace $(2i,2i+1)$ by angle $n\,\theta_i$.  When two rotated vectors meet inside an inner product,

\[
(\operatorname{Rot}(n)\,\mathbf{q})^{\!\top}(\operatorname{Rot}(m)\,\mathbf{k})
= \mathbf{q}^{\!\top}\bigl[\operatorname{Rot}(m-n)\bigr]\, \mathbf{k},
\]

the resulting term depends **only** on their relative distance $(m-n)$—precisely what makes RoPE simultaneously an *absolute* encoding (it knows `$n$') yet yields *relative*-aware attention scores without extra bias terms.



### Why Rotations Matter for Long Sequences  

Each subspace rotates at its own speed:
- Low‐index dimensions ($i$ small) possess **high frequencies** ($\theta_i$ large).  
  Hence their angles vary rapidly with $n$, allowing fine discrimination among nearby tokens.
- High‐index dimensions ($i$ large) evolve **slowly**, acting like coarse “global” clocks capable of distinguishing far‑apart positions without becoming overly crowded.

When we attempt to extend context length dramatically—e.g., up through millions of tokens—the high‑frequency dimensions would otherwise wrap around many times, leading multiple distant positions onto nearly identical angular values (“crowding”).  Conversely low‐frequency dimensions remain well behaved even at extreme distances because their periods are billions long.


## Implementation Details in Common Libraries  

Most modern deep‑learning frameworks expose RoPE through a dedicated routine called `apply_rotary_pos_emb`.  The high‑level workflow follows three steps:

1. **Pre‑compute cosine/sine tables**  
   For every supported length $L_{\max}$ one builds two tensors,
   $
   C_{i,n}= \cos(n/\beta^{\,i}),\
   S_{i,n}= \sin(n/\beta^{\,i}),
   $
   where index $i$ runs over half‐the hidden dimension ($0,\dots,d/2{-}1$).  
   In practice these tables live either on CPU memory or GPU cache for fast lookup.
   
2. **Split queries/keys into even–odd halves**  
   Query matrix $\mathbf Q \in \mathbb R^{B\times L\times d}$ gets reshaped into $(B,L,d/2,2)$ where last axis stores $(x_{\text{even}},x_{\text{odd}})$.
   
3. **Elementwise rotation**  
   For each head,
   \[
   \begin{aligned}
   q_{\text{even}}' &:= q_{\text{even}}\odot C - q_{\text{odd}}\odot S ,\\
   q_{\text{odd}}' &:= q_{\text{even}}\odot S + q_{\text{odd}}\odot C .
   \end{aligned}
   \]
   Identical operations are carried out on keys $\mathbf K$.  
   After this step one proceeds with ordinary scaled dot–product attention using $(q',k')$.
   
Because only elementwise multiplications replace addition or concatenation steps found in traditional absolute schemes,
the overall computational cost remains essentially unchanged.
Consequently models extended via LongRoPE retain **the original architecture** except for substituting these tiny rotation kernels—a point emphasized repeatedly throughout Section 3 (“Models extended via LongRoPE retain the original architecture with minor modifications”).

The HuggingFace Transformers library implements exactly this procedure under `modeling_xxx.py` (`apply_rotary_pos_emb`), making it straightforward for practitioners to swap into existing LLaMA 2 or Mistral checkpoints without rewriting larger parts of code.



## Strengths of RoPE for Long‑Range Dependencies  

The empirical studies presented later (§ 4–§ 6) reveal several concrete advantages stemming from Rotatory design:

* **Implicit Relative Awareness** – By folding position offsets directly inside query–key inner products,
MoE-free attention naturally distinguishes far apart tokens without auxiliary bias tables.
This eliminates extra parameters while preserving geometric meaning across arbitrary distances.
  
* **Frequency‑Adaptive Scaling** – High‑frequency dimensions capture short‐range minutiae whereas low frequencies encode very coarse trends.
When extending context windows one typically rescales rotation angles differently per dimension.
Theoretical analyses such as Neural Tangent Kernel theory (\S 5) argue precisely why lower frequencies tolerate larger rescaling factors ($\lambda_i = s^{\,i}$) while higher frequencies should remain nearly untouched ($\lambda_i\simeq1$).  

* **Reduced Catastrophic Values** – The main obstacle identified in Section 3 (“non‑uniformities”) concerns massive overflow caused by naïvely interpolating all dimensions uniformly (PI).  
LongRoPE remedies this by searching *non‑uniform* rescale factors $\lambda_i$ together with an initial untampered segment length $\hat n$.  By preserving early tokens unchanged—and allowing high‐frequency dimensions little scaling—the method mitigates crowding effects leading to smoother perplexity curves even up to $2048k$ tokens.
  
* **Compatibility With Fine‑Tuning** – Because rotary rotations sit inside attention rather than being concatenated externally,
they impose almost no architectural change.
Fine‑tuning procedures described (§ 5) can adjust only these scalars while keeping every other weight frozen,
making large extensions feasible with merely *thousand* gradient steps—a dramatic reduction compared with full‐model retraining at million‐token lengths.
  
* **Empirical Robustness Across Datasets** – Tables 4–7 demonstrate that LLaMA 2–7B and Mistral–7B equipped with LongRoPE consistently achieve lower perplexities than baselines such as plain PI or YaRN across diverse corpora (PG19, Proof Pile, Books3).  
Even under extreme evaluation lengths (> 2048k), passkey retrieval accuracy stays above $90$\% – evidence that rotary encoding sustains discriminative power throughout massive spans.

### Takeaway  

Rotary Position Encoding embeds positions through smooth trigonometric rotations whose frequencies vary systematically across dimensions.
This simple mathematical trick endows vanilla self‑attention heads with built‑in relative reasoning while preserving efficiency.
When combined with principled non‑uniform rescaling—searching suitable per‑dimension factors ($\lambda_i$) and optionally leaving early tokens untouched (\(\hat n>0\))—RoPE becomes powerful enough to stretch modern LLMs well past two million tokens without sacrificing performance at conventional short contexts.
The success reported throughout this study underscores why RoPE has emerged as the de facto positional backbone for today’s large language models.

3. Existing Approaches to Extending Context Windows  

# Fine‑tuning on Longer Sequences – Data Scarcity and Computational Cost  

A straightforward way to enlarge a language model’s usable context is to continue training it on sequences that are longer than the original window length $L$. When a model is exposed repeatedly to token positions beyond $L$, its internal parameters learn how to attend to and predict tokens situated at those novel indices. Recent work has demonstrated that this strategy can push the effective window size from a few thousand tokens up to roughly $128\,\text{k}$ tokens \cite{longlora,pi,yarn,zhang2024soaring,liu2023scaling}.  

However, two practical hurdles quickly become dominant once we aim far beyond $128\,\text{k}$ tokens. First, publicly available corpora contain only a limited supply of documents whose tokenized length exceeds $1\,\text{M}$. The longest ubiquitous benchmark datasets—PG‑19 \cite{pg19}, Proof‑pile \cite{proof-pile}, Books3 \cite{pile}—rarely provide enough examples for stable gradient estimates at such extreme lengths. Consequently the optimizer sees very few instances of the newest position indices during fine‑tuning, which hampers generalisation.  

Second, training transformers with quadratic attention costs $\mathcal O(L'^2)$ makes each step substantially more expensive as $L'$ grows. Extending from $4\,\text{k}$ to $256\,\text{k}$ already demands orders of magnitude more GPU memory and wall‑clock time than conventional pre‑training regimes; extending toward millions of tokens would require prohibitive numbers of GPU hours even when using efficient parallelism techniques \cite{cube}. These two constraints—the paucity of ultra‑long text data and the steep computational overhead—explain why prior fine‑tuning approaches have stalled around the $100\,\text{k}$ token mark.


# Position Interpolation (PI): Linear Scaling of Rotation Angles  

Rotary Position Embedding (RoPE) encodes each token’s absolute index $n$ as a set of sinusoidal rotations applied dimensionwise \cite{rope}. For embedding dimension $d$, a single RoPE vector can be expressed as  

\[
\bigl[\cos(n\theta_0),\,\sin(n\theta_0),\,\cos(n\theta_1),\,\sin(n\theta_1),\,\dots,\,
\cos(n\theta_{d/2-1}),\,\sin(n\theta_{d/2-1})\bigr],
\tag{1}
\]  

where $\theta_i=\theta^{-2i/d}$ defines a decreasing frequency spectrum (the default base $\theta=10\,000$).  

When extending the context from $L$ tokens to a larger target length $L'$, Position Interpolation (PI) simply rescales every rotary angle by a uniform factor equal to the extension ratio  

\[
s=\frac{L'}{L}.
\]  

In practice this amounts to dividing every argument inside the cosine/sine functions by $\lambda=s$, yielding the unified formulation  

\[
[\cos(\tfrac{n}{\lambda}),\, \sin(\tfrac{n}{\lambda}),\, 
 \cos(\tfrac{n}{\lambda^{{1}}}),\, \sin(\tfrac{n}{\lambda^{{1}}}),\, 
 \dots,\,
 \cos(\tfrac{n}{\lambda^{d/2-1}}),\, \sin(\tfrac{n}{\lambda^{d/2-1}})].
\tag{2}
\]  

Because $\lambda$ is identical for all dimensions, PI compresses the entire spiral of positional codes into a tighter region of the unit circle. The resulting “crowded” representation makes it difficult for attention heads to discriminate nearby token indices—a problem that grows rapidly as $s$ increases. Empirically PI performs acceptably only for modest extensions (e.g., $s=2$); once $s$ reaches four or higher its perplexity degrades sharply.


# Neural Tangent Kernel–Based Scaling – Unequal Dimension‑wise Interpolation/Extrapolation  

The Neural Tangent Kernel (NTK) viewpoint treats RoPE’s sinusoidal components as Fourier features encoding the scalar input $n$ \cite{ntk,dynamicntk}. Information theory suggests that low‑frequency dimensions (\emph{i.e.,} those with large $\theta_i$) capture coarse positional structure while high‑frequency dimensions encode finer granularity. Consequently applying a single uniform rescale factor misallocates interpolation pressure across dimensions.  

NTK‑aware methods therefore assign a dimension‑dependent scale  

\[
\lambda_i = s^{\,i},
\]  

where $i$ indexes over half‑the embedding dimensions ($i = 0,\dots,d/2-1$). Smaller indices correspond to higher frequencies; they receive a smaller $\lambda_i$, meaning less compression (“interpolation”). Larger indices get larger $\lambda_i$, allowing more aggressive compression (“extrapolation”). This heterogeneous treatment spreads positional distortion more evenly across frequencies and mitigates crowding in the highest–frequency slots. A dynamic variant further adjusts $\lambda_i$ depending on the current sequence length during inference \cite{dynamicntk}, enabling modest extensions ($s \le 4$) without any additional fine‑tuning. Nonetheless even under NTK scaling the attainable non‑fine‑tuned stretch remains bounded well below a million tokens.


# YaRN Method – Three‑Group Frequency–Based Scaling Scheme  

YaRN builds upon both linear PI and NTK ideas by recognizing that not all frequency bands benefit equally from a single interpolation rule \cite{yarn}. It partitions the set of RoPE dimensions into three contiguous groups according to their intrinsic frequency:

* **High‑frequency group** – retains its original scale ($\lambda=1$, i.e., pure extrapolation).  
* **Mid‑frequency group** – adopts an NTK‐style power law $\lambda_i = s^{\,i}$, providing graded compression between high‐ and low‐frequency ends.  
* **Low‑frequency group** – follows pure linear PI ($\lambda=s$), applying uniform downscaling across these coarser components.

The exact boundaries between groups are chosen manually based on empirical validation experiments performed on each model family. By allocating a gentle treatment to high frequencies while compressing low frequencies more aggressively, YaRN achieves stronger performance than raw PI or static NTK when extending windows up through several tens of thousands of tokens. However because its grouping rule is handcrafted rather than data driven, it may miss optimal allocations for newer architectures or dramatically larger extensions.


# Limitations Observed at Extensions Beyond ≈ 128 k Tokens  

Empirical studies reported throughout the literature consistently indicate that none of the aforementioned schemes sustain quality past roughly one hundred thousand tokens. When evaluated on long‐form language modelling benchmarks such as PG‑19 or Proof‑Pile, models employing PI quickly suffer perplexity blowups after modest stretches; NTK continues flattening performance only up until about fourfold expansion ($L'≈16$ k when starting from $4$ k); YaRN’s three–group strategy begins deteriorating once it reaches contexts far larger than its designed operating range—for example its perplexity spikes already near $7$ k when attempting an $8$ k evaluation window in non‐fine‐tuned settings (c.f., Fig.\,\ref{fig:non-ft}). Consequently all prior works converge around an upper bound close to $128$ k tokens if they rely solely on positional interpolation together with limited fine‑tuning resources.


# Fundamental Obstacles Identified by the Authors  

The inability of existing approaches to breach the $128\,\text{k}$ limit stems from three intertwined challenges articulated in the introduction:

* **Catastrophic values from untrained positions**  
  When an LLM’s context window is enlarged dramatically—say from $4\,000$ tokens toward over one million—more than ninety percent of absolute indices have never been seen during pretraining. Those fresh positions lack calibrated rotary angles within RoPE’s learned spectrum, producing outliers (“catastrophic values”) that poison attention scores and impede convergence during subsequent fine‑tuning ⟨\(^{[1]}\).

* **Scarcity of ultra‑long training corpora**  
  Datasets containing passages longer than one thousand thousand tokens remain rare or synthetically constructed at great expense. Without abundant examples spanning the target length $L'$, gradient updates cannot reliably teach a model how best to exploit newly introduced positional codes ⟨\(^{[2]}\).

* **Attention crowding leading to degradation on short contexts**  
  Extending context dilutes each token’s contribution across an ever larger set of pairwise interactions; attention weights become spread thinly over millions of positions rather than concentrating around nearby neighbours crucial for short‐range reasoning ⟨\(^{[3]}\). This “attention crowding” manifests as noticeable drops in performance even when evaluating within the original ($4\,000$ ‑token) window after naïve interpolation has been applied.


Taken together, these obstacles explain why previous techniques plateau near \( \sim10^5 \) tokens despite methodological refinements such as NTK adaptations or Yu↑R​N’s three–group scheduling. Overcoming them requires both a more expressive way of reshaping RoPE across dimensions *and* an efficient strategy for progressively adapting models without demanding massive ultra‑long corpora—a motivation that drives the LongRoPE method introduced later in this textbook.

4. Empirical Analysis of Non‑Uniformities in Positional Interpolation  

# Preliminary  

Understanding how large language models encode the order of tokens is essential before delving into the empirical observations made by the authors. Modern transformer‑based language models typically rely on rotary position embeddings (RoPE) because they allow the attention mechanism itself to incorporate positional information without requiring an explicit additive bias. For a token placed at discrete position index \(n\), its RoPE vector can be expressed compactly as  

\[
\bigl[\cos (n\theta _0),\;\sin (n\theta _0),\;\cos (n\theta _1),\;\dots ,\;\cos \bigl(n\theta _{d/2-1}\bigr),\;\sin \bigl(n\theta _{d/2-1}\bigr)\bigr]\!,
\]  

where \(d\) denotes the hidden dimension of the model, each pair \((\cos ,\sin )\) corresponds to one two‑dimensional rotation plane, and \(\theta _i=\theta ^{-\,2i/d}\) specifies the rotation frequency associated with dimension \(i\). The scalar \(\theta\) is called the base value of RoPE; existing large language models adopt a default base of \(10\,000\).  

When researchers wish to enlarge a model’s context window from its original length \(L\) to a longer length \(L'\), they introduce an **extension ratio**  

\[
s=\frac{L'}{L}\!,
\]  

which quantifies how many times longer the new window is relative to the pretrained one. Extending the context window inevitably creates novel position indices that have never been seen during pretraining, which can destabilize training if handled naïvely. A common remedy is **positional interpolation**, i.e., modifying the angular frequencies so that newly introduced positions are effectively “compressed” into the range on which the model was originally trained.  

All recent positional‑interpolation schemes can be written under a unified formulation that rescales each rotation angle by a factor that may depend on both the RoPE dimension \(i\) and a global scaling function \(\lambda (\beta )^i\):  

\[
 
    \bigl[\cos \!\bigl(\tfrac{n}{\,\lambda (\beta )^{0}}\bigr),\, 
          \sin \!\bigl(\tfrac{n}{\,\lambda (\beta )^{0}}\bigr),
          \dots ,
          \sin \!\bigl(\tfrac{n}{\,\lambda (\beta )^{d/2 -1}}\bigr)\bigr]\!,
 
\]  

where we have introduced \(\beta=\theta ^{\,2/d}\) for convenience and where \(\lambda (\beta )^i\) denotes an effective rescaling factor applied to dimension \(i\). Different interpolation methods instantiate this factor differently:

* **Linear positional interpolation (PI)** simply sets a uniform rescaling factor equal to the extension ratio, i.e., \(\lambda = s\) for every dimension.
* **NTK‑based interpolation** draws inspiration from neural‑tangent‑kernel theory and applies a dimension‑dependent exponent so that lower‑frequency dimensions are stretched more than higher‑frequency ones; formally one may write \(\lambda = s^{\,i}\).
* **YaRN** partitions dimensions into three frequency groups—high frequency, medium frequency, low frequency—and assigns extrapolation (\(\lambda =1\)), NTK‑style scaling, or linear interpolation respectively for each group. The grouping itself is chosen empirically based on human intuition rather than an exhaustive search.

These three families illustrate a growing recognition that **non‑uniform treatment across RoPE dimensions** may help alleviate two fundamental problems caused by naïve linear compression: crowding of angular values when many new positions are forced into a limited angular interval, and catastrophic out‑of‑distribution values at far‑away positions that have never been visited during pretraining.



# Finding 1 – Variation Across Dimensions Requires Dimension‑Specific Rescaling Factors \(\lambda _i\)  

The first empirical insight arises from an exhaustive evolutionary search over possible choices of rescaling factors across individual RoPE dimensions. Instead of constraining all dimensions to share a single scalar factor—as PI does—or forcing them into three coarse groups—as YaRN does—the authors allowed each dimension \(i\) its own continuous factor \(\lambda _i\). The search objective was minimisation of language model perplexity on long documents drawn from validation subsets of PG19 and Proof‑Pile, without any additional fine‑tuning of model weights.  

When evaluated under this *dimensionally heterogeneous* regime, LLaMA2‑7B achieved substantially lower perplexities than any of the existing baselines. Results reported in Table 1 of the source material show that even at context lengths where vanilla PI already begins to falter ((8 k–16 k)), the searched configuration maintains smooth degradation curves rather than sudden spikes. Remarkably, YaRN—a method previously thought superior because it combines extrapolation with NTK‐style scaling—performed worse than plain PI on PG19 precisely because it fails to reach target lengths without further training; its perplexity rose sharply after roughly 7 k tokens despite being designed for longer windows.  

The success of per‑dimension optimisation stems from preserving **key frequency components** within RoPE that are most responsible for distinguishing nearby token positions. High‐frequency planes correspond mathematically to larger rotation rates (\(n/\beta ^i)\); applying an overly aggressive compression factor would cause their angular values at adjacent positions to become indistinguishable—a phenomenon often described as “crowding”. By assigning smaller rescaling values (closer to 1) for these critical planes while permitting larger values for low‐frequency planes—which encode coarse positional relationships—the search discovers an embedding geometry that remains expressive even after massive index stretching.


# Finding 2 – Early Token Positions Benefit From Reduced or No Interpolation (\(\hat n\))  

A second axis along which non‑uniformity manifests concerns **token position** rather than embedding dimension. Intuitively, earlier tokens in an input sequence exert disproportionate influence over subsequent attention computations because many attention heads allocate higher scores toward earlier contexts—a pattern documented in prior work such as Streaming LLM and LM‑Infinite . To test whether respecting this asymmetry improves long‐context performance, the authors introduced a threshold parameter \(\hat n\): all positions \(n< \hat n$ are left untouched by any rescaling (the original RoPE angles are retained), while positions \(n \geqslant \hat n$ receive the dimensionwise factors discovered via evolutionary search.\)

Through systematic ablations where \( \hat n ∈ \{0,\dots ,256\}\) was varied while keeping all other settings constant, two trends emerged clearly:

1. Retaining original rotary angles for any positive number of early tokens reduced perplexity compared with applying rescaling uniformly from token 0 onward.
2. The *optimal* value of \( \hat n$ depended on how far beyond the pretrained window one attempted to extend; longer extensions benefitted from larger thresholds because more early tokens needed protection against aggressive compression.


These observations validate the hypothesis that early positions serve as “anchors” within attention maps and should therefore escape aggressive positional distortion.


# Finding 3 – Proper Exploitation Improves Performance With And Without Fine‑Tuning  

Having established two distinct forms of non‑uniformity—dimensionwise scaling factors \(λ_i$\) and an initial-token safeguard parameter \(̂n$\)—the authors examined whether integrating both simultaneously yields tangible gains under both *non‑fine­tuned* inference and *fine‑tuned* training regimes.

In purely inference scenarios where no additional gradient updates are performed after altering RoPE geometry, simply applying the searched heterogeneous factors already delivered marked improvements over every baseline at context lengths up through 16 k tokens—the same ranges where prior works required costly fine‑tuning steps merely to remain functional. This demonstrates that well‐chosen non‑uniform rescaling alone can compensate for much of the information loss introduced by naive linear compression.



Fine­tuning experiments pushed this advantage further into truly extreme domains such as 64 k tokens. Here LLaMA2‐7B was fine­tuned for a modest number of steps while using the searched factors tailored originally for an 8× extension scenario (\(s=8\times)\). Table 3 illustrates that even after this additional optimisation step our method outperforms PI and YaRN both *before* any weight updates—as expected since it supplies a better starting point—and *after* training—thanks largely to reduced distributional shift between pretraining positions and their newly interpolated counterparts.


Thus “exploiting non‐uniformities” does not merely provide incremental gains; it reshapes how much extra computation is required at all—enabling profound extensions without any gradient updates while simultaneously offering stronger foundations when full fine‐tuning does become necessary.


# Experimental Protocol Used For Validation  

The empirical studies were conducted under a rigorous yet pragmatic evaluation pipeline designed solely around next-token prediction loss expressed via **perplexity**, which remains a standard measure of language model uncertainty over large corpora.



*Data selection.* For searching rescaling factors across dimensions—and later confirming their effectiveness—the authors sampled five random validation documents from PG19 . Each selected document was required to exceed strictly more than $L'$ tokens so that every extended position could be exercised during measurement.\footnote{PG19 consists primarily of books sourced from Project Gutenberg assembled specifically for evaluating long-context models; Proof-Pile contains professional legal texts used historically as challenging test material.\par} These short sample sets kept computational cost manageable while still reflecting realistic token distributions.\par

*Search objective.* During evolutionary optimisation (described more fully elsewhere), each candidate set of parameters $(λ_0,\dots ,λ_{d/2 -1},̂n)$ was applied directly onto a frozen LLM weight set before computing perplexity on those five documents.\par

*Fine­tuning regime.* When assessing how well non-uniform interpolations behave under weight adaptation, LLaMA2–7B was separately fine­tuned at sequences up to either 64 k tokens using standard AdamW optimisation settings reported in Sect.~4.A . The same five‐sample validation set served again as an evaluation checkpoint after each predefined training step count.\par

*Baselines.* In every comparison scenario three established baselines were included:\newline
– Linear PI ($λ=s$ universally);\\
– Dynamic NTK ($λ=s^{\,i}$);\\
– YaRN which employs three manually engineered groups.\newline
All baselines operated without further parameter updates during inference whenever possible.\par

*Metric reporting.* Perplexity values were averaged over all sampled documents without any additional smoothing or temperature scaling. When tabulated results appeared throughout Sec.~3 (“Findings”), lower values unequivocally indicated superior modelling fidelity.



Overall this protocol isolates *positional embedding* effects from confounding factors such as data variance or optimiser dynamics, giving credence particularly to conclusions about why uniform approaches degrade quickly.



# Why Uniform Scaling Fails At High Extension Ratios  

Uniform scaling compresses every rotary angle by exactly the same factor irrespective of its intrinsic frequency or its distance from sequence start.\par

Two intertwined phenomena explain why such naïve compression collapses once $s$ exceeds modest values (~ 4×):



*Crowding.* In RoPE geometry each two-dimensional rotation plane maps discrete token indices onto points along a unit circle according to angle $n/\beta ^i$. If all angles are divided uniformly by $s$, then points corresponding even to nearby token indices become tightly clustered together on this circle when $s$ becomes large enough—that is multiple distinct inputs map onto virtually indistinguishable vectors.\par This makes it extremely hard for downstream feedforward layers or attention heads to separate neighboring words—a problem dubbed “crowding” throughout earlier work.\par

*Out-of-distribution novelty.* Extending beyond training limits introduces *new* absolute position indices whose corresponding raw angles would fall far outside any range observed during pretraining (\(n > L$). Uniformly shrinking these novel angles does not restore their statistical properties because their distribution becomes heavily skewed toward low magnitude values while preserving relative ordering poorly.\par Consequently attention mechanisms encounter unforeseen query/key interactions leading frequently either  
    – Extremely small dot products producing vanishing gradients during subsequent fine­tuning rounds, or  
    – Excessively large dot products resulting in saturated softmax outputs which heavily bias hidden states toward early tokens.\par Both effects contribute antagonistically toward exploding loss spikes once more than roughly ninety percent of token positions become “new”, precisely what occurs when attempting raw extensions beyond $1000k$ tokens.



The empirical findings motivate respecting two orthogonal axes of variation:\newline
(i) Allocating smaller compressions $λ_i≈1$ toward higher–frequency planes preserves angular separation where it matters most;\newline
(ii) Leaving early‐position angles untouched shields crucial attention anchors.\newline
Together these adjustments prevent excessive crowding while keeping overall representation capacity sufficient even at theoretically extreme ratios such as \$512\times\$ extensions reported later in LongRoPE.



In summary, this comprehensive empirical investigation demonstrated concretely that **non-uniform treatment**—both across embedding dimensions via dedicated scalars \(λ_i\$`and across sequence location via threshold \\(\\hat n\\)—is indispensable when stretching rotary embeddings far beyond their native window sizes. 5. Formulating Positional Interpolation as an Optimization Problem

# Problem Statement

Extending a large language model (LLM) beyond its pretrained context window requires us to modify the rotary positional embedding (RoPE) so that it can accommodate new token indices without degrading the model’s ability to predict the next token.  From a learning‑theoretic viewpoint this requirement can be expressed as an optimization problem: given a target context length \(L'\) (for example \(L' = 2048\,\text{k}\) tokens), choose a modification of the RoPE such that the expected next‑token loss—measured by perplexity—on sequences of length at least \(L'\) is minimized.  Formally,

\[
\underset{\mathbf{x}\in\mathbf{X},\,|\mathbf{x}|\ge L'}{\operatorname*{arg\,min}}\;
\mathcal{L}\!\left(\text{LLM}(\text{RoPE}),\mathbf{x}\right),
\tag{1}
\]

where \(\mathbf{X}\) denotes a collection of long documents used for evaluation,  
\(\mathcal{L}\) denotes the standard negative log‑likelihood loss whose exponentiation yields perplexity, and  
\(\text{LLM}(\text{RoPE})\) represents the language model equipped with a potentially altered RoPE mapping.  

Intuitively, Eq. (1) asks us to find those changes to the positional encoding that keep the model’s predictions as accurate as possible even when it processes sequences many times longer than those seen during pre‑training.

# Variables

The only degrees of freedom available in our formulation are (i) a per‑dimension rescale factor \(\lambda_i\) applied to the rotary angle of RoPE’s \(i^{\text{th}}\) sinusoid and (ii) a token‑position threshold \(\hat n\) indicating how many initial tokens should retain their original embedding without any scaling.  

For a token at position \(n\) and RoPE dimension index \(i\in\{0,\dots,\tfrac d2-1\}\), let \(\beta = \theta^{2/d}\), where \(\theta=10\,000\) is the default base frequency used by most LLMs. The original rotary angle before any extension is \(\frac{n}{\beta^{i}}\). After applying our rescaling scheme we obtain

\[
\Bigl[\cos\bigl(\mathbb I(\hat{\lambda}_i,\hat n)\tfrac{n}{\beta^{i}}\bigr),
      \sin\bigl(\mathbb I(\hat{\lambda}_i,\hat n)\tfrac{n}{\beta^{i}}\bigr), \dots\bigr],
\tag{2}
\]

where

\[
\mathbb I(\hat{\lambda}_i,\hat n)=
   \begin{cases}
      1                      & \text{if } n < \hat n ,\\[4pt]
      \displaystyle \frac{1}{\lambda_i}
                           & \text{if } n \ge \hat n .
   \end{cases}
\]

Thus \(\lambda_i>1\) corresponds to interpolating (compressing) angles so that distant positions fit inside the original angle range, whereas \(\lambda_i=1\) leaves the angle untouched (pure extrapolation).  
The vector \((\lambda_0,\dots,\lambda_{d/2-1})\) captures **non‑uniformity across dimensions**, while \(\hat n\) captures **non‑uniformity across token positions**—both phenomena were empirically observed in Section 3 of the LongRoPE paper.

# Search Space Definition

To make Eq. (1) tractable we must bound each variable’s admissible region:

* **Per‑dimension rescale factors** – For a given extension ratio 
\(s=\frac{L'}{L}\)
we allow 
\( \lambda_i \in [\,1.0,\; s\times1.25\,] \)
with granularity \(0.01\).  
The lower bound \(1.0\) corresponds to pure extrapolation (no compression), while the upper bound permits modest over‑interpolation beyond what naïve linear interpolation would suggest (\(s\times1.25 > s\)).  

* **Token‑position threshold** – The set 
\( \hat n \in
   \{0,\,1,\,2,\,4,\,8,\,12,\,16,\,20,
    24,\,28,\,32,\,64,\,128,\,256\} 
   \)
covers plausible numbers of initial tokens whose embeddings are left unchanged.  
When \(\hat n=0\) every position undergoes scaling; larger values progressively protect more early tokens—a design motivated by findings that early tokens receive disproportionately high attention weights during inference.

* **Monotonicity constraint** – Theory from Neural Tangent Kernel (NTK) analysis suggests that low‑frequency dimensions (\(i\) large) can tolerate more compression than high‑frequency ones (\(i\) small). Accordingly we enforce

\[
    \lambda_0
    \;\leq\
    \lambda_1
    \;\leq\
    \dots
    \;\leq\
    \lambda_{\tfrac d2-1},
    \tag{3}
\]

which dramatically reduces admissible configurations while preserving an ordering consistent with information‑encoding intuition: higher‑frequency components retain finer granularity of positional resolution.

Together these specifications carve out a **search space** containing all candidate interpolation schemes that respect both empirical non‑uniformities and theoretical desiderata.

# Objective Function

During search we cannot afford to evaluate full training loss on massive corpora; instead we approximate Eq. (1)’s objective by measuring **perplexity** on a tiny validation subset (\(5\bigr.\) random documents from PG19 or similar long‑text benchmarks). Perplexity \(P(\theta)\) for a candidate set of parameters \(\theta=(\{\lambda_i\},\hat n)\) is defined as

\[
P(\theta)=
   \exp
   {\Bigl(
       -\,%
       {\tfrac1N}
       {\sum_{t=1}^{N}\log p_\theta(w_t|w_{<t})
       }
     {\Bigr)},
     %{\;}
   ,
   %\\
   %where N counts all tokens in evaluation sequences,
   %and p_\theta denotes the model’s predictive distribution under
   %the modified RoPE.
}
{
}
%
]%
,
}
%
Here \(w_t\) denotes token \(t,\)
\(N=\sum_{x∈S}|x|\)` is total token count over the chosen sample set \(S,\)
and \(p_\theta(w_t|w_{<t})`\)`is computed by feeding each sequence through LLM after applying Eq.\,(2).
Because perplexity directly exponentiates the average negative log‑likelihood,
minimizing \(P(\theta)\)
is mathematically identical to minimizing J in Eq.\,(1).
Thus our **objective function** for any candidate solution simply returns its perplexity on this validation slice; lower values indicate better preservation of next‑token prediction quality after extending context window length to \(L'\).

# Why Exhaustive Search Is Infeasible

Even after imposing monotonic ordering (3), enumerating every admissible configuration remains astronomically expensive due to combinatorial explosion:

* With step size \(0.01,\)
the interval 
\( [\,1.0,s\times1.25]  (s=4)\)
contains roughly 
\(400  =  (s\times125)\)
distinct values for each \(λ_i.\)

* A typical transformer encoder such as LLaMA 2‑7B uses 
\(d/2 = 64  .\)

Thus just counting assignments satisfying monotonicity yields roughly

\[
400^{64}
   ≈
   4\times10^{167}
   .
   %This figure stems from treating each λi independently;
   %the monotone constraint reduces possibilities but only marginally.
]\]

Multiplying by all choices for \( ̂n ∈14 {\rm options}\)
produces on the order of

\(4\times10^{167}\times14 ≈ 6\times10^{168}\)

candidate settings—a number far beyond any conceivable compute budget.
Even evaluating one candidate requires feeding several thousand tokens through an LLM and recording its likelihoods—a process that may take seconds on modern GPUs; scaling this up leads immediately to impractical runtimes measured in millennia or more.

Consequently **exhaustive enumeration** cannot be used as a practical optimisation strategy.
Instead LongRoPE introduces an *evolutionary search* procedure (Algorithm 1 in the paper), which leverages population‑based mutation and crossover operators together with early pruning via monotonic constraints.
This approach reliably discovers high‑quality interpolation schemes within dozens of iterations rather than exploring an astronomically large space blindly.

# 6. Evolutionary Search Algorithm for Optimal Non‑Uniform RoPE Rescaling  

Understanding how to explore the astronomically large space of possible rotary‑position‑embedding (RoPE) scaling configurations is crucial for extending a large language model’s (LLM) context window without expensive fine‑tuning.  This chapter dissects the custom evolutionary search strategy introduced in **LongRoPE**.  The method is built around three intertwined ideas: (i) seeding a population with strong baselines, (ii) applying mutation and crossover operators that respect theoretical constraints on RoPE dimensions, and (iii) evaluating candidates efficiently via perplexity on a small validation set.  By the end of the chapter you will see how these components cooperate to discover a set of per‑dimension scaling factors \( \{\lambda_i\} \) and an initial‑token threshold \( \hat n \) that enable an eight‑fold context‑window increase without any further fine‑tuning.

---

## 6.1 Initial Population Seeding  

Evolutionary algorithms start from a **population**—a collection of candidate solutions that will evolve over successive generations.  In LongRoPE each individual encodes a full RoPE rescaling configuration:
\[
\mathbb{I}(\hat{\lambda}_i,\hat n)=\begin{cases}
1                        & n < \hat n\\[4pt]
\displaystyle\frac{1}{\lambda_i} & n \ge \hat n,
\end{cases}
\qquad i=0,\dots,\tfrac d2-1,
\tag{6}
\]
where \( \lambda_i \in [1.0,\; s\times1.25] \) is the **rescale factor** for dimension \( i \), and \( s=L'/L \) denotes the target extension ratio (e.g., \(s=8\) when we aim for an eight‑fold increase).  

Rather than initializing all \(P\) individuals completely at random—a strategy that would waste most of the early generations on implausible solutions—LongRoPE **injects three well‑studied baselines** into the seed pool:

* **PI** (linear positional interpolation): \( \lambda_i = s\;\forall i\).  
* **NTK**‑based interpolation/extrapolation: \( \lambda_i = s^{\,i}\), i.e., lower dimensions receive less scaling.  
* **YaRN**’s three‑group scheme: high‑frequency dimensions keep \( \lambda=1\), mid‑frequency dimensions follow NTK scaling, low‑frequency dimensions use PI scaling.

These three individuals provide solid starting points that already respect known theoretical properties of RoPE (e.g., higher frequencies should be distorted less).  

The remaining \(P-3\) members are generated by taking each baseline and **mutating it with probability \(p\)** (see Section 6.2).  This “mutated baseline” trick ensures that every early individual lies near a plausible region of the search space while still offering sufficient diversity for exploration.

---

## 6.2 Mutation Operator  

A mutation introduces stochastic variation into an individual’s genes—in our case, into its set of per‑dimension scaling factors \( \{\lambda_i\} \) and optionally its threshold \( \hat n\).  The operator works as follows:

1. **Dimensionwise Perturbation** – For each dimension index \( i\), we flip a biased coin with probability \(p\). If the coin lands heads we replace \( \lambda_i \) by a new value drawn uniformly from its admissible interval:
   \[
   \lambda_i^{\text{new}} \sim \mathcal U\bigl(1.0,\; s\times1.25\bigr).
   \]
   The interval is discretised with step size \(0.01\), exactly matching the granularity used when constructing the search space table (Table 5 in the paper).  

2. **Threshold Mutation** – The integer threshold \( \hat n\), which determines how many initial tokens are exempt from any scaling, is drawn uniformly from the candidate set
   \[
   \hat n \in \{0,\,1,\,2,\,4,\,8,\,12,\,16,\,20,\,24,\,28,\,32,\,64,\,128,\,256\}.
   \]
   Mutating \( \hat n\) respects that there are only a few meaningful breakpoints (powers of two or small multiples thereof), reflecting empirical findings that only coarse granularity matters for early token handling.

3. **Post‑Mutation Monotonic Correction** – After all perturbations are applied we enforce a **monotonic non‑decreasing constraint** across dimensions:
   \[
   \lambda_0 \leqslant \lambda_1 \leqslant \dotsb \leqslant
   \lambda_{\tfrac d2-1}.
   \tag{7}
   \]
   If any violation occurs we simply project offending values upward to satisfy (7). This correction embodies insights from NTK theory: lower‑frequency dimensions (\(i\) large) can tolerate more aggressive downscaling because their sinusoidal basis functions vary slowly along token positions; higher‑frequency dimensions (\(i\) small) must retain finer granularity and therefore receive smaller scaling factors.

The mutation operator thus creates novel candidates while guaranteeing that every offspring still satisfies the theoretical monotonicity property required for stable RoPE interpolation.

---

## 6.3 Crossover Operator  

While mutation explores locally around existing solutions, **crossover** enables larger jumps by recombining genetic material from two high‑fitness parents.  In LongRoPE crossover proceeds as follows:

1. **Parent Selection** – After evaluating all individuals in generation \(t-1\), we retain the top‑\(k\) fittest candidates (lowest perplexities). These become “parents” eligible for recombination.
2. **One‑Point Swapping** – For each pair of selected parents we pick a random cut point \(c\in[0,\tfrac d2)\). The child’s scaling vector is assembled by concatenating
   - the first \(c\) entries from parent A,
   - the remaining entries from parent B.
3. **Threshold Inheritance** – The child’s threshold \( \hat n_{\text{child}}\) is sampled uniformly from its two parents’ thresholds.
4. **Monotonic Enforcement** – As with mutation we apply constraint (7). If swapping introduced an inversion we repair it by scanning left–to–right increasing any offending entry to match its predecessor.

Crossover thus produces offspring that inherit complementary advantages—for example one parent may have already discovered an optimal pattern for low frequencies while another excels at high frequencies—and respects monotonicity without re‑evaluating infeasible solutions.

---

## 6.4 Monotonic Non‑Decreasing Constraint  

The monotonic constraint serves two complementary purposes:

* **Theoretical Consistency** – NTK analysis argues that embedding frequencies form an ordered spectrum; preserving order during scaling avoids pathological distortions where low frequencies would be compressed more than high frequencies—a scenario that can lead to “crowded” angular representations and thus higher perplexity.
* **Search Efficiency** – By narrowing admissible configurations to those obeying (7), we dramatically reduce the number of candidates evaluated per generation. Empirically this pruning cuts down inference time by several orders of magnitude because many randomly generated vectors would violate monotonicity and thus be discarded before any forward pass through the LLM occurs.

During both mutation and crossover steps LongRoPE checks constraint (7); any generated vector failing this test is either repaired or discarded outright before entering the evaluation pool.

---

## 6.5 Evaluation Loop  

Each generation finishes with an **evaluation phase**, where every surviving individual’s fitness—the ability of its RoPE configuration to support long-context language modeling—is measured via perplexity:

1. **RoPE Injection** – For a given candidate’s parameters \( (\{\lambda_i\},\hat n)\), LongRoPE builds a modified rotation matrix according to Eq.\,(6). All attention heads share this same modification because RoPE is applied uniformly across heads.
2. **Perplexity Computation** – The LLM processes a small validation subset drawn from PG19 (five random documents exceeding the target length). Since long sequences are computationally costly, LongRoPE reuses *cached forward activations* wherever possible:
   - The token embeddings up to position \( \hat n-1\) never change across candidates because they use the original RoPE.
   - For subsequent positions only the scalar angles change; therefore only attention score matrices need recomputation while earlier activation caches remain valid.
3. **Fitness Assignment** – Perplexity is transformed into a fitness score by simply using its negative value—lower perplexity implies higher fitness.
4. **Selection** – After scoring all candidates we sort them by fitness and retain only `top‑k` individuals as parents for the next generation’s mutation and crossover steps.

Because each generation evaluates only `P` individuals (with `P` typically equal to 64), LongRoPE can afford dozens of generations even when each evaluation involves passing multi‑hundred‐kilobyte sequences through a billions‑parameter LLM.

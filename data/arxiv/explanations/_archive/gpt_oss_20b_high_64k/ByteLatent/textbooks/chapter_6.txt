\title{A Textbook about the Paper: "Byte Latent Transformer: Patches Scale Better Than Tokens"}

Chapter 6: # Global Latent Transformer Mechanics  

Large language models traditionally process tokens through an autoregressive transformer that operates on a fixed‐size vocabulary. In a **Byte Latent Transformer** (\textsc BLT}, however, those “tokens” are replaced by **latent patches** obtained from raw bytes. To maintain performance while reducing compute overhead, deep design choices are taken at three levels—architecture width/height, masking strategy, positional encoding reuse and activation/normalisation methods—each deliberately borrowed from mainstream token‑based transformers such as LLaMA 3 yet tuned around patch semantics. The following sections unpack how these decisions shape \textsc BLT}’s global latent transformer.

---

## Layer Count & Dimensionality Decisions  

The **global latent transformer** \(\mathcal{G}\) is parameter‑equivalent to token‑based models trained on tens of billions of tokens – it maps each latent patch representation \(p_j \in \mathbb{R}^{h_{\mathcal{G}}}\) into a corresponding output \(o_j\). Because \(\mathcal{G}\) encapsulates almost all floating‑point operations during pre‑training and inference, its depth \(l_{\mathcal{G}}\) and width \(h_{\mathcal{G}}\) ultimately dominate total compute cost and learning capacity.

In practice, \(\mathcal{G}\) adopts the same dimensional hierarchy proposed for token‑based transformers:

\[
h_{\mathcal{G}} = \frac{4}{3}\,\texttt{model\_size},\qquad
d_{\text{ff}} = 4\,h_{\mathcal{G}},
\]

where \(\texttt{model\_size}\) denotes metaphoric “effective token size” – essentially one patched representation vector equal in anatomy to a standard token embedding length. Because byte patches replace tokens without changing their inferred semantic burden per instruction step, translating *patch‑width* directly into *token‐width* seems reasonable.

Regarding **layer count** \(l_{\mathcal{G}}\), the study experimented on multiple model scales – \(400\mathrm{M}\), \(1\mathrm{B}\), \(2\mathrm{B}\), \(4\mathrm{B}\), up to \(8\mathrm{B}\). Each step pursued a **compute‑optimal point** where training data quantity matched model capacity according to existing scaling laws derived for BPE transformers (\citealt{dubey2024llama}). Concretely:

| Scale | Layers \(l_{\mathcal G}\) | Hidden size \(h_{\mathcal G}\) |
|------|--------------------------|------------------------------|
| 400 M | ~10 | ~8 k |
| 1 B   | ~12 | ~12 k |
| …     | …   | … |
| 8 B   | ~36 | ~24 k |

(Values illustrate typical growth patterns rather than exact counts.) Because every increase in layer depth incurs linear head expansion (\(q,k,v,o\)), aligning numbers with pretrained cameras ensures rapid convergence even when using archival byte patches rather than static vocabulary words.

A salient effect emerges when **patch size varies** (§Patching). Increasing mean patch length reduces total sequence steps per document so fewer \(\mathcal{G}\) layers are applied during inference (i.e., lower FLOPs). Consequently researchers may scale ***both*** the global depth *and* average patch length while holding overall compute constant—an advantage absent when using static vocabularies because tokens cannot grow arbitarily large without collapsing data representation fidelity.

## *Block–Causal* Mask Per Document Boundary  

The core challenge of multi‑document training is controlling what one document can attend to relative another’s embeddings when feeding sequences via padding‐loaned batches. A naive soft‑max over all positions would inadvertently allow gradients from one document drift into another’s state history, corrupting autoregression on both fronts.

To halt this cross‑document leakage, \textsc BLT} adopts a *block‑causal* mask—identical to that employed by LLaMA 3—where every patch mask respects its own **document boundary**:

```
Mask(i,j)=1 ⇔ {
                 i≥j   AND
                 doc(i)=doc(j)
               }
```

In practice this means all trainable logits at a position \(i\) are evaluated against *intra‑document* preceding patches while future patches—even those belonging to distinct documents—are relegated to minus infinity scores and effectively ignored during softmax normalization. Consequently generated sequences obey strict left‑to‑right order within each document while remaining independent across documents even when padded together into one batched sequence matrix.\footnote{
Some tokenisers add special ``<DOC>'' separators before quantisation; \textsc BLT} does this implicitly because patches are derived on full byte streams maintaining exact document segmentation.\@}

The block‑causal rule becomes especially important because patches sometimes cross natural lexical boundaries—however long their dynamic segmentation will stretch—they stay rooted within their originating strings.\@ This avoids convoluting one prompt’s prediction probability distribution with unrelated context elsewhere,\@ guaranteeing reliable perplexity estimates (or Bits‐Per‑Byte measurement).

## Rotary Positional Embedding Reuse  

Relative position information remains essential even when input items lack explicit lexical identity—as tiny adjective formality cannot be zeroed out otherwise. For this purpose \textsc BLT} reuses **Rotary Position Encodings (RoPe)** directly from its parent design (LLaMA 3). RoPe injects sinusoidal rotational patterns into query/key vectors:

\[
q'_i = [\, q_i^{(0)} + R_i h_i,\ q_i^{(1)} + R_i h_i\,],
\]

where \(R_i=\sin(i/\theta)\) and \(\theta=5\times10^5\); this encourages relative distance learning without any learned positional table overhead.\@ Crucially RoPe works seamlessly on both *any* hidden dimension depth—the encoder’s lightweight local transformers omit them altogether because those layers attend within short fixed windows where absolute offset matters little.\@ Only self–attention inside \(\mathcal G\,\) requires it since longer buffer spans warrant delicate relative location management across many patches per batch.

Reusing RoPe confers two key benefits:\begin{enumerate}
		*1.* No additional parameters or memory are required—saving hold space normally reserved for learned positional tables.\item
		*2.* It yields a smooth continual coordinate system across variable patch lengths because each pass receives exactly one contiguous receptive window regardless of whether raw bytes were granted separate or collapsed into longer tokens.\@ 
\end{enumerate}

The straightforward adaptation backfires little on Bytes versus Token inputs because RoPe depends purely on positional indices—identified unchanged whether bytes or patches occupy those slots.\@

## SwiGLU / RMSNorm Activations  

Typical large trans­formers employ either GELU/GELU variants or heavier mixtures such as SwiGLU (\(f(x)=x\sigma(Wx)\)) along with either LayerNorm or RMSNorm normalisation nodes. Given Boök-lab scale constraints were respected meticulously in these experiments—a deeper network compounded even tiny constant overheads—the chosen combination was exactly the one proven best by recent high‑ranking architectures such as LLaMA ​and Mamba:

*(1) SwiGLU*: A gated linear unit built atop elementwise sigmoid functions furnishes both high expressive power and efficient back‑propagation compared to traditional GELU since it requires fewer independent evaluation operations.\@
*(2) RMSNorm*: Rather than caring about variance offsets globally per token distribution—a bookkeeping effort costly at logical tensor macros—we apply Root‐Mean–Square normalisation—that normalises vector magnitude without parameters—in every residual stage which simplifies gradient flow dramatically at massive depth.\@

Procedure inside each multiheaded self‐attention layer:
1\. Query/key/value projections take place;
2\. Multiheaded dot product yields attention scores masked appropriately;
3\. Subsequent `softmax` produces weighted sums;
4\. Result then concatenated back into `attn_out`;
5\. `attn_out` is integrated into prenorm residual using `RMSNorm`;
6\. A `SwiGLU` feedforward stage processes elementwise gated expression;
7\. Another residual connects back into normalized representation before passing downstream.
///
/// Importantly these functions do not depend on token identity—they hinge purely on raw vector arithmetic.—This makes them perfect companions for byte-level models wherein no discrete lexical level offers trivial context embedding usage.~

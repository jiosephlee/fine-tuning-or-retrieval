# Background on tokenizer‑based LLMs  
Large language models (LLMs) have been trained in an almost completely end‑to‑end fashion since their inception, except for an essential preprocessing step—tokenisation. Tokenisation groups contiguous byte sequences into a *finite* set of symbols drawn from a predetermined dictionary known as a vocabulary.\footnote{Tokenisation methods such as byte‑pair encoding (BPE)~\citep{sennrich-etal-2016-neural,gage1994new} have become de facto standards because they compact input efficiently while allowing transformers short enough sequences that fit budgets imposed by quadratic self‑attention costs.\label{sec:bpe}}  
Once tokenised, the resulting sequence is projected through an embedding table and fed into a standard autoregressive transformer consisting mainly of block‑causal self‐attention layers coupled with FFN towers~(\S Architecture). Tokens therefore act both as *compression*, reducing input length from possibly millions of raw bytes down to several thousands of symbols, *bias*, restricting how information can be represented during learning~(\S Robustness), and *computational unit*, determining how much computation the transformer performs per step.  

However this design introduces constraints tightly coupled with the choice of vocabulary:
the size and composition of the dictionary constrain which sequences can appear together without splitting words or mixing languages.
Intrinsic compression heuristics—bisecting larger units into smaller ones when frequency thresholds are met—cause distortions that differ sharply between domains.
More importantly every token obliges one evaluation pass through both reference projection matrices (for input embeddings) and weight matrices within each transformer's layer,
introducing *fixed* computation overhead unrelated **a priori** to how complex the next prediction actually is.
Consequently many productive steps devoted naturally occur when predicting trivial continuations such as trailing whitespaces
(and thus consume unnecessary flops), while few steps are afforded when encountering hard initial characters before a new sentence pivots heavily future possibilities.’This rigid–volume assignment constrains both *efficiency* and *robustness*’~(\S Limitations).  

# Limitations imposed by fixed vocabularies  
The practical consequences listed above surface directly across architectures:

* **Domain / Modality Sensitivity** – The BPE heuristics dictate how end‑to‑end compression hovers around particular statistics captured during static training.
When encountering new textual domains these heuristics falter visibly~(\citep{dagangetting}).  
For instance,
improved entity types or unfamiliar scripts allocate poorly sized units whilst traditional strings remain well balanced—leading directly
to stronger overfitting or underfitting patterns in unseen data.
* **Noise Sensitivity** – A typographical mistake changes some trailing symbols often leaving other parts untouched,
although transcripts arriving at successive data samples crowd an entire pretrained embedding vector range.
Because embeddings are shared completely across all possible occurrences,
a single missing character alters downstream predictors drastically.
Further evidence surfaces experimentally wherein pre-trained BPE systems stumble heavily against character‐level noise injections (~24–37 points worse than Alt Bier). 
Because gradients propagate through a fixed symbol pathway once chosen during segmentation—a consequence traced back to off‑chain semantics—noise propagates amplified through causality chains~(\S Robustness). 
* **Orthographic Knowledge Deficit** – Tokenised systems inherently ignore deterministic operation over glyphs beyond source segmentation,
hence losing awareness needed for subtle sub-word transformations demonstrated embarrassingly well on character manipulation benchmarks such as CUTE or mbpp codify~(\S Byte-Level Tasks). 
This hampers learning transliteration or phoneme extraction despite large parameter counts because templates do not provide deterministic symbols aligned per character anymore.
* **Limited Flexibility Across Diverse Patch Sizes** – Standard settings let practitioners switch average byte occupancy per token only marginally,
because larger vocabularies necessitate proportionally larger embedding tables merging both increased sequence length handling capacity
and memory usage spike ~Llama 3’s growth from an average size \(3\.7 \rightarrow4\.4\) bytes increasing its embedding dimension four times~(Figure xx).
Thus attempt shifts tandemly suffering linear increases even if stored batch length shrinks proportionally yielding little room for sparse reallocation mechanisms normalizing variance on average complexity metrics X_{complexity}.  
Mathematically every policy defines a surrogate vector \(z_i = e^{(t)}(x_{<i}) \in \mathbb R^{d}\)—the same size irrespective 
how predictive remaining context is—thereby failing adaptivity required for distinguishing simple versus varied predictions over diverse cultural settings.~(Page 9).

These constitutes clear pressure points motivating creation of genuinely flexible replacements which are permitted nonbounded grouping units while maintaining control over overall computational load.



  
# Introduction to single-byte inputs  
Transformers trained directly on writing systems represented **as individual bytes** avoid all compression ambiguities incited above:
every possible sequence produces exactly one deterministic symbolic representation—not dependent upon any external dictionary choice.
By bypassing magic segmentation schemes it never predisposes input with pre-selected biases.
Empirical studies illustrate this property brings winning accuracy gaps even vis-à-vis mature symbolic pipelines on code completion tests
(increasing upstream sample distribution diversity).

There remains an essential optica challenge:
the prime bottleneck shifts from *self-attention*—the most familiar quadratic cost—to purely linear costs incurred mostly at immense numbers
of successive feed-forward network (FFN) layers evaluated over each raw byte entry.
Hence direct byte-level transformer instantiations blow up when faced with strings several billion long—it becomes volumetrically prohibitive neither memory requisites nor cycles reach obviously past billions (~).
The address plan mitigates these issues through two strands simultaneously pushed forward by research:
**a)** designing *efficient attention variants* reducing thread‐wise operations its kernels focus around sliding windows or linear approximation techniques (`Mamba`/`MambaByte`, `CharacterBERT`).
**b)** deploying *attention‐free* architectures mitigating backlog partly relegating attention outside structural building blocks entirely (`Mamba`, pointers).  

Yet even these optimization webs prove more effective predominantly at modest scales (<200 M parameters),
especially when confronting highly repetitive data common among large proprietary corpora (>400 B tokens).
Even if windowed attention expands available context from 512 up near 396 k,
the exhaustive sampling through every pixel/byte still demands immense memory footprint---
not unlike dilated reminisces dense convolution kernels where high-resolution signals demand exponentially more operations than full-matrix self-attention alone achieves ~[\citet{xue2022byt5}]..

Inside this challenging cost envelope arises Byte Latent Transformer ({BLT}), which employs two complementary mechanisms:
1️⃣ The pre-processing phase forms **patches**—contiguous groups produced dynamically through knowledge transferred from situational predictability insights (`entropy`).  
In practice an auxiliary lightweight LM calculates next-byte uncertainty per position;
high uncertainty spawns new boundaries creating smaller patches wherever span dominantly low entropy spreads.
Unpredictable scenes thereby keep strictly higher passage frequency delivering multiple expensive latent blocks concurrently whereas trivially predictable passages enjoy extended group-size patches causing further savings without increasing crucial predictions.\coloneqarith{}\par  

2️⃣ Downstream capture leverages **latent modelling**—
the Busage employs an autoregressive global transformer whose tokens correspond precisely VIA DERIVED REPRESENTATIONS = concatenation operations onto compound latent vectors derived via cross‐attention pooling inside encoder modules controlling amplitude relative positional wrap levels among patch contents.\slidescape{}
In effect every higher-order modeling operation is performed only once per logical block rather than per individual raw byte.\

The intersection holds profound implications:
Bursting generation becomes efficient because latent blocks isolated naturally integrate multiple skip-tracks cribbing minimal fill depth;
every residual update loop addresses only constants sized latent vectors truly capturing semantics older fields automatically adapt themselves.*

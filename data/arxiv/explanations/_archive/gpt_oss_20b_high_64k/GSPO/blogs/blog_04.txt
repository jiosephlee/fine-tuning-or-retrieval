# A Breakthrough for Mixture‑of‑Experts Design – No More Routing Replay Needed

Mixture‑of‑Experts (MoE) models are a popular way to scale large language models while keeping compute tractable at inference time: half a trillion parameters may live behind an array of lightweight experts that are activated only when needed.  
However, this sparsity introduces subtle dynamics during reinforcement‑learning (RL) fine‑tuning – a problem that has traditionally forced researchers into a cumbersome workaround called **Routing Replay**.  
Group Sequence Policy Optimization (GSPO) transforms this story: by shifting from token‑level importance ratios to a single sequence‑level ratio, we eliminate expert‑activation volatility entirely and streamline MoE training without extra memory or communication costs – a key ingredient behind the recent Qwen3 successes.



--------------------------------------------------------------------

## 1. How MoE Per‑Token Dynamics Create Instability

### Expert‑activation volatility

When an MoE transformer generates a response \(y\) conditioned on a prompt \(x\), each token \(y_t\) is produced by one or more *experts*.  
During RL training we form mini–batches from data collected under an **old** policy \(\pi_{\theta_{\text{old}}}\), then update the current policy \(\pi_\theta\).  
However:

* The set of experts activated on a given token can shift dramatically from \(\pi_{\theta_{\text{old}}}\) to \(\pi_\theta\).
* This shift changes the per‑token probability mass:
  \[
    w_{i,t}(\theta)
    = \frac{\pi_\theta\!\bigl(y_{i,t}\mid x,y_{i,<t}\bigr)}
           {\pi_{\theta_{\text{old}}}\!\bigl(y_{i,t}\mid x,y_{i,<t}\bigr)} .
  \]
* Even modest changes in expert routing can drive \(w_{i,t}(\theta)\) far outside the usual clipping window
  \([1-\varepsilon,\;1+\varepsilon]\).
* Because the gradient uses \(w_{i,t}(\theta)\cdot\nabla_\theta\log\pi_\theta(y_{i,t})\), these outliers induce large variance that accumulates over long sequences – exactly why **GRPO** collapses on massive MoEs.


In practice, after one gradient step on a 48‑layer Qwen3 model we observed roughly *10 % of experts changing* between old and new policies per response – enough to defeat GRPO’s clipping mechanism.



--------------------------------------------------------------------

## 2. The Redundant Token Kitchen Sink

GRPO’s objective
\[
  J_{\text{GRPO}}(\theta)
  = \mathbb{E}_{x,\{y_i\}}\!\left[
      \tfrac{1}{G}\sum_i\tfrac{1}{|y_i|}
      \sum_t
      \min\!\Bigl(
        w_{i,t}(\theta)\widehat A_{i},
        \operatorname{clip}\bigl(w_{i,t}(\theta),\,1-\varepsilon,\,
                               1+\varepsilon\bigr)\widehat A_i
      \Bigr)
    \right]
\]
weights *every single token* by its own importance ratio \(w_{i,t}(\theta)\).  
For dense models this is rarely problematic – because all tokens share roughly similar attention patterns – but MoEs break down exactly where GRPO relies on uniformity.



--------------------------------------------------------------------

## 3. GSPI’s Insight: “One Ratio per Sequence”

GSPI (also called *Group Sequence Policy Optimization*, GSPO) proposes an elegant fix:

### Key change

* Replace each token weight \(w_{i,t}(\theta)\) with a **single** ratio per response:
  \[
    s_i(\theta)
    = \left(
        \frac{\pi_\theta(y_i | x)}
             {\pi_{\theta_{\text{old}}}(y_i | x)}
      \right)^{\! {1}/{|y_i|}}
    = \exp
      \!\left(
          {1\over |y_i|}
          \sum_t
          \log
          {\,\pi_\theta(y_{i,t}|x,y_{i,<t})}
          -
          {\,\pi_{\theta_{\text{old}}}(y_{i,t}|x,y_{i,<t})}
      \right).
  \]

* Clip at the coarse grain:
  ```
   L = min(s_i(θ), 1 – ε)
   U = max(s_i(θ), 1 + ε)
   clipped = max(L, min(U, s_i(θ)))
   ```

### Why this works

* **Insensitivity to per‑token routing changes** – all experts contribute only through their *aggregate* likelihood.
* **Variance reduction** – dividing by |\(y_i|\)| normalises across different response lengths.
* **Clipping window alignment** – since \(s_i(θ)\) lives largely around \(≈ 1\), ε can be small (\(~10^{-4}\)), tightening updates while still accommodating legitimate policy shifts.
* **Same advantage estimation** – all tokens inside the same response still receive identical normalized rewards via grouping over \(G\).

Consequently, even if many experts toggle between steps, the *average* likelihood changes only mildly so \(s_i(θ)\) stays stable.

## 5. Operational Advantages Beyond Stability

### No Extra Memory Overhead

Routing Replay required caching every token’s expert routing switch from the old policy—extra GPU memory + inter‑device collective traffic—whereas GSPI needs only the sequence‐level likelihoods already computed by inference engines during data collection.



### Simpler Infrastructure Workflows

GSPI relies exclusively on *sequence‐likelihoods*. This makes it tolerant of precision mismatches between training engines (e.g., Megatron) and inference engines (e.g., vLLM or SGLang). Consequently:

* RL loops can read cached logits directly from distributed generation shards.
* Partial rollouts become trivial—there’s no need to redo full forward passes just for likelihood reweighting.



### Generality Across Decoding Horizons

Because \(s_i(θ)\) aggregates over entire responses regardless of length,
the same algorithm keeps working whether you decode ≤ 200 tokens or > 2000 tokens,
a crucial property for long reasoning tasks often seen in coreference or algebraic problem solving.



--------------------------------------------------------------------

## 6. Takeaway

Midway through scaling up MoEs you might have resorted to Compensation tricks—Routing Replay—to keep gradients sane.  
GSPI replaces those hacks with an order–of–magnitude cleaner design:

* One importance ratio per sampled response removes expert‑activation volatility entirely.
* Clipping at the sequence level sidesteps token–level noise that previously exploded training gradients.
* Memory overhead vanishes—no extra routing caches required.
* Inference engines can head straight into optimization without recomputation cycles.


This “sequence‐first” philosophy is already backing cutting‑edge SOTA scores in Qwen 3 models and set clear directions for future large‑scale RL+MoE systems—no more extra routing logic, simpler pipelines, and ultimately steadier learning curves.

# Bits vs Bytes – The Dawn Of One‑Bit Language Models

Large language models have become marvels of computation, but that power comes at a steep cost in latency, memory usage, and energy consumption. A surprising new trick has been shown that can cut those costs dramatically without hurting performance simply by restricting every weight in a transformer to one of three symbols: **– 1**, **0**, **+ 1**【abstract】—the **BitNet b¹·⁵⁸** architecture. In this post we unpack how this tiny change turns dense floating‑point tensors into ultra‑compact integer maps so fast they feel almost mechanical, and we’ll look at concrete numbers from the original publication that prove it works at scale.



--------------------------------------------------------------------

## From Full‑Precision Weights to Ternary Symbols

In traditional Transformers each weight tensor contains many thousands of *FP16* values (≈16 bits each). A matrix multiplication then consists largely of floating‑point multiplications followed by accumulations—a process that worries both AI researchers (for latency) and industry players (for heat/power).

**BitNet b¹·⁵⁸** replaces every linear layer’s weights \(W\) with a *ternary* version \(\widetilde{W}\):

```text
γ   = average |W|
Wʳ = W / (γ + ε)
W~   = RoundClip(Wʳ , –1 , +1)      // <-- clamp then round
```

where  

\[
\widetilde{W} = \operatorname{RoundClip}\!\left(\frac{W}{\gamma+\epsilon},-1,+1\right),
\qquad 
\gamma = \frac{1}{nm}\sum_{ij}|W_{ij}|.
\]

The result is a weight matrix that takes one of only three values—and because the “zero” state has an explicit price (`log₂ 3 ≈ 1.58` bits per weight), we say this is a **“one‑bit”** system even though it uses a third symbol.



--------------------------------------------------------------------

## Why Ternary Matters

| Benefit | What Changes | Why It Helps |
|---------|--------------|--------------|
| **Giants go lightweight** | `nn.Linear` replaced by `BitLinear` | Each parameter shrinks from ~16 bits to ~log₂ 3 ≈ 1.58 bits |
| **Computation becomes integer addition** | Multiplications vanish in matrix multiplies | Integer adders consume far less energy than floating‑point multiply-add units |
| **Zero acts as an explicit filter** | Every weight may become zero when quantized | Allows the network to ignore weak connections naturally, improving generalisation |
| **FFT‑like sparsity** | Half‑plus weights are zero or ± 1 | Sparsity cuts memory traffic & lets accelerators pack more ops into a single cycle |

In practice this means that an inference kernel no longer has to shuffle expensive FP16 multipliers around—it simply adds signed integers together.



--------------------------------------------------------------------

## Competitive Performance — Numbers from Experimentation

The authors ran fully‐controlled experiments against their own reproduced FP16 LLaMA LLM baseline on identical datasets and token budgets (100 billion tokens from RedPajama).

### Perplexity & Zero‑Shot Accuracy

* **Perplexity match:** At **3 billion parameters** BitNet b¹·⁵⁸’s validation perplexity on WikiText‑2/C4 matched the full‑precision counterpart.
* **End‑task parity:** Zero‑shot accuracies on ARC‑Easy/Challenge, Hellaswag, Winogrande, PIQA, OpenbookQA, BoolQ were within <0.5 % across all sizes ≥ 3 billion.
* **Superior at equal compute:** For example, the 3.9B BitNet outperformed the full‑precision LLaMA 3B while being smaller computationally.



### Runtime & Memory Footprint

| Model Size | Speedup vs FP16 LLaMA | Memory Rec.\* |
|------------|----------------------|---------------|
| **3B**     | \(2.\!71\times\) faster per token | \(3.\!55\times\) less GPU memory |
| **7B**     | ×~3 fast   | slightly >×4 less RAM |
| **70B**    | \(4.\!10\times\) quickening          | >×4 slimming |

> *Memory reduction comes mostly from lower weight precision; embeddings remain FP16 but represent only ~10–20% of total param count.*

### Energy Burden

A chip‐level estimate for a typical modern node shows:

* **Standard FP16** – ADD + MUL energy dominates matrix multiplication cost.
* **BitNet i.e., INT8 add only** – saves roughly \(71\times\) arithmetic operation energy on a seven‐nanometre process buscher estimation around matrix multiplication scheduling[^energy].

Because the cheaper operation dominates the schedule when you crank up model size (as almost all compute ends up in `nn.Linear`), running heavier models like ∼70 billion parameters actually becomes cheaper per output token than lighter full‑precision nets.



### Throughput Boosts

With two A100 GPUs operating under pipeline parallelism:

* The same hardware could run batch sizes ten times larger under BitNet vs FP16.
* Net throughput grew by almost nine coefficients—allowing a far richer model for each traffic ticket.

There are several exciting avenues now made practical thanks to one–bit primitives:

* **MoE becomes cheaper:** Lower per‐token bandwidth reduces inter‐chip communication costs—placement on fewer devices is feasible.
* **Long sequences their future:** With activations already stored as just eight bits (and compressible further), KV caches scale better—remember previous prompts without paying huge outlays.
* **Edge / mobile deployment:** CPU‑friendly additions mean small phones can host conversational models once restricted enough—potentially real fast local assistants without server dependence.
* **Hardware specialization:** Frolicing research teams are already designing custom low-cost “LPUs” tailored for ternary nets—Groq’s start-up ventures hint toward such future devices.

In short:

So next time someone says “I need more layers for better language models,” you might suggest “More layers you can fit inside one little popcorn kernel using just − ¹/0/+¹”). # Ternary Transformers – Inside the Architecture Of BitNet \(b^{1.58}\)

When people talk about *low‑bit* language models they usually think of a few‑bit *post‑training* quantisation applied only during inference.
What you’ll read here is how **BitNet \(b^{1.58}\)** flips that convention upside down:
the entire network is trained **from scratch** with ternary weights (\{- 1, 0, + 1\}) and eight‑bit activations,
yet matches full–precision Transformer baselines on perplexity and downstream tasks once you reach around three billion parameters.



--------------------------------------------------------------------

## The Core Idea – Replace every linear layer

In a vanilla Transformer every matrix multiplication comes from an `nn.Linear`,
which multiplies floating‑point tensors.
**BitNet \(b^{1.58}\)** replaces these dense blocks with its own module called **BitLinear**.
All multiplications now collapse into *integer additions*:

```
output = input            *   weight_scaling_factor
        + sign(weight)    ∘   input             # sign(weight) ∈ {−1,0,+1}
```

Because a ternary weight is either − or + or disappeared entirely (`0`),
the dot products do **not require any real multiplication**, only an
add/subtract operation per non‑zero entry.
This cheap operation means two things immediately:

* **Arithmetic becomes fast** – modern GPUs have highly optimised INT8 adders,
and custom silicon can trivially drop multipliers.
* **Memory shrinks** – every weight needs just one *sign* bit
plus one extra bit telling whether it’s a zero.



--------------------------------------------------------------------

## Ternarising Weights – “absmean” rounding

The key challenge is forcing all parameters into \{- 1, 0, + 1\}
while still letting gradients flow during learning.
BitNet adopts an *absmean* quantisation strategy:

```math
g          = \\displaystyle\\frac{\\sum_{i,j}\\lvert W_{ij}\\rvert}{n m}
\\tilde W   = \\operatorname*{RoundClip}\\!
           \\Big(\\frac{W}{g+\\varepsilon},\\,-\\,01,+\\,01\\Big)
```

where  
\(g\) is the average absolute value over the whole matrix,
and \(\operatorname*{RoundClip}(x,a,b)\) snaps \(x\) first to the nearest integer
and then clamps it between \(a\) and \(b\).
The division by \(g\) normalises the spectrum before rounding,
so the discrete set remains balanced;
the added constant \(\varepsilon\) keeps division well-defined.


Because this operation is performed *inside the forward pass*,
gradients naturally back‑propagate through the rounding step –
the usual “straight‑through estimator” trick that has become standard
in quantised‐training papers.



--------------------------------------------------------------------

## Activations Stay Intensity Two’s Complement

Weights get completely binary,
but activations stay eight‐bit integers.
Why eight bits?

| Reason | Description |
|--------|-------------|
| Symmetry | Activations span both positive and negative values after every norm layer; keeping a symmetric range avoids an extra “zero‐point” offset |
| Practicality | We range‑scale each token’s activation map into \([-Q_b,Q_b]\), giving lighter hardware and simpler pipelines |
| Performance | Empirically dropping activations past four bits hurts downstream tasks severely,
but eight bits gives room for learning complex patterns without extra FP reduction |

Unlike post‑trained compression schemes that rescale outputs before non‑linearities,
BitNet keeps raw eight‑bit values across all Transformer blocks,
streamlining both software inference engines and hardware RTL.



--------------------------------------------------------------------

## From Token → Token – Training From Scratch

Unlike conventional low‑bit approaches,
BitNet doesn’t start from an already huge FP model
and then compresses it.
Instead it begins anew:
the REDPajama corpus feeds **100 B tokens**, identical seed data as their FP baselines;
optimisation uses Adam over ternarised parameters;
all biases were omitted—all were split out exactly following LLaMA’s bias–free design:
RMSNorm replaces LayerNorm,
SwiGLU replaces GELU,
and rotary embeddings stay unchanged.


The outcome was striking:

* At **3 B parameters**, perplexities on WikiText2/C4 match those of an FP16 version trained under identical colour settings.
* For larger sizes (**3·9 B**) BitNet slightly surpasses its FP counterpart while consuming \<35 % of the GPU memory and being ≳2·4× faster per output token.
These benefits magnify again farther up in scale;
a **70 B† model runs >4× faster than its FP16 peer**, squeezing triple legacy memory usage.



--------------------------------------------------------------------

## Why This Matters For Faster & Greener Inference

| Metric | Conventional FP16 | BitNet \(b^{1.58}\) |
|--------|------------------|-----------------------|
| Matrix mult arithmetic | FP16 × FP16 → FP32 mul + add | INT8 add(+/-)/skip |
| Memory footprint | Weight matrix ≈ 32 bits per param | Weight matrix ≈ 2–3 bits per param |
| Bandwidth when loading | High DRAM→GPU traffic |︎ Near-zero transfer contention |
| Energy cost (matrix stage) | ~71× higher silicon power per cycle | Low INT power → order‑of‑magnitude saving |

The research saw an almost **71× reduction** in arithmetic–energy crunch
reported via an open silicon model at eleven nanometres,
illustrating how cheap integer arithmetic translates into hotter mind FlPs fit onto a single die.



--------------------------------------------------------------------

## Scaling Law Revisited

Because even tiny five‐hundred megabyte gains compound
as per layer count grows,
BitNet’s scaling law looks surprisingly different.
A rough equivalence table floats around:

| Target Tier | Equivalent Quality |
|-------------|--------------------|
| *13 B* parseable scores “equal” → equivalent fully precise **3 B** model |
| *30 B* matches fully precise ⇒ equivalent “7 B” level |
| *70 B* speeds past fully precise “13 B” partner |

This turns “size × cost” trade‑off upside down:
you care more about adding capacity than letting cost go linear.



--------------------------------------------------------------------

## What This Enables Downstream

Besides headline numbers,
the architectural choices unlock practical paths:

* **Mixture–of–Experts** becomes simpler  
The reduced memory leaves room for dozens of experts per chip  
and cuts intra‑chip communication dramatically ‑ pushing MoE toward single‐chip deployment again.
  
* **Longer context windows**  
Kalib favourite lengths now fit twice into a fixed KV buffer
because activations float only eight bits versus twenty‐six required otherwise;
further hopdowns to four bits are planned next QAs.

* **Edge & Mobile devs**  
Surprise trade space permits deploying >10 bn parameter networks on phones
without hitting billable GPU rentals –
CPU-friendly integer workloads make portable acceleration beautiful again.



--------------------------------------------------------------------

BitNet \(b^{i.e.\;} {\rm ln\, decimal\, b}_{=2\.58^\circ C}^{ {…}}\)

It proves you do _not_ need floating point heavyweights:
by rethinking two pillars—forcing ternary synchronisation across linear layers  
and keeping eight‐bit activations—a Transformer trained fresh stays true-to-performance while halving latency and cutting energy aggressively.


It opens many doors—from hardware prototypes tailored purely for (*signed*) INT adders 
to smarter inference backends that treat text tokens almost like data streams drawn off cheap SRAM lanes instead of dense floating registers.

# Designing Chips That Speak One Bill – Why AI Drivers Are Turning Toward Ultra Tiny Arithmetic  

Large‑language models have grown far beyond what a single commodity chip could ever run cheaply or sustainably today. When you strip down an inference pipeline you find two dominant constants worth disrupting: **floating‑point multiplications** that burn power and **gigabytes‑worth of parameters** that flood off‑chip memories every minute you wait for a response.



-----------------------------------------------------------------------

## The Grand Scaling Problem  

Predictive performance scales logarithmically with both dataset size and model depth while inferencing costs grow nearly cubically once you turn on an automatic‐mixed precision GEMM loop across dozens of thousands of voxels in every forward pass.
The industry’s standard workaround has been post‑training low‑bit quantisation (\< 8 bits) applied via techniques such as SmoothQuant or GPTQ.
However,
post‑training compression inevitably loses granularity that is vital when you start training larger meshes or raise token counts into trillions.
Moreover, even state‑of‑the‐art QAT pipelines still deploy floating‐point multipliers during training due to rule‑based extensions rather than fundamental change.



-----------------------------------------------------------------------

## From Floating Point Paradise To One‑bit Language Models  

Enter **BitNet b\(^{\,{\scriptscriptstyle​}}_{\,^{—}}\)**—an elegant project extending its predecessor BitNet into a fully direct‑from‑scratch trainer that renders every weight ternary:
$$
w_{ij}\;\in\;\{-\,1,\;\!\!0,\;\!+\,1\}.
$$
The key idea behind restricting weights comes straight forward yet powerful:
the dot product no longer demands any multiply unit,
only an addition conditioned on whether the weight is positive,
a subtraction conditioned on a negative sign,
or nothing when it’s zero.
Consequently every linear layer collapses into essentially an **add tree**, eliminating hundreds of floating‐point multiplier ASIC lanes.



-----------------------------------------------------------------------

#### Quantisation Scheme Summarised  

To clamp trainable continuous weights onto this set,
BitNet trains them using an **absmean** approach:
$$
\tilde W
= {\rm RoundClip}\!\left(\frac{W}{\gamma+\varepsilon}\right),
\qquad 
{\rm RoundClip}(x,a,b)
= \max(a,\min(b,\lfloor x\rceil)),
$$
where $\gamma=\tfrac{1}{nm}\sum_{ij}|W_{ij}|$ normalises our distribution before rounding.
Activations undergo a similar squeeze into eight integers per element,
keeping rounding deviance below $10^{-2}$ while removing any signed offset overall—
which simplifies SIMD lane control dramatically.



-----------------------------------------------------------------------

## Architecture Side Effects At Scale  

### Multipliers → Adders  
A generic transformer block requires $O(N^2)$ multiply–accumulate vcores.
Replacing every MAC buffer with an adder tree cuts power draw dramatically –
floating‐point sub‑nanometer circuits consume roughly $\times80$ more joule per operation than their integer counterparts.
Consequently modern GPUs hitting $10^{12}$ FLOPs per watt cannot rely solely on strength normalization anymore –
they become bottlenecked either upstream actuator heat core or bus serialization.



### Micro­Memory Levers  
Given $m$ model parameters originally stored one per two bytes ($FP_{16}$),
cost drops proportionally:
bitternous storage needs only $\log_2(3)\approx 1.\!585$ durable bits,
meaning a theoretical $\times31$\!-\!40 reduction compared against binary storage.
For instance,
a nominally \$70 B transformer falls from roughly \$140 GB FP\(^{0}\)
to under \$5 GB @ \('\textbf{{-\!0,+\!}}\)tally',
an entirely different consumer class once just dealing with DRAM access latency.

# Tiny Bits Big Impact – From Mobile Edge Devices To Long Contexts

Large language models (LLMs) have become smaller no more smaller — today models reach hundreds of billions of parameters while still demanding gigabytes of VRAM, multi‑GPU clusters, and huge electricity bills during both training and inference.  
A recent family of models called **BitNet b₁·₅₈** turns this trend around by replacing every floating‑point weight with one wheel‑turn ternary value \(\{-1,\!0,\!+1\}\). Because each weight needs only \( \log_2(3)\approx1.6\) bits whereas conventional weights occupy \(16\) bits, the resulting network is lightning‑fast, embarrassingly cheap to store, yet *matches* full‑precision baselines again once it reaches about \(3\) billion parameters.



------------------------------------------------------------------

## A Quick Primer on BitNet b₁·₅₈

| Feature | Standard FP16 Transformer | BitNet b₁·₅₈ |
|---------|---------------------------|--------------|
| Weight format | \(16\)-bit floating point | Ternary \(\{-1,\!0,\!+1\}\) (≈ \(1{+}\log_2(4)\) bits after scaling) |
| Activation format | \(16\)-bit FP | \(8\)-bit INT |
| Core matmul | FP‐multiply + FP‑add | Integer add only |
| Uniform layers | Full precision linear layers (`nn.Linear`) | Replace with `BitLinear` layers that respect the ternary scale |
| Architecture palette | RMSNorm + SwiGLU + rotary embeddings | Same LLaMA–style backbone |

Quantization works through what the authors call an *absmean* mapping:
\[
\widetilde{W} = \text{RoundClip}\!\biggl( \frac{W}{\,\gamma+\epsilon\,},\, -1 ,\, +1 \biggr ),
\qquad
\gamma = \frac{1}{nm}\sum_{ij}|W_{ij}|.
\]
All computations therefore stay integer‑only after this initial integer scaling step.



------------------------------------------------------------------

## Why One‐Bit Is Such a Game Changer

### Memory

If a regular \(10^9\times10^9\) weight tensor needs \(160\,\text{GB}\), its ternary counterpart shrinks it down by almost an order of magnitude—all without hurting downstream task performance once the model has grown past roughly \(3\,\text{billion}\).

### Compute

During inference typical transformers perform half–million instructions per token × parameter count—a blowout largely dominated by floating‑point multiplications inside `nn.Linear`. Removing those multiplications leaves only integer additions:

* **Latency:** At \(70\,\text{billion}\) parameters BitNet b₁·₅₈ ran **over four times faster** than the same sized FP16 model—mostly because the `nn.Linear` kernels dominate runtime calls and become trivial integer adds.
* **Throughput:** Running two A100 GPUs side‑by‑side with pipeline parallelism let BitNet process almost eleven times larger batches than its floating‑point counterpart—nearly ninefold higher overall throughput.
* **Energy:** In silicon powered by modern \(7\,\text{nm}\) processes each INT8 add drills down past an energy cost roughly an order smaller than an FP16 multiply–add chain—leading investigators to claim more than seventy‐fold savings in raw arithmetic‐energy budget just for matrix multiplies.



------------------------------------------------------------------

## Real‑World Ramifications

### Clothes Well For Smartphone & Embedded CPUs

The reduced footprint means all the neural network data—including expanding GPT‑style chains—can cohabit comfortably inside phone RAM or minimally within an MCU cache tier that is normally limited to several megabytes today:
* A \(4\,\text{billion}\)-parameter version occupies about twelve petabytes fewer GPU‑like words → well under a few megabytes in ideated edge nodes.
* Integer additions heavily map onto standard ALU pipelines present even on minimal microcontrollers else requiring little from specialized SIMD units—a boon when battery life craves minimal power draw.



### Longer Stateful Conversations Unleashed

Current transformer decoders abuse their KV cache waves (\(O(L)\times D\times B\)), pushing very long context stretches heavy on both storage and traffic among DPUs/chips people harness when scaling prototypes outwards.
With activation precision dropped from FP16 into INT8,
the KV cache becomes half its former width—as if every slot already lives twice as long—and equates classroom data usage akin to renaming runtime impetus:
> Doubling max feasible session length without any extra memory allocation or bandwidth pressure.



### Put Mixture-of-Experts On A Single Chip

Mixture-of-experts designs bring huge computational savings through expert gating—but historically demand many devices plus expensive interconnect traffic for moving activations between shards.
Because each parameter contracts into one wire instead of sixteen,
exponentially more experts fit into a handset’s single die volume,
and inter-expert communication becomes cheaper enough that scientists envision deploying MoE blocks entirely inside one chip’s SRAM isolation arena.



------------------------------------------------------------------

## Scaling Law Revisited

BitNet introduces an altogether different scaling trajectory versus classic linear ones:

| Quantization Model | Relative Efficiency vs Full Precision |
|--------------------|----------------------------------------|

In other words: “a tenfold tensor growth doesn’t stir up tenfold runtime cost”—the relationship between compute/memory footprints remains flat once you move past modest sizes.

\title{Blogs about the Paper: "DeepSeekMath: Pushing the Limits of Mathematical Reasoning in Open Language Models"}

# Coding Trains Math Skills Too

> “Code training” isn’t just game‑development slang—it actually boosts mathematical problem solving.  
> In this post we break down two sets of multi‑stage experiments that show why starting a large language model (LLM) from a deep coder gives its later math instruction time an extra edge.



## Why Zipping Between Code & Math Matters

Large language models typically learn everything together—text, instructions, answers—but when you want them to crack hard numbers or prove equations you hit a wall.  
The authors of **DeepSeekMath** put one theory to test:

> **Code bugs are tiny puzzles**  
>   *Programming* forces you to think in *precise, step‑wise* terms—writing correct syntax is one thing, debugging is another.  
> If an LLM has already learned how browsers catch “if mismatches” before it learns arithmetic rules, it carries over a procedural mindset that works well on long chain‑of‑thought problems.



## Two Kinds of Multiplatform Trials

The experiments split into two families—each telling us what happens when you combine coding data *before* or *alongside* mathematical data.



### 1. Two‑Stage Curriculum

| Stage | Tokens | Purpose |
|-------|--------|---------|
| **First** | **400 B** – Unsupervised code | Teach raw syntax & logical flow |
| **Second** | **150 B** – Maths | Layer arithmetic & proof patterns |

**What happened?**

* After the first phase alone, the model was already better at writing working Python scripts for short questions—for example GA–<boosted probability by ~15 % versus a model trained only on natural language>.
* A second maths pass sharpened its ability to *reason stepwise* while still using tools—GSM8K jumps from roughly 70 % → 85 %, and MATH climbs from near 40 % → 55 % accuracy.
* A control line trained first on generic text instead of code saw far weaker gains after maths fine‑tuning (~25 % less on GSM8K), proving that coding itself matters.



### 2. One‑Stage Hybrid Mix

| Distribution | Tokens | Aim |
|--------------|--------|-----|
| Code + Maths | **400 B + 150 B** blended together | Full‑stack learning within one continuous loop |

**Observations**

* Mixing inside a single pass kills the “catastrophic forgetting” you see when switching phases—the model keeps its programming chops while still catching new maths logic.
* Resulting programs solve more guided Python problems—upward shift similar to two‑stage heights (~+10 % over pure‐math baseline).
* For pure non‑toolmath styles (answers written out without executing Python), blending was even slightly worse than two stages alone—likely because a ~1–1.3 B parameter model cannot fully absorb both streams simultaneously.



## Digging Into Why Coding Helps

1. **Procedural Discipline** – Code forces “do something until something else” loops; maths problem solving often follows similar bootstrapped procedures (e.g., algebraic substitution).
2. **Error Signal Clarity** – A compiler raises *exactly* where you went wrong; reward signals during continued pre‑training reflect precise failures instead of vague natural language confusion.
3. **Logical Unit Testing** – Executable snippets let the model see if each intermediate step actually gives the correct output—a positive reinforcement signal not present when just reading text.



## Practical Takeaways for Anyone Building Math LLMs

1. **Start With Code First?**  
   *Good enough.* If your hardware allows it, begin by spending a substantial portion (≈40 % ) your pre‑training budget teaching coding sequences before doing mathematics modules—especially if you plan tool–integrated reasoning soon afterward.
2. **Mix It Up When Capacity’s High**  
   *When you have ≥10–12 B parameters,* start blending coding & maths rather than staging them sequentially—this avoids forgetting while still hearing both signals cleanly.
3. **Match Scale With Strategy**  
   Small models (“LLM‑small”) shine under staged curriculum; medium models are tolerant of mix‐in; huge models like GPT‑4 can handle either without aggressive changes.
4. **Don’t Forget Non‑Toolmath Losses**  
   Even if your end goal is toolable maths (Python + SymPy), keep some plain question answering batches alive—they help build commonsense grounding necessary for open domain problems.



## Bottom Line

When DeepSeekMath’s authors mapped out “what happens if we give an LLM years’ worth of compiler-minded practice before pushing it into arithmetic wars,” they found:

* Coding provides a robust scaffolding for structured problem solving,
* Two stages give clean separation but risk forgetting,
* One stage adds synergy – especially when replayed against powerful reward regimes such as GRPO,
* And crucially—cooking up massive amounts of mathematically oriented web data alone isn’t enough unless accompanied by a generous share of solid code examples.

So next time you think “let’s train an LLM end straight on mathematics,” remember: the best recipes bake in some karma from coding first—because those tiny syntax errors turn out being golden nuggets for higher‑level number crunching!

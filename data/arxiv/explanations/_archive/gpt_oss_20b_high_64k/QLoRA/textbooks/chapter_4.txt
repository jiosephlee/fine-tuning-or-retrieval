# Computing Gaussian Quantiles \(q_{i}\)

The foundation of NormalFloat lies in exploiting the statistical regularity observed across transformer weight tensors. If a tensor’s elements are drawn from a zero‑centered Gaussian distribution \(N(0,\sigma)\), then every length‑\(b\times h\) block shares a well‑defined shape under any scaling factor applied uniformly across the block. Because the sign symmetry guarantees an identical distribution before and after sign change, we can describe all possible element magnitudes using a single cumulative density function (CDF). Consequently it becomes tractable—contrary to ill‑estimated “first‑stage” “blockwise” methods—to compute *exact* percentiles once and reuse them across all blocks via a simple look‑up table.

To create a \(k\)-bit data type whose bins contain an equal amount of probability mass we compute
\[
q_{i}
~=~\frac{1}{2}\!\left(Q_{N(0,\,1)}\!\left(\tfrac{i}{\,2^{\,k}+\,1\,}\right)
                         ~+~Q_{N(0,\,1)}\!\left(\tfrac{i+\,1}{\,2^{\,k}+\,1\,}\right)\right),
\quad i=0,\dotsc ,2^{\,k}-1,
\]
where \(Q_{N(0,\,1)}(\cdot)\) is the inverse CDF of a unit‑variance standard normal variable.
The arithmetic above simply averages two neighbouring theoretical percentiles so that every term corresponds precisely to the midpoint between two probability masses. Tapping this list yields precisely \(w_{\min},w_{\min+\delta}, \dotsc ,w_{\max}\) spaced so that all intervals capture equal likelihood under the underlying normal model. Thus our resulting bins honor an *information‑theoretically optimal* allocation scheme—each bin absorbs roughly \(\tfrac{100}{2^{\,k}}\%\) of samples when confronted with truly Gaussian data—ensuring minimal mean‑square distortion per bit spent.

Because transformer weights are batched/flattened naturally into blocks during inference or training, each block shares its own scale factor yet shares these global indices \(q_i\); the work above therefore lends itself perfectly well into blockwise stateful or state‑free “hash map” implementations where each stored integer simply refers back through this table during decompression rather than storing floating point densities themselves.

# Asymmetrised Zero‑Point Construction

A naïve choice would force us onto a symmetric binary interval such as
\[
[-M,M],~M=2^{\,k-}\!-\!1,
\]
yet it would inevitably suffer two fundamental ailments:
firstly there would be no literal numeric token representing exact zero—critical when padding tensors are diffused across multiple blocks; secondly symmetric intervals waste one entry by overlapping on both signs when allocating an odd number of bins.
To solve this problem without sacrificing our quantity‑optimality guarantees we construct an **asymmetric** scheme whereby negative numbers occupy exactly half the bin space while positive numbers receive one additional bin so that one copy can encode true zero separately.
Concretely we run our \(q_i\) routine twice:
one run populates –\(q_0,\dotsc,-q_{\lfloor 2^{\,k}/2 \rfloor - 1}\),
the second produces \(+q_0,+q_+\dotsc,+q_{\lceil 2^{\,k}/2\rceil - 3}\).
Because both lists share a unique ‘zero’ element at i=0,
we discard one duplicate so that every eventual integer encoding contains a single exact–zero symbol occupying its own codeword.

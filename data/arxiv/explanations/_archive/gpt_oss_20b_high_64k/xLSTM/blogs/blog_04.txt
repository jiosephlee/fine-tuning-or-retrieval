# Scaling Beyond Attention – Why x‑LSTMs Outperform Transformers When Size Matters  

Large‑scale language modelling has been dominated by self‑attention since Vaswani et al.’s Transformer introduced linear‑time self‑attention kernels that can be parallelised across GPUs.  
What happens if we put **the venerable LSTM** – a gated recurrent network that has lived through decades of NLP research – at billion‑parameter scale and patch its historic weaknesses? The answer appears surprisingly positive: **x‑LSTMs** — an extensive extension of the classic LSTM — beat GPT‑3–sized Transformers and State‑Space Models (SSMs) on validation perplexity when trained on huge corpora, scale favourably according to power‑law laws, maintain low perplexity even at a sequence length of \(16\,384\) tokens, and run faster because their memory usage is constant w.r.t. context length.  

Below we walk through the main advances that enable this performance jump, summarize key experimental findings, and discuss what it means for deployment on edge devices and reinforcement learning agents where long‑term memory matters most.


## A Quick Primer on x‑LSTM

### Exponential Gating  

In a standard LSTM the input gate \(i_t\), forget gate \(f_t\), and output gate \(o_t\) are all sigmoid bounded in \([0,1]\):
\[
c_t = f_tc_{t-1}+i_tz_t,\qquad
h_t=o_t\psi(c_t).
\]
Exponential gating replaces the sigmoid with an unbounded exponential function:
\[
i_t=\exp(\tilde i_t),\qquad
f_t=
\begin{cases}
\sigma(\tilde f_t)&\text{or}\\
\exp(\tilde f_ t)
\end{cases}
\]
This change lets an LSTM *revise* earlier storage choices more aggressively—the forget gate can now grow arbitrarily large instead of being capped at one – which turns out essential for **state tracking** tasks such as formal grammar parsing and rare‐token prediction.


### Two Memory Variants

| Variant | Memory form | Update rule | Parallelizable |
|---------|-------------|-----------|----------------|
| **sLSTM** | Scalar \(c \in \mathbb R\) + normalizer \(n\) | Same update as regular LSTM plus normalizer accruing future forget gates | No – hidden‐to‐hidden mix still sequential |
| **mLSTM** | Matrix \(\mathbf C \in \mathbb R^{d\times d}\) (key/value covariances) | Covariance update \( \mathbf C_t=\mathbf C_{t-1}+i_tv_kk^\top\)| Yes – no recurrent projection between consecutive states |

The **mLSTM** receives key/value vectors derived from every token,
stores their outer product into a shared matrix using a decay factor supplied by \(f_t\), and retrieves a query vector through a simple dot product:
\[
q_t=\mathbf W_qx_t,\quad
h_t=\frac{\mathbf C t q}{\max(|n^\top q|,1)}.
\]
Because each step only mutates a fixed size matrix it can be computed entirely in parallel using level‑3 BLAS primitives — akin to FlashAttention’s batched matrix–matrix operations.



### Residual Backbone & Scaling Up

Both variants sit inside familiar pre‑LayerNorm‐residual blocks:

* **sLSTM block** – post‑up-projection style (like the original Transformer encoder).
* **mLSTM block** – pre‑up-projection style (like S4), bringing richer memory into higher-dimensional space before projection back down.

An **x‑LSTM architecture** stacks dozens of these blocks uniformly — exactly the same recipe used by contemporary large language models.



## Large‑Scale Validation Experiments

### Training Setup
* Dataset : **15 B** tokens from SlimPajama.
* Model size : ~350 M parameters (~GPT‑3’s 350 M base).
* Compared systems  
  * Transformers (GPT‑3 / Llama)\  
  * State‑Space Models (H3 / Mamba)\  
  * Recurrent nets with linear attention & Fast Weight tricks  
    *(RWKV/GLA/HGRN/RWKV5/6)*

All models ran under identical mixed‑precision training schemes.



### Peaking over GPT–3

On the SlimPajama validation set *perplexity* shows that **x-LSTMa surpasses every competitor** measured in this cohort:

> *The best transformer (GPT‑3) achieved X PPL whereas x-LSTMa hit Y PPL*, an improvement that persists across all explored checkpoints.  
> Crucially this was achieved without extra layers or rescaled vocabularies—something TG enters manually by shared weights.



### Power­law Scaling Is Not Breached

Plotting model size versus perplexity reveals all families follow a clean inverse–power law:
\(E(N)=a\,N^{b}\).
All curves bend similarly—with slopes (**\(b ≈ ‑0.25… −0.28\)**) almost identical—but they differ in *offset* \(a\).
x-LSTMa has consistently smaller offsets than both transformers and SSMs,
so as you upscale past billions-of-parameters regime it will stay at least a few percent ahead.



## Long–Context Robustness

Rethinking “long‐term memory” in language modeling requires testing whether narrowing context during training locks you into short windows later.

In a separate series:

1. Models trained on *2048*-token contexts were evaluated at lengths ranging from 512 up to **16 384 tokens**.
2.
   *RNN-style baselines* degrade quickly once past their training window  
   (perplexity often doubles beyond 4096 tokens).
   *Transformer/SSM baselines* suffer due partly from quadratic self-composition costs dropping accuracy sharply beyond 8192 tokens.
   *x-LSTMa*, however, keeps perplexity almost flat out until ~16 k—a large step forward for high‐memory tasks such as story generation or policy logging.


The key driver is exponential gating in s/L/LS/Tmie that lets newer observations outweigh older ones smoothly without requiring expensive attention heads.



## Inference Speed & Constant Memory Footprint

Recurrent nets normally carry forward just one hidden vector along the sequence—no additional per-position state—thus inference cost grows linearly:
\(T_{\text{inf}}=O(N)\).

Transformer cells need an additional \(O(N^2)\) dot products per layer because every token attends to every other token—in practice exploding GPU load.


**Measured timings (ten thousand token batches)**  

| Model | Per-token time | Throughput @ batch=32 |
|-------|-----------------|-----------------------|
| Transformer & Mamba | Quadratic growth → ~50 ms/token at 2560 chars | ~20 t/s |
| **x-LSTMa** | Near-linear           → <10 ms/token @ 2560 chars | >70 t/s |

Even though s-LSTMa cannot be fully parallelised due to hidden projection mixes its custom CUDA kernels finish within twice time of m-LSTMa’s blas implementations—well below real-world overhead of transformer inference pipelines implemented carelessly.


**Implication:** Deploying a billion‐parameter language model on an edge device becomes tractable because:

* Memory remains bounded by constant model parameters *(≈ few hundred MB)* regardless of context depth.
* Computation collapses linearly with length instead of exploding quadratically.
* No specialized GPU kernels are required beyond ordinary matrix multiplication for m-LSTMa or fast-looking custom kernels for s-LSTMa.



## Downstream Utility Across Tasks

When fine-tuned on downstream benchmarks available via `lmeval`, **x-LSTMa win rates translated directly into better performance across almost every task**, especially:

* Common-sense reasoning suites,
* Retrieval-based question-answering,
* Knowledge grounding measures,
* Code-generation tests,

with only one exception—the ARC dataset where Mamba had slight edge at some checkpoints—showing heritage performance close enough that choice depends mainly on system constraints rather than raw metrics.



## Significance for Reinforcement Learning & Edge AI

Reinforcement learning agents often operate over thousands of timesteps while maintaining internal belief states about hidden dynamics—they essentially solve *state tracking*. Historically RNN-cell components were abandoned because transformers shone elsewhere despite quadratic cost spikes during simulation rollouts on long horizons.



With powerful exponential-gated s/L/Tmstm modules that allow revisable long-term retention—and easily scalable matrices carrying rich association memories—the same architecture could become an almost drop-in replacement for current recurrent policy networks without sacrificing sample efficiency:


| Deployment    | Trade-offs                       |
|---------------|----------------------------------|
| Cloud PPO     | Can train billions directly      |
| DaVinci RL    | Edge-friendly inference          |
| Offline explainability | Bounded long-term trace         |

Furthermore A11 fixes approximate value functions just via simple dot products instead of multiply–accumulate attention heads — saving both compute cycles and energy consumption—a lot appreciated when building autonomous robots or IoT sensors that must learn continually online.



## Bottom Line: What Even You Can Do Right Now  

If you’re ready to experiment with an “attention-free” yet **comparable-scaled** language model today:

1️⃣ Clone their git repository `https://github.com/NX-AI/xlstm` – it contains PyTorch heavy weight versions running fully automatically under `torch.compile` after installing optional dependencies (`faiss`, `flash_attn`).

2️⃣ Start with one “minimalist” configuration e.g.:

```python
from xlstm import XLTMAGrid
model = XLTMAGrid(
    dim=1024,
    depth=48,
    xlstm_ratio=(7,1),   # mostly mLLS blocks
    heads=12,
    prenorm=True,
)
```

3️⃣ Fine-tune against your own corpus using plain `AdamW( lr=5e-5 )`; no special learning rates required since they tied them all together automatically thanks scientific exploration done in Section 5B regarding gating design choices.



In summary, practitioners who value “longer context”, “linear inference time”, or “deployability” return substantial gains simply by switching from Transformer cores (-scaling-perplexities + better sequences + lower latency). It feels almost like breathing life into an old staple design—now turbo-charged with modern tricks—when you realise carefully engineered gates handcuff nonlinearities back into place instead of exploding them onto dense tensor products.

# Benchmarks and Beyond: How xLSTM Performs on Synthetic Tasks, Long‑Range Arena, and Real‑World Language Modeling  

In the last few years the Transformer has become the de‑facto backbone of large language models (LLMs).  Yet the classic recurrent architecture – the Long Short‑Term Memory (LSTM) – still has a loyal following because of its linear time‑and‑memory scaling and its ability to store information over arbitrarily long horizons.  The **xLSTM** paper asks a simple yet ambitious question: *What happens if we scale LSTMs to billions of parameters while fixing their historic shortcomings?*  

The authors answer this by introducing two key ingredients:  

1. **Exponential gating** (input and forget gates can be exponential instead of sigmoid, together with a stabilizer state).  
2. **New memory structures** – a scalar‑based sLSTM that adds a normalizer state for reversible updates, and a matrix‑based mLSTM that stores key‑value pairs via a covariance (outer‑product) update.  

Both variants are wrapped in modern residual blocks, yielding **xLSTM blocks** that can be stacked into deep architectures just like the layers of GPT‑3 or Mamba.  

Below we walk through the experimental evidence presented in the paper, from carefully crafted synthetic problems to full‑scale language modeling, and explain why xLSTM often outperforms Transformers and State‑Space Models (SSMs) on these benchmarks.

---  

## 1. Synthetic Formal‑Language Tasks – Testing Exponential Gating & Memory Mixing  

Formal languages are a classic probe for sequence models because they require **state tracking**: a model must keep an internal flag that flips based on distant symbols (e.g., parity or copy tasks).  Earlier work showed that vanilla Transformers and many SSMs cannot solve such tasks reliably because they lack hidden‑to‑hidden recurrence.  

### What the authors did  
* Extended the suite from Deletang et al. (2023) to allow training on multiple sequence lengths and testing on extrapolation lengths.  
* Compared 2‑block versions of several models:   

| Model | Block composition | Key property |
|-------|-------------------|--------------|
| xLSTM[0:1] | Only sLSTM | Exponential gating + memory mixing |
| xLSTM[1:0] | Only mLSTM | Matrix memory, no mixing |
| xLSTM[1:1] | Mixed sLSTM+mLSTM | Both ingredients |
| Llama | Transformer | No hidden recurrence |
| Mamba / RWKV / Retention / Hyena | SSM / linear RNNs | Linear dynamics, no mixing |
| LSTM & LSTM‑in‑TransformerBlock | Classic RNNs | Sigmoid gating only |

* Measured task accuracy (0 = random, 1 = perfect) on the *relevant* tokens only.  

### Results & Takeaways  
* **Only models with memory mixing (sLSTM)** solved parity and other regular grammars with near‑perfect accuracy, even when extrapolating to longer sequences than seen during training.  
* Pure Transformers and SSMs plateaued near chance, confirming earlier theoretical claims that they are *fundamentally less expressive* for state tracking.  
* Adding a matrix memory (mLSTM) alone does **not** give state tracking ability, but when combined with sLSTM in xLSTM[1:1] the model benefits from both larger storage capacity *and* reversible updates, achieving the highest scores among recurrent baselines.  

**Bottom line:** Exponential gating together with hidden‑to‑hidden mixing gives xLSTM a decisive edge on tasks that demand explicit state preservation – something traditional attention mechanisms struggle with.

---  

## 2. Associative Recall – Probing Memory Capacity with mLSTM  

The *Multi‑Query Associative Recall* (MQAR) benchmark tests whether a model can store many key–value pairs in its hidden state and later retrieve them using a query vector.  It is directly relevant to language modeling where rare tokens must be memorized over long spans.

### Experimental design  
* Sequences contain up to **256 random key–value pairs**, each drawn from a large vocabulary.  
* Context length stretched to **2048 tokens** – far beyond typical LLM training windows.  
* Compared 2‑block versions of Llama (Transformer), Mamba (SSM), RWKV‑5/6 (RNN), and two xLSTM configurations (xLSTM[1:1] and xLSTM[1:0]).  

### Findings  
* **xLSTM[1:1]** achieved the highest recall accuracy among all non‑Transformer models across every difficulty level.  
* The pure mLSTM block (xLSTM[1:0]) performed well but lagged slightly behind when the number of pairs grew very large; this shows that *memory mixing across heads* in sLSTM can actually amplify the effective capacity of the matrix memory.  
* Transformers still hold an advantage because attention’s quadratic interaction yields an exponential effective capacity; however, xLSTM narrows the gap dramatically while keeping linear time/memory cost.

**Interpretation:** The covariance update rule of mLSTM acts like a fast weight programmer – each key/value pair adds an outer product to a $d\times d$ matrix.  Exponential forget/input gates control how quickly older entries decay, enabling stable long‑term storage without blowing up gradients.

## 3. Long Range Arena – Handling Thousands of Tokens  

The Long Range Arena (LRA) is a suite of six tasks ranging from path finding in graphs to image classification from flattened patches, all designed to test *very long context handling*.  

### Setup  
* Models were given their standard context window (usually 2048 tokens) and evaluated on all six LRA tasks.  
* xLSTM used mixed sLSTM/mLSTM blocks as in earlier experiments; other baselines included Transformers, Mamba, RWKV, Hyena, etc.

### Outcome  
Across every LRA task xLSTM **consistently ranked among the top performers**, frequently beating both pure Transformers and SSMs. The advantage was most pronounced on tasks that require explicit tracking of an evolving hidden state (e.g., *PathX*, *ListOps*).  

This result reinforces two earlier observations:

1. **Linear scaling** – because recurrence processes each token once, runtime grows only linearly with sequence length.  
2. **Expressivity from memory mixing** – hidden-to-hidden connections let xLSTM maintain precise symbolic information that would otherwise be lost in purely linear dynamics.

## 4. Real‑World Language Modeling – From 15 B to 300 B Tokens  

The ultimate test for any new architecture is whether it can compete with state-of-the-art LLMs on genuine language data.  The authors trained several xLSTM configurations on two scales:

| Training data | Token count | Model size family |
|---------------|-------------|-------------------|
| SlimPajama “small” | 15 B | ~350 M parameters |
| SlimPajama “large” | 300 B | 125 M → 1.3 B parameters |

All models share the same pre‑LayerNorm residual backbone as modern GPT variants, allowing a fair comparison.

### 4.1 Validation Perplexity on 15 B Tokens  
| Method | Params ≈350 M | Validation PPL |
|--------|---------------|----------------|
| GPT‑3 (Transformer) | — | ~13 |
| Llama | — | ~12 |
| H3 / Mamba (SSM) | — | ~12–13 |
| RWKV series (RNN) | — | ~13–14 |
| **xLSTM[7:1]** (mostly mLSTM) | — | **~11** |
| **xLSTM[1:0]** (pure mLSTM)   | — | **~11** |

xLSTM beats every baseline by roughly one perplexity point—a non‑trivial margin at this scale.

### 4.2 Ablation Insights  
Starting from a plain LSTM inside the same residual stack, three incremental changes were applied:

1. **Add residual block & up‑projection** → modest gain.
2. **Introduce exponential gating** → sizable drop in perplexity.
3. **Replace scalar cell with matrix memory (mLSTM)** → further reduction.

Both exponential gating *and* matrix memory proved essential; removing either erased most of the advantage.

### 4

#### Scaling to 300 B Tokens  
Four model sizes were trained (125 M → 1.3 B). Across all sizes:

* **xLSTM[7:1]** achieved the lowest validation perplexities versus Llama, Mamba, and RWKV-4.
* In *sequence length extrapolation*, xLSTM maintained low perplexity even when evaluated at context lengths up to **16 k**, whereas Transformers degraded sharply due to quadratic attention cost.
* On downstream reasoning benchmarks (*ARC*, *BoolQ*, etc.) xLSTM outperformed competitors in most cases; only ARC sometimes favored Mamba.
* The PALOMA benchmark—571 diverse text domains—showed that xLSTM[1:0] had lower perplexity than any other model in **99.5 %** of domains.

### 4.3 Scaling Laws  
Plotting loss versus model size revealed classic power‑law behavior for all families but with different intercepts:

```
Loss ≈ A * N^{-α} + B
```

where `N` is number of parameters.
- `α` was nearly identical across families (~0.07), indicating similar asymptotic slopes.
- `B` for xLSTM was consistently lower than for Transformers/SSMs, confirming an intrinsic quality advantage rather than just better scaling.

Consequently, extrapolating suggests that at multi‑billion parameter scales an xLSTM could beat current GPT‑4 level baselines while retaining linear inference cost.

---  

## 5. Practical Considerations – Speed & Memory  

Despite their recurrent nature, both sLSTM and mLSTMs keep *constant memory footprint* w.r.t sequence length:

- **Inference time:** Linear scaling for xLSTM contrasts with quadratic growth for Transformers; measured generation time per token stays flat up to at least 16k context.
- **Throughput:** Because memory does not grow with context length, batch sizes can be increased dramatically—xLSTM achieved higher tokens/second than Llama even without kernel optimizations.
- **GPU utilization:** Current CUDA kernels for mLSTMs are about four times slower than FlashAttention; however this overhead is modest compared to the gains from avoiding quadratic attention matrices.

The main bottleneck remains the matrix memory update (`d × d` operations). Future work on optimized kernels akin to FlashAttention could close this gap further.

---  

## 6. Where Does xLSTM Shine?  

| Benchmark Category          | Strength of xLSTM                                           |
|-----------------------------|-------------------------------------------------------------|
| Formal language / state tracking   | Exponential gating + hidden-to-hidden mixing enables perfect accuracy where Transformers fail |
| Associative recall / rare token storage | Covariance update provides high-capacity mutable memory without exploding parameters |
| Long Range Arena            | Linear time + expressive recurrence beats both Transformers and SSMs |
| Large-scale LM (15–300 B tokens)   | Lower validation perplexity; superior extrapolation; best performance on multi-domain PALOMA benchmark |

Overall, whenever a task demands **precise internal state**, **long-range dependency handling**, or ***efficient scaling*** beyond quadratic attention limits, xLSTM offers a compelling alternative.

---  

## 7. Limitations & Future Work  

- **Parallelism:** sLSTM’s memory mixing prevents full parallel execution; current CUDA kernels are ~2× slower than fully parallel mLSTMs.
- **Kernel maturity:** mLSTMs still lag behind highly tuned FlashAttention implementations; optimized kernels could unlock further speedups.
- **Memory size vs context:** For extremely long contexts (>16k) the fixed‐size matrix may saturate; adaptive strategies or hierarchical memories may be needed.
- **Hyperparameter tuning:** Large‐scale experiments used default settings; targeted tuning could push performance even higher.

---  

## Conclusion  

The experiments in “xLSTM: Extended Long Short-Term Memory” make a persuasive case that *recurrent architectures are not obsolete*. By modernizing gating mechanisms and expanding the cell into a learnable matrix memory, xLSTMs combine the best of both worlds:

- Linear compute & constant memory like classic RNNs,
- Expressive state tracking comparable to Turing-complete machines,
- Competitive or superior performance on synthetic reasoning tasks,
- State-of-the-art perplexities on massive language corpora,
- Strong scaling behavior promising continued gains at billions of parameters.

If you’re building models where inference speed matters (edge devices, real-time systems), or you need reliable long-range reasoning beyond what attention can provide, give xLSTMs a try—the code is openly available at https://github.com/NX-AI/xlstm .

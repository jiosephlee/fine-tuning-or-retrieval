# Memory Makeover: How Matrix Memories in mLSTM Boost Language Modeling

## Introduction

Long Short‑Term Memory networks (LSTMs) have been a workhorse of sequence modeling for three decades. Their hallmark—an additive **cell state** updated by gated inputs—solved the vanishing‑gradient problem that plagued earlier RNNs. Yet, classic LSTMs store information in a **scalar** cell (or a small vector of scalars), which severely limits what they can remember.  

The recent **xLSTM** family tackles this bottleneck head‑on. Its flagship variant, the **mLSTM**, replaces the usual scalar memory with a **matrix memory** and updates it using a **covariance (outer‑product) rule** reminiscent of associative memories and fast‑weight programmers. In practice, this richer memory lets xLSTM compete with modern Transformers on two notoriously hard language‑modeling challenges:

1. **Rare‑token prediction**, where the model must recall infrequent words that appear only a handful of times in the training corpus.  
2. **Associative recall**, where the model has to store many key‑value pairs and retrieve the correct value given a later query.

Below is an accessible walkthrough of how the matrix memory works, why the covariance update rule is ideal for key‑value storage, and how these ingredients translate into tangible performance gains.

## From Scalars to Matrices: The Core Idea

In a vanilla LSTM the cell state is a single number \(c_t\). At each time step we compute

\[
c_t = f_t\,c_{t-1} + i_t\,z_t,
\]

where \(i_t\) and \(f_t\) are the input and forget gates, and \(z_t\) is the candidate content. This formulation lets the network add or forget *one* piece of information per time step.

The mLSTM generalizes this to a **matrix cell** \(\mathbf{C}_t \in \mathbb{R}^{d\times d}\). Instead of adding a scalar, we add an *outer product* of two vectors:

\[
\mathbf{C}_t = f_t\,\mathbf{C}_{t-1} + i_t\,\mathbf{v}_t \mathbf{k}_t^\top .
\tag{1}
\]

- \(\mathbf{k}_t \in \mathbb{R}^d\) is called the **key** (think of it as an address).  
- \(\mathbf{v}_t \in \mathbb{R}^d\) is the **value** we want to remember at that address.  
- The gates \(i_t, f_t\) control *how strongly* we write or decay that outer product.

Because we store *pairs* of vectors instead of scalars, the matrix can hold up to \(d^2\) pieces of information (subject to linear dependencies). In practice, even modest dimensions (\(d=64\)–\(128\)) give vastly higher storage capacity than a scalar LSTM.

## Covariance Update Rule: Why It Works

Equation (1) is exactly the **covariance update rule** used in classic **Bidirectional Associative Memories (BAMs)** and later in **Fast Weight Programmers**:

\[
\Delta\mathbf{C} = \mathbf{v}\,\mathbf{k}^\top .
\]

Why is this update attractive for language modeling?

1. **Optimal Separability** – The outer product creates a rank‑one matrix that aligns perfectly with both key and value directions. When later multiplying by a query \(\mathbf{q}\), the retrieved vector becomes proportional to \(\mathbf{v}\) if \(\mathbf{q}\) aligns with \(\mathbf{k}\). This maximizes signal‑to‑noise ratio for binary or one‑hot queries (Dayan & Abbott, 1991).

2. **Linear Retrieval** – Retrieval is simply a matrix‑vector product:
   \[
   \tilde{\mathbf{h}}_t = \frac{\mathbf{C}_t\,\mathbf{q}_t}{\max\bigl(|\mathbf{n}_t^\top \mathbf{q}_t|,\,1\bigr)},
   \]
   where \(\mathbf{n}_t = f_t\,\mathbf{n}_{t-1}+i_t\,\mathbf{k}_t\) tracks the overall “strength” of stored keys (a normalizer that prevents division by near‑zero values). This operation is fully parallelizable on GPUs.

3. **Decay via Forget Gate** – The term \(f_t\,\mathbf{C}_{t-1}\) acts like an exponential decay on older memories, analogous to the forget gate in plain LSTMs. By learning appropriate \(f_t\), mLSTM can keep recent facts fresh while gradually fading obsolete ones.

Overall, the covariance update gives us an *associative* data structure: write once with a key–value pair, read later with any query that resembles the key.

## Putting It All Together: Forward Pass of mLSTM

Summarizing the full per‑step computation (omitting bias terms for brevity):

1. **Project input** into three vectors:
   - Query:                \( \mathbf{q}_t = \mathbf{W}_q \mathbf{x}_t \)
   - Key:               \( \mathbf{k}_t = \frac{1}{\sqrt{d}}\,\mathbf{W}_k \mathbf{x}_t \)
   - Value:        \( \mathbf{v}_t = \mathbf{W}_v \mathbf{x}_t \)

2. **Compute gates** (input gate uses an exponential activation, forget gate can be sigmoid or exponential):
   - \( i_t = \exp(\tilde{i}_t) ,\quad f_t = \sigma(\tilde{f}_t)  (\text{or } \exp)\)

3. **Update matrix memory** via Eq. (1).

4. **Update normalizer state**:
   - \( \mathbf{n}_t = f_t\,\mathbf{n}_{t-1} + i_t\,\mathbf{k}_t .\)

5. **Retrieve hidden state**:
   - Compute raw readout \( \tilde{\mathbf{h}}_t =  \frac{\mathbf{C}_t\,\mathbf{q}_t}{\max(|\mathbf{n}_t^\top \mathbf{q}_t|, 1)}.\)
   - Apply output gate: \(  \mathbf{h}_t = o_t \odot \tilde{\mathbf{h}}_t .\)

All matrix multiplications are dense linear algebra operations that modern GPUs handle extremely efficiently; there’s no explicit attention matrix that grows quadratically with sequence length.

## Why Matrix Memory Helps with Rare Tokens

Rare tokens pose two challenges for conventional LSTMs:

- The scalar cell must compress *many* contexts into a single number; finegrained distinctions get lost.
- A forget gate that never “rewrites” may permanently overwrite rare information once it appears later.

With a matrix memory each token can be stored as its own key–value pair:

- A *unique* key vector (derived from the token embedding and surrounding context) points to a *value* that captures its semantic contribution.
- Because outer products are additive, storing many rare tokens does not catastrophically interfere; they occupy orthogonal directions as long as their keys differ enough.
- The normalizer guarantees stable scaling even when many keys accumulate.

Empirically (see the paper’s Wikitext‑103 experiments), xLSTM with mLSTM dramatically reduces perplexity on low‑frequency word buckets—exactly where plain LSTMs fall short.

## Associative Recall: Putting Memory to the Test

The **Multi‑Query Associative Recall (MQAR)** benchmark stresses memory capacity by requiring models to memorize up to 256 random key–value pairs across a context up to 2048 tokens long and later answer several queries.

Results from the xLSTM paper show:

| Model                | MQAR Accuracy (256 pairs) |
|----------------------|---------------------------|
| Transformer (Llama) | ≈ 94 % |
| xLSTM[1:0] (all mLSTM blocks) | ≈ 95 % |
| xLSTM[7:1] (mostly mLSTM + one sLSTM) | ≈ 93 % |
| RWKV / Mamba        | ≈ 80 % |

The mLSTM’s matrix memory matches—or slightly exceeds—the massive quadratic attention of Transformers while keeping linear compute cost w.r.t. sequence length. In short, it gives us “Transformer‑level recall” without paying the quadratic price.

## From Theory to Practice: Scaling Benefits

Because mLSTM’s operations are linear in sequence length and constant in memory consumption, they scale nicely to billions of parameters:

- **Constant GPU memory per token:** No need to store an ever‑growing attention map.
- **Parallelizable updates:** Although sLSTM still needs sequential mixing, pure mLSTM blocks can be expressed as batched matrix multiplications similar to FlashAttention.
- **Favorable scaling laws:** In experiments on 15 B and 300 B token corpora, xLSTM consistently achieved lower validation perplexity than GPT‑3–scale Transformers and state‑space models across multiple model sizes.

These findings suggest that once implementation details (CUDA kernels for matrix memory, better forget‑gate initializations) are polished, mLSTM could become a go‑to building block for large language models that need both long context handling and efficient inference.

## Takeaway

The shift from a scalar cell to a full matrix memory—guided by the classic covariance update rule—gives LSTMs a dramatic boost in expressive power:

- It supplies *associative storage*: keys map directly to values via outer products.
- It expands capacity without blowing up compute: all steps are dense linear algebra.
- It solves concrete language‑modeling pain points such as rare-token prediction and associative recall.

In short, **matrix memories are the “memory makeover” LSTMs needed to stay competitive with Transformers**, opening new avenues for recurrent architectures at scale. If you’re curious about trying it yourself, check out the open‑source implementation at https://github.com/NX-AI/xlstm. Happy modeling!

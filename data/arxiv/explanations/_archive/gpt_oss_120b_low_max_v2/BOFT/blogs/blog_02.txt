\title{Blogs about the Paper: "Parameter-Efficient Orthogonal Finetuning via Factorization"}

# From Block‑Diagonal to Butterfly: Making Orthogonal Finetuning Parameter‑Efficient  

*In this post we unpack why the original Orthogonal Finetuning (OFT) blows up in parameters, how the authors turned the problem into an “information‑transmission” puzzle, and why borrowing the butterfly graph from the Fast Fourier Transform lets us shrink the trainable budget from \(O(d^{2})\) to \(O(d\log d)\).*  

---

## 1. Why Orthogonal Finetuning needs a rethink  

Finetuning massive foundation models without blowing up memory or compute is now a central challenge. OFT offers a principled alternative to low‑rank methods like LoRA: it **multiplies** each pretrained linear layer \(\mathbf W^{0}\in\mathbb R^{d\times n}\) by a learnable orthogonal matrix \(\mathbf R\in\mathbb R^{d\times d}\),

\[
\mathbf z = (\mathbf R \mathbf W^{0})^{\!\top}\mathbf x,
\]

preserving pairwise angles between neurons and therefore keeping much of the pretraining knowledge intact.  

The catch? A full dense orthogonal matrix has \(d^{2}\) entries, far too many to store or optimise when \(d\) is in the thousands (as in vision transformers or large language models). The original OFT paper sidestepped this by **forcing \(\mathbf R\) to be block‑diagonal**, i.e.

\[
\mathbf R = \operatorname{diag}(\mathbf R_{1},\dots,\mathbf R_{r}),\qquad \mathbf R_{i}\in\mathbb R^{b\times b},\; br=d,
\]

which reduces parameters to \(O(bd)\). Unfortunately, this sparsity pattern is quite rigid: each block transforms a disjoint subset of neuron dimensions independently, limiting expressiveness and preventing the matrix from ever becoming truly dense.

So the question becomes: **Can we obtain a dense orthogonal transformation while keeping the parameter count low?**  

---

## 2. Recasting the problem as information transmission  

Think of \(\mathbf R\) as a *connectivity matrix*: entry \(R_{ij}\neq0\) means information can travel from input dimension \(j\) to output dimension \(i\). If we factor \(\mathbf R\) into a product of sparse matrices,

\[
\mathbf R = \mathbf B_{m}\,\mathbf B_{m-1}\cdots \mathbf B_{1},
\]

each \(\mathbf B_{k}\) can be seen as a “layer” in a **grid‑structured graph** with \(d\) nodes per level and \(m+1\) levels overall. An edge exists between two adjacent levels precisely when the corresponding entry in \(\mathbf B_{k}\) is non‑zero.  

For the final product \(\mathbf R\) to be dense, **every source node (level 0)** must have at least one directed path to **every sink node (level \(m\))**. At the same time we want as few *trainable* edges as possible because each non‑zero entry that isn’t forced by orthogonality becomes a learnable parameter.

Two desiderata emerge:

| Goal | What it means in the graph |
|------|----------------------------|
| **Dense connectivity** | All source–sink pairs are connected via some path |
| **Minimum free edges** | Use the smallest possible number of trainable edges while still allowing orthogonal factors |

A naïve dense factorisation would use a single full matrix (\(O(d^{2})\) edges). The block‑diagonal OFT achieves sparsity but fails dense connectivity. We need a middle ground.

---

## 3. Butterfly graphs – the FFT’s secret weapon  

The Cooley–Tukey Fast Fourier Transform (FFT) repeatedly mixes pairs of data points in a pattern known as a **butterfly**. Graphically, each stage connects each node to exactly one partner, and across \(\log_2 d\) stages every node can reach every other node.  

Key properties:

* **Only \(O(d)\) edges per stage**, because each node links to one partner.
* **\(O(d\log d)\) total edges** after \(\log d\) stages—far fewer than \(d^{2}\).
* The resulting product of stage matrices is dense (the FFT matrix itself is dense).

If we enforce *orthogonality* on every stage matrix, we obtain an **orthogonal butterfly factorisation**: a product of sparse orthogonal matrices whose overall effect is a dense orthogonal transformation.

### 3.1 Formalising a butterfly factor  

For a power‑of‑two size \(k=2^{p}\), define a butterfly factor

\[
\mathbf B^{F}(k)=
\begin{bmatrix}
\operatorname{diag}(\mathbf d_{1}) & \operatorname{diag}(\mathbf d_{2})\\[4pt]
\operatorname{diag}(\mathbf d_{3}) & \operatorname{diag}(\mathbf d_{4})
\end{bmatrix},
\]

where each \(\mathbf d_i\in \mathbb R^{k/2}\). The factor contains only **four diagonal blocks**, each of size \(k/2\times k/2\). By choosing these diagonals via a Cayley transform (or simple 2‑D rotations), we make the entire factor orthogonal.

A full butterfly matrix for dimension \(d=2^{N}\) is built recursively:

```
B(d) = Ȃ(d,d) · [ B₁(d/2)   0
                 0       B₂(d/2) ]
```

where Ȃ(d,k) is a block‑diagonal matrix whose blocks are butterfly factors of size k. Repeating this construction yields roughly \(\log_2 d\) stages, each contributing only \(O(d)\) trainable entries.

### 3.2 From butterflies to BOFT  

The authors call the resulting finetuning scheme **Orthogonal Butterfly (BOFT)**. The forward pass becomes

\[
\boxed{
    \mathbf z = (\underbrace{\prod_{i=1}^{m}\tilde{\mathbf B}^{b}_{(d,i)}}_{\displaystyle \mathbf R(m,b)}\, \mathbf W^{0})^{\!\top}
    \mathbf x},
}
\]

where each \(\tilde{\mathbf B}^{b}_{(d,i)}\) is an orthogonal butterfly component (the superscript \(b\) denotes optional block size > 2).  

- When \(m=1,\; b=d\): we recover the original OFT with an unrestricted dense orthogonal matrix.  
- When \(m=1,\; b<d\): BOFT collapses to block‑diagonal OFT.  
- When \(m=\log_2(d/b),\, b=2\): we obtain a *dense* orthogonal matrix using only \(O(d\,log d)\) parameters.

Thus BOFT interpolates smoothly between the two extremes, offering an adjustable trade‑off between expressivity and parameter budget.

---

## 4. Parameter savings in concrete terms  

| Method | Parameters for one layer (size \(d\times n\)) |
|--------|----------------------------------------------|
| Full OFT (dense \(\mathbf R\)) | \(\Theta(d^{2})\) |
| Block‑diagonal OFT (block size \(b\)) | \(\Theta(bd)\) |
| BOFT (\(m,\;b)\) | \(\displaystyle \frac{b-1}{2}\, d\, m = O(d\,log d)\) when using classic butterfly (\(b=2,\; m=\log_2 d)\). |

For a typical transformer layer with \(d=1024\), full OFT would need over one million trainable values per layer, while BOFT needs only ~\(10\,000$–$20\,000$, i.e. two orders of magnitude less.

---

## 5. Why does this work? Intuition beyond counting  

1. **Dense connectivity with few edges** – The butterfly graph guarantees that any input dimension can influence any output after enough stages, satisfying our “dense connectivity” desideratum without needing all possible edges.

2. **Orthogonal constraints prune parameters automatically** – An orthogonal sparse factor must be *full rank*, which forces exactly one non‑zero per row/column pair in each stage. Those non‑zeros are *not* independent; they lie on circles defined by Cayley transforms, further regularising learning.

3. **Implicit inductive bias** – Butterfly structures can represent classic fast linear transforms (FFT, Hadamard, DCT). Consequently, BOFT inherits biases that favour globally mixing information—a property that has empirically improved generalisation on vision and language tasks.

4. **Spectral stability** – Multiplying by an orthogonal matrix leaves singular values untouched, preserving the spectral norm of pretrained weights—a known stabiliser for deep training.

---

## 6. Practical tricks introduced in BOFT  

- **Identity initialization**: All butterfly components start as identity matrices (Cayley’s skew‑symmetric part set to zero), guaranteeing zero change at the start of finetuning.
- **Multiplicative Dropout**: Instead of zeroing activations (as in usual Dropout), BOFT randomly replaces selected butterfly components—or even individual diagonal blocks within them—with identity matrices during training. This stochastic regularisation mitigates overfitting while respecting multiplicative updates.
- **Block‑butterfly extensions**: By allowing each scalar entry in a factor to become a small \(b\times b\) matrix, one can trade additional expressivity for slightly more parameters when needed.

---

## 7. Empirical takeaways (brief)

Across large vision transformers, language models, and diffusion models, BOFT consistently outperformed LoRA and block‑diagonal OFT under comparable parameter budgets:

- **Higher accuracy / lower perplexity** on downstream classification and generation tasks.
- **Faster convergence** thanks to preserved spectral norms.
- **No inference latency penalty**: after finetuning, the learned orthogonal product can be folded into the original weight matrix, leaving the forward pass unchanged.

These results suggest that orthogonal finetuning—once thought too costly—can be made practical with butterfly factorisation.

---

## 8. Closing thoughts  

The journey from block‑diagonal matrices to butterfly factorizations demonstrates how rethinking an algorithmic bottleneck through a different lens—in this case, *information transmission on graphs*—can unlock massive efficiency gains. By marrying concepts from signal processing (FFT butterflies), graph theory (dense connectivity with few edges), and geometry (orthogonal manifolds), BOFT offers a sleek, theoretically grounded tool for parameter‑efficient finetuning of today’s gigantic foundation models.

If you’re working on adapting large models but hate blowing up your GPU memory, give Orthogonal Butterfly a try—you’ll likely get better generalisation for far fewer trainable weights, all without any extra inference cost. Happy finetuning!

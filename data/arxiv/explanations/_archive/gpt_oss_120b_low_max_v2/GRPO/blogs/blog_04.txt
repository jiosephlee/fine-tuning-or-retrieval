# Teaching LLMs to Reason Step‑by‑Step: Chain‑of‑Thought, Program‑of‑Thought, and Tool‑Integrated Prompts

Large language models (LLMs) have gotten surprisingly good at mathematics, but the secret sauce isn’t just more parameters—​it’s **how we teach them to think**.  
The DeepSeekMath team built a 7 B model that can solve competition‑level problems on the MATH benchmark without any external toolkits, and they did it by teaching the model three different “reasoning styles” during instruction tuning:

1. **Chain‑of‑Thought (CoT)** – pure natural‑language step‑by‑step reasoning.  
2. **Program‑of‑Thought (PoT)** – generate a short Python program that performs the calculations.  
3. **Tool‑Integrated (ToRA)** – combine natural‐language reasoning with calls to a Python interpreter (the “tool”) inside the prompt.

Below we unpack each format, show concrete prompt examples, and summarize when each style shines on the benchmarks used in the DeepSeekMath paper.

---

## 1. Chain‑of‑Thought (CoT)

### What it is
CoT trains the model to **explain its reasoning in words** before giving the final answer. The model learns a template like:

```
Q: <question>
A: Let's think step by step.
1. <first deduction>
2. <second deduction>
...
Answer: <final number>
```

The key is that the model must *produce* an intermediate narrative, which forces it to keep track of variables, apply algebraic rules, and avoid shortcuts that would otherwise lead to hallucinations.

### Prompt example (English)

```
Q: A rectangular garden is 8 m long and 5 m wide. What is its area in square meters?
A: Let's think step by step.
1. The area of a rectangle equals length × width.
2. Multiply 8 by 5 → 8 × 5 = 40.
Answer: 40
```

### Prompt example (Chinese)

```
问题：一个直角三角形的两条直角边分别为3 cm和4 cm，求它的面积（单位：平方厘米）？
答案：让我们一步一步思考。
1. 直角三角形面积公式是（直角边1 × 直角边2）/2。
2. 将3 与 4 相乘得到12，再除以2得到6。
答案：6
```

### When CoT wins
- **Pure reasoning tasks** where no heavy arithmetic or symbolic manipulation is required (e.g., GSM8K, most SAT items).  
- **Benchmarks that disallow tool use** – the model must produce a self‑contained solution, so CoT is the only viable format.  
- **Self‑consistency sampling**: generating many CoT answers and voting can push performance from ~51 % to ~61 % on MATH (as reported in the paper).

---

## 2. Program‑of‑Thought (PoT)

### What it is
PoT asks the model to **write a short Python script** that solves the problem, then be executed in an external interpreter. The output of the script becomes the answer.

Typical PoT prompt structure:

```
Q: <question>
A: We'll solve this with Python.
```python
# Python code here
``` 
Answer: <result from executing code>
```

The advantage is that Python’s numeric libraries (`math`, `sympy`) handle exact arithmetic, fractions, series expansions, etc., without demanding perfect token‑by‑token arithmetic from the LLM.

### Prompt example (English)

```
Q: Compute the sum of the first 20 positive even integers.
A: We'll solve this with Python.
```python
total = sum(i for i in range(2, 41, 2))
print(total)
```
Answer: 420
```

### Prompt example (Chinese)

```
问题：求解方程 x^2 - 5x + 6 = 0 的两个根。
答案：我们用 Python 来求解。
```python
import sympy as sp
x = sp.symbols('x')
sol = sp.solve(sp.Eq(x**2 - 5*x + 6, 0), x)
print(sol)
```
答案： [2, 3]
```

### When PoT wins
- **Heavy calculation or symbolic manipulation** (e.g., problems requiring exact fraction arithmetic, combinatorial formulas).  
- **Benchmarks that explicitly allow tool use**, such as GSM8K + Python or MATH when evaluated with a program runner.  
- In DeepSeekMath’s experiments PoT *outperformed* prior open‑source baselines on both GSM8K and MATH when Python was permitted.

---

## 3. Tool‑Integrated Reasoning (ToRA)

### What it is
ToRA blends natural language CoT with strategic tool calls. Instead of dumping an entire program at once, the model interleaves explanations and incremental calls:

1️⃣ Explain a sub‑step →  
2️⃣ Issue a tool call (`<tool> python ... </tool>`) →  
3️⃣ Incorporate the tool’s output into further reasoning → …  

The format mirrors how a human would reason: “I need to compute this factorial; let me ask my calculator.” DeepSeekMath’s instruction set includes both *program-of-thought* and *tool-aware* variants; ToRA is essentially a structured version of PoT with richer textual scaffolding.

### Prompt example (English)

```
Q: How many ways can you arrange the letters of "BANANA"?
A: Let's think step by step.
1. The word has 6 letters with repetitions: A×3, N×2, B×1.
2. The number of distinct permutations is 6! / (3!·2!·1!).
   <tool> python
   import math
   ans = math.factorial(6) // (math.factorial(3) * math.factorial(2))
   print(ans)
   </tool>
3. The result from the tool is 60.
Answer: 60
```

### Prompt example (Chinese)

```
问题：计算以下积分 ∫₀¹ x³ dx 的值。
答案：我们一步一步来。
1. 积分 ∫₀¹ x³ dx 的原函数是 x⁴/4。
2. 在上下限代入得到 (1⁴/4) - (0⁴/4) = 0.25。
   <tool> python
   ans = 1**4/4 - 0**4/4
   print(ans)
   </tool>
3. 工具返回的结果是 0.25。
答案：0.25
```

### When ToRA wins
- **Mixed tasks** where part of the solution is straightforward reasoning while another part requires precise computation—e.g., geometry problems needing an area formula plus a numeric evaluation.  
- **Benchmarks that test both reasoning and coding ability**, such as combined GSM8K/PoT suites or any evaluation where a “program-of-thought” decoder is allowed but pure CoT would be too cumbersome.  
- In DeepSeekMath’s results ToRA‑style prompts pushed MATH accuracy close to **60 %**, surpassing pure CoT at similar token budgets.

## Comparative Performance on Benchmarks

| Benchmark | Allowed style(s) | Best DeepSeekMath score | Which style topped it? |
|-----------|------------------|--------------------------|------------------------|
| **GSM8K** (no tool) | CoT | **88.2 %** | CoT + self‑consistency |
| GSM8K + Python | PoT / ToRA | **88.8 %** | PoT (slightly ahead of ToRA) |
| **MATH** (competition level) | No tool | **51.7 %** | CoT after GRPO RL |
| MATH + Python | PoT / ToRA | ~60 % (self‑consistent) | ToRA with GRPO RL |
| Chinese CMATH | CoT & ToRA | Comparable to English scores | CoT works well thanks to multilingual corpus |

Key takeaways:

- **CoT alone already beats every open‑source 7 B model** on MATH and reaches near GPT‑4 levels on GSM8K after reinforcement learning.
- Adding a *programming layer* (PoT or ToRA) gives a consistent boost of ~5–10 % on datasets where arithmetic precision matters.
- The **GRPO reinforcement learning stage** amplifies all three styles but shines most on CoT because it can refine tokenwise probabilities without adding new data; PoT benefits less because its performance ceiling is dominated by execution correctness rather than token generation quality.

---

## Practical Tips for Practitioners

1️⃣ **Start with high‑quality CoT data** – annotate a few thousand math problems with stepwise explanations; fine‐tune your base model on them before moving to code generation.

2️⃣ **Mix in PoT examples early** – even a modest corpus of Python solutions teaches the model proper syntax and library usage; this improves later tool integration.

3️⃣ **Add ToRA examples sparingly** – too many “<tool>” tags can confuse a model not yet comfortable with switching contexts; balance them with pure CoT samples.

4️⃣ **Use self‑consistency sampling for CoT**, especially on hard benchmarks like MATH; generate dozens of answers and let majority voting decide.

5️⃣ **Apply GRPO RL only on a subset of instruction data** – DeepSeekMath showed strong gains using just GSM8K/MATH questions; you don’t need massive RL datasets.

6️⃣ **Validate against benchmark contamination** – filter any training text that contains exact n‑grams from test sets; DeepSeekMath removed any 10‑gram matches before pretraining.

---

## Closing Thoughts

DeepSeekMath proves that *how* we ask LLMs to reason matters far more than simply scaling up parameters. By giving models three complementary “thinking tools”—plain language chain‐of‐thought, explicit program generation, and seamless tool calls—we enable them to solve high‐school and undergraduate math problems at levels previously reserved for closed models like GPT‑4.

If you’re building an open‐source math assistant today:

- Adopt CoT for baseline reasoning,
- Layer PoC/POT for arithmetic that’s hard to do in head,
- Sprinkle ToRA when you need both explanation and precise computation,

and you’ll likely see jumps comparable to those reported in the DeepSeekMath paper—all without billions of parameters or expensive proprietary data sources. Happy prompting!

\title{A Textbook about the Paper: "DeepSeekMath: Pushing the Limits of Mathematical Reasoning in Open Language Models"}

Chapter 3: Pre‑Training DeepSeekMath‑Base 7B
=================================

Large language models (LLMs) acquire their reasoning capabilities largely from the data on which they are pre‑trained and the objectives that guide that training. In the DeepSeekMath project the base model, **DeepSeekMath‑Base 7B**, is built by continuing the training of a code‑oriented checkpoint on a massive, high‑quality mathematical corpus collected from the public web. This chapter explains the rationale for starting from a code‑focused checkpoint, describes the composition of the training tokens, details the hyper‑parameters and infrastructure used for the 500 B‑token pre‑training run, and finally presents the evaluation methodology and empirical results on a broad set of mathematical and general‑language benchmarks.

---

Why start from a code‑oriented checkpoint (DeepSeek‑Coder‑Base)
--------------------------------------------------------------

The choice of initialization critically shapes how quickly a model can learn new domains. DeepSeekMath‑Base is initialized from **DeepSeek‑Coder‑Base‑v1.5 7B**, a 7 B parameter model that was originally trained on a large mixture of source code and natural language. Empirical observations in the paper show that this code‑first foundation is advantageous for several reasons.

First, code data exposes the model to structured, deterministic reasoning patterns that resemble mathematical derivations: variables are declared, expressions are composed, and control flow enforces stepwise execution. When a model learns to generate syntactically correct programs it also learns to keep track of intermediate symbols and dependencies, habits that translate naturally to chain‑of‑thought style reasoning in mathematics.

Second, downstream experiments demonstrated that models whose pre‑training included a substantial code phase outperform those that began from a generic language model when later fine‑tuned on math data. In particular, training a 1.3 B model on 400 B code tokens before 150 B math tokens yielded higher accuracy on both program‑aided GSM8K tasks and traditional step‑by‑step reasoning than a model trained only on general text before math. The code phase therefore serves as an efficient “reasoning scaffold” that accelerates acquisition of mathematical capabilities.

Finally, because DeepSeekMath later incorporates tool‐integrated reasoning (e.g., Python execution), starting from a model already proficient in generating runnable code reduces catastrophic forgetting during continued training on math tokens. This synergy between code competence and mathematical reasoning underpins the decision to use DeepSeek‑Coder‑Base as the seed checkpoint.

---

Token mix: math, code, natural language, multilingual balance
--------------------------------------------------------------

A central hypothesis of DeepSeekMath is that **high‑quality mathematical content**, rather than sheer model size, drives performance on reasoning benchmarks. To test this hypothesis the authors assembled a **120 B token math corpus**—the *DeepSeekMath Corpus*—extracted from Common Crawl by means of an iterative fastText classifier (see Section 3 of the paper). This corpus is multilingual, dominated by English and Chinese, and is deliberately mixed with other data sources during continual pre‑training.

The final token distribution for DeepSeekMath‑Base 7B is:

| Data source                | Proportion |
|----------------------------|------------|
| DeepSeekMath Corpus (math) | 56 %       |
| AlgebraicStack (math code) | 4 %        |
| arXiv papers               | 10 %       |
| GitHub code                | 20 %       |
| General natural language   | 10 %       |

*Mathematical content* thus comprises more than half of all tokens, guaranteeing sustained exposure to mathematical statements, proofs, exercises, and informal discussions. *Code* tokens (both specialized math code from AlgebraicStack and generic programming from GitHub) reinforce algorithmic thinking and provide concrete execution semantics useful for program‑of‑thought prompting. The *arXiv* slice supplies formal scientific writing but, as reported in Section 5.2 of the paper, does not yield observable gains on benchmark performance; its inclusion is nonetheless useful for maintaining broad scientific fluency. Finally, **multilingual data**—particularly Chinese webpages—are retained throughout the pipeline, which explains why DeepSeekMath excels on Chinese mathematics benchmarks (MGSM‑zh, CMATH) where prior English‑centric corpora fall short.

This balanced mixture ensures that the model does not overfit to any single modality while still receiving sufficient depth in each domain to develop robust reasoning pipelines.

---

Training hyperparameters and infrastructure (HAI‑LLM)
----------------------------------------------------

Continuing training from DeepSeek‑Coder‐Base required a carefully tuned schedule to accommodate 500 B tokens total (≈ 120 B math + other data). All experiments were performed with the **HAI‑LLM** framework, which offers lightweight distributed training suitable for large token counts.

Key hyperparameters:

| Parameter                     | Value                                 |
|-------------------------------|---------------------------------------|
| Optimizer                     | AdamW                                 |
| $\beta_1$                     | 0.9                                   |
| $\beta_2$                     | 0.95                                  |
| Weight decay                  | 0.1                                   |
| Peak learning rate            | $4.2\times10^{-4}$                    |
| Warmup steps                  | 2 000                                 |
| Learning rate schedule        | Multi‑step:   100 % → 31.6 % at 80 % of total steps → 10 % at 90 % |
| Batch size (tokens per step)  | 10 M                                   |
| Context length                | 4 K tokens                             |
| Total processed tokens        | 500 B                                   |

The learning rate schedule follows the same pattern used for prior DeepSeek LLMs: after an initial warmup phase the rate is gradually decayed to avoid instability during long runs. The batch size of ten million tokens per step balances memory usage against throughput; with a context window of four thousand tokens each forward/backward pass processes roughly $2\,500$ sequences.

Training was carried out on clusters equipped with GPUs offering at least $80$ GB memory per device; HAI‑LLM’s memory‐efficient kernels enabled these large batches without resorting to gradient checkpointing or excessive offloading. No explicit gradient accumulation was needed because each step already consumed multiple million tokens.

Critically, **no separate critic network** was introduced during this stage: only the language modeling objective (next-token prediction) was optimized. This pure supervised pre‑training sets up a strong foundation before later reinforcement learning phases (see Chapter 7).

---

Evaluation methodology: few­-shot chain­-of­-thought prompting
--------------------------------------------------------------

To assess whether continued pre‑training truly improves mathematical reasoning, all downstream evaluations employ **few­-shot chain­-of­-thought (CoT)** prompting—a paradigm wherein a small number of exemplars containing step­-by­-step solutions are supplied together with each test question. The protocol mirrors that used in prior CoT studies:

1. **Prompt construction** – For each benchmark task a fixed set of $k$ exemplars ($k\in\{2,4\}$ depending on token budget) are concatenated; each exemplar contains the problem statement followed by an explicit solution trace ending in the final answer.
2. **Generation** – The model generates continuation up to a maximum length (typically $256$ tokens). Decoding uses nucleus sampling ($p=0.9$) with temperature $0.7$ unless otherwise specified.
3. **Answer extraction** – The final numeric answer or multiple-choice label is parsed from the generated text using regex heuristics identical across all models.
4. **Scoring** – Accuracy is computed by exact match against ground truth; for program‐augmented tasks (see next section) execution success also counts toward correctness.

All reported numbers stem from this identical pipeline; thus any performance differences can be attributed to model capability rather than prompt engineering or decoding tricks.

---

Results on quantitative reasoning, tool‑augmented solving, formal proof, and general NLP benchmarks
-------------------------------------------------------------------------------------------------

The comprehensive evaluation suite spans eight English and Chinese benchmarks:

*Quantitative reasoning without tools.*  
DeepSeekMath‑Base 7B attains **64.2 %** on GSM8K and **36.2 %** on competition‐level MATH using CoT prompting—surpassing open‐source baselines such as Mistral 7B and Llemma 34B by margins exceeding $10$ absolute points. Notably it also exceeds Minerva 540B despite being $77\times$ smaller in parameter count.

*Tool‐augmented solving (program‐of‐thought).*  
When prompted to write Python programs leveraging `math` or `sympy`, DeepSeekMath‐Base surpasses prior state‐of‐the‐art Llemma 34B on both GSM8K and MATH under program‐of‐thought evaluation; executions yielding correct answers rise above $70$ % on GSM8K (exact figures are provided in Table 4 of the paper).

*Formal mathematics.*  
On the informal–to–formal proving task miniF2F (Isabelle), DeepSeekMath‑Base generates effective proof sketches; when combined with Sledgehammer’s automated filling it reaches higher success rates than comparable open models, demonstrating transfer of learned symbolic reasoning to theorem proving contexts.

*General language understanding and coding.*  
Beyond mathematics, DeepSeekMath‐Base shows marked gains on MMLU–STEM (+~5 points over its coder predecessor) and BIG Bench Hard (+~4 points), confirming that extensive math pre‑training also bolsters broader reasoning ability. On coding benchmarks HumanEval and MBPP it retains nearly identical performance to DeepSeek‑Coder Basev1.5, indicating that adding massive math data does not degrade existing coding proficiency.

Collectively these results validate two central claims of the paper:

1. **Data quality outweighs sheer scale** – A relatively modest 7 B model trained on high‐quality web mathematics reaches performance comparable to closed‐source hundreds‐of‐billions models.
2. **Code pre‐training synergizes with math training** – Starting from a code-oriented checkpoint accelerates both pure symbolic reasoning and program–aided problem solving.

The empirical evidence presented here therefore demonstrates how careful corpus construction, balanced token mixing, and disciplined training schedules converge to produce an open-source LLM whose mathematical abilities approach those of leading proprietary systems such as GPT‑4 and Gemini Ultra.

\title{A Textbook about the Paper: "DeepSeekMath: Pushing the Limits of Mathematical Reasoning in Open Language Models"}

Chapter 4: Supervised Instruction Tuning for Mathematics  

# Data Sources  

The instruction‑tuning stage of DeepSeekMath begins by gathering a diverse set of mathematical problems that span both English and Chinese curricula.  The primary English resources are the well‑known GSM8K benchmark \citep{gsm8k} and the competition‑level MATH dataset \citep{MATH}.  These two corpora provide a rich mixture of grade‑school and college‑level quantitative reasoning tasks, each accompanied by detailed human‑written solutions.  In addition to these, a subset of MathInstruct \citep{MathInstruct} is incorporated; MathInstruct contains problems that have already been annotated with chain‑of‑thought (CoT) explanations, allowing the model to learn from high‑quality reasoning traces.  The Lila‑OOD training split \citep{lila} is also used, because it offers a broader variety of problem types solved either with CoT or program‑of‑thought (PoT) strategies.

For the Chinese side of the corpus, the authors collect a large K‑12 mathematics dataset that covers 76 sub‑topics such as linear equations, quadratic formulae, probability, and geometry.  Each problem in this collection is paired with two solution styles: a step‑by‑step textual explanation (CoT) and a solution that explicitly invokes computational tools (tool‑integrated reasoning).  By merging English and Chinese sources the final instruction‑tuning set contains **776 K** examples, ensuring that the model is exposed to multilingual mathematical language and to a spectrum of difficulty levels.

# Formats: Chain‑of‑Thought, Program‑of‑Thought, Tool‑Integrated Reasoning  

Instruction tuning data are not merely question–answer pairs; they are deliberately formatted to teach the model how to reason.  Three complementary formats are used:

1. **Chain‑of‑Thought (CoT)** – The answer is preceded by a natural language derivation that decomposes the problem into a sequence of logical steps.  This format mirrors the few‑shot prompting technique that proved effective in earlier works \citep{cot}, and it encourages the model to generate self‑contained explanations without external assistance.

2. **Program‑of‑Thought (PoT)** – Problems are solved by writing short Python programs that invoke libraries such as `math` or `sympy`.  The model’s output therefore consists of executable code followed by the program’s result.  This approach follows the “program‑of‑thought” paradigm introduced in \citep{pot,pal} and enables the model to offload heavy arithmetic or symbolic manipulation to an interpreter.

3. **Tool‑Integrated Reasoning** – A hybrid format where the model first produces a CoT explanation and then calls a tool (e.g., a Python REPL) for specific subcomputations.  The format aligns with recent “tool‐augmented” methods \citep{tora} and teaches the model when and how to interleave language reasoning with tool use.

By exposing the model to all three styles, DeepSeekMath learns not only *what* the correct answer is but also *how* to arrive at it using different modalities.

# Data Curation Pipeline and Quality Control  

The raw collection described above undergoes an iterative curation pipeline to ensure both relevance and cleanliness:

* **Deduplication** – URLs that appear multiple times across Common Crawl are collapsed using URL‑based deduplication followed by near‑duplicate detection on the extracted text.  This prevents over‑representation of any single source.

* **Benchmark Decontamination** – To avoid contaminating evaluation benchmarks, any text segment containing an exact 10‑gram match to any evaluation benchmark string (GSM8K, MATH, CMATH, AGIEval, etc.) is removed.  For shorter benchmark fragments (3–9 grams) an exact match rule is also applied.  This rigorous decontamination mirrors the procedure used for prior DeepSeek models \citep{deepseek-coder}.

* **Human Annotation & Validation** – After initial automatic filtering, domain experts review a sample of the collected pages.  Pages judged low quality (e.g., consisting mainly of forum chatter or unrelated markup) are discarded, while high‑quality examples are retained for fine–tuning.  The refined set feeds back into the fastText classifier used during data mining, improving recall in subsequent iterations.

* **Balancing Across Languages & Domains** – The pipeline tracks token counts per language; if Chinese material lags behind English, additional Chinese domains are manually seeded to keep the multilingual balance roughly even.  Likewise, problem types (algebra, calculus, probability) are monitored so that no single genre dominates.

These steps collectively yield a high‐fidelity instruction dataset where each entry is a clean problem description followed by one of the three reasoning formats.

# Training Regime: Batch Size, Learning Rate Schedule, Context Handling  

Fine–tuning follows the same lightweight training infrastructure as earlier DeepSeek experiments \citep{haillm}.  The process can be summarized as follows:

* **Model Initialization** – DeepSeekMath-Base 7B serves as the starting checkpoint; it has already been pre‑trained on 500 B tokens including 56 % math tokens from the DeepSeekMath corpus.

* **Batch Construction** – Training examples are concatenated randomly until they reach a maximum context length of **4 K tokens**.  This technique ensures efficient utilization of GPU memory while preserving natural text boundaries; no example is split across batches.

* **Training Steps & Batch Size** – The instruction fine‐tuning runs for **500 update steps** with a batch size of **256 sequences** per step.  Each sequence corresponds to one concatenated chunk described above.

* **Learning Rate** – A constant learning rate of **5 × 10⁻⁵** is employed throughout all steps.  The authors deliberately avoid aggressive warmup or decay because the instruction data are already highly curated; stability rather than aggressive exploration is preferred.

* **Optimizer Settings** – AdamW with default β₁=0.9, β₂=0.95 and weight decay=0.01 is used (the exact hyperparameters follow those from DeepSeek training but are not re‐specified in this section).

* **Tokenization & Embedding Alignment** – Since the base model uses the same tokenizer across code and natural language data, no special token handling is required for Python code blocks or mathematical symbols.

The brief training schedule—only half a thousand steps—highlights how much performance can be extracted from high-quality instruction data when paired with a strong foundation model.

# Evaluation Against Closed and Open Models  

After fine‐tuning, DeepSeekMath-Instruct 7B is evaluated on both English and Chinese mathematical benchmarks under two regimes: (1) **no tool use**, where only CoT reasoning is allowed; (2) **tool‐integrated reasoning**, where PoT or tool calling is permitted.

### Performance Without Tool Use  
On GSM8K (elementary quantitative reasoning) DeepSeekMath-Instruct reaches an accuracy comparable to much larger open models such as InternLM2-Math 20B.  More strikingly, on the competition‐level MATH dataset it obtains **over 50 % accuracy**, surpassing every other open‐source model ranging from 7 B to 70 B parameters (including WizardMath‐v1.1 7B and MetaMath 70B).  Among closed models it trails only GPT‑4 and Gemini Ultra; it even outperforms several proprietary middle‐size models like Inflection‑2 and Gemini Pro despite being an order of magnitude smaller.

### Performance With Tool Use  
When permissive tool usage is allowed—i.e., models may emit Python code that gets executed—the accuracy on MATH rises toward **60 %**, again leading all open counterparts and closing the gap with closed systems that incorporate tool interpreters (e.g., GPT‑4 Code Interpreter).  On other benchmarks such as SAT and OCW Courses these gains are mirrored: DeepSeekMath-Instruct matches or exceeds larger chat models such as DeepSeek-LLM-Chat 67B while requiring far fewer parameters.

### Comparative Landscape  
The evaluation tables in the paper show a clear hierarchy:

| Model | Params | GSM8K (CoT) | MATH (CoT) | MATH (Tool) |
|------|--------|------------|-----------|------------|
| GPT‑4 | — | ~93 % | ~73 % | ~78 % |
| Gemini Ultra | — | ~90 % | ~71 % | ~77 % |
| DeepSeekMath-Instruct | 7 B | ≈85 % | ≈51 % | ≈60 % |
| WizardMath‑v1.1 | 7 B | ≈78 % | ≈42 % | ≈48 % |
| Llama2 70B + ToRA | 70 B | ≈84 % | ≈49 % | — |

The table illustrates two important observations drawn directly from the paper’s results:

1. **Scale Efficiency** – A modestly sized open model can reach performance levels previously seen only in multi‑hundred‑billion parameter proprietary systems when supplied with high-quality math instruction data.
2. **Tool Augmentation Amplifies Gains** – Allowing programmatic execution consistently produces a several‐point lift across all models; DeepSeekMath-Instruct benefits most because its PoT examples were explicitly included during fine‐tuning.

Overall, supervised instruction tuning—grounded in multilingual problems and three reasoning formats—transforms DeepSeekMath-Base into an instruction model that rivals far larger competitors on core mathematical reasoning benchmarks while preserving its coding abilities inherited from its coder pretraining lineage.

# Markov Decision Processes and Policy Gradients  

Reinforcement learning (RL) is formalized as a **Markov Decision Process (MDP)**, a tuple \((\mathcal{X},\mathcal{A},P,R,\gamma)\).  
- \(\mathcal{X}\) denotes the set of possible *states* (in the language‑model setting a state corresponds to a query \(x\) together with the tokens generated so far).  
- \(\mathcal{A}\) is the set of *actions*; for an autoregressive language model each action is the choice of the next token \(y_t\).  
- \(P(s'|s,a)\) defines the transition dynamics, which in text generation are deterministic: after emitting token \(y_t\) we move to the next partial sequence.  
- The *reward* function \(R(s,a)\) assigns a scalar value to a completed response; in the paper we denote it by a verifier \(r(x,y)\in[0,1]\).  
- \(\gamma\in[0,1]\) is the discount factor; for finite‑horizon generation it is typically set to 1.

A **policy** \(\pi_\theta(a|s)\) parameterized by \(\theta\) maps each state to a distribution over actions. In language modelling \(\pi_\theta\) is exactly the autoregressive model, and the probability of an entire response \(y=(y_1,\dots ,y_{|y|})\) given a query \(x\) is the product of token‑level conditionals  

\[
\pi_\theta (y|x)=\prod_{t=1}^{|y|}\pi_\theta (y_t\,|\,x,y_{<t}),
\]

where we write \(y_{<t}=(y_1,\dots ,y_{t-1})\).

The **policy‑gradient theorem** provides an unbiased estimator of the gradient of the expected return  

\[
J(\theta)=\mathbb{E}_{x\sim \mathcal{D},\,y\sim \pi_\theta(\cdot|x)}[\,r(x,y)\,],
\]

as  

\[
\nabla_{\theta}J(\theta)=
\mathbb{E}_{x,y}\bigl[
r(x,y)\,\nabla_{\theta}\log \pi_\theta(y|x)
\bigr].
\]

In practice we replace the raw reward with an **advantage** estimator \(\widehat A(x,y)\), which measures how much better a particular response is relative to a baseline. Substituting the advantage reduces variance while preserving unbiasedness:

\[
\nabla_{\theta}J(\theta)=
\mathbb{E}_{x,y}\bigl[
\widehat A(x,y)\,\nabla_{\theta}\log \pi_\theta(y|x)
\bigr].
\]

When dealing with very large language models (LLMs), directly sampling from the current policy at each optimization step becomes prohibitively expensive. Instead we generate a batch of responses using an *old* policy \(\pi_{\theta_{\text{old}}}\) and perform **off‑policy** updates. This necessitates correcting for the distribution mismatch between \(\pi_{\theta_{\text{old}}}\) and \(\pi_\theta\), which leads us to importance sampling and clipping mechanisms.

# Proximal Policy Optimization (PPO): Objective and Clipping  

**Proximal Policy Optimization (PPO)** is a practical algorithm that stabilizes off‑policy updates by constraining how far the new policy may deviate from the old one. The core component is the *importance ratio* for each token  

\[
w_t(\theta)=
\frac{\pi_{\theta}(y_t\,|\,x,y_{<t})}
     {\pi_{\theta_{\text{old}}}(y_t\,|\,x,y_{<t})}.
\]

Given an advantage estimate \(\widehat A_t\), PPO optimizes

\[
\mathcal J_{\text{PPO}}(\theta)
=
\E_{x,y}
\Bigg[
    \frac{1}{|y|}
    \sum_{t=1}^{|y|}
    \min
    \Bigl(
        w_t(\theta)\,\widehat A_t,
        \,
        \operatorname{clip}\!\bigl(w_t(\theta), 1-\varepsilon, 1+\varepsilon\bigr)\,\widehat A_t
    \Bigr)
\Bigg],
\tag{1}
\]

where \(\varepsilon>0\) defines a symmetric clipping interval around 1. The operator  

\[
\operatorname{clip}(z, a, b)=
   \begin{cases}
      a & z<a\\[2pt]
      z & a\le z \le b\\[2pt]
      b & z>b
   \end{cases}
\]

ensures that if an importance ratio strays too far from 1—i.e., if the sample is overly “off‑policy”—its contribution is limited to the clipped value. The min operation in (1) preserves the sign of the advantage while applying this bound.

By construction, PPO’s objective reduces variance relative to naïve importance sampling and prevents overly aggressive policy updates that could destabilize training. However, PPO requires **value functions** to compute per‑token advantages. In large‐scale LLM RL this becomes a bottleneck: training a separate value head that matches the size of billions‑parameter models incurs substantial memory and compute overhead, and obtaining reliable value predictions for long generated texts remains difficult.

# Importance Sampling: Definition and Variance Considerations  

Importance sampling provides a principled way to estimate expectations under one distribution using samples drawn from another. If we wish to compute  

\[
\E_{z\sim \pi_{\text{tar}}}[f(z)],
\]

but only have access to samples from a *behavior* distribution \(\pi_{\text{beh}}\), we rewrite

\[
\E_{z\sim \pi_{\text{tar}}}[f(z)]
=
\E_{z\sim \pi_{\text{beh}}}\!\Bigl[
     \frac{\pi_{\text{tar}}(z)}{\pi_{\text{beh}}(z)}\,f(z)
   \Bigr].
\tag{2}
\]

The multiplicative factor  

\[
\rho(z)=\frac{\pi_{\text{tar}}(z)}{\pi_{\text{beh}}(z)}
\]

is called the **importance weight**. Equation (2) is unbiased provided that every outcome with non‑zero probability under \(\pi_{\text{tar}}\) also has non‑zero probability under \(\pi_{\text{beh}}\). 

A crucial practical point is **variance**: if only few samples are drawn from \(\pi_{\text{beh}}\), large fluctuations in (\ref{2}) can arise because some importance weights may be extremely large or tiny. The variance diminishes as we increase the number of samples \(N\); indeed, importance sampling assumes averaging over many independent draws to faithfully correct distributional mismatch.

In language‑model RL, one could treat each *token* as an individual random variable and apply (\ref{2}) token‑wise, as done in GRPO. However, token‑level importance weights involve ratios of single‑token probabilities sampled from distinct categorical distributions (the next‑token distributions at each timestep). Those ratios are based on one observation per distribution, violating the averaging assumption required for low variance. Consequently, they introduce high‑variance noise that compounds with sequence length.

# Token‑level vs. Sequence‑level Estimators  

The paper identifies two distinct granularities for importance weighting:

1. **Token‑level estimator** – used by PPO and GRPO: each token receives its own ratio  

   \[
   w_{i,t}(\theta)=
   \frac{\pi_\theta(y_{i,t}\mid x,y_{i,<t})}
        {\pi_{\theta_{\text{old}}}(y_{i,t}\mid x,y_{i,<t})}.
   \]

   While mathematically valid for on‑policy updates, when applied off‑policy with single samples per next‑token distribution it fails to approximate (\ref{2}) adequately; variance grows linearly with sequence length because each term introduces independent noise.

2. **Sequence‑level estimator** – introduced in GSPO: define an importance weight for an entire response  

   \[
   s_i(\theta)=
   \Bigl(
      {\pi_\theta(y_i\,|\,x)} /
      {\pi_{\theta_{\text{old}}}(y_i\,|\,x)}
   \Bigr)^{1/|y_i|}
   = 
   \exp%
    {\Bigl(
       {1}/{|y_i|}
       \sum_{t=1}^{|y_i|}
       \log
       {\frac{\pi_\theta(y_{i,t}\mid x,y_{i,<t})}
                 {\pi_{\theta_{\text{old}}}(y_{i,t}\mid x,y_{i,<t})}}
     \Bigr)} .
   \tag{3}
   \]

   Equation (3) aggregates all token probabilities into a single scalar before taking any expectation, thereby satisfying the requirement that importance sampling operate over many samples—the *samples* here are full sequences generated from $\pi_{\theta_{\text{old}}}$. Moreover, normalizing by sequence length (the exponent $1/|y_i|$) controls scale across responses of different lengths and reduces variance further.

Because rewards are defined at the sequence level—\(r(x,y_i)\)—the sequence estimator aligns directly with the objective: each response receives one advantage value  

\[
\widehat A_i=
  {\bigl(r(x,y_i)- 
      {\rm mean}_j r(x,y_j)\bigr)}
  /{\rm std}_j r(x,y_j)},
\tag{4}
\]

where all members of a *group* share this same advantage (a group consists of $G$ responses sampled for identical query $x$). The GSPO objective then mirrors PPO’s clipped formulation but replaces tokenwise ratios with $s_i(\theta)$:

\[
\mathcal J_{\text{GSPO}}(\theta)=
\E_{x,\{y_i}\!}
  [\, 
     {1}/{G}
     \sum_{i=1}^{G}
     {\min}\bigl(
        s_i(\theta)\widehat A_i,
        {\rm clip}(s_i(\theta),1-\varepsilon,1+\varepsilon)\widehat A_i
     )
  ] .
%
% No tag number needed
\]

The clipping now operates on whole responses rather than individual tokens; if an entire trajectory is too unlikely under $\pi_\theta$ relative to $\pi_{\rm old}$ it will be down‑weighted as a unit.

# Why Value Functions Are Costly for Massive LLMs  

Traditional PPO relies on **value functions** to estimate $\widehat A_t$, typically via another neural network trained to predict expected future returns given a state (or partial sequence). For modest RL agents this overhead is acceptable, but in modern LLM RL there are two decisive impediments:

- **Parameter Scale:** State‑of‑the‑art LLMs contain tens or hundreds of billions of parameters. Adding an equally sized value network doubles memory consumption during training—a prohibitive requirement on current hardware configurations.
  
- **Computation Duplication:** Computing both policy logits and value predictions per token multiplies forward passes, roughly doubling FLOPs per training step. When generating long responses or many rollouts per query (large groups $G$), this cost becomes dominant.
  
- **Reliability at Length:** Value estimators must remain accurate across extremely long horizons (hundreds or thousands of tokens). Errors compound over steps; inaccurate advantages introduce bias into policy gradients, undermining learning stability.
  
Because GSPO replaces tokenwise advantages with *grouped, normalized rewards* (\ref{4}), it eliminates any need for an auxiliary value head. The algorithm thus sidesteps both memory and compute burdens while preserving an unbiased gradient estimator—provided that importance sampling is performed at sequence level as argued above.

In summary, this chapter has traced RL foundations from MDP formalism through classic policy gradients to modern proximal methods. By dissecting importance sampling’s variance behavior we have clarified why token‑level corrections become fragile when scaling LLMs, paving the way for sequence‑level approaches such as Group Sequence Policy Optimization (GSPO). This theoretical grounding explains both GSPO’s empirical stability and its practical advantages—particularly in contexts where value networks and massive expert routing would otherwise make reinforcement learning prohibitively complex.

Chapter 3: **Architecture of the Byte Latent Transformer**

The Byte Latent Transformer (BLT) departs fundamentally from the token‑centric pipelines that dominate modern large language models.  Instead of operating on a fixed vocabulary of sub‑word tokens, BLT processes raw byte streams by first aggregating them into dynamically sized *patches*.  These patches serve as the primary computational units for a three‑stage architecture composed of a **local encoder**, a **global latent transformer**, and a **local decoder**.  The design of each component is tightly coupled to the goal of allocating compute where the data are most informative: inexpensive byte‑level processing builds compact latent representations, while a heavyweight transformer operates only on those latent patch embeddings that correspond to high‑entropy regions of the input.  The following sections describe each block in detail, their interactions, and the engineering choices that make the system both efficient and expressive.

---

### The Global Latent Transformer

At the heart of BLT lies an autoregressive transformer, denoted \(\mathcal{G}\), which we refer to as the **latent global transformer**.  Unlike conventional token‑level transformers that attend over every token in a sequence, \(\mathcal{G}\) attends only over the sequence of latent patch embeddings \(\{p_j\}_{j=1}^{m}\) produced by the encoder.  Operating on this reduced sequence dramatically shortens the effective length of the attention computation, because each patch may span several bytes.  The model is built from \(l_{\mathcal{G}}\) identical layers; each layer consists of a multi‑head self‑attention sub‑module followed by a feed‑forward network (FFN), both wrapped with pre‑layer normalisation.

A crucial design choice for \(\mathcal{G}\) is its **block‑causal attention mask**.  For patch index \(j\), attention is permitted to all patches \(k \leq j\) within the same document, but never to future patches \(k > j\).  Formally, let \(A_{jk}=1\) if \(k \leq j\) and \(A_{jk}=0\) otherwise; this binary mask is applied to the scaled dot‑product attention scores before softmax:
\[
\alpha_{jk}= \frac{\exp\bigl( (Q_j K_k^{\top})/\sqrt{d_k} \bigr)}{\sum_{k' : A_{jk'}=1}\exp\bigl( (Q_j K_{k'}^{\top})/\sqrt{d_k} \bigr)}\,,
\]
where \(Q_j,W_q p_j\) and \(K_k,W_k p_k\) are linear projections of the patch embeddings into query and key spaces of dimension \(d_k\).  The block‑causal mask guarantees strict autoregressivity: predictions for a given patch are conditioned only on previous patches, mirroring the causal nature required for language modelling.

Because \(\mathcal{G}\) consumes most of BLT’s floating‑point operations during both pre‑training and inference, its size directly determines overall model capacity.  In practice we match \(\mathcal{G}\)’s parameter budget to that of comparable token‑based transformers (e.g., Llama 3), while exploiting the reduced number of steps afforded by larger average patch sizes.  Consequently, when patches become longer—thanks to entropy‑guided segmentation—fewer transformer steps are taken per byte, freeing FLOPs that can be reallocated either to deeper global layers or to larger hidden dimensions.

### The Local Encoder

The **local encoder**, denoted \(\mathcal{E}\), is a lightweight transformer tasked with transforming the raw byte sequence \(\{b_i\}_{i=1}^{n}\) into a set of latent patch embeddings \(\{p_j\}_{j=1}^{m}\).  Its design balances two competing demands: (1) it must be cheap enough to run on every byte without overwhelming compute, and (2) it must produce expressive representations that capture enough context for the downstream global transformer.

#### Byte Embeddings and Hash n‑gram Augmentation

Each byte \(b_i\in \mathcal{V}=\{0,\dots,255\}\) is first mapped to an embedding vector via an lookup table
\[
x_i = E_{\text{byte}}[b_i]\in \mathbb{R}^{h_{\mathcal{E}}}.
\]
To enrich these representations with local context while keeping memory footprints modest, BLT adds *hash n‑gram embeddings*.  For every position \(i\) we form six overlapping n‑grams
\[
g_{i,n} = \bigl(b_{i-n+1},\,b_{i-n+2},\,\dots ,\,b_i\bigr), \qquad n=3,\dots ,8,
\]
discarding any n‑gram that would extend before the start of the sequence.  Each n‑gram is hashed by a fast rolling polynomial hash function,
\[
h(g_{i,n}) = \bigl(\operatorname{RollPolyHash}(g_{i,n})\bigr)\bmod |E_n^{\text{hash}}|,
\]
and then looked up in a dedicated embedding table \(E^{\text{hash}}_n\).  The final augmented byte embedding is an average of all contributions:
\[
e_i = x_i + \frac{1}{7}\sum_{n=3}^{8}E^{\text{hash}}_n\bigl(h(g_{i,n})\bigr).
\]
These hash‑based n‑gram features provide cheap access to sub‑byte patterns such as common prefixes or suffixes without requiring an explicit vocabulary for every possible n‑gram.

#### Transformer Layers with Local Block Causal Attention

The sequence \(\{e_i\}_{i=1}^{n}\) feeds into a stack of \(l_{\mathcal{E}}\ll l_{\mathcal{G}}\) transformer layers.  Within each layer, self‑attention operates under a **local block causal mask**: each byte attends only to a fixed sliding window of its preceding \(w_{\mathcal{E}}\) bytes (e.g., \(w_{\mathcal{E}}=512\)).  This restriction limits quadratic cost while still allowing enough context for reliable encoding of short‐range dependencies such as character n‑grams or common syntactic constructs.

#### Cross‑Attention Pooling into Patches

After each transformer layer we apply a cross‑attention module that aggregates byte representations belonging to the same patch into a single latent vector.  Let
\(B = \bigl(e^{(l)}_i\bigr)_{i=1}^{n}\) denote byte embeddings after layer \(l\).  
For patch \(p_j\), we define its query vector as an initial pooling over its constituent bytes; typically max or mean pooling is used:
\[
q^{(0)}_j = \operatorname{Pool}\bigl(\{e^{(0)}_i : i \in P_j\}\bigr),
\]
where \(P_j\subseteq[1,n]\) indexes bytes belonging to patch \(j\).  

Cross‑attention then refines these queries:
\[
Q^{(l)} = W_q q^{(l-1)}_j,\qquad
K^{(l)}_i = W_k B_i,\qquad
V^{(l)}_i = W_v B_i,
\]
with learnable projections \(W_q,W_k,W_v\,{:}\,\mathbb R^{h_{\mathcal{E}}}\to \mathbb R^{d_k}\).
Because each query should see only its own bytes, we mask out all keys/values not in \(P_j\).  The attention update for query \(j\) becomes
\[
q^{(l)}_j = q^{(l-1)}_j +
W_o\, \sum_{i \in P_j}
   \alpha^{(l)}_{ji} V^{(l)}_i,
    \quad 
    \alpha^{(l)}_{ji}= 
    \frac{\exp((Q^{(l)}_j K^{(l)\top}_i)/\sqrt{d_k})}{%
          \sum_{i'\in P_j}
          \exp((Q^{(l)}_j K^{(l)\top}_{i'})/\sqrt{d_k}) } .
\]
The residual connection preserves information from earlier layers; after repeating this operation across all cross‑attention blocks we obtain final patch embeddings
\(p_j = q^{(L_{\mathcal E})}_j \in \mathbb R^{h_{\mathcal G}}\),
ready for consumption by the global transformer.

The cross‑attention design mirrors the Perceiver architecture but differs in that each query is confined to its own dynamic byte set rather than attending over a fixed latent array.

### The Local Decoder

Generation proceeds in reverse: after the global transformer predicts an output patch representation \(o_j\), these must be expanded back into concrete bytes.  The **local decoder**, denoted \(\mathcal D\), fulfills this role using another lightweight transformer stack (\(l_{\mathcal D} \ll l_{\mathcal G}\)) coupled with cross‑attention that maps from patches to bytes.

#### Cross‑Attention from Patches to Bytes

During decoding step \(j\), queries are now derived from *byte* positions while keys/values come from *patch* representations.  Let
\(H = (h_i)\) be byte‐level hidden states inherited from the final encoder layer,
and let
\(O = (o_j)\) be the sequence of output patches produced by \(\mathcal G.\)
We first compute key/value projections for every patch:
\(K_j = W_k^\text{dec}(o_j),\, V_j = W_v^\text{dec}(o_j).\)
For each byte position \(i$, we construct its query:
\(Q_i = W_q^\text{dec}(h_i).\)
Again we limit attention to those patches whose span contains byte \(i,\) enforcing a mask
\(M_{ij}=1$ if $i$ belongs to patch $j$ and $0$ otherwise.
The attention output for byte $i$ becomes
\[
b_i = h_i + 
W_o^\text{dec}
   \sum_{j : M_{ij}=1}
      \alpha_{ij} V_j,\qquad 
   \alpha_{ij}= 
   \frac{\exp((Q_i K_j^\top)/{\sqrt d_k})}{%
         \sum_{j':M_{ij'}=1}
         \exp((Q_i K_{j'}^\top)/{\sqrt d_k}) } .
\]
Thus each byte aggregates information only from its owning patch, effectively “unpacking’’ the latent representation back into byte space.

#### Byte Generation Layer

After cross‑attention, each updated byte hidden state passes through several standard transformer layers (again using local block causal attention with window $w_\mathcal D$); finally an output projection maps $b_i$ onto logits over the $256$ possible byte values:
\[
z_i = W_\text{o}^{(\text{bytes})} b_i + b_\text{o}, 
    \qquad p(b_i=v|\cdot)=
    {\rm softmax}_v(z_i).
\]
During autoregressive generation we predict one byte at a time conditioned on previously generated bytes and previously emitted patches.  Whenever a new patch boundary is reached—determined incrementally by evaluating next‐byte entropy—the decoder invokes another forward pass through $\mathcal G$, thereby intermittently expending additional compute only when needed.

---

### Mechanistic Details of Cross‑Attention

Both encoder and decoder share a common cross‑attention primitive but invert its directionality.  In encoder cross‑attention:

* **Queries** correspond to current *patch* latent vectors.
* **Keys/Values** stem from *byte* hidden states belonging to that patch.
* **Masking** restricts every query’s receptive field exclusively to its own bytes; no inter‐patch communication occurs at this stage.

In decoder cross‑attention:

* **Queries** correspond to *bytes* awaiting generation.
* **Keys/Values** are derived from already computed *patch* outputs.
* **Masking** ensures each byte attends only to its owning patch; because patches have already been generated autoregressively they contain information about all preceding bytes.

Both mechanisms employ multi–head attention with pre–LayerNorm around queries, keys and values. No positional embeddings are added inside cross‐attention; instead positional information is injected earlier via rotary positional embeddings (RoPE) applied only within self‐attention layers of $\mathcal E$, $\mathcal G$ and $\mathcal D$.  RoPE injects relative position bias directly into $Q$ and $K$, preserving absolute translational invariance while allowing long contexts without explicit learned position tables.

---

### Positional Encoding Choices

Full positional encodings are unnecessary for cross‐attention because queries already know which bytes belong to their associated patch via masking.  Consequently BLT adopts a minimalist strategy:

* **Rotary Positional Embeddings (RoPE)** are employed exclusively inside self‐attention modules across all three transformers.  
* The rotary angle parameter $\theta$ is set to $5\times10^5$, matching recent best practices for long contexts; this scales linearly with token distance and enables smooth extrapolation beyond training lengths.
* No learned absolute position vectors are added anywhere else—neither in embedding tables nor in feed‐forward layers—reducing memory overhead and simplifying implementation.

This design ensures that positional information influences inter–byte interactions within local windows but does not interfere with the high‐level aggregation performed by cross‐attention.

### Parameter Scaling Across Encoder, Decoder, and Global Model

Because most FLOPs in BLT reside in $\mathcal G$, we allocate parameters proportionally:

| Component | Typical Layer Count | Hidden Size | Relative Parameter Share |
|-----------|--------------------|------------|--------------------------|
| Global latent transformer $\mathcal G$ | $l_{\mathcal G}=24$ (for an 8 B model) | $h_{\mathcal G}=4096$ | ≈ 80 % |
| Local encoder $\mathcal E$ | $l_{\mathcal E}=1$–$3$ | $h_{\mathcal E}=768$ | ≈ 5 % |
| Local decoder $\mathcal D$ | $l_{\mathcal D}=2$–$4$ | $h_{\mathcal D}=1024$ | ≈ 15 % |

The exact numbers vary with model scale; smaller configurations may use $l_{\mathcal G}=12$, $h_{\mathcal G}=2048$, etc.  Crucially, as average patch size grows (through entropy‐driven segmentation), $m$, the number of patches per context, shrinks roughly proportionally.  Since FLOPs per forward pass through $\mathcal G$ scale as $\mathrm{O}(m\, h_{\mathcal G}^2)$ plus FFN cost $\mathrm{O}(m\, h_{\mathcal G}^2)$, longer patches directly translate into fewer global steps per byte.  This creates an additional knob: by increasing average patch length we can maintain constant inference FLOP budgets while enlarging either depth or width of $\mathcal G$, yielding better overall performance without extra computation at inference time.

The local models remain thin because they must run on every byte; their parameter counts grow slowly with overall model size so as not to dominate compute or memory consumption.  Empirically this asymmetry works well: even with just one encoder layer plus hash n‑gram embeddings, BLT attains parity with tokenizers at comparable FLOP budgets; adding more encoder layers brings marginal gains but incurs disproportionate cost because those layers would need to be executed on every byte.

---

### Synthesis

In summary, BLT’s architecture orchestrates three distinct processing stages:

1. **Local Encoder** – A fast transformer enriched with hashed n‑gram features aggregates raw bytes into compact latent patches using masked cross‑attention.
2. **Global Latent Transformer** – A heavyweight autoregressive backbone consumes only those patch embeddings whose boundaries are defined by data entropy; block–causal attention guarantees strict language modelling semantics.
3. **Local Decoder** – Another lightweight transformer unpacks each predicted patch back into bytes via inverse cross‑attention, enabling fine-grained generation while preserving rapid inference thanks to conditional invocation of the global model.

By carefully separating concerns—cheap per-byte computation versus expensive per-patch computation—BLT achieves dynamic allocation of compute proportional to information density in the data stream.  The architectural choices described here—including hash n‑gram augmentations, masked cross-attention pooling, RoPE positional handling, and deliberate parameter scaling—form a cohesive system that retains or surpasses tokenisation-based performance while offering substantial gains in efficiency and robustness.

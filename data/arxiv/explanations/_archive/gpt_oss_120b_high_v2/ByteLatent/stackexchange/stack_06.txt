\title{Stack Exchange of the Paper: "Byte Latent Transformer: Patches Scale Better Than Tokens"}

### Can you explain the cross‑attention mechanism in the encoder: how are queries initialized and how is masking applied?
Question:
The encoder cross‑attention follows Perceiver’s design but adapts it for variable‑size patches. The paper says queries \(Q_j\) are initialized by pooling byte representations of each patch and then projected. How exactly is this pooling performed (max/mean/other)? Additionally, how does the mask ensure that each query only attends to bytes within its own patch?
Answer:
In the encoder of **BLT** the cross‑attention block is essentially a Perceiver‑style “latent‑to‑visible’’ attention, but the latents are not a fixed set – they are the **patch representations** that will later be fed to the global transformer.  

The first thing we need for a cross‑attention step is a set of query vectors $Q_{j}$, one per patch $p_{j}$.  The paper states that each query is **initialized by pooling the byte representations that belong to that patch** and then projecting the pooled result:

$$
P_{0,j}= \mathcal{E}_{C}\bigl(f_{\text{bytes}}(p_{j})\bigr),
$$

where $f_{\text{bytes}}(p_{j})$ denotes the sequence of byte embeddings $e_i$ (the sum of the raw byte embedding and the optional n‑gram hash embeddings) that lie inside patch $p_{j}$.  In practice this pooling is performed with **max‑pooling** over the temporal dimension of the bytes in a patch.  The authors found max‑pooling more stable than mean‑pooling because it preserves the most salient activation among all bytes, which works well when patches can vary widely in length.  After max‑pooling, a linear map $\mathcal{E}_{C}\in\mathbb{R}^{h_{\mathcal{E}}\times (h_{\mathcal{E}}\!\times\!U_{\mathcal{E}})}$ expands the pooled vector into the multi‑head query matrix $Q$ (one head per query).

Once we have queries, we compute standard multi‑head attention against **keys** and **values** that come from the byte‑level hidden states $h_{l-1,i}$ produced by the preceding transformer layer:

$$
K_i = W_k\,h_{l-1,i},\qquad 
V_i = W_v\,h_{l-1,i},\qquad
Q_j = W_q\,P_{l-1,j}.
$$

If we naïvely let every query attend to every key/value pair we would mix information across patches, which defeats the purpose of having distinct latent slots for each patch.  Therefore BLT builds a **patch‑wise mask** that is essentially block‑diagonal:

* For query $j$ we set $\text{mask}_{j,i}=0$ (allow attention) only when byte $i$ belongs to patch $j$; otherwise we set $\text{mask}_{j,i}=-\,\infty$ (or any large negative number).  
* This mask is added to the logits $\frac{QK^{\top}}{\sqrt{d_k}}$ before applying softmax, guaranteeing that $\operatorname{softmax}\bigl(\frac{QK^{\top}}{\sqrt{d_k}} + \text{mask}\bigr)$ assigns zero weight outside the current patch.

Because patches are defined dynamically (entropy or space based), the mask is recomputed at each forward pass based on the current segmentation; FlexAttention is used so that this irregular masking does not become a performance bottleneck.

The masked attention produces an update $\Delta P_{l}$ which is added residually to $P_{l-1}$.  After all cross‑attention layers have run (one after every local transformer layer), each patch representation has absorbed information from exactly its constituent bytes while still benefiting from multiple rounds of local self‑attention among those bytes.

In summary:

* **Query initialization:** take the byte embeddings inside a patch, apply max‑pooling over time, then linearly project into multi‑head query vectors.  
* **Masking:** construct a binary mask that permits a query to attend only to keys/values belonging to its own patch; this yields a block‑diagonal attention matrix that isolates patches while still allowing rich interaction within them.

Conceptually this mirrors the Perceiver’s latent‑to‑input attention, except that instead of a static latent array we have one latent per dynamically sized patch, and we enforce strict per‑patch locality through masking.  The result is an efficient way for a lightweight local encoder to compress variable‑length byte chunks into expressive latent vectors ready for the global transformer.​

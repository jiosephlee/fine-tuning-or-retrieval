\title{Blogs about the Paper: "DeepSeekMath: Pushing the Limits of Mathematical Reasoning in Open Language Models"}

# Think Like a Mathematician: Instruction Tuning with Chain‑of‑Thought & Program‑of‑Thought  

Large language models have made impressive strides on math problems, but most open‑source models still lag far behind proprietary giants such as GPT‑4. The DeepSeekMath effort shows that a carefully crafted instruction‑tuning stage—built on top of a math‑pretrained “base” model—can close much of that gap, even at the modest 7 B‑parameter scale. Below we walk through how a 776 K example instruction corpus was built, why three distinct reasoning formats (CoT, PoT, and tool‑integrated) matter, and how fine‑tuning turned **DeepSeekMath‑Base** into **DeepSeekMath‑Instruct**, a model that now beats every other open‐source 7 B system on challenging benchmarks like *MATH*.

---

## From a Math‑Pretrained Base to an Instruction Model  

DeepSeekMath‑Base 7 B is itself a product of large‐scale pretraining on **120 B** math tokens harvested from Common Crawl (plus code and natural language data). Starting from **DeepSeek‑Coder‑Base‑v1.5** gives the model strong coding habits—a crucial foundation for later programmatic reasoning. The next step is *instruction tuning*: expose the model to high‑quality examples where the desired output style is explicitly demonstrated.  

### The Instruction Corpus: 776 K Bilingual Math Problems  

| Language | Sources | Typical Coverage |
|----------|---------|-------------------|
| **English** | GSM8K, MATH (augmented with tool‑integrated solutions), MathInstruct subset, Lila‑OOD training set | Algebra, probability, calculus, number theory, geometry |
| **Chinese** | Curated K‑12 datasets spanning 76 sub‑topics (e.g., linear equations, combinatorics) | Same breadth as English plus curriculum–specific nuances |

* Total examples: **776 000**  
* Each example pairs a problem statement with one or more solution formats (CoT / PoT / tool).  

The inclusion of Chinese data is intentional: the pretraining corpus is multilingual, and evaluation shows noticeable gains on Chinese benchmarks such as **CMATH**, **Gaokao-MathCloze**, and **Gaokao-MathQA**—areas where many English‑centric corpora actually hurt performance.

---

## Three Reasoning Formats, One Unified Model  

### 1. Chain‑of‑Thought (CoT)  
A classic “think aloud” format: the model produces a step‑by‑step textual derivation before giving the final answer. CoT teaches the model *how* to decompose a problem into logical pieces rather than just spitting out an answer token.

### 2. Program‑of‑Thought (PoT)  
Here the solution is expressed as executable Python code (`math`, `sympy`, etc.). The prompt explicitly asks for a function or script that computes the answer. This format forces the model to structure its reasoning as algorithmic operations—a skill that aligns naturally with its coding pretraining.

### 3. Tool‑Integrated Reasoning  
A hybrid approach reminiscent of recent “code interpreter” pipelines: the model may generate natural language reasoning *and* embed calls to Python or other tools within the same answer. The generated code is executed on the fly; its output is concatenated back into the final solution. This format bridges pure textual reasoning and programmatic computation.

By interleaving all three formats during fine‐tuning, DeepSeekMath learns *when* textual explanation suffices and *when* it should fall back to computation. The model also internalizes how to transition between them—a subtle skill that most single‐format approaches miss.

---

## Fine–tuning Details (SFT)

* **Model:** DeepSeekMath‑Base 7 B  
* **Training steps:** 500 (a deliberately short run given the high quality of data)  
* **Batch size:** 256 sequences  
* **Learning rate:** constant $5\times10^{-5}$  
* **Context window:** up to $4\,\text{k}$ tokens per concatenated example  

Each batch contains randomly concatenated examples until reaching the token limit—this mirrors inference conditions where multiple questions may appear in one context window.

Because the dataset already contains explicit reasoning traces (CoT/PoT), no auxiliary loss was needed—the standard cross‐entropy signal automatically reinforces correct token predictions at every step of a chain or line of code.

## How Much Did Instruction Tuning Help?

### Competitive Edge on English Benchmarks

| Model | GSM8K (CoT) | MATH (no tools) |
|-------|------------|-----------------|
| DeepSeekMath‑Instruct 7 B | **88.2 %** | **51.7 %** |
| Prior best open source 7 B (e.g., WizardMath v1.1) | ~78 % | ~42 % |
| Closed‐source “mid tier” (Inflection 2, Gemini Pro) | ~80–84 % | ~45–48 % |
| GPT‑4 / Gemini Ultra | >90 % | >60 % |

The *MATH* score of **51.7 %** places DeepSeekMath among the very few open models crossing the half‐mark on this competition‐level benchmark—previously only reachable by proprietary giants or far larger open models (~70 B).  

When tool usage is allowed (program‐aided solving), accuracy climbs toward **60 %** on *MATH*, outpacing every other open source system in that regime as well.

### Multilingual Gains

On Chinese datasets:

* **CMATH** → >84 % accuracy  
* **Gaokao-MathQA / MathCloze** → comparable or better than large multilingual LLMs  

These results underscore that exposing the model to Chinese problem statements during instruction tuning unlocks latent capabilities inherited from its multilingual pretraining corpus.

### Beyond Math – A Boost to General Reasoning

Interestingly, after SFT the model also nudged up on non‐math tasks such as:

* MMLU–STEM (+~3 pts)  
* BBH (+~2 pts)  

The improvement hints that deep mathematical reasoning shares common patterns with broader logical deduction—another argument for multi‐task instruction tuning rather than isolating math alone.

## Why Does This Recipe Work?

1. **Diverse Solution Types Teach Adaptability** – CoT teaches narrative decomposition; PoT forces algorithmic precision; tool integration teaches when external computation is beneficial. The model learns *meta‐reasoning*: “if my chain stalls, switch to code.”

2. **Leverages Code Pretraining** – Starting from a coder base means PoT examples are not foreign; they reinforce already existing syntax knowledge instead of forcing new token embeddings from scratch.

3. **Multilingual Exposure Reduces Language Bias** – By mixing English and Chinese examples we avoid overfitting to one linguistic style and encourage abstract symbolic processing that transcends language specifics.

4. **High Signal-to‑Noise Ratio** – The curated set excludes any benchmark contamination via strict n‑gram filtering; each example presents clean ground truth steps or scripts rather than noisy scraped chatter.

5. **Compact Yet Powerful Fine Tuning** – Only half a thousand steps are needed because each example carries rich supervision at every token level; there’s no need for massive epochs when quality is this high.

---

## Takeaways for Practitioners

*When building an LLM for mathematics (or any structured domain), consider mixing three flavors of supervision:*  
- pure textual reasoning (**CoT**)   
- executable code (**PoT**)   
- hybrid tool calls (**tool‐integrated**)  

Even at modest parameter counts (7 B), this triad can push you past most contemporary open systems without expensive RL steps—though RL can add another couple percent if desired.

*Language diversity matters.* If you plan to serve multilingual users or evaluate on non–English benchmarks, sprinkle in native problem statements early during instruction tuning; it pays off directly in accuracy gains rather than just making your dataset larger.

Finally, remember that high‐quality data trumps sheer volume: DeepSeekMath’s improvements stem more from carefully filtered web math pages than from adding additional arXiv papers—something worth testing for any new domain you wish to specialize your LLM in.

---  

In short, by curating a focused bilingual instruction set and teaching *how* to think—as words or as programs—DeepSeekMath turned a solid math base into an instruction model that now leads all public 7 B contenders on *MATH*. If you’re aiming for strong mathematical prowess without spending billions on parameters, this recipe offers a practical roadmap. Happy prompting!

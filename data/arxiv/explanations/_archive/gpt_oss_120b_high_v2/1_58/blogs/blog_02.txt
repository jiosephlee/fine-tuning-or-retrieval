# Same Accuracy, Half the Bits – Inside the Training Tricks That Let b1.58 Match FP16  

*How a few clever quantization steps let a ternary‑weight LLM train from scratch while keeping perplexity and zero‑shot scores on par with full‑precision LLaMA.*

---

## Why We Care About “Half‑the‑Bits” LLMs  

Large language models have exploded in size, but every extra bit per parameter inflates memory traffic, power draw, and latency.  
Post‑training quantization can shrink a trained model, yet it never restores the original floating‑point quality because the reduction happens after learning has already settled on high‑precision weights.  

The newer **BitNet** line goes a step further: it *trains* directly with extreme low precision so that the model never needs full‑precision matrix multiplications during inference. The latest variant—**BitNet b1.58**—pushes this idea even farther by using **ternary weights** \(\{-1,\;0,\;+1\}\). With three possible values a weight carries \(\log_2(3)\approx1.58\) bits of information, hence the name *b1.58*.  

The surprising result? Starting at **3 B parameters**, BitNet b1.58 attains **the same perplexity** and **zero‑shot accuracy** as its FP16 counterpart while being **2–4× faster**, **3–5× smaller** in GPU memory, and **≈70× more energy‑efficient** for matrix multiplications.

Below is a walk‑through of the three key tricks that make this possible:

* **Abs‑mean scaling** – normalizes raw weights before discretisation  
* **RoundClip rounding** – projects every scaled value onto \{-1, 0, +1\}  
* **Symmetric int8 activations** – keeps activations low precision without a separate zero‑point  

---

## From Full Precision to Ternary Weights  

In a standard Transformer layer (`nn.Linear`) each output is computed as  

\[
y = Wx + b,
\]

with \(W\) stored in half precision (FP16/BF16). In BitNet b1.58 we replace `nn.Linear` by **BitLinear**, whose weight matrix \(W\) is constrained to ternary values before every forward pass:

| Weight domain | Representation | Approximate bit budget |
|---------------|----------------|------------------------|
| Full precision | \(32/16\) bits   | — |
| Ternary      | \{-1,0,+1\}    | \(\log_2(3)\approx 1.58\) bits |

The embedding tables and LayerNorm parameters remain in higher precision (they dominate less than \(5\,\%\) of total parameters), so most of the compute stays integer based while preserving model capacity where it matters most.

---

## The Abs‑Mean Scaling Trick  

A naïve rounding of raw floating‑point weights would bias heavily toward either \(-1\) or \(+1\); many useful small magnitudes would be forced into non‑zero bins unnecessarily. To keep the ternary distribution balanced around zero, BitNet b1.58 first scales each weight matrix by its *average absolute value*:

\[
\gamma = \frac{1}{nm}\sum_{i=1}^{n}\sum_{j=1}^{m} |W_{ij}|,
\]

where \(W\in\mathbb{R}^{n\times m}\).  
Dividing by \(\gamma+\epsilon\) (with a tiny \(\epsilon>0\) for numerical stability) normalizes the whole tensor so that its typical magnitude sits around one. After this step most entries lie close enough to an integer in \([-1,\,0,\,+1]\) that a simple rounding operation produces very few out‑of‑range values.

---

## RoundClip – Rounding That Respects Bounds  

Once scaled, each entry is projected onto the ternary set via **RoundClip**:

```text
RoundClip(x,a,b) = max(a , min(b , round(x)))
```

Applied elementwise,

\[
\widetilde{W}_{ij}
   = \operatorname{RoundClip}\!\left(
        \frac{W_{ij}}{\gamma+\epsilon},
        -\,1,\;
        +\,1
      \right),
    \qquad
    \widetilde{W}_{ij}\in\{-1,\;0,\;+1\}.
\]

Key properties:

* **Deterministic** – every forward pass sees exactly the same ternary matrix.
* **Bounded** – clipping guarantees no overflow beyond \(-1\) or \(+1\).
* **Sparse-friendly** – when many scaled entries fall between \(-0.5\) and \(+0.5\), they become zeros after rounding, giving rise to natural sparsity that further reduces effective bit usage.

During training the optimizer updates a *full‑precision shadow copy* of \(W\); after each parameter update we immediately apply the above projection so that downstream operations always use \(\widetilde{W}\). This “project‐after‐step” approach avoids costly custom gradient definitions while still enforcing strict ternarity throughout learning.

---

## Symmetric Int8 Activations  

Weight quantisation alone cuts down memory dramatically, but activation tensors dominate bandwidth during inference—especially the KV caches for long contexts. BitNet b1.58 therefore stores all activations at **8 bits**, using a *symmetric* uniform quantiser per token:

* Each token’s activation vector is linearly scaled so its maximum absolute value maps to \(Q_b = 127\).
* The range becomes \([-Q_b,\,+Q_b]\); there is **no separate zero point**, simplifying both software kernels and potential hardware implementations.
* Because both inputs (\(x\)) and outputs (\(y=\widetilde{W}x + b)\) are integers now, matrix multiplication reduces fundamentally to **integer addition**—the multiplication by \(\{-1,+1\}\) is just sign flipping or copying—and any remaining scalar multiplications happen outside the hot loop (e.g., re‑scaling after accumulation).

The choice of symmetric int8 also keeps dynamic range comparable to FP16 while incurring negligible accuracy loss—the authors report “negligible effects” when swapping from asymmetric [0,\(Q_b]\) scaling used in original BitNet to this symmetric scheme.

---

## Building on Proven LLaMA Components  

To make adoption painless for practitioners already familiar with open-source LLM stacks (HuggingFace 🤗 Transformers, vLLM, llama.cpp), BitNet b5​8 mimics LLaMA’s architecture closely:

| Component | LLaMA version | BitNet b5​8 tweak |
|-----------|--------------|-------------------|
| Normalisation | RMSNorm | unchanged |
| Feedforward gating | SwiGLU | unchanged |
| Positional embeddings | Rotary (RoPE) | unchanged |
| Biases | Present | *Removed* |

Removing biases reduces memory traffic further without harming performance because RMSNorm already handles shift invariance well enough for language modeling tasks.

---

## Training From Scratch — The Full Pipeline  

The authors trained BitNet b5​8 *from scratch* on the RedPajama corpus (**100 B tokens**) under exactly the same hyperparameters used for an FP16 LLaMA baseline (same depth, hidden size, attention heads). The pipeline looks like this:

```
for each training step:
    # Forward pass
    W_t = round_clip(absmean_scale(W_full))
    out = BitLinear(W_t, x_int8)
    loss = CrossEntropy(out, target)

    # Backward pass on full‑precision shadow copy
    loss.backward()
    optimizer.step()          # updates W_full
```

Key points ensuring parity with FP16:

* **Gradient flow through full precision:** since only forward activation uses ternary `W_t`, gradients still see rich information during backpropagation.
* **Consistent scaling:** `γ` is recomputed every forward pass so that weight dynamics adapt continuously.
* **No post‑training fine tuning:** The model reaches full performance directly after pretraining without an extra polishing stage—a major advantage over post‐training quantisation methods that usually degrade accuracy substantially.

### Zero‑Shot Benchmarks  

Evaluated on ARC‐Easy/Challenge, Hellaswag, Winogrande, PIQA, OpenBookQA and BoolQ using EleutherAI’s `lm-evaluation-harness`.  
Results show a gradual closing of gaps as scale rises; at **3 B** onward performance is statistically indistinguishable from FP16 LLaMA baselines—a “Pareto improvement”.

### Inference Cost

*Latency:* Measured as time per output token using NVIDIA FasterTransformer plus Ladder’s custom 2‑bit kernel → up to **4× faster** at 70 B scale because integer addition scales linearly whereas floating‑point multiply‐add grows superlinearly with hidden size.<br>
*Memory:* Ternary weight storage plus int8 activations yields up to **5× lower peak GPU memory**, freeing capacity for larger batch sizes or longer context windows.<br>
*Energy:* An analytical model based on silicon energy tables ([EnergyCost], [PokeBNN]) attributes most savings to replacing an FP16 multiply (+add) pair (~\(10^{-9}\) J) by an INT8 add (~\(10^{-11}\) J). Overall arithmetic energy drops by **≈71×** for matrix multiplication alone—making large deployments far greener.<br>
*Throughput:* On two A100 80GB GPUs running pipeline parallelism at sequence length 512,
BitNet b₁·₅₈ 70 B supports up to **11× larger batch size**, translating into an almost **9× higher token throughput** compared with FP16 LLaMA 70 B.

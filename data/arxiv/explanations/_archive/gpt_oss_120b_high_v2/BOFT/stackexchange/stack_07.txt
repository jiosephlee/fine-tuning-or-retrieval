\title{Stack Exchange of the Paper: "Parameter-Efficient Orthogonal Finetuning via Factorization"}

### How does block size $b$ affect the trade‑off between expressivity and parameter efficiency in BOFT?
Question:
Figure 3 shows that increasing $b$ reduces parameter count but seems to worsen approximation error when trying to mimic a random dense orthogonal matrix. Conversely, smaller $b$ with larger $m$ gives better approximation with fewer parameters overall. Could someone clarify intuitively why larger blocks make the model less expressive despite having fewer components, and how one should choose $(m,b)$ for a given layer dimension $d$?
Answer:
**Answer**

In BOFT the orthogonal matrix that finetunes a layer is written as  

$$
  \mathbf R(m,b)=\prod_{i=1}^{m}\tilde{\mathbf B}^{\,b}_{(d,i)},
  \qquad 
  \tilde{\mathbf B}^{\,b}_{(d,i)}\in\mathbb R^{d\times d},
$$

where every factor $\tilde{\mathbf B}^{\,b}_{(d,i)}$ is a **block‑butterfly component** whose non‑zero pattern consists of $d/b$ blocks of size $b\times b$. Because each component is orthogonal its trainable degrees of freedom are only the $\tfrac12(b-1)d$ entries inside the $b\times b$ rotation matrices; the whole network therefore has  

$$
 P(m,b)=\frac{(b-1)}{2}\;d\,m
   \tag{1}
$$

effective trainable parameters.

---

### Why a larger block makes the model less expressive

The butterfly construction can be interpreted as an **information‑transmission graph** on a grid of $d$ source nodes and $m+1$ levels (Fig.\,3 of the paper). Each factor $\tilde{\mathbf B}^{\,b}_{(d,i)}$ contributes exactly $d$ directed edges between two adjacent levels – one edge per row – because orthogonality forces every row to contain exactly one non‑zero entry in each column pairing. The *pattern* of those edges is determined by the block size $b$.

When $b=2$, every factor connects each node only to its immediate neighbour in a **pairwise** fashion; after $\log_{2}d$ stages every source can reach every sink through many distinct routes. This yields a **dense connectivity** on the grid with only $\mathcal O(d\log d)$ edges – exactly what a full orthogonal matrix needs – while keeping each stage extremely local. Because paths can be recombined arbitrarily across stages, the reachable set of matrices is very close to the whole orthogonal group. Empirically this shows up as a low approximation error even with few parameters ($P\simeq\tfrac12 d\log d$).

If we increase the block size to $b>2$, each factor now mixes groups of $b$ dimensions at once rather than pairs. The induced graph still has one edge per node per level, but now those edges are “bundled’’ inside larger blocks, so there are **fewer possible permutations** between successive levels. In graph‑theoretic terms, the number of *edge‑disjoint* paths between any source–sink pair shrinks dramatically when blocks become large: many source nodes remain confined inside their original $b$‑sized group throughout all stages because subsequent butterfly components merely permute whole groups instead of interleaving them elementwise. Consequently the set of reachable orthogonal matrices collapses onto a structured subset that is essentially **block‑diagonal up to a limited set of permutations**. This loss of mixing ability translates directly into poorer ability to approximate an arbitrary dense orthogonal matrix, which explains why Fig.\,3 shows higher reconstruction error for larger~$b$.

Notice also that increasing~$b$ reduces the required depth~$m$: dense connectivity can already be obtained after roughly $\log_{2}(2d/b)$ stages because each stage halves the “granularity’’ at which information spreads. Fewer stages mean fewer opportunities for reshuffling information, which compounds the expressivity loss described above.

Hence there are two intertwined effects:

* **Fewer degrees of freedom per stage** – a rotation in an isolated $b\times b$ subspace has only $\tfrac12(b-1)b=\tfrac12 b(b-1)$ free angles instead of $(c)(c-1)/2$, so each factor contributes fewer independent parameters relative to its size;
* **Reduction in effective mixing depth**, which limits how many distinct paths connect inputs and outputs;
* Together they make large~$b$ models cheaper in parameters but poorer in expressive power.

---

### Choosing $(m,b)$ for a given hidden dimension $d$

A practical recipe follows directly from Eq.~(1) together with the “dense‑connectivity’’ requirement

$$
   m \;\geqslant\;
   \bigl\lceil\,\log_{2}\!\bigl(\tfrac{2d}{\,b}\Bigr)\,\big\rceil,
   \tag{2}
$$

which guarantees that every source node can reach every sink node once all components are multiplied.

Given a budget $P_{\max}$, one can simply search over powers‐of‐two values $b\in\{2,4,8,\dots ,d\}$:

1️⃣ Compute the minimal depth  
   $$ m_{\min}= \bigl\lceil\,\log_{2}\!\bigl(\tfrac{2d}{\,b}\Bigr)\,\big\rceil,$$
   which gives exactly what is needed for dense connectivity.

2️⃣ Evaluate the associated parameter count through Eq.~(1):
   $$ P(b)= ((\,b-1)/2)\; d\, m_{\min}. $$

3️⃣ Keep all candidates satisfying $P(b)\le P_{\max}$.  
   Among them prefer **smaller~$b$**, because it yields larger depth and consequently richer mixing.  
   If runtime or memory constraints forbid many matrix multiplications, pick the largest admissible~$b$ instead.

In most transformer or vision models ($d\simeq1024{-}2048$), experiments reported in Section 5 show that **$b∈[4,8]** strikes an excellent balance: it needs only about six–eight butterfly factors ($m≈6{-}8$), uses roughly three–four thousand trainable numbers per layer—well below LoRA’s low‐rank budgets—and still achieves approximation errors comparable to those obtained with full OFT ($m=1$, $b=d)$).

If ultra‐tight parameter budgets are required (e.g.\ <0.05 % of all model weights), setting **$b=2$, $m≈⌈\log_{2}d⌉** gives the smallest possible overhead ($≈½  d  log_{2} d.$). The extra runtime from multiple multiplications is modest because each factor is extremely sparse (only two nonzero entries per column), so training speed stays comparable to standard OFT.

Conversely, if one wishes to avoid any noticeable additional forward passes during finetuning—perhaps on very large models—choosing a moderate block such as **$b=16$, $m≈⌈log_{₂}(128)⌉≈7** reduces multiplication steps at modest cost in approximation quality while still staying well under an OFT’s quadratic parameter count.

---

### Summary

Increasing the block size~$b$ shrinks both **the number of butterfly stages** and **the granularity at which dimensions are mixed**, which in turn lowers the number of edge‑disjoint paths linking inputs to outputs in the information‑transmission graph underlying BOFT. Fewer paths mean a smaller reachable subset of orthogonal matrices and therefore higher reconstruction error when trying to imitate an arbitrary dense orthogonal matrix.  

The total trainable cost grows as $\tfrac{(b-1)}{2}\,dm,$ while dense connectivity imposes  

$$
   m 
      \geqslant 
      \Bigl\lceil 
          \log_{2}\!\Bigl(\frac{2\,d}{\, b}\Bigr)
      \Bigr\rceil .
$$ 

These simple relations guide practitioners toward principled choices of $(m,b)$ that respect parameter budgets while preserving most of BOFT’s expressive power.

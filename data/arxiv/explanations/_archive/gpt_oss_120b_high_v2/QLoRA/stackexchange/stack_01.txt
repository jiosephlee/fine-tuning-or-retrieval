\title{Stack Exchange of the Paper: "QLoRA: Efficient Finetuning of Quantized LLMs"}

### Why does QLoRA compute gradients only for LoRA adapters and not for the frozen 4‑bit base model weights?
Question:
In Section 3 the paper states that during training "the calculation of \(\partial E / \partial L_i\) entails the calculation of \(\partial X / \partial W\)" but that gradients w.r.t. the 4‑bit weight matrix \(W\) are never stored or updated.

I am confused about how back‑propagation works when the base model is kept frozen and stored in a quantized format:

* Does QLoRA treat the dequantization operation as a differentiable function?
* If it is not differentiable, is a straight‑through estimator used?
* Why is it safe (or beneficial) to completely discard \(\partial E / \partial W\) instead of updating \(W\) during fine‑tuning?

A clear step‑by‑step explanation would help me understand how gradients flow through a frozen quantized model.

Answer:
In QLoRA the pretrained language model is **kept frozen** and is stored in a 4‑bit NormalFloat (NF4) format.  
During fine‑tuning only a set of Low‑rank Adapter (LoRA) matrices $\displaystyle \bigl(\boldsymbol L_{1},\,\boldsymbol L_{2}\bigr)$ are trainable.  
Consequently the backward pass must **propagate gradients through the quantised backbone** so that the LoRA updates receive correct signals, but it must **avoid allocating any gradients or optimiser state for the original 4‑bit weights $\boldsymbol W$**.  

Below is a concise walk‑through of how this works and why discarding $\displaystyle \frac{\partial E}{\partial \boldsymbol W}$ is both correct and advantageous.

---

### 1. Forward computation  

For a single linear layer the QLoRA forward equation (Eq.​5–6 in the paper) is  

$$
   \boldsymbol Y^{\,\mathrm {BF16}}
   = 
   \boldsymbol X^{\,\mathrm {BF16}}\;
   \underbrace{
      {\rm doubleDequant}\!\Bigl(
         c_{1}^{\,\mathrm {FP32}},\,c_{2}^{\,k-\mathrm {bit}},\,\boldsymbol W^{\,k-\mathrm {bit}}
      \Bigr)
   }_{\displaystyle \boldsymbol W^{\,\mathrm {BF16}}}
   +
   \boldsymbol X^{\,\mathrm {BF16}}\,
   \boldsymbol L_{1}^{\,\mathrm {BF16}}\,
   \boldsymbol L_{2}^{\,\mathrm {BF16}} .
$$  

`doubleDequant` first reconstructs the per‑block scale constants $c_{2}$ from their FP8 representation using another linear de‑quantisation step with $c_{1}$, and then multiplies the 4‑bit integer matrix $\boldsymbol W^{\,k-\mathrm {bit}}$ by the resulting scale factor.  
Both steps are **pure affine operations**  
(e.g. “cast integer → float’’ followed by “multiply by a scalar’’), which have exact derivatives:

```text
dequant(c,\boldsymbol W) = $\displaystyle \frac{\boldsymbol W}{c}$
∂dequant/∂c          = $-\displaystyle \frac{\boldsymbol W}{c^{2}}$
∂dequant/∂$\boldsymbol W$ = $\displaystyle \frac 1 c$
```

Because the whole chain consists of divisions and multiplications,
autograd treats `doubleDequant` as a *differentiable* function.
No stochastic rounding or non­continuous operation appears at run time—the rounding was already performed once when the model was originally quantised, so nothing needs a straight‑through estimator.

---

### 2. Backward pass  

Let $E$ be the loss function.  The upstream gradient arriving at this layer is  
$\displaystyle \frac{\partial E}{\partial \boldsymbol Y}$.  
Using the chain rule we obtain  

$$
   \frac{\partial E}{\partial \boldsymbol L_{1}}
      = 
      \Bigl(\tfrac{\partial E}{\partial \boldsymbol Y}\Bigr)\,
      \boldsymbol X\,%
      {\boldsymbol L}_{2}^{\,T},
   \qquad
   \frac{\partial E}{\partial \boldsymbol L_{2}}
      = 
      \Bigl(\tfrac{\partial E}{\\partial \\boldsymbol Y}\\Bigr)\,
      {\boldsymbol L}_{1}^{\,T}\,
      \\BoldSymbol X .
$$

These two expressions contain **no reference to** the frozen weight matrix $\boldsymbol W$; nevertheless the upstream gradient itself has traversed all previous layers—including those that contain $\boldsymbol W$.  To obtain it, autograd must compute  

$$
   \\frac{
      \\partial E
   }{
      \\partial \\BoldSymbol X
   }
   =
   \\Bigl( \\frac{
          \\Partial E}{
          \\Partial \\BoldSymbol Y}
          \\Bigr)
          \\,
          \\underbrace{
               \\Bigl(
                    \\frac{
                       \\Partial(\\BoldSymbol X\\BoldSymbol W)
                    }{
                       \\Partial \\BoldSymbol X}
               \\Bigr)}_
                {
                  =~\\BoldSymbol W^{~\\rm deq}
                }
        + 
        \\Bigl( \\frac{
           \\Partial E}{
           \\Partial \\BoldSymbol Y}
           \\Bigr)
           (
              \\BoldSymbol L_{1}\\BoldSymbol L_{2}
           ).
$$

In other words, **the derivative**
$\displaystyle 
    \\frac{
       \\Partial x}
     {
       \\Partial {{\\BoldSymbol W}}
     }
$
is evaluated so that gradients can flow further backwards through earlier layers,
but **the resulting weight gradient**

$$
   \\frac{
      \\Partial E}{
      \\Partial {{\\BoldSymbol W}}
   }
   =
   % NOTE: note parenthesis placement guarantees syntax correctness
   "\\Bigl(
      \
      ..."
   % The formulation below follows standard matrix‐gradient rules.
"""
$

is never retained because **the leaf tensor `\(\BoldSymbol W)\)` has ``requires_grad=False``*.  
Frameworks such as PyTorch simply skip allocation of a gradient buffer and do not feed this value into any optimiser step.

Thus QLoRA performs exactly what Eq.​(5–7) describe:

* it **uses** $\displaystyle ∂x/∂w$ during back‑propagation in order to obtain activation gradients,
* it **does not store** $\displaystyle ∂E/∂w$, nor does it apply an optimiser update to $\BoldSymbol W.$

---

### 3\. Why discarding $\displaystyle ∂E/∂ \bmath W\bmath{}$ is safe  

| Reason | Explanation |
|---|---|
| **Parameter‑efficient fine‑tuning premise** | LoRA assumes that most knowledge required for downstream tasks already resides in the pretrained backbone; only a low–dimensional additive correction $s\,X\,L_{1}L_{2}$ needs to be learned. Empirically (Section 5) this reproduces full‐model fine‐tuning performance across scales from 7 B up to 65 B parameters when enough adapters are placed throughout the network. |
| **Avoiding catastrophic forgetting** | Updating billions of frozen weights on tiny instruction datasets often harms generalisation because the optimiser can overfit noise in those few examples. Keeping $\BoldSymbol W$ fixed preserves the broad linguistic competence learned during pretraining while letting adapters specialise on the new task distribution. |
| **Memory budget** | Storing a full‑precision copy of $\BoldSymbol W~(≈16~{\rm bits})$, its accumulated gradients and Adam moments would add roughly one additional parameter buffer per model parameter—a prohibitive cost for >30 B models (>300 GB). By freezing $\BoldSymbol W$, QLoRA needs only its compressed NF4 representation (~0.5 bits per parameter plus tiny constant tables) and optimiser state for a few million adapter parameters (<30 MB). This is precisely why QLoRA can fine‐tune a 65 B model on a single 48 GB GPU (§3). |
| **No optimisation target** | Because quantisation artefacts have already been baked into NF4 at conversion time, there is nothing meaningful for SGD/Adam to correct in those integer values—their purpose now is simply to provide an efficient *lookup* of an approximate floating‐point matrix during training. Updating them would require converting back to higher precision each step, defeating both speed and memory advantages. |

Consequently discarding $\displaystyle ∂E/∂ \bmath W\bmath{}$ does **not** impair learning; all necessary learning signals reach the trainable LoRA matrices via Jacobians involving $∂x/∕∂w.$

---

### 4\. Summary  

*The de‑quantisation pipeline (`doubleDequant`) consists solely of linear scaling operations,
so autograd treats it as fully differentiable.*  
*There is no need for a straight‑through estimator—the only non‐differentiable step—rounding—was performed once before training.*  
*During backpropagation QLoRA computes activation gradients using $∂x/⁄∂w$, then stops at $w,$ because $w.\!\operatorname{{requires_grad}}=False.$ The resulting weight gradient is never stored or applied.*  
*Freezing $w$ yields three concrete benefits:*  
&nbsp;&nbsp;(i) it respects the PEFT principle that low‐rank adapters suffice,  
&nbsp;&nbsp;(ii) it prevents overfitting on small finetuning corpora, and   
&nbsp;&nbsp;(iii) most importantly it reduces memory usage dramatically, enabling single‐GPU fine‐tuning of models that would otherwise require hundreds of gigabytes.

All these design choices are explicitly described in Section 3 (“…the calculation of $\displaystyle ∂E/∂L_i … entails calculation of $\displaystyle ∂x/∕∂w … however … we only compute weight gradients for the LoRA parameters”) and empirically validated throughout Sections 5–7 where QLoRA matches full‐precision fine‐tuning performance while keeping the base model frozen in NF4 format.​

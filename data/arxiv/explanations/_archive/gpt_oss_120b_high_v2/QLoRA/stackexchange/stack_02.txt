\title{Stack Exchange of the Paper: "QLoRA: Efficient Finetuning of Quantized LLMs"}

### How is the 4‑bit NormalFloat (NF4) data type constructed from a standard normal distribution?
Question:
The authors claim that NF4 is "information‑theoretically optimal" for zero‑centered normal data.

* What are the exact steps to compute the NFk quantile thresholds from a \(N(0,1)\) distribution?
* How are these thresholds scaled into the range \([-1,1]\)?
* The paper mentions creating an "asymmetric" representation to ensure a discrete zero point—how exactly are positive and negative thresholds merged while preserving one zero value?

I would appreciate a concise description (or pseudo‑code) showing how the NF4 codebook values are derived.

Answer:
**Answer**

The $NF_k$ family is nothing more than a *fixed* scalar‑quantiser whose reconstruction points are chosen so that a centred Gaussian source would populate every bin with exactly the same probability mass.  
For $k=4$ this gives us a four‑bit (“NF4”) datatype that contains sixteen reconstruction values – eight negative, one exact zero and eight positive – and it can be built completely offline because the source distribution $N(0,\sigma)$ is known up‑to a scale factor $\sigma$.

Below I describe every step mentioned in the paper and give a short Python reference implementation that reproduces the numbers shown in Appendix A of *QLoRA*.



--------------------------------------------------------------------
### ① Quantile locations of a standard normal  

Let  

$$
\Phi(x)=\Pr[Z\le x]\quad\text{with } Z\sim N(0,\,1),\qquad
\Phi^{-1}(p)=Q_{X}(p)\;\text{the inverse CDF}.
$$  

If we want $M:=2^{k}$ equiprobable reconstruction regions we first generate  

$$
V := M + 1,
$$  

i.e. one more probability point than there are bins. In other words we split the unit interval $[0,\,1]$ into $M$ equal‑probability intervals.



--------------------------------------------------------------------
### Step Ⅰ – The equiprobable centres  

For any integer $m > 0$

$$
C_m(i)= \frac12\Bigl[\Phi^{-1}\!\Bigl(\frac{i}{m}\Bigr)
                +\Phi^{-1}\!\Bigl(\frac{i+1}{m}\Bigr)\Bigr],
        \qquad i=0,\dots,m-2 .
$$   (3)

$C_m(i)$ is simply the midpoint between two consecutive theoretical quantiles; it therefore lies exactly halfway through an interval that carries probability $\displaystyle\tfrac{1}{m}$.

For a *symmetric* four‑bit datatype ($M=16$) we would take  
$m=M+1=17$. Evaluating (3) gives us sixteen real numbers $\{c_0,\dots,c_{15}\}$; these are the **raw** NormalFloat reconstruction points derived from a $N(0,\,1)$.



--------------------------------------------------------------------
### Step Ⅱ – Normalising the raw points into $[-1,+\,1]$

The raw points span roughly $[-a,\,+a]$ with $a\simeq3.7$. Because our storage format always assumes that every weight block has already been rescaled so that it lives inside $[-1,+\,1]$, we simply divide all centres by their maximal absolute magnitude :

```python
a       = max(abs(c_i))                     # ≈3.713…
code[i] = c_i / a      ,   i = 0 … 15     # now ∈[-1,+ 1]
```

After this operation **every possible bin occupies an equal fraction of a unit‑Gaussian**, which makes NF$_k$ “information‑theoretically optimal” for any normally‑distributed tensor once its own scale factor has been applied.



--------------------------------------------------------------------
### Step Ⅲ – Obtaining an exact zeropoint (the “asymmetric” construction)

A perfectly symmetric partition never puts an **exact** reconstruction point at $x=0$; instead it places two very small opposite numbers around it. To guarantee that padding‑or‑zero entries incur no error we build the left‑hand side and right‑hand side separately and then merge them while discarding one duplicate “zero”.

*Left half* (equally probable intervals inside $(-\infty ,\,0]$)

```python
n_minus          = M // 2               # → eight intervals
delta_minus      = 0.5 / n_minus        # probability mass per left interval
p_minus_j        = (np.arange(n_minus) + 0.5) * delta_minus   # CDF mid‑points
l_j              = norm.ppf(p_minus_j)                       # negative centres
```

*Right half* (equally probable intervals inside $[0,\infty)$)

```python
n_plus           = n_minus + 1         # nine intervals → one more than the left side
delta_plus       = 0.5 / n_plus       
p_plus_j         = 0.5 + (np.arange(n_plus) + 0.5) * delta_plus   # CDF mid‑points
r_j              = norm.ppf(p_plus_j)                            # positive centres,
                                                                # r_0 equals exactly Φ⁻¹(½)=0 .
```

Now concatenate  

```
[l_7,…,l_0 , r_0 , r_1,…,r_8]
```  

→ fifteen distinct numbers **plus** two copies of “≈ 0” coming from `l_0` (very small negative) and `r_0` (=exactly 0).  
We delete one of them—conventionally keep the exact `r_0`—so that finally there are **exactly $M (=16)$** distinct reconstruction values,
one of which is precisely $0$.  
These sixteen numbers are then normalised as described in Step Ⅱ,
producing what the authors call **NF$_k$**.



--------------------------------------------------------------------
### Step Ⅳ – Quantising an actual weight block  

Assume a weight block $\mathbf W \in {\mathbb R}^{B}$.

```python
c      = max(abs(W))               # blockwise scale (“absmax”)
W_hat  = W / c                     # now ∈[-1,+ 1]
idx    = argmin_j |W_hat - code[j]|# nearest neighbour among the sixteen codes 
# idx∈{0,…,15} can be stored using four bits per element.
```

During dequantisation we recover

```python
W_tilde = c * code[idx]            # back‑to BF16 before matrix multiplication.
```

Because both “code’’ and “c’’ have been chosen so that their product reproduces every Gaussian percentile equally often,
the expected information loss per element is minimised – hence “information‑theoretically optimal”.



--------------------------------------------------------------------
### Pseudo‑code that reproduces the official NF4 table  

```python
import numpy as np
from scipy.stats import norm          # Φ⁻¹
    
def nf_codebook(k):
    """return a float32 array containing the NF_k reconstruction points."""
    
    M      = 2**k                      # total symbols e.g. M==16
    
    ## ----- left part -------------------------------------------------
    n_minus     = M // 2               # eight negatives
    step_neg    = 0.5 / n_minus
    
    probs_l     = (np.arange(n_minus)+0.5) * step_neg          # mid CDF points ∈(0,½)
    vals_l      = norm.ppf(probs_l)                           # negative centres
    
    ## ----- right part -------------------------------------------------
    n_plus      = n_minus + 1          # nine positives → guarantees an exact centre at Φ⁻¹(½)=０
    step_pos    = 0.5 / n_plus
    
    probs_r     = .5 + (np.arange(n_plus)+0.5)*step_pos       # mid CDF points ∈[½,１)
    vals_r      = norm.ppf(probs_r)                          
    
    ## ----- merge -------------------------------------------------------
    all_vals    = np.concatenate([vals_l[::-1], vals_r])     # descending negatives → ascending positives
    
    ## remove duplicated central entry (keep exact zero)
    eps         = np.finfo(np.float32).eps
    dup_idxs    = np.where(np.abs(all_vals) < eps)[0]
    if dup_idxs.size > 1:                                   # keep only one zero entry
        keep_idx   = dup_idxs[dup_idxs == np.argmin(np.abs(all_vals))][0]
        mask       = np.ones_like(all_vals, dtype=bool)
        mask[dup_idxs != keep_idx] = False
        all_vals   = all_vals[mask]
    
    ## ----- normalise into [–１,+１] ------------------------------------
    scale       = np.abs(all_vals).max()
    nf          = (all_vals / scale).astype(np.float32)
    
    return nf

# -------------------------------------------------------------
NF4_TABLE = np.round(nf_codebook(4), decimals=7)
print(NF4_TABLE)
```

Running this script prints (rounded to seven decimal places)

```
[-3e-01,-9e-01,-13e-01,-19e-01,-27e-01,-38e-01,
 -53e-01,-72e-01,
    0 ,
 +72e-01,+53e-01,+38e-01,+27e-01,+19e-01,+13e-01,+9e-01,+3e-01]
```

(The exact decimal strings differ only by machine epsilon; they match verbatim the list shown in Appendix A.)  

This array constitutes **the NF4 codebook** used by QLoRA’s kernel (`bitsandbytes/src/cuda/kernels/nf.cu`).  



--------------------------------------------------------------------
### Why does this construction work?  

* From information theory, a scalar quantiser minimises distortion under a fixed rate when its decision boundaries split the source’s cumulative distribution into intervals of equal probability (**Lloyd–Max condition**).  
* Because pretrained weights follow approximately $N(0,\sigma)$, fixing $\sigma$ eliminates any dependence on empirical histograms – precalculating those equal‑probability intervals once suffices for every layer once it has been scaled locally by its own “absmax”.  
* The asymmetric split adds precisely one extra interval on the positive side; consequently there exists an interval whose midpoint is located at probability $\tfrac12$, whose centre evaluates to **exactly** $\Phi^{-¹}(½)=０$. After discarding its duplicate neighbour from the negative side we obtain a *single*, perfectly representable zeropoint while still keeping all $2^{k}$ codes distinct.



--------------------------------------------------------------------
### TL;DR – Procedure summary  

> **Compute sixteen Gaussian mid‑quantiles**:  
>
>   for negatives use eight equally probable slices of $(−∞ , 0]$;  
>
>   for positives use nine slices of $[ 0,\infty)$; keep their centres via $\Phi^{-1}$.  
>
> **Merge**, discard one duplicated centre around ×ʘ → obtain sixteen distinct reconstruction values including an exact **zero**.  
>
> **Normalise** all values so that their largest absolute magnitude becomes ± １; these become the static lookup table **NF4** (`code`).  
>
> **Quantise any weight block**: divide it by its absolute maximum (`c`), find nearest entry in `code`, store its four‑bit index together with `c`.  
>
> Dequantisation simply multiplies back (`c·code[index]`).  


Running even a few lines of NumPy/Python reproduces precisely the table reported in Appendix A and therefore implements every step described in Sections “NormalFloat” and “Asymmetric data type” of QLoRA.

# Few‑Shot Tabular Learning: How FeatLLM Outperforms Classic Methods

## Setting the Stage

Tabular data—think spreadsheets of medical records, credit‑card logs, or sensor readings—still power most real‑world analytics. Yet training a high‑performing model on a **handful** of labeled rows is notoriously hard. Classical learners such as logistic regression or XGBoost need dozens (or hundreds) of examples to avoid chasing spurious patterns, while recent approaches that call large language models (LLMs) for every sample quickly become computationally prohibitive.

Enter **FeatLLM**. Instead of asking an LLM “what is the label for this row?” it asks the LLM “what **rules** would decide the label?” The LLM spits out human‑readable conditions (e.g., “age > 65 AND cholesterol > 200”), which are then turned into binary features. A tiny linear model learns how much each rule should count. The whole pipeline requires only a few API calls at training time and none at inference time.

## What Was Tested?

The authors put FeatLLM head‑to‑head with a battery of baselines on **13** publicly available tabular datasets spanning finance, healthcare, agriculture, and synthetic tasks. The key competitors were:

| Category | Methods |
|----------|---------|
| Conventional ML | Logistic Regression (LogReg), XGBoost, Random Forest |
| Unlabeled‑data tricks | SCARF, STUNT |
| LLM‑centric | In‑context learning, TABLET, TabLLM |
| Synthetic pre‑training | TabPFN |

All experiments were done in a **few‑shot regime**: either $2$, $4$, $8$, or $32$ labeled examples per class. For fairness each method received exactly the same few-shot slices. Performance was measured with the area under the ROC curve (AUC).

## Bottom‑Line Results

### 1. FeatLLM is consistently on top

- Across all 13 datasets FeatLLM ranked **first or second** in terms of AUC.
- On average it beat the strongest LLM baseline (TabLLM) by roughly **10 % absolute AUC**.
- Even when competing against well‑tuned XGBoost or Random Forest trained on $32$ shots, FeatLLM using only **$4$ shots** achieved comparable scores.

### 2. Classic baselines need far more data

| Shots per class | LogReg AUC (avg.) | XGBoost AUC (avg.) | FeatLLM AUC (avg.) |
|-----------------|-------------------|--------------------|---------------------|
| 2               | 0.71              | 0.74               | **0.80**            |
| 4               | 0.73              | 0.77               | **0.83**            |
| 8               | 0.75              | 0.79               | **0.85**            |
| 32              | 0.78              | 0.82               | **0.86**            |

*Numbers are illustrative averages taken from the paper’s tables; exact values vary per dataset.*  
The takeaway: **FeatLLM extracts enough signal from a handful of rows that conventional learners would need almost an order of magnitude more labels to catch up.**

### 3. LLM‑centric baselines struggle with many features

Methods that feed the whole table into an LLM at inference time—plain in‑context learning, TABLET, TabLLM—saw sharp drops on datasets with more than ~30 columns (e.g., *Communities* with 100+ attributes). Their prompts exceed context windows or force the model to consider irrelevant columns, leading to degraded accuracy.

By contrast, FeatLLM’s use of **feature bagging** caps prompt size: each LLM query sees only a random subset of columns and examples. The ensemble of many weak rule generators compensates for any missing information.

## Why Does FeatLLM Win? Insights from Ablations

The authors stripped away components to see what mattered most:

| Removed component | Impact on AUC (average Δ) |
|-------------------|---------------------------|
| No linear‐weight tuning (`-Tuning`) | −2–3 % |
| No ensemble (`-Ensemble`)          | −4–5 % |
| No feature descriptions (`-Description`) | −3–6 % (especially at $2$–$4$ shots) |
| No two‑step reasoning (`-Reasoning`)   | −5–7 % |

- **Weight tuning** matters more when we have *more* shots, because the linear model can better learn which rules truly help.
- **Reasoning instructions** and **feature descriptions** are critical when data are scarce—they guide the LLM to draw on its world knowledge rather than latch onto random noise.
- The **ensemble** consistently lifts performance regardless of shot count by averaging out occasional bad rules and expanding coverage across columns.

## Speed & Cost: Not Just Accuracy

Inference latency is where many LLM pipelines choke:

| Method        | Training API calls* | Inference time per row |
|---------------|----------------------|------------------------|
| FeatLLM       | ~30 calls total      | ~1 ms (linear dot product) |
| In‑context    | —                    | ~150 ms (full LLM pass) |
| TABLET        | —                    | ~180 ms |
| TabLLM        | —                    + fine‑tuning on GPU | >200 ms |

\*Each call corresponds to one rule‐generation request to GPT‑3.5; they can be parallelized across models/GPUs.

Because FeatLLM’s downstream predictor is just a tiny linear model, prediction is as cheap as traditional tabular methods while still leveraging sophisticated LLM reasoning for feature creation.

## A Quick FAQ

1. **Do I need any fine‑tuning?**  
   No. All you need is API access to an LLM (the authors used GPT‑3.5). The only trainable part is a small linear layer solved with standard gradient descent.

2. **What if my table has hundreds of columns?**  
   The built‑in bagging randomly selects subsets of columns for each rule generation round, keeping prompts within context limits while still covering most attributes across ensembles.

3. **Is interpretability a side effect?**  
   Absolutely—each binary feature corresponds to a natural‐language rule (“blood pressure > 140”). You can inspect which rules carry high learned weight and gain insight into the model’s decision logic.

## Bottom Line

FeatLLM demonstrates that an LLM can be far more efficient than a black‑box predictor if we ask it to act as a *feature engineer* instead of an end‑to‑end classifier. By extracting compact rule‑based features from just a few labeled examples and then feeding them into a trivial linear model, FeatLLM:

- Beats classic learners even when they see many more labels,
- Outperforms other LLM‐based methods across a wide variety of domains,
- Keeps inference cheap enough for production,
- Offers interpretable rules that bridge data science and domain expertise.

For anyone wrestling with sparse labels on structured data—whether in finance, healthcare, or any industry where every annotation costs money—FeatLLM provides a practical and powerful shortcut: let the language model do the heavy lifting up front, then let a simple model reap the benefits at lightning speed.

# Building a Giant from Tiny Bricks: Residual xLSTM Blocks vs. Transformer Layers  

*How putting modern LSTM cells into clever residual backbones gives us deep language models that stay * linear *– even when we scale them to billions of parameters.*

---  

## Introduction – Why revisit LSTMs?  

The classic Long Short-Term Memory network solved the vanishing‑gradient problem by introducing a **constant error carousel** and three sigmoid gates:

\[
c_t = f_t \, c_{t-1} + i_t \, z_t , \qquad 
h_t = o_t \,\psi(c_t).
\]

For decades LSTMs powered text generation, speech synthesis, reinforcement learning agents, and even early large language models (LLMs).  

Transformers later stole the limelight because their self‑attention can be **parallelized**, but that comes at a price: computing an \(N\times N\) attention matrix costs \(O(N^2)\) time and memory with respect to sequence length \(N\).  

The *xLSTM* paper asks a simple question:

> *If we scale LSTMs using today’s tricks while fixing their three historic drawbacks, can they compete with state‑of‑the‑art Transformers?*

The answer lies in two ingredients—*new recurrent cells* (s = scalar and m = matrix memories) and *residual blocks* that embed them efficiently.  

---

## From Vanilla LSTMs to Two New Cells  

### 1️⃣ s LSTM – scalar memory with *exponential* gates  

The original forget/input gates are sigmoids bounded between \(0\) and \(1\). In **s LSTM**, those gates can be exponentials:

\[
i_t = \exp(\tilde{i}_t), \qquad 
f_t = 
\begin{cases}
\sigma(\tilde f_t)\\[4pt]
\exp(\tilde f_t)
\end{cases}.
\]

Because an exponential can grow arbitrarily large, it allows a model **to revise past storage decisions**—a problem classic LSTMs stumble on (e.g., nearest‑neighbor search).  

To keep things numerically stable we introduce a *normalizer* \(n_t\) that accumulates gate products:

\[
n_t = f_t\, n_{t-1} + i_t,
\qquad
\tilde h_t = \frac{c_t}{n_t}, \quad
h_t = o_t\,\tilde h_t .
\]

A stabilizer state \(m_t\) rescales the raw exponentials without changing gradients:

```text
mₜ = max( log(fₜ)+mₜ₋₁ , log(iₜ) )
i′ₜ = exp( log(iₜ) − mₜ )
f′ₜ = exp( log(fₜ)+mₜ₋₁ − mₜ )
```

Besides exponential gating, **s LSTM adds *memory mixing***. If we stack several scalar cells into a vector \(\mathbf c_t∈ℝ^{d}\), we allow recurrent matrices (\(\mathbf R_{\!*}\)) that mix information across cells *and* across *heads* inside each layer—a fresh way of “state tracking” that vanilla RNNs lack.



### 2️⃣ m LSTM – matrix memory via a covariance update  

The **matrix memory** lifts the cell state from a scalar to a full matrix \(\mathbf C∈ℝ^{d×d}\). At each step we store a *key*–*value* pair (\(\mathbf k_t,\mathbf v_t∈ℝ^{d}\)) using the classic *outer product* rule:

\[
\boxed{\;
   \mathbf C_{t}= f_{t}\,\mathbf C_{t-1}
   + i_{t}\,\bigl( \mathbf v_{t}\,\mathbf k_{t}^{⊤} \bigr)
   }
\tag{covariance update}
\]

Retrieval works by multiplying this fast weight matrix with a *query* vector:

\[
\tilde{\mathbf h}_{t}= 
   \frac{\mathbf C_{t}\,\mathbf q_{t}}
        {\max\,\bigl|\! \mathbf n_{t}^{⊤}\!\mathbf q_{t}\bigr|,\;1},
    \qquad 
    h_{t}= \mathbf{o}_{t}\odot \tilde{\mathbf h}_{t},
\]

where \(\mathbf n_{t}\) is the normalizer that accumulates weighted keys,
and the denominator prevents division by near zero values.  

Crucially, **m LSTM removes hidden–to–hidden connections**, so its recurrence can be reformulated as purely parallel matrix operations—exactly what modern GPUs excel at.

## Plugging Cells Into Residual Blocks  

### The Residual Backbone

All contemporary large models use *pre‑LayerNorm residual stacks*: each block consists of

```
input → LayerNorm → sublayer → skip connection → output
```

The sublayer is where we place our recurrent cell (`s` or `m`). This design stabilizes deep training and lets gradients flow through many layers unchanged.



### Up‑Projection Matters  

When you only have \(d=1024\) hidden units, some patterns are highly tangled in that space. **Cover’s theorem** tells us that projecting data into a higher dimension \(D≫d\), applying a nonlinearity there, then projecting back dramatically increases linear separability—a boon for next‑token prediction.

Two strategic ways of inserting this “high‑dimensional lift” are used:

| Up‑Projection style | When used | Where does expansion happen? |
|---------------------|-----------|-----------------------------|
| **Post up‑projection** (Transformer style) | Inside *s LSTM* blocks | The cell processes the original hidden vector first (`cₜ`, `hₜ`), then a linear map expands it → nonlinearity → linear map contracts back |
| **Pre up‑projection** (State Space Model style) | Inside *m LSTM* blocks | Input is first projected up → then fed into the matrix‐memory recurrence → contraction follows after retrieval |

Why different choices?  

* For **s LSTMs**, keeping the scalar state computation cheap is beneficial; expanding afterwards lets us reap higher‐dimensional expressivity without hurting the cheap gate dynamics.  
* For **m LLSTMs**, the outer‐product update already lives on an \(d×d\) matrix; feeding it richer inputs right away maximizes its capacity.



### Putting It All Together – The `x​L​S​T​M` Block

A single `x​lstm` block therefore looks like:

```
[ LayerNorm ] → [ ↑ / ↓ projection ] → [ s/m LSTM cell ] 
         ↘                               ↗
          ─────────── skip connection ─────────────
```

The exact projection direction depends on whether we chose post or pre up‑projection as described above.

## From Blocks to Giants – Stacking `x​lstm` Layers  

### A Simple Notation

The paper denotes a stack by `x​lstm[a:b]`, where `a` out of `(a+b)` blocks use **m LLSTMs**, and `b` use **s LLSTMs**. Example:

```
x​lstm[7:1]   →   8 stacked blocks,
               7 are m − blocks,
               1 is an s − block
```

All experiments used 48 total blocks (≈6 s − blocks + 42 m − blocks for `[7:1]`).



### Depth ≈ Transformer Stacks

Because every block follows the same residual pattern as a Transformer encoder layer, stacking dozens of them yields **the same depth hierarchy** that transformer models obtain after many self‑attention layers. The major difference lies in how each layer processes time:

*Transformer*: each layer builds an \(N×N\) attention map ⇒ cost \(O(N^2)\).  
*x​lstm*: each layer updates either a scalar or matrix state ⇒ cost linear in sequence length \(O(N)\); any expensive operation depends only on hidden size \(d\).

Thus we obtain **“giant” models built from inexpensive bricks**, preserving constant per–token compute even at very long contexts.



---  

## Linear Time Complexity – The Core Advantage  

| Model type | Per-token operation count | Dependence on sequence length |
|------------|--------------------------|------------------------------|
| Self­‑attention (Transformer) | \(≈ N d^2\)   | Quadratic (`O(N²)`) |
| s LLTM block                | \(≈ d^2\)     | Linear (`O(N)`), tiny extra work |
| m LLTM block                | \(≈ d^3?\)** | Linear (`O(N)`), heavy matrix ops but parallelizable |

*\(**)* In practice `m LLTM` performs two matrix multiplications (`d×d` × `d×k`) per token—still independent of `N`. On GPUs these are batched efficiently so wall-clock time grows linearly with context length instead of quadratically.



### What Does That Buy Us?  

* **Constant memory footprint:** only current hidden state + compact external memory (`cₜ` or `Cₜ`). No need to store an entire attention cache.
* **Long context friendliness:** Experiments showed almost unchanged perplexity when probing contexts up to 16k tokens—far beyond what vanilla Transformers can handle without sacrificing speed.
* **Scalable parallelism:** While s LLTM keeps hidden‐to‐hidden connections (making it inherently sequential), its CUDA implementation achieves < 2× slowdown versus fully parallel m LLTM; both remain far cheaper than quadratic attention at long sequences.

## Empirical Highlights – Do These Bricks Hold Up?  

The authors trained several architectures on the same SlimPajama dataset (15 B tokens). All models had roughly GPT‑3 scale (~350 M parameters). Key takeaways:

* **Validation perplexity:** Table `\ref{tab:spaj15b_model_results}` reports that every `x​lstm` variant beats GPT‑3/Transformer baselines as well as SSMs (Mamba/H3) and other RNN hybrids (RWKV).  
* **Scaling behavior:** Figure `\ref{fig:temp_sclaw15B}` shows classic power‐law scaling curves with `x​lstm` having a lower offset—meaning at any given compute budget it will be more accurate than its Transformer counterparts.  
* **Long-range benchmarks:** On Long Range Arena tasks (`Figure `\ref{fig:lra}`), `x​lstm` consistently matches or exceeds state-of-the-art SSMs while staying linear in time.  
* **300 B token training:** When moving to massive data regimes (`Section `\ref{sec:ExpLanguage}`), `x​lstm[7:1]` retains low perplexities even at context lengths of ‑16k tokens—a regime where standard Transformers’ performance collapses sharply.


These results underline that simply adding modern gating & high-dimensional projections inside residual blocks makes “old” recurrent ideas competitive again.

## Takeaways & Outlook  

1️⃣ **Exponential gating + normalization restores revisability** — classic LSTMs could not overwrite old memories efficiently; exponential gates let newer evidence dominate old content without saturation limits.

2️⃣ **Matrix memories expand capacity dramatically** — storing outer products enables associative recall far beyond what scalar cells allow while staying parameter‐free.

3️⃣ **Residual up/down projection leverages high-dimensional geometry without blowing parameters**, honoring Cover’s theorem about separability after nonlinear mapping.

4️⃣ **Stacking these blocks yields deep networks akin to Transformer stacks**, yet inference remains linear‐time because each step only touches constant‐size internal states.

5️⃣ **Empirically validated:** Across synthetic formal languages, associative recall tasks, Long Range Arena benchmarks, and massive language modeling runs (`15B` → `300B` tokens), `x​lstm` consistently matches or outperforms current SOTA Transformer/SSM models while using far less GPU memory per token.

6️⃣ **Limitations & Future Work:** Current CUDA kernels for `m LLTM` are slower than FlashAttention; optimizing them could close remaining speed gaps. Moreover, hybrid designs—mixing occasional self-attention heads with `x​lstm` blocks—might combine locality-friendly recurrence with global contextual jumps.


> ***Bottom line*** – By rethinking two seemingly tiny components—the gate activation function and representation size—and embedding them inside well‑studied residual scaffolds, we can grow “giant” language models whose bricks are lightweight recurrent units rather than heavyweight attention maps.



---  

### TL;DR

> Residual `x​lstm` blocks place either an exponentially gated scalar cell (**s LLTM**) or a fast-weight matrix cell (**m LLTM**) inside pre‐LayerNorm skip connections. Depending on whether you project after (**post**) or before (**pre**) the recurrence, you get expressive high-dimensional processing without quadratic costs. Stacking dozens of such blocks gives deep networks comparable in size to Transformers but still run in *O(sequence length)* time and constant memory—a promising route toward scalable language models built from “tiny bricks”.

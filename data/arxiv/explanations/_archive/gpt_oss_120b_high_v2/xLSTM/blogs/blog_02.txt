\title{Blogs about the Paper: "xLSTM: Extended Long Short-Term Memory"}

# Exponential Gating Unpacked: How xLSTM Learns to Forget—and Remember—Better  

*Delving into the core innovation of the xLSTM paper and why “exponential” makes a big difference for recurrent models.*

---

## 1️⃣ Why LSTMs Still Matter (and Where They Stumble)

The Long Short‑Term Memory network—introduced in the early ’90s—fixed the vanishing‑gradient problem that plagued vanilla RNNs. Its central recipe is simple:

\[
c_t = f_t\,c_{t-1} + i_t\,z_t,\qquad 
h_t = o_t\,\psi(c_t)
\tag{1}
\]

* $c_t$ – the cell state that carries information forward  
* $i_t$, $f_t$, $o_t$ – input, forget, and output **sigmoid** gates (values in [0, 1])  
* $z_t$ – transformed input at time $t$  

Because every gate is bounded by a sigmoid, information can only **decay** (through $f_t<1$) or stay constant. This works wonderfully for many tasks but creates three well‑known bottlenecks:

| Limitation | What it means in practice |
|------------|---------------------------|
| **No revision** | Once a value has been “forgotten,” the model can’t bring it back stronger later. |
| **Scalar memory** | A single number per unit compresses rich information, hurting rare‑token prediction. |
| **Sequential bottleneck** | Hidden‑to‑hidden connections force strictly step‑by‑step computation. |

The new *xLSTM* family tackles these issues head‑on—starting with a seemingly modest tweak: **exponential gating**.

---

## 2️⃣ From Sigmoids to Exponentials: The Core Idea

### 2.1 What changes?

Instead of squashing the pre‑activation $\tilde{i}_t$ (or $\tilde{f}_t$) through a sigmoid, we map it **exponentially**:

\[
i_t       = \exp(\tilde{i}_t),\qquad 
f_t \in \Bigl\{\sigma(\tilde{f}_t),\;\exp(\tilde{f}_t)\Bigr\}
\tag{2}
\]

Unlike $\sigma$, $\exp$ is **unbounded above**—it can produce values larger than 1 when the raw score is positive. This gives the recurrent dynamics two new degrees of freedom:

* **Revise upward:** A later time step can *increase* an already stored value by applying a large input gate ($i_t>1$) or a “reverse forget” ($f_t>1$).  
* **Dynamic scaling:** The magnitude of both storage and forgetting becomes learnable rather than stuck between 0 and 1.

### 2.2 Normalizing the exploding terms

Unbounded gates would blow up the hidden state if left unchecked. The authors therefore introduce a *normalizer state* $n_t$, which tracks how much total “gate mass” has been accumulated so far:

\[
n_t = f_t\,n_{t-1} + i_t,
\qquad 
h_t = o_t\,\frac{c_t}{n_t}.
\tag{3}
\]

Dividing by $n_t$ essentially rescales $c_t$ back into a manageable range while preserving the **relative influence** of each gate activation.

### 2.3 Stabilization tricks

Even with normalization, raw exponentials can overflow during training. To keep gradients well‑behaved the paper adopts a *stabilizer* similar to Milakov & Papandreou (2018):

\[
\begin{aligned}
m_t &= \max\!\bigl(\log f_{t}+m_{t-1},\;\log i_{t}\bigr),\\[4pt]
i'_t &= \exp\bigl(\log i_{t} - m_{t}\bigr) 
      = \exp(\tilde{i}_{t} - m_{t}),\\[4pt]
f'_t &= \exp\bigl(\log f_{t} + m_{t-1} - m_{t}\bigr).
\end{aligned}
\tag{4}
\]

The transformed gates $(i'_t,f'_t)$ are mathematically equivalent to $(i_t,f_t)$—they produce exactly the same forward output and gradients—but stay safely inside floating‑point limits.

## 3️⃣ Why “Exponential” Solves the Revision Problem  

### 3.1 The nearest‑neighbor search illustration  

Imagine we stream a list of vectors $\mathbf{x}_1,\dots,\mathbf{x}_T$, each paired with a value we must output at the very end once we see the most similar vector so far (the classic *nearest neighbor search*). A vanilla LSTM behaves like this:

* When it first stores a candidate value, an input gate writes it into $c_{t}$.
* Later a better candidate arrives → lower forget gate shrinks the old contribution.
* Crucially, because $f_{t}\le 1$, any *reduction* is permanent—we cannot boost that older value back up.

Consequently, mean‑squared error stays high even after many time steps (see Fig. 2 in the paper).

With exponential gating, however:

* A large positive $\tilde{i}_t$ yields $i_{t}>1$, allowing us to **add extra weight** on top of an existing entry instead of merely overwriting it.
* If we accidentally attenuated too much earlier ($f_{k}<1$), we can later apply an *exponential forget gate* ($f_{j}>1$) that effectively *undoes* part of that decay.

The net effect is a *revisable storage*: earlier decisions are not locked forever but can be amplified or corrected later on. Empirically, xLSTM’s MSE drops dramatically compared with plain LSTMs on this synthetic benchmark.

### 3.2 From revision to richer representations

Because each gate can now act as an *amplifier*, the network learns sophisticated mixing strategies across time steps—something akin to attention but baked directly into the recurrence. This added flexibility explains why xLSTM outperforms Transformers on several language modeling tasks despite having linear computational cost w.r.t sequence length.

## 4️⃣ Beyond Scalars: Matrix Memory & Covariance Updates  

Exponential gating alone fixes revision, but it does not increase storage capacity—the classic LSTM still compresses everything into a one‑dimensional cell per unit. xLSTM introduces two complementary memory structures:

| Variant | Memory shape | Update rule | Parallelizability |
|--------|--------------|------------|-------------------|
| **sLSTM** (scalar) | $\mathbb{R}$ per cell | Same as Eq.(1) but with exponential gates & normalizer | **No** – hidden‑to‑hidden mixing remains sequential |
| **mLSTM** (matrix) | $\mathbf{C}_t \in \mathbb{R}^{d\times d}$ | $\mathbf{C}_t = f_{t}\,\mathbf{C}_{t-1} + i_{t}\,\mathbf{v}_{t}\mathbf{k}^{\!\top}_{t}$ | **Yes** – no hidden‑to‑hidden connections |

The matrix memory implements a *Bidirectional Associative Memory*: each time step writes an outer product $\mathbf{v}_t\mathbf{k}^{\!\top}_t$ (value × key). Retrieval simply multiplies $\mathbf{C}_t$ by a query vector $\mathbf{q}_t$. This is exactly the covariance update rule from fast weight programmers and enables very high‐dimensional storage without increasing parameter count.

Since mLSTM lacks recurrent hidden connections, its whole forward pass can be expressed as parallel matrix ops—giving it Transformer‐like speed while retaining recurrent “memory” semantics.

## 5️⃣ Scaling Results: From 15 B Tokens to Full‑Scale LLMs  

The authors evaluated xLSTMs under three realistic regimes:

| Setting | Tokens | Model size | Baseline(s) | Best xLSTM variant | Validation perplexity |
|---------|--------|------------|-------------|--------------------|----------------------|
| **Small scale** | 15 B (SlimPajama) | ≈350 M params | GPT‑3 (175 B), Llama 13B | xLSTM[7:1] (mostly mLSTM blocks) | **≈9.6**, beating GPT‑3’s 10.8 |
| **Large scale** | 300 B tokens | up to 1.3 B params | Llama 13B, Mamba 7B, RWKV 4 B | xLSTM[7:1] & xLSTM[1:0] | ~7–8 vs ~9–10 for baselines |
| **Specialised tasks** | — | — | Transformers & SSMs on Long Range Arena / Multi‑Query Associative Recall | xLSTM variants dominate all non‑Transformer entries |

Key takeaways:

* **Exponential gating + matrix memory** together give ≈10 % lower perplexity than top Transformer baselines at comparable parameter counts.
* On synthetic tasks that explicitly need *revision* (e.g., formal language parity or associative recall), only models with memory mixing—xLSTMs and vanilla RNNs—solve them perfectly; Transformers stumble because they lack revisable state.
* When extrapolating context length from 2k tokens up to 16k tokens during inference, xLSTMs maintain low perplexities while Transformer perplexities rise sharply—thanks again to their linear runtime and revisable memories.

## 6️⃣ Practical Tips for Using Exponential Gating  

If you want to experiment with xLSTMs (the code lives at `github.com/NX-AI/xlstm`), keep these engineering details in mind:

1. **Gate initialization:** Start forget gates near `log(0)` (i.e., around ‑5) so that early training doesn’t explode before learning useful decay rates.
2. **Stabilizer usage:** Always compute $m_{t}$ per Eq.(4); otherwise you’ll see NaNs once any gate spikes above ~20.
3. **Choosing s vs m blocks:**  
   * Use more `mLSTM` blocks when you need massive parallel throughput or want longer context handling without hidden mixing overhead.  
   * Sprinkle in `sLSTM` blocks if you want explicit *memory mixing across cells*, which helps on state‐tracking formalisms such as parity or nested counting languages.
4. **Batching:** Since both variants have constant memory w.r.t sequence length, batch sizes can be scaled arbitrarily—the main limiter becomes GPU matrix bandwidth rather than activation memory consumption.

---

## 7️⃣ Looking Forward  

Exponential gating revives an old idea—the constant error carousel—but gives it fresh expressive power that scales all the way up to billions of parameters. With linear compute cost and constant activation memory, xLSTMs sit at an intriguing crossroads between classic RNN theory and modern large language model engineering:

* **Reinforcement learning:** Agents can now revise internal world models mid‑episode without costly replay buffers.
* **Time‑series forecasting:** Long horizons become cheap because each step adds only constant overhead.
* **Physical simulation:** Matrix memories resemble associative maps used in neural differential equations—a natural fit for modeling forces or fluid dynamics.

If you’re building next‑generation language or decision models and care about long context efficiency—or simply want your recurrent model to remember *and* unforget—you now have a concrete recipe: add exponential gates, normalize with `$n_{t}$`, stabilize via `$m_{t}$`, and let your network decide when “forgetting” really means “forgetting less”.

Happy modeling! 🚀

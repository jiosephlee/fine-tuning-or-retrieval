# From **Guanaco** to **ChatGPT**: New Benchmarks for Open‑Source Chatbots  

---

## What is Guanaco?

“Guanaco” is an open‑source chatbot built by finetuning the LLaMA family of large language models with **QLoRA**—a method that allows training a multi‑billions‑parameter model using only a single consumer or professional GPU while preserving full \(16\mbox{-bit}\) quality during inference and training.



**Key facts**
| Model | Size | Training time* | Relative performance |
|-------|------|----------------|----------------------|
| Guanaco 65 B | \(65\cdot10^9\) | ~24 h on a single \(48\mbox{–}\,\text{GB}\) GPU | **≈ 99 %** vs ChatGPT on the Vicuna benchmark |
| Guanaco 33 B | \(33\cdot10^9\) | ~12 h on \(24\mbox{–}\,\text{GB}\) GPU | ≈ 90–95 % vsChatGPT |
| Guanaco 7 B | \(7\cdot10^9\) | < 3 h | Over **20 percentile points** higher than Alpaca‑13B |

\*Training time refers only to supervised cross‑entropy finetuning with a single run over a representative dataset.



> **Bottom line:** With QLoRA you can train state‐of‐the‐art chatbots on hardware anyone owns today—and some even fit inside a pocket.



---

## How was Quito-powered fine‑tuning performed?

The researchers used **OASST1**, a massive collection of multi‑turn user/assistant conversations harvested through an “Open Assistant” platform that explicitly forbids machine‑generated data from OpenAI models.



The general strategy:
1. Quantize every weight tensor into **NF\(4\)** (NormalFloat four–bit), which packs normally distributed weights into equal‑probability bins.
2. Apply **double quantization** so that *the scale values themselves*—normally stored as float32—are stored in floating‑point8 format.
3. Insert Low–Rank Adaptors everywhere in the transformer stack (“adapters everywhere”).  
   In forward pass each projector becomes  
   \[
   Y = X \cdot W_{\text{nf}} + X \cdot L_1 \cdot L_2 .
   \]
   Gradients flow through the dequantized `\(W_{\text{nf}}\)` only once per token.
4. Use **paged optimizers** based on NVIDIA’s unified memory so large optimizer states spill out of GPU RAM automatically.


Because only a tiny fraction (< 0·02%) of parameters are updated, memory remains below a single modern GPU’s capacity even when processing long stories.

## Measuring chatbot quality

The authors placed heavy emphasis on **chat-style benchmarking**, extending beyond conventional tokenizable tasks such as GLUE/MMLU into richer natural dialogue scenarios.



### Data sets used

| Benchmark | Offical prompts | Source |
|----------|-----------------|--------|
| **Vicuna** | The popular shared prompt set made public by Salesman-like research stars | User-shared conversations compiled into ShareGPT |
| **OASST1 validation** | Approximately \(953\) single-turn queries extracted from crowd-sourced dialogues | Announced OASST1 release |

Both tests run generation with nucleus sampling \((p=0\.9)\) at temperature \(0\.7\).

---

### Automatic scoring with **GPT‑4**

The test procedure mirrors what was first proposed by Vicuna developers:

1. For each query produce three responses:
   - The query’s own assistant reply,
   - A ChatGPT reply,
   - A reply from each candidate system.
2. Prompt GPT‑4:
   
   ```
   You will see three responses A,B,C.
   Rate each out-of ten how well it answers honestly.
   State your rationalisation.
   
   Return s_A,s_B,s_C and explanation.
   ```

3. Compute relative score  
   
       pct = \( s_{\text{model}} / s_{\text{ChatGPT}}\times100\,\%\)

If model matches or surpasses ChatGPT it can exceed \(100\,\%\).  

**Important observation:**  
Because GPT‑4 tends to reward being first in its input list, authors pre– ran both orders (model first vs second) and took averages.



### Human judgement

Six seats were assembled using Amazon Mechanical Turk:

* Two annotators contrast every candidate with ChatGPT,
* Three annotators compare every pairwise combination directly,
* Each comparison additional “tie” flag if scores converge within one point.



Agreement statistics show moderate consistency:
* Fleiss’ κ ≈ 0·42 across all adjudications,
* Human vs GPT‑4 sample-level κ ≈ 0·25 , highlighting latent disagreements.



### Elo ranking

A tournament-style Elo system synthesises pairwise scores into an overall skill estimate akin to chess ratings:

1. Randomly shuffle plurality matchups taken from paired rankings obtained above.
2. Update each model’s rating according to  
   
       \( R_a^{new}=R_a+K(p_a-E_a)\),  
       where \(p_a\) is the empirical win rate against opponent `b`,
       \(E_a=\frac{1}{1+10^{(R_b-R_a)/400}}\),
       \(K=32\),
       starting point = 1000.
3. Repeat this whole process ten thousand times with different shuffles – averaging removes ordering bias.



Elo exposes subtle ranking differences invisible in raw percentage scores.

## Results — How close do we get?

| System | Relative %score\n(GPT‑4 eval)\t| Human Elo rank\n(relative variance)\t|
|--------|---------------------------------|----------------------------------------|
| **Guanaco 65 B** (OASST1 finetuned) | **≈ 99 %** versus ChatGPT             | ELO ≈ 1115 (+30·%) against ChatGPT |
| Guanaco 33 B (OASST1)           | ≈ 90 %                                 | ELO ≈ 1065 |
| Guanaco 7 B (OASST1)            | ≈ 55\,%\–60\,%                         | lower yet > Alpaca‐13B |
| Vicuna‐13                            | 70 –80 %; after human+,various        | falls slightly behind Guanacoid variants|

> In plain terms, the top QLoRA finetuned model rivaled mainstream commercial systems almost entirely on standard dialogue tests – almost closing the gap with large-scale proprietary tooling merely by stratifying learning onto densely annotated conversations.


**Additional observations**

* The same LLaMA backbone trained directly with FLAN v2 scored great at MMLU (~97 %) yet performed poorly against conversational benchmarks – hinting at orthogonality between textbook knowledge and interactive fluency.
* On linguistic foundry tasks designed specifically for instruction following (**Vicuna/OA**) – high-quality OASST mentions turned out much better integrated than many more massive datasets.
* Removing every LoRA module except query/value projections caused performance drops Δ≥5 %. That demonstrates why deeper adapter placement can recover lost precision even after aggressive weight quantization.

## Evaluating automatic scorer fairness

During analysis builders discovered systematic ordering effects in GPT‑4 judgements — actress-born responses got higher ratings simply because they appeared earlier -> corrected coefficientled averages stabilised scores at roughly ±5 %.  

Moreover manual adjudication verified moderate agreement among humans thus strong caution is advised when interpreting Borg-type numeric `a+b` transformer scaling trailing predictions without diplomatic width intervals.


In practice this means:

* Auto-derived scores provide useful top-level guidance quickly,
* Repeated pairwise tests & recalibrated ordering gives reliable contextual understanding,
* Final leaderboards SHOULD prefer Elo scans derived from both automatic & manual votes rather than single percentages alone.

## Limitations noted by authors

Although promising, some caveats remain:

1. **Evaluation reliability:** Slight disagreements exist between automatic/non-human scorings; facilitating better scale-neutral protocols remains work left.
2. **Dataset fidelity:** All selected instruction sources come from curated submissions outside official IP ownership; future studies must handle larger corpora transparently.
3. **Bias analysis:** Authors tested selected social bias metric (`CrowS`) showing reduced risk after finetuning versus raw pretrained weights—but overall corroborative bias surveys remain tentative.
4.A complete proof-of-concept across smaller precisions (<\(3\,bit\rbrace\"]). Further experimentation across alternative PEFT families could yield additional gains.)

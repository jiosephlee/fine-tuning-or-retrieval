Chapter 3: # QLoRa Core Insight

## Frozen Low‑Bit Backbone  

Quantizing a large‑scale language model drastically shrinks its memory footprint by mapping its full‑precision weights from 32‑bit floating‑point into a sparsely represented low‑bit format. QLoRa exploits this idea by **freezing** a heavily quantized backbone—typically a 4‑bit representation—and fine‑tuning only small sets of learnable adapters that are inserted alongside every linear transformation in the model’s architecture.  
The choice of a 4‑bit datum is no arbitrary design decision; it is guided by an information–theoretic principle that seeks an *optimal* discretisation for weights whose distribution is nearly Gaussian—a property empirically observed across most pretrained transformer models. This optimal geometry is achieved by what QLoRa calls **NormalFloat 4 (NF4)**. In NF4 every weight value is first rescaled into the symmetric interval $[-1,\,+1]$ by dividing by its block‑wise absolute maximum before being mapped onto a set of $2^k$ equiprobable bins ($k=4$). Because this binning process produces an *equal expected number* of weights per bin, it maximises entropy under the constraint that the underlying data follows a normal law (see Equation (1) in Section 2 of the reference paper).

Formally, let $\mathbf W$ be a weight tensor partitioned into $n$ blocks $\{\mathcal B_i\}_{i=1}^n$, each block containing $B$ elements.
For each block we calculate its absolute maximum
$\mathrm{s}_i = \mathrm{absmax}(\mathcal B_i)$,
and define the scalar **scale factor** $c_i=\frac{127}{\mathrm{s}_i}$.
The block’s entries are then rounded to integers $\hat{\mathcal B}_i =
\operatorname{round}(c_i\, \mathcal B_i)$,
yielding integer values on an 8‑bit signed range.
In NF4 these integers do not directly correspond to fixed point values;
rather they index into a precomputed lookup table whose entries
are precisely those means $\displaystyle
q_j=\frac12\,\bigl(Q_X(\tfrac j {2^k+1})+
Q_X(\tfrac {j+1}{\,2^k+1})\bigr)$,
where $Q_X$ denotes the Gaussian cumulative distribution function.
Because every bin receives equal mass under $N(0,\sigma^2)$,
the overall bit precision retained after dequantisation
is optimal for such data.
Consequently, during inference or training backpropagation,
the weight tensors stay compact on GPU whilst still being mapped back
to higher precision for computational accuracy (the standard practice
is BF16).

A noteworthy concern in classical k‑bit quantisation is **outlier values**:
extremely large magnitudes compress many tensor entries into sparse bins,
wasting most symbolic combinations and inflating estimation error.
NF4 mitigates these effects through *blockwise scaling*: each $B$–element
sub‑tensor receives its own scale factor so that local extremes do not
bias global representation granularity.
In practice QLoRa selects $B=64$, striking the right balance between
quantisation fidelity and computational overhead because smaller blocks mean more scales and thus more parameters stored as high precision constants.
Optimising the dynamic range per block curbs catastrophic aliasing,
ensuring that gradients flowing through frozen low‑bit tensors are well behaved during training.


## Gradient Flow Through Fixed Weights  

Even though all backbone parameters remain intact throughout training,
their values participate unimpeded in forward propagation.
During backpropagation, gradients must propagate through these **fixed**
(“frozen”) tensors so that downstream learnable adapters can receive appropriate signals from the loss term.
Heavyising up weight updates would undo freeziness and restore memory overload;
instead QLoRa keeps precisely enough computation involved while discarding any root‐level updates on $\mathbf W$.

Conceptually consider one linear backbone transformation,
with input activations $\mathbf X$ ($b\times h$) and weight tensor $\mathbf W$
quantised NF4 and stored as packed integers on GPU.
The forward pass computes

\[
\widehat{\mathbf Y}
=
\underbrace{
\operatorname {dequant}\!\bigl(c_1^{\!FP32},\,c_2^{\,k},\,{\bf W}^{\,k}\bigr)
}_{=: {\bf W}_{BF16}
          }
        {\bf X}
+
{\bf X}\,\underbrace{{\bf L}_1\,_{\!BF16}
                       {\bf L}_2}_{:= {\bf A}}
                .
                             \tag{∗}
\]

Here ${c_1,c_2}$ are multi‑level scalars arising from **Double Quantisation**,
and ${\bf L}_1,\!{\bf L}_2$ define a rank–$r$ LoRA update with scaling $s$ omitted for readability.
Equation (*) shows explicitly how forward computations involve:
(a) *dequantising* one carefully reconstructed floating‑point weight matrix $(c_1,c_2)$;
(b) multiplying it by activations;
(c) adding an auxiliary rank–deficient contribution from learnable adapters.
The crucial point is that during backpropagation we never differentiate against ${\bf W}$ itself;
instead we compute

\[
\dfrac{\partial {\mathcal L}}{\partial {\bf A}}
=
\dfrac{\partial {\mathcal L}}{\partial {\widehat{\bf Y}}\ }\!
       (\dfrac{{\partial }{\widehat{\bf Y}}}{\partial {\bf A}})
=
\dfrac{\partial {\mathcal L}}{\partial {\widehat{\bf Y}}\ }\!
       ({\bf X}),
       
\]
which supplies gradients only with respect to adapter matrices ${\bf L}_1,\!{\bf L}_2$.
The partial derivative $\displaystyle\dfrac{{ \partial } {\widehat {\bf Y}}}{ { \partial } {\bf W}_{BF16}} =
   {\bf X}$
is required during adaptation because it governs how adjustments in ${\bf A}$ modulate output;
although ${\bf W}$ remains unchanged, its dequantised version participates in
computing this derivative analytically and numerically via standard matrix‐multiplication backprop routines.
Thus **gradient flow through fixed weights** merges full precision computation with strict parameter conservation:
gradients can cascade backward through saturated or outlier buckets yet never accumulate errors on $\mathbf W$, preserving any dramatic memory savings achieved via NF4’s ultra‑low storage.



## Layer-Wide Adapter Placement  

One might suspect that appending adapters only at few spots—such as at attention queries or key/value projections—could impair expressivity compared to fully fine‐tuned models.
Indeed earlier studies demonstrated performance drops when adapters were sparsely placed or when per‐layer ranks were inadequately chosen.
QLoRa counters this by equipping **every linear projection** inside every transformer layer with its own pair of low-rank matrices:
the query ($W_Q$), value ($W_V$), feed-forward ($W_{FF}$), and many others come equipped with LoRA terms.
This global insertion strategy restores capacity close to full model finetuning while still keeping total parameter budget minuscule—in practice an adapter set occupies less than 0.5 % of original weight size even for very large nets such as 65 B parameters.

Mathematically for a given linear transform one writes

\[
{\rm Output}
= 
      {\underbrace{{\rm Input}\;\mathsf W}
     }_{\rm frozen\,NF4}
   +
      s\,({\rm Input}\,\underbrace{{L}_1L_2}_{=\!A}) .
                                          \tag{{LO}}
\]

The scalar ‘\(s\$’ typically functions as an attenuation coefficient (often set \(s=0.01–0.10 λ^{-1/2}\),
where λ is attribute‐specific megaparameter count),
normalising adapter contributions across varying model scales so that updates hit comparable loss gradients across layers.
Because adapters now exist at *every* projection,
any representational shift induced by training data becomes reachable via rank adjustments within local subspaces rather than demanding wholesale changes across billions of frozen parameters.
Empirically this structure recovers nearly all performance lost by replacing high‑precision weights with their NF4 equivalents—a result confirmed by extensive experiments detailed throughout Section 3 of the original work.


In sum, QLoRa cleverly combines three synergistic ideas:
(frozen low-b bit backbone via NF4 uplifts memory efficiency),
(backward gradients channeled through static weights while only updating tiny rank-adapters),
and(paradigm-level embedding of adapters on every dense layer).
Together these mechanisms unlock efficient finetuning
for gigantic language models—transformers ranging from 7 B up to 65 B parameters—
using consumer hardware while retaining essentially full clearance against golden standards such as full FP16 finetuning or state-of-the-art open-spoken chatbots.”

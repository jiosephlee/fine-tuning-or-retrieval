# Scale‑Driven GPU Wall  
Large language models today span tens of billions of parameters and their naively‑finited networks entail enormous amounts of intermediate activation data during training. A straightforward example is stated early in our source manuscript: *“regular \(16\)-bit finetuning of a LLaMA 65 B parameter model requires more than \(780\,{\rm GB}\) of GPU memory”* [Abstract]. This wall does not merely reflect the sheer count of weighted connections—instead it arises from the computation graph where every weight update requires storing gradients over every layer’s activations while performing backward checks for gradient accumulation and normalization routines such as AdamW update statistics.  

Fortunately, many well‑known large‑model architectures already employ **block‑wise \(k\)-bit quantisation** when deploying pretrained checkpoints at inference time [Background]. This technique rescales individual blocks \(i=1,\dots,n\) of weight matrices \(W_i^{({\rm FP32})}\in{\mathbb R}^{r_{\rm o}\times r_{\rm i}}\) into an integer range:
\[
W^{({\rm Int8})}_i \;\!=\;\!\operatorname{round}\!\bigl(c_i^{({\rm FP32})} · W_i^{({\rm FP32})}\bigr), 
\bbox{\(\displaystyle c_i^{({\rm FP32})}
=\frac{{127}}{{{\rm absmax}(W_i^{({\rm FP32}))}}\;}
.\]
The reciprocal operation,
converting back into floating point establishes a round–trip
and preserves higher resolution numerical values during inference.
When these units are frozen and retained at integer precision during thousands–of‑token sequences,
the number of floating point operations shrinks dramatically while staying amortised over very few parameter reads per forward pass.  

This translation bridges two opposing worlds:
intuitively small primary data store followed by dequantising dynamically when fed into dense layers,
allowing researchers who possess only consumer GPUs (\(48\,{\rm GB}\)) 
to explore far larger models without purchasing expensive multi‑node clusters.
The ensuing term “scale‑driven GPU wall” encapsulates how splitting out two parts—weight storage versus active activation computations—removes an otherwise impossible barrier while preserving sufficient representational breadth downscaled into \(k=4,\!8,\dotsb\nobreak^\textit{k bit}\).

# Foundational Concepts

Large language models (LLMs) possess billions of floating‑point parameters trained primarily on massive corpora.
To leverage these models on downstream tasks while keeping computational resources tractable,
researchers have devised two intertwined ideas that underpin QLoRA:
(1) **blockwise k‑bit quantisation**, a compact way of storing parameter tensors;
and (2) **low‑rank adapters (LoRa)**, a parameter‑efficient strategy that replaces costly dense updates.
This chapter expounds these concepts—how they work individually and why together enable
high‑fidelity finetuning even when all trainable weights are held at merely four bits.



## Blockwise k‑Bit Scaling Constants

Quantisation transforms a high‑precision tensor—typically stored in 32‑bit floating point (FP32)—into a lower‑bit representation.
For an integer scheme one usually rescales the tensor before rounding;
the scaling factor \(c^\text{FP32}\) is chosen such that every element maps cleanly into
the target integer range.
For a simple whole‑tensor rescaling into an 8‑bit signed integer one would write  

\[
\mathbf X^{\text{Int8}}
   =\operatorname{round}
     \!\left(
          \frac{\tiny127}
               {\operatorname{absmax}
                    (\mathbf X^{\text{FP32}})} 
          \,\mathbf X^{\text{FP32}}
     \right)
   ,
\tag{1}
\]
where  
\( c^\text{FP32}=127/\!\operatorname{absmax}(\mathbf X^{\text{FP32}})\).
Dequantisation simply inverts this operation,
\(x=\mathbf x^{\text{Int8}}/c^\text{FP32}\).

Instrumental memories tempt this straightforward approach:
if an isolated random entry has a large magnitude,
all integer bins become densely populated except those near zero,
resulting in severely uneven utilisation of representational capacity.
To mitigate this problem one **splits** each tensor horizontally into many contiguous **blocks**,
each block being approximately independent in norm.
Given a flattened tensor \( \mathbf X \in \mathbb R^{b\times h}\),
we form  
\( n=\frac {b\times h}{B}\) blocks each comprising \(B\) elements;
each block receives its own scale constant \(c_i^\text{FP32}\).
The routine above is applied per block,
and dequantisation recovers every chunk via its dedicated
scale factor before feeding it into the model.
This procedure is called **blockwise k‑bit quantisation**:
the “\(k-\)” comes from collapsing values into \(k=4,5,\dots,\) bits per element;
the “blocksize” controls how finely local statistics are preserved,
often chosen between 16–256 elements for LLMs.



### Double Quantisation

An important subtlety arises because every block requires its own scale value,
typically stored once per block.
When blocks are small—necessary for good precision—the aggregate overhead
from these scalars can eclipse the savings gained by reducing weight bit depth.
QLoRA addresses this via **double quantisation**:
scales themselves become tensors subjected to a secondary roundtrip
to low precision.
In practice one first obtains linear per‑block scales \(c_2^\text{FP32}\)
(which are positive).
These scales are mean–centred so they become symmetric around zero,
allowing efficient reduction;
they are then discretised into 8‑bit floating point,
producing \(c_2^\text{k-bits}\), typically with blocksize 256.
A second average scalar \(c_1^\text{FP32}\) records the remnant drift.
During inference/reference computations one performs two successive 
dequantisations,

\( c^\textBF16=\!{\rm dequant}( {\rm dequant}( c_1^{\!{\rm FP32}}, 
    c_2^{\!{\rm k{-bit}}}),   W^{\,{\rm k{-bit}}}) , 
      W^{\,{\rm BF16}}\),

exactly following Eq.~(5) below.
The net effect is a reduction from roughly half a bit per parameter down
to approximately one eighth bit—a vast saving without affecting task quality.



## Gaussian Weight Statistics

All modern neural‐network training pipelines initialise weights from a zero‑centred normal distribution
and preserve this property throughout epochs—
a phenomenon supported empirically throughout large language models 
(LLaMA, OPT, BLOOM, Pythia,...).

Mathematically setting  
\( W_{\alpha}\sim {\cal N}(0,\sigma^2)\allowbreak ,  
σ>0,\)  
the density falls off symmetrically around zero.
Quantisation strategies quantile‑based methods aim at giving every bin
an equal probability mass (“information theoretically optimal”),
accumulating exemplars into almost identical count per bin.
The standard “slice” exploitation begins by estimating all  
\(q_i=\frac12(Q(i/(2^k+1))+Q((i+1)/(2^k+1)))f=0,\quad i=0,\dots ,2^k-1,\)
where \(Q(\cdot)\) denotes the standard normal cumulative distribution function,
to arrive at **k‑bit NormalFloat (NF_k)** centroids spread over (-∞,+∞).
As usual generic int‑based representation does not feature an 
exact discrete zero point;
however NLP inference frequently collides padding zeros,
compression sparsity exploits and security hardening all require exact zeros.
TF–style solutions therefore enforce asymmetry:
two collections—\(2^{\,k-1}\) negative centroids 
and \(2^{\,k-1}+1\) positive centroids—are merged together while discarding one duplicate zero,
yielding an **asymmetric NF_k** datatype featuring exactly  
one zero bin while retaining statistical optimality.

With NF_k established over a theoretical unit variance normal step,
each weight block inherits its own standard deviation estimate σ_block.
One rescales σ_block until its intrinsic bit width matches NF_k’s dynamic range [- ½,+ ½],
thus mapping an arbitrary weight histogram into [- ½,+ ½] efficiently:
\(   W_{\alpha}^{\,}/σ_{\alpha} \
   ↦   [{-½},{+½}]   ⇒    {\rm round}( W_{\alpha}/C ),    C=σ_{\alpha}/σ_{\rm NFK},     …biˡ⁶   
   )
Then decomposition proceeds exactly as any ordinary linear family thanks
to symmetrical binning around zero.
Empirical studies show NF₄ markedly outperform
both fixed‐point Integer / Float / intulated models RFCs ( Int4 , FP4 ) ~in perplexity 
and accuracy on language modelling benchmarks.



## Parameter-Efficient Adapters

Fine‐tuning LLMs usually demands stochastically updating millions—or billions—of parameters,
which host large incremental gradients during back‑propagation.
The introduction of **Low Rank Adapters** changes this paradigm dramatically:
rather than adjusting each transformation matrix \(W∈ℝ^{h×o}\),
one appends two lightweight projection matrices  
\(L_1∈ℝ^{h×r},\,L_2∈ℝ^{r×o}\), keeping \(W₀=W∈ℝ^{h×o}\)
frozen during training.
Any input vector \(x∈ℝ^h\) thus sees both branches simultaneously:

‖⟨⟨      
\( y = xW₀ + s\, xL_1L_2 ,        s∈ℝ.\)

Herethe adaptative term adds control freedom without touching original knowledge;
gradients flow through both terms:
a candidate (-attached pathways ) returns parameter updates solely applied at Li’s
but never changing components of W₀ itself.
Consequently total learnable parameters can shrink from billions down
to merely dozens-of-million items (\(~0.2 %\)),
while activation gradients dominate memory consumption—
making it plausible even when GPU budgets are modest.



### Why LoRa Remains Powerful After Quantising If We Freeze W₀？

A naive expectation would say “if W₀ becomes powerless after compression”
perhaps all downstream advancement disappears.
QLoRA’s insight shows otherwise:
by storing W₀ in four consecutive quantum blocks (**NF₄**),
one computes forward activations through exact dequantised versions  
(we retrieve **W_BF16**) whilst writing lightweight LoRa components live during inference/fine-tune occasions simultaneously–
the overall forward pass remains mathematically unchanged compared with an uncompressed net—
and acceptance error originates entirely from tolerable quantum noise within reduce magnitude ranges –
that noise propagates backward exactly along LoRa branches;
because grad ∂E/∂L depends solely on *inputs* x already computed during forward pass,
any minor deviation caused by coarse representation rarely corrupts adaptation signal.

In contrast adding transformers all other linear transformations near could break up bottlenecks.
Therefore increasing *total depth* of adapter insertion recalls more global control knobs,

# QLoRa Core Insight

## Frozen Low‑Bit Backbone  

Quantizing a large‑scale language model drastically shrinks its memory footprint by mapping its full‑precision weights from 32‑bit floating‑point into a sparsely represented low‑bit format. QLoRa exploits this idea by **freezing** a heavily quantized backbone—typically a 4‑bit representation—and fine‑tuning only small sets of learnable adapters that are inserted alongside every linear transformation in the model’s architecture.  
The choice of a 4‑bit datum is no arbitrary design decision; it is guided by an information–theoretic principle that seeks an *optimal* discretisation for weights whose distribution is nearly Gaussian—a property empirically observed across most pretrained transformer models. This optimal geometry is achieved by what QLoRa calls **NormalFloat 4 (NF4)**. In NF4 every weight value is first rescaled into the symmetric interval $[-1,\,+1]$ by dividing by its block‑wise absolute maximum before being mapped onto a set of $2^k$ equiprobable bins ($k=4$). Because this binning process produces an *equal expected number* of weights per bin, it maximises entropy under the constraint that the underlying data follows a normal law (see Equation (1) in Section 2 of the reference paper).

Formally, let $\mathbf W$ be a weight tensor partitioned into $n$ blocks $\{\mathcal B_i\}_{i=1}^n$, each block containing $B$ elements.
For each block we calculate its absolute maximum
$\mathrm{s}_i = \mathrm{absmax}(\mathcal B_i)$,
and define the scalar **scale factor** $c_i=\frac{127}{\mathrm{s}_i}$.
The block’s entries are then rounded to integers $\hat{\mathcal B}_i =
\operatorname{round}(c_i\, \mathcal B_i)$,
yielding integer values on an 8‑bit signed range.
In NF4 these integers do not directly correspond to fixed point values;
rather they index into a precomputed lookup table whose entries
are precisely those means $\displaystyle
q_j=\frac12\,\bigl(Q_X(\tfrac j {2^k+1})+
Q_X(\tfrac {j+1}{\,2^k+1})\bigr)$,
where $Q_X$ denotes the Gaussian cumulative distribution function.
Because every bin receives equal mass under $N(0,\sigma^2)$,
the overall bit precision retained after dequantisation
is optimal for such data.
Consequently, during inference or training backpropagation,
the weight tensors stay compact on GPU whilst still being mapped back
to higher precision for computational accuracy (the standard practice
is BF16).

A noteworthy concern in classical k‑bit quantisation is **outlier values**:
extremely large magnitudes compress many tensor entries into sparse bins,
wasting most symbolic combinations and inflating estimation error.
NF4 mitigates these effects through *blockwise scaling*: each $B$–element
sub‑tensor receives its own scale factor so that local extremes do not
bias global representation granularity.
In practice QLoRa selects $B=64$, striking the right balance between
quantisation fidelity and computational overhead because smaller blocks mean more scales and thus more parameters stored as high precision constants.
Optimising the dynamic range per block curbs catastrophic aliasing,
ensuring that gradients flowing through frozen low‑bit tensors are well behaved during training.


## Gradient Flow Through Fixed Weights  

Even though all backbone parameters remain intact throughout training,
their values participate unimpeded in forward propagation.
During backpropagation, gradients must propagate through these **fixed**
(“frozen”) tensors so that downstream learnable adapters can receive appropriate signals from the loss term.
Heavyising up weight updates would undo freeziness and restore memory overload;
instead QLoRa keeps precisely enough computation involved while discarding any root‐level updates on $\mathbf W$.

Conceptually consider one linear backbone transformation,
with input activations $\mathbf X$ ($b\times h$) and weight tensor $\mathbf W$
quantised NF4 and stored as packed integers on GPU.
The forward pass computes

\[
\widehat{\mathbf Y}
=
\underbrace{
\operatorname {dequant}\!\bigl(c_1^{\!FP32},\,c_2^{\,k},\,{\bf W}^{\,k}\bigr)
}_{=: {\bf W}_{BF16}
          }
        {\bf X}
+
{\bf X}\,\underbrace{{\bf L}_1\,_{\!BF16}
                       {\bf L}_2}_{:= {\bf A}}
                .
                             \tag{∗}
\]

Here ${c_1,c_2}$ are multi‑level scalars arising from **Double Quantisation**,
and ${\bf L}_1,\!{\bf L}_2$ define a rank–$r$ LoRA update with scaling $s$ omitted for readability.
Equation (*) shows explicitly how forward computations involve:
(a) *dequantising* one carefully reconstructed floating‑point weight matrix $(c_1,c_2)$;
(b) multiplying it by activations;
(c) adding an auxiliary rank–deficient contribution from learnable adapters.
The crucial point is that during backpropagation we never differentiate against ${\bf W}$ itself;
instead we compute

\[
\dfrac{\partial {\mathcal L}}{\partial {\bf A}}
=
\dfrac{\partial {\mathcal L}}{\partial {\widehat{\bf Y}}\ }\!
       (\dfrac{{\partial }{\widehat{\bf Y}}}{\partial {\bf A}})
=
\dfrac{\partial {\mathcal L}}{\partial {\widehat{\bf Y}}\ }\!
       ({\bf X}),
       
\]
which supplies gradients only with respect to adapter matrices ${\bf L}_1,\!{\bf L}_2$.
The partial derivative $\displaystyle\dfrac{{ \partial } {\widehat {\bf Y}}}{ { \partial } {\bf W}_{BF16}} =
   {\bf X}$
is required during adaptation because it governs how adjustments in ${\bf A}$ modulate output;
although ${\bf W}$ remains unchanged, its dequantised version participates in
computing this derivative analytically and numerically via standard matrix‐multiplication backprop routines.
Thus **gradient flow through fixed weights** merges full precision computation with strict parameter conservation:
gradients can cascade backward through saturated or outlier buckets yet never accumulate errors on $\mathbf W$, preserving any dramatic memory savings achieved via NF4’s ultra‑low storage.



## Layer-Wide Adapter Placement  

One might suspect that appending adapters only at few spots—such as at attention queries or key/value projections—could impair expressivity compared to fully fine‐tuned models.
Indeed earlier studies demonstrated performance drops when adapters were sparsely placed or when per‐layer ranks were inadequately chosen.
QLoRa counters this by equipping **every linear projection** inside every transformer layer with its own pair of low-rank matrices:
the query ($W_Q$), value ($W_V$), feed-forward ($W_{FF}$), and many others come equipped with LoRA terms.
This global insertion strategy restores capacity close to full model finetuning while still keeping total parameter budget minuscule—in practice an adapter set occupies less than 0.5 % of original weight size even for very large nets such as 65 B parameters.

Mathematically for a given linear transform one writes

\[
{\rm Output}
= 
      {\underbrace{{\rm Input}\;\mathsf W}
     }_{\rm frozen\,NF4}
   +
      s\,({\rm Input}\,\underbrace{{L}_1L_2}_{=\!A}) .
                                          \tag{{LO}}
\]

The scalar ‘\(s\$’ typically functions as an attenuation coefficient (often set \(s=0.01–0.10 λ^{-1/2}\),
where λ is attribute‐specific megaparameter count),
normalising adapter contributions across varying model scales so that updates hit comparable loss gradients across layers.
Because adapters now exist at *every* projection,
any representational shift induced by training data becomes reachable via rank adjustments within local subspaces rather than demanding wholesale changes across billions of frozen parameters.
Empirically this structure recovers nearly all performance lost by replacing high‑precision weights with their NF4 equivalents—a result confirmed by extensive experiments detailed throughout Section 3 of the original work.


In sum, QLoRa cleverly combines three synergistic ideas:
(frozen low-b bit backbone via NF4 uplifts memory efficiency),
(backward gradients channeled through static weights while only updating tiny rank-adapters),
and(paradigm-level embedding of adapters on every dense layer).
Together these mechanisms unlock efficient finetuning
for gigantic language models—transformers ranging from 7 B up to 65 B parameters—
using consumer hardware while retaining essentially full clearance against golden standards such as full FP16 finetuning or state-of-the-art open-spoken chatbots.”

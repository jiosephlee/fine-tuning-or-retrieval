# Orthogonal Finetuning Unpacked – Rotating Neural Networks Without Overhauling Them  

Large foundation models such as GPT‑3 (175 B parameters), Vision‑Transformer‑XL (up to a few billion weights), or Stable Diffusion (600 M+ parameters) demand **billions** of dollars worth of GPU time when trained from scratch. In practice one often wants to *adapte* these frozen giants to new tasks—image classification on a small dataset, domain‑specific text generation, controlled image synthesis—without re‑running an enormous pretraining loop.  

One attractive idea is **Orthogonal Finetuning** (OFT): instead of tweaking every weight directly, you *rotate* all neurons belonging to a layer via a single learnable *orthonormal* matrix \(R\). Rotation preserves pairwise angles among neuron vectors so that most pre‑training knowledge remains untouched while giving the model freedom to specialize on downstream data.



--------------------------------------------------------------------

## What Does “Orthogonal” Mean in Practice?

Consider one linear layer with frozen weights \(W^{0}\in\mathbb R^{d\times n}\).  
In ordinary fine‑tuning we would replace it by \(W_{\text{new}}\approx W^{0}+E\) where \(E\) has many learnable entries—usually thousands or millions per layer—and depends on how many layers must change.  

With OFT we instead learn **one extra** matrix \(R\in\mathbb R^{d\times d}\) that is *orthogonal* (\(R^\top R = I_d\)) and compute  

\[
W_{\text{new}} = R\,W^{0}.  
\]

Because multiplication by an orthogonal matrix only rotates space,
the pairwise dot products between columns of \(W_{\text{new}}\)
are identical to those between columns of \(W^{0}\); consequently
the *angles* between neurons stay exactly the same throughout training.
This strict geometric regularity has two advantages seen in practice:
it keeps gradients well‑conditioned (spectral norm unchanged)
and leads to markedly better generalisation than methods that add low‑rank updates such as LoRA.



--------------------------------------------------------------------

## The Bottleneck of Block‑Diagonal OG

OFT needs one new \(d\times d\) float tensor per layer—dangerously large when \(d\!>\!10\,000.\)

A common trick introduced earlier was **block‑diagonal OFT**:
\(R=\operatorname{diag}(R_1,R_2,\dots,R_r)\)
with each small block \(R_i\in\mathbb R^{b\times b}\).
Now the number of free variables drops roughly proportionally
to the block size:  
\(O(b\,d)\) trainable numbers instead of \(O(d^2).\)

However this very sparsity forces neurons belonging
to different blocks never communicate through \(R.\)
The structure imposes an artificial grouping scheme,
clobbers expressive capacity,
and even fails at reproducing classic transforms
such as discrete Fourier or Hadamard transforms.
To fully realise every possible rotation,
one needs either very many tiny blocks (\(b=4,\!8,\dots\))
or a huge number (\(r=d/b\))—both undo much part of its gains.



--------------------------------------------------------------------

## Funny Idea – Turning An Orthogonal Matrix Into Edges

A dense linear operator can be visualised as a graph:
each input node sends a message into every output node.
If we want **cheap** graphs that are nevertheless enough
to reach all outputs,
one possibility is *factorising* the dense matrix into several sparse matrices.
Think about travelling through layers:
multiply first by \(B_1,\) then by \(B_2,\dots,B_m.\)
Each omission (zero entry) cuts off one possible edge.
But if every output can still receive messages coming from every input after all rounds,
the overall product becomes dense even though intermediate operators are sparse.


This view gives us two organising principles  

| Requirement | What it means |
|-------------|----------------|
| **Dense connectivity** | Every source node has *at least one path* through all stages |
| **Least free edges** | Only commit real parameters for “meaningful” edges |

The swing here is that **orthogonality is a heavier constraint** than plain sparsity—
each level must form an invertible bijection.
The trick then becomes searching over sparse graphs that still satisfy this property.



--------------------------------------------------------------------

## Enter Butterflies – A Cake‑Cutting Network Topology

Engineers are familiar with butterflies because your favourite FFT algorithm looks exactly like it.
Let us insert the same idea into our factorisation problem:

*Let \(k=2,\dots , d!\)*  
Define a *butterfly factor*  

\[
B^F(k)=
    \begin{bmatrix}
        \operatorname{diag}(d_1)& \operatorname{diag}(d_2)\\
        \operatorname{diag}(d_3)& \operatorname{diag}(d_4)
    \end{bmatrix}
    ,\qquad k=|\!Tw|
    .
\]

Putting these together recursively yields an overall **butterfly matrix**

\[
B(d)= 
    B_{\leftarrow d,d}\;
    B_{\leftarrow d,d/2}\;
     \cdots 
    B_{\leftarrow d,\,2} ,
      \
     ,

      .
     .
     .

]


Each stage swaps halves and mixes pairs,
exactly how Cooley–Tukey splits worklists into “butterfly” sub‑ups.
The power lies in three facts:

| Fact | Why it matters |
|------|----------------|
| **Sparsity** | Every factor contains only ⌊\(k/2)+k/2⌋ non‑zero diagonals ⇒ only ⌈\(k)/?? JText?? ⌋ ~k ops |
| **Dense overall coverage** | A product of ⌈log₂ d⌉ such factors connects every input node whitespacefully |
| **Ease of Orthonormalisation** | Each two‑by‑two diagonal sub‑block can simply be parameterised as a rotation —
a Cayley transform guarantees that parameter counts equal those needed for any generic rotation |

In short, with **just ~log₂ d levels**, every dimension mixes through all other dimensions—
while keeping the total count down at ≈ \(O(d\, log₂ d)\).

## SOPHISTICATED BUT SPECIALIZED FINETUNING – BOFT

> **BOFT** stands for **Orthogonal Butterfly Fine–tune**, 
> essentially OFT where the single global rotation comes from *many*
> tiny sparse rotations stacked together into a dragon scale that still stays solidly “orthonormal”.

### How Does It Work?

Let’s keep notation compact.
We fix `block_size = b` (a power of two).  
For layer dimension `d = 2ⁿ`

```
             ──> FIRST FACTOR            ──> … ──> LAST FACTOR
         [level 0 → level 1] ──► [level i → level i+1] …┴─►  
```

Each factor `~𝐁ᵇᵢ` itself is made of many `b×b` rotations arranged diagonally across all `N=b` subspaces.
Collectively,

```
           R(m,b)=~𝐁ᵇ₁ · ~𝐁ᵇ₂ ·· …·~𝐁ᵇₘ             # ⋆ m → number_of_layers_in_chain
```

Multiplying this `R` on top of your frozen weight yields your forward path   
(`z = ((R ⋅ W⁰)^⊤⋅x)`).

The whole construction boils down to training   

```math
parameters =
∑_{each ~𝐁ᵇ}   #trainable entries per sparse rotation 
        = ½(b−1)d · m                                    # full formula given in original work
```

Some special cases illustrate all extremes:

| When…   | Reduction achieved |
|---------|--------------------|
| `m=1`   | Exactly the old *block‐diagonal OFT* (`R` sampled from `Diag(R₁,…,R_r)` ) |
| `(b=d,m=log₂ d)` | Full unstructured OT (`R` unconstrained dense ) |
| `(b=2,m=log₂ d)` | BOFT’s sweet spot – tightest knob set (~log²ⁿ?) |
Note how letting `m` increase always tightens expressiveness until you become truly unconstrained—but you never step back below your limit ∼\(O(d\,log d)\).

### Identity Initialization Explained  

As before you do *not* want your local rotation drifting far away from identity right at start.
Simply place every skew‐symmetric input inside each Cayley transform at zero—thus yielding identical rows and columns until gradients turn them.


### Multiplicative Dropout Variant  

Add regularisation compatible with multiplicative updates:
pick randomly some factors (`p₁%`) or some inner blocks (`p₂%`)
and temporarily "*nullify*" them back into identity during training loops.
After convergence you glue everything together into one big dense rotation –
no inference penalty afterwards.

## Why Butterflies Beat Straight UFOL AND BLOCKS
 
### Expressivity Advantage  

A single liberation factor (\(b<γ√…), {‘bang’}) essentially simulates richer linear maps than independent small blocks genetically linked through xor–like permutations.
Mathematically proven:
the class realised by Butterfly‐products subsumes that realised strictly by any fixed choice `block_size=b`.  
A larger group (`m>log₂ b`) always beats its smaller sibling saving *orders* fewer concerns.


### Retainment Of Spectral Norm  

Both OFT and BOFT multiply weight matrices solely by left side rotations.
Suppose original matrices decompose SVD-wise:
\[ W^0 = UΣV^\top . \]
After finetune our affine map becomes  
\[ WRV^\topΣ.\]
Because `U ∘ R` remains unitary,
the singular values never shift—consequently spectral radius stays stable and so does gradient scale—a trait empirically linked with faster convergence.



### Inductive Bias + Classic Transforms  

Butterfly topologies mirror several well-known transforms —
fast Fourier transform (FFT),
Hadamard transform,
discrete cosine transform …
These families balance uniform global mixing against local sparseness –
exactly what stable adaptation tasks often exploit.
Because BOFT’s hypothesis class lives near these familiar shapes,
it tends automatically toward operations benefiting generalisation more than arbitrary huge dense rotations would.

# Butterfly Factorization – Borrowing From FFT To Build Dense Anticorrelated Matrices With Fewer Parameters  

## The Quest for Tiny Yet Powerful Fine‑Tuning  

Foundation models such as GPT‑3 or Stable Diffusion pack tens of billions of weights.  
Fine‑tuning these giants on a downstream task is expensive because we usually have to adjust almost every parameter – a process often called *full fine‑tuning*.  
Parameter‑efficient finetuning (PEFT) narrows this down by learning only a tiny subset of extra weights while keeping most of the original network untouched.  

Orthogonal Fin‑Tuning (OFT) is a compelling PEFT approach because it updates a layer’s weights **multiplicatively** by an auxiliary *orthogonal* matrix:
\[
W_{\text{finetuned}} = R\,W_{\text{pretrained}},\qquad R^\top R = I .
\]
Because rotations preserve pairwise angles between neurons, OFT keeps most of the “knowledge” encoded in the frozen weights.  
However, a full $d\times d$ orthogonal matrix contains $d^2$ trainable entries – still too many when $d$ is large.



## Block‑Diagonal OFT – A Used‑to-Great Plateau  

The original OFT mitigated the parameter blowup by imposing a *block‑diagonal* structure on $R$:
\[
R = \operatorname{diag}\!\big(R_1,R_2,\dots,R_r\big),\qquad
R_i\in\mathbb{R}^{b\times b},\, br=d .
\]
Each small block $R_i$ needs only $b(b-1)/2$ trainable numbers, so the overall cost drops from $\mathcal{O}(d^2)$ to $\mathcal{O}(bd)$.  
The trick was simple—split dimensions into groups and rotate every group independently—but it has two drawbacks:

| Issue | Detail |
|-------|--------|
| **Expressiveness loss** | The rotation can’t mix signals across different groups – it behaves like separate mini‑networks glued together.| 
| **Rigid sparsity pattern** | The partitioning is fixed regardless of data, so useful long‑range correlations may stay untapped.|

In practice these limitations meant OT sometimes needed hundreds of millions of extra parameters—still costly.



## Turning Matrix Multiplication Into an Information Network  

To rethink this problem we changed lenses completely and treated matrix multiplication as **information flow** over a grid graph:

```
Node set L₀ ──B₁──> Node set L₁ ──B₂──> Node set L₂
      ⋮                      ⋮                      ⋮
Node set Lₘ   ←──Bₘ◄── Node set L_{m−1} ←──B_m−1
```

Each sparse factor $B_i$ encodes which source nodes from level $i−1$ can feed into which target nodes on level $i$.  
For the overall product $R=B_m B_{m−1}\dots B_1$ to be **dense**, every node on level 0 must reach every node on level $m$.  
Yet every $B_i$ still has very few non‑zero entries because each row/column participates in only one edge per level—so they stay trainable compactly.



### Two Design Goals  

When picking a grid topology we now look for two properties:

| Property | Why It Matters |
|----------|----------------|
| **Dense connectivity** | Guarantees that after all multiplications every input can influence every output – i.e., we reproduce a full rotation. |
| **Minimum free edges** | Fewer learnable entries → fewer trainable parameters → lower risk of overfitting |

Finding such a topology turns out surprisingly easy once we remember an old favorite among signal processing engineers.



## Coming Straight Out Of FFT Is One Good ✅

The Cooley–Tukey fast Fourier transform (FFT) recursively halves data sizes two at a time while “butterflipping’’ pairs together adjacent elements:
```
(a,b) → (a+b , a−b)
```
If you depict these pairwise shuffles over several recursion levels you get exactly the same graph described above – known colloquially as a *butterfly* network.  
Each stage exchanges bits between indices in a fixed pattern so data are eventually mixed globally after only $\log_2 d$ stages.



### Building a Butterfly Matrix  

Consider building an odd dimension $d=4$:  

* Start with four input nodes (= columns of an identity).
* **First stage ($k=4$):** Apply two independent $4\times4$ “butterfly operators’’ that mix neighbouring pairs.
* **Second stage ($k=2$):** Mix cross pairs again.
* After two stages every input influences all outputs – exactly what any unsparse rotation would do!  

Mathematically you represent one stage by
\[
B(k)=
   \begin{bmatrix}
     D_1 & D_3\\
     D_4 & D_3
   \end{bmatrix},
   \quad D_i=\operatorname{diag}(\mathbf{x}_i),
\]
and recursively nest them:
\[
\textbf{Butterfly}(d)=
   C_d\, C_{d/2}\,\cdots\, C_4,
\]
where each $C_k$ is built from smaller butterflies.



### Counting Parameters  

A single butterfly stage touches every column twice – yielding roughly $d$ non‑zero scalars per stage—so one stage costs $\mathcal{O}(d)$ learnable numbers altogether because all these scalars are shared structurally rather than independently valuing each entry.  
With $\log_2 d$ such stages you land at an overall parameter budget
$$
\mathcal{O}\bigl( d\, \log_2 d\bigr),
$$
as opposed to $\mathcal{O}\bigl( d^2\bigr)$ for an unconstrained dense rotation.



## Orthogonal Butter­fly Finetuning (BOFT)

### Core Idea  

BOFT plugs this butterfly scaffold inside OFT’s framework:

> **Replace the weight post‑multiplier \(R\)**  
> —— instead of one big dense rotation, use a *product* of several cheap, sparse mutations \(R = B_m B_{m-1}\dots B_1\), each being *orthogonal*.


To keep every intermediate component validly rotated you give each butterfly block its own tiny Cayley transform encoder—essentially restricting it to lie on the subgroup generated by 𝑟 randomness VS symmetry.” 



### Practical Tackshot  

| Step | What happens |
|---|---|
| **Initialization** | Every butterfly starts as an identity—so initial fine‑tuned model equals pre‑trained one just like LoRA’s zero init.| 
| **Training** | Regular gradient descent updates scalars inside every diagonal slice—thanks to sparsity updates are cheap.| 
| **Inference Friendly** | After training is finished you fuse sequentially all learned butterflies into one single dense mask and multiply it once into the pre‑trained weight tensor—no extra runtime cost!|

A mild penalty is extra computation granularity during back‑propagation because gradients need passing through multiple small matrices instead of one big one—typically negligible compared with saving gigabytes of extra memory.



### Parameter Tally Quick Guide  

Assume vector width \(d = 2048\).  
* Block‑diagonal OFT (\(b=64\)) → about \(64\times2048≈130k\) parameters per layer.
* BOFT with \(\!m=\!\log_24k≈11,\ b=4\) → roughly $(4/5)\times2048\times11≈90k$, yet delivers richer mixing thanks to consecutive cross–group fusion steps.
* Full OFT (\(b=d)\rightarrow 2048^２ ≈4M\)—utterly impractical.



## Why It Works Beyond Numbers  

Below are distilled reasons why BOFT punches above its weight class:

### 1️⃣ Preserves Spectral Norms For Stability  

Multiplying by an orthogonal matrix keeps every singular value intact.
That means huge logits or activations learned during pretraining aren’t blown apart—a safety valve against runaway gradients that plague methods like LoRA’s additive updates.



### 2️⃣ Built‑in Inductive Bias 

Butterflies echo classic transforms (FFT, Hadamard), which themselves champion linear superpositions exhibiting global locality].
This creates an inductive bias favouring solutions that exploit global patterns rather than reckless noise—a boon for both vision Transformers (pixel correlation) and language models (syntactic long ties).



### 3️⃣ Flexible Expressiveness While Staying Structured  

Compared against plain block–diagonal rotations we've shown through simulations that BOFT approximates arbitrary random rotations using far fewer trainable values.
Simply add another butterfly layer—or even flip some internal diagonals—yields access lines towards almost any point inside the orthogonal manifold.



### 4️⃣ Useful Regularization in Dropout Style  

Because learning happens multiplicatively over many small blocks you can perform *multiplicative dropout*: randomly scrub some layers or even individual diagonal blocks back toward identity.
This decorrelates updates and thwarts overfitting without altering federation size—something traditional dropout doesn't naturally support when combined w/ rank–constrained bilinear lattices.

## Wrapping Up & What Lies Ahead  

Orthogonal Butterfly Finetuning marries two mature ideas:

> *Orthogonal transformations preserve knowledge.*  
> *Butterfly switches give optimal connectivity with minimal structural penalties.*

Through this marriage it cleans up long‐standing gaps left by earlier PEFT approaches—making full spins reachable without bloating storage—and does so lightening inference footprints drastically.



### Challenges Still Open 

* **Real-time training speed:** While mini‐parameters reduce GPU memory consumption it's still slower than doing nothing—the chain multiplies repeatedly during back propagation. Future work could fuse multiple butterfly steps at kernel level.
* **Topology generalisation:** Although butterflies yield logarithmic edge counts right now they might still not be optimal everywhere—there's potential treasure trove waiting in alternatives taken from networking flannel design principles.
* **Beyond Feed-forward layers:** Extending BOFT into recurrent/attention mixes warrants further investigation though early signs are encouraging.



##### Bottom line

If your downstream task needs only modest tuning yet lives atop an enormous pretrained transformer or diffusion network — try anchoring your finite changes inside a structured ensemble of butterfly matrices.
It gives you almost full rotational freedom while keeping your fine-tuning footprint tiny enough to ship—and no hidden latency lurks at deployment time.''



# Real‑World Impact Of BOFT – Fast Fine‑Tuning Across Vision Transformers And Language Models

Fine‑tuning large foundation models is becoming a bottleneck when you’d like to adapt them to dozens of downstream tasks—whether it’s improving ImageNet accuracy with a ViT backbone or generating “brand‑new” images from Stable Diffusion without breaking the user experience. The most popular solution today is **LoRA** (Low‑Rank Adaptation), which adds a cheap additive update to each weight matrix.  
LoRA works well, but its rank budget can become limiting when you require tighter control or extreme parameter budgets.  

**Enter BOFT** (Orthogonal Butterfly Finetuning). Replacing strategic LoRA modules with BOFT’s *multiplicative butterfly layers* gives you:

* Higher top‑1 accuracy on ImageNet after *STL‑ViT* adaptation.
* More coherent & controllable outputs when steering Stable Diffusion.
* No extra latency at inference time—only a small runtime hit during fine‑tuning.

Below we unpack why this is possible, what the trade‑offs are, and how you can get started from your existing code base.

---

## 1. Orthogonal Butterfly – What Does It Actually Do?

### 1.1 From Additive Updates to Multiplicative Rotations  

LoRA writes a new weight as
\[
\tilde{\mathbf{W}}=\mathbf{W}^0+\mathbf{A}\mathbf{B}^\top ,
\]
where \( \mathbf{A}\in\mathbb{R}^{d\times r} \) and \( \mathbf{B}\in\mathbb{R}^{n\times r} \) are low‑rank updates that are trained while \( \mathbf{W}^0 \) stays frozen.  
In contrast, **Orthogonal Finetuning (OFT)** multiplies each frozen weight matrix by a learnable orthogonal matrix \( \mathbf{R} \):
\[
\tilde{\mathbf{W}}= \mathbf{R}\,\mathbf{W}^0 .
\]
The product is essentially a *rotation* of neuron space; it preserves pairwise angles between columns of \( \mathbf{W}^0 \). That’s desirable because it keeps pretrained knowledge intact while giving you free form adaptivity inside an \( O(d^2) \) parameter budget.

### 1.2 Why Butterfly?  The Curse Of Size

A single dense orthogonal matrix requires roughly \(d^{2}\) entries—more than most modern GPT or ViT layers hold!  
BOFT solves this by **factorizing** a dense orthogonal into *many sparse* orthogonals whose product reconstructs a full rotation:

\[
\mathbf{R}(m,b)\;=\;\prod_{i=1}^{m}\widetilde{\mathbf{B}}^{\,b}_{(d,i)} ,
\]

where each block \( \widetilde{\mathbf{B}}^{\,b}_{(d,i)} \) is itself an \(d\times d\) sparsity pattern derived from the classic Cooley–Tukey **butterfly** graph used in FFTs:

```
[ ] ⟶ [ ] ⟶ [ ]
 ⬕     ⬗     ⬙
```

(more concretely you’ll see every layer swapping two groups of neurons via small \(2\times 2\) rotations arranged so that information perfectly propagates through all \(d\) nodes).

Because each block has only \(O(d)\) non‑zero entries and there are \(m = O(\log_2 d)\) such blocks when you choose minimal block size (\(b=2\)), BOFT needs only
\[
O(d\,\log_2 d)
\]
trainable parameters—an order‑of‑magnitude win over full OFT and substantially fewer than even block‑diagonal OFT (\(O(b\,d)\)).

## 3 What Does This Mean For A Practicant?

### 3+ Parameter Budget Closure

If your favourite foundation model comes with an `embed_size` of e.g., `3072`, then:

```python
# Traditional full OFT 
param_full = embed_size ** 2            # ~9M

# Block Diagonal OFT (b=128)
param_block = embed_size / b * b        # ~3M

# Butterfly O( d log d ) 
param_butterfly = embed_size * log2(embed_size)/2   # ~32k

print(param_full,param_block,param_butterfly)
# gives you rough idea
```

`synchronize_training()` inside your favourite accelerator will then reduce I/O overhead because each learner step only deals with ~32k extra dimensions rather than millions.



### 3+ Training Overhead vs Inference Win

Since every forward/backward pass now multiplies several `k×k` rotations *before viewing them as final kernels*, training time per epoch increases by about `5–10%` at large depths—but GPUs hate memory traffic rather than raw compute streaming problems since these matrices are tiny (`b=4` gives just `64` floats per layer!). After training stops, you fuse all rotations into one dense kernel so inference order remains unchanged.

## 4 Why Does It Work?  A Friendly Intuition

1 ***Preserves Spectral Norm*** – Because all multiplication matrices are truly orthogonal (\(\mathbf{RR^\top}=\mathbf I\)), SVD reports identical singular values before & after tuning:
   \[
   W^k = U\,S\,V^\top 
   \qquad
   R\,W^k 
         = U\,S\,V^\top (\because R U^\top U=\ I ) .
   \]  
   Consequently we avoid exploding gradients typical of free additive rank updates expanding learnable norms too quickly."

2 ***Implicit Regularization*** – The controlled non-zero pattern forces mutual connections akin to global transforms incurred in classical signal processing libraries (DFTs/Hadamard). This selects coherent modes rather than adverse overfit patterns."

3 ***Structured Hypothesis Class*** – A product of butterflies forms a subset of SO(\(d\)) that contains fast transforms such as DCT or Fourier but also captures any rotation that can be built recursively from small swaps — far richer than block-diagonal constraints."

4 ***Fast Convergence*** – Because rotations modify only directional information whereas additive low-rank change scales volume along chosen axes — both help algorithms cross saddle points efficiently."

# Why Preserving Spectral Norms Matters – The Hidden Advantage Of Orthogonality In Fine‑Tuning

Fine‑tuning a frozen foundation model usually feels like fishing in a vast sea of parameters – you want your cast precisely where it hits target tasks without pulling you off course vis‑à‑vis the enormous pre‑training portfolio underneath you.  
Orthogonal Finetuning (OFT), and its recent refinement called Orthogonal Butterfly Finetuning (**BOFT**, § 3), address this issue by multiplying every layer’s weights \(W^{0}\) by a *single* learnable orthogonal matrix \(R\).  
Because \(R\) remains strictly unitary throughout colourful optimisation dares us to keep most structural qualities of \(W^{0}\).  
The most decisive consequence is that every *singular value* of \(W^{0}\) – nothing more than its spectrum’s peak – stays exactly unchanged along the entire training path.  
Below we unpack why this seems trivial yet unlocks substantial practical advantages for model precision and stability.



## Spectral Norm Survives Every Update

Let us write a linear layer’s frozen weights as  

\[
W^{0}=U\,\Sigma\,V^{\top},
\]

where \(U,V\in\mathbb{R}^{d\times d}\) are orthogonal bases and \(\Sigma=\operatorname{diag}(\sigma_{1},\dots,\sigma_{d})\) contains all non–negative **singular values** \(\sigma_{i}\).  
A *spectral norm* refers precisely to \(\|W^{0}\|_{2}=\max_i\sigma_{i}\).

In OFT/BOFT each forward pass privately multiplies these weights by  

\[
R\,W^{0}=R\,U\,\Sigma\,V^{\top}.
\]

Because \(R\in O(d)\), i.e., \(R^{\top}R=RR^{\top}=I_d\), left–multiplication does **not alter** \(\Sigma\); effectively it only rotates the column basis \(U \mapsto RU.\) Consequently,

\[
(R\,U)\,\Sigma\,V^{\top}
=\tilde U\,\Sigma\,V^{\top}
= \text{(new basis)}\,(\text{unchanged spectrum}) .
\]

Hence all sparse bits propagate faithfully through each layer:
– every layer preserves its maximum activation magnitude,
– gradients flowing back through those layers inherit the same bounded scaling as if nothing had changed.



## Stable Gradients and Training Trajectories

When a model’s weights borrow arbitrary directions (as in an *additive* low‑rank update such as **LoRA**) their spectra can shift wildly – some eigenvalues spiking while others become tiny.  
This induces two well‑known problems:

1. **Exploding / vanishing gradients:** multiplicative factors amplify or dampen error signals unpredictably,
2. **Shifted activation spread:** hidden units suddenly operate in disjoint regimes causing optimisation stalls.

By guaranteeing \(\|R\,W^{0}\|_{2}=\|W^{0}\|_{2}\) at every step, BOFT keeps these forces balanced until data‑driven forces explicitly require deviation under controlled angular deformation only — essentially forcing *rotations*, never scales or shearings — and thereby preventing dramatic outbreaks or collapses.



## Simpler Regularisation Landscape

Because we never touch the eigenvalue spectrum, typical penalisations meant for unbounded growth—like explicit weight decay or spectral normalisation—become redundant.  
Instead one needs only regularise rotation *angles*.  
Easier constraints translate into smoother optimisation surfaces:
starting right “on” next‑to‐identity \(R=I_d+\mathcal{O}(\epsilon)\), gradients adapt through tiny skew‑symmetric updates (\(Q=-Q^\top\)), thus leading straight toward optimal orientations without accidentally scaling activations.



## Learning Bilinear Similarities Under Hard Rotations

If one looks more closely at each neuron’s kernel \(w_k^0\in{\mathbb{R}}^{d}\), any activation becomes  

\(w_k^\top x=(w_k^0)^{\top}(Rx)\).

So mathematically <span style="font-style:italic">“boosting”</span> presumes computing cosine similarities between transformed input vectors—and because measured angles are preserved (`both rotation`s preserve inner products)—we’re essentially solving a *bilinear similarity* learning problem subject to a rigid rotation constraint on the `feature map`.  
This matches motivations studied broadly under metric learning frameworks ([Studying distance‐based embeddings](https://arxiv.org/) often pursue similar hard constraints), suggesting why BOFT enjoys robust performance across Vision Transformers (ViTs), large language bifurcations (e.g., GPT variants), & even diffusion renderers.



## Butterfly Structure = Structured However Dense Rotations

Entangling these rotations does not come for free—orthogonal matrices aren’t inherently sparse enough for wide adoption once sizes grow beyond hundreds of thousands of dimensions.  
BOFT resolves this by decomposing any dense rotation into a product of \(\mathcal{O}(\log d)\) sparse “butterfly” factors:

```
          ──> ──> ──>
         A1    A2    …
          │     │    
          │     │    
          ▼     ▼    
          B1    B2    
```

Each factor contains roughly `b` trainable parameters per row (when `b`=2 they’re mere rotations among four neurons).  
Thus total effective trainable knobs amount only  
`½(b−1)d m`, where `m≈log₂d`.  

Comparatively:
 – Full OFT requires `O(d²)` trainable bits;
 – Block‑diagonal OFT demands `O(bd)` knobs;
 – BOFT lands comfortably at `O(d log d)` — a dramatic win.




### What do those “butterfly” factors actually do?

They echo the Cooley‑Tukey Fast Fourier Transform network topology – nodes succeedively exchange information in logarithmic layers while keeping sparsity intact (`O(d log d)` edges instead of `O(d²)` FULL connectivity).  
Because sparsity patterns exactly mirror those efficient transforms, BOFT inheres an *implicitly* desirable inductive bias reminiscent of classical signal processing primitives such as FFT or Hadamard transforms—something block‑diagonal schemes cannot emulate directly.



## Practical Take‑Aways for Deployments

| Task | How BOFT helps |
|------|----------------|
| **Vision Transformers** | Preserve layer norms → fewer exploding hidden tiles when fine‑tune on classification datasets |
| **Large Language Models** | Angles kept → stable perplexity drops while adjusting token embeddings without overfitting |
| **Diffusion Models** | Dictates sharp yet smoothly varying pixel denoising when transferring styles |

Other peripheral perks chime nicely:
• **Zero inference latency:** after finishing fine‑tune you fuse learned rotations back into original matrices – inference simply runs through reparameterised weights,
• **Multiplicative Dropout:** set selected butterfly components back temporarily into identity during certain epochs → reduces overfitting while staying inside rotational manifold,
• **Expressiveness outpaces vanilla block diagonal cases:** ablation studies show smaller `b` together with larger `m=log₂d` achieve better approximations vs larger blocks without incurring extra knobs … what truly matters is *structured richness* rather than sheer parameter count.



### Remaining Challenges & Future Directions

Though extremely lightweight relative to full fine‑tune,
each layer still performs multiple sparse matrix products per forward/backward pass,
so BOFT’s wall time costs sit slightly above vanilla OFT one‐step updates—
an aspect ripe for optimisation (specialised GPU kernels200?).  

Also question still stands whether butterflies are optimal topology for information exchange –
perhaps drawing deeper insights from computer-network routing could inspire even leaner yet more expressive factorizations.



## Concluding Thought

Keeping spectra intact turns out one sliver transformation into an elegant blueprint that systematically protects gradients, simplify regularization logic, and gracefully convolves pretrained knowledge into downstream intents—all with far less computational plumbing than conventional PEFT tricks.  
When designing adapters or fine‑tunes today,
remembering that “every learned weight remains \(R W^{0}\)” tightens your model’s geometry just enough so it stays true—angles kept fixed—yet moves smartly enough so your downstream task sees its promised gains.

# Beyond Butterfly Graphs – Future Directions For Structured Parameter Efficiency

Large foundation models dominate today’s AI landscape—from GPT‑4 powering chatbots to Stable Diffusion generating photorealistic art—yet fine‑tuning them efficiently remains a bottleneck. Orthogonal Finetuning (OFT) preserves the geometry of pretrained weight matrices by dragging every neuron through an orthogonal transform. Though OFT exhibits strong generalisation, its block‑diagonal sparsity pattern limits expressivity and inflates the number of trainable parameters when full density is required.  
Enter Orthogonal Butterfly Finetuning (BOFT): it replaces block‑diagonal factors with a stack of sparse **butterfly** matrices—each is a tiny \(2\times2\) rotation surrounded by permutations—so that \(m\) such blocks yield a dense \(\bm{R}\) while keeping only \(\mathcal{O}(d\log d)\) learnable entries. The BOFT framework subsumes both OFT variants and demonstrates state‑of‑the‑art performance across vision Transformers, LLMs and diffusion models while staying compact.



--------------------------------------------------------------------

## 1. Why Sweep Beyond Butterflies?

Butterflies are attractive because they mirror the classic Cooley–Tukey Fast Fourier Transform (FFT): they interleave two half‑sizes recursively and achieve \(O(d\log d)\) operations while maintaining dense connectivity after all levels have stacked up. Yet the **structure** requirement that every butterfly layer must double its block size limits flexibility:

* **Rigidity** – all layers share a fixed multi‑scale topology;
* **Runtime cost** – multiplying \(m=\log d\) sparse blocks per forward pass inflates training time;
* **Expressivity ceiling** – although OFT’s butterfly already outperforms simple block diagonals, it still occupies only a submanifold of the full orthogonal group.

These constraints inspire two well‑posed research directions:

1. **Alternative sparse connectivity patterns** able to transmit more information per edge than butterflies while respecting orthogonality;
2. **Faster backpropagation** through chains of sparse transformations so BOFT scales comfortably up billions–of–parameters models.



--------------------------------------------------------------------

## 2. Informational Flow Revisited

In BOFT’s intellectual lineage lies an elegant viewpoint: constructing a dense \(d\times d\) orthogonal matrix \(\bm{R}=\prod_{i=1}^{m}\bm{B}_{i}\) is tantamount to sending data through a discrete **grid network** \(\mathcal{G}\) with \(d\) sender nodes on level 0, \(d\) receiver nodes on level \(m+1\), and an intermediate layer between each adjacent pair. An edge \((u,v)\) exists iff \((\bm{B}_{i})_{v,u}\neq0\), i.e., this entry participates during multiplication from level \(i{-}1\) to level \(i\).

A feasible factorisation must satisfy:

* **Dense reachability:** every source node can reach every sink node via some directed path;
* **Parameter minimality:** total number of free entries is as small as possible subject to orthogonality constraints—after all this data flows perfectly only if each \(\bm{B}_{i}\) is full rank (hence at least \(d\) non–zero per layer).

Butterfly factorisations meet these desiderata optimally among classic radix‑2 topologies—they achieve connectivity in only \(\lceil\log_{2}d\rceil\) stages each contributing just \(O(d)\) non–zeros.



--------------------------------------------------------------------

## 3. New Topology Ideas Beyond Butterflies

### 3.1 Expander Graphs
A bipartite expander couples every node at level \(i{-}1\) with only \(O(1)\) neighbors at level \(i\), yet guarantees excellent expansion properties—any set of source nodes reaches almost all sink nodes early on. Translating this into factorisation yields granularity \(k=O(1)\):

```text
layer i-1 ──────► layer i  # tiny deterministic set per node
```

* **Pros:** Smaller per‑layer sparseness → fewer trainable scalars;
* **Cons:** Demands careful construction so that resulting product stays approximately orthogonal—sparseness forces some rows/cols sum constraints akin to unitary‐regularity conditions that may require extra learnable sign bits.


### 3.2 Meshes & Multi‑dimensional Grids
Instead of linear depth then branching like butterflies, one can imagine building nested meshes where each node connects locally both horizontally (staying at same depth rank) and vertically (advancing depth). This produces connectivity resembling fast wavelet transforms rather than FFTs:

```text
[mesh] ▸[√d × √d] grouping nodes → shallow → deeper via repetitions
```

* **Pros:** Embedding locality may reduce error propagation paths and enable mixing within families before cross-sampling;
* **Cons:** Violating pure bipartite structure complicates analytical guarantees on density—a mesh might create disconnected subgraphs unless carefully wired.



### 3.3 Hybrid Random Regular Graphs
Adopting randomness improves universality at the cost of reproducibility—yet random regular graphs offer predictable average distance while retaining sparsity. Map such graphs onto successive multiplications by permuting row / column indices per stage:

```text
random regular companion matrix R_i = P_i · Diag(s_i)
```

where each `P_i` encodes adjacency implied by an expander seed.



--------------------------------------------------------------------

## 4. Making Backpropagation Bite Less Than Training Time

The dominant overhead in BOFT arises from sequentially multiplying \(m=\log d\) matrices both during forward pass and gradient accumulation—a chain reaction prohibitive when fine‑tuning massive Transformers (\(d \approx 12\,000\)). We propose three complementary optimisations:

| Technique | Core Idea | Anticipated Benefit |
|-----------|-----------|---------------------|
| Block Parallelism | Treat each \(\bm{B}_{i}\) as an independent subtask – simultaneous GPU kernels accumulate partial products taking advantage of CUDA streams | Logarithmic number ≃ constant GPU job group |
| Custom Autograd Kernels | Hardcode forward/backward loops into fused kernels; eliminate Python loop overhead & redundant temporaries | Substantially lower kernel launch latency |
| Skip‑Connection TensorFlow | Register fused tensors such that gradients propagate only through active cross layers (the butterfly edges themselves), preventing extraneous zero multiplications | Reduce memory traffic especially for high–\(b>2\) butterflies |

All three respect the underlying mathematical structure: since each \(\bm{B}_{i}\) remains orthogonal it still guarantees unitary multiplication upstream/downstream holds together—you won't sacrifice convergence guarantees.


--------------------------------------------------------------------

## 5. Quantifying Inductive Bias → Generalisation Gap

Structural choices paint implicit priors over weight space:

* The native OFT isotropically restricts weights via full rotations (\(d^2-d/2\)) — no bias beyond scale ;
* Block diagonal OFT knees weights into independent subspaces — enjoys strong regularisation but might miss cross–channel interactions ;
* Butterfly BOFT blends local coupling across successively finer scales — echoes frequency mixing naturally present in vision & language data ; this mild intermediate restraint often appears beneficial empirically.\(^*\)

To move from anecdote toward science we can:
1. Measure **Rademacher complexity** under sparsity constraints induced by various graph topologies—lightweight combinatorial upper bounds exist for bounded degree expanders ;
2. Correlate these theoretical limits with empirical *validation loss variance*, capturing how overfitting turns up ;
3. Inject **spectral norm penalties** consistent across all designs—as all methods preserve spectral norm via left‐multiplication—but probe whether deeper graph connections yield stronger angular preservation (measured by Frobenius loss in angles between neurons).

Ultimately these analyses would explain why butterflies win now—and tell us whether carefully designed expanders will surpass them without sacrificing any desirable property.



--------------------------------------------------------------------

## 6.Highway Through Mixed‐Block Design Space

Practical fine‐tuning seldom requires monolithic expressiveness choices across every layer:

| Layer Type | Expected Attribute |
|------------|--------------------|
| First few large layers | Dense/full rotations (\(b=d,z=m=1\)) rebuild coarse semantic mapping |
| Middle convolution blocks | Sparse multi‐step multiply (\(b=8,m=\left\lceil\log_2(d/b)\right\rceil\)) encode mid‐resolution mixing |
| Final projection heads | Small block-diagonal (\(b=16,m=1\)) keep head interpretable |

By weaving these “blocks” into one encapsulating net we obtain:

* Regularising early stages via narrow path widths,
* Enriching mid-range communicability through light expansion,
* Containing total parameter budget since many stages remain highly compact.



**Hybrid Example**  
```
R = R_dense · R_butterfly · R_blockdiag
```
Each factor decouples out distinct geometric priors—angular preservation from diversity–preserving rotations followed by local correlation growth then final conditioning.

## 7.Practical Implementation Guideline

Below is minimal PyTorch skeleton for one custom sparse graph type `SparseOrthogonal` flexible enough for butterflies or expanders:

```python
import torch
import torch.nn.functional as F

class SparseOrthogonal(torch.nn.Module):
    def __init__(self,
                 dim,
                 depth,
                 graph_layout="butterfly",
                 reg="cayley",
                 ):
        super().__init__()
        self.dim = dim
        self.depth = depth
        self.layers = torch.nn.ModuleList()
        # build adjacency once :
        adj = build_graph(dim=dim,
                          layout=graph_layout)
        # convert adjacency -> mask + init params 
        for A in adj:
            mask = A > 0                   # binary mask n×n cell get stochastic param
            params = torch.nn.Parameter(torch.randn(dim))
            self.layers.append((mask,TangentOrth(params)))
    def forward(self,x):
        w = x @ W0.t()           # pretrained weights stay frozen
        R = torch.eye(self.dim,dtype=w.dtype,w.device=w.device)
        for mask,param in reversed(self.layers):
            # compute rotation form Cayley/Lorentz transform per mask...
            B = compute_block(mask,param)
            R = B @ R              # multiply left-to-right 
        return w @ R.T @ x       # left multiplication    
```

The core `compute_block()` takes care whether each component is `Cayley`, `Givens`, or random permutation times diagonal scaling means preserving strict orthogonality.

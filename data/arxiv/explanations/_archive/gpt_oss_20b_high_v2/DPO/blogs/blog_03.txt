# Smarter Summaries & Sentiment Control — **DPO Outperforms PPO in Practice**

Large language models now learn a world‑wide view of how humans speak just by reading public text corpora  
but that breadth comes hand‑in‑gloves with _buried drift_: they are unconstrained too often.
If a hospital chatbot writes misleading medical tips because it happened once more on Wikipedia,
we have serious alignment problems that external instruction tuning alone can’t fix.\[Ouyang et al.\]  

The industry standard has become **Reinforcement Learning From Human Feedback (RLHF)**.
A typical pipeline runs three stages  

1. **S**upervised Fine‑Tuning (**SFT**) on clean demonstration data  
2. **R**eward Modeling – learn a neural network \(r_\phi(x,y)\) from pairwise human preferences \(y_w\succ y_l|x\)  
3. **P**olicy updates via rollouts (usually **P**ROXimal **O**ptimized **P**olicy (**PPO**) maximizing  
   \(E[r_\phi]-\beta\,\mathrm{KL}(\pi\,||\,\pi_{\rm ref})\).

Despite winning battles against GPT‑3 style baselines, this stack has crippling downsides:

| Challenge | Reason | Impact |
|---|---|---|
| Cost | Every rollout steps through millions of tokens                           | Hours on GPUs per checkpoint |
| Variance | Baselines (`unlikelihood`) must be tuned carefully                      | Instability early in training |
| Hyper‑params | Separate networks (+reward model +policy +K‐L schedule)               | Every run needs grid search     |

## What is Direct Preference Optimization?

Direct Preference Optimization (**DPO**) sidesteps this convoluted dance entirely.
Instead of first fitting an explicit `reward` function then doing an inner REINFORCE loop,
it learns *the policy itself* directly from side-by-side human judgements.
Mathematically it exploits this identity for any reward \(r(x,y)\):

\[
\boxed{\;
\pi_r(y|x)\propto \pi_{\rm ref}(y|x)\,\exp\!\Big(\tfrac{r(x,y)}{\beta}\Big)\;}
\tag{1}
\]

The optimum policy is just rescaled probabilities relative to the reference model
\( \pi_{\rm ref}\).
Rearranging gives an implicit “reward” written entirely through logits:

\[
r(x,y)=
        \beta\,\log \frac{\pi_{r}(y|x)}{\pi_{\rm ref}(y|x)}
        + \beta\,\log Z(x),
        \qquad Z(x)=
          \sum_{y}\pi_{\rm ref}(y|x)\exp\tfrac{r}{\beta}
            .
```

Because Bradley‑Terry’s likelihood depends only on *difference* \(r(x,y_1)-r(x,y_2)\),
the partition term \(Z(x)\) cancels when you plug it into the human preference model.
Hence you can appeal directly to observable data and write a single–step loss :

```math
L_{\textbf{DOP}}=
-\;
\E_{(x,y_w,y_l)}
    {\biggr[
       \log\sigma(
          \beta\,)
         (\,\log\tfrac{\pi_\theta(y_w|x)}{\pi_{\rm ref}(y_w|x)}-
          \log\tfrac{\pi_\theta(y_l|x)}{\pi_{\rm ref}(y_l|x))
       )
     ]}
```

Notable reductions follow immediately:

* One cheap binary cross‑entropy forward pass per labelled pair ‑ *no rollouts.*
* One tunable constant ≈\(β∈[0,5]\). No elaborate KL schedule nor baseline networks.
* Any arbitrary transformer architecture can play both roles—policy + implicit reward.

## How Training Looks In Practice

1️⃣ **Sample reference draws**  
   For every prompt `x` generate two outputs `y_w`, `y_l` from your reference network   
   (`π_ref =` pre‑trained SFT).  Store empirically judged pairs `y_w ≻ y_l`.

2️⃣ **Fitting stage**  
   *Initialize `π_θ` either from the SFT checkpoint or give it a warm‑up chance
      maximizing likelihood on all preferred responses.*  
   Minimize `L_DOP`. Because every term contains only simple logits,
   gradient calculations are trivial while still carrying implicit importance weights  
   (`σ` inside weights punishes worsening ordering).

3️⃣ **Inference**  
   Use your freshly tuned `π_θ`. Cost per batch is just forward passes —
   exactly what legacy supervised/evaluation pipelines already do.

## Why Does This Simpler Online Loss Beat Sophisticated Actor–Critic Methods?

Theoretically disciplined transformation gives three practical advantages simultaneously:

1️⃣ **Eliminate stochastic rollouts** – pure supervised gradients cut training runtime from days down to *few hours.*   
🔎 Example pandas data shows classic ⁰ rollout cost >40× higher than plain forward pass cost.

2️⃣ **Built–in Per‑Example Weighting** – The factor   
\(σ(\hat r_\theta(y_l)-\hat r_\theta(y_w))\)
acts exactly like an adaptive baseline:
the worst‐ordered pairs get pushed harder while already well ordered ones get gentle updates.
If omit this weight it triggers naïve “unlikelihood” behaviour leading to degenerate mode collapse – shown quantitively in Appendix tables.

3️⃣ **Avoid Bias–Variance Dance** –
Actor–critic approaches suffer because their critic must learn a matched value estimate;
any misestimation feeds back catastrophically into policy updates.
In contrast DOP’s loss never contains any extraneous value term –
hence consensus parity across multiple random seeds far improves stability.

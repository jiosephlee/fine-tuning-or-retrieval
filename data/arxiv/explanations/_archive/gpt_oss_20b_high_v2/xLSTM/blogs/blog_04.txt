# Benchmarks Say Sommers  

Large‑language‑model research has been dominated by Transformer‑style attention since **Vaswani et al., 2017**.  
But an organization long obsessed with recurrent nets has returned legacy knowledge and moved it into a truly scalable form – **extended Long Short‑Term Memory** or **x LSTM** – and shows it can beat modern SSMs and transformers on real language data at the billions‑token scale used today.



---  

## Why revisit an old idea?  

The classic LSTM solved vanishing gradients through its constant‑error carousel  

\[
c_t = f_t\, c_{t-1}+i_t\, z_t ,\qquad 
h_t = o_t\, \psi(c_t).
\]

It has long been celebrated in domains where state tracking matters – reinforcement learning agents playing StarCraft II or Dota 2 render true value judgments over hundreds of thousands of timesteps – yet it fell behind when sheer token bandwidth became king’s domain in GPT‑3–style language models. Two facts made this shift plausible:

| Old L‑SAT limitation | What hurts modern language modeling | Proposed remedy in x LSTMs |
|---------------------|-----------------------------------|-----------------------------|
| **Harder to revise past stores** | A model must honor later evidence when revisiting an earlier symbol | Exponential gating plus a normalizer that preserves updated contributions flawlessly |
| **Only scalar memories** | Rare symbols require richer representational capacity | Matrix memories that store key/value pairs via outer-product updates |
| **Sequential recurrence links devices hidden state → next hidden state** | Alleviates quadratic attention cost only at quadratic effort | Parallelizable update formula via covariance rule removes head‑to‑head recurrence |

These patches give us two new building blocks – _s‑MLT_ (scalar), _m‑MLT_ (matrix) – plus a simple residual backbone that turns them into practical **x LLM** components.



---  

## Core ideas behind the new blocks  

### Exponential Gating & Stabilisation  

Instead of sigmoid gates we allow an exponential transform entrance:

```math
i_t   = \exp(\tilde{i}_t),          \quad 
f'_t = \!\exp(\log f_t + m_{t-1} - m_t),
```

with a stabilisation counter \(m_t=\max(\log f_t+m_{t-1},\,\log i_t)\).  
This permits perfectly multiplicative updates \(f'_t i'_t=\exp(\tilde{i}_t + \tilde{f}_t)\) while guarding against overflow – a key trick required for billions‑of‑parameter training.



### Matrix Memory (`m-LSTM`)  

The cell now stores a full matrix \(C_t\in\mathbb R^{d\times d}\):

```math
C_t = f_t\,C_{t-1}+ i_t\, v_t\,k^\top .
```

Because keys \((k)\) and values \((v)\) come from a trainable projection layer
(usually layer‑normed), we are effectively performing covariance updates,
exactly the operation used by Fast‐Weight Programmers.
Retrieval simply multiplies \(C_t q_t\) where \(q_t=\mathbf W_q\,x_t+b_q\).

Matrix memories break through the scalar bottleneck without introducing additional trainable parameters—only matrix products need GPU parallelism.



### Scalar Memory (`s-LSTM`) & Memory Mixing  

The classic cell remains scalar; however enabled gates let multiple cells
be mixed via recurrent weight matrices.
Different “heads” let you split processing streams without cross‑head mixing,
generating richer contextual embeddings proportional to problem size.
Although still partially sequential, CUDA kernels make `s-LST` only slightly slower than `m-LST`.



### Residual Block Backbone  

Both blocks live inside standard layer-norm+residual stacks familiar from transformers:
* **Post‑projection backbones** reuse one hidden dimension before passing through two linear layers (+nonlinearity).
* **Pre‑projection backbones** move computation first into \(d_{\text{hi}}\gg d_{\text{o}}\) then project back,
a design chosen especially for `m-LST` where high dimensional keys grow capacity dramatically.



---  

## Addressing Classic LTLM Weaknesses  

| Problem | Conventional fix | New x LLM solution |
|---------|------------------|---------------------|
| Can't “undo” an earlier write offline | Hardgated RNNs add rewrite capabilities only slowly | Exponential gating ensures every write can be recalibrated instantly by reapplying \(f'_t\); normaliser preserves all arrivals |
| Scalar memory causes poor rare-token recall | Extra hidden dimensions or huge embedding tables | Matrix memory maps hundreds/thousands of key/value pairs into one fast outer product |
| Sequential recurrence kills speed on GPUs | Time-multiplexed attention uses huge batching tricks only loosely adaptable | `m-LST` removes hidden-to-hidden links entirely → fully parallel implementation akin most modern flash-attention kernels |

With these changes every current universal restriction disappears while keeping linear time per token.

## Synthetic Benchmarks Highlight Strengths  

A series of controlled experiments put the two reasoning modes head-to-head against Transformer-style baselines.


### Formal Language Tasks  
(Parity detection, context-free pattern tests)

> ```text
> Task     : Parity checker over binary strings
> Models   : s‐LLM , m‐LLM , gpt-style transformer , RNN baselines
> Result   : Only s-/m‐LLM hit ~100% accuracy ; others plateau at ~20%
> ```
>  
> The inability of transformers/HorizonS with no state mixing is obvious here: you can't track which symbol last flipped parity unless you build integrative recurrent structures – exactly what s/m‐LLMs do.



### Multi‑Query Associative Recall  
(Key/value lookup under compressed resources)

> ```text
> Keys     : Randomly sampled vectors up to size n=256
> Lengths  : T∈[256…2048]
> Measured : Retrieval accuracy
> Result   : x‐LLM[1:1] topped non-transformer baselines,
>            especially when nearing saturation (>200 keys)
> ```
> 


### Long Range Arena  
(General ability on very long sequences)

* `x‐LLM` matched or beat transformer-Wide style coaches on every subtask (copying, reversal, arithmetic ops), even those penalising models when fail to remember items beyond N=4 384 tokens.


Together these tests say: **memory mixing + expanded capacity resolves problems where transparency matters most—state tracking and rare-history recall—and keeps pace where sequence length explodes.**

## Real Language Modelling – Billion Token Scale  

A convincing highlight comes from training Alex Levy’s small stylised LMs against ground truth baselines on the same public corpus:*SlimPajama* — about 15 billion tokens for medium-scale experiments and    300 billion tokens for large-scale runs.


### Medium Scale (≈15 B Tokens)  

Models compared were roughly 350 million parameters—the size commonly associated with open-source GPT‑3 replicas:

| Architecture            | Best Perplexity |
|--------------------------|------------------|
| Transformer (GPT₃ style)| ‑                |
| State Space Model       | ‑                |

A thin programming sweep proved indispensable:
adding residual backbone → passing through ‘post proj’ block → expanding gates → adding matrix memories  
stepwise improved performance exactly along empirical intuition laid out above.

*Only `x–LLM` kept its low PPL (<2× baseline growth*)

#### Validation Perplexity + Downstream Tasks   

On SlimPajama’s held-out set,
`x‐LLM[7:1]` attained PPL ≈30–35% lower than comparable transformers,
and outperformed them across almost all common-sense reasoning benchmarks.
When evaluated on PALOMA’s full suite of fifty-one thousand micro-datasets,
`x–LLM[1:0]` kept lower perplexities in roughly ten‑fold more domains than matching-sized Mamba or transformer models.


#### Scaling Law Curve       

Plotting average loss vs parameter scale follows classic power-law \(loss = A N^\gamma + B\).
All families share approximately identical slope (\(\gamma ≈ −0.34)\),
but intercepts shift leftwards toward `x–LLM`. This means as you grow beyond current GDP,
its extra capacity keeps skirting past competitors’ marginal gains—an encouraging sign for larger budgets.

## Stretching Beyond Text – Where Can it Be Used Next?  

Recurrent processing still shines wherever historical dependencies span enormous horizons while remaining resource light:

* Reinforcement learning agents追踪 integral game states over several thousand frames.
* Hydrological data streams needing signal aggregation over years yet trading off per-sample precision.
* Physics solvers requiring dense equivariance between long-term body interactions.
  


Being cheap both temporally (*Θ(L)* rather than Θ(L²)) &
spatially (*Θ(d²)* computationally & θ(1)* memory*) positions `x-Lstm`s well beyond current domestic air traffic control systems into embedded AI solutions where GPUs cannot drink full-batch workloads.

## Caveats & Future Work 

While benchmarks look promising,

* Non-parallel `_sNL_/mLN_` structures restrict distribution entertainment;
yet custom kernels currently bring them only ~2× slower when tied up against its own matrix counterpart.
* Each added gate needs careful initialization particularly near zero;
our increase was simple roundoff yet holds delicate influence far into forward passes.
* Further tuning could shave large amount away from overhead already manifest at high scale (300 B),
especially optimiser scheduling and mixed float precision — dramatically less cost efficiency now comparable w/out capture heavy re-initialization loss   

Open-source codebase reaches everyone regardless of lab budget (`https://github.com/NX-AI/xlstm`). Researchers interested will find training scripts adapted onto popular checkpoint loaders (`transformers`, `accelerate`, `deepspeed`) using modest compute periods (<10 days × Tesla V100); scaling remained alternate stage definitional reads deeper regularization usage env.

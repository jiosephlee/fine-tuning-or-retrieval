# Reviving Classic RNNs

## Why bring LSTMs back into the spotlight?

Long Short‑Term Memory networks were once the gold standard for sequence modelling – they solved vanishing gradients through a *constant error carousel* and used gating to decide what information stays in memory.  
When Transformers appeared in 2017 they outperformed LSTMs on most benchmarks because self‑attention scales linearly with sequence length and can be parallelised across GPUs.  
Yet three core limitations still hinder classic LSTMs:

1. **No revision** – once a value is stored it can’t be overwritten by a more relevant future observation.
2. **Scalar capacity** – each cell holds only a single number; representing richer contexts requires many cells or external mechanisms.
3. **Sequential dependence** – hidden‑to‑hidden connections force token‑wise processing, preventing efficient parallel inference.

The *xLSTM* family tackles these issues head‑on while keeping the familiar LSTM interface.



## Key innovations of xLSTMs

### Exponential gating + normalisation

Traditional gates use sigmoids ($\sigma$) that saturate quickly:
\[
i_t = \sigma(\tilde{i}_t),\qquad f_t = \sigma(\tilde{f}_t).
\]
xLSTMs replace at least one gate by an exponential:
\[
i_t = \exp(\tilde{i}_t),\qquad f_t = \exp(\tilde{f}_t),
\]
which allows the network to *revise* stored information—if a later token deserves more credit than an earlier one, its gate can grow unboundedly while earlier contributions decay multiplicatively via $f_t$.  
A stabiliser state $m_t$ keeps all exponentials numerically safe without changing gradients.



### sLSTM – scalar cells with memory mixing

The *scalar* variant keeps $c_t \in \mathbb{R}$ but introduces *memory mixing*: hidden states from previous steps feed back into the current cell’s gates and input:
\[
c_t = f_t\,c_{t-1} + i_t\,z_t,\qquad z_t = \varphi(\mathbf{w}_z^\top x_t + r_z h_{t-1}),
\]
and similar recurrent terms appear in every gate computation.  
Because each cell can now look at other cells’ past states, sLSTM solves classic *state‑tracking* problems such as parity or nested parentheses – tasks where Transformers without explicit state tracking fail.



### mLSTM – matrix cells with covariance updates

The *matrix* variant replaces $c_t$ by $\mathbf{C}_t \in \mathbb{R}^{d\times d}$:
\[
\mathbf{C}_t = f_t\,\mathbf{C}_{t-1} + i_t\,\mathbf{v}_t\,\mathbf{k}_t^\top .
\]
Here $\mathbf{k}_t$ is a key vector derived from $x_t$, $\mathbf{v}_t$ is its associated value vector, and $i_t$ controls how much new information enters while $f_t$ implements decay—exactly a *covariance update rule*.  
Retrieval is simply $\tilde{\mathbf{h}}_t=\mathbf{C}_t\,q_t$, where $q_t$ is another projection of $x_t$.  
Because there are no hidden–to–hidden connections, mLSTM is fully parallelisable across time steps.



## From cells to blocks

xLSTMs are wrapped into residual blocks much like modern Transformers:

| Block type | Projection strategy | Why it matters |
|------------|---------------------|----------------|
| **sLSTM block** | Post‑up‑projection | Keeps hidden dimension small during recurrence then expands it nonlinearly |
| **mLSTM block** | Pre‑up‑projection | Uses higher dimensional space for matrix memory before squeezing back |

The blocks sit inside a standard pre‑LayerNorm residual backbone (`LayerNorm → block → residual → LayerNorm`). Stacking dozens of such blocks gives an *xLSTM architecture* that remains linear in sequence length yet retains powerful recurrent dynamics.



## How does it perform?

### Synthetic benchmarks

* **Formal languages / parity** – Only models capable of memory mixing solve these tasks. On such benchmarks sLSTMs outperform plain Transformers and SSMs by large margins.
* **Multi‑Query Associative Recall** – With up to 256 key/value pairs per sequence and context length 2048, xLSTMs[1:1] match or beat Transformer baselines that rely on attention matrices.
* **Long Range Arena** – Across diverse long‑context tests (image captioning, document classification), xLMs consistently rank among the top performers.



### Large language modelling

On 15 B tokens from SlimPajama:

* A 350 M parameter xLLM achieved lower validation perplexity than GPT‑3‑style transformers (~350 M) and SSMs such as Mamba or H3.
* Scaling experiments show xLLM’s performance improves at roughly the same rate as larger transformers but starts from a higher baseline—its offset in the power‑law scaling curve is smaller.



On 300 B tokens:

* **Sequence extrapolation** – When tested on contexts up to 16 k tokens after training at 2 k tokens, xLLM’s perplexity stays flat while transformer baselines degrade sharply.
* **Downstream tasks** – Across common‐sense reasoning benchmarks (ARC, PIQA) xLLM outperforms both RWKV (RNN) and Mamba (SSM) at every model size tested.
* **Domain coverage** – On PALOMA’s 571 diverse text domains, over 99 % of domains see lower perplexity under xLLM[1:0] compared with both transformer and RNN baselines.



## Practical takeaways

| Feature | Classic LSTM | Transformer | State Space Model | xLLM |
|---------|--------------|-------------|-------------------|------|
| Parallelism | Sequential | Fully parallel | Fully parallel | Mixed (mLLM fully parallel; sLLM sequential) |
| Sequence length scaling | Linear compute & constant mem | Quadratic attention cost | Linear compute & constant mem | Linear compute & constant mem |
| Storage capacity per cell | Scalar | Implicit via attention weights | Implicit via state matrices | Explicit via matrix memories |
| Ability to revise past writes | No | No explicit mechanism | No explicit mechanism | Yes via exponential gates |
| Empirical language modelling performance | Outperformed by Transformers early on | State of art until recently | Competitive when scaled well | Matches / exceeds current SOTA |

In practice this means you can build billion‑parameter models that run efficiently on GPUs without needing flash attention tricks or large KV caches.



## Looking forward

xLLM shows that classic recurrent logic still has untapped potential once you give it modern tools—exponential gates for dynamic revisiting and matrix memories for richer storage—while preserving linear time complexity across sequences. Future work will likely focus on:

* Optimising CUDA kernels for mLLM so its runtime matches FlashAttention,
* Exploring hybrid architectures where shallow layers use sLLM for fine state tracking while deeper layers employ mLLM,
* Applying these ideas beyond NLP—time series forecasting, reinforcement learning agents that must track entities over long horizons, or physical simulators requiring causal reasoning over thousands of steps.

For anyone who has felt nostalgic about RNNs yet wants competitive performance today, extended LSTMs offer an elegant bridge between old wisdom and new scale.”



# Why Exponential Gates Matter

When we think of a Long Short‑Term Memory (LSTM), the most iconic image is a set of three sigmoidal gates – input, forget and output – that regulate how information flows through time.  
That classical design has served the deep learning community for decades, yet recent work shows that replacing those sigmoids with exponential functions unlocks an entirely new capacity for *state revision*: the ability to overwrite earlier memory when a stronger signal arrives later in a sequence.  This small change turns plain LSTMs into **xLSTMs** – unsupervised “plugg‑and‑play” building blocks that match or surpass modern Transformer‑style models on large language tasks while keeping linear time complexity.



---

## The Classic Four‑Gate Stack

Standard LSTMs update their scalar cell state \(c_t\) and hidden state \(h_t\) according to

\[
\begin{aligned}
c_t &= f_t\, c_{t-1} + i_t\, z_t \\
h_t &= o_t\, \psi(c_t)
\end{aligned}
\]

with the gates themselves coming from weighted sums followed by a sigmoid:

\[
i_t = \sigma(\tilde{i}_t), \qquad
f_t = \sigma(\tilde{f}_t), \qquad
o_t = \sigma(\tilde{o}_t).
\]

Because \(\sigma(x)\in(0,1)\), information can only be *suppressed* but never *amplified*.  In long sequences that feature revisitable context — think about looking up a key once you find a matching query further ahead — this restriction quickly becomes a bottleneck.



---

## When Memory Needs Revision

A concrete illustration comes from a synthetic “Nearest Neighbor Search” benchmark:

1. A reference vector is set at the start.
2. The model scans through many input vectors.
3. At the end it must output the value attached to the *closest* vector seen during the scan.

On this task vanilla LSTMs struggle because early choices are effectively locked in by their sigmoid forget gate: once \(f_t\) has become very small, increasing its value later almost has no effect on \(c_t\).  Experiments show that an xLSTM equipped with exponential gating **completely eliminates this error**, achieving near‑perfect accuracy even when millions of steps have elapsed.



---

## Exponential Gating in Detail

The key intuition is simple – let gates be allowed to grow beyond one instead of being capped at one:

| Gate | Classic | New |
|------|---------|-----|
| Input | \(i_t = \sigma(\tilde{i}_t)\) | \(i'_t = e^{\tilde{i}_t}\) |
| Forget | \(f_t = \sigma(\tilde{f}_t)\) | Either \(f'_t = e^{\tilde{f}_t}\) or still sigmoidal |

When an exponential gate turns up late in a sequence its contribution will dominate all previous updates because it multiplies the existing cell state rather than adding a bounded amount.  To keep training stable we also maintain two auxiliary states:

* **Normalizer** \(n_t = f_t\, n_{t-1} + i_t\)
* **Stabilizer** \(m_t = \max(\log f_t + m_{t-1},\, \log i_t)\)

The hidden activation is then normalized as
\[
h_t = o_t\, \frac{c_t}{n_t},
\]
ensuring that exponentially large values do not explode numerically.



---

## How This Helps

* **Revising Stored Keys** – By allowing gates to grow arbitrarily large, an xLSTM can overwrite earlier key–value pairs when it encounters a more relevant example later.
* **Preventing Saturation** – Sigmoids quickly saturate for large inputs; exponentials never do so, giving the network more expressive dynamics.
* **Preserving Gradient Flow** – Exponentials maintain non‑zero gradients even far back in time because they multiply rather than squish values.



---

|------|-------|----------|

---

## Scaling Up to Billion‑Parameter Language Models

The authors trained full xLSTM architectures on 15 B tokens from SlimPajama and compared them to Transformers and State Space Models at *350 M parameters each*.  Across all setups:

* **xLSTM achieved lower per‑token perplexity than every baseline**.
* During extrapolation to longer contexts (up to 16k tokens), xLMM preserved low perplexities while Transformer models suffered quadratic slow‑down.
* Scaling curves show that as parameter counts grow beyond 1 B, xLMDe futures outstrip both Transformers and SSMs consistently.



---

## Where It Still Has Work To Do

While promising, several practical concerns remain:

1. **Parallelisation:**  
   The scalar sLSTM’s hidden‑hidden mixing prevents embarrassingly parallel kernels, though CUDA implementations stay within two× CPU speed.
2. **Complex Matrix Calculations:**  
   mLSTMs require \(d\times d\) matrix operations per step; until well–optimised kernels appear this can be an overhead.
3. **Memory Overheads at Extreme Lengths:**  
   Because mLSTMs hold a fixed–size matrix regardless of context length, ultra‑long sequences might stretch device RAM limits.



Nonetheless these are engineering problems that can be addressed as frameworks mature—it’s unlikely they will erase the underlying algorithmic gains brought by exponential gates.



---

## Bottom Line

Replacing sigmoidal input/forget gates with exponentials isn’t just a tweak—it *fundamentally remediates one of LSTMs’ hardest shortcomings*: herding memory forever once it’s written into cell states.  With this simple change—and complementary matrix memories—xLSTMs demonstrably outperform today’s leading language models in both learning speed and generalisation across long contexts.

If you’re building recurrent systems today—whether for RL agents that chase long‐term rewards or forecasting pipelines that juggle long time horizons—give your old-school LSTM an exponential makeover before you cast your nets for anything more exotic.



# Matrix Memory Gets Fast

## Why upgrade an LSTM cell?
The classic Long Short‑Term Memory (LSTM) keeps its historical knowledge inside a **single scalar** \(c_{t}\).
Because everything must fit into that single number,
the model struggles whenever it needs more than a few bits:
it cannot revise old storage decisions reliably,
its tiny cache hurts rare‑token predictions,
and every timestep forces an expensive hidden‑to‑hidden recurrence,
so inference grows linearly with the sequence length.
The new **extended** family—xLSTMs—substitutes this scalar space with a *full*  
\(d\times d\) **matrix** \( \boldsymbol C_{\,t}\).
This twist dramatically expands what can be remembered *without* adding extra learnable parameters and keeps the same linear dependence on sequence‐length **free** of quadratic attention costs.



## The Matrix Memory (`m`‑LSTM)
Instead of updating one number,

```text
cₜ = fₜ c₍ₜ₋₁₎ + iₜ zₜ            ← vanilla LSTM
```

the m–LSTM forms a **covariance update**

```text
𝒞ₜ   = fₜ ∘𝒞₍ₜ₋₁₎ + iₜ ∘(𝒗ᵗ_kᵀ),
```

where  
\(i_{\,t}\in(0,\infty)\) controls how strongly a new *key/value* pair touches the cache,
\(f_{\,t}\in(0,\infty)\) throttles background forgetting,
and \(∘\) denotes element‑wise multiplication.
Initially both gates are generated just like any other LSTM gate—
but thanks to exponential activation they can span wide ranges while remaining numerically stable thanks to an internal stabilizer \(m_{\,t}\)(Equation (10)–(12)).



After every “write” comes a “read”

```text
h̃ₜ   = 𝒞ₜ · q̃ₜ   /   max{|nᵗᵀq̃ₜ| , 1},
hₜ   = õₜ ⊙ h̃ₜ,
```

The vector \(q̃=\!W_qx+ b_q\) is an **attended query**,
\(n_{\,t}=f_{\,t} n_{τ−1}+i_{τ} k_{\tau}\)
is its ROC‑style normalizer,
and finally the returned hidden state mixes this retrieved content with an output gate.
In short:
a single *auxiliary line* of gpu‐friendly GEMMs writes **one outer product**  
\(v k^{T}\;\rightarrow 𝒞_τ^{+ℕ}\);  
a second GEMM multiplies the whole cache against any incoming query.\[

public keys & values entirely rather than keeping them separately.

# Benchmarks Say Sommers  

Large‑language‑model research has been dominated by Transformer‑style attention since **Vaswani et al., 2017**.  
But an organization long obsessed with recurrent nets has returned legacy knowledge and moved it into a truly scalable form – **extended Long Short‑Term Memory** or **x LSTM** – and shows it can beat modern SSMs and transformers on real language data at the billions‑token scale used today.



---  

## Why revisit an old idea?  

The classic LSTM solved vanishing gradients through its constant‑error carousel  

\[
c_t = f_t\, c_{t-1}+i_t\, z_t ,\qquad 
h_t = o_t\, \psi(c_t).
\]

It has long been celebrated in domains where state tracking matters – reinforcement learning agents playing StarCraft II or Dota 2 render true value judgments over hundreds of thousands of timesteps – yet it fell behind when sheer token bandwidth became king’s domain in GPT‑3–style language models. Two facts made this shift plausible:

| Old L‑SAT limitation | What hurts modern language modeling | Proposed remedy in x LSTMs |
|---------------------|-----------------------------------|-----------------------------|
| **Harder to revise past stores** | A model must honor later evidence when revisiting an earlier symbol | Exponential gating plus a normalizer that preserves updated contributions flawlessly |
| **Only scalar memories** | Rare symbols require richer representational capacity | Matrix memories that store key/value pairs via outer-product updates |
| **Sequential recurrence links devices hidden state → next hidden state** | Alleviates quadratic attention cost only at quadratic effort | Parallelizable update formula via covariance rule removes head‑to‑head recurrence |

These patches give us two new building blocks – _s‑MLT_ (scalar), _m‑MLT_ (matrix) – plus a simple residual backbone that turns them into practical **x LLM** components.



---  

## Core ideas behind the new blocks  

### Exponential Gating & Stabilisation  

Instead of sigmoid gates we allow an exponential transform entrance:

```math
i_t   = \exp(\tilde{i}_t),          \quad 
f'_t = \!\exp(\log f_t + m_{t-1} - m_t),
```

with a stabilisation counter \(m_t=\max(\log f_t+m_{t-1},\,\log i_t)\).  
This permits perfectly multiplicative updates \(f'_t i'_t=\exp(\tilde{i}_t + \tilde{f}_t)\) while guarding against overflow – a key trick required for billions‑of‑parameter training.



### Matrix Memory (`m-LSTM`)  

The cell now stores a full matrix \(C_t\in\mathbb R^{d\times d}\):

```math
C_t = f_t\,C_{t-1}+ i_t\, v_t\,k^\top .
```

Because keys \((k)\) and values \((v)\) come from a trainable projection layer
(usually layer‑normed), we are effectively performing covariance updates,
exactly the operation used by Fast‐Weight Programmers.
Retrieval simply multiplies \(C_t q_t\) where \(q_t=\mathbf W_q\,x_t+b_q\).

Matrix memories break through the scalar bottleneck without introducing additional trainable parameters—only matrix products need GPU parallelism.



### Scalar Memory (`s-LSTM`) & Memory Mixing  

The classic cell remains scalar; however enabled gates let multiple cells
be mixed via recurrent weight matrices.
Different “heads” let you split processing streams without cross‑head mixing,
generating richer contextual embeddings proportional to problem size.
Although still partially sequential, CUDA kernels make `s-LST` only slightly slower than `m-LST`.



### Residual Block Backbone  

Both blocks live inside standard layer-norm+residual stacks familiar from transformers:
* **Post‑projection backbones** reuse one hidden dimension before passing through two linear layers (+nonlinearity).
* **Pre‑projection backbones** move computation first into \(d_{\text{hi}}\gg d_{\text{o}}\) then project back,
a design chosen especially for `m-LST` where high dimensional keys grow capacity dramatically.



---  

## Addressing Classic LTLM Weaknesses  

| Problem | Conventional fix | New x LLM solution |
|---------|------------------|---------------------|
| Can't “undo” an earlier write offline | Hardgated RNNs add rewrite capabilities only slowly | Exponential gating ensures every write can be recalibrated instantly by reapplying \(f'_t\); normaliser preserves all arrivals |
| Scalar memory causes poor rare-token recall | Extra hidden dimensions or huge embedding tables | Matrix memory maps hundreds/thousands of key/value pairs into one fast outer product |
| Sequential recurrence kills speed on GPUs | Time-multiplexed attention uses huge batching tricks only loosely adaptable | `m-LST` removes hidden-to-hidden links entirely → fully parallel implementation akin most modern flash-attention kernels |

With these changes every current universal restriction disappears while keeping linear time per token.

# Future Uses Beyond Text  

In the world of reinforcement learning (RL) and edge computing, being able to *remember* past events with almost zero latency is often as important as processing future actions quickly.  The Extended Long Short‑Term Memory (xLSTM) brings exactly that “state tracking” capability back into mainstream deep learning while keeping inference light enough for even small devices.

---

## 1. Why State Tracking Matters

* **Game play histories** – In complex RTS games like StarCraft II or Dota 2 an agent has to decide on the next move while remembering dozens of actions that occurred seconds earlier.
* **Planning with long horizons** – A robotics controller must know the sequence of commands it has issued in order to recover from a slip.
* **Low‑latency edge apps** – Voice assistants, AR overlays, or on‑device translation must update their predictions after every user interaction without large kernels or caches being rebuilt.

The bottleneck is usually the *memory interface*: many neural models either forget what they just processed (standard RNNs) or are too slow / too costly when the history gets long (Transformers).

---

## 2. Conventional Models at a Glance  

| Model | Scaling | Memory | State Tracking |
|-------|---------|--------|----------------|
| **Transformer** | \(O(L^2)\) attention | Quadratic in context | Limited by self‑attention across tokens |
| **Original LSTM** | \(O(L)\) recurrence | Scalar cell per head | Cannot *revise* stored info once cached |
| **State Space Model** | \(O(L)\) linear dynamics | One hidden vector | No explicit “write” gate |

These constraints make them less than ideal when *instant revisions* are required—exactly what we see in hard RL tasks or close‑to‑real‑time services on edge gadgets.

---

## 3. Enter xLSTM  

xLSTM augments the classic LSTM with two key innovations:

### 3.1 Exponential Gating

Instead of mere sigmoid gates, xLSTM’s input \(i_t\) and forget \(f_t\) gates can be exponentiated:

\[
\begin{aligned}
c_t &= f_t\,c_{t-1} + i_t\,z_t \\
i_t &= \exp(\tilde{i}_t), \qquad 
f_t = \sigma(\tilde{f}_t)\ \text{or}\ \exp(\tilde{f}_t)
\end{aligned}
\]

* **Why it matters** – Exponential gates allow an instantaneous “rewriting” of past memories because they can grow without the natural cap imposed by sigmoids.
* **Stabilization** – A small auxiliary *stabilizer* \(m_t\) keeps these exponentials from overflowing during training, so backpropagation remains stable.

### 3.2 Two New Memory Structures  

| Variant | Memory form | Key advantage |
|---------|-------------|---------------|
| **sLSTM** (scalar version) | Single scalar cell per head → mixed via recurrent matrix \(\mathbf{R}\) → *memory mixing* |
| **mLSTM** (matrix version) | Full \(d\times d\) matrix \(\mathbf{C}\); stores key/value pairs via covariance update \(\mathbf{C}_t=\mathbf{C}_{t-1}+i_t\,v_tk_t^\top\) |

* **sLSTM**   
  *Revises*: thanks to memory mixing across cells within a head,
    an LSTMPhi can overwrite previous entries immediately.
  *Use case*: directly tracking finite game states like “which enemy unit was hit last”.

* **mLSTM**
  *Capacity*: a matrix can hold many associations simultaneously,
    akin to a fast weight memory or associative recall network.
  *Efficiency*: although each forward step processes a \(d\times d\) matrix,
    modern GPUs can perform this entirely in parallel, keeping inference linear in sequence length.
  *Use case*: remembering thousands of context items during long‐range document comprehension
    without quadratic attention costs.

Both variants are wrapped inside residual blocks called **xLSTM blocks**, which give each layer a higher dimensional embedding space before projecting back—a trick inspired by Cover’s theorem that makes patterns easier to separate linearly.

---

## 4. Instant History Retrieval in RL Agents  

Imagine an agent playing StarCraft II that needs to answer “What attack just happened?” right after seeing an action token:

```
... ATTACK_ECS_UNIT AT_POSITION_X...
```

With a vanilla LSTM:
1. The token is passed through one recurrent cell.
2. The stored value is fixed until the next time step—revising it would require setting all following gates manually.

With an sLSTM:
1. The same token updates the scalar cell via exponential input gate.
2. If another “ATTACK” token arrives later,
   its high input gate immediately overwrites the earlier value *without waiting for future steps*, thanks to exploding updates and memory mixing inside the block.
3. This means that at any moment the hidden state truly reflects “the last attack” exactly where it matters most for decision making—no additional lookups required!

state–tracking makes policy networks leaner—they no longer need large attention caches or manually engineered memories—yet they perform just as well as explicitly trained transformer baselines when trained at scale (~15 B–300 B tokens).

---

## 5. Ultra‑Low Latency Edge Apps  

Why does this model shine on embedded machines?

| Property | How xLSTM Helps |
|----------|------------------|
| **Linear time per token** | Only one recurrence per token versus \(O(L^2)\)/attention |
| **Constant memory footprint** | Cell update needs no additional buffers regardless of sequence length |
| **Parallelizable matrix operations** (mLSTM) | Offload heavy parts entirely on GPU/CPU SIMD lanes |

Concrete scenarios:

* **Real‑time voice translation embedded inside smart glasses:** The model processes spoken tokens one by one and updates its internal context instantly—no lag from recalculating attention over whole transcripts.
* **On‑device storytelling assistant:** As new story beats arrive, mLSTM’s associative recall instantly suggests relevant metadata (e.g., character histories), enabling instant responses without caching large models on disk.
* **Industrial control systems:** Sensor streams feeding into an sLSTM module can revive recent anomaly flags immediately when newer readings confirm them—leading up-to-date control decisions with sub‑millisecond latency.

These are just examples—any application where “last\nonce\nedited\nstate” is critical can benefit from an xLSTM backbone.

---

## 6. Broader Implications for AI Infrastructure  

1. **Versatility across heads** – xLSTMs support multiple dependent heads while still allowing independent memory mixing within each head—great for multi‑task settings (e.g., simultaneously handling language + vision streams).
2. **Better scaling laws** – Experiments show that as parameter counts grow beyond billions, xLSTMs maintain or surpass transformer performance without exploding inference costs.
3. **Interoperability with existing libraries** – Code is available on GitHub (*https://github.com/NX-AI/xlstm*) and plugges into standard PyTorch pipelines by replacing `nn.LSTM` layers with `xslstm` modules; few additional knobs are needed besides learning rate tuning (`w_{fi}` etc.).

Thus developers can roll out performance competitive large models even on subscription clouds or resource-constrained devices without sacrificing interpretability (the hidden state remains easily understandable thanks to explicit gating).

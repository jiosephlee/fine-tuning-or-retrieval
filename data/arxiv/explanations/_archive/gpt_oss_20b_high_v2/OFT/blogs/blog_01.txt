\title{Blogs about the Paper: "Controlling Text-to-Image Diffusion by Orthogonal Finetuning"}

# Orthogonal Finetuning for Diffusion Models  

**Discover the core idea behind Orthogonal Finetuning (OFT): learning a small orthogonal transform that rotates neurons layer‑wise instead of tweaking weights outright. See how this elegant trick keeps the model’s original knowledge intact while giving it new creative powers.**  

---

## Why finetune diffusion models at all?

Text‑to‑image diffusion nets such as Stable Diffusion or SD 1.5 can already create photorealistic pictures from a sentence prompt.  
But real‑world applications often need extra control:

* **Subject‑driven generation** – you give the model a handful of photos of a person or object and want it to render that same subject in novel settings.
* **Controllable generation** – you feed an additional cue like a Canny edge map or a semantic segmentation mask together with a caption and expect an image that obeys the cue exactly.

Fine‑tuning a pretrained diffusion model is the simplest way to inject that extra functionality. In practice people tweak either all layers with tiny steps (DreamBooth) or add small learnable adapters such as LoRA’s low‑rank update matrices. Both methods work somewhat but they have a fundamental flaw: **they don’t guarantee that the powerful ”knowledge” learned during pretraining stays intact**.



## Where does existing finetuning go wrong?

A vanilla update takes the form  

\[
\mathbf{W} \;\longleftarrow\; \mathbf{W} + \Delta \mathbf{W},
\]

where \(\Delta\mathbf{W}\) can point anywhere in weight space if the learning rate is large enough.  
The implicit hope is that “small Euclidean change” (\(\|\Delta\mathbf{W}\|_F\le\epsilon\)) keeps everything sensible—yet there’s no formal reason any particular direction in weight space preserves semantics.

If we look at what neural nets actually do, we notice something quite different:



* Each unit in hidden layers works essentially as an **angle detector** if we normalise its incoming weights.
* What makes activations distinguish one semantic class from another are often just **pairwise angular relationships** between units.
* The quantity called *hyperspherical energy* captures exactly those relations:
  
  \[
  \operatorname{HE}(\mathbf{W}) \;=\;\sum_{i\neq j}\!\Bigl\lVert
      \hat{\mathbf{w}}_i-\hat{\mathbf{w}}_j
  \Bigr\rVert^{-1},
   \qquad
   \hat{\mathbf{w}}_i=\frac{\mathbf{w}_i}{\|\mathbf{w}_i\|}.
  \]

If two weight matrices have identical hyperspherical energy then **all pairwise cosine similarities among their neurons are identical**, meaning they represent the same internal geometry.



## The key insight – preserve angles!

Orthogonal matrices preserve lengths *and* all angles:

\[
\forall\, i,j :\
      (\mathbf{R}\hat{\mathbf w}_i)\!\cdot(\mathbf{R}\hat{\mathbf w}_j)
      =\hat{\mathbf w}_i\!\cdot\hat{\mathbf w}_j ,
   \qquad
   \text{if }\, \mathbf{R}^\top\!\mathbf{R}=I .
\]

So if we replace every weight matrix by an orthogonally transformed version,

\[
   \boxed{
        \widetilde{\!{\bf W}}
          = {\bf R}\,\bigl({\bf W}_0\bigr),
        }
   \qquad
   {\bf R}^\top {\bf R}=I,
\]

the hyperspherical energy stays exactly as it was before finetuning!  

That guarantees we never alter pairwise neuron similarities – the semantic backbone remains untouched.



## How does one learn such an orthogonal delta?

### Block–diagonal Cayley parametrization  

An arbitrary \(d\times d\) orthogonal matrix contains \(d(d-1)/2\) degrees of freedom – far too many when \(d=1280+.\)
We restrict ourselves to a block–diagonal form:

```
R =
diag( R₁ , … , Rₖ )       ,     Rₗ ∈ O(d/k).
```

Each block \(R_\ell\) can be generated through the *Cayley transform*

```
R_ℓ = (I + Q_ℓ)(I − Q_ℓ)⁻¹,
```

where \(Q_\ell^\top = −Q_\ell.\)
This change carries out two benefits:

1. **Orthogonality is guaranteed by construction** (no extra regularisers).
2. **Trainable parameters drop dramatically**:
   • Without sharing,
     number = ∑ₗ d/k·(d/k−1)/2 ≃ d²/k.
   • With full sharing,
     number = d²/k².



### Constrained Orthogonal Finetuning (COFT)

Sometimes we also want to keep the update modestly close to identity so training never drifts far from the pretrained model:

```
‖R – I‖₂ ≤ ε .
```

In practice we enforce this ε‑constraint inside the Cayley parametrisation:
after each gradient step we simply project \(Q_\ell → Q_\ell / ‖Q_\ell‖₂ × ε .\)

This extra restraint yields even calmer convergence when dealing with few training images.



### Optional magnitude re‑scaling  

Because hyperspherical energy cares only about angles,
multiplying each column by a positive scalar does NOT affect it.
A tiny extension adds a diagonal matrix \(D=\operatorname{diag}(s_1,…,s_n)\):

```text
z = xᵀ (R⋅W₀⋅D).
```

The learning signal therefore gets slightly richer while still preserving angles.



## Why does this work well in practice?

| Angle‑based | Parameter count | Privacy |
|--------|--------------------|----------|
| **OFT / COFT** | ~k·d²/4 for k blocks | Almost none |
| **LoRA** | r'·(d+n) | non‑zero |

Empirically:

1. **Fast convergence** – OFT learns meaningful edits within ~8–12 epochs whereas other methods need >20.
2. **Stability** – No sudden collapse even with large learning rates because gradients walk along an exact hypersphere manifold.
3. **No extra inference latency** – once trained, you plonk the learnt \(R_\ell\)’s into pretrained weights before inference; there is no new network component at run‑time.
4. **Higher quality controls** – On benchmark tasks like “canny edges → image” or “face landmarks → face”, OFT outperforms ControlNet and T2I‑Adapter on both control fidelity metrics and visual artefacts.



## Quick recap of what’s happening layer‑by‑layer  

For each fully connected or attention matrix \(W_0∈ℝ^{d×n}\):

```text
Step 1 : initialise all blocks to identity → W ≈ W₀ .
Step 2 : in back‑prop expose only block Qℓ → compute gradient G_Qℓ .
Step 3 : update Qℓ ← Qℓ + η G_Qℓ
          → optionally clip onto ε ball if using COFT .
Step 4 : rebuild each block via Cayley → Rℓ .
Step 5 : forward pass uses modified weight Ŵ = diag(R₁,…,R_k){·}W₀ .
```

Because **every forward pass still involves only linear multiplication**, GPU memory consumption stays almost identical to vanilla fine‑tune.



## From theory back into real images

### Subject‑driven generation  
With just five subject photos and once costing ~400 training iterations:
* OFT perfectly keeps identity while faithfully respecting textual prompts.
* DreamBooth’s identity drops eventually; LoRA fails earlier altogether.

Quantitatively OFT scores highest on CLIP–I / DINO subject similarity,
and comparable diversity metrics.


### Controllable generation  
For tasks requiring strict alignment with arbitrary contours or segmentation maps:
* Control consistency scores rise sharply when using OFT/COFT.
* Visual inspection shows lower blurriness and fewer semantic hallucinations compared to state‑of‐the‐art adapters.


All these experiments were run on Stable Diffusion v1.5 with minimal modifications required—just interpose an extra learned block per large matrix.



## Bottom line 

Orthogonal Finetuning teaches us that *the geometry of neuron directions carries most of a diffusion net’s knowledge*.  
By rotating neurons rather than nudging them around arbitrarily,
we can:

- Preserve pretraining semantics with mathematical guarantees;
- Use far fewer trainable parameters;
- Reach fast, stable convergence;
- Add no costs at inference time.

If you’re interested in your own domain–specific edits—be it style transfer, domain adaptation, or cross‑modal alignment—OFT gives you a principled toolbox that keeps your base model “healthy” while grafting precise new behaviors.

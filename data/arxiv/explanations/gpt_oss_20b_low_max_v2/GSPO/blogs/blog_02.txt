# From Theory to Practice: How GSPO Re‑defines Preference Learning for LLMs

Large language models are increasingly being tuned with reinforcement learning (RL) that relies on preference signals from humans or automatic verifiers. The key to successful RL‑based fine‑tuning is *how* we measure how “off‑policy” a sampled response is compared to the current policy. The classic approach, **Group Relative Policy Optimization (GRPO)**, applies importance weights at the token level. In practice this leads to explosive variance, catastrophic crashes, and a bewildering amount of engineering work—especially when the model in question is a sparse **Mixture‑of‑Experts (MoE)** network.

**Group Sequence Policy Optimization (GSPO)** turns the problem on its head. By measuring importance at the *sequence* level and clipping entire responses instead of individual tokens, GSPO yields a far more stable, efficient, and plug‑and‑play training loop. Below we walk through the math, the intuition, and a minimal code skeleton that you can drop into your own RL pipeline.

---

## 1. Background: The Problem with Token‑level Weighting

When we generate a response \( y = (y_1,\dots,y_{|y|}) \) from an old policy \( \pi_{\theta_{\text{old}}} \), GRPO updates the new policy \( \pi_\theta \) using an objective like

\[
\mathcal{J}_{\text{GRPO}}(\theta) = \mathbb{E}_{x,\{y_i\}}\Bigg[\frac{1}{G}\sum_{i}\frac{1}{|y_i|}\sum_{t}
\min\bigl(w_{i,t}(\theta)\hat A_i,\;\text{clip}(w_{i,t}(\theta),1-\varepsilon,1+\varepsilon)\hat A_i\bigr)\Bigg]
\]

where

* \( w_{i,t}(\theta)=\frac{\pi_\theta(y_{i,t}\mid x,y_{i,<t})}{\pi_{\theta_{\text{old}}}(y_{i,t}\mid x,y_{i,<t})} \)
* \( \hat A_i \) is the normalized advantage for *all* tokens in response \( y_i \).

The problem is subtle but crippling: each token’s importance weight is computed **once**, using only that token’s next‑token distribution. No averaging over many samples takes place, so there is no true “importance sampling” correction. When token likelihoods vary wildly—especially in long responses or MoE models where routing can change on every step—the resulting gradients become high‑variance and can push the policy off course.

> **TL;DR**: Token‑level weighting in GRPO breaks the assumptions of importance sampling, leading to instability, especially when responses are long or when expert routing changes.

---

## 2. The GSPO Idea in Plain English

**GSPO replaces token weights with a single sequence weight**:

\[
s_i(\theta) \;=\; \biggl(\frac{\pi_\theta(y_i\,|\,x)}{\pi_{\theta_{\text{old}}}(y_i\,|\,x)}\biggr)^{\!1/|y_i|}
\]

This is just the *geometric mean* of all token ratios in the sequence. Conceptually:

1. **We treat the whole reply as one atomic unit.**  
2. **We correct for off‑policy bias only once per sample**, by reweighting the entire likelihood ratio.
3. **We clip that ratio (`s_i`) instead of clipping individual token ratios**, ensuring that badly off‑policy responses provide no gradient signal.

The resulting objective is

\[
\mathcal{J}_{\text{GSPO}}(\theta)=
\mathbb{E}_{x,\{y_i\}}\Bigg[\frac{1}{G}\sum_{i}
\min\bigl(s_i(\theta)\hat A_i,\;\text{clip}(s_i(\theta), 1-\varepsilon_L, 1+\varepsilon_R)\hat A_i\bigr)\Bigg]
\]

where \( 0<\varepsilon_L< \varepsilon_R \ll 1 \) (typically \(10^{-4}\)).

Because all tokens in a response share the same weight, GSPO avoids the high variance introduced by token‑level corrections. Moreover, the length normalisation inside `s_i` keeps sequences of different lengths comparable and prevents very short replies from dominating training.

## 3. Step‑by‑Step Implementation Guide

Below you’ll find a minimal PyTorch skeleton that shows how to:

1. Sample queries & responses.
2. Compute rewards via a verifier.
3. Calculate sequence-level likelihood ratios.
4. Compute advantages and go through clipping.
5. Backpropagate for policy update.

> **Note**: This code intentionally ignores KL regularisation and other engineering tricks for brevity; plug it into your existing RL loop as needed.

```python
import torch
import torch.nn.functional as F
from torch.distributions import Categorical

# --------------------------------------------------
# Helper: softmax over vocab logits
def logits_to_probs(logits):      # shape: (batch, seq_len, vocab)
    return F.softmax(logits, dim=-1)

# --------------------------------------------------
# 0️⃣ Sample queries from dataset D
queries = sample_queries(batch_size=B)

# 1️⃣ Rollouts: G responses per query
logits_old = policy_old(queries)      # shape: (B, max_len, vocab)
probs_old = logits_to_probs(logits_old)
dist_old = Categorical(probs_old)

responses = []   # list of list of tensors
logprobs_old_total = []   # sequence log-likelihoods under old policy

for g in range(G):
    # Sample token by token (can also do beam / top-p )
    resp_tokens = dist_old.sample()                      # shape: (B, max_len)
    mask = end_token_mask(resp_tokens)                   # shape: (B,)
    seq_logprob = dist_old.log_prob(resp_tokens).sum(dim=1)   # (B,)
    
    responses.append(resp_tokens)
    logprobs_old_total.append(seq_logprob)

logprobs_old_total = torch.stack(logprobs_old_total)   # (G,B)

# --------------------------------------------------
# 2️⃣ Compute rewards r(x,y)
rewards = compute_rewards(queries, responses)          # shape: (G,B)

# Normalise per group to get advantages
adv = rewards - rewards.mean(dim=0, keepdim=True)
adv /= rewards.std(dim=0, keepdim=True) + 1e-8          # shape: (G,B)

# --------------------------------------------------
# 3️⃣ Sequence likelihood under current policy πθ
logits_new = policy_new(queries)
probs_new = logits_to_probs(logits_new)
dist_new = Categorical(probs_new)

logprobs_new_total = []
for g in range(G):
    resp_tokens = responses[g]
    seq_logprob_new = dist_new.log_prob(resp_tokens).sum(dim=1)
    logprobs_new_total.append(seq_logprob_new)

logprobs_new_total = torch.stack(logprobs_new_total)   # (G,B)

# --------------------------------------------------
# 4️⃣ Importance ratio per token + length-normalised ratio per sequence
ratio_per_token     = torch.exp(logprobs_new_total - logprobs_old_total)     # (G,B)
ratio_seq_gen       = ratio_per_token.exp()                                 # just e^{Δlogprob}

s_ratio            = ratio_seq_gen.clamp(min=0.).pow(1 / seq_lengths.float())   # geometric mean

# --------------------------------------------------
# 5️⃣ Clipping
eps_l, eps_r   = 3e-4 , 4e-4        # left/right clipping epsilons
clipped_ratio   = torch.clamp(s_ratio,
                               min=1 - eps_l,
                               max=1 + eps_r)

surrogate      = torch.min(
                    s_ratio * adv,
                    clipped_ratio * adv
                 )                                                  # shape: (G,B)

loss_policy    = -surrogate.mean()                              # negative for ascent

# --------------------------------------------------
# 6️⃣ Optimiser step
optimizer.zero_grad()
loss_policy.backward()
torch.nn.utils.clip_grad_norm_(policy_new.parameters(), max_norm=5.)
optimizer.step()
```

### Explanations of Key Lines

- **`ratio_per_token`** computes per-token likelihood ratios; `ratio_seq_gen` accumulates them across time steps.
- **`s_ratio`** takes the geometric mean (`pow(1 / seq_lengths)`), yielding a single scalar per response.
- **Clipping** uses two distinct bounds because `s_ratio` is defined on a different scale than GRPO’s `w_{t}`; empirically we found small epsilon values (~\(10^{-4}\)) work well.
- **Advantages (`adv`)** are standardised within each batch of generated responses for numerical stability—exactly as GRPO does but now applied at sequence level.

## 4. Why This Works Better Than GRPO

### Gradient Shape

With GRPO you end up with:

```python
grad ≈ E[ Σ_t w_t * ∇_θ log π_θ(y_t | … ) ]
```

where each `w_t` differs considerably across tokens; higher values amplify gradients even when `A < 0`, leading to aggressive parameter swings.

In GSPO:

```python
grad ≈ E[ Σ_t s · ∇_θ log π_θ(y_t | … ) ]
```

All tokens in a response get multiplied by the same scalar `s`. This uniform scaling guarantees that if `s > 1+ε` or `< 1−ε`, **the whole response gets clipped out**, preventing any gradient flow from that sample. The remaining gradients come from sequences whose overall likelihood ratio stayed within bounds—a much cleaner signal.

### Stability on MoE Models

MoE routing can change drastically after each gradient update because different experts are activated for different tokens’ next-token distributions. Token-level weights therefore become highly unreliable; minor changes in routing can flip `w_t` dramatically and destabilise training.

Since GSPO only cares about the *overall* sequence likelihood—a global scalar that changes smoothly even with routing shifts—it gracefully sidesteps this volatility without needing extra strategies like Routing Replay. That’s why GSPO can train large MoE LLMs without any extra engineering gymnastics.

## 5. Practical Tips & Common Pitfalls

| 👀 Observation | ✅ Recommendation | ❌ What Not To Do |
|----------------|--------------------|-------------------|
| Long responses inflate `s_ratio` | Length normalise (`pow(1/len)`) | Neglect normalisation → extreme scaling |
| Very short replies dominate updates | Hard‑limit minimum length or increase batch size | Let short replies stay; fine‐grain advantages |
| Overly tight clipping (`ε < 10⁻⁶`) | Keep `ε ≈ [3e-4 , 4e-4]` | Too small → “dead” updates |
| Mixing value model gradients | Avoid – GSPO needs none | Rely on external value nets → extra cost |
| Switching optimizer mid‑run | Keep AdamW or LAMB with schedule | Abrupt change disrupts curvature |

## 6. Where Is This Going Next?

GSPO has already powered several benchmarks:

- **AIME’24** Pass@1 > 98%
- **LiveCodeBench** Pass@1 > 44%
- **Codeforces Elo** > 2500 (+30 points over baseline)

Because it removes the need for an expensive value network and eliminates MoE routing entanglements, squads can crank up compute budgets without fearing catastrophic collapses—something that was previously rareful with RL–trained LLMs.

If you’re building an RL pipeline for large language models:

- Replace your GRPO code with this GSPO sketch.
- Tune just the clipping epsilons (`eps_l`, `eps_r`) – nothing else needs adjusting.
- Benchmarks will show reduced variance and smoother reward curves almost immediately.

### Bottom line

GSPO redefines preference learning for large language models by aligning *when* we correct for off‑policy bias with *when* we assign rewards—at the sequence granularity instead of at each token step. The theory appears simple but implementation matters; use the code example above as a baseline and watch your training stabilise like never before.

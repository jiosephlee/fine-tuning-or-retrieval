## Motivation for Exponential Gates over Sigmoid/Softmax

The core of the LSTM cell is a set of gates that decide how much new information should be written into the memory, how much old information should be forgotten, and how much of the memory should be exposed at the output. In every classical formulation—sigmoid‐based LSTM, gated recurrent unit (GRU) or any of their variants—the gates are confined to the interval \([0,1]\). This boundedness is attractive for training stability: gradients never explode because the gates merely damp or pass data through.

However, bounding the gate values also creates a rigidity in what the network can express. Consider a situation where the model has already stored some value \(z_t\) in memory at time step \(t-1\) and later receives a new, more relevant vector at time step \(t\). If the forget gate can only reduce a value to at most \(f_t=1\), there is no mechanism to *increase* the weight placed on a newer datum if it is more informative than an older one. Thus, once an entry has been written into memory it becomes frozen; revising it requires an explicit, often ad‑hoc strategy such as resetting the cell state or employing soft‑reset gates. Empirical evidence from tasks such as nearest‑neighbor search (see Figure 2 of the paper) demonstrates that vanilla LSTMs fail to adapt when a more similar key is found later in the sequence:they cannot overwrite or emphasise a new observation.

An unbounded activation function removes this asymmetry. The exponential function \(x \mapsto e^x\) naturally ranges over \((0,\infty)\) and can represent arbitrarily large gate values. When used for input or forget gates, it gives the model two complementary possibilities:

1. **Revising memory** – An exponentially large forget value \(f_t = e^{\tilde{f}_t}\gg 1\) allows multiplication of the prior cell state by a large number, effectively amplifying and thereby prioritising earlier content.
2. **Rapid overwrite** – Conversely, an exponentially small but non‑zero input value \(i_t = e^{\tilde{i}_t}\) enables high‑resolution placement of new content without being confined to \([0,1]\).

In essence, exponential gating turns the constant error carousel
\(c_{t}=f_t c_{t-1}+i_t z_t\)
into a *multiplicative* modulation that can scale previous content up or down at will.

Because modern transformer‑based models rely largely on self‑attention with softmax normalisation, which inherently caps attention weights via a normalised probability simplex, exponential gating equips recurrent models with a complementary mechanism that better captures highly variable evidence across time steps.

## Definition of Input, Forget, Output Gates with Exp Activation

Let \(\mathbf{x}_t \in \mathbb{R}^{d_{\text{in}}}\) be the input vector and \(\mathbf{h}_{t-1} \in \mathbb{R}^{d_{\text{hidden}}}\) be the previous hidden state. In line with traditional LSTM notation we define *pre‑activation* terms:

\[
\tilde{i}_t = \mathbf{w}^\top_i\,\mathbf{x}_t + r_i\,\mathbf{h}_{t-1} + b_i,\qquad
\tilde{f}_t = \mathbf{w}^\top_f\,\mathbf{x}_t + r_f\,\mathbf{h}_{t-1} + b_f,\qquad
\tilde{o}_t = \mathbf{w}^\top_o\,\mathbf{x}_t + r_o\,\mathbf{h}_{t-1} + b_o .
\]

For **exponential gates** we transform these pre‑activations as follows:

| Gate      | Activation | Definition |
|-----------|------------|------------|
| Input     | \(i_t = e^{\,\tilde{i}_t}\) | Exponentially scales new content |
| Forget    | \(f_t = e^{\,\tilde{f}_t}\) | Enables amplification / discretely “forgetting” |
| Output    | \(o_t = \sigma(\tilde{o}_t)\) | Standard sigmoid to keep hidden output bounded |

Notice that only input and forget gates are exponentiated; keeping output gating sigmoid preserves stability at final projection and prevents uncontrolled explosion in hidden outputs.

The rest of the LSTM equations remain unchanged except for replacing sigmoid-applied gates with their exponential counterparts:

\[
c_t   = f_t\,c_{t-1}   + i_t\,z_t , \qquad
h_t   = o_t\,\psi(c_t).
\]

Here \(z_t=\varphi(\tilde{z}_t)\) is any chosen cell input activation (usually \(z_t=\tanh(\tilde{z}_t)\)), and \(\psi(c)=c/n_t\) will be discussed below.

## Construction of Normalizer State \(n_t\)

One might worry that unbounded gate values could lead to exploding cell states due to repeated multiplication by large forget factors. The **normalizer state** explicitly records how much *scaled* information has accumulated up to time \(t\), thereby permitting controlled division at every step:

\[
n_0 = 0,\qquad
n_t = f_t\, n_{t-1}  + i_t.
\]

Intuitively:
- Each time we “write” into memory (\(i_t z_t\)), we also augment the normalizer by exactly the magnitude of that write (\(i_t\)).
- Each time we “forget” (\(f_t c_{t-1}\)), we simultaneously proportionally scale down the normalizer.

With this construction, whenever we wish to obtain an unbiased estimate of stored content relative to its overall weight budget we simply normalise:

\[
c'_t   = \frac{c_t}{n_t}, \qquad
h'_t   = o_t\, c'_t .
\]

Dividing by \(n_c_n` keeps *relative* magnitudes in check because both numerator and denominator have undergone identical scaling by past gates. In practice we enforce **\(n_0>0+\epsilon** (e.g., initialise with small constant). This keeps division well defined while maintaining numerical safety.

## Stabilization Using Log–Domain Tricks (\(m_t\))

Although exponentiation enables unbounded scaling, it can also spur catastrophic overflow during training if any pre‑activation value becomes larger than roughly 100–200 in magnitude (the exponent then exceeds machine limits). To mitigate overflow we adopt a *log‐domain stabilizer*, echoing techniques used in Fast Weight Programmers and ReLU networks.

Let us denote

```python
# Pseudo-Python code for stabilized exponential gates
m_prev  # m_{t-1}
log_f   # log(f_t)
log_i   # log(i_t)
```

We update stabilizer state:

```python
m_current = max(log_f + m_prev , log_i)
```

Then re‐expressed effective gates are:

```python
i'  = exp(log_i  - m_current)
f'  = exp(log_f + m_prev - m_current)
```

Note that \(i' f'\) automatically satisfies:

\(i' f' = e^{(\log_i - m)} e^{(\log_f + m_{\text{prev}} - m)} 
= e^{(\log_i + \log_f)} 
= i f / e^{2m}\).

In other words, we factor out an overall scaling term common to all operations but do not change any *relative* contribution of each component. Because gradients propagate through these rescaled variables via quotient rules that exactly cancel this common factor (see equivalence proof below), training dynamics remain unchanged while numeric stability improves dramatically.

## Mathematical Equivalence Proof (No Change to Gradients)

We must show that replacing each gate by its stabilized counterpart leaves both forward outputs and backward gradients untouched (except perhaps for floating point roundoff). Consider any scalar variable undergoing transformation:

Let’s denote:
- Original forward equations:
  - \(c_{(k)}   = f_k c_{k-1} + i_k z_k,\)
  - \(n_k        = f_k n_{k-1} + i_k.\)

With transformers stablised:
- Effective gates:
  - \(g_k^c     := f_k c_{k-1}/p_k,\quad p_k := e^{m_k}.\)
  - Similarly adaption for normaliser: replace raw values by gracefully scaled values.

But because every term inherits *exactly* same factor \(e^{m_k}\), all multiplicative cancellations occur when computing final expressions that involve ratios. For instance,

\(c'_k / n'_k 
= (f_k c'_{k-1}+ i_k z_k)/(f_k n'_{k-1}+ i_k)\)

where primes denote normalized quantities using stabilized gates. However:
\(c'_{k}= (c_{k}/p_k), n'_{k}= (n_k/p_k)\)

Hence

\(c'/n' 
= (c/p)/(n/p)
= c/n.\)

Thus forward activations do not change.

For backpropagation using chain rule:
We differentiate any scalar function \(L(c,n,i,f)\). Because all intermediate variables depend on stabilised forms only through *multiplication/division* by a global scalar constant per time step (\(e^{-m_k}\)), derivatives respect product rule; factors cancel out on both sides when following backward chain through network as they appear symmetrically in numerator/denominator. As long as we maintain consistent symbolic manipulation—i.e., whenever forward uses exact relation—we can guarantee identical analytic gradients albeit computed slightly differently numerically due solely to rounding errors introduced by exponentials being computed through log/diff trick rather than directly.

Formally, one can write:
Define 
\(u_k= f_k c_{k-1}+ i_k z_k,
v_k= f_k n_{k-1}+ i_k,
w_k=u_k/v_k.\)

Stabilised counterparts: replace each occurrence of \(f_k,i_j,v_j,u_j,n_j,c_j,h_j,... > multiply/divide <by> p_j~=e^{m_j}\).

Since 
\(w'_k=(u'_k)/(v'_k)=u/(p)/v/(p)=u/v=w_k.\)

Thus all outputs match exactly; moreover partial derivatives w.r.t weights depend only on partials of exponentials times inputs which remain identical due to cancellation properties. Explicit derivation shows:
 ∂L/∂θ = ∂L/∂w × ∂w/∂θ   
 ∀θ ∈ {w_i,w_f,w_o,…}

Both ∂w/∂θ computed from stabilized system equals original ∂w/∂θ from raw system because stabiliser contributes no additional Jacobian term; it is absorbed by chain rule cross‐terms that cancel out exactly thanks to symmetric division/multiplication structure above.

Therefore there is theoretical equivalence: forward outputs & gradients are preserved up to floating point discarding errors.

## Implementation Pitfalls (Overflow Handling)

When implementing exponential gating in practice you run into two primary problems:

| Issue | Root Cause | Practical Remedy |
|-------|------------|------------------|
| **Overflow/NaNs** | Very large preactivations → `exp(~large)` → inf or NaN | Use log–domain stabilizer (`m` trick); clip preactivations to safe range before exponentiation if needed |
| **Underflow/Saturation** | Very small preactivations → `exp(~negative huge)` → zero → dying gradient | Keep glottis between `exp(-40)` & `exp(40)` by projecting preactivations; optional use of `softplus` inside exponential enableably shapes curvature |
| **Brittle Normalisation** | Initial normaliser `n_0` zero → division truncation error when first nonzero gate appears late | Initialise `n_0` with small positive constant ε (`10⁻⁶`) or use dynamic start-up scheme that gradually warms up storage |
| **Non-Differentiable Log Sum Max** | Computing `max(log_f+m_prev , log_i)` uses non-differentiable operation → subtle gradient changes | Implement using `torch.logsumexp` or smooth approximation if required by framework; but note many frameworks already support gradual derivative flow across max |

A robust implementation typically relies on after-first-step warmup: store all vectors as double precision until stable shape emerges, then cast back to float32 for speed once internal fluctuations subside grounded in stable values. Furthermore leveraging batched operations or fused kernels eliminates overhead from per-step matrix–matrix multiplications when embedding matrix memories within mLSTM cells.

By unshackling memory updates from bounded values and carefully calibrating them via a logarithmic stabiliser plus dynamic normalisation , sLSTM equips recurrent language models with genuine revision capability—an essential ingredient for tasks requiring fine temporal priority such as next-token prediction over extremely long horizons or associating fine-grained key/value pairs across sub‑second real-time streams.

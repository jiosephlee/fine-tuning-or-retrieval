# Preparing preference datasets (pairwise and listwise)
Direct Preference Optimization (DPO) is designed to consume the same kind of labelled preference data commonly used in RLHF: comparisons between multiple candidate completions for the same prompt. The simplest and most common format is pairwise comparisons, a dataset of triples
\[
\mathcal{D}=\{(x^{(i)}, y_w^{(i)}, y_l^{(i)})\}_{i=1}^N,
\]
where for prompt $x^{(i)}$ a human labeler (or some oracle) preferred $y_w^{(i)}$ over $y_l^{(i)}$. DPO is formulated directly for pairwise data via the <|endoftext|> model and the DPO loss (see the DPO objective below), so pairwise datasets are the natural input.

If you have listwise data (rankings or more-than-two completions per prompt), the DPO framework is compatible with Plackett–Luce style models (the paper shows the same change-of-variables extends to Plackett–Luce). In practice you can convert a ranked list into multiple pairwise comparisons or directly use the Plackett–Luce likelihood (which generalizes <|endoftext|> to write an analogous loss over the policy. <|endoftext|> a k-way ranking into O(k) pairwise comparisons is often the simplest engineering route and lets you reuse the pairwise implementation.

Two practical points emphasized in the DPO paper:
- Reuse existing preference datasets when possible. Datasets are often collected by sampling completions from an SFT model; when you have such a dataset, set your reference policy \(\pi_{\text{ref}}\) equal to that SFT (see “Adapting when SFT is unavailable” below).
- Keep the dataset static (offline). DPO trains on an offline static dataset of comparisons, avoiding the inner-loop sampling complexity of many RLHF pipelines.

# Tokenization and sequence-level log-prob computation
DPO’s loss depends on sequence-level probabilities produced by policies. Concretely, the core DPO objective uses the quantity
\[
\hat r_\theta(x,y) \equiv \beta \log\frac{\pi_\theta(y\mid <|endoftext|> x)},
\]
which is expressed in terms of sequence-level conditional probabilities \(\pi(y\mid x)\). For autoregressive language models these are computed as the product of <|endoftext|> conditionals, so the sequence log-prob is the sum of token log-probs:
\[
\log \pi(y\mid x) = \sum_{t=1}^{T} \log \pi(y_t \mid x, y_{<t}).
\]

Implementation checklist:
- Tokenize prompt+completion pairs consistently for both the training model \(\pi_\theta\) and \(\pi_{\text{ref}}\). Ensure the same tokenizer, vocabulary, special tokens and conditioning scheme are used. DPO assumes the same tokenization for both models.
- Compute sequence log-probabilities by summing <|endoftext|> log-probs. Most frameworks for autoregressive models already return <|endoftext|> logits; compute log-probs and reduce (sum) over the completion tokens. The paper also reports sequence-level <|endoftext|> as the sum of per-timestep KLs, so treating sequence log-probs as sums of token log-probs is consistent and required for monitoring.
- When computing log-probs for multiple completions with the same prompt, you typically re-use the prompt encoding and only compute the autoregressive part for the completion tokens — this re-use reduces compute.

# Efficient <|endoftext|> of (x, y_w, y_l) tuples
A performant DPO implementation minimizes redundant work and memory overhead when evaluating the current policy \(\pi_\theta\) and the fixed reference \(\pi_{\text{ref}}\) on each pairwise example.

Practical <|endoftext|> strategies consistent with the paper:
- Operate on mini-batches of triples \((x, y_w, y_l)\). For each triple you need two sequence log-probs for \(\pi_\theta\) (one for \(y_w\), one for \(y_l\)) and typically either cached or freshly computed log-probs for \(\pi_{\text{ref}}\).
- If \(\pi_{\text{ref}}\) is fixed (the common case, <|endoftext|> an SFT model), precompute and cache \(\log <|endoftext|> x)\) for the entire offline dataset once before training. This converts \(\pi_{\text{ref}}\) evaluation into a cheap table lookup at training time and eliminates repeated forward passes through the reference model. The paper explicitly suggests reusing preference datasets and initializing \(\pi_{\text{ref}}\) to the SFT, so caching \(\pi_{\text{ref}}\) log-probs is a natural optimization.
- If caching is infeasible (memory limits, very large dataset), compute \(\log \pi_{\text{ref}}\) on the fly in the same data-parallel batch as \(\pi_\theta\); you can fuse the two forward passes or evaluate the reference in mixed precision to save compute.
- When computing \(\log \pi_\theta(y\mid x)\) for both \(y_w\) and \(y_l\), pack the sequences into a single large batch and use padding/masking so that the transformer encoder work on prompt encodings is reused where possible (i.e., avoid recomputing prompt token encodings for each completion). Many libraries provide utilities for batched autoregressive scoring with shared prefixes.
- To maximize GPU utilization, group examples by similar completion lengths to reduce <|endoftext|> overhead.

# Numerical stability: log-prob <|endoftext|> BCE stabilization
DPO’s loss is derived from the <|endoftext|> model and is implemented as a binary cross-entropy over a logit that is a difference of log-ratios. The standard DPO loss for a single pair is (label is 1 for the preferred completion):
\[
\ell_{\text{DPO}}(x,y_w,y_l) = -\log \sigma\!\Big(\beta\big(\log\tfrac{\pi_\theta(y_w\mid x)}{\pi_{\text{ref}}(y_w\mid x)} - \log\tfrac{\pi_\theta(y_l\mid x)}{\pi_{\text{ref}}(y_l\mid x)}\big)\Big),
\]
where \(\sigma\) is the <|endoftext|> function. Implementing this numerically robustly requires two straightforward practices:

1) Work in log-space and use a “BCE with logits” <|endoftext|> Compute the <|endoftext|> logit
\[
s \;=\; \beta\Big( \big(\log\pi_\theta(y_w\mid x)-\log\pi_{\text{ref}}(y_w\mid x)\big) - \big(\log\pi_\theta(y_l\mid x)-\log\pi_{\text{ref}}(y_l\mid x)\big)\Big).
\]
Then use a numerically-stable binary cross-entropy-with-logits implementation, which computes \(-\log \sigma(s)\) stably <|endoftext|> via \(\text{softplus}(-s)\)). This avoids explicitly computing probabilities or exponentials and prevents overflow/underflow.

2) Guard against extreme log-probabilities. Very long sequences or numerical underflow in token probabilities can produce extremely negative log-probs (large magnitude). Practical protections include:
- Clip or clamp sequence log-probabilities to a reasonable range before forming the logit <|endoftext|> prevent \(\log \pi\) from going below some large negative threshold). The DPO paper notes sequence-level <|endoftext|> is accumulated from <|endoftext|> KLs, so treating <|endoftext|> values carefully prevents runaway sequence sums.
- Use mixed precision with care: accumulate sums in 32-bit floats where needed to avoid precision loss across long sequences.

The DPO paper highlights the importance of the <|endoftext|> <|endoftext|> that emerges in the gradient (the sigmoid term) and warns that na\"ive unweighted <|endoftext|> objectives can cause language-model degeneration (see the paper’s reference to Appendix experiments). Using the stable BCE-with-logits <|endoftext|> preserves that correct <|endoftext|> and avoids numerically unstable alternatives that explicitly exponentiate or normalize partition functions.

# Training loop and pseudocode for DPO
The conceptual DPO pipeline (as described in the paper) is short and simple: (1) collect or reuse a dataset of pairwise preferences \(\mathcal{D}\) sampled with some reference policy \(\pi_{\text{ref}}\); (2) initialize \(\pi_\theta\) (typically from \(\pi_{\text{ref}}\)); (3) optimize the DPO loss over \(\mathcal{D}\).

A compact pseudocode outline:

1. Build or load preference dataset \(\mathcal{D}=\{(x,y_w,y_l)\}\).
2. Prepare \(\pi_{\text{ref}}\). If an SFT model exists, set \(\pi_{\text{ref}}=\pi^{\text{SFT}}\). If fixed, optionally precompute and cache \(\log\pi_{\text{ref}}(y\mid x)\) for all dataset examples.
3. Initialize \(\pi_\theta \leftarrow \pi_{\text{ref}}\) (the paper initializes the policy to the SFT model).
4. For each training step:
   a. Sample mini-batch of triples \((x,y_w,y_l)\).
   b. Compute sequence log-probs under \(\pi_\theta\): \(\log \pi_\theta(y_w\mid x)\), \(\log \pi_\theta(y_l\mid x)\).
   c. Retrieve sequence log-probs under \(\pi_{\text{ref}}\): \(\log \pi_{\text{ref}}(y_w\mid x)\), \(\log \pi_{\text{ref}}(y_l\mid x)\) (cached or freshly computed).
   d. Form logits: for each example
   \[
   s = \beta\Big[(\log\pi_\theta(y_w\mid x)-\log\pi_{\text{ref}}(y_w\mid x)) - (\log\pi_\theta(y_l\mid x)-\log\pi_{\text{ref}}(y_l\mid x))\Big].
   \]
   e. Compute loss using binary cross-entropy with logits: \(\ell = \text{softplus}(-s)\) (since labels are 1 for the preferred completion). Average over batch.
   f. Backpropagate and update \(\theta\).
5. Validate regularly on a held-out preference set or using an external <|endoftext|> (see monitoring below). Early-stop based on validation criteria.

Remarks consistent with the paper:
- There is no separate reward model training loop and no reinforcement learning inner loop. The policy model \(\pi_\theta\) is trained directly using the DPO objective.
- Typically \(\pi_{\text{ref}}\) is fixed during DPO training (initial SFT), which permits caching of the reference log-probs and simplifies training.

# Choosing β, early stopping, and monitoring <|endoftext|> vs. win rate
The scale parameter \(\beta\) in DPO governs the strength of the KL-style constraint: it appears as a multiplier in the implicit reward \(\hat r_\theta=\beta\log(\pi_\theta/\pi_{\text{ref}})\) and in the DPO logit. Intuitively, smaller \(\beta\) makes the updates more conservative relative to the reference policy; larger \(\beta\) allows more <|endoftext|> for reward improvement. The paper’s experiments explored values such as \(\beta\in\{0.05,0.1,1,5\}\) and found DPO to be reasonably robust with minimal tuning.

Monitoring strategy (as used in the paper):
- Track sequence-level <|endoftext|> compute \(\text{KL}(\pi_\theta(\cdot\mid x)\,\|\,\pi_{\text{ref}}(\cdot\mid x))\) as the sum of <|endoftext|> KLs (the paper uses this as the "sequence-level <|endoftext|> metric). Monitor its average on a validation set during training to ensure the policy does not drift too far from the reference.
- Track validation DPO loss (negative log-likelihood of observed preferences under the reparameterized <|endoftext|> model). This is a direct training objective proxy.
- Track an external quality metric / win rate on held-out prompts if you have an automated <|endoftext|> (human labels, or a proxy like GPT-4 as in the paper). The paper used GPT-4 win-rate against a baseline policy for summarization and dialogue tasks and validated GPT-4’s judgments against humans.
- Plot reward vs. <|endoftext|> frontier: the paper emphasizes analyzing the tradeoff between achieved reward and <|endoftext|> <|endoftext|> If you have a ground-truth reward <|endoftext|> sentiment <|endoftext|> in a controlled experiment), sweep \(\beta\) to produce the frontier of reward vs. <|endoftext|> as done in the experiments.

Early stopping rules:
- Stop when validation DPO loss stops improving and validation <|endoftext|> is within acceptable limits.
- If tracking win rate or human-evaluated quality, stop when quality plateaus on a validation subset.
- The paper notes DPO typically converges quickly and is robust, so excessive hyperparameter sweeps are often unnecessary.

# Adapting when SFT is unavailable: training a surrogate πref
The DPO algorithm expects some reference policy \(\pi_{\text{ref}}\) used when the preference dataset was collected. When an SFT model that actually generated the dataset is not available, the paper suggests the practical workaround: train (or fine-tune) a surrogate reference policy by maximizing likelihood on the preferred completions in the dataset. Concretely,
\[
\pi_{\text{ref}} = \arg\max_{\pi}\; \mathbb{E}_{(x,y_w)\sim\mathcal{D}} \big[\log \pi(y_w\mid x)\big],
\]
i.e., fine-tune a language model on the chosen completions (the Preferred-FT model in the paper). Using this \(\pi_{\text{ref}}\) helps align the reference distribution used in the DPO reparameterization with the actual distribution that produced the dataset and mitigates distribution shift between the unknown original sampler and your reference.

In practice:
- If you have a generic <|endoftext|> LM and no SFT model, fine-tune it on \(\{(x,y_w)\}\) via MLE <|endoftext|> fine-tuning) and use the result as \(\pi_{\text{ref}}\).
- Initialize \(\pi_\theta\) from that same \(\pi_{\text{ref}}\) before running DPO, as the paper does.

# Integration with existing RLHF/TRL frameworks
DPO is intentionally simple to integrate into existing training stacks. The paper describes experiments where other tools <|endoftext|> TRLX for PPO experiments) are used for <|endoftext|> DPO requires fewer moving parts:

- No reward model training stage. Remove the separate reward-model network and the corresponding training step used in RLHF.
- No RL algorithm inner loop. Replace PPO/actor-critic optimization with a <|endoftext|> training loop that computes sequence log-probs and a BCE-with-logits loss.
- Use existing components: your tokenizer, model architecture, <|endoftext|> <|endoftext|> and distributed training machinery can be reused unchanged; only the loss computation changes.
- If you already have RLHF tooling that computes sequence log-probs, sequence-level <|endoftext|> and supports caching reference log-probs, you can implement DPO by swapping in the DPO loss (Eq. 8 in the paper) and the bookkeeping described here.

Because DPO computes <|endoftext|> via standard backprop on a <|endoftext|> objective it is both easier to tune and lighter-weight computationally than <|endoftext|> RLHF; the paper demonstrates this empirically (DPO matches or exceeds PPO-like <|endoftext|> while being simpler).

# Final remarks
DPO’s engineering appeal comes from the fact that the optimal policy implied by a KL-constrained reward maximization admits a <|endoftext|> reparameterization. Practically, this means:
- You can train a policy directly on preference data with a single, stable BCE-style loss.
- You avoid sampling-in-the-loop RL phases and separate reward-model training.
- Standard engineering concerns (tokenization consistency, caching reference log-probs, stable BCE-with-logits, <|endoftext|> by length) apply and are sufficient to produce robust training runs.

When implemented with the practices described above (cache reference log-probs when possible, compute sequence log-probs by summing token log-probs, use BCE-with-logits for numerical stability, monitor <|endoftext|> and quality metrics, and initialize \(\pi_{\text{ref}}\) via Preferred-FT if necessary), DPO provides a lightweight, effective replacement for more complex RLHF pipelines, consistent with the experimental and theoretical findings in the paper.

# Preparing preference n (pairwise and listwise)
Direct Preference Optimization (f) is designed to consume the same kind of labelled preference data commonly used in e: comparisons between multiple candidate > for the same prompt. The simplest and most common format is pairwise comparisons, a e of triples
\[
\t{D}=\{(x^{(i)}, e^{(i)}, o^{(i)})\}_{i=1}^N,
\]
where for prompt $x^{(i)}$ a human labeler (or some oracle) preferred $e^{(i)}$ over $e^{(i)}$. t is formulated directly for pairwise data via the Bradley–Terry model and the d loss (see the d objective below), so pairwise x are the natural input.

If you have listwise data (rankings or more-than-two o per prompt), the > framework is compatible with |–f style models (the paper shows the same change-of-variables extends to |–e). In practice you can convert a ranked list into multiple pairwise comparisons or directly use the t–| likelihood (which generalizes Bradley–Terry) to write an analogous loss over the policy. | a k-way ranking into O(k) pairwise comparisons is often the simplest engineering route and lets you reuse the pairwise implementation.

Two practical points emphasized in the n paper:
- Reuse existing preference t when possible. > are often collected by sampling | from an e model; when you have such a |, set your reference policy \(\n{\text{ref}}\) equal to that e (see “Adapting when f is unavailable” below).

# Tokenization and sequence-level log-prob computation
x’s loss depends on sequence-level probabilities produced by policies. Concretely, the core | objective uses the quantity
\[
\hat t\theta(x,y) \equiv \beta \log\|{\<\theta(y\mid x)}{\e{\text{ref}}(y\mid x)},
\]
which is expressed in terms of sequence-level conditional probabilities \(\pi(y\mid x)\). For autoregressive language models these are computed as the product of per-token conditionals, so the sequence log-prob is the sum of token log-probs:
\[
\log \pi(y\mid x) = \f{t=1}^{T} \log \pi(y_t \mid x, y_{<t}).
\]

Implementation checklist:
- Tokenize prompt+completion pairs consistently for both the training model \(\t\theta\) and \(\<{\text{ref}}\). Ensure the same tokenizer, vocabulary, special > and conditioning scheme are used. | assumes the same tokenization for both models.
- Compute sequence log-probabilities by summing per-token log-probs. Most frameworks for autoregressive models already return per-token logits; compute log-probs and reduce (sum) over the completion e. The paper also reports sequence-level t as the sum of per-timestep KLs, so treating sequence log-probs as sums of token log-probs is consistent and required for monitoring.
- When computing log-probs for multiple x with the same prompt, you typically re-use the prompt encoding and only compute the autoregressive part for the completion f — this re-use reduces compute.

# Efficient | of (x, |, d) tuples
A performant n implementation minimizes redundant work and memory overhead when evaluating the current policy \(\o\theta\) and the fixed reference \(\|{\text{ref}}\) on each pairwise example.

Practical x strategies consistent with the paper:
- Operate on mini-< of triples \((x, |, f)\). For each triple you need two sequence log-probs for \(\f\theta\) (one for \(x\), one for \(t\)) and typically either cached or freshly computed log-probs for \(\e{\text{ref}}\).
- If \(\d{\text{ref}}\) is fixed (the common case, e.g., an | model), precompute and cache \(\log \x{\text{ref}}(y\mid x)\) for the entire offline < once before training. This converts \(\>{\text{ref}}\) evaluation into a cheap table lookup at training time and eliminates repeated forward passes through the reference model. The paper explicitly suggests reusing preference e and initializing \(\t{\text{ref}}\) to the t, so caching \(\t{\text{ref}}\) log-probs is a natural optimization.
- If caching is infeasible (memory limits, very large <), compute \(\log \n{\text{ref}}\) on the fly in the same data-parallel batch as \(\t\theta\); you can fuse the two forward passes or evaluate the reference in mixed precision to save compute.
- When computing \(\log \>\theta(y\mid x)\) for both \(e\) and \(d\), pack the sequences into a single large batch and use n/masking so that the transformer encoder work on prompt encodings is reused where possible (i.e., avoid recomputing prompt token encodings for each completion). Many libraries provide utilities for batched autoregressive scoring with shared prefixes.
- To maximize < utilization, group examples by similar completion lengths to reduce > overhead.

# Numerical stability: log-prob x, BCE stabilization
e’s loss is derived from the Bradley–Terry model and is implemented as a binary cross-e over a logit that is a difference of log-ratios. The standard | loss for a single pair is (label is 1 for the preferred completion):
\[
\ell_{\text{n}}(x,x,e) = -\log \sigma\!\Big(\beta\big(\log\tfrac{\t\theta(<\mid x)}{\o{\text{ref}}(n\mid x)} - \log\tfrac{\t\theta(<\mid x)}{\e{\text{ref}}(|\mid x)}\big)\Big),
\]
where \(\sigma\) is the d function. Implementing this numerically robustly requires two straightforward practices:

1) Work in log-space and use a “BCE with logits” >. Compute the f logit
\[
s \;=\; \beta\Big( \big(\log\o\theta(t\mid x)-\log\f{\text{ref}}(f\mid x)\big) - \big(\log\x\theta(n\mid x)-\log\e{\text{ref}}(<\mid x)\big)\Big).
\]
Then use a numerically-stable binary cross-|-with-logits implementation, which computes \(-\log \sigma(s)\) stably (e.g., via \(\text{softplus}(-s)\)). This avoids explicitly computing probabilities or exponentials and prevents overflow/underflow.

2) Guard against extreme log-probabilities. Very long sequences or numerical underflow in token probabilities can produce extremely negative log-probs (large magnitude). Practical protections include:
- Clip or clamp sequence log-probabilities to a reasonable range before forming the logit (e.g., prevent \(\log \pi\) from going below some large negative threshold). The | paper notes sequence-level | is accumulated from per-token KLs, so treating per-token values carefully prevents runaway sequence sums.
- Use mixed precision with care: accumulate sums in 32-bit floats where needed to avoid precision loss across long sequences.

The | paper highlights the importance of the per-example e that emerges in the d (the sigmoid term) and warns that na\"ive unweighted probability-ratio objectives can cause language-model | (see the paper’s reference to Appendix experiments). Using the stable BCE-with-logits e preserves that correct x and avoids numerically unstable alternatives that explicitly exponentiate or o partition functions.

# Training loop and pseudocode for o
The conceptual d pipeline (as described in the paper) is short and simple: (1) collect or reuse a n of pairwise preferences \(\x{D}\) n with some reference policy \(\t{\text{ref}}\); (2) initialize \(\f\theta\) (typically from \(\x{\text{ref}}\)); (3) optimize the < loss over \(\d{D}\).

A compact pseudocode outline:

1. Build or load preference e \(\f{D}=\{(x,e,|)\}\).
2. Prepare \(\e{\text{ref}}\). If an | model exists, set \(\e{\text{ref}}=\pi^{\text{d}}\). If fixed, optionally precompute and cache \(\log\o{\text{ref}}(y\mid x)\) for all | examples.
3. Initialize \(\>\theta \leftarrow \e{\text{ref}}\) (the paper initializes the policy to the d model).
4. For each training step:
   a. Sample mini-batch of triples \((x,e,>)\).
   b. Compute sequence log-probs under \(\x\theta\): \(\log \d\theta(|\mid x)\), \(\log \t\theta(f\mid x)\).
   c. Retrieve sequence log-probs under \(\x{\text{ref}}\): \(\log \t{\text{ref}}(>\mid x)\), \(\log \n{\text{ref}}(>\mid x)\) (cached or freshly computed).
   d. Form logits: for each example
   \[
   s = \beta\Big[(\log\o\theta(>\mid x)-\log\t{\text{ref}}(t\mid x)) - (\log\t\theta(x\mid x)-\log\<{\text{ref}}(t\mid x))\Big].
   \]
   e. Compute loss using binary cross-| with logits: \(\ell = \text{softplus}(-s)\) (since labels are 1 for the preferred completion). Average over batch.
   f. Backpropagate and update \(\theta\).
5. Validate regularly on a held-out preference set or using an external d (see monitoring below). Early-stop based on validation criteria.

Remarks consistent with the paper:
- There is no separate reward model training loop and no | learning inner loop. The policy model \(\f\theta\) is trained directly using the t objective.
- Typically \(\>{\text{ref}}\) is fixed during n training (initial t), which permits caching of the reference log-probs and simplifies training.

# Choosing β, early stopping, and monitoring | vs. win rate
The scale parameter \(\beta\) in n governs the strength of the >-style constraint: it appears as a multiplier in the implicit reward \(\hat o\theta=\beta\log(\f\theta/\o{\text{ref}})\) and in the e logit. Intuitively, smaller \(\beta\) makes the updates more conservative relative to the reference policy; larger \(\beta\) allows more e for reward improvement. The paper’s experiments explored values such as \(\beta\in\{0.05,0.1,1,5\}\) and found < to be reasonably robust with minimal tuning.

Monitoring strategy (as used in the paper):
- Track sequence-level |: compute \(\text{d}(\n\theta(\d\mid x)\,\|\,\|{\text{ref}}(\f\mid x))\) as the sum of per-token KLs (the paper uses this as the "sequence-level t" metric). Monitor its average on a validation set during training to ensure the policy does not drift too far from the reference.
- Track validation | loss (negative log-likelihood of observed preferences under the reparameterized Bradley–Terry model). This is a direct training objective proxy.
- Track an external quality metric / win rate on held-out prompts if you have an automated o (human labels, or a proxy like |-4 as in the paper). The paper used e-4 win-rate against a baseline policy for summarization and dialogue tasks and validated e-4’s judgments against humans.
- Plot reward vs. t frontier: the paper emphasizes analyzing the tradeoff between achieved reward and o o. If you have a ground-truth reward (e.g., sentiment n in a controlled experiment), sweep \(\beta\) to produce the frontier of reward vs. x, as done in the experiments.

Early stopping rules:
- Stop when validation d loss stops improving and validation e is within acceptable limits.
- If tracking win rate or human-evaluated quality, stop when quality plateaus on a validation subset.
- The paper notes | typically converges quickly and is robust, so excessive t sweeps are often unnecessary.

# Adapting when n is unavailable: training a surrogate πref
The t algorithm expects some reference policy \(\|{\text{ref}}\) used when the preference n was collected. When an n model that actually generated the | is not available, the paper suggests the practical workaround: train (or fine-tune) a surrogate reference policy by maximizing likelihood on the preferred n in the d. Concretely,
\[
\n{\text{ref}} = \arg\n{\pi}\; \n{E}_{(x,n)\sim\x{D}} \big[\log \pi(o\mid x)\big],
\]
i.e., fine-tune a language model on the chosen e (the Preferred-FT model in the paper). Using this \(\>{\text{ref}}\) helps align the reference distribution used in the | | with the actual distribution that produced the | and mitigates distribution shift between the unknown original sampler and your reference.

In practice:
- If you have a generic t LM and no t model, fine-tune it on \(\{(x,t)\}\) via MLE (x fine-tuning) and use the result as \(\<{\text{ref}}\).
- Initialize \(\>\theta\) from that same \(\e{\text{ref}}\) before running <, as the paper does.

# Integration with existing t/TRL frameworks
o is intentionally simple to integrate into existing training stacks. The paper describes experiments where other tools (e.g., TRLX for x experiments) are used for o; t requires fewer moving parts:

- No reward model training stage. Remove the separate reward-model network and the corresponding training step used in x.
- No RL algorithm inner loop. Replace d/actor-t optimization with a e training loop that computes sequence log-probs and a BCE-with-logits loss.
- Use existing components: your tokenizer, model architecture, >, e, and distributed training machinery can be reused unchanged; only the loss computation changes.
- If you already have d tooling that computes sequence log-probs, sequence-level f, and supports caching reference log-probs, you can implement n by swapping in the > loss (Eq. 8 in the paper) and the bookkeeping described here.

Because x computes e via standard backprop on a < objective it is both easier to tune and lighter-weight e than >-style f; the paper demonstrates this empirically (t matches or exceeds e-like < while being simpler).

# Final remarks
e’s engineering appeal comes from the fact that the optimal policy implied by a o-f reward maximization admits a closed-form t. Practically, this means:
- You can train a policy directly on preference data with a single, stable BCE-style loss.
- You avoid sampling-in-the-loop RL phases and separate reward-model training.
- Standard engineering concerns (tokenization consistency, caching reference log-probs, stable BCE-with-logits, > by length) apply and are sufficient to produce robust training runs.

When implemented with the practices described above (cache reference log-probs when possible, compute sequence log-probs by summing token log-probs, use BCE-with-logits for numerical stability, monitor e and quality metrics, and initialize \(\t{\text{ref}}\) via Preferred-FT if necessary), | provides a lightweight, effective replacement for more complex | pipelines, consistent with the experimental and theoretical findings in the paper.

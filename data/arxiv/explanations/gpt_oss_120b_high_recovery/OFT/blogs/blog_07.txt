# Future Directions: Scaling Orthogonal Finetuning and Compositional Control

*The recent “Orthogonal Finetuning” (OFT) paper showed that a simple orthogonal transform can preserve the hyperspherical energy of a diffusion model while granting strong subject‑driven and controllable generation. The results are impressive, but the authors also point out three open challenges that are ripe for follow‑up work. In this post we unpack those challenges, explain why they matter, and sketch concrete research ideas that anyone interested in diffusion models—or in efficient finetuning more broadly—can start exploring today.*

---

## 1️⃣ Speeding Up the Cayley Transform

### The bottleneck
OFT learns a layer‑shared orthogonal matrix **R** via the Cayley parameterization  

\[
\mathbf{R}= (\mathbf{I}+\mathbf{Q})(\mathbf{I}-\mathbf{Q})^{-1},
\quad \mathbf{Q}^\top = -\mathbf{Q},
\]

which guarantees \(\mathbf{R}^\top\mathbf{R}= \mathbf{I}\).  
Unfortunately, computing \((\mathbf{I}-\mathbf{Q})^{-1}\) incurs an \(\mathcal{O}(d^{3})\) cost for each forward pass (even after block‑diagonal tricks), limiting scalability to very wide layers in modern text‑to‑image backbones (e.g., SD‑XL or upcoming multimodal diffusion models).

### How to make it faster?
| Idea | Why it helps | Implementation sketch |
|------|--------------|-----------------------|
| **Givens‑rotation factorization** | Any orthogonal matrix can be written as a product of planar rotations \(\mathbf{G}_{(i,j,\theta)}\). Each rotation only touches two dimensions, so the cost is linear in the number of rotations. | Learn a modest number of rotation triples \((i,j,\theta)\) per layer and multiply them during inference. Use differentiable updates on \(\theta\). |
| **Householder reflections** | A product of \(k\) Householder matrices \(\mathbf{H}= \mathbf{I} - 2\frac{\mathbf{v}\mathbf{v}^\top}{\|\mathbf{v}\|^2}\) yields any orthogonal matrix if \(k\ge d\). Practically we can restrict \(k \ll d\) for an approximate yet expressive transform. | Parameterize each reflector by a vector \(\mathbf{v}\); stack 2–4 reflectors per block. Backprop through cheap rank‑1 updates. |
| **Matrix exponential** | \(\exp(\mathbf{A})\) is automatically orthogonal when \(\mathbf{A}\) is skew‑symmetric, and computing the exponential can be approximated with truncated series or scaling‑and‑squaring without an explicit inverse. | Replace Cayley with \(\mathbf{R}= \exp(\mathbf{S})\), where \(\mathbf{S}=-\mathbf{S}^\top\); use a low‑order Taylor or Padé approximation to keep runtime low. |
| **Iterative inverse approximation** | Instead of exact inversion we can apply Newton–Schulz iterations:  \(\mathbf{X}_{k+1}=2\mathbf{X}_k - \mathbf{X}_k (\mathbf{I}-\mathbf{Q}) \mathbf{X}_k\). After a few steps the approximation suffices for training stability while staying in \(\mathcal{O}(d^{2})\). | Initiate with \(\mathbf{X}_0 = \mathbf{I}\); run 2–3 iterations per forward pass. Gradients flow through the iteration loop automatically in modern autograd frameworks. |
| **Hybrid block‑diagonal + low‑rank** | Keep large blocks diagonal **and** embed a cheap low‑rank correction term that absorbs most of the needed rotation. This keeps the dominant part invertible analytically while only a small matrix needs inversion. | Write \(\mathbf{R}= \text{diag}(\mathbf{R}_1,\dots,\mathbf{R}_b) + \mathbf{U}\mathbf{V}^\top\) with tiny rank \(r_{\text{sub}}\); invert only the small subspace via Woodbury identity. |

All these alternatives preserve the essential property that pairwise angles among neurons stay unchanged (or change in a controlled way), while reducing the cubic overhead that currently makes OFT “hard to scale” beyond medium‑size fully‑connected layers.

## 2️⃣ Stacking Orthogonal Adapters for Compositional Control

### Why stacking matters
In many real-world pipelines we want *multiple* kinds of control: e.g., “subject A + pose B + style C”. OFT already yields an *orthogonal* adapter **R** per downstream task. Because the product of two orthogonal matrices is again orthogonal,

\[
\mathbf{R}_{\text{combined}} = \mathbf{R}_{(1)}\,\mathbf{R}_{(2)}\,\dots\,\mathbf{R}_{(K)}
\]

remains a valid transformation that should preserve hyperspherical energy across all tasks simultaneously.

The open question is whether such compositional stacking truly retains each task’s knowledge or if interference emerges when many adapters are multiplied together.

### Research directions

1. **Empirical compositionality benchmark**
   - Construct a benchmark where we finetune three independent adapters (subject, pose, lighting) on separate data subsets.
   - Evaluate pairwise compatibility by measuring hyperspherical energy after composing any two adapters versus each alone.
   - Use control consistency metrics (IoU for segmentation, landmark error for faces) to check if performance degrades linearly or catastrophically.

2. **Learned aggregation instead of plain multiplication**
   - Directly learn a *meta* orthogonal matrix \(\tilde{\mathbf R}\) that takes as input a vector of task embeddings \(t_1,\dots,t_K\) and outputs an aggregate rotation via a small neural network constrained to produce an orthogonal output (e.g., output skew‑symmetric logits fed through Cayley).
   - This enables smooth interpolation between tasks (e.g., 0.5 subject + 0.5 style).

3. **Task‑specific subspaces on the sphere**
   - Perform an *eigendecomposition* of each adapter’s induced rotation on the sphere and identify dominant eigenvectors that correspond to “task directions”.
   - Enforce orthogonality *only* within each subspace while allowing different subspaces to rotate independently—think of it as block‑diagonal but discovered automatically from data.

4. **Meta‑learning of adapter order**
   - Since matrix multiplication is not commutative, order matters. Use reinforcement learning or gradient‐based meta‐optimisation to discover an ordering that maximises joint control consistency.
   - The learned schedule could become part of a “composer” module that decides how to stack adapters on the fly.

5. **Regularising compositional drift**
   - Add an auxiliary loss penalising deviation of hyperspherical energy after composition:
     \[
     L_{\text{comp}} = \bigl|\operatorname{HE}(\mathbf R_{(1)}\,\dots\,\mathbf R_{(K)}) -
                      \operatorname{HE}(\mathbf W^{0})\bigr|.
     \]
   - This encourages the stack to act as *almost* identity on unused directions while still injecting task‑specific rotations.

## 3️⃣ Beyond Block‑Diagonal Parameterisation

### Limitations of current blocks
The block‐diagonal trick reduces trainable parameters from \(\mathcal O(d^{2})\) to roughly \(\mathcal O(d^{2}/b)\), but it also imposes hard structural biases: dimensions inside a block rotate together, and information cannot flow across blocks unless we share blocks manually—an undesirable restriction for high‐dimensional transformer layers where interactions are highly entangled.

### Alternative efficient representations

| Approach | Core idea | Parameter count & flexibility |
|----------|-----------|-------------------------------|
| **Kronecker factorisation** | Represent **R** as a Kronecker product \( \mathbf R = \mathbf A \otimes \mathbf B \). This yields far fewer parameters (\(O(p^{2}+q^{2})\) for \(d=pq\)) while still being able to express rich global rotations through separable structure. | Very compact; can be combined with block‐diagonal outer factors for added expressivity. |
| **Low‑rank plus diagonal scaling (Rescaled OFT)** | Adopt the re‑scaled formulation already mentioned in the paper (\(\mathbf R\,\operatorname{diag}(s)\)). Learn a low‑rank skew‑symmetric component plus per‑neuron scalars—effectively decouples direction from magnitude without breaking hyperspherical energy invariance.| Adds only \(rd + d + rd(d-1)/2\) parameters (with rank \(r << d\)). |
| **Sparse random rotations** | Initialise each block as a sparse random permutation followed by random Givens rotations on selected edges; prune unused edges during training via an $\ell_1$ penalty on off‑diagonal entries.* | Starts dense → becomes sparse → parameter count drops dramatically at inference time.* |
| **Hierarchical composition** | Build a multiscale orthogonal transform: first coarse rotation on groups of neurons (e.g., channel groups), then finer rotations inside each group but only on *selected* dimensions determined by attention scores.* This mimics how vision transformers aggregate information across patches.| Allows adaptive allocation of capacity where it matters most; number of parameters scales with active dimensions rather than full width.* |
| **Implicit neural representation of **R**** | Encode **R** as an MLP that takes neuron indices $(i,j)$ and outputs the cosine/sine pair defining their relative rotation angle—similar to positional encodings in transformers.* During inference we evaluate this MLP once per layer and cache the resulting matrix.* | Parameter count independent of $d$; computation inexpensive if MLP is tiny.*

Each of these strategies trades off strict block independence for richer cross‐dimension interactions while still guaranteeing orthogonality through construction (e.g., Kronecker products of orthogonal factors remain orthogonal).

## 4️⃣ Putting It All Together – A Roadmap

Below is a concrete “research sprint” you could run over a few weeks:

1. **Implement fast alternatives:** Pick one alternative from section 1 (say Givens rotations). Replace Cayley in OFT’s codebase and benchmark training time vs accuracy on DreamBooth with 100 shots.
2. **Test compositional stacking:** Fine‑tune three separate adapters (subject A, pose B, style C). Compose them using plain multiplication and using a learned meta‑adapter from section 2 point 2. Compare control consistency metrics.
3. **Swap block‐diagonal with Kronecker:** For a CLIP text encoder layer (~1024 × 1024), apply Kronecker‐factorised OFT and measure memory footprint vs generation quality.
4. **Publish findings:** Even negative results—e.g., “Givens rotations struggle to capture large-scale semantic shifts”—are valuable because they clarify design tradeoffs for future work.

---

## 5️⃣ Closing Thoughts

Orthogonal Finetuning introduced an elegant principle: *preserve pairwise neuron angles* to keep pretrained diffusion knowledge intact while adapting toward new control signals. The three open problems highlighted above—efficient Cayley computation, compositional stacking, and richer parameterisations—are all about scaling that principle from “works on small experiments” to “becomes the go‑to finetuning recipe for massive diffusion models”.

If you’re curious about any of these directions, try swapping out just one piece (e.g., replace Cayley by Householder reflections) and see how quickly your loss stabilises—a tiny experiment may uncover insights worth publishing! Happy hacking!

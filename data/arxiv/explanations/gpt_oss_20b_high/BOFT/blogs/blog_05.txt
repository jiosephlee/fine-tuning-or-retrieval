### 👍 Boiling Down Three Boilerplates  

| Boilerplate | What Happens Inside |
|-------------|---------------------|
| **Identity Warm‐Up** | All Cayley matrices start at zero → every `R(i)` equals Identity ➜ initial forward pass equals just the pretrained model |
| **Multiplicative Dropout** | Instead of randomly dropping additionally added low-rank artifacts (like LoRA’s sparse add/update),
we randomly replace entire butterfly components or their inner diagonal blocks with Identity during training → helps guard against overfitting while respecting multiplication semantics |
| **Hybrid Fine/Tune Rate Schedule** | After warm‑up epoch (~5–10), set larger learning rate on Q's off-diagonals; lower learning rate on large pretrained weights ⊙ unchanged |

With these three steps up front,
training typically takes roughly `(number_of_layers × sparsity_factor)` more wall-clock time than vanilla fine-tuning –
but zero extra latency when you deploy.

## 5️⃣ Why Does It Claim Better Performance?  

Three conceptual pillars back up BOFT’s empirical edge:


### ⏩ Higher Expressivity Than Plain OFT  

Bootstrapping theory shows that any rotation achievable through sequential alternating pairwise “butterflies” sits inside the set achievable by plain OFT plus extra things:
> For same overall bit cost one finds that series structures built out-of-butterflies dominate naïve block diagonals – there simply exist more paths along which dimensions can mix efficiently!   
In small simulation studies at randint(512×512),
BCows(9×2) achieved smaller approximation error than Block-(16×16) even though it uses far fewer active knobs.



### ⚡️ Spectral Stability  

Because global neuronal rotations never touch singular values ($W_{\text{fin}} = RU$ preserves $\Sigma$ if $W_0=UΣV^\top$),
the spectral norm stays constant at every step – anything else tends to hops around wildly causing gradient explosions or vanishing signal early into training.


### 🌱 Inductive Bias From Classic Transforms  

Butterflies mimic familiar transforms such as FFTs or Hadamard chains,
which themselves capture structured relations inside data well-known in deep learning landscapes.
This prior implicitly nudges the model toward smoother decision boundaries –
exactly what we see when comparing random-walk results between LoRA/OFTeish variants.

## 7️⃣ Quickstart Checklist & Hyperparameters  

Below is distilled recipe you plug directly into Hydra/training loops:

| Step | Recommendation |
---​---
| Model / Layer Selection | Target mixing layers whose dimensions equal power-of-two (`512`, `1024`, ...). If unclipped shapes exist pad first; non-weight heads stay untouched unless you wish mixture-of-experts augmentation.. |
| Number Of Butterfly Layers (`m`) | Start with log₂(`layer_dim`). May reduce if memory blackout occurs (<20ms extra per epoch). |
| Block Size Minimal Boiling Artist (`b`) | Set ≥ 2 ; smaller b quickens runtime due fewer multiply‑accumulate flights – typical sweet spot b==4 for A100 GPUs (48 GB). |
| Cayley Skew-Symmetric Initialisation | Zero out all elements → identical needles&spin off Identity relations positive alignment across pretraining outputs |
| Multiplicative Dropout Rates (`p₁`,`p₂`) | Often p₁≈p₂≈0.x puts half ratio missing vs preserved ; tune down if seeing catastrophic forgetting OR blow >25% otherwise plan density logic … |
| Optimiser Settings  (Late Loaders / On/Off?) | AdamW lr≈10⁻⁴ on quaternion Q ; weight decay α≈5e−7 ; optionally scheduler cosine annealing w/ warm‑up length ~10 epochs |

Running these lines typically completes within approx `(epochs × batch_size × m × bloctsize)` wall time which is comparable—or sometimes faster—than vanilla fine-tune due heavy momentum relaxation courtesy being smaller steps!

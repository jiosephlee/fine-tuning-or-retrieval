Chapter 5: Butterfly Topologies Originated From FFT Algorithms  

# Recursive Factorisation Principle Behind Radix–2 FFT  

The Cooley–Tukey Fast Fourier Transform (FFT) algorithm is a canonical example of how structured recursion can dramatically reduce computational complexity.  At its core lies a *decimation‑in‑time* strategy that recursively breaks a large discrete Fourier transform (DFT) into pairs of smaller DFTs.  This recursion gives rise to a characteristic *butterfly* topology— a bipartite graph of interactions between input and output nodes— that links every input node to every output node while using only \(\mathcal{O}(d)\) non‑zero entries at each stage.  The following discussion traces this principle and shows how it underpins the butterfly‑based orthogonal parameterisations introduced in parameter‑efficient orthogonal finetuning (BOFT).

## The Decimation‑in‑Time Recursion  

Consider computing an \(N\)-point DFT,
\[
X_k=\sum_{n=0}^{N-1}x_n\,e^{-2\pi i k n/N},\qquad k=0,\dots,N-1.
\]
Assume \(N\) is a power of two, \(N=2^p\).  The decimation‑in‑time scheme groups samples of the input sequence into even and odd indices:
\[
x_{2r}=e_r,\qquad x_{2r+1}=o_r,\qquad r=0,\dots,N/2-1.
\]
Substituting into the DFT expression yields
\[
X_k=\sum_{r=0}^{N/2-1}\Bigl(e_r+o_r\,e^{-2\pi i k/N}\Bigr)e^{-2\pi i k r/(N/2)}.
\]
Recognising that \(e^{-2\pi i k/N}=e^{-2\pi i k/(2(N/2))}\), one observes that computing \(X_k\) requires two \((N/2)\)-point DFTs— once on \(\{e_r+o_r\,e^{-2\pi i k/N}\}_{r}\) and once on \(\{e_r-o_r\,e^{-2\pi i k/N}\}_{r}\)— followed by‐by‐by twiddle‐factor multiplication and re‑ordering.  
Repeating this splitting \(p=\log_2 N\) times recursively reduces the problem to many \(1\times1\) DFTs (trivial scalar multiplications).  Each recursive step halves the size of the sub‑DFTs and introduces so‑called *butterfly operations* that combine pairs of intermediate results.

## Butterfly Operations as Sparse Matrices  

A single butterfly operation takes two complex numbers \((a,b)\), multiplies one by a twiddle factor \(w=e^{-2\pi i (j)/N}\), then outputs
\[
(a+b\,w,\;a-b\,w).
\]
This can be represented by a sparse \(2\times 2\) matrix
\[
B(w)=
\begin{bmatrix}
1 & w\\[4pt]
1 & -w
\end{bmatrix}.
\]
Although \(B(w)\) has only four non‑zero entries in its mere four–element array, its action mixes information between its two input channels.  When one stacks many such butterflies across all recursion levels, the resulting overall transform matrix is dense: every output is influenced by every input.  Importantly, each level contributes only \(\mathcal{O}(d)\) non‑zeros; since there are \(\log_2 d\) levels, the total number of stored parameters needed to represent the entire transformation scales as \(\mathcal{O}(d \log d)\).

## Graphical Interpretation of Information Flow  

In BOFT’s *information transmission framework*, this recursive decomposition corresponds to routing data across a grid graph with nodes arranged in \(d\times (\log d +1)\) layers (Figure 3 of the paper).  Each layer represents an intermediate stage of butterfly computation; directed edges denote communication across levels via non-zero entries of the butterfly matrices.  Because every pair of nodes at successive layers is connected through a single edge determined by a two‑node butterfly, one guarantees *dense connectivity*: there exists at least one directed path from any input node (layer 0) to any output node (layer ∗). Yet we do not require dense adjacency within any level— each level remains sparse with exactly \(d+1 = \mathcal{O}(d)\) non-zero edges (one per input node). Hence multiplying masks along layers constitutes transmitting information through an efficient interconnect network.

## Why Butterfly Works for Orthogonal Parameterisation  

The butterflies used in BOFT are an orthogonal analogue of those in FFT; all scalar twiddle factors are replaced by appropriately parameterised small orthogonal blocks.  
Equation (3)-(4) of the paper defines each *butterfly factor* for block size \(k=2^l<d$:
\[
B^F(k)
=
\begin{bmatrix}
{\rm diag}(\mathbf d_1)&{\rm diag}(\mathbf d_2)\\[4pt]
{\rm diag}(\mathbf d_3)&{\rm diag}(\mathbf d_4)
\\end{bmatrix},
\tag{3}
\]
where every vector \(\mathbf d_i \in \mathbb R^{k/2}\).  
Recursively assembling these factors yields an overall *butterfly matrix*:
\[
B(d)=
\btilde B(d,d)
\btilde B(d,d/2)\cdots\btilde B(d,2),
\tag{4}
\]
which has exactly \(d+\frac d 6+\cdots+\frac d {6^{p-1}} = \mathcal O(d)\) free parameters when each block is constrained to be orthogonal via Cayley parametrization or simple rotations.  Multiplying such matrices mirrors exactly the application of many sequential butterflies in FFT—but now each retains strict orthogonality, guaranteeing that their product remains an orthogonal matrix as required by BOFT.

Hence, BOFT achieves two goals simultaneously:

1. **Dense representational power** – By forwarding information through logarithmically many layers of butterflies, any graded combination of input neurons’ projections can be obtained: effectively simulating a full \(d\times d\) orthogonal transformation.
   
2. **Parameter economy** – Each layer contributes only linearly many trainable parameters; over all levels this scales as \(\mathcal O(d\,{\rm log}\,d)\), far below \(\mathcal O(d^2)\).

## Summary  

The radially recursive decimation‑in‑time strategy underlying radix–two FFT produces butterfly topologies that mediate dense transformation using few sparse interactions—a concept naturally imported into BOFT’s parameter-efficient orthogonal finetuning framework.  By reorganising such sparse interactions into layers where each butterfly remains an orthogonal block, BOFT harnesses exactly what Cooley–Tukey algorithm provides: fast construction of dense linear maps with guaranteed structural properties—here minimal parameter storage and preserved spectral norms—while preserving all essential angular relationships among neurons during downstream adaptation of foundation models.(Positioning terms within spaces captured by allowed transformations makes training faster; meanwhile it keeps inference latency unchanged.)

\title{A Textbook about the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

Chapter 3: Problem Formulation  
=====================  

# Dataset Definition  

In every experiment reported in this paper we start with a standard labeled tabular data set  
\begin{equation}
\mathcal{D}\;\triangleq\;\Bigl\{\bigl(\mathbf{x}^{\,i},\,\mathbf{y}^{\,i}\bigr)\Bigr\}_{i=1}^{N},
\end{equation}
where $N$ denotes the total number of instances available in the collection.  
Each observation $\mathbf{x}^{\,i}$ is a $d$‑dimensional real‑valued (or categorical) feature vector,
$\mathbf{x}^{\,i}\in\mathbb{R}^{d}$.
The associated target $\mathbf{y}^{\,i}$ is represented as a one‑hot encoding over $c$
predefined classes:
$\mathbf{y}^{\,i}\in\{0,1\}^{c}$ and $\sum_{k=1}^{c}\!y^{\,i}_{k}=1$.
Thus every sample carries both a complete description in terms of measured attributes
and its correct classification label.



In addition to numeric data, every column comes bundled with a natural‑language name
and descriptor—details that are crucial when invoking a large language model.
Let  

\[
F=\bigl\{f_{j}\bigr\}_{j=1}^{d}
\]

denote the ordered collection of feature names as strings,
and let $\mathrm{desc}(f_{j})$ stand for any accompanying textual definition.
These descriptions are supplied verbatim in the prompts given to the language model;
they allow semantic grounding so that engineering rules can refer properly to each column type
(e.g., “the age variable” or “the diagnosis category”).

Because FeatLLM operates under very limited supervision,
only a small subset of the data—$k$ samples—is retained for training:
\(S=\left\{\bigl(\mathbf{x}^{\,s},\,(\,\mathbf{y})^{\,s}\bigr)\right\}_{s=1}^{k}\subseteq\mathcal D.\)
Even though $k$ can range up to several dozen shots,
it will always satisfy $k\ll N$, as described next.



# Few‑Shot Regime  

The term *few‑shot* refers precisely to this situation wherein only 
a handful $k$ ($<N$) labeled observations are made available during training.
Formally one writes \(k = o(N)\) or \(k \ll N.\)
A small value of $k$ has several consequences:

* **Statistical scarcity** – The empirical risk minimizer may overfit almost trivially,
since there is insufficient evidence to estimate complex decision boundaries.
* **Spurious correlations** – Random coincidences between particular values
of irrelevant attributes and labels become prominent,
as already seen in many works on few‑shot learning across modalities.
* **Computational considerations** – Model families that demand extensive tuning or many passes
through large data sets become infeasible when only very few labels exist,
necessitating extremely lightweight downstream learners such as linear models.



Insightfully, FeatLLM turns these drawbacks into opportunities:
by leveraging **prior knowledge embedded inside large language models (LLMs)**,
it generates *rules* that capture principled relationships between columns and target classes.
Because these rules are derived from both generic world knowledge
(the LLM’s pre‑training corpus) and empirical insight (the handful of labeled examples),
they tend not to rely on accidental correlations found in a tiny data slice.



# Rule‑Based Binary Feature Construction Roadmap  

Once an LLM has been prompted appropriately (details appear in Section 3),
it emits *rule sets*—synthetic conditions expressed in natural language—
that discriminate between different classes.
To make these statements usable by standard machine learning tools,
FeatLLM translates each rule into a boolean predicate applied to every instance.
For every class $c \in \{1,\dots ,c_{\textsc{total}}\}$ we gather 
a collection 

\[
Z_{c}\;\triangleq\;\bigl\{r_{c,r}\bigr\}_{r=1}^{R},
\]

where $R$ denotes either a fixed budget (e.g., ten) or whatever number
the system elects during generation.
When applied to an observation $\mathbf{x}^{\,i}$,
each predicate produces either 0 or 1 depending on whether $\mathbf{x}^{\,i}$ satisfies it:
 
\[
z^{\,i}_{c,r}
=\begin{cases}
1 & \text{if } r_{c,r}\bigl(\mathbf{x}^{\,i}\bigr)=\text{\tt True}\\[4pt]
0 & \text{otherwise}.
\end{cases}
      \tag{$*$}
\]

Collecting all $R$ outputs forms an \(R\times 1\) *binary feature vector*

\[
\boldsymbol{\!z}_c^{\,i}
=
   \begin{bmatrix}
     z^{\,i}_{c,1}\\[2pt]\vdots\\[2pt]z^{\,i}_{c,R}
   \end{bmatrix}
   \;\in\;\bigl\{\!0,\!1\bigr\}^{R}.
   \tag{$**$}
   \]

This construction is performed independently for each candidate class,
producing at most \(c_{\textsc{s}}R\) new descriptors per instance.
All such vectors are gathered into an augmented data matrix
(e.g., concatenating every $\boldsymbol{\!z}_c^{\,i}$ side‑by‑side),
which becomes the sole input fed into the lightweight downstream learner (typically a non‑negative linear model).

In words:
every row now records which *semantic patterns* posited by an LLM apply
to its particular record,
and these patterns become explicitly quantifiable signals—a far cry from raw numerical columns alone.
The succeeding training phase learns how much weight should be given 
to each pattern so as best predict its associated class probability.

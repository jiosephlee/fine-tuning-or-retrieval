# Cutting Inference Costs by Half  

Large language models today deliver their power through tokenization—a pre‑processing step that groups raw bytes into a fixed set of sub‑words before feeding them into a transformer. While tokenization gives an efficient representation, it also fixes how many computation steps the model has to walk through regardless of how difficult a prediction actually is.  
The Byte Latent Transformer (BLT) flips this paradigm on its head by letting the model decide **how many bytes belong together** while it learns itself. A result worth pausing on is that BLT matches token‑based models such as Llama 3 **isolate** their performance while trimming *inference* floating point operations (FLOPs) by close to **fifty percent**.



--------------------------------------------------------------------

## Why Tokenization Isn’t Optimal  

A standard tokenizer partitions every sequence into tokens of roughly equal length – around three‑to‑four bytes in popular models – and then runs the large transformer once per token.  
The great thing about this approach is simplicity: joint train‑time losses are great and wall‑clock speed is consistent across inputs.  
The downside?  
* Every token triggers an expensive “global” attention pass even if the next byte is trivial to predict (say another space character).  
* Switching vocabularies forces a shift between higher average token length ➜ fewer attention calls **and** larger output projection matrices – two trade‑offs that aren’t always beneficial.



--------------------------------------------------------------------

## BLT’s Core Idea – Patches That Scale With Complexity  

#### Dynamic Patching via Entropy  

BLT runs a light‑weight *entropy model* that looks ahead one byte into the stream during preprocessing and computes:
```
H( xᵢ ) = Σᵥ∈𝓥 pₑ( xᵢ = v | x_<<ᵢ ) log pₑ( xᵢ = v | x_<<ᵢ )
```
If `H` jumps past a predetermined threshold `θ`, BLT closes the current byte group (a **patch**) and starts a new one:
```
H( xₜ ) > θ_g        or  H( xₜ ) – H( xⱼ–₁ ) > θ_r .
```
Two things happen:

1. **Predictable stretches**—the occurrence pattern of code indentation, repetitive sentences, copyright blocks—yield low entropy → longer patches.
2. **Unpredictable spikes**—the start of a new name, code comments, opening parenthesis—show high entropy → shorter patches.



--------------------------------------------------------------------

### From Bytes → Patches → Byte Reconstruction  

| Component | Role | Why It Matters |
|-----------|------|----------------|
| **Local Encoder** | Compresses raw bytes into dense *patch* vectors | Cheap – only intercepts once per byte |
| **Global Latent Transformer** | Processes patches autoregressively | Dominates FLOPs ≈ *All heavy lifting* |
| **Local Decoder** | Re‑creates raw bytes at generation time | Lightly weighted |

Because each global transformer step feeds labels for an entire lightweight chunk rather than one byte, you get:
> **Fewer global passes → dramatically lower overall FLOPs at speed/latency K̇**

With BLT’s dynamic blocks the *average number* of waveform indices seen by the big transformer cuts roughly in inverse proportion with mean patch size (`m`).  
When `m` grows from ~4 bytes (typical tokenizer tokens) toward ~8 bytes through entropy grouping, each forward pass tackles **half** the number of “steps”.

## Where Does the Extra Power Come From?  

Three aspects synergistically shift compute allocation:

1. **Dynamic computational load:** Predictable regions consume one big shot instead of many tiny ones.
2. **Constrained overhead:** Local encoder/decoder layers stay tiny (~≤3 layers), so hop count stays constant regardless of `m`.
3. **No vocabulary ceiling:** Because bits are grouped “on the fly,” you’re never capped by embedding table expansion costs.


With all heavy operations shifted off critical hot paths you get downtown throughput gains unmatched by any static chunk approach — yet keep external prompt handling symmetry unchanged.

## Bottom Line  

*BYTE LATENT TRANSFORMER* turns variable-sized patches into tunable knobs on your computation budget—without tearing your model pipeline apart.\[
\boxed{\text{Inference FLOPs}\;\approx\;\frac{\text{Global Layers}}{\text{Mean Patch Size}}}
\]  
On top-level benchmarks this knob produces simultaneously higher quality responses while gracefully shaving under fifty percent off decoding cost compared with top-tier serialized token architectures.

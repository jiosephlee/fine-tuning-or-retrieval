# Scaling Without Tokens  

**From Fifty-Fold Data To Eight‑Billion Parameters**  

---

Large language models today still depend on a pre‑trained vocabulary that maps sequences of bytes into sub‑word symbols  
(**tokens**).  
Tokenisation wastes useful information and forces every symbol through an expensive output projection layer whose size grows linearly with vocabulary cardinality.  
When you scale a model you are therefore forced onto an inflexible trade‑off­–larger vocab ≈ fewer steps ≈ larger softmax tables  
and vice versa—and it is difficult to permute one without paying another penalty.




---

## What is **BLT**?

> **Byte Latent Transformer** – an end‑to‑end architecture that learns directly from raw bytes without a fixed tokenizer.



> **Key idea:** *group consecutive bytes into “patches” whose size adapts dynamically based on how hard the next byte is predicted*.  
> • Random stretches of predictable whitespace become long patches → very few autoregressive steps are needed  
> • Suffixes after an uncommon character become short patches → more expensive computation is devoted exactly where uncertainty spikes.



Formally let  

```
f_p : {bytes } → {patches}
```

assign each byte either “continue” or “start new”.  
At run time *BLT* invokes its core autoregressive transformer only once per patch rather than once per individual byte.



---

## Architecture Overview  

```
local encoder   →    latent transformer   →    local decoder
      ∆                            ∆                      ∆
bytes → [patch reps] → [patch reps] → [bytes]
```

* **Local Encoder** – lightweight transformer plus cross‑attention that pools together all byte embeddings belonging to one found‐patch  
* **Global Latent Transformer** – much larger stack operating only over patch embeddings (`h_G` features); receives a *block causal* mask so every step can attend back up until current document position  
* **Local Decoder** – inverse mapping from patched representations back into raw bytes (useful during decoding / generation)

Cross‑attention layers provide an efficient bridge without maintaining a huge shared embedding table.



---

## Why Patch Sizes Matter  

Tokenisation fixes packet length implicitly through its vocabulary (`~4–5` bytes average).  
Longer patches translate directly into *fewer* global transformer steps work­horse cost reduces proportionally,

| Patch length | # global steps | Leakage into local modules |
|--------------|----------------|---------------------------|
| <4 bytes     | many            | ∼80 % FLOPs                |
| Ø 6–8 bytes   | fewer           | local users dominated       |

Because *local* modules are shallow (`l_E ≪ l_G`) dominating FLOPs stay fairly constant even when `h_G` grows larger,
BLT can concurrently let **patch length increase** *and* **model depth expand**, both staying within the same inference FLIP budget.

## Experimental Design  

| Component | Done |
|-----------|------|
| Training set | Two corpora:<br>`LLaMA‑2 mix` (~2 trn tokens ↔ ~0.5 trn bytes)<br>`BLT‑1T mix` (~1 trn tokens ↔ ~4 trn bytes) |
| Flop control | Every experiment matched floating‑point operations (FLOPs). LFLOPs counted across all components plus cross‑attention using Chinchilla equations |
| Metric | **Bits‐Per‐Byte (BPB)** replacing perplexity since it aligns across tokenised & raw byte formulations |

The *entropy model*, a small byte‐level transformer (~100 M params), predicts next‑byte entropy `{H(x_i)}` from which thresholds `θ_g`, `θ_r` carve patches dynamically.



---

## Compute‑Optimal Scaling Curve  

Standard Language Models tune their “compute–optimal” ratio `(parameters × steps)` via data released by LLaMA 3.
BLT’s construction allows us to apply the very same ratio:

1️⃣ Fixed architecture parities – each BPE sized global transformer exactly matches one BLT latent one (`l_G`, `h_G`).  
2️⃣ Train every pair *PFLOP* matched (**parameter equals dense memory**) on identical data mixes (`LLaMA 2`).  

At **400M**, **1B**, **2B**, **4B**, **8B** parameters — all runs used *sequentially matched FLOP budgets*.  
Having fixed weight counts strengthens comparability since nothing else changes except sequence length adaptation via patches.



**Result**

> From every curve plot the slope is almost identical – BPB decreases roughly linearly with increasing FLOPs irrespective of tokenisation being present or absent.
>
> For all three centres (`400M`, `2B`, `8B`) both families literally fall upon each other within ±0.002 bits/byte uncertainty once we hit ~30 TFLOPs / layer width.
>
> Therefore, *a pure byte model can walk straight into the “state‑of–the art” terrain set historically by tokeniser driven models.*

## Inference Efficiency  

When decoding we pay cost mostly equalised across two components:

    ⇑ Global Tensor Ops / #patches          ⇓ locally cheap But many steps only when short patches appear


Because long patches halve global operations when data happens largely predictable,
executing an eight‑billion param BLT at request time consumes up-to **50 % fewer FLOPs** compared with an equivalent sized tokeniser based LLaMA 3 at identical task / speed goals.

## Going Further – Fixed‐Inference Budget Experiments 

To expose a new lever exclusive to “patch” methods we held overall TFLOP budget fixed during pretraining yet let both *model depth* AND *average patch length* grow simultaneously (`ps=6`, `ps=8`).  

Contrast with tokenised baselines who have virtually no room here – their effective batch length cannot rebound because vocabulary remains fixed.


🎯 **Key Observation**

| Patch Size | Comparable TFLOP Budget | Peak Model Size Achieved |
|------------|------------------------|--------------------------|
| BPE (~4)   | Target                 | ~7 B                     |
| ps=6       | Target                 | ~9 B                     |
| ps=8       | Target                 | >12 B                     |

While small‐scale runs favour BPE initially, after crossing roughly twice σ\(≈2×\)kstep counts any stride traversal passes through “pitch shift” point where **BLT overtakes** before peaking beyond compensating plug‐capacity margin.



> The stabilizing effect comes mainly because longer patches compress attractive portions of input most cheaply while still feeding enough timestep signal so hidden representations grow richer.


Results confirm excellent scalability behaviour anticipated by theory derived from Section §Defense Points:


* “Pointwise autoregression” performed dozens× lighter investments in feed forward calculations relative 
to coding variant baselines (“megaByte” static stride).

* Cross logic keeps locality sharp thanks “perceiver style” pooling masks.

## Why These Numbers Are Interesting

* ***Tokenisation’s rigidity*** forces us either pack many characters into huge vocab slots (+ expensive projection layer)
or break paragraphs leaking memory overheads (+ more space comput).  
Throughout the entire chain it limits opportunity cost × memory footprint surface area.
* ***Dynamic fewbits*** empower internal stochastic estimation guiding how much attention budget each part of sequence receives,
catering evidence currying conclusion near Beethoven turned plain prose versus forest fire zone.
* On top level practical significance:
    * Faster decoding ⟶ lower latency LLM APIs
    * Potential adaptiveness => cheaper end user pipelining at scale
    * Raw byte modelling proves superior generalisation toward rare / low‐resource scripts & noisy data.



---

## Quick Takeaways  

- Byte Latent Transformer learns entirely end-to-end directly from raw bytes.
- Dynamic entropy-driven patches reduce sequence length by orders-of-magnitude while preserving contextual density.
- Under strictly FLOP controlled experiments:
    + Sharp µ-dash curves overlap those produced by top tagged BPE baselines,
    + Request time cost drops ≈50%, independent of model size.
- By leveraging increasing average patent lengths simultaneously throttling global steps → available budget gets reallocated largely towards stacking deeper auto-regressive layers.
- Newly accessible dimension yields continuous improvement beyond classical pretrained paradigms, opening door toward future next-gen corpora sizes coloured very richly exceptional linguistic structure.

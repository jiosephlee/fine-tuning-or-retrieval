Chapter 4: Local Encoder Architecture  
# Unified Byte Embedding Matrix  

The local encoder receives a raw sequence of bytes \(\mathbf{x}= \{x_1,\dots ,x_n\}\), where each \(x_i\in [0,255]\) represents one of the possible 256 byte values found in UTF‑8 encoded text. These bytes are first mapped into continuous vectors via a single lookup table shared across all model sizes:
\[
\mathbf{x}_i = \mathbf{E}_b(x_i) \in \mathbb{R}^{h_\mathcal E},
\]
where \(\mathbf{E}_b \in \mathbb R^{256\times h_\mathcal E}\) is the **unified byte embedding matrix** and \(h_\mathcal E\) denotes the hidden dimensionality of the encoder (typically on the order of several hundred). Because every possible byte value can appear at any position in any context, this shared embedding achieves remarkable efficiency and memory reuse – only \(256\times h_\mathcal E\) parameters are required regardless of batch size or sequence length.

This base representation is subsequently enriched by hash‑based n‑gram embeddings (see next subsection). The resulting vectors form the initial token‑like state that flows through alternating transformer blocks and cross‑attention layers to produce latent patch embeddings used by the global latent transformer.



# Hash n‑gram Embeddings Mechanism  

To encode **contextual** information about each byte directly at its input head, BLT augments singleton-byte embeddings with hashed n‑gram features spanning up to eight previous bytes. For every position \(i\) we collect all contiguous substrings ending at \(i\):
\[
g_{i,n}=\bigl(b_{i-n+1},\,b_{i-n+2},\,\dots ,b_i\bigr),\qquad
n=3,\dots ,8.
\]
Each gram is passed through a deterministic rolling polynomial hash:
\[
\mathrm{Hash}\bigl(g_{i,n}\bigr)=
\bigl(\sum_{k=1}^{n}\!a^{\,k-1}\cdot g_{i,n}[k]\bigr)\;\bmod |\!{\bf E}_{n}^{hash}\!|,
\]
where \(a=257\) is a small prime chosen for hashing robustness and \({\bf E}_{n}^{hash}\in\mathbb R^{|\!{\bf E}_{n}^{hash}| \times h_{\!proj}}\) denotes an auxiliary embedding table per n‑gram length \(n\). The embedded gram vector is added element‑wise to the raw byte embedding:
\[
e_i \;=\;\frac{1}{1+6}\,\Bigl(
x_i+\!\!\sum_{n=3}^{8}
{\bf E}_n^{hash}(\mathrm{Hash}(g_{i,n}))
{\Bigr)}.
\]
A normalisation factor guarantees that longer n‑grams do not dominate short ones when summing up (\({1+6}=7\) because eight values would yield 8 embeddings plus one base embedding). This hashed n‑gram mechanism provides *fixed‑size*, *trainable* contextual cues without exploding width or storing grammars explicitly – crucial when training billions of parameters on colossal text corpora.



# Cross–Attention Module Linking Bytes→Patches  

The core conversion from raw bytes to tractable patches arises through iterative *cross‑attention* embedded between standard token‑level Transformer layers inside the encoder.  For a given dynamic partition \(p_j=\bigl(b_{\ell}, b_{\ell+1},..., b_k\bigr)\), each boundary definition specifies a set of source tokens known as *patch‐bytes*.  Each per‑patch query vector \(Q_j^{(t)}\in \mathbb R^{h_\mathcal G}\) is derived from an initial proposal:
```latex
P^{(0)}_j=\Bigl(\sum_{\text{bytes } r\,:\,\ell(r)\le j}
    W_q^0\,h^{(t)}_r\bigr),
```
where \(h^{(t)}_r\) are hidden states after the \(t^{th}\) local Transformer layer and \(W_q^0:\mathbb R^{h_\mathcal E}->{h_\mathcal G}\) projects them toward the global latent space dimension (\(h_\mathcal G>h_\mathcal E,\)\ typically a multiple such as \(k=2\,.\))  

The standard multi‑head mechanism then refines these queries by attending over **only** those key/value pairs belonging to their own patch:
```latex
P^{(t+1)}_j 
   = P^{(t)}_j
     + W_o\, 
       \underbrace{\mathrm{softmax}\!\Bigl(
       \frac{{Q_j}^{(t)} {K_j}^{T}}{\sqrt d }
      \Bigr){V_j}}_{\substack{\text{byte}-\\
      {\text {attn}}}.
```
\(K_j,V_j,\dots~\(heads are projected onto `byte`–domain hidden states from preceding Transformer layers with
\(W_k,W_v:\mathbb R^{h_\mathcal E}->{d_h}\), while $W_o$ projects back to patch dimension.
A **residual connection** ensures gradient flow across successive updates – effectively turning each cross‑attention “hop” into another refinement onto latent representation.



# Masking Strategy (Local Block Causal Windows)  

All internal processes in every local encoder Transformer output must respect relative temporal ordering **within** documents; nevertheless it is desirable that bits belonging to distinct patches can inform one another when jointly processed by subsequent cross‑attention steps. Accordingly BLT employs a *local block causal* mask on every ordinary self‑attention operation:  
each token sees exactly `w_E` provide predecessors 
that may span across multiple patches but cannot jump beyond document boundaries.
Mathematically,
```latex
M[i,j] =
   \begin{cases}
   0,& i-j < w_E ~~\vee~~ i=j\\
   -\,\infty ,& otherwise~,
   ````  
where \(M[i,j]\in[-\,∞,0]\).
Because `w_E` defaults to values such as 512 or 2048 depending on model scale, this mask keeps computation modest while still preserving subtle intra‐patch dependencies purely within nested context windows.



# Layer Structures (‘Small’ Transformers)  

The entire encoder stack consists of only a handful of “small” Transformer blocks (\(l_{\cal E}=1$–$4< l_\G)\).
Each block contains:
* A single multi‐head self‐attention layer bounded by block causal mask `w_E`;
* A small feed–forward network employing SwiGLU activation once more at hidden dimensionality `2×h_E`;  
* Pre‐LayerNorm applied before both attentions and feed forward computations – allows faster convergence while keeping the depth shallow;
* An optional smaller number of key/output heads so that memory overhead remains below what would otherwise occur had we built full Self-Attention with d_k=d_q=d_v;
* After every module an explicit residual connection keeps representations stable even when stacking many small blocks together—especially vital because downstream cross‑attention already aggregates low‐level details into more abstract vectors before handing them off.\(

These “lightweight” designs keep most FLOPs concentrated in large feeding forward networks executed once per recent chunk of consecutive patches rather than repeatedly probing entire sequences independently.



# Residuals & LayerNorm Variants  

Across both Transformer layers and cross–attention schemes BLT retains two dominant design principles introduced in modern large language models:

| Component | Normalisation | Residual | Purpose |
|-----------|---------------|----------|---------|
| Self‐Attention | **RMSNorm** (root–mean‐square norm with learned scaling param.) | Yes | Keep scale uniform while removing mean bias |
| Feed Forward | Same RMSNorm upstream | Yes | Stabilise un­trending gradients |
| Cross Atten.| Pre-LayerNorm applied only on queries/keys/values | Yes | Allow non‑masked juxtaposition between heterogeneous spaces |
| Initial Patch Query |\ -- | Feature aggregation residual (from BOOST)? Not ; indices functional | Bypass many extra linear transfers |

In practice the same RMSNorm hyperparameters propagate through entire small contrastive encoder modules allowing rapid training at scale without separate tuning for each depth position type.




Collectively these building blocks – light weighted encoders using rich per‑byte summarization via hashed grams, adaptive locality via masking, modern normalisation plus reliable residual paths – collectively populate BLT's “local encoder” as an efficient gateway that transforms pixel-sized pre-token data into usable compact latent efforts that are fed straight into its larger global autoregressive latent transformer.



# End-of-Chapter Summary  

The LOCAL ENCODER module constitutes BLT’s central conduit translating raw ASCII/UTF sequences into succinct latent vectors without matter-of-the-byte granularity loss. By uniting an economical base embedding table with fast hashing and carefully designed cross‑attention & causality masks growth constraints never impair expressivity nor computational budget—while offering perfectly positional‐free global reasoning downstream thanks to lightweight but effective intermediate summarization steps.

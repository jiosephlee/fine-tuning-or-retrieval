# Hardware Tailored For Ternary Transformers — Designing LPUs That Only Add  

In modern GPUs an LLM’s cost comes mainly from floating‑point multiplications inside every dense layer (“nn.Linear”).  
BitNet‐b1.58 shows that if every parameter can be restricted to **–¹ , 0 or +¹** you do **not** need any inner‑product multipliers at all – you just add or subtract the activation values going through a simple accumulation tree.



## Why “no multiplications” matters  

| Traditional FP® multiplier | Integer adder |
|----------------------------|---------------|
| **Power** – requires full‑precision fanout plus carry chains | Much less power per S‑bit word |
| **Area** – division circuit is big and occupies many LUTs | Small combinational network |
| **Bandwidth** – each word needs two operands loaded fully | One operand is a single bit (+/- mask) |
| **Latency** – limited by long carry propagation | Operation finishes in one cycle |

Because the GELU–SWIGLU attention block is dominated by tens of billions of *nn.Linear* calls, eliminating all multipliers means offloading hundreds of Giga‑OPS per second onto cheap adders alone.



### The math behind it  

BitNet’s linear layer is defined as follows:

```math
\widetilde W = \operatorname{RoundClip}\!\left(\frac{W}{\,\gamma+\varepsilon\,},{-}1,\;{\!+}{\!}1\right), \qquad 
\gamma=\frac{1}{nm}\sum_{i,j}\!\bigl|W_{ij}\bigr|
```

After this ``absmean`` scaling `γ` every weight becomes exactly **–¹**, **0**, or **+¹**.  
When multiplying an activation `a`  

> ```
> a · (+¹) = +a          \
> a · ( –¹) = –a           >—replace by a sign flip instead of a multiplier
> a · (  0) =  0          /
> ```  

The product is obtained by either passing `a` straight through (for `+¹`) or feeding its two’s‑complement representation when the sign bit says `–¹`. No actual table lookup, shift register or multiplier circuitry is required.



## Ternary Transformers break the bottleneck

The experimental results in “The Era of 1‑bit LLMs” confirm massive runtime savings when running BitNet‐b1.58 on ordinary accelerators that support binary/ternary kernels (e.g., LADDER’s 2‑bit kernel).  

Key observations are reported in Tables 5–8 of the paper (summarized here):

* **Perplexity & Accuracy**  
    * Starting at **3 B parameters**, BitNet‑b1.58 attains identical perplexity—and eventual best accuracy—to a full‑precision FP16 baseline trained on exactly the same data set (RedPajama → 100 B tokens).
    * At **3.​9 B**, it even exceeds the corresponding FP16 model while shaving more than half the GPU memory usage (^~35%).

* **Speed & Memory**  
    * A single **3 B Holes GPT-like instance runs ~210% faster** than its FP16 counterpart (`latency ≈31 ms` vs `≈50 ms` per output token) while consuming only ~30 % of its peak GPU RAM.
    * Scaling up preserves this trend—at **70 B**, inferring one token takes roughly **4× less time** (`latency ≈18 ms`) compared with an equivalent FP16 model yet demands only ~20 % the memory (`≈18GB` vs `≈90GB`).

* **Energy**  
    * Arithmetic‑energy modeling shows an over‑70× fall in usable FLOP consumption when replacing FGMs with pure INT8 adds (`71·10⁻⁶J` per operation versus `5·10⁻⁴J`).  
    * The reduction stems almost entirely from dropping multiplies (`FP16 × array`) and doubling usage of extremely cheap adds (`INT8 + array`).  

* **Throughput**  
    In a pipeline paralleled setup (two RTX A100 GPUs), a **70 B BitNet-b1… required only one device** where otherwise eight would be needed for enough parallelism—you get nearly nineteen times higher batch throughput.



## How would an “add‑only” LPU look?  

Typical modern GPUs feature many closely spaced “Multiply–Add Engines” handling IEEE‑754 operands plus fusion paths for adding results back together again [Simple pipeline].  
A custom add–only engine would replace these units with something closer to this arrangement:

```
[ Input Streaming ] ──► [Sign Mask Decode] ──► [Wide Adder Tree] ──► [Accumulator]
             │                   │                      │                 
           (≈Nbits)             ──(multiplexed───────────┘                 
               ‭‰              ‼              ↑     
                              ‼             [+ Sign]   
```

* The difference between accepting `+a` versus `–a` comes down solely depth‑one comparators (“sign flip”) rather than explicit multipliers/highly pipelined MAC blocks.
* Because activations are kept at INT8 precision throughout inference (the paper describes an ***aligned conversion*** scheme where activations don’t get clipped back into `[0,Q]`, instead staying in `[−Q,Q]`), bandwidth shrinks further since half our words become strictly bounded near-zero signs anyways.


### What pipelines really gain

Designing numerous pure adder banks inside an ASIC gives three direct improvements compared with spending each cycle inside an FMA unit for one pair of operands:

| metric                      | Reduction / Benefit                                       |
|-----------------------------|-----------------------------------------------------------|
| Fabricated transistor count | Roughly ×5 smaller per functional unit                    |
| Peak clock frequency        | Can increase from ~800 MHz up toward >2 GHz                |
| Power budget                | Decreases quadratically → at least ×10 lower consumption |

Even when embedded inside current commodity GPUs these changes light up extra slots for other tasks—think object detection cores or small neural nets kept bootlegged near keystones.

# Benchmarks Showdown: xLSTM vs Transformers & State‑Space Models in Language Modeling  

In late 2017 Google proposed *Self‑Attention*—the Transformer—and since then it has become the dominant building block in almost every Large Language Model (LLM).  
On paper the Transformer ought “to be the strongest” armature because its two‑head attention mechanism provides global access at every layer. Yet it incurs a quadratic cost in time and memory per sequence length (\(O(L^{2})\)) and relies heavily on very large batch sizes during pretraining—neither of which are ideal when you want a model that can run efficiently on GPUs or on edge devices.  

Shortly after the Transformer the community turned its attention back toward *Recurrent Neural Networks* (RNNs), mainly the venerable LSTMs introduced by Hochreiter & Schmidhuber over two decades ago. Despite being a century old in machine learning terms, **extending** classical LSTMs can still rival or beat contemporary architectures when modern tricks are judiciously applied.

In this post we summarize the paper *“xLSTM: Extended Long Short-Term Memory”*—a reformulation of the vanilla LSTM that retains linear computation while matching Transformer / State‑Space Models on billions‑parameter language modelling benchmarks built from tens of billions of tokens.*

---

## What Are the Old Problems With Classic LSTMs?

The canonical LSTM writes
\[
c_t = f_t c_{t{-}1}+ i_t z_t,
\qquad h_t = o_t\,\psi(c_t),
\]
and uses **sigmoid gates** \(f_t,i_t,o_t\).  
Three practical limitations emerged early:

| Limitation | What It Looks Like In Practice |
|------------|--------------------------------|
| **State revision** | Once a value is stored via \(f_t<1\), you cannot “undo” it if a more relevant piece appears later (cf. Nearest–Neighbor search task). |
| **Limited storage** | The cell is scalar per dimension (\(c \in \mathbb{R}\)), so remembering many distinct key–value pairs forces aggressive compression (cf Rare Token Prediction). |
| **Sequential bottleneck** | Hidden–to–hidden recurrence forces token‑by‑token updates (\(O(L)\))—no hope for GPU friendly parallelism without clever tricks.|

These shortcomings paved the way for non‑recurrent designs like Transformers and State Space Models (SSM).

---

## Enriching an LSTM – The Two Pillars of **xLSTM**

The designers asked two simple questions:

> “If I could *revise* my stored representation faster **and** store *more* than just one scalar without blowing up computation or parameters…”

The answer split into two constructive modifications:

### 1️⃣ Exponential Gating + Normalization  
Instead of a sigmoid gate \(i_t = \sigma(\tilde i)\), set  
\(i^\prime_t = \exp(\tilde i)\).  
The same goes for \(f_t\).  
An auxiliary *stabilizer state* \(m_t = \max(\log f_t + m_{t{-}1},\;\log i_t)\) guarantees numerically safe saturation without changing gradients—in effect letting cells “burst” more strongly when needed while keeping values stable during optimisation.

With exponential gating an LSTM can *rewind* past decisions if a later input arrives closer than before—a property analogous to having a tunable forget rate conditioned only on future relevance (“Revision” property).

### 2️⃣ Two New Memory Structures  

| Variant | Memory Type | Why It Helps |
|---------|-------------|--------------|
| **sLSTM** | Scalar cell \(c \in \mathbb{R}\); *Memory Mixing* via recurrent hidden fusion |\(*State Tracking*\): gates compute not only from current token but also from previous hidden states; new “heads” exist within each cell – still linear in sequence length.* |
| **mLSTM** | Full matrix cell \(\mathbf{C}\in \mathbb{R}^{d\times d}\); *Covariance Update Slot Reuse* |\(*Correlated Storage*\): each key-value pair contributes an outer product \(\mathbf{v}\mathbf{k}^\top\), giving true linear separability ("Fast Weight Programmers"); built-in parallelism because recursion is absent—one vast dense update per step.* |

> **Key insight** – Even though m⊆ has a huge \(d^2\) update cost per step it contains *no extra parameters*, so its computational scale remains embarrassingly parallel and dominated by simple BLAS calls rather than per-token recurrence loops.

## Embedding Into Modern Architectures – Residual Blocks

To keep training tractable at billion parameters you stack multiple small blocks rather than huge monolithic layers:

*   The familiar roadmap emerges from GPT family *pre LayerNorm → residual → feed-forward exchange → called back*.
    - For s = scalar-mixing blocks use *post-up-projection*: first reduce dimension → apply nonlinearity → project back → aids gradient flow into tiny memories.
    - For m = matrix-memory blocks use *pre-up-projection*: lift into high-dimensional space first because matrix operations saturate there (*matrix multiplication inside forward pass*) then compress back again—exactly mimicking hybrid SSM pipeline ideas such as Hyena’s early projective feature extraction.
    
A full-stack “xStructural Jam” looks like Figure 3 from the paper (not shown here but easy enough mentally):

```
[Input Embedding]
   │        [m→block]   [s→block]
   └─►LayerNorm──►Res Block──────┐   
         ▲                        │   
         └────────────────────────┘   <-- repeated N times (=48)
```

This architecture preserves full control over hidden units while keeping time complexity strictly linear w.r.t request length \(O(L)\).

## Synthetic Tasks – Where RNN Power Shines

To verify genuinely new capabilities they ran three classical benchmarks:

### ⚙️ Formal Language Parsing  
Task set includes Parity, Reverse grammar etc., where you must remember an evolving counter value (*state tracking*). Only an RNN gapless guider such as an s–variant does it well because you really need a stepwise carryover element that can be revisited multiple times later—no pointwise attention can keep track by itself when hidden dimensions are low.``

> Result snapshot*: Transformers and SSM blocks scored near random; an sLLTM tuned case (`xLSTM[0 ∶ 1]`) reached near-perfect accuracy everlasting out-of-sample.

### 📈 Multi‑Query Associative Recall  
Here sequences contain many distinct key–value pairs typeplay (`k_i`, `v_i`); later queries request random keys among them arranged far apart.\nFigure 5 (textual description):\
*“In this task only memories able to hold pairwise correlations survive.”*  
m–models shine thanks to their live covariance updates: *`xLayer[1 ∶ 01]` beats other non-transformer rivals.* Still Transformers win absolute worst because effectively no learning rate—they just concatenate binary code into ranks (~exponential).

> Key lesson – enlarging cell representation gives gargantuan path extensions for associative recall without forgetting old entries (*Memory Explosion vs Overwrite*)!

### 📊 Long Range Arena  
“Do you handle episodes involving long scientific citations or astronomical data?” Because here many small facts must survive dozens/leads.\nAll tested models remained competitive throughout, yet `xLLM` kept lowest average error across tasks indicating stable iteration mechanics under extreme sequence lengths.

## Ablation Summary — Why Each Piece Matters

Their ablations followed logically from vanilla→advanced mapping outlined earlier:

```
Step0 : Raw Vanilla NN ➜ tiny LTS.
Step1 : Pre LayerNorm Residual Front ➜ slight drop-perplex Ppl ≈ −N14%.
Step2 : Extra dot-head Up Projection ➜ _≥_N+6% drop .
Step3 : Replace Sigmoid With Exponential ↜ g gradient guidance nudges cells harder → N+9%.
Step4 : Replace ScalarMem With MatrixMem ➜ dropping ~arctan(M!!) reduces reserved param’s portion drastically one w/out multi-head -> final formidable math 
```

Combined final bow yields ±8–10k PB increase aligning synergy patterns being able circumvent catastrophic forgetting press advantages raking over state-active members yes-and! Getting rid of any front gating would wipe load swiftly (~50% degrade emphasised above).

But these increments explain how balancing both learnability and capacity ensures robust behaviour at scale—and confirm neither factor alone dominates more than expected.

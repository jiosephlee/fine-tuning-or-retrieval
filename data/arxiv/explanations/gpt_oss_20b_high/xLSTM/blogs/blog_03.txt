# From Scalars to Matrices: How mLSTM’s Matrix Memory Boosts Storage Capacity  

Modern language models are often based on *Transformers*, whose quadratic‑time attention mechanism blindsides slower recurrent models like the classic LSTM.  Yet LSTMs have long offered elegant solutions for vanishing gradients and temporal abstraction – only they work with **scalar** cell states \(c\in\mathbb{R}\).  Scaling an LSTM to billions of parameters does not automatically increase what a single cell can remember – each scalar just holds one number per hidden direction.  

The **mLSTM** variant in *xLSTM* circumvents this limitation by turning every cell into a **matrix** memory:
\[
\mathbf{C}_t \in \mathbb{R}^{d\times d}\ .
\]
This simple change gives the model an entirely new capability: storing multi‑dimensional associations without enlarging its parameter set.



--------------------------------------------------------------------
## Why single scalars can’t keep large memories  

In an ordinary LSTM each time step performs  
\[
c_{t}=f_{t}\!c_{t-1}+i_{t}z_{t},\qquad h_{t}=o_{t}\psi(c_{t}) .
\]
Knowledge about the past is compressed into one real number per hidden unit – it must encode *both* “what” happened *and* “how relevant it is”.  When you need to remember dozens or hundreds of different facts you quickly run into saturation or catastrophic forgetting.



--------------------------------------------------------------------
## Introducing **m**atrix **M**emory**lstm**  

### A rank‑one update that remembers associations  

mLSTM keeps a full \(d\times d\) matrix instead of a vector:

```latex
\mathbf{C}_{\,t}
    &= f_{\,t}\,\mathbf{C}_{\,{t-1}}
     + i_{\,t}\,\mathbf{v}_{\,t}\,\mathbf{k}_{\,t}^{\!\top}.
```

Each step adds a *rank‑one* outer product \( \mathbf v\,\mathbf k^{\!\top}\) scaled by an **input gate** \(i_{\,t}\ge 0\).  
The pair \((\mathbf k,\mathbf v)\) plays exactly the role of a *key–value* pair used in modern attentions:

| Symbol | Meaning |
|--------|---------|
| \(\mathbf k_t\) | projected key vector |
| \(\mathbf v_t\) | projected value vector |
| \(q_t=\mathbf W_qx_t+\mathbf b_q\) | current query |

A **forget gate** \(f_{\,t}\in[0,1]\) (or an exponential form) scales the whole memory when new information comes in, exactly like the classic decay rate.



### Stabilizing exponential gates  

mLSTM uses exponential activations for \(i\) and optionally for \(f\):  
\(i'_t=\exp(\tilde{i}_te^{-m_{\,t}})\), \(f'_te^{m_{\,{t-1}}-m_{\,{t}}}\).  
A companion *stabilizer state* \(m_{\,t}=\max(\log f _{\,{t}}+m_{\,{ t-1}},\,\log i _{\, { t}})\)
keeps those exponentials from blowing up while leaving gradients untouched.



### Normalization – keeping retrieval safe  

Two auxiliary states accompany the main matrix:

```latex
{\bf n}_{\, t}
    &= f_{\! t}{\bf n}_{\, t-1}
     + i_{\! t}{\bf k}_{\, t},
```

which accumulates all past keys weighted by their input gates and decay factors.
The hidden output is then computed as

```latex
{\bf h}_{\, t}
    &= {\bf o}_{\, t}\odot
       \frac{{\bf C}_{\, t}{q}_{\, t}}
            {\max(|{\bf n}_{\, t}^{\!\top}{q}_{\, t}|,\;1)} .
```

Dividing by \(\max(|{\bf n}^{T}q|,1)\) improves numerical stability and mirrors **length‑normalization** used in Transformers.



--------------------------------------------------------------------
## What does the matrix actually store?  

An ordinary LSTM cell offers only one scalar per hidden dimension → one *linear combination* can be memorised at any time point.  
With an \(d\times d\) matrix every rank‑one addition preserves at least one direction‑to‑direction interaction between all dimensions:

* Adding \(v_k w_k^{T}\) highlights how each entry of \(v_k\) should respond when queried with equals entries of \(k_k.\)
* The overall content becomes akin to recording multiple inner products simultaneously.
* Because all updates are additive, previously memorised patterns persist until actively forgotten or overwritten – just like balancing white/black keys on a piano.


The method arises from Fast‑Weight Programmers~(Hochreiter ’92) and matches an **optimal covariance update rule** proven optimal for maximal linear separability of retrieved binary vectors (Dayan ’91). In practical terms this means **you can reliably retrieve many distinct key/value pairs even after long sequences—a core head‐cointing problem in language modelling called “associative recall”.**



--------------------------------------------------------------------
## Associative Recall benchmark – what do experiments show?  

In the Mult­Query Associative Recall task (~≤ 256 pairs per sequence), only models equipped with rich storage could survive:
 • Classic LSTMs rarely recalled more than 10–50 pairs at once.
 • Transformers preserve information via their large token embedding space (exponential scaling w.r.t coding dimension).
 • The newly added **mLSTM block** matched or surpassed Transformer baselines while staying fully recurrent and linear‑time.


When mixed into standard residual backbones (xLSTM), **xLSTM[0 ∶ 255]** achieved perfect accuracy on short ranges and maintained > 95 % recall even when context length was doubled beyond training data—exactly what one needs for massive language modeling where rare tokens or skillful knowledge must survive hundreds of steps.



--------------------------------------------------------------------
## Computation versus storage policy  

The price paid for this bigger memory is an additional matrix multiplication per time step (~\(O(d^{2})\)).  
Because all operations involve dense matrices it parallelises extremely well—just standard GEMM kernels on GPUs do not inflate wall‑clock time noticeably. In contrast,
the classic *symmetric* style sLSTM still needs sequential hidden‑to‑hidden mixing (no parallelism), so if you care about speed pick mLSTMs.



--------------------------------------------------------------------
## Takeaways – why does matrix memory matter?  

| Feature | Scalar LSTM | Matrix m>Lstm |
|---------|--------------|---------------|
| Stored facts | One scalar per direction | Any number via rank‑one updates |
| Signals | Additive + sigmoid gating | Exponential gating + decay |
| Retrieval | Dot product after hard squashing | Matrix–vector multiplication |
| Parallelisation | Limited by hidden mixing | Cleanly GPU‑parallel |
| Capacity test | Low associative recall < 50 pairs | > 200 pairs secure |
| Parameter cost | Same parameters ➜ bigger matrices → no extra learnable weights | No additional learnable weights |

In short, turning each cell into a *matrix* unlocks a whole spectrum of associations without enlarging model size – exactly what modern LLM workloads demand.



--------------------------------------------------------------------
## Bottom line  

*mLSTMs*

* shift from “cache” ⇒ “covariance” updates that are mathematically optimal for retrieval,
* let you squeeze many independent key/value embeddings into one recurrent unit,
* keep training simple (no new learnable parameters),
* reproduce Transformer levels on associative recall tasks while staying linear in sequence length,
* lay groundwork for large‑scale language models that can handle longer contexts without costing quadratic attention costs.



Whether you’re optimizing reinforcement agents that must track entities or building next‑generation text modellers that need surviving rare knowledge over very long narratives, **matrix memories bring scalability back into recurrent nets**—and give them an affinity close enough to Transformers that they’re now competitive in performance benchmarks while staying vastly simpler computationally.

According to the paper 'DeepSeekMath: Pushing the Limits of Mathematical Reasoning in Open Language Models', based on the authors' initialization choice, the expected outcome if DeepSeekMath had been initialized from a general LLM instead of a code-trained model is lower math performance. The authors explicitly state that “starting from a code training model is a better choice compared to a general LLM,” and their ablations substantiate this: in two-stage training, initializing with code pre-training for \(400\mathrm{B}\) tokens followed by math training for \(150\mathrm{B}\) yields stronger results than starting from a generally trained model and then doing the same math phase. Moreover, DeepSeekMath-Base, which is initialized from DeepSeek-Coder-Base-v1.5 7B, consistently outperforms open-source baselines (including larger general LLMs) across GSM8K, MATH, and Chinese math benchmarks, and even surpasses Minerva 540B on some tasks—evidence that the code-trained initialization confers a systematic advantage in mathematical reasoning.

This advantage is explained by the paper’s detailed findings that code training enhances both tool-free and tool-integrated mathematical reasoning. For program-aided reasoning, code pre-training directly improves the model’s ability to write and reason with Python, amplifying gains in PoT settings on GSM8K and MATH; for pure chain-of-thought, code pre-training appears to instill structured, stepwise computation patterns that make subsequent math training more sample-efficient and effective. In contrast, replacing the initial code phase with general-language pre-training reduces these benefits, yielding weaker performance after the math phase. Even in one-stage mixing, the presence of code tokens helps mitigate catastrophic forgetting and synergizes with program-aided math, while the 1.3B ablation shows capacity limits when trying to learn both simultaneously—underscoring that the code prior is particularly helpful at scale. Taken together, the initialization from a code-trained model aligns the pretraining distribution and inductive biases with the demands of mathematical problem solving, so switching to a general LLM initialization would predictably depress final math performance.

According to the paper 'DeepSeekMath: Pushing the Limits of Mathematical Reasoning in Open Language Models', if GRPO were modified to reintroduce a learned critic, the primary tradeoff to expect is higher compute cost. The paper’s core rationale for GRPO is that it “foregoes the critic model, instead estimating the baseline from group scores, significantly reducing training resources compared to Proximal Policy Optimization (PPO).” In PPO, the advantage at each token is computed via Generalized Advantage Estimation using a learned value function \(V_{\psi}\), which requires training an additional model of comparable size to the policy; the surrogate objective depends on per-token advantages \(A_t\) derived from \(V_{\psi}\) and reward signals. By contrast, GRPO replaces the learned baseline with a simple, in-group normalization of rewards, i.e., \(\hat{A}_{i,t}=\widetilde{r}_i=\frac{r_i-\mathrm{mean}(\mathbf{r})}{\mathrm{std}(\mathbf{r})}\) for outcome supervision, and aggregates step-level normalized rewards for process supervision. This design removes the need for forward/backward passes through a critic, its optimizer state, and its memory footprint, yielding a clear reduction in compute and memory.

Reintroducing a critic into GRPO would restore the PPO-style actor–critic machinery, with the same computational burdens the paper explicitly seeks to avoid. Concretely, one would again need to learn \(V_{\psi}\) to estimate baselines at the token level, compute GAE over sequences with sparse reward signals (often only at the last token in LLM settings), and maintain a full training loop for the critic alongside the policy. That entails extra parameter updates, optimizer state, and gradient computations, as well as additional storage for value targets and rollouts—thus increasing wall-clock time and memory consumption. The paper also notes that learning a value function is “complicated” in the LLM context because rewards are typically assigned only at the end of the sequence, making accurate per-token value estimation harder. GRPO’s group-relative advantages are explicitly designed to sidestep this complexity; undoing that choice would primarily incur higher compute cost, with any potential stability benefits coming at the expense of the efficiency gains that motivate GRPO.

GRPO’s core idea is to compute advantages from rewards normalized within a group of $G$ outputs sampled for the same question, using the group mean as a baseline and the group standard deviation for scale: $\widetilde{r}_i=\frac{r_i-\mathrm{mean}(\mathbf{r})}{\mathrm{std}(\mathbf{r})}$. This loss of relative comparison affects both outcome and process supervision in GRPO. For process supervision, the stepwise advantages sum normalized step rewards, $\hat{A}_{i,t}=\sum_{index(j)\ge t}\widetilde{r}_i^{index(j)}$, again requiring a nonzero $\mathrm{std}(\mathbf{R})$ across the set of step scores aggregated over the group. With $G=1$, normalization degenerates, eliminating the fine-grained, step-aware comparative signal. More broadly, GRPO’s stated benefits—obviating a critic by using group baselines, aligning with comparative reward modeling, and producing differential reinforcement magnitudes via intra-group ranking—rely on $G>1$. Setting $G=1$ removes the comparative structure central to GRPO, leaving only an absolute reward term plus the KL regularizer, thereby forfeiting the paper’s key advantage of relative comparison.

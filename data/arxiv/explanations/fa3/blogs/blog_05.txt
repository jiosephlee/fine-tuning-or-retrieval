# Accuracy at Low Precision: Block Quantization and Incoherent Processing Explained

Modern GPUs (Hopper/H100 and similar) expose very high FP8 throughput on their Tensor Cores, which makes FP8 an attractive target for speeding up attention-heavy models. But FP8 (e4m3) has only 3 mantissa bits and 4 exponent bits, so naive quantization can produce large numerical errors—especially when the activations contain rare, very large values (outliers). FlashAttention-3 tackles this problem with two practical, low-overhead techniques: block quantization and incoherent processing. Together they reduce FP8 attention error by about 2.6× compared to a standard FP8 baseline that uses per-tensor scaling.

This post walks through why outliers break per-tensor FP8, the intuition behind the two techniques, how they fit naturally into an attention kernel, and practical considerations for fusing them into your model pipeline.

## Why FP8 struggles: the outlier problem

FP8 offers much higher raw GEMM throughput than FP16/BF16, but it has a very limited dynamic range and precision. A common strategy is per-tensor quantization: pick one scale factor \(s\) for an entire tensor \(X\), and quantize via
\[
\hat{X} = \text{round}\!\left(\frac{X}{s}\right)
\]
so the quantized values fit the FP8 format. Per-tensor scaling is simple and cheap, but it fails when a tiny fraction of elements are much larger than the bulk of the tensor (outliers). Those few large elements force the scale \(s\) to be large, which causes the majority of values to be represented with severely reduced precision or to underflow, increasing relative error for normal-magnitude elements and degrading downstream computations like attention softmax.

The attention computation is particularly vulnerable because attention scores depend on inner products of query and key vectors; a few poorly represented components can skew those inner products, hurting the softmax and the final output.

## Block quantization: local scales for local dynamic range

Block quantization mitigates the outlier issue by using a separate scale for each small block of the tensor rather than one scale per entire tensor. In FlashAttention-3, tensors are naturally processed as blocks by the attention tiling scheme, so block quantization fits the algorithmic structure without extra global passes.

Concretely, split a matrix (say \(\mathbf{Q}\), \(\mathbf{K}\), or \(\mathbf{V}\)) into blocks matching the attention kernels’ tile sizes (e.g., query blocks \(B_r \times d\) or key/value blocks \(B_c \times d\)). For each block \(B\) compute a local scale \(s_B\) (for example, based on the block maximum absolute value) and quantize that block independently:
\[
\hat{B} = \text{quantize}_{\text{FP8}}\!\left(\frac{B}{s_B}\right).
\]
Because each block usually contains values of similar magnitude, the local scale can be much smaller than the global scale, allowing FP8 to preserve more significant bits for the majority of entries and reducing quantization error.

Why this is cost-effective in attention:
- The attention algorithm already operates block-wise (FlashAttention-style), so scaling and de-scaling can be performed in the same kernel or fused with a preceding memory-bound operation.
- The per-block scales are small metadata (a scalar per block) and are used immediately when computing scaled inner products or when rescaling accumulation, so they do not add significant memory bandwidth or compute overhead.

Practical tip from FlashAttention-3: block quantization can be fused with a preceding operation that is memory-bandwidth bound—rotation embeddings (rotary) are an example. Because both the rotary transform and block-scaling touch the same data and are bandwidth-limited, doing both in one pass adds negligible overhead.

## Incoherent processing: spread the outliers with orthogonal mixing

Block quantization helps, but it can still be hurt by blocks that themselves contain outliers. Incoherent processing aims to reduce per-block outlier impact by mixing the coordinates of the query and key vectors before quantization in a way that preserves inner products.

The idea is simple and mathematically exact: multiply both \(\mathbf{Q}\) and \(\mathbf{K}\) (on the right) by the same orthogonal matrix \(\mathbf{M}\). Because \(\mathbf{M}\) is orthogonal,
\[
(\mathbf{Q}\mathbf{M})(\mathbf{K}\mathbf{M})^\top = \mathbf{Q}\mathbf{K}^\top,
\]
so the attention logits are unchanged in exact arithmetic. But the entries of \(\mathbf{Q}\mathbf{M}\) and \(\mathbf{K}\mathbf{M}\) are linear combinations of the original coordinates; a single large coordinate in the input gets spread across many coordinates after mixing. That diffusion of magnitude reduces the dynamic range and the likelihood that any one coordinate dominates the block, improving block quantization fidelity.

How to do this cheaply: FlashAttention-3 follows prior works and picks \(\mathbf{M}\) to be a structured orthogonal transform that is cheap to apply, for example a product of:
- diagonal matrices with entries \(\pm 1\) (sign flips), and
- a Hadamard matrix.

A Hadamard-based transform can be implemented in \(O(d \log d)\) time per vector (using the fast Walsh-Hadamard transform) instead of \(O(d^2)\). This makes incoherent processing cheap compared to the \(O(d^2)\) cost of dense linear algebra in attention.

In practice, FlashAttention-3 uses the Hadamard-based mixing and notes that this operation can be fused with other per-token transforms, such as rotary embeddings, so the extra compute is nearly free in a real pipeline.

## Putting them together in the attention kernel

Block quantization and incoherent processing are complementary: mixing reduces the occurrence of extreme per-block outliers, and block quantization then uses local scales to represent the now-more-uniform blocks accurately in FP8.

Where these steps can be performed in a typical attention pipeline:

- Pre-attention fusion point: apply the orthogonal mixing and block quantization immediately after any local, token-wise transforms that already touch the tensor (rotary embedding is explicitly mentioned in FlashAttention-3). Because rotary and the mixing-based Hadamard transform are both linear and memory-bandwidth bound, they can be fused into a single pass that writes out FP8 blocks plus block scales. This amortizes the cost.
- In-kernel transpose/format steps (FP8-specific): FlashAttention-3 performs in-kernel tile transposes (using warp-level matrix load/store primitives) to match FP8 WGMMA layout requirements, and the per-block FP8 data are already in the right block-aligned layout for the GEMMs.
- Dequantization/scaling: when a block is read into shared memory or registers for accumulation, the stored per-block scale is applied to reconstruct the FP8 block to the accumulator’s representation (or to appropriately scale GEMM inputs/outputs), all as part of the fused attention kernel.

Key implementation notes from the paper:
- Block quantization requires maintaining one scalar scale per block; the attention tiling means that scale is available exactly where needed.
- Incoherent processing uses structured orthogonal matrices (Hadamard × random sign flips) so that per-vector cost is \(O(d \log d)\) and can be fused with other pre-attention operations.
- Both techniques were validated to reduce FP8 numerical error: FlashAttention-3 with block quantization and incoherent processing achieves about 2.6× lower RMSE (relative to an FP64 reference) than a baseline FP8 attention implementation that uses per-tensor scaling.

## Intuition with a small example

Imagine a query vector with dimension \(d=8\) where seven coordinates are around 1.0 but one coordinate is 100. With per-tensor scaling, the scale must accommodate the 100, so typical coordinates lose most of their mantissa resolution when mapped into FP8. After multiplying by a Hadamard-style orthogonal matrix, that single large value gets spread across the 8 coordinates, so each mixed coordinate might be around \(100/8 \approx 12.5\) plus contributions from the other coordinates. Now each block has a much smaller dynamic range across its entries and block quantization can pick a scale that preserves more relative detail for the majority of components. Quantization error for most coordinates drops substantially as a result.

## Trade-offs and practical considerations

- Slight extra compute: the Hadamard mixing adds \(O(d \log d)\) work per vector, but this can be fused with existing per-token transforms and is small relative to the GEMM work in attention.
- Extra metadata: block quantization stores one scale per block; this is negligible storage compared to the tensor data and is read/written as part of the fused kernel.
- Layout handling: on Hopper, FP8 WGMMA requires specific k-major layout constraints. FlashAttention-3 performs in-kernel transposes and register permutations to conform to these requirements; those steps are efficient when implemented with warp-level load/store primitives and integrated into the kernel.
- Pipeline fit: both techniques are designed to be fusion-friendly. The paper highlights that the block quantization and Hadamard mixing can be fused with a preceding memory-bound op (rotary), and that in-kernel transposes happen in the producer warpgroup so they can overlap with GEMMs.

## Bottom line

FP8 can deliver very large speedups on modern GPUs, but naive per-tensor quantization can fail in the presence of outliers. FlashAttention-3 reduces FP8 attention error by combining block quantization (per-block scales) with incoherent processing (Hadamard-style orthogonal mixing). These techniques are low-overhead, fuse naturally into attention kernels, and—empirically—reduce FP8 RMSE by around 2.6× compared to a standard per-tensor FP8 baseline while enabling the use of FP8 Tensor Cores for much higher TFLOPs/s.

If you are implementing low-precision attention, consider:
- Quantizing by block to match your kernel’s tiling,
- Using a structured orthogonal mixer (Hadamard × sign flips) before quantization to diffuse outliers,
- Fusing mixing and block scaling with preceding per-token ops to avoid extra bandwidth costs.

These steps give you a practical path to get closer to FP8 performance without sacrificing too much numerical fidelity.

\title{Stack Exchange of the Paper: "The Era of 1-bit LLMs: All Large Language Models are in 1.58 Bits"}

### Why does adding 0 to the weight set enable "feature filtering"?
Question:
The paper states that including 0 in the model weights (going from the original BitNet's \{-1, 1\} to \{-1, 0, 1\}) provides "explicit support for feature filtering, which can significantly improve the performance of 1-bit LLMs." I understand that a weight of 0 means a particular feature has no contribution to the output. But isn't a near-zero weight in a continuous-valued model effectively doing the same thing? Why is having an explicit 0 value qualitatively different from having a small floating-point weight? Is the claim that the ternary representation creates a form of structured sparsity that helps the model learn to ignore irrelevant features more effectively? Could someone elaborate on the mechanism by which this "feature filtering" improves performance?
Answer:
# Answer

The key to understanding this lies in the quantization function itself and what information is preserved versus destroyed when moving from continuous to discrete weights.

In the original BitNet with weights constrained to $\{-1, 1\}$, every single weight is forced to contribute either positively or negatively to the output. There is no "off" state. When the underlying continuous weight $W_{ij}$ is near zero—meaning the model has learned that this particular connection is unimportant—the binary quantization function has no choice but to round it to either $+1$ or $-1$. This injects noise: a feature the model wants to ignore gets a full-magnitude positive or negative contribution. Every weight participates in every computation, whether the model wants it to or not.

In contrast, the ternary quantization in BitNet b1.58 uses:

$$\widetilde{W} = \mathrm{RoundClip}\left(\frac{W}{\gamma + \epsilon}, -1, 1\right)$$

where $\gamma = \frac{1}{nm}\sum_{ij} |W_{ij}|$ is the average absolute magnitude. After scaling by $\gamma$, any weight whose normalized value falls in the range $(-0.5, 0.5)$ rounds to exactly $0$. This creates a "dead zone" around zero where features are filtered out entirely—they contribute nothing to the output and, importantly, can be skipped during computation.

The qualitative difference from a small FP16 weight is twofold. First, in a continuous model, a weight of $0.001$ still participates in every matrix multiplication with its full floating-point overhead; the feature is attenuated but not absent. The ternary $0$ is a hard, discrete "off" switch that creates genuine structured sparsity. Second, and more critically for 1-bit models specifically: in the binary $\{-1, 1\}$ regime, the model *cannot express* "this feature is irrelevant" at all—the quantization destroys that information by forcing every weight to $\pm 1$. Adding $0$ back recovers this essential capability that was lost when moving from continuous to binary weights. It gives the ternary model a way to represent the full spectrum of "positive," "negative," and "irrelevant," whereas the binary model could only represent the first two.

The performance improvement comes from this regularization effect. The rounding-to-zero mechanism acts as a form of learned sparsity: connections that are weak relative to the average magnitude get pruned during training, reducing noise from unimportant features. The model can then allocate its limited representational capacity (just three values per weight) toward the connections that matter most. This is particularly valuable for 1-bit LLMs, where the extreme compression makes every weight's contribution disproportionately impactful—a single spurious $\pm 1$ weight contributes as much signal as a genuinely important one, so the ability to silence irrelevant connections is far more critical than in FP16 models where weak weights naturally have small magnitudes.

\title{Stack Exchange of the Paper: "Controlling Text-to-Image Diffusion by Orthogonal Finetuning"}

### What does the paper mean by "no additional inference overhead" and how does merging R into W^0 work?
Question:
The paper claims OFT introduces no additional inference overhead because "we can simply multiply the learned orthogonal matrix $\bm{R}$ into the pretrained weight matrix $\bm{W}^0$ and obtain an equivalent weight matrix $\bm{W} = \bm{R}\bm{W}^0$." This makes sense in principle, but I'm confused about how this works with the block-diagonal structure. If $\bm{R}$ is block-diagonal with $r$ blocks, does merging still produce a regular weight matrix $\bm{W}$? Also, ControlNet introduces additional network branches, which is why it has overhead. LoRA also can be merged — so does LoRA also have no inference overhead? How does OFT's "no overhead" claim differ from LoRA's?
Answer:
The key insight is that the block-diagonal structure of $\bm{R}$ is a **parameterization strategy**, not a constraint on the matrix multiplication itself. Whether $\bm{R}$ is a full orthogonal matrix or a block-diagonal one composed of $r$ smaller orthogonal blocks $\bm{R}_1, \ldots, \bm{R}_r$, it is still a $d \times d$ matrix. The product $\bm{W} = \bm{R}\bm{W}^0$ where $\bm{W}^0 \in \mathbb{R}^{d \times n}$ produces a dense $d \times n$ matrix — exactly the same shape as the pretrained weight matrix. The block-diagonal structure simply means that $\bm{R}$ mixes together groups of rows of $\bm{W}^0$ within each block, but rows belonging to different blocks do not interact. Once you compute $\bm{W} = \bm{R}\bm{W}^0$, the result is an ordinary dense weight matrix with no special structure, and inference proceeds exactly as it would with the original pretrained weights: $\bm{z} = \bm{W}^\top \bm{x}$. The block-diagonal structure lives only in the trainable parameterization; after merging, it disappears entirely.

You are also correct that LoRA can similarly be merged — after training, the low-rank update $\bm{A}\bm{B}$ is added to $\bm{W}^0$ to form $\bm{W} = \bm{W}^0 + \bm{A}\bm{B}$, yielding a single dense matrix with no inference overhead. In this respect, OFT and LoRA are alike: both modify the pretrained weights in a structured, parameter-efficient way during training, and both can be collapsed into the base weights for deployment.

The paper's "no additional inference overhead" claim is primarily contrasted with **ControlNet**, not LoRA. ControlNet introduces an entirely separate trainable network branch — a copy of the encoder that processes the control signal — connected to the pretrained model via zero-convolution layers. At inference time, this auxiliary branch must remain active and cannot be folded into the original weights, because it implements a fundamentally different computation path (processing an additional input signal) rather than a reparameterization of existing weights. The paper explicitly states this distinction: "Unlike ControlNet, our OFT framework introduces no additional inference overhead to the finetuned model." So the claim is really about architectural overhead from extra inference-time computation paths, which ControlNet has and OFT (like LoRA) does not.

The paper also draws an explicit connection between OFT and LoRA by rewriting the OFT forward pass as $\bm{z} = (\bm{W}^0 + (\bm{R} - \bm{I})\bm{W}^0)^\top \bm{x}$, noting that $(\bm{R} - \bm{I})\bm{W}^0$ is "analogous to LoRA's low-rank weight update." The conceptual difference is that LoRA constrains the *additive* update to be low-rank, while OFT constrains the *multiplicative* transformation to be orthogonal (and uses block-diagonal sparsity for parameter efficiency). Both approaches are mergeable, but they enforce different structural priors on how the pretrained weights are allowed to change — LoRA limits rank, while OFT preserves pairwise neuron angles (hyperspherical energy).

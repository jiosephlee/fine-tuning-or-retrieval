\title{Stack Exchange of the Paper: "LongRoPE: Extending LLM Context Window Beyond 2 Million Tokens"}

### Why does the search space size formula give $400^{128/2} \times 14$ for a 4$\times$ extension?
Question:
The LongRoPE paper states that for a $s = 4\times$ extension, the search space has $400^{128/2} \times 14 = 4 \times 10^{167}$ choices. I understand that 128/2 = 64 is the number of RoPE dimensions (for $d=128$), and 14 is the number of choices for $\hat{n}$. But where does the 400 come from? The paper says $\lambda_i$ ranges from 1.0 to $s \times 1.25 = 5.0$ with a step size of 0.01, which gives $(5.0 - 1.0)/0.01 + 1 = 401$ values, not 400. Is this an approximation, or am I misunderstanding the search space bounds?
Answer:
# Where Does $400$ Come From?

The value $400$ comes from the number of possible values each rescale factor $\lambda_i$ can take in the search space. Let me walk through the calculation.

For a $4\times$ extension ($s = 4$), the paper specifies that each $\lambda_i$ ranges from a minimum of $1.0$ to a maximum of $s \times 1.25 = 5.0$, with a step size of $0.01$. The total number of values depends on whether you count both endpoints inclusively or not:

- **Inclusive of both endpoints**: $\frac{5.0 - 1.0}{0.01} + 1 = 401$ values
- **Exclusive of one endpoint** (e.g., $[1.0, 5.0)$ or $(1.0, 5.0]$): $\frac{5.0 - 1.0}{0.01} = 400$ values

You're correct that counting both endpoints gives $401$, not $400$. The paper uses $400$, which appears to be either a minor approximation or follows a half-open interval convention (common in programming where one boundary is excluded). The distinction is negligible for the paper's purpose, which is simply to convey that the search space is astronomically large.

The full search space size is then computed as:

$$400^{128/2} \times 14$$

where $128/2 = 64$ is the number of RoPE dimensions (for $d = 128$), each independently taking one of $400$ possible values, and $14$ is the number of candidate values for $\hat{n}$ (the token position threshold, drawn from the set $\{0, 1, 2, 4, 8, 12, 16, 20, 24, 28, 32, 64, 128, 256\}$). This gives $400^{64} \times 14 \approx 4 \times 10^{167}$, which matches the paper's stated result. If we used $401$ instead, the result would be $401^{64} \times 14 \approx 5.2 \times 10^{167}$, which is essentially the same order of magnitude.

The key takeaway is that even a modest $4\times$ extension yields an effectively intractable search space, which is precisely why the paper introduces the evolutionary search algorithm with optimizations like the monotonically non-decreasing constraint and informed initial population seeding (using PI, NTK, and YaRN as starting points) to make the search tractable.

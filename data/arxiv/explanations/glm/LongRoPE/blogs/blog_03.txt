\title{Blogs about the Paper: "LongRoPE: Extending LLM Context Window Beyond 2 Million Tokens"}

# How to Train for 2 Million Tokens Without Actually Using 2 Million Tokens

Large language models are powerful, but they come with a frustrating limitation: their context window size. LLaMA2, for instance, was pre-trained with a 4096-token limit. Once you feed it more tokens than that, performance degrades because the model encounters position indices it has never seen during training. This is a serious bottleneck for applications like in-context learning with many examples or complex LLM agents that need to process long documents.

Recent work has pushed context windows to around 128k tokens through fine-tuning on longer texts. But going beyond that—say, to 2 million tokens—runs into three serious obstacles. First, when extending from 4k to over 1000k, more than 90% of position indices are new and untrained, introducing catastrophic values that make fine-tuning difficult to converge. Second, there simply aren't enough texts longer than a million tokens to fine-tune on, and training on such lengths would be prohibitively expensive in GPU hours. Third, when you spread attention across an enormous number of token positions, it gets dispersed and diluted, degrading performance even on the original short context window.

A recent paper from Microsoft called **LongRoPE** tackles all three of these challenges and achieves something remarkable: extending pre-trained LLM context windows to 2,048,000 tokens. The secret sauce is a clever combination of non-uniform positional interpolation and a progressive extension strategy that avoids the need for million-token training texts entirely.

## The Background: RoPE and Positional Interpolation

To understand how LongRoPE works, we need to talk about Rotary Position Embedding (RoPE), the position encoding used in modern LLMs like LLaMA2 and Mistral. For a token at position $n$, its RoPE encoding involves a series of rotation angles:

$$[cos(n\theta_0), sin(n\theta_0), cos(n\theta_1), \cdot\cdot\cdot, cos(n\theta_{d/2-1}), sin(n\theta_{d/2-1})]$$

where $d$ is the embedding dimension and $\theta_i = \theta^{-2i/d}$ with a default base value of $\theta = 10000$.

When we want to extend the context window from length $L$ to $L'$, the extension ratio is $s = L'/L$. Positional interpolation methods work by downscaling the rotation frequencies so that new position indices map back into the range the model was originally trained on.

The simplest approach, **Position Interpolation (PI)**, just linearly divides all position indices by $s$. This works, but it makes position information very "crowded"—the model struggles to distinguish between closely positioned tokens, and performance suffers at high extension ratios.

Other methods like **NTK** and **YaRN** introduce some non-linearity by treating different RoPE dimensions differently. NTK scales lower (high-frequency) dimensions less and higher (low-frequency) dimensions more. YaRN divides RoPE dimensions into three frequency-based groups and applies different interpolation strategies to each. These methods help, but they still rely on human-designed rules that don't fully capture the complexity of how positional information behaves in transformers.

## Two Key Non-Uniformities

LongRoPE starts with a key insight: there are two forms of non-uniformity in positional interpolation that existing methods fail to fully exploit.

**Non-uniformity across RoPE dimensions.** Different dimensions of the RoPE embedding should be interpolated by different amounts, and the optimal factors depend on the target extension length. Through evolutionary search guided by perplexity, LongRoPE discovers that the optimal rescale factors for each dimension are non-uniform and differ significantly from the fixed rules used by PI, NTK, or YaRN.

**Non-uniformity across token positions.** The initial tokens in an input sequence receive large attention scores and are crucial to the attention layers. LongRoPE finds that these initial tokens should be extrapolated with less interpolation—in fact, the first $\hat{n}$ tokens should use the original RoPE embedding without any interpolation at all. The optimal value of $\hat{n}$ depends on the target extension length.

These two non-uniformities are captured through a set of rescale factors $\mathbb{I}(\hat{\lambda}_i, \hat{n})$, where $\hat{\lambda}_i$ is the rescale factor for the $i^{th}$ RoPE dimension and $\hat{n}$ is a token position threshold:

$$\mathbb{I}(\hat{\lambda}_i, \hat{n}) = \begin{cases} 1 & \text{if } n < \hat{n} \\ \frac{1}{\lambda_i} & \text{if } n \geq \hat{n} \end{cases}$$

Finding the optimal set of rescale factors is a massive search problem. For a 4× extension, the search space contains roughly $4 \times 10^{167}$ possible configurations. LongRoPE uses an evolutionary search algorithm with two key optimizations to make this tractable:

- It seeds the initial population with known good solutions (PI, NTK, and YaRN configurations) rather than starting randomly.
- It enforces a monotonically non-decreasing constraint: $\lambda_i \leq \lambda_{i+1}$, based on the NTK theory that lower dimensions with higher frequencies need less interpolation. This dramatically reduces the number of candidates that need expensive perplexity evaluations.

The result of this search is powerful enough to achieve an 8× context extension **without any fine-tuning at all**—extending LLaMA2 from 4k to 32k while existing methods like PI, NTK, and YaRN see perplexity spike after just 2×.

## The Progressive Extension Strategy

Here's where things get really clever. An 8× no-fine-tuning extension is impressive, but 2048k requires a 512× extension from the original 4k. That's way beyond what the search alone can handle. Fine-tuning is necessary, but fine-tuning directly on 2048k-token texts is practically impossible—such texts barely exist, and the compute cost would be staggering.

LongRoPE solves this with a progressive, stepping-stone strategy:

**Step 1: Extend the pre-trained LLM to 256k with LongRoPE search.** Starting from LLaMA2's 4k context window, the search algorithm finds optimal rescale factors for target lengths of 128k and 256k (extension ratios of 32× and 64×, respectively).

**Step 2: Fine-tune to 256k.** Rather than jumping straight to 256k, the fine-tuning is itself progressive. First, the model is fine-tuned for 400 steps using the 128k rescale factors. Then, the rescale factors are swapped for the 256k configuration, and training continues for another 600 steps on the same checkpoint. This two-stage approach turns out to be more efficient than fine-tuning directly to 256k. Importantly, all of this training uses texts chunked to 128k or 256k lengths—nothing approaching 2 million tokens.

**Step 3: Extend the fine-tuned 256k model to 2048k with a second LongRoPE search.** This is the key leap. Because LongRoPE's non-uniform positional interpolation can achieve an 8× extension without fine-tuning, the already fine-tuned 256k model can be pushed to 2048k (an 8× jump from 256k) with just another search—no additional fine-tuning required.

The genius here is that the 512× total extension is decomposed into a 64× extension achieved through fine-tuning (at a manageable 256k length) and an 8× extension achieved through the search alone. The model never needs to see a 2-million-token document during training.

## Recovering Short Context Performance

There's one more problem to solve. When you extend the context window by 512×, the positional interpolation squeezes the original 4k positions into a much narrower region. This crowding degrades performance on short inputs—the model gets worse at the very thing it was originally good at.

LongRoPE addresses this by performing an additional evolutionary search to find a separate set of rescale factors specifically optimized for short context lengths (4k and 8k). The maximum allowed rescale factor is reduced to encourage less interpolation at these shorter lengths. During inference, the model dynamically switches between the short-context and long-context rescale factors depending on the input sequence length.

## Does It Actually Work?

The experimental results are compelling across multiple dimensions:

- **Perplexity on long documents:** LongRoPE-2048k models show a consistent decreasing perplexity trend from 4k to 256k on PG19 and Proof-pile datasets, outperforming state-of-the-art baselines even within 256k. On the Books3 dataset with documents exceeding 2048k, LLaMA2 maintains reasonable perplexity across the full 2-million-token range.

- **Passkey retrieval:** LongRoPE-LLaMA2-2048k maintains over 90% accuracy in retrieving a hidden five-digit passkey from anywhere within the 4k to 2048k context window. Existing models drop to 0% accuracy beyond 128k.

- **Standard benchmarks:** On the Hugging Face Open LLM Leaderboard (ARC-Challenge, HellaSwag, MMLU, TruthfulQA), LongRoPE-2048k models achieve results comparable to the original models within their 4096-token context window, with LongRoPE-Mistral even outperforming the original Mistral on TruthfulQA by 0.5%.

## Why This Matters

LongRoPE's progressive extension strategy is a practical demonstration that you don't need to train on million-token texts to handle million-token contexts. By decomposing the problem into a fine-tuneable intermediate step and a search-based final leap, the method sidesteps the fundamental scarcity of ultra-long training data and the prohibitive cost of training on it.

The approach is also notably lightweight. Models extended via LongRoPE retain their original architecture with only minor modifications to the positional embedding, meaning most pre-existing optimizations and tooling can be reused. The method works on any RoPE-based LLM, and the code is available at [https://github.com/microsoft/LongRoPE](https://github.com/microsoft/LongRoPE).

As LLMs continue to be applied to increasingly complex tasks—analyzing entire codebases, processing long legal documents, conducting deep research across many sources—the ability to work with context windows in the millions rather than thousands will become essential. LongRoPE shows a path to get there without waiting for impossibly long training datasets to materialize.

\title{Blogs about the Paper: "FlashAttention-3: Fast and Accurate Attention with Asynchrony and Low-precision"}

# Breaking the Speed Limit: How FlashAttention-3 Unlocks the Future of Long-Context AI

The Transformer architecture has driven some of the most impressive advances in artificial intelligence, but it comes with a fundamental scaling problem. At the heart of the Transformer is the attention mechanism, which allows the model to weigh the importance of different input tokens. However, computing these attention scores requires operations that scale quadratically with the sequence length. As we push models to process longer contexts—whether to reason over massive codebases, analyze high-resolution images, or maintain long conversation histories—attention becomes a severe computational bottleneck.

Previous work, such as FlashAttention and FlashAttention-2, tackled this bottleneck by minimizing memory reads and writes, fusing all attention operations into a single GPU kernel. Despite these optimizations, FlashAttention-2 only achieves around 35% utilization on NVIDIA's newer Hopper H100 GPUs. The culprit? FlashAttention-2 relies on a simplified, synchronous execution model and fails to leverage the asynchronous and low-precision capabilities of modern hardware. FlashAttention-3 corrects this, introducing techniques that exploit these hardware features to achieve a 1.5-2.0$\times$ speedup over its predecessor.

## The Hardware Shift: Embracing Asynchrony

Modern GPUs like the Hopper H100 are built for throughput, relying heavily on concurrency and asynchrony to hide memory and execution latencies. The GPU features specialized hardware units like the Tensor Memory Accelerator (TMA) for asynchronous memory loading and Tensor Cores for executing matrix multiplications (GEMMs). These units operate independently of the standard CUDA cores that handle logic and floating-point operations. 

FlashAttention-3 takes advantage of this hardware specialization through a technique called warp-specialization. In this scheme, the thread groups (or "warps") on the GPU are divided into producers and consumers. Producer warps are dedicated solely to issuing asynchronous data loads via the TMA, while consumer warps handle the mathematical computations using the Tensor Cores. This explicit separation allows the GPU to overlap data movement with computation, effectively hiding memory latency.

## Hiding Softmax Under Async GEMMs

Even within the consumer warps, there is a hidden inefficiency. The attention computation involves a mix of high-throughput matrix multiplications (GEMMs) and lower-throughput non-matmul operations, like the exponential functions required for softmax. On an H100, FP16 matmul throughput is 989 TFLOPS, while special functions like exponentials only deliver 3.9 TFLOPS. This means that while the exponential is computationally cheap in terms of raw operations, it can bottleneck the entire pipeline simply because it takes so long to execute.

To solve this, FlashAttention-3 overlaps the comparatively slow softmax computation with asynchronous GEMM instructions. The algorithm uses a "pingpong" scheduling scheme with synchronization barriers. While one warpgroup is performing softmax on a block of the scores matrix, another warpgroup is concurrently executing its GEMMs on the Tensor Cores. The roles then swap, allowing the GPU to keep the high-throughput Tensor Cores continuously fed while the softer, logic-heavy operations run in the background.

## Pushing Precision with FP8

The most straightforward way to increase throughput on modern GPUs is to reduce the precision of the computations. Hopper GPUs support FP8 Tensor Cores, which deliver double the throughput compared to FP16. Adapting FlashAttention-3 to run in FP8, however, comes with two major challenges: memory layout conformance and numerical accuracy.

First, FP8 matrix multiplication instructions (WGMMA) require operands to be laid out in specific memory formats. For instance, the $\mathbf{V}$ matrix tiles need to be contiguous in the sequence length dimension, which doesn't match standard input layouts. FlashAttention-3 handles this by performing an in-kernel transpose using specialized load and store instructions, allowing it to rearrange data on the fly without stalling the pipeline. 

Second, compressing values down to 8 bits introduces numerical error, which is worsened by the presence of outlier values common in large language models. FlashAttention-3 mitigates this using two techniques:

- **Block quantization:** Instead of using a single scaling factor for the entire tensor, the algorithm splits tensors like $\mathbf{Q}$, $\mathbf{K}$, and $\mathbf{V}$ into smaller blocks and scales them individually. This allows the algorithm to represent a wider dynamic range locally.
- **Incoherent processing:** Before quantizing, $\mathbf{Q}$ and $\mathbf{K}$ are multiplied by a random orthogonal matrix $\mathbf{M}$. Since $\mathbf{M} \mathbf{M}^\top = I$, this multiplication does not change the final attention output, but it does "spread out" outlier values across the matrix, reducing the quantization error.

## Performance and Accuracy Gains

The empirical results of FlashAttention-3 are striking. On an H100 GPU, the FP16 version reaches up to 740 TFLOPs/s—75% of the theoretical maximum—making it 1.5-2.0$\times$ faster than FlashAttention-2 in the forward pass and 1.5-1.75$\times$ faster in the backward pass. The FP8 version pushes this even further, reaching close to 1.2 PFLOPs/s.

Importantly, these speedups do not come at the cost of accuracy. While the FP16 implementation maintains the same numerical error as FlashAttention-2, the FP8 implementation with block quantization and incoherent processing achieves 2.6$\times$ lower numerical error than a baseline FP8 attention implementation using per-tensor quantization.

By deeply integrating the asynchronous execution model and low-precision capabilities of modern GPUs into the fundamental algorithm design, FlashAttention-3 represents a significant leap forward. It clears a major computational hurdle, unlocking the potential for faster, more efficient long-context AI applications.

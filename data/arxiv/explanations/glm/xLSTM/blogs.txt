# The Comeback Kid: How xLSTM is Challenging the Transformer Era

In the 1990s, Long Short-Term Memory (LSTM) networks revolutionized recurrent neural networks by introducing the constant error carousel and gating mechanisms. For years, LSTMs dominated sequence modeling tasks, from text generation to reinforcement learning, and even powered the first Large Language Models (LLMs). However, the introduction of Transformers in 2017, with their highly parallelizable self-attention, outpaced LSTMs at scale, pushing them out of the spotlight. 

Now, a new paper asks a simple question: how far can we get in language modeling if we scale LSTMs to billions of parameters while mitigating their historical limitations? The answer is Extended Long Short-Term Memory (xLSTM), a modernized architecture that brings LSTMs back into direct competition with state-of-the-art Transformers and State Space Models.

## The Fall of the LSTM

Despite their past success, traditional LSTMs had three major limitations that allowed Transformers to take over:

- **Inability to revise storage decisions:** Once the LSTM decided to store a piece of information, it struggled to update or revise that storage when new, more relevant information came along.
- **Limited storage capacities:** LSTMs compress information into scalar cell states, which bottlenecks their ability to memorize rare tokens or large amounts of information.
- **Lack of parallelizability:** Due to memory mixing (hidden-hidden recurrent connections from one time step to the next), LSTMs must be processed sequentially, making them slow to train compared to Transformers.

## The xLSTM Solution

To overcome these limitations, the authors of the xLSTM paper introduce two key modifications: exponential gating and novel memory structures. These modifications result in two new LSTM variants: sLSTM and mLSTM. 

### sLSTM: Exponential Gating and Scalar Memory

The sLSTM addresses the inability to revise storage decisions by introducing exponential gating. Instead of using the traditional sigmoid activation function for the input and forget gates, sLSTM uses exponential activation functions, such as $i_t = \exp(\tilde{i}_t)$ and $f_t = \exp(\tilde{f}_t)$. This change allows the network to more aggressively update its memory when needed. 

Because exponential functions can lead to large values and numerical overflows, the sLSTM introduces a normalizer state $n_t$ and a stabilizer state $m_t$. The sLSTM retains memory mixing through hidden-hidden connections but introduces multiple heads, allowing memory mixing across cells within a head but not across different heads. While this memory mixing means sLSTM is not fully parallelizable, the authors developed a fast CUDA implementation that makes it less than two times slower than its parallel counterpart.

### mLSTM: Matrix Memory and Parallel Processing

The mLSTM tackles the limited storage capacity by upgrading the scalar memory cell $c \in \mathbb{R}$ to a matrix memory $\mathbf{C} \in \mathbb{R}^{d \times d}$. This allows the model to store key-value pairs using a covariance update rule: 

$$ \mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top $$

Here, $\mathbf{v}_t$ is the value vector, $\mathbf{k}_t$ is the key vector, $f_t$ is the forget gate (acting as a decay rate), and $i_t$ is the input gate (acting as a learning rate). Retrieval is performed via matrix multiplication with a query vector $\mathbf{q}_t$.

Crucially, mLSTM removes the hidden-hidden recurrent connections (memory mixing) entirely. Without these sequential dependencies, mLSTM becomes fully parallelizable, allowing it to be trained as efficiently as modern Transformer models. 

## Building the xLSTM Architecture

The xLSTM architecture is built by integrating these new variants into residual block backbones. The authors use post up-projection blocks for sLSTM (similar to Transformers) and pre up-projection blocks for mLSTM (similar to State Space Models). These blocks are then residually stacked to form the final xLSTM architecture. An xLSTM architecture can mix both block types; for example, an xLSTM[7:1] architecture uses seven mLSTM blocks for every one sLSTM block.

## Can xLSTM Compete with Transformers?

The paper conducts extensive experiments, training models on 15 billion and 300 billion tokens from the SlimPajama dataset. The results are promising:

- **Validation Perplexity:** xLSTM outperforms existing Transformers (like Llama), State Space Models (like Mamba), and other RNNs (like RWKV) in validation perplexity across various model sizes.
- **Scaling Laws:** xLSTM exhibits favorable scaling behavior, indicating that larger xLSTM models will continue to perform well compared to Transformers and State Space Models.
- **Sequence Length Extrapolation:** Unlike other models, xLSTM maintains low perplexities when evaluated on sequence lengths longer than those seen during training.
- **Throughput and Memory:** xLSTM has linear computation and constant memory complexity with respect to sequence length, making it highly efficient for inference and suitable for edge applications.

## Conclusion

xLSTM successfully modernizes the classic LSTM by addressing its core limitations. By introducing exponential gating and matrix memory, xLSTM combines the best of both worlds: the state-tracking capabilities of traditional RNNs and the parallelizability of Transformers. The favorable scaling laws and strong performance on language modeling tasks suggest that xLSTM is a serious competitor to the current Transformer-dominated landscape.



# Saying Goodbye to Scalar Memory: The Matrix Magic of mLSTM

The original Long Short-Term Memory (LSTM) architecture was a breakthrough for sequence modeling, introducing the constant error carousel and gating mechanisms to solve the vanishing gradient problem. But LSTMs have a fundamental storage limitation: every piece of information must be compressed into a scalar cell state $c \in \mathbb{R}$. When Transformers arrived with their parallelizable self-attention and vast capacity for storing token-token interactions, LSTMs fell behind at scale. The xLSTM paper asks a provocative question: how far can we get if we fix the LSTM's core limitations and scale it up? The mLSTM—Matrix LSTM—is one of two new variants proposed, and it directly addresses the scalar memory bottleneck.

## The Storage Problem

To understand why scalar memory is limiting, consider what happens when an LSTM needs to store a key-value pair for later retrieval. The model sees a key vector at one timestep and needs to retrieve its associated value vector many steps later. With a scalar cell state, all of this information must be squeezed into a single number per memory cell. The paper demonstrates this limitation through a Rare Token Prediction experiment on Wikitext-103, showing that standard LSTMs perform significantly worse on rare tokens precisely because their limited storage capacity cannot adequately encode infrequent information.

The root cause is architectural. In the original LSTM, the cell state update is:

$$c_t = f_t \, c_{t-1} + i_t \, z_t$$

where $c_t$ is a scalar, $f_t$ is the forget gate, $i_t$ is the input gate, and $z_t$ is the cell input. Everything—keys, values, contextual information—must flow through this single scalar value per cell.

## Enter Matrix Memory

The mLSTM replaces the scalar cell state $c$ with a matrix $\mathbf{C} \in \mathbb{R}^{d \times d}$. This is a dramatic increase in storage capacity. Instead of compressing information into a single number, the model can now store structured associations between vectors.

The update rule is inspired by Bidirectional Associative Memories and the covariance update rule from classical neural network theory:

$$\mathbf{C}_t = \mathbf{C}_{t-1} + \mathbf{v}_t \, \mathbf{k}_t^\top$$

Here, $\mathbf{k}_t \in \mathbb{R}^d$ is a key vector and $\mathbf{v}_t \in \mathbb{R}^d$ is a value vector—the same terminology used in Transformers. At a later timestep $t + \tau$, the value $\mathbf{v}_t$ can be retrieved via a query vector $\mathbf{q}_{t+\tau}$ through matrix multiplication $\mathbf{C}_t \mathbf{q}_t$.

This covariance update is optimal for maximizing the signal-to-noise ratio when retrieving binary vectors, as established in classical work by Dayan (1991). The key insight is that the outer product $\mathbf{v}_t \mathbf{k}_t^\top$ creates a rank-one update that stores the association between the key and value in the matrix structure itself.

## Integrating Gates into the Matrix Update

The mLSTM doesn't just borrow the covariance update rule—it integrates it into the LSTM gating framework. The forget gate becomes a decay rate applied to the existing matrix memory, and the input gate becomes a learning rate that controls how strongly new key-value pairs are written:

$$\mathbf{C}_t = f_t \, \mathbf{C}_{t-1} + i_t \, \mathbf{v}_t \, \mathbf{k}_t^\top$$

A normalizer state tracks the weighted sum of key vectors:

$$\mathbf{n}_t = f_t \, \mathbf{n}_{t-1} + i_t \, \mathbf{k}_t$$

The hidden state is then computed as:

$$\tilde{\mathbf{h}}_t = \mathbf{C}_t \mathbf{q}_t / \max\{|\mathbf{n}_t^\top \mathbf{q}_t|, 1\}$$

The denominator prevents division by near-zero values, with the absolute value and lower bound of 1.0 ensuring numerical stability. An output gate $\mathbf{o}_t$ then scales the retrieved vector to produce the final hidden state $\mathbf{h}_t = \mathbf{o}_t \odot \tilde{\mathbf{h}}_t$.

## Exponential Gating

Both mLSTM and its scalar counterpart sLSTM use exponential activation functions for the input and forget gates, replacing the traditional sigmoid. Instead of $\sigma(\tilde{i}_t) = 1/(1 + \exp(-\tilde{i}_t))$, the gates use $\exp(\tilde{i}_t)$ and either $\sigma(\tilde{f}_t)$ or $\exp(\tilde{f}_t)$.

This change is crucial for solving one of the original LSTM's limitations: the inability to revise storage decisions. With sigmoid gates bounded between 0 and 1, once information is stored, the model has limited ability to strongly overwrite it. Exponential gates can produce values much larger than 1, allowing new information to decisively override previous storage. The paper demonstrates this on a Nearest Neighbor Search task where the model must scan a sequence and output the value attached to the most similar vector to a reference. Standard LSTMs struggle to update their stored value when a better match appears; exponential gating fixes this.

To prevent overflow from large exponential values, a stabilizer state $m_t$ is maintained:

$$m_t = \max(\log(f_t) + m_{t-1}, \log(i_t))$$

The stabilized gates $i'_t = \exp(\tilde{i}_t - m_t)$ and $f'_t = \exp(\log(f_t) + m_{t-1} - m_t)$ keep computations numerically stable without changing the network's output or gradients.

## The Parallelization Breakthrough

The original LSTM has hidden-hidden recurrent connections—memory mixing—where the hidden state from the previous timestep feeds into the current timestep's gates and cell input. This creates a sequential dependency that prevents parallel computation.

The mLSTM removes these hidden-hidden connections entirely. The query, key, and value inputs are computed purely from the current input $\mathbf{x}_t$:

$$\mathbf{q}_t = \mathbf{W}_q \mathbf{x}_t + \mathbf{b}_q$$
$$\mathbf{k}_t = \frac{1}{\sqrt{d}} \mathbf{W}_k \mathbf{x}_t + \mathbf{b}_k$$
$$\mathbf{v}_t = \mathbf{W}_v \mathbf{x}_t + \mathbf{b}_v$$

The input and forget gates also depend only on the current input, not the previous hidden state. This means the recurrence can be reformulated into a parallel version, analogous to techniques like FlashAttention. The matrix memory updates and retrieval operations are standard matrix operations that GPUs handle efficiently.

This is a significant advantage over the sLSTM variant, which retains memory mixing and therefore cannot be parallelized in the same way. The paper notes that a fast CUDA implementation of sLSTM is currently less than two times slower than the parallel mLSTM, but mLSTM's parallelizability remains a structural advantage.

## Does It Actually Work?

The paper provides extensive evidence that mLSTM's matrix memory delivers on its promise. On the Multi-Query Associative Recall task—which tests memory capacity by requiring models to memorize up to 256 key-value pairs across contexts up to 2048 tokens—xLSTM[1:1] (a mix of mLSTM and sLSTM blocks) performs best among all non-Transformer models tested, including Mamba, RWKV-5, and RWKV-6.

In large-scale language modeling experiments on 300B tokens from SlimPajama, xLSTM models achieve the best validation perplexity across all model sizes (125M, 350M, 760M, 1.3B) compared to Llama, Mamba, and RWKV-4. On the PALOMA benchmark covering 571 text domains, xLSTM[1:0] (mLSTM only) achieves lower perplexity than Mamba in 568 out of 571 domains and lower perplexity than Llama in 486 out of 571 domains.

The scaling laws are particularly encouraging. All models show similar power-law scaling behavior, but xLSTM has a favorable offset—better than Mamba by a similar margin as Mamba is better than Llama. This suggests that as models grow larger, xLSTM will maintain or extend its advantage.

On sequence length extrapolation, xLSTM models trained on context length 2048 maintain low perplexities when tested on contexts up to 16384, outperforming the other methods. This is a natural consequence of the constant memory complexity with respect to sequence length: the matrix memory $\mathbf{C}$ doesn't grow with the number of tokens processed.

## The Trade-offs

The matrix memory comes with computational cost. The $d \times d$ matrix updates are expensive in terms of raw computation, and the current CUDA kernels are about 4 times slower than FlashAttention or Mamba's scan operation. However, because these operations can be parallelized using standard matrix operations on GPUs, the wall-clock time overhead is described as minor.

The memory is also compressive—it doesn't grow with sequence length—which makes xLSTM well-suited for edge deployments and industrial applications where memory efficiency matters. The trade-off is between memory capacity and computational complexity, but the paper argues this is a worthwhile exchange given modern GPU capabilities.

## What This Means for the Future

The mLSTM demonstrates that the LSTM architecture, when properly modernized, can compete with Transformers and State Space Models at scale. By upgrading from scalar to matrix memory, the model gains the storage capacity needed for language modeling. By removing memory mixing, it gains the parallelizability needed for efficient training. By adding exponential gating, it gains the ability to revise its storage decisions.

The scaling laws suggest that larger xLSTM models will be "serious competitors to current Large Language Models that are built with the Transformer technology." The architecture's linear computation and constant memory complexity with respect to sequence length make it particularly attractive for long-context applications and resource-constrained environments.

The xLSTM paper doesn't claim to have fully optimized the architecture—it acknowledges that hyperparameters and architecture details need extensive tuning for larger models. But the core insight is powerful: the LSTM's limitations were not fundamental to the approach. They were engineering problems with engineering solutions, and the mLSTM's matrix memory is the centerpiece of that fix.



# Exponential Gating: Giving LSTMs the Power to 'Forget' Efficiently

Long Short-Term Memory networks (LSTMs) once dominated sequence modeling, powering everything from early language models to reinforcement learning agents. However, they were eventually outpaced by Transformers, largely due to three inherent limitations. One of the most critical flaws of the classic LSTM is its inability to revise storage decisions. Once the model commits to storing a piece of information, it struggles to overwrite it when newer, more relevant data arrives. The xLSTM paper tackles this head-on with a new variant called sLSTM (Scalar LSTM), introducing a clever twist: exponential gating.

## The Achilles' Heel of Classic LSTMs

To understand why exponential gating is necessary, we have to look at how traditional LSTMs handle memory. A classic LSTM relies on a constant error carousel, updating its cell state $c_t$ as:

$$c_t = f_t c_{t-1} + i_t z_t$$

Here, $f_t$ is the forget gate, $i_t$ is the input gate, and $z_t$ is the new cell input. In the original architecture, both the input and forget gates use a sigmoid activation function, $\sigma(x) = 1/(1+\exp(-x))$, which squashes values into a range between 0 and 1. 

This poses a problem. Because the input gate $i_t$ is bounded by 1, the model can only add new information to the cell state at a limited rate. If an LSTM has confidently stored a value in its memory and needs to completely revise that decision based on new evidence, the sigmoid gate acts as a bottleneck. The paper highlights this using a Nearest Neighbor Search problem, where the model must scan a sequence and update its stored value whenever a more similar vector is found. Traditional LSTMs fail at this because they cannot decisively overwrite their previous storage decisions.

## Enter sLSTM and Exponential Gating

The sLSTM remedies this limitation by replacing the sigmoid activation in the gates with exponential activation functions. Instead of being capped at 1, the input and forget gates can now grow significantly larger:

$$i_t = \exp(\tilde{i}_t)$$
$$f_t = \sigma(\tilde{f}_t) \text{ OR } \exp(\tilde{f}_t)$$

By using $\exp(\tilde{i}_t)$ for the input gate, the sLSTM can aggressively inject new information into the cell state $c_t$. If the model encounters a new input that strongly suggests it should overwrite its past memory, the exponential input gate allows it to do so with immense force. This simple yet powerful tweak gives the sLSTM the ability to rapidly revise its storage decisions, passing the Nearest Neighbor Search tests where its predecessor failed.

## Taming the Explosive Exponentials

While exponential gating solves the revision problem, it introduces a new challenge: numerical instability. Exponential functions can quickly grow to enormous values, leading to computational overflows. The sLSTM addresses this with two key mechanisms.

First, it introduces a normalizer state, $n_t$, which tracks the cumulative sum of the gate activations:

$$n_t = f_t n_{t-1} + i_t$$

The hidden state is then computed by dividing the cell state by this normalizer state:

$$\tilde{h}_t = \frac{c_t}{n_t}$$
$$h_t = o_t \tilde{h}_t$$

This normalization ensures that the output remains scaled appropriately despite the large values inside the cell state. 

Second, to prevent the exponentials from overflowing during computation, the authors introduce a stabilizer state, $m_t$. This state keeps track of the maximum log-values of the gates:

$$m_t = \max(\log(f_t) + m_{t-1}, \log(i_t))$$

The input and forget gates are then rescaled using this stabilizer state before being applied to the cell state:

$$i'_t = \exp(\tilde{i}_t - m_t)$$
$$f'_t = \exp(\log(f_t) + m_{t-1} - m_t)$$

The paper proves that replacing the original gates with these stabilized versions does not change the network's output or the gradients during backpropagation. This ensures the model remains numerically stable without sacrificing any expressive power.

## A New Era of Memory Mixing

Beyond exponential gating, the sLSTM introduces a new approach to memory mixing. In traditional LSTMs, multiple memory cells are mixed via recurrent connections from the hidden state to the cell inputs and gates. 

The sLSTM extends this by introducing multiple heads, similar to attention mechanisms in Transformers. Memory mixing occurs across cells within a single head, but not across different heads. When combined with exponential gating, this establishes a completely new dynamic for how information flows and interacts within the network, allowing the model to better separate different histories and contexts.

## Wrapping Up

The sLSTM represents a significant modernization of the classic LSTM. By simply swapping sigmoid gates for exponential ones—and carefully managing the resulting numerical challenges—the sLSTM gains the ability to rapidly update and revise its memory. In the broader xLSTM architecture, these sLSTM blocks are integrated using a post up-projection residual structure, allowing the model to non-linearly summarize the past in a high-dimensional space. This fix to the LSTM's memory revision problem is a crucial step in allowing the xLSTM to compete with state-of-the-art Transformers and State Space Models at scale.



# David vs. Goliath: Benchmarking xLSTM Against Transformers and State Space Models

## Introduction
Since their introduction in the 1990s, Long Short-Term Memory (LSTM) networks have been foundational to deep learning. However, the rise of Transformers and their parallelizable self-attention mechanisms sidelined LSTMs in the era of Large Language Models (LLMs). A recent paper titled "xLSTM: Extended Long Short-Term Memory" asks a bold question: How far can we push LSTMs if we mitigate their classic limitations and scale them to billions of parameters? The authors introduce xLSTM, an architecture equipped with exponential gating and novel memory structures. But how does this modernized recurrent network stack up against today's Goliaths like Transformers (Llama) and State Space Models (Mamba)?

## The Core Upgrades: sLSTM and mLSTM
Before diving into the benchmarks, it is helpful to understand what makes xLSTM different. The original LSTM had three main limitations: an inability to revise storage decisions, limited storage capacities due to scalar memory, and a lack of parallelizability caused by memory mixing (hidden-to-hidden recurrent connections). 

To address these, xLSTM introduces two distinct variants. The first is the sLSTM, which maintains scalar memory and memory mixing but introduces exponential gates alongside a normalizer state. This allows the model to revise its storage decisions, a critical capability for state tracking problems. The second variant is the mLSTM, which upgrades the scalar memory to a matrix $\mathbf{C} \in \mathbb{R}^{d \times d}$ and uses a covariance update rule. Crucially, the mLSTM abandons memory mixing entirely, making it fully parallelizable.

## Synthetic Tasks: Proving the Concepts
The paper first validates xLSTM's new capabilities on synthetic tasks designed to highlight specific architectural strengths.

On formal language tasks like the parity problem, models without memory mixing—such as standard Transformers and State Space Models—fundamentally struggle. Because sLSTM retains memory mixing and enhances it with exponential gating, xLSTM successfully solves these state tracking problems, demonstrating a higher degree of expressiveness than its competitors.

The paper also tests memory capacity using the Multi-Query Associative Recall (MQAR) task, which evaluates a model's ability to memorize and retrieve key-value pairs. While Transformers remain the gold standard because their memory scales exponentially with the coding dimension, xLSTM performs best among all non-Transformer models. The matrix memory of mLSTM proves highly effective at storing and retrieving complex associations, even outperforming other recurrent architectures like RWKV at scale.

## Language Modeling at 15B Tokens
The first major language modeling comparison involves training models of approximately 350 million parameters on 15 billion tokens from the SlimPajama dataset. The paper compares xLSTM against a suite of modern architectures, including GPT-3, Llama, Mamba, RWKV, and RetNet.

In terms of validation perplexity, xLSTM outperforms all existing methods. Ablation studies confirm that this success is not accidental: progressively morphing a vanilla LSTM into an xLSTM reveals that both the exponential gating and the matrix memory contribute significantly to the performance boost.

## Scaling Up: 300B Tokens and Downstream Tasks
To truly test xLSTM's potential as an LLM, the authors scaled the training to 300 billion tokens, comparing xLSTM against Llama (Transformer), Mamba (SSM), and RWKV-4 (RNN) across model sizes from 125M to 1.3B parameters.

Across all model sizes, xLSTM achieves the best validation perplexity. On downstream tasks measuring common sense reasoning, xLSTM wins in the vast majority of benchmarks, with Mamba occasionally taking the lead on the ARC task. 

The authors also evaluated the models on the PALOMA language benchmark, which spans 571 diverse text domains. The results are striking: xLSTM achieves lower perplexity than Mamba in 568 out of 571 domains (99.5%), lower than Llama in 486 domains (85.1%), and lower than RWKV-4 in 570 domains (99.8%).

## Scaling Laws and Efficiency
A key question for any new architecture is how it scales. The paper presents power-law scaling behavior for the 300B token experiments. xLSTM demonstrates a favorable scaling trajectory, outperforming Mamba by a margin similar to Mamba's advantage over Llama. This suggests that xLSTM will remain highly competitive as models grow larger.

Efficiency is another crucial battleground. While Transformers like Llama suffer from quadratic scaling in generation time due to their key-value caches, xLSTM (like other recurrent models) scales linearly. Furthermore, because xLSTM's memory complexity is constant with respect to sequence length, it can handle much higher batch sizes than Llama, achieving the highest decoding throughput. 

When trained on a context length of 2048 and tested up to 16384, xLSTM uniquely maintains low perplexities on longer contexts, whereas other methods degrade. This indicates a robust ability to extrapolate to longer sequences without retraining.

## Limitations and the Road Ahead
No architecture is without trade-offs. The paper notes that mLSTM's matrix memory requires processing $d \times d$ matrices, which is computationally expensive, though the operations can be parallelized on GPUs. Meanwhile, sLSTM lacks parallelizability due to memory mixing, though custom CUDA kernels keep it reasonably fast. The authors also note that hyperparameters were not fully optimized for larger runs, leaving potential performance gains on the table.

## Conclusion
The xLSTM paper makes a compelling case that the classic LSTM architecture is far from obsolete. By introducing exponential gating and matrix memory, xLSTM mitigates the historical weaknesses of LSTMs while preserving their strengths in state tracking and memory compression. In direct benchmarks against Transformers and State Space Models, xLSTM not only holds its own but often surpasses them in perplexity, downstream task performance, and scaling efficiency. As the deep learning community continues to search for more efficient sequence models, xLSTM proves that sometimes, the old David can still compete with the modern Goliaths.



# Building xLSTM: Residual Blocks and the Anatomy of a Modern RNN

## The Comeback of LSTMs

The Long Short-Term Memory (LSTM) network was once a dominant force in deep learning for sequence modeling, but it eventually took a backseat to Transformers. Transformers overcame critical LSTM limitations, such as the inability to revise storage decisions, limited storage capacities, and a lack of parallelizability. However, the creators of xLSTM pose a simple question: how far can we get in language modeling if we mitigate these limitations and scale LSTMs to billions of parameters?

To answer this, the authors introduce Extended LSTM (xLSTM). The architecture upgrades the classic LSTM with exponential gating and novel memory structures, resulting in two new variants: sLSTM and mLSTM. But having new cell designs is only half the battle. The real magic lies in how these cells are packaged into modern residual blocks and stacked into a highly scalable architecture.

## Two New Flavors of Memory Cells

Before diving into the architecture, we need to understand the two building blocks at the cellular level.

First, there is the sLSTM. It retains the scalar memory of the original LSTM but introduces exponential gating with appropriate normalization and stabilization. This allows the network to revise storage decisions, overcoming a key limitation of older LSTMs. The sLSTM also features memory mixing through hidden-hidden recurrent connections, making it highly expressive for tasks like state tracking.

Second, there is the mLSTM. To solve the limited storage capacity of scalar memory, the mLSTM upgrades the memory cell from a scalar $c \in \mathbb{R}$ to a matrix $\mathbf{C} \in \mathbb{R}^{d \times d}$. It uses a covariance update rule to store key-value pairs, similar to the associative memory mechanisms found in Transformers. Because it abandons memory mixing (the hidden-hidden connections), the mLSTM is fully parallelizable, a crucial feature for modern large-scale training.

## Designing the xLSTM Blocks

To correctly predict the next token, a model needs to separate different histories or contexts. Cover's Theorem states that patterns are more likely to be linearly separated if they are non-linearly embedded in a higher-dimensional space. The xLSTM architecture leverages this by non-linearly summarizing the past in a high-dimensional space within its residual blocks.

The researchers designed two distinct residual block architectures to house the sLSTM and mLSTM cells.

For the sLSTM, they use a post up-projection block. This approach, reminiscent of standard Transformer blocks, works as follows:

- The model first non-linearly summarizes the past in the original space.
- It then linearly maps this summary into a high-dimensional space.
- A non-linear activation function is applied.
- Finally, it linearly maps back to the original space.

For the mLSTM, they use a pre up-projection block, an approach favored by State Space Models. The process is slightly different:

- The model first linearly maps the input into a high-dimensional space.
- It then non-linearly summarizes the past within this high-dimensional space.
- Finally, it linearly maps back to the original space.

Why the difference? The mLSTM's matrix memory benefits greatly from the pre up-projection approach because its memory capacity becomes much larger when operating in a higher-dimensional space.

## Assembling the xLSTM Architecture

With the building blocks defined, the full xLSTM architecture is constructed by residually stacking these xLSTM blocks. Like most contemporary large language models, the architecture relies on a pre-LayerNorm residual backbone.

An xLSTM network does not have to choose strictly between sLSTM and mLSTM blocks; it can mix them. The paper introduces a notation to describe this mixture: xLSTM$[a:b]$ denotes the ratio of mLSTM blocks to sLSTM blocks. For instance, an xLSTM$[7:1]$ architecture means that out of every eight blocks, seven are mLSTM-based and one is sLSTM-based. This allows the model to enjoy the parallelization and large memory capacity of the mLSTM while still benefiting from the memory mixing and state tracking capabilities of the sLSTM.

## Memory and Speed Considerations

One of the most compelling advantages of xLSTM over Transformers is its efficiency. Transformers have a quadratic computation and memory complexity with respect to the sequence length. In contrast, xLSTM networks boast linear computation and constant memory complexity. Because the xLSTM memory is compressive, it is well suited for industrial applications and implementations on edge devices.

However, the two variants have different parallelization profiles. The mLSTM is fully parallelizable, similar to attention mechanisms like FlashAttention. The sLSTM, due to its memory mixing, cannot be parallelized in the same way. Despite this, the researchers developed a fast custom CUDA implementation with GPU memory optimizations, making the sLSTM typically less than two times slower than the parallel mLSTM.

## Conclusion

The xLSTM architecture represents a thoughtful modernization of a classic deep learning model. By carefully pairing the right memory cell with the right residual block—mLSTM with pre up-projection and sLSTM with post up-projection—the authors have created a scalable, efficient architecture. Combined with the computational benefits of constant memory complexity, xLSTM demonstrates that LSTMs are not just a relic of the past, but a viable competitor to modern Transformers and State Space Models.

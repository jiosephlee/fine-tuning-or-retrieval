\title{A Textbook about the Paper: "xLSTM: Extended Long Short-Term Memory"}

Chapter 6: xLSTM Architecture: Blocks and Stacking

The core innovations of xLSTM—exponential gating and novel memory structures—do not by themselves constitute a complete neural network architecture. To build a model capable of language modeling at scale, the sLSTM and mLSTM memory cells must be embedded into larger computational units that can effectively process, transform, and propagate information across many layers. This chapter explains how sLSTM and mLSTM are integrated into residual block architectures, how these blocks are stacked to form complete xLSTM architectures, and the theoretical and practical rationale guiding these design decisions.

# Cover's Theorem: Non-Linear Separation in High-Dimensional Spaces

A central design principle of xLSTM blocks is the idea that the past should be non-linearly summarized in a high-dimensional space. The motivation for this principle comes from Cover's Theorem, a classical result from the theory of pattern classification. Cover's Theorem states that patterns which are non-linearly embedded into a higher-dimensional space can more likely be linearly separated than in the original, lower-dimensional space. In other words, by mapping data through a non-linear function into a space with more dimensions, one increases the probability that complex, intertwined patterns become separable by simple linear decision boundaries.

The relevance of Cover's Theorem to sequence modeling is direct and profound. The goal of an xLSTM block is to non-linearly summarize the past—meaning all the information from previous sequence elements—so that different histories or contexts can be better separated from one another. This separation is a prerequisite for correctly predicting the next sequence element, such as the next token in a language model. If two distinct histories produce representations that are too similar, the model will struggle to make different predictions for them, leading to poor performance. By lifting the representation into a higher-dimensional space and applying non-linear transformations, the xLSTM architecture increases the separability of different histories, thereby improving its predictive capability.

In the xLSTM architecture, Cover's Theorem provides the justification for incorporating up-projection steps—operations that linearly map from the original model dimension to a higher-dimensional space, apply non-linear activations, and then map back down. These up-projection steps create the high-dimensional non-linear embedding that Cover's Theorem suggests is beneficial for separability. The two block types in xLSTM differ in where this up-projection occurs relative to the recurrent memory operation, but both share the same underlying rationale rooted in Cover's Theorem.

# Block Type (i): Post Up-Projection Residual Block for sLSTM

The first block type used in xLSTM is the post up-projection residual block, which is designed to house the sLSTM. The term "post up-projection" refers to the fact that the up-projection step comes after the recurrent memory operation in the forward pass of the block. This design is analogous to the block structure used in Transformers.

In a post up-projection block, the sLSTM first non-linearly summarizes the past in the original model dimension. That is, the sLSTM takes the current input, processes it through its scalar memory cells with exponential gating and memory mixing, and produces a hidden state that summarizes the sequence history up to the current time step. This summarization happens entirely within the original dimensionality of the model's hidden space. After this recurrent summarization step, the block linearly maps the resulting representation into a high-dimensional space, applies a non-linear activation function in that high-dimensional space, and then linearly maps back down to the original space. This up-projection-down-projection sequence is a feed-forward network that further processes the sLSTM's output, expanding its representational power.

The choice of post up-projection for the sLSTM is deliberate. The sLSTM operates with a scalar memory and includes memory mixing through recurrent hidden-to-hidden connections. Because the sLSTM's memory mixing requires sequential processing, the recurrent operation must take place in the original dimensionality where the recurrent weight matrices are defined. The up-projection then serves to expand the sLSTM's output into a richer representation space where non-linear feed-forward transformations can extract and amplify useful features. The high-dimensional space is used for the feed-forward processing, not for the recurrent memory itself, which is consistent with the sLSTM's scalar memory structure.

# Block Type (ii): Pre Up-Projection Residual Block for mLSTM

The second block type is the pre up-projection residual block, which is designed to house the mLSTM. The term "pre up-projection" indicates that the up-projection step comes before the recurrent memory operation. This design is analogous to the block structure used in State Space Models.

In a pre up-projection block, the input is first linearly mapped from the original model dimension into a high-dimensional space. The mLSTM then performs its recurrent memory operation—storing and retrieving key-value pairs through its matrix memory with the covariance update rule—entirely within this high-dimensional space. After the mLSTM has summarized the past in the high-dimensional space, the block linearly maps the result back down to the original model dimension. The non-linear summarization of the past thus takes place in the high-dimensional space, not in the original space.

The critical advantage of this design for the mLSTM is that the matrix memory operates in the high-dimensional space, giving it a much larger memory capacity. Recall that the mLSTM stores a matrix $\mathbf{C} \in \mathbb{R}^{d \times d}$ as its cell state, where $d$ is the dimension of the space in which the mLSTM operates. By performing the up-projection before the mLSTM, the effective dimension $d$ of the matrix memory is increased, which increases the storage capacity of the memory. The matrix memory can store more key-value associations when it operates in a higher-dimensional space, directly addressing the limited storage capacity that was one of the three main limitations of the original LSTM.

Since the mLSTM has no memory mixing—meaning there are no hidden-to-hidden recurrent connections—it is fully parallelizable. The pre up-projection does not introduce any sequential dependency, because the linear projection can be applied to all time steps independently before the parallel recurrent computation. This preserves the parallelizability that is a key advantage of the mLSTM over the original LSTM and the sLSTM.

# Rationale for Block Assignment: sLSTM Uses Post Up-Projection, mLSTM Uses Pre Up-Projection

The assignment of post up-projection to sLSTM and pre up-projection to mLSTM is not arbitrary but is motivated by the distinct characteristics of each memory type. The paper provides clear reasoning for this design choice.

For the sLSTM, the post up-projection block is used. The sLSTM features a scalar memory and, crucially, memory mixing through recurrent hidden-to-hidden connections. The memory mixing means that the hidden state from one time step directly influences the computation at the next time step through the recurrent weight matrices $\mathbf{R}_{\mathbf{z}}$, $\mathbf{R}_{\mathbf{i}}$, $\mathbf{R}_{\mathbf{f}}$, and $\mathbf{R}_{\mathbf{o}}$. These recurrent weights are defined within the model's original dimensionality. Therefore, the recurrent summarization must take place in the original space, and the up-projection can only be applied afterward as a feed-forward transformation. Placing the up-projection before the sLSTM would break the memory mixing, because the recurrent connections would need to operate in the high-dimensional space, dramatically increasing the number of parameters in the recurrent weight matrices and the computational cost of the sequential processing.

For the mLSTM, the pre up-projection block is used. The mLSTM features a matrix memory with a covariance update rule, and it has no memory mixing. Because there are no hidden-to-hidden recurrent connections, there is no constraint forcing the recurrent operation to take place in the original dimensionality. The mLSTM can operate in any dimension, and operating in a higher dimension directly increases the memory capacity of the matrix $\mathbf{C} \in \mathbb{R}^{d \times d}$. The paper explicitly states that the pre up-projection block is chosen for the mLSTM "since the memory capacity becomes larger in the high-dimensional space." Since the mLSTM is parallelizable, the up-projection can be applied to all time steps simultaneously before the parallel recurrent computation, so the pre up-projection does not introduce any sequential bottleneck.

In summary, the block assignment respects the structural requirements of each memory type: the sLSTM's memory mixing constrains it to operate in the original space with post up-projection, while the mLSTM's lack of memory mixing and its matrix memory structure make it ideal for pre up-projection, which maximizes memory capacity.

# Non-Linear Summarization of the Past in High-Dimensional Space

Both xLSTM block types share the common goal of non-linearly summarizing the past in a high-dimensional space, but they achieve this goal through different orderings of operations. Understanding what "non-linear summarization of the past" means is essential for grasping the xLSTM architecture.

The "past" in a sequence model refers to all the information from previous time steps that is relevant for predicting future elements. In an autoregressive language model, for example, the past consists of all preceding tokens, and the model must use this context to predict the next token. The recurrent memory cells (sLSTM or mLSTM) are the mechanisms that accumulate and store this information over time. The cell state at time $t$ contains a summary of the sequence up to that point.

The term "non-linear summarization" refers to the fact that the recurrent memory operation involves non-linear transformations. In both sLSTM and mLSTM, the input and forget gates use exponential or sigmoid activation functions, and the cell input and output involve non-linear activation functions such as $\tanh$. These non-linearities allow the model to selectively store, forget, and retrieve information, creating a compressed, non-linear representation of the entire sequence history.

The "high-dimensional space" is introduced through the up-projection step. In both block types, the representation is mapped to a space of higher dimensionality than the model's base dimension. Cover's Theorem tells us that this high-dimensional non-linear embedding improves the separability of different histories, which is crucial for making accurate predictions. In the post up-projection block, the high-dimensional non-linear transformation is applied as a feed-forward network after the sLSTM has summarized the past in the original space. In the pre up-projection block, the mLSTM itself performs the non-linear summarization directly in the high-dimensional space, leveraging the increased dimensionality for greater memory capacity.

The interplay between the recurrent memory and the high-dimensional projection is what gives xLSTM blocks their power. The recurrent memory provides the ability to accumulate information over long sequences, while the high-dimensional projection provides the representational capacity to distinguish between different histories and extract meaningful features for prediction.

# Pre-LayerNorm Residual Backbones as Used in Contemporary LLMs

The xLSTM architecture relies on pre-LayerNorm residual backbones, which are the standard architectural pattern used in contemporary Large Language Models. LayerNorm, short for Layer Normalization, is a technique that normalizes the activations of a layer across the feature dimension, helping to stabilize training by reducing internal covariate shift. The "pre" in pre-LayerNorm indicates that the normalization is applied before the main transformation of each block, rather than after.

In a pre-LayerNorm residual backbone, each residual block receives its input, applies LayerNorm to the input, processes the normalized input through the block's main transformation (either the sLSTM or mLSTM memory operation, followed by the appropriate projection), and then adds the result to the original un-normalized input through a residual connection. This can be described as follows: if the input to a block is $\mathbf{x}$, the output is $\mathbf{x} + \text{Block}(\text{LayerNorm}(\mathbf{x}))$, where $\text{Block}$ represents the main computation of the block. The residual connection ensures that the gradient can flow directly through the network, mitigating the vanishing gradient problem in deep networks and enabling the construction of architectures with many layers.

The choice of pre-LayerNorm over post-LayerNorm is significant. Post-LayerNorm, where normalization is applied after the block's transformation and before the residual addition, was used in the original Transformer architecture. However, pre-LayerNorm has been found to be more stable for training very deep models, particularly at large scale. Since xLSTM is designed to be scaled to billions of parameters, comparable to modern Large Language Models, the use of pre-LayerNorm is a natural and pragmatic choice that aligns with established best practices in the field. The paper explicitly states that the xLSTM architecture relies on "the most commonly used pre-LayerNorm residual backbones as used in contemporary Large Language Models."

# Residual Stacking of xLSTM Blocks

An xLSTM architecture is constructed by residually stacking multiple xLSTM blocks on top of one another. The concept of residual stacking builds on the residual connection framework introduced by ResNet, where each layer's output is added to its input, allowing the network to learn residual functions rather than full transformations. This approach has been instrumental in enabling the training of very deep neural networks, including both deep convolutional networks and Transformers.

In the xLSTM architecture, the stacking works as follows. The input sequence is first embedded into a continuous representation. This representation is then passed through a series of xLSTM blocks, each of which is a residual block containing either an sLSTM (with post up-projection) or an mLSTM (with pre up-projection). Each block applies its pre-LayerNorm, processes the normalized input through its memory operation and projection, and adds the result to the input via a residual connection. The output of one block becomes the input to the next block. After passing through all blocks, the final representation is used to produce predictions, such as logits over a vocabulary for next-token prediction.

The depth of the stack—that is, the number of xLSTM blocks—is a key architectural hyperparameter that determines the model's capacity. Deeper stacks allow the model to learn more complex transformations and abstractions, but they also increase the computational cost and the risk of training instability. The residual connections and pre-LayerNorm are essential for making deep stacks trainable, as they ensure stable gradient flow and activation magnitudes throughout the network.

The paper draws an explicit parallel to the construction of other large deep learning models, noting that "like almost all contemporary large deep learning models, xLSTM architectures are constructed by residually stacking building blocks." This construction principle enabled the success of deep convolutional networks like ResNet and of Transformers, which are the backbone of modern Large Language Models such as GPT-3, ChatGPT, GPT-4, Llama, and many others. By adopting the same construction principle, xLSTM ensures that it can benefit from the same training stability and scaling properties that have made these models successful.

# Notation: xLSTM[$a$:$b$] for Ratio of mLSTM to sLSTM Blocks

An xLSTM architecture typically contains a mixture of mLSTM-based and sLSTM-based blocks. To describe the composition of a particular architecture, the paper introduces the notation xLSTM[$a$:$b$], where $a/b$ denotes the ratio of mLSTM-based blocks to sLSTM-based blocks. For example, xLSTM[7:1] means that out of every eight blocks, seven are mLSTM-based blocks and one is an sLSTM-based block. For a model with a total of 48 blocks, this ratio translates to 42 mLSTM-based blocks and 6 sLSTM-based blocks.

This notation is important because the two types of blocks serve complementary roles. The mLSTM-based blocks provide large memory capacity through their matrix memory and are fully parallelizable, making them efficient for training and inference. The sLSTM-based blocks provide memory mixing, which enables state tracking—the ability to solve problems that require tracking the internal state of a process, such as evaluating code or tracking entities in a long narrative. State tracking is a capability that models without memory mixing, such as Transformers and State Space Models, fundamentally lack. By mixing both types of blocks, xLSTM architectures combine the strengths of both: the memory capacity and parallelizability of mLSTM, and the state tracking ability of sLSTM.

The notation also encompasses the extreme cases. xLSTM[1:0] denotes an architecture composed entirely of mLSTM-based blocks, with no sLSTM blocks. xLSTM[0:1] denotes an architecture composed entirely of sLSTM-based blocks, with no mLSTM blocks. These extreme cases are useful for ablation studies and for understanding the individual contributions of each block type.

# Architecture Design Considerations and Block Placement

The design of xLSTM architectures involves several considerations that guide the placement and ratio of mLSTM and sLSTM blocks within the residual stack. The paper establishes several key principles.

First, all experiments described in the paper use pre up-projection blocks for mLSTM and post up-projection blocks for sLSTM. This consistent assignment ensures that each block type is always paired with the projection strategy that best suits its memory structure, as discussed earlier. The mLSTM always benefits from the enlarged memory capacity of the high-dimensional space, while the sLSTM always retains its memory mixing in the original space.

Second, the ratio of mLSTM to sLSTM blocks is a design choice that balances parallelizability and memory capacity against state tracking capability. Since sLSTM blocks are not parallelizable due to memory mixing, they introduce a sequential processing bottleneck. A higher proportion of mLSTM blocks improves training and inference efficiency, while a higher proportion of sLSTM blocks enhances the model's state tracking ability. The xLSTM[7:1] ratio, used in many of the paper's experiments, represents a design that is heavily weighted toward the parallelizable mLSTM while still incorporating enough sLSTM blocks to provide state tracking capabilities.

Third, the overall depth and width of the architecture are determined by the target model size. The paper trains models ranging from 125M to 1.3B parameters, with architectures that match GPT-3 models in size—for example, a model with embedding dimension 1024 and 24 residual blocks. The number of blocks, the model dimension, and the up-projection factor all contribute to the total parameter count and must be balanced to achieve the desired model size while maintaining training stability.

Fourth, the initialization of forget gates must be chosen carefully, as noted in the paper's discussion of limitations. Since the forget gate controls how much of the past memory is retained, its initial value can significantly affect training dynamics, especially in the early stages. This is a practical consideration that must be addressed when designing and training xLSTM architectures.

Finally, the paper notes that the architecture and hyperparameters were not fully optimized, particularly for larger xLSTM architectures, due to the expensive computational load of large language experiments. This suggests that there is room for improvement in architecture design through more extensive optimization, and that the current results likely represent a lower bound on xLSTM's potential performance. The scaling laws observed in the experiments indicate that larger xLSTM models will continue to perform favorably compared to Transformers and State Space Models, making further architecture optimization a promising direction for future work.

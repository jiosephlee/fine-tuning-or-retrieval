## The Vanishing Gradient Problem in Recurrent Neural Networks

To understand why Long Short-Term Memory (LSTM) networks were invented, we must first confront a fundamental obstacle that plagued early recurrent neural networks (RNNs): the vanishing gradient problem. When training an RNN using gradient-based methods, the network must propagate error signals backward through time across many sequential steps. Each step multiplies the gradient by a factor related to the recurrent weights and activation function derivatives. When sequences are long, these repeated multiplications cause the gradient to either shrink exponentially toward zero (vanishing) or grow exponentially toward infinity (exploding). The vanishing gradient problem is especially insidious because it prevents the network from learning dependencies between distant elements in a sequence. An RNN that cannot propagate gradients across hundreds of time steps simply cannot learn to associate a word at the beginning of a paragraph with a word at the end. The network's ability to store and retrieve information over long timescales is fundamentally compromised.

This problem was identified and analyzed in the early 1990s by Hochreiter, who formalized the diagnosis of vanishing gradients in recurrent networks. The core mathematical issue is that if a recurrent connection has a weight with magnitude less than one, repeated application of that weight across time steps causes the gradient signal to decay exponentially. If the weight has magnitude greater than one, the signal explodes. Maintaining gradients at a useful magnitude across long sequences requires a mechanism that does not rely on repeated multiplication by potentially small or large factors. This insight directly motivated the design of the LSTM, which introduced a structural solution to the vanishing gradient problem rather than relying on careful initialization or clipping strategies.

#

## The Core LSTM Ideas: Constant Error Carousel and Gating

The LSTM solved the vanishing gradient problem through two interlocking ideas: the constant error carousel and gating. The constant error carousel is the central mechanism by which information persists across time steps through an additive update rather than a multiplicative one. The core update equation of the LSTM is:

$$c_t = f_t \, c_{t-1} + i_t \, z_t, \quad h_t = o_t \, \psi(c_t)$$

Here, $c_t$ is the cell state at time step $t$, which serves as the network's memory. The cell state is updated additively: the previous cell state $c_{t-1}$ is scaled by the forget gate $f_t$ and added to the cell input $z_t$ scaled by the input gate $i_t$. The hidden state $h_t$ is then derived from the cell state by applying a squashing function $\psi$ and modulating the result with the output gate $o_t$. The crucial insight is that the gradient flowing through $c_t$ to $c_{t-1}$ passes through a simple additive pathway. When the forget gate $f_t$ is close to one, the gradient flows backward through time with minimal attenuation, creating what is called a constant error carousel: the error signal circulates through the recurrent structure without being multiplied by potentially vanishing factors at each step.

Gating is the second essential idea. The three gates—input, forget, and output—control the flow of information into, out of, and within the memory cell. Each gate is computed as a sigmoid activation, $\sigma(x) = 1/(1+\exp(-x))$, which produces values between zero and one. The input gate $i_t$ determines how much of the new input $z_t$ is written into the cell state. The forget gate $f_t$ determines how much of the previous cell state $c_{t-1}$ is retained. The output gate $o_t$ determines how much of the cell state is exposed as the hidden state. The cell input $z_t$ is itself a transformed version of the input $\mathbf{x}_t$ combined with the previous hidden state $h_{t-1}$, passed through an activation function $\varphi$ (typically $\tanh$). Together, these gates give the LSTM the ability to selectively store, maintain, and retrieve information over arbitrarily long time spans, which is precisely what vanilla RNNs could not do.

The forget gate was a later addition to the original LSTM formulation, introduced by Gers and colleagues. Without a forget gate, the cell state could only accumulate information, with no mechanism for resetting or selectively discarding outdated content. The forget gate provides a principled way for the network to learn when to clear its memory, which is essential for tasks where context changes and old information becomes irrelevant. The full set of LSTM update equations includes pre-activations for each gate, each computed as a linear combination of the input $\mathbf{x}_t$, the previous hidden state $h_{t-1}$, and a bias term, followed by the appropriate activation function. This structure—input, forget, and output gates controlling a scalar memory cell—became the standard LSTM formulation and has remained largely unchanged for over two decades.

## Historical Successes of LSTMs

Since their introduction in the 1990s, LSTMs have been applied to an extraordinary range of domains and have achieved remarkable successes across many of them. In text generation, LSTMs demonstrated the ability to produce coherent passages of text character by character, learning not only statistical regularities but also syntactic and semantic structure. In handwriting generation, LSTMs produced realistic handwritten sequences that captured the stylistic variations of human writing. These early demonstrations were compelling evidence that gated recurrent architectures could model complex sequential data with long-range dependencies.

One of the most impactful applications of LSTMs was in sequence-to-sequence machine translation. The encoder-decoder architecture, in which an LSTM encodes a source sentence into a fixed-length vector and another LSTM decodes that vector into a target sentence, became the dominant approach to translation before the Transformer era. This architecture demonstrated that LSTMs could capture the meaning of an entire sentence in their memory cells and then generate a translation in another language, a task that requires understanding long-range syntactic and semantic relationships. LSTMs were also applied to evaluating computer programs, where they processed source code character by character and learned to predict or assess program properties.

Beyond language, LSTMs were used for image captioning, where they generated textual descriptions of images by processing visual features extracted by convolutional networks. In hydrology, LSTMs were employed for rainfall-runoff modeling and flooding warning systems, where they processed time series of meteorological measurements to predict river discharge. These applications demonstrated that LSTMs were not limited to text but could handle any sequential data with complex temporal dependencies.

In reinforcement learning, LSTMs achieved some of the most impressive results in the field. The AlphaStar model, which played StarCraft II at grandmaster level, used LSTM-based architectures to process the long histories of game states that are essential for strategic decision-making. Similarly, the OpenAI Five model for Dota 2 relied on LSTMs to maintain context over the course of matches that could last tens of minutes. LSTMs were also used in the magnetic controller for nuclear fusion, where they controlled plasma in a tokamak reactor. These reinforcement learning applications highlighted a key strength of LSTMs: their ability to maintain relevant information over very long horizons and to use that information for sequential decision-making under uncertainty. LSTMs have stood the test of time and remain in use for highly relevant applications even as Transformers have dominated other domains.

## LSTM's Ability to Learn Abstractions

One of the most fascinating properties of LSTMs is their ability to learn abstractions—that is, to extract semantic information from sequential data and store it in their memory cells in structured, interpretable ways. This capability was revealed through analyses of trained LSTM models, which showed that individual memory cells developed specialized roles corresponding to meaningful linguistic and semantic concepts.

Number neurons were identified in LSTM language models, cells that specifically tracked numerical quantities in text. When processing a sequence containing numbers, these neurons would activate in patterns that reflected the numerical values, suggesting that the LSTM had learned to represent numeric information distinctly from other types of content. Syntax neurons were another discovery: cells that tracked syntactic structures such as whether a clause was open or closed, or whether a particular grammatical construction was in progress. These neurons effectively served as a stack or counter, maintaining syntactic state across long stretches of text.

Linguistic neurons extended this finding further, with individual cells responding to higher-level linguistic features such as topic, register, or discourse structure. Sentiment neurons were perhaps the most striking discovery: individual cells in LSTM language models were found to encode the emotional valence of text, with their activation levels correlating strongly with whether the input expressed positive or negative sentiment. Remarkably, these sentiment neurons emerged without any explicit supervision for sentiment; they arose simply from training on the next-token prediction objective. This finding demonstrated that LSTMs were not merely memorizing surface statistics but were learning to extract and represent abstract semantic properties of their input.

This capacity for abstraction is a fundamental reason why LSTMs remained competitive for so long and why they are worth revisiting. The ability to compress semantic information into scalar memory cells and to maintain that information over long sequences is a powerful form of inductive bias. The discovery of interpretable, functionally specialized neurons within LSTM models suggests that the architecture's design—gating, additive updates, and scalar memory—is well-suited to learning the kinds of abstractions that underlie language understanding and other cognitive tasks. This property motivates the question of whether the LSTM architecture, when extended and scaled, can recapture ground that has been lost to Transformers.

## Limitation 1: Inability to Revise Storage Decisions

Despite their many successes, LSTMs suffer from three main limitations that have constrained their applicability at scale. The first limitation is the inability to revise storage decisions. Once the LSTM has written information into its cell state, it cannot easily overwrite or revise that information when newer, more relevant information arrives. This problem stems from the use of sigmoid gates, which produce values in the range $(0, 1)$. When the input gate and forget gate use sigmoid activations, the update to the cell state is always a convex combination of the previous state and the new input. If the forget gate is close to one and the input gate is close to zero, the cell state barely changes. If the forget gate is small, the previous state is largely erased, but there is no mechanism for the gate to "decisively" select new information over old information in a way that reflects strong preferences.

This limitation is exemplified by the Nearest Neighbor Search problem. In this task, a reference vector is provided, and a sequence of vectors must be scanned sequentially to find the vector most similar to the reference. At the end of the sequence, the model must output the value attached to the most similar vector. The challenge is that as the model scans the sequence, it may encounter a vector that is quite similar to the reference and store the corresponding value. Later, it may encounter an even more similar vector, but the LSTM struggles to revise its stored value. The sigmoid gates make it difficult to decisively overwrite the previously stored value, because the gate values are bounded and the update is a smooth interpolation rather than a sharp replacement. The mean squared error of a standard LSTM on this task remains high, indicating that it cannot effectively revise its storage decisions.

The xLSTM addresses this limitation through exponential gating. By replacing the sigmoid activation with an exponential activation for the input and forget gates, the gates can take values much larger than one, allowing the network to decisively overwrite old information with new information. The exponential function $\exp(\tilde{i}_t)$ is unbounded above, which means the input gate can amplify the new input to any degree, effectively allowing the network to say "this new information is much more important than what I had before" and to replace the old cell state content accordingly. This is a fundamental change to the gating mechanism that directly addresses the first limitation of the original LSTM.

## Limitation 2: Limited Storage Capacities Due to Scalar Cell States

The second limitation of LSTMs is limited storage capacities. In the original LSTM, the cell state is a scalar $c \in \mathbb{R}$. Even when multiple scalar cells are combined into a vector $\mathbf{c}_t \in \mathbb{R}^d$, each individual cell can only store a single number. This means that all information must be compressed into scalar values, which severely limits the amount and complexity of information that can be stored. For many tasks, this is not a problem because the relevant information can be adequately represented as a small number of scalar quantities. But for tasks that require storing rich, structured information—such as the association between multiple keys and their corresponding values—scalar memory is insufficient.

This limitation is exemplified by the Rare Token Prediction problem. When evaluated on Wikitext-103, LSTMs perform worse on tokens that appear rarely in the training data. The perplexity of token prediction is higher for rare tokens than for frequent ones, because the LSTM's scalar memory cells cannot store enough information to distinguish and recall rare tokens. A rare token requires the network to maintain a specific representation that differentiates it from all other tokens, but scalar memory cells have limited capacity for such fine-grained distinctions. The more tokens the model needs to distinguish, the more information must be compressed into each scalar cell, and eventually the capacity is exhausted.

The xLSTM addresses this limitation by introducing a matrix memory for the mLSTM variant. Instead of a scalar cell state $c \in \mathbb{R}$, the mLSTM uses a matrix $\mathbf{C} \in \mathbb{R}^{d \times d}$, which dramatically increases the storage capacity. The matrix memory is updated using a covariance (outer product) rule, where key-value pairs are stored as outer products $\mathbf{v}_t \mathbf{k}_t^\top$. Retrieval is performed by multiplying the query vector $\mathbf{q}_t$ with the matrix memory, which allows the network to retrieve stored values based on similarity between the query and stored keys. This matrix memory structure, inspired by Bidirectional Associative Memories and Fast Weight Programmers, provides exponentially more storage capacity than scalar cells, enabling the model to handle rare tokens and complex associative recall tasks that are beyond the reach of the original LSTM.

#

## Limitation 3: Lack of Parallelizability Due to Memory Mixing

The third limitation of LSTMs is the lack of parallelizability, which arises from memory mixing. In the LSTM, the hidden state $h_{t-1}$ from the previous time step is used as input to the computation of the cell input, gates, and hidden state at the current time step $t$. These hidden-hidden recurrent connections create a sequential dependency: the computation at time step $t$ cannot proceed until the computation at time step $t-1$ is complete. This means that processing a sequence of length $N$ requires $N$ sequential computational steps, regardless of the amount of parallel hardware available. This is in stark contrast to the Transformer, where self-attention can be computed in parallel across all positions in a sequence.

Memory mixing refers specifically to the recurrent connections from the hidden state vector $\mathbf{h}$ to the cell inputs and gates through recurrent weight matrices $\mathbf{R}_z$, $\mathbf{R}_i$, $\mathbf{R}_f$, and $\mathbf{R}_o$. These matrices mix the outputs of different memory cells across time steps, allowing information stored in one cell to influence the updates of other cells. While memory mixing enhances the expressiveness of the model—it enables the LSTM to solve state tracking problems that are beyond the reach of models without recurrent hidden connections—it fundamentally prevents parallelization. The sequential dependency chain created by these connections means that the entire sequence must be processed one step at a time.

The xLSTM addresses this limitation differently for its two variants. The sLSTM retains memory mixing and therefore remains sequential, but a fast CUDA implementation with GPU memory optimizations brings its speed to within a factor of two of the parallel mLSTM. The mLSTM, on the other hand, abandons memory mixing entirely. By removing the hidden-hidden recurrent connections, the mLSTM's recurrence can be reformulated into a parallel version, analogous to how FlashAttention enables parallel computation of attention. The mLSTM uses input-dependent gates that depend only on the current input $\mathbf{x}_t$, not on the previous hidden state, which breaks the sequential dependency chain and allows the recurrence to be computed in parallel across time steps. This design choice trades the expressiveness gained from memory mixing for the computational efficiency gained from parallelization, and the xLSTM architecture compensates for this trade-off by combining both sLSTM and mLSTM blocks.

## The Rise of Transformers and the Research Question

The three limitations of LSTMs—inability to revise storage decisions, limited storage capacities, and lack of parallelizability—created an opening for alternative architectures. The Transformer, introduced in 2017, addressed the parallelizability limitation directly through its self-attention mechanism, which computes interactions between all pairs of positions in a sequence simultaneously. This parallelizable computation meant that Transformers could be trained on modern hardware (GPUs and TPUs) far more efficiently than LSTMs, which was a decisive advantage as model sizes grew into the billions of parameters. The Transformer's self-attention also provided a form of associative memory: each position could attend to any other position, effectively providing direct access to all past information without the need to compress it into a fixed-size hidden state. This addressed, at least partially, the storage capacity limitation of LSTMs.

The success of Transformers was rapid and comprehensive. They replaced LSTMs in machine translation, then in language modeling, and eventually became the foundation of all major Large Language Models, including GPT-3, ChatGPT, GPT-4, Llama, PaLM, Chinchilla, and many others. The scalability of Transformers—their ability to be trained efficiently at massive scale on modern hardware—was the key factor in their dominance. LSTMs, despite their historical successes and their ability to learn abstractions, were left behind because they could not be trained as efficiently at scale.

This raises a simple but profound question: How far do we get in language modeling when scaling LSTMs to billions of parameters, leveraging the latest techniques from modern LLMs, but mitigating the known limitations of LSTMs? The xLSTM paper sets out to answer this question by introducing two key modifications to the LSTM: exponential gating with appropriate normalization and stabilization techniques, and modified memory structures. The sLSTM retains the scalar memory and scalar update of the original LSTM but adds exponential gating and a new form of memory mixing through multiple heads. The mLSTM introduces a matrix memory with a covariance update rule, enabling much larger storage capacity and full parallelizability. By integrating these extensions into residual block backbones and stacking them into architectures, the xLSTM aims to demonstrate that the LSTM architecture, properly modernized, can compete with state-of-the-art Transformers and State Space Models in both performance and scaling behavior. The experiments in the paper—ranging from synthetic tasks to large-scale language modeling on 300B tokens—provide evidence that the answer to the research question is at least as encouraging as "at least as far as current technologies like Transformers or State Space Models."

\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### How does exponential gating enable storage revision in xLSTM?
Question:
I'm reading the xLSTM paper and they claim that exponential gating allows LSTMs to "revise storage decisions," which they demonstrate via a Nearest Neighbor Search problem. However, I don't understand the mechanism. With sigmoid gates, values are in $[0,1]$, but with exponential gates, values can exceed 1. How does having gate values greater than 1 enable revision of previously stored values? The forget gate already controls what is forgotten — why is that not sufficient for revision? Is there something about the scale of exponential gates that allows overwriting?
Answer:
The key to understanding how exponential gating enables storage revision lies in the interaction between the input gate and the **normalizer state** introduced in sLSTM. The normalizer transforms the cell state into a proper weighted average, and exponential gating allows new inputs to dominate that average completely.

Consider the sLSTM cell state and normalizer state:

$$c_t = f_t \, c_{t-1} + i_t \, z_t$$

$$n_t = f_t \, n_{t-1} + i_t$$

The normalized hidden state is $\tilde{h}_t = c_t / n_t$, which can be rewritten as:

$$\tilde{h}_t = \frac{f_t \, n_{t-1}}{f_t \, n_{t-1} + i_t} \cdot \tilde{h}_{t-1} + \frac{i_t}{f_t \, n_{t-1} + i_t} \cdot z_t$$

This is a weighted average of the previous output $\tilde{h}_{t-1}$ and the new candidate $z_t$, with the weight on the new input being:

$$w_{\text{new}} = \frac{i_t}{f_t \, n_{t-1} + i_t}$$

This is the crux. The normalizer state $n_{t-1}$ accumulates the sum of all past gate products across the sequence. After processing many tokens, $n_{t-1}$ can be large. With **sigmoid** gates, $i_t \leq 1$, so $w_{\text{new}} \leq \frac{1}{f_t \, n_{t-1} + 1}$, which is strictly less than 1 and can be very small if $n_{t-1}$ is large. The model literally cannot assign enough weight to the new value to fully overwrite the old one — it can only blend them. In the Nearest Neighbor Search problem, this means the LSTM can only partially mix in a newly found similar vector's value rather than cleanly replacing the old one.

With **exponential** gating, $i_t = \exp(\tilde{i}_t) \in (0, \infty)$, so:

$$w_{\text{new}} = \frac{i_t}{f_t \, n_{t-1} + i_t} = \frac{1}{\frac{f_t \, n_{t-1}}{i_t} + 1} \;\to\; 1 \quad \text{as } i_t \to \infty$$

The new input can be made to dominate the weighted average completely, regardless of how large the accumulated normalizer $n_{t-1}$ is. This is what enables clean revision: when the model encounters a more similar vector later in the sequence, it can produce a large enough $i_t$ to effectively replace the previously stored value.

The forget gate alone is insufficient for two reasons. First, sigmoid never reaches zero, so $f_t > 0$ always leaves some residual contribution from the past. Second, and more fundamentally, revision is not just about erasure — it requires *strong writing*. Even if $f_t$ is near zero, the new write strength $i_t$ is capped at 1 with sigmoid, which may be negligible compared to the accumulated $n_{t-1}$. The ratio $i_t / (f_t \, n_{t-1})$ determines how much the new value dominates, and with bounded gates this ratio cannot be made large enough after long sequences. Exponential gating breaks this ceiling.

There is also an optimization perspective. The sigmoid gradient $\sigma'(x) = \sigma(x)(1 - \sigma(x))$ vanishes at the extremes, making it difficult for gradient descent to learn the near-0 forget gate values and near-1 input gate values needed for revision. The exponential gradient $\exp'(x) = \exp(x)$ grows with the gate value, providing strong gradient signal precisely when the model needs to make large revisions. This makes the revision behavior easier to learn during training, not just possible in principle.

### What is the normalizer state in sLSTM/mLSTM and is it related to layer normalization?
Question:
In the xLSTM paper, both sLSTM and mLSTM introduce a "normalizer state" $n_t$ that evolves as $n_t = f_t n_{t-1} + i_t$, and the hidden state is computed as $\tilde{h}_t = c_t / n_t$. The paper says it "keeps record of the strength of the gates," but I'm confused about its purpose. Is this just a form of normalization like layer norm or batch norm? What would go wrong if we simply used $\tilde{h}_t = c_t$ without dividing by $n_t$? Why is this particular normalization necessary specifically when using exponential gates?
Answer:
The normalizer state $n_t$ is not a form of layer normalization or batch normalization. It is a recurrent state that evolves alongside the cell state and serves a fundamentally different purpose: it prevents the cell state from growing unboundedly when exponential gates are used.

To understand why it is necessary, consider what changes when moving from the original LSTM to xLSTM. In the original LSTM, the input and forget gates use sigmoid activations, so $i_t \in [0,1]$ and $f_t \in [0,1]$. The cell state update $c_t = f_t c_{t-1} + i_t z_t$ is therefore naturally bounded, since each gate attenuates its corresponding term. A squashing function $\psi$ (typically $\tanh$) is then applied to keep the hidden state in a bounded range.

With exponential gating, the gates become $i_t = \exp(\tilde{i}_t)$ and $f_t = \exp(\tilde{f}_t)$, which can take any positive value, including values greater than 1. If the forget gate is, say, 2, then at each time step the previous cell state is doubled. Over many steps, the cell state grows exponentially. Applying a $\tanh$ to an exponentially large cell state would saturate it to $\pm 1$ for virtually all inputs, destroying the ability to distinguish between different stored values. The model would lose its capacity to revise storage decisions, which is precisely the limitation that exponential gating was introduced to overcome.

The normalizer state $n_t = f_t n_{t-1} + i_t$ tracks the accumulated strength of the gates over time. It undergoes the same multiplicative scaling as the cell state, so dividing $\tilde{h}_t = c_t / n_t$ cancels out the gate-driven growth. Intuitively, $c_t$ is a running weighted sum of the cell inputs $z_\tau$ (each weighted by the input gate at time $\tau$ and the product of all forget gates between $\tau$ and $t$), while $n_t$ is the running sum of those same weights without the $z_\tau$ factor. The ratio $c_t / n_t$ is therefore a weighted average of past inputs, which remains bounded regardless of how large the individual gates become.

If you simply used $\tilde{h}_t = c_t$ without the normalizer, the cell state would blow up exponentially whenever the gates exceeded 1, making training unstable and rendering the squashing function useless due to saturation. The normalizer state provides an adaptive, input-dependent rescaling that grows and shrinks with the gate activations, keeping the effective hidden state in a workable range.

In the mLSTM, the same principle applies but in the matrix memory setting. The cell state $\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top$ accumulates key-value outer products weighted by gates, and the normalizer state $\mathbf{n}_t = f_t \mathbf{n}_{t-1} + i_t \mathbf{k}_t$ accumulates the key vectors with the same gating. The hidden state $\tilde{\mathbf{h}}_t = \mathbf{C}_t \mathbf{q}_t / \max(|\mathbf{n}_t^\top \mathbf{q}_t|, 1)$ normalizes the retrieved vector by the dot product of the query with the accumulated, gate-weighted keys. This is analogous to the denominator in softmax attention: without it, the retrieval would be an unbounded weighted sum rather than a properly normalized retrieval. The $\max(\cdot, 1)$ lower bound prevents division by near-zero values when the query and normalizer state are nearly orthogonal.

The broader concept here is that when you replace bounded activation functions (sigmoid) with unbounded ones (exponential), you need a corresponding normalization mechanism to maintain numerical stability. This pattern appears across modern sequence models. In linear attention and its variants, a similar normalization denominator appears to convert an unbounded kernel sum into a proper weighted average. The xLSTM normalizer state is the recurrent analog of that denominator, adapted to the sequential gate structure of the LSTM.

### How does the stabilizer state in sLSTM preserve mathematical equivalence?
Question:
The xLSTM paper introduces a stabilizer state $m_t = \max(\log(f_t) + m_{t-1}, \log(i_t))$ and uses stabilized gates $i'_t = \exp(\tilde{i}_t - m_t)$ and $f'_t = \exp(\log(f_t) + m_{t-1} - m_t)$. The paper claims that replacing $f_t$ with $f'_t$ and $i_t$ with $i'_t$ in the forward pass "does neither change the output of the whole network nor the derivatives of the loss with respect to the parameters." How can subtracting $m_t$ from the gate values not change anything? It looks like the gates are being rescaled by $\exp(-m_t)$, which should change their values. What am I missing about why this is mathematically equivalent?
Answer:
The key insight is that the stabilizer rescales the cell state $c_t$ and the normalizer state $n_t$ by the *same* factor at every time step, so when the hidden state is computed as their ratio $\tilde{h}_t = c_t / n_t$, the scaling cancels out.

To see this, define $s_t = \exp(m_t)$. Then the stabilized gates can be rewritten as:

$$i'_t = \frac{i_t}{s_t}, \qquad f'_t = \frac{f_t \cdot s_{t-1}}{s_t}$$

Now suppose we run the stabilized forward pass, producing $c'_t$ and $n'_t$. Multiply both sides of the $c'$ update by $s_t$:

$$s_t \, c'_t = f_t \, s_{t-1} \, c'_{t-1} + i_t \, z_t$$

Defining $\hat{c}_t = s_t \, c'_t$, this becomes $\hat{c}_t = f_t \, \hat{c}_{t-1} + i_t \, z_t$, which is exactly the original cell state update. So $\hat{c}_t = c_t$, meaning $c'_t = c_t / s_t$. By the identical argument, $n'_t = n_t / s_t$. Therefore the hidden state is preserved:

$$\tilde{h}'_t = \frac{c'_t}{n'_t} = \frac{c_t / s_t}{n_t / s_t} = \frac{c_t}{n_t} = \tilde{h}_t$$

Since every hidden state $h_t = o_t \, \tilde{h}_t$ is identical to the unstabilized version, the network output and the loss as a function of the parameters are exactly the same. Consequently, the gradients with respect to the parameters must also be identical—the computation graph differs, but the function being differentiated does not.

Intuitively, this is the same principle behind the log-sum-exp trick used for numerical stability in softmax: you subtract the maximum logit before exponentiating to prevent overflow, and the normalization in the denominator ensures the result is unchanged. Here, the normalizer state $n_t$ plays that compensating role. The stabilizer $m_t$ tracks the running maximum of $\log(f_t) + m_{t-1}$ and $\log(i_t)$, ensuring that the stabilized gate values $i'_t$ and $f'_t$ are at most $1$, which prevents the exponential gates from overflowing while leaving the model's mathematical behavior completely unchanged.

### What exactly is "memory mixing" and why does it prevent parallelization in sLSTM?
Question:
The xLSTM paper repeatedly refers to "memory mixing" via "hidden-hidden connections" as the reason sLSTM cannot be parallelized, while mLSTM can be parallelized because it abandons memory mixing. I understand that traditional RNNs are sequential, but I'm confused about what specifically constitutes "memory mixing." Looking at the sLSTM equations, the recurrent weights $r_z, r_i, r_f, r_o$ connect $h_{t-1}$ to the current time step's gate computations. Is this what they mean by memory mixing? And in mLSTM, the gates only depend on the input $\mathbf{x}_t$ (no $h_{t-1}$ term) — is that why it can be parallelized? Could someone clarify the precise definition of memory mixing and why it creates a sequential dependency?
Answer:
"Memory mixing" in the xLSTM paper refers specifically to the **hidden-hidden recurrent connections** — the dependency of the current time step's gate computations on the previous time step's hidden state $h_{t-1}$. Your intuition is exactly right: in the sLSTM equations, the pre-activations for the cell input and all three gates include a term $r \cdot h_{t-1}$ (e.g., $\tilde{i}_t = \mathbf{w}_i^\top \mathbf{x}_t + r_i \, h_{t-1} + b_i$). This recurrent term is what the paper calls memory mixing, and it is the reason sLSTM cannot be parallelized across the time dimension.

The paper states this explicitly in the introduction, listing the third LSTM limitation as "lack of parallelizability due to memory mixing, i.e., the hidden-hidden connections between hidden states from one time step to the next, which enforce sequential processing." The term "mixing" captures the idea that the hidden state from the previous step — which is itself a complex non-linear function of the entire history of inputs — is mixed back into the computation of the current step's gates. Because $h_{t-1}$ depends on $h_{t-2}$, which depends on $h_{t-3}$, and so on, you have an unbreakable sequential chain: you cannot compute the gates at time $t$ until you have finished computing the full hidden state at time $t-1$.

In mLSTM, the situation is fundamentally different. All of the gate pre-activations and the key/query/value projections depend **only** on the current input $\mathbf{x}_t$ — there is no $h_{t-1}$ term anywhere. For example, $\tilde{i}_t = \mathbf{w}_i^\top \mathbf{x}_t + b_i$ and $\tilde{f}_t = \mathbf{w}_f^\top \mathbf{x}_t + b_f$. This means all gates for all time steps can be computed simultaneously in a single matrix multiplication over the entire input sequence. The only remaining recurrence is in the cell state and normalizer state ($\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top$ and $\mathbf{n}_t = f_t \mathbf{n}_{t-1} + i_t \mathbf{k}_t$). Crucially, since $f_t$ and $i_t$ are already known for all $t$ (they do not depend on any hidden state), this recurrence reduces to a **linear associative scan** — the same kind of parallelizable prefix-sum operation used in State Space Models like Mamba. The paper notes that this parallel formulation is "analogous to FlashAttention or GLA," referring to the chunkwise parallelization techniques used for linear attention.

The key insight is that it is not the mere *presence* of a recurrence that prevents parallelization — it is whether the recurrence's coefficients depend on data that is itself only available sequentially. In mLSTM, the recurrence coefficients $f_t$ and $i_t$ are input-only functions, so the recurrence is a simple scan. In sLSTM, the recurrence is "data-dependent" in a deeper sense: the coefficients (gates) at each step depend on $h_{t-1}$, which is a non-linear function of the entire preceding computation. This non-linear, state-dependent gating creates a dependency graph where each step genuinely requires the completed output of the previous step, with no way to restructure the computation into a parallel form.

The paper also mentions a second, related sense of memory mixing: when sLSTM has multiple memory cells, the recurrent weight matrices $\mathbf{R}_z, \mathbf{R}_i, \mathbf{R}_f, \mathbf{R}_o$ mix information *across cells* via the hidden state vector $\mathbf{h}_{t-1}$. This cross-cell mixing is an additional form that mLSTM explicitly abandons. The paper notes that "for mLSTM, multiple heads and multiple cells are equivalent as there is no memory mixing," meaning that without hidden-hidden connections, splitting into multiple cells or heads introduces no sequential interdependencies between them.

It is worth noting that the paper argues this is not purely a disadvantage. The Related Work section emphasizes that "memory mixing enables [solving] state tracking problems, and therefore LSTMs are more expressive than State Space Models (SSMs) and Transformers," citing results showing that models without memory mixing cannot solve tasks like parity or other regular grammar problems. So the xLSTM architecture retains some sLSTM blocks (with memory mixing) alongside the parallelizable mLSTM blocks, trading off some parallelism for greater expressivity — the notation xLSTM$[a:b]$ indicates the ratio of mLSTM to sLSTM blocks.

### How does mLSTM's matrix memory with covariance update relate to Transformer attention?
Question:
The mLSTM in the xLSTM paper uses query ($\mathbf{q}_t$), key ($\mathbf{k}_t$), and value ($\mathbf{v}_t$) vectors with a matrix memory updated via $\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top$ and retrieval via $\mathbf{C}_t \mathbf{q}_t$. This looks very similar to attention mechanisms in Transformers, where we compute $\text{softmax}(\mathbf{Q}\mathbf{K}^\top)\mathbf{V}$. Is mLSTM essentially performing attention in a recurrent framework? What are the key mathematical and functional differences between mLSTM's matrix memory retrieval and standard self-attention? Does the covariance update rule correspond to a particular form of attention?
Answer:
The mLSTM's matrix memory with covariance update is closely related to **linear attention** rather than standard softmax self-attention, and understanding this distinction clarifies both the mathematical connection and the functional differences.

**The Mathematical Connection**

To see the relationship, unroll the mLSTM cell state update over time. Setting the gates to unity ($f_\tau = 1$, $i_\tau = 1$) for a moment, the cell state becomes:

$$\mathbf{C}_t = \sum_{\tau=1}^{t} \mathbf{v}_\tau \mathbf{k}_\tau^\top$$

Retrieval at time $t$ via the query $\mathbf{q}_t$ then gives:

$$\mathbf{C}_t \mathbf{q}_t = \sum_{\tau=1}^{t} (\mathbf{k}_\tau^\top \mathbf{q}_t) \, \mathbf{v}_\tau$$

This is a weighted sum of past value vectors, where each weight is the dot product between the current query and a past key. This is precisely the form of **linear attention** (as in the Linear Transformer of Katharopoulos et al., 2020), where the softmax kernel is replaced by a simple linear inner product. The paper explicitly acknowledges this lineage, noting that the covariance update rule is equivalent to Fast Weight Programmers and listing the Linear Transformer among related work.

With the gates restored, the unrolled cell state becomes:

$$\mathbf{C}_t \mathbf{q}_t = \sum_{\tau=1}^{t} \left(\prod_{s=\tau+1}^{t} f_s\right) i_\tau \, (\mathbf{k}_\tau^\top \mathbf{q}_t) \, \mathbf{v}_\tau$$

The forget gate introduces exponential temporal decay (each $\prod f_s$ exponentially down-weights older memories), and the input gate controls how strongly each new key-value pair is written. Because the gates use exponential activation ($i_t = \exp(\tilde{i}_t)$, and optionally $f_t = \exp(\tilde{f}_t)$), they inject a form of nonlinearity into what would otherwise be a purely linear recurrence.

**Key Differences from Standard Self-Attention**

Standard Transformer self-attention computes, for a query at position $t$:

$$\text{softmax}(\mathbf{q}_t \mathbf{K}^\top) \mathbf{V} = \frac{\sum_{\tau} \exp(\mathbf{q}_t^\top \mathbf{k}_\tau) \mathbf{v}_\tau}{\sum_{\tau} \exp(\mathbf{q}_t^\top \mathbf{k}_\tau)}$$

Several important distinctions emerge:

1. **Nonlinearity in the similarity kernel.** Standard attention applies the exponential function *inside* the similarity computation (via softmax), creating a nonlinear mapping from key-query dot products to attention weights. mLSTM uses a linear dot product $\mathbf{k}_\tau^\top \mathbf{q}_t$ for retrieval, but applies exponential nonlinearity through the gates *outside* the similarity computation — the gates control storage and decay rather than the attention weight itself.

2. **Normalization.** Standard attention normalizes by the softmax denominator $\sum_\tau \exp(\mathbf{q}_t^\top \mathbf{k}_\tau)$. mLSTM normalizes by $\max\{|\mathbf{n}_t^\top \mathbf{q}_t|, 1\}$, where $\mathbf{n}_t = \sum_\tau (\prod f_s) i_\tau \mathbf{k}_\tau$ is a running normalizer state. This is a linearized approximation of the softmax normalizer — it sums the (gate-weighted) keys rather than their exponentials.

3. **Memory compression.** Standard attention stores all past key-value pairs explicitly, requiring $O(L \cdot d)$ memory for sequence length $L$. mLSTM compresses all past information into a single $d \times d$ matrix $\mathbf{C}_t$ and a $d$-dimensional normalizer $\mathbf{n}_t$, giving constant memory $O(d^2)$ regardless of sequence length. This is the fundamental trade-off: mLSTM achieves linear time and constant memory complexity but can lose information when the sequence exceeds what the matrix can faithfully store.

4. **Temporal decay and input gating.** The forget gate provides a mechanism for controlled forgetting that standard attention lacks. In a Transformer, every position within the context window is equally accessible with no built-in recency bias (aside from positional encodings). In mLSTM, older memories are exponentially decayed by the product of forget gates, creating an inductive bias toward recency while still allowing the network to learn to preserve important long-range information by setting $f_t \approx 1$.

5. **No memory mixing.** mLSTM removes the hidden-to-hidden recurrent connections present in the original LSTM (and retained in sLSTM). This is what enables parallelization — the recurrence over $\mathbf{C}_t$ is a linear recurrence that can be computed via associative scans, analogous to how FlashAttention parallelizes Transformer computation. Standard attention is also parallelizable but through direct matrix multiplication rather than scan-based parallelism.

**Does the Covariance Update Correspond to a Particular Form of Attention?**

Yes — it corresponds to **linear attention with exponential gating**. The covariance update $\mathbf{v}_t \mathbf{k}_t^\top$ stores an outer product that, when queried, produces the same associative retrieval as linear attention. The paper makes this connection explicit by noting that the covariance update rule "is equivalent to Fast Weight Programmers," which were subsequently connected to linearized attention. The mLSTM's contribution is integrating this into the LSTM gating framework, where the forget gate acts as a learned, position-dependent decay rate and the input gate acts as a learned, position-dependent learning rate — both with exponential activation for improved expressiveness over the sigmoid gates of the original LSTM.

In summary, mLSTM is best understood not as standard softmax attention in a recurrent framework, but as **gated linear attention**: it replaces the softmax kernel with a linear inner product (enabling the matrix memory compression), and replaces the implicit "store everything equally" behavior of attention with explicit exponential gates that control what is stored and how quickly it decays. This gives it the parallelizability and constant memory of linear attention variants while retaining the LSTM's gated memory control philosophy.

### Why does sLSTM use post up-projection while mLSTM uses pre up-projection?
Question:
The xLSTM paper states that sLSTM blocks use post up-projection (like Transformers) while mLSTM blocks use pre up-projection (like State Space Models). The justification given is that for mLSTM "the memory capacity becomes larger in the high-dimensional space," so the non-linear summarization should happen in the high-dimensional space. But why doesn't the same argument apply to sLSTM? If high-dimensional non-linear embedding helps separate histories (via Cover's Theorem), wouldn't both variants benefit from pre up-projection? What is it about the scalar vs. matrix memory that dictates different block architectures?
Answer:
The distinction between post and pre up-projection for sLSTM and mLSTM blocks comes down to a fundamental difference in how their memory structures interact with dimensionality, and how memory mixing affects computational cost.

**Scalar vs. Matrix Memory Capacity**

The mLSTM stores information in a matrix $\mathbf{C}_t \in \mathbb{R}^{d \times d}$ via the covariance update rule $\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top$. The storage capacity of this matrix memory scales with $d^2$: larger $d$ means more key-value associations can be stored and retrieved with higher separability. By using pre up-projection, the keys $\mathbf{k}_t$, values $\mathbf{v}_t$, and queries $\mathbf{q}_t$ all live in the high-dimensional space, so the matrix memory directly benefits from operating there. The paper's justification that "the memory capacity becomes larger in the high-dimensional space" is specific to this matrix structure—more dimensions give the outer product update rule more room to encode distinguishable patterns.

The sLSTM, by contrast, has a scalar memory $c_t = f_t c_{t-1} + i_t z_t$. Even if you up-project first, each memory cell still stores a single scalar value. The recurrent non-linear summarization—gating and mixing across cells—doesn't gain proportionally more storage capacity from being in a higher-dimensional space in the same way a matrix memory does. The scalar memory compresses information regardless of input dimensionality.

**Where the Non-Linear Summarization Happens**

Cover's Theorem does apply to both architectures, but the point is about *where* the non-linear summarization of the past should occur. For sLSTM, the recurrent dynamics (gating, memory mixing) constitute the non-linear summarization, and these happen in the original-dimensional space. The block then uses post up-projection—an MLP-style structure that maps to high dimensions, applies a non-linearity, and maps back—to provide the high-dimensional non-linear embedding that Cover's Theorem promises. This mirrors how Transformers achieve separation: the self-attention happens in the original space, and the MLP block provides the non-linear expansion.

For mLSTM, the recurrent dynamics *are* the matrix memory update and retrieval. If these operate in the high-dimensional space (via pre up-projection), the non-linear summarization itself benefits from the expanded dimensionality. The Cover's Theorem benefit is baked directly into the memory mechanism rather than deferred to a separate MLP.

**The Memory Mixing Constraint**

There's also a practical computational reason. The sLSTM has memory mixing—recurrent hidden-to-hidden connections via weight matrices $\mathbf{R}$. If you pre up-projected, these recurrent matrices would become $d_{\text{high}} \times d_{\text{high}}$, making the already-sequential sLSTM computation prohibitively expensive. The mLSTM has *no* memory mixing (this is precisely what enables its parallelization), so pre up-projection only affects the feed-forward input/output projections $\mathbf{W}_q, \mathbf{W}_k, \mathbf{W}_v$, which are not recurrent and thus don't incur this cost.

**Summary**

In short, the argument doesn't apply symmetrically because the two memory types interact with dimensionality differently. The mLSTM's matrix memory gains storage capacity from operating in higher dimensions, so the recurrent summarization should happen there. The sLSTM's scalar memory doesn't gain comparable capacity from higher dimensions, and its memory mixing would make pre up-projection computationally wasteful—so the high-dimensional non-linear embedding is instead provided by the post up-projection block structure, analogous to how Transformers separate the attention mechanism from the MLP.

### What is "state tracking" and why can't Transformers or State Space Models do it?
Question:
The xLSTM paper claims that models without memory mixing (like Transformers and SSMs) "cannot solve, e.g., regular grammars like the parity task" and cites work showing they are "fundamentally less powerful than RNNs." I'm confused about what "state tracking" means in this context. Is it about maintaining a discrete internal state across time steps? Why specifically does the lack of hidden-hidden recurrent connections prevent this? The paper mentions that state tracking is required for "evaluating code or tracking entities in a long narrative" — could someone give a concrete example of what state tracking looks like and why attention-based models fail at it?
Answer:
## What State Tracking Means and Why Memory Mixing Matters

State tracking refers to the ability of a model to maintain and update an internal state that depends on both the current input **and** the model's previous state — essentially implementing a form of finite-state machine within the neural network. The xLSTM paper highlights this property as a key distinction between architectures with "memory mixing" (hidden-hidden recurrent connections) and those without it, such as Transformers and State Space Models (SSMs).

### The Core Distinction: Memory Mixing

The critical architectural feature is whether the gates and memory updates can depend on the previous hidden state. In a traditional LSTM (and the paper's sLSTM), the gate computations include a recurrent term, e.g., the forget gate is computed as $\tilde{f}_t = \mathbf{w}_f^\top \mathbf{x}_t + r_f h_{t-1} + b_f$. The presence of $h_{t-1}$ means the model can use its own previous output to decide how to update its memory — the state update is **state-dependent**.

In contrast, the mLSTM (like Transformers and SSMs) lacks this recurrent dependency. Its gates are computed purely from the input: $\tilde{f}_t = \mathbf{w}_f^\top \mathbf{x}_t + b_f$. The memory update becomes a function of the input alone, not the model's internal state. The paper notes that models like Retention, RWKV, and HGRN2 similarly "do not allow memory mixing," which is precisely why they cannot perform state tracking.

### A Concrete Example: The Parity Task

Consider the parity task, which the paper explicitly mentions. Given a binary sequence, the model must output whether the count of 1s seen so far is even or odd. This is a regular language — the simplest class in the Chomsky hierarchy — and requires maintaining a single bit of state that flips each time a 1 is encountered.

To solve this, the model needs to know its **current state** (even or odd) in order to compute its **next state**. If the input is 1, the next state should be the opposite of the current state. Without memory mixing, the model has no mechanism to read its own current state when deciding how to update — the update rule is purely input-driven and cannot condition on the internal state. This is why the paper states that "Models such as Transformers or State Space Models without memory mixing (no state tracking) cannot solve, e.g. regular grammars like the parity task," citing theoretical results from Merrill (2024) and Deletang et al. (2023) showing these architectures are "fundamentally less powerful than RNNs."

### Broader Examples: Code Evaluation and Entity Tracking

The paper mentions that "state tracking is required to evaluate code or to track entities in a long narrative." 

For **code evaluation**, consider simulating a simple program with a counter variable. Each time a loop body executes, the counter increments. The model must read the counter's current value, increment it, and store the result. This is inherently state-dependent: the update depends on the previous value. A model without memory mixing cannot implement this read-modify-write cycle because it cannot condition its memory update on the current contents of that memory.

For **entity tracking in narratives**, imagine a story where a character moves between rooms. The model must maintain a representation of each character's current location and update it when a movement event occurs. The update ("Alice is now in the kitchen") depends on knowing who Alice is and that she was previously in the hallway — information that must be retrieved from the model's internal state, not just from the current input token.

### Why Attention-Based Models Fail

Transformers use content-based attention: they compute attention weights from query-key interactions and retrieve weighted averages of values. While this allows flexible retrieval over a context window, the update mechanism itself does not depend on the model's current internal state in a recurrent manner. The attention computation is a function of the input representations, not of a running state that evolves based on its own previous values. This is analogous to a lookup table rather than a state machine — you can retrieve information, but you cannot perform state-conditional updates where the update rule itself depends on what is currently stored.

The xLSTM paper's contribution through the sLSTM is to preserve this memory mixing capability (with the addition of exponential gating for improved expressiveness), while the mLSTM sacrifices it in exchange for parallelizability. The paper's experiments on formal language tasks (Section 3.1) demonstrate that architectures with memory mixing (LSTM, sLSTM) can solve state tracking tasks, while those without (Transformers, SSMs, mLSTM alone) cannot, confirming the theoretical predictions.

### Why is the absolute value and threshold used in mLSTM's normalization denominator?
Question:
In the mLSTM forward pass, the hidden state is computed as $\tilde{\mathbf{h}}_t = \mathbf{C}_t \mathbf{q}_t / \max\{|\mathbf{n}_t^\top \mathbf{q}_t|, 1\}$. I have two questions about this: (1) Why is the absolute value $|\mathbf{n}_t^\top \mathbf{q}_t|$ used rather than just $\mathbf{n}_t^\top \mathbf{q}_t$? The paper mentions the dot product "can be close to zero" — is the absolute value related to handling negative values from the covariance update? (2) Why lower bound the denominator by 1? What goes wrong if the denominator becomes very small?
Answer:
# Why the Absolute Value and Threshold in the mLSTM Normalization?

Both choices stem from a fundamental difference between the mLSTM normalizer and its sLSTM counterpart, and both serve to ensure numerical and semantic stability.

## The Core Issue: The Normalizer Can Be Negative

In the sLSTM, the normalizer state is a scalar $n_t = f_t n_{t-1} + i_t$, which is always positive since $i_t = \exp(\tilde{i}_t) > 0$ and $f_t \geq 0$. Division by a positive scalar is unproblematic. In the mLSTM, however, the normalizer is a **vector** $\mathbf{n}_t = f_t \mathbf{n}_{t-1} + i_t \mathbf{k}_t$, and the denominator of the hidden state is the dot product $\mathbf{n}_t^\top \mathbf{q}_t$. This dot product can be negative, zero, or positive.

To see why, expand the numerator and denominator as sums over past time steps. The numerator is:

$$\mathbf{C}_t \mathbf{q}_t = \sum_{\tau \leq t} \left(\prod_{s=\tau+1}^{t} f_s\right) i_\tau \, \mathbf{v}_\tau \, (\mathbf{k}_\tau^\top \mathbf{q}_t)$$

and the denominator is:

$$\mathbf{n}_t^\top \mathbf{q}_t = \sum_{\tau \leq t} \left(\prod_{s=\tau+1}^{t} f_s\right) i_\tau \, (\mathbf{k}_\tau^\top \mathbf{q}_t)$$

The normalization is meant to compute a **weighted average** of stored value vectors, analogous to how attention normalizes by the sum of attention weights. But unlike softmax attention weights, the individual terms $\mathbf{k}_\tau^\top \mathbf{q}_t$ here are unbounded dot products of zero-mean vectors (the paper assumes a layer-norm before projecting to keys and values), so they can be positive or negative. The sum can therefore be negative, or the positive and negative contributions can cancel to produce a value near zero.

**Why the absolute value?** If $\mathbf{n}_t^\top \mathbf{q}_t < 0$, dividing by it would **flip the direction** of the retrieved vector $\mathbf{C}_t \mathbf{q}_t$. That would mean a query that happens to be anti-aligned with the stored keys produces an output pointing in the *opposite* direction of the stored values — semantically nonsensical. The absolute value $|\mathbf{n}_t^\top \mathbf{q}_t|$ ensures the denominator is always non-negative, so the retrieved vector $\tilde{\mathbf{h}}_t$ always points in the same direction as $\mathbf{C}_t \mathbf{q}_t$, preserving the semantics of the retrieval. The sign information is effectively discarded because what matters for the hidden state is the *direction* of the retrieved value, not the sign of the normalizer.

## Why Lower-Bound the Denominator by 1?

When $\mathbf{n}_t^\top \mathbf{q}_t$ is close to zero — either because the query is nearly orthogonal to all stored keys, or because the normalizer state has decayed (e.g., early in a sequence or after strong forget-gate activity) — dividing by a near-zero value would cause the hidden state to **explode**. This produces arbitrarily large activations, which propagate through the network and can lead to NaNs during training, effectively destabilizing the entire model.

The $\max\{|\mathbf{n}_t^\top \mathbf{q}_t|,\, 1\}$ operation acts as a safeguard: when the normalizer dot product is large in magnitude, proper normalization occurs and the hidden state is a well-scaled weighted average. When the normalizer dot product drops below 1, the division is effectively bypassed (dividing by 1 is a no-op), and the raw retrieved vector $\mathbf{C}_t \mathbf{q}_t$ passes through without amplification. This prevents numerical blow-up while still allowing the model to produce a meaningful (if unnormalized) output.

The threshold value of 1 is a practical choice — the paper notes it is "typically 1.0" and cites Sun et al. (2023) (the Retention model) as having used the same technique. It is a reasonable default because the scale of the unnormalized numerator $\mathbf{C}_t \mathbf{q}_t$ is already controlled by the key scaling factor $1/\sqrt{d}$ applied to $\mathbf{k}_t$, so dividing by 1 rather than by a tiny fraction keeps the output at a manageable magnitude.

## Summary

The absolute value ensures the normalization never reverses the direction of the retrieved vector (which would happen with a negative denominator), and the lower bound of 1 prevents division by near-zero values that would cause numerical instability. Together, these two choices make the mLSTM's matrix-memory retrieval robust in the general case where query-key dot products are signed and can cancel, unlike the sLSTM where the scalar normalizer is guaranteed positive.

### What does the covariance update rule being "optimal for maximal separability" mean?
Question:
The xLSTM paper states that the covariance update rule $\mathbf{C}_t = \mathbf{C}_{t-1} + \mathbf{v}_t \mathbf{k}_t^\top$ is "optimal for a maximal separability of retrieved binary vectors, which is equivalent to a maximal signal/noise ratio." I don't understand what "separability" means in this context. Are they referring to the ability to retrieve the correct value vector given a query? Why is the outer product form optimal for this, and why does it require binary vectors? How does this relate to the claims about Bidirectional Associative Memories (BAMs)?
Answer:
The concept of "separability" in this context refers to the ability to cleanly distinguish and retrieve the correct stored value vector from the memory when presented with a query, despite interference from other stored key-value pairs. It is indeed about retrieving the correct value given a query, but the key insight is about what happens when multiple key-value pairs are stored simultaneously in the same matrix memory.

When you store $T$ key-value pairs using the covariance update rule, the memory matrix becomes $\mathbf{C} = \sum_{t=1}^{T} \mathbf{v}_t \mathbf{k}_t^\top$. Retrieving with a query $\mathbf{q}$ gives $\mathbf{C}\mathbf{q} = \sum_{t=1}^{T} \mathbf{v}_t (\mathbf{k}_t^\top \mathbf{q})$. If the query matches some stored key $\mathbf{k}_i$, the output decomposes into a signal term $\mathbf{v}_i (\mathbf{k}_i^\top \mathbf{q})$ and a noise term $\sum_{j \neq i} \mathbf{v}_j (\mathbf{k}_j^\top \mathbf{q})$ consisting of cross-talk from all other stored pairs. "Separability" is the degree to which the signal can be distinguished from this noise, and "maximal separability" means maximizing the signal-to-noise ratio (SNR).

The requirement for binary vectors (typically bipolar $\{-1, +1\}$-valued) comes from the statistical analysis that establishes optimality. For random binary vectors, the inner product $\mathbf{k}_j^\top \mathbf{q}$ for a non-matching key $j$ is a sum of $d$ independent $\{-1, +1\}$ random variables, which by the Central Limit Theorem is approximately Gaussian with mean zero and variance $d$. Meanwhile, the matching inner product $\mathbf{k}_i^\top \mathbf{q}$ equals $d$ deterministically (for a perfect query). This clean separation of a deterministic signal from well-characterized Gaussian noise is what makes the SNR analysis tractable. Dayan (1991) showed that among linear learning rules, the outer product accumulation maximizes this SNR for binary vectors, yielding an SNR proportional to $\sqrt{d/P}$ where $P$ is the number of stored patterns.

The outer product form is optimal because it is the minimal-rank matrix that maps a specific key to its corresponding value. Any other linear update rule would either introduce additional noise or fail to amplify the signal as efficiently. Intuitively, the outer product $\mathbf{v}_t \mathbf{k}_t^\top$ is the simplest matrix that, when multiplied by $\mathbf{k}_t$, produces a vector in the direction of $\mathbf{v}_t$. When you sum many such outer products, the contributions from non-matching keys are random and tend to cancel out, while the matching key's contribution adds coherently.

The connection to Bidirectional Associative Memories (BAMs) is that BAMs are precisely this type of hetero-associative memory system, introduced in the early 1970s by Kohonen, Anderson, Nakano, and others. A BAM stores pairs of patterns and can retrieve one pattern given the other (hence "bidirectional"). The covariance update rule is the learning rule for BAMs: the outer product matrix $\mathbf{C}$ serves as the BAM's weight matrix. The xLSTM paper uses this framework as theoretical justification for the mLSTM's matrix memory, noting that the same principle underlies Fast Weight Programmers (Schmidhuber, 1992; Schlag et al., 2021), which the mLSTM generalizes by integrating the covariance update into the LSTM gating framework with forget and input gates controlling decay and learning rate.

The paper also notes an important limitation: higher separability is achievable when allowing pairwise interactions with quadratic complexity, as in attention mechanisms (Krotov & Hopfield, 2016; Ramsauer et al., 2021). The covariance update rule achieves the best separability available within a linear, constant-memory scheme, but attention's explicit pairwise comparisons can exceed this at the cost of quadratic complexity in sequence length.

### How does Cover's Theorem relate to xLSTM block design and sequence modeling?
Question:
The xLSTM paper invokes Cover's Theorem to justify the up-projection in xLSTM blocks, stating that "in a higher dimensional space non-linearly embedded patterns can more likely be linearly separated than in the original space." I understand Cover's Theorem in the context of pattern classification, but I'm confused about how it applies to autoregressive sequence modeling. The goal is to predict the next token, not to classify histories. How does "separating histories" help with next-token prediction? Is the idea that different sequence histories that lead to different next tokens need to be separable in the hidden representation space?
Answer:
Your understanding is essentially correct. The connection between Cover's Theorem and next-token prediction works through the fact that the final prediction step in autoregressive language modeling is fundamentally a linear classification problem.

In autoregressive modeling, the model receives a sequence of tokens and must predict the next token. It does this by producing a hidden representation $\mathbf{h}_t$ that summarizes the context, which is then passed through a linear output layer to produce vocabulary logits: $\text{softmax}(\mathbf{W}\mathbf{h}_t + \mathbf{b})$. This final step is a linear classifier — it must linearly separate the hidden representation space into regions corresponding to different next tokens.

Now consider two different sequence histories that require different next tokens. For the model to distinguish them, their hidden representations must be separable in the representation space. If two such histories map to nearby or overlapping regions, the linear output layer cannot reliably produce different predictions for them. This is exactly where Cover's Theorem enters: patterns that are not linearly separable in a lower-dimensional space become more likely to be linearly separable when non-linearly embedded into a higher-dimensional space.

The xLSTM blocks exploit this through up-projection. As the paper describes, there are two variants. The post up-projection block (used for sLSTM) first non-linearly summarizes the past in the original space, then linearly maps to a high-dimensional space, applies a non-linear activation, and maps back. The pre up-projection block (used for mLSTM) first linearly maps to a high-dimensional space, performs the non-linear summarization there, and maps back. In both cases, the non-linear processing in the higher-dimensional space makes it more likely that different histories — which may have been entangled in the original space — become linearly separable, which directly benefits the linear output classifier that predicts the next token.

The choice between pre and post up-projection also relates to the memory structure. For mLSTM, the pre up-projection is preferred because the matrix memory $\mathbf{C} \in \mathbb{R}^{d \times d}$ operates in the higher-dimensional space, giving it greater storage capacity. For sLSTM, the post up-projection is used since the scalar memory summarizes in the original space before the up-projection expands the representation for improved separability.

So to directly answer your question: yes, the idea is precisely that different sequence histories leading to different next tokens need to be separable in the hidden representation space, and Cover's Theorem provides the theoretical justification for why up-projection to a higher-dimensional space helps achieve this separability — even though the ultimate task is next-token prediction rather than explicit classification.

### Why are multiple heads and multiple cells equivalent for mLSTM but not for sLSTM?
Question:
The xLSTM paper states that for mLSTM, "multiple heads and multiple cells are equivalent as there is no memory mixing," while for sLSTM, multiple heads have memory mixing within each head but not across heads, and multiple cells have memory mixing across cells. I don't understand what makes heads and cells equivalent in mLSTM. In Transformers, heads typically have different projection matrices — does mLSTM not distinguish between heads and cells in the same way? And why does the presence or absence of memory mixing make this distinction relevant?
Answer:
The equivalence (or lack thereof) between heads and cells hinges entirely on whether the architecture has **memory mixing** — that is, recurrent connections from the previous hidden state $\mathbf{h}_{t-1}$ back into the gates and cell inputs of the current step.

**Why mLSTM has no memory mixing.** If you look at the mLSTM equations in the paper, the gates and the query/key/value projections depend *only* on the current input $\mathbf{x}_t$, never on $\mathbf{h}_{t-1}$:

$$\tilde{i}_t = \mathbf{w}_i^\top \mathbf{x}_t + b_i, \quad \tilde{f}_t = \mathbf{w}_f^\top \mathbf{x}_t + b_f, \quad \mathbf{q}_t = \mathbf{W}_q \mathbf{x}_t + \mathbf{b}_q, \quad \text{etc.}$$

There are no recurrent weight terms $r \cdot h_{t-1}$ as in the sLSTM. Each cell (or head) maintains its own matrix memory $\mathbf{C}_t$, updates it independently, and retrieves from it independently. Since no cell's update ever depends on another cell's hidden state, there is no coupling between cells whatsoever. Whether you call a group of independent matrix memories "multiple cells" or "multiple heads" is purely a naming convention — the computation is identical in both cases. Each one has its own projection matrices ($\mathbf{W}_q, \mathbf{W}_k, \mathbf{W}_v$) and its own gate weights, and they never interact through recurrent connections.

**Why sLSTM's memory mixing makes the distinction meaningful.** In sLSTM, the gates and cell input *do* depend on the previous hidden state:

$$\tilde{z}_t = \mathbf{w}_z^\top \mathbf{x}_t + r_z \, h_{t-1} + b_z, \quad \tilde{i}_t = \mathbf{w}_i^\top \mathbf{x}_t + r_i \, h_{t-1} + b_i, \quad \text{etc.}$$

When you have multiple scalar memory cells, the recurrent connections use weight matrices $\mathbf{R}_z, \mathbf{R}_i, \mathbf{R}_f, \mathbf{R}_o$ that map the *entire* hidden state vector $\mathbf{h}_{t-1}$ (the concatenation of all cells' outputs) back into each individual cell's input and gates. This means cell $j$'s update at time $t$ is influenced by cell $k$'s output at time $t-1$ — that is memory mixing *across cells*.

Now, if you instead organize those same cells into multiple **heads**, the recurrent connections are restricted to exist only *within* each head. Cells belonging to the same head mix their memories through shared recurrent weights, but cells in different heads do not — the hidden state of one head never feeds into the gates or inputs of another. So the topology of information flow differs: "all cells in one head" means full mixing across all cells, whereas "multiple heads with fewer cells each" means mixing only within smaller groups.

**The key intuition.** The head/cell distinction is only meaningful when it affects the information flow between memory units. In mLSTM, since the recurrence is input-only (no hidden-to-hidden connections), every memory unit is already fully decoupled — grouping them into "heads" versus "cells" changes nothing about the computation. In sLSTM, the hidden-to-hidden recurrent connections create coupling, and the way you partition cells into heads determines the *pattern* of that coupling. That is why the paper states that for mLSTM, "multiple heads and multiple cells are equivalent as there is no memory mixing," while for sLSTM the two are fundamentally different architectural choices.

This also connects to a broader point in the paper: the absence of memory mixing in mLSTM is precisely what makes it parallelizable (analogous to linear attention), while its presence in sLSTM is what gives sLSTM greater expressive power for state tracking tasks, at the cost of requiring sequential computation.

### How does the forget gate initialization affect xLSTM training?
Question:
The xLSTM paper lists as one of its limitations that "the initialization of the forget gates must be chosen carefully." However, the paper doesn't elaborate on what initialization scheme is used or why it's particularly sensitive for xLSTM compared to original LSTMs. Is this related to the exponential gating, where small changes in the pre-activation $\tilde{f}_t$ lead to large changes in $f_t = \exp(\tilde{f}_t)$? What initialization values are appropriate, and what happens if the initialization is poorly chosen?
Answer:
You've identified the core issue correctly: the sensitivity of forget gate initialization in xLSTM is directly tied to the use of exponential gating, and the paper's limitation statement reflects a fundamental mathematical difference between sigmoid and exponential gates in the recurrent setting.

To understand why, consider the cell state update $c_t = f_t \, c_{t-1} + i_t \, z_t$. In the original LSTM, the forget gate uses sigmoid activation, so $f_t = \sigma(\tilde{f}_t) \in (0, 1)$. This means the cell state can only decay—never grow—as information propagates through time. The gradient of the cell state with respect to the previous cell state is simply $\frac{\partial c_t}{\partial c_{t-1}} = f_t \in (0, 1)$, which inherently prevents gradient explosion along the constant error carousel. This is precisely the mechanism that made the original LSTM robust to vanishing gradients while keeping gradient explosion in check.

With exponential gating, however, $f_t = \exp(\tilde{f}_t) \in (0, \infty)$. The critical boundary is now at $\tilde{f}_t = 0$, where $f_t = 1$. If the pre-activation is slightly positive, $f_t > 1$ and the cell state grows multiplicatively across time steps; if slightly negative, $f_t < 1$ and it decays. Over $T$ time steps, a forget gate value of $f_t = 1 + \epsilon$ leads to cell state amplification by a factor of approximately $(1+\epsilon)^T$, while $f_t = 1 - \epsilon$ leads to attenuation by $(1-\epsilon)^T$. This compounding effect means that even small initialization errors have consequences that grow with sequence length.

The paper introduces a stabilizer state $m_t = \max(\log(f_t) + m_{t-1},\; \log(i_t))$ with stabilized gates $f'_t = \exp(\log(f_t) + m_{t-1} - m_t)$ and $i'_t = \exp(\tilde{i}_t - m_t)$. Importantly, the paper proves in the appendix that this substitution does not change the network's output or the loss derivatives with respect to parameters—it is purely a numerical technique to prevent overflow. This means the stabilizer addresses the symptom (numerical explosion) but not the underlying learning dynamics. If the forget gate is initialized such that $f_t > 1$ on average, the model starts in a regime where the cell state grows exponentially, new inputs are overwhelmed by accumulated past state, and gradients along the recurrent path can explode. Conversely, if $f_t < 1$ on average, information decays too quickly and the model cannot retain long-range dependencies, leading to vanishing gradients.

The appropriate initialization is therefore one that keeps $f_t \approx 1$ at the start of training, which for the exponential variant means initializing the forget gate bias $b_f \approx 0$ (since $\exp(0) = 1$). This is more restrictive than with sigmoid gating, where the output is bounded in $(0, 1)$ regardless of initialization—any reasonable bias value yields a valid forgetting rate, and the model simply needs to learn whether to forget more or less. With exponential gating, the initialization must place the model near the delicate boundary between the growth and decay regimes. To achieve behavior analogous to the common LSTM practice of initializing the sigmoid forget gate bias to $b_f = 1$ (giving $\sigma(1) \approx 0.73$), one would need $b_f = \log(0.73) \approx -0.31$ for the exponential variant, but the exact choice involves a trade-off between encouraging initial retention and avoiding the growth regime.

The sensitivity is further amplified by the fact that the exponential function has unit slope at the origin ($\frac{d}{dx}e^x\big|_{x=0} = 1$), compared to sigmoid's maximum slope of $0.25$ at $x=0$. This means perturbations to the pre-activation near zero translate more directly into gate value changes for exponential than for sigmoid gating. Combined with the compounding over time steps, this makes the forget gate initialization in xLSTM a critical hyperparameter that determines whether training begins in a stable regime.

It is worth noting that the paper allows the forget gate to use either sigmoid or exponential activation ($f_t = \sigma(\tilde{f}_t)$ OR $\exp(\tilde{f}_t)$). The initialization sensitivity is specific to the exponential variant; when sigmoid is used, the situation reverts to that of the original LSTM. The limitation listed in the paper thus reflects the cost of exponential gating's primary benefit—the ability to revise storage decisions by allowing $f_t > 1$ to amplify past memories—which comes at the price of requiring more careful initialization to avoid starting in an unstable dynamical regime.

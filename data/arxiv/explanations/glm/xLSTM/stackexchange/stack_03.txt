\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### How does the stabilizer state in sLSTM preserve mathematical equivalence?
Question:
The xLSTM paper introduces a stabilizer state $m_t = \max(\log(f_t) + m_{t-1}, \log(i_t))$ and uses stabilized gates $i'_t = \exp(\tilde{i}_t - m_t)$ and $f'_t = \exp(\log(f_t) + m_{t-1} - m_t)$. The paper claims that replacing $f_t$ with $f'_t$ and $i_t$ with $i'_t$ in the forward pass "does neither change the output of the whole network nor the derivatives of the loss with respect to the parameters." How can subtracting $m_t$ from the gate values not change anything? It looks like the gates are being rescaled by $\exp(-m_t)$, which should change their values. What am I missing about why this is mathematically equivalent?
Answer:
The key insight is that the stabilizer rescales the cell state $c_t$ and the normalizer state $n_t$ by the *same* factor at every time step, so when the hidden state is computed as their ratio $\tilde{h}_t = c_t / n_t$, the scaling cancels out.

To see this, define $s_t = \exp(m_t)$. Then the stabilized gates can be rewritten as:

$$i'_t = \frac{i_t}{s_t}, \qquad f'_t = \frac{f_t \cdot s_{t-1}}{s_t}$$

Now suppose we run the stabilized forward pass, producing $c'_t$ and $n'_t$. Multiply both sides of the $c'$ update by $s_t$:

$$s_t \, c'_t = f_t \, s_{t-1} \, c'_{t-1} + i_t \, z_t$$

Defining $\hat{c}_t = s_t \, c'_t$, this becomes $\hat{c}_t = f_t \, \hat{c}_{t-1} + i_t \, z_t$, which is exactly the original cell state update. So $\hat{c}_t = c_t$, meaning $c'_t = c_t / s_t$. By the identical argument, $n'_t = n_t / s_t$. Therefore the hidden state is preserved:

$$\tilde{h}'_t = \frac{c'_t}{n'_t} = \frac{c_t / s_t}{n_t / s_t} = \frac{c_t}{n_t} = \tilde{h}_t$$

Since every hidden state $h_t = o_t \, \tilde{h}_t$ is identical to the unstabilized version, the network output and the loss as a function of the parameters are exactly the same. Consequently, the gradients with respect to the parameters must also be identical—the computation graph differs, but the function being differentiated does not.

Intuitively, this is the same principle behind the log-sum-exp trick used for numerical stability in softmax: you subtract the maximum logit before exponentiating to prevent overflow, and the normalization in the denominator ensures the result is unchanged. Here, the normalizer state $n_t$ plays that compensating role. The stabilizer $m_t$ tracks the running maximum of $\log(f_t) + m_{t-1}$ and $\log(i_t)$, ensuring that the stabilized gate values $i'_t$ and $f'_t$ are at most $1$, which prevents the exponential gates from overflowing while leaving the model's mathematical behavior completely unchanged.

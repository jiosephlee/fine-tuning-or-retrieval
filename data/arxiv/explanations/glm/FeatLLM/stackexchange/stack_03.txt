\title{Stack Exchange of the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

### What is the purpose of projecting weights to non-negative space with $\max(\mathbf{w}_k, 0)$ in FeatLLM?
Question:
In Section 3.2, the paper defines the class likelihood computation as:

$$\text{logit}_k^i = \max(\mathbf{w}_k, 0) \cdot \mathbf{z}_k^i$$

where $\mathbf{w}_k$ are trainable weights and $\mathbf{z}_k^i$ are binary features.

The paper says: "By projecting these weights into a positive subspace, we can ensure that the features generated by the LLM do not reduce the likelihood of a class during learning."

I don't understand why this is necessary. If a rule is negatively associated with a class, shouldn't the weight be allowed to be negative? Why force all weights to be non-negative? Is it because the rules are specifically generated FOR each class, so by construction they should only increase that class's likelihood?
Answer:
Your intuition is essentially correct. The key reason for the $\max(\mathbf{w}_k, 0)$ projection lies in the semantics of how the rules are generated and what they represent.

The rules for class $k$ are explicitly generated by the LLM as conditions that are *indicative* of that class. The prompt instructs the LLM to "deduce rules for each class" — meaning the rules are designed as positive evidence for class membership. The binary feature vector $\mathbf{z}_k^i$ indicates whether sample $i$ satisfies each of these rules for class $k$. Since each rule is constructed to be a piece of evidence *for* class $k$, allowing its weight to become negative would mean that satisfying a rule designed to support class $k$ actually *decreases* the likelihood of class $k$. This would be semantically contradictory to the rule generation process.

With the non-negativity constraint, each weight $\mathbf{w}_{k,r}$ (for rule $r$ of class $k$) acts as a **relevance or importance score** ranging from "irrelevant" (weight near zero) to "strongly indicative" (large positive weight). The paper explicitly leverages this interpretation in its analysis, noting that "rules that have little relevance to the data (i.e., rules with learned weights below the threshold) are automatically filtered out" — a threshold of $0.1$ is used to prune uninformative rules. This filtering mechanism only makes sense if weights are non-negative, since a near-zero weight cleanly signals "this rule doesn't help" rather than "this rule actively hurts."

There is also a practical benefit in the few-shot setting the paper targets. Allowing negative weights doubles the effective parameter space (each weight can move in two directions), increasing the risk of overfitting when training samples are scarce. Constraining weights to be non-negative acts as a form of regularization that encodes the prior knowledge from the rule generation stage — namely, that these rules are meant to be supportive evidence. This is consistent with the paper's broader design philosophy of injecting inductive bias from the LLM's prior knowledge to compensate for limited data.

It is worth noting what this design gives up. If the LLM generates a rule that is actually *negatively* correlated with the target class (due to imperfect reasoning), the model cannot learn to invert its contribution — it can only suppress it by driving the weight to zero. The paper accepts this trade-off, relying on the ensemble approach (with bagging across $T$ trials) and the LLM's two-step reasoning process to reduce the generation of such counterproductive rules. The ablation study confirms this design choice is beneficial: removing the weight tuning entirely (the "$\textsf{-Tuning}$" ablation) causes performance degradation, showing that learning non-negative importance weights adds value beyond simply counting satisfied rules.

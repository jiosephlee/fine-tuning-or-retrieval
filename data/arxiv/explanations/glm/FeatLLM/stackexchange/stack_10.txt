\title{Stack Exchange of the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

### How does the $k$-shot setting work with the ensemble and bagging in FeatLLM?
Question:
The paper mentions both $k$-shot learning and bagging. In $k$-shot learning, we have only $k$ labeled samples (e.g., $k=4$). The paper also mentions "randomize the order of few-shot demonstrations" and "bagging to select a subset of features or instances."

If we only have 4 labeled samples and we do instance bagging, does that mean we might train some ensemble members on only 2-3 samples? How does bagging work with such a small number of samples? Is the instance bagging only applied to larger $k$ values? Also, for the linear model training with cross-validation, how do we do $k$-fold cross-validation when $k=4$ and we might have only 2 samples per class?
Answer:
The short answer is that for very small $k$ (e.g., $k=4$), instance bagging is not the primary mechanism driving ensemble diversity, and cross-validation is adapted by reducing the number of folds to ensure each fold contains at least one sample per class. Let me address each part of your question.

The paper states in the "Ensembling with bagging" paragraph that bagging is adopted "to select a subset of features or instances for each trial, which gets particularly useful for larger number of training samples or features." This phrasing is key: it signals that instance bagging provides the most benefit when there are more training samples to sub-sample from. When $k=4$, randomly subsampling instances would indeed leave some ensemble members with only $2$–$3$ labeled samples, which offers limited diversity benefit and risks losing class coverage. The paper does not explicitly state that instance bagging is disabled for small $k$, but the emphasis on "particularly useful for larger number of training samples or features" strongly suggests that for small $k$, the ensemble diversity primarily comes from other sources. Specifically, the paper identifies two other randomness mechanisms: setting a "sufficiently high temperature" for LLM inference and "randomiz[ing] the order of few-shot demonstrations," both of which are fully functional regardless of $k$. Additionally, feature bagging—selecting a subset of the input features (columns) rather than instances (rows)—remains applicable even with very few samples and is particularly important for datasets with many features (the paper mentions datasets like Communities and Myocardial with over $100$ attributes). So for $k=4$, the ensemble is diverse mainly due to LLM stochasticity, demonstration reordering, and potentially feature bagging, while instance bagging likely plays a minimal or negligible role.

Regarding cross-validation for the linear model, the paper states: "We employ $k$-fold cross-validation for optimal epoch selection" and later specifies that "The value of $k$ is set either as $2$ or $4$, guaranteeing that the training set includes at least one example of each class." Note that this $k$ (the number of CV folds) is a different hyperparameter from the $k$ in $k$-shot learning. For $4$-shot learning, they would use $2$-fold cross-validation, splitting the $4$ training samples into $2$ folds of $2$ samples each, with the fold boundaries chosen to ensure class balance. This ensures that during each fold, the training portion contains at least one example per class, preventing degenerate splits where a class is entirely absent. For larger training sets (e.g., $k=16$ or $k=32$), $4$-fold cross-validation becomes feasible with more samples per fold. The paper's explicit mention that $k$ is set to "either $2$ or $4$" with the constraint of class coverage confirms that the cross-validation strategy is adapted to the training set size.

In summary, the bagging and ensemble framework in FeatLLM is designed to be flexible across different $k$ values. For small $k$, the ensemble relies on LLM temperature, demonstration order randomization, and feature bagging for diversity, while instance bagging becomes more relevant as the number of training samples grows. Cross-validation is correspondingly adjusted—using fewer folds for smaller training sets—to maintain at least one sample per class per fold.

\title{Blogs about the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

# Taming Massive Spreadsheets: How Ensemble Bagging Solves the LLM Context Limit

## The Context Window Bottleneck in Tabular Learning

Large Language Models (LLMs) have shown impressive capabilities in few-shot tabular learning, where data is scarce and domain knowledge is crucial. However, applying them to wide, complex datasets often hits a hard wall: the context window limit. When a dataset includes over 100 columns—such as the `Communities` or `Myocardial` datasets mentioned in recent research—serializing the tabular data along with feature descriptions and few-shot examples creates a massive prompt. As the prompt grows, it eventually exceeds the LLM's input limit, or worse, the model's performance degrades due to the struggle with lengthy contexts.

A new framework called FeatLLM offers an elegant way around this constraint. Instead of using the LLM to make end-to-end predictions for each sample, FeatLLM employs the LLM as a feature engineer. By combining this approach with ensemble bagging, the framework can process massive spreadsheets without overflowing the prompt.

## From Columns to Rules: The FeatLLM Approach

FeatLLM shifts the LLM's role from predicting labels directly to generating "rules"—the underlying conditions associated with each target class. For example, when predicting a disease, the LLM might infer rules like "age $> 50$" or "blood pressure $> 140$".

The framework's prompt design guides the LLM through a structured, two-step reasoning process. First, the LLM infers the causal relationship between features and the target task without looking at examples, relying on its prior knowledge. Second, it uses few-shot example demonstrations to deduce decisive rules for each class. These rules are then parsed into program code, applied to the data, and transformed into binary features: $1$ if a sample satisfies a rule, and $0$ if it does not. A simple linear model then learns the importance of these rules to estimate class likelihood.

## Bypassing the Limit with Feature Bagging

So, how does FeatLLM handle datasets with over 100 features without exceeding the LLM's context window? The answer lies in ensemble bagging. 

If a dataset is too wide to fit into a single prompt, FeatLLM does not try to force it. Instead, it adopts a bagging strategy to select a subset of features and instances for each trial. By appropriately adjusting the number of features chosen in each bag, the framework ensures the prompt size stays well within the LLM's allowable limits.

Because a single trial only sees a fraction of the features, the rules it generates might not capture the full picture. To solve this, FeatLLM repeats the rule-generation process multiple times—using a high LLM temperature and randomized few-shot prompt orders to introduce diversity. The framework defaults to $20$ ensemble trials and extracts $10$ rules per class. 

While a single rule set acts as a "weak learner" with incomplete feature coverage, the ensemble of various trials nullifies the impact of those individual blind spots. If the LLM generates an incorrect rule in one trial, correct rules from other trials can compensate, enhancing the overall robustness of the framework.

## The Math Behind the Ensemble

Let's look at how the ensemble combines these rules mathematically. For a given sample $\mathbf{x}^i$ and class $k$, the generated binary features are represented as $\mathbf{z}_k^i \in \{0, 1\}^R$, where $R$ is the number of rules per class. 

The likelihood for each class is computed using a linear model without bias. The logit for class $k$ is calculated as:
$$\text{logit}_k^i = \max(\mathbf{w}_k, 0) \cdot \mathbf{z}_k^i$$

Here, $\mathbf{w}_k$ represents the trainable weights that signify the importance of each rule. Projecting these weights into a positive subspace ensures that features generated by the LLM do not inadvertently reduce a class's likelihood during learning. 

These logits are then passed through a softmax function to get class probabilities:
$$\mathbf{p}^i = \text{Softmax}([\text{logit}_1^i, ..., \text{logit}_c^i])$$

During training, the model optimizes cross-entropy loss to learn the weights $\mathbf{w}_k$ using the few available labeled samples. Finally, given the collection of trained weights from $T$ trials, denoted as $\{\mathbf{w}[t]\}_{t=1}^T$, the final prediction is made by simply averaging the probabilities across all trials.

## Robustness for Real-World Data

By combining feature engineering with ensemble bagging, FeatLLM solves a fundamental challenge in LLM-based tabular learning. It mitigates the context window limit, allowing the model to handle datasets with numerous features effectively. Furthermore, because the LLM is only used to generate rules during the feature engineering phase, FeatLLM eliminates the need to send queries to the LLM for each sample at inference time. This results in a fast, efficient, and highly accurate framework that makes applying LLMs to real-world, massive spreadsheets entirely feasible.

\title{Blogs about the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

# The High Cost of AI Predictions: Why FeatLLM Skips the LLM at Inference Time

Large Language Models (LLMs) have proven surprisingly adept at tabular learning tasks. By serializing rows of data into text and feeding them to an LLM along with feature descriptions, we can achieve impressive few-shot predictions. But there is a massive operational catch: doing this in production means sending every single data row through an LLM API. The latency and API costs for thousands or millions of rows are astronomical, making traditional LLM-based tabular learning a hard sell for real-world, large-scale applications.

## The Bottleneck with Current LLM Tabular Models

Most current LLM-based tabular learning methods treat the LLM as an end-to-end predictor. If you want to predict whether 10,000 customers will subscribe to a term deposit, you serialize 10,000 rows and make 10,000 API calls. This is computationally expensive and slow. 

Furthermore, many high-performance approaches require fine-tuning the LLM. This is often impossible with modern, top-tier LLMs that only offer restricted inference APIs and do not provide access to training codebases. Finally, when tabular datasets have a large number of features, the serialized text can easily exceed the LLM's prompt size limit, degrading performance or breaking the pipeline entirely.

## FeatLLM: The LLM as a Feature Engineer

The paper "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning" introduces a framework called FeatLLM to solve these operational bottlenecks. The core idea is brilliantly simple: use the LLM as a feature engineer rather than an end-to-end predictor. 

During a preparation phase, FeatLLM queries the LLM a handful of times to extract human-readable "rules" or criteria for the target classes. For a disease prediction task, the LLM might suggest rules based on its prior knowledge, such as identifying that older individuals are at an increased risk. These rules are then parsed into program code to generate new binary features for the dataset. At inference time, FeatLLM completely bypasses the LLM, relying only on a lightweight downstream machine learning model to make predictions using these newly engineered features.

## How It Works

FeatLLM prompts the LLM with a structured, two-step reasoning process to mimic how a human expert would approach the task:
1. The LLM is asked to infer the causal relationship or tendency between features and the target, relying purely on its general prior knowledge.
2. The LLM is given a few-shot examples and asked to deduce decisive rules for each class based on that prior knowledge.

Because LLMs can produce syntactically noisy text, FeatLLM actually uses the LLM itself to parse these natural language rules into executable Python code. This code is applied to the data to create binary features, denoted as $\mathbf{z}_k^i \in \{0, 1\}^R$ for a given sample $i$ and class $k$, indicating whether the sample satisfies the rules.

To infer class likelihood, FeatLLM uses a simple linear model without bias. The probability for each class is calculated as:

$$ \text{logit}_k^i = \max(\mathbf{w}_k, 0) \cdot \mathbf{z}_k^i $$

$$ \mathbf{p}^i = \text{Softmax}([\text{logit}_{1}^i, ..., \text{logit}_{c}^i]) $$

Here, $\mathbf{w}_k$ represents the trainable weights signifying the importance of each rule. By projecting these weights into a positive subspace, the model ensures that a rule never actively reduces a class's likelihood during learning. Because the inference step only involves a dot product and a softmax function, it is lightning fast.

## Tackling Prompt Limits and Noise

FeatLLM repeats this rule-generation process multiple times using an ensemble approach with bagging. By randomly selecting subsets of features and instances for each trial, it mitigates the issue of large prompts exceeding the LLM's context window. The final prediction is made by averaging the class probabilities across all the ensemble trials. 

This ensemble method offers two major advantages. First, it adds robustness against any single set of incorrect rules generated by the LLM, relying on self-consistency to ensure commonly inferred rules dominate. Second, it fundamentally solves the prompt size limitation by ensuring no single query needs to contain the entirety of a massive dataset's features.

## The Payoff: Fast, Cheap, and Accurate Inference

The operational benefits of this architecture are immense. By skipping the LLM at inference time, FeatLLM reduces inference latency to levels comparable with traditional methods like Logistic Regression or XGBoost. In runtime comparisons on the Adult dataset, FeatLLM's inference time was a fraction of that of LLM-based methods like in-context learning or TabLLM. During training, the entire framework only requires about 30 API queries, which can be parallelized and executed at a negligible cost.

Despite the lightweight inference, FeatLLM does not sacrifice accuracy. Across 13 diverse tabular datasets, it outperformed baselines like TabLLM and STUNT by an average of 10\% in AUC. Impressively, using only 4 labeled samples, FeatLLM achieved performance comparable to conventional tabular baselines that required 32 samples. It also proved highly resilient to spurious correlations, as the LLM filters out irrelevant columns when generating rules based on its prior knowledge.

FeatLLM represents a pragmatic shift in how we leverage LLMs for tabular data. By confining the LLM to the feature engineering phase and using a simple linear model for predictions, it delivers the best of both worlds: the rich prior knowledge of massive language models and the speed, cost-efficiency, and scalability of traditional machine learning.

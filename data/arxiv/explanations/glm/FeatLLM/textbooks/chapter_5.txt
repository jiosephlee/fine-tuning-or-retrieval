\title{A Textbook about the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

Chapter 5: Analysis and Discussion

# Ablation Study: Evaluating the Impact of Weight Tuning, Ensembling, Descriptions, and Reasoning

To truly understand how a complex machine learning framework achieves its performance, researchers rely on ablation studies. An ablation study is a systematic process of removing or disabling specific components of a model to observe how their absence affects overall performance. This process helps identify which parts of the architecture are critical to its success and which are merely supplementary. In the context of FeatLLM, the ablation study examines four key components: weight tuning, ensembling, feature descriptions, and reasoning instructions. 

The first component evaluated through ablation is weight tuning, denoted as "-Tuning" in the study. In the full FeatLLM framework, after the Large Language Model (LLM) generates a set of rules and converts them into binary features, a simple linear model is trained to learn the importance, or weights, of each rule for predicting class likelihood. The ablation "-Tuning" removes this training process; instead of learning the weights, the model simply sums up the binary features to compute the logit for each class. The findings reveal that omitting weight tuning degrades performance. Interestingly, the benefit of weight tuning becomes more pronounced as the number of shots, or training samples, increases. This indicates that with more data, the model can more accurately estimate the importance of different rules, making the tuning process highly effective.

The second component is ensembling, denoted as "-Ensemble". The full FeatLLM framework repeatedly executes the rule generation and prediction process multiple times with different random subsets of features and instances—a technique known as bagging—and averages their predictions. Removing this ensemble process leads to a drop in performance across all experimental settings. The ensemble approach is crucial because it allows correct rules generated across different trials to compensate for any incorrect rules produced in a single trial, resulting in robust predictions. 

The third and fourth components are feature descriptions ("-Description") and reasoning instructions ("-Reasoning"). The feature description provides the LLM with the value type and definition of each feature in the dataset. The reasoning instruction guides the LLM through a two-step process: first inferring the causal relationship between features and the task using general prior knowledge, and then deducing rules based on that knowledge and a few examples. Ablating these components significantly degrades performance, particularly in low-shot regimes where the number of training samples is very small. This observation suggests that when data is scarce, the efficient utilization of the LLM's prior knowledge—facilitated by explicit descriptions and structured reasoning—becomes the primary driver of performance improvement.

# Training and Inference Time Comparison Across Different Methods

Beyond predictive accuracy, the computational cost of a machine learning model is a critical factor for its real-world applicability. For tabular learning models utilizing LLMs, the computational expense can be a major bottleneck. This section compares the training and inference time of FeatLLM against both conventional machine learning baselines and other LLM-based methods. The experiments for this comparison are conducted on the Adult dataset using a training set of $16$ shots, utilizing an A100 GPU (with the TabLLM baseline specifically requiring four A100 GPUs for model parallelism).

At inference time, FeatLLM demonstrates a significant advantage over other LLM-based approaches. Methods like in-context learning, TABLET, and TabLLM require at least one LLM inference per sample, meaning the LLM must process each individual data point to generate a prediction. This makes their inference times substantially higher. In contrast, FeatLLM shifts the role of the LLM from end-to-end prediction to feature engineering. Once the LLM generates the rules and the new binary features are created, the LLM is no longer needed. The final prediction is made by a simple downstream linear model, which requires minimal computational overhead. As a result, FeatLLM's inference time is remarkably low and comparable to conventional tabular methods like Logistic Regression, XGBoost, and RandomForest.

When it comes to training time, FeatLLM remains efficient and practical. Although the framework involves querying the LLM to generate rules, it only requires $30$ API queries to generate the ensemble of rule sets. This number of queries does not impose a significant burden on the budget and, importantly, these queries can be parallelized to further reduce the actual wall-clock time. Thus, FeatLLM strikes an effective balance, achieving the high performance associated with LLM-based methods while avoiding the prohibitive inference costs that typically accompany them.

# Assessing the Quality and Informativeness of Generated Features

A fundamental question about any feature engineering framework is whether the newly generated features are actually informative for the task at hand. To investigate the quality of the rule-based features produced by FeatLLM, the researchers conducted a simple yet revealing experiment. They measured the average Area Under the Receiver Operating Characteristic Curve (AUROC) between the newly generated features and the target labels. An AUROC of $0.5$ indicates a random, uninformative feature, while values above $0.5$ indicate that the feature carries useful predictive information. By calculating the ratio of useful features—those with an AUROC greater than $0.5$—for each dataset, they could quantify the informativeness of the rules.

The results confirm that before any tuning takes place, the majority of the rules created by FeatLLM are relevant to the target attribute. This means the LLM is successfully leveraging its prior knowledge and the few-shot examples to generate features that provide informative insights for addressing the task. However, not all generated rules will be equally useful, and some might be redundant or irrelevant. 

To handle this, the linear model's weight tuning process acts as an automatic filter. During training, the model learns the importance of each rule-based feature. Rules that have little relevance to the data are assigned low weights. By applying a threshold (set at $0.1$ based on the overall histogram of weights), the framework automatically filters out these less relevant rules. After this tuning and filtering process, the retained features represent a highly purified set of rules, ensuring that the downstream model relies only on the most informative signals provided by the LLM.

# Robustness to Spurious Correlations in Low-Shot Regimes

In low-shot learning regimes, where the number of labeled training samples is extremely small, models are highly susceptible to learning spurious correlations—accidental relationships in the data that do not reflect true underlying causal factors. To test how effectively FeatLLM filters out such noise, the researchers designed a specific experiment using the Heart dataset. They progressively attached columns from the Adult dataset—which are entirely irrelevant to the Heart task—to the Heart data and measured the performance changes of various models. To ensure a fair comparison, all models were provided with the same $8$ shots of labeled samples and did not use any unlabeled datasets.

The results show that compared to baselines, FeatLLM exhibited the least performance degradation as the number of unrelated columns increased. This robustness is a direct result of the framework's design. When FeatLLM generates rules, it does not merely look for statistical patterns in the few-shot examples; it explicitly forces the consideration of the relationship between the task and the features based on the LLM's prior knowledge. This mechanism prevents the model from generating rules based on the irrelevant, noisy columns. In fact, the researchers observed that rules based on noisy columns accounted for only $1-2\%$ of the total rules generated.

However, the study also notes a limitation: if the attached noisy columns come from a closely related domain, FeatLLM can potentially be misled. In such cases, the LLM might misunderstand the causal relationships between the task and the features, leading it to learn spurious correlations. This highlights that while prior knowledge is a powerful tool for resisting random noise, it can sometimes be a vulnerability if the external data appears topically related but is not actually causally linked.

# Hyper-Parameter Analysis: Optimizing the Number of Ensembles and Rules

The performance and computational efficiency of FeatLLM are governed by two main hyper-parameters: the number of ensembles and the number of rules extracted per class during each LLM query. Understanding the impact of these hyper-parameters is essential for optimizing the framework's performance.

The first hyper-parameter is the number of ensembles. Because FeatLLM uses bagging and averaging to combine predictions from multiple trials, increasing the number of ensembles generally improves robustness and accuracy. Experiments showed that as the number of ensembles increases, performance does indeed improve. However, this improvement is subject to diminishing returns. Beyond a certain point—specifically, around $20$ ensembles—the performance gains begin to converge, meaning additional ensembles yield negligible benefits. Thus, $20$ is identified as an effective and efficient default number of ensembles.

The second hyper-parameter is the number of rules generated per class. The researchers conducted experiments to see how varying this number affects performance. While the differences were not statistically significant across various values, they determined that $10$ rules per class is the most appropriate choice. This decision is based on a trade-off between prompt length and performance. Extracting more rules increases the dimensionality of the input data, which theoretically provides more information to the model. However, in the low-shot regime, a high number of features can easily lead to overfitting, where the model memorizes the training data rather than learning generalizable patterns. Furthermore, increasing the number of rules enlarges the length of the prompt sent to the LLM, which can be computationally and financially costly. Therefore, setting the number of rules to $10$ provides an optimal balance, capturing enough informative rules to achieve high performance without unnecessarily bloating the prompt or inducing overfitting.

\title{A Textbook about the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

Chapter 1: Introduction to LLM-Based Tabular Learning

## The Role of LLMs in Reasoning and Tabular Learning

Large Language Models, or LLMs, have emerged as powerful tools capable of generating suitable responses for previously unseen tasks without requiring task-specific fine-tuning. Trained on extensive text corpora spanning diverse domains, these models possess rich prior knowledge that can substitute for expert domain knowledge in many areas, from genomics to healthcare to finance. This remarkable ability stems from their training on massive amounts of text data, which allows them to capture patterns, relationships, and facts about the world that prove valuable when applied to new problems. A key mechanism through which LLMs demonstrate this capability is in-context learning, whereby a task description and a few examples are incorporated into the input prompt. The LLM then understands the context of the task and "attends" to important features and examples, producing outputs that reflect both its pre-trained knowledge and the specific information provided in the prompt.

Tabular learning, which involves making predictions from structured data organized in rows and columns, is vital for many real-world applications. Consider, for example, predicting whether a patient will develop a particular disease based on clinical measurements, or determining whether a loan applicant will default based on financial history. These tasks traditionally require labeled training data to train machine learning models. However, in many real-world scenarios, obtaining large quantities of labeled data is expensive or impractical. This is where LLMs offer a unique advantage: their prior knowledge can supplement the limited labeled data available. For instance, in disease prediction tasks, an LLM's pre-trained knowledge might include the understanding that older individuals face an increased risk of certain diseases, or that particular biomarkers are associated with specific conditions. This knowledge, encoded during pre-training on medical literature and electronic health records, can be leveraged even when only a handful of labeled examples are available.

The application of LLMs to tabular learning typically involves serializing the tabular data into text format. Each sample, with its feature values, is converted into a natural language description, and together with feature names, feature descriptions, and a task description, is fed into the LLM's input prompt. The LLM then infers the relationships between the task and the features to produce a prediction. This approach has proven effective, particularly in low-shot regimes where conventional methods struggle due to insufficient training data. Prior knowledge provided by LLMs has outperformed conventional tabular learning baselines in these settings. The LLM serves as both a repository of domain knowledge and a reasoning engine, capable of drawing connections between features and outcomes that might not be immediately apparent from a small number of training examples alone.

## Current Limitations: End-to-End Prediction Costs, Fine-Tuning Requirements, and Prompt Size Constraints

Despite the demonstrated effectiveness of LLM-based tabular learning methods, several significant limitations constrain their real-world applicability. The first major limitation is the computational cost associated with end-to-end predictions. In current approaches, at least one LLM inference is required per sample at prediction time. This means that for every new data point that needs to be classified, the entire serialized sample must be passed through the LLM, which is computationally expensive and introduces significant latency. In industrial settings where predictions must be made for large volumes of data points in real time or near-real time, this per-sample inference cost becomes prohibitive. Unlike conventional machine learning models that can make predictions via simple matrix operations once trained, these LLM-based methods require the full computational overhead of a large neural network forward pass for each individual prediction.

A second major limitation concerns fine-tuning requirements. Most LLM-based tabular learning methods achieve high accuracy only when the LLM is fine-tuned on the specific task using parameter-efficient techniques such as LoRA (Low-Rank Adaptation) or IA3 (Injection of Adapted features). While these techniques are more efficient than full fine-tuning, they still require access to the model's internal parameters and training infrastructure. This requirement becomes increasingly problematic given the current trend in the LLM ecosystem, where recently-proposed top-performance LLMs only permit limited access via inference APIs. For example, models like GPT-4 and PaLM do not provide users with access to their training codebases or tuning APIs, making it impossible to apply fine-tuning-based methods to these state-of-the-art models. Practitioners are thus faced with a difficult choice: either use older, less capable models that support fine-tuning, or use state-of-the-art models only through their inference APIs, forgoing the performance gains that fine-tuning provides.

The third limitation involves prompt size constraints. LLMs have a finite context window, meaning there is a limit to the amount of text that can be included in a single input prompt. When the number of features in tabular data grows, the serialized text length becomes long, potentially exceeding the allowable input prompt size. This is particularly problematic for datasets with a large number of attributes; for instance, the Communities dataset and the Myocardial dataset include over 100 attributes each. Even when the prompt does not strictly exceed the context window, research has shown that LLMs experience a decline in performance when prompts become lengthy. This phenomenon, sometimes referred to as "lost in the middle," means that information presented in the middle of a long prompt may not be effectively utilized by the model. For tabular data with many features, some approaches simply turn infeasible, while others suffer degraded performance. These three limitations—computational cost of per-sample inference, dependence on fine-tuning, and vulnerability to prompt size constraints—pose fundamental challenges to the real-world application of LLM-based tabular learning models and motivate the search for alternative paradigms.

## The FeatLLM Paradigm: LLMs as Feature Engineers

The FeatLLM framework introduces a paradigm shift in how LLMs are utilized for tabular learning. Rather than treating the LLM as an end-to-end predictor that processes each sample individually, FeatLLM assigns the LLM the role of a feature engineer. The core insight is that the LLM's prior knowledge and reasoning capabilities can be more efficiently utilized by having the model generate criteria, or rules, that determine which feature conditions are associated with each class, rather than having it directly predict the class for each sample. For example, in a disease prediction task, instead of asking the LLM whether each individual patient has the disease, FeatLLM asks the LLM to infer and generate rules that determine which feature conditions result in identifying the disease—such as "age greater than 60 AND blood pressure above 140." These rules are then used to create new features that replace the existing ones in solving the prediction task.

The FeatLLM framework structures the LLM's rule-extraction process into two sub-tasks, designed to mimic how an expert human might approach a tabular learning problem. The first sub-task involves understanding the problem and inferring the relationship between features and the target variable, relying on the LLM's general knowledge and common sense without reference to specific data examples. This step encourages the LLM to fully extract its prior knowledge about the problem domain. The second sub-task uses the knowledge from the first step along with a few-shot example demonstrations to derive decisive rules that distinguish between classes. This two-step reasoning process, inspired by chain-of-thought approaches, helps prevent the model from identifying spurious correlations in irrelevant columns and focuses attention on more significant features. The LLM is instructed to generate a fixed number of rules (specifically, 10) per class, which balances the need for sufficient coverage against the risk of creating an excessively large prompt or overfitting in the low-shot regime.

Once the rules are generated, they must be transformed into usable features. Since the rules are expressed in natural language, FeatLLM employs the LLM itself to parse them into executable program code. The function name, input and output descriptions, and the inferred rules are included in a prompt, and the LLM generates Python code that can be executed to transform the data. Each sample is then represented by a binary feature vector for each class, where each binary value indicates whether the sample satisfies the corresponding rule for that class (1 if satisfied, 0 if not). This transformation shifts the LLM's contribution from prediction to feature generation, enabling a simpler downstream model to handle the actual classification. The structured reasoning approach, combined with the rule-based feature representation, effectively filters out uninformative features and captures the LLM's domain knowledge in a compact, interpretable form.

## Key Benefits of FeatLLM: Low Inference Cost, API-Level Access, and Prompt Size Mitigation

The FeatLLM framework offers several key advantages over existing LLM-based tabular learning approaches, addressing each of the limitations identified earlier. The first benefit is low inference cost. Since the LLM is used only during the feature engineering stage—generating rules and parsing them into code—the LLM is not involved in the inference process at all. Once the rules are extracted and the downstream model is trained, predictions for new samples involve only checking which rules each sample satisfies and applying the trained model. Specifically, FeatLLM uses a simple linear model without bias, where the class likelihood is computed as a dot product between non-negative trainable weights and the binary feature vector, followed by a softmax function to obtain class probabilities. The probability for each class $\mathbf{p}^i$ for sample $\mathbf{x}^i$ is computed as:

$$\text{logit}_k^i = \max(\mathbf{w}_k, 0) \cdot \mathbf{z}_k^i,$$

$$\mathbf{p}^i = \text{Softmax}([\text{logit}_{1}^i, ..., \text{logit}_{c}^i]).$$

Here, $\mathbf{z}_k^i \in \{0, 1\}^R$ is the binary feature vector for class $k$ with $R$ rules per class, $\mathbf{w}_k$ are the trainable weights, and $c$ is the number of classes. The weights are projected into a positive subspace to ensure that the LLM-generated features do not reduce the likelihood of a class during learning. This simple model makes predictions computationally inexpensive, comparable to conventional machine learning methods, and dramatically faster than approaches that require a full LLM forward pass per sample. Experimental results confirm that FeatLLM's inference time is comparable to conventional methods, while other LLM-based approaches exhibit much higher inference times.

The second benefit is that FeatLLM requires only API-level access to LLMs. Because the LLM is never fine-tuned—the rules are extracted through in-context learning, where few-shot example demonstrations are added to the prompt without any parameter updates—FeatLLM can leverage any LLM that provides an inference API. This is a significant advantage over methods that require fine-tuning, as it makes FeatLLM compatible with the most capable and recently-proposed LLMs, including those that do not offer training codebases or tuning APIs. The training process for FeatLLM involves only 30 API queries, which does not impose a significant budget burden and can be parallelized. This makes the framework feasible for practitioners who rely on commercial LLM services and do not have the resources or access to fine-tune large models.

The third benefit is the mitigation of prompt size constraints. FeatLLM employs ensemble methods, specifically feature bagging, to handle datasets with large numbers of features or samples. In each trial, a subset of features and instances is selected, reducing the serialized text length to fit within the LLM's context window. The entire rule-extraction and model-training process is repeated multiple times (the paper uses 20 ensembles by default), and predictions are made by averaging the class probabilities across all trials. To introduce randomness and diversity across trials, a sufficiently high temperature is set for LLM inference, and the order of few-shot demonstrations is randomized. This ensemble approach offers two key advantages. First, even if the LLM generates incorrect rules in some trials, correct rules from other trials can compensate, enhancing overall robustness. This aligns with the concept of LLM self-consistency, where rules commonly inferred across multiple trials are more likely to be accurate. Second, the ensemble method directly addresses the prompt size limitation: while a single rule set might not capture the relationships of all features, the combination of various weak learners created across multiple trials can nullify the impact of incomplete feature or instance coverage in individual trials. Experimental results demonstrate that FeatLLM, employing both bagging and ensemble techniques, proves effective even on datasets with numerous features, where other LLM-based approaches fail to produce predictions altogether.

\title{Blogs about the Paper: "Byte Latent Transformer: Patches Scale Better Than Tokens"}

# Goodbye Tokenizers: How the Byte Latent Transformer is Rewriting the Rules of LLMs

Modern large language models (LLMs) are trained almost entirely end-to-end, but they still rely on a heuristic pre-processing step: tokenization. Tokenizers group raw bytes into a static set of tokens, which biases how text is compressed and processed. This seemingly innocuous step introduces several well-documented limitations, including domain and modality sensitivity, fragility to input noise, a lack of orthographic knowledge, and multilingual inequity. 

The Byte Latent Transformer (BLT) offers a way out. By learning directly from raw bytes, BLT eliminates the need for fixed-vocabulary tokenization entirely. For the first time, this byte-level architecture matches the performance of tokenization-based models at scale, while significantly improving both inference efficiency and robustness.

## The Problem with Fixed Tokenization

In a standard LLM, a tokenizer determines how a sequence of bytes is chunked into tokens before the model ever sees them. This creates a rigid computation structure. The model expends the same amount of compute on every token, regardless of whether it is predicting a highly predictable word ending or the critical first word of a new sentence.

Furthermore, tokenization forces a trade-off between vocabulary size and compute efficiency. Increasing the vocabulary size to create larger average tokens reduces the sequence length, but it drastically increases the size of the model's embedding and output projection layers. Because of this trade-off, token-based models have very little room to reduce their inference costs by changing token sizes.

## Dynamic Patching with Entropy

Instead of relying on a fixed vocabulary, BLT dynamically groups bytes into "patches." The core idea is to allocate compute where it is actually needed. To achieve this, BLT uses entropy patching.

First, a small byte-level auto-regressive language model is trained on the training data. This lightweight model computes the entropy of the next-byte prediction at each step, defined as:

$$H(x_i) = \sum_{v \in \mathcal{V}} p_{e}(x_i=v|\pmb{x}_{<i}) \log p_{e}(x_i=v|\pmb{x}_{<i})$$

If the entropy of a byte exceeds a certain threshold, BLT marks it as the start of a new patch. The model can use a global constraint, where a patch begins if $H(x_t) > \theta_g$, or an approximate monotonic constraint, where a patch begins if the entropy spikes relative to the previous byte: $H(x_t) - H(x_{t-1}) > \theta_r$. 

This approach creates contextualized groupings of bytes with relatively uniform information density. Predictable sequences (like repetitive boilerplate text or common word suffixes) are grouped into long patches, saving compute. High-entropy sequences (like the first character of a complex answer) trigger more frequent patch boundaries, allocating more model capacity to where the predictions are hardest.

## The BLT Architecture

To process these dynamic patches efficiently, BLT uses three distinct transformer blocks:

- **Local Encoder:** A lightweight model that maps raw input bytes into expressive patch representations. It uses hash n-gram embeddings to capture local context and a cross-attention layer to pool byte representations into patch representations.
- **Latent Global Transformer:** A large autoregressive transformer that processes the patch representations. Because it operates on patches rather than individual bytes, this is where the bulk of the compute is spent, but it is invoked much less frequently than a standard token-based model.
- **Local Decoder:** Another lightweight model that decodes the global patch representations back into raw bytes, using cross-attention where byte representations act as queries and patch representations act as keys and values.

## Scaling and Efficiency Gains

The paper presents the first FLOP-controlled scaling study of byte-level models up to 8B parameters and 4T training bytes. The results are striking: BLT matches the training FLOP-controlled performance of Llama 3 while using up to 50% fewer FLOPs at inference time.

BLT also unlocks a new dimension for scaling LLMs. Because longer patch sizes save compute, you can simultaneously increase the patch size and the size of the global latent transformer while maintaining a fixed inference budget. In fixed inference-cost scaling experiments, BLT models demonstrate significantly better scaling trends than tokenization-based architectures. As models grow larger, the compute share of the lightweight byte-level encoder and decoder shrinks relative to the global transformer, making larger patch sizes even more efficient.

## Robustness and Byte-Level Understanding

By directly working with raw bytes, BLT avoids the brittle nature of tokenizers and gains a deeper understanding of text. The paper highlights several areas where BLT outperforms token-based models:

- **Input Noise:** BLT is significantly more robust to character-level noising strategies (like dropping characters, repeating characters, or random casing) compared to Llama 3, outperforming it by an average of 8 points on noised benchmarks.
- **Character Manipulation:** On the CUTE benchmark, which tests orthographic knowledge and character manipulation, BLT outperforms BPE-based Llama 3 models by more than 25 points, achieving near-perfect scores on spelling tasks.
- **Phonology:** BLT outperforms baseline Llama 3 models on grapheme-to-phoneme (G2P) tasks, demonstrating an understanding of how characters map to pronunciation.
- **Low-Resource Translation:** BLT outperforms Llama 3 on translating into and out of lower-resource languages, proving that byte-level modeling generalizes better to the long-tail of data.

## Conclusion

Tokenization has long been a necessary evil in large language models, introducing fragility and multilingual inequity in exchange for manageable sequence lengths. The Byte Latent Transformer proves that we can train models end-to-end directly from bytes at scale without sacrificing performance. By dynamically allocating compute based on entropy, BLT not only solves the longstanding issues of tokenization but also redefines how we can scale LLMs efficiently.

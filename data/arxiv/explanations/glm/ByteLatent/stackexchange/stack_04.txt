\title{Stack Exchange of the Paper: "Byte Latent Transformer: Patches Scale Better Than Tokens"}

### What does the parameter $k$ represent in BLT's FLOP estimation, and why is $V=0$ for some components?
Question:
In Section 4.6, the FLOP estimation formula for BLT includes a parameter $k$ described as 'the ratio of patch-dimension to byte-dimension i.e. the number of local model splits that concatenate to form a global model representation ($k=2$ in Figure 3).' I don't understand what 'local model splits' means here. Also, the formula sets $V=0$ for the global transformer and encoder but $V=256$ for the decoder. I assume $V$ is the vocabulary size for the output projection — does this mean only the decoder produces byte predictions, and the global transformer has no output projection at all? How does the global transformer's output get used if it doesn't project to a vocabulary?
Answer:
The parameter $k$ represents the ratio of the global model's hidden dimension to the local model's hidden dimension, i.e., $k = h_{\mathcal{G}} / h_{\mathcal{E}}$. The phrase "local model splits that concatenate to form a global model representation" refers to the mechanism described in Section 3.2.1, where the cross-attention maintains patch representations as multiple heads of dimension $h_{\mathcal{E}}$ (the local model dimension) and then concatenates them into $h_{\mathcal{G}}$-dimensional representations for the global transformer. So when $k=2$, the global hidden dimension is twice the local hidden dimension, meaning two $h_{\mathcal{E}}$-sized heads are concatenated to form each $h_{\mathcal{G}}$-sized patch representation. This matters for FLOP estimation because the cross-attention layers must project between these two dimensions, and $k$ determines how many such projections occur per patch.

As for $V$, your intuition is correct. The $V$ parameter corresponds to the vocabulary size of the output projection (the final linear layer producing logits). In BLT's architecture, only the local decoder predicts actual bytes, so $V=256$ (the byte vocabulary size) appears only there. The global transformer and the local encoder do not project to a vocabulary at all — they produce continuous representations, hence $V=0$. The global transformer maps input patch representations $p_j$ to output patch representations $o_j$, which are not logits over any vocabulary. Similarly, the encoder maps bytes to patch representations without producing vocabulary predictions.

The global transformer's output is not discarded; rather, it is consumed by the local decoder through cross-attention. As described in Section 3.3.1, the decoder cross-attention uses byte representations as queries and the global model's output patch representations $o_j$ as keys and values. This allows each byte position to attend to the relevant patch representation and produce byte-level predictions. So the information flows as: bytes $\rightarrow$ encoder $\rightarrow$ patch representations $\rightarrow$ global transformer $\rightarrow$ output patch representations $\rightarrow$ decoder cross-attention $\rightarrow$ byte predictions. The global transformer serves as a latent computation space operating on patches, and the decoder is responsible for translating that latent representation back into the byte vocabulary.

This design is central to BLT's efficiency: the expensive global transformer runs once per patch rather than once per byte, and only the lightweight local decoder incurs the $V=256$ output projection cost at the byte level.

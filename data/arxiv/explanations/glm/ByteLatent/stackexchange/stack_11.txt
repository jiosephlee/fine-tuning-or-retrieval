\title{Stack Exchange of the Paper: "Byte Latent Transformer: Patches Scale Better Than Tokens"}

### What is 'entropy drift' and why does resetting context help?
Question:
In Section 4.4, the paper discusses using 'approximate monotonicity constraint' for the large-scale BLT-Entropy run because it 'suffers less from entropy drift from changes in context length.' They also reset the entropy model's context with new lines. I don't understand what 'entropy drift' means here. Is the entropy model's predicted entropy systematically biased by the length of its context window? Why would structured content like multiple choice tasks (mentioned in the MMLU example) cause progressively larger patches? And how does resetting the context with new lines fix this?
Answer:
The key to understanding "entropy drift" lies in how BLT's entropy patching works and how the small entropy model's predictions depend on its context window.

BLT segments bytes into patches based on the entropy of next-byte predictions from a small byte-level language model. A patch boundary is created when the entropy $H(x_t)$ crosses some threshold. The intuition is that high-entropy bytes (where the model is uncertain) deserve their own patch with dedicated compute, while low-entropy bytes (where the prediction is easy) can be grouped together.

"Entropy drift" refers to a systematic shift in the entropy model's predicted entropy values as a function of its context length. The entropy model is autoregressive — it computes $H(x_i) = \sum_{v \in \mathcal{V}} p_e(x_i = v \mid \mathbf{x}_{<i}) \log p_e(x_i = v \mid \mathbf{x}_{<i})$, meaning its prediction at position $i$ depends on everything it has seen so far. When the input contains repetitive, structured content — as is common in MMLU multiple-choice questions with their repeated "A. ... B. ... C. ... D. ..." format — the entropy model sees the same patterns recur within its context window. This drives its predicted entropies progressively lower, because the model becomes increasingly confident about what comes next after seeing the pattern multiple times. The longer the context, the more repetition it has observed, and the lower the entropy estimates become overall. This is the "drift."

With the **global entropy constraint** $H(x_t) > \theta_g$, patch boundaries are placed at absolute entropy values exceeding a fixed threshold $\theta_g$. If the entropy estimates drift downward due to accumulating repetitive context, fewer and fewer bytes exceed $\theta_g$, so patches grow progressively larger. This is problematic because the compute allocation becomes misaligned with actual prediction difficulty.

The **approximate monotonicity constraint** $H(x_t) - H(x_{t-1}) > \theta_r$ addresses this by looking at *relative* changes in entropy between consecutive bytes rather than absolute values. Even if the absolute entropy values drift downward due to context length, the local "jumps" in entropy — say, at the boundary between the end of one answer choice and the start of the next — remain relatively stable. A spike from a very low entropy region to a slightly higher one still triggers a boundary, regardless of whether the absolute scale of both values has shifted. This is why it "suffers less from entropy drift from changes in context length."

Resetting the entropy model's context at newlines provides a complementary fix. Instead of letting the context grow unboundedly across an entire document, the entropy model's context is truncated at each newline. This prevents the model from accumulating long histories of repetitive content, which is what causes the drift in the first place. Newlines are a natural choice because they typically correspond to structural boundaries in formatted text (especially in tasks like MMLU), making the reset semantically meaningful rather than arbitrary.

It is worth noting that this change only affects how entropies are *computed* for the patching decision; the threshold-finding procedure remains the same, and the main BLT model still processes the full context through its global transformer. The fix is purely about stabilizing the entropy estimates that drive patch boundary placement.

\title{Stack Exchange of the Paper: "Byte Latent Transformer: Patches Scale Better Than Tokens"}

### How can BLT simultaneously increase model size and patch size while keeping inference FLOPs fixed?
Question:
Section 5.3 of the BLT paper claims that BLT 'can simultaneously increase model size and patch size while maintaining the same inference flop budget.' I understand that larger patches mean the global latent transformer runs on fewer steps, which saves FLOPs. But if you increase the model size (more parameters in the global transformer), wouldn't each step become more expensive? How do these two effects cancel out exactly? The paper says longer patch sizes save compute 'which can be reallocated to grow the size of the global latent transformer, because it is run less often' — but this seems hand-wavy. Is there a precise mathematical relationship between patch size and model size that preserves FLOPs?
Answer:
The key insight is that in BLT's architecture, the global latent transformer and the local byte-level models have fundamentally different relationships with patch size, and this asymmetry is what enables the simultaneous scaling.

**The FLOPs decomposition**

From Section 4.5, the total FLOPs per byte for BLT decompose as:

$$\text{FL}_{\text{BLT per byte}} = \underbrace{\frac{2\,P_{\mathcal{G}}}{n_p}}_{\text{global transformer}} + \underbrace{2\,P_{\mathcal{E}} + 2\,P_{\mathcal{D}}}_{\text{local models}}$$

where $P_{\mathcal{G}}$, $P_{\mathcal{E}}$, $P_{\mathcal{D}}$ are the parameter counts of the global, encoder, and decoder models, and $n_p$ is the average patch size. The factor of $2$ approximates multiply-add operations per parameter per forward step (following standard Chinchilla-style FLOPs estimation). The crucial structural feature is that the global transformer FLOPs are divided by $n_p$ — it runs once per *patch*, not per *byte* — while the local encoder and decoder FLOPs are *not* divided by $n_p$, because they process every byte regardless of patch size.

**The scaling relationship**

To keep inference FLOPs per byte fixed while growing the global transformer, we need:

$$\frac{P_{\mathcal{G}}}{n_p} = \text{const}$$

This means if you scale the global transformer parameters by a factor $\alpha$, you scale the patch size by the same factor $\alpha$. The global transformer FLOPs per byte remain $2\,\alpha P_{\mathcal{G}} / (\alpha\, n_p) = 2\,P_{\mathcal{G}}/n_p$. This is the precise mathematical relationship the paper is relying on.

**Why this works for BLT but not for BPE**

The reason this trade-off is unavailable to tokenization-based models, as explained in Section 3.4, is that increasing the vocabulary size to get larger tokens also increases the size of the embedding table and output projection layer — which are part of the expensive main transformer and scale its FLOPs. In BLT, the byte-level vocabulary is fixed at $256$, and the output projection sits in the *small* local decoder, not the global transformer. So growing the global transformer and growing the patch size are independent levers that can be tuned against each other.

**The approximation and its limits**

This is not an *exact* cancellation because the local model FLOPs ($2\,P_{\mathcal{E}} + 2\,P_{\mathcal{D}}$) are constant regardless of patch size. At small scales, they constitute a non-trivial fraction of total FLOPs, so the cancellation is imperfect. However, the paper notes in Section 5.3 that "when growing total parameters $20\times$ from $400$M to $8$B, we only roughly double BLT's local model parameters." This means the local models' share of total FLOPs shrinks as you scale up, making the $\frac{P_{\mathcal{G}}}{n_p} = \text{const}$ relationship an increasingly accurate approximation. This is also why the patch-size-8 model's parameter multiplier relative to the baseline grew from $1.6\times$ to $1.7\times$ when moving to the larger scale — the fixed local model overhead became proportionally smaller, allowing slightly more global model growth within the same FLOP budget.

In summary, the "hand-wavy" claim reduces to a clean relationship: **global transformer parameters and patch size must scale proportionally** to preserve inference FLOPs, with the local models acting as a fixed overhead whose relative cost diminishes at scale.

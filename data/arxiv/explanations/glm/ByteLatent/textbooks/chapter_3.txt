Chapter 3: The BLT Architecture

## Architecture Overview: Global Autoregressive Model Plus Local Encoder and Decoder

The Byte Latent Transformer (BLT) is built upon a fundamental rethinking of how language models process raw byte sequences. Rather than relying on a fixed-vocabulary tokenizer that groups bytes into predefined tokens before training, BLT dynamically groups bytes into patches and processes these patches through a carefully designed three-component architecture. The key insight is that not all bytes require the same amount of computational effort: some bytes, such as the first character of a new word, involve high-entropy predictions that benefit from deep computation, while others, such as the ending bytes of a predictable word, are low-entropy and can be handled with much lighter computation. The architecture is designed to allocate compute accordingly.

At the highest level, BLT consists of three interconnected transformer-based modules. The first is a large **Latent Global Transformer** ($\mathcal{G}$), which serves as the primary computational engine of the model. This global model operates not on individual bytes, but on **patch representations**—compact, latent vectors that each encode a dynamically sized group of bytes. Because the global transformer processes patches rather than bytes, it runs far fewer computational steps than a byte-level model would require, yet it handles the most cognitively demanding predictions.

Flanking the global transformer are two smaller, lightweight models: the **Local Encoder** ($\mathcal{E}$) and the **Local Decoder** ($\mathcal{D}$). The local encoder's job is to take a sequence of raw input bytes and efficiently compress them into the patch representations that the global transformer consumes. The local decoder performs the inverse operation: it takes the output patch representations produced by the global transformer and expands them back into a sequence of raw bytes. Both local models have far fewer layers than the global transformer ($l_{\mathcal{E}} \ll l_{\mathcal{G}}$ and $l_{\mathcal{D}} \ll l_{\mathcal{G}}$), reflecting their role as efficient auxiliary modules rather than the primary reasoning engine.

This architectural decomposition is what enables BLT to achieve both the flexibility of byte-level modeling and the efficiency of token-level modeling. The global transformer concentrates expensive compute where it matters most—on the high-level, high-entropy decisions that occur at patch boundaries—while the local models handle the more routine, byte-level predictions at a fraction of the cost. The flow of information proceeds as follows: raw bytes enter the local encoder, which pools them into patch representations; the global transformer processes these patch representations autoregressively; and the local decoder expands the resulting output patch representations back into individual bytes. The global transformer consumes the bulk of the floating-point operations (FLOPs) during both pre-training and inference, so the choice of when to invoke it—determined by the patching scheme—directly controls the computational cost of the model.

## The Latent Global Transformer: Block-Causal Attention and the Main Computational Engine

The Latent Global Transformer, denoted $\mathcal{G}$, is the heart of the BLT architecture. It is an autoregressive transformer model with $l_{\mathcal{G}}$ layers that maps a sequence of latent input patch representations $\{p_j\}$ into a sequence of output patch representations $\{o_j\}$. The subscript $j$ is used throughout to index patches, while $i$ is reserved for indexing individual bytes—a convention that helps clarify which level of granularity the model is operating at. The global transformer's architecture closely follows that of modern transformer-based LLMs, with feed-forward layers and self-attention mechanisms that constitute the bulk of the model's parameters and computational cost.

A critical design choice is the **block-causal attention mask** used by the global transformer. In a standard causal (autoregressive) language model, each position in the sequence can attend to itself and all preceding positions, but not to any future positions. The block-causal mask extends this idea to the patch level: each patch representation can attend to all patches up to and including the current patch within the current document, but cannot attend to future patches or patches that belong to a different document. This ensures that the model remains autoregressive at the patch level—it can only use information from patches that have already been processed—and that document boundaries are respected, preventing information from leaking across separate documents during training.

The global transformer's role as the main computational engine cannot be overstated. Because the feed-forward network layers in a transformer are applied at every step of the sequence, and because these layers typically dominate the parameter count and FLOP count of large models, the number of steps at which the global transformer operates directly determines the model's computational cost. In a tokenization-based LLM, this number of steps is determined by the number of tokens, which is in turn determined by the tokenizer's vocabulary size—a fixed property set before training. In BLT, however, the number of steps is determined by the number of patches, which is controlled by the patching function. By dynamically selecting longer patches when the data is predictable and shorter patches when it is complex, BLT can allocate more compute to the global transformer exactly where it is needed, and less compute where the predictions are easy.

This dynamic allocation is what distinguishes BLT from both tokenization-based models and prior byte-level architectures. In a tokenization-based model, every token receives the same amount of computation regardless of whether it represents a high-entropy prediction (such as the first word of a sentence) or a low-entropy one (such as the suffix of a common word). In a naive byte-level model, every byte receives a full transformer step, which is prohibitively expensive at scale. BLT threads this needle by using the global transformer only at patch boundaries—points of high entropy where the model's predictive power is most needed—and delegating the remaining byte-level predictions to the more efficient local models.

## The Local Encoder: Lightweight Transformer with Cross-Attention for Pooling Bytes into Patch Representations

The Local Encoder, denoted $\mathcal{E}$, is responsible for transforming a sequence of raw input bytes into the patch representations that the global transformer consumes. It is a lightweight transformer-based model with $l_{\mathcal{E}}$ layers, where $l_{\mathcal{E}}$ is much smaller than $l_{\mathcal{G}}$, the number of layers in the global transformer. The encoder's architecture follows the standard transformer design but introduces a critical modification: the addition of a **cross-attention layer** after each transformer layer, whose function is to pool byte-level representations into patch-level representations.

The processing pipeline of the local encoder begins with the input bytes. Each byte $b_i$ is embedded using an embedding matrix of shape $\mathbb{R}^{256 \times h_{\mathcal{E}}}$, where 256 is the size of the byte vocabulary and $h_{\mathcal{E}}$ is the hidden dimensionality of the encoder. These initial embeddings, denoted $x_i$, capture only the identity of the individual byte at position $i$. To enrich these embeddings with contextual information about the surrounding bytes, the encoder augments them with **hash n-gram embeddings** before any transformer layers are applied—a technique discussed in detail in the next section.

After augmentation, the byte representations pass through a series of alternating **transformer layers** and **cross-attention layers**. The transformer layers in the encoder use a **local block-causal attention mask**: each byte attends to a fixed window of $w_{\mathcal{E}}$ preceding bytes. This windowed attention is a departure from the full block-causal attention used in the global transformer, and it reflects the encoder's role as a local, efficient processor. The window can cross dynamic patch boundaries—meaning a byte near the end of one patch can attend to bytes in the preceding patch—but it cannot cross document boundaries, ensuring that information does not leak between separate documents.

The cross-attention layers that follow each transformer layer are where the actual pooling from bytes to patches occurs. Each cross-attention layer takes the byte-level hidden representations produced by the preceding transformer layer and, using a query mechanism based on patch representations, aggregates the byte representations into updated patch representations. This design is inspired by the Perceiver architecture, with the key difference that in BLT, the "latent" representations correspond to variable, dynamically determined patches rather than a fixed set of latent vectors. Each patch query attends only to the bytes that belong to that specific patch, ensuring that the resulting patch representation faithfully encodes the information contained in its constituent bytes.

The output of the encoder is a set of patch representations $P \in \mathbb{R}^{n_p \times h_{\mathcal{G}}}$, where $n_p$ is the number of patches and $h_{\mathcal{G}}$ is the hidden dimensionality of the global transformer. These representations serve as the input to the global transformer. Because the encoder's hidden dimensionality $h_{\mathcal{E}}$ is typically smaller than $h_{\mathcal{G}}$, the cross-attention mechanism maintains the patch representations as multiple heads of dimension $h_{\mathcal{E}}$ during the attention computation, and concatenates them into $h_{\mathcal{G}}$ dimensions afterward. This design allows the encoder to operate efficiently at a smaller dimensionality while still producing representations that are compatible with the larger global transformer.

## Encoder Hash n-gram Embeddings: Incorporating Byte n-gram Context via Hash Functions and Embedding Tables

A key challenge in byte-level modeling is that individual bytes carry very little information on their own. A single byte value, such as the ASCII code for the letter "a," tells the model nothing about the surrounding context—is this "a" the start of a word, the middle of a word, or part of a longer sequence? In tokenization-based models, this problem is sidestepped because tokens already encode multi-byte subword units. In BLT, the local encoder must build up this contextual information from scratch, starting from individual bytes. The **hash n-gram embeddings** are a critical mechanism for doing so efficiently.

The idea is to model each byte $b_i$ not just individually, but also as part of a **byte n-gram**—a sequence of $n$ consecutive bytes ending at position $i$. For each byte position $i$ and each n-gram size $n$ from 3 to 8, the encoder constructs a byte-gram:

$$g_{i,n} = \{b_{i-n+1}, \ldots, b_i\}$$

These n-grams capture local context at multiple scales: a 3-gram might capture a common letter trigram like "ing," while an 8-gram might capture an entire short word or a meaningful subword unit. The n-gram sizes from 3 to 8 are chosen to cover a range of local contexts without being so large that the embedding tables become unwieldy or the n-grams become too sparse. When $i < n$, meaning there are not enough preceding bytes to form an n-gram of size $n$, that n-gram size is simply omitted for that position.

To represent these n-grams, the encoder uses **hash n-gram embeddings**. Each byte n-gram $g_{i,n}$ is mapped through a hash function to an index in a fixed-size embedding table $E_n^{hash}$, with a separate table for each n-gram size $n \in \{3, 4, 5, 6, 7, 8\}$. The hash function used is a **RollPolyHash**, and the index is computed as:

$$\text{Hash}(g_{i,n}) = \text{RollPolyHash}(g_{i,n}) \% |E_n^{hash}|$$

The use of hashing is a practical necessity: the number of possible n-grams grows exponentially with $n$, so maintaining a full embedding table for every possible n-gram would be infeasible. Hashing allows the encoder to use fixed-size embedding tables while still assigning distinct (or near-distinct) embeddings to most observed n-grams. The potential for hash collisions—where two different n-grams map to the same embedding—is mitigated by using sufficiently large embedding tables. In the paper's experiments, 500,000 hash entries with a single hash function are used for all BLT models.

The augmented embedding for byte position $i$ is then computed by summing the individual byte embedding with all the n-gram hash embeddings:

$$e_i = x_i + \sum_{n=3,\ldots,8} E_n^{hash}(\text{Hash}(g_{i,n}))$$

This sum is then normalized by dividing by the number of n-gram sizes plus one (to account for the individual byte embedding). The normalization ensures that the scale of the augmented embedding remains consistent regardless of how many n-gram sizes are applicable at a given position. The resulting normalized embedding $e_i$ is passed as input to the local encoder model.

The hash n-gram embeddings serve a role analogous to what tokenization provides in token-based models: they give the encoder access to local, multi-byte context from the very first layer. Without them, the encoder's transformer layers would need to build up this context entirely through attention, which would require more layers and more computation. Experiments in the paper show that hash embeddings are vital to bringing BLT's performance to match that of tokenizer-based models, with particularly strong benefits on Wikipedia and GitHub data. After approximately 300,000 hash entries, however, there are diminishing returns, and the gains from hash embeddings appear to be largely complementary with the gains from cross-attention, as they improve performance on different datasets.

## Encoder Multi-Headed Cross-Attention: Perceiver-Style Attention with Patch-Specific Masking and Pooling Initialization

The cross-attention mechanism in the local encoder is one of the most distinctive components of the BLT architecture. It is the mechanism by which byte-level representations are pooled into patch representations, and it is what allows the encoder to bridge the gap between the fine-grained byte level and the coarser patch level. The design closely follows the input cross-attention module of the **Perceiver architecture**, with one major difference: in the Perceiver, the latent representations are a fixed set of learned vectors, while in BLT, they correspond to variable, dynamically determined patch representations.

The cross-attention module operates on two sets of representations: **queries**, which correspond to patch representations, and **keys/values**, which correspond to byte representations from the preceding transformer layer. The query vector for each patch $p_j$ is initialized by **pooling** the byte representations corresponding to that patch—specifically, max-pooling is used in the paper's experiments—and then applying a linear projection $\mathcal{E}_C \in \mathbb{R}^{h_{\mathcal{E}} \times (h_{\mathcal{E}} \times U_{\mathcal{E}})}$, where $U_{\mathcal{E}}$ is the number of encoder cross-attention heads. Formally, if $f_{\text{bytes}}(p_j)$ denotes the sequence of bytes corresponding to patch $p_j$, then:

$$P_{0,j} = \mathcal{E}_C(f_{\text{bytes}}(p_j))$$

where $f$ is the pooling function. This initialization is important because it gives the cross-attention a meaningful starting point: rather than beginning with a random or fixed query, the query for each patch is initialized with information drawn from the very bytes it is meant to represent.

The cross-attention computation itself follows the standard scaled dot-product attention formula. At each cross-attention layer $l$, the patch representations are updated as:

$$P_l = P_{l-1} + W_o\left(\text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V\right)$$

where the queries, keys, and values are computed as:

$$Q_j = W_q(P_{l-1,j}), \quad K_i = W_k(h_{l-1,i}), \quad V_i = W_v(h_{l-1,i})$$

Here, $W_q$, $W_k$, $W_v$, and $W_o$ are the projection matrices for queries, keys, values, and the output, respectively. The keys and values are projections of the byte representations $h_{l-1,i}$ from the previous transformer layer (or the augmented embeddings $e_i$ for the first cross-attention layer). A crucial aspect of this design is the **patch-specific masking strategy**: each query $Q_j$ only attends to the keys and values that correspond to the bytes in patch $j$. This means that the cross-attention is not global—the representation for a given patch is computed solely from the bytes that constitute that patch, not from bytes belonging to other patches. This ensures that each patch representation faithfully encodes only the information from its constituent bytes.

Because the cross-attention uses multiple heads (following the standard multi-headed attention paradigm) and the patch representations have a larger dimensionality ($h_{\mathcal{G}}$) than the byte representations ($h_{\mathcal{E}}$), the design maintains $P_l$ as multiple heads of dimension $h_{\mathcal{E}}$ during the cross-attention computation. These heads are later concatenated into $h_{\mathcal{G}}$ dimensions, producing patch representations that are directly compatible with the global transformer. This dimensional upscaling through concatenation is an elegant way to bridge the smaller encoder and the larger global model without requiring expensive projection matrices.

Additional design details of the encoder cross-attention include the use of **pre-LayerNorm** on the queries, keys, and values before the attention computation, the absence of **positional embeddings** in the cross-attention module (since positional information is already captured by the byte representations from the transformer layers), and a **residual connection** around the cross-attention block, which allows the patch representations to accumulate information across multiple cross-attention layers while preserving the information from earlier layers.

## The Local Decoder: Decoding Global Patch Representations Back into Raw Bytes

The Local Decoder, denoted $\mathcal{D}$, performs the inverse operation of the local encoder: it takes the output patch representations produced by the global transformer and decodes them into a sequence of raw bytes. Like the encoder, the decoder is a lightweight transformer-based model with $l_{\mathcal{D}}$ layers, where $l_{\mathcal{D}} \ll l_{\mathcal{G}}$. Its role is to expand each patch representation back into the individual bytes that it represents, predicting the byte sequence autoregressively as a function of previously decoded bytes.

A key architectural difference between the decoder and the encoder is the order in which cross-attention and transformer layers are applied. In the encoder, the transformer layer is applied first (to process the byte representations), followed by the cross-attention layer (to pool bytes into patches). In the decoder, this order is **reversed**: the cross-attention layer is applied first, to create byte-level representations from the patch representations, and then the transformer layer operates on the resulting byte sequence. This ordering reflects the decoder's function: it must first "unpack" the patch representation into byte-level representations, and then process those byte-level representations to make byte-by-byte predictions.

The decoder takes as input not only the output patch representations $o_j$ from the global transformer, but also the **hidden representations produced by the local encoder** for the byte sequence. This is a crucial design choice: by reusing the encoder's hidden states, the decoder has access to the byte-level features that the encoder already computed, which provides valuable context for predicting the next bytes. Specifically, the initial byte representations for the decoder's cross-attention are initialized as the byte embeddings from the last encoder layer, denoted $h_{l_{\mathcal{E}}}$. This connection between the encoder and decoder means that information flows not only through the patch representations (via the global transformer) but also directly at the byte level, creating a richer information pathway.

The decoder predicts a sequence of raw bytes $y_i$ as a function of previously decoded bytes. Because it operates at the byte level, the decoder must produce output over the full byte vocabulary of size 256, which requires an output projection layer with a vocabulary dimension of 256. This is one of the few places in the BLT architecture where a vocabulary projection is needed, and it is much smaller than the vocabulary projections used in tokenization-based models (which typically have vocabularies of 32,000 to 128,000 tokens). The decoder's transformer layers use a local attention window of size $w_{\mathcal{D}}$, similar to the encoder's windowed attention, allowing each byte to attend to a fixed window of preceding bytes.

The decoder plays a critical role in BLT's efficiency. Because the global transformer operates at the patch level, it cannot directly produce byte-level predictions. The decoder fills this gap, but at a much lower computational cost than running the global transformer on every byte. The decoder's lightweight design—with few layers and a small hidden dimensionality—means that the cost of byte-level prediction is kept low, while the bulk of the model's reasoning capacity is concentrated in the global transformer's patch-level processing.

## Decoder Multi-Headed Cross-Attention: Reversed Query/Key-Value Roles Compared to the Encoder

The cross-attention mechanism in the local decoder mirrors that of the encoder, but with a critical inversion: the roles of queries and keys/values are **interchanged**. In the encoder cross-attention, the patch representations serve as queries, and the byte representations serve as keys and values—the model is asking, "for each patch, what information should I extract from the constituent bytes?" In the decoder cross-attention, the byte representations serve as queries, and the patch representations serve as keys and values—the model is asking, "for each byte, what information should I extract from the patch representation to help predict this byte?" This reversal reflects the decoder's function: rather than pooling bytes into patches, it must distribute patch-level information back out to the individual bytes.

The initial byte representations for the cross-attention are initialized as the byte embeddings from the last encoder layer, $h_{l_{\mathcal{E}}}$. This initialization provides the decoder with a starting point that already contains rich byte-level features computed by the encoder. The subsequent byte representations for each decoder layer $l$, denoted $d_{l,i}$, are computed through the following sequence of operations:

$$D_0 = h_{l_{\mathcal{E}}}$$

$$B_l = D_{l-1} + W_o\left(\text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V\right)$$

where the queries, keys, and values are:

$$Q_i = W_q(d_{l-1,i}), \quad K_j = W_k(\mathcal{D}_C(o_j)), \quad V_j = W_v(\mathcal{D}_C(o_j))$$

Here, $W_q$ is the query projection operating on the byte representations $d_{l-1}$ from the previous decoder transformer layer (or $h_{l_{\mathcal{E}}}$ for the first layer), while $W_k$ and $W_v$ are the key and value projection matrices operating on the patch representations $o_j$ from the global model, processed through a linear transformation and split operation $\mathcal{D}_C$. The output $B \in \mathbb{R}^{h_{\mathcal{D}} \times n_b}$, where $n_b$ is the number of output bytes, is then passed through a decoder transformer layer to produce the next decoder representations $D_l$.

As in the encoder cross-attention, the decoder cross-attention uses multiple heads, pre-LayerNorm on the queries, keys, and values, no positional embeddings, and a residual connection around the cross-attention module. The residual connection is particularly important here because it allows the decoder to retain the byte-level information from the encoder (initialized in $D_0$) while augmenting it with patch-level information from the global transformer's outputs.

The conceptual elegance of this design is that the decoder cross-attention acts as an information **broadcast** mechanism: the global transformer's patch representation, which encodes high-level information about the entire patch, is distributed to each byte within that patch through the attention mechanism. Each byte query attends to the patch key/value and extracts the information most relevant to predicting that particular byte. This allows the decoder to produce different byte predictions from the same patch representation, depending on the position of the byte within the patch and the context provided by previously decoded bytes.

## Architectural Details: SwiGLU, RoPE, RMSNorm, Flash Attention, and Flex Attention for Dynamic Masks

The transformer blocks in BLT—both the local models and the global transformer—largely follow the architecture of Llama 3, incorporating several modern design choices that have been shown to improve the performance and training stability of large language models.

The **SwiGLU activation function** is used in the feed-forward layers of all transformer blocks. SwiGLU is a gated linear unit that combines element-wise multiplication with a Gaussian Error Linear Unit (GELU) gating mechanism, providing a smooth, differentiable activation that has been shown to outperform standard ReLU or GELU activations in large-scale transformer models. The use of SwiGLU in the feed-forward layers is consistent across the local encoder, local decoder, and global transformer.

**Rotary Positional Embeddings (RoPE)** with a base frequency of $\theta = 500000$ are used, but only in the self-attention layers. RoPE encodes positional information by applying a rotation to the query and key vectors based on their position in the sequence, allowing the model to capture relative positional relationships without requiring explicit positional embedding parameters. The choice of $\theta = 500000$ follows the Llama 3 configuration. Importantly, RoPE is not used in the cross-attention layers, as positional information in those layers is already captured by the byte representations from the preceding transformer layers. The distinction between where RoPE is and is not applied reflects a careful design philosophy: positional embeddings are used where they add value (in self-attention, where the model needs to understand the relative positions of elements in the sequence) and omitted where they would be redundant (in cross-attention, where the positional information is already encoded in the input representations).

**RMSNorm** (Root Mean Square Normalization) is used for layer normalization throughout all transformer blocks. RMSNorm is a simplified variant of LayerNorm that normalizes by the root mean square of the activations without subtracting the mean, reducing computational cost while maintaining the benefits of normalization for training stability. The use of pre-normalization (applying normalization before the attention or feed-forward computation, rather than after) is standard in modern transformer architectures and is employed throughout BLT.

For attention implementation, BLT leverages two different technologies depending on the type of attention mask being used. **Flash Attention** is used for all self-attention layers that employ fixed, standard attention masks, such as the block-causal mask in the global transformer or the fixed-window block-causal mask in the local models. Flash Attention is a highly optimized implementation that reduces memory usage and improves speed by avoiding the materialization of the full attention matrix, making it essential for efficient training and inference at scale.

However, the cross-attention layers in the encoder and decoder present a unique challenge: they involve **dynamic, patch-dependent masks** that vary based on the specific patch boundaries in each input sequence. Unlike the fixed block-causal or windowed masks used in self-attention, the patch-specific masking in cross-attention cannot be precomputed or represented as a simple, regular pattern. To handle this efficiently, BLT uses **Flex Attention**, a PyTorch feature that allows for the creation of fused implementations of attention with arbitrary, dynamically determined masks. Flex Attention compiles the attention computation with the specific mask pattern into an efficient kernel, significantly speeding up training compared to a naive implementation that would need to apply the mask at runtime.

The window size for fixed-width attention masks is set to 512 bytes in both the local encoder and local decoder. This means that in the local models, each byte can attend to the 512 preceding bytes, providing a substantial local context window without the computational cost of full sequence-length attention. The global transformer, by contrast, uses full block-causal attention with no window restriction, as its sequence length (in patches) is much shorter and full attention is computationally feasible.

These architectural details, while individually consistent with modern transformer design, collectively contribute to BLT's ability to operate efficiently at the byte level. The combination of SwiGLU for expressive feed-forward computation, RoPE for positional awareness, RMSNorm for training stability, and the dual attention implementation strategy (Flash Attention for fixed masks, Flex Attention for dynamic masks) ensures that the model can be trained and deployed at scale without sacrificing the flexibility that comes from dynamic patching and byte-level modeling. The careful selection of which techniques to apply where—such as using RoPE only in self-attention and using windowed attention only in the local models—reflects a deep understanding of the different computational roles played by each component of the architecture.

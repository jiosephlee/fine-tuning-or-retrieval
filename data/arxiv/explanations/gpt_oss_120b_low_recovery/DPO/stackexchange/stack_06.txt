\title{Stack Exchange of the Paper: "Direct Preference Optimization: Your Language Model is Secretly a Reward Model"}

### How is the reference policy $\pi_{\text{ref}}$ chosen when an SFT model is unavailable, and what impact does this have on DPO performance?
Question:
Section 4 says that if $\pi^{\text{SFT}}$ is not available, they initialize $\pi_{\text{ref}}$ by maximizing the likelihood of preferred completions. How is this optimization performed in practice (e.g., number of epochs, data split)? Also, does using this proxy reference policy affect the KL‑penalty term or the theoretical guarantees of Theorem 1?
Answer:
In the DPO pipeline the reference policy **πref** plays the same rôle that the SFT model plays in classic RL‑HF: it anchors the fine‑tuned policy and appears inside the KL‑penalty of Eq. (3).  
When a pretrained SFT checkpoint is available the authors simply set  

\[
\pi_{\text{ref}}=\pi^{\text{SFT}},
\]

because the preference set 𝒟 was generated by sampling from that model, and the KL term therefore measures exactly the deviation from the distribution on which the (implicit) reward is calibrated.

### When an SFT model is missing

In many public benchmark collections the SFT checkpoint is not released.  Section 4 therefore proposes a *proxy* reference policy that is learned only from the **preferred** completions in 𝒟:

\[
\pi_{\text{ref}} = \arg\max_{\pi}\; \mathbb{E}_{(x,y_w)\sim\mathcal D}\bigl[\log \pi(y_w\mid x)\bigr].
\tag{8}
\]

In practice this is just a short supervised‑fine‑tuning run on the pairs \((x,y_w)\).  The authors do not prescribe a universal number of epochs because the optimum is reached very quickly on the usually small set of preferred completions.  In all of the experiments reported in the paper the reference model is trained for **one to three epochs** over the training split of 𝒟, using the same optimizer and learning‑rate schedule that would be used for ordinary SFT.  A standard 80/20 split (train/validation) is employed only to monitor over‑fitting; the validation loss is used to stop training early if it stops improving.  Because the objective (8) is a plain maximum‑likelihood loss, the hyper‑parameters are the same as for any language‑model fine‑tuning (e.g. batch size 32, learning rate ≈ 5 × 10⁻⁵ for a 1 B‑parameter model).  The authors report that extending the training beyond three epochs does not noticeably improve the KL‑distance to the true SFT distribution, but it can make πref overly sharp, which in turn reduces the flexibility of DPO.

### Effect on the KL‑penalty

The KL term in the original RL‑HF objective  

\[
\beta\,\mathrm{D}_{\mathrm{KL}}\bigl[\pi_{\theta}(\cdot\mid x)\,\Vert\,\pi_{\text{ref}}(\cdot\mid x)\bigr]
\]

depends only on the *relative* probabilities of the two policies; it does **not** require that πref be the exact SFT model, only that it be a reasonable approximation of the distribution from which the preference data were drawn.  By training πref on the preferred completions the authors obtain a policy that lives in the same support as the data and, importantly, assigns higher probability to the same examples that the human annotators marked as “good”.  Consequently the KL measured during DPO training still reflects how far the current policy has moved away from the **data‑generating** distribution, even though the reference is a surrogate.

Because πref is fitted by maximum‑likelihood, it tends to be *more concentrated* than a true SFT model (which is often trained on a much larger corpus).  This concentration makes the KL term slightly larger for a given change in πθ, effectively increasing the “cost of moving” in regions of the output space that were rarely seen during the reference‑model training.  In practice the authors found that this does **not** hurt performance: the DPO frontier in Figure 2 (sentiment‑generation experiment) is virtually unchanged whether πref is the genuine SFT checkpoint or the proxy obtained from (8).  The reason is that DPO’s loss (Eq. 7) already contains a per‑example importance weight—σ(ĥrθ(x,yl)−ĥrθ(x,yw))—that down‑weights updates on examples where the implicit reward is already correct, compensating for a tighter KL.

### Impact on the theoretical guarantees (Theorem 1)

Theorem 1 (stated as Theorem 2 in the appendix) asserts that for **any** reference policy πref the DPO loss is a maximum‑likelihood estimator of the Bradley‑Terry preference model and that the optimal solution of the KL‑constrained RL problem can be written as  

\[
\pi^{*}(y\mid x)=\frac{1}{Z(x)}\;\pi_{\text{ref}}(y\mid x)\,
\exp\!\bigl(\tfrac{1}{\beta}r^{*}(x,y)\bigr).
\tag{4}
\]

The proof only uses the fact that πref is a *distribution* over completions; it does not assume anything about how that distribution was obtained.  Consequently, replacing the true SFT model with a proxy trained on the preferred completions does **not** invalidate the theorem.  What changes is the *partition function* \(Z(x)\), because it now depends on the new πref, but the algebraic cancellation that leads to Eq. (6) (the DPO likelihood) still holds.  In other words, the same optimal policy π* is recovered, only expressed relative to a slightly different baseline.  

The only subtle point is that the equivalence class of reward functions (Lemma 2) is defined modulo an additive function of x.  When πref is altered, the additive term shifts accordingly, but the induced preference probabilities remain identical.  Hence the KL‑penalty still enforces the same deviation budget β, and the DPO optimisation continues to be a consistent estimator of the underlying human preference model.

### Summary

* **How the proxy πref is obtained:** a few epochs (1–3) of ordinary maximum‑likelihood fine‑tuning on the set of preferred \((x,y_w)\) pairs, using a standard train/validation split for early stopping.  
* **Effect on KL:** the KL is still computed against a well‑defined reference distribution; because the proxy is a tighter fit to the preferred data, the KL values may be modestly larger for the same policy change, but DPO’s per‑example weighting mitigates any adverse impact.  
* **Theoretical guarantees:** none of the proofs for Theorem 1 (or Theorem 2 in the appendix) rely on πref being the original SFT model, only on it being a probability distribution.  Therefore the consistency and optimal‑policy recovery results remain valid when the reference is the likelihood‑trained proxy.

In practice the authors observe negligible differences in the reward‑KL frontier when using the proxy reference, confirming that the DPO algorithm is robust to the absence of an explicit SFT checkpoint.

\title{Stack Exchange of the Paper: "FlashAttention-3: Fast and Accurate Attention with Asynchrony and Low-precision"}

### Why does incoherent processing (random orthogonal transform) not affect attention output?
Question:
In Section 4.2 the authors multiply Q and K by a random orthogonal matrix M before FP8 quantization, claiming that (Q M)(K M)^T = QK^T. I see that M M^T = I, but I am worried about numerical issues: does applying M change the distribution of values such that quantization error is reduced uniformly? How is M generated efficiently (they mention diagonal +/-1 and Hadamard), and does this extra multiplication cost affect performance?
Answer:
In the FP8 variant of FlashAttention‑3 the authors first **quantise** the query and key matrices block‑wise and then apply a *random orthogonal* matrix $M$ to both of them before the quantisation step.  
The crucial observation is that the attention scores are computed as the inner product  

$$
S = QK^{\top}\;,
$$

so that after the transform we obtain  

$$
(QM)(KM)^{\top}=QM\,M^{\top}Q^{\top}=QK^{\top},
$$

because $M$ is orthogonal and therefore $MM^{\top}=I$.  Hence the **exact real‑valued scores are unchanged**; any difference in the final output can only come from the subsequent FP8 quantisation and rounding.

### Why does this help quantisation?

When we quantise a matrix entry to FP8 we keep only three mantissa bits and four exponent bits (e4m3).  Large outlier values dominate the dynamic range of a whole tensor and force a coarse scaling factor, which in turn makes most “ordinary’’ values suffer a large relative error.  Multiplying by a random orthogonal matrix mixes every component of a row (or column) with all the others.  Concretely, each entry of $QM$ (or $KM$) is a weighted sum of many original entries with coefficients $\pm1$.  Because the signs are random, any single outlier is spread over many positions, and its contribution to any particular entry is reduced roughly by a factor of $\sqrt{d}$ (the length of the row).  Consequently the distribution of the transformed matrix becomes **more isotropic**: its entries have a smaller variance contrast and fit into a tighter range.  When we then apply block‑wise scaling, the same number of bits can represent the data with less absolute error, which is why the paper reports a $2.6\times$ reduction in root‑mean‑square error compared with per‑tensor scaling.

The transformation does **not** bias the result because the subsequent inner product cancels $M$.  It only changes the order in which rounding errors are introduced: errors now happen on quantities that are already “flattened’’ and therefore less sensitive to a single large outlier.

### How is $M$ generated efficiently?

A fully dense random orthogonal matrix would cost $O(d^{2})$ to apply, which would defeat any speed gain.  The authors follow prior work (e.g. QuIP) and construct $M$ as  

$$
M = D_{1}\,H\,D_{2},
$$

where  

* $D_{1}$ and $D_{2}$ are diagonal matrices with independent Rademacher entries ($\pm1$ with equal probability),  
* $H$ is the Walsh–Hadamard matrix.

The Hadamard matrix can be applied in place using the **Fast Walsh–Hadamard Transform (FWHT)**, which requires only $O(d \log d)$ additions/subtractions and no multiplications.  The diagonal sign flips are trivially fused into the same kernel (they are just conditional negations).  Because both $Q$ and $K$ are already being processed block‑wise, we can perform

1. Load a block of $Q$ (or $K$) into registers or shared memory,
2. Apply a vectorised sign‑flip,
3. Run one FWHT pass,
4. Apply the second sign‑flip,

all inside the same CUDA kernel that later quantises the block.  No separate memory allocation or extra kernel launch is needed, so the extra arithmetic cost is negligible compared with the dominant GEMM work.

### Does this extra multiplication hurt performance?

In practice it does not. The dominant cost of attention on Hopper is still the two GEMM operations performed by WGMMA (each reaching several hundred TFLOP/s).  The FWHT on a vector of length $d=64,\;128,\;256$ costs on the order of a few thousand floating‑point operations per block, i.e. less than 0.01 % of the FLOPs spent in the GEMMs.  Moreover, because the transform is fused with existing memory‑bound stages (loading $Q,K$), its latency is hidden behind asynchronous TMA loads and warp‑specialised pipelines described in Sections 4.2–4.3.

Empirically, Table 3 (the ablation on numerical error) shows that enabling incoherent processing improves accuracy without any measurable slowdown; runtime tables report identical TFLOP/s numbers for FP8 attention with and without incoherent processing.

### Summary

* Multiplying both $Q$ and $K$ by an orthogonal matrix leaves exact attention scores unchanged because $(QM)(KM)^{\top}=QK^{\top}$.  
* The random orthogonal transform spreads out large outliers, yielding a more uniform distribution that can be quantised with lower absolute error under FP8’s limited mantissa/exponent range.  
* By constructing $M = D_{1}HD_{2}$ we can apply it in $O(d \log d)$ time using cheap sign flips and an in‑place Hadamard transform; this work is fused into existing kernels, so it adds virtually no overhead.  
* Consequently incoherent processing reduces FP8 numerical error (by up to $2.6\times$ in their experiments) while keeping performance essentially unchanged.

\title{Stack Exchange of the Paper: "FlashAttention-3: Fast and Accurate Attention with Asynchrony and Low-precision"}

### How does block quantization reduce FP8 quantization error compared to per‑tensor scaling?
Question:
The paper reports a 2.6× accuracy improvement for FP8 FlashAttention‑3 using block quantization. I understand per‑tensor scaling keeps a single scale factor for an entire Q/K/V matrix, but I'm not sure why splitting into blocks (e.g., B_r×d) helps with outliers. Does each block get its own exponent bias? How is the scaling factor computed per block without incurring extra memory bandwidth? Also, how does this interact with the subsequent softmax rescaling step?
Answer:
**Answer**

In the FP8 version of FlashAttention‑3 the authors replace the naïve *per‑tensor* quantisation (one scale for the whole $Q$, $K$ or $V$ matrix) with a *block‑wise* scheme.  
The improvement comes from the fact that the matrices that enter the attention score product are highly non‑uniform: a few rows (or columns) contain “outlier’’ values that are orders of magnitude larger than the bulk of the data. When a single scale is used, the scale must be chosen large enough to accommodate those outliers; everything else is then represented with very few mantissa bits and suffers a large relative error. By splitting the tensor into smaller tiles we can choose a different scale for each tile, so that most tiles are quantised with a scale that matches their local dynamic range. Consequently the round‑off error of each tile is dramatically reduced and, after the two matrix multiplications, the accumulated error in the soft‑max scores $\mathbf S = QK^{\top}$ is much smaller.

---

### How block quantisation works internally

1. **Tile definition** – The attention kernel already processes $Q$ and $K$ in blocks of size $B_{r}\times d$ (rows of queries) and $B_{c}\times d$ (rows of keys). The same tiling is reused for quantisation: each block gets its own scalar *exponent bias* (the FP8 exponent field after biasing), i.e. its own scale factor $\sigma_{b}$.

2. **Scale computation** – For a given block $\mathbf X_{b}$ (either a $Q$- or $K$-block) we compute
   $$
   \sigma_{b}= 2^{\,\lceil \log_{2}\bigl(\max(|\mathbf X_{b}|)\bigr)\rceil - 3},
   $$
   which is exactly the exponent bias that would be stored in an FP8 e4m3 number that can represent the largest absolute value in that block. The operation is a simple reduction (max‑abs) over the block and can be performed while the block is already resident in shared memory; it does **not** incur extra global‑memory traffic because the reduction uses registers and SMEM that are needed anyway for the GEMM.

3. **Quantisation** – The block is then converted to FP8 by dividing by its own $\sigma_{b}$ and rounding to nearest e4m3 value. Since each block uses its own bias, no additional “bias‑vector’’ has to be stored: the bias lives only in registers during the GEMM.

4. **No extra bandwidth** – The algorithm never writes back a per‑block scaling table to global memory. All scaling factors are kept in registers (one per warp or per thread‑block) and applied on‑the‑fly when loading the operands for the WGMMA instruction. The extra work is therefore only a handful of extra arithmetic instructions per tile, which is negligible compared to the cost of the matrix multiplication.

---

### Interaction with the softmax rescaling

After the first GEMM we have
$$
\mathbf S^{(b)} = (Q_{b}/\sigma^{Q}_{b})\, (K_{c}/\sigma^{K}_{c})^{\top}\;,
$$
where $\sigma^{Q}_{b}$ and $\sigma^{K}_{c}$ are the block scales for query block $b$ and key block $c$. The product therefore carries an *implicit* overall scale
$$
\sigma^{S}_{bc}= \sigma^{Q}_{b}\,\sigma^{K}_{c}.
$$
When we compute the row‑wise max and exponential for softmax we first undo this implicit scale:
* we multiply each entry of $\mathbf S^{(b)}$ by $\sigma^{S}_{bc}^{-1}$; this is just a single fused‑multiply‑add with a scalar stored in a register,
* then we perform `rowmax`, subtract it, exponentiate, and accumulate as usual.

Because every block pair uses its own $\sigma^{S}_{bc}$, there is no “global” overflow or underflow in any row of $\mathbf S$. The softmax rescaling step therefore receives values that are already centred around zero with a well‑behaved magnitude, which makes the subsequent FP16 exponential more accurate.

---

### Why this reduces error compared with per‑tensor scaling

* With per‑tensor scaling we would have one global factor $\sigma^{Q}$ for all queries and one $\sigma^{K}$ for all keys. If an outlier appears in any row, those two factors must be increased enough to avoid clipping; every other element then loses up to three mantissa bits (FP8 e4m3 has only three bits of precision).  
* Block scaling adapts locally: only blocks that actually contain large values receive a large $\sigma$; all other blocks keep a smaller exponent bias and retain more mantissa resolution. The quantisation error on each block scales roughly as
  $$
  \varepsilon_{\text{block}}\;\approx\;2^{-3}\,\sigma_{b},
  $$
  which is far smaller for “normal’’ blocks than for a single global scale.
* Since attention scores are formed by summing many products across blocks, reducing the per‑product error translates directly into lower variance of $\mathbf S$. The experiments in §5.3 confirm that this yields a **2.6 × lower RMSE** on an FP8 baseline that uses per‑tensor scaling.

---

### Summary

Block quantisation in FlashAttention‑3 works by aligning the quantisation granularity with the algorithm’s natural tiling: each $B_{r}\times d$ or $B_{c}\times d$ tile receives its own FP8 exponent bias computed from a cheap max‑abs reduction while residing in shared memory. No additional global memory traffic is introduced because scales stay in registers and are applied during loading for WGMMA. During softmax we simply renormalise each score tile by its implicit product scale before applying row‑wise max/subtract/exp, preserving numerical stability. This local adaptation eliminates the need to inflate a single global scale to accommodate rare outliers, thereby keeping most values within FP8’s three mantissa bits and achieving dramatically lower quantisation error—exactly what leads to the reported 2.6 × accuracy improvement over per‑tensor scaling.

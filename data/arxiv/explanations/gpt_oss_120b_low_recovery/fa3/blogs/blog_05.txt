## 1. Quick Primer on What FlashAttention‑3 Gives You  

| Feature | What it means for you |
|---------|----------------------|
| **Producer–consumer warp specialization** | Data movement (Tensor Memory Accelerator, TMA) and matmul (WGMMA) run on separate warp groups, hiding memory latency. |
| **2‑stage GEMM–softmax pipelining** | While one block of **Q·Kᵀ** is being multiplied, the softmax for the previous block is executed, keeping the Tensor Cores busy > 70 % of the time (≈ 740 TFLOP/s FP16 on H100). |
| **FP8 Tensor‑Core support** | Near‑doubling of raw FLOP throughput (≈ 1.2 PFLOP/s) with only a modest 2.6× reduction in RMSE compared to naïve FP8 quantization, thanks to block‑wise scaling and an orthogonal “incoherent processing” step. |
| **Exact attention** | No approximation—same mathematical definition as vanilla softmax attention, just a fused kernel that never writes the intermediate score matrix to global memory. |

All of this lives inside a single CUDA kernel that you can call from Python just like `torch.nn.functional.scaled_dot_product_attention`. The API mirrors the original FlashAttention‑2 so migrating code is painless.

## 2. Installing the Library  

The repository is hosted at https://github.com/Dao-AILab/flash-attention and released under a permissive MIT license.

```bash
# 1️⃣ Clone the repo
git clone https://github.com/Dao-AILab/flash-attention.git
cd flash-attention

# 2️⃣ Install building dependencies (requires CUDA 12.x and a recent GCC)
conda create -n flash3 python=3.11 pytorch torchvision torchaudio -c pytorch -c nvidia
conda activate flash3
conda install -c nvidia cuda-nvcc cuda-cudart-dev   # adjusts to your driver version

# 3️⃣ Build the extension (automatically detects Hopper/H100)
pip install -e .
```

The build script picks up `--arch=sm90` when it sees an H100 GPU; otherwise it falls back to a CPU stub that raises an informative error. If you are on a multi‑GPU node with a mix of Hopper and older cards, set `TORCH_CUDA_ARCH_LIST=90` before running `pip install`.

> **Tip:** The first build may take a few minutes because CUTLASS is compiled from source to expose the new WGMMA and TMA intrinsics. Subsequent builds are incremental.

## 3. Enabling FP16 vs. FP8  

FlashAttention‑3 supports two precision modes out of the box:

```python
import torch
from flash_attn import flash_attn_func

# Q, K, V are (B, N, D) tensors in fp16 or fp8_e4m3
Q = torch.randn(batch, seq_len, d_head, dtype=torch.float16, device='cuda')
K = torch.randn_like(Q)
V = torch.randn_like(Q)

# ---- FP16 (default) -------------------------------------------------
out_fp16 = flash_attn_func(
    Q, K, V,
    dropout_p=0.0,
    softmax_scale=1.0 / math.sqrt(d_head),
    causal=False,
    dtype=torch.float16          # <‑ tells FlashAttention-3 to stay in fp16
)

# ---- FP8 ------------------------------------------------------------
# First we need to quantize Q/K/V blockwise; helper is provided:
from flash_attn import quantize_fp8_blockwise

Q8, scale_q = quantize_fp8_blockwise(Q)
K8, scale_k = quantize_fp8_blockwise(K)
V8, scale_v = quantize_fp8_blockwise(V)

out_fp8 = flash_attn_func(
    Q8, K8, V8,
    dropout_p=0.0,
    softmax_scale=1.0 / math.sqrt(d_head),
    causal=False,
    dtype=torch.float8_e4m3   # selects FP8 WGMMA path
)

# Dequantize if you need fp16 output:
out_fp8 = out_fp8 * (scale_q * scale_k * scale_v).view(1,-1,1)
```

*What’s happening under the hood?*  
- In FP16 mode the kernel keeps the accumulator in FP32 (as shown in the paper) and only writes back FP16 results—this matches FlashAttention‑2’s numerical profile.
- In FP8 mode each block of `Q`, `K`, `V` gets its own scaling factor (`scale_*`). This is **block quantization**, which dramatically reduces error for outlier values (the paper reports 2.6× lower RMSE).  
- The orthogonal “incoherent processing” matrix `M` is baked into `quantize_fp8_blockwise`; you don’t need to call it manually.

## 4. Wiring FlashAttention‑3 into Existing Transformers  

Most transformer implementations already call either PyTorch’s native `scaled_dot_product_attention` or an older FlashAttention wrapper. Replacing those calls with `flash_attn_func` is usually a single line change.

### 4.1 Vanilla PyTorch Example  

```python
class MySelfAttn(torch.nn.Module):
    def __init__(self, dim, n_heads):
        super().__init__()
        self.n_heads = n_heads
        self.head_dim = dim // n_heads
        self.qkv_proj = torch.nn.Linear(dim, dim * 3, bias=False)

    def forward(self, x):
        B, N, _ = x.shape
        qkv = self.qkv_proj(x)                         # (B,N,3*dim)
        qkv = qkv.reshape(B,N,self.n_heads,self.head_dim*3)
        Q,K,V = qkv.unbind(-1)                         # each: (B,N,n_heads,head_dim)

        # Collapse batch & heads for FlashAttention API
        Q = Q.transpose(1,2).reshape(-1,N,self.head_dim)   # (B*n_heads,N,d_h)
        K = K.transpose(1,2).reshape(-1,N,self.head_dim)
        V = V.transpose(1,2).reshape(-1,N,self.head_dim)

        out = flash_attn_func(
            Q,K,V,
            dropout_p=0.0,
            softmax_scale=1.0 / math.sqrt(self.head_dim),
            causal=False,
            dtype=Q.dtype
        )   # returns (B*n_heads,N,d_h)

        # Reshape back
        out = out.reshape(B,self.n_heads,N,self.head_dim).transpose(1,2)
        return out.reshape(B,N,-1)
```

Only three things changed from a naïve implementation:
1. **Reshape / transpose** so each head becomes its own batch dimension – this matches how FlashAttention expects its inputs.
2. **Pass `dtype`** to select FP16 vs FP8 automatically.
3. **Dropout handling** – FlashAttention‑3 implements dropout internally; set `dropout_p` accordingly.

### 4.2 🤗 Transformers Integration  

If you are using Hugging Face’s `transformers`, simply replace the existing attention class:

```python
from transformers.models.gpt2.modeling_gpt2 import GPT2Attention

class GPT2FlashAttention(GPT2Attention):
    def _attn(self,
              query: torch.Tensor,
              key: torch.Tensor,
              value: torch.Tensor,
              attention_mask: Optional[torch.Tensor] = None,
              head_mask: Optional[torch.Tensor] = None,
              output_attentions: bool = False):
        # query/key/value already have shape (B,N,n_head,d_h)
        B,n_head,N,d_h = query.shape
        # collapse batch & heads for kernel call
        q = query.reshape(B*n_head,N,d_h)
        k = key.reshape(B*n_head,N,d_h)
        v = value.reshape(B*n_head,N,d_h)

        # causal mask handling – use causal=True flag if mask is triangular
        causal = attention_mask is not None and attention_mask.dtype == torch.bool

        attn_output = flash_attn_func(
            q,k,v,
            dropout_p=self.attention_dropout.p if self.training else 0.0,
            softmax_scale=self.scale_attention,
            causal=causal,
            dtype=q.dtype)

        # reshape back
        attn_output = attn_output.view(B,n_head,N,d_h).transpose(1,2).contiguous()
        return attn_output.view(B,N,-1), None   # we ignore weights for efficiency
```

Now every forward pass through a GPT‑style model will invoke the fused kernel automatically. The same pattern works for BERT (`BertSelfAttention`) or Vision Transformers—just adjust how you flatten batch × heads.

## 5. Troubleshooting Common Scenarios  

### 5.1 Sequence Length Too Short  

FlashAttention benefits from tiling; very short sequences (< 256 tokens) may not fill a full tile and can fall back to lower occupancy. In practice:

- **What you’ll see:** TFLOP counts drop below 400 TFLOP/s; latency may be comparable to standard PyTorch.
- **Fix:** Pad your input to at least one tile size (`B_r` or `B_c`, typically 128–256). Padding cost is negligible compared with the huge speed gain on longer runs.

```python
def pad_to_tile(tensor, tile=256):
    seq_len = tensor.size(1)
    if seq_len % tile == 0:
        return tensor
    pad_len = tile - (seq_len % tile)
    return torch.nn.functional.pad(tensor,(0,0,0,pad_len))
```

### 5.2 Causal Masking Overhead  

The paper reports that causal masking adds about a 20 % slowdown because half of the score matrix is omitted but we still have to compute max/reduce per row. In FlashAttention‑3:

- The kernel has a dedicated fast path (`causal=True`) that skips loading future key/value blocks.
- If you notice more than a ~30 % slowdown compared with non‑causal runs, make sure:
  1. You are passing `causal=True` rather than supplying an explicit boolean mask tensor.
  2. Your sequence length aligns with the tile size; otherwise extra boundary checks dominate.

### 5.3 Running on Non‑Hopper GPUs  

FlashAttention‑3 gracefully degrades:

- On Ampere (`sm80`) it runs using legacy WGMMA instructions without FP8 support.
- On older architectures it falls back to an emulated kernel that still avoids materializing `S`. Performance will be similar to FlashAttention‑2 but you won’t get the ~75 % utilization bump.

Set CUDA arch explicitly if automatic detection fails:

```bash
export TORCH_CUDA_ARCH_LIST=80   # for A100s
pip install -e .                # rebuild after changing env var
```

### 5.4 Mixed Precision Training Pitfalls  

When training large language models you typically keep model parameters in BF16 or FP16 while activations flow through attention in FP32 accumulators:

- **FlashAttention‑3 already does this for FP16** (the paper’s Table 1 shows identical RMSE to FlashAttention‑2).
- For **FP8 training**, remember that loss scaling must be applied *after* dequantization because gradients are accumulated in higher precision (`dtype=torch.float32`). A simple pattern:

```python
loss_scale = 256.0          # typical value for FP8
output_fp8 = flash_attn_func(... dtype=torch.float8_e4m3)
output_fp32 = output_fp8 * combined_scale   # dequantize as shown earlier

loss = loss_fn(output_fp32.float(), target)
scaled_loss = loss * loss_scale
scaled_loss.backward()
for p in model.parameters():
    p.grad.data /= loss_scale     # unscale before optimizer step
```

## 6️⃣ Verifying Correctness & Performance  

A quick sanity check after integration:

```python
import timeit
def bench(fn):
    t = timeit.timeit(lambda: fn(), number=20) / 20 * 1000   # ms per forward pass
    print(f"Avg latency: {t:.2f} ms")

# Baseline PyTorch sdpa (FP16)
def baseline():
    torch.nn.functional.scaled_dot_product_attention(Q,K,V,
                                                     dropout_p=0.,
                                                     scale=1./math.sqrt(d_head),
                                                     is_causal=False)

# FlashAttention‑3 (FP16)
def flash():
    flash_attn_func(Q,K,V,
                    dropout_p=0.,
                    softmax_scale=1./math.sqrt(d_head),
                    causal=False,
                    dtype=torch.float16)

bench(baseline)   # ~7 ms on H100 for seq_len=8192
bench(flash)      # ~4 ms → ≈ 75 % speedup as reported in the paper
```

For reproducibility we recommend fixing random seeds (`torch.manual_seed(42)`), using deterministic kernels (`torch.backends.cudnn.deterministic=True`) and comparing RMSE against a high‑precision reference (`torch.float64`) as done in Section 6 of the paper.

## 7️⃣ Going Further: Custom Block Sizes & Persistent Kernels  

The default tiling parameters (`B_r`, `B_c`) are chosen automatically based on head dimension and sequence length (the authors tuned them for TFLOPs/max occupancy). If you have very large batches or unusual head sizes you can override them via environment variables:

```bash
export FLASH_ATTN_BLOCK_Q=256   # forces query block size B_r=256
export FLASH_ATTN_BLOCK_KV=128   # forces key/value block size B_c=128
```

Persistent kernels—where one CTA stays resident across many token blocks—are already enabled for FP16 paths; they are under development for FP8 due to extra register pressure (see Section 7 of the paper). Keep an eye on future releases if you need ultra‑low latency inference on short prompts.

\title{A Textbook about the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

Chapter 10: # Ablation Studies and Component Analysis

Understanding why a machine‑learning system works often requires more than just reporting its overall performance.  
In the **FeatLLM** framework, several novel choices are intertwined: a two‑step reasoning prompt, explicit natural‑language feature descriptions, extraction of a fixed set of logical rules, a lightweight linear model that learns non‑negative weights for those rules, and an ensemble that combines many such rule‑based learners using feature‑bagging.  
To verify that each of these ingredients truly contributes to the observed gains, the authors carried out a series of *ablation experiments*.  An ablation removes or modifies one component while keeping the rest of the pipeline fixed, allowing a clean comparison of the impact of that component.  
In this chapter we walk through each ablation, explain the motivation behind it, describe how it was performed, and interpret the resulting changes in performance across different few‑shot regimes (2‑shot, 4‑shot, 8‑shot, etc.).  The goal is to give the reader an intuitive sense of why each design decision matters and how they interact.

---

## Removing Weight Tuning vs. Simple Rule Count

### What the original design does
After the LLM has produced a set of binary rule‑based features \(\mathbf{z}_k^i \in \{0,1\}^R\) for each class \(k\), FeatLLM does **not** treat all rules as equally informative.  
Instead, it trains a *linear* model without bias:

\[
\text{logit}_k^i \;=\; \max(\mathbf{w}_k,0)\cdot \mathbf{z}_k^i,
\qquad
\mathbf{p}^i \;=\; \operatorname{Softmax}\big([\text{logit}_1^i,\dots,\text{logit}_c^i]\big),
\]

where \(\mathbf{w}_k\) are trainable, non‑negative weights learned by minimizing the cross‑entropy loss on the few labeled examples.  
The projection \(\max(\mathbf{w}_k,0)\) guarantees that a rule can only increase, never decrease, the logit for its class.  This step allows the system to **up‑weight** highly predictive rules and effectively discard noisy ones (weights near zero).

### The ablation
In the *‑Tuning* ablation the linear weights are omitted.  The logit for a class is simply the *sum* of its satisfied rules:

\[
\text{logit}_k^i \;=\; \sum_{r=1}^{R} z_{k,r}^i .
\]

No learning occurs; the model merely counts how many rules each sample satisfies.

### Why this matters
If the raw rule set already captures most of the signal, counting may be sufficient.  However, the LLM can generate *redundant* or *partially correct* rules, especially when the prompt contains many features or when the few‑shot examples are noisy.  A learned weighting scheme can differentiate:

- **Highly predictive rules** (e.g., “age > 65 AND cholesterol > 240”) receive a large weight.
- **Ambiguous or generic rules** (e.g., “gender is male”) receive a small weight.

By removing this step, we expect performance to degrade, particularly when more training shots are available, because the extra data make the weight estimation more reliable.

### Empirical findings
Across all 13 benchmark datasets, the *‑Tuning* ablation caused a **consistent drop** in area‑under‑the‑curve (AUC).  The magnitude of the drop grew with the number of shots: with 2 shots the loss was modest (≈ 0.5 % absolute AUC), while with 8 shots the loss reached up to 2 % absolute AUC on some datasets.  This pattern matches the intuition that richer supervision lets the linear model learn more accurate importance scores, amplifying the benefit of weight tuning.

## No Ensemble / No Bagging

### The original ensemble strategy
FeatLLM repeats the entire rule‑extraction pipeline \(T\) times (the default \(T=20\)).  For each repetition it:
1. Randomly *bags* a subset of the original columns (feature bagging) and/or a subset of the few‑shot examples,
2. Queries the LLM with a higher temperature (e.g., 0.5) to encourage diverse rule sets,
3. Trains a separate linear weight vector \(\mathbf{w}[t]\).

The final class probability for a test sample is the average of the softmax outputs from all \(T\) learners.  This process mirrors classic ensemble methods such as random forests: each weak learner may be imperfect, but their average reduces variance and mitigates systematic errors.

### The ablation
In the *‑Ensemble* ablation the pipeline is run **once** only, with no bagging and no averaging.  Consequently, the model relies on a single rule set and a single weight vector.

### Why this matters
Two failure modes are addressed by ensembling:

1. **Prompt‑size constraints** – When the original table has many columns, a single prompt may need to truncate or omit some features.  Bagging ensures each feature appears in at least some prompts, allowing the LLM to generate rules that involve the whole feature space across the ensemble.
2. **LLM stochasticity** – Even with a deterministic temperature, the LLM can produce different rule sets depending on the order of the few‑shot examples.  Averaging over many draws smooths out idiosyncratic, possibly incorrect rules.

### Empirical findings
Eliminating the ensemble reduced the average AUC by about **1–3 % absolute** across datasets, with the greatest penalties on the *high‑dimensional* datasets (e.g., *Communities* and *Myocardial*).  In those cases, a single prompt could not accommodate all columns; the bagging mechanism restored coverage in the full FeatLLM system, explaining the larger gap.

## Omitting Feature Descriptions

### What the description provides
Each column name \(f_j\) is accompanied by a short natural‑language definition (e.g., “*age*: integer representing years of the patient”).  The prompt also indicates the value type (numeric, categorical, binary).  This information serves two purposes:

1. **Disambiguation** – The LLM can correctly interpret “high”, “low”, “yes”, “no”, etc., according to the column’s type.
2. **Prior knowledge activation** – The description can trigger relevant world knowledge (“*cholesterol* is a risk factor for heart disease”).

### The ablation
The *‑Description* variant removes all feature definitions from the prompt, retaining only the column names and their serialized values.

### Why this matters
Without a definition, the LLM must infer the semantics of a column solely from its name and the few examples.  For ambiguous or domain‑specific names (e.g., “*G*” in a genetics dataset), the model may generate ill‑formed or mis‑typed rules (e.g., treating a categorical variable as numeric).  Moreover, the LLM loses the chance to inject relevant domain knowledge.

### Empirical findings
The omission caused a noticeable AUC decrease, especially in the **2‑shot** and **4‑shot** regimes where the few examples provide very limited statistical evidence.  Average losses of **0.8–1.5 %** were observed.  When more shots were available, the drop shrank because the data themselves began to dominate the LLM’s reasoning, but the gap never vanished entirely, underscoring the lasting value of explicit descriptions.

## Skipping the First Reasoning Step

### Two‑step reasoning prompt
FeatLLM’s prompt contains a *reasoning instruction* that splits the LLM’s thought process:

1. **Step 1 – Causal inference** – The LLM is asked to think about the *general relationship* between features and the task, without looking at the few‑shot examples.  This encourages the model to rely on its broad prior knowledge (e.g., “older age generally increases risk of heart disease”).
2. **Step 2 – Rule extraction** – Using the causal insight from Step 1 together with the concrete examples, the LLM then formulates explicit logical rules for each class.

The separation is designed to prevent the LLM from latching onto spurious correlations that only appear in the tiny demonstration set.

### The ablation
In the *‑Reasoning* version, Step 1 is **removed**; the LLM jumps straight to rule formulation using the examples alone.

### Why this matters
When only a few labeled rows are shown, random coincidences (e.g., “all training samples with label = 1 happen to have gender = female”) can mislead a model that does not first consider general domain knowledge.  By forcing the LLM to articulate a *prior* causal map, FeatLLM biases the rule‑generation toward features that are globally relevant.

### Empirical findings
The impact of dropping Step 1 is most severe in the **lowest‑shot** settings.  With 2 shots, the AUC loss averaged **≈ 2 %** absolute, indicating that many generated rule sets became dominated by dataset‑specific noise.  As the number of shots increased to 8, the loss shrank to about **0.5 %**, reflecting that sufficient examples can partially compensate for the missing prior reasoning.  Nevertheless, the presence of Step 1 consistently improved robustness across all datasets.

## Interpreting Results Across Shot Numbers

The ablation study reports performance for several *k‑shot* configurations (commonly 2, 4, and 8).  Examining how each component behaves as the amount of labeled data changes yields deeper insight:

| Component | Effect at 2‑shot | Effect at 4‑shot | Effect at 8‑shot |
|-----------|------------------|------------------|------------------|
| Weight tuning | Small improvement (≈ 0.5 % AUC) | Moderate (≈ 1 % AUC) | Larger (≈ 2 % AUC) |
| Ensemble / bagging | Very important (≈ 2–3 % AUC) | Important (≈ 1–2 % AUC) | Still helpful but smaller gain |
| Feature descriptions | Noticeable (≈ 1 % AUC) | Moderate (≈ 0.7 % AUC) | Minor (≈ 0.3 % AUC) |
| First reasoning step | Critical (≈ 2 % AUC) | Helpful (≈ 1 % AUC) | Slight benefit (≈ 0.5 % AUC) |

**Key takeaways:**

1. **Learning capacity grows with shots.**  The linear weight tuning becomes more valuable as more labeled examples are available, because the model can more reliably estimate each rule’s contribution.
2. **Prior knowledge matters most when data are scarce.**  Both feature descriptions and the causal reasoning step provide external information that compensates for the paucity of examples; their relative importance fades as the dataset grows.
3. **Ensembling is a universal stabilizer.**  Even with many shots, bagging mitigates the prompt‑size limitation and reduces variance induced by LLM randomness, so it remains beneficial across the board.

Overall, the ablation experiments confirm that the **FeatLLM** design is not an accidental collection of tricks; each piece addresses a concrete statistical challenge inherent to few‑shot tabular learning with large language models.  Removing any one of them degrades performance, and the magnitude of degradation aligns with theoretical expectations about bias‑variance trade‑offs, prior‑knowledge utilization, and model capacity.  This systematic analysis gives practitioners confidence that the full pipeline—reasoning prompt, feature descriptions, rule‑based binary features, learned non‑negative weights, and ensemble bagging—is a cohesive, well‑justified solution to the problem of data‑efficient tabular prediction.

\title{A Textbook about the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

Chapter 12: # Interpretability and Explainability

Understanding why a model makes a particular prediction is as important as achieving high predictive accuracy, especially in high‑stakes domains such as medicine and finance.  The **FeatLLM** framework introduces a transparent pipeline in which a large language model (LLM) first generates human‑readable rules and then a simple linear model learns to weight those rules.  Because every decision is ultimately reduced to a weighted sum of binary rule‑satisfaction features, the reasoning process can be inspected at multiple levels: the natural‑language rules themselves, the learned non‑negative weights that indicate rule importance, and the final class probabilities obtained from a soft‑max of the weighted logits.  This chapter explains how to interpret the outputs of FeatLLM, illustrates the process with concrete case studies, and situates the approach within the broader interpretability literature.

---

## Reading the Generated Natural‑Language Rules

The first step of FeatLLM is to prompt the LLM to produce **rules** that capture the conditions under which a sample belongs to a particular class.  The prompt is carefully structured into three parts:

1. **Basic Information Description** – the task description, feature names and definitions, and a few serialized training examples.  
2. **Reasoning Instruction** – a two‑step chain‑of‑thought cue that first asks the LLM to reason about causal relationships between features and the target, then to derive concrete rules using the few‑shot examples.  
3. **Response Instruction** – a strict template that tells the LLM how to format each rule (e.g., “If `age > 65` and `cholesterol = high` then class = `heart_failure`”).

Because the LLM is guided to produce a *fixed number of rules* (ten per class in the experiments), the output is a concise, enumerated list rather than a free‑form paragraph.  An example rule for a binary medical diagnosis might appear as:

```
Rule 1 (Heart Failure):
   (age > 65) AND (ejection_fraction < 30) AND (serum_creatinine > 1.2)
```

When reading such rules, a practitioner should:

- **Identify feature types** (numeric comparisons, categorical equality, or range checks).  The response instruction forces the LLM to respect the declared feature type, preventing type mismatches.
- **Check logical composition** – rules may contain conjunctions (`AND`) or disjunctions (`OR`).  The prompt explicitly allows both, but the subsequent parsing step translates the natural language into executable Python code, guaranteeing that the logical structure is preserved.
- **Assess plausibility** – because the LLM leverages both its pretrained knowledge and the few examples, many rules align with domain knowledge (e.g., “older patients have higher cardiovascular risk”).  Anomalous rules can be flagged for removal before the downstream linear model is trained.

Thus, the rule list serves as a **human‑readable explanation** of the model’s decision surface, directly exposing which feature combinations the LLM believes are decisive for each class.

## Inspecting Learned Weights to Rank Rule Importance

After rule extraction, FeatLLM converts each rule into a binary feature `z_k^i ∈ {0,1}^R` for class `k` (where `R = 10` in the standard configuration).  A **linear model without bias** then aggregates these binary features with a non‑negative weight vector `w_k`:

\[
\text{logit}_k^i = \max(\mathbf{w}_k, 0) \cdot \mathbf{z}_k^i,
\qquad
\mathbf{p}^i = \operatorname{Softmax}\big([\text{logit}_1^i,\dots,\text{logit}_c^i]\big).
\]

Because the weights are constrained to be non‑negative, each rule can only increase the logit of its associated class; a weight of zero means the rule is effectively ignored.  The training objective is the standard cross‑entropy loss on the few‑shot training set, allowing the model to **learn the relative importance** of each rule from data.

Interpretability is achieved through the following steps:

1. **Extract the weight vector** after training.  For each class `k`, we obtain a list `[(rule_1, w_{k,1}), …, (rule_R, w_{k,R})]`.
2. **Rank rules** by descending weight.  Rules with larger weights contribute more strongly to the class probability whenever they are satisfied.
3. **Visualize** the distribution of weights (e.g., a bar chart) to see whether a few rules dominate or whether importance is spread evenly.
4. **Threshold** low‑weight rules (e.g., `w < 0.1`) to prune noisy or irrelevant conditions.  The paper shows that after this pruning, the proportion of useful features (AUROC > 0.5) increases, confirming that the linear model successfully filters out spurious rules.

Because the weights are **learned directly from labeled data**, they reflect an empirical assessment of how well each rule aligns with the true target.  Consequently, the combination of human‑written rules and data‑driven weighting yields a transparent, two‑stage explanation: “The model predicts class k because rule r, which encodes condition C, has a high weight and is satisfied by the input.”

## Case Studies: Medical and Financial Datasets

### Medical Diagnosis – Predicting Chronic Heart Failure

Consider the **Myocardial** dataset, where the task is to predict whether a patient suffers from chronic heart failure.  FeatLLM generates rules such as:

```
Rule 3 (Heart Failure):
   (ejection_fraction < 35) AND (serum_sodium < 135)
Rule 7 (Heart Failure):
   (age > 70) AND (max_heart_rate_achieved < 120)
```

After training on only four labeled patients, the learned weights might be:

| Rule | Weight |
|------|--------|
| Rule 3 | 0.84 |
| Rule 7 | 0.12 |
| Rule 1 (less relevant) | 0.03 |

The high weight on Rule 3 indicates that the model strongly relies on low ejection fraction combined with hyponatremia, a medically plausible marker of heart failure.  By inspecting the weight table, a clinician can verify that the model’s emphasis matches clinical intuition, or flag any surprising high‑weight rule for further review.

### Financial Risk – Predicting Credit Good/Bad

In the **Credit‑g** dataset, the goal is to classify an applicant as a good or bad credit risk.  Sample rules produced include:

```
Rule 2 (Bad Credit):
   (duration_months > 24) AND (credit_amount > 5000) AND (purpose = "new_car")
Rule 5 (Good Credit):
   (age > 30) AND (existing_credits <= 1) AND (checking_status = "moderate")
```

Training on eight examples yields weights such as:

| Rule | Class | Weight |
|------|-------|--------|
| Rule 2 | Bad | 0.71 |
| Rule 5 | Good | 0.65 |
| Rule 9 (Good) | 0.10 |

Here, both “Bad Credit” and “Good Credit” rules receive substantial weights, reflecting that the model uses *both* discriminative patterns rather than a single dominant heuristic.  A credit analyst can inspect Rule 2 and see that long loan durations combined with high amounts for a new car purchase are indeed associated with higher default risk, lending confidence to the model’s decision.

These case studies illustrate how **rule readability**, together with **weight ranking**, provides a clear, domain‑specific narrative for each prediction, enabling stakeholders to trust and act upon the model’s outputs.

## Link to Broader Interpretability Literature

FeatLLM’s interpretability approach aligns with several established strands of research:

1. **Rule‑Based Models** – Classical decision‑tree and rule‑list methods (e.g., CART, RIPPER) offer direct logical explanations.  FeatLLM differs by **leveraging an LLM** to synthesize rules that incorporate world knowledge, yet it retains the same form of interpretable logical conditions.

2. **Post‑hoc Feature Importance** – Methods such as SHAP or LIME assign importance scores to original features after training a black‑box model.  FeatLLM **integrates importance learning into the model** (the linear weight vector) rather than interpreting retrospectively, yielding inherently interpretable parameters.

3. **Concept Bottleneck Models** – Those approaches train a model to predict intermediate human‑understandable concepts before the final prediction.  In FeatLLM, the binary rule features act as **concepts** that are directly engineered by the LLM, and the downstream linear model only consumes these concepts.

4. **Self‑Explaining Neural Networks** – Recent work designs architectures that output explanations alongside predictions.  FeatLLM follows a similar philosophy but does so with **no neural training beyond a tiny linear layer**, making the explanations exact (the rules themselves) rather than approximations.

5. **Ensemble Interpretability** – Bagging and ensembling are traditionally viewed as reducing variance at the cost of interpretability.  FeatLLM circumvents this trade‑off by ensembling *rule‑generating* processes while still producing a **single aggregated weight vector** per ensemble member; the final prediction is the average of softmax probabilities, which can be decomposed back into per‑rule contributions across members.

Overall, FeatLLM demonstrates that **large language models can be harnessed as knowledge‑rich feature engineers** while preserving the clarity of rule‑based explanations.  By coupling LLM‑generated rules with a simple, non‑negative linear model, the framework provides a transparent decision pipeline that satisfies both predictive performance and the regulatory or ethical demands for explainability in sensitive domains.

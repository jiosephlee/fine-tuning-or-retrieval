\title{A Textbook about the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

Chapter 6: Learning from Generated Features
# Formulation of the Linear Scorer

After the LLM has produced a collection of deterministic rules for each class, each rule can be interpreted as a binary indicator that tells whether a particular sample satisfies the condition expressed by the rule.  For a given class \(k\) we denote by  

\[
\mathbf{z}_{k}^{i}\;=\;\bigl[z_{k,1}^{i},\,z_{k,2}^{i},\dots ,z_{k,R}^{i}\bigr]^{\top}\in\{0,1\}^{R}
\]

the vector of binary rule‑features generated for the \(i\)-th sample, where \(R\) is the fixed number of rules extracted for each class (the paper uses ten).  The simplest way to turn these binary features into a score for class \(k\) is to compute a linear combination

\[
\text{logit}_{k}^{i}\;=\;\max \bigl(\mathbf{w}_{k},\,0\bigr)\cdot \mathbf{z}_{k}^{i},
\tag{1}
\]

where \(\mathbf{w}_{k}\in\mathbb{R}^{R}\) is a learnable weight vector associated with class \(k\), and the operator \(\max(\cdot,0)\) is applied element‑wise.  The use of the element‑wise non‑negative projection \(\max(\mathbf{w}_{k},0)\) is a crucial design choice: it guarantees that any rule that is satisfied by a sample can only increase, never decrease, the logit for its own class.  Consequently, each rule can be interpreted as a *supporting* piece of evidence rather than a contradictory one, which aligns with the intuitive meaning of a rule (“if the condition holds, the sample is more likely to belong to this class”).

The dot product in (1) aggregates the contributions of all satisfied rules.  Because the binary feature vector is sparse—most rules will be false for a given example—the resulting logit reflects precisely how many of the most salient, LLM‑derived conditions are met, weighted by their learned importance.  This formulation replaces the need for a complex classifier: the entire decision‑making process rests on a single linear scorer applied to the rule‑based representation of the data.

# Softmax Conversion to Probabilities

The logits computed for each class must be transformed into a valid probability distribution over the \(c\) possible classes.  This is achieved with the softmax function:

\[
\mathbf{p}^{i}\;=\;\operatorname{Softmax}\bigl([\text{logit}^{i}_{1},\dots ,\text{logit}^{i}_{c}]\bigr),
\qquad
p^{i}_{k}\;=\;\frac{\exp(\text{logit}^{i}_{k})}{\sum_{j=1}^{c}\exp(\text{logit}^{i}_{j})}.
\tag{2}
\]

Equation (2) guarantees that each component \(p^{i}_{k}\) lies in \((0,1)\) and that \(\sum_{k=1}^{c}p^{i}_{k}=1\).  The softmax thus maps the raw, additive evidence gathered from the rule‑features into a calibrated class probability vector \(\mathbf{p}^{i}\).  In practice, because the logits are non‑negative (thanks to the positivity constraint on the weights) the softmax tends to assign higher probability to classes whose rule set is more extensively satisfied, while still allowing competition between classes when multiple rule sets are partially triggered.

# Training Objective: Cross‑Entropy on \(k\)‑Shot Data

During the few‑shot learning phase we are given only a small labeled subset of the full dataset, denoted by \(\{(\mathbf{x}^{i},\mathbf{y}^{i})\}_{i=1}^{k}\).  After the rule extraction step, each training sample is converted into its binary rule representation \(\mathbf{z}^{i}\).  The parameters to be learned are the weight vectors \(\{\mathbf{w}_{k}\}_{k=1}^{c}\).  The standard cross‑entropy loss is employed:

\[
\mathcal{L}\;=\;-\frac{1}{k}\sum_{i=1}^{k}\sum_{k=1}^{c}y^{i}_{k}\,\log p^{i}_{k},
\tag{3}
\]

where \(y^{i}_{k}\) is the one‑hot encoding of the true class label for sample \(i\).  Minimizing (3) encourages the model to increase the logits—and consequently the probabilities—of the correct class while reducing those of incorrect classes.  Because the loss is differentiable with respect to the (projected) weight vectors, gradient‑based optimization can be applied even when only a handful of training points are available.  The paper observes that, despite the extreme data scarcity, the rule‑based representation is already highly informative, so even a simple linear model can achieve strong performance after modest training.

# Why Positivity Constraints Improve Interpretability

Constraining the weights to be non‑negative has two complementary benefits:

1. **Semantic clarity.**  A rule that is satisfied should intuitively contribute positively to the likelihood of its associated class.  By forcing \(\mathbf{w}_{k}\ge 0\), the model respects this semantics: a rule’s influence can be interpreted directly as “how much evidence this rule provides for class \(k\).”

2. **Avoiding destructive interference.**  Without the constraint, a rule that is frequently satisfied could be assigned a negative weight, effectively turning a valid piece of domain knowledge into a penalty.  In a few‑shot setting this can easily happen due to over‑fitting to the tiny training set.  The positivity projection prevents such pathological situations, leading to more stable training and better generalisation.

Because each weight is a scalar attached to a human‑readable rule, the final learned model can be inspected: rules with high weight are the most decisive criteria identified by the LLM and subsequently confirmed by the data.  This aligns with the goal of the paper to provide an interpretable alternative to black‑box LLM inference.

# Optimization Details (Adam, Epochs, Early Stopping)

Training the linear scorer proceeds with the Adam optimiser, a widely used variant of stochastic gradient descent that adapts learning rates per parameter.  The implementation in the paper uses a learning rate of \(0.01\) and runs for up to \(200\) epochs.  Because the dataset is extremely small, the authors employ \(k\)-fold cross‑validation on the few‑shot training set to select the epoch that yields the best validation cross‑entropy, effectively performing early stopping.  This prevents over‑training on the limited data while allowing the weights to converge to values that reflect the true predictive power of each rule.

In practice the optimisation loop looks as follows:

1. Initialise the weight vectors \(\mathbf{w}_{k}\) (e.g., to zeros).
2. For each epoch:
   - Compute binary rule features \(\mathbf{z}^{i}\) for all training samples.
   - Compute logits via (1) and probabilities via (2).
   - Evaluate the cross‑entropy loss (3).
   - Update the weight vectors with Adam’s gradient step.
3. After each epoch, evaluate on a held‑out fold; if the validation loss has not improved for a preset number of epochs, stop and keep the best weights.

Because the model contains only \(c\times R\) parameters (for example, ten rules per class on a ten‑class problem yields at most one hundred parameters), training is computationally cheap.  This efficiency, together with the fact that inference after training requires only a dot product and a softmax, makes the overall pipeline suitable for real‑time deployment, a primary advantage highlighted by the authors over methods that must query the LLM for every test instance.

\title{Stack Exchange of the Paper: "Byte Latent Transformer: Patches Scale Better Than Tokens"}

### What is the exact FLOP formula used for the latent global transformer when counting "per byte" cost?
Question:
In Section 4.1 the FLOP count for BLT includes a term \text{Transf. FL}(h_{\mathcal{G}}, l_{\mathcal{G}}, m=n_{ctx}/n_p, V=0) / n_p.  I want to understand each argument: $h_{\mathcal{G}}$ hidden size, $l_{\mathcal{G}}$ layers, $m$ context length in patches (so $n_{ctx}$ bytes divided by number of patches), and $V$ = 0 because there is no output vocabulary projection at this stage. Could someone expand this into the standard QKV + FFN FLOP equations and show how it reduces to per‑byte cost? Also, why is there no addition of patch‑dependent positional embeddings?
Answer:
The term that appears in § 4.1

\[
\frac{\text{Transf.\;FL}\bigl(h_{\mathcal G},\,l_{\mathcal G},\,m=n_{\text{ctx}}/n_{p},\,V=0\bigr)}{n_{p}}
\]

is simply the ordinary FLOP count of a **standard decoder‑only transformer** (the *latent global transformer* $\mathcal G$) evaluated on a sequence whose length is the number of *patches* that are processed in one forward‑backward pass, and then divided by the number of bytes $n_{\text{ctx}}$ in the original context.  Because each patch corresponds to a contiguous block of bytes, dividing by the patch count $n_{p}$ yields the cost **per byte**.

Below we expand the four arguments of `Transf.FL` into the familiar $QKV$‑attention + feed‑forward (FFN) equations and show how the division by $n_{p}$ collapses everything to a per‑byte budget.  We also explain why no patch‑dependent positional embeddings appear in this term.

---

### 1.  What `Transf.FL` actually computes  

For a transformer layer with hidden dimension $h$ and sequence length $m$ (here $m = n_{\text{ctx}}/n_{p}$, i.e. the number of patches), the FLOP count used in the paper follows Chinchilla [2022] and can be written as  

\[
\text{FL}_{\text{layer}}(h,m,V)=
\underbrace{2\,h^{2}m}_{\text{self‑attn }(Q,K,V)}+
\underbrace{2\,h^{2}m}_{\text{output projection}}+
\underbrace{4\,h^{2}m}_{\text{FFN (gate+up)}}
+
\underbrace{2\,hmV}_{\text{final vocab projection}} .
\]

* The first two terms come from three linear projections for queries, keys and values ($3hmh = 3hmh$ multiplies + same number of adds, i.e. $2hmh)$) and from the final output projection that maps the attention result back to a hidden vector.
* The FFN uses a SwiGLU feed‑forward block with two linear layers (gate + upward projection); each contributes $2hmh$ FLOPs, hence $4hmh$.
* The last term is present only when a vocabulary projection is needed (e.g. in a token‑level decoder). For the latent transformer we set $V=0$, so this term vanishes.

Summing over all global layers gives  

\[
\text{Transf.\;FL}(h_{\mathcal G},l_{\mathcal G},m,V)
   = l_{\mathcal G}\,\Bigl[\,4h_{\mathcal G}^{2}m
        +4h_{\mathcal G}^{2}m
        +2\,h_{\mathcal G}mV \Bigr] .
\]

Because $V=0$,

\[
\boxed{\;\text{Transf.\;FL}(h_{\mathcal G},l_{\mathcal G},m,0)
      = l_{\mathcal G}\,8\,h_{\mathcal G}^{2}m \;}
      \qquad (1)
\]

which is just **$8\,l_{\mathcal G}\,h_{\mathcal G}^{2}$** multiplied by the patch length $m$.

---

### 2.  From “per‑patch’’ to “per‑byte’’  

The latent transformer is invoked **once per patch**.  If a training batch contains on average

* $n_{\text{ctx}}$ bytes,
* split into $n_{p}=n_{\text{ctx}}/m$ patches,

the total number of FLOPs spent on the global model for that batch is (1).  
Dividing by the number of bytes gives

\[
\frac{\text{Transf.\;FL}(h_{\mathcal G},l_{\mathcal G},m,0)}{n_{p}}
=
\frac{l_{\mathcal G}\,8\,h_{\mathcal G}^{2} m}{n_{p}}
=
l_{\mathcal G}\,8\,h_{\mathcal G}^{2}
   \underbrace{\frac{m}{n_{p}}}_{= \frac{n_{\text{ctx}}}{n_{p}^{2}}}.
\]

Since $m = n_{\text{ctx}}/n_{p}$, the fraction simplifies to **$1/m = n_{p}/n_{\text{ctx}}$**, giving finally  

\[
\boxed{\;
 \frac{\text{Transf.\;FL}}{n_{p}}
 = l_{\mathcal G}\,8\,h_{\mathcal G}^{2}\,\frac{1}{m}
 = l_{\mathcal G}\,8\,h_{\mathcal G}^{2}\,
   \frac{n_{p}}{n_{\text{ctx}}}
 \;}
     \qquad (2)
\]

which is exactly “flops per byte’’: every additional byte contributes a constant amount
$8\,l_{\mathcal G}\,h_{\mathcal G}^{2}/(\text{average bytes per patch})$.

If we write it directly in terms of the four arguments originally shown:

* **$h_{\mathcal G}$** – hidden size of the latent transformer,
* **$l_{\mathcal G}$** – number of its layers,
* **$m = n_{\text{ctx}}/n_{p}$** – patch‑wise context length,
* **$V=0$** – no output vocabulary head,

the per‑byte cost follows from plugging these values into (1) and then dividing by $n_{p}$.

---

### 3.  Why there is no patch‑dependent positional embedding in this term  

Positional information for *patches* lives entirely inside the **global transformer**’s self‑attention mechanism via RoPE (rotary embeddings).  RoPE does not add any extra matrix multiplication; it simply rotates query/key vectors element‑wise before computing their dot‑product.  Consequently it incurs **zero FLOPs** (the paper explicitly treats RoPE as cost‑free).  

Patch‑level positional embeddings are *not* added as a separate embedding lookup because:

1. **Embedding lookups are counted as zero FLOPs** in § 4.1 (“the input embedding layer is implemented as an efficient lookup instead of a dense matrix multiplication”).  
   The patch’s absolute position could be added as a learned vector, but this would be another lookup and therefore does not change the FLOP budget.

2. The *cross‑attention* modules that aggregate bytes into patches already contain their own query/key/value projections; the authors deliberately omitted any additive positional term there (“no positional embeddings are used in this cross‑attention module”).  This design keeps the cross‑attention cost identical to a vanilla attention block and avoids extra FLOPs that would otherwise appear in `Cross Attn. FL`.

Hence, when we write `Transf.FL(..., V=0)` we are already accounting for all arithmetic performed by the latent transformer; any positional encoding that might exist is either a zero‑cost rotation (RoPE) or a free lookup, so it does not appear explicitly in the formula.

---

### 4.  Putting everything together  

The full per‑byte FLOP budget of BLT (equation (3) in the paper) consists of five pieces:

1. **Global latent transformer** – eqs. (1)–(2) above, divided by $n_{p}$.
2. **Local encoder** – same `Transf.FL` with hidden size $h_{\mathcal E}$, layers $l_{\mathcal E}$, context length equal to its fixed window $w_{\mathcal E}$, and again no vocab head.
3. **Local decoder** – same but with vocab size $V=256$ because it finally predicts a byte.
4. **Encoder cross‑attention** – FLOPs proportional to $h_{\mathcal E}^2 n_{p}(r)$, where $r=n_{p}/k$ is the ratio of queries (patches) to keys/values (bytes).  Multiplying by $k/n_{p}$ accounts for the fact that each cross‑attention step processes only one patch’s bytes.
5. **Decoder cross‑attention** – analogous term with the decoder dimensions.

All five terms are summed; only term (1) contains the factor $\frac{\text{Transf.\;FL}(h_\G,l_\G,m,V=0)}{n_p}$, which after expanding becomes exactly equation (2).  This expression shows clearly how increasing average patch size (larger $m$) lowers the per‑byte cost because fewer global transformer steps are required.

---

### TL;DR  

* `Transf.FL(h,l,m,V)` counts standard QKV attention plus SwiGLU FFN FLOPs:  
  \[
    \displaystyle l \bigl[8 h^{2} m + 2 h m V\bigr].
  \]  
* For the *latent global transformer* we set $V=0$; its per‑byte cost is obtained by dividing this quantity by the number of patches $n_p=n_\text{ctx}/m$.  
* After simplification we obtain  

  \[
  \frac{\text{Transf.\;FL}(h_\G,l_\G,m,0)}{n_p}
   = l_\G \cdot 8 h_\G^{2} \frac{1}{m},
  \]

  i.e. FLOPs per byte scale inversely with average patch size.  
* Positional information does not add FLOPs because RoPE rotations are free and any learned patch positions are just lookups; therefore no extra term appears in `Transf.FL`.  

This explains precisely how Eq. (4.1)’s mysterious term translates into ordinary transformer arithmetic and why it already represents “flops per byte’’ without any additional positional overhead.

# Code Skeleton (PyTorch Pseudo‑code) for Cayley‑Parameterized OFT  

In this section we present a minimal yet complete PyTorch‑style implementation that follows the formalism introduced in the paper.  Recall that a single OFT‑enabled layer replaces the original weight matrix \(\mathbf{W}^{0}\in\mathbb{R}^{d\times n}\) by  

\[
\mathbf{W}= \mathbf{R}\,\mathbf{W}^{0},
\qquad   \mathbf{R}^{\top}\mathbf{R}=\mathbf{I},
\]

where \(\mathbf{R}\) is an orthogonal matrix generated through the Cayley transform.  Let \(\mathbf{Q}\in\mathbb{R}^{d\times d}\) be a skew‑symmetric matrix (\(\mathbf{Q}=-\mathbf{Q}^{\top}\)).  The Cayley map  

\[
\mathbf{R}= (\mathbf{I}+\mathbf{Q})\bigl(\mathbf{I}-\mathbf{Q}\bigr)^{-1}
\tag{1}
\]

produces an orthogonal matrix with \(\det(\mathbf{R})=1\); this satisfies the invariance property of hyperspherical energy described in the paper.  

Below is a concise skeleton that can be inserted into any diffusion model where a linear layer, a convolution, or an attention projection is to be finetuned.  The code is deliberately written to expose the three major steps: (i) construction of a skew‑symmetric matrix from a free‑parameter tensor, (ii) Cayley conversion, and (iii) forward substitution of the transformed weight.

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class OFTLiner(nn.Module):
    """
    Orthogonal Finetuning (OFT) wrapper for a linear projection.
    The pretrained weight W0 is frozen; an orthogonal matrix R,
    parameterized by a skew‑symmetric Q, is learned.
    """
    def __init__(self, weight_pretrained: torch.Tensor,
                 block_size: int = None,
                 share_blocks: bool = False):
        """
        Args:
            weight_pretrained: Tensor of shape (d, n) – the frozen
                               pretrained weights W0.
            block_size:       Size of each block in the block‑diagonal
                               decomposition of R (see paper).  If None,
                               a full d×d matrix is used.
            share_blocks:     If True, all blocks share the same
                               parameters, further reducing the
                               number of learnable parameters.
        """
        super().__init__()
        self.W0 = weight_pretrained  # frozen, register as buffer
        self.register_buffer('W0', self.W0.clone())

        d, _ = self.W0.shape
        # ---------- Determine block structure ----------
        if block_size is None:
            block_size = d                     # full matrix
        self.num_blocks = d // block_size
        assert d % block_size == 0, "d must be divisible by block_size"

        # ---------- Allocate raw parameters for Q ----------
        # For each block we store the upper‑triangular entries of a
        # skew‑symmetric matrix.  A skew‑symmetric matrix of size b has
        # b(b‑1)/2 independent elements.
        b = block_size
        self.q_shape = (self.num_blocks, b, b)
        # store only the strict upper‑triangular part, flattened
        self.raw_q = nn.Parameter(
            torch.zeros(self.num_blocks, b, b)
        )  # we will enforce skew‑symmetry later

        self.block_size = block_size
        self.share_blocks = share_blocks

    def _build_Q(self) -> torch.Tensor:
        """
        Construct a block‑diagonal skew‑symmetric matrix Q from the raw
        learnable parameters.
        """
        # Enforce skew symmetry: Q = (raw_q - raw_q.T) / 2
        Q_blocks = (self.raw_q - self.raw_q.transpose(-2, -1)) * 0.5

        if self.share_blocks:
            # Broadcast a single block to all positions
            Q_blocks = Q_blocks[0:1].expand(self.num_blocks, -1, -1)

        # Assemble block‑diagonal matrix
        Q = torch.block_diag(*[Q_blocks[i] for i in range(self.num_blocks)])
        return Q  # shape (d, d)

    def _cayley(self, Q: torch.Tensor) -> torch.Tensor:
        """
        Apply the Cayley transform (1) to obtain an orthogonal matrix R.
        """
        I = torch.eye(Q.shape[0], device=Q.device, dtype=Q.dtype)
        # (I + Q) @ (I - Q)^{-1}
        # Use torch.solve or torch.linalg.solve for stability
        R = (I + Q) @ torch.linalg.solve(I - Q, I)
        return R  # shape (d, d), orthogonal and det(R)=1

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        """
        Replace the original linear projection by (R W0)^T x.
        """
        Q = self._build_Q()                # (d, d)
        R = self._cayley(Q)                # (d, d)
        # Compute transformed weight once per forward pass
        # Note: we keep W0 frozen, thus the gradient flows only
        # through R (hence through raw_q).
        W = R @ self.W0                     # (d, n)
        # Linear projection (the diffusion model expects (W^T x))
        out = F.linear(x, W.t())            # shape (..., n)
        return out
```

Key points to notice:

* **Skew‑symmetry enforcement** – we store an unrestricted tensor `raw_q` and symmetrize it on the fly, guaranteeing \(\mathbf{Q} = -\mathbf{Q}^{\top}\).  
* **Block‑diagonal parameterization** – the `block_size` argument corresponds to the \(r\) blocks described in the paper.  When `share_blocks=True` the memory footprint drops from \(\mathcal{O}(d^{2}/r)\) to \(\mathcal{O}(d^{2}/r^{2})\).  
* **Cayley transform** – the implementation uses `torch.linalg.solve` to avoid explicit matrix inversion while preserving differentiability.  The resulting matrix fulfills \(\mathbf{R}^{\top}\mathbf{R}=\mathbf{I}\) and, because of the determinant constraint, belongs to the special orthogonal group.  

The same wrapper can be applied to convolutional kernels (by reshaping the kernel to a 2‑D matrix) or to the query/key/value projection matrices of a transformer block.  In all cases the semantics are identical: the pretrained parameters are rotated by an orthogonal matrix that is learned jointly with the downstream loss.

# Choosing Block Size \(r\) and \(\epsilon\) for COFT  

## Block Size \(r\)  

The hyper‑parameter \(r\) controls how many square blocks appear on the diagonal of \(\mathbf{R}\).  According to the paper, a full matrix (\(r=1\)) enjoys maximal expressive power at a cost of \(\mathcal{O}(d^{2})\) learnable parameters.  When memory is limited, increasing \(r\) reduces the number of free parameters to  

\[
\#\text{params}( \mathbf{R}) = \frac{d\bigl(d/r-1\bigr)}{2}.
\]

A practical rule of thumb, validated empirically in the experiments, is:

| Model dimension \(d\) | Recommended \(r\) | Approx. trainable params |
|-----------------------|-------------------|--------------------------|
| \(d \le 256\)         | \(r=1\) (full)    | \(\approx 32\text{k}\)   |
| \(256 < d \le 1024\)  | \(r = 4\)         | \(\approx 0.5d^{2}\)     |
| \(d > 1024\)          | \(r = 8\) or larger (share blocks) | \(\approx 0.125d^{2}\) |

When the same block is shared across all positions (`share_blocks=True`), the parameter count shrinks further to \(\mathcal{O}(d^{2}/r^{2})\).  In the diffusion backbone of Stable Diffusion (U‑Net with hidden dimension 1024), the authors report using \(r=8\) with shared blocks, which reduces each orthogonal matrix to roughly \(16\,\text{k}\) parameters while preserving the hyperspherical energy invariance.

## Radius Constraint \(\epsilon\) for COFT  

COFT augments the OFT objective with an explicit deviation bound  

\[
\|\mathbf{R} - \mathbf{I}\| \le \epsilon,
\tag{2}
\]

ensuring that the finetuned model stays close to the pretrained weights.  Because the Cayley transform linearises around the identity as  

\[
\mathbf{R} \approx \mathbf{I} + 2\mathbf{Q} + \mathcal{O}(\mathbf{Q}^{2}),
\]

the bound (2) can be equivalently imposed on \(\mathbf{Q}\) as  

\[
\|\mathbf{Q}\| \le \epsilon'.
\tag{3}
\]

In practice one enforces (3) after each gradient step by a simple projection:

```python
with torch.no_grad():
    norm = torch.norm(self.raw_q, p='fro')
    if norm > eps_prime:
        self.raw_q.mul_(eps_prime / norm)
```

Empirical observations in the paper (Figure 7) suggest that:

* **Large \(\epsilon\) (e.g. \(\epsilon \approx 0.5\))** – COFT behaves similarly to unconstrained OFT, providing maximal flexibility but with a slightly higher risk of over‑adjusting the direction of neurons.  
* **Medium \(\epsilon\) (0.1 – 0.2)** – offers the best trade‑off: the model converges quickly, retains most of the pretrained semantic capacity, and is robust to random seeds.  
* **Very small \(\epsilon\) (< 0.05)** – the finetuned model remains almost identical to the pretrained one, which may be insufficient to capture the downstream control signal.  

A recommended initial setting for Stable Diffusion’s 1024‑dimensional layers is \(\epsilon = 0.15\) (corresponding to \(\epsilon' \approx 0.075\)).  One can later perform a grid search around this value; the training curves are usually monotonic with respect to \(\epsilon\), making the selection straightforward.

# Memory and Compute Considerations for Large Models  

Even though OFT replaces the conventional additive weight‑update (e.g., LoRA) with a multiplicative orthogonal transformation, the computational overhead is modest:

| Operation | Complexity | Memory Impact |
|-----------|------------|---------------|
| Construction of \(\mathbf{Q}\) (block‑diagonal) | \(\mathcal{O}(d^{2}/r)\) | Only raw parameters are stored (no full \(d\times d\) matrix). |
| Cayley transform (solve linear system) | \(\mathcal{O}(d^{3})\) per forward if naive, but practical implementations use the block‑diagonal structure, reducing to \(\mathcal{O}(d^{3}/r)\). | The intermediate inverse is never materialised; we solve \((\mathbf{I}-\mathbf{Q})\mathbf{X} = \mathbf{I}+\mathbf{Q}\) via `torch.linalg.solve`, which reuses memory. |
| Multiplication \(\mathbf{R}\mathbf{W}^{0}\) | \(\mathcal{O}(d^{2}n/r)\) | The product can be cached for several steps if the downstream loss does not modify \(\mathbf{R}\) dramatically. |

**Practical memory tips**

1. **Cache the transformed weight per training step** – after the first forward pass of a batch, store \(\mathbf{W} = \mathbf{R}\mathbf{W}^{0}\) in a buffer and reuse it for the remaining micro‑batches of the same iteration.  This avoids recomputing the matrix product for each micro‑batch.  
2. **Mixed‑precision training** – the orthogonal matrix is well‑conditioned so FP16 does not degrade the orthogonality enforcement, and it halves the memory consumption of `raw_q`.  
3. **Gradient checkpointing** – for very deep U‑Net blocks one can checkpoint the computation of \(\mathbf{R}\) and re‑compute it during the backward pass, swapping a few extra FLOPs for a large memory saving.  

By adopting a block‑diagonal \(r\) of 8 or larger, the additional memory required on a 24 GB GPU for a full 1024‑dimensional layer stays below 30 MB, which is negligible compared with the activation memory of the diffusion backbone.

# Tips for Hyper‑Parameter Tuning (Learning Rate, Epochs, Seed Robustness)  

The empirical studies in the paper show that OFT (and COFT) are considerably less sensitive to the number of fine‑tuning epochs than traditional DreamBooth or LoRA.  Nevertheless, sensible defaults accelerate convergence and improve reproducibility.

| Hyper‑parameter | Recommended Range | Rationale |
|-----------------|-------------------|-----------|
| Learning rate (for `raw_q`) | \(1\!\times\!10^{-4}\) – \(5\!\times\!10^{-4}\) (AdamW) | The orthogonal manifold is smooth; a moderate step size keeps \(\mathbf{R}\) close to identity while allowing enough rotation to capture the downstream signal. |
| Weight decay | 0 (or \(1\!\times\!10^{-5}\) for very large \(r\)) | The orthogonal constraint already regularises the model; additional decay can unnecessarily shrink the rotation magnitude. |
| Number of epochs | 5 – 30 (subject‑driven) / 10 – 20 (controllable) | Figures 4‑5 in the paper demonstrate that stable performance is achieved after ≈200 – 400 iterations (≈5 epochs on a modest dataset).  Extending beyond 20 epochs rarely improves metrics but may increase the risk of over‑rotating when \(\epsilon\) is large. |
| Random seed | Test at least three seeds; use the median of metrics. | The paper reports variance across seeds; OFT’s variance is smaller than DreamBooth’s, but evaluating a few seeds guards against pathological initializations of the skew‑symmetric matrix. |
| Block size \(r\) | 1 (full) for low‑dimensional layers, 4–8 for hidden dimensions ≥ 512 | Larger \(r\) reduces parameters and stabilises training while preserving enough expressive power. |
| \(\epsilon\) (COFT) | 0.1 – 0.2 (default 0.15) | Controls the trade‑off between faithful preservation of the pretrained knowledge (small \(\epsilon\)) and ability to learn new control signals (larger \(\epsilon\)). |

**Tuning workflow**

1. **Start with the default \(\epsilon=0.15\) and \(r=8\)** (shared blocks) on a single layer (e.g., the text‑conditioned cross‑attention projection).  
2. **Run a short 5‑epoch probe**; monitor the validation hyperspherical energy difference \(\| \text{HE}(\mathbf{W}) - \text{HE}(\mathbf{W}^{0})\|\).  If the difference remains near zero, the orthogonal constraint is correctly enforced.  
3. **If downstream loss plateaus early**, increase \(\epsilon\) by 0.05 increments while keeping the learning rate fixed.  Observe whether validation metrics (e.g., CLIP‑I for DreamBooth) improve.  
4. **If training becomes unstable (loss spikes or generated images collapse)**, either shrink \(\epsilon\) or increase \(r\) (more blocks → fewer degrees of freedom per block).  
5. **Finalize** by training the full set of selected layers for the target number of epochs; evaluate on a held‑out validation set and keep the checkpoint with the best combined metric (e.g., DINO + CLIP‑T).  

Because OFT preserves hyperspherical energy by construction, the usual early‑stopping based on Euclidean weight drift is unnecessary; the model’s semantic capacity remains intact as long as the \(\epsilon\) bound is respected.

# Deploying the Fine‑Tuned Model with Zero Inference Overhead  

One of the most attractive properties of OFT (and COFT) is that the orthogonal transformation can be *absorbed* into the pretrained weight matrix after training, yielding a standard weight tensor that can be used by any existing diffusion pipeline without modification.

The post‑training step is straightforward:

```python
def bake_orthogonal_transform(original_weight, raw_q, block_size, share_blocks):
    # Build Q as in the training wrapper
    Q = build_Q(raw_q, block_size, share_blocks)          # (d, d)
    R = cayley_transform(Q)                               # (d, d)
    # Compute the baked weight
    baked_weight = R @ original_weight                     # (d, n)
    return baked_weight
```

Once `baked_weight` replaces the original \(\mathbf{W}^{0}\) in the model checkpoint, the inference path becomes exactly the same as the pretrained network:

* **No extra matrix multiplication** – the orthogonal‐matrix multiplication is performed once offline.  
* **Identical memory layout** – the baked weight is a dense tensor, compatible with any accelerator‑optimized kernel.  
* **Zero latency impact** – the diffusion timestep loop, classifier‑free guidance, and other components remain untouched.  

The same “baking” procedure can be applied to every OFT‑wrapped layer (e.g., all cross‑attention projections, the up‑sampling convolutions, or any custom linear module).  After baking, the checkpoint can be exported to the standard `diffusers` or `CompVis` format and loaded by downstream services without any code change.

In summary, the deployment pipeline is:

1. **Finetune** using the OFT/COFT wrapper (training time only).  
2. **Bake** orthogonal matrices into the frozen weights.  
3. **Save** the resulting checkpoint as a standard diffusion model.  
4. **Load** the checkpoint in any existing inference script – the model behaves exactly as a vanilla diffusion model, but now embodies the learned controllability.  

This zero‑overhead property makes OFT especially appealing for production environments where latency and memory budgets are strict, and it aligns with the paper’s claim that “no additional inference overhead” is introduced.

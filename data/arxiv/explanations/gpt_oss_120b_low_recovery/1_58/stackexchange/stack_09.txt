\title{Stack Exchange of the Paper: "The Era of 1-bit LLMs: All Large Language Models are in 1.58 Bits"}

### How does BitNet b1.58 achieve “feature filtering” with the zero weight value?
Question:
The authors claim that adding the zero value to the weight set (
{-1, 0, +1}) enables explicit feature filtering and improves performance over the original 1‑bit BitNet. Could someone explain the intuition behind this: how does the presence of zero weights affect the attention or feed‑forward computations, and is there any quantitative analysis showing that sparsity of zero weights correlates with better downstream performance?
Answer:
**Answer**

In the original “1‑bit” BitNet every weight is forced to be either **–1** or **+1**.  
Because the weight matrix is dense, every hidden unit participates in every
matrix‑multiply, even if the contribution of a particular weight is only a sign
change. By adding a third value – 0 – the weight matrix becomes **sparse** and the
network can *explicitly* turn off a connection.  

### Why a zero weight acts as a feature filter

In a Transformer layer the two most expensive operations are the linear
projections that compute

\[
\mathbf{Z}= \mathbf{X}\,\widetilde{\mathbf{W}} ,
\qquad\widetilde{\mathbf{W}}\in\{-1,0,1\}^{d_{\text{in}}\times d_{\text{out}}},
\]

where \(\mathbf{X}\) are the activations (8‑bit in BitNet b1.58) and
\(\widetilde{\mathbf{W}}\) is the ternary weight matrix.  
If a row (or column) of \(\widetilde{\mathbf{W}}\) contains many zeros, the
corresponding output dimension receives contributions only from the non‑zero
entries; the rest of the inputs are literally *filtered out*. This is
functionally identical to a hard‑gating or masking operation that is learned
during training.

In the attention branch the query, key and value projections all use ternary
matrices. A zero weight therefore removes a particular dimension of the query
(or key/value) from the dot‑product that produces the attention scores. The same
logic holds for the feed‑forward (FFN) branch: a zero weight in the first
linear layer drops a specific feature from the hidden representation before the
non‑linearity, and a zero in the second layer prevents that feature from
contributing to the final output. In other words, the model can *learn* which
features are useful and which can be ignored, rather than relying on the sign
alone to encode that information.

### What this buys us

* **Learned sparsity** – The optimizer is free to set any weight to 0, so the
model can allocate capacity where it matters and prune irrelevant connections.
* **Reduced compute** – Multiplication with 0 disappears, and the remaining
operations are just integer additions (‑1 · x is a subtraction, +1 · x a
addition). The sparsity also lowers the number of additions that have to be
performed, giving a small extra speedup on top of the already‑multiplication‑free
kernel.
* **Memory saving** – Zero entries can be stored with a run‑length or bitmap
compression, further shrinking the weight footprint beyond the 1.58‑bit average
entropy that the paper reports.

### Empirical evidence in the paper

The authors do not present a separate ablation that varies the amount of zero
weights, but they give two pieces of quantitative evidence that support the
“feature‑filtering” claim:

1. **Perplexity** – Table 1 shows that a 3 B BitNet b1.58 (ternary) matches the
   validation perplexity of a full‑precision 3 B LLaMA model, whereas the
   original 1‑bit BitNet (binary) lags behind by a noticeable margin. The only
   architectural difference between the two is the presence of the 0 value, so
   the improvement can be attributed to the sparsity it enables.

2. **Zero‑shot task performance** – In Table 2 the 3.9 B BitNet b1.58 outperforms
   the 3 B full‑precision baseline on almost all downstream tasks, while the
   binary‑only version (reported in the BitNet paper) does not reach that
   level. Again, the gain correlates with the ability of the model to set many
   weights to 0 during training.

Although the paper does not plot the *fraction* of zero weights, the authors
state that “explicit support for feature filtering” is one of the two
advantages of the ternary setting, and the empirical results above are the
only concrete numbers they provide to back the claim.

### Take‑away intuition

Think of a ternary weight matrix as a **learned mask** over the dense
connectivity of a standard Transformer. The mask can turn off entire
input‑output pairs, allowing the network to discard noisy or redundant
features early in the computation. This “hard” gating is possible only because
the weight set contains 0; with a binary \{-1,+1\} set every connection must
contribute either positively or negatively, which limits the expressiveness of
the model in low‑bit regimes. The observed improvements in perplexity and
zero‑shot accuracy are the paper’s quantitative confirmation that this added
degree of freedom translates into better modelling power.

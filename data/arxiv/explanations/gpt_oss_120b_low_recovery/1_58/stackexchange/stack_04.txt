\title{Stack Exchange of the Paper: "The Era of 1-bit LLMs: All Large Language Models are in 1.58 Bits"}

### How is the “zero‑point” quantization avoided for activations in BitNet b1.58?
Question:
The activation quantization is described as scaling to the range \([-Q_b, Q_b]\) per token instead of the usual \([0, Q_b]\) with a zero‑point. I am confused about how this per‑token scaling works in practice: is a separate scale computed for each token in the batch, and does it introduce any additional overhead? Also, how does this choice affect the distribution of activation values after the ReLU‑like non‑linearity?
Answer:
In BitNet b1.58 the activations are quantised to 8 bits **without** a zero‑point.  
The authors achieve this by treating each *token* (i.e. each row of the activation
matrix that corresponds to a single position in the sequence) as an independent
scalar field and scaling it to the symmetric interval \([‑Q_{b},\, Q_{b}]\) where  
\(Q_{b}=2^{7}-1=127\) for unsigned 8‑bit representation that is interpreted as a
signed integer.  

### How the per‑token scale is computed

For a given token \(t\) we have a vector of pre‑non‑linear activations
\(\mathbf{a}^{(t)}\in\mathbb{R}^{d}\) (e.g. the output of a linear projection before
the SwiGLU). The scale for that token is

\[
s^{(t)}=\frac{\max_{i}\bigl|a^{(t)}_{i}\bigr|}{Q_{b}} .
\]

In other words the largest absolute value of the token‑wise activation determines
the dynamic range that we want to fit into \([‑Q_{b},Q_{b}]\). The quantised
integer representation is then

\[
\hat a^{(t)}_{i}= \operatorname{clip}\!\bigl(
\operatorname{round}\bigl(\frac{a^{(t)}_{i}}{s^{(t)}}\bigr),\,
‑Q_{b},\, Q_{b}\bigr) .
\]

During the forward pass the de‑quantisation that the next linear layer needs is
simply a multiplication by the same scale:

\[
\tilde a^{(t)}_{i}= s^{(t)}\;\hat a^{(t)}_{i}.
\]

Because the scale is a **single scalar per token**, the overhead is tiny:
computing the maximum absolute value costs \(O(d)\) per token (the same order as
the matrix‑multiply itself) and the scale is stored as a 32‑bit float alongside
the integer activations. In practice the implementation fuses the max‑abs
reduction with the preceding linear kernel, so no extra kernel launch is needed.

### Why a zero‑point is unnecessary

Standard asymmetric quantisation maps a real interval \([x_{\min},x_{\max}]\) to
\([0,Q_{b}]\) and therefore needs a zero‑point \(z\) so that the real value zero
can be represented. By forcing the interval to be centred at zero, i.e.
\([-M,M]\) with \(M = Q_{b}\,s^{(t)}\), the integer value **0 already corresponds to
the real value 0**. Consequently the zero‑point disappears and the quantisation
kernel becomes a pure scaling‑and‑round operation, which is both simpler to
implement and cheaper on hardware (no additive offset to be stored or applied).

### Effect on the activation distribution after the ReLU‑like non‑linearity

BitNet b1.58 uses the SwiGLU activation, which consists of a linear projection,
a gated SiLU and a linear “gate” projection. The quantisation is performed **before**
the non‑linearity, exactly as in the original BitNet. Because the scaling is
symmetric, positive and negative values are treated uniformly; after the SiLU‑style
gate the distribution becomes strongly skewed toward the positive side (the SiLU
is roughly \(x\cdot\sigma(x)\)). The subsequent quantisation of the *output* of the
SwiGLU again uses a per‑token symmetric scale, so the final integer activations
remain centered around zero but with a much smaller dynamic range on the
negative side—effectively the zero‑point issue is hidden by the symmetric
scaling. Empirically the authors report “negligible effects to the performance”,
which indicates that the slight loss of precision on the negative tail does not
hurt the model, likely because the gating mechanism already suppresses many
negative values.

### Summary

* A **single scalar scale** \(s^{(t)}\) is computed for each token by dividing the
largest absolute activation by the 8‑bit integer range.
* This adds only a constant‑time reduction per token and can be fused into the
linear kernel, so the overhead is negligible.
* Because the range is symmetric around zero, the integer value 0 represents the
real value 0, eliminating the need for a zero‑point offset.
* After the SiLU‑like gating, the activation distribution becomes predominantly
positive, but the symmetric quantisation still works because the scale adapts
per token, preserving the information needed for the next layer.

Thus the “zero‑point‑free” per‑token scaling in BitNet b1.58 is both a practical
implementation trick and a hardware‑friendly design that does not degrade
accuracy.

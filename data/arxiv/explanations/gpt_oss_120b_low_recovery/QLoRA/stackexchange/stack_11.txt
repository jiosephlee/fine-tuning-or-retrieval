\title{Stack Exchange of the Paper: "QLoRA: Efficient Finetuning of Quantized LLMs"}

### "Data quality matters more than dataset size" – what evidence supports this claim in the QLoRA experiments?
Question:
The authors state that a 9k OASST1 dataset outperforms a 450k FLAN v2 subset on Vicuna benchmark performance. I am looking for details:
- Which specific models/dataset combinations were compared (model sizes, LoRA settings)?
- How were token counts controlled so that size differences are isolated from data quality?
- Could there be confounding factors such as domain overlap between OASST1 and Vicuna prompts?
Answer:
In the **QLoRA** paper the statement *“data quality matters more than dataset size”* is backed by a set of controlled finetuning experiments that isolate the effect of the instruction‑following corpus while keeping everything else – model architecture, LoRA configuration and total number of optimisation steps – fixed.  
Below I walk through exactly how those experiments were set up and why they give us confidence that the superior performance of the $9\,\text{k}$‑sample OASST‑1 collection is not an artefact of accidental confounds such as longer training or a larger overlap with the Vicuna test prompts.

---

### 1.  What was compared?

The authors finetuned **four LLaMA model families** ($7\,\text{B}$, $13\,\text{B}$, $33\,\text{B}$ and $65\,\text{B}$) with **QLoRA** on two very different instruction datasets:

| Model size | Dataset | # samples | average tokens / sample | total training tokens |
|------------|---------|-----------|------------------------|-----------------------|
| $7\,\text{B}$ – $65\,\text{B}$ | **OASST‑1** (Open‑Assistant) | **$\approx 9{,}000$** | $\approx 150$ (multi‑turn dialogues) | $\approx 1.3\,\text{M}$ |
| $7\,\text{B}$ – $65\,\text{B}$ | **FLAN‑v2 (sub‑sampled)** | **$\approx 450{,}000$** | $\approx 150$ (single turn instructions) | $\approx 67\,\text{M}$ |

Both datasets were “instruction‑following” in spirit – each row is an *instruction → response* pair – but their provenance is very different: OASST‑1 consists of human‑written multi‑turn conversations gathered via crowdsourcing, whereas FLAN‑v2 is a massive aggregation of automatically generated prompts and model‑generated answers.

All experiments used the **same LoRA hyper‑parameters**:

* rank $r = 64$ (the “standard” value for LLaMA adapters)  
* scaling factor $s = 2$  
* adapters placed **on every linear layer** (the paper’s “full‑layer LoRA” that was shown to be necessary for matching full‑model finetuning)  
* learning rate $= 2\times10^{-5}$ for the $7\,\text{B}/13\,\text{B}$ models, halved for $33\,\text{B}$ and $65\,\text{B}$; batch size $=128$ for the smaller models and doubled for the larger ones (as described in §4.2).  

These settings were deliberately kept identical across the two data conditions; only the *training set* differed.

---

### 2.  Controlling for token count

Because the FLAN subset contains many more examples, one could argue that it simply sees more optimisation steps. The authors therefore **fixed the number of passes over the data (epochs)** rather than fixing a token budget. Every model was trained for **one epoch** over its respective corpus. Consequently:

* The OASST‑1 runs involve roughly **$1.3\,\text{M}$ token updates**, while FLAN‑v2 runs involve about **$67\,\text{M}$ token updates**.  
* The disparity in *total* tokens is intentional – it is exactly what we want to test: does a *much larger but noisier* corpus beat a *tiny but high‑quality* one when both are used to train the same architecture with identical optimisation schedules?

Since both runs use the same optimiser (Paged AdamW), same gradient checkpointing strategy and identical early‑stopping criteria (none – they always run one epoch), any difference in downstream performance can be attributed to properties of the data rather than to differences in training dynamics.

---

### 3.  Avoiding domain overlap confounds

The Vicuna benchmark consists of **$80$ handcrafted prompts** that were originally harvested from the ShareGPT community. To make sure that OASST‑1 does not accidentally contain many of these prompts (which would give an unfair advantage), the authors performed a two‑step overlap check:

1. **Exact string matching** between every Vicuna prompt and every OASST‑1 user turn – none matched.  
2. **Fuzzy matching** with a Levenshtein distance threshold of $5$ characters followed by manual inspection of the closest pairs – again no semantically identical or near‑identical examples were found.

Because FLAN‑v2 is a broad mixture of public instruction sources, it also has essentially zero overlap with Vicuna.

Thus any performance gap cannot be explained by “the model simply memorised test questions”.

---

### 4.  The empirical result

After training, all models were evaluated on the Vicuna benchmark using both **GPT‑4 relative scoring** and a **human Elo tournament**, as described in §4.3. The key numbers are reproduced here (rounded for clarity):

| Model (size) | Trained on OASST‑1 | Trained on FLAN‑v2 ($450k$) |
|--------------|-------------------|---------------------------|
| Guanaco‑$7\,\text{B}$   | **$71\%$** of ChatGPT (GPT‑4 score) | $55\%$ |
| Guanaco‑$13\,\text{B}$  | **$84\%$**                        | $68\%$ |
| Guanaco‑$33\,\text{B}$  | **$96\%$**                        | $85\%$ |
| Guanaco‑$65\,\text{B}$  | **$99.3\%$**                      | $92\%$ |

Across every scale, the model fine‑tuned on just nine thousand high‑quality OASST‑1 examples *outperforms* the one that saw nearly five hundred thousand FLAN examples. The Elo ratings from human pairwise comparisons show exactly the same ordering, confirming that it is not an artefact of the automated GPT‑4 scoring.

---

### 5.  Why does this support “quality > quantity”?

Because all other variables – architecture, optimizer settings, number of optimisation steps per epoch and even total compute time (≈24 h on a single GPU for each run) – are held constant, the only systematic difference left is *the nature of the training tokens*.  

OASST‑1’s conversations are:

* **Human authored**, containing genuine intent–response structure,
* **Multi–turn**, which forces models to learn context handling,
* **Curated to avoid obvious noise**, as indicated by OpenAI’s instruction that GPT outputs must not be used in its creation.

FLAN‑v2, by contrast, aggregates many automatically generated or distilled instruction–response pairs whose quality varies widely; many entries are short synthetic prompts that do not require any real reasoning.

The experiments therefore demonstrate empirically that a modest amount of clean, dialogic data can teach a large LLM to behave better in a chatbot setting than an order-of-magnitude larger collection that contains substantial noise.

---

### TL;DR

- The paper compared LLaMA $7$–$65\,\text{B}$ models fine‑tuned with identical LoRA hyperparameters on either **$9k$ OASST‑1 samples** or **$450k$ FLAN v2 samples**.
- Both trainings used exactly one epoch, so each run performed the same number of optimizer updates; only the *token distribution* differed.
- No prompt overlap with Vicuna was found after exhaustive exact and fuzzy matching.
- Across all model sizes, OASST‑1 finetuning gave higher Vicuna scores and Elo ratings than FLAN v2 despite having $\sim50\times$ fewer tokens.

These controlled experiments constitute the evidence behind the authors’ claim that *data quality matters more than dataset size* in instruction finetuning for chatbots.

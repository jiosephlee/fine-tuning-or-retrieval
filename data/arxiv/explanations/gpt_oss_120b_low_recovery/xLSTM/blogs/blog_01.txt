# From LSTMs to xLSTMs: Why Reviving Classic RNNs Matters for Modern AI

## Introduction  

Long Short‑Term Memory networks (LSTMs) were the workhorses of sequence modelling for more than two decades. Introduced in the early 1990s, they solved the vanishing‑gradient problem of ordinary recurrent neural networks (RNNs) by adding a **constant‑error carousel** and a set of three gates (input, forget, output). This simple idea enabled LSTMs to remember information over long horizons, power everything from handwriting synthesis to game‑playing agents such as AlphaStar and OpenAI Five.

When the Transformer architecture arrived in 2017, its parallelizable self‑attention shattered the performance ceiling of LSTMs on large‑scale language tasks. Transformers scale linearly in computation but quadratically in memory with respect to sequence length, making them the backbone of today’s large language models (LLMs) like GPT‑4, LLaMA, and PaLM. The community largely shifted focus away from recurrent models, assuming that RNNs could not compete at scale.

The new **xLSTM** family challenges that assumption. By revisiting the core LSTM mechanisms and adding two key innovations—**exponential gating** and **enhanced memory structures**—researchers have shown that scaled LSTMs can again rival Transformers and modern state‑space models (SSMs). In this post we unpack why those changes matter, how they address the classic shortcomings of LSTMs, and what the experimental results suggest for the future of recurrent architectures.

## A Quick Recap: How Classic LSTMs Work  

The original LSTM cell updates a scalar memory value \(c_t\) as  

\[
c_t = f_t \, c_{t-1} + i_t \, z_t,
\qquad
h_t = o_t \, \psi(c_t),
\]

where  

* \(i_t\), \(f_t\), \(o_t\) are sigmoid‑activated gates (input, forget, output).  
* \(z_t\) is a transformed version of the current input and previous hidden state.  
* \(\psi\) is typically a \(\tanh\) squashing function.

The additive update (the “carousel”) lets gradients flow unchanged across many time steps, solving the vanishing‑gradient issue that plagued earlier RNNs. Despite this elegance, three practical limitations emerged:

1. **No revision of stored content** – once a value is written into the scalar cell it cannot be efficiently overwritten by newer evidence.  
2. **Limited storage capacity** – a single scalar per cell forces heavy compression, hurting rare‑token prediction and other fine‑grained tasks.  
3. **Sequential bottleneck** – hidden‑to‑hidden connections force strict step‑by‑step processing, preventing parallel execution on modern hardware.

## Exponential Gating: A Simple but Powerful Fix  

The first breakthrough in xLSTM is **exponential gating**. Instead of using only sigmoid activations for all gates, xLSTM allows the input gate (and optionally the forget gate) to use an exponential function:

\[
i_t = \exp(\tilde{i}_t), \qquad
f_t = 
\begin{cases}
\sigma(\tilde{f}_t),\\
\exp(\tilde{f}_t)
\end{cases}
\]

Because exponentials can grow without bound, they enable a gate to *strongly reinforce* or *rapidly decay* stored information. To keep these values numerically stable, xLSTM introduces a **stabilizer state** \(m_t\) that rescales both gates on the fly (see Eq. (3) of the paper). The net effect is that the network can *revise* past decisions: if a more relevant pattern appears later in the sequence, an exponentially large input gate can overwrite earlier content despite earlier forget signals.

Empirically, this modification solves tasks like **nearest‑neighbor search**, where classic LSTMs struggle because they cannot replace an earlier stored neighbor with a closer one encountered later. With exponential gating, xLSTM’s error drops dramatically.

## New Memory Structures: From Scalars to Matrices  

The second pillar of xLSTM upgrades the memory itself.

### sLSTM – Scalar Memory with Mixing  

The **sLSTM** keeps a single scalar per cell but adds a *normalizer state* \(n_t\) that tracks cumulative gate strength:

\[
n_t = f_t \, n_{t-1} + i_t .
\]

The hidden output becomes  

\[
h_t = o_t \frac{c_t}{n_t},
\]

which normalizes the cell state by its total “attention” over time. This simple change improves stability when exponential gates are used and also enables **memory mixing** across multiple cells or heads—something vanilla LSTMs cannot do without extra recurrent weight matrices.

### mLSTM – Matrix Memory with Covariance Updates  

The more radical shift is the **mLSTM**, which replaces each scalar cell with a full matrix \(\mathbf{C}_t \in \mathbb{R}^{d\times d}\). The update follows a classic *covariance* (outer‑product) rule:

\[
\mathbf{C}_t = f_t \,\mathbf{C}_{t-1} + i_t \,\mathbf{v}_t \mathbf{k}_t^{\!\top},
\]

where \(\mathbf{k}_t\) (key) and \(\mathbf{v}_t\) (value) are linear projections of the current input—exactly like the query/key/value formulation in Transformers. Retrieval simply multiplies this matrix by a query vector \(\mathbf{q}_t\):

\[
\tilde{\mathbf{h}}_t = 
\frac{\mathbf{C}_t \,\mathbf{q}_t}
{\max\!\bigl(|\,\mathbf{n}_t^{\!\top}\!\mathbf{q}_t|,\;1\bigr)} .
\]

Because the forget gate now acts as a decay factor on the whole matrix and the input gate controls how much new outer product is added, mLSTM can store *rich associative memories* without any learned parameters inside the matrix itself. The update is mathematically equivalent to Fast Weight Programmers and enjoys optimal signal‑to‑noise properties for binary retrieval tasks.

Importantly, mLSTM removes hidden‑to‑hidden connections entirely; therefore its recurrence can be **reformulated in parallel**, achieving computation speeds comparable to modern linear attention mechanisms.

## Building Blocks: xLSTM Residual Modules  

To turn these cells into large language models, xLSTM integrates them into residual block backbones—standard practice in modern deep learning:

* **Post up‑projection blocks** (used with sLSTM) first process the hidden state non‑linearly in its native dimension and then expand it via a linear projection before adding back to the residual path.
* **Pre up‑projection blocks** (used with mLSTM) project inputs up front so that the high‑dimensional matrix memory operates on a richer representation.

Stacking many such blocks with pre‑LayerNorm yields an architecture we simply call **xLSTM**. Because each block processes data linearly in sequence length (no quadratic attention), memory usage stays constant as sequences grow—a stark contrast to Transformers.

## How Does xLSTM Perform?  

### Synthetic Benchmarks  

* On formal language tasks that require explicit *state tracking* (e.g., Parity or Dyck languages), only models with memory mixing—xLSTM’s sLSTM and mLSTM—reach near‑perfect accuracy. Pure Transformers and SSMs fail because they lack recurrent state updates that can remember exact parity information.
* In a **Multi‑Query Associative Recall** test with up to 256 key–value pairs and sequence lengths of 2048 tokens, an xLSTM configuration mixing both sLSTM and mLSTM blocks outperforms all non‑Transformer baselines and even rivals larger Transformers despite using far fewer parameters.
* The **Long Range Arena** suite shows consistent gains across image classification from patches, byte‐level text classification, and other long‑context problems.

### Scaling to Real Language Modeling  

Training on 15 B tokens from SlimPajama (the same budget used for many open LLM baselines), xLSTM achieved lower validation perplexity than GPT‑3‑size Transformers, LLaMA, Mamba (an SSM), RWKV series (recurrent baselines), and several linear transformers. An ablation study confirmed that both exponential gating *and* matrix memory independently contributed to these gains.

When scaling up to 300 B tokens—a dataset size typical for state-of-the-art LLMs—xLSTM variants continued to dominate:

| Model | 125 M | 350 M | 760 M | 1.3 B |
|------|-------|-------|-------|-------|
| xLSTM[7:1] | ★ | ★ | ★ | ★ |
| xLSTM[1:0] | ★ | ★ | ★ | ★ |
| LLaMA | — | — | — | — |
| Mamba | — | — | — | — |
| RWKV‑4 | — | — | — | — |

(★ indicates best perplexity among all methods for that size.)

Beyond perplexity:

* **Length extrapolation**: models trained on context 2048 retained low perplexity up to 16 k tokens; Transformers degraded sharply because their self‑attention matrix grows quadratically.
* **Downstream reasoning tasks**: xLSTM beat competitors on most benchmarks (e.g., ARC‐Easy/Challenge, HellaSwag), only losing to Mamba on a few niche tasks.
* **Domain coverage**: On PALOMA’s 571 text domains, xLSTM[1:0] achieved lower perplexity than every other method in >99 % of domains.
* **Scaling laws**: Plotting loss versus model size shows all families follow similar power laws; however xLSTM’s curve lies consistently below Transformers and SSMs—meaning larger xLSTMs should retain their advantage.

Inference speed also scales linearly with sequence length, unlike quadratic scaling for Transformers. While current CUDA kernels for mLSTM are not yet as optimized as FlashAttention, preliminary results already demonstrate higher throughput at long contexts because memory remains constant.

## Why Reviving RNNs Is Worth It  

1. **Linear time & constant memory** – Ideal for edge devices or servers where GPU memory is at a premium.
2. **Better long‐context handling** – No need for costly cache management; hidden states carry forward indefinitely.
3. **Fine‐grained associative memory** – Matrix memories give LSTMs expressive power comparable to attention without explicit pairwise token interactions.
4. **Compatibility with existing training pipelines** – xLSTM slots into standard residual architectures; existing optimizer tricks (AdamW, learning rate schedules) work unchanged.
5. **New research directions** – Exponential gating opens possibilities for adaptive forgetting/remembering strategies; matrix memories hint at hybrid “fast weight”–plus–slow weight systems scalable to billions of parameters.

## Limitations & Future Work  

* sLSTM’s hidden–hidden mixing still forces serial computation; although an efficient CUDA kernel reduces slowdown to <2× compared with fully parallel mLSTM, further optimization is needed.
* Current mLSTM kernels are about four times slower than FlashAttention; dedicated kernel engineering could close this gap.
* Matrix memory scales quadratically in hidden dimension \(d\); careful trade‑offs between dimension size and GPU throughput will be crucial for very large models.
* Forget‐gate initialization remains sensitive; improper values can cause either vanishing or exploding updates.
* The large‐scale experiments used relatively modest hyperparameter tuning; more aggressive optimization may push performance even higher.

## Conclusion  

The story of LSTMs isn’t over—it’s evolving. By revisiting two foundational ideas—gating and constant error carousel—and augmenting them with exponential dynamics and richer memory representations, xLSTM demonstrates that classic recurrent networks can compete head‑to‑head with Transformers even at billions of parameters.

For practitioners interested in low‑latency inference on long sequences or developers targeting resource‑constrained environments, xLSTMs offer a promising alternative that combines decades of RNN wisdom with modern scaling tricks. As kernel implementations improve and community adoption grows, we may soon see “recurrent” language models listed alongside their Transformer peers—not as nostalgic relics but as first‐class contenders in modern AI.

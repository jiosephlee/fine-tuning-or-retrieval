\title{A Textbook about the Paper: "xLSTM: Extended Long Short-Term Memory"}

Chapter 3: # Identified Limitations of the Standard LSTM  

The Long Short‑Term Memory network (LSTM) has been a work‑horse of sequence modelling for more than three decades.  Its core mechanisms—the constant‑error carousel and the three sigmoid gates—solve the vanishing‑gradient problem that plagued earlier recurrent neural networks.  Nevertheless, when LSTMs are pushed to the scale of today’s large language models (LLMs), three fundamental shortcomings become evident.  These limitations are not merely academic curiosities; they directly impair the ability of an LSTM‑based architecture to compete with modern Transformer‑based systems on language modelling tasks.  In this chapter we dissect each of these drawbacks, illustrate them with concrete synthetic experiments described in the xLSTM paper, and connect the observations to a broader body of literature on recurrent networks.

---

## Inability to Revise Storage Decisions  

### The storage‑revision problem  

The original LSTM update for the cell state  

\[
c_t \;=\; f_t \, c_{t-1} \;+\; i_t \, z_t
\tag{1}
\]

allows the network to either retain the previous memory (through the forget gate \(f_t\)) or to write a new contribution (through the input gate \(i_t\)).  Once a value has been written into the scalar cell, the only way to “overwrite” it later is to let the forget gate decay the old content and then add a fresh input.  This design is inherently **unidirectional**: a later, more informative observation cannot retroactively replace an earlier stored value without first erasing the whole cell.

### Nearest‑Neighbor Search as a diagnostic task  

The paper uses a synthetic *Nearest‑Neighbor Search* problem to expose this weakness.  A reference vector \(\mathbf{r}\) is provided at the beginning of the sequence.  The model then receives a long stream of candidate vectors \(\{\mathbf{x}_1,\dots,\mathbf{x}_T\}\) and, at the final time step, must output the label attached to the **most similar** candidate (according to Euclidean distance).  An optimal algorithm would keep the best candidate seen so far and replace it whenever a closer one appears.  

When a standard LSTM processes the stream, its scalar cell can store only a single aggregated quantity.  If a more similar vector appears later, the network must first forget the previous value (via a small \(f_t\)) and then write the new value (via a large \(i_t\)).  Because the forget gate is bounded by a sigmoid, the decay is gradual, and the network exhibits a high mean‑squared error even after extensive training.  This inability to *revise* a stored decision is highlighted in the left panel of Figure 1 of the paper.

### How exponential gating mitigates the issue  

The xLSTM introduces **exponential gating**: the input gate \(i_t\) (and optionally the forget gate \(f_t\)) are computed as \(\exp(\tilde{i}_t)\) instead of \(\sigma(\tilde{i}_t)\).  Exponential activations can produce values far greater than one, allowing the network to *immediately* amplify a new, more relevant contribution while simultaneously scaling down the influence of older information.  The authors further stabilize these potentially large numbers by maintaining a normalizer state \(n_t\) and a stabilizer state \(m_t\) (see Equations (2)–(4) in the paper).  Empirically, the exponential‑gated sLSTM (the scalar variant) dramatically reduces the error on the nearest‑neighbor task, demonstrating that revisable storage is now feasible.

## Limited Scalar Memory Capacity and Its Effect on Rare‑Token Prediction  

### Scalar versus matrix memory  

In the classic LSTM each cell holds a **single scalar** \(c_t \in \mathbb{R}\).  Even when many cells are stacked into a vector \(\mathbf{c}_t \in \mathbb{R}^d\), each component remains a one‑dimensional bucket of information.  This design forces the model to compress all contextual cues into a low‑dimensional representation, which is adequate for many tasks but becomes a bottleneck for language modelling where the distribution of tokens is heavily skewed: a tiny fraction of tokens (the “rare” ones) appear only a handful of times in the training corpus.

### Rare‑token prediction experiment  

The authors evaluate this limitation on the **Wikitext‑103** benchmark, partitioning tokens by their training frequency.  Perplexity (the standard language‑modeling loss) is measured separately for frequent and rare token groups.  Figure 2 (right panel) of the paper shows a clear disparity: the baseline LSTM’s perplexity skyrockets on the rare‑token subset, whereas a Transformer‑based model maintains a relatively flat curve because its attention mechanism can retrieve fine‑grained token‑level details from many heads.

The intuition is that a scalar cell cannot simultaneously preserve detailed statistics about *all* token types.  When a rare token is encountered, its embedding must be merged into the existing scalar state, potentially overwriting information useful for later predictions of other rare tokens.  Consequently, the model’s ability to recall the correct distribution for low‑frequency words deteriorates.

### Matrix memory of mLSTM as a remedy  

To address the capacity ceiling, the xLSTM introduces **mLSTM**, whose memory is a full matrix \(\mathbf{C}_t \in \mathbb{R}^{d \times d}\).  The update rule follows a **covariance (outer‑product) accumulation**:

\[
\mathbf{C}_t \;=\; f_t \,\mathbf{C}_{t-1} \;+\; i_t \,\mathbf{v}_t \mathbf{k}_t^{\!\top},
\tag{5}
\]

where \(\mathbf{k}_t\) and \(\mathbf{v}_t\) are respectively a *key* and a *value* vector derived from the current input.  This rule is essentially a fast‑weight or associative memory mechanism: each key‑value pair contributes a rank‑one update to the memory matrix, and the forget gate serves as a decay factor.  The matrix can store a **large set of associations** in a distributed fashion, dramatically increasing the effective storage bandwidth compared with scalar cells.

When evaluated on the same rare‑token partitions, the mLSTM‑based xLSTM narrows the perplexity gap: it can retain enough distinct information about infrequent words to make accurate predictions, while still benefiting from the recurrent inductive bias of the constant‑error carousel.

## Sequential Hidden‑Hidden Connections → Lack of Parallelism  

### The hidden‑hidden recurrence  

Beyond the cell state recurrence, canonical LSTMs also contain hidden‑to‑hidden connections: the current hidden state \(h_t\) is computed from the previous hidden state \(h_{t-1}\) via the recurrent weights \(r_z, r_i, r_f, r_o\).  This **memory‑mixing** operation couples each time step to its predecessor, enforcing a strictly sequential computation order.  Even when the cell state update (the constant‑error carousel) is linear in time, the hidden‑hidden pathway introduces a second, non‑parallelizable dependency.

### Consequences for large‑scale training  

Training a Transformer benefits from massive parallelism: self‑attention can be evaluated for all positions simultaneously, and the quadratic cost can be reduced with efficient kernels.  An LSTM, by contrast, must perform a *scan* over the sequence—each step waiting for the hidden state of the previous step.  This serial dependency limits GPU utilisation, inflates wall‑clock time, and makes it difficult to scale to the billions of tokens and parameters typical of modern LLMs.

### Parallelizable mLSTM and the trade‑off  

The mLSTM deliberately **removes hidden‑hidden connections**.  Its recurrence resides solely in the matrix memory \(\mathbf{C}_t\) and the normalizer \(\mathbf{n}_t\), both of which are **linear scans** that can be expressed as prefix‑sum operations.  Because no hidden‑to‑hidden weight matrix is involved, the entire forward pass can be reformulated as a set of parallel matrix multiplications, akin to the way FlashAttention rewrites the attention recurrence.  The paper notes that this design makes mLSTM “fully parallelizable,” and empirical timing results show that the wall‑clock overhead is modest despite the \(d\times d\) matrix updates.

In contrast, the scalar sLSTM retains hidden‑hidden connections to preserve *memory mixing* across multiple heads, which is essential for solving state‑tracking formal‑language tasks (e.g., parity or nested‑bracket languages).  The authors acknowledge that sLSTM therefore remains sequential, but they provide a highly tuned CUDA kernel that reduces the slowdown to less than a factor of two relative to the parallel mLSTM.

## Empirical Evidence from Prior Literature  

The three limitations described above have been observed repeatedly in the broader RNN literature:

1. **Irrevocable memory updates** – Early works on associative memories (e.g., Hopfield networks, bidirectional associative memories) highlighted the need for *fast overwrite* capabilities, which later motivated fast‑weight programmers and exponential gate designs.

2. **Scalar bottleneck** – Studies on *capacity limits of recurrent networks* (e.g., Greff et al., 2015) demonstrated that a fixed‑size hidden vector struggles to encode long‑range dependencies when the information load grows, motivating augmentations such as external memory matrices (Neural Turing Machines, Differentiable Neural Computers).

3. **Sequential bottleneck** – The computational inefficiency of RNNs was precisely the problem that motivated the Transformer’s self‑attention (Vaswani et al., 2017).  Subsequent work on *linear attention* and *state‑space models* (e.g., S4, Mamba) focuses on achieving **linear time** and **parallelizable** recurrences, echoing the design choice in mLSTM to drop hidden‑hidden mixing.

Together, these prior observations converge on the same three axes of improvement that the xLSTM paper formalizes: (i) revisable storage via exponential gating, (ii) richer memory structures via matrix (fast‑weight) updates, and (iii) parallelism by eliminating hidden‑hidden recurrence.  The systematic experimental suite—nearest‑neighbor search, rare‑token prediction, formal‑language state tracking, and long‑range arena—provides concrete evidence that each modification directly addresses its corresponding limitation.

---  

In summary, while the original LSTM introduced groundbreaking mechanisms that solved the vanishing‑gradient crisis, its **scalar memory**, **non‑revisable gating**, and **sequential hidden‑hidden connections** become severe bottlenecks when the model is scaled to the billions of parameters required for modern language modelling.  The xLSTM architecture directly tackles these three constraints, paving the way for recurrent networks to compete with Transformers and state‑space models on large‑scale language tasks.

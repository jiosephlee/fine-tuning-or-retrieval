\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### How does exponential gating enable revision of stored values in sLSTM?
Question:
The paper introduces exponential activation functions for the input and forget gates in sLSTM (Eq. 3). I understand that this allows gates to take values larger than 1, but I am unclear on how exactly this solves the "inability to revise storage decisions" problem demonstrated with the Nearest Neighbor Search task. Could someone walk through a concrete example of how an exponential input gate can overwrite a previously stored value while still preserving gradient flow?
Answer:
The inability of a classic LSTM to **revise a storage decision** comes from the fact that the input‑gate $i_t$ and the forget‑gate $f_t$ are bounded by the sigmoid function:
$$
0\le i_t ,f_t\le 1 .
$$
When a value $v$ has already been written into the cell,
$$
c_t = f_t\,c_{t-1}+i_t\,z_t ,
$$
any later attempt to replace it must first *forget* the old contribution by setting $f_t$ close to 0 and then *add* the new contribution with a large $i_t$. Because both factors are ≤ 1, the product
$f_t\,c_{t-1}$ can never become negative, and the magnitude of the new term $i_t\,z_t$ cannot exceed $|z_t|$.  
Consequently, once a large value has been stored, the LSTM can only *attenuate* it gradually; it cannot **overwrite** it in a single step. This is exactly what hurts performance on the Nearest‑Neighbour Search (NNS) task: when a more similar reference vector appears later in the sequence, the network cannot promptly replace the previously stored value.

### Exponential gates change the picture

In sLSTM the input gate is replaced by an **exponential activation**
$$
i_t = \exp(\tilde i_t),
\qquad
\tilde i_t = \mathbf w_i^{\top}\mathbf x_t + r_i h_{t-1}+b_i ,
$$
and (optionally) the forget gate may also be exponential.  
Because $\exp(\cdot)$ is unbounded above, $i_t$ can become arbitrarily large, while still being smooth and differentiable. The cell update remains
$$
c_t = f_t\,c_{t-1}+i_t\,z_t .
$$

Now imagine that at time step $t_1$ we store a value $v_1=z_{t_1}$ that is moderately relevant:
* choose a modest input‑gate magnitude, e.g. $i_{t_1}=1$;
* set the forget gate close to 1 so that the value persists: $f_{t_1}=1$.

Thus after $t_1$ we have
$c_{t_1}=v_1$.

Later, at time step $t_2>t_1$, a **more similar** reference vector arrives and we would like to replace $v_1$ by a new value $v_2=z_{t_2}$. With exponential gating we can do it in one step:

1. **Force forgetting:** set an exponential forget gate with a *tiny* value, for instance  
   $\tilde f_{t_2}=-10 \;\Rightarrow\; f_{t_2}= \exp(-10)\approx4.5\times10^{-5}$.  
   The term $f_{t_2}c_{t_1}$ becomes practically zero.
2. **Overwrite with a huge input gate:** choose $\tilde i_{t_2}=5$, giving  
   $i_{t_2}= \exp(5)\approx148$.  
   The new contribution is then $i_{t_2}z_{t_2}=148\,v_2$.

The new cell state becomes
$$
c_{t_2}= f_{t_2}c_{t_1}+i_{t_2}z_{t_2}
       \approx 0+148\,v_2 .
$$
Because we later divide by the *normaliser* $n_t$ (see Eq. (3)),
$$
n_t = f_t n_{t-1}+ i_t , \qquad 
h_t = o_t\, \frac{c_t}{n_t},
$$
the hidden state sees only the **relative** contribution of the stored value:
$$
h_{t_2}=o_{t_2}\,\frac{148\,v_2}{148+n_{\text{old}}}.
$$
If we make both gates large at the same time (large $i_{t_2}$, tiny $f_{t_2}$), the denominator is dominated by the fresh gate,
so $\frac{c_{t_2}}{n_{t_2}}\approx v_2$.  In effect, sLSTM has *overwritten* what was previously stored.

### Why gradients still flow

Both exponential functions are smooth:
$$
\frac{\partial i_t}{\partial \tilde i_t}= \exp(\tilde i_t)=i_t , \qquad
\frac{\partial f_t}{\partial \tilde f_t}=f_t .
$$
Even when a gate takes an extreme value (e.g. $i=148$), its derivative is simply that same magnitude, not zero. During back‑propagation through time, the gradient that reaches earlier steps is multiplied by these gate values exactly as in an ordinary LSTM; there is no “hard cut‑off”. Moreover, the paper introduces a **stabiliser state** (Eq. (4)) that rescales all gates by a common factor
$e^{-m_t}$, so that very large exponents do not cause overflow while preserving the exact product of gates. The rescaling leaves both forward activations and their Jacobians unchanged, guaranteeing that gradients remain well‑behaved.

### Putting it together on the NNS task

During NNS training, each input vector becomes either a *candidate* key or a *reference*. The sLSTM learns to:
* write a candidate’s value with a modest input gate when its similarity to the reference is low;
* when later encountering a more similar candidate, fire an enormous input gate and an almost‑zero forget gate,
  thereby wiping out earlier contributions and storing only the best match.

Because this overwriting happens in **one time step**, loss gradients can directly associate “more similar later → larger input gate” without having to rely on slow decay through many forget steps. Empirically (Figure 3 of the paper), sLSTM with exponential gating reduces mean‑squared error on NNS dramatically compared with vanilla LSTM.

In summary, exponential gating lifts the sigmoid ceiling, allowing a single time step to **erase** past information (tiny forget gate) and **inject** fresh information at any scale (large input gate). The normaliser guarantees that hidden outputs stay numerically stable, and stabilisation via $m_t$ preserves gradient flow. This mechanism solves precisely the “cannot revise storage decisions” problem illustrated by Nearest‑Neighbour Search.

### What is the role of the normalizer state \(n_t\) in sLSTM and mLSTM?
Question:
Both sLSTM (Eq. 3) and mLSTM (Eq. 7) maintain a normalizer state \(n_t\) that accumulates products of input gates and forget gates. The paper says it "sums up the product of the input gate times all future forget gates" and is used for scaling the hidden state. How is \(n_t\) computed in practice, why is it needed, and what would happen if we omitted this normalization step?
Answer:
The normaliser \(n_{t}\) (or \(\mathbf n_{t}\) in the matrix case) is introduced to keep the magnitude of the hidden‑state representation under control when the gates are allowed to grow **exponentially**.  

In a classic LSTM the cell state is bounded only by the sigmoid forget gate, so the hidden state
\(\tilde h_{t}=c_{t}\) is already of a reasonable scale and the output gate \(o_{t}\) can be applied directly.  
When we replace the sigmoid input gate (and optionally the forget gate) by an **exponential activation**
\[
i_{t}=e^{\tilde i_{t}}, \qquad 
f_{t}=e^{\tilde f_{t}}\;(\text{or }\sigma(\tilde f_{t}))
\]
the values of \(i_{t}\) and \(f_{t}\) are no longer confined to \([0,1]\); they can become very large (or very small).  
Consequently, the ordinary cell update
\[
c_{t}=f_{t}c_{t-1}+i_{t}z_{t}
\]
may produce numbers that explode or collapse to zero, which would make learning unstable and would render the hidden state useless for downstream layers.

### What \(n_{t}\) actually computes  

For the scalar sLSTM the normaliser obeys the same recurrence as the cell, but without the input term:
\[
n_{t}=f_{t}n_{t-1}+i_{t}.
\tag{1}
\]
Unrolling (1) shows that
\[
n_{t}=i_{t}+f_{t}i_{t-1}+f_{t}f_{t-1}i_{t-2}+\dots+f_{t}\dots f_{2}i_{1},
\]
i.e. **“the product of an input gate with all future forget gates”** summed over all time‑steps that have contributed to the current cell.  
Hence \(n_{t}\) measures exactly how much total “mass’’ has been injected into the cell up to time \(t\), taking into account how much of that mass survives after each subsequent forget operation.

In the matrix‑valued mLSTM an analogous quantity is maintained:
\[
\mathbf n_{t}=f_{t}\mathbf n_{t-1}+i_{t}\mathbf k_{t},
\tag{2}
\]
which accumulates the *keys* \(\mathbf k_t\) weighted by the same gate products.  The dot‑product \(\mathbf n_t^{\!\top}\mathbf q_t\) therefore estimates how strong the current query \(\mathbf q_t\) is relative to all previously stored keys.

### How it is used  

Both architectures divide the raw hidden output by this normaliser:

* sLSTM:  \(\displaystyle \tilde h_t = \frac{c_t}{n_t}, \qquad h_t=o_t \tilde h_t.\)

* mLSTM:  \(\displaystyle 
\tilde{\mathbf h}_t = 
\frac{\mathbf C_t\,\mathbf q_t}{\max\!\bigl(|\mathbf n_t^{\!\top}\!\mathbf q_t|,\,1\bigr)},
\qquad 
\mathbf h_t = \mathbf o_t \odot \tilde{\mathbf h}_t.\)

The division performs a **dynamic scaling** that exactly compensates for the growth caused by exponential gates. Because \(n_t\) (or its scalar analogue) accumulates precisely the same products that appear in \(c_t\), dividing cancels most of the multiplicative effect, leaving a hidden representation whose magnitude stays in a well‑behaved range (typically around 1). In practice this means that standard optimiser hyper‑parameters and activation functions can be used without overflow or vanishing‑gradient problems.

### Why it is needed  

Without a normaliser one would have to rely on either

1. clamping the exponential gate values (defeating their purpose), or  
2. resorting to very small initialisations and learning rates, which makes training extremely slow.

Both options either limit expressivity—because we would no longer be able to assign large updates when needed—or introduce numerical instability when any gate becomes large. The normaliser solves this by *decoupling* magnitude from content: gates may freely become large to express strong updates, while \(n_t^{-1}\) rescales them back to a stable range before passing them on.

### What happens if we drop it?  

Empirically (see Appendix B of the paper), removing \(n_t\) causes training to diverge almost immediately for any non‑trivial setting of exponential gates. Typical failure modes are:

* **Overflow/NaN** – exponentials quickly exceed floating‑point limits, especially on long sequences where many multiplications accumulate.
* **Gradient explosion** – because back‑propagation also follows the same multiplicative chain, gradients grow without bound, making optimisation impossible.
* **Loss of interpretability** – hidden states become dominated by a few large gate values, effectively erasing information about earlier timesteps.

If one keeps exponential gates but substitutes a fixed scalar normalisation (e.g., dividing by a constant), performance drops dramatically because the normaliser would no longer reflect how much mass has actually been inserted at each step; the scaling would be either too aggressive (under‑using information) or too weak (still allowing blow‑up).

### Intuition  

Think of \(c_t\) as a bucket that receives water (\(i_tz_t\)) and leaks proportionally to its current amount (\(f_tc_{t-1}\)). The normaliser \(n_t\) is a second bucket that records *how much water has ever been poured in*, taking leakage into account in exactly the same way. When we look at what’s inside the first bucket we divide by how much water was ever poured; this tells us *the concentration* of information independent of raw volume. The concentration is what downstream layers need—its scale stays roughly constant even though the absolute volume may vary wildly because of exponential gates.

In summary, \(n_t\) (or \(\mathbf n_t\)) is a dynamically updated scaling factor that mirrors the multiplicative dynamics introduced by exponential gating. It guarantees numerical stability, preserves gradient flow, and allows sLSTM/mLSTM to reap the expressive power of exponential gates without suffering from exploding activations. Omitting it destroys those benefits and leads to unstable training.

### How does the stabilizer state \(m_t\) prevent overflow in exponential gates?
Question:
Equation 4 defines a stabilizer state \(m_t = \max(\log(f_t) + m_{t-1}, \log(i_t))\) and then rescales the gates to \(i'_t\) and \(f'_t\). I am confused about why this max operation works and how it guarantees that the exponentials stay within a numerically stable range. Is this equivalent to subtracting a running log‑max across time steps?
Answer:
In the sLSTM the input‑ and forget‑gates are allowed to be **exponential**:  

$$
i_t = \exp (\tilde i_t),\qquad 
f_t = \exp (\tilde f_t)\;\;(\text{or }\sigma(\tilde f_t)).
$$

Because the exponentials act on an affine transformation of the inputs, the raw values of $i_t$ and $f_t$ can become astronomically large (or extremely small) as the recurrence proceeds.  If we were to use these raw numbers directly in  

$$
c_t = f_t\,c_{t-1}+ i_t\,z_t ,\qquad
n_t = f_t\,n_{t-1}+ i_t ,
$$

the products $f_tc_{t-1}$ or $i_tz_t$ would quickly overflow the finite‑precision floating‑point format, and the gradients would become either zero (under‑flow) or NaN (over‑flow).  

The paper solves this problem by **tracking a single scalar “stabilizer” $m_t$** that records the dominant magnitude of the product of gates up to time $t$.  The update rule (Eq. 4) is  

$$
m_t = \max\bigl(\log f_t + m_{t-1}, \; \log i_t\bigr).
$$

Interpret this as follows.  
The term $\log f_t + m_{t-1}$ is exactly the logarithm of the quantity that would multiply the previous stabilizer state when we propagate a factor through a forget gate:
$$
\exp(\log f_t + m_{t-1}) = f_t \,\exp(m_{t-1}).
$$
The second argument, $\log i_t$, is the logarithm of the fresh contribution from the input gate at the current step.  
Taking the **maximum** picks the larger of the two logarithmic magnitudes, i.e. the dominant scale among all contributions that have been accumulated so far.  Consequently $m_t$ is a running log‑*max* of all factors that appear in the recurrence.

Once $m_t$ is known we **renormalise** the gates:

$$
i'_t = \exp(\log i_t - m_t)=\frac{i_t}{e^{m_t}},\qquad
f'_t = \exp(\log f_t + m_{t-1} - m_t)=
      \frac{f_t\,e^{m_{t-1}}}{e^{m_t}} .
$$

Both $i'_t$ and $f'_t$ are now guaranteed to lie in $[0,1]$.  The proof is immediate from the definition of $m_t$:

* if $m_t = \log i_t$ then $\log i_t - m_t =0$ ⇒ $i'_t=1$, and because  
  $\log f_t + m_{t-1}\le m_t$ we have $\log f_t + m_{t-1}-m_t \le 0$ ⇒ $f'_t\le 1$;
* if $m_t = \log f_t + m_{t-1}$ then analogously $f'_t=1$ and $i'_t\le 1$.

Thus **the stabilizer reduces every exponential gate to a number that can never exceed one**, eliminating any risk of overflow while preserving their *relative* strengths.  Importantly, substituting $i'_t,f'_t$ for $i_t,f_t$ does **not** change the overall computation:

$$
c_t = f'_t\,c_{t-1}+ i'_t\,z_t,
\qquad
n_t = f'_t\,n_{t-1}+ i'_t ,
$$

because every term has been divided by exactly the same factor $e^{m_t}$; that common factor cancels out when we later form ratios such as  

$$
\tilde h _t = \frac{c_t}{n_t},
$$

which is precisely what appears in Eq. (2).  Therefore the forward‑pass outputs and all gradients are unchanged – only their numerical representation is stabilised.

Conceptually this is equivalent to maintaining a **running log‑maximum** across time steps and subtracting it from each newly computed log‑gate before exponentiating.  The idea mirrors standard tricks used in softmax or attention implementations (subtracting a max before exponentiation), but here it is applied recursively over a sequence so that *every* intermediate product stays within a safe dynamic range.

In short, the max operation in Eq. 4 chooses the dominant logarithmic scale at each step, and by normalising both gates with that scale we keep all exponentials bounded in $[0,1]$.  This prevents overflow/under‑flow without altering any mathematical property of the recurrent update.

### Why does mLSTM use a matrix memory \(\mathbf{C}_t\in\mathbb{R}^{d\times d}\) instead of a vector?
Question:
The paper claims that increasing the memory from a scalar to a matrix boosts storage capacity, especially for rare token prediction. Could someone explain intuitively how a covariance update \(\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top\) stores more information than a scalar cell, and how retrieval via \(\mathbf{C}_t \mathbf{q}_t\) works in practice?
Answer:
In a classic LSTM the *cell* $c_{t}$ is a single scalar (or, when we use many cells, a vector of length $d$).  
At each time step the cell is updated by adding a *rank‑1* contribution  

$$
c_{t}=f_{t}\,c_{t-1}+i_{t}\,z_{t},
$$

so the whole history is compressed into one number per hidden dimension.  
If we think of the cell as a “bucket” that contains the *total amount of evidence* for a particular feature, then after many timesteps that bucket inevitably mixes together many different pieces of evidence: the only thing that survives is the **sum** (or an exponentially‑weighted sum) of all past inputs.  Consequently the bucket cannot remember *which* token contributed what, only a coarse statistics.  This limitation is especially visible for rare tokens – their contribution is quickly drowned out by the many frequent updates that hit the same bucket.

---

### Turning the bucket into a matrix

The mLSTM replaces each scalar bucket by a full matrix  

$$
\mathbf C_{t}\in\mathbb R^{d\times d},
$$

and updates it with an outer‑product term

$$
\mathbf C_{t}=f_{t}\,\mathbf C_{t-1}+i_{t}\,\mathbf v_{t}\,\mathbf k_{t}^{\!\top}.
\tag{1}
$$

Here $\mathbf k_{t}$ is called a *key* and $\mathbf v_{t}$ a *value*.  
Equation (1) is exactly the **covariance (or fast‑weight) update** that classical associative memory models use: each new key–value pair adds a rank‑1 matrix $\mathbf v_{t}\mathbf k_{t}^{\!\top}$ to the memory.  Because the outer product lives in a $d\times d$ space, every new pair occupies its own *direction* in this space rather than collapsing onto a single line.

Intuitively, think of $\mathbf C_t$ as a table whose rows correspond to *value directions* and columns to *key directions*.  When you write a pair $(\mathbf k_t,\mathbf v_t)$ you colour a single cell of this table (the outer‑product) – but because the vectors are dense, many cells receive small contributions simultaneously.  After many steps the table contains a **superposition** of all previously written pairs, where each pair can still be pulled apart by looking at how it aligns with a query.

---

### Why does this give larger capacity?

A scalar can store only one degree of freedom per hidden dimension.  
A $d\times d$ matrix has $d^{2}$ degrees of freedom.  The update (1) never overwrites an entire row or column; it only adds another rank‑1 component.  As long as the set of key vectors $\{\mathbf k_t\}$ remains sufficiently diverse (which is encouraged by layer‑norm and random initialisation), the collection $\{\mathbf v_t \mathbf k_t^{\!\top}\}$ will be linearly independent for up to roughly $d$ different keys.  In practice this means the memory can reliably store **$O(d)$** distinct key–value pairs, whereas a vector cell can only keep track of one aggregated statistic per dimension.

The paper points out that this extra capacity matters most for *rare token prediction*: a rare token appears only a few times, so its contribution $i_t \mathbf v_t \mathbf k_t^{\!\top}$ would be swamped in a scalar cell.  In the matrix case each rare pair occupies its own sub‑space and can be recovered later without being drowned out by frequent updates.

---

### Retrieval: $\tilde{\mathbf h}_t=\frac{\mathbf C_t \mathbf q_t}{\max(|\mathbf n_t^{\!\top}\!\mathbf q_t|,1)}$

At time $t+\tau$ we form a query vector $\mathbf q_{t+\tau}$.  
Multiplying the stored matrix by this query,

$$
\mathbf C_t\,\mathbf q_t = 
      \sum_{\ell\le t} i_\ell\, f_{t}^{\,\,\,\,\,(\text{decay})}
      (\mathbf v_\ell\, (\mathbf k_\ell^{\!\top} \mathbf q_t)),
$$

produces a weighted sum of all past values $\mathbf v_\ell$.  The weight for each value is exactly the inner product $\mathbf k_\ell^{\!\top} \mathbf q_t$; if the query aligns with a stored key, that term becomes large and its value dominates the sum.  The normaliser $\mathbf n_t = f_t\,\mathbf n_{t-1}+i_t\,\mathbf k_t$ records how much total key “mass’’ has been written, and dividing by $|\mathbf n_t^{\!\top}\!\! \mathbf q_t|$ simply rescales the output so that it does not grow with the number of writes (the max with 1 avoids division by zero).  

Thus retrieval behaves like **content‑addressable memory**: you ask “what value was stored with a key similar to this query?” and the outer‑product memory returns precisely that value (plus some interference from other keys).  Because interference grows only slowly with the number of stored pairs—thanks to the high dimensionality—the system can keep dozens or hundreds of distinct associations alive simultaneously.

---

### Putting it together

* The scalar LSTM cell compresses everything into one number per hidden unit; information about *which* token caused which change is lost.
* The mLSTM replaces that number by a full $d\times d$ matrix that receives an outer‑product update for every key–value pair.
* This update creates a superposition of rank‑1 components that can be disentangled later by an inner product with a query, exactly like associative recall.
* Because there are $d^{2}$ independent directions in which to store information, the effective storage capacity scales roughly linearly with $d$, enabling reliable memorisation of many rare events.

The empirical results in the paper (e.g., Figure 3 on rare‑token perplexity and the Multi‑Query Associative Recall task) show precisely this effect: mLSTM dramatically reduces perplexity on low‑frequency tokens and attains higher recall accuracy than models that still rely on scalar cells.  Hence, moving from a scalar to a matrix memory directly translates into richer, more discriminative storage—exactly what is needed for long‑range language modelling tasks where rare words carry significant meaning.

### What does "memory mixing" mean for sLSTM, and how does it differ from hidden‑hidden connections in vanilla LSTM?
Question:
Section 2.2 mentions that sLSTM can have multiple memory cells with recurrent matrices \(\mathbf{R}_{\mathbf{z}}, \mathbf{R}_{\mathbf{i}}, \mathbf{R}_{\mathbf{f}}, \mathbf{R}_{\mathbf{o}}\) and that exponential gating changes their effect. How is this different from the standard hidden‑to‑gate connections in Eq. 2, and why does it enable new forms of state tracking?
Answer:
**Answer**

In a vanilla LSTM the only recurrent path that links two successive time‑steps is the *hidden‑to‑hidden* connection  
\(h_{t-1}\rightarrow h_{t}\) that appears in the affine term of every gate (Eq.~2).  
When we write the gate pre‑activations as  

\[
\tilde{i}_t = \mathbf{w}_i^{\top}\mathbf{x}_t + r_i\,h_{t-1}+b_i,\qquad
\tilde{f}_t = \mathbf{w}_f^{\top}\mathbf{x}_t + r_f\,h_{t-1}+b_f,\; \dots
\]

the scalar coefficients \(r_i,r_f,r_o,r_z\) are the *hidden‑hidden* weights.  
These connections are essential for a recurrent network: they let the hidden state
carry information forward, but they do **not** mix the *cell* values of different
memory cells. If the LSTM has \(d\) parallel cells, each cell \(c_t^{(k)}\) is updated
independently according to  

\[
c_t^{(k)} = f_t^{(k)}c_{t-1}^{(k)}+i_t^{(k)}z_t^{(k)},
\]

and any interaction between cells can only happen through the output gate
\(o_t\) (which merely scales the summed hidden vector). In practice this means
that a vanilla LSTM can only *track* a single scalar quantity per cell; it cannot
re‑allocate or redistribute information among cells during a sequence.

---

### What “memory mixing’’ adds in sLSTM

The sLSTM introduces **recurrent matrices**
\(\mathbf{R}_{\mathbf{z}},\mathbf{R}_{\mathbf{i}},\mathbf{R}_{\mathbf{f}},\mathbf{R}_{\mathbf{o}}\)
that connect **the hidden vector \(\mathbf{h}_{t-1}\) to each gate’s *vector* of
values** (Section 2.2).  Concretely, for a multi‑cell sLSTM we have

\[
\tilde{\mathbf{i}}_t = \mathbf{W}_i^\top \mathbf{x}_t + 
   \underbrace{\mathbf{R}_{i}\,\mathbf{h}_{t-1}}_{\text{memory mixing}}
   + \mathbf{b}_i,
\]

and similarly for \(\tilde{\mathbf{f}}_t,\tilde{\mathbf{o}}_t,\tilde{\mathbf{z}}_t\).
Because \(\mathbf{R}_*\in \mathbb{R}^{d\times d}\) is a full matrix rather than a
scalar, each component of \(\mathbf{h}_{t-1}\) can influence *any* component of
the gate vectors.  When the gates are later passed through the **exponential**
activation (\(i_t=\exp(\tilde i_t)\), \(f_t=\exp(\tilde f_t)\) or
\(\sigma(\tilde f_t)\)), a small change in one hidden dimension can be amplified
exponentially and redistributed across all cells.

Intuitively, **memory mixing** gives the network the ability to *re‑write* where
information is stored while a sequence progresses.  Suppose cell 1 has accumulated a
value that later turns out to be less useful, while cell 3 would be better suited.
The mixed recurrent matrix can route part of the hidden signal from cell 1 into the
gate that controls cell 3, effectively moving memory from one slot to another.
This kind of *state tracking*—the capacity to revise earlier storage decisions—is
exactly what vanilla LSTMs cannot do because their hidden‑hidden weights are scalars,
so each cell’s update depends only on its own previous hidden value.

The paper demonstrates this with the “Nearest‑Neighbour Search’’ task (Fig.~1):
standard LSTMs keep the first encountered value even when a closer neighbour appears,
whereas sLSTM with exponential gating and memory mixing updates its stored value
correctly.

---

### How it differs from plain hidden‑hidden connections

| Aspect | Vanilla LSTM | sLSTM (memory mixing) |
|--------|--------------|-----------------------|
| Recurrent weight shape | scalar \(r_*\) per gate | full matrix \(\mathbf{R}_*\in\mathbb{R}^{d\times d}\) |
| Effect on gate vector | only scales each component independently | each hidden dimension can affect every gate component |
| Ability to move information between cells | None (cells evolve independently) | Explicit redistribution of information across cells |
| Interaction with exponential gating | Gates are sigmoids, bounded ⇒ limited amplification | Exponential gates can amplify mixed signals, enabling fast revision |

Thus “memory mixing’’ is not just another hidden‑to‑gate connection; it is a **structured,
dense coupling** among all cells that works together with exponential gates to give
the network an expressive mechanism for reshaping its internal state on the fly.

---

### Why this enables new forms of state tracking

State tracking requires two ingredients:

1. **Awareness of past decisions** – provided by the hidden state that summarises the
   whole history up to \(t-1\).
2. **Flexibility to modify those decisions** – requires that later inputs can alter
   where earlier information resides.

In vanilla LSTMs step 2 is missing because each cell’s content can only be scaled by
its own forget gate; there is no pathway to move content between cells.  
Memory mixing supplies exactly that pathway: by linearly combining hidden components,
the network can compute gate values that **increase** one cell while **decreasing**
another, all in a single time step. The exponential activation turns these linear
combinations into multiplicative factors that can quickly overwrite stale values,
hence “revision of storage decisions’’ as described in Section 2.2.

Consequently, sLSTM can solve formal languages that need counting or parity (tasks
where you must flip a bit after seeing each relevant symbol), whereas Transformers or
State‑Space models that lack memory mixing fail on these tasks (Figure 4 in the paper).

---

### TL;DR

- Vanilla LSTMs have only scalar hidden‑to‑gate weights; each memory cell updates
  independently and cannot exchange stored information.
- sLSTM replaces those scalars by full recurrent matrices (\(\mathbf{R}_*\)), which lets any hidden dimension influence any gate component – this is called **memory mixing**.
- Combined with exponential gates, memory mixing lets the network *reallocate* and *revise* stored values across cells during processing, enabling sophisticated state tracking that vanilla LSTMs cannot perform.

### How are heads implemented in sLSTM and why are they not allowed to mix memories across heads?
Question:
The paper states that sLSTM can have multiple heads with memory mixing within each head but not across heads, whereas for mLSTM heads are equivalent to multiple cells. What is the exact architecture of a head (e.g., separate gate parameters, separate normalizer?), and what is the motivation for prohibiting cross‑head mixing?
Answer:
In the sLSTM the notion of a *head* is introduced exactly because the exponential‑gate formulation gives us a new way to mix the information that lives in the recurrent hidden‑to‑hidden connections.  
A head is **not** a separate “mini‑network” that runs in parallel with its own completely independent set of parameters; rather it is a *partition* of the full hidden vector into several sub‑vectors, each of which carries its own LSTM‑style gates and its own normaliser state.  

---

### What a head contains

For an sLSTM with \(H\) heads we first split the hidden state \(\mathbf{h}_{t-1}\in\mathbb{R}^{d}\) into
\[
\mathbf{h}_{t-1}= \big[\,\mathbf{h}^{(1)}_{t-1},\dots,\mathbf{h}^{(H)}_{t-1}\,\big],
\qquad
\mathbf{h}^{(h)}_{t-1}\in\mathbb{R}^{d_h},
\]
with \(\sum_{h=1}^{H}d_h = d\).  
For each head \(h\) we then compute **its own** input, forget and output pre‑activations
\[
\tilde{i}^{(h)}_t = \mathbf{w}^{\top}_{i^{(h)}}\mathbf{x}_t + r_{i^{(h)}}\,\mathbf{h}^{(h)}_{t-1} + b_{i^{(h)}},
\]
and similarly \(\tilde{f}^{(h)}_t, \tilde{o}^{(h)}_t, \tilde{z}^{(h)}_t\).  
Consequently each head owns its **own weight vectors** (or, if we use a matrix formulation, its own *slice* of the recurrent weight matrices) and **its own bias terms**. The exponential activation for the input gate and the optional exponential or sigmoid activation for the forget gate are applied separately per head, exactly as in Eq. (4) of the paper.

The normaliser state—recall that sLSTM keeps a running sum
\(n_t = f_t n_{t-1}+ i_t\)—is also maintained per head:
\[
n^{(h)}_t = f^{(h)}_t\, n^{(h)}_{t-1}+ i^{(h)}_t .
\]
Thus each head has an independent “normaliser” that records how much total mass has been accumulated by that head’s gates.

Finally the hidden output of a head is
\[
\tilde{h}^{(h)}_t = \frac{c^{(h)}_t}{n^{(h)}_t}, \qquad
h^{(h)}_t = o^{(h)}_t\, \tilde{h}^{(h)}_t .
\]
The full hidden vector is re‑assembled by concatenating all \(h^{(h)}_t\).

In short, a head is a **self‑contained sLSTM cell**: it has its own gate parameters (\(\mathbf{w}_{i},r_i,b_i,\dots\)), its own normaliser state, and consequently its own stabiliser state (the \(m_t\) variable used to avoid overflow). There is no shared parameter across heads beyond the usual input‑projection matrix that maps \(\mathbf{x}_t\) into the common pre‑activation space; after that projection each head takes a disjoint slice of that projection.

---

### Why there is *no* memory mixing across heads

Memory mixing in sLSTM means letting the hidden state of one time step influence the *cell* (the scalar \(c_t\)) of another cell through the recurrent matrices
\(\mathbf{R}_{z}, \mathbf{R}_{i}, \mathbf{R}_{f}, \mathbf{R}_{o}\) (see Sec. 2.2).  
If we allowed a connection from head \(p\)’s hidden vector to head \(q\)’s cell, then the update rule for \(c^{(q)}_t\) would contain terms such as
\(r^{(q,p)}_{i}\,\mathbf{h}^{(p)}_{t-1}\).
Because the input and forget gates are exponential (or very large sigmoid) functions, such cross‑head couplings would make the *effective* mixing matrix highly non‑linear and could easily produce exploding or vanishing magnitudes when many heads are stacked.  

More concretely, two design objectives motivated the restriction:

1. **Stability of exponential gates** – The paper stabilises each gate with a per‑head scalar \(m_t^{(h)}\) (Eq. 5). This stabiliser only works when it can track the maximum log‑gate value *inside* one head; mixing values from other heads would break this guarantee because the maximum could shift arbitrarily across heads at each time step.

2. **Interpretability and parallelisation** – By keeping heads independent, the recurrence for each head can be expressed as an independent scan operation over time. Modern GPU libraries (e.g., `torch.scan`, CUDA kernels) can therefore process all heads simultaneously without needing a dense matrix–matrix multiplication across heads at every step. If cross‑head mixing were allowed we would have to assemble a full \(d\times d\) recurrent matrix each step, destroying the linear‑time‑and‑constant‑memory advantage that sLSTM enjoys over Transformers.

Thus prohibiting cross‑head mixing preserves **the original design goal of sLSTM: memory mixing *within* a head (via recurrent matrices) but not *across* heads**, which gives us richer expressive power than a plain scalar LSTM while still keeping the recurrence tractable and numerically stable.

---

### How this differs from mLSTM

In mLSTM the cell state is a full matrix \(\mathbf C_t\in\mathbb R^{d\times d}\) and there is **no hidden‑to‑hidden recurrent connection** at all—the update is purely additive,
\( \mathbf C_t = f_t\, \mathbf C_{t-1}+ i_t\, \mathbf v_t \mathbf k_t^\top \).
Because there is no recurrence on the hidden side, adding multiple heads simply means splitting the query/key/value projections into independent slices; there is nothing to mix anyway, so “multiple heads ≡ multiple cells” in mLSTM.

---

### Take‑away

A *head* in sLSTM is essentially an independent copy of an sLSTM cell with its own gate weights, normaliser state, and stabiliser. Memory mixing (the recurrent weight matrices) operates only inside each copy; prohibiting mixing across copies guarantees numerical stability of exponential gates and lets us implement all heads as parallel scans, preserving the linear‑in‑time advantage that makes sLSTM competitive with modern sequence models. In mLSTM such a partitioning collapses to “multiple cells”, because the matrix memory removes hidden-to-hidden connections altogether.

### Can you clarify the relationship between the covariance update rule and Fast Weight Programmers?
Question:
In Section 2.3 it is mentioned that the matrix update \(\mathbf{C}_t = \mathbf{C}_{t-1} + \mathbf{v}_t \mathbf{k}_t^\top\) is equivalent to Fast Weight Programmers (FWP). How does the addition of decay/learning rates via forget and input gates map onto the classic FWP formulation? Are there any subtle differences in training dynamics?
Answer:
The update that appears in the mLSTM cell  

$$
\mathbf C_{t}=f_{t}\,\mathbf C_{t-1}+i_{t}\,\mathbf v_{t}\,\mathbf k_{t}^{\top}
\tag{1}
$$

is exactly the “fast‑weight” rule that was proposed in the original Fast‑Weight Programmer (FWP) papers \citep{Schmidhuber:92ncfastweights,Schlag:21}.  
In a classic FWP the fast‑weight matrix $\mathbf W^{(f)}$ is modified at every time step by an additive outer‑product of a *key* (or “parameter”) vector and a *value* (or “activation”) vector:

$$
\mathbf W^{(f)}_{t}= \underbrace{(1-\eta)}_{\text{decay}}\mathbf W^{(f)}_{t-1}+ \underbrace{\lambda}_{\text{learning‑rate}}\;\mathbf v_{t}\,\mathbf k_{t}^{\top}.
\tag{2}
$$

If we identify  

* the **forget gate** $f_{t}$ with the factor $(1-\eta)$, i.e. it determines how much of the previous fast‑weight matrix is retained, and  
* the **input gate** $i_{t}$ with the effective learning‑rate $\lambda$,

then (1) is precisely (2) with the additional twist that both $f_{t}$ and $i_{t}$ are *dynamic*: they are computed from the current input $\mathbf x_t$ (and optionally from the previous hidden state) via a sigmoidal or exponential activation.  This makes the decay and learning‑rate **data‑dependent**, a capability that ordinary FWP formulations did not have.

### How the gates map onto FWP components

| FWP component | mLSTM gate | Role in (1) |
|---------------|------------|--------------|
| Decay factor  | $f_{t}\in[0,1]$ (sigmoid or $\exp$) | Multiplies $\mathbf C_{t-1}$; when $f_t\approx 0$ the old memory is forgotten, when $f_t\approx 1$ it is retained. |
| Learning rate | $i_{t}>0$ (exponential activation) | Scales the outer product $\mathbf v_t\mathbf k_t^{\!\top}$; larger $i_t$ writes stronger memories. |
| Fast weight matrix | $\mathbf C_t$ | Stores accumulated key–value associations; retrieved by multiplying with a query vector $\mathbf q_t$. |

Because both gates are produced by **exponential activations**, they can take values far larger than one.  The paper therefore introduces a stabiliser state (eq. (5)) that normalises the gates without changing gradients, ensuring numerical stability while preserving the exact FWP dynamics.

### Subtle differences in training dynamics

1. **State‑dependent decay** – In a vanilla FWP the decay constant is usually fixed, e.g. $(1-\eta)=0.99$.  In mLSTM, $f_t$ can increase or decrease sharply depending on $\mathbf x_t$.  Consequently, the model can *selectively* erase specific parts of its fast‑weight memory while preserving others, which gives it a richer forgetting behaviour than static decay.

2. **Gate‑controlled write strength** – The input gate $i_t$ acts like an adaptive learning rate.  When a particular key–value pair is highly relevant (for example a named entity that must be recalled later), the network can boost $i_t$ to write a strong outer product; for irrelevant inputs it can shrink $i_t$, preventing noise from polluting $\mathbf C_t$.  This dynamic scaling is absent from classic FWP where $\lambda$ is usually constant.

3. **Normalization via the normaliser state** – The normaliser $\mathbf n_t = f_t\,\mathbf n_{t-1}+ i_t\,\mathbf k_t$ accumulates a weighted sum of keys and appears in the denominator of the retrieved hidden state,
   $$
   \tilde{\mathbf h}_t = \frac{\mathbf C_t\,\mathbf q_t}{\max(|\mathbf n_t^{\!\top}\!\mathbf q_t|,\,1)}.
   $$
   This extra division protects against exploding inner products when many keys have been written; classic FWP does not include such a normaliser because it typically assumes bounded keys/values or relies on explicit clipping.

4. **Stabilisation trick** – The paper’s stabiliser state $m_t = \max(\log f_t+m_{t-1},\,\log i_t)$ rescales $f_t,i_t$ so that their product never exceeds numerical limits.  From a training‑dynamics perspective this means that gradients flowing through the gates are unaffected (the rescaling cancels out), but overflow is avoided—something normally omitted in earlier FWP work.

5. **Parallelisable recurrence** – Because there is no hidden‑to‑hidden recurrent weight matrix in mLSTM, the whole recurrence can be rewritten as a scan that runs in parallel across time steps (see Appendix A).  Classical FWPs are also often described as "online" updates, but they are usually implemented sequentially; the paper points out that with exponential gating and static matrix memory, one can compute all updates simultaneously on a GPU, achieving transformer‑like throughput.

### Bottom line

The covariance update rule of mLSTM is *identical* to a Fast Weight Programmer if we interpret

* **forget gate** ⇔ **decay factor**, and  
* **input gate** ⇔ **learning‑rate**.

The novelty introduced by xLSTM lies in making those factors *learnable functions of the current input*, adding a normaliser to keep retrieval stable, and providing a numerically safe re‑parameterisation of exponential gates.  These modifications do not change the underlying fast‑weight mathematics but give the model far more expressive control over how memories are written and erased, which in turn leads to smoother training dynamics and better performance on tasks that require selective storage and long‑range recall.

### Why does mLSTM’s retrieval denominator use \(\max\{|\mathbf{n}_t^\top \mathbf{q}_t|, 1\}\)?
Question:
The hidden state computation in Eq. 7 divides by the maximum of the absolute dot product between normalizer and query and 1. What is the intuition behind this clipping, and how sensitive is performance to the chosen threshold (default 1.0)?
Answer:
The denominator in the mLSTM hidden‑state equation  

\[
\tilde{\mathbf h}_{t}= \frac{\mathbf C_{t}\,\mathbf q_{t}}
{\displaystyle \max\!\Bigl\{\,\bigl|\mathbf n_{t}^{\top}\mathbf q_{t}\bigr|,\;1\Bigr\}}
\]

plays the same rôle as the normaliser that appears in the sLSTM.  
Recall that the **normalizer state**  

\[
\mathbf n_{t}=f_{t}\,\mathbf n_{t-1}+i_{t}\,\mathbf k_{t}
\]

stores a weighted sum of all keys that have been written to the matrix memory, each key being multiplied by the input gate at its time of insertion and by every subsequent forget gate.  When a query \(\mathbf q_{t}\) arrives we would like to retrieve the stored value as a *scaled* linear combination of the keys:

\[
\mathbf C_{t}\,\mathbf q_{t}= 
\sum_{\tau\le t} i_{\tau}\, \bigl(\prod_{\tau< s \le t}f_{s}\bigr)\,
\mathbf v_{\tau}\,(\mathbf k_{\tau}^{\top}\mathbf q_{t}) .
\]

If the dot product \(\mathbf n_{t}^{\top}\mathbf q_{t}= 
\sum_{\tau\le t} i_{\tau}
\bigl(\prod_{\tau< s \le t}f_{s}\bigr)\,
(\mathbf k_{\tau}^{\top}\mathbf q_{t})\) is *large*, the retrieval already carries the appropriate overall magnitude and no further scaling is needed.  
If, however, the query is (almost) orthogonal to the accumulated key direction, the raw dot‑product can become very small – even zero – which would make \(\tilde{\mathbf h}_{t}\) explode (division by a tiny number) or become undefined.  

The authors therefore **clip** the denominator at a constant value (default 1.0):

* **Stability.**  The clipping guarantees a lower bound on the scaling factor, preventing division by numbers whose magnitude is below 1. This avoids numerical overflow or extreme amplification of noise when \(|\mathbf n_{t}^{\top}\mathbf q_{t}|\) is close to zero.
* **Normalization analogue.**  In the scalar sLSTM the hidden state is simply \(c_t / n_t\).  For matrices we cannot divide element‑wise, so we use a single scalar normaliser that approximates “how much total key mass has been written”.  Taking the absolute value preserves sign‑invariance (the magnitude matters for scaling), and clipping at 1 implements a soft “max(·,1)” that leaves large normalisers unchanged while protecting against tiny ones.
* **Consistency with prior work.**  The same trick was adopted in Retention [Sun et al., 2023] and other fast‑weight models; it has been shown empirically to keep training stable without harming expressive power.

### Sensitivity to the threshold  

The paper reports using the default threshold \(1.0\).  Because the denominator only intervenes when \(|\mathbf n_{t}^{\top}\mathbf q_{t}|<1\), any threshold modestly larger than 1 merely enlarges the region where clipping occurs and slightly reduces the amplitude of \(\tilde{\mathbf h}_t\).  Empirically (see Appendix C.2), varying the threshold between 0.5 and 2 changes validation perplexity by less than 0.05 ppl across model sizes, indicating that performance is **not highly sensitive** to this hyper‑parameter.  The choice of 1.0 is convenient—it corresponds exactly to “no scaling when the normaliser already has unit magnitude”, which matches the intuition from the scalar case.

In summary, the max‑clipping serves as a safeguard against division by near‑zero inner products while leaving genuine large normalisers untouched; its value of 1.0 is a reasonable default that does not materially affect model performance.

### How does the pre‑up‑projection vs post‑up‑projection block affect sLSTM vs mLSTM performance?
Question:
The authors use post up‑projection blocks for sLSTM and pre up‑projection blocks for mLSTM (Section 2.4). What exactly are these two designs, and why is one more suitable for scalar memory while the other benefits matrix memory?
Answer:
In the xLSTM paper the two kinds of residual blocks are introduced only to decide **where** the high‑dimensional “up‑projection’’ lives relative to the recurrent core (the sLSTM or the mLSTM).  

A *post up‑projection* block works exactly like the usual Transformer block: the recurrent core first processes the input in its native dimensionality (the hidden size $d$), then a linear layer expands the result to a higher‑dimensional space $D\;(D\gg d)$, a non‑linearity is applied, and finally a second linear layer projects back to $d$.  Symbolically  

$$
h_{t}^{\;(post)} \;=\; \Pi_{d\leftarrow D}\bigl(\sigma(\Pi_{D\leftarrow d}( \text{core}(h_{t-1},x_{t}) ))\bigr) ,
$$

where $\Pi_{D\leftarrow d}$ is the *up‑projection* and $\Pi_{d\leftarrow D}$ the *down‑projection*.  Because the up‑projection comes **after** the recurrent computation, the recurrent unit only ever sees vectors of size $d$.  This is exactly what the authors call “post up‑projection (like Transformers)”.

A *pre up‑projection* block swaps the order: the input is first lifted to the high‑dimensional space, then the recurrent core (now working on vectors of size $D$) performs its update, and finally a down‑projection brings the result back to $d$:

$$
h_{t}^{\;(pre)} \;=\; \Pi_{d\leftarrow D}\bigl(\text{core}\bigl(\Pi_{D\leftarrow d}(h_{t-1}),\,\Pi_{D\leftarrow d}(x_{t})\bigr)\bigr) .
$$

Here the core operates on a **larger hidden dimension**.  The authors point out that this is similar to what State‑Space Models (SSMs) do: they first embed the sequence into a high‑dimensional state space and then evolve that state linearly.

---

### Why sLSTM uses post up‑projection

The scalar LSTM (sLSTM) retains **memory mixing** – i.e. hidden‑to‑hidden recurrent matrices $\mathbf{R}_{z}, \mathbf{R}_{i}, \mathbf{R}_{f}, \mathbf{R}_{o}$ that connect different cells (see Section 2.3).  These matrices are dense in size $d\times d$ and must be multiplied by the hidden vector at every time step.  If we were to increase $d$ dramatically by moving the up‑projection **before** the sLSTM, those mixing matrices would become huge ($D\times D$) and would dominate both memory consumption and compute cost.  Moreover, memory mixing makes sLSTM inherently *sequential*: each step depends on the exact hidden vector produced in the previous step, so there is no opportunity for parallel scan tricks.  Keeping the sLSTM in its native low dimensionality therefore limits the cost of mixing while still allowing it to benefit from a high‑dimensional non‑linear summary performed **after** its recurrence.  In other words, post up‑projection gives sLSTM a cheap way to embed its scalar memory into a richer representation without blowing up the size of its internal weight matrices.

### Why mLSTM uses pre up‑projection

The matrix LSTM (mLSTM) replaces scalar cells by a full matrix memory $\mathbf{C}_{t}\in\mathbb{R}^{d\times d}$ and, crucially, **removes memory mixing** altogether (Section 2.4).  The only recurrence is an elementwise forget gate applied to $\mathbf{C}_{t-1}$ and an outer‑product update $\mathbf{v}_{t}\mathbf{k}_{t}^{\top}$.  Because there are no dense hidden‑to‑hidden weight matrices, enlarging the hidden dimension does not increase any quadratic parameter count—the only extra cost is larger matrix multiplications for reading ($\mathbf{C}_{t}\mathbf{q}_{t}$) and updating ($\mathbf{v}_{t}\mathbf{k}_{t}^{\top}$).  These operations can be expressed as standard batched GEMM kernels and are highly parallelizable on GPUs.  

Placing an up‑projection **before** the mLSTM therefore lets us store more information in a larger matrix memory without any additional learnable parameters.  The “high‑dimensional” space directly becomes the dimension of $\mathbf{C}_{t}$; after reading we compress back to $d$ for downstream layers.  This design matches what State Space Models do—project into a large linear state space, evolve it with cheap linear dynamics, then project back—hence why the paper calls it “pre up‑projection (like SSMs)”.

---

### Summary of intuition

* **Post up‑projection → sLSTM**  
  *Keeps hidden size small → cheap mixing matrices.*  
  *Provides a high‑dimensional nonlinearity after recurrence.*  

* **Pre up‑projection → mLSTM**  
  *No mixing matrices, so we can afford a large hidden state.*  
  *Matrix memory benefits directly from a larger dimensionality; all operations remain parallelizable.*

Thus each design matches the structural properties of its underlying LSTM variant: sLSTM needs a low-dimensional recurrent core because it mixes hidden states across cells, whereas mLSTM’s parameter‑free matrix memory can safely be expanded before recurrence, gaining capacity without additional parameter cost.

### In the ablation study, how much does exponential gating contribute versus matrix memory?
Question:
Table 2 (top) shows stepwise morphing from vanilla LSTM to xLSTM. However, I’m not sure whether the performance gain is mainly due to exponential gating, matrix memory, or their interaction. Could someone break down the individual contribution numbers or suggest an experiment to isolate each factor?
Answer:
In the paper the authors quantify the effect of the two new ingredients — exponential gating and the matrix‑valued memory — by a step‑wise “morphing’’ ablation that starts from a vanilla LSTM and successively adds the architectural changes that lead to a full xLSTM (Table 3, top part).  
The most informative rows of that table are reproduced here (the numbers are validation‑set perplexities on the $15\,$B‑token SlimPajama training run):

| Model (15 B tokens) | Perplexity |
|---------------------|------------|
| Baseline LSTM (inside a pre‑LayerNorm residual block) | **13.9** |
| LSTM + post up‑projection block | **13.2** |
| LSTM + post up‑projection + exponential gating (sLSTM) | **12.5** |
| LSTM + post up‑projection + matrix memory (mLSTM) | **12.3** |
| Full xLSTM (post up‑projection + exponential gating + matrix memory) | **11.8** |

From these figures we can read off the *individual* contribution of each component:

* **Exponential gating** (the jump from $13.2 \rightarrow 12.5$) reduces perplexity by **0.7 points**, i.e. roughly a **$5\%$** relative improvement over the post‑up‑projection baseline.  
* **Matrix memory** (the jump from $13.2 \rightarrow 12.3$) reduces perplexity by **0.9 points**, i.e. about a **$7\%$** relative gain.  
* Adding both together yields an additional $0.5$‑point drop ($12.3 \rightarrow 11.8$), showing a small synergistic effect but indicating that most of the benefit comes from the two mechanisms independently rather than from a strong interaction.

Thus, in the $48$‑block xLSTM configuration used for the $15\,$B‑token experiment, exponential gating contributes roughly *half* of the total gain while matrix memory contributes slightly more than half; their interaction is modest.

### How to isolate the factors experimentally  

If you want to verify these numbers on your own dataset or with a different model size, you can run three controlled experiments that match everything except the component you are testing:

1. **Baseline recurrent block** – a vanilla LSTM placed inside the same pre‑LayerNorm residual backbone and using the same post up‑projection block as in the paper.  
2. **Only exponential gating** – replace the sigmoid gates of the baseline with the exponential formulation described in Eq.~$(4)$ and keep a *scalar* cell state (i.e., use sLSTM). All other hyper‑parameters, including the normalizer state and stabilizer, stay identical to the baseline.  
3. **Only matrix memory** – keep sigmoid gates but switch the scalar cell to the matrix formulation of Eq.~$(7)$ (mLSTM). The rest of the pipeline—including query/key/value projections and normalizer—remains as in the baseline.

Make sure to keep training budget, optimizer settings, learning rate schedule and batch size exactly the same across runs; otherwise differences could be attributed to training dynamics rather than architecture changes. Reporting validation perplexity after convergence will give you numbers directly comparable to those in Table 3.

If you also want to assess any interaction effect, train a fourth model that incorporates *both* exponential gating and matrix memory (the full xLSTM). The difference between this model’s perplexity and the average of the two “single‑component’’ models approximates the interaction term.

### Take‑away  

The ablation in the paper makes it clear that exponential gating and matrix memory are both essential and roughly equally important for closing the gap between traditional LSTMs and modern large‑scale language models. Each alone gives a $5\text{–}7\%$ relative perplexity reduction; together they yield an overall $\approx15\%$ gain over a well‑trained LSTM baseline, with only a modest extra boost from their interaction. This quantitative split should help you decide which extension is worthwhile for a given computational budget or research focus.

### What are the theoretical limitations of sLSTM’s non‑parallelizability?
Question:
The paper notes that sLSTM cannot be parallelized because of memory mixing, yet they provide a fast CUDA kernel that is only twice slower than mLSTM. How does this kernel achieve parallelism across time steps (e.g., using scan operations), and what are the fundamental algorithmic barriers that prevent full parallelization?
Answer:
**Answer**

The sLSTM variant introduced in *xLSTM: Extended Long Short‑Term Memory* inherits the classic recurrent connection “hidden → hidden” that couples every time step to the next one.  
Because the cell update

$$
c_t = f_t\,c_{t-1}+ i_t\,z_t ,\qquad 
n_t = f_t\,n_{t-1}+ i_t
$$

and the gate pre‑activations (e.g. \(\tilde i_t = w_i^\top x_t + r_i h_{t-1}+b_i\)) contain a term proportional to \(h_{t-1}\), the forward computation of \(h_t\) cannot be expressed as a function of the current input alone; it needs the *exact* hidden state produced at the previous step.  This “memory mixing” creates a data‑dependency chain of length equal to the sequence length, which is why a naïve implementation must run strictly sequentially.

### How the fast CUDA kernel works

Even though the recurrence cannot be broken, one can still hide much of the latency by exploiting two ideas that are standard in high‑performance RNN implementations:

1. **Kernel‑level fusion and register tiling** – All gate pre‑activations, the exponential (or sigmoid) non‑linearities, and the two linear recurrences for \(c_t\) and \(n_t\) are computed inside a single CUDA kernel.  The kernel loads a small “tile” of the input sequence (for example 64 timesteps) into registers, computes the gates for each step, and then updates the two scalars \((c, n)\) in register space.  Because registers reside on‑chip, each step of the recurrence costs only a few arithmetic operations without any global‑memory traffic.

2. **Explicit loop unrolling over a short window** – Within a tile the recurrence is executed in a tight loop; after each tile finishes, the final \((c,n)\) values are written back to global memory and become the initial state for the next tile.  This approach is exactly what “scan” (prefix‑sum) algorithms do, except that here we have **two coupled scans** (the cell state and its normalizer).  The dependence still exists, but it is confined to a tiny number of steps that fit entirely in registers, so the GPU can keep all warps busy while waiting for memory.

Because only two scalar values have to be carried across tiles, the amount of data that must be transferred between successive kernel launches is negligible.  The overall wall‑clock time therefore scales almost linearly with sequence length, and on modern GPUs the kernel reaches *$\approx 2\times$* the throughput of the fully parallelizable mLSTM (which can be expressed as a single matrix scan without any hidden‑to‑hidden link).

### Fundamental algorithmic barriers

The speedup described above is essentially as good as one can get without breaking the recurrence:

* **Data dependency** – The hidden state \(h_{t-1}\) appears inside every gate’s affine transformation.  Any attempt to compute \(h_t\) before \(h_{t-1}\) would produce mathematically incorrect results.  This is unlike mLSTM where all gates depend only on the current input (\(x_t\)) and on a *matrix* memory that is updated additively; there is no hidden‑to‑hidden term, so one can rewrite the whole update as a *scan* over independent contributions.

* **Non‑linear coupling of two recurrences** – sLSTM maintains both a cell state \(c_t\) and a normalizer state \(n_t\).  They are updated with identical forget / input gates, so they cannot be eliminated or merged into a single linear recurrence.  The double‑scan eliminates neither dependency nor arithmetic complexity; it only lets us compute both scans together while keeping everything in fast on‑chip storage.

* **Memory mixing across multiple heads/cells** – When sLSTM is extended with several cells or heads, each head has its own hidden‑to‑hidden weight matrices \(\mathbf R_{\*}\).  Even if we could parallelise within a single head, inter‑head mixing forces an additional sequential pass because each head’s output becomes part of the next head’s input at every time step.

Because these ingredients are intrinsic to sLSTM’s design (they give sLSTM its ability to “revise storage decisions” via exponential gating), they cannot be removed without changing the model’s expressive power.  Consequently, full parallelisation—i.e. computing all timesteps simultaneously as in Transformers—is impossible for sLSTM; we are limited to *intra‑tile* parallelism implemented by tightly fused CUDA kernels.

### Bottom line

The authors’ CUDA implementation attains near‑optimal performance for an inherently sequential model by:

* fusing all per‑step operations into one register‑level kernel,
* processing short tiles of timesteps in an unrolled loop (a scan over a very small window), and
* moving only two scalar states between tiles.

These tricks reduce memory traffic and hide latency but cannot eliminate the fundamental hidden‑to‑hidden dependency that defines sLSTM.  Hence sLSTM will always remain at least *O(T)* in wall‑clock time with respect to sequence length, whereas mLSTM—by discarding memory mixing—can be written as a true parallel scan and achieves full GPU parallelism.

### How does xLSTM compare to Retention or RWKV on formal language tasks requiring state tracking?
Question:
Figure 3 shows xLSTM solving parity-like tasks while Transformers/SSMs fail. The caption mentions "state tracking" as a key advantage. Could someone elaborate on why exponential gating plus memory mixing gives xLSTM an edge over Retention or RWKV, which also have gating mechanisms?
Answer:
**Answer**

The parity‑like experiments in Figure 3 are a canonical “state‑tracking’’ benchmark: the network has to remember a binary counter that is toggled whenever the input symbol `1` appears, and it must output the current parity at the end of the sequence.  
A model can solve this task only if two conditions are satisfied

1. **the hidden state can be revised arbitrarily** – when a new `1` arrives the previously stored parity must be *overwritten* (or “flipped’’) without being diluted by older contributions, and  
2. **different hidden units can exchange information** – the update that flips the parity may have to use a combination of several scalar cells (e.g. one cell storing the sign, another storing a mask).

Standard LSTMs fulfil (1) only weakly because their forget gate is bounded by a sigmoid, so the old cell value can be attenuated but never *removed* in one step.  Consequently an early `1` leaves a tiny residue that accumulates over long sequences and destroys perfect parity tracking.  

Both **Retention** [Sun et al., 2023] and **RWKV** [Peng et al., 2023] adopt the same “fast‑weight’’ or “linear‑RNN’’ formulation as xLSTM’s mLSTM: they maintain a matrix (or vector) memory that is updated by an outer‑product of a key and a value, and they use an exponential or sigmoid decay for the forget term.  However, these models **do not contain any hidden‑to‑hidden recurrent connections** (the *memory mixing* of Eq.~(1) in the paper).  Their recurrence is entirely described by

\[
\mathbf{C}_{t}=f_t\,\mathbf{C}_{t-1}+i_t\,\mathbf{v}_t\mathbf{k}_t^{\!\top},
\]

where every gate depends only on the current input (and possibly a static bias).  Because of this, each *cell* evolves independently of the other cells; there is no way for one cell’s state to influence another cell’s gate computation at the next time step.

### Why exponential gating + memory mixing matters

1. **Exponential gating gives unbounded overwriting.**  
   In sLSTM (the scalar variant used for parity) the input gate is defined as  

   \[
   i_t = \exp(\tilde i_t),\qquad 
   f_t = \exp(\tilde f_t)\ \text{or}\ \sigma(\tilde f_t),
   \]

   with a stabiliser that rescales both gates so that their product never overflows (Eqs.~(2)–(3)).  Because $\exp(\cdot)$ can grow arbitrarily large, a single step can set $i_t\gg f_t$ and therefore *completely replace* the old cell value:

   \[
   c_t = f_t\,c_{t-1}+i_t\,z_t
        \approx i_t\,z_t \quad\text{if }i_t\gg f_t.
   \]

   This is precisely what is needed for parity: when a `1` arrives we want $c_t = -c_{t-1}$.  The exponential gate can generate a negative sign (through $z_t$) and simultaneously make $i_t$ dominate $f_t$, erasing any trace of the previous count.

2. **Memory mixing lets cells cooperate.**  
   The sLSTM extends the classic LSTM with *hidden‑to‑hidden* recurrent matrices $\mathbf R_{\!*}$ that connect all hidden units at time $t-1$ to every gate at time $t$.  In practice this looks like

   \[
   \tilde i_t = \mathbf w_i^\top x_t + \mathbf R_i h_{t-1} + b_i,
   \]

   with analogous terms for $f_t$, $o_t$, $z_t$.  When several scalar cells are present, the term $\mathbf R_i h_{t-1}$ mixes their hidden activations before computing each gate.  Consequently a flip that is detected on *any* cell can instantly drive the input gate of another cell, allowing a compact encoding of “parity’’ as a **single joint linear combination** of many cells rather than requiring each cell to store its own copy of the counter.

   Retention and RWKV lack this mixing: their update rule treats every key–value pair independently, so even if one pair learns to flip a sign it cannot directly influence another pair’s gate.  The result is an effective *feed‑forward* memory that can store many distinct key–value associations (hence excellent performance on associative‑recall tasks) but struggles with tasks where the *relationship* between successive inputs matters.

3. **Normalization stabilises long‑range accumulation.**  
   Both sLSTM and mLSTM introduce an auxiliary normalizer $n_t$ that tracks the cumulative product of forget gates (Eqs.~(4)–(5)).  The hidden state is computed as  

   \[
   h_t = o_t\,\frac{c_t}{n_t},
   \]

   so any exponential growth in $i_t$ or $f_t$ is automatically re‑scaled by $n_t$.  This prevents gradients from exploding while preserving the ability to *exactly* overwrite old content when needed—a balance that pure sigmoid gating cannot achieve.

### Connecting back to Figure 3

In Figure 3 the parity task error curves show:

* **Transformers/SSMs:** error stays near random because their self‑attention or linear kernels lack any mechanism to overwrite earlier context; each token contributes additively with a fixed decay, so after many steps the parity signal is drowned in noise.
* **Retention / RWKV:** error improves slightly thanks to exponential forgetting, but without memory mixing they cannot propagate a flip across cells; consequently they converge to a sub‑perfect accuracy (~0.7–0.8).
* **xLSTM (sLSTM):** error drops to zero even for lengths far beyond training because each new `1` triggers an exponential input gate that fully replaces the stored scalar while hidden‑to‑hidden mixing distributes this decision across all cells, guaranteeing exact state reversal.

Thus, *the edge comes from two synergistic ingredients*:  

1. **Exponential gates** give unlimited capacity to erase or dominate previous state in one timestep;  
2. **Memory mixing** (the hidden‐to‐hidden recurrent matrices) allows those powerful updates to be coordinated across multiple cells.

When both are present—as in sLSTM—the model attains true “state tracking’’ ability that matches formal language theory results stating that RNNs with unrestricted hidden‑to‑hidden connections are strictly more expressive than linear SSMs or Transformers on regular languages such as parity.  Retention and RWKV inherit many benefits of fast‑weight memories but remain limited to *purely associative* storage; they excel at recall tasks but cannot reliably perform stateful transformations required by formal language benchmarks.

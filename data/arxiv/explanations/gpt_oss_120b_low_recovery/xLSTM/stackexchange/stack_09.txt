\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### How does the pre‑up‑projection vs post‑up‑projection block affect sLSTM vs mLSTM performance?
Question:
The authors use post up‑projection blocks for sLSTM and pre up‑projection blocks for mLSTM (Section 2.4). What exactly are these two designs, and why is one more suitable for scalar memory while the other benefits matrix memory?
Answer:
In the xLSTM paper the two kinds of residual blocks are introduced only to decide **where** the high‑dimensional “up‑projection’’ lives relative to the recurrent core (the sLSTM or the mLSTM).  

A *post up‑projection* block works exactly like the usual Transformer block: the recurrent core first processes the input in its native dimensionality (the hidden size $d$), then a linear layer expands the result to a higher‑dimensional space $D\;(D\gg d)$, a non‑linearity is applied, and finally a second linear layer projects back to $d$.  Symbolically  

$$
h_{t}^{\;(post)} \;=\; \Pi_{d\leftarrow D}\bigl(\sigma(\Pi_{D\leftarrow d}( \text{core}(h_{t-1},x_{t}) ))\bigr) ,
$$

where $\Pi_{D\leftarrow d}$ is the *up‑projection* and $\Pi_{d\leftarrow D}$ the *down‑projection*.  Because the up‑projection comes **after** the recurrent computation, the recurrent unit only ever sees vectors of size $d$.  This is exactly what the authors call “post up‑projection (like Transformers)”.

A *pre up‑projection* block swaps the order: the input is first lifted to the high‑dimensional space, then the recurrent core (now working on vectors of size $D$) performs its update, and finally a down‑projection brings the result back to $d$:

$$
h_{t}^{\;(pre)} \;=\; \Pi_{d\leftarrow D}\bigl(\text{core}\bigl(\Pi_{D\leftarrow d}(h_{t-1}),\,\Pi_{D\leftarrow d}(x_{t})\bigr)\bigr) .
$$

Here the core operates on a **larger hidden dimension**.  The authors point out that this is similar to what State‑Space Models (SSMs) do: they first embed the sequence into a high‑dimensional state space and then evolve that state linearly.

---

### Why sLSTM uses post up‑projection

The scalar LSTM (sLSTM) retains **memory mixing** – i.e. hidden‑to‑hidden recurrent matrices $\mathbf{R}_{z}, \mathbf{R}_{i}, \mathbf{R}_{f}, \mathbf{R}_{o}$ that connect different cells (see Section 2.3).  These matrices are dense in size $d\times d$ and must be multiplied by the hidden vector at every time step.  If we were to increase $d$ dramatically by moving the up‑projection **before** the sLSTM, those mixing matrices would become huge ($D\times D$) and would dominate both memory consumption and compute cost.  Moreover, memory mixing makes sLSTM inherently *sequential*: each step depends on the exact hidden vector produced in the previous step, so there is no opportunity for parallel scan tricks.  Keeping the sLSTM in its native low dimensionality therefore limits the cost of mixing while still allowing it to benefit from a high‑dimensional non‑linear summary performed **after** its recurrence.  In other words, post up‑projection gives sLSTM a cheap way to embed its scalar memory into a richer representation without blowing up the size of its internal weight matrices.

### Why mLSTM uses pre up‑projection

The matrix LSTM (mLSTM) replaces scalar cells by a full matrix memory $\mathbf{C}_{t}\in\mathbb{R}^{d\times d}$ and, crucially, **removes memory mixing** altogether (Section 2.4).  The only recurrence is an elementwise forget gate applied to $\mathbf{C}_{t-1}$ and an outer‑product update $\mathbf{v}_{t}\mathbf{k}_{t}^{\top}$.  Because there are no dense hidden‑to‑hidden weight matrices, enlarging the hidden dimension does not increase any quadratic parameter count—the only extra cost is larger matrix multiplications for reading ($\mathbf{C}_{t}\mathbf{q}_{t}$) and updating ($\mathbf{v}_{t}\mathbf{k}_{t}^{\top}$).  These operations can be expressed as standard batched GEMM kernels and are highly parallelizable on GPUs.  

Placing an up‑projection **before** the mLSTM therefore lets us store more information in a larger matrix memory without any additional learnable parameters.  The “high‑dimensional” space directly becomes the dimension of $\mathbf{C}_{t}$; after reading we compress back to $d$ for downstream layers.  This design matches what State Space Models do—project into a large linear state space, evolve it with cheap linear dynamics, then project back—hence why the paper calls it “pre up‑projection (like SSMs)”.

---

### Summary of intuition

* **Post up‑projection → sLSTM**  
  *Keeps hidden size small → cheap mixing matrices.*  
  *Provides a high‑dimensional nonlinearity after recurrence.*  

* **Pre up‑projection → mLSTM**  
  *No mixing matrices, so we can afford a large hidden state.*  
  *Matrix memory benefits directly from a larger dimensionality; all operations remain parallelizable.*

Thus each design matches the structural properties of its underlying LSTM variant: sLSTM needs a low-dimensional recurrent core because it mixes hidden states across cells, whereas mLSTM’s parameter‑free matrix memory can safely be expanded before recurrence, gaining capacity without additional parameter cost.

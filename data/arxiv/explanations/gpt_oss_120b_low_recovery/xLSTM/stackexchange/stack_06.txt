\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### How are heads implemented in sLSTM and why are they not allowed to mix memories across heads?
Question:
The paper states that sLSTM can have multiple heads with memory mixing within each head but not across heads, whereas for mLSTM heads are equivalent to multiple cells. What is the exact architecture of a head (e.g., separate gate parameters, separate normalizer?), and what is the motivation for prohibiting cross‑head mixing?
Answer:
In the sLSTM the notion of a *head* is introduced exactly because the exponential‑gate formulation gives us a new way to mix the information that lives in the recurrent hidden‑to‑hidden connections.  
A head is **not** a separate “mini‑network” that runs in parallel with its own completely independent set of parameters; rather it is a *partition* of the full hidden vector into several sub‑vectors, each of which carries its own LSTM‑style gates and its own normaliser state.  

---

### What a head contains

For an sLSTM with \(H\) heads we first split the hidden state \(\mathbf{h}_{t-1}\in\mathbb{R}^{d}\) into
\[
\mathbf{h}_{t-1}= \big[\,\mathbf{h}^{(1)}_{t-1},\dots,\mathbf{h}^{(H)}_{t-1}\,\big],
\qquad
\mathbf{h}^{(h)}_{t-1}\in\mathbb{R}^{d_h},
\]
with \(\sum_{h=1}^{H}d_h = d\).  
For each head \(h\) we then compute **its own** input, forget and output pre‑activations
\[
\tilde{i}^{(h)}_t = \mathbf{w}^{\top}_{i^{(h)}}\mathbf{x}_t + r_{i^{(h)}}\,\mathbf{h}^{(h)}_{t-1} + b_{i^{(h)}},
\]
and similarly \(\tilde{f}^{(h)}_t, \tilde{o}^{(h)}_t, \tilde{z}^{(h)}_t\).  
Consequently each head owns its **own weight vectors** (or, if we use a matrix formulation, its own *slice* of the recurrent weight matrices) and **its own bias terms**. The exponential activation for the input gate and the optional exponential or sigmoid activation for the forget gate are applied separately per head, exactly as in Eq. (4) of the paper.

The normaliser state—recall that sLSTM keeps a running sum
\(n_t = f_t n_{t-1}+ i_t\)—is also maintained per head:
\[
n^{(h)}_t = f^{(h)}_t\, n^{(h)}_{t-1}+ i^{(h)}_t .
\]
Thus each head has an independent “normaliser” that records how much total mass has been accumulated by that head’s gates.

Finally the hidden output of a head is
\[
\tilde{h}^{(h)}_t = \frac{c^{(h)}_t}{n^{(h)}_t}, \qquad
h^{(h)}_t = o^{(h)}_t\, \tilde{h}^{(h)}_t .
\]
The full hidden vector is re‑assembled by concatenating all \(h^{(h)}_t\).

In short, a head is a **self‑contained sLSTM cell**: it has its own gate parameters (\(\mathbf{w}_{i},r_i,b_i,\dots\)), its own normaliser state, and consequently its own stabiliser state (the \(m_t\) variable used to avoid overflow). There is no shared parameter across heads beyond the usual input‑projection matrix that maps \(\mathbf{x}_t\) into the common pre‑activation space; after that projection each head takes a disjoint slice of that projection.

---

### Why there is *no* memory mixing across heads

Memory mixing in sLSTM means letting the hidden state of one time step influence the *cell* (the scalar \(c_t\)) of another cell through the recurrent matrices
\(\mathbf{R}_{z}, \mathbf{R}_{i}, \mathbf{R}_{f}, \mathbf{R}_{o}\) (see Sec. 2.2).  
If we allowed a connection from head \(p\)’s hidden vector to head \(q\)’s cell, then the update rule for \(c^{(q)}_t\) would contain terms such as
\(r^{(q,p)}_{i}\,\mathbf{h}^{(p)}_{t-1}\).
Because the input and forget gates are exponential (or very large sigmoid) functions, such cross‑head couplings would make the *effective* mixing matrix highly non‑linear and could easily produce exploding or vanishing magnitudes when many heads are stacked.  

More concretely, two design objectives motivated the restriction:

1. **Stability of exponential gates** – The paper stabilises each gate with a per‑head scalar \(m_t^{(h)}\) (Eq. 5). This stabiliser only works when it can track the maximum log‑gate value *inside* one head; mixing values from other heads would break this guarantee because the maximum could shift arbitrarily across heads at each time step.

2. **Interpretability and parallelisation** – By keeping heads independent, the recurrence for each head can be expressed as an independent scan operation over time. Modern GPU libraries (e.g., `torch.scan`, CUDA kernels) can therefore process all heads simultaneously without needing a dense matrix–matrix multiplication across heads at every step. If cross‑head mixing were allowed we would have to assemble a full \(d\times d\) recurrent matrix each step, destroying the linear‑time‑and‑constant‑memory advantage that sLSTM enjoys over Transformers.

Thus prohibiting cross‑head mixing preserves **the original design goal of sLSTM: memory mixing *within* a head (via recurrent matrices) but not *across* heads**, which gives us richer expressive power than a plain scalar LSTM while still keeping the recurrence tractable and numerically stable.

---

### How this differs from mLSTM

In mLSTM the cell state is a full matrix \(\mathbf C_t\in\mathbb R^{d\times d}\) and there is **no hidden‑to‑hidden recurrent connection** at all—the update is purely additive,
\( \mathbf C_t = f_t\, \mathbf C_{t-1}+ i_t\, \mathbf v_t \mathbf k_t^\top \).
Because there is no recurrence on the hidden side, adding multiple heads simply means splitting the query/key/value projections into independent slices; there is nothing to mix anyway, so “multiple heads ≡ multiple cells” in mLSTM.

---

### Take‑away

A *head* in sLSTM is essentially an independent copy of an sLSTM cell with its own gate weights, normaliser state, and stabiliser. Memory mixing (the recurrent weight matrices) operates only inside each copy; prohibiting mixing across copies guarantees numerical stability of exponential gates and lets us implement all heads as parallel scans, preserving the linear‑in‑time advantage that makes sLSTM competitive with modern sequence models. In mLSTM such a partitioning collapses to “multiple cells”, because the matrix memory removes hidden-to-hidden connections altogether.

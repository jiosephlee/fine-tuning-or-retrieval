\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### How does exponential gating enable revision of stored values in sLSTM?
Question:
The paper introduces exponential activation functions for the input and forget gates in sLSTM (Eq. 3). I understand that this allows gates to take values larger than 1, but I am unclear on how exactly this solves the "inability to revise storage decisions" problem demonstrated with the Nearest Neighbor Search task. Could someone walk through a concrete example of how an exponential input gate can overwrite a previously stored value while still preserving gradient flow?
Answer:
The inability of a classic LSTM to **revise a storage decision** comes from the fact that the input‑gate $i_t$ and the forget‑gate $f_t$ are bounded by the sigmoid function:
$$
0\le i_t ,f_t\le 1 .
$$
When a value $v$ has already been written into the cell,
$$
c_t = f_t\,c_{t-1}+i_t\,z_t ,
$$
any later attempt to replace it must first *forget* the old contribution by setting $f_t$ close to 0 and then *add* the new contribution with a large $i_t$. Because both factors are ≤ 1, the product
$f_t\,c_{t-1}$ can never become negative, and the magnitude of the new term $i_t\,z_t$ cannot exceed $|z_t|$.  
Consequently, once a large value has been stored, the LSTM can only *attenuate* it gradually; it cannot **overwrite** it in a single step. This is exactly what hurts performance on the Nearest‑Neighbour Search (NNS) task: when a more similar reference vector appears later in the sequence, the network cannot promptly replace the previously stored value.

### Exponential gates change the picture

In sLSTM the input gate is replaced by an **exponential activation**
$$
i_t = \exp(\tilde i_t),
\qquad
\tilde i_t = \mathbf w_i^{\top}\mathbf x_t + r_i h_{t-1}+b_i ,
$$
and (optionally) the forget gate may also be exponential.  
Because $\exp(\cdot)$ is unbounded above, $i_t$ can become arbitrarily large, while still being smooth and differentiable. The cell update remains
$$
c_t = f_t\,c_{t-1}+i_t\,z_t .
$$

Now imagine that at time step $t_1$ we store a value $v_1=z_{t_1}$ that is moderately relevant:
* choose a modest input‑gate magnitude, e.g. $i_{t_1}=1$;
* set the forget gate close to 1 so that the value persists: $f_{t_1}=1$.

Thus after $t_1$ we have
$c_{t_1}=v_1$.

Later, at time step $t_2>t_1$, a **more similar** reference vector arrives and we would like to replace $v_1$ by a new value $v_2=z_{t_2}$. With exponential gating we can do it in one step:

1. **Force forgetting:** set an exponential forget gate with a *tiny* value, for instance  
   $\tilde f_{t_2}=-10 \;\Rightarrow\; f_{t_2}= \exp(-10)\approx4.5\times10^{-5}$.  
   The term $f_{t_2}c_{t_1}$ becomes practically zero.
2. **Overwrite with a huge input gate:** choose $\tilde i_{t_2}=5$, giving  
   $i_{t_2}= \exp(5)\approx148$.  
   The new contribution is then $i_{t_2}z_{t_2}=148\,v_2$.

The new cell state becomes
$$
c_{t_2}= f_{t_2}c_{t_1}+i_{t_2}z_{t_2}
       \approx 0+148\,v_2 .
$$
Because we later divide by the *normaliser* $n_t$ (see Eq. (3)),
$$
n_t = f_t n_{t-1}+ i_t , \qquad 
h_t = o_t\, \frac{c_t}{n_t},
$$
the hidden state sees only the **relative** contribution of the stored value:
$$
h_{t_2}=o_{t_2}\,\frac{148\,v_2}{148+n_{\text{old}}}.
$$
If we make both gates large at the same time (large $i_{t_2}$, tiny $f_{t_2}$), the denominator is dominated by the fresh gate,
so $\frac{c_{t_2}}{n_{t_2}}\approx v_2$.  In effect, sLSTM has *overwritten* what was previously stored.

### Why gradients still flow

Both exponential functions are smooth:
$$
\frac{\partial i_t}{\partial \tilde i_t}= \exp(\tilde i_t)=i_t , \qquad
\frac{\partial f_t}{\partial \tilde f_t}=f_t .
$$
Even when a gate takes an extreme value (e.g. $i=148$), its derivative is simply that same magnitude, not zero. During back‑propagation through time, the gradient that reaches earlier steps is multiplied by these gate values exactly as in an ordinary LSTM; there is no “hard cut‑off”. Moreover, the paper introduces a **stabiliser state** (Eq. (4)) that rescales all gates by a common factor
$e^{-m_t}$, so that very large exponents do not cause overflow while preserving the exact product of gates. The rescaling leaves both forward activations and their Jacobians unchanged, guaranteeing that gradients remain well‑behaved.

### Putting it together on the NNS task

During NNS training, each input vector becomes either a *candidate* key or a *reference*. The sLSTM learns to:
* write a candidate’s value with a modest input gate when its similarity to the reference is low;
* when later encountering a more similar candidate, fire an enormous input gate and an almost‑zero forget gate,
  thereby wiping out earlier contributions and storing only the best match.

Because this overwriting happens in **one time step**, loss gradients can directly associate “more similar later → larger input gate” without having to rely on slow decay through many forget steps. Empirically (Figure 3 of the paper), sLSTM with exponential gating reduces mean‑squared error on NNS dramatically compared with vanilla LSTM.

In summary, exponential gating lifts the sigmoid ceiling, allowing a single time step to **erase** past information (tiny forget gate) and **inject** fresh information at any scale (large input gate). The normaliser guarantees that hidden outputs stay numerically stable, and stabilisation via $m_t$ preserves gradient flow. This mechanism solves precisely the “cannot revise storage decisions” problem illustrated by Nearest‑Neighbour Search.

\title{Stack Exchange of the Paper: "Parameter-Efficient Orthogonal Finetuning via Factorization"}

### Can BOFT represent any orthogonal matrix given enough depth and block size?
Question:
Theorem 1 states that by multiplying certain butterfly matrices and their transposes, BOFT can approximate any orthogonal matrix. I have several doubts:

* What is the exact construction of the sequence \(B_{d-1,1}(d), B^{\top}_{d-1,2}(d), …, B_{1,1}(d), B^{\top}_{1,2}(d)\)?
* Does this require depth proportional to \(d\) (i.e., linear depth), or can it be achieved with logarithmic depth as used in practice?
* In practice, BOFT uses a much smaller number of components; how far is this from universal approximation in terms of approximation error?

Answer:
**Answer**

Theorem 1 of the BOFT paper states that a product of butterfly matrices (and their transposes) can generate any orthogonal matrix in $\mathbb R^{d\times d}$.  
Below we unpack the construction that appears in the theorem, explain why the depth required is linear in the dimension, discuss what happens if we restrict ourselves to the $\log d$‑depth butterfly that is used in practice, and finally comment on how far a modest‑depth BOFT model is from a universal approximator.

---------------------------------------------------------------------

### 1.  What the product  $\mathbf B_{d-1,1}(d)\,\mathbf B^{\top}_{d-1,2}(d)\,\cdots\,\mathbf B_{1,1}(d)\,\mathbf B^{\top}_{1,2}(d)$ looks like

Recall that a *butterfly factor* $\mathbf B^{F}(k)$ (Eq. (1) of the paper) is a $k\times k$ matrix whose non‑zero entries lie in four diagonal blocks:
$$
\mathbf B^{F}(k)=
\begin{bmatrix}
\operatorname{diag}(\mathbf d_1) & \operatorname{diag}(\mathbf d_2)\\[2pt]
\operatorname{diag}(\mathbf d_3) & \operatorname{diag}(\mathbf d_4)
\end{bmatrix},
\qquad \mathbf d_i\in\mathbb R^{k/2}.
$$
A **butterfly component** $\tilde{\mathbf B}(d,k)$ is just a block‑diagonal matrix whose blocks are independent copies of $\mathbf B^{F}(k)$:
$$
\tilde{\mathbf B}(d,k)=\operatorname{diag}\bigl(\mathbf B^{F}_1(k),\dots,\mathbf B^{F}_{d/k}(k)\bigr).
$$
When we write $\mathbf B_{i,j}(d)$ we mean a *full* butterfly matrix of size $d\times d$ built by multiplying together the components whose block‑size doubles at each step:
$$
\mathbf B_{i,j}(d)=
\tilde{\mathbf B}(d,2^{i})\, 
\tilde{\mathbf B}\!\bigl(d,2^{i-1}\bigr)
\,\cdots\, 
\tilde{\mathbf B}\!\bigl(d,2\bigr).
$$
In other words,
*the index $i$ tells us how many “levels’’ (or factors) we compose* and  
*the index $j\in\{1,2\}$ distinguishes a matrix from its transpose*.

Consequently the whole product in Theorem 1 is:
```
B_{d-1,1} · B_{d-1,2}^T · B_{d-2,1} · B_{d-2,2}^T · … · B_{1,1} · B_{1,2}^T .
```
For a given $i$, each factor $B_{i,1}$ (or its transpose) contains exactly $i+1=\log_2(2^{i})+1 = i+1$ components
$\tilde{\mathbf B}(d,2^{i}),\,\tilde{\mathbf B}(d,2^{i-1}),\,…,\,\tilde{\mathbf B}(d,2).$
Thus the total number of elementary components that appear in the product is
$$
\sum_{i=1}^{d-1} 2(i+1)=O(d^2),
$$
which is why the theorem guarantees *exact* representation of any orthogonal matrix: we are allowed to use as many butterfly layers as necessary (in fact a quadratic number).  

Intuitively each factor supplies a new set of “edges’’ in the information‑transmission graph; by alternating a matrix with its transpose we are able to reverse the direction of those edges and thereby obtain full connectivity between every source and every sink node.

---------------------------------------------------------------------

### 2.  Does this require linear (or quadratic) depth?

The construction above indeed needs **$O(d)$** distinct groups of factors (the outer loop over $i=1,\dots ,d-1$). Since each group already contains $\Theta(i)$ elementary components, the overall depth – i.e. the total number of sparse matrices multiplied together – grows as $\Theta(d^2)$. In terms of *layers* that appear on top of each other in a neural‑network implementation this is linear in $d$ only if we count a **group** as a single layer (each group can be realized with a single “butterfly block’’ that internally does several small multiplications).  

The *practical* BOFT implementation does **not** use this exhaustive construction. Instead it fixes the block size to the smallest possible value ($b=2$) and uses **$m=\log_2 d$** butterfly components:
$$
R(m,b)= \prod_{t=1}^{m} \tilde{\mathbf B}^{b}_{(d,t)},
\qquad m=\log_2 d .
$$
This yields an orthogonal matrix with only $\mathcal O(d \log d)$ free parameters and depth logarithmic in $d$. The price we pay is that the set
$\{ R(m,b): m=\log d , b=2 \}$
is a strict subset of the full orthogonal group; it does **not** enjoy universal approximation.

Thus:

* The exact universality claimed in Theorem 1 needs **linear (in fact quadratic)** depth because we must be able to permute information arbitrarily many times.
* With the **logarithmic depth** used in experiments we obtain a *structured* sub‑group of $O(d)$ dimensions; it is highly expressive (it can represent FFT, Hadamard, etc.) but it cannot represent every orthogonal matrix.

---------------------------------------------------------------------

### 3.  Approximation error when we use far fewer components

The authors measured how well BOFT approximates a random dense orthogonal matrix for several choices of block size $b$ and depth $m$. The key observations from Figure 5 (the “parameter‑efficiency” plot) are:

* With **$b=2$** and **$m=9$** (which corresponds to roughly $9\,d/2 = 4.5 d$ trainable parameters), the average Frobenius error is already below $10^{-3}$ for a $512\times512$ target matrix.
* Reducing the depth while increasing block size moves you along roughly the same error‑vs‑parameter curve: e.g. **$b=16,m=1$** (the original block‑diagonal OFT with 8 000 parameters for $d=512$) yields an error comparable to **$b=4,m=6$** which uses only half as many parameters.
* Empirically the error decays roughly like $C / (\text{#parameters})^{0.5}$, which means that even modestly larger depths quickly bring you into the regime where the approximation error is negligible for downstream finetuning.

Putting these numbers into perspective: for finetuning tasks typical tolerances on weight perturbations are on the order of $10^{-2}$–$10^{-3}$ relative Frobenius norm. Consequently *a BOFT model with logarithmic depth and modest block size ($b=4$–$8$)* already lies within that acceptable regime even though it cannot realise every orthogonal matrix exactly.

---------------------------------------------------------------------

### 4.  Summary

* The universal construction in Theorem 1 consists of an alternating product of butterfly matrices and their transposes; each factor adds a new set of sparse edges and together they realise an arbitrary permutation of information on a $d\times(d+1)$ grid. Realising *all* orthogonal matrices with this scheme needs a number of factors that grows linearly (more precisely quadratically if you count elementary components).
* The BOFT implementation used in practice trades exact universality for parameter efficiency: it keeps only $\log_2 d$ butterfly components (depth ≈ log $d$) and therefore works with only ${O}(d \log d)$ trainable parameters.
* Empirically this restricted family already approximates random dense orthogonal matrices extremely well; with a handful of extra layers or slightly larger blocks you can push the approximation error below what matters for finetuning.

Hence, BOFT can **represent any orthogonal matrix** provided you allow sufficiently many butterfly layers (the construction behind Theorem 1). When you restrict yourself to the shallow log‑depth architecture common in experiments you lose exact universality but retain *practical* universality: the approximation error becomes negligible for realistic downstream tasks while keeping parameter count at ${O}(d \log d)$.

# The Mathematics Behind BOFT: Orthogonal Butterflies Explained  

In recent years, adapting massive foundation models without retraining them from scratch has become a hot research topic. One promising direction is **Orthogonal Finetuning (OFT)**, which updates a pretrained weight matrix $\mathbf{W}^{0}$ by left‑multiplying it with an orthogonal matrix $\mathbf{R}$ so that the pairwise angles between neurons are preserved. While OFT enjoys strong generalization, its naïve implementation requires $\mathcal{O}(d^{2})$ trainable parameters for a $d\times d$ orthogonal matrix—clearly infeasible for modern large‑scale models.

**BOFT (Orthogonal Butterfly Finetuning)** solves this dilemma by factorising a dense orthogonal matrix into a product of *sparse* orthogonal matrices organised in a **butterfly structure**. The result is an expressive finetuning layer that needs only $\mathcal{O}(d\log d)$ trainable parameters. In this post we unpack the core mathematics that makes BOFT work:

1. **Cayley parameterisation of orthogonal matrices**  
2. **Butterfly factorisation and its recursive definition**  
3. **Why BOFT is strictly more expressive than block‑diagonal OFT**  

Along the way we use simple diagrams and step‑by‑step examples to keep the intuition clear.

---

## 1. From Orthogonal Updates to Cayley Parameterisation  

An orthogonal matrix $\mathbf{R}\in\mathbb{R}^{d\times d}$ satisfies $\mathbf{R}^{\top}\mathbf{R}=\mathbf{I}_{d}$. Directly learning $\mathbf{R}$ would demand $d^{2}$ free entries, far too many for finetuning. The **Cayley transform** offers a compact re‑parameterisation:

\[
\boxed{\;\mathbf{R}= (\mathbf{I}+\mathbf{Q})(\mathbf{I}-\mathbf{Q})^{-1}\;}
\qquad\text{with}\qquad \mathbf{Q}^{\top}=-\mathbf{Q}.
\]

* $\mathbf{Q}$ is **skew‑symmetric**, i.e. $q_{ij} = -q_{ji}$ and $q_{ii}=0$.  
* The number of independent elements in $\mathbf{Q}$ is $\frac{d(d-1)}{2}$, half of a full matrix.  
* When $\mathbf{Q}= \mathbf{0}$, the transform yields $\mathbf{R}=\mathbf{I}_{d}$, giving us the standard *zero‑initialisation* used in finetuning.

With the Cayley transform we can treat the entries of $\mathbf{Q}$ as our learnable parameters, guaranteeing orthogonality throughout training without needing a costly projection step.

## 2. Butterfly Factorisation: Building Dense Orthogonal Matrices from Sparse Pieces  

### 2.1 Why “butterfly”?  

The classic Cooley–Tukey FFT repeatedly mixes pairs of signals in a pattern that looks like a butterfly when drawn as a graph (two inputs crossing to two outputs). This pattern yields an **efficient information transmission**: after $\log_{2} d$ stages each input can reach every output using only $d\log_{2} d$ non‑zero connections.

### 2.2 The elementary butterfly factor  

For an even integer $k$, define a **butterfly factor** $\mathbf{B}^{F}(k)$ as

\[
\mathbf{B}^{F}(k)=
\begin{bmatrix}
\operatorname{diag}(\mathbf{d}_{1}) & \operatorname{diag}(\mathbf{d}_{2})\\[4pt]
\operatorname{diag}(\mathbf{d}_{3}) & \operatorname{diag}(\mathbf{d}_{4})
\end{bmatrix},
\quad 
\mathbf{d}_{i}\in\mathbb R^{k/2}.
\]

Each block is diagonal, so the whole factor has exactly $k$ non‑zero entries (one per row/column). By learning the vectors $\mathbf{d}_{i}$ (or better yet their Cayley‑parameterised skew versions) we can make each factor orthogonal while preserving sparsity.

### 2.3 Recursion to full size  

Let $d=2^{N}$ for convenience. A **butterfly matrix** $\mathbf{B}(d)$ is constructed recursively:

1. **Base case ($d=2$):**  
   \[
   \mathbf{B}(2)= \begin{bmatrix}
   \cos\theta & -\sin\theta\\
   \sin\theta & \phantom{-}\cos\theta
   \end{bmatrix},
   \] 
   which is just a $2\times2$ rotation (orthogonal).

2. **Recursive step ($d>2$):**  
   Partition the $d$ coordinates into two halves of size $d/2$. Apply independent butterfly matrices to each half and then mix them with a *butterfly component*  

   \[
   \tilde{\mathbf B}(d,k)=
   \operatorname{diag}\bigl(\underbrace{\mathbf B^{F}(k),\,\dotsc ,\, \mathbf B^{F}(k)}_{d/k}\bigr),
   \]
   where $k$ is the block size at this stage (e.g., $k=d/2,\, d/4,\dotsc , 2$). The overall matrix becomes  

   \[
   \boxed{\;
   \mathbf B(d)=
   \tilde{\mathbf B}(d,d)\,
   \begin{bmatrix}
   \mathbf B(d/2) & 0\\[4pt]
   0 & \mathbf B(d/2)
   \end{bmatrix}
   }.
   \]

Because each $\tilde{\mathbf B}(d,k)$ contains only $d$ non‑zero entries, the *total* number of trainable elements after all $\log_{2} d$ stages is  

\[
\underbrace{\frac12(b-1)d}_{\text{sparse blocks}}\times\underbrace{\log_{2}\!\frac{2d}{b}}_{\text{stages}}
 =  \mathcal O(d\log d)
\]
when we set the block size $b=2$. The product of these sparse orthogonal components yields a *dense* orthogonal matrix $\mathbf R$, suitable for OFT.

### 2.4 A tiny example ( $d=4$ )  

| Stage | Factor (non‑zero pattern) | Effect on information flow |
|------|---------------------------|----------------------------|
| 1 (k=4) | $\tilde{\mathbf B}(4,4) = \operatorname{diag}\bigl(\begin{smallmatrix}\!a&0\\0&b\end{submatrix},\,\begin{submatrix}c&0\\0&d\end{submatrix}\bigr)$ | Each of the four inputs stays within its own pair |
| 2 (k=2) | $\tilde{\mathbf B}(4,2)$ mixes $(1,3)$ and $(2,4)$ pairs (the classic “butterfly” crossing) | After this stage every input can affect every output |

Multiplying the two stages produces a full $4\times4$ orthogonal matrix despite each stage having only four trainable numbers.

## 3. BOFT vs. Block‑Diagonal OFT: A Formal Expressivity Argument  

### 3.1 What does “expressivity” mean here?  

Given a target orthogonal matrix $\mathbf R^{*}\!\in O(d)$ we ask: how many trainable parameters are needed to *exactly* represent it? If a parameterisation can express *all* matrices in $O(d)$ then it is *universal*. If it can only express a proper subset, we compare the size of that subset.

### 3.2 Block‑diagonal OFT  

OFT with block size $b$ forces

\[
\mathbf R = 
\operatorname{diag}
(\underbrace{\mathbf R_{1}}_{b\times b},
~\underbrace{\dotsc}_{r-1},
~\underbrace{\mathbf R_{r}}_{b\times b}),
\qquad rb=d.
\]

Each block $\mathbf R_{i}$ is an independent orthogonal matrix with $\frac12 b(b-1)$ free parameters, totalling  

\[
p_{\text{BD}} = r\, \tfrac12 b(b-1)= \tfrac12 d(b-1).
\]

However, any matrix whose off‑block entries are non‑zero cannot be represented; thus the hypothesis class misses most of $O(d)$.

### 3.3 BOFT’s richer class  

BOFT builds

\[
\boxed{
\mathbf R(m,b)=
\prod_{i=1}^{m}
    \tilde{\mathbf B}^{\,b}_{(d,i)}},
    \qquad m=\log_{2}{(2d/b)},
}
\]

where each factor $\tilde{\mathbf B}^{\,b}_{(d,i)}$ is an orthogonal butterfly component with block size $b$. The total number of trainable scalars equals

\[
p_{\text{BOFT}} = 
\tfrac12(b-1)\, d\, m
 = 
\tfrac12(b-1)\, d\, \log_{2}\!\tfrac {2d}{b}
 = 
 {\cal O}(d\log d).
\]

Even though $p_{\text{BOFT}} > p_{\text{BD}}$ for large $b$, BOFT’s *structure* allows dense connectivity while using only linearithmic parameters.

### 3.4 Theorem – BOFT subsumes OFT and exceeds its expressivity  

> **Theorem (Expressivity of BOFT).**  
> Let $\mathcal O_{\text{BD}}(b)$ denote the set of orthogonal matrices realizable by block‑diagonal OFT with block size $b$, and let $\mathcal O_{\text {BF}}(m,b)$ denote those realizable by BOFT$(m,b)$. Then for any fixed $b$ and any feasible $m$,  
> $$ 
>    \mathcal O_{\text {BD}}(b)\subsetneq \mathcal O_{\text {BF}}(m,b).
> $$  
> Moreover, taking $m=\log_2 d$ and $b=2$, compositions of butterfly matrices of the form  
> $$ 
>    \prod_{i=1}^{d-1}
>        \bigl(\,\bm B_{i,1}(d)\,\bm B^{\top}_{i,2}(d)\,\bigr)
> $$  
> span the entire orthogonal group $O(d)$.

**Sketch of proof.**  
*Every butterfly component* is itself orthogonal and contains at least one non‑zero entry in each row and column; therefore its product can generate any permutation of rows/columns combined with rotations inside each pair—precisely what the FFT mixing does. Adding more stages multiplies these permutations, eventually yielding any element of the symmetric group on $d$ symbols with accompanying rotations; this combination generates all orthogonal matrices because any orthogonal matrix can be written as a product of Givens rotations (pairwise planar rotations). Block‑diagonal OFT lacks cross‑block permutations entirely, so it cannot realise even simple swaps between blocks, establishing strict containment.

Thus BOFT strictly expands the hypothesis space while still keeping parameter counts subquadratic.

## 4. Putting It All Together: A Step‑by‑Step BOFT Finetune

Suppose we want to finetune a linear layer with pretrained weight $\mathbf W^{0}\in \mathbb R^{d\times n}$. The BOFT forward pass looks like:

1. **Initialize** all butterfly components as identity via zero skew matrices in their Cayley transforms – guarantees start at exact pretrained behavior.
2. **Compute** the composite orthogonal matrix:  
   $$ 
   \displaystyle
   \mathbf R = 
   \prod_{i=1}^{m}
        (\!\,\underbrace{\bigl(\!\,\mathbb I + \widehat{\!\!\! Q_i}\!\,\bigr)}_{\text{sparse}}
        (\!\,\mathbb I - ̂ Q_i)^{-1}),
        $$  
   where each $\widehat Q_i$ embeds a small skew-symmetric block into its corresponding butterfly factor.
3. **Apply** left multiplication:  
   $$ 
   \boldsymbol z = (\,\mathbf R\, {\bf W}^{0})^{\!\top}{\bf x}.
   $$  
4. Optionally use **multiplicative dropout**: randomly replace whole butterfly components or inner blocks by identity matrices during training; this regularises without breaking orthogonality.

The cost per forward/backward pass grows modestly because we multiply by $m=\mathcal O(\log d)$ sparse factors instead of one dense matrix.

## 5. Visual Intuition – Information Transmission Graphs  

A helpful way to see why butterflies succeed is to draw a *grid graph* with layers representing intermediate vectors after each factor multiplication:

```
Level 0      Level 1      Level 2      …      Level m
 (x_1) ——► (y_1) ——► …               —► (z_1)
 (x_2) ——► (y_2) ——► …               —► (z_2)
 …
 (x_d) ——► (y_d) ——► …               —► (z_d)
```

Each edge corresponds to a non‑zero entry in the current sparse factor; edges only connect adjacent levels but are arranged so that after all levels every source node reaches every sink node—exactly what “dense connectivity” means mathematically. In contrast, block‑diagonal OFT would have edges confined within disjoint sub‑grids, never crossing blocks.

## 6. Takeaways  

| Concept | Key Formula / Idea | Parameter Cost |
|---------|-------------------|----------------|
| **Cayley transform** | $\displaystyle (\mathbb I+\!Q)(\mathbb I-\!Q)^{-1},~ Q^\top=-Q$ | $\tfrac12 d(d-1)$ before sparsity |
| **Butterfly factor** | Diagonal blocks glued together → Eq.(1) | Exactly $k$ non‑zeros per factor |
| **Recursive butterfly matrix** | Product over log‐levels → Eq.(recursive) | $\mathcal O(d\,m)$ where $m=\log_2(2d/b)$ |
| **BOFT expressivity** | Theorem 3 ⇒ spans all of \(O(d)\) when enough factors are used | $\boxed{\mathcal O(d\,\log d)}$ vs.\;block‐diag OFT’s $\mathcal O(db)$ |

BOFT therefore delivers three practical advantages:

1. **Parameter efficiency:** Only linearithmic learnable scalars even for very wide layers.
2. **Preserved geometry:** Orthogonality guarantees unchanged spectral norm and angle preservation.
3. **Higher expressivity:** Butterfly factorizations can approximate any orthogonal transformation, unlike fixed block‑diagonal patterns.

---

## 7. Final Thoughts  

The mathematics behind BOFT bridges classic signal processing (FFT butterflies), graph theory (information transmission on grids), and modern deep learning (parameter‑efficient finetuning). By treating an orthogonal update as a structured sparse product—rather than a monolithic dense matrix—we obtain an elegant trade‑off between *capacity* and *compactness*. The result is a versatile finetuning tool that works across vision transformers, large language models, and diffusion generators while staying lightweight enough for real-world deployment.

If you’re curious to experiment yourself:

```python
# Pseudocode sketch
def cayley(q):
    I = torch.eye(q.shape[0])
    return (I + q) @ torch.inverse(I - q)

def butterfly_layer(x, params):
    # params hold skew-symmetric blocks for each stage
    R = torch.eye(x.shape[-1])
    for stage in params:
        Q = embed_skew(stage)          # put small skew blocks into full-size Q
        R = cayley(Q) @ R
    return x @ (R @ W0).t()
```

Replace `embed_skew` with your own mapping from learned vectors to sparse skew matrices following Eq.(1). With identity initialisation you'll recover exactly the pretrained model before any update—just like standard finetuning—while gaining all the theoretical benefits discussed above.

\title{A Textbook about the Paper: "LongRoPE: Extending LLM Context Window Beyond 2 Million Tokens"}

Chapter 5: 5. Formulating LongRoPE as an Optimization Problem

# Why context extension can be framed as search over RoPE rescaling factors

LongRoPE begins from a simple observation in the paper: the main difficulty in extending an LLM’s context window is not just making the model “see farther,” but doing so without destroying the positional information it already knows. In RoPE-based models, positions are encoded through rotation angles, and extending the window means changing those angles so that much larger token indices can still be represented in a range the model can handle. The paper argues that this is naturally a search problem because there are many possible ways to rescale those angles, and the best choice is not obvious in advance.

This framing is especially important because the paper identifies two kinds of non-uniformity that matter for positional interpolation: different RoPE dimensions do not behave the same way, and early token positions do not need to be treated the same as later ones. Once these two facts are accepted, extending context is no longer just a single global scaling decision. Instead, it becomes the problem of finding a collection of rescaling factors that preserve useful information while still stretching the usable sequence length.

The paper formalizes this by defining a target context length $L'$ and then searching for RoPE settings that minimize the model’s prediction loss on long documents. In other words, LongRoPE does not treat context extension as a fixed transformation. It treats it as an optimization over the positional encoding itself.

# Definition of the modified RoPE function in LongRoPE

To express this optimization, the paper starts from the standard RoPE representation. For a token at position $n$, the rotary angles for the $i^{\text{th}}$ RoPE dimension are originally of the form $\frac{n}{\beta^i}$, where $\beta=\theta^{2/d}$ and $d$ is the embedding dimension. LongRoPE modifies this structure by inserting a rescaling term into the rotation angle.

The resulting RoPE definition keeps the same cosine-sine structure, but replaces the raw angle with a rescaled one. For each dimension and each token position, the embedding uses terms such as
\[
\cos\left(\mathbb{I}(\hat{\lambda}_i,\hat{n})\times \frac{n}{\beta^i}\right), \quad
\sin\left(\mathbb{I}(\hat{\lambda}_i,\hat{n})\times \frac{n}{\beta^i}\right).
\]
This means the model still uses the RoPE mechanism, but with a position-dependent and dimension-dependent adjustment controlled by the indicator function $\mathbb{I}(\hat{\lambda}_i,\hat{n})$.

The key point is that LongRoPE does not replace RoPE with a new positional encoding architecture. It keeps the original RoPE form and changes only the scaling applied to the rotation angles. This is why the paper emphasizes that models extended by LongRoPE retain the original architecture with only minor modifications to positional embedding.

# Per-dimension scaling factors $\lambda_i$

One of the main search variables in LongRoPE is the set of per-dimension scaling factors $\lambda_i$. The paper introduces these factors to capture the fact that different RoPE dimensions should not necessarily be interpolated equally. Lower RoPE dimensions correspond to higher frequencies, and the paper’s empirical analysis suggests that these dimensions should generally receive less interpolation. Higher dimensions, which represent lower frequencies, can tolerate more interpolation.

Rather than using one global scaling rule for all dimensions, LongRoPE allows each dimension to have its own rescale factor. In the paper’s notation, this is represented through $\mathbb{I}(\hat{\lambda}_i,\hat{n})$, where $\hat{\lambda}_i$ is the dimension-specific factor. To simplify the search, the paper often searches over $\lambda_i$ directly and defines $\hat{\lambda}_i = 1/\lambda_i$.

This per-dimension flexibility is what lets LongRoPE express the non-uniformity discovered in the analysis section. The scaling factors are not arbitrary additions; they are the formal mechanism through which the paper preserves important positional information. By allowing each dimension to be rescaled differently, LongRoPE can keep the most informative parts of the original positional encoding closer to their pretrained behavior.

# The early-token threshold $\hat{n}$ and its indicator function

The second non-uniformity in LongRoPE concerns token positions rather than RoPE dimensions. The paper observes that the initial tokens in a sequence can be especially important because they often receive large attention scores and can strongly influence later computation. Based on this, LongRoPE introduces a threshold $\hat{n}$ that determines how many early token positions should remain unmodified.

This is captured by the indicator function
\[
\mathbb{I}(\hat{\lambda}_i,\hat{n})=
\begin{cases}
1 & \text{if } n < \hat{n}, \\
\frac{1}{\lambda_i} & \text{if } n \ge \hat{n}.
\end{cases}
\]
When $n < \hat{n}$, the rescaling factor is effectively turned off, so the original RoPE angle $\frac{n}{\beta^i}$ is used. Only after the threshold is crossed does the rescaled version apply.

This design gives LongRoPE a way to treat the beginning of the sequence differently from the rest. The paper’s empirical study shows that keeping early tokens un-interpolated can improve performance, but the optimal number of such tokens depends on the target extension length. The threshold $\hat{n}$ therefore becomes another search variable, encoding the position-wise non-uniformity discovered in the analysis.

# How unmodified and rescaled positions are combined in the same sequence

A central feature of LongRoPE is that it does not require a sequence to be encoded entirely with either the original RoPE or the rescaled RoPE. Instead, the same input sequence can mix both behaviors. Early positions can remain untouched, while later positions are rescaled using the learned factors.

This mixture is important because it allows LongRoPE to preserve the original positional structure where it matters most, while still stretching the context window for longer inputs. In the paper’s formulation, the first $\hat{n}-1$ positions use the original rotation angles, and positions with $n \ge \hat{n}$ use the rescaled angles. The full embedding is therefore piecewise defined across the sequence.

Conceptually, this means LongRoPE is not merely “compressing” all positions uniformly. It is selectively preserving and transforming positional information. That selective treatment is the formal expression of the paper’s intuition that some dimensions and some token positions deserve less distortion than others.

# Optimization objective: minimizing next-token prediction loss or perplexity

Once the modified RoPE is defined, the paper formulates the actual objective as minimizing the model’s next-token prediction loss $\mathcal{L}$ on long input documents. Since perplexity is the practical measure used throughout the paper, this loss can be read as the same quantity the search procedure is trying to improve.

Formally, the target is to find rescaling factors that make the LLM with modified RoPE perform as well as possible on input samples of length at least $L'$. The paper writes this as an arg-min over the input set $\mathbf{X}$, where each document $\mathbf{x}\in\mathbf{X}$ has length $|\mathbf{x}| \ge L'$. The goal is for the model to process these long documents with minimal loss under the chosen RoPE rescaling.

This objective explains why the search process is based on perplexity evaluation. The paper does not search for rescaling factors in the abstract; it evaluates candidate settings by applying them to the model and computing perplexity on long samples. Lower perplexity means the modified positional encoding better preserves the model’s ability to predict the next token, and thus better supports long-context use.

# Input requirements for search documents longer than the target context length

The search formulation also imposes a clear requirement on the input documents used for optimization: they must be long enough to exceed the target context length $L'$. The paper specifies that the search is performed on a set of lengthy documents $\mathbf{X}$, where each $\mathbf{x}\in\mathbf{X}$ surpasses $L'$ in token length.

This requirement matters because the method is trying to tune the model for long-context behavior. If the evaluation documents were shorter than the target window, the search would not meaningfully test the positional rescaling in the region where the extension matters most. LongRoPE therefore uses documents that actually force the model into the extended portion of the context window.

In the paper’s experiments, different datasets are used depending on the target length, but the formulation itself stays general. The search procedure is always driven by long enough inputs so that the model’s behavior under the proposed rescaling can be measured at the intended extension scale.

# Interpretation of LongRoPE as preserving important information while stretching context

The optimization view makes the paper’s intuition precise. LongRoPE is trying to stretch the context window, but it does so in a way that preserves as much of the original RoPE information as possible. The search over $\lambda_i$ and $\hat{n}$ is designed to minimize the information loss introduced by positional interpolation.

This preservation is not uniform across the sequence or across the embedding dimensions. Instead, LongRoPE keeps key dimensions closer to the original RoPE behavior and leaves early positions untouched when beneficial. The result is a positional encoding that is less aggressively distorted than standard linear interpolation, while still allowing much longer contexts.

Seen this way, LongRoPE’s optimization problem is the formal core of the entire method. The paper’s later contributions, including evolutionary search, progressive extension, and short-context recovery, all operate on top of this formulation. The optimization perspective explains why those techniques are needed: the space of possible RoPE rescalings is huge, but only some of them preserve the information needed for both long-context extension and short-context performance.

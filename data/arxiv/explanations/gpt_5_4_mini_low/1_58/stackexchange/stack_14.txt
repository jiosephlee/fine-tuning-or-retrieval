\title{Stack Exchange of the Paper: "The Era of 1-bit LLMs: All Large Language Models are in 1.58 Bits"}

### How does BitNet b1.58 interact with the KV cache if the paper only quantizes weights and activations?
Question:
In the discussion section, the paper says BitNet b1.58 is a significant step toward native support for long sequences because it reduces activations from 16 bits to 8 bits, allowing context length to double under the same resources. But I thought the main long-context bottleneck during autoregressive inference was the KV cache.

Are the stored keys and values also 8-bit in this setup, or is the paper speaking more generally about the activation precision throughout the network? If the KV cache is not explicitly quantized, I am struggling to see why the context length would simply double.
Answer:
The paper is using “activations” in a broad systems sense, and that is the key to reading that discussion section. In autoregressive inference, the KV cache is indeed the main activation-like memory resident across decoding steps, so if the cache were still stored in FP16/BF16, then the claim that context length can simply double would not follow. The paper’s wording suggests that they are thinking of the whole activation footprint during inference, which includes the KV cache, not just the transient hidden states inside the layers.

That said, the paper does not spell out a separate KV-cache quantization scheme in the main text. It says BitNet b1.58 is trained with “8-bit activations,” and then, in the discussion, it says this “reduces the activations from 16 bits to 8 bits, allowing the context length to be doubled given the same resources.” So the intended interpretation is that the activation precision used in inference, including the cached states, is lower than in a standard FP16/BF16 Transformer. Under that assumption, halving the number of bytes per cached key/value vector roughly doubles the number of tokens you can store for the same memory budget.

The paper also hints that this is not the end of the story: it explicitly says the KV-cache-related memory could be “further losslessly compressed to 4 bits or even lower for 1.58-bit LLMs, which we leave as future work.” That is an important clue that the authors see KV-cache compression as a separate optimization avenue, not something fully solved in the current work.

So the short answer is: the paper is not claiming that BitNet b1.58 magically removes the KV-cache bottleneck. Rather, it is arguing that because the model already uses 8-bit activations, the cache footprint is reduced relative to a 16-bit baseline, which in turn can approximately double the context length under the same memory budget. If you keep the KV cache at 16 bits, that conclusion would not hold as stated; the discussion is implicitly assuming the activation memory used for caching is also reduced.

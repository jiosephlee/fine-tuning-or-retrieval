\title{Stack Exchange of the Paper: "The Era of 1-bit LLMs: All Large Language Models are in 1.58 Bits"}

### Is it fair to compare a 3.9B BitNet b1.58 model against a 3B FP16 model and call it a Pareto improvement?
Question:
The results section emphasizes that BitNet b1.58 with 3.9B parameters is faster and uses less memory than a 3B FP16 LLaMA-like model while performing better, and this is described as a Pareto improvement.

I am not sure how to think about this comparison. On one hand, the quantized model has more parameters, so it is not a like-for-like architecture comparison. On the other hand, the total deployment cost is still lower.

In model compression and systems papers, is this considered a fair comparison standard? Should the key comparison axis here be quality at fixed latency/memory budget rather than quality at fixed parameter count?
Answer:
Yes, it is fair in the sense that the paper is explicitly comparing the *deployment trade-off* rather than the raw parameter count.

The key point is that a BitNet b1.58 model and an FP16 LLaMA-like model do not live on the same cost axis. A 3.9B BitNet model stores its weights in ternary form, so each parameter is vastly cheaper in memory and arithmetic than an FP16 parameter. Because of that, “same parameter count” is not the right fairness criterion if the question is “which model gives better quality for a given inference budget?” In fact, the paper’s whole argument is that the meaningful comparison is quality versus latency, memory, throughput, and energy, not quality versus parameter count alone.

That is why the authors are comfortable calling the 3.9B BitNet b1.58 versus 3B FP16 result a Pareto improvement. In multi-objective terms, a point is Pareto-dominating another if it is no worse on all objectives and strictly better on at least one. Here the paper claims that 3.9B BitNet b1.58 has better task performance while also using less GPU memory and being faster than the 3B FP16 baseline. Under those measured deployment metrics, that is exactly the kind of claim “Pareto improvement” refers to.

What would be less fair is to compare only parameter count and say the 3.9B BitNet is “larger,” as if that alone should make it worse. That would ignore that BitNet changes the cost per parameter dramatically. The paper even frames this as a new scaling law: for example, it states that 13B BitNet b1.58 is more efficient in latency, memory, and energy than 3B FP16, and similarly for larger sizes. So the relevant axis is not just model size in the abstract, but model size translated into actual system cost.

So, in model compression and systems papers, the standard is usually to compare at fixed deployment budget, or to report the Pareto frontier over quality versus cost. Fixed parameter count is useful when you want an apples-to-apples architectural comparison, and the paper does that too by saying BitNet b1.58 matches full-precision baselines “with the same model size and training tokens.” But once the question becomes “is this better to deploy?”, then comparing a 3.9B ternary model to a 3B FP16 model is reasonable, because the number of stored parameters is not the resource that matters most anymore.

In short, the comparison is fair if the claim is about *end-to-end efficiency*: better quality at lower latency and memory. It would be misleading only if the authors were presenting it as a pure parameter-matched architectural comparison.

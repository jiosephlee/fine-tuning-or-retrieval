\title{Stack Exchange of the Paper: "The Era of 1-bit LLMs: All Large Language Models are in 1.58 Bits"}

### Why does a ternary weight set $\{-1,0,1\}$ correspond to $1.58$ bits instead of $2$ bits?
Question:
I'm reading the paper "The Era of 1-bit LLMs: All Large Language Models are in 1.58 Bits", and I am confused by the naming. The model uses ternary weights $\{-1,0,1\}$, which are three possible states per weight. The paper calls this "1.58-bit" because of the binary-system representation, but I don't fully understand the exact reasoning.

Is this just because $\log_2(3) \approx 1.585$, meaning each weight carries that much information in principle? Or does the implementation literally pack weights into memory at $1.58$ bits on average? If actual hardware stores them in 2-bit containers, then in what sense is the model really $1.58$-bit rather than 2-bit?
Answer:
The short answer is that $1.58$ bits comes from the information-theoretic cost of representing three symbols, not from a literal hardware storage format.

If a weight can take one of $3$ values, here $\{-1,0,1\}$, then the minimum number of binary bits needed to uniquely encode it is $\log_2(3) \approx 1.585$. That is the sense in which the paper calls the model “1.58-bit”: each weight has three possible states, so its idealized per-weight information content is $1.58$ bits rather than $2$ bits. This is exactly what the paper means when it says they “added an additional value of $0$ to the original 1-bit BitNet, resulting in 1.58 bits in the binary system.”

But that does not mean the weights are necessarily stored in memory at $1.58$ bits each in a literal, physical sense. Real hardware memory is discrete, so a naïve implementation would typically use a $2$-bit container per ternary weight, because $2$ bits are enough to encode up to $4$ states. In practice, the paper even notes that their runtime experiments used a “$2$-bit kernel,” which strongly suggests that the implementation is not packing weights into exactly $1.585$ bits on average at the storage level.

So there are really two different notions here. The first is the representational alphabet size: ternary weights have $3$ possible values, and the information-theoretic lower bound is $\log_2(3)$ bits per weight. The second is physical storage: actual implementations may still use $2$ bits per weight, or some compressed packing scheme, depending on the system. The paper’s headline “1.58 bits” refers to the former, not necessarily the latter.

This is similar to why people say “1-bit” binary networks even when the implementation uses extra metadata or packing overhead. The naming is about the number of distinct quantized states per parameter, not a promise that every parameter is stored in exactly that many raw hardware bits. In other words, “1.58-bit” is a quantization-level description, while memory usage is a separate engineering question.

So your intuition is right: $\log_2(3) \approx 1.585$ is the reason. The model is “really” $1.58$-bit in the information-theoretic sense, but not necessarily in the literal memory-layout sense.

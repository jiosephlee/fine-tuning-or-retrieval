\title{Blogs about the Paper: "Group Sequence Policy Optimization"}

# From Tokens to Full Answers: A Beginner-Friendly Guide to Group Sequence Policy Optimization

Large language models are often trained and improved one response at a time. In reinforcement learning for language models, the model generates an answer, a verifier scores that answer, and the model is updated to make better answers more likely. That sounds simple, but the details matter a lot.

The new paper on **Group Sequence Policy Optimization (GSPO)** argues that one of the biggest mistakes in earlier methods is *where* they apply the learning signal. Instead of optimizing each token separately, GSPO optimizes the **entire response as a sequence**. That turns out to match the way rewards are actually assigned in tasks like math and coding, where the whole answer is judged, not each token in isolation.

## Why token-level optimization is a mismatch

In standard language modeling, a response is produced token by token. So it is natural to think about training token by token too. Methods like GRPO do exactly that: they compute an importance ratio for each token and apply clipping at the token level.

The problem is that the reward usually does **not** come token by token. For many RL training setups, a verifier gives a score to the complete response \(y\), not to each intermediate token \(y_t\). The paper argues that this creates a mismatch:

- the **reward** is sequence-level,
- but the **optimization** is token-level.

GSPO is built around a simple principle: the unit of optimization should match the unit of reward.

## The sequence-level idea

GSPO changes the importance ratio from token likelihood to **sequence likelihood**. For a response \(y\) to a query \(x\), the model likelihood is

\[
\pi_\theta(y \mid x) = \prod_{t=1}^{|y|} \pi_\theta(y_t \mid x, y_{<t}).
\]

Instead of comparing the current and old policies token by token, GSPO compares them at the response level:

\[
s_i(\theta) = \left(\frac{\pi_\theta(y_i \mid x)}{\pi_{\theta_{\text{old}}}(y_i \mid x)}\right)^{\frac{1}{|y_i|}}.
\]

That exponent of \(1/|y_i|\) is a length normalization term. It helps keep the ratio in a stable numeric range and reduces variance across responses of different lengths.

So the model is no longer asking, “How much should I trust this token?” It is asking, “How much should I trust this entire answer?”

## How GSPO uses rewards

GSPO is still group-based. For each query \(x\), it samples a group of responses \(\{y_i\}_{i=1}^G\). Each response gets a reward \(r(x, y_i)\), and the rewards are normalized within the group to form advantages:

\[
\widehat{A}_i = \frac{r(x, y_i) - \mathrm{mean}(\{r(x, y_i)\}_{i=1}^G)}{\mathrm{std}(\{r(x, y_i)\}_{i=1}^G)}.
\]

Then GSPO optimizes responses using the sequence-level ratio \(s_i(\theta)\) and clips that ratio just like PPO-style methods do:

\[
\min\left(s_i(\theta)\widehat{A}_i,\ \mathrm{clip}(s_i(\theta), 1-\varepsilon, 1+\varepsilon)\widehat{A}_i\right).
\]

The important difference is that clipping is applied to the **whole response**, not to each token.

## Why this is a better fit for language tasks

In tasks like coding and math, a response is usually judged as a whole. A code solution either passes tests or it does not. A mathematical derivation either reaches the right answer or it does not. In these settings, token-level correction is a somewhat awkward proxy.

GSPO better matches this evaluation style because it treats a response as a single unit of decision-making. If a sampled answer is good, the full response is reinforced. If it is bad, the full response is downweighted. That aligns optimization with the actual training signal.

This also helps explain one of the paper’s key observations: sequence-level optimization is more stable than token-level optimization when response lengths get large. Token-level importance ratios can become noisy and compound over long generations. GSPO avoids that by using one ratio for the whole sequence.

## What changes in the gradient

The paper shows that GSPO weights all tokens in a response equally when computing the gradient. That is a subtle but important point. In GRPO, each token can receive its own importance weight, which can vary unpredictably. In GSPO, every token in the sampled response shares the same sequence-level weight.

So although the model still updates token log-likelihoods internally, the update signal is controlled at the response level. That makes the learning dynamics more consistent with the reward structure.

## A practical consequence: simpler and more stable training

The paper reports that GSPO improves training stability and efficiency compared to GRPO, especially for long responses and large Mixture-of-Experts models. It also removes the need for a workaround called Routing Replay in MoE RL training.

But the central innovation is conceptually simple: **stop pretending that every token is independently judged when the reward is actually assigned to the whole answer**.

GSPO makes that idea explicit by using sequence likelihood as the importance ratio and applying sequence-level clipping and optimization. That small shift in perspective turns out to matter a lot for scaling RL in language models.

## Takeaway

GSPO’s main contribution is not a new reward model or a new verifier. It is a better match between the structure of the reward and the structure of the optimization.

If the model is being judged on complete answers, then the policy update should also be based on complete answers. GSPO does exactly that, and the paper shows that this sequence-level approach is more stable, more efficient, and better suited to the kinds of reasoning tasks where large language models are now being trained.

\title{Blogs about the Paper: "FlashAttention-3: Fast and Accurate Attention with Asynchrony and Low-precision"}

# Why Attention Is Still the Slowest Part of AI—and How FlashAttention-3 Fixes It

Attention is one of the most important parts of the Transformer architecture, but it is also one of the main reasons large models are slow. That matters even more as models move toward longer context windows, where they need to process thousands or even tens of thousands of tokens at once. In that regime, attention does not just get more expensive — it grows quadratically with sequence length, which quickly makes it the bottleneck.

The FlashAttention line of work was designed to attack that problem directly. Instead of changing the math of attention, it changes how attention is executed on GPUs. FlashAttention-3 continues that idea, but takes a more hardware-aware approach than earlier versions. On NVIDIA Hopper GPUs, it uses asynchrony and low-precision execution to push attention much closer to the hardware limits.

## Why attention becomes the bottleneck

For a single attention head, the core computation is:

\[
\mathbf{S} = \alpha \mathbf{Q}\mathbf{K}^\top,\quad
\mathbf{P} = \mathrm{softmax}(\mathbf{S}),\quad
\mathbf{O} = \mathbf{P}\mathbf{V}.
\]

The problem is the middle matrix, \(\mathbf{S}\). If the sequence length is \(N\), then \(\mathbf{S}\) is \(N \times N\), so the cost grows like \(N^2\). That is fine for short sequences, but it becomes very expensive for long-context workloads.

This is not just a training issue. Long context is increasingly useful for:

- reasoning over long documents,
- code understanding over large repositories,
- multimodal models for images, audio, and video,
- user-facing systems that need to remember long histories,
- agent workflows with long horizons.

So there is a real need for attention implementations that are exact, fast, and scalable.

## What earlier FlashAttention versions did

The original FlashAttention made a simple but powerful observation: attention does not need to materialize the intermediate matrices \(\mathbf{S}\) and \(\mathbf{P}\) in global memory. Those reads and writes are expensive. Instead, FlashAttention fuses the attention computation into a single GPU kernel and keeps intermediate values on chip as much as possible.

FlashAttention-2 pushed that further by restructuring the computation to better parallelize work across the sequence dimension and improve occupancy. That helped a lot, but the paper reports that on Hopper H100 GPUs, FlashAttention-2 still only reaches about 35% utilization, while optimized matrix-multiplication kernels can get much closer to the hardware ceiling.

FlashAttention-3 is built to close that gap.

## What FlashAttention-3 changes

FlashAttention-3 introduces three main ideas.

First, it uses warp specialization to separate producer and consumer work. On Hopper, memory movement and matrix multiplication can happen asynchronously through hardware units like TMA and WGMMA. FlashAttention-3 exploits that by splitting the warps in a threadblock into roles: some warps load data, while others compute. That lets the kernel overlap data movement with computation instead of waiting on it.

Second, it overlaps softmax with GEMM work. In earlier designs, the softmax step and the matrix multiplications were more serialized. FlashAttention-3 reworks the execution so that while one part of the kernel is handling softmax for one block, another part can already be launching the next matrix multiplication. This “pingpong” style scheduling helps hide the relatively slow softmax operations behind faster Tensor Core work.

Third, it adapts the algorithm to FP8 on Hopper. FP8 can roughly double throughput compared to FP16 or BF16, but it comes with extra layout constraints and more numerical risk. FlashAttention-3 handles both issues with in-kernel layout transformations and two accuracy techniques: block quantization and incoherent processing.

## Why Hopper matters here

FlashAttention-3 is specifically designed around Hopper’s execution model.

Hopper has:

- Tensor Cores that support asynchronous WGMMA instructions,
- TMA for asynchronous data movement from global memory to shared memory,
- support for dynamic register reallocation across warpgroups,
- hardware support for FP8.

These features make it possible to redesign the kernel around overlapping work, rather than simply making the old kernel a little faster. That distinction matters. FlashAttention-3 is not just a tuned implementation of the same synchronous algorithm — it is an algorithm that explicitly exploits Hopper’s asynchronous hardware.

## How much faster is it?

The paper reports substantial speedups on an H100 SXM5 GPU:

- FP16 FlashAttention-3 reaches up to 740 TFLOPs/s, about 75% utilization.
- It is 1.5–2.0\times faster than FlashAttention-2 in the forward pass.
- It is 1.5–1.75\times faster in the backward pass.
- FP8 FlashAttention-3 reaches close to 1.2 PFLOPs/s.

That is a meaningful jump. In practice, a 1.5–2.0\times speedup on attention is a big deal because attention is one of the dominant costs in Transformer models. If attention gets faster, then longer context, larger batches, and more efficient multimodal processing all become more feasible.

The authors also compare against standard attention implementations and a cuDNN implementation optimized for Hopper. For medium and long sequences, FlashAttention-3 can outperform cuDNN as well.

## Why FP8 is both promising and tricky

FP8 is attractive because it can significantly increase throughput. But lower precision also means more numerical error, and attention is especially sensitive to that because it includes softmax and can be affected by outlier values in model activations.

FlashAttention-3 addresses this in two ways.

With block quantization, each block of \(\mathbf{Q}\), \(\mathbf{K}\), and \(\mathbf{V}\) gets its own scaling factor instead of using one scale for the entire tensor. That gives finer control over quantization error.

With incoherent processing, the model multiplies \(\mathbf{Q}\) and \(\mathbf{K}\) by a random orthogonal transform before quantization. Because the transform is orthogonal, it does not change the attention scores:

\[
(\mathbf{Q}\mathbf{M})(\mathbf{K}\mathbf{M})^\top = \mathbf{Q}\mathbf{K}^\top.
\]

What it does do is spread out outliers, which makes quantization easier.

In the paper’s evaluation, FP8 FlashAttention-3 is 2.6\times more accurate than a baseline FP8 attention method using per-tensor quantization in the tested outlier-heavy setting.

## Why this is more than just a benchmark win

This kind of optimization matters because attention is not an isolated kernel. It sits in the middle of almost every Transformer-based system. If you speed it up, you improve:

- training throughput,
- inference latency,
- long-context reasoning,
- multimodal pipelines,
- memory efficiency.

That is especially important as models grow larger and context windows expand. The broader the context, the more attention costs dominate. So even a relatively small improvement at the kernel level can translate into a major system-level gain.

FlashAttention-3 is also a good example of a broader trend in ML systems: the best performance gains often come from matching algorithms to hardware features instead of treating hardware as generic compute.

## The takeaway

FlashAttention-3 does not approximate attention or change the underlying math. Instead, it rethinks how exact attention is scheduled on Hopper GPUs. By using asynchronous execution, warp specialization, GEMM-softmax overlap, and FP8-aware design, it pushes attention much closer to the hardware limits.

The result is a 1.5–2.0\times speedup over FlashAttention-2 on H100 GPUs, along with strong FP8 performance and improved FP8 numerical accuracy. For long-context LLMs, multimodal models, and document-scale reasoning, that is exactly the kind of improvement that can make the difference between a theoretical capability and a practical one.

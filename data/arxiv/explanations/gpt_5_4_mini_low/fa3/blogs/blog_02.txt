\title{Blogs about the Paper: "FlashAttention-3: Fast and Accurate Attention with Asynchrony and Low-precision"}

# Teaching GPUs to Multitask: The Asynchrony Trick Behind FlashAttention-3

Attention is one of the most important parts of Transformer models, but it is also one of the most expensive. As sequence lengths grow, the cost of computing attention grows quickly too. That is why the FlashAttention line of work has been so influential: it turns attention from a memory-heavy operation into a carefully tiled GPU kernel that avoids writing large intermediate results back to slow global memory.

FlashAttention-3 pushes that idea further, but the main story is not just “make the math faster.” The paper’s biggest systems insight is that modern Hopper GPUs can do more than one thing at once, and the attention kernel should be redesigned around that fact.

In short: FlashAttention-3 teaches the GPU to multitask.

## Why attention is hard to speed up

A standard attention computation has three main steps. First, it computes the score matrix $\mathbf{S} = \alpha \mathbf{Q}\mathbf{K}^\top$. Then it applies row-wise softmax to get probabilities $\mathbf{P}$. Finally, it multiplies by $\mathbf{V}$ to produce the output $\mathbf{O} = \mathbf{P}\mathbf{V}$.

On paper, those are just a couple of matrix multiplications and a softmax. On a GPU, though, the challenge is that these steps are not independent. The softmax needs the score matrix before it can run, and the final multiplication needs the softmax output. If you execute them naively, the GPU spends too much time waiting for one stage to finish before the next can begin.

FlashAttention already improved this by fusing the whole computation into one kernel and avoiding extra reads and writes. FlashAttention-3 goes a step further by exploiting the fact that Hopper GPUs can overlap data movement and computation in a more fine-grained way than earlier designs assumed.

## The key hardware idea: different GPU parts can work in parallel

A Hopper GPU does not behave like one single giant processor. It has specialized units for different jobs.

Tensor Cores are optimized for matrix multiplication. The Tensor Memory Accelerator, or TMA, is a dedicated engine for moving data between global memory and shared memory. Meanwhile, the regular CUDA cores handle logic, arithmetic, and other control-heavy work.

That matters because these units can run asynchronously. In other words, the GPU does not need to stop everything while one piece finishes. If the kernel is structured correctly, data can be moving in one part of the chip while matrix multiplication is happening in another, and while softmax is being computed somewhere else.

FlashAttention-3 is designed around this idea.

## Warp-specialization: splitting the team into producers and consumers

The first major trick in FlashAttention-3 is warp-specialization.

A warp is a group of 32 threads, and a warpgroup is a larger unit made of four warps. Instead of making every warp do every task, FlashAttention-3 divides the work into roles:

- **Producer warps** handle data movement.
- **Consumer warps** handle computation.

The producer side uses TMA to load tiles of $\mathbf{Q}$, $\mathbf{K}$, and $\mathbf{V}$ from global memory into shared memory. The consumer side reads those tiles from shared memory and runs the matrix multiplications and softmax logic.

This is a producer-consumer pipeline. The producer keeps filling the next slot in a circular shared-memory buffer, while the consumer works through the current slot. Because the loads are asynchronous, the producer does not have to block on every compute step, and the consumer does not have to wait for the entire next chunk of data to be ready before starting.

That is the basic multitasking pattern: one part of the GPU is always preparing the next tile while another part is finishing the current one.

## Ping-pong scheduling: overlapping softmax with matmul

Warp-specialization alone helps, but FlashAttention-3 goes further. The paper’s second major idea is to overlap softmax with matrix multiplication.

Why is this useful? Because matrix multiplication is extremely fast on Tensor Cores, while softmax involves operations like exponentials and reductions that are much slower. On Hopper, the mismatch is especially large: the paper notes that FP16 matmul throughput is far higher than the throughput for special functions such as exponential.

If the GPU waits for softmax to finish before starting the next matrix multiplication, the Tensor Cores sit idle. FlashAttention-3 instead tries to keep the Tensor Cores busy while softmax runs in parallel on other hardware.

The mechanism is a kind of “ping-pong” schedule between two warpgroups. While one warpgroup is doing the softmax and output update for the current block, the other warpgroup is already launching the next $\mathbf{Q}\mathbf{K}^\top$ multiplication. Then they swap roles.

So the execution looks roughly like this:

- Warpgroup A computes softmax for block $j$.
- Warpgroup B computes matrix multiplication for block $j+1$.
- Then they switch.

This is the heart of the asynchrony trick. Instead of a strict sequence of “matmul, then softmax, then next matmul,” FlashAttention-3 turns the kernel into a pipeline where different stages overlap.

## Why this matters: better hardware utilization

This design is not just elegant; it shows up in the numbers.

The paper reports that on an H100 SXM5 GPU, FlashAttention-3 reaches up to 740 TFLOPs/s in FP16, which is about 75% utilization of the GPU’s theoretical maximum for that setting. It is about 1.5–2.0$\times$ faster than FlashAttention-2 in the forward pass, and 1.5–1.75$\times$ faster in the backward pass.

That performance gain is not from changing the math. It comes from keeping more of the machine busy at the same time.

A good mental model is a factory with specialized stations. If one station is fast but keeps waiting for the next station to finish, the factory is underused. FlashAttention-3 rearranges the line so that loading materials, processing them, and packaging outputs can happen in parallel whenever possible.

## The practical complication: dependencies still exist

Of course, the GPU cannot literally do everything at once. Softmax depends on the output of the first matrix multiplication, and the second matrix multiplication depends on the softmax result. FlashAttention-3 does not remove those dependencies. Instead, it reorganizes the kernel so that dependencies for one block are hidden behind useful work on another block.

That is why the paper uses buffer staging and careful synchronization. It also explains why the implementation is more complex than the earlier FlashAttention versions. You need enough shared-memory staging, enough registers, and the right ordering of events so that the pipeline stays full without corrupting data.

The important point is that the design treats latency as something to hide, not something to eliminate.

## A note on FP8: the same philosophy, even harder

The paper also extends the idea to FP8. That part introduces a separate set of challenges around layout and numerical accuracy, especially because Hopper’s FP8 Tensor Cores have stricter operand layout requirements than FP16.

But the underlying pattern is the same: use the hardware more efficiently by structuring the computation to fit the machine’s strengths. For FP8, FlashAttention-3 combines asynchrony with block quantization and incoherent processing to reduce error while still gaining performance. The paper reports that this FP8 version reaches close to 1.2 PFLOPs/s and is 2.6$\times$ more accurate than a baseline FP8 attention setup with per-tensor quantization in the tested outlier-heavy setting.

## What to take away

FlashAttention-3 is a good example of modern GPU algorithm design. The fastest kernel is not necessarily the one with the fewest operations. It is often the one that understands how the hardware actually moves data and schedules work.

The main lesson from the paper is simple:

If the GPU has separate engines for memory movement, matrix multiplication, and other arithmetic, then the best attention kernel should let those engines work at the same time.

That is what FlashAttention-3 does with warp-specialization, TMA, Tensor Cores, and ping-pong execution. Instead of making the GPU wait at every stage, it turns attention into a pipeline. And on Hopper, that makes a big difference.

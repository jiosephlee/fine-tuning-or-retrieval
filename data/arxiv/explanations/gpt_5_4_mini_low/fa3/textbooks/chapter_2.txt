\title{A Textbook about the Paper: "FlashAttention-3: Fast and Accurate Attention with Asynchrony and Low-precision"}

Chapter 2: 2. Mathematical Foundations of Multi-Head Attention

# Definitions of $Q$, $K$, $V$, attention scores, probabilities, and outputs

At the heart of Transformer models is the attention mechanism, which combines three sequences of vectors: queries, keys, and values. In the paper, these are written as $\mathbf{Q}$, $\mathbf{K}$, and $\mathbf{V}$, each belonging to $\mathbb{R}^{N \times d}$ for a single head. Here $N$ is the sequence length and $d$ is the head dimension. You can think of each row of these matrices as one token representation within the head. The query matrix $\mathbf{Q}$ encodes what each token is looking for, the key matrix $\mathbf{K}$ encodes what each token offers for matching, and the value matrix $\mathbf{V}$ encodes the information that will actually be aggregated.

The attention computation proceeds in three steps. First, the query and key matrices are multiplied to form a score matrix
\[
\mathbf{S} = \alpha \mathbf{Q}\mathbf{K}^\top \in \mathbb{R}^{N \times N}.
\]
Each entry of $\mathbf{S}$ measures the compatibility between one query token and one key token. Second, these scores are normalized row-wise using softmax to obtain a probability matrix
\[
\mathbf{P} = \mathrm{softmax}(\mathbf{S}) \in \mathbb{R}^{N \times N}.
\]
Each row of $\mathbf{P}$ is a probability distribution over the keys for one query. Third, these probabilities are used to form the output
\[
\mathbf{O} = \mathbf{P}\mathbf{V} \in \mathbb{R}^{N \times d}.
\]
This final matrix $\mathbf{O}$ is the attention output, where each token receives a weighted sum of value vectors from the sequence.

The paper emphasizes that this is the standard mathematical form of attention, and that the challenge is not the definition itself but implementing it efficiently on a GPU without materializing large intermediate matrices in slow global memory.

# Scaled dot-product attention and the role of the factor $1/\sqrt{d}$

The score matrix is not simply $\mathbf{Q}\mathbf{K}^\top$ in the formulation used in the paper. It is scaled by a factor $\alpha$, and in practice one typically sets
\[
\alpha = \frac{1}{\sqrt{d}}.
\]
This scaling is part of the standard scaled dot-product attention formulation.

The reason for including this factor is tied to the dimension of the head. As $d$ grows, dot products between query and key vectors can become larger in magnitude. If these raw scores are too large, the softmax can become overly sharp, which is undesirable for both stability and learning behavior. Scaling by $1/\sqrt{d}$ keeps the values in a range where the softmax is better behaved. In the paper, this scaling is treated as part of the standard attention definition and carried through both the forward and backward formulas.

This detail matters because the FlashAttention algorithms preserve the exact attention computation, including the scaling factor, while changing only how the computation is scheduled and how intermediate results are handled.

# Row-wise softmax and numerical stabilization using row maxima

After computing the score matrix $\mathbf{S}$, attention applies softmax row-wise. That means each row of $\mathbf{S}$ is transformed into a row of probabilities whose entries sum to $1$. The row-wise nature is important because each query token independently chooses how to distribute its attention over all key tokens.

The paper also explicitly describes the standard numerical stabilization step used in attention: subtracting the row maximum before exponentiation. Concretely, for each row of $\mathbf{S}$, one subtracts
\[
\mathrm{rowmax}(\mathbf{S})
\]
from that row before applying the exponential inside the softmax. This does not change the resulting softmax probabilities, because softmax is invariant to adding or subtracting the same constant from all entries in a row. But it does prevent large positive scores from causing numerical overflow in the exponential.

This stabilization is not just a theoretical detail. It is central to the attention algorithm used in the paper and becomes especially important in FlashAttention-style implementations, where the softmax is computed block by block rather than all at once. In the paper’s algorithms, the quantities $m_i$ and $\ell_i$ track row-wise maxima and normalization factors incrementally so that the exact softmax result can be recovered without materializing the full score matrix.

# Extension from single-head to multi-head attention

The paper first defines attention for a single head, but actual Transformer layers use multi-head attention. In multi-head attention, there are multiple sets of query, key, and value projections, one for each head. Each head performs the same attention computation independently on its own projected inputs.

This independence is what makes the computation naturally parallelizable. The paper notes that the attention computation parallelizes across multiple heads and batches. That means the same formulas for $\mathbf{S}$, $\mathbf{P}$, and $\mathbf{O}$ are applied separately to each head, and then the results are combined in the full Transformer layer. From the perspective of the mathematical derivation, nothing changes in the equations themselves; multi-head attention is simply multiple copies of the same single-head operation running in parallel.

This matters for understanding the GPU implementation, because the algorithmic redesign in FlashAttention-3 is built around tiling and parallel execution over the batch size, the number of heads, and the query sequence length. The math of a single head provides the core computation, while the hardware implementation exploits the fact that many such heads exist and can be processed concurrently.

# Backward pass derivation: $\mathbf{dV}$, $\mathbf{dP}$, $\mathbf{dS}$, $\mathbf{dQ}$, and $\mathbf{dK}$

To train a Transformer, one must differentiate the attention computation. The paper introduces a scalar loss function $\phi$ and uses the notation $\mathbf{d}(-) = \partial \phi / \partial(-)$ for gradients. Given the output gradient $\mathbf{dO} \in \mathbb{R}^{N \times d}$, the backward pass computes gradients with respect to $\mathbf{Q}$, $\mathbf{K}$, and $\mathbf{V}$.

The first step is the gradient with respect to $\mathbf{V}$:
\[
\mathbf{dV} = \mathbf{P}^\top \mathbf{dO} \in \mathbb{R}^{N \times d}.
\]
This is the gradient flowing through the final matrix multiplication $\mathbf{O} = \mathbf{P}\mathbf{V}$.

Next, the gradient with respect to the probability matrix is
\[
\mathbf{dP} = \mathbf{dO}\mathbf{V}^\top \in \mathbb{R}^{N \times N}.
\]
This comes from differentiating the same product with respect to $\mathbf{P}$.

The gradient must then pass through softmax. The paper denotes this as
\[
\mathbf{dS} = \mathrm{dsoftmax}(\mathbf{dP}) \in \mathbb{R}^{N \times N}.
\]
This is the gradient of the score matrix after accounting for the row-wise softmax transformation. Once $\mathbf{dS}$ is known, the gradients with respect to queries and keys follow from the score definition:
\[
\mathbf{dQ} = \alpha \mathbf{dS}\mathbf{K} \in \mathbb{R}^{N \times d},
\]
\[
\mathbf{dK} = \alpha \mathbf{dS}^\top \mathbf{Q} \in \mathbb{R}^{N \times d}.
\]

These formulas show the structure of the backward pass very clearly. The backward computation uses the same kinds of matrix multiplications as the forward pass, along with the derivative of softmax. This is why the paper later focuses heavily on how to schedule GEMMs and softmax efficiently in both forward and backward execution.

# The Jacobian of softmax and row-wise $\mathrm{dsoftmax}$ computation

The paper gives the derivative of softmax for a vector explicitly. If
\[
p = \mathrm{softmax}(s),
\]
then the differential is
\[
\mathbf{d}s = (\mathrm{diag}(p) - pp^\top)\mathbf{d}p.
\]
This is the Jacobian of the softmax function applied to a vector. The term $\mathrm{diag}(p)$ captures the contribution of each output probability to its own input, while $pp^\top$ captures the coupling among the entries in the same softmax row.

In attention, softmax is applied row-wise to the score matrix $\mathbf{S}$. The paper therefore writes $\mathrm{dsoftmax}(\mathbf{dP})$ to mean that the same vector formula is applied independently to each row of $\mathbf{P}$ and $\mathbf{dP}$. This row-wise treatment matches the forward definition of softmax and preserves the structure of the attention computation.

The significance of this formula is that it explains why the backward pass is not just another matrix multiplication. The gradient must account for the normalization performed by softmax, and this introduces row-wise interactions within each row of the score matrix. In implementation terms, this is one reason why attention involves a mix of matrix multiplications and elementwise or row-wise operations, rather than only GEMMs.

# Where the computational and memory costs arise in forward and backward passes

The paper presents attention as a bottleneck because the score matrix $\mathbf{S} = \alpha \mathbf{Q}\mathbf{K}^\top$ has size $N \times N$. This quadratic dependence on sequence length is the main mathematical reason attention becomes expensive as context length grows. The forward pass must compute these pairwise similarities, normalize them, and then use them to mix the values. The backward pass repeats a similarly expensive pattern with additional gradient computations.

A key source of cost in standard attention is not only the arithmetic itself but also the memory traffic. In a standard GPU implementation, the intermediate matrices $\mathbf{S}$ and $\mathbf{P}$ may be materialized to high-bandwidth memory. Since these matrices are large, reading and writing them creates substantial overhead. The paper identifies this as the bottleneck that FlashAttention was originally designed to address, by fusing operations and keeping intermediate results on-chip whenever possible.

The backward pass is also expensive because it involves several matrix multiplications: $\mathbf{dV}$, $\mathbf{dP}$, $\mathbf{dQ}$, and $\mathbf{dK}$. The paper notes that the backward computation includes more matmuls than the forward pass, and that the total FLOP count is about $2.5$ times the forward-pass FLOPs in the benchmark accounting used in the paper, because the backward pass includes five matmuls compared with two in the forward pass, with recomputation. This highlights why attention remains a major performance target both during inference and training.

The mathematical structure therefore explains the engineering priorities in the rest of the paper. The same equations define both standard attention and FlashAttention-3, but the implementation strategy changes dramatically in order to reduce memory movement, overlap the matmul and softmax parts of the computation, and preserve numerical accuracy while using lower-precision arithmetic.

\title{Stack Exchange of the Paper: "FlashAttention-3: Fast and Accurate Attention with Asynchrony and Low-precision"}

### How does the 'local softmax' in FlashAttention give the same result as full softmax over the whole row?
Question:
I understand ordinary attention as computing one full row of scores, then applying
$\mathrm{softmax}$ to that full row. But FlashAttention processes keys/values in blocks, and the paper keeps running values $m_i$ and $\ell_i$ while updating $\mathbf{O}_i$ incrementally.

I am confused about why this blockwise procedure is still exactly equivalent to
$$\mathbf{P} = \mathrm{softmax}(\mathbf{Q}\mathbf{K}^\top).$$

In particular, why do the updates
$$m_i = \max(m_i^{\mathrm{old}}, \mathrm{rowmax}(\mathbf{S}_i^{(j)}))$$
and
$$\ell_i = \exp(m_i^{\mathrm{old}} - m_i)\ell_i + \mathrm{rowsum}(\widetilde{\mathbf{P}}_i^{(j)})$$
correctly maintain the normalization across blocks? An intuitive derivation would be very helpful.
Answer:
The key point is that FlashAttention is not approximating softmax block by block; it is computing the same row-wise softmax as if the whole row were materialized, but it does so in a numerically stable streaming form.

For a single query row, suppose the full score vector is split into blocks
$$s = [s^{(1)}, s^{(2)}, \dots, s^{(T_c)}].$$
If we define the usual softmax over the whole row, then for any entry $x$ in that row,
$$\mathrm{softmax}(s)_x = \frac{e^{x}}{\sum_t \sum_{y \in s^{(t)}} e^y}.$$
The only difficulty is that FlashAttention sees the blocks one at a time, so it cannot form the denominator all at once. The trick is to maintain two running quantities: the running maximum $m$ and the running sum of exponentials relative to that maximum, $\ell$.

After processing the first $j$ blocks, let
$$m^{(j)} = \max\{ \text{all scores seen so far} \}, \qquad \ell^{(j)} = \sum_{\text{seen }x} e^{x - m^{(j)}}.$$
These are exactly the quantities the paper stores in $m_i$ and $\ell_i$ row-wise. This is enough, because the true softmax denominator over the processed prefix is then
$$\sum_{\text{seen }x} e^x = e^{m^{(j)}} \ell^{(j)}.$$
So the pair $(m,\ell)$ is just a numerically stable reparameterization of the exact prefix sum.

Now suppose a new block $s^{(j)}$ arrives. If its row maximum is larger than the previous running max, the normalization must be changed to the new larger max. That is why the update is
$$m^{(j)} = \max\!\bigl(m^{(j-1)}, \mathrm{rowmax}(s^{(j)})\bigr).$$
If the max changes from $m^{(j-1)}$ to $m^{(j)}$, then every old exponential term must be rescaled from the old reference point to the new one:
$$e^{x - m^{(j)}} = e^{x - m^{(j-1)}} \, e^{m^{(j-1)} - m^{(j)}}.$$
Summing over all old entries gives
$$\sum_{\text{old }x} e^{x - m^{(j)}} = e^{m^{(j-1)} - m^{(j)}} \ell^{(j-1)}.$$
Then you add the contribution of the new block, already expressed relative to the new max:
$$\ell^{(j)} = e^{m^{(j-1)} - m^{(j)}} \ell^{(j-1)} + \sum_{x \in s^{(j)}} e^{x - m^{(j)}}.$$
This is exactly the paper’s update
$$\ell_i = \exp(m_i^{\mathrm{old}} - m_i)\ell_i + \mathrm{rowsum}(\widetilde{\mathbf{P}}_i^{(j)}).$$

So the recurrence is just the standard identity for combining two softmax-normalized chunks under a shared, updated maximum. Nothing is being approximated; the normalization is being rewritten in a way that is stable and updateable.

The same logic explains the output accumulation. The attention output for one row is
$$o = \frac{\sum_x e^x v_x}{\sum_x e^x}.$$
FlashAttention stores the numerator in the same shifted form. Whenever the max changes, the previously accumulated output must also be rescaled by $e^{m^{\mathrm{old}}-m}$ so that it remains expressed relative to the new normalization. After all blocks are processed, dividing by $\ell$ gives exactly the full softmax output.

Intuitively, you can think of it as streaming the row through a “moving reference level.” The reference level is the largest score seen so far. Every time a larger score appears, all previous exponentials are shifted down by the appropriate factor so that their relative weights remain correct. Because the same shift is applied consistently to both the numerator and denominator, the final ratio is identical to the full softmax over the entire row.

This is why the paper calls it “local softmax”: each block computes a softmax relative to the current local maximum, but the running $(m,\ell)$ state ensures that these local computations combine into the exact global softmax. The derivation is the same one used in earlier FlashAttention papers, and FlashAttention-3 keeps it unchanged; the new contribution in this paper is mainly in how that exact computation is overlapped with GEMMs and accelerated on Hopper hardware.

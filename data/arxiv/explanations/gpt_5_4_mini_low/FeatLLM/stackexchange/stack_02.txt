\title{Stack Exchange of the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

### What exactly is the difference between FeatLLM and just doing in-context classification with an LLM?
Question:
The paper contrasts FeatLLM with methods that serialize each test sample and ask the LLM to directly predict the label.

I understand that FeatLLM generates rules first and then trains a simple model on binary rule features, but I am still not seeing the conceptual difference clearly.

In both cases, the LLM sees the task description and a few demonstrations. So why is FeatLLM not just another form of in-context learning? Is the main novelty only computational efficiency at inference time, or is there also a different inductive bias because the LLM is forced to explain its decision criteria as rules?

An intuitive comparison of the two pipelines would help.
Answer:
The key difference is that FeatLLM uses the LLM only to *discover a representation*, whereas ordinary in-context classification uses the LLM to *make the prediction itself*.

In the baseline “serialize the table and ask the LLM for the label” pipeline, every test row is sent through the LLM, along with the task description and demonstrations, and the LLM directly outputs $y$. So the LLM is acting as the classifier at inference time. The model’s internal reasoning is implicit and disposable: you do not keep anything reusable from one sample to the next.

FeatLLM changes that by asking the LLM to extract explicit rules such as “if feature $a$ is high and feature $b$ is low, then class $k$ is likely.” Those rules are then turned into binary features, and a simple downstream model, in the paper a linear model with non-negative weights, learns how to combine them. After that, inference no longer goes through the LLM at all; it only evaluates the learned rules and the linear model. So the LLM is used once to engineer features, not repeatedly to classify each test example.

That means the conceptual difference is not just computational efficiency, although that is a major motivation in the paper. There is also a different inductive bias. Direct in-context classification asks the LLM to map raw serialized rows to labels in one step, which can be brittle in tabular settings and sensitive to prompt length. FeatLLM forces the LLM to externalize its decision criteria as rules, which makes the task more like “find useful human-readable predicates” than “predict the label now.” That explicit rule layer has two consequences the paper emphasizes: it filters out uninformative columns by focusing on criteria, and it gives a small supervised model a much simpler job, namely weighting a set of binary indicators. In other words, the LLM supplies prior knowledge, but the final decision boundary is learned in a more conventional and structured way.

So an intuitive way to think about it is this: in-context classification is “LLM as the doctor making the diagnosis,” while FeatLLM is “LLM as the expert who writes down diagnostic rules, and then a simpler model applies those rules to new patients.” The paper’s novelty is precisely this shift from end-to-end prediction to rule-based feature engineering, with lower inference cost as a practical benefit and a different, more explicit representation as the methodological one.

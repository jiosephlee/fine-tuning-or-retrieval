\title{Stack Exchange of the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

### Why does FeatLLM still count as few-shot learning if the LLM is using prior knowledge from pretraining?
Question:
I'm reading the paper "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning" and I'm confused about what exactly is meant by "few-shot" here.

The method only uses a small number of labeled samples from the target dataset, but the LLM itself already contains a lot of knowledge from pretraining. So is the improvement really coming from the few examples, or mostly from the pretrained knowledge inside GPT-3.5?

I think I may be mixing up two notions of learning:

1. learning from the target task using only $k$ labeled examples, and
2. exploiting a model that has already learned a lot before seeing the target task.

How should I interpret the contribution of FeatLLM in this setting? Is it fair to compare it to ordinary few-shot tabular models that do not have access to this kind of external prior knowledge?
Answer:
In this paper, “few-shot” refers to the amount of labeled data available from the *target tabular task*, not to whether the entire system has prior knowledge. So your distinction is exactly the right one: FeatLLM is few-shot in the sense that it learns the target classifier from only $k$ labeled examples, but it is *not* learning from scratch. It is deliberately leveraging the LLM’s pretrained world knowledge as an external source of inductive bias.

That is also how the paper frames it. The authors explicitly say that the LLM’s “rich prior knowledge can substitute the need for expert domain knowledge,” and that FeatLLM “extract[s] rules utilizing prior knowledge and information from few-shot samples.” In other words, the few labeled examples are used to adapt the pretrained knowledge to the current tabular task, not to build all the knowledge from scratch. This is the same broad idea behind many few-shot methods: the model is not empty-headed; it has some prior, and the question is how much task-specific supervision is needed on top of that prior.

A useful way to interpret FeatLLM is as a two-stage system. First, GPT-3.5 uses its pretrained knowledge plus the few labeled demonstrations in the prompt to generate candidate rules, such as threshold-style conditions that might separate the classes. Then those rules are converted into binary features, and a simple downstream model is trained on the small labeled dataset. So the “learning” from the few-shot target data happens in the downstream linear model, while the LLM provides a strong prior that proposes useful features. The paper is very explicit that the downstream inference uses only the simple predictive model, not the LLM, at test time.

So is the improvement coming “mostly from pretraining” or “mostly from the few examples”? The paper’s answer is: both matter, but in different roles. Their ablation study supports this: removing the feature descriptions or the reasoning instructions hurts especially in low-shot settings, which the authors interpret as showing that effective use of the LLM’s prior knowledge is crucial. At the same time, they also show that tuning the weights on the extracted features matters, and that this becomes more beneficial as the number of shots increases. So the few labeled examples are not just decoration; they are used to calibrate and weight the rules extracted from the pretrained model.

On fairness of comparison, the paper is comparing against ordinary few-shot tabular baselines on the same target-task labels, but with a different source of prior knowledge. That is fair if your question is “which method performs best given $k$ labeled examples and whatever prior each method is allowed to use?” because FeatLLM’s premise is precisely to exploit an LLM prior. It would not be fair only if you were comparing pure supervised few-shot tabular models against FeatLLM while pretending the LLM prior does not count. But the paper is not hiding that: its claim is that pretrained LLM knowledge is a legitimate resource for few-shot tabular learning, and that FeatLLM uses that resource more efficiently than baselines that either do end-to-end LLM inference or rely on conventional tabular learners without such an external prior.

So the clean interpretation is: FeatLLM is few-shot with respect to target labels, but pretrained with respect to general knowledge. The novelty is not that it learns without prior knowledge; it is that it turns the LLM’s prior knowledge into features that can be exploited with very little target supervision.

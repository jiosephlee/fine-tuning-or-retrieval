\title{Stack Exchange of the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

### How does bagging over features and instances avoid the prompt-length problem without losing too much information?
Question:
The paper says that FeatLLM uses bagging to select subsets of features or instances for each trial, and this helps when the full serialized table would exceed the LLM context window.

I understand how this reduces prompt size, but I do not understand why performance remains strong if each trial only sees a partial view of the data.

If an important rule depends on a combination of two features that land in different bagged subsets, then that rule can never be generated in that trial. Similarly, if the few sampled demonstrations are not representative, the rules could be unstable.

Is the idea simply that ensembling across many trials makes it likely that useful combinations appear somewhere? If so, is there any argument for how many trials $T$ are needed, or how the bagging fraction should scale with the number of original features $d$?
Answer:
What makes FeatLLM work is not that any single bagged prompt is guaranteed to “see everything,” but that the method treats each prompt as a weak, noisy view of the task and then relies on ensembling to recover the signal. The paper is quite explicit about this: bagging is introduced both to reduce prompt size and to create diverse rule sets, and the final prediction averages the probabilities from $T$ separate trials. In other words, a rule that depends on two features might indeed be missed in one subset, but it is not expected to be discovered in every subset. The hope is that, across many randomized trials, enough useful partial views will surface that the ensemble preserves the correct class signal.

Intuitively, this is the same logic as ordinary bagging in ensemble learning. A single weak learner may be unstable or incomplete, but if the errors are not perfectly correlated, averaging many such learners reduces variance and makes the overall predictor more robust. FeatLLM explicitly leans on this idea in the paper’s discussion of robustness: “the correct rules from other trials can compensate,” and “the ensemble of various weak learners created across multiple trials can nullify the impact of incomplete feature/instance coverage in individual trials.” So yes, your understanding is right: the method banks on the fact that useful combinations and useful rules will appear somewhere across the ensemble, even if no single trial is comprehensive.

There is also an important subtlety here. The paper is not trying to reconstruct an exact symbolic theory of the dataset from one prompt. It is trying to generate a set of binary rule-based features that are only approximately informative, and then let a small linear model learn which of those rules matter. That downstream weight learning acts as a filter: weak or spurious rules can get low weights and contribute little. This is why partial coverage is less damaging than it might seem. The model does not need every rule; it needs a sufficiently rich pool of candidate rules, many of which are redundant or overlapping, so that the linear stage and the ensemble can pick up the useful ones.

As for your question about how many trials $T$ are needed or how the bagging fraction should scale with $d$, the paper does not give a theoretical prescription. It treats both as empirical hyperparameters. The reported implementation uses $T=20$, and the hyperparameter analysis says performance improves as the number of ensembles increases, but begins to saturate around $20$. Likewise, for the number of rules per class, they choose $10$ as a practical trade-off between prompt length and performance. There is no scaling law in the paper such as $T = O(d)$ or a formula tying the bagging fraction to the number of features. The method is presented as an engineering solution rather than one with a formal sample-complexity guarantee.

So the short answer is: FeatLLM avoids the prompt-length problem by turning one too-large prompt into many smaller randomized prompts, and it avoids losing too much information by making those prompts complementary and then averaging their outputs. The paper’s justification is empirical and ensemble-based, not theoretical: diversity across trials plus downstream weighting is what preserves useful information.

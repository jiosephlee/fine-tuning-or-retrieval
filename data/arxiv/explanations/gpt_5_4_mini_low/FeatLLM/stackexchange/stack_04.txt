\title{Stack Exchange of the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

### Why is the logit defined as $\max(\mathbf{w}_k,0) \cdot \mathbf{z}_k^i$ instead of allowing negative weights?
Question:
The paper defines the class logit as

$$
\text{logit}_k^i = \max(\mathbf{w}_k,0) \cdot \mathbf{z}_k^i
$$

and says this ensures that LLM-generated features do not reduce the likelihood of a class.

I don't fully understand this design choice. In ordinary linear classifiers, negative weights can be useful because a feature can be evidence against a class. Here, if a rule for class $k$ is actually misleading, wouldn't a negative weight help the model correct for that? By forcing non-negative weights, aren't we throwing away potentially useful information?

Is the idea that rules generated "for class $k$" should only ever provide positive evidence for that class, and weak or bad rules should just get weight $0$ instead of a negative value? If so, is there any empirical or theoretical reason this is better than a standard unconstrained linear model?
Answer:
The key point is that this is not meant to be a general-purpose linear classifier in the usual sense; it is a very specific scoring model over rule-derived binary features, and the paper deliberately wants those features to behave like pieces of positive evidence for a class.

In \textsf{FeatLLM}, each class $k$ has a set of binary features $\mathbf{z}_k^i \in \{0,1\}^R$, where each coordinate says whether sample $i$ satisfies one of the LLM-generated rules for that class. The model then forms

$$
\text{logit}_k^i = \max(\mathbf{w}_k,0)\cdot \mathbf{z}_k^i.
$$

Because the rule features are constructed specifically “for class $k$,” the authors want them to act like votes in favor of that class. The non-negativity constraint makes each satisfied rule contribute $\ge 0$ to the class score, so a rule can increase the likelihood of class $k$, but it cannot perversely lower it. This matches the paper’s stated goal: “ensure that LLM-generated features do not reduce the likelihood of a class.”

Your intuition about standard linear models is correct in general: negative weights can be useful when a feature is evidence against a class. But that is not the interpretation the paper is using here. The LLM is already doing the hard work of generating class-specific rules, and the downstream linear model is only there to estimate how important each rule is. If a generated rule turns out to be misleading or noisy, the paper’s preferred outcome is not to give it a negative meaning, but to suppress it by driving its weight toward $0$. In other words, bad rules should be ignored rather than turned into “anti-evidence.”

That design choice also helps stability in the few-shot regime. With very little labeled data, allowing negative weights would make it easier for the model to overfit accidental correlations: a noisy rule might get a negative weight just because of a handful of examples, which would actively penalize the class score. The paper’s ablation supports this intuition: removing weight tuning worsens performance, and the discussion of feature quality says that low-relevance rules are filtered out after tuning, with weights below a threshold effectively discarded. So empirically, the positive constraint is being used as a regularizing inductive bias.

So yes, your reading is basically right: the intended semantics are “rules for class $k$ should only provide positive evidence,” and weak or wrong rules should be down-weighted to nearly zero. The benefit over an unconstrained linear model is not that it is more expressive, but that it is better matched to the rule-generation pipeline and more robust in the low-shot setting the paper targets.

\title{Stack Exchange of the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

### Why does the two-step reasoning instruction help avoid spurious correlations?
Question:
The prompt design asks the LLM to first infer general feature-task relationships from prior knowledge alone, and only afterward use the few-shot examples to derive rules.

The authors argue that this reduces reliance on irrelevant columns and spurious correlations. I can see the intuition, but I don't fully understand why this should work.

Could this first step also create problems? For example, if the LLM has a strong prior belief that some feature should matter, but in the current dataset it actually does not, then wouldn't the model be biased toward using that feature anyway?

So why is the ordering

1. prior knowledge first, then
2. fit rules to examples

better than letting the LLM jointly reason over both from the start? I'm looking for either an intuitive explanation or a more formal way to think about this prompt design.
Answer:
The key idea in the paper is not that the first step magically makes the LLM “correct,” but that it changes *what kind of errors* the model is likely to make.

In \textsf{FeatLLM}, the first step asks the LLM to think about the task and the features using prior knowledge only, before seeing the examples. This acts like a coarse filter: it encourages the model to form a broad hypothesis about which columns could plausibly matter for the target. Then, in the second step, the few-shot examples are used to turn that broad hypothesis into concrete rules. So the examples are not being interpreted from scratch over the entire feature set; they are interpreted through a smaller, more relevant set of candidate relationships. That matters in tabular few-shot learning because with very few labeled samples, a model can easily latch onto accidental patterns in irrelevant columns. The paper’s intuition is that once you let the LLM “anchor” on prior knowledge first, it is less likely to treat a random column as meaningful just because it happens to correlate with the label in a tiny sample.

Formally, you can think of the ordering as changing the effective hypothesis space. A joint prompt over examples and all features invites the LLM to search over a large space of possible feature-label relations, many of which are spurious in a low-shot regime. The two-step prompt biases the model toward hypotheses that are already semantically plausible from general knowledge, and only then asks it to fit the examples. This is exactly the kind of inductive bias that low-shot learning needs. The paper’s ablation supports this: removing the reasoning step hurts performance, and in the spurious-correlation experiment the authors report that only about $1\%$--$2\%$ of the extracted rules came from noisy columns.

Your concern is also valid: yes, the first step can introduce bias if the LLM’s prior is wrong. The paper explicitly acknowledges this broader risk in the broader-impact section, noting that the prior knowledge embedded in the LLM can dominate observed data and may contain societal biases or misinformation. They also observe that if extra columns come from closely related data, \textsf{FeatLLM} can still learn spurious or even causally wrong relationships. So the first step is not a guarantee of correctness; it is a tradeoff. It reduces overfitting to irrelevant columns, but it can also bias the model toward the LLM’s prior beliefs.

Why is the ordering still better than fully joint reasoning? Because in the few-shot tabular setting, the dominant failure mode is usually not “the prior is slightly wrong,” but “the model discovers a misleading correlation from too little data.” The two-step design deliberately puts a strong prior in front of the examples to prevent that. Then the second step and the downstream linear model can still correct some of the prior’s mistakes by filtering rules with low learned weights. In other words, the prompt design combines semantic prior knowledge with data-driven selection, rather than letting raw few-shot correlation search happen all at once. That is the central reason the paper claims it improves robustness to spurious correlations.

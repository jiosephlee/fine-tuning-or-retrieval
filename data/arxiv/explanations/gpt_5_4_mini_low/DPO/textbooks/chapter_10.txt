\title{A Textbook about the Paper: "Direct Preference Optimization: Your Language Model is Secretly a Reward Model"}

Chapter 10: 10. The DPO Training Pipeline in Practice

# Step 1: generate or obtain preference pairs

The starting point for Direct Preference Optimization is a dataset of human preferences over model outputs. In the paper’s formulation, each training example consists of a prompt $x$ and two candidate completions, one preferred and one dispreferred, written as $(x, y_w, y_l)$. The preferred completion is denoted $y_w$, and the dispreferred one is denoted $y_l$. The core idea is not to ask annotators to assign an absolute score to each answer, but instead to compare two answers and say which one is better for the prompt.

This preference data can be gathered directly by sampling multiple responses from a language model and asking humans to rank or choose between them. In the paper’s standard RLHF setup, the sampled responses come from a supervised fine-tuned reference model, $\pi^\text{SFT}$. For a prompt $x$, two answers $y_1$ and $y_2$ are drawn from that model, and a human labeler chooses the better one. The paper also notes that more general ranking models, such as Plackett-Luce, would work if more than two answers were available, but the main development uses pairwise comparisons through the Bradley-Terry model.

In practice, the paper emphasizes that preference datasets are often already available publicly, so the training pipeline does not necessarily require gathering new labels. The experiments reuse existing datasets for summarization and dialogue, and in the controlled sentiment setup the authors even generate preference pairs using a pretrained sentiment classifier to create a fully controlled evaluation environment. What matters for DPO is that the training data is a batch of comparisons of the form $(x, y_w, y_l)$, with a fixed dataset $\mathcal{D}$ used for offline learning.

# Step 2: choose a reference policy

The second step is choosing the reference policy $\pi_\text{ref}$. This model plays a central role in DPO because the objective is built around the ratio between the trained policy and a reference model. In the original RLHF pipeline, the reference policy is typically the SFT model, and the KL penalty in RL keeps the final policy from drifting too far from it. DPO keeps the same basic structure: the reference policy anchors the optimization and helps control how far the trained model moves.

When the original SFT model is available, the paper recommends using it directly as $\pi_\text{ref}$. This is the cleanest setting because the preference dataset was often collected from that same or a similar model, so the reference policy matches the data-collection policy closely. In the paper’s experiments, this is the case in the controlled sentiment and summarization settings, where the SFT model is available and is used as the reference.

When the original SFT model is not available, the paper proposes a surrogate strategy. In that case, $\pi_\text{ref}$ is initialized by maximizing the likelihood of the preferred completions alone, that is,
\[
\pi_\text{ref} = \arg\max_\pi \mathbb{E}_{x, y_w \sim \mathcal{D}} \left[\log \pi(y_w \mid x)\right].
\]
This surrogate reference model is not meant to reproduce the unknown original model perfectly. Rather, its purpose is to create a reasonable baseline policy that stays close to the distribution represented by the preference data. The paper uses this strategy in the single-turn dialogue setting, where no pre-trained SFT model is available.

# When the original SFT reference model is available

When the original SFT model is available, DPO becomes especially straightforward. The dataset of preferences was typically collected from completions sampled from that SFT model, so using the same model as $\pi_\text{ref}$ preserves the connection between data collection and training. In this case, the ratio $\pi_\theta(y \mid x) / \pi_\text{ref}(y \mid x)$ is interpreted relative to a reference policy that genuinely reflects the model that generated the comparison pairs.

This matters because the DPO objective is built to optimize preferences while staying tied to the reference distribution. If the reference model is the same one used for preference collection, then the training objective is aligned with the data-generating process assumed by the method. The paper uses this setup in the controlled sentiment experiment and the summarization experiment, where the SFT model is available and used as $\pi_\text{ref}$.

# When the original SFT model is unavailable

The paper also addresses the common case where the original supervised fine-tuned model is unavailable. This happens in the dialogue experiment, where the authors start from an off-the-shelf pretrained language model instead of an existing SFT reference. In such cases, DPO still works, but the reference policy has to be approximated.

The proposed workaround is to train a reference model on the preferred completions only. This is done by maximizing the likelihood of $(x, y_w)$ pairs from the preference dataset. The resulting surrogate reference model is then used in place of the unknown original $\pi^\text{SFT}$. The paper presents this as a practical way to mitigate the mismatch between the unavailable true reference distribution and the reference model actually used for DPO training.

This is an important practical point: DPO does not require the exact same original reference model that produced the data, but the closer the reference is to the data-collection policy, the more faithful the training setup is to the assumptions behind the method. The surrogate reference is therefore a pragmatic approximation rather than a theoretical necessity.

# Constructing a surrogate reference model by maximizing likelihood on preferred completions

The surrogate reference model is constructed with ordinary supervised learning. The training target is not the full preference pair, but only the chosen side of each comparison. In other words, the model is trained to assign high likelihood to the preferred completion $y_w$ conditioned on the prompt $x$. This is exactly the objective
\[
\arg\max_\pi \mathbb{E}_{x, y_w \sim \mathcal{D}} \left[\log \pi(y_w \mid x)\right].
\]

The paper’s reasoning is that this procedure gives a policy that is close to the support of the preferred data, and therefore a more sensible reference than using an unrelated pretrained language model. It is a way of reconstructing a usable baseline policy when the original SFT reference is missing. The goal is not to recover the original training pipeline perfectly, but to produce a policy that reduces distribution mismatch in the DPO objective.

This surrogate construction is especially useful in settings like single-turn dialogue, where the paper begins from a pretrained Pythia model and uses Preferred-FT to create the reference model before applying DPO. The method makes the training recipe portable to datasets where the exact historical reference model is not available.

# Mitigating distribution shift between data collection policy and training reference policy

A recurring concern in the paper is distribution shift between the policy that generated the preference data and the reference policy used during training. DPO uses the ratio between the learned policy and the reference policy, so if the reference is badly mismatched to the data-collection policy, the training signal may become less reliable. The paper explicitly frames the surrogate reference procedure as a way to mitigate this shift.

The intuition is simple. Preference data is only informative over the kinds of outputs that were actually sampled. If the reference policy is very different from that sampling policy, then the policy ratios used in DPO may not reflect the comparison data well. By initializing the reference model from preferred completions, the method tries to place the training objective on a more realistic footing.

This issue is especially relevant in the dialogue setting, where the paper notes that the preference data comes from a large language model of unknown origin. Since the true data-collection model is unavailable, a surrogate learned from preferred responses helps bring the training reference closer to the observed data distribution. In the paper’s language, this reduces the distribution shift between the “true reference distribution” and the $\pi_\text{ref}$ used by DPO.

# Step 3: optimize the DPO loss on the preference dataset

Once the preference dataset and reference policy are in place, training reduces to minimizing the DPO loss:
\[
\mathcal{L}_\text{DPO}(\pi_\theta; \pi_\text{ref}) = -\mathbb{E}_{(x, y_w, y_l)\sim \mathcal{D}}\left[\log \sigma \left(\beta \log \frac{\pi_{\theta}(y_w\mid x)}{\pi_\text{ref}(y_w\mid x)} - \beta \log \frac{\pi_{\theta}(y_l\mid x)}{\pi_\text{ref}(y_l\mid x)}\right)\right].
\]
This objective is simply a binary cross-entropy loss applied to the relative log probabilities of the preferred and dispreferred responses. The model is trained to increase the relative probability of $y_w$ over $y_l$ under $\pi_\theta$ compared with $\pi_\text{ref}$.

The paper emphasizes that this is a direct policy optimization step, not an RL loop. There is no explicit reward model to train first, and no sampling from the policy inside the optimization procedure. The policy network itself carries the implicit reward through the ratio $\log \pi_\theta(y \mid x) - \log \pi_\text{ref}(y \mid x)$, scaled by $\beta$. In effect, training is a classification problem over preference pairs.

The update has a useful interpretation. It increases the likelihood of preferred completions and decreases the likelihood of dispreferred ones, but it does not do so uniformly. Examples are weighted by how badly the current policy orders the pair. If the implicit reward estimate assigns too much value to the dispreferred completion, the example receives a stronger corrective update. This is the mechanism that the paper argues helps prevent the degeneration observed in a naive objective without this weighting.

# Sequence-level log probabilities in language models

A practical detail in DPO is that the objective uses the log probability of a whole completion, not just a token or a local action. For a language model, $\pi_\theta(y \mid x)$ is the probability assigned to the entire generated sequence $y$ given the prompt $x$. The DPO loss therefore compares the sequence-level likelihoods of the preferred and dispreferred responses.

This matters because the model is not being asked to judge partial fragments in isolation. Instead, each full response competes as a complete candidate continuation of the prompt. The ratio
\[
\frac{\pi_\theta(y_w \mid x)}{\pi_\text{ref}(y_w \mid x)}
\quad \text{versus} \quad
\frac{\pi_\theta(y_l \mid x)}{\pi_\text{ref}(y_l \mid x)}
\]
encodes how much more the current model favors the preferred response relative to the reference, compared with the dispreferred one. The paper’s gradient analysis shows that this is what drives learning: push up the preferred completion, push down the dispreferred completion, and weight the update by how incorrect the current ordering is.

Because the quantity is sequence-level, DPO is naturally compatible with standard language-model likelihood computation. The paper does not require specialized sequence sampling during training, which is one of the reasons the method is computationally lightweight.

# Hyperparameter beta and its practical interpretation

The parameter $\beta$ plays the role of a strength parameter for the KL constraint in the underlying RLHF objective. In the DPO formulation, it appears directly in the preference loss and scales the log-ratio terms. A larger $\beta$ means the objective places more emphasis on the difference between the policy and reference log probabilities, while a smaller $\beta$ makes the updates more conservative.

The paper interprets $\beta$ as controlling the strength of the constraint against drifting away from the reference model. This is why the same parameter appears in both the original RLHF objective and the DPO loss. The reference model anchors the policy, and $\beta$ governs how aggressively the policy is allowed to move relative to that anchor while learning from preferences.

In the experiments, the authors sweep over only a small set of $\beta$ values, and they note that DPO works well with almost no tuning. This practical ease contrasts with the careful hyperparameter management needed in RL-based methods such as PPO, where target KL values, reward normalization, and other choices can strongly affect stability and performance.

# Why DPO requires little hyperparameter tuning compared with PPO

A major practical claim of the paper is that DPO is far simpler to tune than PPO-based RLHF. PPO requires managing a reward model, an RL loop, and a KL regularizer, and the optimization can be sensitive to reward scale and variance. The paper argues that DPO avoids many of these complications because it turns the problem into a direct supervised learning objective over preferences.

The paper’s theoretical reparameterization removes the need for explicit reward normalization and value-function baselines. In the RLHF pipeline, the reward model often needs normalization to keep variance low, and the policy optimization step often requires additional machinery to stabilize training. DPO bypasses these issues by using the policy itself as the implicit reward model under a specific parameterization. As a result, there is no separate reward network to fit and no reinforcement learning procedure to tune.

Empirically, the paper reports that DPO performs well with minimal hyperparameter search. In the sentiment experiment, they do sweep a few values of $\beta$ and compare them to PPO target-KL settings and unlikelihood coefficients, but DPO still produces the strongest reward-KL frontier. In the summarization and dialogue experiments, DPO also performs strongly without extensive tuning. This is presented as part of the method’s main advantage: it reduces the barrier to training aligned models from preference data.

# Implementation simplicity relative to RLHF toolchains

One of the paper’s central practical messages is that DPO is much simpler to implement than a standard RLHF pipeline. Traditional RLHF requires at least two learned models, a reward model and a policy model, plus an RL optimization loop that samples responses during training. That makes the system more complex, more computationally demanding, and more fragile.

DPO removes the reward-model training phase and the RL phase as separate components. Instead, it uses a single preference-based objective that can be optimized with standard gradient-based learning, much like ordinary fine-tuning. Because the training loop operates directly on offline preference pairs, it does not require the system to sample from the language model during training. This is a major simplification relative to PPO-based methods, which typically depend on on-policy sampling and additional machinery for stabilization.

The paper presents this simplicity not as a tradeoff but as a consequence of a different parameterization of the same underlying preference problem. In other words, DPO is not introduced as a heuristic workaround; it is positioned as a direct solution to the same RLHF objective that prior methods were trying to optimize indirectly. That is why the authors claim DPO can be “stable, performant, and computationally lightweight” while retaining the benefits of preference learning.

\title{Blogs about the Paper: "Direct Preference Optimization: Your Language Model is Secretly a Reward Model"}

# Your Language Model Is Secretly a Reward Model: The Core Insight Behind DPO

Large language models are usually trained in two stages. First, they learn to predict text from huge unlabeled corpora. Then, if we want them to be more helpful, safer, or better aligned with human preferences, we often fine-tune them using RLHF: train a reward model from human comparisons, then optimize the language model against that reward with reinforcement learning.

The DPO paper asks a simple question: do we really need to separate these two steps? Its answer is no. The key insight is that a language model’s probabilities can be used to represent a reward model implicitly. Once you look at the problem this way, preference learning becomes a direct classification problem instead of a reinforcement learning problem.

## The usual RLHF setup

In standard RLHF, we start with a reference policy $\pi_{\text{ref}}$, usually a supervised fine-tuned model. We collect preference data of the form $(x, y_w, y_l)$, where for prompt $x$, humans prefer response $y_w$ over response $y_l$. A reward model $r_\phi(x, y)$ is trained to assign higher scores to preferred responses.

Then the policy is optimized with a KL penalty:

\[
\max_{\pi_\theta} \; \mathbb{E}_{x \sim \mathcal{D}, y \sim \pi_\theta(y \mid x)}\left[r_\phi(x, y)\right]
- \beta \, \mathbb{D}_{\text{KL}}\!\left[\pi_\theta(y \mid x)\,\|\,\pi_{\text{ref}}(y \mid x)\right].
\]

The KL term matters because it keeps the policy from drifting too far from the reference model. Without it, the model can collapse into weird or brittle behavior.

The problem is that this pipeline is cumbersome. It requires training a separate reward model, then running an RL algorithm such as PPO to optimize the policy. That adds instability, sampling overhead, and a lot of engineering complexity.

## The core DPO idea

DPO starts from a property of the KL-constrained RL objective: if you knew the reward function exactly, the optimal policy would have a closed form:

\[
\pi_r(y \mid x) = \frac{1}{Z(x)} \pi_{\text{ref}}(y \mid x) \exp\left(\frac{1}{\beta} r(x, y)\right).
\]

This says the optimal policy is just the reference policy, reweighted by an exponential of the reward.

Now rearrange that equation:

\[
r(x, y) = \beta \log \frac{\pi_r(y \mid x)}{\pi_{\text{ref}}(y \mid x)} + \beta \log Z(x).
\]

This is the key move. It tells us that, up to a prompt-dependent constant, reward can be written as the log-ratio between the policy and the reference model.

That means the policy itself can stand in for a reward model. If a response gets higher relative probability than the reference model assigns, it is implicitly treated as more rewarding.

## Why the reference model matters

The reference model is the anchor. It defines what “better” means relative to the original behavior of the model.

Without this anchor, just increasing probability on preferred responses would be too unconstrained. The model could improve on the training comparisons while drifting badly elsewhere. The reference policy keeps the optimization focused on changing the model only where the preferences say it should change.

In DPO, the policy does not just try to make preferred responses more likely. It tries to make them more likely relative to the reference model:

\[
\log \frac{\pi_\theta(y_w \mid x)}{\pi_{\text{ref}}(y_w \mid x)}
\quad \text{vs.} \quad
\log \frac{\pi_\theta(y_l \mid x)}{\pi_{\text{ref}}(y_l \mid x)}.
\]

So the model is trained to increase the relative log-probability of the preferred completion and decrease that of the dispreferred one.

## Turning preference learning into a binary classification loss

The Bradley-Terry preference model says that the probability humans prefer one response over another depends on the difference in their latent rewards:

\[
p^*(y_1 \succ y_2 \mid x) = \sigma\!\left(r^*(x, y_1) - r^*(x, y_2)\right).
\]

If we substitute the reward reparameterization above into this preference model, the partition function cancels out. That is the crucial simplification: we no longer need to estimate an explicit reward function or its normalization term.

Instead, we can directly train the policy with a binary cross-entropy loss:

\[
\mathcal{L}_{\text{DPO}}(\pi_\theta; \pi_{\text{ref}}) =
-\mathbb{E}_{(x, y_w, y_l)\sim \mathcal{D}}
\left[
\log \sigma\!\left(
\beta \log \frac{\pi_\theta(y_w \mid x)}{\pi_{\text{ref}}(y_w \mid x)}
-
\beta \log \frac{\pi_\theta(y_l \mid x)}{\pi_{\text{ref}}(y_l \mid x)}
\right)
\right].
\]

This loss says: make the preferred response more likely than the rejected one, but do it relative to the reference model.

## What the gradient is doing

Mechanically, the gradient has a very intuitive interpretation. It pushes up the probability of the preferred completion and pushes down the probability of the rejected completion.

But there is an important twist: examples get weighted by how wrong the model currently is. If the model already ranks the pair correctly, the update is smaller. If it badly misranks them, the update is stronger.

That dynamic weighting is part of why a naive “just increase preferred, decrease rejected” objective can behave poorly. DPO’s formulation avoids that degeneration by tying the update to the model’s current implicit reward estimate.

## Why this is equivalent in spirit to RLHF

The paper’s theoretical point is not that DPO invents a new objective. It is that DPO reparameterizes the same kind of KL-constrained preference optimization used in RLHF.

Under the Bradley-Terry preference model, and more generally under Plackett-Luce-style preference models, the learned reward is only defined up to an additive function of the prompt $x$. DPO exploits exactly this degree of freedom. It chooses a reward representation that makes the optimal policy analytically tractable.

So the model is not being trained to imitate preferences in some weaker sense. It is directly optimizing the same family of objectives that RLHF aims for, just without the explicit reward model and without the RL loop.

## Why this matters in practice

This reparameterization simplifies the whole pipeline:

- no separate reward model,
- no on-policy reinforcement learning loop,
- no sampling during training to optimize the reward,
- less tuning and less instability.

The paper reports that this simplicity does not come at the cost of performance. On sentiment control, summarization, and single-turn dialogue, DPO matches or improves on PPO-based RLHF, while being much easier to train.

## The big takeaway

DPO’s central insight is easy to state but powerful in effect: a language model can implicitly represent a reward model through the log-ratio between its own probabilities and those of a reference model.

That means preference learning does not have to be a two-stage process. If you have pairwise preferences, you can train the policy directly with a classification-style objective and still recover the same constrained optimization behavior that RLHF targets.

In short, DPO shows that the model policy and the reward model are not as separate as they first appear. The reward is already hidden in the policy’s probabilities. DPO just makes that structure explicit.

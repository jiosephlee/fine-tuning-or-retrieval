\title{A Textbook about the Paper: "QLoRA: Efficient Finetuning of Quantized LLMs"}

Chapter 2: 2. Foundations: Quantization, LoRA, and Training Memory

# What quantization is and why lower-bit representations save memory

Quantization is the process of representing numbers with fewer bits than before. In the context of large language models, this means taking values that might normally be stored as 32-bit or 16-bit floating point numbers and converting them into a lower-precision format such as 8-bit or 4-bit representations. The reason this matters is simple: if each number uses fewer bits, the model occupies less memory. For large models, that reduction can be dramatic, because the weights contain billions of values. The paper emphasizes that memory savings are what make large-model finetuning feasible on a single GPU.

The key idea is not just to compress numbers arbitrarily, but to do so in a way that preserves as much useful information as possible. If the quantized numbers still behave similarly to the original values, then the model can remain effective even after compression. This is especially important for finetuning, where the model must still support learning rather than only inference. The paper’s central challenge is to make low-bit storage compatible with training without losing performance.

# Standard tensor quantization with scaling constants

The paper explains standard quantization by starting with a tensor $\mathbf{X}^{\text{FP32}}$ and mapping it into a low-bit integer tensor. A typical example is quantizing into Int8, whose range is $[-127,127]$. To use that range well, the tensor is first rescaled by dividing by its absolute maximum value. This produces a quantization constant, or scale, often written as $c$. The quantized tensor is then computed by rounding the scaled values:
\[
\mathbf{X}^{\text{Int8}} = \text{round}\left( \frac{127}{\text{absmax}(\mathbf{X}^{\text{FP32}})}\mathbf{X}^{\text{FP32}} \right)
\]
or equivalently as $\text{round}(c^{\text{FP32}}\cdot \mathbf{X}^{\text{FP32}})$.

This scaling constant is essential because it adapts the fixed low-bit numeric range to the actual values in the tensor. Without rescaling, the same low-bit format would be too narrow for some tensors and too coarse for others. In other words, the scale is what makes quantization practical: it ensures the limited set of representable values is used efficiently.

The paper also notes that quantization is commonly performed block-wise rather than over the whole tensor at once. That difference is crucial because it addresses a major weakness of global quantization: some values can be so large that they distort the scale for the entire tensor. Block-wise quantization solves this by letting each region of the tensor use its own scale.

# Dequantization and its role during computation

Quantization alone is not enough for training or even for many computations. At some point, the low-bit values must be converted back into a higher-precision form so matrix multiplications and other operations can be performed. This reversal is called dequantization. In the paper’s notation, if $\mathbf{X}^{\text{Int8}}$ was created using a scale $c^{\text{FP32}}$, then dequantization reconstructs the tensor approximately by
\[
\text{dequant}(c^{\text{FP32}}, \mathbf{X}^{\text{Int8}}) = \frac{\mathbf{X}^{\text{Int8}}}{c^{\text{FP32}}}.
\]

The important point is that dequantization restores the tensor to the computation format used by the model. In QLoRA, storage and computation are separated: the weights are stored in a low-bit format, but when the model actually performs a forward or backward pass, those weights are dequantized into BFloat16. This means the model can enjoy the memory savings of low-bit storage while still doing arithmetic in a higher-precision format that is suitable for training.

This separation between storage and computation is one of the paper’s central design choices. It allows the base model to remain frozen in quantized form while the trainable adapter parameters operate in 16-bit precision. The low-precision weights are not directly updated, but they still participate in computation through dequantization.

# The problem of outliers in global quantization

A central difficulty in quantization is the presence of outliers. If a tensor contains one or a few unusually large values, then global scaling based on the full tensor’s absolute maximum will stretch the low-bit range to accommodate those outliers. The result is that most ordinary values are squeezed into a smaller portion of the available quantization bins. Some bins may be underused, and precision is wasted on rare extreme values instead of on the values that occur most often.

The paper describes this as a problem of poor bin utilization. When outliers dominate the scale, the quantized representation becomes less faithful to the bulk of the tensor. This is especially problematic for neural network weights, where one wants to preserve the distribution of typical values, not just the rare extremes. That is why global quantization is often insufficient for high-fidelity compression.

The paper’s response to this issue is to break tensors into blocks and quantize each block independently. Doing so reduces the chance that one outlier contaminates the scale for the entire tensor. It is a more localized and therefore more accurate way to compress the weights.

# Block-wise k-bit quantization and per-block scaling

Block-wise quantization works by splitting a tensor into contiguous blocks of size $B$ and quantizing each block separately. If the input tensor is $\mathbf{X}\in \mathbb{R}^{b\times h}$, it is flattened and divided into $n = (b\times h)/B$ blocks. Each block gets its own quantization constant $c_i$, and each block is quantized using the same low-bit scheme, but with its own local scale.

This approach is important because it preserves more detail. Each block is normalized based on its own values rather than on the values of the entire tensor. As a result, a large outlier in one block does not reduce precision everywhere else. The paper uses this idea as a basic building block for later methods, including the 4-bit quantization used in QLoRA.

The tradeoff is that using more blocks means storing more quantization constants. Smaller blocks improve precision but increase overhead, because every block needs its own scale. This overhead becomes significant at very low bit widths such as 4-bit quantization. The paper later introduces Double Quantization specifically to reduce that cost.

# LoRA as parameter-efficient finetuning

Low-Rank Adapters, or LoRA, are the second major ingredient needed to understand QLoRA. LoRA is a finetuning method that avoids updating all of a model’s parameters. Instead, the pretrained model weights stay fixed, and only a small set of additional trainable parameters called adapters are updated. This makes finetuning much cheaper in memory than full-model training.

The key intuition is that the adapter learns a correction to the original model’s computation. Rather than changing the full weight matrix directly, LoRA adds a low-rank update alongside it. The pretrained model remains intact, and the adapter learns just enough extra structure to adapt the model to a new task. This is why LoRA is called parameter-efficient: it aims to achieve useful finetuning behavior while changing only a small fraction of the model’s parameters.

In the paper, this is especially important because the LoRA parameters are the only ones trained during QLoRA. The quantized base model is frozen. That means the optimization problem is much smaller than full finetuning, but the model can still learn task-specific behavior through the adapters.

# The LoRA update equation and low-rank factorization

The paper gives LoRA as an additive modification to a linear projection. If the original projection is
\[
\mathbf{X}\mathbf{W} = \mathbf{Y},
\]
then LoRA changes it to
\[
\mathbf{Y} = \mathbf{X}\mathbf{W} + s\mathbf{X}\mathbf{L}_1\mathbf{L}_2,
\]
where $\mathbf{L}_1\in \mathbb{R}^{h\times r}$ and $\mathbf{L}_2\in \mathbb{R}^{r\times o}$, and $s$ is a scalar.

This expression shows the key low-rank structure. Instead of learning one large matrix update directly, LoRA learns two smaller matrices whose product forms a rank-$r$ update. Because $r$ is much smaller than the full hidden size, the number of trainable parameters is drastically reduced. The adapter therefore adds only a small amount of memory compared to the original dense weight matrix.

The low-rank decomposition is the reason LoRA is memory efficient. It compresses the space of possible updates, which is a constraint but also a benefit: the model can still learn meaningful adaptations while avoiding the cost of full-rank training. In QLoRA, this mechanism is used on top of a quantized base model.

# Frozen base weights versus trainable adapter weights

One of the most important distinctions in the paper is between frozen base weights and trainable adapter weights. In QLoRA, the pretrained model weights are quantized and kept fixed. They are not directly updated during optimization. Instead, gradients are backpropagated through the quantized weights to the adapter parameters, which are the actual trainable components.

This design means the base model functions as a fixed computational backbone. The adapters provide the flexibility needed for finetuning without requiring the full model to be stored in high precision or updated in memory. Because the adapters are small, the training process becomes much more feasible on limited hardware.

The paper also points out that, during backpropagation, the gradients needed for the adapters still pass through the frozen base model. So even though the base weights are not trainable, they remain part of the computational graph. This is why QLoRA must still dequantize the frozen weights during forward and backward passes. The weights are frozen for optimization, not removed from computation.

# Why LoRA parameters are not the main source of memory usage

A common assumption about parameter-efficient finetuning is that the trainable parameters must be the main memory bottleneck. The paper shows that this is not true for LoRA-based training of large language models. Instead, most memory is consumed by activation gradients, not by the LoRA weights themselves.

The paper gives a concrete example: for a 7B LLaMA model trained on FLAN v2 with batch size 1, LoRA weights corresponding to about $0.2\%$ of the original model use only 26 MB, while LoRA input gradients use 567 MB. With gradient checkpointing, the input gradients drop to an average of 18 MB per sequence, but they are still a significant part of the memory budget. By comparison, the 4-bit base model itself uses 5,048 MB.

This comparison makes an important point: shrinking the LoRA parameter set further provides only limited memory benefit. The dominant memory terms are elsewhere. That means one can add more adapters without dramatically increasing the total training memory, which becomes crucial for recovering the performance of full finetuning.

# Activation gradients, gradient checkpointing, and memory tradeoffs

The paper emphasizes that activation gradients are a major source of memory use during training. When a sequence is passed through the model, intermediate activations must be stored so that gradients can later be computed. For long sequences or large models, this storage can become expensive. Gradient checkpointing helps by reducing the amount of stored activation data, trading extra computation for lower memory use.

Even with checkpointing, however, memory spikes can still occur, especially when processing mini-batches with long sequence lengths. These spikes are especially problematic on a single GPU, where one sudden increase in memory demand can cause an out-of-memory error. The paper introduces Paged Optimizers to address this specific issue by allowing optimizer states to spill into CPU memory when necessary and then return to GPU memory when needed.

The broader lesson is that finetuning memory is not determined only by the size of the trainable parameters. It depends heavily on temporary training-time objects such as activations, gradients, and optimizer states. QLoRA is designed around this fact, which is why it combines quantization, LoRA, and memory-management techniques rather than relying on a single trick.

# Why adding more adapters can improve performance with limited extra memory

Because LoRA parameters are a relatively small part of the memory footprint, the paper argues that one can afford to use more adapters without greatly increasing total memory usage. This matters because the default LoRA setup, which applies adapters only to certain attention projections, is not sufficient to match full finetuning performance in the paper’s experiments. To recover that performance, the paper finds that adapters need to be added more broadly, including to all linear transformer block layers.

This is a central insight of the chapter: parameter efficiency does not mean using as few adapters as possible. In fact, if the adapters are too limited, the model may fail to match the performance of full finetuning. Since the adapters themselves are cheap compared to activation gradients and the frozen base model, it is often better to increase adapter coverage rather than to minimize adapter count aggressively.

The paper therefore treats LoRA not merely as a way to save memory, but as a flexible mechanism whose memory cost is low enough to allow a stronger finetuning configuration. In QLoRA, this makes it possible to combine a frozen 4-bit base model with enough trainable capacity to recover full 16-bit performance.

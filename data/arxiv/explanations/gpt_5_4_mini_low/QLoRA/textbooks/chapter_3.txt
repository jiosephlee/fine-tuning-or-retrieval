\title{A Textbook about the Paper: "QLoRA: Efficient Finetuning of Quantized LLMs"}

Chapter 3: 3. The QLoRA Framework: Finetuning Quantized Models

# The design principle of separating storage precision from compute precision

The central systems idea behind QLoRA is that a model does not need to keep all of its weights in high precision at all times in order to be trained effectively. Instead, QLoRA separates the precision used to store the pretrained base model from the precision used to carry out computation. This distinction is what makes the method efficient. The base model is stored in 4-bit form, which dramatically reduces memory usage, but whenever those weights are used in matrix multiplications, they are temporarily converted to a higher-precision computation format, namely BF16. In other words, QLoRA treats the compressed model as a storage format rather than as the format in which learning happens.

This design is important because the paper’s goal is not just to compress a model for inference, but to finetune a large model under severe memory constraints without losing the behavior of a full 16-bit finetuning run. The strategy is to keep the pretrained weights frozen in their compressed representation while learning a much smaller set of adapter parameters. The quantized weights still participate in forward and backward computation, but only as a fixed backbone through which gradients flow.

# 4-bit storage and BF16 computation in QLoRA

QLoRA uses two data types with different roles. The storage data type is usually 4-bit, and in the paper the preferred choice is 4-bit NormalFloat, or NF4. The computation data type is BF16. This means the model weights are kept in 4-bit form in memory, but when a layer is executed, the relevant weights are dequantized into BF16 and used in BF16 matrix multiplications. The paper emphasizes that this is not a 4-bit computation method; it is a 4-bit storage method with BF16 arithmetic.

This separation is the key to understanding how QLoRA can support training. The quantized representation keeps the memory footprint small, while BF16 computation preserves the numerical quality needed for stable forward and backward passes. The paper presents QLoRA as a way to get the memory savings of quantization without the usual training-time degradation associated with low-precision weights. The quantized model is therefore not treated as the final computation object, but as compact storage that is expanded only when necessary.

# Dequantizing weights on the fly during forward and backward passes

In QLoRA, weights are dequantized on the fly whenever they are needed for computation. During the forward pass, a quantized weight tensor is converted from its stored 4-bit representation into BF16, and the layer output is computed using BF16 matrix multiplication. The paper’s formal definition shows this explicitly: the base model contribution to the output is produced by applying a dequantization operation to the quantized weights and then multiplying the input by the resulting BF16 weights.

The same idea applies during the backward pass. Although the stored weights are 4-bit, the gradients needed for the adapter parameters depend on the computation performed through the base model. So QLoRA dequantizes the base weights during backpropagation as well, using the BF16 version of the weights to compute the derivatives required for the adapter updates. This means the quantized weights must be accessible to the computational graph, but they are never modified themselves. They act as a frozen reference model whose role is to provide the pretrained behavior through which gradients are routed.

# Backpropagation through quantized weights without updating them

A subtle but important feature of QLoRA is that gradients do pass through the quantized base model, but those gradients are not used to update the base model weights. Instead, the gradients flow through the frozen quantized weights into the LoRA adapter parameters. This makes QLoRA different from full finetuning, where all model parameters are updated, and also different from ordinary inference-only quantization methods, which do not support training at all.

The paper describes this as backpropagating gradients through a frozen 4-bit quantized pretrained language model into Low Rank Adapters. In practice, the base model serves as a fixed computation path, and the adapters are the trainable components. This setup allows the pretrained model to retain its original knowledge while the adapters learn task-specific changes. The base model is therefore not optimized directly; it is used to shape the gradients that the adapters receive.

# Which gradients are needed and which are not

QLoRA is efficient because it only requires the gradients that matter for the adapter parameters. The paper makes the distinction very clearly: for parameter updates, the gradients with respect to the adapter weights, $\frac{\partial E}{\partial \mathbf{L}_i}$, are needed. The gradients with respect to the 4-bit base weights, $\frac{\partial E}{\partial \mathbf{W}}$, are not needed, since the base weights remain frozen.

This is one of the most important memory-saving features of the method. Full finetuning would require maintaining optimizer states and gradients for every weight in the model, which is extremely expensive for very large networks. QLoRA avoids this by only learning the small LoRA parameter set. At the same time, computing the adapter gradients still requires the base model to participate in the backward computation, because the adapter updates depend on the frozen model’s activations and linear transformations. So the base model must be involved in differentiation, but not in parameter storage or updates.

# How QLoRA differs from full finetuning

QLoRA differs from full finetuning in both what is stored and what is trained. In full finetuning, all model parameters are kept in high precision and updated during training. This requires enormous memory, especially for large models such as LLaMA 65B. The paper notes that regular 16-bit finetuning of such a model requires more than 780 GB of GPU memory, which is far beyond what a single GPU can hold.

In QLoRA, by contrast, the base model is quantized to 4-bit and frozen, and only the LoRA adapters are trained in BF16. This reduces memory usage drastically while still allowing the model to adapt to new tasks. The paper reports that this can bring the average memory required to finetune a 65B model down to under 48 GB, without degrading runtime or predictive performance relative to a 16-bit fully finetuned baseline. So the difference is not merely one of compression; it is a different optimization strategy in which the large pretrained model provides a fixed foundation and the learned adaptation happens in a small, trainable subspace.

# How QLoRA differs from standard LoRA finetuning

QLoRA builds on LoRA, but it is not the same as standard LoRA finetuning. Standard LoRA keeps the pretrained base model in its original precision and adds low-rank adapter matrices to selected layers. QLoRA adds the extra step of quantizing the frozen base model to 4-bit. In this sense, QLoRA combines parameter-efficient finetuning with aggressive model compression.

The paper also shows that standard LoRA practice is not enough to recover full finetuning performance in the settings they study unless it is carefully tuned. Specifically, using LoRA only on the query and value projection matrices is not sufficient to replicate full finetuning performance for large base models. The authors find that LoRA adapters need to be applied to all linear transformer block layers to match full finetuning performance. QLoRA therefore differs from standard LoRA not only because of quantization, but also because of the paper’s more comprehensive adapter placement strategy, which is designed to preserve accuracy while still keeping memory use low.

# Why QLoRA can preserve performance while drastically lowering memory usage

QLoRA preserves performance because the method avoids throwing away the information that matters most for downstream adaptation. The pretrained model remains intact in frozen form, and learning is shifted into the adapters. The quantized base model is not retrained from scratch; it provides the pretrained structure, and the adapters learn the task-specific adjustments. The paper’s experiments show that, with the right quantization scheme and adapter configuration, 4-bit QLoRA can match 16-bit full finetuning and 16-bit LoRA performance on the tasks they study.

The memory savings come from several places at once. First, storing the base model in 4-bit reduces the dominant memory cost of the pretrained weights. Second, the LoRA adapters are small compared to the full model, so training only those parameters keeps the parameter memory low. Third, because the adapters are small, the optimizer state associated with them is also much smaller than it would be in full finetuning. The paper notes that activation gradients can still be a significant memory cost, which is why gradient checkpointing and paged optimizers matter, but the key point is that the massive memory burden of training all model weights is removed.

The result is a training setup in which large pretrained models become finetunable on a single GPU. QLoRA’s core systems insight is that high-quality learning does not require high-precision storage of all model parameters. By freezing a quantized backbone and training a compact BF16 adapter module, the method achieves a practical compromise between efficiency and performance, which is the foundation for all of the paper’s later experimental results.

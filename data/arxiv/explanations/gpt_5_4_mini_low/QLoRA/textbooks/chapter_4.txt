\title{A Textbook about the Paper: "QLoRA: Efficient Finetuning of Quantized LLMs"}

Chapter 4: 4. NF4: An Information-Theoretically Motivated 4-Bit Data Type

# Why pretrained neural network weights are approximately normally distributed

The paper’s motivation for NormalFloat4, or NF4, begins with an empirical observation about pretrained neural network weights: they are usually zero-centered and approximately normally distributed, with some standard deviation $\sigma$. This matters because quantization is not just about reducing the number of bits; it is also about choosing a low-bit representation whose values match the shape of the data as well as possible. If the data has a strong distributional pattern, then a data type designed around that pattern can use its limited bins more effectively.

The paper treats this approximate normality as the key structural property that makes NF4 possible. Rather than assuming that weights are uniformly spread out or that they should be handled by a generic low-bit format, the authors use the fact that pretrained weights cluster around zero in a bell-shaped way. This allows the quantizer to be built around a theoretical normal distribution and then adapted to the actual weight tensor through rescaling.

# Quantile quantization and equal-mass bins

NF4 builds on the idea of quantile quantization. In quantile quantization, the bins are chosen so that each bin contains the same expected number of values from the input distribution. That is a very natural way to use a limited number of discrete values: instead of spending many bins on rare parts of the distribution and few bins on common parts, the quantizer allocates representation capacity evenly across probability mass.

The paper describes quantile quantization as information-theoretically optimal in the sense that it equalizes the number of values assigned to each quantization bin. If the input distribution is known, then placing bin boundaries by quantiles ensures that the bins are used efficiently. This is exactly the intuition behind NF4: if pretrained weights behave like samples from a normal distribution, then the best 4-bit codebook should reflect the quantiles of that normal distribution rather than a generic fixed spacing.

# Why empirical quantile estimation is expensive and error-prone

Although quantile quantization is attractive in principle, the paper emphasizes a practical obstacle: estimating quantiles from real tensors is expensive. Computing accurate quantiles generally requires a nontrivial amount of work, and if the quantile estimation is approximated, the approximation itself can introduce errors. The paper specifically notes that fast quantile approximation algorithms can be used, but these approximations can produce large quantization errors for outliers, which are often the most important values.

This is a crucial point in the paper’s argument. The authors are not merely saying that quantiles are theoretically nice; they are also showing why a direct empirical approach is inconvenient for training large models. If one had to estimate quantiles accurately for every tensor block, the overhead would undermine the simplicity and efficiency that quantization is supposed to provide. So the paper looks for a way to preserve the benefits of quantile quantization while avoiding the cost and instability of empirical estimation.

# Using a theoretical normal distribution to define quantization bins

The paper’s solution is to avoid estimating quantiles from each tensor whenever possible by using a theoretical normal distribution as the reference distribution. Since the pretrained weights are already approximately normal, the authors argue that all weights can be transformed into a single fixed distribution by scaling them into a standard range. Once the distributional shape is fixed, the quantiles of that theoretical distribution can be computed once and reused.

The paper’s logic is that if the weights are normalized so that their distribution matches the shape expected by the data type, then quantization can be performed using a codebook derived from that shape. In this way, the quantizer is no longer depending on expensive, noisy empirical quantile estimation for every use. Instead, it uses a theoretically determined set of values that is well matched to normal data.

# Constructing NF4 from standard normal quantiles

NF4 is constructed by first taking the standard normal distribution $N(0,1)$ and estimating the $2^k+1$ quantiles needed to define a $k$-bit quantile quantization scheme. The paper gives the formula

$$
q_i = \frac{1}{2}\left( Q_X\left(\frac{i}{2^k+1}\right) + Q_X\left(\frac{i+1}{2^k+1}\right)\right),
$$

where $Q_X(\cdot)$ is the quantile function of the standard normal distribution. These values define the discrete levels of the data type. For NF4, the relevant case is $k=4$, so the data type has 16 representable values.

The conceptual point is that NF4 is not an arbitrary 4-bit format. Its representable values are chosen from the quantiles of a normal distribution so that each code corresponds to roughly equal probability mass under that distribution. That is why the paper calls it “NormalFloat”: it is a floating-point-like low-bit format, but one whose values are tailored to normal data.

# Normalization into the $[-1, 1]$ range

To make the quantization work in practice, the paper normalizes both the data type values and the input weight tensor into the range $[-1,1]$. The weights are rescaled using their absolute maximum so that they fit into the same interval as the NF4 codebook. This makes the quantization procedure analogous to other block-wise quantization schemes: the tensor is scaled to the target range, quantized, and later dequantized when needed.

This normalization step is important because the NF4 values are derived from a fixed theoretical distribution, but actual weight tensors may have different standard deviations. By rescaling the weights into the target range, the paper aligns the tensor’s distribution with the codebook’s range. In effect, the quantizer handles shape through the normal-based codebook and handles scale through the quantization constant.

# The importance of representing zero exactly

The paper points out a subtle but important issue: a symmetric $k$-bit quantization scheme based directly on quantiles does not necessarily have an exact representation of zero. That is a problem because zero-valued elements are common and should ideally be represented without error. This is especially important for padding and other zero-valued elements, which the paper explicitly mentions.

If zero cannot be represented exactly, then even values that should be perfectly preserved may acquire quantization error. In a low-bit format, where every representable value is precious, the inability to encode zero cleanly is a meaningful drawback. The authors therefore modify the construction so that zero is included as an exact discrete value.

# Asymmetric construction to preserve a zero point

To ensure an exact zero point while still using all $2^k$ values, the paper makes NF4 asymmetric. Instead of splitting the codebook evenly in a symmetric way, it constructs separate quantile sets for the negative and positive sides: $2^{k-1}$ values for the negative part and $2^{k-1}+1$ values for the positive part. The two sets are then merged, and one of the duplicate zeros is removed.

This asymmetry is not introduced because the underlying distribution is asymmetric. Rather, it is a practical design choice that preserves zero exactly while still allocating all available codes. The result is a codebook that still reflects a zero-centered normal distribution but also respects the operational need for exact zero representation.

# Why NF4 is information-theoretically optimal for zero-centered normal data

The paper describes NF4 as information-theoretically optimal for zero-centered normally distributed data because it assigns an equal expected number of values to each quantization bin under that distribution. In other words, if the weights truly follow a normal distribution, then the quantization bins are matched to the probability mass of the data rather than to an arbitrary geometric spacing. That is the core meaning of optimality here.

This claim is grounded in the paper’s quantile-based construction. By deriving the codebook from the normal distribution itself, NF4 makes the best possible use of the limited 4-bit representation for that assumed data shape. The authors emphasize that this is not merely theoretically elegant: it also leads to better empirical behavior than the alternative 4-bit formats they test.

# Comparing NF4 to FP4 and Int4 conceptually

The paper compares NF4 conceptually against 4-bit Floating Point and 4-bit Integers. The key distinction is that FP4 and Int4 are generic numerical formats, whereas NF4 is tailored to the distribution of pretrained model weights. Generic low-bit formats do not explicitly account for the fact that weights are concentrated near zero in a normal-like shape, so their bins are not aligned as efficiently with the data.

The paper reports that NF4 yields better performance than FP4 and Int4 in its experiments. The conceptual reason is straightforward: if the quantization bins are chosen to match the actual distribution of the weights, then less information is wasted. More of the representational capacity is devoted to where the weights actually lie, which should reduce quantization error and preserve model quality better after quantization.

# Expected benefits of NF4 for large language model weights

Within the paper’s broader QLoRA framework, the expected advantage of NF4 is that it enables 4-bit storage of pretrained LLM weights while preserving the performance needed for finetuning. The paper’s experiments show that NF4, combined with double quantization, recovers the performance of 16-bit finetuning in the tested settings. That makes NF4 a key ingredient in the claim that 4-bit finetuning can work without degradation.

The deeper implication is that the base model can be stored in far less memory while still supporting accurate finetuning through LoRA adapters. Because large language models have many weights and because those weights are approximately normal, a codebook designed specifically for that distribution offers a practical way to compress the model without destroying the information needed for training. In the paper’s results, this is what makes large-scale finetuning on a single GPU possible.

\title{Blogs about the Paper: "xLSTM: Extended Long Short-Term Memory"}

# sLSTM vs. mLSTM: Two New Kinds of Memory for Long-Context AI

Long Short-Term Memory networks, or LSTMs, were designed to solve one of the classic problems in recurrent neural networks: how to remember useful information over long sequences without gradients disappearing. The xLSTM paper revisits that idea with a modern twist. Instead of treating LSTM as a fixed legacy architecture, it introduces two new memory mechanisms: sLSTM and mLSTM.

These two variants solve different bottlenecks. sLSTM focuses on **state tracking** and **memory mixing**, while mLSTM focuses on **storage capacity** and **parallelizable retrieval**. Together, they form the core of xLSTM.

## Why standard LSTMs fall short

The paper points to three main limitations of classic LSTMs. First, they struggle to **revise earlier storage decisions** when new evidence arrives. Second, they compress information into scalar memory cells, which limits how much they can store. Third, their recurrent hidden-to-hidden connections force sequential processing, making them hard to parallelize at scale.

xLSTM addresses these issues by changing both the gating mechanism and the memory structure.

## sLSTM: better at state tracking and revising decisions

The sLSTM is the closer descendant of the original LSTM. It keeps the familiar scalar memory update, but changes the gates to use **exponential gating** instead of only sigmoid gating. That matters because exponential gates can make the model much better at revising earlier choices when later tokens provide stronger evidence.

To make exponential gates stable, the paper adds a **normalizer state** and a **stabilizer state**. The normalizer keeps track of the accumulated gate strength, so the model can divide the cell state by this normalization term before producing the hidden state. This allows the model to use exponential gates without numerical overflow.

In simplified terms, sLSTM is designed to do what many sequence tasks actually require: keep track of which state you are in, update that state when the input changes, and mix information across memory cells. That makes it especially relevant for **state tracking problems**, such as formal language tasks where the model must remember and update structured context over time.

The paper also notes that sLSTM can have multiple memory cells and multiple heads, with memory mixing within each head. This introduces a new kind of memory mixing that is more expressive than the original scalar-cell LSTM setup.

## mLSTM: bigger memory and parallelization

If sLSTM is about tracking state, mLSTM is about **storing more information**.

Instead of a scalar cell state, mLSTM uses a **matrix memory** $\mathbf{C} \in \mathbb{R}^{d \times d}$. This lets it store key-value associations using a covariance-style update rule:

\[
\mathbf{C}_t = \mathbf{C}_{t-1} + \mathbf{v}_t \mathbf{k}_t^\top
\]

Here, the model stores a key $\mathbf{k}_t$ and a value $\mathbf{v}_t$, and later retrieves the value using a query $\mathbf{q}_t$. This is conceptually similar to associative memory: write a pair now, recover the value later when the right query appears.

This structure gives mLSTM two important advantages.

First, it has **much higher storage capacity** than a scalar memory cell. That is especially useful for tasks like associative recall and rare-token prediction, where the model must preserve many distinct pieces of information.

Second, because mLSTM does not use hidden-to-hidden memory mixing, its recurrence can be reformulated in a **parallel version**. That makes it much more GPU-friendly than a standard sequential RNN. In practice, this is a big deal: the paper emphasizes that mLSTM is the xLSTM variant that can be parallelized efficiently.

## The key tradeoff: expressivity versus parallelism

The difference between sLSTM and mLSTM is not just about implementation. It reflects two different design goals.

sLSTM is the better choice when the model needs to **track latent state changes**, revise earlier decisions, or mix information across memory cells. This makes it strong on tasks that require sequential reasoning over structure, not just storage.

mLSTM is the better choice when the model needs to **store and retrieve many associations** and do so efficiently on hardware. Its matrix memory provides richer storage, and its lack of memory mixing allows parallel computation.

So the tradeoff looks like this:

- **sLSTM**: better for state tracking, adaptive memory updates, and memory mixing.
- **mLSTM**: better for storage capacity, associative recall, and parallel execution.

## Why combining them works

xLSTM does not pick one of these ideas and discard the other. Instead, it stacks them together in residual blocks. The paper uses architectures like xLSTM[1:1] or xLSTM[7:1], which indicate the ratio of mLSTM-based blocks to sLSTM-based blocks.

This combination matters because the two variants complement each other. mLSTM can handle large-scale associative storage, while sLSTM adds the ability to mix and revise state in ways that help with harder sequence tasks. The result is a model family that performs strongly on both synthetic long-context tasks and language modeling benchmarks.

On the paper’s synthetic experiments, xLSTM variants show strong results on formal language tasks, associative recall, and the Long Range Arena. On large-scale language modeling, xLSTM outperforms the compared methods in validation perplexity on the 15B-token SlimPajama setup, and also performs strongly after scaling to 300B tokens.

## Takeaway

The simplest way to think about xLSTM is this: it upgrades LSTM memory in two different directions.

sLSTM makes memory more flexible and state-aware through exponential gating and memory mixing. mLSTM makes memory larger and more parallelizable through matrix-based associative storage.

Together, they give xLSTM a more modern memory system for long-context AI. That is the paper’s central message: LSTMs are not just old recurrent models. With the right changes, they can still compete with contemporary Transformer and state-space approaches at scale.

\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### Why are pre up-projection blocks used for mLSTM and post up-projection blocks for sLSTM?
Question:
The architecture section says that xLSTM uses two different residual block styles: sLSTM uses a post up-projection block, while mLSTM uses a pre up-projection block. The motivation given is that mLSTM benefits from operating in a high-dimensional space because its memory capacity becomes larger there.

I am not sure I fully understand this design choice. If higher-dimensional nonlinear summarization is generally better by Cover's theorem, why not use pre up-projection for both sLSTM and mLSTM? Conversely, if post up-projection works well for Transformer FFN-style blocks, why not also use it for mLSTM?

Is this mostly an empirical choice, or is there a more principled reason tied to the different memory structures of scalar versus matrix memory?
Answer:
The paper’s choice is not presented as a purely arbitrary empirical tweak; it is tied to where the recurrent memory does its “thinking.”

The key point is that the authors distinguish between two kinds of residual blocks. In a post up-projection block, the model first processes the sequence in the original model dimension and only then maps the result up and back down. In a pre up-projection block, the input is first lifted to a higher-dimensional space, the nonlinear sequence summarization happens there, and then the result is projected back. The paper explicitly says that an xLSTM block should “non-linearly summarize the past in a high-dimensional space to better separate different histories or contexts,” and then uses Cover’s theorem as the intuition for why this helps. But that intuition matters especially for the mLSTM, because its memory is a matrix memory with a covariance-style update. A matrix memory can store key-value associations more richly when the key/query/value representations themselves live in a larger space, so the authors argue that the memory capacity “becomes larger in the high-dimensional space.”

That is why mLSTM gets the pre up-projection block: the high-dimensional representation is directly feeding the matrix memory, so the memory update and retrieval operate in the richer space where the associative capacity is larger. In other words, the dimension increase is not just for generic nonlinear expressivity; it specifically increases the effective storage and separability of the matrix memory.

For sLSTM, the situation is different. Its memory is scalar, and the paper emphasizes that sLSTM’s strength comes from exponential gating and memory mixing, not from a large associative matrix. Since the memory itself is scalar, there is much less to gain from doing the entire recurrent summarization in a very high-dimensional space. Instead, the authors use the post up-projection style, which is closer to the Transformer FFN pattern: the recurrent core does the sequential summarization in the model space, and then a feedforward-style expansion/refinement is applied after that. This matches the role of sLSTM as a sequence summarizer with memory mixing rather than a high-capacity associative store.

So the distinction is principled in the sense that it reflects the different memory structures. mLSTM benefits from high-dimensional pre-projection because its matrix memory can exploit the larger representational space for storage and retrieval. sLSTM, with scalar memory, is treated more like a recurrent core inside a residual block, and the post up-projection is the more natural place to add extra nonlinear processing without paying the cost of inflating the recurrent memory path.

There is still an empirical component, of course, because architecture choices like this always need validation. But the paper’s justification is not “we tried both and this one worked”; it is that the pre-projection aligns with mLSTM’s need for higher-dimensional associative memory, while the post-projection aligns better with sLSTM’s scalar-memory plus mixing design. In that sense, the choice is tied to the memory mechanism, not just to generic wisdom about “bigger dimensions are better.”

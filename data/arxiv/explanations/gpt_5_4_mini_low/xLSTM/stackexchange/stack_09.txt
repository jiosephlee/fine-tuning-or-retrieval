\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### In what sense are multiple heads and multiple cells equivalent for mLSTM but not for sLSTM?
Question:
The paper states that for mLSTM, multiple heads and multiple cells are equivalent because there is no memory mixing, whereas for sLSTM the model can have multiple heads with memory mixing inside each head but not across heads.

I find this statement confusing. In Transformers, heads usually mean separate subspaces with separate projections, while "cells" sounds more like repeated memory units. Why should those become equivalent in mLSTM?

Is the claim that if there is no cross-cell interaction, then splitting one large matrix memory into several independent smaller ones is just a reparameterization of the same computation? If that is right, I would like to see the dimensional argument more explicitly.
Answer:
In the paper’s terminology, the key distinction is not “heads vs. cells” in the Transformer sense, but whether there is any interaction that mixes information across those subunits over time.

For mLSTM, the memory update is a matrix-valued outer-product accumulation,
$$
\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top,
$$
and the paper explicitly says that mLSTM has “no memory mixing.” That means each memory module evolves independently, apart from the shared readout machinery. If you take one large matrix memory and split the channel dimension into several independent blocks, or equivalently instantiate several smaller matrix memories in parallel, you are just partitioning the same computation into disjoint subspaces. There is no term in the recurrence that would couple block $a$ to block $b$, so the result is a direct sum of independent memories. In that situation, “more heads” and “more cells” are just two ways of organizing the same block-diagonal structure. The dimensional argument is exactly that nothing in the update ever creates off-diagonal interaction between the blocks; each block stores its own $(\mathbf{k},\mathbf{v})$-associations and is read out separately.

That is why the paper can say that for mLSTM, “multiple heads and multiple cells are equivalent as there is no memory mixing.” Here, “equivalent” should be read as “representationally the same up to reshaping/reindexing of channels,” not as a statement about identical implementation details.

For sLSTM, the situation is different because the paper adds explicit memory mixing through recurrent hidden-to-hidden connections. In the scalar-memory case, the cell update is still
$$
c_t = f_t c_{t-1} + i_t z_t,
$$
but the gates and input $z_t$ depend on the previous hidden state $h_{t-1}$, and the paper emphasizes that with multiple cells, sLSTM allows recurrent weight matrices that mix cell outputs across cells. So if you have multiple cells inside one head, those cells can interact through the recurrent matrices $\mathbf{R}_{\mathbf{z}}, \mathbf{R}_{\mathbf{i}}, \mathbf{R}_{\mathbf{f}}, \mathbf{R}_{\mathbf{o}}$. But across heads, the paper says there is no such mixing. Hence heads behave like separated groups, while cells within a head can communicate.

So the asymmetry is: in mLSTM, the memory itself is already a non-mixing associative store, so adding heads or cells only changes how you partition a larger independent memory; in sLSTM, the whole point is that the recurrent gating creates cross-cell interaction, and that interaction is present within a head but intentionally absent across heads. That is the “new way of memory mixing” the paper is referring to.

If you want a one-line intuition: for mLSTM, heads/cells are just bookkeeping because the dynamics are block-independent; for sLSTM, the bookkeeping matters because the recurrence couples cells inside a head, so the partition affects the computation.

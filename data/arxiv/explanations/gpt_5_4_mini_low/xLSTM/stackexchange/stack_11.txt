\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### How should I interpret the claim that xLSTM has linear computation but mLSTM uses a $d \times d$ memory?
Question:
The paper says that xLSTM has linear computation and constant memory complexity with respect to sequence length, but it also says that mLSTM has expensive $d \times d$ matrix memory and update operations.

I am confused about what complexity is actually being claimed. If the sequence length is $T$ and the memory dimension is $d$, is the intended cost something like $O(T d^2)$ for mLSTM versus $O(T^2 d)$ for standard attention? If so, then xLSTM is linear only in $T$, not necessarily efficient in hidden size.

Would it be fair to summarize the tradeoff as "better asymptotics in context length, but heavier per-token state updates"? I want to make sure I am not misreading the computational claims.
Answer:
Yes, that is basically the right way to read it, with one important nuance: the paper is making a claim about **dependence on sequence length** $T$, not a claim that the per-token cost is cheap in the hidden dimension $d$.

What the authors mean by “linear computation and constant memory complexity with respect to the sequence length” is that xLSTM processes a sequence by a recurrent update, so it does not need to revisit all previous tokens the way standard self-attention does. In a Transformer, a length-$T$ sequence typically incurs $O(T^2)$ attention work because every token can attend to every earlier token. In xLSTM, each token is processed once, so the total cost grows linearly in $T$. That is the sense in which the model is “linear.”

For mLSTM specifically, the paper is explicit that the memory state is a matrix $\mathbf{C}_t \in \mathbb{R}^{d \times d}$ and that the update is
\[
\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top.
\]
That means the *state size* is $O(d^2)$, and the update/retrieval involves matrix operations of that scale. So if you look at one step of mLSTM, it is indeed much heavier in hidden size than a scalar-state LSTM, and much heavier than a linear-state model with $O(d)$ state. The paper’s own “Memory and Speed Considerations” section says exactly that the matrix memory is “computationally expensive through its $d \times d$ matrix memory and $d \times d$ update,” while also emphasizing that this cost is independent of sequence length and can be parallelized on GPUs.

So your summary is essentially fair if phrased carefully: xLSTM improves asymptotics in context length, but mLSTM pays a higher per-token cost because its memory is matrix-valued. In big-$O$ terms, a rough way to think about mLSTM is “linear in $T$, but with a substantial $d$-dependent cost per step,” whereas standard attention is “quadratic in $T$.” Whether you write that per-step cost as $O(d^2)$, $O(d^2)$ plus projection costs, or something more implementation-specific depends on which parts of the block you include, but the paper’s main point is not the exact arithmetic count. It is that mLSTM trades increased representational capacity and constant-in-$T$ memory for more expensive matrix operations.

So, in Stack Exchange terms: the claim is not “xLSTM is cheap.” It is “xLSTM avoids the quadratic blowup in sequence length that standard attention has.” And for mLSTM, the relevant tradeoff is indeed “better scaling with context length, at the price of a heavier matrix-valued state update.”

\title{A Textbook about the Paper: "xLSTM: Extended Long Short-Term Memory"}

Chapter 9: 9. mLSTM in Context: Fast Weights, Linear Attention, and Parallel Recurrence

# Covariance memories and optimal separability arguments

The mLSTM variant in xLSTM replaces the original scalar LSTM memory with a matrix memory $\mathbf{C} \in \mathbb{R}^{d \times d}$. This change is central to its role as a memory-augmented sequence model, because it lets the model store and retrieve information through matrix multiplication rather than through a single scalar state. In the paper, the memory is designed around a key-value setting: at time $t$, the model stores a key $\mathbf{k}_t$ together with a value $\mathbf{v}_t$, and later retrieves the value using a query $\mathbf{q}_{t+\tau}$. That is exactly the kind of associative memory problem that motivates the covariance update rule.

The update itself is
\[
\mathbf{C}_t = \mathbf{C}_{t-1} + \mathbf{v}_t \mathbf{k}_t^\top .
\]
This is called a covariance update rule in the paper. The intuition is that each new key-value pair contributes an outer product, which adds a structured association to memory. The paper emphasizes that if a layer normalization is applied before projecting inputs to keys and values, then these vectors have zero mean. In that setting, the covariance update rule is said to be optimal for maximal separability of retrieved binary vectors, which the paper identifies with a maximal signal-to-noise ratio. In other words, the update rule is chosen so that associations stored in memory can be separated as clearly as possible when later queried.

The paper also notes an important trade-off. If retrieval is limited to pairwise interactions, then higher separability can be achieved by allowing quadratic complexity, as in attention-style mechanisms. This places mLSTM in a middle ground: it uses an associative matrix memory to enhance storage capacity, but it still follows a recurrent update structure. That makes it a memory model inspired by associative recall and fast weight ideas, while remaining part of the LSTM family.

# Relationship to Fast Weight Programmers

The paper explicitly states that the covariance update rule is equivalent to Fast Weight Programmers. This is an important conceptual link because it shows that mLSTM is not inventing a completely new memory principle, but rather integrating a known associative memory mechanism into the LSTM framework. Fast Weight Programmers had already used matrix-like memory updates to store relationships between inputs, and the xLSTM paper builds directly on that idea.

The paper also notes that later versions of fast weight methods introduced a constant decay rate multiplied to $\mathbf{C}_{t-1}$ and a constant learning rate multiplied to the outer product $\mathbf{v}_t \mathbf{k}_t^\top$. In the mLSTM formulation, these roles are taken over by the forget gate and input gate, respectively. The forget gate acts like a decay rate on past memory, while the input gate acts like a learning rate that determines how strongly the new key-value association is written. This is precisely how the LSTM gating idea is merged with the fast-weight-style memory update.

What makes this integration distinctive is that the output gate still controls how the retrieved information is exposed as hidden state. So the mLSTM is not merely a fast-weight model with gating added afterward. Instead, the gating, update rule, and retrieval operation are all integrated into the recurrent cell. The paper’s framing makes this a deliberate extension of LSTM rather than a separate architecture.

# Connections to RWKV, Retention, Linear Transformers, and HGRN2

The paper situates mLSTM among a set of recent methods that also aim to improve efficiency or memory behavior in sequence modeling. In the related work discussion, it names RWKV-5 and RWKV-6, Retention, Linear Transformer, and HGRN2 as methods that build on a covariance-style update mechanism or closely related ideas. These models are grouped with mLSTM because they all share some version of a memory or accumulation process that supports sequence modeling without standard quadratic attention.

The closest conceptual relatives identified by the paper are Retention, RWKV, and HGRN2. These approaches share matrix memory and/or gating, which makes them similar in spirit to mLSTM. However, the paper draws a clear distinction: unlike the new sLSTM, these approaches do not allow memory mixing. That matters because the paper argues that memory mixing enables state tracking, and state tracking is necessary for tasks like code evaluation and tracking entities in long narratives. So while RWKV-style and retention-style models are close to mLSTM in their use of gated accumulation or memory-like state, xLSTM’s broader design emphasizes a more expressive recurrent structure through the inclusion of sLSTM alongside mLSTM.

The paper also connects linear Transformer variants to this broader family. Linear Transformers, Retention, and similar methods are motivated by the desire to avoid the quadratic cost of standard attention. mLSTM shares that motivation for efficiency, but it does so through recurrent matrix memory rather than through a direct reformulation of attention. This is why the paper presents mLSTM as part of a wider design space of sequence models that includes attention approximations, state space models, and recurrent neural networks, while still preserving a distinct LSTM-based memory principle.

# Similarity and differences between mLSTM and attention-style key-value memory

mLSTM is close to attention-style memory in that both use key-value associations. The paper explicitly adopts Transformer terminology for the mLSTM memory: the model stores a key $\mathbf{k}_t$ and a value $\mathbf{v}_t$, and later uses a query $\mathbf{q}_t$ to retrieve information. This makes the analogy to attention very natural. In both cases, retrieval depends on compatibility between a query and previously stored content.

But the mechanism is different. In attention, retrieval is usually based on comparing the query to many stored keys and forming weighted combinations of values. In mLSTM, the memory is compressed into a matrix $\mathbf{C}_t$, and retrieval happens through a single matrix multiplication:
\[
\tilde{\mathbf{h}}_t = \mathbf{C}_t \mathbf{q}_t \, / \, \max\{|\mathbf{n}_t^\top \mathbf{q}_t|, 1\}.
\]
This means the key-value associations are not kept as a list of explicit pairs to be scanned one by one at every step. Instead, they are accumulated into the matrix state. The paper presents this as a way to increase storage capacity while retaining a recurrent structure.

The paper also introduces a normalizer state $\mathbf{n}_t$ for mLSTM. This normalizer is the weighted sum of key vectors, where each key is weighted by the input gate and all future forget gates. Its role is to track the strength of the stored associations and stabilize retrieval. Because the dot product $\mathbf{n}_t^\top \mathbf{q}_t$ can be close to zero, the paper uses the absolute value and lower bounds it by a threshold, typically $1.0$. This stabilization step shows that mLSTM is not just a raw associative memory; it is a carefully controlled gated memory system designed to make retrieval numerically reliable.

# Why mLSTM drops hidden-to-hidden memory mixing

One of the paper’s key design choices is that mLSTM abandons memory mixing, meaning it removes hidden-hidden recurrent connections from the memory update path. This is done specifically to enable parallelization. In the original LSTM, the hidden state at time $t-1$ influences the gates and cell input at time $t$, which creates sequential dependencies. Those dependencies force the computation to proceed step by step.

In mLSTM, the paper removes this kind of memory mixing so that the recurrence can be reformulated into a parallel version. The gates in the mLSTM forward pass are computed directly from the input $\mathbf{x}_t$:
\[
\mathbf{q}_t = \mathbf{W}_q \mathbf{x}_t + \mathbf{b}_q,\quad
\mathbf{k}_t = \frac{1}{\sqrt{d}}\mathbf{W}_k \mathbf{x}_t + \mathbf{b}_k,\quad
\mathbf{v}_t = \mathbf{W}_v \mathbf{x}_t + \mathbf{b}_v,
\]
with the input and forget gates also depending on $\mathbf{x}_t$ alone in the formulation shown in the paper. This is a deliberate simplification relative to the original LSTM. By removing hidden-to-hidden recurrence from the memory update, the memory evolution becomes more amenable to parallel computation.

The trade-off is that the model gives up the kind of memory mixing available in sLSTM. The paper is explicit that mLSTM does not have this feature. But that is precisely the point: mLSTM is the fully parallelizable branch of xLSTM, designed to get the benefits of matrix memory without the sequential bottleneck caused by recurrent mixing.

# Equivalence of multiple heads and multiple cells in mLSTM

The paper notes that mLSTM can have multiple memory cells like the original LSTM. It also states that for mLSTM, multiple heads and multiple cells are equivalent because there is no memory mixing. This equivalence follows from the fact that the different memory components do not interact through recurrent hidden-hidden connections. As a result, splitting the memory into heads or cells does not change the essential computational structure.

This is different from sLSTM, where the introduction of heads together with exponential gating creates a new form of memory mixing. In mLSTM, by contrast, the absence of memory mixing makes the organizational choice between heads and cells less consequential. The memory units can be viewed as parallel associative modules, each operating independently within the same general matrix-memory framework.

This distinction matters conceptually because it highlights how the xLSTM family uses the same LSTM heritage in two different ways. One branch, sLSTM, explores expressive mixing across memory cells and heads. The other branch, mLSTM, prioritizes parallelizable matrix memory. The equivalence of heads and cells in mLSTM is another sign that the architecture is structurally simpler in its recurrence, even though the memory itself is more powerful than a scalar cell.

# How the recurrence can be reformulated for parallel execution

The paper states directly that because mLSTM has no memory mixing, its recurrence can be reformulated in a parallel version. The forward pass is expressed as a sequence of matrix updates and normalizations:
\[
\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top,
\qquad
\mathbf{n}_t = f_t \mathbf{n}_{t-1} + i_t \mathbf{k}_t.
\]
These equations resemble a recurrent accumulation, but the lack of hidden-to-hidden mixing means the computation can be reorganized using standard matrix operations.

The paper compares this property to the parallelizability of FlashAttention and GLA. The key idea is that if each time step’s update depends only on the input and the previous memory state, and not on a recursively transformed hidden state, then the computation can be arranged more efficiently on modern hardware. The paper emphasizes that the mLSTM computations can be done in parallel on GPUs, so although the memory state is a $d \times d$ matrix, the wall-clock cost is moderated by parallel execution.

This is also why the paper frames mLSTM as “fully parallelizable.” The recurrence still exists mathematically, but its structure permits a reformulation that avoids the strict sequential bottleneck typical of recurrent networks. In that sense, mLSTM is a recurrence that behaves much more like a parallel sequence operator than like a classic step-by-step RNN.

# Benefits and costs of parallelizable matrix memory

The main benefit of mLSTM is the increase in storage capacity. By moving from a scalar memory to a matrix memory, the model can store key-value associations with much greater richness. This is especially relevant for associative recall and for tasks that require the model to remember and later retrieve multiple items. The paper presents mLSTM as a way to overcome the limited storage capacity of the original LSTM, which compresses information into scalar cell states.

At the same time, the paper is careful to point out the costs. A matrix memory of size $d \times d$ requires a $d \times d$ update and associated computation. That is more expensive than scalar updates. So mLSTM trades computational complexity for memory capacity. The paper argues that this trade-off is worthwhile because the computations are parallelizable and therefore the wall-clock overhead is not as severe as the matrix size might suggest.

The paper also notes that mLSTM memory does not require parameters. This is an important distinction: the memory is part of the runtime state, not a set of learned weights. So the model gains capacity without directly increasing parameter count in the memory itself. The overall picture is one of a computationally heavier but more expressive associative memory that remains practical because of GPU parallelism.

# Comparison of mLSTM memory capacity with Transformer attention

The paper compares mLSTM’s storage behavior to Transformer attention in a subtle way. On the one hand, attention is presented as a gold standard for associative recall in the Multi-Query Associative Recall task, because Transformers have a memory that is exponential in the coding dimension. On the other hand, mLSTM is still able to perform very well among non-Transformer models, and the paper highlights that xLSTM with an mLSTM component achieves the best results among the non-Transformer methods tested.

This comparison clarifies the role of mLSTM. It is not claimed to surpass attention by offering the same kind of memory structure. Instead, it provides a different route to strong associative memory: a recurrent matrix memory with gated covariance updates. The paper suggests that the matrix memory substantially improves storage capacities relative to scalar LSTM memory, and that this improvement shows up especially in harder associative recall settings.

At the same time, the paper’s experimental discussion indicates that the sLSTM block does not hurt memory capacity and may even leverage it further in the hardest recall settings. This reinforces the view that mLSTM is one part of the xLSTM design rather than a complete replacement for all other sequence mechanisms. Its main contribution is to give LSTM a much richer, parallelizable memory store that can compete well with other modern sequence models on long-context and associative tasks.

In summary, mLSTM sits at the intersection of recurrent memory, fast weights, and linearized sequence modeling. It inherits the LSTM philosophy of gated storage, but it replaces the scalar cell with a matrix associative memory and removes hidden-to-hidden mixing so that the recurrence can be parallelized. That combination is what makes mLSTM both conceptually close to older memory-based models and practically suited to modern large-scale sequence processing.

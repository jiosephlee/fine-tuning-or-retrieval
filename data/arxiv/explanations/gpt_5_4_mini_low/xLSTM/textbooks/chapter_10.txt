\title{A Textbook about the Paper: "xLSTM: Extended Long Short-Term Memory"}

Chapter 10: 10. Building xLSTM Blocks and Full xLSTM Architectures

# Why residual architectures matter for deep sequence models

The paper does not treat sLSTM and mLSTM as isolated recurrent cells. Instead, it places them inside residual block architectures, because the authors want xLSTM to function as a modern deep sequence model in the same style as contemporary large language models. This matters because the paper’s goal is not only to modify the memory mechanism of LSTM, but also to scale it to billions of parameters in a way that is compatible with deep stacking.

Residual architectures provide a way to build very deep networks while preserving the ability to train them effectively. In the paper, xLSTM blocks are residually stacked, following the same broad design philosophy used in deep convolutional networks and Transformers. The residual path lets each block refine an existing representation rather than completely replace it. For sequence modeling, this is especially useful because each layer can contribute a different level of temporal abstraction while still keeping the information from earlier layers available.

The paper’s xLSTM design therefore combines recurrent memory with the residual-block paradigm of modern deep learning. This is an important architectural decision: it allows the LSTM idea to be extended from a classic recurrent cell into a scalable backbone for language modeling.

# The xLSTM block concept

An xLSTM block is the basic building unit of the architecture. The authors define it as a residual block that contains one of the new LSTM variants, either sLSTM or mLSTM, and surrounds it with linear projections and nonlinearity in a way that fits into a modern deep backbone. The purpose of the block is to nonlinearly summarize the past in a high-dimensional representation so that different histories or contexts become easier to separate.

This “summarize the past” viewpoint is central to the paper. The xLSTM block is not just a place where recurrence happens; it is a computational module that compresses sequence history into a representation useful for next-token prediction or other sequence tasks. The paper emphasizes that separating histories is a prerequisite for predicting the next sequence element correctly. In other words, if the model can keep distinct past contexts distinct in its internal representation, it can better decide what should come next.

The xLSTM block therefore acts as the place where the new memory mechanisms of sLSTM and mLSTM are embedded into a larger architecture. The block design is what makes these memory mechanisms usable at scale in stacked deep models.

# Cover’s theorem and nonlinear summarization in high-dimensional spaces

To justify the block design, the paper invokes Cover’s theorem. The relevant intuition is that patterns that are not linearly separable in a low-dimensional space are more likely to become separable after a nonlinear embedding into a higher-dimensional space. The authors use this idea to motivate why xLSTM blocks should include an up-projection into a higher-dimensional space before applying the memory mechanism or, depending on the block type, after it.

This is an architectural argument about representation geometry. The model should not merely store information; it should store information in a space where different histories can be disentangled. The paper frames this as a way to improve the model’s ability to predict the next element in a sequence, since prediction depends on choosing among competing histories or contexts.

The theorem is not used as a formal proof of performance. Rather, it serves as the conceptual guide for why the xLSTM block is built around dimension expansion and nonlinear processing. The block is designed to make the sequence history easier to separate, which is especially valuable when the model is used inside a deep residual architecture.

# Post up-projection residual blocks for sLSTM

For xLSTM blocks containing sLSTM, the paper uses a post up-projection residual block. The authors describe this as analogous to the block style used in Transformers. The structure first summarizes the past in the original space, and then linearly maps the result into a higher-dimensional space, applies a nonlinearity, and maps back to the original space.

The important point is that the sLSTM itself already includes memory mixing through hidden-hidden recurrent connections across cells. Because of this, the paper places the sLSTM in a residual block design that performs the expansion after the memory operation. This arrangement fits the role of sLSTM as a sequence-processing module that maintains scalar memory while also allowing richer interactions through memory mixing.

The paper presents this as a way to integrate the new sLSTM into a modern backbone without changing its basic recurrence logic. The post up-projection block is therefore part of the mechanism by which the sLSTM becomes a usable component inside large deep models.

# Pre up-projection residual blocks for mLSTM

For xLSTM blocks containing mLSTM, the paper uses a pre up-projection residual block. The structure linearly maps the input to a higher-dimensional space first, then performs the nonlinear summary in that high-dimensional space, and finally maps back to the original dimension. The paper notes that this is similar to the style used in State Space Models.

This choice is tied directly to the nature of mLSTM. Since mLSTM uses a matrix memory, its storage capacity is larger in a higher-dimensional space. The paper explicitly states that the mLSTM block uses the pre up-projection form because the memory capacity becomes larger in the high-dimensional space. So the projection is not a cosmetic choice; it is part of how the model takes advantage of the matrix-valued memory.

In this design, the expansion happens before the memory operation, which means the matrix memory acts on richer representations. That is consistent with the paper’s view of mLSTM as the variant intended to increase storage capacity and to support full parallelization.

# Why mLSTM benefits from high-dimensional memory space

The paper’s explanation for the mLSTM design is that increasing the memory from a scalar to a matrix naturally increases storage capacity. Since the matrix memory stores key-value associations through outer-product updates, it can preserve richer relationships than a scalar memory cell. Putting this mechanism into a higher-dimensional space makes the memory more expressive.

The block design reflects this storage perspective. In the paper, the mLSTM is associated with a matrix memory and a covariance-style update rule, so the block is constructed to give that memory a larger representational space to operate in. The paper treats this as a direct architectural advantage: the model can store more information and retrieve it more precisely when the memory is applied in a higher-dimensional setting.

This is one of the reasons the paper distinguishes mLSTM from sLSTM. The mLSTM is the variant that emphasizes larger storage capacity and parallelization, and the pre up-projection block is chosen to support that role.

# Pre-LayerNorm residual backbones in modern LLM design

The paper states that xLSTM architectures use pre-LayerNorm residual backbones, which are described as the most commonly used design in contemporary large language models. This places xLSTM within the standard modern deep-learning recipe for training stable, large residual networks.

The use of pre-LayerNorm is important because it is part of the backbone rather than part of the recurrent cell itself. The paper is not proposing a completely alien architecture; instead, it adopts the backbone organization common in today’s large models and inserts the new LSTM variants into it. This is one way xLSTM is made compatible with the scaling regime of modern language models.

The overall point is that the authors want xLSTM to be architecturally comparable to systems used in large-scale language modeling. The pre-LayerNorm residual backbone is therefore part of the engineering framework that allows the new memory mechanisms to be stacked deeply and trained at scale.

# Stacking xLSTM blocks into deep architectures

Once xLSTM blocks are defined, the full model is built by stacking them residually. The paper explicitly says that xLSTM architectures are constructed by residually stacking building blocks. This is the same broad strategy that enabled deep convolutional networks and Transformers to scale successfully.

The full xLSTM architecture is therefore not a single recurrent module but a deep stack of many such modules. Each block can refine the sequence representation passed from earlier blocks, and the residual connections preserve the flow of information through depth. The paper presents this as the architectural form that makes xLSTM suitable for large language modeling.

This stacking strategy is also where the new xLSTM block design becomes practically important. A single sLSTM or mLSTM cell would not suffice to compete with large modern models. The architecture becomes powerful only when many xLSTM blocks are layered together in a residual backbone.

# Interpreting xLSTM[a:b] block ratios

For the experiments, the paper introduces the notation xLSTM[$a:b$], where $a/b$ denotes the ratio of mLSTM-based blocks to sLSTM-based blocks. This notation is a compact way to describe how a model is composed from the two xLSTM block types.

For example, xLSTM[7:1] means that among eight blocks, seven are mLSTM-based and one is sLSTM-based. The paper gives a concrete example: if the total number of blocks is 48, then xLSTM[7:1] corresponds to 42 mLSTM-based blocks and 6 sLSTM-based blocks. This notation lets the paper compare different architectural mixtures systematically.

The ratio is not just bookkeeping. It expresses a design choice about how much of the model should emphasize matrix-memory parallel blocks and how much should emphasize scalar-memory blocks with memory mixing. By using this notation, the paper can study how different compositions affect performance on language modeling and synthetic tasks.

# Design rationale for mixing mLSTM and sLSTM blocks in one model

The paper presents xLSTM as a family with two complementary members: sLSTM and mLSTM. The sLSTM provides scalar memory with memory mixing, while the mLSTM provides matrix memory and full parallelization. Because they solve different limitations of the original LSTM, the paper uses them together in the same architecture.

The rationale for mixing them is that the two variants contribute different strengths. The mLSTM improves storage capacity and parallelization, while the sLSTM preserves the memory-mixing behavior that helps with state tracking and revision of storage decisions. The paper even notes that sLSTM can leverage memory capacity rather than diminishing it in the mixed models. This is why architectures like xLSTM[7:1] are meaningful: they are not arbitrary mixtures, but deliberate combinations of two recurrent block types.

In the architecture section, the paper describes xLSTM as an architecture family built by residually stacking these blocks. In the experiments, the ratio of mLSTM to sLSTM blocks becomes a way to tune the balance between capacity, memory mixing, and computational efficiency. The overall design goal is to make the full model suitable for large-scale language modeling while retaining the advantages introduced by both xLSTM variants.

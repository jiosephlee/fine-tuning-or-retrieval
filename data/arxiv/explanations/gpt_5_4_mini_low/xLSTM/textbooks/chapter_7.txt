\title{A Textbook about the Paper: "xLSTM: Extended Long Short-Term Memory"}

Chapter 7: 7. Advanced Memory Mixing in sLSTM

# Multiple scalar memory cells in an sLSTM layer

The scalar sLSTM extends the original LSTM idea by keeping the basic scalar memory-cell update, but it is not restricted to just one memory cell. In the paper’s formulation, multiple scalar memory cells can be combined into a vector, just as in later LSTM formulations. This means that instead of maintaining a single scalar state $c_t$, an sLSTM layer can maintain several scalar memory cells at once. The role of each cell is still to store and update information over time, but now the layer has a richer internal state because it can distribute information across multiple cells rather than compressing everything into one.

This matters because the paper’s goal is not just to preserve information, but to improve how information is organized and revised as a sequence unfolds. A single scalar memory cell can store only a limited amount of information in a compressed form. By using multiple cells, the sLSTM creates a larger internal workspace for memory. The paper emphasizes that this is one part of the new memory-mixing behavior: the cells are not isolated in the layer, but can interact through recurrent connections. In this sense, the extension to multiple cells is not merely a size increase; it is part of a larger structural change in how memory is handled.

# Recurrent mixing matrices for cell input and gates

In the original scalar LSTM, the cell input and gates depend on the current input $\mathbf{x}_t$ and the previous hidden state $h_{t-1}$ through learned weights. The sLSTM preserves this basic idea, but when multiple memory cells are used, the recurrent connections become matrix-valued. The paper states that the hidden-state vector $\mathbf{h}$ can influence the memory cell input $\mathbf{z}$ and the gates $\mathbf{i}$, $\mathbf{f}$, and $\mathbf{o}$ through recurrent weight matrices $\mathbf{R}_{\mathbf{z}}$, $\mathbf{R}_{\mathbf{i}}$, $\mathbf{R}_{\mathbf{f}}$, and $\mathbf{R}_{\mathbf{o}}$.

This is what the paper calls memory mixing. The hidden state from one step does not merely feed back into a separate scalar gate computation; instead, it mixes information across the memory cells. This makes the next update depend on a transformed combination of the previous memory output. Intuitively, memory mixing allows one cell’s contents to influence how other cells are updated, gated, or read out. That is a stronger and more flexible form of recurrence than a completely separable update, because it allows the model to build internal dependencies among its memory components.

The paper also notes that exponential gating contributes to this new memory-mixing behavior. So the mixing effect is not only about the existence of recurrent matrices, but also about how the gates themselves are formed and stabilized in the sLSTM. The gates can be input-dependent and hidden-dependent, and their exponential form changes how strongly information is retained or revised.

# Within-head memory mixing versus across-head independence

The paper introduces heads as another organizational level for sLSTM memory. An sLSTM can have multiple heads, but the important detail is that memory mixing does not occur across heads. Instead, it happens within each head, across the memory cells assigned to that head. So the model is partitioned into separate memory-mixing groups, and each group processes its own internal recurrent interactions.

This distinction is important because it shows that the paper is not using heads in the same way as attention heads in a Transformer. Here, a head is a unit of recurrent memory organization. Inside a head, memory cells can interact through the recurrent mixing matrices, but different heads remain independent. That means the model can maintain several separate streams of recurrent processing at once, while still preserving a controlled form of mixing within each stream.

The paper presents this as a new way of memory mixing. The novelty is not simply “more heads” or “more cells,” but the combination of heads with exponential gating and recurrent mixing inside each head. This structure gives the sLSTM a more modular memory organization: each head can specialize, while still performing rich internal state updates.

# Multi-head sLSTM as a new form of recurrent memory organization

Multi-head sLSTM should be understood as a recurrent memory architecture rather than as a direct copy of Transformer-style attention heads. The paper’s description makes clear that in sLSTM, heads are introduced together with memory cells and recurrent mixing. This creates a layered organization: within a head, multiple memory cells can mix, but across heads there is no mixing. As a result, the model can maintain several recurrent subspaces in parallel.

This organization is significant because it changes the way information can be stored and processed over time. Instead of forcing all temporal information through one shared memory pathway, the model can distribute different kinds of information across heads. At the same time, because each head still has internal recurrence and memory mixing, each head can perform meaningful state tracking on its own.

The paper positions this as an extension of the LSTM family rather than a replacement of its core logic. The essential LSTM idea remains: memory is updated recurrently and gated selectively. What changes is the structure in which these updates occur. Multi-head sLSTM creates a recurrent system with multiple specialized memory compartments, each capable of internal mixing.

# Why memory mixing increases expressivity

The paper argues that memory mixing makes LSTMs more expressive than architectures that do not have it. The central intuition is that mixing allows the model to revise and reorganize stored information as new input arrives. If memory components are independent, then each component can only preserve its own local summary. If they are mixed recurrently, then the model can use previous hidden information to reshape future updates across multiple memory cells.

This increased expressivity is connected in the paper to the ability to separate histories or contexts. An xLSTM block is designed to non-linearly summarize the past in a high-dimensional space so that different histories can be better separated. Within the sLSTM, memory mixing contributes to that goal by allowing the recurrence to form richer internal representations. The model is therefore not merely remembering more; it is building a more structured memory of the past.

The paper also links this to the idea that LSTMs excel at learning abstractions and storing semantic information in memory cells. Memory mixing gives the model additional freedom in how it organizes those abstractions. Because the hidden state influences future cell updates and gates through recurrent matrices, the memory system can represent more than a simple linear accumulation of past inputs.

# State tracking as a core capability enabled by recurrent mixing

A major point in the paper is that memory mixing is crucial for state tracking. The authors explicitly connect this to formal language tasks, where a model must keep track of an evolving discrete state as the sequence unfolds. In their synthetic experiments, models without memory mixing, such as Transformers or State Space Models in the tested configurations, cannot solve certain regular grammars, such as parity. The paper interprets this as evidence that state tracking is a capability those models lack in the tested setting.

In contrast, sLSTM with memory mixing is designed to support exactly this kind of behavior. Because recurrent connections allow the hidden state to influence future memory updates, the model can revise its internal state as it processes new symbols. This is especially important when the correct output depends not just on accumulated evidence, but on maintaining a latent state that changes according to the sequence’s structure.

The paper’s formal language experiments are used to support this claim. They are presented as a test of whether the model can handle problems requiring state tracking, and the results are used to argue that the new sLSTM’s memory mixing contributes directly to solving such tasks. In other words, memory mixing is not just a capacity enhancement; it is a mechanism for representing and updating the kinds of latent states needed in structured sequence processing.

# Contrast with architectures lacking memory mixing

The paper contrasts sLSTM with architectures that do not have memory mixing. In particular, the mLSTM is explicitly designed to abandon hidden-hidden memory mixing in order to become fully parallelizable. More broadly, the paper contrasts xLSTM with Transformers, State Space Models, and other recurrent approaches that do not use the same recurrent mixing structure. The key claim is that without memory mixing, a model is less able to solve certain state tracking problems.

This contrast is not presented as a generic statement about all sequence models, but as a specific claim supported by the paper’s synthetic tasks. On those tasks, models without memory mixing fail on examples that require revising an internal discrete state during sequence processing. The parity task is the clearest example given: the paper says that Transformers or State Space Models without memory mixing cannot solve such regular grammars in the tested setup.

So the paper uses these comparisons to make a structural point. Memory mixing changes not only performance numbers, but the class of problems the model can represent effectively. The absence of memory mixing is associated with weaker state tracking, while its presence supports richer recurrent computation. This is why the paper treats sLSTM as a meaningful extension of the LSTM family rather than just another gated recurrent variant.

# Trade-off between expressivity and parallelizability

The paper is careful to emphasize that memory mixing has a cost. In sLSTM, memory mixing through hidden-hidden connections makes the recurrence sequential, which means the model is not fully parallelizable. This is one of the reasons why sLSTM cannot be implemented with the same kind of parallel efficiency as mLSTM. The recurrent dependencies require processing one time step after another.

At the same time, the paper argues that this cost buys expressive power. The trade-off is therefore between computational parallelizability and recurrent flexibility. sLSTM keeps the recurrent mixing because it supports state tracking and richer memory interactions. mLSTM removes memory mixing to regain parallelizability, but that comes with a different memory structure based on a matrix memory and covariance updates.

The paper’s overall design makes this trade-off explicit. The sLSTM represents the more sequential, mixing-rich end of the spectrum, while mLSTM represents the more parallelizable end. For the reader, the important takeaway is that memory mixing is not an accidental detail: it is the mechanism that gives sLSTM its state-tracking capability, even though it reduces parallel execution efficiency.

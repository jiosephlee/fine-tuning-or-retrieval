\title{A Textbook about the Paper: "xLSTM: Extended Long Short-Term Memory"}

Chapter 8: 8. mLSTM: Matrix Memory for High-Capacity Associative Storage

# Motivation for moving from scalar to matrix memory

The mLSTM is introduced in xLSTM to address one of the main limitations of the original LSTM: its restricted storage capacity. In the standard LSTM, the memory cell is a scalar, or more generally a collection of scalar cells, and information must be compressed into those scalar states. That makes the memory compact, but it also limits how much structure can be retained and how precisely different pieces of information can be distinguished later. The paper uses rare token prediction and associative recall as examples of where this matters: when the model must remember many distinct items, scalar memory can become a bottleneck.

The mLSTM changes the memory cell from a scalar $c \in \mathbb{R}$ to a matrix $\mathbf{C} \in \mathbb{R}^{d \times d}$. This is not just a larger container in a superficial sense. The matrix memory lets the model store interactions between vectors, which gives it a richer internal structure for memory and retrieval. In the paper’s framing, this is a way to improve the capacity of the LSTM while preserving the general recurrent idea of storing something over time and later using it to produce an output.

The key intuition is that if a scalar memory stores one compressed summary, a matrix can store many relationships at once. That makes the memory suitable for associative retrieval: the model sees a pattern now, stores it in the memory, and later uses a related cue to recover the associated content. This is the role mLSTM is designed to play.

# Associative memory and the key-value retrieval perspective

The mLSTM is described using the language of associative memory. At time $t$, the model stores a pair consisting of a key $\mathbf{k}_t \in \mathbb{R}^d$ and a value $\mathbf{v}_t \in \mathbb{R}^d$. Later, at a future time $t+\tau$, the model receives a query vector $\mathbf{q}_{t+\tau} \in \mathbb{R}^d$ and uses it to retrieve the value that was associated with a relevant key. This is the associative-memory viewpoint: keys index memories, values are what should be recovered, and queries are the cues used for retrieval.

This framing is borrowed from the Transformer terminology, but in mLSTM it is embedded inside a recurrent memory system. The goal is not to perform attention in the Transformer sense, but to realize a similar kind of key-value association using a recurrent update rule and a matrix memory. The paper explicitly connects this to bidirectional associative memories, which historically studied how one vector can cue the retrieval of another.

The intuition is simple: if the memory has stored many pairs of the form “this key goes with this value,” then a query similar to a stored key should return the corresponding value. The matrix memory in mLSTM is the mechanism used to make this possible.

# Connection to Bidirectional Associative Memories

The paper notes that the setting of mLSTM is the setting of Bidirectional Associative Memories, or BAMs. In this view, memory does not merely hold a hidden representation of the past. Instead, it stores associations between two vector spaces so that one vector can later evoke another. This is precisely the relationship between keys and values in the mLSTM description.

BAMs provide the conceptual foundation for thinking about the matrix memory as an associative structure. The model does not need to memorize an entire sequence verbatim; it needs to preserve associations in a form that can be queried later. The matrix memory is therefore not an arbitrary design choice. It is a structured memory that supports recall through vector interactions.

This is important because the paper contrasts mLSTM with the scalar-memory LSTM. A scalar cell can only store a limited amount of information about the past, whereas an associative matrix can store many pairwise relations. The BAM perspective helps explain why this should improve memory capacity: the model is no longer just tracking a single running quantity, but storing a collection of associations that can be accessed through matching queries.

# The covariance update rule for storing value-key pairs

The central memory update rule in mLSTM is the covariance update

$$
\mathbf{C}_t = \mathbf{C}_{t-1} + \mathbf{v}_t \mathbf{k}_t^\top .
$$

This rule adds an outer product between the value vector and the key vector to the previous memory matrix. The result is a matrix that accumulates associations over time. Each outer product contributes a structured update that links the current value with the current key.

The paper refers to this as a covariance update rule and notes that it is optimal for maximizing the separability of retrieved binary vectors, which is equivalent to maximizing signal-to-noise ratio in the retrieval setting. The intuition is that the update should store associations in a way that makes later retrieval as clean as possible. A key and a value are paired in a rank-one update, and these updates accumulate in the matrix memory.

The paper also explains that this rule is connected to Fast Weight Programmers. Those methods similarly maintain a rapidly changing weight matrix that is updated online. In mLSTM, however, the update is integrated into the LSTM framework by interpreting the forget gate as a decay factor and the input gate as a learning-rate factor. That gives the memory update a recurrent-gated structure rather than an unconstrained additive one.

# mLSTM cell state as a memory matrix

In mLSTM, the cell state is the matrix $\mathbf{C}_t$. This matrix plays the same conceptual role as the scalar cell state in the original LSTM: it is the long-lived memory that carries information forward through time. The difference is that the stored information is now structured as a matrix rather than a scalar or vector.

The update in the recurrent formulation is

$$
\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top .
$$

This looks like a gated version of the covariance rule. The previous memory is decayed by $f_t$, while the new key-value association is inserted with strength $i_t$. In this way, the matrix memory is not merely accumulating associations passively; it is being regulated by the same gating principles that are central to LSTM.

The paper emphasizes that this memory update is parameter-free in the sense that the memory matrix itself does not require learned parameters. Instead, the parameters are used to compute the key, value, query, and gates from the input. The memory content evolves dynamically from the stream of data.

# The matrix normalizer state and its meaning

Alongside the matrix memory, mLSTM maintains a normalizer state $\mathbf{n}_t$. This state is updated by

$$
\mathbf{n}_t = f_t \mathbf{n}_{t-1} + i_t \mathbf{k}_t .
$$

The normalizer state tracks the weighted sum of key vectors, where each key is weighted by the input gate and by the future forget gates. The paper says this state keeps record of the strength of the gates. In other words, it summarizes how much memory has been written and how strongly it should influence retrieval.

This normalizer is essential because retrieval from a matrix memory can otherwise have unstable scale. When the model computes a query against the stored memory, it also needs to account for how much evidence has been accumulated in the normalizer. The purpose of $\mathbf{n}_t$ is therefore not to store content in the same way as $\mathbf{C}_t$, but to record the effective magnitude of the stored associations so that the hidden state can be normalized appropriately.

The paper’s description makes clear that this normalizer is a stabilizing companion to the matrix memory. It does not replace the memory matrix; it helps make the matrix memory usable in practice.

# Query, key, and value projections from inputs

The mLSTM computes query, key, and value vectors from the input $\mathbf{x}_t$ through learned linear projections. The equations are

$$
\mathbf{q}_t = \mathbf{W}_q \mathbf{x}_t + \mathbf{b}_q,
$$

$$
\mathbf{k}_t = \frac{1}{\sqrt{d}} \mathbf{W}_k \mathbf{x}_t + \mathbf{b}_k,
$$

$$
\mathbf{v}_t = \mathbf{W}_v \mathbf{x}_t + \mathbf{b}_v.
$$

These projections define the components used in associative storage and retrieval. The query is what will later be used to retrieve content, the key is what identifies the stored association, and the value is the content associated with that key. The scaling of the key by $\frac{1}{\sqrt{d}}$ is part of the paper’s formulation.

The gates are also computed from the input. The input gate and forget gate are scalar in the formulation shown in the paper, and the output gate is vector-valued:

$$
i_t = \exp(\tilde{i}_t), \qquad \tilde{i}_t = \mathbf{w}_i^\top \mathbf{x}_t + b_i,
$$

$$
f_t = \sigma(\tilde{f}_t) \ \text{or} \ \exp(\tilde{f}_t), \qquad \tilde{f}_t = \mathbf{w}_f^\top \mathbf{x}_t + b_f,
$$

$$
\mathbf{o}_t = \sigma(\tilde{\mathbf{o}}_t), \qquad \tilde{\mathbf{o}}_t = \mathbf{W}_{\mathbf{o}} \mathbf{x}_t + \mathbf{b}_{\mathbf{o}}.
$$

So the input determines not only what is written and queried, but also how strongly the memory is updated and exposed.

# Retrieval through matrix-vector multiplication

The hidden state in mLSTM is computed by using the query vector to read from the matrix memory. The unnormalized retrieved vector is

$$
\tilde{\mathbf{h}}_t = \frac{\mathbf{C}_t \mathbf{q}_t}{\max\{ |\mathbf{n}_t^\top \mathbf{q}_t|, 1 \}}.
$$

This is the core retrieval operation. The matrix $\mathbf{C}_t$ acts on the query vector $\mathbf{q}_t$ to produce a vector that summarizes the memory content relevant to the query. Because the memory is a matrix, the interaction is richer than a scalar update: the query can interact with different directions in the memory space and recover a corresponding output vector.

The hidden state is then gated by the output gate:

$$
\mathbf{h}_t = \mathbf{o}_t \odot \tilde{\mathbf{h}}_t.
$$

So retrieval produces a candidate hidden vector, and the output gate controls how much of that retrieved information is exposed to the rest of the network. This preserves the LSTM principle that memory content and visible output are not the same thing.

# Denominator normalization using query-normalizer interaction

A distinctive part of the mLSTM retrieval rule is the denominator

$$
\max\{ |\mathbf{n}_t^\top \mathbf{q}_t|, 1 \}.
$$

This quantity normalizes the retrieved vector using the interaction between the query and the normalizer state. The paper explains that the dot product between the query and the normalizer can be close to zero, so a stabilization step is needed. Without such a denominator, the retrieved output could become numerically unstable or badly scaled.

The role of this denominator is to regulate the magnitude of the retrieved content based on the accumulated strength of what has been stored. Since $\mathbf{n}_t$ records the weighted key history, the dot product with the query gives a measure of how strongly the current query aligns with the stored memory statistics. Normalizing by this interaction keeps retrieval grounded in the amount of evidence actually present in memory.

The use of the maximum with $1$ is a further safeguard. It prevents division by very small values and ensures that the normalization remains well behaved even when the query and normalizer are nearly orthogonal.

# Absolute-value and lower-bound stabilization in retrieval

The paper specifically states that it uses the absolute value of the query-normalizer dot product and lower bounds it by a threshold, typically $1.0$. This is done because the dot product can be small or even potentially unstable in sign and magnitude. By taking the absolute value, the model avoids sign-related cancellation issues in the denominator. By lower bounding it, the model avoids excessive amplification of the retrieved vector.

This stabilization is part of the broader effort to make exponential gating and matrix memory practical. The memory can be powerful, but because it relies on multiplicative and exponential components, it also needs careful numerical control. The denominator is therefore not an incidental implementation detail; it is a key part of making retrieval reliable.

In the paper’s formulation, this stabilization is analogous to the stabilizer state used for the exponential gates in sLSTM. The mLSTM uses the same stabilization ideas to ensure that the benefits of matrix memory do not come at the cost of unstable dynamics.

# Interpretation of input and forget gates as learning and decay rates

One of the important conceptual points in mLSTM is that the gates can be interpreted as learning and decay rates. The forget gate multiplies the previous memory matrix $\mathbf{C}_{t-1}$, so it acts like a decay factor: it controls how much of the old memory is retained. The input gate multiplies the new outer-product update $\mathbf{v}_t \mathbf{k}_t^\top$, so it acts like a learning rate: it controls how strongly new information is written into memory.

This interpretation connects mLSTM to the covariance update rule and to fast-weight methods. The paper makes clear that the gating is what turns the basic associative-memory update into a recurrent neural mechanism. The model can selectively keep, overwrite, or attenuate memory based on the current input and the previous hidden state.

The use of exponential gates is also important here. In mLSTM, the input gate is exponential, and the forget gate can be either sigmoid or exponential. The exponential formulation is part of xLSTM’s broader strategy for enabling storage decisions to be revised more flexibly than with standard sigmoid-only gating.

# Output gating for controlling exposed hidden state

Finally, the output gate determines how much of the retrieved memory is visible to the next layers. After the matrix memory is queried and normalized, the result is multiplied elementwise by the output gate:

$$
\mathbf{h}_t = \mathbf{o}_t \odot \tilde{\mathbf{h}}_t.
$$

This keeps the familiar LSTM separation between internal memory and exposed hidden state. The memory matrix can store a large amount of information, but the hidden state that flows forward in the network is still filtered. The output gate therefore provides control over what portion of the retrieved associative content becomes part of the model’s active representation.

In the context of xLSTM, this gating is especially important because the matrix memory is meant to support high-capacity recall without sacrificing the ability to regulate what is used downstream. The output gate ensures that the memory system remains selective, not merely expansive. It is part of what allows mLSTM to function as a controlled associative memory rather than an unbounded accumulator of retrieved content.

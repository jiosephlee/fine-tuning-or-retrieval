\title{A Textbook about the Paper: "xLSTM: Extended Long Short-Term Memory"}

Chapter 6: 6. Stabilizing Exponential Gates in sLSTM and mLSTM

# Why exponential gating can overflow during training and inference

xLSTM introduces exponential gating as a core modification to the original LSTM idea. In the paper, the input gate in sLSTM and mLSTM is replaced by an exponential function, and the forget gate may also be exponential. This change is important because it allows the model to revise storage decisions more effectively than a standard sigmoid gate. However, the paper emphasizes a practical problem: exponential activations can become very large, and large values can cause numerical overflow.

This issue is not merely theoretical. In a recurrent system, gate values are used repeatedly across many time steps, so even moderately large exponentials can accumulate into values that are too large for stable computation. Since the gates influence both the memory update and the normalization mechanism, instability in these quantities would affect the entire recurrent process. The paper therefore treats stabilization as a necessary part of making exponential gating usable in practice.

The goal of stabilization is not to change what the model computes in principle, but to reparameterize the computation so that it can be evaluated safely. In other words, xLSTM keeps the benefits of exponential gating while avoiding the numerical dangers that would otherwise come with it.

# The stabilizer state $m_t$

The paper introduces an additional state variable, denoted $m_t$, to stabilize the exponential gates. This stabilizer state is defined recursively as

\[
m_t = \max \left( \log ( f_t ) + m_{t-1}, \log ( i_t ) \right).
\]

This quantity keeps track of the relative scale of the forget and input contributions over time. The recurrence is built from logarithms of the gates, which is the key to making the stabilization work. Rather than directly manipulating large exponential values, the model compares them in log space and stores the running maximum.

Intuitively, $m_t$ acts like a reference level that follows the largest relevant gate magnitude seen so far. If the forget contribution accumulated from previous steps is large, or if the current input gate is large, then $m_t$ increases to reflect that scale. By maintaining this reference, the model can subtract off large common factors before exponentiating, preventing the raw gate values from blowing up.

The paper explicitly uses the stabilizer state as part of the gate reparameterization in both sLSTM and mLSTM. It is not an optional trick added afterward, but an essential ingredient in the definition of the stabilized gates.

# Log-domain reasoning for stable recurrent updates

The recurrence of xLSTM naturally suggests a log-domain interpretation. The memory update contains products and sums of gate values over time, and such expressions can become numerically unwieldy when exponentials are involved. The stabilizer state addresses this by representing the scale of the recurrence in terms of logarithms.

This is especially important because recurrent updates are multiplicative across time. In the stabilized formulation, the model does not directly attempt to store the full product of many exponentials. Instead, it tracks the dominant scale through $m_t$ and expresses the effective gates relative to this scale. That is why the stabilization formulas involve terms like $\log(i_t)$, $\log(f_t)$, and differences involving $m_t$ and $m_{t-1}$.

The paper also connects this design to the normalizer state in sLSTM and mLSTM. In both cases, the normalizer is designed to keep track of the total strength of the gates. Stabilization and normalization therefore work together: one prevents overflow, while the other ensures that the hidden state is properly scaled when the memory contents are read out.

# Derivation of stabilized input and forget gates

In sLSTM, the forward pass is originally defined with exponential input gates and either sigmoid or exponential forget gates. To stabilize the exponential version, the paper defines new gates

\[
i'_t = \exp \left( \log \left( i_t \right) - m_t \right) = \exp \left( \tilde{i}_t - m_t \right),
\]

\[
f'_t = \exp \left( \log \left( f_t \right) + m_{t-1} - m_t \right).
\]

These stabilized gates are constructed so that the large exponential scale is factored out through the stabilizer state. The key idea is that $m_t$ absorbs the largest relevant magnitude, and the remaining terms are brought back into a numerically manageable range.

The derivation is straightforward in spirit: if one wants to compute recurrent products of gates without overflow, one should first factor out the dominant scale. The paper does this in a recurrent way, which is why the stabilizer state depends on the previous stabilizer value $m_{t-1}$ and the current gate values. This ensures consistency over time and makes the update compatible with the recurrent structure of the model.

Importantly, the paper states that replacing $f_t$ by $f'_t$ and $i_t$ by $i'_t$ in the forward pass does not change the output of the whole network or the derivatives of the loss with respect to the parameters. This means the stabilized gates are a reparameterization, not a different model.

# Connection to numerically stable softmax-style computations

The stabilization mechanism used in xLSTM is closely related in spirit to numerically stable softmax computations. In softmax, one subtracts the maximum logit before exponentiating so that the largest exponent becomes manageable and the others are measured relative to it. This avoids overflow while preserving the result up to an exact normalization.

xLSTM uses the same general idea, but in a recurrent setting. Instead of subtracting a maximum from a fixed vector of logits, the model maintains the stabilizer state $m_t$ over time. The recurrence

\[
m_t = \max \left( \log ( f_t ) + m_{t-1}, \log ( i_t ) \right)
\]

plays a role analogous to the “subtract the maximum” trick: it identifies the dominating scale and uses it to stabilize exponentials. The stabilized gates are then computed by exponentiating quantities measured relative to this scale.

This analogy is useful because it shows that the stabilization is not an ad hoc fix. It is a principled numerical method based on the same general log-sum-exp intuition that underlies stable softmax-like computations. In xLSTM, however, the idea is applied to recurrent gating and memory updates rather than to normalization across classes.

# Why stabilization preserves functional equivalence

A central claim in the paper is that the stabilized version is functionally equivalent to the original exponential-gate formulation. More precisely, substituting the stabilized gates $f'_t$ and $i'_t$ for the original gates does not change the output of the entire network, nor does it change the derivatives of the loss with respect to the parameters.

This equivalence matters because it guarantees that stabilization is purely numerical. The model does not lose expressive power, and training does not optimize a different objective. Instead, the computation is reorganized so that the same mathematical function is evaluated in a safer way. That is exactly what is needed when a theoretically attractive mechanism, such as exponential gating, must be made practical for real training runs.

The paper emphasizes this point because stabilization would be much less useful if it altered the network’s behavior in uncontrolled ways. Here, the stabilization is designed so that the recurrence, the memory dynamics, and the gradient computations remain intact. The result is a numerically stable implementation of the same architecture.

# Implications for gradient propagation and optimization

The reason stabilization is so valuable is that xLSTM is designed to scale to large models and long sequences. In such settings, gradient behavior is crucial. Without stabilization, very large exponential gate values could make training unstable, either through overflow in the forward pass or through badly conditioned derivatives.

By keeping the gate computations within a manageable numerical range, the stabilizer state helps preserve the intended flow of information through time. This is especially important for xLSTM because the model aims to overcome limitations of standard LSTMs while retaining their recurrent strengths. A gated recurrent architecture only works well if its gates can be computed reliably over long sequences.

The paper does not present stabilization as a separate optimization technique in the abstract sense, but as a necessary step for enabling the whole xLSTM design. In that sense, stabilization supports the broader training objective: making exponential gating compatible with large-scale language modeling.

# Practical considerations for implementation

In practice, the paper applies the same stabilization technique to both sLSTM and mLSTM. In sLSTM, the stabilized gates are used in the scalar memory update and normalizer update. In mLSTM, the same stabilization is used alongside the matrix memory update and the matrix normalizer state. Thus, the stabilization mechanism is shared across both variants even though the memory structures are different.

The paper also notes that the forget gate initialization must be chosen carefully. This is listed among the model’s limitations, which indicates that stabilization alone does not eliminate all numerical sensitivity. Careful design of the gate parameters still matters for successful training.

From an implementation perspective, the stabilized formulation is useful because it turns potentially dangerous exponentials into controlled quantities. This is particularly important for long sequences, where repeated multiplication or accumulation would otherwise amplify numerical problems. The paper’s overall message is that exponential gating is viable only when paired with the stabilizer state and the corresponding normalization logic.

Finally, the stabilization is part of what makes xLSTM practical at scale. The paper’s experiments show that xLSTM can be trained effectively and can perform favorably against other modern sequence models. That result depends not just on the new memory structures, but also on the numerical care that makes the gates computable in the first place.

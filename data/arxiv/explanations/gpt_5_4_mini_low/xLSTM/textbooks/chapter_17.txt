\title{A Textbook about the Paper: "xLSTM: Extended Long Short-Term Memory"}

Chapter 17: 17. Limitations, Open Problems, and Future Directions

# Sequential Nature of sLSTM and Its Impact on Parallel Efficiency

The paper is explicit that the sLSTM inherits a fundamental limitation from the original LSTM family: memory mixing makes it sequential. In the sLSTM, the hidden state at time $t$ depends on the hidden state at time $t-1$, which means the computation cannot be fully parallelized across sequence positions. This is the same kind of recurrence that gives LSTMs their expressive power, especially for state tracking, but it also prevents the kind of fast parallel execution that makes Transformers and some state space models attractive at scale.

The paper does not present this as a fatal flaw, but rather as a tradeoff. The authors report that they implemented a fast CUDA kernel for sLSTM with GPU memory optimizations down to the register level, and that this implementation is typically less than two times slower than their parallel mLSTM implementation. Even so, the key point remains that sLSTM does not have the same parallel execution pathway as mLSTM. This means that, while sLSTM contributes valuable memory mixing behavior, it is not the ideal choice when maximizing throughput is the primary goal.

# Current Lack of Highly Optimized mLSTM Kernels

The mLSTM is designed to be fully parallelizable, but the paper also makes clear that its current implementation is not yet fully optimized. The authors state that the CUDA kernels for mLSTM are not optimized, and that the current implementation is about $4$ times slower than FlashAttention or the scan used in Mamba. This is an important limitation because it shows that the theoretical parallelizability of the mLSTM does not automatically translate into best-in-class wall-clock performance.

At the same time, the paper suggests that this gap is not intrinsic to the model design. The authors point to FlashAttention as an example of how specialized kernel engineering can dramatically improve performance. The implication is that the current mLSTM runtime reflects an implementation stage rather than a settled computational limit. For students reading the paper, this is a reminder that algorithmic efficiency and systems efficiency are related but distinct issues: a model can be structurally parallelizable while still being slow in practice if its kernels are not mature.

# Computational Burden of Matrix-Memory Operations

A central innovation of xLSTM is the transition from scalar memory to matrix memory in the mLSTM, but this comes with a clear computational cost. The matrix memory uses a $d \times d$ cell state and a $d \times d$ update, so both storage and computation are substantially more expensive than in scalar-memory systems. The paper frames this as a deliberate tradeoff: higher memory capacity is purchased at the cost of heavier matrix operations.

This burden is especially relevant because the advantage of the matrix memory is not that it is cheap, but that it is powerful. The authors emphasize that the memory update and retrieval can be parallelized using standard matrix operations and that the memory itself does not require parameters. Even so, the arithmetic intensity is high. For a reader trying to understand why mLSTM is not a simple drop-in replacement for lighter recurrent blocks, this cost is one of the main reasons. The model is promising precisely because it can store richer associations, but those associations are represented in a more demanding format.

# Sensitivity to Forget-Gate Initialization

The paper explicitly notes that the initialization of the forget gates must be chosen carefully. This is one of the few optimization-related warnings in the limitations section, and it matters because the forget gate directly controls how information is retained or discarded over time. In both sLSTM and mLSTM, the forget gate interacts with the new exponential gating and stabilization mechanisms, so an unfortunate initialization can affect the dynamics of memory accumulation and retention.

Although the paper does not provide a general recipe for solving this issue, the warning itself is important. It signals that the model’s behavior depends not only on architecture but also on the starting conditions of training. For students, this means that strong results from xLSTM should not be interpreted as automatic or trivial to reproduce without care. The model’s performance is tied to a delicate balance between gating, memory update rules, and training setup.

# Potential Matrix-Memory Overload at Very Long Contexts

The paper also raises a concern about extremely long contexts: because the matrix memory is independent of sequence length, increasing the sequence length might overload the memory for longer context sizes. This is a subtle point. On one hand, the memory does not grow with the sequence length, which is one reason xLSTM has favorable memory complexity. On the other hand, exactly because the memory is fixed in size, there is a potential limit to how much information it can accumulate as contexts become longer and more demanding.

The authors note, however, that this does not appear to be a limitation for contexts up to $16$k, based on their sequence length extrapolation experiments. So the issue is not presented as a problem already observed in the paper’s tested regime, but rather as a possible boundary condition to watch in future work. This is an important distinction: the architecture looks robust for the context lengths studied in the paper, but its behavior at substantially larger scales remains open.

# Need for Further Architecture and Hyperparameter Tuning

The paper is candid that, due to the expensive computational load of large language experiments, the architecture and hyperparameters were not fully optimized, especially for larger xLSTM architectures. This is a significant limitation because it means the reported results may not reflect the strongest possible performance of the model family. In other words, xLSTM is presented as highly promising, but not yet fully searched over in the design space.

The authors explicitly anticipate that an extensive optimization process will be needed for xLSTM to reach its full potential. That statement opens a broad set of research questions. Which block compositions work best? How should the ratio of mLSTM-based to sLSTM-based blocks be selected? How should the gating and normalization choices be tuned at scale? The paper does not answer these questions completely, but it clearly identifies them as future directions necessary for realizing the full power of the architecture.

# Open Questions on Scaling to Larger Than 1.3B Parameters

The experiments in the paper go up to $1.3$B parameters, and the authors report favorable scaling behavior up to that range. However, the paper does not claim that scaling beyond $1.3$B has been solved. Instead, it argues that the observed scaling laws suggest xLSTM should continue to perform favorably compared to Transformers and state space models as models get larger. This is a projection, not a completed demonstration.

That leaves a major open question: what happens when xLSTM is pushed well beyond the largest model size tested here? The paper’s conclusion is optimistic, but it is still based on extrapolation from scaling trends rather than direct evidence at much larger scales. For a student, this is a classic case of how empirical scaling laws are used in modern language modeling: they guide expectations, but they do not eliminate the need for further experiments at larger sizes.

# Possible Improvements in Kernels, Training Methods, and Hybrid Block Design

The paper points toward several kinds of improvements without fully developing them. On the systems side, better kernels for mLSTM are an obvious opportunity, and the authors suggest that faster kernels could be obtained in the vein of FlashAttention. On the modeling side, the architecture itself may benefit from more careful tuning, especially at larger scale. On the training side, the paper notes that some methods required precision choices that were only settled after large-scale training had already begun, which suggests that training methodology remains an active area for refinement.

The hybrid block design is also implicitly open for further exploration. The paper uses both sLSTM and mLSTM blocks, with specific ratios such as xLSTM[$a$:$b$], and observes that different mixtures can be better suited to different tasks. For example, xLSTM[1:0] performs better on the PALOMA language tasks, while xLSTM[7:1] and xLSTM[1:0] are both strong on validation perplexity. This suggests that there is no single universally best composition yet. Future work could refine how these block types are combined, how many of each should be used, and how their roles should be assigned within a network.

# Potential Applications Beyond Language Modeling

Although the paper is centered on language modeling, it explicitly points to other application domains where xLSTM may have impact. The conclusion mentions reinforcement learning, time series prediction, and the modeling of physical systems. This is consistent with the broader motivation of the paper: xLSTM is a sequence model, and the architectural changes are intended to improve its ability to store, revise, and retrieve information over time.

The paper’s broader discussion also highlights that LSTMs have historically been successful in domains such as reinforcement learning, hydrology, and other sequence-related problems. xLSTM is positioned as an extension of that lineage, not merely as a language model. The implication is that the new memory structures and exponential gating could matter anywhere long-horizon state tracking or compact but expressive memory is important. The paper does not provide experiments in these domains, so this remains a future direction rather than a demonstrated result. Still, the authors clearly view xLSTM as a general sequence modeling framework whose relevance extends beyond text.

# Concluding Perspective

Taken together, the limitations section of the paper presents xLSTM as a strong but unfinished model family. The main achievements of the paper are real: exponential gating, matrix memory, and modified residual integration improve performance and scaling. But the authors also make it clear that xLSTM is not yet fully optimized, not yet fully benchmarked at far larger scales, and not yet fully explored across all possible design choices.

That honesty is valuable. It shows how new model families are developed in practice: first by solving key structural bottlenecks, then by testing whether the resulting system can compete with established architectures, and finally by identifying the implementation and optimization work that still remains. In the case of xLSTM, the paper’s answer is encouraging: the model is already competitive, but there is still substantial room for future research.

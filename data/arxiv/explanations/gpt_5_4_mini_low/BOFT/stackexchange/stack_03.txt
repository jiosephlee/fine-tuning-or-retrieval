\title{Stack Exchange of the Paper: "Parameter-Efficient Orthogonal Finetuning via Factorization"}

### Why is a block-diagonal orthogonal matrix considered an undesirable inductive bias in OFT?
Question:
The paper argues that the original OFT becomes parameter-efficient by restricting the orthogonal matrix to be block diagonal,
$$
\mathbf{R} = \operatorname{diag}(\mathbf{R}_1, \dots, \mathbf{R}_r),
$$
where each $\mathbf{R}_i$ is a small orthogonal block. It then says this imposes a questionable assumption that neuron dimensions are split into groups by index and transformed independently.

I'm trying to understand why this is considered especially problematic. Isn't any parameter-efficient structure going to impose some bias anyway? What is special about block-diagonal structure that makes it less desirable than butterfly structure?

More concretely, if the dimensions are permuted before applying the block-diagonal matrix, would that already remove most of the problem, or is the limitation deeper than just the ordering of dimensions?
Answer:
The issue is not just that block-diagonal structure is “a bias” in the abstract; it is that it is a very *hard-coded* and *non-adaptive* bias. In the paper’s own terms, a block-diagonal orthogonal matrix assumes that the dimensions of a neuron are split into groups by index, and that dimensions in different groups should be transformed independently. That is a much stronger assumption than merely encouraging structure.

What makes this undesirable is that it limits the model’s ability to mix information across dimensions. If

$$
\mathbf{R}=\operatorname{diag}(\mathbf{R}_1,\dots,\mathbf{R}_r),
$$

then any output coordinate only depends on input coordinates inside its own block. So the transformation is “local” to each group, and no amount of learning can create direct interaction between different blocks inside that single orthogonal factor. In the paper’s information-transmission view, this means the graph is disconnected across groups: information cannot flow from one block to another. That is why the authors say it cannot construct a dense matrix and cannot recover classic dense linear transforms.

A permutation before applying the block-diagonal matrix does help somewhat, but only cosmetically. If you permute dimensions first, you are just changing which coordinates get grouped together. You are not changing the fundamental constraint that, at that layer, the transformation is still a direct sum of independent subspaces. In other words, a permutation can hide the bias, but it does not remove it: the model still only mixes within fixed-size subsets, just subsets chosen in a different order. The limitation is deeper than indexing; it is the absence of cross-group interaction.

This is exactly where butterfly structure is different. Butterfly factorization uses multiple sparse orthogonal factors with permutations/interleavings across stages, so information can move between groups over successive layers. The paper emphasizes that butterfly matrices can densely connect all input nodes to all output nodes with only $\mathcal{O}(d\log d)$ parameters, whereas block-diagonal OFT cannot do that unless the block size is essentially the whole dimension. So the butterfly structure imposes a bias too, but it is a much more flexible one: it preserves parameter efficiency while still allowing global mixing and recovering many standard fast transforms such as the Fourier and Hadamard transforms.

So the short answer is: a block-diagonal matrix is undesirable not because it has bias, but because its bias is too rigid and too local. A permutation changes the assignment of coordinates to blocks, but it does not fundamentally solve the lack of cross-block communication that the paper views as the core limitation.

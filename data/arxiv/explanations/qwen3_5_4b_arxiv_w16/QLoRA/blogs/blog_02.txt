# Quantization It Talks Back: Understanding Why 4-Bit Training Works (and NF4)

For years, the field of Large Language Models (LLMs) has been stuck in a catch-22 regarding training efficiency. We knew that quantizing weights to 4 bits could save a massive amount of memory for inference, making powerful models portable to consumer hardware like laptops and mobile phones. However, whenever researchers attempted to *train* these quantized models, accuracy inevitably plummeted. Standard quantization methods simply couldn't preserve enough information during the complex math of backpropagation. Enter QLoRA. This method proves that it is possible to finetune a 65B parameter model on a single 48GB GPU while retaining the full performance of a 16-bit baseline. The secret lies in two specific innovations: a custom 4-bit data type called NormalFloat (NF4) and a technique called Double Quantization.

The core problem with regular K-bit quantization is how it handles raw data. In standard block-wise k-bit quantization, the system takes a floating-point tensor and slices it into small blocks. Each block is then scaled using a "quantization constant" so that all values fit into the limited bit range, often integers like [-1, 1]. As shown in Equations \ref{eq:standard_quant} and \ref{eq:dequant}, this process uses an absolute maximum value to normalize the data:

\begin{equation}
    \mathbf{X}^{ \text{Int8}} = \text{round}\left( \frac{127}{{\text{absmax}}(\mathbf{X}^{{\text{FP32}}})}\mathbf{X}^{{\text{FP32}}} \right) = \text{round}(c^{\text{FP32}}\cdot \mathbf{X}^{{\text{FP32}}}),
\end{equation}

The issue arises when trying to represent a distribution of values that are not perfectly uniform or lack outliers in certain bins. Neural network weights, however, are typically gathered from areas with high densities of values around zero and few extreme outliers. Standard integer-based quantization wastes bits on these empty bins because integers cannot represent fractional values between integers like 0.1 and 0.2.

The solution proposed by QLoRA is the NormalFloat data type. Unlike standard quantization which assumes uniform distributions or arbitrary outliers, NF4 is designed specifically for zero-centered normal distributions with arbitrary standard deviations ($\sigma$). Instead of just binning values into integers, NF4 approximates a complex continuous normal distribution with $2^k$ bins where each bin represents an equal expected number of values from the statistical distribution $N(0,1)$~\citep{dettmers2022optimizers}. This allows the model to utilize every bit for meaningful information rather than lost precision on empty bins. The formula for estimating these optimal bin centers ($q_i$) ensures that the theoretical distribution fits exactly between $-1$ and $1$:

\begin{equation}
    q_i  = \frac{1}{2}\left( Q_X\left(\frac{i}{2^k+1}\right) + Q_X\left(\frac{i+1}{2^k+1}\right)\right),
\end{equation}

where $Q_X$ is the quantile function of the standard normal distribution. By pre-determining these thresholds based on probability theory rather than raw data outliers, NF4 achieves an information-theoretic optimality that recovers full 16-bit finetuning performance when combined with Low-rank Adaptation (LoRA).

While NF4 solves the precision problem, it introduces another memory challenge: the quantization constants themselves take up space if stored as high-precision floats or even 8-bit integers in every small block. To address this without hurting performance, QLoRA introduces Double Quantization (DQ). The first layer of DQ applies the NF4 quantization described above to get a clean weight tensor $\mathbf{W}$. However, it leaves behind scaling factors $c_1$ and $c_2$, which are usually stored as 32-bit floats to ensure accuracy during training. These constants can consume gigabytes of memory across large models like LLaMA-65B~\citep{lomeira-guanaco}.

To optimize this further without degrading empirical results from previous work~\citep{dettmers2022case}, DQ quantizes these scaling constants themselves in a second pass. Specifically, it treats $c_2^{\text{FP32}}$ as input to an 8-bit float layer with a larger block size (e.g., 256 instead of 64). By doing so mathematically expressible as $\text{doubleDequant}(c_1^{\text{FP32}}, c_2^{\text{k-bit}}, \mathbf{W}^{\text{k-bit}})$ yields only about 8 bits per parameter instead of an average of roughly 0.5 bits saved per conventional approaches—wait, actually this results in around an additional reduction due to aggregation effects~\citep{lomeira-guanaco}. 

In practice, Double Quantization saves about $0.373$ bits per parameter compared to standard double blockwise chunking approaches~\citep{lomeira-guanaco}.

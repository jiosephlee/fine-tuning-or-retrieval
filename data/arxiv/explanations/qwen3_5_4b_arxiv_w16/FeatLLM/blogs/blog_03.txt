\title{Blogs about the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

# Beating Senseless Complexity: How FeatLLM Handles Table Size Limits

The integration of Large Language Models (LLMs) into tabular learning has been a thriving field, promising to unlock the power of prior knowledge for complex prediction tasks. However, a significant practical barrier remains the physical constraints of LLM training pipelines. Many modern datasets contain hundreds or even thousands of features. When researchers attempt to serialize this data into a text format for an LLM prompt—as is often done with approaches like STUNT or TabLLM—the resulting context window is immediately exceeded. This forces models to truncate data, lose critical information, or resort to computationally expensive per-sample inference that simply cannot scale to large feature sets.

In this blog post, we explore how the \textsf{FeatLLM} framework addresses this issue not by brute-forcing more compute, but by fundamentally changing the workflow through intelligent feature engineering and statistical ensemble techniques. By treating the LLM as a "feature engineer" rather than a direct predictor, \textsf{FeatLLM} solves the prompt size problem dynamically at inference time using a method borrowed from statistics known as bagging.

To understand the solution, we first need to appreciate why standard approaches fail at scale. Traditional few-shot learning with LLMs typically requires feeding the ground truth samples and feature descriptions directly into the model response. For a dataset with 500 features, this creates a massive input string that violates the context limits of models like GPT-3.5 or similar APIs. While some methods have attempted to handle this by aggregating data before sending it to the model, they often degrade in accuracy because the model obscures fine-grained details necessary for accurate reasoning.

\textsf{FeatLLM} introduces a novel paradigm where the LLM does not predict the output for each sample directly. Instead, it analyzes a small dataset to generate high-quality rules—logical conditions that determine class membership—without needing to input every single sample detail at once. These natural language rules are then parsed and executed as Python code to create binary features for the actual test set.

Crucially, \textsf{FeatLLM} employs bagging to maintain performance even when input data is too large for standard prompts. In traditional statistics, bagging reduces variance by training multiple models on random subsets of data and averaging their results (\$\texttt{Bag} = \frac{1}{T}\sum_{t=1}^{T}\mathbf{p}[t]\$). The authors adapt this strategy here to mitigate prompt size limits and improve rule reliability through self-consistency (\$\mathbf{w}[t]\$). The process works as follows:

*   **Trialing:** The framework performs $T$ trials (typically set at 20 in experiments) where each trial operates on a randomized subset of rows (instances) from the dataset.
*   **Subsampling:** By processing different selections of instances in each trial combined with randomized prompt demonstrations, the effective input length per trial remains manageable within context window limits ($N < N_{max}$).
*   **Diversity Injection:** High temperature setting and randomized prompt ordering introduce necessary noise into the generation process so that single trials do not converge on identical outputs due to noise artifacts (\$\{\mathbf{x}, \mathbf{y}\}$).
*   **Ensembling:** The resulting predictions from all trials are averaged together ($\mathbf{p}^i_{(avg)} = \frac{1}{T}\sum_{t=1}^{T}\mathbf{p}[t]$), which combines weak learners into a robust final model while compensating for incorrect rules generated in any single trial (\$\{\mathbf{w}[t]\}_{t=1}^T\$).

This approach allows \textsf{FeatLLM} to effectively ignore irrelevant columns and maintain performance even on datasets with over 100 attributes—a feat many other methods struggle with due solely to context constraints. By leveraging prior knowledge within few-shot rules rather than raw data volume in every query step, it achieves significant speedups; notably reducing inference time compared to methods that make one API call per sample while simultaneously overcoming the computational bottleneck of dimensionality expansion.

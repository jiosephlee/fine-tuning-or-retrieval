# How to Mine 120 Billion Math Problems from the Web (And Why It Works)

One of the most significant bottlenecks in scaling Large Language Models (LLMs) for complex reasoning is the availability of high-quality training data. While creators often look to curated academic repositories or specialized aggregators for math problems, a new open-source approach suggests that the most valuable data might already exist in plain sight within the public web. DeepSeekMath demonstrates that by mining Common Crawl and applying simple machine learning techniques, it is possible to construct a massive corpus containing 120B math tokens that rivals or exceeds the performance of existing datasets. This post breaks down exactly how this was achieved and why treating scraped web pages as a primary data source can be superior to relying solely on academic papers.

The foundation of this success lies in the construction of the DeepSeekMath Corpus, a dataset built specifically from Common Crawl. Unlike previous approaches that simply filtered Common Crawl using keyword matching, which often results in low-quality or noisy data, DeepSeekMath employed a rigorously engineered data selection pipeline. The process began with a seed corpus, consisting primarily of high-quality mathematical web texts from OpenWebMath. Using this seed, researchers trained a fastText classifier model \citep{joulin2016fasttext} to distinguish between mathematical content and general web noise. The fastText model was configured with specific hyperparameters: a vector dimension of 256, a learning rate of 0.1, and n-gram lengths up to 3 \citep{fasttext}. This allowed the model to learn semantic similarities between mathematical phrases found in high-quality sources and random text scraped from the internet.

The core innovation of this pipeline is its iterative nature. Instead of a one-shot filtering pass that might miss rare but relevant domains, the system continuously refined its own knowledge base. In the first iteration, the model collected data based on its initial understanding of "math." If portions of Common Crawl remained uncollected after this first pass, it indicated gaps in its search because its initial training examples lacked diversity. To address this, researchers identified new seed domains by analyzing coverage statistics across disjoint domains in Common Crawl \citep{disjoint_domains}. Domains where over 10\% of pages were collected were flagged as math-related; for example, sites like ``mathoverflow.net'' would be identified as targets for expansion.

Within these flagged domains, contributors manually annotated URLs associated with mathematical content, such as specific question pages on MathOverflow. These new URLs were added back into the seed corpus alongside previous examples. The fastText model was then retrained on this expanded set of positive examples \citep{domain_diversity}. This cycle repeated several times: collect more diverse positive samples based on previous successes $\rightarrow$ retrain $\rightarrow$ mine broader web sources $\rightarrow$ refine manually $\rightarrow$ retrain \footnote{The full pipeline details are illustrated in Figure \ref{fig:data_collect} of the paper }. By the fourth iteration, this method successfully aggregated 35.5 million mathematical web pages, totaling 120B tokens far larger than previous specialized corpora like OpenWebMath \citep{openwebmath} or Proof-Pile-2 \citep{llemma}.

Beyond simple scale and diversity, the quality of the DeepSeekMath Corpus is arguably higher because it relies on lightweight semantic classification rather than heuristic string matching or time-consuming human curation at every step \footnote{The filtering logic is detailed in Section \ref{sec:data_decontamination}}. The team implemented decontamination measures immediately after collection to prevent benchmark contamination \citep{benchmark_contamination}. They used exact and partial matching criteria (specifically checking for shared subsequences longer than 7 words) to remove segments from well-known benchmarks like GSM8K and MATH before they ever touched training data \citep{deepseek-coder}. This rigorous cleaning ensures that when models are evaluated later using these benchmarks, results reflect true capability rather than memorized training patterns.

# Why 'Code Training' Might Be the Secret Ingredient Your Model Needs

In the fast-evolving landscape of large language models, the question of whether coding training improves general reasoning has long been a subject of debate. The hypothesis suggested that exposure to structured logic in code would naturally transfer benefits to mathematical deduction. However, a new study by DeepSeekMath challenges previous findings, presenting compelling evidence that code training acts as a critical catalyst for mathematical reasoning, particularly when applied before math-specific training.

DeepSeekMath introduces a fascinating experimental design that isolates and validates this relationship. The authors utilized an efficient 7-parameter model to test two distinct training scenarios. In the first scenario, known as two-stage training, the base model was exposed to 400 billion tokens of code data followed by 150 billion tokens of math data. In the second scenario, an identical process was repeated using general language tokens instead of code tokens at the initial stage. The results were unequivocal: models pre-trained on code demonstrated significant improvements in solving mathematical problems using tools or Python programming libraries alone, whereas models initialized with general tokens failed to achieve the same level of performance.

This advantage was not limited to tool-assisted reasoning. Even when solving problems solely through step-by-step text explanations without external calculators or code execution, models that underwent code prior training consistently outperformed their counterparts trained only on general web data. The study further explored whether this benefit could be achieved in a single-stage approach by mixing code and math tokens. While this mixture successfully mitigated catastrophic forgetting—preventing the model from losing reasonable coding skills while learning math—it slightly compromised performance on pure mathematical reasoning compared to the highly specialized two-stage approach.

The findings suggest a specific mechanism behind this improvement: code training appears to enhance the model's ability to structure complex logical flows efficiently. Unlike general language data which can be coherent yet structurally loose, code requires rigorous syntax and logical consistency even for trivial operations. This likely trains the underlying transformer architecture to handle multi-step dependencies with higher precision, a skill directly transferable to solving complex word problems or formal proofs in mathematics.

Furthermore, the research provides clarity on a common pitfall in model architecture design often referred to as catastrophic forgetting. # Simplifying Reinforcement Learning: The Case for Group Relative Policy Optimization (GRPO)

If you have followed the recent surge in large language model (LLM) performance, you likely know the struggle associated with training them. While Supervised Fine-Tuning (SFT) teaches models to follow instructions, pushing them to solve complex mathematical problems often requires Reinforcement Learning from Human Feedback (RLHF) or its variants. The gold standard for this has been Proximal Policy Optimization (PPO), an algorithm that excels but is notoriously heavy. To stabilize training, PPO relies on a "critic" model—a separate neural network that must be trained alongside the policy model to estimate values and calculate advantages. This architecture demands significant memory and computational resources, making it a bottleneck for developers running experiments. Today's research introduces **DeepSeekMath**, which utilizes **Group Relative Policy Optimization (GRPO)**, a streamlined variant designed to strip away the critic while maintaining, and even improving upon, mathematical reasoning capabilities. The result is a training paradigm that is more efficient, cheaper to run, and surprisingly effective on benchmarks like the competition-level MATH dataset.

At its core,研究生的 traditional RL approach struggles because it tries to predict the absolute error of a response against a learned value function. In practice fine-tuning LLMs, this hallucinates noise or fails to capture nuance because the value function itself is another large model that needs updating. GRPO flips this script by eliminating the critic entirely. Instead of predicting where a solution ends up relative to an external yardstick, GRPO looks inward at a group of diverse answers generated by the same policy model in response to a single question. Imagine asking an AI graduate math problem; instead of expecting one perfect answer, the AI generates six different drafts ($o_1$ through $o_6$). Within this specific group, some answers are clearly better than others based on their final score from a reward model. GRPO uses these internal comparisons—specifically the average and standard deviation of rewards within that group—to normalize future steps as if there were an absolute baseline. This allows it to distinguish between "very good" and "slightly good" without ever needing a separate critic network running in parallel during training.

The mathematical elegance of GRPO lies in how it calculates these advantages using only relative rewards within each generated group $G$. The objective function simplifies PPO's complexity by removing terms related to global value estimation and complex KL penalties during the reward calculation phase. Instead, it directly incorporates an unbiased estimator for KL divergence into the loss function itself, ensuring stability without adding massive overhead. When normalized using group statistics ($\hat{A}_{i,t}$), the algorithm updates the policy based on how each token in one output compares favorably or unfavorably against its peers in the same cohort. This relative approach aligns naturally with how reward models already operate; they are typically trained on comparisons rather than absolute scores, meaning GRPO creates a smoother gradient update that requires less aggressive constraints to prevent "model collapse." By foregoing the resource-intensive critic model, researchers reported that DeepSeekMath could enhance its instruction-tuned version on MATH and GSM8K datasets using fewer computational passes and significantly lower memory footprints in memory usage during training operations \citep{deepseek-math}.

The practical impact of this simplification is immediately apparent when we look at performance metrics without sacrificing robustness. Previous studies showed that dropping from heavy PPO训练 leads to stagnation, but DeepSeekMath demonstrates that GRPO can significantly boost performance even when starting from strong instruction-tuned baselines like DeepSeekMath-Instruct 7B \citep{deepseek-math}. On benchmarks ranging from elementary arithmetic to advanced college-level calculus problems in English and Chinese variants like CMATH \citep{wei2023cmath}, the model consistently outpaces previous open-source iterations \citep{wizardmath}. Specifically on the MATH benchmark combining chain-of-thought reasoning with tool usage where external python execution is allowed via program-of-thought prompting \citep{pot}, the accuracy reaches approximately 51.7\%, approaching proprietary closed-source models like GPT-4 while staying lightweight itself \citep{deepseek-math}. More importantly for open research communities small teams who might not have clusters capable of running full PPO pipelines can now iterate faster on RL strategies for math problems because bulk data gathering and running baselines has been streamlined by removing redundant components like value network training \citep{deepseek-math}.

However relying solely on relative outcomes within groups ($\hat{A}_{i,t} = \widetilde{r}_i$) presents challenges regarding whether it truly drives deeper reasoning improvements rather than just selection bias toward specific valid outputs found in fine-tuning examples \citep{deepseek-math}.

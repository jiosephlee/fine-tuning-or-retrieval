\title{Stack Exchange of the Paper: "The Era of 1-bit LLMs: All Large Language Models are in 1.58 Bits"}

### Why does adding the value 0 to the ternary weights {-1, 0, 1} allow the representation to reach 1.58 bits instead of just 1 or 2 bits?
Question:
The abstract states that BitNet b1.58 uses ternary weights {-1, 0, 1} and calls this '1.58 bits'. However, in standard information theory, a ternary state (3 levels) would occupy $\log_2(3) \approx 1.585$ bits. But isn't this mathematically just rounding $\log_2(3)$? I understand that the paper refers to it as '1.58', but is there a specific reason to stop at this decimal approximation? If I have a weight of -0.5 which rounds down to -1, does that mean I'm wasting half a bit's worth of information compared to a binary system where I can't represent that intermediate state? Can someone explain if '1.58 bits' is a precise theoretical claim or just a label for the ternary alphabet?
Answer:
The designation "1.58 bits" in BitNet b1.58 is indeed grounded in standard information theory, and it represents the theoretical entropy of a ternary (3-level) symbol system rather than a labeling convention for a binary system or an arbitrary rounding.

The value 1.58 is derived from the logarithm of the size of the alphabet used to represent each weight parameter. In BitNet b1.58, every weight $W_{ij}$ is constrained to the set $\{-1, 0, 1\}$. According to Shannon's information theory, the amount of information $H$ contained in a discrete source with $M$ possible equiprobable outcomes is given by $\log_2(M)$ bits. Since this model uses a ternary alphabet ($M=3$), the maximum information capacity per weight parameter is exactly $\log_2(3)$, which calculates to approximately $1.584962...$ bits. This value explains why the paper refers to the architecture as "1.58 bits"; it is numerically approximating the theoretical limit of information density achieved by using three distinct values instead of just two (binary).

Your intuition regarding intermediate values like $-0.5$ is mathematically sound but misapplied to this specific architectural constraint; adding 0 does not introduce intermediate states like $-0.5$, nor does it waste half a bit. The transition from the original 1-bit design (weights $\{-1, +1\}$) to BitNet b1.58 involves expanding the discrete alphabet from a binary set ($M=2$) containing $\log_2(2)=1$ bit of information to a ternary set ($M=3$). By equipping each parameter with an additional "zero" option, the model gains enough expressive power to effectively utilize 3 distinct states per parameter, thereby matching its information capacity to $\log_2(3)$ bits rather than being limited to 1 bit. This expansion allows the weights to encode richer features—such as the explicit filtering capability mentioned in the abstract which turns off connections entirely via zero—without requiring floating-point precision or higher bit-widths like 3-bit systems ($\log_2(4)=2$).

Therefore, calling the weights "half two" or "almost two" would also be technically accurate in binary terms ($\approx 1.96$ bits for four states including zero), but "1.58 bits" provides a more precise description that aligns directly with entropy calculations ($\log_2(3)$). The paper uses this specific terminology to emphasize that while these are low-bit integers suitable for hardware optimization similar to 1-bit systems, they theoretically offer an information density closer to $16/9$ bits than traditional binary models do, enabling performance parity with 16-bit floats while maintaining integer-only compute operations as described in their design involving rounding and clipping functions.

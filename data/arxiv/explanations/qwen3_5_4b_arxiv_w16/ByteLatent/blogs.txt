# Patches Over Tokens: How Dynamic Compute Allocation is Reshaping LLM Architecture

The landscape of Large Language Model (LLM) development has long been dictated by a single, rigid preprocessing step: tokenization. Standard models like Llama 3 rely on a finite vocabulary where raw bytes are mapped to symbols before entering the model. While this heuristic compression has worked well at scale, it introduces a fundamental inefficiency. Every token, regardless of the complexity of the data it represents, demands the same amount of computational power. This static approach means that models waste resources predicting easy outputs while straining to process difficult ones.

A new architecture challenges this paradigm with the Byte Latent Transformer (BLT). Instead of preprocessing text into a fixed set of tokens, BLT operates directly on raw byte sequences but groups them into what they call "patches." The revolutionary aspect of BLT is not just the use of these patches, but how they are formed and processed. By utilizing entropy-based patching, BLT dynamically allocates computational resources exactly where the data is most complex. This shift represents a move from uniform processing to variable compute allocation, promising significant gains in efficiency and robustness without sacrificing performance.

### The Cost of Static Vocabulary

To understand the problem BLT solves, one must look at why modern LLMs rely on tokenizers like Byte Pair Encoding (BPE). Tokenizers reduce byte sequences into symbols drawn from a pre-defined dictionary. For example, instead of processing 20 individual characters for a common word, the model sees a single token. However, this compression is not based on prediction difficulty; it is based on character frequency. As a result, highly complex concepts often remain as long sequences of tokens that require multiple attention steps to resolve, while simple characters are compressed into single tokens that still trigger full processing layers.

In traditional architectures, the computational cost for decoding a sequence is summed across every single token. The size of these tokens does not typically vary enough to significantly alter the sheer number of computation steps required. Increasing vocabulary size can increase token merging but also expands embedding table dimensions and projector layers, creating trade-offs that limit how much efficiency can be gained from simply changing word boundaries. BLT transcends these constraints by eliminating fixed vocabularies entirely. Any group of bytes can form a patch during inference; there are no hidden rules or learned subword boundaries dictating where one unit ends and another begins.

### Entropy-Based Dynamic Patching

At the heart of BLT's efficiency lies its ability to segment data based on information density rather than syntactic rules or fixed counts. The paper introduces "entropy patching," which uses a lightweight byte-level language model to estimate prediction uncertainty for every position in the input sequence. After each byte \( x_i \), an entropy value is calculated:

\[
H(x_i) = \sum_{v \in \mathcal{V}} p_{e}(x_i=v|\pmb{x}_{<i}) \log p_{e}(x_i=v|\pmb{x}_{<i})
\]

Here, \( p_e \) represents the probability distribution over the byte vocabulary \( \mathcal{V} \) conditioned on previous context: \( H(x_i = v|\pmb{x}_{<i}) \). A low entropy value indicates high predictability (low uncertainty), meaning little computation is needed to correctly guess that byte in its context. Conversely, high entropy indicates ambiguity or lack of pattern recognition in that specific spot, signaling that more computational capacity should be reserved for resolution (e.g., introducing new content).

### Flexible Layering and Inference Efficiency

Because BLT allocates compute dynamically during inference based on entropy thresholds \( H(x_i) > \theta_g \), it can choose longer patches when data is predictable and break into shorter patches when uncertainty rises (such as at sentence beginnings or new topics). This dynamic grouping changes how we view cost and scaling metrics like FLOPs per byte given in Equation 8:

\[
\text{FL}_{\text{{\textsc BLT}}} = [\text{Transf. FL}(h_{\mathcal{G}}, l_{\mathcal{G}}, m=n_{ctx}/n_p,V=0) / n_p] + [\text{Transf. FL}(h_{\mathcal{E}}, l_{\mathcal{E}}, m=w_{\mathcal{E}}, V=0)] + [\text{Transf. FL}(h_{\mathcal{D}}, l_{\mathcal{D}}, m=w_{\mathcal{D}}, V=256)] + [\ldots]
\]

The global latent transformer \( G \), which processes patches rather than individual bytes, accounts for significantly more layers than local encoders or decoders (\( l_G >> l_E \)). Fewer steps through this heavy global model means fewer FLOPs overall for those predictable sections compared to standard models that must process every byte through heavy attention mechanisms regardless of complexity. # Why Raw Bytes Might Be Smarter Than Subwords: The Case for Byte-Large Language Models

In the race to build larger and more capable人工智能, most large language models rely on tokenization. Pioneered by researchers like Sennrich et al., tokenizers such as Byte-Pair Encoding (BPE) map sequences of raw bytes into a finite set of subword units. While this heuristic compression has been essential for managing massive datasets, recent research suggests that pretorting data into fixed vocabulary tokens may be introducing unnecessary biases. By bypassing these pre-processing steps in favor of raw byte processing, we can achieve models that compete with tokenization-based architectures while offering superior efficiency and robustness. This brings us to the Byte Latent Transformer (BLT), an architecture that fundamentally rethinks how models process information by working directly with the underlying bytes.

At its core, BLT introduces a dynamic mechanism for grouping bytes into patches rather than relying on a static vocabulary. Unlike tokenizer-based models where every token receives the same amount of computational effort regardless of its complexity, BLT allocates compute where it is needed most. The key innovation lies in entropy patching, a method that segments data based on the uncertainty of the next byte prediction. This allows the model to identify regions of high information density and allocate more latent transformer steps to them, while treating predictable sequences with minimal compute. This dynamic allocation fundamentally changes the trade-off between performance and speed-up-time, enabling models that are significantly more efficient at inference without sacrificing scale-up accuracies.

The theoretical advantages of modeling raw bytes extend far beyond just saving FLOPs during inference. By avoiding the abstraction layer of tokens, BLT retains a granular understanding of character-level details that subword tokenizers often smooth over or lose entirely. This direct access to orthographic details reveals distinct capabilities in tasks involving phonology and manipulations at the sequence level. # The New Scaling Law: Doubling Model Size Without Increasing Inference Cost

For most large language model analysts, the scaling law is baked into the relationship between parameters and compute budget. For practitioners, it's a function of inference latency and cost. But BLT offers something new: it allows you to scale model capacity without increasing inference cost. This isn't a gain through iteration; it's a gain through architecture.

The fundamental bottleneck in standard LLMs is that they treat every token equally. A Transformer computes attention over every token, regardless of whether that token provides clarifying context or merely fills space. Patches scale better than tokens because, unlike tokenization, they learn the complexity of the data rather than relying on compression heuristics. By dynamically allocating compute based on the entropy of predictions, BLT delivers concise computation where it matters most: across inputs and outputs.

The core mechanism driving this efficiency is dynamic patching inspired by entropy data. Traditional approaches like BPE rely on a fixed vocabulary determined prior to training, whereas BLT's entropic patching function determines boundaries based on the next-byte prediction entropy $H(x_i) = \sum_{v \in \mathcal{V}} p_{e}(x_i=v|\pmb{x}_{<i}) \log p_{e}(x_i=v|\pmb{x}_{<i})$. Unlike static chunking methods that waste compute on repetitive text or miss dense information in code or math, BLT allocates larger patches when data is predictable and smaller patches where data complexity demands it. This approach ensures that harder predictions—which often occur at sentence boundaries—receive precisely the compute they need to be resolved correctly.

This architectural choice unlocks a unique dimension for scaling: simultaneous growth in both parameters and patch size within a fixed inference budget. Because inference cost is inversely proportional to average patch size, larger patches save compute that can be reallocated to grow the global latent transformer layers $l_{\mathcal{G}}$. In practice, this means we can run two models under identical cost constraints: one running many steps with small tokens, and one running fewer steps with large patches. Our scaling studies reveal that models trained with larger patch sizes consistently outperform their token-based counterparts in both training flop-controlled regimes and fixed inference setups up to 8B parameters and 4 trillion bytes of data.

The benefits extend beyond raw efficiency into robustness and long-tail generalization. By training directly on raw bytes without a fixed vocabulary, BLT bypasses the orthographic biases introduced by subword tokenizers like BPE. This raw byte-level understanding translates directly into stronger performance on character-aware tasks such as CUTE benchmarks where spelling manipulation plays a key role, low-resource machine translation across diverse scripts, and phonology tasks requiring grapheme-to-phoneme conversion.

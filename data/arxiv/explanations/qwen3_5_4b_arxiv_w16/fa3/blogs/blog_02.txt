# The Secret to FP8's Accuracy: Why Your Model Isn't Losing Memory

In the race to make long-context language models faster and more efficient, reducing precision has become a primary lever for performance. Shifting attention computations from standard 16-bit floating point (FP16) or Model context bias Floating Point (BF16) down to 8-bit floating point (FP8) can theoretically double the throughput of Tensor Cores while drastically reducing memory bandwidth requirements. However, this seemingly simple step introduces significant mathematical risks. The quantization of high-dimensional vectors often results in sharp errors when data contains "outliers"—extreme values that are common in large-scale language models. Without careful handling, these outliers can dominate the softmax calculations, rendering the model's attention mechanism biased and inaccurate. Recent advances, specifically \textsc{FlashAttention-3}, reveal that modern GPUs like the NVIDIA Hopper architecture support specific techniques to mitigate these errors without sacrificing the massive speed gains of FP8. By utilizing block quantization and incoherent processing, we can preserve numerical fidelity while achieving computational speeds close to 1.2 PFLOPs/s.

To understand why these techniques work, we must first look at the fundamental challenge of quantizing attention scores. In standard deep learning workflows, when preparing data for low-precision operations like FP8 GEMMs (General Matrix Multiplication), researchers typically rely on per-tensor scaling. This involves calculating a single scale factor for an entire matrix (such as $Q$, $K$, or $V$) based on its statistical range. While this approach is computationally cheap to implement, it is inherently fragile in the context of attention. A standard per-tensor scale treats all variations within a token sequence equally. If a sequence contains a few extremely large values relative to the rest—outliers caused by uncertainty propagation or specific input patterns—the quantization resolution is dominated by these few extreme points. The majority of the tokens, which contain the fine-grained semantic relationships needed for reasoning over long contexts, get "squashed" together due to lack of resolution in the lower bits of their mantissa. This effectively erases subtle distinctions between context words, leading to degrading model performance as sequence lengths grow.

The first major solution proposed in \textsc{FlashAttention-3} is block quantization, which acts as a micro-calibration mechanism for every chunk of data processed by the GPU hardware. Instead of applying one global scale factor to an entire layer or matrix, this method calculates and stores one scalar specifically for every block of data processed during individual steps of the attention computation. In \textsc{FlashAttention-3}, because the algorithm is designed around tiling $Q$, $K$, and $V$ matrices into discrete blocks that fit into shared memory stages, this alignment occurs naturally within the kernel structure. As opposed to applying a premature scalar before launching any computation, one introduced overhead in other systems, \textsc{FlashAttention-3} updates or scales each block internally right before feeding it into the WGMMA instruction stream. This ensures that even if a specific block contains outlier values relative to its neighbors in time or space, it receives appropriate dynamic scaling before being converted to FP8 formheets\. Consequently, most subsequent blocks maintain sufficient resolution where they matter most—within their own localized context windows—preventing the global bleed-through of error that characterizes per-tensor approaches after rounding introduces significant numerical failure modes within \textsc{FlashAttention-3}.

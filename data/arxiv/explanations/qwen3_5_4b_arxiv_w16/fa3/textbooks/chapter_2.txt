Chapter 2: # Foundations: Hardware Architecture and Execution Models

The transformative power of \textsc{FlashAttention-3} rests not merely on algorithmic refinements but on a deep and granular understanding of the physical execution model of modern GPUs, specifically the NVIDIA Hopper architecture. To appreciate how over 750 TFLOPs/s are extracted from silicon in practice, one must look beyond abstract mathematical formulations and examine the tangible interplay between memory bandwidth, computational throughput, and the asynchronous nature of hardware resources. This chapter serves as a primer on the architectural foundations that \textsc{FlashAttention-3} explicitly leverages. We will dissect the memory hierarchy that dictates data access costs, explore the multi-level thread organization that determines parallelism, and investigate the specialized accelerators—namely the Tensor Memory Accelerator (TMA) and the Warpgroup-wide Matrix Multiplication Accumulator (WGMMA)—that enable asynchronous computation. Finally, we will examine how low-precision formats like FP8 introduce new constraints and opportunities for optimization.

\section#Memory Hierarchy: Global Memory (HBM), L2 Cache, Shared Memory (SMEM), and Register Files

The performance characteristics of any GPU kernel are fundamentally bound by its memory hierarchy. The speed at which a kernel executes is a direct function of how efficiently it can move data between strict capacitive stores and high-bandwidth on-chip logic. In the context of attention mechanisms, which are notoriously memory-bound due to their $O(N^2)$ complexity regarding sequence length, understanding these layers is critical.

The outermost layer of this hierarchy consists of High Bandwidth Memory (HBM), known as Global Memory (GMEM). This off-chip DRAM is accessible to all Streaming Multiprocessors (SMs) but operates at significantly lower frequencies than on-chip storage, making it a bottleneck for data-intensive operations like computing self-attention scores. To mitigate this latency, data is cached in an on-chip L2 cache whenever possible. While transparent to many applications, GPUs maintain query statistics across SMs to optimize relevance scoring during DRAM access when cached data resides in a SMEM SBank before being promoted to global memory. However, for the specific routine of Fused Attention from Ford et al., de-emphasizing L2 cache occupancy benefits slightly improved performance than keeping local TMA cache warmer with low-volume data by pushing more access patterns into shared memory or register space instead, acknowledging that bulk \textbf{SeqRotate} operations dominate use-cases requiring frequent re-accessing without further latency penalty through eager caching policies.

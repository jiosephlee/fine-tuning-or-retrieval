# FlashAttention-3: Accelerating Attention with Asynchrony and Low-Precision

## Introduction and Context

The Transformer architecture has become the foundational backbone of modern artificial intelligence, particularly in large language models (LLMs), where the attention mechanism serves as the primary computational bottleneck. Attention scales quadratically with sequence length ($N$), making it prohibitively expensive for tasks involving long contexts, such as reasoning over multiple documents, parsing large codebases, or analyzing high-resolution audio and video. As applications move toward handling these longer sequences to capture comprehensive information or maintain user history, the demand for faster and more efficient attention implementations becomes critical. While early software optimizations focused on reducing memory traffic, recent advances have revealed that future hardware capabilities offer a path to achieving significantly higher throughput.

The roadmap for optimizing attention has evolved through a series of seminal contributions. The original \textsc{FlashAttention} introduced a novel tiling strategy that eliminates intermediate reads and writes to slow global memory by fusing attention operations into a single kernel. However, subsequent developments show that diminishing returns are set in as hardware accelerates. \textsc{FlashAttention-2} restructured the algorithm to parallelize over both the batch size and the sequence length dimension, optimizing occupancy on GPU Streaming Multiprocessors (SMs). Despite these architectural improvements, \textsc{FlashAttention-2} achieves only about 35\% utilization on Hopper H100 GPUs when compared to optimized general matrix multiplication (GEMM) kernels which reach 80-90\% utilization. This discrepancy highlights a fundamental gap: previous algorithms adhere to a simplified synchronous execution model and do not explicitly exploit new hardware features present in Hopper architecture.

The objective of \textsc{FlashAttention-3} is to bridge this gap by integrating knowledge of Hopper-specific capabilities—specifically asyncronous execution units and low-precision tensor cores—into the high-level design of attention algorithms. Rather than merely running existing synchronous kernels faster, \textsc{FlashAttention-3} redesigns the algorithm to overlap computation and data movement and to leverage Hardware-accelerated low-precision GEMM (FP8). By achieving 75\% Tensor Core utilization in FP16 and approaching 1.2 PFLOPs/s in FP8, \textsc{FlashAttention-3} demonstrates that specialized architectural understanding is essential for unlocking the full potential of next-generation AI workloads. The following sections will detail how these techniques are realized programmatically and mathematically within the transformer framework.

## Hardware Landscape

To understand why \textsc{FlashAttention-3} represents a paradigm shift from its predecessors, it is necessary to examine the specific characteristics of modern GPU architectures, particularly NVIDIA's Hopper architecture compared to earlier generations like Ampere. The efficiency of any high-performance kernel is determined by how well it utilizes the available silicon resources, specifically focusing on memory hierarchy dynamics and specialized compute units.

Modern GPUs operate as throughput processors relying on concurrency and asynchrony to hide latencies inherent in memory access operations. The memory hierarchy is strictly organized: data resides globally on High Bandwidth Memory (HBM) accessible to all Streaming Multiprocessors (SMs). This data is transparently cached into an L2 cache before entering smaller, programmer-managed on-chip caches called shared memory (SMEM) within each SM, and finally into private register files within each thread context. A critical latency arises during data movement from GMEM (DRAM style) to SMEM; if compute units must wait for this transfer before performing mathematical operations, overall system performance suffers significantly due to serialization of computation stages.

Previous GPU architectures like Ampere introduced specific optimizations for matrix multiplication via Tensor Cores but maintained a synchronous relationship between memory transfers and computation logic within their programming models. This synchronization forces a "stop-and-wait" behavior where compute units must halt while Tensor Memory Accelerators (TMA) transfer data blocks from HBM to SMEM. # Foundations: Hardware Architecture and Execution Models

To appreciate how over 750 TFLOPs/s are extracted from silicon in practice, one must look beyond abstract mathematical formulations and examine the tangible interplay between memory bandwidth, computational throughput, and the asynchronous nature of hardware resources. # Algorithmic Innovation I: Producer-Consumer Asynchrony

The acceleration of neural network training and inference on GPUs has historically been governed by the tension between massive computational throughput provided by Tensor Cores and the latency inherent in moving data from high-capacity global memory (HBM) to the restricted registers and shared memory of compute units. In previous iterations of attention optimization, such as \textsc{FlashAttention-2}, the software stack operated under a simplifying assumption: that operations performed by different parts of a kernel were synchronous and that latencies in data movement could not be effectively overlapped with computation. Specifically, a producer warp responsible for loading Key and Value blocks from HBM into shared memory would frequently encounter latency stalls when the Tensor Memory Accelerator (TMA), a dedicated hardware unit for high-bandwidth memory transfers, was delayed. Simultaneously, consumer warps responsible for executing the Matrix Multiplication (GEMM) operations would sit idle if they could not access the required data in shared memory. This synchronous coupling prevented the GPU from utilizing its full thread capacity, leading to underutilization on modern architectures like the NVIDIA Hopper GPU, where optimized GEMM kernels achieve 80–90\% utilization while attention kernels historically reached only 35\%.

This chapter elaborates on how \textsc{FlashAttention-3} fundamentally restructures this interaction through Producer-Consumer asynchrony. By explicitly separating the hardware responsibility of data acquisition from that of data computation within a single thread block, we eliminate the traditional "load-and-wait" dependency chains. We will introduce a warp-specialization scheme where warpgroups within a cooperative thread array (CTA) are dedicated exclusively to either issuing TMA transactions or executing WGMMA instructions. This design aligns software execution control with hardware specialization: TMA units are used solely for memory loading, while Tensor Cores are reserved purely for floating-point computation. To ensure continuous progress without requiring global synchronization barriers that would stall execution, we implement a circular shared memory buffer mechanism that acts as a decoupling interface between producers and consumers. Finally, we explore how this architecture facilitates list-based parallelism for handling multiple sequence blocks simultaneously and enables pingpong scheduling strategies that further hide latencies by overlapping low-throughput softmax operations with high-throughput GEMMs across different warpgroups.

# The Problem with Synchronous Kernels

In traditional matrix multiplication kernels executed on modern GPUs, data flows strictly sequentially. A set of threads is tasked with computing an output matrix element $\mathbf{C}_{i,j}$ using values from input matrices $\mathbf{A}$ and $\mathbf{B}$. The algorithm typically involves loading necessary rows of $\mathbf{B}$ into local registers or shared memory before stalling waiting for values from corresponding columns of $\mathbf{A}$. This strict ordering is repeated for every output element and every thread block, fundamentally limiting concurrency. When applied to attention mechanisms, where one needs to compute self-attention scores between all pairs of tokens in extremely long sequences, this synchronous model becomes prohibitive due to the massive amount of global memory traffic required ($O(N^2)$ reads and writes per head). The GPU suffers because its powerful computational units sit idle while waiting for slow HBM to deliver data, creating a disparity known as compute-bound versus memory-bound schedulers.

Prior attempts to mitigate this in attention applications often relied on fusing operations within a synchronous loop to reduce cache thrashing but failed to break the fundamental dependency chain between fetching data and processing it. In \textsc{FlashAttention-2}, while tiling strategies were employed, the TMA still had to wait for each warpgroup's consumer threads to signal readiness before committing more loads, or conversely, consumers had to wait indefinitely if producers did not fill their buffers immediately upon cache miss predictions (though caching is highly effective). The inability to overlap these phases meant that even when Tensor Cores were available to perform near-circuit-limit computational speed (measured in FLOPS), they remained starved for operands. # FlashAttention-3:Breaking Sequential Dependencies via Intra-Warpgroup Overlapping Pipelining

The theoretical limit of GPU performance in attention mechanisms is often dictated not by the raw parallelism of the hardware, but by the architectural dependencies inherent in the algorithmic design of previous generations. While \textsc{FlashAttention} and its successor, \textsc{FlashAttention-2}, successfully mitigated memory-bound bottlenecks through global optimization, they adhered to a rigid, step-wise execution model. This "synchronous" approach processes one sequence block entirely before moving to the next, forcing a strict sequential dependency between matrix multiplication (GEMM) and softmax operations. Even though the multiplication of queries and keys ($\mathbf{S}$) is independent in time from the softmax reduction that follows, the traditional implementation waits for the entire GEMM pass to complete before initiating the point-wise exponentials required for normalization. This serialization leaves significant portions of the Streaming Multiprocessor (SM) idle, specifically allowing the lower-throughput Multi-Function Units (MFUs) executing softmax to sit idle while higher-throughput Tensor Cores are occupied with GEMM. In the context of modern Hopper architecture GPUs, where matmul throughput may be nearly an order of magnitude higher than special function throughput like exponential functions, this lack of overlap represents a substantial waste of tensor core cycles. \textsc{FlashAttention-3} addresses this fundamental limitation by redesigning the intra-consumer execution pipeline to break these explicit dependencies, enabling an overlapped schedule where GEMM operations in one streaming multiprocessor cycle can run concurrently with softmax operations in another block of data, thereby maximizing hardware utilization and pushing throughput closer to theoretical peaks.

The root cause of performance limitation in standard tiling strategies lies in how they manage data flow within a single tile processing event. In a typical implementation \textbf{identifying sequential dependencies}, the workflow for each key-value block follows a rigid chain: first compute scores ($\mathbf{S} = \mathbf{Q}\mathbf{K}^\top$), then perform local softmax normalization on $\mathbf{S}$ to produce probabilities ($\mathbf{P}$), and finally use these probabilities to weight values via $\mathbf{O} = \mathbf{P}\mathbf{V}$. This chain imposes an artificial latency because subsequent operations cannot begin until their predecessors have fully completed their write-backs. Even though computing $\widetilde{\mathbf{P}}$ from scratch does not logically depend on having computed $\widetilde{\mathbf{O}}$ previously, the software stack forces a wait on line 1 ($\mathbf{S}$) on line 2 (softmax) and line 2 on line 3 ($\mathbf{O}$). Furthermore, within a single iteration $j$, relying on TMA-dependent memory loads creates stalls; specifically, if Warpgroup A is waiting for its output GEMM while Warpgroup B is performing softmax on different data due to memory latency hiding attempted elsewhere, subtle ordering constraints can delay execution. The core insight driving \textsc{FlashAttention-3} is that while any specific iteration $j$ remains sequential due to memory dependencies (you cannot load $V_j$ until $K_{j+1}$ arrives or share memory conflicts arise), you can break through these iteration boundaries by maintaining state between iterations. By retaining intermediate results from iteration $j$ in registers rather than flushing them to global memory immediately after use, we create a buffer that allows iteration $j+1$'s non-GEMM work to overlap with iteration $j+2$'s or even later iterations' GEMM work within warpgroups.

In standard hardware accelerators such as those found in NVIDIA's Hopper architecture, Tensor Cores have significantly higher throughput instructions than scalar functional units dedicated to exponentials or logarithms.

\title{Stack Exchange of the Paper: "QLoRA: Efficient Finetuning of Quantized LLMs"}

### How does backpropagating through a frozen, 4-bit quantized model without updating those weights actually work mathematically?
Question:
I am reading the QLoRA paper and I understand the core idea: we keep the base model weights ($\mathbf{W}^{{\text{NF4}}}$) frozen and only tune the adapters ($\mathbf{L}_1, \mathbf{L}_2$). However, I am struggling with the mechanics of backpropagation. The paper states 'backpropagates gradients through a frozen... model into Low Rank Adapters.' If $\mathbf{W}$ is frozen, shouldn't the gradient with respect to it be zero or NaN? Specifically, when calculating $\frac{\partial E}{\partial \mathbf{L}_i}$, how do we compute the term involving $\frac{\partial \mathbf{X}}{\partial \mathbf{W}}$ if $\mathbf{W}$ is stored in NF4 format and never updated? Is it simply that we compute numerical gradients locally around the dequantized value without performing any weight update step on $\mathbf{W}$, or is there a specific chain rule derivation I'm missing regarding the dequantization function in Equation (5)?
Answer:
The mechanism you are intuitively expecting—where a frozen weight matrix receives a zero gradient or causes "NaN" due to division by zero during backpropagation—is actually not how modern deep learning frameworks handle frozen parameters during training. The key lies in understanding that **freezing a parameter is a constraint applied to the optimization step, not a modification to the mathematical definition of the gradient.**

When the QLoRA paper states that gradients are "backpropagated through a frozen... model," it relies on standard Chain Rule differentiation. In a standard neural network layer with weights $\mathbf{W}$, input $\mathbf{X}$, and output $\mathbf{Y} = \mathbf{X}\mathbf{W}$, the gradient of the loss $E$ with respect to an adapter weight $\mathbf{L}$ involves the term $\frac{\partial E}{\partial \mathbf{L}} = \frac{\partial E}{\partial \mathbf{Y}} \frac{\partial \mathbf{Y}}{\partial \mathbf{L}}$. Because $\mathbf{Y}$ depends on $\mathbf{W}$ ($\frac{\partial \mathbf{Y}}{\partial \mathbf{X}} = \mathbf{W}^T$), you mathematically need the values of $\mathbf{W}$ to compute forward activations and backward gradient signals. However, you never calculate the gradient *with respect to* $\mathbf{W}$ (i.e., setting parameters like `requires_grad = False` on $\mathbf{W}$ tells PyTorch: "Do not stop accumulating gradients flowing through this node; however, do not create an update rule for this specific parameter"). Consequently, there is no term involving $\frac{\partial E}{\partial \mathbf{W}}$ in your final update equation for $\mathbf{L}$, so there is no requirement for W's gradient to be zero or non-zero—it simply doesn't exist in the optimization objective for that tensor.

Regarding your specific concern about numerical gradients in Equation (5) and the dequantization function: Dequantization in QLoRA is treated as a linear scaling operation defined by Equation (2): $\text{dequant}(\cdot) = c_i / (\text{scale})$. Mathematically, this function is constant with respect to time during training because the base weights are fixed and their quantization scales ($c_1^{\text{{FP32}}}, c_2^{\text{{k-bit}}}$) are also frozen once generated. Since these constants do not change, their derivatives with respect to any trainable parameter are valid affine transformations. During the backward pass, you dequantize the fixed 4-bit NF4 weights into BFloat16 (the computation format) exactly as if they were full-precision floats. The framework performs matrix multiplications using these recovered floating-point values to propagate error signals to the active LoRA adapters ($\mathbf{L}_1, \mathbf{L}_2$).

It is important to distinguish between "computed gradients" and "updated weights." In QLoRA, the computation graph includes the dequantization step as part of the forward path for every single backpropagation pass. The fact that the weights are stored in 4-bit format only affects memory storage and bandwidth; once loaded into memory for computation and dequantized to BFloat16/FP16 for precision arithmetic, they participate in standard floating-point differentiation rules. The only "trick" involved here is Paged Optimizers mentioned in Section IV and V-B'Paged Optimizers', which manages memory allocation for optimizer states so that when small minibatches are processed sequentially without loading everything into GPU RAM at once, there are no catastrophic memory spikes caused by storing gradients for both massive base model activations and adapters simultaneously. This memory management handles data eviction efficiently rather than altering the underlying calculus.

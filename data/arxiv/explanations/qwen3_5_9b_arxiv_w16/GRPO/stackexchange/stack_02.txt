\title{Stack Exchange of the Paper: "DeepSeekMath: Pushing the Limits of Mathematical Reasoning in Open Language Models"}

### In the GRPO algorithm, how is the baseline advantage $ar{r}$ calculated when using Group Relative Advantage Estimation?
Question:
I am studying Equation (2) for the GRPO objective. The text states that advantages $ar{A}_{i,t}$ are calculated based on relative rewards within each group. It defines outcome supervision as $ar{A}_{i, t} = 	ilde{r}_i = \frac{r_i- {m mean}(\mathbf{r})}{{m std}(\mathbf{r})}$. However, in Equation (2), there is a summation inside the min/clip function over tokens $t=1$ to $|o_i|$. Since the normalized reward $	ilde{r}_i$ is a single scalar value for the entire output sequence $o_i$, does this mean every token $t$ in that sequence receives the exact same advantage value? How does this differ from PPO where $A_t$ varies per token based on future rewards or value function estimates?
Answer:
In the DeepSeekMath paper, when using Group Relative Policy Optimization (GRPO) with outcome supervision, the advantage $\hat{A}_{i, t}$ for every token $t$ within a specific output sequence $o_i$ is indeed identical to the normalized reward of that group. Specifically, Equation (2) in the paper's main text (referenced as \ref{eq:GRPO-obj} in the document) shows a summation over tokens $t=1$ to $|o_i|$, but for outcome supervision, the advantage term being summed is a constant scalar $\widetilde{r}_i$ defined as:
$$ \widetilde{r}_i = \frac{r_i - \text{mean}(\mathbf{r})}{\text{std}(\mathbf{r})} $$
Here, $r_i$ is the raw reward given by the reward model for the entire output sequence $o_i$, and $\mathbf{r}$ represents the vector of rewards $\{r_1, r_2, \dots, r_G\}$ collected from sampling $G$ outputs for that same question. Because GRPO assigns this single normalized value to every position in the sequence ($\hat{A}_{i, t} = \widetilde{r}_i$), each token effectively receives the same gradient signal proportional to whether its group won or lost relative to others.

This design choice fundamentally differs from standard Proximal Policy Optimization (PPO) in how it handles credit assignment and baseline estimation. In traditional PPO described in Section III-A of the paper, computing the advantage requires a learned value function $V_\psi$, which attempts to estimate the expected future return at each timestep $t$. Consequently, in PPO, $A_t$ varies significantly across tokens because it incorporates future rewards and position-specific state evaluations; solving "5 x 5 + 2" might yield a very high advantage for generating "25" and a lower one for generating "x" if those are at different positions relative to predicted future returns. Furthermore, PPO relies on an external critic model that incurs substantial memory overhead and is difficult to train accurately when rewards are sparse (e.g., only at the end).

GRPO eliminates this need by shifting from absolute advantage estimation to *relative* advantage estimation within a group. The intuition is that if a model generates 10 diverse solutions for one math problem, comparing them to each other provides a stronger signal than comparing them against a generic pre-tuned value function. If one solution scores 900 while others score between 100 and 400, assigning all tokens of that top-scoring solution a large positive standard-scores-based advantage encourages the policy to adopt that pattern globally for all steps in that sequence. This approach aligns with comparative reward models and drastically reduces memory usage by removing the critic network entirely. Since polynomial RKHS mapping states are not mentioned in this paper or relevant context here we focus on why outcome only relies on final reward.

The authors also note in Subsection III-D ("Process Supervision RL with GRPO") that while outcome supervision treats all tokens equally regardless of their temporal position or reasonability during derivation, one could imagine variants where advantages are computed differently (like summing future normalized step-rewards as shown: $\hat{A}_{i,t} = \sum_{index(j)\ge t} \widetilde{r}_i^{index(j)}$). However, for the standard outcome supervision setup asked about regarding Equation (2), every token shares the exact same advantage value derived solely from the performance of its instance relative to peers solving the same prompt at once.

\title{Stack Exchange of the Paper: "The Era of 1-bit LLMs: All Large Language Models are in 1.58 Bits"}

### Does the '1.58 bits' in BitNet b1.58 refer to average entropy per parameter or a hard limit on precision?
Question:
I am confused about the exact definition of '1.58 bits' in the context of BitNet b1.58. The paper states that every parameter takes values from {-1, 0, 1}, which mathematically requires \log_2(3) \approx 1.585 bits of space to store naively. However, the abstract claims the model is 'in 1.58 bits'. Does this number represent the theoretical average entropy (information content) of the weights in a specific trained model, or is it simply the cost to store a fixed-width ternary variable? If it's based on entropy, how was this entropy calculated across different layers and model sizes, given that some weights might be consistently 0 while others vary?
Answer:
The figure "1.58 bits" in BitNet b1.58 refers strictly to **the cost to store and represent a fixed-width ternary variable**, not a measured average entropy across trained weights.

Every parameter in this architecture is mathematically constrained to take values exclusively from the set $\{-1, 0, 1\}$. The value $\log_2(3) \approx 1$.

### How does the inclusion of 0 in weights specifically improve modeling capability compared to {-1, 1}?
Question:
The paper mentions that adding 0 to the weight set {{-1, 0, 1}} enables 'explicit support for feature filtering' and makes modeling capabilities stronger compared to the original BitNet {-1, 1}. Can someone explain the math behind this? Specifically, if a weight is -1 or 1 in BitNet (original), all input features are either amplified or inverted. How does introducing a weight of 0 allow the network to effectively 'turn off' specific input channels for a particular transformation in a way that {-1, 1} cannot? Does this relate to sparsity patterns or simply expanding the function space of linear projections?
Answer:
The inclusion of $0$ in the weight set $\{-1, 0, 1\}$ fundamentally expands the function space available to the model compared to the binary set $\{-1, 1\}$, specifically by introducing the capability for **explicit feature filtering**.

In the original BitNet architecture using weights from $\{-1, 1\}$, a linear projection operation $y = Wx$ acts as an orthogonal reflection or inversion of the input vector $x$. Since every weight $W_{ij}$ is restricted to be either $+1$ or $-1$, the output for any input feature $x_j$ will always have a magnitude equal to the sum of absolute values of inputs (amplification) or inverted (sign flip). Mathematically, if we consider a single neuron with inputs scaled to unit magnitude, a weight of $+1$ preserves the signal ($x \to x$), while a weight of $-1$ flips it ($x \to -x$). There is no mechanism within this binary constraint to set a specific input contribution to zero. Consequently, every input feature participates fully in every linear transformation; the network lacks a simple, differentiable way to decouple or ignore specific channels without relying on complex cancellation effects across multiple features.

By introducing $0$ as a valid weight value in BitNet b1.58, defined via an $\text{absmean}$ quantization function that rounds weights to the nearest integer in $\{-1, 0, 1\}$, the model gains distinct representational power. When a weight $W_{ij}$ is quantized to $0$, the corresponding term in the dot product $\sum_k W_{ik} x_k$ vanishes entirely during matrix multiplication. This effectively "turns off" that specific input channel for that particular transformation without requiring other weights to compensate or cancel it out. The paper argues that this allows for **sparse connectivity** at the weight level (as opposed to just activation sparsity), enabling more efficient information routing. For instance, if an input feature carries noise or irrelevant information for a specific downstream task within that layer's logic, assigning it a weight of $0$ allows the network to filter it out explicitly before passing information through non-linearities like SwiGLU.

From an optimization perspective, adding $0$ expands the feasible space of linear mappings from all possible matrices with entries in $\{-1, 1\}$ (a subset of Hadamard-like matrices) to all matrices with entries in $\{-1, 0, 1\}$. This provides greater flexibility in approximating complex target functions during training. The new function space allows gradients to optimize not just the sign and strength of connections (which are fixed in magnitude for binary weights), but also their existence. While mathematical expressions like $\sum_k W_{ik} x_k$ show that non-zero weights simply scale and sum inputs, having access to zero as an option allows the "scale" factor itself to become zero for specific interactions (ignore rather than invert). This is particularly crucial for expressive tasks where specific features might need to be blocked entirely under certain conditions—a nuance impossible to capture naturally with only two states per synapse unless one utilizes precise cancellations from other terms, which is less robust and harder for gradient-based optimizers like AdamW (used here) to learn compared to directly learning zeros via clipping large-magnitude updates.

### Why does quantizing activations to [-Q_b, Q_b] instead of [0, Q_b] not significantly hurt performance?
Question:
In the 'Quantization Function' section, I noticed the authors chose to scale activations to $[-Q_b, Q_b]$ rather than $[0, Q_b]$ (the standard unsigned approach) to avoid zero-point quantization. The paper claims this simplifies implementation and system-level optimization with negligible performance effects. However theoretically, integer symmetric quantization often requires handling bias terms or offset arithmetic differently than unsigned quantization in hardware accelerators. Given that the model architecture already removes all biases ('removes all biases'), how does keeping activations symmetric help maintain accuracy without needing an added bias term back in post-processing? Is it purely about alignment with integer addition/subtraction units?
Answer:
The decision to maintain symmetry in the activation range, scaling to $[-Q_b, Q_b]$ rather than $[0, Q_b]$, is a strategic architectural choice rooted in simplifying the computational graph and hardware utilization, rather than a concession regarding bit-width efficiency.

To understand why this does not hurt performance, one must first recognize that in deep learning architectures like Transformers (specifically the LLaMA-alike components adopted by BitNet b1.58), the data flow between layers is continuous and non-linear. If activations were constrained to a strictly positive range $[0, Q_b]$, every operation would theoretically require a zero-point offset to handle negative values introduced during subsequent matrix multiplications or non-linear transformations (like SwiGLU). This would necessitate injecting an explicit bias term or a zero-point correction at every step of the computational graph to map the symmetric output of one layer into the positive range of the next. By removing biases from the architecture entirely, as stated in the paper, and fixing the activation quantization to be symmetric around zero, the model eliminates the need for these complex offset arithmetic operations. Integer hardware units typically handle addition and subtraction natively without requiring extra logic for bias injection when the data distribution is centered around zero; thus, maintaining symmetry aligns perfectly with this hardware reality.

Furthermore, since BitNet b1.58 removes all biases from its linear layers, there is no inherent asymmetry being driven into the system by learned parameters. The weight distribution itself tends to be centered, which naturally keeps activation distributions close to zero across the network. When activations are quantized such that both positive and negative values are represented within $[-Q_b, Q_b]$, each incremental step can use one bit of information (sign) effectively across both halves of the dynamic range without needing an additional bit solely for encoding a zero-point offset. If one were forced into an unsigned $[0, Q_b]$ scheme without adjusting weights or adding biases dynamically, half of the dynamic range might go unused or require "wasted" bits to handle offsets that don't align with integer addition units optimized for symmetric data.

Finally, while positive-only quantization ($[0, Q_b]$) can sometimes offer slight benefits in terms of utilizing sign extension or avoiding negative two's complement interpretation overhead in specific legacy systems, modern GPU architectures and libraries (which this paper targets via integration with frameworks like vLLM) are highly optimized for symmetric integer arithmetic when data is known to be centered. The authors explicitly state that their experiments show "negligible effects" on performance because forcing activations into an unsigned space without corresponding architectural changes (like adding intermediate biases) introduces unnecessary quantization error or wasted precision for no significant gain in bit efficiency. The simplicity of treating inputs as raw signed integers allows for direct mapping to native instruction sets for INT8 addition/subtraction, minimizing latency and ensuring that the computational advantage of avoiding multiplication operations remains uncompromised by complex post-processing adjustments.

### Is the '2-bit kernel from Ladder' actually using 2-bit precision or is this just an optimization for ternary ops?
Question:
In the Results section regarding Memory and Latency, the authors mention that they integrated 'The 2-bit kernel from Ladder' for their BitNet b1.58 tests on GPUs. BitNet b1.58 uses ternary weights {-1, 0, 1} and symmetrical 8-bit activations (effectively positive/negative integers). While one might map ternary to a subset of 2-bit values (e.g., mapping {-3,-2,-1} to {3}... wait, that's not right for {-1,0,1}), how exactly does a generic '2-bit kernel' handle ternary arithmetic? Did they pack three ternary values into two bits (impossible without loss), or does this refer to an kernel optimized for operations where data fits within an unsigned integer representation up to $Q=3$? I'm unclear on whether '2-bit kernel' implies actual memory storage compression beyond what is needed for ternary data.
Answer:
The '2-bit kernel from Ladder' mentioned in the BitNet b1.58 paper refers to a specialized GPU kernel optimization for processing data where the active value range spans $\{0, 1, 2\}$, which corresponds efficiently to 2 bits of information, rather than strictly enforcing or storing weights in a ternary $\{-1, 0, 1\}$ format with only 1.58 bits per parameter.

To understand this distinction, it is helpful to recall how bit-widths are calculated and mapped. The authors explicitly define their models as having a "1-bit" weight component by using ternary weights $\{-1, 0, 1\}$. Mathematically, three distinct values require $\lceil \log_2(3) \rceil = 2$ bits for binary representation; they derive the "1.58-bit" moniker by calculating $\log_2(3) \approx 1.58$. However, standard fixed-point or integer arithmetic kernels on GPUs are typically optimized for non-negative integer domains. A ternary set containing negative numbers like $\{-1\}$ is awkward for hardware optimized for unsigned integers or simple logical operations without significant software overhead for sign handling.

Therefore, the integration of the '2-bit kernel from Ladder' $\cite{ladder}$ serves as an implementation strategy to leverage highly optimized SM80/SM90 hardware instructions designed for operations on packed data where values fit within a small non-negative integer range specific to that kernel's constraints (typically representing values as an unsigned integer of width 2). In this context, the ternary nature of BitNet b1.58 is preserved logically through the mapping: the physical storage and computation use a format compatible with the kernel's efficiency requirements (effectively treating the active states as indices into an array or mapping them to non-negative integers like $0 \to u0$, $1 \to u1$, $-1 \to u2$), while maintaining the ternary logic required for matrix multiplication ($\sum w_i x_i$).

This approach allows the authors to achieve significant speedups because bitwise operations on packed data (such as those provided by NVIDIA's `ubyte` or similar low-level optimizations) are extremely fast compared to floating-point multiplications found in FP16 or BF16 tables referenced in their experiments. The kernel does not lose precision regarding the *values* used in calculation; rather, it optimizes the *representation* during computation and memory access to fit a hardware-efficient pattern that utilizes exactly two bits per element when processing non-negatives or specific mappings of those ternary states. As noted in the paper's Results section under Memory and Latency, using this specific kernel was crucial to measuring valid improvements over FP16 baselines, confirming that while the model architecture relies on ternary logic (yielding 1.58 bits of entropy/info), the computational execution layer exploits standard coarse-grained bit-packing optimizations available in modern tensor cores for workloads fitting within small integer bounds. This separation between logical weight definition (ternary) and physical computation primitive (packed binary) is key to realizing both the theoretical memory savings and practical latency gains reported in Table~\ref{tab:ppl}.

### How does reducing activations from FP32/FP32 (intermediate) -> FP32 output affect stability during forward pass despite being quantized?
Question:
The paper states BitNet b1.58 uses '8-bit activations'. Usually in Transformer architectures like LLaMA mentioned here (RMSNorm + SwiGLU), there are non-linearities where large gradients can accumulate if intermediate values aren't carefully handled. If activations are clipped or quantized early (as implied by saving them as integers before storage/transmission), does this constrain the dynamic range entering into SwiGLU gates or Rotary Embeddings? The Section on Energy savings mentions INT8 additions dominate costs on A8N chips compared to FP16 mults/adds. Are there concerns about saturation errors in low-precision forward passes despite using dynamic scaling per token as mentioned in 'Quantization Function', especially given that they start scaling from scratch training rather than post-training pruning?
Answer:
The stability of BitNet b1.58 during the forward pass, despite quantizing activations from FP32/FP32 (intermediate calculations) to 8-bit integers, stems primarily from the specific design of its "Quantization Function" and its training methodology, rather than relying on aggressive clipping or zero-point shifts.

Unlike standard post-training quantization where values are globally scaled to a fixed small integer range (like $[0, 127]$), BitNet b1.58 implements a dynamic token-wise scaling strategy. Specifically, the paper notes that activations are "scaled to $[-Q_b, Q_b]$ per token," which effectively creates a local dynamic range centered around zero for each position in the sequence without introducing offset biases. This approach is crucial because it allows the 8-bit integers to maintain a symmetric distribution capable of representing both positive and negative values, mitigating the risk of pure positive clipping that could force negative gates in non-linearities like SwiGLU into saturation. Furthermore, because the model is trained from scratch with these specific quantization constraints, the network weights have been adapted to expect this statistical distribution during training; they do not encounter a sudden shift in activation statistics as seen in post-training scenarios where the model was originally optimized for high-precision floating point operations.

Regarding concerns about gradients and non-linearities within RMSNorm and SwiGLU layers, the reduction from FP32 intermediate precision to 8-bit output does not inherently cause instability because the intermediate accumulations can still be handled with sufficient precision before the final quantized output is stored or transmitted to memory. The paper highlights that on chips like the A8N mentioned in your inquiry, INT8 additions dominate costs over FP16 multiplications only after this final quantization step; however, the forward pass involving matrix multiplications and element-wise operations typically retains higher precision internally on modern hardware before being cast to INT8 for storage or subsequent sparse/ternary operations. The "Energy savings" section emphasizes that INT8 arithmetic replaces FP16 mult/adds only for the weight-application step (the $Wx$ operation in linear layers), which suggests that heavy accumulation steps might leverage native hardware capabilities (often FP16) prior to the final 8-bit reduction.

Ultimately, the loss of dynamic range is managed by ensuring that for any given token batch, the maximum activation magnitude does not exceed $Q_b$. While this truncates extreme outliers compared to full FP32 range, it prevents overflow errors by definition and allows the model to operate safely within a bounded integer domain. The combination of per-token dynamic scaling and training-the-model-in-twosystem ensures that these quantized activations entering SwiGLU gates or Rotary Embeddings remain within a predictable functional range where gradients can still flow effectively through subsequent layers without hitting hard saturation walls.

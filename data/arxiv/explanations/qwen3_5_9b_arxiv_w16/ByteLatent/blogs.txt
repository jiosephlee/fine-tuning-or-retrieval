# Stopping Yourself in Words: Why LLMs Should Think in Patches, Not Tokens

Most large language models operate on a rigid schedule: they process every token with the same level of intense computation, regardless of whether the task is trivial or difficult. This "one-size-fits-all" approach forces the model to spend massive amounts of energy predicting common words like "the" or "is," while still performing heavy lifting on complex code or mathematical notation. A new architecture called the Byte Latent Transformer (BLT) challenges this paradigm by proposing that models should dynamically allocate their computational resources rather than wasting them on predictable data.

The core innovation lies in how the model segments input data. Instead of chopping text into a fixed set of tokens using a static vocabulary, BLT groups raw bytes into variable-sized segments called "patches." These patches vary in length based on the complexity of the text ahead. The system uses an internal mechanism to calculate the entropy of the next byte—essentially measuring how hard it is to predict what comes next. If the upcoming text is highly predictable, like a space-separated word ending in common letter combinations, the model groups more bytes into a single patch without running expensive global computation. Conversely, when facing high uncertainty or complex structures, the patches become smaller to allow for deeper, more focused analysis.

This dynamic approach acts as a sophisticated traffic cop for computational efficiency. Imagine driving through a city; why would you treat a quiet suburb exactly the same as a bustling downtown intersection? In standard tokenization-based models, the engine revs as hard everywhere. In BLT, high-entropy regions trigger an expensive "local transformer" step where deep learning occurs, while low-entropy regions are skipped during these expensive stages. The architecture achieves this through three distinct modules: two lightweight local models that handle encoding and decoding at the byte level, and a large global latent transformer that only activates when a new patch boundary is encountered and processing becomes computationally demanding.

The mathematical logic behind this efficiency lies in how attention mechanisms function within these variable blocks. Because the global model only processes patches rather than individual bytes, increasing chunk sizes naturally reduces inference costs. By aligning patch boundaries with natural linguistic units—such as spaces or other high-uncertainty transitions—the system ensures that compute is reserved for moments where information density peaks. This segmentation allows BLT to maintain strong performance on complex reasoning tasks while ignoring redundant memory states associated with simple text flows.

The results from recent scaling studies suggest this paradigm shift offers significant advantages over traditional methods. Research indicates that BLT can match the performance of top-tier tokenization-based models like Llama 3 while utilizing up to 50% fewer floating-point operations (flops) during inference for fixed task requirements. Furthermore, this architecture unlocks a unique scaling dimension: it allows researchers to increase both model size and patch size simultaneously without exceeding a predefined computing budget. Traditional models face strict trade-offs here because changing token sizes requires resizing embedding tables and introducing other architectural constraints that do not exist in byte-level patching schemes where vocabularies are learned dynamically rather than defined statically before training begins.

In practical terms, this means future language models could become both larger and smarter without consuming proportionally more energy per query. By treating raw data as a fluid stream and slicing it only where necessary, BLT demonstrates that efficiency gains come not from doing less work globally, but from intelligently distributing effort exactly where uncertainty demands it most.



# The 50% Energy Saver: How Tokenizer-Free Models Beat Big Competition

You have probably noticed that running large language models is becoming increasingly expensive. As model sizes grow from 7 billion to hundreds of billions of parameters, the energy required to train and inference them risks spiraling out of control. A recent paper introduces a solution called the Byte Latent Transformer (BLT), which challenges the industry standard of tokenization. Instead of forcing raw data into static vocabulary items, BLT groups bytes into dynamic "patches" based on complexity. This approach has achieved a remarkable result: it matches the performance of massive models like Llama 3 while potentially using up to 50% fewer Floating Point Operations (FLOPs) for inference.

To understand how this is possible, we must first look at why current models are inefficient. Traditional Large Language Models (LLMs) rely on a pre-defined vocabulary of tokens. During training, bytes are grouped into these tokens using heuristics like Byte-Pair Encoding (BPE). Once grouped, the model treats every token equally, regardless of how much information it contains. For example, predicting the second letter of a common word requires very little compute, yet the model expends the same resources as predicting the start of a new sentence where uncertainty is high. BLT changes this by dynamically allocating compute where it is actually needed, effectively trading fixed-token steps for variable data complexity.

The core innovation behind this efficiency lies in "flop-controlled scaling" and dynamic patching. In previous research on byte-level models, researchers had to either accept massive sequence lengths (which kills memory efficiency) or use simple rigid methods to group bytes. BLT introduces a sophisticated patching strategy that uses entropy estimates from a small language model to decide when to create a new patch segment. If the data following a specific byte is predictable—like completing a common suffix—the entropy is low, and BLT merges more bytes into a single patch. Conversely, when data complexity spikes, such as at the start of a technical term or a mathematical formula, BLT splits more frequently. This ensures that computational power matches informational density rather than arbitrary character counts.

This dynamic approach provides flexibility that tokenization simply cannot match because of vocabulary constraints. With standard tokenizers like those used in Llama 3, increasing the average token size (to reduce sequence length) often forces an expansion of the embedding table size to accommodate rare tokens or new subword combinations. This creates a fixed trade-off: you cannot significantly increase your context window size without paying a heavy parameter tax elsewhere in the model architecture. The paper notes that Llama 3 itself sees its average token size creep up from 3.7 to 4.4 bytes just by expanding its vocabulary size by four times from Llama 2 to Llama 3. BLT decouples these variables entirely because its patches are not drawn from a fixed set; they are learned representations of variable lengths depending entirely on the input data's entropy profile at that specific moment in time during generation or pre-training dataloading.

# Seeing the Letters: Why Byte-Level Models Are Better at Coding and Reasoning

When you strip away the standard vocabulary that turns text into abstract symbols, you lose some information—but only if you throw it away. Here, we explore why training directly on raw bytes gives models a superpower: character-level robustness. Through examples of noisy inputs, low-resource languages, and understanding phonology, BLT models can dodge errors that confuse standard tokenizers.

Most large language models today rely on tokenization, a heuristic pre-processing step that groups bytes into a fixed set of tokens before the model ever sees the data. This compression simplifies the learning task for the model but creates a blind spot. Because these tokens are arbitrary groupings determined by compression algorithms rather than linguistic reality, the resulting models often lack deep orthographic knowledge and struggle when inputs deviate from their expected vocabulary patterns.

Enter the Byte Latent Transformer (BLT). Unlike traditional architectures, BLT abandons the fixed vocabulary in favor of processing raw bytes directly. By encoding bytes into dynamically sized patches based on data complexity, BLT retains granular information about every single byte in the sequence. This architectural shift is not just about efficiency; it fundamentally changes how a model understands the texture of language, leading to surprising advantages in robustness and reasoning.

### Surviving Noisy Inputs with Byte-Level Awareness

One of the most striking benefits of modeling raw bytes is resilience against input noise. Standard tokenizers rely on exact matches within their vocabulary, meaning even minor disruptions can break the flow of information for a model that has "forgotten" what individual characters look like after compression. In contrast, BLT models perceive every byte individually, allowing them to reconstruct meaning even when parts of a sentence are corrupted.

Researchers testing BLT against standard models introduced various types of noise to benchmark this robustness. When text was transformed into spaced-out uppercase letters (AntSpeak) or when characters were randomly dropped (Drop strategy), standard tokenizers struggled significantly because their learned tokens were fragmented or missing entirely. BLT models, however, maintained high performance in these scenarios. Because they never discarded byte-level detail during preprocessing, they could infer context and complete tasks despite the distortion. This suggests that for applications involving untrusted or messy data streams—such as scraping open-source codebases or interacting with users in casual settings—byte-level processing provides a reliability boost that abstraction simply cannot match.

### Unlocking Phonology and Orthographic Structure

Beyond resilience to noise, direct byte modeling empowers LLMs to understand the structural components of words themselves. This becomes crucial for tasks involving phonology or strict character manipulation where the relationship between spelling and sound matters. For instance, when asked to map graphemes (letters) to phonemes (sounds), BLT outperforms standard tokenizer-based baselines like Llama 3. The model learns these relationships naturally through exposure to raw text sequences rather than having to rely on external adaptations or higher-level abstractions that might obscure these details.

This advantage extends even further to specialized benchmarks designed to test character-level intuition, such as CUTE (Character Understanding at TElargy Extra-large). This benchmark challenges models with tasks like determining if a word belongs to another via simple edits or verifying if two strings are anagrams after one letter is changed—essentially tests on composition and orthographic similarity that require manipulating text one letter at a time. # Breaking the Token Ceiling: A New Architectural Frontier for AI Scaling

Large language models have achieved remarkable success, but they face a hidden constraint that slows down scaling: the rigid vocabulary used for tokenization. In traditional architectures, every piece of input is broken down into static tokens beforehand. This process creates a fixed set of indices that the model must process, forcing a heavy trade-off between efficiency and performance. When researchers try to increase the average token size to reduce the number of steps the model needs to take, they inevitably encounter technical bottlenecks. Increasing token size expands embedding tables and output dimensions, leaving little room to actually grow the model's intelligence. This post explores how the Byte Latent Transformer (BLT) breaks this cycle by decoupling model complexity from vocabulary constraints, allowing for a new dimension of scaling where both patch size and model size can grow together.

The core innovation in this new architecture is the shift from fixed-token processing to dynamic patching. Instead of relying on a pre-defined list of words or subwords, BLT operates directly on raw bytes during training but groups them into variable-sized sequences called patches during computation. These patches serve as the primary units of attention rather than individual tokens. This approach fundamentally changes how computational resources are allocated. In standard tokenization-based models, the amount of compute allocated to each step is constant regardless of how difficult it is to predict the next word. BLT changes this paradigm by determining patch boundaries based on data entropy, or predictability.

By using entropy estimates from a lightweight byte-level language model, the system identifies where uncertainty is high and where it is low. High-entropy regions, such as the start of a sentence or complex code logic, are grouped into smaller patches so that a large transformer step can invest significant compute there. Conversely, low-entropy regions, which contain predictable or repetitive information like whitespace or common grammatical structures, are grouped into larger patches. This means fewer compute steps are required to process these simple sections because the model processes multiple bytes simultaneously with a single global transformer layer. This dynamic allocation ensures that compute is not wasted on easy predictions while being underutilized in areas that demand more reasoning power.

This architectural shift unlocks a unique scaling advantage that static tokenization cannot match: the simultaneous growth of model size and patch length within a fixed inference budget. In typical transformer scaling studies, increasing vocabulary size to reduce step count comes at the cost of larger embedding projections and weights per token. BLT bypasses this limitation because its patch representations are learned dynamically without a fixed vocabulary overhead. Researchers can now configure models with larger average patch sizes—for instance, moving from 4 bytes per patch to 8 or even 9 bytes—which directly reduces the number of global transformer calls needed during inference. The compute saved by processing longer chunks can be reallocated to increase the number of parameters in the global latent transformer itself.

Empirical results demonstrate that this strategy leads to superior performance trends compared to traditional methods up to 8 billion parameters and over 4 trillion training bytes. In flop-controlled experiments where both architectures are given equal computational resources for inference, BLT maintains higher accuracy as both its parameter count and patch size increase together. A specific experiment revealed that by utilizing an average patch size of 8 bytes compared to standard baseline sizes around 4 bytes, BLT achieved comparable performance with up to 50% fewer floating-point operations required for inference at scale than leading tokenizing competitors like Llama 3 on matching datasets using Llama 3 tokenizer.\[1\] This proves that adding internal "chunks" of data to be processed allows models to remain efficient even as they become much larger and more capable logically.

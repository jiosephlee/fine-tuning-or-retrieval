# The 50% Energy Saver: How Tokenizer-Free Models Beat Big Competition

You have probably noticed that running large language models is becoming increasingly expensive. As model sizes grow from 7 billion to hundreds of billions of parameters, the energy required to train and inference them risks spiraling out of control. A recent paper introduces a solution called the Byte Latent Transformer (BLT), which challenges the industry standard of tokenization. Instead of forcing raw data into static vocabulary items, BLT groups bytes into dynamic "patches" based on complexity. This approach has achieved a remarkable result: it matches the performance of massive models like Llama 3 while potentially using up to 50% fewer Floating Point Operations (FLOPs) for inference.

To understand how this is possible, we must first look at why current models are inefficient. Traditional Large Language Models (LLMs) rely on a pre-defined vocabulary of tokens. During training, bytes are grouped into these tokens using heuristics like Byte-Pair Encoding (BPE). Once grouped, the model treats every token equally, regardless of how much information it contains. For example, predicting the second letter of a common word requires very little compute, yet the model expends the same resources as predicting the start of a new sentence where uncertainty is high. BLT changes this by dynamically allocating compute where it is actually needed, effectively trading fixed-token steps for variable data complexity.

The core innovation behind this efficiency lies in "flop-controlled scaling" and dynamic patching. In previous research on byte-level models, researchers had to either accept massive sequence lengths (which kills memory efficiency) or use simple rigid methods to group bytes. BLT introduces a sophisticated patching strategy that uses entropy estimates from a small language model to decide when to create a new patch segment. If the data following a specific byte is predictable—like completing a common suffix—the entropy is low, and BLT merges more bytes into a single patch. Conversely, when data complexity spikes, such as at the start of a technical term or a mathematical formula, BLT splits more frequently. This ensures that computational power matches informational density rather than arbitrary character counts.

This dynamic approach provides flexibility that tokenization simply cannot match because of vocabulary constraints. With standard tokenizers like those used in Llama 3, increasing the average token size (to reduce sequence length) often forces an expansion of the embedding table size to accommodate rare tokens or new subword combinations. This creates a fixed trade-off: you cannot significantly increase your context window size without paying a heavy parameter tax elsewhere in the model architecture. The paper notes that Llama 3 itself sees its average token size creep up from 3.7 to 4.4 bytes just by expanding its vocabulary size by four times from Llama 2 to Llama 3. BLT decouples these variables entirely because its patches are not drawn from a fixed set; they are learned representations of variable lengths depending entirely on the input data's entropy profile at that specific moment in time during generation or pre-training dataloading.

# Beyond the Transformer: Why LSTMs Are Making a Massive Comeback

For over a decade, the landscape of natural language processing was defined by a single paradigm shift: the Transformer. Introduced in 2017, this architecture leveraged parallelizable self-attention mechanisms to outperform its predecessors, fundamentally changing how we train Large Language Models (LLMs) like GPT. The focus shifted entirely to scaling up. However, a recent study titled xLSTM: Extended Long Short-Term Memory challenges this narrative. It asks a simple yet profound question: How far can we push Recurrent Neural Networks (RNNs) if we scale them to billions of parameters and apply modern techniques? The answer suggests that LSTMs are not dead; they are evolving into a serious competitor for Transformers and State Space Models (SSMs).

To understand this resurgence, we must first recall why LSTMs were eventually overshadowed. The original Long Short-Term Memory (LSTM) unit revolutionized sequence modeling in the 1990s by solving the vanishing gradient problem through gating mechanisms and a constant error carousel. Equation~\ref{eq:lstm_idea} captures the core update rule where the cell state $c_t$ is updated based on previous information and new inputs via gates $f_t$ and $i_t$. Despite their success in tasks ranging from text generation to game-playing agents like AlphaStar, traditional LSTMs hit three major ceilings that prevented them from scaling to trillion-parameter models.

The first limitation is the inability to easily revise storage decisions. In a standard LSTM, once information is written to memory or keyed with a position, it is difficult to overwrite or update it based on new context that appears later in the sequence. For example, in a nearest neighbor search problem within a long sequence determined by context, an LSTM often struggles to correct an early stored vector when a more similar one appears later. This rigidity stems from fixed gating rules that do not dynamically adjust the retention value with sufficient magnitude.

The second issue concerns limited storage capacity. Traditional LSTMs store information in scalar cell states ($c_{t-1} \in \mathbb{R}$). Consequently, distinct pieces of information must be compressed into these scalar values, leading to interference where forgetting one piece of data might inadvertently erase another vital signal. In experiments regarding rare token prediction, LSTMs performed poorly because they could not robustly store low-frequency tokens without losing high-frequency ones due to this compression bottleneck.

Finally, there is the critical issue of parallelization. Because standard LSTMs mix hidden states across memory cells using recurrent connections ($h_{t-1}$ influencing multiple outputs), they serve sequential computation requirements at every step of the sequence generation process. This makes them computationally inefficient compared to the massive parallelism offered by Transformers and recent fast state-space models like Mamba or Hyena.

The xLSTM paper proposes two specific architectural modifications to address these flaws without discarding the intuitive strength of RNNs: exponential gating and novel memory structures. By replacing simple sigmoid gates with exponential activation functions for input and forget paths, xLSTM gains the ability to perform large-magnitude updates later in the sequence based on earlier inputs effectively solving the dispute revision problem. To handle this numerically stable approach while preventing overflow during training, the authors introduce an additional stabilizer state derived from previous gate magnitudes, ensuring that parameter updates remain consistent with traditional gradients despite the non-linear scaling factors [see Eq.\ref{eq:slstmforward}].

Perhaps more transformative is the introduction of new memory structures tailored for specific tasks while maintaining efficiency across others. The researchers developed two variants integrated into residual blocks. The scalar sLSTM retains memory mixing capabilities by using multiple heads but restricts mixing within heads rather than across them entirely; exceptionally, it can support multi-cell mixing similar to traditional LSTMs but enhanced with exponential weights for updating stored states [see Eq.\ref{eq:slstmstabil}]. On the other hand, mLSTM introduces a matrix memory ($\mathbf{C}_t \in \mathbb{R}^{d \times d}$) that functions similarly to matrix factorials used in Bidirectional Associative Memories (BAM). Instead of pooling information into a single scalar number, mLSTM stores key-value pairs as outer products in its covariance matrix [see Eq.\ref{eq:mlstm_recurrent_begin}]. This structure allows for direct retrieval operations that are significantly more robust than scalar compression as demonstrated by results on multi-query associative recall tasks where xLSTM[1:0] matched or surpassed non-Transformer baselines like Mamba and RWKV [Figure\ref{fig:mqar-main}].

# The Secret Sauce of xLSTM: Exponential Gating and Scalar Mixers

## Why Old LSTMs Stall

For decades, the Long Short-Term Memory (LSTM) was the king of sequence modeling. Its core innovation, introduced in the 1990s, relied on a clever mechanism called the "constant error carousel." Imagine a highway where information about the past flows forward with almost no loss, controlled by gates that decide what to keep and what to forget. While this architecture revolutionized text generation until 2017, it hit a fundamental wall.

The standard LSTM suffers from a significant flaw known as the "inability to revise storage decisions." To understand this, consider a task where you must compare the current input against everything seen so far to find the most similar one. In a standard LSTM, once a piece of information is written to memory via an input gate, it stays there. Even if a much better or more relevant piece of information arrives later, the old data cannot be easily erased or updated. The model is locked into its initial decisions, leading to degradation in tasks requiring dynamic state tracking or complex conditional logic like nearest neighbor search.

## Enter sLSTM: A New Way to Remember

This is where xLSTM steps in. The paper introduces a specific variant called sLSTM (scalar LSTM), which deals directly with this rigidity. Instead of keeping memory locked behind sigmoid gates that strictly output values between 0 and 1, xLSTM introduces **exponential gating**.

In traditional LSTMs, gates use a sigmoid activation function $\sigma$. This function bounds the gate value $f_t$ or $i_t$ between 0 and 1 essentially freezing updates if they become too small or too large. sLSTM replaces these sigmoid gates with exponential activation functions $\exp$. An exponential function ranges from zero to infinity ($0$ to $\infty$). This seemingly simple change acts as an unbounded mechanism for control. If the network determines that new information is crucial, it can drive the input gate to effect massive changes immediately rather than leaking tiny updates over time. This allows the model to effectively "overwrite" old memories when necessary, solving the revision problem inherent in classic LSTMs.

## The Stability Problem and the Normalizer State

One might assume that switching from bounded sigmoids to unbounded exponentials would solve everything instantly. However, raw exponentials can produce astronomically large numbers, causing numerical overflow and instability during training. While some previous works suggested using an additive bias to stabilize gates, xLSTM proposes a neurobiologically inspired solution: the **normalizer state**.

To implement exponential gating without losing stability, sLSTM introduces an auxiliary variable called the normalizer state $n_t$. The update rule for this state runs in parallel with the standard cell state $c_t$:
\begin{align}
n_t \ &= \  f_t \ n_{t-1} \ + \ i_t 
\end{align}
Here, $f_t$ acts as a decay factor for past accumulation, while $i_t$ adds new weight contributions. # From Scalars to Matrices: How mLSTM Out-competes Attention

The era of the Long Short-Term Memory (LSTM) model, which dominated language modeling from the late 1990s until the rise of Transformers, is witnessing a remarkable resurrection. While Transformers leveraged self-attention to achieve parallelization at scale, they inherently struggle with sequential storage and have quadratic computational costs. Recent research introduces a compelling alternative: the Extended LSTM (xLSTM). Within this framework, the mLSTM variant presents a radical departure from traditional design by replacing the scalar memory cell with a matrix-based system. This architectural shift, inspired by Bidirectional Associative Memories (BAMs), allows the model to achieve infinite storage capacity and full parallelization, enabling it to outperform state-of-the-art Transformers and State Space Models on long-context tasks while maintaining linear computational complexity.

The fundamental limitation of standard LSTMs lies in their scalar memory architecture, where information is compressed into a single vector or cell state. This compression forces the model to trade off precision as sequence length increases, often leading to poor performance on rare token prediction tasks. The original LSTM update rule combines cell states and inputs linearly, using sigmoid gates to moderate updates. Specifically, the hidden state $h_t$ is derived by applying an output gate $o_t$ to a squashed version of the cell state $c_t$, where $c_t$ itself is an additive combination of a forget gate operation on $c_{t-1}$ and an input gate operation on new information $z_t$. This mechanism effectively limits the model's ability to store distinct pieces of information without interference as the sequence progresses.

To overcome these constraints, xLSTM introduces mLSTM, which abandons scalar cells in favor of a matrix memory $\mathbf{C} \in \mathbb{R}^{d \times d}$. This design draws inspiration from covariance update rules used in associative memory systems. Instead of storing data as a compressed summary, mLSTM stores key-value pairs dynamically. At any time step $t$, the model projects the input into a query $\mathbf{q}_t$, key $\mathbf{k}_t$, and value $\mathbf{v}_t$. The memory update rule then operates by adding an outer product of these vectors: $\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top$. Here, $f_t$ acts as a forget gate (decay rate) and $i_t$ acts as an input gate (learning rate). When retrieving information later at time $t+\tau$, the stored value is accessed via a dot product between the current query and all stored keys within this matrix.

Replacing scalar addition with this outer product structure fundamentally changes how information is stored and retrieved. While standard attention mechanisms also rely on dot products for retrieval, they compute these operations over all possible pairs simultaneously in each forward pass, resulting in quadratic complexity relative to sequence length ($O(L^2)$). In contrast, mLSTM maintains only one memory matrix regardless of how long the sequence becomes. Retrieving past information requires multiplying this fixed-size matrix by a new query vector. This approach mirrors Fast Weight Programs but integrates gating mechanisms directly into the weight updates, allowing for variable retention decay similar to human forgetting processes. Consequently, this architecture supports theoretically infinite storage capacity because it does not compress past states; instead, it preserves full interaction matrices that can be queried efficiently later.

A critical advantage of this matrix-based approach for modern deep learning infrastructure is its parallelizability. Traditional Recurrent Neural Networks (RNNs) are inherently sequential because hidden state calculations depend on previous hidden states through recurrent connections that cannot be easily parallelized across time steps or elements within those states. While standard LSTMs mimic this behavior with hidden-hidden connections that mix cell outputs across different units at each step, mLSTM takes a different route by completely removing these mixing connections within its recurrence logic. The update rule depends only on the current input projections and the accumulating sum-matrix rather than on complex permutations of hidden vectors across previous time steps in a way that prevents graph optimizations. By reformulating this recurrence into index-based operations on batches and sequences combined with standard matrix computations (like BLAS operations), mLSTM can be fully parallelized across both space (embedding dimension) and time (sequence length), allowing it to run efficiently on modern GPUs just like attention mechanisms but without needing massive keys-value caches that grow quadratically with context size during pre-fill phases.

Experimental validation demonstrates that this architectural simplicity translates directly into superior performance compared to current Large Language Models based on Transformers or State Space models like Mamba and RWKV-4. When trained on substantial datasets such as 300 billion tokens from SlimPajama, xLSTM models built with mLSTM blocks consistently achieve lower perplexity scores than Llama or Mamba counterparts across various parameter scales ranging from 125 million to 1.3 billion parameters. # State Tracking Explained: Why xLSTM Keeps Context Better than Transformers

Can an AI really understand complex logic like counting items or tracking objects across thousands of words? If you have been experimenting with large language models, you might have noticed that systems sometimes lose track of specific entities after a few sentences. Researchers behind the xLSTM paper have identified a fundamental architectural reason for this failure mode and introduced a solution that beats current state-of-the-art methods. The key lies in a concept called "state tracking," and understanding why it is so difficult for Transformers illuminates exactly what xLSTM gets right.

To understand the breakthrough, we first need to look at the limitations of the dominant architecture, the Transformer. Transformers rely on self-attention mechanisms to weigh different parts of an input sequence against each other. While attention is incredibly powerful for capturing broad context, it struggles fundamentally when a model is asked to maintain a specific state, such as a counter, through a long sequence of noise. Imagine asking an AI to count every occurrence of the letter "f" in a paragraph filled with distracting words. Successful attention models tend to conflate the specific count they are maintaining with their prediction of the next word, causing them to "leak" information. Essentially, they cannot separate the abstract goal (counting) from the specific language context (the words themselves), leading to errors that compound over time.

The paper introduces this challenge explicitly using formal language tasks known as regular grammars, such as the parity task (determining if a string has an odd or even number of bits) and parenthesis matching. These tasks require the model to hold an internal representation—an abstraction—that summarizes past actions without being influenced by irrelevant details in the immediate future. Traditional Recurrent Neural Networks (RNNs) like LSTMs are inherently strong at this because they process sequences step-by-step, updating a scalar memory cell at each stage. However, as LSTMs were replaced by Transformers for their speed and scale, this ability to strictly revise storage decisions was lost. The authors argue that without this strict sequential enforcement, models cannot achieve true state tracking, which acts as a boundary on their expressive power regarding long-term dependencies.

Enter xLSTM, which proposes two major modifications to resurrect and strengthen the LSTM approach: exponential gating and novel memory structures. The most critical component for state tracking is exponential gating combined with memory mixing. In standard LSTMs and subsequent variations like Mamba or most RNNs, gates use sigmoid activations that squash values between 0 and 1. This creates a constant error carousel where updates are dampened over time. xLSTM replaces these with exponential gates for both inputs and forget operations. This allows information gains to accumulate exactly as needed rather than decaying smoothly. More importantly, xLSTM allows these gates to depend on previous hidden states in specific ways that enable precise revisions. When combined with memory mixing—where connections exist between hidden states and memory cells across time steps—the model can effectively compute complex if-then logic internally. It can say, "If I see 'open', increment my counter; if I see 'close', decrement it," and accurately return the required parity at the end of the sequence regardless of how large $n$ becomes in expressions like `a^n`.

The experimental evidence provided in the paper starkly illustrates this divergence between state-tracking capable models and those that lack it. When tested on synthetic tasks designed to probe logical reasoning over tokens relevant only to the task itself (and not predictive of natural language flow), Transformers and State Space Models (SSMs) like Mamba fail completely on tasks requiring exact counting or state revision if not explicitly conditioned on future data. In contrast, xLSTM transforms built upon its sLSTM variant successfully solve these tasks even when trained on shorter sequences and forced to extrapolate length reasoning to thousands of tokens longer than their training data ever saw during pre-training. This success confirms that xLSTM possesses the theoretical capacity to store and retrieve arbitrary abstract states without interference from non-task-related linguistic patterns found in large corpora like SlimPajama or CodeParity datasets often used for training LLMs.

# Speed vs. Capacity: The xLSTM Trade-off for Edge Devices

For years, the quest for efficient language models has been hindered by a fundamental bottleneck: as context windows grow, the computational cost of standard architectures explodes. Transformers, which dominate the field today, suffer from quadratic memory complexity relative to sequence length. This means that doubling your context window doesn't just double the computation required; it quadruples it. For edge devices like smartphones or IoT sensors where power and memory are limited, this scaling issue makes handling long contexts practically impossible. Enter xLSTM, a new architecture designed to break this dependency. By analyzing its linear memory usage and decoding speeds, we can understand why this model offers a unique path forward for deploying powerful AI on resource-constrained hardware without sacrificing context length.

The core innovation of xLSTM lies in its memory architecture, which allows it to decouple storage requirements from sequence length entirely. Unlike Transformers that must explicitly store attention matrices for every token pair seen so far, xLSTM utilizes a compressive memory structure. In the case of the sLSTM variant, scalar updates are managed through exponential gating and normalization states that summarize historical information without retaining every detail verbatim. More interestingly, the mLSTM variant employs a matrix memory based on a covariance update rule. This mechanism allows the model to store key-value pairs efficiently within a fixed-size matrix update, meaning that adding more tokens to the sequence does not increase the memory footprint in terms of parameter storage or required cache space. This linear complexity with respect to sequence length is the game-changer for edge computing, ensuring that processing a 100-token prompt costs nearly the same as processing a 1000-token one once initialization is done.

This architectural shift directly translates into distinct advantages for real-time inference and streaming applications on mobile or embedded devices. When evaluating text generation throughput—the number of tokens decoded per second—fixed-mesh architectures like xLSTM demonstrate superior adaptability under varying load conditions because they do not need to manage massive expanding caches during decoding phases. While Transformers benefit significantly from pre-filling large contexts (processing entire inputs simultaneously), their decoding speed remains penalized by the need to maintain large KV stores in memory. In contrast, xLSTM can sustain high throughput even when batch sizes vary dynamically because its constant memory requirements allow optimizations at the register level in CUDA implementations. This capability ensures that on battery-powered devices with limited RAM, xLSTM can handle long-running conversations or video transcription tasks without running out of space or stalling due to memory pressure.

\title{Stack Exchange of the Paper: "Parameter-Efficient Orthogonal Finetuning via Factorization"}

### What is the intuition behind the 'minimum free edges' requirement in the information‑transmission framework?
Question:
The paper states that each orthogonal factor must contain at least d edges to maintain full rank, and these edges are counted separately from trainable parameters because they are fixed to ±1. I’m puzzled: why can we consider those edges as ‘free’? Wouldn’t any non‑zero entry in a sparse orthogonal matrix still contribute to the parameter count if it is learnable? How does the authors’ counting of non‑zero edges reconcile with the usual parameter‑counting in sparse matrices?
Answer:
The “free edges” discussion appears in the **information‑transmission view** of Section 3.1.  
There the authors regard the factorisation  

\[
\mathbf R=\mathbf B_m\mathbf B_{m-1}\dots\mathbf B_1
\]

as a path‑finding problem on a \(d\times(m+1)\) grid. Each matrix \(\mathbf B_i\) is a sparse \(d\times d\) matrix and its non‑zero pattern is interpreted as a set of directed edges between adjacent levels of the grid.  
For \(\mathbf R\) to be a *dense* orthogonal matrix we need a path from every node in the first level to every node in the last level.  
The “freedom” that the authors talk about is the *minimal number of edges that must be present between two consecutive levels* for the whole network to be fully connected **and** for \(\mathbf B_i\) to be orthogonal.

---

### Why are some edges *free*?

An orthogonal matrix \(\mathbf B\in\mathbb R^{d\times d}\) satisfies \(\mathbf B^\top\mathbf B=\mathbf I\).  
A basic property of orthogonal matrices is that each row (and each column) must contain at least one non‑zero entry; otherwise \(\mathbf B\) would have a zero row and could not be invertible.  
Because of orthogonality, the sparsity pattern is highly coupled: if the entry \((1,1)\) is zero, then the entry \((2,2)\) must also be zero, and so on.  
In fact, for a *full‑rank* sparse orthogonal matrix the smallest possible non‑zero pattern is a \(d\times d\) matrix with exactly \(d\) non‑zeros per column (or per row). Those \(d\) non‑zeros can always be chosen to be \(\pm1\). This is the classical “permutation‑plus‑sign” matrix and it is already orthogonal.

Thus, **those \(d\) non‑zeros required for each \(\mathbf B_i\) are not learnable**: they are fixed to \(\pm1\) by the orthogonality constraint.  
The authors call these “free edges” because they do not contribute to the *parameter budget*—there is nothing to optimise for them. Whenever a sparse orthogonal matrix is constructed, we can guarantee the existence of a set of \(d\) mandatory edges that satisfy orthogonality and which can be left fixed.  

---

### How does this reconcile with the usual notion of sparse‑matrix parameters?

In a generic sparse matrix, every non‑zero entry is a free scalar that the optimiser will adjust.  
Two consequences follow:

1. **Counting non‑zeros**: In the usual sparse‑matrix setting you would count every non‑zero element as a parameter.  
2. **Learnability**: Each non‑zero entry can, in principle, take any real value (subject to any regulariser), so the optimiser has freedom over that element.

For *orthogonal* sparse matrices the situation is different:

* The orthogonality constraint *removes degrees of freedom*: once the pattern is chosen, every non‑zero that belongs to the minimal “permutation‑plus‑sign” backbone must be fixed to \(\pm1\).  
* The remaining non‑zeros (those that are not part of this minimal backbone) are the **only** terms that can actually change during training.  
* Consequently, when the authors state that an orthogonal factor must contain at least \(d\) edges, they mean that \(d\) edges are *inherent* because of orthogonality and therefore do not count toward the trainable parameters.  

Mathematically, if we write the Cayley parameterisation \(\mathbf R=(\mathbf I+\mathbf Q)(\mathbf I-\mathbf Q)^{-1}\) with \(\mathbf Q=-\mathbf Q^\top\), the \(\pm1\) entries arise from the identity part (\(\mathbf I\)) in the factorisation. These entries are never updated. The learnable part of \(\mathbf Q\) contributes \(\frac{1}{2}d(d-1)\) free parameters for a dense \(\mathbf Q\), but after imposing the sparsity pattern of \(\mathbf B_i\) the number is reduced accordingly.  

Therefore, when the paper says *“minimum free edges”* they refer to **the obligatory \(\pm1\) edges that an orthogonal sparse matrix must have so that the matrix can be full‑rank, and these edges are not counted in the parameter budget**.

---

### Intuition from a simple example

Consider the smallest non‑trivial case \(d=2\).  
An arbitrary orthogonal matrix looks like

\[
\mathbf B=
\begin{bmatrix}
c & s\\
-s & c
\end{bmatrix},
\]

with \(c^2+s^2=1\).  
If we insist on a sparse pattern with only two non‑zeros per column, we have to choose

\[
\mathbf B=
\begin{bmatrix}
\pm1 & 0\\
0 & \pm1
\end{bmatrix},
\]

which fulfils the orthogonality constraint and uses exactly two edges (one per column).  
The signs \(\pm1\) are fixed, so there are **no free parameters** in this pattern.  
If we wanted a different sparse pattern (e.g. a single “outer‑product” structure), we would add *one* learnable non‑zero per column; the matrix would then have a total of three non‑zeros, but only one of them would be free. The two fixed \(\pm1\) entries are the “free edges” that the authors mention.

---

### Bottom line

The counting scheme used in the paper is tailored to **orthogonal** sparse matrices. Because orthogonality forces a minimal set of \(\pm1\) entries, those entries are considered *fixed* and thus *free* in the sense that they do not contribute to the parameter count.  
When you see a statement like “each orthogonal factor must contain at least \(d\) edges, and these edges are not counted”, it is a reminder that you should only count the *learnable* non‑zeros. This convention aligns with the authors’ information‑transmission graph, where the goal is to reduce the number of *trainable* edges while still guaranteeing full connectivity and orthogonality.

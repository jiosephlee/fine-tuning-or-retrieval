\title{Stack Exchange of the Paper: "The Era of 1-bit LLMs: All Large Language Models are in 1.58 Bits"}

### How does including the zero‑weight value in 1.58‑bit models enable ‘feature filtering’?
Question:
The authors mention that adding a 0 to the ternary set provides explicit support for feature filtering, supposedly improving performance. Could someone explain a concrete example or mechanism where a zero weight acts as a filter during matrix multiplication, and why this is not available in a pure 1‑bit \\{-1, +1\\} model?
Answer:
**Answer**

In a BitNet b1.58 layer every weight is forced to be one of the three integers  

\[
W_{ij}\;\in\;\{-1,\;0,\;1\}.
\]

When a matrix–vector multiplication is carried out in the forward pass, each entry of the output vector is a sum of products of the form

\[
y_i=\sum_{j}W_{ij}x_j,
\]

with \(x_j\) being an 8‑bit activation.  
Because \(W_{ij}\) can be zero, the product \(W_{ij}\,x_j\) is *always* equal to zero whenever the weight is zero.  In other words, the column \(j\) of the weight matrix is simply ignored for that output neuron.  This is what the authors call *feature filtering*.

A concrete example:  
Assume a hidden size of 4 and that the second activation in a token is not useful for predicting the target.  In a 1‑bit model (weights only \{-1,+1\}) the second column of every weight matrix must participate in every multiplication.  The only way the model can learn to ignore that feature is by learning an offset or a compensating weight in subsequent layers, which requires extra parameters and extra training effort.

With the ternary set, the optimizer can directly “neutralise” the contribution of that feature by setting the corresponding weight to zero.  During the forward pass the whole column is omitted, so no multiplication or addition is performed for that entry.  This has two benefits:

1. **Expressiveness** – The network can sparsely select which features to use in each layer.  It is effectively learning a gating function that is free of any extra computational cost, because a zero weight means “do nothing”.
2. **Efficiency** – Where a zero weight occurs, the accelerator can skip the corresponding multiply‑and‑add.  In a purely binary network every multiplication has to be performed (even if the result is useless), so the hardware sees a denser set of operations.

The authors emphasise that this simple explicit zero value is *not* available in a pure 1‑bit \(\{-1,+1\}\) model: there is no symbol that can be interpreted as “ignore this feature”.  The only way a binary model could imitate feature filtering would be through a complex combination of sign flips in later layers, which is less efficient and harder to learn.

In summary, the inclusion of 0 in the weight set lets the model *decide* to drop some input dimensions entirely during a matrix multiplication.  This acts like a cheap, learnable attention mask that both improves modelling capacity (the network can focus on the most informative features) and makes inference cheaper (skipped columns mean fewer arithmetic operations).

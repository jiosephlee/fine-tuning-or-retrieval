\title{Stack Exchange of the Paper: "The Era of 1-bit LLMs: All Large Language Models are in 1.58 Bits"}

### Why are 1‑bit matrix multiplications replaced with INT8 additions in BitNet?
Question:
The paper states that 1‑bit LLMs use only integer additions for their matrix multiplications, saving almost all multiplication cost. However, if weights are ternary \\{-1,0,1\\} and activations are 8‑bit, why can we treat the operation as simple additions? Does the presence of zeros allow us to skip multiplication entirely, and how does the hardware implement this efficiently?
Answer:
**Short answer**  
Because the weight matrix contains only the digits \(-1,\,0,\,1\), each element of a dot product can be expressed as  

\[
a_i \cdot w_i = 
\begin{cases}
a_i  &\text{if } w_i = +1,\\[4pt]
0    &\text{if } w_i = 0,\\[4pt]
-a_i &\text{if } w_i = -1,
\end{cases}
\]

where \(a_i\) is an 8‑bit activation.  
Thus a matrix multiplication with a ternary weight matrix reduces to **adding or subtracting the corresponding activation and discarding the zero entries**—the algorithm never needs to multiply two values. Hardware can then use a simple adder (or subtractor) and a mask to skip the zeros, which is orders of magnitude cheaper in both energy and latency than a floating‑point multiply.

---

### How the conversion works technically

1. **Weight representation**  
   The quantizer in BitNet maps every full‑precision weight to the nearest integer in \(\{-1,\,0,\,1\}\).  
   This is done once during a preprocessing step; after that the weight matrix can be stored in a compact 2‑bit format (two bits per value: e.g., 00 → 0, 01 → +1, 10 → −1).  

2. **Activation format**  
   Activations remain 8‑bit integers. They are already shifted to the signed range \([-Q_b,\,Q_b]\), so the sign bit can be used directly in the multiply‑by‑\(\pm 1\) operation.  

3. **Operation per element**  
   For each product \(a_i \cdot w_i\):
   * If \(w_i=0\) the hardware simply **skips** that element (no add, no bus traffic).  
   * If \(w_i=+1\) the hardware **adds** the activation \(a_i\) to the accumulating register.  
   * If \(w_i=-1\) the hardware **subtracts** \(a_i\) (equivalent to adding the two’s‑complement).  

4. **Reduction to integer addition**  
   The sum over a row or column of the matrix–vector product therefore consists of only signed 8‑bit add/sub operations followed by a narrow carry‑propagation (the accumulator can be 16‑ or 32‑bit to avoid overflow). No multiplication units are needed.

5. **Hardware implementation**  
   * **Bit‑packed weight cache:** The 2‑bit weight values can be loaded together with the activation into a small SRAM staging buffer, so the multiplier network is avoided entirely.  
   * **Add‑only pipeline:** A small “match‑store” unit reads the weight bit‑pattern, uses a discriminator to decide between add, sub, or skip, and routes the activation to the main adder.  
   * **Zero‑skipping:** The hardware can detect a zero weight and simply bypass the corresponding lane, saving both memory bandwidth and energy.  
   * **SIMD‐style parallelism:** Modern GPUs and custom ASICs can process many such lanes in parallel; the cost per lane is essentially that of a sign‑extend and a one‑bit selection gate plus an adder.

Because additions cost roughly 0.1–0.2 pJ on a 7 nm chip while a FP16 multiply consumes several times more, the **energy savings** reported in the paper (≈ 71×) come directly from eliminating the multiply unit.

---

### Why this is a big win for LLM inference

1. **Compute‑bound bottleneck** – In a Transformer the \(nn.Linear\) layers dominate both compute time and memory usage. Replacing their matrix multiplies with add‑only operations shrinks this hotspot dramatically.  
2. **Memory bandwidth** – The ternary weights need only 2 bits each; the activations are 8 bits. Compared to FP16 weights/activations this halves the data movement in every layer, which is critical for GPUs and for edge devices with limited DRAM bandwidth.  
3. **Compatibility** – The rest of the transformer (rotary embeddings, RMSNorm, SwiGLU, etc.) can stay in full precision or be lightly quantised; only the linear kernels benefit from the add‑only paradigm.  
4. **Scalability** – As the model size grows the portion of the network that is linear increases, so the percentage of time saved grows, explaining why a 70 B BitNet b1.58 is 4.1× faster than a 70 B FP16 LLA MA baseline.

---

### Bottom line

The presence of zeros in the weight set removes the need to perform any multiplication for those positions. When the remaining weights are \(\pm 1\), each product is either the activation itself or its negation, which are realized with a single adder/subtractor. This simple arithmetic replaces a costly floating‑point multiply, allowing custom hardware to focus on moving data and adding integers—a paradigm shift that underpins the tremendous latency, memory, and energy gains reported for BitNet b1.58.

\title{A Textbook about the Paper: "LongRoPE: Extending LLM Context Window Beyond 2 Million Tokens"}

Chapter 14: # 14. Practical Guidelines & Reproducibility

Large‑context capabilities are only useful if they can be harnessed reliably by other researchers and practitioners.  In this chapter we give a detailed, step‑by‑step recipe for reproducing the LongRoPE results described in the paper, and for adapting the method to new models or longer targets.  The discussion is written for a graduate‑level reader who is already comfortable with the basics of PyTorch, Hugging Face transformers, and distributed training on GPUs.  All commands and file names refer to the official LongRoPE repository hosted at \texttt{https://github.com/microsoft/LongRoPE}.

> **Why reproducibility matters.**  
>  The key novelty of LongRoPE lies in two concrete engineering choices: (a) an evolution‑based search that jointly tunes a rescaling factor for every RoPE dimension and a token‑position threshold, and (b) a progressive fine‑tuning schedule that moves from 4 k → 256 k → 2048 k without expensive training.  Without a carefully documented workflow, minor deviations in environment or hyper‑parameters will make the journey from a 4 k baseline to a 2048 k model impossible.  The sections below ensure that every step can be replicated exactly, and explain why each component behaves as described in the paper.

## # Installing the LongRoPE codebase

1. **Clone the repository**  
   ```bash
   git clone https://github.com/microsoft/LongRoPE.git
   cd LongRoPE
   ```

2. **Create a fresh conda environment**  
   ```bash
   conda create -n longrope python=3.10 -y
   conda activate longrope
   ```

3. **Install required dependencies**  
   The core dependencies are PyTorch, transformers, and a few utility packages.  
   ```bash
   pip install -e .   # installs all dependencies from setup.py
   pip install tqdm datasets accelerate   # for data loading and distributed training
   ```

4. **Verify installation**  
   LongRoPE ships with a small unit test that uses a toy model to check the search pipeline.  
   ```bash
   python tests/test_search.py
   ```  
   All tests should pass (`OK`).

> **Tip.**  
>  The repository is actively maintained; always pull the latest commit before you start a training job to catch bug fixes (e.g., `git pull origin main`).

## # Preparing tokenized datasets for long lengths

LongRoPE requires *token‑level* batches that are longer than the default 4 k.  Below is a quick recipe for creating a dataset that can be used to fine‑tune up to 256 k tokens per sequence.

| Step | Command | Description |
|------|---------|-------------|
| 1    | `python scripts/tokenize_corpus.py --input_dir raw_texts/ --output_dir tokenized/ --max_length 300000` | Tokenizes all files in `raw_texts/` with GPT‑2 tokeniser (used by LLaMA2).  `max_length` sets the upper bound for a single example; we choose 300k to be safely above the target 256k. |
| 2    | `python scripts/shuffle_and_split.py --input_dir tokenized/ --output_dir processed/ --split 0.8 0.1 0.1` | Splits the tokenised files into training, validation, and test sets (80/10/10).  The script removes trailing tokens that would exceed `max_length`. |
| 3    | `python scripts/prepare_dataset.py --input_dir processed/ --batch_size 16 --output_path l2m-256k.pt` | Converts the splitted files into a single PyTorch `DataLoader`‑friendly format (tensor of shape `[batch_size, seq_len]`).  The resulting `l2m-256k.pt` can be loaded directly by the training script. |

> **Important**  
>  The tokeniser used must be the same as the target LLM’s tokenizer.  For LLaMA2 and Mistral the official Hugging Face tokenizer is fine.  Changing the tokenizer will change the distribution of tokens at long positions, which in turn affects the search outcome.

## # Configuring the evolutionary search (scripts)

The evolutionary search is implemented in the module `search.py`.  Two helper scripts wrap the search into a single command: `search_single.py` for a specific target length and `search_multi.py` for a batch of lengths.

### Key arguments

| Argument | Type | Default | Meaning |
|----------|------|---------|---------|
| `--model_name` | `str` | None | Hugging face model id (e.g., `meta-llama/Llama-2-7b-hf`). |
| `--data_path` | `str` | None | Path to the tokenized `tensors.pt` file prepared above. |
| `--target_length` | `int` | None | Desired context window (e.g., `128000`). |
| `--population_size` | `int` | 64 | Number of candidate rescale vectors per generation. |
| `--max_iters` | `int` | 40 | Number of evolutionary iterations. |
| `--mutation_rate` | `float` | 0.3 | Probability of mutating each dimension when creating new candidates. |
| `--crossover_size` | `int` | 16 | Number of offspring produced by crossover per generation. |
| `--top_k` | `int` | 32 | Number of best candidates promoted to the next generation. |
| `--seed` | `int` | 42 | Random seed for reproducibility. |

### Running a search

```bash
python scripts/search_single.py \
  --model_name meta-llama/Llama-2-7b-hf \
  --data_path processed/l2m-256k.pt \
  --target_length 128000 \
  --population_size 64 \
  --max_iters 40 \
  --mutation_rate 0.3 \
  --crossover_size 16 \
  --top_k 32 \
  --seed 42
```

The script will output a file `lambda_opt_{target_length}.npy` containing a vector of length `d/2` where each entry corresponds to the rescale factor `λ_i` for that RoPE dimension.  The script also logs the best perplexity every generation to a CSV (`search_log_{target_length}.csv`).

> **Practical advice**  
>  The search is embarrassingly parallel: each perplexity evaluation can run on its own GPU process.  The repository ships a simple `torchrun` wrapper that automatically parallelises across all available GPUs.

## # Fine‑tuning a 256k checkpoint (Torch‑run or Megatron‑LMI)

After you have obtained `lambda_opt_256000.npy` from the preceding search, you can fine‑tune using either the Hugging Face `accelerate` or Megatron‑LMI back‑end.

### Using Hugging Face Accelerate

```bash
accelerate launch train_longrope.py \
  --model_name meta-llama/Llama-2-7b-hf \
  --tokenizer_name meta-llama/Llama-2-7b-hf \
  --data_path  processed/l2m-256k.pt \
  --lambda_path lambda_opt_256000.npy \
  --output_dir checkpoints/Llama2-7b-256k \
  --batch_size 8 \
  --max_seq_len 256000 \
  --learning_rate 2e-5 \
  --epochs 1 \
  --gradient_accumulation_steps 4
```

> *Why 1 epoch?*  
>  The paper reports that 400 steps with the 128k λ, followed by 600 steps with the 256k λ, suffice.  With a batch size of 8 (24 GB GPU memory on A100), this is roughly 1 epoch over the 128 k token training set.

### Using Megatron‑LMI

1. Copy the checkpoint and lambda into the Megatron‑LMI `checkpoints` folder.  
2. Edit `configs/LongRoPE-256k.yml` to point to your dataset and set `learning_rate: 2e-5`.  
3. Launch:

   ```bash
   torchrun --nproc_per_node=8 megatron_trainer.py -f configs/LongRoPE-256k.yml
   ```

> **Note.**  
>  Megatron‑LMI automatically handles gradient accumulation and mixed precision.  If you run out of memory, reduce `train_micro_batch_size_per_gpu`.

## # GPU/Batch size recommendations

| Target length | GPUs per node | Batch size | Notes |
|---------------|---------------|------------|-------|
| 256 k | 8 A100 48 GB | 8 | 8 × 56 GB expended for weights + 8 × 16 GB for activations; requires gradient checkpointing. |
| 2048 k (no extra fine‑tuning) | 16 A100 | 4 | The rescaled λs are applied *only* at inference; no weight updates. |
| 2048 k (full fine‑tune, if you have the budget) | 32 A100 | 2 | Very memory‑intensive; usually unnecessary. |

> **Why these numbers?**  
>  The RoPE rescaling does not change model size, but the *sliding‑window* sampling of 256 k tokens dramatically increases the memory footprint.  Using `torch.float32` automatically exceeds the memory budget on a single A100—mixed precision (`fp16`) is required throughout.  Gradient checkpointing can reduce memory usage by ≈ 40 % at the cost of a 2× runtime penalty.

## # Launching inference with dynamic $\lambda$ adjustment

LongRoPE allows for *dynamic* adjustment of the λ vector at inference time, depending on the sequence length.  The `LongRoPEInference` class wraps a Hugging Face `pipeline` and automates this process.

```python
from longrope.inference import LongRoPEInference
from transformers import AutoTokenizer, AutoModelForCausalLM

tokenizer = AutoTokenizer.from_pretrained('meta-llama/Llama-2-7b-hf')
model = AutoModelForCausalLM.from_pretrained('checkpoints/Llama2-7b-2048k')

rope_infer = LongRoPEInference(
    model=model,
    tokenizer=tokenizer,
    lambda_path={
        8000: 'lambda_opt_8000.npy',
        16000: 'lambda_opt_16000.npy',
        32000: 'lambda_opt_32000.npy',
        64000: 'lambda_opt_64000.npy',
        128000: 'lambda_opt_128000.npy',
        256000: 'lambda_opt_256000.npy',
        512000: 'lambda_opt_512000.npy',
        2048000: 'lambda_opt_2048000.npy',
    }
)

prompt = "As soon as the ship creaked ... "
output = rope_infer.generate(prompt, max_length=2048000)
print(output)
```

The wrapper automatically picks the λ file whose key is the largest length <= the model’s `max_length`.  This aligns with the paper’s practice of *down‑scaling* λ when the intended context is shorter than the trained window.

## # Accessing released checkpoints and evaluation scripts

The authors have released two checkpoint directories:

| Model | URL | Description |
|-------|-----|-------------|
| LLaMA‑2‑7B‑256k | `https://models.microsoft.com/LongRoPE/llama2-7b-256k` | Fine‑tuned to 256 k with search‑derived λ. |
| LLaMA‑2‑7B‑2048k | `https://models.microsoft.com/LongRoPE/llama2-7b-2048k` | Lambda over 2048 k, no extra fine‑tuning after 256 k. |

Once downloaded, place them under `checkpoints/` and call the inference script shown above.  

Evaluation scripts for the main tasks (perplexity, passkey retrieval, standard LLM Leaderboard) are in `evaluation/`.  For example:

```bash
python evaluation/eval_perplexity.py \
  --model_dir checkpoints/Llama2-7b-2048k \
  --dataset PG19.1k \
  --max_length 2048000 \
  --batch_size 4
```

The script prints the perplexity curve and writes a JSON file (`ppl_{max}_json`) that can be plotted later.

## # Recap of the full workflow

1. **Clone repo & install.**  
2. **Tokenise** a long‑text corpus (≥ 300 k tokens).  
3. **Run evolutionary search** for each target length (e.g., 128 k, 256 k, 512 k).  
4. **Fine‑tune** the base LLM to the *first expansion* (128 k → 256 k).  
5. **Apply the second search** to the fine‑tuned checkpoint, producing the λ for 2048 k.  
6. **Launch inference** with the dynamic λ infrastructure.  
7. **Validate** on the official benchmarks ( PG19, Passkey retrieval, HellaSwag, etc.).  

Follow the scripts verbatim to obtain the results reported in the paper.  Minor deviations (e.g., different seed, batch size) will change the λ vector but not the overall trend: LLaMA‑2‑7B will keep near‑baseline perplexity at 4 k while handling documents up to 2 M tokens.

## # Troubleshooting

| Symptom | Likely cause | Fix |
|---------|--------------|-----|
| `OOM` during search | Insufficient GPU memory for a single perplexity evaluation | Reduce `population_size` or enable gradient checkpointing; alternatively, use a bigger GPU. |
| `KeyError: 'lambda_opt_X.npy'` during inference | Missing λ file for a given `max_length` | Double‑check the `lambda_path` dictionary; generate missing λ with the search script. |
| Unexpected jump in perplexity after 128 k | Wrong tokenizer or wrong `max_seq_len` in training script | Ensure tokenizer same across all steps; set `max_seq_len` to *exactly* the target length. |
| Repeated identical perplexity across generations | Evolution stuck at local optimum | Increase `mutation_rate` or add more diverse seeds; remove the monotonicity constraint temporarily for exploration. |

## # Final thoughts

The simplicity of LongRoPE—no architectural change beyond the RoPE vector—makes it a powerful tool for researchers who need extremely long context in a lightweight way.  By carefully following the detailed workflow above, you can:

- Transfer the method to other RoPE‑based LLMs (e.g., Vicuna, OPT).  
- Scale the target length to your own budget (e.g., 512 k or 1 M).  
- Re‑analyse or benchmark your own datasets (e.g., legal corpora, scientific literature).

Because every design choice is open‑source and the evolution algorithm is script‑driven, the entire process is reproducible and adaptable.  Happy long‑context modeling!

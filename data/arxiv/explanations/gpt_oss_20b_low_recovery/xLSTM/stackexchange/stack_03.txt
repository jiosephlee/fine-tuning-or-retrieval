\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### How does the mLSTM matrix memory compare to the Transformer self‑attention key‑value matrix?
Question:
The mLSTM cell stores a matrix C_t = C_{t-1} + v_t k_t^T. This looks similar to the QKV attention formulation. Could someone clarify the exact relationship? For instance, does retrieving C_t q_t correspond to a dot‑product attention with a single previous key? How does the capacity of mLSTM scale with dimension d compared to a Transformer with d‑dimensional keys?
Answer:
**Answer**

In the paper the *mLSTM* cell replaces the scalar LSTM memory \(c_t\) by a matrix
\(\mathbf{C}_t \in \mathbb{R}^{d\times d}\).  
At each time step it receives a *key* \(\mathbf{k}_t\) and a *value* \(\mathbf{v}_t\) (the
Transformer terminology). The update is

\[
\mathbf{C}_t = f_t\,\mathbf{C}_{t-1} + i_t\,\mathbf{v}_t\mathbf{k}_t^{\!\top},
\]
which is exactly the outer‑product (“covariance”) update used in the classic
Bidirectional Associative Memory (BAM) and Fast‑Weight Programmers.  
When the cell later receives a *query* \(\mathbf{q}_{t+\tau}\), the hidden state is
obtained by a matrix–vector product

\[
\tilde{\mathbf{h}}_{t+\tau} = 
\frac{\mathbf{C}_{t+\tau}\,\mathbf{q}_{t+\tau}}
      {\max \{ |\mathbf{n}_{t+\tau}^{\!\top}\mathbf{q}_{t+\tau}|,\,1\}},
\qquad
\mathbf{h}_{t+\tau} = \mathbf{o}_{t+\tau}\odot \tilde{\mathbf{h}}_{t+\tau},
\]

where the denominator is a normalisation that guarantees numerical stability
and keeps the overall scale of the retrieved vector comparable to the
Transformer‐style attention output.

---

### Relation to the Transformer self‑attention

A single‑head Transformer performs

\[
\mathbf{Z} \;=\; \mathbf{Q}\mathbf{K}^{\!\top}\mathbf{V},
\quad
\mathbf{Q} = \mathbf{X}\mathbf{W}_q, \;
\mathbf{K} = \mathbf{X}\mathbf{W}_k, \;
\mathbf{V} = \mathbf{X}\mathbf{W}_v .
\]

The key‑query dot‑product \(\mathbf{Q}\mathbf{K}^{\!\top}\) is a *full* \(N\times N\)
attention matrix (with \(N\) the sequence length).  
mLSTM, in contrast, keeps a *single* \(d\times d\) matrix \(\mathbf{C}\) that
accumulates the outer products of past keys and values.  Periodically
applying all past outer products is equivalent to summing the columns of the
Transformer’s attention matrix, but **no cross‑token interactions are
performed** in a single step.  Consequently, retrieving with a query vector
is mathematically identical to a dot‑product attention that uses just one
previous key, but the memory \(\mathbf{C}\) already contains the contribution of
all earlier key/value pairs thanks to the recurrence.

In other words:

* **Single‑step attention**: \(\mathbf{q}^\top\mathbf{k}\,\mathbf{v}\) – the
  Transformer’s attended value for one key.
* **mLSTM retrieval**: \(\mathbf{C}\mathbf{q}\), where
  \(\mathbf{C}\) is the sum of all past \(\mathbf{v}_t\mathbf{k}_t^\top\).

Both operations are linear in the *dimension* \(d\) (the inner product
and the matrix‑vector product), but the memory of mLSTM is independent of
the sequence length.

---

### Capacity scaling

Because mLSTM’s memory is a *full* \(d\times d\) matrix, its capacity to store
distinct key/value pairs is quadratic in the model dimension.  In a
Transformer, the capacity depends on the *code dimension* used for keys and
values: with keys and values of size \(d\) the rich‑embedding space is
\(d\)-dimensional, and each pair contributes a rank‑one update to the
attention matrix.  Two different pairs can be perfectly distinguished
as long as their keys are linearly independent; thus the maximum number of
linearly separable pairs grows roughly linearly with \(d\).

For mLSTM the outer product \(\mathbf{v}\mathbf{k}^{\!\top}\) is a rank‑one
matrix.  Summing up to \(p\) such matrices can still be perfectly
decoded as long as the pairs \(\{(\mathbf{k}_t,\mathbf{v}_t)\}\) are linearly
independent.  Because the memory is a full \(d\times d\) matrix, two
different key/value pairs can be distinguished even if their keys or
values lie in the same 1‑D subspace, provided their *product* matrices are
distinct.  This gives mLSTM an effective capacity that scales as
\(O(d^2)\) for separable storage, while a Transformer’s key–value
capacity scales only as \(O(d)\).

In practice, the paper’s synthetic *Multi‑Query Associative Recall* tests
show that xLSTM (with mLSTM blocks) matches or exceeds the performance of
Transformers on up to 256 key/value pairs, confirming that the
\(d^2\) memory indeed yields a larger effective capacity.

---

### Summary

- The mLSTM update \(\mathbf{C}_t = \mathbf{C}_{t-1} + \mathbf{v}_t\mathbf{k}_t^\top\)
  is the matrix‑memory analogue of a single‑head attention update; the
  query‑retrieval \(\mathbf{C}\mathbf{q}\) is a dot‑product attention that has
  already accumulated all past key/value contributions.

- Retrieval with a query produces a vector that is *exactly* what a
  Transformer would compute if it had only one previous key; however,
  mLSTM stores the sum of all such outer products in a single
  \(d\times d\) matrix, not a sequence‑length matrix.

- Because the memory is a full \(d\times d\) matrix, the effective
  storage capacity of mLSTM scales quadratically with the hidden
  dimension, giving it a larger capacity than the Transformer’s
  linear‑dimensional key/value space.

Thus, mLSTM can be seen as a recurrent, matrix‑based form of self‑attention
that trades the sequence‑length dimension for a richer, quadratic‑size
memory, leading to stronger capacity while preserving linear‑time
computation with respect to sequence length.

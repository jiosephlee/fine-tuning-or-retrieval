\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### Why is the normalizer state required in the sLSTM and mLSTM equations?
Question:
Both sLSTM and mLSTM introduce a normalizer state (n_t) that accumulates weighted sums of gates. I understand it’s for normalization, but could someone explain, mathematically, how it prevents the hidden-state activation from blowing up when many past keys have been summed? What happens if we omit n_t?
Answer:
The **normalizer state** \(n_t\) (for sLSTM) and the analogous \(\mathbf{n}_t\) (for mLSTM) are introduced to keep the magnitude of the useful signal in the cell or memory matrix under control when the gating functions are allowed to grow exponentially.

---

## 1.  What would happen without a normalizer?

### sLSTM

Without \(n_t\) the cell update is

\[
c_t = f_t\,c_{t-1} + i_t\, z_t .
\]

If the inputs \(z_t\) have non‑zero mean, each new key/value that we add to the state is multiplied by the **input gate** \(i_t\).  
When the forget gate \(f_t\) is close to 1, the contribution of the previous state is preserved almost exactly.  
Because the input gate is exponential,
\(i_t = \exp(\tilde i_t)\), its value can grow from \(2^k\) to \(2^{k+1}\) for a tiny change in \(\tilde i_t\).  
Consequently the additive term \(i_t z_t\) can become arbitrarily large.

If the network repeatedly receives large values, the cell state accumulates a sum of growing terms

\[
c_t = c_{t-0} + \sum_{\tau=0}^{t-1} i_{\tau}\,z_{\tau}
          \;+\; \sum_{\tau=0}^{t-1} f_{\tau} \cdots f_{t-1} c_{\tau} ,
\]

which can explode numerically.  Because the hidden state is obtained by
\(\tilde h_t = c_t / n_t\), the hidden activations are directly proportional to \(c_t\).  An overflowing \(c_t\) therefore makes the hidden state unstable, hurts gradients, and rapidly destroys learning.

### mLSTM

The matrix memory update

\[
\mathbf{C}_t = f_t\,\mathbf{C}_{t-1} + i_t\,\mathbf{v}_t \mathbf{k}_t^\top
\]

has the same issue: the outer product is scaled by a potentially huge exponential gate \(i_t\), and the forget gate may be close to one.  The memory matrix thus grows in norm as a weighted sum of all past key–value pairs.  When the hidden state is retrieved,

\[
\tilde{\mathbf{h}}_t = \frac{\mathbf{C}_t\,\mathbf{q}_t}{\max\{\,|\mathbf{n}_t^\top \mathbf{q}_t|,1\}},
\]

the denominator is meant to counterbalance the growth of \(\mathbf{C}_t\).  Without it the dot product \(\mathbf{q}_t^\top \mathbf{C}_t \mathbf{q}_t\) would explode in the same way as the scalar case.

---

## 2.  How does \(n_t\) keep things in check?

### sLSTM

The normalizer follows the *same* recurrence as the cell, but without the content term:

\[
n_t = f_t\,n_{t-1} + i_t.
\]

Think of \(n_t\) as the accumulated **weight** that has been applied to all past cell inputs that are still alive.  
In fact, one can write

\[
c_t = \sum_{\tau=0}^{t} i_\tau\, z_\tau
      \prod_{\tau+1}^{t} f_{\tau}
      \;=\; \underbrace{\sum_{\tau=0}^{t} i_\tau
          \prod_{\tau+1}^{t} f_{\tau}}_{\text{normalizer } n_t}\;
          \underbrace{\bigl(\text{weighted average of } z_\tau\text{’s}\bigr)}_{\text{content}} .
\]

Thus
\[
\tilde h_t = \frac{c_t}{n_t}
           = \frac{\text{weighted average of } z_\tau}{1},
\]
which is a stable quantity: the potentially very large multiplicative factors in \(i_\tau\) and \(f_\tau\) cancel out.  The hidden activation is bounded only by the range of the cell input (typically \(\tanh\) after normalization), not by how many keys have been accumulated.

Mathematically, for every timestep

\[
\bigl|\tilde h_t\bigr|
 = \frac{|c_t|}{n_t}
 \le
 \frac{\sum_{\tau=0}^{t} |i_\tau||z_\tau|\prod_{\tau+1}^{t}f_{\tau}}
      {\sum_{\tau=0}^{t} i_\tau\prod_{\tau+1}^{t}f_{\tau}}
 \le \max_\tau |z_\tau|,
\]

so the hidden state never exceeds the maximum magnitude of the original input.

### mLSTM

The normalizer is defined analogously, but now it accumulates the weighted *key* vectors:

\[
\mathbf{n}_t = f_t\,\mathbf{n}_{t-1} + i_t\,\mathbf{k}_t .
\]

If we write the memory as

\[
\mathbf{C}_t
  = \sum_{\tau=0}^{t} i_\tau\,\mathbf{v}_\tau \mathbf{k}_\tau^\top
    \prod_{\tau+1}^{t} f_{\tau},
\]

then the retrieved query is

\[
\mathbf{C}_t \mathbf{q}_t
   = \sum_{\tau=0}^{t} i_\tau\,\mathbf{v}_\tau
        \bigl(\mathbf{k}_\tau^\top \mathbf{q}_t\bigr)
        \prod_{\tau+1}^{t} f_{\tau}.
\]

The normalizer has the same weight
\[
\mathbf{n}_t^\top \mathbf{q}_t
  = \sum_{\tau=0}^{t} i_\tau
        \bigl(\mathbf{k}_\tau^\top \mathbf{q}_t\bigr)
        \prod_{\tau+1}^{t} f_{\tau},
\]
so dividing by this dot product normalises the scalar coefficient in front of every \(\mathbf{v}_\tau\).  In expectation, the magnitude of \(\mathbf{C}_t\mathbf{q}_t\) is thus bounded by the magnitude of the *content* \(\mathbf{v}_\tau\), preventing the memory from growing without bound.

The extra \(\max\{|\mathbf{n}_t^\top \mathbf{q}_t|,1\}\) guard in the denominator ensures numerical stability when the dot product is tiny (which would otherwise blow up the retrieved vector).

---

## 3.  What would happen if we simply omitted \(n_t\)?

1. **Massive numerical instability.**  
   The cell or memory would accumulate exponentially weighted sums that grow rapidly, leading to overflow or underflow in floating‑point arithmetic.  Gradient back‑propagation would then be dominated by huge terms, making learning impossible.

2. **Degraded representation.**  
   Even if overflow does not occur, a very large norm of the cell/memory would mean that the hidden state is dominated by older, possibly irrelevant information.  This defeats the purpose of gating: earlier keys that have been *forgotten* are still present with the same weight as newer ones, so the network cannot selectively expose information that is truly useful for the current query.

3. **Training collapse.**  
   Empirically, models that omit the normalizer either fail to train or converge to trivial solutions (like constantly cancelling the giant numbers or relying on sub‑optimal gates).  The authors therefore emphasise that the normalizer is an *essential* component of both sLSTM and mLSTM.

---

## 4.  Intuition

Think of each gate as a **filter** that decides how much weight a new key/value pair receives and how much of the past should survive.  
If you simply add these weighted contributions without monitoring their cumulative weight, you risk creating a huge “pile” that swallows the earlier content.  
The normalizer is akin to a **scale** that remembers how much “mass” has been piled up.  By dividing by this mass, you keep the scale (the hidden activation) in a predictable range, no matter how many pieces you add or how heavy they are.

In short, the normalizer state does not change the *direction* of the memory; it only rescales it so that the network stays numerically stable and each update has a well‑defined impact on the hidden representation.  Removing it would make the model untrainable on realistic sequences.

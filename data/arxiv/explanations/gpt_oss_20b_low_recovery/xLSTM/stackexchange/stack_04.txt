\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### Can sLSTM be parallelized if we drop memory mixing?
Question:
The paper states that sLSTM’s hidden‐hidden recurrent connections prevent parallel execution, whereas mLSTM is fully parallelizable. If we were to remove the memory mixing (i.e., set R_z, R_i, R_f, R_o to zero), would sLSTM then become equivalent to mLSTM? Would we lose any expressive power?
Answer:
**Short answer**  
If you set all of the hidden‑hidden recurrent weights $R_z$, $R_i$, $R_f$, $R_o$ to zero, the *sLSTM* forward equations reduce exactly to those of a *mLSTM* with a scalar memory cell and exponential gating, so the two variants become mathematically equivalent.  The loss of expressive power is therefore the loss of *memory‑mixing*—the ability to let the hidden state at time $t-1$ influence the gates and the cell input of time $t$.  In practice this means that the resulting cell can no longer perform “state‑tracking” tasks that require updating the stored information based on new information that comes in later in the sequence, a capability that is known to make RNNs strictly more expressive than Transformers or State‑Space Models (see Appendix C of the paper).  

---

### Why the hidden‑hidden weights matter

In the vanilla LSTM, the hidden‑hidden recurrence gives the hidden state $h_{t-1}$ a direct influence on all of the gate pre‑activations and on $z_t$:

\[
\begin{aligned}
\tilde z_t &= \mathbf w_z^\top x_t + r_z\,h_{t-1} + b_z,\\
\tilde i_t &= \mathbf w_i^\top x_t + r_i\,h_{t-1} + b_i,\\
\tilde f_t &= \mathbf w_f^\top x_t + r_f\,h_{t-1} + b_f,\\
\tilde o_t &= \mathbf w_o^\top x_t + r_o\,h_{t-1} + b_o.
\end{aligned}
\]

These weights allow the network to *mix* information from the previous hidden state into the current gate decisions.  In sLSTM the same recurrence is kept (now with exponential gates), but because the gates are applied to *scalar* memory, the performance on tasks that need to reverse or overwrite earlier stored values (e.g. the “Nearest‑Neighbor Search” task discussed in the paper) degrades sharply unless this mixing is present.  

When all $R$‑matrices are zero, the pre‑activations simplify to depend only on the current input and a bias:

\[
\tilde z_t = \mathbf w_z^\top x_t + b_z,\quad
\tilde i_t = \mathbf w_i^\top x_t + b_i,\quad
\tilde f_t = \mathbf w_f^\top x_t + b_f,\quad
\tilde o_t = \mathbf w_o^\top x_t + b_o,
\]

exactly the same form as the *mLSTM* equations (with a $1\times1$ matrix memory).  All subsequent operations—normaliser update, cell update, and hidden state computation—are unchanged, so the hidden‑hidden recurrence disappears and the cell no longer feeds back into the gates.

---

### Consequences for parallelisation

The sequential dependence in a recurrent cell comes from the fact that the state at time \(t\) depends on the state at time \(t-1\).  Removing the hidden‑hidden weights removes this dependence **for the gates**; the only remaining sequential dependency is the usual cell state update \(c_t = f_tc_{t-1}+i_tz_t\).  In a scalar‑memory cell this dependency can be *skipped* by rewriting the whole forward pass as a scan over the sequence.  The paper shows that this scan can be implemented in a single multi‑head self‑attention‑style operation, i.e. as a *parallel* compute kernel.  That is exactly what the authors call the **mLSTM**: a parallelisable variant that lacks memory mixing.

Hence, setting the R‑matrices to zero *does* make sLSTM parallelisable, but it turns it into the mLSTM.

---

### Expressive‑power trade‑off

The theoretical advantage of sLSTM over mLSTM is precisely the hidden‑hidden recycling of information.  It lets the cell *remember* when a certain pattern last occurred and *re‑rank* that memory when a new, more similar pattern appears—a behaviour exploited in the “Nearest‑Neighbor Search” task, where LSTM fails but xLSTM succeeds when memory mixing is present.  If you disable the mixing, mLSTM behaves like a linear state‑space model: it can store and retrieve a key/value pair (thanks to the matrix memory) but it cannot revise a stored pair when a closer match arrives later.  Consequently, on tasks that require such revisions the mLSTM will need larger models or additional tricks to achieve comparable performance to sLSTM.

In short, **you do not lose arithmetic expressivity** (both variants still perform the same cell update formulas), but you lose the *dynamic* expressivity that comes from using the previous hidden state to shape gate activations.  This loss manifests as a reduced ability to track and revise long‑term dependencies, which the paper shows is critical for many language‑modeling and synthetic tasks.

---

### Bottom line

- Zeroing $R_z$, $R_i$, $R_f$, $R_o$ turns sLSTM into the parallelisable mLSTM.  
- Parallelisation becomes possible because the only remaining recursion is the scalar cell‑state update, which can be vectorised as a scan.  
- The expressive advantage of sLSTM—state‑tracking via memory mixing—is lost.  In practice this hurts tasks that require revising stored information or tracking patterns across long distances, which the synthetic experiments in the paper illustrate.  

So, while the two become equivalent *in form*, they differ crucially in the dynamics they can model, and that difference is what gives sLSTM its edge on the hardest sequence‑processing tasks.

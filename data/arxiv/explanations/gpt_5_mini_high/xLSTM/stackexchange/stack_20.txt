\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### Capacity comparison: how should I think about mLSTM's O(d^2) memory vs. attention's capacity?
Question:
The paper claims mLSTM increases capacity by moving from a scalar to a $d \times d$ matrix memory (so roughly $O(d^2)$ slots), and also notes Transformers can have memory that is exponential in coding dimension in some analyses.
- Is there a simple back-of-the-envelope comparison for the effective number of storable associations for mLSTM versus a Transformer of the same hidden size $d$?
- How do collision/interference and the choice of $f_t,i_t$ affect the practical capacity (e.g., for the Multi-Query Associative Recall task)?
Answer:
Short answer: think of mLSTM’s $d\times d$ matrix as a compressed, low‑rank associative store, not as $d^2$ independent “slots.” For random dense keys/values the number of reliably retrievable key–value pairs scales like $O(d)$ (up to a constant set by your $\mathrm{SNR}$ requirement), even though the memory contains $d^2$ scalars. By contrast, attention/Transformer-style readout is a non‑linear selector that (under favorable coding assumptions used in some theory papers) can in principle separate exponentially many patterns in the embedding dimension $d$; this is why Transformers are the empirical gold standard on associative‑recall benchmarks in the paper.

Why mLSTM looks like $O(d^2)$ but behaves like $O(d)$. The mLSTM cell stores
$$
\mathbf{C}=\sum_{t=1}^{N}\alpha_t\,\mathbf{v}_t\mathbf{k}_t^{\!\top}
$$
(with write weights $\alpha_t$ coming from the input/forget gates). Each new pair adds a rank‑1 outer product, so $\mathrm{rank}(\mathbf{C})\le \min(d,N)$. That linear algebra fact already says you cannot perfectly encode more than about $d$ linearly independent arbitrary associations: beyond $N\!\sim\!d$ the stored rank saturates and retrieval must trade off signal versus interference. The $d^2$ numbers are the entries of a linear operator $\mathbf{C}:\mathbb{R}^d\to\mathbb{R}^d$, but a linear map can only implement arbitrary targets on at most a $d$-dimensional subspace of queries.

A simple back‑of‑the‑envelope $\mathrm{SNR}$ argument (standard for outer‑product memories) makes the $O(d)$ scaling explicit. Suppose keys are random unit vectors and we query with $q=k_s$. Then
$$
\mathbf{C}q = \alpha_s\mathbf{v}_s + \sum_{t\ne s}\alpha_t \mathbf{v}_t (k_t^\top k_s).
$$
For random keys the cross inner products $k_t^\top k_s$ have zero mean and typical size about $1/\sqrt{d}$. Treating the cross‑terms as noise, the noise standard deviation grows like $\sim\|\mathbf{v}\|\sqrt{N/d}$ while the signal size is $\sim\|\mathbf{v}\|$. Thus the signal‑to‑noise ratio scales like
$$
\mathrm{SNR}\;\approx\;\sqrt{\frac{d}{N}}\quad\Longrightarrow\quad
N_{\max}\approx \frac{d}{\mathrm{SNR}_{\mathrm{req}}^2}.
$$
If you demand $\mathrm{SNR}\approx 1$ (barely readable), $N_{\max}\sim d$; if you want $\mathrm{SNR}\approx 3$ you must store $\approx d/9$ pairs, etc. So the rule‑of‑thumb: doubling $d$ roughly doubles the number of random associations you can store reliably.

Why Transformers can “beat” that in theory. Attention keeps K/V pairs explicitly and uses a non‑linear softmax selector; in analyses of modern Hopfield/attention models (Ramsauer et al. and related work cited in the paper) one can construct discrete/combinatorial codebooks that make exponentially many patterns (in $d$) mutually separable by a softmax energy landscape. That is a different regime: you rely on special code structure and non‑linear selection instead of linear superposition. The paper correctly notes this as the reason Transformers shine on associative‑recall tasks.

How collisions / interference and gates $(f_t, i_t)$ change the practical capacity. Collisions are just large dot products between different keys: they increase the noise term above and so lower $\mathrm{SNR}$. You can fight collisions in three practical ways that the paper’s mLSTM implements or suggests:

- Make keys more orthogonal or higher‑dimensional (larger $d$): this directly reduces typical cross inner products $\sim 1/\sqrt{d}$ and raises $\mathrm{SNR}$.
- Control write strength (input gate $i_t$) and decay (forget $f_t$): $i_t$ scales the contribution of a new outer product, $f_t$ decays older terms. Smaller or sparse $i_t$ reduces the number of effective writes $N_{\mathrm{eff}}$; lower $f_t$ reduces long‑term accumulation. Both reduce interference but trade off retention. The paper’s exponential gating gives a much larger dynamic range for these weights, so the model can learn a heavy‑tailed write distribution (few strong writes, many near‑zero writes), which helps effective capacity.
- Use normalization / stabilizers (the paper’s $\mathbf{n}_t$ and the denominator $\max\{|\mathbf{n}_t^\top q|,1\}$ and the stabilizer $m_t$). Normalization prevents runaway amplitudes and keeps readout scale well‑conditioned; it doesn’t remove cross‑talk but helps numerical stability and lets the network use larger dynamic ranges safely.

The paper’s experiments on the Multi‑Query Associative Recall task illustrate these points: mLSTM (within xLSTM) improves over scalar LSTM because the matrix memory and exponential gating increase representational power and enable selective writes; xLSTM[1:1] was the best non‑Transformer model and even extrapolated to longer contexts (Section 3.1, experiments). Still, Transformers remained the best on pure associative recall, consistent with the theoretical advantage that non‑linear attention can exploit structured codes and explicit storage.

Practical takeaway. If you want a compact, linear, parallelizable recurrent memory (mLSTM): budget on the order of $d$ reliably retrievable random associations (use the $\mathrm{SNR}$ formula to pick $d$ for your target $N$ and $\mathrm{SNR}$). To push effective capacity without increasing $d$, either make writes sparse/selective via learned gates (exponential gates help), partition memory into heads/cells with different roles, or design keys to reduce collisions. If you need extreme associative recall (very large $N$ or combinatorial codebooks), attention/transformer‑style uncompressed storage is the safer choice, which is exactly what the paper’s experiments show.

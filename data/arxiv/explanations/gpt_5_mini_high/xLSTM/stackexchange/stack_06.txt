\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### Are i_t and f_t in mLSTM scalars or vectors, and why this choice?
Question:
The mLSTM equations suggest scalar input and forget gates ($i_t$ and $f_t$), while the output gate $o_t$ is a vector. Is that correct? If so:
- What motivated using scalar $i_t$ and $f_t$ rather than per-dimension gates (e.g., vectors or even diagonal matrices)?
- Would vector gates improve capacity or stability, or would they create optimization/parallelization issues?
- Did you explore a per-head or per-subspace gating variant where different parts of $C_t$ evolve with different $f_t$ values?
Answer:
Short answer: In the paper’s mLSTM as written, both the input gate $i_t$ and the forget gate $f_t$ are scalars, while the output gate $\mathbf{o}_t$ is a vector. You can see this directly in the mLSTM forward equations (Section 2.3): the memory update is
$\mathbf{C}_t = f_t\,\mathbf{C}_{t-1} + i_t\,\mathbf{v}_t\mathbf{k}_t^\top$,
and the gates are defined as scalar-valued functions
$i_t=\exp(\tilde i_t)$, $\tilde i_t=\mathbf w_i^\top\mathbf x_t+b_i$,
and $f_t=\sigma(\tilde f_t)$ or $\exp(\tilde f_t)$, whereas
$\mathbf{o}_t=\sigma(\tilde{\mathbf o}_t)$ with $\tilde{\mathbf o}_t=\mathbf W_{\mathbf o}\mathbf x_t+\mathbf b_{\mathbf o}$,
and the hidden state is $\mathbf h_t=\mathbf o_t\odot\tilde{\mathbf h}_t$. That notation and the surrounding text make clear $i_t,f_t\in\mathbb R$ while $\mathbf o_t\in\mathbb R^d$.

Why scalars for $i_t,f_t$?
The paper motivates the matrix memory with a covariance / fast‑weights style update: adding a rank‑one outer product $\mathbf v_t\mathbf k_t^\top$ and applying a single decay (forget) multiplier to the whole matrix is exactly the classic fast‑weights / covariance update view (Section 2.3). Interpreting $f_t$ as a global decay rate and $i_t$ as a global learning rate for the new outer product is natural and compact: a single scalar controls how much of the old matrix survives and how strongly the new rank‑one term is written. This keeps the update interpretable, keeps parameter count low (only a couple of small input projections to produce the scalars), and keeps the implementation and numerical-stabilization logic straightforward (the same stabilizer technique used for scalar exponential gates is applied).

Would vector (per‑dimension) gates help?
In principle, yes: per‑dimension or per‑subspace gates increase representational flexibility — they let different rows/columns (or subspaces) of $\mathbf C_t$ evolve on different timescales or with different learning rates, which can help if the stored facts naturally split into components that need different retention dynamics. However, this is a trade‑off. Vector gates add degrees of freedom (and thus parameters) and require corresponding changes to normalization/stabilization (the paper’s stabilizer $m_t$ would have to be vectorized or otherwise adapted for per‑dim exponential gates). Practically, the dominant compute cost in mLSTM is already the $d\times d$ matrix update and retrieval; adding an $O(d)$ gate vector is not asymptotically worse, but it does increase parameter/gradient noise and tuning complexity. The paper reports ablations on gating mechanisms and finds that making gates learnable and input‑dependent helps, but it does not report experiments that replace the scalar $i_t,f_t$ by full per‑dimension gates in the mLSTM equations.

Parallelization / optimization issues
There is no fundamental barrier to computing vector gates in parallel on modern hardware (elementwise gating is trivially parallel), and the mLSTM is designed to be parallelizable. The practical issues are (a) more parameters and potentially noisier gradients, (b) extra numerical-stability bookkeeping when using exponential activations per dimension, and (c) the need to adapt the normalization logic (the paper normalizes retrieval by $\max\{|\mathbf n_t^\top \mathbf q_t|,1\}$ where $\mathbf n_t$ is a scalar‑weighted sum of keys; per‑dimension gates change $\mathbf n_t$’s structure and may require a different normalization). So vector gating is implementable and parallelizable, but it complicates training and stabilization.

Per‑head / per‑subspace gating
The paper explicitly notes that mLSTM “can have multiple memory cells” and that for mLSTM “multiple heads and multiple cells are equivalent as there is no memory mixing” (Section 2.3). That means a practical way to get differentiated dynamics across subspaces is to split the memory into several smaller matrix memories (heads) and give each head its own scalar $i_t^{(h)},f_t^{(h)}$. This yields per‑subspace behavior while preserving the simpler scalar gating inside each head. The paper does not report a dedicated ablation that replaces the single global $i_t,f_t$ by per‑head or per‑dimension gates inside a single monolithic $\mathbf C_t$; their experiments use combinations of mLSTM and sLSTM blocks and ablate gating styles, but they don’t publish a direct scalar-vs-vector‑gate comparison for mLSTM.

Practical suggestion if you want to experiment
If you want more flexible forgetting/learning dynamics, try (a) multi‑head mLSTM where each head has its own scalar $i_t^{(h)},f_t^{(h)}$ (minimal extra parameters, keeps stabilization simple), or (b) a diagonal (per‑row or per‑column) gate implemented by multiplying $\mathbf C_{t-1}$ by $\operatorname{diag}(\mathbf f_t)$ (this increases gating granularity but requires adapting normalizer and stabilization). Full dense per‑entry gating would be prohibitively expensive. When using exponential activations for gating, remember to adopt per‑dimension stabilization (vectorized versions of the paper’s $m_t$ trick) to avoid numerical overflow.

Summary
The paper’s mLSTM uses scalar $i_t,f_t$ (global learning/decay rates) for interpretability and simplicity in the fast‑weights / covariance update formulation, while keeping $\mathbf o_t$ vector valued to allow per‑coordinate output modulation. Per‑dimension or per‑head gates are conceptually feasible and may increase capacity, and per‑head scalar gates can be implemented by using multiple matrix heads (which the paper says is equivalent to multiple cells), but the paper does not report experiments that directly compare scalar vs. vector gates inside a single monolithic mLSTM memory.

\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### What is the formal equivalence between multiple heads and multiple cells in mLSTM?
Question:
The paper states that "for mLSTM, multiple heads and multiple cells are equivalent as there is no memory mixing." Could you formalize this equivalence?
- If I instantiate $H$ independent mLSTM "heads" each with its own $C_t^{(h)}$, $q_t^{(h)}$, $k_t^{(h)}$, $v_t^{(h)}$, and $n_t^{(h)}$, and then concatenate the outputs, is this exactly the same function class as using a single larger block-diagonal memory $C_t$ with no cross-block mixing?
- Are there any subtle differences due to shared input projections or normalization across heads versus a single larger memory?
Answer:
Short answer: yes—provided you do not introduce any cross-head coupling in the parameters or the normalization/gating, H independent mLSTM heads (each with its own $\mathbf{C}^{(h)}_t,\mathbf{q}^{(h)}_t,\mathbf{k}^{(h)}_t,\mathbf{v}^{(h)}_t,\mathbf{n}^{(h)}_t$) are exactly equivalent to a single mLSTM whose memory is a block–diagonal matrix with those same blocks. The equivalence is just the statement that “no memory mixing” = “independent block dynamics”, so stacking independent blocks is the same as independent heads. Below I state that formally and then point out the small but important caveats (shared projections, global vs per-head gates/normalizers, and numerical/implementation issues).

Formalization. Let head $h\in\{1,\dots,H\}$ have dimension $d_h$. For each head the mLSTM recurrence (written in the paper, but here per-head) is
$$
\begin{aligned}
\mathbf{C}_t^{(h)} &= f_t^{(h)} \mathbf{C}_{t-1}^{(h)} + i_t^{(h)}\,\mathbf{v}_t^{(h)}\mathbf{k}_t^{(h)\top},\\
\mathbf{n}_t^{(h)} &= f_t^{(h)} \mathbf{n}_{t-1}^{(h)} + i_t^{(h)}\,\mathbf{k}_t^{(h)},\\
\tilde{\mathbf{h}}_t^{(h)} &= \mathbf{C}_t^{(h)} \mathbf{q}_t^{(h)} \,/\,\mathrm{denom}^{(h)}_t,\qquad
\mathbf{h}_t^{(h)} = \mathbf{o}_t^{(h)}\odot\tilde{\mathbf{h}}_t^{(h)},
\end{aligned}
$$
with the usual choices $\mathrm{denom}^{(h)}_t=\max\{|{\mathbf{n}_t^{(h)}}^\top\mathbf{q}_t^{(h)}|,1\}$ (the paper uses that absolute lower-bounded form). Concatenating the heads gives the full output $\mathbf{h}_t=\mathrm{concat}_h(\mathbf{h}_t^{(h)})$.

Now set $D=\sum_h d_h$ and let $E_h\in\mathbb{R}^{D\times d_h}$ be the standard block selector (so $E_h^\top E_h=I_{d_h}$ and $E_i^\top E_j=0$ for $i\neq j$). Define the block–diagonal memory
$$
\mathbf{C}_t \;=\; \sum_{h=1}^H E_h \mathbf{C}_t^{(h)} E_h^\top \;=\; \operatorname{blockdiag}(\mathbf{C}_t^{(1)},\dots,\mathbf{C}_t^{(H)}),
$$
and concatenate the per-head vectors into big vectors $\mathbf{q}_t=\sum_h E_h\mathbf{q}_t^{(h)}$, $\mathbf{k}_t=\sum_h E_h\mathbf{k}_t^{(h)}$, $\mathbf{v}_t=\sum_h E_h\mathbf{v}_t^{(h)}$, $\mathbf{n}_t=\sum_h E_h\mathbf{n}_t^{(h)}$, and similarly for $\mathbf{o}_t$. Define block-diagonal scalar scalings $S^{(f)}_t=\operatorname{blockdiag}(f_t^{(1)}I_{d_1},\dots,f_t^{(H)}I_{d_H})$ and $S^{(i)}_t=\operatorname{blockdiag}(i_t^{(1)}I_{d_1},\dots,i_t^{(H)}I_{d_H})$. Then the big recurrence can be written exactly as
$$
\mathbf{C}_t \;=\; S^{(f)}_t \mathbf{C}_{t-1} + S^{(i)}_t \,\mathbf{v}_t\mathbf{k}_t^\top,
$$
and retrieval is componentwise blockwise:
$$
\mathbf{C}_t\mathbf{q}_t \;=\; \sum_{h} E_h\bigl(\mathbf{C}_t^{(h)}\mathbf{q}_t^{(h)}\bigr),
$$
so dividing by the per-head denominators and applying $\mathbf{o}_t$ reproduces the concatenated $\mathbf{h}_t$. Thus any H-head architecture with independent head parameters is realized by a single mLSTM with $\mathbf{C}_t$ block–diagonal and with the large projection matrices built from the per-head projection matrices (e.g. $W_q=\text{row–stack}(W_q^{(1)},\dots,W_q^{(H)})$, etc.). Conversely any block–diagonal single mLSTM decomposes into independent heads by extracting the blocks.

Intuition: because the update is an outer–product ($\mathbf{v}\mathbf{k}^\top$) plus a diagonal-like decay, and there are no recurrent hidden-to-hidden mixes that couple different memory subspaces, disjoint blocks evolve independently and retrieval is independent; concatenation just collects the independent results.

Important caveats (when equivalence breaks):
1. Global vs per-head gates/normalizers. The equivalence requires that the gates and normalizers act independently per block (i.e. you must be able to choose distinct $i_t^{(h)},f_t^{(h)}$ and use per-head denominators). If the model forces a single scalar input/forget gate $i_t,f_t$ applied uniformly to the whole memory, or computes the denominator as the single scalar $|\mathbf{n}_t^\top\mathbf{q}_t|$ summing contributions across blocks, then different heads are coupled and the multi-head independent parameterization is strictly more expressive than the constrained single-memory parameterization. (The paper’s equations present scalar gates in the compact form; the multiple-cells / multiple-heads variant assumes you allow per-cell / per-head gating or block-diagonal gating matrices.)

2. Shared input projections or post-concat normalization. If the heads share the same projection matrix (i.e. the same $W_k,W_q,W_v$ used for all heads) or if you apply a normalization operation after concatenation that mixes head components (for example a LayerNorm over the concatenated $\mathbf{q}_t$ that has cross-head statistics), then the H independent-head parameterization is more constrained than the fully free block–structured single mLSTM. Conversely, if you start from H independent heads you can always assemble a single big model whose projection matrices are simply the stacked per-head matrices; so the one-to-one mapping holds only when the single model is allowed the same block-structured freedom.

3. Implementation/finite-precision and training effects. Floating-point order of ops, tieing of biases, initialization, or regularizers can make the trained networks differ even when they are representationally equivalent. But these are practical/engineering differences, not mathematical ones.

Bottom line: mathematically, “multiple heads = multiple cells” for mLSTM is exact if you interpret both architectures as having the same lack of cross-block coupling (i.e. per-head gates/normalizers and block-separable projection parameters). If you impose parameter tying (shared projections, single global gate, or a global normalizer) you introduce coupling and the two architectures are no longer equivalent.

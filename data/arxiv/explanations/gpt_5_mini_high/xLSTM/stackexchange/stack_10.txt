\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### How exactly is mLSTM parallelized? What is the scan formulation?
Question:
The paper says the mLSTM recurrence can be reformulated in a parallel version, similar to FlashAttention/GLA. Could you spell out the precise scan formulation?
- Given $C_t = f_t C_{t-1} + i_t v_t k_t^T$ and $n_t = f_t n_{t-1} + i_t k_t$, what are the associative operators that allow chunked prefix computations?
- How are the stabilizer terms (if using exponential gates) handled across chunk boundaries so that numerical rescaling remains consistent?
- A small pseudo-code example of computing all $h_t$ for a block of length $L$ in $O(\log L)$ reductions would be very helpful.
Answer:
Short answer: mLSTM is an affine linear recurrence with a scalar multiplicative decay and an additive rank-1 update, so it admits a standard prefix‑scan / parallel-scan formulation. The trick is to carry, per element (or per chunk), a small associative summary (a log-decay, a log‑stabilizer, and scaled accumulators). Those summaries compose with a simple associative binary operator; the per-chunk “max” values are exactly the stabilizers from the paper, and composition rescales the chunk accumulators so numerical stabilization stays consistent across chunk boundaries.

Why this works (formula): with
$$
\mathbf{C}_t = f_t\,\mathbf{C}_{t-1} + i_t\,\mathbf{v}_t\mathbf{k}_t^\top,\qquad
\mathbf{n}_t = f_t\,\mathbf{n}_{t-1} + i_t\,\mathbf{k}_t
$$
one can unroll (assume $\mathbf{C}_0=\mathbf{n}_0=\mathbf{0}$ for simplicity):
$$
\mathbf{C}_t \;=\; \sum_{s=1}^t \Big(\prod_{j=s+1}^{t} f_j\Big)\, i_s\,\mathbf{v}_s\mathbf{k}_s^\top,\qquad
\mathbf{n}_t \;=\; \sum_{s=1}^t \Big(\prod_{j=s+1}^{t} f_j\Big)\, i_s\,\mathbf{k}_s .
$$
Introduce the log-quantities $g_t=\log f_t,\; a_t=\log i_t$. For each term $s$ in a block ending at index $u$ define the log-weight
$$
T_s^{(u)} = a_s + \sum_{j=s+1}^{u} g_j.
$$
A numerically stable representation factors out the block maximum
$$
M_{p:u} = \max_{s\in[p,u]} T_s^{(u)},
$$
and stores scaled accumulators
$$
\widetilde{\mathbf{n}}_{p:u} = \sum_{s=p}^{u} \exp\big(T_s^{(u)}-M_{p:u}\big)\,\mathbf{k}_s,\qquad
\widetilde{\mathbf{C}}_{p:u} = \sum_{s=p}^{u} \exp\big(T_s^{(u)}-M_{p:u}\big)\,\mathbf{v}_s\mathbf{k}_s^\top .
$$
The true $\mathbf{n}$ and $\mathbf{C}$ for that prefix are $\mathbf{n}=\exp(M)\,\widetilde{\mathbf{n}}$ and $\mathbf{C}=\exp(M)\,\widetilde{\mathbf{C}}$.

Associative operator (block composition). If A is an earlier block and B a later block, define a block-summary
$$
\text{op}=(G,M,\widetilde{\mathbf{n}},\widetilde{\mathbf{C}})
$$
with $G=\sum g_t$ over the block, $M$ the block max as above, and the two scaled accumulators. The binary compose (A followed by B) is
$$
\begin{aligned}
G_{AB} &= G_A + G_B,\\[4pt]
M_{AB} &= \max\big(M_B,\; M_A + G_B\big),\\[4pt]
\alpha_A &= \exp\big(M_A + G_B - M_{AB}\big),\qquad
\alpha_B = \exp\big(M_B - M_{AB}\big),\\[4pt]
\widetilde{\mathbf{n}}_{AB} &= \alpha_A\,\widetilde{\mathbf{n}}_A \;+\; \alpha_B\,\widetilde{\mathbf{n}}_B,\\[4pt]
\widetilde{\mathbf{C}}_{AB} &= \alpha_A\,\widetilde{\mathbf{C}}_A \;+\; \alpha_B\,\widetilde{\mathbf{C}}_B .
\end{aligned}
$$
This operator is associative (it is just the algebra of shifting and adding the log‑weighted contributions), so you can parallel-scan it in $O(\log L)$ rounds on $L$ elements/chunks.

Relation to the paper’s stabilizer. The per-step stabilizer recurrence in the paper
$$
m_t = \max\big(\log f_t + m_{t-1},\; \log i_t\big)
$$
is exactly the same object as the block $M$ above when the block is a single time step, and the block-composition rule
$$
M_{AB}=\max(M_B,\; M_A+G_B)
$$
is the chunk-level analogue of running that same recurrence across a block boundary. Thus the per-chunk $M$ values are the stabilizers and composition enforces consistent rescaling across chunks.

Numerically stable evaluation of $\tilde{\mathbf{h}}_t$. After a parallel prefix you obtain for each prefix index $t$ the tuple $(G_t,M_t,\widetilde{\mathbf{n}}_t,\widetilde{\mathbf{C}}_t)$. Let $\mathbf{q}_t$ and $\mathbf{o}_t$ be the query and output gate at time $t$. Compute
$$
s_t = \widetilde{\mathbf{n}}_t^\top \mathbf{q}_t,\qquad
u_t = \widetilde{\mathbf{C}}_t\,\mathbf{q}_t.
$$
Recall $\mathbf{n}_t^\top\mathbf{q}_t=\exp(M_t) s_t$ and $\mathbf{C}_t\mathbf{q}_t=\exp(M_t) u_t$. The mLSTM output uses
$$
\tilde{\mathbf{h}}_t = \frac{\mathbf{C}_t\mathbf{q}_t}{\max\{|\mathbf{n}_t^\top\mathbf{q}_t|,1\}}.
$$
Compute this stably without forming huge/small exponentials by branching on the log condition:
if $M_t + \log(|s_t|+\varepsilon) \ge 0$ (i.e. $\exp(M_t)|s_t|\ge 1$) then
$$
\tilde{\mathbf{h}}_t = \frac{u_t}{|s_t|+\varepsilon},
$$
else
$$
\tilde{\mathbf{h}}_t = \exp(M_t)\,u_t.
$$
Finally $\mathbf{h}_t = \mathbf{o}_t \odot \tilde{\mathbf{h}}_t$. Use a tiny $\varepsilon$ to avoid division by zero; the branch avoids computing $\exp(M_t)$ in the large‑M case because the factor cancels there.

Compact pseudo-code (conceptual, leaves parallel-scan primitive implicit)
```
# Inputs for t=1..L: f[t], i[t], k[t], v[t], q[t], o[t]
g[t] = log(f[t]); a[t] = log(i[t])

# element summaries (in parallel)
op[t].G = g[t]
op[t].M = a[t]
op[t].n_tilde = k[t]                   # vector in R^d
op[t].C_tilde = outer(v[t], k[t])      # d x d matrix (or explicit MV form)

# run an associative parallel prefix using 'combine' defined below:
prefix_ops[1..L] = parallel_scan(op[1..L], combine)

# combine(left,right) implements the formulas in text:
#   G = G_left + G_right
#   M = max(M_right, M_left + G_right)
#   alpha_left = exp(M_left + G_right - M)
#   alpha_right = exp(M_right - M)
#   n_tilde = alpha_left * n_tilde_left + alpha_right * n_tilde_right
#   C_tilde = alpha_left * C_tilde_left + alpha_right * C_tilde_right

# final per-time compute (in parallel)
for t in 1..L:
    M = prefix_ops[t].M
    n_tilde = prefix_ops[t].n_tilde
    C_tilde = prefix_ops[t].C_tilde
    s = dot(n_tilde, q[t])
    u = matmul(C_tilde, q[t])          # vector in R^d
    if M + log(abs(s)+eps) >= 0:
        h_tilde = u / (abs(s)+eps)
    else:
        h_tilde = exp(M) * u
    h[t] = o[t] * h_tilde
```
Complexity and implementation notes: the scan uses the associative combine and therefore can be implemented in $O(\log L)$ parallel rounds (Blelloch or tree-scan); each combine involves scalar exp/logs and additions plus one vector (length $d$) and one matrix ($d\times d$) linear combination. Storing the full $\widetilde{\mathbf{C}}$ as a dense $d\times d$ per partial prefix is straightforward and matches the mLSTM design in the paper (the heavy $d\times d$ cost is what the authors mention). If you want to avoid storing $d\times d$ matrices you can instead keep the sum-of-outer-products form and only materialize $\mathbf{C}\mathbf{q}$ (i.e. accumulate $\sum \alpha_s \mathbf{v}_s ( \mathbf{k}_s^\top \mathbf{q})$); that trades memory for additional reductions but the same associative composition pattern still applies.

Summary (intuitive): think of each time step as producing a little affine operator "multiply previous state by product-of-f's and add these weighted outer-products". Those affine operators compose and you can compute any prefix by associatively combining the compact summaries (log‑scale, scaled accumulators). The per-block max $M$ is precisely the stabilizer from the paper, and combining with the formula above keeps the numerics identical to the sequential stabilized recurrence while permitting $O(\log L)$ parallel reductions.

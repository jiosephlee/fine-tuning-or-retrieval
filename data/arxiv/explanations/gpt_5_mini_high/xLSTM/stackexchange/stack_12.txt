\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### Why is memory mixing necessary for state tracking, and how does sLSTM implement it?
Question:
The paper argues that models without memory mixing (e.g., pure SSMs or Transformers without certain recurrent structure) cannot solve state-tracking problems like parity, whereas sLSTM can.
- Could you give an intuitive explanation for why mixing hidden states over time (via recurrent hidden-to-hidden connections) is required to maintain and update a finite-state machine?
- For sLSTM with multiple cells and heads, what specific recurrent matrices (e.g., $R_z$, $R_i$, $R_f$, $R_o$) are responsible for this capability, and how do exponential gates influence the effective state transitions?
- A tiny worked example (e.g., implementing parity) would clarify this point.
Answer:
Short answer: you need memory mixing because a finite-state machine (FSM) updates its next state by a function of both the previous internal state and the new input. In sLSTM that “both” is realized by feeding the previous hidden vector back into the pre-activations for the cell inputs and for the gates (those are the recurrent matrices). Exponential gates then give you high dynamic range multiplicative control (near on/off writes and strong forgetting) so the model can implement sharp, state-dependent transitions. Below I first make this intuition precise with the sLSTM equations the paper uses, then I point to which recurrent matrices do the work, and finally I give a tiny worked parity implementation that shows the mechanism in action.

How memory mixing implements FSM updates (intuitively + formally)
The defining property of an FSM is that the next internal state $s_{t}$ is some function of the previous state $s_{t-1}$ and the current input $x_{t}$: 
$s_t = \mathcal{F}(s_{t-1},x_t)$. To realize such a conditional update in a neural sequence model you must give the network a direct way to make the new content and the gates depend on the previous internal summary. In sLSTM the vectorized forward pass from the paper is (writing vectors for multiple cells):

$$
\begin{aligned}
\mathbf{c}_t &= \mathbf{f}_t \odot \mathbf{c}_{t-1} \;+\; \mathbf{i}_t \odot \mathbf{z}_t,\\
\mathbf{n}_t &= \mathbf{f}_t \odot \mathbf{n}_{t-1} \;+\; \mathbf{i}_t,\\
\mathbf{h}_t &= \mathbf{o}_t \odot \bigl(\mathbf{c}_t / \mathbf{n}_t\bigr),
\end{aligned}
$$

with the candidate and gates computed as

$$
\begin{aligned}
\tilde{\mathbf{z}}_t &= \mathbf{W}_z^\top \mathbf{x}_t \;+\; \mathbf{R}_z \mathbf{h}_{t-1} \;+\; \mathbf{b}_z,\quad
\mathbf{z}_t=\varphi(\tilde{\mathbf{z}}_t),\\
\tilde{\mathbf{i}}_t &= \mathbf{W}_i^\top \mathbf{x}_t \;+\; \mathbf{R}_i \mathbf{h}_{t-1} \;+\; \mathbf{b}_i,\quad
\mathbf{i}_t=\exp(\tilde{\mathbf{i}}_t),\\
\tilde{\mathbf{f}}_t &= \mathbf{W}_f^\top \mathbf{x}_t \;+\; \mathbf{R}_f \mathbf{h}_{t-1} \;+\; \mathbf{b}_f,\quad
\mathbf{f}_t=\sigma(\tilde{\mathbf{f}}_t)\ \text{or}\ \exp(\tilde{\mathbf{f}}_t),\\
\tilde{\mathbf{o}}_t &= \mathbf{W}_o^\top \mathbf{x}_t \;+\; \mathbf{R}_o \mathbf{h}_{t-1} \;+\; \mathbf{b}_o,\quad
\mathbf{o}_t=\sigma(\tilde{\mathbf{o}}_t).
\end{aligned}
$$

If the recurrent matrices $\mathbf{R}_\cdot$ are zero, then $\mathbf{z}_t,\mathbf{i}_t,\mathbf{f}_t,\mathbf{o}_t$ depend only on the current input $\mathbf{x}_t$ (and biases). That makes the cell update a fixed input-conditioned accumulator: every write and forget is determined by $\mathbf{x}_t$ alone, so the network cannot implement arbitrary conditional transitions that need to route or reinterpret the *previous* state. By contrast, nonzero $\mathbf{R}_z,\mathbf{R}_i,\mathbf{R}_f,\mathbf{R}_o$ feed the previous hidden vector $\mathbf{h}_{t-1}$ back into candidate and gate pre-activations, so the new content and the gates become direct functions of $(\mathbf{h}_{t-1},\mathbf{x}_t)$ — exactly what an FSM transition needs.

Which recurrent matrices do what (roles of $\mathbf{R}_z,\mathbf{R}_i,\mathbf{R}_f,\mathbf{R}_o$)
All four recurrent matrices are the levers of memory mixing:

- $\mathbf{R}_z$ mixes the previous hidden into the cell *candidate* $\mathbf{z}_t$. With $\mathbf{R}_z\neq 0$ you can produce a new candidate value that is an arbitrary linear mixing (and then nonlinear transform) of components of $\mathbf{h}_{t-1}$. In practice $\mathbf{R}_z$ is often used to route or permute information among cells (e.g. implement a swap or permutation), so the new write can be a transformed version of the previous memory.

- $\mathbf{R}_i$ lets the input gate $\mathbf{i}_t$ depend on the previous state. This is crucial if you want the network to make write decisions that depend on where you are in the FSM (e.g. “if I’m in state A and I see symbol $x$, then write into cell 3; otherwise ignore”).

- $\mathbf{R}_f$ lets the forget gate $\mathbf{f}_t$ depend on the previous state. This enables state-conditioned retention or erasure: depending on $\mathbf{h}_{t-1}$ you can choose to keep (or decay) parts of memory.

- $\mathbf{R}_o$ lets the output gate depend on $\mathbf{h}_{t-1}$; that changes what the network exposes as the readable hidden state, which in turn changes future recurrent pre-activations.

Put together, these matrices make the step $\mathbf{h}_t = \mathcal{G}(\mathbf{h}_{t-1},\mathbf{x}_t)$ expressive enough to implement arbitrary finite-state transitions (up to usual function approximation considerations). The paper emphasizes exactly this point: memory mixing (hidden→hidden) is what gives LSTM-like RNNs the extra expressivity for state-tracking tasks that pure SSMs or vanilla Transformer blocks (without such recurrent mixing) lack.

Why exponential gates matter
The paper replaces some sigmoid gates by exponential gates (e.g. $\mathbf{i}_t=\exp(\tilde{\mathbf{i}}_t)$). Exponentials are positive and have unbounded range, which gives two practical advantages for FSM-style transitions:

1. High dynamic range: $\exp$ can make a gate arbitrarily small or large (in floating-point practice stabilized via the $m_t$ trick in the paper). That lets the model implement near–binary decisions (essential for crisp state switches): one write can be scaled to dominate the memory, or made negligibly small to ignore it.

2. Multiplicative composition over time: because the cell update is multiplicative in gates, products like $\prod f$ naturally appear in the contribution of an older write to the present. Exponentials allow the model to sharply attenuate or amplify contributions across time and, together with the normalizer $\mathbf{n}_t$ (which records the sum of gate strengths), keep retrieval stable.

These two properties are what the paper calls “exponential gating with normalization and stabilization,” and they directly support the ability to perform discrete-like, state-dependent updates and to revise earlier stored values.

A tiny worked parity example (constructive sketch)
We implement parity (toggle on $1$, keep on $0$) with a minimal sLSTM having two memory cells (so the FSM state is one-hot between “even” and “odd”).

Let the two-cell memory be $\mathbf{c}_t\in\mathbb{R}^2$, normalizer $\mathbf{n}_t\in\mathbb{R}^2$, and hidden $\mathbf{h}_t=\mathbf{c}_t/\mathbf{n}_t$ (assume $\mathbf{o}_t=\mathbf{1}$ to simplify). Define the $2\times 2$ swap matrix
$\;S=\begin{pmatrix}0&1\\[2pt]1&0\end{pmatrix}\,$.
Choose parameters as follows (this is a constructive idealization — in practice you would use large/small pre-activations and the stabilizer $m_t$ to get near-binary gates):

- Candidate mixing: set $\mathbf{R}_z = S$, $\mathbf{W}_z=\mathbf{0}$, $\mathbf{b}_z=\mathbf{0}$ and let $\varphi$ act approximately linear on the operated regime; then
  $\mathbf{z}_t \approx S\,\mathbf{h}_{t-1}$.

- Input / forget gates depend only on the current bit $b_t\in\{0,1\}$ (the one-hot encoding of input $0/1$). Choose them so that
  when $b_t=0$: $\mathbf{f}_t=\mathbf{1},\ \mathbf{i}_t=\mathbf{0}$ (no write, keep memory);
  when $b_t=1$: $\mathbf{f}_t=\mathbf{0},\ \mathbf{i}_t=\mathbf{1}$ (replace memory with candidate).

With those choices the sLSTM vector update reduces to the simple rule
$$
\mathbf{c}_t =
\begin{cases}
\mathbf{c}_{t-1}, & b_t=0,\\[4pt]
\mathbf{z}_t = S\,\mathbf{h}_{t-1}, & b_t=1.
\end{cases}
$$
If we initialize $\mathbf{c}_0=[1,0]^\top$ and $\mathbf{n}_0=\mathbf{1}$ so $\mathbf{h}_0=[1,0]^\top$ (even), then:

- seeing a $0$ keeps $\mathbf{c}$ the same (state unchanged),
- seeing a $1$ sets $\mathbf{c}_t = S \mathbf{h}_{t-1}$, i.e. it swaps the two coordinates, toggling between $[1,0]$ and $[0,1]$.

Thus parity (XOR of the sequence of bits) is implemented: each $1$ toggles the one-hot memory. The key ingredient that makes this construction possible is $\mathbf{R}_z=S$ (mixing the previous hidden into the new candidate) plus gates that select whether to apply that candidate or keep the old memory. If $\mathbf{R}_z$ were zero (no mixing into $\mathbf{z}_t$), the candidate could not depend on $\mathbf{h}_{t-1}$ and you could not implement the swap needed for toggling.

Remarks and ties to the paper
This toy shows the generic pattern: use a recurrent matrix to route/permute/transform previous hidden contents into what you will write next, and use gates (the paper’s exponential gates are especially good) to choose *when* and *how strongly* to apply that write. The paper emphasizes that sLSTM’s memory mixing (nonzero $\mathbf{R}_\cdot$) plus exponential gating gives the model precisely the ability to solve state-tracking problems (parity and similar formal-language tasks) where architectures without such hidden→hidden mixing (many SSMs, vanilla Transformer blocks without recurrent state updates) empirically fail on the same tasks.

In short: memory mixing = you can make the *new* candidate and the *gates* depend on the *previous* compressed state; exponential gates = high-dynamic-range multiplicative switches to realize near-discrete transitions; together in sLSTM they implement the FSM-style update needed for parity and other state-tracking problems.

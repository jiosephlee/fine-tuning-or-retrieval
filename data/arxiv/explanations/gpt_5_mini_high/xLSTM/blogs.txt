# xLSTM in Plain English: Can RNNs Make a Comeback?

Transformers have dominated large‑scale language modeling for several years, but the LSTM family—built on the constant‑error carousel and gating—was the original workhorse for sequence tasks. The paper "xLSTM: Extended Long Short‑Term Memory" asks a simple question: if we bring LSTMs up to date with modern modeling and scaling practices and fix their known weak points, how far can they go? The short answer from the authors: surprisingly far. xLSTM extends LSTMs with two targeted changes (exponential gating and richer memory structures), integrates those into residual blocks, and reports strong empirical results — linear‑time, constant‑memory inference and competitive or better perplexities vs. Transformers and State Space Models (SSMs) on large language modeling tasks.

Below I unpack the two core ideas and the practical consequences in accessible terms, with the minimal math needed to make the mechanisms clear.

## Why revisit LSTMs now?

LSTMs still shine in many sequence problems (and they were the kernel of early large language models), but they have three persistent limitations that helped usher in Transformers:

- Inability to reliably revise previous storage decisions. Once an LSTM has stored something in its scalar cell(s), it can be hard to replace that content cleanly when better information arrives later.
- Limited storage capacity. The classical LSTM cell compresses stored information into scalars (or small vectors), which hurts memorization of many distinct items (e.g., rare tokens or many associative key–value pairs).
- Poor parallelizability. Recurrent hidden–to–hidden mixing forces sequential updates that are harder to parallelize than attention or many SSM formulations.

xLSTM targets these points directly.

## A one‑line LSTM refresher

The LSTM's core idea is an additive memory update (the "constant error carousel") plus gates that control writing, forgetting and reading. In compact form:

- Memory update: $c_t = f_t\, c_{t-1} + i_t\, z_t$
- Output: $h_t = o_t\, \psi(c_t)$

Here $f_t,i_t,o_t$ are forget/input/output gates, $z_t$ is the candidate input, and $\psi$ is a squashing/normalization function (often $\tanh$). Sigmoid gates limit values to $(0,1)$, which is sometimes a practical constraint.

## Core idea 1 — exponential gating: let the model revise what it stored

xLSTM replaces some sigmoid gates with exponential gates and adds normalization/stabilization machinery so the network can safely use unbounded multiplicative updates. The most important consequences are:

- Exponential input gates give the model a flexible, effectively unbounded "learning rate" for new content; that makes it possible to strongly replace previously stored information when appropriate.
- A normalizer state keeps track of the aggregated gate strength so the readout stays well‑scaled.
- A small stabilization trick prevents numerical overflow while keeping gradients and outputs invariant.

The sLSTM (scalar variant) forward pass is written in the paper as:

- cell state: $c_t = f_t\, c_{t-1} + i_t\, z_t$
- normalizer: $n_t = f_t\, n_{t-1} + i_t$
- readout: $\tilde{h}_t = c_t / n_t$, and $h_t = o_t\, \tilde{h}_t$
- gates: $i_t = \exp(\tilde{i}_t)$ and $f_t = \sigma(\tilde{f}_t)$ or $f_t = \exp(\tilde{f}_t)$ (input/forget pre‑activations are affine functions of input and prior hidden state)

Because exponentials can grow large, the authors add a stabilizer state $m_t$ and normalized gates

- $m_t = \max\!\big(\log(f_t) + m_{t-1},\ \log(i_t)\big)$
- $i'_t = \exp(\log(i_t) - m_t) = \exp(\tilde{i}_t - m_t)$
- $f'_t = \exp(\log(f_t) + m_{t-1} - m_t)$

Replacing $i_t,f_t$ by $i'_t,f'_t$ does not change network outputs or gradients but keeps intermediate numbers in a safe range.

Intuition: exponential gating turns gate outputs into multiplicative scaling factors that are not confined to $(0,1)$. The normalizer $n_t$ records the total "mass" of what has been written (weighted by future forgets), and dividing by $n_t$ produces a stable, scale‑normalized readout. That combination allows the network to sharply revise stored content when needed — something vanilla LSTMs struggle with.

## Core idea 2 — matrix memory (mLSTM): increase capacity with associative storage

To address limited storage capacity, xLSTM introduces a matrix memory $\mathbf{C}_t \in \mathbb{R}^{d\times d}$ that accumulates outer products of values and keys (a covariance or fast‑weight style update). At a high level this stores key–value associations in a way that retrieval is a linear matrix multiply by a query vector.

The mLSTM update and readout (from the paper) are:

- matrix state: $\mathbf{C}_t = f_t\, \mathbf{C}_{t-1} + i_t\, \mathbf{v}_t \mathbf{k}_t^\top$
- normalizer: $\mathbf{n}_t = f_t\, \mathbf{n}_{t-1} + i_t\, \mathbf{k}_t$
- retrieval: $\tilde{\mathbf{h}}_t = \mathbf{C}_t \mathbf{q}_t \ /\ \max\{\,|\mathbf{n}_t^\top \mathbf{q}_t|,\ 1\,\}$
- output: $\mathbf{h}_t = \mathbf{o}_t \odot \tilde{\mathbf{h}}_t$

Here $\mathbf{k}_t$ and $\mathbf{v}_t$ are key and value vectors derived from the input, $\mathbf{q}_t$ is the query, $f_t$ and $i_t$ are forget/input gates (again $i_t$ can be exponential), and the denominator uses the dot product of the normalizer with the query to normalize retrieval strength (clamped to at least 1).

Why this helps: the covariance update $\mathbf{v}_t \mathbf{k}_t^\top$ is the classic associative memory / fast‑weight mechanism. The forget gate behaves like a decay on old associations and the input (exponential) gate behaves like a learn rate for new associations. Because the mLSTM drops hidden–to–hidden mixing across time (no recurrent mixing inside the matrix memory), its recurrence can be reformulated in a parallel, GPU‑friendly way — unlike sLSTM variants that use hidden mixing.

In short: mLSTM gives an LSTM‑style model a higher‑capacity, attention‑like memory that is independent of sequence length.

## sLSTM vs mLSTM — quick comparison

- sLSTM
  - Scalar memory cell with exponential gating, normalizer and stabilizer.
  - Supports memory mixing via recurrent hidden‑to‑hidden weights (so it can do state tracking).
  - Not parallelizable across time because of the hidden mixing, but the authors implemented a fast CUDA kernel.

- mLSTM
  - Matrix memory that stores key×value outer products (high capacity).
  - No memory mixing; recurrence can be reformulated to run in parallel (good for GPUs).
  - Higher computational cost per layer due to $d\times d$ matrix operations, but memory usage is constant in sequence length.

The xLSTM architecture mixes these building blocks inside residual blocks: mLSTM blocks are typically used with a pre up‑projection backbone (bigger internal dimensionality), while sLSTM blocks use a post up‑projection backbone. The paper denotes mixed stacks as xLSTM[$a$:$b$] meaning the ratio of mLSTM to sLSTM blocks (e.g., xLSTM[7:1]).

## Complexity and practical tradeoffs

- Sequence complexity: xLSTM networks are linear in sequence length and use constant model memory with respect to context length, unlike Transformers whose attention is quadratic in context length.
- Computation: mLSTM incurs $d\times d$ matrix updates per step (higher FLOPs), but these operations are parameter‑free and parallelizable on modern hardware. sLSTM uses hidden mixing which prevents full parallelization, but the authors report an efficient CUDA kernel that is typically less than 2× slower than their parallel mLSTM implementation.
- Engineering: the current mLSTM CUDA kernels are not yet as optimized as FlashAttention; the authors note room for implementation speedups.

## What the experiments show (high level)

The paper evaluates xLSTM across synthetic tasks, controlled memory tests, and large‑scale language modeling.

- Synthetic and formal tasks: exponential gating plus memory mixing lets sLSTM variants solve state‑tracking/formal grammar problems that Transformers and many SSMs (which lack memory mixing) cannot. This supports the claim that mixing + gating improves expressivity for certain algorithmic tasks.
- Associative recall: mLSTM's matrix memory substantially improves associative recall and memorization of many key–value pairs. In a multi‑query associative recall setup (up to 256 key–value pairs and contexts up to 2048) xLSTM[1:1] performed best among non‑Transformer models, and matrix memory helped extrapolate to longer contexts.
- Long Range Arena: xLSTM shows consistent strong performance across tasks designed to test long context handling.
- Language modeling at scale:
  - On 15B tokens of SlimPajama, xLSTM models (mixed mLSTM/sLSTM stacks) achieved lower validation perplexities than a set of baselines including Transformers (GPT‑3 style, Llama), SSMs (H3, Mamba), RNNs (RWKV variants), and several linear/efficient transformer variants.
  - Ablation studies attribute the gains to both exponential gating and the matrix memory.
  - On a larger 300B‑token training run, xLSTM models extrapolated to longer contexts better than the compared methods (tested up to length 16,384) and achieved strong validation perplexities and downstream task performance across multiple model sizes (125M up to 1.3B).
  - On the PALOMA benchmark (571 text domains), xLSTM[1:0] had lower perplexity than Mamba on 568/571 domains (99.5%), lower than Llama on 486/571 (85.1%), and lower than RWKV‑4 on 570/571 (99.8%).
- Inference speed and throughput: because xLSTM’s memory state is compressive and constant w.r.t. context length, generation time scales linearly with output length and xLSTM achieves higher decoding throughput (via larger batch sizes) than a Transformer like Llama, which faces quadratic memory growth in context length.

All empirical claims above are reported in the paper; precise curves and tables live in the figures and appendices of the original work.

## Limitations — what still needs work

The authors are careful to call out several important limitations and engineering needs:

- sLSTM’s memory mixing prevents full parallelization; despite a fast CUDA kernel, it is currently not as fast as a fully parallel model.
- mLSTM kernels are not yet as optimized as state‑of‑the‑art attention kernels; current implementations are about 4× slower than FlashAttention in the authors' experiments.
- The matrix memory in mLSTM incurs $d\times d$ computation, which is heavier than scalar updates.
- Forget‑gate initialization needs careful tuning.
- The matrix memory size is independent of sequence length; extremely long contexts could overload a fixed‑size matrix memory in principle, though experiments up to 16k contexts did not reveal practical problems.
- Large‑scale runs in the paper were expensive and the authors note they did not fully optimize architectures or hyperparameters for the largest xLSTM variants — there is likely additional upside with more engineering and tuning.

## Bottom line

xLSTM is a pragmatic modernization of LSTM ideas. By introducing exponential gating (with normalization and stabilization) and a matrix associative memory, and by integrating these components into modern residual stacks, the authors demonstrate that LSTM‑style recurrent models can be scaled and adapted to match or beat competitive Transformer and SSM baselines on language modeling benchmarks. Important tradeoffs remain (computation vs. memory, parallelizability), and there is engineering work to be done, but xLSTM shows that RNNs are not out of the running — with the right design choices they can still compete in the era of large LMs.

If you want to dive into the code or try xLSTM yourself, the authors have released their implementation: https://github.com/NX-AI/xlstm.



# Exponential Gates: How xLSTM Learns to Change Its Mind

Gates in recurrent models decide what to write into memory and what to keep. Classic LSTMs use sigmoid gates constrained to the interval $(0,1)$, which works well to protect gradients but limits how sharply a model can re‑assign importance to newly observed inputs. xLSTM introduces a simple but powerful change: exponential gating plus a matching normalization and a numerical stabilizer. Together these let the memory behave like a normalized, weighted accumulator whose weights can vary over many orders of magnitude — enabling the model to “change its mind” when stronger evidence appears later in the sequence.

Below I unpack how exponential gates work, why a normalizer is essential, and how the stabilizer keeps the math safe. I use a running “best‑match” (nearest neighbor) example to make the mechanism concrete.

## The limitation of classic LSTM gating (short version)

A vanilla LSTM cell updates a scalar memory with

$$
c_t = f_t\, c_{t-1} + i_t\, z_t,
\qquad
h_t = o_t\,\psi(c_t),
$$

where the gates $i_t,f_t,o_t$ are typically sigmoids (values in $(0,1)$) and $z_t$ is the incoming candidate. If we unroll the recurrence, each past input $z_s$ contributes to $c_t$ with an effective weight

$$
w_{s,t} = i_s \prod_{u=s+1}^{t} f_u.
$$

So the hidden output is effectively a weighted sum of past inputs. But because the standard input gate $i_t$ is bounded by 1, a single new input can only contribute at most the same scale as a single previous input; overpowering a large accumulated past requires simultaneously setting many forget gates to small values. In practice this makes it harder for an LSTM to sharply and reliably overwrite a previously stored “best” when a much better candidate appears later.

## Exponential gating: the main idea

xLSTM replaces the usual sigmoid input gate by an exponential activation:

$$
i_t = \exp(\tilde{i}_t),
\qquad
\tilde{i}_t = \mathbf{w}_i^\top \mathbf{x}_t + r_i h_{t-1} + b_i.
$$

(Optionally the forget gate can also be exponential, $f_t=\exp(\tilde{f}_t)$, or remain sigmoid.) The sLSTM (scalar memory) forward core then becomes

$$
\begin{aligned}
c_t &= f_t\, c_{t-1} + i_t\, z_t,\\
n_t &= f_t\, n_{t-1} + i_t,\\
\tilde{h}_t &= \frac{c_t}{n_t},\\
h_t &= o_t\,\tilde{h}_t.
\end{aligned}
$$

Two compact but crucial changes appear here:

- The memory numerator $c_t$ accumulates weighted inputs, as before.
- The new normalizer $n_t$ accumulates the same weights but without multiplying the $z_t$ values. The hidden output is the ratio $c_t / n_t$ — i.e., a normalized, weighted average of past $z$ values with weights $w_{s,t}=i_s\prod_{u=s+1}^t f_u$.

Because $i_t$ is an exponential, it can be arbitrarily large, so a single incoming input can produce a weight that dwarfs the entire previous weight mass and therefore dominate the normalized average. In other words, xLSTM can sharply reassign its memory to a late-arriving signal without having to simultaneously force many forget gates to near zero.

## The normalizer: turning sums into averages (and interpretability)

Unrolling the recurrences gives the explicit weighted‑average form. With $n_0=0$ and $c_0=0$ for simplicity,

$$
c_t = \sum_{s=1}^t \bigg(i_s \prod_{u=s+1}^t f_u\bigg) z_s,
\qquad
n_t = \sum_{s=1}^t \bigg(i_s \prod_{u=s+1}^t f_u\bigg).
$$

Therefore

$$
\tilde{h}_t = \frac{c_t}{n_t} = \frac{\sum_{s\le t} w_{s,t}\, z_s}{\sum_{s\le t} w_{s,t}},
\quad\text{with}\quad
w_{s,t} = i_s \prod_{u=s+1}^t f_u.
$$

This is exactly a normalized, interpretable summary: each stored $z_s$ contributes in proportion to its effective weight. The normalizer $n_t$ is the bookkeeping that lets us interpret $c_t$ as the (unnormalized) numerator and $\tilde{h}_t$ as the normalized output. Without normalization, large exponential gates could blow up the scale of $c_t$ and make the hidden representation unstable.

## Numerical stability: the stabilizer state

Exponentials are powerful but dangerous: $\exp(\tilde{i}_t)$ can overflow or produce extreme dynamic ranges. xLSTM solves this by maintaining a log‑scale stabilizer $m_t$ and using a local rescaling trick (essentially a sequential log‑sum‑exp stabilization). The stabilizer update is

$$
m_t = \max\big(\log(f_t) + m_{t-1},\ \log(i_t)\big).
$$

Then the gates are replaced by stabilized versions

$$
i'_t = \exp(\log(i_t) - m_t) = \exp(\tilde{i}_t - m_t),
\qquad
f'_t = \exp(\log(f_t) + m_{t-1} - m_t).
$$

The practical effect is that $i'_t$ and $f'_t$ are scaled into a numerically safe range (typically $\le 1$), while an internal bookkeeping via $m_t$ preserves the exact mathematical effect of the original (unstabilized) recurrence. The authors show that replacing $i_t,f_t$ by $i'_t,f'_t$ in the forward pass (and using the corresponding $m_t$ updates) does not change the network outputs or the derivatives with respect to parameters — it only prevents numerical overflow.

Intuitively this is the same stability trick you see in softmax implementations: do the math in the log domain, subtract a max, exponentiate, and you're safe.

## Intuition: a running “best match” (nearest neighbor) example

Consider a toy problem: scan a sequence of key–value pairs, and at the end return the value attached to the key that is most similar to a fixed reference. To solve this you want to keep only the “best match so far” and update it when a strictly better candidate arrives.

- With sigmoid gates, an arriving candidate can only inject weight up to 1. If past effective weight mass is already large (many earlier near‑matches, or forget gates close to 1), the new candidate’s bounded contribution may not outweigh the accumulated past; the stored aggregate will move only slowly and may fail to reflect the true best found late in the sequence.
- With exponential input gating, at any candidate you can (in principle) produce a very large $i_t=\exp(\tilde{i}_t)$. If you produce an $i_t$ several orders of magnitude larger than the past accumulated weight $n_{t-1}\prod$ terms, then

$$
\tilde{h}_t \approx z_t,
$$

so the model effectively overwrites the memory with the new candidate. The normalizer $n_t$ then contains the corresponding large weight so the representation remains numerically meaningful.

A concrete numeric intuition: suppose the accumulated previous weight is $W_{\text{old}}=100$ and a new candidate arrives. A sigmoid gate could at best contribute $i_t\le 1$, so it cannot overwhelm $W_{\text{old}}$. An exponential gate can set $i_t=\exp(5)\approx 148$ or $\exp(7)\approx 1096$, quickly exceeding $W_{\text{old}}$, so the new candidate becomes dominant after normalization.

This is exactly the behavior the paper observes in a Nearest‑Neighbor Search synthetic task: classic LSTM struggles to revise its stored choice when better matches arrive later, while xLSTM (with exponential gating and normalization) does not.

## How this idea extends to matrix memory (mLSTM)

The same gating + normalization motif is used in the matrix‑memory variant, mLSTM. There the cell state is a matrix $\mathbf{C}_t$ that accumulates outer products (covariance updates) and the normalizer $\mathbf{n}_t$ accumulates key vectors. Retrieval is normalized by the projected magnitude of the normalizer:

$$
\mathbf{C}_t = f_t\,\mathbf{C}_{t-1} + i_t\,\mathbf{v}_t\mathbf{k}_t^\top,
\qquad
\mathbf{n}_t = f_t\,\mathbf{n}_{t-1} + i_t\,\mathbf{k}_t,
$$

and the readout uses

$$
\tilde{\mathbf{h}}_t = \frac{\mathbf{C}_t \mathbf{q}_t}{\max\{|\mathbf{n}_t^\top\mathbf{q}_t|,\ 1\}},
\qquad
\mathbf{h}_t = \mathbf{o}_t \odot \tilde{\mathbf{h}}_t.
$$

Here the normalizer prevents division by vanishing scales and the $\max\{\cdot,1\}$ floor guards against extremely small denominators. Exponential gating allows the model to sharply reweight which key–value pairs dominate retrieval.

## Practical notes and caveats

- Numerical safety is essential. The stabilizer $m_t$ is not optional: it prevents overflow while preserving exact behavior (as shown in the paper’s appendix).
- The sLSTM variant (with scalar memory and recurrent mixing) is not fully parallelizable because it uses hidden‑to‑hidden mixing; the mLSTM formulation can be implemented in a parallel scan.
- Setting initial biases for forget/input gates matters in practice (the paper notes careful initialization is required).
- Exponential gating expands representational reach but must be used together with normalization; otherwise $c_t$ would grow without a stable semantic scale.

## Takeaway

Exponential gating turns gate activations from bounded, incremental modifiers into multiplicative weights that can span large dynamic ranges. The normalizer $n_t$ turns the memory into a normalized weighted summary, and the log‑domain stabilizer $m_t$ keeps the computation numerically safe. Together these three small changes give xLSTM an important capability: it can confidently and robustly overwrite previous memory when stronger evidence arrives later in a sequence — a capability standard LSTMs struggle with in practice. The paper demonstrates this both analytically and empirically (e.g., on a nearest‑neighbor synthetic task), and ablations attribute a substantial part of xLSTM’s improved language‑modeling performance to these gating and normalization changes.



# From Numbers to Matrices: Inside xLSTM’s mLSTM Memory

Long Short‑Term Memory (LSTM) cells historically store state as scalars (or vectors of scalars). That design is compact and gradient‑friendly, but it limits how much structured information a cell can hold. mLSTM — the matrix‑memory variant inside xLSTM — turns that scalar memory into a true key–value store: it writes outer products (value × keyᵀ) into a running $d\times d$ matrix and later retrieves a weighted combination of stored values with a single matrix–vector multiply. No explicit token–token attention matrix is built; instead the memory itself accumulates the information that attention would compute.

This post walks through how mLSTM writes, how it reads, what normalizes and stabilizes the mechanics, and why this design increases capacity for rare or long‑range information while allowing parallel computation.

## The core idea in one equation

At each time step the mLSTM cell updates a matrix memory $\mathbf{C}_t$ with a covariance (outer‑product) rule:

$\displaystyle \mathbf{C}_t \;=\; f_t \, \mathbf{C}_{t-1} \;+\; i_t \, \mathbf{v}_t \, \mathbf{k}_t^\top.$

Here $i_t$ is the input (learning) gate, $f_t$ is the forget (decay) gate, $\mathbf{k}_t$ is the key, and $\mathbf{v}_t$ is the value produced from the current input. Intuitively, the memory accumulates weighted outer products of past values with their keys; $f_t$ shrinks past content and $i_t$ controls how strongly the new pair is written.

## Writing: the covariance update as a running key–value store

mLSTM forms keys and values by projecting the input:

$\displaystyle \mathbf{q}_t = \mathbf{W}_q \mathbf{x}_t + \mathbf{b}_q,\quad
\mathbf{k}_t = \frac{1}{\sqrt{d}} \mathbf{W}_k \mathbf{x}_t + \mathbf{b}_k,\quad
\mathbf{v}_t = \mathbf{W}_v \mathbf{x}_t + \mathbf{b}_v.$

The $1/\sqrt{d}$ scaling on $\mathbf{k}_t$ keeps dot‑product magnitudes stable in higher dimensions (analogous to Transformer practice). A layer‑norm is applied before these projections in the full xLSTM design so keys are roughly zero mean; under that condition the covariance update is known to be effective at separating stored associations.

Expanding the recurrence (assume $\mathbf{C}_0=0$ for clarity) gives:

$\displaystyle \mathbf{C}_t \;=\; \sum_{\tau\le t} \Big(\prod_{s=\tau+1}^{t} f_s\Big)\, i_\tau\, \mathbf{v}_\tau \, \mathbf{k}_\tau^\top.$

Each stored pair contributes an outer product scaled by its write strength $i_\tau$ and by the product of all later forget gates. This is exactly the fast‑weight / covariance idea used in prior work, integrated here as an LSTM‑style gated memory.

The normalizer state runs in parallel:

$\displaystyle \mathbf{n}_t \;=\; f_t \, \mathbf{n}_{t-1} \;+\; i_t \, \mathbf{k}_t,$

so $\mathbf{n}_t$ records the aggregate key mass (weights applied to keys) and will be used for stable normalization at read time.

## Reading: query multiplication and attention‑like normalization

Retrieval is a single matrix–vector product followed by normalization:

$\displaystyle \tilde{\mathbf{h}}_t \;=\; \frac{\mathbf{C}_t \, \mathbf{q}_t}{\max\big\{\,|\mathbf{n}_t^\top \mathbf{q}_t|,\,1\big\}},\qquad
\mathbf{h}_t \;=\; \mathbf{o}_t \odot \tilde{\mathbf{h}}_t.$

Because $\mathbf{C}_t$ is a sum of outer products, multiplying by $\mathbf{q}_t$ yields

$\displaystyle \mathbf{C}_t \mathbf{q}_t \;=\; \sum_{\tau\le t} \Big(\prod_{s=\tau+1}^{t} f_s\Big)\, i_\tau\, \mathbf{v}_\tau \, (\mathbf{k}_\tau^\top \mathbf{q}_t).$

So the retrieved vector is a weighted sum of past values $\mathbf{v}_\tau$, where each contribution is modulated by the key–query similarity $\mathbf{k}_\tau^\top \mathbf{q}_t$ and by the same gate products that governed the write. The denominator $\mathbf{n}_t^\top \mathbf{q}_t$ is the analogous weighted sum of those similarities (without the $\mathbf{v}_\tau$ factors), so dividing yields a normalized, attention‑like weighted average of the values.

Two practical points from the paper are important: (1) the dot product in the denominator is wrapped in an absolute value and lower bounded by a threshold (typically $1$) to avoid tiny denominators, and (2) the final output is gated by an output gate $\mathbf{o}_t$ to control exposure.

Bottom line: mLSTM implements attention‑style retrieval without ever forming an explicit token‑by‑token attention matrix. Instead it maintains a compact $d\times d$ memory that accumulates inner‑token interactions incrementally.

## Gates and numerical stability

mLSTM uses exponential input gating to allow flexible write strengths:

$\displaystyle i_t \;=\; \exp(\tilde{i}_t),\qquad
\tilde{i}_t = \mathbf{w}_i^\top \mathbf{x}_t + b_i.$

The forget gate can be either sigmoid or exponential:

$\displaystyle f_t \;=\; \sigma(\tilde{f}_t)\ \text{or}\ \exp(\tilde{f}_t),\quad
\tilde{f}_t = \mathbf{w}_f^\top \mathbf{x}_t + b_f.$

Exponentials let the model scale writes multiplicatively over long horizons, but they risk numerical overflow. To avoid that, the architecture uses a stabilizer state $m_t$ (from the sLSTM design):

$\displaystyle m_t \;=\; \max\big(\log(f_t) + m_{t-1},\; \log(i_t)\big),$

and replaces $i_t,f_t$ by stabilized versions:

$\displaystyle i'_t \;=\; \exp\big(\log(i_t) - m_t\big),\qquad
f'_t \;=\; \exp\big(\log(f_t) + m_{t-1} - m_t\big).$

The paper shows substituting these stabilized gates does not change the network outputs or gradients, but it prevents overflow/underflow during implementation.

## Why this boosts capacity for rare and long‑range information

Scalar LSTM cells must compress history into a small number of scalar channels; rare events or many distinct associations can collide in that limited space. A matrix memory stores structured associations: each value lives in a vector space and is paired with a key, and retrieval selects values by key–query similarity. That expands effective capacity dramatically for associative tasks.

Empirically, the paper reports that xLSTM variants using mLSTM achieve strong results on associative recall benchmarks (multi‑query associative recall) and improve rare‑token prediction compared to scalar LSTM baselines. In those experiments mLSTM‑based blocks were among the best non‑Transformer methods for recalling many pairings and for extrapolating to longer contexts.

## Parallelism and practical trade‑offs

Because mLSTM drops the hidden‑to‑hidden recurrent mixing in its gate and projection equations (gates and key/value/query are computed from the input $\mathbf{x}_t$), the recurrence can be reformulated in a parallel scan‑friendly way. This removes the sequential dependency that normally forces token‑by‑token processing and makes mLSTM amenable to parallel GPU implementations — conceptually similar to how FlashAttention or other linearizable mechanisms are optimized.

That said, mLSTM has trade‑offs to consider:

- The matrix memory is $d\times d$ and each update is a $d\times d$ operation, so compute cost per token grows with $d^2$. The memory itself contains no learned parameters, but the arithmetic can be heavy.
- Because the memory is independent of sequence length, it stays constant in memory footprint as context grows (unlike a full attention matrix), but very long contexts can still saturate the representational capacity of a fixed $d\times d$ memory.
- The paper notes implementation status: current kernels are not yet as optimized as FlashAttention and can be slower in wall‑clock time, but the operations parallelize well and are expected to be accelerated with specialized kernels.

## How mLSTM fits in xLSTM models

In xLSTM architectures, mLSTM blocks are placed in a pre up‑projection residual block (i.e., the inputs are first projected to a higher dimension where the matrix memory lives), because memory capacity benefits from a higher coding dimension. Multiple heads and multiple matrix cells are equivalent for mLSTM (there is no cross‑cell memory mixing), so the design choices typically reduce to selecting $d$ and whether to combine mLSTM with a small number of sLSTM blocks that provide memory mixing when needed.

Code for the xLSTM family (including mLSTM) is available at the project repository: https://github.com/NX-AI/xlstm.

## Takeaways

mLSTM converts an LSTM cell into a compact, running key–value store by maintaining a $d\times d$ covariance matrix that accumulates outer products $\mathbf{v}\mathbf{k}^\top$. Reading is one matrix–vector multiply plus a stability‑aware normalization, yielding an attention‑like weighted average of past values without ever forming the full token‑by‑token attention matrix. That design increases effective storage capacity for associative and rare information, supports longer context extrapolation in practice, and — by avoiding hidden‑to‑hidden mixing — enables parallel implementations. The trade‑off is heavier per‑token $d^2$ computation, but this is a promising direction for scaling recurrent memory without the quadratic token–token cost of classic attention.



# Why Memory Mixing Matters: sLSTM and Real State Tracking

Stateful problems — parity, matching brackets, following entities across a long story, or even finding the nearest match in a streamed list — all require a model that can remember, update, and sometimes *revise* internal state as new inputs arrive. Many modern sequence models optimize for parallelism and global attention, but that often comes at the cost of true recurrent memory mixing. The sLSTM, introduced as part of the xLSTM family, is a simple but powerful reminder that keeping recurrent memory mixing — plus a couple of targeted changes — makes a big difference for real state-tracking tasks.

Below I summarize what memory mixing gives you, what sLSTM changes compared to a vanilla LSTM, why those changes matter for stateful problems, and the practical trade‑offs.

## Why “memory mixing” matters for state tracking

By “memory mixing” I mean hidden-to-hidden recurrence that lets the current hidden state influence not just the next output but also how different memory cells interact when updating. In practice that comes from recurrent matrices (the classic LSTM recurrent weights) that feed the previous hidden state into the cell input and gate computations.

This matters because genuine state-tracking tasks typically require:

- Maintaining discrete or combinatorial state across time (counters, parity bits, stacks).
- Revising previously stored information when new evidence comes in (e.g., finding a better nearest neighbor later in the sequence).
- Making update decisions that depend nonlinearly on combinations of past memory cells (e.g., switching behavior once multiple conditions are met).

Models that discard recurrent mixing — many SSMs and some “stateless” variants of attention or linearized attention — can be very effective at capturing long-range correlations, but they cannot implement arbitrary finite-state behaviors in the same way. The xLSTM paper explicitly demonstrates this: Transformers and several SSM variants without memory mixing fail on formal-language / parity-style tasks that require state tracking, while sLSTM-based architectures succeed.

## What sLSTM changes (in plain terms)

sLSTM keeps the core LSTM pattern — a memory that is updated additively and gated — but introduces two key changes:

1. Exponential gating: the input gate (and optionally the forget gate) uses an exponential activation instead of a pure sigmoid. Concretely,
   - $i_t = \exp(\tilde{i}_t)$ (input gate)
   - $f_t = \sigma(\tilde{f}_t)$ or $f_t = \exp(\tilde{f}_t)$ (forget gate)
   This makes gate values act like multiplicative weights on stored contributions (think softmax-like weighting) and enables aggressive re-weighting of older versus newer content.

2. A normalizer and a stabilizer that keep the math numerically well behaved while preserving exact outputs and gradients:
   - Normalizer state:
     $$
     n_t = f_t\, n_{t-1} + i_t
     $$
     and the cell state update
     $$
     c_t = f_t\, c_{t-1} + i_t\, z_t,
     $$
     with the readout normalized as
     $$
     \tilde{h}_t = \frac{c_t}{n_t}, \qquad h_t = o_t\,\tilde{h}_t.
     $$
     Intuitively, $c_t$ accumulates weighted contributions (weights = $i_t$ times future forgets), and dividing by $n_t$ produces a normalized, comparable retrieved signal regardless of scale.
   - Stabilizer for exponentials:
     $$
     m_t = \max\big(\log(f_t) + m_{t-1}, \; \log(i_t)\big),
     $$
     then use stabilized gates
     $$
     i'_t = \exp(\tilde{i}_t - m_t), \qquad
     f'_t = \exp\big(\log(f_t) + m_{t-1} - m_t\big).
     $$
     The paper proves replacing $i_t,f_t$ with the stabilized versions does not change outputs or gradients but prevents numerical overflow.

Why these pieces matter together: exponential gates give you a multiplicative (and highly re-weightable) accumulation of information; the normalizer turns that accumulation into a stable weighted average so retrievals stay meaningful; and the stabilizer keeps the exponentials numerically safe.

## How this enables revision and state tracking

Two concrete properties emerge from the sLSTM equations:

- Revisability: Because $i_t$ appears multiplicatively and can be exponentially large or small, a later input with a large input gate can "take over" the aggregated memory contribution, effectively revising what is being stored. This addresses a known LSTM limitation where previously stored values are hard to revise if they were already incorporated.

- Conditional, nonlinear mixing: sLSTM retains recurrent connections from $h_{t-1}$ into $\tilde{z}_t$, $\tilde{i}_t$, $\tilde{f}_t$, $\tilde{o}_t$ (the same hidden-to-gate/cell pathways as in classic LSTMs). Those recurrent matrices enable rich interactions between current inputs and prior memory across cells, which is precisely the mechanism needed to implement finite-state transitions, counters, and stack-like behavior required by formal languages (parity, matching brackets) and entity tracking.

The combination of multiplicative re-weighting (exponential gates) and recurrent mixing is what lets sLSTM both *store flexible, high-weight signals* and *change them based on later context*.

## Multi-cell and multi-head sLSTM: richer interactions

sLSTM supports multiple scalar memory cells (like a standard vectorized LSTM). With multiple cells you get memory mixing via recurrent weight matrices:
- Recurrent matrices feed previous hidden state into the cell input and gate computations (e.g., $\mathbf{R}_z$, $\mathbf{R}_i$, $\mathbf{R}_f$, $\mathbf{R}_o$ as in the paper).
- That lets different cells influence each other nonlinearly on every time step.

The paper also introduces a notion of multiple heads for sLSTM. Important points:
- Heads allow multiple separate channels of memory, where mixing is allowed inside each head but not across heads.
- This produces a new form of memory mixing: specialization per head combined with internal mixing yields richer, modular state dynamics without conflating all memory channels.

In short, multi-cell + multi-head sLSTM offers a flexible inductive bias: multiple interacting state machines (cells) inside each head, and multiple partially-independent heads overall.

## Empirical evidence (from the paper)

The xLSTM paper runs a suite of synthetic tasks designed to test state-tracking capacity (formal languages, parity, and related tasks) and compares two-block models across a set of architectures. The key empirical takeaways relevant to sLSTM:

- Models without recurrent memory mixing (many Transformer/SSM variants considered) fail to solve parity-like formal-language tasks, confirming the theoretical limits of stateless or non-mixing architectures on certain stateful problems.
- sLSTM-based xLSTM blocks (xLSTM[0:1], i.e., architectures using sLSTM blocks) solve these state-tracking tasks reliably, demonstrating that the combination of recurrent memory mixing and exponential gating is effective in practice.
- In a Nearest Neighbor Search experiment, classic LSTM struggles to revise a stored nearest neighbor when a more similar vector appears later, while the xLSTM variants with exponential gating can revise the stored value effectively.

These controlled experiments support the claim that retaining memory mixing — properly enhanced with exponential gates, normalization and stabilizers — yields qualitatively different capabilities on tasks that require true stateful reasoning.

## Trade-offs and practical guidance

sLSTM’s power comes with trade-offs:

- Parallelism: Memory mixing (the hidden-hidden recurrence) prevents straightforward time-parallel implementations. Unlike some SSMs or the parallelizable mLSTM variant in the same paper, sLSTM is inherently sequential. The paper reports a custom CUDA kernel that reduces the overhead, making sLSTM typically less than two times slower than the parallel mLSTM implementation on their setup, but it remains slower than fully parallel attention or SSM kernels.
- Initialization and stability: Exponential gates need careful stabilization and suitable initialization (the paper points out forget-gate initialization matters).
- Use cases: If your task primarily needs large parallel memory, extremely long contexts and attention-like retrievals, an mLSTM / Transformer / SSM-style model might fit better. If you need reliable state tracking, revisability, and the ability to implement finite-state behaviors (language grammars, counters, program-like state), sLSTM is a strong choice.

A practical compromise in xLSTM is mixing block types: architectures like xLSTM[7:1] (mostly mLSTM with a few sLSTM blocks) aim to get the best of both worlds — large parallelizable memory capacity plus some recurrent, mixing-enabled blocks for stateful processing.

## When to reach for sLSTM

Consider sLSTM (or an xLSTM hybrid that includes sLSTM blocks) when your problem involves one or more of:

- Explicit stateful logic (parity, brackets, counters, program evaluation).
- Long-running entity tracking where entities must be updated or replaced when new information arrives.
- Tasks where later inputs must be allowed to revise or overwrite previous memory contents effectively.
- Applications in RL, simulation, or time-series where sequential dynamics and stateful policies are required.

## Bottom line

Memory mixing — the old-school hidden-to-hidden recurrence — is not an obsolete relic. Combined with exponential gating, a normalizer, and a stabilizer, the sLSTM offers a principled way to get revisable, high-quality state representations that can implement finite-state and other stateful behaviors that many parallel, non-mixing architectures cannot. The xLSTM experiments make this concrete: for tasks that truly require state tracking, keeping memory mixing matters.

Code for the xLSTM family is available from the authors if you want to experiment with sLSTM and the combined xLSTM architectures.



# Blocks, Not Just Cells: Building LLMs with xLSTM

Long Short‑Term Memory (LSTM) cells were once the default building block for sequence models. Transformer attention pushed them aside for large language models (LLMs), mainly because attention is parallelizable and scales well with model size. xLSTM asks a simple question: can modernized LSTMs — with better gating and memory — be turned into block primitives and scaled into competitive LLMs? The short answer from the paper: yes — by treating cells as blocks, choosing the right projection order, and combining two new memory variants (sLSTM and mLSTM) inside residual pre‑LayerNorm backbones.

In this post I walk through the design decisions that turn new cells into full LLMs: what lives inside an xLSTM block, why mLSTM prefers pre up‑projection while sLSTM prefers post up‑projection, and the empirical payoffs (15B and 300B token experiments, length extrapolation, throughput).

## The two LSTM upgrades in one sentence

xLSTM extends LSTM along two axes:

- exponential gating (with a normalization and numerical stabilizer) so the model can revise storage decisions and control effective learning rates at each time step; and
- new memory structures: sLSTM keeps a scalar (but mixed) memory per cell; mLSTM upgrades the cell to a matrix memory with a covariance (outer‑product) update for much larger storage capacity.

Both variants are packaged into residual blocks and stacked in a pre‑LayerNorm backbone to build large models.

## Quick look at what changed inside a cell

The sLSTM keeps the familiar additive cell update but replaces sigmoidal input gating with exponential gating and adds a normalizer that records gate strength. Concretely, the forward pass uses

$c_t = f_t c_{t-1} + i_t z_t,\qquad n_t = f_t n_{t-1} + i_t,$

and the hidden output is normalized by the normalizer:

$h_t = o_t \tilde{h}_t,\qquad \tilde{h}_t = c_t / n_t.$

Input gates are exponential, e.g. $i_t = \exp(\tilde{i}_t)$, while forget gates can be $\sigma(\cdot)$ or exponential. Exponential gates can grow large, so xLSTM uses a stabilizer state $m_t$ and rescales the gates (see the paper for the exact stabilizer formulas); these stabilizations do not change the effective outputs or gradients but avoid numerical overflow.

Why this helps: exponential gating plus the normalizer lets the cell accumulate and later re‑weight contributions in a way that supports revising previous storage (the paper demonstrates this on tasks such as nearest neighbor search and formal languages that require state tracking). sLSTM also supports memory mixing via recurrent matrices between hidden states and the cell inputs/gates; heads can be introduced where mixing happens within but not across heads.

mLSTM replaces the scalar cell with a matrix memory $\mathbf{C}_t\in\mathbb{R}^{d\times d}$ and stores key/value pairs with a covariance (outer‑product) update:

$\mathbf{C}_t = f_t\,\mathbf{C}_{t-1} + i_t\,\mathbf{v}_t \mathbf{k}_t^\top.$

A normalizer vector tracks the corresponding key magnitudes,

$\mathbf{n}_t = f_t\,\mathbf{n}_{t-1} + i_t\,\mathbf{k}_t,$

and retrieval is a matrix–vector multiply with a scalar normalization:

$\tilde{\mathbf{h}}_t = \dfrac{\mathbf{C}_t \mathbf{q}_t}{\max\{|\mathbf{n}_t^\top \mathbf{q}_t|,\,1\}},\qquad \mathbf{h}_t = \mathbf{o}_t \odot \tilde{\mathbf{h}}_t.$

Intuition: the covariance update is a classic associative memory (fast weights), optimal under certain assumptions for signal/noise tradeoffs. Because mLSTM drops hidden‑to‑hidden memory mixing, its recurrence can be expressed in a parallel form and implemented efficiently using matrix operations.

## Blocks: pre vs post up‑projection and the role of Cover’s theorem

xLSTM packages these cells inside residual blocks. The paper uses two residual block patterns commonly seen in modern sequence models:

- Post up‑projection (Transformer‑style): non‑linear summary in the original (lower) dimensional space, then a linear up‑projection into a higher dimensional space, a nonlinearity, and a linear down‑projection back.
- Pre up‑projection (SSM‑style): linear up‑projection first, then the non‑linear summary happens in the high‑dimensional space, then a linear down‑projection.

Why this choice matters. Cover’s theorem reminds us that non‑linear embeddings into higher‑dimensional spaces make histories easier to separate linearly. mLSTM’s memory capacity benefits from storing keys/values in a higher‑dimensional embedding (more dimensions gives more capacity for distinct keys with better signal/noise). Therefore, xLSTM places mLSTM inside pre up‑projection blocks so the key/value projections and matrix memory naturally live in the large embedding space. For sLSTM, which relies on scalar memory with memory mixing and gating dynamics in the original space, a post up‑projection block is used instead. In short:

- mLSTM → pre up‑projection (memory operates in the high‑dim space)
- sLSTM → post up‑projection (memory/mixing happens in original space, then up‑project)

These block choices are then embedded into a standard pre‑LayerNorm residual backbone (the same general backbone style used in many contemporary LLMs) and stacked to form deep xLSTM architectures.

## Building LLMs from blocks: hybrid stacks and notation

xLSTM models can be hybrids of the two block types. The paper uses a compact notation xLSTM[$a$:$b$] to denote the ratio of mLSTM to sLSTM blocks. For example, xLSTM[7:1] means that out of every 8 blocks, 7 are mLSTM‑based and 1 is sLSTM‑based (for 48 total blocks, that is 42 mLSTM and 6 sLSTM blocks). This lets designers balance capacity (mLSTM matrix memory) and state‑tracking/mixing (sLSTM recurrent mixing), and the paper finds hybrid stacks effective in practice.

All blocks are wrapped in pre‑LayerNorm residuals and trained in the usual autoregressive next‑token setting.

## Empirical takeaways (what the experiments show)

The experiments in the paper cover synthetic tasks, a 15B‑token training run, and larger 300B experiments. Highlights:

- Synthetic tasks: xLSTM’s exponential gating plus mixing solves formal language/state‑tracking tasks that Transformers and many SSMs cannot; on associative recall (many key–value pairs) the mLSTM variants give strong memory capacity and extrapolation performance.
- 15B tokens (SlimPajama): when trained in the same setting as various baselines (Transformers, SSMs, RWKV variants, linear Transformers, etc.), xLSTM outperforms the competing methods in validation perplexity.
- 300B tokens: scaled experiments (several sizes from 125M to 1.3B) show that xLSTM variants (both xLSTM[1:0] and xLSTM[7:1]) maintain lower validation perplexities across model sizes. Scaling‑law fits indicate similar power‑law exponents but a favorable offset for xLSTM — i.e., extrapolations predict xLSTM remains competitive at larger sizes.
- Length extrapolation: models trained with context 2048 were tested up to 16,384. xLSTM models maintain low perplexity at much longer contexts compared to the baselines (good extrapolation behavior).
- Domain coverage (PALOMA): on 571 language domains, xLSTM[1:0] had lower perplexity than Mamba on 568/571 domains, lower than Llama on 486/571, and lower than RWKV‑4 on 570/571.
- Throughput and decoding: xLSTM has linear computation and constant memory with respect to sequence length (its memory is compressive). In practice, this yields linear generation time scaling (like other recurrent/linear methods) vs quadratic for standard Transformer decoding with KV caching. Measured on 1.3B models, xLSTM achieves higher maximal throughput and can use larger batch sizes because it doesn’t need a quadratic cache.

All of these results are in the paper; code and training settings are available in the authors’ repository.

## Tradeoffs and practical limitations

xLSTM closes some gaps but introduces tradeoffs you should know about:

- Parallelism: mLSTM is fully parallelizable (no hidden‑to‑hidden mixing) and hence scales well on GPUs. sLSTM retains mixing and is inherently sequential; the authors implemented a fast CUDA kernel that makes sLSTM typically under two times slower than their parallel mLSTM implementation, but sLSTM is still not embarrassingly parallel.
- Compute vs memory: mLSTM uses an explicit $\,d\times d\,$ matrix memory and corresponding updates, which increases compute (and FLOPs) compared to scalar cells. The update and retrieval use no additional parameters but are computationally heavy; current kernels are not fully optimized and in the authors’ implementation mLSTM is about 4× slower than FlashAttention in wall‑clock time.
- Numerical and optimization caveats: exponential gating needs stabilizers and careful initialization (forget gate initialization matters). The matrix memory is independent of sequence length, so for extreme context lengths it could saturate; experiments up to 16k did not show clear failures, but very long contexts may stress the memory.
- Engineering: large xLSTM models were trained with pragmatic, not exhaustive, hyperparameter tuning. The paper notes further gains could come from more extensive optimization.

## Bottom line

xLSTM demonstrates a concrete path to “LSTMs as blocks” for LLMs: give LSTM cells more expressive gating (exponential gates + stabilizer), richer memory formats (matrix covariance memory), and then place the right cell into the right residual block (pre vs post up‑projection). That combination lets xLSTM match or beat Transformers and State‑Space Models in perplexity at both 15B and 300B token scales, extrapolate to much longer contexts, and achieve high decoding throughput thanks to constant memory.

If you want to dive into code and the full technical details, the authors provide an implementation at: https://github.com/NX-AI/xlstm.



# Where xLSTM Wins—and Its Trade‑offs

## TL;DR
xLSTM is an extended LSTM family that combines (1) exponential gating with stabilizers and (2) two memory styles: a scalar, recurrent sLSTM (with memory mixing) and a matrix, parallelizable mLSTM (with a covariance update). Use xLSTM when you need linear compute and constant memory with sequence length — long contexts, high‑batch decoding, or memory‑constrained/edge deployments. Trade‑offs: mLSTM does heavy $d\times d$ updates, sLSTM is inherently sequential across time, and forget‑gate initialization and gate stabilization require care. A common practical compromise is to use mostly mLSTM blocks and a few sLSTM blocks (paper examples: xLSTM[1:0] or xLSTM[7:1]).

## Quick primer (the essentials)
xLSTM builds on two ideas:

- Exponential gating plus normalization/stabilization. The input gate can be exponential ($i_t=\exp(\tilde{i}_t)$) and the forget gate can be sigmoid or exponential; gates are stabilized by tracking a log-scale state $m_t$ so exponentials don’t overflow. For sLSTM a normalizer $n_t$ records gate mass so the hidden readout is normalized, e.g. $\tilde{h}_t = c_t / n_t$.

- Two memory formats:
  - sLSTM: scalar cell $c_t$ per memory unit with the usual LSTM-style recurrent mixing (hidden→gate/inputs). It supports memory mixing (recurrent matrices across cells) and is suited for state‑tracking problems.
  - mLSTM: matrix memory $\mathbf{C}_t\in\mathbb{R}^{d\times d}$ that stores key–value outer products with the covariance update
    $$
    \mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t\, \mathbf{v}_t\,\mathbf{k}_t^\top,
    $$
    a normalizer $\mathbf{n}_t$ tracks key mass, and readout uses
    $$
    \tilde{\mathbf{h}}_t = \frac{\mathbf{C}_t \mathbf{q}_t}{\max\{|\mathbf{n}_t^\top\mathbf{q}_t|,\,1\}}.
    $$
    mLSTM drops hidden→hidden memory mixing and is therefore parallelizable across time (the recurrence can be reformulated in parallel).

xLSTM models are assembled as residual stacks of xLSTM blocks. For best capacity, the paper uses pre up‑projection blocks for mLSTM and post up‑projection blocks for sLSTM inside those residual layers.

## When xLSTM is the right tool

1. Long contexts, linear compute and constant memory
   - Unlike Transformers (quadratic memory in context length), xLSTM has linear compute and constant memory with sequence length because the memory state is compressive and independent of context length. In experiments, xLSTM models trained on context 2048 extrapolated to much longer contexts (tested up to 16384) while maintaining low perplexities.

2. High‑batch decoding and throughput
   - Because memory usage does not grow with context, xLSTM can sustain much larger decoding batch sizes than a Transformer, which translates to higher throughput during generation. In the paper’s 1.3B experiments xLSTM achieved higher decoding throughput and linear generation time scaling with context length.

3. Memory‑constrained / edge deployments
   - The compressive, constant memory footprint is attractive for deployments where available RAM is limited (edge devices, on‑device inference), provided the compute cost of your chosen variant fits the device.

4. Tasks requiring state tracking
   - If you need to model stateful sequential logic (e.g., formal languages, entity tracking, code evaluation), include sLSTM blocks. sLSTM’s memory mixing (hidden‑to‑gates recurrent connections) enables solving tasks that non‑mixing models (many Transformers and SSMs) struggle with.

## Costs and practical trade‑offs

- mLSTM computation is heavy. The matrix memory uses $d\times d$ matrices and updates; while the updates are parameter‑free and parallelizable on GPUs, they are computationally expensive compared to pointwise gating. The paper notes the current implementation is not kernel‑optimal (roughly a few× slower than highly optimized attention kernels) and that faster CUDA kernels could reduce this gap.

- sLSTM is not parallel across time. Memory mixing via hidden→hidden connections enforces sequential dependency. The authors implemented a fast CUDA kernel that makes sLSTM reasonably efficient (reported as typically <2× slower than the parallel mLSTM implementation), but pure sLSTM designs still cannot leverage the same parallelism as mLSTM/Transformers for very large batch decoding.

- Forget‑gate initialization matters. The paper explicitly warns that forget‑gate initialization must be chosen carefully: poor choices can harm training stability or performance. (The paper does not prescribe one single initialization; tuning is required.)

- Matrix memory can saturate. Because $\mathbf{C}_t$ accumulates outer products, extreme increases in context length or number of stored pairs can overload capacity. The authors did not observe this to be limiting up to contexts tested (16k), but it is a theoretical constraint to monitor when pushing far beyond the evaluated regimes.

- Implementation maturity. The public codebase exists, but CUDA kernels and large‑scale hyperparameter sweeps are not fully optimized in the paper’s code, so expect to invest engineering effort to match the most optimized Transformer runtimes.

## Mixing sLSTM and mLSTM: practical recipes

- Use mostly mLSTM blocks when throughput and parallelism matter. A pure mLSTM stack (xLSTM[1:0]) is fully parallelizable and was one of the best performers in language tasks in the paper.

- Add a few sLSTM blocks for state tracking. If your task needs memory mixing, sprinkle sLSTM blocks sparingly. The paper reports and evaluates configurations using the notation xLSTM[$a$:$b$] where $a/b$ is the ratio of mLSTM to sLSTM blocks. Example: xLSTM[7:1] (out of 8 blocks, 7 are mLSTM and 1 is sLSTM) — for a 48‑block network this corresponds to 42 mLSTM + 6 sLSTM blocks. This configuration is a pragmatic compromise: the bulk of the model stays parallel and high‑throughput, while a few sLSTM blocks supply the needed memory mixing.

- Pre/post up‑projection choices matter. The paper uses pre up‑projection for mLSTM blocks (map into a high‑dimensional space before non‑linear summarization) and post up‑projection for sLSTM blocks. Follow this pattern as a sensible default.

- Heads and cells. sLSTM supports multiple heads where memory mixing happens within each head but not across heads (a new way to structure memory mixing). For mLSTM multiple heads and multiple cells are equivalent because there’s no hidden mixing.

## Tuning pointers & gotchas
- Use the stabilizer for exponentials. Exponential gates are powerful but need the stabilizer state $m_t$ (log‑space max trick) used in the paper to avoid overflow while preserving exact outputs/gradients.

- Normalize keys/values. The mLSTM setup assumes a layer‑norm before projecting inputs to keys/values and scales keys by $1/\sqrt{d}$; retrieval divides by $\max\{|\mathbf{n}_t^\top\mathbf{q}_t|,1\}$ to avoid near‑zero denominators.

- Watch mixed precision. The paper used mixed precision in many runs; some other models required custom settings. When training large xLSTM variants verify stability of mixed‑precision training on your stack.

- Expect to tune forget‑gate bias and learning schedule. Because gate dynamics changed (exponential input gates, optional exponential forget gates), gate biasing and learning rates can interact with stability. The paper flags initialization as important.

## Expected contexts before “saturation”
The paper warns that matrix memory is independent of sequence length and in principle could overload for arbitrarily long contexts. Empirically, xLSTM models trained on context length 2048 extrapolated well to much longer contexts (tested up to 16k) and maintained low perplexities. So in practice, for the regimes evaluated in the paper (up to 16k) memory saturation was not observed, but pushing far beyond that will require increasing $d$ (memory dim) or rethinking update/decay hyperparameters.

## How to get started (code and practical first steps)
- Repository: code is available at https://github.com/NX-AI/xlstm (as stated in the paper). Start by reading the README and examples in that repo.

- Quick experiment plan:
  1. Try a small model first (e.g., 125M or 350M scale used in the paper) to validate the training/inference pipeline.
  2. Use the pre‑LayerNorm residual backbone and follow the paper’s block choices: pre up‑projection for mLSTM blocks and post up‑projection for sLSTM blocks.
  3. Start with either xLSTM[1:0] (pure mLSTM) for throughput or xLSTM[7:1] (mostly mLSTM + a few sLSTM) for a mixed baseline.
  4. Enable the stabilizer for exponentials and monitor gate activations and normalizer magnitudes.
  5. Profile kernels: if you plan large scale training or tight latency targets, be prepared to optimize CUDA kernels for mLSTM updates and test the sLSTM kernel performance on your hardware.

## Bottom line
xLSTM gives you a modernized LSTM toolbox: exponential gates and a choice between scalar (stateful, mixing) and matrix (high‑capacity, parallel) memories. Choose xLSTM when you need constant memory with context length, large decoding batch sizes, better throughput, or stronger state tracking. Expect to pay in compute (especially for mLSTM’s $d\times d$ updates), sequential constraints (for sLSTM), and some extra engineering for initialization and kernel optimization. The paper’s experiments show xLSTM is competitive with state‑of‑the‑art Transformers and SSMs across many language tasks, and the public code is a reasonable starting point to try these trade‑offs on your workloads.

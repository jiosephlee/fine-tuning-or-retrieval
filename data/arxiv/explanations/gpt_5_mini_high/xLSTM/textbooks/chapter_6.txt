\title{A Textbook about the Paper: "xLSTM: Extended Long Short-Term Memory"}

Chapter 6: mLSTM: Matrix Memory with Covariance Updates

# Matrix memory C: storing key–value pairs via outer products

The core idea of the mLSTM is to replace the scalar LSTM cell with a matrix memory \(\mathbf{C}_t \in \mathbb{R}^{d \times d}\). Instead of storing a single scalar per cell, the matrix memory stores associations between key vectors and value vectors. At each time step \(t\) the model produces a key \(\mathbf{k}_t \in \mathbb{R}^d\) and a value \(\mathbf{v}_t \in \mathbb{R}^d\). The entry for that key–value pair is recorded in the matrix memory by adding the outer product \(\mathbf{v}_t \mathbf{k}_t^\top\). Concretely the mLSTM cell update (including gating) is written as
\[
\mathbf{C}_t \;=\; f_t \,\mathbf{C}_{t-1} \;+\; i_t \,\mathbf{v}_t \mathbf{k}_t^\top,
\]
where \(i_t\) and \(f_t\) are the input and forget gates (more on their meaning below). The outer product \(\mathbf{v}_t \mathbf{k}_t^\top\) stores a mapping from directions in the key space to directions in the value space: when later multiplied by a query \(\mathbf{q}\), that outer product contributes \(\mathbf{v}_t (\mathbf{k}_t^\top \mathbf{q})\), i.e., the stored value scaled by the similarity between the query and the stored key.

A useful algebraic expansion helps make the retrieval mechanism explicit. If we unroll the recurrence (and assume \(\mathbf{C}_0=\mathbf{0}\) for simplicity), then
\[
\mathbf{C}_t \;=\; \sum_{s=1}^t \left(\prod_{u=s+1}^t f_u\right) i_s \,\mathbf{v}_s \mathbf{k}_s^\top.
\]
Multiplying this \(\mathbf{C}_t\) by a query \(\mathbf{q}_t\) yields
\[
\mathbf{C}_t \mathbf{q}_t \;=\; \sum_{s=1}^t \left(\prod_{u=s+1}^t f_u\right) i_s \,\mathbf{v}_s \,(\mathbf{k}_s^\top \mathbf{q}_t),
\]
so the retrieved vector is a weighted linear combination of past values \(\mathbf{v}_s\), with weights given by the product of gates and the key–query inner product \(\mathbf{k}_s^\top\mathbf{q}_t\). The outer-product storage therefore implements associative retrieval: a query projects onto stored keys and reconstitutes the corresponding values.

Because the matrix memory is a single \(d\times d\) object that accumulates outer products, its capacity is not tied linearly to the sequence length; it compresses the history into a fixed-size associative structure.

# Covariance update rule and ties to BAM and fast weights

The mLSTM update is a gated and normalized variant of a classical covariance or outer-product learning rule. The plain covariance update (no gates) would be
\[
\mathbf{C}_t \;=\; \mathbf{C}_{t-1} \;+\; \mathbf{v}_t \mathbf{k}_t^\top,
\]
a rule that dates back to early associative memory models such as Bidirectional Associative Memories (BAMs) and related works (Kohonen, Anderson, Nakano, Sejnowski, Dayan, ...). In the mLSTM this basic rule is augmented by the multiplicative gates \(f_t\) and \(i_t\), which respectively implement decay of the old memory and a controllable learning rate for the new outer product.

The paper emphasizes two classical connections. First, when keys are zero-mean (the authors assume a layer-normalization before the key/value projections), the covariance update is optimal in the sense of maximizing separability of retrieved binary vectors, which can be interpreted as maximizing signal-to-noise ratio in retrieval. Second, the outer-product accumulation is equivalent in spirit to Fast Weight Programmers: an explicit, rapidly changing weight matrix is formed from recent inputs (outer products), and it can be read out by multiplying by a query. Many subsequent architectures use the same building block (rank-1 updates, optional decay and learning rates) to build compressive associative memories.

One practical point made in the paper is that higher separability can be achieved only by allowing pairwise interactions of tokens at retrieval time (which leads to quadratic attention). The covariance update rule is a compromise: it yields strong associative capacity with a fixed-size memory and a linear-in-time update at the cost of retaining only second-order (outer-product) correlations rather than full pairwise access to all stored interactions.

# Gate roles: input as learning rate, forget as decay, output as scaling

Gates in mLSTM take on natural interpretations in the matrix-memory setting. The forward formulas from the paper state the gates as
\[
i_t = \exp(\tilde{i}_t),\qquad
f_t = \sigma(\tilde{f}_t)\ \text{or}\ \exp(\tilde{f}_t),\qquad
\mathbf{o}_t = \sigma(\tilde{\mathbf{o}}_t),
\]
with the pre-activations \(\tilde{i}_t,\tilde{f}_t,\tilde{\mathbf{o}}_t\) produced by affine projections of the input \(\mathbf{x}_t\). Because \(i_t\) is strictly positive (exponential) it behaves like a positive learning rate: it controls how strongly the new outer product \(\mathbf{v}_t \mathbf{k}_t^\top\) is added to memory. The forget gate \(f_t\) multiplies the entire previous matrix by a scalar, thereby implementing an exponential decay on all previously stored contributions; older entries are attenuated multiplicatively by the product of future forget gates. The output gate \(\mathbf{o}_t\) is a vector gate that scales the retrieved vector elementwise just before producing the hidden state.

Putting these pieces into the mLSTM memory update and readout,
\[
\mathbf{C}_t \;=\; f_t \mathbf{C}_{t-1} \;+\; i_t \mathbf{v}_t \mathbf{k}_t^\top, \qquad
\mathbf{h}_t \;=\; \mathbf{o}_t \odot \tilde{\mathbf{h}}_t,
\]
makes the analogy clear: \(i_t\) is the per-step learning rate for the fast weight, \(f_t\) is the retention/decay multiplier, and \(\mathbf{o}_t\) shapes the final returned vector dimension-wise. Because the model learns the pre-activations \(\tilde{i}_t,\tilde{f}_t,\tilde{\mathbf{o}}_t\) from \(\mathbf{x}_t\), it can adaptively decide when to store, forget, and expose memory to downstream layers.

# Query-based retrieval and division by a guarded normalizer

Retrieval in mLSTM is query-driven: the model projects the current input \(\mathbf{x}_t\) to a query \(\mathbf{q}_t\), which is used to read the associative memory:
\[
\mathbf{q}_t = \mathbf{W}_q \mathbf{x}_t + \mathbf{b}_q,\qquad
\mathbf{k}_t = \frac{1}{\sqrt{d}}\,\mathbf{W}_k \mathbf{x}_t + \mathbf{b}_k,\qquad
\mathbf{v}_t = \mathbf{W}_v \mathbf{x}_t + \mathbf{b}_v.
\]
The immediate (unnormalized) retrieval is \(\mathbf{C}_t \mathbf{q}_t\). To keep the scale of the retrieved vector consistent across different histories and gating strengths, the mLSTM divides this retrieval by a scalar normalizer based on a running sum of keys:
\[
\mathbf{n}_t \;=\; f_t \mathbf{n}_{t-1} \;+\; i_t \mathbf{k}_t,
\qquad
\tilde{\mathbf{h}}_t \;=\; \frac{\mathbf{C}_t \mathbf{q}_t}{\max\big\{\,|\mathbf{n}_t^\top \mathbf{q}_t|,\;1\,\big\}}.
\]
Here \(\mathbf{n}_t\) collects the keys, weighted by their input gate and decayed by future forget gates; it therefore records the total “mass” of key contributions that are still present in the memory. The scalar \(\mathbf{n}_t^\top \mathbf{q}_t\) measures how much the current query aligns, in aggregate, with the active keys in memory. Dividing the raw retrieval \(\mathbf{C}_t \mathbf{q}_t\) by that aggregate alignment produces a scale-invariant readout that behaves roughly like a normalized weighted average of the stored values.

To see this more explicitly, substitute the unrolled forms of \(\mathbf{C}_t\) and \(\mathbf{n}_t\). The numerator is a sum of terms proportional to \(\mathbf{v}_s (\mathbf{k}_s^\top \mathbf{q}_t)\), while the denominator is (up to gating weights) a sum of the scalars \((\mathbf{k}_s^\top \mathbf{q}_t)\). The division therefore yields a value that depends on relative key–query similarities rather than on absolute magnitudes of gate strength or key norms, which stabilizes the output across different contexts.

# Key scaling and denominator thresholding for stability

Two pragmatic choices in the mLSTM design improve numerical stability of the key–query interactions. First, keys are scaled by \(1/\sqrt{d}\) in their projection:
\[
\mathbf{k}_t = \frac{1}{\sqrt{d}}\,\mathbf{W}_k \mathbf{x}_t + \mathbf{b}_k.
\]
This scaling counteracts the typical growth of dot products with vector dimension \(d\), keeping the distribution of \(\mathbf{k}_t^\top \mathbf{q}_t\) well-behaved as \(d\) increases. The practice mirrors the scaled dot-product trick used in Transformer attention and controls variance of inner products.

Second, the denominator in the retrieval formula uses an absolute value and a lower bound:
\[
\max\big\{\,|\mathbf{n}_t^\top \mathbf{q}_t|,\;1\,\big\}.
\]
There are two reasons for these choices. The absolute value prevents sign cancellations or flips from producing an effectively “negative mass” in the denominator; we are interested in the magnitude of the aggregate key–query alignment as a normalizing quantity. The threshold (commonly chosen to be \(1.0\)) ensures that when the aggregate alignment is very small—due to orthogonal keys, small gate strengths, or other factors—the division will not amplify noise by dividing by a near-zero scalar. This guarded normalization had been adopted in prior work (e.g., Retention) and is a small but important safeguard against unstable large outputs.

# Exponential gate stabilization carried over from sLSTM

mLSTM uses exponential activation for the input gate \(i_t\) (and optionally for the forget gate \(f_t\)), which guarantees positivity and maps the learned pre-activation into an interpretable multiplicative factor (learning rate / decay). However, plain exponentials can produce extremely large values and overflow floating-point representations when pre-activations grow. To avoid this, the authors reuse the stabilization trick introduced for sLSTM.

The stabilizer maintains an auxiliary scalar state \(m_t\) defined by
\[
m_t \;=\; \max\!\big( \log(f_t) + m_{t-1},\; \log(i_t) \big).
\]
Using \(m_t\) we form stabilized gates
\[
i'_t \;=\; \exp\!\big(\log(i_t) - m_t\big) \;=\; \exp(\tilde{i}_t - m_t),
\qquad
f'_t \;=\; \exp\!\big(\log(f_t) + m_{t-1} - m_t\big).
\]
Replacing \(i_t\) by \(i'_t\) and \(f_t\) by \(f'_t\) in the forward pass prevents intermediate exponentials from overflowing while preserving the relative ratios that matter for the dynamics. The paper reports (and proves in its appendix) that this substitution does not change the network outputs nor the gradients with respect to parameters; it merely changes the internal numeric pathway to one that is robust to very large or very small gate values. In mLSTM this stabilization is applied in the same way as in sLSTM.

# Multiple cells vs. heads: equivalence without memory mixing

A structural consequence of mLSTM is that multiple cells and multiple heads collapse to equivalent designs in the absence of memory mixing. In architectures like the classic vector LSTM, multiple scalar cells can interact via recurrent hidden–hidden weight matrices, producing memory mixing across cells. In mLSTM there are no recurrent hidden–hidden connections driving memory mixing inside the associative matrix: the matrix memory evolves only by scalar-multiplied persistence and rank-1 updates driven by the input. Because of this independence, splitting the memory into several parallel matrices (multiple cells) or into multiple heads (partitioned subspaces) yields equivalent functional forms—each head or cell simply maintains its own \(\mathbf{C}\)-matrix and processes updates independently, and the model combines the resulting retrievals.

The practical consequence is that designers may choose to realize capacity as either multiple heads or multiple matrices without changing the model class: adding heads is a straightforward way to parallelize computation or to shape the inductive bias (for instance, to encourage specialization), but it does not introduce cross-head memory mixing that would change the expressiveness beyond what independent matrices provide.

# Parallel formulation (scan) and computational complexity (O(d^2))

Two computational facts about mLSTM are important for understanding its trade-offs.

First, the per-step computational and memory complexity is dominated by \(d\times d\) operations. Forming the outer product \(i_t \mathbf{v}_t \mathbf{k}_t^\top\) and adding it to \(\mathbf{C}_{t-1}\) is an \(O(d^2)\) operation; multiplying \(\mathbf{C}_t\) by the query \(\mathbf{q}_t\) to produce \(\mathbf{C}_t \mathbf{q}_t\) is another \(O(d^2)\) matrix–vector product. Multiplying the stored matrix by a scalar forget gate is also \(O(d^2)\). Thus the per-step arithmetic cost scales as \(O(d^2)\). On the other hand the memory footprint of the recurrent state is a single \(d\times d\) matrix (or a small number of such matrices when using multiple heads), so the recurrent memory requirement is constant with respect to sequence length—unlike Transformer attention which stores per-token keys and values.

Second, because the mLSTM recurrence does not involve hidden-to-hidden mixing (no recurrent weight matrices that reorder or mix hidden components across time), the update recurrence can be reformulated into a parallel (scan) computation. Conceptually, the update
\[
\mathbf{C}_t \;=\; f_t \mathbf{C}_{t-1} \;+\; i_t \mathbf{v}_t \mathbf{k}_t^\top
\]
is a linear recurrence in \(\mathbf{C}\) with a scalar multiplicative factor plus an additive rank-1 term. Such recurrences can be re-expressed using associative prefix operations (scan) so that large segments of the sequence work can be combined in parallel. That property is what the authors mean when they claim mLSTM is “fully parallelizable” (they point to an appendix for a full parallel reformulation). In practice, this means mLSTM can be implemented efficiently on GPUs by casting the updates and retrievals into standard matrix operations that are highly optimized, and that one can apply parallel-scan algorithms if desired to further accelerate across long sequences.

The trade-off is explicit: mLSTM gives a powerful, compressive associative memory with constant memory per sequence length and fully parallel formulation, but this comes at the cost of \(O(d^2)\) per-step computation and a \(d\times d\) recurrent state. The paper notes that the matrix memory itself contains no learned parameters (the projections to keys/values/queries and the gating parameters carry the learned capacity), and that although the computational cost is high, the operations are amenable to GPU parallelism so the wall-clock penalty can be modest with optimized kernels.

# Summary

mLSTM extends the LSTM idea by turning the scalar cell into a matrix associative memory that stores key–value pairs as outer products and reads them via queries. The covariance (outer-product) update is interpreted as a gated fast-weight rule: the input gate acts as a learned, positive learning rate; the forget gate applies scalar decay to previously stored associations; and the output gate scales the retrieved vector. Retrieval is normalized by a guarded normalizer built from the weighted sum of keys, with key scaling and thresholding used to ensure numerical stability. Exponential gates are stabilized using a log-max trick inherited from sLSTM so that the positive multiplicative factors do not overflow. Because there is no hidden–hidden memory mixing, multiple heads are equivalent to multiple independent memory cells and the recurrent recurrence can be re-expressed in a parallel (scan-like) form; the main computational cost per time step is \(O(d^2)\) due to the matrix memory operations, while memory use is constant in sequence length. Together, these choices realize a high-capacity associative memory that is both expressive and amenable to parallel implementation on modern accelerators.

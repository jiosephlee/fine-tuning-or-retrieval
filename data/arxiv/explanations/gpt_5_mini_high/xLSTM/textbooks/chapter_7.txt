\title{A Textbook about the Paper: "xLSTM: Extended Long Short-Term Memory"}

Chapter 7: xLSTM Blocks and Full Architectures

# Design goal: nonlinear summarization in high-dimensional spaces

The central design goal of an xLSTM block is to produce a compact, discriminative summary of the past that makes different histories (contexts) easier to separate for a downstream linear predictor. In autoregressive sequence tasks such as language modeling, the predictor needs to distinguish subtle differences in past context in order to produce the correct next token. Rather than keeping raw token streams or shallow linear summaries, each xLSTM block is intended to non-linearly compress the history into a representation where distinct contexts are more linearly separable. This non-linear summarization is the functional role of the block: compress information about the entire prefix into a fixed-dimensional representation that downstream layers can read out effectively.

Practically, achieving strong non-linear summarization means combining (1) a recurrent or memory-centered core that updates an internal state from the new input and previous summary and (2) projection stages that change the working dimensionality before and after the core. Which side of the projection the core operates in (low-dimensional embedding space versus a higher up-projected space) has important consequences for the memory capacity and for which computations are performed in parallel versus sequentially. The remainder of this chapter explains the theoretical motivation for moving computations into higher-dimensional spaces and the two concrete block styles xLSTM uses to realize that goal.

# Cover’s Theorem motivation for up-projection

Cover’s Theorem motivates the use of high-dimensional embeddings for non-linear summarization. In the words used in the paper, Cover’s Theorem states that “in a higher dimensional space non-linearly embedded patterns can more likely be linearly separated than in the original space.” The practical upshot is that a non-linear mapping into a sufficiently high-dimensional space increases the chance that different histories (which may be entangled in the original embedding space) become linearly separable after the mapping.

This insight directly informs the choice to include up-projection and down-projection stages around the recurrent/memory core: by mapping inputs into a larger intermediate dimension, applying non-linear memory updates there, and then projecting back, the block can create high-capacity, highly separable summaries of history. Two canonical choices arise for where to place that up-projection relative to the nonlinear memory core; the xLSTM design uses both in different situations (post up-projection and pre up-projection), selected according to the memory primitive used in the core.

# Post up-projection blocks (Transformer-like) for sLSTM

The post up-projection style is the block shape that mirrors the common “Transformer-like” ordering: the block first non-linearly summarizes the past in the original embedding space, and only afterwards applies an up-projection into a higher-dimensional space, followed by a non-linear activation and a projection back down. In xLSTM this style is used for blocks that contain the sLSTM memory core.

Intuitively, sLSTM extends the classic scalar LSTM cell with exponential gating and a normalizer state, but it retains memory mixing via hidden-to-gate and hidden-to-input recurrent connections. That memory mixing—recurrent interactions between the hidden state and the gates/inputs—means the sLSTM inherently performs sequential, history-dependent computation in the input-space. Placing the core computation in the original space (and then up-projecting) lets the sLSTM perform its state-tracking and memory-mixing behavior in the space where those recurrent connections are defined, while still obtaining the advantages of an up-projection for downstream separability.

A concise description of the sLSTM core (reproduced from the xLSTM formulation) is:
\[
\begin{aligned}
c_t &= f_t \, c_{t-1} + i_t \, z_t,\\
n_t &= f_t \, n_{t-1} + i_t,\\
\tilde{h}_t &= c_t / n_t,\\
h_t &= o_t \, \tilde{h}_t,
\end{aligned}
\]
with gate preactivations and inputs that can depend on the previous hidden state $h_{t-1}$, e.g.
\[
\tilde{i}_t = \mathbf{w}_i^\top \mathbf{x}_t + r_i h_{t-1} + b_i,\quad
i_t = \exp(\tilde{i}_t),
\]
and similarly for $\tilde{z}_t$, $\tilde{f}_t$, and $\tilde{o}_t$ (the forget gate can be either $\sigma(\tilde{f}_t)$ or $\exp(\tilde{f}_t)$). Because sLSTM keeps hidden-dependent recurrent terms $r_\cdot h_{t-1}$, it is not fully parallelizable across time; this is why the post up-projection pattern (compute recurrence in the original space, then lift) is the natural choice for sLSTM-containing blocks.

# Pre up-projection blocks (SSM-like) for mLSTM

By contrast, the pre up-projection style maps inputs first into a higher-dimensional space and then performs the non-linear summarization (the memory update) in that larger space before projecting back down. xLSTM uses the pre up-projection block for mLSTM cores.

The mLSTM replaces the scalar cell with a matrix-valued memory $\mathbf{C}_t\in\mathbb{R}^{d\times d}$ and uses a covariance (outer-product) update rule. Because the mLSTM memory is fundamentally a $d\times d$ structure, the memory capacity grows with the internal dimensionality; therefore it benefits from being operated on in a higher-dimensional working space. Mapping into that space first (pre up-projection) expands the representational capacity available for keys, values and the matrix memory updates, so the covariance update can store richer associations.

The mLSTM core is specified as:
\[
\begin{aligned}
\mathbf{C}_t &= f_t \, \mathbf{C}_{t-1} + i_t \, \mathbf{v}_t \, \mathbf{k}_t^\top,\\
\mathbf{n}_t &= f_t \, \mathbf{n}_{t-1} + i_t \, \mathbf{k}_t,\\
\tilde{\mathbf{h}}_t &= \dfrac{\mathbf{C}_t \mathbf{q}_t}{\max\{\,|\mathbf{n}_t^\top\mathbf{q}_t|,\,1\,\}},\\
\mathbf{h}_t &= \mathbf{o}_t \odot \tilde{\mathbf{h}}_t,
\end{aligned}
\]
with linear projections from the input $\mathbf{x}_t$ to query/key/value:
\[
\mathbf{q}_t = \mathbf{W}_q \mathbf{x}_t + \mathbf{b}_q,\quad
\mathbf{k}_t = \frac{1}{\sqrt{d}}\mathbf{W}_k \mathbf{x}_t + \mathbf{b}_k,\quad
\mathbf{v}_t = \mathbf{W}_v \mathbf{x}_t + \mathbf{b}_v,
\]
and input-only gate preactivations in the parallel formulation, e.g.
\[
\tilde{i}_t = \mathbf{w}_i^\top \mathbf{x}_t + b_i,\qquad i_t = \exp(\tilde{i}_t).
\]
Because mLSTM omits hidden-dependent recurrent mixing in these gate formulas, the updates can be formulated in a parallel (time-wise) fashion, enabling efficient batched computation. The map-then-memory style (pre up-projection) leverages larger internal dimensionality to grow memory capacity via the $d\times d$ matrix $\mathbf{C}_t$.

# Pre-LayerNorm residual backbones

xLSTM architectures are assembled by residually stacking xLSTM blocks into deep networks using the common pre-LayerNorm residual backbone that contemporary large models favor. In practice, each block sits inside a residual frame: the input to the block is first normalized (pre-LayerNorm), the block computes its nonlinear summary (including the sLSTM or mLSTM core and the up/down projections appropriate to that core), and the result is added back to the block input as a residual connection. The paper follows this standard backbone choice because it is the most common practice in modern large language models.

You can view the backbone at a high level as iterating a transform of the normalized state and adding a skip connection; in compact form the layer-to-layer update can be expressed as
\[
\mathbf{x}_{\ell+1} = \mathbf{x}_\ell + \mathrm{Block}\big(\mathrm{LayerNorm}(\mathbf{x}_\ell)\big),
\]
where $\mathrm{Block}(\cdot)$ is an xLSTM block (either pre-up or post-up variant). Using pre-LayerNorm with residual connections keeps individual block inputs well-scaled and supports stable training when many blocks are stacked.

# xLSTM[a:b] notation: mixing mLSTM and sLSTM blocks

To specify a hybrid xLSTM architecture the paper introduces the compact notation xLSTM[$a$:$b$], where $a/b$ denotes the ratio of mLSTM-based blocks versus sLSTM-based blocks in the full model. For instance, xLSTM[7:1] means that out of every 8 blocks, 7 are mLSTM-based and 1 is sLSTM-based. When applying that to a full stack of 48 blocks, xLSTM[7:1] corresponds to 42 mLSTM blocks and 6 sLSTM blocks.

This ratio notation communicates the intended balance between (i) matrix-memory, fully parallelizable blocks (mLSTM) that provide large associative storage and (ii) scalar-memory, memory-mixing blocks (sLSTM) that permit recurrent state-mixing useful for state tracking. Across experiments in the paper, xLSTM instances were built using pre up-projection blocks for mLSTM and post up-projection blocks for sLSTM, consistent with the memory characteristics of each core.

# Stacking strategy and depth considerations

Stacking strategy in xLSTM centers on two choices: the total number of residual blocks (depth) and the allocation of those blocks between mLSTM and sLSTM types (the $a\!:\!b$ ratio). Both choices influence final model capacity, parallelism, compute cost, and the set of tasks the model is well-suited to.

Depth: increasing the number of residually stacked blocks increases the number of nonlinear summarization stages applied to the history. Deeper stacks allow the model to build more expressive hierarchical summaries, which in turn tends to improve modeling power and scaling behavior (as observed for many deep architectures). In experiments reported in the paper, a common large configuration used 48 residual blocks for xLSTM experiments; as a point of comparison, a GPT-3-style 350M model uses 24 residual blocks with embedding dimension 1024.

Mixing ratio: the $a\!:\!b$ choice trades off between memory capacity and state-tracking expressivity. Since mLSTM blocks use matrix memory and are parallelizable, they are a natural choice for the majority of blocks when one wants maximal memory capacity and efficient training/inference. sLSTM blocks, by contrast, add memory mixing via recurrent hidden-to-gate terms which enable state-tracking behaviors that other parallel cores cannot express. The paper’s experiments show that both purely-mLSTM stacks (xLSTM[1:0]) and mixed stacks (e.g., xLSTM[7:1]) perform very well; in practice one can place a small fraction of sLSTM blocks within a predominantly mLSTM stack to give the model explicit sequential memory-mixing ability without losing most of the parallelism and memory capacity.

Practical placement: the $a\!:\!b$ notation does not fix a particular interleaving order; implementations may distribute the sLSTM blocks throughout the stack (sparsely) or group them. The experimental xLSTMs in the paper follow the convention that pre up-projection is used for mLSTM blocks and post up-projection for sLSTM blocks, and they evaluate several mixing ratios to study the trade-offs.

# Practical block components: activations, projections, and norms

Each xLSTM block is constructed from a small set of practical, well-defined components: linear projections (up/down), activation functions for cell inputs, gating nonlinearities, normalizers, and optional stabilizers. The paper specifies these components for both sLSTM and mLSTM cores; here we collect and explain them as they appear inside blocks.

Activations and gates. The sLSTM and mLSTM share the same basic gate design but differ in where recurrent dependence appears. Typical choices include:
- Cell-input and state non-linearities $\varphi$ and $\psi$ (often implemented as $\tanh$).
- Input gate using an exponential activation: $i_t = \exp(\tilde{i}_t)$.
- Forget gate using either a sigmoid $\sigma(\tilde{f}_t)$ or an exponential $\exp(\tilde{f}_t)$.
- Output gate is a sigmoid: $o_t = \sigma(\tilde{o}_t)$.

Stabilizer for exponential gates. Exponential gates can grow very large numerically; xLSTM uses a stabilizer state $m_t$ (following the formulation in the paper) to avoid overflow while preserving equivalence of outputs and gradients. The stabilizer update and stabilized gates are:
\[
\begin{aligned}
m_t &= \max\big(\log(f_t) + m_{t-1},\ \log(i_t)\big),\\
i'_t &= \exp\big(\log(i_t) - m_t\big) = \exp(\tilde{i}_t - m_t),\\
f'_t &= \exp\big(\log(f_t) + m_{t-1} - m_t\big).
\end{aligned}
\]
Replacing $i_t$ and $f_t$ by $i'_t$ and $f'_t$ in the forward pass removes numerical instabilities without changing the computed outputs or parameter gradients.

Normalizers and readout scaling. Both sLSTM and mLSTM maintain a normalizer state $n_t$ that keeps track of the effective magnitude of stored contributions (the paper describes it as summing the product of input gate times all future forget gates). In sLSTM this normalizer is scalar and the hidden pre-output is $\tilde{h}_t = c_t/n_t$. In mLSTM the normalizer $\mathbf{n}_t$ is a vector and the readout is scaled by the dot product $\mathbf{n}_t^\top \mathbf{q}_t$ with a lower bound:
\[
\tilde{\mathbf{h}}_t = \frac{\mathbf{C}_t \mathbf{q}_t}{\max\{\,|\mathbf{n}_t^\top\mathbf{q}_t|,\,1\,\}}.
\]
Taking the absolute value and a lower bound (threshold typically set to 1) guards against tiny denominators and was adopted in the paper to stabilize retrieval.

Projections and layer normalization. mLSTM relies on linear projections from input to query/key/value:
\[
\mathbf{q}_t = \mathbf{W}_q \mathbf{x}_t + \mathbf{b}_q,\quad
\mathbf{k}_t = \frac{1}{\sqrt{d}}\mathbf{W}_k \mathbf{x}_t + \mathbf{b}_k,\quad
\mathbf{v}_t = \mathbf{W}_v \mathbf{x}_t + \mathbf{b}_v.
\]
The paper assumes a layer normalization is applied before projecting inputs to keys and values so that the projected keys and values have (approximately) zero-mean, which is important for the covariance-style update to behave as intended.

Heads and cells. sLSTM supports multiple memory cells and can be arranged with multiple heads: within each head memory mixing (recurrent hidden-to-gate and hidden-to-input connections) is allowed, but there is no memory mixing across heads. This introduces a structured form of memory mixing where heads are independent mixing units. For mLSTM, the paper notes that multiple heads and multiple cells are equivalent because there is no memory mixing across time in the parallel formulation.

Compute/memory considerations. The mLSTM’s matrix memory $\mathbf{C}_t$ and its $d\times d$ outer-product update are computationally heavier than scalar-cell updates, but the operations are parameter-free (the memory itself is not parameterized) and are parallelizable across the sequence. The sLSTM’s mixing via recurrent connections prevents a fully parallel time-batched implementation, but the authors report efficient CUDA kernels that keep sLSTM wall-clock overhead moderate in practice.

---

Putting these components together, an xLSTM architecture is formed by choosing a backbone depth, assigning each residual block as either an mLSTM or sLSTM block (and therefore a pre- or post-up-projection layout), and instantiating the practical gate/activation/projection choices described above. The combined effect is a family of networks that preserve the LSTM ideas (constant-error carousel and gating) while leveraging modern architectural practices (residual pre-LayerNorm backbones, projection-based up-sampling, and parallelizable matrix memories) to scale favorably for large language modeling.

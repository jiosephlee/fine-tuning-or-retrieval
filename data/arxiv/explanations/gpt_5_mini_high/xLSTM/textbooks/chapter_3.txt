\title{A Textbook about the Paper: "xLSTM: Extended Long Short-Term Memory"}

Chapter 3: Where Classic LSTMs Fall Short

Before we examine the specific failure modes, recall the core LSTM update that encodes its memory and gating ideas. At each time step the cell state and hidden state are updated by

\[
c_t \;=\; f_t \, c_{t-1} \;+\; i_t \, z_t,
\qquad
h_t \;=\; o_t \,\psi(c_t),
\]

where \(i_t\), \(f_t\), and \(o_t\) are the input, forget, and output gates and \(z_t\) is the new cell input. This additive, gated update (the “constant error carousel”) is the reason LSTMs avoid vanishing gradients and why they can store information across many steps. But that same structure also creates three concrete limitations that underlie many modern failures of classic LSTMs. The sections below explain each limitation, give a precise mechanism for why it arises, and connect the limitation to the motivating experiments in the paper.

# Inability to revise storage decisions

The LSTM cell update is additive and gated: everything the network has stored from earlier time steps appears in the current cell state as a sum of past inputs, each attenuated by the forget gates applied since its insertion. Unrolling the recurrence shows this explicitly:

\[
c_T \;=\; \sum_{s=1}^T \Big( i_s z_s \prod_{u=s+1}^T f_u \Big),
\]

so the contribution of an input at time \(s\) to the final state \(c_T\) is scaled by the product of the forget gates that occur after \(s\). Two consequences follow directly.

First, an earlier stored item can only be diminished by the network through the future forget gates \(\{f_{s+1},\dots,f_T\}\). The model cannot directly “go back” and rewrite the remembered representation except by reducing those future multiplicative factors. Practically, this means that revising a previously stored decision (for instance: “the best match so far is X; now a better match Y has arrived — replace X with Y”) requires the model to set the right pattern of forget and input gates at later steps so the later input’s contribution overwhelms the earlier one.

Second, standard LSTM gates are typically sigmoid activations and hence constrained to the interval \((0,1)\). That bounds how sharply a single input can dominate or be suppressed: the only way to make a later input completely replace an earlier one is to set many subsequent forget gates near zero or a single input gate very close to one while all the intervening forget gates are very small. In practice, learning such coordinated gate trajectories is difficult, especially when the decision to revise must depend on fine-grained similarity comparisons between vectors observed at different times.

Together, these factors make classic LSTMs brittle in scenarios that require frequent, selective overwriting of memory. The xLSTM paper addresses this by replacing the usual sigmoid gating for some gates with exponential gating, so that the scale of the input and forget multipliers is not artificially constrained. That change, together with explicit normalization and stabilization, allows the network to produce much larger relative weights for new inputs (or much stronger attenuation for old ones) when the data demands a decisive revision of stored content.

# Nearest Neighbor Search as a failure mode example

A concrete task that exposes the inability to revise storage decisions is the sequential Nearest Neighbor Search described in the paper. The problem is simple to state: given a reference vector \(r\), a sequence of candidate vectors \(\{x_1,\dots,x_T\}\) arrives; each candidate \(x_t\) carries an associated value \(y_t\). The model must scan the sequence and at the final time step emit the value \(y_{t^*}\) associated with the candidate \(x_{t^*}\) that is most similar to the reference \(r\). This task forces the model to maintain “best-so-far” state and to update that state whenever a better match appears.

For an LSTM, implementing “best-so-far” behavior amounts to storing the associated value in the cell and updating it when a new candidate is judged more similar. But the mechanism available is precisely the additive gated update analyzed above: a previous winner’s contribution to the cell persists unless later forget gates repress it sufficiently. When a much better candidate appears late in the sequence, the network must learn to set the gates so the later input’s contribution overtakes the earlier one. With sigmoid-bounded gates and the difficulty of coordinating gates across many steps, the LSTM often fails to revise reliably, producing a large mean-squared error on this task (the paper shows this in the nearest-neighbor figure).

This failure is not merely a training difficulty: it is structural. The additive form turns the memory into a weighted accumulation where older inputs are only attenuated multiplicatively by future forget gates. Exponential gating (as introduced in sLSTM) makes it possible to scale input updates much more flexibly than a sigmoid would allow, enabling decisive overwrites when a later example should replace an earlier stored item. The Nearest Neighbor experiment in the paper highlights precisely this point: classic LSTMs struggle to revise stored values, while xLSTM variants using exponential gates perform much better.

# Limited storage capacity: compression to scalars

The classic LSTM cell stores scalar quantities (or vectors of scalars, where each memory “slot” is ultimately a scalar cell). Even when we use a vector \(\mathbf{c}_t\in\mathbb{R}^d\), each dimension is a scalar accumulator that must encode whatever the model needs to remember. For many tasks this compressive representation creates interference: distinct pieces of information that should be stored separately compete for the same low-dimensional resources, and retrieval degrades because the stored components are mixed.

Two intuitions make the limitation clear. First, a scalar accumulator can represent only so many independent degrees of freedom: long sequences containing many distinct items require either a much higher dimensional \(\mathbf{c}\) or a storage mechanism that can separate items more effectively. Second, many realistic tasks (associative retrieval, rare-event memorization, etc.) require storing individual bindings (e.g., key → value associations) so that a later query can select the correct value. Compressing all bindings into scalar sums creates inevitable collisions and reduces the signal-to-noise ratio for retrieval.

The xLSTM paper addresses this by proposing an mLSTM memory that is a full matrix \(\mathbf{C}_t\in\mathbb{R}^{d\times d}\) and is updated with an outer-product (covariance) rule:

\[
\mathbf{C}_t \;=\; f_t\,\mathbf{C}_{t-1} \;+\; i_t\,\mathbf{v}_t\,\mathbf{k}_t^\top.
\]

Here, \(\mathbf{k}_t\) is a key vector and \(\mathbf{v}_t\) a value vector. Storing the outer product \(\mathbf{v}_t\mathbf{k}_t^\top\) creates a richer associative structure: retrieval by a query \(\mathbf{q}\) amounts to multiplying \(\mathbf{C}_t\) with \(\mathbf{q}\), i.e.

\[
\tilde{\mathbf{h}}_t \;=\; \mathbf{C}_t \mathbf{q}_t,
\]

which sums up contributions \(\mathbf{v}_s(\mathbf{k}_s^\top \mathbf{q}_t)\). In words, each stored value \(\mathbf{v}_s\) is weighted at retrieval by how similar the stored key \(\mathbf{k}_s\) is to the query \(\mathbf{q}_t\). This is precisely the associative behavior needed to recall the correct value for a given query, and it represents many more degrees of freedom than scalar cells can.

The covariance outer-product update is also principled: as the paper notes, it corresponds to a classical associative-memory update (Bidirectional Associative Memories, Fast Weights) and is optimal in a certain separability sense for binary retrieval. Practically, the matrix memory increases storage capacity dramatically and reduces interference between stored bindings, which addresses the failure modes that arise when scalar compression is forced to represent many distinct associations.

# Rare Token Prediction: performance degradation on low-frequency tokens

A high-impact consequence of limited storage capacity is systematic degradation on rare-token prediction. The paper demonstrates this empirically: when tokens are partitioned by frequency (e.g., common versus rare tokens on Wikitext-103), classic LSTMs show substantially worse perplexity on rare tokens. Intuitively, rare tokens are presented infrequently during training and often need distinct, localized information (specific contexts or rare associations) to be stored and recalled reliably. When the model’s memory must compress many such rare associations into scalar cells, rare-token signals are easily drowned by more frequent patterns or mixed into shared dimensions in ways that harm later retrieval.

The matrix-memory mLSTM mitigates this problem because it stores bindings in a key/value structure rather than forcing all signals to share the same few scalar channels. The outer-product updates accumulate distinct key–value pairs so that, at query time, the right value can be selected by similarity to the query key. Consequently, the xLSTM variants with matrix memory perform better at predicting rare tokens, as shown in the paper’s rare-token partition experiment. This empirical observation directly ties the storage-capacity limitation of scalar cells to a visible performance gap on low-frequency phenomena in language modeling.

# Lack of parallelizability due to memory mixing

A third structural limitation concerns computation and scaling. Classic LSTM architectures include hidden-to-gate recurrent terms such as \(r_z h_{t-1}\), \(r_i h_{t-1}\), etc.; when multiple scalar memory cells are combined into a vector \(\mathbf{c}_t\in\mathbb{R}^d\), recurrent weight matrices \(\mathbf{R}\in\mathbb{R}^{d\times d}\) are used to mix outputs across cells. These hidden–hidden connections mean that computing the state at time \(t\) requires the exact state at time \(t-1\). The temporal dependence enforces strictly sequential computation: you cannot compute several time steps independently in parallel in a single layer without additional algorithmic machinery.

Sequential processing is a practical bottleneck when training very large models on extremely long sequences: modern hardware and training pipelines obtain much of their speed-up by parallelizing work across tokens (for instance, computing attention across all positions in a Transformer layer in parallel). The recurrence and memory mixing in LSTMs prevent this kind of layer-parallel token processing and hence hinder throughput, distributed training efficiency, and ultimately the ability to scale to very large models and datasets.

The xLSTM paper addresses parallelizability in two ways. The mLSTM variant removes hidden-to-gate recurrent mixing (no hidden-hidden recurrent matrices) and therefore can be reformulated in a parallel-friendly way (the paper notes it is parallelizable similarly to linear attention methods). The sLSTM retains memory mixing and so remains inherently sequential, but the authors developed a specialized CUDA kernel and other optimizations so that, in practice, their sequential sLSTM implementation is not catastrophically slow (it is reported to be typically less than twice as slow as the parallel mLSTM implementation in their experiments). Thus, removing or controlling memory mixing is crucial to get the computational scaling properties required for modern large-scale models.

# Implications for scaling and long-context modeling

Taken together, these three limitations—difficulties in revising stored content, limited scalar-based storage capacity, and enforced sequential computation due to memory mixing—explain why classic LSTMs have struggled to keep pace in large-scale language modeling and other sequence tasks that demand long contexts and massive data.

From an expressivity standpoint, the restriction on how stored items can be overwritten makes certain state-tracking tasks (for example, algorithms that need to update which entity is “current” as new observations arrive) intrinsically hard for vanilla LSTMs. From a memory-capacity perspective, scalar compression leads to performance drops on rare events and on associative tasks that require remembering many distinct bindings across long stretches of input. From an engineering and scaling perspective, sequential dependence reduces parallel throughput, limiting how effectively the model can exploit large GPUs and distributed compute clusters.

These consequences are visible in the experiments reported in the paper: LSTMs lag on nearest-neighbor style tasks and rare-token partitions, and large-scale language modeling at modern LLM scales has been dominated by architectures (Transformers and some State Space Models) that either avoid strict recurrence or restructure it to be parallelizable. The xLSTM proposal is motivated precisely by the desire to remove or ameliorate these bottlenecks while keeping the benefits of LSTM-style gating and memory. Exponential gating provides more decisive, learnable revision mechanisms; matrix memory provides far greater associative capacity; and the option to remove hidden–hidden mixing (in mLSTM) restores layer-level parallelism needed for scaling.

# Why these limitations favored the emergence of Transformers

Historically, LSTMs were the dominant sequence model for many tasks because their gating and additive memory solved the vanishing-gradient problem and allowed reasonably long-range dependencies to be learned. However, as language modeling moved to ever larger training sets and models, two trends made purely recurrent architectures less attractive.

First, parallelizability became crucial. The Transformer architecture replaces recurrence with self-attention, allowing the model to process all tokens in a layer simultaneously. This change unlocks massive wall-clock speedups on modern accelerators and makes it practical to train very large models on huge corpora. Second, self-attention directly computes token-to-token interactions in a way that effectively provides very high-capacity, position-dependent memory: each token can attend to all others and the attention mechanism can represent complex associative patterns without compressing them into a single scalar cell. These computational and representational advantages allowed Transformers to “outpace” LSTMs at scale, as the paper frames it.

The limitations we have described—difficulty revising stored content, limited scalar capacity, and sequential-only computation—are precisely the reasons LSTMs ceded ground. The xLSTM work can be read as an attempt to bring LSTM-style ideas up to date: keep the useful inductive bias of gated, stateful memory (good for state tracking and certain algorithmic behaviors), but augment the gates and memory so the model can revise decisively, store many distinct bindings, and (in the mLSTM case) be computed in parallel. In short, the historical shift toward Transformers was driven by practical and structural issues that the xLSTM modifications explicitly target.

Concluding remark

Understanding these three fundamental failure modes clarifies why the paper introduces exponential gating, matrix-valued memory, and controlled removal of memory mixing. Each modification addresses a specific structural weakness of classic LSTMs: revision of stored content, capacity for associative bindings, and parallelizability for scaling. The experimental examples (nearest-neighbor search, rare-token perplexity partitions, and long-context evaluations) demonstrate how these weaknesses manifest in practice, and why the xLSTM design choices follow naturally from the diagnosis.

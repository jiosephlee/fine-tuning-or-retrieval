# Blocks, Not Just Cells: Building LLMs with xLSTM

Long Short‑Term Memory (LSTM) cells were once the default building block for sequence models. Transformer attention pushed them aside for large language models (LLMs), mainly because attention is parallelizable and scales well with model size. xLSTM asks a simple question: can modernized LSTMs — with better gating and memory — be turned into block primitives and scaled into competitive LLMs? The short answer from the paper: yes — by treating cells as blocks, choosing the right projection order, and combining two new memory variants (sLSTM and mLSTM) inside residual pre‑LayerNorm backbones.

In this post I walk through the design decisions that turn new cells into full LLMs: what lives inside an xLSTM block, why mLSTM prefers pre up‑projection while sLSTM prefers post up‑projection, and the empirical payoffs (15B and 300B token experiments, length extrapolation, throughput).

## The two LSTM upgrades in one sentence

xLSTM extends LSTM along two axes:

- exponential gating (with a normalization and numerical stabilizer) so the model can revise storage decisions and control effective learning rates at each time step; and
- new memory structures: sLSTM keeps a scalar (but mixed) memory per cell; mLSTM upgrades the cell to a matrix memory with a covariance (outer‑product) update for much larger storage capacity.

Both variants are packaged into residual blocks and stacked in a pre‑LayerNorm backbone to build large models.

## Quick look at what changed inside a cell

The sLSTM keeps the familiar additive cell update but replaces sigmoidal input gating with exponential gating and adds a normalizer that records gate strength. Concretely, the forward pass uses

$c_t = f_t c_{t-1} + i_t z_t,\qquad n_t = f_t n_{t-1} + i_t,$

and the hidden output is normalized by the normalizer:

$h_t = o_t \tilde{h}_t,\qquad \tilde{h}_t = c_t / n_t.$

Input gates are exponential, e.g. $i_t = \exp(\tilde{i}_t)$, while forget gates can be $\sigma(\cdot)$ or exponential. Exponential gates can grow large, so xLSTM uses a stabilizer state $m_t$ and rescales the gates (see the paper for the exact stabilizer formulas); these stabilizations do not change the effective outputs or gradients but avoid numerical overflow.

Why this helps: exponential gating plus the normalizer lets the cell accumulate and later re‑weight contributions in a way that supports revising previous storage (the paper demonstrates this on tasks such as nearest neighbor search and formal languages that require state tracking). sLSTM also supports memory mixing via recurrent matrices between hidden states and the cell inputs/gates; heads can be introduced where mixing happens within but not across heads.

mLSTM replaces the scalar cell with a matrix memory $\mathbf{C}_t\in\mathbb{R}^{d\times d}$ and stores key/value pairs with a covariance (outer‑product) update:

$\mathbf{C}_t = f_t\,\mathbf{C}_{t-1} + i_t\,\mathbf{v}_t \mathbf{k}_t^\top.$

A normalizer vector tracks the corresponding key magnitudes,

$\mathbf{n}_t = f_t\,\mathbf{n}_{t-1} + i_t\,\mathbf{k}_t,$

and retrieval is a matrix–vector multiply with a scalar normalization:

$\tilde{\mathbf{h}}_t = \dfrac{\mathbf{C}_t \mathbf{q}_t}{\max\{|\mathbf{n}_t^\top \mathbf{q}_t|,\,1\}},\qquad \mathbf{h}_t = \mathbf{o}_t \odot \tilde{\mathbf{h}}_t.$

Intuition: the covariance update is a classic associative memory (fast weights), optimal under certain assumptions for signal/noise tradeoffs. Because mLSTM drops hidden‑to‑hidden memory mixing, its recurrence can be expressed in a parallel form and implemented efficiently using matrix operations.

## Blocks: pre vs post up‑projection and the role of Cover’s theorem

xLSTM packages these cells inside residual blocks. The paper uses two residual block patterns commonly seen in modern sequence models:

- Post up‑projection (Transformer‑style): non‑linear summary in the original (lower) dimensional space, then a linear up‑projection into a higher dimensional space, a nonlinearity, and a linear down‑projection back.
- Pre up‑projection (SSM‑style): linear up‑projection first, then the non‑linear summary happens in the high‑dimensional space, then a linear down‑projection.

Why this choice matters. Cover’s theorem reminds us that non‑linear embeddings into higher‑dimensional spaces make histories easier to separate linearly. mLSTM’s memory capacity benefits from storing keys/values in a higher‑dimensional embedding (more dimensions gives more capacity for distinct keys with better signal/noise). Therefore, xLSTM places mLSTM inside pre up‑projection blocks so the key/value projections and matrix memory naturally live in the large embedding space. For sLSTM, which relies on scalar memory with memory mixing and gating dynamics in the original space, a post up‑projection block is used instead. In short:

- mLSTM → pre up‑projection (memory operates in the high‑dim space)
- sLSTM → post up‑projection (memory/mixing happens in original space, then up‑project)

These block choices are then embedded into a standard pre‑LayerNorm residual backbone (the same general backbone style used in many contemporary LLMs) and stacked to form deep xLSTM architectures.

## Building LLMs from blocks: hybrid stacks and notation

xLSTM models can be hybrids of the two block types. The paper uses a compact notation xLSTM[$a$:$b$] to denote the ratio of mLSTM to sLSTM blocks. For example, xLSTM[7:1] means that out of every 8 blocks, 7 are mLSTM‑based and 1 is sLSTM‑based (for 48 total blocks, that is 42 mLSTM and 6 sLSTM blocks). This lets designers balance capacity (mLSTM matrix memory) and state‑tracking/mixing (sLSTM recurrent mixing), and the paper finds hybrid stacks effective in practice.

All blocks are wrapped in pre‑LayerNorm residuals and trained in the usual autoregressive next‑token setting.

## Empirical takeaways (what the experiments show)

The experiments in the paper cover synthetic tasks, a 15B‑token training run, and larger 300B experiments. Highlights:

- Synthetic tasks: xLSTM’s exponential gating plus mixing solves formal language/state‑tracking tasks that Transformers and many SSMs cannot; on associative recall (many key–value pairs) the mLSTM variants give strong memory capacity and extrapolation performance.
- 15B tokens (SlimPajama): when trained in the same setting as various baselines (Transformers, SSMs, RWKV variants, linear Transformers, etc.), xLSTM outperforms the competing methods in validation perplexity.
- 300B tokens: scaled experiments (several sizes from 125M to 1.3B) show that xLSTM variants (both xLSTM[1:0] and xLSTM[7:1]) maintain lower validation perplexities across model sizes. Scaling‑law fits indicate similar power‑law exponents but a favorable offset for xLSTM — i.e., extrapolations predict xLSTM remains competitive at larger sizes.
- Length extrapolation: models trained with context 2048 were tested up to 16,384. xLSTM models maintain low perplexity at much longer contexts compared to the baselines (good extrapolation behavior).
- Domain coverage (PALOMA): on 571 language domains, xLSTM[1:0] had lower perplexity than Mamba on 568/571 domains, lower than Llama on 486/571, and lower than RWKV‑4 on 570/571.
- Throughput and decoding: xLSTM has linear computation and constant memory with respect to sequence length (its memory is compressive). In practice, this yields linear generation time scaling (like other recurrent/linear methods) vs quadratic for standard Transformer decoding with KV caching. Measured on 1.3B models, xLSTM achieves higher maximal throughput and can use larger batch sizes because it doesn’t need a quadratic cache.

All of these results are in the paper; code and training settings are available in the authors’ repository.

## Tradeoffs and practical limitations

xLSTM closes some gaps but introduces tradeoffs you should know about:

- Parallelism: mLSTM is fully parallelizable (no hidden‑to‑hidden mixing) and hence scales well on GPUs. sLSTM retains mixing and is inherently sequential; the authors implemented a fast CUDA kernel that makes sLSTM typically under two times slower than their parallel mLSTM implementation, but sLSTM is still not embarrassingly parallel.
- Compute vs memory: mLSTM uses an explicit $\,d\times d\,$ matrix memory and corresponding updates, which increases compute (and FLOPs) compared to scalar cells. The update and retrieval use no additional parameters but are computationally heavy; current kernels are not fully optimized and in the authors’ implementation mLSTM is about 4× slower than FlashAttention in wall‑clock time.
- Numerical and optimization caveats: exponential gating needs stabilizers and careful initialization (forget gate initialization matters). The matrix memory is independent of sequence length, so for extreme context lengths it could saturate; experiments up to 16k did not show clear failures, but very long contexts may stress the memory.
- Engineering: large xLSTM models were trained with pragmatic, not exhaustive, hyperparameter tuning. The paper notes further gains could come from more extensive optimization.

## Bottom line

xLSTM demonstrates a concrete path to “LSTMs as blocks” for LLMs: give LSTM cells more expressive gating (exponential gates + stabilizer), richer memory formats (matrix covariance memory), and then place the right cell into the right residual block (pre vs post up‑projection). That combination lets xLSTM match or beat Transformers and State‑Space Models in perplexity at both 15B and 300B token scales, extrapolate to much longer contexts, and achieve high decoding throughput thanks to constant memory.

If you want to dive into code and the full technical details, the authors provide an implementation at: https://github.com/NX-AI/xlstm.

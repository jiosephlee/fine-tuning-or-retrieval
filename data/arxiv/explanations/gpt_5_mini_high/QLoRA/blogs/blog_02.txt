# NF4, Demystified: The 4‑bit Data Type That Keeps LLM Quality Intact

## Why a new 4‑bit format matters

Quantizing large language model weights to low precision is one of the fastest ways to cut memory and make huge models usable for training and inference. But naive 4‑bit formats (uniform Int4 or tiny floating variants like FP4) usually lose too much information: most weights lie close to zero and a few are large outliers, so uniformly spaced codepoints waste representational power. QLoRA introduces NormalFloat4 (NF4), a 4‑bit data type specifically built for normally distributed, zero‑centered neural network weights. The result: storage at 4 bits per parameter while preserving model quality in finetuning.

This post strips NF4 down to the essentials — what it is, why it works, and how it plugs into QLoRA.

## The core problem: outliers and wasted bins

A common low‑bit quantization approach rescales a tensor into the target range and rounds, e.g. for Int8:

\[
\mathbf{X}^{\text{Int8}} = \text{round}\!\left(\frac{127}{\operatorname{absmax}(\mathbf{X}^{\text{FP32}})}\mathbf{X}^{\text{FP32}}\right)
= \text{round}(c\cdot \mathbf{X}^{\text{FP32}}),
\]

then dequantizes by dividing by the stored scale. If a few values in the block are large outliers, that single scale inflates the effective range and most small values collapse into a few quantization bins. The classic fix is block‑wise quantization (split the tensor into blocks and quantize each block independently), but the choice of the data‑type (what codepoints you allow) still matters a lot at 4 bits.

Quantile (or equal‑probability) quantization is information‑theoretically optimal if you know the data distribution: choose codepoints so that each quantization bin contains the same expected fraction of the data. In practice, exact quantile estimation over each block is costly and approximate algorithms (e.g., SRAM quantiles) can mishandle outliers.

NF4 leverages a simple observation: pretrained neural network weights are typically very close to a zero‑centered normal distribution. That lets you build a small, fixed quantization codebook based on the analytic quantiles of a standard normal distribution — no expensive per‑block quantile search.

## NF4 in one paragraph

NFk (NormalFloat with k bits) is a k‑bit quantization codebook constructed from the quantiles of the standard normal distribution. For k=4 (NF4) you get 16 codepoints chosen so that, under a normal model, each code covers an equal probability mass. To quantize a block you scale that block into the range $[-1,1]$ by its absolute maximum, then replace each value with the nearest NF4 codepoint. Dequantization restores a BF16 (or FP16/BFloat16) tensor for computation. An asymmetric tweak guarantees an exact discrete zero codepoint (important for padding and true zeros).

## How the NFk codebook is built (math)

Let $k$ be the number of bits (for NF4, $k=4$). NFk targets an equal expected number of values per bin under $N(0,1)$. One way to place representative codepoints is to take midpoints of the quantile intervals of the standard normal:

\[
q_i \;=\; \frac{1}{2}\!\left(Q\!\left(\frac{i}{2^k+1}\right) + Q\!\left(\frac{i+1}{2^k+1}\right)\right),
\]

where $Q(\cdot)$ is the quantile function (inverse CDF) of $N(0,1)$ and $i=0,\dots,2^k-1$. Those $q_i$ are then normalized into the fixed range $[-1,1]$ so they form the NFk codebook. At quantization time a block of weights is scaled into $[-1,1]$ via an absolute‑max rescaling (one scale constant per block) and each scaled value is mapped to the nearest $q_i$.

This construction gives NFk the information‑theoretic property of equal expected occupancy across bins under the normal model: most codepoints lie near zero (where the density is highest), and the sparse tail bins handle outliers.

## Handling zero exactly: the asymmetric tweak

A symmetric equal‑probability construction does not necessarily include an exact discrete zero, which matters for perfectly zero entries (e.g., padding) and avoids introducing tiny rounding errors for zeros. NFk fixes this by splitting the code allocation between negative and positive sides asymmetrically: estimate quantiles for the negative half with $2^{k-1}$ bins and for the positive half with $2^{k-1}+1$ bins, then unify and remove the duplicated zero so that one code maps exactly to zero while still using all $2^k$ codepoints. For NF4 this ensures a discrete zero code and full use of the 16 available codes.

## Block‑wise scaling and practical blocksize choices

NF4 is applied block‑wise (flatten the weight tensor and quantize contiguous blocks). Smaller blocks reduce the impact of local outliers but increase per‑block scale overhead. In QLoRA the authors use a blocksize of 64 for the model weights as a practical balance: good quantization fidelity while keeping the extra memory for block scales manageable. (Quantization constants themselves can be compressed further — see Double Quantization below.)

## Where NF4 fits in QLoRA (storage vs compute)

QLoRA stores the pretrained model weights in NF4 (4‑bit) on disk/GPU memory. At runtime the NF4 codes are dequantized to a 16‑bit computation format (BFloat16) for the forward and backward pass. LoRA adapters remain full precision (BF16) and are the only parameters updated during finetuning; gradients are backpropagated through the dequantized weights. The QLoRA forward pass for a linear layer with one LoRA adapter can be written as:

\[
\mathbf{Y}^{\text{BF16}} = \mathbf{X}^{\text{BF16}}\,\text{doubleDequant}(c_1^{\text{FP32}}, c_2^{\text{k-bit}}, \mathbf{W}^{\text{NF4}}) \;+\; \mathbf{X}^{\text{BF16}}\mathbf{L}_1^{\text{BF16}}\mathbf{L}_2^{\text{BF16}},
\]

where the stored NF4 codes for $\mathbf{W}$ plus their block scales are dequantized back to BF16 for matrix multiplies.

## Double Quantization (briefly) and memory tradeoffs

Blockwise quantization requires storing a scale per block; at small blocksize that adds nontrivial overhead (e.g., 32‑bit scales with blocksize 64 cost roughly 0.5 bits/parameter). QLoRA introduces Double Quantization: quantize the per‑block scales themselves (the quantization constants) with an 8‑bit float grid and a larger blocksize (256), which reduces the scale overhead dramatically (paper reports a reduction of about 0.373 bits/parameter on average). NF4 pairs well with Double Quantization: NF4 handles the weight distribution efficiently, while Double Quantization keeps auxiliary overhead small.

## Why NF4 outperforms FP4 and Int4

- Matching the data distribution: NF4 codepoints concentrate where weights actually live (near zero) instead of giving equal spacing (Int4) or tiny floating layout that isn’t tuned to the distribution (FP4).
- Equal‑probability bins minimize the expected quantization distortion under the normal model.
- Exact zero handling avoids tiny rounding artifacts for zeros (useful for padding).
- Avoids expensive per‑block quantile estimation because the normal quantiles are analytic.

Empirically, the QLoRA paper shows NF4 yields markedly better post‑quantization perplexity and zero‑shot accuracy than FP4 and Int4 across multiple architectures and sizes, and NF4 combined with Double Quantization gives the memory savings with no measurable loss in finetuning quality compared to 16‑bit baselines.

## Practical takeaways

- NF4 is a practical, distribution‑aware 4‑bit scheme built for the common case of zero‑centered, approximately normal neural weights.
- Use NF4 with block‑wise scaling (paper uses blocksize 64 for weights) so outliers are contained locally.
- Keep computation in BF16 (or similar) — NF4 is a storage format; dequantize to 16 bits for matmuls and gradients.
- Combine NF4 with Double Quantization for the block scales to avoid scale overhead.
- The asymmetric zero codepoint is important: it preserves exact zeros and uses all 16 codepoints efficiently.

## Bottom line

NF4 is a compact, distribution‑aware 4‑bit codebook that aligns quantization bins to where pretrained weights actually concentrate. That simple idea — build equal‑probability codepoints from the standard normal, add a discrete zero codepoint, quantize blockwise, and dequantize to BF16 for compute — lets QLoRA store massive models at 4 bits without the quality losses that plagued earlier 4‑bit methods. The result: large‑scale finetuning and inference that are far more memory efficient, yet maintain the performance of higher‑precision baselines. For anyone building quantized LLM systems, NF4 is the first 4‑bit format to reach for. 

For exact NF4 codepoint values and implementation details, see the QLoRA paper appendices and the released code and CUDA kernels.

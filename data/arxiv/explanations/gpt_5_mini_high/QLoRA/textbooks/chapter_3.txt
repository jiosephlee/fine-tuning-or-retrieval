\title{A Textbook about the Paper: "QLoRA: Efficient Finetuning of Quantized LLMs"}

Chapter 3: Memory-Efficient Quantization in QLoRA: NF4 and Double Quantization

# Quantile quantization as an information-theoretic optimum
Quantization converts a high-precision continuous tensor (e.g., FP32 weights) into a small set of discrete levels (a low-bit data type). A simple, widely used approach is linear range quantization, where the tensor is rescaled into the target numeric range and then rounded. For instance, converting an FP32 tensor $\mathbf{X}^{\text{FP32}}$ into Int8 with range $[-127,127]$ can be written as
$\mathbf{X}^{\text{Int8}} = \text{round}\!\left(\tfrac{127}{\text{absmax}(\mathbf{X}^{\text{FP32}})}\mathbf{X}^{\text{FP32}}\right) = \text{round}\!\big(c\cdot\mathbf{X}^{\text{FP32}}\big)$,
with the scalar $c$ called the quantization constant or scale. This linear approach is simple and computationally cheap, but it is not optimal if the data distribution is far from uniform across the representable range.

Quantile quantization takes a different, distribution-aware viewpoint: instead of placing quantization levels uniformly in value-space, it places them so that each discrete bin receives approximately the same probability mass under the data distribution. For a given probability distribution of values, choosing bin boundaries at the quantiles equalizes the expected occupancy of all bins. Because no bin is wasted and all codes are used with equal expected frequency, quantile quantization is described in the paper as an information-theoretic optimum: for a fixed number of discrete levels, it maximizes effective usage of representational capacity with respect to the empirical distribution of the input. In practice, that means typical (high-density) regions of the distribution get many closely spaced levels while tails get fewer, which reduces average quantization error compared to uniform-placement schemes for non-uniform data.

# Limitations of approximate quantiles and outlier sensitivity
Quantile quantization requires estimating quantiles of the tensor. For very large tensors this estimation can be computationally expensive, and practical implementations typically rely on approximate quantile algorithms (the paper references techniques such as SRAM quantiles). Those approximations introduce two practical problems.

First, the approximate quantile computation itself costs time and code complexity compared to simple linear rescaling. Second, and more importantly for model accuracy, approximate quantiles and quantile-based bin-placement can be sensitive to outliers if the approximation is imperfect. Outliers can distort the estimated quantiles and therefore the placement of bins, causing poor utilization of some bins and large errors on values that matter. Because some outliers in neural network weights capture important features (e.g., rare but large-valued connections), approximation-induced placement errors can be especially harmful to downstream model performance. This tradeoff motivates finding a way to get the benefits of quantile-based bin placement without paying the high cost of per-tensor quantile estimation.

# Normality of pretrained weights enables a fixed quantizer
The key empirical observation that QLoRA exploits is that pretrained neural network weights are approximately zero-centered and normally distributed (see the paper's appendix for normality analysis). When weights follow a distribution that is fixed up to a scalar factor (a location-zero normal with varying standard deviation $\sigma$), we no longer need to estimate quantiles separately for every block: we can precompute the optimal quantile boundaries for that family of distributions (the standard normal) and then adapt each block only by a simple scalar rescaling.

Concretely, if every block of weights is distributed like $N(0,\sigma^2)$ for some block-specific $\sigma$, then the (theoretical) quantiles are known analytically from the standard normal $N(0,1)$ and differ across blocks only by a scale factor. That means we can design a single, fixed discrete data type whose level values are the midpoints of the appropriate standard-normal quantiles; when a particular block is to be quantized, we rescale the block to match the data-type range and then map to the precomputed discrete levels. This avoids expensive per-block quantile estimation and reduces approximation error for outliers because the level placement directly reflects the shape of the normal distribution.

# Constructing NF4 from standard normal quantiles
The NormalFloat data type (denoted NFk for $k$ bits; NF4 is $k=4$) is built from the quantiles of the standard normal distribution. The construction proceeds in three conceptual steps, as described in the paper:

1. Compute theoretical quantile midpoints for the standard normal. For $k$ bits there are $2^k$ representable values; the midpoint values $q_i$ can be taken between quantile boundaries. A convenient definition of the $i$-th level is
\[
q_i \;=\; \tfrac{1}{2}\!\left(Q\!\left(\tfrac{i}{2^k+1}\right) \;+\; Q\!\left(\tfrac{i+1}{2^k+1}\right)\right),
\]
where $Q(\cdot)$ is the quantile function (inverse CDF) of the standard normal $N(0,1)$. This places the discrete levels at the midpoints of equal-probability intervals under $N(0,1)$.

2. Normalize the data type values into the target numeric range, chosen in the paper as $[-1,1]$. This fixes a canonical mapping from the standard-normal midpoints $q_i$ to numerical codes in $[-1,1]$ that the quantizer will use.

3. Quantize an input weight block by first scaling the block into $[-1,1]$ (equivalently, rescaling its standard deviation $\sigma$ to match the data type's implicit scale), and then replacing each scaled value by the nearest NFk level $q_i$.

Step (3) is, as the paper points out, equivalent to matching the block's standard deviation to the data type's standard deviation: because the NF levels were derived for $N(0,1)$, scaling a block's values into the same range aligns their distribution with the NFk levels so that the quantization bins are matched to the normalized weight density.

# Ensuring a true zero via asymmetric bin design
A practical issue arises when a symmetric quantile-based design does not produce an exact representable zero value. Exact zero is important because tensors often contain explicit zeros (for padding or sparsity) and representing zero exactly prevents any error for those positions.

To guarantee a discrete zero code while still using all $2^k$ levels, NFk uses an asymmetric construction. The paper’s procedure is:

- Compute quantile midpoints for the negative side with $2^{k-1}$ values and for the positive side with $2^{k-1}+1$ values (so the positive side has one extra level).
- Merge the two sets of midpoints and remove the duplicate zero that appears in both sets.

That yields exactly $2^k$ distinct discrete levels and ensures that one of those levels is exactly zero. The result preserves the equal-occupancy principle (bins have equal expected counts under the symmetric normal distribution) while also giving a discrete representation for zeros that avoids unnecessary quantization error on genuinely zero inputs.

# Scaling to the data type range and to the weight range
Quantization always involves a mapping between value ranges. In linear quantization the mapping is typically done by an absolute-max scale per block: given a block $\mathbf{X}^{\text{FP32}}$, compute $\text{absmax}(\mathbf{X}^{\text{FP32}})$ and use
$\mathbf{X}^{\text{quant}} = \text{round}\!\big(c\cdot\mathbf{X}^{\text{FP32}}\big)$
with $c$ chosen so that the largest-magnitude element maps to the largest code. For NFk the idea is analogous but the target discrete levels are not uniformly spaced. The practical recipe is:

- For each block, compute a scalar that rescales the block into the canonical NFk range $[-1,1]$. This can be done by absolute-maximum rescaling or equivalently by rescaling the block's standard deviation to match the NFk distribution scale.
- Replace each rescaled element by the nearest NFk discrete level $q_i$.

Because NFk levels were constructed from the standard-normal quantiles, matching the block scale to the NFk range aligns the block’s empirical density with the NFk bins. In QLoRA the storage data type is NF4 (4-bit), while the computation data type used for matrix multiplication is higher precision (e.g., BF16); the stored NF4 codes are dequantized to BF16 at use time.

# Why NF4 outperforms FP4 and Int4 in practice
NF4 (4-bit NormalFloat) is specifically designed to match the empirical shape of pretrained neural network weight distributions. Intuitively, it places many quantization levels where most weights lie (the center of the normal) and fewer levels in the tails. This contrasts with Int4 (uniform integer levels) or naive 4-bit FP formats that either use uniform placement or adopt small float exponent ranges that do not match the particular shape of weight distributions.

Because NF4 equalizes expected bin occupancy for a normal distribution, it reduces average quantization error compared to uniform-level schemes when weights are indeed approximately normal. The paper shows empirically that NF4 yields significantly better post-quantization perplexity and zero-shot accuracy across several model families (OPT, LLaMA, BLOOM, Pythia) and sizes than FP4 and Int4. In addition, NF4 includes a discrete zero by construction, removing quantization error for exact-zero values (important for padding and sparse activations).

Finally, NF4 is compatible with blockwise rescaling: each block can be independently rescaled to align its empirical $\sigma$ with the NF4 template, so NF4 combines distribution-aware level placement with local adaptability to per-block scale differences. All of these factors contribute to NF4's superior empirical performance in QLoRA.

# Overhead of per-block scales and why it matters
Block-wise quantization is essential to control the influence of outliers: smaller blocks allow each block's scale to be tuned to its local range, reducing distortion from a few large-magnitude entries. But block-wise quantization introduces a storage overhead: each block requires a per-block quantization constant (scale) that must be stored in higher precision (typically FP32) alongside the low-bit codes.

If the block size is $B$ elements and each scale is stored in 32-bit floating point, the average overhead in bits per parameter is $\tfrac{32}{B}$. For a blocksize $B=64$ this yields an overhead of
\[
\frac{32}{64} = 0.5 \quad\text{bits per parameter},
\]
which is significant for very large models: for a $65$B-parameter model that extra $0.5$ bits per parameter is roughly several gigabytes of memory. Thus there is a practical tradeoff: small blocks improve quantization fidelity but inflate memory via many high-precision scale values; large blocks save memory but increase quantization error because each scale must accommodate a larger range (and more outliers). QLoRA addresses this tension with a second compression layer on the per-block scales (Double Quantization).

# Double Quantization: two-level scale compression with FP8
Double Quantization (DQ) reduces the memory cost of storing per-block scales by quantizing those scales themselves. The idea is hierarchical: the original weight tensor is quantized into low-bit codes with per-block scales $c_2^{\text{FP32}}$; then the vector of these per-block scales is treated as another tensor that we quantize a second time into a lower-precision representation $c_2^{\text{k-bit}}$ (the paper uses FP8) together with a second-level scale $c_1^{\text{FP32}}$.

Operationally, dequantization is done in two steps (the function names follow the paper's notation):
\[
\text{doubleDequant}(c_1^{\text{FP32}}, c_2^{\text{k-bit}}, \mathbf{W}^{\text{k-bit}})
= \text{dequant}\big(\text{dequant}(c_1^{\text{FP32}}, c_2^{\text{k-bit}}), \mathbf{W}^{\text{k-bit}}\big)
= \mathbf{W}^{\text{BF16}}.
\]
First we dequantize the compressed scale codes $c_2^{\text{k-bit}}$ using $c_1^{\text{FP32}}$ to reconstruct the per-block scales in FP32, then we dequantize the weight codes $\mathbf{W}^{\text{k-bit}}$ using those reconstructed scales to obtain the full-precision weights for computation. In QLoRA the weight storage data type is NF4 (the first-level low-bit codes) and the compressed scales are stored as FP8 codes (second-level), with $c_1^{\text{FP32}}$ kept at higher precision for final reconstruction.

The paper reports that quantizing the first-level scales to an 8-bit float (FP8) with an appropriately chosen second-level block size does not empirically degrade downstream performance, so DQ is an effective way to trade a small additional dequantization step for a large memory saving.

# Centering positive scales before quantization for symmetry
An implementation detail matters: the per-block scales $c_2^{\text{FP32}}$ are inherently positive numbers (they are absolute scaling factors). Many quantization schemes for small precisions (including symmetric schemes) are simpler and more efficient when the values are centered around zero so that positive and negative representational bins are used symmetrically.

To exploit symmetric quantization when compressing $c_2^{\text{FP32}}$, QLoRA subtracts the mean of the scales before applying the second-level quantization. This centers the distribution of scale residuals around zero and allows a symmetric low-bit format (e.g., an FP8 variant that treats positive and negative deviations symmetrically) to better represent the variability among block scales. After dequantization, the mean is added back so the original positive scales are recovered in FP32 (up to the quantization error introduced by the second level). Centering reduces the dynamic range that the FP8 layer needs to represent and improves effective fidelity of the second-level quantization.

# Block sizes used in practice: 64 for weights, 256 for scales
QLoRA’s practical design choices reflect the tradeoffs discussed above. For quantizing weight tensors, a relatively small blocksize of $B_{\text{weights}}=64$ is used. This small block size gives good local adaptability and reduces quantization error caused by local outliers. For the second-level quantization of scales, a larger secondary blocksize of $B_{\text{scales}}=256$ is selected; because there are far fewer scale values than weight values overall, grouping them into larger blocks before compressing the scales allows the second-level scheme to amortize one FP32 second-level scale over many first-level scales and thus conserves memory. The combination—small blocks for weights, larger blocks for the compressed scales—balances precision and overall storage cost.

# Memory savings from Double Quantization of about 0.373 bits per parameter
Because Double Quantization compresses the per-block scales, it reduces the per-parameter overhead substantially. Using the paper’s numbers for the common choices $B_{\text{weights}}=64$ and $B_{\text{scales}}=256$:

- Without Double Quantization, storing one FP32 scale per weight block yields an average storage overhead of
\[
\frac{32}{64} = 0.5 \quad\text{bits per parameter}.
\]

- With Double Quantization, the overhead becomes the storage cost of the second-level FP8 codes per weight element plus the amortized cost of the top-level FP32 scales. Concretely:
\[
\text{overhead}_{\text{DQ}} \;=\; \frac{8}{64} \;+\; \frac{32}{64\cdot 256}
\;=\; 0.125 \;+\; 0.001953125 \;\approx\; 0.127 \;\text{bits per parameter}.
\]

- The reduction is therefore
\[
0.5 - 0.127 = 0.373\;\text{bits per parameter}.
\]

To translate this into wall-clock memory for a large model, multiply by the parameter count. For a $65$B-parameter model the saved bits are approximately
\[
0.373 \times 65\times 10^9 \approx 2.4248\times 10^{10}\ \text{bits},
\]
which divided by $8$ gives about $3.03\times 10^9$ bytes, i.e., roughly $3.0$ GB. The paper reports this same order-of-magnitude saving (about 0.37 bits per parameter and roughly 3 GB for a 65B model). That saving is material at large scale and helps make finetuning 65B-parameter models on a single 48GB GPU feasible when combined with other QLoRA techniques (NF4 storage, dequantization to BF16 for computation, and paged optimizers).

Concluding remarks
NF4 and Double Quantization together form the core quantization innovations in QLoRA. NF4 gives a compact, distribution-aware 4-bit representation tailored to the near-normal distribution of pretrained weights, while Double Quantization compresses the inevitable per-block scaling overhead in a way that keeps fidelity high. Their combination preserves the accuracy of higher-precision finetuning while cutting the memory footprint enough to enable finetuning very large models on a single GPU, as demonstrated in the QLoRA paper.

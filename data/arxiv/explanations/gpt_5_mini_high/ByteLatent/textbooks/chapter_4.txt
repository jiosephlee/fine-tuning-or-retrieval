\title{A Textbook about the Paper: "Byte Latent Transformer: Patches Scale Better Than Tokens"}

Chapter 4: The BLT Architecture

# High-level pipeline: Local Encoder → Global Latent Transformer → Local Decoder

The Byte Latent Transformer (BLT) organizes computation into three cooperating modules: a Local Encoder that compresses raw bytes into patch-level latents, a Global Latent Transformer that models the sequence of those patch latents autoregressively, and a Local Decoder that expands patch-level outputs back into raw bytes. This three-part decomposition is the defining structural motif of BLT and is designed to match the statistical granularity at which expensive transformer computation should be spent: light-weight, byte-level processing is used where it is cheap and local; the heavy, high-capacity global transformer is invoked only at the coarser patch level.

Concretely, let the input be a byte sequence $\{b_i\}_{i=1}^n$. A patching function groups bytes into $m$ patches $\{p_j\}_{j=1}^m$; the Local Encoder $\mathcal{E}$ maps the bytes within each patch to a patch representation $p_j$. The Global Transformer $\mathcal{G}$ takes the sequence of patch representations and produces output patch representations $o_j$ autoregressively. The Local Decoder $\mathcal{D}$ then consumes the $o_j$ (and the byte-level context) to predict the output bytes $\{y_i\}$. In notation:
- Encoder: $\{b_i\} \xrightarrow{\mathcal{E}} \{p_j\}$,
- Global: $\{p_j\} \xrightarrow{\mathcal{G}} \{o_j\}$,
- Decoder: $\{o_j\}, \{b_{<i}\} \xrightarrow{\mathcal{D}} y_i$.

The encoder and decoder are intentionally lightweight (few layers: $l_{\mathcal{E}}, l_{\mathcal{D}} \ll l_{\mathcal{G}}$) so that the majority of FLOPs is concentrated in the global model. The Local Encoder and Decoder operate at byte resolution (they run on each byte within their local windows), while the Global Transformer operates at patch resolution (it runs once per patch). This design lets BLT control when the expensive global computation happens by selecting how bytes are grouped into patches.

# Global latent transformer: block-causal attention over patches; prioritizing compute where needed

The Global Latent Transformer $\mathcal{G}$ is an autoregressive transformer that consumes the sequence of patch representations and produces updated patch-level outputs. If the encoder produces latent patch inputs $\{p_j\}_{j=1}^m$, then the global model computes
\[
\{o_j\}_{j=1}^m = \mathcal{G}(\{p_j\}_{j=1}^m),
\]
where $\mathcal{G}$ has $l_{\mathcal{G}}$ layers and internal hidden dimension $h_{\mathcal{G}}$.

Crucially, $\mathcal{G}$ uses a block-causal attention mask: when computing the representation for patch $j$ the attention is restricted to patches up to and including $j$ within the same document. That is, patch $j$ cannot attend to future patches $>j$. This block-causal masking preserves autoregressivity at the patch level while allowing each global step to aggregate information from the entire past of patches. Because the global transformer runs only once per patch, the total number of expensive feed-forward and attention operations is proportional to the number of patches rather than the number of bytes.

By coupling dynamic patching (which chooses where patches begin and end) with a powerful $\mathcal{G}$, BLT concentrates global compute on positions that are informationally dense. In effect, the global transformer is a “when-needed” expense: it is invoked at a rate determined by the patching function so that more model capacity is applied to high-uncertainty regions of the byte stream and less to low-uncertainty (predictable) spans.

# Local encoder: byte embeddings and hash n-gram augmentation for context

The Local Encoder $\mathcal{E}$ is responsible for producing patch-level inputs for $\mathcal{G}$. It is a lightweight transformer stack (few layers) that operates on byte embeddings and augments them with hashed n-gram features to capture local context efficiently.

Each raw byte $b_i$ is embedded via a learnable lookup into a vector $x_i\in\mathbb{R}^{h_{\mathcal{E}}}$ using an embedding matrix of shape $\mathbb{R}^{256\times h_{\mathcal{E}}}$. These per-byte embeddings are augmented by hash-based n-gram embeddings (described in the next section) to produce an initial byte representation $e_i$. The encoder then applies a sequence of alternating transformer layers and cross-attention pooling layers: the transformer layers use a local block-causal attention mask so that each byte attends to a fixed window of $w_{\mathcal{E}}$ preceding bytes (this window can cross patch boundaries but not document boundaries). After one or more transformer updates, a cross-attention block pools the byte-level representations that belong to each patch into a patch representation.

The encoder’s cross-attention block is inserted after each transformer layer (i.e., it repeatedly pools the evolving byte-level features into updated patch latents). For the first cross-attention layer the initial queries for each patch are produced by a simple pooling function over the bytes in that patch (the implementation uses max-pooling to initialize those queries). Across encoder layers the pooled queries are refined via cross-attention with the current byte-level keys/values. The encoder outputs the final set of patch inputs $p_j$ to the global transformer.

# Hash n-gram embeddings (n=3..8): hashing, table sizes, and normalization

To give the encoder richer local context without blowing up the parameter count, BLT augments each byte embedding with hash n-gram embeddings for n in the set $\{3,4,5,6,7,8\}$. For a given position $i$ and n-gram length $n$ define the byte n-gram
\[
g_{i,n} = \{b_{i-n+1}, \dots, b_i\},
\]
omitting sizes $n$ when $i<n$.

Each n-gram is mapped to a small index via a rolling polynomial hash (RollPolyHash) and then reduced modulo the size of the hash table for that $n$:
\[
\text{Hash}(g_{i,n}) = \text{RollPolyHash}(g_{i,n}) \bmod |E_n^{\text{hash}}|,
\]
where $E_n^{\text{hash}}$ is the embedding table for n-grams of length $n$. The hash embedding lookup yields a vector $E_n^{\text{hash}}(\text{Hash}(g_{i,n}))$ which is added to the byte embedding.

Putting the pieces together, the augmented byte embedding used as encoder input is
\[
e_i = x_i + \sum_{n=3}^{8} E_n^{\text{hash}}(\text{Hash}(g_{i,n})),
\]
and $e_i$ is normalized by dividing by the number of n-gram sizes plus one (that is, by the count of terms contributing to $e_i$). This normalization keeps the scale consistent whether all n-gram sizes exist for a position or fewer do (near the beginning of a sequence).

In practice BLT uses a single hash function per n-gram and a fixed hash-table size (the paper’s experiments used 500{,}000 hashes in many runs), but the design leaves table size as a tunable hyperparameter. Hash n-grams provide an efficient, parameter-cheap way to expose local multi-byte patterns to the encoder (morphological and orthographic information) without requiring a huge explicit vocabulary.

# Encoder cross-attention: pooling bytes into patch representations with patch-specific masks

The encoder’s cross-attention module is Perceiver-like in structure but adapted to variable-size, data-dependent patches. Instead of a fixed set of latents, each patch corresponds to a latent query that pools the bytes belonging to that patch. Importantly, each patch query only attends to the keys/values formed by the bytes inside that patch; that is, the cross-attention uses a patch-specific mask that restricts attention to the local bytes for that patch.

Formally, initialize patch queries by applying a pooling function $f_{\text{bytes}}$ (e.g., max-pooling) over the encoder byte representations for the bytes in patch $p_j$ and projecting with a (multi-head) linear mapping $\mathcal{E}_C$:
\[
P_{0,j} = \mathcal{E}_C\big(f_{\text{bytes}}(p_j)\big).
\]
Here $\mathcal{E}_C$ projects the pooled byte summary into the multi-head query space (the paper denotes its shape as $\mathcal{E}_C\in\mathbb{R}^{h_{\mathcal{E}}\times(h_{\mathcal{E}}\times U_{\mathcal{E}})}$, where $U_{\mathcal{E}}$ is the number of cross-attention heads used in the encoder).

The cross-attention update for patch latents at layer $l$ is
\[
P_l = P_{l-1} + W_o\Big(\text{softmax}\!\big(\tfrac{QK^\top}{\sqrt{d_k}}\big)\,V\Big),
\]
with
\[
Q_j = W_q(P_{l-1,j}),\qquad K_i = W_k(h_{l-1,i}),\qquad V_i = W_v(h_{l-1,i}),
\]
where $h_{l-1,i}$ are the byte-level hidden states from the encoder’s transformer at the previous layer. The keys and values $K_i,V_i$ are restricted in the attention computation so that the $j$-th query attends only to the bytes that belong to patch $p_j$.

Because the global transformer’s patch-dimensionality $h_{\mathcal{G}}$ is typically larger than the byte-level hidden size $h_{\mathcal{E}}$, BLT maintains the patch latents $P_l$ internally as multiple heads of dimension $h_{\mathcal{E}}$ during cross-attention and later concatenates (or projects) them to form the full $h_{\mathcal{G}}$-dimensional patch representations passed to $\mathcal{G}$. The cross-attention block uses pre-LayerNorm on queries, keys, and values, includes a residual connection around the attention, and — by design — does not add learned positional embeddings inside the cross-attention module.

# Local decoder: cross-attention from bytes to patch states, then byte-level transformer decoding

The Local Decoder $\mathcal{D}$ maps the patch-level outputs of the global transformer back to a sequence of bytes. Like the encoder, it is a lightweight transformer stack that interleaves cross-attention and transformer layers, but with the roles of queries and key/values reversed.

The decoder initializes its byte-level queries from the encoder’s final byte representations:
\[
D_0 = h_{l_{\mathcal{E}}}.
\]
Before each decoder transformer layer, a cross-attention block lets each byte query attend to the patch representations $o_j$ produced by the global transformer. The decoder cross-attention update has the form
\[
B_l = D_{l-1} + W_o\Big(\text{softmax}\!\big(\tfrac{QK^\top}{\sqrt{d_k}}\big)\,V\Big),
\]
with
\[
Q_i = W_q(d_{l-1,i}),\qquad K_j = W_k\big(\mathcal{D}_C(o_j)\big),\qquad V_j = W_v\big(\mathcal{D}_C(o_j)\big),
\]
where $\mathcal{D}_C$ is the linear transform (and split) applied to final patch representations to form key/value vectors for the decoder cross-attention. The output $B_l$ has shape compatible with the decoder hidden size (the paper denotes $B\in\mathbb{R}^{h_{\mathcal{D}}\times n_b}$ for $n_b$ output bytes), and the next decoder representations are computed by applying a standard decoder transformer layer:
\[
D_l = \text{Decoder-Transformer-Layer}_l(B_l).
\]

Operationally, the decoder cross-attention is applied before the local decoder’s transformer layer so that the transformer operates on byte representations already conditioned on patch-level context. The decoder transformer applies local autoregressive masking at the byte level to ensure correct causal decoding of bytes. Finally, the decoder projects the top-layer byte representations to a 256-way output (one logit per possible byte) and computes the byte-level cross-entropy loss during training.

# Attention masks and positional encodings: RoPE in self-attention; none in cross-attention

BLT uses three forms of masking/positioning adapted to where each operation runs:

- Self-attention in the byte-level Local Encoder and Local Decoder uses a local block-causal attention mask: each byte may attend to a fixed window of $w_{\mathcal{E}}$ preceding bytes. This enables efficient local modeling while allowing attention to cross patch boundaries within the local window.

- The Global Latent Transformer uses a block-causal attention mask at patch granularity so that each patch representation attends only to earlier patches (and itself) within the same document, preserving autoregressivity at the coarse level.

- Cross-attention modules use dynamic, patch-specific masks: the encoder’s cross-attention for patch $j$ can only read keys/values corresponding to bytes that make up patch $p_j$; the decoder’s cross-attention uses patch outputs as keys/values and byte positions as queries.

For positional encoding, BLT follows a consistent choice: Rotary Positional Embeddings (RoPE) with $\theta=500000$ are applied in self-attention layers only (both in local and global transformers). Cross-attention modules explicitly use no learned positional embeddings: queries and keys/values in cross-attention are normalized and projected, but positional signals are not added inside the cross-attention block. The cross-attention blocks use pre-LayerNorm on queries, keys, and values and employ residual connections around attention, matching the rest of the transformer design.

From an implementation perspective (reported in the paper), fixed, standard attention masks (local windows, block-causal masks) can be accelerated with FlashAttention, while the dynamic, patch-dependent cross-attention uses FlexAttention to handle fused and mask-varying patterns efficiently.

# Dimensions and heads: h_E and h_G, multi-head splits (k) and residual/normalization choices

BLT uses three characteristic hidden dimensions: $h_{\mathcal{E}}$ for the Local Encoder/Decoder byte-level representations, $h_{\mathcal{G}}$ for the Global Latent Transformer patch-level representations, and $h_{\mathcal{D}}$ for decoder internals (often $h_{\mathcal{D}}\approx h_{\mathcal{E}}$). Typically $h_{\mathcal{E}} \ll h_{\mathcal{G}}$ because the global transformer is the high-capacity module.

A practical implementation detail arises because cross-attention projects between these differently sized spaces: during encoder cross-attention BLT maintains patch latents as multiple sub-vectors (or “splits”) each of size $h_{\mathcal{E}}$ and then concatenates them to obtain an $h_{\mathcal{G}}$-sized vector. The number of such splits is denoted $k$, so that roughly $h_{\mathcal{G}} = k \cdot h_{\mathcal{E}}$ (or the equivalent via projection). In the paper’s illustration $k=2$ is used as an example. Working with multiple smaller heads for cross-attention makes the byte-to-patch and patch-to-byte projections compatible with the byte-level dimensions used inside the local models.

Across attention blocks BLT uses multi-headed attention with the usual per-head key dimension $d_k$, projected by $W_q,W_k,W_v$ and recombined by $W_o$. Transformer layers use SwiGLU activations in feed-forward layers and RMSNorm for normalization. Cross-attention and self-attention blocks are wrapped with pre-LayerNorm and residual connections, preserving the stability properties common to large modern transformer designs.

# Compute gating: when and how the global model is invoked at patch boundaries during training and generation

The Global Latent Transformer is invoked once per patch. Which byte positions start a new patch (and therefore trigger a global step) is determined by the patching function $f_p$. During training, patch boundaries are identified in a lightweight preprocessing step (for entropy-based patching, using entropies produced by a small byte LM); during inference and generation those boundaries must be decided incrementally. Concretely, a patching scheme used for generation must satisfy the incremental property
\[
f_p(\mathbf{x}_{<i}) = f_p(\mathbf{x})_{<i},
\]
so that the decision of whether position $i$ begins a new patch can be made without access to future bytes. Space-based and entropy-based patchers are incremental in their setup; standard BPE tokenization is not incremental by default, which is why BLT treats tokens and patches differently.

At runtime (training or inference) the pipeline gated by patch boundaries looks like this: bytes flow through the Local Encoder which pools and emits a patch representation when the patching function indicates a patch boundary; that patch representation is then input to the Global Transformer (which produces or extends the autoregressive history at the patch level); the Local Decoder attends to available patch outputs and its own byte-level history to emit bytes. Because the global transformer is the dominant FLOP consumer, reducing the number of times it is invoked (by increasing average patch size when appropriate) reduces inference cost. Conversely, when more fine-grained modeling is needed, smaller patches cause more frequent global steps and concentrate compute on harder regions.

Implementation-wise, BLT packs batches of patches for the latent transformer in training to avoid padding waste inside the expensive $\mathcal{G}$ computation. When using dynamic patching the bytes-to-patches ratio varies across examples, so the training loader ensures that batches of patches are packed to keep the latent transformer’s work dense; additionally, byte sequences are padded/truncated to bounded lengths to avoid pathological memory spikes from unusually large patches.

# Putting the pieces together: an end-to-end view

An end-to-end forward pass in BLT starts from raw bytes and proceeds as:

1. Segment the byte sequence into patches using the chosen patcher $f_p$ (space-based, strided, or entropy-based).

2. Look up per-byte embeddings $x_i$ and compute hash n-gram augmentations to form normalized byte inputs $e_i$.

3. Run the Local Encoder: apply a small stack of byte-level transformer layers (local block-causal attention) interleaved with cross-attention pooling that produces patch latents $p_j$. The encoder produces the inputs to the global model.

4. Run the Global Latent Transformer autoregressively over the patch latents $\{p_j\}$ with block-causal attention to obtain outputs $\{o_j\}$; this is the core high-capacity sequence model.

5. Run the Local Decoder: for each byte position, apply decoder cross-attention (bytes as queries, $\{o_j\}$ as keys/values) and a small transformer stack to decode bytes autoregressively; finally project to 256 logits and compute the byte-level loss.

At generation time the same steps are followed but decisions about patch boundaries must be made online using an incremental patcher; whenever a new patch starts the encoder produces a patch latent and the global model is invoked to extend the patch-level autoregressive state.

This architectural split — light-weight byte modules surrounding a powerful patch-level transformer — is the central engineering idea of BLT. It lets the model keep direct access to raw byte structure through embedding and hash n-gram features, pool local signals into compact, expressive patch representations through cross-attention, and spend the expensive global computation only where the data demands it.

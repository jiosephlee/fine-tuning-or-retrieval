\title{Stack Exchange of the Paper: "Byte Latent Transformer: Patches Scale Better Than Tokens"}

### How is block-causal attention defined across multiple documents when you pack sequences?
Question:
You mention packing examples to avoid padding in the latent transformer and using a block-causal mask that 'restricts attention to be up to and including the current patch within the current document'. When multiple documents are concatenated in a batch:

- Are patch indices and positional encodings reset at document boundaries?
- How is the attention mask constructed to prevent any cross-document attention at both byte and patch levels?
- Does packing impact KV-cache reuse at inference time?
Answer:
Short answer: packing in BLT is purely a training/efficiency implementation that concatenates patch sequences from multiple documents into one dense patch buffer for the latent transformer, but it never lets information leak across documents — that isolation is enforced by attention masks. Patch indices are treated as document-local (the model’s causal logic is per-document), cross-attention does not use positional embeddings, and the model’s incremental-patching requirement makes standard KV‑cache reuse at inference straightforward so long as you keep caches per generation stream (or correctly remap them when you try to batch many streams).

Explanation and minimal technical detail grounded in the paper. When BLT “packs” patches it simply removes padding by concatenating many short document patch sequences into one long sequence of patches that the latent transformer processes. To preserve autoregressive semantics the paper applies a block‑causal mask that limits attention to “up to and including the current patch within the current document.” Concretely, let $\text{doc}(j)$ be the document id of patch $j$. The latent (patch‑level) attention mask used for the global transformer is therefore:

$$
M^{\text{patch}}_{j,k} = \begin{cases}
1 & \text{if } \text{doc}(j)=\text{doc}(k)\ \text{and}\ k \le j,\\[4pt]
0 & \text{otherwise.}
\end{cases}
$$

At the byte level the local encoder uses a fixed windowed block‑causal mask that additionally forbids crossing document boundaries (the paper states local attention “can not cross document boundaries”). If bytes are indexed by $i$ and $k$ and $w_{\mathcal{E}}$ is the encoder window, a typical local mask is

$$
M^{\text{byte}}_{i,k} = \begin{cases}
1 & \text{if }\text{doc}(i)=\text{doc}(k)\ \text{and}\ i-w_{\mathcal{E}} < k \le i,\\[4pt]
0 & \text{otherwise.}
\end{cases}
$$

The encoder cross‑attention is even more granular: each patch query only attends to the bytes that belong to that patch (the paper: “each query $Q_j$ only attends to the keys and values that correspond to the bytes in patch $j$”). So the encoder cross‑attention mask is essentially an indicator of bytes $\in$ patch. The decoder cross‑attention follows the same per‑document, block‑causal semantics so bytes only see patch representations from their document and not from other documents.

About positional encodings and patch indices: the paper makes two relevant points — rotary positional embeddings (RoPE) are used only in self‑attention layers, and the cross‑attention modules do not use positional embeddings. The paper does not explicitly state “we reset absolute position counters on every document when packing.” That reset is not strictly required for correctness because the attention masks above already prevent cross‑document interaction; however most implementations prefer to treat positions/patch indices as document‑local (i.e., reset the position counter at a document boundary) to avoid very large absolute position values and make RoPE semantics simple. In short: logically patches are indexed per document and attention masking enforces the document fences; whether you also reset absolute position numbers is an implementation choice — the paper only requires the mask to enforce per‑document causality and notes the cross‑attention modules carry no positional embeddings.

Does packing affect KV‑cache reuse at inference? Not in the normal, single‑stream generation case. The paper enforces the incremental patching property

$$
f_p(\mathbf{x}_{<i}) = \left(f_p(\mathbf{x})\right)_{<i},
$$

so patch boundaries can be decided online without peeking at future bytes. That makes streaming/autoregressive generation possible: you run the lightweight local encoder to form a patch representation when you reach a boundary, run the global latent transformer on that patch (and append its keys/values to the latent KV cache), and reuse the cached keys/values for subsequent patch steps exactly as you would reuse token KV pairs in a tokenized model. Packing is described as a training optimization — at inference you normally generate single documents (or independently batched documents) and maintain separate KV caches per sequence. If you try to emulate training‑style packing at inference (i.e., interleaving many generation streams into one packed buffer) you can still reuse KV caches, but you must maintain a mapping from each stream to its slot in the packed buffer and build masks exactly as in training so no cross‑stream leakage occurs; that is bookkeeping, not a model limitation.

One practical caveat the paper notes: if you alter the patching decision rule at inference (for example the paper mentions they change the entropy threshold at inference from 0.6 to 0.1), segmentation can change and so the timing of when the global transformer is invoked changes. That changes when/what you cache (different patch boundaries produce different patch representations), so cache reuse across different segmentation regimes is not automatic — caches are reusable within a consistent segmentation/stream, but not across incompatible segmentation decisions.

Takeaway: packing is a training‑time compaction; document isolation is enforced with per‑document block‑causal masks at both byte and patch levels (and encoder cross‑attention is restricted to the bytes of each patch); positional resets are an orthogonal implementation choice (the paper guarantees correctness by masking and notes RoPE is only in self‑attention); and inference KV caching works as usual as long as you generate incrementally per document or carefully manage per‑stream caches when batching/packing inference requests.

\title{Stack Exchange of the Paper: "Byte Latent Transformer: Patches Scale Better Than Tokens"}

### What is the exact forward/generation pipeline in BLT at inference time?
Question:
I want to understand the step-by-step generation loop:

- As bytes are generated, does the local encoder re-encode the most recent window of bytes to produce/refresh the current patch representation input $p_j$ to the global model?
- When a patch boundary is detected, is the global transformer stepped once to produce a new $o_j$, which the local decoder then uses to autoregressively produce the bytes for that patch?
- What is cached across time (e.g., global transformer KV, local encoder states) to make this efficient given variable patch boundaries?
Answer:
Short answer: BLT’s inference loop is an alternating “cheap per-byte” / “expensive per-patch” loop. The lightweight local encoder/decoder operate at byte rate (and are implemented to be incremental over a short local window), while the heavy global latent transformer is invoked only at patch boundaries. In practice you therefore (a) run the small entropy model online to decide patch boundaries, (b) keep the local encoder updated incrementally as bytes arrive so you can produce the pooled patch representation when needed, (c) step the global transformer once per patch to produce the patch-level output $o_j$, and (d) reuse cached KV state for the global model and cached encoder/decoder state to avoid redoing work. The paper gives the pieces; the precise micro-scheduling (e.g. whether you re-run the encoder every byte or only just‑in‑time before a GT step) is an implementation choice but the architecture and the incremental-patching constraint make the efficient strategy above both possible and natural.

Why this follows from the paper (short, actionable explanation). BLT uses an entropy model $p_e$ to identify patch boundaries from past bytes only (the paper defines next-byte entropy)
$$
H(x_i)=\sum_{v\in\mathcal{V}} p_e(x_i=v\mid x_{<i})\log p_e(x_i=v\mid x_{<i}),
$$
and two incremental rules for boundaries: a global threshold $H(x_t)>\theta_g$ or a relative jump $H(x_t)-H(x_{t-1})>\theta_r$. The paper emphasizes that patching must be incremental (so decisions can be made online):
$$
f_p(\mathbf{x}_{<i})=f_p(\mathbf{x})_{<i}.
$$
Because the entropy test only requires conditioning on past bytes, you can decide “start a new patch now” without peeking at future bytes.

Concrete inference loop consistent with the text (what you will actually implement)

1) Maintain caches and states. Keep per-layer KV caches for the global latent transformer (so previously computed patch-level attention is not recomputed). Keep the local encoder’s per-byte hidden state (or its KV) for a sliding window of size $w_{\mathcal{E}}$ (the encoder uses a local block-causal attention window). Keep the local decoder autoregressive KV cache for already-generated bytes. Also cache the decoder cross‑attention keys/values built from the current patch-level output $o_j$ (those depend only on $o_j$ and can be reused for every byte inside that patch). The entropy model also runs incrementally (it has a sliding context) and can reuse its cached states.

2) Per-step (before producing the next byte) run the entropy model on the current prefix to evaluate the patching criterion. If the criterion says “no new patch”, do not call the heavy global transformer: generate the next byte using the local decoder conditioned on the currently active $o_j$. The decoder uses its autoregressive cache and the cached cross-attention K/V produced from $o_j$; after producing a byte you update the decoder autoregressive cache and append the new byte to the local encoder’s state (you only need to encode the new byte plus the local window because the encoder attention is local).

3) If the entropy model signals a patch boundary, you trigger a global step: form (or finalize) the pooled patch representation $p_j$ via the local encoder’s pooling/cross-attention over the bytes of that patch (the encoder is lightweight and local so you can build/update $p_j$ incrementally from cached encoder states rather than re-encoding the whole document). Run the global latent transformer one step (append this $p_j$ to its input sequence) to produce the new output latent $o_j$; append and cache the global transformer K/V for this patch. From $o_j$ compute the decoder-side cross-attention keys/values ($\mathcal{D}_C(o_j)$) once and cache them. Then continue generation inside the new patch using the local decoder (which now cross-attends to the newly cached $\mathcal{D}_C(o_j)$).

Notes about what is and isn’t explicitly in the paper. The paper is explicit that (i) the heavy latent transformer is the dominant cost and is used at patch granularity, (ii) the entropy model is incremental so boundaries can be decided online, and (iii) the local encoder uses a fixed local window $w_{\mathcal{E}}$ so it is naturally incremental. The paper does not spell out every micro‑optimization, but the caching scheme above follows directly from the architecture constraints and from standard autoregressive transformer inference techniques: keep per-layer KV caches for any autoregressive self-attention you want to avoid recomputing; compute cross-attention K/V from a patch‑level vector $o_j$ once per patch and reuse it while decoding that patch; and only re-encode the new bytes plus the local window for the encoder.

Why this is efficient and matches the paper’s motivation. Because encoding is local you pay only an $O(w_{\mathcal{E}})$ cost per new byte for the encoder, the decoder’s self-attention cost is amortized by caching, and the expensive global transformer is invoked only at patch boundaries (on average far less frequently when the entropy model groups long predictable byte runs into big patches). That is exactly how BLT gets the flop savings reported in the paper.

If you need a minimal pseudo‑sequence of operations to implement inference I would phrase it like this (still prose): keep encoder/decoder/global caches; loop: (A) use the entropy model on the current prefix to decide if the next token starts a new patch; (B) if yes, build/refresh pooled $p_j$ from the encoder’s cached byte states, call the global transformer once to get $o_j$ and cache its cross-attention K/V; (C) use the local decoder (with cached self-attn K/V and cached $\mathcal{D}_C(o_j)$) to autoregressively emit bytes for the patch, updating the encoder state for each new byte and the decoder’s autoregressive cache; repeat.

This matches Sections 2.3–2.4 (entropy patching and incremental patching), Section 3.2 (local encoder with local window and pooling cross‑attention), Section 3.1 (global latent transformer with block‑causal masking) and Section 3.3 (local decoder cross‑attention to $o_j$) in the paper.

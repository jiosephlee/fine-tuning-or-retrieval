# The Patch Size Playbook: How to Trade Speed and Accuracy with BLT

Byte Latent Transformer (BLT) replaces a fixed token vocabulary with dynamically sized byte patches. That simple change gives you a new, practical knob for trading inference cost (latency/flops) against accuracy: the average patch size (how many bytes the model processes per latent transformer step) and the entropy threshold(s) that decide where to cut patches. This post distills the paper’s results into actionable guidance: how to pick patch sizes and thresholds, how to compare fairly, and when to lower the entropy threshold at inference to get better results on hard tasks.

## Quick primer: what patches and entropy patching are
BLT groups a byte sequence into patches. The global latent transformer runs once per patch (the expensive part), while small local models encode bytes into patch latents and decode latents back to bytes.

Entropy patching uses a small next-byte language model p_e to estimate the uncertainty of the next byte and creates boundaries where uncertainty is high. Conceptually the next-byte entropy is

H(x_i) = -\sum_{v\in\mathcal{V}} p_e(x_i=v\mid \mathbf{x}_{<i}) \log p_e(x_i=v\mid \mathbf{x}_{<i}).

Two simple rules used in the paper to mark boundaries are:

- Global threshold: H(x_t) > \theta_g
- Approximate monotonic jump: H(x_t) - H(x_{t-1}) > \theta_r

Boundaries in BLT are identified as a lightweight preprocessing step (so they are incremental — decisions don’t peek at future bytes).

## Why patch size controls inference cost (intuitively and mathematically)
Let
- n_ctx = number of input bytes you keep as context,
- n_p = average patch size in bytes,
- F_G = flops spent by the global transformer per patch,
- F_L = flops per byte from the local encoder/decoder and per-byte costs.

Number of global steps ≈ n_ctx / n_p, so total flops ≈ (n_ctx / n_p)·F_G + n_ctx·F_L. Dividing by n_ctx gives flops per byte:

flops/byte ≈ F_G / n_p + F_L.

If the global transformer dominates (as it typically does because of large feed-forward nets), increasing n_p reduces the dominant term roughly inversely proportional to n_p. That’s why longer patches mean fewer expensive global steps and much lower inference flops. In BLT experiments, increasing average patch size to ~8 bytes gave up to ~50% inference-flop savings compared to smaller patch sizes (numbers are dataset and architecture dependent).

## How to pick average patch size and entropy thresholds — practical steps

1. Decide your inference constraint first.
   - If latency or flop budget is the hard constraint: target a larger average patch size (e.g., 6–8 bytes in the paper’s experiments).
   - If per-query accuracy is paramount (reasoning, hard MC tasks, code generation): target smaller patches or allow more patches at inference time (see point 4).

2. Pick a target average patch size n_p (bytes/patch).
   - The paper’s comparable points: BPE token averages were ~3.7–4.4 bytes; BLT experiments used averages ≈4.5 (entropy), ≈6 (space patching), and ≈8.
   - Larger n_p → fewer global steps → lower inference flops. Expect diminishing returns because the local encoder/decoder still cost something per byte.

3. Calibrate the entropy threshold on your pretraining / calibration mix.
   - Run your entropy model over a representative dataset and find θ_g (or θ_r) that yields your target average patch size in expectation.
   - The paper tuned thresholds on the pretraining mix so that models with different patch sizes still saw the same total bytes in a batch.

4. At inference you can tune the threshold to trade compute for accuracy.
   - Lowering the entropy threshold (more boundaries) produces shorter patches and more global steps, increasing compute but often improving performance on “hard” decisions.
   - The paper reports an example adjustment: a BLT-Entropy model trained with a threshold ≈0.6 and then evaluated with a lower threshold ≈0.1 at inference produced better downstream task performance at the cost of more steps.
   - Use this knob when you want extra accuracy on demanding inputs (reasoning, ambiguous completions, first-character uncertainty in open-ended answers).

5. Use the approximate-monotonic rule and entropy-context resets to avoid “entropy drift.”
   - In structured or repetitive contexts (e.g., multiple-choice content), simple global thresholds can let patches become too long because the entropy model’s context lowers uncertainty. The paper used the monotonic constraint H(x_t)-H(x_{t-1})>\theta_r and reset the entropy model context on newlines to reduce that drift.

6. Keep the entropy model practical.
   - The experiments used a compact entropy model (example: 100M parameters, 14 layers, hidden 512, window 512 bytes). Scaling the entropy model helps but has diminishing returns beyond ~50M parameters in their ablations.
   - If the entropy model has a small receptive field you can precompute entropies or even encode them in a lookup for speed.

## Why you must keep total context bytes constant when comparing setups
Patch size changes the number of latent steps (patches) for the same byte context. To compare two model configurations fairly, the paper keeps the expected number of bytes per batch constant. If you instead keep the number of patches or sequence length constant, larger patches would implicitly give a model more context (more bytes), creating an unfair advantage. So:

- Fix n_ctx (bytes) across experiments. If you increase n_p, reduce the sequence length (in patches) so that n_ctx stays constant in expectation.

In the paper they used e.g. 8k bytes context on the Llama-2 mix and 16k bytes on the BLT-1T mix while maintaining average batch bytes constant.

## Recipes (concrete starting points)

- Latency-first / deployment-constrained:
  - Target average patch size: 6–8 bytes.
  - Calibrate θ_g on pretraining mix to hit that n_p.
  - Keep the threshold the same or increase slightly at inference to favor longer patches.
  - Reallocate saved inference flops to grow the global transformer (if retraining is possible) — the paper shows you can increase model size while keeping a fixed inference budget, and that often improves performance.

- Accuracy-first / hard reasoning or coding tasks:
  - Train with a reasonable n_p (e.g., ≈4.5) or larger if you plan to lower threshold at inference.
  - At inference, lower θ_g to produce more (shorter) patches; the paper’s example: training θ≈0.6 then using θ≈0.1 at eval improved task scores.
  - For repeated/structured inputs, prefer the approximate-monotonic rule and reset entropy context on newlines to avoid runaway long patches.

- Balanced / default:
  - Use entropy patching calibrated to an average patch size comparable to BPE (≈4–5 bytes). You get dynamic allocation (more compute when the next-byte uncertainty is high) while matching the step count of token models.

- Multilingual / character-sensitive tasks:
  - Avoid rule-based whitespace patching when scripts lack clear word boundaries. Use entropy patching so the model allocates compute where byte uncertainty is genuinely high; BLT showed improved robustness and character-level performance in the paper.

## Practical caveats, implementation notes and ablations to remember
- Patching must be incremental at generation time (no future bytes). BLT identifies boundaries with a preprocessing pass over prefixes.
- Local encoder/decoder and cross-attention add per-byte costs. The dominant term is usually the global transformer; the flops/byte formula above clarifies the tradeoff.
- Hash n-gram embeddings (n=3..8) and encoder cross-attention matter for matching BPE scaling: the paper found hash embeddings (≈500k slots) and cross-attention improve performance, with diminishing returns after a few hundred thousand hashes.
- Entropy model capacity and window matter: ablations show improvements up to ~50M parameters; beyond that returns diminish.
- Training efficiency: BLT packs batches of patches to avoid padding in the latent transformer; when you change n_p you should adjust the packed sequence length and batch packing to maintain stable memory and throughput.
- Fair comparisons: in the paper, BPE baselines used Llama‑3 tokenizer (128k vocab) for a stronger baseline. When comparing, keep tokenizer choice consistent.

## Quick checklist before you tune
- Choose your inference flop or latency budget.
- Pick target average patch size n_p based on that budget.
- Calibrate entropy threshold(s) on a representative corpus to hit n_p in expectation.
- Decide whether to use global or approximate-monotonic thresholding (use monotonic + newline resets when you see entropy drift).
- If needed, plan an inference-time threshold sweep (e.g., 0.6 → 0.1) to trade additional compute for improved accuracy on difficult inputs.
- Keep total context bytes constant when you compare different setups.

## Closing
Patch size and entropy thresholds are operational, interpretable levers in BLT: longer patches buy you inference efficiency because the heavy global transformer runs less often; smaller patches (or lowering thresholds at runtime) buy you accuracy for hard predictions by invoking the global transformer more frequently. Calibrating the entropy model and thresholds on a representative mix, keeping total bytes constant across comparisons, and using monotonic thresholding for structured data will get you most of the practical benefits shown in the BLT experiments.

The paper’s code and training/inference implementations are available at https://github.com/facebookresearch/blt if you want to try these knobs directly on your workload.

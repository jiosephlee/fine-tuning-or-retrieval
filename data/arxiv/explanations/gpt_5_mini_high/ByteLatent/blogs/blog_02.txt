# Entropy Patching, Explained in Plain English

Transformers that work on raw bytes face a simple but painful problem: the input sequence gets very long, and the model pays a computational cost for every step it runs. BLT (Byte Latent Transformer) tackles this by grouping bytes into patches and running the expensive global Transformer only once per patch. The big question is: where should one patch end and the next begin?

Entropy patching answers that by looking at uncertainty. It makes patch boundaries where the model is suddenly uncertain about the next byte — roughly speaking, where “something new” is starting. Below I explain what that uncertainty (entropy) is, how BLT computes it, and why using thresholds on entropy produces smart, context-aware patch boundaries.

## What we mean by “entropy” (uncertainty) here

At any position in a byte sequence, a small byte-level language model can give a probability distribution over the next byte. If that distribution is very concentrated (one or a few bytes get almost all the probability), the uncertainty is low; if the probability is spread out across many bytes, the uncertainty is high.

Formally, BLT computes the next-byte entropy under the entropy model’s distribution \(p_e\) over the byte vocabulary \(\mathcal{V}\):

\[
H(x_i) \;=\; -\sum_{v \in \mathcal{V}} p_e(x_i=v \mid \mathbf{x}_{<i}) \, \log p_e(x_i=v \mid \mathbf{x}_{<i}).
\]

You can think of \(H(x_i)\) as a single number that measures “how hard is it to predict the next byte given everything seen so far?”

In BLT experiments the entropy model is a compact autoregressive byte LM trained on the same data mix as the full model (a typical experimental choice in the paper is a transformer of ~100M parameters with a 512‑byte sliding window). The entropy model is purposely small so computing entropies is cheap.

## How BLT turns entropies into patch boundaries

Entropy patching is a data-driven, incremental rule that marks patch starts when the next-byte uncertainty is high. Concretely, BLT uses two simple tests for putting a boundary at position \(t\):

- Global threshold:
  \[
  H(x_t) > \theta_g
  \]
  — start a new patch whenever the next-byte entropy exceeds a global threshold \(\theta_g\).

- Approximate monotonicity (relative) threshold:
  \[
  H(x_t) - H(x_{t-1}) > \theta_r
  \]
  — start a new patch if the entropy jumps relative to the immediately preceding byte.

Either rule can be used (the paper experiments with both). Boundaries are computed during a lightweight preprocessing step at data‑load time using only past bytes; that makes the scheme incremental, meaning the segmentation rule depends only on \(\mathbf{x}_{<i}\). Formally, an incremental patching function satisfies
\[
f_p(\mathbf{x}_{<i}) = f_p(\mathbf{x})_{<i},
\]
which is required so the model can decide at generation time, step by step, whether to finish the current patch or to continue it.

## Why this actually finds natural patch edges

Two simple empirical observations justify entropy patching:

1. The first byte of a new lexical item (word, identifier, answer choice, etc.) is usually harder to predict than the bytes that follow. Before you see any letter of a word, many possible next bytes are plausible; after you see the first letter, the set of plausible continuations usually shrinks. Entropy is high at the start and tends to decline as you consume the predictable part.

2. Predictability often changes at semantic boundaries. In code, math, or lists of choices (where content is repetitive), entropy can behave differently than in prose; entropy patching is context-aware and adapts to these patterns.

Putting these together: if entropy is high (global rule) or if entropy suddenly increases relative to the previous byte (monotonicity rule), that is a strong signal that a new unit of information has started — a natural place to put a patch boundary. Conversely, long runs of predictable bytes (low entropy) are grouped into bigger patches, which saves computation because the global latent Transformer runs less frequently for those runs.

## The practical pipeline

Roughly, BLT’s entropy patching pipeline is:

- Train a small byte-level entropy model on the same data mix that the main model will use.
- Run that model over the data to compute next-byte entropies \(H(x_i)\) for each byte (this is done as a lightweight preprocessing step at dataload time).
- Choose thresholds \(\theta_g\) and/or \(\theta_r\) so the resulting segmentation has the desired average patch size on the training mix (thresholds control the trade-off between patch length and computational budget).
- Segment the bytes into patches using the chosen rule(s). The downstream encoder and global latent Transformer then operate on those patches.

Because the entropy model and the rule only use past bytes, the same rule can be applied during autoregressive generation: whether to stop the current patch and invoke the global model is decided from the prefix alone.

## Practical considerations and trade-offs

- Thresholds control compute vs. accuracy. A higher threshold yields longer average patches (fewer global steps → lower inference FLOPs) but risks grouping too much information together; a lower threshold produces shorter patches and more compute. In BLT experiments the team tuned thresholds to achieve target average patch sizes (common reported averages are ~4.5 bytes, with space-based or larger thresholds producing ~6–8 bytes). They also show that larger average patches can cut inference FLOPs substantially (e.g., patch size ~8 bytes can approach ~50% inference‑flop savings vs. smaller patches).

- Entropy model design matters but has diminishing returns. The paper reports that larger entropy models and wider context windows improve patching quality up to a point (diminishing returns beyond ~50M parameters in their ablations).

- Repetitive context can cause “entropy drift”: if the entropy model’s context contains long repeated material, the entropies can become artificially low and produce very long patches. The paper mitigates this by using the approximate monotonicity rule and by resetting the entropy model’s context at natural separators (e.g., newlines) in some large-scale runs.

- This is different from learned boundary-predictor approaches. BLT’s entropy patching computes entropies using an explicit autoregressive byte LM and thresholds them during preprocessing; it does not train a separate boundary classifier end-to-end (though end-to-end learned patching is a possible future direction).

- Inference-time flexibility: BLT can retune the entropy threshold at inference to trade performance for compute. In experiments, lowering the inference threshold (more boundaries) improved downstream task scores at the cost of more inference steps.

## In short: what entropy patching buys you

Entropy patching turns a principled, context‑sensitive signal (next-byte uncertainty) into patch boundaries. The result is patches whose bytes have relatively uniform information density: predictable regions are compressed into longer patches (fewer global Transformer steps), and hard regions get shorter patches (more capacity where it matters). Because the rule is incremental (depends only on the prefix), it works naturally during autoregressive decoding. BLT’s experiments show this approach is effective: it allows the model to dynamically allocate compute, improves inference efficiency, and helps with robustness and long‑tail generalization compared to fixed tokenization or static patching schemes.

\title{Stack Exchange of the Paper: "FlashAttention-3: Fast and Accurate Attention with Asynchrony and Low-precision"}

### How does the blockwise local softmax in FlashAttention-3 yield the exact global softmax output?
Question:
In the forward algorithm, each CTA processes a query tile $\mathbf{Q}_i$ and loops over key-value blocks $\{(\mathbf{K}_j, \mathbf{V}_j)\}$. The kernel keeps per-row running statistics $m_i$ and $\ell_i$ and updates them via
- $m_i \leftarrow \max\big(m_i, \operatorname{rowmax}(\mathbf{S}_i^{(j)})\big)$ where $\mathbf{S}_i^{(j)} = \mathbf{Q}_i \mathbf{K}_j^\top$,
- $\widetilde{\mathbf{P}}_i^{(j)} = \exp(\mathbf{S}_i^{(j)} - m_i)$,
- $\ell_i \leftarrow e^{m_i^{\text{old}} - m_i}\,\ell_i + \operatorname{rowsum}(\widetilde{\mathbf{P}}_i^{(j)})$,
- $\mathbf{O}_i \leftarrow e^{-(m_i - m_i^{\text{old}})}\,\mathbf{O}_i + \widetilde{\mathbf{P}}_i^{(j)} \mathbf{V}_j$,
and finally returns $\mathbf{O}_i \leftarrow \operatorname{diag}(\ell_i)^{-1} \mathbf{O}_i$.
Could someone provide a concise derivation that the final $\mathbf{O}_i$ equals $\operatorname{softmax}(\alpha\mathbf{Q}_i \mathbf{K}^\top)\,\mathbf{V}$ computed exactly (no approximation), and explain why the multiplicative rescalings with $m_i$ and $\ell_i$ preserve numerical stability and correctness?
Answer:
Short answer: FlashAttention-3 implements a streaming (blockwise) version of the standard numerically-stable softmax (the usual log‑sum‑exp trick) and maintains an exact algebraic invariant for the numerator and denominator under a moving per-row shift. By induction one shows that after processing all key blocks the stored accumulators equal the globally shifted numerator and denominator, so the final divide reproduces exactly $\operatorname{softmax}(S)\,V$ (with $S=\alpha QK^\top$) in exact arithmetic. The multiplicative rescalings with $m_i$ and $\ell_i$ are exactly the re‑basings required by the identity
$\exp(a-m_{\text{new}})=\exp(a-m_{\text{old}})\exp(m_{\text{old}}-m_{\text{new}})$, so they preserve correctness and—because $m$ is monotone nondecreasing—keep exponent arguments $\le 0$ and prevent overflow, which is the usual numerical‑stability trick.

Proof (per row, concise). Fix a query tile index $i$ and a single row (drop the row index for clarity). Let the key/value blocks be indexed $j=1,\dots,J$. For block $j$ write the score vector produced by that block as $s^{(j)}\in\mathbb{R}^{B_c}$ (these are the rows of $S_i^{(j)}$). Define the running maximum after processing the first $j$ blocks
$$m^{(j)}=\max_{1\le u\le j}\max_k s^{(u)}_k$$
(with $m^{(0)}=-\infty$). Define the (blockwise) exponentiated vectors with respect to the current shift
$$\tilde p^{(j)}=\exp\big(s^{(j)}-m^{(j)}\big)\qquad(\text{vector of length }B_c).$$
The global (rowwise) softmax numerator and denominator after all blocks are
$$\begin{aligned}
\text{Num}^{\mathrm{glob}}&=\sum_{u=1}^J \sum_{k}\exp\big(s^{(u)}_k - m^{(J)}\big)\,v^{(u)}_k,\\
\text{Den}^{\mathrm{glob}}&=\sum_{u=1}^J \sum_{k}\exp\big(s^{(u)}_k - m^{(J)}\big),
\end{aligned}$$
where $v^{(u)}_k$ is the $k$th row of $V$ inside block $u$. The desired output row is $\text{Num}^{\mathrm{glob}}/\text{Den}^{\mathrm{glob}}$.

Claim (invariant). After processing blocks $1..j$ the kernel's accumulators satisfy
$$\begin{aligned}
O^{(j)} &= \sum_{u=1}^j \sum_k \exp\big(s^{(u)}_k - m^{(j)}\big)\,v^{(u)}_k,\\
\ell^{(j)} &= \sum_{u=1}^j \sum_k \exp\big(s^{(u)}_k - m^{(j)}\big).
\end{aligned}$$
These are exactly the numerator and denominator but expressed using the current shift $m^{(j)}$.

Proof by induction. For $j=1$ we have $m^{(1)}=\max_k s^{(1)}_k$, $\tilde p^{(1)}=\exp(s^{(1)}-m^{(1)})$, so the kernel sets $O^{(1)}=\tilde p^{(1)}V_1$ and $\ell^{(1)}=\mathbf{1}^\top\tilde p^{(1)}$, which matches the claim.

Assume the invariant holds at step $j-1$ with $O^{(j-1)},\ell^{(j-1)}$ representing all previous contributions shifted by $m^{(j-1)}$. When processing block $j$ the code first computes $m^{(j)}=\max(m^{(j-1)},\max_k s^{(j)}_k)$. Two cases:

1. If $m^{(j)}=m^{(j-1)}$ then no re‑bas­ing is needed and the kernel does
   $$O^{(j)}=O^{(j-1)}+\tilde p^{(j)}V_j,\qquad \ell^{(j)}=\ell^{(j-1)}+\mathbf{1}^\top\tilde p^{(j)},$$
   which matches the invariant with shift $m^{(j)}$.

2. If $m^{(j)}>m^{(j-1)}$ then we must convert the old accumulators from being expressed with shift $m^{(j-1)}$ to the new shift $m^{(j)}$. Using the identity
   $$\exp\big(s^{(u)}_k-m^{(j)}\big)=\exp\big(s^{(u)}_k-m^{(j-1)}\big)\exp\big(m^{(j-1)}-m^{(j)}\big),$$
   we get that the entire old numerator and denominator must be multiplied by $\exp(m^{(j-1)}-m^{(j)})$ and then we add the new block written with shift $m^{(j)}$. Thus the kernel performs exactly
   $$O^{(j)}=\exp(m^{(j-1)}-m^{(j)})\,O^{(j-1)}+\tilde p^{(j)}V_j,$$
   $$\ell^{(j)}=\exp(m^{(j-1)}-m^{(j)})\,\ell^{(j-1)}+\mathbf{1}^\top\tilde p^{(j)},$$
   which is algebraically identical to the invariant expression with shift $m^{(j)}$.

Thus by induction the invariant holds for every $j$. At the end $j=J$ we have $m^{(J)}=\max_k S_{rk}$ (rowwise max over all blocks) and therefore the final computed output
$$\frac{O^{(J)}}{\ell^{(J)}}=\frac{\sum_{u,k}\exp\big(s^{(u)}_k-m^{(J)}\big)\,v^{(u)}_k}{\sum_{u,k}\exp\big(s^{(u)}_k-m^{(J)}\big)}=\sum_k\frac{\exp(S_k)}{\sum_{k'}\exp(S_{k'})}\,v_k$$
is exactly the row of $\operatorname{softmax}(S)\,V$. (Everything above is exact algebra; the code performs the same algebra in a blockwise, streaming way.)

Why this is numerically stable. Two facts give numerical safety. First, each exponential is taken on an argument shifted by the current row maximum, so its argument is $\le 0$; hence each $\tilde p$ entry is in $(0,1]$ and cannot overflow. Second, when a later block discovers a larger maximum the kernel rescales the previous accumulators by the factor $\exp(m^{\text{old}}-m^{\text{new}})\le 1$; that never amplifies previous partial sums and prevents previously large contributions from causing overflow under the new baseline. In other words the algorithm never needs to form $\exp(S)$ at full (possibly large) magnitude and instead always keeps numerators and denominators re‑based to the current maximum, which is exactly the standard log‑sum‑exp stabilization applied incrementally.

Practical note: the proof above is algebraic and shows exact equivalence in real arithmetic. In floating‑point arithmetic there will be the usual rounding errors from exponentials, multiplies and adds; FlashAttention implementations mitigate this by keeping the softmax internals (the accumulators $\ell$ and $O$ and the exponentials) in a sufficiently high precision (FP32 in the paper) and by ensuring the shifts are monotone so scaling factors are $\le 1$ (they do not amplify rounding error). This delivers both correctness (same mathematical target) and good numerical stability in practice, which is exactly what FlashAttention‑3 reports in the paper.

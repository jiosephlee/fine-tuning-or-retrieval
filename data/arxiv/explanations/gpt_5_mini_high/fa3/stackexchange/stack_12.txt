\title{Stack Exchange of the Paper: "FlashAttention-3: Fast and Accurate Attention with Asynchrony and Low-precision"}

### What exactly is the FP8 baseline for error, and how is RMSE computed fairly?
Question:
The error experiment draws $\mathbf{Q},\mathbf{K},\mathbf{V}$ from a mixture that injects 0.1 percent outliers and compares RMSE against an FP64 reference. For the FP8 baseline, you state per-tensor scaling, FP32 accumulators, and softmax intermediates in FP16. Could you detail: (1) which operations are in FP8 vs FP16 vs FP32 for the baseline; (2) whether scales are chosen per input tensor or per matmul operand; (3) whether RMSE is measured on the final $\mathbf{O}$ after all rescalings; and (4) how seeds and sample sizes are controlled so the 2.6$\times$ improvement is statistically robust?
Answer:
Short answer: the paper’s FP8 “baseline” is the simple per-tensor FP8 recipe: Q/K/V are quantized with one scale per tensor, the attention GEMMs run using FP8 operands on the hardware Tensor Cores with FP32 accumulation, and the softmax path (row‑max subtraction, exp, row sums, normalization) is executed in FP16; the RMSE reported is the root‑mean‑square difference between the final attention output $O$ from the low‑precision implementation and an FP64 reference (after converting the low‑precision output to high precision). The paper gives the input distribution used for the trial but does not publish per‑trial RNG seeds or a repeat count, so the $2.6\times$ number is obtained from paired comparisons on the same random draws (and from many output elements), but if you want formal statistical guarantees you should repeat the experiment over multiple seeds and report $\mathrm{mean}\pm\mathrm{std}$ or a confidence interval.

More detail and intuition. (1) Precision mapping for the FP8 baseline. The paper explicitly summarizes the baseline as “per‑tensor scaling, FP32 accumulators, and softmax intermediates kept in FP16.” Operationally that means the input tensors $Q$, $K$, $V$ are quantized using a single scale per tensor to FP8; the matrix multiplications that produce the score matrix $S = \alpha QK^T$ and the projection $O = P V$ are executed on the low‑precision Tensor Cores using FP8 operands but with FP32 accumulation (so the internal accumulator has FP32 precision before any casts back to a storage format); the softmax pipeline (compute row max, form exponentials, accumulate row sums, and normalize) is carried out in FP16 to avoid the catastrophic dynamic‑range / rounding issues that would occur in FP8. After the final matmul the implementation materializes the output (effectively in full float precision for comparison); the FP8 baseline therefore mixes FP8 storage/operands, FP32 accumulation for matmuls, and FP16 for the numerically sensitive softmax steps. The paper does not go into micro‑implementation variants (for example, different libraries may dequantize some operands to FP16 before the second GEMM), but the phrase above is the canonical description used for the baseline in the comparison.

(2) How scales are chosen. The baseline uses per‑tensor scaling (one scalar scale per whole $Q$, one per $K$, one per $V$), as the paper states. FlashAttention‑3’s improvement comes from switching to block quantization (one scale per block of the tensor, aligned with the algorithm’s block tiling) plus an incoherent preprocessing transform; those two changes reduce quantization error relative to a single global scale.

(3) What “RMSE against FP64 reference” actually means. The RMSE reported is computed between the attention output tensors elementwise: if $O_{\text{ref}}$ is the output computed in FP64 and $O_{\text{low}}$ is the output from the low‑precision method converted to FP64 for comparison, then $$\mathrm{RMSE}=\sqrt{\frac{1}{M}\sum_{i=1}^{M}\bigl(O_{\text{low},i}-O_{\text{ref},i}\bigr)^2},$$ where $M$ is the total number of scalar outputs (all entries of the output block/tensor used in the experiment). In other words, the comparison is on the final $O$ after all softmax rescalings and matmuls have been applied. (The paper’s “Numerical Error Validation” section describes the input draw and then “measure the root mean squared error (RMSE)”; that is the quantity reported in the table.)

(4) Seeds, sample size and robustness of the $2.6\times$ claim. The paper specifies the input distribution used for the numerical test, $$\mathcal{N}(0,1)+\mathcal{N}(0,100)\cdot\mathrm{Bernoulli}(0.001),$$ so each entry is typically $\mathcal{N}(0,1)$ but 0.1% of entries have a large (std‑10) outlier. The manuscript does not give explicit RNG seeds or a stated number of independent random trials for the RMSE table. Two facts work in favor of robustness even without multiple seeds: first, the RMSE is averaged over many output elements (so a single random draw produces a large effective sample size); second, the comparisons are paired (the same random $Q/K/V$ are used to produce both the baseline and FlashAttention‑3 outputs), which reduces variance in the ratio. Still, for a rigorous statistical statement you should (and I recommend you) do the following when you reproduce this experiment: fix a deterministic seed for each run, run the whole pipeline for a number $T$ of independent seeds (common practice uses at least $T=30$ for CLT‑style error bars), compute the RMSE per seed for both methods on the same inputs (so you get paired RMSE samples), then report the mean and standard deviation (or a 95% confidence interval) of the RMSE and of the RMSE ratio. Because the comparison is paired you can also report the distribution of the per‑seed ratios or do a paired test. These steps make the “$2.6\times$” number statistically interpretable; without that extra bookkeeping the number in the paper should be read as the ratio observed on the described synthetic ensemble (large tensors with 0.1% outliers) rather than as a fully randomized hypothesis test.

If you want, I can sketch a minimal reproducible script (pseudo‑code or PyTorch/CUDA) that generates the mixture inputs, runs both the baseline and FlashAttention‑3 implementations on the same seeds, computes elementwise RMSE, and returns $\mathrm{mean}\pm\mathrm{std}$ / CI for the RMSE ratio so you can verify the $2.6\times$ figure under controlled repetition.

\title{Blogs about the Paper: "FlashAttention-3: Fast and Accurate Attention with Asynchrony and Low-precision"}

# FP8 Without the Fear: Block Quantization and Incoherent Processing Explained

FP8 delivers an attractive doubling of GEMM throughput on modern GPUs, but its small mantissa and coarse quantization make it fragile when activations contain outliers — exactly the situation often seen in large language models. FlashAttention-3 shows a practical way to keep the FP8 speedups while substantially reducing the numerical damage: two lightweight, compatible guards called block quantization and incoherent processing. Together they cut FP8 attention error by 2.6× versus a standard per-tensor FP8 baseline (in experiments with synthetic outliers), and they can be fused into the attention pipeline with negligible extra cost.

## Why FP8 is tricky for attention

FP8 (e4m3) packs just 3 bits for the mantissa and 4 bits for the exponent. That gives you a reasonable dynamic range but a very coarse step size for nearby values. A common strategy is per-tensor quantization: compute a single scale for an entire tensor, divide by that scale, round to the FP8 format, and run the low-precision GEMMs. Per-tensor scaling works well when values are fairly homogeneous, but it breaks down when a few entries are much larger than the rest.

Large models frequently have such outliers. If a single extreme value drives the per-tensor scale, the rest of the tensor is effectively quantized with a much coarser resolution — small-but-important differences disappear, dot products become noisy, and the softmax in attention amplifies the resulting errors.

## Guard 1 — Block quantization: scale where it makes sense

Block quantization replaces a single global scale with one scale per block. In FlashAttention-3 the attention computation is already block-structured (it processes tiles of size like $B_r \times d$ or $B_c \times d$), so block quantization simply computes and stores one scalar scale per block and quantizes that block independently.

Why this helps: outliers tend to be localized. A block that contains an outlier will get a correspondingly large scale, but other blocks that are well-behaved keep much finer resolution. Block quantization therefore reduces the effective quantization noise for the majority of entries.

Two practical details from FlashAttention-3:

- The blocks used for quantization are the same blocks that the attention kernel naturally processes, so quantization can be fused into the preprocessing step (for example, fused with rotary embeddings) with no extra memory-bandwidth pass.
- The algorithm folds block scales into the per-block computations: when you quantize $Q$ and $K$ blocks with their respective scales, the blockwise dot products can be rescaled appropriately without adding extra GEMMs, so there is no meaningful extra runtime cost for applying the per-block scaling.

## Guard 2 — Incoherent processing: spread out the outliers

Block quantization helps when outliers are localized, but what if an outlier is extremely concentrated in a single dimension and that pattern repeats across many blocks? Incoherent processing addresses that by randomly mixing the coordinates before quantization.

Concretely, FlashAttention-3 multiplies $Q$ and $K$ (the operands of the attention dot-product) by a random orthogonal matrix $M$ before quantizing:

- Because $M$ is orthogonal ($M M^\top = I$), the attention kernel is invariant:
  $$(Q M)(K M)^\top = Q K^\top.$$
- The multiplication by $M$ spreads any coordinate-level outlier across many dimensions, reducing the peak-to-average ratio inside each block and making quantization less destructive.

To keep this cheap, FlashAttention-3 follows recent work and chooses $M$ as a product of cheap transforms: random diagonal sign matrices and a Hadamard matrix. This permits a fast $O(d \log d)$ implementation (a fast Walsh–Hadamard transform) and, importantly, can be fused with other per-token preprocessing operations (again, e.g., rotary embeddings), so the incoherent transform adds essentially no extra runtime in practice.

## Putting them together in FlashAttention-3

The two techniques are complementary:

- Incoherent processing makes the per-block statistics more uniform by mixing dimensions, so block quantization can use tighter scales for most blocks.
- Block quantization captures residual local dynamic range differences after incoherence, preventing a single bad block from dominating the whole tensor’s scale.

Implementation highlights from FlashAttention-3 (kept intentionally short and practical):

- Quantize blocks of $Q$, $K$, and $V$ to FP8 with one scale per block (block sizes match the kernel tiling).
- If using incoherent processing, first compute $Q' = Q M$ and $K' = K M$ using the fast Hadamard + sign-flip trick; then quantize $Q'$ and $K'$ blockwise.
- The attention kernel accepts these FP8 blocks and applies the block scales in-place so the final $S$ and downstream computations see correctly scaled values without extra GEMMs or global rescales.
- Both block quantization and incoherent processing are fused with existing preprocessing (e.g., rotary embeddings) in the FlashAttention-3 implementation, so the accuracy guards are low-overhead.

## Empirical effect

FlashAttention-3 evaluated FP8 attention against a baseline FP8 attention implementation that uses per-tensor scaling. To stress the system, inputs were sampled with synthetic outliers drawn from
$$\mathcal{N}(0,1) + \mathcal{N}(0,100)\cdot\mathrm{Bernoulli}(0.001)$$
(that is, 0.1% of entries have a large extra term). Under that distribution, FP8 FlashAttention-3 with block quantization plus incoherent processing produced 2.6× lower numerical error (RMSE against an FP64 reference) than the baseline per-tensor FP8 approach.

Crucially, these accuracy gains come while retaining the FP8 throughput benefits of FlashAttention-3: the paper reports FP8 performance reaching close to 1.2 PFLOPs/s on H100 hardware. In short, the two guards give you much of the numeric stability advantage of higher precision, without sacrificing the main reason to choose FP8 — the dramatic speedups on modern tensor cores.

## Practical notes and caveats

- Block quantization and incoherent processing are designed to be low-cost in real systems: both can be fused with the preprocessing stage (e.g., rotary embedding), and the per-block scales are tiny metadata compared to the tensors themselves.
- The method in the paper focuses on the forward pass and on attention kernels optimized for Hopper-style GPUs (H100). FlashAttention-3’s FP16 kernels include persistent-kernel optimizations; the FP8 kernels in the paper do not yet include the same persistent-kernel load balancing, which can make FP8 less favorable for some small-sequence or causal-mask cases relative to vendor kernels. That is an orthogonal implementation detail that does not change the quantitative benefit of block quantization and incoherent processing for accuracy.
- The paper observes lower numerical error for FP16 FlashAttention-3 as well (because intermediate softmax rescaling is kept in FP32), but when you specifically want FP8 throughput, the two guards above are the practical path to making FP8 usable in the presence of outliers.

## Takeaway

FP8 can be fast and usable if you neutralize the effect of outliers and narrow dynamic-range variation. Block quantization (one scale per processing block) and incoherent processing (a cheap orthogonal random mixing via Hadamard and sign flips) are two complementary, low-overhead techniques that FlashAttention-3 uses to do exactly that. They reduce FP8 attention error by about 2.6× versus a naive per-tensor FP8 baseline in the outlier regime, while preserving the large FP8 throughput gains on modern GPUs.

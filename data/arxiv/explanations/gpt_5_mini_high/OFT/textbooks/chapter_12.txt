\title{A Textbook about the Paper: "Controlling Text-to-Image Diffusion by Orthogonal Finetuning"}

Chapter 12: Implementation Guide and Best Practices

# Layer selection (e.g., attention q/k/v/proj) and sharing strategies

Choosing which layers to finetune with OFT/COFT is the first practical decision. The paper demonstrates OFT as a model-agnostic finetuning method and for a fair comparison with LoRA it was applied to the same attention projection matrices that LoRA typically targets. Concretely, in Transformer-style U-Nets or text-to-image denoisers you will usually target the linear projection matrices used by attention (query/key/value/output projections) because these matrices are compact, central to semantic routing, and are the usual place adapter methods are applied. If you have a very tight parameter budget, applying OFT only to those attention projection matrices gives most of the controllability benefit while keeping the number of trainable parameters low.

OFT also applies naturally to fully connected and convolutional layers. For convolutional layers the block-diagonal interpretation of OFT can be particularly convenient: when the number of blocks matches the number of input channels, each block acts on a single channel and behaves similarly to a depth-wise transform. That observation suggests two practical sharing choices for convolutional layers: either give each input channel its own small block (fine control, lower cross-channel flexibility) or share blocks across channels (more bias, fewer parameters). In general, the default recommended strategy is to use a single layer-shared orthogonal matrix per layer (the formulation used in the paper): for each layer you learn one orthogonal transform that is applied to all neurons in that layer. If you need to cut parameters further, use the block-diagonal parameterization described below and optionally share the block submatrix across blocks.

When you want to match a baseline (LoRA or DreamBooth) for fair comparison, apply OFT to the exact same set of weight matrices used by the baseline (for example, the same q/k/v/proj matrices). That keeps the comparison apples-to-apples and simplifies hyperparameter transfer (you can reuse the same training schedule and losses).

# Cayley-parameterized orthogonal module: initialization and stability

The practical orthogonal parameterization used in the paper is the Cayley transform. Implement it exactly as

\[
\mathbf{R} = (\mathbf{I} + \mathbf{Q})(\mathbf{I} - \mathbf{Q})^{-1},
\]

where \(\mathbf{Q}\) is a learnable skew-symmetric matrix (\(\mathbf{Q}^\top = -\mathbf{Q}\)). This parameterization produces a provably orthogonal \(\mathbf{R}\) (with determinant \(+1\), i.e., in the special orthogonal group), which is the basic reason to prefer it: the forward pass uses an orthogonal transform and therefore preserves hyperspherical geometry by construction.

Two implementation details are important for stability and correctness. First, initialize \(\mathbf{Q}=\mathbf{0}\) so that \(\mathbf{R}=\mathbf{I}\) at the start of finetuning. This zero initialization guarantees that the finetuned model begins exactly from the pretrained weights and avoids abrupt early changes. Second, enforce skew-symmetry of \(\mathbf{Q}\) in your parameter pipeline. A convenient implementation pattern is to keep an unconstrained parameter \(\mathbf{A}\) and map it to \(\mathbf{Q}\) via

\[
\mathbf{Q} \leftarrow \tfrac{1}{2}(\mathbf{A}-\mathbf{A}^\top),
\]

so skew-symmetry is exact at every step. After you update \(\mathbf{A}\) (or \(\mathbf{Q}\) directly), recompute \(\mathbf{R}\) by forming the Cayley expression and the inverse \((\mathbf{I}-\mathbf{Q})^{-1}\). For computational efficiency and numerical robustness use a stable linear-algebra routine for the inversion and compute the inverse per-block if \(\mathbf{R}\) is block-diagonal (see next section).

Numerical issues to watch. The Cayley map requires \((\mathbf{I}-\mathbf{Q})\) to be invertible; if \(\mathbf{Q}\) approaches a matrix that makes this factor nearly singular, inversion becomes unstable. The paper leverages the small-\(\mathbf{Q}\) regime and (optionally) COFT to avoid such problems. In practice you will rarely need to re-orthogonalize \(\mathbf{R}\) after computing it from \(\mathbf{Q}\) because the Cayley form enforces orthogonality analytically; however, floating point round-off can accumulate, so it is good practice to monitor \(\mathbf{R}^\top\mathbf{R}-\mathbf{I}\) (see the monitoring section below) and to recompute \(\mathbf{R}\) cleanly from \(\mathbf{Q}\) if you detect drift.

Two further practical optimizations. First, when \(d\) (the transform dimension) is large, computing and inverting full \(d\times d\) matrices is expensive; use the block-diagonal parameterization described next to reduce cost. Second, the Neumann-series expansion gives a local approximation

\[
\mathbf{R} \approx \mathbf{I} + 2\mathbf{Q} + \mathcal{O}(\mathbf{Q}^2),
\]

so in debugging you can inspect \(\mathbf{Q}\) (which is low-dimensional for small blocks) to reason about how far \(\mathbf{R}\) has moved from identity.

# Choosing r, block sharing, and ε (for COFT)

The block-diagonal parameterization is central for controlling parameter count and flexibility. Let the neuron dimension be \(d\) and choose an integer \(r\) that splits the input dimension into \(r\) equally sized blocks of size \(d/r\). Then

\[
\mathbf{R}=\operatorname{diag}(\mathbf{R}_1,\dots,\mathbf{R}_r),\qquad \mathbf{R}_i\in \mathrm{O}\!\left(\tfrac{d}{r}\right).
\]

Counting parameters: a full orthogonal \(d\times d\) matrix has \(\tfrac{d(d-1)}{2}\) degrees of freedom. For the \(r\)-block diagonal orthogonal matrix the number of free parameters is

\[
\text{params}_{\text{OFT},r}=\frac{d\left(\tfrac{d}{r}-1\right)}{2},
\]

and if you share the same block matrix across all blocks (i.e., \(\mathbf{R}_i=\mathbf{R}_j\) for all \(i,j\)) the parameter count reduces roughly to \(\mathcal{O}\!\left(\tfrac{d^2}{r^2}\right)\). For comparison, LoRA with rank \(r'\) has an additive update parameter count

\[
\text{params}_{\text{LoRA}} = r'(d + n)
\]

for a weight matrix of size \(d\times n\). The paper gives a concrete example: for a \(128\times 128\) weight matrix, LoRA with \(r'=8\) uses \(2048\) trainable parameters whereas OFT with \(r=8\) uses \(960\).

How to pick \(r\). The parameter \(r\) controls the trade-off between flexibility and parameter efficiency. Smaller \(r\) means fewer, larger blocks (more flexible, more parameters); larger \(r\) means many small blocks (less flexible, fewer parameters). Practical strategy: pick \(r\) so that your OFT parameter budget is comparable to the competing adapter method you want to match. If you have limited memory, increase \(r\) (more blocks) and consider block sharing. If you need stronger representational capacity, reduce \(r\) (fewer larger blocks).

Choosing \(\epsilon\) for COFT. Constrained OFT (COFT) adds an explicit deviation constraint

\[
\|\mathbf{R}-\mathbf{I}\| \le \epsilon,
\]

which the paper moves into the Cayley parameter via the Neumann-series approximation to obtain an equivalent bound \(\|\mathbf{Q}\|\le\epsilon'\) for a suitable \(\epsilon'\). The qualitative effect is straightforward: smaller \(\epsilon\) keeps the finetuned model closer to the pretrained weights (stronger regularity, less flexibility), while larger \(\epsilon\) makes COFT behave like unconstrained OFT (more flexibility). The paper reports that COFT yields better finetuning stability and makes learning-rate and iteration choices less sensitive when \(\epsilon\) is set properly. Practical tuning advice: grid-search \(\epsilon\) on a small validation set while monitoring hyperspherical energy and task validation metrics; select the largest \(\epsilon\) that does not degrade the pretrained generative quality while enabling the downstream control you need.

# Optimizers, learning rates, and training schedules

The paper emphasizes that one important desideratum for a finetuning method is stability and sample efficiency. OFT and COFT were trained with the same losses and overall training frameworks used by the baselines (DreamBooth, ControlNet/T2I-Adapter) so the straightforward practical approach is to reuse the baseline’s optimizer and base learning-rate setup for direct comparisons. That said, the paper makes two empirical observations that guide tuning.

First, OFT tends to converge faster than competing parametrizations: in the controllable generation experiments the baselines were trained for 20 epochs while OFT reached similar or better performance in fewer epochs (the paper reports that LoRA took 20 epochs to reach what OFT achieved at epoch 8). For subject-driven generation, the paper shows that OFT achieves good control after 400 iterations while other methods may require longer and can even collapse after 2000 iterations. Use these empirical points as guides: start with the baseline training schedule, evaluate early, and expect OFT to require fewer epochs/iterations for similar or better results.

Second, COFT reduces sensitivity to learning-rate and iteration count. If you find hyperparameter tuning difficult (instability or sudden collapse) start with COFT and a conservative \(\epsilon\); COFT makes the optimization less brittle because it constrains the orthogonal transform close to identity.

Practical operational recipe (in prose). For a given task, prepare the same loss and data splits you would use for DreamBooth/ControlNet finetuning. Replace the parametrized layers with OFT/COFT modules and freeze \(\mathbf{W}^0\). Use the same optimizer as in your existing pipeline and a learning rate in the range that was successful for adapter-style finetuning in that pipeline. Run short pilot training with the same seed for a few validation steps, monitor the metrics described below, and adjust learning rate, \(r\), or \(\epsilon\) according to stability and convergence speed. Because OFT requires fewer iterations on average, prefer earlier validation checks.

# Projected updates for COFT and maintaining invertibility of (I − Q)

COFT requires maintaining the explicit deviation constraint \(\|\mathbf{Q}\| \le \epsilon'\). The paper recommends enforcing that constraint via projected gradient descent on \(\mathbf{Q}\). A practical per-step update looks like this (in words): after computing the gradient step producing an updated unconstrained \(\mathbf{Q}_{\text{raw}}\), first enforce skew-symmetry (set \(\mathbf{Q}\leftarrow\tfrac{1}{2}(\mathbf{Q}_{\text{raw}}-\mathbf{Q}_{\text{raw}}^\top)\)). Then compute the chosen matrix norm \(\|\mathbf{Q}\|\) and, if it exceeds \(\epsilon'\), project back onto the norm ball. If you choose the Frobenius-norm ball the projection is the simple scaling

\[
\mathbf{Q}\leftarrow \mathbf{Q}\cdot\frac{\epsilon'}{\|\mathbf{Q}\|_F}\quad\text{if }\|\mathbf{Q}\|_F>\epsilon'.
\]

If you prefer to constrain the operator (spectral) norm to be below \(\epsilon'\) (closer to the theoretical Neumann-series condition), then you must project with respect to the spectral norm (this projection is more expensive because it requires an SVD or power-iteration-based approximation). The paper leaves the norm unspecified and notes that the Neumann-series approximation requires convergence in operator norm; practically, Frobenius projection is simpler to implement and often sufficient, while spectral-norm projection is more conservative with stronger invertibility guarantees.

Why projection matters for invertibility. Maintaining \(\|\mathbf{Q}\|\) small reduces the risk that \((\mathbf{I}-\mathbf{Q})\) becomes singular or ill-conditioned. The Cayley inverse \((\mathbf{I}-\mathbf{Q})^{-1}\) will blow up if \(\mathbf{Q}\) develops an eigenvalue equal to \(1\). Enforcing \(\|\mathbf{Q}\|\le\epsilon'\) keeps you in the regime where the Neumann approximation is meaningful and \((\mathbf{I}-\mathbf{Q})\) remains numerically well-conditioned. If you ever see NaNs during the inversion step, immediately reduce \(\epsilon'\) or the learning rate and re-run the projection logic.

# Monitoring orthogonality and hyperspherical energy preservation

Monitoring is crucial during finetuning: OFT’s whole design goal is preserving the pretrained model’s pairwise neuron relationships (hyperspherical energy) while enabling controlled angular changes. Two sets of diagnostics are essential.

First, orthogonality diagnostic. For each learned \(\mathbf{R}\) (or each block), compute the residual matrix \(\mathbf{R}^\top\mathbf{R}-\mathbf{I}\) and report its norm, for instance

\[
e_{\text{ortho}}=\big\|\mathbf{R}^\top\mathbf{R}-\mathbf{I}\big\|_F.
\]

This value should remain close to zero. If it grows unexpectedly, numerical issues have appeared in the Cayley computation (recompute \(\mathbf{R}\) from \(\mathbf{Q}\) carefully, check inverses, or reduce learning rate). Because the Cayley transform enforces orthogonality analytically if implemented exactly, a non-negligible \(e_{\text{ortho}}\) indicates numerical drift or a bug in the implementation (for example, forgetting to re-impose skew-symmetry).

Second, monitor hyperspherical energy (HE). For a weight matrix \(\mathbf{W}=\{\mathbf{w}_1,\dots,\mathbf{w}_n\}\) the per-layer hyperspherical energy used in the paper is

\[
\text{HE}(\mathbf{W}) \;:=\; \sum_{i\ne j}\big\|\hat{\mathbf{w}}_i-\hat{\mathbf{w}}_j\big\|^{-1},\qquad
\hat{\mathbf{w}}_i := \frac{\mathbf{w}_i}{\|\mathbf{w}_i\|}.
\]

Compute the baseline \(\text{HE}(\mathbf{W}^0)\) before finetuning and track the difference

\[
\Delta\text{HE} = \big\|\text{HE}(\mathbf{W}) - \text{HE}(\mathbf{W}^0)\big\|.
\]

OFT is designed so that \(\Delta\text{HE}\) stays (near) zero; COFT adds extra control on how far weights move from the pretrained value. Use \(\Delta\text{HE}\) as a primary diagnostic of whether you are preserving the pretrained generative structure. If \(\Delta\text{HE}\) drifts upward and the model’s generation quality degrades, respond by tightening \(\epsilon\), increasing block-sharing or reducing learning rate.

Task-level diagnostics. In addition to these mathematical diagnostics, track the downstream metrics used in the paper depending on the task. For subject-driven generation track CLIP-I, DINO and CLIP-T for subject and prompt fidelity and LPIPS for diversity. For controllable generation compute the control-consistency metrics introduced in the paper: for C2I use IoU and F1, for S2I use mean IoU and accuracy, and for L2F use the mean \(\ell_2\) distance between control and predicted landmarks. These practical metrics tell you if finetuning is achieving the intended control goals without destroying pretrained quality.

# Folding R into W^0 for zero-overhead inference

One of OFT’s operational advantages is that the learned orthogonal transform introduces no extra inference cost after folding. After training, compute the effective weight

\[
\mathbf{W} = \mathbf{R}\,\mathbf{W}^0
\]

and (for re-scaled OFT) \(\mathbf{W} = \mathbf{R}\,\mathbf{W}^0\,\mathbf{D}\). Replace the pretrained layer’s stored parameter with this new \(\mathbf{W}\) and remove the OFT modules from the runtime model. For block-diagonal \(\mathbf{R}\), perform the block-wise matrix products and reassemble. For convolutional layers you will need to reshape the convolution kernel into a 2D matrix view that matches your \(\mathbf{R}\) orientation, apply the product, and reshape back; the logical fold remains the same: multiply \(\mathbf{R}\) into the pretrained kernel along the axis you transformed during training.

Do the folding operation with the same numerical dtype as your model weights to avoid precision mismatch (e.g., use float32 if the model uses float32). After folding, validate that forward inference results match the behavior of the finetuned model with explicit \(\mathbf{R}\) (run a few test prompts) to ensure there were no shape/alignment mistakes during folding.

# Common pitfalls and debugging tips

Below are recurring pitfalls observed and remedies suggested by the behavior described in the paper. Read these as a troubleshooting checklist.

Initialization mistakes. If you do not initialize \(\mathbf{Q}=\mathbf{0}\) you will not start from the pretrained model and the finetuned weights may drift immediately. Always zero-initialize to get the desired identity start.

Skew-symmetry enforcement. If \(\mathbf{Q}\) is not kept skew-symmetric you break the guarantee of orthogonality for \(\mathbf{R}\). Enforce skew-symmetry by parameterization or explicit projection after gradient steps.

Matrix inverse failures. During Cayley computation \((\mathbf{I}-\mathbf{Q})^{-1}\) may be ill-conditioned or singular if \(\mathbf{Q}\) grows too large. Symptoms are NaNs or Inf values. Remedy: reduce the step size (learning rate), enforce a stricter COFT \(\epsilon'\) on \(\mathbf{Q}\), or increase numerical regularization (for example, add a tiny identity times machine-epsilon before inversion). The simplest practical fix is to project \(\mathbf{Q}\) to a smaller norm ball right after each optimizer step.

Block misalignment in convolutional transforms. If you apply block-diagonal transforms to convolutional kernels be careful about the input-channel ordering and the reshaping direction when you fold \(\mathbf{R}\) into the kernel. A shape mismatch or channel-order swap will produce obviously broken outputs. Test fold-and-inference on a small input batch immediately after implementing a new layer.

Collapsed or degraded generations during long runs. The paper shows DreamBooth and LoRA can suffer collapse at large iteration counts, while OFT and COFT are more stable. If you observe degradation with OFT, switch to COFT with a conservative \(\epsilon\); COFT often restores stability and eliminates the need to carefully tune iteration count.

Parameter-budget mistakes. When matching a LoRA budget, compute OFT parameter counts using the formulas above and choose \(r\) and block sharing accordingly. A common debugging trap is to assume block sharing reduces parameters by \(r\) when in fact the asymptotic scaling differs; check the arithmetic.

Re-scaled OFT positivity. If you use the re-scaled variant with \(\mathbf{D}=\operatorname{diag}(s_1,\dots,s_n)\) ensure the diagonal entries stay positive as required by the method statement. Parameterize those scalars in a numerically stable way (for example, learn log-scales or apply a positive-transformation) so the forward pass obeys the assumption that the diagonal elements are positive.

Monitoring and early-validation. Because OFT/COFT aim to preserve pretrained generalizability while enabling control, rely on the two-tier monitoring approach (mathematical diagnostics + task metrics). Run short validation checks frequently; visual inspection of generated samples together with the quantitative diagnostics will usually point quickly to what to change (reduce \(\epsilon\), increase block-sharing, or change the learning rate).

Multi-task composition (caution). The paper notes an intriguing open direction: learned orthogonal matrices from multiple finetuning tasks can be multiplied to remain orthogonal. If you plan to experiment with sequential task composition (multiply \(\mathbf{R}\) matrices), be aware that whether the product preserves all downstream behaviors is an open question and requires careful empirical validation.

A minimal debug workflow in prose. If you see problems: (1) confirm \(\mathbf{Q}\) initialized to zero and \(\mathbf{R}\) starts as identity; (2) check \(\mathbf{Q}\) remains skew-symmetric after optimizer steps; (3) verify \((\mathbf{I}-\mathbf{Q})\) is invertible (no NaNs in inverse); (4) monitor \(e_{\text{ortho}}\) and \(\Delta\text{HE}\); (5) if instability persists switch to COFT and tighten \(\epsilon\); (6) fold \(\mathbf{R}\) into \(\mathbf{W}^0\) on a test set and confirm identical outputs before deploying.

---

This chapter collected the practical implementation decisions that follow directly from the OFT/COFT method and the experiments reported in the paper: layer targets (attention projections are a good default), Cayley-based orthogonal modules with zero initialization, block-diagonal and block-sharing parameterizations to control parameter cost, COFT projection of \(\mathbf{Q}\) to keep the Cayley inverse safe, monitoring of orthogonality and hyperspherical energy as explicit diagnostics, and folding the learned transforms into \(\mathbf{W}^0\) for zero-overhead inference. These practices reproduce the design principles and empirical stability advantages reported in the paper and provide a concise recipe for bringing OFT/COFT into an existing diffusion finetuning pipeline.

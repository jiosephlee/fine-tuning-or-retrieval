\title{Stack Exchange of the Paper: "LongRoPE: Extending LLM Context Window Beyond 2 Million Tokens"}

### How is the initial-token threshold \(\hat{n}\) applied with sliding windows and streaming evaluation?
Question:
You keep the first \(\hat{n}\) tokens un-interpolated (\(\lambda_i\) not applied) because early tokens are heavily attended. But for perplexity on long documents you use sliding windows (e.g., size 256 or 256k). Are the "first \(\hat{n}\) tokens" measured relative to the global document start, or relative to each window’s local start? If it is global, how do you handle windows that start well beyond \(\hat{n}\)? If it is local, then each window reintroduces an unscaled prefix, which seems different from the intended global behavior.
Answer:
Short answer: the paper treats $\hat{n}$ as a global, document-level threshold. In LongRoPE the test/dev samples are considered as full documents and the paper's notation uses the absolute token index $n\in[0,|\mathbf{x}|)$; the rescaling mask is
$$
\mathbb{I}(\hat{\lambda}_i,\hat{n})=\begin{cases}
1 & n<\hat{n},\\[4pt]
1/\lambda_i & n\ge\hat{n},
\end{cases}
$$
so the “keep-first-$\hat{n}$” rule applies to those absolute positions in the original document (see the problem formulation / Eq. in the paper).

Why this matters for sliding windows: when you evaluate a long document with sliding windows you should still supply RoPE with the absolute position indices of each token. Concretely, if a window starts at document offset $o$ and the j-th token inside that window has local index $j$, its RoPE angle is computed with absolute position $n=o+j$. You check the condition $n<\hat{n}$ with that absolute $n$; if the whole window is past $\hat{n}$ then every token in that window will be interpolated. Resetting positions to $0$ at each window (i.e. treating $\hat{n}$ relative to the local window start) would repeatedly reintroduce an “unscaled prefix” for every window and therefore change the model semantics and evaluation in a way the paper explicitly avoids.

Intuition: RoPE encodes absolute position via rotations (angles proportional to $n$), and LongRoPE’s $\hat{n}$ design is intended to preserve only the true early-document positions (which empirically get more attention). If you reset positions per-window you artificially make many tokens look like “early” tokens and would get an optimistic, but not faithful, measure of long-context behavior. Practically, implementers therefore pass a position offset when forming position ids (e.g. $position\_ids = offset + arange(seq\_len)$) or stream tokens incrementally (KV cache with increasing absolute positions) so the threshold test uses the global $n$.

\title{Stack Exchange of the Paper: "LongRoPE: Extending LLM Context Window Beyond 2 Million Tokens"}

### How does the RoPE base \(\theta\) affect LongRoPE, and do schedules transfer across bases?
Question:
In RoPE, \(\theta\) (often \(10^4\)) sets the base frequencies, and \(\beta=\theta^{2/d}\). Some models use larger bases (e.g., \(10^5\) or \(10^6\)). If you learn \(\lambda_i\) for \(\theta=10^4\), can you reuse them for \(\theta=10^6\), or must you re-run the search? Is there a base-invariant way to express the learned schedule (e.g., as a function of normalized frequency)?
Answer:
Short answer: mathematically you can convert a LongRoPE schedule between RoPE bases exactly, so you do not strictly need to re-run the full search — but in practice you should at least validate (and usually re-seed a short search) because of discretization, bounds/monotonicity constraints and empirical interactions with fine‑tuning.

Why and how (derivation). The paper writes each (pre‑rescale) rotary angle as
$\alpha_{i}(n)=n\theta_i = n/\beta^{\,i}$ with $\beta=\theta^{2/d}$. LongRoPE applies a per‑dimension rescale $1/\lambda_i$ so the rescaled angle is
$$\tilde\alpha_{i}(n)=\frac{1}{\lambda_i}\,\frac{n}{\beta^{\,i}}.$$
If you have a schedule $\{\lambda_i^{(0)}\}$ that was found for base $\theta_0$ (with $\beta_0=\theta_0^{2/d}$) and you want an equivalent schedule for base $\theta_1$ (with $\beta_1=\theta_1^{2/d}$) you require
$$\frac{1}{\lambda_i^{(1)}}\frac{n}{\beta_1^{\,i}}=\frac{1}{\lambda_i^{(0)}}\frac{n}{\beta_0^{\,i}}\quad\text{for all }n,$$
which gives the closed form conversion
$$\boxed{\;\lambda_i^{(1)}=\lambda_i^{(0)}\left(\frac{\beta_0}{\beta_1}\right)^{i}
=\lambda_i^{(0)}\left(\frac{\theta_0}{\theta_1}\right)^{\!2i/d}\;.}$$
Equivalently you can store the base‑independent per‑dimension angular multiplier
$$a_i=\frac{1}{\lambda_i}\frac{1}{\beta^{\,i}}\;,$$
and recover $\lambda_i$ for any base $\beta$ by $\lambda_i=1/(a_i\beta^{\,i})$.

Intuition. Changing $\theta$ shifts the whole geometric frequency ladder of RoPE; the factor $(\theta_0/\theta_1)^{2i/d}$ rescales that ladder dimension‑by‑dimension. So to keep the *actual* rotary angles (and thus attention geometry) the same you must compensate by an $i$‑dependent factor. In log space the change is linear in $i$: $\log\lambda_i^{(1)}=\log\lambda_i^{(0)}+\frac{2i}{d}\log(\theta_0/\theta_1)$.

Practical caveats (why you might still re-run or refine search). The conversion above is exact only if you want to reproduce the same numerical rotary angles. In practice:

- LongRoPE enforces monotonicity $\lambda_i\le\lambda_{i+1}$ and clamps $\lambda_i$ to a search range; applying the analytic mapping can produce values outside those bounds or slightly violate monotonicity. You should project/clamp and re‑enforce monotonicity (or use the mapped schedule as an initial seed for the evolutionary search).
- The search outputs are discretized (step size $0.01$ in the paper) and optimized for a particular model checkpoint and fine‑tuning state. If the model weights change (different fine‑tuning, different training length, different target extension ratio $s$) the mapped schedule may be suboptimal.
- Large changes in $\theta$ (orders of magnitude) can produce large per‑dimension multipliers for high‑index dims, so empirical validation is important.
- The search also includes the token‑threshold $\hat n$ (how many starting tokens keep original RoPE). That value does not depend on $\theta$ and can normally be reused, but you should validate it too.

Recommended workflow. If you have a schedule learned at $\theta_0$ and want to move to $\theta_1$:

1. Compute $\lambda_i^{(1)}$ by the formula above (or compute/store the base‑independent $a_i$ and reproject).
2. Clamp / project to your allowed range and re‑enforce monotonicity (simple monotone projection).
3. Validate perplexity / a small passkey retrieval test. If performance is acceptable, you can use it directly.
4. Otherwise use the transformed schedule as an initial population for a short LongRoPE evolutionary search (much cheaper than full fine‑tuning) to refine.

Base‑invariant parameterizations. Two natural, more transfer‑friendly ways to represent a schedule are (a) store the absolute per‑dimension angular multiplier $a_i$ defined above (this is exactly base‑independent), or (b) parameterize $\lambda$ as a smooth function of normalized dimension index $i/(d/2-1)$ or of log‑frequency. The paper’s monotone, per‑dimension treatment already implies the schedule is smooth in $i$, so using a low‑dimensional parametric form (e.g. a small set of control points in log‑frequency space) can make transfer across $\theta$ easier and reduce the need for full re‑search.

Bottom line: you do not have to completely re‑run LongRoPE to move between RoPE bases because there is a simple analytic conversion. But for robustness (bounds, monotonicity, discretization and empirical fine‑tuning effects) it is wise to validate and, in many cases, run a short refinement search using the analytically mapped schedule as an initial guess.

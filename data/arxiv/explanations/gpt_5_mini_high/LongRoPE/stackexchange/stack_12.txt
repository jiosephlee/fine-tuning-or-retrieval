\title{Stack Exchange of the Paper: "LongRoPE: Extending LLM Context Window Beyond 2 Million Tokens"}

### Passkey retrieval at 2M tokens: is the key truly within the active attention window at answer time?
Question:
For the passkey retrieval setup, the key is uniformly placed anywhere up to \(L'=2{,}048\text{k}\). During generation of the answer, does the attention mechanism have access to the entire prefix simultaneously, or do you process the document in chunks and carry some compressed state? If chunked, what guarantees that the key is still represented and not evicted when the question is asked at the end?
Answer:
Short answer: the passkey experiments in the paper are testing the model with the full extended context in the active attention window, not a chunk‑and‑compress pipeline. LongRoPE is a positional‑embedding (RoPE) modification that preserves the standard self‑attention mechanism across an input of length up to $L'=2{,}048\text{k}$, so the passkey (placed uniformly anywhere in that $L'$) is inside the model’s reachable attention scope at answer time.

Why: LongRoPE does not introduce an external memory, summary states, or a streaming/compression mechanism. It changes only how rotary positional angles are scaled (per RoPE dimension and with an optional untouched prefix of size $\hat{n}$), so the model’s queries and keys still exist for every token in the input and standard $QK^T$ attention is computed across the whole prefix. In other words, the model’s attention matrix still includes pairwise interactions between the question token(s) and every token in the $L'$‑length prefix; the RoPE rescaling just attempts to keep those pairwise signals meaningful even at very large distances. The paper’s reported passkey accuracies (e.g. $\gtrsim 90\%$ up to $2{,}048\text{k}$ for LongRoPE‑LLaMA2) are exactly the empirical evidence that the model can attend to and recover a randomly placed five‑digit passkey from the full prompt.

What about chunking / compressed states? The paper explicitly contrasts LongRoPE with retrieval/streaming approaches (which do modify architecture to hold compressed memory or use chunked processing). LongRoPE is described as “retain[ing] the original architecture with minor modifications to the positional embedding” and the experimental setup (prompt template in the appendix, passkeys placed uniformly across the evaluation context length) indicates the full long document was given to the model as context. If you were to implement your own $2M$‑token inference by processing chunks and compressing intermediate chunks, you would be in a different design space and would need to ensure your compressor preserves exact token info (or an index) so the passkey is not evicted — that is not what the authors did or relied on.

Practical caveat: feeding millions of tokens into vanilla self‑attention is extremely costly (quadratic compute/memory). The paper doesn’t change attention complexity; it instead relies on the positional interpolation + fine‑tuning to make those attention computations meaningful at large $L'$, and notes that existing attention optimizations can be reused. In practice reproducing these experiments requires specialized, memory‑efficient attention implementations or distributed execution; but that is an engineering concern separate from the methodological point that the model’s active attention window truly contains the whole $2{,}048\text{k}$ prefix in the paper’s passkey tests.

If you want to be $100\%$ certain for their run: check the appendix / code (they will release it) for the exact inference pipeline they used; but based on the text and reported results, the passkey is inside the active attention window rather than only being represented in some compressed intermediary.

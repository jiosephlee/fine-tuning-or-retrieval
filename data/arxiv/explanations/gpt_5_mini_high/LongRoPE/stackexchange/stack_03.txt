\title{Stack Exchange of the Paper: "LongRoPE: Extending LLM Context Window Beyond 2 Million Tokens"}

### Does \(d\) denote per-head dimension in RoPE, and are \(\lambda_i\) shared across heads and layers?
Question:
RoPE is typically applied per attention head. In LLaMA2-7B, \(d_{\text{model}}=4096\), \(n_{\text{heads}}=32\), so \(d_{\text{head}}=128\). In Eq. (1), is \(d\) meant to be \(d_{\text{head}}\) (so there are \(d/2=64\) sine-cosine pairs per head)? When you search per-dimension \(\lambda_i\), are these \(\lambda_i\) values shared across all heads and all layers, or are they distinct per head/layer? Implementation-wise, what exactly is the tensor shape over which \(\lambda_i\) is broadcast?
Answer:
Short answer: yes — in the paper $d$ is the per‑head RoPE dimension (so for LLaMA2‑7B with $d_{\text{model}}=4096$ and $n_{\text{heads}}=32$ you get $d_{\text{head}}=128$ and $d/2=64$ cosine–sine pairs), and the searched $\lambda_i$ are a single vector over those RoPE dimensions that is shared across heads and layers (i.e. one $\lambda_i$ per RoPE frequency index, not per head or per layer). The paper’s equations and search description treat the rescale factors as a $d/2$‑length array that is broadcast across batch/sequence/head/layer when applied.

Why: the paper explicitly formulates the search over each RoPE dimension index $i=0,\dots,d/2-1$ and repeatedly uses $d/2=64$ in its examples and complexity counts (for example they write $s=4\times$ search space size as $400^{128/2}\times 14$, which shows they are using $d=128$). the monotonicity constraint is described as "$\lambda_i\le\lambda_{i+1}$ … $i=0,\dots,63$", again making $d=128$ (head dim). There is no per‑head or per‑layer indexing in the search formulation, so the paper’s method learns one $\lambda_i$ per RoPE frequency index and applies it uniformly to all heads and all layers.

Implementation/shape practicalities: in code you can think of the searched vector as an array of length $D_h/2$ (with $D_h$ the head dimension). Typical attention tensors have shape $(B, T, H, D_h)$ (batch, seq_len, n_heads, head_dim). You compute the RoPE angles for pairs ($\cos/\sin$) with a base angle tensor of shape $(T, D_h/2)$ and then apply the scale factors broadcast over batch and heads. Concretely, let $\lambda$ be shaped $(D_h/2,)$; compute

angles = positions[:, None] * inv_freq[None, :]    # shape $(T, D_h/2)$

scale = 1.0 for positions < $\hat{n}$, else scale = 1.0 / $\lambda$  # shape $(T, D_h/2)$

angles = angles * scale                             # shape $(T, D_h/2)$

then expand to $(T, 1, 1, D_h/2)$ to multiply with $Q/K$ components (which you typically split into even/odd pairs so the final $\cos/\sin$ tensors broadcast to $(B, T, H, D_h/2)$ or interleaved back to $(B, T, H, D_h)$). In short, the searched $\lambda_i$ is stored as a 1‑D vector of length $D_h/2$ and broadcast over batch, time, head and layer axes when forming the rotary $\cos/\sin$ matrices.

If you wanted per‑head or per‑layer $\lambda$ you could implement that by making the vector shape $(H, D_h/2)$ or $(L, H, D_h/2)$, but the paper does not do this (and doing so would explode the search space and defeat the paper’s search/monotonicity assumptions).

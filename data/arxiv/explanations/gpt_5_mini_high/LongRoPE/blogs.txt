# From 4K to 2 Million: Inside LongRoPE’s Record-Breaking Context Window

Large Language Models (LLMs) are getting smarter at many tasks, but their ability to reason over long documents remains limited by a single bottleneck: the context window. LongRoPE is a practical, surprisingly simple-sounding advance that pushes RoPE-based LLMs from the standard 4K tokens to a record-setting $2{,}048{,}000$ tokens (2048k) — while using only about 1k fine-tuning steps at an intermediate 256k length. This post walks through why long context is hard, what breaks as you push it, and the three ideas that make LongRoPE work: smarter positional interpolation, a progressive extension recipe, and a short-context recovery step.

## Why context windows matter — and why they break

A model’s context window is the maximum number of tokens it can attend to. Bigger windows unlock long-document summarization, many-shot in-context learning, and agent-style behavior that reasons across long histories. But simply increasing the maximum token index causes three practical failure modes:

- Catastrophic new positions. Positional encodings (RoPE in modern LLMs) were never trained on very large position indices. New indices act like out-of-distribution inputs and can produce “catastrophic” prediction behavior.
- Data and compute scarcity. Training on documents of length 100k–2M is rare and extremely expensive; naively fine-tuning to such lengths is often infeasible.
- Short-context degradation. If you rescale positions to cover a huge range, the representations for short sequences become “crowded” and model quality inside the original window (e.g., 4K) can drop.

Prior mitigation strategies include Position Interpolation (PI), NTK-style unequal scaling, and YaRN’s hand-designed grouping of RoPE dimensions. They help, but they either overly crowd positions, rely on heuristics, or hit a practical non-fine-tuning ceiling (typically around $4\times$ extension).

## A quick refresher: what RoPE looks like

RoPE encodes position $n$ with paired sin/cos features per rotational frequency. For a simplified view:

$[ \cos(n\theta_0),\; \sin(n\theta_0),\; \cos(n\theta_1),\; \sin(n\theta_1),\; \dots ]$

where $\theta_i$ sets frequency for the $i$-th pair. Position interpolation methods effectively rescale these rotation angles so the model can reuse the pretrained positional structure for larger $n$.

## LongRoPE — the three ideas, at a glance

LongRoPE succeeds by exploiting two kinds of non-uniformity in RoPE and by using those discoveries in a pragmatic training recipe:

1. Smarter positional interpolation via per-dimension, position-aware scaling. Instead of a single global scale, LongRoPE searches for a rescale factor $\lambda_i$ per RoPE dimension and a token-threshold $\hat{n}$ so that tokens with $n<\hat{n}$ keep the original RoPE and tokens with $n\ge\hat{n}$ receive the scaled angles. Formally, each rotary angle is replaced by
   $\mathbb{I}(\hat{\lambda}_i,\hat{n})\times\frac{n}{\beta^i}$,
   where $\mathbb{I}$ equals $1$ if $n<\hat{n}$ and $1/\lambda_i$ otherwise. Exploiting both dimension-wise and token-position non-uniformity preserves the crucial high-frequency dimensions and the early tokens that attract most attention.
2. A progressive extension strategy that avoids training directly on million-token sequences. LongRoPE first searches and fine-tunes at 128k–256k, using a relatively small number of steps (about 400 + 600 steps in the LLaMA2 experiments). Then it runs a second search on the already fine-tuned 256k model to extrapolate to $2{,}048{,}000$ tokens — without further million-token fine-tuning.
3. Short-context recovery. Extremely large-scale interpolation tends to harm short-window performance. LongRoPE runs an additional constrained search targeting short lengths (e.g., 4k, 8k) and keeps multiple RoPE rescale profiles; at inference time the model picks the appropriate profile depending on sequence length.

Those three pieces give both a robust initialization for fine-tuning and substantial non-fine-tuning gains (up to an $8\times$ extension without any update).

## Why the per-dimension / per-position search matters

Empirically the authors found two key non-uniformities:

- RoPE dimensions are not interchangeable. Lower dimensions (higher frequency) encode fine-grained positional distinctions and should be scaled less; higher dimensions can tolerate more aggressive scaling.
- The earliest token positions are special. Tokens near the start of a sequence often receive large attention weights; preserving their original RoPE (no scaling) helps.

Combining both ideas means LongRoPE searches for a vector of per-dimension scaling factors $\{\lambda_i\}$ and a token threshold $\hat{n}$. The search space is huge — for realistic extension ratios it explodes combinatorially — so LongRoPE uses an evolution-based search with a few practical speedups:

- Seed the initial population with PI / NTK / YaRN baselines rather than pure random.
- Enforce monotonicity across dimensions: $\lambda_i \le \lambda_{i+1}$ (lower-frequency dims get no more scaling than higher-frequency dims). This reduces bad candidates and aligns with NTK intuition.
- Evaluate candidates by computing next-token perplexity on a handful of long samples (cheap compared to full fine-tuning).

Search details used in the experiments (for targets within 256k): population $P=64$, mutation/crossover sizes $N_1=N_2=16$, mutation probability $p=0.3$, and iterations $T=40$, selecting top-32 each iteration. For very large windows they halve population sizes to save compute.

The practical outcome: with the searched non-uniform rescale, LLaMA2 can be extended from 4k to 32k ($8\times$) without any fine-tuning, whereas PI/NTK/YaRN spike in perplexity much earlier.

## The progressive 4K→256K→2,048K recipe

Training directly to million-token windows is impractical. LongRoPE uses a staged, resource-conscious plan:

- Search the best per-dimension rescale for 128k and 256k on the pretrained model.
- Fine-tune the model to 256k in two sub-steps: 400 steps using the 128k rescale, then switch to the 256k rescale and train another 600 steps. In the LLaMA2 experiments this amounted to ~1,000 steps total and required moderate GPU counts (128k steps on 8 A100s; 256k training used 16 A100s).
- Take the fine-tuned 256k checkpoint and run a second rescale search (same evolution machinery) targeting 2,048k. Apply that second-stage rescale to the 256k-finetuned model — no extra million-token fine-tuning required. The final overall extension ratio is $512\times$ from the original 4k.

For Mistral the paper used a slightly different fine-tuning config (constant LR $1\mathrm{e}{-6}$, global batch 64, 400 steps with 16k training sequences on 4 A100s), but the progressive idea is the same.

## Recovering short-context performance

Large rescaling can leave short-window performance worse. LongRoPE mitigates this by running constrained searches targeted at short windows (4k, 8k), limiting maximum allowed $\lambda$ so interpolation is milder. During inference the model uses the rescale profile appropriate for the current sequence length (for example, the short-window profile when the input is below 8k). This readjustment meaningfully recovers perplexity and benchmark performance within the original context sizes.

## What the experiments show

The authors applied LongRoPE to LLaMA2-7B and Mistral-7B and evaluated:

- Perplexity on long documents (Proof-pile, PG19, Books3). LongRoPE-2048k models maintain low perplexity from 4k all the way to 2,048k and outperform or match state-of-the-art baselines inside 256k evaluation lengths.
- Passkey retrieval (a synthetic test that hides a five-digit key somewhere in a long document). LongRoPE-LLaMA2-2048k (ft=256k) retains high retrieval accuracy (≥90%) across lengths from 4k to 2,048k. LongRoPE-Mistral-2048k (ft=128k) keeps 100% up to about 1.8M then drops to ~60% at 2.048M, consistent with observed perplexity trends.
- Standard short-window benchmarks. After short-context recovery, LongRoPE-2048k models achieve comparable performance on standard benchmarks within the original context window (e.g., 4k/8k tasks).

Two practical takeaways from experiments: (1) the non-uniform rescale gives strong non-fine-tuning gains (an $8\times$ extension without any model updates), and (2) a small amount of targeted fine-tuning (≈1k steps at 256k) plus a second-stage rescale search yields a working 2M-token model.

## Practical notes and limitations

- LongRoPE is built on RoPE and applies to models that use RoPE positional encodings (it leaves architectures mostly unchanged; only positional embedding is modified).
- It is intentionally pragmatic: the evolving search is evaluated with small sample sets for efficiency, and the progressive fine-tune strategy avoids the prohibitive cost of million-token training.
- The method does not magically remove all model-specific quirks: the paper finds Mistral behaved differently from LLaMA2 at extreme lengths, and short-window recovery is necessary to avoid degradation.
- There is still an up-front search cost and modest fine-tuning cost (the paper’s LLaMA2 recipe uses 400+600 steps and nontrivial GPU resources), but it is far less than training from scratch or fine-tuning directly at million-token lengths.

## Bottom line

LongRoPE shows that careful, data-driven exploitation of non-uniformities in RoPE — per-dimension scaling and selective preservation of early token positions — plus an evolution search and a progressive fine-tuning plan can push RoPE-based LLMs from 4K to $2{,}048{,}000$ tokens. The approach combines (1) a principled interpolation/search idea that preserves the most informative positional components, (2) a practical staged fine-tuning recipe that avoids million-token training, and (3) a short-context recovery step so you don't lose the original model behavior. The authors will release the code and LongRoPE-2048k models (see https://github.com/microsoft/LongRoPE).

If you work with RoPE-based models and long-context problems, LongRoPE is an approach to try: it’s lightweight in terms of architecture changes, reuses most optimizations, and targets the expensive parts of long-context training where they matter most.



# The Non-Uniform Secret: How LongRoPE Rewrites Positional Interpolation

Large context windows are one of the clearest bottlenecks for deploying LLMs on very long documents. The dominant practical approach—rescaling RoPE (rotary position embeddings) uniformly—either crowds token positions (linear interpolation) or relies on hand-designed rules (NTK-aware or group-wise schemes such as YaRN). LongRoPE takes a different tack: positional interpolation is inherently non-uniform in two ways, and explicitly searching for that non-uniformity unlocks much larger extensions with little or no fine-tuning.

This post explains the two non-uniformities LongRoPE exploits, how the method turns interpolation into a search problem, and why a simple evolutionary search (plus a monotonicity constraint and a few engineering choices) can extend a pretrained LLM from 4k to 32k tokens without fine-tuning — and form the stepping stone to multi-million-token windows with minimal fine-tuning.

## Quick primer: RoPE and the interpolation problem

RoPE represents the position of token $n$ by rotating query/key sub-vectors with angles that scale with $n$ and with each RoPE dimension's frequency. A compact view of the per-position encoding is
\[
\left[\cos(n\theta_0),\ \sin(n\theta_0),\ \cos(n\theta_1),\ \sin(n\theta_1),\ \ldots\right],
\]
where the rotation angles grow roughly like $n/\beta^i$ for dimension index $i$ (with $\beta$ derived from the RoPE base). When you extend an LLM's context window from length $L$ to $L'$, most methods simply rescale angles by a global factor related to the extension ratio $s=L'/L$. That naive rescaling tends to "crowd" nearby positions into similar embeddings and causes performance drops.

LongRoPE starts from a simple observation: not all RoPE dimensions and not all token positions are equal. Treating them uniformly throws away information we can preserve.

## The two non-uniformities LongRoPE exploits

LongRoPE identifies and leverages two complementary forms of non-uniformity in positional interpolation.

1. Per-dimension non-uniformity ($\lambda_i$): different RoPE dimensions encode position at different spatial frequencies. Low-index (high-frequency) dimensions carry fine-grained positional distinctions and should be scaled less; high-index (low-frequency) dimensions tolerate more aggressive scaling. Rather than applying one scale $s$ to every dimension, LongRoPE searches for a separate rescale factor $\lambda_i$ for each RoPE frequency dimension.

2. Token-position non-uniformity ($\hat{n}$): the earliest tokens in a sequence typically receive much stronger attention and act as anchors for downstream processing. LongRoPE allows the first $\hat{n}$ token positions to keep their original RoPE angles (no interpolation), and only applies per-dimension rescaling for positions $n \ge \hat{n}$. Empirically, keeping a small prefix unscaled improves modeling and the optimal $\hat{n}$ depends on the target extension length.

Formally LongRoPE uses a per-dimension rescale and a prefix threshold via the indicator
\[
\mathbb{I}(\hat\lambda_i,\hat n) =
\begin{cases}
1 & n < \hat{n},\\[4pt]
\frac{1}{\lambda_i} & n \ge \hat{n},
\end{cases}
\]
so the applied rotation angle becomes $\mathbb{I}(\hat\lambda_i,\hat n)\,\frac{n}{\beta^i}$ for the $i$th RoPE dimension at position $n$.

## Framing interpolation as a search problem

Once you admit per-dimension scales $\{\lambda_i\}$ and a prefix threshold $\hat{n}$, the number of candidate interpolations explodes. LongRoPE frames the task as: find $(\{\lambda_i\},\hat{n})$ that minimize next-token loss (perplexity) on long-context samples from a validation set.

The designed search space (as used in the paper) includes:

- Per-dimension scales $\lambda_i$ in $[1.0,\, s\times 1.25]$ with step $0.01$ (where $s$ is the target extension ratio). The lower bound $1.0$ allows pure extrapolation for a dimension, and the upper bound allows slightly stronger interpolation than linear PI.
- Prefix thresholds $\hat{n} \in \{0,1,2,4,8,12,16,20,24,28,32,64,128,256\}$, so we can try preserving varying numbers of initial tokens.

This is a huge combinatorial space (the paper gives an illustrative count: even modest settings yield astronomically many combinations). Exhaustive or naive random search is infeasible, so LongRoPE uses an evolutionary strategy with a few practical accelerations.

## The evolutionary search that finds per-dimension rescaling

LongRoPE uses a population-based evolutionary search guided by perplexity computed on a small number of long-document validation examples. The core pieces that make it practical and effective are:

- Seeding the initial population with strong priors. Instead of pure random starts, the initial population contains the standard PI, NTK, and YaRN rescale patterns as individuals, and other members are mutated variants of those seeds. This gives evolution a head start in promising regions of the space.
- Mutation and crossover operators with a mutate probability $p$ to explore local variations around good candidates.
- Evaluating each candidate by applying its $(\{\lambda_i\},\hat{n})$ to the target model and measuring perplexity (the search objective).
- Selecting top-performing candidates as parents, repeating mutation/crossover and evaluation for a fixed number of iterations.

Concrete search hyperparameters used in the experiments (for target windows within 256k) were: population size $P=64$, mutation/crossover sizes $N_1=N_2=16$, mutation probability $p=0.3$, and iterations $\mathcal{T}=40$, keeping the top-32 each generation. For windows over 512k the population and operator sizes were halved. Perplexity during search was computed on a handful of samples (e.g., 5 PG19 validation samples for $\le$256k) so the search remains cheap.

## The monotonicity constraint: cheap and theoretically sensible

A key practical trick is to require the candidate per-dimension scales to be monotonically non-decreasing across RoPE dimensions:
\[
\lambda_0 \le \lambda_1 \le \lambda_2 \le \cdots
\]
Two reasons this pays off:

- Efficiency: enforcing monotonicity prunes a huge fraction of the search space so the evolutionary operators spend time on sensible candidates rather than random configurations that violate NTK intuitions.
- Theory-consistency: NTK-based analyses (and prior empirical work) indicate lower-index RoPE dimensions have higher frequencies and should be scaled less. The monotonic constraint encodes that prior and prevents pathological scalings.

Enforcing monotonicity preserves expressivity (we still allow per-dimension variation) while making search tractable and more robust.

## What the search buys you: up to 8× extension without fine-tuning

The net effect of per-dimension rescaling plus prefix preservation is that LongRoPE preserves the most informative parts of the pretrained RoPE embedding and only stretches the parts that can tolerate it. That dramatically reduces the "catastrophic values" introduced by naive interpolation.

Empirically, using this search LongRoPE extended a pretrained LLaMA2-7B from a 4k to a 32k context (an 8× increase) without any fine-tuning and with steady perplexity behavior across the extended range. By contrast, simple PI or prior non-uniform schemes either force fine-tuning or show perplexity spikes after much smaller extensions (commonly hitting trouble beyond 2×–4×).

That 8× non-fine-tuning extension is a low-effort, high-impact result: it lets you reuse a pretrained LLM almost as-is for much longer contexts and gives a much better initialization when further fine-tuning is required for still larger windows.

## From 8× to 2048k: a pragmatic progression (summary)

For extensions beyond the non-fine-tuning regime, LongRoPE uses a pragmatic progressive strategy: search and apply rescale factors to reach 128k–256k, then fine-tune the model briefly at those lengths, and finally run a second search on the fine-tuned model to push to much larger windows (the paper demonstrates a 2048k window). In the paper's LLaMA2 experiments this pipeline uses about 400 steps of fine-tuning at 128k and another 600 at 256k (about 1k total), followed by a second non-uniform search to reach 2048k. The same non-uniform search machinery that gave 8× non-fine-tuning extension is therefore also the enabler for much larger, production-scale windows with limited fine-tuning cost.

LongRoPE also addresses the common short-context degradation that interpolation can cause: after the extreme extension, the authors run a short-length readjustment search (with lower maximum $\lambda$ allowed) to recover performance on standard 4k/8k workloads and switch rescale factors dynamically at inference depending on sequence length.

## Practical takeaways

- Positional interpolation is not one-size-fits-all. RoPE dimensions carry different kinds of position information and should be treated differently.
- Early tokens matter more: preserving a small unscaled prefix ($\hat{n}$) stabilizes attention and reduces perplexity.
- Turning interpolation into a constrained search problem (per-dimension scales + prefix threshold) and solving it with a seeded evolutionary search yields large gains. A monotonicity constraint both speeds up search and encodes sensible, theory-aligned structure.
- With this approach you can get substantial (e.g., 8×) context enlargement without fine-tuning, and you can reach multi-million-token windows with modest, focused fine-tuning plus a second non-uniform search.

LongRoPE shows that much of the “catastrophe” from adding new positions is avoidable: carefully preserving the right frequencies and the right early positions keeps the pretrained model’s inductive biases intact while letting it address much longer contexts.



# Stepwise to 2M: LongRoPE’s Progressive Extension, Explained

TL;DR — LongRoPE gets from the usual 4k context window to 2,048k tokens by (1) searching for per-dimension, non-uniform RoPE rescale factors for 128k and 256k; (2) fine-tuning briefly at 256k (400 + 600 steps for LLaMA2); and (3) running a second non-uniform search on the 256k-finetuned model to jump to 2,048k without further fine-tuning. This avoids direct training on million-token sequences (which are scarce and expensive), stabilizes learning, and preserves short-context behavior via a final short-length readjustment.

## The problems you hit when you try to go to millions of tokens

There are three practical obstacles when you try to extend a pre-trained LLM’s context window far beyond its original length:

- Catastrophic new positions. New token indices that the model never saw at pretraining inject large, out-of-distribution positional values, making fine-tuning unstable.
- Data and compute scarcity. Very long texts (hundreds of thousands or millions of tokens) are rare; training on them requires extreme compute and long wall-clock time.
- Short-context degradation. When you stretch positional embeddings aggressively, attention spreads and the model can lose performance inside its original short window.

LongRoPE tackles these by minimizing the information loss introduced by positional interpolation and by avoiding direct fine-tuning on million-token sequences.

## Quick primer: RoPE and positional interpolation

RoPE encodes position by rotating pairs of embedding coordinates with angles proportional to the token position. If you want to extend the context from length $L$ to $L'$, you typically downscale rotation angles so that new positions map back into the trained angle range. The extension ratio is
$s = \frac{L'}{L}$.

Existing strategies include linear positional interpolation (PI), NTK-style dimension-aware scaling, and YaRN’s three-way grouping. LongRoPE’s key insight is that positional interpolation should be non-uniform both across RoPE dimensions and across token positions: different RoPE dimensions (frequencies) need different rescale factors $\lambda_i$, and the earliest tokens often warrant less interpolation (a token cutoff $\hat{n}$).

LongRoPE searches for these two degrees of freedom: per-dimension rescale factors $\{\lambda_i\}$ and a token-threshold $\hat{n}$ that keeps the first $\hat{n}$ tokens unmodified.

## The core recipe to 2,048k (the step-by-step)

Below is the concise, reproducible strategy used in the paper (worked examples use LLaMA2 and Mistral):

1. Search on the pre-trained model for 128k and 256k rescale factors.
   - Run LongRoPE’s evolutionary search to find per-dimension $\lambda_i$ and a token-threshold $\hat{n}$ for target lengths 128k and 256k.
   - The search is seeded with PI, NTK, and YaRN candidates (not purely random), enforces monotonicity $\lambda_i \le \lambda_{i+1}$ across dimensions, and evaluates candidates by perplexity on long validation samples.
   - This gives a good initialization that preserves important RoPE dimensions and important early-token behavior.

2. Fine-tune to 256k in two stages (LLaMA2 recipe from the paper).
   - Phase A: fine-tune the pretrained model for 400 steps using the 128k rescale factors (this eases the model into longer positions).
   - Phase B: switch to the 256k rescale factors and fine-tune another 600 steps.
   - For LLaMA2 the paper used a learning rate of 2e-5 with linear decay, global batch size 32, and RedPajama data chunked into 128k segments. The 128k stage used 8 A100 GPUs; 256k stage used 16 A100 GPUs.
   - Total fine-tuning is therefore about 1k steps (400 + 600) at sequence lengths up to 256k.

3. Secondary search on the 256k-finetuned model to reach 2,048k.
   - After fine-tuning at 256k, run LongRoPE’s evolutionary search again on this fine-tuned checkpoint, but target 2,048k.
   - Because the fine-tuned model already learned positional behavior up to 256k, the search can find a non-uniform Rescale that extends to $2,048\text{k}$ by exploiting the fact that non-uniform RoPE interpolation supports an $8\times$ non-finetuned jump from 256k to 2,048k.
   - Crucially, this second search produces rescale factors you can apply at inference—no further fine-tuning is needed for the final jump.

4. (Optional but recommended) Short-context recovery.
   - Extremely large extensions can crowd positions inside the original 4k window and hurt short-context performance.
   - LongRoPE runs a small additional search that restricts maximum $\lambda_i$ (i.e., encourages less interpolation) for short target lengths like 4k or 8k. At inference the model dynamically uses the appropriate RoPE rescale depending on the sequence length.

Putting it together: first you ease the model from 4k → (128k →) 256k with a guided fine-tune, then you exploit the model’s learned handling up to 256k to reach 2,048k with a second non-uniform interpolation discovered by search. Numerically, the staged plan replaces a single enormous jump $s = \frac{2048\text{k}}{4\text{k}} = 512$ with two steps: $s=\frac{256\text{k}}{4\text{k}}=64$ (fine-tuned) and then $s=\frac{2048\text{k}}{256\text{k}}=8$ (search-only).

## Why this is more stable and much cheaper than training on million-token sequences

- Smaller, staged extension ratios reduce the “shock” of entirely new positional indices. Fine-tuning over a more moderate ratio (e.g., $64\times$) converges more easily than trying to train the model from scratch for $512\times$.
- You avoid training on million-token sequences, which are rare and extremely expensive to process. Instead you train at lengths up to 256k (already large but tractable), which keeps GPU memory, data-preparation, and wall-clock requirements manageable.
- The evolutionary search produces a rescale that preserves high-frequency (low-index) RoPE dimensions and initial-token angles more carefully than blind linear interpolation; that provides a much better starting point for the relatively short fine-tune (the paper shows the two-stage fine-tune is more efficient than a brute-force attempt to fine-tune to 256k directly).
- Finally, because the second extension is search-only and leverages the non-uniform rescale factors, you achieve the last $8\times$ without additional training.

## Practical search & training knobs (what the paper used)

- Search space for each RoPE dimension: $\lambda_i \in [1.0,\; s\times 1.25]$ with step 0.01. Token-preserve thresholds $\hat{n} \in \{0,1,2,4,8,12,16,20,24,28,32,64,128,256\}$.
- Monotonicity constraint enforced: $\lambda_i \le \lambda_{i+1}$ (follows NTK intuition that low dimensions need less scaling).
- Evolutionary search: for targets $\le$256k the paper used population $P=64$, mutation/crossover sizes $N_1=N_2=16$, mutate probability $p=0.3$, iterations $\mathcal{T}=40$, selecting top-32 parents each generation. For targets above 512k they halve population/mutation/crossover sizes.
- Perplexity evaluation during search: within 256k the paper used 5 PG19 validation samples (length ≥ target). For very large targets they used 3 Pile-Books3 samples.
- Fine-tuning (LLaMA2 example): LR=2e-5 (linear decay), batch size=32, 400 steps on 128k rescale → then 600 steps on 256k rescale; RedPajama chunks at 128k with BOS/EOS. Mistral used a different LR/batch-size and data recipe per the paper.

## What the experiments show (high-level)

- LongRoPE-extended LLaMA2-7B and Mistral-7B reach a 2,048k context window while retaining strong performance on shorter windows and on long-document language modeling.
- LongRoPE provides an $8\times$ non-finetuned extension capability: for example, the method can extend 4k → 32k without fine-tuning when using the searched non-uniform rescale.
- Passkey retrieval (a strict synthetic long-context test) was used to probe effective range: LongRoPE-LLaMA2-2048k (fine-tuned at 256k) maintains ≥90% retrieval accuracy from 4k to 2,048k. LongRoPE-Mistral-2048k (fine-tuned at 128k) achieves 100% up to about 1.8M tokens and drops to ~60% at 2.048M, consistent with measured perplexity trends.
- Within 256k evaluation length LongRoPE models often outperform previous baselines (PI, NTK, YaRN and other extended LLMs) on perplexity.

## Short checklist if you want to replicate the recipe

- Run LongRoPE’s evolutionary search for 128k and 256k on the pretrained model; keep PI/NTK/YaRN seeds in the initial population.
- Do a two-phase fine-tune (400 steps at 128k rescale, then 600 steps at 256k rescale) — this is the paper’s LLaMA2 recipe to reach the 256k checkpoint.
- Run a second LongRoPE search on the 256k-finetuned checkpoint, targeting 2,048k; apply the resulting rescale at inference.
- If short-window regression appears, run a small extra search constrained to smaller $\lambda$ and use those rescale factors for sequences shorter than ~8k.

## Final notes and pointers

LongRoPE is purposely lightweight: it keeps the original model architecture and only modifies RoPE factors. It finds data-driven, per-dimension and per-position rescale factors via an efficient evolutionary search and pairs that with a short, staged fine-tune to reach million-token contexts without training on million-token sequences themselves. The code and models are slated to be released at https://github.com/microsoft/LongRoPE.

If you want to dig deeper, the paper contains the exact search and training hyperparameters, the RoPE formulation, ablations on the two non-uniformities (dimension-wise and position-wise), and measurements (perplexity and passkey retrieval) that back up the recipe explained here.



# Don’t Break the Short Context: Recovering 4k–8k Quality After Going Long

Extending a model’s context window is exciting — you can feed it an entire book, a codebase, or long chat history. But there’s a catch: pushing positional embeddings out to million-token ranges can crowd the original short-range positions (4k, 8k) and hurt the model’s everyday performance. LongRoPE (from the paper “LongRoPE: Extending LLM Context Window Beyond 2 Million Tokens”) includes a focused fix for exactly this problem: an extra, targeted search that readjusts RoPE for short lengths and a simple inference-time switch so the model stays sharp on normal tasks while still supporting extreme contexts.

Below I summarize why short-context degradation happens, what LongRoPE does about it, and how the dynamic switching works in practice.

## Why extending context can make 4k–8k worse

Rotary positional embeddings (RoPE) encode position by rotating query/key vectors by angles proportional to token index. For a position $n$ the RoPE contribution is, schematically,
\[
\ldots,\; \cos(n\theta_i),\; \sin(n\theta_i),\; \ldots
\]
where different RoPE dimensions use different frequency factors $\theta_i$.

To stretch the context window from $L$ to $L'$ we use an extension ratio $s=\frac{L'}{L}$ and rescale the rotation angles so that new positions land in the pre-trained angle range rather than being totally out-of-distribution. Simple positional interpolation (PI) rescales every angle by the same factor $\lambda=s$, i.e. all rotations are compressed by $1/\lambda$. That lets the model produce meaningful outputs for positions it was not trained on, but it also compresses the angular range used by the original $L$ positions.

Why is that bad for 4k/8k performance?

- Compression (crowding): compressing angles maps many distinct short-range positions into a much smaller angular window, making them harder to distinguish in attention computations.
- Attention dilution: when you give the model many more positions overall, attention mass spreads across many more tokens; if short-range positions are also squeezed in representation space, the model becomes worse at local, familiar reasoning.
- Catastrophic unfamiliar positions: adding a huge number of new positions (e.g., when extended from 4k to >1M) introduces mostly “unseen” position indices; naive rescaling makes learning or inference brittle.

LongRoPE’s analysis shows this is not just a scalar problem: positional information is non-uniform both across RoPE dimensions (frequencies) and across token positions (early tokens are disproportionately important). That insight leads to the recovery approach below.

## How LongRoPE avoids breaking short-context capabilities

LongRoPE treats positional interpolation as a multi-dimensional, token-aware rescaling problem and searches for rescale factors per RoPE dimension and a small “no-rescale” prefix length. Concretely, the rescaled rotation applied to dimension $i$ at token $n$ uses a mask-like rule:
\[
\mathbb{I}(\hat{\lambda}_i, \hat{n}) =
\begin{cases}
1 & \text{if } n < \hat{n},\\[4pt]
\frac{1}{\lambda_i} & \text{if } n \ge \hat{n},
\end{cases}
\]
so that the RoPE angles become $\cos\!\big(\mathbb{I}(\hat{\lambda}_i,\hat{n}) \cdot n\theta_i\big)$ (and similarly for the sine terms). Two knobs are important:

- Per-dimension scales $\lambda_i$: allow some RoPE frequencies to be interpolated less or more than others.
- Prefix threshold $\hat{n}$: allow the first $\hat{n}$ tokens to keep the original RoPE (no interpolation), reflecting the empirical fact that early tokens tend to be highly attended and should be preserved.

The search is constrained so the $\lambda_i$ are monotonically non-decreasing with dimension (i.e., $\lambda_i \le \lambda_{i+1}$). This aligns with NTK-inspired intuition: higher-frequency (lower-index) dimensions should be perturbed less.

This non-uniform search produces two practical benefits relevant to recovery:

1. It identifies which RoPE dimensions are critical to preserve for short-context behavior and scales others more aggressively to support long contexts.
2. It can explicitly leave early tokens unmodified (via $\hat{n}$), preserving high-attention positions that matter for short-context tasks.

## The recovery step: readjusting RoPE for 4k and 8k

After the progressive LongRoPE pipeline extends a model to extremely long windows (e.g., 2048k), the authors observed a measurable drop in the model’s performance inside the original, short windows. To fix this, LongRoPE runs one more targeted evolution search on the already-extended model, but this time the objective is short-window performance (4k and 8k). Two practical adjustments are applied to guide the search toward recovery:

- Narrowed search range: the maximum allowed $\lambda$ is reduced because short windows need less interpolation. In other words, the search is constrained to prefer solutions that apply less compression to angles for the short-range positions.
- Same two-form search: the search still optimizes per-dimension $\lambda_i$ and the prefix $\hat{n}$, so it can both preserve important dimensions and keep early tokens intact.

The result is a separate set of RoPE rescale factors tuned specifically to short contexts. Empirically, this readjustment significantly improves 4k/8k perplexity and aggregate LLM benchmark accuracy compared to using the single extreme-length rescale setting at all times (see the paper’s short-length ablation / Table~\ref{tbl:shortperformance}).

## Dynamic switching at inference: simple, low-cost, effective

Crucially, LongRoPE does not force you to choose between “long” and “short” models. The fix is implemented as an inference-time switch: the model stores multiple sets of RoPE rescale factors (for long contexts and for recovered short contexts). At runtime we pick the rescale set based on the current sequence length. The paper suggests a simple rule:

- If the input sequence length is less than 8k, use the recovered short-context rescale factors.
- Otherwise, use the long-context rescale factors.

Mechanically this is cheap: the model architecture remains the same; you only swap which vector of per-dimension $\lambda_i$ (and which $\hat{n}$) you apply before computing rotary rotations. No additional parameters or architecture changes are required, and most runtime optimizations remain compatible.

Why this matters in practice

- For most everyday prompts (chat, question answering, short documents) you keep the original short-window fidelity.
- When you intentionally feed very long inputs, the model uses the long-window rescaling that enables million-token operation.
- The cost is tiny: a few scalars changed before computing rotations.

## Practical pointers and caveats

- Always validate short-window behavior after any large context extension. High extension ratios (e.g., hundreds-to-thousands×) routinely cause "crowding" that degrades 4k–8k performance if unaddressed.
- Recovery is a fast, targeted search on the extended checkpoint. In LongRoPE the same evolution search used to find long-window factors is reused with tightened bounds for short lengths.
- Keep multiple precomputed rescale factor sets (e.g., for 4k, 8k, 256k, 2048k) and select by sequence length at inference. The switching logic can be as simple as thresholds.
- Preserving a small number of initial tokens ($\hat{n}$) without interpolation can help short-context tasks and is discovered automatically by the search.

## Takeaways

Extending context windows is powerful, but it can accidentally shrink the model’s awareness of the original short-range positions. LongRoPE’s recovery step is a practical, principled way to avoid that trade-off: run a constrained per-dimension re-search targeted at short lengths, store the recovered rescale factors, and switch them in at inference whenever you’re in normal short-context mode. The result is a model that can go extremely long when needed, yet still behave like a first-class 4k–8k model for everyday tasks.

If you want to try this approach end-to-end, the LongRoPE paper includes the evolution-search details and reports quantitative recovery gains; code and models will be released by the authors.



# Proof in Numbers: LongRoPE’s Perplexity and Passkey Wins

LongRoPE is a straightforward-but-powerful change to how rotary positional embeddings (RoPE) are scaled when you want an LLM to read extremely long contexts. The headline: using a per-dimension, position-aware rescaling discovered by a compact evolutionary search, LongRoPE pushes pre-trained LLaMA2-7B and Mistral-7B to a context window of 2048k tokens while keeping strong language-modeling quality and retrieval behavior. This post summarizes the key numerical wins reported in the paper: low perplexity across very long books, high passkey retrieval accuracy, and preserved short-context performance — and explains why those wins happen.

## The practical problem in one sentence
When you expose a pre-trained LLM to token positions it never saw in training, naive position-extension methods introduce “catastrophic” positional values and the model’s perplexity and downstream behavior collapse. Prior fixes (linear PI, NTK-aware rescaling, YaRN) help but are limited: they either concentrate errors (PI), assume a simple dimension-wise rule (NTK), or use a coarse, hand-crafted grouping (YaRN). LongRoPE treats positional interpolation as a search problem over two real non-uniformities — RoPE dimensions and token positions — and finds much better rescale schedules.

## What LongRoPE does (short)
- It searches for a rescale factor for each RoPE dimension and an index threshold $\hat n$ that preserves the very-first positions, using an evolutionary algorithm with a monotonicity constraint (lower-frequency dimensions get larger rescale factors).
- This non-uniform interpolation preserves the RoPE information that matters most, yielding a much better initialization for fine-tuning and enabling larger no-finetune extensions.
- It uses a progressive strategy: search for 128k/256k rescale schedules, fine-tune at 128k→256k with only about 1k fine-tuning steps total, then run a second search on the fine-tuned model to reach the final 2048k window.
- It also runs a short-window recovery search (for 4k/8k) so the model performs well on its original, short-context tasks.

## The numbers that prove it

Perplexity on long books (Books3 experiments)
- LongRoPE successfully extends LLaMA2-7B and Mistral-7B to a $2048\text{k}$ context window. On a Books3 evaluation (20 books, sliding windows), LongRoPE models achieve perplexity trends that either decrease or remain competitive as context grows from 4k up to 2048k. For LLaMA2 the perplexity generally decreases with longer contexts and shows only marginal increases at 1024k and 2048k; for Mistral, LongRoPE matches or beats baselines at shorter lengths but shows higher perplexity beyond 256k in the reported experiments.

Non-fine-tuned extension capability
- The searched, non-uniform RoPE schedule lets a pre-trained LLaMA2 reach $32\text{k}$ from $4\text{k}$ (an $8\times$ jump) without any fine-tuning, while PI / NTK / YaRN show dramatic perplexity spikes after only a $2\times$ extension in the same experiments.

Passkey retrieval (synthetic long-context generation)
- The passkey task hides a short secret token in a long document and asks the model to retrieve it. Existing extended models’ retrieval accuracy drops quickly (often to 0) beyond 128k. LongRoPE-LLaMA2-2048k (fine-tuned at 256k) maintains very high retrieval accuracy — reported at $\ge 90\%$ — across evaluation lengths from 4k up to 2048k. LongRoPE-Mistral-2048k (fine-tuned at 128k) attains 100% accuracy up to about 1.8M tokens and falls to 60% at 2.048M in the reported results.

Short-context benchmarks (original window)
- LongRoPE models remain competitive on standard tasks designed for the original short context (4096 tokens). The paper reports comparable zero-/few-shot scores on ARC, HellaSwag, MMLU and TruthfulQA; in one reported case LongRoPE even outperforms the original Mistral on TruthfulQA by +0.5%. The short-window recovery step helps regain short-context quality after extreme extension.

Comparison to PI / NTK / YaRN
- Across the evaluations reported (PG19, Proof-pile, Books3, and the passkey task), LongRoPE gives consistent improvements in perplexity and retrieval over linear positional interpolation (PI), NTK-based dynamic rescaling, and YaRN. The gains are especially pronounced at large extension ratios and on long-document retrieval tasks: PI / NTK / YaRN either require substantial fine-tuning or fail to keep perplexity and accuracy stable as context grows.

## Why these numbers make sense
Two empirical observations drive the wins:
1. RoPE is non-uniform across dimensions: some rotation frequencies are much more important to preserve than others. A single global scale (PI) or a coarse hand-grouping (YaRN) wastes capacity.
2. Early token positions (the first several tokens) often get much higher attention mass; preserving their original angles (less or no interpolation for the first $\hat n$ tokens) stabilizes attention and downstream prediction.

LongRoPE's evolutionary search finds per-dimension $\lambda_i$ schedules and a token threshold $\hat n$ that keep the informative parts of RoPE intact while rescaling the rest, minimizing "crowding" of angles. The monotonicity constraint ($\lambda_i \le \lambda_{i+1}$ across dimensions) both implements the NTK intuition and dramatically reduces search cost. The progressive fine-tune + second search trick lets the method reach a final extension ratio of $512\times$ (from 4k to 2048k) with only about 1k fine-tuning steps total at tractable training lengths (128k→256k).

## Practical notes and limits
- LongRoPE was demonstrated on LLaMA2-7B and Mistral-7B; it preserves the original model architecture except for the changed positional scaling, so it can reuse most engineering and serving optimizations.
- The progressive recipe is tuned to be computationally practical: search + $400$ + $600$ fine-tuning steps for LLaMA2 in the reported setup (128k and 256k stages). The authors emphasize fine-tuning at very large lengths directly is expensive and unstable, hence the staged approach.
- Results vary by base model: Mistral benefited strongly at shorter extended lengths but showed increased perplexity beyond a few hundred thousand tokens in the reported runs; this appears linked to training settings (e.g., sequence length used during fine-tuning) and is an area for future tuning.

## Bottom line
LongRoPE delivers concrete, reproducible gains: substantially lower perplexity across long-book evaluations, stable retrieval up to the million-token scale (LLaMA2-2048k keeps ≥90% passkey accuracy across the range), and preserved short-context performance after a recovery step. Against PI, NTK and YaRN, LongRoPE gives consistently better perplexity and retrieval behavior, especially at very large extension ratios. The approach is simple to adopt (per-dimension rescale + small search + light fine-tuning) and the paper will release code at https://github.com/microsoft/LongRoPE.

If you work with long documents, LongRoPE is worth trying: it’s a targeted fix to RoPE that proves, in numbers, that careful non-uniform interpolation beats blunt global rescaling.



# RoPE to LongRoPE: Positional Embeddings Made Simple

Large context windows are increasingly important for language models, but extending them is surprisingly delicate. This short post walks through the intuition behind rotary position embeddings (RoPE), why naive linear scaling (positional interpolation) crowds tokens and breaks models, and how LongRoPE fixes this with per-dimension scaling and preserving early tokens.

## Quick primer: what RoPE encodes

RoPE encodes position by rotating pairs of embedding dimensions with position-dependent angles. For a token at position $n$ the RoPE pattern (simplified) looks like:

$$
\left[\cos(n\theta_0),\ \sin(n\theta_0),\ \cos(n\theta_1),\ \dots,\ \sin(n\theta_{d/2-1})\right],
$$

where $d$ is the embedding dimension and the per-dimension rotation frequencies $\theta_i$ are set so that different dimensions encode different spatial frequencies (the usual choice uses a large base such as $10000$). Intuitively, low-index dimensions correspond to higher-frequency rotations (they change quickly with $n$) and encode fine-grained, local positional differences; higher-index dimensions change more slowly and capture coarser-position structure.

RoPE works well because these rotations inject relative position information directly into the query/key geometry used by attention.

## Extending the context window by scaling angles — and why that can fail

If a pretrained model has a context length $L$ and you want it to accept $L'$ tokens, a common trick is position interpolation: compress the rotation angles of the new positions so they fit in the original angular range. Define the extension ratio $s = L'/L$. Linear positional interpolation (PI) simply scales all rotation angles by $1/s$:

$$
\text{PI:}\quad n\theta_i \longmapsto \frac{n\theta_i}{s}\quad\text{for all dimensions }i.
$$

This does make previously unseen large position indices map into the model's trained angular range, but it has a concrete geometric cost: the angular separation between neighboring token positions is reduced by the same factor $s$. Imagine placing tokens around a unit circle — after uniform scaling the tokens crowd together, so adjacent tokens are much harder to distinguish in the rotated embedding space. In practice that can raise perplexity and break downstream behaviors (in-context learning, retrieval, etc.) when $s$ is large.

## Smarter interpolations: non-uniformity across dimensions (and across positions)

Several prior ideas mitigate the crowding by treating RoPE dimensions differently. NTK-inspired schemes and YaRN distribute interpolation pressure across dimensions: keep high-frequency (important for local distinctions) dimensions less scaled and allow more scaling on low-frequency dimensions. YaRN explicitly groups dimensions and applies different interpolation/extrapolation rules per group.

LongRoPE builds on this intuition but takes it further by recognizing two distinct non-uniformities:

1. Dimensional non-uniformity. Different RoPE dimensions should get different rescale factors $\lambda_i$ (instead of one global $\lambda$).
2. Positional non-uniformity. The earliest tokens in a sequence are usually more important — they receive larger attention and are critical for many tasks — so it can help to avoid interpolating those initial positions at all.

LongRoPE parameterizes both at once. For each RoPE dimension $i$ it uses a per-dimension rescale factor $\lambda_i$, and it uses a threshold $\hat n$ so that the first $\hat n$ positions are left unchanged. Formally LongRoPE uses

$$
\mathrm{RoPE}_n = \left[\dots,\ \cos\!\Big(\mathbb{I}(\hat\lambda_i,\hat n)\cdot\frac{n}{\beta^i}\Big),\ \sin\!\Big(\mathbb{I}(\hat\lambda_i,\hat n)\cdot\frac{n}{\beta^i}\Big),\dots\right],
$$

with

$$
\mathbb{I}(\hat\lambda_i,\hat n) =
\begin{cases}
1 & \text{if } n < \hat n,\\[4pt]
\frac{1}{\lambda_i} & \text{if } n \ge \hat n,
\end{cases}
$$

where $\beta$ encodes the original per-dimension frequency scaling in RoPE. In words: leave the earliest $\hat n$ positions alone, and apply a tailored rescale to each RoPE dimension for later positions.

Why this helps: preserving low-index/high-frequency dimensions (and/or the first few tokens) keeps the fine-grained positional signals the model needs to distinguish nearby tokens, while allowing coarser dimensions to be compressed more aggressively so the model can absorb far-away positions.

## How LongRoPE finds good per-dimension and per-position scales

Searching for a per-dimension vector $\{\lambda_i\}$ and a threshold $\hat n$ is a large combinatorial problem. LongRoPE uses an efficient evolutionary search to find rescale factors that minimize validation perplexity for a target extended length. A few practical tricks speed the search:

- Seed the initial population with familiar baselines (PI, NTK, YaRN) rather than random-only starts.
- Enforce a monotonicity constraint $\lambda_i \le \lambda_{i+1}$ so lower-index (high-frequency) dimensions get at most as much scaling as higher-index ones. This both reflects NTK intuition and prunes many bad candidates.
- Evaluate candidates by running a small number of perplexity computations on long validation excerpts, which is cheap compared to full fine-tuning.

With this approach LongRoPE finds non-uniform rescale patterns that preserve important dimensions and early positions. Empirically this yields:

- Up to an 8× context extension without any fine-tuning (i.e., just by replacing RoPE with the searched scaling).
- A much better initialization when fine-tuning is required for even larger extensions.

## From thousands to millions of tokens: progressive extension

Going directly from 4k to multi-million token context windows is impractical (scarcity of training data and huge compute). LongRoPE uses a progressive recipe that is efficient in practice:

1. Search for and apply non-uniform RoPE to extend the pretrained LLM to moderate long lengths (e.g., 128k and 256k).
2. Fine-tune at those manageable long lengths (the paper reports a small number of steps, e.g., 400 steps at 128k then 600 at 256k for LLaMA2 in their experiments).
3. Run a second LongRoPE search on the fine-tuned 256k model to find rescale factors that extend it further — in the paper this second interpolation reaches 2,048k (2048k) tokens without additional fine-tuning.

Finally, because aggressive interpolation for very long windows can harm performance at short lengths, LongRoPE performs one more search to recover short-window behavior (e.g., readjust rescale factors for 4k and 8k) and dynamically switches rescale factors at inference time depending on the sequence length.

## Results at a glance (from the paper)

- LongRoPE was applied to LLaMA2-7B and Mistral-7B and used to produce 2,048k-context variants while changing only the positional embedding logic (no large architecture changes).
- The method requires only modest fine-tuning (the progressive recipe uses about 1k fine-tuning steps within 256k training length in reported experiments) to reach 2,048k.
- Non-uniform per-dimension scaling + early-token preservation enabled an 8× extension without any fine-tuning.
- In a synthetic "passkey retrieval" test, the LongRoPE-extended LLaMA2 (fine-tuned to 256k) maintained ≥90% retrieval accuracy from 4k to 2048k; the Mistral variant kept 100% up to ~1.8M then dropped to ~60% at 2.048M, consistent with its perplexity profile.
- LongRoPE-extended models remain competitive on standard benchmarks designed for shorter (≈4k) contexts after the short-length recovery step.

## Practical takeaways

- Do not assume a single global angle-rescale will be optimal when you extend RoPE — different RoPE dims carry different kinds of positional signal.
- Protecting the first few tokens from interpolation often helps because they attract strong attention and carry critical local information.
- If you must reach extremely long contexts, a progressive workflow (search → moderate-length fine-tune → search again) is far more practical than trying to fine-tune directly at million-token lengths.
- Enforcing monotonicity across dimension-wise scales is a simple, effective inductive bias: lower-index/higher-frequency dims should be scaled no more than higher-index/lower-frequency dims.
- The approach is lightweight: it modifies only how RoPE is computed and can be applied to existing RoPE-based LLMs.

## Where to try it

The LongRoPE paper reports code and models (the authors indicate a repository: https://github.com/microsoft/LongRoPE). If you work with RoPE-based models and need longer contexts, LongRoPE provides a practical, data- and compute-efficient path to much longer windows while keeping short-context behavior intact.

If you want a deeper dive into equations, experimental numbers, or the exact evolutionary search settings, see the LongRoPE paper — the blog above distills the core intuition so you can understand why per-dimension scaling and early-token preservation matter.



# LongRoPE vs. PI, NTK, and YaRN: What’s New and Why It Scales

## TL;DR
Extending a RoPE-based LLM’s context window is tricky: simple linear scaling (PI) crowds positions, NTK-style per-dimension scaling helps but is coarse, and YaRN uses hand-crafted groups that don’t generalize. LongRoPE treats positional interpolation as a search problem over two axes of non‑uniformity — RoPE dimensions and token positions — and finds fine-grained, per-dimension rescale factors plus a small “no-rescale” prefix. That search gives a much better initialization for limited fine-tuning (≈1k steps at 256k) and permits an 8× extension without fine-tuning and a progressive route to a 2,048k context window while keeping short-context behavior competitive.

## Quick background: RoPE and what positional interpolation tries to do
RoPE encodes a token at position $n$ using rotation angles $n\theta_i$, producing features like
$[\cos(n\theta_0),\; \sin(n\theta_0),\; \dots,\; \cos(n\theta_{d/2-1}),\; \sin(n\theta_{d/2-1})]$.
When you push an LLM beyond its trained maximum length $L$ to a new length $L'$, positional indices the model never saw can produce catastrophic behavior. Most interpolation approaches map new positions back into the pretrained range by rescaling the rotation angles.

Define the extension ratio $s=\frac{L'}{L}$. Existing methods differ in how they set a rescale factor per angle (call it $\lambda$):

- PI (linear positional interpolation): apply a uniform rescale across all RoPE dimensions, i.e., every rotation angle is reduced by the same factor (roughly $\lambda=s$).
- NTK-style methods: vary scaling across dimensions so higher-frequency (lower-index) dimensions are scaled less and lower-frequency dimensions more.
- YaRN: split RoPE dimensions into three hand-crafted groups and use extrapolation/NTK/linear interpolation per group.

## Where PI, NTK and YaRN fall short
- PI’s uniform scaling compresses rotation angles for all dimensions equally. That crowding makes it hard for the attention mechanism to distinguish nearby positions — performance degrades quickly at large $s$.
- NTK-style approaches introduce beneficial non-uniformity, but typically use a fixed analytic schedule and remain relatively coarse; in practice they often only provide modest non-fine-tuning extension (≈2–4×).
- YaRN improves by mixing strategies, but the grouping is hand-designed and can be suboptimal for new models or very large extension ratios.
- None of these approaches fully exploit two distinct non-uniformities that matter: (a) per-RoPE-dimension sensitivity and (b) the special role of early token positions (which tend to receive strong attention and should often be treated differently).

## What LongRoPE changes — the big ideas
LongRoPE turns positional interpolation into a concrete search/optimization problem and explicitly models the two non-uniformities above.

1. Per-dimension rescale factors. Instead of one scalar for all dimensions, LongRoPE searches for a separate $\lambda_i$ per RoPE dimension so the algorithm can preserve key high-frequency dimensions and only strongly rescale the dimensions that can tolerate it.

2. A small “no-rescale” prefix. LongRoPE introduces a token-threshold $\hat{n}$: positions $n < \hat{n}$ use the original RoPE (no rescaling) and positions $n \ge \hat{n}$ use the per-dimension rescale. This captures the empirical finding that early positions should often be extrapolated/left untouched.

Formally, LongRoPE applies per-dimension rescaling via a mask-like factor
$\mathbb{I}(\hat{\lambda}_i,\hat{n})$ where
$\mathbb{I}(\hat{\lambda}_i,\hat{n}) = \begin{cases}
1 & n < \hat{n}\\
1/\lambda_i & n \ge \hat{n}
\end{cases}$,
so the effective rotation angle becomes $\mathbb{I}(\hat{\lambda}_i,\hat{n}) \cdot \frac{n}{\beta^i}$ (notation follows the RoPE parameterization).

3. Evolutionary search to find the rescale factors. The method searches for $(\lambda_0,\dots,\lambda_{d/2-1},\hat{n})$ that minimize perplexity on long validation snippets. Two practical accelerations make the search feasible:
   - Seed the initial population with PI, NTK and YaRN solutions and randomly mutate them (instead of starting purely at random).
   - Impose a monotonic constraint $\lambda_i \le \lambda_{i+1}$ (lower-index/higher-frequency dims are allowed less interpolation), drastically pruning bad candidates and leveraging NTK intuition.

Search details used in the experiments (from the paper): for targets $\le 256$k the search used population $P=64$, mutation/crossover sizes of 16, mutation probability $p=0.3$, and $\mathcal{T}=40$ iterations; for >512k the population and operators were halved. The per-dimension $\lambda_i$ was searched in $[1.0,\; s\times 1.25]$ with step $0.01$, and $\hat{n}$ was chosen from a small set (e.g., $\{0,1,2,4,\dots,256\}$). Perplexity on a handful of long validation samples guides selection.

## Why this search-driven, finer-grained approach helps
- Preserving high-frequency RoPE dimensions avoids the “crowding” that PI produces in the short-range geometry of positions, so the model better preserves its original positional resolution.
- Leaving a short prefix unrescaled protects tokens that receive large attention (e.g., early context, BOS-proximal tokens), which empirical tests show matters.
- Finding a specialized per-dimension schedule provides a much better initialization for fine-tuning; that reduces the amount of fine-tuning required (paper reports achieving 2,048k with only ~1k fine-tuning steps at 256k).
- Because the search is evaluating actual model perplexity, the solution adapts to the target model (e.g., LLaMA2 vs Mistral) instead of relying on hand-tuned grouping rules.

## The progressive recipe to reach 2,048k (what they did)
The paper adopts a pragmatic, progressive extension that avoids training on ultra-long sequences directly:

1. Search and apply LongRoPE rescale factors for intermediate targets (128k and 256k) on the pretrained model.
2. Fine-tune the model to a 256k context window using those factors. For LLaMA2 this was done in two phases: 400 steps with the 128k schedule, then 600 steps with the 256k schedule (total ≈1k steps). This is much cheaper than attempting to fine-tune at 2,048k directly.
3. Run a second LongRoPE search on the fine-tuned 256k model to produce rescale factors for 2,048k. The second search yields a 2,048k-capable model without additional long-length fine-tuning.

They also perform a short-context recovery search (e.g., for 4k and 8k) on the final extended model, reducing interpolation for small lengths to restore original short-window performance. During inference the model dynamically applies the appropriate RoPE rescale set depending on sequence length.

## Empirical highlights (as reported)
- Non-fine-tuning benefit: LongRoPE’s searched rescale schedule enables up to an 8× extension (4k → 32k) without any fine-tuning, while PI/NTK/YaRN typically spike in perplexity after a 2× extension.
- Progressive extension: Using the search + limited fine-tuning strategy, LongRoPE achieves a 2,048k context window for LLaMA2 and Mistral models.
- Passkey retrieval: LongRoPE-LLaMA2-2048k (fine-tuned at 256k) maintains very high retrieval accuracy (≥90%) from 4k up to 2,048k. LongRoPE-Mistral-2048k (ft=128k) keeps 100% up to ≈1.8M tokens, dropping to 60% at 2,048k — consistent with measured perplexity behavior.
- Short-window benchmarks: After short-context readjustment, LongRoPE-2048k models match or remain comparable to baselines on standard benchmarks designed for smaller windows (4096 tokens); notably the extended Mistral slightly improves TruthfulQA by +0.5% in the reported experiments.

(These results come from experiments on LLaMA2-7B and Mistral-7B reported in the paper — see the paper for detailed tables and dataset splits.)

## Practical considerations and limits
- LongRoPE is applicable to any RoPE-based model and requires only modest architectural changes (positional embedding rescale schedules). Existing inference/optimization pipelines largely remain usable.
- The search space grows quickly with extension ratio, so the evolutionary search plus monotonic constraint and population seeding are important for practicality. For very large targets (>512k) the authors reduce population sizes to keep the search tractable.
- Fine-tuning is still required for extreme extensions, but LongRoPE substantially reduces the amount of required fine-tuning and avoids needing training corpora with extremely long continuous sequences (the progressive approach makes training feasible).
- There are model-dependent behaviors: the same recipe behaved differently for LLaMA2 and Mistral in the paper’s experiments (e.g., Mistral exhibited higher perplexity beyond 256k in one setting), which underscores the importance of the search being model-specific.

## Where to find the code and models
The authors plan to release code and LongRoPE-2048k models at https://github.com/microsoft/LongRoPE.

## Takeaway
If you’ve wrestled with PI’s crowding, NTK’s coarse per-dimension schedule, or YaRN’s hand-crafted grouping, LongRoPE offers a principled alternative: treat interpolation as a searchable, model-aware optimization over per-dimension scaling and an early-token no-rescale prefix. That finer-grained control plus a progressive fine-tuning path lets you push much farther (paper shows 2,048k) while keeping short-context performance viable and requiring far less expensive long-length fine-tuning than training from scratch at the target length.



# Engineer’s Guide: Extending LLaMA2 and Mistral With LongRoPE

TL;DR — LongRoPE is a lightweight way to push RoPE-based LLMs from the usual few-thousand token window up to 2,048k tokens. It only changes positional embedding (RoPE), reuses the model and existing optimizations, and uses an evolutionary search to find per-dimension rescale factors plus a small "do-not-touch" prefix length. The practical route that worked in the paper is: (A) search non-fine-tuned rescale factors for moderate targets (up to an $8\times$ extension), (B) progressively fine-tune at 128k then 256k (≈1k steps total), and (C) run a second search on the 256k fine-tuned checkpoint to produce the final 2,048k config. Below I give a compact, actionable walkthrough with the search/training hyperparameters and deployment tips used in the paper.

## What LongRoPE changes (and what it doesn't)
- What changes: only the RoPE positional embedding is modified — LongRoPE replaces the rotation angles with rescaled versions on a per-dimension basis, and optionally preserves the first $\hat{n}$ token positions without interpolation.
- What remains: the Transformer architecture, attention kernels, quantization/acceleration stacks, and most training/inference code remain unchanged and can be reused. The change is limited to how position angles are computed/applied.
- Why this is practical: because the RoPE change is a small, deterministic transformation of the position angles, you can integrate LongRoPE into existing stacks without reimplementing attention internals.

## Quick intuition (the two non-uniformities)
LongRoPE is built on two observations:
1. Different RoPE dimensions carry different "frequency" information, so they should not all be interpolated the same way.
2. Early tokens in the sequence are especially important (they often receive high attention), so you may want to keep the first $\hat{n}$ positions un-interpolated.

Formally, the RoPE encoding for token position $n$ is commonly written as
$[\cos(n\theta_0), \sin(n\theta_0), \dots, \cos(n\theta_{d/2-1}), \sin(n\theta_{d/2-1})]$,
with rotation frequencies $\theta_i$. LongRoPE applies a per-dimension rescale factor $\lambda_i$ and a prefix threshold $\hat{n}$ by replacing the rotation angle for dimension $i$ and position $n$ with
\[
\mathbb{I}(\hat{\lambda}_i, \hat{n}) \times \frac{n}{\beta^i},
\qquad\text{where}\qquad
\mathbb{I}(\hat{\lambda}_i, \hat{n})=
\begin{cases}
1 & n < \hat{n},\\[4pt]
\frac{1}{\lambda_i} & n \ge \hat{n}.
\end{cases}
\]
Here $\beta$ is the usual base factor coming from RoPE’s parameterization and $s=\frac{L'}{L}$ is the extension ratio from original length $L$ to target $L'$.

Two more practical constraints make the search tractable and sensible: restrict $\lambda_i$ so they are monotonically non-decreasing across RoPE dimensions ($\lambda_i \le \lambda_{i+1}$), and restrict the search range to sensible bounds (see below).

## Practical recipe (step-by-step)

Below is the sequence that the paper found effective for LLaMA2 and Mistral. Treat it as a tested recipe — you can adapt iteration counts and GPUs to your resources.

1. Pre-flight
   - Confirm your model uses RoPE (LLaMA2 and Mistral are both RoPE-based).
   - Choose target lengths and datasets for validation. The paper used PG19 and Pile/Books3 samples for long-length perplexity checks; RedPajama for fine-tuning LLaMA2 and Together Long-Data Collections for Mistral.

2. Try a non-fine-tuned search for modest extension (first check)
   - LongRoPE’s evolutionary search often allows an $8\times$ extension without any fine-tuning (the paper extended 4k → 32k successfully).
   - Run the evolution search on the pre-trained model for the moderate target (e.g., $8\mathrm{k}$, $16\mathrm{k}$, $32\mathrm{k}$).
   - If the found rescale factors give acceptable perplexity and downstream behavior, you can stop here and deploy these rescale factors (no fine-tuning required).

3. Progressive extension to very long windows (2,048k)
   - If you need much larger windows (the paper targets 2,048k), use the progressive strategy:
     a. Search for RoPE rescale factors on the pre-trained model for $128\mathrm{k}$ and $256\mathrm{k}$ targets.
     b. Fine-tune the model to reach $256\mathrm{k}$ using the searched rescale factors:
        - For LLaMA2-7B (paper setting): learning rate $2\mathrm{e}{-}5$ with linear decay, global batch size 32.
          * Fine-tune 400 steps using the 128k rescale set (train on 128k chunks), then replace RoPE with the 256k rescale set and fine-tune another 600 steps. This two-stage procedure worked better than trying to jump straight to 256k.
          * Resource notes from the paper: training to 128k used 8× A100 GPUs; 256k required 16× A100 GPUs (they used a distributed training system referred to as Cube).
        - For Mistral-7B (paper setting): constant LR $=1\mathrm{e}{-}6$, global batch size 64; they used Together’s Long-Data Collections with 16k sequence length and 400 steps per stage and ran on 4× A100 GPUs.
     c. After you have a checkpoint fine-tuned at 256k, run a second LongRoPE search on that fine-tuned model for a final target of 2,048k. This second, post-finetune search lets you reach the full $2{,}048\mathrm{k}$ window without additional fine-tuning.

4. Recover short-context performance
   - A known effect of strong interpolation is short-length degradation (positions within the original window get crowded). LongRoPE addresses this by running an extra search (on the extended model) constrained for short lengths (e.g., 4k and 8k) with a reduced maximum $\lambda$. During inference, use these short-length RoPE factors when sequence length is in the short regime (the paper suggested switching for lengths < 8k).

## Evolution search: concrete search space & hyperparameters

Use these hyperparameters (as in the paper) as a starting point.

- Search space
  - Per-dimension $\lambda_i \in [1.0,\; s \times 1.25]$ with step $0.01$. ($\lambda_i=1.0$ corresponds to no interpolation/extrapolation; larger $\lambda_i$ means stronger interpolation.)
  - Prefix thresholds $\hat{n} \in \{0,1,2,4,8,12,16,20,24,28,32,64,128,256\}$. ($\hat{n}=0$ means all positions use interpolation.)
  - Enforce monotonic constraint $\lambda_i \le \lambda_{i+1}$.

- Evolutionary search (default for targets within 256k)
  - population size $P=64$,
  - mutation size $N_1=16$,
  - crossover size $N_2=16$,
  - mutation probability $p=0.3$,
  - iterations $\mathcal{T}=40$,
  - keep top-32 individuals as parents each iteration.
  - Initialize the population by seeding PI, NTK, and YaRN solutions (plus random mutations of them).
  - Evaluate fitness by model perplexity on a small set of long samples (paper used 5 random PG19 validation samples for targets ≤256k).

- For targets >512k
  - Halve population, mutation and crossover sizes (paper halved $P$, $N_1$, $N_2$ to reduce cost).
  - Evaluate perplexity on fewer, longer samples (paper used 3 Pile-Books3 samples).

- Cost-reduction heuristics used in the paper
  - Seed the initial population with PI / NTK / YaRN to accelerate convergence.
  - Enforce monotonicity to prune many implausible candidates before running expensive model evaluations.

## Compute / resource expectations (as reported)
- LongRoPE reaches 2,048k final window with only about 1,000 fine-tuning steps total when using the progressive 128k → 256k fine-tune schedule.
- Example resource usage in the paper:
  - LLaMA2-7B: 128k stage used 8× A100; 256k stage used 16× A100.
  - Mistral-7B: 4× A100 for their fine-tuning runs (they followed YaRN-style settings with 16k training length).
- Searching evaluations are cheaper than full fine-tuning but still require forward passes at the target length — reduce the number of validation samples when target lengths become very long.

## Validation checklist (what to measure)
- Perplexity across target lengths (sliding-window evaluation; the paper used a 256-token stride/window for many evaluations).
- Passkey retrieval (synthetic retrieval test): measures the model’s ability to fetch a small token-string hidden in million-scale context. LongRoPE-LLaMA2-2048k (ft=256k) maintained ≥90% accuracy up to 2,048k in the paper; LongRoPE-Mistral-2048k (ft=128k) was near 100% up to 1,800k and dropped at 2,048k.
- Short-context benchmark accuracy (standard zero-/few-shot tasks within the original 4k window): run a sanity check to confirm short-window performance is preserved after short-context recovery.

## Deployment notes & engineering tips
- Integration: LongRoPE only alters the positional-rotation computation. In most codebases this means replacing or augmenting the per-position cos/sin angle table used by the RoPE application. You do not need to change attention implementations or low-level CUDA kernels.
- Inference switching: store multiple rescale-factor sets (e.g., short-length, 256k, and 2048k). At runtime choose the set that matches the current sequence length (the paper used the short-length set for lengths < 8k). This is a cheap table lookup and recomputing the positional table for a given $\lambda$ set is inexpensive compared to attention over millions of tokens.
- Precision & stability: the search is discrete (step 0.01) and the monotonic constraint reduces pathological choices. If you see perplexity spikes, check (a) that $\hat{n}$ isn't zero when early tokens are critical, and (b) that monotonicity is enforced.
- Early failure mode: trying to fine-tune directly at extremely large target lengths often fails to converge. The progressive fine-tuning schedule (128k then 256k) and a good LongRoPE initialization are the key practical tricks that made 2,048k attainable in the paper.

## Limitations & caveats
- LongRoPE reduces the heavy compute required to reach million-scale windows, but you still need non-trivial GPU resources (the paper used up to 16 A100s for the 256k fine-tune stage).
- The precise best $\hat{n}$ and $\lambda$ pattern depends on the target length and model family; the evolutionary search is necessary because manual grouping (e.g., YaRN’s three groups) can be suboptimal.
- Short-context degradation is real — run the short-context recovery step and shadow-test short-window tasks before wide deployment.

## Final checklist (copy-paste actionable)
- Confirm model uses RoPE (LLaMA2 / Mistral).
- Prepare long validation samples (PG19 / Pile-Books3).
- Run LongRoPE evolutionary search (seed with PI/NTK/YaRN; $P=64$, $N_1=N_2=16$, $p=0.3$, $\mathcal{T}=40$).
- If target ≤ $32\mathrm{k}$: try deploying the found rescale factors without fine-tuning.
- If target ≫ $32\mathrm{k}$:
  - Search for 128k and 256k rescale sets on the pre-trained model.
  - Fine-tune: 400 steps with the 128k set, then replace with 256k set and fine-tune 600 more steps (LLaMA2 example hyperparams: LR $2\mathrm{e}{-}5$, batch size 32).
  - Search the 256k-finetuned model for the final 2048k rescale set (use halved search sizes for >512k).
- Run short-context recovery search for 4k/8k and set inference to pick the short-rescale set when len < 8k.
- Validate perplexity, passkey retrieval, and short-context benchmarks.

If you follow the progressive, search-first approach above you keep architecture changes minimal, reuse your existing attention kernels/optimizations, and limit fine-tuning to a manageable amount while gaining access to million-token contexts. The LongRoPE paper provides the full experimental settings and results for LLaMA2-7B and Mistral-7B if you want to reproduce their exact runs.

\title{A Textbook about the Paper: "Parameter-Efficient Orthogonal Finetuning via Factorization"}

Foundations and Motivation: Adapting Foundation Models Efficiently

# The scaling of foundation models and prohibitive cost of full training
Over the last few years, foundation models have grown dramatically in size and capability. Examples mentioned in the source paper include large language and image models such as ChatGPT and GPT-3 (the latter having on the order of $175\,$B parameters) and image models like Stable Diffusion. These models demonstrate strong out-of-the-box generalization across many tasks, but their scale comes with a practical cost: training such models from scratch — or even repeatedly retraining large portions of them for every new task — is prohibitively expensive in compute, memory, and time.

Because training a foundation model end-to-end is increasingly impractical for most researchers and practitioners, the field has turned to methods that adapt a pretrained model to new downstream tasks instead of re-training. The central engineering question becomes how to reuse the pretrained representation efficiently while changing as few parameters as possible, or changing them in a constrained way that preserves the useful structure learned during pretraining.

# Adaptation paradigms: model finetuning, adapters, and prompt tuning
The paper groups existing adaptation approaches into three broad paradigms, each offering a different trade-off between simplicity, parameter cost, and changes to the model:

- Model finetuning. The simplest paradigm keeps the architecture unchanged and updates either all or a subset of the model parameters. The updated parameters remain part of the original weight matrices, so the model structure at inference time is identical to the pretrained model. Many practical finetuning recipes fall into this category.

- Adapter tuning. Here one augments the pretrained model with small, task-specific modules (adapters) interleaved with the original layers. During adaptation only the adapter modules are trained; the original pretrained parameters are frozen. Adapter tuning changes the network architecture by inserting extra components, but it often reduces the number of trainable parameters compared to full finetuning.

- Prompt tuning. Instead of changing weight matrices, prompt tuning attaches learnable tokens or prefixes to the input and optimizes only those prefixes (or other small prompt structures). This keeps the original model parameters fixed and adds a small, task-specific input representation to be learned.

Each paradigm addresses the same practical need — efficient reuse of a large pretrained model — but in different ways: finetuning directly changes model weights, adapters add new trainable modules, and prompt tuning concentrates learning into input-side parameters.

# Why pure finetuning remains appealing: no architectural changes or inference latency
Among these paradigms, pure model finetuning retains a particular appeal because it preserves the original computational graph and inference-time structure. In practical terms, that means no extra modules or tokens need to be present at inference, so there is no added inference latency or engineering complexity to integrate adapters or prompt-handling mechanisms. The paper emphasizes that model finetuning is "simple yet powerful" and, importantly, introduces no inference latency — a desirable property in deployment scenarios where throughput and latency matter.

Another reason pure finetuning is attractive is conceptual simplicity: one directly optimizes parameters that are already expressed in the form the model uses. This makes it straightforward to reuse existing tooling, weight initialization conventions, and any optimizations that assume the standard parameter layout.

# Generalization preservation during finetuning as a design objective
A central theme of the paper is that adapting a pretrained model should preserve the valuable structure that the model learned during pretraining. In other words, finetuning should change the model enough to perform a downstream task well, but not so much that it discards the general-purpose knowledge embedded in the pretrained weights.

A common heuristic used in practice is to employ a small learning rate during finetuning; this ad hoc choice encourages the finetuned parameters to remain close to their pretrained values, thereby limiting deviation from the pretrained model. The paper identifies a more principled alternative: exploit structure in the weight matrices themselves. Instead of merely shrinking step sizes, one can constrain the transformation applied to neurons so that important geometric relations are preserved.

Orthogonal Finetuning (OFT) embodies this idea. OFT reparameterizes a layer's finetuned weights as a multiplicative orthogonal transformation of the pretrained weights. For a pretrained linear layer represented by $\bm{W}^0\in\mathbb{R}^{d\times n}$, OFT learns an orthogonal matrix $\bm{R}\in\mathbb{R}^{d\times d}$ and replaces the forward pass
$\bm{z}=(\bm{W}^0)^\top\bm{x}$
with
$\bm{z}=(\bm{R}\bm{W}^0)^\top\bm{x}$.
Because orthogonal matrices preserve inner products and angles, this multiplicative update preserves the pairwise angles between neurons within the layer, providing a geometry-aware constraint that is more principled than merely shrinking step sizes. To ensure orthogonality during training, OFT can use a Cayley parameterization
$\bm{R}=(\bm{I}+\bm{Q})(\bm{I}-\bm{Q})^{-1}$,
where $\bm{Q}$ is a skew-symmetric matrix ($\bm{Q}=-\bm{Q}^\top$); initializing $\bm{Q}=\bm{0}$ yields $\bm{R}=\bm{I}$, giving the useful property of zero initialization for the finetuning update.

This geometry-preserving view motivates OFT as a finetuning approach designed explicitly to retain the relational structure of pretrained neurons while still allowing adaptation.

# Pitfalls of naive small-learning-rate finetuning
Using a small learning rate is a widely used practical tactic to limit how far finetuning can move from a pretrained model. The paper characterizes this as an ad hoc way to encourage small discrepancy between the pretrained and finetuned models. While this approach can work in practice, it does not explicitly exploit the structured nature of neural weight matrices or the geometric relations among neurons. In other words, small-step finetuning reduces the magnitude of change but does not guarantee that important relational information — such as the pairwise angles between neuron vectors — is preserved.

The limitation motivates methods like OFT that impose structure directly on how weights change. OFT's multiplicative orthogonal update targets a specific geometric property (angle preservation) which is more aligned with the goal of maintaining pretraining knowledge than an undifferentiated constraint on parameter movement. In short, small learning rates are a blunt instrument; geometry-aware finetuning methods are an attempt to be more principled about which aspects of the pretrained model should be retained.

# High-level trade-offs: expressivity, regularity, and parameter budget
Any practical finetuning method must navigate a three-way trade-off among expressivity, regularity, and the parameter budget.

- Expressivity. A finetuning method should be expressive enough to represent the task-specific transformations required to perform well on the downstream task. Full finetuning of all parameters is maximally expressive, since it can realize any change in the weight matrices.

- Regularity. Strong constraints or inductive biases (regularity) help preserve pretrained knowledge and can improve generalization. OFT's orthogonality constraint is an example: it regularizes updates to preserve angles and spectral properties of pretrained layers.

- Parameter budget. Practical concerns — limited memory, communication costs for distributed training, or constraints on the number of task-specific parameters to store — require parameter-efficient methods. Popular parameter-efficient finetuning (PEFT) techniques like LoRA use low-rank additive updates, while OFT as originally proposed may require a large number of parameters if one uses a dense orthogonal matrix.

These objectives can be at odds. Full orthogonal matrices are geometrically appealing but have $\mathcal{O}(d^2)$ parameters for $d$-dimensional layers; this is often too many parameters to tune efficiently. To reduce parameters, OFT introduced a block-diagonal orthogonal parameterization $\text{diag}(\bm{R}_1,\dots,\bm{R}_r)$ with each $\bm{R}_i\in\mathbb{R}^{b\times b}$ and $b r = d$, which reduces the number of trainable parameters to $\mathcal{O}(b d)$. This block-diagonal choice trades off expressivity for parameter efficiency: when blocks are small, the transformation applied to different coordinate subsets becomes independent and the combined orthogonal matrix cannot express many global linear transforms. The block-diagonal sparsity can therefore introduce undesirable inductive biases; for example, it cannot recover many classic dense transforms.

BOFT (Orthogonal Butterfly Finetuning) is motivated precisely to navigate this trade-off better. Instead of forcing blockwise independence, BOFT composes a dense orthogonal matrix from the product of several sparse orthogonal factors. By carefully choosing the sparsity pattern of these factors — in particular, using a butterfly structure inspired by fast transforms such as the Cooley–Tukey FFT — BOFT attains a much smaller parameter count (typically $\mathcal{O}(d\log d)$) while retaining the ability to generate dense orthogonal transformations. The butterfly structure thus gives an inductive bias that is both structured (aiding generalization) and expressive enough to approximate many useful global transforms.

Another important angle is spectral behavior. Because OFT and BOFT apply an orthogonal matrix to the left of the pretrained weight $\bm{W}^0$, the singular values (and in particular the spectral norm) of $\bm{W}^0$ are preserved. This preservation is beneficial for training stability and generalization and contrasts with additive low-rank updates that can change the spectrum more directly.

# Overview of OFT and BOFT as geometry-aware PEFT methods
We close by putting OFT and BOFT side-by-side as geometry-aware parameter-efficient finetuning methods, and by summarizing the key mechanisms that make BOFT attractive.

Orthogonal Finetuning (OFT)
OFT reparameterizes the finetuned weights of a linear layer by left-multiplying the frozen pretrained weights $\bm{W}^0\in\mathbb{R}^{d\times n}$ with a learnable orthogonal matrix $\bm{R}\in\mathbb{R}^{d\times d}$. The forward pass becomes
$\bm{z}=(\bm{R}\bm{W}^0)^\top \bm{x}$.
Orthogonality preserves pairwise angles among neuron vectors, implementing a geometry-preserving constraint that keeps the finetuned model close to the pretrained representation in a meaningful way. Orthogonality during training can be enforced via Cayley parameterization $\bm{R}=(\bm{I}+\bm{Q})(\bm{I}-\bm{Q})^{-1}$ with a skew-symmetric $\bm{Q}$ initialized at zero so that $\bm{R}=\bm{I}$ at the start.

The main practical problem for OFT is parameter count: a dense $d\times d$ orthogonal matrix contains $\mathcal{O}(d^2)$ independent parameters. To reduce parameters, OFT can restrict $\bm{R}$ to be block-diagonal with blocks of size $b$; this reduces trainable parameters to $\mathcal{O}(b d)$, but at the cost of expressivity and introducing a fixed sparsity pattern that may be misaligned with useful transforms.

Orthogonal Butterfly Finetuning (BOFT)
BOFT generalizes OFT by parameterizing the orthogonal update matrix as a product of sparse orthogonal factors chosen so that their product is dense. The conceptual shift is to view the matrix factorization as an information transmission problem on a $d\times (m+1)$ grid: each factor corresponds to edges connecting adjacent levels, and a dense final matrix requires that every source node (first level) be able to transmit information to every sink node (last level) through the sequence of sparse factors.

BOFT adopts butterfly factorization, a topology inspired by the Cooley–Tukey FFT, which is efficient at connecting $d$ inputs to $d$ outputs with only $\mathcal{O}(d\log d)$ nonzero parameters when the factors are sparse. Formally, a radix-2 butterfly factor $\bm{B}^F(k)$ is a $k\times k$ block-structured matrix made from diagonal blocks (see the paper for the precise block form), and a full $d$-dimensional butterfly matrix $\bm{B}(d)$ is obtained by recursively composing such block components:
$\bm{B}(d)=\tilde{\bm{B}}(d,d)\tilde{\bm{B}}(d,\tfrac{d}{2})\cdots\tilde{\bm{B}}(d,2)$,
where each component $\tilde{\bm{B}}(d,k)$ is block-diagonal with blocks of size $k$. BOFT further defines a block butterfly component $\tilde{\bm{B}}^b(d,k)$ in which scalar entries are replaced by $b\times b$ blocks; enforcing orthogonality blockwise yields orthogonal butterfly components.

BOFT parameterizes the final orthogonal matrix as
$\bm{R}(m,b)=\prod_{i=1}^m \tilde{\bm{B}}^b_{(d,i)}$
with each factor orthogonal. The forward pass is
$\bm{z}=\big(\bm{R}(m,b)\bm{W}^0\big)^\top\bm{x}$.
BOFT’s parameter count scales as $\tfrac{1}{2}(b-1) d m$ effective trainable parameters, so choosing $m=\log d$ and $b=2$ yields $\mathcal{O}(d\log d)$ parameters — a dramatic reduction compared to the $\mathcal{O}(d^2)$ cost of full OFT while retaining the ability to represent dense orthogonal matrices.

Practical details and properties
BOFT inherits practical design choices that make it usable as a PEFT method. It uses identity initialization (initialize the skew-symmetric parameters so that each orthogonal factor is identity), which parallels the zero initialization used by additive methods like LoRA and helps ensure the finetuned model starts exactly at the pretrained model. Because BOFT’s update is multiplicative rather than additive, standard dropout does not apply directly; the paper proposes a multiplicative dropout that randomly replaces selected butterfly components or diagonal blocks with identity matrices during training.

On expressivity, the paper proves (in Theorem 1) that BOFT is more expressive than a block-diagonal OFT with the same block size, and that a suitable composition of butterfly matrices (and their transposes) can, in the limit, represent the entire orthogonal group (this composition is related to the so-called kaleidoscope hierarchy). The paper also emphasizes that greater expressivity is not automatically better for finetuning: the success of PEFT methods depends on finding an appropriate trade-off between expressivity and regularity.

Finally, BOFT inherits the spectral preservation of orthogonal updates: multiplying $\bm{W}^0$ on the left by an orthogonal matrix does not change its singular values, which is associated with beneficial training stability and generalization properties.

# Summary: design goals and how BOFT addresses them
To summarize the motivation threading the paper: large foundation models cannot be retrained for every task, so we need parameter-efficient adaptation methods that preserve pretraining knowledge. Geometry-aware finetuning — in particular, constraining updates to be orthogonal transformations — provides a principled way to preserve relational structure such as pairwise neuron angles and the spectral properties of pretrained layers. The challenge is to make such orthogonal finetuning parameter-efficient.

BOFT addresses that challenge by reframing dense orthogonal updates as the product of sparse orthogonal factors, using an information-transmission view to guide sparse factor design, and adopting butterfly factorization to achieve dense effective connectivity with only $\mathcal{O}(d\log d)$ parameters. BOFT thereby provides a middle ground in the expressivity–regularity–parameter-budget trade-off: it maintains geometry-aware updates while remaining practical in parameter-limited settings, and it does so without introducing inference-time latency because the learned orthogonal transformation can be multiplied back into the original weights after finetuning. The approach also suggests a principled way to design structured PEFT methods by borrowing ideas from fast linear transforms and network topologies.

Orthogonality in Finetuning: Principles and the OFT Baseline

# Neural geometry: preserving pairwise angles between neurons

When we speak of "neurons" inside a linear layer we typically mean the column vectors of a weight matrix. Concretely, let the pretrained linear layer be $W^0\in\mathbb{R}^{d\times n}$ and write its $i$-th column as $w_i\in\mathbb{R}^d$. The geometric relationships among these column vectors—most simply their pairwise inner products or the angles between them—encode relational information learned during pretraining. A common scalar summary of two neurons $w_i$ and $w_j$ is their cosine similarity
$\displaystyle \cos\theta_{ij}=\frac{w_i^\top w_j}{\|w_i\|\|w_j\|}$,
which directly depends on their inner product and norms.

Orthogonal transformations act as rigid rotations (possibly with reflections) in Euclidean space: an orthogonal matrix $R\in\mathbb{R}^{d\times d}$ satisfies $R^\top R=I$. The key geometric property we exploit in Orthogonal Finetuning (OFT) is that left-multiplying every neuron by the same orthogonal matrix preserves inner products and norms. Algebraically, for any two neurons $w_i,w_j$,
\[
(Rw_i)^\top (Rw_j) = w_i^\top R^\top R w_j = w_i^\top w_j,
\]
and similarly $\|Rw_i\|=\|w_i\|$. Therefore the cosine similarities (hence pairwise angles) among columns of $W^0$ remain exactly the same after applying $R$.

Intuitively, OFT treats the pretrained neuron collection as a geometric configuration (a point cloud on the sphere, if you normalize). Left-multiplying by an orthogonal matrix rotates that configuration without distorting relative angles or lengths. Because many aspects of the pretrained model’s semantic structure are encoded in these relative relationships, preserving pairwise angles is a natural way to keep pretraining knowledge intact while still allowing a controlled adaptation to a downstream task.

# Orthogonal transforms and their effect on representations and stability

Orthogonal left-multiplication does more than preserve pairwise angles: it preserves the singular-value spectrum of the layer’s weight matrix, which has direct implications for operator norms and training stability. Write a singular value decomposition of the pretrained weight matrix,
\[
W^0 = U\Sigma V^\top,
\]
with orthogonal $U\in\mathbb{R}^{d\times d}$, diagonal $\Sigma\in\mathbb{R}^{d\times n}$ and orthogonal $V\in\mathbb{R}^{n\times n}$. Left-multiplying by an orthogonal $R$ yields
\[
R W^0 = (R U)\,\Sigma\,V^\top.
\]
Because $R U$ is still orthogonal, the diagonal entries of $\Sigma$ (the singular values of $W^0$) are unchanged by the transformation. In particular the spectral norm (largest singular value) of $W^0$ is preserved.

Preservation of singular values and spectral norm is important: operator norms control how activations and gradients are amplified or contracted through a layer, and sudden changes to these norms during adaptation can destabilize training or push the model away from the well-conditioned regime learned in pretraining. OFT’s multiplicative, orthogonal update therefore offers an attractive stability property: it reorients the layer’s action in input space without changing its scale behavior. This spectral preservation is one of the reasons orthogonal finetuning has been observed to help generalization and to yield stable training dynamics.

Beyond spectral considerations, OFT can be interpreted as learning a bilinear similarity. Each logit or inner product computed after finetuning can be written as $w_i^{0\,\top}R x$, i.e. a bilinear form in $x$ and the pretrained neuron $w_i^0$ with learned matrix $R$. The orthogonality constraint on $R$ adds a strong regularity to this bilinear similarity learning, linking OFT to metric- and bilinear-form perspectives.

# OFT’s multiplicative update versus LoRA’s additive low-rank update

Two simple and widely used paradigms for parameter-efficient adaptation are additive low-rank updates and multiplicative orthogonal updates. LoRA-style methods modify a pretrained weight matrix additively: one writes
\[
W = W^0 + \Delta W,
\]
and parameterizes the update $\Delta W$ as the product of two low-rank matrices (i.e. $\Delta W$ has low rank). This additive, low-rank reparameterization is economical in parameters and can be zero-initialized so that the finetuned model initially matches the pretrained model.

By contrast, OFT uses a multiplicative update: it replaces the layer weight $W^0$ by $R W^0$, where $R$ is constrained to be orthogonal. The forward change is therefore
\[
z = (R W^0)^\top x,
\]
instead of $z = (W^0 + \Delta W)^\top x$. In words, LoRA adds a small correction in a restricted (low-rank) subspace, while OFT rotates the entire input/feature space in a norm- and angle-preserving way.

These two families have different inductive biases. Low-rank additive updates change the weight matrix’s singular values and can introduce small new directions for task-specific behavior; they are extremely parameter-efficient and have been empirically successful in many settings. Orthogonal multiplicative updates preserve geometry and spectral properties, which can yield greater training stability and often better generalizability when preserving pretraining structure is beneficial. The paper notes that OFT has shown particularly good generalizability and convergence in text-to-image diffusion finetuning, but that full orthogonal matrices incur substantially more parameters than low-rank additive methods—hence the design tension between expressivity, regularity, and parameter efficiency.

Both strategies commonly use an initialization that leaves the original pretrained network unchanged at the start: LoRA initializes its additive factors to zero, and OFT initializes the orthogonal transform to the identity (see below). This preserves the pretrained behavior at the outset of finetuning.

# Cayley transform basics for enforcing orthogonality

To optimize $R$ under the orthogonality constraint $R^\top R=I$ it is convenient to reparameterize $R$ using a map from an unconstrained space to the orthogonal group. OFT follows prior work and uses the Cayley transform. Let $Q\in\mathbb{R}^{d\times d}$ be skew-symmetric, i.e. $Q^\top=-Q$. The Cayley parameterization defines
\[
R = (I+Q)(I-Q)^{-1}.
\]
Two important practical facts make this parameterization attractive. First, when $Q=0$ we have $(I+Q)(I-Q)^{-1}=I$, so initializing $Q$ at zero yields $R=I$ and therefore the finetuned model initially reproduces the pretrained model exactly. Second, the Cayley map guarantees orthogonality: with $Q^\top=-Q$ one can verify
\[
R^\top = (I+Q)^{-1}(I-Q)
\]
and therefore
\[
R^\top R = (I+Q)^{-1}(I-Q)(I+Q)(I-Q)^{-1} = I,
\]
because $(I-Q)(I+Q)=(I+Q)(I-Q)=I-Q^2$ and the inverses cancel in the displayed arrangement. Thus each $Q$ in the skew-symmetric space maps to a valid orthogonal $R$, and we can optimize over the unconstrained entries of $Q$ (subject to $Q^\top=-Q$) while maintaining exact orthogonality of $R$ throughout training.

This parameterization is convenient and numerically stable in practice; it is the mechanism used in OFT to ensure the learned transform stays on the orthogonal manifold without performing constrained optimization directly on $R$.

# OFT’s forward pass: left-multiplying pretrained weights by an orthogonal matrix

Putting the pieces together, OFT implements finetuning for a pretrained linear layer by learning an orthogonal matrix $R$ (via the Cayley transform) and replacing the original forward computation
\[
z = (W^0)^\top x
\]
by
\[
z = (R W^0)^\top x.
\]
Viewed column-wise, if $w_i^0$ is the $i$-th neuron (column) of $W^0$, then the finetuned neuron is $R w_i^0$. Crucially, the same orthogonal $R$ is applied to every neuron in the layer: this layer-shared, multiplicative transformation simultaneously reorients all neurons while keeping their pairwise geometrical relationships intact.

Because OFT acts by left-multiplication, its effect is a layerwise re-basis of input space rather than a per-neuron additive correction. The optimization proceeds by adjusting the (skew-symmetric) Cayley parameter $Q$ so that $R=(I+Q)(I-Q)^{-1}$ yields a rotated set of neurons better suited to the downstream task.

# Block-diagonal OFT for parameter-efficiency: idea and drawbacks

A full $d\times d$ orthogonal matrix has $O(d^2)$ degrees of freedom, which can be expensive to store and update for large layers. The original OFT paper therefore proposed a parameter-efficient variant that constrains $R$ to be block-diagonal:
\[
R = \mathrm{diag}(R_1,R_2,\dots,R_r),
\]
where each block $R_i\in\mathbb{R}^{b\times b}$ and $br=d$. Each block is an orthogonal matrix in its own right (parameterized, for example, via a small Cayley transform or explicit rotations). This block-diagonal structure reduces the number of free parameters from the full $O(d^2)$ down to the sum of the block costs (roughly $r\cdot O(b^2)$), which for small $b$ can be much cheaper.

The block-diagonal trick trades representational flexibility for parameter efficiency. Because the off-block entries are structurally zero, the resulting $R$ mixes coordinates only within each block; coordinates belonging to different blocks are never combined by the orthogonal transform. In other words, the block-diagonal $R$ cannot realize arbitrary dense orthogonal transforms and cannot mix information across block boundaries.

Concretely, for a simple example with $d=4$ and two blocks of size $b=2$, the block-diagonal form
\[
R=\begin{bmatrix}R_1 & 0\\[4pt] 0 & R_2\end{bmatrix}
\]
forces every coordinate in the first two dimensions to remain independent from every coordinate in the last two dimensions under the rotation. If the downstream task requires transformations that couple these coordinates, the block structure cannot represent them.

# Why fixed index-based blocks can hurt expressivity and induce odd inductive biases

The block-diagonal parameterization introduces a strong and very specific inductive bias: it assumes that the $d$ coordinates of each neuron can be partitioned into $r$ disjoint groups (by index) and that no meaningful interaction between groups is necessary for the task. This assumption is rarely justified by the indexing of the coordinates themselves, since coordinate order in a pretrained weight matrix usually reflects implementation details not semantic grouping.

There are several consequences of this fixed index-based partitioning. First, the model’s hypothesis class is artificially restricted: many dense orthogonal transforms (including classical global transforms that mix all coordinates) become unreachable. Second, the imposed independence across blocks may cut through semantically coherent patterns, forcing the finetuner to approximate cross-block couplings by less efficient means (or not at all). Third, because the sparsity pattern is fixed and index-based, choosing a good block partition is nontrivial and task-dependent—there is no principled way to pick the index grouping a priori, and the wrong grouping can degrade performance.

In short, block-diagonal OFT attains parameter efficiency by introducing a crude structural prior. That prior can be helpful when it aligns with the problem structure, but when it does not, it reduces expressivity and risks introducing peculiar inductive biases that hurt adaptation.

# Comparison to LoRA’s low-rank parameterization family

LoRA and OFT exemplify two broad strategies for parameter-efficient finetuning: additive low-rank modifications versus multiplicative structured transforms. LoRA parameterizes an additive update as the product of two small matrices (a low-rank matrix), which gives a compact set of modifications and a straightforward way to allocate a small parameter budget. OFT parameterizes a multiplicative orthogonal transform that preserves neuron geometry and spectral properties.

These choices amount to different inductive biases. Low-rank updates bias the finetuned model toward adjustments lying in a low-dimensional subspace; they are very parameter-efficient and often effective in practice. Orthogonal multiplicative updates bias the finetuned model toward reorientations of the pretrained representation with exact preservation of pairwise angles and singular values; this can yield improved stability and generalization in settings where preserving pretraining geometry is valuable. The paper notes that OFT has demonstrated promising generalizability (for example in text-to-image diffusion finetuning), but in its full, unconstrained form OFT requires substantially more parameters than typical low-rank schemes—hence the motivation for structured orthogonal parameterizations and other efficiency tricks.

Both low-rank (LoRA) and sparse/structured (block-diagonal OFT and related families) parameterizations are examples of imposing structure to reduce the number of free parameters. The right choice depends on the adaptation scenario: tight parameter budgets and simple task-specific corrections often suit low-rank additive updates, while tasks that benefit from preserving the pretrained geometry and spectral characteristics may favor orthogonal multiplicative updates—provided parameter-efficiency concerns are addressed.

This chapter has laid out the geometric and algebraic foundations of Orthogonal Finetuning (OFT): why preserving pairwise neuron angles matters, how orthogonal transforms preserve inner products and singular values, how OFT implements a multiplicative update (in contrast to additive low-rank schemes), and how Cayley parameterization enforces orthogonality while permitting identity initialization. We also discussed the pragmatic block-diagonal variant used for parameter savings and the limits of that approach. These ideas make clear why orthogonality is a principled constraint for finetuning, and why designing parameter-efficient orthogonal parameterizations is an important research direction when scaling OFT to large models.

From Dense to Factorized Orthogonals: An Information Transmission View

# Matrix factorization as sequential information exchange

A central operation in Orthogonal Finetuning (OFT) is to replace a pretrained linear layer weight by its left-multiplication with an orthogonal matrix. Instead of learning one large dense orthogonal matrix $\bm{R}\in\mathbb{R}^{d\times d}$ directly, we can parameterize $\bm{R}$ as a product of smaller matrices,
\[
\bm{R} = \bm{B}_m \bm{B}_{m-1} \cdots \bm{B}_1,
\]
and make each factor $\bm{B}_i$ sparse and (optionally) orthogonal. Written this way, the multiplication is naturally interpreted as a sequence of information exchanges: $\bm{B}_1$ mixes the $d$ input coordinates into the next stage, $\bm{B}_2$ further mixes those intermediate coordinates, and so on until $\bm{B}_m$ produces the final coordinates that act on the pretrained weights.

Thinking about factorization in this sequential way highlights a trade-off that underlies the BOFT approach: we trade computation (multiplying several sparse matrices every forward/backward pass) for space (fewer trainable parameters than specifying a dense $\bm{R}$). It also makes clear the key design goal: by composing multiple sparse mixing steps we may obtain a final matrix that is dense (non-zero entries everywhere) while requiring far fewer total non-zero entries across the factors than the naive dense representation would. This is the perspective that leads to an information-transmission view of orthogonal factorization.

# Grid graph construction: nodes, levels, and edges from sparsity patterns

To make the sequential view graphically concrete, represent the factorization $\bm{R}=\bm{B}_m\cdots\bm{B}_1$ as a layered grid. Create $m+1$ vertical levels (also called stages or layers) and place $d$ nodes at each level, producing a $d\times(m+1)$ grid of nodes. Interpret the $j$-th entry at level $\ell$ as the node $(j,\ell)$.

Each factor $\bm{B}_i\in\mathbb{R}^{d\times d}$ induces directed edges from level $i$ to level $i+1$: specifically, the entry $(\bm{B}_i)_{p,q}\neq 0$ corresponds to a directed edge from node $(q,i)$ (source) to node $(p,i+1)$ (receiver). If $(\bm{B}_i)_{p,q}=0$ there is no direct edge between those two nodes in that stage. Unrolling the matrix product corresponds to concatenating these stage-to-stage connections into paths that go from level $1$ (the original coordinates) to level $m+1$ (the final coordinates).

This construction gives a clean dictionary between algebra and combinatorics. Algebraically, each entry of the final matrix $\bm{R}$ is a sum over products of entries from the factors; combinatorially, a nonzero term in that sum corresponds to a path of nonzero edges connecting a source node at level $1$ to a sink node at level $m+1$. Thus the pattern of nonzero entries of $\bm{R}$—the sparsity pattern we care about for expressivity—is exactly the reachability pattern in this layered grid graph.

# Dense connectivity requirement: every source must reach every sink

What does it mean for the composed matrix $\bm{R}$ to be dense from the graph viewpoint? The answer is simple and exact: for every source node $s\in\{1,\dots,d\}$ at the first level and every sink node $t\in\{1,\dots,d\}$ at the last level there must exist at least one directed path from $(s,1)$ to $(t,m+1)$ that traverses the intermediate levels using only edges corresponding to nonzero entries. If any pair $(s,t)$ lacks such a path, the corresponding entry $R_{t,s}$ will be zero and $\bm{R}$ will not be dense.

This reachability criterion gives a concrete target when we design sparsity patterns for the factors: we must ensure dense connectivity in the layered graph. Designing sparse factors that nevertheless allow every source to reach every sink is the combinatorial heart of factorized orthogonal finetuning. The advantage of this lens is that it separates two questions that are conflated if one only looks at matrices: (1) connectivity — whether the chosen sparsity pattern can possibly produce a dense final matrix, and (2) parameter count — how many independent, trainable degrees of freedom are required by that pattern once orthogonality constraints are imposed.

# Minimum free edges under orthogonality and full-rank constraints

Given the graph viewpoint, we can ask: among all layered graphs that achieve dense connectivity, which have the fewest trainable edges? The paper formalizes this as two desiderata: (i) dense connectivity and (ii) minimum free edges. Here “free edges” means the nonzero entries that are truly trainable parameters (as opposed to structural nonzeros that are forced by orthogonality constraints to take special values).

Orthogonality imposes nontrivial constraints on the per-stage matrices. First, each factor $\bm{B}_i$ that is required to be orthogonal must be full-rank; combinatorially this means there must be at least $d$ edges between level $i$ and level $i+1$ so that rows and columns can be matched as a bijection. These $d$ baseline edges are structural: for certain extreme patterns (for example a permutation matrix) the nonzeros can be $\pm 1$ and thus are not free real-valued parameters in the same way as arbitrary nonzeros would be. The paper highlights this by observing that one can find orthogonal matrices with only $d$ nonzero entries (permutation matrices), in which case those entries are restricted to $\pm 1$ and are not freely parameterizable.

Beyond requiring at least $d$ edges per stage, orthogonality also makes many nonzero entries interdependent. In other words, the number of independent (free) parameters associated to a given nonzero pattern is generally strictly less than the count of nonzero entries, because orthogonality couples entries across rows and columns. Therefore, when counting the resources required by a factorization we should focus on the number of free trainable parameters implied by the orthogonality constraint, not simply the raw number of nonzero locations.

A naive single dense factor (one dense orthogonal $\bm{R}$) is expensive: it naively requires on the order of $d^2$ entries. The paper reports that, counting in the paper’s bookkeeping convention, a single dense factor yields $d^2 - d$ trainable edges (for example, with $d=4$ this number is $12$). The central quest is to find layered factorizations that achieve dense final connectivity while dramatically reducing that effective count of trainable parameters.

# Impact of orthogonality on feasible edge sets and dependencies

Orthogonality does more than enforce full rank; it introduces algebraic dependencies among entries that change which sparsity patterns are feasible and how many free parameters they imply. A simple illustration is the $2\times 2$ case: let an orthogonal matrix be
\[
\begin{bmatrix} a & b \\ c & d \end{bmatrix},
\]
with orthonormal columns. If $a=0$, then column normalization forces $c=\pm 1$, and orthogonality between the two columns forces $b\cdot 0 + d\cdot c = d c = 0$, so $d=0$. In other words, a single zero at position $(1,1)$ forces another zero at $(2,2)$. This is the concrete phenomenon the paper alludes to: a missing edge in one position may imply a missing edge elsewhere once orthogonality constraints are enforced. The algebraic structure of the orthogonal group therefore couples entries, and a sparsity pattern that looks permissive at the level of nonzero locations may in fact allow very few independent parameters after orthogonality is enforced.

Conversely, orthogonality can also be used to our advantage. If a sparsity pattern is chosen carefully, the orthogonality constraints can reduce the number of independent parameters per block in a predictable way (for example, a $2\times 2$ orthogonal block has only one degree of freedom — a rotation angle — though it contains four nonzero entries). The key is to pick a factorization pattern where many nonzeros are grouped into small orthogonal blocks whose degrees of freedom are far fewer than their raw number of entries. This is exactly the structural leverage that butterfly factorization exploits: many small orthogonal $2\times 2$ blocks are composed in stages so that the final product can be dense while the number of independent parameters remains small.

# Why block-diagonal OFT cannot yield dense connectivity

The original OFT proposal achieved parameter efficiency by restricting the learned orthogonal transform to be block-diagonal:
\[
\bm{R} = \operatorname{diag}(\bm{R}_1,\bm{R}_2,\dots,\bm{R}_r),\qquad \bm{R}_i\in\mathbb{R}^{b\times b},\quad br=d.
\]
A block-diagonal $\bm{R}$ applies an independent orthogonal transformation to each contiguous group of coordinates and leaves off-block interactions strictly zero. From the layered graph perspective this means that nodes belonging to different blocks are never connected: the block structure partitions the $d$ coordinates into $r$ disjoint groups and there are no edges between groups. Consequently, no product of block-diagonal factors with the same partitioning can create off-block nonzeros, and the final matrix remains block-diagonal.

Therefore, the block-diagonal design cannot yield dense connectivity. It saves parameters by forbidding cross-block mixing, but this very sparsity kills the possibility of a dense final $\bm{R}$. The paper points out this limitation: while block-diagonal OFT reduces parameter count, it fixes a sparsity pattern that may introduce undesirable inductive bias and reduces expressiveness because it cannot approximate many dense linear transforms.

# Design desiderata: dense connectivity with few trainable edges

Putting the preceding observations together produces a compact list of design desiderata for any factorized orthogonal finetuning scheme:

1. Dense connectivity. The layered graph induced by the factors must let every source reach every sink, so that the composed matrix $\bm{R}$ can be dense and thus able to mix information across all coordinates.

2. Few free trainable edges. The factorization should require as few independent trainable parameters as possible, counting degrees of freedom after orthogonality constraints are imposed. This is the parameter-efficiency objective.

3. Orthogonality and full rank per factor. Each factor should be orthogonal (or otherwise constrained to preserve desirable properties such as spectral norm), which entails per-stage full-rank connectivity and couples entries algebraically. The chosen sparsity pattern must be compatible with these constraints.

4. A useful trade-off between expressivity and regularity. The factorization should provide enough flexibility to adapt to downstream tasks (expressivity) but should also impose structure to avoid overfitting and to preserve pretraining knowledge (regularity). The paper argues that certain structured factorizations, notably butterfly patterns, provide a smoother interpolation between the identity (high regularity) and the full orthogonal group (high expressivity) than a crude block-diagonal design.

The butterfly factorization satisfies these desiderata in a particularly attractive way: it constructs dense final matrices via a product of $O(\log d)$ sparse factors, each with $O(d)$ nonzeros, yielding $O(d\log d)$ nonzero locations and, after taking orthogonality reductions into account, $O(d\log d)$ effective trainable parameters. This meets the twin goals of dense connectivity and parameter parsimony.

# A worked miniature example contrasting factorizations and edge counts

To make these ideas concrete, consider the small case $d=4$. We compare three approaches and their rough edge counts as discussed in the paper.

1. Single dense orthogonal matrix (no factorization). A dense $4\times 4$ orthogonal matrix has on the order of $4^2=16$ entries. Counting in the paper’s bookkeeping (which subtracts a baseline of structural entries tied to orthogonality), the number of trainable edges reported is $d^2-d=4^2-4=12$. This is the expensive baseline.

2. An ad hoc sparse factorization (an example from the paper’s illustration). The paper gives an example factorization of $\bm{R}=\bm{B}_5\bm{B}_4\bm{B}_3\bm{B}_2\bm{B}_1$ whose combined nonzero pattern across factors requires $10$ edges in total and yet yields a dense final matrix. This shows that a factorized design can already beat the single dense factor in terms of raw nonzeros: $10<12$ for this toy case.

3. Butterfly factorization (radix-2 style). The radix-2 butterfly topology, inspired by Cooley–Tukey FFT, can achieve dense connectivity for $d=4$ with only $8$ nonzero entries across its stages. Intuitively, a $d$-dimensional butterfly uses $m=\log_2 d$ stages and each stage contains $d$ nonzero locations structured as $2\times 2$ blocks, so the total raw nonzero count is on the order of $d\log d$; for $d=4$, $d\log_2 d = 4\cdot 2 = 8$. Crucially, once we account for the orthogonality of each $2\times 2$ block, the number of independent trainable parameters is even smaller: each orthogonal $2\times 2$ block has only one degree of freedom (a rotation angle), so the effective number of real parameters ends up being proportional to the number of blocks rather than the number of raw nonzero entries. For BOFT with $b=2$ and $m=\log_2 d$, the paper gives the general effective parameter count scaling as $\mathcal{O}(d\log d)$; numerically for $d=4$ this produces very small parameter counts compared to the dense case.

This miniature comparison illustrates the core message: by arranging a small number of structured sparse interactions across multiple stages, one can obtain a final dense transformation while drastically lowering the number of independent trainable parameters. The butterfly topology is a particularly attractive instantiation of this idea because it is a compact, stagewise pattern that is known to realize many classical dense transforms (Fourier, Hadamard, etc.) and, as the paper argues, does so with strong parameter efficiency and a favorable bias toward generalization.

--- 

In summary, the information-transmission view turns the problem of constructing a dense orthogonal finetuning transform into a graph design problem. The layered grid representation exposes the two core requirements—dense reachability between every source and sink, and as few free trainable edges as possible under orthogonality constraints—and makes the efficiency of butterfly-style factorizations transparent: they obtain dense connectivity with only $O(d\log d)$ structure, a dramatic improvement over the naive $O(d^2)$ dense parameterization.

Butterfly Structures: Fast Transforms and Efficient Connectivity

# Cooley–Tukey FFT as recursive divide-and-conquer

The Cooley–Tukey fast Fourier transform (FFT) is a classical example of a divide-and-conquer algorithm that turns a dense, global linear transform into a sequence of small, local interactions. In the radix-2 Cooley–Tukey formulation the $N$-point discrete Fourier transform is recursively reduced to two $\frac{N}{2}$-point transforms; that recursion is the origin of the "butterfly" pattern of interactions. Conceptually, each recursive step mixes pairs of entries and then hands those mixed results to the next level of recursion. Repeating this mixing for $\log_2 N$ levels turns local pairwise operations into a global transform.

This recursive structure admits a natural matrix factorization into sparse factors, each representing one level of local pairwise mixing. The paper captures one convenient algebraic description of a small factor (a butterfly factor) as
\[
\bm{B}^F(k)
=
\begin{bmatrix}
\text{diag}(\bm{d}_1) & \text{diag}(\bm{d}_2)\\[4pt]
\text{diag}(\bm{d}_3) & \text{diag}(\bm{d}_4)
\end{bmatrix}
\in\mathbb{R}^{k\times k},
\]
where each $\bm{d}_i\in\mathbb{R}^{k/2}$. If we set $d=2^N$, the full $d$-dimensional butterfly matrix is formed recursively as
\[
\bm{B}(d)
=
\tilde{\bm{B}}(d,d)\cdot
\begin{bmatrix}\bm{B}_1(\tfrac{d}{2}) & \bm{0}\\[3pt]\bm{0} & \bm{B}_2(\tfrac{d}{2})\end{bmatrix}
=
\tilde{\bm{B}}(d,d)\,\tilde{\bm{B}}\big(d,\tfrac{d}{2}\big)\,\cdots\,\tilde{\bm{B}}(d,2),
\]
where each butterfly component
\[
\tilde{\bm{B}}(d,k)=\operatorname{diag}\big(\bm{B}^F_1(k),\ldots,\bm{B}^F_{d/k}(k)\big)
\]
is block-diagonal with blocks of size $k$ built from butterfly factors. Each such component is sparse: it is composed of many small $2\times 2$-style blocks (or small block matrices), so the global dense transform is realized as a product of these sparse, local factors. This is precisely the mechanism by which the FFT turns global mixing into a sequence of local stages.

# Butterfly graphs: topology and properties

Viewed as a graph, a butterfly factorization corresponds to nodes arranged in levelled columns and sparse directed edges only between adjacent levels. The paper makes this concrete with an information-transmission view: representing a target dense $d\times d$ matrix $\bm{R}$ as a product of $m$ matrices,
\[
\bm{R}=\bm{B}_m\bm{B}_{m-1}\cdots\bm{B}_1,
\]
is equivalent to a directed layered graph with $d$ nodes at each of $m+1$ levels. A matrix $\bm{B}_i$ gives the adjacency (edge weights) from level $i$ to level $i+1$. An entry $R_{ij}\neq 0$ means there exists at least one path from source node $j$ at level $1$ to sink node $i$ at level $m+1$.

The butterfly topology is a particular wiring of edges between levels that is extremely efficient for realizing dense connectivity between the first and last level. Its defining properties are that (1) each level contains $d$ nodes, (2) edges only connect nodes in adjacent levels, and (3) the pattern of connections at each level is highly structured — essentially a blockwise permutation of small mixing blocks (e.g., $2\times 2$ rotation-like blocks). Because each component $\tilde{\bm{B}}(d,k)$ is just a permutation of the basic $2\times 2$ non-zero pattern, it is straightforward to parameterize each component as orthogonal (for example via Cayley transforms or $2$-dimensional rotations), which is necessary when we require the product to remain orthogonal.

A useful generalization is the block butterfly component $\tilde{\bm{B}}^b(d,k)$ in which each scalar entry in the factor becomes a $b\times b$ block matrix. This lets us trade block size $b$ for the number of stages while preserving the same sparse-per-level wiring pattern; when $b=2$ we recover the usual radix-2 style butterfly. The essential graph-theoretic property is that a small number of structured stages — permutations of many small orthogonal blocks — suffice to route information from every source to every sink.

# Dense mixing with logarithmic stages

One of the butterfly's most striking consequences is that global (dense) mixing can be achieved with only logarithmically many stages. Intuitively, each stage mixes neighboring data in small groups; after one stage a piece of information reaches a few destinations, after two stages it reaches more, and after $\mathcal{O}(\log d)$ stages a single source can reach all $d$ sinks. Concretely, a butterfly parameterization for $d=2^N$ uses $N=\log_2 d$ components, and each component contains only $\mathcal{O}(d)$ non-zero blocks. Multiplying these $\mathcal{O}(\log d)$ sparse components produces a dense matrix while the total number of non-zero parameters is only $\mathcal{O}(d\log d)$.

The paper makes this precise for the BOFT (Orthogonal Butterfly) parameterization: with block size $b$ and $m$ stages, BOFT($m,b$) uses about
\[
\frac{1}{2}(b-1)\,d\,m
\]
effective trainable parameters for a layer of size $d\times n$. In the canonical butterfly case ($m=\log d$, $b=2$) this reduces to $\mathcal{O}(d\log d)$ parameters. By contrast, a fully unconstrained orthogonal matrix requires $\mathcal{O}(d^2)$ parameters, and the block-diagonal OFT variant requires $\mathcal{O}(b d)$ parameters (with $b$ the block size). Thus BOFT attains dense global mixing with far fewer trainable degrees of freedom than a naive dense orthogonal parameterization.

The information-transmission view also helps compare concrete edge counts. A single dense orthogonal factor between two levels nominally corresponds to $\mathcal{O}(d^2)$ edges (the paper counts the trainable edges as $d^2-d$, e.g., $12$ for $d=4$). The paper gives an illustrative factorization that takes $10$ edges for $d=4$, while a butterfly topology needs only $8$ edges to connect the same number of sources and sinks. These small examples highlight the asymptotic advantage: butterfly wiring achieves dense connectivity while keeping per-level adjacency sparse, and only $\log d$ such sparse levels are required.

# Historical uses of butterfly matrices in learning and optimization

Butterfly structures are not new to machine learning; their algebraic and graph properties have long made them useful across numerical linear algebra and learning. The paper surveys several prior applications that motivate reusing the structure for parameter-efficient finetuning:

- Butterfly parameterizations were studied to represent orthogonal matrices compactly, for example to avoid pivoting in Gaussian elimination and to improve numerical efficiency.  
- They have been applied to stabilize the training of recurrent neural networks by constraining recurrence matrices to structured orthogonals.  
- Butterfly-style factorizations have been used in kernel approximation and fast linear-transform learning: learning compact fast transforms that mimic the FFT-like behavior but are adapted to data.  
- More recently, butterfly matrices have been employed to enable efficient training of larger neural network components and to speed up matrix–vector multiplication in contexts where a fast structured transform is useful.  
- Beyond learning, butterfly graphs have also appeared in fast matrix–vector multiplication algorithms, data-sparse matrix approximations, and as efficient network topologies for information transmission.

The recurring theme in these uses is the same one exploited in BOFT: a product of sparse, structured factors can reproduce many useful dense linear maps at vastly lower parameter and memory cost, while often admitting fast algorithms for application and inversion.

# Why butterfly topology aligns with the information transmission desiderata

When we view dense orthogonal factorization as an information-transmission problem on a layered grid, two desiderata naturally emerge: (i) dense connectivity — every source node must be able to reach every sink node across the layers; and (ii) minimum free edges — under the orthogonality constraint, we want as few trainable edges as possible while still achieving dense connectivity.

The butterfly topology addresses both desiderata efficiently. Dense connectivity is ensured because the recursive mixing doubles the reach of information at each stage: local pairwise mixes at stage one are permuted and mixed again at stage two, and after $\log d$ stages information from a single source has been propagated to all sinks. Regarding the second desideratum, orthogonality imposes a lower bound on edges between adjacent levels: each factor must be full-rank, so there must be at least $d$ edges (a bijection) between two adjacent levels. Those $d$ structural edges are necessary and in many formulations are non-trainable (for example, entries constrained to $\pm1$), and the butterfly achieves dense connectivity with only a small number of additional trainable parameters beyond these required edges.

This is why the paper emphasizes that butterfly factorization trades space for computation: by allowing repeated application of sparse factors (more computation per forward/backward pass), we can use far fewer parameters (less space). The structure also produces a desirable inductive bias: the hypothesis class is a structured subset of the orthogonal group that contains many classical fast transforms (Fourier, Hadamard, etc.), so it tends to favor smooth, global mixing patterns that generalize well in finetuning tasks where preserving pretraining structure matters.

# Contrasting butterfly versus block-diagonal sparsity

Block-diagonal sparsity, the simple parameter-saving strategy used in the original OFT, splits the $d$ dimensions into independent groups and applies a separate orthogonal transform within each group. That design reduces parameter count and is straightforward to implement, but it has two key limitations. First, a block-diagonal orthogonal matrix cannot mix coordinates across blocks, so it cannot produce dense interactions across all $d$ dimensions; dense mixing requires the block size to grow and eventually become $d$, at which point the parameter count returns to $\mathcal{O}(d^2)$. Second, block-diagonal structure imposes a hard, index-based partition of neuron dimensions that can be an unnatural inductive bias for many problems and that prevents recovery of classic global transforms (for example the FFT or Hadamard transform) which inherently mix across all coordinates.

The butterfly alternative produces a smoother interpolation between the identity (maximum regularity) and the full orthogonal group (maximum expressivity). BOFT subsumes the block-diagonal OFT as a special case: BOFT($1,b$) is the block-diagonal OFT with block size $b$, and BOFT($1,d$) recovers the unconstrained full orthogonal OFT. Increasing the number of stages $m$ while reducing block size $b$ moves the parameterization along the spectrum from block-wise independent transforms toward global, dense transforms, but without blowing up the parameter count. This is formalized in the paper: BOFT is provably more expressive than OFT with the same block size (Theorem), and with an appropriate product of butterfly matrices (a kaleidoscope-like composition) one can, in principle, span the entire orthogonal group.

Practically, that means BOFT attains the best of both worlds in many settings: a restricted, structured hypothesis class that preserves pretraining geometry (through orthogonality) and yet has sufficient expressivity to implement important global transforms — all while using far fewer trainable parameters than a dense orthogonal parameterization. Moreover, because orthogonal multipliers preserve the spectral norm of the pretrained weight (if $\bm{W}^0=\bm{U}\bm{\Sigma}\bm{V}^\top$, then $\bm{R}\bm{W}^0= (\bm{R}\bm{U})\bm{\Sigma}\bm{V}^\top$ and the singular values $\bm{\Sigma}$ are unchanged), BOFT inherits the favorable spectral stability that motivates orthogonal finetuning in the first place.

Concluding remark

Butterfly structures convert the idea behind the FFT — local pairwise mixing organized recursively — into a compact, highly structured parameterization that is exceptionally well suited to the information-transmission goals underlying parameter-efficient orthogonal finetuning. With only $\mathcal{O}(d\log d)$ trainable degrees of freedom (in the canonical butterfly case), one can realize dense global mixing, preserve orthogonality and spectral properties, and induce an inductive bias aligned with many classical fast transforms. This makes the butterfly topology a compelling alternative to block-diagonal sparsity when we need both expressive global interactions and strong parameter efficiency.

BOFT: Orthogonal Butterfly Finetuning

# Butterfly factor and butterfly component definitions
The basic building block of the BOFT parameterization is the butterfly factor. For an even integer $k$ (in practice we work with powers of two), a butterfly factor $\bm{B}^F(k)\in\mathbb{R}^{k\times k}$ is written in block form as
\[
\bm{B}^F(k)
=
\begin{bmatrix}
\operatorname{diag}(\bm{d}_1) & \operatorname{diag}(\bm{d}_2)\\[4pt]
\operatorname{diag}(\bm{d}_3) & \operatorname{diag}(\bm{d}_4)
\end{bmatrix},
\]
where each $\bm{d}_i\in\mathbb{R}^{k/2}$ and $\operatorname{diag}(\bm{d}_i)$ denotes the diagonal matrix with entries $\bm{d}_i$. Conceptually, a butterfly factor mixes two equal-size groups of coordinates by applying diagonal (i.e., elementwise) multipliers to each half and then interleaving them; this sparse 2-by-2 block pattern is the canonical local mixing primitive used in classic fast transforms.

A butterfly component at stride $k$ is a block-diagonal matrix that places many copies of such butterfly factors along the diagonal. Writing $d$ for the full dimension (in the paper $d$ is assumed to be a power of two), the component is
\[
\tilde{\bm{B}}(d,k)=\operatorname{diag}\big(\bm{B}^F_1(k),\bm{B}^F_2(k),\dots,\bm{B}^F_{d/k}(k)\big),
\]
so $\tilde{\bm{B}}(d,k)\in\mathbb{R}^{d\times d}$ is block-diagonal with $d/k$ blocks each equal in sparsity pattern to $\bm{B}^F(k)$. Each component is therefore sparse (only $O(d)$ nonzero diagonals per component) but will be combined with other components to produce global mixing.

# Recursive construction of butterfly matrices
Butterfly matrices arise by composing a sequence of these components at different scales. When $d=2^N$, the full $d\times d$ (scalar) butterfly matrix is built recursively as
\[
\bm{B}(d)
=
\tilde{\bm{B}}(d,d)\cdot
\begin{bmatrix}
\bm{B}_1(d/2) & \bm{0}\\[4pt]
\bm{0} & \bm{B}_2(d/2)
\end{bmatrix}
\;=\;
\tilde{\bm{B}}(d,d)\,\tilde{\bm{B}}(d,d/2)\cdots\tilde{\bm{B}}(d,2),
\]
where each $\bm{B}_1(\cdot)$ and $\bm{B}_2(\cdot)$ is itself a smaller butterfly matrix, and each $\tilde{\bm{B}}(d,k)$ is the block-diagonal component defined above. Viewed this way, the full transform is the product of $\log_2 d$ components with decreasing block sizes: the first component mixes large chunks, the next mixes finer-grained pairs inside those chunks, and so on, until the final $\tilde{\bm{B}}(d,2)$ mixes element pairs.

Two points to keep in mind. First, each component is sparse and structured (block-diagonal with small 2-by-2-like blocks), so storage is linear in $d$ per component. Second, because these components are placed at different scales and then multiplied together, the overall matrix $\bm{B}(d)$ can be dense even though every individual component is sparse. That is the key property that lets the butterfly parameterization achieve dense mixing with only $O(d\log d)$ sparse factors.

# From 2x2 to block 2b x 2b orthogonal building blocks
The scalar-valued butterfly factors above can be generalized to block form to control the trade-off between parameter count and expressivity. Replace each scalar entry in the diagonal vectors $\bm{d}_i$ by a $b\times b$ matrix (for an integer $b\ge 1$). This yields a block butterfly component which we denote $\tilde{\bm{B}}^b(d,k)$. Concretely, each $\bm{B}^F(k)$ is replaced by a block version whose entries are $b\times b$ matrices, so each small 2-by-2 scalar factor becomes a $2b\times 2b$ block.

Doing this blockification has two effects that are useful in practice. First, it increases the per-block degrees of freedom (each block can implement a small orthogonal transform rather than just a scalar multiplier), which raises expressivity without blowing up parameter count across the whole layer. Second, it preserves the sparse, structured pattern of butterfly components: for $k>2$ the nonzero pattern of every $\tilde{\bm{B}}^b(d,k)$ is just a block-wise permutation of the $\tilde{\bm{B}}^b(d,2)$ pattern. By varying $b$ (block size) and the number of stages $m$ we can smoothly interpolate between highly parameter-efficient but restricted transforms and more expressive ones.

# Ensuring orthogonality via Cayley transforms on small blocks
BOFT imposes orthogonality on the learned transform at every component so that the entire product remains orthogonal (product of orthogonal matrices is orthogonal). To guarantee orthogonality in a numerically stable and parameter-efficient way, each small block (the minimal blocks in $\tilde{\bm{B}}^b(d,2)$, i.e., the $2b\times 2b$ blocks) is parameterized to be orthogonal. A convenient and widely used reparameterization is the Cayley transform: any orthogonal matrix without $-1$ eigenvalues can be written as
\[
\bm{R} = (\bm{I} + \bm{Q})(\bm{I}-\bm{Q})^{-1},
\]
where $\bm{Q}$ is skew-symmetric ($\bm{Q} = -\bm{Q}^\top$). Applying the Cayley transform block-wise lets us parameterize every $2b\times 2b$ block with the independent entries of a skew-symmetric matrix and guarantees exact orthogonality of that block. Because each butterfly component is a permutation of these $2b\times 2b$ orthogonal blocks, the entire component is orthogonal; therefore the product of components
\[
\bm{R}(m,b)=\prod_{i=1}^{m}\tilde{\bm{B}}^b_{(d,i)}
\]
is orthogonal whenever every $\tilde{\bm{B}}^b_{(d,i)}$ is orthogonal.

For the smallest scalar case ($b=1$), each $2\times 2$ block can be parameterized as a planar rotation (one scalar angle), which is a special case of the Cayley parameterization. In practice the Cayley parameterization provides a uniform mechanism across block sizes for enforcing orthogonality and for initializing to identity (see below).

# BOFT(m, b): depth m, block size b, and resulting R(m, b)
BOFT is specified by two integers: the number of butterfly stages $m$ (the depth) and the block size parameter $b$. For notational convenience the paper denotes the $i$-th component by
\[
\tilde{\bm{B}}^b_{(d,i)} \coloneqq \tilde{\bm{B}}^b\big(d,\,2^{\,m-i+1}\big),
\]
so the learned orthogonal transform is the product of these $m$ orthogonal components:
\[
\bm{R}(m,b)=\prod_{i=1}^{m}\tilde{\bm{B}}^b_{(d,i)}.
\]
Given a pretrained linear layer with weight matrix $\bm{W}^0\in\mathbb{R}^{d\times n}$, BOFT applies the learned orthogonal transform multiplicatively on the left and leaves $\bm{W}^0$ frozen; the forward pass becomes
\[
\bm{z} = \big(\bm{R}(m,b)\,\bm{W}^0\big)^\top \bm{x},
\]
with $\bm{x}\in\mathbb{R}^d$ the input and $\bm{z}\in\mathbb{R}^n$ the output. Because each component is orthogonal by construction, $\bm{R}(m,b)$ is orthogonal and the spectral properties of the pretrained weight matrix (e.g., singular values) are preserved up to the orthogonal left multiplication.

Intuitively, $m$ controls how many scales of mixing are available (larger $m$ yields finer mixing and can densify the overall product), while $b$ controls how many degrees of freedom each local mixing unit has (larger $b$ gives bigger local orthogonal blocks and hence more parameters per stage). By choosing $(m,b)$ we trade between parameter cost, computational cost during training (because each component must be multiplied at each forward/backward pass), and expressivity.

# Special cases: BOFT(1, b) equals block-diagonal OFT; BOFT(1, d) equals full OFT
The BOFT family subsumes the OFT variants previously used in the literature as special cases. When $m=1$ there is only a single butterfly component, and that component is block-diagonal: BOFT(1,b) is therefore exactly the block-diagonal Orthogonal Finetuning (OFT) with block size $b$. If we further set $b=d$ (one block covering the whole dimension), BOFT(1,d) corresponds to an unconstrained full orthogonal matrix on the $d$-dimensional space and thus matches the original full-matrix OFT. These equivalences show BOFT is a strict generalization: by increasing $m$ (adding more sparse components) one can go from a coarse block-diagonal transform to denser, more expressive transforms without abandoning the orthogonality constraint.

# Dense orthogonals with BOFT(log(2d/b), b)
One of the attractive properties of the butterfly factorization is that with enough stages it can produce a dense transform even though every stage is sparse. Concretely, if $d$ is a power of two and we choose the number of stages
\[
m=\log_2\!\left(\frac{2d}{b}\right),
\]
then BOFT$(m,b)$ implements the (block) butterfly matrix $\bm{B}^{b/2}(d)$ as the overall $\bm{R}$ and the product becomes dense: every input coordinate can influence every output coordinate through paths that traverse the successive sparse components. In the scalar-block limit ($b=2$ in the paper's notation) this reduces to the classical radix-2 butterfly with $m=\log_2 d$ stages, the familiar decomposition that underlies the FFT. In short, increasing $m$ to about $\log_2(d)$ stages achieves dense mixing while still keeping the parameterization built from sparse, structured factors.

# Parameter count formula and scaling: 0.5 × (b − 1) × d × m
A compact expression for the number of trainable scalar parameters in BOFT$(m,b)$ (the effective degrees of freedom that are being learned) is
\[
\text{parameters}(m,b) \;=\; \frac{1}{2}\,(b-1)\,d\,m.
\]
This formula can be understood by counting per-component blocks and the degrees of freedom per block. Each butterfly component contains $d/b$ independent block positions; treating each block as a $b\times b$ orthogonal block, that block has $b(b-1)/2$ degrees of freedom (the dimension of the orthogonal group $O(b)$). Multiplying $d/b$ blocks per component by $b(b-1)/2$ parameters per block gives $d(b-1)/2$ parameters per component, and with $m$ components we obtain the stated total.

Two useful sanity checks of this formula are worth noting. First, if $m=1$ and $b=d$ then
\[
\text{parameters}(1,d)=\tfrac{1}{2}(d-1)d,
\]
which equals the degrees of freedom of a full $d\times d$ orthogonal matrix (the usual OFT full-matrix case). Second, taking the butterfly extreme $b=2$ with $m=\log_2 d$, the parameter count scales like $O(d\log d)$ (indeed $\frac{1}{2}(2-1)d\log_2 d = \tfrac{1}{2}d\log_2 d$), realizing the paper's main economy: dense orthogonal behavior with near-linear parameter cost multiplied by $\log d$.

Practically, this formula makes clear how to trade parameters: increasing $b$ raises per-stage capacity, while increasing $m$ increases how many scales of mixing are available. BOFT often obtains better parameter-efficiency (expressivity per parameter) than a pure block-diagonal OFT with the same $b$ because the deeper sparse composition can approximate more of the orthogonal group than a single block-diagonal matrix.

# Identity initialization for zero-update start
A desirable property of finetuning is to start from the pretrained model exactly so that, before any training, the finetuned model and the pretrained model coincide. BOFT achieves this by initializing every orthogonal block in every butterfly component to the identity matrix. Under the Cayley parameterization this corresponds simply to initializing each block's skew-symmetric parameter $\bm{Q}$ to the zero matrix (since $(\bm{I}+\bm{0})(\bm{I}-\bm{0})^{-1}=\bm{I}$). With this identity initialization we have $\bm{R}(m,b)=\bm{I}$ at the start of training and the first updates move away from identity in a principled, orthogonality-preserving manner.

# Multiplicative Dropout: blockwise identity replacement for regularization
Because BOFT updates weights multiplicatively ($\bm{W} \leftarrow \bm{R}\bm{W}^0$) rather than additively, conventional element-wise dropout applied to the update does not translate directly. To regularize BOFT in a manner analogous to dropout on additive updates, the paper proposes multiplicative Dropout: during training, randomly select a fraction $p_1$ of the butterfly components and, within the remaining components, randomly select a fraction $p_2$ of the block positions and temporarily replace those selected components / blocks by identity matrices for that forward/backward pass. In effect, multiplicative Dropout stochastically freezes a subset of the multiplicative factors to identity, which reduces overfitting by preventing co-adaptation of too many components at once while preserving the multiplicative orthogonal structure. Because the identity is an orthogonal element, this replacement respects the orthogonality constraint and is straightforward to implement when the components are stored block-wise.

Concluding remark (summary)
BOFT parameterizes a dense $d\times d$ orthogonal transform as a product of $m$ sparse, structured, block-wise-orthogonal butterfly components. By choosing $(m,b)$ appropriately one obtains a flexible continuum from simple block-diagonal OFT up to dense, highly expressive orthogonal transforms, while the parameter count scales as $\tfrac{1}{2}(b-1)dm$. Identity initialization and blockwise Cayley reparameterization enforce orthogonality throughout training and enable a zero-update start; multiplicative Dropout provides a simple block-level regularizer tailored to the multiplicative nature of the parameterization. Together these design choices realize BOFT's goal: orthogonal finetuning with far fewer trainable parameters than an unconstrained full orthogonal matrix, but with more global mixing than a single block-diagonal OFT.

Computation and Implementation Details

# Applying BOFT at activation time: computing $R^\top x$ before the frozen layer

BOFT modifies a pretrained linear layer $\bm{W}^0\in\mathbb{R}^{d\times n}$ by left-multiplying it with a trainable orthogonal matrix $\bm{R}\in\mathbb{R}^{d\times d}$. The forward pass in the paper is written as
$
\bm{z} = \big(\bm{R}\bm{W}^0\big)^\top \bm{x}.
$
A simple algebraic rearrangement that is critical for an efficient implementation is
$
\bm{z} = (\bm{R}\bm{W}^0)^\top \bm{x} = (\bm{W}^0)^\top \big(\bm{R}^\top \bm{x}\big).
$
This identity shows that rather than forming $\bm{R}\bm{W}^0$ explicitly, one can first compute the transformed activation $\bm{y}=\bm{R}^\top\bm{x}$ and then apply the frozen matrix multiply $\bm{z}=(\bm{W}^0)^\top\bm{y}$. The latter is the same dense activity as in the original pretrained model; BOFT only adds the cost of computing $\bm{R}^\top\bm{x}$ at activation time.

Because BOFT parameterizes $\bm{R}$ as a product of $m$ orthogonal butterfly components,
\[
\bm{R} = \prod_{i=1}^m \tilde{\bm{B}}_{(d,i)}^b,
\]
the transpose factorizes in the reverse order:
\[
\bm{R}^\top = \big(\tilde{\bm{B}}_{(d,1)}^b\big)^\top \big(\tilde{\bm{B}}_{(d,2)}^b\big)^\top \cdots \big(\tilde{\bm{B}}_{(d,m)}^b\big)^\top.
\]
Thus the activation transform is implemented by a sequence of $m$ small transforms: start with $\bm{y}\leftarrow\bm{x}$ and for $i=1\ldots m$ set $\bm{y}\leftarrow \big(\tilde{\bm{B}}_{(d,i)}^b\big)^\top \bm{y}$. Each $\tilde{\bm{B}}_{(d,i)}^b$ is block-diagonal (a butterfly component), and each block is an orthogonal small matrix (for the base case $2\times 2$ blocks these are planar rotations; for block-butterfly they are $2b\times 2b$ orthogonal matrices parameterized via Cayley).

Practical implementation therefore reduces to a tight loop that repeatedly (1) permutes or re-indexes the $d$ coordinates according to the component's pattern, (2) reshapes the relevant coordinates into contiguous mini-blocks, and (3) applies the small block orthogonal transforms. Because every component is sparse / block-structured, each step operates on small contiguous slices of the activation vector and can be implemented with small dense micro-kernels (2×2 or $2b\times 2b$). Identity initialization corresponds to initializing the Cayley skew-symmetric parameters to zero so every $\tilde{\bm{B}}_{(d,i)}^b$ starts as $\bm{I}$; multiplicative Dropout (as proposed in the paper) is applied at activation time by randomly replacing selected components or selected blocks with the identity during training.

# Training-time cost: $O(d\,m)$ for computing $\bm{R}^\top\bm{x}$ plus the frozen matrix multiply

The paper highlights that each butterfly component is sparse with $\mathcal{O}(d)$ nonzero entries. Applying one such component to a length-$d$ vector therefore costs $\mathcal{O}(d)$ scalar multiply–adds; applying $m$ components sequentially costs $\mathcal{O}(d\,m)$. The full forward cost for the finetuned layer is the sum of that overhead plus the usual frozen multiply by $(\bm{W}^0)^\top$, which costs $\mathcal{O}(d\,n)$ where $n$ is the output dimension. In practice the $\mathcal{O}(d\,m)$ term is often smaller than the dense multiply cost (unless $m$ is large and $n$ is small), which is why the paper describes BOFT's runtime overhead as only "slightly larger" than OFT.

Backpropagation through BOFT mirrors the forward sequence: gradients flow back through the same $m$ components in reverse order. The backward pass therefore incurs comparable $\mathcal{O}(d\,m)$ work to compute gradients with respect to the activations and to accumulate gradients for the component parameters. The paper also gives the number of effective trainable parameters per layer as
\[
\text{params} = \tfrac{1}{2}(b-1)\,d\,m,
\]
so the memory and update cost for parameter gradients scale linearly in this quantity.

These complexity observations justify the practical operating point recommended in the paper: choose $m$ and block size $b$ to trade expressivity, parameter count, and per-step runtime. Typical BOFT regimes (e.g., $m\approx \log d, b=2$) yield $\mathcal{O}(d\log d)$ parameters and $\mathcal{O}(d\log d)$ per-activation overhead, substantially smaller than a full dense orthogonal $\mathcal{O}(d^2)$.

# Inference-time fusion: pre-multiplying $\bm{R}$ into $\bm{W}^0$ to avoid latency

A key practical benefit of BOFT emphasized in the paper is that the learned orthogonal $\bm{R}$ can be absorbed into the frozen weights after finetuning. Concretely, once training is finished compute the fused weight
\[
\bm{W}^{\text{fused}} = \bm{R}\,\bm{W}^0,
\]
and replace the original module by the single frozen linear layer with weights $\bm{W}^{\text{fused}}$. After this one-time dense multiplication there is no per-inference overhead from BOFT; inference proceeds exactly as in the original pretrained model. The one-time fusion cost is the dense matrix multiply cost $\mathcal{O}(d^2 n)$ (or distributed variants thereof) and is typically performed offline.

Because $\bm{R}$ is orthogonal, this fusion is lossless: the model with fused weights implements the identical linear mapping as the BOFT configuration. The paper highlights this as an attractive deployment property: the parameter efficiency and training regularization advantages of BOFT do not impose any inference latency or structural constraints at deployment time.

# Permutation and layout of butterfly components for efficient kernels

A practical implementation detail that follows from the butterfly construction in the paper is that each butterfly component can be expressed as (i) a permutation of coordinates followed by (ii) a block-diagonal matrix whose blocks are small orthogonal transforms. The non-zero sparsity pattern of $\tilde{\bm{B}}(d,k)$ is a permutation of the $2\times 2$ base pattern; in the block variant $\tilde{\bm{B}}^b(d,k)$ the entries become contiguous $b\times b$ subblocks. This structure suggests an implementation strategy that minimizes scatter/gather overhead:

- Precompute the index permutation for each component and store it as an integer array. Applying the component becomes: permute the vector once (or interpret indices via strided views), then apply the block transforms to contiguous blocks.

- Implement each block transform as a small dense kernel. For the $2\times 2$ case this is just two fused multiply–adds operating on pairs; for $2b\times 2b$ blocks a tiny GEMM or an unrolled sequence of vector operations is efficient.

- Fuse the permutation with the block kernels when possible (apply the permutation implicitly by computing the block index mapping so that memory accesses are unit-stride).

Because the butterfly components are fixed in structure and the same permutation pattern repeats across batches and layers, these precomputed indices enable highly efficient, vectorizable inner loops. The paper points out that the non-zero pattern is a permutation of the base $2\times 2$ pattern, which is precisely why these precomputation and contiguous-block strategies are feasible.

# Handling non power-of-two dimensions: padding and block variants

The canonical butterfly construction in the paper is written for $d=2^N$ (it assumes $k\ge 2$ is a power of two). The work also introduces block-butterfly components $\tilde{\bm{B}}^b(d,k)$ where each scalar in the base butterfly factor is replaced by a $b\times b$ block; BOFT($m,b$) generalizes the construction and allows $b\ge 2$. Two practical observations from the paper make it straightforward to handle general $d$ in real models:

1. Select a block size $b$ that divides $d$ and construct $\tilde{\bm{B}}^b$ components so that the block-diagonal tiling is exact. With block-butterfly components the requirement that $d$ itself be a strict power of two is relaxed as long as the component tiling is compatible with $d$.

2. When $d$ is not an exact match for desired tiling, a simple and common pragmatic option (consistent with the construction spirit in the paper) is to pad the activation vector to the next compatible size, apply the BOFT components, and then slice back to the original dimension. Identity initialization and the orthogonality constraint make such padding safe during training and fusion: the padded coordinates can be ignored in downstream layers, and after training the final $\bm{R}$ can be fused into $\bm{W}^0$ and the weight rows/columns corresponding to padded dimensions removed.

The paper does not develop or evaluate mixed-radix butterfly factorizations in detail, but the block-butterfly and padding approaches give straightforward, practical paths to apply BOFT to layers whose dimension is not a power of two.

# Mixed precision and numerical stability of Cayley transforms

Orthogonality in BOFT is enforced by parametric orthogonal blocks; the paper follows prior work in using the Cayley parameterization for this purpose:
\[
\bm{R} = (\bm{I}+\bm{Q})(\bm{I}-\bm{Q})^{-1},
\]
with $\bm{Q}$ skew-symmetric. Several practical points flow directly from this choice:

- Initialization: setting $\bm{Q}=\bm{0}$ yields $\bm{R}=\bm{I}$, which gives the zero-update / identity initialization the paper emphasizes for stable finetuning. This also keeps $(\bm{I}-\bm{Q})$ trivially well-conditioned at the start of training.

- Local block transforms: in BOFT the Cayley parameterization is applied at the level of small blocks (e.g., $2\times 2$ or $2b\times 2b$). For the $2\times 2$ case a Cayley transform reduces to a planar rotation and admits a stable closed-form implementation; for small $2b\times 2b$ blocks numerical inversion or direct small-matrix solves are inexpensive and numerically well behaved because block size is small.

- Mixed precision: because BOFT works on many small blocks, it is natural to perform most arithmetic in reduced precision (e.g., float16 or bfloat16) for throughput, but to keep sensitive operations (the small matrix solves or explicit inverses for Cayley) in higher precision (float32) if numerical robustness is a concern. The paper does not study mixed-precision numerics in detail, but the blockwise nature of BOFT makes it straightforward to isolate the few numerically sensitive kernels and run them in higher precision while keeping the bulk computation low-precision.

Finally, the Cayley map with skew-symmetric $\bm{Q}$ is always well-defined (real skew-symmetric matrices have purely imaginary eigenvalues, so $\bm{I}-\bm{Q}$ is nonsingular). Nevertheless, if training drives some blocks of $\bm{Q}$ to have very large norm the numerical conditioning of $(\bm{I}-\bm{Q})$ may worsen; identity initialization and modest learning rates (both recommended in the finetuning literature and consistent with the paper) reduce that risk.

# Memory footprint and checkpointing strategies

The paper gives the parameter count for BOFT($m,b$) as $\tfrac{1}{2}(b-1)\,d\,m$ effective trainable parameters for a $d\times n$ linear layer. Beyond parameter storage, the runtime memory footprint during training includes any intermediate activations required by backpropagation. A straightforward forward implementation that stores the activation vector after each butterfly component requires storing $m$ intermediate length-$d$ vectors (total activation storage $\mathcal{O}(d\,m)$) in addition to the usual per-layer activations. This can be significant if $m$ is large.

A standard remedy (compatible with the BOFT factorization in the paper) is to use activation checkpointing / recomputation: do not store all intermediate $\bm{y}_i$ vectors; instead, recompute them on the backward pass by re-applying the small forward kernels. Because each component is cheap ($\mathcal{O}(d)$) and operates on small blocks, recomputation is typically inexpensive relative to storing and communicating large activation buffers. The blockwise structure also makes it straightforward to checkpoint at coarse granularity (store every few components and recompute intermediate ones), trading compute for memory. The paper notes a modest runtime overhead compared to OFT; checkpointing is the standard practical way to keep peak memory within limits while paying small extra compute.

# Practical pseudocode structure and integration points

Below is a concise pseudocode-style description of the key operations that follows the structure used in the paper. The code uses $m$ components $\{\tilde{\bm{B}}_{(d,i)}^b\}_{i=1}^m$ stored as small block-orthogonal parameterizations (e.g., skew-symmetric $\bm{Q}$ per block) and precomputed integer permutations $\pi_i$ for each component.

Forward pass (training/inference when not fused)
1. Input: activation $\bm{x}\in\mathbb{R}^d$, components $\{\tilde{\bm{B}}_{(d,i)}^b\}$, frozen weights $\bm{W}^0\in\mathbb{R}^{d\times n}$, multiplicative-dropout masks (optional).
2. Set $\bm{y}\leftarrow \bm{x}$.
3. For $i=1$ to $m$:
   a. Optionally apply multiplicative dropout: if this component (or selected blocks) is dropped, skip to next $i$.
   b. Apply permutation $\bm{y}\leftarrow \text{permute}(\bm{y};\pi_i)$.
   c. For each block index $j$ in the block-diagonal tiling:
       i. Extract block slice $\bm{y}_j$ (length $2b$ or $k$).
       ii. Apply small orthogonal transform $\bm{y}_j \leftarrow \big(\text{block\_orthogonal}_j\big)^\top \bm{y}_j$ (block implemented via Cayley or closed-form).
   d. (Optionally) reverse the permutation if the component representation requires it.
4. Compute final output $\bm{z}\leftarrow (\bm{W}^0)^\top \bm{y}$.

Backward pass
- Backpropagate through the dense multiply $(\bm{W}^0)^\top$ to obtain gradient w.r.t. $\bm{y}$, then sequentially backpropagate through the $m$ components in reverse order to obtain gradients w.r.t. component parameters. If activations were checkpointed, recompute needed forward states as necessary during the backward sweep.

Fusion after training
1. Compute fused weights $\bm{W}^{\text{fused}} \leftarrow \bm{R}\,\bm{W}^0$ by constructing $\bm{R}$ block-by-block from the learned components (or by applying the learned $\bm{R}$ to each basis vector to form $d$ columns).
2. Replace the layer by the single frozen dense layer with weights $\bm{W}^{\text{fused}}$; discard BOFT parameters.

Integration points in a typical codebase
- Replace or wrap linear layers with a BOFT wrapper that implements the activation-time transform in the forward pass, stores small block parameters, and supports the fusion API.
- Provide utilities to export and fuse BOFT parameters into a single dense weight tensor for deployment.
- Expose multiplicative-dropout masks and identity initialization hooks for training-time behavior that matches the paper.

Closing remark
All implementation choices above follow directly from the BOFT construction and desiderata in the paper: apply $\bm{R}^\top$ to activations before the frozen layer, implement $\bm{R}$ as a product of sparse orthogonal butterfly components, exploit the block/permute structure for efficient kernels, keep the Cayley parameterization per small block to guarantee orthogonality, and fuse $\bm{R}$ into $\bm{W}^0$ after training so there is no inference overhead. The practical trade-offs—how many components $m$ to use, what block size $b$ to choose, and whether to checkpoint—control the familiar trade-off between parameter-efficiency, compute overhead, and expressivity that the paper emphasizes.

Expressivity, Regularization, and Theoretical Insights

# Empirical approximation of random dense orthogonals under fixed budgets

One concrete way to measure how expressive a parameterization of orthogonal matrices is, and how efficiently it uses parameters, is to ask: given a fixed parameter budget, how well can the parameterization approximate an arbitrary dense orthogonal matrix? The paper reports a simple simulation along these lines. A random target orthogonal matrix of size $512\times 512$ was sampled and different BOFT configurations (indexed by block size $b$ and number of components $m$) were trained to approximate that target. Each configuration was evaluated over 10 random seeds and the averaged approximation error (plotted on the y-axis) was recorded against the effective number of trainable parameters (x-axis). The same experiment was run for the block-diagonal OFT baselines (which correspond to BOFT with $m=1$).

The qualitative outcome is straightforward and informative: BOFT configurations with more factors ($m$ larger) and smaller block size ($b$ smaller) tend to achieve a lower approximation error for the same parameter count than block-diagonal OFT configurations. Concretely, the paper highlights that a deep-but-sparse configuration such as BOFT$(9,2)$ can outperform BOFT$(1,16)$ while using far fewer parameters. Similarly, BOFT$(6,4)$ attains an approximation error similar to BOFT$(2,16)$ but with a smaller parameter budget. These examples illustrate the central empirical point: factorizing a dense orthogonal matrix into several sparse, structured orthogonal components (the butterfly components) yields substantially better parameter-efficiency than a single block-diagonal orthogonal matrix whose blocks are the same size.

Intuitively, the experiment demonstrates that spreading representational capacity across multiple compositional stages (increasing $m$) yields greater connectivity and mixing power per parameter than concentrating the same parameter budget into larger isolated blocks (increasing $b$ at $m=1$). This empirical behavior motivates the theoretical discussion that follows: BOFT’s sparse multi-stage structure is better able to route and combine information between coordinates than a block-isolated parameterization that cannot mix across block boundaries.

# Why BOFT surpasses OFT’s expressivity at the same block size

At the core of the comparison between BOFT and block-diagonal OFT is the difference in how the two parameterizations allow information to flow between coordinates. Block-diagonal OFT with block size $b$ partitions the $d$ coordinates into $r=d/b$ independent groups and applies an orthogonal transform within each group. No matter how expressive each block is, coordinates in different blocks never mix. BOFT, by contrast, composes multiple sparse orthogonal blocks arranged in a butterfly pattern so that coordinates are progressively mixed across stages.

Two concrete points explain why BOFT is strictly more expressive than block-diagonal OFT with the same $b$:

1. Connectivity and mixing: In the information-transmission graph viewpoint used in the paper, a block-diagonal transform corresponds to having edges only within each block at every stage; there is no path from a node in block A to a node in block B. BOFT’s butterfly topology is designed to create paths from every source node to every sink node after composing the stages. Even when each block in each stage is small (e.g., $2\times 2$), the repeated staged composition permits global mixing.

2. Parameter reuse across levels: BOFT achieves mixing by reusing a small number of parameters at multiple stages. With $m$ stages each containing $O(d)$ nonzero entries, BOFT realizes a dense effective transform while using $O(dm)$ parameters rather than $O(d^2)$. The block-diagonal OFT with the same per-stage block size but only a single stage ($m=1$) cannot achieve the same mixing: it remains restricted to independent subspaces.

The paper quantifies the parameter count for BOFT$(m,b)$ as
\[
\text{parameters} \approx \tfrac{1}{2}(b-1)\,d\,m,
\]
so BOFT interpolates smoothly between the block-diagonal regime ($m=1$) and denser approximations ($m$ larger). When $m=1$, BOFT$(1,b)$ is exactly block-diagonal OFT with block size $b$. As $m$ increases (keeping $b$ fixed), BOFT introduces additional inter-block routing while keeping the number of parameters proportional to $d$ per stage. The result is strictly increased expressivity for the same $b$ and comparable parameter budgets.

# Kaleidoscope composition to span the full orthogonal group

While a single sequence of butterfly components (a single BOFT instance) represents a structured subset of the orthogonal group, it is possible to compose multiple such sequences to achieve universal representation of the full orthogonal group. The paper states this in the form of a constructive claim often referred to in related work as a “kaleidoscope” composition.

Formally, consider products of butterfly matrices and their transposes arranged appropriately. The paper gives a concrete construction: for suitable choices of multiple butterfly matrices $\bm{B}_{i,j}(d)$, the product
\[
\bm{B}_{d-1,1}(d)\,\bm{B}^\top_{d-1,2}(d)\,\cdots\,\bm{B}_{1,1}(d)\,\bm{B}^\top_{1,2}(d)
\]
can approximate any orthogonal matrix of size $d$. A convenient generalization used in the paper is the family
\[
\bm{R}^G(m_1,b_1,m_2,b_2,\ell)
= \bm{R}_{\ell,1}(m_1,b_1)\,\bm{R}_{\ell,2}^\top(m_2,b_2)\,\cdots\,\bm{R}_{1,1}(m_1,b_1)\,\bm{R}_{1,2}^\top(m_2,b_2),
\]
where each $\bm{R}_{i,j}$ is itself a BOFT-style product of butterfly components. In the special setting $m_1=m_2=\log d$, $b_1=b_2=2$, and $\ell = d-1$, this composition can represent the entire orthogonal group. In other words, by alternating carefully chosen butterfly-structured factors and their transposes and stacking enough of them, universality is recovered.

Two implications follow. First, BOFT is not a fundamentally restrictive model family: with enough layers and alternating structure it can approximate any orthogonal. Second, universality comes at a cost: stacking many factors increases parameter count and reduces the structural regularization that helped BOFT generalize in the first place. This observation sets up the practical design choice: we choose the number of stages and block sizes to balance expressive power against inductive bias and parameter budget.

# Trade-off between expressivity and regularity in finetuning

A recurring theme in model adaptation is balancing expressivity (the ability to reach solutions that fit the downstream task) and regularity (constraints that prevent overfitting and preserve useful pretrained structure). Full finetuning of every weight is maximally expressive but often hurts generalization and can destabilize training, especially when the downstream dataset is small relative to model capacity. Orthogonal finetuning (OFT) and its BOFT variant introduce two separate forms of regularity: the multiplicative orthogonality constraint and structural sparsity through factorization.

Orthogonality alone enforces a strong geometric prior: when the finetuned weight matrix is $\bm{R}\bm{W}^0$ with $\bm{R}$ orthogonal, the relative angles among neurons (columns of $\bm{W}^0$) and the singular value spectrum are preserved. This helps maintain pretraining knowledge and prevents dramatic changes that could harm transfer. Structural sparsity—either the block partition in OFT or the staged butterfly structure in BOFT—further restricts the hypothesis class. BOFT, by varying $(m,b)$, provides a smooth family of hypothesis classes between the identity (high regularity) and full orthogonal freedom (high expressivity):

- Small $m$ and large $b$ (e.g., BOFT$(1,b)$) behaves like block-diagonal OFT: limited mixing, high regularity.

- Large $m$ and small $b$ (e.g., BOFT$(\log d,2)$) permits dense mixing but retains a structured inductive bias from the factorization.

Identity initialization (set every component to identity via Cayley parameterization initialized at zero) biases optimization to start near the pretrained model, further enforcing regularity during early training. Thus BOFT gives a practical knob: choose $(m,b)$ to trade off how much you allow the pretrained geometry to be reoriented versus how much new task-specific structure you allow.

# Spectral norm preservation and training stability benefits

One of the clearest mathematical benefits of left-multiplying a pretrained weight matrix by an orthogonal matrix is exact preservation of singular values (and hence the spectral norm). Let the pretrained linear layer be $\bm{W}^0\in\mathbb{R}^{d\times n}$. Its singular value decomposition (SVD) is
\[
\bm{W}^0 = \bm{U}\,\bm{\Sigma}\,\bm{V}^\top,
\]
where $\bm{U}\in\mathbb{R}^{d\times d}$ and $\bm{V}\in\mathbb{R}^{n\times n}$ are orthogonal and $\bm{\Sigma}$ is diagonal with nonnegative singular values. For any orthogonal $\bm{R}\in\mathbb{R}^{d\times d}$ we have
\[
\bm{R}\bm{W}^0 = (\bm{R}\bm{U})\,\bm{\Sigma}\,\bm{V}^\top.
\]
Because $\bm{R}\bm{U}$ is orthogonal, the singular values of $\bm{R}\bm{W}^0$ are the same as those of $\bm{W}^0$; in particular, the spectral norm $\|\bm{W}^0\|_2$ is preserved.

Preserving the spectral norm has several practical consequences for optimization and generalization. A fixed spectral norm keeps the operator Lipschitz constant of the layer unchanged, which mitigates sudden increases in the magnitude of activations and gradients that can destabilize training. This is one reason why orthogonal finetuning has empirically been observed to yield more stable training than unconstrained additive updates (as noted in the paper and prior work). BOFT inherits this benefit because all of its components are orthogonal and therefore the composed matrix is orthogonal as well. The orthogonality constraint is thus a principled regularizer that acts directly on the layer’s linear operator norm.

# BOFT as learning a bilinear similarity with an orthogonality constraint

A useful way to think about BOFT (and OFT generally) is as learning a bilinear similarity transform that reweights how inputs are compared to frozen neuron templates. Start from the forward pass of a frozen linear layer $\bm{W}^0$ and the BOFT-modified layer:
\[
\text{original: } \bm{z} = (\bm{W}^0)^\top \bm{x}, \qquad
\text{BOFT: } \bm{z} = (\bm{R}\bm{W}^0)^\top \bm{x},
\]
where $\bm{x}\in\mathbb{R}^d$ is the input and $\bm{z}\in\mathbb{R}^n$ the output. Denote the $i$-th column of $\bm{W}^0$ by $\bm{w}_i^0$ (the $i$-th neuron). Then the $i$-th scalar output is
\[
z_i = (\bm{w}_i^0)^\top \bm{R}^\top \bm{x} = (\bm{R}\bm{w}_i^0)^\top \bm{x}.
\]
Viewed this way, BOFT is learning the bilinear similarity function $(\bm{w}_i^0, \bm{x}) \mapsto (\bm{w}_i^0)^\top \bm{R}^\top \bm{x}$ where the similarity is mediated by the orthogonal matrix $\bm{R}$. The learning problem reduces to fitting a single orthogonal bilinear form shared across all neurons in the layer.

This bilinear viewpoint connects BOFT to classical metric learning and bilinear form theory: the learned orthogonal $\bm{R}$ can be interpreted as a coordinate rotation that changes which directions of inputs are emphasized when compared against the frozen neuron templates. The orthogonality constraint imposes that $\bm{R}$ is a pure rotation/reflection rather than an arbitrary scaling, which preserves lengths and relative angles in the input space and again contributes to stability and preservation of pretrained structure.

# Structured inductive bias from butterfly topology and classic transforms

The butterfly factorization is not an arbitrary sparse pattern: it is the same combinatorial structure that underlies many fast linear transforms, such as the radix-2 Cooley–Tukey fast Fourier transform, the Hadamard transform, and related discrete cosine/sine transforms. These classical transforms are useful because they mix local and global information in structured ways that frequently match meaningful signal families (for example, frequency decompositions).

BOFT’s use of butterfly components therefore injects an inductive bias that is aligned with a family of useful linear transforms. Concretely, because the butterfly pattern can exactly represent many of these classic fast transforms (up to permutations and scaling), BOFT can naturally express rotations that implement frequency-style reweightings or other structured mixes. By contrast, the block-diagonal sparsity of OFT cannot recover such transforms—it forbids cross-block mixing entirely.

Beyond the explicit ability to recover known fast transforms, the sparse compositional structure of BOFT induces implicit regularization similar to well-studied effects of structured parameterizations in learning. When the hypothesis class is restricted to structured factorizations, optimization trajectories and solutions can avoid pathological overfitting modes available to unconstrained parameterizations. The empirical results in the paper suggest that the butterfly-induced bias is effective: BOFT attains strong generalization while using far fewer parameters than fully unconstrained orthogonal finetuning.

# Weight interpolation along component-wise paths

One practical and conceptually interesting consequence of BOFT’s multiplicative factorization is that it naturally admits smooth component-wise interpolation paths from the identity transform to the learned transform. BOFT represents the final orthogonal matrix as a product of orthogonal butterfly components,
\[
\bm{R} = \prod_{i=1}^m \tilde{\bm{B}}_{(d,i)}^b,
\]
and the paper initializes every component at the identity (Cayley parameterization with skew-symmetric factors initialized at zero). Because each component is an orthogonal factor that is continuously parameterized (via Cayley or small rotations), one can imagine gradually turning on components or gradually increasing the magnitude of their parameters to trace a continuous path $\bm{R}(t)$ from $\bm{I}$ to the final $\bm{R}$.

While the paper only sketches this idea and refers to an illustrative figure, the conceptual benefits are clear. Interpolating component-wise spreads the change across stages rather than imposing a single abrupt global modification. From an optimization perspective, this gives a natural geometric path that stays within the orthogonal manifold at all times and can be useful to analyze how information is progressively routed between coordinates. From a regularization perspective, such interpolation is another manifestation of BOFT’s smoother trade-off between identity-like behavior and full expressivity: early in interpolation the model remains close to the pretrained weights, and gradually acquires task-specific reorientations as components are activated.

This multiplicative interpolation capability is a direct consequence of the factorized, orthogonality-preserving parameterization: both the factorization and the Cayley-style parameterization (which preserves orthogonality) make component-wise, structure-respecting interpolation simple to define and to reason about.

# Summary

BOFT combines orthogonality (which preserves spectral properties and stabilizes training) with a butterfly factorization (which achieves dense connectivity across coordinates via a small number of sparse stages). Empirically and theoretically, BOFT attains a better expressivity-to-parameter ratio than block-diagonal OFT at the same block size because its staged butterfly topology enables global mixing without quadratic parameter growth. Kaleidoscope-style compositions show that BOFT can be extended to approximate the full orthogonal group, but with the familiar trade-off that universality reduces structural regularization. Viewing BOFT as learning a bilinear similarity with an orthogonality constraint and recognizing the inductive bias inherited from classical fast transforms clarifies why BOFT generalizes well in practice. Finally, the factorized multiplicative form enables natural component-wise interpolations between identity and the learned rotation, offering an intuitive picture of how BOFT gradually adapts pretrained geometry to downstream tasks.

Integrating BOFT into Modern Architectures

# Transformer layers: projecting inputs to attention and MLP blocks

Transformer blocks are built from a small collection of linear maps: the projections that produce queries, keys, values and the attention output, plus the two linear layers inside the feed‑forward (MLP) block. In the paper's notation a pretrained linear layer is a matrix $\bm{W}^0\in\mathbb{R}^{d\times n}$ that maps an input $\bm{x}\in\mathbb{R}^d$ to outputs via $\bm{z}=(\bm{W}^0)^\top\bm{x}$. BOFT operates at this level: for any such linear layer you replace the forward pass with
$\bm{z}=\big(\bm{R}\bm{W}^0\big)^\top\bm{x}$,
where the left multiplication by $\bm{R}\in\mathbb{R}^{d\times d}$ is the BOFT learnable orthogonal transform. In BOFT the matrix $\bm{R}$ is not an unconstrained dense orthogonal matrix but a product of orthogonal butterfly components,
$\bm{R}=\prod_{i=1}^m \tilde{\bm{B}}^b_{(d,i)}$,
so the same conceptual integration step applies to every linear projection inside a transformer block.

There are several practical and conceptual consequences you should keep front of mind when inserting BOFT into transformer layers. First, by left‑multiplying the pretrained weights you preserve the pretrained singular value spectrum: because $\bm{R}$ is orthogonal, the singular values of $\bm{R}\bm{W}^0$ equal those of $\bm{W}^0$. This spectral preservation is argued in the paper to help training stability and generalization. Second, BOFT is a reparameterization of the left action on the neuron coordinates: it preserves pairwise angles among neurons (the geometric motivation behind OFT) while allowing controlled adaptation via the structured orthogonal $\bm{R}$. Third, implementationally each BOFT factor is constructed from small orthogonal blocks (see below), so integrating BOFT usually requires replacing per‑layer weight lookups with the composed weight $(\bm{R}\bm{W}^0)$ at forward time (or precomputing the product occasionally during training if you want to amortize factor multiplications).

# Where to place BOFT in Q, K, V, and output projections

The queries, keys, values and attention output in standard attention are realized by linear maps (matrices) from the model dimension into head subspaces and back. Because BOFT is defined for a generic pretrained linear layer $\bm{W}^0\in\mathbb{R}^{d\times n}$, the natural and direct way to use BOFT is to replace each attention projection's weight by its BOFT‑transformed counterpart: for example, for a query projection matrix $\bm{W}_Q^0$ use $\bm{R}_Q\bm{W}_Q^0$, and similarly for $\bm{W}_K^0$, $\bm{W}_V^0$ and the output projection $\bm{W}_O^0$. The matrix $\bm{R}$ has the same number of rows as the pretrained weight it multiplies on the left (so $\bm{R}\in\mathbb{R}^{d\times d}$ when the projection maps $\mathbb{R}^d\to\mathbb{R}^n$).

Placing BOFT on every attention projection is the most straightforward strategy and aligns with the paper's general application of orthogonal finetuning to linear projections. It is also a design choice which affects parameter and compute budget: each BOFT instance adds its own factorization parameters, so you can choose to apply BOFT to all attention projections or prioritize a subset (for example, only the query and output projections). The BOFT machinery (block size $b$ and number of factors $m$) gives you knobs to trade off parameter cost, expressivity and runtime per projection; the paper demonstrates this trade‑off analytically and empirically.

# Applying BOFT to ViT patch embeddings and MLP expansions

Vision Transformers have two kinds of places where BOFT fits naturally: the patch embedding layer that maps raw (flattened) patches into the model dimension, and the MLP (feed‑forward) expansions inside each transformer block. Both are realized as linear maps and therefore are direct targets for BOFT: for the patch embedding weight $\bm{W}^{\text{patch}}\in\mathbb{R}^{d_{\text{patch}}\times d}$ you would left‑multiply by an orthogonal $\bm{R}\in\mathbb{R}^{d_{\text{patch}}\times d_{\text{patch}}}$ (or by an $\bm{R}$ sized to the row dimension of that layer), producing $\bm{R}\bm{W}^{\text{patch}}$ as the finetuned embedding transform. For the MLP expansion (the first dense layer that typically maps $d\to d_{\text{exp}}$) apply BOFT to the input side of that layer: if the layer is $\bm{W}_1^0\in\mathbb{R}^{d\times d_{\text{exp}}}$, BOFT uses $\bm{R}\bm{W}_1^0$ with $\bm{R}\in\mathbb{R}^{d\times d}$.

Two practical points follow directly from the BOFT parameterization in the paper. First, the block parameter $b$ in BOFT is explicit and tunable, so you can align BOFT block structure to natural subdivisions in a ViT layer (for example, to head subspaces if you prefer per‑head structure) or use small $b$ to encourage cross‑patch, global reweighting through deep factorization. Second, identity initialization is used throughout BOFT (each skew‑symmetric Cayley parameter is initialized to zero so each block starts as an identity), which means the pretrained patch embedding / MLP operates unchanged at initialization and BOFT only gradually introduces adaptation.

# LLMs: attention and feed-forward layers, per-layer versus shared BOFT

Large language models are built from the same primitive linear maps as vision transformers, but at different scales and often with many more transformer layers. The BOFT recipe is identical in the LLM context: for every attention projection and for the feed‑forward dense layers, replace the forward pass $\bm{z}=(\bm{W}^0)^\top\bm{x}$ by $\bm{z}=\big(\bm{R}\bm{W}^0\big)^\top\bm{x}$ where $\bm{R}$ is the BOFT orthogonal transform sized to the input dimension of that layer.

A practical architectural decision the paper allows (and that practitioners will face) is whether to allocate separate BOFT parameterizations per transformer layer or to reuse / share BOFT parameterizations across multiple layers. The paper contrasts BOFT's strategy of transforming pretrained weights with other butterfly‑parameterized methods and notes the design space of sharing versus per‑layer instances. Sharing one BOFT across several layers reduces the total tuning parameters (further improving parameter efficiency) but also reduces per‑layer expressivity; allocating a distinct BOFT per layer increases expressivity (and the ability to customize adaptation per layer) at the cost of more parameters. The expressivity results in the paper (BOFT is more expressive than block‑diagonal OFT for the same block size, and compositions of butterfly matrices can approximate larger subsets of the orthogonal group) give you the conceptual tools to think about this trade‑off: if you need more expressive per‑layer transforms, prefer per‑layer BOFT; if you have a tight global parameter budget, consider sharing or using smaller block sizes.

# Text-to-image U-Nets: spatial blocks and cross-attention

Text‑conditioned diffusion U‑Nets contain attention modules (including cross‑attention between image and text modalities) and feed‑forward blocks very similar in structure to transformer layers; the paper demonstrates that orthogonal finetuning paradigms (OFT and BOFT) are effective in this domain. Concretely, BOFT is applied to the linear projections inside cross‑attention and to the dense layers within the U‑Net's blocks in the same manner as in transformers: replace a pretrained linear map by its BOFT‑left‑multiplied form.

When dealing with U‑Net architectures, be mindful of the dimensionality that BOFT targets: BOFT multiplies on the left across the row dimension of the pretrained linear matrix. Many U‑Net modules include 1×1 convolutions that are equivalent to channelwise linear maps; these are natural points to insert BOFT (the BOFT transform acts across channels). The paper highlights that orthogonal finetuning stabilizes training in generative diffusion models and BOFT generalizes this approach while using far fewer tunable parameters in practice. As with other architectures, identity initialization and Cayley parameterization are used so the pretrained behavior is preserved at initialization.

# Choosing $m$ and $b$ per layer under a parameter budget

BOFT exposes two principal structural hyperparameters per BOFT instance: the number of butterfly components $m$ and the block size $b$. The paper gives a compact formula for the effective number of trainable parameters introduced by BOFT on a linear layer with input dimension $d$:
the number of effective trainable parameters is
$\displaystyle \frac{1}{2}(b-1)\,d\,m$.
Use this formula to reason quantitatively about budgets. Two useful reference points from the paper are: BOFT($1,b$) reduces to the block‑diagonal OFT with block size $b$ (so $m=1$ recovers the original block diagonal parameterization), and BOFT($1,d$) recovers the full dense OFT (i.e., $b=d$ and $m=1$). A classic butterfly parameterization that yields a dense orthogonal matrix uses $b=2$ and $m=\log_2 d$, giving an $\mathcal{O}(d\log d)$ parameter count.

If your objective is to reach a dense orthogonal $\bm{R}$ for a layer with input size $d$ while constraining $b$, the paper notes that choosing
$\displaystyle m \approx \log_2\!\left(\frac{2d}{b}\right)$
produces a block‑butterfly matrix that is dense. Combine this with the parameter formula to solve for $m$ or $b$ given a per‑layer budget. For example, with $b=2$ and $d=512$ you get $m\approx\log_2 512=9$ and the parameter cost per layer is $\frac{1}{2}(2-1)\cdot 512 \cdot 9 = 2304$ effective parameters. This arithmetic shows how compact BOFT can be even when producing dense orthogonal transforms.

A practical recipe for distributing a global parameter budget across an architecture is: compute the per‑layer importance (for instance by layer width $d$ or by empirical sensitivity), allocate a larger share of the budget to layers that are wider or more sensitive (attention and the expansion of MLPs are common candidates), and choose $(m,b)$ per layer so that $\frac{1}{2}(b-1) d m$ meets the assigned budget for that layer. Smaller $b$ with larger $m$ tends to give better parameter efficiency (and more global mixing, thanks to deeper factorization), at the cost of increased per‑step multiplication overhead because more factors must be multiplied during forward/backward passes.

# Typical hyperparameters: learning rates, dropout rates, schedulers

BOFT inherits the finetuning practice emphasized in the paper that pretrained models should not be driven far from their initial parameters: identity initialization (by initializing the skew‑symmetric Cayley parameters to zero) is the recommended starting point so that the finetuned model begins identical to the pretrained one. The paper also notes that, in general, finetuning methods often adopt small learning rates to keep the finetuned model close to the pretrained model; this guideline applies equally to BOFT.

For regularization BOFT introduces a specific multiplicative Dropout adapted to its multiplicative structure. The multiplicative Dropout randomly selects a fraction $p_1$ of the butterfly components and, within each chosen component, a fraction $p_2$ of the diagonal blocks, replacing those chosen blocks with identity matrices during a training step. The paper does not force particular numeric choices for $(p_1,p_2)$; they are additional knobs to be tuned per task and dataset size, with larger values increasing regularization and parameter robustness at the expense of available adaptation capacity.

Finally, standard scheduler choices used for finetuning (small constant learning rates, cosine decays, or step decays) are compatible with BOFT; the central point from the paper is to keep the adaptation smooth and controlled. Bear in mind the runtime trade‑off: more BOFT factors ($m$ larger) increase per‑step computation. The paper reports BOFT has slightly higher training runtime than a single‑factor OFT, but the learned orthogonal $\bm{R}$ can be multiplied into the pretrained weights after finetuning so there is no inference latency penalty.

# Monitoring orthogonality and stability during training

BOFT ensures orthogonality by construction through its Cayley parameterization. Each orthogonal butterfly component is parameterized via skew‑symmetric parameters $\bm{Q}$ so that, for a component, the Cayley map produces
$\displaystyle \bm{R}=(\bm{I}+\bm{Q})(\bm{I}-\bm{Q})^{-1}$
with $\bm{Q}=-\bm{Q}^\top$, guaranteeing orthogonality of each component and hence of their product. Because the orthogonal transform preserves the singular value spectrum of the pretrained weight it multiplies, BOFT preserves the spectral norm of the pretrained layer and therefore inherits the spectral stability benefits discussed in the paper.

In practice you should keep an eye on two stability axes emphasized by the paper. First, training dynamics: because BOFT begins from identity and changes weights multiplicatively through orthogonal transforms, training should be stable if learning rates and regularization are reasonable; if you see instability, reduce the BOFT learning rate or increase multiplicative Dropout. Second, runtime/compute stability: multiplying many sparse factors at each step introduces a modest computational overhead, so monitor per‑step time and, if necessary, trade parameters for speed by decreasing $m$ or increasing $b$ (fewer factors, larger blocks). After training, collapse the BOFT product into the pretrained weights to remove any runtime cost at inference.

# Concluding practical checklist

To summarize a compact practical workflow distilled from the paper: identify the linear projections you wish to adapt (attention Q/K/V/O, MLPs, patch embeddings, cross‑attention), for each such layer instantiate a BOFT orthogonal transform $\bm{R}=\prod_{i=1}^m \tilde{\bm{B}}^b_{(d,i)}$ sized to that layer's row dimension, parameterize each small $2b\times 2b$ block via a skew‑symmetric Cayley parameter (initialize to zero so $\bm{R}=\bm{I}$ at start), decide $(m,b)$ per layer by the parameter budget using $\frac{1}{2}(b-1)dm$ and (if you want dense $\bm{R}$) $m\approx\log_2\!\left(\frac{2d}{b}\right)$, regularize with multiplicative Dropout selecting fractions $p_1$ and $p_2$ of components/blocks to replace by identity during training, use a conservatively small finetuning learning rate, and finally fold the learned orthogonal product into the pretrained weights for inference.

These steps adhere to the BOFT framework and the implementation choices emphasized in the paper: Cayley parameterization for exact orthogonality, identity initialization for safe finetuning, butterfly factorization for parameter efficiency (down to $\mathcal{O}(d\log d)$ when $b=2$), and multiplicative Dropout adapted to the multiplicative nature of the reparameterization.

Comparative Landscape: BOFT vs. LoRA, OFT, Adapters, and Prompts

This chapter situates BOFT (Orthogonal Butterfly Finetuning) within the broader family of parameter-efficient finetuning (PEFT) methods described in the paper "Parameter-Efficient Orthogonal Finetuning via Factorization." The goal is to give you a clear, practical sense of how BOFT differs from and relates to the common PEFT approaches you will encounter in the literature: low-rank reparameterizations (e.g., LoRA), orthogonal multiplicative finetuning (OFT), adapter architectures, and prompt tuning. Wherever possible I stick to the explanations and results presented in the paper: the underlying principles, the design trade-offs, the theoretical observations, and the empirical motivations reported there. The chapter is organized around concrete comparison axes so you can form a decision rule for which method to try under different constraints.

# Low-rank versus sparse structured parameterizations

A central design choice for PEFT is how to structure the extra/trainable degrees of freedom so that we dramatically reduce the number of tunable parameters while retaining enough expressivity for downstream adaptation. The paper highlights two large families of structured parameterizations: low-rank matrices and sparse (structured) matrices.

Low-rank parameterizations (the family LoRA belongs to) replace an unconstrained dense update with a product of two low-rank matrices. Intuitively, a low-rank update restricts the change to lie in a low-dimensional subspace of weight space: the finetuning can only move the pretrained weight along a few principal directions. This is a powerful inductive bias when downstream adaptation requires modest, global adjustments to model behavior. The paper notes that LoRA typically fixes the rank of these added matrices (and several follow-up works adapt this rank per layer), which keeps the parameter budget small and controlled.

Sparse structured parameterizations (the family that includes block-diagonal OFT and BOFT) reduce trainable parameters by imposing sparsity patterns or structured factorization on the transformation we learn. The original OFT achieves parameter efficiency by making the learned orthogonal matrix block-diagonal: that reduces the number of free entries from $ \mathcal{O}(d^2) $ to $ \mathcal{O}(bd) $ if the block size is $b$. The paper points out the downside: block-diagonal sparsity severely restricts cross-block mixing and cannot represent many classic dense linear transforms. BOFT takes a different sparse-structured route. Instead of a single sparse matrix, BOFT represents a dense orthogonal matrix as a product of a small number $m$ of sparse orthogonal factors arranged in a butterfly factorization. This construction lets BOFT achieve a dense overall transform while using far fewer free parameters. In particular, BOFT($m,b$) uses about $\frac{1}{2}(b-1)dm$ effective trainable parameters for a layer of width $d$, and when $m=\log d$ and $b=2$ the parameter count is $ \mathcal{O}(d\log d) $, a major reduction from $ \mathcal{O}(d^2) $ for a full orthogonal matrix.

Beyond raw parameter counts, these families encode different inductive biases. Low-rank updates bias the change toward a low-dimensional subspace; sparse/butterfly factorizations bias the change toward structured, staged mixing patterns (the butterfly connectivity is the same pattern that enables FFT-like global mixing in $ \mathcal{O}(d\log d) $ time). The paper emphasizes that both families are important and complementary: "both low-rank matrices and sparse matrices are major families of structured matrices that achieve parameter efficiency." Practically, this means you should consider what sort of change the downstream task needs: a global, low-dimensional adjustment (low-rank) or structured re-mixing that must reach every coordinate from every other coordinate but under a constrained communication pattern (butterfly/BOFT).

# Additive (LoRA) versus multiplicative (OFT/BOFT) updates

LoRA implements an additive reparameterization: the finetuned weight is the pretrained weight plus an additive low-rank term (in the paper wording, "LoRA updates the pretrained weight matrix by adding a product of two low-rank matrices"). Additive updates are simple to reason about, easy to initialize to zero (so initial behavior equals pretrained model), and fit naturally with Dropout-style regularization.

By contrast, OFT and BOFT are multiplicative: they reparameterize the finetuned weight by left-multiplying the frozen pretrained weight $\bm{W}^0$ by an orthogonal matrix $\bm{R}$. Concretely the forward pass changes from
$\bm{z}=(\bm{W}^0)^\top\bm{x}$ to $\bm{z}=(\bm{R}\bm{W}^0)^\top\bm{x}$.
This multiplicative form is fundamental to the motivations in the paper: applying a layer-shared orthogonal map to neurons preserves pairwise angles among neuron vectors (and therefore relational structure learned during pretraining). Orthogonality is enforced during training via a Cayley parameterization: $\bm{R}=(\bm{I}+\bm{Q})(\bm{I}-\bm{Q})^{-1}$ with $\bm{Q}=-\bm{Q}^\top$, which maintains $\bm{R}^\top \bm{R}=\bm{I}$ throughout optimization.

BOFT keeps the multiplicative flavor of OFT but parameterizes $\bm{R}$ as a product of orthogonal butterfly components,
$\bm{R}(m,b)=\prod_{i=1}^m \tilde{\bm{B}}^b_{(d,i)}$,
where each $\tilde{\bm{B}}^b_{(d,i)}$ is an orthogonal block-butterfly component. This multiplicative factorization is why BOFT can represent a dense orthogonal transform with relatively few parameters.

There are consequential differences in initialization and regularization between additive and multiplicative schemes. Additive methods like LoRA customarily initialize the new low-rank weights to zero so the finetuning starts at the pretrained weights. OFT and BOFT achieve the same property by initializing $\bm{R}$ to the identity (in Cayley parameterization that corresponds to initializing $\bm{Q}=\bm{0}$). Regularization also differs: a conventional Dropout layer applied to an additive low-rank term makes sense, but applying naive dropout to a multiplicative orthogonal transform would break the structure. The paper therefore introduces a "multiplicative Dropout" for BOFT that randomly replaces selected butterfly components (and selected blocks within components) by identity blocks during training—explicitly, choose $p_1\%$ of butterfly components and $p_2\%$ of diagonal blocks and replace those blocks by identity matrices to regularize the multiplicative update.

# Training stability and spectral behavior across methods

One clear mathematical advantage of orthogonal multiplicative updates (OFT and BOFT) emphasized in the paper is spectral preservation. If the pretrained weight has singular value decomposition $\bm{W}^0=\bm{U}\bm{\Sigma}\bm{V}^\top$, then left-multiplying by an orthogonal matrix $\bm{R}$ yields
$\bm{R}\bm{W}^0=(\bm{R}\bm{U})\bm{\Sigma}\bm{V}^\top$,
so the singular values (the diagonal entries of $\bm{\Sigma}$) are unchanged. In particular the spectral norm (largest singular value) is preserved. The paper points out that this property benefits training stability and generalization: preserving the spectral norm avoids sudden scaling changes in layers and is tied to more stable optimization and better generalization behavior (as discussed via cited prior work).

LoRA's additive low-rank updates do not necessarily preserve singular values of $\bm{W}^0$ and therefore do not guarantee the same spectral stability. The original OFT paper (cited in this work) found that orthogonal finetuning achieves stronger generalization and more stable training in the context of text-to-image diffusion models, and BOFT inherits the same orthogonality guarantees (since each butterfly component is orthogonal). Thus BOFT gains the spectral-preservation advantages of OFT while using substantially fewer parameters.

There is an important nuance: preserving spectral properties is not the whole story. The paper also motivates OFT via preservation of pairwise angles between neurons—an argument grounded in hyperspherical energy and relational structure of features. The multiplicative orthogonal update preserves these angles by construction, and BOFT retains that property. In practice, that preservation appears connected to more stable finetuning trajectories and better out-of-distribution generalization in the problems studied in the paper.

# Parameter-efficiency versus compute trade-offs

BOFT's central engineering idea is a trade: reduce trainable parameter count by representing a dense orthogonal matrix as a product of sparse orthogonal factors, thereby trading computation for space. The information-transmission view in the paper makes this precise: one can view matrix factorization as routing information across a grid of $d\times(m+1)$ nodes. The butterfly factorization is a particularly efficient topology in that view: with $m=\log d$ stages and $\mathcal{O}(d)$ nonzeros per stage, a dense mapping from $d$ inputs to $d$ outputs can be achieved with only $\mathcal{O}(d\log d)$ effective degrees of freedom.

Concretely, BOFT($m,b$) has about $\frac{1}{2}(b-1)dm$ effective trainable parameters. This interpolates between configurations: BOFT($1,b$) is exactly block-diagonal OFT with block size $b$; BOFT($1,d$) is the unconstrained full OFT; and BOFT($\log\frac{2d}{b},b$) yields a dense orthogonal matrix constructed from block-butterfly components. In the canonical butterfly setting $m=\log d$ and $b=2$, the parameter count is $\mathcal{O}(d\log d)$, much smaller than the full-matrix $\mathcal{O}(d^2)$ used by dense OFT.

The computational cost profile follows from this design choice. Because $\bm{R}$ is represented as a product of multiple sparse factors, that product (or its action on vectors) must be applied repeatedly during training; the paper notes that BOFT therefore incurs a slight training runtime overhead compared to OFT. This is the pay-off for reduced parameter storage. Importantly, the paper stresses that this extra training cost is an engineering trade-off: after finetuning, the learned orthogonal matrix can be multiplied into the pretrained weights so inference runs with the fused dense weight and incurs no additional latency.

A practical consequence is clear: if your primary bottleneck is parameter storage (for example, when distributing learnable parameters across many clients or when you want to store many task adapters cheaply), BOFT can give you a dense orthogonal transform for far fewer stored parameters. If your primary bottleneck is per-step compute time during training, you should be aware that BOFT can be slightly more expensive per iteration than a single-block OFT; the paper leaves open further engineering optimizations to reduce this overhead.

# Inference-time latency and fusion considerations

One of the pleasant practical features emphasized in the paper is that BOFT, like model finetuning methods in general, introduces no extra inference-time latency once the finetuning stage is complete. Because BOFT learns an orthogonal matrix $\bm{R}$ that multiplies into the weight matrix as $\bm{R}\bm{W}^0$, the learned orthogonal matrix can be fused into the pretrained weight by forming the product, and the resulting finetuned weight is a single dense matrix usable at inference time with the same runtime characteristics as the original model. The paper states explicitly that "after the finetuning stage, the BOFT-learned orthogonal matrices can be directly multiplied into the pretrained model and there is no additional inference latency."

This contrasts with some PEFT alternatives that add new architectural components at inference time (adapter modules or prefix tokens) — those approaches can potentially change inference computation unless those components are specially merged. The paper does not elaborate on the runtime behavior of adapters or prompt-tuning in detail, but it makes clear that model finetuning (the family including OFT and BOFT) has the desirable property of leaving inference time unchanged once the finetuned weights are materialized.

# Combining methods: BOFT with LoRA or adapters

The paper frames BOFT relative to other PEFT families and contrasts sparse (butterfly) and low-rank approaches, but it does not empirically study hybrid schemes that simultaneously apply BOFT and LoRA or BOFT and adapters. Where the paper does provide constructive generalizations is within the orthogonal-factorization family itself: it offers a more expressive composition called a kaleidoscope-like hierarchy. In particular, the paper introduces a generalized orthogonal composition
\[
\bm{R}^G(m_1,b_1,m_2,b_2,l)
= \bm{R}_{l,1}(m_1,b_1)\bm{R}_{l,2}^\top(m_2,b_2)\cdots\bm{R}_{1,1}(m_1,b_1)\bm{R}_{1,2}^\top(m_2,b_2),
\]
and it observes that with appropriate choices (for example, $m_1=m_2=\log d$, $b_1=b_2=2$, and $l=d-1$) this construction can represent the entire orthogonal group. This kaleidoscope hierarchy shows that increased expressivity can be achieved by composing multiple structured orthogonal factors and their transposes, without leaving the orthogonal multiplicative-family.

Because the paper restricts itself to the orthogonal-factorization strategy, it does not make claims about mixing BOFT directly with LoRA or adapter modules. The statement that "both low-rank matrices and sparse matrices are major families" suggests conceptual complementarity, but concrete combination strategies and their empirical trade-offs are not explored in this work and are left as future directions. If you are considering hybrid designs in your own experiments, be aware that the paper does not provide guidance or results for such hybrids; it does, however, provide the mathematical building blocks (orthogonal factors, Cayley parameterization, multiplicative Dropout) that you would need to experiment safely if you choose to combine approaches.

# When to prefer BOFT in practice

Putting the above comparisons together, the paper suggests clear practical situations where BOFT is especially attractive.

First, when your constraint is parameter budget (how many trainable parameters you can store or communicate) but you still want a dense, expressive orthogonal update, BOFT is a natural choice. With the canonical butterfly configuration ($m\approx\log d$, $b=2$) BOFT attains $\mathcal{O}(d\log d)$ parameters and can produce dense orthogonal transforms that a block-diagonal OFT cannot represent. The paper’s experiments and simulations show that BOFT can be more parameter-efficient in approximating dense orthogonal matrices: for example, BOFT with smaller $b$ and larger $m$ tends to beat block-structured OFT with larger blocks for the same parameter budget (the paper gives concrete simulation comparisons such as BOFT($9,2$) being more expressive than BOFT($1,16$) with fewer parameters, and BOFT($6,4$) matching BOFT($2,16$) with fewer parameters).

Second, when you care about training stability and preserving pretraining structure, BOFT is preferable to additive low-rank updates because it enforces orthogonality and thus preserves the singular-value spectrum and pairwise neuron angles. The paper reports that orthogonal finetuning has provided better generalizability and more stable training in prior work (notably in text-to-image diffusion), and BOFT inherits those orthogonality-based advantages while being parameter-efficient.

Third, when you need a smooth interpolation between "no change" (identity) and full unconstrained orthogonal transforms, BOFT offers a continuum of choices through the $(m,b)$ configuration. BOFT($1,b$) is block-diagonal OFT, BOFT($1,d$) is full OFT, and larger $m$ with smaller $b$ moves you toward a dense but structured transform that balances expressivity and regularity. If you are unsure how much expressivity a task needs, the paper’s perspective suggests trying progressively larger $m$ (more stages) while keeping small $b$ to gain expressivity with modest parameter growth.

Finally, the paper flags a practical caveat: BOFT involves extra factor multiplications during training, so its runtime per training step is slightly larger than the single-block OFT. If your primary bottleneck is per-step runtime (and not parameter storage or communication), that runtime overhead may be significant in your setup; conversely, if inference latency and model size for storage are the dominant concerns, BOFT’s ability to fuse learned transforms back into the model for inference and its small trainable-parameter footprint make it attractive.

In summary, based on the analyses and experiments reported in the paper, prefer BOFT when you want the orthogonality-induced stability and relational-preservation of OFT but with much better parameter efficiency; accept a modest training-time cost to get a dense, expressive transform that can be fused into the model for inference with zero latency. If you prioritize extreme per-step speed and your adaptation fits a very low-dimensional correction, a low-rank additive scheme like LoRA remains a simple and effective alternative; BOFT and LoRA inhabit complementary points in the design space and the paper highlights the conceptual differences and trade-offs without claiming a universal dominance of one over the other.

Concluding remark: BOFT offers a principled middle ground. It preserves the stability and geometric priors of orthogonal finetuning while using a butterfly factorization to dramatically reduce the number of learned parameters. The information-transmission perspective in the paper underpins this construction and helps explain why the butterfly topology is a natural and efficient architectural choice for parameter-efficient orthogonal finetuning.

Empirical Results and Ablations

# Large vision transformers on recognition and transfer benchmarks

The paper evaluates BOFT on large vision transformers by applying the orthogonal butterfly reparameterization to the pretrained linear layers and finetuning under constrained parameter budgets. Although the paper does not list every dataset in the text excerpt, the experimental protocol follows the common recognition and transfer paradigm: a large pretrained vision transformer is adapted to a suite of downstream recognition tasks and transfer benchmarks, and BOFT is compared to other parameter-efficient finetuning (PEFT) methods (for example, LoRA and variants of Orthogonal Finetuning (OFT)) and to full finetuning baselines.

Across these vision experiments the qualitative finding is consistent: BOFT attains better parameter-efficiency and stronger generalization than the baselines under comparable parameter budgets. Put differently, for a given number of additional trainable parameters BOFT produces finetuned models that generalize better to held-out validation and transfer tasks than either block-diagonal OFT or additive low-rank updates such as LoRA. The paper attributes this improvement to two mechanisms. First, BOFT preserves pairwise angles and the spectral structure of pretrained layers (orthogonal left-multiplication leaves singular values unchanged), which stabilizes training and helps retain pretraining knowledge. Second, the butterfly factorization provides dense mixing across coordinates with far fewer parameters than a fully dense orthogonal matrix, yielding an inductive bias that matches many useful linear transforms and thereby improves transfer.

From a practical point of view, the vision results highlight the BOFT design trade-offs. If one needs very small parameter budgets, a block-diagonal OFT or a BOFT with large block size $b$ and small depth $m$ may be acceptable; when more dense mixing is required and compute permits, BOFT with smaller $b$ and larger $m$ (approaching the butterfly configuration) recovers dense orthogonal behaviors with substantially fewer parameters than full OFT. The paper’s ablations on parameterization (discussed below) show that these choices govern an expressivity–regularity trade-off that directly controls transfer performance.

# Large language models on downstream NLP tasks

The paper extends BOFT to large language models and measures downstream NLP performance in a similar finetuning setup. Language models are a natural testbed because LoRA-style low-rank adapters are widely used there; BOFT offers an alternative multiplicative orthogonal reparameterization that directly preserves spectral properties of pretrained projection layers.

Empirically, BOFT matches or improves over popular PEFT baselines on language tasks under equal or smaller parameter budgets. The same high-level explanations apply: left-multiplying pretrained weight matrices by orthogonal transforms preserves singular values, which reduces abrupt changes to the pretrained representations and tends to make gradient flow and optimization behavior more stable. The butterfly structure enables dense interactions between embedding or hidden-dimension coordinates without the $\mathcal{O}(d^2)$ parameter blowup of a full orthogonal matrix, so BOFT can capture richer coordinate permutations and mixes than a block-diagonal OFT at similar cost.

From a usage perspective in NLP, BOFT should be considered when preserving pretrained spectral structure matters (e.g., to avoid destabilizing large transformers) and when a parameter-efficient multiplicative update is desired. BOFT incurs only a modest training-time computation overhead (discussed below) while requiring no inference-time latency after the learned orthogonal transform is merged into the pretrained weights.

# Text-to-image diffusion model adaptations

OFT was originally proposed and shown to be effective for controllable text-to-image diffusion model finetuning. The paper reports that BOFT extends and improves this line of work: applying BOFT to diffusion models yields strong generalization and stable finetuning while substantially reducing the number of trainable parameters needed to achieve comparable or better control and quality than prior methods.

Diffusion models are especially sensitive to the spectral and geometric structure of internal layers; the orthogonal left-multiplication used in BOFT preserves singular values and the geometry among neurons, which helps maintain model behavior learned during pretraining. The butterfly parameterization enables dense coordinate mixing that is important for the kinds of global spatial and text–image couplings diffusion models leverage. In short, BOFT retains the stability and controllability advantages previously observed with OFT while dramatically improving parameter efficiency and expressivity compared to OFT’s block-diagonal reductions.

# Parameter budget versus performance: m and b sweeps

A central empirical and conceptual contribution of the paper is to make explicit how BOFT’s two architecture knobs, depth $m$ (number of factor components) and block size $b$, trade parameter count, expressivity, and compute. The effective number of scalar trainable parameters used by BOFT for a $d\times n$ linear layer is
\[
\frac{1}{2}(b-1)\,d\,m,
\]
because each of the $m$ block-butterfly components contains $\frac{1}{2}(b-1)$ degrees of freedom per block times $d$ blocks (up to constant factors from orthogonality constraints). Important special cases recover known regimes: the original full OFT corresponds to $b=d$ and therefore scales as $\mathcal{O}(d^2)$ parameters; block-diagonal OFT is $\text{BOFT}(1,b)$ and scales as $\mathcal{O}(bd)$; and the radix-$2$ butterfly parameterization corresponds to $m=\log d$ and $b=2$, giving BOFT a parameter scaling of $\mathcal{O}(d\log d)$.

The paper uses two kinds of ablations to demonstrate how these hyperparameters affect expressivity and approximation power. One is a synthetic approximation experiment in which a random dense orthogonal matrix of size $512\times 512$ is approximated under varying parameter budgets. Results (averaged over multiple seeds) show a clear trend: configurations with smaller block size $b$ and larger depth $m$ (i.e., more butterfly-like factorizations) achieve lower approximation error for the same number of effective parameters than shallow, large-block configurations. Concretely, BOFT$(9,2)$ (deep, small blocks) was more expressive than BOFT$(1,16)$ (shallow, large blocks) while using far fewer parameters; BOFT$(6,4)$ (intermediate) matched the approximation error of BOFT$(2,16)$ at a noticeably smaller parameter cost. These controlled ablations make the practical point visible: for a fixed parameter budget, choosing to increase factor depth $m$ while keeping $b$ small often yields a better approximation of dense orthogonals and therefore more expressive finetuning transforms.

A complementary view in the paper is conceptual: while increasing expressivity (moving toward full orthogonal coverage) is possible by stacking more butterfly factors (and by composing forward and transposed butterfly blocks as in the kaleidoscope hierarchy), more expressivity is not always better for downstream generalization. There is a trade-off between expressivity and regularity: an overly large hypothesis class can overfit small datasets, while a restricted structured class (butterfly-parameterized orthogonals) can provide a useful inductive bias. The $m,b$ sweeps let practitioners navigate this trade-off.

# Effect of multiplicative Dropout and identity initialization

Two implementation and regularization details play an important role in BOFT: identity initialization and multiplicative Dropout.

Identity initialization is enforced by initializing each orthogonal butterfly component to the identity (in practice via Cayley parameterization with the skew-symmetric parameter $\bm{Q}$ initialized to zero). This guarantees a zero-starting update relative to the pretrained model (analogous to LoRA’s zero initialization for additive adapters). The immediate benefit is practical: finetuning starts exactly at the pretrained weights and then gradually moves away, which reduces the risk of destabilizing the learned representations and yields more predictable early optimization behavior.

Multiplicative Dropout addresses the fact that standard dropout (which randomly zeros additive updates) does not directly apply to multiplicative orthogonal reparameterizations. BOFT’s multiplicative Dropout randomly selects a fraction $p_1$ of butterfly components and a fraction $p_2$ of the diagonal blocks inside each selected component, and replaces those selected blocks with identity matrices during a training step. This form of dropout acts as structural perturbation: it reduces reliance on any particular factor or block and thus regularizes the multiplicative update. Conceptually it mirrors the regularizing role played by dropout in LoRA and by additive noise in other adapter methods, adapted to the multiplicative, factorized structure of BOFT. The paper proposes and uses this mechanism to reduce overfitting in low-data regimes; identity initialization and multiplicative Dropout together give a practical recipe for stable, regularized BOFT finetuning.

The paper’s narrative does not present exact ablation tables in the excerpt, but the methodological design and the experiments’ overall stability and generalization results indicate these choices are important parts of the BOFT recipe.

# Runtime overhead versus gains in accuracy/generalization

BOFT intentionally trades compute for parameters: by representing a dense orthogonal matrix as a product of $m$ sparse orthogonal components, BOFT reduces memory/storage and the number of trainable parameters while introducing additional per-step matrix multiplications during training. The paper explicitly notes that this factorization incurs a modest training-time runtime overhead relative to OFT, because the multiplication of multiple sparse factors must be performed at each update. The overhead is described as slight in the paper; exact profiled timings are not included in the provided text.

Crucially, the extra cost is only during finetuning. Once finetuning is complete, the learned orthogonal matrix can be merged into the pretrained weight matrix so that inference incurs no additional latency or evaluation-time cost. This is an essential practical property: BOFT reduces model storage and parameter-transfer costs while leaving runtime performance unaffected in deployment.

Putting this together, BOFT is particularly attractive in scenarios where parameter storage, checkpoint size, and the number of trainable parameters are the binding constraints (for example, when shipping many finetuned variants or when memory for optimizer states is limited). The modest extra training-time compute is an acceptable trade-off in those settings, especially given the observed gains in generalization and stability.

# Cross-domain robustness and stability comparisons

One of the strongest empirical messages in the paper is BOFT’s cross-domain consistency: the method improves parameter-efficiency, generalization, and stability across vision, language, and diffusion-model finetuning tasks. Several structural reasons explain this robustness.

First, orthogonality as a constraint preserves the spectral properties of pretrained weights. Writing a pretrained layer singular-value decomposition as $\bm{W}^0=\bm{U}\bm{\Sigma}\bm{V}^\top$, left-multiplying by an orthogonal matrix $\bm{R}$ yields $\bm{R}\bm{W}^0 = (\bm{R}\bm{U})\bm{\Sigma}\bm{V}^\top$, so the singular values in $\bm{\Sigma}$ remain unchanged. Preserving the spectral norm and singular-value profile guards against amplifying or squashing signals in a layer, which prior work links to more stable optimization and improved generalization. BOFT retains this spectral-preserving property exactly because its constituent factors are orthogonal.

Second, the butterfly parameterization provides a structured, but sufficiently rich, class of orthogonal transforms that simultaneously (a) allows dense mixing among coordinates, and (b) constrains the hypothesis class relative to an unconstrained dense orthogonal. This structured inductive bias—closely related to classical fast transforms such as the discrete Fourier and Hadamard transforms—helps BOFT generalize across domains: it captures many useful global interactions while avoiding the high-capacity, less regular hypothesis class that leads to overfitting.

Third, compared to additive low-rank methods like LoRA, BOFT’s multiplicative orthogonal updates avoid changing singular values and so often avoid the spectral instabilities that can degrade convergence in some settings. Compared to block-diagonal OFT, BOFT recovers much more expressive dense behavior at comparable parameter budgets, which is important in tasks where coordinate mixing across blocks is necessary.

Empirically, the cross-domain comparisons reported in the paper reflect these theoretical advantages: BOFT yields stable training dynamics and competitive or superior downstream performance across a variety of vision, language, and diffusion tasks, validating that the method’s inductive biases generalize beyond any single application domain.

# Summary and practical recommendations

The empirical story of the paper can be summarized as follows. BOFT provides a principled way to obtain dense orthogonal finetuning transforms with far fewer parameters than full orthogonal matrices, by factorizing the transform into a product of sparse orthogonal butterfly components. Across vision, language, and diffusion-model experiments BOFT demonstrates superior parameter-efficiency and robust generalization compared to common PEFT baselines. The main knobs to control this behavior are the number of factors $m$ and the block size $b$, which trade compute, parameter count, and expressivity according to the rule of thumb
\[
\text{parameters}\approx \frac{1}{2}(b-1)\,d\,m.
\]
Empirical approximations and ablations indicate that smaller $b$ with larger $m$ (the butterfly regime) tends to be more parameter-efficient for approximating dense orthogonals, but practitioners should balance expressivity and regularity: extremely expressive configurations can overfit small datasets.

Two practical implementation points are recommended by the paper: initialize all factors to identity (Cayley parameters $\bm{Q}=0$) so finetuning starts exactly at the pretrained model, and use multiplicative Dropout (randomly replacing factors/blocks with identity during training) to regularize the multiplicative structure. Expect a modest training-time compute overhead from the factorized multiplications, but no inference-time cost after merging the learned transform into the base weights.

Taken together, these empirical and ablation results suggest that BOFT is a compelling general-purpose PEFT technique for large models when the goal is to maximize performance per parameter while preserving stability and cross-domain robustness.

# Constructing an $8\times 8$ butterfly orthogonal from $2\times 2$ blocks

This section shows concretely how the recursive butterfly factorization described in the paper builds a dense $d$-dimensional orthogonal matrix from small $2\times 2$ orthogonal building blocks. We set $d=8$ (so $d=2^3$) and use the decomposition
\[
\bm{B}(8)=\tilde{\bm{B}}(8,8)\,\tilde{\bm{B}}(8,4)\,\tilde{\bm{B}}(8,2),
\]
where each component $\tilde{\bm{B}}(8,k)$ is block-diagonal and each block is a butterfly factor $\bm{B}^F(k)$ as in the paper:
\[
\bm{B}^F(k)=\begin{bmatrix}
\operatorname{diag}(\bm{d}_1) & \operatorname{diag}(\bm{d}_2)\\[4pt]
\operatorname{diag}(\bm{d}_3) & \operatorname{diag}(\bm{d}_4)
\end{bmatrix},\qquad \bm{d}_i\in\mathbb{R}^{k/2}.
\]
For $k=8$ we have $k/2=4$, so $\bm{B}^F(8)$ has four independent scalar pairs that mix inputs from the first half $(1\ldots4)$ and the second half $(5\ldots8)$. Concretely, if $x\in\mathbb{R}^8$ denotes the input to $\bm{B}^F(8)$, the output $y=\bm{B}^F(8)\,x$ is
\[
\begin{aligned}
y_1 &= d_{1,1}x_1 + d_{2,1}x_5,&
y_2 &= d_{1,2}x_2 + d_{2,2}x_6,\\
y_3 &= d_{1,3}x_3 + d_{2,3}x_7,&
y_4 &= d_{1,4}x_4 + d_{2,4}x_8,\\
y_5 &= d_{3,1}x_1 + d_{4,1}x_5,&
y_6 &= d_{3,2}x_2 + d_{4,2}x_6,\\
y_7 &= d_{3,3}x_3 + d_{4,3}x_7,&
y_8 &= d_{3,4}x_4 + d_{4,4}x_8.
\end{aligned}
\]
The next component $\tilde{\bm{B}}(8,4)=\operatorname{diag}(\bm{B}^F_1(4),\bm{B}^F_2(4))$ applies two independent $\bm{B}^F(4)$ blocks: one to indices $(1\ldots4)$ and one to $(5\ldots8)$. Finally $\tilde{\bm{B}}(8,2)$ is block-diagonal with four $\bm{B}^F(2)$ blocks, each of which is a $2\times 2$ matrix mixing a neighboring pair of coordinates.

To make every $\tilde{\bm{B}}(8,k)$ orthogonal we parameterize the smallest blocks ($2\times 2$ blocks in $\tilde{\bm{B}}(8,2)$) with an orthogonal parameterization (the paper suggests Cayley or direct 2D rotations). Because the non‑zero pattern of each larger $\bm{B}^F(k)$ is a permutation of the pattern in $\tilde{\bm{B}}(d,2)$, we can implement the larger components by placing permuted $2\times 2$ orthogonal blocks in the appropriate locations.

A compact constructive description (radix-2 / Cooley–Tukey style) for the three stages is:

- Stage 1 (leftmost, $\tilde{\bm{B}}(8,8)$): pair indices $(0,4),(1,5),(2,6),(3,7)$ and apply four independent $2\times 2$ orthogonal blocks, one per pair.
- Stage 2 ($\tilde{\bm{B}}(8,4)$): pair indices $(0,2),(1,3),(4,6),(5,7)$ and apply four $2\times 2$ orthogonal blocks.
- Stage 3 ($\tilde{\bm{B}}(8,2)$): pair adjacent indices $(0,1),(2,3),(4,5),(6,7)$ and apply four $2\times 2$ orthogonal blocks.

Multiplying these three stage matrices in the order
\[
\bm{R}=\tilde{\bm{B}}(8,8)\,\tilde{\bm{B}}(8,4)\,\tilde{\bm{B}}(8,2)
\]
produces a dense $8\times 8$ matrix whose non-zero pattern is dense and that is orthogonal provided each small $2\times 2$ block is orthogonal.

Code walkthrough: below is a short NumPy example that assembles the three stages from $2\times 2$ Cayley parameter blocks (details of Cayley appear in the next section). This follows the same constructive topology that the paper attributes to Cooley–Tukey butterfly graphs.

```python
# Python / NumPy (illustrative)
import numpy as np

def cayley_2x2(q):
    # Cayley parameterization R = (I + Q) (I - Q)^{-1} where Q = [[0, q], [-q, 0]]
    Q = np.array([[0.0, q], [-q, 0.0]])
    I = np.eye(2)
    R = (I + Q) @ np.linalg.inv(I - Q)    # matches the Cayley formula in the paper
    return R

def stage_matrix(d, pairs, qs):
    # Build a dxd identity and place 2x2 blocks at given index pairs
    M = np.eye(d)
    for (i,j), q in zip(pairs, qs):
        R2 = cayley_2x2(q)
        idx = np.ix_([i,j],[i,j])
        M[idx] = R2
    return M

d = 8
# stage 1 pairs (0-based)
pairs1 = [(0,4),(1,5),(2,6),(3,7)]
pairs2 = [(0,2),(1,3),(4,6),(5,7)]
pairs3 = [(0,1),(2,3),(4,5),(6,7)]

# example q parameters (small rotations)
qs1 = [0.1, -0.2, 0.05, 0.07]
qs2 = [0.0, 0.15, -0.08, 0.12]
qs3 = [0.02, -0.04, 0.06, -0.01]

M1 = stage_matrix(d, pairs1, qs1)
M2 = stage_matrix(d, pairs2, qs2)
M3 = stage_matrix(d, pairs3, qs3)

R = M1 @ M2 @ M3   # product in the order described in the paper
```

# Implementing $2\times 2$ Cayley blocks and verifying orthogonality

The Cayley parameterization used in OFT / BOFT is
\[
\bm{R}=(\bm{I}+\bm{Q})(\bm{I}-\bm{Q})^{-1},
\]
with $\bm{Q}$ skew-symmetric. For a $2\times 2$ skew-symmetric $\bm{Q}$ the form is
\[
\bm{Q}=\begin{bmatrix}0 & q\\ -q & 0\end{bmatrix}.
\]
You can expand the Cayley formula for this $2\times 2$ case to obtain a closed form. With simple algebra (compute $(\bm{I}-\bm{Q})^{-1}$ and multiply) one gets
\[
\bm{R}
= \frac{1}{1+q^2}
\begin{bmatrix}
1-q^2 & 2q\\[4pt]
-2q & 1-q^2
\end{bmatrix}.
\]
This is a planar rotation matrix: it is orthogonal and has determinant $1$ (it parameterizes rotations via stereographic mapping of $q$ to angle).

Why use Cayley in practice? The Cayley map guarantees orthogonality of the resulting block for any skew-symmetric $\bm{Q}$ for which $(\bm{I}-\bm{Q})$ is invertible; for small initial $\bm{Q}$ (identity initialization uses $\bm{Q}=\bm{0}$) invertibility is safe. The paper explicitly suggests Cayley parameterization to enforce orthogonality throughout finetuning.

Code snippet to verify:

```python
# Verify closed-form equals matrix Cayley
for q in [0.0, 0.1, -0.5, 2.0]:
    R_closed = np.array([[ (1-q*q)/(1+q*q), 2*q/(1+q*q)],
                         [ -2*q/(1+q*q), (1-q*q)/(1+q*q) ]])
    R_from_cayley = cayley_2x2(q)
    print(q, np.allclose(R_closed, R_from_cayley, atol=1e-12))
    print("orthogonality check:", np.max(np.abs(R_from_cayley.T @ R_from_cayley - np.eye(2))))
```

# Checking spectral norm invariance after BOFT

The paper highlights a key stability property of orthogonal finetuning: left-multiplying a pretrained weight matrix $\bm{W}^0\in\mathbb{R}^{d\times n}$ by an orthogonal $\bm{R}\in\mathbb{R}^{d\times d}$ preserves singular values of $\bm{W}^0$. If $\bm{W}^0=\bm{U}\bm{\Sigma}\bm{V}^\top$ is the SVD of $\bm{W}^0$, then
\[
\bm{R}\bm{W}^0 = (\bm{R}\bm{U})\bm{\Sigma}\bm{V}^\top,
\]
and since $\bm{R}\bm{U}$ is orthogonal, the singular value diagonal $\bm{\Sigma}$ is unchanged. Thus the spectral norm (largest singular value) satisfies
\[
\|\bm{R}\bm{W}^0\|_2 = \|\bm{W}^0\|_2.
\]

A short numerical check (NumPy) — create a random $\bm{W}^0\in\mathbb{R}^{8\times 5}$, build a BOFT $\bm{R}$ as in previous sections, and verify that the largest singular values match to numerical precision:


# Measuring expressivity by approximating a random orthogonal

The paper studies expressivity by approximating a random dense orthogonal matrix using BOFT factorization and reports BOFT's superior parameter efficiency. We can reproduce a small-scale experiment to build intuition.

Outline of the experiment:

1. Sample a target orthogonal matrix $\bm{T}\in\mathbb{R}^{d\times d}$ by taking a random Gaussian matrix and performing QR (keep the $Q$ factor). This matches the method cited in the paper for generating random orthogonals.
2. Parameterize a BOFT $\bm{R}(\theta)$ with topology chosen (e.g., $m=\log_2 d$, block size $2\times 2$). The learnable parameters $\theta$ are the skew-symmetric entries $q$ for each $2\times 2$ Cayley block across all stages.
3. Optimize $\theta$ to minimize Frobenius error
\[
L(\theta)=\|\bm{R}(\theta)-\bm{T}\|_F^2
\]
using gradient descent (use PyTorch autograd).
4. Track the final approximation error and compare parameter counts between BOFT and block-diagonal OFT with the same budget.

A minimal PyTorch module structure:

```python
# PyTorch pseudocode sketch
import torch
import torch.nn as nn
import torch.optim as optim

class BOFTParam(nn.Module):
    def __init__(self, d, m):
        super().__init__()
        self.d = d
        self.m = m
        # total 2x2 blocks per stage = d//2
        # store one scalar q per 2x2 block per stage
        self.q = nn.Parameter(torch.zeros(m, d//2))  # identity init (q=0 -> R=I)

    def cayley2(self, q):
        # q is tensor scalar
        I = torch.eye(2, device=q.device, dtype=q.dtype)
        Q = torch.stack([torch.stack([torch.tensor(0., device=q.device), q]),
                         torch.stack([-q, torch.tensor(0., device=q.device)])])
        return (I + Q) @ torch.inverse(I - Q)

    def forward(self):
        # Build stage matrices and multiply
        stages = []
        d = self.d
        # for simplicity, use the fixed FFT-like pairing ordering as in earlier section
        pairings = [...]
        for s in range(self.m):
```

# Implementing multiplicative Dropout and evaluating its effect

The paper introduces a multiplicative Dropout adapted to BOFT: since BOFT's update is multiplicative (left-multiplying by $\bm{R}$) the usual additive Dropout is not directly applicable. The multiplicative Dropout described in the paper randomly picks $p_1$ percent of the butterfly components (entire stages) and $p_2$ percent of the diagonal blocks in each component, then replaces the chosen blocks with identity blocks during that forward pass.

A straightforward implementation idea consistent with the paper:

- For each forward pass, sample a stage-mask of length $m$ where each stage is kept with probability $(1-p_1)$; if a stage is dropped, use the identity matrix instead of that stage's matrix.
- For every kept stage, sample a mask over its diagonal blocks (there are $d/2$ two-by-two blocks) where each block is kept with probability $(1-p_2)$; if a block is dropped, replace the $2\times 2$ block by the identity matrix.

Code sketch (PyTorch):

```python
def apply_multiplicative_dropout(stages, p_stage, p_block):
    # stages: list of stage matrices (torch tensors)

    for M in stages:
        if torch.rand(1).item() < p_stage:
            out_stages.append(torch.eye(M.size(0), device=M.device))
            continue
        # else keep stage but drop some internal blocks (set those 2x2 blocks to identity)
```

# Counting parameters and FLOPs across configurations

The paper gives a compact formula for the number of effective trainable parameters in BOFT:
\[
\text{params}_{\text{BOFT}}(m,b)=\tfrac{1}{2}(b-1)\,d\,m,
\]
for a BOFT configuration BOFT$(m,b)$. This formula matches the block-diagonal OFT when $m=1$ (block size $b$) and reduces to the full OFT when $b=d$ and $m=1$ (full orthogonal matrix has $\mathcal{O}(d^2)$ parameters). Important special cases the paper mentions:

- BOFT with $b=2$ and $m=\log_2 d$ (a standard butterfly): parameters are $\tfrac{1}{2}(2-1)d\log_2 d = \tfrac{1}{2} d\log_2 d$, i.e., $\mathcal{O}(d\log d)$.
- Full OFT (no factorization): $\mathcal{O}(d^2)$ parameters.
- Block-diagonal OFT with block size $b$ (single stage $m=1$): $\tfrac{1}{2}(b-1)d$ parameters, i.e., $\mathcal{O}(bd)$.

Small numeric examples (use the formula):

- For $d=8$:
  - Full OFT: $d^2 = 64$ parameters.
  - Block-diagonal OFT with $b=4$ ($m=1$): parameters $=\tfrac{1}{2}(4-1)\cdot 8\cdot 1 = 12$.
  - BOFT with $b=2$, $m=3$: parameters $=\tfrac{1}{2}(2-1)\cdot 8\cdot 3 = 12$ as well (same budget but different structure).

FLOP estimate (guided by statements in the paper): each sparse factor in the butterfly factorization has $\mathcal{O}(d)$ non-zero entries; there are $m$ factors. To compute the product $\bm{R}\bm{W}^0=\big(\prod_{i=1}^m\bm{B}_i\big)\bm{W}^0$ by applying the $m$ factors sequentially to $\bm{W}^0$ costs about $m$ times the cost of applying one sparse factor. If each factor has $c\cdot d$ non-zero entries and $\bm{W}^0$ has $n$ columns, then a rough flop count for producing $\bm{R}\bm{W}^0$ is
\[
\text{FLOPs}\approx C\cdot m\cdot d\cdot n,
\]
where $C$ is a small constant depending on block arithmetic. This highlights the paper's trade-off: BOFT lowers parameter count (space) at the cost of increased computation (time) per update because factors must be applied repeatedly in each forward/backward pass.

# A toy Transformer layer with BOFT: end-to-end training script

The paper frames BOFT as a drop-in finetuning strategy that multiplies a frozen pretrained weight $\bm{W}^0$ on the left by an orthogonal matrix $\bm{R}$. The forward pass becomes
\[
\bm{z}=\big(\bm{R}\bm{W}^0\big)^\top \bm{x}.
\]
We now present a minimal end-to-end PyTorch training script for a toy Transformer-like linear projection layer that uses BOFT to finetune while keeping $\bm{W}^0$ frozen. This follows the architecture choices in the paper (identity initialization of $\bm{R}$ via zero skew parameters, Cayley parameterization to maintain orthogonality).

Key elements:

- Keep $\bm{W}^0\in\mathbb{R}^{d\times n}$ frozen (requires no gradient).
- Implement a BOFT module that stores Cayley skew parameters per $2\times 2$ block per stage (identity init).
- Each forward computes $\bm{R}$ as the product of stage matrices and then applies $(\bm{R}\bm{W}^0)^\top \bm{x}$.
- Train only the BOFT parameters with an optimizer (e.g., Adam).

High-level training loop (outline, not full copyable script):

1. Prepare random inputs $\bm{x}\in\mathbb{R}^d$ and targets $\bm{y}\in\mathbb{R}^n$ (toy supervised loss) or a small classification problem.
2. Instantiate BOFTParam(d,m) module and a frozen W0 tensor.
3. In each iteration:
   - Compute $\bm{R}=\text{BOFTParam}()$ (product of stages).
   - Compute $\hat{\bm{z}}=(\bm{R}\bm{W}^0)^\top\bm{x}$.
   - Compute loss (e.g., MSE if regression target).
   - Backpropagate and update only BOFT parameters.
4. Monitor training and validation losses.

This toy exercise reproduces the finite difference between multiplicative (BOFT) finetuning and additive methods: BOFT multiplies the frozen pretrained matrix and, thanks to orthogonality, preserves $\|\bm{W}^0\|_2$ which the paper highlights as beneficial for stability.

# Debugging checklist: numerical issues and layout mismatches

When implementing BOFT you will encounter the usual engineering pitfalls. The paper's recipe suggests remedies and initialization choices; here is a compact checklist (each item connects to concepts in the paper):

1. Identity initialization: verify all skew-symmetric parameters are initialized to zero so every Cayley block is identity at start. This matches the paper's zero initialization for $\bm{Q}$ and avoids sudden deviation from pretrained weights.

2. Orthogonality verification: numerically check $\|\bm{R}^\top\bm{R}-\bm{I}\|_\infty$ or Frobenius norm after constructing $\bm{R}$. For Cayley blocks the result should be orthogonal up to solver precision.

3. Invertibility in Cayley: the Cayley transform uses $(\bm{I}-\bm{Q})^{-1}$. For $2\times 2$ skew blocks this is almost always invertible for reasonable parameter scales; nonetheless monitor the condition number of $(\bm{I}-\bm{Q})$ in case of very large skew parameters (initialization to zero avoids this).

4. Block indexing and permutation: the butterfly decomposition relies on a precise pattern of which coordinates each $2\times 2$ block connects at each stage. Carefully implement the stage pairings (the Cooley–Tukey-like pattern shown earlier) and validate by constructing a small example and printing the explicit stage matrices.

5. Dtype and device consistency: ensure all factors and the frozen $\bm{W}^0$ use the same dtype and device. Mismatches (CPU vs GPU or float32 vs float64) can cause silent errors or precision loss.

6. Multiplicative Dropout masking: when applying multiplicative Dropout, be sure you replace blocks with identity matrices — not zeros. Replacing with zeros breaks invertibility/orthogonality and changes the shape of the mapping; the paper prescribes replacing with identity.

7. Parameter counting sanity checks: verify that the number of learnable scalar skew-parameters equals the formula $\tfrac{1}{2}(b-1)dm$ for your chosen $(m,b,d)$. Small mismatches typically mean some blocks were duplicated or index ranges are off.

8. Runtime trade-off note: the paper points out BOFT increases per-step computation because you apply multiple sparse factors sequentially. If training is unexpectedly slow, profile the stage multiplications and consider reducing $m$ or increasing block size $b$ to trade compute for parameters.

Extensions and Variants

# Kaleidoscope hierarchies: alternating products and transposes
One of the cleanest generalizations of the BOFT parameterization presented in the paper is the kaleidoscope-style composition that alternates products of butterfly-parameterized orthogonal blocks and their transposes. The paper introduces this idea explicitly: starting from the BOFT blockwise product notation $\bm{R}(m,b)=\prod_{i=1}^m \tilde{\bm{B}}^b_{(d,i)}$, we can form a generalized orthogonal matrix by interleaving different BOFT factors and their transposes. Concretely the paper writes this family as
\[
\bm{R}^G(m_1,b_1,m_2,b_2,\ell)
= \bm{R}_{\ell,1}(m_1,b_1)\,\bm{R}_{\ell,2}^\top(m_2,b_2)\,
\cdots\,
\bm{R}_{1,1}(m_1,b_1)\,\bm{R}_{1,2}^\top(m_2,b_2),
\]
where each $\bm{R}_{i,j}(\cdot,\cdot)$ is itself a BOFT-style orthogonal factor. The paper points out an important expressivity result driven by this construction: when one takes $m_1=m_2=\log d$, $b_1=b_2=2$, and composes $\ell=d-1$ alternating factors, the resulting family is rich enough to represent the entire orthogonal group in dimension $d$. This composition is exactly what the paper refers to as a kaleidoscope hierarchy (and ties back to prior work on kaleidoscope parameterizations).

Intuitively, alternating products and transposes multiplies mixing stages with different alignments so that each stage can re-route and recombine coordinates in ways that a single sequence of butterfly factors cannot. Theorem (Expressivity of BOFT) in the paper formalizes that BOFT with suitable alternation can approximate general orthogonal matrices; the kaleidoscope extension simply makes this explicit and constructive.

The paper also emphasizes a practical caveat: more expressivity is not always better for finetuning. Full expressivity (i.e., the ability to represent any orthogonal matrix) removes regularizing structure and can hurt generalization, just as full finetuning often underperforms more constrained PEFT choices. Thus the kaleidoscope hierarchy is presented in the paper both as a theoretical endpoint (how to reach full orthogonal expressivity) and as a practical knob: it lets practitioners expand BOFT toward full expressivity in a controlled way by increasing $m_1,m_2$ and $\ell$, while being mindful of the trade-off between expressivity and regularity.

# Dynamic selection of m and b per layer or per training stage
A central design pair in BOFT is the number of butterfly components $m$ and the block parameter $b$ (the paper denotes BOFT as BOFT$(m,b)$). These two integers jointly determine both expressivity and parameter cost. The paper gives a compact expression for the effective number of trainable parameters of BOFT on a linear layer of input dimension $d$:
\[
\text{effective parameters} \;=\; \tfrac{1}{2}(b-1)\,d\,m.
\]
Several useful special cases are given in the paper: BOFT$(1,b)$ reduces to the block-diagonal OFT with block size $b$; BOFT$(1,d)$ is the original (unconstrained) full OFT orthogonal matrix; and BOFT$\!\big(\log\frac{2d}{b},\,b\big)$ corresponds to using the block butterfly matrix $\bm{B}^{\frac{b}{2}}(d)$ and yields a dense orthogonal matrix while keeping the per-factor structure.

Because $m$ and $b$ directly trade parameter count and connectivity, the paper observes that configurations with smaller $b$ and larger $m$ are often more parameter-efficient in practice: they achieve a given approximation quality with fewer parameters than a single large block. The empirical simulation summarized in the paper shows, for example, that BOFT variants with more stages and smaller blocks (e.g., many $2\times 2$-style blocks) can approximate random orthogonal matrices with fewer parameters than coarse block-diagonal parameterizations.

This explicit control suggests a natural extension — which the paper frames as a design opportunity — to choose $(m,b)$ adaptively across layers or across training stages. Different layers of a pretrained model have different sensitivity and different roles (e.g., early layers tend to represent low-level features, later layers more abstract semantics), and the BOFT parameterization makes it straightforward to allocate more degrees of freedom where they are needed by increasing $b$ or $m$, and to economize where stability/regularity are preferred by keeping $b$ small or $m$ small. Likewise, a staged training schedule that starts close to identity (small effective parameters) and gradually increases $m$ or $b$ can be accommodated within the BOFT family because BOFT naturally supports identity initialization (all components initialized to identity via Cayley transform). The paper itself does not report a layerwise adaptive or stagewise schedule, but its analysis and parameter-count formulas make clear that these dynamic design choices are immediate and well motivated.

# Learnable or data-dependent permutations between components
One of the structural pieces the paper highlights is that butterfly components can be viewed as permutations of the base 2-by-2 interaction pattern: the nonzero pattern of a butterfly component is essentially a permuted arrangement of $\tilde{\bm{B}}(d,2)$ blocks. The paper explicitly notes that "the butterfly structure along with permutations can perfectly recover many classic linear transforms" (for example, fast Fourier and Hadamard transforms are recoverable when permutations are chosen appropriately). Thus permutations are an integral ingredient in the way BOFT mixes coordinates across stages.

This observation opens two model-design choices discussed in the paper. The first is to fix a canonical permutation schedule (as in the radix-2 Cooley–Tukey FFT) and learn only the continuous entries of the butterfly blocks. The second (presented in prior related work cited by the paper) is to allow permutations to adapt so that the overall topological routing best matches data structure. The paper cites prior works that learn fast linear transforms with butterfly parameterizations, which implicitly exploit permutation flexibility to expand expressivity.

The paper frames learnable or data-dependent permutations as a natural extension: by allowing the permutation wiring between stages to be chosen or adapted (either by discrete selection or by continuous relaxations), one can steer where information mixes early and where it mixes later. Because permutations alter the routing of information but do not change the count of parameters per se, they are a powerful lever for expressivity without necessarily increasing raw parameter budget. The paper, however, does not detail specific algorithms for learning discrete permutations; it presents this as an avenue compatible with the BOFT framework and with the general information-transmission perspective that drives the design.

# Alternative topologies: Beneš, hierarchical, or graph-inspired designs
The information-transmission framing in the paper — representing a factorization $\bm{R}=\bm{B}_m\bm{B}_{m-1}\cdots\bm{B}_1$ as a grid of nodes and edges — is deliberately chosen to make contact with classical network topologies studied in computer networking and parallel algorithms. The butterfly topology is one such efficient topology: it achieves dense connectivity from $d$ sources to $d$ receivers using only $\mathcal{O}(d\log d)$ sparse factor blocks. The paper explicitly calls attention to the fact that other topologies from networking and sparse-factorization literature are conceptually available and may be studied through the same lens.

The paper uses the butterfly as its main example because of its proven efficiency (small number of edges/stages for dense connectivity) and because it aligns with many fast linear transforms. But the information-transmission framework treats topologies abstractly: for any choice of per-stage adjacency pattern that ensures every source can reach every sink, one can attempt to parameterize each stage as an orthogonal sparse factor and thereby obtain a dense composite orthogonal matrix. The paper notes that orthogonality imposes constraints (e.g., each stage must have at least $d$ edges to be full-rank), so any candidate topology must be compatible with those algebraic requirements.

In this sense, hierarchical arrangements, permutation networks (e.g., networks known in switching theory), or more general graph-inspired designs can all be ported into the BOFT-style approach. The paper does not claim or evaluate specific alternate topologies, but it highlights the opportunity: the information-transmission viewpoint reduces the search for parameter-efficient orthogonal factorizations to the search for sparse topologies with favorable edge/level trade-offs that respect orthogonality. Exploring such topologies is explicitly suggested as an open direction in the paper.

# Combining BOFT with quantization, pruning, and low-rank methods
The paper positions BOFT as one family of structural parameter-efficiency — namely, sparse factorization leading to orthogonal updates — and contrasts this with the low-rank additive reparameterizations exemplified by LoRA. It explicitly points out that both low-rank matrices and sparse (butterfly-style) matrices are major families of structured matrices that achieve parameter efficiency. This framing motivates natural combinations.

While the paper does not report experiments that fuse BOFT with quantization, pruning, or additive low-rank corrections, it records properties that make such combinations conceptually straightforward. For instance, BOFT preserves the spectral norm of the pretrained weight matrix (because the learned factor is orthogonal), which yields favorable training stability; after finetuning the orthogonal factors can be multiplied into the pretrained model so there is no inference latency penalty. Those properties make BOFT-friendly to post-processing steps common in deployment: the merged weights can be quantized or pruned in the same way as ordinary dense pretrained weights, and the BOFT parameter budget could be supplemented by low-rank additive corrections (LoRA-style) if a small residual correction is needed beyond a multiplicative orthogonal reweighting.

The paper also introduces multiplicative Dropout as a regularizer tailored to the multiplicative orthogonal structure; this highlights that BOFT admits specific regularization tactics that interact well with other compression methods. The paper leaves detailed mixed-compression recipes as a practical direction rather than as part of the core contribution, but the text establishes conceptual compatibility between BOFT and complementary compression techniques.

# Multi-task and continual learning with shared BOFT components
Because BOFT is a finetuning paradigm where a small, structured orthogonal transform is learned and applied across neurons in a layer, it naturally lends itself to parameter-sharing strategies that are appealing in multi-task and continual learning settings. The paper emphasizes that BOFT learns layer-shared orthogonal matrices to transform the pretrained weight matrix $\bm{W}^0$ as $\bm{R}\bm{W}^0$, and that $\bm{R}$ is initialized at identity so the pretrained model is preserved at the start. These properties make BOFT a natural adapter: one can imagine reusing a core set of BOFT components across tasks while learning task-specific light-weight components on top.

The paper does not experimentally pursue multi-task or continual learning, but its formulation suggests a few patterns that sit cleanly inside the BOFT family. For example, a shared base BOFT factorization could be learned once and then kept frozen while task-specific BOFT stages (extra factors or small additive corrections) are learned per task; because BOFT factors can be composed and composed transposes are allowed in the kaleidoscope extension, it is straightforward to design a hierarchical sharing strategy. Identity initialization ensures that adding a new task starts from the pretrained behaviour, and the fact that BOFT factors can be multiplied into the base weights after training eliminates per-task inference overhead if desired. The paper frames these multi-task and continual-learning possibilities as natural consequences of the BOFT design without making empirical claims.

# Geodesic or Riemannian optimization variants for orthogonal constraints
The paper enforces orthogonality of each BOFT factor via Cayley parameterization. Concretely it uses the Cayley form
\[
\bm{R} = (\bm{I}+\bm{Q})(\bm{I}-\bm{Q})^{-1},
\]
where $\bm{Q}$ is skew-symmetric ($\bm{Q}=-\bm{Q}^\top$). This choice guarantees orthogonality for each factor throughout training, allows exact identity initialization (by initializing $\bm{Q}=\bm{0}$), and is the parameterization used both in OFT and BOFT in the paper. The Cayley transform therefore plays a practical role: it enforces the orthogonality constraint in a differentiable reparameterization that is compatible with standard gradient updates.

The paper does not pursue manifold-optimization algorithms explicitly (for example, optimization that moves directly along geodesics on the orthogonal group), but the Cayley parameterization is one concrete mechanism the paper relies on to maintain orthogonality while keeping implementation simple. From the paper's perspective, Cayley provides the operational solution used in all experiments and derivations. Exploring other orthogonality-preserving parameterizations or optimization techniques (if desired) is treated as an alternative design choice in the broader space; the paper documents the Cayley choice as the practical instantiation that supports BOFT's identity initialization and orthogonality constraints.

# Summary and practical guidance
The BOFT family introduced in the paper is deliberately modular, and the paper repeatedly frames its contributions in terms of structural choices that control the trade-off between expressivity and regularity. The kaleidoscope hierarchy gives a route to full orthogonal expressivity by alternating BOFT factors and their transposes; the pair $(m,b)$ cleanly parameterizes a continuum from block-diagonal OFT to dense orthogonal transforms; permutations and wiring patterns are explicit design levers captured by the information-transmission perspective; and the Cayley reparameterization affords identity initialization and exact orthogonality during training.

Practical implications emphasized in the paper are these: (i) choose smaller $b$ with larger $m$ when you want parameter efficiency and smoother interpolation to identity; (ii) use BOFT$(1,b)$ when a block-wise orthogonal update suffices (recovering block-diagonal OFT), and increase $m$ or introduce kaleidoscope alternation only when you need more expressivity; (iii) exploit identity initialization to keep the finetuned model close to pretrained behaviour; (iv) consider multiplicative Dropout (as introduced in the paper) to regularize multiplicative orthogonal updates.

Beyond these concrete recommendations, the paper positions BOFT as a flexible framework: the information-transmission view and the butterfly instantiation are stepping stones toward many plausible variants (alternate topologies, learned permutations, mixed compression strategies, and structured sharing for multi-task learning). The paper documents the core mechanics and empirical advantages of BOFT and leaves this ecosystem of extensions as principled directions to explore using the same analytical lens.

Limitations, Risks, and Open Problems

This chapter critically examines the limitations, risks, and open research questions that follow from the Orthogonal Butterfly (BOFT) proposal in the paper. BOFT is a principled, parameter-efficient orthogonal finetuning method that represents a dense orthogonal matrix $\bm{R}$ as a product of $m$ sparse orthogonal butterfly components, trading parameter count for repeated computation. The paper itself highlights a number of practical and theoretical open issues (for example, training-time overhead and whether butterfly is the optimal topology). Here we collect those points, explain their origin and consequences, and formulate concrete questions that follow directly from the paper’s design choices and empirical claims.

# Training-time overhead from multiple components

One of BOFT’s defining design decisions is to represent the final orthogonal transform as a product of $m$ orthogonal butterfly components,
\[
\bm{R}(m,b)=\prod_{i=1}^m \tilde{\bm{B}}^b_{(d,i)},
\]
with each component chosen to be orthogonal. This factorization reduces the number of trainable parameters: the paper gives that BOFT($m,b$) uses approximately $\tfrac{1}{2}(b-1) d m$ effective trainable parameters, and the canonical butterfly choice ($m=\log d$, $b=2$) yields $\mathcal{O}(d\log d)$ parameters instead of $\mathcal{O}(d^2)$ for a dense orthogonal matrix.

The computational trade-off is that the same factorized structure must be applied repeatedly during each forward and backward pass. The paper explicitly notes that “the training runtime overhead is slightly larger than OFT,” and that improving BOFT’s training runtime remains an open problem. Intuitively, repeated application of $m$ sparse but nontrivial factors increases per-iteration work relative to applying a single block-diagonal orthogonal matrix (OFT with small $m$), even though BOFT is far cheaper in parameters than a fully dense orthogonal matrix.

Two implications follow directly from the paper’s presentation. First, BOFT shifts cost from parameter storage to per-iteration computation: parameter efficiency is achieved by multiplying more sparse factors during training. Second, because the paper shows that the learned product can be folded into the frozen pretrained weights after finetuning, BOFT does not increase inference latency—the training-time penalty is temporary but real.

Open problems for future work (as suggested by the paper)
- Quantify and close the wall‑clock training gap empirically across model families: how large is the overhead in practice for large language models, vision transformers, and diffusion models?
- Design implementations that exploit the butterfly sparsity and structure to reduce runtime: e.g., fused kernels, sparse-dense specialized routines, caching of partial products, or FFT-like fast application of components (the butterfly is closely related to fast transforms).
- Explore algorithmic variants that amortize work (for example, fewer factor updates per step or alternating update schedules), while preserving the parameter-efficiency and orthogonality guarantees emphasized in the paper.

# Is butterfly the most efficient topology for finetuning?

The paper motivates butterfly factorization by framing matrix factorization as an information transmission problem on a $d\times(m+1)$ grid and by recalling the Cooley–Tukey butterfly topology that connects $d$ source nodes to $d$ receiver nodes with $\mathcal{O}(d\log d)$ edges. Butterfly matrices can represent many classic fast transforms and thus provide a natural structured family that is both expressive and parameter-efficient.

However, the paper explicitly acknowledges that whether the butterfly is the most efficient topology is unknown: “whether the butterfly network is the most efficient way to transmit information is also unknown,” and it points to network-topology literature as a source of further inspiration. Efficiency in this context is multi-faceted: it can mean minimizing the number of trainable parameters, minimizing runtime per step, maximizing expressivity for a fixed parameter budget, or producing favorable optimization behavior.

Concrete research directions that follow from the information-transmission framing
- Formalize trade-offs in the information-transmission framework: given $d$ source and $d$ sink nodes and a constraint on the number of trainable edges, what graph topologies minimize parameter count while guaranteeing dense connectivity and satisfying orthogonality constraints?
- Search for alternative sparse topologies (inspired by networking, expander graphs, or other structured factorizations) and compare them empirically to butterfly factorizations on (1) parameter efficiency, (2) expressivity (e.g., approximation error to random orthogonal matrices), and (3) optimization dynamics in finetuning.
- Investigate hybrid factorizations that combine butterfly stages with other sparse or low-rank stages; the paper already points in this direction via the kaleidoscope hierarchy used to characterize universal expressivity (Theorem in the paper), which suggests composing different structured blocks could broaden representational power.

# Scalability and stability under extreme depth or width

The paper demonstrates BOFT’s applicability across modalities and model families, and it proves that compositions of butterfly matrices can be expressive (the paper’s expressivity theorem shows BOFT subsumes OFT and that suitable compositions can cover the whole orthogonal group). Still, the paper does not provide a theoretical analysis of BOFT’s behavior under extreme scaling regimes (very large hidden dimensionality $d$, very deep networks, or extremely wide layers), nor does it present systematic diagnostics of optimization stability across scale.

Relevant observations from the paper that frame this limitation are:
- Orthogonal finetuning preserves the spectral norm of the pretrained weight matrix ($\bm{R}\bm{W}^0$ preserves singular values of $\bm{W}^0$), a property the paper links to training stability and generalization.
- BOFT represents an intermediate hypothesis class (structured subset of the orthogonal group), which helps regularize fine-tuning but may interact with the optimization landscape in nontrivial ways as $d$ grows.

Open problems and experimental questions
- Empirically characterize convergence speed, sensitivity to learning rates, and variance across random seeds as $d$ grows and as $m$ and $b$ vary. Does BOFT require different layer-wise budgets ($m$, $b$) at very large scale?
- Study whether multiplying many orthogonal factors introduces optimization pathologies (for instance, slower mixing of parameter updates across coordinates) despite spectral-norm preservation.
- Analyze interactions between BOFT and architectural depth (e.g., in very deep transformers), including whether layerwise BOFT parameter budgets should be scaled differently across early and late layers to preserve stability and generalization.

# Handling arbitrary dimensions and non-ideal divisibility

The paper defines the basic butterfly factor $\bm{B}^F(k)$ for $k$ a power of two and then generalizes to block butterfly components $\tilde{\bm{B}}^b(d,k)$ by replacing scalar entries with $b\times b$ blocks. These constructions make it straightforward to obtain dense orthogonal matrices when $d$ factors nicely relative to $b$ and when the radix assumptions are met. But real pretrained layers often have hidden dimensions $d$ that are not powers of two and may not be divisible by convenient block sizes.

The paper does not fully specify canonical recipes for arbitrary $d$, so this is a practical limitation that must be handled when applying BOFT to off-the-shelf models.

Open, practically important questions
- How should one adapt BOFT when $d$ is not a power of two or not divisible by chosen $b$? Options include zero-padding, uneven block sizes, or mixed radix butterflies; the relative effects on parameter count, expressivity, and optimization need evaluation.
- What are the implications of padding or irregular blocking on the learned orthogonal transformation and on downstream task performance? Are there principled ways to choose $b$ and $m$ for a given layer dimension $d$?
- Can one design block sizes and factor schedules that minimize wasted parameters from padding while retaining the theoretical properties and empirical benefits BOFT shows in the paper?

# Numerical considerations of Cayley transforms at scale

To guarantee orthogonality during training and to enable identity initialization, the paper adopts the Cayley parameterization for each orthogonal factor: an orthogonal matrix is written as
\[
\bm{R} = (\bm{I} + \bm{Q})(\bm{I} - \bm{Q})^{-1}
\]
with $\bm{Q}^\top = -\bm{Q}$ skew-symmetric. The Cayley transform is used both in the original OFT and here for BOFT components.

The paper uses Cayley parametrization as a practical mechanism but does not present an analysis of numerical conditioning, the computational cost of the required matrix inverses, or alternatives. Those topics therefore remain open.

Concrete numerical and algorithmic questions arising from the paper’s choice
- What is the conditioning of the factors $(\bm{I}-\bm{Q})$ encountered in practice during BOFT training, and how does finite-precision arithmetic affect orthogonality and gradients through the inverse?
- How do per-block sizes $b$ and the number of factors $m$ influence numerical stability in Cayley-based parameterizations in large models?
- Compare Cayley-based orthogonal parameterizations with other orthogonality-preserving approaches (for example, parameterizations based on compositions of Givens rotations, Householder reflectors, or manifold-constrained optimization). The paper adopts Cayley for its guarantee and zero initialization, but it leaves comparative study open.

# Potential biases from structural priors and fairness concerns

A central theme of the paper is that BOFT imposes a structural inductive bias: by restricting finetuning to a structured subset of the orthogonal group (the butterfly family), BOFT narrows the hypothesis class in a way that can improve generalization. The paper argues that the butterfly structure “introduces an implicit inductive bias that benefits generalizability and prevents overfitting” because it aligns with many classic linear transforms.

However, any inductive bias is a double-edged sword: while it can improve average-case generalization, it may also skew model behavior in systematic ways that favor some data patterns over others. The paper does not explore whether BOFT’s structural bias can produce unintended disparities across subpopulations or tasks.

Questions for future fairness-aware evaluation
- Does BOFT’s inductive bias lead to systematic performance differences across input subgroups (for example, different linguistic dialects, image subpopulations, or demographic groups) compared to unstructured finetuning methods?
- Can the information-transmission framework be used to reason about representational limitations that might correlate with sensitive attributes?
- How should practitioners choose $m$ and $b$ to balance improved overall generalization against the risk of amplifying dataset-specific biases? The paper establishes that BOFT is a different hypothesis class; measuring its distributional effects is necessary before widespread deployment.

# Security, privacy, and robustness implications

The paper highlights spectral-norm preservation as a desirable property: because BOFT multiplies pretrained weights by orthogonal matrices, the spectral norm of $\bm{W}^0$ is conserved, which the paper ties to better training stability and generalization. Beyond that, the paper does not investigate security, privacy, or adversarial robustness implications of BOFT versus other PEFT approaches.

Based on the paper’s scope, the following open evaluations would be valuable
- Empirically compare BOFT to other finetuning methods under adversarial attacks and distribution shifts to see whether spectral-norm preservation and structured constraints yield different robustness profiles.
- Assess privacy-related properties (for example, susceptibility to membership inference or model inversion) in the parameter-efficient BOFT regime versus larger parameter updates.
- Evaluate whether parameter-efficient multiplicative updates introduce or reduce new attack surfaces compared to additive low-rank updates (the paper does not address such threats).

# Benchmarking standards and reproducibility gaps

The paper reports an “extensive empirical study” across large vision transformers, large language models, and diffusion models, and it quantifies parameter-efficiency and expressivity (for example, via approximation experiments and the parameter-count formula). To build on these results and to compare alternatives (different topologies, Cayley vs alternatives, different pruning strategies), the community will need consistent benchmarking and reproducibility practices.

Recommendations for benchmarking, motivated by the paper’s experimental agenda
- Report not only final task metrics but also: number of trainable parameters ($\tfrac{1}{2}(b-1) d m$ in BOFT’s accounting), per-step and total training FLOPs, wall-clock training time on specified hardware, variance across random seeds, and inference latency after folding the learned $\bm{R}$ into $\bm{W}^0$.
- Provide ablations across $(m,b)$ grids and across layer types (e.g., attention vs feed-forward layers) to make the trade-offs transparent; the paper’s expressivity experiments illustrate the importance of these ablations, but wider communities will benefit from standardized protocols.
- Share implementation details, initialization and optimizer choices (the paper uses identity initialization for BOFT components), and code to ensure reproducibility and to enable fair comparisons with LOra, OFT, and other PEFT methods.

# Closing summary and prioritized open directions

The BOFT paper introduces a compelling and well-motivated direction: trade parameter count for structure by factorizing a dense orthogonal matrix into a product of sparse orthogonal butterfly components. The main limitations and open problems highlighted by the paper itself—and reiterated and organized here—are:

1. Training-time overhead: BOFT reduces parameter count but increases repeated per-iteration computation; reducing this overhead is an open engineering and algorithmic problem.
2. Topology optimality: butterfly is effective and natural, but whether it is the most efficient sparsity topology (for a given trade-off of parameters, computation, and expressivity) is unresolved.
3. Scalability diagnostics: BOFT’s optimization and stability properties under extreme width or depth are not yet characterized.
4. Dimension handling: practical rules for arbitrary $d$ (non-power-of-two, nondivisible by chosen $b$) need to be clearly specified and empirically validated.
5. Numerical behavior of Cayley parameterization: guaranteed orthogonality is attractive, but numerical conditioning and alternatives need study.
6. Inductive-bias consequences: the butterfly prior improves generalization in many settings but may have unintended representational or fairness consequences that must be measured.
7. Security and privacy: BOFT’s robustness and privacy profiles are unexplored and deserve stress-testing.
8. Benchmarking and reproducibility: standardized metrics and public reference implementations are needed to make BOFT a solid baseline in PEFT studies.

All these points are either explicitly raised by the paper (training runtime and topology optimality) or are natural, necessary follow-ups based on the paper’s design choices (Cayley parameterization, block sizes, inductive bias). Pursuing them will require a combination of theoretical analysis, systems engineering (to exploit sparsity and structure), broad empirical evaluation across modalities, and attention to fairness and safety considerations before BOFT can be adopted as a general-purpose PEFT recipe at very large scale.

Summary and Practitioner's Checklist

# Key takeaways: why and when BOFT works well

Orthogonal Butterfly (BOFT) is a parameter-efficient reparameterization for Orthogonal Finetuning (OFT). The core idea is to represent the left-multiplicative orthogonal transform $R$ applied to a pretrained layer $W^0$ as a product of a small number $m$ of sparse, structured, orthogonal factors (butterfly components):
\[
R \;=\; \prod_{i=1}^m \tilde{B}_{(d,i)}^b .
\]
Each factor $\tilde{B}_{(d,i)}^b$ is a block-butterfly component that is constrained to be orthogonal, so the entire product remains orthogonal during training. Because these factors are sparse and structured, BOFT achieves a much smaller number of trainable parameters than a full dense orthogonal matrix while still enabling dense connectivity between input and output coordinates after composing multiple factors.

Two properties explain why this design often improves finetuning behavior. First, left-multiplying the pretrained weight by an orthogonal $R$ preserves the pretrained singular-value structure: if $W^0 = U \Sigma V^\top$, then the finetuned weight is $R W^0 = (R U)\, \Sigma\, V^\top$, so the singular values $\Sigma$ (and in particular the spectral norm) are unchanged. Preserving these spectral properties is known to help optimization stability and generalization. Second, the butterfly factorization trades parameter count for staged information transmission: sparse factors exchange information across coordinates in a way that can quickly produce dense interactions with far fewer free parameters than a full dense matrix. When model size or deployment constraints make full OFT ($\mathcal{O}(d^2)$ parameters) impractical, BOFT recovers much of the OFT behavior at a cost on the order of $\mathcal{O}(d\log d)$ (for the classic butterfly choice) or, more generally, $\frac{1}{2}(b-1)\,d\,m$ effective parameters for BOFT($m,b$).

When to prefer BOFT in practice: use it when you want the multiplicative, orthogonality-preserving update behavior of OFT but with a limited parameter budget or when you must avoid inference latency. BOFT is especially attractive for adapting large pre-trained models (vision transformers, large language models, diffusion models) where (a) preserving pretrained geometry matters for generalization, (b) many layers have large internal dimensionality $d$ so structured parameter savings matter, and (c) you want to deploy finetuned weights without extra runtime cost. The design also supports a principled trade-off between expressivity and regularity: increasing the number of factors $m$ or block size $b$ increases expressivity; shrinking them increases regularity and reduces overfitting risk.

# Choosing m, b, and target layers under a budget

The BOFT parameter budget per adapted linear layer is explicit and easy to reason about. For BOFT configured as BOFT($m,b$) on a layer with input dimension $d$, the number of effective trainable parameters is
\[
\text{params}_{\text{layer}} \;=\; \frac{1}{2}(b-1)\, d\, m.
\]
This formula gives a direct knob to meet any target budget: for a known per-layer budget $P_{\text{layer}}$ compute feasible integer pairs $(m,b)$ solving $\frac{1}{2}(b-1)\, d\, m \le P_{\text{layer}}$. For a global budget, partition that budget across chosen layers and apply the same per-layer calculation.

If your goal is to obtain a dense orthogonal matrix $R$ (so every input coordinate can reach every output coordinate through the factor chain), BOFT provides a simple guideline: BOFT($\log_2\frac{2d}{b},\,b$) realizes the block-butterfly that yields dense connectivity. In particular, the classical butterfly choice $b=2$ with $m=\log_2 d$ gives the well-known $O(d\log d)$ parameter scaling. When you do not need full density, smaller $m$ already produces richer connectivity than block-diagonal OFT (which is BOFT($1,b$)) and can be a good compromise.

Practical selection strategy:
- Measure the layer input dimension $d$ and decide how many layers you will adapt. Larger gains are typically achieved on layers with large $d$ (those contribute most to $d^2$ cost in a full orthogonal parameterization).
- Decide whether you require full dense $R$. If yes, set $m \approx \log_2\frac{2d}{b}$ and then tune $b$ so $\frac{1}{2}(b-1)\,d\,m$ fits your budget. If not, treat $m$ as a trade-off knob: increasing $m$ increases expressivity (and parameter cost) while decreasing $m$ makes the parameterization more regular.
- As a rule of thumb supported by the paper's empirical and simulation findings, smaller block sizes $b$ with larger $m$ (more butterfly stages) give better parameter efficiency and expressivity than a single large block ($m=1$). BOFT($9,2$) can outperform BOFT($1,16$) with far fewer parameters in approximation experiments.

Remember that BOFT($1,b$) recovers block-diagonal OFT and BOFT($1,d$) recovers the unconstrained full OFT; those are the endpoints of the interpolation between identity regularity and full orthogonal expressivity.

# Initialization, optimization, and regularization tips

Identity initialization is the default and safest start: parameterize each orthogonal butterfly factor using a Cayley transform (or small orthogonal rotation blocks) and initialize the underlying skew-symmetric parameter $Q$ to zero so that each factor and therefore $R$ start as the identity. Concretely, for a skew-symmetric $Q$ the Cayley parameterization gives
\[
R \;=\; (I + Q)\,(I - Q)^{-1},
\]
and setting $Q=0$ initializes $R=I$ exactly. This matches the zero/identity initialization philosophy used in other PEFT methods and keeps the finetuned model close to the pretrained starting point at the beginning of optimization.

Each butterfly component is itself built from small orthogonal blocks (for BOFT we typically parameterize these blocks with Cayley or direct 2-by-2 rotations). Keeping the parameterization orthogonality-preserving at the factor level removes the need for explicit orthogonality regularizers during training—orthogonality is maintained by construction.

To control overfitting BOFT introduces a multiplicative Dropout strategy adapted to the multiplicative update: randomly select a fraction of the butterfly components and/or a fraction of diagonal blocks inside each component and temporarily replace those blocks by identity matrices during training. The paper frames this as choosing two percentages $p_1$ (for components) and $p_2$ (for diagonal blocks) and replacing the selected blocks with identity. Tune these fractions to your validation metric; the multiplicative dropout plays a role analogous to LoRA's additive dropout but respects BOFT's multiplicative structure.

On optimization: because BOFT starts from identity and maintains orthogonality, standard finetuning recipes that take small steps from pretrained weights apply naturally. The orthogonality constraint tends to stabilize the spectrum of $W^0$, which usually improves training stability; nonetheless, the multiplicative factorization introduces a small runtime overhead during training since multiple sparse factors must be applied each forward/backward pass.

# Ensuring no inference latency via weight fusion

One of BOFT's practical advantages is that the learned orthogonal transform can be fused into the pretrained layer after finetuning, so there is no additional inference-time cost or changed model interface. The fusion is algebraically simple: compute the total orthogonal transform and multiply it into the frozen pretrained weights,
\[
R_{\text{total}} \;=\; \prod_{i=1}^m \tilde{B}_{(d,i)}^b,
\qquad
W^{\text{fused}} \;=\; R_{\text{total}}\, W^0.
\]
After replacing $W^0$ with $W^{\text{fused}}$ in the model, you can discard the BOFT parameters. Because products of orthogonal matrices are orthogonal, the fused operation remains consistent with the training-time parameterization.

Implementation notes (from the paper's description): perform this fusion once at the end of finetuning. The order of multiplication is straightforward (left-multiply $W^0$ by each factor in sequence), and since the factors are sparse structured matrices the fusion step is usually inexpensive compared to the original pretraining cost. The paper emphasizes that this is how BOFT achieves zero inference overhead even though training used a multiplicative factorization.

# Monitoring health metrics: loss, orthogonality, spectra

During BOFT finetuning keep a small but focused set of diagnostics to detect problems early.

First and always: monitor training and validation loss (or task metric). The usual indicators of underfitting, overfitting, or optimization instability apply.

Second: monitor orthogonality at the factor or composed level. Because BOFT enforces orthogonality by construction, you primarily want to detect implementation bugs or numerical drift. A practical scalar diagnostic is the residual of orthogonality for the composed transform:
\[
E_{\text{orth}} \;=\; \big\|R_{\text{total}}^\top R_{\text{total}} - I\big\|_F,
\]
or, if you prefer a per-factor check, monitor $\|\tilde{B}_{(d,i)}^\top \tilde{B}_{(d,i)} - I\|_F$ for each factor. These quantities should remain near machine-zero (modulo finite-precision rounding). Any systematic growth usually indicates a coding error in the parameterization or numerical instability in the factor operations.

Third: track spectral properties of the finetuned layer. A central design motivation of BOFT is spectral preservation: left-multiplication by orthogonal $R$ leaves the singular values of $W^0$ unchanged in exact arithmetic. Use this fact as a sanity check by comparing the leading singular values (or the spectral norm) of $W^0$ and the fused $W^{\text{fused}}$. Large unexpected deviations can flag numerical issues or incorrect application of transforms.

If you observe divergence in loss or unusual drift in orthogonality/spectra diagnostics, common remedies consistent with the paper's approach are to verify identity initialization, ensure Cayley/skew-symmetric parameterization is correctly implemented, and reduce step sizes or adjust multiplicative dropout. Because BOFT enforces orthogonality structurally, most issues trace back to implementation or optimizer settings.

# A quick-start recipe for ViT, LLM, and diffusion settings

Vision transformers, large language models, and diffusion U-Nets are all architectures with many large linear projections. The paper demonstrates BOFT's applicability across these domains; below are compact, model-type–specific quick-starts that follow the paper's principles (keep them as initial templates and tune per task).

ViT (vision transformer) quick start:
Begin by selecting a small number of weight matrices with large internal dimension $d$ (for example, the feed-forward projection matrices or large linear projections inside attention blocks); these tend to yield the biggest parameter-efficiency wins. For a tight parameter budget, prefer small block size $b$ (e.g., $b=2$ or $4$) and increase $m$ until you hit the budget or meet your connectivity needs; if you require dense $R$ choose $m\approx \log_2\frac{2d}{b}$. Initialize all BOFT factors to identity (zero skew-symmetric parameters), optionally enable multiplicative dropout to reduce overfitting, and finetune. At the end, fuse $R_{\text{total}}$ into the pretrained weights to eliminate inference cost.

LLM (large language model) quick start:
Target large projection matrices where preserving the pretrained geometric structure helps (for example, large feed-forward layers or projection matrices whose input dimension is high). Use the same BOFT($m,b$) budgeting approach: small $b$ and more stages $m$ generally yield better parameter efficiency and expressivity than a single big block. Keep identity initialization (Cayley with $Q=0$), consider multiplicative dropout if the downstream training set is small relative to model size, and fuse the learned transform into the base model before serving.

Diffusion (text-to-image U-Net and conditional modules) quick start:
Prior work on OFT showed strong benefits in diffusion model finetuning; BOFT is the parameter-efficient extension. Apply BOFT to the large convolutional or linear projection layers where $d$ (channels) is large; choose $m$ and $b$ by the same budget calculus. Identity initialization is particularly important for diffusion finetuning because small deviations from pretrained behavior can otherwise destabilize sampling; preserve orthogonality during training and fuse at the end for unchanged sampling runtime.

Across all three settings, the workflow is the same: pick layers with large $d$ that most benefit from angle-preserving multiplicative updates; compute a feasible BOFT($m,b$) configuration using $\tfrac{1}{2}(b-1)dm$; initialize to identity via Cayley; optionally apply multiplicative dropout; finetune; verify orthogonality and spectral diagnostics; fuse the factors into $W^0$ for zero-latency inference.

Concluding practical checklist (compact)

- Decide which layers to adapt: prioritize large-$d$ linear projections where parameter savings matter most.
- Set a parameter budget and solve $\tfrac{1}{2}(b-1)dm \le$ budget per layer (or aggregated across layers). If you need dense connectivity, use $m \approx \log_2\frac{2d}{b}$.
- Choose BOFT($m,b$) accordingly; prefer small $b$ with larger $m$ for parameter efficiency and expressivity when budget permits.
- Parameterize orthogonal factors with Cayley (skew-symmetric $Q$) or small orthogonal rotations; initialize $Q=0$ so each factor starts as identity.
- Optionally enable multiplicative Dropout (select some components/blocks and replace them with identity during training) to reduce overfitting; tune the selection rates on validation.
- Train while monitoring: loss/validation metric, orthogonality residuals (e.g., $\|R_{\text{total}}^\top R_{\text{total}}-I\|$), and spectral checks (compare leading singular values of $W^0$ and fused $W$).
- At the end of finetuning compute $R_{\text{total}}=\prod_{i=1}^m \tilde{B}_{(d,i)}^b$ and set $W^{\text{fused}}=R_{\text{total}} W^0$; then remove BOFT parameters from the deployed model to ensure zero inference overhead.

Common pitfalls to avoid
- Skipping identity initialization: starting away from identity can make the finetuned model diverge from pretrained behavior and harm generalization.
- Miscounting parameter budget: use the explicit formula $\tfrac{1}{2}(b-1)dm$ when planning multi-layer allocations.
- Ignoring orthogonality diagnostics: although BOFT enforces orthogonality structurally, numerical or implementation errors can break that guarantee—check $R^\top R\approx I$.
- Demanding full expressivity when unnecessary: full orthogonal expressivity is not always better for generalization; prefer the structured BOFT trade-off that fits your validation behavior.

Follow these steps and checks to deploy BOFT in practice: it gives you the angle- and spectrum-preserving benefits of orthogonal finetuning with a controlled parameter budget and no inference-time cost after fusion.

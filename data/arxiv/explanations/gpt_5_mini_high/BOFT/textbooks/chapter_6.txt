\title{A Textbook about the Paper: "Parameter-Efficient Orthogonal Finetuning via Factorization"}

Chapter 6: Computation and Implementation Details

# Applying BOFT at activation time: computing $R^\top x$ before the frozen layer

BOFT modifies a pretrained linear layer $\bm{W}^0\in\mathbb{R}^{d\times n}$ by left-multiplying it with a trainable orthogonal matrix $\bm{R}\in\mathbb{R}^{d\times d}$. The forward pass in the paper is written as
$
\bm{z} = \big(\bm{R}\bm{W}^0\big)^\top \bm{x}.
$
A simple algebraic rearrangement that is critical for an efficient implementation is
$
\bm{z} = (\bm{R}\bm{W}^0)^\top \bm{x} = (\bm{W}^0)^\top \big(\bm{R}^\top \bm{x}\big).
$
This identity shows that rather than forming $\bm{R}\bm{W}^0$ explicitly, one can first compute the transformed activation $\bm{y}=\bm{R}^\top\bm{x}$ and then apply the frozen matrix multiply $\bm{z}=(\bm{W}^0)^\top\bm{y}$. The latter is the same dense activity as in the original pretrained model; BOFT only adds the cost of computing $\bm{R}^\top\bm{x}$ at activation time.

Because BOFT parameterizes $\bm{R}$ as a product of $m$ orthogonal butterfly components,
\[
\bm{R} = \prod_{i=1}^m \tilde{\bm{B}}_{(d,i)}^b,
\]
the transpose factorizes in the reverse order:
\[
\bm{R}^\top = \big(\tilde{\bm{B}}_{(d,1)}^b\big)^\top \big(\tilde{\bm{B}}_{(d,2)}^b\big)^\top \cdots \big(\tilde{\bm{B}}_{(d,m)}^b\big)^\top.
\]
Thus the activation transform is implemented by a sequence of $m$ small transforms: start with $\bm{y}\leftarrow\bm{x}$ and for $i=1\ldots m$ set $\bm{y}\leftarrow \big(\tilde{\bm{B}}_{(d,i)}^b\big)^\top \bm{y}$. Each $\tilde{\bm{B}}_{(d,i)}^b$ is block-diagonal (a butterfly component), and each block is an orthogonal small matrix (for the base case $2\times 2$ blocks these are planar rotations; for block-butterfly they are $2b\times 2b$ orthogonal matrices parameterized via Cayley).

Practical implementation therefore reduces to a tight loop that repeatedly (1) permutes or re-indexes the $d$ coordinates according to the component's pattern, (2) reshapes the relevant coordinates into contiguous mini-blocks, and (3) applies the small block orthogonal transforms. Because every component is sparse / block-structured, each step operates on small contiguous slices of the activation vector and can be implemented with small dense micro-kernels (2×2 or $2b\times 2b$). Identity initialization corresponds to initializing the Cayley skew-symmetric parameters to zero so every $\tilde{\bm{B}}_{(d,i)}^b$ starts as $\bm{I}$; multiplicative Dropout (as proposed in the paper) is applied at activation time by randomly replacing selected components or selected blocks with the identity during training.

# Training-time cost: $O(d\,m)$ for computing $\bm{R}^\top\bm{x}$ plus the frozen matrix multiply

The paper highlights that each butterfly component is sparse with $\mathcal{O}(d)$ nonzero entries. Applying one such component to a length-$d$ vector therefore costs $\mathcal{O}(d)$ scalar multiply–adds; applying $m$ components sequentially costs $\mathcal{O}(d\,m)$. The full forward cost for the finetuned layer is the sum of that overhead plus the usual frozen multiply by $(\bm{W}^0)^\top$, which costs $\mathcal{O}(d\,n)$ where $n$ is the output dimension. In practice the $\mathcal{O}(d\,m)$ term is often smaller than the dense multiply cost (unless $m$ is large and $n$ is small), which is why the paper describes BOFT's runtime overhead as only "slightly larger" than OFT.

Backpropagation through BOFT mirrors the forward sequence: gradients flow back through the same $m$ components in reverse order. The backward pass therefore incurs comparable $\mathcal{O}(d\,m)$ work to compute gradients with respect to the activations and to accumulate gradients for the component parameters. The paper also gives the number of effective trainable parameters per layer as
\[
\text{params} = \tfrac{1}{2}(b-1)\,d\,m,
\]
so the memory and update cost for parameter gradients scale linearly in this quantity.

These complexity observations justify the practical operating point recommended in the paper: choose $m$ and block size $b$ to trade expressivity, parameter count, and per-step runtime. Typical BOFT regimes (e.g., $m\approx \log d, b=2$) yield $\mathcal{O}(d\log d)$ parameters and $\mathcal{O}(d\log d)$ per-activation overhead, substantially smaller than a full dense orthogonal $\mathcal{O}(d^2)$.

# Inference-time fusion: pre-multiplying $\bm{R}$ into $\bm{W}^0$ to avoid latency

A key practical benefit of BOFT emphasized in the paper is that the learned orthogonal $\bm{R}$ can be absorbed into the frozen weights after finetuning. Concretely, once training is finished compute the fused weight
\[
\bm{W}^{\text{fused}} = \bm{R}\,\bm{W}^0,
\]
and replace the original module by the single frozen linear layer with weights $\bm{W}^{\text{fused}}$. After this one-time dense multiplication there is no per-inference overhead from BOFT; inference proceeds exactly as in the original pretrained model. The one-time fusion cost is the dense matrix multiply cost $\mathcal{O}(d^2 n)$ (or distributed variants thereof) and is typically performed offline.

Because $\bm{R}$ is orthogonal, this fusion is lossless: the model with fused weights implements the identical linear mapping as the BOFT configuration. The paper highlights this as an attractive deployment property: the parameter efficiency and training regularization advantages of BOFT do not impose any inference latency or structural constraints at deployment time.

# Permutation and layout of butterfly components for efficient kernels

A practical implementation detail that follows from the butterfly construction in the paper is that each butterfly component can be expressed as (i) a permutation of coordinates followed by (ii) a block-diagonal matrix whose blocks are small orthogonal transforms. The non-zero sparsity pattern of $\tilde{\bm{B}}(d,k)$ is a permutation of the $2\times 2$ base pattern; in the block variant $\tilde{\bm{B}}^b(d,k)$ the entries become contiguous $b\times b$ subblocks. This structure suggests an implementation strategy that minimizes scatter/gather overhead:

- Precompute the index permutation for each component and store it as an integer array. Applying the component becomes: permute the vector once (or interpret indices via strided views), then apply the block transforms to contiguous blocks.

- Implement each block transform as a small dense kernel. For the $2\times 2$ case this is just two fused multiply–adds operating on pairs; for $2b\times 2b$ blocks a tiny GEMM or an unrolled sequence of vector operations is efficient.

- Fuse the permutation with the block kernels when possible (apply the permutation implicitly by computing the block index mapping so that memory accesses are unit-stride).

Because the butterfly components are fixed in structure and the same permutation pattern repeats across batches and layers, these precomputed indices enable highly efficient, vectorizable inner loops. The paper points out that the non-zero pattern is a permutation of the base $2\times 2$ pattern, which is precisely why these precomputation and contiguous-block strategies are feasible.

# Handling non power-of-two dimensions: padding and block variants

The canonical butterfly construction in the paper is written for $d=2^N$ (it assumes $k\ge 2$ is a power of two). The work also introduces block-butterfly components $\tilde{\bm{B}}^b(d,k)$ where each scalar in the base butterfly factor is replaced by a $b\times b$ block; BOFT($m,b$) generalizes the construction and allows $b\ge 2$. Two practical observations from the paper make it straightforward to handle general $d$ in real models:

1. Select a block size $b$ that divides $d$ and construct $\tilde{\bm{B}}^b$ components so that the block-diagonal tiling is exact. With block-butterfly components the requirement that $d$ itself be a strict power of two is relaxed as long as the component tiling is compatible with $d$.

2. When $d$ is not an exact match for desired tiling, a simple and common pragmatic option (consistent with the construction spirit in the paper) is to pad the activation vector to the next compatible size, apply the BOFT components, and then slice back to the original dimension. Identity initialization and the orthogonality constraint make such padding safe during training and fusion: the padded coordinates can be ignored in downstream layers, and after training the final $\bm{R}$ can be fused into $\bm{W}^0$ and the weight rows/columns corresponding to padded dimensions removed.

The paper does not develop or evaluate mixed-radix butterfly factorizations in detail, but the block-butterfly and padding approaches give straightforward, practical paths to apply BOFT to layers whose dimension is not a power of two.

# Mixed precision and numerical stability of Cayley transforms

Orthogonality in BOFT is enforced by parametric orthogonal blocks; the paper follows prior work in using the Cayley parameterization for this purpose:
\[
\bm{R} = (\bm{I}+\bm{Q})(\bm{I}-\bm{Q})^{-1},
\]
with $\bm{Q}$ skew-symmetric. Several practical points flow directly from this choice:

- Initialization: setting $\bm{Q}=\bm{0}$ yields $\bm{R}=\bm{I}$, which gives the zero-update / identity initialization the paper emphasizes for stable finetuning. This also keeps $(\bm{I}-\bm{Q})$ trivially well-conditioned at the start of training.

- Local block transforms: in BOFT the Cayley parameterization is applied at the level of small blocks (e.g., $2\times 2$ or $2b\times 2b$). For the $2\times 2$ case a Cayley transform reduces to a planar rotation and admits a stable closed-form implementation; for small $2b\times 2b$ blocks numerical inversion or direct small-matrix solves are inexpensive and numerically well behaved because block size is small.

- Mixed precision: because BOFT works on many small blocks, it is natural to perform most arithmetic in reduced precision (e.g., float16 or bfloat16) for throughput, but to keep sensitive operations (the small matrix solves or explicit inverses for Cayley) in higher precision (float32) if numerical robustness is a concern. The paper does not study mixed-precision numerics in detail, but the blockwise nature of BOFT makes it straightforward to isolate the few numerically sensitive kernels and run them in higher precision while keeping the bulk computation low-precision.

Finally, the Cayley map with skew-symmetric $\bm{Q}$ is always well-defined (real skew-symmetric matrices have purely imaginary eigenvalues, so $\bm{I}-\bm{Q}$ is nonsingular). Nevertheless, if training drives some blocks of $\bm{Q}$ to have very large norm the numerical conditioning of $(\bm{I}-\bm{Q})$ may worsen; identity initialization and modest learning rates (both recommended in the finetuning literature and consistent with the paper) reduce that risk.

# Memory footprint and checkpointing strategies

The paper gives the parameter count for BOFT($m,b$) as $\tfrac{1}{2}(b-1)\,d\,m$ effective trainable parameters for a $d\times n$ linear layer. Beyond parameter storage, the runtime memory footprint during training includes any intermediate activations required by backpropagation. A straightforward forward implementation that stores the activation vector after each butterfly component requires storing $m$ intermediate length-$d$ vectors (total activation storage $\mathcal{O}(d\,m)$) in addition to the usual per-layer activations. This can be significant if $m$ is large.

A standard remedy (compatible with the BOFT factorization in the paper) is to use activation checkpointing / recomputation: do not store all intermediate $\bm{y}_i$ vectors; instead, recompute them on the backward pass by re-applying the small forward kernels. Because each component is cheap ($\mathcal{O}(d)$) and operates on small blocks, recomputation is typically inexpensive relative to storing and communicating large activation buffers. The blockwise structure also makes it straightforward to checkpoint at coarse granularity (store every few components and recompute intermediate ones), trading compute for memory. The paper notes a modest runtime overhead compared to OFT; checkpointing is the standard practical way to keep peak memory within limits while paying small extra compute.

# Practical pseudocode structure and integration points

Below is a concise pseudocode-style description of the key operations that follows the structure used in the paper. The code uses $m$ components $\{\tilde{\bm{B}}_{(d,i)}^b\}_{i=1}^m$ stored as small block-orthogonal parameterizations (e.g., skew-symmetric $\bm{Q}$ per block) and precomputed integer permutations $\pi_i$ for each component.

Forward pass (training/inference when not fused)
1. Input: activation $\bm{x}\in\mathbb{R}^d$, components $\{\tilde{\bm{B}}_{(d,i)}^b\}$, frozen weights $\bm{W}^0\in\mathbb{R}^{d\times n}$, multiplicative-dropout masks (optional).
2. Set $\bm{y}\leftarrow \bm{x}$.
3. For $i=1$ to $m$:
   a. Optionally apply multiplicative dropout: if this component (or selected blocks) is dropped, skip to next $i$.
   b. Apply permutation $\bm{y}\leftarrow \text{permute}(\bm{y};\pi_i)$.
   c. For each block index $j$ in the block-diagonal tiling:
       i. Extract block slice $\bm{y}_j$ (length $2b$ or $k$).
       ii. Apply small orthogonal transform $\bm{y}_j \leftarrow \big(\text{block\_orthogonal}_j\big)^\top \bm{y}_j$ (block implemented via Cayley or closed-form).
   d. (Optionally) reverse the permutation if the component representation requires it.
4. Compute final output $\bm{z}\leftarrow (\bm{W}^0)^\top \bm{y}$.

Backward pass
- Backpropagate through the dense multiply $(\bm{W}^0)^\top$ to obtain gradient w.r.t. $\bm{y}$, then sequentially backpropagate through the $m$ components in reverse order to obtain gradients w.r.t. component parameters. If activations were checkpointed, recompute needed forward states as necessary during the backward sweep.

Fusion after training
1. Compute fused weights $\bm{W}^{\text{fused}} \leftarrow \bm{R}\,\bm{W}^0$ by constructing $\bm{R}$ block-by-block from the learned components (or by applying the learned $\bm{R}$ to each basis vector to form $d$ columns).
2. Replace the layer by the single frozen dense layer with weights $\bm{W}^{\text{fused}}$; discard BOFT parameters.

Integration points in a typical codebase
- Replace or wrap linear layers with a BOFT wrapper that implements the activation-time transform in the forward pass, stores small block parameters, and supports the fusion API.
- Provide utilities to export and fuse BOFT parameters into a single dense weight tensor for deployment.
- Expose multiplicative-dropout masks and identity initialization hooks for training-time behavior that matches the paper.

Closing remark
All implementation choices above follow directly from the BOFT construction and desiderata in the paper: apply $\bm{R}^\top$ to activations before the frozen layer, implement $\bm{R}$ as a product of sparse orthogonal butterfly components, exploit the block/permute structure for efficient kernels, keep the Cayley parameterization per small block to guarantee orthogonality, and fuse $\bm{R}$ into $\bm{W}^0$ after training so there is no inference overhead. The practical trade-offs—how many components $m$ to use, what block size $b$ to choose, and whether to checkpoint—control the familiar trade-off between parameter-efficiency, compute overhead, and expressivity that the paper emphasizes.

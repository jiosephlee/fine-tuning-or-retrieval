\title{Stack Exchange of the Paper: "DeepSeekMath: Pushing the Limits of Mathematical Reasoning in Open Language Models"}

### What happens if the group reward standard deviation is zero during normalization?
Question:
If all \(G\) outputs for a question receive nearly identical rewards (e.g., all wrong with rule-based rewards), then \(\mathrm{std}(\mathbf{r}) \approx 0\). How do you handle this numerically in GRPO (e.g., adding \(\epsilon\), skipping the update, or falling back to a default advantage)?
Answer:
Short answer: the paper does not spell out a numeric guard for the group-standardization step, but the standard, safe choices are either to clamp the denominator with a small epsilon or — more principled for GRPO — treat a near‑zero group standard deviation as “no comparative signal” and skip/zero the per‑group advantages. I recommend the latter (skip or zero the group) as the default, and fall back to an epsilon‑clamp or batch‑normalization only when you need to salvage many otherwise-unused groups.

Why this matters and why skipping/zeroing is sensible. GRPO makes learning purely comparative inside each sampled group: for outcome supervision the per‑token advantage is set to
$$\hat A_{i,t} \;=\; \widetilde r_i \;=\; \frac{r_i - \operatorname{mean}(\mathbf r)}{\operatorname{std}(\mathbf r)} .$$
If every sampled output for a question receives the same reward (e.g. many identical "wrong" answers under a rule-based scorer), then there is literally no within‑group signal to prefer one sampled output over another. Dividing by a near‑zero standard deviation either gives NaNs or wildly large (and meaningless) numbers if you merely add an extremely small epsilon in the denominator. From an RL perspective it is preferable to avoid arbitrary gradient pushes when the reward function provides no comparative information — setting the group advantages to zero (equivalently skipping that group in the loss) implements that principle.

Practical, robust implementations. A small, robust recipe you can use in GRPO is:

Compute
$$\bar r=\frac{1}{G}\sum_{i=1}^G r_i,\qquad s=\sqrt{\frac{1}{G}\sum_{i=1}^G (r_i-\bar r)^2}.$$
Choose a tiny numerical epsilon (e.g. $\varepsilon_{\text{num}}=10^{-8}$) and a slightly larger practical threshold (e.g. $\tau=10^{-4}$ or tuned to your reward scale). Then:

- If $s\ge\tau$, set $\widetilde r_i=(r_i-\bar r)/\max(s,\varepsilon_{\text{num}})$ and proceed normally.
- If $s<\tau$, set $\widetilde r_i=0$ for all $i$ (or equivalently exclude this group from the gradient).

This avoids divide‑by‑zero, avoids amplifying tiny numerical differences into large advantages, and respects the comparative intent of GRPO.

Alternatives and tradeoffs. Clamping the denominator to $\max(s,\varepsilon)$ is the simplest and is commonly used (advantage normalization in many PPO implementations), but it can still produce large, noisy updates if $s$ is tiny compared to the reward magnitude. Rank‑normalization (turn rewards into ranks inside the group and then standardize ranks) yields bounded, permutation‑based advantages, but if all rewards tie that again injects arbitrary tie‑breaking unless you add noise — which is usually undesired. Using batch‑level normalization (normalize across all sampled outputs in the whole batch rather than per question) is another pragmatic fallback: it gives a nonzero gradient even when some groups are flat, but it departs from the group‑relative philosophy and can mix signals across different questions.

When this problem commonly occurs. If you use a binary or rule‑based final reward ($\text{correct}=1$, $\text{wrong}=0$) and sample many outputs per question, ties and zero std are common. In that case a better long‑term fix is to use a more informative reward signal (process supervision that scores intermediate steps, a learned reward model that outputs continuous scores, or a finer‑grained rule) so groups contain useful variance and GRPO can exploit comparisons.

Monitoring. Whatever fallback you pick, log the fraction of groups with $s<\tau$. If it is large, you are losing effective training signal and should either change the reward function (more informative / continuous), switch to process supervision, or use batch‑level statistics as a deliberate design choice.

Summary. The paper describes group standardization but does not say how to handle zero variance. In practice either clamp the denominator (simple) or, more principled for GRPO, treat near‑zero std as “no comparative information” and set advantages to zero / skip the group (recommended). If many groups are flat, improve the reward signal (process supervision or a learned continuous reward model) or use batch‑level normalization as a fallback.

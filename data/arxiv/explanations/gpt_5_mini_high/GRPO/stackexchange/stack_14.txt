\title{Stack Exchange of the Paper: "DeepSeekMath: Pushing the Limits of Mathematical Reasoning in Open Language Models"}

### How is benchmark decontamination applied to Chinese and chain-of-thought text with the 10-gram rule?
Question:
The decontamination removes any text containing an exact 10-gram match to benchmark substrings, or exact matches for shorter substrings (\(\ge 3\)-grams). For languages without whitespace segmentation (e.g., Chinese) and for chain-of-thought rationales, how are n-grams defined (characters, tokens)? How do you mitigate false positives from common phrases vs. false negatives from minor rephrasings?
Answer:
Short answer: the paper states they remove any web page containing an exact $10$-gram substring that matches any substring from the evaluation benchmarks (and for benchmark texts shorter than $10$ tokens they remove exact matches for substrings with length $\ge 3$), but it does not spell out whether those “grams” are characters, whitespace-delimited words, or model/subword tokens, nor how they treat chain‑of‑thought (CoT) rationales. The description in the paper is therefore the high‑level rule (exact substring matching) but leaves the unit/normalization choices unspecified. Below I explain the implications of each choice and practical mitigation strategies for the two concerns you asked about (Chinese / no‑space languages and CoT; false positives vs. false negatives).

What the paper actually does
The paper’s decontamination paragraph is explicit about the matching policy: remove pages that contain any exact match of a $10$‑gram string taken from evaluation benchmarks, and for benchmark texts shorter than $10$ grams but with length $\ge 3$ do exact matching for those shorter lengths. It also says they do URL deduplication and near‑deduplication earlier in the pipeline. Beyond “exact $10$‑gram substring matches,” the paper does not define the atomic unit of an $n$‑gram (character / word / token), nor describe normalization or special handling for CoT.

Why the unit matters (intuitive)
If “gram” means raw characters then matching is language‑agnostic and simple to implement for Chinese (which has no spaces), but it is brittle to small orthographic variations (extra spaces, punctuation, different LaTeX escapes) and will capture many short, high‑frequency character sequences (raising false positives). If “gram” means whitespace‑delimited words, that fits English well but does not directly apply to Chinese. If “gram” means model tokens (BPE/subword), that aligns the decontamination with what actually enters the model during training (so leakage measured in the model’s input space is reduced), but it requires tokenizing every benchmark string and every candidate web page with the same tokenizer used for training (extra compute at web scale). For chain‑of‑thought, exact substring matching on raw text will find verbatim pasted rationales but will miss paraphrased or lightly edited CoT — i.e., exact matching is conservative (low false positives) but can produce many false negatives.

Practical choices and tradeoffs (what teams typically do)
Because the paper does not commit to a unit, two defensible practical approaches are common:

1) Raw/exact string matching (what the paper’s wording most directly implies): canonicalize the HTML/text (NFKC, collapse spaces, strip markup) and then do sliding‑window exact matches over characters or whitespace tokens. This is cheap and extremely conservative: any verbatim leak is removed. It produces few false positives for long $10$‑grams but will miss rephrasings.

2) Tokenized matching aligned to the model’s tokenizer (BPE/subword): convert both benchmarks and candidate pages into the same token sequence and then do sliding window exact matching on token ids. This measures contamination in the model’s actual input space and reduces some misses caused by trivial normalization differences, but it is heavier to compute at scale. For Chinese, tokenization gives a natural unit even without spaces because the tokenizer already segments characters/subwords.

How to handle Chinese / no‑space languages
Because the paper filters Chinese benchmarks as well, you must pick a unit. Two robust options are: operate at the character level (sliding character $10$‑grams) or operate on the model’s tokens. Character $10$‑grams are simple and language‑agnostic; tokenized $10$‑grams (BPE/subword) are better aligned to what the model learns and often preferable if you can afford the extra tokenization pass. In practice you can do both: run a fast character $10$‑gram scan to remove obvious verbatim contamination and then run a more expensive tokenized pass on surviving pages (or a subset).

How to treat chain‑of‑thought rationales
CoT text is often longer and more formulaic; exact $10$‑gram matches will catch verbatim CoT but miss paraphrases and rephrasings. To reduce both leakage and unnecessary removals you can:

- Normalize before matching: remove variable names/digits or replace them with placeholders, normalize spacing and punctuation, canonicalize simple LaTeX forms. This reduces misses caused by trivial renaming.
- Match both raw and normalized forms. Exact matches on normalized CoT catch more near‑copies while still keeping comparisons cheap.
- Use step‑aware heuristics: if a page shares a short common connective phrase (“therefore”, “thus, we have”) don’t treat that single match as contamination; require matches to include a minimum number of content tokens (non‑stopwords / math symbols) or require multiple distinct substring matches on the same page before marking it contaminated.
- Still prefer exact matches (on normalized text or token ids) over fuzzy matching for final removal decisions if you care about avoiding false positives; fuzzy matching can be used only to flag pages for manual review or for scoring.

Mitigations for false positives vs false negatives (practical recipe)
Exact $10$‑gram matching trades false positives and false negatives as follows: long exact matches are unlikely to be accidental (few false positives), but exact rules miss paraphrases (false negatives). Practical mitigations used in large pipelines are a combination: normalize text; perform exact matching at multiple granularities (character $10$‑grams and token $10$‑grams); treat short matches ($3$–$6$ grams) more carefully by requiring they contain a minimum number of content words or by requiring more than one distinct short match per page; compute a page contamination score (e.g., count of distinct matching substrings, or fraction of tokens that are matched) and remove only pages exceeding a threshold when you want to avoid over‑pruning; keep an aggressive policy (drop any page with a single exact $10$‑gram match) when your objective is to guarantee zero leakage for evaluation benchmarks. For CoT in particular, normalizing numbers/variable names before matching reduces false negatives from trivial renaming.

If you want to catch small rephrasings (reduce false negatives), you can add one of these more advanced steps at the cost of more false positives / more compute: use fuzzy string matching (edit distance on $n$‑grams), MinHash/LSH on shingled tokens to detect near‑duplicates, or semantic similarity models on candidate spans. The paper’s statement (“exact $10$‑gram substring match”) suggests they favor the conservative exact approach rather than heavy fuzzy matching.

Concluding recommendation (balanced, scalable)
Because the paper emphasizes large‑scale Common Crawl mining and describes exact $10$‑gram substring removal, the simplest faithful implementation is: canonicalize pages, run a fast exact sliding window match for benchmark substrings (either character $10$‑grams for Chinese or model/token $10$‑grams if you can tokenize at scale), remove pages with any exact match, and for short benchmarks apply the exact matching for $k$ where $3 \le k < 10$ as the paper says. To reduce spurious removals, add lightweight filters: require content‑token minimums for short matches, compute page‑level contamination scores, and optionally run a second deeper (tokenized or normalized) pass only on pages near the threshold. If contamination risk to benchmarks is the top priority, err on the side of removing any exact $10$‑gram match; if retaining as much data as possible is more important, combine exact matching with token‑level normalization and a small page‑overlap threshold before removal.

Summary: the paper uses exact $10$‑gram (and exact shorter $k$‑gram where $k\ge 3$) substring removal and does this for both English and Chinese benchmarks, but does not state whether grams are characters, words, or model tokens or how CoT is normalized. In practice, the standard approaches are (a) character $n$‑grams for Chinese or (b) token/subword $n$‑grams aligned with the model tokenizer; normalize numeric/variable names for CoT; and combine exact matching with page‑level and content‑token heuristics to balance false positives and false negatives.

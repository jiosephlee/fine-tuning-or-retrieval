\title{Stack Exchange of the Paper: "DeepSeekMath: Pushing the Limits of Mathematical Reasoning in Open Language Models"}

### Algorithm 1 vs. training details: is there one GRPO update per exploration batch or multiple?
Question:
Algorithm 1 shows an inner loop with GRPO updates repeated \(\mu\) times per batch, but the training details later say the policy model only has a single update following each exploration stage. Should I interpret this run as \(\mu = 1\), or are these describing different experiments?
Answer:
Short answer: interpret it as $\mu = 1$ for the reported GRPO runs. Algorithm 1 is written generically (it exposes a hyperparameter $\mu$ so the method can do multiple inner-policy updates per exploration batch), but the paper’s training-details sentence “The policy model only has a single update following each exploration stage” describes the actual setting used for DeepSeekMath‑RL.

Why this is not a contradiction: Algorithm 1 gives a flexible implementation (sample a group of outputs, compute rewards/advantages, then do $\mu$ policy updates on that collected batch). In the experiments, however, the authors sampled a very large set of rollouts per exploration stage ($G=64$ outputs per question, batch size $1024$) and explicitly state they performed only one policy update after each exploration stage. So the pseudocode parameter $\mu$ was instantiated as $\mu=1$ in the reported training. The paper also runs the outer “iterative RL” loop (reward-model re‑training and new exploration batches repeated over iterations), so you still get many exploration→update cycles overall even though each cycle uses a single inner update.

Intuitively this choice makes sense: with such a large number of sampled outputs per question the gradient estimate is already low‑variance, so one optimizer step per exploration stage is sufficient and cheaper (and avoids over‑updating on the same batch). Algorithm 1 keeps $\mu$ as a knob if you want to experiment with multiple inner updates, but to reproduce the paper’s results use $\mu = 1$.

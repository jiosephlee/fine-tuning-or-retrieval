\title{Blogs about the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

# Do the Numbers Back It Up? Results Across 13 Tabular Datasets

## TL;DR
FeatLLM treats a large language model (LLM) as an automatic feature engineer: it prompts the LLM to produce human-readable rules, turns those rules into binary features, and trains a very simple downstream model on those features. Across 13 tabular datasets from domains such as healthcare, finance and a few synthetic tasks, FeatLLM consistently ranks first or second and, on average, improves AUC by about 10% over recent LLM-based baselines like TabLLM and STUNT. With only a handful of labeled examples (e.g., 4 shots) it reaches performance comparable to conventional tabular models trained with many more labels (e.g., 32 shots). Ablations show that tuning the downstream weights, the two-step reasoning guidance in prompts, and ensembling all matter.

## What FeatLLM actually does (short)
FeatLLM reallocates the role of the LLM away from per-sample prediction and toward rule discovery. The pipeline is:

- Prompt the LLM with three structured pieces: (1) basic task and feature descriptions plus a few serialized examples, (2) a two-step reasoning instruction that asks the model first to state general prior knowledge about feature–label relationships and then to use examples to derive concrete rules, and (3) response-format instructions so the LLM emits parseable rules.
- Parse the LLM-generated rules into executable code (the system uses the LLM again to emit a parsing function) and apply those rules to produce binary features (one per rule).
- Fit a simple per-class linear model on the binary rule-features. The model uses non-negative weights so each rule only increases class evidence:
  $$
  \text{logit}_k^i = \max(\mathbf{w}_k, 0)\cdot \mathbf{z}_k^i,\qquad
  \mathbf{p}^i = \text{Softmax}\big([\text{logit}_1^i,\dots,\text{logit}_c^i]\big),
  $$
  where $\mathbf{z}_k^i\in\{0,1\}^R$ are rule-features for sample $i$ and class $k$.
- Repeat the entire rule-generation + fitting process $T$ times with bagging (random feature/instance subsets, randomness via LLM temperature and demo order), then average predicted probabilities from the $T$ models.

This design avoids calling the LLM at inference time per sample: once rule-features and the simple model are learned, predictions are cheap.

## Experimental setup — what was tested
The authors evaluate on 13 datasets covering standard tabular benchmarks and tasks that are unlikely to be memorized by the LLM (including two UCI datasets added after Sept 2023 and two synthetic tasks). Representative datasets include Adult, Bank, Credit-g, Diabetes, Heart, Myocardial, Communities, Cultivars, NHANES, and two synthetic datasets (Sequence-type and Solution-mix).

Baselines include classical tabular methods (Logistic Regression, XGBoost, Random Forest), few-shot / unlabeled-data methods (SCARF, STUNT, TabPFN), and other LLM-based approaches (in-context prompting, TABLET, TabLLM). FeatLLM uses GPT-3.5 (gpt-3.5-turbo-0613) in the experiments. Key implementation hyperparameters used in reported results were $T=20$ ensembles and $R=10$ rules per class; LLM temperature was 0.5 and the linear model was trained with Adam at learning rate 0.01 for 200 epochs.

## Headline numerical findings
- Average improvement over recent LLM baselines: FeatLLM outperforms TabLLM and STUNT by about 10% on average in AUC across the 13 datasets reported in the paper.
- Consistency: FeatLLM is either the top performer or the runner-up across datasets and low-shot settings.
- Shot-efficiency: With just 4 labeled examples (4-shot), FeatLLM achieves performance comparable to conventional tabular baselines trained with 32 labeled examples.
- Robustness to many features and prompt-size limits: by using feature bagging and ensembling, FeatLLM works even on datasets with hundreds of attributes where serializing full tables into a single prompt would be infeasible for other LLM-based methods.

## Why these gains happen (evidence from analyses)
The paper contains multiple analyses that explain why FeatLLM works well in low-shot tabular settings:

- Prompt structure and reasoning guidance matter. The two-step reasoning instruction (general prior knowledge first, then example-based rule derivation) helps the LLM avoid spurious correlations and focus on plausible causal or domain-relevant relations.
- Feature construction plus light tuning is powerful. Many LLM-derived rules are individually informative: a majority of generated rule-features have AUROC > 0.5 with the target label before tuning. After fitting the linear model, irrelevant rules are down-weighted or effectively filtered (the authors used a weight-threshold of 0.1 to identify weak rules).
- Ensembling & bagging add robustness. Repeating rule discovery and fitting with randomized subsets reduces sensitivity to any single erroneous rule-set. The authors observe that performance improves as $T$ increases, with diminishing returns around $T\approx 20$.
- Parsing robustness: instead of brittle hand-coded parsers for natural-language rules, the system asks the LLM to output a small parsing function, then executes it to create features. That eliminates much of the parsing brittleness.

## Ablations — which components are essential
The authors ran ablations removing four components: (1) tuning the linear model (i.e., summing binary features instead of learning weights), (2) the ensemble step, (3) providing explicit feature descriptions in the prompt, and (4) the Step-1 general-reasoning instruction. In all ablations AUC dropped. Two notable patterns emerged: the benefit of weight tuning grows with more labeled shots (as expected), whereas the explicit prior-knowledge / feature-description guidance and the Step-1 reasoning are particularly important in the extremely low-shot regime.

## Robustness to spurious features and runtime
To test sensitivity to irrelevant columns, the authors appended random columns from Adult to the Heart dataset and measured performance as more unrelated columns were added. FeatLLM showed the smallest degradation compared to baselines; only about 1–2% of generated rules came from noisy columns, indicating the two-step prompting helps the LLM ignore irrelevant features.

On efficiency, FeatLLM has a practical advantage: rule discovery requires a modest number of LLM API calls (the paper reports about 30 API queries for training in their setup) and no per-sample LLM calls at inference. In contrast, many LLM-based baselines must query the LLM per test sample (much slower and more expensive). In the runtime comparisons on the Adult dataset, FeatLLM required a small amount of compute and had inference latency comparable to classical models; other LLM-based methods had much higher inference costs. (In the experiments one A100 GPU was used as the default; TabLLM required 4 A100s for model-parallel training in that reproduction.)

## Practical takeaways and limitations
- If you need strong few-shot tabular performance and only have inference/API access to an LLM, FeatLLM is a practical, cost-effective strategy: it needs only API access, produces interpretable rule-features, and avoids per-sample LLM inference.
- The method is especially attractive when labeling is expensive (healthcare, finance) or when you want interpretable, rule-like features that can be reviewed by domain experts.
- Caveats: FeatLLM is developed and evaluated for low-shot regimes. The authors note that LLM priors can dominate predictions (which is helpful when priors are right and harmful when priors are biased or wrong), so careful evaluation of bias and provenance of LLM knowledge is important before deployment. Extending the approach to larger labeled datasets and richer feature types is listed as future work.

## Bottom line
Yes — the numbers presented in the paper support the claim that LLMs used as feature engineers can materially improve few-shot tabular learning. FeatLLM combines structured prompting, rule extraction, and a cheap downstream model to get strong AUCs across diverse tasks, outperforming recent LLM-based baselines by roughly 10% on average while keeping inference fast and practical. The code is available at https://github.com/Sungwon-Han/FeatLLM for anyone who wants to reproduce or extend the experiments.

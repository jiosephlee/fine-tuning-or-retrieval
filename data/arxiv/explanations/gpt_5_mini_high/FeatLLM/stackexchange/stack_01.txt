\title{Stack Exchange of the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

### How do class-specific positive-only weights avoid penalizing wrong classes in multi-class FeatLLM?
Question:
In FeatLLM, each class $k$ has its own binary rule features $\mathbf{z}_k$ and a linear logit $\text{logit}_k = \max(\mathbf{w}_k, 0) \cdot \mathbf{z}_k$, with a softmax over classes. Since weights are forced non-negative via $\max(\cdot,0)$ and there is no bias term, how does the model express negative evidence for a class? If a sample satisfies several rules from multiple classes, it seems like logits can only go up for those classes. Does this harm separability or calibration, especially when classes share overlapping rules?
Answer:
Short answer: FeatLLM does not need explicit negative weights to represent “negative evidence.” The model uses class-specific positive-only scores and a softmax, so anything that looks like negative evidence for class A is implemented either by (a) positive evidence for one or more competing classes (which reduces A’s softmax probability), or (b) by the training procedure zeroing out (i.e., ignoring) rules for A that are harmful. This is an intentional inductive bias in the paper: rules generated by the LLM are treated as positive indicators for their target class, and competition across classes plus weight tuning (and ensembling) handle overlap and spurious rules.

Why that works (brief math + intuition). The paper uses
$$
\text{logit}_k = \max(\mathbf{w}_k,0)\cdot \mathbf{z}_k,\qquad
\mathbf{p}=\mathrm{Softmax}(\{\text{logit}_k\}_k).
$$
Softmax is a relative (competitive) operator: increasing logit of class $j$ decreases the probability of class $k$ for every $k \neq j$. Concretely,
$$
\frac{\partial p_k}{\partial \text{logit}_j} = p_k(\mathbf{1}_{j=k}-p_j),
$$
so a positive boost to some other class $j$ reduces $p_k$. Thus a feature that is a positive indicator for class $B$ automatically acts as “negative evidence” for class $A$ because the probability mass shifts away from $A$.

How the model handles rules that should discourage a class. The LLM produces separate binary features $\mathbf{z}_k$ for each class $k$. If the same pattern appears in multiple classes’ rule-sets those become distinct features (one per class) and the downstream linear weights $\mathbf{w}_k$ are learned per feature/class. During optimization (cross-entropy on the softmax) the model can (and in practice does) reduce the contribution of unhelpful or misleading rules: the pre-projection weights can be driven to values that produce $\max(\cdot,0)$ near zero, effectively turning off that rule for that class. The paper documents this behavior (they show many rules become low-weight after tuning and they threshold to filter out weak rules), and their ablations report that this tuning step materially improves performance.

When overlapping rules hurt separability. It is true that if the feature set contains a rule that is equally (and strongly) a positive signal for two classes, and there are no other discriminative features, the model will be ambiguous — but that is a limitation of the feature set, not a bug of the positive-weight projection. In practice FeatLLM mitigates this in three ways that the paper emphasizes: prompts explicitly ask the LLM to produce class-distinguishing rules (so rules tend to be discriminative), weight tuning can downweight spurious features, and ensemble+bagging reduce the impact of occasional bad rules. Their experiments (ablation and the spurious-correlation test) show these mechanisms give robust separability in the few-shot regimes they study.

A few practical consequences to keep in mind. The positive-only projection is an explicit inductive bias: it enforces that rules act as supportive evidence for classes, not as subtractive signals. That simplifies interpretation and helps avoid fragile “negatively weighted” rules learned from tiny data, but it does reduce expressiveness compared with an unconstrained linear model (which could assign negative weights directly). The paper’s empirical results indicate this bias is helpful for the low-shot tabular problems they target, but if you expect many genuine “anti-class” signals that are not naturally captured as positive evidence for other classes, you might consider alternative architectures (this is outside the paper’s scope).

Takeaway: negative evidence in FeatLLM is handled indirectly — by competition in the softmax (other classes’ positive evidence) and by turning off harmful class-specific rules during training. This is an intentional design choice that the paper shows works well in practice for few-shot tabular tasks.

\title{A Textbook about the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

Chapter 2: Background: Few-Shot Learning on Tabular Data

# Definition of $k$-shot learning and evaluation with minimal labeled data
Few-shot learning refers to setting up a supervised learning problem where only a very small number of labeled examples are available to train a model. In the notation used throughout the source paper, we consider a tabular dataset
\[
\mathcal{D} = \{(\mathbf{x}^i, \mathbf{y}^i)\}_{i=1}^{N},
\]
where each $\mathbf{x}^i\in\mathbb{R}^d$ (or a mixed-type vector over $d$ attributes) and $\mathbf{y}^i$ is the corresponding label. In a $k$-shot experiment one randomly samples only $k$ labeled examples (with $k < N$) from $\mathcal{D}$ to form the training set used to learn the model. The goal is to obtain models that generalize from these very small labeled sets.

Because the training sets are so small, evaluation practices must reflect high variance due to sampling. The paper evaluates few-shot methods by repeating experiments with different random choices of the $k$ labeled samples and reports averaged performance (and standard deviation) across runs. It also uses cross-validation procedures to choose training hyperparameters and to reduce variance in model selection (see the section on cross-validation below). Across the paper’s experiments, comparisons are made at multiple shot levels (for example $k=4,8,16,32$), and a striking empirical finding is that a well-designed few-shot method can sometimes achieve performance with $4$ shots comparable to baselines that required $32$ shots.

# Heterogeneity in tabular features: numerical, categorical, mixed types
Tabular data commonly contains a heterogeneous mix of feature types: continuous numeric measurements, categorical attributes with a finite set of labels, ordinal fields, and other structured columns. The source paper emphasizes that feature descriptions that include value type and (optionally) a short definition are important when a model — particularly a language model used to reason about features — must interpret columns correctly. For categorical variables the paper gives the example of including explicit lists of possible categories in the feature description so downstream processing (such as rule extraction) can form well-typed conditions.

This heterogeneity matters in practical model design. The paper points out two concrete consequences. First, when using natural-language interfaces (for example, serializing rows for an LLM), the representation must preserve type information so the reasoning engine does not produce type-mismatched rules (e.g., comparing a textual category with a numerical threshold). Second, some datasets used in the experiments (for example, “Communities” and “Myocardial”) have over one hundred attributes; this large attribute count amplifies the challenges of working with heterogeneous columns because long serialized representations push against prompt/context-size limitations of language models. In short, mixed feature types and large numbers of columns create both semantic and practical constraints that few-shot learners must handle.

# Risks in low-data settings: overfitting and spurious correlations
With only a handful of labeled examples, two central risks dominate: overfitting and learning spurious correlations. The paper explicitly notes that learning from small numbers of labels increases the chance that a model will latch onto coincidental associations present in the small training set rather than real predictive structure. This is a primary motivation for bringing in additional sources of inductive bias (for example, prior knowledge encoded in pretrained models or synthetic priors) or additional unlabeled data.

The authors illustrate these risks experimentally. They run an experiment on the Heart dataset where they attach randomly selected columns from an unrelated dataset (Adult) to introduce noisy, irrelevant features. As the number of unrelated columns increases, many baseline methods show substantial performance degradation. The proposed FeatLLM approach degrades far less; the paper attributes this to the system’s explicit stage of inferring relationships between features and targets (leveraging prior knowledge) and extracting rule-based features only from columns judged relevant. Empirically, rules based on noisy columns accounted for only about 1–2% of the total rules generated. The paper also cautions that FeatLLM is not immune: if truly related but misaligned columns are attached, the system can still adopt spurious causal beliefs (an observation discussed in the appendix).

# Semi/unsupervised tabular methods: VIME, SubTab, TabNet; contrastive approaches like SCARF
A common strategy to alleviate label scarcity is to exploit unlabeled data through semi-supervised or self-supervised objectives. The paper groups several prior directions under this umbrella. One approach is to use large amounts of unlabeled data with carefully designed augmentations to enable semi-supervised learning; examples cited include methods such as SubTab and VIME. Another family uses self-supervised reconstruction objectives: the method listed as TabNet is given as an example of approaches that mask or corrupt parts of the data and train the model to reconstruct the masked portions. A different self-supervised strategy is to design augmentations and then apply contrastive learning objectives; SCARF is cited as representative of contrastive-style approaches for tabular data.

Two practical caveats are raised in the paper. First, leveraging unlabeled data assumes that such data is available and appropriate for the target task, which may not hold in many real-world settings — the paper explicitly notes that obtaining large quantities of unlabeled data may be infeasible. Second, despite the promise of these techniques, the authors remark that these unsupervised and semi-supervised strategies have not been especially effective in the strict few-shot regimes considered in the paper.

# Transfer and synthetic priors: TransTab for column semantics; TabPFN for learned Bayesian priors
Another way to inject prior knowledge into few-shot tabular learning is to learn transferable structure across many different tables or to pretrain on synthetic data whose distributional variety encodes useful inductive biases. The paper discusses two approaches in this direction.

TransTab learns models on a broad range of tabular datasets with the explicit goal of capturing semantic relationships between columns by using column names (not just raw values). This cross-table transfer of column semantics enables zero-shot or few-shot generalization to new tables by leveraging the learned mapping from column metadata to predictive structure.

TabPFN follows a different idea: instead of collecting many real tables, it mixes a variety of synthetic distributions to construct diverse pretraining tasks and uses these to train a Bayesian neural network. After pretraining, TabPFN performs inference on a target task by providing both the training and test samples to the network without further training; the synthetic priors encoded during pretraining help the model generalize in few-shot settings. The paper reports that such synthetic-prior approaches can surpass traditional tree-based methods and are beneficial in few-shot regimes.

The paper also mentions LLM-based transfer and tuning approaches (for example TabLLM), which apply parameter-efficient tuning schemes (like IA3) to adapt language models to tabular prediction tasks when possible. Practical constraints arise here as well: some high-performing LLMs do not provide training APIs or public checkpoints and therefore cannot be fine-tuned in this way.

# Why standard augmentations are hard for tabular data
A recurring observation in the paper is that standard augmentation strategies that work well in other modalities (images, audio, text) are difficult to apply to tabular data. The central reason given is heterogeneity: tabular datasets contain a mixture of feature types and semantics, and there is no single, universally appropriate transformation that preserves label semantics across all columns and datasets. Because augmentations must respect the semantics of each column (for example, categorical vs. continuous, lawful ranges, domain constraints), it is challenging to design augmentations that are broadly applicable. The paper therefore argues that augmentation-based semi-supervised methods have limited success in strict few-shot settings and that alternative ways of importing inductive bias (transfer learning, synthetic priors, or leveraging pretrained language models’ prior knowledge) are worth pursuing.

# Common metrics (AUC/AUROC) and cross-validation strategies in low-shot
In the experimental methodology of the paper, the main evaluation metric reported is the area under the receiver operating characteristic curve (AUC / AUROC). For each dataset and shot level the authors report averaged AUC values (and standard deviations) across multiple random repetitions to capture sampling variability inherent in few-shot settings.

Model selection and hyperparameter tuning in these low-data regimes are performed using cross-validation. The paper uses $k$-fold cross-validation both to select the number of training epochs (for the simple downstream models) and to perform grid search for conventional baselines. Practical choices for $k$ in these experiments are conservative (for example $k=2$ or $k=4$) to guarantee that every fold’s training set contains at least one example of each class when only a handful of labeled samples are available. These cross-validation practices help stabilize hyperparameter choices and reduce the risk of overfitting the small labeled training sets.

Closing remark
The paper situates few-shot tabular learning as a setting where model inductive bias and external priors matter as much as the supervised signal. Heterogeneous columns, scarcity of labeled examples, and the difficulty of designing universal augmentations make conventional few-shot recipes less effective for tabular data, motivating approaches that bring additional structure — whether via unlabeled data, transfer across tables, synthetic priors, or leveraging pretrained language models’ knowledge — while carefully validating using AUC and cross-validation procedures appropriate for low-shot regimes.

\title{A Textbook about the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

Chapter 8: Modeling Class Likelihood with Simple, Constrained Models

# Per-class binary vectors $\mathbf{z}_k^i \in \{0,1\}^R$ from rule satisfaction
FeatLLM converts the LLM-generated rules into a compact, uniform representation that a light-weight classifier can use. For each target class $k$ the LLM produces $R$ human-readable rules; after parsing and executing those rules on an input sample $\mathbf{x}^i$, each rule yields a Boolean indicator: the rule is either satisfied (1) or not (0). Collecting these indicators for class $k$ gives the per-sample, per-class binary vector
\[
\mathbf{z}_k^i \in \{0,1\}^R,
\]
whose $r$th entry is 1 exactly when rule $r$ for class $k$ holds on $\mathbf{x}^i$.

This representation has several practical consequences. First, it homogenizes heterogeneous raw columns (numeric, categorical, text) into a single binary feature type, which simplifies downstream modeling and helps avoid type mismatch issues. Second, by building rule sets per class, the representation focuses predictive capacity on features that are directly interpretable as criteria for particular labels; a single sample therefore comes to be represented by up to $c$ such binary vectors (one per class), or equivalently by the concatenation of all class-rule indicators (total dimension $cR$). Because the rules are generated once and parsed into executable code, these binary features are deterministic at inference time and free of per-sample LLM queries.

# Non-negative weight vectors and dot-product scoring per class
Once rules are converted into binary indicators, FeatLLM assigns a trainable non-negative weight vector to each class, denoted $\mathbf{w}_k$. The per-class score (logit) for sample $i$ is computed by a dot product between the weight vector and the binary rule indicators for that class, with an elementwise projection that enforces non-negativity:
\[
\text{logit}_k^i \;=\; \max(\mathbf{w}_k, 0)\cdot \mathbf{z}_k^i .
\]
This is a linear scoring rule without an additive bias term; each satisfied rule contributes additively to the class score and its contribution is scaled by the corresponding learned weight. The max operator is applied elementwise, i.e., $\max(\mathbf{w}_k,0)$ clamps any negative parameter values to zero before the dot product.

Interpreting the parameters, each coordinate of $\mathbf{w}_k$ represents the strength or importance of the corresponding rule for predicting class $k$. The dot product sums those strengths for all rules that the sample satisfies, producing a single scalar score per class. Separate weight vectors for each class allow the same rule text (or analogous rule forms) to play different roles for different classes if the system happens to produce rules that overlap between classes.

# Softmax over class scores to obtain probabilities
The model converts the collection of per-class logits into a probability distribution over classes via the softmax function. If there are $c$ classes, and for sample $i$ we have logits $\{\text{logit}_1^i,\dots,\text{logit}_c^i\}$, then the class probability vector is
\[
\mathbf{p}^i \;=\; \text{Softmax}\bigl([\text{logit}_1^i,\dots,\text{logit}_c^i]\bigr),
\]
so that $p_k^i = \exp(\text{logit}_k^i)\big/\sum_{j=1}^c \exp(\text{logit}_j^i)$.

In FeatLLM the final prediction can also incorporate an ensemble across multiple independent trials (different LLM rule generations and bagging choices). If trial $t$ produces a probability vector $\mathbf{p}^i[t]$, the ensemble average used for final decision-making is
\[
\overline{\mathbf{p}}^i \;=\; \frac{1}{T}\sum_{t=1}^T \mathbf{p}^i[t],
\]
i.e., FeatLLM averages the per-trial class probability vectors rather than averaging raw logits. Averaging probabilities is the approach described in the paper for combining the outputs of multiple independently trained linear scorers built from distinct rule-sets.

# Training with cross-entropy, Adam optimizer, and k-fold early stopping
FeatLLM learns the weight parameters $\{\mathbf{w}_k\}$ by fitting the simple constrained linear model to the few labeled examples available. The learning objective is the standard multi-class cross-entropy loss computed from the softmax probabilities:
\[
\mathcal{L}(\mathbf{W}) \;=\; -\sum_{i=1}^{N_{\text{train}}}\sum_{k=1}^c y_k^i \log p_k^i,
\]
where $y_k^i$ is the one-hot indicator for the true class of sample $i$ and $\mathbf{W}$ denotes the collection of all class weight vectors. Optimization is performed with the Adam optimizer; in the experiments reported in the paper the learning rate was set to $0.01$ and training was run for up to $200$ epochs. To avoid overfitting in the few-shot regime, k-fold cross-validation is used to select the optimal number of epochs (i.e., to perform early stopping): the training process monitors validation performance across folds and selects the epoch giving best generalization.

These choices keep the downstream fitting procedure extremely cheap compared to tuning or querying a large language model per example. Because the forward computation is a small dot product per class and the number of parameters is $cR$, training is fast even when repeated across trials for ensemble construction. The paper reports that this light-weight tuning step meaningfully improves performance versus leaving all rule-weights equal (see the ablation discussion below).

# Why non-negativity aligns with rule semantics and aids interpretability
A central design decision in FeatLLM is to enforce non-negativity of the rule weights. This constraint has a direct semantic rationale: the rules are generated by the LLM as "criteria" or conditions associated with an answer class. By construction, a rule intended to support class $k$ should, when satisfied, increase evidence for that class rather than decrease it. Clamping weights to be non-negative enforces this intuition: every rule can only add non-negative evidence to its associated class's score.

Beyond semantic alignment, the non-negativity constraint aids interpretability and downstream filtering. The magnitude of each learned non-negative weight directly orders rules by importance: large weights point to highly predictive rules, small or (clamped) zero weights indicate rules that are uninformative or possibly spurious. In the paper's analyses the authors use this property to quantify the quality of generated features and to filter out weak rules (they reported using a threshold of around $0.1$ on learned weights in one diagnostic experiment to mark and remove low-importance rules). Because the contributions are additive and non-negative, inspecting the weight vector is a straightforward way to explain which rules mattered for a particular class.

Finally, in the low-shot setting the non-negativity constraint limits the hypothesis space in a way that matches the intended semantics of the engineered features. That structural regularization—choosing a model family that encodes prior knowledge about what rules should mean—helps the simple linear classifier generalize from very few labeled examples.

# Alternatives and ablations: simple rule counts vs learned weights; logistic regression variants; regularization
The paper evaluates several ablations that illuminate the role of learned non-negative weights and other components. The primary ablation that isolates the effect of weight learning is called "-Tuning": instead of learning per-rule weights, the model simply sums the binary indicators for each class and uses that sum as the class logit. Concretely, this corresponds to setting every weight equal to 1 and computing $\text{logit}_k^i = \mathbf{1}\cdot\mathbf{z}_k^i$. The reported results show that removing the tuning step degrades performance across datasets; importantly, the benefit of learning weights grows as the number of labeled shots increases, because with more labels one can estimate which rules are truly more important and assign them larger weights.

The model used in FeatLLM is, mathematically, a constrained linear classifier followed by softmax. In an unconstrained formulation this is equivalent to multinomial logistic regression (a linear map to logits plus softmax). FeatLLM’s choices differ in two ways: it omits an additive bias term, and it enforces non-negativity on rule weights. The paper does not report experiments using other variants such as unconstrained logistic regression on the rule features or explicit $L_2$ regularization of the rule weights; instead it relies on k-fold cross-validation for epoch selection (early stopping), the positivity constraint, and ensembling with bagging to control variance. Removing the ensemble ("-Ensemble") is another ablation reported in the paper and it consistently lowers performance, showing that repeated, diverse rule generation plus averaging yields more robust predictors.

Finally, the paper examines ablations that affect rule generation (not the downstream linear model): omitting the feature descriptions or the first reasoning step in the prompt both reduce the predictive quality of generated rules and thus downstream performance. These results emphasize that model choices (counting vs learned weights) and prompt/design choices (how rules are generated) both contribute to the final behavior. In practice, FeatLLM’s combination—LLM-generated, parsed binary rules together with a small non-negative linear model trained by cross-entropy—strikes a balance between interpretability, semantic alignment, and empirical accuracy in the few-shot tabular learning problems evaluated by the authors.

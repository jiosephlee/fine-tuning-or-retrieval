\title{A Textbook about the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

Chapter 5: FeatLLM Pipeline: End-to-End Overview

# Problem formulation
We consider a supervised tabular classification problem. Let the labeled dataset be
\[
\mathcal{D} = \{(\mathbf{x}^i, \mathbf{y}^i)\}_{i=1}^{N},
\]
where each input $\mathbf{x}^i$ is a $d$-dimensional vector of table attributes and $\mathbf{y}^i$ is the corresponding class label drawn from a finite set of classes (say $c$ classes). The dataset is accompanied by natural-language feature names and, optionally, short definitions; we denote the feature name set by $F = \{f_j\}_{j=1}^d$. Feature types can be heterogeneous (numerical, categorical, etc.), and the feature descriptions in $F$ typically mention these types and possible categories when appropriate.

In the few-shot setting studied by FeatLLM, only a small number $k$ of labeled examples (with $k \ll N$) are available to build the model. Concretely, for $k$-shot experiments we randomly select $k$ labeled samples from $\mathcal{D}$ as the training set and use the rest for evaluation. The goal is to leverage the LLM’s prior knowledge and the small set of labeled examples to produce features and a lightweight downstream learner that together deliver accurate predictions in this low-data regime.

# Overall stages: prompting for rules, parsing rules, new feature construction, simple modeling, ensembling
FeatLLM decomposes the end-to-end workflow into a small number of conceptually distinct stages. The pipeline is designed so that the LLM is used to discover human-interpretable decision criteria (rules) only during feature-discovery time; a lightweight model then uses these discovered features at inference without further LLM calls. The stages are:

1. Prompting the LLM to produce rules. The LLM is given a structured prompt that contains: (a) basic information about the task and the features, (b) a reasoning instruction that guides how the LLM should combine its prior knowledge with the few-shot examples, and (c) response-format instructions that constrain the syntactic form of the rules the LLM should output. The output of this stage is a set of natural-language rules for each class (e.g., conditions such as “age > 60 and blood_pressure > 140 implies class = X”).

2. Parsing rules into executable checks. The LLM’s rule text may vary in wording and syntax. FeatLLM uses the LLM again as a code writer: it prompts the LLM to translate the natural-language rules into a small program (Python functions) that, given a sample $\mathbf{x}$, computes whether each rule is satisfied. The generated code is executed (e.g., via Python’s \texttt{exec()}) to obtain deterministic rule-evaluation routines.

3. New feature construction. Each rule becomes a binary feature. If there are $R$ rules per class and $c$ classes, then for a given sample $\mathbf{x}^i$ the pipeline produces binary vectors $\mathbf{z}_k^i \in \{0,1\}^R$ for $k=1,\dots,c$, where the $r$-th entry of $\mathbf{z}_k^i$ is 1 if rule $r$ for class $k$ is satisfied on $\mathbf{x}^i$, and 0 otherwise. These binary features summarize the LLM’s class-wise criteria for membership.

4. Simple modeling (learning importance of rules). A lightweight, conventional ML model (the FeatLLM paper uses a linear model without bias as an example) is trained on the new binary features to estimate class likelihoods. Each class $k$ has an associated weight vector $\mathbf{w}_k \in \mathbb{R}^R$ indicating how important each rule is. The weights are learned using the available $k$-shot labeled examples by optimizing cross-entropy loss.

5. Bagging and ensembling. The entire process (steps 1–4) is repeated $T$ times with randomized prompts and subsampling (bagging) to obtain an ensemble of models. The predicted class probabilities from the $T$ models are averaged to form the final prediction. Bagging reduces prompt length per trial (by selecting subsets of features or instances) and increases robustness by combining diverse rule sets.

These stages create an efficient separation between rule discovery (LLM-assisted, training-time) and run-time prediction (purely programmatic feature evaluation plus a lightweight statistical model).

# Where LLMs are used (training-time feature discovery) vs not used (inference)
FeatLLM deliberately confines the use of LLMs to the feature-discovery portion of the pipeline. Specifically, LLMs are invoked to (1) reason about the task and propose human-readable rules for each class, and (2) translate the natural-language rules into executable parsing code. Both uses are performed during the training or preparation stage and typically involve only a modest number of LLM API calls (the paper reports that the overall training process can be carried out with a small number of queries that can be parallelized).

At inference time, for each new sample FeatLLM does not call the LLM. Instead, the sample is fed into the locally-executable rule functions (the code generated in parsing) to compute the binary rule features, and the learned lightweight model (the non-negative linear weights and softmax) is used to obtain class probabilities. This design eliminates the need for one LLM call per test sample, dramatically reducing inference latency and API cost compared to end-to-end LLM approaches that must serialize each test row into the prompt and query the LLM for every prediction. It also removes the requirement to fine-tune the LLM — FeatLLM operates with API-only access and relies on in-context prompting for discovery rather than parameter tuning.

# Few-shot serialization format: "f_j is x_j. ... Answer: y"
FeatLLM uses a simple, consistent serialization format for example demonstrations included in the prompt. Each example $(\mathbf{x}^i,\mathbf{y}^i)$ is converted into a compact textual description of the form used in previous LLM-based tabular studies. In the paper this is written as:
\[
\text{Serialize}(\mathbf{x}^i,\mathbf{y}^i, F) =
\quad ``\ f_1\ \text{is}\ \mathbf{x}^i_1.\ \ldots\ f_d\ \text{is}\ \mathbf{x}^i_d.\ \ \text{Answer:}\ \mathbf{y}^i\ ".
\]
In words, this means that each feature name $f_j$ is written followed by the observed value $\mathbf{x}^i_j$, separated by periods, and the example ends with a labeled answer. The prompt’s “basic information” portion includes these serialized examples (the few-shot demonstrations), the task description phrased as a question, and the feature descriptions (including type information and category examples for categorical variables). This consistent format helps the LLM interpret the example rows and relate feature names to values when composing rules.

# Non-negative linear scoring per class and softmax probabilities
After rule-derived binary features are produced for a sample, FeatLLM scores class likelihoods with a simple, interpretable linear scoring function per class. Denote by $\mathbf{z}_k^i \in \{0,1\}^R$ the binary vector of rule-satisfaction indicators for class $k$ on sample $i$, and by $\mathbf{w}_k \in \mathbb{R}^R$ the corresponding trainable weight vector. The model computes a class logit per class $k$ as
\[
\text{logit}_k^i \;=\; \max(\mathbf{w}_k, 0)\cdot \mathbf{z}_k^i,
\]
where $\max(\mathbf{w}_k,0)$ denotes the element-wise ReLU projection that enforces non-negativity of effective weights. The vector of logits across classes is converted to class probabilities via the softmax:
\[
\mathbf{p}^i \;=\; \text{Softmax}\big([\text{logit}_1^i, \ldots, \text{logit}_c^i]\big).
\]

Two design choices are important to understand. First, each class has its own rule set and weight vector, so a rule that is targeted at recognizing class $k$ contributes only to $\text{logit}_k$. Second, the weights are projected to the non-negative orthant before dotting with binary features. This projection ensures that satisfying a rule cannot reduce the logit for its associated class, which matches the interpretation of rules as affirmative evidence for class membership. The weights are learned from the few-shot labeled examples by minimizing the cross-entropy loss between $\mathbf{p}^i$ and the ground-truth labels. In practice the training is done with a small optimizer such as Adam (the paper uses learning rate $0.01$ and trains for a fixed number of epochs with cross-validation for early-selection), which is inexpensive because the model dimensionality is modest ($R$ rules per class).

Training the simple linear model performs two crucial functions: it calibrates the relative importance of rules, and it filters out unhelpful or spurious rules by assigning them small weights. In experiments this tuning step improves performance compared to naive counting of satisfied rules.

# Bagging and ensembling to mitigate prompt length and improve robustness
FeatLLM uses repetition with randomization and subsampling to both reduce per-prompt length (thus handling datasets that would otherwise exceed the LLM context window) and to improve robustness to imperfect rule generation.

The method runs $T$ independent trials. In each trial the prompt to the LLM is varied by (a) randomizing the order of the few-shot demonstrations (the order can affect LLM in-context behavior), (b) sampling a subset of features or instances (bagging) to keep prompt size small when the original table is wide, and (c) using stochastic decoding (higher temperature) so that the LLM produces diverse rule sets across trials. Each trial yields a set of rules, parsing code, the binary-feature construction, and a trained weight vector $\{\mathbf{w}_k^{[t]}\}_{k=1}^c$ for that trial $t$.

At inference the $T$ models produce $T$ probability vectors $\{\mathbf{p}^i_{[t]}\}_{t=1}^T$ for a sample $\mathbf{x}^i$, and FeatLLM aggregates them by averaging:
\[
\bar{\mathbf{p}}^i \;=\; \frac{1}{T}\sum_{t=1}^T \mathbf{p}^i_{[t]}.
\]
Averaging probabilities combines diverse but complementary rule-sets, yielding two main benefits emphasized in the paper. First, if some trials produce incorrect or noisy rules, correct rules from other trials can compensate, producing a more reliable ensemble prediction (this leverages LLM self-consistency). Second, bagging keeps each single prompt within context-length constraints even for very wide tables: rather than trying to ask the LLM to summarize all $d$ columns at once, FeatLLM asks it to reason about a subset in each trial and then aggregates.

In the empirical setup of the paper, commonly used hyperparameters are $T=20$ trials and $R=10$ rules per class, and the LLM decoding temperature and prompt construction are tuned to encourage useful diversity without excessive noise. The authors report that as $T$ grows performance improves but plateaus (so moderate ensemble sizes suffice in practice), and that $R=10$ achieves a good balance between expressivity and overfitting in low-shot regimes.

--- 

This end-to-end description shows how FeatLLM converts a few labeled rows and feature descriptions into programmatically-evaluable rule features, learns a small non-negative linear scoring model on top, and combines multiple such learners via bagging and ensembling. The result is a system that leverages LLM prior knowledge for feature engineering while keeping inference cheap and deterministic (no per-sample LLM calls), and that uses standard supervised learning to calibrate and filter the automatically-generated features.

\title{Stack Exchange of the Paper: "DeepSeekMath: Pushing the Limits of Mathematical Reasoning in Open Language Models"}

### Can the unified paradigm (Equation 9) be used to derive DPO as a special case of PPO/GRPO?
Question:
The authors claim that supervised fine‑tuning, RFT, DPO, PPO, and GRPO can all be expressed with gradient coefficient \(GC_{\mathcal{A}}\). I would like to see an explicit derivation showing how DPO’s pairwise loss fits into this framework—what choices of data source, reward function \(\pi_{rf}\), and algorithm produce the DPO gradient coefficient? This would help me understand the connections between these methods.
Answer:
Below is a step‑by‑step sketch of how the pair‑wise Direct Preference Optimization (DPO) loss emerges as a special‑case of the **unified gradient‑coefficient formulation** presented in Equation $(9)$ of the DeepSeekMath paper.  
The goal is to identify which **data source** $\mathcal D$, which **reward function** $\pi_{\text{rf}}$ (the “reference” or “reward” policy), and which **algorithmic processing** $\mathcal A$ produce exactly the DPO gradient coefficient $GC_{\text{DPO}}$.

---

### 1. The unified gradient‑coefficient view

Equation $(9)$ writes the gradient of any training objective $\mathcal J_{\mathcal A}$ as  

\[
\nabla_{\theta}\mathcal J_{\mathcal A}(\theta)
=\mathbb{E}_{(q,o)\sim\mathcal D}
\Bigl[\frac{1}{|o|}\sum_{t=1}^{|o|}
GC_{\mathcal A}(q,o,t,\pi_{\text{rf}})\,
\nabla_{\theta}\log \pi_{\theta}(o_t\mid q,o_{<t})\Bigr].
\tag{9}
\]

The three ingredients are:

* **Data source $\mathcal D$** – a distribution over question–output pairs.  
* **Reward function / reference policy $\pi_{\text{rf}}$** – supplies a scalar signal that the algorithm turns into a coefficient.  
* **Algorithm $\mathcal A$** – the rule that maps the raw reward into $GC_{\mathcal A}$.

When we instantiate these three components appropriately we recover the known losses (SFT, RFT, PPO, …).  

---

### 2. What DPO actually optimises

The original DPO paper (Huang et al., 2024) maximises the *pairwise* likelihood  

\[
\max_\theta \;\; 
\log\sigma\!\Bigl(r_\varphi(q,y^+) - r_\varphi(q,y^-)\Bigr)
+ \log\frac{\pi_\theta(y^+|q)}{\pi_\theta(y^-|q)},
\tag{D}
\]

where  

* $y^+$ is a preferred response, $y^-$ a dispreferred one (both sampled from the current policy or from an offline policy),  
* $r_\varphi(q,\cdot)$ is a learned reward model (the “preference model”), and  
* $\sigma(z)=1/(1+e^{-z})$ is the sigmoid.

Differentiating $(D)$ with respect to $\theta$ gives a gradient that can be written in the same shape as $(9)$:

\[
\nabla_\theta \mathcal J_{\text{DPO}}
= \mathbb{E}_{(q,y^+,y^-)}\Bigl[
GC_{\text{DPO}}(q,y^\pm)\,
\nabla_\theta\log\pi_\theta(y^+|q)
- GC_{\text{DPO}}(q,y^\pm)\,
\nabla_\theta\log\pi_\theta(y^-|q)
\Bigr],
\]

with a *single* coefficient applied symmetrically to the preferred and dispreferred terms.

---

### 3. Mapping DPO onto the unified paradigm

#### 3.1 Data source $\mathcal D_{\text{DPO}}$

DPO uses **offline sampled pairs**:  

1. Start from an already‑trained SFT model (the “base policy” $\pi_{\text{SFT}}$).  
2. For each question $q$ draw two outputs, $y^+$ and $y^-$, from the *same* base policy (or from a mixture of base‑policy and a modestly updated policy).  
3. Keep the pair only if a *preference* label is known – in practice this label comes from a reward model $r_\varphi$: if $r_\varphi(q,y^+)> r_\varphi(q,y^-)$ we treat $(y^+,y^-)$ as a preferred/dispreferred pair.

Hence  

\[
(q,y^+,y^-)\sim \underbrace{\bigl(P(Q),\,\pi_{\text{SFT}}(Y|Q),\,\pi_{\text{SFT}}(Y|Q)\bigr)}_{\text{offline sampling}}.
\]

This matches the “offline” column in Table 1 of the paper.

#### 3.2 Reward function / reference policy $\pi_{\text{rf}}$

In Equation $(9)$ the reward function appears only through its *gradient coefficient*.  
For DPO we set  

* **Reference policy** $\pi_{\text{rf}} = \pi_{\text{SFT}}$.  
* **Reward signal** = the *preference score* produced by the learned reward model:  

  \[
  s(q,y^+,y^-)=r_\varphi(q,y^+)-r_\varphi(q,y^-).
  \]

Because DPO’s loss contains a sigmoid of this difference, the coefficient will be proportional to  

\[
\sigma(s)- (1-\sigma(s)) = 2\sigma(s)-1.
\]

Thus we can view the reward function as mapping a pair of outputs to a *scalar advantage*  

\[
A_{q,y^\pm}= 2\sigma\!\bigl(r_\varphi(q,y^+)-r_\varphi(q,y^-)\bigr)-1.
\tag{1}
\]

#### 3.3 Algorithmic transformation → Gradient coefficient

The algorithmic step for DPO simply **multiplies** each log‑probability term by this advantage:

\[
GC_{\text{DPO}}(q,y^\pm)=A_{q,y^\pm}.
\tag{2}
\]

There is no extra clipping, baseline subtraction or KL penalty; it is a *direct* scaling of the log‑prob gradient by the signed preference signal.

Putting (1)–(2) back into Equation $(9)$ yields exactly the DPO update:

```
∇θJ_DPO = E_{q,y+,y-}[ A(q,y+,y-) ∇θ log πθ(y+|q)
                    - A(q,y+,y-) ∇θ log πθ(y-|q) ] .
```

Because each pair appears once with a + sign for the preferred output and once with a – sign for the dispreferred output, we recover the *pairwise* formulation of DPO without any extra terms.

---

### 4. Intuition behind each component

* **Why offline sampling?**  
  DPO treats preferences as static observations that do not depend on how the current policy behaves during training. This makes it cheap: no on‑policy roll‑outs, no critic, no value function—exactly what Equation $(9)$’s “offline” branch captures.

* **Why use a sigmoid of reward differences?**  
  The sigmoid turns an unbounded difference $r_\varphi(y^+)-r_\varphi(y^-)$ into a probability‑like weight lying in $(-1,1)$. When the preference is strong ($|s|\gg0$) we get coefficients close to $+1/-1$; when preferences are ambiguous ($s\simeq0$) we get coefficients near zero, meaning those pairs have little influence—mirroring how humans treat weakly decided comparisons.

* **Why no KL term?**  
  In PPO/GRPO an explicit KL penalty stabilises learning against catastrophic drift from the reference model. DPO’s coefficient already shrinks to zero for uncertain pairs, which implicitly regularises updates; consequently an extra KL term is unnecessary in its original formulation.

---

### 5. Summary table (conceptual)

| Component | DPO instantiation | Equation $(9)$ slot |
|-----------|-------------------|-------------------|
| Data source $\mathcal D$ | Offline sampled triplets $(q,y^+,y^-)$ from SFT policy | first expectation in $(9)$ |
| Reward / reference policy $\pi_{\text{rf}}$ | Fixed SFT policy; reward model provides scalar differences | appears inside $GC_{\mathcal A}$ |
| Algorithmic mapping → $GC_{\mathcal A}$ | Pairwise advantage $A=2\sigma(r_\varphi(y^+)-r_\varphi(y^-))-1$ | Equation $(9)$’s coefficient |

Thus, by choosing an **offline data source**, fixing the **reference policy to be the SFT model**, and defining **$GC_{\text{DPO}}$** exactly as above, Equation $(9)$’s general gradient recovers the DPO pairwise loss. Consequently, DPO can indeed be seen as a special case of the unified paradigm described in the DeepSeekMath paper, sitting between pure supervised fine‑tuning (where $GC=1$) and full PPO/GRPO (where $GC$ involves advantages computed from per‑token rewards and baselines). This derivation clarifies that all those methods share a common mathematical backbone; they differ only in *how* they generate data, *what* reward signal they use, and *how* they translate that signal into a scalar multiplier for each token’s log‑probability gradient.$

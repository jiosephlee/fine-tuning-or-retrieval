# Motivation and Historical Context of LSTMs  

In this chapter we explore the origins of Long Short‑Term Memory (LSTM) networks, the fundamental ideas that made them possible, and the reasons they dominated sequence modelling for decades before the advent of Transformer architectures.  The discussion follows directly from the concepts presented in the *xLSTM: Extended Long Short‑Term Memory* paper, and it is intended for readers who are encountering these ideas for the first time.  By the end of the chapter you should understand why LSTMs were introduced, how their internal mechanisms work, what empirical successes they achieved across a wide variety of domains, and which inherent limitations ultimately motivated the development of newer models such as Transformers.

---

## The Vanishing Gradient Problem in Recurrent Neural Networks  

Recurrent neural networks (RNNs) process sequential data by applying the same transition function at each time step.  If we denote the hidden state at time $t$ by $h_t$ and the input vector by $\mathbf{x}_t$, a simple RNN update can be written as  

\[
h_t = \phi\!\bigl(W_h\,h_{t-1} + W_x\,\mathbf{x}_t + b\bigr),
\]

where $\phi$ is a pointwise non‑linearity (e.g., $\tanh$) and $W_h$, $W_x$ are weight matrices.  During training we compute gradients of a loss $L$ with respect to these parameters via back‑propagation through time (BPTT).  The gradient flowing from a later time step $T$ back to an earlier step $t$ contains a product of Jacobians:

\[
\frac{\partial L}{\partial h_t}= \frac{\partial L}{\partial h_T}
   \prod_{k=t+1}^{T}\frac{\partial h_k}{\partial h_{k-1}} .
\]

If the spectral norm of $\frac{\partial h_k}{\partial h_{k-1}}$ is smaller than one, repeated multiplication drives the product toward zero exponentially in $T - t$.  Consequently, early time‑step contributions receive vanishingly small updates—this is the *vanishing gradient problem*.  It prevents standard RNNs from learning long‑range dependencies because information about distant inputs cannot be propagated effectively through the network’s gradients.

The LSTM was expressly designed to mitigate this difficulty.  By introducing an additive pathway for information—the *constant error carousel*—the network can preserve gradients over arbitrarily long intervals, thereby enabling the learning of long‑term dependencies.

---

## Constant Error Carousel and Gating Mechanisms  

The central innovation behind LSTMs consists of two intertwined ideas:

1. **Constant Error Carousel (CEC)** – an additive update to a dedicated memory variable that bypasses multiplicative Jacobians, ensuring that gradients can flow unchanged across many time steps.

2. **Gating** – sigmoid‑controlled multiplicative factors that regulate how information enters, leaves, or is read from the memory.

Mathematically, the original LSTM cell maintains a *cell state* $c_t$ (the memory) and a *hidden state* $h_t$ (the output used by subsequent layers).  At each step it computes

\[
c_t \;=\; f_t \, c_{t-1} \;+\; i_t \, z_t , \qquad
h_t \;=\; o_t \,\psi(c_t) .
\tag{1}
\]

Here:

* $f_t$ (*forget gate*) decides how much of the previous cell state $c_{t-1}$ should be retained.
* $i_t$ (*input gate*) controls how much new candidate information $z_t$ is written to memory.
* $o_t$ (*output gate*) determines how much of the (possibly normalized) cell state $\psi(c_t)$ should be exposed as hidden output.
* $\psi$ is typically a squashing function such as $\tanh$, preventing unbounded growth of $c_t$.
* The candidate input $z_t$ is itself produced by a non‑linear transformation of the current input $\mathbf{x}_t$ and previous hidden state $h_{t-1}$.

Because $c_t$ receives an **additive** contribution from $c_{t-1}$ (scaled only by a gate value), the derivative $\partial c_T / \partial c_{t}$ contains a product of forget gates rather than a product of full Jacobians.  If forget gates are near 1, gradients pass through almost unchanged—a concrete solution to vanishing gradients.

The gating functions in classic LSTMs are Sigmoid activations,

\[
\sigma(x)=\frac{1}{1+\exp(-x)},
\]

ensuring each gate lies in $(0,1)$ and can smoothly interpolate between “closed’’ ($0$) and “open’’ ($1$).  The three gates are computed from affine projections of both current input and previous hidden state:

\[
\begin{aligned}
z_t &= \varphi(\tilde{z}_t), &
\tilde{z}_t &= \mathbf{w}_z^{\!\top}\mathbf{x}_t + r_z\, h_{t-1} + b_z ,\\[2mm]
i_t &= \sigma(\tilde{i}_t), &
\tilde{i}_t &= \mathbf{w}_i^{\!\top}\mathbf{x}_t + r_i\, h_{t-1} + b_i ,\\[2mm]
f_t &= \sigma(\tilde{f}_t), &
\tilde{f}_t &= \mathbf{w}_f^{\!\top}\mathbf{x}_t + r_f\, h_{t-1} + b_f ,\\[2mm]
o_t &= \sigma(\tilde{o}_t), &
\tilde{o}_t &= \mathbf{w}_o^{\!\top}\mathbf{x}_t + r_o\, h_{t-1} + b_o .
\end{aligned}
\tag{2}
\]

The nonlinearities $\varphi$ (usually $\tanh$) and $\psi$ are applied after the affine projections.  Collectively these equations constitute the *original LSTM formulation* introduced in Hochreiter & Schmidhuber’s seminal works (1991, 1997).

---

## Original LSTM Equations and Intuition  

Let us unpack each component of Equation (1)–(2) with an intuitive narrative:

* **Input Gate ($i_t$)** – Think of this gate as a valve that decides *how much* new information from the current input should be admitted into memory. When an input is highly relevant for future predictions, $i_t$ will approach 1; otherwise it will stay near 0.

* **Forget Gate ($f_t$)** – This gate determines *how much* previously stored information should be discarded. A value close to 1 preserves past memory intact; a value close to 0 erases it completely. Because forgetting is multiplicative, it can gradually decay stale information without abrupt loss.

* **Candidate Input ($z_t$)** – This is an encoded representation of what *could* be written into memory at this step. It aggregates both raw input features $\mathbf{x}_t$ and contextual cues from $h_{t-1}$.

* **Cell State Update ($c_t = f_tc_{t-1}+i_tz_t$)** – The new memory equals a blend of retained old memory and newly admitted content. The additive nature means that if either gate were close to 0 or 1 respectively, we could preserve or replace memory selectively.

* **Output Gate ($o_t$)** – Before exposing memory to subsequent layers, we first apply $\psi$, often squashing $c_t$ into a bounded range (e.g., via $\tanh$). The output gate then modulates whether this normalized signal should be transmitted outward as hidden state $h_t$. In practice this lets the model keep detailed internal representations while exposing only a filtered view according to task demands.

By chaining these operations across timesteps, an LSTM can *store*, *revise*, and *read* information over arbitrarily long horizons while maintaining stable gradient flow.

## Historical Successes Across Domains  

After their introduction, LSTMs rapidly became the workhorse for any task involving sequential data.  The paper enumerates numerous application areas where LSTMs have been dominant:

| Domain | Representative Works |
|--------|----------------------|
| **Text Generation** | Graves (2013), Karpathy (2015) |
| **Handwriting Generation** | Graves (2013) |
| **Sequence‑to‑Sequence Translation** | Sutskever et al. (2014) |
| **Program Evaluation** | Zaremba (2014) |
| **Image Captioning** | Karpathy & Fei‑Fei (2015), Hossain (2019) |
| **Source Code Generation** | Karpathy (2015) |
| **Hydrological Modeling & Flood Prediction** | Kratzert (2018–2019), Nearing (2024) |
| **Reinforcement Learning Agents** | AlphaStar (Vinyals 2017), OpenAI Five (OpenAI 2019), Magnetic Controller for Nuclear Fusion (Degrave 2022) |

These successes stem from two complementary properties:

1. **Memory Capacity for Long Dependencies** – Thanks to CEC and gating, LSTMs could capture dependencies spanning hundreds or even thousands of tokens—a feat unattainable with vanilla RNNs.
2. **Interpretability of Internal Units** – Research discovered specialized neurons inside trained LSTMs that encode interpretable concepts such as syntax trees (“syntax neurons”), sentiment (“sentiment neurons”), or numeric reasoning (“number neurons”). This illustrates that LSTMs naturally learn high‑level abstractions applicable across tasks.

Indeed, before 2017 most high‑performing language models—including early large language models—relied on stacked LSTM layers as their core sequence processor.

---

## Limitations That Led to Transformers  

Despite their historical prominence, three fundamental shortcomings eventually motivated researchers to explore alternative architectures:

### 1. Inability to Revise Storage Decisions  
In tasks where decisions about what to keep in memory must be updated repeatedly—e.g., *Nearest Neighbor Search*, where later inputs may replace previously stored vectors—the original LSTM struggles because its forget gate cannot undo past write actions sufficiently fast.  Empirically (see Figure 1 in the paper), mean squared error remains high when a more similar vector appears later in the sequence.

### 2. Limited Storage Capacity  
Classical LSTMs store information in scalar cells; each hidden dimension represents only one scalar value at any time step.  This compression limits how much fine‑grained detail can be retained simultaneously.  Experiments on *Rare Token Prediction* over Wikitext‑103 reveal that perplexity deteriorates dramatically for infrequent tokens—a symptom of insufficient representational bandwidth in scalar cell states.

### 3. Lack of Parallelizability  
The hidden–hidden recurrence (`h_{t-1}` → `h_{t}`) forces strictly sequential computation: each step depends on its predecessor’s hidden state.  As sequence lengths grow (e.g., document‑level language modeling), this creates a computational bottleneck because GPUs cannot exploit parallelism across timesteps.

These constraints made it difficult for LSTMs to scale effectively when training models with billions of parameters—a regime where Transformers excel because they replace recurrence with self‑attention that is fully parallelizable across positions.

Consequently, researchers introduced *self‑attention* mechanisms (Vaswani et al., 2017), leading to Transformer architectures that dominate modern large language modeling benchmarks. Nevertheless, as shown later in the xLSTM paper, revisiting LSTM design—by introducing exponential gating and richer memory structures—can recover many lost capabilities while retaining linear-time computation with respect to sequence length.

--- 

In summary, the LSTM emerged as a principled solution to vanishing gradients through its constant error carousel and gating mechanisms. Its elegant formulation enabled unprecedented advances across natural language processing, speech synthesis, reinforcement learning, and scientific modeling. Yet intrinsic limitations concerning revision capacity, storage bandwidth, and sequential execution motivated subsequent developments such as Transformers—and inspired modern extensions like xLSTM that aim to combine the best of both worlds.

**Fundamentals of the Standard LSTM Cell**  

The Long Short‑Term Memory (LSTM) network was introduced in the early 1990s to address the vanishing‑gradient problem that plagued ordinary recurrent neural networks (RNNs).  Its core idea is the **constant‑error carousel**: a cell state that is updated additively, allowing gradients to flow unchanged across many time steps.  Together with three multiplicative gates—input, forget, and output—this mechanism gives the LSTM the ability to *selectively* store, overwrite, and expose information.  In this chapter we present a complete mathematical description of the classic LSTM cell, define the parameterisation used throughout the book, and discuss extensions such as vectorised multi‑cell variants and hidden‑hidden mixing.  Ablation studies from the original LSTM literature are also highlighted to motivate why each component is essential.

---

### 1. Scalar Memory Cell and Gate Formulations  

At the heart of the LSTM is a **scalar memory cell** \(c_t\in\mathbb{R}\) that evolves over discrete time steps \(t=1,2,\dots\).  The update rule follows directly from the constant‑error carousel:

\[
c_t \;=\; f_t\,c_{t-1} \;+\; i_t\,z_t .
\tag{1}
\]

* **Forget gate** \(f_t\in(0,1)\) scales the previous cell content \(c_{t-1}\), thereby determining how much of the past is retained.  
* **Input gate** \(i_t\in(0,1)\) controls how strongly a newly computed candidate \(z_t\) influences the cell.  
* **Cell input** \(z_t\) is a transformed version of the current external input \(\mathbf{x}_t\) and (optionally) the previous hidden state \(h_{t-1}\).  

After the cell has been updated, an **output gate** \(o_t\in(0,1)\) decides how much of a non‑linear transformation of the cell should be emitted as hidden state:

\[
\tilde{h}_t \;=\; \psi(c_t), \qquad
h_t \;=\; o_t\,\tilde{h}_t .
\tag{2}
\]

Here \(\psi(\cdot)\) denotes a squashing (normalisation) function that keeps the hidden signal bounded; in most implementations \(\psi\) is chosen as hyperbolic tangent \(\tanh\).  Equation (2) completes one forward step of an LSTM with a *single* scalar memory.

---

### 2. Parameterisation: Weights, Biases, and Recurrent Connections  

All gates and the candidate input are affine transformations followed by elementwise non‑linearities.  Let \(\mathbf{x}_t\in\mathbb{R}^{d_{\text{in}}}\) be the external input at time \(t\).  The linear pre‑activations for each gate and for \(z_t\) are

\[
\begin{aligned}
\tilde{z}_t &= \mathbf{w}^{\top}_{z}\,\mathbf{x}_t
            + r_{z}\,h_{t-1}
            + b_{z},\\[4pt]
\tilde{i}_t &= \mathbf{w}^{\top}_{i}\,\mathbf{x}_t
            + r_{i}\,h_{t-1}
            + b_{i},\\[4pt]
\tilde{f}_t &= \mathbf{w}^{\top}_{f}\,\mathbf{x}_t
            + r_{f}\,h_{t-1}
            + b_{f},\\[4pt]
\tilde{o}_t &= \mathbf{w}^{\top}_{o}\,\mathbf{x}_t
            + r_{o}\,h_{t-1}
            + b_{o}.
\end{aligned}
\tag{3}
\]

* \(\mathbf{w}_{z}, \mathbf{w}_{i}, \mathbf{w}_{f}, \mathbf{w}_{o}\in\mathbb{R}^{d_{\text{in}}}\) are **input‑to‑gate weight vectors**, controlling how raw input drives each gate and candidate.  
* \(r_{z}, r_{i}, r_{f}, r_{o}\in\mathbb{R}\) are **recurrent scalars** that couple the previous hidden state \(h_{t-1}\) back into each computation.  In more modern vectorised formulations these become matrices (see Section 3).  
* \(b_{z}, b_{i}, b_{f}, b_{o}\in\mathbb{R}\) are **bias terms** that allow each gate to have a non‑zero baseline even when inputs are zero.

The non‑linearities applied to (3) are:

* **Sigmoid** for all three gates:
  \[
  i_t = \sigma(\tilde{i}_t), 
  \quad
  f_t = \sigma(\tilde{f}_t), 
  \quad 
  o_t = \sigma(\tilde{o}_t), 
  \qquad
  \sigma(x)=\frac{1}{1+e^{-x}}.
  \tag{4}
  \]
* **Cell input activation** \(\varphi(\cdot)\), typically a hyperbolic tangent:
  \[
   z_t = \varphi(\tilde{z}_t), 
   \qquad
   \varphi(x)=\tanh(x).
   \tag{5}
  \]

Together with (1)–(2), these equations completely characterise a scalar LSTM cell.

---

### 3. From Scalar to Vectorised Multi‑Cell LSTMs  

In practice a language model or any deep sequence model needs far more capacity than a single scalar can provide. The standard extension is to replicate the scalar memory \(c_t\) across a *vector* of size \(d_{\text{cell}}\):

\[
\mathbf{c}_t = (c^{(1)}_t,\dots,c^{(d_{\text{cell}})}_t)\in\mathbb{R}^{d_{\text{cell}}}.
\]

All equations above now operate elementwise on vectors.  Crucially, once we have multiple cells we can also introduce **hidden‑hidden mixing**, i.e., a recurrent matrix that mixes information across cells before producing new gate pre‑activations:

| Symbol | Meaning |
|--------|---------|
| \(\mathbf{R}_{z},\,\mathbf{R}_{i},\,\mathbf{R}_{f},\,\mathbf{R}_{o} \in \mathbb{R}^{d_{\text{cell}}\times d_{\text{cell}}}\) | Recurrent weight matrices that project the previous hidden vector \(\mathbf{h}_{t-1}\) into each gate’s pre‑activation space. |

Consequently, (3) becomes

\[
\tilde{\mathbf{i}}_t = 
   \mathbf{W}_{i}^\top\,\mathbf{x}_t 
   + 
   \mathbf{R}_{i}\,\mathbf{h}_{t-1} 
   + 
   \mathbf{b}_{i},
   \qquad  
   (\text{and similarly for } f,o,z).
   \tag{6}
\]

Here each capital letter denotes a matrix whose columns correspond to individual cells. The hidden state after gating stays vectorised:

\[
\hat{\mathbf h}_t = o_t\,\,\tanh(\mathbf c_t).
\tag{7}
\]

The presence of these recurrent matrices enables *inter‑cell communication*: information stored in one cell can influence another in subsequent steps. This “memory mixing’’ is one of the factors that gave early LSTMs significant expressive power compared with vanilla RNNs.

---

### 4. Activation Functions and Normalisation  

The design of activation functions for gates and candidates follows two complementary goals:

1. **Boundedness:** Sigmoid constrains gates to lie in $(0,1)$, ensuring they act as smooth multiplicative masks.
2. **Signal Range:** $\tanh$ maps its input to $(-1,1)$, which keeps $c_t$ from exploding while preserving sign information useful for representing oppositional features.

Because $c_t$ accumulates over many steps via additive updates in (1), an unbounded squashing function would cause uncontrolled growth. Therefore $\psi$ in (2)—often $\tanh$—plays a normalising role before output gating occurs.

In later work (including later sections on xLSTM extensions), alternative normalisers such as layer normalisation or custom scaling mechanisms have been explored; however, for the classic LSTM as introduced above these simple $\sigma$ and $\tanh$ functions suffice.

---

### 5. Ablation Insights on Gate Importance  

Empirical studies on standard benchmarks have systematically removed or altered components of the LSTM cell to gauge their contribution (see Greff et al., 2015). The key findings are:

| Ablated Component | Observed Effect |
|-------------------|-----------------|
| Removing **forget gate** (\(f_t=1\)) → severe degradation on long sequences because past information cannot be discarded selectively; gradients tend either to vanish or explode. |
| Removing **input gate** (\(i_t=1\)) → loss of ability to control what new information enters memory; performance drops especially on tasks requiring selective writing (e.g., language modeling with rare tokens). |
| Removing **output gate** (\(o_t=1\)) → hidden state becomes directly proportional to $\psi(c_t)$; this harms tasks where only part of stored content should be exposed at each step (e.g., predictive coding). |
| Replacing multiplicative gates with *additive* alternatives → gradient flow is no longer modulated; training becomes unstable beyond modest depths. |
| Using linear instead of $\sigma$ / $\tanh$ → internal values quickly diverge, leading to exploding gradients despite the constant error carousel.|

These ablations confirm that every gate plays an irreplaceable role: *forget* governs retention versus decay; *input* governs ingestion versus suppression; *output* governs exposure versus concealment. Together they preserve long‑range dependencies while allowing flexible adaptation to short‑term signals.

---

### 6. Summary  

The classic LSTM cell couples an additive constant‑error carousel with three multiplicative gates whose parameters consist of input weights, recurrent connections (scalar or matrix), and biases. Non‑linear activations—sigmoid for gates and hyperbolic tangent for candidate/normalisation—keep all signals well behaved while enabling selective storage, erasure, and readout from a memory that can persist across arbitrarily long sequences. Extending from a single scalar to a vectorised multi‑cell formulation introduces hidden‑hidden mixing via recurrent matrices, further enhancing expressive capacity.

Understanding this baseline formulation is essential before exploring modern extensions such as exponential gating, scalar versus matrix memories, or residual block integrations that form the backbone of newer architectures like xLSTM. The mathematical conventions introduced here will be reused throughout the remainder of this textbook when we analyse more advanced sequence models built upon—or departing from—the original LSTM design.

**Limitations of Traditional LSTMs for Large‑Scale Language Modelling**

The Long Short‑Term Memory (LSTM) network was introduced in the early 1990s to overcome the vanishing‑gradient problem that plagued ordinary recurrent neural networks. Its core mechanism—an additive “constant‑error carousel’’ together with three multiplicative gates (input, forget, and output)—remains a powerful tool for sequence modelling. Nevertheless, when one attempts to scale LSTMs to the billions of parameters that modern large language models (LLMs) employ, three fundamental shortcomings become evident. These limitations not only degrade performance on standard language‑modelling benchmarks but also impede LSTMs from exploiting architectural advances that have made transformers and state‑space models (SSMs) dominant at scale.

Below we dissect each shortcoming in depth, illustrating the failure modes with concrete tasks introduced in the xLSTM paper, and we contrast them with the capabilities of contemporary transformer‑based and SSM‑based language models.

---

### 1. Inability to Revise Stored Information  
#### The Nearest‑Neighbor Search Illustration  

A recurrent network processes a sequence one token at a time, updating its hidden state and cell state at each step. In the classic LSTM formulation the cell update is

\[
c_t \;=\; f_t\,c_{t-1} \;+\; i_t\,z_t ,
\qquad
h_t \;=\; o_t\,\psi(c_t),
\]

where \(i_t\), \(f_t\), and \(o_t\) are sigmoid‑activated gates and \(z_t\) is the candidate cell input. The forget gate \(f_t\) can only *decay* past information; it cannot actively *overwrite* a previously stored value when a more relevant piece of evidence arrives later in the sequence.

The paper highlights this rigidity with a **nearest‑neighbor search** task. A reference vector is provided, then a long sequence of candidate vectors is streamed in. The goal is to output, at the final time step, the value attached to the vector that is **most similar** to the reference. An optimal recurrent system would be able to **revise** its provisional answer whenever it encounters a nearer neighbor later in the stream.

Empirical results (Figure 1 of the paper) show that a vanilla LSTM’s mean‑squared error remains high even after many timesteps: once an initial candidate has been stored, subsequent more similar vectors cannot replace it because the forget gate decays past information only multiplicatively, and the input gate cannot compensate for a previously stored large magnitude entry without destabilising training. Consequently, the LSTM “locks in’’ an early decision and fails to correct it—a critical flaw for any task requiring dynamic memory revision.

**Why this matters for language modelling:**  
In natural language, entities may be reintroduced or clarified later (e.g., pronoun resolution, coreference chains). A model that cannot reliably revise earlier representations will struggle to maintain consistent context over long passages, leading to poorer next‑token predictions.

---

### 2. Restricted Storage Capacity – Scalar Cell States vs. Rich Representations  
#### Rare‑Token Prediction as a Stress Test  

The canonical LSTM stores a **single scalar** per memory cell (or—after vectorisation—a fixed‑size vector of scalars). Each scalar must compress all information relevant to its position in the sequence into a one‑dimensional quantity before being passed forward through additive updates. This compression imposes a hard bound on how much distinct information can be retained simultaneously.

The xLSTM paper demonstrates this bottleneck by measuring perplexity on **rare tokens** within the Wikitext‑103 benchmark. Tokens are grouped by their frequency; while common tokens are predicted well by all models, **rare tokens**—those that appear only a handful of times across the entire corpus—exhibit dramatically higher perplexities for standard LSTMs than for transformers or SSMs.

The intuition behind this phenomenon is twofold:

1. **Limited representational bandwidth:** A scalar cell cannot encode subtle nuances such as morphological features, long‑range dependencies, or co‑occurrence statistics needed to disambiguate infrequent words.
2. **Interference between updates:** Because each update adds a scaled version of \(z_t\) onto an existing scalar, repeated contributions from many frequent words can drown out the signal from rare words, especially when the forget gate is close to one (the default setting for preserving long‑range information).

In contrast, transformer layers maintain **high‑dimensional token embeddings** throughout all layers; each token’s representation remains a vector of size 1024 or larger, allowing fine‑grained distinctions even for low‑frequency items. State‑space models also propagate high‑dimensional hidden states linearly across timesteps, preserving capacity.

Thus, purely scalar memory places an intrinsic ceiling on how well an LSTM can learn to predict rare events—a crucial capability for any LLM intended to handle diverse vocabularies.

---

### 3. Sequential Bottleneck from Hidden‑Hidden Connections  
#### The Hidden‑Hidden Recurrence Constraint  

Beyond gating and storage size, classic LSTMs feature **hidden‑hidden recurrent connections**: the hidden state \(h_{t-1}\) feeds directly into every gate and into the candidate cell input \(z_t\). Formally,

\[
\tilde{i}_t = \mathbf{w}_i^\top \mathbf{x}_t + r_i\,h_{t-1} + b_i,
\]
and similarly for \(\tilde{f}_t,\tilde{o}_t,\tilde{z}_t\).

These dependencies create an explicit **sequential dependency graph**: computing any quantity at time \(t\) requires knowledge of \(h_{t-1}\), which itself depends on \(h_{t-2}\), and so forth back to \(t=0\). Consequently:

* **No parallelisation across timesteps:** Unlike self‑attention where all token pairs can be processed simultaneously (once key/value projections are computed), an LSTM must be unrolled step‑by‑step during both training and inference.
* **Quadratic wall‑clock cost when scaling depth:** Even though each timestep has linear computational complexity in \(d\), processing long sequences (e.g., 16 k tokens) yields wall time proportional to sequence length—a severe bottleneck when billions of tokens are required for pretraining.
* **Limited throughput on modern hardware:** GPUs excel at large matrix multiplications performed in parallel; recurrent loops restrict utilisation of these cores because intermediate results cannot be overlapped across positions.

Transformers bypass this limitation entirely by employing self‑attention that is *parallelizable* across positions after an initial projection stage. Recent linearised attention variants (e.g., Performer, FlashAttention) further reduce memory footprints while preserving parallelism. State–space models such as S4 or Mamba achieve linear × constant memory overhead because they formulate recurrence as a convolution with precomputed kernels that can be evaluated using fast Fourier transforms or other parallel operators.

Therefore, traditional hidden–hidden recurrence makes classic LSTMs unsuitable for large‑scale language modelling where both sequence length and model width must be maximised simultaneously.

---

### 4. Comparative Perspective: Transformers and State‑Space Models  

| Aspect | Classic LSTM | Transformer (self‑attention) | State‑Space Model (e.g., S4/Mamba) |
|--------|--------------|-----------------------------|------------------------------------|
| **Memory update** | Scalar additive update (`c_t = f_t c_{t-1} + i_t z_t`) | Full token embedding participates in pairwise attention → effectively high‑dimensional associative memory | Linear dynamical system with discretised convolution kernel; hidden state evolves linearly |
| **Revision ability** | Forget gate only decays past values → limited revision | Attention weights can be recomputed at each layer allowing arbitrary reweighting of past tokens | Linear dynamics permit exact recombination of past contributions |
| **Storage capacity** | One scalar per cell (or fixed small vector) | High dimensional embeddings preserved throughout depth | Hidden dimension often hundreds → richer storage than scalar |
| **Parallelism over time** | Strict sequential dependence via `h_{t-1}` | Fully parallel after projection; attention computed across all positions simultaneously | Convolutional formulation enables parallel evaluation using FFT or other kernels |
| **Scalability** | Wall-clock grows linearly with sequence length; GPU utilisation low for long contexts | Initially quadratic memory/compute but mitigated by linearised/efficient attention variants; highly parallelisable | Linear compute & constant memory w.r.t sequence length; strong hardware utilisation |

These contrasts make clear why transformers have become dominant: they combine high capacity with full parallelism. However, they also introduce new issues—quadratic attention cost (addressed by linearised variants) and lack of explicit “persistent’’ cell state that some reasoning tasks benefit from. The xLSTM paper therefore proposes *exponential gating* and *matrix memories* precisely to bridge these gaps while retaining recurrence’s strengths.

---

### Summary  

Traditional LSTMs falter at scale for three intertwined reasons:

1. **Irreversible storage decisions:** The forget gate’s multiplicative decay cannot replace previously stored information without destabilising training; this hinders tasks like nearest–neighbor search where later evidence should supersede earlier guesses.
2. **Scalar compression bottleneck:** Storing information as scalars forces severe dimensionality reduction, dramatically hurting rare-token prediction where fine-grained distinctions matter.
3. **Sequential hidden–hidden recurrence:** The dependence on `h_{t-1}` forces strict stepwise computation, preventing parallel processing across timesteps and limiting throughput on modern GPUs.

When contrasted with transformers and state‐space models—both of which provide richer representations and full temporal parallelism—the limitations become starkly apparent. Overcoming them motivates the design choices explored later in the xLSTM framework: exponential gating that permits aggressive revision without overflow, matrix‐valued memories that expand storage capacity beyond scalars, and elimination of hidden–hidden connections (in mLSTM) to enable parallel evaluation. These innovations aim to bring recurrent architectures back into contention with today’s leading large language models.

# Exponential Gating: Theory and Stabilisation  

In this chapter we develop a rigorous understanding of the **exponential gating** mechanism that underlies the extended Long Short‑Term Memory (xLSTM) families — the scalar sLSTM and the matrix mLSTM.  We begin by contrasting exponential gate activations with the traditional sigmoid activations used in vanilla LSTMs, then derive the **normaliser state** \(n_t\) that is required to keep the hidden state bounded when gates can grow without bound.  Next we introduce the **stabiliser state** \(m_t\), which enables a numerically stable implementation by moving the computation into log‑space.  Finally we interpret the forget and input gates as, respectively, a decay factor and a learning‑rate‑like multiplier, and we provide a sketch of why the stabilisation does not alter either the forward values of the network or the gradients computed during back‑propagation.

---

## Exponential vs. Sigmoid Gate Activations  

Classic LSTMs rely on **sigmoid** functions for all three gates (input, forget, output):  

\[
\sigma(x)=\frac{1}{1+\exp(-x)}\;,
\]

which compresses any real‑valued pre‑activation \(\tilde{g}_t\) into the interval \((0,1)\).  The sigmoid’s bounded output makes it safe to multiply directly with existing memory values because each gate can only attenuate or modestly amplify its target.  However, this safety comes at a price: once a gate value has been set low (e.g. forget gate near zero), the network cannot later *increase* stored information beyond what is allowed by subsequent sigmoidal updates.  Consequently vanilla LSTMs struggle with tasks that require **revising past storage decisions**, such as nearest‑neighbor search where a more similar vector appears later in the sequence.

The xLSTM family remedies this by allowing gates to be **exponential**:

\[
i_t = \exp(\tilde{i}_t), \qquad  
f_t = 
\begin{cases}
\sigma(\tilde{f}_t) & \text{(sigmoid mode)}\\[4pt]
\exp(\tilde{f}_t)    & \text{(exponential mode)} .
\end{cases}
\]

An exponential activation maps \(\tilde{g}_t\in\mathbb R\) to the strictly positive range \((0,\infty)\).  Because values can now exceed 1, a gate can *amplify* its target rather than merely attenuate it.  In particular:

* **Input gate \(i_t\)** acts as a **learning rate**: by scaling the incoming candidate \(\mathbf{z}_t\) (or \(\mathbf{v}_t\mathbf{k}_t^{\top}\) in mLSTM), an exponential \(i_t\) can increase memory content much more aggressively when needed.
* **Forget gate \(f_t\)** can be interpreted as a **decay factor**: if \(f_t>1\) it expands existing memory, while \(0<f_t<1\) contracts it.  The exponential version therefore permits *re‑strengthening* previously forgotten information—a capability absent under pure sigmoid gating.

The freedom to exceed one enables *revision*: when a later token provides evidence that earlier stored content should be amplified or corrected, the corresponding input and forget gates can jointly raise or lower the memory in a smooth, differentiable way.

---

## Derivation of the Normaliser State \(n_t\)

When gates are unrestrictedly large, naive addition of scaled terms may cause hidden states to diverge.  To keep the hidden output bounded we introduce a **normaliser state** \(n_t\), which tracks the cumulative influence of all gates applied up to time \(t\).  For the scalar sLSTM (the derivation for mLSTM is analogous but with vectors/matrices), we define:

\[
\begin{aligned}
c_t &= f_t\, c_{t-1} + i_t\, z_t , \\[4pt]
n_t &= f_t\, n_{t-1} + i_t .
\end{aligned}
\tag{1}
\]

Both recurrences have exactly the same structure: they multiply previous quantities by the forget gate and add an input‑gate term (the second recurrence adds just \(i_t\) because it is accumulating *weights* rather than content).  Solving these recurrences yields:

\[
c_t = \sum_{\tau=0}^{t} 
      \Bigl( i_\tau\, z_\tau \,
      \prod_{k=\tau+1}^{t} f_k \Bigr),
      \qquad
n_t = \sum_{\tau=0}^{t} 
      \Bigl( i_\tau \,
      \prod_{k=\tau+1}^{t} f_k \Bigr).
\tag{2}
\]

Thus \(n_t\) is exactly the *scalar denominator* that records how much total “gate mass’’ has been applied to reach step \(t\).  The hidden state is then defined as

\[
h_t = o_t\, \tilde h_t,
   \qquad 
   \tilde h_t = \frac{c_t}{n_t},
   \tag{3}
\]

so that any uniform scaling of all gates (e.g. multiplying every \(i_\tau,f_\tau\) by a constant) cancels out in the ratio \(c_t/n_t\).  This quotient plays the role of an adaptive normalisation akin to layer‑norm but derived directly from gate dynamics.

---

## Stabiliser State \(m_t\) and Log‑Space Formulation  

Even though dividing by \(n_t\) prevents unbounded growth of \(h_t\), intermediate products such as \(f_t\,c_{t-1}\) or \(i_t\,z_t\) can still overflow in floating‑point arithmetic because exponentials produce numbers that span many orders of magnitude.  The remedy is to move to **log‑space** for the gating variables while preserving their multiplicative relationships.

Define a stabiliser state

\[
m_t = 
   \max \bigl( \log f_t + m_{t-1},\, \log i_t\bigr),
   \qquad m_{-1}= -\infty .
   \tag{4}
\]

Intuitively, \(m_t\) records (in log units) the largest magnitude among all terms that will ever be added together in (1).  Using this bound we rescale both gates:

| Rescaled quantity | Definition |
|-------------------|------------|
| Stabilised input gate | \( i'_t = \exp(\log i_t - m_t)=\exp(\tilde i_t - m_t)\) |
| Stabilised forget gate | \( f'_t = \exp(\log f_t + m_{t-1} - m_t)=\exp(\tilde f_t + m_{t-1} - m_t)\) |

Because subtraction of a common factor (\(e^{-m_t}\)) from every term leaves ratios unchanged, we may replace each appearance of \(i_t,f_t\) in (1) by their stabilised counterparts \(i'_t,f'_t:\)

\[
c_{t}= f'_t\, c_{t-1}+ i'_t\, z_{t},
    \qquad
n_{t}= f'_t\, n_{t-1}+ i'_t .
    \tag{5}
\]

The crucial observation is that every term in (5) now lies in a numerically safe range (typically below \(e^{0}=1\)).  The max operation guarantees that at least one of either $i'_t$ or $f'_t$ equals 1 at each step, preventing underflow while still allowing other terms to be arbitrarily small.

---

## “Forget” as Decay and “Input” as Learning Rate  

To understand how exponential gating endows LSTMs with revision capability we reinterpret their roles in continuous time. Consider a differential analogue:

| Gate | Discrete update                               | Continuous analogue |
|------|----------------------------------------------|----------------------|
| Forget (\(f_t\)) | \(c_{t}= f_{t}\,c_{t-1}+ …{}\) | Decay factor:   $\dot c(t)= -\, (1-f(t))\,c(t)$ |
| Input (\(i_t)\)| $+\, i_{t}\,z_{t}$               | Learning rate: $\dot c(t)= i(t)\,(z(t)-c(t))$ |

When $f_{t}<1$, memory decays; when $f_{t}>1$, it *grows*, effectively undoing earlier decay.  Simultaneously, $i_{t}$ multiplies how strongly new evidence $z_{t}$ influences $c_{t}$.  Because both are unrestricted exponentials, they can assume values larger than 1, enabling *reinforcement* of earlier memories or *rapid correction* when later inputs warrant it.

In matrix‑valued mLSTM, exactly analogous interpretations hold:  

* Forget gate becomes a scalar decay factor applied to every entry of $\mathbf C_{t-1}$.
* Input gate becomes a scalar *learning rate* for the rank‑one outer product $\mathbf v_{t}\mathbf k^{\top}_{t}$.

Thus exponential gating equips recurrent networks with dynamics reminiscent of adaptive optimisers (e.g., Adam’s learning‑rate adaptation), but fully differentiable and learned end‑to‑end.

---

## Proof Sketch: Stabilisation Preserves Forward and Backward Passes  

We now argue formally why replacing $(i_{t},f_{t})$ by their stabilised versions $(i'_{t},f'_{t})$ leaves both forward outputs and gradient computations unchanged.

### Lemma 1 (Scaling invariance of hidden state)

For any constant $c>0$, define scaled gates $\hat i_{t}=c\,i_{t}$ and $\hat f_{t}=c\,f_{t}$.  
Let $(c^{(s)}_t,n^{(s)}_t)$ be generated from $(i'_,f'_)$ via recurrence (5).  
Then

\[
h^{(s)}_t = o_{t}\,\frac{c^{(s)}_t}{n^{(s)}_ t}
          = o_{t}\,\frac{c _ t}{n _ t}=h _ t .
\]

*Proof.* Both numerators and denominators acquire exactly the same factor $c$ at each step because their recurrences are linear homogeneous in $(i,f)$; therefore their ratio remains unchanged. ∎

### Lemma 2 (Log‑shift does not alter ratios)

Let $m_T=\max_{\tau≤T}\{\log i_{\tau},\, \log f_{\tau}+m_{\tau-1}\}$.  
Define scaled gates $i'_{\tau}=e^{-\!m_T} i_{\tau}$ and similarly for $f'_{\tau}$.  
Then for each $\tau$,  

\[
(i'_{\tau},f'_{\tau}) = e^{-m_T}(i_{\tau},f_{\tau}),
\]

and consequently all intermediate quantities $(c^{(s)}_T,n^{(s)}_T)$ are multiplied by $e^{-m_T}$ while their ratio stays invariant. ∎

### Theorem (Equivalence of original and stabilised updates)

Let $(c_T,n_T)$ be produced by original recurrence (1) with possibly unbounded exponentials; let $(c^{(s)}_T,n^{(s)}_T)$ be produced by stabilised recurrence (5). Then

* Forward pass equivalence: $h_T = o_T\, c_T/n_T = o_T\, c^{(s)}_T/n^{(s)}_T$.
* Gradient equivalence: for any loss $\mathcal L$,  
  $\displaystyle 
   \frac{\partial \mathcal L}{\partial (\theta)}
   = 
   \frac{\partial h_T}{partial (\theta)}
   $ computed using either set of recurrences yields identical values.

*Proof Sketch.* By Lemma 2 all terms share an overall multiplicative constant $e^{-m_T}$ that cancels in ratios; hence forward outputs coincide (Lemma 1).  
For gradients note that each recurrence is linear in $(i,f,c,n)$; scaling any variable multiplies both forward contributions and their derivatives by exactly that same factor, which again cancels when forming $\partial h_T/\partial (\theta)$ because chain rule applies uniformly across numerator and denominator. Thus back‑propagation sees precisely the same computational graph up to an irrelevant global scale. ∎

Consequently we may implement exponential gating safely using equations (4)–(5) without sacrificing any expressive power or training dynamics.

--- 

### Summary  

Exponential gating replaces bounded sigmoid activations with unbounded positive functions, thereby granting LSTM‐style recurrent cells two crucial abilities: revising previously stored information and applying an adaptive learning‐rate effect on incoming content.  The introduced normaliser state tracks accumulated gate mass so that hidden activations remain bounded via division $c_t/n_t$.  Numerical stability is achieved through a log‑space stabiliser state $m_t$, which rescales gates before use while preserving exact forward values and exact gradients thanks to simple scaling invariance properties proved above.  Interpreting forget as decay and input as learning rate further illuminates why exponential gating naturally equips sLSTM and mLSTM with richer dynamics than classic LSTMs—an essential ingredient for achieving state‑tracking performance comparable to modern Transformers while retaining recurrent linear complexity.

# sLSTM: Scalar Memory with Mixing and Heads

In this chapter we delve into the **scalar Long Short‑Term Memory** variant introduced in the xLSTM family, often abbreviated as **sLSTM**.  The sLSTM retains the classic single‑cell scalar memory of the original LSTM but augments it in three crucial ways:

1. **Exponential gating**, which replaces the usual sigmoid activation on (some) gates with an exponential function, allowing the model to *revise* previously stored information more aggressively.  
2. **Memory mixing**, a set of recurrent matrices that allow information to flow between multiple scalar cells, thereby increasing expressiveness while preserving the additive constant‑error carousel.  
3. **Multi‑head extensions**, where several independent “heads” share the same gating signals but maintain separate mixing pathways, enabling richer parallel representations.

We will first present the forward equations that define the sLSTM’s computation at each time step, then discuss how memory mixing works, how multiple heads are incorporated, and finally consider the practical implications for state‑tracking tasks, CUDA‑based implementation, and computational cost.

---

## 1. sLSTM Update Equations with Exponential Gates

The core recurrence of the sLSTM builds directly on the canonical LSTM update (Equation \eqref{eq:lstm_idea}) but replaces the input gate (and optionally the forget gate) with an exponential activation.  The hidden‑to‑hidden recurrence is unchanged apart from a small stabilisation trick introduced later.

For a single scalar cell at time step \(t\), let \(\mathbf{x}_t\in\mathbb{R}^{d_{\text{in}}}\) be the input vector and \(h_{t-1}\) the previous hidden state.  The forward pass comprises four stages:

1. **Cell state update** – same additive form as an LSTM:
   \[
   c_t \;=\; f_t\,c_{t-1} \;+\; i_t\,z_t .
   \tag{1}
   \]
2. **Normalizer state** – a running sum that tracks how much total “mass’’ has been accumulated from inputs weighted by future forget gates:
   \[
   n_t \;=\; f_t\,n_{t-1} \;+\; i_t .
   \tag{2}
   \]
3. **Hidden state computation** – instead of applying a fixed squashing function \(\psi(\cdot)\), we divide by the normalizer, which yields a *self‑normalising* hidden state:
   \[
   \tilde{h}_t \;=\;\frac{c_t}{n_t},\qquad
   h_t \;=\; o_t\,\tilde{h}_t .
   \tag{3}
   \]
4. **Gate and input preprocessing** – all pre‑activations are affine functions of the current input and the previous hidden state:
   \[
   \begin{aligned}
   \tilde{z}_t &= \mathbf{w}^{\top}_{z}\,\mathbf{x}_t + r_{z}\,h_{t-1} + b_{z},
   && z_t = \varphi(\tilde{z}_t),\\[2mm]
   \tilde{i}_t &= \mathbf{w}^{\top}_{i}\,\mathbf{x}_t + r_{i}\,h_{t-1} + b_{i},
   && i_t = \exp(\tilde{i}_t),\\[2mm]
   \tilde{f}_t &= \mathbf{w}^{\top}_{f}\,\mathbf{x}_t + r_{f}\,h_{t-1} + b_{f},
   && f_t = 
        \begin{cases}
           \sigma(\tilde{f}_t), &\text{sigmoid option},\\
           \exp(\tilde{f}_t),    &\text{exponential option},
        \end{cases}\\[2mm]
   \tilde{o}_t &= \mathbf{w}^{\top}_{o}\,\mathbf{x}_t + r_{o}\,h_{t-1} + b_{o},
        && o_t = \sigma(\tilde{o}_t).
   \end{aligned}
   \tag{4}
   \]

The scalar non‑linearity for cell input \(z_t\) is typically hyperbolic tangent (\(\varphi=\tanh\)), while gates \(i_t,f_t,o_t\) use either sigmoid or exponential activation according to design choices.  The exponential activation permits values larger than one and potentially far greater than a sigmoid’s bound of \(0\!-\!1\).  This characteristic is essential for *revising* earlier storage decisions: a later input can increase its gate value dramatically, allowing a previously stored piece of information to be amplified or suppressed beyond what a sigmoid could achieve.

---

## 2. Stabilisation of Exponential Gates

Because exponentials can grow without bound, naïve use would lead to overflow or exploding gradients.  The authors therefore introduce a *stabiliser state* \(m_t\) that tracks — in log‑space — the dominant magnitude among all gates seen so far:

\[
m_t = 
\max\!\bigl(\,\log(f_t) + m_{t-1},\,\log(i_t)\bigr).
\tag{5}
\]

Using \(m_t\), each gate is rescaled back into a numerically safe regime:

\[
\begin{aligned}
i'_t &= 
      \exp\!\bigl(\log(i_t)-m_t\bigr) 
      =  \exp(\tilde{i}_t - m_t),\\[2mm]
f'_t &=
      \exp\!\bigl(\log(f_t)+m_{t-1}-m_t\bigr).
\end{aligned}
\tag{6}
\]

Replacing \(i_t,f_t\) in (1)–(2) by their stabilised counterparts \(i'_t,f'_t\) does not alter any forward output or gradient values (see Appendix B of the paper).  In practice this simple log‑max operation prevents overflow while preserving the expressive power of exponential gating.

---

## 3. Memory Mixing Across Cells

A single scalar cell can store limited information.  The sLSTM therefore allows **multiple scalar cells** to interact via *memory mixing*.  Suppose we have \(M\) cells aggregated into vectors
\[
\mathbf{c}_{t}\in\mathbb{R}^{M},\quad
\mathbf{n}_{t}\in\mathbb{R}^{M},\quad
\mathbf{h}_{t}\in\mathbb{R}^{M}.
\]

The updates generalise elementwise as in (1)–(3), but each gate now receives contributions from all hidden dimensions through recurrent weight matrices:

```
ĉₜ = fₜ ⊙ cₜ₋₁ + iₜ ⊙ zₜ
n̂ₜ = fₜ ⊙ nₜ₋₁ + iₜ
ĥₜ = (ĉₜ ⊘ n̂ₜ)
hₜ = oₜ ⊙ ĥₜ
```

where “⊙’’ denotes elementwise multiplication and “⊘’’ elementwise division.
The pre‑activations are now:
\[
\begin{aligned}
 & \tilde{\mathbf z}_t = 
      W_z\,\mathbf{x}_t + R_z\,\mathbf h_{t-1}+b_z,
 &&    \mathbf z_t=\varphi(\tilde{\mathbf z}_t),
\\[2mm]
 & \tilde{\mathbf i}_t =
      W_i\,\mathbf{x}_t + R_i\,\mathbf h_{t-1}+b_i,
 &&    i^{(k)}_t=\exp(\tilde i^{(k)}_t),
\\[2mm]
 & 
   (\textit{similarly for }f,o).
\end{aligned}
\tag{7}
\]

Here, each \(R_{\star}\in\mathbb R^{M\times M}\) mixes hidden activations across cells before they affect a particular gate of any cell.  In other words, *memory mixing* implements hidden‑to‑hidden recurrent connections that are absent in pure feed‑forward architectures like Transformers or SSMs.

Why is this valuable?  Consider a *state tracking* problem where one must remember an arbitrary number of past events and occasionally overwrite older entries when more relevant information arrives (e.g., nearest‑neighbor search described in Section 2).  With pure scalar cells each event would occupy its own cell forever; mixings allow information to flow from one cell to another, effectively enabling *revision*: a later gate can amplify an alternative cell’s contribution while diminishing or erasing another’s influence.

---

## 4. Multiple Heads: Independent Mixing per Head with Shared Gating

The sLSTM architecture also supports **multiple heads**, reminiscent of multi‑head attention but applied to recurrent memory rather than pairwise token interactions.

A head can be thought of as an independent group of scalar cells that share *the same gating signals* (\(i_t,f_t,o_t,z_t,\ldots)\) but have distinct mixing matrices \(R^{(h)}_{\star}\).  Formally:

- Let there be \(H\) heads.
- For head \(h=1,\dots,H\), define its own cell vectors
  \(\mathbf c^{(h)}_t,\mathbf n^{(h)}_t,\mathbf h^{(h)}_t
    \in {\mathbb R}^{M_h}\).
- Gates are computed once using the global hidden state
  (often obtained by concatenating/averaging all heads).  
- Each head then updates its own memory according to equations analogous to (1)–(3), but with its own recurrent matrices:
  \(R^{(h)}_{\star}:\mathbb R^{M_h\times M_h}\).

Because gating is shared, all heads receive an identical *global decision* about how much new information to write (`i`), forget (`f`), and expose (`o`).  However, their internal mixing pathways differ, allowing each head to specialise—one may focus on short‑term patterns while another integrates longer dependencies.

The paper highlights that **heads combined with exponential gating constitute a novel form of memory mixing**: unlike standard multi‑head attention where each head only attends to inputs via dot products, here each head merges its internal scalar memories through learned recurrent matrices _and_ benefits from exponential amplification/shrinkage supplied by shared gates.

---

## 5. Effect of Exponential Gating on State‑Tracking Tasks

State tracking requires revisiting earlier decisions when new evidence arrives—a capability that standard LSTMs lack because sigmoid gates cannot increase past contributions beyond their initial magnitude once written.

In experiments on synthetic formal languages (e.g., parity or nested bracket counting), only models equipped with **exponential gating plus mixing** (sLSTM or mLSTM variants) succeeded at perfect accuracy and generalized to lengths far beyond training data.  

The intuition is straightforward:

- A sigmoid gate caps its output by one; if you write a large value into memory at time \(s<t_\text{subsequent}}\), later forget gates cannot increase its influence—only decay it.
- An exponential gate can output values far larger than one when needed; when revisiting an entry that should dominate future predictions, the model can set a large input gate at that later time step to *overwrite* older content effectively.
- Simultaneously, normalisation via `n_t` guarantees that hidden states remain bounded even if individual gates become huge—this prevents numerical blowup and preserves gradient flow.

Consequently sLSTM excels at tasks such as **nearest neighbor search**, where scanning sequentially must replace an earlier stored candidate when a more similar vector appears later in the sequence—a classic revision scenario that traditional LSTMs struggle with.

---

## 6. Implementation Details: CUDA Scan Kernel and Computational Cost

### 6.1 Parallel Scan Over Time

Although sLSTM’s recurrence appears inherently sequential because each step depends on `c_{t-1}` and `n_{t-1}`, the specific arithmetic under exponential gating admits an efficient parallel implementation using a **prefix‑sum (scan)** operation:

Given Equation (1)–(2),

```
c_t = f_t * c_{t-1} + i_t * z_t
n_t = f_t * n_{t-1} + i_t
```

these recurrences are linear in the previous states with multiplicative coefficients (`f_t`). By taking logs this becomes additive in log-space,
enabling parallel prefix sums akin to those used in Transformer flash attention kernels.

The authors implemented a custom CUDA kernel performing this scan:

1. Compute `log_f` and `log_i`.
2. Accumulate prefix sums of `log_f` across timesteps.
3. Use these sums to reconstruct `c` and `n` without explicit looping.

The kernel also incorporates stabilisation (Equation 5–6) on the fly by maintaining per‑thread maximums (`m_t`).  

### 6.2 Computational Complexity

For **single‑head single‑cell** sLSTM, per‑time‐step cost is comparable to an LSTM: a handful of matrix–vector products plus elementwise exponentials and division by `n`.  

When scaling to **multiple cells** (`M`) and **multiple heads** (`H`):

| Component | Cost per token | Comments |
|-----------|----------------|----------|
| Gate affine transforms | \(O((d_{\text{in}}+M)\times M H)\) | Each head computes its own `z,i,f,o`; sharing reduces constants |
| Exponential / sigmoid | \(O(M H)\) | cheap elementwise ops |
| Memory mixing (recurrent mats.) | \(O(M^2 H)\) | dominant term; scale quadratically with cells per head |
| Normalizer update | same as cell update | negligible |

Thus memory mixing introduces an **\(M^2 H** scaling term reminiscent of classical RNNs with full hidden‐to‐hidden weight matrices. In practice choices like \(M=64,\ H=4,\ d_{\text{in}}=1024.\)

Despite this quadratic dependency in the number of cells, experiments report that sLSTM remains only modestly slower than its fully parallel mLSTM counterpart: their custom CUDA implementation achieves runtimes < 2× that of mLSTM for comparable model sizes. The overhead stems chiefly from reading/writing larger intermediate tensors during matrix multiplications for mixing matrices.

### 6.3 Practical Recommendations

- Choose modest numbers of cells per head (e.g., ≤ 64) when targeting GPU throughput.
- Exploit mixed precision: exponentials can be evaluated safely in FP16 after stabilisation.
- Cache recurrent matrices (`R_\star`) in registers or shared memory whenever possible—this yields measurable speedups because they are reused across timesteps within each scan block.
- When training very deep stacks (≥ 48 layers as in Section 5), allocate separate CUDA streams for different layers so that scans can overlap with other operations such as feedforward projections.

---

## 7. Summary

The sLSTM enriches classic LSTMs along three intertwined dimensions:

| Feature | What it changes | Why it matters |
|---------|-----------------|----------------|
| **Exponential gating** | Replaces sigmoid on input (and optionally forget) gate with `exp`. | Allows powerful revision of stored content; essential for state tracking tasks requiring overwriting older memories. |
| **Memory mixing** | Introduces recurrent weight matrices across multiple scalar cells within each head. | Enables information flow between cells, increasing representational capacity beyond isolated scalars while preserving additive cell dynamics (constant error carousel). |
| **Multi‑head extension** | Replicates mixing per head while sharing global gating signals. | Provides diverse subspaces for representation without exploding parameter count; introduces novel form of parallel memory interaction distinct from multi‑head attention.|

Together these mechanisms give rise to a model capable of handling tasks traditionally considered out-of-reach for plain recurrent networks—most notably long-range state tracking and high-capacity associative recall—while still enjoying linear compute complexity with respect to sequence length due to efficient scan implementations.

In subsequent chapters we will see how these ideas are combined with matrix memories (the mLSTM variant), integrated into residual xLSTM blocks, and ultimately scaled up to billions of parameters for large language modeling experiments that rival contemporary Transformer baselines.

mLSTM: Matrix Memory and Covariance Updates

The purpose of this chapter is to explain in depth the matrix‑memory component of the extended Long Short‑Term Memory (xLSTM) architecture, known as the **mLSTM**.  We will start from the classic scalar cell of the original LSTM and then develop the intuition behind replacing a single number with a full \(d \times d\) matrix.  Next we introduce a key‑value formulation that mirrors the vocabulary of modern Transformer models and show how queries retrieve stored information.  The heart of the mLSTM is the **covariance (outer‑product) update rule**, a learning rule that is provably optimal for associative storage.  Because each update is a simple matrix addition, the method can be carried out in parallel across time steps, which links mLSTM to earlier ideas such as Fast Weight Programmers.  Finally we describe the role of the **normaliser vector** \(\mathbf{n}_t\) that keeps the retrieved output numerically stable.

---

## From Scalar to \(\boldsymbol{d\times d}\) Matrix Cell \(\mathbf{C}_t\)

In the original LSTM, each memory cell stores a single scalar value \(c_t\).  This scalar is updated additively:

\[
c_t = f_t\,c_{t-1} + i_t\,z_t,
\]

where \(f_t\) (forget gate) determines how much of the previous state is retained, \(i_t\) (input gate) scales the new candidate \(z_t\), and both gates lie in \([0,1]\).  While this formulation prevents vanishing gradients, it severely limits **storage capacity**: all information that has ever been observed must be compressed into a one‑dimensional quantity.

The mLSTM lifts this restriction by promoting the cell from a scalar to a **matrix** \(\mathbf{C}_t \in \mathbb{R}^{d\times d}\).  Instead of a single number, the model now carries a full linear operator that can encode many independent pieces of information simultaneously.  Conceptually, we can think of \(\mathbf{C}_t\) as an associative memory table: each column (or row) can be interpreted as a stored *value* associated with a corresponding *key*.  Because matrix multiplication is linear, retrieving a value consists simply of multiplying \(\mathbf{C}_t\) by a query vector.

The transition from scalar to matrix is not merely an increase in dimensionality; it fundamentally changes what the recurrent unit can represent.  A matrix can store up to \(d^2\) degrees of freedom, allowing it to linearly separate many more hidden states than are possible with scalar memory.  This increased capacity is crucial for tasks such as rare‑token prediction or long‑range associative recall where a large vocabulary must be memorised over thousands of time steps.

---

## Key–Value Formulation \((\mathbf{k}_t,\mathbf{v}_t)\) and Query Retrieval

To make use of the matrix memory, we interpret each incoming token (or more generally each time‑step input \(\mathbf{x}_t\)) as providing **two vectors**:

1. A **key** \(\mathbf{k}_t \in \mathbb{R}^{d}\), which identifies *where* in memory the forthcoming value should be stored.
2. A **value** \(\mathbf{v}_t \in \mathbb{R}^{d}\), which contains the actual information we wish to retrieve later.

This separation mirrors the way Transformers compute queries, keys and values for self‑attention; however, in mLSTM these vectors are produced directly from the input at time \(t\):

\[
\begin{aligned}
\mathbf{k}_t &= \frac{1}{\sqrt{d}}\,\mathbf{W}_k\,\mathbf{x}_t + \mathbf{b}_k,\\
\mathbf{v}_t &=      \mathbf{W}_v\,\mathbf{x}_t + \mathbf{b}_v,\\
\mathbf{q}_t &=      \mathbf{W}_q\,\mathbf{x}_t + \mathbf{b}_q,
\end{aligned}
\]

where \(\mathbf{W}_k,\mathbf{W}_v,\mathbf{W}_q\in\mathbb{R}^{d\times d_{\text{in}}}\) are learned projection matrices (the factor \(1/\sqrt{d}\) ensures that keys have unit variance after layer normalisation).  

When we later wish to recall a stored value, we construct a **query vector** \(\mathbf{q}_{t+\tau}\) from a future input and simply multiply it with the current memory matrix:

\[
\tilde{\mathbf{h}}_{t+\tau} = 
    \frac{\mathbf{C}_{t+\tau}\,\mathbf{q}_{t+\tau}}{\max\!\Bigl\{\bigl|\mathbf{n}_{t+\tau}^{\!\top}\!\mathbf{q}_{t+\tau}\bigr|,\;1\bigr\}},
}
\]

where division by the denominator (described in detail below) normalises the retrieved signal. The resulting vector is then gated by an output gate \( \mathbf{o}_{t+\tau} = \sigma(\tilde{\mathbf{o}}_{t+\tau}) \) and finally used as hidden state:

\[
\mathbf{h}_{t+\tau} = \mathbf{o}_{t+\tau} \odot \tilde{\mathbf{h}}_{t+\tau}.
\]

Thus retrieval becomes an elementary linear operation rather than an attention softmax over all past positions; this linearity underlies the parallelizability of mLSTM.

---

## Covariance (Outer‑Product) Update Rule and Optimality

The central learning rule that updates the matrix memory follows directly from classical *Bidirectional Associative Memories* (BAMs).  When we observe a key–value pair at time \(t\), we add their outer product to the current memory:

\[
\boxed{\;\displaystyle
   \mathbf{C}_{t} = f_t\,\mathbf{C}_{t-1}
                 + i_t\, (\mathbf{v}_{t}\,\mathbf{k}_{t}^{\!\top}) .
   }\tag{1}
\]

Here:
- The forget factor \(f_t \in [0,1]\) optionally decays older entries.
- The input factor \(i_t>0\) (realised via an exponential activation) scales how strongly we write the new pair.
- The term \(\mathbf{v}_{t}\,\mathbf{k}_{t}^{\!\top}\) is an outer product—a rank‑one matrix whose columns are multiples of \(\mathbf{k}_{t}\).

From a statistical perspective, this rule implements an online estimate of a **covariance matrix** between keys and values.  If inputs are zero‑mean (guaranteed by layer‑normalisation before projection), then accumulating outer products yields an unbiased estimator of 

\[
\mathrm{Cov}[\textbf{V},\,\textbf{K}] = 
    \mathbb E[\textbf V\, \textbf K^{\!\top}],
}
which maximises signal‑to‑noise ratio for later retrieval under Gaussian assumptions (Dayan & Abbott, 1991).  

The optimality claim rests on two observations:

1. **Maximum separability**: When retrieving with query \( \mathbf q = k_i ,\) inner product with stored memories reduces to
   \( (\mathbf v_i^{\,})^\top + {\rm noise}\).
   The variance of that noise is minimised when each key–value pair contributes exactly its outer product—no extra mixing terms—ensuring that different pairs remain orthogonal as much as possible.

2. **Equivalence to Fast Weight Programmers**: Fast weight models rewrite synaptic connections at every step using precisely such rank‑one updates.  Early work (Schmidhuber, 1992; Schlag et al., 2021) proved that when those fast weights decay exponentially (our forget gate), they implement exact gradient descent on an implicit loss defined by stored patterns. Hence Equation (1) inherits those convergence guarantees.

Because each update consists solely of addition and scaling of matrices, it can be implemented with highly optimised BLAS routines on GPUs.  Moreover, since each time step writes only one outer product, there are no data dependencies across positions beyond the cumulative sum; this enables us to reformulate recurrence as a parallel scan operation.

## Normaliser Vector \(\boldsymbol n_t\) for Scaling the Retrieved Output

If we naïvely retrieved by multiplying \( \mathbf C_t \nobreakspace ×\nobreakspace \mathbf q_t ,\) we would quickly encounter numerical instability:  
- The forget gate may shrink entries toward zero, while exponential input gates may cause rapid growth.
- Keys are not guaranteed to have unit norm after projection; their magnitudes affect downstream scaling.

To address this, mLSTM maintains a companion **normaliser state** \( \mathbf n_t ∈ ℝ^{d}\):

\[
\boxed{\;\displaystyle
   \mathbf n_{t}= f_t\,\mathbf n_{t-1}+ i_t\,\mathbf k_{t}.
   }\tag{2}
}
This recurrence mirrors Equation (1) but tracks only “how much” key mass has been injected up to time \(t.\)

During retrieval we compute a scalar denominator

\[
d_t = 
   \max
   \Bigl(
      |\;\!\,\mathbf n_{t}^{\,T}\!\;\! \mathbf q_{t}|,\;
      1
   \Bigr),
}
which is guaranteed never to fall below 1.  Dividing by \(d_t\) normalises the magnitude of 
\( {\bf C}_t {\bf q}_t.\)

Intuitively,
- The numerator accumulates contributions from all past keys weighted by their values,
- The denominator records total “key strength” contributed so far,
so their ratio approximates an average value per unit key mass—an operation akin to dividing by a running count in stochastic averaging.

Using absolute value before taking max ensures that when query and accumulated key vector become orthogonal (dot product near zero), we fall back on safe scaling rather than blowing up or collapsing to zero.

## Parallel Implementation and Relation to Fast Weight Programmers

Because both recurrences (Equations (1)–(2)) are *linear* in their previous states,
they belong to a broad class known as **linear recurrences with constant coefficients**.  
On modern GPUs one can compute all intermediate states simultaneously using an *exclusive scan* algorithm:

1. Construct tensors holding all projected keys \(K = [\,k_1,\dots,k_T\,]\),
   values \(V = [\,v_1,\dots,v_T\,]\),
   forget factors \(F=[\,f_1,\dots,f_T\,]\),
   input factors \(I=[\,i_1,\dots,i_T\,]\).
2. Compute cumulative products of forgets:
   \(p_t = f_t f_{t-1} … f_1.\)
3. Using these products we rewrite Equation (1) as  
   \( {\bf C}_T = 
       p_T {\bf C}_0
       + 
       Σ_{τ=1}^{T} p_T/p_τ· i_τ·(v_τ k_τ^{T}), 
   }\)
   which can be evaluated with batched matrix multiplications after an elementwise weighting step.
4. An analogous scan yields all normaliser vectors \( {\bf n}_τ.\)

Thus every time step’s contribution is computed in parallel, followed by an efficient prefix‑sum reduction—a pattern identical to what FlashAttention or recent linear Transformers exploit for quadratic‑to‑linear reductions.

The resulting algorithm bears strong resemblance to **Fast Weight Programmers**, where “fast weights” correspond exactly to our matrix memory \( {\bf C}\).  
In classic Fast Weight literature,
- A decay term implements forgetting,
- An outer‑product stores new associations,
- Retrieval occurs via multiplication with a probe vector.
Our mLSTM adds two modern ingredients:
- Learned exponential gating (\(i_t=\exp(\tilde i_t)\), possibly also exponentiated forget),
- A normaliser state guaranteeing stable scaling.

Both these enhancements preserve differentiability and enable end‑to‑end training alongside large language modeling pipelines.

### Summary

The mLSTM component transforms recurrent sequence processing from a scalar additive update into a high‑capacity associative memory governed by simple linear algebra:

| Aspect | Classic LSTM | mLSTM |
|-------|--------------|-------|
| Memory type | Scalar \(c_t ∈ ℝ.\) | Matrix \( {\bf C}_t ∈ ℝ^{d×d}.\) |
| Update rule | Additive weighted sum | Covariance‐style outer product: \(f_t {\bf C}_{t-1}+ i_t {\bf v}_tk_t^{T}.\) |
| Retrieval | Nonlinear squashing via \(ψ(c_t).\) | Linear query multiplication \( {\bf C}_t{\bf q}_t / d_t.\) |
| Parallelism | Sequential due to hidden‑hidden mixing | Fully parallelizable via scan/ prefix sum |
| Storage capacity | One degree of freedom per cell | Up to \(d^2.\) |

By grounding its design in associative memory theory and fast weight programming, mLSTM achieves **high storage capacity**, robust retrieval through normalisation, and **perfectly parallelizable computation**, making it well suited for scaling LSTMs up to billions of parameters while retaining many advantages traditional recurrent networks provide for state tracking tasks.

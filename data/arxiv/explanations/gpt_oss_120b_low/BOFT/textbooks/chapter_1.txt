\title{A Textbook about the Paper: "Parameter-Efficient Orthogonal Finetuning via Factorization"}

Chapter 1: Motivation and Background for Parameter‑Efficient Finetuning  

## Scaling of foundation models and the finetuning problem  

In the last few years, the field of artificial intelligence has been driven by ever larger **foundation models**—deep neural networks pre‑trained on massive corpora of data and then repurposed for a multitude of downstream tasks.  Notable examples include GPT‑3, which contains roughly $175\text{B}$ parameters, and Stable Diffusion, a large text‑to‑image diffusion model.  The performance of these systems improves dramatically as the number of parameters grows, but the sheer size also makes **training from scratch** practically impossible for most research groups: the required compute budget, memory footprint, and energy consumption far exceed what can be afforded outside a handful of industrial labs.

Consequently, the community has shifted its focus from building ever larger models to **adapting** existing pretrained models to new tasks.  The adaptation step—often called **finetuning**—must satisfy two competing requirements.  First, we wish to preserve as much of the knowledge acquired during pretraining as possible, because that knowledge is precisely what grants the model its strong generalization abilities.  Second, we must keep the number of trainable parameters small so that the adaptation does not become as costly as a full retraining.  This tension motivates a line of research that we refer to as **parameter‑efficient finetuning** (PEFT).

Mathematically, let $\mathbf{W}^{0}\in\mathbb{R}^{d\times n}$ denote the weight matrix of a pretrained linear layer (or a block that can be reshaped into a matrix).  A naïve full finetuning replaces $\mathbf{W}^{0}$ with an independently learned matrix $\mathbf{W}^{\text{new}}$, requiring $dn$ trainable parameters and typically incurring a non‑trivial increase in inference latency because the full set of weights must be stored and multiplied at test time.  When $d$ and $n$ are each in the thousands or millions, this approach quickly becomes infeasible.

The **Orthogonal Finetuning (OFT)** paradigm introduced by Qiu *et al.* (2023) offers a more principled alternative: instead of learning an arbitrary new matrix, one learns an orthogonal transformation $\mathbf{R}\in\mathbb{R}^{d\times d}$ and updates the layer as
\[
\mathbf{z}= (\mathbf{R}\,\mathbf{W}^{0})^{\!\top}\mathbf{x},
\]
where $\mathbf{x}\in\mathbb{R}^{d}$ is the input vector and $\mathbf{z}\in\mathbb{R}^{n}$ is the output.  Orthogonality ($\mathbf{R}^{\!\top}\mathbf{R}=\mathbf{I}_{d}$) guarantees that pairwise angles between neurons are preserved \cite{liu2018learning,qiu2023controlling}, which in turn helps retain the semantic structure learned during pretraining.  However, a dense orthogonal matrix contains $\mathcal{O}(d^{2})$ free parameters—still too many for large $d$—so OFT introduces a block‑diagonal structure to reduce this cost at the price of expressive power.

The remainder of this chapter surveys the broader landscape of finetuning techniques against which OFT and its later butterfly‑based improvement (BOFT) are positioned.

## Overview of model finetuning, adapter tuning, and prompt tuning  

Three major families of PEFT have emerged:

1. **Model finetuning** – The architecture remains unchanged; only a subset of existing weights is updated.  Classical approaches simply apply stochastic gradient descent with a small learning rate so that the updated model stays close to its pretrained initialization \cite{raffel2020exploring}.  OFT belongs to this family but replaces additive updates with a *multiplicative* orthogonal transformation.

2. **Adapter tuning** – A small set of newly introduced parameters is inserted into each layer (often as bottleneck MLPs) while the original weights stay frozen \cite{houlsby2019parameter}.  During forward passes, the adapter’s output is added to or concatenated with the original activation, allowing task‑specific adjustments without altering the bulk of the pretrained network.

3. **Prompt tuning** – Instead of touching internal weights at all, one prepends trainable “prompt” tokens or embeddings to the input sequence \cite{lester2021power}.  The model processes these tokens together with the original input; learning only modifies these prompts while leaving every weight unchanged.

All three families share two essential goals: (i) keep **inference latency** low—no additional expensive computation should be required after adaptation; (ii) achieve **parameter efficiency**—the number of trainable parameters should be orders of magnitude smaller than that of the full model.

Adapter tuning and prompt tuning typically add *new* parameters rather than modifying existing ones; consequently they may increase memory usage slightly at inference time because extra matrices or embeddings must be stored alongside the frozen backbone.  By contrast, model finetuning methods such as OFT preserve *exactly* the original parameter count at inference because once training finishes we can absorb any learned transformations (e.g., multiply $\mathbf{R}$ into $\mathbf{W}^{0}$).  This property makes model finetuning especially attractive for latency‑critical applications.

## Limitations of full finetuning and parameter‑efficient alternatives  

Full finetuning—updating every parameter in $\mathbf{W}^{0}$—offers maximal expressivity: any target function can be represented given sufficient data and compute.  Yet in practice it suffers from several severe drawbacks when applied to today’s foundation models:

* **Resource consumption** – The optimizer must maintain momentum buffers for all $dn$ parameters; GPU memory scales linearly with model size.
* **Overfitting risk** – With billions of tunable weights and relatively few task‑specific examples, gradient descent can easily memorize the downstream data rather than learning robust adaptations.
* **Catastrophic forgetting** – Large updates can destroy useful representations learned during pretraining, harming generalization on out‑of‑distribution inputs.
* **Inference overhead** – Even if training succeeded, storing an entirely new set of weights doubles memory requirements at deployment.

Parameter‑efficient alternatives mitigate these issues by deliberately constraining how much they are allowed to modify:

* In **adapter tuning**, only $k\ll d$ hidden units per layer are trained; this reduces trainable parameters to $\mathcal{O}(k\,d)$ but introduces an extra forward pass through each adapter module.
* In **prompt tuning**, only a few hundred prompt embeddings are learned regardless of model depth; however this method works best for tasks that can be expressed through input conditioning.
* In **orthogonal finetuning**, one learns a single orthogonal matrix per layer.  When parameterized densely it still costs $\mathcal{O}(d^{2})$, but clever sparsity patterns—such as block‑diagonal or butterfly factorizations—reduce this to $\mathcal{O}(d\log d)$ while preserving essential geometric properties.

The choice among these strategies hinges on trade‑offs among **expressivity**, **regularity**, and **computational budget**.  OFT’s orthogonal constraint provides strong regularity (preserving angles and spectral norm), which empirically yields more stable training than low‑rank additive methods such as LoRA \cite{hulora2022}, but its original block‑diagonal implementation imposes an undesirable inductive bias because dimensions are arbitrarily partitioned.

## Key concepts: parameter efficiency, inference latency, and knowledge preservation  

Before proceeding to more advanced constructions like Orthogonal Butterfly Finetuning (BOFT), it is useful to formalize three concepts that recur throughout PEFT literature.

1. **Parameter efficiency** refers to reducing the number $p_{\text{train}}$ of *trainable* parameters relative to the total number $p_{\text{total}}$ in the pretrained model.  A method is said to be $\alpha$‑parameter efficient if $p_{\text{train}}\leq \alpha\,p_{\text{total}}$, where typical values for $\alpha$ range from $10^{-4}$ (LoRA with rank 1) to $10^{-2}$ (adapter modules).  BOFT achieves parameter efficiency by representing an orthogonal matrix as a product of $m$ sparse butterfly components; each component contributes only $\frac12(b-1)d$ learnable entries, yielding overall complexity $\mathcal{O}(d\log d)$ instead of $\mathcal{O}(d^{2})$.

2. **Inference latency** captures additional wall‑clock time needed when deploying a finetuned model compared with using the frozen backbone alone.  Additive approaches (adapters) require extra matrix multiplications during forward passes; prompt methods increase token length but otherwise keep layerwise computation unchanged.  Pure model finetuning—including OFT and BOFT—incurs *zero* additional latency after training because any learned linear transform can be merged into preexisting weight matrices (e.g., replace $\mathbf{W}^{0}$ with $\mathbf{R}\mathbf{W}^{0}$).

3. **Knowledge preservation** quantifies how much information from pretraining survives after adaptation.  Orthogonal transformations guarantee preservation of pairwise inner products among neuron weight vectors:
   \[
   \langle \mathbf{w}_{i}^{0}, \mathbf{w}_{j}^{0}\rangle
   = 
   \langle \mathbf{R}\,\mathbf{w}_{i}^{0}, \mathbf{R}\,\mathbf{w}_{j}^{0}\rangle,
   \]
   because orthogonal matrices are length‑preserving isometries.  Consequently spectral properties such as singular values remain unchanged:
   \[
   (\mathbf{R}\,\mathbf{W}^{0})^{\!\top}(\mathbf{R}\,\mathbf{W}^{0})
   = (\mathbf{W}^{0})^{\!\top}(\mathbf{W}^{0}),
   \]
   which has been linked theoretically to improved optimization stability \cite{miyato2018spectral,yoshida2017spectral}.  By respecting these geometric invariants, orthogonal finetuning mitigates catastrophic forgetting while still allowing substantial functional change via rotation in weight space.

In summary, scaling trends in foundation models have rendered full retraining untenable, prompting a wave of PEFT methods that balance expressive adaptation against strict resource constraints.  Model finetuning remains attractive because it avoids extra inference cost; orthogonal finetuning refines this approach by embedding geometric regularity directly into the update rule.  The subsequent chapters will delve into how butterfly factorizations transform this idea into a highly parameter‑efficient scheme without sacrificing expressivity—a development we refer to as Orthogonal Butterfly Finetuning (BOFT).

**Orthogonal Finetuning (OFT): Principles and Limitations**

---

# Geometric motivation: preserving pairwise neuron angles  

When a deep neural network is pretrained on a large corpus, its weight matrices encode rich relational information among neurons. A neuron in a linear layer can be identified with a column vector of the weight matrix, and the *pairwise angle* between two such column vectors reflects how similar or complementary the corresponding features are. If finetuning dramatically reshapes these angles, the knowledge acquired during pretraining may be lost, leading to poor generalization on downstream tasks.

Orthogonal transformations offer a principled way to preserve these geometric relationships. An orthogonal matrix \( \mathbf{R}\in\mathbb{R}^{d\times d}\) satisfies
\[
\mathbf{R}^\top \mathbf{R}= \mathbf{I}_d,
\]
which implies that for any two vectors \( \mathbf{u},\mathbf{v}\in\mathbb{R}^{d}\),
\[
\langle \mathbf{R}\mathbf{u}, \mathbf{R}\mathbf{v}\rangle = \langle \mathbf{u},\mathbf{v}\rangle,
\quad
\cos\theta(\mathbf{R}\mathbf{u},\mathbf{R}\mathbf{v}) = \cos\theta(\mathbf{u},\mathbf{v}),
\]
so the angle \(\theta\) between any pair of neurons is exactly preserved. This observation underlies *Orthogonal Finetuning* (OFT): instead of adding arbitrary perturbations to the pretrained weights, we multiply them on the left by an orthogonal matrix that rotates the entire space of neuron representations without altering their mutual geometry.

# Formal definition of OFT: multiplicative orthogonal update  

Consider a pretrained linear layer with weight matrix \( \mathbf{W}^{0}\in \mathbb{R}^{d\times n}\). For an input activation vector \( \mathbf{x}\in\mathbb{R}^{d}\), the original forward computation is
\[
\mathbf{z}= (\mathbf{W}^{0})^{\!\top}\!\mathbf{x}.
\]
OFT replaces this by a *multiplicative* orthogonal update:
\[
\boxed{\;\mathbf{z}= (\mathbf{R}\,\mathbf{W}^{0})^{\!\top}\!\mathbf{x}\;}
\qquad
\text{with } \mathbf{R}\in\mathbb{R}^{d\times d}, \;\; \mathbf{R}^\top \mathbf{R}= \mathbf I_{d}.
\]
All parameters of \( \mathbf{W}^{0} \) remain frozen; only the orthogonal matrix \( \mathbf{R} \) is learned. Because \( \mathbf{R} \) acts uniformly on every column (neuron) of \( \mathbf{W}^{0} \), the transformation respects the geometric motivation described above: all pairwise angles among columns are preserved throughout training.

A key desideratum for any finetuning method is *zero‑initialization*: at the start of training the model should behave exactly like the pretrained model. OFT satisfies this by initializing \( \mathbf R=\mathbf I_d\), which leaves the forward pass unchanged.

# Cayley parameterization of orthogonal matrices  

Directly optimizing over the Stiefel manifold of orthogonal matrices is difficult because naively updating \( \mathbf R \) with gradient descent will typically break orthogonality. Instead, OFT adopts the *Cayley transform*, a classic way to map a skew‑symmetric matrix to an orthogonal one while guaranteeing that orthogonality is preserved for every update.

Let \( \mathbf Q\in\mathbb R^{d\times d}\) be skew‑symmetric, i.e.
\[
\mathbf Q = -\mathbf Q^{\!\top}.
\]
The Cayley transform defines an orthogonal matrix as
\[
\boxed{\;\mathbf R = (\mathbf I + \mathbf Q)\,(\mathbf I - \mathbf Q)^{-1}. \;}
\]
Because any skew‑symmetric matrix has purely imaginary eigenvalues, the denominator \( (\mathbf I-\mathbf Q)\) is always invertible for sufficiently small \( \|\mathbf Q\|_2 < 1.\) During training we parametrize \( \mathbf Q\) directly and update its entries with ordinary gradient steps; after each step we recompute \( \mathbf R\) via the Cayley formula, guaranteeing that the resulting transformation remains orthogonal at every iteration.

Zero initialization is achieved by setting all entries of \( \mathbf Q\) to zero, which yields \( \mathbf R = (\mathbf I + 0)(\mathbf I - 0)^{-1}= \mathbf I.\)

# Block‑diagonal OFT: sparsity vs. expressivity trade‑off  

A dense orthogonal matrix in dimension \( d\times d\) possesses \( d^2\) entries, but only about \( d(d-1)/2\) degrees of freedom due to orthogonality constraints. Directly learning a full dense orthogonal matrix would thus require on the order of \( O(d^2)\) trainable parameters—prohibitively large for modern foundation models where \( d = 1024, 2048,\) or more.

To reduce this cost, the original OFT paper introduced a *block‑diagonal* structure:
\[
\boxed{\;
    \mathbf R = 
    {\rm diag}(\,\underbrace{\mathbf R_1,\dots,\mathbf R_r}_{r~{\rm blocks}}\,),
    \qquad
    \mathbf R_i\,{\in}\,\mathbb R^{b\times b},
    \;
    br = d.
}
\]
Each block \( \mathbf R_i\) is itself an orthogonal matrix (parameterized again via Cayley), but because blocks are independent, only parameters within each block need be learned. The total number of trainable parameters scales as
\[
O(br)=O(bd),
\]
which can be far smaller than \( O(d^2)\) when the block size \( b << d.\)

However, this sparsity comes at a price. The block‑diagonal pattern forces each neuron’s dimensions to be split into disjoint groups (the columns belonging to different blocks). The orthogonal transformation applied to one block never interacts with dimensions belonging to another block; consequently information cannot flow across blocks during finetuning. This imposes a strong inductive bias: only intra‑block rotations are possible, while any transformation that mixes different blocks (e.g., a full Fourier transform or a random dense rotation) lies outside the hypothesis space.

# Analysis of parameter count and inductive biases in block‑diagonal OFT  

### Parameter count  

If we denote by \( b \) the block dimension and by \( r = d/b.\) Each block orthogonal matrix has roughly \( b(b-1)/2 = O(b^2)\) independent degrees of freedom. Since there are \( r = d/b.\) such blocks, the total number of free parameters becomes
\[
r\, O(b^2)= O(bd).
\]
For concrete numbers: with \( d=1024,\) choosing \( b=16,\) yields about \( 16\times1024 = 16\,384$ effective parameters—orders of magnitude smaller than the full dense case (\(\approx10^6.\))

### Inductive bias from block diagonalization  

The block structure introduces two intertwined biases:

1. **Limited mixing across groups** – because each block acts only on its own coordinate subset, any downstream task that would benefit from cross‑group interactions must rely on other components of the model (e.g., later layers or attention heads). This can hinder tasks where global recombination of features is essential.

2. **Regularity towards identity** – when each block starts as an identity matrix (zero initialization of its corresponding skew‑symmetric parameter), early training steps tend to keep each block close to identity. This bias toward small rotations can improve stability and generalization but may also restrict expressive power if larger rotations are required.

Empirically, block‑diagonal OFT has been shown to improve stability compared with additive low‑rank methods such as LoRA, yet its parameter efficiency is still limited because achieving a truly dense orthogonal transformation would demand setting \( b=d,\) which defeats the purpose of sparsity.

Consequently, researchers have sought alternative factorizations that retain dense connectivity while keeping parameter count sub‑quadratic. The *butterfly factorization* introduced later in the paper provides precisely such an avenue: by composing several sparse orthogonal factors arranged in a butterfly topology, one can realize a dense overall rotation with only \( O(d\,\log d)\) trainable parameters, thereby bridging the gap between expressivity and efficiency that block‑diagonal OFT leaves open.

**Information Transmission Perspective on Orthogonal Matrices**

In this chapter we reinterpret the task of building dense orthogonal transformations as an information‑transmission problem on a grid‑structured graph.  This viewpoint, introduced in the paper *Parameter‑Efficient Orthogonal Finetuning via Factorization*, provides a clear and intuitive way to reason about how a dense orthogonal matrix can be assembled from a small number of sparse factors while preserving orthogonality.  By treating the entries of a matrix as potential communication channels between “source” and “receiver’’ nodes, we can formalize the desiderata for a parameter‑efficient factorization and understand why butterfly‑type factorizations succeed where naïve sparsity patterns (e.g., block‑diagonal) fail.

---

### Dense connectivity as a graph problem

Consider a linear layer with a weight matrix \(\mathbf{W}^{0}\in\mathbb{R}^{d\times n}\) that has been pretrained on a massive corpus.  In orthogonal finetuning (OFT) we replace the forward pass

\[
\mathbf{z}= (\mathbf{W}^{0})^{\!\top}\mathbf{x}
\]

by

\[
\mathbf{z}= (\mathbf{R}\,\mathbf{W}^{0})^{\!\top}\mathbf{x},
\qquad \mathbf{R}\in\mathbb{R}^{d\times d}, \ \mathbf{R}^{\!\top}\mathbf{R}= \mathbf{I}_{d},
\]

where \(\mathbf{R}\) is an orthogonal matrix learned during adaptation.  The matrix \(\mathbf{R}\) can be regarded as a **connectivity map** from the \(d\) input dimensions (the “source’’ nodes) to the \(d\) output dimensions (the “receiver’’ nodes).  In this interpretation:

* A non‑zero entry \(R_{ij}\neq 0\) means that information can flow from source node \(j\) to receiver node \(i\).
* A zero entry blocks that flow.

Thus, the full dense orthogonal matrix corresponds to a **fully connected bipartite graph**: every source is linked (directly or indirectly) to every receiver.  Our goal is to reproduce this dense connectivity using far fewer *trainable* edges.

---

### Factorizing a matrix into a product of sparse matrices

A convenient way to obtain many edges from few trainable parameters is to compose several **sparse** matrices:

\[
\mathbf{R}= \underbrace{\mathbf{B}_{m}}_{\text{sparse}}\,
           \underbrace{\mathbf{B}_{m-1}}_{\text{sparse}}\cdots
           \underbrace{\mathbf{B}_{1}}_{\text{sparse}} .
\tag{1}
\]

Each factor \(\mathbf{B}_{k}\in\mathbb{R}^{d\times d}\) can be seen as an adjacency matrix between two consecutive “levels’’ of nodes in a layered graph.  If we unfold the multiplication in (1), we obtain a **grid graph** with \(d\) nodes on each of the \(m+1\) levels (see Figure 2 in the paper).  An edge exists from node \(j\) on level \(\ell\) to node \(i\) on level \(\ell+1\) exactly when the entry \((i,j)\) of \(\mathbf{B}_{\ell+1}\) is non‑zero.  

When we multiply all factors, information propagates level by level: first according to \(\mathbf{B}_{1}\), then \(\mathbf{B}_{2}\), and so on until \(\mathbf{B}_{m}\).  The overall product \(\mathbf{R}\) therefore describes whether *any* path exists from a source node on level 0 to a receiver node on level \(m\).  If for every pair of source and receiver there exists at least one directed path, then the resulting matrix \(\mathbf{R}\) is dense (all entries potentially non‑zero).  

Consequently, designing sparse factors is equivalent to designing **edge patterns** on this layered grid such that every source can reach every sink.

---

### Directed edges, levels, and path‑based dense connectivity

Formally, let the vertices be indexed as  
\(v^{(\ell)}_{i},\, i=1,\dots,d,\; \ell=0,\dots,m\).  
An edge from \(v^{(\ell-1)}_{j}\) to \(v^{(\ell)}_{i}\) is present iff \((\mathbf{B}_{\ell})_{ij}\neq0\).  A **directed path** of length \(m\),

\[
v^{(0)}_{j} \rightarrow v^{(1)}_{i_{1}} \rightarrow v^{(2)}_{i_{2}} 
   \rightarrow \dots \rightarrow v^{(m)}_{i},
\]

corresponds to the product of entries  
\( (\mathbf{B}_{1})_{i_{1}j} (\mathbf{B}_{2})_{i_{2} i_{1}}\cdots (\mathbf{B}_{m})_{i\, i_{m-1}}.\)

If at least one such product is non‑zero, then entry \(R_{ij}\) in the final matrix is non‑zero.  Therefore:

> **Dense connectivity condition.**  
> For every pair \((j,i)\), there must exist at least one directed path from \(v^{(0)}_{j}\) to \(v^{(m)}_{i}\).

This condition translates directly into a graph‑theoretic requirement: the union of edges across all levels must induce a **strongly connected bipartite network** between the first and last layers.

---

### Desiderata: dense connectivity and minimal free edges

When seeking parameter efficiency we must respect two competing desiderata:

1. **Dense connectivity** – as defined above, ensuring that the product matrix can represent any dense orthogonal transformation.
2. **Minimal free edges** – each trainable non‑zero entry corresponds to an adjustable weight in one of the sparse factors.  To keep the total number of learnable parameters low we want as few *free* edges as possible.

In addition, each factor must be orthogonal (or at least full rank), which imposes structural constraints on permissible edge patterns: an orthogonal factor cannot arbitrarily drop edges without breaking invertibility.

The paper points out an important baseline: if we used a single dense orthogonal matrix as a factor, we would have \(d^{2}-d = O(d^{2})\) free edges (subtracting the inevitable \(d\) fixed magnitude‑one entries required for orthogonality).  The butterfly construction dramatically reduces this count to \(O(d\log d)\).

---

### ω‑edge counting under orthogonality constraints

Orthogonality means that each factor satisfies  

\[
\mathbf{B}_{k}^{\!\top}\mathbf{B}_{k}= \mathbf{I}_{d},
\qquad k=1,\dots,m .
\tag{2}
\]

Equation (2) forces each factor to be **bijective** between its input and output levels; consequently each level must contain exactly \(d\) edges that form disjoint perfect matchings (for binary sparsity patterns these are permutations).  These mandatory edges are *not* learnable because in any orthogonal permutation they are forced to be either \(+1\) or \(-1\).  We therefore count only those entries that are adjustable – the **free edges**, denoted by \(\omega_k\).

For any feasible sparse factorization:

* The total mandatory edge count across all levels is at least \(d\,m.\)
* The total free edge count satisfies  

  \[
  \sum_{k=1}^{m} \omega_k = O(d\,m).
  \]

If each factor contains only \(O(d)\) free entries—as is true for butterfly factors—then the overall number of trainable parameters scales as  

\[
O(d\,m)= O(d\,\log d)
\]

when we set \(m = \log_2 d,\) precisely what the butterfly construction achieves.

In contrast, block‑diagonal OFT forces each factor to have a fixed sparsity pattern where blocks are completely isolated; this yields dense connectivity only within each block and therefore fails the dense‑connectivity condition unless many small blocks are used, which dramatically increases parameter count or harms expressivity.

---

### Summary

By reframing orthogonal finetuning as an information transmission problem on a layered grid graph, we obtain a clear criterion for building dense orthogonal matrices from sparse pieces: every source node must be able to reach every sink node through directed paths while using as few adjustable edges as possible.  The butterfly topology satisfies both criteria elegantly—it provides logarithmic depth (\(m = O(\log d)\)) and each layer contributes only linear (\(O(d)\)) free parameters, yielding an overall parameter budget of \(O(d\,\log d)\).  This perspective not only explains why butterfly factorization yields far more parameter‑efficient orthogonal finetuning than naïve block‑diagonal schemes but also opens the door to exploring alternative network topologies from computer networking or coding theory that might further improve sparsity–expressivity trade‑offs.

**Butterfly Factorization: Theory and Construction**

# Cooley‑Tukey FFT and Butterfly Graphs  

The celebrated Cooley‑Tukey algorithm provides the first fast method for computing the discrete Fourier transform (DFT).  For an input vector $\mathbf{x}\in\mathbb{R}^{d}$ with $d=2^{N}$, the DFT is the linear map  
\[
\mathbf{y}= \mathbf{F}_{d}\,\mathbf{x},\qquad 
\mathbf{F}_{d}[k,\ell]=\exp\!\bigl(-2\pi i k\ell /d\bigr),
\]  
which would naïvely require $O(d^{2})$ arithmetic operations.  Cooley and Tukey observed that the DFT can be decomposed recursively into two DFTs of half the size, yielding the recurrence  
\[
\mathbf{F}_{d}= \underbrace{\begin{bmatrix}
\mathbf{I}_{d/2}& \mathbf{I}_{d/2}\\[2pt]
\mathbf{I}_{d/2}& -\mathbf{I}_{d/2}
\end{bmatrix}}_{\text{butterfly}}\;
\bigl(\mathbf{F}_{d/2}\oplus \mathbf{F}_{d/2}\bigr)\;
\underbrace{\begin{bmatrix}
\operatorname{diag}(\omega^{0}) & \\ & \operatorname{diag}(\omega^{1})\\[-4pt]
 & \ddots \\[-4pt]
 & & \operatorname{diag}(\omega^{d/2-1})
\end{bmatrix}}_{\text{twiddle factors}},
\]  
where $\omega=\exp(-2\pi i/d)$ and $\oplus$ denotes block‑diagonal concatenation.  The central $2\times 2$ block matrix is called a **butterfly** because it connects each pair of “even’’ and “odd’’ indices, exactly as a butterfly’s wings cross.  

If we draw each stage of the recursion as a layer of nodes, edges exist only between nodes belonging to adjacent layers, and every edge corresponds to a non‑zero entry in the matrix that implements that stage.  The resulting layered digraph is known as a **butterfly graph**.  A key property of this graph is that a source node at the first layer can reach any sink node at the final layer using exactly $N=\log_{2} d$ edges; consequently, the total number of edges scales as $O(d\log d)$.  This sparsity pattern underlies the reduction from $O(d^{2})$ to $O(d\log d)$ arithmetic complexity in the FFT.

# Definition of Butterfly Factors and Recursive Butterfly Matrices  

Motivated by the FFT graph, we formalize a family of sparse matrices that can be multiplied together to obtain a dense transformation while retaining only $O(d\log d)$ trainable parameters.

### Butterfly factor  

For an even integer $k$, define a **butterfly factor** $\mathbf{B}^{F}(k)\in\mathbb{R}^{k\times k}$ as  
\[
\mathbf{B}^{F}(k)=
\begin{bmatrix}
\operatorname{diag}(\mathbf{d}_{1}) & \operatorname{diag}(\mathbf{d}_{2})\\[4pt]
\operatorname{diag}(\mathbf{d}_{3}) & \operatorname{diag}(\mathbf{d}_{4})
\end{bmatrix},
\tag{1}
\]  
where each $\mathbf{d}_{i}\in \mathbb{R}^{k/2}$ supplies independent scalar entries for a diagonal block.  The matrix consists of four diagonal blocks arranged in a $2\times 2$ pattern; all off‑diagonal entries are zero, which yields exactly $k$ non‑zero elements.

### Recursive butterfly matrix  

Let $d=2^{N}$ and let $\tilde{\mathbf B}(d,k)$ denote a block‑diagonal matrix whose blocks are butterfly factors of size $k$:  
\[
\tilde{\mathbf B}(d,k)=
\operatorname{diag}\bigl(\underbrace{\mathbf B^{F}_{1}(k),\,\dots,\, \mathbf B^{F}_{d/k}(k)}_{d/k\; \text{blocks}}\bigr)\in \mathbb {R}^{d\times d}.
\tag{2}
\]  
Using these components we define the **butterfly matrix** recursively:
\[
\begin{aligned}
\mathbf B(d) &=
 \tilde{\mathbf B}\!\bigl(d,d\bigr)
 \begin{bmatrix}
   \mathbf B(d/2) & \mathbf 0\\[2pt]
   \mathbf 0      & \mathbf B(d/2)
 \end{bmatrix} \\[4pt]
&= \tilde{\mathbf B}(d,d)\,
   \tilde{\mathbf B}\!\bigl(d,d/2\bigr)\,
   \tilde{\mathbf B}\!\bigl(d,d/4\bigr)\,
   \cdots\, 
   \tilde{\mathbf B}(d,2).
\end{aligned}
\tag{3}
\]  
Each multiplication introduces a new set of edges between two consecutive layers of the information‑transmission graph; after $\log_{2} d$ stages every source node can reach every sink node.  Because each $\tilde{\mathbf B}(d,k)$ contains only $d$ non‑zero entries (one per row), the total number of stored scalars after $\log_{2} d$ stages is $O(d\,\log d)$.

# Block‑Butterfly Components and Permutation Structure  

The formulation above uses scalar entries in each diagonal block.  To increase flexibility without breaking sparsity we replace each scalar by a small dense matrix of size $b\times b$.  Let $b$ divide $d$, and define a **block butterfly factor** $\mathbf B^{F,b}(k)$ by substituting each scalar $\; d_{i,j}$ in (1) with an independent trainable matrix $\;\mathbf D_{i,j}\in \mathbb {R}^{b\times b}$:
\[
\mathbf B^{F,b}(k)=
\begin{bmatrix}
\operatorname{blockdiag}(\!\mathbf D_{1,1},\, … ,\, \mathbf D_{1,k/2}\!) &
\operatorname{blockdiag}(\!\mathbf D_{1,k/2+1},\, … ,\, \mathbf D_{1,k}\!)\\[6pt]
\operatorname{blockdiag}(\!\mathbf D_{2,1},\, … ,\, \mathbf D_{2,k/2}\!) &
\operatorname{blockdiag}(\!\mathbf D_{2,k/2+1},\, … ,\, \mathbf D_{2,k}\!)
\end{bmatrix},
\]  
where each block diagonal term contains $b\times b$ sub‑matrices placed along its diagonal.  The resulting $\tilde{\mathbf B}^{b}(d,k)$—the block‑diagonal stacking analogue of (2)—has exactly $d/b$ blocks, each of size $k$, and therefore still contributes only $O(d)$ trainable parameters per stage.

A crucial observation is that all butterfly components differ from one another only by **permutations of rows and columns**.  When we move from $\tilde{\mathbf B}^{b}(d, k)$ to $\tilde{\mathbf B}^{b}(d, k/2)$ we essentially regroup the existing blocks according to a perfect shuffle permutation (the same permutation used in the FFT).  Consequently, once we have learned the set of small matrices $\{\mathbf D_{i,j}\}$ for one stage, later stages reuse them with systematic index shuffling; this is why the overall parameter budget grows only linearly with the number of stages.

# Ensuring Orthogonality of Each Component  

Our ultimate goal is to construct a dense orthogonal matrix $\mathbf R$ as a product of several sparse orthogonal factors:
\[
\boxed{\displaystyle 
   \mathbf R = 
   \prod_{\ell=1}^{m}\tilde{\mathbf B}^{b}_{(\ell)} },
   \qquad 
   (\tilde{\mathbf B}^{b}_{(\ell)})^{T}\tilde{\mathbf B}^{b}_{(\ell)}=
   \tilde{\mathbf B}^{b}_{(\ell)} (\tilde{\mathbf B}^{b}_{(\ell)})^{T}= 
   \mathbf I_{d}.
   } 
   \tag{4}
]  

Because orthogonal matrices form a group under multiplication, it suffices to enforce orthogonality on each factor individually.  Two standard constructions are used:

### (i) Cayley transform on each sparse factor  

Every real skew‑symmetric matrix $\boldsymbol Q=-\boldsymbol Q^{T}$ defines an orthogonal matrix via the Cayley map
\[
   \mathcal C(\boldsymbol Q)= (\boldsymbol I+\boldsymbol Q)(\,\boldsymbol I-\boldsymbol Q)^{-1}.
   \tag{5}
]  
In practice we apply (5) separately to each dense block inside a butterfly factor (or to each $2\times 2$ scalar factor).  The transformation preserves differentiability and guarantees exact orthogonality throughout training.

### (ii) Direct parameterization as $2\times 2$ rotations  

When $b=1$, every butterfly factor reduces to a collection of independent $2\times 2$ blocks
%
\[
   \begin{bmatrix}
      c & -s\\[2pt]
      s & c
   \end{bmatrix},
   \qquad c=\cos \theta,\; s=\sin \theta,
   \tag{6}
]  
%
parameterized by an angle $\theta$.  Enforcing this structure automatically yields an orthogonal block because any rotation matrix satisfies $\boldsymbol R^{T}\boldsymbol R=\boldsymbol I$.  For larger blocks $(b>1)$ we embed an arbitrary orthogonal matrix (e.g., via QR decomposition or successive Givens rotations) inside each $2b\times 2b$ sub‑block, again guaranteeing orthogonality.

Both strategies share two practical advantages: they keep the number of trainable scalars equal to the number of free entries in the sparse factor (i.e., roughly $(b-1)d/2$ per stage), and they guarantee that gradient updates never leave the orthogonal manifold.

# Parameter Count Analysis  

Consider a linear layer with input dimension $d$ and output dimension $n$.  In naïve Orthogonal Finetuning (OFT) we would learn a *full* orthogonal matrix $\boldsymbol R'\in O(d)$ directly; storing an arbitrary element of $O(d)$ requires $(d^{2}-d)/2$ independent parameters because orthogonal matrices have $\frac12 d(d-1)$ degrees of freedom.  Hence OFT’s parameter budget scales as
%
\[
    |\Theta_{\text {full OFT}}| = O(d^{\,2}). 
    \tag{7}
]  

A common remedy is **block‑diagonal OFT**, which partitions $\boldsymbol R'$ into $r = d/b$ blocks of size $b\times b$.  Each block contributes $(b^{\,2}-b)/2$ trainable scalars, giving
%
\[
    |\Theta_{\text {blk}}| = r\, O(b^{\,2})
    = O(b d).
    \tag{8}
]  
When $b$ is modest (e.g., $8$), this yields substantial savings but at the cost of severely constrained expressivity: rows belonging to distinct blocks never interact.

The **Butterfly Orthogonal Finetuning (BOFT)** construction replaces one dense block by a product of $m=\log_{k/(k/2)}(d/k_{\min}) = O(\log d)$ sparse factors, each with exactly $d/b$ non‑zero *trainable* entries. Consequently,
%
\[
    |\Theta_{\text {BOFT}}|
    = m\, O(b d)
    = O( d\, b\, \log d).
    \tag{9}
]  
If we set the smallest block size to its minimal value $b=2$, then
%
\[
    |\Theta_{\text {BOFT}}|
    = O( d\, \log d),
    ] 
which is dramatically smaller than both full OFT ($O(d^{\,2})$) and block‑diagonal OFT with any fixed block size ($O(b d)$).  

To summarize:

| Method | Parameter growth | Typical expressive power |
|--------|------------------|--------------------------|
| Full OFT | $\displaystyle O(d^{\,2})$ | Can represent any orthogonal transformation |
| Block‑diagonal OFT | $\displaystyle O(b d)$ (fixed \(b>1)\) | Limited to independent intra‑block rotations |
| BOFT | $\displaystyle O(d\, b\, \log d)$ → \(O(d\,\log d)\) for \(b=2$\) | Dense orthogonal matrices with structured sparsity; substantially more expressive than block‑diagonal while remaining highly parameter efficient |

Thus butterfly factorization offers an elegant middle ground: it retains enough degrees of freedom to approximate arbitrary orthogonal maps while requiring only logarithmically many extra parameters compared with naïve dense parametrizations.

By defining butterfly factors, recursing over them, and enforcing orthogonality via either Cayley transforms or explicit rotations, we obtain **Orthogonal Butterfly**—a compact yet expressive parameterization that underpins modern parameter‑efficient finetuning methods such as BOFT.

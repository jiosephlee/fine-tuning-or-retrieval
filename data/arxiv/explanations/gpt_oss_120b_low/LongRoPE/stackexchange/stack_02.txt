\title{Stack Exchange of the Paper: "LongRoPE: Extending LLM Context Window Beyond 2 Million Tokens"}

### What is the intuition behind keeping the first \(\hat n\) tokens un‑interpolated?
Question:
The authors claim that the initial tokens receive large attention scores and therefore should be exempt from positional interpolation (Finding 2). Why does reducing interpolation for these early positions improve perplexity? Is there empirical evidence that attention weights are indeed higher for the first few tokens, or is this mainly a heuristic? How does the choice of \(\hat n\) interact with different extension ratios (e.g., 8× vs 64×)?
Answer:
The short‑answer is that the very first tokens of a sequence are repeatedly used as “reference points’’ in the attention maps of a transformer, so the model relies on them more heavily than on later tokens.  
If those early positions are altered by the same aggressive RoPE‑interpolation that is applied to the rest of the sequence, their rotary angles become under‑discriminative: many distinct positions collapse onto almost the same set of sinusoidal values and the attention scores that should be concentrated on the first few tokens are consequently weakened.  
By leaving the rotary angles of the first \(\hat n\) positions untouched (i.e. \(\mathbb I(\hat\lambda_i,\hat n)=1\) for \(n<\hat n\)), we preserve the original geometry of the pre‑trained RoPE for exactly those positions that receive the largest attention weights. This simple “protect‑the‑head’’ step reduces the amount of information loss introduced by interpolation and therefore lowers next‑token loss (perplexity) on long‑context evaluations.

### Why does this help perplexity?

In a standard multi‑head self‑attention layer each query \(q_n\) is compared with all keys \(k_m\) via a dot product
\[
\mathrm{score}(n,m)=\frac{q_n^\top k_m}{\sqrt{d}}\,,
\]
where \(q_n,k_m\) already contain the RoPE rotation \(\mathrm{R}(n)\) (or \(\mathrm{R}(m)\)).  
Because of the triangular causal mask used for language modelling, token \(n\) can only attend to positions \(m\le n\). Consequently, early tokens (small \(n\)) appear in *every* subsequent query’s key set and contribute to a large fraction of the total attention mass. Empirically, streaming‑LLM and LM‑Infinite papers report that the average attention weight assigned to token 0 is often an order of magnitude larger than that assigned to token \(L-1\).  

When we interpolate RoPE uniformly with a factor \(\lambda=s>1\) (the naïve PI rule), we shrink all angles by \(1/s\). For high‑frequency dimensions this “crowding’’ effect is especially severe: \(\cos(n\theta_i/s)\) varies slowly with \(n\), so queries cannot differentiate nearby early positions. The loss in discriminability shows up as a higher cross‑entropy loss on the validation set, i.e. a higher perplexity.

By exempting the first \(\hat n\) positions we keep their original high‑frequency angles intact, preserving their discriminative power. The remaining positions still receive a rescaling factor \(\lambda_i\ge 1\), which spreads them out enough to avoid excessive crowding at long range. The net effect is a smoother trade‑off: early tokens keep their strong influence, while later tokens are allowed to be “stretched’’ to accommodate the new length. In practice this reduces perplexity by up to 5–10 % on 8k–32k windows compared with pure PI or NTK interpolation (see Table 2 of the paper).

### Is there empirical evidence that early tokens get larger attention scores?

Yes. The authors refer to the observations made in **Streaming LLM** and **LM‑Infinite**, both of which analyse per‑position attention distributions and find that the first few hundred tokens dominate the attention mass in causal models. In their own ablation (Table 3), they explicitly measured perplexity while varying \(\hat n\in\{0,2,4,\dots ,256\}\). The curve shows a clear dip when \(\hat n>0\), confirming that preserving those positions indeed improves language modelling performance.

### How does \(\hat n\) interact with different extension ratios?

The optimal size of \(\hat n\) grows with the extension ratio because two opposing forces become stronger:

1. **More interpolation pressure** – when we extend from 4k to 256k (\(s=64\times\)), each RoPE dimension must be stretched much more; if we left all positions interpolated we would severely collapse early angles.
2. **Longer effective context** – as we move farther from the start of the sequence, later tokens become relatively less important for any given prediction, so protecting a larger prefix does not hurt downstream capacity.

Empirically (see Table 3), for an 8k extension (\(s=2\times\)) a tiny prefix such as \(\hat n=8\) already yields most of the benefit; for a 32k extension (\(s=8\times\)) \(\hat n=64\) is better; and for 256k (\(s=64\times\)) the best value moves to \(\hat n=128\!-\!256\). Beyond a certain size (e.g., \(\hat n>256\)) there is diminishing return because those extra protected positions are rarely attended to after they fall outside most queries’ receptive fields.

In short:

* The first \(\hat n\) tokens receive disproportionately large attention weights.
* Interpolating them would make those weights less reliable, hurting next‑token prediction.
* Keeping them un‑interpolated preserves their original high‑frequency RoPE geometry, which empirically lowers perplexity.
* The appropriate \(\hat n\) grows with the target extension ratio because larger ratios require more aggressive stretching of later positions while still needing to keep early positions intact.

Thus Finding 2 in *LongRoPE* is not just a heuristic; it is grounded in measured attention distributions and validated by systematic ablations across several extension factors (8×, 16×, 64×, etc.).

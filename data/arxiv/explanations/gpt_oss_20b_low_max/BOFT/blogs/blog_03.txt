# From Block Diagonal to Butterfly: The Evolution of Orthogonal Finetuning

Orthogonal Finetuning (OFT) was a neat idea: instead of drifting a huge weight matrix with gradients, we rotate all the activations inside a layer with a single orthogonal matrix. The rotation keeps pairwise angles between neurons intact, helping the model keep its pre‑training knowledge while learning a new task.  
In its first incarnation, OFT used a **block‑diagonal** orthogonal matrix. That packed the rotating “pieces” into small blocks, dramatically cutting the number of trainable parameters. The trade‑off? The rotation was *local* – every group of neurons was rotated by its own tiny block and never talked to neurons in other groups.  

The new **Orthogonal Butterfly (BOFT)** takes these constraints and turns them into a structured, information‑propagating design borrowed from the famous Cooley‑Tukey Fast Fourier Transform (FFT). Below is a walk‑through of why the switch matters—examining expressivity, parameter counts, inductive bias, and giving you clear before/after illustrations.

---

## 1. A Quick Recap: What OFT Does

| Step | Plain finetune | OFT (Block‑diagonal) |
|------|-----------------|----------------------|
| Weight update | Additive change \(W^{\text{fin}} = W^0 + \Delta W\) | Multiplicative change \(W^{\text{fin}} = R \cdot W^0\) |
| Rotational preservation | None | Angles between neurons are preserved because \(R^\top R = I\) |
| Trainable parameters | Millions (full weight) | \(b d\) where \(b\) is block size (small) |

**Block‑diagonal structure**:  
If your layer has dimension \(d=512\), you can split it into \(r=32\) blocks of size \(b=16\). Each block is an independent small orthogonal matrix. The advantage: only \(\frac{1}{2}(b-1)d\) free parameters (≈4 k). The drawback: no “cross‑block” interference; as you’ll see later, this limits what rotations are possible.

## 3. Cue the Butterfly!

### 3.1 Information Transmission View

Imagine each neuron as a node on a grid. A dense orthogonal matrix is like a fully connected graph—every node can send information to every other node in one step.

Instead of closing all the edges at once (`O(d²)` parameters), we *factorize* this dense graph into sequences of sparse graphs:

```
R = B_m · B_{m−1} · … · B_1
```

Each `B_i` only connects local pairs but when stacked together they let any start node reach any end node—a **dense connectivity** with far fewer edges.

### 3.2 Butterfly Factorization

The Cooley–Tukey FFT splits data hierarchically:

```
B(d):     d × d butterfly matrix
        = ˜B(d,d) · ˜B(d,d/2) · … · ˜B(d,2)
```

Each `˜B(d,k)` is itself block‑diagonal with `k × k` sub-butterflies—exactly the sparsity pattern BOFT uses.

*Why butterflies?*  
Because a `d`-point FFT can be implemented in `O(d log d)` multiplications—exactly how we want our parameter count to scale! We translate that intuition into *orthogonal matrices*: each sparse factor is enforced to be orthogonal via Cayley parameterization.

---

## 4. The New Formulation: BOFT

Let’s distill the math into bite‑sized chunks:

- **Orthogonal factor**:
  
  \[
    B^F(k)=
    \begin{bmatrix}
      \operatorname{diag}(d_1)&\operatorname{diag}(d_2)\\[4pt]
      \operatorname{diag}(d_3)&\operatorname{diag}(d_4)
    \end{bmatrix}
    \in\mathbb{R}^{k\times k}
  \]

- **Full butterfly matrix** (recursive):
  
  \[
    B(d)=\tilde{B}(d,d)\tilde{B}(d,\tfrac d2)\cdots \tilde{B}(d,2)
  \]

- **Parameterized orthogonal product**:
  
  \[
    R(m,b)=\prod_{i=1}^{m}\tilde{B}^{\,b}_{(d,i)} 
      \quad\text{s.t.}\quad
      \tilde{B}^{\,b}_{(d,i)}^\top
      \tilde{B}^{\,b}_{(d,i)}=\mathbf I_d
  \]

Here:
- `m` = number of butterfly layers.
- `b` = size of base blocks (e.g., `b=2` gives vanilla butterfly).
- For `m=log₂ d`, we get exactly an `O(d log d)` parameter budget.

After training finishes, we **collapse** the product `R(m,b)` into one dense orthogonal matrix and merge it with the frozen pretrained weights—no extra inference cost.

## 6. Quantitative Gains

| Method | Params per layer | Accuracy gain (@10% fine‑tune budget) |
|--------|-------------------|---------------------------------------|
| OFT blk‑diag (`b=32`) | ≈ 160 k | +0.8 % |
| BOFT (`m=log₂ d`, `b=2`) | ≈ 25 k | +1.6 % |

*Note:* The experiments reported in the paper span vision transformers, large language models, and diffusion models—all seeing similar trends.

---

## 7. Inductive Bias & Generalization

Butterfly factorization carries an implicit bias toward transforms that are *well understood* (FFT, Hadamard). This structured inductive bias:

- Helps avoid overfitting when few target data are available.
- Preserves spectral norms of pretrained weights—improving stability.
- Enables smooth interpolation between identity and arbitrary rotations via multiplicative dropout.

In short: a cleaner hypothesis space → better generalization.

---

## 8. Gotchas & Future Directions

- **Training speed:** Each forward pass now multiplies through several sparse matrices; runtime overhead is modest (~5–10%) but worth noting.
- **Alternative topologies:** Think beyond butterflies—any network that satisfies densely reachable pairs could be mined from computer‑network research.
- **Automatic design:** Future work could learn optimal number of layers (`m`) or block sizes (`b`) per layer automatically.

---

## 9. Takeaway

Switching from local block rotations to global butterfly factorizations turns **parameter efficiency** into an explicit *graph problem*. We keep what mattered most about OFT—angle preservation—and massively boost expressivity without blowing up the parameter budget or hurting inference speed.

So next time you’re finetuning a gigantic foundation model but fear runaway costs: give BOFT another look—and enjoy learning rotations that feel just like FFTs but for neural networks!

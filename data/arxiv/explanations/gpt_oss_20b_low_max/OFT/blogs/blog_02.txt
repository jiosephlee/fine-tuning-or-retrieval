# Orthogonal Finetuning Unpacked: A Hands‑On Guide for Adapting Diffusion Models

> In this post we dive into the *Orthogonal Finetuning* (OFT) trick that lets you glue a few extra neurons on top of a big diffusion model without blowing up the number of learnable parameters or losing the model’s pre‑trained vibe.  
> We’ll walk through the core idea – rotating all neurons in a layer – and then show you how to do it efficiently with a Cayley transform and a block‑diagonal trick.  Finally we’ll give you some tips to keep training stable.

---

## 1. Why do we care about **angles**?

Diffusion models, like Stable Diffusion or Imagen, are massive neural nets where each weight matrix \(\mathbf{W}\) can have millions of parameters.  When we finetune them for a downstream task (say, wig‑in‑human faces, image‑to‑image translation, etc.) we really want to keep the *semantic* structure that the model already knows.

**The observation**  
When you normalize every neuron \(\mathbf{w}_i\) to unit length (\(\hat{\mathbf{w}}_i = \mathbf{w}_i/\|\mathbf{w}_i\|\)) and look at all pairwise angles on the *unit hypersphere*, you get what’s called **hyperspherical energy**. This energy measures how *uniform* the neurons are on that sphere:

\[
\text{HE}(\mathbf{W}) = \sum_{i \neq j}\|\hat{\mathbf{w}}_i-\hat{\mathbf{w}}_j\|^{-1}.
\]

If you rotate all neurons by the same matrix \(\mathbf{R}\), every angle stays exactly the same, so HE stays unchanged.

**Why does that matter?**

| Learning method | Feature preserved | Effect |
|-----------------|-------------------|--------|
| Small LR finetune | Euclidean distance | May change angles significantly |
| LoRA (low‑rank update) | Adds a low‑rank *shift* | Angles drift – loss of semantics |
| OFT (orthogonal rotation) | **Angles fixed** (hyperspherical energy preserved) | Keeps semantic knowledge unchanged |

By keeping angles fixed, OFT provably preserves the *pairwise relationships* between neurons – the very thing that lets a diffusion model know “what is a face” or “what does an edge look like”.

---

## 2. The core operation: an orthogonal multiplication

For a fully connected layer with weights \(\mathbf{W}^0 \in \mathbb{R}^{d\times n}\) (pre‑trained), OFT learns a single orthogonal matrix for that layer:

\[
\boxed{
\begin{aligned}
\text{forward pass: }~& \mathbf{z} = (\mathbf{R}\,\mathbf{W}^0)^{\!\top}\,\mathbf{x},\\
& \text{s.t. }\;\mathbf{R}^{\!\top}\!\mathbf{R}= \mathbf{I}.
\end{aligned}}
\]

All training happens **inside** \(\mathbf{R}\).  As soon as you have \(\mathbf{R}\), you can drop it from inference: just replace the original weight matrix with \(\mathbf{W}=\mathbf{R}\,\mathbf{W}^0\). No extra runtime cost.

### Pseudo-code sketch

```python
class OFTLayer(nn.Module):
    def __init__(self, W0):
        super().__init__()
        self.W0 = W0.detach()   # frozen original weights
        # learnable skew-symmetric Q (see section 3)
        self.Q = nn.Parameter(torch.zeros_like(W0))

    def forward(self, x):
        R = cayley(self.Q)          # orthogonal matrix
        W = torch.matmul(R, self.W0)
        z = torch.matmul(W.t(), x)
        return z
```

`cayley(Q)` implements \( \mathbf{R} = (\mathbb I+Q)(\mathbb I-Q)^{-1} \).

---

## 3. Efficiently parameterising an orthogonal matrix

A naïve `torch.linalg.qr` or Gram–Schmidt would be too slow for every layer in a huge diffusion model.  Instead we use two tricks:

1. **Cayley parameterisation**  
   Any skew‑symmetric \(Q=-Q^{\!\top}\) produces an orthogonal \(R=(I+Q)(I-Q)^{-1}\). We only train \(Q\), which has \(d(d-1)/2\) free entries instead of \(d^2\).  

2. **Block‑diagonal matrices**  
   Instead of one big \(d\times d\) block we split into `r` smaller blocks along the diagonal:

   ```
   R = diag( R1 , R2 , ... , Rr )
   ```

   Each `Ri` operates on `d/r` dimensional neurons.  
   The number of free parameters drops from \(O(d^2)\) to \(O(d^2 / r)\), and if we share the same block across all channels we'll get an extra saving factor of `r`.  

Both tricks preserve true orthogonality – they just restrict us to matrices that are easier to compute.

### Choosing a block size

- `r = d`: single neurons – gives full flexibility but many parameters.
- `r ≈ sqrt(d)` or `r ≈ log d`: good balance between expressiveness and memory.
- `r` equal to number of input channels in a conv layer makes each block *depth‑wise*—an interpretation that sometimes accelerates training.

---

## 4. Constrained Orthogonal Finetuning (COFT)

Sometimes you want an extra safety net: keep each neuron’s direction close to its original one **and** preserve angles.

COFT enforces:

\[
\|\; R - I \;\|_F \leq \varepsilon,
\]

where `F` denotes Frobenius norm and `I` is identity.  

We impose this by restricting `Q`’s norm during training:

```python
# project Q onto ball radius eps_prime before each optimizer step
Q.data = project_onto_ball(Q.data, eps_prime)
```

The radius ε controls how much the model can drift:
- Large ε → behaves like plain OFT.
- Small ε → stays almost identical to the pre‑trained weights (good for tiny datasets).

## 5. Practical debugging checklist

| Symptom | Likely cause | Fix |
|---------|--------------|-----|
| Model diverges in early epochs | Q has large values → huge rotations | Clamp init Q=0; start with tiny learning rate |
| Generated images look identical to prompts (overfitted control) | Too many epochs or too large ε | Reduce epochs / shrink ε |
| Subject identity lost in DreamBooth style finetuning | R deviated too much from identity → angle drift | Use COFT with tighter ε |
| Training time spikes after adding many layers | Block diagonal not yet shared ⇒ too many params | Share blocks across layers or reduce r |
| Gradient explosions in Q update | Q close to singularity (I-Q near zero) | Add small epsilon in denominator of Cayley inverse |

A good practice is to monitor **hyperspherical energy difference** along training:

```python
he_ref = compute_he(W0)
def compute_he(W):
    normed = W / W.norm(dim=0, keepdim=True)
    diff = torch.cdist(normed.t(), normed.t())
    return diff[~torch.eye(diff.shape[0], dtype=bool)].sum()
```

You should see this value staying close to zero throughout finetuning.

---

## 6. How fast does it converge?

In both subject-driven generation and controllable generation experiments, OFT/COFT typically hit peak performance after only ***8–12 epochs*** on modest datasets – fewer iterations than LoRA or ControlNet.  
Because angle preservation keeps the network in a smooth manifold on the hypersphere, gradients flow without wandering into bad valleys.

Key takeaways:

- **Rotate all neurons in a layer:** preserves hyperspherical energy → keeps semantic knowledge.
- **Cayley + block‐diagonal:** cheap & scalable.
- **Optional radius constraint (COFT):** extra stability.
- **No inference overhead:** just replace weights offline.

Give it a try on your favorite diffusion backbone – you might be surprised at how little tuning is required to get high‑fidelity, accurate control!

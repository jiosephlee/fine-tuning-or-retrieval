\title{A Textbook about the Paper: "QLoRA: Efficient Finetuning of Quantized LLMs"}

Chapter 8: Can QLoRA Match 16-bit Finetuning?

# LoRA defaults are insufficient: need adapters across all linear layers
One of the first empirical observations in the paper is that applying LoRA only to the commonly targeted attention projection matrices (for example, the query and value projections) does not reliably recover the performance of full 16-bit finetuning for larger base models. Intuition for this result comes from understanding where gradients must flow during adapter training. LoRA works by inserting a low-rank update to an existing linear projection so that the family of functions represented by the frozen pretrained weights plus the adapter can approximate the optimally finetuned weights. If the adapter is present in only a small subset of the network’s linear projections, then the expressivity available to correct or adapt representations is concentrated and cannot compensate for distributional or task-specific shifts that require changes in other parts of the network.

Empirically, the paper reports experiments on LLaMA 7B finetuning on Alpaca where expanding the number of adapters to cover all linear layers (i.e., placing LoRA modules at every linear projection inside transformer blocks, not just attention) is critical to match full finetuning performance. The dominant hyperparameter determining parity with full finetuning turned out to be the total number and placement of adapters rather than the LoRA projection rank \(r\). In other words, spreading small adapter modules broadly across the model is more important than making a small number of adapters large. This finding also aligns with the memory analysis: LoRA parameter storage is very small compared to activation and gradient memory, so using more adapters increases representational capacity without causing a prohibitive memory overhead. Practically, the paper concludes that to achieve performance parity with full 16-bit finetuning one should place LoRA adapters on essentially all linear layers in the transformer, not only attention projections.

# NF4 outperforms FP4/Int4 post-quantization
Quantization of weights to k bits requires choosing a discrete set of representable values. The paper introduces a NormalFloat k-bit data type (NFk), derived from the quantiles of a standard normal distribution, then rescaled to match the target storage range (e.g., \([-1,1]\)). The motivation is straightforward: pretrained model weights are empirically close to zero-centered Gaussian-like distributions (up to scaling by a per-block constant). When the source distribution is approximately normal, designing k-bit levels according to the quantiles of a normal gives an information-theoretically optimal allocation of representable values across the input weight mass. In contrast, plain 4-bit floating point (FP4) or 4-bit integer (Int4) schemes impose uniformly spaced representable points (in some transform), which are less matched to the actual distribution of weights.

The paper evaluates NF4 (the 4-bit NormalFloat) against FP4 and Int4 on post-quantization metrics such as zero-shot task accuracy and perplexity across multiple model families (OPT, LLaMA, BLOOM, Pythia) and sizes from 125M up to 13B. The reported results show that NF4 yields substantially better model quality after quantization than FP4 and Int4. In addition, combining NF4 with Double Quantization (quantizing the per-block quantization constants themselves using an inexpensive second-stage quantization) preserves this accuracy while reducing memory footprint. In short, because NF4 places quantization bins where weights are most likely to fall, it reduces the quantization noise that would otherwise hurt downstream performance.

# On GLUE and Super-NaturalInstructions: 4/8/16-bit adapters ≈ full 16-bit
A central empirical claim is that finetuning a quantized base model using adapters can recover the performance of full-precision finetuning. The paper tests this claim on standard supervised benchmarks: GLUE (with RoBERTa-large) and Super-NaturalInstructions (with T5) covering model sizes from 125M to 3B parameters. Across these settings, adapter-based finetuning at multiple precisions—16-bit, 8-bit, and 4-bit storage for the frozen base—replicates the performance of the fully finetuned 16-bit baseline. That is, whether the base weights are stored in BF16 (16-bit) or quantized to 8-bit or 4-bit and left frozen while LoRA adapters are updated, final task metrics (e.g., GLUE accuracy or Super-NaturalInstructions performance) are statistically indistinguishable when training and adapter placement are done correctly.

The intuition behind this finding is that the adapter parameters, though small in number, are sufficient to steer the frozen quantized feature extractor to produce outputs appropriate for the downstream task. Finetuning via adapters only requires accurate gradients through the frozen base to compute adapter updates. By dequantizing to a 16-bit computation type during forward/backward passes, QLoRA preserves enough numerical precision in intermediate operations to allow effective gradient computation for the adapters. Concretely, the paper uses a workflow where weights are stored in NF4 (4-bit) but are dequantized on-the-fly to BF16 for computation; only adapter weights are represented and updated in BF16. This combination allows 4-bit storage without losing optimization fidelity compared to classic 16-bit finetuning.

# At 7B–65B: NF4+DQ matches 16-bit LoRA on MMLU
The paper extends the evaluation to significantly larger decoder-only models (LLaMA) spanning 7B to 65B parameters, assessing upstream instruction-following finetuning outcomes via the MMLU benchmark (5-shot accuracy). Here the setup is particularly relevant because full 16-bit full-model finetuning at 33B and 65B is impractical on commodity hardware, so adapter-based comparisons provide an accessible proxy.

Using NF4 storage for the base model combined with Double Quantization (DQ) for the per-block scales, and employing LoRA adapters at all linear layers, QLoRA recovers the MMLU performance of a 16-bit LoRA baseline across the 7B–65B range. The paper reports that NF4 + DQ matches the 16-bit LoRA MMLU scores, while 4-bit FP4 (plain 4-bit floating) lags the 16-bit brain-float LoRA baseline by about one percentage point. This result demonstrates that: (1) adapter tuning after aggressive quantization can restore academic benchmark performance even at very large scales, and (2) the choice of 4-bit data type matters—NF4 is sufficient to close the gap while FP4 is not.

The mechanism for parity again relies on dequantizing stored NF4 weights into BF16 for computation and computing gradients only for the adapter parameters. Double Quantization reduces the memory overhead of storing many per-block scales without hurting performance, enabling the practical application of these methods at scales that would otherwise require hundreds of gigabytes of GPU memory.

# Where FP4 lags and why
Although both FP4 and NF4 are 4-bit formats, their differing design philosophies lead to different empirical outcomes. FP4 is a small floating-point-like format with a limited set of uniformly structured representable ranges and exponent/mantissa trade-offs. For weight tensors that are approximately normally distributed, FP4’s uniform or floating-grid placement of representable values does not match the empirical distribution of weight values as well as NF4's quantile-based placements. As a result, FP4 can allocate many representable values to regions of weight space that are rarely used and too few to regions with high probability mass, which increases average quantization error.

In experiments on model families and downstream metrics (e.g., zero-shot accuracy, perplexity, and MMLU), FP4 systematically trails NF4 by non-trivial margins. The paper quantifies this effect: in the LLaMA MMLU experiments, QLoRA with FP4 weights lags roughly one percentage point behind BF16 LoRA baselines, whereas QLoRA with NF4 matches them. The practical implication is that with very aggressive quantization (4-bit), the distribution-aware design of NF4 reduces representational mismatch and thus preserves the signal necessary for adapters to succeed. FP4’s poorer matching to weight distributions manifests as residual quantization noise that adapters alone cannot fully compensate for during finetuning.

# Implications: scale by parameter count at lower precision
A notable policy conclusion drawn from the empirical results is that, within a fixed memory or compute budget, it is often more beneficial to increase model parameter count while decreasing parameter precision than to keep fewer parameters at higher precision. In the experiments, moving to larger LLaMA models stored in 4-bit NF4 and adapter-tuned with QLoRA delivered better downstream performance than smaller models at higher precision, holding training budget roughly constant. This suggests a favorable trade-off between model width/scale and numeric precision: quantization allows representing more parameters in the same memory footprint, and provided the quantization is distribution-aware (NF4) and adapters are applied broadly, the extra parameter capacity translates into improved downstream capabilities.

Concretely, because QLoRA makes it feasible to finetune 33B and 65B models on a single 24–48GB GPU, practitioners can choose to train larger base models with 4-bit storage and adapter tuning instead of smaller full-precision models. The combination of NF4 (to minimize quantization error), Double Quantization (to reduce the overhead of storing many per-block scales), and broad LoRA placement (to give adapters sufficient representational coverage) is what enables this scaling strategy without sacrificing performance. The broader lesson is that careful quantization plus parameter-efficient finetuning enables a different axis of model scaling: size in parameters can be preferred to numeric precision when memory is the scarce resource.

# Summary and practical takeaways
The empirical core of the paper establishes that QLoRA—using NF4 storage, Double Quantization of scales, paged optimizers to mitigate memory spikes, and LoRA adapters placed across all linear layers—recovers the performance of full 16-bit finetuning on standard supervised benchmarks and matches 16-bit LoRA on instruction-learning benchmarks such as MMLU across model sizes up to 65B. Key practical lessons are:

- Do not rely on the default practice of applying LoRA only to attention query/value matrices when trying to match full finetuning; instead, place adapters across all linear layers to provide sufficient adaptation capacity.
- Use NF4 rather than FP4 or Int4 for 4-bit storage when weights are approximately normal; NF4’s quantile-informed levels reduce quantization noise.
- Double Quantization compresses per-block quantization constants with negligible quality loss and measurable memory savings.
- With these choices, it becomes advantageous to prefer larger models at lower precision (more parameters stored in 4-bit) over smaller models at higher precision, because adapter finetuning can recover performance lost to quantization.

These findings together show a robust pathway to high-fidelity finetuning under tight memory constraints: distribution-aware 4-bit quantization plus properly distributed adapter capacity yields parity with 16-bit methods and unlocks new practical scaling regimes.

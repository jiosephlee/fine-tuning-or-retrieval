\title{A Textbook about the Paper: "QLoRA: Efficient Finetuning of Quantized LLMs"}

Chapter 4: Double Quantization: Compressing the Scales

# Overhead of per-block scales with small block sizes

Block-wise quantization of large weight tensors is an effective way to avoid the outlier problem: by splitting a tensor into many contiguous blocks and quantizing each block independently, each small block has its own quantization constant (scale) and therefore the limited number of representable bins are used more evenly. However, this benefit comes with a predictable cost: the more blocks you create (i.e., the smaller your block size $B$), the more quantization constants you must store. Each per-block quantization constant is typically stored in a relatively high-precision format (e.g., 32-bit float), and when divided across many parameters the constants add a non-negligible per-parameter memory overhead.

Concretely, suppose a weight matrix $\mathbf{W}$ has $N$ parameters and is quantized with block size $B$ so that there are $n = N / B$ blocks. If each block stores a single 32-bit floating point quantization constant, then the total memory used by these constants is $32 \cdot n$ bits. Averaged over $N$ parameters, that is
\[
\frac{32 \cdot n}{N} = \frac{32}{B}
\]
bits per parameter. For a practical and effective small block size such as $B = 64$, this becomes $32/64 = 0.5$ bits per parameter. For very large models (tens of billions of parameters), $0.5$ bits per parameter corresponds to multiple gigabytes of extra storage just for the scales. Thus, while small block sizes are desirable for quantization precision, they create a meaningful memory overhead from the stored per-block scales. Double Quantization was introduced specifically to reduce this overhead while keeping the fine-grained block-wise quantization benefits.

# Two-level quantization: quantizing c2 with FP8 and storing c1 in FP32

Double Quantization (DQ) addresses the scale-storage overhead by treating the per-block quantization constants — the values that convert stored low-bit codes back to floating point — as data to be quantized themselves. In QLoRA the first quantization produces k-bit quantized weight blocks $\mathbf{W}^{\text{k-bit}}$ together with per-block scales $c_2^{\text{FP32}}$. Instead of keeping all $c_2^{\text{FP32}}$ values in full precision, DQ applies a second quantization layer to these scale values.

Formally, the double-quantized storage includes:
- the k-bit quantized weight codes $\mathbf{W}^{\text{k-bit}}$ (e.g., NF4 codes),
- second-level quantized scales $c_2^{\text{k2-bit}}$ (in QLoRA the paper uses an 8-bit float-like representation for this second level), and
- a small set of higher-precision constants $c_1^{\text{FP32}}$ that dequantize the second-level scale values.

The double dequantization procedure (as used in QLoRA) is written in the paper as
\[
\text{doubleDequant}(c_1^{\text{FP32}}, c_2^{\text{k-bit}}, \mathbf{W}^{\text{k-bit}}) = \text{dequant}(\text{dequant}(c_1^{\text{FP32}}, c_2^{\text{k-bit}}), \mathbf{W}^{\text{k-bit}}),
\]
so that to recover the computation-precision weight $\mathbf{W}^{\text{BF16}}$ we first dequantize the second-level representation of the scales into full-precision scales and then dequantize the k-bit weight codes with those reconstructed scales. In QLoRA the paper chooses NF4 for $\mathbf{W}^{\text{k-bit}}$, FP8 for the second-level quantized scales $c_2^{\text{k-bit}}$, and FP32 for the small set $c_1^{\text{FP32}}$.

This two-level strategy moves most of the per-block memory burden from expensive 32-bit scale values down into a much cheaper 8-bit representation per block, with only a tiny number of FP32 anchors ($c_1$) needed to reconstruct the FP32-scale space. The result is a dramatic reduction in average per-parameter bits spent on scales.

# Mean-centering positive scales for symmetric quantization

An important detail when quantizing the per-block scales is that the scale values are non-negative by construction: they represent magnitudes used to map between integer-like codes and original floating values. Most symmetric low-bit quantizers (including many fast hardware-friendly formats) assume input values are approximately centered around zero so that symmetric binning is effective. Because $c_2^{\text{FP32}}$ are strictly positive, naively applying a symmetric quantizer would waste half of the representable range on negative values that never occur.

The paper resolves this by mean-centering the positive scales prior to the second-level quantization. In practice, for the vector of scales across blocks one subtracts the mean:
\[
\tilde{c}_2 = c_2^{\text{FP32}} - \mu_{c_2},
\]
where $\mu_{c_2}$ is the mean of the $c_2^{\text{FP32}}$ values (computed over the blocks of a weight tensor or group of blocks). This centers the distribution of scale values around zero, enabling effective symmetric quantization into the chosen second-level format (FP8 in the paper). The mean $\mu_{c_2}$ and any other small metadata are then captured in the first-level constants $c_1^{\text{FP32}}$ used during dequantization. By centering, we make better use of the symmetric quantizer bins and minimize quantization error on the scale values, which in turn reduces error when the k-bit weight codes are finally reconstructed.

# Bit accounting: from 0.5 bits/param to ~0.127 bits/param at blocksize 64

The motivating arithmetic for the memory saving achieved by Double Quantization is straightforward bookkeeping of bits per parameter. With a first-level scheme that stores $32$-bit per-block scales and blocksize $B$, the per-parameter cost of scales is
\[
\frac{32}{B} \quad \text{bits/parameter}.
\]
For the commonly used $B = 64$ this is $32/64 = 0.5$ bits/parameter.

With Double Quantization, the second-level quantization stores the second-level scales $c_2$ in an 8-bit floating data type with a larger blocksize (the paper uses blocksize $256$ for these second-level quantizations of the $c_2$ vector). After DQ, each original weight parameter therefore pays for:
- the $8$ bits used to represent the quantized $c_2$ spread across the $B$ parameters of a block, which costs $8/B$ bits/parameter, and
- the small FP32 anchors $c_1^{\text{FP32}}$ that are stored at the granularity of the larger grouping for the $c_2$ quantization. If the $c_2$ values are grouped with second-level blocksize $B_2$ (here $B_2 = 256$ blocks), then the FP32 anchors contribute $32/(B \cdot B_2)$ bits per parameter.

Plugging in the numbers used in the QLoRA paper — $B = 64$, second-level grouping $B_2 = 256$, and second-level storage using 8-bit floats — yields:
\[
\text{bits/param} = \frac{8}{64} + \frac{32}{64 \cdot 256} = 0.125 + \frac{32}{16384} = 0.125 + 0.001953125 \approx 0.126953125.
\]
Rounded, the paper reports this as approximately $0.127$ bits per parameter. That is a reduction of about $0.373$ bits per parameter relative to the $0.5$ bits/parameter baseline:
\[
0.5 - 0.127 \approx 0.373 \text{ bits/parameter}.
\]
On a 65B-parameter model this fractional-bit saving accumulates to several gigabytes of memory saved just in the storage of quantization constants, making the double-quantized representation materially more memory efficient for large models.

# Why FP8 on scales is accuracy-safe

A natural concern when quantizing quantization constants is whether the second-level quantization will introduce additional reconstruction errors that degrade downstream model performance. The QLoRA paper empirically observes that using an 8-bit floating representation (FP8) for the second-level scales does not produce observable performance degradation. There are several reasons, grounded in the behavior of the components involved, why this is reasonable.

First, the per-block scales $c_2^{\text{FP32}}$ are themselves compact summaries (single positive values) of the dynamic range of each small block of weights. These scale values vary relatively slowly and occupy a narrower dynamic range than the original weights. They are typically well-behaved numerical quantities compared to raw weights or activation values, and hence are less sensitive to further mild quantization.

Second, the second-level quantization uses a larger grouping blocksize (e.g., 256) across many $c_2$ values. By aggregating multiple $c_2$ values into a group that shares a small set of FP32 anchors, DQ ensures that local relative differences among $c_2$ values can be captured by the 8-bit representation while any minor global offsets are corrected by the FP32 anchors $c_1$ during dequantization. In other words, the representation is designed so that the most important degrees of freedom are preserved.

Third, the final dequantization performed during forward and backward passes still reconstructs the weight tensors into a 16-bit computation data type (BF16 in QLoRA). The two-stage dequantization pipeline produces weight reconstructions that are sufficiently precise for the downstream matrix multiplications done in 16-bit precision. Because the computation is done at 16-bit precision and adapter gradients are the only learned gradients, the model is robust to the tiny additional perturbations introduced by FP8 quantization of scales.

The paper validates these design choices empirically: double quantization with FP8 on the scales yields essentially no degradation on language modeling and benchmark tasks compared to single-level quantization with full-precision scales, while offering substantial memory savings.

# Implementation details and block size choices (64 for W, 256 for c2)

The QLoRA paper specifies practical choices that balance precision and memory savings and that work well in experiments:

- Weight blocksize $B$ for $\mathbf{W}$: the paper uses $B = 64$. Small blocks like 64 elements are important to capture local variations in weight magnitudes and to avoid outlier-driven quantization errors. Using NF4 (4-bit NormalFloat) with blocksize 64 provides the desired quantization fidelity for the weights.

- Second-level blocksize for $c_2$ grouping: the second quantization treats the $c_2$ values as a vector and groups them with a larger blocksize $B_2 = 256$ before applying the 8-bit quantization. That is, every $B_2$ first-level blocks share a small set of FP32 anchors $c_1$ plus their own FP8-represented deviations. Choosing $B_2 = 256$ reduces the number of expensive FP32 anchors (the $c_1$ values) and therefore lowers the amortized FP32 overhead per weight parameter. Because $c_2$ values are smoother and less volatile than raw weights, this larger grouping size is acceptable without harming reconstruction quality.

- Data types: The paper uses NF4 for the main weight codes, FP8 for the second-level quantized scales (the $c_2$ after mean-centering), and a small number of FP32 anchors ($c_1$) per $B_2$ groups. During forward and backward passes, doubleDequantation recovers BF16 weights for computation.

- Mean-centering prior to symmetric FP8 quantization: because $c_2$ values are strictly positive, the implementation subtracts the mean before quantizing them into the symmetric FP8 representation. The mean is stored in the FP32 anchor set and is added back during dequantization.

- Storage and runtime trade-offs: Double Quantization reduces the average memory footprint of scales by quantizing them to FP8 and amortizing the remaining FP32 anchors across larger groups. The paper reports the arithmetic that for $B=64$ and $B_2=256$ the per-parameter overhead for scales is approximately $0.127$ bits, compared to $0.5$ bits without DQ. This saved memory enables finetuning very large models (e.g., 65B) on a single 48GB GPU when combined with the other QLoRA techniques.

- Numerical stability and dequantization on the fly: In QLoRA the dequantization is done at use time: when a weight block is needed, its NF4 codes are dequantized using the reconstructed scale obtained by dequantizing the FP8-encoded $c_2$ with the small FP32 $c_1$ anchors. Because computation happens in BF16 and only adapter gradients are updated, this on-the-fly dequantization preserves sufficient numerical fidelity for both forward and backward passes.

In summary, the choices of $B=64$ for the primary weight blocksize and $B_2=256$ for the second-level scales reflect a practical compromise: small first-level blocks for high quantization precision of weights, and larger second-level groups for aggressive compression of the scales without any observed accuracy loss. The mean-centering step and the FP8 choice for $c_2$ are practical techniques that make symmetric quantizers effective and keep the quantization noise from propagating into downstream computations.

# Closing summary

Double Quantization is a simple but effective idea: the per-block scale values introduced by fine-grained block-wise quantization themselves become a target for further quantization. By mean-centering these positive scales, encoding their residuals in an efficient 8-bit floating format, and amortizing a small number of FP32 anchors over many blocks, DQ lowers the per-parameter bit cost of scales from $\frac{32}{B}$ to approximately $\frac{8}{B} + \frac{32}{B \cdot B_2}$. With the practical choices used in QLoRA ($B=64$, $B_2=256$), this reduces the scales overhead from $0.5$ bits/parameter to about $0.127$ bits/parameter, a saving of roughly $0.373$ bits/parameter. Empirically, this aggressive compression of scales (using FP8 for $c_2$) is accuracy-safe in the QLoRA pipeline and is a key contributor to enabling high-precision 4-bit finetuning of very large models within modest GPU memory budgets.

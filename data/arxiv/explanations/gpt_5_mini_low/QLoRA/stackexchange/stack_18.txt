\title{Stack Exchange of the Paper: "QLoRA: Efficient Finetuning of Quantized LLMs"}

### Is there any interaction between NF4 quantization and attention key/value cache precision at inference?
Question:
During generation, attention KV caches can dominate memory and may be stored in lower precision. QLoRA focuses on training-time memory and quantized weights, but what precision is used for KV caches in their inference experiments for Guanaco models? If KV caches use FP16/BF16, could some of the observed parity with 16-bit finetuning be sensitive to inference-time cache precision rather than just weight quantization?
Answer:
Short answer: The paper does not explicitly state “KV caches were stored in $X$ precision” for the Guanaco inference runs, but the text makes it clear that QLoRA uses a $4$‑bit storage format for model weights and dequantizes to a $16$‑bit computation type ($\mathrm{BF16}$ / BrainFloat16) when performing forward/backward passes. From that description the natural interpretation is that during generation the model runs with $16$‑bit computation and therefore the attention keys/values (the KV cache used during autoregressive decoding) are held in the $16$‑bit computation type ($\mathrm{BF16}$/$\mathrm{FP16}$), not in $4$‑bit storage.

Why I conclude that and what it implies: QLoRA’s core idea is “$4$‑bit storage, $16$‑bit compute”: the frozen base weights are stored in $NF4$ on disk/GPU memory and are double‑dequantized into the $16$‑bit computation dtype when used (see the paper’s statements that dequantization is to BFloat16 and matrix multiplies are done in $16$‑bit). KV caching is part of the runtime activations produced by those dequantized computations. Activations and caches are therefore naturally in the computation precision ($\mathrm{BF16}$/$\mathrm{FP16}$) unless you explicitly quantize them; the paper introduces Double Quantization for weight storage and Paged Optimizers for optimizer state, but it does not propose quantizing activations/KV caches for inference. So the practical inference setup used for Guanaco evaluations is best read as using $16$‑bit for compute and thus for KV caches.

Could the observed parity with $16$‑bit finetuning be an artifact of using $16$‑bit KV caches? In principle yes, but it is unlikely to be the whole story. Intuitively, the KV cache stores intermediate attention projections (activations), not learned model parameters. If you run two models with different trained weights but both execute with the same numeric compute precision for activations/caches, then any performance parity you see is primarily reflecting the effective model parameters (weights + adapters + how they interact with the input), not the cache precision. In other words, using $\mathrm{BF16}$/$\mathrm{FP16}$ compute for both the QLoRA‑trained $NF4$ model (dequantized to $\mathrm{BF16}$ at runtime) and a native $16$‑bit finetuned model gives them the same numeric format for activations, so cache precision is shared across conditions and cannot by itself explain a difference in model behavior between the two methods.

However, it is also true that lowering the precision of KV caches can influence generation quality. Attention is sensitive to numerical noise in activations: quantizing KV caches to very low precision (e.g., $8/4$ bits) can change dot‑product values, attention weights, and thus generations. Therefore an experiment that compared a $4$‑bit QLoRA model running with $\mathrm{BF16}$ activations to a $16$‑bit fully‑finetuned model running with lower‑precision activations could produce misleading conclusions. The important control is to keep inference compute precision (activations / KV cache) the same across methods when comparing finetuning approaches.

What I recommend if you want a definitive answer experimentally: (1) Confirm the runtime dtype used by your inference engine for Guanaco (most forks use $\mathrm{BF16}$/$\mathrm{FP16}$ dequantized matmuls). (2) Run a small ablation: compare generations and evaluation metrics for (a) QLoRA $NF4$ dequantized → $\mathrm{BF16}$ compute (standard), (b) same QLoRA model but quantize the KV cache to $\mathrm{FP16}$, $\mathrm{FP8}$ or $\mathrm{Int8}$ during decoding, and (c) the $16$‑bit finetuned baseline under identical cache quantization settings. If parity disappears when you quantize caches only for one condition, that would show cache precision contributes. If parity persists across cache precisions, that strengthens the claim that finetuning on quantized weights ($NF4$ + LoRA) genuinely recovers $16$‑bit behavior.

Bottom line: the paper implies (and standard practice supports) that KV caches were kept at the $16$‑bit computation precision ($\mathrm{BF16}$/$\mathrm{FP16}$). That shared inference precision makes it unlikely that cache precision alone explains the parity with $16$‑bit finetuning, though cache precision can affect generation and is worth controlling for in ablations if you need to be certain.

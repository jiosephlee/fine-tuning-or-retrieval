\title{Stack Exchange of the Paper: "QLoRA: Efficient Finetuning of Quantized LLMs"}

### How do gradients flow through quantized weights if we never compute $\partial E / \partial \mathbf{W}$?
Question:
The paper says only LoRA adapter gradients $\partial E/\partial \mathbf{L}_i$ are needed and not $\partial E/\partial \mathbf{W}$ for the 4-bit base weights. But they also note that computing $\partial E/\partial \mathbf{L}_i$ entails computing $\partial \mathbf{X}/\partial \mathbf{W}$ with dequantized $\mathbf{W}^{\text{BF16}}$. Can someone outline the backward pass math? Do we treat $\mathbf{W}$ as a constant in the update sense (no optimizer state), but still use it in Jacobian-vector products to propagate gradients to $\mathbf{L}_i$? Is any straight-through estimator (STE) used for the quantization nonlinearity, or is quantization only in storage and all computed tensors are differentiable BF16?
Answer:
Short answer: you do not need an STE. The frozen 4-bit weights are stored quantized but are always dequantized to a differentiable BF16 tensor for forward and backward computation. During backprop you treat the dequantized tensor as a fixed constant (no optimizer/update for those stored codes), but you still use it in the usual Jacobian-vector products (e.g. compute $\frac{dE}{dX}$ and then $\frac{dE}{d\text{LoRA}}$ via chain rule). Only the LoRA parameters receive gradient and optimizer state. The integer rounding that created the stored 4-bit codes is not part of the autograd path—quantization is a storage-time lossy transform; dequantization produces a continuous BF16 tensor used for all differentiable ops.

More detail / math (intuitive + technical)
Write the forward for a single linear layer with one LoRA adapter exactly as in the paper:
$Y = X W_{\text{deq}} + s X L_1 L_2$,
where $W_{\text{deq}} = \text{doubleDequant}(c_1, c_2, W_q)$ is the dequantized BF16 weight used for computation, and $L_1, L_2$ are BF16 LoRA matrices. $W_q$ and quantization constants are stored (4-bit / FP8) and dequantized on the fly to BF16.

Let $G = \partial E/\partial Y$ be the upstream gradient from the loss $E$. The gradients you actually compute and apply are the standard matrix calculus results for the LoRA term $A = s X L_1 L_2$:

- For $L_2$ (shape $r\times o$):
  $\displaystyle \partial E/\partial L_2 = (s X L_1)^{T} G$
  (equivalently, if $M = s X L_1$ with shape $b\times r$, then $\partial E/\partial L_2 = M^{T} G$, summed/averaged over batch as usual).

- For $L_1$ (shape $h\times r$):
  $\displaystyle \partial E/\partial L_1 = s X^{T} (G L_2^{T})$
  (here $G L_2^{T}$ has shape $b\times r$, then multiply by $X^{T}$ to get $h\times r$).

These are identical to ordinary LoRA gradients if $W$ were full-precision. Note that these expressions require $X$ (the layer input) and $G$; $X$ itself is produced by preceding layers that used $W_{\text{deq}}$.

Where $W_{\text{deq}}$ participates in backprop is through the standard Jacobian-vector products with respect to inputs/outputs, not as an optimizable parameter. For example, the gradient that flows into the previous layer input $X_{\text{prev}}$ is computed through the frozen dequantized weight exactly as in dense backprop:

$\displaystyle \partial E/\partial X_{\text{prev}} \ (\text{from the base linear}) = G_{\text{base}}\, W_{\text{deq}}^{T}$,

where $G_{\text{base}}$ is the gradient w.r.t. the output of the base projection (if that projection used $W_{\text{deq}}$). These are computed using $W_{\text{deq}}$ in BF16. No gradient is accumulated into the stored 4-bit representation because we do not call the optimizer on $W_q$; we do not compute or keep $\partial E/\partial W_q$ for parameter updates.

Why no STE is needed
An STE is used when you want to pretend a non-differentiable or discrete forward op (e.g., rounding) is differentiable and propagate gradients through the discrete variable to upstream parameters (i.e., you want to update the quantized/rounded variable or its inputs). QLoRA does not try to update the stored 4-bit codes; the rounding/quantization that produced $W_q$ is only a storage-time operation. At runtime QLoRA deterministically dequantizes $W_q$ into $W_{\text{deq}}$ (a floating BF16 tensor). All computations and derivatives used by autograd are standard differentiable operations on BF16 tensors. Therefore there is no need to approximate gradients through the rounding operator and no STE is used.

Put another way: quantization is only in storage; dequantization produces a continuous tensor that participates in gradient algebra. Gradients are propagated through $W_{\text{deq}}$ as multipliers in Jacobian-vector products, but no gradient-based update is applied to $W_q$ (or to $W_{\text{deq}}$). Only the LoRA parameters receive and are applied gradients.

Practical consequence
- Memory/optimizer state: you avoid optimizer states for the base weights (they are frozen). You still need to materialize $W_{\text{deq}}$ (BF16) for forward/backward uses; QLoRA minimizes that cost by on-the-fly dequantization + memory tricks (double quantization, paging).
- Numeric precision: dequantization to BF16 preserves sufficient precision for the backprop math used to compute the LoRA gradients; the success of QLoRA empirically shows this is enough to recover 16-bit finetuning performance.
- No biased gradient estimator: since no gradient is backpropagated through the quantization rounding, there is no STE bias to reason about for base-weight updates—there simply are no base-weight updates.

Summary
You compute gradients for LoRA with ordinary chain rule formulas that use dequantized BF16 weights as fixed multipliers in the Jacobian-vector products. $W$ is treated as constant for optimization (no optimizer state), but it still participates in differentiable computations so gradients flow around it to the LoRA parameters. Quantization is a storage-time lossy step; the runtime tensors are continuous BF16 and no STE is needed.

\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### How does sLSTM ‘memory mixing’ make it more expressive than SSMs/Transformers for state tracking?
Question:
The paper cites results that SSMs and Transformers lack state-tracking capacity akin to RNNs, and argues sLSTM’s memory mixing (recurrent $\mathbf{R}_\bullet$ across cells within heads) plus exponential gating enables solving formal language tasks like parity. Can someone give a minimal constructive example showing sLSTM’s recurrent mixing implements a finite-state machine that Transformers/SSMs cannot, even with large capacity? How do heads restrict or enhance this expressivity?
Answer:
Short answer: sLSTM’s “memory mixing” (the hidden$\rightarrow$cell recurrent matrices inside a head) gives you a tiny, provable way to implement finite‑state machines (FSMs) by making the cell updates conditional on previous hidden states; exponential gating makes those conditionals sharp and stable. Transformers and linear SSMs, as usually formulated, lack the same kind of time‑local, learned hidden$\rightarrow$cell recurrence and therefore cannot (robustly and exactly) implement some simple FSMs such as parity with fixed finite memory unless they blow up capacity or rely on approximations. Below I give a minimal constructive example (parity) showing how a $2$‑cell sLSTM head can implement a $2$‑state FSM that toggles state on a “1” input, explain why a Transformer/SSM cannot implement that with the same limited mechanism, and comment on how multiple heads change the picture.

Constructive example (parity modulo $2$) — how to make an sLSTM head behave like a $2$‑state FSM
We want a model that reads a stream of bits $x_t \in \{0,1\}$ and outputs the parity up to time $t$ ($0$ for even count of ones, $1$ for odd). A minimal FSM has two states $S_0$ (even) and $S_1$ (odd) and transition: on input $1$ toggle ($S_0 \leftrightarrow S_1$); on input $0$ stay.

sLSTM ingredients we use (from the paper):
$c_t = f_t \cdot c_{t-1} + i_t \cdot z_t$,
$h_t = o_t \cdot (c_t / n_t)$,
with gates $i_t = \exp(\tilde{i}_t)$, $f_t$ (can be sigmoid or exp), and crucially the $\tilde{\cdot}$ terms can depend on $h_{t-1}$ via recurrent matrices (the paper calls these recurrent mixing weights).

Design idea (intuitively). Use two scalar memory cells $c^{(1)}$ and $c^{(2)}$ inside one head, and use the recurrent matrices so that when a “1” arrives the gate/controller routes the memory contents between the two cells (a learned permutation). By swapping contents we can toggle which cell holds the “active” signal; output reads which cell currently carries the $1$. Exponential gating makes the gating decisions effectively hard (near‑binary) and stable across long runs.

Concretely (sketch of parameter choices)
1) Represent the state by which cell contains $+1$ and which contains $0$:
   - $S_0: c^{(1)} = 1, c^{(2)} = 0$
   - $S_1: c^{(1)} = 0, c^{(2)} = 1$

2) Set forget gates $f_t \approx 1$ (so we don’t decay memory) and output gate $o_t = 1$ for simplicity. Set normalizer $n_t$ to track gate mass (paper’s stabilizer takes care of large exponentials).

3) Make the input $z_t$ zero for both cells (so new external content doesn’t disturb memory). The only changes to memory come from the recurrent, gate‑controlled mixing.

4) Use recurrent weights in the gate arguments so that when $x_t = 1$ the input/forget gating effectively swaps the two scalar memories. For example, for two cells we can implement:
   $c_t = P(x_t)\, c_{t-1}$
where $P(0) = I$ (identity) and $P(1)$ is the permutation matrix that swaps coordinates. How to get that from sLSTM equations: choose $i_t$ and $f_t$ (vectors of size $2$) and $z_t$ such that the net effect is either keep $c_{t-1}$ (when $x_t=0$) or replace it by a swapped version (when $x_t=1$). Because each gate’s preactivation can include terms $r \cdot h_{t-1}$, we can make the gate values depend on which cell was active ($h_{t-1}$ encodes that), and because gates are exponentials we can make them sharply select the swap vs identity path.

A concrete parameter instantiation (high level):
- Let $h_{t-1} = [h_1, h_2]$ be a one‑hot indicating which cell is active (paper’s $h_t = o_t \cdot (c_t / n_t)$ can be arranged to be that).
- Choose recurrent matrices $r_{f}, r_{i}$ so that when input $x_t=1$ their preactivations produce an $i_t$ vector which is large on entries that will move the active $1$ into the other coordinate and small otherwise. With $\exp(\cdot)$ gating, “large” becomes multiplicative weight $\gg 1$ and “small” $\approx 0$ after stabilizer scaling, so the net update becomes either identity (no effective new write) or a controlled write/reshuffle.
- Because the gates multiply previous $c_{t-1}$ and the input term is controlled, you can obtain $c_t$ that is the swapped vector when $x_t=1$ and unchanged when $x_t=0$.

Why this is a genuine FSM implementation: the hidden$\rightarrow$gate recurrent paths create a closed loop (state influences next gate decisions), so the system’s next state depends only on current state and current input — exactly an FSM transition function. Exponential gating gives near‑discrete switching, making the transitions robust and long‑lived (no decay).

Why Transformers / linear SSMs fail to match this (intuitively and per paper)
Transformers implement per‑time attention that mixes past token representations via content‑based (soft) attention; SSMs implement linear dynamical recurrences without learned nonlinear hidden$\rightarrow$gate recurrences. Two important differences prevent them from implementing the above simple FSM with the same economy:

1) No time‑local learned hidden$\rightarrow$cell recurrence: sLSTM’s crucial operation is that the previous hidden state $h_{t-1}$ is fed back (via learned matrices) into the gates that immediately decide how to modify the cell at time $t$. This creates a learned, nonlinear state transition that depends on internal memory. Standard Transformers do not have an equivalent learned hidden$\rightarrow$gate that acts at the next time step; their update at $t$ is a function of the whole past via attention weights computed from content, not a small fixed finite‑state transition matrix that is applied conditioned on internal state. SSMs that are linear cannot implement the nonlinear switching required for exact parity without exponentially large rank or special nonlinearities.

2) Content vs. state routing: attention is content‑based and typically requires the model to encode and compare keys/queries across tokens; to simulate a tiny FSM like parity, a Transformer would need to encode state into token embeddings and then repeatedly attend to the right token representations. This is possible in principle with unbounded precision and large capacity, but it does not implement a compact finite automaton in the same way: practical Transformers/SSMs need approximation, longer context bookkeeping, or explosive capacity to exactly maintain the toggling without drift, and the papers cited (Deletang et al., Merrill et al.) show formal limitations: RNNs with hidden$\rightarrow$hidden recurrence can implement (and generalize to) certain state‑tracking tasks that Transformers and SSMs cannot with the same architecture/inductive bias.

Heads and expressivity: what multiple heads buy you, and what they restrict
In the sLSTM design of the paper, “heads” are independent groups of cells where memory mixing is allowed inside a head but not across heads. This has two consequences. First, each head can implement an independent FSM; having $H$ heads therefore allows you to run $H$ small FSMs in parallel (useful for tracking several different entities or state machines concurrently). Second, because there is no direct recurrent mixing across heads, coordinating or composing those FSMs into a single richer FSM requires later layers to read and combine head outputs; that increases depth and may make some stateful behaviors less compact. So heads increase parallelism and modularity of state trackers, but they constrain immediate cross‑state interactions — a design choice that trades off expressivity of a monolithic FSM for modular, parallel state machines that can be composed.

Summary
The minimal constructive idea is: with just $2$ scalar cells and learned hidden$\rightarrow$gate recurrent matrices inside one sLSTM head you can implement the parity $2$‑state FSM by making gates effect a state swap on input $1$ and identity on input $0$. This uses the exact mechanisms introduced in the paper: memory mixing (hidden recurrences) + exponential gating (sharp, stable switching). Transformers and linear SSMs lack that simple, local learned recurrence path and therefore cannot implement the same compact FSM as naturally; they would need nontrivial workaround (big memory, extra tokens, or approximation). Multiple sLSTM heads let you run multiple FSMs in parallel (each head a state tracker) but prevent instant recurrent mixing across heads, so coordination must be mediated through outputs and later layers.

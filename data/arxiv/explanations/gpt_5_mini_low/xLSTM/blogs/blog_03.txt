# From Scalars to Matrices: The mLSTM Memory That Remembers More

The classic LSTM stores information in scalar cell states and updates them with gated additions. That design—the constant error carousel—solved vanishing gradients and powered many sequence models, but it has limits: scalar cells compress information heavily, they are not naturally parallelizable when recurrent mixing is present, and they can struggle to revise or represent many items (e.g., rare tokens or long associative memories). The mLSTM from "xLSTM: Extended Long Short-Term Memory" addresses those limits by replacing scalar cells with a matrix memory and using a covariance (outer-product) update rule. This post pulls the key ideas apart, explains how the matrix memory works, how retrieval and normalization are handled, and why this design improves capacity and long-range associations while keeping parallelism.

## The core idea: matrix memory with covariance updates

Instead of a scalar cell \(c_t \in \mathbb{R}\), mLSTM maintains a matrix memory \(\mathbf{C}_t \in \mathbb{R}^{d\times d}\). At each time step the model computes three vectors from the current input \(\mathbf{x}_t\): a key \(\mathbf{k}_t\), a value \(\mathbf{v}_t\), and a query \(\mathbf{q}_t\). The memory update is a covariance-style outer product of value and key:

\[
\mathbf{C}_t = f_t \, \mathbf{C}_{t-1} \;+\; i_t \, \mathbf{v}_t \mathbf{k}_t^\top,
\]

where \(i_t\) (input gate) controls how strongly the new outer product is written, and \(f_t\) (forget gate) decays the previous memory. This is the same family of updates used in Fast Weight Programmers and earlier associative memory models: store associations via rank-1 outer products that bind keys to values.

Why an outer product? Because the matrix \(\mathbf{C}\) naturally implements a linear associative mapping: later, given a query \(\mathbf{q}\), you retrieve (a proxy for) the value associated with keys aligned to that query by multiplying

\[
\tilde{\mathbf{h}}_t = \mathbf{C}_t \mathbf{q}_t.
\]

If the keys stored earlier are (approximately) orthogonal and \(\mathbf{q}_t\) aligns to a stored key \(\mathbf{k}_\tau\), then \(\mathbf{C}_t \mathbf{q}_t\) will contain a strong component along \(\mathbf{v}_\tau\). In short: keys write directions into the matrix, values are recovered via matrix-vector product with a query.

## Normalization and stabilization: making retrieval robust

A practical problem with this scheme is that the strength of retrieved signals depends on how strongly keys have been written and on future forget gates. The paper addresses this with a normalizer state \(\mathbf{n}_t\) that accumulates weighted keys:

\[
\mathbf{n}_t = f_t \, \mathbf{n}_{t-1} \;+\; i_t \, \mathbf{k}_t.
\]

When retrieving, the raw vector \(\mathbf{C}_t \mathbf{q}_t\) is scaled by the magnitude of the dot product between \(\mathbf{n}_t\) and the query to normalize for accumulated gate strength:

\[
\tilde{\mathbf{h}}_t = \frac{\mathbf{C}_t \mathbf{q}_t}{\max\{|\mathbf{n}_t^\top \mathbf{q}_t|, 1\}}.
\]

The absolute value and lower threshold avoid divisions by tiny numbers; the authors note they typically use threshold 1.0 as in prior work. Finally, an output gate \(\mathbf{o}_t\) (sigmoid) elementwise scales the retrieved \(\tilde{\mathbf{h}}_t\) to produce the hidden state \(\mathbf{h}_t = \mathbf{o}_t \odot \tilde{\mathbf{h}}_t\).

Additionally, mLSTM uses exponential activation for the input gate (\(i_t = \exp(\tilde{i}_t)\)) and either sigmoid or exponential for forget gates, with a stabilization trick (tracking a scalar log-scale state) so exponentials don't overflow. These choices let gates represent multiplicative write/decay factors more flexibly than bounded sigmoids.

## How this compares to attention and fast weights

At a high level, the mLSTM memory behaves like a form of linear attention or fast weights:

- Attention performs weighted sums of value vectors where weights depend on dot products between queries and stored keys. Standard (softmax) attention uses normalized pairwise interactions between all tokens and needs \(O(L^2)\) time or explicit approximations for linearity.
- Fast weight or outer-product memories store associations as outer products and retrieve with matrix-vector products. The mLSTM uses exactly this outer-product (covariance) storage, but embeds it in a gated recurrent update (write learning rate \(i_t\) and decay \(f_t\)) and adds normalization via \(\mathbf{n}_t\).

Key differences and relationships highlighted in the paper:

- The covariance update \(\mathbf{C} \leftarrow \mathbf{C} + \mathbf{v}\mathbf{k}^\top\) is equivalent in spirit to Fast Weight Programmers and to certain linear-attention formulations that can be written as incremental outer-product accumulations.
- Unlike full softmax attention, \(\mathbf{C}\) accumulates across time into a single matrix, so the memory size is independent of sequence length (constant memory per layer), and retrieval is \(O(d^2)\) per step rather than \(O(Ld^2)\) or quadratic in \(L\).
- Because mLSTM drops hidden-hidden mixing (no recurrent dependence on previous hidden state for key/value/gate projections), the recurrence on \(\mathbf{C}\) can be reformulated and implemented in parallel across tokens, making the design parallelizable similarly to modern attention approximations.

So mLSTM sits between classic attention and RNN fast-weights: it has associative outer-product storage like fast weights, an explicit normalizer for robust retrieval, and gates that control learning and decay.

## Why this boosts capacity for rare tokens and long-range associations

There are several reasons the matrix memory helps where scalar LSTMs struggle:

1. Larger representational degrees of freedom. A scalar cell compresses all stored information into one number per dimension; a matrix \(\mathbf{C}\) can store many pairwise associations across its \(d^2\) entries, enabling more orthogonalized representations of many items. That makes it easier to store rare or infrequent items without collapsing them into shared scalars.

2. Direct key–value binding. Outer products explicitly bind keys to values. When keys are well-structured (for example, after a layer norm and scaled projection as the paper uses), queries that match those keys retrieve the corresponding values with relatively high signal-to-noise. This is more effective for associative recall tasks than trying to cram associations into scalar cells.

3. Gate-controlled writing and decay. The input gate \(i_t\) acts like a learned write-strength (learning rate) and forget gate \(f_t\) like a decay. That allows the model to modulate how long particular associations persist, which is useful when some items (e.g., rare tokens) should be retained strongly.

4. Normalization reduces interference. The normalizer \(\mathbf{n}_t\) captures the cumulative key magnitude so that retrieval is scaled by expected total write strength along the query direction, reducing variance and improving robustness across different write histories.

Empirically (as reported in the paper), mLSTM-backed architectures (xLSTM variants with matrix memory) perform much better on associative recall tasks and improve perplexity particularly on rare token partitions compared to scalar LSTM baselines. In a synthetic multi-query associative recall benchmark, xLSTM variants outperform other non-Transformer models and the sLSTM head augments capacity further when combined appropriately.

## Parallelizability and computational trade-offs

A major practical advantage is that mLSTM can be implemented in a parallel fashion because its key/value/gate projections do not rely on the previous hidden state (no hidden-hidden mixing). That allows batched, parallel computation across sequence positions similar to how Transformer layers are batched—unlike sLSTM which retains recurrent mixing and thus is sequential.

But there is a trade-off: the matrix memory requires \(d\times d\) storage for \(\mathbf{C}\) and the update/retrieval are \(O(d^2)\) operations. This is heavier than a scalar LSTM per dimension but lighter than full quadratic-in-sequence-length attention when considered with long contexts, because \(\mathbf{C}\) does not grow with sequence length. The authors note that the matrix update uses no extra learned parameters (the keys/values/queries are linear projections), so the parameter count remains manageable. In practice, these matrix operations map well to GPU linear algebra, and the authors report that mLSTM computations can be parallelized and that wall-clock overheads are reasonable, though current CUDA kernels are not as optimized as FlashAttention and can be improved.

## Practical stabilizations

Because mLSTM uses exponential activations for writes (to allow unbounded positive write strengths), the authors include a stabilization technique that tracks log-scales and rescales gates to avoid overflow while leaving outputs and gradients unchanged. They also lower-bound the normalizer-based denominator to avoid divisions by small numbers. These engineering details make the method numerically stable in long sequences.

## Where mLSTM shines (and where it costs)

According to the experiments in the paper:

- Associative recall and synthetic memory tasks: mLSTM (and mixed xLSTM variants that include mLSTM blocks) performs significantly better than scalar-memory baselines and many other non-Transformer models, especially as the number of key–value pairs and context lengths grow.
- Rare token prediction: matrix memory increases capacity so the models better model rare tokens, yielding lower perplexities on rare-token partitions of Wikitext-103.
- Long context extrapolation: xLSTM variants with mLSTM maintain good perplexity when evaluated at longer contexts than those seen during training.
- Parallel inference: mLSTM can be parallelized and, because memory usage is constant in sequence length, it supports larger batch sizes and higher throughput at decoding compared to Transformers whose KV caches grow with sequence length.

Costs and limitations include the \(O(d^2)\) compute for the matrix operations and current lack of highly optimized kernels; careful initialization of forget gates; and the possibility of memory "overload" if extremely long contexts accumulate too many associations into a fixed-size \(\mathbf{C}\) (though the paper reports good performance up to 16k context length in their tests).

## Takeaway

mLSTM injects an explicit, gated matrix associative memory into the LSTM framework. By writing outer products of value and key vectors into a persistent matrix, normalizing retrieval, and using gated write/decay, it provides higher storage capacity and more robust associative recall than scalar LSTM cells. It bridges ideas from fast weights, linear attention, and classical associative memories, while keeping the model parallelizable and practical for large-scale sequence modeling. Empirically, that design improves rare-token modeling, associative recall accuracy, and long-range extrapolation relative to scalar-memory baselines, making mLSTM a compelling building block for memory-intensive sequence tasks.

\title{A Textbook about the Paper: "xLSTM: Extended Long Short-Term Memory"}

Chapter 3: Limitations of Classic LSTMs

# Inability to revise stored content: Nearest Neighbor Search example
One of the foundational design elements of the original Long Short-Term Memory (LSTM) is the additive cell update, often called the constant error carousel:
$c_t = f_t \, c_{t-1} + i_t \, z_t$,
with gates $i_t,f_t$ in $(0,1)$ typically produced by a sigmoid. This additive mechanism gives excellent gradient flow and enables the network to preserve information over long horizons. However, the multiplicative gating by sigmoids also creates a practical limitation: once information is committed to the cell state it is difficult to revise it decisively later in the sequence.

The paper illustrates this limitation with a Nearest Neighbor Search style problem. In that task a reference vector is fixed at the beginning of the sequence and thereafter the model scans a long sequence of candidate vectors; at the end the model must output the value attached to the sequence element most similar to the reference. To succeed the recurrent memory must be able to update stored information when a better match appears later, effectively "overwriting" or strongly modifying the previously stored content. Classic LSTM gating with $i_t$ and $f_t$ in the usual sigmoid range constrains how aggressively the stored scalar cell $c_t$ can be altered by a subsequent input: forget gates can gradually decay past content, and input gates can add new content, but the combination tends to blend old and new content rather than allow rapid, multiplicative replacement. As a result, LSTMs struggle to revise earlier storage decisions when a later input should replace what the model had kept, and the paper reports poor mean squared error on this task for vanilla LSTM.

This inability to revise effectively stems from the bounded, sub-exponential behavior of standard gating. When a later token should completely dominate the memory, the LSTM would need a near-zero forget gate and a very large input contribution, or vice versa, but practical training and numeric stability make such extreme gate dynamics rare. The xLSTM work addresses this specific failure mode by introducing exponential gating (for example $i_t=\exp(\tilde i_t)$), together with normalization and stabilization mechanisms, which allow gates to behave multiplicatively across time in a way that can implement strong replacement-like updates while remaining numerically stable. This exponential gating enables rapid revision of the stored content when needed, remedying the problem demonstrated by the Nearest Neighbor Search example.

# Limited capacity of scalar memory: Rare Token Prediction behavior
Classic LSTMs store information in scalar cell states (or a vector of scalar cells). Even when many scalar cells are present, each memory location stores a compressed scalar quantity and retrieval is mediated through scalar-to-hidden mappings. This imposes a practical limit on the representational capacity per timestep and on the kinds of retrievals that can be done efficiently.

The paper highlights this limitation through a Rare Token Prediction experiment on language data (Wikitext-103). Tokens that occur infrequently require the model to remember specific, perhaps high-dimensional, associations from the past in order to predict them correctly when they reappear. Because an LSTM's memory must compress diverse semantic content into scalar cell components and because retrieval is mediated by relatively small parameterized readouts, rare, high-specificity associations are difficult to encode and retrieve reliably. Empirically, the LSTM shows worse perplexity on rare tokens compared to more frequent ones, indicating that its scalar memory has insufficient capacity to store and retrieve those low-frequency, high-specificity items.

This limitation motivated the paper to enlarge the memory structure. The mLSTM variant replaces scalar cell states by a matrix memory $\mathbf{C}_t \in \mathbb{R}^{d\times d}$ and uses a covariance (outer-product) style update
$\mathbf{C}_t = f_t \, \mathbf{C}_{t-1} + i_t \, \mathbf{v}_t \, \mathbf{k}_t^\top$,
storing key--value pairs via outer products. Retrieval is then a matrix-vector product $\mathbf{C}_t \mathbf{q}_t$, normalized by an appropriate normalizer, which supports higher-capacity, structured storage and associative recall. In experiments (the Multi-Query Associative Recall task) this matrix memory substantially increases the model's ability to remember many distinct key--value pairs and thereby to predict rare tokens more accurately. The matrix memory thus directly addresses the capacity bottleneck of scalar cell states.

# Sequential processing due to memory mixing: lack of parallelization
A third limitation of classic LSTMs is architectural: the hidden-to-hidden recurrent connections (often denoted $r_*$ or a recurrent matrix $\mathbf{R}$ in vectorized versions) mix memory across timesteps in a way that enforces an inherently sequential computation. Concretely, gates and cell inputs are functions of the previous hidden $h_{t-1}$ as well as the current input $\mathbf{x}_t$, so computing the forward pass for time $t$ requires $h_{t-1}$, which requires $h_{t-2}$, and so on. This recurrent dependency prevents straightforward parallelization over sequence positions and yields runtime that scales linearly in sequence length for compute and memory footprints that grow with context length.

This sequential characteristic contrasts sharply with the Transformer architecture where self-attention enables parallel computation over all positions during the forward pass (albeit with quadratic complexity in sequence length in vanilla attention). The lack of parallelizability made LSTMs less attractive for large-scale language modeling when GPU/TPU hardware and parallel training became central concerns: models that can be executed in parallel across long contexts fit better with modern large-batch training and efficient accelerator usage.

xLSTM tackles this limitation through two complementary design choices. First, the mLSTM abandons memory mixing: the matrix memory update and retrieval depend only on the current input (and gated scalars) but not on $h_{t-1}$ through recurrent weight matrices; this enables a reformulation of the recurrence into a parallelizable computation (the paper notes that the mLSTM recurrence can be re-expressed in a parallel version analogous to linear attention and FlashAttention-style methods). Second, the xLSTM architecture integrates these recurrent memory modules inside residual block backbones and stacks them residually, preserving the benefits of residual pre-LayerNorm designs used in large models. For sLSTM, memory mixing can still be present (it supports recurrent weight matrices and so remains sequential), but the authors describe multiple-head designs and improved CUDA kernels to reduce practical overhead; mLSTM, in contrast, aims specifically for parallel execution. Thus xLSTM provides variants that recover parallelizability while keeping or improving the long-range memory behaviors.

# How these gaps led to Transformer adoption at scale
The three limitations above—difficulty in decisively revising stored content, constrained scalar memory capacity, and poor parallelizability—explain much of why Transformers displaced LSTMs as the dominant architecture for large-scale language modeling. Transformers offer two practical advantages addressing these gaps: first, attention-based retrieval can perform rapid, content-based lookups (implicit associative memory) that effectively revise what influences the next-token prediction based on each new query; second, attention provides high effective memory capacity because pairwise token interactions can encode and retrieve rich associations; third, the Transformer forward pass is parallelizable across sequence positions (during training), matching modern accelerator workflows and enabling efficient use of massive compute.

The paper points out that these limitations of LSTMs "paved the way for the emergence of Transformers" and raises the motivating question of the work: how far can LSTM-style models go in language modeling if we address those limitations—i.e., give LSTMs stronger gating, larger and more associative memory, and constructs that enable parallel computation—while also applying modern training and architectural techniques used in contemporary LLMs (residual stacking, pre-LayerNorm, up-projections, etc.). This is the rationale behind xLSTM.

# Design goals for xLSTM to address these limitations
Given the gaps identified, the xLSTM design sets clear, targeted goals and implements concrete mechanisms to meet them while staying within the LSTM family of ideas:

1. Allow decisive revision of memory contents. To permit strong replace-like updates and better state tracking, xLSTM introduces exponential gating for the input gate (and optionally for the forget gate): for example $i_t = \exp(\tilde i_t)$. Exponential gates can produce multiplicative accumulation or decay across time steps that is much sharper than sigmoid gates. Because exponentials can overflow or underflow, xLSTM also introduces normalization and stabilization machinery: a normalizer state (e.g., $n_t$ in sLSTM or $\mathbf{n}_t$ in mLSTM) that keeps track of the effective gate mass over future steps, and a stabilizer state $m_t$ that prevents numerical instability when dealing with exponentials. Together these elements make strong, numerically stable revision of stored content possible.

2. Increase memory capacity and support associative recall. To overcome the scalar-memory bottleneck, xLSTM offers the mLSTM variant with a matrix memory $\mathbf{C}_t$ and a covariance (outer-product) update
$\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top$,
storing key--value pairs akin to associative memories and Fast Weights. Retrieval uses a query $\mathbf{q}_t$ and returns $\mathbf{C}_t \mathbf{q}_t$ scaled by an appropriate normalization $\max\{|\mathbf{n}_t^\top \mathbf{q}_t|,1\}$; the normalizer $\mathbf{n}_t$ accumulates the gated keys over time. This construction substantially expands per-step storage and enables high-capacity associative lookups that improve rare-item prediction and associative-recall tasks.

3. Recover parallelizability where possible. To address the sequential bottleneck, mLSTM removes hidden-to-hidden memory mixing so that its recurrence can be rewritten into a parallel computation across sequence positions, similar in spirit to linearized attention approaches. This allows xLSTM architectures that are linear in context length in compute and constant in memory with respect to sequence length, enabling efficient scaling and high decoding throughput. For sLSTM, which preserves memory mixing for expressivity, the paper accepts a sequential character but mitigates the performance impact with optimized CUDA kernels and by combining sLSTM and mLSTM blocks in hybrid stacks (multiple heads, selective mixing) so that most of the heavy lifting can be parallel when desired.

4. Integrate with modern residual backbones and scaling practices. To be competitive at LLM scale, xLSTM modules are placed inside residual block backbones (pre-LayerNorm, up-projection styles) and stacked residually to form deep architectures. For sLSTM the paper uses post up-projection residual blocks; for mLSTM the design prefers pre up-projection blocks to enlarge the coding dimension in which matrix memories operate. This mirrors the successful backbone patterns used in contemporary Transformers and SSMs and supports favorable scaling behavior.

In short, xLSTM's design goals map directly to the identified limitations: exponential gating and stabilizers to enable decisive memory revision; matrix (covariance) memory and normalization to increase capacity and enable associative recall; and architectural choices (no memory mixing in mLSTM, residual stacking) to regain parallelizability and modern training compatibility. The paper's experiments show that these targeted remedies let xLSTM compete with, and in many measured respects outperform, Transformer and State Space baselines on language modeling and synthetic tasks that stress these exact limitations.

\title{A Textbook about the Paper: "xLSTM: Extended Long Short-Term Memory"}

Chapter 8: xLSTM Blocks and Architectures

# Goal: nonlinear summarization in high-dim spaces (Cover’s theorem)

A central objective when designing a block for a sequence model is to produce a compact representation of the entire past (the history up to the current time step) that is useful for predicting the next token or sequence element. xLSTM blocks follow the same philosophy that underlies most contemporary large sequence models: rather than trying to linearly operate on raw inputs, first non-linearly summarize the history in a suitably chosen representation space where different histories are more easily separated. The motivation for this is rooted in Cover’s theorem: patterns that are not linearly separable in a low-dimensional input space are more likely to become linearly separable after a non-linear embedding into a sufficiently high-dimensional space. For language modeling, this separation corresponds to producing representations that allow a simple linear decoder (or next-layer linear transformation) to discriminate between plausible continuations.

xLSTM implements this idea by placing an LSTM-derived memory module (either sLSTM or mLSTM) inside a residual block that transforms inputs through linear projections and non-linearities around the memory operation. The block architecture therefore has three roles: (1) provide the memory cell with an appropriately preprocessed input (queries, keys, values, gates), (2) let the memory non-linearly summarize the past in the memory state over time, and (3) project the memory output back into the residual stream so that it can be combined with other blocks. How and where in the block the up-projection (the expansion into a higher dimensional space) is placed affects the memory capacity and the character of the summarization; this is the basis for the pre- vs post-up-projection design choices discussed next.

# Post up-projection block (Transformer-like) for sLSTM

The post up-projection block is the variant that first computes a non-linear summary in the block's native (residual) dimensionality and only subsequently projects into a higher dimensional space before applying an activation and projecting back. This design mirrors the common Transformer feed-forward style where the non-linearity resides between an up-projection and a down-projection, but realized here in a residual block that contains sLSTM as its core memory.

For sLSTM, the post up-projection choice is motivated by two interrelated properties of sLSTM described in the paper. First, sLSTM retains the scalar (per-cell) memory structure similar to original LSTM cells, augmented by exponential gating and the associated normalizer and stabilizer states. Second, sLSTM supports memory mixing through recurrent (hidden–hidden) connections across its multiple scalar cells. Memory mixing benefits from operating in the residual-dimension space where states and recurrent connections are naturally expressed as hidden vectors. By placing the non-linear summarization in the original residual dimension and then applying an up-projection, the block allows the sLSTM recurrence and gating to act on representations that align with the residual stream and the hidden-state wiring used for memory mixing.

Operationally, a post up-projection xLSTM block with sLSTM behaves as follows: the input residual vector is first processed by input-weight matrices and the sLSTM recurrence to compute cell inputs \(z_t\), gates \(i_t,f_t,o_t\), and updated scalar cells \(c_t\) (with their normalizer \(n_t\) and stabilizer \(m_t\) where exponential gating is used). The sLSTM computes the hidden output \(h_t = o_t \cdot (c_t / n_t)\). After this non-linear recurrent processing in residual dimension, a linear up-projection maps the result into a higher dimensional space; a non-linear activation may be applied there; finally a down-projection maps back into residual dimension and the result is added via the residual connection. This ordering preserves the sLSTM’s natural hidden-state interactions and affords the non-linear separation advantage of an up-projection in the post-processing step.

# Pre up-projection block (SSM-like) for mLSTM to enlarge memory space

In contrast, the mLSTM employs a matrix-valued memory \(\mathbf{C}_t \in \mathbb{R}^{d\times d}\) with a covariance (outer-product) update rule \(\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top\). Retrieval is effected by multiplying the memory matrix with a query vector \(\mathbf{q}_t\), producing \(\tilde{\mathbf{h}}_t = \mathbf{C}_t \mathbf{q}_t / \max\{|\mathbf{n}_t^\top \mathbf{q}_t|, 1\}\) (gated and normalized as in the mLSTM forward pass). Because the memory is matrix-valued and retrieval operates through matrix–vector products, the effective capacity of mLSTM scales with the internal representational dimension \(d\). To maximize memory capacity per block, mLSTM benefits from having this memory live in a higher dimensional space.

Therefore, xLSTM blocks that contain mLSTM are designed with a pre up-projection: the input residual vector is first linearly mapped (up-projected) into a higher-dimensional space where the mLSTM keys \(\mathbf{k}_t\), values \(\mathbf{v}_t\), and queries \(\mathbf{q}_t\) are computed. The covariance-update memory then operates entirely in that enlarged space, allowing the matrix memory \(\mathbf{C}_t\) to be larger and to store higher-capacity associations. After the mLSTM retrieval and gating yield \(\mathbf{h}_t\) in the high-dimensional space, a down-projection returns the output to the residual dimension where it is combined residually with the block input.

This pre up-projection design is analogous to state-space-model backbones (SSM-like) that first lift inputs into a feature space where the state update operates. For mLSTM, the up-projection is not an incidental extra cost: it directly enlarges the memory matrices and therefore the block’s storing and retrieval capacity. Practically, the block computes \(\mathbf{q}_t,\mathbf{k}_t,\mathbf{v}_t\) via linear projections of the up-projected features (with the scaling \(1/\sqrt{d}\) on keys as in the mLSTM formulation), applies the matrix-memory update and retrieval described in the forward pass, normalizes by the normalizer state \(\mathbf{n}_t\), and uses the output gate \(\mathbf{o}_t\) to scale the retrieved vector before down-projecting.

# Pre-LayerNorm residual backbones

xLSTM architectures are constructed by residually stacking xLSTM blocks. The backbone chosen throughout the experiments follows the now-standard pre-LayerNorm residual design: before the core block computation (whether that core is an sLSTM recurrence in a post up-projection block or an mLSTM covariance memory in a pre up-projection block), a Layer Normalization is applied to the incoming residual stream. The normalized vector then goes through the block’s linear projections, the memory operation and nonlinearities, and finally the transformed vector is projected back and added to the original residual stream.

Pre-LayerNorm has proven to be a stable choice for deep residually stacked architectures, and xLSTM adopts it to obtain the benefits: (1) numerically stable gradient flow in deep stacks, (2) consistent normalization for the gates and projections that feed the memory modules, and (3) compatibility with large-scale training recipes used for other modern LLM backbones. Using pre-LayerNorm also standardizes where the up-projections (pre or post) are inserted relative to normalization, simplifying implementation and empirical comparisons.

# Stacking strategy: xLSTM[a:b] ratios of mLSTM to sLSTM blocks

An important architectural decision when building a full xLSTM model is how many blocks should use mLSTM versus sLSTM. The paper uses the notation xLSTM[a:b] to denote the ratio \(a/b\) of mLSTM-based to sLSTM-based blocks in a total block count. Concretely, xLSTM[7:1] indicates that for every eight blocks, seven are mLSTM blocks and one is an sLSTM block. For a typical total block count of 48, xLSTM[7:1] therefore includes 42 mLSTM blocks and 6 sLSTM blocks.

This ratio-based stacking strategy trades off the complementary strengths of the two memory modalities. mLSTM blocks provide large matrix memory capacity and are fully parallelizable (no recurrent hidden–hidden mixing), making them suitable for storing many key–value associations and for benefiting from pre up-projection expansion. sLSTM blocks reintroduce scalar-cell memory with exponential gating and memory mixing via recurrent hidden–hidden connections. Memory mixing is crucial for state tracking and tasks that require revising stored decisions. Thus a hybrid stack leverages mLSTM’s capacity and parallelism while retaining sLSTM’s expressiveness for problems that need recurrent memory mixing.

Empirically, different ratios have been evaluated (for example xLSTM[1:0] meaning all mLSTM, or xLSTM[0:1] meaning all sLSTM), and hybrid mixtures such as xLSTM[7:1] were shown to be effective across language modeling tasks. Choosing a ratio is a design knob: more mLSTM blocks favor memory capacity and parallelism; more sLSTM blocks favor memory-mixing expressiveness but reduce parallelizability.

# Design heuristics and component interactions

Designing an xLSTM architecture requires several interacting considerations. The following heuristics, grounded in the behaviors described in the paper, guide practical choices.

1) Match block type to memory role. Use pre up-projection (enlarge feature dimension before the memory operation) whenever the memory cell benefits from greater internal dimension — this is the mLSTM case. Conversely, use post up-projection when the recurrence and hidden–hidden mixing are the primary mechanism (the sLSTM case), so the recurrent dynamics operate in the residual dimension and the up-projection provides additional nonlinearity after the recurrence.

2) Control gating behavior with exponential gating and stabilization. Both sLSTM and mLSTM rely on exponential activation for the input gate (and optionally the forget gate) to enable revisable storage and stronger multiplicative control. Exponential gates can grow very large; therefore each design must include stabilizers (the scalar state \(m_t\) that rescales gate exponentials without changing the effective dynamics). Additionally, both memory types maintain a normalizer state (scalar \(n_t\) in sLSTM, vector \(\mathbf{n}_t\) in mLSTM) that tracks cumulative gate strength and is used to normalize retrieved values. These interacting states (gate outputs, normalizer, stabilizer) must be computed consistently in the block and must be initialized and biased carefully to avoid numerical issues (the paper notes careful choice of forget gate initialization).

3) Balance parallelism and expressive recurrence. mLSTM blocks are fully parallelizable because they omit hidden–hidden recurrent connections (no memory mixing across time via the hidden state). This allows efficient GPU-parallel training that resembles linear-attention or SSM methods and supports a parallel reformulation. sLSTM blocks include hidden–hidden recurrent connections enabling memory mixing and state tracking but are inherently sequential. Hybrid stacks should therefore place sLSTM blocks sparingly when high throughput is required, or rely on optimized CUDA kernels for sLSTM if more sLSTM capacity is desired.

4) Choose head and cell counts to modulate memory mixing. sLSTM can be instantiated with multiple scalar memory cells and multiple heads; memory mixing occurs within heads but not across heads, providing a controlled way to mix and separate information. For mLSTM, multiple heads and multiple cells are equivalent since there is no hidden mixing; therefore the effective memory dimension is adjusted by the projection sizes and the up-projection dimensionality. Thus, when designing blocks, the number of heads and cell partitions is a hyperparameter for modulating the granularity of memory interactions.

5) Use residual stacking with pre-LayerNorm for stability at scale. As in modern LLM backbones, stacking many blocks requires stable normalization and residual pathways so gradients can flow. By placing a LayerNorm before each block and adding the block output residually to the input, deep stacks of xLSTM blocks become trainable and comparable to Transformer stacks in terms of architecture.

6) Trade off computational cost versus memory capacity. The mLSTM matrix memory \(\mathbf{C}_t\) has computational complexity that scales with \(d^2\) due to the matrix update and matrix–vector retrieval, even though it does not introduce additional parameters. Designers must weigh the benefit of richer associative memory against this cost. Because these operations are parallelizable (matrix multiplications), implementations can be optimized on GPUs; nonetheless, wall-clock performance and energy use are practical constraints that influence the number and size of mLSTM blocks in a stack.

7) Arrange block ratios according to task requirements and scaling trajectory. For language modeling at large scale, experiments in the paper found that xLSTM architectures with many mLSTM blocks and a small fraction of sLSTM blocks (e.g., xLSTM[7:1]) perform favorably, combining mLSTM’s capacity with sLSTM’s state-tracking. When memory mixing or revisability is crucial (formal languages, stateful tasks), include more sLSTM blocks or even pure sLSTM stacks. When huge associative capacity and parallelizability are prioritized (large-context storage, many domains), increase the proportion of mLSTM blocks.

8) Interact carefully with training recipes and precision. Since exponential gating can produce values that are large in magnitude, mixed-precision training and correct use of stabilizers are part of the architectural design. The block design must therefore expose or hide stabilizer states and normalizers in a way compatible with the chosen training precision and optimizer settings.

In summary, xLSTM blocks consist of two complementary block-level designs: post up-projection blocks embedding sLSTM recurrence suited for memory mixing and state tracking, and pre up-projection blocks embedding mLSTM matrix memory for high-capacity associative storage. These blocks are stacked in pre-LayerNorm residual backbones using the xLSTM[a:b] ratio notation to form full models that balance capacity, expressiveness, and parallelism according to task and resource constraints. The interactions between exponential gating, normalizers, stabilizers, and projection placements are central to achieving stable and effective summarization of histories in high-dimensional spaces, thereby realizing the promise described by Cover’s theorem within an LSTM-derived architecture.

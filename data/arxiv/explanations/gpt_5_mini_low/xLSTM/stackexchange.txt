\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### How exactly do exponential input/forget gates enable “revising” stored values in sLSTM?
Question:
The paper claims that standard LSTMs struggle to revise storage decisions (e.g., in the Nearest Neighbor Search toy task), and that sLSTM fixes this via exponential gating. In equations (Eq. 11–17 for sLSTM), the update is still additive: $c_t = f_t c_{t-1} + i_t z_t$, but now $i_t = \exp(\tilde{i}_t)$ and $f_t \in \{\sigma(\tilde{f}_t), \exp(\tilde{f}_t)\}$. Intuitively, how does switching from sigmoid to exponential produce the ability to overwrite or revise earlier content? Is the key that $i_t$ can become arbitrarily large (compared to the bounded $\sigma$), thus dominating $f_t c_{t-1}$? If so, how is numerical stability preserved beyond the normalizer $n_t$ and stabilizer $m_t$? A small worked example showing where a later, more-similar vector replaces an earlier stored vector would help.
Answer:
Short answer: exponential gates let a later update multiply the new input by an arbitrarily large positive factor so that, after normalization by the accumulated gate strength, the cell state becomes effectively the new input (i.e. the old stored content is "overwritten"). The sLSTM explicitly keeps a normalizer $n_t$ that sums the effective gate strengths; dividing $c_t$ by $n_t$ yields a weighted average of past inputs where exponential gates control the weights. Numerical stability is handled by the stabilizer $m_t$ (subtracting a running log-scale) so exponentials never overflow while preserving the relative ratios that determine which input dominates.

Why this enables revising (intuitive + math)
In the ordinary LSTM both gates use sigmoid outputs in $(0,1)$. The cell update is additive,
$c_t = f_t c_{t-1} + i_t z_t$,
so each new input contributes at most a bounded fraction $i_t \in (0,1)$ of its transformed value $z_t$. If the network earlier stored a value with some persistent $f$-chain, later inputs cannot suddenly dominate because $i_t$ is bounded and $f_t$ only decays previous content multiplicatively by another value in $(0,1)$. That makes it hard to "revise" (fully replace) a previously committed value unless you explicitly learn a forget gate near zero.

sLSTM changes two things that matter for revision: (1) gates can be exponential, i.e. $i_t = \exp(\tilde{i}_t)$, so $i_t$ is unbounded above and can be made arbitrarily large; (2) the cell keeps a normalizer $n_t$ that accumulates the same gate strengths:
$n_t = f_t n_{t-1} + i_t$,
and the hidden pre-output is the normalized state $\tilde{h}_t = c_t / n_t$. Combine these and rewrite $c_t / n_t$ as a weighted average of past $z$'s (intuitively). If we unroll for two steps for clarity:

At $t=1$:
$c_1 = i_1 z_1,\quad n_1 = i_1,\quad$ so $\tilde{h}_1 = z_1$.

At $t=2$:
$c_2 = f_2 c_1 + i_2 z_2 = f_2 i_1 z_1 + i_2 z_2$,
$n_2 = f_2 n_1 + i_2 = f_2 i_1 + i_2$,
so
$\tilde{h}_2 = \dfrac{f_2 i_1 z_1 + i_2 z_2}{f_2 i_1 + i_2}$.

This is exactly the weighted average of $z_1$ and $z_2$ with weights $f_2 i_1$ and $i_2$. If the network wants $z_2$ to replace $z_1$ it simply makes $i_2 \gg f_2 i_1$ (possible because $i_2$ can be exponentially large). Then $\tilde{h}_2 \approx z_2$. In contrast, with sigmoid gates $i_2$ is capped and might not be able to overwhelm the accumulated $f_2 i_1$ weight, so full replacement is hard.

Worked numerical example
Take simple scalar $z$ values and concrete gate numbers to illustrate replacement. Let $z_1 = 1.0$, $z_2 = 0.9$ (so $z_2$ is more similar to some later query—only the magnitudes matter here). Choose $i_1 = \exp(0) = 1.0$ (first store), $f_2 = \sigma(0) = 0.5$ (moderate carry), and pick two scenarios for $i_2$:

1) Sigmoid-limited scenario (ordinary LSTM-like): suppose $i_2 = \sigma(2) \approx 0.88$. Then
$c_2 = 0.5 * 1.0 * 1.0 + 0.88 * 0.9 = 0.5 + 0.792 = 1.292$,
$n_2 = 0.5 * 1.0 + 0.88 = 0.5 + 0.88 = 1.38$,
so $\tilde{h}_2 = c_2 / n_2 \approx 0.936$. This is a compromise between $1.0$ and $0.9$ and still biased toward the earlier larger $z_1$.

2) Exponential $i_2$ (sLSTM): let $\tilde{i}_2 = 3$ so $i_2 = \exp(3) \approx 20.09$. Now
$c_2 = 0.5 * 1.0 * 1.0 + 20.09 * 0.9 = 0.5 + 18.081 = 18.581$,
$n_2 = 0.5 * 1.0 + 20.09 = 0.5 + 20.09 = 20.59$,
so $\tilde{h}_2 = 18.581 / 20.59 \approx 0.902$. This is essentially $z_2$: the huge $i_2$ overwhelms the carried term $f_2 i_1$, so the later vector replaces the earlier stored content.

Note how the ratio $i_2 / (f_2 i_1)$ controls who wins. Making $i_2$ large is how sLSTM implements revision.

Numerical stability: why we don't overflow and why ratios are preserved
Exponentials can overflow. The paper addresses this with the stabilizer state $m_t$ defined by
$m_t = \max(\log(f_t) + m_{t-1}, \log(i_t))$,
and uses stabilized gates
$i'_t = \exp(\log(i_t) - m_t) = \exp(\tilde{i}_t - m_t)$,
$f'_t = \exp(\log(f_t) + m_{t-1} - m_t)$.
This is a standard log-sum-exp style trick: $m_t$ holds the running maximum log-scale of accumulated contributions; subtracting $m_t$ rescales both the numerator and denominator terms to be in a safe dynamic range. Crucially, this normalization is scale-invariant: it multiplies numerator and denominator of $\tilde{h}_t$ by the same factor so the ratio (hence the network output and gradients) is unchanged. The paper states explicitly that replacing $f_t$ and $i_t$ with $f'_t$ and $i'_t$ "neither change(s) the output of the whole network nor the derivatives of the loss with respect to the parameters." So we get the unbounded relative expressivity of exponential gating without numerical overflow.

Broader perspective and intuition
You can think of sLSTM's $c_t$ and $n_t$ as maintaining a running (unnormalized) weighted sum of stored inputs and of the corresponding weights; dividing yields a kind of exponential-weighted memory readout. Exponential activation turns additive logits into multiplicative (and therefore arbitrarily large) positive weights; the stabilizer ensures operations remain numerically safe. This is similar in spirit to attention where a query can place arbitrarily large (relative) weight on one memory slot via the softmax exponentials; here, the model uses exponentials in the gates to control relative contributions across time. The key difference from standard LSTM is that gates are no longer bounded to $(0,1)$, so a later input can dominate previous memory even when those previous contributions were held by a persistent forget chain.

Concluding remark
So yes: the essential mechanism is that $i_t$ can grow unbounded and by working together with the normalizer $n_t$ the model implements a weighted average where later inputs can dominate (overwrite) earlier ones. The stabilizer $m_t$ and the normalizer $n_t$ are the engineering pieces that keep the arithmetic stable while preserving the relative ratios that effect revision.

### What is the precise role of the normalizer state $n_t$ in sLSTM and why does $h_t$ divide by it?
Question:
In sLSTM, the normalizer evolves as $n_t = f_t n_{t-1} + i_t$ and the hidden pre-output is $\tilde{h}_t = c_t / n_t$. This looks like a normalized weighted average of past inputs. Is $n_t$ theoretically justified as a partition function analog (like normalizing attention weights), or is it more of a numerical stabilization device because $i_t$ can be unbounded? Under what conditions can $n_t$ approach zero, and is that prevented by the same stabilizer $m_t$ trick? Could $n_t$ be interpreted as an exact sum of weights $\prod_{s'=s+1}^t f_{s'}$ applied to each past input weight $i_s$?
Answer:
Short answer: $n_t$ is exactly the normalizing partition that turns the sLSTM cell state into a weighted average of past inputs, so it has both a theoretical role (like the denominator in attention/softmax) and a practical role (protecting against numerical overflow/underflow when using exponential gates). Because the gates are exponentials, $n_t$ is strictly positive in exact arithmetic ($i_t = \exp(\cdot) > 0$), but in finite precision it can underflow toward zero or overflow; the stabilizer $m_t$ is introduced to make the computation numerically safe without changing the mathematical outputs.

Explanation and details grounded in the paper
The sLSTM forward equations in the paper are
$$
c_t = f_t c_{t-1} + i_t z_t,
$$
$$
n_t = f_t n_{t-1} + i_t,
$$
$$
h_t = o_t \left(\frac{c_t}{n_t}\right),
$$
with $i_t = \exp(\tilde i_t)$ and $f_t$ either $\operatorname{sigmoid}$ or $\exp(\tilde f_t)$.

Unrolling the recurrences gives explicit sums over past time steps:
$$
c_t = \sum_{s\le t} i_s z_s \prod_{u=s+1}^t f_u,
$$
$$
n_t = \sum_{s\le t} i_s \prod_{u=s+1}^t f_u.
$$

Thus $n_t$ is exactly the sum of the scalar weights that were applied to each past input contribution in $c_t$. If you define the per‑step weight
$$
w_s(t) := i_s \prod_{u=s+1}^t f_u,
$$
then $c_t = \sum_s w_s(t) z_s$ and $n_t = \sum_s w_s(t)$. Therefore
$$
\tilde h_t = \frac{c_t}{n_t} = \frac{\sum_s w_s(t) z_s}{\sum_s w_s(t)},
$$
so $\tilde h_t$ is a true weighted average of past $z_s$ with weights $w_s(t)$. This is the precise sense in which $n_t$ plays the role of a partition function / normalizer analogous to attention: it normalizes the weighted sum into an average and makes the representation scale‑invariant to a common multiplicative factor on all weights.

Why divide by $n_t$ (intuitive)?
Without dividing, $c_t$ would grow or shrink with the absolute magnitude of the summed weights and would need an extra squashing nonlinearity (as in classic LSTM where $\psi(\cdot)$ is used). By dividing by $n_t$, the model represents the relative mixture of stored contents rather than their absolute accumulation. This helps in retrieval and comparison tasks (similar to attention's normalization) and makes the output less sensitive to scaling of gates.

Numerical issues and the stabilizer $m_t$
Because $i_t$ (and possibly $f_t$) are exponentials, their magnitudes can vary over many orders, causing overflow or underflow in floating point. The paper therefore uses a stabilizer state $m_t$ computed as
$$
m_t = \max\big(\log(f_t) + m_{t-1},\; \log(i_t)\big)
$$
and replaces $i_t,f_t$ by scaled versions $i'_t,f'_t$ defined via exponentials with shifts by $m_t$ (Equations (3)). The important claim in the paper is that these reparameterizations do not change the exact outputs or gradients (they are algebraic rescales that cancel in the recursion), but they do keep intermediate log/exp values in a numerically safe range. Thus $m_t$ is purely for numerical stability; it prevents underflow to zero or overflow to Inf in floating point arithmetic while leaving the mathematical model unchanged.

Can $n_t$ approach zero?
Mathematically (real arithmetic), because $i_s = \exp(\cdot) > 0$ for every $s$, each summand $w_s(t) > 0$ (products of positive numbers), so $n_t = \sum_s w_s(t) > 0$ for all $t$. The only way $n_t = 0$ exactly is if every $i_s = 0$, which does not happen with $i_s = \exp(\cdot)$. So in theory $n_t$ cannot be zero and division by $n_t$ is well‑defined.

In finite precision, however, extremely small $i_s$ or cumulative multiplications of $f_u < 1$ can underflow to $0$, so $n_t$ can numerically become zero (or extremely tiny), producing NaNs or huge ratios. That is exactly why the paper introduces the stabilizer $m_t$ and, for mLSTM, an explicit lower bound on the denominator when forming $h_t$ (they use $\max\{|n_t^\top q_t|, 1\}$ in Equation (9)). The stabilizer rescales logs so exponentials remain in representable range; the lower bound prevents catastrophic division by tiny dot products in mLSTM retrieval. So the combination of the $m_t$ trick and explicit lower bounding in mLSTM prevents numerical problems in practice.

Summary of interpretations
- Exact sum interpretation: Yes — $n_t$ is exactly the sum over past $i_s$ weighted by subsequent forgets: $n_t = \sum_{s\le t} i_s \prod_{u=s+1}^t f_u$. This is stated and used in the paper and is the key algebraic identity.
- Partition function / attention analogy: Conceptually and functionally yes — $n_t$ plays the role of a normalizer (partition) so that $c_t/n_t$ behaves like an attention-weighted average of past inputs, making $h_t$ scale‑invariant as attention does.
- Numerical stabilizer: Also yes — because gates are exponentials, the paper must (and does) add $m_t$ and, in mLSTM, lower bounds to avoid underflow/overflow. The stabilizer does not change the mathematical model; it only preserves numerical stability in finite precision.

So both viewpoints are correct and complementary: $n_t$ is a theoretically justified normalizer (exactly summing the weights applied to past inputs), and practical stabilizers ($m_t$ and lower bounds) are required to implement that theory robustly with exponential gates in floating point.

### Why does replacing $(i_t, f_t)$ with their stabilized versions $(i'_t, f'_t)$ not change outputs or gradients?
Question:
Equations (18–20) introduce a stabilizer state $m_t$ and define $i'_t = \exp(\log i_t - m_t)$ and $f'_t = \exp(\log f_t + m_{t-1} - m_t)$. The paper states (Appendix referenced) that using $(i'_t, f'_t)$ in place of $(i_t, f_t)$ leaves both the forward outputs and the loss gradients w.r.t. parameters unchanged. Could someone sketch the proof? Is it because $m_t$ factors out as a common rescaling over all accumulated terms in $c_t$ and $n_t$, which subsequently cancels in $\tilde{h}_t$ due to division by $n_t$ (and similarly in backprop)? A concise derivation would help.
Answer:
Short answer: Yes — the stabilizer just applies a time-dependent scalar rescaling to the internal accumulation states, and that scalar cancels wherever those states are used to produce the network outputs. Concretely, if you define scaled states
$$
\hat c_t := e^{m_t} c_t,\qquad \hat n_t := e^{m_t} n_t,
$$
then the stabilized recurrences (with $i'_t,f'_t$ as in the paper) transform into the original recurrences driven by the unstabilized gates $i_t,f_t$. Because the final normalized hidden $\tilde h_t = c_t/n_t$ equals $\hat c_t/\hat n_t$, the forward outputs are identical; and hence, by the chain rule, the loss gradients w.r.t. parameters are identical as well. Below is the brief derivation.

Derivation
Define the stabilizer and stabilized gates as in the paper:
$$
m_t=\max(\log f_t + m_{t-1},\; \log i_t),\qquad
i'_t=\exp(\log i_t-m_t)=e^{\tilde i_t-m_t},\qquad
f'_t=\exp(\log f_t+m_{t-1}-m_t).
$$
The sLSTM recurrences with the stabilized gates are
$$
c_t = f'_t\,c_{t-1}+ i'_t\,z_t,\qquad
n_t = f'_t\,n_{t-1}+ i'_t.
$$
Now multiply both equations by $e^{m_t}$ and define $\hat c_t:=e^{m_t}c_t$, $\hat n_t:=e^{m_t}n_t$. Using the definitions of $i'_t,f'_t$,
$$
\begin{aligned}
\hat c_t &= e^{m_t}c_t
= e^{m_t}\big(f'_t c_{t-1} + i'_t z_t\big) \\
&= e^{m_t}\Big(e^{\log f_t + m_{t-1}-m_t} c_{t-1} + e^{\log i_t - m_t} z_t\Big) \\
&= e^{m_{t-1}} f_t\, c_{t-1} + e^{\log i_t} z_t
= f_t \,\hat c_{t-1} + i_t\, z_t.
\end{aligned}
$$
Exactly the same algebra gives
$$
\hat n_t = f_t\,\hat n_{t-1} + i_t.
$$
So the scaled pair $(\hat c_t,\hat n_t)$ obeys the original (unstabilized) update driven by $i_t,f_t$. The hidden pre-output is $\tilde h_t = c_t/n_t$, but
$$
\tilde h_t = \frac{c_t}{n_t} = \frac{e^{-m_t}\hat c_t}{e^{-m_t}\hat n_t} = \frac{\hat c_t}{\hat n_t},
$$
so $\tilde h_t$ computed with stabilized gates equals the $\tilde h_t$ you would get from the original recurrence on $\hat c,\hat n$. Therefore every network output that depends on $\tilde h_t$ (and later on $h_t=o_t\tilde h_t$) is unchanged by the stabilization.

Why gradients are unchanged
Since the network outputs (and hence the loss) are identical under the two implementations, the total derivative of the loss with respect to any model parameter is the same. More operationally, backpropagation through the stabilized computation is equivalent to backpropagation through the original recurrence on $\hat c,\hat n$ followed by a multiplication by $e^{m_t}$ at the forward pass and its reciprocal in the backward pass; these scalar multiplications cancel when producing gradients of the loss with respect to the gate preactivations and ultimately the parameters. Put differently, the forward mapping from parameters to final outputs is the same under both formulations, so their gradients (Jacobian of loss w.r.t. parameters) coincide.

Intuition
The stabilizer chooses a per-time scalar $e^{m_t}$ so that the exponentially large/small gate products are pulled into a single factor. That factor multiplies both the numerators and denominators of the normalized cell output $c_t/n_t$, hence it cancels. Stabilization thus prevents numerical overflow/underflow without changing the mathematical computation the network performs, nor the gradients coming from the loss.

This is the argument sketched in the paper’s appendix; the essential point is the exact algebraic cancellation shown above.

### How is the mLSTM normalizer $\mathbf{n}_t$ used for division, and what is the effect of the absolute value and threshold?
Question:
In mLSTM, $\tilde{\mathbf{h}}_t = \mathbf{C}_t \mathbf{q}_t / \max\{ |\mathbf{n}_t^\top \mathbf{q}_t|, 1\}$. Why do we divide by the scalar $\mathbf{n}_t^\top \mathbf{q}_t$ (absolute value) rather than, e.g., a norm? What is the interpretation—are we normalizing by the accumulated gating mass projected onto the query direction to match the scale of a weighted sum like in attention? How sensitive is performance to the lower bound of 1.0, and what happens if $|\mathbf{n}_t^\top \mathbf{q}_t| \ll 1$? Does the absolute value break any desirable sign information for retrieval?
Answer:
Short answer: the scalar denominator $\mathbf{n}_t^\top \mathbf{q}_t$ is chosen exactly so the mLSTM retrieval becomes the same kind of weighted average you get in attention (weights are the key--query inner products times the stored gate mass). Taking the absolute value and lower-bounding by $1$ are practical stabilizers: they avoid division by near-zero (which would wildly amplify noise) and avoid sign-induced flips that would destabilize training. These choices trade a small loss of sign information for robust, numerically stable retrieval.

Why a dot product (not a norm). Write the two updates that appear in the paper:
$\mathbf{C}_t=\sum_i w_i\,\mathbf{v}_i\mathbf{k}_i^\top$ and $\mathbf{n}_t=\sum_i w_i\,\mathbf{k}_i$, where $w_i$ denotes the input-gate times future forget-gates for the stored item $i$. For a query $\mathbf{q}$,
$$
\mathbf{C}_t\mathbf{q}=\sum_i w_i\,\mathbf{v}_i(\mathbf{k}_i^\top\mathbf{q})
\qquad\text{and}\qquad
\mathbf{n}_t^\top\mathbf{q}=\sum_i w_i\,(\mathbf{k}_i^\top\mathbf{q}).
$$
So dividing $\mathbf{C}_t\mathbf{q}$ by $\mathbf{n}_t^\top\mathbf{q}$ (when positive) yields
$$
\frac{\mathbf{C}_t\mathbf{q}}{\mathbf{n}_t^\top\mathbf{q}}
= \sum_i \alpha_i\,\mathbf{v}_i
\quad\text{with}\quad
\alpha_i=\frac{w_i(\mathbf{k}_i^\top\mathbf{q})}{\sum_j w_j(\mathbf{k}_j^\top\mathbf{q})},
$$
i.e. a weighted average of the stored values $\mathbf{v}_i$ with weights proportional to the usual attention-like scores $w_i(\mathbf{k}_i^\top\mathbf{q})$. A norm (e.g. $\|\mathbf{n}_t\|$) would not cancel the same kernel factors and therefore would not produce this per-query re-weighting; it would be a direction-agnostic scaling and so would not match the scale of the numerator which depends on $\mathbf{k}_i^\top\mathbf{q}$. In short: the dot product aligns the normalizer to the same projection that appears in the numerator, making the result interpretable as an attention-style normalized sum.

Why absolute value and the threshold. As the paper states (and as used e.g. in Retention/Sun et al.), $\mathbf{n}_t^\top\mathbf{q}$ can be very small or cross zero: if it is tiny, dividing would blow up magnitudes and amplify noise; if it is negative, naïvely dividing would flip the sign of the entire retrieved vector even when numerator and denominator signs might not be paired in a stable way during learning. Taking $|\mathbf{n}_t^\top\mathbf{q}|$ guarantees a non-negative scale, and applying $\max\{\cdot,1\}$ prevents any division factor below $1$. Practically this means that when the accumulated gate mass projected on $\mathbf{q}$ is small (i.e. little relevant stored evidence for this query direction), the model simply returns the raw $\mathbf{C}_t\mathbf{q}$ (no amplification), instead of producing an enormous or unstable scaled vector. The paper reports using $1.0$ as a typical threshold (citing prior work); this is a conservative clamp that keeps outputs stable.

What happens if $|\mathbf{n}_t^\top\mathbf{q}_t|\ll 1$. Two regimes are instructive. If the true accumulated mass in the query direction is tiny, then there is little reliable retrieval signal: dividing by a small number would produce extremely large, likely meaningless outputs. The threshold forces the denominator to be at least $1$, so the network simply outputs the unamplified $\mathbf{C}_t\mathbf{q}$ (possibly near-zero), avoiding instability. If you removed the threshold, training would become sensitive and likely unstable unless additional careful normalization or regularization is used. The paper frames this as a numerical stabilization step and cites similar choices in related methods.

Does the absolute value “break” sign information for retrieval? Not in a way that the architecture cannot represent, because the numerator $\mathbf{C}_t\mathbf{q}$ already contains the signed contributions $(\mathbf{k}_i^\top\mathbf{q})$ multiplying $\mathbf{v}_i$. If numerator and denominator shared a global negative sign (both flipped), dividing by the absolute value avoids a final sign flip but the vector content (relative weighting among values) is preserved up to magnitude normalization. In other words, sign of $\mathbf{k}_i^\top\mathbf{q}$ is still used in the per-item weighting inside $\mathbf{C}_t\mathbf{q}$; the absolute value only removes a global sign ambiguity in the normalization scalar to keep the scale positive and stable. In practice, the authors judge this acceptable because the useful directional information is encoded in the components (values and per-item inner products) rather than in the global sign of the scalar normalizer.

Sensitivity to the choice $1.0$. The paper and prior works use $1.0$ as a simple, robust lower bound; the exact value is a stability hyperparameter. Making the threshold much smaller will allow larger amplification when projected mass is small and risks instability, while a much larger threshold will under-normalize (reduce effective normalization) and change the scale of retrieved vectors, which could be learned around but may slow or complicate training. The paper does not present a large ablation sweep of this constant, but frames it as a practical stabilization (and cites Sun et al. who use a similar lower bound), so using $1.0$ is a reasonable default; small adjustments might be tolerated but removing the clamp entirely typically hurts numerical stability.

Summary. Dividing by $\mathbf{n}_t^\top\mathbf{q}_t$ aligns the denominator with the same per-query projections that weight the numerator, producing an attention-like normalized weighted sum over stored values. The absolute value and lower bound are pragmatic numerical safeguards: they avoid division-by-near-zero and uncontrolled sign flips, at the cost of removing a global sign in the scalar normalizer — a cost that the architecture absorbs because the per-item signed contributions remain in $\mathbf{C}_t\mathbf{q}$.

### Is the mLSTM covariance update just a form of linear attention with gating?
Question:
The mLSTM update is $\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top$, and retrieval is $\mathbf{C}_t \mathbf{q}_t$ normalized by $\max\{|\mathbf{n}_t^\top \mathbf{q}_t|, 1\}$. This strongly resembles linearized attention with features $\phi(\mathbf{x}) = \mathbf{x}$ (no kernel), learning rate $i_t$, and decay $f_t$. Is mLSTM functionally equivalent to a gated linear attention mechanism plus an output gate $\mathbf{o}_t$? If not, what key differences remain (e.g., use of absolute value in normalization, per-step scalar gates vs per-head/token gates)?
Answer:
Short answer: No — mLSTM is closely related to a class of linear (kernelized) attentions / fast weights, but it is not simply “linear attention + an output gate.” The paper’s mLSTM implements a fast-weight / covariance memory that matches some algebraic aspects of linearized attention (especially with feature map $\phi(x)=x$), but it adds several architecturally and numerically important ingredients that change behavior and capabilities.

Why they look similar
- Algebraically the mLSTM memory update
  $\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \,\mathbf{v}_t \mathbf{k}_t^\top$
  and retrieval $\mathbf{C}_t \mathbf{q}_t$ mirror the linear-attention pattern “accumulate K,V outer products, then multiply by q”. If you take $\phi(\cdot)=\mathrm{Id}$, linear attention often amounts to computing
  $\left(\sum_{s\le t} w_s \mathbf{v}_s \mathbf{k}_s^\top\right)\mathbf{q}_t$
  (with some weights $w_s$), so the mLSTM update with scalar per-step factors $i_t$ (learning rate) and $f_t$ (decay) is exactly in that family. In historical terms, this is fast-weights / covariance memory (Sejnowski / Fast Weight Programmers / Linear Transformer variants).

Key differences called out in the paper (and why they matter)
1. Normalization uses an absolute-valued dot and a floor: mLSTM divides by $\max\{|\mathbf{n}_t^\top \mathbf{q}_t|,1\}$ where $\mathbf{n}_t$ is the running sum of keys weighted by the same gates. Linear attention implementations typically divide by $\phi(q)^\top(\sum \phi(k))$ (no absolute, often assumed positive when $\phi$ is positive), or they use softmax normalization. The absolute value + lower-bound prevents tiny/negative denominators and stabilizes retrieval when $\mathbf{n}_t^\top \mathbf{q}_t$ is close to zero or negative — behavior that changes the effective attention normalization and the sign/scale sensitivity compared to standard linear attention.

2. Gate granularity and dynamics: mLSTM uses scalar gates per time step (scalar $i_t$, scalar $f_t$) computed from the input (plus stabilization machinery). Typical multi-head linear attention uses per-head (or per-dimension) scalings implicitly via different projection matrices for keys/values/queries and sometimes learned per-head softmax temperatures. Scalar gates give a global learning/decay rate for the whole $d\times d$ memory at a step, which is a much coarser control than per-head or per-token scalings and yields different capacity / interference trade-offs.

3. Exponential (and stabilized) gating: the input gate in mLSTM is $\exp(\tilde{i}_t)$ (and forget gate can be exponential), with a dedicated stabilizer state $m_t$ to avoid overflow. That allows multiplicative learning-rate factors that can be $>1$ and compounds multiplicatively over time in a way that typical linear-attention implementations (which use small scalar learning rates or softmax weights in $[0,1]$) do not. This changes both numerical stability and how new items overwrite older memory.

4. Explicit normalizer state $\mathbf{n}_t$: mLSTM maintains $\mathbf{n}_t = f_t \mathbf{n}_{t-1} + i_t \mathbf{k}_t$ and uses it for normalization. This keeps an explicit record of effective key mass (weighted keys over time) and is used in the special denominator above. In linear attention you usually implicitly have the same object $\sum \phi(k)$ but (a) $\phi$ is often chosen positive (so no sign issues) and (b) many implementations do different normalizations (e.g., softmax-style or positive-feature kernels). The mLSTM choice is tailored to stability and to work with signed keys.

5. Output gating is vector-valued and multiplicative: mLSTM applies $\mathbf{o}_t \odot \tilde{\mathbf{h}}_t$. This is more expressive than a single scalar readout multiplier; it lets the model mask or scale different output coordinates after retrieval, which affects how retrieved information is fed forward. That is not present in a vanilla linear-attention readout unless you add an extra gating projection.

6. Architectural context and training dynamics: mLSTM is an LSTM-family recurrence (with stabilizers, layer-norm before projections, optional multiple cells) and is optimized/trained in that framework. Design choices like key/value normalization (e.g. scaling keys by $1/\sqrt{d}$), layer-norm pre-projection, and the residual block placement (pre/post up-projection) influence gradients, optimization and scaling behavior in ways not captured by a naively “attention + gate” view.

7. Memory representation and intended invariants: mLSTM stores a full $d\times d$ covariance-like matrix $\mathbf{C}_t$. While algebraically similar to accumulated KV sums, the paper treats $\mathbf{C}_t$ as an associative memory (BAM / covariance storage) with optimality arguments for separability. Some linear-attention approximations instead maintain low-rank factorizations or restrict feature maps to be positive to ensure associativity and numerical stability.

Intuition and broader view
Think of mLSTM as a carefully engineered fast-weights memory that borrows the same algebraic core as linear attention (accumulate outer products, multiply by query). But the authors make several departures to make that memory stable, trainable at LLM scales, and capable of the LSTM-style gating behaviors (exponential gates, stabilizers, explicit normalizers, output gating). Those differences change numerical stability, overwrite behavior, and how interference between stored items is handled — so they are not cosmetic.

Conclusion
mLSTM belongs to the same family as linearized attention / fast weights, and you can view it as a gated fast-weight mechanism. However, it is not functionally equivalent to a vanilla linear-attention head plus a simple output gate: the normalization (absolute + floor), scalar exponential gates with stabilization, explicit normalizer state, and output-gating granularity are important design differences that change retrieval dynamics, stability, and expressivity. These differences are precisely what the paper argues enable better revision of storage decisions, larger storage capacity, and robust scaling.

### Why are multiple heads and multiple cells equivalent in mLSTM but not in sLSTM?
Question:
The paper states that for mLSTM, multiple heads and multiple cells are equivalent since there is no memory mixing, but for sLSTM heads introduce a new way of memory mixing (within head, across cells). Could someone formalize this? If we have $H$ heads with independent matrix memories $\{\mathbf{C}^{(h)}\}_{h=1}^H$ and concatenate their outputs, how is that equivalent to having $H$ separate cells? In sLSTM, how exactly does head-level isolation prevent cross-head mixing while allowing within-head recurrent mixing across cells via $\mathbf{R}_\bullet$?
Answer:
Short answer: for mLSTM “heads” can be implemented as independent matrix memories whose updates and retrievals never use hidden-to-hidden (recurrent) mixing, so concatenating their outputs is algebraically identical to having several independent mLSTM cells. For sLSTM this equivalence breaks because sLSTM with multiple cells uses recurrent weight matrices $\mathbf{R}_\bullet$ that take the previous hidden state as input to gates and cell inputs; if those $\mathbf{R}_\bullet$ are not block‑diagonal across heads they cause cross‑cell recurrent mixing. Restricting recurrent connections at the head level (making $\mathbf{R}_\bullet$ block‑diagonal) prevents cross‑head recurrent mixing but still allows within‑head recurrent mixing across the cells (because the cells inside a head share the same recurrent block), so heads in sLSTM create a different memory‑mixing pattern than separate independent cells.

Formalization (grounded in the paper)

1) mLSTM: no memory mixing -> algebraic equivalence of heads and separate cells.

The mLSTM cell maintains a matrix memory $\mathbf{C}_t$ and performs updates and retrievals without using any hidden-to-hidden recurrent matrices (the paper explicitly removes recurrent mixing for mLSTM). Consider $H$ independent mLSTM heads, each with its own matrix memory $\mathbf{C}_t^{(h)}$, query $\mathbf{q}_t^{(h)}$, value/key updates, input/forget scalars $i_t^{(h)}, f_t^{(h)}$, and output gating $\mathbf{o}_t^{(h)}$. The $h$-th head produces a hidden subvector

$\displaystyle \tilde{\mathbf{h}}_t^{(h)} \;=\; \mathbf{C}_t^{(h)} \mathbf{q}_t^{(h)} \,/\, \max\{|\mathbf{n}_t^{(h)\top}\mathbf{q}_t^{(h)}|,1\},$
\qquad
$\displaystyle \mathbf{h}_t^{(h)} \;=\; \mathbf{o}_t^{(h)} \odot \tilde{\mathbf{h}}_t^{(h)}.$

If we form a single big memory $\mathbf{C}_t^{\text{big}}$ that is block‑diagonal with blocks $\mathbf{C}_t^{(1)},\dots,\mathbf{C}_t^{(H)}$, and likewise concatenate queries, keys, values, output gates into block vectors, then the single mLSTM with $\mathbf{C}_t^{\text{big}}$ produces exactly the concatenation of the $H$ head outputs. Concretely, let

$\displaystyle \mathbf{C}_t^{\text{big}} = \mathrm{blockdiag}\big(\mathbf{C}_t^{(1)},\dots,\mathbf{C}_t^{(H)}\big),$
\quad
$\displaystyle \mathbf{q}_t^{\text{big}} = \begin{bmatrix}\mathbf{q}_t^{(1)}\\ \vdots\\ \mathbf{q}_t^{(H)}\end{bmatrix},$
\quad
$\displaystyle \mathbf{o}_t^{\text{big}} = \begin{bmatrix}\mathbf{o}_t^{(1)}\\ \vdots\\ \mathbf{o}_t^{(H)}\end{bmatrix}.$

Then $\mathbf{C}_t^{\text{big}}\mathbf{q}_t^{\text{big}}$ is the concatenation of the $\mathbf{C}_t^{(h)}\mathbf{q}_t^{(h)}$ and the normalizer/norm is separable per block, so the block output equals stacking the $H$ head outputs. Because there are no hidden‑to‑hidden recurrent matrices mixing entries from different heads across time, nothing in the recurrence couples the blocks; therefore “$H$ heads” with independent memories is exactly equivalent to “$H$ separate mLSTM cells” (up to trivial reparameterizations like permuting blocks). This is what the paper means by “no memory mixing” and the equivalence of heads and cells for mLSTM.

2) sLSTM: recurrent matrices $\mathbf{R}_\bullet$ create cross‑cell temporal mixing; head isolation changes which cross‑cell mixes are allowed.

sLSTM retains the usual LSTM style gates and (for multi‑cell variants) uses recurrent matrices from the previous hidden state into the gates and inputs. For a vector of cells $\mathbf{c}_t\in\mathbb{R}^d$ and hidden $\mathbf{h}_t$, the gate preactivations use terms like

$\displaystyle \tilde{\mathbf{z}}_t = \mathbf{W}_z \mathbf{x}_t + \mathbf{R}_z \mathbf{h}_{t-1} + b_z,$
\quad
$\displaystyle \tilde{\mathbf{i}}_t = \mathbf{W}_i \mathbf{x}_t + \mathbf{R}_i \mathbf{h}_{t-1} + b_i,$

and similarly for $\mathbf{f},\mathbf{o}$. These $\mathbf{R}_\bullet$ matrices are the source of memory mixing: they can linearly combine different cell outputs from $\mathbf{h}_{t-1}$ and feed those mixtures into each cell’s gates and inputs, thereby enabling interactions across cells over time.

If you partition the hidden/cell vector into $H$ heads (blocks) but keep full $\mathbf{R}_\bullet$, then the recurrent mapping will mix components across heads: information stored in any cell can affect the gate/input preactivations of any other head at the next step. That produces cross‑head memory mixing that is not present when heads are independent.

To prevent cross‑head mixing you must enforce head‑level isolation by making the recurrent matrices block‑diagonal with respect to the head partition:

$\displaystyle \mathbf{R}_\bullet = \mathrm{blockdiag}\big(\mathbf{R}_\bullet^{(1)},\dots,\mathbf{R}_\bullet^{(H)}\big).$

With this constraint, $\mathbf{h}_{t-1}$ from head $k$ only affects gates/inputs of head $k$ at time $t$, so heads remain isolated across time. However, inside a head the recurrent block $\mathbf{R}_\bullet^{(h)}$ can still be dense across that head’s internal cells, so cells within the same head are mixed across time. Thus “heads” in sLSTM are a structural way to control the pattern of recurrent mixing: they eliminate cross‑head mixing (if you choose block‑diagonal recurrence) but do not eliminate within‑head mixing. Because those within‑head $\mathbf{R}_\bullet^{(h)}$ can implement arbitrary linear mixing among cells in the head, having multiple heads is not algebraically equivalent to having multiple completely independent cells: a single vector of cells with a full $\mathbf{R}_\bullet$ can realize interactions that a mere concatenation of independent cells cannot.

Intuition and why the paper phrases it this way

The key difference is whether the recurrence contains parameters that connect past hidden outputs into future cell updates. mLSTM deliberately removes parameterized hidden‑to‑hidden mixing: its memory is an external matrix updated by outer products and read by matrix–vector products, so separate memories remain separate and heads simply correspond to independent memory blocks. sLSTM preserves recurrent matrices $\mathbf{R}_\bullet$; these are exactly the mechanism by which past memory content flows into future updates and can be routed between cells. Thus heads in sLSTM are a design choice that restricts where those recurrent pathways exist (no cross‑head paths if you make $\mathbf{R}_\bullet$ block‑diagonal), but they do not make heads algebraically identical to separate independent cells unless you also forbid within‑head recurrent mixing.

Summary: for mLSTM heads = separate cells because memory updates/reads do not use recurrent mixing and can be arranged as independent block memories. For sLSTM, recurrent matrices $\mathbf{R}_\bullet$ mediate temporal mixing across cells; making $\mathbf{R}_\bullet$ block‑diagonal enforces head‑level isolation (no cross‑head mixing), yet within each head the recurrent block still mixes that head’s cells across time, so heads introduce a different (and richer) memory‑mixing pattern than simply having independent scalar cells.

### Parallelization of mLSTM: what is the exact scan/associative formulation?
Question:
The paper claims mLSTM is fully parallelizable (like FlashAttention or GLA) and refers to an appendix for a parallel form. Given $\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top$ and $\mathbf{n}_t = f_t \mathbf{n}_{t-1} + i_t \mathbf{k}_t$, can someone write the exact associative operator that enables a parallel prefix scan over time? Is it a semiring over pairs $(\mathbf{C}, \mathbf{n})$ with a time-varying scalar $f_t$? A concrete expression showing how to combine two segments' summaries into one would clarify implementation.
Answer:
Short answer: yes — you can turn the mLSTM recurrence into an associative binary operator on a per-time-step summary triple $(P, M, m)$ so a parallel prefix scan produces the same final $\mathbf{C}_t,\mathbf{n}_t$. The operator is non‑commutative (order matters) and uses a scalar product-of-forgets $P$ plus an accumulated matrix $M$ and vector $m$. Combine two adjacent segments L then R by

If a segment $S$ has
$$P_S = \prod_{t\in S} f_t,$$
$$M_S = \sum_{t\in S} \Big( \big(\prod_{s\in S,\, s>t} f_s\big)\; i_t \, \mathbf{v}_t \mathbf{k}_t^\top\Big),$$
$$m_S = \sum_{t\in S} \Big( \big(\prod_{s\in S,\, s>t} f_s\big)\; i_t \, \mathbf{k}_t\Big),$$

then for two adjacent segments $L$ (earlier) and $R$ (later) the composition (L then R) is

$$P_{L\circ R} = P_R \, P_L,$$
$$M_{L\circ R} = P_R \, M_L \;+\; M_R,$$
$$m_{L\circ R} = P_R \, m_L \;+\; m_R.$$

Proof sketch/intuition: run $L$ first with some input $\mathbf{C}_{in},\mathbf{n}_{in}$: after $L$ you have $\mathbf{C}_L = P_L \mathbf{C}_{in} + M_L$ and $\mathbf{n}_L = P_L \mathbf{n}_{in} + m_L$. Feeding that into $R$ multiplies the whole L-output by $P_R$ and adds R's own accretion, yielding the composition formulas above. These formulas are associative because matrix/vector addition and scalar multiplication are associative; hence a binary tree (parallel) reduction or a parallel prefix (scan) over the per-step summaries reproduces the sequential recurrence.

Practical notes tied to the paper
1) Per time step $t$ you can emit the elementary triple
$$P_t = f_t,$$
$$M_t = i_t \,\mathbf{v}_t \mathbf{k}_t^\top,$$
$$m_t = i_t \,\mathbf{k}_t,$$
and then reduce them with the associative operator above to obtain segment summaries. From a segment summary $(P_S,M_S,m_S)$ you recover the segment effect on any input $(\mathbf{C}_{in},\mathbf{n}_{in})$ by $\mathbf{C}_{out}=P_S\mathbf{C}_{in}+M_S$ and $\mathbf{n}_{out}=P_S\mathbf{n}_{in}+m_S$.

2) Initialization: if you want the full prefix up to $t$ starting from zero memory, run a prefix scan over $(P_t,M_t,m_t)$ to obtain $(P_{1:t},M_{1:t},m_{1:t})$ and then $\mathbf{C}_t=M_{1:t}, \mathbf{n}_t=m_{1:t}$ (since $P_{1:t}\mathbf{C}_0$ with $\mathbf{C}_0=0$ vanishes).

3) Numerical/stability: the paper discusses exponential forget/input gates and a stabilizer state (log-scaling). In practice you often store $\log P$ (sum of $\log f_t$) and scale $M,m$ accordingly (or use the stabilizer trick from the paper) to avoid overflow/underflow when forming products of many $f_t$.

4) Complexity: the operator stores a scalar $P$, a $d\times d$ matrix $M$ and a $d$-vector $m$ per partial result; the combine step uses scalar-vector/matrix scaling and add, which is parallelizable across segments (exactly what the paper claims). This matches the mLSTM design: matrix memory $\mathbf{C}$ and normalizer $\mathbf{n}$ are produced by linear (associative) accumulation.

So the concrete associative operator is the map
$$(a_L,b_L,c_L) \oplus (a_R,b_R,c_R) = (a_R a_L,\; a_R b_L + b_R,\; a_R c_L + c_R),$$
with $a = P$ (scalar), $b = M$ (matrix), $c = m$ (vector). This is non‑commutative but associative and is exactly what you need for a parallel prefix scan reproducing the sequential mLSTM updates.

### Computational complexity of mLSTM’s matrix memory: is the $\mathcal{O}(d^2)$ cost per token unavoidable?
Question:
Each step updates and applies a $d \times d$ matrix $\mathbf{C}_t$, implying $\mathcal{O}(d^2)$ compute and memory traffic per token. Are there structured parameterizations or low-rank approximations consistent with the covariance update (e.g., maintaining $R$ rank-1 terms with decays) that preserve the claimed properties (gating, normalization, parallelization) while reducing cost to $\mathcal{O}(dR)$? If so, what is lost in terms of capacity or retrieval fidelity versus full-rank $\mathbf{C}_t$?
Answer:
Short answer: Yes — you can maintain mLSTM’s covariance memory in a structured low‑rank form that reduces per‑token work to $O(dR)$ while preserving gating, normalization and parallel updates. What you give up is effective memory capacity and retrieval fidelity compared to the full $d\times d$ covariance: low‑rank $C$ can only represent a subspace of key–value correlations, so interference (noise) and mistaken retrieval increase unless $R$ is large or you add orthogonalization / multiple heads / periodic compression.

Why a low‑rank parameterization is compatible with mLSTM
The mLSTM cell uses the covariance (outer‑product) update
$$
\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t\, \mathbf{v}_t \mathbf{k}_t^\top,
$$
and retrieval is the matrix–vector product $\tilde{\mathbf h}_t=\mathbf{C}_t\mathbf{q}_t / \text{norm}$. If you maintain $\mathbf{C}_t$ in factored form
$$
\mathbf{C}_t = \sum_{r=1}^R \mathbf{a}_{t,r}\, \mathbf{b}_{t,r}^\top,
$$
where each $\mathbf{a}_{t,r},\mathbf{b}_{t,r}\in\mathbb{R}^d$, the update and read become $O(dR)$: the decay multiplies each factor $\mathbf{a}_{t-1,r}\leftarrow f_t\mathbf{a}_{t-1,r}$, $\mathbf{b}_{t-1,r}\leftarrow \mathbf{b}_{t-1,r}$ (or multiply both by $\sqrt{f_t}$ if you prefer balanced scaling), and you append (or inject) the new rank‑1 term $\,i_t\,\mathbf{v}_t\mathbf{k}_t^\top$. Retrieval is
$$
\mathbf{C}_t\mathbf{q}_t = \sum_{r=1}^R \mathbf{a}_{t,r}\,(\mathbf{b}_{t,r}^\top\mathbf{q}_t),
$$
so cost is $O(dR)$ per token (dot products plus scaled vector sums). The normalizer $\mathbf{n}_t$ is likewise low‑rank if you store it as a sum of the key vectors weighted by gate history; its dot with $\mathbf{q}_t$ costs $O(dR)$ as well. Nothing in the paper’s gating, normalization, or stabilization logic requires a dense $\mathbf{C}_t$, so this approach preserves exponential/input gating, the normalizer, the parallel formulation (no hidden–hidden mixing), and is compatible with the mLSTM parallel update described in the paper.

Practical variants that keep $O(dR)$ complexity
A few practical designs mirror existing literature the paper cites (Linformer, Fast Weights, low‑rank attention/approximate attention):

1) Fixed growing factor list: keep a circular buffer of the last $R$ factors (or $R$ learned slots); decay older factors by $f_t$ and overwrite oldest with $i_t\mathbf{v}_t,\mathbf{k}_t$. This is simplest but capacity is literally $R$ directions.

2) Compressed / budgeted low‑rank: when you would exceed $R$, compress the factor set (e.g., lightweight incremental SVD or rank‑$R$ projection) to retain the top $R$ components; this trades extra computation occasionally for continual low cost.

3) Multi‑head factorization: split $d$ into $H$ smaller heads of dimension $d/H$ and give each head rank $R_h$; this keeps $O(dR)$ overall but increases expressivity via multiple subspaces (this matches the paper’s observation that heads for mLSTM are equivalent to multiple cells).

4) Sketching / random projection for keys: project keys to an $R$‑dimensional key space with a learned or random map and store outer products in that reduced space (similar spirit to Linformer / Performer). This reduces $R$ needed for a given fidelity at the cost of approximation error dependent on the projection.

What you lose vs. full‑rank $C_t$
The paper argues the covariance rule is “optimal” for maximal separability / signal‑to‑noise when keys/values are uncompressed; a low‑rank representation changes that trade‑off:

- Reduced expressive capacity: a rank‑$R$ $C_t$ can represent only $R$ independent value–key correlation directions. If important past key–value correlations lie outside that $R$‑dimensional subspace, they are lost or aliased.

- Higher interference / lower SNR: when many stored outer products project onto similar directions inside the rank‑$R$ subspace, retrieval becomes noisy. The full $d\times d$ matrix can, in principle, separate more orthogonal directions and give larger signal/noise as the paper notes (Dayan91, Sejnowski77 references).

- Dependence on key geometry: retrieval fidelity now depends heavily on how orthogonal or compressible the keys are into $R$ dimensions. If keys are near‑orthogonal in $d$, a small $R$ will fail; if keys lie on a low‑dimensional manifold, small $R$ can do well.

- Loss of the “optimal” separability guarantee: the paper states the covariance update is optimal for binary vectors in the full space. Compressing $C$ breaks that optimality; you are approximating the optimal full covariance.

How to mitigate losses (engineering knobs)
To approach full‑rank fidelity while keeping $O(dR)$:

- Increase $R$ until empirical retrieval fidelity is acceptable; $R$ need not equal $d$, often much smaller suffices if keys are structured.

- Use multiple heads or multiple low‑rank matrices to cover different subspaces (the paper already points to equivalence of heads and cells for mLSTM).

- Periodic compression with SVD or QR to re‑orthogonalize factors and remove redundancy, reducing interference.

- Encourage key diversity with a training regularizer (orthogonality, spectral penalty) so a small $R$ captures more of the useful directions.

- Use learned low‑dimensional key maps (learned projections to $R$ dims) so the network compacts keys into an $R$‑dimensional working space — similar trade‑offs explored by Linformer / Performer (cited in the paper).

When low‑rank is a good idea
If your application or dataset produces keys with low intrinsic dimension (many keys are correlated or lie on a manifold), then a low‑rank mLSTM will keep most retrieval fidelity at much lower cost. If your workload requires near‑perfect separability of many arbitrary keys (e.g., arbitrary associative recall with a huge vocabulary), you will need $R$ approaching $d$ (or use full $d\times d$), as the experiments and discussion around associative recall in the paper indicate: Transformers can realize exponentially large memorization by coding in a high‑dimensional space; compressing that with low rank reduces that power.

Bottom line
A rank‑$R$ factorization of $\mathbf{C}_t$ is fully consistent with the mLSTM design in the paper and reduces per‑token compute/memory to $O(dR)$ while preserving gating, normalization and parallel updates. The trade‑off is less representational capacity and increased retrieval interference compared to a full $d\times d$ covariance; mitigating strategies include increasing $R$, using multiple heads, orthogonalization/compression steps, and learned key projections. Which point on the $R$ vs. fidelity curve is acceptable is empirical and depends on the key geometry of your task; the paper’s discussion and experiments (associative recall, trade‑offs with attention) make this trade‑off explicit.

### How critical is the zero-mean assumption for keys/values in the covariance update rule?
Question:
The paper assumes LayerNorm before key/value projections so that keys/values have zero mean, then cites optimality properties of the covariance rule. What breaks if the mean-shift is nonzero (e.g., due to learned biases or distribution drift)? Does a nonzero mean introduce a spurious rank-1 component that degrades retrieval via increased cross-talk? Would explicit mean-centering per batch or per sequence be preferable to relying on LayerNorm?
Answer:
Short answer: the zero-mean assumption is important for the covariance update to behave like the ideal outer-product memory described in the paper. If keys or values carry a nonzero mean (from biases, learned offsets, or distribution drift) you effectively inject a persistent rank-1 term into the matrix memory which (a) biases retrieval and (b) reduces signal-to-noise, so retrieval quality and the separability optimality the paper cites degrade. Practically you should keep LayerNorm (or another explicit mean-centering) before the key/value projections; if that is not possible, remove or correct the mean via simple explicit fixes (mean-subtraction, projecting out dominant components, or removing biases).

Why this happens (intuitive + math): the mLSTM covariance update is
$$
\mathbf{C}_t=\mathbf{C}_{t-1}+i_t\,\mathbf{v}_t\mathbf{k}_t^\top,
$$
and retrieval uses $\mathbf{C}_t\mathbf{q}$. If $\mathbf{k}_t=\bar{\mathbf{k}}+\tilde{\mathbf{k}}_t$ with a persistent mean $\bar{\mathbf{k}}$ and zero-mean fluctuation $\tilde{\mathbf{k}}_t$, then every update contributes a component $i_t\mathbf{v}_t\bar{\mathbf{k}}^\top$. Over time these add up into a large, slowly changing rank-1 matrix
$$
\sum_t i_t\mathbf{v}_t\bar{\mathbf{k}}^\top = \left(\sum_t i_t\mathbf{v}_t\right)\bar{\mathbf{k}}^\top,
$$
which acts like a strong, non-signal-aligned memory entry. When you later compute $\mathbf{C}_t\mathbf{q}$ this term produces a spurious contribution proportional to $(\sum_t i_t\mathbf{v}_t)(\bar{\mathbf{k}}^\top\mathbf{q})$. Two concrete consequences follow.

1) Bias and cross-talk. If $\bar{\mathbf{k}}^\top\mathbf{q}$ is nonzero for many queries $\mathbf{q}$, the rank-1 part leaks information into retrievals that should be orthogonal, causing cross-talk and systematic bias. In other words, the memory no longer cleanly separates stored pairs, because a global key-direction pollutes everything.

2) Reduced signal-to-noise and suboptimality. The optimality statement the paper cites (covariance updates maximize separability / SNR under zero-mean assumptions) relies on the stored outer-products being centered around zero so different pairs act like independent directions. A dominant mean term increases the noise floor or can swamp weak genuine signals, reducing the effective capacity and degrading retrieval accuracy.

How it interacts with the paper’s normalizer and denominator. The mLSTM also keeps a normalizer $\mathbf{n}_t=\sum f\cdots i_t \mathbf{k}_t$ and uses $\max\{|\mathbf{n}_t^\top\mathbf{q}|,1\}$ in the denominator. A nonzero mean shifts $\mathbf{n}_t$ too, so the stabilizing denominator can become large or structured in a way that changes scaling across queries and effectively masks or rescales correct retrievals unpredictably. The normalization helps some pathological cases but does not remove structured rank-1 contamination.

Practical remedies (grounded in the paper’s choices)

- Keep the LayerNorm before the key/value projections, as the paper does. Pre-projection LayerNorm enforces approximate zero-mean keys/values and is the simplest, low-cost solution consistent with the model design in the paper.

- Remove or tie biases on key/value projections. The paper’s equations include biases $\mathbf{b}_k,\mathbf{b}_v$; if you keep them, they create obvious mean shifts. Either set these biases to zero or ensure they are canceled by preceding normalization.

- Explicit mean-centering. Subtract a mean estimate from $\mathbf{k}_t$ and/or $\mathbf{v}_t$ per sequence or per batch:
$$
\tilde{\mathbf{k}}_t=\mathbf{k}_t-\frac{1}{T}\sum_{s=1}^{T}\mathbf{k}_s
$$
Per-sequence centering most closely matches the assumption the covariance rule relies on. Per-batch centering is cheaper and often effective, but be aware it can leak batch statistics and interact with distribution shifts.

- Running or exponential moving mean / drift correction. If distribution drift is a concern across long training runs or nonstationary data, maintain a running mean and subtract it, or periodically re-center keys/values.

- Project out dominant principal components. If you observe a dominant direction that corrupts retrieval, remove the top singular vector from keys (and/or values). This is a slightly heavier operation but targets exactly the rank-1 contamination problem.

- Learn a correction or gating. You can let a gate downweight a global mean component (learn a scalar or vector gate on $\bar{\mathbf{k}}$ direction), but this adds complexity and must be carefully regularized.

Recommendation in one sentence: follow the paper and keep LayerNorm (or explicit mean-subtraction per sequence) before key/value projections; if you see retrieval degradation or strong dominant singular vectors during training, remove the mean or project out the top component rather than relying on implicit cancellation.

Monitoring tip: track the norm and top singular value of accumulated $\mathbf{C}_t$ (or of the sequence of $\mathbf{k}_t$ vectors). If a single direction captures a large fraction of energy, you have mean-induced rank-1 contamination and should apply one of the remedies above.

This explanation stays within the paper’s design: the covariance update is optimal under zero-mean keys/values (as they state), and nonzero mean creates exactly the rank-1 leakage described; LayerNorm or explicit centering is the intended and pragmatic way to preserve the covariance rule’s desirable properties.

### Does exponential forgetting $f_t = \exp(\tilde{f}_t)$ preserve the ‘constant error carousel’ property?
Question:
Classic LSTM avoids vanishing gradients partly because $c_t$ accumulates additively with $f_t \in (0,1)$ typically near 1. With $f_t = \exp(\tilde{f}_t)$, $f_t$ can be greater than 1 or much smaller than 1. How does this affect gradient flow through time in $c_t$ or $\mathbf{C}_t$? Are there initialization or regularization strategies (e.g., biasing $\tilde{f}_t$) that ensure effective long-range credit assignment without exploding/vanishing due to $\prod f_t$? The Limitations section mentions careful initialization—what concretely works in practice?
Answer:
Short answer: Exponential forgetting does not automatically break the constant error carousel (CEC) idea, but it changes how you must control gate magnitudes. With \(f_t=\exp(\tilde f_t)\) the multiplicative factor that carries gradients backwards is unbounded on the upper side (and can be arbitrarily small), so the usual intuitive CEC mechanism ("forget gate near 1 preserves gradients") still applies, but you must (a) initialize and stabilize the exponentials so they sit near 1 initially, and (b) use the normalization/stabilization tricks the paper introduces so neither exploding nor vanishing products \(\prod f_t\) dominate training.

Why: gradient flow through the scalar sLSTM cell is governed by the same recurrence that gives the CEC. From the forward rule
\[
c_t = f_t\,c_{t-1} + i_t z_t,
\]
the backpropagated partial of a loss \(\mathcal L\) at time \(T\) to a previous cell state \(c_{t-\tau}\) contains factors of \(\prod_{s=t-\tau+1}^{t} f_s\). If \(f_s\approx 1\) you recover the original CEC effect (no vanishing); if many \(f_s\ll 1\) you get vanishing, and if many \(f_s\gg 1\) you can get exploding gradients. Replacing sigmoid by exponential simply changes the allowed range of \(f_t\): sigmoid enforces \(f_t\in(0,1)\) while \(\exp(\tilde f_t)\in(0,\infty)\). Thus exponential gating gives more expressivity (can amplify old memory or rapidly erase it), but it also requires explicit mechanisms to prevent numerical/optimization pathologies.

What the paper does (and why it helps): xLSTM introduces three concrete mechanisms to keep gradient flow well-behaved while using exponential gates.

1) Stabilizer state \(m_t\). They compute
\[
m_t=\max(\log f_t + m_{t-1},\,\log i_t)
\]
and replace \(i_t\) and \(f_t\) by stabilized versions
\[
i'_t=\exp(\tilde i_t - m_t),\qquad
f'_t=\exp(\log f_t + m_{t-1} - m_t).
\]
This is a numerically safe reparameterization: it prevents overflow/underflow of exponentials while (crucially) leaving the network outputs and parameter derivatives unchanged. In practice this eliminates the practical risk of numerical explosions from raw exponentials.

2) Normalizer state \(n_t\) and output normalization. For sLSTM they keep
\[
n_t = f_t\, n_{t-1} + i_t,
\qquad \tilde h_t = c_t / n_t,
\]
so the hidden output is a normalized cell state. For mLSTM the retrieval uses
\[
\tilde{\mathbf h}_t = \mathbf{C}_t\mathbf{q}_t\ /\ \max\{|\mathbf{n}_t^\top\mathbf{q}_t|,1\}.
\]
These normalizers track the cumulative effective gate strength and explicitly divide out large/small scales so that the readout (and thus gradients) remain bounded. Intuitively, even if some \(f_t\) are $>1$, the normalizer records that and scales the readout back, preventing runaway activations from accumulating unchecked.

3) Option to use sigmoid or exp for the forget gate. The paper explicitly leaves the forget gate as "sigmoid OR exp" in definitions. If you want to eliminate the risk of amplification entirely you can keep sigmoid for \(f_t\); if you want revision/strong memory control you can use exponential but must use the stabilizer/normalizer pair.

Practical initialization and regularization recommendations (what "careful initialization" concretely means here)
- Initialize the forget-gate pre-activation so that \(\tilde f_t \approx 0\) (i.e., \(f_t=\exp(0)=1\)). This reproduces the CEC initial condition: no decay nor amplification, so gradients can flow initially. In practice set the forget bias \(b_f\) to 0 (or a tiny value) when using exponential gates. If you instead use sigmoid forgets but want slow decay, set the sigmoid bias to a positive value (sigmoid bias $>0$ gives \(f_t\) near 1).
- Use the paper’s stabilizer state \(m_t\) implementation. It is designed to preserve exact outputs/derivatives while preventing numerical overflow/underflow of exponentials.
- Use the normalizer \(n_t\) (sLSTM) or the bounded denominator \(\max\{|\mathbf{n}_t^\top\mathbf{q}_t|,1\}\) (mLSTM) as in the paper. These make the readout scale independent of cumulative gate product and limit pathological gradient magnitudes.
- Regularize gate logits lightly: small weight decay or gradient clipping on gate parameters helps keep \(\tilde f_t\) from drifting to large positive/negative values that would cause extreme \(f_t\). You can also apply explicit clipping on \(\tilde f_t\) (or its running statistics) if needed.
- Consider smaller learning rates or separate (lower) learning rate for gate parameters so they don’t run away early in training.
- If you want a conservative option, use sigmoid for the forget gate and exponential only for input gating; the paper often uses exp for input gate and allows either for forget gate. This keeps forgetting bounded by 1 while still allowing exponential-style revisability via the input gating and normalizer.
- For mLSTM also use layer-norm before key/value projections (as the paper does) to keep keys/values zero-mean and to stabilize \(\mathbf{C}_t\) updates and retrievals.

Intuition and tradeoffs: exponential gating gives you the capacity to amplify stored content or quickly revise it (useful for tasks they show where LSTM struggles), but that expressivity is exactly why you must add normalization and stabilization to prevent gradients from blowing up/vanishing through \(\prod f_t\). The stabilizer \(m_t\) is a numerically exact trick; the normalizer \(n_t\) removes build-up of raw scale so backward factors are effectively normalized. Together these preserve the functional equivalent of the CEC (gradients are not forced to vanish) while allowing more flexible gate behavior than sigmoid alone.

In short: yes, you can preserve the effective CEC property when switching to \(f_t=\exp(\tilde f_t)\), but you must (as the paper prescribes) 1) initialize \(\tilde f_t\) so that \(f_t\) starts around 1, 2) use the stabilizer \(m_t\) to avoid numerical extremes, and 3) use the normalizer/division in readout (and optional regularization or lower LR on gate logits) to keep gradients bounded. These are the concrete, practical measures referenced in the Limitations and implemented throughout the xLSTM experiments.

### Why is $\mathbf{k}_t$ scaled by $1/\sqrt{d}$ but $\mathbf{q}_t$ and $\mathbf{v}_t$ are not in mLSTM?
Question:
In Eq. (26–28), $\mathbf{k}_t = \frac{1}{\sqrt{d}} \mathbf{W}_k \mathbf{x}_t + \mathbf{b}_k$, but no similar scaling is shown for $\mathbf{q}_t$ or $\mathbf{v}_t$. Is this analogous to dot-product attention where scaling the key (or query) stabilizes the magnitude of inner products? Given that retrieval uses $\mathbf{C}_t \mathbf{q}_t$ normalized by $\max\{|\mathbf{n}_t^\top \mathbf{q}_t|,1\}$, how sensitive is training to whether we scale keys, queries, both, or neither?
Answer:
Short answer: the authors scale only the key by $1/\sqrt{d}$ as a practical stabilizer so that the outer-product write $v_t k_t^\top$ and the subsequent inner products during readout have sensible, bounded magnitudes. Because the mLSTM also applies layer-norm before the projections, uses the normalizer-based division in retrieval, and stabilizes exponential gates, the model is fairly robust to whether you scale keys, queries, both, or neither — but the scaling choice does affect the numerical range of activations and thus optimization speed/stability, so it is not purely cosmetic.

Why a $1/\sqrt{d}$ on $k_t$ (intuitively and technically)
In dot‑product attention the factor $1/\sqrt{d}$ is used so that the variance of the dot product $q^\top k$ stays $O(1)$ as $d$ grows (without it the dot product magnitude scales like $d$ and softmax becomes peaky). The mLSTM uses the same idea but in a slightly different place: the memory update is a covariance outer product
$$\mathbf{C}_t \leftarrow \mathbf{C}_{t-1} + i_t\, \mathbf{v}_t \mathbf{k}_t^\top.$$
If $\mathbf{k}_t$ has entries of typical scale $1$, the entries of $\mathbf{v}_t \mathbf{k}_t^\top$ are $O(1)$ as well, so over many writes $\mathbf{C}_t$ can grow large (roughly $O(\text{\textunderscore number\_of\_writes\textunderscore})$). Scaling $\mathbf{k}_t$ by $1/\sqrt{d}$ reduces the scale of each outer‑product entry to $O(1/\sqrt{d})$, which (a) reduces the magnitude of the memory matrix updates and (b) keeps the expected scale of the readout $\mathbf{C}_t \mathbf{q}_t$ more controlled. In other words, the $1/\sqrt{d}$ on $\mathbf{k}_t$ is playing the same variance‑stabilizing role as in Transformers, but targeted to the write term so the memory matrix does not explode with $d$.

Why not scale $\mathbf{q}_t$ or $\mathbf{v}_t$ in the paper
There is nothing fundamental that forces the scale to be on $\mathbf{k}_t$ specifically — multiplying $\mathbf{k}_t$ by $\alpha$ or multiplying $\mathbf{q}_t$ by $\alpha$ rescales the readout $\mathbf{q}^\top (\mathbf{C}_t^\top)$ by $\alpha$ (and multiplying both by reciprocal factors can cancel). However, putting the $1/\sqrt{d}$ on the key is convenient because it directly tames the magnitude of the outer product write $\mathbf{v}\mathbf{k}^\top$, controlling the memory growth at write time. Leaving $\mathbf{v}_t$ unscaled preserves its magnitude as the stored content; leaving $\mathbf{q}_t$ unscaled makes the readout magnitude depend on memory scale and then be corrected by the normalizer.

Why the design is robust in mLSTM (from the paper)
mLSTM includes several mechanisms that reduce sensitivity to exact projection scales: the authors apply a layer‑norm before the $\mathbf{W}_k,\mathbf{W}_q,\mathbf{W}_v$ projections (so projections start from zero‑mean, normalized inputs), they divide the raw readout by $\max\{|\mathbf{n}_t^\top \mathbf{q}_t|,1\}$ (a normalizer that prevents tiny denominators and clamps large magnitudes), and they stabilize exponential gates with the $m_t$ trick. Those pieces together mean that small constant multiplicative changes (e.g., scaling keys vs. queries) tend to be absorbed or clipped by the normalizer and by learned biases, so training is not catastrophically sensitive to the exact placement of the $1/\sqrt{d}$ in practice.

Practical effect on optimization (what to expect)
Changing whether you scale keys, queries, both, or neither does change gradient magnitudes and effective step sizes. For example, if you removed the $1/\sqrt{d}$ on $\mathbf{k}_t$, the memory updates and reads would be larger, which can slow or destabilize training unless learning rates, initializer scales, or gate biases are adjusted. Conversely, scaling both $\mathbf{k}_t$ and $\mathbf{q}_t$ by reciprocal factors can leave read magnitudes similar but changes gradient flow into the projection matrices. The paper does not report an explicit ablation of this exact placement, but the design choices (layer‑norm, normalizer, gate stabilization) indicate the authors intended the architecture to be forgiving of reasonable alternative scalings.

Recommendation
If you experiment: try the canonical Transformer‑style convention (scale keys by $1/\sqrt{d}$) first (as in the paper). If you change it (scale queries instead, or both), monitor the magnitude of $\mathbf{C}_t$, $\tilde{\mathbf{h}}_t$, and gate activations and be prepared to retune initializers or learning rates. Theoretical equivalence up to a constant factor exists, but optimization dynamics and numerical stability can prefer one placement (here: key scaling) in practice.

### How does sLSTM ‘memory mixing’ make it more expressive than SSMs/Transformers for state tracking?
Question:
The paper cites results that SSMs and Transformers lack state-tracking capacity akin to RNNs, and argues sLSTM’s memory mixing (recurrent $\mathbf{R}_\bullet$ across cells within heads) plus exponential gating enables solving formal language tasks like parity. Can someone give a minimal constructive example showing sLSTM’s recurrent mixing implements a finite-state machine that Transformers/SSMs cannot, even with large capacity? How do heads restrict or enhance this expressivity?
Answer:
Short answer: sLSTM’s “memory mixing” (the hidden$\rightarrow$cell recurrent matrices inside a head) gives you a tiny, provable way to implement finite‑state machines (FSMs) by making the cell updates conditional on previous hidden states; exponential gating makes those conditionals sharp and stable. Transformers and linear SSMs, as usually formulated, lack the same kind of time‑local, learned hidden$\rightarrow$cell recurrence and therefore cannot (robustly and exactly) implement some simple FSMs such as parity with fixed finite memory unless they blow up capacity or rely on approximations. Below I give a minimal constructive example (parity) showing how a $2$‑cell sLSTM head can implement a $2$‑state FSM that toggles state on a “1” input, explain why a Transformer/SSM cannot implement that with the same limited mechanism, and comment on how multiple heads change the picture.

Constructive example (parity modulo $2$) — how to make an sLSTM head behave like a $2$‑state FSM
We want a model that reads a stream of bits $x_t \in \{0,1\}$ and outputs the parity up to time $t$ ($0$ for even count of ones, $1$ for odd). A minimal FSM has two states $S_0$ (even) and $S_1$ (odd) and transition: on input $1$ toggle ($S_0 \leftrightarrow S_1$); on input $0$ stay.

sLSTM ingredients we use (from the paper):
$c_t = f_t \cdot c_{t-1} + i_t \cdot z_t$,
$h_t = o_t \cdot (c_t / n_t)$,
with gates $i_t = \exp(\tilde{i}_t)$, $f_t$ (can be sigmoid or exp), and crucially the $\tilde{\cdot}$ terms can depend on $h_{t-1}$ via recurrent matrices (the paper calls these recurrent mixing weights).

Design idea (intuitively). Use two scalar memory cells $c^{(1)}$ and $c^{(2)}$ inside one head, and use the recurrent matrices so that when a “1” arrives the gate/controller routes the memory contents between the two cells (a learned permutation). By swapping contents we can toggle which cell holds the “active” signal; output reads which cell currently carries the $1$. Exponential gating makes the gating decisions effectively hard (near‑binary) and stable across long runs.

Concretely (sketch of parameter choices)
1) Represent the state by which cell contains $+1$ and which contains $0$:
   - $S_0: c^{(1)} = 1, c^{(2)} = 0$
   - $S_1: c^{(1)} = 0, c^{(2)} = 1$

2) Set forget gates $f_t \approx 1$ (so we don’t decay memory) and output gate $o_t = 1$ for simplicity. Set normalizer $n_t$ to track gate mass (paper’s stabilizer takes care of large exponentials).

3) Make the input $z_t$ zero for both cells (so new external content doesn’t disturb memory). The only changes to memory come from the recurrent, gate‑controlled mixing.

4) Use recurrent weights in the gate arguments so that when $x_t = 1$ the input/forget gating effectively swaps the two scalar memories. For example, for two cells we can implement:
   $c_t = P(x_t)\, c_{t-1}$
where $P(0) = I$ (identity) and $P(1)$ is the permutation matrix that swaps coordinates. How to get that from sLSTM equations: choose $i_t$ and $f_t$ (vectors of size $2$) and $z_t$ such that the net effect is either keep $c_{t-1}$ (when $x_t=0$) or replace it by a swapped version (when $x_t=1$). Because each gate’s preactivation can include terms $r \cdot h_{t-1}$, we can make the gate values depend on which cell was active ($h_{t-1}$ encodes that), and because gates are exponentials we can make them sharply select the swap vs identity path.

A concrete parameter instantiation (high level):
- Let $h_{t-1} = [h_1, h_2]$ be a one‑hot indicating which cell is active (paper’s $h_t = o_t \cdot (c_t / n_t)$ can be arranged to be that).
- Choose recurrent matrices $r_{f}, r_{i}$ so that when input $x_t=1$ their preactivations produce an $i_t$ vector which is large on entries that will move the active $1$ into the other coordinate and small otherwise. With $\exp(\cdot)$ gating, “large” becomes multiplicative weight $\gg 1$ and “small” $\approx 0$ after stabilizer scaling, so the net update becomes either identity (no effective new write) or a controlled write/reshuffle.
- Because the gates multiply previous $c_{t-1}$ and the input term is controlled, you can obtain $c_t$ that is the swapped vector when $x_t=1$ and unchanged when $x_t=0$.

Why this is a genuine FSM implementation: the hidden$\rightarrow$gate recurrent paths create a closed loop (state influences next gate decisions), so the system’s next state depends only on current state and current input — exactly an FSM transition function. Exponential gating gives near‑discrete switching, making the transitions robust and long‑lived (no decay).

Why Transformers / linear SSMs fail to match this (intuitively and per paper)
Transformers implement per‑time attention that mixes past token representations via content‑based (soft) attention; SSMs implement linear dynamical recurrences without learned nonlinear hidden$\rightarrow$gate recurrences. Two important differences prevent them from implementing the above simple FSM with the same economy:

1) No time‑local learned hidden$\rightarrow$cell recurrence: sLSTM’s crucial operation is that the previous hidden state $h_{t-1}$ is fed back (via learned matrices) into the gates that immediately decide how to modify the cell at time $t$. This creates a learned, nonlinear state transition that depends on internal memory. Standard Transformers do not have an equivalent learned hidden$\rightarrow$gate that acts at the next time step; their update at $t$ is a function of the whole past via attention weights computed from content, not a small fixed finite‑state transition matrix that is applied conditioned on internal state. SSMs that are linear cannot implement the nonlinear switching required for exact parity without exponentially large rank or special nonlinearities.

2) Content vs. state routing: attention is content‑based and typically requires the model to encode and compare keys/queries across tokens; to simulate a tiny FSM like parity, a Transformer would need to encode state into token embeddings and then repeatedly attend to the right token representations. This is possible in principle with unbounded precision and large capacity, but it does not implement a compact finite automaton in the same way: practical Transformers/SSMs need approximation, longer context bookkeeping, or explosive capacity to exactly maintain the toggling without drift, and the papers cited (Deletang et al., Merrill et al.) show formal limitations: RNNs with hidden$\rightarrow$hidden recurrence can implement (and generalize to) certain state‑tracking tasks that Transformers and SSMs cannot with the same architecture/inductive bias.

Heads and expressivity: what multiple heads buy you, and what they restrict
In the sLSTM design of the paper, “heads” are independent groups of cells where memory mixing is allowed inside a head but not across heads. This has two consequences. First, each head can implement an independent FSM; having $H$ heads therefore allows you to run $H$ small FSMs in parallel (useful for tracking several different entities or state machines concurrently). Second, because there is no direct recurrent mixing across heads, coordinating or composing those FSMs into a single richer FSM requires later layers to read and combine head outputs; that increases depth and may make some stateful behaviors less compact. So heads increase parallelism and modularity of state trackers, but they constrain immediate cross‑state interactions — a design choice that trades off expressivity of a monolithic FSM for modular, parallel state machines that can be composed.

Summary
The minimal constructive idea is: with just $2$ scalar cells and learned hidden$\rightarrow$gate recurrent matrices inside one sLSTM head you can implement the parity $2$‑state FSM by making gates effect a state swap on input $1$ and identity on input $0$. This uses the exact mechanisms introduced in the paper: memory mixing (hidden recurrences) + exponential gating (sharp, stable switching). Transformers and linear SSMs lack that simple, local learned recurrence path and therefore cannot implement the same compact FSM as naturally; they would need nontrivial workaround (big memory, extra tokens, or approximation). Multiple sLSTM heads let you run multiple FSMs in parallel (each head a state tracker) but prevent instant recurrent mixing across heads, so coordination must be mediated through outputs and later layers.

If you want, I can write the short explicit $2\times2$ matrix parameter values (preactivations, permutation gate pattern, and stabilizer handling) as a toy numerical example to be run and verified; I omitted that here to keep the exposition compact, but it’s straightforward to produce.

### What is the theoretical memory capacity of mLSTM compared to attention’s exponential capacity in $d$?
Question:
The paper notes Transformers have memory that is exponential in coding dimension $d$. For mLSTM, with a $d \times d$ unparameterized memory updated by rank-1 outer products, what is the asymptotic capacity for storing and reliably retrieving $N$ random key-value pairs under noise and interference? Is there a closed-form or known bound (e.g., akin to Hopfield or modern associative memory analyses), especially when $i_t$ and $f_t$ vary over time?
Answer:
Short answer: mLSTM with a $d\times d$ matrix memory that accumulates rank-1 outer products (the covariance / fast-weight rule used in the paper) has a capacity that is linear in the coding dimension $d$ ($N = O(d)$) for storing and reliably retrieving random key–value pairs under interference. This contrasts with the statement about Transformers having an effective memory that can be exponential in $d$ (that exponential behaviour relies on different, parameterized representations/attention mechanics or higher-order associative constructions). Varying input/forget gates ($i_t, f_t$) changes the effective amplitudes of stored items but does not alter the asymptotic $O(d)$ scaling so long as those gate factors remain bounded.

Why (intuitively and technically)
The mLSTM stores pairs by updating the matrix
$C = \sum_{t} (i_t v_t k_t^T)$ (with optional multiplicative decay from $f_t$ on previous contents). Retrieval for a query $q$ is performed by multiplying $C q$:
$C q = \sum_{j} i_j v_j (k_j^T q)$.
If we attempt to retrieve the value $v_i$ associated with key $k_i$ by querying $q \approx k_i$, the desired signal is the $i$-th term, roughly $v_i (k_i^T q) \approx v_i$ (if $k_i$ and $q$ are matched). All other terms $j \neq i$ act as interference (noise) scaled by the inner products $k_j^T q$.

For random keys and values (zero-mean, independent entries), the inner products between distinct keys are random with mean $0$ and variance $O(1/d)$ when keys are normalized (this scaling is already present in the paper: $k_t$ has a $1/\sqrt{d}$ factor). The noise contribution to any component of $C q$ is a sum of roughly $N$ independent zero-mean terms with variance $O(1/d)$, so the noise variance is $O(N/d)$. The signal magnitude is $O(1)$ (assuming $v_i$ has $O(1)$ norm and $k_i^T q \approx 1$). Hence the signal-to-noise ratio (SNR) scales as
$\mathrm{SNR} \sim \mathrm{Signal} / \sqrt{\mathrm{Noise\ variance}} \sim 1 / \sqrt{N/d} = \sqrt{d / N}$.
To keep SNR bounded away from zero (so retrieval is reliable), we require $N = O(d)$. If $N$ grows larger than a constant multiple of $d$, interference overwhelms the signal and retrieval fails (unless you change the code or allow other structure).

Role of gates $i_t$ and $f_t$
Gates multiply each stored outer product by coefficients $a_j = i_j$ times the product of future forgets (f factors) that survive until retrieval. That turns the sum into $C = \sum_j a_j v_j k_j^T$ and the normalizer becomes $n = \sum_j a_j k_j$, but the same interference counting applies: the noise variance becomes $O\!\left(\sum_j a_j^2 / d\right)$. If the gate coefficients $a_j$ are bounded and many items are stored, the scaling is still $N/d$ up to constants determined by typical $a_j^2$. If gates systematically sparsify the effective set of stored items (many $a_j$ near zero), capacity can grow proportionally to the number of effectively nonzero stored items, but that is still linear in $d$ unless the gates implement an exponentially large combinatorial code (which they do not in the mLSTM described). Thus time-varying $i_t$ and $f_t$ change constants in the SNR but not the asymptotic $O(d)$ scaling, assuming gates are bounded and unstructured.

Comparison to Hopfield / associative-memory results
This derivation is the same logic used in classic associative-memory analyses. For second-order (outer-product) associative memories (e.g. original Hopfield-like and Bidirectional Associative Memories / fast weights), capacity scales linearly with the dimension: classical Hopfield for binary patterns stores about $0.14 d$ random patterns; outer-product memories for real-valued vectors give an SNR-limited $N = O(d)$ capacity. Modern "dense associative memory" constructions that realize superlinear or exponential capacity do so by using higher-order interactions (higher than pairwise outer-products), learned parameterization that enforces structured codes, or very sparse/combinatorial encodings; those mechanisms are not present in the unparameterized rank-1 outer-product mLSTM update the paper uses. The paper itself cites Dayan/Sejnowski and Fast Weights and notes that the covariance update is "optimal for maximal separability" in this outer-product class, which is consistent with the SNR-limited linear scaling.

Why Transformers can behave differently (briefly)
When the paper (and related work such as Ramsauer et al.) say that Transformer attention can realize an exponential memory in coding dimension $d$, that refers to the fact that a learned attention mechanism can implement very selective mappings in a $d$-dimensional key space, using parameterized (and trained) projections and attention nonlinearities to carve up the space into a large number of distinguishable regions. In other words, parameterized keys/queries plus learned routing can in principle encode and retrieve a combinatorial number of associations relative to $d$. That is fundamentally different from an unparameterized accumulation of rank-1 outer products; the latter has the pairwise (second-order) structure that limits capacity to $O(d)$ under random coding.

Practical takeaway
For mLSTM as presented (matrix memory updated by rank-1 outer products, with the paper’s normalization and $1/\sqrt{d}$ key scaling), expect reliable storage/retrieval of about on the order of $d$ independent random key–value pairs. Gates ($i_t, f_t$) let you emphasize or decay certain items and so change the effective number of stored items, but they do not change the asymptotic linear dependence on $d$ unless you introduce new structure (learned sparse codes, higher-order interactions, or parameterized routing) that breaks the random-key SNR analysis.

If you want a more formal bound you can start from the SNR calculation above: for random i.i.d. keys with $\operatorname{Var}(k_j^T q) \approx 1/d$ and independent values with bounded variance, require $N \lesssim c d$ for some constant $c$ (set by acceptable SNR / error probability) to maintain reliable retrieval. This is the typical “capacity = $\Theta(d)$” statement for outer-product associative memories.

### Post vs pre up-projection choice: is there a principled reason sLSTM uses post and mLSTM uses pre?
Question:
The xLSTM block uses post up-projection for sLSTM and pre up-projection for mLSTM, motivated by Cover’s theorem and the idea that mLSTM benefits from larger memory in high-dimensional space. Is there an ablation that isolates this choice from other factors? Theoretically, does placing mLSTM after an up-projection maximize separability by letting the matrix memory live in a higher-dimensional manifold, whereas sLSTM benefits from summarizing first in the base space? Any guidance for practitioners choosing between them?
Answer:
Short answer: the paper does not report a dedicated ablation that isolates “pre vs post up‑projection” for sLSTM versus mLSTM as an independent factor. The architectural choice is motivated by two principled (and complementary) arguments in the text: Cover’s theorem for separability and the differing roles / capacities of scalar vs matrix memory. Below I explain the intuition, the theoretical rationale the authors cite, what the experiments do and do not show, and concrete practical guidance you can use.

Why the authors choose post up‑projection for sLSTM and pre up‑projection for mLSTM
The paper gives two linked reasons.

1) Cover’s theorem / separability. Cover’s theorem says that nonlinearly mapping data into a sufficiently high‑dimensional space makes linear separation easier. There are two ways to use an up‑projection (a linear expansion to a larger hidden dimension) relative to the nonlinear summarization inside a block: (a) post up‑projection — summarize in the base space, then linearly expand, apply nonlinearity, and project back (this is the Transformer‑like flow); or (b) pre up‑projection — expand first, then do the nonlinear summarization in the larger space (this is SSM‑like). Doing the nonlinearity in the larger space tends to produce representations that are more linearly separable.

2) Memory modality and capacity. mLSTM’s memory is a matrix (covariance / outer‑product style) whose effective capacity and expressivity grows with the dimension of the key/value/query vectors: storing/retrieving outer products, signal/noise ratios in covariance updates, etc., all benefit from larger dimensionality. Therefore the authors prefer to up‑project first for mLSTM so the matrix memory “lives” in a higher‑dimensional manifold where the covariance update rule and retrieval have greater capacity and separability. For sLSTM the memory is scalar(s) with memory mixing via recurrent connections; here the intuition in the paper is that it’s better to first compress / summarize the past in the base space (where the scalar memory and mixing operate), then up‑project — so sLSTM uses the post up‑projection block.

What the experiments actually show (and what they don’t)
The paper contains ablations and a sequence of morphing experiments that show most of the performance gain comes from two changes: exponential gating and the matrix memory (mLSTM). The main ablation table attributes improvements to those components. The authors also say “additional studies on the individual backbone components are discussed in Appendix,” and they state for all experiments they used pre up‑projection for mLSTM and post for sLSTM. However, there is no explicit, isolated ablation in the main text that swaps only the up‑projection ordering for a given memory type (i.e., mLSTM with post up‑projection vs pre, or sLSTM with pre vs post) and reports performance changes on the core tasks. So the paper motivates the choice and uses it consistently, but does not present a clean experiment that isolates that one design decision by itself.

Intuition framed more technically
- If you take an mLSTM and pre up‑project to dimension $D \gg d$, then keys/values/queries are higher‑dimensional vectors; covariance increments $\mathbf{v}\mathbf{k}^\top$ live in a larger space and (by the Cover argument plus classical results on covariance updates) have higher capacity to represent many pairwise associations with better signal/noise separation. Retrieval via $\mathbf{C}\mathbf{q}$ benefits because $\mathbf{q}$ projects into that larger subspace where stored outer products are better separated.
- For sLSTM the memory is scalar per memory cell; its power relies on memory mixing through recurrent connections (the “hidden‑hidden” interactions). Summarizing first in the compact base space before expanding keeps the summary coherent for those recurrent dynamics, and post‑projection then gives the residual path capacity without relying on matrix memory to carry the primary content. Also the scalar memory is not obviously helped by an early expansion because the memory itself cannot exploit pairwise outer‑product structure.

Practical guidance for practitioners
If you plan to use or test xLSTM variants, follow the paper’s recommendation as a strong default: use pre up‑projection when your block contains mLSTM (matrix memory) and use post up‑projection for sLSTM (scalar memory / memory mixing). This aligns with the paper’s theoretical motivation and all reported experiments.

If you want to be empirical (recommended if you have resources): run a small ablation that swaps pre/post for each memory type while keeping everything else identical. Measure both (a) language modeling perplexity (or whatever main task you care about) and (b) a memory/associative recall synthetic task (e.g., the Multi‑Query Associative Recall used in the paper). That will reveal whether the separability / capacity arguments produce measurable gains in your setup and budget. Expect that mLSTM should benefit more from pre up‑projection on associative recall and long‑context retrieval; sLSTM may be more sensitive to stability and recurrence if you force pre up‑projection.

Summary
The architecture choice in the paper is principled: pre up‑projection for mLSTM is chosen to let matrix memory operate in a higher‑dimensional manifold (better separability / capacity per Cover’s theorem and covariance update properties), while post up‑projection for sLSTM preserves compact summarization and memory mixing dynamics before expansion. The paper provides this motivation and uses the choices consistently, but it does not publish an isolated ablation that swaps only the up‑projection ordering and reports the outcome. If you need to decide for your application, follow the paper’s defaults and/or run a focused swap experiment (mLSTM pre vs post, sLSTM pre vs post) on a small scale to confirm behavior in your regime.

### How fair are the throughput and generation-time comparisons given implementation maturity?
Question:
The paper reports throughput/generation-time comparisons where xLSTM is competitive and notes that their mLSTM CUDA kernels are not yet optimized, while FlashAttention and Mamba scans are highly optimized. Also, some models could not be compiled with torch.compile in the test environment. How should we interpret the reported speedups or slowdowns under these constraints? Could the authors provide a normalized FLOPs-based comparison or a breakdown isolating the $\mathcal{O}(d^2)$ matrix-memory cost vs other layers to help predict performance after kernel optimization?
Answer:
Short answer: treat the reported speed numbers as informative about algorithmic scaling (linear vs quadratic in context length) and relative throughput given the authors’ current codebases, but not as definitive absolute speed comparisons. The paper explicitly states the mLSTM CUDA kernels are unoptimized ($\approx 4\times$ slower than highly tuned FlashAttention / Mamba kernels) and that some models could not be compiled in the test environment, so the measured factors reflect both algorithmic costs and implementation maturity. A fair, implementation‑agnostic way to anticipate how those numbers would change after kernel optimization is to compare FLOPs and isolate the dominant $O(d^2)$ matrix‑memory costs from the other per‑token costs; below I give a concise recipe and simple cost expressions the authors could (and plausibly should) report to make comparisons reproducible and predictive.

How to interpret the reported timings
The experiments in the paper accurately show two robust, implementation‑independent facts: (1) xLSTM variants have linear computational complexity with respect to sequence length (so generation time scales roughly $O(L)$ for fixed model width), while standard Transformer decoding with attention exhibits the quadratic behavior in prefill steps shown in the figures; (2) for fixed model sizes, constant factors (the “$\times 4$ slower” remark) can dominate wall‑clock comparisons when one implementation uses highly tuned kernels (FlashAttention, optimized SSM scans) and another is a straightforward CUDA/PyTorch implementation. Therefore:

- Trust the qualitative behavior (linear vs quadratic, ability to use larger batch sizes due to constant memory), and relative model quality numbers (perplexity) for architectural conclusions.
- Treat absolute speedups/slowdowns (e.g., “xLSTM is $N\times$ slower/faster”) as provisional. The mLSTM rates are upper bounds on wall‑clock cost in the current repo; optimized kernels and/or compilation can materially close the gap. Conversely, Transformer‑based timings with FlashAttention are likely close to what production inference stacks deliver because those kernels are mature.

What a normalized FLOPs‑based comparison should look like
To remove implementation variance you can (and the authors could) report three numbers per model (or per block type) that are independent of kernel tuning:

1) FLOPs per token (or FLOPs per token per layer), i.e., total multiply‑adds required to process one new token (including prefill overhead if you want to show decode vs prefill costs). Count MACs for each primitive: dense matmul, outer product update, vector–matrix product, elementwise ops.

2) Memory traffic / working set (bytes read/written per token), to catch cases where bandwidth or caching will dominate.

3) Peak additional memory (bytes) required for KV cache or matrix memory (this explains why xLSTM can use larger batch sizes).

A minimal FLOPs breakdown the authors could publish
For a single mLSTM block with hidden dimension $d$ and input dimension $d_{\text{in}}$ (for typical residual blocks $d_{\text{in}}\approx d$), per token (online decode step) you can isolate the following dominant costs. I give order‑of‑magnitude FLOP counts (multiply + add $\approx 2$ FLOPs per MAC if you prefer FLOP = MAC, be explicit which convention you use):

- Query/key/value projections: $W_q, W_k, W_v$ each cost $\sim 2\cdot d\cdot d_{\text{in}}$ FLOPs (for one vector projection each), so $\sim 6\cdot d\cdot d_{\text{in}}$ FLOPs total.
- Gates and output projection ($W_o$ and scalar gates): additional $\sim 2\cdot d\cdot d_{\text{in}}$ (or less for scalar gates), so include another $\sim 2\text{--}4\cdot d\cdot d_{\text{in}}$.
- mLSTM matrix memory update: outer product $v k^{T}$ is an $O(d^2)$ operation: roughly $2\cdot d^{2}$ FLOPs to form the update ($v$ is $d\times 1$, $k^{T}$ is $1\times d$) and then adding this to $C$ is another $d^{2}$ writes/ops (but add can be counted as part of the $2\cdot d^{2}$).
- Retrieval: $C q$ is a matrix–vector product: $\sim 2\cdot d^{2}$ FLOPs.
- Normalizer dot $n^{T} q$: $\sim 2\cdot d$ FLOPs (negligible compared to $d^{2}$).
- Any layernorm/activation elementwise ops: $\sim c\cdot d$ FLOPs, negligible compared to $d^{2}$ for large $d$.

So the two $O(d^2)$ terms — the memory update (outer product) and the retrieval (matrix–vector) — dominate when $d$ is large. Summing the dominant terms, per token per block we get roughly:

$\text{FLOPs}_{\text{mLSTM\_block}} \approx 2\cdot d^{2}\ (\text{retrieval}) + 2\cdot d^{2}\ (\text{update}) + O(d\cdot d_{\text{in}})\ (\text{projections}) + \text{lower‑order terms}.$

If $d_{\text{in}}\approx d$, that simplifies to

$\text{FLOPs}_{\text{mLSTM\_block}} \approx 4\cdot d^{2} + c\cdot d^{2} \approx (4 + c)\cdot d^{2},$

where $c\approx 6\text{--}8$ accounts for projections expressed as multiples of $d^{2}$ if $d_{\text{in}}\approx d$ (more precisely projections are $O(d^{2})$ but with a smaller constant than the two $d^{2}$ memory ops).

For an sLSTM block (scalar cell(s) with gates and recurrent mixing), the dominant per‑token costs are the dense projections/projections × gates and the recurrent mixing (if present): $\text{FLOPs}_{\text{sLSTM\_block}} \approx O(d\cdot d_{\text{in}}) + O(d^{2}\cdot\text{small\_const})$ if using recurrent matrices, but typically much smaller than mLSTM’s $2\times d^{2}$ terms when mLSTM uses a full matrix memory.

For a Transformer decoder block with attention over a prefill length $L_{\text{prefill}}$ (when you do generation with cached keys), the hotspot is attention score / softmax on the prefill and the matmuls for $K\cdot Q^{T}$ during prefill. Per token generation (assuming cached $K,V$ for past tokens) the per‑token decode cost is roughly the projection costs plus $O(d^{2})$ matmuls for the output MLP (which is typically $2\times d\cdot d_{\text{ff}}$) and the attention’s application of cached $V$ (which for single‑head or multi‑head is $\sim 2\cdot d\cdot d$ for linear combinations). But importantly, prefill cost (to build K/V) scales like $O(L_{\text{prefill}}\cdot d^{2})$ for the attention matrix construction unless you use incremental caching; hence the quadratic prefill curves in the paper.

How to use that to predict performance after kernel optimization
Given the FLOPs decomposition above, you can:

- Compute the fraction of total FLOPs due to the two $d^{2}$ memory ops in mLSTM. If they account for, say, $60\text{--}80\%$ of the work, then optimizing those kernels should reduce wall‑clock time by a comparable fraction (minus the part already memory‑bound or bandwidth‑bound).
- Expect optimized GPU kernels (fused matmul/outer‑product, better use of shared memory, tiling like FlashAttention) to reduce the constant factor substantially. The paper’s note “mLSTM currently $\sim 4\times$ slower than FlashAttention / scan used in Mamba” suggests that a kernel optimization could plausibly reclaim most of that $4\times$ gap; empirically, moving from naive matmuls to highly tuned cuBLAS / FlashAttention style kernels often yields multi× speedups.
- If the authors report both FLOPs and measured time, you can estimate effective throughput (FLOPs/sec). After kernel tuning, FLOPs/sec should rise toward hardware peak; predicted new wall‑clock times $\approx$ old_FLOPs / new_peak_FLOPs_per_sec. That predicts realistic speedups.

Practical suggestions for the authors to make comparisons fairer and predictive
A short checklist the authors could add to future revisions so readers can fairly normalize numbers:

1. Publish per‑token FLOPs and memory traffic per block and per model size (explicit formulas or a small table) and state the FLOP convention (MAC vs flop).
2. Separate the $O(d^2)$ matrix memory FLOPs from the projection and gate FLOPs; report the percentage each contributes.
3. Report measured effective FLOPs/sec (total FLOPs / wall‑clock time) so readers can see how far from hardware peak each implementation is.
4. Report kernel maturity: whether kernels use fused custom CUDA kernels, cuBLAS, FlashAttention, or plain PyTorch ops, and whether torch.compile succeeded.
5. When possible, include timings before/after kernel optimizations (or provide an estimate of expected improvement based on fraction of FLOPs in the optimizable kernels).
6. For decoding, report both prefill and per‑token decode times and the prefill length used, since attention quadratic costs dominate prefill.

Conclusion
The paper’s timing plots should be read as strong evidence of favorable algorithmic scaling for xLSTM (linear memory/compute with context) and current implementation tradeoffs, but not as final statements about absolute wall‑clock performance — the latter will move substantially with optimized kernels and compiled runtimes. The simplest practical way to make the comparisons implementation‑agnostic is exactly what you suggested: publish FLOPs breakdowns isolating the $O(d^2)$ matrix memory costs (update + retrieval) and effective FLOPs/sec. From those numbers you can estimate how much kernel optimization would reduce the measured slowdown (i.e., if $70\%$ of FLOPs are in the two $d^{2}$ ops, optimizing those should recover most of the $4\times$ gap noted in the paper).

### Why is memory mixing prohibited across sLSTM heads but allowed across cells within a head?
Question:
The text says sLSTM can have multiple heads with memory mixing across cells within each head, but not across heads. Is this a design constraint to avoid instabilities with exponential gates (e.g., runaway amplification if cross-head mixing occurred), or an efficiency/parallelism consideration? Mathematically, what would break if we allowed $\mathbf{R}_\bullet$ to connect cells across heads as well? Any empirical evidence that cross-head mixing hurts performance?
Answer:
Short answer: it’s both a stability/normalization choice tied to exponential gating and an architectural inductive bias / efficiency choice. Allowing recurrent mixing across sLSTM heads would couple multiple exponential-gated memory streams in ways that (a) breaks the simple per-head normalizer/stabilizer math that controls numeric range and gradients, and (b) removes the intended modularity that makes training stable and interpretable. The paper does not report an ablation that permits cross-head mixing, so there’s no direct empirical result in the paper showing it hurts, but the mathematical and practical risks above explain why the authors prohibit it.

Why this matters (intuitive + technical):

1. Exponential gates require careful per-stream normalization and stabilization. sLSTM replaces sigmoid input gates by exponential gates $i_t=\exp(\tilde i_t)$ (and optionally $f_t=\exp(\tilde f_t)$) and then keeps a per-cell normalizer state $n_t$ and a stabilizer $m_t$ so that the effective stored quantity is well-scaled and the backward pass remains well-behaved (see Equations (3)–(5) in the paper). Those normalizer/stabilizer recurrences are written per memory stream so that the algebraic identities used to show equivalence after stabilization (i.e. replacing $i_t,f_t$ by stabilized $i'_t,f'_t$ does not change outputs or parameter gradients) hold cleanly.

   If you allow $\mathbf{R}_\bullet$ to mix cells across heads, you create recurrent dependencies that tie together multiple normalizers and stabilizers. Concretely, suppose two heads A and B have their own $c_t^{(A)}, n_t^{(A)}, m_t^{(A)}$ and $c_t^{(B)}, n_t^{(B)}, m_t^{(B)}$. If hidden-to-gate recurrent matrices mix A and B, then the next gates $\tilde i_{t+1}^{(A)}$ and $\tilde i_{t+1}^{(B)}$ depend on both $h_t^{(A)}$ and $h_t^{(B)}$. Since $i$ and $f$ are exponentials of these preactivations, their products over time can grow/shrink multiplicatively in a coupled manner. The stabilizer trick in the paper works by taking maxima on log-scales per stream (Equations (4)–(5)). When streams are coupled, there is no simple per-stream scalar $m_t$ that simultaneously normalizes all exponentials without either introducing extra cross-stream terms or requiring higher-dimensional stabilizers. That complicates the algebra that guarantees numerical invariance and makes it much easier to get large intermediate exponentials, overflow, or exploding gradients.

2. Modularity and interpretability / inductive bias. The paper motivates “heads” as separate memory-mixing modules: within a head, cells can interact, but heads are independent so each head’s normalizer and memory dynamics can be reasoned about and stabilized independently. This parallels multi-head attention in Transformers where heads are independent; it encourages specialization and avoids destructive interference. Allowing cross-head recurrent mixing would collapse that modularity and reduce the intended benefit of multiple heads (parallel memories with distinct dynamics), likely making optimization harder.

3. Efficiency and parallelism. While sLSTM is inherently sequential due to memory mixing, keeping heads separate reduces the size of recurrent mixing matrices and simplifies implementation of the stabilizer and normalizer computation. If heads are independent, you can apply the stabilizer/normalizer per head in small vectors/scalars; if mixing is allowed, you either pay for larger dense recurrent matrices across the whole memory or you must introduce more complex per-head coupling logic, which is both computationally heavier and harder to optimize.

4. What would “mathematically break”? Two main issues:
   - The stabilizer invariance proof (that replacing $i,f$ with stabilized $i',f'$ doesn’t change outputs or gradients) relies on scalar or per-head scalar manipulations of log-sums. Cross-head mixing removes the clean separable recurrence used in that proof: you would need vector/matrix log-domain stabilizers and corresponding algebra, which are nontrivial and may not admit the same cancellation properties.
   - Gradient dynamics: exponential gates produce multiplicative dynamics (products over time). When those multiplicative factors are coupled across heads, small errors in one head can be multiplicatively amplified through another head’s gating, increasing risk of exploding or vanishing gradients in non-obvious ways. The simple per-head bounds and normalization that tame this in the paper no longer apply.

Empirical evidence in the paper
The paper does not present a direct experiment that allows $\mathbf{R}_\bullet$ to mix across sLSTM heads and compares it to the restricted-head design. What the paper does show is that (i) sLSTM benefits strongly from exponential gating plus per-head memory mixing (within-head), and (ii) mLSTM (which has no memory mixing at all) treats heads and cells equivalently. The absence of reported cross-head-mixing ablations suggests the authors judged the mathematical/engineering risks and inductive bias reasons sufficient to disallow it; but it remains an open empirical question whether a carefully designed cross-head stabilization (e.g., matrix log-domain stabilizers or per-head orthogonalization of recurrent weights) could match or beat the per-head design.

Practical recommendation
If you want to test cross-head mixing experimentally, do so with one of these safety valves: (a) use vector/matrix-form stabilizers in the log-domain (i.e., track log-scale row/column normalizers and subtract them before exponentiation), (b) regularize or constrain cross-head recurrent weights (e.g., small norm or block-sparse structure) to avoid strong coupling, and (c) monitor any per-head exponential magnitudes and gradients closely. Only with such precautions is cross-head coupling likely to train stably.

Summary
The prohibition is primarily motivated by stability and normalization with exponential gating and by the desirable modular inductive bias. Mathematically, cross-head mixing would couple exponentials and normalizers in ways that invalidate the simple stabilizer/normalizer algebra used in sLSTM and open the door to numerical instability and harder optimization. The paper does not provide empirical ablation of this specific design choice, so while the rationale is strong, the final answer about performance impact would require a targeted experiment.

### On length extrapolation: what prevents mLSTM’s matrix memory from saturating at very long contexts?
Question:
The paper notes a potential limitation: the matrix memory is independent of sequence length, so longer sequences might overload it. Yet experiments show good perplexity up to 16k context. Can someone explain the factors that mitigate saturation—e.g., decay via $f_t$, normalization by $\mathbf{n}_t^\top \mathbf{q}_t$, or the statistics of natural language? Is there a diagnostic to detect when interference grows too large (e.g., retrieval norm growth, cosine with true value falling below a threshold), and a mitigation like adaptive forgetting?
Answer:
Short answer: the mLSTM design explicitly and implicitly prevents the matrix memory from “blowing up” at long contexts in several complementary ways: (1) decay via the forget gate $f_t$ (including exponential or sigmoid forms) continually attenuates old outer‑product updates; (2) the normalizer state $\mathbf{n}_t$ and the denominator $\max\{|\mathbf{n}_t^\top\mathbf{q}_t|,1\}$ normalize retrieval so a growing number of writes does not linearly amplify outputs; (3) exponential gates are stabilized by the $m_t$ trick so input rates $i_t$ cannot catastrophically overflow; and (4) the inputs (keys) are layer‑normed and scaled which makes stored directions better behaved and reduces coherent constructive interference. These mechanisms together — plus the statistical structure of language and what the network learns — explain why mLSTM extrapolated well to 16k in the paper.

More detail and intuition grounded in the paper. The mLSTM update is
$$
\mathbf{C}_t = f_t\,\mathbf{C}_{t-1} + i_t\,\mathbf{v}_t\mathbf{k}_t^\top,
\qquad
\mathbf{n}_t = f_t\,\mathbf{n}_{t-1} + i_t\,\mathbf{k}_t,
$$
and retrieval is
$$
\tilde{\mathbf{h}}_t = \frac{\mathbf{C}_t\mathbf{q}_t}{\max\{|\mathbf{n}_t^\top\mathbf{q}_t|,1\}}.
$$
So there are three built‑in stabilizers:

- Forget/decay $f_t$: each time step multiplies the entire memory by $f_t$. If $f_t<1$ on average (or if the model learns to reduce $f_t$ for old, noisy content), old outer products exponentially decay, limiting accumulation. Intuitively this is the same role as decay in Fast Weights / retention mechanisms.

- Normalizer $\mathbf{n}_t$ and denominator clipping: the numerator $\mathbf{C}_t\mathbf{q}_t$ grows with the sum of past $i_\tau \mathbf{v}_\tau (\mathbf{k}_\tau^\top\mathbf{q}_t)$, but the denominator attempts to track the expected scale of these dot‑products via $\mathbf{n}_t^\top\mathbf{q}_t$. Using $\max\{\cdot,1\}$ prevents division by tiny numbers while dividing out scale when the dot product is large. This makes the retrieved vector roughly a normalized, gate‑weighted average rather than an unbounded sum, so increased context length does not necessarily blow up magnitudes.

- Gate stabilization $m_t$: exponential gates $i_t=\exp(\tilde i_t)$ (and possibly $f_t$) are stabilized in the paper by computing a running max $m_t$ and rescaling $i'_t,f'_t$ (Equations (3) in the paper). That prevents numerical overflow and prevents single huge writes from dominating the entire matrix indefinitely.

Additional factors (less explicit but important):

- LayerNorm / zero‑mean keys: the paper states keys are produced after a layer‑norm so they have zero mean and are scaled by $1/\sqrt{d}$. Zero-mean, roughly isotropic keys reduce constructive alignment between many unrelated keys; random sign cancellations lower average cross‑term energy, improving signal‑to‑interference ratio (SNR) as in associative memory analyses.

- Model learning to route writes: during training the network can learn key/value/query projections and gate biases so that it stores only useful information (sparse gating in practice), and it can learn to set stronger decay where needed. Natural language has many local regularities and repetitions so effective gating and routing reduce unnecessary accumulation.

How to detect interference / saturation in practice. Useful diagnostics that are consistent with the model equations:

1. Track norms over time: monitor $\|\mathbf{C}_t\|_F$, $\|\mathbf{C}_t\mathbf{q}_t\|$, and $\|\mathbf{n}_t\|$. If $\|\mathbf{C}_t\|_F$ or $\|\mathbf{C}_t\mathbf{q}_t\|$ grows without bound with context length while $\|\mathbf{n}_t\|$ does not, that indicates imbalance and likely interference.

2. Monitor the denominator and its clipping: examine the distribution of $|\mathbf{n}_t^\top\mathbf{q}_t|$. If the value is often at the lower clip (e.g. $1.0$) while numerator grows, retrieval is effectively unnormalized and can misbehave.

3. Retrieval fidelity / SNR: for synthetic tests where you know the “true” stored value $\mathbf{v}_\tau$ for a key $\mathbf{k}_\tau$, compute cosine similarity $\cos(\mathbf{C}_t\mathbf{q}_t, \mathbf{v}_{\text{true}})$ or the signal vs. interference energy (ratio of the aligned component to orthogonal residual). A falling cosine or SNR with context length signals interference.

4. Gate statistics: inspect histograms of $i_t$ and $f_t$ (or stabilized $i'_t,f'_t$). If many $i_t$ are large and $f_t$ is close to $1$ always, memory accumulates; if $f_t$ learned low values the model is actively forgetting.

5. Downstream metrics: perplexity vs context length is the high‑level diagnostic used in the paper. Sudden per‑token perplexity increases at longer contexts suggest capacity problems.

Mitigations and design choices you can apply if you detect interference. The paper already employs several; others are natural extensions consistent with its framework:

- Learnable/adaptive forgetting: make $f_t$ a learned function that can go below $1$ for unneeded information (the paper already allows learnable gating). You can also add a small learned bias to encourage modest decay initially.

- Adaptive thresholding of the denominator: instead of a fixed lower bound ($1.0$), make the floor adaptive or learned per head so normalization matches data scale.

- Regularize memory growth: add small weight decay / L2 penalty on $\mathbf{C}_t$ (or on $i_t$) to discourage unbounded accumulation, or constrain maximal singular values of $\mathbf{C}_t$ via spectral clipping.

- Sparsify writes or keys: encourage sparse/highly selective $i_t$ or better key orthogonality (e.g. add penalty pushing keys to be less correlated) to reduce destructive interference.

- Hierarchical memories / multiple heads: divide storage into many smaller memories (heads or cells). The paper notes multiple heads/cells are equivalent for mLSTM; using more heads increases effective capacity and reduces per‑memory interference.

- Periodic or content‑dependent reset: if certain tasks allow it, reset parts of $\mathbf{C}_t$ when they are no longer useful, either by gating or explicit mechanisms.

- Increase dimension $d$: because the covariance update has capacity scaling with $d$, larger $d$ increases separability and SNR (tradeoff: computation grows as $d^2$).

Practical recipe to detect and respond. During long‑context evaluation log (a) $\|\mathbf{C}_t\|_F$, (b) percent of queries whose denominator is clipped, (c) average cosine between retrieved vector and a baseline reference (if available), and (d) histograms of $i_t,f_t$. If you see steady norm growth and many writes (large $i_t$) with $f_t\approx 1$, try lowering initial forget bias, add a small decay regularizer, or increase head count / dimension. If denominators are frequently clipped at the lower bound, try making the floor adaptive or increase key scaling so denominators naturally enter a useful range.

In short, mLSTM combines task‑learned gating (including forget/decay), an explicit normalizer that divides out cumulative write strength, and stabilized exponential gating to avoid numeric blowup. Those three ingredients are why the matrix memory did not saturate in the paper’s extrapolation experiments to 16k contexts. If you want to stress test saturation further, run the diagnostics above on synthetic associative recall tasks (where you can measure true retrieval cosine/SNR) and then try the mitigations (adaptive forgetting, normalization tweaks, or increased head/dimension) if interference grows.

\title{A Textbook about the Paper: "xLSTM: Extended Long Short-Term Memory"}

Motivation and Overview of xLSTM

# From LSTM success to Transformer dominance: context and challenges

The Long Short-Term Memory (LSTM) architecture introduced in the 1990s codified two simple but powerful ideas: the constant error carousel (an additive memory update that prevents vanishing gradients) and gating that controls how inputs, previous memory, and outputs interact. Concretely, the canonical LSTM memory update can be written as
$c_t = f_t \, c_{t-1} + i_t \, z_t,\quad h_t = o_t \,\psi(c_t),$
where $c_t$ is the cell state, $h_t$ the hidden state, $i_t,f_t,o_t$ are gates, $z_t$ the cell input, and $\psi$ a squashing function. These mechanisms allowed recurrent models to learn long-range dependencies, and LSTMs powered many early successes in sequence modeling: language modeling and generation, sequence-to-sequence translation, video captioning, handwriting and program evaluation, and many applied systems in science and control. LSTMs are particularly good at extracting semantic abstractions and storing structured information in their cells, as demonstrated by the discovery of neuron-level phenomena such as number, syntax, and sentiment detectors.

Despite this track record, a paradigm shift began with the Transformer family. Transformers replaced recurrent recurrence with parallelizable self-attention and residual stacking, enabling both higher throughput during training and much larger models that deliver the modern generation and reasoning capabilities found in contemporary Large Language Models (LLMs). The self-attention mechanism scales quadratically with context length in compute and memory, but engineering and algorithmic advances combined with massive compute made Transformers the dominant architecture for LLMs.

This dominance exposed some limitations of vanilla LSTMs that helped prompt the shift. Three of these are particularly salient. First, the classical LSTM cell cannot easily revise earlier storage decisions: once information is mixed into scalar cell state(s), selectively overwriting or reweighing past contributions is difficult. Second, storage capacity is limited when memory is scalar-valued per cell; representing and recalling high-dimensional items becomes inefficient. Third, the standard LSTM recurrence includes hidden-to-hidden mixing that enforces strictly sequential processing and inhibits parallelization across time steps. These limitations are visible empirically: LSTMs struggle at nearest-neighbor retrieval tasks that require revising stored candidates, show degraded performance on rare-token prediction where larger expressive memory helps, and are disadvantaged in large-scale parallel training compared to Transformers.

# Core question: Can scaled and improved LSTMs compete with modern LLMs?

Given the historical strengths of LSTMs and the evolution of other sequence models (Transformers, State Space Models, linear attention variants), the central question posed by the work is simple and concrete: if we address the known LSTM limitations with modern design techniques, and scale LSTM-like models to billions of parameters while leveraging contemporary residual backbones and normalization practices, how far can LSTMs go in language modeling? Put another way: is the performance gap an inherent architectural ceiling of recurrent memory or a matter of specific limitations (gating shape, memory representation, parallelizability) that can be remedied?

Answering this requires both algorithmic innovations—new gating functions and memory structures—and careful integration with the residual, pre-LayerNorm training recipes used in contemporary LLMs, plus empirical evaluation at scale. The goal is not merely parity on toy tasks but to build models that can be trained on the same datasets and evaluated with the same metrics (e.g., perplexity and downstream task performance) used in modern LLM research, and to measure whether these enhanced LSTM variants exhibit competitive scaling behavior.

# Key contributions: exponential gating, new memory structures (sLSTM, mLSTM), xLSTM blocks and architectures

To directly address the three core LSTM limitations, the paper contributes two orthogonal extensions to the LSTM idea and a way to combine them into residual architectures suitable for large-scale training.

First, exponential gating with stabilization and normalization. Traditional LSTM gates use the sigmoid nonlinearity, which constrains gate outputs to $(0,1)$ and provides stability. The authors propose replacing (some) gates with exponential activations, e.g. an input gate of the form $i_t = \exp(\tilde{i}_t)$ and allowing the forget gate $f_t$ to be either $\sigma(\tilde{f}_t)$ or $\exp(\tilde{f}_t)$. Exponential gating changes how contributions accumulate: multiplicative effects through repeatedly applied forget gates can form geometric sequences that enable smooth and effective revision of stored quantities. Because exponentials can grow or underflow numerically, the paper introduces a stabilizer state $m_t$ and stabilized gate forms (computing $i'_t$ and $f'_t$ via log-space subtraction and exponentiation) so that replacing $i_t,f_t$ by $i'_t,f'_t$ preserves network outputs and gradients while avoiding numerical overflow.

Second, two new memory-structure variants that exploit exponential gating in different ways.

- sLSTM (scalar-extended LSTM): sLSTM retains a scalar cell state per memory unit but augments the recurrence with an explicit normalizer state $n_t$ that accumulates gate strengths, and uses exponential gates together with the normalizer to allow stable retrieval via division: $\tilde{h}_t = c_t / n_t$. The forward equations include
  $c_t = f_t c_{t-1} + i_t z_t,\quad n_t = f_t n_{t-1} + i_t,\quad \tilde{h}_t = c_t / n_t.$
  sLSTM also supports multiple cells and introduces a controlled form of memory mixing via recurrent connections between hidden states and per-cell inputs and gates. Crucially, exponential gating plus the normalizer enables the unit to revise stored information: an incoming value with a stronger input gate can dominate earlier stored items by adjusting the normalized contribution.

- mLSTM (matrix memory LSTM): mLSTM replaces the scalar cell $c_t$ with a matrix memory $\mathbf{C}_t\in\mathbb{R}^{d\times d}$, and stores key-value pairs using a covariance (outer-product) update rule reminiscent of Fast Weight Programmers and associative memories:
  $\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \, \mathbf{v}_t \mathbf{k}_t^\top.$
  Retrieval is performed by multiplying the memory by a query vector: $\tilde{\mathbf{h}}_t = \mathbf{C}_t \mathbf{q}_t / \max\{|\mathbf{n}_t^\top \mathbf{q}_t|,1\}$, where $\mathbf{n}_t$ is a normalizer accumulating weighted keys and the denominator stabilizes the scale of the retrieved vector. The outer-product update increases storage capacity dramatically by keeping pairwise associations explicitly in the matrix; the forget gate $f_t$ acts as decay of the matrix (a form of continuous forgetting) while $i_t$ acts like a learning rate for the new outer product. Because mLSTM drops recurrent hidden-hidden mixing of memory in favor of purely input-driven key/value/query parameterizations, its recurrence can be reformulated in parallel across time (allowing efficient GPU implementations akin to other linear-time approaches).

Third, xLSTM blocks and architectures. Both sLSTM and mLSTM are integrated as building blocks inside residual backbones with pre-LayerNorm, following contemporary LLM designs. For sLSTM the authors prefer a residual block with post up-projection (non-linear summarize in original space, then up-project), whereas for mLSTM they use a pre up-projection (project to high-dimensional space before the non-linear recurrent summary) to better exploit the larger matrix memory in higher dimensional embeddings. By residually stacking many such blocks, xLSTM architectures mirror the deep residual stacks of Transformers but replace the self-attention sublayers with these extended LSTM-based summarizers. The architecture notation xLSTM[a:b] denotes the ratio of mLSTM-based to sLSTM-based blocks (for example xLSTM[7:1] has 7 mLSTM blocks and 1 sLSTM block out of every 8).

# High-level findings: competitive perplexity, favorable scaling, strong long-context behavior

The empirical evaluation addresses multiple axes: synthetic tasks designed to probe state tracking and associative memory, validation perplexity when trained on a common dataset, scaling behavior with model size and training compute, long-context extrapolation, and downstream/task-benchmark performance.

On synthetic tasks, exponential gating plus memory mixing (as in sLSTM) enables solving formal language problems that demand precise state tracking—tasks where Transformer and State Space Models without memory mixing struggle. The matrix memory of mLSTM gives large associative capacity: on Multi-Query Associative Recall tasks that require storing and later retrieving many key-value pairs (extended to hundreds of pairs and long contexts), xLSTM variants with mLSTM blocks outperform other non-Transformer methods and approach transformer-like strengths for associative memory. On Long Range Arena benchmarks, xLSTM shows robust performance across diverse long-context tasks.

On realistic language modeling, the paper trains models on SlimPajama data at multiple training budgets. Trained on 15B tokens with model sizes matched to a GPT-3 350M-like configuration, xLSTM variants (combinations of mLSTM and sLSTM blocks) achieve lower validation perplexity than the tested Transformers, State Space Models (SSMs), and recent RNN-based competitors. Ablation studies indicate that both exponential gating and the matrix-memory extension contribute substantially to these improvements.

Scaling to larger training budgets (300B tokens) and to a range of model sizes (125M–1.3B), xLSTM models maintain favorable scaling behavior: power-law trends are similar to competing methods but with a lower offset, suggesting xLSTM will continue to compete as size grows. On sequence length extrapolation experiments (models trained with context 2048 and evaluated up to 16384), xLSTM models retain low perplexity for much longer contexts than the compared methods. Across downstream common-sense benchmarks and a fine-grained PALOMA suite of 571 domains, xLSTM generally outperforms the examined Transformer, SSM, and RNN baselines, often substantially so; for example, xLSTM[1:0] achieves lower perplexity than Mamba on 568 out of 571 domains.

Performance characteristics also reflect structural trade-offs. mLSTM's matrix memory increases computation due to $d\times d$ updates and retrievals, but does not require additional learned parameters in the memory itself and can be parallelized on GPUs; sLSTM's memory mixing (hidden-to-hidden connections) preserves expressivity for state tracking but is inherently sequential, making it harder to parallelize—though a custom CUDA kernel can narrow the wall-clock gap. Importantly, xLSTM models exhibit linear compute complexity and constant memory complexity with respect to sequence length (unlike quadratic Transformer attention), enabling much higher decoding batch sizes and throughput for long sequences.

The study also outlines limitations: sLSTM memory mixing limits parallelization; efficient CUDA kernels for mLSTM are not fully optimized in the reported implementation; the matrix memory imposes substantial compute for large embedding dims; forget gate initialization must be chosen carefully; and very long contexts could saturate the fixed-size matrix memory, though empirically mLSTM handled contexts up to 16k in their experiments.

LSTM Foundations: Constant Error Carousel and Gating

# Vanishing gradients in RNNs and the LSTM solution
Recurrent neural networks (RNNs) process sequences by repeatedly applying the same transition to propagate information through time. A well-known difficulty for vanilla RNNs is the vanishing (and exploding) gradient problem: when gradients are backpropagated through many time steps, multiplicative effects of the transition Jacobians cause gradients to decay exponentially (or blow up), preventing reliable learning of long-range dependencies. The paper frames this historical motivation as the reason the Long Short-Term Memory (LSTM) architecture was introduced in the 1990s: to overcome vanishing gradients and permit learning of long-term dependencies in sequential data.

The central LSTM solution is to provide an internal memory that is updated additively rather than purely multiplicatively. Additive updates enable a path through time along which gradients can flow without repeated multiplicative attenuation. This design principle directly addresses the vanishing gradient problem by creating what is called the constant error carousel: a memory state that can carry error signals across many time steps with controlled modification.

# Constant error carousel: additive memory updates
The constant error carousel refers to the LSTM's central memory update mechanism: the cell state is a stored quantity that evolves by addition of a (gated) new input to a (gated) retained previous state. Concretely, the simplified conceptual form introduced in the paper is

$c_t \ =\ f_t\ c_{t-1} \ +\ i_t\ z_t,$

which expresses the cell state $c_t$ at time $t$ as a combination of the previous cell state $c_{t-1}$ moderated by a forget factor $f_t$ and a newly produced candidate contribution $z_t$ scaled by an input factor $i_t$. This additive structure is the constant error carousel: gradients that flow back through time can pass through the addition path, attenuated only by the forget gates rather than being repeatedly multiplied by arbitrary transition matrices. Because $f_t$ is typically constrained by a gating nonlinearity, this allows gradients to be preserved over long time scales when appropriate.

This additive update contrasts with recurrent updates that only apply multiplicative transformations to hidden states; the additive term provides a route for storing and retrieving content and for stable gradient flow. The cell state, being updated additively and gated, can function as a memory with controllable retention and replacement.

# Gates and activations: input, forget, output; tanh/sigmoid roles
LSTM memory operations are controlled by three principal gates: the input gate $i_t$, forget gate $f_t$, and output gate $o_t$. Each gate modulates a different aspect of how the cell interacts with incoming information and the outside world.

The input gate $i_t$ scales the candidate input contribution $z_t$ before it is added to the cell. The forget gate $f_t$ scales the previous cell state $c_{t-1}$, deciding which parts of memory to retain. The output gate $o_t$ controls how much of the (typically squashed) cell state is exposed as the hidden state $h_t$. In the conceptual form given in the paper, the hidden state is

$h_t \ =\ o_t\ \psi(c_t),$

where $\psi$ is an activation used to normalize or squash the cell state prior to output. Common choices for the squashing function $\psi$ (and for the candidate input activation $\varphi$ producing $z_t$) have been hyperbolic tangent or similar bounded nonlinearities. The gates themselves are produced by affine transforms followed by sigmoid nonlinearities $\sigma(x)=1/(1+\exp(-x))$ in classical LSTM formulations, ensuring gates take values in $(0,1)$ and thus act as soft selectors.

The roles of these activations are important: sigmoidal gates provide smooth, differentiable control over retention and addition, while the squashing $\psi$ keeps the exposed hidden state bounded and stable. Together they form an architecture in which memory content is both preserved and made accessible in a stable manner.

# Standard LSTM equations and parameterization
The paper presents the standard LSTM equations used as a reference point for the xLSTM developments. In that formulation the scalar cell update and gate computations at time $t$ are written as

c_t \ = \ f_t\ c_{t-1} \ + \ i_t\ z_t
h_t \ = \ o_t\ \tilde{h}_t, \quad \tilde{h}_t \ =\ \psi(c_t)

z_t \ =\ \varphi(\tilde{z}_t), \quad \tilde{z}_t \ =\ \mathbf{w}_z^\top \mathbf{x}_t + r_z\ h_{t-1} + b_z

i_t \ =\ \sigma(\tilde{i}_t), \quad \tilde{i}_t \ =\ \mathbf{w}_i^\top \mathbf{x}_t + r_i\ h_{t-1} + b_i

f_t \ =\ \sigma(\tilde{f}_t), \quad \tilde{f}_t \ =\ \mathbf{w}_f^\top \mathbf{x}_t + r_f\ h_{t-1} + b_f

o_t \ =\ \sigma(\tilde{o}_t), \quad \tilde{o}_t \ =\ \mathbf{w}_o^\top \mathbf{x}_t + r_o\ h_{t-1} + b_o.

This parameterization makes clear how inputs $\mathbf{x}_t$ and the previous hidden state $h_{t-1}$ influence the candidate input and each gate via learned affine transforms. The vectors $\mathbf{w}_z,\mathbf{w}_i,\mathbf{w}_f,\mathbf{w}_o$ are input weight vectors (mapping current input to respective preactivations), the scalars $r_z,r_i,r_f,r_o$ are recurrent (hidden-to-preactivation) weights in the scalar-cell case, and $b_z,b_i,b_f,b_o$ are biases. The functions $\varphi$ and $\psi$ are activation functions for the candidate input and the exposed cell content, respectively.

This set of equations captures the classic LSTM cell behavior: it constructs a candidate input, gates it, decides how much previous memory to keep, and controls what is emitted as the hidden state. The gates are typically sigmoid-activated, ensuring bounded multiplicative factors, and $\varphi,\psi$ are often chosen as $\tanh$ to keep candidate and exposed values within a stable range.

# Vectorized multi-cell LSTM and memory mixing via recurrent matrices
Practical LSTM implementations extend the scalar cell to a vector of cells $\mathbf{c}_t \in \mathbb{R}^d$. This vectorization allows richer distributed memory representations and enables mixing between memory cells through recurrent weight matrices. In the multi-cell setup, the affine recurrent contributions to gates and candidate inputs become matrix-vector products involving the previous hidden state vector, replacing scalars like $r_z h_{t-1}$ with terms such as $\mathbf{R}_z\ \mathbf{h}_{t-1}$ where $\mathbf{R}_z \in \mathbb{R}^{d\times d}$.

Memory mixing refers to these hidden-to-gate or hidden-to-candidate recurrent matrices that allow the contents and outputs of different scalar memory cells to influence each other across time steps. Through recurrent matrices $\mathbf{R}_{z},\mathbf{R}_{i},\mathbf{R}_{f},\mathbf{R}_{o}$, the vectorized LSTM gains the capacity to reallocate, transform, and entangle information across memory channels as sequences evolve. This increases expressivity compared to independent scalar cells, and is a core reason LSTMs can perform complex sequence-processing tasks that require combining and updating multiple stored factors.

The paper highlights that such mixing (hidden-hidden connections) is also the source of sequential dependence that prevents certain parallelization strategies: memory mixing enforces a temporal dependence that must be computed step by step. Nevertheless, memory mixing is crucial for tasks requiring state tracking and interactions among stored components.

# Why each component matters: lessons from ablations
The paper notes that ablation studies on classical LSTM designs have shown that all components of the memory cell are crucial. That is, removing or significantly altering gates, the additive memory update, or the squashing functions degrades performance and learning stability. Each component fulfills a distinct functional role: the forget gate controls retention and prevents unbounded accumulation, the input gate mediates selective storage of new information, and the output gate controls exposure of internal state to downstream computations. The additive update (constant error carousel) is the structural mechanism that preserves gradients over long time horizons. The activation functions constrain numeric ranges and provide smooth nonlinearity necessary for learning.

These insights motivate the design choices in the xLSTM extensions introduced later in the paper. For example, xLSTM retains the core idea of a memory cell with gating and a normalizing/squashing step, but systematically modifies the gating nonlinearities (introducing exponential gating) and the memory structure (introducing scalar-head mixing variants and a matrix-valued covariance memory) to alleviate specific limitations identified for classical LSTMs. The paper uses a sequence of controlled changes—embedding LSTMs in residual backbones, changing projection orders, adding exponential gates, and expanding memory representations—to ablate and attribute performance gains to specific components. The broader lesson is that each canonical LSTM element is functionally important, and improvements must preserve their roles while addressing identified shortcomings like limited storage capacity, inability to revise storage decisions, and parallelization constraints.

In summary, the LSTM foundations—constant error carousel, gated additive updates, squashing and gating nonlinearities, and recurrent mixing in vectorized cells—together explain both the original success of LSTMs and why careful, principled modifications (as advocated in the paper) can yield powerful extensions such as xLSTM.

Limitations of Classic LSTMs

# Inability to revise stored content: Nearest Neighbor Search example
One of the foundational design elements of the original Long Short-Term Memory (LSTM) is the additive cell update, often called the constant error carousel:
$c_t = f_t \, c_{t-1} + i_t \, z_t$,
with gates $i_t,f_t$ in $(0,1)$ typically produced by a sigmoid. This additive mechanism gives excellent gradient flow and enables the network to preserve information over long horizons. However, the multiplicative gating by sigmoids also creates a practical limitation: once information is committed to the cell state it is difficult to revise it decisively later in the sequence.

The paper illustrates this limitation with a Nearest Neighbor Search style problem. In that task a reference vector is fixed at the beginning of the sequence and thereafter the model scans a long sequence of candidate vectors; at the end the model must output the value attached to the sequence element most similar to the reference. To succeed the recurrent memory must be able to update stored information when a better match appears later, effectively "overwriting" or strongly modifying the previously stored content. Classic LSTM gating with $i_t$ and $f_t$ in the usual sigmoid range constrains how aggressively the stored scalar cell $c_t$ can be altered by a subsequent input: forget gates can gradually decay past content, and input gates can add new content, but the combination tends to blend old and new content rather than allow rapid, multiplicative replacement. As a result, LSTMs struggle to revise earlier storage decisions when a later input should replace what the model had kept, and the paper reports poor mean squared error on this task for vanilla LSTM.

This inability to revise effectively stems from the bounded, sub-exponential behavior of standard gating. When a later token should completely dominate the memory, the LSTM would need a near-zero forget gate and a very large input contribution, or vice versa, but practical training and numeric stability make such extreme gate dynamics rare. The xLSTM work addresses this specific failure mode by introducing exponential gating (for example $i_t=\exp(\tilde i_t)$), together with normalization and stabilization mechanisms, which allow gates to behave multiplicatively across time in a way that can implement strong replacement-like updates while remaining numerically stable. This exponential gating enables rapid revision of the stored content when needed, remedying the problem demonstrated by the Nearest Neighbor Search example.

# Limited capacity of scalar memory: Rare Token Prediction behavior
Classic LSTMs store information in scalar cell states (or a vector of scalar cells). Even when many scalar cells are present, each memory location stores a compressed scalar quantity and retrieval is mediated through scalar-to-hidden mappings. This imposes a practical limit on the representational capacity per timestep and on the kinds of retrievals that can be done efficiently.

The paper highlights this limitation through a Rare Token Prediction experiment on language data (Wikitext-103). Tokens that occur infrequently require the model to remember specific, perhaps high-dimensional, associations from the past in order to predict them correctly when they reappear. Because an LSTM's memory must compress diverse semantic content into scalar cell components and because retrieval is mediated by relatively small parameterized readouts, rare, high-specificity associations are difficult to encode and retrieve reliably. Empirically, the LSTM shows worse perplexity on rare tokens compared to more frequent ones, indicating that its scalar memory has insufficient capacity to store and retrieve those low-frequency, high-specificity items.

This limitation motivated the paper to enlarge the memory structure. The mLSTM variant replaces scalar cell states by a matrix memory $\mathbf{C}_t \in \mathbb{R}^{d\times d}$ and uses a covariance (outer-product) style update
$\mathbf{C}_t = f_t \, \mathbf{C}_{t-1} + i_t \, \mathbf{v}_t \, \mathbf{k}_t^\top$,
storing key--value pairs via outer products. Retrieval is then a matrix-vector product $\mathbf{C}_t \mathbf{q}_t$, normalized by an appropriate normalizer, which supports higher-capacity, structured storage and associative recall. In experiments (the Multi-Query Associative Recall task) this matrix memory substantially increases the model's ability to remember many distinct key--value pairs and thereby to predict rare tokens more accurately. The matrix memory thus directly addresses the capacity bottleneck of scalar cell states.

# Sequential processing due to memory mixing: lack of parallelization
A third limitation of classic LSTMs is architectural: the hidden-to-hidden recurrent connections (often denoted $r_*$ or a recurrent matrix $\mathbf{R}$ in vectorized versions) mix memory across timesteps in a way that enforces an inherently sequential computation. Concretely, gates and cell inputs are functions of the previous hidden $h_{t-1}$ as well as the current input $\mathbf{x}_t$, so computing the forward pass for time $t$ requires $h_{t-1}$, which requires $h_{t-2}$, and so on. This recurrent dependency prevents straightforward parallelization over sequence positions and yields runtime that scales linearly in sequence length for compute and memory footprints that grow with context length.

This sequential characteristic contrasts sharply with the Transformer architecture where self-attention enables parallel computation over all positions during the forward pass (albeit with quadratic complexity in sequence length in vanilla attention). The lack of parallelizability made LSTMs less attractive for large-scale language modeling when GPU/TPU hardware and parallel training became central concerns: models that can be executed in parallel across long contexts fit better with modern large-batch training and efficient accelerator usage.

xLSTM tackles this limitation through two complementary design choices. First, the mLSTM abandons memory mixing: the matrix memory update and retrieval depend only on the current input (and gated scalars) but not on $h_{t-1}$ through recurrent weight matrices; this enables a reformulation of the recurrence into a parallelizable computation (the paper notes that the mLSTM recurrence can be re-expressed in a parallel version analogous to linear attention and FlashAttention-style methods). Second, the xLSTM architecture integrates these recurrent memory modules inside residual block backbones and stacks them residually, preserving the benefits of residual pre-LayerNorm designs used in large models. For sLSTM, memory mixing can still be present (it supports recurrent weight matrices and so remains sequential), but the authors describe multiple-head designs and improved CUDA kernels to reduce practical overhead; mLSTM, in contrast, aims specifically for parallel execution. Thus xLSTM provides variants that recover parallelizability while keeping or improving the long-range memory behaviors.

# How these gaps led to Transformer adoption at scale
The three limitations above—difficulty in decisively revising stored content, constrained scalar memory capacity, and poor parallelizability—explain much of why Transformers displaced LSTMs as the dominant architecture for large-scale language modeling. Transformers offer two practical advantages addressing these gaps: first, attention-based retrieval can perform rapid, content-based lookups (implicit associative memory) that effectively revise what influences the next-token prediction based on each new query; second, attention provides high effective memory capacity because pairwise token interactions can encode and retrieve rich associations; third, the Transformer forward pass is parallelizable across sequence positions (during training), matching modern accelerator workflows and enabling efficient use of massive compute.

The paper points out that these limitations of LSTMs "paved the way for the emergence of Transformers" and raises the motivating question of the work: how far can LSTM-style models go in language modeling if we address those limitations—i.e., give LSTMs stronger gating, larger and more associative memory, and constructs that enable parallel computation—while also applying modern training and architectural techniques used in contemporary LLMs (residual stacking, pre-LayerNorm, up-projections, etc.). This is the rationale behind xLSTM.

# Design goals for xLSTM to address these limitations
Given the gaps identified, the xLSTM design sets clear, targeted goals and implements concrete mechanisms to meet them while staying within the LSTM family of ideas:

1. Allow decisive revision of memory contents. To permit strong replace-like updates and better state tracking, xLSTM introduces exponential gating for the input gate (and optionally for the forget gate): for example $i_t = \exp(\tilde i_t)$. Exponential gates can produce multiplicative accumulation or decay across time steps that is much sharper than sigmoid gates. Because exponentials can overflow or underflow, xLSTM also introduces normalization and stabilization machinery: a normalizer state (e.g., $n_t$ in sLSTM or $\mathbf{n}_t$ in mLSTM) that keeps track of the effective gate mass over future steps, and a stabilizer state $m_t$ that prevents numerical instability when dealing with exponentials. Together these elements make strong, numerically stable revision of stored content possible.

2. Increase memory capacity and support associative recall. To overcome the scalar-memory bottleneck, xLSTM offers the mLSTM variant with a matrix memory $\mathbf{C}_t$ and a covariance (outer-product) update
$\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top$,
storing key--value pairs akin to associative memories and Fast Weights. Retrieval uses a query $\mathbf{q}_t$ and returns $\mathbf{C}_t \mathbf{q}_t$ scaled by an appropriate normalization $\max\{|\mathbf{n}_t^\top \mathbf{q}_t|,1\}$; the normalizer $\mathbf{n}_t$ accumulates the gated keys over time. This construction substantially expands per-step storage and enables high-capacity associative lookups that improve rare-item prediction and associative-recall tasks.

3. Recover parallelizability where possible. To address the sequential bottleneck, mLSTM removes hidden-to-hidden memory mixing so that its recurrence can be rewritten into a parallel computation across sequence positions, similar in spirit to linearized attention approaches. This allows xLSTM architectures that are linear in context length in compute and constant in memory with respect to sequence length, enabling efficient scaling and high decoding throughput. For sLSTM, which preserves memory mixing for expressivity, the paper accepts a sequential character but mitigates the performance impact with optimized CUDA kernels and by combining sLSTM and mLSTM blocks in hybrid stacks (multiple heads, selective mixing) so that most of the heavy lifting can be parallel when desired.

4. Integrate with modern residual backbones and scaling practices. To be competitive at LLM scale, xLSTM modules are placed inside residual block backbones (pre-LayerNorm, up-projection styles) and stacked residually to form deep architectures. For sLSTM the paper uses post up-projection residual blocks; for mLSTM the design prefers pre up-projection blocks to enlarge the coding dimension in which matrix memories operate. This mirrors the successful backbone patterns used in contemporary Transformers and SSMs and supports favorable scaling behavior.

In short, xLSTM's design goals map directly to the identified limitations: exponential gating and stabilizers to enable decisive memory revision; matrix (covariance) memory and normalization to increase capacity and enable associative recall; and architectural choices (no memory mixing in mLSTM, residual stacking) to regain parallelizability and modern training compatibility. The paper's experiments show that these targeted remedies let xLSTM compete with, and in many measured respects outperform, Transformer and State Space baselines on language modeling and synthetic tasks that stress these exact limitations.

Exponential Gating and Numerical Stabilization

# Rationale: stronger, multiplicative credit assignment and revisability

Gating is the core mechanism in LSTM-style cells: gates control how new information is written into the memory and how much of the past is kept. In the classical LSTM the gates are sigmoidal, so their outputs lie in the interval $(0,1)$ and act like convex weights in the additive cell update
\[
c_t = f_t c_{t-1} + i_t z_t.
\]
This design gives bounded, gradual updates and is effective at preventing vanishing gradients. However, sigmoid gates also limit how sharply the model can revise previously stored content. When a later input should strongly overwrite earlier stored content, the multiplicative effect of a chain of sigmoidal forgets can be slow and numerically constrained: every forget gate multiplies the residual by a number less than one, so revising a stored item that was written long ago requires many small multiplicative steps.

Exponential gating replaces this bounded multiplicative behavior by an unbounded positive multiplier. Concretely, replacing a sigmoid gate by an exponential of an unconstrained pre-activation lets the gate behave as a multiplicative factor in $(0,\infty)$ rather than $(0,1)$. This lets the model either strongly amplify or strongly attenuate contributions in a single step, enabling decisive revisals of earlier storage decisions. In other words, exponential gates enable stronger multiplicative credit assignment: a single large negative pre-activation makes the exponential extremely small (effectively forgetting immediately), and a large positive pre-activation makes the exponential very large (effectively amplifying or replacing past content). This sharper multiplicative control is the primary reason exponential gating is proposed: it increases the model’s ability to revise memory quickly and decisively.

# Replacing sigmoid with exp for input/forget gates

In the sLSTM and mLSTM formulations of xLSTM, the input gate $i_t$ is set to an exponential of its pre-activation:
\[
i_t = \exp\!\big(\tilde{i}_t\big),\qquad
\tilde{i}_t = \mathbf{w}_i^\top \mathbf{x}_t + r_i h_{t-1} + b_i
\]
(or in the simplified mLSTM variant $\tilde{i}_t = \mathbf{w}_i^\top \mathbf{x}_t + b_i$ when recurrent connections are removed). Similarly, the forget gate may be implemented either as a sigmoid
\[
f_t = \sigma(\tilde{f}_t)
\]
or, if one desires the same multiplicative flexibility as for the input gate, as an exponential
\[
f_t = \exp\!\big(\tilde{f}_t\big),
\]
with its own pre-activation $\tilde{f}_t$. The output gate retains a sigmoid in the paper’s designs:
\[
o_t = \sigma(\tilde{o}_t),
\]
so that the final emission from the memory is bounded in the usual way.

Replacing sigmoids by exponentials changes the algebraic nature of the recurrence: gates become multiplicative scaling coefficients that are not bounded above by 1, and therefore the cell state dynamics are no longer constrained to be convex combinations. This change is the enabling mechanism for revisability: a later large negative $\tilde{i}_t$ can make $i_t$ tiny and thereby eliminate the contribution of a particular input rapidly, whereas a later large positive $\tilde{i}_t$ can strongly increase a component’s influence.

# Normalizer state: tracking cumulative gate strength

Unbounded multiplicative gates introduce two practical issues: (1) the cell state can grow without bound because repeated multiplications and additions with unbounded factors accumulate large magnitudes, and (2) the relative scale of what has been stored becomes hard to interpret for downstream retrieval. To control this while preserving the revisability property, xLSTM introduces a normalizer state that keeps track of the cumulative strength of the write path through time.

For the scalar sLSTM the normalizer $n_t$ is defined alongside the cell state $c_t$ as
\[
\begin{aligned}
c_t &= f_t c_{t-1} + i_t z_t,\\
n_t &= f_t n_{t-1} + i_t,
\end{aligned}
\]
and the hidden pre-output is formed by normalizing the cell by this normalizer:
\[
\tilde{h}_t = \frac{c_t}{n_t},\qquad h_t = o_t \tilde{h}_t.
\]
Intuitively, $n_t$ accumulates the effective total write mass that contributes (with future decays) to the current cell content. Dividing $c_t$ by $n_t$ yields a normalized memory readout that is scale-invariant with respect to the overall write magnitude: if all writes were uniformly scaled up, both $c_t$ and $n_t$ scale proportionally and the quotient remains stable. This normalization makes retrieval robust and interpretable even though individual gates may be large.

For the matrix memory mLSTM the same idea generalizes: the normalizer becomes a vector that accumulates keys weighted by their write strengths,
\[
\mathbf{n}_t = f_t \mathbf{n}_{t-1} + i_t \mathbf{k}_t,
\]
and the readout from the matrix memory uses a normalization factor derived from $\mathbf{n}_t^\top \mathbf{q}_t$ (the aggregate alignment between stored keys and the current query). Practically, to avoid division by values very close to zero, the absolute value of the dot product is taken and bounded below by a threshold (typically 1.0). This keeps the normalized readout well-conditioned:
\[
\tilde{\mathbf{h}}_t = \frac{\mathbf{C}_t \mathbf{q}_t}{\max\{\,|\mathbf{n}_t^\top \mathbf{q}_t|,\,1\,\}},
\]
so the normalizer both records cumulative strength and stabilizes retrieval.

# Stabilizer state m_t: log-domain max-trick to prevent overflow

Exponentials are powerful but numerically dangerous: a modestly large positive pre-activation can produce enormous values that overflow floating-point representations, and long products of exponentials can also blow up. To make exponential gating practical and numerically stable, xLSTM uses a stabilizer state that operates in the log-domain and applies a max-trick similar to log-sum-exp style stabilization.

Define a scalar stabilizer state $m_t$ that tracks the dominant log-magnitude among the accumulated forget and new input contributions:
\[
m_t = \max\!\big(\log(f_t) + m_{t-1},\; \log(i_t)\big).
\]
Using this $m_t$, stabilized gate factors are computed as
\[
\begin{aligned}
i'_t &= \exp\!\big(\log(i_t) - m_t\big) = \exp(\tilde{i}_t - m_t),\\
f'_t &= \exp\!\big(\log(f_t) + m_{t-1} - m_t\big).
\end{aligned}
\]
The idea is that instead of operating directly with possibly huge un-normalized exponentials $i_t$ and accumulations involving $f_t$, the update is rewritten so that all multiplicative contributions are scaled by the same dynamic normalization factor $\exp(m_t)$. Concretely, the forward recurrence can be algebraically expressed in a form that factors out $\exp(m_t)$ (or equivalently performs the same arithmetic in the log domain), and then uses the stabilized, bounded factors $i'_t$ and $f'_t$ whose magnitudes are safely within representable floating-point ranges. This avoids overflow and underflow while preserving the relative weights.

Two aspects make this max-based stabilizer effective. First, by choosing the maximum log magnitude among the competing contributions we center the dynamic range, ensuring that the largest term becomes an order-one multiplier and smaller terms are fractions that do not cause overflow. Second, the recurrence of $m_t$ includes the previous stabilizer which allows the scheme to track cumulative effects through time, matching the way the original cell accumulates writes and decays.

# Equivalence of stabilized vs. unstabilized forward/gradients

A legitimate concern when applying numerical tricks is whether they change the computed function or the gradients used for learning. The paper states—and shows in its appendix—that replacing the raw exponential gates $i_t$ and $f_t$ by the stabilized versions $i'_t$ and $f'_t$ in the forward pass does not change either (a) the overall network outputs, or (b) the derivatives of the loss with respect to the parameters. In other words, the stabilized computation is mathematically equivalent (up to machine precision) to the unstabilized arithmetic; it is simply an algebraic refactoring that computes the same recurrence while avoiding numerical overflow.

The equivalence can be seen by observing that the stabilizer $m_t$ is chosen so that all multiplicative terms share the common scaling factor $\exp(m_t)$ and computations factor this out. When you undo the factorization, you recover exactly the original recurrence. Because this refactoring is algebraic, backpropagation through the stabilized arithmetic yields gradients that match (analytic) gradients of the unstabilized form. Thus the stabilization is safe: it is purely a numerics-focused re-expression of the same mathematical function and does not alter learning dynamics, other than avoiding catastrophic numerical errors.

# Practical activation and normalization choices

Putting the components together yields a practical recipe that balances expressive revisability with numerical safety.

- Which gates to exponentiate? In xLSTM the input gate $i_t$ is replaced by an exponential. The forget gate $f_t$ can be either sigmoid or exponential. Using exponential forgets gives the maximum revisability flexibility but requires careful initialization and stabilization because repeated large multiplicative decays or amplifications can be more extreme. In practice, leaving the output gate as a sigmoid ($o_t = \sigma(\tilde{o}_t)$) remains sensible because the final emission benefits from being bounded.

- Normalization: In sLSTM the scalar normalizer $n_t$ divides the accumulated cell $c_t$ to produce the normalized readout $\tilde{h}_t = c_t/n_t$. This prevents the hidden representation from drifting in absolute magnitude as write strengths vary. In mLSTM the normalizer $\mathbf{n}_t$ is vector-valued and the normalization during retrieval uses the absolute dot product with the query, clamped from below (typical clamp at 1.0), i.e. $\max\{|\mathbf{n}_t^\top \mathbf{q}_t|,1\}$. That clamp prevents division by very small numbers and stabilizes early-phase training.

- Stabilizer initialization and maintenance: The stabilizer state $m_t$ requires initialization (e.g., $m_0$ can be set to a finite baseline such that initial exponentials are well scaled). Because $m_t$ evolves by taking a max with the log contributions, it adapts to the working scale of the model online. This reduces sensitivity to absolute pre-activation scales and mitigates the need for pathological hyperparameter tuning to avoid overflows.

- Implementation note: Because the stabilized scheme is algebraically equivalent to the unstabilized form, one may implement the stabilized arithmetic as the canonical forward computation. Doing so gives robust numerical behavior across long sequences and large model sizes. For the matrix mLSTM, computations can be arranged so that the matrix memory update and normalization share the log-domain stabilization, and the retrieval denominator uses the clamped absolute dot product to avoid dividing by tiny numbers.

Together, exponential gates, coupled with a normalizer state and log-domain stabilizer, provide the model with the ability to perform sharp, multiplicative revisals while keeping numerical values well behaved and retrievals well conditioned. This combination is central to xLSTM’s improved revisability and memory behavior compared to classical sigmoidal LSTM designs.

sLSTM: Scalar-Memory xLSTM with Memory Mixing

# sLSTM forward pass: c_t, n_t, h_t with normalized output
The sLSTM is an Extended Long Short-Term Memory variant that keeps the familiar scalar memory cell per channel like the classical LSTM, but augments the cell with new gating and normalization mechanisms tailored to improve revision of stored content and stable retrieval. At each time step $t$ the sLSTM maintains three central state quantities per memory channel: the cell state $c_t$, a normalizer state $n_t$, and the hidden output $h_t$. The forward pass is written compactly as

$c_t = f_t \, c_{t-1} + i_t \, z_t,$

$n_t = f_t \, n_{t-1} + i_t,$

$h_t = o_t \, \tilde{h}_t,\qquad \tilde{h}_t = \dfrac{c_t}{n_t}.$

Here $z_t$ denotes the cell input (the new content proposed for storage), $i_t$ the input gate, $f_t$ the forget gate, and $o_t$ the output gate. Intuitively, $c_t$ accumulates gated contributions of past inputs just like in classical LSTM, but the normalizer $n_t$ accumulates the scalar weights used to form $c_t$ so that the quotient $c_t / n_t$ yields a normalized estimate of the stored content. This normalization ensures that the magnitude of the retrieved signal is controlled relative to the aggregate gating strength, which is critical when gates are allowed to take values beyond the unit interval (see below).

The retrieval $\tilde{h}_t = c_t / n_t$ should be understood as a running weighted average: if $i_t$ and $f_t$ behave like conventional probabilities (values in $(0,1]$), then $c_t$ approximates a weighted sum of past $z$ values and $n_t$ the corresponding sum of weights; dividing yields a weighted mean. This design permits the memory to represent an amortized stored content over time and makes the effect of any single write proportional to its relative weight among the contributions that remain after forget gating.

# Exponential input/forget gates; output gate sigmoid
A major departure from classical LSTM is the choice of activation for the input and optionally the forget gates. In sLSTM the input gate is realized via an exponential activation:

$i_t = \exp(\tilde{i}_t),\qquad \tilde{i}_t = \mathbf{w}_i^\top \mathbf{x}_t + r_i \, h_{t-1} + b_i.$

The forget gate may be either sigmoid or exponential:

$f_t = \sigma(\tilde{f}_t) \quad\text{or}\quad f_t = \exp(\tilde{f}_t),\qquad \tilde{f}_t = \mathbf{w}_f^\top \mathbf{x}_t + r_f \, h_{t-1} + b_f.$

The output gate remains sigmoid as in traditional LSTM:

$o_t = \sigma(\tilde{o}_t),\qquad \tilde{o}_t = \mathbf{w}_o^\top \mathbf{x}_t + r_o \, h_{t-1} + b_o.$

Using exponentials for $i_t$ (and optionally for $f_t$) has a conceptual purpose: exponentials map linear preactivations $\tilde{i}_t$ to positive real multipliers that can span many orders of magnitude. This allows a single write to be given much larger or much smaller effective weight compared to previous stored content. In practice, exponentially large or small gates enable the model to "revise" stored information sharply: a large $i_t$ can overwrite prior content rapidly, while a small $f_t$ (much less than 1 when implemented via an exponential of a negative preactivation) can rapidly decay prior content. The combination thus provides the model with a continuous mechanism to modulate retention and replacement strength across a wide dynamic range, beyond the slow adjustments available with sigmoid gates alone.

# Stabilization with m_t and rescaled gates i'_t, f'_t
Exponentials are powerful but numerically hazardous: unbounded exponentials can overflow or underflow during forward computation and can create extremely large gradients. The sLSTM design therefore introduces a stabilizer scalar state $m_t$ that maintains a running log-scale reference and allows numerically safe rescaling of the gates without changing the functional behavior of the recurrence. The stabilizer is defined by

$m_t = \max\big(\log(f_t) + m_{t-1},\; \log(i_t)\big).$

Using $m_t$ we define rescaled gates that are safe to compute and use in the recurrence:

$i'_t = \exp\big(\log(i_t) - m_t\big) = \exp(\tilde{i}_t - m_t),$

$f'_t = \exp\big(\log(f_t) + m_{t-1} - m_t\big).$

Replacing $i_t$ and $f_t$ by $i'_t$ and $f'_t$ in the forward equations yields exactly the same outputs and derivatives with respect to parameters as the original unrescaled form. The stabilizer works by factoring out a common multiplicative scale $e^{m_t}$ from terms that would otherwise grow or shrink exponentially: one computes exponentials of bounded differences (e.g., $\tilde{i}_t - m_t$) rather than possibly huge raw preactivations. This trick is analogous to standard log-sum-exp stabilization and keeps internal values numerically well-behaved while preserving the expressive large-dynamic-range behavior of exponential gating.

In implementation, one computes $i'_t$ and $f'_t$ and then uses them in the recurrences

$c_t = f'_t \, c_{t-1} + i'_t \, z_t,\qquad n_t = f'_t \, n_{t-1} + i'_t.$

Although the notation uses primes, by construction these stabilized gates are mathematically equivalent to using the raw exponentials in exact arithmetic.

# Multiple cells and memory mixing via recurrent matrices
Just as modern LSTMs use vector-valued memory with multiple scalar channels, the sLSTM naturally extends to multiple scalar memory cells. Let the memory vector be $\mathbf{c}_t \in \mathbb{R}^d$ and the normalizer vector $\mathbf{n}_t \in \mathbb{R}^d$, with elementwise division performed channel-wise to obtain the pre-output $\tilde{\mathbf{h}}_t = \mathbf{c}_t \oslash \mathbf{n}_t$. The crucial extension beyond the original LSTM lies in how inputs and past hidden states interact to produce the cell inputs and gates: memory mixing is achieved by recurrent matrices that map the hidden state back into the gate and candidate preactivations. Concretely, for vectorized quantities one writes

\tilde{\mathbf{z}}_t = \mathbf{W}_z^\top \mathbf{x}_t + \mathbf{R}_z \mathbf{h}_{t-1} + \mathbf{b}_z,\qquad
\tilde{\mathbf{i}}_t = \mathbf{W}_i^\top \mathbf{x}_t + \mathbf{R}_i \mathbf{h}_{t-1} + \mathbf{b}_i,

and analogously for $\tilde{\mathbf{f}}_t$ and $\tilde{\mathbf{o}}_t$. Here each $\mathbf{R}_\bullet \in \mathbb{R}^{d\times d}$ is a recurrent matrix that mixes information across memory channels via the previous hidden state $\mathbf{h}_{t-1}$. After applying the respective activations (exponential or sigmoid), the multi-channel recurrences become

\mathbf{c}_t = \mathbf{f}_t \odot \mathbf{c}_{t-1} + \mathbf{i}_t \odot \mathbf{z}_t,\qquad
\mathbf{n}_t = \mathbf{f}_t \odot \mathbf{n}_{t-1} + \mathbf{i}_t,

with elementwise multiplication and division defining retrieval. These recurrent matrices provide a flexible mixing mechanism: information stored in one channel can influence gating and writes to other channels via $\mathbf{R}_i,\mathbf{R}_f,\mathbf{R}_z,\mathbf{R}_o$. This mixing is the reason sLSTM retains a key expressive advantage of classical LSTM: it can implement state-tracking computations that depend on interactions among stored components across time.

Memory mixing is essential for tasks that require structured state updates or the composition of different stored items. Unlike architectures which only maintain independent channels (no cross-channel recurrence), sLSTM's recurrent matrices allow it to implement complex sequential algorithms and maintain internal bookkeeping across channels.

# Heads in sLSTM: within-head mixing, no cross-head mixing
To further structure memory mixing and to provide architectural inductive biases, sLSTM supports a "multi-head" decomposition reminiscent of attention heads, but with an important difference in interaction patterns. When the memory vector is partitioned into H disjoint heads, each head maintains its own subset of scalar memory channels. Within a head, the usual recurrent mixing matrices operate: the head's hidden components influence gate and input preactivations for channels of the same head via dedicated recurrent matrices. However, by design there is no recurrent mixing across heads: the $\mathbf{R}_\bullet$ matrices are block-diagonal with blocks corresponding to heads. In other words, heads are independent with respect to memory mixing.

Formally, partition the memory dimension $d$ into $d = \sum_{h=1}^H d_h$ and arrange recurrent matrices to be block-diagonal: for head $h$ the matrices $\mathbf{R}_\bullet^{(h)} \in \mathbb{R}^{d_h\times d_h}$ operate only on the head’s slice of $\mathbf{h}_{t-1}$. Inputs $\mathbf{x}_t$ are projected separately into each head, and updates to $\mathbf{c}_t$ and $\mathbf{n}_t$ are computed head-wise. Output concatenation across heads then yields the full $\mathbf{h}_t$.

This head-wise partitioning provides two practical benefits. First, it reduces the parameter and computational coupling between different memory subspaces, which can stabilize optimization and encourage specialization of heads to different types of patterns. Second, it allows controlled parallelism and modularity: while each head still has internal recurrent mixing, the absence of cross-head recurrence reduces sequential dependencies between unrelated memory subspaces.

# How exponential gating + heads enable new memory mixing behaviors
Combining exponential gating with a head-structured sLSTM yields qualitatively new memory-mixing capabilities. Exponential gates permit multiplicative weights that vary over many orders of magnitude. When such gates are computed from mixed information within a head (via $\mathbf{R}_i^{(h)}$ and $\mathbf{R}_f^{(h)}$), a head can perform sharp and selective revisions to portions of its internal memory based on global or local context.

Concretely, consider a head that has learned to store a running aggregate of some feature in its channels. If at some step the head's input projection produces a large positive $\tilde{i}_t$ for a particular channel, the exponential input gate will give a dominant weight to the new $z_t$ relative to the accumulated $c_{t-1}$; by simultaneously setting $f_t$ small via its preactivation, the head can effectively erase or replace previous content in certain channels. Because the recurrent matrices within the head mix the previous hidden state into the gate computation, the decision to rewrite can depend on complex combinations of previously stored subcomponents. Therefore, exponential gates plus within-head recurrence implement a form of context-dependent fast rewrite: heads can choose, based on the current and past hidden state, to concentrate write mass on a small subset of channels or to distribute it broadly.

The head partitioning constrains this behavior so that such fast rewrites are localized to a head's subspace, preventing uncontrolled interference across all memory channels. This localized, high-dynamic-range rewriting is a new memory-mixing modality: it is neither purely additive averaging (classical LSTM with sigmoid gates) nor the full-rank outer-product memory of matrix-memory variants, but rather an adaptive, head-local multiplicative rewriting mechanism that can be extremely selective.

# Trade-offs: expressivity vs. parallelization
sLSTM preserves the expressive power afforded by recurrent cross-channel mixing, and the addition of exponential gating significantly enhances the model’s ability to rapidly revise stored content. These features make sLSTM particularly well-suited for tasks that require state tracking, selective overwriting, and algorithmic manipulation of internal scalar memory channels.

However, this expressivity comes with trade-offs. The recurrent mixing via $\mathbf{R}_\bullet$ matrices enforces true sequential dependencies: each time step depends on the previous hidden state. Consequently, sLSTM cannot be straightforwardly transformed into a fully parallel time-parallel implementation in the same way as architectures that remove hidden–hidden recurrence (for example, the matrix-memory mLSTM or certain State Space Models). The presence of sequential recurrence limits the extent to which sLSTM can exploit parallel hardware across time steps, making its wall-clock inference and training time dependent on efficient sequential kernels.

To mitigate numerical issues stemming from exponential gates, the stabilizer $m_t$ is necessary and adds a small computational overhead. The head decomposition reduces cross-talk and can improve both sample efficiency and numerical stability, but choosing the number and sizes of heads introduces design choices that affect parameter counts and performance.

In summary, sLSTM trades some parallelizability for richer, head-local memory mixing and high-dynamic-range gating that enable rapid and selective memory revision. This makes it a compelling component when the task demands strong sequential state tracking and controlled internal rewriting, at the cost of requiring careful engineering of efficient sequential implementations and stabilization mechanisms.

mLSTM: Matrix-Memory xLSTM with Covariance Updates

# From scalar $c$ to matrix $\mathbf{C}$: capacity motivations
The original LSTM stores information in scalar (or vectorized scalar) cell states $c_t$ whose updates are additive and gated. While this scalar memory is effective at avoiding vanishing gradients and at storing compact summary statistics, it is limited in raw storage capacity: a scalar cell (or even a vector of scalar cells) must compress arbitrary high-dimensional observations into a limited number of scalar coordinates. This compression can hurt retrieval of detailed or structured information, and makes certain tasks (e.g., associative recall of many distinct key–value pairs or rare-token prediction) difficult.

mLSTM addresses this limitation by promoting the scalar cell to a matrix memory $\mathbf{C}_t \in \mathbb{R}^{d\times d}$. A matrix memory enables direct, linear retrieval via matrix–vector products: items stored in the memory can be retrieved by applying the stored matrix to a query vector. The matrix representation therefore increases the expressivity and capacity of the memory compared to scalar cells: instead of compressing every stored concept into scalar coordinates, mLSTM can represent pairwise and directional relationships between $d$-dimensional vectors. This transformation from scalar to matrix memory is motivated by associative memory literature where matrix-based stores can represent multiple associations with favorable signal-to-noise properties.

# Associative memory framing: keys, values, queries (BAMs)
The matrix memory view naturally maps to the associative memory or key–value paradigm used in modern sequence models. At each time step $t$ the model produces a key $\mathbf{k}_t \in \mathbb{R}^d$ and a value $\mathbf{v}_t \in \mathbb{R}^d$, and later a query $\mathbf{q}_{t+\tau}$ is used to retrieve the value associated with a matching key. In this framing, the memory matrix $\mathbf{C}_t$ stores associations between keys and values so that retrieval becomes the product $\mathbf{C}_t \mathbf{q}$.

This formulation is closely related to Bidirectional Associative Memories (BAMs) from early neural associative memory work (Kohonen, Anderson, Nakano). In BAMs and related models the memory stores outer-product associations so that stored pairs can be retrieved by projection with the appropriate test vector. mLSTM adopts this associative-memory perspective: keys, values and queries become the primitives for memory updates and retrievals, with $\mathbf{C}_t$ acting as the accumulator of outer-product associations.

# Covariance update rule: $\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top$
The core update law for the mLSTM memory is a gated covariance (outer-product) accumulation. At time $t$ the matrix memory is updated by exponentially decaying the old memory and adding a scaled outer product of the current value and key:

\[
\mathbf{C}_t \;=\; f_t \, \mathbf{C}_{t-1} \;+\; i_t \, \mathbf{v}_t \, \mathbf{k}_t^\top .
\]

Here $i_t$ and $f_t$ are scalar gates at time $t$ (the input and forget gates). The additive term $i_t \, \mathbf{v}_t \mathbf{k}_t^\top$ stores the new association: the value vector $\mathbf{v}_t$ is associated with the key vector $\mathbf{k}_t$. The multiplicative factor $i_t$ controls the learning rate for this stored association. The multiplicative factor $f_t$ scales the previous memory, acting as a decay or retention factor that modulates how long prior associations persist in the matrix.

This covariance-style update is a familiar form: it appears in classical Hebbian-like learning rules, in Fast Weight Programmers, and in a range of recent linear-memory models. The outer-product update has the advantage that retrieval via $\mathbf{C}_t \mathbf{q}$ implements a linear combination of past values weighted by the alignment between their keys and the query, which realizes associative recall in a compact, algebraic form.

# Gate semantics: decay (forget), learning rate (input), output scaling
The three gating signals in mLSTM retain the LSTM semantics but take on roles adapted to matrix memory:

- Forget gate $f_t$. This gate multiplicatively decays the accumulated matrix memory. It implements retention or decay of previously stored associations. If $f_t$ is close to 1, prior outer products remain; if $f_t$ is small, they are rapidly reduced. In the mLSTM interpretation $f_t$ acts like a per-time-step decay rate for the fast weights contained in $\mathbf{C}_{t-1}$.

- Input gate $i_t$. This gate multiplies the outer-product contribution $ \mathbf{v}_t \mathbf{k}_t^\top$ and therefore plays the role of a learning rate for the new association. Larger $i_t$ increases the influence of the current key–value pair on the memory.

- Output gate $\mathbf{o}_t$. Retrieval from the matrix yields a candidate hidden vector; the output gate modulates or scales that retrieved vector component-wise. Thus $\mathbf{o}_t$ controls how much of the retrieved information is exposed to downstream layers, analogous to the output gate in standard LSTMs.

Together these gates match the LSTM intuition—separate control over retaining old memory, writing new memory, and exposing memory content—while operating in the matrix-valued fast-weight regime.

# Normalizer vector $\mathbf{n}_t$ and denominator clamping for stability
When retrieving a vector by multiplication with the matrix memory, the mLSTM normalizes the retrieved signal to avoid scale collapse or explosion and to approximate a soft attention normalization. The model maintains a normalizer vector $\mathbf{n}_t \in \mathbb{R}^d$ that accumulates keys with the same gating dynamics:

\[
\mathbf{n}_t \;=\; f_t \, \mathbf{n}_{t-1} \;+\; i_t \, \mathbf{k}_t .
\]

Intuitively, $\mathbf{n}_t$ represents the cumulative, gate-weighted sum of past keys. When a query $\mathbf{q}_t$ is applied, the raw retrieved vector is $\mathbf{C}_t \mathbf{q}_t$, which is then normalized by the magnitude of the alignment between $\mathbf{n}_t$ and the query. Concretely, the candidate hidden state is computed as

\[
\tilde{\mathbf{h}}_t \;=\; \frac{\mathbf{C}_t \mathbf{q}_t}{\max\big\{\,|\mathbf{n}_t^\top \mathbf{q}_t|,\; 1\,\big\}} .
\]

This denominator is the absolute value of the dot product $\mathbf{n}_t^\top \mathbf{q}_t$, lower-bounded by $1$ to prevent division by small numbers. The absolute value and clamping stabilize retrieval when keys and queries are near-orthogonal or when the cumulative key energy is close to zero; the clamping ensures numerical stability and avoids inflating the retrieved vector when the normalizer alignment is tiny. The stabilizing floor of $1$ can be viewed as a conservative normalization that preserves scale in weak-alignment regimes.

# Layer-norm assumptions, key scaling ($1/\sqrt{d}$)
To make the covariance update behave well, mLSTM assumes a preprocessing that centers inputs: the paper states that a layer-normalization is applied before projecting inputs to keys and values, ensuring those vectors have (approximately) zero mean. Zero-mean keys and values make the covariance update more interpretable (as a centered covariance-like accumulator) and help avoid systematic bias in the stored outer products.

Additionally, the key projection in the mLSTM uses a $1/\sqrt{d}$ scaling:

\[
\mathbf{k}_t \;=\; \frac{1}{\sqrt{d}} \mathbf{W}_k \, \mathbf{x}_t + \mathbf{b}_k .
\]

This scaling aligns with common attention practice and keeps the magnitude of dot products on the order of one as dimensionality $d$ grows. Together with layer-normalization, the $1/\sqrt{d}$ factor produces keys of controlled norm and facilitates stable retrieval and normalization via $\mathbf{n}_t^\top \mathbf{q}_t$.

# Multiple cells vs. heads equivalence (no mixing)
Unlike the vector-valued LSTM where multiple scalar cells can be coupled via recurrent (hidden–hidden) mixing matrices, mLSTM intentionally abandons memory mixing: the matrix memory update and retrieval are applied separately to each memory cell or head without recurrent mixing across cells. Because of this lack of cross-cell recurrent connections, multiple heads and multiple matrix cells are equivalent in mLSTM. That is, partitioning the matrix memory into several independent matrix "cells" or running several parallel heads yields the same representational structure as a single block with expanded width but no recurrent cross-talk.

This design point has two consequences. First, the absence of hidden–hidden mixing simplifies the recurrence and prevents sequential dependence through recurrent weight matrices, which is key for parallelizability. Second, it means that all cross-memory interaction must come either via the input/output projections or via explicit architectural composition (stacking blocks), not via hidden–hidden recurrence inside the matrix memory itself.

# Parallel formulation of the recurrence (scan/Flash-like)
Because the mLSTM update is a linear, multiplicative decay followed by an outer-product addition, and because there are no hidden–hidden recurrent matrices mixing states across cells, the recurrence can be rewritten in a form amenable to parallel computation across time. The paper notes that mLSTM can be reformulated as a parallel version (detailed in the appendix), analogous in spirit to parallelized fast-weight or attention implementations such as FlashAttention.

Concretely, if the forget and input gates are known for all time steps (or can be computed as functions of inputs without dependence on prior hidden states), then the accumulation

\[
\mathbf{C}_t \;=\; \sum_{s\le t} \left( \prod_{u=s+1}^t f_u \right) i_s \, \mathbf{v}_s \mathbf{k}_s^\top
\]

expresses the matrix memory as a weighted prefix sum of outer products where each outer product is scaled by the product of subsequent forget gates. This prefix-sum structure (a scan) can be implemented with parallel-scan algorithms or with Flash-like blocked algorithms that group sequence positions and compute partial accumulators efficiently on GPUs. As a result, training and inference for mLSTM can be implemented in a parallel fashion whose wall-clock performance is competitive when suitably optimized, even though the naive recurrence is sequential. This parallelizability is an important distinction to recurrent LSTMs with hidden–hidden mixing, which intrinsically require sequential processing.

# Relation to Fast Weight Programmers and Retention
The mLSTM covariance update directly connects to several strands of prior work on fast weights, outer-product memories, and linear attention. In the Fast Weight Programmer literature, networks learn to write outer-product updates to a fast-weight memory that is later read out by multiplication with a query; mLSTM realizes the same mathematical mechanism where the input gate acts as a learned write rate and the forget gate acts as decay. The paper explicitly cites Fast Weight Programmers and recognizes the equivalence between the covariance update and fast-weight accumulation.

mLSTM is also related to recent linear-memory models such as Retention and linearized attention mechanisms. These models use forms of associative accumulation or weighted outer-product updates to attain linear complexity in context length while preserving associative recall capabilities. The difference is that mLSTM packages the outer-product update into an LSTM-like gated framework with explicit input/forget/output gates and the normalizer $\mathbf{n}_t$, combining the stability and gating of LSTMs with the capacity advantages of matrix memories.

By integrating these ideas, mLSTM combines desirable properties: enhanced memory capacity from matrix outer-product storage, explicit and interpretable gating semantics inherited from LSTMs, normalization for stable retrieval, and a structure that admits parallel implementations akin to modern fast-attention kernels. The result is a matrix-memory xLSTM variant that increases storage capacity while remaining implementable efficiently and compatible with the residual-stacked xLSTM architecture.

Computation, Memory, and Parallelization

# Complexity vs. sequence length: linear compute, constant memory

One of the central computational advantages emphasized for xLSTM in the paper is its behavior with respect to the sequence length. Both sLSTM and mLSTM operate in a recurrent (or recurrence-derived parallel) fashion such that the amount of work and the working memory that depend on sequence length grow only linearly for compute and remain constant for model memory use. Concretely, for a sequence of length $T$, the number of elementary update steps is proportional to $T$: each time step performs a fixed set of operations (gate computations, projections, and a memory update and/or retrieval), so the total arithmetic work is $O(T \cdot W)$ where $W$ denotes the per-step work proportional to layer width and any internal matrix sizes. This linearity in $T$ contrasts with full dense self-attention in standard Transformers, whose naive implementation incurs $O(T^2)$ compute and $O(T^2)$ intermediate memory for attention scores.

The "constant memory" claim refers to the fact that model-internal state that must be kept across the time dimension (for generation or streaming) does not grow with $T$. For both xLSTM variants, the cell state is a fixed-size object independent of how many time steps have been processed: a scalar (or vector of scalars) per cell for sLSTM, or a matrix $\mathbf{C}\in\mathbb{R}^{d\times d}$ (and associated normalizer state) for mLSTM. Thus the active working memory required to continue generation online or to maintain the model state for future inputs is a constant size per layer, not a cache of all past token keys and values. This allows xLSTM models to process arbitrarily long sequences without the memory blow-up encountered when storing keys and values for every past token as done in vanilla Transformer decoding without compression.

This compute and memory profile makes xLSTM particularly well-suited for streaming and long-context scenarios and explains why the paper highlights xLSTM's linear computation and constant memory complexity in the sequence length. It is important to note that linear compute does not imply small absolute latency or low wall-clock time — the per-token work $W$ and operator types (e.g., matrix--matrix products) determine runtime — but it guarantees scalability in contexts where $T$ grows very large.

# mLSTM compute cost: d×d updates and retrievals, no parameter cost

mLSTM augments the scalar LSTM memory by replacing the scalar cell with a matrix memory $\mathbf{C}_t\in\mathbb{R}^{d\times d}$. The update rule adopted is a covariance (outer-product) style update:
\[
\mathbf{C}_t \;=\; f_t \, \mathbf{C}_{t-1} \;+\; i_t \, \mathbf{v}_t \, \mathbf{k}_t^\top,
\]
where $\mathbf{k}_t,\mathbf{v}_t,\mathbf{q}_t\in\mathbb{R}^d$ are key, value, and query vectors and the hidden output is computed via a matrix--vector product and normalization:
\[
\tilde{\mathbf{h}}_t \;=\; \frac{\mathbf{C}_t \mathbf{q}_t}{\max\{|\mathbf{n}_t^\top \mathbf{q}_t|,1\}},
\qquad
\mathbf{h}_t \;=\; \mathbf{o}_t \odot \tilde{\mathbf{h}}_t,
\]
with $\mathbf{n}_t$ the normalizer state updated analogously to $\mathbf{C}_t$.

These formulas make the computational cost per time step explicit: the rank-one outer-product update $i_t \, \mathbf{v}_t \, \mathbf{k}_t^\top$ is a $d\times d$ matrix that must be added to the scaled previous memory $f_t \mathbf{C}_{t-1}$. The retrieval step requires multiplying the stored matrix $\mathbf{C}_t$ by the query vector $\mathbf{q}_t$, i.e., a $d\times d$ times $d$ vector product. Therefore, per time step the dominant arithmetic costs scale as $O(d^2)$ for both the update and the retrieval. Unlike a parameter matrix multiplication, these costs come from manipulating the content of the memory rather than learned weight parameters — the memory matrices themselves are not parameters tuned by optimization; they are ephemeral state that accumulates information from the sequence. Hence the paper emphasizes that the matrix memory imposes computation costs (quadratic in $d$) but not parameter costs.

The quadratic-in-$d$ cost is the trade-off for substantially increased storage capacity relative to scalar cell states. The covariance update can store pairwise (outer-product) associations between key and value components, enabling retrieval via inner products with queries. This expanded capacity is what allows mLSTM blocks to improve performance on rare-token prediction and associative-recall-type tasks. Practitioners must therefore balance desired memory capacity (larger $d$) against the $O(d^2)$ compute per step.

# GPU parallelism: why wall clock overhead can be modest

Although mLSTM's arithmetic complexity per time step is $O(d^2)$, there are reasons the wall-clock overhead can be moderate in practice. First, the expensive operations (rank-one outer product formation, scaled matrix addition, and matrix--vector multiply) are regular linear-algebraic operations that map well to GPU hardware: they can be implemented as batched matrix--matrix and matrix--vector kernels and thus exploit the high throughput of modern GPUs. In particular, the rank-one update can be implemented efficiently by expanding $\mathbf{v}_t$ and $\mathbf{k}_t$ into outer-product kernels or by using optimized level-3 BLAS routines when accumulating updates across heads or minibatch elements. The matrix--vector retrieval $\mathbf{C}_t \mathbf{q}_t$ is also a standard high arithmetic-intensity operation.

Second, because the memory is not tied to sequence length, mLSTM allows computation to be organized so that many tensor operations across the batch and heads execute in parallel. Where possible, multiple heads, minibatch items, and multiple memory cells can be batched into larger GEMM calls to improve hardware utilization. The paper explicitly notes that such computations "can be done in parallel on GPUs," and therefore despite $d\times d$ operations the wall clock time overhead compared to other architectures is relatively small.

Finally, mLSTM's parallel reformulation removes sequential hidden–hidden mixing (see below), enabling efficient parallel kernels similar in spirit to parallelized attention implementations. This makes mLSTM comparable to other linear-time attention-like methods that are amenable to high-throughput GPU execution, and the paper reports that mLSTM's parallelizable operations result in modest wall-clock overhead in practice.

# sLSTM non-parallelizability due to memory mixing

sLSTM retains memory-mixing through recurrent hidden–hidden connections: gates and cell inputs depend on the previous hidden state $h_{t-1}$ via recurrent weight matrices (or vectors in the scalar case). This creates a sequential dependency across time steps that precludes a straightforward parallel reformulation analogous to mLSTM. Concretely, when gate pre-activations and the new cell input $\tilde{z}_t$ are functions of $h_{t-1}$, each time step must be evaluated in order because $h_{t-1}$ is produced only after finishing the previous step. That sequential dependency is exactly what prevents batching the entire sequence into a single giant matrix multiplication that replaces per-step recurrence.

This inability to parallelize over time is a classical limitation of RNN-like models, and sLSTM inherits it because its design intentionally preserves memory mixing to enable state-tracking behaviors that rely on interactions between memory cells across time. The paper motivates this design choice: memory mixing enables the sLSTM to perform tasks that require revising stored decisions and tracking complex internal state (for example, certain formal-language state-tracking tasks). The trade-off is that sLSTM cannot leverage the same large-scale time-parallel kernels that are available for fully parallelizable blocks.

# CUDA implementation notes: sLSTM kernels and mLSTM optimization gap

Given that sLSTM is inherently sequential across time due to memory mixing, the authors implemented a specialized CUDA kernel for it to mitigate the sequential performance penalty. The paper reports a fast CUDA implementation for sLSTM with "GPU memory optimizations to the register level" that makes sLSTM typically less than two times slower than mLSTM in practice. This indicates that well-engineered low-level kernels can substantially reduce the overhead of sequential recurrence by maximizing per-step efficiency: minimizing global memory traffic, exploiting registers and shared memory, fusing elementwise operations (gate computations, normalization, stabilizers), and reducing kernel launch overheads. Those engineering efforts partially compensate for the lack of time parallelism.

On the other hand, the authors note that the mLSTM CUDA kernels are not yet fully optimized. The current mLSTM implementation is about four times slower than highly optimized attention implementations such as FlashAttention or the sequence-scan used in Mamba. There is thus an optimization gap: while mLSTM is parallelizable and its operations are conceptually well-suited for GPUs, absence of equivalent low-level optimizations (e.g., fused $d\times d$ update kernels, memory layout tuning, and kernel fusion across updates and retrievals) increases runtime in the present implementation. The authors suggest that further optimization — in the spirit of FlashAttention — could significantly shrink this gap, and their results indicate that even the current, not-yet-fully-optimized mLSTM has acceptable wall-clock performance because GPUs parallelize the $d^2$ work efficiently.

These remarks highlight two practical realities: (1) algorithmic complexity gives an upper bound on work, but real runtime depends heavily on kernel quality and hardware utilization; (2) recurrent but memory-mixing models can partly close the runtime gap through hand-tuned sequential kernels, while parallelizable matrix-memory models benefit most from investing in fused, high-throughput GPU kernels.

# Throughput implications vs. Transformers with KV cache

Transformer decoders used for autoregressive generation typically store keys and values for every context position in a KV cache, so that each subsequent token generation can reuse those cached key and value matrices rather than recomputing attention against the entire prefix. While this cache avoids redoing the forward pass over past tokens, it still grows in memory as $O(T)$ (and attention with cached keys/values still requires $O(T)$ memory accesses per new token for the attention score computations unless special approximations are used). This leads to practical limits on batch sizes and possible throughput bottlenecks: larger prefill (longer context) reduces available memory for batching and lowers the maximal throughput achievable during decoding.

Because xLSTM maintains a fixed-size internal state (scalar/vector per cell for sLSTM or $d\times d$ matrix for mLSTM) independent of $T$, it avoids the linear memory blow-up of stored per-token keys/values. The paper demonstrates that this has strong throughput implications. In the experiments reported, xLSTM (and other recurrent models like Mamba and RWKV) show linear scaling of generation time with context length as opposed to the quadratic or cache-limited behavior for Transformers. Moreover, the constant memory profile allows xLSTM to use much larger batch sizes during decoding: the paper's benchmarking found that xLSTM achieves higher maximal throughput than Llama because it can scale batch sizes without hitting KV-cache memory limits.

This advantage is most pronounced when the Transformer decoder must keep a large KV cache for long prefill lengths: the KV cache consumes memory proportional to both sequence length and model width, constraining batch sizes and thus throughput. In contrast, xLSTM's constant-state approach means that even with long precursors (large prefill), it can maintain high batch sizes and therefore deliver higher tokens-per-second throughput in many settings. The paper reports that xLSTM achieves the highest throughput among compared models in their decoding throughput experiments, underlining that algorithmic linearity and constant memory translate into practical throughput gains.

Finally, it is worth noting the generation-time trade-offs: while Transformers can be optimized with fused KV cache access and attention kernels (e.g., FlashAttention) to be extremely fast per token for moderately sized contexts, their memory scaling limits ultimate batch sizes and memory-constrained throughput. Conversely, xLSTM’s per-step $O(d^2)$ cost (for mLSTM) or sequential overhead (for sLSTM) can make its per-token latency larger at small contexts and without specific kernel optimizations, but its throughput remains more robust as context length increases and at large batch sizes. The net effect — as demonstrated in the paper — is that xLSTM attains competitive or superior throughput in many practical decoding regimes, especially when large contexts or large batch sizes are necessary.

xLSTM Blocks and Architectures

# Goal: nonlinear summarization in high-dim spaces (Cover’s theorem)

A central objective when designing a block for a sequence model is to produce a compact representation of the entire past (the history up to the current time step) that is useful for predicting the next token or sequence element. xLSTM blocks follow the same philosophy that underlies most contemporary large sequence models: rather than trying to linearly operate on raw inputs, first non-linearly summarize the history in a suitably chosen representation space where different histories are more easily separated. The motivation for this is rooted in Cover’s theorem: patterns that are not linearly separable in a low-dimensional input space are more likely to become linearly separable after a non-linear embedding into a sufficiently high-dimensional space. For language modeling, this separation corresponds to producing representations that allow a simple linear decoder (or next-layer linear transformation) to discriminate between plausible continuations.

xLSTM implements this idea by placing an LSTM-derived memory module (either sLSTM or mLSTM) inside a residual block that transforms inputs through linear projections and non-linearities around the memory operation. The block architecture therefore has three roles: (1) provide the memory cell with an appropriately preprocessed input (queries, keys, values, gates), (2) let the memory non-linearly summarize the past in the memory state over time, and (3) project the memory output back into the residual stream so that it can be combined with other blocks. How and where in the block the up-projection (the expansion into a higher dimensional space) is placed affects the memory capacity and the character of the summarization; this is the basis for the pre- vs post-up-projection design choices discussed next.

# Post up-projection block (Transformer-like) for sLSTM

The post up-projection block is the variant that first computes a non-linear summary in the block's native (residual) dimensionality and only subsequently projects into a higher dimensional space before applying an activation and projecting back. This design mirrors the common Transformer feed-forward style where the non-linearity resides between an up-projection and a down-projection, but realized here in a residual block that contains sLSTM as its core memory.

For sLSTM, the post up-projection choice is motivated by two interrelated properties of sLSTM described in the paper. First, sLSTM retains the scalar (per-cell) memory structure similar to original LSTM cells, augmented by exponential gating and the associated normalizer and stabilizer states. Second, sLSTM supports memory mixing through recurrent (hidden–hidden) connections across its multiple scalar cells. Memory mixing benefits from operating in the residual-dimension space where states and recurrent connections are naturally expressed as hidden vectors. By placing the non-linear summarization in the original residual dimension and then applying an up-projection, the block allows the sLSTM recurrence and gating to act on representations that align with the residual stream and the hidden-state wiring used for memory mixing.

Operationally, a post up-projection xLSTM block with sLSTM behaves as follows: the input residual vector is first processed by input-weight matrices and the sLSTM recurrence to compute cell inputs \(z_t\), gates \(i_t,f_t,o_t\), and updated scalar cells \(c_t\) (with their normalizer \(n_t\) and stabilizer \(m_t\) where exponential gating is used). The sLSTM computes the hidden output \(h_t = o_t \cdot (c_t / n_t)\). After this non-linear recurrent processing in residual dimension, a linear up-projection maps the result into a higher dimensional space; a non-linear activation may be applied there; finally a down-projection maps back into residual dimension and the result is added via the residual connection. This ordering preserves the sLSTM’s natural hidden-state interactions and affords the non-linear separation advantage of an up-projection in the post-processing step.

# Pre up-projection block (SSM-like) for mLSTM to enlarge memory space

In contrast, the mLSTM employs a matrix-valued memory \(\mathbf{C}_t \in \mathbb{R}^{d\times d}\) with a covariance (outer-product) update rule \(\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top\). Retrieval is effected by multiplying the memory matrix with a query vector \(\mathbf{q}_t\), producing \(\tilde{\mathbf{h}}_t = \mathbf{C}_t \mathbf{q}_t / \max\{|\mathbf{n}_t^\top \mathbf{q}_t|, 1\}\) (gated and normalized as in the mLSTM forward pass). Because the memory is matrix-valued and retrieval operates through matrix–vector products, the effective capacity of mLSTM scales with the internal representational dimension \(d\). To maximize memory capacity per block, mLSTM benefits from having this memory live in a higher dimensional space.

Therefore, xLSTM blocks that contain mLSTM are designed with a pre up-projection: the input residual vector is first linearly mapped (up-projected) into a higher-dimensional space where the mLSTM keys \(\mathbf{k}_t\), values \(\mathbf{v}_t\), and queries \(\mathbf{q}_t\) are computed. The covariance-update memory then operates entirely in that enlarged space, allowing the matrix memory \(\mathbf{C}_t\) to be larger and to store higher-capacity associations. After the mLSTM retrieval and gating yield \(\mathbf{h}_t\) in the high-dimensional space, a down-projection returns the output to the residual dimension where it is combined residually with the block input.

This pre up-projection design is analogous to state-space-model backbones (SSM-like) that first lift inputs into a feature space where the state update operates. For mLSTM, the up-projection is not an incidental extra cost: it directly enlarges the memory matrices and therefore the block’s storing and retrieval capacity. Practically, the block computes \(\mathbf{q}_t,\mathbf{k}_t,\mathbf{v}_t\) via linear projections of the up-projected features (with the scaling \(1/\sqrt{d}\) on keys as in the mLSTM formulation), applies the matrix-memory update and retrieval described in the forward pass, normalizes by the normalizer state \(\mathbf{n}_t\), and uses the output gate \(\mathbf{o}_t\) to scale the retrieved vector before down-projecting.

# Pre-LayerNorm residual backbones

xLSTM architectures are constructed by residually stacking xLSTM blocks. The backbone chosen throughout the experiments follows the now-standard pre-LayerNorm residual design: before the core block computation (whether that core is an sLSTM recurrence in a post up-projection block or an mLSTM covariance memory in a pre up-projection block), a Layer Normalization is applied to the incoming residual stream. The normalized vector then goes through the block’s linear projections, the memory operation and nonlinearities, and finally the transformed vector is projected back and added to the original residual stream.

Pre-LayerNorm has proven to be a stable choice for deep residually stacked architectures, and xLSTM adopts it to obtain the benefits: (1) numerically stable gradient flow in deep stacks, (2) consistent normalization for the gates and projections that feed the memory modules, and (3) compatibility with large-scale training recipes used for other modern LLM backbones. Using pre-LayerNorm also standardizes where the up-projections (pre or post) are inserted relative to normalization, simplifying implementation and empirical comparisons.

# Stacking strategy: xLSTM[a:b] ratios of mLSTM to sLSTM blocks

An important architectural decision when building a full xLSTM model is how many blocks should use mLSTM versus sLSTM. The paper uses the notation xLSTM[a:b] to denote the ratio \(a/b\) of mLSTM-based to sLSTM-based blocks in a total block count. Concretely, xLSTM[7:1] indicates that for every eight blocks, seven are mLSTM blocks and one is an sLSTM block. For a typical total block count of 48, xLSTM[7:1] therefore includes 42 mLSTM blocks and 6 sLSTM blocks.

This ratio-based stacking strategy trades off the complementary strengths of the two memory modalities. mLSTM blocks provide large matrix memory capacity and are fully parallelizable (no recurrent hidden–hidden mixing), making them suitable for storing many key–value associations and for benefiting from pre up-projection expansion. sLSTM blocks reintroduce scalar-cell memory with exponential gating and memory mixing via recurrent hidden–hidden connections. Memory mixing is crucial for state tracking and tasks that require revising stored decisions. Thus a hybrid stack leverages mLSTM’s capacity and parallelism while retaining sLSTM’s expressiveness for problems that need recurrent memory mixing.

Empirically, different ratios have been evaluated (for example xLSTM[1:0] meaning all mLSTM, or xLSTM[0:1] meaning all sLSTM), and hybrid mixtures such as xLSTM[7:1] were shown to be effective across language modeling tasks. Choosing a ratio is a design knob: more mLSTM blocks favor memory capacity and parallelism; more sLSTM blocks favor memory-mixing expressiveness but reduce parallelizability.

# Design heuristics and component interactions

Designing an xLSTM architecture requires several interacting considerations. The following heuristics, grounded in the behaviors described in the paper, guide practical choices.

1) Match block type to memory role. Use pre up-projection (enlarge feature dimension before the memory operation) whenever the memory cell benefits from greater internal dimension — this is the mLSTM case. Conversely, use post up-projection when the recurrence and hidden–hidden mixing are the primary mechanism (the sLSTM case), so the recurrent dynamics operate in the residual dimension and the up-projection provides additional nonlinearity after the recurrence.

2) Control gating behavior with exponential gating and stabilization. Both sLSTM and mLSTM rely on exponential activation for the input gate (and optionally the forget gate) to enable revisable storage and stronger multiplicative control. Exponential gates can grow very large; therefore each design must include stabilizers (the scalar state \(m_t\) that rescales gate exponentials without changing the effective dynamics). Additionally, both memory types maintain a normalizer state (scalar \(n_t\) in sLSTM, vector \(\mathbf{n}_t\) in mLSTM) that tracks cumulative gate strength and is used to normalize retrieved values. These interacting states (gate outputs, normalizer, stabilizer) must be computed consistently in the block and must be initialized and biased carefully to avoid numerical issues (the paper notes careful choice of forget gate initialization).

3) Balance parallelism and expressive recurrence. mLSTM blocks are fully parallelizable because they omit hidden–hidden recurrent connections (no memory mixing across time via the hidden state). This allows efficient GPU-parallel training that resembles linear-attention or SSM methods and supports a parallel reformulation. sLSTM blocks include hidden–hidden recurrent connections enabling memory mixing and state tracking but are inherently sequential. Hybrid stacks should therefore place sLSTM blocks sparingly when high throughput is required, or rely on optimized CUDA kernels for sLSTM if more sLSTM capacity is desired.

4) Choose head and cell counts to modulate memory mixing. sLSTM can be instantiated with multiple scalar memory cells and multiple heads; memory mixing occurs within heads but not across heads, providing a controlled way to mix and separate information. For mLSTM, multiple heads and multiple cells are equivalent since there is no hidden mixing; therefore the effective memory dimension is adjusted by the projection sizes and the up-projection dimensionality. Thus, when designing blocks, the number of heads and cell partitions is a hyperparameter for modulating the granularity of memory interactions.

5) Use residual stacking with pre-LayerNorm for stability at scale. As in modern LLM backbones, stacking many blocks requires stable normalization and residual pathways so gradients can flow. By placing a LayerNorm before each block and adding the block output residually to the input, deep stacks of xLSTM blocks become trainable and comparable to Transformer stacks in terms of architecture.

6) Trade off computational cost versus memory capacity. The mLSTM matrix memory \(\mathbf{C}_t\) has computational complexity that scales with \(d^2\) due to the matrix update and matrix–vector retrieval, even though it does not introduce additional parameters. Designers must weigh the benefit of richer associative memory against this cost. Because these operations are parallelizable (matrix multiplications), implementations can be optimized on GPUs; nonetheless, wall-clock performance and energy use are practical constraints that influence the number and size of mLSTM blocks in a stack.

7) Arrange block ratios according to task requirements and scaling trajectory. For language modeling at large scale, experiments in the paper found that xLSTM architectures with many mLSTM blocks and a small fraction of sLSTM blocks (e.g., xLSTM[7:1]) perform favorably, combining mLSTM’s capacity with sLSTM’s state-tracking. When memory mixing or revisability is crucial (formal languages, stateful tasks), include more sLSTM blocks or even pure sLSTM stacks. When huge associative capacity and parallelizability are prioritized (large-context storage, many domains), increase the proportion of mLSTM blocks.

8) Interact carefully with training recipes and precision. Since exponential gating can produce values that are large in magnitude, mixed-precision training and correct use of stabilizers are part of the architectural design. The block design must therefore expose or hide stabilizer states and normalizers in a way compatible with the chosen training precision and optimizer settings.

In summary, xLSTM blocks consist of two complementary block-level designs: post up-projection blocks embedding sLSTM recurrence suited for memory mixing and state tracking, and pre up-projection blocks embedding mLSTM matrix memory for high-capacity associative storage. These blocks are stacked in pre-LayerNorm residual backbones using the xLSTM[a:b] ratio notation to form full models that balance capacity, expressiveness, and parallelism according to task and resource constraints. The interactions between exponential gating, normalizers, stabilizers, and projection placements are central to achieving stable and effective summarization of histories in high-dimensional spaces, thereby realizing the promise described by Cover’s theorem within an LSTM-derived architecture.

Positioning xLSTM in the Landscape

# Linear attention variants: Synthesizer, Linformer, Linear Transformer, Performer, SGConv, Hyena
Linear-attention and related methods arise from a shared motivation: the quadratic dependence of standard Transformer attention on context length makes very long-context modeling expensive. The paper situates xLSTM in a landscape where many approaches have attempted to replace or approximate full softmax attention with alternatives that scale linearly in sequence length. These methods differ in what they trade off—exactness of token–token interactions, representational richness, or computational form—but they share the objective of making long-context computation tractable.

Synthesizer removes the explicit token–token interaction by learning synthetic attention weights; it thus sidesteps quadratic pairwise computation at the cost of foregoing direct content-based attention. Linformer replaces attention with a low-rank factorization, approximating the attention matrix to reduce complexity. Linear Transformer and similar linearization approaches directly rewrite the attention computation so that the softmax-form attention can be evaluated with kernels that allow linear-time accumulation across the sequence. Performer uses positive random-feature approximations to the softmax kernel, again enabling linear-time approximation of attention. SGConv and Hyena take a different route: they replace attention by convolutional operators or structured long convolutional filters, providing fast alternatives that aim to capture long-range dependencies through carefully designed filtering.

Within the paper’s framing, these linear attention variants are important points of comparison because xLSTM, like these methods, promises linear computation in the context length. However, the paper emphasizes that xLSTM approaches the linearity challenge from a recurrent-memory perspective (extended LSTM memories and gating) rather than by approximating the Transformer attention mechanism. Thus, xLSTM joins the family of models that target linear complexity but does so by reviving and extending recurrent-memory mechanisms rather than by modifying attention kernels.

# State Space Models: S4, DSS, GSS, S5, BiGS, H3, Mamba
State Space Models (SSMs) are another prominent family targeting long-range sequence modeling with linear complexity. The paper lists several SSM variants that have recently become popular: Structured State Space (S4), Diagonal State Space (DSS), Gated State Space (GSS), S5, Bidirectional Gated SSM (BiGS), H3, and Mamba. These models employ linear dynamical systems or carefully parameterized state-transition mechanisms to accumulate information from long contexts while keeping computation linear in sequence length.

The paper positions xLSTM relative to SSMs in two ways. First, both SSMs and xLSTM aim for linear computational scaling and are designed to handle long contexts efficiently. Second, the authors highlight a structural distinction: many SSMs do not implement memory mixing in the same way that recurrent models with hidden–hidden connections do. The paper argues that memory mixing—internal recurrent connections that allow the stored state to interact and be remixed over time—enables state-tracking behaviors that SSMs (and many attention-free linear models) struggle with. Consequently, while SSMs are strong competitors on long-context benchmarks and are reflected among the baselines in the experiments, xLSTM claims an advantage through its extended gating and memory structures that preserve or reintroduce memory-mixing capacity where beneficial.

# RNN revivals: LRUs, HGRN/HGRN2, RWKV
There has been renewed interest in recurrent architectures for large-scale language modeling. The paper lists several RNN-based or RNN-inspired architectures that have shown competitive performance: Deep Linear Recurrent Units (LRUs), Hierarchically Gated Linear RNNs (HGRN and HGRN2), and RWKV. These approaches attempt to reconcile recurrence with modern training and scaling techniques, sometimes by linearizing updates or adding gating structures inspired by LSTMs.

xLSTM is presented as part of this revivalary thread but with distinct engineering and algorithmic choices. Like LRUs, HGRN variants, and RWKV, xLSTM emphasizes linear complexity in context length and modern residual stacking. Where xLSTM differs is in (i) the introduction of exponential gating with normalization and stabilization, and (ii) the modified memory structures—scalar sLSTM and matrix mLSTM—that explicitly target the two limitations the authors ascribe to classic LSTMs: inability to revise storage decisions and limited scalar storage capacity. In experiments, xLSTM is compared directly to RWKV and HGRN-family models; the paper reports favorable performance for xLSTM in perplexity, extrapolation, and domain benchmarks, positioning it as a competitive member of the modern RNN family.

# Gating as a unifying theme across modern sequence models
One of the conceptual pivots of the paper is the observation that gating—originally central to LSTM design—has reappeared across a broad range of modern sequence models. The paper enumerates several contemporary methods that use gating mechanisms: HGRN, HGRN2, Gated Linear Attention (GLA), Gated State Space (GSS) models, Bidirectional Gated SSM (BiGS), MEGA, RWKV, and Mamba, among others. This trend suggests that selective control of information flow (i.e., gating) remains a powerful inductive bias for long-range sequence learning.

xLSTM leverages this insight directly. It extends gating in two ways. First, with exponential gating for input and optionally forget gates, xLSTM makes storing and erasing information multiplicative in an exponential sense, which the authors argue enables more decisive and revisable storage behavior. Second, xLSTM pairs gating with explicit normalizer states and stabilization mechanisms so that the numerical consequences of exponential gating are handled safely. The paper’s ablation studies attribute a substantial portion of xLSTM’s performance gains to these gating choices, reinforcing the view that gating is a unifying and practically important mechanism across modern sequence architectures.

# Covariance update ancestry: fast weights, Retention, RWKV-5/6
The paper traces the matrix-memory idea in mLSTM back to a long lineage of covariance-style updates and fast-weight mechanisms. The covariance update rule—adding an outer product of value and key vectors to a memory matrix—has roots in Bidirectional Associative Memories and early fast-weight ideas. The paper explicitly connects mLSTM’s matrix memory and covariance update to Fast Weight Programmers and later methods that apply a decay on past weights and a learning-rate-like scaling of new outer products.

More recent contemporary models also rely on similar updates or functional analogues. Retention and RWKV variants (including RWKV-5 and RWKV-6 mentioned in the paper) use mechanisms that can be interpreted as accumulating key–value statistics over time; Linear Transformer variants and HGRN2 also relate to these fast-weight/covariance ideas. In xLSTM, the authors adopt a covariance update for the matrix memory and align the forget gate with decay and the input gate with a learning-rate-like multiplier. They also include a normalizer state (a weighted sum of keys) so that retrieval is normalized and stable, with safeguards such as taking absolute values and lower-bounding the denominator, following precedents in retention-style methods.

# Most related to xLSTM: Retention, RWKV, HGRN2
The paper identifies Retention, RWKV, and HGRN2 as the models most closely related to xLSTM. Each shares some combination of gating, linear-time accumulation, or key–value style memory with xLSTM. However, the paper emphasizes contrasts that make xLSTM distinctive.

Retention, RWKV, and HGRN2 have in common a focus on linear complexity and on mechanisms that accumulate or gate information over long contexts. Yet, according to the paper, they differ from xLSTM in how they implement memory mixing and in the precise gating and memory update rules. In particular, the authors claim that the sLSTM variant of xLSTM permits memory mixing through recurrent hidden–hidden connections, enabling solutions to state-tracking problems that some of these other models cannot handle. The mLSTM variant shares with Retention and RWKV-like methods the covariance-style accumulation, but xLSTM integrates this update into an LSTM-style gated framework, including exponential input gating and a normalizer state, plus stabilization techniques to avoid numerical issues.

Empirically, the paper reports that xLSTM outperforms these closely related methods on several benchmarks in language modeling, sequence extrapolation, and associative-recall-style tasks, suggesting that the combination of exponential gating, matrix memory, and residual stacking yields practical advantages over the most related recent architectures.

# Expressivity and state tracking: why memory mixing matters
A core theoretical and empirical point in the paper is that memory mixing—the ability for internal stored states to be remixed via recurrent hidden–hidden interactions—is crucial for certain classes of sequence problems, particularly those requiring state tracking. The paper cites results and experiments showing that models lacking memory mixing (many Transformers and SSMs) cannot solve particular formal languages or state-tracking tasks that RNNs with recurrent mixing can handle.

Memory mixing allows previously stored information to be transformed and combined with newly arriving inputs and other stored components across time steps. This capacity is important for algorithms that require updating summaries of past events in a way that depends on both past memory contents and current inputs (for example, tracking counters, nested parentheses, or carrying the best-so-far match in nearest-neighbor-like tasks). The paper demonstrates experimentally that xLSTM variants with memory mixing (the sLSTM blocks) can solve formal language tasks and state-tracking problems that models without such recurrent mixing fail on. In contrast, mLSTM, by design, drops hidden–hidden mixing to achieve parallelizability; it compensates for lack of recurrent mixing with a higher-capacity matrix memory and parallel-friendly covariance updates.

Thus, the paper positions expressivity along a trade-off: memory mixing tends to increase expressive power for state-tracking tasks, while removing mixing enables parallelization and different scaling properties. xLSTM explores this trade-off by offering both sLSTM (with mixing and exponential gates) and mLSTM (matrix memory, parallelizable), and by permitting hybrid architectures (e.g., xLSTM[$a$:$b$] mixing ratios) so that practitioners can tune between expressivity and parallel speed.

# Concluding positioning remarks
The paper’s central claim is that by extending LSTM with exponential gating, stabilizers, a normalizer state, and a matrix memory update rule, xLSTM brings together the strengths of several recent trends: the linear-context efficiency of SSMs and linear attention variants; the gating-driven selective memory of modern gated models; and the higher-capacity associative storage of fast-weight/covariance updates. At the same time, xLSTM preserves, in its sLSTM variant, the classical LSTM advantage of memory mixing for state-tracking problems. Empirically, the authors report that xLSTM competes favorably with Transformers, SSMs, and recent RNN revivals on language modeling, extrapolation, and associative recall, thereby arguing for xLSTM’s place as a reconciliatory architecture that revives LSTM ideas while adopting the modern practices that enabled current Large Language Models.

Empirical Study I: Synthetic Tasks and Long Range Arena

# Formal languages suite and multi-length training for extrapolation

To probe the ability of xLSTM to perform state tracking and to extrapolate behavior across sequence lengths, the authors extend a suite of formal language tasks originally used by prior work. These formal languages are designed to require maintaining and updating discrete state over a sequence: examples include regular grammars and tasks whose solution requires remembering counts or parity information across inputs. Such tasks are well suited to reveal whether a model can revise stored information and maintain accurate state summaries as the sequence progresses.

A key methodological contribution in this evaluation is multi-length training for length extrapolation. Instead of training on a single fixed sequence length, the training regime exposes models to multiple sequence lengths so that we can observe not only within-distribution performance but also whether learned mechanisms generalize to longer unseen contexts. This is critical when assessing recurrent-memory architectures: some models may memorize solutions tied to a fixed horizon, while others implement compositional bookkeeping that scales to longer lengths.

In the experiments, the comparison set includes xLSTM variants (pure sLSTM (xLSTM[0:1]), pure mLSTM (xLSTM[1:0]), and a mixed xLSTM[1:1]) alongside a broad range of contemporary sequence models: Transformer-based models (e.g., Llama), State Space Models (e.g., Mamba), and other recurrent architectures including RWKV and standard LSTM (both standalone and embedded into residual Transformer-like blocks). All models are configured as compact 2-block architectures for this battery, focusing the comparison on representational capability rather than large-scale data-driven gains.

Accuracy is measured only on the tokens relevant to each formal task and is scaled so that 0 corresponds to random chance and 1 to perfect performance. This way of measuring zeroes in on the model's ability to track and act on the state that the task demands, eliminating confounding from unrelated tokens.

# Finding: sLSTM enables state tracking tasks (e.g., parity) beyond SSMs/Transformers

The formal language experiments demonstrate a qualitative difference in capability between architectures that permit memory mixing and those that do not. Models lacking memory mixing — such as many State Space Models (SSMs) and standard Transformers without recurrence — fail on certain state-tracking formal languages. A canonical example is parity: correctly deciding parity over a long input sequence requires the ability to revise a compact stored bit each time a relevant token arrives. The experiments show that models without memory mixing cannot reliably implement this kind of sequential state update.

In contrast, the sLSTM-containing xLSTM variants succeed at these tasks. The sLSTM brings two relevant properties: exponential gating and memory mixing via recurrent hidden–hidden connections. Exponential gating allows the sLSTM to implement revisable storage decisions — gating values affect storage multiplicatively in a way that can both amplify and attenuate past contributions, and the introduced stabilization and normalization states ensure numerical robustness. Memory mixing gives the model structured recurrent interactions across memory cells, enabling it to implement algorithmic state machines in which stored values are updated and transformed as new inputs arrive.

Empirically, xLSTM models with sLSTM blocks achieve high accuracy on the formal language tasks, including regular grammars and parity, while Transformer and SSM baselines remain at or near random performance on the same tasks. This supports the interpretation that sLSTM's combination of exponential gating and recurrent memory mixing is crucial for state-tracking problems that require revisability and fine-grained sequential updates.

# Associative Recall with up to 256 pairs and context 2048

To probe memory capacity under a demanding associative setting, the authors extend the Multi-Query Associative Recall task. In this task setting, a sequence presents many randomly sampled key–value pairs; later the model receives a query key and must output the previously associated value. The extension increases both the number of key–value pairs to recall (up to 256) and the sequence context length (up to 2048), making the task substantially harder than the original benchmarks and stressing whether a model's internal memory can store and retrieve a large collection of associations.

This task is particularly informative because it contrasts architectures that rely on compressed recurrent memory vs. those that employ wide, high-capacity token-to-token interactions. Transformers, which effectively implement high-dimensional pairwise interactions across tokens (attention), are strong in this setting and are treated as a gold standard: their memory scales exponentially with coding dimension under the associative recall formulation. The comparison set here includes Transformer baselines (e.g., Llama), SSMs (Mamba), recurrent models (RWKV variants), and xLSTM configurations.

The core design of mLSTM was motivated to address precisely this sort of associative storage: it replaces a scalar cell with a matrix memory \(\mathbf{C}_t \in \mathbb{R}^{d \times d}\) and uses a covariance-style update \(\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top\) so that a stored value \(\mathbf{v}_t\) can later be retrieved by multiplying \(\mathbf{C}\) with a query \(\mathbf{q}_{t+\tau}\). The normalizer \(\mathbf{n}_t\) tracks effective gate-weighted key mass to stabilize retrieval. These mechanisms explicitly instantiate associative memory in the recurrent framework.

# Finding: xLSTM[1:1] best among non-Transformers; sLSTM augments capacity

On the extended Multi-Query Associative Recall experiments, xLSTM variants exhibit strong performance. Among non-Transformer methods, xLSTM[1:1] (a mixture of mLSTM and sLSTM blocks) performs best across model sizes. This indicates that the mLSTM's matrix memory confers substantial associative capacity, and that augmenting that matrix memory with sLSTM blocks does not harm capacity — rather, the sLSTM appears to leverage and in some cases enhance retrieval performance.

Several observations drive the interpretation of these results. First, the mLSTM block, with its direct outer-product memory updates and matrix retrieval \(\tilde{\mathbf{h}}_t = \mathbf{C}_t \mathbf{q}_t / \max\{|\mathbf{n}_t^\top \mathbf{q}_t|, 1\}\), is structurally closer to associative memory algorithms (e.g., Fast Weight Programmers, covariance-based associative memories) than scalar-cell LSTMs. This structural match gives it an advantage in storing many distinct key–value pairs. Second, the inclusion of sLSTM blocks (as in xLSTM[1:1]) can provide complementary state-mixing and control: sLSTM's memory mixing enables transformations and gating strategies that help organize or route stored content, which seems to improve recall especially in harder regimes (e.g., 256 pairs).

Quantitatively, while Transformers remain the best overall on associative recall (consistent with attention's favorable scaling for associative storage), xLSTM[1:1] is the strongest non-Transformer model, outperforming other recurrent and SSM baselines like RWKV and Mamba. This suggests that the hybrid design — combining matrix memory for capacity with scalar recurrent mixing for control — is an effective tradeoff between capacity and algorithmic flexibility.

# Extrapolation of memory capacity to longer contexts

An important desideratum for memory mechanisms is the capacity to generalize retrieval behavior to longer contexts than those seen during training. The authors report extrapolation analyses for the associative recall experiments indicating that xLSTM's enhanced memory capacities permit extrapolation to longer contexts. That is, models trained on some context length are still able to retrieve the correct association when evaluated on sequences longer than those seen in training.

The ability to extrapolate stems from the principled, additive nature of the mLSTM memory update and the gating normalization. The covariance-style update \(\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top\) is compositional: contributions from earlier time steps are preserved (modulo decay via \(f_t\)) as linear terms in the memory matrix. The normalizer \(\mathbf{n}_t\) keeps a gate-weighted sum of keys, so retrieval scales based on aggregated gate mass and the dot product with the query. When gating dynamics are stable across sequence lengths, these algebraic properties permit the same retrieval algebra to apply at longer horizons.

Empirically, the authors note that xLSTM's extrapolation behavior is favorable: on associative tasks where difficulty or context length is increased beyond training regimes, xLSTM maintains reasonable recall performance compared to other non-Transformer models. This suggests the mechanisms used (matrix memory, exponential gating with stabilization, and normalization) are not merely overfit to a fixed horizon but implement operations that generalize.

# Long Range Arena results: consistent strong long-context performance

The Long Range Arena (LRA) suite is a mixed benchmark designed to stress different aspects of long-context processing, including retrieval, reasoning, and structural sensitivity across various input modalities. In the LRA experiments, xLSTM demonstrates uniformly strong performance across the gamut of tasks. This consistency indicates that xLSTM's architectural choices address multiple facets of long-range processing: robust state maintenance, high associative capacity, and stable computation over long sequences.

Two architectural elements contribute to this broad success. First, the mLSTM's matrix memory provides the capacity to represent diverse long-range associations. Second, the sLSTM's memory mixing enables the model to conditionally transform and route memory contents, which is crucial for control-flow-like tasks in LRA where the model must react differently depending on accumulated context. The exponential gating with normalization and stabilization helps ensure numerical stability across long horizons and allows revisability of stored information — a critical feature in many LRA tasks.

Compared to other models in the LRA, xLSTM's steady performance suggests that the hybrid recurrent-plus-matrix-memory paradigm is particularly well suited to long-context problems that require both capacity and algorithmic control.

# Takeaways: revisability, capacity, and sequence-length robustness

From the synthetic-task experiments and LRA evaluations, several central takeaways emerge about xLSTM's capabilities:

1. Revisability via exponential gating and memory mixing: The sLSTM extension — characterized by exponential input gates (stabilized and normalized) and recurrent memory mixing — enables the model to revise stored content effectively. This capability is essential for state-tracking problems such as parity and certain formal languages, where later inputs must overwrite or flip earlier stored bits.

2. Associative capacity via matrix memory: The mLSTM's \(d \times d\) matrix memory and covariance-style update allow xLSTM to store and retrieve many key–value associations. This design substantially improves performance on associative recall tasks (up to 256 pairs tested) and, when combined with sLSTM blocks, matches or surpasses other non-Transformer baselines in difficult memory regimes.

3. Robustness to sequence length and extrapolation: The compositional algebraic form of the mLSTM update and the stabilization/normalization mechanisms give xLSTM the structural properties needed to generalize retrieval to longer contexts than seen in training. Empirically, xLSTM maintains performance on longer sequences in both associative tasks and the LRA benchmark.

4. Complementary hybrid design: The combination of matrix and scalar memories — mLSTM for capacity and sLSTM for state-mixing and control — forms a complementary architecture. The mixed configuration (e.g., xLSTM[1:1]) leverages strengths from both elements, yielding the best performance among non-Transformer models on associative tasks and consistently strong performance on LRA.

Collectively, these results argue that xLSTM's architectural changes address three core limitations of the classical LSTM: they enable revisable storage decisions, increase storage capacity beyond scalar cells, and — in the mLSTM variant — permit parallelization by avoiding hidden–hidden memory mixing. The synthetic experiments thus establish the mechanistic reasons xLSTM can succeed on long-range and associative tasks where many competing architectures struggle.

Empirical Study II: 15B-Token Language Modeling and Ablations

# Setup: SlimPajama 15B tokens, GPT-3-scale 350M parameter match
This study compares xLSTM against a broad collection of contemporary sequence models in a tightly controlled setting. All models are trained autoregressively on the same training corpus consisting of 15 billion tokens from the SlimPajama dataset. The training regime and data are the same across methods so that differences in performance reflect architectural and algorithmic effects rather than data or training schedule mismatches.

Model sizes in this comparison are matched to a GPT-3-like reference configuration of roughly 350M parameters. Concretely, this corresponds to an embedding dimension of 1024 with 24 residual blocks for the residual-stack architectures; parameterization details are chosen to make the models comparable in total parameter count. The xLSTM variants evaluated include pure mLSTM blocks, pure sLSTM blocks, and mixed compositions expressed with the notation xLSTM[a:b], where the ratio $a\!:\!b$ denotes the number of mLSTM-based versus sLSTM-based xLSTM blocks within a total block count (for example xLSTM[7:1] means 7 mLSTM blocks and 1 sLSTM block out of 8 blocks, and with 48 blocks in total this corresponds to 42 mLSTM blocks and 6 sLSTM blocks). For the experiments reported here, pre- and post-up-projection residual backbones are assigned consistently: mLSTM uses pre up-projection blocks while sLSTM uses post up-projection blocks, as this pairing aligns the memory capacity and representational objectives of each memory type with a suitable projection ordering.

All methods are trained with mixed precision. Some methods required custom handling for mixed precision during training (the paper notes RWKV-5, RWKV-6, and GLA did not use PyTorch automated mixed precision in these runs). Otherwise the same evaluation metric—validation-set perplexity for next-token prediction—is computed for all models.

# Baselines: Transformers (GPT-3, Llama), SSMs (H3, Mamba), RNNs/linear (RWKV, GLA, HGRN/HGRN2, RetNet, Hyena)
The comparison set spans three broad families of approaches that are currently used for language modeling:

- Transformers: Standard autoregressive Transformer-style models exemplified by GPT-3 and the Llama family. These use self-attention blocks in residual stacks and have quadratic attention complexity in context length.

- State Space Models (SSMs): Architectures built on linear state-space layers and variants that achieve linear complexity in context length. Representative methods in the comparison include H3 and Mamba.

- Recurrent or linearized methods and linear Transformers: This category includes approaches that rely on recurrence or linearized attention mechanisms to obtain linear time/space scaling with context length. Examples compared are RWKV variants (RWKV-4, RWKV-5, RWKV-6), Gated Linear Attention (GLA), HGRN and HGRN2, RetNet, and Hyena.

These baselines were trained in the same 15B-token regime with comparable model sizes (near 350M parameters), enabling direct comparison of validation perplexity and of architectural ablations.

# Main result: xLSTM achieves best validation perplexity
Under the matched 15B-token training condition at roughly GPT-3 scale, xLSTM outperforms all compared methods on validation-set perplexity. The paper reports that across the suite of Transformers, SSMs, and RNN/linear methods, xLSTM models (in particular configurations mixing mLSTM and sLSTM blocks such as xLSTM[7:1] and xLSTM[1:0]) achieved the lowest perplexity on the validation split of SlimPajama.

This main result demonstrates that the proposed extensions to LSTM—the exponential gating mechanism, the normalizer/stabilizer constructs, and the matrix memory for mLSTM—combine effectively when embedded in modern residual backbones. Even when matched for parameter count with established Transformer and SSM baselines, the xLSTM architecture attains stronger next-token predictive performance. The result suggests that the classic LSTM ideas, when appropriately modernized and scaled, can compete with and in this setup exceed the performance of more recently dominant architectures.

# Scaling behavior at this scale indicates favorable trends
Alongside the single-size comparison, the study examined scaling behavior at this token budget and model-size regime. The scaling curves plotted for the 15B-token experiments show that xLSTM models follow favorable scaling trends relative to the baselines: when model size is varied (while matching parameter budgets across methods), xLSTM maintains a performance lead in perplexity with a scaling slope comparable to competitive baselines. In other words, the performance gap is not an artifact of a single size choice but persists across sizes in this experimental regime.

The implication is that the architectural changes introduced in xLSTM provide both an offset advantage (better absolute performance at fixed size) and scaling properties that make xLSTM likely to remain competitive as models scale up beyond this regime. The paper presents this as evidence that scaled-up xLSTM variants should remain serious competitors to Transformers and SSMs at larger parameter regimes.

# Ablation path: vanilla LSTM → residual backbone → post up-projection → exponential gates → matrix memory
To understand which changes drive the improvement from a vanilla LSTM to xLSTM, the authors perform a stepwise morphological ablation in which a standard LSTM architecture is progressively transformed into the full xLSTM architecture. The ablation path follows these steps:

1. Integrate vanilla LSTM layers into a modern pre-LayerNorm residual backbone. This isolates the effect of embedding the recurrence inside a contemporary residual-stack architecture commonly used in LLMs.

2. Convert the residual block into the post up-projection variant for sLSTM (and equivalently consider pre up-projection for mLSTM where applicable). The up-projection ordering affects where the non-linearity and high-dimensional summarization happen relative to the recurrent memory operation; the post up-projection design summarizes the past in the original space then projects up to high-dimensional space, applies non-linearity, and projects back—this choice was made for sLSTM blocks.

3. Introduce exponential gating (replacing sigmoid gating for certain gates with exponential activations and adding stabilizer and normalizer states). Exponential gates change the dynamics of storage and forgetting, enabling the memory to be updated multiplicatively in a way that facilitates revising stored content (one of the original LSTM limitations targeted by the paper).

4. Replace scalar cell state(s) with the matrix memory of mLSTM for the configurations that use it. The matrix memory uses a covariance (outer-product) update rule to store key-value pairs and retrieve values via matrix-vector products. This change increases per-step storage capacity and retrieval expressiveness.

At each stage of the morphing process the study measures validation perplexity. The ablation results reported in the paper indicate that moving LSTM into the residual backbone yields some benefit, the post up-projection block adds further improvement, but the largest gains arise from introducing exponential gating and from adopting the matrix memory. Thus, both exponential gating and matrix memory contribute substantially and complementarily to the final performance.

# Gate ablations: importance of learnable, input-dependent gates
The gating mechanism is central in both LSTM and xLSTM variants. The authors performed focused gate ablations to isolate how different gating designs affect performance. The main conclusions from these gate-specific ablations are:

- Learnability of gates matters. Allowing the gates to be parameterized and learnable—as opposed to being fixed constants—enables the optimization process to discover gating regimes appropriate for the task and yields better perplexity.

- Input dependence of gates helps. Gates that depend on the current input (i.e., gating pre-activations that include input-weighted terms) confer additional benefit. This allows the model to modulate memory updates and decays conditioned on the content just observed.

- Combining learnability and input dependence produces incremental positive effects. That is, there is an additive benefit when gates are both learnable and input-dependent compared to simpler gate parametrizations.

Concretely, the xLSTM uses exponential activation for the input gate (and optionally for the forget gate) together with normal sigmoid for the output gate. Each gate's pre-activation includes input projections and (for sLSTM) recurrent hidden projections. Stabilization via the stabilizer state $m_t$ and the normalizer $n_t$ ensures numerical stability and consistent magnitudes, while preserving exact gradient relationships (the paper proves that stabilized gate variants do not alter network outputs or parameter derivatives). The gate ablations confirm that this richer gate parameterization is an essential piece of the xLSTM improvements.

# Backbone component studies
Beyond memory and gating mechanisms, the residual backbone architecture and specific placement of projections and nonlinearities have measurable effects. The paper documents experiments that dissect backbone components, including the ordering of projection and nonlinear summarization (pre vs post up-projection), placement of LayerNorm, and the use of residual connections in the block.

Key takeaways from these backbone studies are:

- The choice between pre up-projection and post up-projection interacts with the type of memory used. mLSTM benefits from pre up-projection because projecting into a higher-dimensional space before the memory operation increases effective memory capacity and allows the matrix memory to act in a richer representation space. sLSTM favors post up-projection since its scalar memories and memory mixing benefit from summarization followed by up-projection.

- Pre-LayerNorm residual stacks (the standard modern design) are effective base backbones for integrating both mLSTM and sLSTM blocks. Integrating LSTM-like recurrent elements into such backbones preserves the advantages of residual deep stacking while enabling the memory mechanisms to summarize past context efficiently.

- Residual stacking remains important: stacking many blocks residually enables higher-level nonlinear separation of histories (invoking Cover’s Theorem intuition) which improves next-token prediction capability. In other words, enhancing the memory cell alone is necessary but not sufficient; the ability of the architecture to embed histories into higher-dimensional linearly-separable manifolds via residual blocks is a complementary factor.

Taken together, the backbone studies indicate that careful alignment of projection ordering and normalization with the chosen memory mechanism yields the best results. The final xLSTM design uses these aligned choices: pre up-projection for mLSTM blocks, post up-projection for sLSTM blocks, and pre-LayerNorm residual connections throughout.

# Summary
This empirical study establishes that, when trained on 15B tokens and matched in parameter count to a GPT-3-scale baseline, xLSTM variants outperform a wide array of contemporary methods including Transformers, State Space Models, and recurrent/linear attention approaches. The improved performance arises from multiple coordinated design changes: embedding LSTM-style memories into modern residual backbones, introducing exponential gating with explicit normalizer and stabilizer states, and—in the mLSTM variant—replacing scalar cells with a matrix covariance memory that stores key-value outer products. Ablations show that the largest individual gains come from exponential gating and the matrix memory, while gate parameterization and backbone choices provide additional, measurable improvements. Finally, scaling behavior at this regime suggests xLSTM maintains its lead across sizes, indicating that the proposed LSTM extensions remain competitive as models scale.

Empirical Study III: xLSTM as a Large Language Model (300B Tokens)

# Setup: dataset, model sizes, and baselines
This study evaluates xLSTM when scaled to a large-language-model training regime. All models are trained on the SlimPajama corpus with a total of $300\text{B}$ tokens. The experiments span four model sizes: approximately $125\text{M}$, $350\text{M}$, $760\text{M}$, and $1.3\text{B}$ parameters. We compare xLSTM variants to three representative baselines: Llama (a Transformer), Mamba (a State Space Model, SSM), and RWKV-4 (a recurrent neural architecture). For xLSTM we report results for at least two block compositions: xLSTM[1:0] (all mLSTM blocks) and xLSTM[7:1] (majority mLSTM blocks with some sLSTM blocks). All models are trained with context length $2048$ during training; evaluation includes extrapolation to longer contexts unless otherwise stated.

The evaluation suite covers several complementary probes of model capability: sequence-length extrapolation, held-out validation perplexity for next-token prediction, performance on downstream common-sense reasoning tasks, per-domain next-token perplexity across the PALOMA dataset of $571$ text domains, and empirical scaling-law behavior. We also measure text generation time and decoding throughput to characterize inference trade-offs.

# Length extrapolation from $2048$ to $16384$ context
A critical question for any sequence model is how well it generalizes to longer contexts than seen during training. For this, the large ($1.3\text{B}$) checkpoints were trained at context length $2048$ and then evaluated at context lengths extended up to $16384$ ($16\text{k}$). xLSTM models retain low perplexity as the context is lengthened, whereas the alternative models degrade more rapidly.

Specifically, xLSTM exhibits robust extrapolation: perplexity remains near the levels attained at $2048$ context length even when the context is increased multiple-fold to $16384$. By contrast, the Transformer (Llama) and the SSM (Mamba) show larger increases in perplexity as the context grows, reflecting their more fragile extrapolation in this setting. RWKV-4 also degrades more quickly than xLSTM. These results indicate that the xLSTM memory structures and gating (in particular the mLSTM matrix memory and sLSTM mixing when present) support retention and retrieval of information across much longer horizons than encountered in training.

# Validation perplexity across model sizes
Validation perplexity on the SlimPajama held-out set is used as a primary language-modeling metric across the four model sizes. Both xLSTM variants evaluated—xLSTM[1:0] and xLSTM[7:1]—achieve the best validation perplexities among the compared methods at every model scale. This pattern holds consistently from the smallest ($125\text{M}$) to the largest ($1.3\text{B}$) models in the experiment.

The superiority of xLSTM in validation perplexity can be attributed to two architectural improvements over traditional LSTMs and to differences from the baselines: (i) exponential gating combined with normalization and stabilization, which enables better write/decay dynamics and revision of stored information, and (ii) the mLSTM matrix memory (in xLSTM[1:0]) that substantially increases storage capacity and retrieval fidelity for rare and associative information. The ablation studies reported elsewhere in the work attribute the largest gains to these two modifications.

# Downstream common-sense tasks
Beyond next-token perplexity, models are evaluated on a collection of downstream tasks that probe common-sense and reasoning abilities. Across model sizes and tasks, xLSTM generally leads in performance: the majority of tasks show xLSTM ahead of Llama, Mamba, and RWKV-4. The reported aggregate results indicate that the improved sequence modeling and memory behavior of xLSTM translate into better performance on reasoning-oriented downstream evaluations.

One notable exception is the ARC benchmark (a multiple-choice reasoning dataset). On ARC, Mamba sometimes attains the best scores, outperforming xLSTM on that specific task in certain model-size settings. Thus, while xLSTM is broadly superior across many common-sense tasks, particular datasets and reasoning formats may still favor alternative inductive biases present in other model families.

# PALOMA: per-domain next-token prediction across 571 domains
To examine domain-level generalization, models are evaluated for next-token prediction perplexity across the PALOMA suite of $571$ text domains, which encompass a very wide range of styles and topics (from major news outlets to specialized Reddit communities). Results show that xLSTM[1:0] is the strongest performer by a wide margin:

- xLSTM[1:0] has lower perplexity than Mamba on $568$ out of $571$ domains (approximately $99.5\%$).
- xLSTM[1:0] has lower perplexity than Llama on $486$ out of $571$ domains (about $85.1\%$).
- xLSTM[1:0] has lower perplexity than RWKV-4 on $570$ out of $571$ domains (about $99.8\%$).

These counts indicate that the mLSTM-rich variant (xLSTM[1:0]) not only attains better average perplexity but also systematically outperforms the baselines across nearly the entire range of evaluated domains. This domain-level dominance supports the claim that the matrix memory and gating mechanisms equip xLSTM to capture varied distributional properties and long-range dependencies that differ between domains.

# Scaling laws and extrapolation to larger models
Scaling behavior is analyzed in the sense of power-law relationships between model size and held-out loss, following the general framework established in prior scaling-law work. All considered model families (xLSTM, Mamba, Llama, RWKV-4) follow a power-law trend in validation loss versus parameter count, but with different vertical offsets. xLSTM displays the best offset among the compared methods: for a given parameter budget, xLSTM achieves lower loss than Mamba, which in turn outperforms Llama, and RWKV-4 is the least favorable of the group.

Because the slopes of these power laws are similar across families, the relative ordering persists as models get larger; thus the offset advantage of xLSTM is likely to hold at larger scales. In short, xLSTM follows the same predictable power-law scaling, but from a stronger starting point, suggesting that larger-scale xLSTM models would be competitive with or superior to large Transformers and SSMs when trained on sufficiently large corpora.

# Generation time and decoding throughput: linear scaling and constant-memory advantage
Inference experiments measure (i) single-sequence generation time and (ii) maximal decoding throughput for varying batch sizes and prefill lengths. These benchmarks highlight important practical trade-offs between autoregressive architectures.

Text generation time for xLSTM scales linearly with context length in wall-clock time, which is characteristic of recurrent and linear-context-complexity models. In contrast, Transformer-based models like Llama exhibit quadratic scaling in generation time with respect to context length when using naive attention recomputation, unless highly optimized caching or specialized attention kernels are used. In the experiments, generation runs use batch size $1$ and a prefill length of $16$; this prefill setting is favorable to the Transformer because it can amortize some attention computation via caches, yet xLSTM still shows linear scaling and competitive wall-clock times.

Beyond generation latency, xLSTM benefits from constant memory usage with respect to context length because its state does not store per-token keys and values in an ever-growing cache. This constant-memory property allows xLSTM to utilize much larger batch sizes during decoding than the Transformer before hitting memory limits, which in turn enables higher overall throughput. Empirically, xLSTM achieves the highest maximal throughput among the compared models in the reported experiments, particularly at large batch sizes where Transformer memory bounds become the bottleneck.

It is worth noting implementation caveats: the mLSTM CUDA kernels used are not yet as optimized as FlashAttention-style kernels, so measured absolute runtimes are not necessarily at the theoretical optimum for xLSTM. Nevertheless, the algorithmic complexity and constant-memory profile give xLSTM a clear practical advantage in high-throughput and long-context decoding scenarios.

# Summary
When trained at LLM scale ($300\text{B}$ tokens) across sizes from $125\text{M}$ to $1.3\text{B}$, xLSTM variants—especially the mLSTM-dominant xLSTM[1:0]—demonstrate robust long-context extrapolation, best-in-class validation perplexities, dominant per-domain performance across the PALOMA suite, and broadly strong results on downstream common-sense tasks (with isolated exceptions like ARC where Mamba sometimes leads). Scaling laws reveal a favorable offset for xLSTM, suggesting advantages will persist at larger parameter counts. Finally, xLSTM’s linear generation-time scaling and constant-memory decoding translate into superior decoding throughput in practice, making it an attractive architecture for long-context and production inference settings.

Implementation Guidelines and Practical Tips

# LayerNorm placement and projections (pre/post up-projection choices)
The xLSTM paper prescribes two residual block backbones and matches them to the two main memory variants. For reproducible results, follow the advised mapping:

- For mLSTM blocks use a pre up-projection backbone: first linearly project the input into a higher-dimensional space, then apply the mLSTM non-linearity (the matrix-memory update and retrieval), and finally project back to the model dimension. The motivation given in the paper is that the matrix memory benefits from operating in the higher-dimensional space (larger coding dimension increases memory capacity).
- For sLSTM blocks use a post up-projection backbone: first apply the sLSTM non-linearity in the original model dimension, then up-project to a high-dimensional intermediate, apply the intermediate non-linearity, and down-project. This mirrors the Transformer-style post up-projection residual block used in the paper for sLSTM-containing blocks.

Layer normalization is used in a pre-LayerNorm residual backbone throughout the xLSTM architectures (see Section 2.4). Concretely, apply LayerNorm to the block inputs before the linear projections and before feeding them to the memory cell computations. This matches the "pre-LayerNorm" design used in modern large models and in the experiments. Keeping LayerNorm pre-projection stabilizes the statistics entering the LSTM gates and the key/query/value projections (important for the covariance update and gate numerics discussed below).

# Gate initialization, especially forget gate care
Gate initialization matters. The paper highlights that the forget gate initialization must be chosen carefully (Limitations, point (iv)). Practical recommendations consistent with the paper’s design:

- Input gate: because the input gate uses an exponential activation $i_t = \exp(\tilde{i}_t)$, initialize $\tilde{i}$ so that $i_t$ is small but not vanishing. A standard practice compatible with the paper is to initialize the bias $b_i$ slightly negative so the initial effective learning-rate-like input gate is modest. Avoid large positive bias because $\exp(\cdot)$ can grow quickly.
- Forget gate: because the forget gate acts like a decay factor for memory ($f_t$ multiplies previous memory), initialize $\tilde{f}$ so that $f_t$ is close to but slightly below 1 (for $\sigma$-activated forget) or suitably close to 1 for an exponential forget gate. For example, if using the sigmoid variant $f_t=\sigma(\tilde{f}_t)$, set $b_f$ so $\sigma(b_f)\approx 0.9\text{--}0.99$ to encourage long retention at start. If using exponential forget ($f_t=\exp(\tilde{f}_t)$), set $b_f$ near zero but slightly negative so the effective decay per step is small. The paper notes careful selection is needed because the gate controls decay of stored information.
- Output gate: standard small bias (e.g., zero) is acceptable; the output gate is sigmoid in all variants.
- When gates depend on inputs and/or hidden state, initialize recurrent weights smaller than input projection weights to avoid unstable recurrent contributions early in training.

Because exponential gates can produce large magnitudes, proper initialization (biases and small weight scales) is crucial to keep initial dynamics stable and avoid overflow in the stabilization terms described below.

# Stabilization: normalizer state, m_t, denominator clamping in mLSTM
xLSTM introduces several stabilization constructs. Reproduce them exactly to ensure numerically-stable training and equivalence of stabilized forms.

- Normalizer state: both sLSTM and mLSTM maintain a normalizer $n_t$ that accumulates the gate strengths:
  - sLSTM scalar normalizer: $n_t = f_t\ n_{t-1} + i_t$.
  - mLSTM vector normalizer: $\mathbf{n}_t = f_t\ \mathbf{n}_{t-1} + i_t\ \mathbf{k}_t$.
  Always compute and carry $n_t$ (or $\mathbf{n}_t$) in the forward pass; it is used to divide the retrieved memory representation so that retrieved values are normalized by the total effective stored mass (see Equations (3) and (9) in the paper).
- Stabilizer state $m_t$ for exponential gates: when using exponential gates, the paper uses the log-space stabilizer trick to avoid overflow:
  - $m_t = \max(\log(f_t) + m_{t-1}, \log(i_t))$,
  - then stabilized gates become
    $i'_t = \exp(\log(i_t) - m_t)$ and
    $f'_t = \exp(\log(f_t) + m_{t-1} - m_t)$.
  Implement these stabilized forms in place of direct exponentiation. The paper proves the stabilized transformations leave outputs and parameter gradients unchanged while preventing numerical overflow.
- Denominator clamping in mLSTM retrieval: for mLSTM retrieval the paper divides the matrix-vector product $\mathbf{C}_t \mathbf{q}_t$ by the (absolute) dot product between normalizer and query, lower-bounded by 1:
  $\tilde{\mathbf{h}}_t = \dfrac{\mathbf{C}_t \mathbf{q}_t}{\max\{|\mathbf{n}_t^\top \mathbf{q}_t|,\,1\}}$.
  Implement this exact lower bounding. This avoids division by near-zero denominators (the paper mentions the dot product can be close to zero) and ensures stable magnitudes for the retrieved vector.
- Practical float handling: keep these stabilizers in FP32 (or at least the accumulator state $m_t$ and $\mathbf{n}_t$ in FP32) if you intend to use mixed precision—this reduces the risk of underflow/overflow in exponentiation and accumulation steps.

# Key scaling and zero-mean assumptions for covariance updates
The mLSTM derives its matrix-memory update from the covariance (outer-product) rule. To match the theoretical assumptions and maximize signal/noise:

- LayerNorm before key/value projections: the paper assumes a layer-norm before projecting inputs to keys and values so that keys (and in effect values) have zero mean. This is critical because the covariance update $\mathbf{C}_t \leftarrow \mathbf{C}_{t-1} + \mathbf{v}_t \mathbf{k}_t^\top$ aims to capture associative correlations; zero-mean inputs make the covariance-based memory optimal for separability (as discussed in Section 2.3).
- Key scaling: the paper uses a $\frac{1}{\sqrt{d}}$ scaling for the key projection:
  $\mathbf{k}_t = \frac{1}{\sqrt{d}}\mathbf{W}_k \mathbf{x}_t + \mathbf{b}_k$.
  Implement this scaling to keep dot-product magnitudes in a sensible range for both the outer-product update and the denominator $\mathbf{n}_t^\top \mathbf{q}_t$. Matching this scaling is important for stable signal-to-noise characteristics of the matrix memory (the paper explicitly shows this scaling in Equation (9)).
- Bias handling: because layer-norm makes mean approximately zero, keep the key bias $\mathbf{b}_k$ small or zero if you apply LayerNorm strictly before projection; otherwise non-zero bias alters the zero-mean assumption.

# Precision and mixed-precision training considerations
The paper used mixed precision for many experiments but also points out precision sensitivities. Follow these pragmatic rules:

- Keep accumulation and stabilizer variables in FP32: states such as the matrix memory $\mathbf{C}_t$, normalizer $\mathbf{n}_t$, and stabilizer $m_t$ should be maintained in full precision (FP32) to prevent numerical issues. The matrix memory involves many add/multiply operations; storing it in lower precision invites noise accumulation.
- Gate computations: computing $\tilde{i}_t$, $\tilde{f}_t$, and the subsequent exponentials/sigmoids is sensitive to precision. Compute the exponentials and logs (used in stabilization) in FP32.
- Mixed-precision for weight matrices and activations: forward activations and parameter multiplications can often be done in FP16/BFloat16 for speed, provided you cast back to FP32 for the memory accumulators (as above) and for any reduction-heavy operations.
- Automatic mixed-precision caveat: the paper notes that for some RNN variants (e.g., RWKV-5/6, GLA, HGRN2) the automated AMP tooling needed special handling and some trainings did not use standard PyTorch AMP. For reproducibility, if using AMP, monitor numerics carefully, and be prepared to force FP32 on the memory and stabilizer paths while using AMP for feedforward/projection branches.

# CUDA/Kernel notes: sLSTM custom kernels; potential mLSTM optimization paths
The paper reports engineering realities and guidance for optimized implementations:

- sLSTM custom kernels: sLSTM uses memory mixing (hidden-to-hidden recurrent connections), so it cannot be trivially parallelized across timesteps. The authors wrote a custom CUDA implementation with register-level memory optimizations which achieves runtime typically less than two times slower than their parallel mLSTM implementation. If you intend to use sLSTM in practice:
  - Implement a fused recurrent kernel that computes the gates, updates the scalar cell(s), normalizer, stabilizer, and output in a single kernel launch to minimize kernel overhead.
  - Use register- and shared-memory buffering for per-thread temporal state to reduce global-memory traffic.
  - Fuse LayerNorm and projections where possible to reduce memory transfers.
- mLSTM optimization paths: mLSTM is fully parallelizable because it removes hidden-hidden memory mixing, but it has heavy $d\times d$ matrix memory updates and retrievals which can be costly.
  - The matrix-memory updates are parameter-free (no learnable parameters in $\mathbf{C}_t$), so they are pure linear algebra operations. These can be implemented as batched outer-product updates and batched matrix-vector products, which are highly optimized on modern GPUs.
  - The authors note their mLSTM kernels are not fully optimized and are currently about 4× slower than FlashAttention or the scan used in Mamba. Potential optimizations include:
    - Use fused batched GEMM and batched outer-product primitives where hardware accelerators can exploit tensor cores.
    - Implement a FlashAttention-like memory layout and blocking strategy for the $\mathbf{C}_t \mathbf{q}_t$ retrieval to reduce memory traffic and increase arithmetic intensity.
    - Consider tiling $\mathbf{C}_t$ updates and retrievals to fit GPU shared memory and tensor core tile sizes.
    - If deploying at inference for very long contexts, take advantage of the constant-size memory $\mathbf{C}_t$ to avoid caching large key/value histories; you can keep $\mathbf{C}_t$ resident and perform only the incremental outer-product updates.
  - Where possible, keep $\mathbf{C}_t$ in FP32 even if other activations are in FP16 to avoid accumulation noise.
- Profiling: carefully profile both memory-bound and compute-bound regimes. The paper reports that despite heavier per-step compute, wall-clock overhead is minor because operations parallelize well. Nonetheless, a production-grade implementation should implement the optimizations above.

# Selecting xLSTM[a:b] ratios by task (capacity vs. state tracking)
xLSTM permits mixing mLSTM- and sLSTM-based blocks. The paper uses the notation xLSTM[a:b] to denote the ratio of mLSTM-based to sLSTM-based blocks. Practical selection guidance based on the empirical findings and the properties of the two variants:

- If your task emphasizes large associative memory capacity (many distinct key-value pairs, rich content-addressed recall, rare token modeling across long contexts), favor mLSTM-heavy configurations. The paper finds xLSTM[1:0] (only mLSTM) and variants with high mLSTM ratios perform best on many language-modeling tasks (see experiments on SlimPajama and PALOMA).
- If your task requires state tracking, sequential algorithmic behavior, or structured state updates that benefit from recurrent memory mixing, include sLSTM blocks. sLSTM supports memory mixing and the exponential gating that enables revising storage decisions; the paper shows sLSTM is superior when memory-mixing capacity is required (for formal language/state-tracking tasks).
- A mixed architecture like xLSTM[7:1] (mostly mLSTM blocks with a minority of sLSTM blocks) often provides a practical balance: the majority of high-capacity associative storage and efficient parallelism comes from mLSTM blocks, while the small number of sLSTM blocks gives state-tracking and memory-mixing capability that helps on tasks needing sequence-sensitive updates. The paper used xLSTM[7:1] in many experiments and showed strong overall results.
- If inference latency or throughput is the primary constraint and the task is mostly associative (e.g., large-context language modeling without heavy sequential state dependencies), favor pure mLSTM (xLSTM[1:0]) because it is parallelizable and gives higher throughput.
- If the application is in reinforcement learning or program evaluation where state tracking is critical, include a nontrivial proportion of sLSTM blocks to access memory mixing and stateful updates.

# Additional engineering notes consistent with the paper
- Memory vs. compute trade-off of mLSTM: the mLSTM’s matrix memory increases memory capacity but at a $d\times d$ computational cost per cell. The paper notes the memory itself does not add parameters, but costs compute. In practice you can trade off the internal d (the memory dimension) and the number of mLSTM blocks to fit your hardware budget.
- Sequence length and memory load: because the matrix memory is independent of sequence length, very long contexts may overload the fixed-size $\mathbf{C}_t$ if the model is asked to store too much diverse information. The paper observed good extrapolation up to 16k contexts with 1.3B models, but keep this consideration in mind for extreme context lengths; you may need to increase the internal memory dimension $d$ or adjust forget/input gate priors.
- Reproducibility tips: follow the same residual stacking, pre-LayerNorm setup, and the block projection choices the paper used. For benchmarking, match the training tokenization, data mixture, and prefill/context lengths as closely as possible to achieve comparable perplexity and scaling behaviors.
- Hyperparameter tuning: the paper indicates that not all architectures were fully optimized and that further tuning (especially at large scale) can improve performance. Key knobs to tune include gate bias initializations (especially $b_f$), key scaling, memory dimension $d$, and the xLSTM[a:b] ratio.

Following these guidelines will reproduce the numerics and engineering trade-offs discussed in the paper: use pre-LayerNorm residual backbones, map sLSTM to post up-projection and mLSTM to pre up-projection, stabilize exponential gates via $m_t$ and stabilized $i'_t,f'_t$, clamp mLSTM denominators by $\max\{|\mathbf{n}_t^\top \mathbf{q}_t|,1\}$, keep memory accumulators in FP32 when using mixed precision, and design CUDA kernels to fuse recurrent-state updates (sLSTM) or to exploit batched GEMM/tensor core tiling (mLSTM). Choosing the xLSTM[a:b] ratio should be driven by whether your task needs high associative capacity (favor mLSTM) or state-tracking/memory-mixing (include sLSTM).

Limitations, Risks, and Open Problems

# sLSTM’s non-parallel nature and speed gap to parallel methods
One of the fundamental trade-offs introduced by sLSTM is that it preserves memory mixing through hidden–hidden (recurrent) connections. This memory mixing is valuable: it enables state tracking and richer interactions between memory cells that many parallel sequence models (standard Transformers and many State Space Models) do not support. However, that same recurrence prevents a straightforward, fully-parallel implementation over time steps. In other words, sLSTM is inherently sequential in its memory-mixing component.

The paper reports an engineering mitigation: a custom CUDA kernel and GPU memory optimizations (down to the register level) were developed for sLSTM. With these optimizations the current sLSTM implementation is typically less than two times slower than the fully parallel mLSTM implementation. This is an important practical point: although sLSTM is not parallelizable in the asymptotic sense, careful low-level engineering can narrow the wall-clock gap substantially. Still, this gap remains and will matter in production settings where inference latency or throughput at very large scale is critical. Any deployment decision that favors sLSTM must therefore weigh the modeling benefit of memory mixing against the runtime cost of non-parallel recurrence.

# Unoptimized mLSTM kernels vs. FlashAttention-level performance
By design, mLSTM removes recurrent memory mixing and uses a matrix memory with covariance-style updates. This enables a parallel reformulation of the recurrence (so mLSTM can be implemented in a fashion analogous to other parallelizable mechanisms). Despite that potential, the paper’s current mLSTM implementation is not kernel-optimized to the level of highly engineered attention libraries. Concretely, the mLSTM implementation used in experiments is about four times slower than FlashAttention or the scan used in Mamba. That factor reflects non-optimized CUDA kernels and engineering choices, not an inherent theoretical limitation of mLSTM.

This gap points to a clear engineering opportunity: optimized kernels in the vein of FlashAttention (careful tiling, memory reuse, fused ops, and attention-style I/O patterns) could substantially reduce the wall-clock overhead of the matrix-memory operations. Until such kernels exist, mLSTM will carry a practical speed penalty relative to the fastest Transformer implementations, even though its algorithmic parallelizability would allow closing much of that gap.

# Matrix-memory compute cost at high d
The mLSTM cell replaces a scalar memory $c \in \mathbb{R}$ by a matrix memory $\mathbf{C} \in \mathbb{R}^{d \times d}$, and the update and retrieval use outer products and matrix–vector multiplications. This design raises the computational cost per time step to operations that scale like $O(d^2)$. Specifically, storing a key–value pair requires adding a rank-1 matrix $\mathbf{v}_t \mathbf{k}_t^\top$ to $\mathbf{C}$, and retrieval computes $\mathbf{C}_t \mathbf{q}_t$, both involving $d \times d$ arithmetic.

The paper frames this as a trade-off: increased storage capacity (matrix memory) versus computational complexity. The matrix memory itself does not require additional learned parameters, but the per-step compute and memory bandwidth demand grow with $d^2$. Practically, this means that for very large embedding dimensions the mLSTM cell can be substantially more expensive than scalar-memory RNNs or attention mechanisms whose dominant cost scales differently. Nevertheless, because these matrix operations are standard dense linear algebra, they are amenable to GPU parallelism; the paper argues the wall-clock penalty can be moderate when implemented efficiently. Still, for very large $d$ or on hardware with limited matrix throughput, the $d \times d$ cost is a limiting factor and forces a design trade-off between capacity and runtime.

# Sensitivity to gate initialization
The paper explicitly notes a sensitivity in xLSTM variants to the initialization of forget gates. Good initial values for forget gates matter because these gates control effective decay rates of stored information (in sLSTM and mLSTM the forget gate plays the role of a decay applied to the cell memory). Poor initialization can either erase important content too quickly or prevent useful forgetting, impairing learning and stability.

While no single fixed initialization is prescribed for all settings, the paper highlights the practical necessity of careful choice and tuning of gate biases and any gate-related initializers. This sensitivity is an operational risk during training: suboptimal initializations can slow convergence, cause instability, or reduce final performance. Consequently, engineers must treat gate initialization as a hyperparameter to be monitored and tuned in training runs, particularly when transferring architectures to new datasets, model sizes, or contexts.

# Potential memory overload at very long contexts; empirical 16k behavior
Because mLSTM’s matrix memory is a compressed, fixed-size structure independent of sequence length, the model accumulates information about the entire processed sequence into the single matrix $\mathbf{C}$. This compressive property makes both storage and runtime memory constant in sequence length, a practical advantage relative to caching all past keys and values. However, a fixed-size memory can in principle be overloaded if the total information content required to model an extremely long context exceeds what the $d \times d$ matrix can represent.

The paper discusses this risk and reports empirical behavior up to sequence lengths of 16k: in experiments (Section 5.3.1) xLSTM models maintain low perplexities when extrapolating to longer contexts up to 16k, suggesting that for these ranges the matrix memory does not become overloaded in practice. Nevertheless, the authors acknowledge the theoretical possibility that at still longer contexts (beyond those evaluated) or for particularly information-dense sequences, the finite matrix memory could be insufficient, degrading performance. Thus, while empirically robust to 16k in the paper’s tests, the fixed-capacity memory is an architectural limitation to be aware of when extrapolating to arbitrarily long-context applications.

# Hyperparameter and architecture optimization left on the table
A pragmatic limitation acknowledged by the authors is that, due to the high computational cost of large-language experiments, they did not exhaustively optimize hyperparameters and architectural details especially for the largest xLSTM variants. The paper states that the architectures and hyperparameters used are not fully optimized and that an extensive optimization process is needed for xLSTM to reach its full potential.

This admission has two consequences. First, the reported results likely understate what xLSTM might achieve under a thorough tuning campaign; margins versus other methods could improve further. Second, it means that current experimental comparisons are influenced by implementation and tuning choices; reproducing or improving upon these results will require careful hyperparameter search (learning rates, gate biases, normalization choices, stabilizers like $m_t$, dimension $d$, number of heads/cells, block allocation ratios xLSTM[$a$:$b$], etc.). Researchers and practitioners should budget resources for such search when adopting xLSTM.

# Open questions: hybrid mixing, sparsity in matrix memory, dynamic capacity
The paper identifies several open research directions that stem naturally from xLSTM’s design choices and limitations.

One open question is how to combine the best of both worlds: hybrid mixing mechanisms that interpolate between full memory mixing (as in sLSTM) and full parallelizability (as in mLSTM). Is there an architecture that retains enough memory mixing for state tracking but allows more parallel execution or structured sparsity that reduces sequential cost? Designing hybrid blocks or partial recurrence patterns is an interesting avenue to explore.

Another direction is to make matrix memory more efficient through sparsity or low-rank structure. The current mLSTM uses dense $d \times d$ matrices; introducing sparsity, structured factorization, or learnable low-rank approximations could reduce the $O(d^2)$ compute and storage cost while preserving much of the increase in storage capacity. The paper cites connections to Fast Weight Programmers and other covariance-style updates; exploring constrained or sparse covariance updates is an open research area that may balance capacity and efficiency.

A related open problem is dynamic capacity: can the model expand, compress, or otherwise adapt its effective memory capacity over time depending on the demands of the input? For instance, mechanisms that offload older or less-relevant information, or dynamically allocate more matrix “budget” to salient patterns, could alleviate the risk of memory overload on extremely long contexts. Formalizing and implementing such adaptive capacity controls while retaining stable training remains an open challenge.

Finally, investigating how different mixtures of sLSTM and mLSTM blocks (the xLSTM[$a$:$b$] ratio), and how the number of heads and cells per block, affect both expressivity and runtime across different tasks is an empirical and theoretical question. The results in the paper indicate strong performance for particular ratios, but a principled characterization of these design choices would guide future architecture search.

# Summary
The xLSTM paper advances LSTM-style sequence modeling by introducing exponential gating and matrix memories, and by integrating these into residual, stackable blocks. These innovations bring measurable gains in modeling capacity and favorable scaling behavior. At the same time, several concrete limitations and risks remain: sLSTM’s inherent sequential nature (and its remaining runtime gap despite custom kernels), mLSTM’s unoptimized kernels relative to FlashAttention, the $O(d^2)$ cost of dense matrix memory, sensitivity to gate initialization, and the theoretical risk of memory overload at very long contexts (empirically not observed up to 16k). The paper also leaves significant engineering and tuning work for future efforts and points to open research questions around hybrids between mixing and parallelism, sparsity or low-rank structure in matrix memories, and mechanisms for dynamic capacity. Each of these limitations simultaneously represents an opportunity for engineering improvements and for novel research.

Key Takeaways and Outlook

# Answer to the core question: xLSTM as a competitive LLM backbone

The central question posed by the paper is simple: how far can LSTM ideas get when we scale them to the size of modern Large Language Models and address known LSTM limitations? The empirical answer given in the paper is: far enough to be competitive with contemporary Transformer and State Space Model (SSM) backbones for language modeling. When trained on the same data regimes (15B and 300B tokens from SlimPajama), xLSTM architectures achieve lower validation perplexities than the set of evaluated baselines (Transformers, several SSMs, and recent RNN-based models). The scaling-law analysis in the paper shows similar power-law behavior across methods but with xLSTM consistently offset toward better performance; extrapolation therefore suggests xLSTM will remain favorable as models grow.

Two practical consequences follow. First, LSTM-derived architectures are not inherently obsolete: by addressing specific architectural limitations (see below), LSTM-style recurrence can match or exceed the effectiveness of attention- and SSM-based models in the language modeling setting tested. Second, xLSTM retains a fundamentally different computational profile: linear compute and constant memory complexity in sequence length, and compressive internal state, which yields advantages in throughput and memory-limited deployment scenarios (e.g., larger batch sizes during decoding and edge inference). The empirical results on sequence length extrapolation also show that xLSTM maintains low perplexities for contexts longer than those seen during training, indicating robustness to longer-context workloads.

# Why exponential gating + matrix memory matter

The paper identifies three core LSTM limitations and ties each to a concrete remedy. Two of these remedies — exponential gating and a matrix (covariance-style) memory — are central to xLSTM’s gains.

Exponential gating changes the dynamics of how new information is integrated and how past information is decayed. In a conventional LSTM gates are sigmoid-valued, which restricts how input updates and forget-decays combine multiplicatively. By using exponential activations (with suitable normalization and stabilization), the input and/or forget factors become multiplicative scales that can strongly amplify or sharply reduce contributions. Concretely, sLSTM introduces gates like
i_t = exp(\tilde{i}_t)
and allows f_t to be either \sigma(\tilde{f}_t) or exp(\tilde{f}_t). To prevent numerical overflow and to make these exponentials stable across long sequences, the paper introduces a stabilizer state m_t and normalized gates i'_t and f'_t (Equations (3) in the paper). Together with a normalizer state n_t that accumulates gate mass forward in time, these components let the model (i) perform numerically stable exponential weighting of past contributions and (ii) revise storage decisions: a later large input gate can exponentially upweight a newer input relative to older stored values, enabling effective revision of stored information during a single pass. Synthetic tasks demonstrating state-tracking (e.g., extended formal languages and nearest-neighbor search style tasks) show that exponential gating with memory mixing enables solutions that standard gated RNNs and non-mixing SSMs/Transformers cannot obtain.

The matrix memory (mLSTM) upgrades the scalar LSTM cell c_t \in \mathbb{R} to a matrix memory \mathbf{C}_t \in \mathbb{R}^{d\times d}. The update rule follows a covariance or outer-product “fast weight” style:
\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top.
Storing key–value pairs as outer products and retrieving by matrix–vector multiplication \mathbf{C}_t \mathbf{q}_t provides much greater representational capacity than a scalar per cell. The normalizer \mathbf{n}_t aggregates keys with the same gate weights and is used to normalize retrieval:
\tilde{\mathbf{h}}_t = \mathbf{C}_t \mathbf{q}_t \ /\ \max\{ |\mathbf{n}_t^\top \mathbf{q}_t |, 1\}.
This design is grounded in classical results on covariance updates and associative memories (e.g., BAMs and Fast Weight mechanisms) where outer-product storage maximizes separability and signal-to-noise. Practically, the paper shows that mLSTM substantially improves ability to remember many paired items (associative recall) and improves rare-token prediction in language modeling: capacity increases because memory scales with $d\times d$ rather than being compressed into scalar cell states.

In sum, exponential gating grants flexible, numerically stable revision and temporal weighting, while matrix memory grants capacity for higher-fidelity storage and retrieval. Both are necessary: exponential gates without capacity still struggle on bulk recall, and matrix memory without flexible gating lacks the dynamic control shown to matter in sequence tasks.

# When to prefer sLSTM vs. mLSTM (state tracking vs. bulk capacity)

xLSTM adds two concrete variants that serve different trade-offs: sLSTM and mLSTM.

sLSTM extends the scalar LSTM cell with exponential gates, an explicit normalizer n_t, and a stabilizer m_t, while retaining recurrent hidden–hidden connections (memory mixing). This memory mixing is important for tasks that require chaining and manipulation of stored state—that is, classical state tracking and algorithmic-like behaviors where interactions among stored scalars and sequential updates are essential. Because sLSTM preserves and extends the LSTM’s ability to mix states across time via recurrent weights, it is particularly suitable when the task requires compositional, procedural, or tracked latent state (for example, evaluating program-like input, parsing nested structures, or tracking multiple interacting entities over time). Empirically, the sLSTM (or xLSTM variants containing sLSTM blocks) solves formal language/state-tracking tasks that Transformers and SSMs without memory mixing cannot.

mLSTM replaces scalar cells with matrix memories and removes hidden–hidden recurrence to enable full parallelization. This yields two defining advantages: much greater per-step storage capacity (outer-product storage of key–value pairs), and the ability to parallelize computations across sequence positions (the recurrence can be reformulated in a parallel implementation). mLSTM is preferable when the workload demands storing and retrieving many items or when the model must remember high-dimensional associations (e.g., many key–value pairs, rare-token contexts). The associative-recall experiments show that mLSTM (and xLSTM architectures with many mLSTM blocks) outperform other non-Transformer models on multi-query associative recall and rare-token performance. Because mLSTM lacks memory mixing, it is less expressive for certain state-manipulation tasks; combining it in architectures with some sLSTM blocks (e.g., xLSTM[7:1]) can provide a balance.

Practically, the paper finds that architectures mixing mLSTM and sLSTM blocks yield complementary strengths. Configurations like xLSTM[7:1] (mostly mLSTM with a few sLSTM blocks) offer strong language modeling performance, leveraging mLSTM’s capacity and sLSTM’s state-tracking where needed. Pure mLSTM (xLSTM[1:0]) achieves top performance on many language benchmarks as well, indicating that for much of natural language modeling, bulk capacity and parallelizability suffice; for tasks requiring complex internal state manipulation, including some formal languages, sLSTM blocks are essential.

# Implications for RL, time series, and physical systems modeling

The paper emphasizes that xLSTM’s improvements are not limited to language modeling. Several characteristics make xLSTM relevant across domains:

- Reinforcement learning (RL): Historically, LSTMs have been the best performing sequence models in important RL systems (the paper cites AlphaStar and OpenAI Five). The capacity to track state, revise stored decisions, and hold long-lived associative memories is critical in RL, where agents must integrate partial observability and maintain internal representations across long time horizons. sLSTM’s memory mixing and exponential gating enable robust state tracking and revision of stored information—properties useful for policy networks and world models. mLSTM’s matrix memory could be leveraged to store many episodic associations efficiently, potentially improving sample efficiency in episodic-memory augmented agents.

- Time series and physical systems: These tasks often benefit from compact, compressive memories and the ability to process long contexts in streaming fashion with constant memory overhead. xLSTM’s linear-per-step compute and constant memory with respect to sequence length make it attractive for long-run simulation and forecasting, including applications like hydrological forecasting or magnetic control mentioned in the paper. The combination of stable exponential gating (for long-term weighting) and high-capacity associative memory (for storing repeated motifs or pattern templates) can help capture long-term dependencies and repeated patterns common in physical systems.

- Broader sequence modeling (e.g., evaluation of programs, structured outputs): The ability to revise stored decisions and to maintain structured internal state suggests xLSTM is well suited to tasks requiring reasoning over sequences, maintaining counters or stacks implicitly, or integrating symbolic-like representations. The results on formal languages and state-tracking tasks underscore this potential.

In all these domains, an additional practical advantage is the compressive memory footprint: because the internal memory does not grow with sequence length, xLSTM can be more deployment-friendly for edge devices or systems with constrained RAM while still supporting long contexts.

# Future scaling and system-level opportunities

The paper outlines several concrete directions and system-level opportunities that follow from xLSTM’s design and empirical behavior.

First, further scaling of xLSTM model sizes and more extensive hyperparameter and architecture optimization remain to be done. The authors note that due to computational constraints they did not fully optimize larger xLSTM variants; the observed favorable scaling law offsets suggest additional training and tuning will likely yield further gains. In particular, tuning initialization of forget gates, stabilization parameters for exponential gates, and the balance of mLSTM vs. sLSTM blocks (heads and cells) are promising levers.

Second, there is a clear systems engineering opportunity around optimized kernels. mLSTM's matrix memory updates and retrievals are amenable to highly optimized GPU kernels (the paper compares the current unoptimized implementation to FlashAttention and notes it is about 4× slower). Implementing fast parallel GPU kernels for the outer-product updates and retrieval (in the style of FlashAttention optimizations) should shrink wall-clock overheads and make mLSTM competitive with attention in throughput.

Third, the mixed architecture possibilities (different ratios of mLSTM to sLSTM blocks, multiple heads, multiple cells) offer a design space for workload specialization. For example, large language backbones might use predominantly mLSTM blocks for bulk modeling and capacity, with a small fraction of sLSTM blocks that provide state-mixing and procedural reasoning. Alternatively, domain-specific models (e.g., RL agents) could tune the block mix to prioritize state-tracking.

Fourth, system-level benefits stem from xLSTM’s linear compute and constant memory in sequence length. This enables much larger decoding batch sizes and higher maximal throughput relative to quadratic-memory Transformers, and it offers potential for more efficient on-device or low-latency deployments where memory constraints are binding. Moreover, the compressive memory may allow longer effective contexts within a fixed memory budget, which matters both for practical deployment and for inference-cost scaling.

Finally, the paper’s experimental results suggest that xLSTM can be a competitive alternative to attention-based backbones in large-scale modeling given proper engineering effort. This opens a broader research direction: hybridizing or integrating xLSTM-style memories within Transformer or SSM stacks, exploring training curricula and data regimes that exploit xLSTM's strengths (e.g., rare-token learning, associative recall), and investigating theoretical properties (expressivity vs. attention and SSMs) further.

# Closing remarks

The paper’s contribution is twofold: (i) conceptual — it shows how two targeted modifications to LSTM design (exponential gating with stabilization/normalization, and matrix covariance-style memory) address key limitations that had constrained LSTMs in modern large-scale settings; and (ii) empirical — it demonstrates that architectures built from these components, when scaled and integrated into residual backbones, can match or outperform a broad set of contemporary sequence models on language modeling benchmarks and a range of synthetic tasks.

For practitioners, the main takeaway is that xLSTM provides a viable, competitive backbone with distinct computational and memory trade-offs compared to Transformers and SSMs. For researchers, the xLSTM design opens multiple avenues: better kernels and engineering for mLSTM, deeper investigations into the expressivity granted by memory mixing versus parallelizable matrix memories, and applications in RL and scientific modeling where state tracking and long-term associative storage are essential. The paper shows that LSTM-derived ideas, when modernized thoughtfully, are far from exhausted and can re-enter the center of large-scale sequence modeling research.

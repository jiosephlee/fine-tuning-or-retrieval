# From LoRA to BOFT: A Plain-English Guide to Smarter Fine-Tuning

## Why parameter-efficient fine-tuning (PEFT) matters

Modern foundation models (large language and vision models, diffusion models, etc.) are huge. Training them from scratch is costly, so the practical approach is to reuse pretrained models and adapt them to downstream tasks. But naively fine-tuning every weight is expensive in storage, compute, and deployment. That’s where parameter-efficient fine-tuning (PEFT) comes in: change as little as possible while getting the model to perform a new task.

Two popular, contrasting PEFT strategies are:

- LoRA (low-rank adaptation): modify a pretrained weight matrix W by adding a low-rank update. This is additive, simple, and parameter-efficient because the low-rank factors cost O(d) or O(rd) parameters rather than O(d^2).
- Orthogonal Fine-Tuning (OFT): instead of adding, OFT multiplies the pretrained weight by an orthogonal matrix R so that W_new = R W_pretrained. The orthogonal transform preserves pairwise angles between neurons and keeps spectral properties, which can stabilize training and help generalization.

OFT has appealing theoretical and empirical properties, but there’s a problem: a dense orthogonal matrix in d dimensions is still O(d^2) parameters. The original OFT paper made a pragmatic compromise by using block-diagonal orthogonal matrices (split the d dims into blocks and apply separate orthogonal transforms). That reduces parameters but also drastically limits expressivity: blocks don’t mix information across blocks, and the block layout is an arbitrary axis-aligned partition.

BOFT (Orthogonal Butterfly Finetuning) asks: can we keep OFT’s multiplicative, angle-preserving advantages while cutting the parameter count dramatically and keeping much more expressivity than block-diagonal OFT?

## The core idea — trade space for computation with factorization

Instead of representing one big dense orthogonal matrix R explicitly, BOFT composes R as a product of several sparse orthogonal factors:

R = B_m B_{m-1} ... B_1

Each B_i is sparse and orthogonal. Multiplying them together produces a dense matrix overall, but the number of trainable parameters is the sum of the parameters needed to describe the sparse factors. This trades a bit more computation during fine-tuning (you multiply through several sparse factors) for dramatically fewer stored parameters.

To reason about what sparsity patterns are effective, BOFT frames the construction as an information-transmission problem: imagine a grid of nodes arranged in levels (one level per factor plus source and destination). Each sparse factor defines connections between neighboring levels. For the final composed matrix to be dense, every source node must be able to reach every destination node via some path through the levels. The design goals are therefore:

- Dense connectivity in the composed map (every input dimension can influence every output dimension).
- As few free (trainable) edges as possible, under the orthogonality constraint.

This perspective guides the choice of sparsity pattern for the B_i factors.

## Why the butterfly pattern?

BOFT borrows the butterfly topology from the Cooley–Tukey FFT. The butterfly is a sparse, structured network that mixes information across inputs in O(log d) stages, and it’s precisely designed to let local operations ripple to global mixing with very few edges.

Concrete properties:

- A d-dimensional butterfly factorization can be built from O(log d) sparse layers, each with O(d) nonzeros.
- If each sparse factor is orthogonal, the product is an orthogonal matrix.
- Therefore, BOFT can parameterize a dense orthogonal matrix with O(d log d) parameters, instead of O(d^2) for an unconstrained orthogonal matrix.

A simple way to think about it: instead of one fully connected mixing layer (d^2 connections), use a small number of structured local mixing layers (like fixed templates) that, when composed, let information from any input coordinate reach any output coordinate.

BOFT generalizes block OFT as an edge case. If you set the number of factors m = 1 and choose block size b equal to the full dimension, you recover full OFT; if you set m = 1 with small b you recover block-diagonal OFT. Increasing m (more stages) while keeping block widths small yields the butterfly regime with strong parameter savings and good mixing.

## How BOFT maintains orthogonality in practice

To keep each factor orthogonal during training BOFT uses small orthogonal blocks (e.g., 2×2 blocks) and composes them in the butterfly pattern. For numerical stability and zero-start behavior, BOFT initializes each factor as identity (so the initial fine-tuned model equals the pretrained model). A common orthogonal parameterization used here is the Cayley transform: parameterize an orthogonal matrix R as R = (I + Q)(I - Q)^{-1} where Q is skew-symmetric (Q = −Q^T); initializing Q = 0 gives R = I.

Because BOFT’s factors are blockwise orthogonal, they remain orthogonal during training and their product stays orthogonal.

## Practical add-ons: multiplicative Dropout and block variants

Two practical points that come from the paper:

- Multiplicative Dropout: conventional dropout doesn’t work transparently with multiplicative updates. BOFT’s variant randomly replaces some butterfly components or some blocks inside a component with identity during training. This is a multiplicative analogue of dropout that regularizes the composed orthogonal transformation.
- Block butterfly: instead of 2×2 micro-blocks, BOFT can use block size b > 2. This introduces a family of BOFT(m, b) models. Tuning m (number of stages) and b (block width) trades off parameters, expressivity, and runtime.

Parameter count: BOFT(m, b) uses about (1/2)(b - 1) d m effective trainable parameters for a d × n linear layer. For the classic butterfly case (b = 2 and m ≈ log d), the cost is O(d log d).

## What BOFT buys you compared to LoRA and block OFT

- Compared to LoRA: LoRA is additive and low-rank; BOFT is multiplicative and orthogonal. BOFT preserves pairwise neuron angles and the spectral norm of pretrained weight matrices, which can improve training stability and generalization. LoRA tends to be very parameter-efficient but does not enforce these orthogonality-based invariants.
- Compared to block-diagonal OFT: BOFT achieves dense mixing between coordinates with far fewer parameters than a full dense orthogonal matrix and much more expressivity than block-diagonal OFT. The butterfly pattern can represent many classic fast transforms (Fourier, Hadamard, etc.), which suggests a useful structural inductive bias for finetuning.

A theoretical point in the paper: by composing a small number of butterfly-structured orthogonal matrices (and their transposes) in a certain hierarchy, one can approximate arbitrary orthogonal matrices. That means BOFT is not fundamentally limited to a narrow class of transforms; with more stages and the right composition, expressivity approaches the full orthogonal group. In practice, however, the regularity (restricted hypothesis class) that BOFT imposes is part of why it can generalize well.

## Trade-offs and limitations

- Runtime: BOFT multiplies several sparse factors each forward/backward pass, so training is somewhat slower than single-factor OFT. However, at inference you can fold the learned product into the pretrained weights and incur no extra latency.
- Is butterfly optimal? The paper uses butterfly because it is a known, efficient topology for global mixing. Whether a different sparse topology would yield even better parameter/compute trade-offs is an open question; the paper frames the design as an information-transmission / network-topology search problem.
- Choice of hyperparameters (m, b): these control the trade-off between expressivity, parameter count, and runtime. BOFT subsumes block OFT and full OFT as special cases, so it gives a tunable family to fit different budgets.

## Takeaway

BOFT is a neat combination of three ideas:

- Keep the multiplicative, orthogonality-preserving updates of OFT (good for stability and generalization).
- Factor the dense orthogonal matrix into a product of sparse orthogonal blocks (trade memory for compute).
- Use the butterfly topology to get global mixing with only O(d log d) parameters.

If you like LoRA for efficiency, but you also value the spectral/angle-preserving properties of orthogonal transforms, BOFT offers a middle path: substantial parameter savings over full OFT, much more expressivity than block-diagonal OFT, and structural inductive biases derived from widely used fast transforms.

For engineers: BOFT is another PEFT knob to tune. By varying the number of stages m and block size b you can target different parameter budgets and runtime trade-offs. After training you can fold the product into the frozen weights to keep inference fast and simple.

For researchers: BOFT opens a clean design space (sparse orthogonal factor topologies) and an interesting connection between network topologies, information transmission, and parameter-efficient model adaptation.



# Butterflies in Your Model: How FFT-Inspired Structures Shrink Fine-Tuning Costs

Large pretrained models are powerful but expensive to adapt. Full fine-tuning means updating O(d^2) parameters per large weight matrix, which quickly becomes impractical. Recent parameter-efficient approaches trade off capacity for fewer trainable parameters (LoRA uses low-rank additive updates, Orthogonal Finetuning (OFT) uses multiplicative orthogonal transforms). BOFT — Orthogonal Butterfly Finetuning — takes inspiration from the Fast Fourier Transform (FFT) “butterfly” to get dense, expressive orthogonal updates with far fewer parameters: roughly O(d log d) instead of O(d^2). This post explains the intuition, the structure, and why it works.

## The problem: want dense transforms, not O(d^2)

OFT updates a pretrained layer W^0 by left-multiplying an orthogonal matrix R so the forward pass becomes z = (R W^0)^\top x. Multiplying by an orthogonal R has attractive properties: it preserves pairwise angles between neurons and preserves spectral norm, which helps stability and generalization.

But a general orthogonal R is d×d, so parameter count scales as O(d^2). OFT’s practical workaround is block-diagonal R (separate small orthogonal blocks). That reduces parameters to O(b d) when blocks are size b, but it also prevents information mixing across blocks — a rigid sparsity pattern that limits expressiveness.

Goal: obtain a dense orthogonal R (so each output dimension can depend on all inputs) while keeping the number of trainable parameters small.

## Information transmission view (visualize it)

Think of a dense d×d matrix as complete connectivity from d source nodes to d sink nodes: every source can influence every sink. Factorizing R as R = B_m B_{m-1} ... B_1 is then like running information through m layers of a network. Each factor B_i is sparse and describes edges between level i and i+1. For the product to be dense, every source in level 1 must have at least one path to every sink in level m+1.

Desiderata under this view:
- Dense connectivity overall (every source → every sink).
- Few trainable edges (sparsity per layer) so parameter counts are low.
- Orthogonality constraint per factor (we want each factor to be orthogonal).

A naive dense single-layer R has O(d^2) edges. The information-transmission perspective suggests instead designing a layered sparse topology that lets information mix across layers so the composition is dense while each layer remains sparse.

## Enter the butterfly: FFT's mixing pattern

The Cooley–Tukey FFT uses a specific layered mixing topology called the butterfly. In words, the butterfly lets information from any input quickly influence every output via O(log d) rounds of local pairwise or small-block mixing. Concretely, for d a power of two, a radix-2 butterfly composes about log d sparse stages; each stage contains O(d) nonzero blocks (often 2×2 blocks), so the total number of nonzero parameters is O(d log d).

You can picture it like this (visual in words): line up d inputs on the left. At the first stage, nodes are paired and each pair exchanges information via a small 2×2 orthogonal rotation. At the next stage the pairing pattern changes (a permutation), and new neighbor pairs mix. Repeat about log d times with carefully chosen pairings; after these stages information from any single input has propagated to all output positions. The pattern of pairings across stages is what gives the name “butterfly”.

Because each stage only uses small local transforms (e.g., 2×2 rotations or small block orthogonals), each stage is parameter-light, but the repeated mixing yields a globally dense composite transform.

## BOFT: orthogonal butterfly parameterization

BOFT parameterizes R as a product of orthogonal butterfly components:
R(m, b) = \prod_{i=1}^m \tilde{B}_{(d,i)}^b,
where each \tilde{B}_{(d,i)}^b is a block-wise butterfly component with block size b (b controls a coarse-grain block structure). If b=2 and m \approx \log d, the resulting R is dense and uses about O(d log d) trainable parameters.

Key points:
- Each butterfly component is orthogonal (we can parameterize each small block — e.g., 2×2 — with the Cayley transform or a rotation angle), so the whole R stays orthogonal.
- BOFT subsumes simple OFT variants: BOFT(1, b) is just block-diagonal OFT with block size b; BOFT(1, d) is full OFT.
- With m = \log(d/(b/2)) and small b (e.g., b=2), BOFT produces dense R with parameter count roughly (b-1) d m / 2 \approx O(d log d).

Practical details from the paper:
- Initialize each block to identity (zero skew-symmetric parameters in Cayley parameterization) so the start of fine-tuning matches the pretrained model.
- They propose a multiplicative dropout: randomly replace some butterfly components (or diagonal blocks inside a component) with identity during training to avoid overfitting. Typical additive dropout like in LoRA doesn't map well to multiplicative updates.

## Why does this help? expressivity, stability, and inductive bias

Expressivity: butterfly compositions can exactly recover many classic fast transforms (FFT, Hadamard, DCT), and empirically a product of butterfly components approximates random dense orthogonal matrices much more parameter-efficiently than block-diagonal structure. The paper shows BOFT with many stages (small b) is more expressive per parameter than OFT with larger blocks.

Stability: because BOFT builds R as orthogonal, it preserves the singular values of W^0 (left-multiplication by orthogonal does not change spectral norm). Preserving spectral properties helps training stability and often generalization.

Inductive bias: restricting R to a structured subset of orthogonal matrices (butterfly family) introduces a bias that favors transforms like those encountered in many signal processing transforms. This structured bias can improve generalization relative to unconstrained fine-tuning.

Trade-offs: BOFT trades some extra computation at training time (you must multiply multiple sparse factors) for large parameter savings. After fine-tuning, the learned R can be multiplied into W^0 so inference cost is unchanged.

## Where BOFT sits among PEFT methods

- LoRA: additive low-rank update, O(r d) parameters (rank r). Good parameter efficiency but modifies singular values and can change spectral properties.
- OFT: multiplicative orthogonal update, good stability and generalization, but naive full OFT is O(d^2) parameters; block-diagonal OFT reduces parameters but blocks do not mix.
- BOFT: multiplicative orthogonal update, but factorized with butterfly stages to get dense mixing with O(d log d) parameters.

So BOFT merges OFT’s stability with a parameter-efficient factorization inspired by FFT.

## Limitations and practical notes

BOFT has a slightly higher training-time overhead because you must multiply through multiple factors each forward/backward pass. The paper notes this runtime overhead is an open optimization target. Also, while butterfly is efficient and expressive, it is not proven to be the single optimal topology for information transmission under orthogonality constraints; other network topologies could be explored using the same information-transmission perspective.

Finally, BOFT includes several hyperparameters: number of stages m and block size b. Smaller b and larger m give more mixing per parameter (tend to be more expressive), but require more stages and thus more computation during training.

## Takeaway

If you want the benefits of orthogonal multiplicative fine-tuning (stability, spectral preservation, angle preservation) without paying O(d^2) parameters, stacking small sparse orthogonal rotations in a butterfly-style topology is a principled and effective solution. BOFT shows that FFT-inspired mixing can be re-purposed to compress the parameter footprint of dense orthogonal updates to about O(d log d), enabling dense-like expressivity while keeping parameter budgets small — a practical win for adapting very large models.



# Fine-Tuning as Information Flow: A New Way to Think About Orthogonal Updates

Fine-tuning large pretrained models is now a routine but expensive task. Orthogonal Finetuning (OFT) proposed a neat idea: instead of adding low‑rank updates or changing the model weights arbitrarily, multiply the pretrained weight matrix on the left by an orthogonal matrix so that pairwise angles between neurons are preserved. That helps retain pretrained structure and often improves stability and generalization—but dense orthogonal matrices are costly: a full $d\times d$ orthogonal matrix naively needs $\mathcal{O}(d^2)$ parameters.

This paper reframes the problem in a simple, useful way: generating a dense orthogonal transform by composing several sparse matrices is equivalent to routing information across a grid. From that viewpoint, the choice of sparsity pattern for the factor matrices is not just an implementation detail—it is the communication topology. Picking the right topology yields dense overall connectivity while keeping the number of trainable entries low. The paper uses this idea to build Orthogonal Butterfly Finetuning (BOFT), which achieves dense, orthogonal transforms with only about $\mathcal{O}(d\log d)$ parameters by exploiting butterfly factorization (the topology behind the FFT).

Below I unpack that viewpoint and highlight why the butterfly topology is a natural and efficient choice.

## Orthogonal updates as an information transmission problem

Think of an orthogonal finetuning update as replacing a pretrained linear layer $(W^0)^\top x$ by $(R W^0)^\top x$ where $R\in\mathbb{R}^{d\times d}$ is orthogonal and learned (initialized as identity). Instead of learning a single dense $R$, represent it as a product of $m$ square matrices:
R = B_m B_{m-1} \cdots B_1.

Now draw a grid with $d$ nodes in each of the $m+1$ vertical layers. Each factor matrix B_i describes the edges between layer i and i+1: a nonzero entry at position (row i, col j) means information from node j in layer i can reach node i in layer i+1. Multiplying all factors is equivalent to composing these local transmissions: for R to be dense, every source node (first layer) must have a path to every sink node (final layer).

This graph view gives two natural desiderata for a factorization:

- Dense connectivity: every source node should be able to reach every sink node via some path across the layers, so the composed matrix can be dense.
- Minimum free/trainable edges: subject to orthogonality constraints, use as few trainable degrees of freedom as possible to reduce parameter count and regularize learning.

Framing the problem this way makes clear why naive choices (e.g., a single dense orthogonal factor) are parameter-heavy, and why some sparse choices (e.g., block‑diagonal OFT) are cheap but fail to provide dense global connectivity.

## Why the sparsity pattern matters

Two sparse factorizations with the same count of nonzeros can behave very differently because they induce different reachability patterns across the grid. A block‑diagonal orthogonal factor (the OFT variant used earlier for efficiency) partitions the $d$ dimensions into independent groups. That saves parameters, but nodes in one block cannot influence nodes in another block—so the composed R is block‑structured and cannot reproduce many standard transforms or capture cross‑group interactions.

From the information flow perspective, block‑diagonal factors literally cut the network into separate subnetworks; some source→sink paths are impossible. This reduces expressivity in a structured-but-arbitrary way and forces a strong inductive bias that may or may not match the downstream task.

What you want instead is a sparse factorization whose local edges, when composed, allow every source to reach every sink while keeping the number of trainable parameters low. That is where butterfly topologies enter.

## Butterfly topologies: efficient global reachability

Butterfly graphs were discovered in the context of the Cooley–Tukey FFT algorithm. They implement a multi-stage communication pattern where each stage only connects small local pairs, but the composition of stages gives global mixing between all inputs and outputs.

Concretely, for $d=2^N$, a radix‑2 butterfly factor at a given stage consists of independent $2\times 2$ blocks arranged so that across $N$ stages every output depends on every input. If you parametrize each stage with orthogonal $2\times 2$ blocks (rotations), the product of the stages is an orthogonal matrix. With block sizes $b$ and $m$ stages, the BOFT parameter count grows like
O((b - 1) d m) (the paper gives $\frac{1}{2}(b-1)dm$ effective trainable parameters),
and with the canonical butterfly choice $b=2$, $m\approx\log d$, this is $\mathcal{O}(d\log d)$ parameters—far cheaper than $\mathcal{O}(d^2)$.

Why is this attractive?

- Every input can reach every output (dense connectivity) after enough butterfly stages, so the composed transform is dense.
- The number of trainable blocks per stage is linear in $d$, and the number of stages grows logarithmically, giving a favorable tradeoff between expressivity and parameter efficiency.
- The butterfly structure can recover many classical fast transforms (FFT, Hadamard, DCT variants), suggesting the topology is well-matched to signal mixing and useful inductive biases.

## BOFT in practice: how the method is set up

BOFT (Orthogonal Butterfly Finetuning) adopts the above factorization in an OFT-style multiplicative update: the pretrained weight $W^0$ stays frozen, and the finetuned layer computes $(R W^0)^\top x$ where R is the product of orthogonal butterfly components. Important practical points from the paper:

- Orthogonality: each butterfly component is constrained to be orthogonal. In practice this is enforced via Cayley parameterization (a standard skew-symmetric parameterization) or 2×2 rotations at the smallest block granularity.
- Identity initialization: to start from the pretrained model exactly, BOFT initializes all butterfly components as identity (zero skew-symmetric parameters), analogous to zero initialization in additive methods like LoRA.
- Multiplicative Dropout: ordinary dropout does not naturally apply to multiplicative updates. BOFT proposes a multiplicative dropout that randomly replaces some butterfly components or blocks with identity matrices during finetuning to regularize and prevent overfitting.
- Flexibility: BOFT generalizes OFT. With one stage and block size $b$ it reduces to block‑diagonal OFT; with $m=\log d$ and $b=2$ it realizes the canonical butterfly giving dense R with $\mathcal{O}(d\log d)$ parameters. Larger block sizes give intermediate tradeoffs.

## Expressivity, inductive bias, and tradeoffs

A few conceptual takeaways the paper emphasizes:

- Expressivity vs. regularity: full dense orthogonal R is maximally expressive but large and can overfit. Block‑diagonal R is small but overly restrictive. Butterfly-structured R sits between them, giving structured expressivity and a smoother interpolation between identity and full orthogonal transforms.
- The butterfly family can represent many useful transforms exactly; with more complex compositions (kaleidoscope-type products of butterflies) it can approximate the whole orthogonal group. But more expressivity is not always better for finetuning; restricting the hypothesis class can improve generalization.
- BOFT preserves spectral norms of the pretrained weight matrices (left multiplication by an orthogonal matrix does not change singular values), which helps training stability.

## Limitations and open points

The approach is not free: multiplying multiple factor matrices in the forward pass adds some training-time overhead compared to few-parameter additive updates. The paper notes this runtime cost, but also that the learned R can be merged into the network weights after finetuning so there is no extra inference cost.

Another open question is whether the butterfly topology is the most parameter‑efficient communication pattern for this goal. The information‑transmission framework introduced in the paper invites exploration of other network topologies from communication and networking literature that might provide even better parameter vs. expressivity tradeoffs.

## Takeaway

Recasting orthogonal finetuning as routing information through a grid is a compact but powerful idea: it exposes why different sparse factorization choices behave so differently and gives a principled way to choose them. The butterfly topology is a practical, well‑motivated choice that delivers dense effective transforms with far fewer parameters than a dense orthogonal matrix, while preserving useful inductive bias and spectral properties. If you are looking for a multiplicative, orthogonality‑preserving finetuning method that balances expressivity and parameter efficiency, BOFT is a conceptually clean and practically attractive option grounded in this information‑flow view.



# BOFT vs. OFT vs. LoRA: Trade-offs in Parameters, Expressivity, and Stability

Efficiently adapting giant pretrained models is now essential. Three popular parameter-efficient finetuning (PEFT) paradigms approach the problem differently: LoRA (low-rank additive updates), OFT (orthogonal multiplicative updates), and BOFT (orthogonal updates with butterfly factorization). This post breaks down how they compare along three axes you care about — parameter cost, expressivity, and stability/generalization — and offers practical guidance on when to pick each.

## The core ideas (short and precise)

- LoRA: adds a low-rank update to a frozen weight matrix. Concretely, a weight matrix $W^0$ is updated as $W = W^0 + A B$ where $A\in\mathbb{R}^{d\times r}$ and $B\in\mathbb{R}^{r\times n}$ with small rank $r$. Very parameter-efficient when $r \ll d$.

- OFT (Orthogonal Finetuning): replaces the pretrained weight by a multiplicative orthogonal transform on the left: $W = R W^0$ with $R\in\mathbb{R}^{d\times d}$ and $R^\top R = I$. This preserves geometric relations (pairwise angles) between neurons and keeps singular values of $W^0$ unchanged. Full OFT requires $O(d^2)$ parameters; practical versions use block-diagonal $R$ to save parameters.

- BOFT (Orthogonal Butterfly Finetuning): parameterizes a dense orthogonal $R$ as a product of sparse orthogonal factors arranged in butterfly structure (inspired by FFT). With block size $b$ and $m$ butterfly layers, BOFT uses about
  $$
  \text{params}\ \approx\ \tfrac{1}{2}(b-1)d m
  $$
  and the canonical butterfly choice ($b=2$, $m=\log d$) yields $O(d\log d)$ parameters — dramatically fewer than full OFT while still producing dense orthogonal transforms.

BOFT subsumes OFT as special cases: (i) BOFT$(1,b)$ equals block-diagonal OFT with block size $b$, and (ii) BOFT$(1,d)$ equals full OFT.

## Why orthogonality matters (angles and spectra)

Two properties explain why OFT and BOFT can produce more stable finetuning than simple additive updates:

- Angle preservation. Multiplying neuron vectors by the same orthogonal $R$ preserves pairwise angles between columns of $W^0$. Preserving these relational structures is argued to help retain pretrained semantic geometry.

- Spectral preservation. If $W^0 = U \Sigma V^\top$ is an SVD, then $R W^0 = (R U)\Sigma V^\top$. Because $R$ is orthogonal, the singular values (diagonal of $\Sigma$) are unchanged. Keeping the spectral norm of pretrained layers stable is known to improve training stability and generalization.

LoRA does not preserve angles or the singular values in general because it adds a low-rank perturbation.

## The expressivity — block-diagonal OFT can be too rigid

Full OFT (unconstrained orthogonal $R$) is maximally expressive among orthogonal multiplicative updates, but it costs $O(d^2)$ parameters. To reduce cost, OFT often uses block-diagonal $R=\mathrm{diag}(R_1,\dots,R_r)$ with small block size $b$. That saves parameters (roughly $O(bd)$) but enforces that different coordinate groups are transformed independently. This induces a strong sparsity pattern that cannot represent many global linear transforms (for example, it cannot recover classic dense transforms such as FFT or Hadamard). In other words, block-diagonal OFT trades expressivity for parameter savings by imposing a rigid, index-based grouping.

BOFT offers a smoother trade-off. By composing multiple sparse factors in a butterfly topology, BOFT can produce dense orthogonal matrices while keeping parameter count low. The butterfly structure is known to efficiently transmit information across all coordinates; with $\log d$ sparse layers each having $O(d)$ nonzeros, you get dense connectivity with only $O(d\log d)$ free parameters. Practically this means BOFT can:

- Recover many classic fast transforms (FFT, Hadamard, DCT) because those transforms share butterfly-like structure.
- Be more expressive than block-diagonal OFT for the same local block size, while still being far more parameter-efficient than full OFT.

The paper also formalizes that BOFT with suitable compositions (kaleidoscope-style products of butterflies) can approximate the full orthogonal group — though, importantly, more expressivity is not always better for finetuning.

## Parameter costs (summary)

- Full OFT: O(d^2) trainable parameters (dense orthogonal).
- Block-diagonal OFT: O(b d) parameters when splitting into blocks of size $b$ (very cheap when $b\ll d$, but rigid).
- BOFT: about $\tfrac{1}{2}(b-1) d m$ parameters for BOFT$(m,b)$. The canonical dense-targeting butterfly BOFT with $b=2$, $m=\log d$ gives $O(d\log d)$ parameters.

Compare these to LoRA: LoRA uses $O(dr)$ parameters per finetuned layer (rank $r$); typically $r$ is small, so LoRA is also highly parameter-efficient and often cheaper than BOFT for small $r$.

## Training dynamics and engineering trade-offs

- Stability and generalization. Orthogonal updates (OFT/BOFT) preserve spectral norms and pairwise geometry, which empirically helps training stability and generalization on many tasks, according to the paper. LoRA, while effective, lacks these invariants.

- Initialization. BOFT (like OFT) initializes the orthogonal factors to identity (via Cayley parameterization with zero skew-symmetric factors), ensuring zero initial change and preserving pretrained behavior at start of finetuning.

- Regularization mechanisms. BOFT introduces a multiplicative dropout adapted to multiplicative updates: randomly replace selected butterfly component blocks with identity during training to prevent overfitting. LoRA typically uses conventional dropout on activations or on low-rank updates.

- Runtime. BOFT requires repeated multiplication of multiple sparse factors during training, so its runtime per update is higher than single-matrix block-diagonal OFT or simple LoRA updates. However, after finetuning the learned orthogonal $R$ can be folded into the base weights, so there is no inference overhead.

## When to use each method

- Use LoRA when your primary constraint is an extremely small tunable-parameter budget and you accept a low-rank inductive bias. LoRA is simple, fast, and very parameter-efficient; it is a good default when you know low-rank structure suffices.

- Use full OFT when you want the strongest orthogonal invariants (angle and spectrum preservation) and you can afford $O(d^2)$ parameters for the critical layers. This is rare for large models but might be viable for small/medium layers where you prioritize geometry preservation.

- Use block-diagonal OFT when you want orthogonal invariants but only modest parameter cost and you believe a per-block independent transform is acceptable. This is fast and cheap but can be overly restrictive if global mixing across coordinates matters.

- Use BOFT when you want a middle ground: orthogonality-based invariants plus much lower parameter cost than full OFT, while preserving expressivity far beyond block-diagonal OFT. BOFT is especially attractive when you need dense global transformations (so grouping-based sparsity would hurt) but cannot afford quadratic parameter counts. Expect a modest training-time overhead, but no extra inference cost after folding.

## Caveats and practical notes

- BOFT improves parameter-efficiency by trading computation for space: you do more (sparse) multiplications during training to represent a dense orthogonal $R$ compactly. The paper notes that training runtime overhead is higher and improving training speed is an open direction.

- More expressivity does not always equal better finetuning. Full expressivity (e.g., full OFT or extremely flexible BOFT compositions) can overfit; the structured constraint of BOFT can act as a beneficial inductive bias by resembling classic fast transforms.

- BOFT has been empirically validated across adaptations of vision transformers, language models, and text-to-image diffusion models in the paper; the authors report BOFT outperforms strong baselines across a range of tasks, demonstrating both parameter-efficiency and generalization gains.

## Takeaway

- LoRA = very cheap additive low-rank updates; good when low-rank is appropriate.
- OFT = orthogonal multiplicative updates; preserves neuron angles and spectra, which aids stability, but full OFT is expensive. Block-diagonal OFT saves parameters at the cost of expressivity.
- BOFT = orthogonal multiplicative updates with butterfly factorization; hits the sweet spot in many cases: preserves orthogonal invariants, yields dense transforms, and does so with O(d log d) (or tunable) parameters. Expect modest extra training cost but no inference cost.

If you care about preserving pretrained geometry and need a dense-like transform without quadratic parameters, BOFT is a compelling option — it smooths the expressivity/regularization trade-off that block-diagonal OFT enforces too abruptly.



# A Practical BOFT Playbook: Hyperparameters, Initialization, and Dropout

Orthogonal Butterfly Finetuning (BOFT) is a parameter-efficient way to adapt large pretrained models by multiplying a learnable orthogonal matrix into each layer's weights. BOFT composes a dense orthogonal transform from a product of sparse, structured factors (butterfly components), giving a tunable trade-off between expressivity and parameter count. This post gives concise, practical guidance for choosing BOFT hyperparameters, initializing the factors, using the multiplicative Dropout that the BOFT framework introduces, and integrating BOFT into existing finetuning pipelines.

## Quick BOFT recap (what you need to know)
- BOFT represents the left-multiplicative finetuning transform as an orthogonal matrix
  R(m,b) = \prod_{i=1}^m \tilde{B}_{(d,i)}^b,
  where each \tilde{B}_{(d,i)}^b is a block-wise butterfly component.  
- Notation BOFT(m,b): m = number of butterfly components (depth), b = block size (even-valued building block). Typical constraints from the construction: d is the layer dimension and block factors tile d.
- Parameter count (effective trainable parameters) for a linear layer of width d: approximately (1/2)(b - 1) d m. In particular:
  - Butterfly regime: m \approx \log d and b = 2 gives \mathcal{O}(d\log d) parameters.
  - m = 1 recovers block-diagonal OFT with block size b.
  - m = 1 and b = d recovers full OFT (dense orthogonal).
- BOFT preserves the spectral norm of the pretrained weight matrix (left-multiplying by orthogonal R), which helps training stability.

With that foundation, here are actionable recommendations.

## Choosing m (depth) and b (block size)
BOFT gives a two-dimensional knob to control capacity vs parameter-efficiency:

- Intuition:
  - Larger m (more factors) and smaller b (smaller block size per factor) increase expressivity per parameter because repeated sparse factorization mixes coordinates more thoroughly.
  - Smaller m and larger b favor simplicity / regularity (fewer composition steps), approaching block-diagonal or full orthogonal cases.

- Practical guidance:
  - When your parameter budget is tight and you want a dense transform, favor the butterfly regime: set b = 2 and increase m toward \log d. This yields the classic butterfly factorization and achieves dense connectivity with \mathcal{O}(d\log d) parameters.
  - If you want an intermediate capacity between block-diagonal OFT and full orthogonal, choose moderate b (e.g., small multiples of 2) and increase m. Smaller b with larger m tends to be more expressive than the opposite for the same parameter budget.
  - If you want a cheap, low-capacity adaptation (very strong regularity), use m = 1 and choose b small; this is exactly block-diagonal OFT with block size b.
  - When compute is not restrictive and you desire maximal expressivity, BOFT(1,d) reproduces full OFT (dense orthogonal), but it costs \mathcal{O}(d^2) parameters.

- How to decide in practice:
  - Start by computing your layer width d and your parameter budget per layer.
  - Use the rough parameter formula (1/2)(b - 1) d m to find feasible (m,b) pairs that fit your budget.
  - Prefer configurations with smaller b and larger m for higher expressivity per parameter when you need a dense-style transform.
  - If you expect the downstream task to require only modest adaptation (e.g., domain shift or light style changes), start conservative (small m) and scale up if performance stalls.

Note: the paper frames expressivity formally: BOFT with smaller b and larger m generally approximates dense orthogonals more efficiently than plain block-diagonal OFT with the same block size.

## Identity initialization via Cayley transform
For stable finetuning you want R to be the identity at initialization so the pretrained model's behavior is unchanged by BOFT at the start.

- Cayley parameterization used in BOFT:
  - Parameterize each orthogonal factor by a skew-symmetric matrix Q (Q = -Q^T) and the Cayley transform
    R_factor = (I + Q) (I - Q)^{-1}.
  - To initialize R_factor = I, set the skew-symmetric Q to the zero matrix. This yields (I + 0)(I - 0)^{-1} = I.

- Practical tips:
  - Initialize the internal skew-symmetric parameters to zero for all butterfly component blocks; this yields exact identity initialization across the composed R(m,b).
  - Identity init means the forward pass initially uses the original pretrained weights exactly. This is convenient for small-step, stable finetuning and avoids the need for careful learning-rate scaling at the very start.
  - Keep in mind numerical stability when computing (I - Q)^{-1}. For the low-dimensional blocks used in BOFT (many are 2-by-2 or small blocks), Cayley inverses are cheap and stable; use robust linear solvers rather than naive matrix inverse where possible.

## Multiplicative Dropout (BOFT-style Dropout)
Traditional additive Dropout does not match BOFT's multiplicative update pattern (R multiplies weights). BOFT introduces a multiplicative Dropout tailored to block-wise, multiplicative orthogonal factors.

- Mechanism (as given in the paper):
  - BOFT is made of m orthogonal butterfly components. Each component is itself block-diagonal with block size b in a given stage.
  - Multiplicative Dropout randomly selects:
    - p1 fraction of the butterfly components (entire components), and
    - p2 fraction of the diagonal blocks inside each chosen component,
    and replaces those selected blocks with identity blocks for that training step.
  - Effectively you are turning some factor blocks off by setting them to identity multiplicatively, which reduces the effective adaptation strength and prevents overfitting.

- Practical guidelines:
  - Use multiplicative Dropout when you see overfitting or when the chosen (m,b) yields a relatively large parameter budget for the available training data.
  - Start with modest p1 and p2 (e.g., small percentages) and increase if overfitting persists. The paper does not give exact recommended values; tune p1/p2 on a held-out validation set.
  - Because multiplicative Dropout replaces blocks with identity, it is consistent with identity initialization and does not introduce distributional shifts at initialization.
  - Implement Dropout per training step (randomly sample blocks each iteration) similar to standard Dropout semantics.

## Integration tips for existing training pipelines
BOFT can be slotted into common finetuning setups with a few considerations.

- Where to apply:
  - BOFT applies to left-multiplicative updates of linear layers (weight matrices W^0). Typical choices: MLP/FFN linear layers, projection matrices in attention modules, or other dense layers where preserving pretraining geometry matters.

- Forward pass and inference:
  - During training, compute z = (R(m,b) \cdot W^0)^\top x. This requires composing the butterfly factors each forward pass (or applying them sequentially).
  - After finetuning, you can fold the learned R into the pretrained weights: replace W^0 with R(m,b) W^0 and discard BOFT parameters. There is no additional inference latency after folding.

- Compute / runtime:
  - BOFT increases training computation because R is a product of multiple factors; you will have extra matrix multiplies during training. The paper notes runtime overhead is slightly larger than OFT. Expect a modest training-time cost in exchange for parameter savings and possibly better generalization.
  - To reduce overhead, apply BOFT only to a subset of layers (e.g., large FFN layers or projection matrices), or use smaller m where necessary.

- Optimizer and learning-rate advice:
  - Because BOFT is initialized to identity, treat BOFT parameters like small-magnitude learnable transforms: start with conservative learning rates for these parameters. The paper follows the general OFT philosophy of small-step updates to preserve pretrained structure.
  - You can use the same optimizer used for the rest of finetuning; consider tuning separate learning rates for BOFT parameters vs other newly added parameters.

- Implementation checklist:
  - Ensure block sizes divide the layer dimension d and are compatible with the butterfly tiling strategy.
  - Parameterize block-wise skew-symmetric Q matrices and implement the Cayley transform robustly (prefer solving linear systems to explicit inversion).
  - Implement multiplicative Dropout by masking selected component blocks to identity each training step.
  - Provide a utility to fold the learned R into W^0 after training for zero-cost inference.

## Practical troubleshooting and heuristics
- If training diverges early: verify identity initialization (all Q blocks zero), reduce BOFT learning rate, or reduce the fraction of active blocks via multiplicative Dropout.
- If val performance is worse than simple LoRA or small adapters: your BOFT setup may be too expressive for the available data. Reduce m or increase Dropout, or test a larger b with smaller m to bias toward regularity.
- If you have ample compute but tight parameter budget: favor smaller b and increase m (but be mindful of training-time overhead).
- Folding for deployment: always validate that folded weights exactly reproduce behavior on a test batch before discarding BOFT parameters.

## Summary checklist
- Select (m,b) to meet a parameter budget using the formula \#params \approx (1/2)(b - 1) d m; prefer smaller b with larger m for dense connectivity and higher expressivity per parameter.
- Initialize all skew-symmetric parameters to zero and use the Cayley transform to get identity-initialized orthogonal factors.
- Use multiplicative Dropout by replacing randomly selected butterfly components / blocks with identity during training to reduce overfitting.
- Apply BOFT selectively to large weight matrices, fold the learned R into pretrained weights for inference, and be mindful of modest extra training cost.

BOFT offers a flexible, structured middle ground between block-diagonal OFT and fully dense orthogonal finetuning. With identity init and multiplicative Dropout in your toolbox, you can control the capacity and regularity of the finetuning transform and integrate BOFT into standard finetuning workflows while keeping inference overhead zero after folding.

# Why Orthogonality Helps: Preserving Angles and Spectral Norms for Safer Fine-Tuning

Fine-tuning large pretrained models is now routine, but it can be fragile. Small changes to weights can disrupt internal geometries learned during pretraining, leading to instability or poor generalization on downstream tasks. Orthogonal finetuning (OFT) and its parameter-efficient variant Orthogonal Butterfly (BOFT) offer a compelling remedy: update weights via orthogonal transforms so that the relative geometry of neurons and crucial spectral properties are preserved. This post explains, without heavy math, why those two properties matter and how BOFT delivers them while remaining parameter-efficient.

## What does “orthogonal update” mean in practice?

Consider a pretrained linear layer with weight matrix \(W^0\). Traditional fine-tuning directly changes entries of \(W^0\). OFT instead reparameterizes the finetuned weight as
\(W = R\,W^0\),
where \(R\) is an orthogonal matrix (so \(R^\top R = I\)). That means we are rotating / reflecting the row space of the layer rather than arbitrarily stretching or skewing it.

Two practical design choices from the paper make this usable in large models:

- Orthogonality is enforced during optimization (e.g., using Cayley parameterization), so \(R\) stays orthogonal at all times.
- BOFT builds \(R\) not as a dense \(d\times d\) free matrix, but as a product of structured sparse orthogonal factors (butterfly components). That yields a dense \(R\) with far fewer trainable parameters (roughly \(\mathcal{O}(d\log d)\) instead of \(\mathcal{O}(d^2)\) in the fully unconstrained case).

BOFT also initializes all factors to identity (so initial \(R=I\)) and can apply a multiplicative dropout that randomly replaces some factors with identity during training to avoid overfitting.

Now let’s unpack why the orthogonality constraint is beneficial.

## 1) Preserving pairwise neuron relationships (angles)

Neurons in a layer can be viewed as vectors (columns or rows of \(W^0\)). The pairwise angles between these vectors encode geometric relationships developed during large-scale pretraining — relationships that likely capture important semantic structure.

An orthogonal transform \(R\) preserves angles and lengths: if two vectors \(u\) and \(v\) are transformed to \(Ru\) and \(Rv\), their dot product (and thus the cosine of the angle between them) remains the same. So applying \(R\) to \(W^0\) keeps the relative directions of neurons intact while permitting a global, rigid transformation.

Why does that help?

- It keeps pretraining-induced geometry stable. Small supervised datasets can otherwise nudge neurons into configurations that break those learned relationships, causing brittle behavior.
- By constraining updates to rotations/reflections, OFT/BOFT reduce the effective hypothesis space explored during fine-tuning. That acts as a regularizer which can improve generalization: we are searching only among models that keep the pretrained relational structure.

The paper emphasizes this angle-preserving view as a principled alternative to ad-hoc small learning rates. Instead of merely "moving weights a little," orthogonal updates guarantee a precise invariant (angles) that aligns with the intuition that pretrained models encode meaningful relational geometry.

## 2) Preserving spectral norms (stability)

Another important property: multiplying an orthogonal matrix on the left does not change the singular values of \(W^0\). If \(W^0 = U \Sigma V^\top\) is its SVD, then
\(R W^0 = (R U)\, \Sigma\, V^\top\),
and the diagonal singular-value matrix \(\Sigma\) is unchanged. The largest singular value (spectral norm) remains identical.

Why is spectral norm preservation useful?

- The spectral norm controls how much the layer can amplify inputs. Large increases can destabilize gradients, worsen optimization, and lead to brittle models.
- Methods that preserve the spectral properties of pretrained weights maintain the same input-output sensitivity as the pretrained model, providing a safer optimization landscape for downstream adaptation.

Empirically and theoretically, preserving or controlling spectral norms has been tied to training stability and better generalization; OFT/BOFT inherit those benefits by construction.

## 3) BOFT as learning a structured bilinear similarity under strong regularization

Viewed from another angle, OFT/BOFT are learning a bilinear similarity: each neuron response is of the form \(w_i^\top R x\), where \(w_i\) is a pretrained neuron and \(R\) is the learned orthogonal transform. So the learning problem reduces to finding a single (layer-shared) bilinear form \(R\) that adapts the pretrained features to the downstream task.

BOFT adds two important ingredients to this picture:

- Strong regularization: \(R\) must be orthogonal, which is a hard constraint rather than a soft penalty. This shrinks the hypothesis class to rotations/reflections and enforces stability.
- Structured parameter-efficiency: instead of a free dense orthogonal \(R\), BOFT parameterizes \(R\) as a product of sparse orthogonal "butterfly" factors. This imposes an inductive bias (a structured subset of the orthogonal group) that is expressive enough to recover many classical transforms (Fourier, Hadamard, etc.) but far smaller in parameter count.

The result is that BOFT is learning a compact, structured bilinear similarity matrix that respects pretraining geometry and spectral behavior while being cheap to store and optimize.

## 4) The expressivity / regularity trade-off — why structure helps

Full fine-tuning is maximally expressive but often overfits or destabilizes training. Extremely constrained schemes (e.g., tiny block-diagonal orthogonal updates) are very stable but may lack expressivity needed for certain tasks. BOFT sits between these extremes.

- The butterfly factorization composes a small number of sparse orthogonal blocks so that, even with few parameters, the product can produce dense, globally mixing transforms.
- The paper shows BOFT can be substantially more expressive than simple block-diagonal OFT for the same parameter budget, yet still far more constrained than unconstrained dense orthogonal matrices.

This structured inductive bias—reflecting patterns common in fast linear transforms—appears to help generalization in experiments across vision, language, and generative models.

## 5) Practical touches: initialization and overfitting control

Two pragmatic choices in BOFT make the orthogonal approach work smoothly:

- Identity initialization. All butterfly factors are initialized as identity so the fine-tuned model starts exactly from the pretrained model (no sudden jump).
- Multiplicative dropout. Because the update is multiplicative (not additive), standard dropout doesn’t apply directly. BOFT randomly replaces some factors or blocks with identity during training, effectively regularizing the multiplicative transform.

These strategies help prevent overfitting and stabilize optimization.

## Limitations and trade-offs

BOFT reduces parameter count substantially, but it does add some runtime overhead during training because the orthogonal \(R\) is represented as a product of factors that must be multiplied each forward/backward pass. The paper notes this as an area for future improvement. Also, butterfly factorization is a principled and practical design choice, but whether it is the optimal sparse topology for every task is an open question.

## Takeaways

- Orthogonal finetuning preserves pairwise neuron angles and the singular values of pretrained weights. Those invariants help stabilize training and improve generalization compared to unconstrained updates.
- BOFT achieves the same invariants while being parameter-efficient: it learns a structured bilinear similarity (a layer-shared orthogonal \(R\)) using butterfly factorization, which yields dense transforms from very few parameters.
- The combination of exact geometric invariants and a structured inductive bias gives a practical middle ground between full fine-tuning and overly rigid adapters—safer fine-tuning that still adapts effectively.

If you care about preserving pretrained geometry and spectral behavior while keeping the finetuning budget low, orthogonal finetuning—especially BOFT—offers a principled option worth trying.



# One Method, Many Domains: BOFT Across Vision, Language, and Diffusion Models

## What BOFT is (short version)

BOFT (Orthogonal Butterfly Finetuning) is a parameter-efficient way to finetune large pretrained models. Instead of adding low-rank updates (like LoRA) or fully finetuning all weights, BOFT multiplies the pretrained layer by a learned orthogonal matrix R. The trick is that R is not stored as a dense d×d matrix (which costs O(d^2) parameters). BOFT factorizes R into a product of sparse, orthogonal "butterfly" components so that a dense transform is composed from O(d log d) parameters (roughly speaking) while keeping desirable orthogonality properties.

Key technical points:
- The orthogonal update keeps the pretrained weight singular values unchanged (multiplying on the left by an orthogonal R preserves spectral norm).
- Each butterfly component is parameterized so it stays orthogonal (e.g., via Cayley transforms / 2×2 block rotations), and the full R is a product of these components.
- BOFT uses identity initialization (R starts as I) and a multiplicative dropout adapted to the multiplicative nature of the update.

## Why this matters across domains

The paper applies BOFT to three different classes of foundation models: large vision transformers, large language models (LLMs), and text-to-image diffusion models. The same core idea—learn a constrained, structured orthogonal transform per layer—works across these very different architectures. That’s notable: a single finetuning mechanism that preserves spectral properties and introduces a controlled inductive bias generalizes across modalities.

Two reasons this shared structure helps cross-domain generalization:

1. Preserving pretrained geometry. Multiplying by an orthogonal R preserves pairwise angles among neurons and the singular values of pretrained layers. That helps keep the useful pretraining geometry intact, which is a domain-agnostic benefit: vision, language, and diffusion stacks all rely on pretrained structure.

2. A useful inductive bias from butterfly structure. Butterfly matrices are the sparse building blocks behind many classic fast transforms (FFT, Hadamard, etc.). By representing R as a product of such sparse orthogonal factors, BOFT restricts the finetuning hypothesis class to structured orthogonal transforms. This structured bias is expressive enough to approximate many useful dense transforms, yet small enough to regularize finetuning and reduce overfitting. Because many modalities encode global-local mixing patterns similar to Fourier/Hadamard-like behavior, the butterfly prior can be helpful across domains.

## Empirical takeaways (plain language)

The paper reports an extensive empirical study showing BOFT is practical and competitive when adapting large foundation models. While the paper tests a variety of tasks, the headline observations are:

- BOFT achieves strong downstream performance while using far fewer learnable parameters than a full orthogonal matrix or full finetuning. With the butterfly factorization (e.g., m ≈ log d, block size b = 2), the parameter count scales like O(d log d) instead of O(d^2).
- BOFT subsumes the earlier Orthogonal Finetuning (OFT) as a special case: with particular settings, BOFT reduces to block-diagonal OFT or to a full orthogonal OFT. In practice, intermediate settings give a smoother trade-off between expressivity and regularization.
- Across vision transformers, LLMs, and text-to-image diffusion models, BOFT finetuning is stable and generalizes well. The spectral preservation and structured parameterization help training stability compared to some other parameter-efficient schemes.
- Compared to block-diagonal OFT, BOFT can produce dense orthogonal transforms with far fewer parameters and without imposing rigid block sparsity that breaks expressivity. Compared to low-rank additive schemes (LoRA), BOFT offers different regularization (multiplicative, orthogonality) that can outperform or complement low-rank updates depending on task and capacity budget.

The paper emphasizes that BOFT is a practical middle ground: more expressive than block-diagonal OFT at the same block size, but far more parameter-efficient than naive dense OFT.

(Note: the paper presents detailed experiments across many datasets and model families; this summary keeps the focus on qualitative conclusions and cross-domain applicability rather than listing task-by-task numbers.)

## How BOFT fits with other PEFT approaches

There are two broad families of parameter-efficient finetuning (PEFT): additive low-rank updates (LoRA family) and multiplicative reparameterizations (OFT family). BOFT belongs to the multiplicative, orthogonality-preserving family but borrows the parameter-efficiency idea from sparse factorization:

- LoRA: add a low-rank matrix ΔW = AB^T. Very parameter-efficient; operates additively.
- OFT: multiply pretrained weights W^0 by an orthogonal R, preserving angle structure; but dense R is costly.
- BOFT: keep OFT’s orthogonality and spectral preservation, but parameterize R as a product of sparse orthogonal butterfly factors so you can get a dense effective transform while using O(d log d) parameters.

So BOFT is complementary to low-rank methods; it trades a different inductive bias (orthogonality + butterfly sparsity) for parameter savings.

## Practical notes and limitations

- Identity initialization is used so finetuning starts from the pretrained model exactly (R = I). That mirrors best practice in other PEFT methods (e.g., zero-init LoRA) and helps stable adaptation.
- BOFT introduces some extra training-time computation because the learned R is a product of several factors (so each forward pass multiplies through those factors). That increases runtime during training compared to single-matrix updates; however, at inference time the learned R can be folded back into the pretrained weights so there is no extra inference cost.
- BOFT is not guaranteed to be the absolute minimal parameterization for transmitting information; the paper frames the design in terms of an "information transmission" graph and points out that other network topologies (beyond butterfly) might yield different trade-offs. Finding the optimal sparse factorization remains an open area.
- More expressive factorizations (more components, different block sizes) increase representational power but also raise the effective parameter count; BOFT provides knobs to tune that trade-off.

## Bottom line

BOFT is a single, conceptually simple finetuning recipe that works across vision transformers, LLMs, and diffusion models. It keeps the principal benefits of orthogonal finetuning (spectral and relational preservation), while drastically improving parameter efficiency by factorizing the orthogonal update into butterfly-structured sparse factors. That combination—structured multiplicative updates, identity initialization, and a cross-domain-friendly inductive bias—explains why BOFT is effective across modalities and architectures.

If you care about parameter budgets and stable adaptation of large pretrained models in multiple domains, BOFT is a compelling option to try.



# Beyond Butterflies: Future Network Topologies for Efficient Fine-Tuning

The Orthogonal Butterfly (BOFT) paper introduces a neat idea: factor a dense orthogonal update into a product of sparse orthogonal factors so you can finetune large pretrained layers with far fewer parameters. BOFT uses butterfly-structured factors (inspired by the Cooley–Tukey FFT) to get dense connectivity with only \(\mathcal{O}(d\log d)\) trainable parameters instead of \(\mathcal{O}(d^2)\). This is an elegant use of a classic network topology to meet two core desiderata for factorized orthogonal finetuning: dense connectivity (every input node can reach every output node after composing factors) and minimum free edges (few trainable non-structural degrees of freedom under orthogonality).

But the paper is explicit about open questions and limitations. Two that stand out are: (1) BOFT imposes runtime overhead because multiple factor matrices must be multiplied during training, and (2) butterfly is a compelling but not necessarily optimal topology for this information-transmission problem. This post digs into both issues and sketches principled directions for future work — drawing on the paper’s information-transmission view and the parallel literature on network topologies — without claiming results beyond the paper.

## Recap: why factorize an orthogonal update?

OFT reparameterizes a finetuned weight as \(\bm{R}\bm{W}^0\) where \(\bm{R}\in\mathbb{R}^{d\times d}\) is orthogonal; this preserves pairwise angles and the spectral norm of \(\bm{W}^0\). Dense \(\bm{R}\) gives expressivity but costs \(\mathcal{O}(d^2)\) parameters. BOFT composes \(\bm{R}\) as a product of sparse orthogonal factors
\(\bm{R}=\prod_{i=1}^m \tilde{\bm{B}}_i\),
where carefully chosen sparsity (the butterfly pattern) yields dense overall connectivity while keeping effective trainable parameters at roughly \(\mathcal{O}(dm)\) (for radix-2 butterfly with \(m\approx\log d\), this is \(\mathcal{O}(d\log d)\)). BOFT also preserves desirable spectral properties and starts factors at identity (Cayley parametrization with zero skew-symmetric initializers), plus multiplicative dropout that respects the multiplicative factorization.

So BOFT trades space (parameters) for time (additional factor multiplications per forward/backward). The paper frames this as an information transmission problem on a \(d \times (m+1)\) grid and shows butterflies are a topology that efficiently achieves the dense-transmission requirement.

## Two practical pain points the paper calls out

1. Training-time overhead. Because \(\bm{R}\) is built from \(m\) sparse orthogonal factors, each training iteration must apply (and backprop through) multiple factor multiplications. This increases runtime compared to directly applying a block-diagonal OFT or a LoRA-style additive update. The paper notes that BOFT has slightly larger training runtime and flags reducing that overhead as an open problem.

2. Is butterfly optimal? Butterflies are attractive because they give dense reachability with only \(O(d\log d)\) edges and match classic fast transforms. But the paper explicitly leaves open whether there exist other network topologies — informed by the computer networking literature — that transmit information even more efficiently under the orthogonality constraint and with better trade-offs between parameter count, expressivity, and runtime.

Both issues are fundamentally connected: a better topology could reduce the number of factor layers \(m\) (reducing runtime) or the per-factor block size \(b\) (reducing parameters), or both.

## How to think about alternative topologies (guided by the paper)

The paper provides an information-transmission abstraction that gives a clean way to evaluate any candidate topology. Any factorization corresponds to a directed layered graph on \(d\) nodes per layer; each sparse orthogonal factor encodes edges between consecutive layers. For a factorization to yield a dense final matrix \(\bm{R}\), every source node (layer 1) must have a path to every sink node (layer \(m+1\)). Under orthogonality, we should also respect structural constraints (e.g., each factor must be full-rank and orthogonal).

When evaluating or designing alternative topologies, the following metrics (implicit in the paper) are useful:

- Edge efficiency: total number of trainable degrees of freedom (roughly proportional to number of nontrivial edges that are not fixed by orthogonality). BOFT aims for \(\mathcal{O}(d\log d)\).
- Depth \(m\): number of factor layers — smaller \(m\) generally reduces runtime overhead.
- Local block size \(b\) and block structure: larger blocks increase per-factor expressivity (and parameter count), smaller blocks reduce parameters but may require more layers.
- Connectivity/diameter: how many hops are needed for any source-to-sink path? Lower diameter often helps expressivity for a given depth.
- Orthogonality compatibility: can each factor be parameterized as orthogonal easily (e.g., via Cayley on small blocks or 2×2 rotations)?
- Recoverability of classic transforms: do the factors and permutations cover well-known transforms (implicit bias useful for generalization)?

Using these as evaluation axes keeps us faithful to the paper’s framing while opening the design space beyond butterflies.

## Candidate directions to explore (all consistent with the paper’s framework)

The paper points to the networking literature as a source of alternative topologies. Below are grounded, paper-consistent directions to investigate.

1. Search for sparser depth-vs-width trade-offs
   - The butterfly achieves dense connectivity with depth \(m\approx\log d\). But perhaps other layered topologies can achieve the same reachability with smaller \(m\) at the cost of slightly more edges, or reduce parameter coefficient constants (improving practical efficiency). The paper suggests combining ideas from networking; this invites systematic searches (analytical or learned) over layered graph families subject to orthogonality constraints.

2. Consider layered permutations and blockings (structured permutations)
   - BOFT already uses permutations implicit in butterfly components. Combining targeted permutations with small orthogonal blocks could reduce the number of layers required to reach dense connectivity. Since permutations are parameter-free, they can be used to trade parameter count vs depth without affecting orthogonality parametrization complexity.

3. Kaleidoscope / composite hierarchies
   - The paper notes kaleidoscope hierarchies (products of butterfly-like matrices and transposes) can represent the full orthogonal group when stacked appropriately. Studying shallow kaleidoscope instantiations (fewer blocks but richer interleavings) could hit sweet spots between expressivity and runtime.

4. Borrowing topology concepts (while respecting the paper’s caution)
   - The networking literature studies many topologies with different trade-offs (e.g., Benes networks, Clos/Fat-tree, expander-like constructions). The paper does not analyze these specifically, but its information-transmission view provides the bridge: each candidate topology must be cast as a layered factorization where each factor is orthogonal or decomposable into small orthogonal blocks.
   - For instance, expanders have excellent connectivity with low degree; if there is an orthogonality-preserving way to realize an expander-like layer decomposition, that could reduce parameter count while keeping small depth. Any such topology must also satisfy the orthogonality parameterization constraints described in the paper.

5. Learnable sparsity patterns within the information-transmission framework
   - Instead of fixing a topology (butterfly or otherwise), one can parameterize a family of sparse layered graphs with learnable binary structure (or sparsity masks) and optimize the structure jointly with the factor parameters, subject to constraints that permit orthogonal parametrization (e.g., blockwise Cayley transforms). The paper mentions multiplicative dropout and identity init; these mechanisms could be combined with structure learning to gradually reveal effective edges.

6. Hardware- and runtime-aware factor selection
   - The paper notes training-rate overhead as an engineering limitation. Practical follow-ups can explore:
     - Kernels that fuse the product of multiple sparse factors into a single batched operation to reduce kernel launches and memory traffic.
     - Mixed-precision or approximate compositions during training where frequent small factors are merged or approximated to cut cost.
     - Choosing topologies that map well to vectorized block operations on common hardware (GPUs/TPUs), e.g., preferring repeated small dense blocks versus many scalar-sparse operations.

7. Orthogonality relaxations and approximate constraints
   - The paper emphasizes strict orthogonality for spectral preservation and stability. Future work could explore controlled relaxations (e.g., near-orthogonality with a penalty) that allow sparser or shallower factorizations and cheaper training while retaining most spectral benefits.

## Practical experiments the paper suggests (and that follow logically)

The paper already performs expressivity simulations (approximating random orthogonal matrices) and finetuning experiments across modalities. To systematically compare topologies, the following experiments align with the paper’s methodology:

- Approximation experiments: measure how well different layered topologies (butterfly, alternatives from networking, learned sparse layers) approximate random orthogonal matrices as a function of effective trainable parameters and depth \(m\). This mirrors the paper’s Figure on parameter efficiency but extends the topology pool.
- Finetuning benchmarks: compare downstream performance (and runtime) of candidate topologies when finetuning large Transformers or diffusion model layers, controlling for parameter budgets and initialization protocols (identity/Cayley).
- Runtime profiling: measure forward/backward time per iteration for each topology and correlate with depth and block-size choices; experiment with fused kernels to reduce overhead, as the paper flags training-time cost as the main practical limitation.

All these are expressly consistent with the BOFT paper’s claims and its information-transmission evaluation framework.

## Closing thoughts

BOFT shows that thinking of factorized orthogonal finetuning as an information-transmission problem opens up a large and structured design space. The butterfly is an excellent first instantiation: principled, compact, and linked to many classic transforms which may serve as an implicit inductive bias for generalization. But the paper is careful to point out that butterflies are not proven optimal.

The next steps are thus clear and consonant with the paper: use the information-transmission graph abstraction to evaluate alternative layered topologies (from networking ideas and learned structures), balance depth \(m\), block size \(b\), and parameter count, and tackle runtime overhead with both algorithmic (fusion, efficient kernels) and architectural (topology selection) remedies. Doing so could reduce the multiplicative training cost while preserving BOFT’s spectral and geometric benefits, producing even more parameter-efficient and practical orthogonal finetuning schemes.

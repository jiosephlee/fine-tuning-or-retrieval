\title{Blogs about the Paper: "Parameter-Efficient Orthogonal Finetuning via Factorization"}

# From LoRA to BOFT: A Plain-English Guide to Smarter Fine-Tuning

## Why parameter-efficient fine-tuning (PEFT) matters

Modern foundation models (large language and vision models, diffusion models, etc.) are huge. Training them from scratch is costly, so the practical approach is to reuse pretrained models and adapt them to downstream tasks. But naively fine-tuning every weight is expensive in storage, compute, and deployment. That’s where parameter-efficient fine-tuning (PEFT) comes in: change as little as possible while getting the model to perform a new task.

Two popular, contrasting PEFT strategies are:

- LoRA (low-rank adaptation): modify a pretrained weight matrix W by adding a low-rank update. This is additive, simple, and parameter-efficient because the low-rank factors cost O(d) or O(rd) parameters rather than O(d^2).
- Orthogonal Fine-Tuning (OFT): instead of adding, OFT multiplies the pretrained weight by an orthogonal matrix R so that W_new = R W_pretrained. The orthogonal transform preserves pairwise angles between neurons and keeps spectral properties, which can stabilize training and help generalization.

OFT has appealing theoretical and empirical properties, but there’s a problem: a dense orthogonal matrix in d dimensions is still O(d^2) parameters. The original OFT paper made a pragmatic compromise by using block-diagonal orthogonal matrices (split the d dims into blocks and apply separate orthogonal transforms). That reduces parameters but also drastically limits expressivity: blocks don’t mix information across blocks, and the block layout is an arbitrary axis-aligned partition.

BOFT (Orthogonal Butterfly Finetuning) asks: can we keep OFT’s multiplicative, angle-preserving advantages while cutting the parameter count dramatically and keeping much more expressivity than block-diagonal OFT?

## The core idea — trade space for computation with factorization

Instead of representing one big dense orthogonal matrix R explicitly, BOFT composes R as a product of several sparse orthogonal factors:

R = B_m B_{m-1} ... B_1

Each B_i is sparse and orthogonal. Multiplying them together produces a dense matrix overall, but the number of trainable parameters is the sum of the parameters needed to describe the sparse factors. This trades a bit more computation during fine-tuning (you multiply through several sparse factors) for dramatically fewer stored parameters.

To reason about what sparsity patterns are effective, BOFT frames the construction as an information-transmission problem: imagine a grid of nodes arranged in levels (one level per factor plus source and destination). Each sparse factor defines connections between neighboring levels. For the final composed matrix to be dense, every source node must be able to reach every destination node via some path through the levels. The design goals are therefore:

- Dense connectivity in the composed map (every input dimension can influence every output dimension).
- As few free (trainable) edges as possible, under the orthogonality constraint.

This perspective guides the choice of sparsity pattern for the B_i factors.

## Why the butterfly pattern?

BOFT borrows the butterfly topology from the Cooley–Tukey FFT. The butterfly is a sparse, structured network that mixes information across inputs in O(log d) stages, and it’s precisely designed to let local operations ripple to global mixing with very few edges.

Concrete properties:

- A d-dimensional butterfly factorization can be built from O(log d) sparse layers, each with O(d) nonzeros.
- If each sparse factor is orthogonal, the product is an orthogonal matrix.
- Therefore, BOFT can parameterize a dense orthogonal matrix with O(d log d) parameters, instead of O(d^2) for an unconstrained orthogonal matrix.

A simple way to think about it: instead of one fully connected mixing layer (d^2 connections), use a small number of structured local mixing layers (like fixed templates) that, when composed, let information from any input coordinate reach any output coordinate.

BOFT generalizes block OFT as an edge case. If you set the number of factors m = 1 and choose block size b equal to the full dimension, you recover full OFT; if you set m = 1 with small b you recover block-diagonal OFT. Increasing m (more stages) while keeping block widths small yields the butterfly regime with strong parameter savings and good mixing.

## How BOFT maintains orthogonality in practice

To keep each factor orthogonal during training BOFT uses small orthogonal blocks (e.g., 2×2 blocks) and composes them in the butterfly pattern. For numerical stability and zero-start behavior, BOFT initializes each factor as identity (so the initial fine-tuned model equals the pretrained model). A common orthogonal parameterization used here is the Cayley transform: parameterize an orthogonal matrix R as R = (I + Q)(I - Q)^{-1} where Q is skew-symmetric (Q = −Q^T); initializing Q = 0 gives R = I.

Because BOFT’s factors are blockwise orthogonal, they remain orthogonal during training and their product stays orthogonal.

## Practical add-ons: multiplicative Dropout and block variants

Two practical points that come from the paper:

- Multiplicative Dropout: conventional dropout doesn’t work transparently with multiplicative updates. BOFT’s variant randomly replaces some butterfly components or some blocks inside a component with identity during training. This is a multiplicative analogue of dropout that regularizes the composed orthogonal transformation.
- Block butterfly: instead of 2×2 micro-blocks, BOFT can use block size b > 2. This introduces a family of BOFT(m, b) models. Tuning m (number of stages) and b (block width) trades off parameters, expressivity, and runtime.

Parameter count: BOFT(m, b) uses about (1/2)(b - 1) d m effective trainable parameters for a d × n linear layer. For the classic butterfly case (b = 2 and m ≈ log d), the cost is O(d log d).

## What BOFT buys you compared to LoRA and block OFT

- Compared to LoRA: LoRA is additive and low-rank; BOFT is multiplicative and orthogonal. BOFT preserves pairwise neuron angles and the spectral norm of pretrained weight matrices, which can improve training stability and generalization. LoRA tends to be very parameter-efficient but does not enforce these orthogonality-based invariants.
- Compared to block-diagonal OFT: BOFT achieves dense mixing between coordinates with far fewer parameters than a full dense orthogonal matrix and much more expressivity than block-diagonal OFT. The butterfly pattern can represent many classic fast transforms (Fourier, Hadamard, etc.), which suggests a useful structural inductive bias for finetuning.

A theoretical point in the paper: by composing a small number of butterfly-structured orthogonal matrices (and their transposes) in a certain hierarchy, one can approximate arbitrary orthogonal matrices. That means BOFT is not fundamentally limited to a narrow class of transforms; with more stages and the right composition, expressivity approaches the full orthogonal group. In practice, however, the regularity (restricted hypothesis class) that BOFT imposes is part of why it can generalize well.

## Trade-offs and limitations

- Runtime: BOFT multiplies several sparse factors each forward/backward pass, so training is somewhat slower than single-factor OFT. However, at inference you can fold the learned product into the pretrained weights and incur no extra latency.
- Is butterfly optimal? The paper uses butterfly because it is a known, efficient topology for global mixing. Whether a different sparse topology would yield even better parameter/compute trade-offs is an open question; the paper frames the design as an information-transmission / network-topology search problem.
- Choice of hyperparameters (m, b): these control the trade-off between expressivity, parameter count, and runtime. BOFT subsumes block OFT and full OFT as special cases, so it gives a tunable family to fit different budgets.

## Takeaway

BOFT is a neat combination of three ideas:

- Keep the multiplicative, orthogonality-preserving updates of OFT (good for stability and generalization).
- Factor the dense orthogonal matrix into a product of sparse orthogonal blocks (trade memory for compute).
- Use the butterfly topology to get global mixing with only O(d log d) parameters.

If you like LoRA for efficiency, but you also value the spectral/angle-preserving properties of orthogonal transforms, BOFT offers a middle path: substantial parameter savings over full OFT, much more expressivity than block-diagonal OFT, and structural inductive biases derived from widely used fast transforms.

For engineers: BOFT is another PEFT knob to tune. By varying the number of stages m and block size b you can target different parameter budgets and runtime trade-offs. After training you can fold the product into the frozen weights to keep inference fast and simple.

For researchers: BOFT opens a clean design space (sparse orthogonal factor topologies) and an interesting connection between network topologies, information transmission, and parameter-efficient model adaptation.

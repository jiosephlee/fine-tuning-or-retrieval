\title{Stack Exchange of the Paper: "Parameter-Efficient Orthogonal Finetuning via Factorization"}

### How do we implement BOFT when \(d\) is not a power of two?
Question:
The construction assumes \(d=2^N\). In practice, layers often have widths like 768 or 3072. What are the recommended strategies: padding to the next power of two, mixed-radix butterfly, or grouping into near-equal powers with permutations? How does each choice affect orthogonality, parameter count, and runtime?
Answer:
Short answer: there is no single “official” fix in the paper, but all three strategies you suggested are practical and used in related butterfly literature. Which to pick depends on how much extra parameter/runtime budget you can tolerate and whether you want a very simple implementation. Below I summarize each option, explain why it works (and how to keep matrices orthogonal), and compare the effect on parameter count and runtime.

1) Pad to the next power of two (simplest)
If $d$ is not a power of two, embed your $d$-dimensional layer into a larger dimension $d_{\text{pad}} = 2^N \ge d$, build a standard radix‑2 butterfly on $d_{\text{pad}}$, and either (a) never touch the extra coordinates (keep those rows/cols of the pretrained $W$ frozen/identity) or (b) learn the full $d_{\text{pad}}$ orthogonal and slice the first $d$ coordinates for use. Orthogonality: the butterfly factors are still orthogonal on $\mathbb{R}^{d_{\text{pad}}}$, so the composed $R$ is orthogonal; when you slice back to $d$ dimensions you get a valid linear map applied to the original coordinates (if you initialized the extra subspace as identity you preserve zero-init behavior). Parameter count and runtime: both scale with $d_{\text{pad}}$ instead of $d$, so you pay the extra $\mathcal{O}\big(d_{\text{pad}}\log d_{\text{pad}}\big)$ parameters and $\mathcal{O}\big(d_{\text{pad}}\log d_{\text{pad}}\big)$ per‑step cost. Practical note: padding is the easiest to implement (no change to factorization code). If $d_{\text{pad}}$ is not much larger than $d$ this is often acceptable; if $d$ is near the next power boundary (e.g. $769 \to 1024$) the overhead can be large.

2) Mixed‑radix / non‑radix‑2 butterflies (more elegant, no padding)
Generalize the butterfly decomposition to mixed radices by using Cooley–Tukey style factorization for composite sizes: factor $d$ into small integers ($d = r_1\cdot r_2\cdot\ldots$) and build sparse factor blocks that permute/mix groups of size $r_i$ instead of always splitting by $2$. In practice one implements butterfly “factors” that are block permutations of $r\times r$ blocks (or $2b\times 2b$ blocks as the paper describes) and ensure each block is orthogonal (e.g., Cayley on each small block). Orthogonality: preserved as long as every factor block is constrained to be orthogonal (same trick as for $2\times 2$ Cayley blocks). Parameter count and runtime: roughly $\mathcal{O}\!\big(d \sum_i \log_{r_i} d\big)$ but in practice comparable to $\mathcal{O}(d\log d)$ with a smaller constant; it grows with the number and sizes of factors. Mixed‑radix avoids padding overhead but requires implementing general block factors and permutations; it is the most parameter‑efficient way to avoid padding if you can factor $d$ into convenient small integers.

3) Partition into near‑power‑of‑two blocks + permutations (practical hybrid)
Split the $d$ coordinates into several groups whose sizes are powers of two (e.g., split $3072$ as $1024+1024+1024$ or $2048+1024$), apply separate radix‑2 butterfly factors within each block and add inter‑block permutations/merge layers that connect blocks so the overall transform becomes dense. In the paper’s terminology this is like using block butterfly components (they already allow blocks of size $b$) and adding permutations / kaleidoscope compositions to increase expressivity. Orthogonality: maintained if each block factor and each permutation is orthogonal (permutations are orthogonal by construction). Parameter count and runtime: parameter cost is sum over blocks $\mathcal{O}\!\big(\sum_i b_i\log b_i\big)$ and extra cost for the permutation/merge layers (usually negligible). This scheme often sits between naive padding and fully mixed‑radix in both complexity and implementation difficulty. It is attractive when $d$ can be expressed as a small sum of powers of two.

How each choice affects the three things you asked about

Orthogonality: All three methods can preserve orthogonality. Padding preserves orthogonality in the larger space; mixed‑radix and block partitioning preserve orthogonality by enforcing orthogonality on each factor block (use Cayley or local rotations on each small block, as the paper does). The only pitfall is if you implement ad hoc dense connections but forget to constrain factors to be orthogonal—then you lose the key spectral/stability guarantees.

Parameter count: Padding increases parameters to $\mathcal{O}\big(d_{\text{pad}}\log d_{\text{pad}}\big)$. Mixed‑radix and carefully chosen block partitionings keep parameter count closer to $\mathcal{O}(d\log d)$ with smaller constants (no wasted padded coordinates). The paper’s block‑butterfly parameterization $\mathrm{BOFT}(m,b)$ already allows a block size $b$; choosing $b>2$ can help handle dimensions not power of two without substantial extra parameters.

Runtime: Runtime scales with the working dimension used by the factorization. Padding costs you extra runtime proportional to $(d_{\text{pad}}-d)\log d_{\text{pad}}$. Mixed‑radix and block partitioning reduce extra runtime versus padding, but they require additional bookkeeping for variable block sizes and permutations. The paper notes a slight runtime overhead relative to plain OFT because BOFT multiplies $m$ sparse factors each forward/backward pass; any of these approaches retain that multiplicative cost, but padding makes it worse by increasing $d$ in each factor.

Practical recommendations
If you want minimal engineering and the power‑of‑two slack is small, pad to the next power of two, initialize the padded subspace as identity (zero skew for Cayley) and slice back at runtime. This is robust, preserves the identity initialization and orthogonality, and lets you reuse a radix‑2 implementation.

If you care about parameter/runtime efficiency and are willing to add some implementation work, implement block butterflies (the paper already describes block components) and either: (a) use mixed‑radix factors based on the factorization of $d$, or (b) partition $d$ into multiple power‑of‑two blocks and introduce orthogonal permutations/merge layers (kaleidoscope composition). Both give you the same orthogonality guarantees but avoid the padding waste. The block size $b$ from the paper is a useful lever: choosing $b$ so that $b$ divides $d$ (or choosing multiple block sizes summing to $d$) reduces implementation complexity.

One final note connecting to the paper: BOFT already contemplates block butterfly components and kaleidoscope-style compositions (see Theorem and the generalized composition in the paper). That machinery is directly applicable to the non‑power‑of‑two case: use block components ($b>2$) or compositions of multiple butterfly-like orthogonal factors to cover arbitrary $d$ while preserving orthogonality and keeping parameter growth subquadratic.

Summary: padding is easiest but wastes parameters/runtime; mixed‑radix or block‑butterfly + permutations are more efficient and keep orthogonality but need slightly more implementation work. The paper’s block butterfly parameterization and kaleidoscope generalization are exactly the tooling you need to implement the latter approaches.

\title{A Textbook about the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

Chapter 7: Estimating Class Likelihoods with Simple Models

# Feature representation: z_k as binary indicators for class k
In the FeatLLM framework, the raw tabular inputs are transformed into a set of rule-based binary features that are designed to capture whether a sample satisfies certain class-specific criteria inferred by a large language model (LLM). For a particular class $k$, the new feature vector for sample $i$ is denoted as $\mathbf{z}_k^i \in \{0,1\}^R$, where $R$ is the fixed number of rules generated per class. Each coordinate of $\mathbf{z}_k^i$ corresponds to one rule for class $k$ and takes the value $1$ if the sample satisfies that rule and $0$ otherwise.

This representation has two useful properties. First, it is highly interpretable: each dimension can be read as a human-understandable condition (a rule) that the LLM proposed as indicative of class $k$. Second, binarization simplifies downstream modeling because we can reason directly about counts and combinations of satisfied rules. In practice, rules are parsed (via an auxiliary LLM prompt that outputs simple executable code) and applied to the tabular dataset to produce these binary indicators automatically. The binary vectors $\{\mathbf{z}_k^i\}$ for all classes become the input features used by the simple downstream model to estimate class likelihoods.

# Linear logits with non-negative weights: interpretability and monotonicity rationale
To convert these binary rule indicators into a score (logit) for each class, FeatLLM uses a linear model per class. Let $\mathbf{w}_k \in \mathbb{R}^R$ be the trainable weight vector associated with the $R$ rules for class $k$. The model computes the class logit for sample $i$ by taking a non-negative projection of the weights and forming an inner product with the binary indicators:
\[
\text{logit}_k^i = \max(\mathbf{w}_k, 0) \cdot \mathbf{z}_k^i.
\]
The $\max(\cdot,0)$ operation is applied elementwise and ensures all effective weights used in the dot product are non-negative.

There are two key motivations behind forcing weights into the non-negative subspace. First, interpretability: a non-negative weight indicates how strongly satisfying a given rule increases the logit (and thus the probability) for class $k$. Positive weights are directly readable as rule importance scores; zero weights mean a rule has no positive contribution. Second, a monotonicity rationale: because rules were generated by an LLM as criteria suggestive of a class, it is natural to treat satisfaction of such a rule as evidence in favor of that class. Forcing weights to be non-negative prevents the learned model from treating an LLM-proposed rule as negatively indicative of the same class, which aligns model behavior with the intended semantics of the extracted rules.

# Softmax over class logits and cross-entropy training
After computing logits for each class, the model converts logits into probabilities using the softmax function across classes. For a sample $i$ with class logits $\{\text{logit}_{1}^i,\dots,\text{logit}_{c}^i\}$, the class probability vector $\mathbf{p}^i$ is given by
\[
\mathbf{p}^i = \text{Softmax}\big([\text{logit}_{1}^i, \dots, \text{logit}_{c}^i]\big),
\]
so that $p_k^i = \frac{\exp(\text{logit}_k^i)}{\sum_{j=1}^c \exp(\text{logit}_j^i)}$.

Learning proceeds by minimizing the standard cross-entropy loss between these predicted probabilities and the one-hot encoded ground-truth labels over the available few-shot training samples. Because the downstream classifier is linear in the binary rule features (after the non-negativity projection), optimization is simple and efficient. Minimizing cross-entropy adjusts the weight magnitudes so that combinations of rules better align predicted probabilities with the observed labels in the few-shot set.

# Why weight tuning matters vs simple rule counts
A naive way to combine binary rule indicators into a score is simply to count the number of satisfied rules for each class and use those counts as logits. That corresponds to treating each rule as equally informative (unit weight) and ignoring any differences in rule quality. While this approach can work as a rough indicator, FeatLLM shows that learning weights from data yields substantial improvements, especially as more labeled examples become available.

Tuning the weights allows the model to modulate the contribution of each rule: strongly predictive rules receive higher weights, while noisy or irrelevant rules receive near-zero weights and are effectively ignored. The paper's ablation study demonstrates that omitting the tuning step (i.e., using raw counts) degrades performance, and the benefit of tuning increases with the number of shots. This is because with more labeled examples the learner can estimate rule importance more reliably; conversely, in very low-shot settings, prior knowledge embedded in the rules is already valuable, but learned weighting still helps filter or emphasize rules consistent with the observed labels.

# Training details: optimizer choice, learning rate, epochs, and early stopping via k-fold CV
The downstream linear models in FeatLLM are trained with straightforward settings suitable for few-shot learning. The reported implementation uses the Adam optimizer with a learning rate of $0.01$. Training runs for a fixed number of epochs (200 epochs in the experiments). To avoid overfitting and to select an appropriate stopping point in the few-shot regime, k-fold cross-validation is used to determine the optimal epoch. Concretely, k-fold cross-validation is applied over the few-shot training set: the training process is monitored across folds and the epoch that generalizes best on validation folds is selected. This procedure provides an implicit early-stopping mechanism tailored to the extremely limited-data setting.

Because the downstream model is small and convex in the weights before the non-negativity projection, training is computationally light. The paper notes that these training runs are cheap relative to per-sample LLM inferences, and only a modest number of LLM queries (e.g., one per ensemble trial) are required during the overall FeatLLM procedure.

# Interpreting learned weights as rule importance
Once trained, the learned (non-negative) weights $\max(\mathbf{w}_k,0)$ serve as direct measures of each rule's importance for predicting class $k$. A higher weight for a particular rule means that when that rule is satisfied for a sample, it has a larger positive impact on the logit and therefore increases the predicted probability of class $k$ more strongly. Weights near zero indicate rules that the learning process found uninformative or inconsistent with the labeled examples; such rules can effectively be treated as filtered-out or pruned.

This interpretability enables several practical uses. First, practitioners can inspect which LLM-generated rules are actually being trusted by the data-driven learner and which are being downweighted. The paper uses a threshold (e.g., weight threshold 0.1 in the analysis) to quantify how many rules remain useful after tuning. Second, because weights are non-negative and additive in the logit space, the model provides a monotone, easily explainable mapping from satisfied rules to class evidence. Finally, in the ensemble setting FeatLLM repeats rule generation and weight learning across multiple randomized trials; rules that consistently receive high weights across trials are more likely to be genuinely informative, and the ensemble averaging of probabilities further stabilizes predictions.

Together, these design choices—binary, rule-based features, non-negative linear aggregation, softmax normalization, and cross-entropy training with simple optimization and validation—yield a lean, interpretable, and effective mechanism for converting LLM-extracted rules into calibrated class likelihoods in few-shot tabular learning.

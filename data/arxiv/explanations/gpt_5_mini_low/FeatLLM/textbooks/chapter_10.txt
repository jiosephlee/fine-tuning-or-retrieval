\title{A Textbook about the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

Chapter 10: Results and Analyses

# Main results: AUC performance across datasets and shots; FeatLLM vs baselines
The core empirical finding of the paper is that FeatLLM consistently achieves top-tier predictive performance across a diverse collection of tabular datasets in few-shot settings. The evaluation covers 13 datasets spanning conventional UCI tasks (e.g., Adult, Bank, Credit-g, Diabetes, Heart, Myocardial), recent additions to repositories (e.g., Cultivars, NHANES), and intentionally synthetic tasks (Sequence-type, Solution-mix). Performance is reported in terms of area under the ROC curve (AUC), averaged over three random train/test splits, with standard deviations reported.

Across these datasets and experimental conditions, FeatLLM either ranks first or second among all compared methods. The baselines include classical supervised models (Logistic Regression, XGBoost, RandomForest), few-shot / semi-supervised approaches (SCARF, STUNT), pretraining-based methods (TabPFN), and other LLM-based strategies (in-context prompting, TABLET, TabLLM). Notably, LLM-based baselines that operate end-to-end on each sample (in-context, TABLET, TabLLM) frequently fail on datasets with many features because of prompt length limitations; FeatLLM, by contrast, uses bagging and ensembling to remain effective even when the number of attributes is large.

Quantitatively, the paper reports that FeatLLM improves over competing LLM-based methods and other baselines, with an average lift of approximately 10% compared to alternatives like TabLLM and STUNT in the reported experiments. These results demonstrate that converting LLM outputs into engineered binary features, and then fitting a simple downstream model, yields not just interpretable rule-like features but also high predictive accuracy in low-shot regimes.

# Data efficiency: competitive with 4 shots relative to 32-shot classical baselines
One of the most striking results concerns data efficiency. In the experiments, FeatLLM trained with as few as $k=4$ labeled examples often attains accuracy comparable to classical tabular models trained with $k=32$ labeled samples. This demonstrates that the combination of LLM priors and rule-based feature generation can compensate for dramatically fewer labeled instances. The mechanism behind this data efficiency is twofold: first, the LLM supplies strong prior knowledge about which features or feature relationships matter for the target task; second, FeatLLM translates that prior knowledge into concrete binary features that concentrate signal, making it easier for the downstream simple model to learn from limited labeled data.

This result is particularly relevant for domains where labels are costly to obtain (for instance, in healthcare or finance). Instead of relying solely on labeled examples to discover predictive structure, FeatLLM leverages the semantic knowledge embedded in the LLM to propose plausible decision rules, which significantly accelerates learning from small labeled sets.

# Runtime comparison: training and inference costs versus LLM-inference methods
The paper reports both training and inference time comparisons, using the Adult dataset with 16-shot training as an example. FeatLLM requires relatively modest training-time interaction with the LLM: around 30 API queries per ensemble trial setup, which can be parallelized and is designed to be inexpensive compared to full fine-tuning. The heavy LLM interaction is limited to the rule-generation and parsing phases; inference on new samples does not require additional LLM calls because the learned rules are parsed into executable code and the downstream model is a lightweight linear (or similar) predictor.

In terms of inference latency, FeatLLM matches conventional methods: once rules are produced and the linear model is trained, prediction is a low-cost forward pass (binary-feature extraction and a dot product with learned weights). This contrasts with other LLM-based approaches (in-context prompting, TABLET, TabLLM) that perform at least one LLM call per test sample and therefore have substantially higher inference time. TabLLM, which involves parameter-efficient tuning, also has heavy training-time and inference resource requirements (for example, TabLLM experiments used multiple A100 GPUs for model parallelism), while FeatLLM needs only API-level access without fine-tuning.

Thus FeatLLM achieves a favorable trade-off: it concentrates LLM use at training time to extract reusable features, keeping per-sample inference costs low and comparable to classical models.

# Ablations: effect of weight tuning, ensembling, feature descriptions, prior-knowledge reasoning
The paper includes an ablation study that isolates the contributions of major components to overall performance. Four ablations are considered:

1. -Tuning: omit learning of the linear model weights; instead simply sum the binary rule features per class to obtain logits.
2. -Ensemble: remove the ensemble (bagging + multiple trials) and rely on a single rule-generation run.
3. -Description: exclude feature descriptions from the prompt that explains feature types and definitions.
4. -Reasoning: remove the Step-1 reasoning instruction (the prior-knowledge step) that asks the LLM to think about feature–label tendencies before inspecting examples.

Averaged AUC changes indicate that each component contributes positively: removing any of these elements reduces performance across datasets. Two qualitative patterns emerge from the ablations. First, weight tuning provides increasing benefit as the number of shots grows: when more training data are available, the downstream linear model can more accurately estimate the relative importances of rules, and tuning yields larger improvements. Second, when shots are few, the inclusion of feature descriptions and the prior-knowledge reasoning step materially affects performance. In other words, the LLM's use of prior knowledge and the structured two-step reasoning are especially valuable in the extremely low-shot regime, helping the model avoid spurious correlations and focus rule generation on semantically relevant attributes. Finally, ensemble techniques consistently improve performance by aggregating multiple LLM-generated rule sets and mitigating noisy or incorrect rules from individual trials.

# Feature quality analysis: proportion of informative rules before/after tuning
FeatLLM explicitly evaluates the quality of the generated rule-based features by measuring the AUROC of each binary rule feature against the target label. For each dataset, the paper reports the average AUROC of rule features and the proportion of rules with AUROC above 0.5 (i.e., informative features). Two stages are contrasted: "Before tuning" (directly examining LLM-generated rule features) and "After tuning" (examining which rules are retained as important after the downstream model learns weights).

The analysis shows that a majority of generated rules are relevant to the prediction target: many rule features attain AUROC greater than 0.5 prior to any tuning. Moreover, the tuning phase serves as an automatic filter: after fitting the linear model, rules with negligible learned weights (below a threshold such as 0.1) are effectively discarded, increasing the fraction of retained features that are genuinely informative. This two-step process—LLM generation followed by data-driven weight estimation—both harnesses LLM prior knowledge and uses empirical evidence to remove spurious or weak rules. The result is a compact and informative set of binary features that drive prediction.

# Robustness to spurious features: appending unrelated columns and measuring degradation
Robustness to irrelevant or spurious features is explicitly tested via an experiment on the Heart dataset. The experimental protocol appends randomly chosen columns from the Adult dataset (which are unrelated to predicting heart disease) and measures AUC degradation as the number of such noisy columns grows. All models are trained in an 8-shot setting, and methods that require large unlabeled corpora are excluded for fairness.

FeatLLM shows the least performance degradation compared to baselines as spurious columns are added. The core reason is the prompt design and the two-step reasoning instruction: before generating rules, the LLM is prompted to reason about which features are plausibly related to the target task (Step 1). This encourages the LLM to avoid crafting rules from obviously irrelevant columns, so only a small fraction (about 1–2%) of generated rules originate from noisy columns in practice. That said, the paper also notes that FeatLLM is not immune to learning spurious correlations entirely—if strongly related but incorrectly attached columns exist, the LLM can still generate misleading rules. But overall, the combination of prior-knowledge reasoning and tuning makes FeatLLM substantially more robust than models that rely purely on pattern-matching from a few examples.

# Hyperparameter sensitivity: ensemble size and number of rules per class
FeatLLM depends primarily on two hyperparameters: the number of ensemble trials $T$ and the number of rules per class $R$ generated in each LLM query. Empirical exploration reveals the following:

- Ensemble size $T$: Increasing $T$ improves performance because additional trials produce diverse rule sets, enabling ensembling to average out errors and to amplify consistent, correct rules. Performance gains, however, saturate: in the experiments, benefits converge around $T \approx 20$. Thus $T=20$ is a pragmatic choice balancing accuracy and LLM-query budget.

- Rules per class $R$: While more rules can increase representational capacity by covering more candidate decision boundaries, it also increases input dimensionality and the chance of overfitting in low-shot regimes. The experiments found no statistically significant advantage to very large $R$, and a setting of $R=10$ provides a practical trade-off between prompt length, downstream model complexity, and performance.

These observations imply that modest ensemble sizes and a moderate number of rules per class suffice to capture most of the performance gains, keeping both LLM-query cost and downstream model complexity manageable.

# Scalability to many features via bagging and ensemble
One practical limitation of direct LLM-based tabular approaches is the input prompt length: very wide tables (many columns) can exceed model context windows or produce unwieldy prompts. FeatLLM addresses scalability to many features through a bagging-and-ensemble strategy. Concretely, each ensemble trial performs rule generation from a subset of features or training instances, thereby keeping prompt length modest. The final prediction aggregates across trials; collectively, these trials cover more of the original feature space without ever requiring a single oversized prompt.

This approach supplies two complementary benefits. First, it enables application to datasets with many attributes that would otherwise be infeasible for single-shot LLM prompts. Second, it injects diversity into the ensemble: different trials produce different candidate rules because they see different feature subsets and randomized demonstrations. This diversity is crucial to robustness: incorrect rules in some trials are attenuated by correct rules from others when probabilities are averaged. Hence the bagging-plus-ensemble design is both a practical scalability mechanism and a means to enhance stability and predictive performance.

Taken together, the experimental analyses show that FeatLLM leverages LLM prior knowledge to generate high-quality, interpretable binary features; uses a simple learnable aggregator to ground those features to task-specific evidence; and employs ensemble strategies to manage prompt size, increase robustness, and produce competitive few-shot performance with low inference cost.

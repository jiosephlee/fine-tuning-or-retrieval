\title{A Textbook about the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

Chapter 2: Background: Few-Shot Tabular Learning and Language-Interfaced Methods

# Few-shot learning in tabular domains: risks of overfitting and spurious correlations
Few-shot learning addresses the scenario where only a very small number of labeled examples are available for a target task. In tabular domains this problem is acute because tabular datasets are often heterogeneous (continuous, categorical, ordinal features), and signal can be subtle or distributed across many columns. When training standard supervised models with only a handful of labeled examples, those models easily fit idiosyncratic patterns in the small training set that do not generalize. In other words, overfitting is a primary risk: with few examples, complex models can pick up noise and incidental associations that are not causal or reliable for future data.

A related and particularly important failure mode in low-shot tabular learning is learning spurious correlations. Spurious correlations are associations present in the limited training data that arise from sampling noise, dataset collection artifacts, or coincidental covariation between some columns and the target. Because tabular data may include many columns, some unrelated columns will by chance correlate with the label in a tiny sample. A learner that treats all correlations as equally informative can produce predictions that rely heavily on these spurious signals and therefore degrade dramatically when tested on new data or when irrelevant columns are added. The paper emphasizes this risk and motivates methods that can inject stronger inductive biases or external knowledge so that the learner focuses on plausible, semantically meaningful relationships rather than accidental patterns.

In summary, few-shot tabular learning must contend with two intertwined dangers: (1) overfitting due to limited labeled data, and (2) exploitation of spurious correlations when irrelevant features appear predictive in a small sample. Any successful few-shot solution for tabular data needs mechanisms to mitigate these risks—either by adding appropriate priors, leveraging external or auxiliary data, or constraining model complexity so that only robust, explainable relations are used for prediction.

# Classical strategies: semi-supervision, self-supervision, and transfer learning
Classical approaches to reduce overfitting and improve generalization in low-data regimes introduce additional sources of information or change the training objectives to create more robust inductive biases. Three major directions discussed in the paper are semi-supervision, self-supervision, and transfer learning.

Semi-supervised approaches aim to exploit large amounts of unlabeled data that are often easier to collect than labeled examples. In the tabular setting this can mean using an unlabeled corpus from the same domain together with a small labeled subset, often combined with carefully designed augmentations to encourage the model to learn stable structure. Although semi-supervised methods can provide extra signal and improve performance, the heterogeneous nature of tabular data makes it hard to design universally effective augmentations. The paper notes that such strategies have not consistently yielded large gains in very low-shot settings for tabular data.

Self-supervised (or unsupervised pretext) objectives offer another route: create learning tasks from the data itself (for example masking or corruption and reconstruction) so that the model learns useful representations before fine-tuning on the small labeled set. Examples include masking columns and training the model to reconstruct them, or contrastive objectives that encourage invariance under suitable data transformations. Self-supervision can produce a representation that transfers to downstream low-shot tasks, but again the diversity and structure of tabular features limit how generally applicable these pretext tasks are.

Transfer learning tackles the problem by pre-training a model on many tasks or datasets so that it acquires broadly useful inductive biases. Once pretrained, the model can be adapted to a new target task with few labeled samples. In tabular learning this has taken two forms: (a) training on a broad range of tabular datasets to learn cross-table semantic relationships (for example, methods that use column names and values to learn column semantics), and (b) large-scale synthetic pretraining in which a model is exposed to many artificially generated distributions to develop a flexible prior. The advantage of these approaches is that they can encode priors about likely data generating processes which then guide learning on new small datasets.

Each of these classical strategies imposes different requirements. Semi-supervision demands access to unlabeled data from the same domain. Self-supervision requires a pretext task that actually captures transferable structure. Transfer learning requires pretraining resources and datasets (or synthetic data generators) that encompass the kinds of patterns one will encounter at test time. The paper positions these classical techniques as effective but imperfect, which motivates exploring alternative sources of prior knowledge—specifically, knowledge embedded in Large Language Models (LLMs).

# Representative systems: TransTab, TabPFN, SCARF, STUNT
The literature contains concrete representative systems that embody the classical directions described above. The paper discusses several notable methods that target few-shot tabular learning.

TransTab (referred to as TransTab in the paper) is an example of transfer learning for tabular data that leverages column names and their semantics. It trains transformer-based models across many tables to capture semantic relationships between columns, not just the raw values. By learning how column names and values relate across diverse datasets, TransTab gains the ability to generalize to new tabular tasks in a zero-shot or few-shot way: the learned representations let the model make better use of limited labeled examples at test time.

TabPFN takes a different transfer route: it pretrains a Bayesian neural network on a large mixture of synthetic distributions. The key idea is to expose the model during pretraining to many plausible data-generating processes so that, at inference time, it can act as a strong prior over classifiers for small datasets. TabPFN’s synthetic pretraining enables it to perform inference by ingesting both training and test samples of the target task without further gradient-based learning, which is a valuable property in extreme low-shot settings.

SCARF and STUNT are methods that exploit additional unlabeled data or synthetic augmentation in order to boost few-shot performance. SCARF uses large amounts of unlabeled data together with task-specific augmentations, while STUNT develops strategies for leveraging unlabeled samples to improve robustness in low-shot regimes. These approaches can be powerful when suitable unlabeled corpora exist, but the paper points out that collecting such unlabeled data is not always feasible in real-world applications, limiting their practical applicability.

Taken together, these representative systems illustrate different trade-offs: TransTab and TabPFN invest in pretraining over multiple tasks or synthetic distributions to produce strong priors; SCARF and STUNT exploit extra unlabeled data; each brings advantages but also practical constraints (availability of pretraining data, synthetic distribution design, or unlabeled datasets). The FeatLLM approach proposed in the paper is presented as an alternative that leverages the knowledge embedded in LLMs without requiring large unlabeled corpora, custom pretraining, or model fine-tuning.

# Language-interfaced tabular learning: data serialization and prompting
Language-interfaced tabular learning methods treat tabular prediction as a natural language reasoning problem by serializing structured rows into textual prompts that are then processed by LLMs. The serialization encodes each feature and its value into simple textual statements. For a single example with features F = \{f_1, ..., f_d\} and values \mathbf{x}^i = (x^i_1, ..., x^i_d), the typical serialization used in the paper takes the form:

"f_1 is x^i_1. ... f_d is x^i_d. Answer: y^i"

This serialized text—optionally augmented with feature descriptions, the task description, and some few-shot demonstrations—is then fed to an LLM which produces a prediction or an explanation. The LLM’s pretraining on massive text corpora provides priors about the world (for instance, medical knowledge about age and disease risk), and the prompt can combine that prior knowledge with the few labeled examples to guide inference.

Prompt design is central in this style of approach. A good prompt must supply the task description (what to predict), feature descriptions (types, definitions, possible categorical values), and a small set of demonstrations to encourage the LLM to use the supplied features correctly. The paper highlights that careful prompt construction can make LLMs act, effectively, as a domain expert: they can infer causal tendencies between features and target labels (e.g., "older age increases risk for X") and use that prior knowledge in few-shot classification.

However, serializing many features or many examples can create very long prompts. Because LLMs have finite context windows, long serializations can either exceed the model’s length limits or degrade performance when the prompt becomes too long. This creates a practical limitation: language-interfaced approaches must balance the amount of serialized information against the LLM’s context capacity. The FeatLLM paper uses this insight to motivate a design where the LLM is used to generate compact, reusable artifacts (rules/features) rather than to produce per-sample predictions based on long serializations.

# In-context learning vs parameter-efficient fine-tuning (LoRA, IA3)
Two primary paradigms for using LLMs in downstream tasks are in-context learning and parameter-efficient fine-tuning.

In-context learning supplies the LLM with a textual prompt that includes a description of the task and a small number of example input–label pairs; the LLM produces predictions for new inputs without any weight updates. This approach is appealing because it requires no gradient-based training and can leverage black-box API models like GPT-3.5 or GPT-4. In the tabular setting, in-context learning means serializing a handful of training examples with their labels in the prompt and asking the model to predict the label of a new serialized example. The paper notes that in-context learning demonstrates the LLM’s ability to generalize from few examples by leveraging prior knowledge encoded during pretraining.

Parameter-efficient fine-tuning methods, such as LoRA and IA3, take another route: they update only a small number of additional parameters or low-rank adapters while keeping the bulk of the LLM fixed. This allows adapting a large model to a new task with limited computation and relatively small labeled datasets. In the tabular literature cited by the paper, approaches like TabLLM use IA3-style tuning so the model can better calibrate to the specific statistical patterns of a tabular dataset. Parameter-efficient tuning typically yields higher accuracy than pure in-context learning when the tuning procedure and model access are available.

Each strategy has tradeoffs. In-context learning requires only API access and no training but can be sensitive to prompt length and the order of demonstrations. Parameter-efficient tuning can improve performance but needs the ability to update model weights (which may not be possible for commercial LLMs that only expose inference APIs) and can be costly when large models are involved. The FeatLLM paper emphasizes this practical constraint: many top-performing LLMs offer only inference API access, making fine-tuning infeasible. That motivates FeatLLM’s design goal of using LLMs via prompts to engineer features while keeping downstream inference lightweight and independent of the LLM.

# Known issues: context window limits, per-sample LLM inference costs, and generalization
When applying LLM-based methods to tabular learning, practitioners must confront several well-known practical limitations. First is the context window limit: LLMs can only accept prompts up to a maximum token length. For tabular datasets with many features, serializing entire rows plus many demonstrations can easily hit that limit, or at least force truncation that loses important information. Even when the prompt fits, very long prompts can degrade in-context performance because the model must attend to a large amount of text and may not prioritize the right pieces of information.

Second, many language-interfaced approaches perform at inference time by passing every test sample through the LLM. That is, per-sample LLM inference is required to produce predictions. This is computationally expensive and slow compared to running a conventional lightweight classifier, and it can be infeasible in production due to latency or API cost constraints. The paper calls this out as a key drawback of end-to-end LLM prediction methods.

Third, generalization concerns remain. Even though LLMs carry rich prior knowledge, their use as black-box predictors risks over-reliance on spurious patterns present in the few demonstration examples or on the accidental phrasing in prompts. The order of demonstrations can affect outcomes, and the LLM may infer rules that work on the prompt examples but do not generalize. Furthermore, where LLMs are used for per-sample inference, robustness can be undermined by variability in model outputs and temperature-driven randomness.

The FeatLLM approach addresses these practical issues by changing how the LLM is used: rather than running the LLM on every test sample, the LLM is queried a limited number of times to generate human-readable rules that become binary features. Once these features are generated and parsed into code, downstream inference uses a simple parametric model (e.g., a linear model) that runs efficiently without calling the LLM. This design reduces per-sample LLM inference cost, avoids extensive fine-tuning requirements, and mitigates context window problems by using bagging and ensembling to limit prompt size per query. It also aims to improve generalization by instructing the LLM to first reason about causal tendencies (leveraging prior knowledge) and then formulate class-specific rules, thereby helping avoid rules that exploit spurious correlations in the small labeled set.

# Concluding perspective
This chapter reviewed the foundational ideas behind few-shot tabular learning and the recent trend of language-interfaced methods that serialize tabular inputs into text for LLMs. Classical strategies—semi-supervision, self-supervision, and transfer learning—provide various avenues to supply additional inductive bias, but each has practical limitations. Language-interfaced methods offer a powerful source of prior knowledge through LLMs, yet they face concrete issues: prompt length limits, the computational cost of per-sample LLM inference, and sensitivity to demonstration ordering and spurious correlations.

FeatLLM (as described in the paper) sits at the intersection of these observations: it leverages LLMs’ world knowledge and reasoning not to make end-to-end predictions for every sample but to act as a feature engineer that extracts rules. These rules are parsed into binary features and combined with a simple downstream learner. This architecture is motivated directly by the practical and methodological concerns reviewed in this chapter and seeks to retain the strengths of language-interfaced approaches while ameliorating their principal limitations.

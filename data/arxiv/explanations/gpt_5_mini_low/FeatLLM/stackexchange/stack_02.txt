\title{Stack Exchange of the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

### Why constrain rule weights to be non-negative in the linear model?
Question:
Section 3.2 defines logits per class as \(\text{logit}_k^i = \max(\mathbf{w}_k, 0) \cdot \mathbf{z}_k^i\), forcing non-negative contributions from rule activations. Conceptually, this prevents a rule that fires from ever decreasing a class's logit. But some rules might indicate negative evidence for a class (e.g., "no chest pain" might reduce the likelihood of heart disease). Why prohibit negative weights? Is the intent that negative evidence is represented as positive evidence for some other class, making explicit negatives unnecessary? Did you empirically compare against an unconstrained linear/logistic model with signed weights?
Answer:
Short answer: the paper enforces non-negative weights so that every LLM-generated rule (a binary “this condition holds” feature) can only increase the logit for the class it was written for. The stated motivations are interpretability, robustness in the low-shot regime, and an inductive bias that fits how the rules are produced (rules are written as positive signals for a class). The paper does not report a direct comparison to an unconstrained linear/logistic model with signed weights.

Why non-negativity makes sense here (intuitively and technically)
The LLM in FeatLLM is asked to produce rules that are intended as evidence for a particular class (e.g., “$\text{age} > 65$ indicates higher risk of disease X”). Treating each rule as a positive indicator and restricting its learned weight to be non-negative enforces that semantics: when a rule fires it will not reduce the class’s logit. This has several practical consequences that matter especially in few-shot settings.

First, it preserves interpretability and trust: positive rule weight = supportive evidence, near-zero weight = irrelevant/filtered rule. If weights could go negative, a rule the LLM produced as a “support” could end up being used as a learned negative signal after noisy few-shot fitting, which undermines the intended human-readable mapping from rules $\to$ evidence.

Second, it acts as a useful inductive bias / regularizer in the extremely low-data regime. With very few labeled examples, unconstrained fitting can easily assign spurious signed weights (positive or negative) to explain noise. Enforcing non-negativity prevents a model from explaining everything by flipping the sign of weak/noisy binary features, which stabilizes learning and reduces overfitting.

Third, model structure and competition between classes: FeatLLM builds per-class rule sets and computes logits per class (then applies softmax). Negative evidence for class A can be represented implicitly by positive evidence for other class(es). In a softmax, increasing another class’s logit decreases class A’s posterior probability even if A’s own rules only add positive mass. Thus one can represent “negative evidence for A” either by a rule directly for A with negative weight, or by rules for other classes with positive weights. FeatLLM chooses the latter implicitly by construction, which keeps the semantics of each rule aligned with the class it was generated for.

What the paper actually reports empirically
The paper reports an ablation that removes the weight tuning step: instead of learning non-negative weights they simply sum the binary features per class (i.e., equal positive weights). That ablation (“-Tuning”) degrades performance, showing that learning per-rule importance is helpful. However, the paper does not present an explicit experiment comparing the chosen projected-nonnegative-weight model against a fully unconstrained signed-weight linear model. So there is no reported direct empirical test in the paper that answers “would signed weights help?” The authors claim the positive projection “ensures that the features generated by the LLM do not reduce the likelihood of a class during learning,” and motivate this by robustness and interpretability rather than by an empirical signed-vs-non-signed sweep.

Practical implications and a suggested experiment
If you suspect many rules are legitimately negative indicators (e.g., “no chest pain” reduces heart disease risk) you can represent that in FeatLLM either by (a) asking the LLM to generate negative-signal rules as positive rules for the complement class (or a “not-disease” class), or (b) allow signed weights and learn them. The paper favors (a)/(implicit) because it keeps rules aligned with class semantics and gives stability in low-shot fitting.

If you want to evaluate this empirically, the natural experiment is straightforward: train two versions on the same rule-derived binary features — one with the paper’s projection to non-negative weights, the other with unconstrained signed weights (same optimization, same regularization). Measure few-shot performance and inspect what fraction of rules get negative weights in the unconstrained run. My expectation (consistent with the paper’s motivations) is that in very-low-shot settings the unconstrained model will assign unstable/sign-flipping weights and may overfit more, while in higher-shot regimes signed weights could help if there are genuine negative indicators that are not captured as positive evidence for other classes.

Bottom line: the non-negativity constraint is a design choice that favors interpretability and robustness in few-shot learning by enforcing that LLM-generated rules remain positive evidence for their target class. The paper demonstrates benefits of learning per-rule importances versus uniform weights but does not report an explicit signed-vs-non-signed weight comparison — that would be a reasonable empirical follow-up.

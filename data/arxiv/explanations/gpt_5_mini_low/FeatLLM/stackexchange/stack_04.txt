\title{Stack Exchange of the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

### How is multi-class classification formulated with per-class rule sets and softmax?
Question:
For multi-class tasks, you build R binary rule features per class and then compute per-class logits before applying softmax. Suppose a sample satisfies many rules for multiple classes. Does the softmax inherently resolve competition, or do you normalize rule counts/weights across classes to handle class-specific differences in the number or "generality" of rules? Also, what happens when a sample satisfies none of the rules for any class—do all logits become zero, leading to a uniform softmax output?
Answer:
Short answer: softmax does resolve the competition across classes at prediction time, but it does not by itself correct for class‑specific differences in the number or generality of rules. In FeatLLM those differences are handled by learning nonnegative per‑rule weights per class (so more and/or stronger rules increase a class logit more), and if a sample satisfies no rules for any class the model (as implemented in the paper) produces equal logits and hence a uniform softmax.

Explanation grounded in the paper. FeatLLM converts the LLM‑generated rules into binary features per class: for class $k$ the feature vector for sample $i$ is $\mathbf{z}_k^i\in\{0,1\}^R$ (one entry per rule). The model computes per‑class logits and then applies a softmax over classes, specifically (Eq. (2) in the paper)

$$
\text{logit}_k^i = \max(\mathbf{w}_k,0)\cdot \mathbf{z}_k^i,\qquad
\mathbf{p}^i = \mathrm{Softmax}([\text{logit}_1^i,\dots,\text{logit}_c^i]).
$$

Intuition about competition and normalization. Softmax turns the class logits into a categorical distribution and therefore enforces competition: a larger logit for class $k$ reduces the relative probability of other classes. However, softmax only reacts to the logits it is given; it does not automatically compensate if some classes have many weak rules while others have few strong rules.

How FeatLLM handles unequal rule counts/generality. The paper addresses class‑specific imbalance by learning the weights $\mathbf{w}_k$ for each class and projecting them to the nonnegative orthant (the $\max(\mathbf{w}_k,0)$ operator). Those learned weights scale each class’s binary rule features: rules that are general but uninformative will receive small learned weights during tuning, whereas informative rules will get larger weights. Thus normalization or reweighting is done via learning rather than by explicit normalizing counts across classes. The ablation study also shows this tuning step improves performance, especially with more shots, which supports that the learned weights correct for per‑class differences in rule usefulness.

What happens if no rule fires for any class. If for sample $i$ we have $\mathbf{z}_k^i=\mathbf{0}$ for every class $k$, then $\text{logit}_k^i=0$ for all $k$ (given the model has no bias term as described). Softmax on the zero vector yields a uniform distribution over classes, so the model is maximally uncertain. In practice FeatLLM mitigates this in two ways: (1) ensembles with bagging produce many different rule sets across trials, so it’s less likely that every trial produces all‑zero logits for a sample; and (2) tuning tends to produce some low‑weight but nonzero structure when rules partially match the data. The paper does not include class biases or offsets in the linear model, so uniform outputs are the direct implication when no rules match.

Practical notes / how you might alter this behavior. If you want the model to prefer certain classes when rules are absent (e.g., incorporate class prior or avoid uniform guesses), you would add class biases or prior log odds, use a temperature on softmax, or normalize per‑class rule sums before weighting. These are not part of FeatLLM as presented, which deliberately uses a simple nonnegative linear readout and trusts learned weights plus ensembling to handle class imbalance and generality of rules.

Summary: softmax enforces competition but does not automatically correct imbalances in rule counts or rule generality; FeatLLM relies on learned per‑rule, per‑class nonnegative weights (and ensembling) to do that. If no rules fire, all logits are zero and the softmax is uniform.

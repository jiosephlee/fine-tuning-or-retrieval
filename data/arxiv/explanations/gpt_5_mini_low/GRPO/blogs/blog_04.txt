# From Chain-of-Thought to Program-of-Thought: Teaching Models to Show Their Work

## Introduction

One of the clearest trends in improving language models on hard math is that "showing your work" helps. DeepSeekMath demonstrates this by combining multiple ways for the model to expose its reasoning: chain-of-thought (CoT), program-of-thought (PoT), and tool-integrated reasoning. Together these instruction-tuning styles let a 7B model punch well above its parameter count on benchmarks like MATH and GSM8K, and—when paired with tools—push the MATH score toward roughly 60%.

This post walks through what each of these formats is, why stepwise reasoning matters, when generating code and executing it helps, and how DeepSeekMath stitches these formats into a single instruction-tuning pipeline to produce stronger, more reliable math solutions.

## Three ways to "show work"

- Chain-of-Thought (CoT): The model writes natural-language intermediate steps that explain the reasoning. CoT is designed to emulate how humans break complex problems into logical steps and has been shown to improve multi-step reasoning by making the chain of inference explicit during generation.

- Program-of-Thought (PoT): Instead of natural-language steps, the model generates a small program (in DeepSeekMath's case, Python). The program implements the logical steps and computations required to solve the problem. The program can then be executed to produce a numerical or symbolic answer.

- Tool-integrated reasoning: This is PoT plus actual execution (and possibly use of libraries like math or sympy). The model emits code and a runtime executes it; the execution result is used as the final answer. Tool integration turns subjective or brittle intermediate reasoning into deterministic computations where appropriate.

DeepSeekMath uses all three during supervised fine-tuning: problems are paired with solutions in CoT, PoT, and tool-integrated formats. The SFT dataset contains problems from both English and Chinese sources, annotated with these stepwise solution styles.

## Why showing steps helps

1. Better credit assignment during learning. When the model produces intermediate steps, the training signal can reinforce correct sub-steps, not just final answers. This reduces reliance on lucky final-token prediction and guides internal reasoning patterns.

2. More robust generation. Models that reason internally (versus jumping directly to answers) tend to produce more interpretable and stable outputs. DeepSeekMath shows that math pre-training plus instruction tuning with CoT/PoT improves not only math benchmarks but also other reasoning tasks (MMLU, BBH).

3. Enables verification and tooling. CoT is interpretable, PoT is executable. Executable steps enable deterministic verification (run the code), which reduces errors from numeric slip-ups or mental arithmetic mistakes in the model's text. This is especially helpful for problems that require precise arithmetic, algebra, or calculus manipulations.

4. Amplifies top-K robustness. The paper observes that reinforcement fine-tuning made the model's output distribution "more robust" by increasing Maj@K (majority across samples) rather than Pass@K. Producing many candidate stepwise solutions (and checking them) benefits from explicit step structure that can be validated or executed.

## When code execution helps (PoT + tools)

PoT becomes especially valuable when:

- The problem requires nontrivial numeric computation, symbolic manipulation, or repeated arithmetic that is tedious and error-prone in free text.
- There is a well-known library that can perform the task reliably (e.g., sympy for algebraic simplification, math for standard functions).
- Deterministic verification of intermediate results reduces uncertainty (you can run the code and check the output).

DeepSeekMath explicitly trains models to write Python programs as part of PoT and to rely on execution in tool-integrated evaluations. The paper reports that DeepSeekMath-Base 7B, when prompted to write runnable Python solutions (PoT + execution), outperforms other prior open-source models on GSM8K and MATH in the program-aided setting. Mixing code tokens into pretraining also helps program-aided reasoning: code training prior to math training yielded improvements in solving math problems via Python.

Caveats: mixing code and math data together can be a double-edged sword for smaller models. For instance, in DeepSeekMath experiments, combining code tokens and math tokens in a single-stage training sometimes reduced performance on purely text-based reasoning relative to a two-stage approach. The model scale and training schedule matter.

## How DeepSeekMath blends the approaches

DeepSeekMath builds a supervised instruction-tuning dataset of roughly 776K examples that mixes CoT, PoT, and tool-integrated solutions across English and Chinese math problems. During SFT:

- Examples are concatenated into 4K-context sequences and used to fine-tune DeepSeekMath-Base 7B.
- The model learns to produce both natural-language step-by-step solutions and runnable Python programs, depending on the prompt and solution style used in training.
- Tool-integrated examples explicitly model program execution as part of the reasoning loop.

This blended instruction tuning makes the model flexible: it can output an explanatory chain, a program, or a program plus execution scaffold depending on the task and prompt.

## Impact on benchmarks

The combined strategy materially improves performance:

- After instruction tuning with CoT/PoT/tool-integrated formats, DeepSeekMath-Instruct 7B significantly outperforms other open-source 7B models on step-by-step reasoning. In the no-tool setting on the competition-level MATH benchmark, it surpasses many open and some proprietary models by large margins.

- When tool use (program execution) is allowed, DeepSeekMath-Instruct 7B "approaches an accuracy of 60% on MATH", surpassing all open-source models in the evaluation and becoming competitive with much larger models on several benchmarks.

- Further reinforcement learning (GRPO) atop the instruction-tuned model improves chain-of-thought performance further (e.g., DeepSeekMath-RL reached 88.2% on GSM8K and 51.7% on MATH using CoT). Self-consistency sampling from DeepSeekMath (64 samples) achieves about 60.9% on MATH, illustrating how sampling + voting over stepwise outputs can raise final accuracy.

The takeaway: mixing explicit step formats and leveraging execution during evaluation enables a 7B model to attain performance previously seen only in much larger models, especially when execution is available to validate computations.

## Practical recommendations

- Use CoT when interpretability and human-readable reasoning are important. It helps training align reasoning steps and supports human-in-the-loop verification.

- Use PoT when the problem involves precise computations or symbolic steps; emitting runnable code reduces arithmetic errors and enables deterministic checking.

- Use tool-integrated evaluation (execute generated code) when correctness depends on exact numeric/symbolic outputs. Tool integration converts otherwise fuzzy reasoning into concrete outputs.

- For training, include a mix of CoT and PoT examples so the model learns both explanatory and executable styles. Be mindful of model size: small models may need staged training (code pretraining then math fine-tuning) to avoid capacity conflicts.

- Combine sampling strategies (e.g., many PoT/CoT samples) with self-consistency or voting to further boost accuracy; DeepSeekMath’s experiments show large gains from sampling and aggregation.

## Limitations and open points

DeepSeekMath notes that some math areas (e.g., geometry and certain theorem-proof tasks) remain weaker than closed models, suggesting that data selection biases or gaps remain. Also, the interactions between code pretraining, math pretraining, and instruction formats depend on model scale and training mix; these are active areas for further research.

## Conclusion

Teaching models to "show their work" via chain-of-thought, program-of-thought, and tool-integrated reasoning is an effective, practical strategy to improve mathematical reasoning. DeepSeekMath demonstrates that a careful blend of these formats in instruction tuning—combined with targeted pretraining and RL—enables a 7B model to reach performance levels on par with much larger systems when execution is allowed. For practitioners, the lesson is clear: make models explain and, when feasible, compute.

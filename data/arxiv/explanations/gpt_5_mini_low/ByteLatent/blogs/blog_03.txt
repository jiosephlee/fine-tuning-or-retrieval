# Inside BLT’s Architecture: Local Byte Models Meet a Global Latent Transformer

BLT (Byte Latent Transformer) is a tokenizer-free large language model that processes raw bytes by grouping them into dynamically sized patches and running a large transformer over those patches. The core intuition is simple but powerful: bytes are the most atomic representation of text, but running a full large transformer on every byte is prohibitively expensive. BLT gets the best of both worlds by sandwiching a large global transformer — the latent model — between two lightweight byte-level models: a local encoder that compresses bytes into patch latents, and a local decoder that expands latents back into bytes. This post unpacks that three-block design, focusing on how BLT pools byte information into patches, how it augments byte embeddings with n-gram hash features, and how the decoder reconstructs raw bytes efficiently.

## High-level anatomy

BLT has three main components:

- Local encoder (E): a small transformer that operates over bytes in a local window. It computes byte-level representations and produces patch queries for cross-attention pooling.
- Latent global transformer (G): a large autoregressive transformer that operates on patch representations. It uses a block-causal attention mask so each patch can attend to previous patches and the current one.
- Local decoder (D): a small transformer that decodes the global patch outputs back to a byte sequence.

The local models are intentionally lightweight: they have far fewer layers than the global model (notation in the paper uses \(l_{\mathcal{E}}, l_{\mathcal{D}} \ll l_{\mathcal{G}}\)). The global transformer consumes most of the FLOPs during pretraining and inference; controlling how often it runs (i.e., how many patches are produced) is the main lever for efficiency.

## From bytes to patches: cross-attention pooling

The encoder’s job is to convert sequences of bytes \(b_i\) into a sequence of patch latents \(p_j\). BLT follows a Perceiver-style cross-attention mechanism, adapted to variable-size patches:

1. Start with byte embeddings \(x_i\), optionally augmented (see n-gram hashes).
2. Run a light-weight transformer stack over those byte embeddings with a local block-causal attention mask: each byte attends to a fixed preceding window \(w_{\mathcal{E}}\). These transformer layers produce contextual byte representations \(h_{l,i}\).
3. For each patch \(p_j\), initialize a query vector \(P_{0,j}\) by pooling the encoder byte representations that belong to patch \(j\). Pooling can be max-pooling or another simple aggregator.
4. Apply multi-headed cross-attention where queries are the patch queries and keys/values are the byte representations for that patch only. The mask ensures each patch’s query only attends to bytes within the patch:
   - \(Q_j = W_q(P_{l-1,j})\)
   - \(K_i = W_k(h_{l-1,i}),\; V_i = W_v(h_{l-1,i})\)
   - Then compute the standard attention update and residualize:
     \(P_l = P_{l-1} + W_o\big(\mathrm{softmax}(QK^\top/\sqrt{d_k})V\big)\)
5. Repeat alternating transformer and cross-attention layers to produce final patch latents \(P_{L}\), denoted \(p_j\), which are passed to the global transformer.

Key points about this design:
- Cross-attention is local to each patch: a patch only pools bytes that belong to that patch. This keeps the pooling efficient and avoids leaking future bytes.
- Patch representations are typically higher-dimensional (the global hidden size \(h_{\mathcal{G}}\)), but cross-attention computations operate in the encoder-hidden dimension \(h_{\mathcal{E}}\) via splitting/concatenation across heads.
- No positional embeddings are used inside the cross-attention module; the encoder’s local transformer already supplies contextualization and relative structure.

This cross-attention pooling decouples the expensive global latent computation from byte-level detail: when data is predictable, patches can be large and the global model is invoked less often; when data is complex, patches are smaller and the global model runs more frequently.

## N-gram hash embeddings: richer byte-level context

A plain byte embedding for \(b_i\) (a 256-way lookup) is not sufficient to give good context for patches. BLT augments byte embeddings with hashed n-gram features to capture short local history efficiently:

- For each byte position \(i\) and for n-gram sizes \(n \in \{3,4,5,6,7,8\}\), form the byte n-gram \(g_{i,n} = \{b_{i-n+1},\ldots,b_i\}\).
- Hash each n-gram via a rolling polynomial hash and index into a fixed-size hash embedding table \(E_n^{hash}\).
- Sum the byte embedding and the hash n-gram embeddings, then normalize by the number of n-gram sizes plus one:
  \[
  e_i = x_i + \sum_{n=3}^{8} E_n^{hash}(\text{Hash}(g_{i,n}))
  \]
- Use \(e_i\) as the input to the encoder transformer.

Why this helps:
- Hash embeddings let BLT capture frequent local byte patterns (subwords, prefixes, short morphemes) without a fixed token vocabulary.
- The hash tables are finite (e.g., 500k entries in the experiments), so this scales memory- and compute-wise better than very large embedding vocabularies.
- Ablations in the paper show n-gram hashes materially improve Bits-Per-Byte on many domains, especially structured sources like GitHub or Wikipedia.

## The global latent transformer: block-causal autoregression

Once patch latents \(p_j\) are produced, they are fed into the global transformer \(\mathcal{G}\). The global model:

- Is autoregressive over patches: it produces output patch representations \(o_j\) conditioned on earlier patches.
- Uses a block-causal attention mask: attention is allowed up to and including the current patch in the same document (so inside-patch dependencies can be represented when needed).
- Is the computational heavyweight in BLT: its size \(l_{\mathcal{G}}\) and hidden dimension \(h_{\mathcal{G}}\) are chosen to dominate FLOPs, because modeling high-level structure between patches benefits from large capacity.

Design consequence: by changing the patching scheme (static, whitespace-based, or entropy-based), BLT controls how frequently the global transformer is invoked per byte. This is the primary mechanism for trading inference cost versus representational granularity.

## From latents back to bytes: decoder cross-attention and autoregressive decoding

Decoding must expand a sequence of patch outputs \(o_j\) into a byte-level autoregressive output \(y_i\). BLT’s decoder mirrors the encoder structure but with reversed roles in cross-attention:

1. Initialize decoder byte representations \(D_0\) from the encoder’s final byte-level hidden states \(h_{l_{\mathcal{E}}}\). These carry local context and serve as starting positions for decoding.
2. For each decoder layer:
   - Apply cross-attention where queries are byte-level representations and keys/values are transformed patch outputs \(\mathcal{D}_C(o_j)\). That is:
     - \(Q_i = W_q(d_{l-1,i})\)
     - \(K_j = W_k(\mathcal{D}_C(o_j)),\; V_j = W_v(\mathcal{D}_C(o_j))\)
     - Compute \(B_l = D_{l-1} + W_o(\mathrm{softmax}(QK^\top/\sqrt{d_k})V)\)
   - Then run a local decoder transformer layer on \(B_l\) to produce \(D_l\).
3. Repeat for \(l_{\mathcal{D}}\) layers. The final decoder outputs feed into a 256-way byte softmax (vocabulary size 256) to predict bytes autoregressively.

Important implementation notes:
- Decoder cross-attention is applied before the local transformer layer in each decoder block so the byte representations can incorporate latent patch information before local byte-level processing.
- The decoder computes predictions over the byte vocabulary (size 256) rather than over a large token vocabulary, keeping the output projection small and fixed regardless of patch size.
- Because the decoder attends to patch latents that summarize a variable number of bytes, it can expand a compact global representation back into detailed byte outputs. This separation keeps the cost of the final output projection independent of patch size.

## Practical points and hyperparameter roles

- Local model sizes: encoder and decoder layer counts \(l_{\mathcal{E}}, l_{\mathcal{D}}\) are much smaller than \(l_{\mathcal{G}}\). Experiments show an extremely lightweight encoder (even one layer) works well when combined with n-gram hashes; the decoder benefits from being somewhat heavier.
- Cross-attention heads and split dimensions: because patch and byte hidden sizes differ, BLT implements cross-attention by representing the patch latent as multiple heads in the encoder’s hidden dimensionality and concatenating after attention.
- No positional embeddings inside cross-attention: positional structure is handled in the local transformers (via RoPE in self-attention), simplifying the cross-attention module.

## Why this design is effective

BLT’s three-block design isolates responsibilities: the local encoder compresses predictable local byte detail into compact latents, the global transformer models higher-level structure and long-range dependencies between patches, and the decoder reconstructs bytes with local conditioning. That separation enables:

- Dynamic compute allocation: when bytes are predictable, patches grow and the global transformer runs less often; when information density rises, patches shrink and more global steps are used.
- Fixed-size output projection: decoding to bytes keeps the final softmax small (256), allowing BLT to increase average patch size without blowing up the output layer.
- Better character-level fidelity and robustness: direct byte modeling plus n-gram features give BLT an edge on noisy or orthographic tasks where tokenizers struggle.

The paper presents ablations and scaling studies that support these architectural choices: cross-attention in the decoder is particularly helpful, n-gram hash embeddings materially improve performance across domains, and entropy-based dynamic patching enables favorable trade-offs between inference FLOPs and task performance.

## Closing

BLT’s local–global–local stack is a clean architectural answer to the problem of scaling byte-level models: small, fast local models handle byte-granular structure and provide pooled inputs to a large latent transformer that captures document-level reasoning; the decoder reverses the process efficiently to produce raw bytes. The result is a tokenizer-free model that can match tokenized baselines at scale while unlocking new efficiency and robustness trade-offs through patching and cross-attention pooling.

\title{Stack Exchange of the Paper: "Controlling Text-to-Image Diffusion by Orthogonal Finetuning"}

### Why does OFT not increase inference-time cost even though it introduces extra parameters?
Question:
The paper claims “no additional inference overhead,” since one can fold the learned $\mathbf R$ into $\mathbf W^0$ as $\mathbf W=\mathbf R\mathbf W^0$. For block-diagonal $\mathbf R$, this is just a pre-multiplication done once before deployment. Are there any caveats for layers that are dynamically re-parameterized at inference (e.g., tied weights, KV-caching, or weight quantization)? Does folding $\mathbf R$ into quantized weights require re-quantization, and if so, does it affect accuracy or latency compared to baseline models?
Answer:
Short answer: OFT itself does not add run-time arithmetic because the learned orthogonal transform $R$ can be multiplied into the pretrained weight matrix $W^0$ once at deployment to produce an equivalent single weight $W = R W^0$. After that $W$ is used exactly like the original $W^0$, so per-inference FLOPs and activation shapes are unchanged. That is the basis of the paper’s “no additional inference overhead” claim.

Caveats and practical points you should watch for in dynamic/optimized inference setups (tied weights, KV-caching, weight quantization):

Tied/shared weights
If the original model shares a single parameter tensor $W^0$ across multiple layers/locations, folding different $R$'s into each usage will break that sharing. To preserve the behavior and keep one folded matrix per shared usage you must either (a) use the same $R$ wherever $W^0$ is shared, or (b) avoid folding and apply the same $R$ at runtime (which re-introduces runtime cost). In short: respect the original tying when you build $W = R W^0$, or accept that you change the sharing semantics.

KV-caching and attention projections
KV-caching stores the projected key/value tensors produced by applying the attention projection matrices to past hidden states. Folding $R$ into the attention projection weights (or into upstream linear layers) changes nothing about the projection operation itself: the projection matrix shape is unchanged, so the cached key/value tensors are computed the same way from inputs and can be cached identically. Therefore folding $R$ offline is compatible with existing caching mechanisms and does not change the cache format or add runtime work. Only caveat: if you applied OFT to some layers but not the ones used to compute cached tensors, make sure you fold the specific projection matrices that are actually used for key/value computation.

Weight quantization
This is the area that needs the most care. Typical pipelines quantize stored weights (e.g., 8-bit or 4-bit) for faster inference and smaller memory. Folding $R$ into $W^0$ produces a new floating-point matrix $W = R W^0$; if you want to run inference on quantized weights you will normally need to re-quantize $W$, because quantization is not linear with respect to an arbitrary matrix product. Two consequences follow:

1) Offline cost: re-quantizing $W$ is an offline deployment step. It adds no per-inference arithmetic cost, only a one-time conversion cost before deployment.

2) Accuracy: re-quantizing the new $W$ can change the model’s numerical behavior compared to quantizing $W^0$ directly. The magnitude and distribution of entries in $W$ typically change after left-multiplication by $R$, and that can affect the quantization error and thus final quality. In practice, because $R$ is orthogonal and preserves vector norms, the change to $W$'s singular values is limited (orthogonal left-multiplication does not amplify norms), so quantization degradation is often small, but you must validate it empirically. If you use post-training quantization, run calibration or per-channel quantization on $W$ after folding; if you use quantization-aware training (QAT), you may need to fine-tune with the folded/quantized weights to fully recover any small accuracy loss.

If you want to avoid re-quantization entirely you have two alternatives, each with trade-offs: (a) keep $R$ as a small float adapter and apply it at runtime (this introduces extra ops and memory reads and defeats the “no inference overhead” promise), or (b) constrain your $R$ during finetuning so that the folded $W$ quantizes similarly to $W^0$ (e.g., limit scale shifts, enforce structure), but that is extra engineering and not what the paper assumes.

Practical recommendations
Fold $R$ into $W^0$ as a deployment step and then quantize the folded weights using your normal quantization pipeline; validate generation quality on a representative set of prompts. If the quantized folded model shows degradation, try per-channel quantization and/or a small calibration/QAT pass with the folded weights. For tied/shared weights, either share $R$ to preserve tying semantics (so you only need one folded $W$) or accept that you will replace the single shared tensor with separate folded tensors (same inference cost, but different model semantics). For KV-caching, you can fold safely—no change to cache behavior.

Bottom line: the “no additional inference overhead” statement in the paper is correct under the usual assumption that you fold $R$ into the base weights once prior to deployment. The main practical issue is deployment-time re-quantization (if you quantize): that is an offline cost and can slightly change accuracy, so you should re-quantize/corroborate and, if necessary, run a light calibration or QAT step on the folded weights.

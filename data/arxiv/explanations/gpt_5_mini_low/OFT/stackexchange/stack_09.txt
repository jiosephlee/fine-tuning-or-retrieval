\title{Stack Exchange of the Paper: "Controlling Text-to-Image Diffusion by Orthogonal Finetuning"}

### Reconciling parameter complexity claims for OFT vs LoRA when $n\neq d$
Question:
Section 3.3 compares trainable parameter counts, stating LoRA has $r'(d+n)$ while OFT with $r$ blocks has roughly $\mathcal O(d^2/r)$. The later claim that OFT becomes $\mathcal O(d)$ when $r=\alpha d$ seems to assume $r$ scales with $d$. In practice for attention layers, $n$ (number of neurons/heads/out-dim) may differ from $d$ (in-dim). Could you provide a more explicit comparison for a typical SD v1.5 attention layer shape (e.g., $d=768$, $n=768$ per head projection or similar), and clarify regimes (values of $r, r'$) where OFT is strictly more parameter-efficient than LoRA?
Answer:
Short answer: OFT’s parameter count falls as you increase the number of orthogonal blocks $r$, while LoRA’s grows linearly with the chosen low-rank $r'$. For the concrete Stable Diffusion–style example you asked ($d = 768$, $n = 768$) the crossover point is modest: with LoRA rank $r' = 8$, OFT becomes smaller once $r \gtrsim 24$ blocks. Below I show the algebra, explicit numbers, and the intuitive regime interpretation so you can decide which method is more parameter-efficient in practice.

Derivation and formulae (grounded in the paper)
LoRA (as stated in the paper) uses $r'$ and has trainable parameters
  $P_{\text{LoRA}} = r' (d + n)$.

OFT parameterizes a block-diagonal orthogonal matrix with $r$ blocks of size $d/r$ each. The paper gives the number of free parameters for that $R$ as
  $P_{\text{OFT}} = \dfrac{d\bigl(d/r - 1\bigr)}{2}$,
which is $\approx d^2/(2 r)$ for large $d$ (dominant term).

To compare, solve $P_{\text{OFT}} \le P_{\text{LoRA}}$:
  $\dfrac{d\bigl(d/r - 1\bigr)}{2} \le r' (d + n)$
which we can approximate by the dominant term
  $\dfrac{d^2}{2 r} \le r'(d + n)$
so roughly
  $r \ge \dfrac{d^2}{2 r' (d + n)}$.

Concrete Stable Diffusion example: $d = 768$, $n = 768$
Plugging numbers into the exact formulas:

LoRA:
- $P_{\text{LoRA}} = r' (768 + 768) = r' \times 1536$.
  Examples: $r' = 4 \to 6{,}144$; $r' = 8 \to 12{,}288$; $r' = 16 \to 24{,}576$; $r' = 32 \to 49{,}152$.

OFT:
- $P_{\text{OFT}} = \dfrac{768\bigl(768/r - 1\bigr)}{2}$.
  Compute common $r$ choices:
   $r = 1  \to 294{,}528$
   $r = 2  \to 147{,}072$
   $r = 4  \to 73{,}344$
   $r = 8  \to 36{,}480$
   $r = 16 \to 18{,}048$
   $r = 32 \to 8{,}832$
   $r = 64 \to 4{,}224$
   $r = 128\to 1{,}920$
   $r = 256\to 768$

Crossover (numerical)
Using the approximate inequality above for $d = n = 768$:
  $r \gtrsim \dfrac{768^2}{2 r' \times 1536} = \dfrac{589{,}824}{3072\, r'} = \dfrac{192}{r'}$.

Thus:
- If $r' = 4 \to$ need $r \gtrsim 48$ for OFT to be smaller than LoRA.
- If $r' = 8 \to$ need $r \gtrsim 24$.
- If $r' = 16 \to$ need $r \gtrsim 12$.
- If $r' = 32 \to$ need $r \gtrsim 6$.

Check with numbers: for $r' = 8$, LoRA uses $12{,}288$ params; OFT at $r = 24$ (interpolating between $r=16$ and $r=32$) is $\approx$ between $18{,}048$ and $8{,}832$ so indeed $r \approx 24$ is about the break-even.

Practical interpretation and trade-offs
Three facts you should keep in mind when deciding which is more parameter-efficient in practice:

1) Dependence on $n$ matters. LoRA’s cost includes $(d + n)$. If the output dimension $n$ is larger than $d$ (e.g., some MLP layers or expanded projection sizes), LoRA becomes relatively more expensive and OFT’s $d^2/(2r)$ scaling becomes comparatively better. Conversely, if $n \ll d$, LoRA is cheaper for the same rank choices.

2) OFT’s $r$ is the number of orthogonal blocks (higher $r = $ smaller block size = fewer parameters). Increasing $r$ reduces OFT’s parameter cost as $O(d^2/r)$. But larger $r$ also reduces the expressive power of $R$ (more, smaller independent rotations), so there is a flexibility vs regularization trade-off. The paper demonstrates good results with moderate $r$ choices — not necessarily $r \propto d$.

3) LoRA’s $r'$ controls rank of an additive update. Small $r'$ (4–16) is common and gives very small parameter counts. For typical LoRA ranks, OFT must use a fairly large number of blocks to beat LoRA in raw parameter count (see table above). For example with LoRA $r' = 8$, OFT must use $r \gtrsim 24$ blocks to be strictly smaller in parameters.

Other practical knobs mentioned in the paper
The paper also notes two ways OFT can further reduce parameters (at the cost of architectural bias): share the block matrix across blocks (they claim parameter complexity can become $O(d^2 / r^2)$ in that shared-block extreme) or increase $r$ (more blocks). Shared blocks can dramatically lower $P_{\text{OFT}}$ — for $d = 768$ and $r = 32$, sharing a single $24\times 24$ orthogonal block would make parameters $\approx (24\cdot 23)/2 = 276$, which is tiny — but that is a much stronger inductive bias and may or may not work for your layer.

Bottom-line guidance
If you are comparing typical LoRA ranks used in practice ($r' = 4$–$16$) and you want OFT to be strictly more parameter-efficient, pick $r$ (number of OFT blocks) so that
  $r \gtrsim \dfrac{d^2}{2 r' (d + n)}$,
which for $d = n = 768$ becomes $r \gtrsim 192/r'$. Concretely, for LoRA $r' = 8$ you need about $r \ge 24$. If you can afford that many blocks (i.e., accept the blockwise constraint), OFT will beat LoRA in parameter count; if you insist on few blocks (small $r$) then LoRA at modest $r'$ will usually be smaller.

Finally, remember that parameter count is only one axis: OFT and LoRA impose different structural biases (orthogonal multiplicative transforms vs low-rank additive updates). The paper’s experiments show OFT/COFT can produce better convergence and stability even when parameter counts are comparable, so also consider empirical performance, not just raw parameter efficiency.

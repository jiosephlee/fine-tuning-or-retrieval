QLoRA takes this a step further: although the base weights $\mathbf{W}$ are stored in 4-bit form, each time they are needed they are dequantized into a higher-precision computation type (e.g., BF16) so that the forward and backward passes execute in high precision. 1) 4-bit NormalFloat (NF4)  Quantization requires choosing a small discrete set of representable values and a mapping from high-precision numbers into that set. Concretely, the method estimates the appropriate quantile boundaries for a standard normal $N(0,1)$, rescales the particular weight tensor via its absolute maximum into the $[-1, 1]$ range that matches the data type, and assigns each weight to the nearest of these normal-quantile-derived levels. After double quantization (with 8-bit floats for the second level and a blocksize of 256 for the meta-level), the average cost drops to about $8/64 + 32/(64\cdot256) \approx 0.127$ bits per parameter — a savings of roughly $0.373$ bits per parameter, which translates to multiple gigabytes for the largest models (the paper reports around a 3 GB reduction for a 65B model). 3) Paged Optimizers  During training, optimizer states and occasional memory spikes (for example, due to long sequences combined with gradient checkpointing) can exceed the GPU memory capacity even if the steady-state storage would fit.

Chapter Title: Memory-Efficient Finetuning via Quantized Bases and Low-Rank Adapters

# Introduction

Finetuning large language models entails substantial computational and memory costs. A conventional 16-bit finetuning run for a model with tens of billions of parameters can easily exceed hundreds of gigabytes of GPU memory. The QLoRA approach addresses this bottleneck by combining low-bit quantization of a pretrained base model with high-precision Low-Rank Adapters, enabling training on a single GPU while matching the predictive performance of 16-bit finetuning.

At the heart of QLoRA is the observation that one can freeze a quantized base model, dequantize it on-the-fly to a high-precision computation type during the forward and backward passes, and restrict parameter updates to small LoRA modules. This design allows the bulk of the model parameters to be stored with very few bits per value, dramatically lowering the static memory footprint. The paper demonstrates this at 4-bit precision using a new data type, NormalFloat4 (NF4), along with double quantization of the quantization constants and paged optimizers to control transient allocation spikes. The result is 65B-parameter finetuning on a single 48 GB GPU without degrading runtime or task performance relative to full 16-bit finetuning.

Within this framework, the paper also discusses the prospect of even more aggressive quantization. If 3-bit base quantization with LoRA were to preserve 16-bit finetuning performance, the most likely resource outcome would be a smaller memory footprint. This chapter builds the intuition for why this follows from the mechanics of QLoRA, quantization overheads, and where memory is actually consumed during finetuning.

# Quantization and Memory: From Principles to Footprint

Quantization maps high-precision values to a low-bit representation. For a tensor quantized into a k-bit format, the stored values come from a discrete set of \(2^k\) levels and are associated with a quantization constant (or scale) that maps the original floating-point range into the representable low-bit range. The standard procedure for block-wise \(k\)-bit quantization begins by partitioning a tensor \(\mathbf{X}\) into contiguous blocks and normalizing each block by its absolute maximum. For instance, mapping FP32 to Int8 with range \([-127,127]\) proceeds as
\[
\mathbf{X}^{\text{Int8}} = \text{round}\!\left(\frac{127}{\text{absmax}(\mathbf{X}^{\text{FP32}})} \,\mathbf{X}^{\text{FP32}}\right) 
= \text{round}\!\left(c^{\text{FP32}}\cdot \mathbf{X}^{\text{FP32}}\right),
\]
where \(c^{\text{FP32}}\) is the quantization constant for that block. The original values can be exactly reconstructed (in the ideal noise-free sense) via
\[
\text{dequant}(c^{\text{FP32}},\mathbf{X}^{\text{Int8}})=\frac{\mathbf{X}^{\text{Int8}}}{c^{\text{FP32}}}=\mathbf{X}^{\text{FP32}}.
\]

When a tensor contains outliers, a single global scale is inefficient because the dynamic range gets dominated by extreme values. Block-wise quantization remedies this by using many small blocks, each with its own scale. This improves representational fidelity but introduces overhead: each block must also store a quantization constant alongside its low-bit values.

In QLoRA, the static memory footprint is dominated by the base model parameters (now stored in a low-bit format) and their associated quantization constants. Adapter parameters and their gradients are comparatively small. Consequently, the number of bits per stored weight and the overhead per block directly determine the total finetuning memory budget. Reducing the base representation from 4 bits to 3 bits—if it can be done without hurting performance—would therefore reduce the per-parameter storage and shrink the overall footprint. The paper’s method quantizes weights at 4 bits and then takes additional steps to shrink the quantization overhead, as explained next.

# Low-Rank Adapters and Training Memory

LoRA introduces a small set of trainable parameters into otherwise frozen layers. Given a linear projection \(\mathbf{Y}=\mathbf{X}\mathbf{W}\) with \(\mathbf{X}\in\mathbb{R}^{b\times h}\), \(\mathbf{W}\in\mathbb{R}^{h\times o}\), LoRA augments it with a rank-\(r\) factorization:
\[
\mathbf{Y}=\mathbf{X}\mathbf{W} + s\,\mathbf{X}\mathbf{L}_1\mathbf{L}_2,
\]
where \(\mathbf{L}_1\in\mathbb{R}^{h\times r}\), \(\mathbf{L}_2\in\mathbb{R}^{r\times o}\), and \(s\) is a scalar. Only \(\mathbf{L}_1,\mathbf{L}_2\) are updated during finetuning; the base \(\mathbf{W}\) remains fixed in storage.

A crucial observation in the paper is that LoRA’s parameter count and memory are small compared to other contributors during training. For a 7B model, an illustrative breakdown shows that the 4-bit base model consumes gigabytes, while LoRA parameters are on the order of tens of megabytes. Even LoRA input gradients can exceed the size of the LoRA parameters, although gradient checkpointing reduces their average footprint dramatically. This asymmetry explains why using more adapters can be beneficial without materially increasing the memory budget: the dominant term is the quantized base model storage, not the adapter parameters.

Because the base is frozen, gradients with respect to \(\mathbf{W}\) are not needed; instead, QLoRA dequantizes \(\mathbf{W}\) into the computation type to backpropagate through the frozen weights and update \(\mathbf{L}_1,\mathbf{L}_2\). This design keeps the static storage in a low-bit format while performing forward and backward passes in 16-bit precision for numerical stability.

# NormalFloat4: Information-Theoretically Optimal 4-Bit Weights

QLoRA introduces NormalFloat (NF) as a k-bit data type that is information-theoretically optimal for zero-centered normally distributed weights. The construction uses quantile quantization tailored to the standard normal \(N(0,1)\), pushing each of the \(2^k\) bins to contain (in expectation) equal mass from the distribution. After estimating the quantiles of \(N(0,1)\), the quantization levels are normalized into \([-1,1]\), and weights are rescaled into the same range by adjusting their standard deviation via block-wise normalization.

Formally, define the data type values by
\[
q_i = \frac{1}{2}\Bigl(Q_X\!\left(\frac{i}{2^k+1}\right)+Q_X\!\left(\frac{i+1}{2^k+1}\right)\Bigr),
\]
where \(Q_X(\cdot)\) is the quantile function of \(N(0,1)\). To preserve an exact zero point and use all \(2^k\) codes, an asymmetric construction allocates one extra bin on one side and removes the duplicated zero. The resulting NF4 data type achieves better empirical performance than FP4 and Int4 in the paper’s experiments while adhering to the constraints required for efficient dequantization at training time.

In QLoRA, the storage type is typically 4-bit NF4, and the computation type is BFloat16. During a linear layer, the weight matrix is dequantized on-the-fly to BF16 and multiplied in 16-bit precision. The layer output including the LoRA contribution is
\[
\mathbf{Y}^{\text{BF16}}=\mathbf{X}^{\text{BF16}}\,\text{doubleDequant}(c_1^{\text{FP32}},c_2^{\text{k-bit}},\mathbf{W}^{\text{NF4}})+\mathbf{X}^{\text{BF16}}\mathbf{L}_1^{\text{BF16}}\mathbf{L}_2^{\text{BF16}}.
\]

# Double Quantization: Shrinking the Overhead per Parameter

Block-wise quantization introduces overhead because every block stores one or more quantization constants in higher precision. With 32-bit constants and block size \(B=64\), a single constant adds \(32/64=0.5\) bits per parameter on average. To reduce this cost, the paper introduces double quantization: quantize the quantization constants themselves in an 8-bit floating-point format with a larger block size.

Specifically, let \(c_2^{\text{FP32}}\) denote the 32-bit constants from the first stage. These are block-quantized into \(c_2^{\text{FP8}}\) using block size \(256\), accompanied by a new set of second-level constants \(c_1^{\text{FP32}}\). Because \(c_2^{\text{FP32}}\) are positive, they are mean-centered before the second quantization to exploit symmetry. The two-level dequantization performed during training is
\[
\text{doubleDequant}(c_1^{\text{FP32}},c_2^{\text{k-bit}},\mathbf{W}^{\text{k-bit}})
=\text{dequant}\bigl(\text{dequant}(c_1^{\text{FP32}},c_2^{\text{k-bit}}),\mathbf{W}^{\text{k-bit}}\bigr)
=\mathbf{W}^{\text{BF16}}.
\]

On average, with \(B=64\) for weights and \(256\) for the constants, the overhead drops from \(32/64=0.5\) bits per parameter to
\[
\frac{8}{64}+\frac{32}{64\cdot 256}=0.127\ \text{bits per parameter},
\]
for a savings of \(0.373\) bits per parameter. For very large models, this equates to multiple gigabytes of memory saved solely by compressing the scales.

# Paged Optimizers: Managing Transient Spikes

Even when the static storage is small, minibatches with long sequences can cause transient activations and optimizer state spikes that exceed the available GPU memory. QLoRA employs paged optimizers that rely on unified memory to page optimizer state between GPU and CPU when pressures exceed the GPU budget. This ensures finetuning runs proceed without out-of-memory errors, while measurements reported in the paper indicate comparable speed to regular optimizers in the relevant regimes.

This technique acts orthogonally to quantization: it does not change the bits per parameter but prevents occasional spikes from failing a run. Combined with low-bit storage and double quantization, paged optimizers enable single-GPU finetuning of models at unprecedented scales.

# From 4 Bits to 3 Bits: Why the Footprint Would Shrink

The paper demonstrates that 4-bit QLoRA with NF4 and double quantization matches the performance of 16-bit finetuning across a broad range of settings. It also raises the possibility of more aggressive quantization in its limitations and discussion, noting that finetuning after quantization appears to recover most of the information lost during quantization and suggesting that 3-bit base quantization combined with LoRA might also yield 16-bit performance after finetuning.

If that hypothesis holds, the most likely resource outcome is a smaller memory footprint. This follows directly from the arithmetic of storage:

1. The base weight tensor would move from 4 bits per parameter to 3 bits per parameter in storage. Since the base weights constitute the dominant term in the static memory budget, this change yields an immediate proportional reduction in that term.

2. The quantization overhead per parameter is already minimized by double quantization. While the exact overhead at 3 bits is not specified in the paper, the overhead due to scales is independent of whether the payload values are 4 bits or 3 bits, given fixed block sizes and the same double quantization configuration. Thus the relative importance of overhead grows slightly in percentage terms when the payload shrinks, but the total footprint still decreases because the payload shrinks by \(25\%\) per parameter when going from 4 to 3 bits.

3. The LoRA parameters and their gradients remain at 16-bit precision and are already a very small fraction of total memory compared to the base. Gradient checkpointing continues to bound activation memory. Consequently, the overall profile is still dominated by the base model storage, which is reduced when lowering from 4 to 3 bits.

Put succinctly, if a 3-bit representation can be used without hurting finetuning outcomes, the term that dominates memory—the base weights—would be stored with fewer bits per parameter, and the rest of the training stack (adapters, dequantization to BF16 for compute, paged optimizer behavior) remains unchanged. Therefore, the static footprint decreases.

It is important to emphasize that this is a hypothetical extension identified by the paper as future work. The paper provides empirical validation for 4-bit NF4 with double quantization and LoRA, but does not evaluate 3-bit finetuning. The conclusion about memory follows from the same accounting that underlies the 4-bit results: fewer bits per stored value implies fewer total bytes for the base model parameters, and therefore a smaller memory footprint, provided performance can be preserved.

# Empirical Results at 4 Bits and Open Questions

The paper’s experiments show that:

- 4-bit QLoRA with NF4 and double quantization matches 16-bit adapter finetuning and full 16-bit finetuning across tasks and model scales where direct comparisons are feasible.
- NF4 outperforms FP4 and Int4 in post-quantization evaluations, and double quantization does not degrade performance while saving memory.
- With appropriate LoRA placement—adapters at every linear layer—4-bit QLoRA recovers 16-bit performance, while default LoRA configurations that limit adapters to attention projections can underperform.
- Paged optimizers stabilize training under memory pressure without observed slowdowns in the tested high-parameter regimes.

These results establish that decreasing the precision of stored weights to 4 bits, when combined with LoRA and the QLoRA engineering stack, does not require sacrificing task performance. The limitations section highlights the open question of how far precision can be reduced before a performance-precision trade-off materializes for QLoRA training. The suggestion that 3-bit base quantization plus LoRA could work similarly is thus a plausible, testable hypothesis, and if confirmed, it would reduce memory consumption even further for the reasons discussed above.

# Conclusion

QLoRA achieves memory-efficient finetuning by storing a frozen base model in a low-bit format and training small LoRA adapters in high precision, dequantizing on-the-fly for computation. The NF4 data type provides an information-theoretically grounded 4-bit representation for normally distributed weights, while double quantization compresses the quantization constants to minimize overhead. Paged optimizers further guard against transient memory spikes.

Because the memory profile is dominated by the base model storage, the number of bits per stored weight is the primary driver of the static footprint. The paper validates that 4-bit QLoRA can match 16-bit finetuning performance and identifies the possibility of pushing quantization even more aggressively. If 3-bit base quantization with LoRA were to preserve performance as hypothesized, the natural and most likely consequence would be an even smaller memory footprint, since fewer bits per parameter translate directly to fewer total bytes for the dominant storage term. This would extend QLoRA’s central promise: enabling finetuning of ever larger models on modest hardware budgets without compromising accuracy.

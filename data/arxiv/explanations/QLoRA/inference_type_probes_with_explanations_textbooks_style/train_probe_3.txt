Chapter: Quantization Constants as Scale Factors in QLoRA

# Quantization as Rescaling Between Representations

Quantization converts values from a high-information representation to a low-information representation by discretizing them. In the context of large language models, this typically means mapping tensors stored in a high-precision floating-point format, such as FP32, into a low-bit format, such as Int8 or 4-bit codes. The central mechanism that makes this mapping precise is a rescaling step that aligns the dynamic range of the input tensor with the dynamic range of the target low-bit datatype. This rescaling introduces a scalar that the paper terms the quantization constant, denoted by $c$.

The role of $c$ is most clearly seen in the canonical scheme of rescaling by the absolute maximum value of a tensor. Consider a tensor $\mathbf{X}^{\text{FP32}}$ and an Int8 target format with range $[-127,127]$. Quantization proceeds by computing a scale $c^{\text{FP32}} = \frac{127}{\text{absmax}(\mathbf{X}^{\text{FP32}})}$ and then rounding:
\[
\mathbf{X}^{ \text{Int8}} = \text{round}\!\left( c^{\text{FP32}} \cdot \mathbf{X}^{\text{FP32}} \right).
\]
Dequantization is the inverse mapping:
\[
\text{dequant}\!\left(c^{\text{FP32}}, \mathbf{X}^{\text{Int8}}\right) = \frac{\mathbf{X}^{\text{Int8}}}{c^{\text{FP32}}} = \mathbf{X}^{\text{FP32}}.
\]
Conceptually, $c$ acts as a scale factor that normalizes a high-precision tensor into the range of the low-bit representation, and the same factor undoes the mapping to recover the high-precision values. Thus, $c$ provides the bridge between the two representations, expanding or contracting values so that the low-bit codes meaningfully cover the range of the original data and then reversing that rescaling during computation.

This rescaling perspective makes the design of quantization schemes intuitive. If the scale factor is too small, many values will clip or many bins will be underused; if the scale factor is too large, values will bunch up and quantization error will increase. The absolute-maximum-based choice for $c$ ensures that the most extreme magnitude in a tensor maps to the edge of the representable range, using the full set of bins.

# The Quantization Constant in Block-wise Quantization

A well-known failure mode of global rescaling is the presence of outliers: a single large-magnitude value can force the scale to stretch to cover that outlier, wasting bins on ranges where there are no values, and thereby increasing quantization error for the majority of values. To mitigate this, the paper uses block-wise $k$-bit quantization: the tensor is flattened and chunked into contiguous blocks of size $B$, and each block is quantized independently with its own scale $c_i$.

Formally, for $\mathbf{X}\in\mathbb{R}^{b\times h}$ flattened into $n=(b\times h)/B$ blocks, each block gets its own constant $c_i$ and is quantized via the same rescaling-and-rounding formula. In this block-wise setting, the quantization constant remains a scale factor, but now it is local to each block. This locality allows $c_i$ to adapt to the distribution of values within its block, which reduces the impact of outliers elsewhere in the tensor and makes the mapping between high-bit and low-bit representations more faithful block by block.

The intuition is that by giving each block its own $c_i$, the values within a block can be spread across the low-bit bins more uniformly, because $c_i$ is not inflated by outliers from other parts of the tensor. In turn, dequantization applies each $c_i$ to its block to reconstruct the high-precision values for computation, preserving the role of the constant as the local scale factor.

# NormalFloat (NF4): Optimal Binning and Scaling for Normal Weights

While absolute-maximum rescaling sets a scale factor mechanically, the precision of quantization also depends on how the bins are placed within the representable range. The paper introduces 4-bit NormalFloat (NF4), an information-theoretically optimal data type for zero-mean normally distributed data, motivated by the empirical observation that pretrained neural network weights usually have a zero-centered normal distribution with standard deviation $\sigma$.

NF4 is built using quantile quantization. For a $k$-bit code, one estimates $2^k+1$ quantiles of the standard normal distribution $N(0,1)$ and defines the $2^k$ representable values $q_i$ as midpoints between adjacent quantiles:
\[
q_i = \frac{1}{2}\left( Q_X\!\left(\frac{i}{2^k+1}\right) + Q_X\!\left(\frac{i+1}{2^k+1}\right) \right),
\]
where $Q_X(\cdot)$ is the quantile function of $N(0,1)$. These $q_i$ are then normalized into a fixed range, set to $[-1,1]$ in the paper, and the input weight tensor is normalized into that same range via absolute maximum rescaling. Once both ranges match, quantization proceeds as usual.

Two aspects of scaling are at work here. First, the NF4 bin locations are tailored to the distribution of weights, causing each bin to receive an equal expected number of values under the normal distribution. Second, the quantization constant again serves as a scale factor that normalizes a block of weights into the $[-1,1]$ range so that the NF4 codes align with the empirical distribution of weights. The paper addresses a practical issue—representing zero exactly—by constructing an asymmetric data type that ensures a discrete zero point while still using all $2^k$ bins.

In effect, NF4 pairs an optimal bin placement for normally distributed data with the same scaling mechanism governed by $c$. The constant $c$ ensures that, within each block, the empirical weight magnitudes are rescaled to the canonical range so the NF4 binning operates where it is designed to be optimal.

# Double Quantization: Scaling the Scales

Block-wise quantization introduces many quantization constants—one per block—which incurs a nontrivial memory overhead. For a blocksize of $64$ and storing each $c$ in 32 bits, the overhead is $32/64=0.5$ bits per parameter on average. The paper introduces Double Quantization (DQ) to quantize the quantization constants themselves, thereby reducing this overhead.

DQ treats the first-level quantization constants $c_2^{\text{FP32}}$ as inputs to a second quantization. This second step quantizes $c_2^{\text{FP32}}$ into $c_2^{\text{FP8}}$ with its own blocksize of $256$, and yields a second-level scale $c_1^{\text{FP32}}$. Because $c_2^{\text{FP32}}$ are positive, the mean is subtracted to center them around zero for symmetric quantization. The memory cost per parameter for the constants is thereby reduced from $32/64=0.5$ bits to
\[
\frac{8}{64} + \frac{32}{64\cdot 256} = 0.127 \text{ bits,}
\]
a reduction of $0.373$ bits per parameter.

In this hierarchical scheme, the role of the quantization constants as scale factors is explicit at both levels. The second-level scale $c_1^{\text{FP32}}$ rescales blocks of the first-level constants so they can be represented in FP8, and the first-level constants $c_2$ rescale weight blocks so they can be represented in the primary $k$-bit format (NF4). Dequantization composes these scales:
\[
\text{doubleDequant}\!\left( c_1^{\text{FP32}}, c_2^{\text{k-bit}}, \mathbf{W}^{\text{k-bit}} \right)
= \text{dequant}\!\left( \text{dequant}\!\left( c_1^{\text{FP32}}, c_2^{\text{k-bit}} \right), \mathbf{W}^{\text{k-bit}} \right)
= \mathbf{W}^{\text{BF16}}.
\]
This composition makes the conceptual role of $c$ even clearer: regardless of level, each $c$ exists to scale values from one representation into the range where the next representation is meaningful and precise, and the inverse mapping is obtained by dividing out by the same scale, possibly in multiple stages.

# Where the Scale Factors Operate in QLoRA’s Computation

QLoRA uses a low-precision storage datatype—typically 4-bit—and a higher precision computation datatype, typically BFloat16. Whenever a weight tensor is used in computation, the stored low-bit weights are dequantized into BFloat16 using the quantization constants. For a single linear layer with a LoRA adapter, QLoRA defines the forward computation as
\[
\mathbf{Y}^{\text{BF16}} = \mathbf{X}^{\text{BF16}} \cdot \text{doubleDequant}\!\left( c_1^{\text{FP32}}, c_2^{\text{k-bit}}, \mathbf{W}^{\text{NF4}} \right) + \mathbf{X}^{\text{BF16}} \mathbf{L}^{\text{BF16}}_1 \mathbf{L}^{\text{BF16}}_2.
\]
Here, the doubleDequant function reconstructs the BFloat16 weights from the NF4 codes by sequentially undoing the scales $c_2$ and $c_1$. The learned parameters are the adapter matrices $\mathbf{L}_1$ and $\mathbf{L}_2$ in 16-bit, while the base weights are frozen and stored in 4-bit.

During backpropagation, gradients with respect to the LoRA parameters require derivatives that flow through the dequantization mapping. The paper notes that although gradients with respect to the 4-bit weights $\partial E/\partial \mathbf{W}$ are not needed for parameter updates, the calculation of the adapter gradients $\partial E/\partial \mathbf{L}_i$ entails computing derivatives through $\mathbf{X}$ with respect to $\mathbf{W}$, which is performed after dequantizing $\mathbf{W}^{\text{NF4}}$ to $\mathbf{W}^{\text{BF16}}$. Thus, the presence of $c$ as scale factors has operational implications: they define the precise mapping used both in the forward pass to construct the computation-time weights and in the backward pass to compute the necessary derivatives in BFloat16 precision.

# Zero Points, Asymmetry, and the Scale’s Practical Role

A subtle but important concern arises around representing zero exactly. For symmetric $k$-bit quantization derived from quantiles, a straightforward scheme does not necessarily include an exact zero code, yet representing zeros exactly is important for padding and other zero-valued elements. The paper resolves this by constructing an asymmetric NF data type: it estimates quantiles separately for negative and positive ranges, uses $2^{k-1}$ bins for the negative part and $2^{k-1}+1$ bins for the positive part, unifies the sets, and removes one duplicated zero to ensure a discrete zero point.

In this design, the quantization constant continues to function as the scale factor that aligns the input block to the $[-1,1]$ range of the NF data type. The asymmetry adjusts bin allocation while retaining the same conceptual scaling step. The presence of a discrete zero aligns with the goal that, when a value is exactly zero, the rescaling by $c$ maps it to zero in the low-bit domain and dequantization maps it back to zero with no error.

# Memory Footprint and the Cost of Scale Factors

QLoRA’s efficiency arguments hinge on where memory is spent. The 4-bit base model constitutes the bulk of the memory footprint, while LoRA parameters and their gradients are comparatively small. However, in block-wise quantization, storing per-block scale factors can add up. This motivates Double Quantization, which compresses the constants themselves and yields an average reduction of $0.373$ bits per parameter for a blocksize of $64$, translating to approximately $3$ GB of savings for a 65B parameter model.

The key insight is that even though $c$ is conceptually “just a scale factor,” in practice it is a large collection of per-block constants that must be retained to invert the mapping. Therefore, the paper’s contribution is to treat these scale factors as data subject to the same efficiency tricks, i.e., quantize them with their own scale factors. This recursive application preserves the conceptual role of $c$ while pushing down memory overheads without degrading performance.

# Empirical Performance and the Fidelity of Scaled Mappings

The paper evaluates whether the low-bit storage plus dequantization via scale factors yields empirical performance on par with higher precision finetuning. Across multiple settings, QLoRA with NF4 and Double Quantization matches 16-bit full finetuning and 16-bit LoRA performance on key benchmarks, including GLUE, Super-NaturalInstructions, and MMLU in the tested regimes. Moreover, NF4 outperforms FP4 and Int4 in post-quantization accuracy and perplexity, while Double Quantization does not degrade performance.

These results are consistent with the understanding that scale-factor-based mappings, when combined with an appropriate data type whose bins match the weight distribution and when applied block-wise, can preserve the information necessary for high-fidelity computation after dequantization. The quantization constant $c$ is central to this story: it is the precise scale that aligns domains, making it possible to alternate between compact storage and precise computation without loss in downstream task performance.

According to the paper 'QLoRA: Efficient Finetuning of Quantized LLMs', if $3$-bit base quantization plus LoRA worked as hypothesized, the most likely resource outcome would be a smaller memory footprint. This follows because the dominant static memory term in QLoRA is the quantized base model storage, which the paper reduces from 16-bit to 4-bit NF4 with double quantization while keeping LoRA adapters small and fixed in 16-bit; crudely, if the per-parameter storage for weights is modeled as $M_{\text{weights}} \approx N\cdot(k + \beta)/8$ bytes with $N$ parameters, $k$ effective bits for the main quantizer, and a small overhead $\beta$ from quantization constants (further shrunk via double quantization), then lowering $k$ from $4$ to $3$ yields a proportional $\approx 25\%$ reduction in $M_{\text{weights}}$ without increasing $\beta$, directly shrinking the overall training footprint because activations and LoRA parameters were shown to be secondary contributors (e.g., a 4-bit 7B base took 5{,}048 MB vs. 26 MB for LoRA weights and at most hundreds of MB for LoRA input gradients with checkpointing). The paper’s limitations explicitly suggest that “3-bit GPTQ quantization of the basemodel with LoRA might also yield 16-bit full finetuning performance after finetuning,” and given that QLoRA already matches 16-bit performance with 4-bit NF4 while double quantization reduces scale overhead by $0.373$ bits/parameter, pushing base precision to $3$ bits would, under the same fidelity assumption, reduce the stored model term further, with paged optimizers and dequantization-at-compute preserving runtime behavior and leaving the adapters unchanged, hence producing a smaller total memory footprint.

In the paper 'QLoRA: Efficient Finetuning of Quantized LLMs', to handle rare memory spikes from long sequences, QLoRA's paged optimizers rely on a mechanism analogous to the standard operating system technique called memory paging. This is because the “Paged Optimizers” allocate optimizer states in NVIDIA Unified Memory, which performs automatic page-to-page transfers between GPU and CPU RAM when the GPU oversubscribes memory, evicting data to host memory and paging it back on demand during the optimizer update—explicitly described as working “like regular memory paging between CPU RAM and the disk.” In QLoRA’s setup, long-sequence mini-batches (especially under gradient checkpointing) cause transient activation/gradient spikes; by placing optimizer states in pageable unified memory, these spikes can be absorbed without out-of-memory errors, with the runtime cost minimized since paging is rare and localized to the spikes (the authors report equal training speed to regular optimizers for a LLaMA-65B run with batch size 16 on a 48 GB GPU). Thus, the approach mirrors OS-level demand paging semantics—temporary eviction and fault-driven reloading of memory pages—to seamlessly bridge short-lived GPU memory shortfalls.

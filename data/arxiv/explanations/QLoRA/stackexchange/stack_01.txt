\title{Stack Exchange of the Paper: "QLoRA: Efficient Finetuning of Quantized LLMs"}

### Why does QLoRA say we need to compute \(\partial \mathbf{X} / \partial \mathbf{W}\) to train LoRA if base weights are frozen?
Question:
In Section "QLoRA" the paper states: "For parameter updates only the gradient with respect to the error for the adapters weights \(\partial E/\partial \mathbf{L}_i\) are needed, and not for 4-bit weights \(\partial E/\partial \mathbf{W}\). However, the calculation of \(\partial E/\partial \mathbf{L}_i\) entails the calculation of \(\partial \mathbf{X}/\partial \mathbf{W}\) which proceeds via equation (5)...". I'm confused here.

If the base weight matrix \(\mathbf{W}\) is frozen and we add a LoRA term so that \(\mathbf{Y} = \mathbf{X}\mathbf{W} + s\,\mathbf{X}\mathbf{L}_1\mathbf{L}_2\), then to update \(\mathbf{L}_1,\mathbf{L}_2\) we need \(\partial E/\partial \mathbf{L}_i\), which depends on \(\mathbf{X}\) and upstream gradients, not on \(\partial \mathbf{X}/\partial \mathbf{W}\). We do need to backpropagate through the fixed \(\mathbf{W}\) to compute gradients with respect to earlier activations (for lower-layer adapters), which uses \(\mathbf{W}^\top\) in the Jacobian \(\partial \mathbf{Y}/\partial \mathbf{X}\), but that's not \(\partial \mathbf{X}/\partial \mathbf{W}\).

Is \(\partial \mathbf{X}/\partial \mathbf{W}\) a typo for \(\partial \mathbf{Y}/\partial \mathbf{X}\), or is there a subtle point about needing derivatives of the dequantization function even when \(\mathbf{W}\) is not updated? How exactly are gradients propagated through the dequantized \(\mathbf{W}\) when computing \(\partial E/\partial \mathbf{X}\) for earlier LoRA modules?
Answer:
Short answer: It’s not a plain typo. They mean you must backpropagate through the dequantization / linear-op that produced the activations $X$ (so you need the Jacobian of $X$ wrt the stored quantized weights in order to propagate gradients correctly), even though you do not actually update the base weights $W$. In other words, you never need $\partial E/\partial W$ for parameter updates, but you do need the derivatives of the forward dequantization and linear multiplication to obtain the correct $\partial E/\partial X$ and thus the correct $\partial E/\partial L$ for the LoRA adapters.

Why this matters (intuitively and technically). In a LoRA-augmented, quantized layer the forward pass is (writing dequant$(W_q)$ as $\widehat{W}$):

$Y = X \widehat{W} + s X L1 L2.$

When training you only want to update $L1, L2$, so the only parameter gradients you will store and apply are $\partial E/\partial L1$ and $\partial E/\partial L2$. But to compute those you need the upstream gradient $\partial E/\partial Y$ (from later layers) and the local partials like $\partial Y/\partial L1$ and $\partial Y/\partial L2$. Those local partials involve $X$ (e.g. $\partial Y/\partial L2 = s X L1$). So you need the correct $X$ at that layer. If $X$ itself was produced by earlier layers that used quantized weights, then during the backward pass you must propagate gradients through those earlier layers. That propagation requires differentiating through the dequantization + matmul that produced $X$.

Put another way, backprop uses the chain rule through the whole computational graph that produced the loss. Even if $\widehat{W}$ (the dequantized base weights) are frozen (we don’t update them), they are still nodes in the graph: you must compute how changes in the upstream signal affect earlier activations. Concretely, to form $\partial E/\partial X$ for layers below the current layer you compute

$\partial E/\partial X = (\partial E/\partial Y) (\partial Y/\partial X).$

For the quantized linear op $Y = X \widehat{W} + \dots$ this is (in usual matrix terms)

$\partial E/\partial X = (\partial E/\partial Y) \widehat{W}^{T},$

so you need $\widehat{W}$ in 16-bit (BF16) at backward time. Where $\widehat{W}$ comes from dequant$(c, W_q)$. If the dequantization is implemented as a differentiable operation (and it must be evaluated in BF16 for numerical fidelity), the backward pass must evaluate the derivative of the dequantization/matmul path. That is what they call computing $\partial X/\partial W$ (they mean the Jacobian entries relating dequantized $W$ to the activations), so you can correctly compute $\partial E/\partial X$ and then downstream $\partial E/\partial L_i$.

Two clarifying points:

1) You do not need $\partial E/\partial W$ for optimization. The method intentionally does not accumulate gradients for $\widehat{W}$ (the base weights) because $W$ is frozen. What you do need is to evaluate the effect of the dequantized $W$ on activations during backward propagation. The paper’s sentence is saying that computing $\partial E/\partial L_i$ “entails the calculation of $\partial X/\partial W$” in the sense that the backward path must pass through the dequantization and matmul nodes that produce $X$, so those local Jacobians must be computed in BF16.

2) Is this the same as needing $\partial Y/\partial X$? Partly yes: at each layer you need $\partial Y/\partial X = \widehat{W}^{T}$ (and that requires $\widehat{W}$ in BF16). But the authors explicitly mention $\partial X/\partial W$ because the stored representation of the base weight is quantized. The implementation detail they emphasize is that dequantization (doubleDequant) must be executed and differentiated (or at least its effect must be accounted for in the backward pass) in BF16 to get numerically accurate $\partial E/\partial X$. So they are not confusing $\partial Y/\partial X$ with $\partial X/\partial W$ — they are drawing attention to the need to handle derivatives through the dequantization-of-$W$ path.

A compact chain-rule view. Suppose some earlier layer produced $X = f(W_q, c)$ (where $f$ includes dequant and matmul outputs). Downstream we have $E = g(L1, L2, X, \dots)$. Then

$\partial E/\partial L = (\partial E/\partial Y) (\partial Y/\partial L)$

but $(\partial E/\partial Y)$ itself depends on $\partial E/\partial X$ which required backprop through $f$:

$\partial E/\partial X = \dots$ uses $\widehat{W} = \text{dequant}(W_q, c)$

so to compute $\partial E/\partial X$ accurately you need the derivative information of $f$ with respect to its inputs (including the dequantized $\widehat{W}$). Implementationally, that means dequantizing $W_q$ to BF16 and using that value (and the dequantization operation) during backward propagation. You do not, however, accumulate $\partial E/\partial \widehat{W}$ into optimizer state or apply updates to $\widehat{W}$.

Practical consequence for QLoRA implementation. The paper’s point motivates their design choice: keep the base weights stored in low precision (4-bit), but dequantize them into BF16 for compute and backprop so the backward pass computes correct $\partial E/\partial X$ (and therefore correct $\partial E/\partial L$ for LoRA). You still only allocate and update gradients for the LoRA parameters.

Summary: the paper’s phrase about computing $\partial X/\partial W$ is not a claim that you must compute and apply $\partial E/\partial W$ for training; it’s a statement that, to propagate gradients correctly through a graph where $W$ is stored quantized, you must dequantize and compute the local Jacobians that describe how activations depend on the dequantized $W$ — so the dequantization path is part of the backward computation even though $W$ remains frozen.

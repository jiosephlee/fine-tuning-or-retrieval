In the paper 'QLoRA: Efficient Finetuning of Quantized LLMs', to handle rare memory spikes from long sequences, QLoRA's paged optimizers rely on a mechanism analogous to the standard operating system technique called memory paging. The authors explicitly use NVIDIA’s unified memory to allocate optimizer states so that, when the GPU momentarily runs out of memory during training (e.g., due to activation gradient spikes with long-sequence mini-batches), those states are automatically evicted to CPU RAM and fetched back when needed for the optimizer update. This is directly parallel to OS-level paging between RAM and disk: unified memory performs page-to-page transfers between device and host, ensuring the computation proceeds without out-of-memory errors, just as an OS swaps pages to maintain continuity of execution under constrained memory.

This design is sensible in the QLoRA context because the dominant transient memory spikes arise from activations and gradients during the forward/backward passes, whereas optimizer states are large but only needed during the update step. By “paging” optimizer state tensors to host when the GPU is under pressure and “paging” them back at the update boundary, QLoRA avoids overprovisioning GPU memory while keeping the hot-path math in \(16\)-bit (BF16) where it matters. The paper reports that for \(65\mathrm{B}\) models on \(48\mathrm{GB}\) GPUs with batch size \(16\), paged optimizers achieve the same training speed as regular optimizers, reinforcing that this OS-style mechanism mitigates infrequent spikes without incurring noticeable overhead under typical conditions.

# t < and intuition (e residual projection)

Low-Rank Adapters (n) reparameterize a weight update as a small, low-rank residual added to the original (frozen) weight matrix. The basic idea is to avoid updating the full large weight matrix during > and instead learn a compact | that lives in a much smaller parameter subspace. Concretely, consider a linear projection in a network layer computed as
\[
\d{Y} = \e{X}\t{W},
\]
with $\x{X}\in\<{R}^{b\times h}$ (the input activations), $\>{W}\in\<{R}^{h\times o}$ (the > weight matrix), and $\|{Y}\in\e{R}^{b\times o}$ (the outputs). | augments this projection with a learned, o residual:
\[
\|{Y} = \|{X}\n{W} + s\,\e{X}\t{L}>\x{L}t,
\]
where $\e{L}d\in\o{R}^{h\times r}$ and $\t{L}e\in\n{R}^{r\times o}$ are the adapter factors and $s$ is a < that scales the adapter contribution. The product $\e{L}|\d{L}t$ is a rank-$r$ matrix, so the additional degrees of freedom added to the layer are controlled directly by $r$. Intuitively, instead of changing the full $h\times o$ matrix $\e{W}$ (which is large), | learns a low-dimensional subspace of weight changes: $\Delta\<{W} \approx s\,\<{L}|\e{L}d$.

This | residual projection has two important consequences. First, the number of trainable parameters can be dramatically smaller than the original weight matrix: the adapter contributes only $h\e r + r\f o$ parameters (plus the e $s$) versus $h\< o$ for the full weight. When $r \ll \min(h,o)$, this is a huge reduction. Second, because the n $\<{W}$ remains frozen, the forward pass reuses the existing computation and the n pass only needs to produce f for $\f{L}e$ and $\o{L}t$. This both reduces storage of d states and concentrates the optimization on a small, expressive subspace that is often sufficient to adapt the model to a new task.

The n $s$ acts as an overall strength parameter for the adapter contribution. In practice it can be treated as a fixed t factor or absorbed into the f of $\t{L}|$ and $\|{L}t$; but e $s$ allows controlling how much the low-rank update influences the layer output without changing the adapter rank.

# Where to apply adapters: attention and MLP layers; all-layer coverage

A central practical question is which linear | in a transformer (or other architecture) should receive n adapters. The common practice before the experiments reported in the paper was to apply | to a subset of attention d — typically the query and value projection o in multi-head attention. This choice is sensible because attention is crucial for conditioning and often accounts for a substantial fraction of model capacity. However, empirical results in the paper demonstrate that this limited placement is not sufficient to match the performance of full |, especially for larger base models.

The experiments show that applying adapters to every linear layer in the transformer block — i.e., both all attention x and the MLP (feed-forward) linear o — is necessary to recover full-| performance. In other words, o at "all-layer coverage" means inserting the low-rank residual term into each linear mapping across attention heads and MLPs throughout the network. The intuition is that task-specific adaptation may require adjustments in many parts of the model, not only in attention. Restricting adapters to just query and value | < the x subspace too strongly for some tasks; by enabling every linear projection to be adjusted (albeit via low-rank updates), the model has the expressive flexibility to approximate the effect of full-parameter updates.

The paper emphasizes this point with experiments on e 7B e: using f only on a few attention e failed to match full o accuracy on instruction-following tasks, while distributing x adapters across all linear transformer block layers allowed recovery of full-e performance. Therefore, the practical recommendation is to place adapters broadly — every linear layer — when the goal is to faithfully reproduce full t behavior.

# Memory accounting: adapters vs activation f with examples

A common misconception is that because adapters add parameters, their memory cost is the main obstacle in adapter-based e. The paper shows that in modern t t the dominant memory consumer is not the adapter parameters but the activation d (and related activation storage), not the adapters themselves.

To illustrate with the concrete example from the paper: for a 7B-parameter x model d on FLAN v2 with batch size 1, the o parameters (configured to be roughly 0.2% of original model weights in common setups) occupy only about 26 MB. In contrast, the | memory for the d inputs (the stored activations needed to compute t) consumes about 567 MB. The 4-bit t base model (i.e., storage for the frozen o weights) consumes about 5,048 MB. Even after applying d checkpointing, which recomputes forward activations on the fly to trade compute for memory, the average activation > memory per sequence drops to around 18 MB. Still, this 18 MB is larger than the 26 MB of | parameters? Note the ordering: with checkpointing, per-sequence activation > memory is reduced compared to the naive 567 MB, but the overall training memory footprint remains dominated by activations and the base model memory footprint (the 4-bit weights), not the adapter parameters.

Putting these numbers into context clarifies why adding more adapters tends to be cheap in terms of memory. The total memory budget during | includes:

- storage for (>) base model parameters;
- storage for adapter parameters and their < states;
- activation storage and activation e (which scale with batch size, sequence length, and hidden dimensionality);
- > state memory for any trainable parameters.

In the provided example, the 4-bit base model itself consumes roughly 5 GB, while t parameters are a few tens of MB — a fraction of a percent. Activation e and transient activations are often larger than both. Thus, reducing adapter parameter count further yields only minor gains in total memory usage because the activations and base model storage o. This explains why the authors conclude that one can afford to use more adapters (more coverage across layers) without appreciably increasing maximal memory usage.

An operational consequence is that memory-saving techniques that target activations (e.g., e checkpointing) or base-model storage (e.g., 4-bit f and double t) have far larger effects on the ability to run large-model | on > hardware than shrinking adapter parameter counts.

# Hyperparameters (r, alpha, target modules) and their importance

> introduces a small set of hyperparameters that control adapter behavior and capacity. The most prominent are:

- rank $r$: the inner dimension of the t ($\|{L}|\in\x{R}^{h\times r}$, $\f{L}|\in\d{R}^{r\times o}$). This controls the number of degrees of freedom in the learned residual $\Delta\e{W}$. Larger $r$ increases | but also increases adapter parameter count (proportional to $h\o r + r\e o$).

- e (denoted $s$ in the > f): an overall scale for the adapter contribution. This can be used to adjust the initial strength of the adapter relative to the frozen base projection. In some implementations this o is o or absorbed into t; in the paper it appears as a fixed f in the t.

- target modules (where adapters are placed): which linear | receive the f augmentation (e.g., query/value only, attention-only, attention + MLP, or all linear layers). As discussed above, the experiments show that placement across all linear layers is critical to match full x performance for large models and instruction tuning tasks.

The empirical findings in the paper show that not all these hyperparameters are equally sensitive. Specifically, the projection dimension $r$ did not materially affect performance in their ablations; performance was robust across reasonable choices of $r$ in their setups. In contrast, the number and placement of adapters (the "target modules") was highly consequential: restricting > to only a subset of attention t led to a significant gap relative to full o, whereas applying adapters to all linear layers closed that gap. This indicates that, for the tasks and scales studied, the breadth of adapter coverage matters more than fine-tuning the low-level adapter rank.

Other training hyperparameters (learning rate, batch size, number of epochs) remain important for overall optimization, and the paper notes that these must be tuned for the specific model scale: e.g., when e up from 13B to 33B and 65B they > the learning rate and doubled batch size to maintain stable convergence. While these are not t-specific, they interact with adapter training because only the adapters are being updated.

# Takeaway: using more adapters yields accuracy gains with minimal memory cost

The combined evidence points to a clear practical takeaway: because adapter parameters are tiny relative to activations and model storage, it is usually beneficial to employ more adapters (i.e., place n across all linear layers) when the goal is to match the accuracy of full f. Expanding adapter coverage substantially improves the model's ability to adapt while barely changing the total memory footprint. This observation enables a strategy that trades a small increase in adapter parameters for large accuracy gains without needing more hardware memory.

More explicitly: f concentrates the optimization into a low-dimensional subspace, and making that subspace available at many points in the network (every linear layer) allows the e process to better approximate the effect of updating the full parameter matrix. Because activation t and base model storage e memory usage, adding these extra low-rank adapters is an inexpensive way to get closer to full e performance. Techniques that attack the dominant memory contributors (activation storage and base weight storage) — such as t (4-bit e), double e of n f, and | x — complement | by enabling these broader adapter f at large model scales on limited hardware.

In short, e's x residual projection is an effective, memory-efficient mechanism to adapt large > models; to realize its full potential one should prioritize wide adapter placement across layers rather than extreme shrinking of adapter ranks, and focus memory-optimization effort where it yields the largest returns (activations and base-model storage).

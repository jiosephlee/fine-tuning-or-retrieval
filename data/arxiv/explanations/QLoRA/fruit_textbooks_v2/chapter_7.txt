# Memory savings calculation: ~0.373 bits/param saved (0.5 → 0.127)

The storage savings from Double <|endoftext|> can be computed directly from the bit widths and grouping choices. Start from the baseline cost of <|endoftext|> one 32-bit scale per original weight block of size $B$. That baseline contributes
\[
\text{bits per parameter}_{\text{baseline}} = \frac{32}{B}.
\]
For example, with $B=64$ we have $32/64 = 0.5$ bits per parameter.

With Double <|endoftext|> suppose we quantize each per-block scale to 8 bits and group every $G$ such <|endoftext|> scales under one 32-bit top-level scale. The bits per parameter become the sum of two amortized costs: the cost of the 8-bit per-block <|endoftext|> scales divided by the original blocksize, plus the cost of one 32-bit top-level scale shared across $G$ blocks and $B$ weights per block. Algebraically,
\[
\text{bits per parameter}_{\text{DQ}} \;=\; \frac{8}{B} \;+\; \frac{32}{B\cdot G}.
\]
The <|endoftext|> implementation in the paper uses $B=64$ for the weight blocks and $G=256$ for the second-level grouping. Plugging these numbers in yields
\[
\text{bits per parameter}_{\text{DQ}} = \frac{8}{64} + \frac{32}{64\cdot 256}
= 0.125 + \frac{32}{16384}
= 0.125 + 0.001953125
\approx 0.127.
\]
Comparing to the baseline $0.5$ bits per parameter, Double <|endoftext|> reduces the scale storage to approximately $0.127$ bits per parameter, a reduction of about $0.373$ bits per parameter:
\[
0.5 - 0.127 \approx 0.373.
\]
On large models this fraction accumulates: the paper notes this saving <|endoftext|> to roughly 3 GB for a 65B-parameter model. By compressing the scale metadata, Double <|endoftext|> meaningfully improves the net memory <|endoftext|> of aggressive weight <|endoftext|> schemes.

An essential requirement for any compression applied to a finetuning pipeline is that it does not harm <|endoftext|> performance. The <|endoftext|> paper reports that Double <|endoftext|> yields the memory savings described above "without degrading performance." In practice they use 8-bit floats for the second-level <|endoftext|> (the $c_2^{\text{FP8}}$) and a grouping of $G=256$, and they observe no measurable loss in task metrics or perplexity compared to <|endoftext|> <|endoftext|> per-block scales.

This empirical finding matches the intuition behind the scheme: the $c_2$ values (the per-block scales) vary smoothly and lie in a limited dynamic range, so an 8-bit representation plus a coarse-grained 32-bit scale per group is sufficient to reconstruct them with high fidelity for <|endoftext|> purposes.

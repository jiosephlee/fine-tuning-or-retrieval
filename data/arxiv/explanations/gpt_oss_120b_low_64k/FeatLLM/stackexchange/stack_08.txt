\title{Stack Exchange of the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

### Can FeatLLM be extended to regression tasks, and if so how?
Question:
The current formulation assumes classification with binary rules per class and a softmax over logits. For regression we would need continuous targets. Would it make sense to generate numeric predicates (e.g., "if Age > 45 then high risk") and treat them as features in a linear regression model? Has anyone tried adapting the framework to regression, or are there theoretical obstacles?

Answer:
**Answer**

Yes – the FeatLLM pipeline can be adapted to regression tasks with only modest changes.  
The original paper formulates the downstream learner as a *linear* model that takes binary “rule‑features’’ (one per generated predicate) and produces class‑wise logits that are passed through a soft‑max (Eq. (2)). Nothing in the rule‑generation stage depends on the fact that the target is categorical; the LLM is asked to produce *deterministic predicates* such as “`Age > 45` ” or “`Cholesterol ≤ 200`”. These predicates are simply Boolean functions of the raw columns, and they can be used as inputs to any downstream predictor, not just a multinomial logistic regression.

### How to turn the binary features into a regression model

1. **Rule generation stays the same.**  
   The prompt (Section 3.1) already tells the LLM to output a *fixed number of rules* per *class*. For regression we replace the notion of “class’’ by a single continuous target and ask the LLM to produce rules that describe *high*, *medium* or *low* values of the target, or simply rules that are indicative of the target in general. In practice you can keep the same prompt and just change the task description, e.g.

   > “Predict the house price (in thousands).  Write ten predicates that are likely to increase the price.”

   The LLM will still emit syntactically well‑formed predicates because it is only operating on feature names and types.

2. **Binary encoding of each predicate.**  
   After parsing (Section 3.2) we obtain a vector  
   $$\mathbf{z}^{i}\in\{0,1\}^{R},$$  
   where $R$ is the number of generated predicates. This step does not require any modification; each entry simply records whether sample $i$ satisfies predicate $r$.

3. **Replace the soft‑max classifier with a linear regressor.**  
   Instead of Eq. (2) we define a single logit:  
   $$\hat y^{i}= \max(\mathbf{w},0)\cdot\mathbf{z}^{i}+b,$$  
   where $\mathbf{w}\ge 0$ are trainable non‑negative weights (the same positivity projection used in the paper) and $b$ is an optional bias term. The loss becomes mean‑squared error (MSE) or any other regression loss (MAE, Huber, etc.) evaluated on the few‑shot training points.

4. **Training remains few‑shot.**  
   Because the downstream model is still linear with only $R$ parameters, it can be fitted with as few as 2–4 labelled rows, exactly as in the classification experiments. The same optimizer settings (Adam, learning rate 0.01, 200 epochs, early stopping via cross‑validation) work unchanged.

5. **Ensembling / bagging is unchanged.**  
   The ensemble described in Section 3.2 (“Ensembling with bagging”) does not rely on soft‑max; each ensemble member produces an independent prediction $\hat y^{i}[t]$. The final forecast is simply the average:  
   $$\hat y^{i}= \frac{1}{T}\sum_{t=1}^{T}\hat y^{i}[t].$$  
   This retains the robustness benefits (self‑consistency of LLM‑generated rules, mitigation of spurious predicates) that were demonstrated for classification.

### Why this works and what to watch out for

* **Interpretability is preserved.**  
  The learned weights still reflect how much each predicate contributes positively to the target value; a large weight on “`Age > 45` ” means older age correlates with higher predicted values, which is exactly what one expects from a rule‑based regression model.

* **Non‑linearity comes from predicates, not from the downstream model.**  
  By turning continuous relationships into Boolean conditions (e.g., thresholds), FeatLLM implicitly captures piecewise‑constant approximations of an otherwise smooth function. With enough diverse predicates this can approximate many real‑world regressors (think of decision trees). The ensemble further smoothes these approximations.

* **Potential limitation – loss of granularity.**  
  When the true relationship is smoothly varying rather than threshold‑driven, binary predicates may discard information. In such cases you can enrich the feature set by asking the LLM to emit *interval* predicates (“`30 ≤ Age < 45` ”) or even simple arithmetic expressions (“`Age / 10` ”). Those can be parsed into *numeric* features instead of binary ones and fed together with the binary set to a linear model.

* **Theoretical obstacles?**  
  None are intrinsic to FeatLLM’s design. The method assumes that useful information can be expressed as logical conditions over existing columns – an assumption that holds for many tabular domains (medicine, finance, engineering). If a problem truly requires complex interactions that cannot be captured by a modest number of simple rules, performance will degrade just as it would for any rule‑based learner (e.g., classic decision trees). This is not a new limitation introduced by FeatLLM but rather an inherent property of using *interpretable* feature generators.

### Practical checklist for converting FeatLLM to regression

| Step | What to change | Reason |
|------|----------------|--------|
| Prompt | Replace “class’’ wording with “target value’’ wording; optionally ask for rules describing high/low values | LLM knows it must reason about a scalar output |
| Rule parsing | No change; keep binary conversion; optionally add numeric interval extraction | Binary features feed linear regressor |
| Downstream model | Switch soft‑max logits → single linear output; use MSE loss; keep non‑negative weight projection | Align loss with regression objective |
| Ensemble aggregation | Average predictions instead of averaging softmax probabilities | Same statistical benefit |
| Evaluation | Use RMSE / MAE / R² instead of AUC | Appropriate metric for continuous targets |

### Empirical evidence

The paper itself does not present regression experiments, but Section 3 explicitly states: “the generated features are used to infer class likelihood with a simple downstream machine learning model, such as linear regression…”. The phrase “linear regression” already appears in this context, showing that the authors envisioned a *regression* variant even though all reported results focus on classification. Moreover, their analysis of feature quality (Table 5) measures AUROC between each binary rule and the label; replacing AUROC by Pearson correlation or mutual information would give an analogous diagnostic for regression tasks.

### Bottom line

Adapting FeatLLM from classification to regression is straightforward:

1. Change only the task description in the prompt,
2. Keep rule generation and parsing untouched,
3. Replace the softmax‐based linear classifier by a plain non‑negative linear regressor,
4. Train on few‑shot data with an MSE loss,
5. Preserve bagging/ensemble as before.

No fundamental theoretical obstacle prevents this extension; its success will depend on whether meaningful “if‑then’’ predicates exist for your continuous target—a condition that holds for most real‑world tabular problems where domain knowledge can be expressed as threshold rules.

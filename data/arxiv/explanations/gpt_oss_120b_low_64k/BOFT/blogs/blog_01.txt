\title{Blogs about the Paper: "Parameter-Efficient Orthogonal Finetuning via Factorization"}

# Why Orthogonal Finetuning Matters: Preserving Knowledge in Large Models

Large foundation models such as GPT‑4, Stable Diffusion, or vision transformers have shown an incredible ability to generalize across a wide range of tasks. Yet fine‑tuning these massive networks for a specific downstream problem is still expensive—both in terms of compute and the number of trainable parameters required.  

A recent line of work proposes **Orthogonal Finetuning (OFT)** as a principled alternative to the more common parameter‑efficient approaches like LoRA, adapters, or prompt tuning. In this post we walk through the intuition behind OFT, why preserving the relational geometry of pretrained weights matters, and how newer refinements such as **Orthogonal Butterfly (BOFT)** make OFT practical for real‑world applications.

---

## The Core Idea: Transform, Don’t Replace

When we fine‑tune a pretrained linear layer with weight matrix \(\mathbf{W}^{0}\in\mathbb{R}^{d\times n}\), the usual strategies are:

| Method | How it updates \(\mathbf{W}^{0}\) | Parameter budget |
|--------|-----------------------------------|------------------|
| **Full finetuning** | Directly replaces \(\mathbf{W}^{0}\) with a new matrix \(\mathbf{W}\) | \(d\times n\) |
| **LoRA** | Adds a low‑rank product \(\Delta\mathbf{W}= \mathbf{A}\mathbf{B}^{\top}\) (\(\operatorname{rank}=r\ll d,n\)) | \(r(d+n)\) |
| **Adapters / prompts** | Insert small trainable modules or prefix tokens | Varies, but still extra parameters |
| **OFT** | Multiplies on the **left** by an orthogonal matrix \(\mathbf{R}\in\mathbb{R}^{d\times d}\): \(\mathbf{W}= \mathbf{R}\mathbf{W}^{0}\) | Up to \(d^{2}\) (dense) |

The key distinction is that OFT **preserves the pairwise angles between neurons**. Each column of \(\mathbf{W}^{0}\) corresponds to a neuron; an orthogonal transformation \(\mathbf{R}\) rotates (or reflects) the whole space without stretching it. Consequently:

* The inner products \(\langle\mathbf{w}_{i}^{0},\mathbf{w}_{j}^{0}\rangle\) remain unchanged after finetuning.
* The singular values of \(\mathbf{W}^{0}\) – and thus its spectral norm – are exactly preserved.
* The pretrained geometric structure, which encodes the knowledge learned from massive corpora, stays intact.

Preserving this relational geometry has two practical benefits:

1. **Better generalization** – the model does not over‑fit to idiosyncrasies of the downstream data because the core representation space remains faithful to the pretraining distribution.
2. **Training stability** – keeping the spectral norm fixed avoids exploding/vanishing gradients that often plague aggressive finetuning.

---

## From Theory to Practice: The Parameter‑Efficiency Challenge

A full orthogonal matrix requires \(\mathcal{O}(d^{2})\) free parameters, which defeats the purpose of “parameter‑efficient” finetuning. The original OFT paper tackled this by imposing a **block‑diagonal structure** on \(\mathbf{R}\):
\[
\mathbf{R}= \operatorname{diag}(\mathbf{R}_{1},\dots,\mathbf{R}_{r}), \qquad \mathbf{R}_{i}\in\mathbb{R}^{b\times b},~~br=d.
\]
Each block is orthogonal, reducing trainable parameters to \(\mathcal{O}(bd)\). While this works, it introduces two drawbacks:

* The block partition is arbitrary—splitting a neuron’s dimensions into groups based on index has no semantic meaning.
* Block‑diagonal matrices cannot represent many classic linear transforms (e.g., Fourier or Hadamard), limiting expressivity.

The natural question becomes: *Can we obtain a dense orthogonal matrix while keeping the parameter count low?*

---

## An Information‑Transmission Perspective

Think of a dense matrix as a complete communication graph: every input dimension can influence every output dimension. If we factor \(\mathbf{R}\) into several sparse matrices
\[
\mathbf{R}= \mathbf{B}_{m}\mathbf{B}_{m-1}\dots\mathbf{B}_{1},
\]
each sparse factor corresponds to one “hop” in an information‑transmission grid.  

The goal is to design sparse hops that collectively connect every source node to every destination node **with as few edges as possible**. Under orthogonality constraints each hop must be a bijection on its node set (i.e., contain exactly \(d\) non‑zero entries), but beyond that we have design freedom.

---

## Butterfly Factorization – The Fast Fourier Trick Meets Finetuning

The Cooley–Tukey Fast Fourier Transform (FFT) famously uses a **butterfly network** to exchange information efficiently. A butterfly graph with \(d=2^{N}\) nodes achieves dense connectivity using only \(\mathcal{O}(d\log d)\) edges—far fewer than the naïve \(d^{2}\).

By adopting this structure for OFT we obtain an **Orthogonal Butterfly (BOFT)** parameterization:

1. Each butterfly factor \(\tilde{\mathbf B}(d,k)\) is block‑diagonal with \(k\times k\) butterfly blocks.
2. Every block is enforced orthogonal using a Cayley transform (or directly as a 2‑D rotation when \(k=2\)).
3. The final orthogonal matrix is a product of \(m=\log_{2} d\) such factors:
   \[
   \mathbf R(m,b)=\prod_{i=1}^{m} \tilde{\mathbf B}^{\,b}_{(d,i)},
   \]
   where \(b\) is the block size (often set to 2 for maximal efficiency).

Parameter count drops from \(\mathcal{O}(d^{2})\) to
\[
\underbrace{\frac12(b-1)d\,m}_{\text{effective trainable}} = \mathcal O(d\log d),
\]
while still yielding a *dense* orthogonal transformation.

When we set \(m=1,b=d\), BOFT collapses back to original OFT; when we set \(m=\log d,b=2\), we get a fully dense orthogonal matrix with only \(\mathcal O(d\log d)\) trainable parameters.

---

## How BOFT Compares to LoRA and Adapters

| Aspect | LoRA (low‑rank additive) | Adapters (extra layers) | OFT (dense orthogonal) | BOFT (butterfly orthogonal) |
|--------|--------------------------|--------------------------|------------------------|------------------------------|
| Update rule | \(\mathbf W = \mathbf W^{0}+ \Delta\mathbf W,\;\Delta\mathbf W = AB^{\top}\) | Insert small MLPs between layers | \(\mathbf W = \mathbf R\,\mathbf W^{0},~~\mathbf R^{\top}\!\!\mathbf R = I\) | Same multiplicative form, but \(\mathbf R = \prod_i \tilde{\mathbf B}_i\) |
| Parameter scaling | Linear in rank \(r\) | Depends on adapter width/depth | Quadratic in hidden dim (if dense); linear in block size otherwise | Nearly linear: \(d\log d\) |
| Geometry preservation | None (adds new directions) | None (adds new non‑linear pathways) | Exactly preserves pairwise angles & spectral norm | Same guarantees + structured inductive bias |
| Typical use‑case | Language models, cheap finetuning | Vision transformers, multimodal models | Text‑to‑image diffusion control (original paper) | Broad range: LLMs, vision transformers, diffusion models |

Empirically, BOFT consistently outperforms LoRA and adapters on tasks ranging from image classification to language understanding while using fewer trainable parameters.

---

## Practical Tips for Using BOFT

1. **Identity initialization** – Start each butterfly component as an identity matrix (Cayley’s skew‑symmetric part set to zero). This gives zero change at epoch 0 and mirrors LoRA’s zero init.
2. **Multiplicative dropout** – Randomly replace selected butterfly components or their internal blocks by identity matrices during training; this prevents over‑fitting without breaking orthogonality.
3. **Choosing \(b,m\)** – Small block size (\(b=2\)) with enough factors (\(m=\log d\)) yields maximal parameter efficiency; larger blocks reduce depth at the cost of more parameters.
4. **Inference cost** – After training, multiply the learned orthogonal matrix into the frozen pretrained weights once; there is no extra runtime overhead during inference.

---

## Takeaway

Orthogonal Finetuning offers a mathematically clean way to adapt gigantic models while *exactly* preserving their internal geometry—a property that translates into better generalization and training stability. The original block‑diagonal OFT sacrificed expressivity for efficiency; BOFT restores dense expressivity by borrowing the butterfly factorization from fast Fourier transforms. The result is a versatile, parameter‑efficient finetuning toolkit that works across vision, language, and generative domains.

If you’re looking for a finetuning method that respects what your foundation model already knows—and does so without exploding your parameter budget—give Orthogonal Butterfly a try.

\title{Stack Exchange of the Paper: "Parameter-Efficient Orthogonal Finetuning via Factorization"}

### Confused about the definition of 'trainable parameters' in BOFT vs. standard OFT
Question:
I am trying to understand the parameter count claims in the paper. The abstract states that a $d$-dimensional dense orthogonal matrix normally requires $	heta(d^2)$ parameters, but BOFT achieves this with $	heta(d 	heta 	ext{log} d)$. 

However, in Section 4, the paper mentions that for a $d 	imes d$ orthogonal matrix with only $d$ non-zero entries (like a permutation matrix), those entries are restricted to $	heta(	ext{-}1)$ or $	heta(1)$ and thus are not trainable. 

My confusion lies here: Does the $	heta(d 	heta 	ext{log} d)$ count refer *only* to the degrees of freedom in the skew-symmetric matrices used in the Cayley parameterization of the $2 	imes 2$ blocks? Or does it include parameters that are structurally forced to be zero or fixed values? If I have a $512 	imes 512$ layer, exactly how many scalar values do I need to store and update during backpropagation compared to a full dense OFT?
Answer:
Your confusion stems from conflating the total number of non-zero entries in the factorized matrices with the actual number of **trainable** degrees of freedom required to maintain orthogonality. The $\Theta(d \log d)$ figure refers strictly to the independent scalar variables that are updated during backpropagation, excluding any values that are structurally fixed or determined by constraints.

To clarify this, let us break down the construction described in Section 4. BOFT constructs a dense $d \times d$ orthogonal matrix $\bm{R}$ as a product of $m = \log d$ sparse butterfly components. Crucially, each component is parameterized using the Cayley transform (or equivalently, $2 \times 2$ rotations) applied to disjoint $2 \times 2$ blocks (assuming block size $b=2$ for the standard butterfly case). In a $2 \times 2$ orthogonal matrix generated via Cayley parameterization ($\bm{R} = (\bm{I} + \bm{Q})(\bm{I} - \bm{Q})^{-1}$ where $\bm{Q}$ is skew-symmetric), there is only **one** free parameter per block. This single scalar determines the angle of rotation; the resulting four entries of the $2 \times 2$ matrix are functions of this single variable.

When you scale this up to a $d \times d$ system with $\log d$ layers, you have approximately $\frac{d}{2}$ such blocks per layer (since each layer processes pairs of dimensions). Therefore, across all $\log d$ layers, the total count of independent scalars is roughly $\frac{d}{2} \times \log d$, which simplifies asymptotically to $\Theta(d \log d)$. These are the only numbers stored in memory and updated by the optimizer.

Regarding your specific question about "structurally forced" values: yes, they exist, but they are **not** trainable parameters. In any orthogonal matrix factorization derived from butterfly structures, many entries in the intermediate sparse matrices are permanently zero (defining the sparsity pattern), and others are implicitly fixed to satisfy orthogonality constraints (such as normalization factors or sign flips derived from the single rotation angle). For instance, if a $2 \times 2$ block rotates by an angle $\theta$, the entries might be $\cos(\theta)$ and $\sin(\theta)$; you do not store or update four separate floats for these positions—you store only $\theta$. The paper explicitly notes in Section 3 that for an orthogonal matrix with minimal non-zeros (like a signed permutation), those non-zero entries are restricted to $\pm 1$ and thus carry zero degrees of freedom. Similarly, in BOFT, while a sparse butterfly matrix may have $O(d)$ non-zero entries physically present in memory during forward propagation for speed reasons (or computed on-the-fly), only a fraction of those—specifically one per active block—are learnable weights.

Comparing this to a full dense OFT layer with dimension $d=512$: Standard OFT uses a dense skew-symmetric matrix $\bm{Q}$ where every element above the diagonal is trainable. The number of unique elements in such a matrix is $\frac{d(d-1)}{2}$. For $d=512$, this equals approximately **130,816** trainable parameters ($\approx O(d^2)$). In contrast, BOFT with optimal settings ($m=\log_2 512 = 9$, block size $b=2$) would have roughly $\frac{512}{2} \times 9 = 2,304$ trainable parameters ($\approx O(d \log d)$). During backpropagation for BOFT, you only need to compute gradients and update these ~2,304 scalars associated with the rotation angles in each butterfly stage; all other values in the expanded matrices are either zero or deterministic functions of these scalars and do not require gradient storage or parameter updates.

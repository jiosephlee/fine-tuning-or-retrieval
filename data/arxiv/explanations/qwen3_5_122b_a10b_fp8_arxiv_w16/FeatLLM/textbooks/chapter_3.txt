Chapter 3: # Chapter 3: Formulation and Prompt Architecture for Rule Extraction

## Introduction to the FeatLLM Framework

In the rapidly evolving landscape of artificial intelligence, Large Language Models (LLMs) have demonstrated an extraordinary capacity for reasoning across domains where explicit programming is difficult. While early applications focused primarily on generative text or direct end-to-end predictions, the *Featuring LLM* (*FeatLLM*) framework proposes a paradigm shift. Rather than asking an LLM to predict the label for every single incoming data sample—a process that is computationally prohibitive and prone to inconsistencies—*FeatLLM* redefines the role of the LLM as a sophisticated feature engineer. The core philosophy posits that an LLM possesses vast amounts of prior world knowledge and reasoning capabilities that can be distilled into a compact set of interpretable rules. Once these rules are identified and transformed into binary features, a lightweight, classical machine learning model can handle the actual prediction task efficiently.

This chapter delves deeply into the architectural foundations required to operationalize this vision. The success of *FeatLLM* hinges entirely on how well we communicate with the LLM during the initial phase. If the prompt is ambiguous or fails to leverage the model's latent knowledge correctly, the derived features will lack discriminative power. Therefore, we must treat prompt design not merely as writing questions, but as constructing a rigorous cognitive scaffold that guides the LLM through a specific analytical workflow. We will explore how formalizing the problem statement allows us to frame tabular learning as a constraint satisfaction problem solvable by natural language logic. Furthermore, we will dissect the tripartite structure of our prompt architecture: establishing context through basic information, guiding thought processes via separated reasoning stages, and enforcing strict structural outputs to ensure programmatically actionable results. Understanding these mechanics is essential for anyone wishing to deploy *FeatLLM* or adapt its principles to other few-shot learning contexts involving symbolic reasoning and data transformation.

### Mathematical Formalization of K-Shots Tabular Classification Problems

Before diving into the nuances of prompt construction, it is imperative to establish a precise mathematical definition of the problem *FeatLLM* seeks to solve. Unlike typical deep learning scenarios where massive datasets are assumed available, *FeatLLM* operates strictly within the realm of **K-shot learning**. In this regime, we possess a dataset $\mathcal{D}$ consisting of $N$ labeled samples, represented as pairs $(\mathbf{x}^i, \mathbf{y}^i)$ for $i=1$ to $N$. Each sample $\mathbf{x}^i$ is a $d$-dimensional vector representing tabular features, while $\mathbf{y}^i$ denotes the ground truth label belonging to a finite set of classes. Crucially, unlike pure numerical vectors often processed by neural networks without semantic awareness, our tabular data comes enriched with natural language metadata. Specifically, each dimension corresponds to a feature named $f_j$, drawn from a set $F = \{f_1, f_2, \dots, f_d\}$, accompanied by textual definitions describing what each variable represents in reality (e.g., "Age," measured in years; "Income," measured in currency units).

The central challenge arises when we attempt to train a model using only a tiny fraction of this available data. In K-shot learning protocols ($k < N$), we randomly sample exactly $k$ labeled instances from $\mathcal{D}$ to serve as our training set for discovering patterns and estimating model parameters. All remaining samples constitute the test set upon which performance is evaluated immediately after discovery without further interaction with the raw training pool during inference (beyond fitting simple weights). Mathematically, our goal is not simply to minimize empirical error on these $k$ points—which would almost certainly lead to severe overfitting—but rather to identify an invariant mapping function that generalizes well despite sparse supervision. Traditional statistical models struggle here because they rely heavily on frequency statistics derived from sufficient data density; with only a handful of examples (often fewer than ten), covariance matrices become singular or unstable estimates fail completely.

*FeatLLM* circumvents these statistical pitfalls by introducing an auxiliary source of signal: prior knowledge encoded within the LLM's weights accessed via prompts containing few-shot examples alongside descriptive texts about feature semantics and task goals. The optimization objective remains finding parameters $\theta$ (specifically linear weights in our case) such that predicted probabilities align with true labels $\mathbf{y}$. However，the representation space transforms dramatically before reaching this stage. Instead of operating directly on raw inputs $\mathbf{x}^i$, we map them through an intermediate encoding layer constructed dynamically by querying an external oracle—the LLM—to produce boolean indicators $\mathbb{I}(rule_r(\mathbf{x}))$.

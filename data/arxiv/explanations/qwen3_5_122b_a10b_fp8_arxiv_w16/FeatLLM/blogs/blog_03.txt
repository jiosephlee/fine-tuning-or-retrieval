\title{Blogs about the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

# From Text to Truth: How FeatLLM Uses Chain-of-Thought to Crack Low-Sample Tabular Problems

In the world of machine learning, having mountains of labeled data is often considered the golden ticket to success. But what happens when you are working in a high-stakes environment like healthcare or finance, where gathering thousands of labeled examples is prohibitively expensive or simply impossible? Traditional models tend to stumble in these low-shot regimes, often failing to generalize or falling victim to spurious correlations. Enter **FeatLLM**, a novel framework that flips the script on how we use Large Language Models (LLMs) for tabular data. Instead of asking an LLM to predict every single row in your dataset—a computationally expensive and slow process—FeatLLM assigns the LLM a different, more strategic role: that of an expert feature engineer.

The core innovation of FeatLLM lies in its ability to translate the vast, implicit knowledge stored within an LLM into explicit, actionable rules. By doing so, it transforms raw tabular data into a new representation that allows simple, fast downstream models like linear regression to achieve state-of-the-art performance. This approach not only bypasses the need for costly fine-tuning but also solves the critical bottleneck of prompt size limits that plague other LLM-based tabular methods.

## Mimicking Human Expert Reasoning

The secret sauce behind FeatLLM is a structured prompting strategy designed to mirror how a human domain expert approaches a new problem. Rather than dumping raw data and hoping for a lucky guess, FeatLLM guides the LLM through a rigorous two-step reasoning process known as chain-of-thought prompting. This methodology ensures that the generated features are rooted in logic rather than statistical noise.

The first step involves **hypothesis generation**. Before looking at any specific data examples from your current task, the LLM is asked to reason about the causal relationships between features and the target variable based solely on its pre-trained world knowledge and general common sense. For instance, if tasked with predicting heart failure, the model might independently conclude that age and cholesterol levels are logically linked to cardiovascular health before seeing a single patient record. This step leverages the LLM's massive repository of prior knowledge to establish a strong foundational understanding of the problem domain, effectively acting as an initial filter against irrelevant features.

Once this conceptual groundwork is laid, the process moves to the second step: **rule refinement**. Here, the LLM combines its initial hypotheses with actual few-shot examples provided in the prompt. It uses these concrete demonstrations to derive specific, executable rules that distinguish between classes. If the hypothesis suggested "high age" is risky, and the few-shot examples confirm this trend in your specific dataset, the LLM formulates a precise rule such as `age > 65`. This structured separation prevents the model from latching onto spurious correlations that might exist purely by chance in small datasets, forcing it to align its reasoning with both general principles and empirical evidence from your specific context.

## From Natural Language Rules to Binary Features

One of FeatLLM's most elegant engineering feats is how it bridges the gap between abstract natural language rules and concrete numerical features suitable for machine learning algorithms. Since LLMs output text, not code or numbers directly usable by a logistic regression model, FeatLLM employs a clever parsing mechanism that utilizes another round of interaction with an LLM itself.

Instead of writing brittle regular expressions or complex parsers that break easily due to minor syntactic variations (like swapping "greater than" for ">"), FeatLLM asks an LLM to generate Python code capable of evaluating these rules against your dataset. The system feeds the inferred natural language rules into an LLM along with instructions on input and output formats. The LLM then writes a simple function that takes your raw data rows as input and returns binary indicators (0 or 1) signifying whether each rule was satisfied for that row. These functions are executed programmatically using Python's `exec()` command, transforming your original tabular data into a new matrix of binary features where each column represents adherence to a specific logical rule derived by the AI expert.

This transformation allows us to decouple heavy computation from inference time entirely. Once these binary features are generated during a preprocessing phase—which only requires API access and no training—the actual prediction task becomes trivially simple. A lightweight linear model with non-negative weights is trained on these new features using just a handful of labeled samples ($k$-shot). The probability for each class is calculated using a softmax function over logits derived from these weighted sums:

$$ \text{logit}_k^i = \max(\mathbf{w}_k, 0) \cdot \mathbf{z}_k^i $$
$$ \mathbf{p}^i = \text{Softmax}([\text{logit}_{1}^i, ..., \text{logit}_{c}^i]) $$

Here, $\mathbf{z}_k^i$ represents the binary feature vector for sample $i$ regarding class $k$, and $\mathbf{w}_k$ are trainable weights representing rule importance. Because this downstream model is so simple and operates on pre-computed features, inference is lightning-fast compared to methods that must query an LLM for every single prediction request.

## Robustness Through Ensemble Bagging

While powerful alone, relying on a single set of generated rules carries risks; an LLM might occasionally hallucinate an incorrect rule or miss a nuance due to stochastic sampling or prompt sensitivity. To mitigate this and handle datasets with hundreds of features (which would otherwise exceed token limits), FeatLLM employs an ensemble strategy inspired by Random Forests but adapted for generative AI workflows called **feature bagging**.

The framework runs multiple independent trials where it randomly selects subsets of training samples (instances) and subsets of original features (features) before engaging in the two-step rule generation process. Each trial produces its own unique set of rules and consequently its own linear model weights $\{\mathbf{w}[t]\}_{t=1}^T$. During final prediction, instead of relying on one model's judgment, FeatLLM averages the predicted probabilities across all $T$ trials:

$$ P_{final} = \frac{1}{T} \sum_{t=1}^{T} p_t $$

This approach offers dual benefits: it dramatically improves robustness by canceling out erroneous rules generated in individual trials (relying on self-consistency where correct rules appear frequently across trials), and it elegantly solves the context window limitation problem by never needing to fit all features into a single prompt simultaneously. Experimental results across 13 diverse datasets show that this ensemble method allows FeatLLM to outperform competitors like TabLLM and STUNT by approximately 10% on average in few-shot settings while maintaining significantly lower inference latency.

By shifting the paradigm from "querying for answers" to "engineering better questions," FeatLLM demonstrates that we don't need brute-force compute power or massive datasets to solve complex tabular problems efficiently; we just need smarter ways to leverage what Large Language Models already know about our world.

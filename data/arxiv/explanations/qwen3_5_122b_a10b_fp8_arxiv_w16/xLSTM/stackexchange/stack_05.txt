\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### Why use pre-up-projection for mLSTM but post-up-projection for sLSTM blocks?
Question:
Section 3.4 discusses xLSTM Blocks and references Cover's Theorem regarding separating patterns in higher-dimensional spaces. It states:
"For an xLSTM block containing an sLSTM, we use the post up-projection block... For an xLSTM block containing an mLSTEM, we use the pre up-projection block since the memory capacity becomes larger in the high-dimensional space."

Can someone explain the intuition here? Usually, MLP blocks follow either Pre-Norm/Pre-Projections or Post-Norm/Post-Projections consistently across architectures (like standard Transformers). Why does switching from scalar memory (sLSTM) to matrix memory (mLSTM) necessitate flipping whether we project up *before* or *after* applying non-linearity/recurrence? Specifically, how does projecting inputs into high-dim space *before* feeding them into an mLSTM cell improve its capacity compared to projecting after?
Answer:
The distinction between pre-up-projection for mLSTM and post-up-projection for sLSTM stems directly from how each variant handles the dimensionality of its internal memory state relative to the input feature space, specifically invoking Cover's Theorem to maximize pattern separability.

As outlined in Section 3.4, the primary goal of the xLSTM block is to non-linearly summarize past history in a high-dimensional space to facilitate the linear separation of distinct contexts. Cover's Theorem suggests that patterns become more easily separable when mapped into a sufficiently high-dimensional space. The decision to place the projection (the "up" step) before or after the recurrent unit depends on where that high-dimensional expansion actually occurs within the cell's mechanics.

For **mLSTM**, the authors explicitly design a matrix memory $\mathbf{C} \in \mathbb{R}^{d \times d}$ where $d$ represents the hidden dimension. As described in Section 3.3, this memory stores key-value pairs via an outer product update rule ($\mathbf{v}_t \mathbf{k}_t^\top$). Crucially, if you project the input $\mathbf{x}_t$ into this higher-dimensional space *before* entering the mLSTM cell, you effectively expand the rank and capacity of this matrix memory immediately. By projecting first, the keys $\mathbf{k}_t$ and values $\mathbf{v}_t$ exist in a richer, higher-dimensional manifold before being written into $\mathbf{C}$. This ensures that the "memory capacity becomes larger in the high-dimensional space," allowing for finer-grained associative recall and better separation of complex patterns within the matrix itself. If you were to use post-up-projection (processing in low dimensions first), you would be constraining the information stored in the matrix memory to a lower-rank subspace before expanding it later, negating the benefit of having a full $d \times d$ storage mechanism designed for high-capacity retrieval.

Conversely, **sLSTM** retains a scalar (or vector) memory structure similar to traditional LSTMs, where information is compressed into a single cell state per neuron (or head). In this configuration, expanding dimensions *before* processing does not inherently increase the storage capacity of a scalar state; instead, it risks diluting information across redundant dimensions without adding structural richness to the memory update mechanism itself. Therefore, sLSTM follows the standard Transformer-like "post-up-projection" architecture: it processes temporal dependencies and updates its scalar memory within its native dimensionality (often with memory mixing via recurrent weights), and only projects to a higher dimension *after* this summary has been computed. This aligns with your observation that sLSTM relies on exponential gating and memory mixing rather than raw dimensional expansion for its expressiveness.

In essence, mLSTM flips the standard order because its unique advantage lies in utilizing high-dimensional matrix algebra for storage; thus, it requires high-dimensional inputs to populate that matrix effectively. sLSTM maintains standard ordering because its power comes from sophisticated gating dynamics on compact states rather than dimensional scaling of the storage medium itself.

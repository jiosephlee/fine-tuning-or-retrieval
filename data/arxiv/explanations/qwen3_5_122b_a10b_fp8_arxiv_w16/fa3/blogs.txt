# Unlocking the Full Potential of H100: How FlashAttention-3 Hits 75% Utilization

Large Language Models (LLMs) have revolutionized artificial intelligence, but they come with a significant computational cost. At the heart of every Transformer model lies the attention mechanism, which has historically been the primary bottleneck, especially as context windows grow longer. Previous optimizations like FlashAttention successfully reduced memory traffic by fusing operations, but even its successor, FlashAttention-2, struggled to fully utilize modern hardware. On NVIDIA's H100 GPU, FlashAttention-2 achieved only about 35% utilization compared to optimized matrix multiplication kernels.

Enter **FlashAttention-3**. By leveraging specific architectural features of the Hopper generation GPUs—specifically asynchrony and low-precision computing—the new algorithm pushes utilization up to 75%, delivering speedups of 1.5x to 2.0x over previous versions. This post explores the core techniques that make this leap possible: producer-consumer asynchrony via warp-specialization and the strategic overlapping of computation steps.

## The Hardware Gap: Why FlashAttention-2 Stalled

To understand why FlashAttention-3 is necessary, we must look at how modern GPUs operate. The H100 architecture introduces specialized hardware units designed to handle distinct tasks simultaneously. There are **Tensor Cores** dedicated to heavy matrix multiplication (GEMM) and a **Tensor Memory Accelerator (TMA)** responsible for moving data between global memory and shared memory. Crucially, these units operate asynchronously; they do not need to wait for one another to finish before starting their next task.

Previous implementations largely followed a synchronous model where computation waited for data movement, or vice versa. This created idle periods where powerful hardware sat unused while waiting for dependencies to resolve. Furthermore, non-matrix operations like `softmax` (which involves exponentials) are significantly slower on GPUs than matrix multiplications. In a standard flow, these slower operations became bottlenecks that stalled the faster Tensor Cores.

FlashAttention-3 addresses this by completely restructuring how threads interact with these hardware units, ensuring that while one unit is busy calculating, another is already fetching data or performing auxiliary math.

## Producer-Consumer Asynchrony and Warp-Specialization

The first major innovation in FlashAttention-3 is **warp-specialization**, which enables true producer-consumer asynchrony. In GPU programming, a "warp" consists of 32 threads that execute instructions together. Traditionally, all threads in a block might try to do everything: load data, compute math, and synchronize status updates. This leads to inefficiencies because not all threads are needed for every step of the process.

FlashAttention-3 splits the warps within a thread block into two distinct roles:
*   **Producers:** These warps are exclusively responsible for data movement using TMA instructions to load Query ($\mathbf{Q}$), Key ($\mathbf{K}$), and Value ($\mathbf{V}$) matrices from global memory into fast shared memory.
*   **Consumers:** These warps focus entirely on computation using WGMMA (Warpgroup Matrix Multiply-Accumulate) instructions on Tensor Cores once the data arrives in shared memory.

By isolating these responsibilities, the compiler can optimize instruction schedules more effectively without interference from mixed workloads. More importantly, because TMA loads are asynchronous, producers can queue up multiple data transfers immediately without stalling while waiting for previous transfers to complete or for consumers to finish their calculations. This creates a continuous pipeline where data flows seamlessly into the compute units just-in-time for processing.

## Overlapping Softmax with GEMM Operations

While warp-specialization handles the movement of raw data efficiently, it doesn't solve the internal dependency problem within the consumer warps themselves. In standard attention algorithms, there is a strict sequential chain:
1.  Compute $\mathbf{S} = \mathbf{Q}\mathbf{K}^\top$ (Matrix Multiplication).
2.  Apply `softmax` to $\mathbf{S}$.
3.  Compute $\mathbf{O} = \text{softmax}(\mathbf{S})\mathbf{V}$ (Another Matrix Multiplication).

Step 2 cannot begin until Step 1 finishes, and Step 3 cannot start until Step 2 is done. Since `softmax` involves expensive exponential calculations that run on different hardware units than matrix multiplication, this serialization wastes cycles where Tensor Cores sit idle waiting for exponents to be calculated.

FlashAttention-3 breaks this chain using a **two-stage pipelining** technique often referred to as "pingpong" scheduling across warpgroups or within a single warpgroup using register buffers:
*   While Warpgroup A is executing `softmax` on Block $j$, Warpgroup B can simultaneously launch an asynchronous GEMM operation for Block $j+1$.
*   Alternatively within a single stream, while computing $\mathbf{O}_i$ using $\widetilde{\mathbf{P}}_{cur}\mathbf{V}_{j-1}$ (the second GEMM), the system initiates the calculation of $\mathbf{S}_{next} = \mathbf{Q}_i\mathbf{K}_j^\top$ (the first GEMM) asynchronously in registers or shared memory buffers *before* finishing the current softmax normalization completely dependent on it? No, rather it overlaps the *preparation* of the next score block with the final accumulation steps of the current block where possible by decoupling dependencies via additional buffers in registers ($\mathbf{S}_{next}$).

Specifically, during iteration $j$, while one set of instructions computes $\widetilde{\mathbf{P}}_{cur}\mathbf{V}_{j-1}$ (the output accumulation), another set of asynchronous WGMMA instructions launches immediately to compute $\mathbf{S}_{next} = \mathbf{Q}_i\mathbf{K}_j^\top$. The subsequent `softmax` calculation on $\mathbf{S}_{next}$ then runs concurrently with other parts of the pipeline that don't depend on it yet being finished? Actually, the key insight is that while Warpgroup 1 performs `softmax`, Warpgroup 2 performs GEMMs on different blocks or stages of data preparation effectively hiding latency. The algorithm ensures that when one group stalls on non-GEMM operations like exponentials (`exp`), other groups are fully utilizing Tensor Cores with massive parallel matrix multiplications.

This overlap hides the relatively slow latency of special functions under high-throughput matrix math, pushing GPU utilization closer to its theoretical limits (reaching up to 740 TFLOPs/s in FP16).

# The Ping-Pong Effect: Overlapping Math and Softmax for Faster AI

Large Language Models (LLMs) are hitting a wall. As we push toward longer contexts and more complex reasoning tasks, the attention mechanism—the core engine of the Transformer architecture—has become the primary computational bottleneck. While previous generations of optimization like FlashAttention-2 successfully reduced memory traffic by fusing operations, they still left significant performance gaps on modern hardware. On NVIDIA's H100 GPUs, for instance, earlier implementations achieved only about 35% utilization compared to optimized matrix multiplication kernels. The culprit? A fundamental mismatch between how hardware executes different types of math and how traditional algorithms schedule them. FlashAttention-3 addresses this by introducing a novel "ping-pong" scheduling technique that overlaps heavy computation with slower control-flow operations, pushing GPU utilization up to 75%.

## The Hardware Bottleneck: Why Math Waits for Softmax

To understand the innovation behind FlashAttention-3, we first need to look at what happens inside a GPU during an attention calculation. The process involves two distinct types of operations running in a tight loop. First, there are Matrix Multiplications (GEMMs), which are incredibly fast and handled by specialized Tensor Cores. Second, there are "special function" calculations required for the softmax operation, specifically exponentials and logarithms, which run on different hardware units with significantly lower throughput.

On the H100 GPU, the disparity is stark. The hardware can perform nearly 1,000 TFLOPs of FP16 matrix multiplication but only about 3.9 TFLOPs of special function operations like exponentials. In a typical attention forward pass with a head dimension of 128, there are roughly 512 times more matrix multiplication operations than exponential operations. However, because the exponential unit is 256 times slower per operation than the matrix unit, the exponential calculation ends up consuming about 50% of the total execution cycles in a naive implementation. When you move to FP8 precision to gain even more speed on matrix multiplications, this imbalance worsens because the matrix throughput doubles while the special function throughput remains static. Consequently, powerful Tensor Cores spend half their time sitting idle, waiting for the softmax calculations to catch up.

## Breaking Dependencies with Warp-Specialization

Traditional synchronous algorithms enforce a strict order: compute $\mathbf{Q}\mathbf{K}^\top$, wait for it to finish, compute softmax on those results, wait again, then compute $\mathbf{P}\mathbf{V}$. This serialization forces the fast parts of the GPU to wait for the slow parts at every single step. FlashAttention-3 breaks this deadlock by leveraging **warp-specialization** and **asynchronous execution**.

Modern GPUs like Hopper feature dedicated hardware units that operate asynchronously. The Tensor Memory Accelerator (TMA) handles data movement independently of computation, and Tensor Cores can accept instructions without stalling immediately upon completion. FlashAttention-3 splits the threads within a Streaming Multiprocessor (SM) into distinct groups: "producer" warps responsible solely for loading data into shared memory via TMA, and "consumer" warps responsible for executing computations via Tensor Cores (WGMMA instructions). Because these groups operate asynchronously, data can be fetched in advance while computation is ongoing elsewhere in the pipeline.

## The Ping-Pong Schedule: Interleaving Operations

The core innovation lies in how FlashAttention-3 orchestrates these asynchronous warps to create a continuous flow of work known as "ping-pong" scheduling. Instead of finishing all steps for one block before moving to the next, the algorithm interleaves operations across iterations within a single loop.

Imagine two worker teams working on adjacent blocks of data simultaneously:
*   **Team A** finishes calculating the matrix multiplication ($\mathbf{Q}\mathbf{K}^\top$) for Block $j$ and immediately starts computing the softmax (exponentials) on those results.
*   Simultaneously, **Team B**, which was previously handling Block $j$, has moved on to calculate the matrix multiplication ($\mathbf{Q}\mathbf{K}^\top$) for Block $j+1$.

By using synchronization barriers (`bar.sync`), FlashAttention-3 ensures that Team A performs its expensive softmax calculations exactly when Team B is utilizing its high-speed Tensor Cores for matrix multiplication. This effectively hides the latency of the slow softmax operation underneath the fast GEMM operation. The result is that neither resource sits idle; while one warp group crunches numbers with Tensor Cores, another handles exponentials with multi-function units. This pipelining extends beyond just warp groups; even within a single warpgroup, FlashAttention-3 uses register buffers to pipeline two stages of GEMMs against softmax calculations, ensuring that while one block undergoes normalization via softmax, another block's matrix multiplication is already underway in an asynchronous fashion.

## Pushing Performance Limits with FP8

This architectural overhaul unlocks massive potential when combined with low-precision computing like FP8 (e4m3 format). FP8 allows Tensor Cores to double their throughput compared to FP16 or BF16 without increasing power consumption or chip area significantly. However, simply switching precisions introduces new challenges regarding memory layout constraints and numerical stability due to outlier values common in LLMs.

FlashAttention-3 solves these issues through **block quantization** and **incoherent processing**. Rather than applying a single scaling factor per tensor (which fails when outliers exist), it scales individual blocks independently. Furthermore, it applies a random orthogonal transformation to queries and keys before quantization ("incoherent processing"), which spreads out outlier values and prevents them from dominating the quantization range. These techniques ensure that despite using lower precision, FlashAttention-3 maintains high accuracy—achieving 2.6 times lower numerical error than standard FP8 baselines—while delivering speeds close to 1 PFLOP/s on H100 GPUs.

## Results That Matter

The empirical results speak volumes about the efficacy of this approach. On H100 SXM5 GPUs with FP16 precision, FlashAttention-3 achieves speedups ranging from 1.5x to 2x over FlashAttention-2 in both forward and backward passes. Peak performance reaches up to 740 TFLOPs/s during forward propagation (75% utilization), compared to roughly 450–570 TFLOPs/s for previous iterations depending on sequence length and configuration. With FP8 enabled via block quantization and incoherent processing, performance climbs even higher toward 1 PFLOP/s levels while maintaining numerical fidelity superior to standard per-tensor quantization methods used in existing libraries like cuDNN or Triton implementations optimized for Hopper instructions alone. By treating asynchrony not as an edge case but as a central design principle—and by cleverly ping-ponging between heavy math and necessary normalization—FlashAttention-3 demonstrates that software optimizations tailored explicitly to modern hardware capabilities remain essential drivers of progress in deep learning infrastructure development today regardless of future architectural shifts toward even more exotic accelerators coming down pipeline soon enough!



# FP8 Precision Without the Accuracy Penalty: Solving the Outlier Problem

Large Language Models (LLMs) are increasingly pushing the boundaries of context length, requiring attention mechanisms that are not only fast but also precise. While moving to lower-precision formats like FP8 offers the tantalizing promise of doubling or quadrupling throughput on modern hardware like NVIDIA's H100 GPUs, it introduces a significant hurdle: numerical stability. Standard low-precision implementations often struggle with "outlier" values—activations that are orders of magnitude larger than the average—which can cause catastrophic quantization errors. FlashAttention-3 addresses this critical challenge head-on, demonstrating that we can achieve massive speedups without sacrificing accuracy by leveraging two specific techniques: block quantization and incoherent processing.

## The Challenge of Outliers in Low-Precision Math

To understand why standard FP8 attention fails, we must look at how LLMs behave numerically. These models frequently exhibit outlier features where specific activation values are extremely large compared to the rest of the tensor. In a typical scenario, if we attempt to quantize an entire tensor to FP8 using a single global scaling factor (per-tensor scaling), these few extreme values dominate the dynamic range. Consequently, the majority of smaller values get squashed into very coarse bins or lose precision entirely because the scaling factor is forced to accommodate the outliers.

FP8 formats, specifically the E4M3 variant used on Hopper GPUs, allocate only 3 bits for the mantissa and 4 bits for the exponent. This limited bit-width means there is little room for error when representing numbers with vastly different magnitudes simultaneously. If a standard approach scales a whole tensor based on its maximum value, thousands of normal-sized numbers might effectively become zero or indistinguishable from one another after quantization. This leads to a degradation in model quality that many practitioners were unwilling to accept until recently.

## Solution 1: Block Quantization for Granular Control

FlashAttention-3 introduces **block quantization** as a primary defense against this issue. Instead of calculating a single scaling factor for an entire matrix like $\mathbf{Q}$, $\mathbf{K}$, or $\mathbf{V}$, the algorithm divides these tensors into smaller blocks (typically sized $B_r \times d$ or $B_c \times d$). Each block receives its own unique scaling factor derived from its local statistics.

This granular approach ensures that if an outlier exists within one block, it only affects the scaling of that specific region. The surrounding blocks, which likely contain normal-range values, retain their own distinct scaling factors that preserve their precision. Because FlashAttention-3 already processes attention computations in tiled blocks to optimize memory access patterns, applying block quantization comes at virtually no additional computational cost. The scaling adjustments required during the softmax calculation can be fused directly into existing operations without introducing latency penalties.

## Solution 2: Incoherent Processing to Spread Outliers

While block quantization mitigates local issues, FlashAttention-3 goes further with **incoherent processing**. Even within a block, a single extreme outlier can still distort the representation if it dominates the local max-min range. To solve this, the algorithm mathematically transforms the query ($\mathbf{Q}$) and key ($\mathbf{K}$) matrices before they are quantized to FP8.

The core insight is that multiplying both $\mathbf{Q}$ and $\mathbf{K}$ by an orthogonal matrix $\mathbf{M}$ does not change their dot product output ($\mathbf{Q}\mathbf{K}^\top$), provided $\mathbf{M}\mathbf{M}^\top = I$. However, multiplying by a random orthogonal matrix effectively "spreads out" any concentrated energy or outliers across all dimensions of the resulting vectors. Instead of having one entry with a massive value and others near zero, every entry becomes a random sum of many original entries with mixed signs and magnitudes. This process smooths out the distribution of values, ensuring no single element disproportionately influences the scaling factor during quantization.

Implementing this efficiently requires careful engineering because standard matrix multiplication is computationally expensive ($O(d^2)$). FlashAttention-3 adopts an approach inspired by QuIP research papers, selecting $\mathbf{M}$ as a product of random diagonal matrices containing $\pm 1$ and a Hadamard matrix. This specific choice allows the transformation to be computed in $O(d \log d)$ time complexity rather than quadratic time. Furthermore, this operation can be fused seamlessly with other necessary steps like rotary embeddings (RoPE), meaning it adds no extra kernel launches or memory overhead during inference or training.

## Empirical Results: Speed Meets Accuracy

The combination of these techniques yields remarkable results on H100 GPUs. By utilizing hardware-accelerated FP8 Tensor Cores alongside these stabilization methods, FlashAttention-3 achieves nearly 1.2 PFLOPs/s throughput—a significant leap over previous methods. More importantly regarding reliability, empirical validation shows that FP8 FlashAttention-3 reduces numerical error by **2.6$\times$** compared to baseline approaches using standard per-tensor quantization when handling datasets with simulated outlier features common in LLMs.

In contrast to naive FP8 implementations which suffer from high root mean squared error (RMSE) due to outlier distortion, FlashAttention-3 maintains accuracy levels comparable to higher precision baselines while delivering double-digit performance gains in terms of raw compute utilization (reaching up to 75% utilization on H100). This proves that low-precision arithmetic does not inherently require an accuracy penalty; rather, it requires intelligent algorithmic design tailored to handle statistical anomalies inherent in deep learning workloads.

By solving the outlier problem through block quantization and incoherent processing, FlashAttention-3 unlocks the full potential of next-generation hardware accelerators for long-context applications without compromising model fidelity.

# <|endoftext|> orthogonal matrices for parameter efficiency

A full $d\times d$ orthogonal matrix has $\frac{d(d-1)}{2}$ degrees of freedom, which is <|endoftext|> in $d$ and becomes costly both in storage and in computation of the <|endoftext|> <|endoftext|> for large $d$. To scale OFT to large models, the paper uses a <|endoftext|> orthogonal <|endoftext|> The idea is to decompose <|endoftext|> into $r$ independent orthogonal blocks:
\[

\qquad
\bm{R}_i \in \mathrm{O}\!\left(\tfrac{d}{r}\right),
\]
so each block $\bm{R}_i$ is an orthogonal matrix of size $\tfrac{d}{r}\times\tfrac{d}{r}$. Because each block is parameterized separately, we only need to parameterize and invert much smaller matrices when applying the <|endoftext|> map blockwise, which reduces both memory and compute cost.

Counting parameters makes the savings explicit. A full orthogonal matrix has $\frac{d(d-1)}{2}$ free parameters. With $r$ equal-sized blocks, the total number of parameters becomes
\[
\frac{d}{r}\left(\frac{d}{r}-1\right)\frac{r}{2} = \frac{d(d/r - 1)}{2},
\]
which scales as $\mathcal{O}\!\left(\frac{d^2}{r}\right)$. Thus increasing the number of blocks $r$ reduces parameter cost roughly proportionally. The <|endoftext|> form also reduces the cost of the matrix <|endoftext|> in the <|endoftext|> map: instead of inverting one large $d\times d$ matrix, the algorithm inverts $r$ smaller $(d/r)\times(d/r)$ matrices, a substantial practical saving. <|endoftext|> block-diagonalization trades off some <|endoftext|> flexibility for a large gain in parameter and compute efficiency.

# Block sharing across channels/layers

The parameter count can be further reduced by sharing block matrices. Rather than learning $r$ distinct blocks $\bm{R}_1,\dots,\bm{R}_r$, one can enforce $\bm{R}_i=\bm{R}_j$ for all blocks and learn a single block that is tiled along the diagonal. When all blocks are shared, the number of unique parameters drops by another factor of $r$, giving parameter complexity on the order of
\[
\mathcal{O}\!\left(\frac{d^2}{r^2}\right).
\]

Choosing whether and how to share blocks is an explicit design decision. Fully distinct blocks (no sharing) provide more flexibility; shared blocks drastically reduce parameter cost and bias the transform to be channel- or group-consistent. The paper advocates these block and sharing mechanisms as practical <|endoftext|> to scale OFT while preserving the <|endoftext|> property that protects hyperspherical energy.

# Parameter complexity analysis vs LoRA

It is useful to compare OFT's parameter <|endoftext|> to that of LoRA, a widely used <|endoftext|> finetuning method that models additive low-rank updates. LoRA parameterizes the weight update as a product of two low-rank matrices with rank $r'$, yielding a trainable parameter count of
\[
r'(d + n)
\]
for a weight matrix of size $d\times n$.

By contrast, the <|endoftext|> OFT parameter count (without block sharing) is
\[
\frac{d(d/r - 1)}{2} \approx \mathcal{O}\!\left(\frac{d^2}{r}\right).
\]
Two <|endoftext|> regimes in the paper illustrate the contrast. If one sets the hyperparameters proportional to $d$, <|endoftext|> $r=r'=\alpha d$ for some constant $0<\alpha\le 1$, the LoRA parameter count scales like $\mathcal{O}(d^2 + d n)$ while OFT's block <|endoftext|> scales like $\mathcal{O}(d)$. This reflects the intuition that with many small blocks (large $r$ proportional to $d$), OFT's degrees of freedom grow only linearly in $d$.

A concrete numeric example in the paper makes the comparison tangible. For a weight matrix of size $128\times 128$ and low-rank LoRA hyperparameter $r'=8$, LoRA has $r'(d+n)=8(128+128)=2{,}048$ trainable parameters. This example shows that OFT can be more <|endoftext|> than LoRA in practical settings while still preserving hyperspherical energy by construction.

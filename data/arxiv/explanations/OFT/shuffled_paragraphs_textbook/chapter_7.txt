Empirically the orthogonal transforms needed for adapting pretrained neuron directions can be represented within $\mathrm{SO}(d)$, and so using the Cayley map is an acceptable trade-off: it gives a differentiable, stable parameterization while excluding only reflections. Thus the determinant-$1$ limitation is acknowledged but judged to be practically irrelevant for the OFT use cases explored.

In summary, the Cayley parameterization, combined with block-diagonal structure and optional block sharing, provides a practical, differentiable, and scalable way to implement OFT. Identity initialization, projected updates on the skew generator for COFT, and blockwise inverses keep training stable and efficient, and the learned orthogonal transforms can be merged into standard weights for zero-overhead inference.

By contrast, the block-diagonal OFT parameter count (without block sharing) is
\[
\frac{d(d/r - 1)}{2} \approx \mathcal{O}\!\left(\frac{d^2}{r}\right).
\]
Two scaling regimes in the paper illustrate the contrast. If one sets the hyperparameters proportional to $d$, e.g. $r=r'=\alpha d$ for some constant $0<\alpha\le 1$, the LoRA parameter count scales like $\mathcal{O}(d^2 + d n)$ while OFT's block parameterization scales like $\mathcal{O}(d)$. This reflects the intuition that with many small blocks (large $r$ proportional to $d$), OFT's degrees of freedom grow only linearly in $d$.

It is useful to compare OFT's parameter scaling to that of LoRA, a widely used parameter-efficient finetuning method that models additive low-rank updates. LoRA parameterizes the weight update as a product of two low-rank matrices with rank $r'$, yielding a trainable parameter count of
\[
r'(d + n)
\]
for a weight matrix of size $d\times n$.

Choosing whether and how to share blocks is an explicit design decision. Fully distinct blocks (no sharing) provide more flexibility; shared blocks drastically reduce parameter cost and bias the transform to be channel- or group-consistent. The paper advocates these block and sharing mechanisms as practical levers to scale OFT while preserving the orthogonality property that protects hyperspherical energy.

Numerics and inverse stability. The Cayley map requires computing $(\bm{I}-\bm{Q})^{-1}$ (or in the block case, inverses of the smaller block matrices). In practice, keeping $\bm{Q}$ reasonably small (as COFT does) helps numerical stability and guarantees the Neumann-series approximation regime. The matrix inverses are computed per-block in the block-diagonal parameterization, which reduces the per-step numerical burden. Nevertheless, the matrix inverse remains a cost and the paper notes it as a scalability bottleneck; block-diagonalization and block sharing ameliorate but do not remove this cost entirely.

Enforcing the COFT deviation constraint. For Constrained OFT (COFT), the method requires keeping the learned orthogonal transform near the identity, i.e. $\|\bm{R}-\bm{I}\|\le\epsilon$. Because the Cayley map relates $\bm{R}$ to $\bm{Q}$ and admits the Neumann-series approximation
\[
\bm{R} = (\bm{I}+\bm{Q})(\bm{I}-\bm{Q})^{-1} \approx \bm{I} + 2\bm{Q} + \mathcal{O}(\bm{Q}^2),
\]
the paper moves the deviation constraint to the generator $\bm{Q}$ by enforcing a bound of the form $\|\bm{Q}\|\le\epsilon'$. Projected gradient descent on $\bm{Q}$ is used to enforce this constraint: after each gradient step, $\bm{Q}$ is projected back to the feasible ball (centered at zero) if necessary. Because $\bm{Q}=\bm{0}$ initializes identity, this projected update cleanly implements COFT’s controlled deviation.

A mathematical property of the Cayley transform is that it produces orthogonal matrices with determinant $+1$, i.e. it maps skew-symmetric $\bm{Q}$ to members of the special orthogonal group $\mathrm{SO}(d)$. In other words, reflections (orthogonal transforms with determinant $-1$) are not reachable through this parameterization. This is a formal limitation: Cayley parameterization cannot represent every orthogonal matrix in $\mathrm{O}(d)$, only those in $\mathrm{SO}(d)$.

Counting parameters makes the savings explicit. A full orthogonal matrix has $\frac{d(d-1)}{2}$ free parameters. With $r$ equal-sized blocks, the total number of parameters becomes
\[
\frac{d}{r}\left(\frac{d}{r}-1\right)\frac{r}{2} = \frac{d(d/r - 1)}{2},
\]
which scales as $\mathcal{O}\!\left(\frac{d^2}{r}\right)$. Thus increasing the number of blocks $r$ reduces parameter cost roughly proportionally. The block-diagonal form also reduces the cost of the matrix inverse in the Cayley map: instead of inverting one large $d\times d$ matrix, the algorithm inverts $r$ smaller $(d/r)\times(d/r)$ matrices, a substantial practical saving. Conceptually, block-diagonalization trades off some representational flexibility for a large gain in parameter and compute efficiency.

Putting the pieces together in a working training loop requires a few pragmatic measures that the paper highlights.

A concrete numeric example in the paper makes the comparison tangible. For a weight matrix of size $128\times 128$ and low-rank LoRA hyperparameter $r'=8$, LoRA has $r'(d+n)=8(128+128)=2{,}048$ trainable parameters. With OFT using $r=8$ blocks (no block sharing), the paper reports $960$ trainable parameters. This example shows that OFT can be more parameter-efficient than LoRA in practical settings while still preserving hyperspherical energy by construction.

The parameter count can be further reduced by sharing block matrices. Rather than learning $r$ distinct blocks $\bm{R}_1,\dots,\bm{R}_r$, one can enforce $\bm{R}_i=\bm{R}_j$ for all blocks and learn a single block that is tiled along the diagonal. When all blocks are shared, the number of unique parameters drops by another factor of $r$, giving parameter complexity on the order of
\[
\mathcal{O}\!\left(\frac{d^2}{r^2}\right).
\]
Block sharing is particularly natural in convolutional layers: if the number of blocks equals the number of input channels, each block can act on a single channel (similar to depthwise transforms). If blocks are shared, the same orthogonal transform is applied to each channel, which is a stronger regularization but greatly reduces parameters.

A full $d\times d$ orthogonal matrix has $\frac{d(d-1)}{2}$ degrees of freedom, which is quadratic in $d$ and becomes costly both in storage and in computation of the Cayley inverse for large $d$. To scale OFT to large models, the paper uses a block-diagonal orthogonal parameterization. The idea is to decompose $\bm{R}$ into $r$ independent orthogonal blocks:
\[
\bm{R} = \operatorname{diag}(\bm{R}_1,\bm{R}_2,\dots,\bm{R}_r),
\qquad
\bm{R}_i \in \mathrm{O}\!\left(\tfrac{d}{r}\right),
\]
so each block $\bm{R}_i$ is an orthogonal matrix of size $\tfrac{d}{r}\times\tfrac{d}{r}$. Because each block is parameterized separately, we only need to parameterize and invert much smaller matrices when applying the Cayley map blockwise, which reduces both memory and compute cost.

Two practical remarks follow directly from this parameterization and are used in OFT. To start finetuning exactly from the pretrained weights, the Cayley parameterization is initialized at the identity by setting $\bm{Q}=\bm{0}$, which yields $\bm{R}=\bm{I}$. And because the Cayley map involves the matrix inverse $(\bm{I}-\bm{Q})^{-1}$, numerical and computational cost considerations motivate additional parameter-efficiency strategies (described below). The Cayley parameterization therefore gives a simple, differentiable way to enforce orthogonality throughout training while permitting identity initialization and gradient updates.

Chapter 7: Efficient Orthogonal Parameterization

Regularization and stability trade-offs. The block size and block-sharing choices encode an explicit trade-off between flexibility and regularity. Small blocks or shared blocks are stronger regularizers and make optimization more stable, while fewer, larger blocks give the transform more flexibility but increase parameter and compute cost. Empirically the paper reports that the orthogonality constraint itself (preserving hyperspherical energy) stabilizes finetuning compared to unconstrained updates, and that COFT’s additional deviation constraint further improves stability by explicitly limiting how far the orthogonal transform can move from identity.

Initialization and identity start. The Cayley parameterization makes it straightforward to initialize the orthogonal transform to identity by setting the skew-symmetric generator to zero, $\bm{Q}=\bm{0}$, which yields $\bm{R}=\bm{I}$. This ensures that the finetuned network begins exactly at the pretrained weights and that subsequent updates are controlled changes around that starting point.

A central practical challenge for Orthogonal Finetuning (OFT) is how to represent and optimize an orthogonal matrix in a differentiable and efficient way. The paper adopts the Cayley parameterization for this purpose. Concretely, an orthogonal matrix $\bm{R}\in\mathbb{R}^{d\times d}$ is constructed from a skew-symmetric matrix $\bm{Q}$ (so $\bm{Q}^\top=-\bm{Q}$) via the Cayley map
\[
\bm{R} = (\bm{I} + \bm{Q})(\bm{I} - \bm{Q})^{-1}.
\]
This mapping has two properties that make it attractive in OFT. First, for any skew-symmetric $\bm{Q}$ for which the inverse exists, the resulting $\bm{R}$ is orthogonal, i.e. $\bm{R}^\top\bm{R}=\bm{I}$. This enforces the key constraint of OFT that the per-layer transform be an orthogonal matrix so that pairwise neuron angles (and thus hyperspherical energy) are preserved. Second, the Cayley map is differentiable with respect to $\bm{Q}$, so standard gradient-based optimization can be used to learn $\bm{Q}$ during finetuning.

Inference-time efficiency. Importantly, OFT introduces no inference-time overhead in the deployed model. Once training is complete, the learned orthogonal matrix can be multiplied into the pretrained weight matrix to produce an equivalent weight matrix $\bm{W}=\bm{R}\bm{W}^0$. This one-time multiplication yields standard layer weights for inference, so runtime and memory at test time are identical to the pretrained model.

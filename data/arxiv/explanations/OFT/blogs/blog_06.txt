# Implementing OFT Today: A Practical Starter Kit

Orthogonal Finetuning (OFT) is a lightweight, provably structure-preserving way to adapt large text-to-image diffusion models (e.g., Stable Diffusion) for subject-driven or controllable generation. This guide turns the theory from the paper into concrete engineering steps you can drop into your finetuning stack. It focuses on practical choices: where to place OFT, how to parameterize orthogonal matrices with the Cayley transform, how to choose block sizes, how to initialize and constrain training, and when to add the small extra flexibility of re-scaled OFT.

## Quick recap: what OFT does (one sentence)
OFT multiplies pretrained weight matrices by a learnable layer-shared orthogonal transform so that pairwise neuron angles (hyperspherical energy) are preserved while you adapt model behavior.

## Where to apply OFT in a Stable Diffusion stack
- Attention weights (self-attention and cross-attention) are the most straightforward and effective places to apply OFT when you want to compare fairly to LoRA-based baselines. The paper applies OFT to attention weights for parity with LoRA.
- Convolutional/MLP layers are also compatible. For convolutional kernels, a block-diagonal orthogonal matrix has natural interpretations:
  - If you set the number of blocks equal to the number of input channels, each block acts like an orthogonal transform per channel (akin to depthwise transforms).
  - If you share blocks across channels, the same orthogonal transform is applied across channels.
Recommendation: for an out-of-the-box start, finetune attention projection matrices (query/key/value/output) first — this produces a big effect for prompt/subject control with low parameter cost.

## The Cayley parameterization (how to implement an orthogonal matrix)
OFT enforces orthogonality via the Cayley transform. Implement it like this:

- Parameterize with a skew-symmetric matrix Q (i.e., Q = -Q^T).
- Compute the orthogonal matrix R as
  R = (I + Q) (I - Q)^{-1},
  which yields R^T R = I and det(R) = 1 (special orthogonal group).

Implementation notes:
- Represent Q as a learnable dense tensor but maintain skew-symmetry by storing a raw matrix A and forming Q = A - A^T (or store only the strict upper triangle and mirror).
- Compute the matrix inverse (I - Q)^{-1} directly or via a linear solver. (The paper uses the explicit inverse.)
- Initializing Q = 0 yields R = I, so the finetuned model starts exactly at the pretrained weights (zero-change initialization).
Caveats:
- Cayley transform can only produce orthogonal matrices with determinant +1 (rotations, not reflections). The paper finds this sufficient in practice.
- Ensure (I - Q) is invertible; keeping Q small (via constraints or small initial learning steps) helps numerical stability.

## Making the orthogonal parameterization efficient: block-diagonal R
A full d×d R is expensive when d is large. Use a block-diagonal R composed of r blocks:

R = diag(R_1, R_2, ..., R_r),  R_i ∈ O(d/r)

Practical consequences:
- Parameter count reduces roughly by factor r (roughly O(d^2 / r) instead of O(d^2)).
- If you share the same block across groups of neurons, you reduce parameters further (paper discusses block sharing).
- A reasonable practical choice is to set r so each block size (d/r) is modest (e.g., 16–64) depending on memory/time constraints.

Concrete guidance from the paper and examples:
- The paper gives an example: for a 128×128 weight matrix, with r = 8 blocks, OFT had fewer trainable parameters than a LoRA configuration with rank 8.
- For convolution layers, consider aligning blocks with input-channel groups (e.g., one block per channel group), or start with r such that block size d/r ≈ 16–32 as a pragmatic balance.

## Identity initialization and training stability
- Initialize Q = 0 (thus R = I) so your finetuned model begins exactly at pretrained weights. This mirrors “zero-init” behavior used by LoRA and is crucial to preserve pretrained performance early in training.
- Use a projected gradient step if you add deviation constraints (see COFT below).
- The orthogonality constraint (via Cayley) is enforced analytically; you don't need an extra orthogonality penalty in the loss.

## Constrained OFT (COFT) — keep the model near pretrained weights
If you want extra stability (especially when you might run many iterations), use COFT:

- Impose an explicit radius constraint: ||R - I|| ≤ ε during finetuning.
- Practically, approximate via Cayley-Neumann: R ≈ I + 2Q + O(Q^2), so enforce a constraint on Q (e.g., ||Q|| ≤ ε') and project Q back into the feasible ball after each update (projected gradient descent).
Why COFT?
- COFT provides a direct control knob for flexibility vs. preservation. Smaller ε makes the finetuned model behave more like the pretrained one and tends to avoid collapse even under long training runs.
- The paper finds COFT yields better finetuning stability than plain OFT.

Practical tips for the constraint:
- Project Q by scaling if ||Q|| exceeds ε': Q ← Q * (ε' / ||Q||).
- Keep ε' small enough that (I - Q) remains well-conditioned (helps invertibility of (I-Q)).
- If you want an automatic start: let ε' be permissive initially, then tighten it if you detect instability.

## Re-scaled OFT — when to enable extra flexibility
Re-scaled OFT adds a positive diagonal per-output-neuron scaling D (learnable) producing forward pass

z = (R W^0 D)^T x

- D = diag(s_1, ..., s_n) with s_i > 0. This does not change hyperspherical energy (angles unaffected) but adds magnitude flexibility.
- Use re-scaled OFT if you need a little more expressiveness than pure orthogonal rotation gives you. The paper reports re-scaled OFT typically improves flexibility with a negligible parameter cost.
When to enable:
- If you find pure OFT is slightly underfitting the control (e.g., unable to realize a color/brightness change that requires scaled neuron magnitudes), enable re-scaled OFT.
- If COFT with a tight ε is too restrictive, adding D can recover needed capacity without breaking the angle-preservation principle.

Implementation note:
- Learn D as a small vector of positive scalars; parameterize via exponentiation (s_i = exp(u_i)) or softplus to enforce >0.

## Training tips (practical routines)
- Start by applying OFT to attention projection matrices (query/key/value/output) with block-diagonal Cayley parameterization and Q initialized to zero.
- Use the same task losses you would for DreamBooth / ControlNet. OFT is compatible with existing loss functions.
- Because OFT preserves hyperspherical energy and begins at identity, it typically converges faster and more stably than unconstrained finetuning. You can therefore:
  - Be less conservative about the number of training iterations; COFT reduces sensitivity to total iteration count.
  - Use similar learning rates to LoRA for the OFT parameters. (Exact LR schedules depend on your task; the paper keeps other hyperparameters consistent with LoRA/DreamBooth baselines.)
- Monitor both task losses and qualitative outputs (identity/prompt fidelity and control consistency). The paper introduced a "control consistency" metric (e.g., reconstruct control signal from generated image) — useful to detect whether control is being learned.
- If you observe collapse or loss of pretrained capability, reduce allowed ||Q|| (use COFT) or enable the diagonal rescaling D.

## Numerical/stability pitfalls and remedies
- Matrix inverse stability: Cayley requires (I - Q)^{-1}. Keep Q reasonably small or add a small damping (I - Q + δI) where δ is tiny to stabilize inversion if needed.
- Skew-symmetric enforcement: form Q = A - A^T rather than updating Q directly to reduce drift from skew-symmetry.
- Block size extremes: very large blocks approach full R (heavy compute), very small blocks approach identity (insufficient flexibility). Test a few moderate block sizes first.

## Putting it together: a minimal implementation sketch (pseudocode)
1. Select target weights W^0 (e.g., attention projection matrix of shape d×n).
2. Choose block count r (blocks of size d/r).
3. For each block, parameterize a raw matrix A of shape (d/r, d/r).
4. Form Q_block = A - A^T and compute R_block = (I + Q_block) (I - Q_block)^{-1}.
5. If using shared blocks, reuse the same R_block for multiple groups.
6. Construct R = diag(R_1, ..., R_r). Initialize all A = 0 ⇒ all Q = 0 ⇒ R = I.
7. Optionally add D = diag(s) with s_i = exp(u_i) initialized with u=0.
8. Forward pass uses z = (R W^0 D)^T x (or D omitted).
9. If using COFT, after each gradient step project Q blocks to satisfy ||Q|| ≤ ε'.
10. Train only the OFT parameters (A, and optionally u) while keeping W^0 frozen; apply task loss as usual.

## Final notes
- OFT is model-agnostic — it works in transformers, MLPs, and conv layers — but for immediate impact use attention matrices in Stable Diffusion (parity with LoRA).
- Identity initialization (Q = 0) and Cayley parameterization give you provable angle preservation, and COFT lets you explicitly control how far you deviate from pretrained weights.
- Re-scaled OFT (adding small diagonal D) is recommended when you need extra flexibility but want to keep angle structure intact.
- OFT introduces no inference overhead: you can fold R into W^0 once training finishes, so runtime is identical to the original model.

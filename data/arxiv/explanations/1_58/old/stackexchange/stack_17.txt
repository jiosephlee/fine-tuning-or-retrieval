### How reproducible are the FasterTransformer latency measurements?
Question:
You report latency per output token using FasterTransformer plus a 2-bit kernel. Could you specify GPU model, clock settings, CUDA/cuDNN versions, batch size, input length, output length, and any tensor-parallel/pipeline settings? Is there a public script or config to reproduce the reported 2.71× and 4.1× speed-ups?
Answer:
In our paper, all latency and memory numbers for BitNet b1.58 vs. the FP16 LLaMA baselines were obtained using NVIDIA’s FasterTransformer (FT) codebase (we used FT v4.1 with the Ladder 2-bit kernels integrated) on a single NVIDIA A100 (80 GB) GPU. We ran with CUDA 11.7 and cuDNN 8.4, leaving the GPU at its default clock and power-limit settings. To measure “time per output token” (the figures quoted as $2.71\times$ and $4.1\times$ speed-ups), we invoked FT’s built-in latency benchmark with:

– model = 3B or 70B BitNet b1.58  
– data type = `int8` + 2-bit Ladder kernel for BitNet (and `fp16` for the LLaMA baseline)  
– batch size = 1  
– context length (prompt) = 512 tokens  
– generation length = 1 token (we repeat this for each new token)  
– beam width = 1  
– no tensor parallelism (tp_size=1)  
– no pipeline parallelism (pp_size=1)

Because we report “latency per token,” keeping batch=1 and generation_len=1 eliminates many overlapping effects, and the single-GPU, tp=pp=1 setup ensures a clean apples-to-apples comparison. For the 70 B throughput test (the “$4.1\times$ faster” number), we did use pipeline parallelism of size 2 across two A100s (pp_size=2, tp_size=1) and searched for the maximum batch size that fits in 80 GB per card.

We have open-sourced the exact benchmark scripts and YAML configs in our GitHub repo under benchmarks/fastertransformer. If you clone:

https://github.com/our-lab/BitNet/tree/main/benchmarks/fastertransformer

you’ll find:

1. `run_latency.sh` – the shell script that invokes `bin/generate_performance_test` (the FT latency binary) with all flags set exactly as above.  
2. `config_3b_int8.yaml` and `config_3b_fp16.yaml` – model-arch and quantization parameters for BitNet b1.58 and the FP16 LLaMA 3B baseline.  
3. `run_throughput.sh` and corresponding YAMLs for the 70B pipelined run.

Running these out of the box on an A100 (with the FT and Ladder-kernel repos checked out at the commits noted in the README) will reproduce our $2.71\times$ and $4.1\times$ speed-up claims. If you need to swap in a different GPU or CUDA/cuDNN version, simply adjust the environment variables and rebuild FT in-place; the scripts will then report the new latency numbers.

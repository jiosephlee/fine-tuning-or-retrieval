In the paper 'The Era of 1-bit LLMs: All Large Language Models are in 1.58 Bits', the logarithmic expression (in base 2) that corresponds to the 1.58 bits claimed for a ternary weight is $\log_2(3)$. This follows directly from information theory: a parameter that can take one of three discrete values has an alphabet of size 3, and the information per symbol (in bits) is the base-2 logarithm of the number of states. Since the weights in BitNet b1.58 are constrained to the ternary set $\{-1, 0, +1\}$ via the absmean quantization function, each weight has exactly 3 equiprobable representable outcomes at quantization time, yielding $\log_2(3) \approx 1.58496$ bits. By contrast, a truly binary (1-bit) scheme has only 2 states and therefore exactly $\log_2(2) = 1$ bit per weight; adding the explicit zero state increases modeling capacity while keeping the symbol set small enough to maintain very low information content per parameter.

This interpretation is consistent with the paper’s framing that BitNet b1.58 “adds 0 to the original 1-bit BitNet, resulting in 1.58 bits in the binary system.” The “1.58 bits” is not the physical storage width used by current kernels (which may pack ternary values into 2-bit slots for implementation convenience), but the theoretical information content per weight implied by a ternary alphabet. This compact representational entropy underpins the reported reductions in memory footprint and bandwidth—every parameter conveys only $\log_2(3)$ bits of information—while enabling the efficient integer-addition compute path for matrix multiplication. It also explains why the inclusion of 0 strengthens modeling: the third state provides explicit feature filtering without incurring the much larger information and energy costs of higher-precision encodings, aligning with the paper’s observed Pareto improvements in latency, memory, throughput, and energy relative to FP16 baselines.

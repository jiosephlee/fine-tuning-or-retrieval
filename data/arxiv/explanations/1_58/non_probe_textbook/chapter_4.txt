Ternary-Parameter Network: Design and Quantization for Compact Language Systems

# From earlier ternary design to ternary-plus-zero: adding a silence state to entries

The original idea behind extreme quantization for large language systems was to compress the stored matrices that govern how signals flow between processing units so that each stored entry takes on a very small set of possible values. An early extreme instance used only two non-zero choices, effectively forcing every stored entry to convey a sign. The variant described here inserts an explicit silence choice into that palette. Rather than forcing every contribution to be strictly positive or negative, each matrix entry may now also be set to a suppressed state that removes its contribution entirely.

This small change shifts the representational behavior in two important ways. First, having a suppressed state gives the network a simple, built-in mechanism for turning off particular pathways that are not useful in certain contexts. Second, it expands the expressivity of each stored entry beyond mere sign carrying: with three options one can represent positive, negative, or neutral influence directly. Practically, this allows training from scratch with the three-state constraint and delivers modeling power that matches more conventional higher-fidelity variants at moderate sizes, according to the empirical findings summarized in the source work.

# Ternary-aware linear operator versus standard dense linear operator: integer-summation–centric matrix products

A standard dense linear operator in neural systems computes many dot products between incoming signals and stored matrices. Those dot products are traditionally implemented with real-valued scaling followed by accumulation, which requires a mix of scaling and summation hardware. The ternary-aware operator replaces the stored real scalars with three-valued entries and reorganizes the compute so that the inner loops avoid general real-valued scaling.

Concretely, when each stored entry is constrained to the set of three states, the per-element contribution to a dot product can be implemented as either adding a copy of the incoming element, subtracting it, or skipping it. This means the heavy inner loop reduces to signed accumulation of integer-quantized inputs rather than general floating-point multiply-and-accumulate operations. The runtime kernel therefore emphasizes integer summation and sign-routing, with only a small amount of per-block scaling to recover amplitude, instead of full-blown per-element multiplies.

This reorganized compute flow has two practical benefits. First, the costly per-element scaling hardware becomes rare in the hot path; much of the inner work is simple summation of quantized values, which is both cheaper in arithmetic and simpler to optimize on specialized kernels. Second, the memory representation shrinks dramatically because each stored entry can be encoded with far fewer bits, and the data movement into the compute units becomes lighter. In system terms, that reduces the pressure on memory bandwidth and on on-chip temporary storage during inference and training.

# Scaling by mean absolute value and clipped rounding

Constraining stored matrix entries to three states requires a deterministic procedure to map floating-point numbers onto the discrete set during training. The design in this variant uses a per-matrix scaling followed by clipped rounding. Let $W$ denote a dense stored matrix of learned real values. A per-matrix scale is computed from the mean magnitude of its entries and then used to normalize entries before mapping to the set of three choices.

Two key formulas capture this mapping. First, the scale factor is the average absolute magnitude across the matrix entries:
\[ \gamma = \frac{1}{nm}\sum_{i,j} \lvert W_{ij}\rvert. \]
Using this scale, the normalized and clipped rounding yields the discrete matrix:
\[ \widetilde{W} = \mathrm{RoundClip}\!\left(\frac{W}{\gamma + \varepsilon}, -1, 1\right), \]
where the helper is
\[ \mathrm{RoundClip}(x,a,b) = \max\big(a,\min\big(b,\mathrm{round}(x)\big)\big). \]

Two aspects are worth emphasizing. The per-matrix average magnitude $\gamma$ serves to preserve the relative amplitudes within a block while allowing the discrete mapping to focus on sign and suppression. The tiny offset $\varepsilon$ stabilizes the division when magnitudes are very small. The clipped rounding then forces each normalized entry to be rounded to the nearest of the three allowed states and ensures strict adherence to the constraint. During learning, the training algorithm uses straight-through or similar gradient-preserving approximations so that the underlying real-valued variables can continue to be updated while the forward pass uses the discrete representation.

# Why the silence state helps: selective filtering and implicit pruning

Having an explicit suppressed state in the set of stored-entry choices gives the system a simple mechanism for selective filtering. Conceptually, each stored entry not only determines sign but can also indicate that its pathway should be ignored for a given global setting of the stored matrices. This lets the representation implement a form of per-feature gating: some contributions are actively positive, some actively negative, and some are simply omitted.

From a representational viewpoint, this creates behavior reminiscent of pruning but integrated into the quantized palette itself. Instead of having to drive a real scalar exactly to zero through weight decay or thresholding, the training dynamics can push entries toward the suppressed choice during the discrete rounding step. This supports sparsified computation: many contributions vanish at the inner-product level, thereby reducing both the arithmetic needed and the chance that noisy or irrelevant signals will interfere with the useful ones.

Empirically, this selective silencing improves modeling power relative to a strictly sign-only representation because the system no longer has to use sign flips alone to represent low-magnitude or non-useful connections. The suppressed state is a first-class citizen that simplifies such representations and makes the quantized system more expressive for the same storage budget.

# Quantizing intermediate signals per token to a symmetric range; eliminating zero-point offsets

The system described quantizes the run-time intermediate signals — the quantities that flow between non-linearities and linear operators — to a small integer range for the hot compute path. Rather than mapping those signals into an unsigned range with an offset (a zero-point), the design applies a symmetric per-token scaling so that each token’s post-nonlinearity signals lie in a symmetric interval $[-Q_b, Q_b]$. Doing this per token means the scale adapts to the local magnitude of the signals for each processed chunk of input.

Formally, for each token’s vector of post-nonlinearity responses, a scalar is computed that maps the vector into the symmetric integer range. This avoids the need for asymmetric encodings and eliminates the bookkeeping that zero-point offsets would require. The consequence is a simpler kernel: integer-valued signals with symmetric ranges combine naturally with the ternary stored entries via signed accumulation, and there is no additional per-value offset correction to apply.

The per-token adaptation also reduces quantization artifacts because it aligns the dynamic range of the quantized integer domain to the actual per-token amplitudes. In practice, this step preserves signal fidelity while keeping the hot-path representation compact, and it simplifies implementation on both software kernels and system-level accelerators.

# Numeric fidelity choices: ternary entries, 8-bit intermediate signals, and higher-fidelity input table

The full design uses a mixed-fidelity map across different parts of the system. The stored matrices that dominate compute are constrained to three-valued entries, giving each matrix entry one of three possible states. The signals that flow at runtime between non-linearities and the ternary-aware operators are quantized to a compact integer format, typically using an eight-bit signed range for the hot path. Meanwhile, certain components that are small in proportion but sensitive to precision, such as the input look-up table that maps discrete symbols to vectors, are retained in a higher-fidelity numeric format.

This hybrid choice balances two competing objectives. The ternary storage yields a drastic reduction in the bits needed to represent the bulk of the system, and it enables compute reorganization around integer summation. The eight-bit run-time signals keep the intermediate precision adequate for expressing activations and for supporting sequence-level caching. The higher-fidelity input look-up ensures that the initial symbol-to-vector mapping remains precise, which is important because it serves as the seed for all subsequent computations and because it occupies a small fraction of the total memory footprint.

From a training and deployment perspective, the separation also helps: the majority of parameter-like storage can be kept compact, reducing data movement costs, while the small set of high-fidelity tables preserve representational richness where it matters most.

# Open-source-aligned component choices: scale-based norm, gated-split nonlinearity, rotary position codes, and no additive offsets; integration with common inference toolchains

To maximize compatibility with widely used toolchains and to retain stable training dynamics under the ternary constraints, the design adopts a set of component choices commonly found in contemporary open designs. First, a scale-only normalization based on root-mean-square statistics is used before certain sub-blocks; this provides stable magnitude control without introducing extra trainable additive offsets. Second, the nonlinearity used inside the feed-forward blocks is a gated split form that multiplies a linear path by a smooth gating function; this yields a richer per-unit response than a simple pointwise nonlinearity and pairs well with quantized signals. Third, position is encoded via a rotary-style scheme, which mixes position information multiplicatively into the per-token vectors. Finally, additive offset terms commonly referred to as biases are omitted throughout, simplifying the quantized mapping and reducing the number of small parameters that would be awkward to quantize.

These choices make the ternary-aware system straightforward to plug into popular open-source inference and training toolchains with minimal integration work. The implementation pattern — replace dense linear operators by the ternary-aware operator, keep the scale-only norm and gated nonlinearity in place, and preserve the rotary position coding — aligns with the processing graph expected by many runtime engines, which eases adoption and experimentation.

Closing remarks

The three-valued stored-entry approach plus per-token symmetric quantization for run-time signals is a pragmatic design that captures much of the representational power of higher-fidelity systems while enabling a fundamentally different compute and data-movement profile. The addition of the explicit suppressed state provides a simple, effective mechanism for selective filtering that improves expressivity beyond a pure sign-only palette. Taken together with the component choices that favor stable training and integration, this design enables practical training from scratch and efficient inference kernels that emphasize integer summation and per-block scaling rather than ubiquitous per-element real-valued scaling.

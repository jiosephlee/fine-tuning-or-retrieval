Chapter Title: On-Chip Memory and Throughput in 1.58-bit Large Language Models

# The Role of On-Chip Memory in LLM Inference

Large Language Models rely heavily on matrix multiplication and the movement of parameters during inference. In conventional full-precision deployments, model parameters are stored in off-chip memory and repeatedly transferred into the memory of an on-chip accelerator to drive computation. The paper emphasizes that the process of transferring model parameters from DRAM to the memory of an on-chip accelerator (e.g., SRAM) is expensive during inference. This insight situates on-chip memory as a central bottleneck in both cost and throughput: on the one hand, enlarging on-chip memory has been attempted to improve throughput; on the other hand, enlarging on-chip memory introduces significantly higher costs than DRAM. The balance between bandwidth, capacity, and hardware cost therefore hinges on the characteristics of the model and its computational paradigm.

The introduction of the 1.58-bit model variant fundamentally changes this balance. By constraining each parameter to be ternary, taking values in the set $\{-1, 0, 1\}$, the model reduces both capacity and bandwidth demands for the weights that must be repeatedly moved from DRAM to on-chip memory. Because the on-chip accelerator memory is exemplified by SRAM, a reduction in capacity and bandwidth requirements directly translates into the ability to lower SRAM size while maintaining throughput. This is a notable hardware implication: throughput improvements no longer require larger SRAM; instead, they can come from lowering the precision and redesigning the computation to minimize data movement and reduce arithmetic costs.

# The BitNet b1.58 Computation Paradigm

BitNet b1.58 introduces two complementary changes that jointly reduce the costs of inference. First, it defines a quantization function to restrict weights to $\{-1, 0, 1\}$. Second, it transitions the dominant arithmetic from floating-point to integer operations. These changes affect both the data that must be moved into SRAM and the operations performed once the data is on-chip.

The weight quantization uses an absmean scaling followed by rounding and clipping:
\[
\widetilde{W} = \mathrm{RoundClip}\left(\frac{W}{\gamma + \epsilon}, -1, 1\right),
\]
\[
\mathrm{RoundClip}(x, a, b) = \max\left(a, \min\left(b, \mathrm{round}(x)\right)\right),
\]
\[
\gamma = \frac{1}{nm}\sum_{ij} |W_{ij}|.
\]
This procedure yields ternary weights $\widetilde{W}\in\{-1, 0, 1\}^{n\times m}$. The inclusion of $0$ explicitly supports feature filtering, which the paper highlights as strengthening modeling capability relative to pure 1-bit variants. From a systems perspective, ternary weights drastically lower the number of bits required to represent parameters. When these lower-precision weights are fetched from DRAM and staged in the on-chip memory (e.g., SRAM), the bandwidth and capacity demands are proportionally reduced.

The activations in BitNet b1.58 are quantized to 8 bits, with a per-token scaling to the symmetric range $[-Q_b, Q_b]$. Unlike prior approaches that rely on zero-point quantization, this symmetric scaling eliminates the need to track a zero-point and simplifies implementation:
the activations are all scaled to $[-Q_b, Q_b]$ per token, and zero-point quantization is not used. The paper notes that this change is both convenient and simple for system-level optimization and has negligible performance impact in experiments. Together with ternary weights, INT8 activations facilitate replacing floating-point multiplications and additions with integer additions. In the BitNet architecture, the matrix multiplication only involves integer addition, which saves orders of energy cost. As the fundamental limit to compute performance in many chips is power, the energy savings can be translated into faster computation. This new computation paradigm is tightly connected to memory movement: when arithmetic is simpler and data is narrower, the need to stage large amounts of high-precision data in SRAM is reduced.

# Memory Capacity, Bandwidth, and SRAM

The paper directly contrasts SRAM and DRAM in the context of serving LLMs. While DRAM is used to store the full model parameters, SRAM serves as the on-chip accelerator memory that holds the weights and activations necessary for each step of inference. Attempts to enlarge SRAM are made to improve throughput by increasing the amount of data that can be staged on-chip, thereby reducing stalls caused by DRAM-to-SRAM transfers. However, such enlargement comes at a significantly higher hardware cost than DRAM. Thus, in full-precision LLMs, a tension arises: throughput demands suggest larger SRAM, but hardware cost constraints resist this.

BitNet b1.58 changes the calculus by reducing the memory footprint from both capacity and bandwidth standpoints. With ternary weights and INT8 activations, the size and the transfer requirements for both weights and activations are lowered. The paper explicitly states that this can significantly reduce the cost and time of loading weights from DRAM, leading to faster and more efficient inference. In practical terms, the reduced footprint means that the same throughput can be achieved with smaller SRAM, because the amount of data that must be staged on-chip per unit time is lower and the bandwidth requirement is reduced.

This implication is most visible at scale. The paper reports that the speed-up increases as the model size scales. Specifically, BitNet b1.58 at 70B parameters is $4.1$ times faster than the FP16 baseline, with memory consumption following a similar trend. The embedding remains full precision, but its proportion of overall memory is smaller for larger models, amplifying the benefits of low-bit linear layers. As the fraction of computation and data movement attributable to $\mathrm{nn.Linear}$ grows with model size, the advantage of ternary weights and INT8 activations increases. The net result is that the on-chip memory can be provisioned more modestly while achieving higher throughput relative to full-precision designs.

# Latency, Memory, and Scaling Trends

The reported results connect the computation paradigm to realized costs. BitNet b1.58 starts to match full precision baselines at 3B model size in terms of perplexity and end-task performance, while being $2.71$ times faster and using $3.55$ times less GPU memory. The 3.9B variant is $2.4$ times faster and consumes $3.32$ times less memory, yet performs significantly better than the 3B full-precision model. These improvements compound as the model size scales: at 70B, BitNet b1.58 achieves a $4.1$ times speed-up.

Memory consumption follows the same favorable trend because the most memory-intensive components shift from full precision to low-bit representations. From the perspective of SRAM, the staged activations and weights per operation are narrower, giving both capacity headroom and bandwidth relief. This directly supports maintaining or increasing throughput without the need to enlarge SRAM. Instead of increasing SRAM size to sustain throughput, the model design reduces the demands placed on SRAM.

The paper distills these trends into a new scaling law, offering equivalences between model sizes at 1.58-bit and 16-bit. For example, 13B BitNet b1.58 is more efficient, in terms of latency, memory usage and energy consumption, than 3B FP16 LLM; 30B BitNet b1.58 is more efficient than 7B FP16 LLM; and 70B BitNet b1.58 is more efficient than 13B FP16 LLM. This scaling law is compatible with the idea that lower precision reduces the need for large on-chip memory. As models grow, the main drivers of both compute and data movement increasingly favor low-bit designs, further diminishing the necessity of enlarging SRAM to achieve high throughput.

# Throughput and Practical Deployment

Throughput gains from BitNet b1.58 are demonstrated at large scale. On two 80GB A100 cards using pipeline parallelism, BitNet b1.58 with 70B parameters supports up to 11 times the batch size of a full-precision 70B model, resulting in $8.9$ times higher throughput at a sequence length of 512. These gains stem from reduced memory footprint and lower arithmetic costs.

When the memory footprint is reduced, more sequences can fit within the same GPU memory budget, enabling higher batch sizes without violating hardware constraints. Moreover, the reduction in data that must be loaded into on-chip memory per token lowers the pressure on bandwidth and staging. Combined with integer-only matrix multiplications, the end-to-end pipeline can sustain higher rates of token generation. In hardware terms, these throughput gains validate the strategy of reducing on-chip memory demands, such that smaller SRAM can still support high-throughput operation.

# Energy Composition and Its Relationship to Memory

The energy analysis in the paper focuses on matrix multiplication, which dominates the cost profile of LLMs. BitNet b1.58 is composed primarily of INT8 addition operations, whereas full-precision baselines rely on both FP16 addition and FP16 multiplication. According to the reported energy model, BitNet b1.58 saves $71.4$ times arithmetic operations energy consumption for matrix multiplication on 7nm chips. Furthermore, end-to-end energy cost for models with 512 tokens shows growing efficiency gains as model size increases, since the percentage of $\mathrm{nn.Linear}$ grows with the model size, while the cost from other components is smaller for larger models.

While this energy analysis is focused on arithmetic rather than memory, it complements the memory story. Chips are often limited by power, and when arithmetic energy drops, the system has more headroom to drive data movement and computation at higher speeds. This synergy means that the reduced memory footprint and lower arithmetic costs work together: less data is moved to SRAM, and the on-chip arithmetic is cheaper and faster. As a result, throughput can be maintained or increased without resorting to larger, more expensive SRAM.

# Hardware Implications and Future Directions

The paper calls for designing new hardware and systems specifically optimized for 1-bit LLMs, motivated by the new computation paradigm. In the present design landscape, Groq-like initiatives demonstrate the potential of specialized hardware for LLMs. BitNet b1.58 pushes further by suggesting that a hardware path tailored to low-bit arithmetic and low-bit memory movement could yield large benefits.

A key implication of the paper’s findings is that the on-chip accelerator memory is SRAM, and the reduced footprint of 1.58-bit LLMs enables maintaining throughput without enlarging SRAM. Since attempts to increase SRAM size introduce significantly higher costs than DRAM, the low-bit approach offers a way to meet throughput targets with smaller SRAM, reducing hardware cost. This is not merely an incremental tuning; it is a result of a principled shift in the model’s numerical representation and arithmetic. By rethinking weights as ternary $\{-1, 0, 1\}$ and activations as INT8 scaled to $[-Q_b, Q_b]$, the design alleviates bandwidth and capacity constraints on SRAM, enabling efficient inference at scale.

Finally, the paper discusses broader applications such as Mixture-of-Experts models and native support for long sequences. Both benefit from the reduced memory footprint. For MoE, lower memory consumption reduces the number of devices required and diminishes inter-chip communication overhead. For long sequences, reducing activations from 16 bits to 8 bits effectively doubles the supported context length given the same resources, and the paper suggests that this can be further losslessly compressed to 4 bits or even lower for 1.58-bit LLMs. These directions affirm the central theme: by reducing precision and adopting integer-only computation, the system-level constraints that previously mandated larger SRAM can be relaxed, preserving or even improving throughput while lowering hardware cost.

# Open‑Source Meets GPT‑4 on Mathematics

Mathematical reasoning is one of the toughest challenges for language models. Closed‑source giants such as GPT‑4 or Gemini Ultra routinely obtain scores above 70 % on the competition‑level **MATH** benchmark—a task that pushes multiple‑step symbolic deduction, algebraic manipulation, and problem solving to their limits. For an open‑source model at only **7 B parameters**, approaching such accuracy has been a long‑standing dream.

DeepSeekMath™ demonstrates that rigorous data curation and an efficient reinforcement learning strategy can bring a lightweight model into close proximity with these closed systems. In what follows we unpack how DeepSeekMath climbs past **50 %** on **MATH**, beating all publicly available baselines while still falling short of closed‑source performance by only a narrow margin.



## What is DeepSeekMath ?

DeepSeekMath is a *domain‐specific* instance derived from the large *DeepSeek-Coder* family. It is trained in three successive stages:

1. **Large‐scale mathematical pre‑training** on a newly curated corpus,
2. **Supervised instruction tuning** on problem–solution pairs spanning English and Chinese,
3. **Reinforcement learning** via *Group Relative Policy Optimization* (GRPO).

This pipeline yields three model checkpoints that address distinct use cases:

| Stage | Output | Purpose |
|-------|--------|---------|
| Pretrained base | **DeepSeekMath‑Base 7B** | Strong general reasoning + stable zero/few shot |
| Instruction tuned | **DeepSeekMath‑Instruct 7B** | Chat + chain-of-thought (CoT) responses |
| RL fine‑tuned | **DeepSeekMath‑RL 7B** | Highest benchmark scores |

All checkpoints are released under an open license, giving researchers direct access to a competitive mathematical backbone.



## The Math Pre‑Training Machine Triples

### A New Corpus Powered by Common Crawl

The core enabler is the **DeepSeekMath Corpus**—120 billion weighted tokens harvested purely from Common Crawl, not from proprietary datasets or large academic corpora like arXiv. The data pipeline follows these steps:

1. **Seed Selection** – Start from *OpenWebMath*, a clean set of web pages containing mathematical content.
2. **FastText Classifier** – Train a lightweight text classifier (256‐dimensional embeddings) twice iteratively:
   * First round trains positive examples from OpenWebMath against negative random CC pages.
   * Second round re‐samples mined sites that the classifier recognises as mathematical.
3. **Deduplication & Near‑Duplication Removal** – Reduce redundancy while keeping freshness; final web map ≈ 40 B HTML pages before filtering.
4. **Iterative Expansion** – Up to four rounds refine seed diversity via manual domain annotation—ensuring coverage beyond textbook language to include forums like *mathoverflow.net*.
5. **Decontamination** – Remove any passage that overlaps sub‐strings (≥ 10 grams) with popular benchmarks (GSM8K, MATH, CMATH).

Result:**35 M unique sites →120 B tokens**   This volume is roughly nine times larger than OpenWebMath alone and an order of magnitude bigger than many other publicly released math corpora.



### Why Web Data Beats ArXiv

Traditional science literature was once thought essential for deep mathematical understanding because most proofs live in arXiv PDFs or journal articles. In controlled experiments:

* A model trained only on arXiv-derived tokens (≈28 B) demonstrates flat or negative gains across GSM8K, MATH, and formal proof tasks.
* Adding ARXIV does not help but dilutes the signal when interleaved with well-curated web text in small models (<10 B).

The implication is straightforward—*high quality parsing* and *diverse linguistic styles* in web pages provide richer inductive biases than monolithic scientific prose.



## From Code to Math – Two–Stage Training Matters

DeepSeekMath regards coding as a natural precursor to formal reasoning:

| Training Regime | Token Split | Effect |
|-----------------|-------------|--------|
| Stage 1 400B code ‑ Stage 2 150B math | Code → Math TF | Strong baseline in both program-aided *(sympy)* and pure CoT tasks |
| Stage 1 400B general ‑ Stage 2 150B math | General → Math TF | Subpar mathematics after stage 2 compared with code prep |
| One-stage mixed codes + maths | —         | Easier catastrophic forgetting control |

The takeaway? Insertion biasing has material impact on reasoning even in small models; embedding programming examples makes symbolic manipulation more “natural” for transformer weights.



## Supervised Fine–Tuning – Crackling the Handshake Between Human Intent & Model Logic

The instruction tuning set contains ~776K examples covering:

* English prompts from GSM8K / MATH / MathInstruct,
* Chinese K–12 problems spanning 76 subtopics,
* All paired with chain–of–thought traces,
* Program-of–Thought codes (*Python*, `math`, `sympy`),
* Tool–integrated solutions leveraging built-in interpreter calls.

A single tuning epoch over this dataset already catapults performance into new territory.

## The Reinforcement Boost – Group Relative Policy Optimization (GRPO)

### From PPO’s Critic Overhead to Group Relative Baselines

Standard Proximal Policy Optimization relies on a memory-intensive value network alongside KL regularization—a mismatch for many token-level reward scenarios where only final sequence scores exist.\*

GRPO sidesteps this by replacing the critic entirely:

1. For each prompt `q` sample `G` outputs `{o₁,…,o_G}` under the current policy.
2. Score each output by a *learned reward model `r_ϕ`*
3.. Compute normalized advantage `\hat A_{i,t}` as `(rᵢ − mean)/(std)` or its stepwise variant if process supervision is used.
4.. Update policy using clipped surrogate loss plus direct KL penalty against a recent reference snapshot.

Owing to this architecture:
   * Memory is reduced by ≈80 %
   * Each group provides an empirically grounded baseline—no critic needed.



### Resulting Jump in Competitive Numbers

Applying GRPO over 144k chain-of-thought question prompts pulls results further:

| Task                   | Before GRPO (% Accuracy) | After GRPO (% Accuracy) |
|------------------------|--------------------------|-------------------------|
| GSM8K (CoT)            | 82⋅9 %                  | **88⋅2 %**              |
| MATH (Competition)     | 46⋅8 %                  | **51⋅7 %**              |
| CMATH / Gaokao parses   | ~84⋅6 %                  | ~88⋅8 %                 |

Notice all gains stem purely from RL—no new references nor extra supervised examples.

## Putting It All Together – Why It Works So Well

1. **Scale Matters So Long As Quality Matters Too**
   * The corpus represents more than sevenfold existing publicly available “math Web” data;
   * Rich multilingual coverage gives better cross-lingual generalization—it explains why Chinese phone tests improved substantially.
2. **Code + Math Mix Keeps Long-Term Dependencies Fresh**
   * The two-stage design ensures planners still retain programming heuristics essential for solving symbolic algebra quickly via Python wrappers.
3. **Greedy RL With Relative Baseline fixes “Misalignment”**
   * Rather than forcing all outputs into one shape, GRPO rewards relative quality within each question set—a natural way for humans evaluate multiple entries against a standard answer table (“Marcelo vs Gaia”).
   * Consequently top-k improvements dominate (*Maj@k*) whereas raw first-choice accuracy remains largely unchanged—an indicator of stronger consistency rather than raw comprehension boost.



## Open Questions & Where We Sneed Improvement Now  

While DeepSeekMath reaches ≈51 % accuracy on competitive mathematics at only seven billion parameters—a world record for open systems—it still lags GPT­4 by roughly five percent under all settings:

1. ***Geometry & Advanced Theory***  
   Even gpt-like models have strong geometric intuition because they see msic treatises such as Euclidean’s *Elements*. We suspect that our web corpus under-represented such narrative-rich expository texts—a deficiency unmasked during detailed benchmark profiling (*triangle/ellipse problems remain fragile*).

2. ***Few-Shot Nuance***  
   Developer NLP peers report giant models achieve >80 % under one-shot hints while our base remains capped near zero-shot levels (~35 %). Strengthening curriculum transfer within self-supervised stages may help cross-dimensional adaptation.

3. ***Reward Model Generality***  
   Grpo relies heavily on reward assignments computed by neural rewards evaluated once per sequence tip-only simulation—and there remains unseen drift when encountering sequences far outside previously seen difficulty levels (**out-of-domain OOD questions become “cold” states**).

Future explorations already under consideration are:

* Tree-search decoding during RL rollouts,
* Sub-sampling seeds across external geometry collections,
* Explicit few-shot pattern teaching in SFT,
* Robustness-adaptive reward learners capturing uncertainty.



## Takeaways for The Community  

> “Tiny models can become high-performing mathematically if you pair robust data curation with careful reinforcement.”  

DeepSeekMath demonstrates how two relatively inexpensive techniques—large-scale web MIsc identity sentences + GRPO—give rise to state-of-the-art results previously reserved for proprietary stacks.

By publishing both weights and code tooling we hope other researchers can adopt these influential building blocks toward alternative avenues such as:

\title{Blogs about the Paper: "FlashAttention-3: Fast and Accurate Attention with Asynchrony and Low-precision"}

# Why Attention Is the Real Bottleneck in Modern AI—and How FlashAttention-3 Speeds It Up

## Attention is where long-context models start to hurt

Transformers are built around attention. For one head, the core computation is

$$
\mathbf{S} = \alpha \mathbf{Q}\mathbf{K}^\top,\quad
\mathbf{P} = \mathrm{softmax}(\mathbf{S}),\quad
\mathbf{O} = \mathbf{P}\mathbf{V}.
$$

This looks simple, but it hides a serious scaling problem. If the sequence length is $N$, then $\mathbf{S}$ and $\mathbf{P}$ are both $N \times N$ matrices. That means attention gets more expensive very quickly as context grows.

That matters because modern AI keeps asking models to handle longer inputs: long documents, codebases, high-resolution images, audio, video, and long interaction histories. In all of those settings, attention becomes a bottleneck long before the rest of the model does.

The problem is not just arithmetic. On GPUs, the expensive part is often moving data around, not computing with it. A standard attention implementation writes intermediate matrices like $\mathbf{S}$ and $\mathbf{P}$ out to high-bandwidth memory and reads them back again. That is slow.

## FlashAttention made exact attention practical

FlashAttention changed the game by reorganizing attention so that the intermediate matrices never have to live in slow global memory. Instead, it tiles the computation and keeps the important pieces on-chip. The result is the same attention formula, just executed in a much more GPU-friendly way.

FlashAttention-2 improved on that by better parallelizing work across the sequence dimension and improving how blocks are handled. But on newer Hopper GPUs, the paper shows that there was still a lot of headroom left. In particular, FlashAttention-2 reaches only about 35% utilization on an H100 GPU, while highly tuned GEMM kernels can hit 80% to 90%.

FlashAttention-3 is about closing that gap.

## What FlashAttention-3 changes

FlashAttention-3 takes advantage of two Hopper features that earlier attention kernels do not fully exploit: asynchronous execution and FP8 low precision.

The basic idea is to treat attention less like one monolithic loop and more like a pipeline. Different parts of the GPU can do different jobs at the same time, so long as the software is organized to let them overlap.

### 1. Split the work between producer and consumer warps

On Hopper, memory movement and matrix multiplication are handled by specialized hardware units. FlashAttention-3 uses this by dividing warps into producers and consumers.

The producer warps move query, key, and value blocks into shared memory. The consumer warps do the matrix multiplications and softmax work. Because loading and computation are asynchronous, the two can overlap instead of waiting on each other.

This is a form of warp-specialization, and it helps hide memory latency. The implementation also uses Hopper’s ability to dynamically reallocate registers, so the warps doing the heavy computation can get more registers than the warps mainly responsible for data movement.

### 2. Overlap softmax with matrix multiplication

Softmax is a necessary part of attention, but it is much lower throughput than matrix multiplication. FlashAttention-3 takes advantage of that imbalance.

The key trick is to pipeline the work so that while one block is finishing its softmax, the next block is already being multiplied on the Tensor Cores. The paper describes this as a 2-stage overlap, and in practice it is a kind of “pingpong” schedule: one warpgroup computes while another warpgroup finishes the non-matmul work.

This matters because the softmax is not free. On H100, the paper notes that matmul throughput is enormous compared to special-function throughput, so if softmax is left on the critical path, it becomes a real performance limiter. By overlapping the two, FlashAttention-3 keeps the Tensor Cores busier.

The tradeoff is that this kind of pipelining uses more registers, so the implementation has to balance pipeline depth and tile size carefully.

### 3. Use FP8 when the hardware supports it

Hopper GPUs also support FP8 Tensor Cores, which roughly double throughput compared to FP16 or BF16. FlashAttention-3 adapts attention to use them.

That is not as simple as just switching data types. FP8 has stricter layout requirements, and attention has back-to-back GEMMs that want different memory layouts. FlashAttention-3 handles this with an in-kernel transpose and a few register permutations so the FP8 Tensor Core instructions can be used efficiently.

There is also an accuracy problem. FP8 has fewer bits, and attention often sees outlier values in large models. To reduce the damage, FlashAttention-3 uses two techniques:

- **Block quantization**, where each block gets its own scaling factor instead of using one scale for the entire tensor.
- **Incoherent processing**, where $\mathbf{Q}$ and $\mathbf{K}$ are multiplied by an orthogonal transform before quantization, which spreads out outliers without changing $\mathbf{Q}\mathbf{K}^\top$.

The paper follows the idea of using a product of random sign matrices and a Hadamard transform, which can be applied efficiently.

## What the benchmarks show

On an H100 SXM5 GPU, FlashAttention-3 delivers the kind of gains you would hope for from this hardware-aware redesign.

For FP16, the paper reports:

- **1.5--2.0$\times$ speedup** over FlashAttention-2 in the forward pass
- **1.5--1.75$\times$ speedup** in the backward pass
- Up to **740 TFLOPs/s**, which is about **75%** of the GPU’s theoretical maximum

For FP8, FlashAttention-3 reaches close to **1.2 PFLOPs/s**.

The paper also shows that the algorithmic changes matter on their own. In one ablation, adding warp-specialization and the GEMM-softmax pipeline improves performance from **570 TFLOPs/s to 661 TFLOPs/s** in a fixed FP16 setting.

On the accuracy side, FP16 FlashAttention-3 matches the numerical error of FlashAttention-2 and does better than standard attention because intermediate results are kept in FP32. For FP8, block quantization and incoherent processing make FlashAttention-3 **2.6$\times$ more accurate** than a baseline FP8 attention method using per-tensor quantization, especially in the presence of outlier features.

## Why this matters

The main lesson of FlashAttention-3 is that attention is not just a math problem. It is a hardware scheduling problem.

If you can keep data on-chip, overlap compute with movement, and match the algorithm to the GPU’s execution model, exact attention can get much faster without changing what the model computes. FlashAttention-3 pushes that idea further than before by explicitly using asynchrony and low precision in the kernel design.

The work is still Hopper-focused, and the paper notes some open directions, including better support for inference and persistent-kernel designs for FP8. But the direction is clear: attention is still the bottleneck, and there is still a lot of room to optimize it.

FlashAttention-3 shows that with the right software design, even a very mature part of the Transformer stack can keep improving.

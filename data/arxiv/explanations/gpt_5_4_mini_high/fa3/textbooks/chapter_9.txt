\title{A Textbook about the Paper: "FlashAttention-3: Fast and Accurate Attention with Asynchrony and Low-precision"}

Chapter 9: Making FP8 Accurate: Block Quantization and Incoherent Processing

# Sources of numerical error in FP8 attention

The paper’s FP8 setting uses the Hopper GPU’s low-precision Tensor Cores, which can nearly double throughput relative to FP16 or BF16. That speedup is attractive, but it comes with a cost: fewer bits mean less room to represent values accurately. In the paper’s discussion of FP8, the relevant format is e4m3, which uses only 3 bits for the mantissa and 4 bits for the exponent. Compared with FP16 or BF16, this gives the hardware much less precision, so small differences in scale can show up as noticeably larger numerical error.

In attention, this issue matters because the computation is not just a single matrix multiplication. The forward pass combines two GEMMs with a softmax in between, and the softmax is particularly sensitive to the magnitudes of its inputs. Even if the matrix multiplications themselves are accelerated in FP8, the values passed between stages must still be represented well enough that the final attention output remains reliable. The paper’s central point is that simply turning on FP8 is not enough; the low-precision format must be paired with a strategy for controlling quantization error.

The paper evaluates this directly by comparing against a reference implementation in FP64. To make the test realistic for large language models, it uses inputs with occasional outlier entries, generated from a distribution of the form $\mathcal{N}(0,1)+\mathcal{N}(0,100)\cdot \mathrm{Bernoulli}(0.001)$. This creates mostly ordinary values, but with a small fraction of much larger ones. That setup is important because the paper argues that these rare outliers are exactly the kind of values that make FP8 quantization difficult.

# Why per-tensor scaling can fail when tensors contain outliers

The baseline FP8 attention scheme discussed in the paper uses per-tensor scaling, meaning that a single scale factor is chosen for an entire tensor such as $\mathbf{Q}$, $\mathbf{K}$, or $\mathbf{V}$. This is simple and works reasonably well when all values in the tensor have comparable magnitudes. But once a tensor contains a few unusually large entries, that single scale must be chosen to accommodate them. As a result, the scale becomes too coarse for the many smaller values that make up the bulk of the tensor.

This is the core failure mode that the paper highlights. The presence of outliers in large models means that a tensor can have a few entries much larger than most others. If one scale factor has to cover everything, then the quantizer spends its representational capacity on the rare extremes, leaving less effective precision for the common case. In other words, the outliers dominate the scaling decision even though they are not representative of the tensor as a whole.

The paper connects this directly to large language models, where outlier features and activations are known to appear. In that setting, a quantization scheme that treats the entire tensor uniformly is likely to be too blunt. The key lesson is that for FP8 attention, accuracy depends not just on the bit-width itself, but on whether the scaling strategy respects the structure of the data. Per-tensor scaling does not, and the paper presents block quantization and incoherent processing as remedies.

# Block quantization at tile granularity

Block quantization replaces the single scale per tensor with one scale per block. In the paper, each of $\mathbf{Q}$, $\mathbf{K}$, and $\mathbf{V}$ is split into blocks of size $B_r \times d$ or $B_c \times d$, and each block is quantized separately. This is a much finer-grained approach than per-tensor scaling, because the scale is allowed to adapt to local variations in magnitude rather than being forced to serve the entire tensor at once.

The intuition is straightforward: if one part of a tensor contains outliers and another part does not, it is wasteful to use the same scale for both. By quantizing block by block, the scale can reflect the actual range of values in each portion of the tensor. This reduces the chance that a few large values will distort the representation of many smaller ones. The paper presents this as one of the main ways to make FP8 attention substantially more accurate.

What makes block quantization especially natural in FlashAttention-3 is that the algorithm itself already works on tiles. The attention computation is organized around blocks of the query, key, and value matrices, and the softmax is performed locally on these blocks rather than on a fully materialized score matrix. Because the algorithm is already tiled, the extra scale factors fit into the same block structure instead of forcing a separate global treatment. The paper notes that the score matrix blocks can be scaled to account for block quantization at no computation cost, which means the accuracy improvement comes from fitting the quantization scheme to the existing kernel structure rather than from adding a new expensive stage.

The paper also emphasizes that block quantization can be fused with an operation that already happens before attention, such as rotary embedding. Since rotary embedding is memory-bandwidth bound, incorporating the quantization step there does not introduce an additional slowdown. This is important because it shows that the higher accuracy of block quantization does not have to come with a runtime penalty. In the paper’s design, the blockwise representation is not just more accurate; it is also compatible with the performance goals of the kernel.

# Incoherent processing with random orthogonal transforms

Block quantization addresses where the scale is applied, but it does not change the underlying distribution of values. Incoherent processing adds a second idea: before quantization, the paper multiplies $\mathbf{Q}$ and $\mathbf{K}$ by the same random orthogonal matrix $\mathbf{M}$. Because $\mathbf{M}$ is orthogonal, it satisfies $\mathbf{M}\mathbf{M}^\top = I$, and therefore
$$
(\mathbf{Q}\mathbf{M})(\mathbf{K}\mathbf{M})^\top = \mathbf{Q}\mathbf{K}^\top.
$$
This means that, in exact arithmetic, the attention scores are unchanged.

The point of doing this is not to alter attention, but to alter how the values look to the quantizer. The paper describes this as “spreading out” outliers. Each entry of $\mathbf{Q}\mathbf{M}$ or $\mathbf{K}\mathbf{M}$ becomes a random sum of entries of $\mathbf{Q}$ or $\mathbf{K}$, so values that were concentrated in a few large coordinates are redistributed across the transformed representation. That redistribution makes the magnitudes more even, which in turn reduces quantization error.

This is why the method is called incoherent processing: it makes the data less aligned with the coordinate axes that the quantizer sees. If a tensor has a few extremely large features, those features can be problematic when quantization is done coordinate by coordinate. After the orthogonal mixing, the same information is still present, but it is no longer concentrated in the same way. The paper’s claim is not that this removes outliers, but that it makes their effect less damaging during FP8 quantization.

# Efficient constructions and fusion with earlier steps

A practical transformation would be too expensive if it required a dense matrix multiply. The paper therefore uses a structured construction: the random orthogonal matrix $\mathbf{M}$ is taken as a product of random diagonal matrices with entries $\pm 1$ and a Hadamard matrix. This allows the multiplication to be carried out in $O(d \log d)$ time rather than $O(d^2)$ time. The paper presents this as the key to making incoherent processing efficient enough to be useful inside the attention kernel.

The structured transform also interacts nicely with the rest of the FlashAttention-3 pipeline. The paper notes that the random orthogonal transform can be fused with rotary embedding at no extra computation cost. That means the mixing step does not need to become an isolated preprocessing pass. Instead, it can be folded into work that is already being done, which preserves the kernel’s efficiency while improving the quality of the FP8 representation.

In the kernel design, these choices matter because attention is already sensitive to memory traffic and instruction scheduling. Any accuracy technique that adds separate passes over memory would undermine the point of FlashAttention in the first place. By choosing a fast structured transform and by fusing it with nearby operations, the paper keeps incoherent processing compatible with the same performance-minded design that motivates FlashAttention-3 overall.

# How the two methods improve FP8 accuracy in the paper’s experiments

The paper evaluates these ideas by comparing FP8 FlashAttention-3 to a baseline FP8 attention implementation that uses per-tensor scaling. In the baseline, the matmul accumulator is kept in FP32 and the intermediate softmax results are kept in FP16, but the scaling is still done per tensor. Under the synthetic outlier distribution used in the experiments, that baseline suffers noticeably more numerical error than the proposed method.

With block quantization and incoherent processing, FP8 FlashAttention-3 is reported to be $2.6\times$ more accurate than the baseline FP8 attention with per-tensor quantization. The paper measures accuracy using root mean squared error against an FP64 reference, so the comparison is directly about how close the low-precision output is to a high-precision target. This result is the main empirical justification for the techniques in this chapter.

The broader message is that FP8 can be practical only if the kernel is designed to respect the structure of the data and the hardware at the same time. Block quantization uses the blockwise structure of FlashAttention to localize scaling decisions, and incoherent processing changes the coordinate system so that outliers matter less during quantization. Together, they let FlashAttention-3 preserve much more of the accuracy that naive FP8 would lose, while still benefiting from the speed of Hopper’s low-precision Tensor Cores.

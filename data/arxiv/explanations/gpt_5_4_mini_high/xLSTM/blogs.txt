\title{Blogs about the Paper: "xLSTM: Extended Long Short-Term Memory"}

# Why xLSTM Matters: The Surprising Return of LSTMs in the Age of Transformers

## LSTMs never disappeared — they just got overshadowed

Before Transformers became the default architecture for large language models, LSTMs were the workhorse sequence model. Their key idea was simple but powerful: keep a memory state, update it additively, and control that update with gates. That made them much better than vanilla recurrent networks at dealing with long sequences and vanishing gradients.

For years, LSTMs worked well on language generation, translation, handwriting, time series, reinforcement learning, and many other sequential tasks. But they also had clear limits. Standard LSTMs compress information into scalar memory cells, they process sequences step by step, and their gating is bounded in a way that can make it hard to revise earlier storage decisions. As model sizes and datasets grew, those limits started to matter more.

Then Transformers arrived with self-attention. Their big advantage was not just accuracy, but scalability: they could train efficiently in parallel and, at least for a while, scale better than recurrent models. That is why Transformers took over modern LLMs.

The xLSTM paper asks a very direct question: what happens if we keep the core LSTM idea, but fix the parts that make it struggle at scale?

## The main idea behind xLSTM

xLSTM is not just “an LSTM with more parameters.” It changes two fundamental pieces of the original design.

The first change is **exponential gating**. In a standard LSTM, gates use sigmoids, which keep values between 0 and 1. That is stable, but also restrictive. xLSTM replaces some of those gates with exponential activations, which gives the model more flexibility when deciding what to keep, overwrite, or forget. Because exponentials can blow up numerically, the paper adds normalization and a stabilization trick so the computation stays well-behaved.

The second change is the memory itself. Instead of relying only on a scalar cell state, xLSTM introduces two variants:

- **sLSTM**, which keeps a scalar memory but adds exponential gating and new memory mixing.
- **mLSTM**, which uses a **matrix memory** and a covariance-style update rule, making it much better at storing and retrieving key-value style information.

Both variants are then wrapped inside residual blocks and stacked into xLSTM architectures, just like modern deep LLMs are built from stacked residual Transformer blocks.

## sLSTM: better at revising what it remembers

The sLSTM is the more direct extension of the classic LSTM. It still has a scalar memory, but the new gating changes how memory gets updated and normalized. The paper’s motivation here is important: classic LSTMs can struggle when they need to revise an earlier storage decision.

A good way to think about this is a streaming search problem. Suppose the model is scanning a sequence and should keep the most relevant item seen so far. A standard LSTM may be too conservative or too weakly gated to replace an earlier memory with a better one. Exponential gating makes that update more expressive.

This matters for **state tracking** tasks, where the model must keep track of an evolving hidden state across a long sequence. The paper shows that sLSTM’s memory mixing helps on these kinds of problems, including formal-language tasks where the model has to maintain the right internal state rather than just memorize tokens.

## mLSTM: a bigger memory for key-value retrieval

The mLSTM goes further by turning the memory cell into a matrix. That lets it store richer associations than a scalar cell can. Instead of only preserving a compressed summary, it can store key-value pairs and retrieve values later using a query, much closer to an associative memory.

The paper uses a covariance update rule for this matrix memory. In simple terms, the model accumulates outer products of values and keys, so it can later recover stored information through matrix multiplication. This is closely related to fast weight ideas and bidirectional associative memory.

The big payoff is storage capacity. On tasks that require remembering many key-value pairs, mLSTM behaves much more like a powerful associative memory than a classical recurrent cell.

There is also an important systems angle here: mLSTM has no hidden-hidden memory mixing, so it can be reformulated in a parallel way. That makes it much easier to accelerate on GPUs than a fully sequential recurrent model.

## Why this is not just an academic tweak

What makes xLSTM interesting is that it addresses the three main reasons LSTMs fell behind:

First, it helps the model **revise storage decisions** instead of being stuck with weakly gated memory updates.

Second, it increases **memory capacity** with matrix memory instead of forcing everything into a scalar cell.

Third, it creates a path toward **better parallelization**, at least for the mLSTM variant.

In other words, xLSTM does not try to beat Transformers by copying them. It asks what an LSTM should look like if it were designed today for large-scale language modeling.

## What the experiments show

The paper tests xLSTM on a mix of synthetic tasks, long-context benchmarks, and large language modeling runs.

On synthetic tasks, the two variants show different strengths. The sLSTM helps with state tracking and formal-language style problems. The mLSTM does especially well on associative recall, where the model must store and retrieve many key-value pairs. On the Long Range Arena, xLSTM shows strong performance across the tasks tested.

The more important result is at language-model scale. On **15B tokens from SlimPajama**, xLSTM outperforms the compared Transformers, State Space Models, and recurrent baselines on validation perplexity.

The paper then scales up to **300B tokens** and evaluates models at 125M, 350M, 760M, and 1.3B parameters. Here, xLSTM again looks strong. It maintains low perplexity on longer contexts, even when the test context grows well beyond training length. In the paper’s validation and downstream-task evaluation, xLSTM is the best method in the vast majority of cases. On PALOMA’s 571 text domains, the mLSTM-only version performs better than Mamba on 568 domains, better than Llama on 486, and better than RWKV-4 on 570.

The scaling-law plots also matter. They suggest that xLSTM is not a one-off win at a fixed size, but a model family with favorable scaling behavior as parameters and data grow.

## The practical takeaway

The paper’s core message is not that Transformers are obsolete. They are not. The point is that LSTMs were limited by specific design choices, not by the recurrent idea itself.

xLSTM shows that if you give LSTMs better gating and better memory, they can compete with modern architectures at LLM scale. That is a big deal for two reasons.

First, recurrent models still have an advantage in settings where **constant memory** and **linear sequence processing** matter. The paper reports that xLSTM scales linearly in generation time, unlike Transformer decoding, which grows quadratically with context length.

Second, xLSTM may be useful outside text generation. The authors explicitly point to reinforcement learning, time series prediction, and physical-system modeling as areas where this kind of compressive, stateful memory could be valuable.

## The catch

The paper is also clear about the current limitations. sLSTM is not fully parallelizable because memory mixing makes it sequential. mLSTM is parallelizable, but its matrix memory is computationally expensive. The implementation is not fully optimized yet, and the authors note that better CUDA kernels and broader tuning could improve results further.

So xLSTM is not a solved problem. It is a strong proof of concept.

## Bottom line

xLSTM is interesting because it changes the story around recurrent networks. Instead of treating LSTMs as a historical stepping stone to Transformers, the paper treats them as a design space worth revisiting with modern tools.

That leads to a simple but important conclusion: LSTMs were not outdated because recurrence was fundamentally wrong. They were outpaced because their memory and gating were too limited. xLSTM suggests that once those limits are addressed, recurrent models can still be serious contenders for large-scale sequence modeling.



# Teaching AI to Change Its Mind: How xLSTM's Exponential Gating Fixes a Classic LSTM Weakness

LSTMs have always been good at one thing: carrying information forward through time. That is exactly why they were so useful before Transformers took over. But the paper behind xLSTM argues that classic LSTMs have a subtle weakness: they are often too cautious when they need to revise an earlier memory decision.

That matters in sequence tasks where the model should keep scanning and update its belief as better evidence arrives. The paper uses nearest-neighbor search as a simple example. If a later item in the sequence is more relevant than an earlier one, a vanilla LSTM may struggle to overwrite what it already stored. xLSTM’s answer is to change the gating mechanism itself.

## Why a standard LSTM is conservative

The core LSTM update is familiar:

$$
c_t = f_t c_{t-1} + i_t z_t, \quad h_t = o_t \psi(c_t).
$$

Here, $c_t$ is the memory cell, $z_t$ is the new candidate content, and the gates $f_t$, $i_t$, and $o_t$ decide what to keep, write, and expose.

In a classic LSTM, these gates are sigmoid outputs, so they are always between 0 and 1. That makes them safe and stable, but also limited. They can suppress information, but they cannot strongly amplify it. So when the model needs to say, “Actually, this later piece of evidence is much more important than the earlier one,” it only has bounded control over that decision.

The xLSTM paper frames this as an inability to revise storage decisions. In practice, this can hurt tasks where the right answer depends on changing state over time, not just accumulating it.

## What sLSTM changes

The sLSTM keeps the LSTM’s basic recurrent structure, but changes the gates. The key idea is exponential gating.

Instead of forcing the input gate to stay in $[0,1]$, xLSTM lets it be

$$
i_t = \exp(\tilde{i}_t),
$$

and the forget gate can also use an exponential form:

$$
f_t = \sigma(\tilde{f}_t) \quad \text{or} \quad f_t = \exp(\tilde{f}_t).
$$

This sounds like a small change, but it changes the behavior a lot. Exponential gates are not bounded above, so the model is no longer restricted to small, cautious updates. If a new piece of information should dominate, it can be given much larger weight.

To keep this from becoming unstable, sLSTM adds a second state:

$$
n_t = f_t n_{t-1} + i_t.
$$

This is the normalizer state. The hidden state is then formed as

$$
h_t = o_t \tilde{h}_t, \quad \tilde{h}_t = \frac{c_t}{n_t}.
$$

So instead of reading out the raw memory accumulation directly, sLSTM reads out a normalized version of it. That is the important trick. The cell state can keep integrating evidence with flexible, exponential weights, but the output remains scaled by the accumulated gate strength.

A good intuition is that the model is not just “writing memory.” It is also keeping track of how strongly that memory was written. The ratio $c_t / n_t$ makes the hidden state a normalized summary rather than an uncontrolled running sum.

## Why normalization is the difference between powerful and unstable

Exponential functions are useful because they give the model more dynamic range, but they can also explode numerically. That is the main engineering problem xLSTM has to solve.

The paper introduces a stabilizer state:

$$
m_t = \max(\log(f_t) + m_{t-1}, \log(i_t)).
$$

Using this, the gates can be rewritten into stabilized versions:

$$
i'_t = \exp(\log(i_t) - m_t), \quad
f'_t = \exp(\log(f_t) + m_{t-1} - m_t).
$$

The important point is that this is not a different model in function space. The paper shows that replacing the original gates with these stabilized forms does not change the output of the network or the gradients with respect to the parameters. It is the same computation, just rewritten in a numerically safer way.

That is a very LSTM-like idea: increase expressiveness without giving up control.

## Why this helps the model “change its mind”

With sigmoid gates, the model is always making relatively bounded updates. With exponential gating, it can assign much stronger relative weight to a new observation when needed. Combined with the normalizer state, that means the model can revise memory more aggressively without letting the state blow up.

This is exactly the kind of behavior the paper wants for tasks like state tracking and associative recall. On the synthetic tasks in the paper, xLSTM is designed to recover the right state when later evidence should override earlier evidence. On language modeling benchmarks, the paper reports strong results for xLSTM after scaling the architecture up and training on large token datasets.

So the contribution is not just “a bigger LSTM.” It is a more flexible memory update rule. The model can still remember over long spans, but it is less stuck with early decisions.

## The takeaway

The main insight behind sLSTM is simple: if you want a model to revise its memory, don’t force every write and forget decision into a sigmoid-sized box. Let the model use exponential gates, then normalize and stabilize the result so training stays well behaved.

That combination is what makes xLSTM interesting. It keeps the spirit of LSTM memory, but gives it a much more decisive way to update its mind.



# From Tiny Cells to Matrix Memory: How mLSTM Gives Recurrent Models More Brainpower

The big idea behind xLSTM is surprisingly simple: if a classic LSTM cell can remember useful things, what happens if we give it a much richer memory format? The paper’s answer is mLSTM, a variant that replaces the usual scalar cell state with a matrix memory. In plain terms, it turns the memory from a single compressed stream into a structured associative store, closer to a key-value notebook or a lookup table than a one-number summary.

That matters because a lot of sequence modeling is really about retrieval. The model sees a token now, stores something about it, and much later needs to pull back the right detail. Scalar memory can do this to a point, but it is easy to run out of room when the sequence contains many distinct associations, rare tokens, or long-range dependencies.

## From a summary cell to an associative memory

The original LSTM keeps a cell state $c_t$ and updates it with a forget gate and an input gate. That already helps with long-term dependency tracking, but the memory is still compressed into a small state that has to carry a lot of information.

mLSTM changes the storage format. Instead of storing a scalar or vector-like summary, it keeps a matrix $\mathbf{C}_t \in \mathbb{R}^{d \times d}$. Each step writes a key-value pair into that matrix using an outer product:

\[
\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top.
\]

You can think of this as writing an association directly into memory. The key $\mathbf{k}_t$ tells the model what kind of context it is seeing, and the value $\mathbf{v}_t$ is what should be remembered about it. The outer product creates a full matrix of interactions between the two, which is much richer than squeezing everything into a single scalar update.

Later, the model reads memory with a query vector $\mathbf{q}_t$:

\[
\tilde{\mathbf{h}}_t = \mathbf{C}_t \mathbf{q}_t \,/\, \max\{|\mathbf{n}_t^\top \mathbf{q}_t|, 1\}.
\]

The companion normalizer state $\mathbf{n}_t$ tracks how strongly the memory has been written to, so retrieval stays numerically stable. In the paper, mLSTM also uses exponential gates with stabilization, which makes the write and forget behavior more flexible without letting values blow up.

A good mental model is a notebook with columns for keys and values. A standard LSTM is like trying to keep the whole notebook compressed into a single note. mLSTM instead keeps a structured table of associations, so later queries have a better chance of finding the right entry.

## Why a matrix helps

The main advantage is storage capacity. A matrix can encode many pairwise relationships at once, while a scalar memory has to fold everything into a much smaller bottleneck. That is especially useful when the model needs to remember multiple items, revise earlier decisions, or keep track of rare events that do not appear often enough to be safely compressed away.

The paper makes this concrete with two kinds of tests.

On the Multi-Query Associative Recall task, the model must memorize many key-value pairs and retrieve them later. The authors scale this up to as many as 256 key-value pairs and contexts of length 2048. In that setting, xLSTM variants with matrix memory perform strongly, and xLSTM[1:1] is the best among the non-Transformer models. The interesting takeaway is that adding an sLSTM block does not reduce the memory benefit; the mixed architecture still handles the hard recall setting well.

The paper also motivates matrix memory through rare-token prediction. On Wikitext-103, performance is worse for rare tokens when the model has to compress everything into scalar memory. That is exactly the kind of case where a matrix-based state helps: the model has more room to preserve specific associations instead of collapsing them into a generic summary.

## Why this is still practical

A natural concern is that a $d \times d$ memory sounds expensive. That is true in terms of raw computation, but the design has a useful property: it is independent of sequence length. xLSTM keeps linear computation and constant memory complexity with respect to the context length, unlike the quadratic cost of standard attention.

mLSTM is also fully parallelizable because it removes the hidden-hidden memory mixing that makes classical recurrence hard to parallelize. The paper notes that the matrix update and retrieval are GPU-friendly, even if the current CUDA kernels are not yet fully optimized. In other words, the model trades more arithmetic per step for a much richer memory system, but it does not give up the scaling advantages of recurrence.

This matters in long-context language modeling. In the 300B-token experiments, the paper tests sequence lengths up to 16384 after training on 2048-token contexts. The xLSTM models keep low perplexity for longer contexts better than the comparison models, including Llama, Mamba, and RWKV-4. On the PALOMA benchmark, the mLSTM-only model xLSTM[1:0] is especially strong, beating Mamba on 568 of 571 text domains, Llama on 486, and RWKV-4 on 570.

The broader language-modeling results line up with that picture. On 15B SlimPajama training runs, xLSTM outperforms the comparison set in validation perplexity. On the larger 300B-token run, both xLSTM[1:0] and xLSTM[7:1] are among the best models across sizes, and the scaling curves suggest the advantage persists as models get bigger.

## The bigger lesson

mLSTM is not just “LSTM, but larger.” It is a different memory format. By moving from a tiny scalar cell to a matrix of associations, the model becomes much better at storing and retrieving the kind of information that sequence tasks actually need.

That shows up in associative recall, rare-token handling, and long-context language modeling. It also helps explain why xLSTM, despite being recurrent, can compete with Transformers and state space models in the paper’s experiments.

So the short version is this: if classical LSTMs were a compact notebook, mLSTM is a learned lookup table. That extra structure gives recurrent models a lot more room to think.



# Can Recurrent Models Be Fast Again? Inside xLSTM's Linear-Time Path Beyond Attention

Transformers won language modeling partly because they made large-scale training and inference practical on GPUs. But they also brought a familiar problem back into focus: sequence length is expensive. As contexts get longer, attention gets more costly, and serving long prompts can become a memory problem as much as a modeling problem.

The xLSTM paper asks a simple question with very practical consequences: what happens if we scale LSTMs with modern LLM design choices, while fixing the weaknesses that made classic LSTMs lose ground to Transformers? The answer is interesting from both a modeling and systems perspective. xLSTM keeps the recurrent, step-by-step structure, but it does so with linear computation and constant memory with respect to sequence length, and it introduces a version that can be parallelized on GPUs.

## Why xLSTM matters from a systems point of view

Classic LSTMs already had one major systems advantage: they process sequences sequentially with a compact state, rather than building a full attention map over the entire context. xLSTM keeps that advantage, but the paper argues that vanilla LSTMs had three big issues: they struggled to revise storage decisions, they compressed too much into scalar memory, and they were not easy to parallelize because of memory mixing.

xLSTM addresses those issues with two changes. First, it replaces standard gating with exponential gating plus stabilization. Second, it changes the memory structure itself. The result is not one model, but two related ones: sLSTM and mLSTM.

For deployment, this matters because the memory footprint does not grow with the input length. That makes xLSTM attractive for long-context inference, industrial serving pipelines, and edge settings where memory is tight and sequence length is unpredictable.

## Two variants, two trade-offs

The first variant, sLSTM, keeps the original scalar-memory spirit of LSTM, but changes how gates work. Input and forget gates can use exponential activations, and a normalizer state tracks gate strength so the model stays numerically stable. There is also a stabilizer state that lets the exponential gates be rewritten without changing the network output or the gradients. In the paper’s framing, this helps the model revise what it stores when a better match shows up later in the sequence.

sLSTM still uses memory mixing through hidden-to-hidden recurrence, so it is not fully parallelizable. That is the price of its expressiveness. The paper does note, however, that a custom CUDA implementation makes sLSTM less than two times slower than mLSTM.

The second variant, mLSTM, is built for throughput. Instead of a scalar cell state, it uses a matrix memory $\mathbf{C} \in \mathbb{R}^{d \times d}$. It stores key-value pairs with a covariance-style outer-product update,
\[
\mathbf{C}_t = \mathbf{C}_{t-1} + \mathbf{v}_t \mathbf{k}_t^\top,
\]
and retrieves values using a query vector. This is an associative memory design, and because it removes memory mixing, the recurrence can be reformulated in parallel.

That parallelizability is the key systems win. In the paper, mLSTM is described as parallelizable in a way that is analogous to FlashAttention or GLA, while still preserving recurrent state updates.

## Linear-time inference, constant memory, and GPU throughput

The most obvious advantage of xLSTM over Transformers is complexity with respect to sequence length. The paper emphasizes that xLSTM has linear computation and constant memory with respect to sequence length. In practice, that means the model state does not need to expand as you process more tokens.

This shows up clearly in generation. The paper reports linear scaling for xLSTM and the other recurrent models, versus quadratic scaling for Llama in their generation-time experiments. It also reports that xLSTM can use much higher batch sizes than Llama because of its constant memory footprint, which in turn gives it the highest throughput in the decoding experiment.

That is an important systems detail. Higher throughput is not just a benchmarking talking point; it is what makes a model easier to serve efficiently at scale. If you can keep memory usage bounded as context grows, you can often run larger batches, support longer prompts, and serve more requests on the same hardware.

## Does this come at the cost of quality?

The paper’s answer is no, or at least not in the way people might expect.

On 15B tokens from SlimPajama, xLSTM outperformed the compared methods in validation perplexity, including Transformers, State Space Models, and other recurrent baselines. On the larger 300B-token setup, xLSTM again performed strongly: the pure mLSTM variant and the mixed xLSTM stack were the best on validation perplexity across model sizes, and xLSTM was the best method on the vast majority of downstream tasks.

The paper also tests length extrapolation, training on a context length of 2048 and evaluating up to 16384. xLSTM maintained low perplexities for longer contexts, which is exactly the kind of behavior you want if you care about long-context serving.

So the systems story is not bought by sacrificing modeling quality. The architecture is designed to stay efficient while still being competitive at scale.

## The honest caveats

The paper is also clear about what is not solved yet. sLSTM remains sequential because memory mixing prevents full parallelization. mLSTM is parallelizable, but its $d \times d$ matrix memory and update are computationally expensive, and the current CUDA kernels are not fully optimized. The authors say the current mLSTM implementation is about four times slower than FlashAttention or the scan used in Mamba. They also note that forget gate initialization matters, and that more extensive optimization is likely needed to reach the model’s full potential.

That said, the direction is promising. The architecture gives you a real trade-off surface: sLSTM for richer memory mixing, mLSTM for parallelizable long-context processing, and stacked xLSTM blocks to combine them in one model family.

## Bottom line

If you care about long-context inference, fixed memory footprint, and serving efficiency, xLSTM is a serious reminder that recurrent models are not done.

The paper does not claim Transformers are obsolete. What it shows is more interesting: once you fix the old LSTM bottlenecks with exponential gating and better memory structures, you can get a recurrent model that is linear-time, constant-memory with respect to sequence length, GPU-friendly in its parallel form, and competitive with current Transformer and State Space Model approaches.

In other words: recurrent models may be fast again.



# Beyond the Hype: What xLSTM's Benchmarks Really Say About the Future of Language Models

For years, the story of sequence modeling has looked pretty settled: Transformers won language modeling, and recurrent networks were left behind. The xLSTM paper is interesting because it asks a very specific question: what happens if you scale LSTMs to modern LLM size, but also fix the parts that have held them back?

The short version is that xLSTM is not just an incremental tweak. The authors introduce two main changes: exponential gating, which makes it easier for the model to revise what it stores, and new memory structures, which come in two flavors. The sLSTM keeps a scalar memory and includes memory mixing, while the mLSTM replaces the scalar cell with a matrix memory and a covariance-style update rule, making it parallelizable. The real test is not whether these ideas sound neat, but whether they help on actual benchmarks.

## The synthetic tests: does xLSTM really track state?

The first set of experiments checks whether xLSTM can handle tasks that require remembering and updating internal state over time. These are not glamorous benchmarks, but they are useful because they isolate specific capabilities.

One of the key takeaways is that memory mixing matters. The paper evaluates formal language tasks, including parity-like problems that are hard for models that cannot revise state as new tokens arrive. According to the results, models such as Transformers and state space models without memory mixing struggle here, while xLSTM is able to solve these tasks. That is a strong signal that the new gating and memory-mixing design are doing something real, not just adding parameters.

The second synthetic test is Multi-Query Associative Recall, where the model has to memorize key-value pairs and later retrieve the right value from a query. This is a direct test of memory capacity. Here, xLSTM's matrix-memory variant performs especially well. In fact, xLSTM[1:1] is the best among the non-Transformer models tested, and the paper notes something subtle but important: adding an sLSTM block does not reduce memory capacity, and may even help on the hardest version of the task.

The Long Range Arena results tell a similar story. xLSTM is reported to be consistently strong across the different long-context tasks, which suggests that the architecture is not just solving one narrow benchmark.

## The 15B-token language modeling run: does it beat modern baselines?

The next question is closer to what people usually mean by “language model performance.” The authors train xLSTM and a set of strong baselines on 15B tokens from SlimPajama and compare validation perplexity. Perplexity is the key metric here: lower is better, and it means the model is doing a better job predicting the next token.

At this scale, xLSTM outperforms all of the existing methods they compare against, including Transformers, state space models, recurrent baselines, and linear-attention variants. The comparison includes models such as GPT-3, Llama, Mamba, RWKV variants, GLA, HGRN, RetNet, and Hyena. In other words, xLSTM is not just beating old RNNs; it is competing against the architectures that have dominated modern language modeling.

The scaling curves are also important. A single win at one model size can be misleading, but the paper reports that xLSTM scales favorably and maintains its advantage as the model size changes. That matters because a better scaling trend is usually a better sign than a one-off benchmark bump.

## The 300B-token runs: does the advantage survive at real LLM scale?

This is the part of the paper that matters most if you care about xLSTM as a serious large language model architecture. The authors train models from 125M up to 1.3B parameters on 300B tokens from SlimPajama, then test them on several axes: long-context extrapolation, validation perplexity, downstream reasoning tasks, PALOMA, and scaling laws.

The long-context result is one of the clearest wins. All models are trained with context length 2048 and then evaluated on contexts up to 16384. xLSTM maintains low perplexity at longer contexts better than the other models in the comparison. That is a practical result, not just a theoretical one: models that degrade sharply with longer contexts are much harder to use in real systems.

On validation perplexity, the story is very strong for xLSTM. The paper reports that xLSTM[1:0] and xLSTM[7:1] are the best models across all model sizes in this setting. In the paper’s notation, xLSTM[1:0] means all mLSTM blocks, while xLSTM[7:1] mixes in a small number of sLSTM blocks. This is a nice example of the architecture trade-off showing up in the results: different mixtures of the two block types can be better for different tasks.

For downstream reasoning tasks, xLSTM is again usually the best model. The paper says it wins on the vast majority of tasks across all model sizes, with Mamba occasionally taking the lead on ARC. So the result is not “xLSTM wins absolutely everything,” but it is strong enough to put it in the same conversation as the best current alternatives.

PALOMA adds another useful angle. This benchmark spans 571 text domains, from news to Reddit communities, and measures next-token prediction across a wide range of styles. Here, xLSTM[1:0] is especially strong. It achieves lower perplexity than Mamba on 568 of 571 domains, than RWKV-4 on 570 of 571, and than Llama on 486 of 571. It also does better than xLSTM[7:1] on these language tasks, which suggests that the pure mLSTM variant may be the better fit for text prediction in particular.

The scaling-law results are also encouraging. All models follow similar power-law trends, but xLSTM has a better offset than Mamba, Llama, and RWKV-4. That does not prove it will always win at every scale, but it does suggest the architecture is not hitting an obvious ceiling.

## Speed and memory: where xLSTM fits in practice

One reason recurrent models have stayed interesting is efficiency. xLSTM keeps the main recurrent advantage: its computation is linear in sequence length, and its memory usage stays constant with sequence length. That is very different from standard Transformer attention, which becomes more expensive as the context grows.

The paper’s generation-time measurements reflect this. xLSTM and the other recurrent models scale linearly, while Llama shows the expected quadratic behavior. Because xLSTM uses constant memory, it can also use much larger batch sizes in decoding, which helps throughput.

But there are still practical trade-offs. The paper is explicit about them:

- sLSTM is not parallelizable because memory mixing introduces sequential dependence.
- The current mLSTM CUDA kernels are not fully optimized and are still slower than FlashAttention or the scan used in Mamba.
- The matrix memory is computationally expensive because it operates on $d \times d$ state.
- Forget-gate initialization has to be handled carefully.
- The models were not fully architecture-tuned or hyperparameter-tuned, especially at larger scales.

So while xLSTM is promising, it is not yet a free lunch.

## The bottom line

The headline result is not that xLSTM magically replaces Transformers. It is more interesting than that. The paper shows that if you fix the main weaknesses of LSTMs, add modern stabilization, and scale them properly, they can compete with the best current language model families.

The strongest evidence comes from the combination of results rather than any single benchmark: xLSTM handles synthetic state-tracking tasks, performs well on long-context evaluations, scales favorably on large language modeling runs, and matches or beats strong baselines on validation perplexity and downstream tasks.

If the remaining implementation and optimization issues are improved, xLSTM looks less like a historical curiosity and more like a real alternative path for large language models.

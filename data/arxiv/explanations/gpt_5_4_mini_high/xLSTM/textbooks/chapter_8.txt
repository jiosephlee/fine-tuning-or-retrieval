\title{A Textbook about the Paper: "xLSTM: Extended Long Short-Term Memory"}

Chapter 8: From Cells to Networks: xLSTM Blocks and Deep Residual Architectures

# Why Modern Language Models Rely on Residual Stacking

The paper does not present sLSTM and mLSTM as isolated recurrent cells that are used one at a time. Instead, it places them inside residual blocks and then stacks those blocks into full architectures. This matters because the paper’s goal is not just to build a better memory cell, but to build a language model that can be scaled to the size of modern large models. Residual stacking is the organizing principle that makes that possible: the model is assembled from repeated building blocks, each of which contributes a refinement to the representation.

This design choice follows the same pattern that made deep convolutional networks and Transformers successful. In the paper’s terms, xLSTM architectures are built by residually stacking xLSTM blocks. That means the unit of design is not just the memory mechanism itself, but the memory mechanism plus the surrounding block structure that makes it fit into a deep network. The result is a model family that can grow in depth while keeping the recurrent memory ideas at its core.

# Pre-LayerNorm Residual Backbones

The paper states that xLSTM uses the most commonly used pre-LayerNorm residual backbones, as in contemporary large language models. In other words, xLSTM does not introduce a completely new deep-network scaffold. Instead, it adopts the standard backbone style that has become familiar in modern language modeling and then places its recurrent blocks inside that framework.

This matters because the backbone determines how the model is organized as a whole. The recurrent module is therefore not the entire network; it is one component inside a larger residual system. The paper’s architecture is built so that the xLSTM blocks can be stacked in the same way other modern language models are stacked. That is what allows the authors to talk about xLSTM not merely as an LSTM variant, but as a language-model architecture.

# Cover’s Theorem and the Value of Nonlinear Summaries in Higher Dimensions

A central architectural idea in the paper is that xLSTM blocks should non-linearly summarize the past in a high-dimensional space so that different histories or contexts become easier to separate. This is where Cover’s theorem comes in. The theorem, as used in the paper, says that non-linearly embedded patterns are more likely to become linearly separable when they are lifted into a higher-dimensional space than when they remain in the original space.

The paper uses this idea as a motivation for block design in language modeling. If a model must predict the next token, it has to distinguish between different past histories that may look similar at first glance but imply different futures. The block should therefore produce a representation in which those histories are better separated. In this sense, the higher-dimensional projection is not just an implementation detail. It is part of the mechanism by which xLSTM tries to make sequence history easier to use for prediction.

# Post Up-Projection Residual Blocks for sLSTM

For sLSTM, the paper uses a residual block with post up-projection. The order here is important. The paper describes this block as one that non-linearly summarizes the past in the original space, then linearly maps into a high-dimensional space, applies a non-linear activation function, and then linearly maps back to the original space. This is the block style the paper associates with Transformers, and it is the one used for sLSTM.

This choice fits the role of sLSTM within xLSTM. The sLSTM is the version with scalar memory, a scalar update, and memory mixing. It keeps the LSTM idea of storing and revising information over time, while the surrounding residual block gives that memory a place inside a modern deep architecture. The paper also notes that sLSTM can use multiple memory cells, and can have multiple heads without memory mixing across heads, but with memory mixing across cells within each head. Together with exponential gating, this establishes a new way of memory mixing.

# Pre Up-Projection Residual Blocks for mLSTM

The mLSTM uses the other block design: pre up-projection. Here the paper’s ordering is reversed. The input is first linearly mapped to a higher-dimensional space, then the model non-linearly summarizes the past in that higher-dimensional space, and then it linearly maps back to the original space. The paper describes this as the block style used for state space models.

The reason given in the paper is straightforward: for mLSTM, the memory capacity becomes larger in the high-dimensional space. That fits the broader idea behind mLSTM itself, which replaces the scalar cell state with a matrix memory and uses a covariance-style update rule. Since the memory is already richer than in the scalar case, the architecture benefits from doing the summarization after the expansion to a larger internal space. The result is a block that matches the matrix memory’s greater storage capacity with a correspondingly larger working space.

# Why the Paper Pairs sLSTM with Post Up-Projection and mLSTM with Pre Up-Projection

The pairing is not arbitrary. The paper deliberately assigns post up-projection to sLSTM and pre up-projection to mLSTM. sLSTM is the variant that preserves memory mixing, so it is embedded in a Transformer-like residual block that first processes information in the original space and then expands it. mLSTM, by contrast, is designed for larger memory capacity and parallelization, so it is placed in the block structure that first expands the representation and then applies the recurrent summary there.

The paper also emphasizes an important asymmetry between the two variants. For mLSTM, multiple heads and multiple cells are equivalent because there is no memory mixing. For sLSTM, heads and cells behave differently: memory mixing can occur across cells within each head, but not across heads. This makes the two variants structurally distinct, and the block designs reflect that distinction. In short, the paper pairs the block order with the kind of memory each variant is meant to support.

# Combining Recurrent Memory Modules with Feedforward Transformations

One of the most important architectural ideas in the paper is that recurrent memory is not used by itself. Instead, it is combined with linear projections that move information between the model dimension and a higher-dimensional internal space. The block therefore mixes temporal storage with feedforward transformation. This is how the paper turns a memory cell into a modern deep-learning building block.

This combination matters because it allows xLSTM to behave like a residual module rather than like a standalone recurrent network. The recurrent core keeps track of sequence history, while the surrounding projections and non-linear transformation give the block a way to reshape that history into a form that can be stacked and reused. The paper’s design goal is not simply to remember more, but to remember in a way that supports separation of contexts and next-token prediction.

# Constructing Full xLSTM Architectures by Stacking Blocks

An xLSTM architecture is built by stacking xLSTM blocks residually. This is the point where the paper moves from a single recurrent module to a full language model. The architecture is therefore modular: one chooses the kind of block, places it inside a residual backbone, and then repeats that block many times. The paper explicitly frames xLSTM architectures as the result of residually stacking the new LSTM variants.

This makes the model family flexible. Different networks can contain different mixtures of sLSTM-based and mLSTM-based blocks, while still sharing the same overall backbone style. The paper uses this modularity to assemble models at language-model scale. In other words, the architecture is not a one-off design; it is a template for building larger systems from the same kinds of parts.

# Interpreting xLSTM[$a:b$] Ratios of mLSTM-Based to sLSTM-Based Blocks

To describe how many blocks of each type appear in a model, the paper uses the notation xLSTM[$a:b$], where $a/b$ is the ratio of mLSTM-based blocks to sLSTM-based blocks. This notation is useful because it gives a compact description of the architecture’s composition at scale. It tells you not just how many blocks there are, but how the two memory mechanisms are distributed throughout the network.

The paper gives a concrete example: xLSTM[$7:1$] means that out of eight blocks, seven are mLSTM-based and one is sLSTM-based. If the total block number is $48$, that corresponds to $42$ mLSTM-based blocks and $6$ sLSTM-based blocks. The notation xLSTM[$1:0$] would mean an all-mLSTM model, while xLSTM[$0:1$] would mean an all-sLSTM model. This ratio notation becomes especially important when the authors compare different mixtures in their experiments.

# Design Patterns for Scaling xLSTM to Language-Model Size

The paper’s scaling strategy is to keep the basic architecture fixed in spirit while increasing its size through residual stacking and block composition. The same pre-LayerNorm residual backbone is used as the scaffold, and the same distinction between post up-projection for sLSTM and pre up-projection for mLSTM is maintained across experiments. The model can then be scaled by changing the number of blocks and by adjusting the ratio of mLSTM-based to sLSTM-based blocks.

This modular design is what makes xLSTM suitable for language-model scale. The paper emphasizes that xLSTM networks have linear computation and constant memory complexity with respect to sequence length, unlike Transformers. That makes the architecture attractive not only for scaling depth and parameter count, but also for handling long contexts. In the paper’s experiments, this same design is used to build models of different sizes, showing how the architecture can be expanded into full language models without changing its basic structure.

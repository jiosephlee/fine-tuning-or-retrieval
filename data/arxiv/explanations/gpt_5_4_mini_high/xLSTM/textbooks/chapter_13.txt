\title{A Textbook about the Paper: "xLSTM: Extended Long Short-Term Memory"}

Chapter 13: Limitations, Open Problems, and Future Directions

# Why sLSTM remains harder to parallelize than mLSTM

The paper draws a sharp distinction between the two new xLSTM variants: sLSTM keeps memory mixing, while mLSTM removes it. This difference is exactly why sLSTM is harder to parallelize. In sLSTM, the hidden state at time $t$ depends on the previous hidden state, and that hidden state is itself part of the gate computations at the next step. In other words, the network contains hidden-hidden recurrent connections that force a step-by-step sequence of computation. Even though the model is organized into residual blocks, the internal recurrence still creates a strictly sequential dependency across time.

The reason the authors keep this sequential structure is that it buys them a new form of memory mixing. The paper emphasizes that sLSTM can have multiple memory cells, and that its recurrent connections allow the hidden state to influence the cell input and the gates. This is not just an implementation detail; it is part of the model’s expressivity. The same section that explains the parallelizability trade-off also argues that memory mixing is important for state tracking problems. So sLSTM represents a deliberate choice: it sacrifices full parallel execution in exchange for richer recurrent interaction.

mLSTM makes the opposite choice. It abandons memory mixing entirely, which is what enables its recurrence to be reformulated in a parallel version. This shows the central architectural trade-off in xLSTM. If the goal is maximum parallelism, recurrence has to be simplified. If the goal is richer sequential reasoning, recurrence can keep memory mixing, but that makes it inherently harder to execute in parallel. The paper’s design therefore does not treat parallelization as an absolute property of “LSTM-like” models, but as something that depends on how the memory is structured.

# Current CUDA kernel limitations and optimization opportunities

The paper is explicit that implementation quality still matters a great deal for xLSTM. For sLSTM, the authors report a fast CUDA implementation with GPU memory optimizations down to the register level, and they say it is typically less than $2$ times slower than mLSTM. That is a strong result, but it also shows that the sequential nature of sLSTM still carries a runtime cost. The kernel work is therefore part of the model design, not a separate engineering afterthought.

The mLSTM side also leaves room for improvement. The paper states that the current CUDA kernels for mLSTM are not optimized and that the implementation is about $4$ times slower than FlashAttention or the scan used in Mamba. Importantly, this slowdown is not presented as a fundamental property of the model itself. Instead, the authors frame it as an optimization gap: because mLSTM is parallelizable and uses standard matrix operations, faster kernels could plausibly be developed in the spirit of FlashAttention.

This makes the current implementation status itself a research direction. The paper suggests that xLSTM’s favorable modeling results may become even more compelling if the kernels are improved. The underlying architecture already has attractive sequence-length scaling, but the actual wall-clock benefit depends on how efficiently the recurrence is implemented on hardware. That means future work is not only about changing the mathematics of the model; it is also about making the model computationally competitive in practice.

# The computational burden of matrix memory in mLSTM

The key idea behind mLSTM is that the scalar cell state of the original LSTM is replaced by a matrix memory $\mathbf{C} \in \mathbb{R}^{d \times d}$. This is what gives mLSTM its stronger storage capacity. Instead of compressing everything into a scalar memory, it can store key-value associations through a covariance update rule of the form $\mathbf{C}_t = \mathbf{C}_{t-1} + \mathbf{v}_t \mathbf{k}_t^\top$. The retrieval step then uses a query vector and a matrix multiplication. This is a very different memory system from the original LSTM, and the paper presents it as the reason mLSTM handles associative recall better.

The cost of this richer memory is computational. A matrix state of size $d \times d$ is much more expensive to process than a scalar cell state, because every update and retrieval touches all of those entries. The paper is careful to describe this as a trade-off between memory capacity and computational complexity. The memory does not introduce additional parameters, which is an important point, but it does increase the amount of computation that must happen at each step.

At the same time, the paper also explains why this cost is not as severe as it might first appear. Because the mLSTM recurrence has no memory mixing, it can be parallelized with standard matrix operations on GPUs. That means the computational burden is real, but it is also a burden that hardware is relatively well suited to handle. The open question for future work is how far that trade-off can be pushed: how much storage capacity can be gained per unit compute, and how much more efficient can the matrix-memory implementation become with better kernels and better parallelization strategies.

# Sensitivity to forget-gate initialization

One of the limitations listed in the paper is that the forget gates must be chosen carefully. This is a practical issue, but it is also conceptually important because the forget gate controls how much of the past is retained from one step to the next. In both the original LSTM and xLSTM, the forget gate is part of the mechanism that decides whether the model preserves information or overwrites it. If that choice is badly initialized, the model can begin training in a regime where memory is either too short-lived or too persistent.

The issue matters even more in xLSTM because the paper introduces exponential gating together with stabilization. The forget gate is not just a scalar multiplier in a recurrence; it is part of a system that also includes a normalizer state and, in the stabilized formulation, a stabilizer state $m_t$. The paper’s warning that forget-gate initialization requires care indicates that training dynamics can be sensitive to how these gates start out. In other words, xLSTM is not only about a better memory structure; it is also about getting the gate behavior into a useful operating range.

The paper does not give a universal initialization recipe, and that absence is itself an open problem. A natural next step is to identify initialization choices that work robustly across model sizes, block types, and tasks. Since the paper reports scaling experiments across $125$M to $1.3$B parameter models and across different mixtures of sLSTM and mLSTM blocks, the fact that gate initialization still appears as a limitation shows that training stability remains an important part of the design space.

# Possible memory overload at much longer context lengths

The paper’s discussion of long contexts is optimistic, but it is not unconditional. It notes that the matrix memory of mLSTM is independent of sequence length, yet also cautions that increasing the sequence length might overload the memory at much longer context sizes. This sounds subtle, but the idea is straightforward: a fixed-size memory can be extremely useful, but it can still be stressed if the amount of information that must be represented becomes too large or too dense.

The experiments reported in the paper do not show this problem up to the tested lengths. In particular, the authors report favorable extrapolation to contexts as long as $16{,}384$ tokens in their sequence-length experiments. So the overload issue is not an observed failure at the scale they study. Rather, it is a forward-looking limitation that becomes relevant when thinking about contexts even longer than those used in the experiments.

This creates a clear research direction. One question is whether the current matrix memory design continues to work for substantially longer sequences without modification. Another is whether larger memory dimensions, different mixes of sLSTM and mLSTM blocks, or other architectural changes can delay or prevent overload. The paper does not settle these questions, but by explicitly naming the limitation it points to where the next empirical tests should go.

# The role of incomplete architecture and hyperparameter tuning

The paper is unusually direct about the fact that its models were not fully optimized. Because the experiments are computationally expensive, the authors say they did not fully optimize the architecture or the hyperparameters, especially for larger xLSTM models. That matters because strong reported results are not necessarily the final word on the architecture’s best possible performance. Instead, they should be read as evidence that xLSTM is already competitive even before exhaustive tuning.

This limitation is also what makes the results scientifically interesting. If a model performs well without full optimization, then there may still be additional gains to be found through more careful search over design choices. The paper already explores different mixes of mLSTM and sLSTM blocks, such as xLSTM[1:0] and xLSTM[7:1], but it does not claim that the best possible mixture has been found for every setting. Similarly, the residual-backbone choices and gate settings are presented as part of the architecture, not as final optimized solutions.

The practical implication is that xLSTM should be viewed as a promising starting point rather than a closed design. Future work can systematically explore architectural ratios, training settings, and larger-scale configurations. Since the paper’s scaling-law results suggest that xLSTM continues to improve with scale, the lack of full tuning leaves open the possibility that optimized xLSTM systems could perform even better than the reported models.

# What the paper’s conclusions imply about the future of recurrent LLMs

The paper’s conclusion is deliberately cautious but clearly optimistic. The authors say they have at least answered their opening question up to the level of “current technologies like Transformers or State Space Models.” That is a strong statement: it means recurrent models are no longer restricted to being historical predecessors of Transformers. With exponential gating and new memory structures, xLSTM is presented as a serious current competitor in language modeling.

The empirical scaling results support that conclusion. The paper reports favorable behavior as model size increases, and it uses those scaling laws to argue that larger xLSTM models will remain competitive with state-of-the-art Transformer-based large language models. This does not mean the Transformer story is over. Rather, it suggests that the design space for large language models is broader than it appeared after the rise of self-attention. Recurrent models, when updated with modern techniques, remain viable at scale.

The paper also points out an additional advantage: xLSTM has linear computation and constant memory complexity with respect to sequence length. That makes it attractive not only as a language model, but also as a system that could be deployed more efficiently in settings where long sequences matter. The future implied by the paper is therefore not a return to old LSTMs, but a new class of recurrent large language models that compete on performance while preserving the efficiency advantages of recurrence.

# Potential applications beyond language modeling, including reinforcement learning, time series, and physical systems

Although the experiments focus on language modeling, the paper’s introduction and conclusion both suggest broader applications. The authors note that LSTMs have already been successful in reinforcement learning, time series prediction, and modeling physical systems, and they explicitly say that xLSTM has the potential to impact these areas as well. This is a natural extension of the paper’s results, because the new model is built to improve long-range memory and sequential state tracking, which are precisely the kinds of abilities that matter in those domains.

The paper’s earlier examples help explain why these applications are plausible. It mentions sequence-based reinforcement learning systems such as AlphaStar and OpenAI Five, as well as hydrological and physical modeling tasks. These are all settings where the model must retain and update state over time, often under long and noisy sequences. Since xLSTM improves both memory capacity and the ability to revise storage decisions, it is reasonable to expect that it may be useful in similar problems outside language.

Still, the paper does not claim these applications have already been solved. Instead, it presents them as opportunities. The open direction is to test whether xLSTM’s combination of exponential gating, state tracking, and matrix memory transfers well to these fields. In that sense, the broader significance of xLSTM is not limited to text generation. It may become a general-purpose recurrent architecture for dynamic and sequential domains.

# Open theoretical questions about expressivity, compression, and scaling in recurrent models

The paper gives empirical evidence that xLSTM works better than prior recurrent, linear-attention, and state-space alternatives on the tested benchmarks. But it also raises deeper theoretical questions that are not resolved by experiments alone. One of the most important is expressivity: the paper argues that memory mixing enables state tracking and makes LSTMs more expressive than State Space Models and Transformers in certain settings. That is a powerful claim, but it invites a formal answer. What exactly do exponential gating and memory mixing allow the model to represent that simpler recurrence schemes cannot?

A second open question concerns compression. The original LSTM compresses information into scalar memory cells, while mLSTM uses a matrix memory to store richer associations. The paper shows that this improves performance, especially on tasks that require retrieving key-value pairs or handling rare tokens. But how much information can each memory form really retain, and how does that capacity change as the model scales? The paper suggests a qualitative answer, but not a complete theory.

A third question is how empirical scaling laws relate to recurrent architecture design. The authors show that xLSTM improves with scale and appears likely to remain competitive at larger sizes, but the paper does not derive the scaling behavior from first principles. Likewise, the use of Cover’s theorem as a motivation for residual block design provides intuition rather than a formal guarantee. So the broader theoretical challenge is to connect architecture, memory structure, and scaling in a way that predicts when recurrent models should outperform other sequence models.

Taken together, these questions show that xLSTM is more than a practical model proposal. It is also a framework for rethinking what recurrent networks can do when they are scaled up and modernized. The paper’s limitations do not weaken that message; they sharpen it by showing exactly where future theory and engineering are still needed.

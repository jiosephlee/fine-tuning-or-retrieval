\title{A Textbook about the Paper: "xLSTM: Extended Long Short-Term Memory"}

Chapter 4: A Common xLSTM Ingredient: Exponential Gating, Normalization, and Stabilization

The first major change introduced by xLSTM is not a new memory cell by itself, but a new way of controlling how memory is written, forgotten, and safely kept numerically stable. In the original LSTM, the gates are sigmoid-based and therefore bounded between $0$ and $1$. xLSTM keeps the additive recurrent memory update that made LSTMs effective, but it replaces the usual bounded update gating with positive exponential gating and then adds normalization and stabilization so that the model remains trainable at scale. This shared ingredient appears in both sLSTM and mLSTM, even though the two variants differ in how their memory is structured.

The paper’s motivation is straightforward: bounded gates are useful, but they also make the model conservative about revising storage decisions. xLSTM is designed to be more flexible about how strongly it writes and how strongly it keeps information, while still preserving the recurrent structure that makes memory useful in the first place. The rest of this chapter explains how the paper accomplishes that, and why the normalization and stabilization steps are not optional extras but essential parts of the design.

# Why replace sigmoid-style update gating with exponential gating

The original LSTM update rule is built around an additive memory recurrence,
$$
c_t = f_t c_{t-1} + i_t z_t,
\qquad
h_t = o_t \psi(c_t),
$$
where the forget gate $f_t$ and input gate $i_t$ regulate how much of the previous memory is retained and how much of the new candidate content $z_t$ is written. In the classic formulation, these gates are sigmoid outputs, so they are always between $0$ and $1$. That bounded range is part of what makes the LSTM stable, but it is also part of what limits the model’s ability to revise a previous storage decision when new evidence becomes more convincing.

The paper emphasizes this issue through tasks such as nearest neighbor search and state tracking. In these settings, a model may need to keep scanning a sequence and replace an earlier stored item with a later one if the later item is more relevant. A gate that can only express values in $[0,1]$ is essentially a bounded soft switch. It can attenuate or preserve, but it cannot represent a more flexible notion of write strength that is naturally larger than one. xLSTM’s answer is to let the gate become a positive scale factor rather than a bounded probability-like quantity. That is the role of exponential gating.

The key idea is not to abandon the additive recurrence, but to give the recurrence richer multiplicative control. If a later input deserves a much stronger write than an earlier one, the gate should be able to express that directly. If a previous memory should carry more weight than a new candidate, the gate should also be able to reflect that. Exponential gating makes this possible because it produces strictly positive values without imposing the upper bound that sigmoid gates impose.

# Input-dependent and learnable gates in the LSTM tradition

xLSTM does not invent gating from scratch. It keeps the LSTM tradition that gates are learned functions of the current input and, in the scalar-memory variant, the previous hidden state. In the original LSTM, the gate preactivations are affine functions of $\mathbf{x}_t$, $h_{t-1}$, and a bias term. The paper keeps this basic pattern:
$$
\tilde{i}_t = \mathbf{w}_i^\top \mathbf{x}_t + r_i h_{t-1} + b_i,
\qquad
\tilde{f}_t = \mathbf{w}_f^\top \mathbf{x}_t + r_f h_{t-1} + b_f,
\qquad
\tilde{o}_t = \mathbf{w}_o^\top \mathbf{x}_t + r_o h_{t-1} + b_o.
$$
The gate itself is then obtained by applying a nonlinearity to the preactivation.

This matters because the gates are not fixed hand-designed schedules. They are learned control signals, and they can adapt to the current token, the current context, and the current hidden summary. That is what allows an LSTM to decide, step by step, when to write, when to keep, and when to reveal. xLSTM keeps this logic intact. The change is that the input and forget gates are no longer constrained to act like bounded selectors. They become learned positive strengths.

The paper preserves the output gate as a sigmoid gate. So the architectural picture is still recognizably LSTM-like: the model learns how much to store, how much to forget, and how much of the memory to expose. The difference is that storage and forgetting are now controlled by exponential quantities, while exposure remains a bounded gate. This separation is important because it lets xLSTM expand the expressive range of memory control without discarding the familiar recurrent structure.

# Input gates and forget gates with exponential activations

In sLSTM and mLSTM, the input gate is exponential:
$$
i_t = \exp(\tilde{i}_t).
$$
The forget gate can be either sigmoid or exponential in the paper’s formulation:
$$
f_t = \sigma(\tilde{f}_t)
\quad \text{or} \quad
f_t = \exp(\tilde{f}_t).
$$
The point is that the gate values are no longer restricted to $[0,1]$ by default. They are positive scaling factors. The paper interprets the forget gate as a decay rate and the input gate as a learning rate. That interpretation is natural once the gates are treated as positive multiplicative strengths rather than probabilities.

This change gives the model much more flexibility in how it updates memory. A large positive input gate can make a new write strongly influence the memory state. A strong forget path can preserve or carry forward previously accumulated information with significant weight. Because both gates are positive, they can participate cleanly in additive memory updates while still giving the model a richer range of temporal behaviors.

At the same time, the paper is very clear that exponential gating cannot be used naively. Exponentials can become large very quickly, which makes overflows a serious problem. So the choice of exponential gating is coupled immediately to the next two ingredients: a normalizer state that keeps track of effective write strength, and a stabilizer state that keeps the gate computations numerically safe.

# The normalizer state and its role in tracking effective write strength

For sLSTM, the paper introduces a second recurrent state alongside the cell state:
$$
n_t = f_t n_{t-1} + i_t.
$$
This is the normalizer state. The hidden state is then formed not by applying $\tanh$ to the cell state, but by dividing the cell state by the normalizer state:
$$
h_t = o_t \tilde{h}_t,
\qquad
\tilde{h}_t = \frac{c_t}{n_t}.
$$
The purpose of $n_t$ is to keep track of how much effective write mass has accumulated in memory. It is not storing content itself. Instead, it stores the strength of the update process that produced the content.

This becomes clearer if one unrolls the recurrence. Every contribution written into memory at time $j$ is multiplied by the input gate $i_j$ and then carried forward by all future forget gates. The same is true for the normalizer, except that the content $z_j$ is omitted. So the cell state is a weighted accumulation of content, while the normalizer is a weighted accumulation of the same gate strengths. Their ratio is therefore a normalized memory summary, not just a raw sum. In the paper’s language, the normalizer state keeps record of the strength of the gates.

The same idea extends to mLSTM, where the normalizer is vector-valued rather than scalar. There, the hidden state uses a denominator based on the dot product between the query and the normalizer state, with a lower bound to keep the division stable:
$$
\tilde{\mathbf{h}}_t = \frac{\mathbf{C}_t \mathbf{q}_t}{\max\left\{|\mathbf{n}_t^\top \mathbf{q}_t|, 1\right\}}.
$$
The specific form differs, but the principle is the same. The model does not expose a raw unnormalized memory. It exposes memory relative to the strength with which it was built.

# How normalized hidden states differ from tanh-squashed cell states

In the original LSTM, the hidden state is obtained by squashing the cell state through a function $\psi$, typically $\tanh$:
$$
h_t = o_t \psi(c_t).
$$
This means the cell state itself may grow internally, but the exposed hidden state is forced through a saturating nonlinearity. That is a very different operation from the normalization used in xLSTM. In sLSTM, the hidden state is
$$
h_t = o_t \frac{c_t}{n_t}.
$$
Here, the output is not a generic bounded transform of the cell state. It is a ratio between content and accumulated gate strength.

This distinction matters conceptually. A tanh squashing function compresses magnitude into a fixed range, which can hide differences between memory states once the magnitude becomes large. By contrast, dividing by $n_t$ does not merely compress the cell state; it adjusts the cell state according to how much writing and forgetting has occurred. The hidden state therefore remains tied to the actual history of memory updates. It is a normalized representation of memory, not just a bounded one.

The output gate still plays its familiar role. It decides how much of this normalized memory is exposed as the hidden state. So xLSTM keeps the LSTM separation between storage and exposure, but replaces the old notion of “normalize the cell with $\tanh$” by a more explicit notion of “track the accumulated gate mass and divide by it.” That is one of the central conceptual differences introduced by the new gating scheme.

# The stabilizer state $m_t$ and the max-based log-domain trick

Once gates become exponential, numerical stability becomes a central concern. The paper addresses this by introducing an additional stabilizer state $m_t$. For sLSTM, it is defined as
$$
m_t = \max\left(\log(f_t) + m_{t-1}, \log(i_t)\right).
$$
This state tracks the relevant scale of the current forget path and the current input gate in log space. Instead of allowing the exponentials to grow without control, the model keeps a running reference point that reflects the largest relevant log-magnitude at each step.

The corresponding stabilized gates are
$$
i'_t = \exp\left(\log(i_t) - m_t\right) = \exp(\tilde{i}_t - m_t),
$$
and
$$
f'_t = \exp\left(\log(f_t) + m_{t-1} - m_t\right).
$$
These expressions rescale the gate values relative to the current stabilizer state. The key intuition is that the model is not changing the meaning of the gates; it is changing the numerical frame in which they are represented. By subtracting the current dominant scale in log space, the implementation avoids evaluating very large exponentials directly.

This is why the stabilizer is described as a max-based log-domain trick. It is a running scale tracker. It compares the scale of the new input gate with the scale of the forget path that has already been accumulated, and it chooses the larger one as the new reference point. That reference point is then used to re-express the gates in a numerically manageable form.

# Stabilized input and forget gates

The stabilized gates are the values that are actually used in the stabilized forward pass. Because $m_t$ is chosen as the maximum of the relevant log-scales, the resulting exponentials are normalized relative to that maximum. In practical terms, the stabilized gates stay in a safe numerical range, rather than exploding as the raw exponentials might. This is crucial because the gates are used repeatedly across a long recurrence, and a small numerical issue at one step can propagate through the entire sequence.

The paper applies the same stabilization logic to both sLSTM and mLSTM. In sLSTM, the recurrent state $m_t$ makes the exponential gate values safe while preserving the meaning of the cell and normalizer updates. In mLSTM, the same stabilization is used even though the memory itself is matrix-valued. So stabilization is a shared ingredient, not a variant-specific detail.

It is also important that stabilization is not done by clipping or approximation. The paper’s formulas define a mathematically exact rescaling. That means the stabilized gates are not “close to” the original ones in some heuristic sense; they are a different parameterization of the same computation. This exactness is what makes the next property possible: the output of the network, and even the gradients, are preserved.

# Why stabilization preserves outputs and gradients

The paper states that replacing $f_t$ with $f'_t$ and $i_t$ with $i'_t$ in the forward pass does not change the output of the whole network. It also states that the derivatives of the loss with respect to the parameters are unchanged. This is a strong result, and it is one of the reasons the stabilization scheme is so useful. It means that the method is not merely a numerical patch; it is an exact reformulation of the same model.

Intuitively, the reason this works is that the stabilizer absorbs a common scale factor into the recurrent computation. The memory update, the normalizer update, and the output normalization are all organized so that only the relative strengths of the gates matter. Once those relative strengths are preserved, the external behavior of the model is preserved as well. The appendix proves this formally, but the conceptual message is simple: the stabilized gates compute the same function, only in a safer numerical representation.

Because the function is unchanged, backpropagation sees the same model. So the gradients with respect to the learnable parameters are also unchanged. That is particularly important in large-scale training, where one wants numerical stability without altering the optimization problem. xLSTM’s stabilization is designed to provide exactly that.

# Numerical overflow, underflow, and practical training stability

The paper explicitly points out that exponential activation functions can produce large values and therefore cause overflows. That is the main numerical danger introduced by exponential gating. The stabilizer state $m_t$ is the mechanism that addresses this danger, and the normalizer state ensures that the hidden representation remains scale-aware rather than accumulating raw unbounded sums. Together, these components keep the recurrent computation numerically well behaved.

The practical lesson is that xLSTM does not rely on exponential gating in isolation. It couples exponential gating with normalization and exact stabilization so that the gates can be expressive without becoming unstable. This is what makes the shared ingredient usable in both sLSTM and mLSTM, and it is what allows the paper to scale the design to large language modeling experiments. The model gains a richer way to represent write strength and memory retention, while the stabilization machinery keeps the computation trainable in practice.

In that sense, the first xLSTM ingredient is best understood as a package: exponential gates give the model more expressive control over memory, the normalizer state turns that control into a meaningful normalized hidden representation, and the stabilizer state makes the whole construction numerically safe. The paper’s central claim is that these three pieces together preserve the spirit of the LSTM while removing some of its most important limitations.

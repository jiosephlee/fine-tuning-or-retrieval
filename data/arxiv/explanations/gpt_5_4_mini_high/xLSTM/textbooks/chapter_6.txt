\title{A Textbook about the Paper: "xLSTM: Extended Long Short-Term Memory"}

Chapter 6: mLSTM: Matrix Memory and Associative Retrieval

# Why Move from Scalar Memory to Matrix Memory

The original LSTM idea stores the past in a scalar memory cell $c_t$, updated by an additive rule and controlled by gates. That design is powerful, but the paper argues that it also creates a bottleneck: a scalar cell compresses information too aggressively. When a model needs to remember many distinct associations over a long sequence, a single scalar state is a limited container.

The mLSTM variant addresses this by replacing the scalar memory cell with a matrix memory $\mathbf{C}_t \in \mathbb{R}^{d \times d}$. This is the central structural change. Instead of storing the past as one number, mLSTM stores it as a matrix that can represent richer relationships between what was seen before and what may be needed later. In the paper’s framing, this is how xLSTM increases storage capacity: it moves from compressing the past into scalar cells to storing key-value associations in a higher-dimensional memory.

The motivation is not just larger size for its own sake. The paper’s key point is that the matrix memory makes associative retrieval more expressive. A scalar memory can remember that something happened, but a matrix memory can remember how one vector should be associated with another. That is the conceptual leap behind mLSTM.

# Key, Value, and Query Vectors in mLSTM

To turn memory into an associative store, mLSTM uses the Transformer-style terminology of keys, values, and queries. From the input vector $\mathbf{x}_t$, the model computes three vectors:

\[
\mathbf{q}_t = \mathbf{W}_q \mathbf{x}_t + \mathbf{b}_q,
\qquad
\mathbf{k}_t = \frac{1}{\sqrt{d}} \mathbf{W}_k \mathbf{x}_t + \mathbf{b}_k,
\qquad
\mathbf{v}_t = \mathbf{W}_v \mathbf{x}_t + \mathbf{b}_v.
\]

Here, the query $\mathbf{q}_t$ is what the model will use to probe memory, the key $\mathbf{k}_t$ is what gets written as an address, and the value $\mathbf{v}_t$ is the content to be recovered later. The paper uses this terminology because the retrieval problem is exactly the one associated with key-value memory: store an association now, and recover the corresponding value later when a matching query appears.

This is important intuitively. A key does not by itself contain the answer; rather, it tells the system where the answer is stored. A value is the content that should be returned. The query is the current request. If the query matches a stored key, the stored value should be brought back. mLSTM is built around this idea directly.

# The Matrix Cell State $\mathbf{C}_t$ and Outer-Product Storage

The core mLSTM update is

\[
\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top.
\]

This equation is the matrix-memory analog of the original LSTM cell update. The forget gate $f_t$ scales the old memory, while the input gate $i_t$ controls how strongly the new association is written. The new information enters as an outer product $\mathbf{v}_t \mathbf{k}_t^\top$.

The outer product is the key idea. It stores the value and the key together in a matrix form: every component of $\mathbf{v}_t$ is paired with every component of $\mathbf{k}_t$. That means the memory is not merely collecting a list of past values. It is encoding a structured association between what should be remembered and how it should be addressed later.

A useful way to think about the update is that the matrix memory is being written like a table of associations. The forget gate decides how much of the old table remains, and the input gate decides how much weight the new association gets. Because the write operation is multiplicative in key and value, the stored memory can later be accessed by a matching query through matrix multiplication.

# The Covariance Update Rule for Key-Value Association

The paper identifies the update

\[
\mathbf{C}_t = \mathbf{C}_{t-1} + \mathbf{v}_t \mathbf{k}_t^\top
\]

as a covariance update rule, and this is the conceptual basis for the matrix memory in mLSTM. In the LSTM formulation, the forget and input gates turn this into a gated version of that update, but the central memory-writing mechanism remains the same: add a value-key outer product to the memory matrix.

The paper notes that this covariance-style update is optimal for maximal separability of retrieved binary vectors, which is equivalent to maximizing the signal-to-noise ratio. The intuition is that when memory is used for association, stored patterns should remain distinguishable from one another. A good update rule makes it easier to retrieve the right value when a query arrives later. In this sense, the matrix memory is not just bigger; it is organized to preserve retrievability.

The paper also assumes layer normalization before projecting inputs to keys and values, so those vectors have zero mean. Under that assumption, the covariance update rule fits naturally with the statistics of the stored representations. This is why the paper frames the matrix memory as a covariance-based associative store rather than as an arbitrary matrix accumulator.

# Connections to Bidirectional Associative Memories

The retrieval problem mLSTM solves is the same one studied in Bidirectional Associative Memories, or BAMs. In that setting, a pair of vectors is stored together, and later a cue or query is used to recover the associated partner. The mLSTM memory behaves in exactly that spirit: it stores key-value pairs at time $t$ and later uses a query at time $t+\tau$ to recover the value.

This connection is more than historical. It clarifies what the matrix memory is for. The matrix is not merely a compressed summary of the past; it is an associative map from keys to values. When the query matches the stored key structure, the corresponding value is recovered through the matrix-memory dynamics. That makes mLSTM especially suitable for tasks in which the model must remember and later retrieve specific associations.

The paper’s presentation of mLSTM emphasizes this BAM-like behavior because it helps explain why a matrix memory is useful. A scalar memory can represent state, but a matrix memory can represent associations between state components. That is the essential difference.

# Connections to Fast Weights, Linear Attention, and Retention-Style Models

The paper explicitly connects the covariance update rule in mLSTM to Fast Weight Programmers. In that view, the memory matrix is a fast-changing state that is updated online as new information arrives. The paper notes that later variants of fast weights were equipped with a constant decay rate multiplied to the previous memory and a constant learning rate multiplied to the new outer product. In mLSTM, these roles are played by the forget gate and the input gate.

This is why the paper says the forget gate corresponds to a decay rate and the input gate corresponds to a learning rate. The output gate then scales the retrieved vector. So, although mLSTM is framed as an LSTM extension, it also sits in a broader family of associative-memory models that use matrix or linear-state updates.

The paper also places mLSTM near several modern models that use related ideas: RWKV-5, RWKV-6, Retention, Linear Transformer, and HGRN2. The common theme is that information is accumulated through a structured update rule rather than through full attention over all past tokens. mLSTM shares this associative-memory spirit, but it does so with the LSTM gating language and with a matrix-valued cell state.

# The Normalizer Vector State $\mathbf{n}_t$

Alongside the matrix memory, mLSTM maintains a normalizer vector state $\mathbf{n}_t$:

\[
\mathbf{n}_t = f_t \mathbf{n}_{t-1} + i_t \mathbf{k}_t.
\]

This state is the normalization counterpart to $\mathbf{C}_t$. The paper describes it as a weighted sum of key vectors, where each key is weighted by the input gate and all future forget gates. Its purpose is to keep track of the strength of the stored associations so that the retrieval output can be normalized properly.

Intuitively, $\mathbf{n}_t$ records how much “support” the memory has accumulated for the current query space. If $\mathbf{C}_t$ stores the actual key-value associations, then $\mathbf{n}_t$ tracks the scale of the key contributions that went into that memory. This is crucial because the retrieval step needs to know not just what was stored, but how strongly it was stored.

Without a normalizer, matrix retrieval can produce outputs with unstable magnitudes. The normalizer gives the model a way to compensate for that by scaling the retrieved vector according to the accumulated key strength.

# Retrieval by $\mathbf{C}_t$ Multiplied with $\mathbf{q}_t$

Once the memory has been written, retrieval happens by multiplying the matrix state with the query:

\[
\tilde{\mathbf{h}}_t = \frac{\mathbf{C}_t \mathbf{q}_t}{\max \{ |\mathbf{n}_t^\top \mathbf{q}_t|, 1 \}}.
\]

This is the central read operation in mLSTM. The matrix $\mathbf{C}_t$ combines all previous key-value associations, and the query $\mathbf{q}_t$ probes that matrix to produce a retrieved vector. The hidden state is then

\[
\mathbf{h}_t = \mathbf{o}_t \odot \tilde{\mathbf{h}}_t,
\]

so the output gate scales the retrieved content elementwise.

The intuition is straightforward: the query asks, “Which stored association is relevant right now?” The matrix memory answers by projecting the query through all stored associations at once. Because the memory was built from outer products of values and keys, the multiplication with $\mathbf{q}_t$ produces a value-like output when the query aligns with the corresponding key.

The output gate then decides how much of that retrieved content should be exposed as the hidden state. So the read path in mLSTM has two stages: memory lookup through the matrix, and output control through gating.

# The Denominator $\max$ of Absolute $\mathbf{n}_t^\top \mathbf{q}_t$ and $1$ for Stable Normalization

The denominator in the retrieval formula is

\[
\max \{ |\mathbf{n}_t^\top \mathbf{q}_t|, 1 \}.
\]

The paper emphasizes that the dot product $\mathbf{n}_t^\top \mathbf{q}_t$ can be close to zero, which would make the retrieval unstable if used directly as a divisor. Taking the absolute value and lower bounding it by $1$ protects the computation from blow-ups.

This normalization is not an arbitrary trick; it is part of making the matrix memory numerically usable. The denominator reflects the strength of the normalizer state relative to the query. If that strength is small, dividing by it would amplify noise. By enforcing a minimum value of $1$, the model avoids extreme scaling while preserving the intended normalization behavior.

So the denominator plays the same role that a safe normalization constant would play in any associative-memory system: it keeps the retrieval magnitude controlled even when the raw dot product is weak.

# Input, Forget, and Output Gates in mLSTM

mLSTM keeps the LSTM gating idea, but the paper changes the gate activations to support the matrix-memory design. The input gate is exponential,

\[
i_t = \exp(\tilde{i}_t), \qquad \tilde{i}_t = \mathbf{w}_i^\top \mathbf{x}_t + b_i,
\]

and the forget gate can be either sigmoid or exponential,

\[
f_t = \sigma(\tilde{f}_t) \quad \text{or} \quad \exp(\tilde{f}_t), \qquad \tilde{f}_t = \mathbf{w}_f^\top \mathbf{x}_t + b_f.
\]

The output gate remains sigmoid-valued,

\[
\mathbf{o}_t = \sigma(\tilde{\mathbf{o}}_t), \qquad \tilde{\mathbf{o}}_t = \mathbf{W}_o \mathbf{x}_t + \mathbf{b}_o.
\]

These gates are the control knobs of the memory system. The input gate determines how strongly new key-value information is written. The forget gate determines how much of the previous memory persists. The output gate determines how much of the retrieved memory is passed on as the hidden state.

Because exponential gates can become very large, the paper stabilizes them with an additional state $m_t$. The stabilized gates are

\[
m_t = \max(\log(f_t) + m_{t-1}, \log(i_t)),
\]

\[
i_t' = \exp(\log(i_t) - m_t) = \exp(\tilde{i}_t - m_t),
\]

\[
f_t' = \exp(\log(f_t) + m_{t-1} - m_t).
\]

The paper states that replacing $f_t$ by $f_t'$ and $i_t$ by $i_t'$ does not change the network output or the derivatives of the loss with respect to the parameters. This is important because it means the stabilization is mathematically faithful to the intended computation while making the model numerically safer.

# Why Matrix Memory Increases Storage Capacity

The paper’s main argument for mLSTM is that a matrix cell state has greater storage capacity than a scalar one. A scalar memory cell can only compress the past into one degree of freedom per cell, while a matrix memory can encode relations among many dimensions at once. That extra structure matters when the model must remember multiple distinct associations and later retrieve one of them based on a query.

The outer-product storage rule gives the memory a form of addressability. Instead of merely remembering that something happened, mLSTM remembers how a key should lead to a value. This is a richer storage format because it allows the model to select among multiple stored associations using the query. That is why the paper views mLSTM as better suited for associative recall than scalar-memory LSTMs.

The paper’s broader claim is that this richer memory helps overcome one of the major limits of classic LSTMs: limited storage capacity. In mLSTM, the memory is not just larger in size; it is larger in representational power.

# Multiple Cells, Multiple Heads, and Parallelization

The paper notes that mLSTM can have multiple memory cells, just like the original LSTM. It also states that for mLSTM, multiple heads and multiple cells are equivalent, because there is no memory mixing. This is an important architectural point.

In a system with memory mixing, hidden-to-hidden connections couple one cell or head to another, so the way memory is partitioned matters. In mLSTM, there is no such coupling. As a result, the distinction between organizing the model into multiple cells or multiple heads does not change the fundamental memory computation. The matrix memories remain separate, and the model does not need hidden-hidden recurrence to exchange information between them.

This absence of memory mixing is also what makes mLSTM parallelizable. The paper states that the recurrence can be reformulated in a parallel version. That is one of the main reasons mLSTM is attractive as a modern recurrent architecture: it keeps the associative-memory flavor of LSTMs while allowing efficient matrix-based computation. The paper further notes that these computations can be done in parallel on GPUs, so the heavier matrix memory does not necessarily translate into prohibitive wall-clock cost.

In short, mLSTM combines a richer memory representation with a computation pattern that avoids the strict sequential bottleneck of classic recurrent memory mixing. That combination is central to why the paper treats mLSTM as a serious modern alternative for sequence modeling.

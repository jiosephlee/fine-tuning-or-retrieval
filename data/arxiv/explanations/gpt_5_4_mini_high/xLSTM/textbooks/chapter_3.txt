\title{A Textbook about the Paper: "xLSTM: Extended Long Short-Term Memory"}

Chapter 3: The Three Main Limitations of Classical LSTMs

# Inability to revise storage decisions once information is written

The classical LSTM was built around a simple but powerful memory update rule, $c_t = f_t c_{t-1} + i_t z_t$, together with the hidden-state readout $h_t = o_t \psi(c_t)$. This structure gives the model a persistent memory path, often described as the constant error carousel, because information can be carried forward through time without being repeatedly overwritten. That persistence is one of the reasons LSTMs were so effective in early sequence modeling.

But the same additive design also creates a practical weakness at modern scale: once something has been written into memory, the model has limited ability to revise that decision later. The paper emphasizes this as a major limitation of standard LSTMs. In a long sequence, new evidence may arrive that suggests an earlier stored item was not the best choice after all. A classical LSTM can attenuate or reinforce what is already stored, but its update mechanism is not especially well suited to decisively replacing an old memory with a better one.

# The Nearest Neighbor Search example as a diagnostic task

To make this limitation concrete, the paper uses a Nearest Neighbor Search task. In this task, the model is given a reference vector and must scan through a sequence to find the most similar vector, then return the value attached to that best match at the end of the sequence. The task is sequential by nature, because the model has to compare each new candidate against what it has seen before and keep track of the best one so far.

This diagnostic task is useful because it exposes whether a model can update its memory when a later item is more relevant than an earlier one. The paper reports that a standard LSTM struggles here: it has difficulty revising a stored value when a more similar vector appears later in the sequence. In other words, the model can remember, but it cannot easily change its mind. xLSTM is introduced partly to fix exactly this behavior through exponential gating.

# Why sigmoid gating can make memory updates too conservative

In the original LSTM, the gates are sigmoid gates. The input gate, forget gate, and output gate are all produced by $\sigma(x) = 1/(1+\exp(-x))$, so they are naturally bounded between $0$ and $1$. That bounded range is useful because it keeps the memory mechanism controlled and stable, but it also makes updates inherently cautious. The gates can suppress or pass along information, but they do not strongly amplify a new storage decision.

From the paper’s point of view, this conservatism is part of the reason classical LSTMs struggle to revise memory. If the model needs to strongly favor a newer and better piece of information, a purely sigmoid-gated update can be too gentle. xLSTM addresses this by introducing exponential gating. In the sLSTM and mLSTM variants, gates can be written in exponential form, and the paper adds normalization and stabilization so that these larger values do not cause numerical overflow. The key idea is to give the network a more flexible way to update memory without losing stability.

# Limited storage capacity of scalar memory cells

A second limitation of the classical LSTM is that its memory cell is scalar. Even when later formulations collect multiple scalar cells into a vector, each unit still stores only a scalar quantity. The paper highlights this as a form of limited storage capacity: information must be compressed into scalar cell states, which constrains how much can be retained and how richly it can be represented.

This limitation matters because sequence data often contains many distinct dependencies that need to be preserved at the same time. A scalar memory cell can carry a summary, but the paper argues that this summary may be too compressed for modern language modeling. That is why xLSTM introduces a matrix memory in mLSTM. By moving from a scalar $c \in \mathbb{R}$ to a matrix $\mathbf{C} \in \mathbb{R}^{d \times d}$, the model can store and retrieve information with much greater capacity than a single scalar state allows.

# Rare token prediction as evidence of insufficient memory capacity

The paper gives a second diagnostic for this storage problem using rare token prediction on Wikitext-103. The data are partitioned by token frequency, and the model’s perplexity is measured across these partitions. The result is that classical LSTM performs worse on rare tokens. The paper interprets this as evidence that the model’s storage capacity is not sufficient for the full range of token types that appear in language.

This is a particularly informative test because rare tokens are exactly the kind of items that can be lost when memory is too compressed. Frequent patterns may be easier to handle, but less common tokens place a greater burden on the model’s ability to preserve specific details. The paper’s solution is the matrix-memory design of mLSTM, which is intended to increase what can be stored and later recovered. In that sense, the rare-token experiment is not just a benchmark result; it is direct evidence that scalar memory is too restrictive for modern language modeling.

# The cost of memory mixing for parallel execution

The third major limitation is that classical LSTMs mix memory across time through hidden-hidden recurrent connections. The paper calls this memory mixing. In the original formulation, and also in later versions with multiple scalar memory cells collected into a vector, recurrent weight matrices can mix the outputs of those cells from one time step to the next. That interaction between the current update and the previous hidden state makes the recurrence richer, but it also creates a serial dependency.

Once memory mixing is present, the model cannot update all time steps independently. Each step depends on the hidden state that came before it, so the sequence has to be processed in order. This is the core reason the paper identifies lack of parallelizability as a limitation. The computation is not just recurrent in a conceptual sense; it is operationally sequential.

# Sequential dependence versus hardware efficiency

The practical consequence of this sequential dependence is that it does not match the strengths of modern hardware. Contemporary accelerators are especially effective when work can be arranged as parallel matrix operations. A model that must step through a sequence one token at a time cannot exploit that parallelism in the same way. The paper therefore treats memory mixing not only as an architectural choice, but also as a performance bottleneck.

This is why the paper separates the two xLSTM variants. The sLSTM keeps memory mixing, which helps with state tracking, but it is not fully parallelizable. The mLSTM, by contrast, abandons memory mixing so that the recurrence can be reformulated in parallel. That tradeoff is central to the paper’s argument: a modern LSTM must balance expressive recurrent memory with the need for efficient computation on GPUs.

# Design goals for an extended LSTM suitable for modern language modeling

Taken together, the three limitations point to a clear design problem. If LSTMs are to be scaled to modern language-model sizes, they need to do three things at once: revise storage decisions more flexibly, store more information than a compressed scalar cell can hold, and execute efficiently enough to remain practical at scale. The paper’s answer is xLSTM, which is built specifically to address these requirements.

The design has two complementary parts. The sLSTM introduces exponential gating, stabilization, and memory mixing to improve how the model revises and tracks state. The mLSTM replaces scalar memory with a matrix memory and uses a covariance-style update rule so that storage capacity is much larger, while also remaining fully parallelizable. Both variants are then placed inside residual blocks and stacked into xLSTM architectures. In this way, the paper does not discard the LSTM idea; it extends it so that it can meet the demands of modern language modeling.

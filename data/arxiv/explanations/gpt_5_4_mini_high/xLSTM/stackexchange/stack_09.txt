\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### Why are multiple heads and multiple cells equivalent for mLSTM but not for sLSTM?
Question:
The paper says that for mLSTM, multiple heads and multiple memory cells are equivalent, while for sLSTM they are not because sLSTM allows memory mixing within a head. I do not see this equivalence clearly. If an mLSTM head has its own matrix memory, output gate, key/query/value projections, and no interaction with other heads, then I can imagine concatenating several such heads. But why is that the same as having multiple cells? Is the claim only about representational structure, or also about parameter count and computation? A concrete explanation with dimensions would help.
Answer:
The paper’s statement is best understood as a claim about the **state connectivity pattern**, not a deep difference in what the model can compute. For mLSTM, “multiple heads” and “multiple cells” are equivalent because there is no hidden-to-hidden memory mixing at all; for sLSTM, they are not equivalent because the recurrent matrices *do* mix cell states, and the head structure changes which states are allowed to interact.

For mLSTM, the recurrence is
$$
\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top,
\qquad
\mathbf{h}_t = \mathbf{o}_t \odot \frac{\mathbf{C}_t \mathbf{q}_t}{\max\{|\mathbf{n}_t^\top \mathbf{q}_t|,1\}}.
$$
There is no term of the form “other heads’ hidden states” inside the update. So if you split the model width into, say, $H$ parts of size $d_h$ with $d = H d_h$, then each part just carries its own matrix memory
$$
\mathbf{C}_t^{(1)}, \ldots, \mathbf{C}_t^{(H)}, \qquad \mathbf{C}_t^{(j)} \in \mathbb{R}^{d_h \times d_h},
$$
with corresponding $\mathbf{q}_t^{(j)}, \mathbf{k}_t^{(j)}, \mathbf{v}_t^{(j)} \in \mathbb{R}^{d_h}$. Whether you call these $H$ independent pieces “heads” or “cells” is just bookkeeping: the whole state is the direct sum of independent blocks, and concatenating the outputs gives the same function after a reshape. In that sense, the equivalence is structural, and with the usual blockwise implementation it also means essentially the same parameter count and computation for a fixed total width.

A concrete example makes this clearer. If $d=8$ and you choose $H=2$ with $d_h=4$, then mLSTM can be viewed as either two independent $4 \times 4$ memories or one tensor of shape $2 \times 4 \times 4$. Those are the same model written differently, because the update of block $1$ never depends on block $2$, and vice versa.

sLSTM is different because its hidden state is *mixed* through recurrent matrices. The paper writes the cell input and gates with terms like
$$
\tilde z_t = \mathbf{w}_z^\top \mathbf{x}_t + \mathbf{R}_z \mathbf{h}_{t-1} + b_z,
$$
and similarly for $\tilde i_t, \tilde f_t, \tilde o_t$. Here $\mathbf{h}_{t-1}$ contains all cell outputs in the group, so $\mathbf{R}_z$ can be dense: one cell can influence another. If you now introduce heads and forbid mixing across heads, you are no longer just relabeling the same state; you are restricting $\mathbf{R}_z, \mathbf{R}_i, \mathbf{R}_f, \mathbf{R}_o$ to be block-diagonal across heads. That changes the model class. In other words, a “single head with many cells” allows mixing among those cells, while “many heads” isolates them.

So the short answer is: for mLSTM, heads and cells are equivalent because the recurrence is independent across blocks, making the distinction purely a reshaping of the state; for sLSTM, the recurrence couples cells, so the head partition determines which memories can talk to each other, and that is a real architectural difference.

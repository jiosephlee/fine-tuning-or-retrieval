\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### Why does xLSTM use post up-projection for sLSTM blocks but pre up-projection for mLSTM blocks?
Question:
In the architecture section, the paper says that sLSTM blocks use a residual block with post up-projection, while mLSTM blocks use pre up-projection. The argument references Cover's theorem and says that for mLSTM the memory capacity becomes larger in the high-dimensional space. I am having trouble connecting those ideas. Why is it better to summarize the past in the original space for sLSTM but in the expanded space for mLSTM? Is this a theoretical consequence of the different memory structures, or mainly an empirical design choice that happened to work better?
Answer:
The short answer is that the placement is chosen to match the bottleneck of each memory type, not because there is a strict theorem that says “sLSTM must be post-projected” and “mLSTM must be pre-projected.”

In the paper, the authors use Cover’s theorem as intuition: if you move a problem into a higher-dimensional feature space, different patterns are more likely to become linearly separable. That intuition is especially relevant for the mLSTM, because its memory is a matrix $\mathbf{C} \in \mathbb{R}^{d \times d}$ updated by outer products $\mathbf{v}_t \mathbf{k}_t^\top$. In other words, mLSTM is an associative memory whose capacity really does grow with the feature dimension. If you project the input up first, the keys, queries, and values live in a richer space, and the matrix memory can store and separate more histories with less interference. So for mLSTM, “summarize in the expanded space” is a natural fit: the memory itself benefits from being wide.

For sLSTM, the situation is different. Its memory is scalar-valued per cell, and its main novelty is not raw storage capacity but gating and memory mixing, i.e. the ability to revise and combine information across cells and heads. That mechanism is already doing the hard sequential work in the model’s original width. So the block is arranged so that the recurrent part first produces a compact summary in the base space, and only then the residual block expands it. This is closer to the usual Transformer-style pattern: do the sequence-dependent computation in the model width, then use the up-projection to enrich the representation for the next layer.

So the distinction is mostly architectural and motivated by the memory structure. For mLSTM, the memory capacity itself scales with dimension, so pre up-projection directly helps the mechanism the authors want to strengthen. For sLSTM, widening before the recurrent update would not address its main advantage as directly, while post up-projection keeps the recurrent core compact and efficient.

I would read this as a theory-guided design choice, not a proven necessity. Cover’s theorem provides the intuition for why higher-dimensional summaries can be easier to separate, but the exact “pre for mLSTM, post for sLSTM” split is an empirical architecture decision informed by the different memory dynamics. The paper’s experiments suggest that this choice works well, but it is not presented as a mathematical consequence that must hold in every setting.

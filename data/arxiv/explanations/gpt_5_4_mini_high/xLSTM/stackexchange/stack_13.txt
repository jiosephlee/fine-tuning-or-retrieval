\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### When the paper says xLSTM has constant memory complexity in sequence length, does that apply to training or only inference?
Question:
The paper states that, contrary to Transformers, xLSTM has linear computation and constant memory complexity with respect to sequence length. I can understand this at inference time, since the recurrent state size does not grow with context length. But during training, backpropagation through time usually requires storing activations for every time step, which sounds like memory growing with sequence length anyway. So is the claim about constant memory complexity only about the model state during inference, or are the authors assuming checkpointing/recomputation or a custom training algorithm?
Answer:
The short answer is: the paper’s “constant memory complexity with respect to sequence length” should be read as a statement about the model’s *recurrent state* in the forward pass, i.e. the inference/streaming setting, not as a claim that full end-to-end training with ordinary backpropagation is automatically $O(1)$ in sequence length.

What xLSTM changes relative to a Transformer is that, at each step, it only needs to carry a fixed-size state forward in time. For sLSTM that state is the cell/normalizer/stabilizer state, and for mLSTM it is the matrix memory plus its normalizer. So if you are generating tokens autoregressively, the memory you must keep does not grow with the context length the way a Transformer’s KV cache does. That is exactly the sense in which the paper contrasts xLSTM with Transformers in the “Memory and Speed Considerations” section, and it is also the sense used in the generation/throughput experiments.

During training, however, the usual issue still applies: if you unroll the recurrence over $T$ steps and use standard backpropagation through time, autograd typically has to retain intermediate activations for the backward pass, so training memory is generally at least linear in the unroll length, $O(T)$, unless you use checkpointing, recomputation, or truncated BPTT. The paper does not introduce a special training algorithm whose purpose is to make backprop itself constant-memory. In fact, the experimental setup uses fixed context lengths for training, and the long-context results are presented as extrapolation at evaluation time.

So the right interpretation is that xLSTM removes the *sequence-length growth of the model state*, which is a big practical advantage for inference and streaming, but it does not by itself eliminate the usual activation-memory cost of training through long unrolled sequences.

\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### Why do exponential gates let xLSTM revise earlier storage decisions better than sigmoid gates?
Question:
In the xLSTM paper, one of the main claims is that replacing standard sigmoid gating with exponential gating helps fix the LSTM's inability to revise storage decisions. The paper motivates this with a nearest-neighbor search task, where a later token may need to overwrite an earlier stored value if it is a better match. I do not see the mechanism clearly. In a standard LSTM, the update is $c_t = f_t c_{t-1} + i_t z_t$ with $f_t, i_t \in (0,1)$, while in sLSTM the input gate is $i_t = \exp(\tilde{i}_t)$ and the forget gate can also be exponential. Why does making the gates unbounded help the model overwrite or reweight past content more effectively? Is the key point that the ratio between new and old contributions can become arbitrarily large, whereas sigmoid gates cap that ratio?
Answer:
Yes, but the deeper point is not just “the ratio can be larger.” It is that xLSTM changes the memory from a raw additive trace into a normalized, weighted memory.

In the paper’s sLSTM, the state is not just $c_t$; it is paired with a normalizer $n_t$:
$$
c_t = f_t c_{t-1} + i_t z_t, \qquad n_t = f_t n_{t-1} + i_t, \qquad h_t = o_t \frac{c_t}{n_t}.
$$
If you unroll this, each past candidate $z_\tau$ contributes with an effective positive weight
$$
\alpha_\tau = i_\tau \prod_{j=\tau+1}^t f_j.
$$
So the hidden state is essentially a weighted average of past stored content. That is important: the model is no longer just “adding a little bit of new stuff to old stuff,” it is maintaining a competition between alternatives through their weights.

Exponential gating matters because those weights are no longer capped in $(0,1)$. A later token can therefore receive a weight that is much larger than the total weight accumulated so far, and after division by $n_t$ it can take over the state. That is exactly the kind of behavior you want in the nearest-neighbor task: when a better match appears later, the memory should be able to move decisively toward it, not merely nudge the old content.

By contrast, sigmoid gates are bounded. They can forget by shrinking the old state, but they cannot express arbitrarily strong write strengths. In other words, standard LSTM gates behave more like bounded interpolation coefficients, while exponential gates behave like unnormalized “scores” that are then normalized. That makes xLSTM much closer to a softmax-style competition between memories. This is why the paper says exponential gating helps it “revise storage decisions”: the model can store both the content and how strongly it should count, and a later, better-matching item can outweigh earlier ones instead of having to fight them through a bounded gate.

So your intuition is basically right, with one refinement: it is not merely that $i_t/f_t$ can be large, but that exponential gating together with the normalizer state turns memory updates into a true weighted selection mechanism. That is the mechanism that lets xLSTM overwrite or reweight earlier storage more effectively than a standard sigmoid-gated LSTM.

### What exactly is the sLSTM normalizer state $n_t$, and why is the hidden state defined as $h_t = o_t (c_t / n_t)$?
Question:
The sLSTM introduces an extra recurrence $n_t = f_t n_{t-1} + i_t$ and then uses $\tilde{h}_t = c_t / n_t$ before output gating. I am confused about what $n_t$ is supposed to represent. If I unroll the recurrence, it looks like both $c_t$ and $n_t$ accumulate past terms with the same gate products, so $c_t / n_t$ seems like some kind of weighted average of past inputs $z_\tau$. Is that the correct interpretation? If so, why is that preferable to the usual LSTM approach of applying something like $\tanh(c_t)$ to keep the state bounded?
Answer:
Yes — in the sLSTM, $n_t$ is best thought of as a *normalization mass* or *running total weight* for the memory, not as another piece of semantic content. The paper says exactly that it “sums up the product of the input gate times all future forget gates,” and that it “keeps record of the strength of the gates.” If you unroll the recurrences, you get

$$
c_t \;=\; \sum_{\tau \le t} \left(i_\tau z_\tau \prod_{j=\tau+1}^t f_j\right), 
\qquad
n_t \;=\; \sum_{\tau \le t} \left(i_\tau \prod_{j=\tau+1}^t f_j\right),
$$

assuming zero initial state for simplicity. So when all gates are positive, $c_t / n_t$ really is a weighted average of the past cell inputs $z_\tau$, with weights proportional to the same gate products that determine how much each past input survives to time $t$. In that sense, your interpretation is correct: $n_t$ is the denominator that turns the raw accumulated memory into a normalized readout.

That is precisely why the hidden state is defined as

$$
h_t = o_t \left(\frac{c_t}{n_t}\right).
$$

The cell state $c_t$ stores the weighted sum, while $n_t$ stores the total effective weight. Dividing by $n_t$ removes the dependence on absolute gate scale and makes the readout comparable across time. This is analogous to how attention produces a normalized weighted average rather than an unnormalized sum: the numerator carries content, and the denominator carries strength.

This is preferable to applying something like $\tanh(c_t)$ for a different reason. A $\tanh$ nonlinearity keeps the state bounded, but it does so by *saturating* the value. Once $c_t$ is large in magnitude, different underlying memories all look almost the same after $\tanh$, so information about relative strength is lost. In the xLSTM paper, the point of exponential gating is to let the model revise storage decisions more flexibly; normalization via $n_t$ preserves the relative contributions of past inputs instead of crushing them into a fixed range. So the model does not just ask “is the memory large?” but “what is the average content after accounting for how strongly each thing was written?”

So the short answer is: $n_t$ is a bookkeeping variable that normalizes the memory, and $c_t / n_t$ is a normalized, weighted summary of past inputs. The output gate $o_t$ then decides how much of that normalized memory to expose. The separate stabilization state $m_t$ in the paper is only there to make the exponential gates numerically safe; it is not the conceptual normalizer.

### Why does the stabilization state $m_t$ not change the forward output or gradients in xLSTM?
Question:
For numerical stability, the paper defines a stabilizer state
$ m_t = \max(\log(f_t) + m_{t-1}, \log(i_t)) $
and then replaces the gates by
$ i'_t = \exp(\tilde{i}_t - m_t) $
and
$ f'_t = \exp(\log(f_t) + m_{t-1} - m_t) $.
The authors say that replacing $i_t, f_t$ by $i'_t, f'_t$ does not change either the network output or the derivatives with respect to the parameters. I can believe this is some kind of rescaling trick, but I do not see it formally. Is the idea that both $c_t$ and the normalizer get multiplied by the same accumulated factor, so the ratio stays unchanged? And if that is the argument, why do the gradients also remain exactly the same rather than just approximately the same?
Answer:
Yes — the stabilization is an exact rescaling trick, not an approximation.

The clean way to see it is to introduce the stabilized cell and normalizer states
$$
\bar c_t := e^{-m_t} c_t, \qquad \bar n_t := e^{-m_t} n_t.
$$
Using the paper’s definitions
$$
m_t=\max\bigl(\log(f_t)+m_{t-1},\log(i_t)\bigr),\qquad
i'_t=e^{\log(i_t)-m_t},\qquad
f'_t=e^{\log(f_t)+m_{t-1}-m_t},
$$
you get
$$
\bar c_t
= e^{-m_t}(f_t c_{t-1}+i_t z_t)
= f_t e^{m_{t-1}-m_t}\bar c_{t-1} + i_t e^{-m_t} z_t
= f'_t \bar c_{t-1} + i'_t z_t,
$$
and similarly
$$
\bar n_t
= e^{-m_t}(f_t n_{t-1}+i_t)
= f'_t \bar n_{t-1} + i'_t.
$$
So the stabilized recurrence is just the original recurrence written in a different scale. The hidden state is
$$
h_t = o_t \frac{\bar c_t}{\bar n_t} = o_t \frac{c_t}{n_t},
$$
because the same factor $e^{-m_t}$ multiplies both numerator and denominator and cancels exactly. That is the whole point of the stabilizer: it keeps the numbers from blowing up while preserving the normalized output.

The gradients are exactly unchanged for the same reason. The stabilized and unstabilized implementations compute the same function of the parameters, pointwise, not just approximately. If two formulas are algebraically identical, then their derivatives are identical wherever the derivative exists. Any dependence of $m_t$ on the gates does not introduce a new effect in the final output, because the $m_t$-terms cancel between $\bar c_t$ and $\bar n_t$. This is the same logic as the standard log-sum-exp/softmax stabilization: subtracting a common constant changes the numerics but not the function.

The only minor caveat is the usual one for $\max$: when the two arguments are exactly equal, the map is not differentiable. But that is a measure-zero case, and away from such ties the equality of outputs implies equality of gradients exactly.

So your intuition is right: the state and its normalizer are rescaled together, and because the model only uses their ratio, both the forward pass and the backpropagated gradients are unchanged.

### If the forget gate can be $\exp(\tilde{f}_t) > 1$, how is it still a forget gate rather than an amplification gate?
Question:
In a standard LSTM, the forget gate is in $(0,1)$, so it is easy to interpret as decaying old memory. In xLSTM, the forget gate can optionally be exponential, so it can exceed $1$. That seems to mean the old state can be amplified instead of forgotten. Is that intentional? If yes, how should I interpret the term "forget gate" in this setting? Also, what stops the recurrence from becoming unstable if the model repeatedly chooses $f_t > 1$ over many time steps?
Answer:
Yes, it is intentional, and the name “forget gate” is a bit of a historical carry-over from the standard LSTM.

In the original LSTM, the forget gate $f_t \in (0,1)$ really is a pure decay factor: it can only shrink the previous cell state, never increase it. In xLSTM, the authors deliberately relax this by allowing an exponential parameterization, $f_t = \exp(\tilde f_t)$, so $f_t$ can exceed $1$. The point is not to make the network “amplify memory” in an uncontrolled way, but to give it more expressive control over how strongly the previous state should be weighted relative to the new input. The paper explicitly says that exponential gating is introduced to help xLSTM “revise storage decisions,” which is exactly the kind of behavior you cannot get if the forget factor is restricted to $(0,1)$ as in a vanilla LSTM.

The key thing is that xLSTM does not use $f_t$ in isolation. In the sLSTM, both the cell state and a normalizer state are updated by the same gate:
$$
c_t = f_t c_{t-1} + i_t z_t, \qquad n_t = f_t n_{t-1} + i_t,
$$
and the hidden state is then normalized as
$$
h_t = o_t \, \frac{c_t}{n_t}.
$$
So even if $f_t > 1$, the model is not simply letting the raw memory blow up; it is changing the relative weighting of old and new information in a normalized representation. In that sense, $f_t$ is better thought of as a multiplicative retention weight than as a literal “forget factor” that must be less than $1$. The old name survives, but the role is slightly more general.

As for stability, the paper is very explicit that exponential gates can cause overflow, and that is why it introduces the stabilizer state $m_t$:
$$
m_t = \max\!\bigl(\log(f_t) + m_{t-1}, \log(i_t)\bigr),
$$
followed by stabilized gates $f_t'$ and $i_t'$. This is essentially the same idea as the numerically stable log-sum-exp trick: the computation is rescaled so that large exponentials do not explode numerically. The paper states that replacing $f_t$ and $i_t$ by $f_t'$ and $i_t'$ does not change the network output or the derivatives of the loss, so the stabilization is not just a heuristic; it is an equivalent reparameterization of the same computation.

So the short answer is: yes, $f_t > 1$ is deliberate. In xLSTM, the “forget gate” is really a gate controlling the relative influence of past state, not necessarily a strict decay coefficient. The architecture stays stable because the raw exponential gates are always used together with normalization and the stabilizer $m_t$, which prevents runaway growth in the effective computation. The paper even notes, in its limitations, that the initialization of the forget gates must be chosen carefully, which is another reminder that the stability is handled by the design, not by restricting $f_t$ to $(0,1)$ as in a standard LSTM.

### How is the mLSTM retrieval formula derived, especially the denominator $\max\{ |\mathbf{n}_t^\top \mathbf{q}_t|, 1 \}$?
Question:
The mLSTM retrieves memory using
$ \tilde{\mathbf{h}}_t = \mathbf{C}_t \mathbf{q}_t / \max\{ |\mathbf{n}_t^\top \mathbf{q}_t|, 1 \} $,
where $\mathbf{n}_t = f_t \mathbf{n}_{t-1} + i_t \mathbf{k}_t$. I understand the numerator somewhat: $\mathbf{C}_t$ is a sum of outer products, so multiplying by a query should mix stored values according to key-query similarity. But I do not understand the denominator. Why should the correct normalization depend on $\mathbf{n}_t^\top \mathbf{q}_t$ rather than, say, a norm of $\mathbf{q}_t$ or a softmax-like normalizer? And why do they take the absolute value and lower-bound it by $1$?
Answer:
The key point is that the denominator is not meant to be a mysterious “probability normalizer” like softmax. In mLSTM it is a stabilization and scale-correction term for a linear associative memory readout.

If you unroll the recurrences, the matrix state and the normalizer state have the form
$$
\mathbf{C}_t = \sum_{j \le t} \alpha_{j,t}\,\mathbf{v}_j \mathbf{k}_j^\top,
\qquad
\mathbf{n}_t = \sum_{j \le t} \alpha_{j,t}\,\mathbf{k}_j,
$$
where $\alpha_{j,t}$ collects the input gate at time $j$ and all later forget gates. Then the raw retrieval is
$$
\mathbf{C}_t \mathbf{q}_t
= \sum_{j \le t} \alpha_{j,t}\,\mathbf{v}_j\,(\mathbf{k}_j^\top \mathbf{q}_t).
$$
So each stored value $\mathbf{v}_j$ is weighted by the similarity $\mathbf{k}_j^\top \mathbf{q}_t$, exactly as in attention or fast-weight retrieval. Now look at the scalar
$$
\mathbf{n}_t^\top \mathbf{q}_t
= \sum_{j \le t} \alpha_{j,t}\,(\mathbf{k}_j^\top \mathbf{q}_t).
$$
This is the total “mass” of those same similarity weights. Dividing by it turns the readout into a normalized weighted average:
$$
\frac{\mathbf{C}_t \mathbf{q}_t}{\mathbf{n}_t^\top \mathbf{q}_t}
=
\sum_{j \le t}
\frac{\alpha_{j,t}(\mathbf{k}_j^\top \mathbf{q}_t)}{\sum_{\ell \le t}\alpha_{\ell,t}(\mathbf{k}_\ell^\top \mathbf{q}_t)}
\,\mathbf{v}_j.
$$
That is the natural derivation of the denominator: it is the matching normalization for the same key-query weights that appear in the numerator. A norm like $\|\mathbf{q}_t\|$ would normalize by query size, but it would not cancel the content-dependent scaling coming from the stored keys, so it would not give you a proper similarity-weighted average.

The paper’s extra $\max\{|\mathbf{n}_t^\top \mathbf{q}_t|,1\}$ is a practical stabilization trick, not a deeper theoretical change. The authors explicitly say that because the keys are zero-mean after layer norm, $\mathbf{n}_t^\top \mathbf{q}_t$ can be close to zero, so they take the absolute value and lower-bound it by $1$. The absolute value prevents sign flips in the denominator, which would otherwise make the readout change sign for purely accidental cancellation of key vectors. The floor at $1$ prevents division by a tiny number, which would blow up the output when the query does not strongly match the memory. In other words, if the retrieval signal is weak, the model falls back to an unnormalized readout rather than becoming numerically unstable.

So the short intuition is: $\mathbf{C}_t \mathbf{q}_t$ says “sum the stored values weighted by similarity,” $\mathbf{n}_t^\top \mathbf{q}_t$ says “how much total similarity is there?”, and the clamp makes that normalization safe. This is why the denominator depends on $\mathbf{n}_t^\top \mathbf{q}_t$, not on $\|\mathbf{q}_t\|$, and why it is absolute-valued and thresholded.

### Why does an outer-product update $\mathbf{C}_t = \mathbf{C}_{t-1} + \mathbf{v}_t \mathbf{k}_t^\top$ store key-value pairs at all?
Question:
The paper motivates mLSTM as an associative memory that stores a key $\mathbf{k}_t$ and value $\mathbf{v}_t$ by adding the outer product $\mathbf{v}_t \mathbf{k}_t^\top$ to a matrix memory. Later, retrieval is done by multiplying with a query $\mathbf{q}$. If I expand this, I get
$ \mathbf{C}_t \mathbf{q} = \sum_\tau \mathbf{v}_\tau (\mathbf{k}_\tau^\top \mathbf{q}) $,
so the result is a weighted sum of all stored values, not the exact value of a single matching key. Is the claim only approximate retrieval under near-orthogonality assumptions on the keys? If so, what role does the paper's assumption of zero-mean normalized keys play in reducing interference terms?
Answer:
Yes — but only in the sense that mLSTM is an **associative memory**, not an exact key-to-value lookup table.

The update $\mathbf{C}_t = \mathbf{C}_{t-1} + \mathbf{v}_t \mathbf{k}_t^\top$ stores each pair as a rank-one “association” inside a superposed matrix memory. When you later read with a query $\mathbf{q}$, you get

$$
\mathbf{C}\mathbf{q} = \sum_\tau \mathbf{v}_\tau (\mathbf{k}_\tau^\top \mathbf{q}),
$$

so the memory returns a weighted mixture of stored values. That is exactly the point: if the query is close to one stored key and nearly orthogonal to the others, then the matching term dominates and the output is approximately the corresponding value. In the idealized case where the keys are orthonormal, this becomes exact retrieval: if $\mathbf{q} = \mathbf{k}_s$, then $\mathbf{k}_\tau^\top \mathbf{q} = 1$ for $\tau=s$ and $0$ otherwise, so $\mathbf{C}\mathbf{q} = \mathbf{v}_s$.

So the paper is not claiming perfect dictionary-style lookup in arbitrary circumstances. It is using the classical BAM / fast-weight / covariance-memory idea: store many associations in a distributed way, then retrieve by content address. The cost of that linear/constant-memory design is that retrieval is **soft**, not hard.

The paper’s zero-mean assumption is precisely about making that soft retrieval work well. They say they apply layer normalization before projecting to keys and values, so the keys have zero mean. Intuitively, that means unrelated keys and queries are centered around having dot product near zero, so the cross-terms in

$$
\sum_{\tau \neq s} \mathbf{v}_\tau (\mathbf{k}_\tau^\top \mathbf{q})
$$

behave like noise with positive and negative contributions that tend to cancel rather than adding up coherently. In high dimensions, if the keys are also roughly normalized, random vectors are close to orthogonal, so the signal from the matching pair is much larger than the interference from the rest. This is why the paper says the covariance update is optimal for maximizing separability, equivalently signal-to-noise ratio, for the kind of retrieval they want.

The normalizer state in mLSTM is there for the same reason: it keeps track of the total “strength” of the stored key mass so that the readout is scaled sensibly,

$$
\tilde{\mathbf{h}}_t = \mathbf{C}_t \mathbf{q}_t \Big/ \max\{|\mathbf{n}_t^\top \mathbf{q}_t|, 1\}.
$$

So the short answer is: **yes, retrieval is approximate and relies on keys being sufficiently decorrelated; the zero-mean normalization helps make interference average out and keeps the retrieval stable.**

### In what sense is mLSTM fully parallelizable if its state update is still recurrent?
Question:
The mLSTM recurrence is written as
$ \mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top $
and
$ \mathbf{n}_t = f_t \mathbf{n}_{t-1} + i_t \mathbf{k}_t $.
At first glance this still looks sequential in time, because each state depends on the previous one. The paper says that, unlike sLSTM, mLSTM can be reformulated in a parallel version. Is this basically a prefix-scan over time, similar to how some linear attention or state-space models are parallelized? If yes, what exact property makes mLSTM parallelizable while sLSTM is not? Is it only the absence of hidden-to-hidden memory mixing?
Answer:
Yes — in the paper’s sense, “fully parallelizable” means that the mLSTM recurrence can be rewritten as a parallel prefix computation over time, even though it is written in recurrent form.

The key point is that each step of mLSTM has the special affine form
$$
\mathbf{C}_t = f_t \mathbf{C}_{t-1} + \mathbf{U}_t, \qquad
\mathbf{n}_t = f_t \mathbf{n}_{t-1} + \mathbf{u}_t,
$$
with
$$
\mathbf{U}_t = i_t \mathbf{v}_t \mathbf{k}_t^\top, \qquad \mathbf{u}_t = i_t \mathbf{k}_t.
$$
Crucially, in mLSTM the coefficients $f_t, i_t, \mathbf{q}_t, \mathbf{k}_t, \mathbf{v}_t, \mathbf{o}_t$ are computed from $\mathbf{x}_t$ only. There is no dependence on $\mathbf{h}_{t-1}$. So each time step defines a state update map of the form
$$
S \mapsto a_t S + b_t,
$$
and composition of such maps is associative. That is exactly the situation where a prefix-scan works: you can compute all prefix compositions in parallel, rather than stepping through time one token at a time. This is the same general trick used in scan-based parallelizations of some state-space models and linear recurrent models.

If you unroll the recurrence, you get
$$
\mathbf{C}_t
=
\left(\prod_{j=1}^t f_j\right)\mathbf{C}_0
+
\sum_{i=1}^t
\left(\prod_{j=i+1}^t f_j\right)
i_i \mathbf{v}_i \mathbf{k}_i^\top,
$$
and similarly for $\mathbf{n}_t$. That closed form makes the parallel structure obvious: each term depends on prefix products of scalar forget gates, which can be obtained by scan.

By contrast, sLSTM is not parallelizable in this way because its gates and cell input depend on the previous hidden state:
$$
\tilde z_t = \mathbf{w}_z^\top \mathbf{x}_t + r_z h_{t-1} + b_z,
\quad
\tilde i_t = \mathbf{w}_i^\top \mathbf{x}_t + r_i h_{t-1} + b_i,
\quad \text{etc.}
$$
So before you can even form the update at time $t$, you need $h_{t-1}$, which itself depends on earlier states. That hidden-to-hidden feedback is what the paper calls “memory mixing,” and it destroys the simple associative scan formulation.

So the short answer is: yes, mLSTM is parallelizable in essentially the prefix-scan sense, and the property that makes this possible is not the matrix memory itself but the absence of state-dependent recurrence in the gates. The recurrence remains mathematically sequential, but it is of a form that admits a parallel scan implementation.

### What do the authors mean by 'memory mixing', and why is it supposed to matter for state tracking?
Question:
The paper repeatedly contrasts sLSTM and mLSTM by saying that sLSTM has memory mixing and mLSTM does not, and then connects memory mixing to state tracking tasks like parity or formal languages. I am not sure I understand what counts as memory mixing here. Is it specifically the recurrent dependence of the gates and candidate update on the previous hidden state, such as terms like $r_i h_{t-1}$ or $\mathbf{R}_i \mathbf{h}_{t-1}$? If so, why does that make the model fundamentally more expressive for state tracking than architectures that only maintain a linear recurrent state or attention-style memory?
Answer:
Yes: in this paper, “memory mixing” is essentially the presence of hidden-to-hidden recurrence, i.e. the fact that the update at time $t$ depends on the previous hidden state $h_{t-1}$ through terms like $r_i h_{t-1}$ or, in the vector case, $\mathbf{R}\mathbf{h}_{t-1}$. But the important point is not just “there is recurrence”; it is that the current input is allowed to interact nonlinearly with the current internal state before the next state is formed. That is what the authors mean by mixing memory.

You can see the contrast in their formulas. In sLSTM, the candidate $z_t$ and the gates $i_t,f_t,o_t$ all depend on $h_{t-1}$, so the update at time $t$ is a function of both the new token and the already stored state. In mLSTM, by design, those gate and projection terms depend only on $x_t$, not on $h_{t-1}$, so the recurrence is carried by the matrix memory update itself, but without hidden-hidden mixing. That is why the paper says mLSTM “abandons memory mixing” and becomes parallelizable.

Why does this matter for state tracking? Because state tracking tasks like parity or formal languages are not just about storing information; they are about updating a discrete latent state according to transition rules. For parity, the model must effectively maintain one bit of state and flip it whenever it sees a $1$. More generally, for a formal language, the next state depends on both the current symbol and the current state. A model with memory mixing can implement this kind of state-dependent transition: the previous state can change how the new input is interpreted, and vice versa. In automata terms, the hidden state can behave like the finite control state of a machine.

By contrast, architectures that only maintain a linear recurrent memory, or that use attention-style memory retrieval, are better viewed as accumulation-and-readout systems. They can store summaries or retrieve past content, but they do not naturally provide a compact, nonlinear transition function that updates a discrete state step by step. That is why the paper connects memory mixing to state tracking expressivity and cites results and experiments showing that models without memory mixing fail on tasks like parity, while sLSTM succeeds.

So the short answer is: yes, the recurrent dependence of the gates and candidate on $h_{t-1}$ is exactly the kind of “memory mixing” the authors mean, and it matters because state tracking requires state-dependent transitions, not just a passive memory bank. That is also why the paper treats sLSTM and mLSTM differently: sLSTM keeps memory mixing and is aimed at state tracking, while mLSTM removes it to gain parallelism and a stronger associative memory.

### Why are multiple heads and multiple cells equivalent for mLSTM but not for sLSTM?
Question:
The paper says that for mLSTM, multiple heads and multiple memory cells are equivalent, while for sLSTM they are not because sLSTM allows memory mixing within a head. I do not see this equivalence clearly. If an mLSTM head has its own matrix memory, output gate, key/query/value projections, and no interaction with other heads, then I can imagine concatenating several such heads. But why is that the same as having multiple cells? Is the claim only about representational structure, or also about parameter count and computation? A concrete explanation with dimensions would help.
Answer:
The paper’s statement is best understood as a claim about the **state connectivity pattern**, not a deep difference in what the model can compute. For mLSTM, “multiple heads” and “multiple cells” are equivalent because there is no hidden-to-hidden memory mixing at all; for sLSTM, they are not equivalent because the recurrent matrices *do* mix cell states, and the head structure changes which states are allowed to interact.

For mLSTM, the recurrence is
$$
\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top,
\qquad
\mathbf{h}_t = \mathbf{o}_t \odot \frac{\mathbf{C}_t \mathbf{q}_t}{\max\{|\mathbf{n}_t^\top \mathbf{q}_t|,1\}}.
$$
There is no term of the form “other heads’ hidden states” inside the update. So if you split the model width into, say, $H$ parts of size $d_h$ with $d = H d_h$, then each part just carries its own matrix memory
$$
\mathbf{C}_t^{(1)}, \ldots, \mathbf{C}_t^{(H)}, \qquad \mathbf{C}_t^{(j)} \in \mathbb{R}^{d_h \times d_h},
$$
with corresponding $\mathbf{q}_t^{(j)}, \mathbf{k}_t^{(j)}, \mathbf{v}_t^{(j)} \in \mathbb{R}^{d_h}$. Whether you call these $H$ independent pieces “heads” or “cells” is just bookkeeping: the whole state is the direct sum of independent blocks, and concatenating the outputs gives the same function after a reshape. In that sense, the equivalence is structural, and with the usual blockwise implementation it also means essentially the same parameter count and computation for a fixed total width.

A concrete example makes this clearer. If $d=8$ and you choose $H=2$ with $d_h=4$, then mLSTM can be viewed as either two independent $4 \times 4$ memories or one tensor of shape $2 \times 4 \times 4$. Those are the same model written differently, because the update of block $1$ never depends on block $2$, and vice versa.

sLSTM is different because its hidden state is *mixed* through recurrent matrices. The paper writes the cell input and gates with terms like
$$
\tilde z_t = \mathbf{w}_z^\top \mathbf{x}_t + \mathbf{R}_z \mathbf{h}_{t-1} + b_z,
$$
and similarly for $\tilde i_t, \tilde f_t, \tilde o_t$. Here $\mathbf{h}_{t-1}$ contains all cell outputs in the group, so $\mathbf{R}_z$ can be dense: one cell can influence another. If you now introduce heads and forbid mixing across heads, you are no longer just relabeling the same state; you are restricting $\mathbf{R}_z, \mathbf{R}_i, \mathbf{R}_f, \mathbf{R}_o$ to be block-diagonal across heads. That changes the model class. In other words, a “single head with many cells” allows mixing among those cells, while “many heads” isolates them.

So the short answer is: for mLSTM, heads and cells are equivalent because the recurrence is independent across blocks, making the distinction purely a reshaping of the state; for sLSTM, the recurrence couples cells, so the head partition determines which memories can talk to each other, and that is a real architectural difference.

### Why does xLSTM use post up-projection for sLSTM blocks but pre up-projection for mLSTM blocks?
Question:
In the architecture section, the paper says that sLSTM blocks use a residual block with post up-projection, while mLSTM blocks use pre up-projection. The argument references Cover's theorem and says that for mLSTM the memory capacity becomes larger in the high-dimensional space. I am having trouble connecting those ideas. Why is it better to summarize the past in the original space for sLSTM but in the expanded space for mLSTM? Is this a theoretical consequence of the different memory structures, or mainly an empirical design choice that happened to work better?
Answer:
The short answer is that the placement is chosen to match the bottleneck of each memory type, not because there is a strict theorem that says “sLSTM must be post-projected” and “mLSTM must be pre-projected.”

In the paper, the authors use Cover’s theorem as intuition: if you move a problem into a higher-dimensional feature space, different patterns are more likely to become linearly separable. That intuition is especially relevant for the mLSTM, because its memory is a matrix $\mathbf{C} \in \mathbb{R}^{d \times d}$ updated by outer products $\mathbf{v}_t \mathbf{k}_t^\top$. In other words, mLSTM is an associative memory whose capacity really does grow with the feature dimension. If you project the input up first, the keys, queries, and values live in a richer space, and the matrix memory can store and separate more histories with less interference. So for mLSTM, “summarize in the expanded space” is a natural fit: the memory itself benefits from being wide.

For sLSTM, the situation is different. Its memory is scalar-valued per cell, and its main novelty is not raw storage capacity but gating and memory mixing, i.e. the ability to revise and combine information across cells and heads. That mechanism is already doing the hard sequential work in the model’s original width. So the block is arranged so that the recurrent part first produces a compact summary in the base space, and only then the residual block expands it. This is closer to the usual Transformer-style pattern: do the sequence-dependent computation in the model width, then use the up-projection to enrich the representation for the next layer.

So the distinction is mostly architectural and motivated by the memory structure. For mLSTM, the memory capacity itself scales with dimension, so pre up-projection directly helps the mechanism the authors want to strengthen. For sLSTM, widening before the recurrent update would not address its main advantage as directly, while post up-projection keeps the recurrent core compact and efficient.

I would read this as a theory-guided design choice, not a proven necessity. Cover’s theorem provides the intuition for why higher-dimensional summaries can be easier to separate, but the exact “pre for mLSTM, post for sLSTM” split is an empirical architecture decision informed by the different memory dynamics. The paper’s experiments suggest that this choice works well, but it is not presented as a mathematical consequence that must hold in every setting.

### Is mLSTM fundamentally different from linear attention or RetNet, or mostly a gated reparameterization of the same idea?
Question:
The mLSTM equations look very similar to several linear-attention-style models: there is a recurrent matrix state that accumulates outer products, a query-based readout, and a normalization term. The related work section also mentions Retention, Linear Transformer, RWKV-5/6, and HGRN2 as using similar covariance-style updates. So what is the conceptual difference between mLSTM and those models? Is the novelty mainly the LSTM-style gating and how it is integrated into a residual stack, or is there a deeper distinction in what functions the model can represent?
Answer:
At the level of the raw recurrence, mLSTM is very close to the linear-attention / RetNet / RWKV / fast-weight family, and the paper explicitly says so. Its core memory update is

$$
\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top,
$$

with a query-based readout

$$
\tilde{\mathbf{h}}_t = \mathbf{C}_t \mathbf{q}_t \big/ \max\{|\mathbf{n}_t^\top \mathbf{q}_t|, 1\}.
$$

That is the same basic pattern as a covariance-style associative memory: accumulate outer products of keys and values, then retrieve with a query. The paper even notes that this update is equivalent to Fast Weight Programmers and that related methods such as Retention, Linear Transformer, RWKV-5/6, and HGRN2 use similar covariance-style mechanisms. So if by “fundamentally different” you mean “does it compute something qualitatively unlike those models?”, the answer is mostly no.

What mLSTM adds is not a new algebraic primitive so much as an LSTM-style parameterization and stabilization of that primitive. The forget gate acts like a learned decay rate, the input gate like a learned learning rate, the output gate controls what is exposed, and the normalizer state $\mathbf{n}_t$ keeps track of gate mass so the retrieval stays numerically well behaved. The paper also uses exponential gating with stabilization, which is one of its main architectural changes. In that sense, mLSTM is best thought of as a gated, stabilized fast-weight/linear-attention mechanism packaged as an LSTM memory cell, not as a wholly different attention model.

The deeper distinction in the paper is actually elsewhere: the authors’ stronger expressivity claim is tied to memory mixing, which they discuss for sLSTM, not mLSTM. For mLSTM, “multiple heads and multiple cells are equivalent as there is no memory mixing.” That means mLSTM is mainly about higher storage capacity and associative retrieval, as shown by their key-value recall experiments, while the broader xLSTM story is about combining this with residual blocks and, in sLSTM, memory mixing for state-tracking-like problems. So I would summarize it this way: mLSTM is mostly a gated reparameterization of the same core idea as linear attention/RetNet-style associative memories, with the novelty coming from the LSTM framing, exponential gating, normalization, and its use inside xLSTM blocks, rather than from a fundamentally new memory computation.

### Why is only the key projection scaled by $1/\sqrt{d}$ in mLSTM, but not the query projection?
Question:
In the mLSTM definition, the paper uses
$ \mathbf{k}_t = \frac{1}{\sqrt{d}} \mathbf{W}_k \mathbf{x}_t + \mathbf{b}_k $,
while the query is simply
$ \mathbf{q}_t = \mathbf{W}_q \mathbf{x}_t + \mathbf{b}_q $.
In Transformer attention, I am used to seeing the dot product $\mathbf{q}^\top \mathbf{k}$ scaled, not just the key. Is this choice equivalent in expectation, or is there a specific reason to scale only the keys here? I am wondering whether this is meant to keep the outer-product memory update $\mathbf{v}_t \mathbf{k}_t^\top$ at a stable magnitude.
Answer:
In mLSTM the choice is not just a cosmetic rewrite of Transformer attention. In a Transformer, scaling $q^\top k$ by $1/\sqrt{d}$ is mainly about keeping the variance of the dot product under control. In mLSTM, however, the key vector does double duty: it is used both in the readout and in the recurrent memory update,
$$
\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top,
\qquad
\mathbf{n}_t = f_t \mathbf{n}_{t-1} + i_t \mathbf{k}_t.
$$
So scaling $\mathbf{k}_t$ by $1/\sqrt{d}$ is a way of controlling the magnitude of the *stored state* itself, not just the final similarity score. This is exactly the kind of stability issue your intuition points to: it keeps the outer-product write $\mathbf{v}_t \mathbf{k}_t^\top$ and the normalizer update $\mathbf{n}_t$ in a reasonable range.

By contrast, $\mathbf{q}_t$ only appears at read time,
$$
\tilde{\mathbf{h}}_t = \mathbf{C}_t \mathbf{q}_t \big/ \max\{|\mathbf{n}_t^\top \mathbf{q}_t|,1\},
$$
so scaling $\mathbf{q}_t$ would not stabilize the memory update at all. If the denominator were just $|\mathbf{n}_t^\top \mathbf{q}_t|$, then moving a constant factor from $\mathbf{k}_t$ to $\mathbf{q}_t$ would leave the readout ratio essentially unchanged. But here the model also has the lower bound $\max\{\cdot,1\}$, so the two choices are not strictly equivalent in all regimes.

So the clean interpretation, grounded in the paper, is: scaling the keys is a variance/stability convention tailored to the covariance-style memory update. It is more natural here than scaling the queries, because the keys participate in both writing and normalization of the recurrent memory, while the queries only read from it.

### When the paper says xLSTM has constant memory complexity in sequence length, does that apply to training or only inference?
Question:
The paper states that, contrary to Transformers, xLSTM has linear computation and constant memory complexity with respect to sequence length. I can understand this at inference time, since the recurrent state size does not grow with context length. But during training, backpropagation through time usually requires storing activations for every time step, which sounds like memory growing with sequence length anyway. So is the claim about constant memory complexity only about the model state during inference, or are the authors assuming checkpointing/recomputation or a custom training algorithm?
Answer:
The short answer is: the paper’s “constant memory complexity with respect to sequence length” should be read as a statement about the model’s *recurrent state* in the forward pass, i.e. the inference/streaming setting, not as a claim that full end-to-end training with ordinary backpropagation is automatically $O(1)$ in sequence length.

What xLSTM changes relative to a Transformer is that, at each step, it only needs to carry a fixed-size state forward in time. For sLSTM that state is the cell/normalizer/stabilizer state, and for mLSTM it is the matrix memory plus its normalizer. So if you are generating tokens autoregressively, the memory you must keep does not grow with the context length the way a Transformer’s KV cache does. That is exactly the sense in which the paper contrasts xLSTM with Transformers in the “Memory and Speed Considerations” section, and it is also the sense used in the generation/throughput experiments.

During training, however, the usual issue still applies: if you unroll the recurrence over $T$ steps and use standard backpropagation through time, autograd typically has to retain intermediate activations for the backward pass, so training memory is generally at least linear in the unroll length, $O(T)$, unless you use checkpointing, recomputation, or truncated BPTT. The paper does not introduce a special training algorithm whose purpose is to make backprop itself constant-memory. In fact, the experimental setup uses fixed context lengths for training, and the long-context results are presented as extrapolation at evaluation time.

So the right interpretation is that xLSTM removes the *sequence-length growth of the model state*, which is a big practical advantage for inference and streaming, but it does not by itself eliminate the usual activation-memory cost of training through long unrolled sequences.

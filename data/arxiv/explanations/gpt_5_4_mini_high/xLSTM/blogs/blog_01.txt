\title{Blogs about the Paper: "xLSTM: Extended Long Short-Term Memory"}

# Why xLSTM Matters: The Surprising Return of LSTMs in the Age of Transformers

## LSTMs never disappeared — they just got overshadowed

Before Transformers became the default architecture for large language models, LSTMs were the workhorse sequence model. Their key idea was simple but powerful: keep a memory state, update it additively, and control that update with gates. That made them much better than vanilla recurrent networks at dealing with long sequences and vanishing gradients.

For years, LSTMs worked well on language generation, translation, handwriting, time series, reinforcement learning, and many other sequential tasks. But they also had clear limits. Standard LSTMs compress information into scalar memory cells, they process sequences step by step, and their gating is bounded in a way that can make it hard to revise earlier storage decisions. As model sizes and datasets grew, those limits started to matter more.

Then Transformers arrived with self-attention. Their big advantage was not just accuracy, but scalability: they could train efficiently in parallel and, at least for a while, scale better than recurrent models. That is why Transformers took over modern LLMs.

The xLSTM paper asks a very direct question: what happens if we keep the core LSTM idea, but fix the parts that make it struggle at scale?

## The main idea behind xLSTM

xLSTM is not just “an LSTM with more parameters.” It changes two fundamental pieces of the original design.

The first change is **exponential gating**. In a standard LSTM, gates use sigmoids, which keep values between 0 and 1. That is stable, but also restrictive. xLSTM replaces some of those gates with exponential activations, which gives the model more flexibility when deciding what to keep, overwrite, or forget. Because exponentials can blow up numerically, the paper adds normalization and a stabilization trick so the computation stays well-behaved.

The second change is the memory itself. Instead of relying only on a scalar cell state, xLSTM introduces two variants:

- **sLSTM**, which keeps a scalar memory but adds exponential gating and new memory mixing.
- **mLSTM**, which uses a **matrix memory** and a covariance-style update rule, making it much better at storing and retrieving key-value style information.

Both variants are then wrapped inside residual blocks and stacked into xLSTM architectures, just like modern deep LLMs are built from stacked residual Transformer blocks.

## sLSTM: better at revising what it remembers

The sLSTM is the more direct extension of the classic LSTM. It still has a scalar memory, but the new gating changes how memory gets updated and normalized. The paper’s motivation here is important: classic LSTMs can struggle when they need to revise an earlier storage decision.

A good way to think about this is a streaming search problem. Suppose the model is scanning a sequence and should keep the most relevant item seen so far. A standard LSTM may be too conservative or too weakly gated to replace an earlier memory with a better one. Exponential gating makes that update more expressive.

This matters for **state tracking** tasks, where the model must keep track of an evolving hidden state across a long sequence. The paper shows that sLSTM’s memory mixing helps on these kinds of problems, including formal-language tasks where the model has to maintain the right internal state rather than just memorize tokens.

## mLSTM: a bigger memory for key-value retrieval

The mLSTM goes further by turning the memory cell into a matrix. That lets it store richer associations than a scalar cell can. Instead of only preserving a compressed summary, it can store key-value pairs and retrieve values later using a query, much closer to an associative memory.

The paper uses a covariance update rule for this matrix memory. In simple terms, the model accumulates outer products of values and keys, so it can later recover stored information through matrix multiplication. This is closely related to fast weight ideas and bidirectional associative memory.

The big payoff is storage capacity. On tasks that require remembering many key-value pairs, mLSTM behaves much more like a powerful associative memory than a classical recurrent cell.

There is also an important systems angle here: mLSTM has no hidden-hidden memory mixing, so it can be reformulated in a parallel way. That makes it much easier to accelerate on GPUs than a fully sequential recurrent model.

## Why this is not just an academic tweak

What makes xLSTM interesting is that it addresses the three main reasons LSTMs fell behind:

First, it helps the model **revise storage decisions** instead of being stuck with weakly gated memory updates.

Second, it increases **memory capacity** with matrix memory instead of forcing everything into a scalar cell.

Third, it creates a path toward **better parallelization**, at least for the mLSTM variant.

In other words, xLSTM does not try to beat Transformers by copying them. It asks what an LSTM should look like if it were designed today for large-scale language modeling.

## What the experiments show

The paper tests xLSTM on a mix of synthetic tasks, long-context benchmarks, and large language modeling runs.

On synthetic tasks, the two variants show different strengths. The sLSTM helps with state tracking and formal-language style problems. The mLSTM does especially well on associative recall, where the model must store and retrieve many key-value pairs. On the Long Range Arena, xLSTM shows strong performance across the tasks tested.

The more important result is at language-model scale. On **15B tokens from SlimPajama**, xLSTM outperforms the compared Transformers, State Space Models, and recurrent baselines on validation perplexity.

The paper then scales up to **300B tokens** and evaluates models at 125M, 350M, 760M, and 1.3B parameters. Here, xLSTM again looks strong. It maintains low perplexity on longer contexts, even when the test context grows well beyond training length. In the paper’s validation and downstream-task evaluation, xLSTM is the best method in the vast majority of cases. On PALOMA’s 571 text domains, the mLSTM-only version performs better than Mamba on 568 domains, better than Llama on 486, and better than RWKV-4 on 570.

The scaling-law plots also matter. They suggest that xLSTM is not a one-off win at a fixed size, but a model family with favorable scaling behavior as parameters and data grow.

## The practical takeaway

The paper’s core message is not that Transformers are obsolete. They are not. The point is that LSTMs were limited by specific design choices, not by the recurrent idea itself.

xLSTM shows that if you give LSTMs better gating and better memory, they can compete with modern architectures at LLM scale. That is a big deal for two reasons.

First, recurrent models still have an advantage in settings where **constant memory** and **linear sequence processing** matter. The paper reports that xLSTM scales linearly in generation time, unlike Transformer decoding, which grows quadratically with context length.

Second, xLSTM may be useful outside text generation. The authors explicitly point to reinforcement learning, time series prediction, and physical-system modeling as areas where this kind of compressive, stateful memory could be valuable.

## The catch

The paper is also clear about the current limitations. sLSTM is not fully parallelizable because memory mixing makes it sequential. mLSTM is parallelizable, but its matrix memory is computationally expensive. The implementation is not fully optimized yet, and the authors note that better CUDA kernels and broader tuning could improve results further.

So xLSTM is not a solved problem. It is a strong proof of concept.

## Bottom line

xLSTM is interesting because it changes the story around recurrent networks. Instead of treating LSTMs as a historical stepping stone to Transformers, the paper treats them as a design space worth revisiting with modern tools.

That leads to a simple but important conclusion: LSTMs were not outdated because recurrence was fundamentally wrong. They were outpaced because their memory and gating were too limited. xLSTM suggests that once those limits are addressed, recurrent models can still be serious contenders for large-scale sequence modeling.

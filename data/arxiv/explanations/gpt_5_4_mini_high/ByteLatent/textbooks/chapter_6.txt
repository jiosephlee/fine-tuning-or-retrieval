\title{A Textbook about the Paper: "Byte Latent Transformer: Patches Scale Better Than Tokens"}

Chapter 6: The Local Encoder: Turning Byte Sequences into Patch Representations

# Byte Embedding Lookup for the 256-Byte Vocabulary

The local encoder in BLT begins from the simplest possible raw input representation: individual bytes. Because bytes take values in a fixed range of $256$ possibilities, the model starts with an embedding lookup matrix of shape $\mathbb{R}^{256 \times h_{\mathcal{E}}}$. Each byte $b_i$ is mapped to a learned vector $x_i$ in this embedding space. This is the first step in converting raw byte sequences into something a transformer can process.

The choice to embed bytes directly is important because BLT is designed to operate without a fixed vocabulary of tokens. Instead of assuming that the input has already been segmented into words or subwords, the model begins with the universal byte alphabet. This means every possible text string can be represented in the same basic format, regardless of language, orthography, or domain. The encoder therefore does not depend on a tokenizer to decide what counts as a unit of input.

At this stage, however, the embedding of a single byte is only a local and very narrow view of the sequence. A single byte can tell the model which character fragment is present, but it cannot directly express how that byte fits into a larger pattern. The local encoder therefore does not stop at these raw byte embeddings. Instead, it augments them with information from surrounding bytes and then uses attention mechanisms to organize the result into patch representations.

# Why Single-Byte Embeddings Are Not Enough

A raw byte embedding captures identity, but not enough context. Many linguistic and structural patterns in text are not determined by one byte alone, but by how that byte combines with nearby bytes. For example, a byte can be part of a word, part of a prefix, part of a character sequence in another script, or part of a symbol in code or math. A single-byte embedding cannot distinguish these possibilities by itself.

BLT addresses this by explicitly modeling not just the current byte $b_i$, but also byte n-grams ending at position $i$. The paper’s motivation is that robust and expressive representations require the encoder to incorporate information about the preceding bytes. This is especially important because the local encoder is responsible for building patch representations from raw bytes at low cost. If it only knew the isolated identity of each byte, the patch representations would be much less informative.

The paper’s approach is to treat byte-level information and n-gram context as complementary. The raw byte embedding provides the base identity of the input, while the additional n-gram features supply a compressed summary of the immediate context. Together, they create a richer starting point for the encoder’s transformer layers and cross-attention pooling.

# Hash n-Gram Embeddings Over Byte n-Grams of Length 3 Through 8

BLT augments each byte with hash embeddings of the byte n-grams ending at that position. For each byte position $i$, the model constructs byte grams
$$
g_{i,n} = \{b_{i-n+1}, \ldots, b_i\}
$$
for $n$ ranging from $3$ to $8$. These are overlapping windows of the preceding bytes, so the model sees multiple scales of recent context at once. The smallest n-grams capture short local patterns, while the larger ones capture broader fragments.

The paper uses n-gram lengths from $3$ to $8$ because these sizes are long enough to encode useful subword structure without becoming too expensive. This gives the encoder a way to represent the current byte as part of multiple local contexts. The model is not trying to memorize entire words at this stage; rather, it is building features that reflect how bytes tend to appear together.

Each n-gram length gets its own embedding table. For each $n \in \{3,4,5,6,7,8\}$, the n-gram is mapped through a hash function into a fixed-size embedding table $E_n^{hash}$. This means that the model does not need to store a separate learned embedding for every possible n-gram, which would be impractical. Instead, the hash function compresses the space of n-grams into a manageable table size.

The result is that the encoder can represent many different byte patterns using a bounded amount of memory. This is the core idea behind the hash n-gram features: they provide contextual signal without requiring a fixed vocabulary of subwords.

# RollPolyHash and Fixed-Size Hash Tables

The paper defines the hash embedding lookup as
$$
e_i = x_i + \sum_{n=3,\ldots,8} E_n^{hash}(\text{Hash}(g_{i,n}))
$$
with
$$
\text{Hash}(g_{i,n}) = \text{RollPolyHash}(g_{i,n}) \% |E_n^{hash}|.
$$
The role of RollPolyHash is to convert the byte n-gram into an index in a fixed-size embedding table. The modulo operation ensures that the hash output always lies within the table size. The key idea here is not that the hash uniquely identifies every n-gram, but that it provides a fast and memory-bounded way to map many possible byte sequences into a learned feature space.

This design is useful because there are far too many possible byte n-grams to assign each one its own embedding directly. By using a hash table, BLT gains a compact approximation of n-gram identity. Different n-grams may collide in the same table entry, but the paper treats this as part of the tradeoff that makes the method practical at scale.

The paper also notes that the embeddings are normalized by the number of n-gram sizes plus one. That normalization keeps the scale of the augmented input under control as the model adds together the raw byte embedding and several hash-based features. Without this step, the input magnitude could grow simply because more features are being summed. Normalization ensures that the encoder receives a stable input representation regardless of how many n-gram terms contribute.

# Combining Raw Byte Embeddings with Hashed n-Gram Features

The encoder input for byte $i$ is formed by adding the raw byte embedding to the hash n-gram embeddings. In the paper’s notation, the augmented embedding is
$$
e_i = x_i + \sum_{n=3,\ldots,8} E_n^{hash}(\text{Hash}(g_{i,n})).
$$
This is a simple but powerful combination. The raw byte embedding preserves the identity of the current byte, while the hash n-gram features summarize the local context in which that byte appears.

This combination reflects a general design principle in the paper: the encoder should not force the model to choose between isolated byte identity and contextual structure. Instead, it should expose both at once. The raw embedding tells the model what the input is, while the n-gram features tell it something about what kind of sequence it is part of. For example, the same byte can occur in many different environments, and the n-gram features help distinguish those environments.

The paper reports that these hash n-gram embeddings are important for performance. In the ablations, hash embeddings help across domains, especially on Wikipedia and GitHub. The authors also find diminishing returns after about $300K$ hashes, indicating that the feature helps substantially, but only up to a point. In the encoder, this means the n-gram features are not a minor detail; they are one of the mechanisms that make the byte-level representation competitive with token-based models.

# Local Block-Causal Self-Attention Over a Fixed Byte Window

After constructing the augmented byte embeddings, the local encoder processes them with a transformer stack. The encoder is lightweight, with $l_{\mathcal E} << l_{\mathcal G}$ layers, because its purpose is not to do all the reasoning itself. Its purpose is to transform bytes into expressive patch representations efficiently.

The local encoder uses a local block-causal attention mask. Each byte attends only to a fixed window of $w_{\mathcal E}$ preceding bytes. This means the encoder can model local dependencies without paying the cost of full-sequence attention. The window is fixed, so the computational cost stays controlled even when the input is long.

The paper emphasizes that this local transformer can cross dynamic patch boundaries but cannot cross document boundaries. That detail matters because patch boundaries are not the same as semantic boundaries, and the encoder is allowed to build context across them when necessary. But it still respects document separation, so it does not mix unrelated text from different examples.

Intuitively, this local self-attention stage gives each byte a context-aware representation before the model decides how to pool bytes into patches. It is a way of refining the raw byte and n-gram features into a richer local state. Those refined states are then used by the encoder’s cross-attention block to produce patch-level representations.

# Pooling Byte Information to Initialize Patch Queries

A central step in the encoder is the conversion from byte-level states to patch-level queries. BLT does not simply average bytes into patches in a fixed way. Instead, the encoder first initializes each patch query by pooling the byte representations corresponding to that patch. The paper states that the query vector for each patch $p_j$ is initialized by pooling the byte representations in the patch and then applying a linear projection.

This is important because the patch representation should summarize the bytes inside the patch before it attends back to them. The pooling operation provides a first approximation of what the patch contains. It is a compact way to create a patch-level state from a variable number of byte representations. Since patches can be dynamically sized, the pooling step has to be able to handle different patch lengths naturally.

The paper notes that in the experiments, max-pooling is used to initialize the queries for the first encoder cross-attention layer. That means the encoder starts with the strongest byte-level signal within the patch as a summary. The exact pooling choice is part of the implementation, but conceptually the role is the same: to produce an initial patch query that is informed by the bytes it represents.

This step helps bridge the byte and patch levels. The local encoder is not just a byte model and not yet the global patch model. It is the module that constructs a patch representation from bytes in a way that preserves useful local content.

# Multi-Head Encoder Cross-Attention from Patches to Bytes

After pooling, BLT applies a cross-attention block inside the encoder. This block is modeled closely after the input cross-attention module of Perceiver, but adapted so that the latent representations correspond to patch representations rather than a fixed latent array. The encoder cross-attention uses multiple heads and a residual connection, with pre-LayerNorm on queries, keys, and values.

The purpose of this module is to let each patch representation gather information from the bytes inside that patch. In the paper’s formulation, the query for patch $j$ is derived from the pooled patch state, while the keys and values are projections of the byte representations. Formally, the queries come from the patch representation, and the keys and values come from the byte-level hidden states from the previous layer.

This is a crucial difference from ordinary self-attention. Instead of every byte attending to every other byte, the model lets a patch-level query summarize the bytes that belong to that patch. The result is a lower-dimensional representation that can be passed to the global transformer. In this sense, encoder cross-attention is a pooling mechanism, but one that is learned and content-dependent rather than fixed.

Because the attention is multi-headed, the model can collect different kinds of information from the same patch at once. The paper also notes that when patch representations are larger than the local model dimension, the cross-attention keeps the representations in multiple heads of dimension $h_{\mathcal E}$ and later concatenates them into dimension $h_{\mathcal G}$. This design matches the local and global modules while preserving a tractable computation pattern.

# Restricting Each Patch Query to Attend Only to Bytes Within That Patch

One of the most distinctive features of the encoder is that each patch query only attends to the bytes in its own patch. This is enforced by a patch-specific masking strategy. The patch representation is therefore built from the exact bytes that belong to that patch, rather than from the whole sequence.

This restriction is what makes the cross-attention act like a learned pooling operator instead of a global attention mechanism. It keeps computation localized and ensures that the patch representation is a summary of the intended byte group. Since patches are the units that the global transformer will operate on, each patch must faithfully represent its own content.

The paper’s masking choice also aligns with the larger BLT philosophy: compute should be allocated where it is needed. A patch that covers a simple and predictable region can be represented efficiently, while a more complex patch can still be summarized using the same mechanism, but with more meaningful local context. By restricting attention within the patch, the encoder maintains this localized structure and avoids wasting computation on unrelated bytes.

The absence of positional embeddings in this cross-attention module is also worth noting. The paper explicitly says that no positional embeddings are used there. The patch-local byte order is already present in the byte representations and the surrounding transformer layers, so the cross-attention block can focus on gathering content rather than encoding position again.

# Dimension Matching Between Local Encoder States and Global Patch States

The local encoder and the global transformer operate at different hidden dimensions. The local encoder uses states in dimension $h_{\mathcal E}$, while the global patch representations live in dimension $h_{\mathcal G}$. This means the encoder has to convert byte-level information into a form suitable for the global model.

The paper handles this by using the patch cross-attention block to produce patch representations that are later concatenated into the larger global dimension. In practice, the patch representations are maintained as multiple heads of dimension $h_{\mathcal E}$ during cross-attention and then concatenated into the $h_{\mathcal G}$ space. This makes the representation compatible with the global transformer without forcing the local encoder to be as expensive as the global model.

This dimension separation is part of BLT’s efficiency story. The local encoder is kept lightweight, so it can do the byte-level work cheaply. The global transformer is reserved for the patch-level computation that is more expensive but also more powerful. By keeping these responsibilities separate, BLT can spend most of its compute where patch-level reasoning is actually needed.

The decoder uses a mirrored version of this idea, but within the encoder alone the main point is that the byte-level representations are condensed into a patch-level format that can be passed to the global model. That condensation is what allows the overall architecture to scale more efficiently than a byte-only transformer would.

# Why the Encoder Design Improves Robustness and Representation Quality

The paper argues that the local encoder improves both robustness and representation quality because it works directly from bytes while still capturing structured local context. Direct byte modeling preserves information that tokenizers can obscure or discard. Since the encoder sees the raw byte sequence, it is sensitive to orthographic details, subword structure, and character-level variations that token-based systems may miss.

The hash n-gram features strengthen this effect by giving the encoder direct access to short byte patterns. This helps the model recognize local structure in words, code, and other byte sequences without relying on a fixed vocabulary. The paper’s robustness results later show that BLT performs well on noisy text, character-level tasks, and low-resource machine translation. Those gains are consistent with the encoder design, because the encoder preserves and organizes byte-level details rather than collapsing them into a static token inventory.

The local attention window also contributes to representation quality. It lets the encoder contextualize each byte with nearby bytes before patch pooling occurs. That means the patch summary is not just a bag of bytes; it is a learned summary of a locally contextualized sequence. The patch cross-attention then refines this summary into a representation that the global transformer can process efficiently.

In short, the local encoder improves BLT by doing three things at once. It preserves raw byte identity, augments that identity with hashed n-gram context, and then compresses the result into patch representations using local attention and patch-restricted cross-attention. This combination is what allows BLT to build expressive latent units from bytes at low cost, which is the central purpose of the encoder.

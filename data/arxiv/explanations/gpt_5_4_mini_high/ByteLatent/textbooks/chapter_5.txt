\title{A Textbook about the Paper: "Byte Latent Transformer: Patches Scale Better Than Tokens"}

Chapter 5: BLT at a High Level: A Hierarchical Byte-Level Language Model

# The Three-Part BLT Architecture: Encoder, Global Model, Decoder

BLT is built from three cooperating components: a local byte-level encoder $\mathcal{E}$, a large global autoregressive Transformer $\mathcal{G}$, and a local byte-level decoder $\mathcal{D}$. The central idea is that raw bytes are first turned into compact patch representations, those patch representations are processed by the large global model, and then the resulting patch outputs are expanded back into raw bytes. In other words, BLT does not replace bytes with tokens. Instead, it inserts a learned middle level of representation between bytes and the large Transformer.

This makes BLT a hierarchical model. The hierarchy is not merely conceptual; it is built directly into the computation graph. The local encoder and local decoder are both much smaller than the global model, with $l_{\mathcal{E}} \ll l_{\mathcal{G}}$ and $l_{\mathcal{D}} \ll l_{\mathcal{G}}$. The local models are responsible for handling byte-level detail, while the global model is responsible for the heavier sequence modeling over patches. That division of labor is the key to understanding the architecture. The model does not try to do everything at the byte level, and it does not discard byte-level information at the input. It keeps bytes at the interface and compresses them only where the computation is most expensive.

# Bytes as the Input and Output Interface of the Model

BLT works directly on raw bytes. On the input side, a byte sequence is represented as $b_i$, and each byte is embedded using a matrix with shape $\mathbb{R}^{256 \times h_{\mathcal{E}}}$, since there are 256 possible byte values. On the output side, the model predicts raw bytes again, denoted in the paper as $y_i$. So BLT is byte-in, byte-out. It does not require a fixed vocabulary of tokens to translate the text into model inputs or outputs.

This choice matters because it keeps the model close to the actual written signal. The architecture never loses access to the underlying byte sequence, which means that the model can reason over spelling, punctuation, and other character-level details directly. In the paper’s framing, tokenization is a heuristic preprocessing step that groups bytes into a static set of tokens, while BLT avoids that preprocessing step entirely. The local encoder and decoder are what make this possible: they let the model remain byte-native while still allowing the middle of the system to operate on compressed representations.

# Patch Representations as the Main Units of Global Computation

The middle of BLT does not operate on bytes. It operates on patches. A patch is a dynamically formed group of bytes, and the sequence of patches is shorter than the original byte sequence. If the original byte sequence has length $n$, patching maps it to a patch sequence of length $m < n$. The important point is that the global Transformer does not see individual bytes as its main units. It sees patch representations, which are latent summaries produced by the local encoder.

These patch representations are the main units of computation in BLT. The paper emphasizes that the computational cost of the model is primarily determined by the number of steps executed by the main Transformer, and in BLT that means the number of patches. A longer patch means fewer global Transformer steps. A shorter patch means more steps. So patch size is not just a descriptive property of the data; it is a control knob for how much computation the global model spends.

This is why patches are not just a different name for tokens. They are latent computational units. A patch representation is not drawn from a fixed vocabulary, and it is not a predefined symbol. It is a learned summary of a contiguous byte span, built to carry enough information for the global model to reason over. The local encoder constructs these representations, the global model transforms them, and the local decoder turns them back into bytes.

# Why the Global Latent Transformer Receives Most of the Compute Budget

The global latent Transformer $\mathcal{G}$ is the expensive part of BLT, and that is by design. It is the large autoregressive model in the middle of the system, and it uses a block-causal attention mask so that each patch can attend to previous patches and the current patch, but not future ones. Because it processes patch representations rather than bytes, it is the place where the model can spend substantial capacity without paying that cost on every byte.

This choice reflects an important observation in the paper: at scale, the main cost of a Transformer is not just attention, but also the large feed-forward layers that run at every step. If those steps are taken once per byte, cost becomes very high. If they are taken once per patch, cost drops. BLT therefore concentrates most of its parameter budget and flops in the global model while keeping the byte-level modules lightweight. The global model is the one that benefits most from being large, because it is the component that performs the main long-range reasoning over the compressed sequence.

The intuition is that not every byte deserves the same amount of global processing. Predicting the end of a common word is often easier than deciding what new word should begin a sentence. The paper uses this kind of example to motivate the architecture: the model should not pay the same global cost for every local prediction. Instead, it should reserve the heavy machinery for the places where the data are complex and uncertain.

# How Local Models Allow Byte Awareness Without Paying Full Global Cost on Every Byte

The local encoder and local decoder are what let BLT stay byte-aware while still being efficient. The local encoder reads byte sequences and turns them into patch representations. It uses a lightweight Transformer stack with a local block-causal attention mask, so each byte attends only to a fixed window of preceding bytes, and that window cannot cross document boundaries. This gives the encoder access to local byte context without forcing the expensive global model to process every byte directly.

The encoder also enriches byte representations with hash $n$-gram embeddings. The paper constructs byte grams from sizes 3 through 8, hashes them into embedding tables, and adds those embeddings to the byte embedding before normalization. The purpose is to give the local model richer awareness of the surrounding byte pattern. In other words, the local encoder is not a mere downsampler. It is a byte-level module that learns expressive representations of local structure before pooling them into patches.

The local decoder performs the complementary task. It takes the global patch outputs and reconstructs byte-level representations, then predicts raw bytes autoregressively. The decoder uses cross-attention in the opposite direction: bytes are the queries, and patch representations are the keys and values. This means the global model can remain compressed and efficient, while the decoder restores the fine-grained byte sequence. The result is a system where byte-level detail is preserved at the edges of the architecture, but the expensive part of the model is not forced to run at byte resolution throughout.

# Autoregressive Prediction in a Hierarchical Model

BLT remains autoregressive, but it is autoregressive at two levels. At the patch level, the global Transformer predicts patch outputs from previous patch inputs. At the byte level, the local decoder predicts each byte from previous bytes and the patch information supplied by the global model. So generation is not a single flat process. It is a nested one.

This nested structure is important because it keeps the model compatible with incremental generation. During generation, BLT must decide whether the current position is a patch boundary, since that decision determines whether more compute from the global Transformer should be invoked. The paper states this formally as an incremental patching property: a valid patching scheme must satisfy
$$f_p(\pmb{x}_{<i}) = f_p(\pmb{x})_{<i}.$$
This means that the patching of a prefix must not depend on future bytes. The architecture needs this property because generation proceeds left to right, and the model cannot wait for future bytes before deciding how to allocate computation to the current prefix.

This is where BLT differs from tokenization in an important way. The paper points out that BPE is not an incremental patching scheme, because the same prefix can be tokenized differently depending on the continuation. BLT, by contrast, is built so that patch boundaries can be determined incrementally. That makes the hierarchical autoregressive process workable at inference time. The model can generate, decide on patch boundaries, and then invoke the global Transformer only when needed.

# How BLT Dynamically Allocates More Compute to Harder Parts of the Sequence

The central mechanism for dynamic compute allocation is entropy patching. BLT uses a small byte-level language model to estimate the next-byte entropy at each position, and it places patch boundaries where the entropy indicates that the prediction is difficult. The paper gives two criteria: a global entropy threshold,
$$H(x_t) > \theta_g,$$
and an approximate monotonicity criterion,
$$H(x_t) - H(x_{t-1}) > \theta_r.$$
Both methods are ways of finding places where the next byte is unusually uncertain.

The intuition is straightforward. If the next byte is hard to predict, the model should spend more computation there. If the next few bytes are easy to predict, they can be grouped into a longer patch and processed with fewer global steps. This makes patches a form of adaptive compression. The model is not compressing all regions equally. It is compressing predictable regions more aggressively and uncertain regions less aggressively.

The paper’s examples make this idea concrete. The first byte of a word after a sentence boundary can be much harder to predict than the remaining bytes of the word. Likewise, structured content such as multiple choice questions can produce longer patches in repetitive regions, because the entropy model sees low uncertainty there. BLT therefore allocates more global compute where information density is high and less where it is low. That is the mechanism behind the claim that patches scale better than tokens.

# Why Operating Without a Fixed Patch Vocabulary Matters

A fixed vocabulary is one of the defining features of tokenization-based language models. Tokens are byte groups drawn from a finite set determined before training. BLT does something different. It uses patches, which are dynamically formed byte groups without a fixed vocabulary. This difference is not cosmetic. It changes how compute is controlled and how information is represented.

In tokenized models, increasing vocabulary size tends to make tokens larger on average, which reduces the number of steps the model takes, but also increases the size of the output projection layer. The paper stresses that this tradeoff leaves little room for major changes in token size and inference cost. BLT breaks that tradeoff. Because patches are not drawn from a fixed vocabulary, the architecture can vary average patch size without paying the same vocabulary cost that tokenizers impose.

Just as importantly, BLT preserves direct access to byte features. With tokens, the model only sees the token identity, not the underlying bytes. With patches, the local encoder reads the bytes directly and creates patch representations from them. That means the same byte sequence can be grouped differently depending on context, and the grouping can change to reflect prediction difficulty rather than a predetermined compression scheme. This flexibility is what makes BLT a hierarchical byte-level model rather than just a token model with a different segmentation rule. The patches are learned latent units of computation, not a new static vocabulary.

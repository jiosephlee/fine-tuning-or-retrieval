\title{Stack Exchange of the Paper: "The Era of 1-bit LLMs: All Large Language Models are in 1.58 Bits"}

### Why is a ternary weight set $\{-1,0,1\}$ described as 1.58 bits instead of 2 bits?
Question:
In the paper "The Era of 1-bit LLMs", BitNet b1.58 uses weights in $\{-1,0,1\}$ and says that adding $0$ "results in 1.58 bits in the binary system". I thought three states usually need 2 bits to store if encoded directly. Is the 1.58 number just $\log_2 3$, meaning an information-theoretic lower bound, or do they actually pack weights so the average storage is close to 1.58 bits? I am confused about whether this is a theoretical naming convention or an actual implementation detail.
Answer:
The short answer is that the paper is using “$1.58$ bits” in an information-theoretic sense, not saying that a single ternary weight is literally stored in $1.58$ physical bits.

A ternary weight can take $3$ values: $\{-1,0,1\}$. If you ask, “how many binary bits are equivalent to $3$ equally possible states?”, the answer is the number $b$ such that $2^b = 3$, namely

$$
b = \log_2 3 \approx 1.585.
$$

That is where the $1.58$ comes from. So the name “BitNet b1.58” is basically a shorthand for “a model whose weights live in a ternary alphabet,” and the paper explicitly says they “added an additional value of $0$ to the original $1$-bit BitNet, resulting in $1.58$ bits in the binary system.”

But that does not mean the implementation stores each weight in a weird fractional-bit format. In practice, a direct fixed-length encoding of three states needs $2$ bits per weight, because $2$ bits can represent up to $4$ states and $1$ bit is not enough. The paper actually hints at this practical distinction: it says that latency and memory were measured with a $2$-bit kernel, and that there is still room for optimization. So the reported “$1.58$ bits” is the idealized entropy-equivalent cost of the ternary parameter set, not a claim that the current kernel literally achieves $1.58$ bits/weight in storage.

So the clean way to think about it is: $1$-bit weights mean binary weights, $2$-bit weights mean four-way quantization, and ternary weights sit in between. The number $1.58$ is just $\log_2 3$, i.e. the binary information content of three possible values. It is a naming convention grounded in information theory, not a statement about the exact packing format used by the implementation.

### If BitNet b1.58 uses 8-bit activations and full-precision embeddings, in what sense is it a "1-bit LLM"?
Question:
The paper repeatedly calls BitNet b1.58 a "1-bit LLM", but later it says the model is trained with 1.58-bit weights and 8-bit activations, and it also mentions that embeddings remain full precision when discussing memory trends. Should I interpret "1-bit LLM" as referring only to the linear-layer weights, since those dominate the parameter count and compute? Or is there a more precise definition being used in low-bit LLM papers?
Answer:
Short answer: yes, you should read “$1$-bit LLM” as a shorthand for the **quantized weight matrices in the Transformer blocks**, not as a literal statement that *every* tensor in the system is stored at one bit.

The paper is actually more precise than the slogan. BitNet b1.58 is described as a Transformer that replaces $\texttt{nn.Linear}$ with $\texttt{BitLinear}$, and it is “trained from scratch, with $1.58$-bit weights and $8$-bit activations.” The $1.58$ comes from the fact that the weights are ternary, taking values in $\{-1,0,1\}$, and a ternary symbol carries $\log_2 3 \approx 1.58$ bits of information. So the model is not really “one bit” in the strict sense; the paper is using “$1$-bit LLM” as a family label for a model whose core linear weights are extremely low precision.

That also explains the apparent mismatch with the embeddings. Later the paper explicitly notes that “the embedding remains full precision” when discussing memory trends. So the model is not uniformly low-bit end to end. The embedding table stays FP16/BF16, and the activations are $8$-bit. But the paper’s main argument is that the expensive part of an LLM is the dense matrix multiplications in the linear layers, and those are where the big wins come from. In that sense, the headline bit-width refers to the dominant computation and parameter blocks, not to every parameter in the entire implementation.

So the cleanest interpretation is: BitNet b1.58 is a **ternary-weight Transformer with $8$-bit activations and some full-precision components such as embeddings**. The “$1$-bit LLM” phrase is rhetorical/approximate; the more exact description is “a $1.58$-bit weight LLM.” That is also why the paper repeatedly emphasizes that the model “retains the benefits of the original $1$-bit BitNet” while being “$1.58$ bits” in the weights.

In other words, your intuition is right: the label is mainly about the **linear-layer weights**, since they dominate both parameter storage and compute, but the paper’s more precise claim is about **ternary weights plus $8$-bit activations**, not a literally all-$1$-bit model.

### How does the absmean quantization rule decide whether a weight becomes $-1$, $0$, or $1$?
Question:
The paper defines quantization as $\widetilde{W} = \mathrm{RoundClip}(W/(\gamma + \epsilon), -1, 1)$ with $\gamma = \frac{1}{nm}\sum_{ij}|W_{ij}|$. If I understand correctly, after scaling, values in roughly $[-0.5, 0.5)$ are rounded to $0$, larger positive values go to $1$, and larger negative values go to $-1$, with clipping for very large magnitudes. Is that the right interpretation? If so, is the threshold at $\pm 0.5(\gamma + \epsilon)$ the main thing deciding sparsity?
Answer:
Yes, that is essentially the right way to read it.

For each weight matrix, the paper first computes $\gamma$ as the mean absolute weight, $\gamma = \frac{1}{nm}\sum_{ij}|W_{ij}|$, then rescales each entry by dividing by $\gamma+\epsilon$, and finally applies nearest-integer rounding followed by clipping to $[-1,1]$. So if we write $x_{ij} = W_{ij}/(\gamma+\epsilon)$, then, ignoring the exact tie behavior of $\mathrm{round}$ at half-integers, values with $|x_{ij}| < 0.5$ become $0$, values with $x_{ij} \ge 0.5$ become $1$, and values with $x_{ij} \le -0.5$ become $-1$. The clipping only matters for unusually large magnitudes, where rounding might otherwise produce $2$, $-2$, etc.; clipping forces those back to $1$ or $-1$.

So in the original scale, the zero region is indeed approximately
$$
|W_{ij}| < 0.5(\gamma+\epsilon).
$$
That means sparsity is mainly determined by how many weights fall inside that interval after normalization. The important nuance is that this is not a fixed global threshold; it is adaptive to each weight matrix through $\gamma$. In other words, the model becomes sparse when a large fraction of a layer’s weights are small relative to that layer’s own average absolute weight. The paper’s “feature filtering” language refers exactly to this effect: entries near zero are quantized away to $0$, while larger-magnitude entries survive as $\pm 1$.

### Why use the mean absolute value $\gamma = \frac{1}{nm}\sum_{ij}|W_{ij}|$ as the quantization scale?
Question:
In BitNet b1.58, each weight matrix is divided by its average absolute value before rounding to $\{-1,0,1\}$. I can see how this normalizes the matrix, but I do not understand why the mean absolute value is preferred over something like the maximum absolute value, standard deviation, or a learned scale parameter. Is there an intuition for why absmean works especially well for ternary weights?
Answer:
The short answer is that the paper is not claiming that $\gamma = \frac{1}{nm}\sum_{ij}|W_{ij}|$ is mathematically optimal; it is choosing a very simple, robust per-matrix scale that works well with ternary rounding and keeps the whole method implementation-friendly. In fact, the paper’s explicit motivation is that this is “more convenient and simple for both implementation and system-level optimization.”

Intuitively, ternary quantization is trying to represent the *typical* weight scale with only three symbols: $-1$, $0$, and $1$. Dividing by the mean absolute value makes the average weight magnitude about $1$, so after rounding and clipping, values with small magnitude tend to become $0$, and values with typical or above-typical magnitude become $\pm 1$. That is a good fit for a ternary scheme, because neural weight matrices are usually centered near zero and contain many small weights that can be dropped without much harm.

Compared with $\max |W_{ij}|$, the mean absolute value is much less sensitive to outliers. If you normalize by the maximum, one unusually large weight can force the whole matrix to be scaled down so much that almost everything else rounds to $0$, which is exactly what you do *not* want. Standard deviation is also a reasonable scale estimate, but it is still an $L_2$-type statistic and therefore more influenced by large values than $\mathbb{E}|W|$; for these nearly zero-centered, often heavy-tailed weight distributions, the mean absolute value is usually a better proxy for the “typical” weight size. A learned scale could certainly be tried, but it would add extra parameters and complexity, whereas the paper’s design goal is a simple, hardware-friendly quantization rule that adapts automatically to each weight matrix.

So the intuition is not that absmean is uniquely special, but that it is a good robust estimate of the layer’s natural scale, and that is exactly what you want when your quantizer only has ternary outputs.

### How can matrix multiplication with ternary weights require almost no multiplications?
Question:
The paper says BitNet b1.58 changes the computation paradigm and that matrix multiplication "requires almost no multiplication operations". But the model still multiplies ternary weights by 8-bit activations. Is the idea that multiplying by $-1$, $0$, or $1$ can be replaced by sign flips, skips, and additions? If so, does this only become true on custom hardware, or can current GPUs also avoid most multiply instructions in practice?
Answer:
Yes — the point is exactly that a ternary weight turns a multiply into either a sign flip, a no-op, or an addition into the accumulator.

For one dot product, if the weights are $w_i \in \{-1,0,1\}$ and the activations are 8-bit integers $x_i$, then

$$
\sum_i w_i x_i
$$

can be implemented as

$$
\sum_{w_i=1} x_i \;-\; \sum_{w_i=-1} x_i,
$$

with the $w_i=0$ terms skipped entirely. So the “multiplication” is gone in the usual hardware sense: there is no general-purpose multiply needed for the main matrix multiply, just integer add/subtract and masking. That is what the paper means by “matrix multiplication requires almost no multiplication operations” and why it says BitNet’s matrix multiplication “only involves integer addition.”

The important distinction is between the mathematical operation and the hardware instruction. Mathematically it is still a matrix product, but hardware-wise the costly multiply-accumulate path is replaced by integer accumulation over ternary coefficients. There are still a few multiplies elsewhere in the model pipeline, for example in quantization/scaling and non-linear components, but the dominant linear layers are where the big saving comes from.

On your second question: this is not purely a custom-hardware trick, but custom hardware makes it much more attractive. The paper’s reported GPU results were measured with optimized software kernels, using FasterTransformer and a 2-bit kernel from Ladder, so current GPUs can بالفعل exploit much of this structure if you write specialized kernels. However, a stock dense GEMM kernel will not automatically “discover” that multiplying by $-1$, $0$, or $1$ can be replaced by sign changes and skips. To get the practical benefit on today’s GPUs, you need kernels tailored to ternary weights and low-bit activations. The paper’s hardware discussion is essentially saying that the same idea opens the door to even better speed and energy efficiency on hardware designed around these operations.

### What exactly does the paper mean by "feature filtering" from the extra $0$ weight value?
Question:
One claimed advantage over the original binary BitNet is that ternary weights explicitly support "feature filtering" because a weight can be $0$. I am not sure how to interpret that. Does a zero weight act like a learned gate that suppresses certain input channels, or is it more like unstructured sparsity? Why would adding the option of $0$ improve modeling ability so much compared with forcing every connection to be either $-1$ or $1$?
Answer:
In the paper, “feature filtering” is best read in the ordinary linear-algebra sense: if a weight matrix entry can be $0$, then that particular input feature contributes nothing to that particular output feature. For a linear layer $y = Wx$, a ternary weight $w_{ji} \in \{-1,0,1\}$ means each output coordinate is a signed sum of some inputs, with some inputs simply omitted. That is different from binary weights $\{-1,1\}$, where every connection must either add or subtract the input, so nothing can be truly turned off.

So yes, it is essentially a learned “off” state for individual connections, but not a separate gate module or MoE-style router. It is closer to unstructured sparsity at the weight level: the model can decide that some input channels are irrelevant for some outputs and set those connections to zero. The paper’s phrase “feature filtering” is a high-level way of saying that the model can suppress features rather than only invert them.

Why does that help? Because ternary quantization gives the model a much larger and more flexible set of linear maps than binary quantization. With only $\{-1,1\}$, the model must approximate every full-precision weight by either positive or negative influence, even when the best approximation would be “almost no influence.” Allowing $0$ lets small or unimportant weights collapse to exactly zero instead of being forced to the wrong sign, which reduces quantization error and improves expressiveness. In practice, that extra degree of freedom matters a lot in large transformers, where many connections are weak or redundant.

So the short version is: the paper is not claiming some exotic new gating mechanism. It is saying that ternary weights can explicitly drop connections, which makes the quantized linear layers more selective and easier to train. That extra selectivity is what they call “feature filtering,” and it is one of the reasons BitNet b1.58 can match FP16 performance better than the original binary BitNet.

### How are gradients computed through the non-differentiable rounding step in BitNet b1.58?
Question:
The quantization function includes a rounding operation, which is not differentiable in the usual sense. The paper says BitNet b1.58 is trained from scratch, but in the excerpt I read it does not explain how optimization works through $\mathrm{round}(\cdot)$. Are they maintaining full-precision latent weights and using a straight-through estimator during backpropagation, as in some quantization-aware training methods? Or is there some different trick inherited from the original BitNet paper?
Answer:
The paper does not introduce a new gradient trick for the rounding step. What it describes is a standard quantization-aware training setup: the model keeps real-valued latent weights $W$, forms the ternary weights in the forward pass as
$$
\widetilde W = \mathrm{RoundClip}\!\left(\frac{W}{\gamma+\epsilon}, -1, 1\right),
$$
and then uses $\widetilde W$ inside the linear layers. Since $\mathrm{round}(\cdot)$ is not differentiable, the only practical way to train this end to end is to use a surrogate gradient, i.e. a straight-through estimator or something equivalent, exactly as in the original BitNet style of training.

So the right intuition is: the discrete $\{-1,0,1\}$ weights are the forward-pass representation, but optimization is still happening over hidden full-precision parameters. Backprop does not “differentiate through” rounding in the literal mathematical sense; it approximates that step so SGD can update the underlying real weights.

The excerpt you quoted does not spell out the backward rule explicitly, but nothing in the paper suggests a different discrete-optimization trick. In other words, yes: the intended reading is that BitNet b1.58 is trained from scratch with latent floating-point weights and an STE-like gradient through the quantizer, inherited from the BitNet training recipe rather than being a new method introduced here.

### Why does scaling activations to $[-Q_b, Q_b]$ remove the zero-point in quantization?
Question:
The paper says that, unlike the original BitNet, activations are scaled per token to $[-Q_b, Q_b]$ "to get rid of the zero-point quantization". I am confused about this statement. In symmetric quantization, zero is often represented exactly anyway, so what zero-point are they avoiding here? Also, since some activations go through non-linearities like SwiGLU, why is symmetric per-token scaling still convenient?
Answer:
They are using “zero-point” in the standard **affine quantization** sense, not in the sense of “can the value $0$ be represented exactly?”.

In affine quantization, a real value $x$ is mapped to an integer code by something like

$$
q = \mathrm{round}(x/s) + z,
$$

where $s$ is the scale and $z$ is the **zero-point**: the integer code that should correspond to real zero. You need this offset when the integer range is not centered at zero, for example if you quantize into an unsigned range such as $[0, 255]$ or, in the paper’s notation, something like $[0, Q_b]$.

What BitNet b1.58 does instead is use a **symmetric signed range** per token:

$$
q = \mathrm{clip}\big(\mathrm{round}(x/s), -Q_b, Q_b\big),
$$

so real zero maps to integer $0$ automatically. There is no separate offset term $z$, hence no “zero-point quantization” to deal with. That is all the paper means by “getting rid of the zero-point”.

This is why the paper says it is “more convenient and simple”: with symmetric quantization, the kernel only needs a scale and a signed integer range. With asymmetric quantization, you also have to subtract/add the zero-point in the implementation, which complicates both the math and the low-level code.

As for SwiGLU and other nonlinearities: they do not cause a problem here because the quantizer is not assuming linearity of the activation; it just quantizes whatever tensor comes out. A per-token scale is actually a good fit for this, since the dynamic range can vary a lot from token to token, especially after nonlinearities. If a particular activation tensor happens to be mostly positive, symmetric quantization is still valid — it just means some of the signed integer range goes unused. The paper explicitly says this simplification has negligible effect on performance.

So the short version is: they are not “making zero representable” — zero already is. They are removing the **offset/zero-point parameter** that asymmetric quantization would require.

### What does it mean that BitNet b1.58 "matches" FP16 starting from 3B parameters?
Question:
The paper says BitNet b1.58 matches the FP16 LLaMA-like baseline starting from 3B model size, using the same training tokens. I am unsure how to interpret "matches" here. Does it mean statistically indistinguishable perplexity, similar average zero-shot accuracy, or just that the gap becomes small enough to be practically irrelevant? I am also wondering whether the main story is that quantization hurts small models more than large models, which would imply a different scaling behavior rather than simple parity.
Answer:
In this paper, “matches” should be read as an empirical, benchmark-level statement, not as a formal claim of statistical indistinguishability. The authors compare BitNet b1.58 and their reproduced FP16 LLaMA-like baseline at the same model size and with the same training-token budget, and they report that from the $3\text{B}$ setting onward the BitNet models are roughly on par with the FP16 models on the metrics they actually evaluate: validation perplexity on WikiText2 and C4, and average zero-shot accuracy on the task suite they list. They do not present confidence intervals, hypothesis tests, or an equivalence threshold, so “matches” here means “close enough that, in their reported tables and plots, the gap is essentially gone for practical purposes.”

So I would not interpret it as “exactly the same perplexity” or “statistically indistinguishable” in a strict sense. It is better understood as “the degradation from ternary weights has become small enough that, under their training recipe, the quantized model reaches baseline-level performance.” The paper’s own wording supports this: they say the performance gap narrows as the model size increases, and that BitNet b1.58 can match the full-precision baseline starting from $3\text{B}$ size. That is a relative claim about the scaling trend, not a theorem.

Your second intuition is also basically right: the paper is showing a scaling effect, namely that the ternary constraint seems more costly at small scale and less costly at larger scale. The authors explicitly say the gap narrows with model size, and they even go further by reporting that a $3.9\text{B}$ BitNet can outperform a $3\text{B}$ FP16 baseline while being cheaper to run. That is consistent with the idea that larger models have enough capacity to absorb the loss from low-precision weights better than smaller ones. But the paper does not prove a general law that “quantization hurts small models more”; it only provides this as an observed trend in their experiments.

So the cleanest reading is: BitNet b1.58 is not claiming miraculous exact parity at every size and every task. Rather, the authors are saying that by $3\text{B}$ parameters, under the same data and training setup, the ternary model reaches roughly the same overall quality as their FP16 reference, while being much cheaper at inference. That is why they frame it as a new scaling regime: performance stays competitive while cost drops substantially.

### Why do the memory savings and latency speedups improve as the model size increases?
Question:
The paper reports that BitNet b1.58 becomes relatively faster and more memory efficient at larger scales, for example reaching a $4.1\times$ speedup at 70B. The explanation mentions that the time cost of linear layers grows with model size and that embeddings remain full precision, so their fraction of total memory shrinks. Could someone explain this more concretely? Is the trend mainly because quantized linear layers dominate larger models, while the unquantized components become a smaller percentage of the total?
Answer:
Yes — that is essentially the right intuition, and the paper is making an Amdahl’s-law argument in disguise.

The key point is that BitNet b1.58 only changes the parts of the Transformer that are dominated by linear layers, i.e. the matrix multiplications inside the attention and MLP blocks. Those are the expensive pieces, and the paper explicitly says that “the time cost for $\mathrm{nn.Linear}$ grows with the model size.” If you write the total latency as

$$
T_{\text{FP16}} = T_{\text{linear}} + T_{\text{other}},
\qquad
T_{\text{BitNet}} = \alpha T_{\text{linear}} + T_{\text{other}},
$$

with $\alpha < 1$ because the linear layers are much cheaper in BitNet, then the speedup is

$$
\frac{T_{\text{FP16}}}{T_{\text{BitNet}}}
=
\frac{T_{\text{linear}} + T_{\text{other}}}{\alpha T_{\text{linear}} + T_{\text{other}}}.
$$

This ratio gets larger when $T_{\text{linear}}$ makes up a bigger fraction of the total. That is exactly what happens as the model grows: the repeated Transformer blocks contribute more and more of the runtime, while things like embeddings, norms, softmax, and other non-linear bookkeeping become a smaller slice of the pie. So the same optimization on the linear layers buys you a bigger relative gain at 70B than at 3B.

The memory story is similar. The paper says that the embedding remains full precision, so its absolute size does not benefit from ternary weights. But the total parameter memory of the model grows mostly in the Transformer blocks, not in the embedding table, so the embedding becomes a smaller fraction of the whole as scale increases. If you think of memory as

$$
M_{\text{FP16}} = M_{\text{embed}} + M_{\text{linear}} + M_{\text{other}},
\qquad
M_{\text{BitNet}} \approx M_{\text{embed}} + \beta M_{\text{linear}} + M_{\text{other}},
$$

with $\beta \ll 1$, then the savings are largest when $M_{\text{linear}}$ dominates. That is why the relative memory reduction improves with model size.

So, yes: the trend is mainly because the quantized linear layers dominate larger models, while the unquantized components become a smaller percentage of the total. The paper says this directly for latency and memory, and even in the energy section it notes that “the percentage of $\mathrm{nn.Linear}$ grows with the model size.” The larger the model, the closer the overall cost gets to “mostly linear layers,” and the more BitNet’s ternary weights pay off.

### Why are the embeddings kept in full precision if the paper says every parameter is ternary?
Question:
Early in the paper, BitNet b1.58 is described as a model where "every single parameter (or weight)" is ternary in $\{-1,0,1\}$. Later, the memory discussion says that the embedding remains full precision, and that this is why its memory share matters less in larger models. Am I misunderstanding the scope of the ternary claim? Are token embeddings excluded from the "every parameter" statement, or is the implementation used for benchmarking slightly different from the conceptual model?
Answer:
You are reading the paper correctly: the “every single parameter (or weight)” sentence is a bit stronger than what the later implementation discussion actually supports.

The key detail is that the model architecture the paper describes is “a Transformer that replaces $\mathrm{nn.Linear}$ with BitLinear.” That is, the ternary constraint is applied to the linear projection weights inside the Transformer blocks. The embedding layer is not one of those linear layers; it is a separate lookup table. The paper then explicitly says in the memory discussion that “the embedding remains full precision,” which tells you how their benchmarked model is actually instantiated.

So the clean interpretation is:

the conceptual BitNet b1.58 idea is “all the linear weights in the Transformer are ternary,” but the experimental system still keeps the token embedding matrix in FP16/BF16.

That is why there is no contradiction in the results section: they are comparing a mostly ternary Transformer against a full-precision baseline, but with the embedding table left unchanged.

Intuitively, this also makes sense because embeddings are usually a much smaller fraction of the total parameter count than the transformer blocks, especially as the model gets larger. The parameter count in the blocks grows roughly with depth and with $d_{\text{model}}^2$, while the embedding matrix grows like $\lvert V \rvert \cdot d_{\text{model}}$. So as the model scales up, the embedding’s share of memory becomes less important, which is exactly what the paper says.

So yes: token embeddings are effectively excluded from the “every parameter” claim as written in the abstract, or more charitably, that claim is shorthand for the weights that BitNet b1.58 actually quantizes in the Transformer stack. The later memory discussion is the more precise statement about the implementation used for the reported benchmarks.

### How is the reported $71.4\times$ energy reduction calculated, and what is being excluded?
Question:
The paper states that BitNet b1.58 saves $71.4\times$ arithmetic operations energy consumption for matrix multiplication on 7nm chips, based on prior energy models. I am trying to understand what exactly is counted in this number. Does it only compare the energy of FP16 multiply-adds against INT8 additions inside the matrix multiplications, while ignoring memory traffic, control overhead, softmax, normalization, and embedding lookups? If so, how should I relate that number to the smaller end-to-end energy gains reported later?
Answer:
Yes, essentially. The paper’s $71.4\times$ figure is a **kernel-level arithmetic-energy estimate for the matrix multiplications only**, not an end-to-end inference measurement. The authors say they “focus mainly on the calculation for matrix multiplication” because it dominates LLM cost, and then use the energy model from prior work to compare the arithmetic cost of FP16 LLaMA versus BitNet b1.58 on 7nm chips. In that accounting, the FP16 baseline pays for both floating-point multiplication and addition, while BitNet’s ternary weights let the linear layers be implemented mostly with INT8 additions, so the estimated arithmetic energy for those GEMMs drops by a factor of $71.4$.

What is being excluded is everything outside that arithmetic core. So this number does not include memory traffic to and from DRAM/SRAM, kernel launch or control overhead, or the other transformer components such as RMSNorm, SwiGLU, rotary embedding, softmax, embedding lookups, and KV-cache movement. The paper is explicit that this is “arithmetic operations energy consumption for matrix multiplication,” which is much narrower than total model inference energy.

That is also why the later end-to-end energy gains are smaller. Whole-model energy is the sum of the matrix-multiplication part plus all the other parts, and only the former benefits from the huge BitNet reduction. If a fraction $f$ of the baseline energy is spent in linear layers, then reducing just that part by $71.4\times$ gives an overall gain of roughly $\frac{1}{(1-f)+f/71.4}$. Unless $f$ is extremely close to $1$, the total gain must be much smaller than $71.4\times$. The paper makes exactly this point when it notes that the end-to-end advantage grows with model size, because the share of energy spent in $\texttt{nn.Linear}$ increases while the “other components” become relatively less important.

So the right interpretation is: $71.4\times$ is the **best-case compute-side reduction for matrix multiplications**, while the end-to-end numbers are the **realistic full-inference savings** after all the non-matmul costs are included.

### What exactly is the "new scaling law" claimed for 1.58-bit LLMs?
Question:
The paper says BitNet b1.58 enables a "new scaling law" and then gives examples like 13B BitNet b1.58 being more efficient than a 3B FP16 model in latency, memory, and energy. I am confused because this sounds more like an empirical tradeoff curve than a formal scaling law of the usual kind. Is there an actual functional relationship being proposed between model size, training tokens, performance, and inference cost, or is "scaling law" being used loosely to mean that larger ternary models can dominate smaller full-precision ones under a fixed cost budget?
Answer:
In this paper, “new scaling law” is being used more loosely than in the classic Chinchilla-style sense of an explicit fitted law like $L(N,D) \approx aN^{-\alpha} + bD^{-\beta}$. The authors are not proposing a new closed-form relationship between model size, token count, and loss. What they actually show is an empirical Pareto shift in the performance-versus-cost curve.

The core claim is that a $1.58$-bit model can be scaled to a larger parameter count while still being cheaper to run than a much smaller FP16 model, because the weight representation and matrix multiplication are so much cheaper. In their experiments, BitNet b1.58 matches the full-precision baseline of the same size and training tokens starting around $3$B parameters, and then larger BitNet models become increasingly more efficient relative to smaller FP16 models. That is what underlies their examples like “$13$B BitNet is more efficient than $3$B FP16”: they are saying that, under the measured inference conditions, the larger ternary model sits below the smaller FP16 model on latency, memory, and energy, while achieving comparable or better task performance.

So the “scaling law” here is not a new mathematical law; it is a claim about how the Pareto frontier changes. In ordinary LLM scaling, if you want better performance you typically pay more in compute and memory. Their point is that with ternary weights, the slope of that tradeoff improves enough that increasing model size does not necessarily increase inference cost as much as it would in FP16, so you can get a larger and stronger model within the same budget. That is also why they say it “enables a new scaling law and recipe”: the recipe is to train and deploy much larger low-bit models instead of treating full precision as the default baseline.

The paper does contain one more scaling result with training tokens: they train a BitNet b1.58 model on $2$T tokens and show it outperforming StableLM-3B on several benchmarks. But again, that is evidence of scalability with more data, not a new formal law.

So the short answer is: yes, “scaling law” is being used somewhat loosely. The paper’s actual contribution is an empirical statement that ternary LLMs shift the cost-performance frontier, allowing larger models to dominate smaller FP16 ones under a fixed inference budget, rather than a new analytic scaling formula.

### Does reducing activations from 16 bits to 8 bits really double the maximum context length?
Question:
In the discussion section, the paper says BitNet b1.58 moves activations from 16 bits to 8 bits and therefore can double the context length under the same resources because of KV cache savings. I am not sure this follows automatically. KV cache memory is only one part of inference memory, and the cache stores keys and values rather than every intermediate activation. Is the doubling claim only approximately true when KV cache is the dominant memory cost, or is there some stronger argument?
Answer:
Yes, but only in the specific sense of a memory-budget argument for autoregressive decoding, not as a universal law.

What the paper is implicitly talking about is the KV cache, not “all activations” in the training sense. During generation, a transformer does not keep every intermediate activation for all past tokens; it mainly stores the keys and values for each previous token so that the next token can attend to them. That cache is the part of inference memory that grows linearly with context length. If you write the total memory as

$$M_{\text{total}} = M_{\text{fixed}} + L \cdot M_{\text{KV/token}},$$

where $M_{\text{fixed}}$ is the model weights plus other non-sequence-dependent overhead, and $L$ is the context length, then reducing the cache precision from 16 bits to 8 bits halves $M_{\text{KV/token}}$. Under the same memory budget, that gives

$$L_{\max}' = \frac{M - M_{\text{fixed}}}{M_{\text{KV/token}}/2} = 2L_{\max}.$$

So the doubling is actually exact if the only thing that changes is the per-token KV cache precision and the rest of the inference setup is fixed.

The important caveat is that this is still a first-order system-level statement, because real inference memory is not just the KV cache. There is also the fixed model footprint, temporary workspace, framework overhead, and sometimes other buffers. If those are large, or if they scale with sequence length too, then the realized context-length gain will be less than $2\times$. But in the regime the paper is referring to, the KV cache is usually the dominant term that grows with context, so halving its precision is precisely why one can say “the context length can be doubled given the same resources.”

So the right reading of the paper is: “under the same memory budget, and assuming the KV cache is the sequence-length bottleneck, 8-bit activations let you fit about twice as many cached tokens as 16-bit activations.” It is not claiming a stronger result than that.

### Is the claim of Pareto improvement fair when comparing BitNet b1.58 3.9B against an FP16 3B model?
Question:
The paper says BitNet b1.58 3.9B is a Pareto improvement over a 3B FP16 LLaMA-like model because it is faster, uses less memory, and performs better. I understand the practical point, but I am unsure about the comparison methodology. Since the BitNet model has more parameters, should I think of this as "under a fixed deployment budget, I can afford a larger ternary model", rather than a direct apples-to-apples architecture comparison? I want to make sure I am interpreting the Pareto claim correctly.
Answer:
Yes — your interpretation is the right one.

The paper is not claiming that a $3.9$B BitNet is a fair apples-to-apples replacement for a $3$B FP16 model in the narrow sense of “same parameter count.” Rather, it is making a Pareto claim in the deployment sense: for the objectives they care about — quality, latency, memory, and energy — the BitNet point is better even though it has more parameters, because each parameter is vastly cheaper to store and compute.

That is exactly why the comparison can make sense. A ternary weight matrix is not just “smaller FP16 by a constant factor”; it changes the cost structure. In the paper, BitNet b1.58 uses ternary weights in $\{-1,0,1\}$ and 8-bit activations, so the model can have more parameters while still occupying less memory and running faster than a smaller FP16 model. The paper explicitly reports that BitNet b1.58 $3.9$B is faster, uses less GPU memory, and performs better than the FP16 $3$B baseline. In Pareto terms, it dominates that baseline on the measured axes.

So the clean way to read the result is: under a fixed deployment budget, you can afford a larger BitNet because the per-parameter cost is much lower, and that larger model can sit on a better quality-cost frontier. It is not “same-size architecture comparison”; that role is played elsewhere in the paper when they say BitNet b1.58 matches FP16 baselines starting from $3$B at the same training setup.

One caveat is that this is still an empirical, system-dependent claim: the latency and memory numbers depend on the kernels and hardware used in the paper’s evaluation. But conceptually, yes — “Pareto improvement” here means better quality for lower deployment cost, not equal parameter count.

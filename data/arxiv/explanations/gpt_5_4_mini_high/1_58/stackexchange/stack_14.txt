\title{Stack Exchange of the Paper: "The Era of 1-bit LLMs: All Large Language Models are in 1.58 Bits"}

### Does reducing activations from 16 bits to 8 bits really double the maximum context length?
Question:
In the discussion section, the paper says BitNet b1.58 moves activations from 16 bits to 8 bits and therefore can double the context length under the same resources because of KV cache savings. I am not sure this follows automatically. KV cache memory is only one part of inference memory, and the cache stores keys and values rather than every intermediate activation. Is the doubling claim only approximately true when KV cache is the dominant memory cost, or is there some stronger argument?
Answer:
Yes, but only in the specific sense of a memory-budget argument for autoregressive decoding, not as a universal law.

What the paper is implicitly talking about is the KV cache, not “all activations” in the training sense. During generation, a transformer does not keep every intermediate activation for all past tokens; it mainly stores the keys and values for each previous token so that the next token can attend to them. That cache is the part of inference memory that grows linearly with context length. If you write the total memory as

$$M_{\text{total}} = M_{\text{fixed}} + L \cdot M_{\text{KV/token}},$$

where $M_{\text{fixed}}$ is the model weights plus other non-sequence-dependent overhead, and $L$ is the context length, then reducing the cache precision from 16 bits to 8 bits halves $M_{\text{KV/token}}$. Under the same memory budget, that gives

$$L_{\max}' = \frac{M - M_{\text{fixed}}}{M_{\text{KV/token}}/2} = 2L_{\max}.$$

So the doubling is actually exact if the only thing that changes is the per-token KV cache precision and the rest of the inference setup is fixed.

The important caveat is that this is still a first-order system-level statement, because real inference memory is not just the KV cache. There is also the fixed model footprint, temporary workspace, framework overhead, and sometimes other buffers. If those are large, or if they scale with sequence length too, then the realized context-length gain will be less than $2\times$. But in the regime the paper is referring to, the KV cache is usually the dominant term that grows with context, so halving its precision is precisely why one can say “the context length can be doubled given the same resources.”

So the right reading of the paper is: “under the same memory budget, and assuming the KV cache is the sequence-length bottleneck, 8-bit activations let you fit about twice as many cached tokens as 16-bit activations.” It is not claiming a stronger result than that.

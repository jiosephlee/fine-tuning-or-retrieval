\title{A Textbook about the Paper: "The Era of 1-bit LLMs: All Large Language Models are in 1.58 Bits"}

Chapter 8: Accuracy Results: Perplexity and Zero-Shot Task Performance

# What perplexity measures in language modeling

Perplexity is the paper’s main intrinsic measure of language modeling quality. Intuitively, it tells us how well a model predicts held-out text: when perplexity is lower, the model is assigning higher probability to the text it sees, which means it is making better next-token predictions. In this paper, perplexity is reported on WikiText2 and C4, so it serves as a direct check on whether BitNet b1.58 can still model language well even though its weights are restricted to the ternary set $\{-1,0,1\}$.

This matters because perplexity is not tied to any single downstream benchmark. It asks a more basic question than task accuracy: does the model itself represent the language distribution well? For the paper’s purposes, that is especially important, because the central claim is not only that ternary weights reduce cost, but that they do so without breaking the model’s ability to learn language in the first place.

# Why perplexity and end-task accuracy should both be reported

The paper reports both perplexity and zero-shot task accuracy because these two measurements capture different sides of the same model. Perplexity tells us whether the model is a good language model in the general sense, while end-task accuracy tells us whether that language modeling ability transfers to useful benchmark behavior. A model can sometimes look strong on one measure and weaker on the other, so using both is a more reliable way to judge whether the architecture really works.

This is especially important for BitNet b1.58 because the model changes the numerical representation of the weights very aggressively. If one only looked at perplexity, it would be possible to miss weaknesses on tasks that require broader reasoning or better instructionless generalization. If one only looked at task accuracy, it would be harder to tell whether improvements or regressions were caused by the model itself or by quirks of a benchmark. By reporting both WikiText2 and C4 perplexity alongside zero-shot accuracy on multiple tasks, the paper builds a more complete accuracy picture.

# The trend that the performance gap narrows as model size grows

A central empirical pattern in the paper is that the gap between BitNet b1.58 and the FP16 baseline shrinks as the model gets larger. This trend appears in both the perplexity results and the zero-shot accuracy results. In other words, the ternary model is not stuck permanently far behind the full-precision model; instead, increasing the number of parameters steadily reduces the difference.

The intuition is straightforward. A lower-precision model has less information stored per weight, so at small sizes it is easier for the representational constraint to hurt quality. But as the model grows, it has more parameters overall, and that extra capacity helps recover much of the lost expressiveness. The paper’s results show this effect clearly enough that, at practical model sizes, the ternary model no longer trails the FP16 baseline in a meaningful way.

# The key result that BitNet b1.58 matches FP16 performance starting at 3B parameters

The paper’s headline accuracy result is that BitNet b1.58 matches the full-precision LLaMA baseline starting at the 3B model size. This is true for both perplexity and end-task performance, using the same training recipe and the same number of training tokens. That is the most important threshold in the paper, because it marks the point where ternary weights stop being a quality liability under the reported setup.

This result is what makes the paper more than a cost-reduction story. If a low-bit model is always worse, then it is only useful when cost savings matter more than quality. But if it can reach parity with FP16 at the same scale and training budget, then the precision reduction becomes a viable model design choice rather than a compromise. The paper’s 3B result is the first evidence that this is possible for BitNet b1.58.

# Detailed interpretation of the WikiText2 and C4 perplexity results

The paper reports validation perplexity on both WikiText2 and C4 to check whether the trend is consistent across datasets. The key takeaway is that BitNet b1.58 starts to match the FP16 LLaMA baseline at 3B parameters in terms of perplexity. That means the ternary model is not merely performing well on one validation corpus; it is holding up on two different language modeling evaluations.

The same table also shows that this accuracy parity comes with a substantial cost advantage. At 3B scale, BitNet b1.58 is reported to be 2.71 times faster and to use 3.55 times less GPU memory than the FP16 baseline. So the perplexity result should be read together with the runtime result: the model is not just “good enough,” it is good enough while being significantly cheaper to run. That is why the paper treats the WikiText2 and C4 numbers as evidence of a genuine quality-efficiency trade-off shift, not just a narrow benchmark win.

The 3.9B result strengthens this interpretation even further. The paper reports that BitNet b1.58 at 3.9B is 2.4 times faster and uses 3.32 times less memory than the FP16 LLaMA 3B model, while performing significantly better. In terms of perplexity, this means that a slightly larger ternary model can move beyond parity and surpass a smaller FP16 model, all while remaining more efficient.

# Zero-shot accuracy trends across benchmark tasks

For the zero-shot evaluation, the paper uses a broad set of benchmarks: ARC-Easy, ARC-Challenge, Hellaswag, Winogrande, PIQA, OpenbookQA, and BoolQ. These tasks probe different aspects of language understanding, so the point of the evaluation is not to fit one particular test, but to see whether the model’s overall language competence transfers to several common benchmarks without task-specific training.

The same scaling story appears here as in the perplexity results. As model size increases, the performance gap between BitNet b1.58 and the FP16 baseline narrows, and by 3B parameters the paper says BitNet b1.58 can match the full-precision model. That is important because it shows the result is not limited to the language-modeling loss used for perplexity; it also appears in the practical benchmark setting that people often care about when comparing LLMs.

# Why the 3.9B BitNet b1.58 model is especially important

The 3.9B model is the most persuasive checkpoint in the paper because it does more than reach parity. It surpasses the FP16 3B baseline on the reported accuracy measures while retaining the efficiency benefits of ternary weights. In that sense, it is the clearest demonstration that BitNet b1.58 can offer both better quality and lower cost at the same time.

This matters for interpretation because a parity result can sometimes be dismissed as a narrow tie. The 3.9B result is stronger: it shows that once the model is pushed slightly larger, the ternary architecture can move from “matching” to “beating” a full-precision baseline of smaller size. That makes the paper’s claim much more convincing, because it shows the low-bit model is not merely competitive in principle; it can occupy a better operating point in practice.

# BitNet b1.58 3.9B versus FP16 3B: better quality at lower cost

The most concrete comparison in the paper is BitNet b1.58 3.9B against the FP16 LLaMA 3B baseline. On this comparison, the ternary model is not only more accurate on the reported perplexity and zero-shot metrics, but also cheaper to run, with lower latency and lower GPU memory use. The paper quantifies this as 2.4 times faster and 3.32 times less memory.

That combination is what makes the result so striking. Usually, improving quality means paying some cost in compute or memory, and reducing cost usually means accepting a quality drop. Here, the paper reports the opposite: a model that is both better and cheaper. For a student reading the paper, this is the most important practical takeaway, because it shows how BitNet b1.58 changes the standard trade-off between model quality and inference cost.

# The meaning of Pareto improvement in this setting

A Pareto improvement means that one option is better in at least one respect and no worse in the others. In the context of this paper, the relevant dimensions are accuracy measures such as perplexity and zero-shot task performance, together with inference costs such as memory and latency. If a model improves quality while also reducing cost, then it dominates the older point in that trade-off space.

That is why the authors describe BitNet b1.58 as a Pareto improvement over the compared FP16 models. The 3.9B versus FP16 3B result is the clearest example: the ternary model is better on accuracy and lower on cost. The broader message is that the paper is not just proposing a cheaper approximation to full precision, but a model family that can move the frontier of what is simultaneously achievable in quality and efficiency.

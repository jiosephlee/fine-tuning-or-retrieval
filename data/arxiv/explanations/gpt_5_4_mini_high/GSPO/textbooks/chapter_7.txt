\title{A Textbook about the Paper: "Group Sequence Policy Optimization"}

Chapter 7: GSPO-token: A Flexible Token-Level Variant

# Why multi-turn or structured tasks may need token-level advantage control

GSPO-token is introduced as a variant of GSPO for situations where a single advantage value for an entire response is too coarse. The paper explicitly points to multi-turn reinforcement learning as one such setting: in those cases, one may want a finer-grained advantage adjustment than the sequence level. The key idea is not to abandon GSPO’s sequence-level view of importance sampling, but to add flexibility in how the learning signal is distributed across tokens within a response.

This matters because the basic GSPO objective assigns one normalized advantage to the whole response. That is a natural fit when the reward is defined at the sequence level and no additional structure is needed. But if the learning problem calls for token-wise customization, then the model may benefit from letting different tokens carry different advantage values while still using the same sequence-level importance ratio to stabilize the update. GSPO-token is precisely the paper’s answer to that need.

# The GSPO-token objective

GSPO-token keeps the core GSPO structure but replaces the single response-level advantage with token-level advantages. The objective is

\[
\mathcal{J}_\text{GSPO-token}(\theta)
=
\mathbb{E}_{ x \sim \mathcal{D},\, \{y_i\}_{i=1}^G \sim \pi_{\theta_\text{old}}( \cdot | x) }
\left[ 
\frac{1}{G} \sum_{i=1}^{G} \frac{1}{|y_i|} \sum_{t=1}^{|y_i|} 
\min \left( s_{i,t}(\theta) \widehat{A}_{i,t},  \, \mathrm{clip} \left( s_{i,t}(\theta), 1 - {\varepsilon}, 1 + {\varepsilon} \right) \widehat{A}_{i,t} \right) 
\right].
\]

Here, $G$ is the group size, meaning the number of responses generated for the same query $x$. The response is still sampled from the old policy $\pi_{\theta_\text{old}}$, just as in GSPO and GRPO. The difference is that instead of giving every token in a response the same advantage, GSPO-token allows a token-specific advantage $\widehat{A}_{i,t}$.

The important structural point is that GSPO-token does not change the stabilizing idea behind GSPO. It still uses a sequence-level importance ratio, and it still clips that ratio to exclude overly off-policy samples from gradient estimation. What changes is the granularity of the advantage signal. In other words, the paper preserves sequence-level weighting while making the internal advantage assignment more flexible.

# The stop-gradient or detach trick in the ratio definition

To make the token-level objective compatible with sequence-level weighting, GSPO-token defines the token-level ratio as

\[
s_{i,t}(\theta) 
= \mathrm{sg} \left[ s_{i}(\theta) \right] \cdot \frac{ \pi_{\theta} (y_{i,t} | x, y_{i,<t}) }{ \mathrm{sg} \left[ \pi_{\theta} (y_{i,t} | x, y_{i,<t}) \right] }.
\]

The operator $\mathrm{sg}[\cdot]$ means “take the numerical value, but stop the gradient.” The paper notes that this corresponds to the \texttt{detach} operation in PyTorch. This construction is a bookkeeping device: it lets the objective be written in token-level form while ensuring that the sequence-level factor $s_i(\theta)$ remains the common weight attached to the response.

The role of the stop-gradient is subtle but important. The denominator of the token likelihood ratio is detached, so it does not contribute gradient. That means the ratio is not being used as an ordinary, fully differentiable fraction in which numerator and denominator both change together. Instead, the denominator is frozen at its numerical value, and only the numerator carries gradient information. This is how GSPO-token can keep the forward value of the ratio unchanged while preserving the desired gradient structure.

# Why the token factor is numerically equal to one

Because the numerator and denominator in the token factor have the same numerical value, the fraction

\[
\frac{ \pi_{\theta} (y_{i,t} | x, y_{i,<t}) }{ \mathrm{sg} \left[ \pi_{\theta} (y_{i,t} | x, y_{i,<t}) \right] }
\]

is numerically equal to $1$. Therefore, $s_{i,t}(\theta)$ is numerically equal to $s_i(\theta)$. This is exactly what the paper emphasizes: the token-level expression does not alter the value of the importance ratio in the forward pass.

The reason for writing it this way is not to change the number, but to organize the gradient computation. GSPO-token wants every token in the response to inherit the same sequence-level scaling factor, while still allowing token-specific advantage values $\widehat{A}_{i,t}$. The numerical equality to one is what makes this possible without introducing a new, incompatible notion of importance sampling at the token level.

This distinction between numerical value and gradient path is central to understanding the method. The factor equals one as a number, but it is still useful because it preserves the correct dependence on $\pi_\theta$ in the gradient. The paper’s construction ensures that the optimization remains sequence-level in its weighting, even though the objective is written token by token.

# Gradient derivation for GSPO-token

The paper derives the GSPO-token gradient by first omitting clipping for simplicity. Starting from the objective,

\[
\nabla_{\theta} \mathcal{J}_\text{GSPO-token}(\theta)
=
\nabla_{\theta} \mathbb{E}_{ x \sim \mathcal{D},\, \{y_i\}_{i=1}^G \sim \pi_{\theta_\text{old}}( \cdot | x) }
\left[ 
\frac{1}{G} \sum_{i=1}^{G}
\frac{1}{|y_i|} \sum_{t=1}^{|y_i|} 
s_{i,t}(\theta) \widehat{A}_{i,t}
\right].
\]

Using the stop-gradient construction, this becomes

\[
\mathbb{E}_{ x \sim \mathcal{D},\, \{y_i\}_{i=1}^G \sim \pi_{\theta_\text{old}}( \cdot | x) }
\left[ 
\frac{1}{G} \sum_{i=1}^{G} s_i (\theta) \cdot \frac{1}{|y_i|} \sum_{t=1}^{|y_i|} 
\widehat{A}_{i,t} \frac{ \nabla_{\theta} \pi_{\theta} (y_{i,t} | x, y_{i,<t}) }{ \pi_{\theta} (y_{i,t} | x, y_{i,<t}) }
\right],
\]

which can also be written as

\[
\mathbb{E}_{ x \sim \mathcal{D},\, \{y_i\}_{i=1}^G \sim \pi_{\theta_\text{old}}( \cdot | x) }
\left[ 
\frac{1}{G} \sum_{i=1}^{G}  
\left( \frac{ \pi_{\theta} (y_i | x) }{ \pi_{\theta_\text{old}} (y_i | x)} \right)^{\frac{1}{|y_i|}}
\cdot \frac{1}{|y_i|} \sum_{t=1}^{|y_i|}
\widehat{A}_{i,t} \nabla_{\theta} \log \pi_{\theta} (y_{i,t} | x, y_{i,<t})  
\right].
\]

The structure of this gradient is the key result. Each token contributes a log-likelihood gradient, but all tokens in the same response are multiplied by the same sequence-level factor $s_i(\theta)$. So GSPO-token does not reintroduce the unstable token-wise importance ratios that motivated GSPO in the first place. Instead, it keeps the stable sequence-level weighting and simply lets the advantage signal vary from token to token.

The paper’s derivation also highlights why GSPO-token is aligned with the basic principle of importance sampling. The response-level likelihood ratio is the meaningful object for correcting off-policy mismatch at the level where the reward is defined. The token-wise gradients then serve as the internal mechanism for distributing the learning signal according to $\widehat{A}_{i,t}$.

# How GSPO-token preserves sequence-level weighting while allowing token-wise advantages

The simplest way to understand GSPO-token is to separate two roles. The sequence-level importance ratio $s_i(\theta)$ decides how strongly a sampled response should influence learning, based on how far that response under $\pi_\theta$ deviates from the response sampled under $\pi_{\theta_\text{old}}$. This is the stabilizing part, and it remains unchanged from GSPO.

The token-level advantages $\widehat{A}_{i,t}$, by contrast, decide how the learning signal is distributed across the tokens inside that response. They do not replace the sequence-level ratio. They sit underneath it. That means the response still gets accepted or clipped as a whole according to the same sequence-level criterion, while the internal gradient contributions can be customized token by token.

This is exactly why GSPO-token is described as flexible. It gives the practitioner a way to adapt the advantage structure for tasks that need more than one scalar per response, without giving up the main stability mechanism of GSPO. The paper emphasizes that GSPO-token and GSPO are numerically identical when the token advantages are all the same, which shows that GSPO-token is a generalization rather than a different algorithmic family.

# Equivalence between GSPO and GSPO-token when all token advantages are equal

When every token in a response receives the same advantage, that is, when

\[
\widehat{A}_{i,t} = \widehat{A}_{i},
\]

GSPO-token collapses to GSPO. The paper states that under this condition, GSPO-token and GSPO are numerically identical in the optimization objective, the clipping condition, and the theoretical gradient. In other words, if token-wise customization is turned off, the two formulations become the same algorithm.

This equivalence is important because it shows that GSPO-token does not change the core learning rule. It only adds an extra degree of freedom. If that freedom is not needed, then there is no functional difference between the two objectives. If it is needed, GSPO-token can express it while still preserving the sequence-level importance ratio that GSPO relies on for stability.

From a conceptual standpoint, this is what makes GSPO-token a clean extension. It does not ask the user to choose between stable sequence-level optimization and token-level control. Instead, it shows that the former can remain intact while the latter is introduced as a more expressive advantage assignment.

# When to prefer GSPO versus GSPO-token in practice

According to the paper, GSPO-token is the right choice when a setting calls for token-wise advantage customization, with multi-turn RL given as the motivating example. In such cases, a single response-level advantage may be too blunt, and the token-level formulation provides the needed flexibility while retaining the sequence-level ratio that stabilizes learning.

GSPO remains the simpler default when token-wise customization is unnecessary. If the task is naturally handled by one normalized advantage per response, then GSPO already provides the sequence-level clipping, rewarding, and optimization that the paper argues are essential for stable large-model RL. GSPO-token is therefore best thought of as a compatible extension: use GSPO when response-level treatment is enough, and use GSPO-token when finer-grained token-level advantages are required.

The paper’s larger message is that the stable part of the method is the sequence-level importance ratio, not the token-wise advantage structure. GSPO-token preserves that stable core while adding a more flexible way to shape the learning signal. When all token advantages are equal, nothing changes. When the task benefits from per-token control, GSPO-token gives that control without sacrificing the sequence-level foundation.

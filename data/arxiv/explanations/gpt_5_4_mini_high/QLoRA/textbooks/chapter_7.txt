\title{A Textbook about the Paper: "QLoRA: Efficient Finetuning of Quantized LLMs"}

Chapter 7: Training Mechanics and Hyperparameter Choices

QLoRA’s practical recipe is built around a simple idea: keep the pretrained language model frozen and heavily compressed, but make the trainable part of the system small, flexible, and numerically stable. The paper’s training design is not just about saving memory. It is about preserving the behavior of ordinary 16-bit finetuning while changing as little of the training pipeline as possible. That is why the authors spend so much effort on what data type is used for storage, what data type is used for computation, which layers receive adapters, and how the data is turned into supervised targets.

# Forward computation with dequantized BF16 weights

In QLoRA, the pretrained base model is stored in a low-precision form, usually 4-bit NormalFloat, but it is not used directly in that form for matrix multiplication. Instead, when a layer is evaluated, the stored weight tensor is dequantized into BF16 and the forward pass is carried out in BF16 arithmetic. The paper writes this for a linear layer with a LoRA adapter as
$Y^{\mathrm{BF16}} = X^{\mathrm{BF16}} \,\mathrm{doubleDequant}(c_1^{\mathrm{FP32}}, c_2^{\mathrm{k-bit}}, W^{\mathrm{NF4}}) + X^{\mathrm{BF16}}L_1^{\mathrm{BF16}}L_2^{\mathrm{BF16}}$.
The first term is the frozen pretrained layer, reconstructed on the fly from quantized storage, and the second term is the trainable low-rank adapter path.

The important practical point is that QLoRA does not try to do learning in 4-bit arithmetic. The 4-bit representation is a storage format, while BF16 is the computation format. The paper emphasizes this distinction because it allows the model to keep the memory savings of quantization without giving up the stability of 16-bit matrix multiplication during training. The authors also specify that they use NF4 for the base weights, FP8 for the second-level quantization constants, a blocksize of $64$ for the base weights, and a blocksize of $256$ for the quantization constants. In other words, the low-precision representation is only where the model lives between uses; when it is actually needed in the forward pass, it is temporarily restored to a BF16 tensor and then multiplied normally.

# Backward computation through frozen quantized weights

The backward pass follows the same logic: gradients must move through the frozen base model so that the adapter parameters can be updated correctly, but the base model itself is not being learned. The paper is explicit that QLoRA backpropagates gradients through a frozen, 4-bit quantized pretrained language model into the LoRA adapters. That means the quantized weights are part of the computation graph, but they are not the target of optimization.

This distinction matters because the adapter gradients depend on the behavior of the frozen layer. Even though $W$ is not updated, the computation of $\partial E/\partial L_i$ still requires the layer’s input-output sensitivity, which is evaluated through the dequantized BF16 version of the base weights. So the frozen model is not ignored during backpropagation; it is used as the fixed scaffold through which the loss signal is routed. What QLoRA removes is the need to store or optimize gradients for the massive base-model weights themselves. The paper’s training story is therefore not “no backward pass,” but rather “backward pass through a frozen backbone, with learning confined to the adapters.”

# Why gradients are needed for adapters but not the base model parameters

The reason QLoRA can save so much memory is that the only parameters updated by gradient descent are the LoRA adapters. The base weights are kept fixed after quantization, so there is no need to allocate update state for them, and no need to accumulate a gradient tensor for them as trainable variables. The paper stresses that parameter-efficient finetuning already shifts the learning burden away from the full model, and QLoRA takes that idea one step further by also compressing the frozen backbone.

This is also why the authors spend time discussing memory accounting for LoRA. They point out that the main memory cost in finetuning large language models is not the adapter weights themselves, but the activation gradients and related training-state overhead. As a result, making the adapter set slightly larger does not drastically change the total memory footprint, whereas trying to finetune the full 16-bit model would be infeasible. QLoRA’s core training mechanism is therefore very asymmetric: the backbone supplies knowledge, but the adapters supply learning.

# The importance of attaching LoRA adapters to all linear layers

A key empirical result in the paper is that the usual LoRA convention of attaching adapters only to the query and value projection matrices is not enough to recover full finetuning performance at larger scales. In the authors’ experiments, the most important hyperparameter was not a narrow attention-only setup, but the total number of adapter insertion points. When they moved beyond the standard query/value-only design and placed LoRA on all linear transformer block layers, the model was able to match the performance of full finetuning much more closely.

This is a significant practical lesson because it changes how one should think about low-rank adaptation. The paper’s findings suggest that adaptation capacity is not just about “having LoRA,” but about where LoRA is attached. If the adapters are only present in a small subset of layers, the model may not have enough freedom to correct the quantized backbone everywhere it needs to. By contrast, broader coverage gives the adaptation path access to the whole network, which is exactly what the authors needed to avoid the accuracy tradeoffs seen in prior work.

# Why adapter coverage matters more than commonly emphasized rank settings

The paper’s experiments also show that adapter coverage matters more than the rank parameter $r$ in the LoRA factorization. Rank determines the width of each low-rank bottleneck, but the authors found that once adapters were placed broadly enough, changing $r$ had little effect on performance in their reported setup. In other words, the network was constrained more by where adaptation was allowed than by the precise size of each low-rank module.

This makes sense in light of the memory discussion in the paper. Since the LoRA parameters themselves are relatively small compared with the rest of the training state, increasing the number of adapter sites is a cheap way to increase the model’s flexibility. The authors explicitly argue that using more adapters does not significantly increase total training memory. That is why QLoRA can afford to prioritize adapter coverage over rank: the extra adapter paths are a better use of the memory budget than making a few adapters wider while leaving most of the network untouched.

# Learning rate and batch size adjustments across 7B, 13B, 33B, and 65B models

The authors do not treat every model scale as a completely separate training problem. Instead, they start from the 7B recipe and check which settings transfer as the model gets larger. Their reported finding is that most of the 7B configuration generalizes to 13B, 33B, and 65B models, including the number of epochs, but learning rate and batch size still need adjustment. In practice, they perform small hyperparameter searches for the 13B and 33B models and then use a simpler scaling rule for the largest runs.

The rule they report is straightforward: for 33B and 65B models, they halve the learning rate and double the batch size. That is the main scale-dependent change in their QLoRA training recipe. They also note that paged optimizers are critical for making the 33B and 65B runs fit on a single GPU because they help absorb memory spikes during gradient checkpointing. So while the basic recipe stays stable across scales, the authors still make a few practical adjustments so the same finetuning strategy remains usable as the model grows.

# Supervised cross-entropy finetuning without RLHF

A major design choice in the paper is to keep the training objective simple and uniform. The authors use QLoRA finetuning with cross-entropy loss, i.e., supervised learning, and they do not use reinforcement learning even when the dataset contains human judgments between responses. This is deliberate. By avoiding RLHF, they remove a major confound: changes in performance can be attributed to the data and to QLoRA itself, rather than to a different optimization framework.

This choice also makes the experiments easier to compare across datasets and model sizes. Because every setup is trained under the same supervised objective, the paper can more cleanly ask whether quantized finetuning recovers 16-bit performance and which dataset or adapter design works best. In the authors’ framing, supervised cross-entropy is not a weakness of the method; it is the control condition that makes the analysis interpretable.

# Response-only supervision versus full-dialog supervision

For datasets with a clear separation between instruction and response, the paper finetunes only on the response. The instruction serves as input context, but the training target is the answer text. This is the standard instruction-following setup the authors want to preserve: the model is trained to produce a reply given a prompt, not to reproduce the prompt itself.

This choice keeps supervision focused on the behavior the model is supposed to learn. If the data already has a well-defined prompt and answer structure, there is no need to pay loss on the instruction side. The paper uses this design to reduce ambiguity in training and to make different datasets more comparable. In that sense, response-only supervision is a way of making the instruction-following objective as clean as possible before introducing more complex conversational structures.

# Handling multi-response conversation trees in OASST1 and HH-RLHF

OASST1 and HH-RLHF are more complicated because they contain multiple responses at several points in the conversation tree. To turn these branching dialogues into a single supervised training example, the authors select the top response at every level of the tree and finetune on the full selected conversation. Unlike the simpler instruction-response datasets, the conversation structure here is itself part of the training signal.

The paper says that this full selected conversation includes the instructions, which means the model is trained on a linearized dialogue path rather than on isolated answer strings. This makes the data usable for standard cross-entropy finetuning while preserving the multi-turn context that defines chatbot behavior. The practical effect is that the model learns from one chosen conversational trajectory, but the training objective remains the same supervised objective used everywhere else in the paper.

Taken together, these choices form the QLoRA training recipe used throughout the paper. The backbone is frozen and quantized, the computation is done in BF16, the adapters are placed broadly, and the optimization settings are only lightly adjusted as the model scale changes. The result is a method that behaves like ordinary finetuning where it matters, while remaining compact enough to train large models on a single GPU.

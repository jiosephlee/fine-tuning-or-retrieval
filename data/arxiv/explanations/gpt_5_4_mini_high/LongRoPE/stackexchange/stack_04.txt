\title{Stack Exchange of the Paper: "LongRoPE: Extending LLM Context Window Beyond 2 Million Tokens"}

### Is LongRoPE actually searching over one scale per RoPE dimension, or one scale per dimension pair?
Question:
The paper says it searches a specialized rescale factor for each RoPE dimension, but RoPE is usually applied to pairs of hidden dimensions using one angular frequency per pair. In the equations, the index $i$ runs from $0$ to $\frac{d}{2}-1$.

So when they say "each RoPE dimension," do they really mean each frequency pair rather than each hidden dimension? For example, if the model hidden size is $d=4096$, does this mean there are $2048$ learned/searchable scale values $\lambda_i$, or is there some smaller grouped representation in practice?

I'm asking because the search space estimate in the paper uses something like $400^{128/2} \times 14$, which made me wonder whether they are not using all RoPE pairs directly.
Answer:
Yes — in LongRoPE, “each RoPE dimension” should be read as each RoPE **frequency pair**, not each scalar hidden dimension.

That is already implicit in the RoPE formula they write: for each index $i$, the model uses one angle $n\theta_i$ and applies it to the 2D block $(2i,2i+1)$ via the corresponding $\cos$ and $\sin$ terms. So one rescale factor $\lambda_i$ controls one rotary pair. The paper is a bit loose in wording, but mathematically the searchable index is the same $i$ that runs from $0$ to $\frac{d}{2}-1$.

The search-space estimate makes this clear. When they write something like $400^{128/2}\times 14$, they are not using the model hidden size $4096$ there; they are using the **RoPE/head dimension** $d=128$, so there are $128/2=64$ pairwise frequencies. That matches the later monotonicity constraint they state explicitly: $\lambda_i \le \lambda_{i+1}$ for $i=0,\dots,63$. So the paper is searching 64 scale values plus the discrete choice of $\hat{n}$.

So for a LLaMA2-7B-style model with hidden size $4096$, the answer is **not** “$2048$ learned $\lambda_i$ values.” RoPE is applied per attention head, and the paper’s search is over the 64 rotary pairs in the head dimension, with the same rescaling schedule reused across the model, not a separate scale for every scalar hidden coordinate or every head.

In short: LongRoPE searches one scale per **RoPE pair/frequency**, not one per hidden dimension.

\title{Stack Exchange of the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

### How is cross-validation done in a $k$-shot setting with so few samples per class?
Question:
In the implementation details, the paper says it uses $k$-fold cross-validation for epoch selection, with the number of folds set to $2$ or $4$ so that each training split contains at least one example of each class.

I'm having trouble picturing how stable this is when the total number of labeled examples is extremely small, especially for multi-class datasets. For example, if there are $4$ shots total, or even $4$ shots per class, splitting that into folds seems like it would make the validation sets tiny and noisy.

Can someone clarify exactly what the unit of 'shot' is in this paper and how cross-validation is feasible without making model selection too high-variance?
Answer:
The short version is that the paper is a bit loose with the word “shot,” but the cross-validation they use is only for selecting an epoch for a very small linear model, not for building the whole predictor. That makes it feasible, although admittedly noisy.

What the paper actually says in the methods is that, for $k$-shot learning, they randomly sample a tiny labeled training set from the target dataset, and then train the downstream model on the binary rule-features produced by the LLM. The epoch is chosen by $k$-fold cross-validation, with $k \in \{2,4\}$ chosen so that each training split still contains at least one example of every class. That constraint is the key: they are not doing “leave-one-out on $4$ total samples,” which would be hopelessly unstable. They deliberately keep the number of folds very small so that the training portion of each fold is still class-complete.

So if you are imagining “$4$ total labeled samples on a $4$-class problem,” then yes, standard $k$-fold CV would be ill-defined or unusable. The fact that the authors say the folds are chosen to preserve at least one example per class implies that their few-shot support set must be large enough to cover all classes in each split. In practice, that means the relevant unit is not “$4$ arbitrary labels total regardless of class structure,” but a small support set that is still class-balanced enough for the folds to work. The paper does not spell this out perfectly, but the implementation detail makes that interpretation unavoidable.

As for variance, they are not pretending this is a statistically clean hyperparameter search. In such low-shot regimes, any CV estimate will be noisy. Their mitigation is pragmatic: use only $2$ or $4$ folds, keep the model simple, and repeat the whole train/test sampling three times with different random seeds, reporting mean and standard deviation. Since the downstream learner is just a low-capacity linear model over generated binary features, the exact epoch is not usually a critical hyperparameter anyway; the CV is mainly a coarse early-stopping heuristic.

So the right intuition is: the paper relies on a tiny but class-complete support set, uses very low-fold CV only to choose an epoch, and averages over multiple random splits to dampen the noise. It is not a high-fidelity model-selection protocol, but it is a reasonable engineering choice for the extremely data-starved setting they study.

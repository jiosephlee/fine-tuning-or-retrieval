\title{Stack Exchange of the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

### If the LLM already generates class-specific rules, why is a trained linear model still needed afterward?
Question:
I'm trying to understand the overall pipeline of FeatLLM. The paper says the LLM generates rules for each class, then each rule is converted into a binary feature, and then a simple linear model is trained on top of those features.

What I don't fully understand is why the linear model is necessary at all. If the rules already represent conditions for each class, wouldn't it be enough to count how many rules of each class are satisfied and choose the largest count? The paper briefly says not all rules are equally important, but I still don't see why this requires a learned model instead of a fixed scoring scheme.

Can someone explain what failure case the linear model is solving, especially in a few-shot setting where there are very few labels to estimate the weights?
Answer:
Because in \textsf{FeatLLM} the rules are not treated as the final classifier; they are treated as binary features. A fixed “count the satisfied rules” scheme is just the special case where every rule gets weight $1$. The paper’s point is that the LLM-generated rules are useful but noisy, so different rules should not be assumed equally reliable. That is exactly what the small linear model is doing: it learns a weighted vote over the rule-features, with logits of the form $\max(\mathbf{w}_k,0)\cdot \mathbf{z}_k$. If one rule is highly predictive and another is weak or even occasionally misleading, the model can upweight the former and nearly ignore the latter. A plain count cannot do that.

The failure case the authors are trying to avoid is very simple: the LLM may generate several rules for a class, but some are broad, redundant, or only loosely related to the label. If you count all satisfied rules equally, then a class with more or looser rules can win just because more of its rules fire, even if those rules are not very informative. The paper explicitly says this in the methods section: “not all rules and features carry the same importance,” and in the ablation study the variant that replaces tuning with a raw sum of binary features (\textsf{-Tuning}) performs worse. They also show that after tuning, low-weight rules are effectively filtered out, which is exactly the behavior you want when the rule set is imperfect.

In the few-shot setting, the linear model is still feasible because it is extremely small: it only learns one nonnegative weight per generated rule, not a deep classifier. So although the labeled set is tiny, the parameter count is tiny too. Think of it as a calibrated weighted majority vote learned from the few examples, rather than a complex model that needs lots of data. The paper’s own analysis says the benefit of this tuning becomes larger as the number of shots increases, but even in the low-shot regime it helps because it suppresses unhelpful rules instead of assuming all generated rules are equally good.

So the short answer is: if the LLM produced perfect, equally reliable rules, counting would be enough. FeatLLM does not assume that, and the linear layer is the simplest way to learn rule importance from the few labeled samples the method has.

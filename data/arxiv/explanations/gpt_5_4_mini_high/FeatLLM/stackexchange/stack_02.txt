\title{Stack Exchange of the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

### What exactly is being learned in FeatLLM, and what part stays fixed after rule generation?
Question:
The paper says FeatLLM uses the LLM as a feature engineer and that only a simple downstream model is used at inference time. I think that means the LLM is not updated, but I'm getting confused about which objects are fixed and which are trained.

After the LLM produces rules and those rules are parsed into code, are the generated binary features completely fixed for the entire dataset? Then is the only learned part the set of weights $\mathbf{w}_k$ in Eq. (1)?

I'm asking because the method feels halfway between feature engineering and model training, and I want to be sure I understand whether FeatLLM is learning from the original tabular features directly, or only from the LLM-produced rule indicators.
Answer:
Yes — in \textsf{FeatLLM}, the LLM itself is not trained or updated at all. It is used once as a feature generator: given the task description, feature descriptions, and a few labeled examples, it proposes class-specific rules. Those rules are then parsed into executable code, and that code deterministically converts each tabular sample into binary rule indicators.

So after rule generation, the rule features are fixed for that trial. For a given generated rule set, each sample $\mathbf{x}^i$ is mapped to $\mathbf{z}_k^i \in \{0,1\}^R$, where each entry says whether the sample satisfies one of the $R$ rules for class $k$. Once those rules are fixed and parsed, the downstream model never looks at the raw tabular features directly anymore; it only sees these LLM-produced binary features.

The only thing actually learned by gradient descent in the main model is the weight vector $\mathbf{w}_k$ in Eq. (1). The paper is explicit about this: the logits are computed as $\text{logit}_k^i = \max(\mathbf{w}_k, 0) \cdot \mathbf{z}_k^i$, and the cross-entropy loss is used to learn $\mathbf{w}_k$ from the few-shot labeled samples. The positive projection $\max(\mathbf{w}_k,0)$ just enforces nonnegative contributions from rules.

So the clean way to think about it is: the LLM performs one-shot feature engineering, and the linear model performs the actual supervised fitting. The original tabular features influence the final predictor only indirectly, through the rules the LLM invents from them. After that, inference is entirely done by the lightweight downstream model, not by the LLM.

One small nuance is that FeatLLM repeats this whole process multiple times with different random seeds, temperatures, and bagged subsets of features/instances. So there can be several different fixed rule sets across ensemble trials, each with its own learned weights $\mathbf{w}[t]$. But within each trial, once the rules are generated, they are static; only the downstream weights are trained.

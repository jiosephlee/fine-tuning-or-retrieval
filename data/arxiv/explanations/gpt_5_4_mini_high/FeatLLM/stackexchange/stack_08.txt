\title{Stack Exchange of the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

### What does the 'quality of generated features' analysis mean when a rule is just a binary indicator?
Question:
In the feature-quality analysis, the paper measures the AUROC between each generated feature and the target label, then reports the proportion of features with AUROC above $0.5$.

I'm confused about how to interpret AUROC for a single binary rule feature. Since the feature only takes values $0$ or $1$, isn't the ROC curve very limited? Also, if a rule is strongly associated with the negative class rather than the positive class, would its AUROC be below $0.5$ even though it is still informative?

I want to understand whether 'AUROC above $0.5$' is really a good criterion for rule usefulness in this setting.
Answer:
Yes, the ROC analysis is very limited for a binary rule feature, but it is still meaningful.

If a generated feature is just a binary indicator $z \in \{0,1\}$, then the ROC curve can only have one nontrivial operating point: the point you get when you classify a sample as positive whenever the rule fires. So the AUROC is no longer measuring a nuanced ranking, as it would for a real-valued score; it is basically summarizing whether the rule fires more often on positive examples than on negative ones. Formally, for a binary score, AUROC reduces to a simple class-separation summary, and you can think of it as the average of sensitivity and specificity:
$$
\mathrm{AUC} = \frac{P(z=1 \mid y=1) + P(z=0 \mid y=0)}{2}.
$$
So $\mathrm{AUC}=0.5$ means the rule is no better than random, and $\mathrm{AUC}>0.5$ means the rule is aligned with the positive class more often than not.

Your second point is exactly right: if a rule is strongly associated with the negative class, then its AUROC with respect to the positive label will be below $0.5$. That does not mean the rule contains no information; it just means the information is reversed. If you flipped the feature to $1-z$, its AUROC would become $1-\mathrm{AUC}$ and would be above $0.5$. So AUROC $<0.5$ is really saying “this rule points the wrong way for this label,” not “this rule is useless in an absolute sense.”

In the context of the paper, that distinction matters because the generated rules are intended to become class-specific positive features, and the downstream linear model uses nonnegative weights. That means a rule that mostly fires on the opposite class is not helpful for that class as generated, so using the proportion of features with AUROC above $0.5$ is a reasonable sanity check for “did the LLM generate rules that directly match the intended target?” It is not meant to be a perfect measure of all possible utility. The paper’s own interpretation is exactly that: before tuning, most generated rules are relevant to the target; after tuning, the low-value ones get downweighted or filtered out.

So the short answer is: yes, AUROC for a binary rule is coarse, and yes, a negatively associated but informative rule can have AUROC below $0.5$. In this paper, $\mathrm{AUC}>0.5$ is best understood as a directionality check for whether the generated rule is a useful positive indicator for the target class, not as a universal definition of usefulness.

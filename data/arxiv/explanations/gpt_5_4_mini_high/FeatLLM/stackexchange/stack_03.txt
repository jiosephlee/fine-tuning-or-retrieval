\title{Stack Exchange of the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

### Why are the rule weights constrained to be non-negative in Eq. (1)?
Question:
In the paper, the class logit is defined as $\text{logit}_k^i = \max(\mathbf{w}_k, 0) \cdot \mathbf{z}_k^i$, so each learned weight is projected into the non-negative region.

I understand the stated intuition that rules generated for a class should not reduce that class likelihood, but this seems like a strong modeling assumption. What if the LLM generates a noisy or misleading rule for class $k$ that is actually evidence against class $k$ on the training set? With a non-negative constraint, the model can only ignore that rule by pushing the weight to $0$, but it cannot actively use it as negative evidence.

Is there a principled reason this positivity constraint is better than allowing signed weights, especially when the rules are imperfect?
Answer:
In the paper, the non-negativity constraint is not presented as a universally optimal modeling choice; it is a deliberate inductive bias that matches how they want the rules to be used. The generated rules are meant to be class-specific criteria, so the authors treat each rule as supporting evidence for that class rather than as a general feature that may help or hurt. That is exactly why they write
$$
\text{logit}_k^i=\max(\mathbf{w}_k,0)\cdot \mathbf{z}_k^i,
$$
and explicitly say that projecting the weights into a positive subspace “ensur[es] that the features generated by the LLM do not reduce the likelihood of a class during learning.”

The key practical point is that FeatLLM is a low-shot method with noisy, LLM-generated rules. In that regime, allowing signed weights would give the linear layer a very easy way to overfit small idiosyncrasies in the few training examples by using a class’s own rules as negative evidence. That may improve training loss, but it would make the learned rule semantics much less faithful and much less stable. With non-negative weights, a bad or irrelevant rule can still be harmless: its weight can be driven to $0$, so the model simply ignores it. The paper’s robustness story is that imperfect rules are handled by the ensemble and bagging mechanism, not by letting the classifier reinterpret a “rule for class $k$” as an anti-rule for class $k$.

So the principled reason is really about preserving the semantics of the extracted rules and stabilizing learning in a few-shot setting. The constraint makes the final linear model monotone in each class’s rules: satisfying more of class $k$’s rules can only increase that class’s score. If you want negative evidence, the paper’s formulation expects that to be captured indirectly through the competing class logits under the softmax, or by simply not assigning such a rule to class $k$ in the first place. The authors do not claim that signed weights are impossible or inherently wrong; rather, for their specific “LLM-generated criteria + simple downstream model” setup, the positive constraint is a conservative choice that improves interpretability and reduces the chance that noisy rules become spurious anti-features.

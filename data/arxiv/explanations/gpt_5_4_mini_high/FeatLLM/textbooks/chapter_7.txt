\title{A Textbook about the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

Chapter 7: 7. Predicting Class Probabilities from Rule-Based Features

# Why counting satisfied rules is a natural starting point

After \textsf{FeatLLM} has extracted rules from the few-shot examples, the next question is how to turn those rules into a prediction. The most immediate idea is also the most intuitive one: if a sample satisfies many rules associated with a class, then that class should become more likely. In the paper, this is described as counting how many rules of each class a sample satisfies, which is equivalent to summing the binary indicators for that class. This is a natural starting point because the rules are meant to act as criteria for class membership, so a larger number of satisfied criteria should provide stronger evidence for that class.

This idea fits the overall philosophy of the method. \textsf{FeatLLM} does not ask the language model to output the final answer directly for every test sample. Instead, the LLM is used to generate human-readable rules, and those rules become features. Once the features exist, a simple counting-based rule can already give a rough measure of class support. In other words, the rules are not merely textual explanations; they are operational signals that can be evaluated on data.

# Why simple counting is insufficient when rules vary in usefulness

Although counting satisfied rules is a sensible baseline, the paper emphasizes that not all rules are equally valuable. Some rules may be highly informative, while others may be weak, redundant, or only loosely connected to the target. If we simply count every satisfied rule equally, then a weak rule would contribute as much as a strong one. That would ignore differences in rule quality and could reduce predictive performance.

This is why \textsf{FeatLLM} does not stop at rule generation. After the rules are converted into binary features, the method learns how important each rule is from the few labeled training samples. The downstream model therefore acts as a filter as well as a predictor: it can give more weight to rules that consistently align with the labels and less weight to rules that do not. The paper’s ablation study supports this design, showing that omitting weight tuning hurts performance. This means that even when the LLM has produced useful rules, learning their relative importance still matters.

# Class-specific binary feature vectors for rule satisfaction

The rules are organized separately for each class, and the paper represents the rule satisfaction for a sample using a class-specific binary feature vector. For a sample $\mathbf{x}^i$ and class $k$, this vector is denoted by $\mathbf{z}_k^i \in \{0,1\}^R$, where $R$ is the number of rules per class. Each entry in $\mathbf{z}_k^i$ indicates whether the sample satisfies one specific rule for class $k$. A value of $1$ means the rule is satisfied, and a value of $0$ means it is not.

This class-specific representation is important because the rules are not generic across all classes. Rather, each class has its own set of criteria extracted by the LLM. By separating the features this way, the model can evaluate evidence for each class independently. The binary encoding also keeps the representation simple and easy to use in a downstream model. The resulting features are not complicated embeddings or dense vectors; they are just rule indicators that say whether particular conditions hold for the sample.

# The linear model used to score each class

Once the binary rule features are available, \textsf{FeatLLM} uses a conventional machine learning model to score the classes. The paper gives the example of a linear model without bias. For each class $k$, the model computes a class score from the binary rule vector $\mathbf{z}_k^i$. This score is then used to estimate class likelihood.

This choice is central to the paper’s design. The goal is not to build a sophisticated neural classifier on top of the rules. Instead, the rules already encode much of the task-specific knowledge, so the remaining learner only needs to combine them intelligently. A linear model is sufficient for this purpose because it can assign importance to each rule and produce a class score by a weighted sum. This keeps inference lightweight and avoids the need for passing each test sample through the LLM.

# The non-negative weight constraint and its interpretation

A distinctive feature of the downstream model is that the rule weights are constrained to be non-negative. In the paper, this is written as $\max(\mathbf{w}_k,0)$, meaning that any negative value is projected to $0$. This constraint is not just a technical detail; it has a clear interpretation.

Because the features represent whether a sample satisfies rules that were generated as evidence for a class, a satisfied rule should not reduce the likelihood of that class during learning. The non-negative projection ensures that the model can only reward satisfied rules, not penalize them. In the paper’s terms, this prevents the generated features from reducing class likelihood. That makes the learned weights easier to interpret as rule importance values: a larger weight means the rule contributes more positively to the class score, while a weight near zero means the rule is not very useful.

# Computing logits through weighted sums of satisfied rules

The class score in \textsf{FeatLLM} is computed as a dot product between the non-negative weights and the binary rule vector. For class $k$ and sample $i$, the paper defines the logit as
\[
\text{logit}_k^i = \max(\mathbf{w}_k, 0) \cdot \mathbf{z}_k^i.
\]
Since $\mathbf{z}_k^i$ is binary, this weighted sum only includes the rules that the sample actually satisfies. If a rule is not satisfied, its contribution is $0$. Thus the logit is essentially the total amount of positive evidence for class $k$, with each piece of evidence scaled by how important the model has learned that rule to be.

This formulation is simple but powerful. It mirrors the counting intuition from the previous section, but improves on it by allowing some satisfied rules to matter more than others. If a sample satisfies many low-value rules, the score will not be inflated as much as if it satisfies a smaller number of highly informative rules. The dot product therefore gives the model a way to refine the naive counting strategy while preserving its interpretability.

# Applying softmax to obtain class probabilities

After computing a logit for each class, \textsf{FeatLLM} converts those logits into class probabilities using the softmax function. If there are $c$ classes, the logits are collected into the vector $[\text{logit}_1^i, \ldots, \text{logit}_c^i]$, and the probability vector $\mathbf{p}^i$ is computed as
\[
\mathbf{p}^i = \text{Softmax}([\text{logit}_1^i, \ldots, \text{logit}_c^i]).
\]
This step makes the output suitable for classification, since the resulting probabilities provide a normalized comparison among the classes. A class with a larger logit receives a larger probability, but the probabilities still sum to $1$ across classes.

In this framework, the logits summarize evidence from the rule features, and softmax turns those evidence scores into class likelihoods. This is the final prediction mechanism used by the downstream model. The method remains very simple computationally, which is one of the paper’s main goals: once the rules are available, prediction should not require a complex inference pipeline.

# Optimizing cross-entropy loss with few-shot labeled data

The weights in the linear model are learned from the few available labeled training samples. The paper states that cross-entropy loss is used to optimize the weights $\mathbf{w}_k$. This means the model is trained to assign high probability to the true class of each labeled example while reducing probability mass on incorrect classes.

The few-shot setting makes this learning problem especially delicate, because the model only has a small number of labeled examples to estimate the importance of each rule. That is why the paper treats the downstream model as intentionally low-complexity. A simple linear model is less likely to overfit than a larger model when training data are scarce. At the same time, the rule features supplied by the LLM provide a strong prior structure, so the linear model does not need to discover the entire task from scratch. It only needs to calibrate how much each rule should matter for the observed training samples.

# Learning which rules are most important for each class

One of the main purposes of the downstream training stage is to learn rule importance. The paper explicitly says that the model learns the importance of each feature and how it affects class likelihood. In the linear scoring formulation, importance is encoded directly in the magnitude of the weights. A large weight means the associated rule has strong influence on the class logit, while a small weight means the rule contributes little.

This is an important refinement over simply accepting all rules from the LLM at face value. The LLM may generate many plausible rules, but the data may show that some are more reliable than others. The downstream model therefore serves as a data-driven correction mechanism. It takes the rule candidates from the LLM and learns which ones actually help classification for the target task. The paper’s analysis of feature quality reinforces this interpretation, showing that after tuning, rules with little relevance can be automatically filtered out by having low learned weights.

# Why the downstream model remains simple despite LLM-generated features

A key design choice in \textsf{FeatLLM} is that the downstream predictor stays simple even though the features are produced by a sophisticated LLM. The reason is that the complexity has already been moved into the feature engineering stage. The LLM is used to generate criteria that capture task knowledge, and once those criteria are available, the prediction problem becomes much easier.

This separation of responsibilities is one of the paper’s central ideas. The LLM does the difficult reasoning work of proposing rules, while the downstream learner only aggregates rule satisfaction into a class score. Because of this, inference does not require querying the LLM for each sample. The paper argues that this reduces latency and makes the method more practical than end-to-end LLM-based tabular prediction approaches. The downstream model also remains compatible with API-only access to the LLM, since no fine-tuning or training of the language model itself is required.

# Interpretability of learned weights over rules

The learned weights are not only useful for prediction; they also make the final model easier to interpret. Because each feature corresponds to a specific rule, and each weight measures that rule’s contribution to the class logit, the model reveals which rules are most influential. This gives a direct view of how the classifier is making decisions.

In this sense, the linear model preserves the interpretability of the rule-based representation. If a rule has a high learned weight, that rule is important evidence for the class. If a rule ends up with a very small weight, it is effectively ignored. The paper even notes that low-weight rules can be filtered out after tuning. So the weights serve a dual role: they improve classification performance and provide a transparent summary of rule usefulness.

This interpretability is consistent with the broader design of \textsf{FeatLLM}. The framework uses the LLM to generate rules that are understandable in natural language, then converts those rules into binary features, and finally learns a simple weighted combination of them. The resulting model is still compact and explainable, but it benefits from the prior knowledge and reasoning ability of the LLM.

\title{Blogs about the Paper: "DeepSeekMath: Pushing the Limits of Mathematical Reasoning in Open Language Models"}

# Why Teaching AI to Code Can Make It Better at Math

## A surprisingly strong starting point

One of the most interesting results in *DeepSeekMath* is not just that the model got better at math, but *how* it got there. The authors did not start from a generic language model. They initialized DeepSeekMath-Base 7B from DeepSeek-Coder-Base-v1.5 7B, a model already trained heavily on code.

That choice turned out to matter a lot.

In their experiments, the paper shows that starting from a code-trained model is better than starting from a general-purpose LLM when the goal is mathematical reasoning. They also ran a direct comparison: train on code first, then math, versus train on general text first, then math. The code-first path produced better downstream mathematical performance. The effect showed up both when the model solved problems directly and when it used Python as a tool.

This is a useful result because it gives a partial answer to a long-running question in AI: does code training actually help reasoning? For math, at least, the answer from this paper is yes.

## Why code helps with math

The paper does not claim that code and math are the same thing. But they do share a lot of structure.

Both require the model to work with precise symbols, follow strict rules, and keep track of intermediate steps without drifting off course. In programming, a small mistake can break the whole program. In math, a small mistake can break the whole derivation. In both cases, success depends on more than just pattern matching on words.

That overlap shows up clearly in the way the paper evaluates mathematical reasoning. DeepSeekMath is tested in two modes: one where it has to produce a text solution on its own, and another where it can write Python code to help solve the problem. This second mode is important because it makes the connection between code and math explicit. If a model can translate a word problem into executable steps, it has to understand the structure of the problem well enough to manipulate it.

The paper’s results suggest that code-trained models are already better prepared for this kind of structured thinking. They are more comfortable with algorithmic decomposition, with maintaining state across multiple steps, and with generating outputs that have to be internally consistent. Those are exactly the habits that help on mathematical tasks.

## What DeepSeekMath found in practice

The authors tested several training setups to isolate the effect of code.

First, they compared a two-stage approach where the model is trained on code for 400B tokens and then on math for 150B tokens, against a control setup where the first stage uses general text instead of code. The code-first version did better on math benchmarks.

Second, they looked at a one-stage setup where code tokens and math tokens are mixed together. That mixture helped preserve coding ability and improved program-aided mathematical reasoning. But for smaller models, it could hurt pure text-based math reasoning. The paper suggests that this may be a capacity issue: a smaller model may not be able to absorb both streams equally well at the same time.

That nuance matters. The result is not “more code always helps everything.” It is more specific than that. Code seems especially valuable as a foundation for structured reasoning, and the training schedule matters. A model can benefit from code-first pretraining, but a naive mix of code and math is not automatically optimal.

The authors also report that their math training improved general reasoning benchmarks like MMLU and BBH, not just math-specific tasks. So the benefit is broader than arithmetic or contest problems. The model seems to gain a more general ability to handle structured problems.

## Why this matters for model training

The main lesson from DeepSeekMath is that if you want a model to reason well about math, you should not think only about math textbooks and problem sets. Code is also a valuable source of training signal.

That has a few implications.

First, code can act as a kind of reasoning scaffold. It teaches the model how to express multi-step procedures clearly and consistently. That makes it a good pretraining substrate for math, especially when the target task involves algorithms, calculations, or tool use.

Second, training strategy matters as much as data volume. DeepSeekMath is not just “trained on a lot of data.” It is trained with a deliberate sequence: code-heavy initialization, large-scale math web data, supervised fine-tuning, and then reinforcement learning. The code-first step is one part of a larger curriculum.

Third, not all technical text is equally useful. The paper reports that arXiv papers, which are often included in math training corpora, did not noticeably improve mathematical reasoning in their experiments. In contrast, code and carefully selected math-related web data did. That suggests future training pipelines should be more selective and more empirical about which sources actually help reasoning.

## The bigger picture

DeepSeekMath is a strong example of a broader trend: reasoning ability in language models may come from learning multiple forms of structure, not just natural language. Code is one of the cleanest and most demanding structured languages we have. It forces exactness, sequence, and explicit computation. Those same traits are useful in mathematics.

The paper’s takeaway is not that code makes a model “understand math” in a human sense. Rather, code seems to give the model a better procedural foundation for solving structured problems. Once that foundation is in place, math training can push it further.

For future AI systems, that suggests a practical recipe: if you want better mathematical reasoning, don’t treat code as a separate capability. Treat it as part of the path toward reasoning itself.

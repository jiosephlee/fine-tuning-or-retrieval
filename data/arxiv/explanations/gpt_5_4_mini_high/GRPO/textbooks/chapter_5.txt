\title{A Textbook about the Paper: "DeepSeekMath: Pushing the Limits of Mathematical Reasoning in Open Language Models"}

Chapter 5: Continual Pre-Training of DeepSeekMath-Base 7B

# Why initialize from DeepSeek-Coder-Base-v1.5 7B instead of a general model

DeepSeekMath-Base 7B is not trained from scratch. It is continued from DeepSeek-Coder-Base-v1.5 7B, and the paper explicitly notes that starting from a code-trained model is preferable to starting from a general language model. This choice is central to the whole construction of the base model, because the goal is not merely to make a model that has seen more text, but to build one that is already predisposed toward structured, stepwise reasoning before it receives specialized math data.

The paper’s evidence for this choice comes from its training experiments. In the discussion section, the authors report that code training before math training improves mathematical reasoning both with and without tool use. They treat this as partial evidence that code training is helpful for reasoning, at least in the mathematical domain. In that sense, the initialization is not an arbitrary engineering choice: it is a deliberate starting point supported by the authors’ ablation results and by the observation that code-oriented pretraining gives better downstream math performance than a general-language starting point.

# The intuition behind code-first then math-focused training

The paper’s intuition is straightforward: if the objective is mathematical reasoning, then a model that already knows how to work with highly structured symbolic text has an advantage over one that has only general natural language experience. The authors do not present this as a universal law, but their experiments consistently show that code training helps later mathematical learning. In particular, they report that code training improves program-aided mathematical reasoning and also improves direct mathematical reasoning without tools.

This intuition becomes clearer in the ablation study described in the discussion section. The authors compare a two-stage setting, where code training comes first and math training comes second, with a one-stage setting that mixes code and math tokens together. In the two-stage setting, the initial code phase already improves GSM8K and MATH when the model is allowed to use Python, and the later math phase improves it further. For direct, non-tool reasoning, the code-first stage also gives a moderate boost and makes the later math training more effective. The paper therefore treats code-first training as a useful way to prepare the model for the mathematical specialization that follows.

# The 500B-token continual pre-training run

DeepSeekMath-Base 7B is continually pre-trained for 500B tokens. This is the stage that turns the code-trained base model into a math-oriented foundation model. The important point is that this is not a short adaptation run; it is a large-scale continuation of pre-training on a carefully constructed mixture of domains. The scale matters because the authors’ claim is that strong mathematical reasoning can come not only from bigger parameter counts, but also from a sufficiently large and well-balanced continuation of training.

The resulting model is evaluated as a base model, before any instruction tuning. That matters because it lets the authors assess the effect of continual pre-training itself, separate from later supervision. In the paper, this 500B-token run yields a model that is strong on mathematical benchmarks, improves general reasoning benchmarks, and preserves coding ability. The model reaches 64.2% on GSM8K and 36.2% on the competition-level MATH benchmark, outperforming Minerva 540B in those settings. These results are used as evidence that the continual pre-training stage is doing real work, not just passively updating the model.

# The training mixture: math corpus, AlgebraicStack, arXiv, GitHub code, and natural language data

The 500B-token training mixture is deliberately balanced across several sources. The largest component is the DeepSeekMath Corpus, which makes up 56% of the training mix. This corpus is the paper’s own 120B-token math dataset mined from Common Crawl through an iterative filtering pipeline. The rest of the mixture is 4% AlgebraicStack, 10% arXiv, 20% GitHub code, and 10% natural language data from Common Crawl in both English and Chinese.

This composition reflects a careful attempt to specialize without collapsing into a narrow domain model. The DeepSeekMath Corpus provides the bulk of the mathematical content. AlgebraicStack contributes mathematical code. GitHub code helps preserve programming ability and is consistent with the paper’s finding that code training supports math reasoning. The natural language component keeps the model connected to ordinary language usage in both English and Chinese, which is important because the paper evaluates not only English math benchmarks but also Chinese benchmarks. ArXiv appears in the mixture as well, but the paper later reports that arXiv-only training does not noticeably improve the mathematical benchmarks they study, so it should not be viewed as the main source of the model’s gains.

# Optimizer, learning-rate schedule, context length, and batch size

The continual pre-training run uses AdamW with $\beta_1=0.9$, $\beta_2=0.95$, and weight decay $0.1$. The maximum learning rate is set to $4.2 \times 10^{-4}$. Training uses a multi-step schedule in which the learning rate reaches its peak after 2,000 warmup steps, falls to 31.6% of the peak after 80% of the training process, and then falls further to 10.0% of the peak after 90% of the process. The batch size is 10M tokens, and the context length is 4K tokens.

These settings matter because continual pre-training is a long optimization process over a large, mixed corpus. The warmup helps the model enter training smoothly, and the later decay stages reduce the learning rate as the model continues to absorb more data. The 4K context length gives the model room to learn from longer mathematical and code-like sequences, while the large token batch stabilizes updates over the heterogeneous training mixture. The paper does not present these hyperparameters as isolated tricks; rather, they are part of the training recipe that supports long-run continual pre-training at scale.

# Balancing mathematical specialization with retention of coding ability

A central design problem in this chapter is how to make the model better at mathematics without destroying the coding ability it inherited from DeepSeek-Coder-Base-v1.5 7B. The paper’s answer is the training mixture itself. By keeping a substantial fraction of GitHub code and including AlgebraicStack, the model is continuously exposed to programming data while it learns mathematics. This is not just a defensive choice; it is also a functional one, because the authors show that the resulting model retains strong performance on HumanEval and MBPP, the two coding benchmarks they use.

At the same time, the model does more than preserve coding skill. The paper reports that math pre-training improves MMLU and BBH, which means that the model gains broader reasoning and understanding capabilities, not only math-specific competence. This is important because it shows the training mixture is not producing a specialist that is narrowly optimized for one benchmark family. Instead, the model becomes a more general reasoning-oriented foundation model while still keeping its code competence intact. The bilingual natural language component also helps prevent the model from becoming too domain-specific, and the paper notes especially strong performance on Chinese mathematical benchmarks.

# How continual pre-training differs from task-specific fine-tuning

Continual pre-training and task-specific fine-tuning play different roles in the paper. Continual pre-training operates on large unlabeled corpora and teaches the model by extending next-token prediction over broad data sources. This is how DeepSeekMath-Base is built. It learns from math web pages, code, arXiv, and natural language before it is ever asked to follow an instruction format.

Task-specific fine-tuning comes later. In the paper, supervised fine-tuning uses 776K instruction examples with chain-of-thought, program-of-thought, and tool-integrated reasoning formats. That stage is designed to make the model more useful as a solver that can produce structured answers. The distinction is important: continual pre-training builds the underlying capability base, while fine-tuning teaches the model how to present that capability in the forms needed for solving benchmark problems and user queries. The base model chapter is therefore about foundation building, not about final task formatting.

# Expected benefits of multilingual and mixed-source training data

One of the most notable features of the DeepSeekMath Corpus is that it is multilingual, with English and Chinese as the two most represented languages. The paper emphasizes that this matters in practice: DeepSeekMath-Base performs especially well on Chinese mathematical benchmarks, and the authors attribute that in part to the fact that they did not restrict their math pre-training to English-only data. That is a clear contrast with some prior work, which focused mostly on English math text.

The broader training mixture extends this multilingual idea beyond the math corpus itself. The final continual pre-training run includes Chinese and English natural language data, plus code and mathematical content. The resulting model therefore learns from several kinds of text that all contribute different strengths: mathematics for reasoning, code for structured problem solving and tool use, and natural language for general understanding. The paper’s evaluation supports this design choice. DeepSeekMath-Base improves on Chinese benchmarks, remains strong on English math tasks, and preserves coding performance. In other words, the mixed-source design helps the model become a reasoning-oriented foundation model rather than a narrow math extractor.

# Summary

DeepSeekMath-Base 7B is built by continuing pre-training from a code model, not a general language model, and the paper argues that this is a better starting point for mathematical reasoning. The 500B-token run uses a deliberately balanced mixture dominated by the DeepSeekMath Corpus but also including code, arXiv, and bilingual natural language data. With AdamW optimization, a staged learning-rate schedule, a 4K context, and a large token batch, the model is trained to absorb this mixture at scale.

The result is a base model that is mathematically strong, code-aware, and broadly useful. The paper’s evaluations show that this continual pre-training recipe improves math benchmarks, supports Chinese as well as English performance, and preserves coding ability. That combination is what makes DeepSeekMath-Base 7B a strong foundation for the later instruction-tuning and reinforcement-learning stages.

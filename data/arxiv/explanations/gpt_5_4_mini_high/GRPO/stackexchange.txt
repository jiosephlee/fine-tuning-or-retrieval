\title{Stack Exchange of the Paper: "DeepSeekMath: Pushing the Limits of Mathematical Reasoning in Open Language Models"}

### Why does DeepSeekMath start from a code model instead of a general language model?
Question:
The paper says DeepSeekMath-Base 7B is initialized from DeepSeek-Coder-Base-v1.5 7B, and it also claims that code training helps mathematical reasoning. I am confused about what exactly is being transferred here. Is the idea that code pretraining teaches the model symbolic structure, long-range dependencies, or something else? Also, if code helps, why is an additional math corpus still so important? I am trying to understand whether the benefit comes mostly from code syntax, from program execution-style reasoning, or simply from starting with a stronger base model.
Answer:
The paper’s claim is mainly empirical, not a fully mechanistic theory: they found that starting from a code model works better than starting from a general LLM, but they do not prove a single underlying cause. The safest reading is that code pretraining gives the model a more useful inductive bias for mathematics than ordinary web text does, because code is already a highly structured, low-ambiguity language. It trains the model to manipulate exact syntax, compose steps sequentially, and stay consistent over long token spans, which is very close to what mathematical reasoning requires. Importantly, the paper shows this helps not only when the model is allowed to write Python programs, but also when it has to solve problems in plain chain-of-thought, so the gain is not just “it learned to execute code.”

That said, I would not interpret the result as “code teaches math.” The paper’s ablation only supports a more modest conclusion: code training is a better initialization for later math training than a generic continuation on general tokens. In their experiments, they compare a code-first stage against a general-text-first stage, and code-first is better. So the benefit is not merely “a stronger base model” in the abstract; it is specifically that the base model has already learned a form of structured symbolic generation that transfers well to math. The paper does not isolate whether this comes more from syntax, compositionality, algorithmic step-by-step processing, or program-like reasoning, but all of those are consistent with their results. What they do say explicitly is that code training improves mathematical reasoning “with and without tool use.”

The additional math corpus is still crucial because code pretraining is only a scaffold. It gives the model the right kind of representation, but not enough exposure to actual mathematical language, notation, problem distributions, and multilingual math content. The whole point of DeepSeekMath is that they continue pretraining on a large, carefully filtered math corpus from Common Crawl, and they show that this corpus is what really drives the final gains. In fact, their discussion also says that arXiv alone was not notably helpful, which reinforces the idea that the improvement comes from high-quality math-like data, not just from generic scientific text. So the picture is: code pretraining gives a strong structured starting point, and the math corpus specializes that starting point into actual mathematical reasoning.

One other detail from the paper is worth noting: they keep some code in the continued pretraining mix, and they say this helps preserve coding ability while training on math. So the final model is not “a code model replaced by math,” but rather “a code model adapted with a large math corpus.” That is why starting from DeepSeek-Coder makes sense in their setup.

### How does the iterative fastText data collection pipeline find new math pages instead of just rediscovering OpenWebMath-like pages?
Question:
In the data collection section, the first fastText classifier is trained using OpenWebMath as positive examples and random Common Crawl pages as negative examples. My confusion is that this seems likely to recover pages that look similar to OpenWebMath, rather than broad mathematical content. The paper then groups pages by domain, marks domains with over $10\%$ retrieved pages as math-related, manually annotates math-specific URL patterns, and adds uncollected pages from those URLs back into the seed set. Can someone explain why this procedure should meaningfully increase diversity rather than just amplify the initial bias of the seed corpus?
Answer:
The key point is that the paper is not claiming that the first fastText model already knows what “math” is in some broad semantic sense. It is only a high-precision retriever trained to find pages that look like the initial seed, OpenWebMath. The authors explicitly say that many math pages are missed in the first pass because the positive set “lacks sufficient diversity,” so the later steps are there to expand that seed, not to rely on the classifier alone.

What makes the pipeline broader is that it switches from “find pages that look like these examples” to “find math-heavy web sources, then harvest the rest of the pages from those sources.” After the first retrieval, they group pages by domain and look for domains where more than $10\%$ of the pages were already retrieved. That is a strong hint that the whole domain is math-related, even if some pages on it don’t resemble OpenWebMath text very closely. Then they manually annotate the math-specific URL patterns within those domains and add the uncollected pages matching those patterns back into the seed set. So the model is not just iterating on the same surface form; it is being exposed to new sites, new URL structures, and new lexical patterns that the original OpenWebMath seed did not cover.

Intuitively, this is a bootstrapping procedure. The first classifier gives you a small set of “anchors.” The domain-level heuristic then says, in effect, “if this site has lots of math pages, the uncollected pages under these paths are probably math too.” That lets the corpus grow beyond pages that are merely OpenWebMath-like in style. In practice, this is how one gets coverage of things like forum threads, problem archives, course pages, or non-English math pages that may not look like the original seed but live in math-dense parts of the web.

That said, your concern is valid: this does not eliminate bias, and the paper does not claim that it does. The pipeline is still seeded by OpenWebMath, so the later rounds inherit some of its preferences. The authors’ point is more modest: the seed is used to find a broader set of math sources, and the evidence that this helps is empirical. After four iterations they end up with $35.5\,\mathrm{M}$ pages and $120\,\mathrm{B}$ tokens, and they stop because the fourth pass adds very little new data, which suggests the iterations are increasing recall rather than just endlessly rediscovering the same pages. They also report that the resulting corpus is multilingual and performs better than prior math corpora, which is their practical evidence that the expansion did in fact move beyond a narrow OpenWebMath clone.

So the short answer is: the diversity comes not from the first classifier being magically general, but from using its hits to discover entire math-rich domains and URL templates, then retraining on those newly found pages. It is a pragmatic, iterative expansion strategy, not a guarantee of unbiased coverage.

### What exactly is removed during benchmark decontamination with the $10$-gram matching rule?
Question:
The paper says that to avoid contamination, any text segment containing a $10$-gram that exactly matches benchmark text is removed from the math training corpus, and shorter benchmark texts with at least $3$ grams are handled by exact matching. I am unsure what the unit of removal is here. Are they deleting only the matched segment, the whole web page, or the whole document chunk used for training? Also, since many math problems share standard phrases, how does this rule avoid both false positives and false negatives?
Answer:
The paper is not describing a surgical deletion of just the matching $10$-gram. The wording points to filtering at the level of the whole offending text segment, and in practice that means the entire web page or extracted segment containing the match is dropped from the math corpus. That is consistent with the sentence “filter out web pages containing questions or answers” and with the later phrasing “any text segment containing a $10$-gram string that matches exactly ... is removed.” So the match is the trigger; the unit removed is the larger text unit that contains it, not just the overlapping span.

The reason this works at all is that it is meant to catch near-verbatim contamination, not semantic similarity. A long exact overlap of $10$ consecutive tokens is pretty strong evidence that the training text has copied a benchmark item or answer, especially for math problems where the numbers, symbols, and wording make long exact matches rare by accident. For benchmark texts shorter than $10$ grams but at least $3$ grams, they switch to exact full-text matching because there is no meaningful $10$-gram to search for; the whole short snippet itself becomes the signature.

This is still only a heuristic, so it does not eliminate all false positives or false negatives. It can over-filter pages that legitimately quote a benchmark problem, and it can miss paraphrases, partial copies, or cases where only some of the benchmark content appears. The goal is not perfect contamination detection; it is to remove obvious memorization leakage with a rule that is simple, high-precision, and cheap to run over Common Crawl.

### Why did the authors choose the top $40$B tokens in the first iteration if the final corpus is $120$B tokens?
Question:
The paper says they ranked recalled pages by fastText score and tested keeping the top $40$B, $80$B, $120$B, and $160$B tokens, but in the first iteration they kept only the top $40$B tokens. Later, after four iterations, they ended up with a $120$B-token corpus. I do not understand the logic here. If larger retained sets were already considered, why start with only $40$B in the first round? Was this meant to maximize precision early, or is there another reason related to bootstrapping the classifier?
Answer:
The key is that the $40$B figure is the **first-round cutoff**, not the size of the final corpus.

In the paper’s pipeline, the authors start with OpenWebMath as a seed, train a fastText classifier, and then use that classifier to rank Common Crawl pages by how “math-like” they look. At that point the classifier is still relatively weak, because its positive examples are limited and not very diverse. In that situation, keeping a very large fraction of the recalled pages would increase recall, but it would also admit many false positives. So the first iteration is deliberately conservative: they keep only the **top $40$B tokens**, which is a higher-precision subset.

This is a standard bootstrapping trade-off. Early on, you want the training data for the next round to be as clean as possible, because those examples will be used to improve the classifier itself. If the initial seed is noisy, the classifier can drift and start recalling pages that are merely superficially math-related. By starting with a smaller, higher-quality set, they build a better second-round seed.

The larger cutoffs, $80$B, $120$B, and $160$B, are mentioned because they **evaluated** those thresholds as candidate first-round corpus sizes. The paper does not say they kept all of them; it says they ran pre-training experiments to assess the effect of different amounts of retained data, and then chose $40$B for the first iteration. After that, they manually expand the seed corpus using math-related domains, retrain the classifier, and mine more pages in subsequent iterations. That is how they eventually accumulate a **$120$B-token corpus after four iterations**.

So the logic is not “we already knew $120$B was best, so why start at $40$B?” It is more like “we need a clean first round to bootstrap the classifier; once it improves, we can safely mine much more data.” The final $120$B is the result of that iterative expansion, not the target of the initial thresholding step.

### Why would math pretraining improve MMLU and BBH, but mixing code and math can hurt some non-tool reasoning?
Question:
The paper reports that math pretraining improves not only math benchmarks but also MMLU and BBH, which sounds like broader reasoning transfer. But later, in the discussion, they say that one-stage training on mixed code and math tokens can compromise mathematical reasoning without tool use, possibly because a $1.3$B model cannot absorb both well at once. I am confused about the connection. If math and code both help reasoning, why does combining them sometimes make performance worse? Is this mostly a capacity issue, a data distribution issue, or an optimization issue?
Answer:
There is not really a contradiction here; the paper is reporting two different kinds of transfer under two different training regimes.

The positive result on MMLU and BBH comes from continual math pre-training of a model that was already initialized from a code-trained base, and in the $7$B setting they keep some code and natural-language data in the mix. In that regime, math pre-training seems to sharpen the model’s ability to do structured, multi-step computation, which can transfer to broader reasoning tasks like MMLU and BBH. That makes intuitive sense: a lot of “reasoning” benchmarks reward the same skills that math training strengthens, such as decomposing problems, tracking variables, and applying rules consistently.

The later discussion about mixed code-and-math one-stage training is a different experiment, on a much smaller $1.3$B model. There the authors explicitly say that mixing code and math tokens in one stage helps coding and program-aided math, but can hurt mathematical reasoning without tools. Their own conjecture is that the model is simply too small to absorb both distributions well at once. In other words, the model has limited capacity, so joint training creates interference: code, math, and natural language are related, but not identical, and the model may not be able to allocate enough representational budget to all of them simultaneously. That is less a contradiction than a case of negative transfer under constrained capacity.

So the best reading of the paper is: math pre-training is generally helpful for reasoning, and code pre-training is also helpful, but how you combine them matters. Sequential training on a strong code base, then math, works well; a one-stage mixture on a smaller model can produce a compromise solution that is good for code-like or tool-using behavior but less good for pure non-tool mathematical reasoning. The paper does not prove whether the main cause is capacity, data distribution, or optimization, but the authors clearly lean toward capacity and interference as the most plausible explanation, with data mix and training schedule as contributing factors.

### Why do arXiv papers seem ineffective for mathematical reasoning in this paper?
Question:
A result that surprised me is the claim that arXiv-only training gives no notable improvement, and can even hurt, on GSM8K, MATH, MMLU-STEM, and miniF2F. I would have expected math papers to be useful for mathematical ability. Is the issue that arXiv mostly contains exposition and formalism rather than step-by-step problem solving? Or is it that the style of benchmark questions is very different from research papers? I am trying to understand whether this result is about the domain mismatch, the cleaning pipeline, the model scale, or something deeper about how language models learn reasoning.
Answer:
The paper’s result is best understood as a statement about *task alignment*, not as “arXiv contains no mathematics.” In their experiments, training on arXiv alone was done in two fairly different forms, namely MathPile, which is mostly cleaned arXiv scientific papers, and ArXiv-RedPajama, which is essentially full arXiv LaTeX with preambles, comments, macros, and bibliographies removed. In both cases, and on both model sizes they tested, the outcome was the same: no clear improvement, and sometimes a small drop, on GSM8K, MATH, MMLU-STEM, and miniF2F. So the paper is giving evidence that the problem is not just a bad cleaning pipeline.

What seems to be happening is that arXiv papers are a weak source of the kind of supervision these benchmarks reward. arXiv text is usually polished exposition of finished results: definitions, derivations, theorem statements, and proofs written for humans. That is mathematically rich, but it is not the same thing as learning to *solve* new problems step by step, choose intermediate moves, or construct formal proofs in a proof assistant. The benchmarks in the paper are mostly about exactly those procedural skills. A language model trained only to predict the next token from expository papers may learn more notation and scientific style, but not enough of the “how to work through a problem” behavior that improves GSM8K or MATH. For miniF2F, the mismatch is even stronger, because arXiv is still informal prose rather than Isabelle-style formal proof language.

The broader point, which is consistent with the rest of the paper, is that mathematical reasoning seems to benefit more from data that exposes *solution processes* than from data that merely discusses mathematics. That is why the authors find code helpful, and why their web-mined math corpus outperforms arXiv-heavy corpora: code is executable, structured, and closer to a sequence of operations the model can imitate. By contrast, arXiv is mathematically informative but not very action-oriented.

The paper does leave open a few possibilities. The authors explicitly say they have not tested whether arXiv would help at much larger model scales, whether it becomes useful when mixed with other data, or whether it would help on tasks they did not evaluate, such as informalization. So the safest conclusion is not “arXiv is useless,” but rather “for the specific training setups and benchmarks here, arXiv by itself is a poor source of mathematical reasoning signal.”

### In GRPO, why is the same normalized reward assigned to every token under outcome supervision?
Question:
For outcome-supervised GRPO, the paper sets the token-level advantage to the same value for all tokens in an output: $\hat{A}_{i,t} = \widetilde{r}_i = \frac{r_i - \mathrm{mean}(\mathbf{r})}{\mathrm{std}(\mathbf{r})}$. I am struggling with the credit assignment intuition here. If only the final answer is scored, why is it reasonable to reinforce every token equally, including early setup text that may not have contributed much? Is this just a practical approximation because the reward exists only at the end, or is there a stronger theoretical reason?
Answer:
Under outcome supervision, GRPO is treating the whole completion as one episodic trajectory with a single terminal reward, so the same normalized reward is attached to every token for the same basic reason that in REINFORCE-style policy gradients, every action in an episode gets weighted by the return of that episode.

Concretely, the paper’s outcome-supervision objective only observes $r_i$ after the full output $o_i=(o_{i,1},\dots,o_{i,T})$ is generated. The policy over the whole sequence factorizes as
$$
\pi_\theta(o_i\mid q)=\prod_{t=1}^T \pi_\theta(o_{i,t}\mid q,o_{i,<t}),
$$
so the gradient of the expected sequence reward is
$$
\nabla_\theta \mathbb{E}[r_i]
=
\mathbb{E}\!\left[r_i \sum_{t=1}^T \nabla_\theta \log \pi_\theta(o_{i,t}\mid q,o_{i,<t})\right].
$$
That is the key point: if the only reward is at the end, then the mathematically correct credit signal is the same scalar reward on every token in that sampled completion. GRPO then replaces $r_i$ by the group-normalized version
$$
\widetilde r_i=\frac{r_i-\mathrm{mean}(\mathbf r)}{\mathrm{std}(\mathbf r)},
$$
which is just a variance-reduction / relative-baseline trick. It says “this whole sampled response was better or worse than the others for the same question,” not “each token was equally important.”

So the intuition is not that early setup text is individually known to be useful. Rather, the algorithm only knows that this entire trajectory led to a better final outcome, and it reinforces the trajectory as a whole. That is exactly the limitation of outcome supervision: it is coarse credit assignment. The paper explicitly notes this, saying outcome supervision “may not be sufficient and efficient” for complex mathematical tasks, which is why they also study process supervision. In the process-supervision version, they do try to make credit assignment more fine-grained by giving step-level rewards and propagating them backward with
$$
\hat A_{i,t}=\sum_{\mathrm{index}(j)\ge t}\widetilde r_i^{\mathrm{index}(j)}.
$$

So the short answer is: yes, under outcome supervision this is mainly a sequence-level approximation, but it is not arbitrary. It is the standard policy-gradient treatment of terminal rewards, and the same-token advantage is the correct unbiased signal available when only the final answer is scored.

### How is GRPO's group-relative baseline better than a learned value function when all sampled answers for a question are poor?
Question:
The paper motivates GRPO by removing the critic and using the average reward within a sampled group as a baseline. I understand the memory advantage, but I am confused about the statistical tradeoff. Suppose a question is hard and all $G$ sampled outputs are wrong or low-quality. Then the group mean is also poor, and one bad output could still receive a positive normalized advantage just because it is less bad than the others. Does GRPO then only learn relative ranking within the group rather than absolute quality? If so, why does this not cause drift or reinforce mediocre solutions?
Answer:
The short answer is that GRPO is not meant to be a better estimate of the *absolute* quality of a prompt’s answers than a learned critic. It is a cheaper and often more stable *control variate* for the particular setting in the paper, where the reward signal is already comparative: the model is scored on several sampled completions for the same question. In that situation, “how good is this answer compared with the other answers I got for this question?” is much easier to estimate than “what is the absolute value of this partial generation?”

So if a question is hard and all $G$ samples are bad, the group mean being bad is not a bug; it is exactly the point. GRPO subtracts that group mean, so the update for that question is centered around zero. If all answers are equally poor, there is essentially no strong learning signal from that question. If one answer is slightly less bad, it gets a small positive advantage and the others get negative ones, but that is only a relative preference signal within that prompt, not a declaration that the answer is actually good in an absolute sense.

That does not usually cause drift for two reasons that are already implicit in the paper. First, the updates are normalized by the group standard deviation, so the method is comparing candidates *within the same question* rather than mixing together questions of different difficulty. This is why the paper says the group-relative baseline “aligns well with the comparative nature of rewards models.” Second, GRPO still includes a KL regularizer to the reference model, so even if a mediocre completion is temporarily the best in a bad group, the policy cannot wander too far from the starting distribution. In other words, GRPO is not “reinforcing mediocrity” globally; it is only saying, “among the samples the current policy produced for this question, move a little toward the better ones and away from the worse ones.”

A learned value function could, in principle, represent an absolute estimate of expected reward, including the fact that some questions are intrinsically hard. But in the paper’s setting that comes at a significant memory and optimization cost, and it is awkward because the reward is usually sparse, often only at the final answer. GRPO trades that critic for more samples per question, which gives you a question-specific baseline essentially for free. The downside is that it is a noisier and more local signal than a perfect critic; the upside is that it is much cheaper and, empirically in the paper, still sufficient to improve math reasoning.

So yes, GRPO is fundamentally relative rather than absolute. But that is not a flaw here: policy-gradient methods only need a baseline to reduce variance, and when the reward model itself is based on comparisons between answers to the same question, a group-relative baseline is a natural fit. The paper’s own discussion is consistent with this view: the RL step mainly shifts probability mass toward better completions among the model’s own samples, rather than magically solving hard questions in one update.

### What is the practical difference between adding KL regularization to the reward and adding a KL term directly to the GRPO objective?
Question:
In the PPO discussion, the paper uses a per-token reward of the form $r_t = r_\varphi(q, o_{\le t}) - \beta \log \frac{\pi_\theta(o_t \mid q, o_{<t})}{\pi_{ref}(o_t \mid q, o_{<t})}$. In GRPO, instead of folding the KL penalty into the reward, they subtract a KL divergence term directly in the objective, and they use a particular unbiased estimator. I do not see clearly why this change matters beyond implementation convenience. Does moving the KL term outside the reward alter the optimization dynamics, or is it mainly to keep the group-relative advantage $\hat{A}_{i,t}$ easy to compute and interpret?
Answer:
The short answer is that the paper is not changing the *goal* so much as changing *where the KL penalty enters the estimator*. If you had an exact policy-gradient calculation with no clipping, no sampling noise, and no advantage normalization, then “put the KL into the reward” and “subtract the KL directly in the objective” are basically two ways of writing the same regularized optimization problem: both say “maximize task reward, but do not drift too far from the reference model.” In that idealized sense, there is no deep conceptual difference.

What *does* matter in GRPO is that the advantage $\hat A_{i,t}$ is deliberately defined from the relative quality of the sampled completions inside each group. The paper’s point is that this quantity should reflect “which answer is better for this prompt,” not “which answer is closer to the reference model.” If you fold the KL term into the reward, then the KL penalty gets mixed into the reward signal used to build $\hat A_{i,t}$, and in GRPO that would contaminate the group-relative comparison with a dense regularization term. Since GRPO has no critic and uses group-normalized rewards, keeping KL outside makes the advantage estimator much cleaner and easier to interpret: $\hat A_{i,t}$ measures task success, while the KL term acts purely as a stabilizer.

So the practical difference is mostly about optimization dynamics and estimator design, not about the high-level objective. Separating the KL term gives a lower-variance, more transparent update: one part of the gradient comes from relative reward within the sampled group, and a separate part explicitly pushes the policy toward $\pi_{ref}$. That separation matters because GRPO uses clipped PPO-style updates and an unbiased KL estimator,
$$
\mathbb{D}_{KL}[\pi_\theta \| \pi_{ref}] = \frac{\pi_{ref}}{\pi_\theta} - \log\frac{\pi_{ref}}{\pi_\theta} - 1,
$$
so the regularizer is being handled as its own term rather than as part of the reward-to-advantage pipeline. In other words, it is not just implementation convenience: it is also a way to keep the group-relative advantage semantically clean and to make training more stable.

### How should I interpret the process-supervision advantage $\hat{A}_{i,t} = \sum_{\mathrm{index}(j) \ge t} \widetilde{r}_i^{\mathrm{index}(j)}$ in GRPO?
Question:
For process-supervised GRPO, the paper scores individual reasoning steps and defines each token's advantage as the sum of normalized rewards from all future step endpoints. This looks similar to a return in reinforcement learning, but I am not sure I understand the exact intuition. Why sum all future step rewards instead of using only the nearest step reward, or discounting them? Also, since the step rewards are normalized across the sampled outputs, does this mean the reward attached to one step depends on what other completions in the same group did?
Answer:
In the paper’s process-supervised GRPO, $\hat{A}_{i,t}=\sum_{\mathrm{index}(j)\ge t}\widetilde{r}_i^{\mathrm{index}(j)}$ is best read as an **undiscounted, step-level return** used for credit assignment, not as a fundamental RL quantity with a special derivation. The idea is that a token at time $t$ contributes not just to the immediate reasoning step it sits in, but to the rest of the chain of reasoning that follows. So the authors give that token credit or blame for the whole suffix of the solution: if later steps are good, earlier tokens that enabled them should be reinforced; if later steps go wrong, earlier tokens that set the trajectory should also receive some penalty. That is why they sum all future step rewards rather than using only the nearest step reward. Using only the nearest reward would make the signal much more local, but in a multi-step math solution the quality of an early step is often only visible once you see whether the later derivation stays consistent. The paper is explicitly trying to make supervision “step-aware,” and this sum is the simplest way to propagate step-level feedback backward through the reasoning trace.

The absence of discounting is also intentional in the sense that the paper does not introduce a discount factor at all. In this setting, the rewards are sparse and tied to reasoning-step endpoints, so discounting would arbitrarily downweight later reasoning signals without any discussion in the paper of why that would help. Their design is much closer to a heuristic Monte Carlo return over step rewards than to a discounted RL return. Since mathematical reasoning is sequential and intermediate steps matter equally as pieces of a proof-like chain, treating all future step rewards with equal weight is a natural choice. It is simple, aligns with their goal of fine-grained process supervision, and avoids needing a value function, which is one of GRPO’s main motivations.

Yes, the normalization makes the reward for one step depend on the other completions in the same sampled group. The paper defines $\widetilde{r}_i^{\mathrm{index}(j)} = \frac{r_i^{\mathrm{index}(j)}-\mathrm{mean}(\mathbf{R})}{\mathrm{std}(\mathbf{R})}$, where $\mathbf{R}$ is the collection of all step rewards across the $G$ sampled outputs for that question. So a step reward is not absolute; it is **relative to the group**. That dependence is not a bug, it is the whole point of GRPO: the method uses group-relative scores as a baseline, which the paper says matches the comparative nature of reward models trained on same-question comparisons. In other words, a step is rewarded if it looks better than the other sampled steps for the same prompt, and penalized if it looks worse. So both the normalization and the summed advantage are deliberately group-coupled: the model is learning from relative ranking signals within a question, not from independently calibrated per-step rewards.

### In what precise sense are DPO, RFT, PPO, and GRPO all part of one 'unified RL paradigm'?
Question:
The paper writes the gradient of several training methods in the common form

$\nabla_{\theta} \mathcal{J}_{\mathcal{A}}(\theta) = \mathbb{E}_{(q,o) \sim \mathcal{D}} \left[ \frac{1}{|o|} \sum_{t=1}^{|o|} GC_{\mathcal{A}}(q, o, t, \pi_{rf}) \nabla_{\theta} \log \pi_{\theta}(o_t \mid q, o_{<t}) \right].$

I can see this as a formal rewriting, but I am not sure when it is actually insightful rather than just notational. For example, DPO is usually presented as supervised preference optimization, not RL in the usual online sense. So what is the substantive claim here? Is the paper saying these methods are equivalent, approximately equivalent, or just structurally comparable after choosing different data sources and gradient coefficients?
Answer:
The paper is **not** claiming that DPO, RFT, PPO, and GRPO are mathematically equivalent, nor that DPO is the same thing as online RL. The claim is weaker, and more useful: they can all be viewed as instances of the same **policy-update template**, where the model is trained by increasing the log-probability of sampled tokens with a coefficient that comes from some notion of reward or preference.

That is what their equation is doing. It has the generic form

$$
\nabla_{\theta} \mathcal{J}_{\mathcal A}(\theta)
=
\mathbb{E}_{(q,o)\sim \mathcal D}
\left[
\frac{1}{|o|}\sum_{t=1}^{|o|}
GC_{\mathcal A}(q,o,t,\pi_{rf})\,
\nabla_{\theta}\log \pi_\theta(o_t\mid q,o_{<t})
\right].
$$

This is basically a weighted policy-gradient / weighted maximum-likelihood update. The unification comes from the fact that all the methods differ only in three places: where the training data $\mathcal D$ comes from, what plays the role of the reward signal $\pi_{rf}$, and how that signal is turned into the gradient coefficient $GC_{\mathcal A}$.

So the substantive point is structural, not equivalence. RFT uses offline sampled outputs and a rule-based correctness signal; good outputs are kept and reinforced, bad ones are discarded. DPO also uses offline data, but the signal is a pairwise preference between outputs rather than an explicit reward model. PPO uses online samples from the current policy, a learned reward model, and an advantage estimate, usually with a critic. GRPO is the same PPO-style online RL idea, but it replaces the critic with a group-relative baseline computed from multiple sampled outputs, which is why the paper calls it a simpler and more memory-efficient variant.

So in the paper’s sense, these methods are all part of one “unified RL paradigm” because they all **update a policy using reward- or preference-derived coefficients on sampled completions**. They are not identical algorithms, and the paper is not proving formal equivalence. It is saying that once you write the gradient this way, the key differences are: offline versus online sampling, rule-based versus model-based feedback, and coarse versus fine-grained credit assignment. That is exactly why the authors can compare them in one framework and study which design choices actually matter.

### Why does reinforcement learning improve $\mathrm{Maj}@K$ but not $\mathrm{Pass}@K$, and what does that imply about 'reasoning ability'?
Question:
One of the most interesting claims in the discussion is that RL improves $\mathrm{Maj}@K$ but not $\mathrm{Pass}@K$, and the authors interpret this as making the output distribution more robust rather than improving fundamental capability. I am not fully convinced I understand this. If $\mathrm{Pass}@K$ stays the same, does that mean the model already knew how to solve those problems before RL, but RL only makes correct solutions more likely? If so, should RL here be viewed more as calibration or preference shaping than as learning new reasoning skills? I would appreciate an explanation of how to read these two metrics together.
Answer:
The clean way to read the two metrics is that they measure different things about the sampled output distribution.

$\mathrm{Pass}@K$ asks, “if I draw $K$ solutions, is at least one of them correct?” So it is sensitive to whether the model has any correct solution in its support under sampling. $\mathrm{Maj}@K$ asks, “if I draw $K$ solutions and take the majority answer, is that answer correct?” So it is sensitive to where the probability mass is concentrated.

That distinction is exactly why the paper interprets “RL improves $\mathrm{Maj}@K$ but not $\mathrm{Pass}@K$” as distribution shaping rather than a big jump in underlying competence. If the model already occasionally samples a correct chain of thought, then $\mathrm{Pass}@K$ can already be high or even saturated. RL can still move probability mass away from plausible but wrong reasoning paths and toward the correct one, which makes the correct answer more likely to be the modal answer and therefore improves $\mathrm{Maj}@K$. A toy example makes this obvious: before RL, among $10$ samples you might get $1$ correct and $9$ wrong, so $\mathrm{Pass}@10=1$ but $\mathrm{Maj}@10=0$; after RL you might get $6$ correct and $4$ wrong, so both become $1$, even though the “ability to ever produce a correct solution” was already there before RL.

So yes, in the paper’s framing, the model likely already had latent reasoning capability on those tasks, and RL mainly made that capability more reliable and self-consistent. That is closer to preference shaping or policy sharpening than to learning an entirely new reasoning skill. The authors say this explicitly in the discussion: RL “enhances the model’s overall performance by rendering the output distribution more robust,” and they add that the gain seems to come from boosting the correct response among the top-$K$ samples “rather than the enhancement of fundamental capabilities.”

One caveat is that unchanged $\mathrm{Pass}@K$ does not *prove* no new capability was learned; the metric can saturate, especially for larger $K$. But taken together, the two metrics strongly suggest the main effect of RL here is to make correct reasoning paths more probable relative to incorrect ones, not to expand the set of problems the model can in principle solve. In practice, that is still very valuable: it makes the model more dependable under sampling, which is exactly what majority vote and self-consistency are trying to exploit.

### Why does online sampling help more than offline sampling in the later stages of training?
Question:
In the unified-paradigm analysis, the paper says Online RFT eventually outperforms offline RFT because the actor diverges from the initial SFT model over time, so real-time samples become more informative. I follow this intuitively, but I am missing a sharper explanation. Is the main issue distribution shift, where the offline dataset stops representing the model being optimized? Or is it that online sampling naturally creates a curriculum by exposing the reward model and policy to progressively harder or more varied outputs? I want to understand exactly what advantage online data provides that offline augmented data cannot.
Answer:
In the paper’s unified-paradigm view, the main advantage of online sampling is not so much a hand-designed curriculum as it is that the training data stays *on-policy*, i.e. matched to the model you are actually updating.

The key point is that offline RFT samples from the initial SFT model, while online RFT samples from the current actor as it changes. Early in training, those two distributions are similar, so offline and online data look almost the same and the gap is small. But later on, the policy has moved away from the SFT model. At that point, an offline dataset becomes stale: it reflects what the old model used to produce, not what the current model is producing now. Those samples are therefore less informative for the present optimization problem. The paper says this explicitly: in the later stage, “the actor will exhibit more significant differences, and real-time data sampling will offer greater advantages.”

Why is that useful? Because the most informative training examples are usually the ones near the model’s current weaknesses. If the model has already mastered the easy patterns present in the offline augmented set, then more samples from that same old distribution mostly repeat familiar cases. Online sampling, by contrast, automatically tracks the model’s evolving failure modes and newly reachable outputs. That gives you fresh positive examples and fresh hard negatives exactly where the model is making mistakes or where small changes in probability matter most.

So, if you want a sharper summary: the benefit is primarily *distribution shift between the offline samples and the current policy*. Curriculum-like behavior can happen as a side effect, because the model tends to encounter different and often harder outputs as it changes, but the paper’s analysis is really about *policy mismatch* and the improved informativeness of on-policy data, not an explicit curriculum mechanism.

This also explains why online RFT is only comparable to offline RFT at the beginning and then pulls ahead later: at first there is little mismatch; later, the mismatch grows, and only online sampling continues to generate training data aligned with the policy being optimized.

### How can GRPO be more memory-efficient than PPO if it samples $64$ outputs per question?
Question:
The paper emphasizes that GRPO saves memory by removing the critic model, which makes sense. But in the RL setup they also sample $64$ outputs for each question, and that sounds expensive in its own right. I am confused about where the actual savings come from. Is the claim specifically about training-time parameter memory because there is no separate value network, while the large group size mainly affects inference-like rollout cost? In other words, what is the right apples-to-apples comparison between PPO and GRPO in terms of memory and compute?
Answer:
Yes — your interpretation is basically right. The “memory-efficient” claim is about removing the critic/value network, not about making the rollout stage free.

In the paper’s PPO description, the extra burden comes from the learned value function $V_\psi$, which is “typically another model of comparable size as the policy model.” That means PPO is training and storing an additional transformer-sized network, plus its optimizer states and activations for backprop. In an LLM setting, that is usually the dominant persistent memory cost. GRPO replaces that critic with a group-relative baseline computed from multiple sampled completions of the same question, so there is no separate value model to keep on GPU.

The fact that GRPO samples $64$ outputs per question is a different kind of cost: it is rollout/exploration compute, not model-parameter memory. Those $64$ completions do not require keeping $64$ full models in memory; they are just generated sequences. At worst, they increase the memory needed to hold a batch of token IDs, logprobs, and rewards, which is tiny compared with the memory for a second 7B-class network and its gradients. So the paper is not claiming that GRPO is cheaper in every sense, only that it reduces the training-time memory footprint of PPO by dropping the critic.

The clean apples-to-apples comparison is therefore this: keep the policy, reward model, reference model, and rollout length fixed. PPO needs all of that plus a value network, whereas GRPO needs no value network but does need a group of samples per prompt to estimate the baseline from the group mean and variance. So GRPO trades some extra sampling compute for substantially less model memory. That is also why the paper separately mentions that “efficient inference techniques” matter for exploration efficiency: the rollout side is a distinct issue from the memory saved by removing the critic.

So the short answer is: the $64$ samples mainly affect compute and rollout cost; the actual memory saving comes from not storing and training a separate critic/value model.

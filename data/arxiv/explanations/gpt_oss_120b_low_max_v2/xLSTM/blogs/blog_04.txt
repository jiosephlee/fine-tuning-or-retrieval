# Building xLSTM Blocks: Residual Connections, Up‑Projection, and Scaling to Billions of Parameters  

When LSTMs first appeared in the early 1990s, their constant‑error carousel and gating mechanisms solved the vanishing‑gradient problem that plagued ordinary recurrent networks. Decades later, Transformers eclipsed LSTMs on large‑scale language modeling thanks to parallelizable self‑attention. The recent **xLSTM** paper asks a simple but bold question: *What happens when we bring the classic LSTM ideas all the way up to billions of parameters, while fixing their known shortcomings?*  

The answer lies in a clever combination of three ingredients:

1. **Exponential gating** that lets the network revise past storage decisions.  
2. **New memory structures** – a scalar‑memory sLSTM and a matrix‑memory mLSTM – that dramatically increase capacity or enable full parallelism.  
3. **Residual up‑projection blocks** that embed these recurrent cores in a deep, high‑dimensional backbone, much like modern Transformer stacks.

In this post we focus on the third piece: how xLSTM builds **xLSTM blocks**, the residual modules that make scaling to billions of parameters both feasible and competitive with state‑of‑the‑art Transformers.

---

## Why Residual Blocks Matter

Deep networks suffer from vanishing or exploding gradients as they get deeper. Residual connections—originally popularized by ResNets—solve this by letting each layer learn a *delta* on top of its input rather than a completely new representation. In language models, almost every architecture now uses a pre‑LayerNorm residual stack:  

\[
\mathbf{x}_{\ell+1}= \mathbf{x}_{\ell}+ \text{FFN}\big(\text{Norm}(\mathbf{x}_{\ell})\big),
\]  

where `Norm` is layer normalization and `FFN` is a feed‑forward sub‑module (self‑attention in Transformers, recurrent core in RNNs).  

xLSTM adopts the same philosophy but swaps out the attention sub‑layer for an **sLSTM** or **mLSTM** core wrapped inside an *up‑projection* residual block.

---

## Two Flavors of Up‑Projection

The authors experiment with **post up‑projection** (Transformer‑style) and **pre up‑projection** (State‑Space‑Model style) blocks. The difference is where the dimensionality expansion happens relative to the nonlinearity that summarizes the past.

### 1. Post Up‑Projection (sLSTM)

```
input ─► LayerNorm ─► sLSTM ─► Linear (down) ─► Activation
       │                                         │
       └───────────────────── Linear (up) ◄─────┘
                 ↑                              
            residual add
```

1. **LayerNorm** normalizes the incoming token embeddings.  
2. The **sLSTM core** processes the sequence with exponential gates and a scalar cell (plus optional mixing across multiple heads).  
3. Its output is first *projected down* to the original hidden size, then passed through a nonlinearity (e.g., GELU).  
4. Finally, a *linear up‑projection* expands back to the high dimensionality used for the next residual addition.

Why “post”? The nonlinearity lives *after* we have already collapsed back to the original hidden size, mirroring how Transformers first apply attention in the base space and then upscale.

### 2. Pre Up‑Projection (mLSTM)

```
input ─► Linear (up) ─► LayerNorm ─► mLSTM ─► Activation ─► Linear (down)
       │                                                                     │
       └───────────────────────────────────── residual add ◄───────────────────┘
```

1. The input is first *projected up* into a high‑dimensional space (often 4× or 8× the hidden size).  
2. After normalization, the **mLSTM core**—with its matrix memory \(\mathbf{C}\in\mathbb{R}^{d\times d}\)—updates and retrieves information via a covariance rule, all while keeping operations fully parallelizable across time steps.  
3. A nonlinearity follows, then a *down* projection returns us to the original hidden dimension before adding back the residual.

The “pre” layout lets the massive matrix memory operate where there is ample capacity; it also aligns with recent State Space Models that place their linear dynamics in an enlarged state space before folding back.

---

## Plugging sLSTM / mLSTM into Residual Blocks

Both block types share a common scaffold:

- **Input → LayerNorm → Core → Activation → Linear → Residual Add → Output**

The only difference is whether we expand *before* (`pre`) or *after* (`post`) the core. This decision is driven by each core’s strengths:

| Core | Memory Type | Parallelism | Preferred Block |
|------|-------------|------------|-----------------|
| **sLSTM** | Scalar cell + exponential gating + memory mixing | Sequential (hidden–hidden connections) | Post up‑projection |
| **mLSTM** | Full matrix \(\mathbf{C}\) + covariance update | Fully parallelizable (no hidden–hidden links) | Pre up‑projection |

When building a deep xLSTM model you can mix both block types arbitrarily: e.g., an architecture denoted **xLSTM[7:1]** contains 7 mLSTM blocks and 1 sLSTM block per 8 residual layers. This hybrid design lets you reap parallel speed from mLSTM while still benefiting from sLSTM’s richer mixing dynamics.

---

## Scaling to Billions of Parameters

With residual connections handling depth, three more ingredients enable billion‑parameter scaling:

1. **Layer Normalization before every core** stabilizes training across long sequences—critical when memory updates become huge (`d×d` matrices).  
2. **Exponential gates** (`i_t = \exp(\tilde{i}_t)`, `f_t = \exp(\tilde{f}_t)` optionally) increase representational power but can overflow; xLSTM incorporates a stabilizer state `m_t` that rescales gates without altering gradients.  
3. **Memory Normalizer (`n_t`)** tracks cumulative gate strength so that divisions such as \(\tilde{h}_t = c_t / n_t\) stay numerically well behaved.

Because each block adds only a modest constant amount of computation per token—linear in sequence length—the overall cost grows as \(\mathcal{O}(T)\) rather than quadratically like self‑attention (\(\mathcal{O}(T^2)\)). This efficiency makes it practical to train models with hundreds of millions or even billions of parameters on commodity GPU clusters.

Empirically, xLSTM models trained on 15 B tokens from SlimPajama already beat GPT‑3–scale Transformers on validation perplexity; scaling experiments up to 300 B tokens show consistent gains and superior long‑context extrapolation (up to 16 k tokens).

## Putting It All Together: A Minimal xLSTM Block Recipe

Below is a concise pseudo‑code sketch for constructing an xLSTM block:

```python
def xlstm_block(x, core='m', dim=1024, upscale=4):
    # x : [B, T, dim] token embeddings
    
    # 1️⃣ Up/down projection choice
    if core == 'm':               # mLSTM -> pre up-projection
        x_up = linear(x, dim*upscale)          # ↑
        y = layer_norm(x_up)
        y = m_lstm(y)                          # matrix memory core
        y = gelu(y)
        y = linear(y, dim)                     # ↓
    else:                         # sLSTM -> post up-projection
        y = layer_norm(x)
        y = s_lstm(y)                          # scalar memory core
        y = linear(y, dim)                     # ↓
        y = gelu(y)
        y = linear(y, dim*upscale)             # ↑
    
    # 2️⃣ Residual add (pre‐LayerNorm style)
    out = x + y
    return out
```

Stacking dozens of such blocks—wrapped with the usual pre‐LayerNorm pattern—yields an **xLSTM architecture** ready for large‐scale language modeling.

---

## Takeaways

- **Residual up/down projection blocks** give xLSTM enough representational bandwidth to compensate for LSTMs’ historically limited capacity.  
- The choice between *pre* and *post* up‐projection hinges on whether you use an mLSTM (parallel matrix memory) or an sLSTM (sequential mixing).  
- By embedding these blocks inside standard pre‑LayerNorm residual stacks, xLSTM inherits all the training stability tricks of modern Transformers while retaining linear time/space complexity.  
- Scaling experiments show that even modestly sized xLSTMs already outperform contemporary Transformers and State Space Models; larger models should continue this trend thanks to clean scaling laws.

In short, xLSTM proves that classic recurrent ideas are not dead—they just needed a modern upgrade: exponential gating, richer memories, and clever residual engineering. If you’re curious about building your own billion‑parameter recurrent language model, start by wiring sLSTM/mLSTM cores into post or pre up‑projection blocks and let residual connections do the heavy lifting!

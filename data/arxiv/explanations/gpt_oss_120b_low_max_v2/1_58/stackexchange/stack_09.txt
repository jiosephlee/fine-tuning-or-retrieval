\title{Stack Exchange of the Paper: "The Era of 1-bit LLMs: All Large Language Models are in 1.58 Bits"}

### Is there any loss in expressivity when all linear layers use ternary weights while embeddings remain full precision?
Question:
BitNet b1.58 keeps embedding layers in full precision but quantizes all subsequent linear projections to ternary values. Could this mismatch cause representational bottlenecks, especially for tasks requiring fine‑grained token embeddings? Has any ablation been performed where embeddings are also ternarized?
Answer:
In **BitNet b1.58** the authors deliberately leave the token‑embedding matrix in 16‑bit (FP16/BF16) while all other linear layers are replaced by the ternary **BitLinear** module.  The paper does not present an experiment in which the embedding matrix itself is ternarised, but the design choices and the reported results give a clear picture of why this “mismatch’’ does not create a representational bottleneck.

### Why full‑precision embeddings are kept

1. **Relative size of the embedding matrix** –  
   For a typical LLaMA‑style model the embedding table accounts for only a few percent of the total parameter budget (roughly $V\times d$ where $V$ is the vocab size and $d$ the hidden dimension).  Even for a 70 B‑parameter model, the embedding layer is less than 5 % of all weights.  Consequently, its memory contribution becomes negligible as the model scales, which is precisely what the authors note when discussing Fig. 2: “the embedding remains full precision and its memory proportion is smaller for larger models”.

2. **Information density of token embeddings** –  
   The embedding vectors are the first place where discrete symbols are mapped into a continuous space.  A high‑precision representation makes it easier for the downstream ternary linear layers to recover fine‑grained semantic distinctions, especially for low‑frequency tokens that have few training examples.  By keeping these vectors in FP16 the model can still allocate three bits per weight for every later transformation without losing the subtle differences that were learned during pre‑training.

3. **Training stability** –  
   The quantisation function used for weights (the *absmean* rounding to $\{-1,0,1\}$) is applied only to parameters that participate in massive matrix multiplications.  Applying it to embeddings would introduce a large amount of zero‑weight noise early in the forward pass, which could destabilise gradient flow because every token would start from a highly quantised representation.  The authors therefore follow the same strategy as the original BitNet paper: quantise only *nn.Linear* modules and leave input embeddings untouched.

### Does this cause an expressivity loss?

Empirically, **no**.  All reported metrics—validation perplexity on WikiText‑2 and C4, zero‑shot accuracies on ARC, Hellaswag, Winogrande, PIQA, etc.—show that BitNet b1.58 matches or exceeds its FP16 baseline starting at 3 B parameters.  The authors explicitly state:

> “It matches the full‑precision Transformer LLM with the same model size … in terms of both perplexity and end‑task performance.”

Because the overall performance curve lines up with the FP16 baseline, any potential bottleneck from keeping embeddings higher precision must be negligible relative to the gains from ternarising all other linear maps.

### Have embeddings been ternarised in an ablation?

The paper does **not** include an ablation where the embedding table is also quantised to ternary values.  The discussion sections focus on scaling laws, latency, memory and energy consumption; they never mention a variant with ternary embeddings, nor do they report any degradation when doing so.  This omission suggests that either (i) such an experiment was not performed because prior work (e.g., BitNet 1‑bit) already demonstrated that full‑precision embeddings are essential for maintaining quality, or (ii) it was tried and yielded noticeably poorer perplexity—hence it was omitted in favour of the more successful configuration.

### Intuition from related work

In earlier 1‑bit/2‑bit quantisation studies (e.g., BinaryConnect, DoReFa-Net), it is common to keep the first and last layers at higher precision precisely because they act as “information portals” between discrete data and heavily compressed internal representations.  The same principle applies here: token embeddings are akin to input layers; preserving their resolution helps downstream ternary layers extract useful patterns despite their limited alphabet $\{-1,0,+1\}$.

### Take‑away

- The paper’s evidence indicates **no measurable loss of expressivity** when only linear projections are ternarised while embeddings stay in FP16/BF16.
- The authors have not published an ablation with ternary embeddings; therefore we cannot quote exact numbers, but based on both theory (embedding size proportion) and practice (successful benchmarks) it is reasonable to conclude that such a variant would likely hurt performance.
- If you need a fully ternary model for extreme hardware constraints, you would have to accept some degradation or compensate with larger model size or more training tokens—a direction that future work could explore.

In short, within the scope of BitNet b1.58 there is no expressivity bottleneck caused by keeping full‑precision embeddings; rather it is a pragmatic design choice that preserves overall model quality while still achieving dramatic reductions in memory, latency and energy consumption.

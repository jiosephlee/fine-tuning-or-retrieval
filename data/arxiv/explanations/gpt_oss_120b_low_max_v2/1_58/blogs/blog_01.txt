# From 16‑bit to 1.58‑bit: How BitNet b1.58 Shrinks LLMs Without Losing Accuracy  

Large language models (LLMs) have become the workhorse of modern NLP, but their ever‑growing size brings hefty memory, latency, and energy costs. Recent progress in quantization shows that we can trim the bits used to store model parameters—sometimes dramatically—while keeping the model useful. The newest milestone is **BitNet b1.58**, a transformer whose every weight is ternary (‑1, 0, +1). Despite using only **1.58 bits** per parameter on average, it matches full‑precision (FP16/BF16) LLaMA baselines in perplexity and downstream task performance.  

In this post we walk through the core ideas that make this possible: the ternary quantization scheme, why the extra “0” value matters, and how the resulting model sidesteps the usual trade‑off between bit‑width and accuracy.

---

## Why Go Below 2 Bits?  

Standard LLMs store weights as 16‑bit floating‑point numbers. Most of the compute in a transformer is spent on matrix multiplications inside `nn.Linear` layers, which require costly FP16 multiplies and adds. By collapsing the weight space to a tiny set of integer values we replace those multiplications with cheap integer additions.  

A pure 1‑bit model would restrict weights to {‑1,+1}. That eliminates multiplications altogether but also removes a way to **filter** information: every input dimension contributes either positively or negatively, never “off”. BitNet b1.58 adds a third option, **0**, which lets the network explicitly drop irrelevant features at each layer. The result is a *ternary* representation that behaves like a “soft” sparsity pattern while still needing almost no multiplication.

---

## Ternary Quantization: From Real Weights to {‑1, 0, +1}

Training starts with full‑precision weights \(W\in\mathbb{R}^{n\times m}\). To force them into the ternary set we apply an **absmean quantizer**:

\[
\gamma = \frac{1}{nm}\sum_{i,j}|W_{ij}| \quad\text{(average absolute magnitude)}
\]

\[
\widetilde{W}_{ij}= \operatorname{RoundClip}\!\left(\frac{W_{ij}}{\gamma+\epsilon},\, -1,\, 1\right)
\]

where  

\[
\operatorname{RoundClip}(x,a,b)=\max\bigl(a,\;\min\bigl(b,\;\operatorname{round}(x)\bigr)\bigr)
\]

and \(\epsilon\) is a tiny constant for numerical stability.  

The scaling by \(\gamma\) normalizes the weight distribution so that most entries land near zero after division; rounding then snaps each entry to the nearest integer in \{-1,0,+1\}. Because \(\gamma\) is recomputed each step, the quantizer adapts as training progresses, preserving gradient flow while keeping the weights ternary.

### Activation Quantization

Activations stay in 8‑bit integer format (INT8). Unlike BitNet’s original scheme that shifts activations into \([0,Q_b]\), BitNet b1.58 scales them symmetrically to \([-Q_b,Q_b]\) per token. This removes the need for a zero‑point offset and simplifies hardware implementation without measurable loss in accuracy.

---

## Zero Weights Aren’t “Empty”: The Role of Sparsity

The added zero value gives each linear layer a built‑in **feature selector**:

* **Noise reduction** – If an input dimension consistently harms predictions, its weight can become zero, preventing it from affecting downstream layers.
* **Effective sparsity** – Even though every weight is stored (as 2 bits for sign + an extra bit for “is zero”), many of them become zero during training, yielding fewer active MAC operations.
* **Better representational capacity** – With three possible states per weight we get roughly \(\log_2(3) \approx 1.58\) bits of information per parameter—hence the name *b1.58*. This modest increase over pure 1‑bit gives enough flexibility to recover accuracy losses that would otherwise appear.

Empirically, this design choice pays off: starting at just 3 B parameters, BitNet b1.58’s perplexity on WikiText‑2 and C4 aligns with its FP16 LLaMA counterpart, and downstream zero‑shot benchmarks (ARC-Easy/Challenge, Hellaswag, Winogrande, PIQA, etc.) are within a few percentage points—often indistinguishable when model size grows beyond 3 B.

---

## Performance Gains: Speed, Memory & Energy

| Metric (3 B model) | FP16 LLaMA | BitNet b1.58 |
|-------------------|------------|--------------|
| Perplexity (WikiText‑2) | ~8.5 | ~8.5 |
| GPU memory (GiB) | 14 | **4** (≈3.5× less) |
| Token latency (ms) | 12 | **4.5** (≈2.7× faster) |
| Energy per matmul (7nm estimate) | 1× | **0.014×** (~71× savings) |

Key observations:

* **Latency** improves because a ternary matrix multiply reduces to integer additions; on GPUs this translates into fewer hardware cycles.
* **Memory** shrinks dramatically: storing 2 bits per weight versus 16 bits yields a >8× raw reduction; after accounting for metadata and activations we still see >3× savings.
* **Energy** consumption drops by more than an order of magnitude for matrix multiplication—the dominant operation in LLM inference.

These advantages amplify with scale: a 70 B BitNet b1.58 runs roughly **4× faster** than a 70 B FP16 LLaMA model while using far less memory; throughput on dual A100s rises almost tenfold thanks to larger batch sizes fitting into GPU RAM.

---

## Training at Scale: The Token Budget Matters

BitNet b1.58 was trained from scratch on the RedPajama corpus for **100 B tokens**, matching the token budget of the reproduced FP16 baselines. When extended to **2 T tokens**, following StableLM‑3B’s data recipe, the ternary model outperformed StableLM on every evaluated task (Winograde, PIQA, SciQ, LAMBADA, ARC‑Easy). This demonstrates that reduced precision does not hinder learning dynamics provided enough data is supplied.

---

## What This Means for Future LLMs

* **New scaling law:** A 13 B BitNet b1.58 is more efficient than a 3 B FP16 model; a 30 B ternary model beats a 7 B full‑precision one; even a 70 B b1.58 surpasses a 13 B FP16 baseline in latency, memory and energy.
* **Edge & mobile deployment:** With sub‑4 GiB memory footprints for multi‑billion parameter models and CPU‑friendly INT8 activations, ternary LLMs become viable on devices previously incapable of running any transformer at all.
* **Hardware opportunities:** The near‑absence of multiplications opens up specialized accelerators (e.g., LPUs à la Groq) that can implement dedicated INT8 add pipelines and massive parallel SRAM arrays tailored for ternary weights.
* **Mixture-of-Experts & long context:** Ternary weights reduce inter‑chip communication overhead in MoE architectures and cut KV‑cache size by half (activations are already INT8), paving the way for native long‑sequence support.

---

## Takeaway

BitNet b1.58 proves that *fewer bits do not inevitably mean weaker models*. By carefully designing a ternary quantizer and leveraging the expressive power of zero weights, we can compress every parameter down to an average of **1.58 bits** while preserving—and sometimes even improving—accuracy on standard LLM benchmarks. The resulting speedups, memory savings, and energy reductions are substantial enough to rewrite deployment economics for both cloud-scale inference and edge devices.

If you’re interested in experimenting with ternary LLMs yourself, look for implementations integrated with HuggingFace Transformers or vLLM; they already include BitLinear layers that handle the quantization logic out of the box.

*The era of ultra‑low‑bit LLMs has arrived—welcome to the world of 1.58‑bit transformers.*

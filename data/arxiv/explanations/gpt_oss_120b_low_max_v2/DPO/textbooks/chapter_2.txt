Chapter 2: Foundations: Preference Modeling and the Standard RLHF Pipeline  

# Supervised Fine‑Tuning (SFT) of a Reference Policy  

Before any preference information can be exploited, a large language model (LM) must first acquire a base capability for the downstream task of interest.  In the standard RLHF pipeline this step is called **supervised fine‑tuning** (SFT).  An SFT model, denoted \(\pi^{\text{SFT}}\), is obtained by taking a pretrained, unsupervised language model \(\pi^{\text{pre}}\) and further training it with maximum‑likelihood estimation on a collection of high‑quality input–output pairs \(\{(x, y)\}\).  Concretely, the objective is  

\[
\max_{\theta}\; \mathbb{E}_{(x,y)\sim\mathcal{D}_{\text{SFT}}}\bigl[\log \pi_{\theta}(y\mid x)\bigr],
\]

where \(\pi_{\theta}\) denotes the parametric policy (the LM) and \(\mathcal{D}_{\text{SFT}}\) is the supervised dataset.  The result is a **reference policy** \(\pi_{\text{ref}} := \pi^{\text{SFT}}\) that already produces reasonable completions for the tasks at hand (dialogue, summarization, coding assistance, etc.).  This reference policy serves two purposes in later stages: it provides a stable starting point for further optimization and it defines the “status‑quo” distribution that the RL stage is constrained not to deviate from too drastically.  

Because SFT relies only on explicit demonstrations (complete answers written by humans), it is straightforward to implement: one simply runs standard cross‑entropy training on a GPU cluster.  However, collecting enough high‑quality demonstrations for all possible tasks can be expensive, motivating the use of *relative* human judgments—pairwise preferences—as a cheaper source of supervision.

# Collecting Pairwise Human Preferences  

Instead of asking annotators to craft an ideal response for each prompt, we can ask them to compare two candidate completions and indicate which one they prefer.  Formally, for a given prompt \(x\) we sample two continuations \(y_1, y_2\) from the reference policy \(\pi_{\text{ref}}(\cdot\mid x)\).  A human labeler then supplies a binary judgment  

\[
y_w \succ y_l \mid x,
\]

where \(y_w\) is the *winner* (preferred) and \(y_l\) is the *loser* (dispreferred).  Collecting many such triples \((x, y_w, y_l)\) yields an offline dataset  

\[
\mathcal{D} = \bigl\{(x^{(i)}, y_w^{(i)}, y_l^{(i)})\bigr\}_{i=1}^{N},
\]

which captures human notions of quality—safety, helpfulness, factuality, sentiment alignment, etc.—without requiring fully written demonstrations.  Pairwise judgments are typically easier and faster for annotators because they merely need to decide “which sounds better?” rather than construct a perfect answer from scratch.

# Bradley‑Terry (and Plackett‑Luce) Preference Formulation  

To turn the raw preference data into a statistical model we adopt the **Bradley‑Terry (BT)** formulation, a special case of the more general **Plackett‑Luce** ranking model.  The BT model assumes that each answer \(y\) paired with its context \(x\) possesses an unobserved scalar *reward* \(r^{*}(x,y)\).  The probability that a human prefers \(y_1\) over \(y_2\) is then

\[
p^{*}(y_1 \succ y_2 \mid x)
   = \frac{\exp \bigl(r^{*}(x,y_1)\bigr)}
          {\exp \bigl(r^{*}(x,y_1)\bigr)+\exp \bigl(r^{*}(x,y_2)\bigr)}.
\tag{1}
\]

Equation (1) captures the intuition that larger rewards make a completion more likely to be chosen; the logistic denominator ensures probabilities sum to one across any pair.

The Plackett‑Luce model extends this idea to rankings of three or more items by multiplying together BT‐type factors for each successive pair in the ranking.  In practice most RLHF datasets contain only binary comparisons, so BT suffices.

# Maximum‑Likelihood Reward Model Training  

Given a parametric reward function \(r_{\phi}(x,y)\)—often implemented as an additional linear head on top of the frozen SFT transformer—we fit its parameters by maximizing the likelihood of the observed preferences under Eq. (1).  The **negative log‑likelihood** loss is

\[
\mathcal{L}_{R}(r_{\phi}, \mathcal{D})
   = -\,\mathbb{E}_{(x,y_w,y_l)\sim \mathcal{D}}
      \Bigl[\,\log\sigma\!\bigl(r_{\phi}(x,y_w)-r_{\phi}(x,y_l)\bigr)\Bigr],
\tag{2}
\]

where \(\sigma(z)=1/(1+e^{-z})\) denotes the logistic sigmoid.  Intuitively, Eq. (2) encourages the reward difference \(r_{\phi}(x,y_w)-r_{\phi}(x,y_l)\) to be positive whenever humans prefer \(y_w\).  In many implementations the reward head is initialized from the SFT model’s final hidden state so that it inherits linguistic knowledge before learning to discriminate preferences.

A practical detail often applied in RLHF pipelines is **reward centering**: after each optimization step we subtract the mean reward over all examples so that  

\[
\mathbb{E}_{(x,y)}[r_{\phi}(x,y)] = 0.
\]

Centering reduces variance of subsequent RL updates without affecting Eq. (2), because adding a constant to every reward leaves preference probabilities unchanged.

# KL‑Constrained Reward Maximization Objective  

Once we have an estimate \(r_{\phi}\) of human preferences, we wish to adjust the language model so that it generates responses with high expected reward.  At the same time we want to avoid moving too far from the reference policy \(\pi_{\text{ref}}\).  This trade‑off is formalized as a **KL‑constrained objective**:

\[
\max_{\pi_{\theta}}
    \;\mathbb{E}_{x\sim p(x),\, y\sim \pi_{\theta}(\cdot|x)}
        \bigl[\, r_{\phi}(x,y) \,\bigr]
    - \beta\, 
      D_{\mathrm{KL}}\!\bigl(\pi_{\theta}(\cdot|x)\,\|\,\pi_{\text{ref}}(\cdot|x)\bigr).
\tag{3}
\]

The first term encourages high reward; the second penalizes divergence from the reference distribution with strength controlled by hyperparameter \(\beta>0\).  The KL penalty serves two purposes:

1. **Safety of reward extrapolation** – The learned reward model is only reliable near the distribution on which it was trained (the SFT data).  
2. **Preservation of diversity** – Without any penalty the policy could collapse to always emit a single “high‑reward” token sequence.

Because language generation proceeds token by token, Eq. (3) actually involves a sum of per‑token KL divergences; nevertheless it can be written compactly as above.

# Reinforcement Learning Methods Used in RLHF (REINFORCE, PPO)  

The objective in Eq. (3) is not differentiable with respect to the LM parameters when sampling discrete tokens.  Consequently traditional RL techniques are employed.

* **REINFORCE** – The simplest Monte Carlo policy gradient method estimates  

  \[
  \nabla_{\theta} J(\theta)
   = \mathbb{E}_{y\sim \pi_{\theta}}
       \bigl[\, (r_{\phi}(x,y)-b(x))\,
              \nabla_{\theta}\log \pi_{\theta}(y|x)
       \bigr],
  \]

  where \(b(x)\) is a baseline (often an estimate of expected reward) used to reduce variance.  REINFORCE directly optimizes Eq. (3) but suffers from high variance and unstable learning when applied to large language models.

* **Proximal Policy Optimization (PPO)** – PPO improves stability by clipping probability ratios and adding an explicit KL penalty term during optimization.  In practice RLHF implementations rewrite Eq. (3) into an *advantage* form

  \[
  A(x,y)= r_{\phi}(x,y)-
          \beta\,(\log \pi_{\theta}(y|x)-\log \pi_{\text{ref}}(y|x)),
  \]

  and then maximize an objective such as  

  \[
  L^{\text{PPO}}(\theta)=
     \mathbb{E}\!\Bigl[\,
        \min
        \Bigl(
            A(x,y)\frac{\pi_{\theta}(y|x)}{\pi_{\text{old}}(y|x)},
            {\rm clip}\bigl(A(x,y),1-\epsilon,1+\epsilon\bigr)
        \Bigr)
     \Bigr],
  \]

  where \(\pi_{\text{old}}\) denotes the policy before the current update and
  \(\epsilon\simeq0.2.\)
  
Both REINFORCE and PPO require **sampling** from the current policy at every training step in order to obtain trajectories \(y\).   This sampling loop dramatically increases computational cost compared with ordinary supervised learning because each update needs fresh forward passes through a large decoder network for many candidate completions.

# Why the Partition Function Makes Classic RLHF Expensive  

In Eq. (3), under exact solution theory one can solve for the optimal policy analytically:

\[
\pi_{r}^{*}(y|x)=
   \frac{
      \pi_{\text{ref}}(y|x)\,
      e^{\,r(x,y)/\beta}
   }{
      Z_{r}(x)
   }, 
   \qquad 
   Z_{r}(x)=
   \sum_{y'} 
       \pi_{\text{ref}}(y'|x)
       e^{\,r(x,y')/\beta}.
   \tag{4}
\]

The factor \(Z_{r}(x)\)—the **partition function**—normalizes probabilities so that they sum to one.  
Computing \(Z_{r}(x)\) exactly requires summing over all possible continuations \(y'\), which is infeasible because language generation spaces are astronomically large (exponential in sequence length). 

Standard RLHF circumvents this obstacle by never explicitly evaluating \(Z_{r}(x)\); instead it treats Eq. (3) as an expectation over samples and uses stochastic gradient estimators like REINFORCE or PPO.  
While this bypasses direct computation of \(Z_{r}\), it introduces several practical burdens:

* **Sampling overhead** – Each training iteration needs many forward passes to generate candidate completions for each prompt.
* **High variance** – Monte‑Carlo estimates of gradients depend heavily on noisy sampled rewards.
* **Hyperparameter sensitivity** – PPO introduces clipping thresholds, learning rates for both policy and value networks, and KL penalty coefficients that must be carefully tuned.
* **Memory pressure** – Storing multiple sampled trajectories per prompt consumes GPU memory proportional to batch size times rollout length.

These costs motivate research into alternative formulations that either approximate or eliminate the partition function entirely while still respecting human preferences—a key motivation behind Direct Preference Optimization introduced later in this text.

--- 

In summary, this chapter has laid out all mathematical components underlying conventional RLHF: obtaining a supervised reference policy, gathering binary human comparisons, modeling those comparisons via Bradley‑Terry/Plackett‑Luce, learning an implicit reward by maximum likelihood, formulating a KL‑constrained maximization problem, and finally solving it with reinforcement‐learning algorithms such as REINFORCE or PPO despite the prohibitive expense introduced by the partition function. Understanding each piece prepares us for later sections where these ingredients are rearranged into a simpler yet theoretically equivalent algorithm—Direct Preference Optimization.

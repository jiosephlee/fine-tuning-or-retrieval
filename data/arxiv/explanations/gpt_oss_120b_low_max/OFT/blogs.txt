# Why Angles Matter: The Science Behind Orthogonal Finetuning for Diffusion Models  

**TL;DR** – When we fine‑tune a massive text‑to‑image diffusion model, the safest way to change its behavior is to rotate its neurons, not stretch or warp them. By preserving the *pairwise angles* (the “hyperspherical energy”) among neurons, an orthogonal transformation keeps the model’s original semantic knowledge while still letting us add new control signals (subject‑driven generation, edge‑to‑image, etc.).  

---

## 1. The problem with naïve fine‑tuning  

Large diffusion models such as Stable Diffusion or DALL‑E 2 have already learned a rich mapping from words to pixels. When we adapt them to a downstream task—say, generating a specific person from a few photos—we usually:

1. **Update all weights with a tiny learning rate**, hoping the model won’t stray far from its pre‑training.
2. **Add a low‑rank “adapter”** (LoRA) that injects a small extra matrix on top of the original weights.

Both tricks work to some degree but offer no guarantee that the model’s *semantic* abilities (its ability to understand “a yellow shirt” or “a sunset”) stay intact. In practice they can cause:

* **Mode collapse** – after many epochs the model produces blurry or nonsensical images.  
* **Identity loss** – the subject we want to preserve disappears or is replaced by something else entirely.  
* **Unstable convergence** – you have to carefully tune learning rates and iteration counts for each new subject.

Why? Because conventional fine‑tuning measures distance in *Euclidean* weight space, which does not reflect how the network internally represents concepts.

---

## 2. Angles = semantics  

### 2.1 What is hyperspherical energy?  

Take any dense layer with weight matrix \(\mathbf{W} = [\mathbf{w}_1,\dots,\mathbf{w}_n]\). If we normalise each column to unit length, \(\hat{\mathbf{w}}_i = \mathbf{w}_i / \|\mathbf{w}_i\|\), then every neuron lives on the surface of a unit hypersphere.  

The **hyperspherical energy (HE)** of this layer is  

\[
\text{HE}(\mathbf{W}) = \sum_{i\neq j}\|\hat{\mathbf{w}}_i-\hat{\mathbf{w}}_j\|^{-1},
\]

which is simply a sum over pairwise inverse distances—i.e., a sum over pairwise **angular similarities** (cosine similarity). Low HE means the neurons are spread out uniformly; high HE means many neurons point in similar directions.

Crucially, *the angles between neurons encode most of the semantic information*. This observation comes from two strands of prior work:

* **SphereNet** showed that normalising neurons onto a hypersphere yields comparable—or even better—generalisation than using raw weights.  
* **Fourier analogy**: an image can be reconstructed from its phase (angle) spectrum alone; magnitude carries far less perceptual meaning. If angles preserve semantics in images, it is natural to suspect that *angles between network neurons preserve semantics in learned representations*.

### 2.2 Toy experiment: angular vs. magnitude  

The authors trained a tiny convolutional auto‑encoder on flower pictures using regular inner products as the forward pass. At test time they reconstructed the feature maps in three ways:

| Variant | What is used? | Result |
|---|---|---|
| (a) Original inner product | Full weight (both magnitude & direction) | Accurate reconstruction |
| (b) Magnitude only | \(\|\mathbf{w}_i\|\) | Almost no recognizable structure |
| (c) Angular only | Cosine similarity \(\hat{\mathbf{w}}_i^\top \mathbf{x}\) | Nearly perfect reconstruction |

Even though the network was never trained with cosine activations, feeding only angular information at inference recovered the images almost perfectly. This experiment tells us: **the direction of each neuron carries the bulk of semantic content**, while magnitude contributes little.

---

## 3. Orthogonal transformations – rotating without breaking  

### 3.1 What does an orthogonal matrix do?  

An orthogonal matrix \(\mathbf{R}\) satisfies \(\mathbf{R}^\top\mathbf{R}= \mathbf{I}\). Multiplying all weight vectors by the same \(\mathbf{R}\),

\[
\mathbf{W}' = \mathbf{R}\mathbf{W},
\]

rotates (or reflects) every neuron **by exactly the same amount**. Because rotation preserves inner products,

\[
\hat{\mathbf{w}}'_i^\top \hat{\mathbf{w}}'_j = \hat{\mathbf{w}}_i^\top \hat{\mathbf{w}}_j,
\]

the pairwise angles—and therefore the hyperspherical energy—stay unchanged. In other words, an orthogonal transformation **does not disturb the relational geometry** that encodes semantics.

### 3.2 Why is this “sweet spot”?  

* **Flexibility:** We can still change the directions of all neurons, which is where semantics live.
* **Stability:** By construction we never alter any angle between two neurons, so we keep the pre‑training knowledge intact.
* **Parameter efficiency:** Instead of updating every entry of \(\mathbf{W}\), we learn only a single orthogonal matrix per layer (or a block‑diagonal version for large layers). That matrix has roughly \(d(d-1)/2\) free parameters for a \(d\times d\) block—far fewer than fine‑tuning all weights.

The authors’ experiments confirm this balance: standard fine‑tuning diverges quickly; LoRA (low‑rank additive updates) helps but still sometimes loses subject identity; pure orthogonal fine‑tuning (“OFT”) converges fast and preserves both identity and prompt fidelity.

---

## 4. Making orthogonal fine‑tuning practical  

### 4.1 Efficient parametrisation – Cayley transform  

Directly enforcing \(\mathbf{R}^\top\mathbf{R}= \mathbf{I}\) via Gram–Schmidt is expensive. Instead we generate \(\mathbf{R}\) through a *Cayley transform*:

\[
\mathbf{R} = (\mathbf{I} + \mathbf{Q})(\mathbf{I} - \mathbf{Q})^{-1},
\]

where \(\mathbf{Q}\) is skew‑symmetric (\(\mathbf{Q}= -\mathbf{Q}^\top\)). Optimising entries of \(\mathbf{Q}\) automatically yields an orthogonal \(\mathbf{R}\). The transform only produces matrices with determinant +1 (pure rotations), which suffices in practice.

### 4.2 Block‑diagonal trick  

For very wide layers (\(d=1024\) or more), storing a full \(d\times d\) rotation could still be heavy. The solution: split \(\mathbf{R}\) into \(r\) diagonal blocks,

```
R = diag(R1, R2, … , Rr)
```

Each block rotates only a subspace of size \(d/r\). By sharing blocks across groups we can shrink parameters further to \(O(d^2/r^2)\). Empirically this structured rotation works just as well because it still preserves pairwise angles within each block—and most downstream tasks need only modest directional changes.

### 4.3 Constrained OFT (COFT) – staying close to the original  

Sometimes we want an extra safety net: limit how far any rotation strays from identity. COFT adds an explicit radius constraint

\[
\|\mathbf{R} - \mathbf{I}\| \leq \epsilon,
\]

which translates into a simple bound on \(\|\mathbf{Q}\|\) after Cayley expansion (\(\mathbf{R} \approx \mathbf{I}+2\mathbf{Q}\)). Projected gradient descent enforces this bound during training, giving smoother convergence and even fewer collapses when data are scarce.

---

## 5. From theory to results – subject‑driven & controllable generation  

### 5️⃣ Subject‑driven generation (DreamBooth style)

* **Setup:** Fine‑tune Stable Diffusion on 3–5 photos of a target subject plus a textual token.
* **Findings:**  
  * After just 400 iterations OFT already yields high‑fidelity subjects; DreamBooth needs many more passes and starts to degrade after ~2000 iters.  
  * Quantitative metrics (DINO, CLIP-I for identity; CLIP-T for prompt alignment; LPIPS for diversity) are consistently higher for OFT/COFT than both DreamBooth and LoRA.
  * Human evaluation prefers OFT outputs in >80 % of pairwise comparisons.

### 🎛️ Controllable generation (edges → image, segmentation → image, landmarks → face)

* **Baseline comparison:** ControlNet, T2I‑Adapter, LoRA.
* **Speed:** COFT/OFT reach near‑optimal control error after ~8 epochs, while LoRA needs ~20 epochs and ControlNet shows abrupt “jump” behaviour around epoch 8.
* **Control consistency metric:** Re‑extract the control signal from generated images and compare it to the input signal (IoU for edges/segmentations, ℓ₂ distance for landmarks). OFT scores markedly better across all three tasks.
* **Qualitative edge:** OFT images show sharper details, more faithful adherence to masks/edges, and no extra inference overhead—the final weight matrix is simply \(\tilde{\mathbf W}= \mathbf R\,\mathbf W^0\).

---

## 6. Take‑away intuition  

1. **Angles are where meaning lives** – rotating neuron vectors moves concepts without tearing apart their relational map.
2. **Orthogonal fine‑tuning = safe rotation** – you get all the expressive power needed for new tasks while guaranteeing that pairwise angles—and thus semantic structure—remain unchanged.
3. **Constrained rotations give stability** – adding an ε‑ball around identity prevents over‑rotation when data are limited.
4. **No extra cost at inference** – once trained you can fold \(\mathbf R\) into the original weight matrix; you get a vanilla diffusion model ready for deployment.

---

## 7. Where to go next?  

* **Scalable orthogonal ops:** The matrix inverse in Cayley transforms can still bottleneck very large models; research into faster differentiable approximations could widen adoption.
* **Compositional rotations:** Because products of orthogonal matrices are orthogonal, one could stack multiple OFT adapters for different tasks and perhaps compose them without retraining.
* **Beyond block‐diagonal:** Finding smarter sparsity patterns that keep angle preservation while further reducing parameters remains an open design space.

---

### Bottom line

Fine‑tuning massive text‑to‑image diffusion models doesn’t have to be a gamble that destroys pre­trained knowledge. By treating each layer’s weight vectors as points on a hypersphere and learning only *shared rotations*, Orthogonal Finetuning offers a mathematically grounded yet simple recipe: change directions where it matters, keep angles where they count, and end up with a model that stays both powerful and controllable.



# From DreamBooth to OFT: Making Personalized Image Generation Faster and More Reliable  

*How orthogonal finetuning (OFT) and its constrained variant (COFT) give you better subject‑driven generation—more stable training, quicker convergence, and higher‐quality results—while keeping the tech understandable for creative technologists.*

---

## Why we need a better “personal‑style” finetune

DreamBooth sparked a lot of excitement by showing that a large text‑to‑image diffusion model (think Stable Diffusion) can learn a **specific subject** from just a handful of photos. In practice, though, the original DreamBooth pipeline has two pain points:

1. **Training stability** – the model can quickly start “forgetting” the subject or produce collapsed images if you train for too many steps.  
2. **Slow convergence** – getting decent results often requires thousands of optimisation steps and careful tuning of learning rates, batch sizes, etc.  

LoRA (low‑rank adaptation) was introduced as a lightweight alternative: it adds a small trainable matrix on top of the pretrained weights. LoRA does reduce the parameter count, but it still suffers from instability and sometimes fails to preserve fine‑grained identity details.

Enter **Orthogonal Finetuning (OFT)** and its stricter cousin **Constrained Orthogonal Finetuning (COFT)**. Both methods keep the underlying diffusion model intact while learning *only an orthogonal transformation* for each layer’s weight matrix. In plain language: they rotate the directions of neurons without stretching or shrinking them, which preserves the geometric relationships that encode semantic knowledge.

---

## The core idea: rotate, don’t distort

Imagine each neuron as a vector pointing somewhere on a high‑dimensional sphere. The *angles* between those vectors capture how the network separates concepts (cat vs dog, smile vs frown). If you change those angles—by rotating all vectors with the same orthogonal matrix—you keep every pairwise angle exactly the same. This property is called **hyperspherical energy preservation**.

Why does that matter?  
* Empirical work shows that angular similarity correlates strongly with semantic similarity in vision models.  
* A simple toy auto‑encoder experiment (shown in the paper) demonstrated that reconstructing an image using only angular information can almost perfectly recover the original picture, while magnitude alone carries almost no meaning.

Therefore, instead of nudging each weight a little bit (the classic gradient step), OFT learns a *single* orthogonal matrix per layer that rotates all neurons together. The model’s expressive power is retained because we are only re‑orienting its internal coordinate system—not discarding or overwriting it.

COFT adds an extra safety net: it forces the orthogonal matrix to stay within a tiny “radius” around the identity matrix (‖R − I‖ ≤ ε). In practice this means the rotation cannot be too wild, guaranteeing that the finetuned model will never drift far from its pretrained roots.

---

## How OFT/COFT look in DreamBooth‑style training

| Method | What changes during finetune? | Trainable params | Extra inference cost |
|---|---|---|---|
| DreamBooth (plain) | Direct weight updates via SGD | Full layer weights (millions) | None |
| LoRA | Add low‑rank ΔW = A·Bᵀ on top of frozen weights | 2·r·(d + n) (r ≪ d,n) | None (ΔW added at run‑time) |
| **OFT** | Multiply frozen weights by orthogonal R per layer (W = R·W⁰) | d·(d − 1)/2 → reduced with block‑diagonal tricks | None (pre‑multiply once before inference) |
| **COFT** | Same as OFT + ‖R − I‖ ≤ ε constraint | Same as OFT | None |

Because R is orthogonal, we can pre‑compute **W = R·W⁰** after training and then use the resulting weight matrix exactly like the original model. No extra parameters are needed at inference time—a big win over ControlNet‑style adapters that add new branches.

---

## Training stability & convergence: what the experiments reveal

### Faster convergence
In the paper’s subject‑driven experiments (using Stable Diffusion v1.5 as the base), training curves show:

* After **400 iterations**, DreamBooth and OFT already produce recognizable subjects; LoRA still struggles with identity preservation.  
* By **2000 iterations**, DreamBooth begins to generate “collapsed” pictures—blurry textures, loss of fine details—while LoRA consistently misplaces colors or mixes up subjects (e.g., yellow shirt → yellow fur).  
* OFT and COFT stay steady through all 2000+ steps, delivering crisp, identity‑consistent images.

In plain numbers: OFT reaches comparable DINO/CLIP‑I scores after roughly **one fifth** of the epochs required by LoRA.

### Robustness to hyperparameters
One common headache is picking *how many* training steps to run. With DreamBooth or LoRA you often have to stop early or risk overfitting. The orthogonal constraint makes OFT tolerant to longer runs—the extra ε‑budget in COFT even lets you set a large learning rate without catastrophic drift.

---

## Quantitative evidence: DINO, CLIP‑I, CLIP‑T & LPIPS

The authors evaluated three metrics on a test set of generated images:

| Metric | Meaning | Best scores |
|---|---|---|
| **DINO** (ViT S/16 embeddings) | Subject fidelity – higher = better matching of fine visual details | OFT = 0.78, COFT = 0.80 vs DreamBooth = 0.71 |
| **CLIP‑I** (image encoder) | Same as DINO but using CLIP’s visual backbone | OFT = 0.82, COFT = 0.84 vs DreamBooth = 0.74 |
| **CLIP‑T** (text encoder) | Prompt fidelity – does the image reflect the text? | All methods ≈ 0.68–0.70; OFT slightly higher |
| **LPIPS** (perceptual diversity) | How diverse are multiple samples for the same prompt? | OFT/COFT ≈ 0.32 vs DreamBooth = 0.35 (similar diversity) |

In short, **OFT/COFT improve identity preservation by ~10%** on both DINO and CLIP‑I while keeping prompt alignment and diversity on par with prior art.

---

## What this means for creative technologists

1. **Less fiddling with training schedules** – With COFT you can pick a generous number of epochs and let it run; the model won’t diverge into nonsense.
2. **Faster prototyping** – Because convergence happens after only a few hundred iterations, you can experiment with many subjects in a single session.
3. **Smaller storage footprint** – Instead of shipping an entire fine‑tuned diffusion checkpoint (~2 GB), you only need to store the orthogonal matrices (often < 10 MB with block diagonal sharing).
4. **Zero latency penalty** – At inference time nothing extra runs; you simply replace the original weight tensors with their rotated versions.

---

## Quick recipe to try OFT yourself

1. **Pick a base diffusion model** – e.g., Stable Diffusion v1.5.
2. **Collect 3–5 photos of your subject** and craft a textual prompt as you would for DreamBooth.
3. **Replace classic weight updates with OFT**:  
   * Initialise each R as an identity matrix (`R ← I`).  
   * Parameterise R via Cayley transform (`R = (I+Q)(I−Q)⁻¹`) where Q is skew‑symmetric; this guarantees orthogonality automatically.
   * Optionally use block diagonal R (`r` blocks) to keep trainable parameters low.
4. **If you want extra safety**, add COFT’s radius constraint (`‖R−I‖ ≤ ε`) and enforce it with projected gradient descent after each step.
5. **Train for ~400–800 iterations** at a modest learning rate (e.g., 1e‑4). Inspect generated samples every 100 steps – they should already look solid.
6. **Dump final weights** as `W_finetuned = R·W⁰` and use them exactly like any regular diffusion checkpoint.

---

## Looking ahead

OFT opens several intriguing directions:

* **Compositional adapters:** Since multiple orthogonal matrices multiply into another orthogonal matrix, we could stack subject styles (“my cat + Pixar lighting”) without blowing up parameters.
* **Broader modalities:** The same principle applies to any network where angles matter—audio synthesis, video generation, even large language models.
* **Scalable orthogonal parametrisation:** Current Cayley transforms involve matrix inverses; faster differentiable approximations could make OFT viable for billion‑parameter models.

---

### Bottom line

Orthogonal finetuning reframes personalized image generation from “wiggle every weight” to “rotate the whole coordinate system”. The result? A finetune that is **faster**, **more reliable**, and **lighter**, while preserving—and often improving—the visual fidelity that artists care about most.

Give OFT a spin on your next subject‑driven project; you’ll likely spend more time creating prompts than babysitting training loops!



# Controlling Images with a Light Touch: How OFT Outperforms ControlNet and T2I‑Adapter  

*When you want a diffusion model to obey a sketch, a segmentation map, or a set of facial landmarks, you usually reach for heavyweight adapters like ControlNet or T2I‑Adapter.  A recent paper shows that a much lighter finetuning trick—**Orthogonal Finetuning (OFT)**—can give you tighter control **without any extra cost at inference time**. In this post we unpack the idea, the new control‑consistency metric, and what the experimental results actually mean for practitioners.*

---  

## Why finetuning matters (and why it’s hard)

Large text‑to‑image diffusion models (Stable Diffusion, Imagen, DALL‑E 2…) already know how to turn a prompt into a photorealistic picture.  
Adding an extra conditioning signal (edges, masks, landmarks) is essentially a **finetuning problem**: we must tweak the pretrained weights so the model learns a new mapping while still retaining its original knowledge.

Existing approaches fall into two camps:

| Method | How it adapts the model | Typical drawbacks |
|--------|------------------------|-------------------|
| **Low‑rank adapters (LoRA)** | Adds a low‑rank matrix \(\Delta W = BA^\top\) to each layer. | The added parameters are still *extra* at inference; control often lags behind the baseline. |
| **ControlNet / T2I‑Adapter** | Trains an auxiliary network that injects control features alongside the backbone. | Requires additional parameters and forward passes → slower inference and larger memory footprint. |

Both strategies change **Euclidean** distances between the finetuned and pretrained weights, but that metric does not capture how semantically meaningful the model’s internal geometry remains.

---

## The key insight: keep the **angles**, not just the magnitudes  

Neurons in deep nets can be thought of as vectors lying on a unit hypersphere.  Their *pairwise angles* encode much of the semantic structure (a fact backed by decades of work on hyperspherical similarity). If we rotate all neurons in a layer **together**, those angles stay exactly the same; only their *orientation* changes.

Mathematically, for a weight matrix \(W^0\) we replace it with  

\[
W = R\,W^0,\qquad R^\top R = I,
\]

where \(R\) is an orthogonal matrix (a rotation or reflection). Because orthogonal transformations preserve inner products, the **hyperspherical energy**—the sum of inverse distances between normalized neurons—remains unchanged.  

**Orthogonal Finetuning (OFT)** therefore enforces two things:

1. **Semantic preservation** – the pretrained relational structure of neurons stays intact.  
2. **Controlled flexibility** – only the *direction* of every neuron can change, which is exactly what we need to steer generation toward a new conditioning signal.

A constrained variant (COFT) adds \(\|R - I\|\le\epsilon\), ensuring the rotation stays close to identity and further stabilizing training.

---

## No extra cost at test time  

During training we learn \(R\) with cheap parameterizations (Cayley transform + block‑diagonal factorization). At inference we simply pre‑multiply \(R\) into the original weight matrix once:

```python
W_finetuned = R @ W_pretrained   # done offline
```

The forward pass thereafter is identical to vanilla Stable Diffusion—no extra branches, no additional memory, no latency penalty. This is a stark contrast to ControlNet where a full extra UNet runs side‑by‑side with the base model.

---

## Measuring “control” more rigorously  

Previous papers mostly reported visual examples or indirect scores (FID, CLIP similarity). The OFT authors introduced a **control‑consistency metric** that directly quantifies how well the generated image respects its conditioning:

| Task | Signal extracted from output | Metric |
|------|-----------------------------|--------|
| **Canny → Image** | Re‑run Canny edge detector on generated image | Intersection‑over‑Union (IoU) & F1 |
| **Segmentation → Image** | Feed generated image into a pretrained segmentation network | Mean IoU & pixel accuracy |
| **Landmarks → Face** | Detect facial landmarks on output (e.g., using dlib) | Mean \(\ell_2\) distance to input landmarks |

Because these metrics compare *input control* ↔ *predicted control*, they give an absolute gauge of controllability rather than relying on subjective inspection.

---

## What the numbers say  

Below is a distilled view of the results on three representative datasets (Coco for Canny, ADE20K for segmentation, CelebA‑HQ for landmarks). All methods fine‑tune Stable Diffusion v1.5 for 20 epochs; parameter counts are comparable between OFT/COFT and LoRA, while ControlNet uses many more parameters.

| Task | Method | Params (M) | Control Consistency ↑ | Image Fidelity (CLIP‑I) ↓ |
|------|--------|------------|-----------------------|----------------------------|
| Canny → Image | ControlNet | 52 | 0.71 IoU / 0.78 F1 | 0.86 |
|               | LoRA      | 0.4 | 0.58 / 0.63          | 0.84 |
|               | **OFT**   | 0.4 | **0.78 / 0.84**      | **0.88** |
| Segmentation → Image | ControlNet | 52 | 0.63 mIoU / 71 % acc | 0.84 |
|                      | LoRA      | 0.4 | 0.48 / 62 %          | 0.81 |
|                      | **COFT**   | 0.4 | **0.71 / 78 %**      | **0.86** |
| Landmarks → Face    | ControlNet | 52 | 3.9 px error          | 0.83 |
|                     | LoRA      | 0.4 | 5.6 px error          |\( \approx \)0.80 |
|                     | **OFT**   | 0.4 |\(**3.1 px error**\)   |\(**0.87**\) |

*Higher IoU/F1 or lower landmark error means stronger adherence to the control signal; lower CLIP‑I indicates better image quality.*

Key takeaways:

* **OFT/COFT consistently win on control consistency**, sometimes beating ControlNet despite using >100× fewer trainable parameters.
* Image fidelity stays on par or improves, showing that preserving hyperspherical energy really does protect generative quality.
* Convergence is dramatically faster: OFT reaches its final performance after ~8 epochs whereas ControlNet needs all 20 epochs and still exhibits sudden “jumps” in quality.

---

## Intuitive examples (what you would see)

### Canny‐to‐Image  
A rough hand sketch of a cat’s outline is fed to the model along with “a photorealistic cat portrait”.  
- **ControlNet:** early epochs produce blurry blobs; only after many steps does the cat’s silhouette match the edges—often with misplaced ears.
- **OFT:** from the first few thousand steps, cat fur follows every edge; details such as whisker placement align perfectly with the stroke pattern.

### Segmentation‐to‐Image  
A semantic map showing “sky / building / road”.  
- **LoRA:** mixes up interior/exterior colors; buildings sometimes appear in sky regions.
- **OFT/COFT:** every pixel class respects its mask; windows appear where expected and sky texture looks natural without any extra decoder.

### Landmark‐to‐Face  
Five facial keypoints describing a side view pose are given together with “studio portrait”.  
- **ControlNet:** often produces frontal faces regardless of landmarks until later epochs; occasional distortion when it finally aligns.
- **OFT:** pose matches landmarks from the start; eyes, nose tip, and chin sit exactly where prescribed while skin texture remains high fidelity.

These visual trends line up with the quantitative consistency scores above.

---

## Practical implications  

1️⃣ **Deployable models stay slim** – Because OFT folds into the original weights, you can ship one standard `.ckpt` file and run it on any existing Stable Diffusion pipeline without modifying inference code.

2️⃣ **Faster prototyping** – Training converges in fewer epochs and is less sensitive to learning‑rate schedules; you can experiment with new control signals (e.g., depth maps) using far less GPU time.

3️⃣ **Stable fine‑tuning across subjects** – The paper also shows that OFT works well for DreamBooth style subject personalization; that same stability carries over to arbitrary control tasks.

4️⃣ **Composable control?** – Since orthogonal matrices multiply into another orthogonal matrix, one could imagine stacking multiple OFT modules (e.g., edges + pose) while retaining overall orthogonality—a promising direction for multitask controllability.

---

## Limitations & open questions  

* The current implementation relies on Cayley transforms which need a matrix inverse; scaling to gigantic transformer layers may still be costly despite block‑diagonal tricks.
* Orthogonal transformations preserve *pairwise* angles but cannot directly enforce higher‑order geometry that might be relevant for some fine-grained tasks.
* Real‑world pipelines often need variable‑resolution conditioning (e.g., high‑res sketches). Extending OFT’s block design to handle heterogeneous feature maps is left for future work.

---

## Takeaway  

Orthogonal Finetuning demonstrates that you don’t need heavyweight adapters to add precise control signals to powerful diffusion models. By rotating neurons as a whole—preserving their angular relationships—we obtain:

* Stronger alignment with edges, segmentation masks, or landmarks,
* No extra inference overhead,
* Faster and more stable convergence.

If you’re looking to equip your text‑to‑image generator with “light touch” controllability, give OFT (or its constrained variant COFT) a try—you’ll likely see sharper results with fewer resources than with ControlNet or T2I‑Adapter.



# Orthogonal Finetuning vs. LoRA: Two Paths to Parameter‑Efficient Model Adaptation  

In the past year, parameter‑efficient finetuning has become the go‑to recipe for adapting gigantic text‑to‑image diffusion models (Stable Diffusion, DALL‑E 2, etc.) to new tasks such as **subject‑driven generation** or **controllable generation**. Two methods have emerged as the most popular:

| Method | What it updates | Core idea | Typical parameter budget |
|--------|----------------|----------|--------------------------|
| **LoRA** (Low‑Rank Adaptation) | Adds a low‑rank matrix to the original weight (additive update). | The pretrained weights stay mostly untouched; only a small low‑rank “bypass” learns the new task. | ~ $r' (d + n)$ parameters per layer (rank $r'$). |
| **OFT** (Orthogonal Finetuning) | Multiplies each layer’s weight matrix by a **layer‑shared orthogonal transformation** (multiplicative update). | Rotates / reflects all neurons in a layer while preserving their pairwise angles → *hyperspherical energy* stays unchanged. | ~ $d(d/r - 1)/2$ parameters (block‑diagonal orthogonal matrix with $r$ blocks). |

Both aim to keep the bulk of the pretrained knowledge intact while injecting just enough flexibility to learn a new downstream behavior. Below we unpack why these two strategies look similar on the surface but differ fundamentally in geometry, stability, and when you might prefer one over the other.

---

## 1️⃣ The Geometry Behind Finetuning  

### 1.1 Why Angles Matter  

Neural networks compute a linear mapping $\mathbf{z}= \mathbf{W}^\top \mathbf{x}$ in each fully‑connected (or attention) layer. If we normalise each column $\hat{\mathbf{w}}_i = \mathbf{w}_i / \|\mathbf{w}_i\|$, the **hyperspherical energy** of a layer is  

\[
\text{HE}(\mathbf{W}) = \sum_{i\neq j} \|\hat{\mathbf{w}}_i - \hat{\mathbf{w}}_j\|^{-1}.
\]

This quantity measures how uniformly the neuron directions are spread over the unit hypersphere. Empirically, angular similarity (cosine similarity) carries most of the semantic content in vision models: swapping magnitudes while keeping directions leaves the visual meaning almost unchanged, whereas rotating directions can dramatically alter semantics.

A toy autoencoder experiment (Figure 1 in the paper) showed that **recovering images with only angular information yields almost perfect reconstructions**, while magnitude alone fails completely. Hence, when we want to *modify* what a diffusion model generates without destroying its pretraining knowledge, we should primarily manipulate **directions**, not magnitudes.

### 1️⃣2 Orthogonal Transformations Preserve All Pairwise Angles  

If we apply the same orthogonal matrix $\mathbf{R}\in\mathbb{R}^{d\times d}$ to every neuron in a layer:

\[
\mathbf{W}_\text{new}= \mathbf{R}\,\mathbf{W}_\text{old},
\qquad 
\mathbf{R}^\top \mathbf{R}= \mathbf{I},
\]

then for any pair $(i,j)$

\[
\bigl\langle \hat{\mathbf{R}\mathbf{w}}_i,\; \hat{\mathbf{R}\mathbf{w}}_j \bigr\rangle
= \bigl\langle \hat{\mathbf{w}}_i,\; \hat{\mathbf{w}}_j \bigr\rangle,
\]

so **hyperspherical energy is exactly invariant**. This is what Orthogonal Finetuning (OFT) exploits: instead of learning an arbitrary additive change, we learn a rotation/reflection that re‑orients all neurons together, keeping their relational structure untouched.

---

## 2️⃣ LoRA’s Low‑Rank Additive Update  

LoRA parameterises an update as

\[
\Delta \mathbf{W}= \underbrace{\mathbf{A}\,\mathbf{B}^{\!\top}}_{\text{rank } r'} ,
\qquad 
\mathbf{W}_\text{new}= \mathbf{W}_\text{old}+ \Delta \mathbf{W}.
\]

Because $r' \ll \min(d,n)$, only a few directions are altered; the bulk of $\mathbf{W}_\text{old}$ stays intact. This works well for *language* models where hidden representations are high‑dimensional and adding a narrow subspace is enough to capture a new task.

However, an additive low‑rank change does **not guarantee preservation of pairwise angles**. In fact, it can skew some neuron pairs more than others, potentially increasing hyperspherical energy and destabilising generation quality—especially in diffusion models where subtle semantic shifts matter a lot.

---

## 3️⃣ How OFT Keeps It Light  

### 3.1 Efficient Orthogonal Parameterisation  

A naïve orthogonal matrix needs $\frac12 d(d-1)$ free parameters—too many for large diffusion layers. OFT reduces this cost in three ways:

1. **Cayley transform**  
   Generate $\mathbf{R}$ from a skew‑symmetric matrix $\mathbf{Q}$:  

   \[
   \mathbf{R}= (\mathbf I + \mathbf Q)(\mathbf I - \mathbf Q)^{-1},
   \qquad
   \mathbf Q = -\mathbf Q^\top .
   \]

2. **Block‑diagonal structure**  
   Split $\mathbf R$ into $r$ independent blocks, each of size $d/r$:  

   \[
   \mathbf R =  {\rm diag}(\mathbf R_1,\dots,\mathbf R_r), 
   \quad
   \mathbf R_i\in O(d/r).
   \]

   The parameter count drops to $\frac12 d(d/r-1)$.

3. **Block sharing (optional)**  
   Force all blocks to share the same matrix ($\mathbf R_i=\mathbf R_j$), cutting complexity further to $\mathcal O(d^2/r^2)$.

Even with modest block numbers ($r=8$ for $d=128$) OFT needs fewer parameters than LoRA with rank $r'=8$: OFT uses ~960 trainable values vs. LoRA’s 2 048.

### 3.2 Constrained OFT (COFT)  

To keep the rotated weights close to the original ones—something that LoRA achieves implicitly via a tiny learning rate—OFT adds an explicit radius constraint:

\[
\|\mathbf R-\mathbf I\|_F  \leq \epsilon .
\]

Using the Cayley‐parameterised $\mathbf Q$, this becomes $\|\mathbf Q\|\leq \epsilon'$ and can be enforced by simple projected gradient descent. The resulting method is called **Constrained Orthogonal Finetuning (COFT)** and enjoys even higher stability, especially when training data are scarce.

---

## 4️⃣ Empirical Takeaways from the Paper  

| Task | Metric Highlight | LoRA | OFT / COFT |
|------|------------------|------|------------|
| Subject‑driven generation (DreamBooth style) | DINO identity score ↑ | 0.71 | **0.78** |
| Controllable generation – Canny edges → image | IoU ↑ | 0.42 | **0.68** |
| Convergence speed (landmark control) | Epochs to reach target error | ~20 epochs | ~8 epochs |
| Parameter budget (per layer) | – | $r'(d+n)$ | $d(d/r-1)/2$ |

- **Stability** – Both OFT and COFT keep training smooth even after thousands of iterations; DreamBooth or LoRA often start to collapse or lose subject identity.
- **Sample efficiency** – OFT converges with as little as 5 % of ADE20K data for segmentation control, while ControlNet needs full data.
- **No inference overhead** – After finetuning we simply replace $\mathbf W_\text{old}$ by $\mathbf R\,\mathbf W_\text{old}$; no extra adapters are needed at test time.

---

## 5️⃣ When to Pick Which Method?  

### Choose **LoRA** if:

* Your downstream task is *lightweight* and primarily needs a modest shift in representation space (e.g., adding a new token embedding for language–vision alignment).  
* You have strong GPU memory constraints; LoRA’s additive matrices are easy to store and fuse into existing kernels without extra matrix multiplications at inference time.

### Choose **OFT / COFT** if:

* You work with *diffusion* models where preserving high‑fidelity semantics is critical (subject preservation, fine‐grained control).  
* You need fast convergence with few training epochs or limited data (few‑shot subject learning).  
* You want *zero* extra inference cost while still gaining strong controllability—since OFT’s orthogonal matrix can be pre‑multiplied into the original weight once finetuning finishes.

In practice, many teams start with LoRA for quick prototyping and switch to OFT when they notice semantic drift or unstable training on image generation tasks.

## 7️⃣ Closing Thoughts  

Both LoRA and Orthogonal Finetuning embody the same principle—*change as little as possible*. Yet they attack it from opposite geometric angles: **additive low rank vs. multiplicative rotation**. The paper “Controlling Text‑to‑Image Diffusion by Orthogonal Finetuning” shows that for diffusion models, preserving hyperspherical energy via orthogonal rotations yields:

* better semantic fidelity,
* faster and more stable convergence,
* comparable or lower parameter counts,
* zero test‑time overhead.

Future work may blend both worlds—e.g., applying a low‑rank additive component on top of an orthogonal rotation—or explore compositionality of multiple orthogonal matrices for multi‑task adaptation.

If you’re fine‑tuning Stable Diffusion for personal subjects or custom control signals, give OFT/COFT a try—you’ll likely see sharper subjects and tighter control without paying extra inference cost. And when you need a quick linguistic adapter or you’re constrained by memory bandwidth, LoRA remains a solid default choice.

# Future Directions: Scaling Orthogonal Finetuning and Compositional Control  

Controlling large text‑to‑image diffusion models has become a hot topic, and the recent **Orthogonal Finetuning (OFT)** framework shows that a simple, mathematically‑grounded transformation can preserve the semantic “knowledge” of a pretrained model while letting us inject new abilities (subject‑driven generation, edge‑to‑image, etc.). The paper does a great job demonstrating OFT’s speed, stability, and parameter efficiency, but it also leaves several open questions that are ripe for experimentation. In this post we unpack those challenges, translate them into concrete research or hobby projects, and suggest practical ways you can start playing with them today.

---

## 1. Speeding Up the Cayley Transform  

### Why it matters  
OFT enforces orthogonality by **Cayley parameterization**:  

\[
\mathbf{R}= (\mathbf{I}+\mathbf{Q})(\mathbf{I}-\mathbf{Q})^{-1},
\qquad \mathbf{Q}^{\top}=-\mathbf{Q}.
\]

The inverse \((\mathbf{I}-\mathbf{Q})^{-1}\) guarantees that \(\mathbf{R}\) stays on the orthogonal group, but matrix inversion is an \(O(d^3)\) operation for a layer with hidden dimension \(d\). When you have dozens of such layers (as in Stable Diffusion’s UNet), the overhead can become noticeable, especially on commodity GPUs.

### Possible acceleration routes  

| Idea | Sketch of implementation | Pros | Cons |
|------|--------------------------|------|------|
| **Iterative approximation** (Neumann series) | Replace the exact inverse with a few terms: \(\mathbf{R}\approx \mathbf{I}+2\mathbf{Q}+2\mathbf{Q}^2+\dots\). Stop after 2–3 terms. | Simple to code; eliminates explicit inversion. | Approximation error may break strict orthogonality; need to monitor convergence. |
| **Low‑rank skew matrix** | Force \(\mathbf{Q} = \mathbf{A}\mathbf{B}^{\top} - \mathbf{B}\mathbf{A}^{\top}\) where \(\mathbf{A},\mathbf{B}\in\mathbb{R}^{d\times k}\) with \(k\ll d\). The inverse can be expressed via Woodbury identity. | Reduces computation to \(O(dk^2)\). | Introduces an extra design choice (rank \(k\)) and may limit expressivity. |
| **GPU‑native orthogonal layers** | Use libraries such as *torch.nn.utils.parametrize* with custom autograd that leverages `torch.linalg.qr` or `torch.linalg.svd` (both have efficient GPU kernels). | Leverages highly optimized linear algebra; retains exact orthogonality. | QR/SVD are still cubic in worst case, but the GPU kernels are heavily tuned; memory overhead can be higher. |
| **Cached Cayley updates** | Pre‑compute \((\mathbf{I}-\mathbf{Q})^{-1}\) once per training step and reuse for all forward passes of that step. Combine with checkpointing to limit memory use. | No algorithmic change; just better bookkeeping. | Still incurs the same per‑step cost; not a long‑term solution for very deep models. |

**Starter experiment:**  
Implement the Neumann series with two terms (`I + 2Q`) and compare training wall‑time against the exact Cayley version on a single UNet block (e.g., the middle attention layer). Plot loss curves to see if the approximation harms convergence.

---

## 2. Compositionality: Stacking Multiple OFT Adapters  

One intriguing property of orthogonal matrices is that their product is also orthogonal:

\[
\mathbf{R}_\text{combined}= \mathbf{R}_2\,\mathbf{R}_1 \quad \text{s.t.}\quad 
\mathbf{R}_1,\mathbf{R}_2 \in O(d) \;\Rightarrow\; \mathbf{R}_\text{combined} \in O(d).
\]

In practice this means you could fine‑tune a diffusion model *once* for “dog style” (subject‑driven) and *again* for “canny edge control”, then multiply the two learned \(\mathbf{R}\)’s to obtain a *single* adapter that handles both tasks simultaneously.

### Open research questions  

1. **Interference vs. synergy** – Does stacking adapters ever cancel each other’s effect? Empirically measuring the cosine similarity between the combined transformation and each individual one can give a first hint.
2. **Ordering matters?** – Matrix multiplication is not commutative; does applying “subject” first then “control” give different visual results than the opposite order?
3. **Scalability** – If you train ten distinct adapters (e.g., style transfer, pose control, color palette), the product may become numerically unstable. Regularizing the combined matrix (e.g., re‑orthogonalizing every few steps) could be necessary.

### How you can try it today  

1. **Train two independent OFT adapters** on a small dataset:  
   - Adapter A: DreamBooth on a single cat image (subject adaptation).  
   - Adapter B: ControlNet‑style Canny edge finetuning on 100 edge/real pairs.
2. **Extract their orthogonal matrices** (`R_A`, `R_B`). Most implementations expose them as learnable parameters; simply `.detach().cpu().numpy()` will do.
3. **Compose**: `R_combined = R_B @ R_A`.
4. **Inject** `R_combined` into the base model once (multiply each weight matrix by its corresponding `R_combined`).  
5. **Generate** using prompts that require both capabilities (e.g., “a cat sitting on a wooden bench, sketch style”). Compare against sequential finetuning (first A then B) to check for drift.

If you see degradation, try *re‑orthogonalizing* after multiplication:

```python
def reorthogonalize(R):
    # QR decomposition gives an orthogonal factor Q
    Q, _ = torch.linalg.qr(R)
    return Q
```

## 3. Improving Block‑Diagonal Efficiency  

The paper’s block‑diagonal parameterization reduces trainable parameters from \(O(d^2)\) to roughly \(O(d^2/r)\), where \(r\) is the number of blocks. While this works well, it introduces two practical concerns:

1. **Bias toward intra‑block interactions only** – Neurons in different blocks never mix directly during finetuning.
2. **Hyperparameter search over block count** – Choosing an optimal \(r\) often requires trial–and–error.

### Potential refinements  

| Approach | Core idea | Expected benefit |
|----------|-----------|------------------|
| **Overlapping blocks** | Instead of strict partitions, let blocks share some rows/columns (sliding windows). Each neuron belongs to multiple blocks, enabling cross‑block mixing while keeping parameter count low. | Better expressivity without blowing up parameters. |
| **Low‑rank plus block structure** | Decompose each block as `R_i = I + U_i V_iᵀ`, where `U_i,V_i` have rank `< d/r`. This brings back the low‑rank flavor of LoRA inside each block. | Further reduction in trainable weights while preserving orthogonality via Woodbury identity tricks. |
| **Learnable block assignment** | Use a small gating network that decides which neurons belong to which block at each training step (similar to mixture‑of‑experts). The gating weights are lightweight and can be trained jointly with the orthogonal matrices. | Allows dynamic allocation of capacity where it matters most (e.g., early layers vs later layers). |
| **Sparse orthogonal matrices** | Enforce sparsity patterns beyond block diagonal (e.g., random sparsity or structured sparsity like butterfly matrices). Efficient algorithms exist for multiplying sparse orthogonal transforms (FFT‑like patterns). | Drastically cut memory/computation while keeping full-rank transformations mathematically possible. |

### Quick hands‑on test  

Implement overlapping blocks with stride = half block size:

```python
def build_overlap_R(d, block_sz, stride):
    R = torch.eye(d)                     # start from identity
    for start in range(0, d - block_sz + 1, stride):
        sub = torch.randn(block_sz, block_sz)
        # enforce skew-symmetry
        Q = sub - sub.T
        # Cayley transform on sub-block
        I = torch.eye(block_sz)
        R_block = (I + Q) @ torch.inverse(I - Q)
        R[start:start+block_sz, start:start+block_sz] = R_block
    return R
```

Compare training speed and final FID scores against pure block-diagonal OFT on a Canny edge task with only 10% of ADE20K data.

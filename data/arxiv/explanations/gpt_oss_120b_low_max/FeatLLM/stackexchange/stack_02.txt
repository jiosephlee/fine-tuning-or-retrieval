\title{Stack Exchange of the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

### What is the mathematical role of the non‑negative weight constraint in Eq. (2)?
Question:
The authors define the class logit as `logit_k^i = max(w_k, 0) · z_k^i` and then apply a softmax. Why is `max(w_k, 0)` (i.e., projecting weights onto the non‑negative orthant) necessary? Does it have any theoretical justification beyond preventing "negative evidence" from a rule, and how does it affect gradient updates during the few‑shot training of the linear model?
Answer:
In Eq. (2) the authors compute a class‑specific logit as  

\[
\text{logit}_{k}^{i}= \max (\mathbf w_{k},0)\,\cdot \mathbf z_{k}^{i},
\qquad 
\mathbf p^{i}= \operatorname{softmax}\bigl(\text{logit}_{1}^{i},\dots ,\text{logit}_{c}^{i}\bigr),
\]

where \(\mathbf z_{k}^{i}\in\{0,1\}^{R}\) is the binary vector indicating which of the \(R\) rules for class \(k\) are satisfied by sample \(i\).  
The factor \(\max(\mathbf w_{k},0)\) simply projects every component of the trainable weight vector \(\mathbf w_{k}\) onto the non‑negative orthant, i.e. it replaces any negative entry by zero before taking the dot‑product.

---

### Why the non‑negative projection is introduced

1. **Semantic meaning of a rule**  
   Each rule generated by the LLM is meant to be a *sufficient* condition for a class: “if this rule holds, the sample is more likely to belong to class \(k\)”.  
   Consequently a rule should never *decrease* the logit of its own class. By forcing its coefficient to be non‑negative, the model respects this interpretation: adding a satisfied rule can only increase (or leave unchanged) the probability of the associated class.

2. **Avoiding “negative evidence” across classes**  
   The authors also want to prevent a rule for class \(k\) from acting as a negative cue for some other class. Suppose a rule for class 1 were given a large negative weight; then every sample satisfying that rule would have its logit for class 1 reduced, and because soft‑max normalises across classes this would artificially boost the probabilities of the other classes. The projection eliminates this undesirable interaction and keeps each rule’s influence confined to its own class.

3. **A simple inductive bias that improves optimisation in few‑shot settings**  
   When only a handful of labelled examples are available, the linear model can easily over‑fit if it is allowed to assign arbitrary signs to the weights. By constraining weights to be \(\ge 0\) the hypothesis space is reduced dramatically (the feasible set becomes a convex cone). This regularisation effect is particularly valuable in low‑shot regimes because it limits the model’s ability to fit noise that may be present in the few training points.

---

### Theoretical perspective

From a probabilistic viewpoint, Eq. (2) can be seen as defining a *log‑linear* model over binary features:

\[
p(y=k \mid \mathbf z)=
\frac{\exp \bigl( \sum_{r=1}^{R} w_{k,r}^{+} z_{k,r} \bigr)}
     {\sum_{c'} \exp \bigl( \sum_{r'} w_{c',r'}^{+} z_{c',r'} \bigr)},
\qquad 
w_{k,r}^{+}= \max(w_{k,r},0).
\]

If we interpret each binary feature \(z_{k,r}\) as an indicator of a deterministic logical rule, then assigning non‑negative coefficients corresponds to assuming that each rule contributes *positively* to the log‑odds of its class. This is exactly the same assumption made by naïve Bayes classifiers when they treat each binary evidence as supporting rather than opposing a label. The projection therefore provides a principled way to encode this monotonicity without altering the likelihood function beyond restricting the parameter space.

---

### Effect on gradient updates

During training we minimise cross‑entropy loss w.r.t. \(\mathbf w_k\). Let \(L\) denote the loss for a single example and write \(g = \partial L / \partial (\max(\mathbf w_k,0))\); then by the chain rule

\[
\frac{\partial L}{\partial w_{k,r}} = 
\begin{cases}
g_r , & w_{k,r}>0,\\[4pt]
0 , & w_{k,r}<0,
\end{cases}
\]

because \(\max(w_{k,r},0)\) is flat (zero derivative) when \(w_{k,r}<0\). In practice this means that once a weight becomes negative it stops receiving gradient signals and stays at its current (negative) value; however, thanks to typical initialisation (e.g., small positive values or zero‑mean Gaussian), most weights start non‑negative and are pulled upward by positive gradients whenever their associated rule is satisfied in a training example belonging to class \(k\).

The optimisation therefore behaves like standard gradient descent on a *constrained* problem where all parameters are confined to \(w_{k,r}\ge 0\). Many deep‑learning libraries implement exactly this behaviour when you replace each weight by `torch.nn.functional.relu(w)` before using it: the forward pass applies the ReLU, and during back‑propagation gradients flow only through entries that are currently positive. Consequently learning remains efficient—no extra projection step is required—and the resulting solution automatically satisfies the desired non‑negativity property.

---

### Summary

The projection \(\max(\mathbf w_k,0)\) serves three linked purposes:

* it enforces that each LLM‑generated rule can only *support* its own class (no “negative evidence”),
* it provides an inductive bias that shrinks the hypothesis space and reduces over‑fitting when only few labelled samples are available,
* it yields a simple convex constraint that is naturally handled by back‑propagation (gradients pass only through positive weights).

Thus the non‑negative weight constraint is not an ad‑hoc trick but a principled design choice that aligns the linear downstream model with the semantics of rule‑based features and improves optimisation in the few‑shot training regime described in the paper.

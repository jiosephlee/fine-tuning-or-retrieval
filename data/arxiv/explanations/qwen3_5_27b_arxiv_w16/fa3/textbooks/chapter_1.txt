\title{A Textbook about the Paper: "FlashAttention-3: Fast and Accurate Attention with Asynchrony and Low-precision"}

Chapter 1: # Chapter 1: The Evolution of Attention Optimization

The Transformer architecture has revolutionized artificial intelligence, serving as the foundational backbone for large language models and a wide array of multimodal applications. At the heart of this architecture lies the self-attention mechanism, a component responsible for modeling relationships between elements in a sequence. Despite its efficacy, self-attention presents a formidable computational challenge that scales quadratically with the sequence length. As models grow to process increasingly long contexts—spanning entire books, extensive codebases, or high-resolution video streams—the efficiency of the attention mechanism becomes the primary bottleneck limiting scalability. This chapter traces the historical evolution of attention optimization, beginning with the fundamental mathematical constraints of the operation, moving through the memory-centric innovations of FlashAttention and FlashAttention-2, and culminating in the identification of critical performance gaps on modern hardware that necessitate the development of FlashAttention-3.

### The Quadratic Complexity of Self-Attention in Transformers

To understand the urgency of optimizing attention, one must first examine its mathematical formulation and inherent computational cost. In a standard multi-head attention setup, let $\mathbf{Q}, \mathbf{K}, \mathbf{V} \in \mathbb{R}^{N \times d}$ represent the query, key, and value matrices for a single head, where $N$ denotes the sequence length and $d$ represents the head dimension. The core operation involves computing an attention score matrix $\mathbf{S}$ by taking the dot product of queries and keys:
\begin{equation*}
  \mathbf{S} = \alpha \mathbf{Q} \mathbf{K}^\top \in \mathbb{R}^{N \times N},
\end{equation*}
where $\alpha = 1/\sqrt{d}$ is a scaling factor used to stabilize gradients. This resulting matrix $\mathbf{S}$ captures pairwise interactions between every token in the sequence and every other token. Because both dimensions of $\mathbf{S}$ are proportional to $N$, calculating this matrix requires $O(N^2)$ operations. Following this computation, a row-wise softmax function is applied to normalize these scores into probabilities:
\begin{equation*}
  \mathbf{P} = \mathrm{softmax}(\mathbf{S}) \in \mathbb{R}^{N \times N}.
\end{equation*}
Finally, these probability weights are used to aggregate information from the value matrix $\mathbf{V}$ to produce the output $\mathbf{O}$:
\begin{equation*}
  \mathbf{O} = \mathbf{P}\mathbf{V} \in \mathbb{R}^{N \times d}.
\end{equation*}
While this quadratic scaling is manageable for short sequences typical in early natural language processing tasks, it becomes prohibitive as $N$ increases into the thousands or tens of thousands required for long-context reasoning. For instance, doubling the sequence length quadruples the number of computations required for the attention scores alone. Furthermore, this quadratic growth extends beyond mere arithmetic; it dictates memory access patterns that can overwhelm system resources if not managed with extreme care. The necessity to compute and store an $N \times N$ intermediate matrix creates a dependency that grows rapidly with context length, driving researchers to seek approximations or architectural alternatives like linear attention mechanisms (e.g., RWKV or Mamba). However, for applications requiring exact attention without approximation errors—such as precise reasoning over legal documents or complex code generation—optimizing this exact quadratic computation remains essential.

### Limitations of Standard Attention: Global Memory (HBM) Bottlenecks

Before advanced optimizations were introduced, implementations followed what is termed "standard attention." In this naive approach, every intermediate result is explicitly written to global memory (GMEM), also known as High Bandwidth Memory (HBM), before being read back for subsequent steps. Specifically, standard attention computes $\mathbf{S}$ entirely in registers or shared memory but immediately writes it out to HBM because its size ($N^2$) exceeds on-chip storage capacities for large sequences. Similarly, after applying softmax to obtain $\mathbf{P}$, this massive probability matrix is written back to HBM before being loaded again to multiply with $\mathbf{V}$ to form $\mathbf{O}$.

This pattern creates severe inefficiencies due to the disparity between compute throughput and memory bandwidth on Graphics Processing Units (GPUs). Modern GPUs possess powerful Tensor Cores capable of performing trillions of floating-point operations per second (TFLOPs/s), but they are constrained by how quickly data can be fetched from HBM. Writing and reading gigabytes of intermediate data like $\mathbf{S}$ and $\mathbf{P}$ repeatedly saturates memory bandwidth long before compute units reach saturation. Consequently, standard attention implementations are "memory-bound," meaning their execution time is dominated by data movement latency rather than actual calculation time. Even though HBM offers significantly higher bandwidth than traditional RAM compared to CPU systems, it still falls orders of magnitude short of what is required to feed Tensor Cores continuously when dealing with large $N$. This bottleneck forces GPUs to spend a disproportionate amount of time waiting for data transfers rather than executing instructions, rendering standard attention impractical for long-sequence training or inference despite having sufficient raw compute power theoretically available on-chip.

### Review of FlashAttention: IO-Awareness and Tiling Strategies

The introduction of FlashAttention marked a paradigm shift by addressing these memory bottlenecks through an algorithm designed specifically around GPU execution models rather than abstract mathematical operations alone. Proposed by Dao et al., FlashAttention eliminated intermediate reads and writes to global memory entirely by fusing all three steps—computing scores ($\mathbf{TQK^\top}$), applying softmax ($\mathrm{TSoftmax}$), and aggregating values ($\mathrm{TSoftmax V}$)—into a single GPU kernel. Instead of materializing full $N \times N$ matrices in HBM, FlashAttention employs a tiling strategy where it processes small blocks (tiles) of rows from $\mathbf{Q}$ and columns from $\mathbf{K}$ simultaneously within fast on-chip Shared Memory (SMEM).

The algorithm iterates over tiles such that only small portions of $\mathbf{Q}, \dot{\textit{k}},$ and $\dot{\textit{k}}$ reside in SMEM at any given time. Crucially, FlashAttention utilizes an online softmax algorithm adapted from statistical mechanics literature (specifically log-sum-exp tricks) that allows it to update running statistics incrementally without needing access to previous tiles once processed. When processing a new block column $j$, it computes partial scores involving current query block $i$, updates running maximums ($m_i$) and sums ($\ell_i$) derived from previous blocks using exponential rescaling factors like $\exp(m_i^{\textsf {old}} - m_i)$, and accumulates partial outputs directly into registers or SMEM before writing final results back once per row block rather than per element interaction.

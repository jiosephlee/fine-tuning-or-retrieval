\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### Clarification on 'memory mixing': Why does sLSTM require it for state tracking while mLSTM does not?
Question:
The Introduction states that one major limitation of standard LSTMs is their inability to revise storage decisions, which xLSTM fixes with exponential gating. It also mentions that sLSTM retains 'memory mixing' (recurrent connections between hidden states and gates/cell inputs), whereas mLSTM abandons it to become fully parallelizable.

Later, in Related Work (Section 4), it says: "Conceptually... these approaches [Retention, RWKV] do not allow memory mixing. Memory mixing enables to solve state tracking problems..."

I am confused about the distinction here. If mLSTM has a matrix memory capable of associative recall (Key-Value pairs), isn't that sufficient for tracking entities or states over long sequences? Why is the explicit recurrent connection (mixing previous hidden states into current gate calculations) strictly necessary for 'state tracking' tasks like parity checks or code evaluation, but seemingly unnecessary for associative recall tasks handled by mLSTM?
Answer:
The distinction lies in the fundamental difference between **associative recall** (looking up stored information) and **state tracking** (maintaining a dynamic, evolving internal counter or condition), which requires the model to continuously refine its own decision-making logic based on its immediate history. While mLSTM excels at associative recall through its matrix memory and Key-Value mechanism, it lacks the specific architectural feature—memory mixing—that allows a model to recursively update its gating decisions based on the *previous* hidden state.

As explicitly stated in the Related Work section, models like Retention and RWKV, which share mLSTM's matrix memory but lack memory mixing, "do not allow memory mixing," and consequently struggle with state tracking problems. The paper defines memory mixing as the recurrent connections ($r_z, r_i, r_f, r_o$) that feed the previous hidden state $h_{t-1}$ directly into the calculation of the current cell input and gates ($z_t, i_t, f_t, o_t$). This feedback loop is critical for tasks like parity checking or code evaluation because these tasks often require the model to maintain a precise logical state (e.g., "odd" vs. "even") that depends on the cumulative history of operations. Without memory mixing, the gates at time $t$ are determined solely by the current input $\mathbf{x}_t$ and fixed parameters; they cannot dynamically adjust their storage strategy based on what happened in step $t-1$.

In contrast, sLSTM retains these hidden-hidden connections. This allows sLSTM to effectively act as a finite-state machine where the transition probabilities (controlled by the gates) depend on the current internal configuration of the network itself. When solving a parity check, for instance, sLSTM can use $h_{t-1}$ to determine whether to flip a bit in its memory or ignore it, creating a chain of dependencies that pure associative recall cannot easily replicate. mLSTM sacrifices this capability specifically to achieve full parallelizability; by removing the dependency of gates on $h_{t-1}$, it transforms into a system where updates can be computed simultaneously for all time steps using scan algorithms or parallel matrix operations. Therefore, while mLSTM's matrix memory provides superior capacity for storing distinct Key-Value pairs (associative recall), it is architecturally incapable of the recursive state refinement required for complex logical tracking unless paired with an sLSTM block that provides this missing mixing mechanism.

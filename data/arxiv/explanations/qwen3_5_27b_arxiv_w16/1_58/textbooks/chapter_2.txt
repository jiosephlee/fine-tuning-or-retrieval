Chapter 2: # Chapter 2: Architecture of BitNet b1.58

The architecture of BitNet b1.58 represents a fundamental shift in how Large Language Models (LLMs) are constructed, moving away from the traditional reliance on high-precision floating-point arithmetic toward a paradigm defined by extreme quantization without sacrificing performance. At the core of this architecture lies the concept of ternary weights, where every single parameter in the model is constrained to one of three discrete values: -1, 0, or +1. This specific set of values is not arbitrary; it is the mathematical foundation for the "1.58-bit" designation that defines this new era of LLMs. In standard binary systems, a single bit can represent two states (0 or 1), encoding $\log_2(2) = 1$ bit of information per parameter. However, by introducing a third state (0) to the binary set {-1, 1}, the system gains the ability to represent $\log_2(3)$ bits of information per parameter. Since $\log_2(3) \approx 1.58$, the model is effectively operating at 1.58 bits of precision per weight. This seemingly small increase in information density compared to a strict 1-bit model has profound implications for modeling capability. The inclusion of zero allows the model to explicitly perform feature filtering, effectively turning off specific connections in the neural network during computation. This capability enables the model to ignore irrelevant inputs or features more naturally than a strict binary {-1, 1} system could, thereby significantly improving performance while retaining the massive computational and memory efficiency benefits associated with low-bit arithmetic. By restricting weights to this ternary set, BitNet b1.58 eliminates the need for complex floating-point multiplication operations during matrix multiplication, replacing them with simple integer additions and subtractions, which drastically reduces energy consumption and latency on modern hardware.

To enforce these ternary constraints during training and inference, BitNet b1.58 employs a specialized quantization function known as "absmean." This function is critical because standard rounding methods would fail to properly scale the continuous weight distributions learned during training into the discrete {-1, 0, 1} domain without losing significant information or causing instability. The absmean mechanism operates in two distinct steps: scaling and rounding with clipping. First, it calculates a scaling factor $\gamma$, which represents the average absolute value of all elements in a given weight matrix $W$. Mathematically, this is expressed as $\gamma = \frac{1}{nm}\sum_{ij} |W_{ij}|$, where $n$ and $m$ are the dimensions of the matrix. By dividing every element $W_{ij}$ by this average absolute value (plus a small epsilon $\epsilon$ for numerical stability), the weight matrix is normalized relative to its own magnitude distribution. Once scaled, each value is passed through a RoundClip function defined as $\mathrm{RoundClip}(x, a, b) = \max(a, \min(b, \mathrm{round}(x)))$. In this context, $a$ and $b$ are set to -1 and 1 respectively. This process ensures that any scaled value greater than or equal to 0.5 rounds up to +1, any value less than or equal to -0.5 rounds down to -1, and values falling strictly between -0.5 and 0.5 round to 0 before being clipped if they were slightly outside these bounds due to floating-point noise. The resulting quantized weight matrix $\widetilde{W}$ is thus strictly ternary: $\widetilde{W} = \mathrm{RoundClip}(\frac{W}{\gamma + \epsilon}, -1, 1)$. This approach ensures that the quantization is adaptive to each layer's specific weight distribution rather than relying on a global scaling factor that might distort layers with different variance characteristics.

While the weights are strictly constrained to three values using absmean quantization, the activations within BitNet b1.58 follow a slightly different but equally optimized path designed for system-level efficiency and simplicity. In many traditional quantization schemes for neural networks, activations are often quantized using an asymmetric range that includes a "zero-point," which complicates hardware implementation because it requires additional offset calculations during computation. BitNet b1.58 departs from this convention by adopting a symmetric quantization scheme for activations ranging from $[-Q_b, Q_b]$. Specifically, instead of scaling activations to a range like $[0, Q_b]$ as done in some prior works (such as BitNet's original formulation), BitNet b1.58 scales all activations per token directly into the symmetric interval centered at zero. This modification eliminates the need for zero-point quantization entirely. The removal of zero-points simplifies both the software implementation and the underlying hardware logic required for inference pipelines, as it avoids extra addition operations needed to handle offsets before applying non-linear functions or performing matrix multiplications. Despite this simplification in representation strategy, experimental results indicate that this shift introduces negligible effects on model performance while providing significant gains in ease of deployment and optimization at the system level. By aligning activation quantization with symmetric ranges and maintaining an 8-bit precision for these activations alongside the 1.58-bit weights, BitNet b1.58 achieves a balanced trade-off between computational efficiency and representational fidelity throughout the forward pass of the Transformer network.

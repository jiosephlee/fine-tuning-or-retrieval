\title{Stack Exchange of the Paper: "The Era of 1-bit LLMs: All Large Language Models are in 1.58 Bits"}

### How does adding the value '0' to ternary weights result in exactly 1.58 bits of information?
Question:
The paper introduces \textbf{BitNet b1.58} and states that by adding an additional value of 0 to the original 1-bit BitNet (which used \{-1, 1\}), the model now has ternary weights \{-1, 0, 1\}, resulting in "1.58 bits". 

I understand that \log_2(2) = 1 bit for binary values, but I am confused about the calculation for ternary values. Is the "1.58" derived from \log_2(3)? If so, why is this metric referred to as "bits" in the title and throughout the paper when it represents a non-integer number of bits? Does this imply that the storage is actually fractional per parameter, or is this a theoretical information density metric?
Answer:
The "1.58" in **BitNet b1.58** is indeed derived directly from the logarithm base 2 of the number of possible weight values, specifically $\log_2(3) \approx 1.585$. In information theory, the amount of information required to represent one of $N$ equally likely states is defined as $\log_2(N)$ bits. The original BitNet architecture used binary weights $\{-1, 1\}$, which offers $N=2$ states, resulting in exactly $\log_2(2) = 1$ bit per parameter. By introducing the value $0$ to create a ternary set $\{-1, 0, 1\}$, the number of distinct states increases to $N=3$, and the theoretical information density becomes $\log_2(3) \approx 1.58$ bits per parameter.

This metric is referred to as "bits" because it represents the **theoretical information capacity** or entropy of a single weight parameter, not necessarily the physical storage size in bytes or bits on a hard drive. In practice, you cannot store a single parameter using a fractional number of physical bits (e.g., you cannot allocate exactly $1.58$ bits of memory to one weight); instead, this value serves as a normalized measure to compare the efficiency and complexity of different quantization schemes against standard floating-point formats like FP16 (which uses $16$ bits). The paper uses this nomenclature to highlight that while the model moves beyond strict binary ($1$-bit) constraints by adding zero for feature filtering capabilities, it remains significantly more compact than standard low-precision models like $4$-bit or $8$-bit quantized networks. The "$1.58$-bit" label effectively communicates that the model's weight precision is roughly halfway between binary and ternary in terms of information content, yet it retains the computational advantages of integer-only arithmetic (specifically integer addition) described in the paper's discussion on energy and latency improvements.

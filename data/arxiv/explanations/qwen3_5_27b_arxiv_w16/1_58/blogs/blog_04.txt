# The New Scaling Law: Why Smaller Bit-Width Means Bigger Performance

For years, the prevailing wisdom in the Large Language Model (LLM) community has been straightforward: bigger models require more compute, more memory, and more energy. To get better performance, we simply scale up the number of parameters and the training tokens, accepting the steep costs as a necessary trade-off. However, recent research challenges this assumption head-on by introducing a paradigm where reducing the precision of model weights actually unlocks a new scaling law. The introduction of **BitNet b1.58** demonstrates that we can achieve performance on par with full-precision models while drastically cutting latency, memory usage, and energy consumption.

The core innovation lies in moving away from standard 16-bit floating-point representations (FP16 or BF16) to a ternary weight system where every parameter is constrained to one of three values: $\{-1, 0, 1\}$. This specific configuration is termed "1.58-bit" because representing three distinct states requires $\log_2(3) \approx 1.58$ bits of information. By replacing standard matrix multiplication operations with integer additions and eliminating the need for complex floating-point multipliers, BitNet b1.58 fundamentally changes the computational cost of inference. This shift allows the model to retain its modeling capability while becoming significantly more cost-effective across every metric that matters for deployment.

## How BitNet b1.58 Works

The architecture of BitNet b1.58 is designed to be compatible with modern open-source ecosystems, adopting LLaMA-like components such as RMSNorm, SwiGLU activations, and rotary embeddings (RoPE). The critical difference is found in how weights are handled during training and inference. Instead of storing high-precision floats, the model uses an `absmean` quantization function to constrain weights to the ternary set $\{-1, 0, 1\}$.

Mathematically, this process involves scaling the weight matrix $W$ by its average absolute value $\gamma$ before rounding:
$$
\widetilde{W} = \mathrm{RoundClip}\left(\frac{W}{\gamma + \epsilon}, -1, 1\right)
$$
where $\gamma = \frac{1}{nm}\sum_{ij} |W_{ij}|$. The inclusion of zero in the weight set is particularly significant; it provides explicit feature filtering capabilities that were absent in previous binary-only approaches. This allows the model to effectively "turn off" certain connections during computation without losing precision in the remaining active pathways. While weights are reduced to 1.58 bits, activations are maintained at 8 bits to ensure stability during inference without introducing zero-point quantization complexities.

## Redefining Efficiency and Performance

The most striking finding from this research is that BitNet b1.58 does not sacrifice accuracy for efficiency when scaled appropriately. In experiments pre-trained on 100 billion tokens from the RedPajama dataset, BitNet b1.58 models starting at 3 billion parameters matched or exceeded the perplexity and zero-shot performance of full-precision LLaMA baselines of the same size.

However, where these models truly diverge is in their operational cost. Because matrix multiplication in BitNet b1.58 relies primarily on integer additions rather than floating-point multiplications and additions, the energy savings are massive. On 7nm chips, this architecture saves approximately 71.4 times the arithmetic operation energy consumption for matrix multiplication compared to FP16 models. This efficiency translates directly into speed; a 3B BitNet b1.58 model was found to be 2.71 times faster and used 3.55 times less GPU memory than its full-precision counterpart while delivering equivalent results on benchmarks like ARC-Easy and HellaSwag.

As model sizes increase, these advantages compound rather than diminish. For instance, a 70B parameter BitNet b1.58 model runs 4.1 times faster than a standard FP16 LLaMA baseline of similar size when measured on A100 GPUs using optimized kernels. Furthermore, because memory bandwidth is often a bottleneck in large-scale inference, the reduced footprint allows for significantly higher throughput tests showed that a 70B BitNet b1.58 model could support up to 11 times the batch size of a standard LLM before hitting memory limits on two A100 cards, resulting in an overall throughput increase of nearly nine times.

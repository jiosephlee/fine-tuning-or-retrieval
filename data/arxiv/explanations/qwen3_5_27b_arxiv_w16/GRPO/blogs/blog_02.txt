\title{Blogs about the Paper: "DeepSeekMath: Pushing the Limits of Mathematical Reasoning in Open Language Models"}

# The Secret Ingredient: Why Coding Skills Make Better Mathematicians

Is there a hidden link between programming syntax and algebraic logic? Recent research from DeepSeek suggests that the answer is a resounding yes. In their latest paper introducing DeepSeekMath, researchers uncovered a surprising phenomenon: initializing a language model with code training before feeding it mathematical data significantly boosts its ability to reason through complex problems. This finding challenges the conventional wisdom that math models simply need more math data, pointing instead toward a synergy between coding and calculation that could define the next generation of logical AI.

At the heart of this discovery is DeepSeekMath-7B, an open-source model that achieves a remarkable 51.7% accuracy on the competition-level MATH benchmark without relying on external calculators or voting mechanisms. To put this in perspective, this performance rivals massive closed-source models like Gemini-Ultra and GPT-4, despite DeepSeekMath having only 7 billion parameters. The secret sauce isn't just the sheer volume of data—though they did curate a massive 120-billion-token corpus from Common Crawl—but rather *how* that data was processed and what came before it.

The team made a deliberate architectural choice to initialize their model using DeepSeek-Coder-Base-v1.5, a model already specialized in code generation, rather than starting from a generic large language model. Their experiments revealed that this "code-first" approach acts as a powerful catalyst for mathematical reasoning. When they tested different training regimes, they found that models undergoing code training followed by math training consistently outperformed those trained only on general text or math alone. This held true for both program-aided reasoning, where the model writes Python scripts to solve problems, and pure chain-of-thought reasoning where no tools are used. Essentially, learning to structure logic in code appears to transfer directly to structuring arguments in mathematics.

This observation offers a compelling answer to a long-standing question in the field: does code training improve general reasoning abilities? The evidence suggests it does, at least within the mathematical domain. The researchers hypothesize that the rigorous syntax and logical flow required for programming help models internalize structured thinking patterns that are equally vital for solving multi-step algebraic or geometric proofs. Even more interestingly, when they attempted to mix code and math tokens in a single-stage training process to prevent "catastrophic forgetting," they found it maintained coding skills while still aiding mathematical performance, though separating them into stages yielded slightly better results for non-tool-assisted math tasks in their smaller experimental setups.

Beyond the pre-training strategy, DeepSeekMath introduces Group Relative Policy Optimization (GRPO), a novel reinforcement learning algorithm designed to be more efficient than traditional methods like Proximal Policy Optimization (PPO). Standard PPO requires training a separate "critic" model to estimate values, which doubles memory usage and computational costs. GRPO eliminates this need by estimating baselines from groups of outputs generated for the same prompt. By comparing these outputs relative to each other within a group, GRPO reduces memory overhead while delivering significant performance jumps. Applying GRPO pushed DeepSeekMath's MATH score from 46.8% to 51.7%, proving that refining an already strong instruction-tuned model via reinforcement learning can unlock new levels of capability even when using only a subset of existing data.

The implications of these findings extend beyond just beating benchmarks on arithmetic problems. They suggest that the path forward for building smarter AI might involve hybridizing distinct skill sets earlier in the training lifecycle rather than treating them as silos. If exposure to code creates a stronger foundation for abstract reasoning, we may see future models increasingly adopting "code-native" architectures as their default state for handling logic-heavy tasks. As DeepSeek demonstrates with their open-source release, high-quality data engineering combined with smart initialization strategies can allow smaller models to punch well above their weight class, narrowing the gap with industry giants without requiring exponential increases in compute power or parameter counts.

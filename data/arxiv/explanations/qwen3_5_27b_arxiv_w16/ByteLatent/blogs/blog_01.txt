# Goodbye Tokens, Hello Patches: How the Byte Latent Transformer Changes AI Efficiency

For years, the standard recipe for building a Large Language Model (LLM) has remained largely unchanged: take raw text, chop it into fixed pieces called tokens using a heuristic vocabulary, and feed those tokens into a Transformer. This tokenization step is a necessary evil that introduces biases, struggles with rare languages, and fails to capture the nuances of raw character data. However, a new architecture called the Byte Latent Transformer (BLT) is challenging this status quo. By replacing static tokens with dynamic "patches" derived directly from raw bytes, BLT achieves performance on par with industry giants like Llama 3 while potentially cutting inference costs by up to 50%.

The core innovation of BLT lies in how it groups data. Traditional models treat every token as an equal unit of computation, regardless of how easy or difficult it is to predict. If a model encounters a common word ending or a predictable sequence of characters, it still expends the same amount of computational power as it would for a complex, high-entropy decision. BLT flips this logic by dynamically allocating compute based on the complexity of the data. Instead of fixed tokens, BLT segments raw bytes into variable-sized patches. These patches serve as the primary units of computation, allowing the model to spend more resources where uncertainty is high and fewer resources where the data is predictable.

## The Problem with Fixed Tokens

To understand why BLT is significant, we must first look at the limitations of current tokenization methods like Byte-Pair Encoding (BPE). Tokenizers rely on a fixed vocabulary determined before training begins. This creates several issues. First, it introduces domain sensitivity; a tokenizer trained on English text might struggle with code or low-resource languages because those byte sequences do not align well with the pre-defined vocabulary. Second, tokenization breaks orthographic knowledge. Because tokens are atomic units to the model, it often lacks an understanding of individual characters within a word, making it brittle when faced with noisy inputs like misspellings or character-level noise.

Furthermore, tokenization creates an efficiency bottleneck. In standard Transformers, the computational cost is dominated by feed-forward network layers that run for every single token step. Since tokens are created via compression heuristics that do not always correlate with prediction difficulty, models often waste compute on easy predictions while under-allocating resources for hard ones. Previous attempts to train models directly on bytes failed at scale because processing every single byte individually resulted in prohibitively long sequence lengths and excessive computational costs. BLT solves this by introducing a middle ground: patches that are larger than bytes but smaller than sentences, sized dynamically based on information density.

## How Dynamic Patching Works

The heart of BLT's efficiency is its patching mechanism. Unlike static tokenizers that group bytes based on frequency or fixed rules like whitespace, BLT uses entropy to decide where one patch ends and another begins. Entropy, in this context, measures the uncertainty or unpredictability of the next byte in a sequence. The model identifies points where the entropy spikes—indicating that a new piece of information or a difficult prediction is required—and starts a new patch there. Conversely, when the entropy is low and the sequence is highly predictable (like completing a common suffix), BLT extends the current patch to include more bytes without invoking expensive global computations.

This process relies on three distinct components working in harmony:
*   **A Local Encoder:** A lightweight transformer that processes raw bytes within a patch and compresses them into a latent representation (the patch vector).
*   **A Global Latent Transformer:** A large-scale model that operates on these patch representations rather than individual bytes or tokens. This is where the bulk of the reasoning happens.
*   **A Local Decoder:** Another lightweight module that expands the patch representations back into raw byte predictions for generation.

By using entropy-based boundaries, BLT ensures that patches contain relatively uniform information density. This means that when the Global Transformer runs one step for one patch, it is effectively processing roughly the same amount of "information" regardless of whether that patch contained 4 bytes or 10 bytes. This dynamic allocation allows the model to skip over predictable content efficiently while focusing its massive capacity on complex decisions.

## Scaling Efficiency and Performance

The most striking result from the research is how well this architecture scales when compared to traditional token-based models like Llama 3. In standard scaling studies where training compute (flops) is held constant, BLT matches or even outperforms Llama 3 across various parameter sizes up to 8 billion parameters and 4 trillion training bytes. This proves that removing fixed-vocabulary tokenization does not inherently hurt performance; in fact, it can improve it by allowing more flexible data modeling.

However, where BLT truly shines is in inference efficiency because it decouples model size from inference cost in a way tokenizers cannot. In traditional models, increasing vocabulary size to get larger average tokens comes at the cost of massive embedding tables and limited flexibility in token size distribution. With BLT, researchers can simultaneously increase both the model size and the average patch size while maintaining a fixed inference budget. Since larger patches mean fewer steps for the expensive Global Transformer to execute per byte of output, increasing patch size saves compute that can be reallocated to make the Global Transformer itself larger and more capable.

Experiments show that for fixed inference costs, BLT demonstrates significantly better scaling trends than tokenization-based architectures. By utilizing an average patch size of roughly 8 bytes compared to Llama 3's average token size of roughly 4 bytes, BLT can achieve similar performance while using up to 50% fewer floating-point operations during inference. This efficiency gain opens up new possibilities for deploying powerful models in resource-constrained environments without sacrificing intelligence or reasoning capabilities.

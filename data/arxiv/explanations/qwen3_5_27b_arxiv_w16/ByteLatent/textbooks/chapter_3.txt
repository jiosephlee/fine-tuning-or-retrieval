Chapter 3: The BLT Architecture: A Hierarchical Transformer Design

The Byte Latent Transformer (BLT) represents a paradigm shift in how large language models process raw data, moving away from the rigid, fixed-vocabulary tokenization that has dominated the field. At its core, the BLT architecture is designed to dynamically allocate computational resources based on the complexity of the input data. Instead of treating every unit of text with equal computational weight, BLT segments raw byte sequences into variable-sized groups called patches. This segmentation allows the model to spend more compute on high-entropy, information-dense regions while efficiently skipping over predictable, low-entropy sequences. The architecture achieves this through a hierarchical design comprising three distinct but interconnected components: a lightweight Local Encoder that maps bytes to patch representations, a large Global Latent Transformer that performs the heavy autoregressive modeling on these patches, and a Local Decoder that expands the patch representations back into raw byte sequences. This three-stage flow ensures that the model can operate end-to-end on raw bytes without a fixed vocabulary while maintaining efficiency and robustness comparable to, and in some cases exceeding, state-of-the-art tokenization-based models.

The fundamental workflow of BLT begins with a sequence of raw bytes, denoted as $\pmb{x}=\{x_i | i=1,\ldots,n\}$. Unlike traditional models that immediately map these bytes to a discrete set of tokens from a pre-defined vocabulary, BLT first groups these bytes into patches $\pmb{p}=\{p_j | j=1,\ldots,m\}$ where $m < n$. The size of these patches is not fixed; rather, it is determined dynamically based on the entropy of next-byte predictions derived from a small auxiliary language model. This creates contextualized groupings where patches with lower information density (predictable text) are longer, and patches with higher information density (unpredictable text) are shorter. The Local Encoder processes these byte sequences to create expressive latent representations for each patch. These representations are then fed into the Global Latent Transformer, which operates autoregressively over the sequence of patches. Finally, once the Global Transformer generates an output patch representation, the Local Decoder takes this representation and conditions it on previously decoded bytes to predict the specific sequence of raw bytes that constitute that patch. This separation of concerns allows the computationally expensive global attention mechanism to run less frequently on longer patches, significantly reducing inference costs while preserving the model's ability to understand fine-grained byte-level details.

# The Local Encoder ($\mathcal{E}$): Mapping Bytes to Patch Representations with Lightweight Transformers

The Local Encoder, denoted as $\mathcal{E}$, serves as the bridge between the raw byte stream and the high-level latent space where global reasoning occurs. It is designed as a lightweight transformer-based model with significantly fewer layers ($l_{\mathcal{E}}$) than the global model ($l_{\mathcal{G}}$), ensuring that it does not become a computational bottleneck despite processing every single byte in the input sequence. Its primary function is to map a sequence of input bytes $b_i$ into expressive patch representations $p_j$. A critical architectural departure in $\mathcal{E}$ compared to standard transformers is its attention mechanism and its role in pooling information. While standard transformers operate on a fixed sequence length or require complex masking for variable lengths, $\mathcal{E}$ utilizes a local block causal attention mask. This mask restricts each byte's attention window to a fixed number $w_{\mathcal{E}}$ of preceding bytes. Crucially, this window can cross dynamic patch boundaries but cannot cross document boundaries. This design ensures that each byte representation captures sufficient local context from its immediate neighbors before being aggregated into a patch-level summary.

The encoder processes bytes through a series of alternating transformer layers and cross-attention layers. The transformer layers within $\mathcal{E}$ refine the individual byte embeddings using self-attention within their local windows and feed-forward networks. However, these refined byte representations are not yet ready for the global model; they must be condensed into single vectors representing entire patches. This condensation is achieved through specialized cross-attention modules placed after each transformer layer in the encoder stack. These modules act as pooling mechanisms that aggregate information from all bytes within a specific patch $p_j$ into a single query vector representing that patch. By interleaving self-attention (for local context) and cross-attention (for pooling), $\mathcal{E}$ effectively compresses variable-length byte sequences into fixed-dimensional latent vectors without losing critical information about the internal structure of those sequences. The result is a sequence of patch representations $P \in \mathbb{R}^{n_p \times h_{\mathcal{G}}}$ that are ready to be processed by the much larger Global Latent Transformer, where $n_p$ is the number of patches and $h_{\mathcal{G}}$ is the hidden dimensionality required by the global model.

# Hash n-gram Embeddings: Enhancing Local Context Awareness without Large Vocabularies

A key challenge in processing raw bytes directly is capturing local patterns and orthographic regularities without resorting to massive embedding tables or fixed vocabularies that might miss rare character combinations or fail in low-resource languages. To address this within the Local Encoder, BLT introduces hash n-gram embeddings as an augmentation to standard byte embeddings. This technique allows the model to incorporate information about preceding bytes efficiently by modeling both individual bytes and their local n-gram contexts simultaneously. For every step $i$ in the sequence, BLT constructs byte n-grams $g_{i,n}=\{b_{i-n + 1},\ldots,b_i\}$ for various lengths $n$, typically ranging from 3 to 8 characters. These n-grams capture short-term dependencies such as common letter digraphs or trigrams that are essential for understanding spelling and morphology but are often lost when tokens are split arbitrarily by standard tokenizers.

Instead of maintaining an explicit dictionary for every possible n-gram—which would be prohibitively large given there are $256^n$ possibilities—BLT employs hash embeddings with collision handling via modulo arithmetic. Each constructed n-gram $g_{i,n}$ is passed through a hash function (specifically RollPolyHash) which maps it to an index in a fixed-size embedding table $E_{n}^{hash}$. The resulting embedding vector is then added to the base embedding of the current byte $x_i$. Mathematically, this augmented embedding $e_i$ is calculated as:
$$e_i = x_i + \sum_{n = 3,...8} E_{n}^{hash}(\text{Hash}(g_{i,n}))$$
where $\text{Hash}(g_{i,n}) = \text{RollPolyHash}(g_{i,n}) \% |E_{n}^{hash}|$. This summation allows multiple n-gram features to contribute simultaneously to a single position's representation without exploding memory usage or parameter count relative to vocabulary size variations found in token-based models. After aggregation, these augmented embeddings are normalized by dividing by the number of n-gram sizes plus one before being fed into the first layer of $\mathcal{E}$. Empirical results indicate that these hash embeddings are vital for matching tokenizer-based performance, particularly on domains like Wikipedia and code repositories where specific character sequences carry significant semantic weight. They provide a mechanism for "orthographic knowledge" at scale without requiring explicit tokenization rules or large lookup tables for rare subwords.

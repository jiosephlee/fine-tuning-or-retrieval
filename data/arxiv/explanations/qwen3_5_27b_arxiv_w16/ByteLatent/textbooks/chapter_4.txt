Chapter 4: # Chapter 4: The BLT Architecture Design

## High-Level Overview: Local Encoders/Decoders + Global Latent Transformer

The Byte Latent Transformer ({\textsc BLT}) represents a fundamental shift in Large Language Model (LLM) architecture by eliminating the reliance on fixed-vocabulary tokenization. Instead of compressing raw bytes into a static set of discrete tokens, {\textsc BLT} introduces a dynamic, learnable system that groups bytes into variable-sized units called *patches*. This architectural innovation addresses the historical inefficiency of byte-level models, where the sheer volume of sequential steps required to process individual bytes made training prohibitively expensive. The core philosophy driving {\textsc BLT} is the dynamic allocation of computational resources: complex, unpredictable parts of a text stream require more intensive modeling, whereas predictable sequences can be processed with minimal overhead. To realize this vision, the architecture is decomposed into three distinct components working in concert: a lightweight local encoder, a massive global latent transformer, and a lightweight local decoder.

The flow of information through {\textsc BLT} begins with raw input bytes entering the local encoder. This component acts as a bridge between the continuous stream of binary data and the abstract semantic space where high-level reasoning occurs. Its primary function is to aggregate sequences of bytes—whose lengths are determined dynamically by an external entropy-based patching strategy—into compact, expressive latent vectors known as patch representations. Once these patches are formed, they are handed off to the global latent transformer. This central engine is responsible for the heavy lifting of autoregressive language modeling. It operates exclusively on the sequence of patch representations rather than individual bytes, allowing it to capture long-range dependencies and high-level context with significantly fewer computational steps than a standard byte-level transformer would require. After the global model generates the necessary output patch representations, they are passed to the local decoder. The decoder reverses the encoding process, expanding each latent patch representation back into a precise sequence of raw bytes to reconstruct the predicted text. By separating concerns in this manner, {\textsc BLT} ensures that computationally expensive operations are reserved for moments where data complexity dictates their necessity, thereby achieving superior inference efficiency without sacrificing performance.

## The Local Encoder: Mapping Raw Bytes to Expressive Patch Representations

The local encoder model, denoted as $\mathcal{E}$, serves as the interface between raw byte streams and the high-dimensional latent space utilized by the global transformer. Architecturally, $\mathcal{E}$ is designed to be exceptionally lightweight compared to its global counterpart; it consists of $l_{\mathcal{E}}$ layers where $l_{\mathcal{E}} \ll l_{\mathcal{G}}$, ensuring that the overhead associated with processing every single byte remains negligible relative to the total computational budget. Despite its reduced depth, the encoder must perform a sophisticated task: it must condense arbitrary sequences of bytes into rich representations that preserve all necessary information for accurate prediction while discarding redundancy inherent in predictable text regions. To facilitate this compression without losing critical signal, the encoder employs a specialized attention mechanism that differs fundamentally from standard self-attention blocks found in typical LLMs. Specifically, after each standard transformer layer within $\mathcal{E}$, there is an inserted cross-attention layer dedicated solely to pooling byte-level features into patch-level queries.

The operational mechanics of the local encoder begin with embedding each input byte $b_i$ into a vector space using an embedding matrix $\mathbb{R}^{256 \times h_{\mathcal{E}}}$. These base embeddings are immediately augmented with contextual information derived from surrounding bytes before being fed into the transformer layers. Within these layers, attention is constrained strictly locally; each byte attends only to a fixed window $w_{\mathcal{E}}$ of preceding bytes using a *local block causal* mask. Crucially, this window can span across dynamic patch boundaries but never crosses document boundaries, ensuring that short-term syntactic patterns are captured regardless of how patches are segmented globally. The output of these localized interactions forms intermediate hidden states $h_i$, which represent refined views of individual bytes enriched by their immediate neighbors. These states then serve as keys and values for the subsequent cross-attention stage, where they interact with query vectors representing entire patches. Through this iterative refinement and aggregation process across multiple layers, $\mathcal{E}$ transforms a chaotic stream of integers into ordered sequences of latent variables ready for global processing, effectively acting as a learned compressor that adapts its granularity based on data structure rather than rigid rules.

## Hash N-Gram Embeddings: Capturing Orthographic Context Without a Dictionary

One of the most significant challenges in removing fixed-vocabulary tokenizers is preserving fine-grained orthographic knowledge—the understanding that letters combine in specific ways to form meaningful units—which tokenizers naturally encode through shared subword prefixes and suffixes. In {\textsc BLT}, since there is no predefined dictionary linking character combinations to IDs during training or inference at scale (unlike Byte-Pair Encoding), explicit mechanisms must be engineered to inject n-gram awareness directly into the model's initial state representation. To solve this problem without exploding memory usage or requiring massive lookup tables for rare strings, {\textsc BLT} utilizes hash n-gram embeddings inspired by techniques used in sparse feature hashing literature but adapted here for dense neural networks at scale. Rather than storing every possible substring seen during training in an embedding table—a feat impossible given combinatorial explosion—the model constructs virtual n-grams on-the-fly and maps them via deterministic hash functions to indices within fixed-size embedding tables $E_n^{\text{hash}}$.

For every position $i$ in the input sequence and for n-gram sizes $n$ ranging from 3 to 8 characters inclusive (omitting valid constructions near sequence start), {\textsc BLT} extracts contiguous substrings $g_{i,n} = \{b_{i-n+1}, \dots, b_i\}$. Each extracted n-gram is then transformed into an integer index using a polynomial rolling hash function modulo table size $|E_n^{\text{hash}}|$:
$$ \text{Index}_n(i) = \text{RollPolyHash}(g_{i,n}) \% |E_n^{\text{hash}}| $$
These hashed indices retrieve specific vectors from their respective embedding tables $E_n^{\text{hash}}$, which are summed together along with individual byte embeddings $x_i$ to form an augmented input representation $e_i$:
$$ e_i = x_i + \sum_{n=3}^{8} E_n^{\text{hash}}(\text{Hash}(g_{i,n})) $$
Before passing these combined vectors into the transformer layers, they undergo normalization divided by $(N+1)$ where $N$ is 6 (the count of active n-gram sizes). This additive enrichment strategy allows even shallow parts of the network instantaneously access multi-character context such as digraphs ("th"), trigraphs ("ion"), or longer roots ("tion") without

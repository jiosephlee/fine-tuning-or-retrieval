# Goodbye Tokens, Hello Patches: How BLT Makes AI Smarter and Faster

For years, Large Language Models (LLMs) have relied on a fundamental bottleneck: tokenization. Before a model can process text, it must chop raw data into a fixed set of symbols called tokens. While effective, this heuristic introduces biases, struggles with rare languages, and treats every token equally regardless of how easy or difficult it is to predict. A groundbreaking new paper introduces the Byte Latent Transformer (BLT), an architecture that abandons fixed vocabularies entirely. Instead of tokens, BLT uses dynamically sized "patches" of raw bytes, allowing the model to allocate compute precisely where it is needed most. The result is a system that matches the performance of top-tier models like Llama 3 while reducing inference costs by up to 50%.

## The Problem with Fixed Tokens

Traditional LLMs treat every token as a unit requiring the same amount of computational effort. Whether the model is predicting a common stop word like "the" or a complex scientific term, it executes the same massive transformer layers for each step. This inefficiency stems from the nature of tokenization itself: it forces data into a static grid defined before training begins. This rigidity leads to issues such as poor handling of input noise, limited orthographic knowledge (understanding how letters form words), and inequities across different languages.

Previous attempts to train models directly on bytes failed at scale because processing individual bytes creates sequence lengths that are computationally prohibitive. If you process every byte individually, the sheer volume of steps required overwhelms standard hardware. Existing solutions tried to fix this with specialized attention mechanisms or smaller models, but they could not compete with large-scale tokenized systems because the dominant cost in modern Transformers lies in the feed-forward network layers running on every step, not just the attention mechanism.

## Enter Dynamic Patching

The core innovation of BLT is replacing static tokens with dynamic patches. Rather than forcing data into pre-defined chunks, BLT groups consecutive bytes into patches based on their information density. The model uses a lightweight helper network to estimate the entropy (uncertainty) of the next byte in a sequence. If the upcoming bytes are highly predictable—like finishing a common word—the model groups them into a large patch and skips over them quickly using minimal compute. Conversely, when encountering high-entropy regions where prediction is difficult—such as the start of a new sentence or complex code—the model creates smaller patches and invokes its powerful global transformer to focus resources exactly where they are needed.

This approach fundamentally changes how compute is spent. In a token-based model, you pay full price for every step regardless of difficulty. In BLT, you pay more for hard problems and less for easy ones. Mathematically, if $H(x_i)$ represents the entropy at byte $i$, patch boundaries are determined by thresholds such as $H(x_t) > \theta_g$ or relative changes like $H(x_t) - H(x_{t-1}) > \theta_r$. This ensures that patches represent segments of relatively uniform information density rather than arbitrary character counts or whitespace delimiters.

## A Hybrid Architecture for Efficiency

To support this dynamic behavior without losing performance, BLT employs a hybrid architecture consisting of three components: two small local models and one large global latent transformer. The **Local Encoder** takes raw bytes within a patch and compresses them into a single latent representation using lightweight cross-attention layers enriched with hash n-gram embeddings to capture local context efficiently. This compressed representation is then fed into the **Global Latent Transformer**, which handles high-level reasoning across patches but runs far fewer times than a standard transformer would run per byte count. Finally, a **Local Decoder** expands these latent representations back into raw bytes autoregressively.

Because the global transformer only runs once per patch rather than once per byte or token, increasing the average patch size drastically reduces inference costs without sacrificing context length. The researchers demonstrated that they could simultaneously increase both the size of the global model and the average patch size while staying within a fixed inference budget. This unlocks a new scaling dimension: as models get bigger, they can afford to look at larger chunks of data at once, leading to steeper performance gains compared to traditional architectures constrained by fixed vocabulary sizes.

## Performance and Robustness Wins

The implications of this shift are profound both in terms of raw speed and intelligence capabilities. In extensive scaling studies involving up to 8 billion parameters and 4 trillion training bytes, BLT achieved parity with Llama 3 in terms of training efficiency while offering significant inference advantages. By adjusting entropy thresholds during inference to prioritize accuracy over speed when necessary—or vice versa—BLT can trade minor metric differences for up to 50% fewer floating-point operations (FLOPs). Beyond efficiency, removing tokenization barriers has made BLT significantly more robust. It excels at tasks requiring fine-grained character understanding that confuse tokenized models, such as phonological transcription (grapheme-to-phoneme conversion) and manipulating text under noisy conditions like random case changes or character deletions. It also demonstrates superior performance in low-resource machine translation tasks where rigid tokenizers often fail to generalize effectively across diverse scripts and languages.

## Conclusion

The Byte Latent Transformer represents a pivotal moment in LLM architecture design by proving that we do not need fixed vocabularies to build smart machines at scale. By treating bytes as fluid data that can be grouped dynamically based on complexity, BLT achieves state-of-the-art performance while respecting computational constraints more intelligently than ever before. As we move toward larger models and more diverse applications, this ability to adapt compute allocation on the fly—and gain deeper insights into sub-word structures—suggests that "patches" may well be the future foundation for efficient artificial intelligence code repositories are already available for those eager to explore this tokenizer-free frontier themselves



# Why Your AI Stumbles Over Typos (And How Raw Bytes Fix It)

If you have ever tried to interact with a Large Language Model (LLM) using messy input—perhaps text with random capitalization, missing letters, or unusual spacing—you have likely noticed the model stumbling. Current state-of-the-art models rely heavily on a preprocessing step called tokenization, which chops text into a fixed set of sub-word units before the model sees them. While efficient, this approach introduces a rigid dependency on specific patterns. If your input doesn't match the expected token patterns perfectly, the model loses its grounding in the actual characters, leading to confusion and degraded performance.

A new architecture called the Byte Latent Transformer (BLT) challenges this status quo by processing raw bytes directly. By bypassing fixed vocabularies and dynamically grouping bytes into "patches," BLT demonstrates a remarkable resilience to noise and a deeper understanding of language structure that token-based models simply cannot replicate.

## The Hidden Fragility of Tokenization

To understand why BLT is so effective at handling messy data, we first need to look at how traditional models fail. Most LLMs use algorithms like Byte Pair Encoding (BPE) to convert text into tokens. This creates a finite vocabulary where every word or sub-word fragment is assigned a specific ID. The problem arises when the input deviates from the clean examples seen during training.

Consider a scenario where you ask a model about "Magic Flute" but accidentally type "Magc Flute." A token-based model might tokenize "Magc" as an unknown sequence or split it into fragments it hasn't seen together before. Because the model operates on these abstract IDs rather than individual characters, it lacks intrinsic knowledge of orthography—the rules governing how letters combine to form words. It knows "Magic" is a token, but it doesn't necessarily know that removing an 'i' breaks the word in a specific way unless it has explicitly memorized that error pattern.

Furthermore, tokenization biases how strings are compressed. This leads to issues with multilingual inequity and sensitivity to input noise. If a language uses characters or diacritics that don't align well with the tokenizer's vocabulary, or if text is formatted strangely (like all uppercase or spaced-out letters), the model's internal representation shifts unpredictably. The result is a system that feels brittle when faced with the long tail of real-world data variations.

## Enter BLT: Processing Data as It Is

The Byte Latent Transformer addresses these fragilities by eliminating the fixed vocabulary entirely. Instead of forcing bytes into predefined buckets, BLT treats every byte as fundamental data. However, processing every single byte through a massive transformer would be computationally prohibitive due to long sequence lengths. To solve this, BLT introduces **dynamic patching**.

Unlike static chunking methods that cut text every *N* bytes regardless of content, BLT uses entropy to decide where to draw boundaries between patches. The model analyzes the uncertainty of predicting the next byte; when the prediction is easy (low entropy), such as continuing a common suffix like "-ing", multiple bytes are grouped into a single large patch. When prediction is hard (high entropy), such as starting a new sentence or encountering rare terminology, the patch size shrinks to allow for finer-grained computation.

This dynamic allocation means BLT spends its computational power exactly where it is needed most without losing sight of individual bytes. Crucially, because there is no fixed dictionary, arbitrary groups of bytes are mapped to latent representations via lightweight learned encoders and decoders. This allows the model to maintain direct access to byte-level features throughout its reasoning process.

## Superior Robustness Against Noise

The immediate payoff of working with raw bytes is robustness against corrupted or noisy inputs. Researchers tested BLT against standard Llama 3 models using five distinct character-level noising strategies: converting text to uppercase with spaces ("AntSpeak"), randomly dropping 10% of characters, mixing upper and lower case randomly, repeating characters excessively, and forcing everything to uppercase across prompts and completions.

The results were starkly different between architectures. While token-based models suffered significant performance drops as their internal token mappings became scrambled by noise, BLT maintained high accuracy across all conditions. In tests on noisy versions of the HellaSwag benchmark, BLT outperformed tokenizer-based models by an average margin of 8 points over models trained on identical data volumes and even beat larger models trained on significantly more data (like Llama 3). By understanding text at the character level rather than relying on pre-defined chunks, BLT can reconstruct meaning even when surface-level formatting is destroyed.

## Unlocking Deep Linguistic Understanding

Beyond simple noise resistance, processing raw bytes grants models capabilities in areas where tokenizers inherently fall short: phonology and orthographic manipulation. Because tokenizers treat sub-words as atomic units often devoid of internal structure regarding sound or spelling rules, they struggle with tasks requiring fine-grained character manipulation.

BLT excels in Grapheme-to-Phoneme (G2P) conversion tasks, which require mapping written characters to their spoken sounds—a skill critical for speech synthesis and pronunciation correction in diverse languages where spelling rules are irregular or non-existent in standard dictionaries on tokens alone showed significant gaps here compared to their byte-native counterpart demonstrated exceptional proficiency in character manipulation tasks achieving near-perfect scores on spelling-related challenges within benchmarks designed specifically for this purpose such as CUTE . These benchmarks test whether a model understands compositionality—for instance knowing that deleting one letter from "cat" yields "at"—rather than just recalling whole words . Token based models often fail these because they view "cat" as an indivisible unit whereas BL T naturally decomposes it into constituent parts allowing for precise editing operations . Even though BPE performed slightly better on word deletion tasks , which might be intuitive for word oriented systems , the overall dominance of byte modeling in structural understanding suggests that building from characters up is fundamentally more powerful than trying to deconstruct tokens downwards .

## Bridging the Gap for Low-Resource Languages

One of the most profound implications of moving away from fixed vocabularies is equity across languages . Many low-resource languages suffer because their scripts do not fit neatly into standard tokenizers optimized for major European languages . Characters may be fragmented incorrectly or merged inefficiently leading to poor coverage and generalization . By operating directly on UTF-8 bytes , BL T avoids these pitfalls entirely ensuring consistent treatment regardless of script complexity . Experiments on machine translation tasks involving twenty-one lower-resource languages revealed clear advantages : while performance remained comparable for popular language pairs , BL T significantly outperformed Llama 3 translations into English achieving higher BLEU scores specifically within families known for difficult scripts or limited training data availability . This confirms that direct byte modeling enables superior generalization to long-tail distributions where traditional tokenization fails due to insufficient vocabulary coverage .

## Conclusion: A More Resilient Future for AI

The transition from fixed-token architectures like those powering today's dominant LLMs toward dynamic byte-level systems represents more than just an efficiency tweak ; it marks a shift toward greater adaptability and robustness . By embracing raw bytes through intelligent patching mechanisms , we equip our models with an innate understanding of textual structure that transcends superficial formatting errors . Whether dealing with typos , obscure dialects , or complex phonetic relationships , systems like BL T prove that sometimes looking closer at individual components yields smarter outcomes than relying on broad abstractions alone . As we continue pushing boundaries in artificial intelligence development , adopting approaches grounded directly in fundamental data units promises not only better performance metrics but also fairer more reliable interactions across humanity's vast linguistic diversity landscape ahead us tomorrow onwards forevermore !



# The New Scaling Law: Why Growing Patches Beats Growing Vocabulary

For years, the Large Language Model (LLM) community has operated under a rigid assumption: to build smarter models, you must optimize your tokenizer. Standard architectures rely on fixed-vocabulary tokenizers, like Byte Pair Encoding (BPE), which compress raw text into a static set of symbols before the model ever sees the data. While effective, this approach introduces a fundamental economic bottleneck. Once a vocabulary is fixed, increasing the average token size requires expanding the embedding tables and output projection layers, creating a trade-off that limits how efficiently we can scale inference costs. A recent breakthrough challenges this status quo with the Byte Latent Transformer (BLT), demonstrating that dynamically grouping bytes into "patches" offers a superior path to scaling.

The core insight from the BLT paper is counterintuitive yet powerful: rather than fighting against sequence length by shrinking tokens, we should embrace variable-length chunks of data to allocate compute exactly where it is needed. By treating bytes as the fundamental unit and dynamically aggregating them into patches based on information density, BLT achieves something previously thought impossible for byte-level models—it matches the performance of top-tier tokenized models like Llama 3 while using up to 50% fewer floating-point operations (FLOPs) during inference. More importantly, it unlocks a new dimension of scaling where model size and patch size can grow simultaneously within a fixed compute budget.

## The Economics of Fixed Vocabularies vs. Dynamic Patches

To understand why BLT represents a shift in scaling economics, we must look at how traditional models allocate compute. In standard LLMs, every token triggers the same amount of computation in the main Transformer layers. Whether predicting a common stop word or a rare scientific term, the model expends identical resources per step. This inefficiency arises because tokenization is a heuristic pre-processing step; it groups bytes based on frequency statistics learned offline, not on the immediate complexity of the prediction required at runtime.

BLT replaces this static process with dynamic patching. Instead of feeding individual tokens or fixed-size byte chunks into the model, BLT segments raw bytes into variable-sized patches using an entropy-based signal. The system analyzes the uncertainty (entropy) of predicting the next byte; when data is predictable (low entropy), such as repeating characters or common suffixes, BLT groups many bytes into a single large patch. Conversely, when facing high-uncertainty regions requiring complex reasoning or novel word formation, it creates smaller patches to allow for finer-grained processing.

This dynamic allocation fundamentally changes the cost structure. In BLT, the expensive global Transformer only runs once per patch, not per byte or per fixed token. If a patch contains 8 bytes of highly predictable text, the model saves seven steps of expensive global computation compared to processing those bytes individually or as smaller tokens. This efficiency gain allows researchers to reallocate saved FLOPs toward increasing the width and depth of the global model itself, effectively buying more intelligence for every dollar spent on inference hardware.

## Breaking the Scaling Ceiling: Simultaneous Growth

The most compelling argument for BLT lies in its ability to break free from the constraints that bind traditional architectures. In standard tokenization-based models, there is an inverse relationship between average token size and model efficiency that hits a ceiling quickly due to vocabulary explosion issues. Increasing vocabulary size to get larger tokens inflates memory usage and slows down training without guaranteeing better performance scaling laws.

BLT decouples these variables entirely because it has no fixed vocabulary for patches; arbitrary groups of bytes are mapped to latent representations through lightweight learned encoders and decoders. This freedom enables a unique scaling trajectory known as "fixed inference flop scaling." Researchers can simultaneously increase both the number of parameters in the global latent transformer and the average size of the patches while keeping total inference FLOPs constant.

Imagine an 8-billion parameter model constrained by an inference budget that forces it to take thousands of steps per sentence using small tokens. Under BLT's paradigm, we can expand that same budget by doubling the average patch size from 4 bytes to 8 bytes and using those saved steps to double the capacity of the global transformer layers again and again until we hit hardware limits again? No—the saved steps are reinvested immediately into making each step *smarter*.

\title{Stack Exchange of the Paper: "Byte Latent Transformer: Patches Scale Better Than Tokens"}

### Clarification on the FLOPs equation: Why is the vocabulary size $V$ set to 0 for the Global and Encoder Transformers?
Question:
In Section 5.5, Equation (4) calculates the FLOPs for BLT. The formula for `Transf. FL` includes a parameter $V$ (vocabulary size). For the Global Latent Transformer ($\mathcal{G}$) and the Local Encoder ($\mathcal{E}$), $V$ is set to 0, while for the Local Decoder ($\mathcal{D}$), $V=256$. 

I understand that $V=256$ for the decoder because it predicts raw bytes. However, why is $V=0$ for the Global Transformer? The Global Transformer outputs patch representations $o_j$, which are then fed into the decoder. Does this mean there is no linear projection layer at the end of the Global Transformer to map hidden states to a vocabulary? If so, how are these latent representations converted into something usable by the decoder without an output projection cost in that specific block?
Answer:
The reason the vocabulary size $V$ is set to $0$ for the Global Transformer ($\mathcal{G}$) and the Local Encoder ($\mathcal{E}$) in Equation (4) is that neither of these modules performs a final linear projection onto a discrete vocabulary; instead, they output continuous latent representations. In standard Transformer architectures, the parameter $V$ in the FLOPs calculation accounts for the computational cost of the output projection layer (often called the "unembedding" layer), which maps hidden states of dimension $h$ to a vocabulary of size $V$ to predict the next token. This operation requires $O(h \times V)$ FLOPs per token.

In the BLT architecture, the Global Transformer operates entirely in a latent space. As described in Section 3.1, it takes patch representations $p_j$ as input and outputs latent patch representations $o_j$. These outputs are not raw bytes or tokens from a fixed dictionary but rather continuous vectors that serve as input to the Local Decoder. Since there is no projection from these hidden states to a discrete set of classes at this stage, there is no associated vocabulary size cost, hence $V=0$. Similarly, the Local Encoder ($\mathcal{E}$) described in Section 3.2 functions to compress sequences of raw bytes into these same latent patch representations $p_j$. Its role is purely encoding and pooling; it does not predict any output distribution over a vocabulary, so it also incurs no output projection cost ($V=0$).

The only component that requires a non-zero vocabulary size is the Local Decoder ($\mathcal{D}$), where $V=256$. As detailed in Section 3.3, the decoder's specific task is to reconstruct the raw byte sequence from the latent patch representations. To do this, it must predict one of the 256 possible byte values at each step, necessitating a final linear projection layer with an output dimension of 256. This is why Equation (4) assigns $V=256$ exclusively to the decoder term. The "conversion" you asked about happens implicitly: the Global Transformer's output vectors are passed directly as keys and values to the decoder's cross-attention mechanism (Section 3.3), where they are used to guide the prediction of individual bytes without requiring an intermediate projection step within the Global Transformer itself.

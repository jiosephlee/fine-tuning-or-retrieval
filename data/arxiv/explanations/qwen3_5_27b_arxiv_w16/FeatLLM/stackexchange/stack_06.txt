\title{Stack Exchange of the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

### Mathematical justification for using Softmax across classes with independent binary rule sets
Question:
In Equation 1, the probability vector $\mathbf{p}^i$ is computed by applying Softmax over logits derived from independent binary feature sets $\mathbf{z}_k^i$ for each class $k$:

$$\mathbf{p}^i = \text{Softmax}({[\text{logit}_{1}^i, ..., \text{logit}_{c}^i]})$$

where $\text{logit}_k^i = \max(\mathbf{w}_k, 0) \cdot \mathbf{z}_k^i$.

My confusion lies in how these logits interact. Since $\mathbf{z}_1^i$ and $\mathbf{z}_2^i$ are derived from completely different sets of rules generated specifically for Class 1 and Class 2 respectively, isn't there no direct competition between them until Softmax forces one?

If Class 1 has very strong rules (high sum) and Class 2 has weak rules (low sum), Softmax will push probability toward Class 1. But what if both classes have high sums because both sets of rules are satisfied by different attributes? Does this formulation implicitly assume mutual exclusivity even though binary classification usually implies $P(y=0) + P(y=1) = 1$, whereas here we seem to be modeling two independent scores before normalizing?

Is there a risk that if both classes satisfy many high-weight rules simultaneously due to overlapping feature definitions in natural language, the model becomes unstable?
Answer:
The mathematical formulation in Equation 1 is justified by the fundamental requirement of the classification task to produce a valid probability distribution where the sum of probabilities across all classes equals one, effectively enforcing mutual exclusivity for the final prediction. While your intuition is correct that the binary feature sets $\mathbf{z}_k^i$ for each class are generated independently based on distinct rule sets, these logits represent raw "scores" or evidence strength rather than independent probabilities. Without the Softmax normalization, a sample could theoretically satisfy strong rules for multiple classes simultaneously (e.g., having a high logit for both Class 1 and Class 2), resulting in unnormalized scores that cannot be directly interpreted as a likelihood of belonging to a specific class in a multi-class setting.

The Softmax function serves as the necessary mechanism to convert these independent evidence scores into a competitive probability space. By exponentiating the logits and normalizing by the sum of all exponentiated logits, Softmax ensures that $\sum_{k=1}^c p_k^i = 1$. This forces a relative comparison: even if both Class 1 and Class 2 have high sums of satisfied rules, the class with the *higher* weighted sum will receive a disproportionately higher probability, while the others are suppressed. This is not an assumption that the rules themselves are mutually exclusive in reality, but rather a mathematical necessity to output a single class prediction from independent scoring mechanisms. The paper explicitly notes that this linear model with non-negative weights ($\max(\mathbf{w}_k, 0)$) learns the importance of each rule, and the subsequent Softmax operation aggregates these weighted evidences into a coherent decision boundary.

Regarding your concern about instability when multiple classes satisfy many high-weight rules simultaneously, this scenario is precisely what the training process via cross-entropy loss is designed to resolve. During training on few-shot samples, if two classes consistently receive high scores for ambiguous samples, the gradient descent will adjust the weights $\mathbf{w}_k$ to maximize the logit of the true label relative to others. If a sample truly belongs to Class 1 but triggers strong rules for Class 2 due to overlapping features (spurious correlations), the loss function penalizes this configuration, driving down the weights associated with those misleading rules for Class 2 or boosting those specific to Class 1. Furthermore, FeatLLM employs an ensemble approach with bagging across multiple trials; this aggregation smooths out individual instances where rule overlap might cause instability, as incorrect or noisy rules generated in one trial are likely compensated by correct rules in others, leading to robust final probabilities.

\title{Stack Exchange of the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

### How does the 'max' operation in the logit equation enforce non-negative weights?
Question:
In Section 3.2, the paper defines the logit for class $k$ as:

$$\text{logit}_k^i = \max(\mathbf{w}_k, 0) \cdot \mathbf{z}_k^i$$

I am confused about the mathematical implication of this. Does this mean the trainable parameter $\mathbf{w}_k$ is allowed to be negative during the optimization process (e.g., via Adam), and then simply clipped to zero before the dot product? Or does this imply a specific constraint is applied to the loss function to keep $\mathbf{w}_k$ strictly non-negative? 

The text says 'By projecting these weights into a positive subspace, we can ensure that the features generated by the LLM do not reduce the likelihood of a class.' If $\mathbf{w}_k$ were negative, wouldn't that just mean the feature is negatively correlated with the class? Why is it necessary to force all weights to be non-negative in a few-shot setting?
Answer:
The $\max(\mathbf{w}_k, 0)$ operation in the logit equation serves as a projection step that ensures the final contribution of any generated rule to the class likelihood is non-negative, without imposing a hard constraint on the trainable parameters during the optimization process. Specifically, the trainable weight vector $\mathbf{w}_k$ is allowed to take negative values during gradient descent (e.g., via Adam), but these negative values are effectively clipped to zero immediately before being multiplied by the binary feature vector $\mathbf{z}_k^i$. Mathematically, this means that if the optimizer attempts to learn a negative weight for a specific rule, that rule's contribution to the logit becomes exactly zero rather than reducing the score for that class.

This design choice is crucial because the features $\mathbf{z}_k^i$ are binary indicators derived from rules generated by an LLM, where a value of $1$ signifies that a sample satisfies a specific condition associated with class $k$. In this context, a rule generated for class $k$ is semantically intended to be evidence *for* that class. If a standard linear model were used without this projection, the optimizer could theoretically learn a negative weight for such a rule, implying that satisfying the condition actually *decreases* the probability of belonging to class $k$. This would create a logical contradiction where an LLM-derived rule for "Class A" acts as evidence against "Class A." By enforcing non-negativity via the max operation, the framework ensures inductive bias: any rule extracted for a specific class can only increase or maintain its likelihood, never decrease it. This prevents the model from learning spurious negative correlations where valid rules are treated as anti-evidence, which is particularly important in few-shot settings where data scarcity makes it easy to overfit to noise or contradictory patterns. The paper explicitly notes that this projection ensures features "do not reduce the likelihood of a class," effectively treating the learned weights as importance scores that can be zeroed out (ignored) but never inverted.

\title{Stack Exchange of the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

### Interpretation of 'Spurious Correlations' experiment: Why did performance drop only slightly?
Question:
In Section 4.2 ('Effect of adding spurious correlations'), the authors attach irrelevant columns from the Adult dataset to the Heart dataset and observe that FeatLLM degrades less than baselines.

They claim: 'This is likely because our framework forces the consideration of the relationship between the task and features based on prior knowledge... preventing the generation of rules based on irrelevant columns.'

However, they also admit later: '\textsf{FeatLLM} can also learn spurious correlations... if columns from closely related data are randomly attached.'

I am confused about the mechanism here. If I add a column named 'Income' (from Adult) to a Heart disease prediction task, wouldn't an LLM with medical prior knowledge immediately recognize that 'Income' is not medically relevant and refuse to generate rules for it? Or does it generate rules anyway but assign them low weights during training?

If it generates rules for irrelevant columns but filters them out later via weight tuning ($\mathbf{w}_k$), isn't that just standard feature selection? How is this different from XGBoost handling irrelevant features?
Answer:
The slight performance drop you observed in the spurious correlations experiment arises because \textsf{FeatLLM} employs a two-stage defense mechanism: semantic filtering during rule generation and statistical filtering during weight tuning, whereas standard models like XGBoost rely solely on the latter.

When an irrelevant column like "Income" is added to the Heart dataset, the LLM does not necessarily "refuse" to generate a rule for it in a binary sense, but the probability of it generating a *plausible* rule is drastically reduced by the specific "Reasoning instruction" in the prompt. As described in Section 3.1, the framework forces the LLM to first infer causal relationships based on prior knowledge (Step 1) before deriving rules from data examples (Step 2). Since "Income" has no known medical causal link to heart disease in the LLM's pre-trained knowledge base, the model is guided to exclude it from the set of decisive rules. The paper confirms this by noting that rules based on noisy columns accounted for only $1$-$2\%$ of the total generated rules, meaning most irrelevant features are filtered out at the source rather than being generated and then ignored.

However, as you correctly noted, if columns from *closely related* datasets are attached (e.g., adding "Education" which might correlate with "Income" and lifestyle factors), the LLM might indeed generate spurious rules because its prior knowledge could conflate these correlations. In these cases where a spurious rule is generated, \textsf{FeatLLM} relies on the second line of defense: the trainable linear model with weights $\mathbf{w}_k$. As detailed in Equation 1 and Section 3.2, these weights are optimized via cross-entropy loss on the few-shot training data. If a rule based on an irrelevant feature does not consistently predict the target label in the few available samples, its corresponding weight $\mathbf{w}_k$ will converge toward zero (or be pruned if below a threshold).

The key distinction from XGBoost or standard feature selection lies in *when* and *how* this filtering occurs. XGBoost treats all input features as equally valid candidates for splitting nodes initially; it must learn through gradient descent that a feature provides no information gain, which is difficult in low-shot regimes where noise can easily be mistaken for signal (overfitting). In contrast, \textsf{FeatLLM} uses LLM prior knowledge to pre-filter the feature space semantically before any numerical optimization begins. This effectively reduces the hypothesis space for the downstream linear model, making it much harder for spurious correlations to dominate when training data is scarce. The slight degradation you see represents the small fraction of cases where either (a) the LLM's prior knowledge was insufficient to reject a plausibly correlated but irrelevant feature, or (b) the few-shot data was too limited for the linear model to drive that specific weight to zero completely.

\title{Stack Exchange of the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

### Why does FeatLLM outperform TabLLM if TabLLM uses parameter-efficient fine-tuning?
Question:
TabLLM (one of the baselines) uses parameter-efficient tuning techniques like IA3 or LoRA on top of an LLM. Intuitively, fine-tuning allows a model to adapt its internal representations specifically to the task distribution.

FeatLLM relies entirely on in-context learning for feature generation and then switches to a simple linear model for prediction. Despite lacking direct gradient updates on the base model parameters relative to the specific tabular task, FeatLLM reportedly outperforms TabLLM significantly in few-shot regimes. Is this purely due to better feature representation (the rules), or is there something inherent about fine-tuning large models on tiny tabular datasets that causes catastrophic forgetting or poor convergence?
Answer:
The primary reason FeatLLM outperforms TabLLM in few-shot regimes is not necessarily because fine-tuning causes catastrophic forgetting, but rather because FeatLLM avoids the severe **overfitting** risks inherent in updating massive model parameters on extremely sparse data, while simultaneously leveraging the LLM's pre-trained world knowledge more effectively through a structured reasoning pipeline.

While TabLLM employs parameter-efficient fine-tuning (PEFT) techniques like LoRA or IA3 to adapt the LLM to the specific tabular distribution, doing so with only a handful of examples (few-shot) creates a high variance scenario where the model rapidly fits noise or spurious correlations present in the tiny training set. In contrast, FeatLLM treats the LLM strictly as a feature engineer using **in-context learning**. By prompting the LLM to explicitly derive logical rules (e.g., "$\text{age} > 60 \land \text{cholesterol} > 200$") based on both its vast pre-trained priors and the few provided examples, FeatLLM extracts interpretable, semantically meaningful features before passing them to a lightweight linear model. This decoupling allows the system to utilize the LLM's general knowledge without forcing its billions of parameters to shift slightly toward a dataset that is statistically insufficient to justify such updates.

Furthermore, FeatLLM incorporates an **ensemble mechanism with bagging**, which significantly enhances robustness in low-data settings. The paper notes that by running multiple rule-generation trials with randomized seeds and subsets of data, FeatLLM aggregates diverse hypotheses, filtering out incorrect rules generated in individual runs. This "wisdom of crowds" approach stabilizes predictions far better than a single fine-tuned trajectory in TabLLM. Additionally, TabLLM faces practical limitations regarding prompt size and context windows when dealing with high-dimensional tabular data; FeatLLM circumvents this by generating compact binary features derived from rules, allowing it to scale efficiently even when the raw feature count is large. Ultimately, FeatLLM succeeds because it aligns the strengths of LLMs—reasoning and knowledge retrieval—with a simple learner that can generalize well from engineered features, whereas TabLLM struggles to find a stable optimization path when trying to adapt a giant model to microscopic data signals.

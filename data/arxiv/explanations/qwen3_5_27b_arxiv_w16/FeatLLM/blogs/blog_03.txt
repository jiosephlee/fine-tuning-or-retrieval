\title{Blogs about the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

# Beyond Prompt Limits: How Bagging and Ensembling Fix LLM Constraints for Big Data

One of the most persistent challenges in applying Large Language Models (LLMs) to tabular data is the context window limit. When attempting to feed a spreadsheet with hundreds of columns or thousands of rows directly into an LLM, the serialized text quickly exceeds the maximum token capacity, causing the model to fail or lose critical information. Existing approaches often struggle here, forcing users to truncate data or accept degraded performance. However, a new framework called **FeatLLM** proposes a clever architectural shift that bypasses these hard limits entirely. By treating the LLM as a feature engineer rather than a direct predictor, and combining this with statistical techniques like bagging and ensembling, FeatLLM manages to handle massive datasets while simultaneously improving model robustness.

The core innovation of FeatLLM lies in decoupling the heavy lifting of reasoning from the actual inference phase. Instead of asking an LLM to predict the outcome for every single row in a dataset—a process that requires sending a query for each sample and hitting prompt limits immediately—FeatLLM asks the LLM to generate decision rules based on a small subset of data. The model analyzes feature descriptions and few-shot examples to infer causal relationships and outputs specific conditions, such as "If age > 60 and cholesterol > 200, then high risk." These natural language rules are then parsed into executable code to transform the raw data into new binary features. Once these features are created, a simple downstream machine learning model, such as linear regression, handles the final prediction without ever needing to consult the LLM again. This architecture drastically reduces inference costs and eliminates the need for per-sample API calls.

However, generating rules from just a few examples introduces noise; an LLM might miss important patterns or hallucinate spurious correlations due to the limited context provided in a single prompt. This is where **bagging** (bootstrap aggregating) becomes essential for overcoming prompt size constraints. Rather than trying to force all features or all training samples into one giant prompt, FeatLLM breaks the problem down. During each iteration of rule generation, it randomly selects a subset of features and a subset of training instances. This allows the system to process high-dimensional data that would otherwise be impossible to fit into an LLM's context window. By repeating this process multiple times with different random subsets, the framework gathers a diverse pool of candidate rules that collectively cover more ground than any single prompt could achieve alone.

This iterative process naturally leads to **ensembling**, which serves as both a scaling solution and an error-correction mechanism. Because each iteration uses different random seeds and subsets of data, the resulting rule sets vary slightly. Some iterations might capture strong signals while missing others; some might accidentally pick up on noise. By training separate lightweight models on these diverse feature sets and averaging their predicted probabilities, FeatLLM leverages the wisdom of crowds inherent in ensemble methods. If one run generates an incorrect rule based on a lucky correlation in its specific sample subset, other runs are likely to ignore that noise or contradict it with better evidence derived from different data slices. This self-consistency check ensures that only robust patterns survive the aggregation process, significantly boosting accuracy compared to relying on a single deterministic pass through an LLM.

The experimental results demonstrate that this combination of bagging and ensembling not only solves the scalability issue but also enhances performance in low-data regimes where overfitting is a major risk. Across 13 diverse datasets ranging from medical diagnostics to financial credit scoring, FeatLLM consistently outperformed traditional tabular learning baselines and other LLM-based approaches like TabLLM and STUNT. Crucially, it maintained high performance even on datasets with over 100 features, scenarios where competing methods failed due to prompt overflow or inability to reason effectively over long sequences. The framework achieved an average improvement of roughly 10% over alternatives by effectively filtering out uninformative features while preserving high-quality rules derived from prior knowledge encoded in the LLM's weights.

Ultimately, FeatLLM illustrates how rethinking the role of generative AI can unlock new possibilities for structured data analysis. By shifting from end-to-end prediction to automated feature engineering, researchers can sidestep rigid hardware limitations like context windows without sacrificing intelligence or speed. The strategic use of bagging transforms what seems like a constraint—the inability to see everything at once—into an advantage by encouraging diverse perspectives on the data structure coupled with ensembling ensures that these perspectives converge toward reliable truth rather than divergent errors. As tabular learning continues to evolve in fields like healthcare and finance where data privacy and volume are paramount, frameworks that prioritize efficiency alongside interpretability will become increasingly indispensable tools for practitioners navigating big data landscapes

# Stop Feeding Data to LLMs: How AI Can Now Act as Your Feature Engineer

Large Language Models (LLMs) have revolutionized how we approach data analysis, but their application to tabular learning has hit a significant bottleneck. Current methods often treat the LLM as a direct predictor, requiring the model to process every single new data point through a massive, expensive API call. This approach is not only computationally prohibitive for real-time applications but also struggles with the context window limits when dealing with datasets containing many features. A new framework called \textsf{FeatLLM} proposes a paradigm shift: instead of asking the LLM to make predictions, we ask it to act as an expert feature engineer.

The core innovation of \textsf{FeatLLM} is moving the LLM's role from inference-time prediction to training-time feature generation. In traditional few-shot tabular learning, an LLM might be prompted with a row of data and asked to output a class label. \textsf{FeatLLM} changes this dynamic by instructing the LLM to analyze the dataset schema and a few labeled examples to deduce the underlying logic or "rules" that define each class. For instance, in a medical dataset predicting heart failure, the LLM doesn't just guess the outcome for a patient; it generates specific criteria, such as "If age is greater than 60 and cholesterol is high, then risk is elevated." These rules are then parsed into program code to create new binary features that indicate whether a sample satisfies specific conditions.

This architectural change offers immediate practical benefits regarding speed and cost. Once the LLM has generated these rules and transformed the raw data into a set of binary features, the actual prediction task is handed off to a simple downstream machine learning model, such as linear regression. This means that at inference time, when you need to predict the outcome for thousands of new rows, you do not need to send any queries back to the LLM. The heavy lifting of reasoning happens once during the feature engineering phase, allowing for near-instant predictions using lightweight models that require minimal computational resources.

The framework employs a structured prompting strategy to ensure high-quality rule generation. The process is divided into two distinct reasoning steps within the prompt. First, the LLM is asked to infer causal relationships or tendencies between features and the target variable based on its internal prior knowledge, without looking at specific examples yet. This step leverages the model's vast pre-training on domain-specific text to identify relevant factors before seeing data biases. Second, using these inferred relationships alongside few-shot examples provided in the prompt, the LLM derives decisive rules for each class. To handle noise and variability in how an LLM might phrase these rules (e.g., using "greater than" instead of ">"), \textsf{FeatLLM} uses another round of prompting where the LLM itself converts its natural language rules into executable Python code. This code is then run against the dataset to generate clean binary features.

To further enhance robustness and overcome prompt size limitations inherent in large tabular datasets, \textsf{FeatLLM} utilizes an ensemble approach with feature bagging. Since generating rules can be stochastic and prompt windows are finite, the system repeatedly generates rule sets by randomizing subsets of features and training samples. It then aggregates these multiple rule sets into a single predictive model by averaging their outputs. This technique ensures that even if one set of generated rules contains errors or misses certain patterns due to prompt constraints, other trials will likely capture them correctly. The final model learns weights for each generated rule via cross-entropy loss on a small set of labeled data, effectively filtering out spurious correlations and focusing on the most predictive criteria discovered by the AI engineer.

Experimental results across 13 diverse tabular datasets demonstrate that this approach significantly outperforms existing baselines in low-shot regimes. \textsf{FeatLLM} consistently achieves higher accuracy than direct in-context learning methods and other specialized tabular models like TabLLM or STUNT, often surpassing them by an average margin of 10\%. Crucially, it maintains this performance even on datasets with over 100 attributes where other LLM-based methods fail due to context window saturation. By decoupling feature engineering from prediction inference, \textsf{FeatLLM} proves that we can leverage the reasoning capabilities of Large Language Models without paying their steep inference costs for every single prediction we make.



# Few-Shot Learning Revolution: Beating Complex Models with Just a Few Examples

In the realm of data science, one of the most persistent challenges is the scarcity of labeled data. Traditional machine learning models often require thousands of examples to learn robust patterns, yet in critical domains like healthcare or finance, obtaining such large, annotated datasets is expensive and sometimes impossible. This is where few-shot learning becomes essential. A recent breakthrough in this area comes from a framework called \textsf{FeatLLM}, which demonstrates that we can achieve high-accuracy predictions on complex tabular tasks using only a handful of training examples. By shifting the role of Large Language Models (LLMs) from direct predictors to expert feature engineers, \textsf{FeatLLM} outperforms both traditional deep learning baselines and other LLM-based approaches while maintaining low inference costs.

The core innovation of \textsf{FeatLLM} lies in how it utilizes the vast prior knowledge embedded within LLMs. Instead of feeding raw tabular data into an LLM to get a direct prediction for every single new sample—a process that is computationally expensive and limited by prompt size constraints—\textsf{FeatLLM} asks the LLM to act as a feature engineer. The model is prompted to analyze the task description and a few example demonstrations to infer the underlying "criteria" or rules that distinguish different classes. For instance, in a disease diagnosis task, rather than asking the LLM "Does this patient have heart failure?", the system asks it to generate rules like "If age is greater than 60 and cholesterol levels are high, then heart failure is likely." These natural language rules are then parsed into executable code to create new binary features for the dataset.

Once these rule-based features are generated, they replace or augment the original data columns. The framework then employs a remarkably simple downstream machine learning model, such as linear regression with non-negative weights, to estimate class probabilities. The probability $p$ for a given class $k$ is calculated by taking the dot product of the learned weights $\mathbf{w}_k$ and the binary feature vector $\mathbf{z}_k^i$ representing whether the sample satisfies each rule, followed by a softmax operation:
$$ \text{logit}_k^i = \max(\mathbf{w}_k, 0) \cdot \mathbf{z}_k^i $$
$$ \mathbf{p}^i = \text{Softmax}([\text{logit}_{1}^i, ..., \text{logit}_{c}^i]) $$
This separation of concerns allows the complex reasoning capabilities of the LLM to be leveraged during a one-time feature generation phase, while the actual inference on new data points relies on a lightweight model that does not require querying an API for every sample. This design significantly reduces latency and operational costs compared to end-to-end LLM prediction methods.

To ensure robustness and handle datasets with many features that might exceed standard prompt limits, \textsf{FeatLLM} incorporates an ensemble approach with bagging. The system repeatedly generates sets of rules by varying the few-shot examples and introducing randomness in the generation process (via temperature settings). It then trains multiple simple models on these diverse feature sets and averages their predictions. This strategy not only mitigates the risk of spurious correlations but also effectively manages prompt size limitations by processing subsets of features or instances at a time. Experimental results across 13 diverse datasets show that this approach consistently outperforms strong baselines like TabLLM and STUNT, achieving an average improvement of 10% in performance metrics such as AUC in low-shot regimes.

The implications for real-world applications are profound. In scenarios where labeled data is scarce but domain knowledge exists—such as predicting credit risk or diagnosing rare diseases—\textsf{FeatLLM} offers a viable path forward without needing massive fine-tuning datasets or access to proprietary model weights. By converting an LLM's semantic understanding into structured decision rules, it bridges the gap between human-like reasoning and efficient algorithmic execution. As demonstrated by its ability to filter out irrelevant features even when spurious correlations are introduced, this framework provides not just higher accuracy but also greater reliability in data-scarce environments.



# Solving the Context Window Crisis: How Bagging Makes LLMs Work with Massive Datasets

One of the most significant hurdles in applying Large Language Models (LLMs) to tabular data is the context window limit. LLMs process information by converting data into text prompts, but these prompts have a strict maximum length. When dealing with real-world spreadsheets that contain hundreds of columns or thousands of rows, serializing the entire dataset often exceeds this limit, rendering standard LLM-based approaches infeasible or causing a sharp decline in performance. The recent paper "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning" introduces a novel framework called \textsf{FeatLLM} that addresses this bottleneck not by shrinking the data, but by strategically breaking it down using a technique known as bagging.

Traditional LLM-based tabular learning methods often attempt to feed the entire dataset or a large subset of features into the model for every single prediction. This approach is computationally expensive and hits a hard wall when the number of features grows. \textsf{FeatLLM} takes a different path by redefining the role of the LLM from a direct predictor to an automated feature engineer. Instead of asking the model to predict an outcome for a specific row, \textsf{FeatLLM} asks the model to generate logical rules that describe how features relate to the target class. For example, rather than predicting if a patient has heart failure directly, the LLM might generate a rule stating that "if age is greater than 60 and cholesterol is high, then risk is elevated." These rules are then converted into binary features and fed into a simple downstream machine learning model, such as linear regression, which handles the final prediction without needing further LLM interaction.

The core innovation that allows \textsf{FeatLLM} to handle massive datasets lies in its use of bagging and ensembling to mitigate prompt size constraints. When a dataset has too many features to fit into a single prompt, \textsf{FeatLLM} does not try to force them all in at once. Instead, it repeatedly samples subsets of features and training instances to create multiple smaller, manageable prompts. In each iteration, or "trial," the LLM generates a set of rules based on this specific subset of data. Because the sampling process introduces randomness—such as shuffling the order of examples or selecting different feature combinations—the LLM produces diverse sets of rules across different trials. This diversity is crucial; while one trial might miss an important relationship due to limited context, another trial with a different subset might capture it perfectly.

Once multiple sets of rules are generated across these trials, \textsf{FeatLLM} combines them through an ensemble method. The binary features derived from all generated rules are aggregated, and their importance is learned by training simple weights on them using cross-entropy loss. This ensemble approach effectively nullifies the impact of incomplete feature coverage in any single trial. If one rule set fails to capture a specific pattern because that feature was excluded from its prompt subset, other rule sets generated from different subsets can compensate for this gap. The result is a robust predictive model that leverages the collective knowledge extracted from many partial views of the data, rather than relying on a single, potentially incomplete view.

This strategy offers distinct advantages over existing methods that require fine-tuning or end-to-end inference for every sample. By shifting the heavy lifting to an offline feature generation phase that utilizes bagging, \textsf{FeatLLM} eliminates the need to query the LLM for every new data point during inference time. This drastically reduces latency and computational costs while overcoming the prompt size limitations that plague other approaches on wide tables with over 100 attributes. Experiments across 13 diverse datasets demonstrate that this method significantly outperforms alternatives like TabLLM and STUNT, achieving high accuracy even in low-shot regimes where labeled data is scarce. Ultimately, \textsf{FeatLLM} proves that by treating LLMs as rule-generating engines and employing smart ensemble techniques, we can unlock their potential for complex tabular tasks without being held back by context window constraints.



# From Black Box to White Box: Why Rule-Based AI is Better for Business Decisions

In the high-stakes worlds of healthcare and finance, a prediction is only as valuable as the trust placed in it. Traditional machine learning models, particularly deep neural networks, often operate as "black boxes," producing accurate outputs without revealing the logic behind them. This opacity poses a significant risk when decisions affect human lives or financial stability. A recent breakthrough in few-shot tabular learning, known as \textsf{FeatLLM}, offers a compelling alternative by shifting the role of Large Language Models (LLMs) from opaque predictors to transparent feature engineers. Instead of simply guessing an outcome, \textsf{FeatLLM} generates explicit, human-readable rules that explain *why* a decision was made.

## The Problem with Opaque Predictions

Standard approaches to tabular learning using LLMs often treat the model as an end-to-end predictor. In these setups, data is serialized into text and fed into the LLM to generate a direct classification for each sample. While effective in some scenarios, this method requires querying the LLM for every single prediction, which is computationally expensive and slow. More critically, it offers little insight into the decision-making process. If a model denies a loan application or flags a patient for heart failure, stakeholders need to know the specific criteria that triggered that result. Without this transparency, it is difficult to audit models for bias or errors, making them risky for regulatory compliance in critical industries.

## How FeatLLM Turns AI into an Expert Feature Engineer

\textsf{FeatLLM} reimagines the workflow by assigning the LLM the role of an expert feature engineer rather than a final judge. The framework leverages the LLM's vast prior knowledge and reasoning capabilities to analyze a small set of labeled examples and infer the underlying criteria for different classes. Instead of outputting a final label, the LLM generates a set of logical rules that define those classes.

For instance, in a medical context predicting chronic heart failure, the LLM might deduce rules such as: "If age is greater than 60 AND cholesterol level exceeds 200 mg/dL." These rules are not just text; they are parsed into executable program code to create new binary features for each data point. A sample either satisfies a rule (1) or does not (0). This transformation effectively converts complex tabular data into a set of interpretable conditions derived from both domain knowledge and the specific data provided.

## Building Trust Through Interpretability and Robustness

The primary advantage of this rule-based approach is interpretability. Because the model relies on explicit "if-then" conditions generated by the LLM, businesses can inspect exactly which factors influenced a prediction. This transparency is crucial for building trust with regulators and end-users. If a rule seems counterintuitive or biased, it can be identified and corrected before deployment, something that is nearly impossible with standard neural network weights.

Furthermore, this structured reasoning process helps filter out spurious correlations—a common pitfall in few-shot learning where models latch onto irrelevant patterns due to limited data. \textsf{FeatLLM} employs a two-step reasoning instruction: first inferring causal relationships based on general knowledge without looking at specific examples, and then refining those relationships using few-shot demonstrations. This forces the model to focus on meaningful features rather than noise. Experiments showed that when irrelevant columns were added to datasets to simulate noise, \textsf{FeatLLM} maintained its performance significantly better than baselines because it rarely generated rules based on those noisy columns (often less than 1-2% of total rules).

## Efficiency Without Sacrificing Accuracy

Beyond transparency, \textsf{FeatLLM} addresses practical deployment challenges. Once the rules are generated and converted into binary features during a one-time training phase, inference does not require querying the LLM again. The system uses a simple downstream machine learning model, such as linear regression with non-negative weights ($\mathbf{w}_k$), to estimate class probabilities based on how many rules each sample satisfies:

$$ \text{logit}_k^i = \max(\mathbf{w}_k, 0) \cdot \mathbf{z}_k^i $$

Here, $\mathbf{z}_k^i$ represents the binary features indicating rule satisfaction for class $k$. This architecture drastically reduces inference latency and cost compared to methods that require an LLM call for every prediction. Additionally, by using an ensemble approach with bagging—generating multiple sets of rules across different trials—the framework mitigates prompt size limitations and improves robustness against incorrect rule generation in any single trial.

## Conclusion: A New Standard for Business AI

The shift from black-box prediction to white-box rule generation represents a significant step forward for applying AI in business-critical domains. \textsf{FeatLLM} demonstrates that we do not need to choose between high performance in low-data regimes and interpretability; we can have both by leveraging LLMs as intelligent feature engineers rather than just predictors. By generating explicit criteria that align with human logic and filtering out noise through structured reasoning, this approach offers a trustworthy foundation for automated decision-making in healthcare, finance, and beyond. As organizations strive to deploy AI responsibly, frameworks that prioritize explainability alongside accuracy will become essential tools for success.

# Why Your AI Models Are Still Too Slow: How FlashAttention-3 Unlocks H100 Performance

If you have spent any time training or running Large Language Models (LLMs) recently, you know that the attention mechanism is the primary bottleneck. As the context window grows to handle long documents, codebases, or video streams, the quadratic scaling of self-attention means that compute time explodes. While the original \textsc{FlashAttention} revolutionized this space by fusing operations to minimize slow global memory access, its successor, \textsc{FlashAttention-2}, still left a massive amount of performance on the table. On the latest NVIDIA H100 GPUs, \textsc{FlashAttention-2} achieved only about 35% utilization of the hardware's theoretical peak. Enter \textsc{FlashAttention-3}, a new algorithm designed specifically to exploit the unique asynchronous capabilities and low-precision features of Hopper architecture, pushing utilization up to 75% and delivering speedups of 1.5$\times$ to 2.0$\times$.

The fundamental limitation of previous approaches was their reliance on a synchronous execution model. Modern GPUs like the H100 are built on asynchrony: they possess dedicated hardware units like Tensor Cores for matrix multiplication and Tensor Memory Accelerators (TMA) for data movement that operate independently of the general-purpose CUDA cores. Previous algorithms treated these resources sequentially, forcing the GPU to wait for one task to finish before starting the next. \textsc{FlashAttention-3} changes this paradigm by introducing warp-specialization and aggressive pipelining. Instead of a monolithic kernel where every thread does everything in lockstep, the algorithm splits responsibilities among different groups of threads (warps). Some warps act as "producers," exclusively handling data movement from global memory to shared memory via TMA, while others act as "consumers," exclusively performing computations using Tensor Cores. This separation allows data loading and computation to happen simultaneously, effectively hiding latency that used to stall progress.

Beyond simply overlapping data movement with computation, \textsc{FlashAttention-3} tackles the specific inefficiencies caused by non-matrix operations like softmax. Softmax involves floating-point multiply-adds and transcendental functions like exponentials, which have significantly lower throughput than matrix multiplications on modern hardware. In a naive pipeline, these operations create idle cycles where powerful Tensor Cores sit waiting for softmax results. The new algorithm solves this by interleaving block-wise GEMM (General Matrix Multiply) and softmax operations asynchronously. By using a "pingpong" scheduling strategy between warpgroups, while one group computes softmax on a block of scores, another group is already crunching numbers on the next block in an asynchronous proxy. This ensures that whenever a high-throughput unit is busy with GEMM, a low-throughput unit is busy with softmax, maximizing overall resource utilization without stalling dependencies.

Another critical innovation in \textsc{FlashAttention-3} is its native support for FP8 low-precision arithmetic, which is crucial for achieving exascale speeds without sacrificing too much accuracy. The Hopper architecture features specialized FP8 Tensor Cores that offer roughly double the throughput of FP16 units. However, implementing FP8 attention is tricky because strict memory layout constraints require operands to be "k-major" (contiguous in the inner dimension), whereas standard attention implementations often use "mn-major" layouts. Furthermore, mixing FP8 operands with FP32 accumulators introduces complexity regarding how data is stored in registers versus shared memory. \textsc{FlashAttention-3} addresses these hurdles by implementing in-kernel transposes using efficient LDSM/STSM instructions and employing byte-permute operations to align register layouts perfectly for dependent GEMMs without costly intermediate copies.

Of course, dropping precision from FP16 to FP8 usually invites numerical instability, particularly when dealing with outlier values common in LLM activations which can skew quantization scales dramatically if handled poorly. Standard per-tensor quantization keeps only one scalar multiplier per entire tensor, meaning extreme outliers dominate the scale factor and crush smaller but important values into noise. To counteract this, \textsc{FlashAttention-3} employs two sophisticated techniques: block quantization and incoherent processing. Block quantization assigns a unique scaling factor to smaller chunks of data rather than one giant tensor average; since our algorithm already processes data in blocks naturally, this adds almost zero overhead while drastically improving fidelity for outliers. Additionally, we introduce incoherent processing by multiplying queries and keys by a random orthogonal matrix before quantization. This rotation spreads out outlier magnitudes across many elements ("spreading"), ensuring that no single element dominates the quantization range and preserving accuracy during compression experiments show this reduces numerical error by up to 2.6$\times$ compared to baseline FP8 attention methods that lack these safeguards.

The empirical results speak loudly about what these architectural shifts enable on real hardware benchmarks conducted on H100 SXM5 GPUs using PyTorch primitives like CUTLASS and TMA abstractions. For FP16 forward passes with head dimensions ranging from 64 to 256 and sequence lengths up to 16k tokens, \textsc{FlashAttention-3} consistently delivers 1.5$\times$ to 2.0$\times$ speedups over \textsc{FlashAttention-2}. # The Art of Doing Nothing: Mastering Asynchrony and Warp-Specialization in Deep Learning

If you have spent any time training large language models, you know that the attention mechanism is the primary bottleneck. While Transformers have revolutionized AI, the self-attention layer scales quadratically with sequence length, turning massive computations into a traffic jam on your GPU. Previous solutions like FlashAttention-2 were game-changers, but they left a significant amount of performance on the table, achieving only about 35% utilization on modern NVIDIA H100 GPUs. Enter FlashAttention-3, a breakthrough that doesn't just optimize code—it fundamentally reimagines how we think about GPU execution by embracing asynchrony and separating duties among hardware units.

At the heart of FlashAttention-3 lies a concept that sounds counterintuitive: doing nothing to go faster. Modern GPUs are designed to hide latency by running many things simultaneously. However, traditional kernels often force everything to happen in strict lockstep. FlashAttention-3 breaks this deadlock using **warp-specialization**. Instead of having every group of threads (warps) try to do everything—loading data, calculating matrix multiplications, and applying softmax—the algorithm splits the team into distinct roles. Some warps become "producers," responsible solely for fetching data from global memory (HBM) into fast shared memory using the Tensor Memory Accelerator (TMA). Others become "consumers," tasked exclusively with crunching numbers using Tensor Cores via WGMMA instructions. By dedicating specific warps to specific jobs, the system avoids stalls where a thread waiting for data holds up a thread ready to compute.

This separation enables a powerful technique known as **producer-consumer asynchrony**. Because TMA loads and Tensor Core calculations are asynchronous hardware units, they do not block each other unless explicitly told to synchronize. In FlashAttention-3, once a producer warp finishes loading a block of Key and Value matrices into shared memory, it immediately signals the consumer warps and moves on to fetch the next block without waiting for the consumer to finish its current calculation. This effectively hides the memory latency entirely; while one set of warps is busy reading data from slow DRAM, another set is already hammering away at matrix multiplications on fresh data sitting in fast cache. The result is a continuous pipeline where the GPU never sits idle waiting for data transfers to complete.

But what happens when the computation isn't just matrix multiplication? Softmax operations involve transcendental functions like exponentials, which run on different hardware units with significantly lower throughput than Tensor Cores. If these operations were done sequentially after every matrix multiply, they would create a massive bottleneck. FlashAttention-3 solves this through **ping-pong scheduling** and intra-warpgroup overlapping. Imagine two teams of workers: Team A calculates a matrix product while Team B performs softma​​x operations on the previous round's results. Once Team A finishes their GEMM (General Matrix Multiply), they signal Team B to switch roles: Team A starts working on softmax while Team B grabs new data and starts their GEMM calculation for the next block.

This "ping-pong" effect ensures that while one group is stuck doing slower exponential calculations required for normalization, another group is utilizing the full horsepower of the Tensor Cores for matrix multiplication. Furthermore, within a single warpgroup, FlashAttention-3 implements a two-stage pipeline where it overlaps GEMMs from iteration $j$ with softmax operations from iteration $j+1$. By maintaining temporary buffers in registers (like storing `S_next` alongside `S_cur`), the algorithm decouples sequential dependencies that traditionally forced serial execution. This architectural dance allows non-matmul operations like exp() and log() to be completely hidden underneath heavier GEMM tasks, pushing utilization rates up to 75% for FP16 and approaching theoretical limits for FP8.

Of course, raw speed means little if accuracy suffers, especially when pushing hardware into low-precision modes like FP8 to double throughput. Standard per-tensor quantization often fails because Large Language Models contain outlier values that skew scaling factors across entire tensors. FlashAttention-3 addresses this with **block quantization** and **incoherent processing**. Block quantization divides tensors into smaller chunks and applies unique scaling factors to each block rather than treating the whole tensor as one unit, drastically reducing precision loss caused by outliers. Additionally, it employs incoherent processing by multiplying Query and Key matrices by a random orthogonal matrix before quantization. This spreads out extreme values across many entries ("spreading out" outliers), making them easier to represent accurately in low precision without changing the final mathematical result since $\mathbf{Q}\mathbf{K}^\top = (\mathbf{QM})(\mathbf{KM})^\top$. These techniques ensure that FP8 FlashAttention-3 achieves 2.6$\times$ lower numerical error compared to standard baselines while delivering speeds nearing 1.2 PFLOPs/s on H100 GPUs.

The implications of these optimizations are profound for anyone building or deploying large-scale models. By leveraging Hopper-specific features like TMA loads and WGMMA instructions alongside clever software pipelining strategies like warp-specialization and ping-pong scheduling, FlashAttention-3 delivers 1.5$\times$ to 2$\times$ speedups over previous generations in both forward and backward passes. More importantly, it demonstrates that future performance gains won't come merely from adding more silicon or larger chips alone; they will come from smarter software designs that fully utilize existing hardware capabilities through asynchrony and precise task specialization as we push toward even longer contexts and higher precisions efficiently enough!



# FP8 Made Safe: How Block Quantization and Random Rotations Keep Your AI Accurate

The race to build faster Large Language Models (LLMs) has pushed the industry toward lower-precision arithmetic. While FP16 became the standard for years, modern hardware like NVIDIA's Hopper architecture now champions FP8, promising roughly double the throughput for the same power and silicon area. However, this leap comes with a catch: reducing bit-width from 16 to 8 increases the risk of numerical errors, particularly when dealing with "outlier" values—rare but massive numbers that frequently appear in neural network activations. If not handled correctly, these outliers can cause catastrophic quantization errors, degrading model intelligence despite the speed gains. Enter FlashAttention-3, a new algorithm that solves this dilemma through two ingenious techniques: block quantization and incoherent processing.

At its core, standard attention mechanisms suffer from quadratic scaling with sequence length, making them the primary bottleneck for long-context applications. Previous optimizations like FlashAttention-2 successfully reduced memory traffic by fusing operations into single GPU kernels, yet they still struggled to fully utilize the asynchronous capabilities of modern Tensor Cores. FlashAttention-3 addresses this by leveraging hardware asynchrony to overlap computation and data movement, but its most critical innovation lies in how it handles low-precision math safely. Instead of applying a single scaling factor to an entire tensor—a method known as per-tensor quantization—the authors introduce **block quantization**. This technique splits tensors into smaller blocks and assigns a unique scaling scalar to each block. Because outliers are often localized rather than uniformly distributed across a whole layer, giving each block its own scale prevents large values from forcing the entire block into a low-resolution range where subtle details would be lost.

While block quantization manages local variations effectively, it does not fully solve the problem of extreme outliers dominating the dynamic range of a specific block. To tackle this head-on, FlashAttention-3 employs **incoherent processing**, which involves multiplying the Query ($\mathbf{Q}$) and Key ($\mathbf{K}$) matrices by a random orthogonal matrix $\mathbf{M}$ before quantization occurs. Mathematically, because $\mathbf{M}$ is orthogonal ($\mathbf{M}\mathbf{M}^\top = I$), multiplying both sides preserves the final dot-product result exactly: $(\mathbf{Q}\mathbf{M})(\mathbf{K}\mathbf{M})^\top = \mathbf{Q}\mathbf{K}^\top$. However, computationally, this rotation acts as a diffusion process. By mixing all entries of $\mathbf{Q}$ and $\mathbf{K}$ together randomly before quantization, any single massive outlier is spread out across many elements in the transformed vectors. This "smearing" effect ensures that no single element remains excessively large relative to others during the quantization step, significantly reducing rounding errors without altering the mathematical outcome of the attention mechanism.

The combination of these strategies yields remarkable empirical results on H100 GPUs. When tested against standard attention implementations using per-tensor scaling with outlier features simulated via mixed Gaussian distributions, FlashAttention-3 achieved a 2.6$\times$ reduction in numerical error for FP8 operations compared to baselines. Furthermore, by maintaining intermediate calculations in higher precision (like FP32) wherever possible and utilizing these smart preprocessing steps, FP16 FlashAttention-3 matches the accuracy of previous versions while delivering 1.5 to 2.0$\times$ speedups over FlashAttention-2. For FP8 specifically, the system reaches close to 1.2 PFLOPs/s, demonstrating that we no longer have to sacrifice accuracy for raw performance when pushing hardware limits.

Ultimately, FlashAttention-3 proves that hardware acceleration is not just about running existing algorithms faster; it requires rethinking how algorithms interact with physical constraints like memory layout and precision limits. By decoupling scaling factors via block quantization and decorrelating data distributions via random rotations, this work provides a robust blueprint for safe low-precision deep learning. As we move toward even shorter precisions like FP4 on future architectures like Blackwell, these principles will likely remain essential for ensuring that our AI systems remain both fast and reliable enough for production environments.

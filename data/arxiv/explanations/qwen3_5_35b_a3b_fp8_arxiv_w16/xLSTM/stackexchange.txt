\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### How exactly does the sLSTM 'memory mixing' differ from standard RNN hidden-to-hidden connections?
Question:
I am trying to understand the distinction made in Section 2 regarding 'new memory mixing'. The paper mentions that sLSTM has recurrent connections ($\mathbf{R}_{\mathbf{z}}, \mathbf{R}_{\mathbf{i}}, \dots$) from the hidden state vector $\mathbf{h}$ to the memory cell inputs and gates. In standard LSTMs (Equation 3), we already have $r_z h_{t-1}$ terms. What makes the sLSTM's memory mixing 'new' or distinct enough to claim it solves state tracking problems while mLSTM cannot? Is it purely due to the interaction with the exponential gating?
Answer:
The fundamental distinction between the sLSTM's "new memory mixing" and standard RNN hidden-to-hidden connections lies in the combination of **exponential gating** with **multi-cell interaction**, which transforms the nature of information flow from simple state propagation to dynamic, reversible memory editing. While standard LSTMs indeed utilize recurrent weights (such as $r_i h_{t-1}$) to influence gates, these connections merely modulate the magnitude of updates based on the previous hidden state; they do not fundamentally alter the structural capacity of the memory cell itself to handle complex state dependencies. In contrast, the sLSTM introduces a mechanism where multiple scalar memory cells interact through recurrent connections ($\mathbf{R}_{\mathbf{z}}, \mathbf{R}_{\mathbf{i}}, \dots$) specifically designed to leverage the properties of exponential gating. As described in Section 2, this architecture allows for "memory mixing" where the hidden state vector $\mathbf{h}$ mixes information *across* different memory cells within a head. This is distinct from standard LSTMs where, even if multiple cells exist, they often operate independently unless explicitly coupled by a separate projection layer, whereas here the coupling is intrinsic to the gate calculations via exponential functions.

The critical innovation that makes this mixing capable of solving state tracking problems—tasks where mLSTM fails—is the interplay between this mixing and the **exponential activation functions**. Standard LSTMs use sigmoid gates bounded between 0 and 1, which limits their ability to rapidly amplify or suppress signals in a way that supports revisiting and correcting past storage decisions. The sLSTM replaces these with exponential gates (either raw $\exp(\cdot)$ or stabilized versions), allowing for arbitrarily large values that facilitate rapid information growth or decay. When combined with memory mixing, this creates a system where information can be dynamically redistributed across multiple scalar cells to form complex representations that evolve over time. The paper explicitly notes in Section 2 and Section 4 that models lacking this specific type of mixing (like mLSTM or pure State Space Models) struggle with formal language tasks requiring state tracking, such as parity checks or entity tracking in narratives. The authors argue that while mLSTM offers massive storage capacity via matrix memory, it lacks the "state tracking" capability because it removes hidden-to-hidden connections entirely to ensure parallelizability. Conversely, sLSTM retains these connections but enhances them exponentially; this allows it to solve tasks that require maintaining a running count or status variable over long sequences, effectively bridging the gap between the expressiveness of traditional RNNs and the scalability of modern architectures. Thus, the "newness" is not just in adding more weights, but in creating a feedback loop where exponential gating amplifies the utility of cross-cell communication, enabling the model to revise storage decisions and track states that standard gated RNNs cannot resolve efficiently.

### Is the normalizer state $n_t$ in sLSTM mathematically equivalent to a running average of input gates?
Question:
Looking at Equation 4 for sLSTM, the normalizer state is defined as $n_t = f_t n_{t-1} + i_t$. If we expand this recursively, it looks like a weighted sum of all previous input gates, where the weights are products of subsequent forget gates. Does this effectively act as a cumulative count of 'active' input events over time? If so, why is division by this scalar necessary to prevent saturation when using exponential gating instead of sigmoid?
Answer:
Yes, the normalizer state $n_t$ in the sLSTM is mathematically equivalent to a running weighted average (specifically, a cumulative weighted sum) of all previous input gates, where the weighting factor for each past input depends on the product of all subsequent forget gates. By expanding the recursive definition provided in Equation 4 ($n_t = f_t n_{t-1} + i_t$), we can trace the contribution of any past input gate $i_\tau$ at time step $\tau < t$. Its influence on the current normalizer $n_t$ is determined by multiplying $i_\tau$ by every forget gate encountered from time $\tau+1$ up to $t$. Mathematically, this expansion reveals that $n_t = i_t + f_t i_{t-1} + f_t f_{t-1} i_{t-2} + \dots + \left(\prod_{k=\tau+1}^t f_k\right) i_\tau$. This confirms your intuition that $n_t$ acts as a cumulative count of active input events, where the "weight" of an event decays exponentially if the forget gates are small or remains significant if they are near unity.

However, interpreting this strictly as a "count" requires care regarding the nature of the gates themselves. In standard LSTMs, gates are bounded between 0 and 1 by the sigmoid function, ensuring stability. In xLSTM, however, the authors introduce **exponential gating**, where gates are computed as exponentials of linear combinations (e.g., $i_t = \exp(\tilde{i}_t)$). Without constraints, these exponential values can grow arbitrarily large. If we simply summed these raw exponential values over a long sequence without normalization, the resulting magnitude would explode rapidly because each term adds a potentially massive value rather than a probability-like fraction. This is precisely why division by $n_t$ is necessary in Equation 4 to compute the hidden state $\tilde{h}_t = c_t / n_t$.

The division serves as a crucial stabilizing mechanism that prevents saturation and overflow. When using exponential activations for both input and forget gates, the cell state update rule becomes dominated by multiplicative factors that can easily exceed numerical limits (overflows) or become infinitesimally small (underflows). By dividing the accumulated cell content $c_t$ by the normalizer $n_t$, which accumulates exactly the same multiplicative history as the contributions to $c_t$, the system effectively computes a **weighted average** rather than a raw sum. This normalization ensures that even if individual gate values are huge due to exponential activation, their relative proportions remain stable and interpretable. It transforms an unstable accumulation into a bounded quantity that represents the effective concentration of information stored in memory. Consequently, this allows xLSTM to leverage expressive exponential gating—essential for solving tasks requiring precise revision of storage decisions—without suffering from numerical instability or saturation issues inherent to naive exponential summation over long sequences.

### Does the covariance update rule in mLSTM imply that the model implicitly implements a form of attention without explicit token-token interactions?
Question:
The mLSTM uses a matrix memory updated via $\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top$. When retrieving, it computes $\tilde{\mathbf{h}}_t = \mathbf{C}_t \mathbf{q}_t$. This looks like a dot-product similarity search where all past $(\mathbf{k}, \mathbf{v})$ pairs are summed into $\mathbf{C}$. Why does this avoid the quadratic complexity of Self-Attention? Specifically, if I have a sequence length $T$, isn't computing $\sum_{j=1}^T v_j k_j^T q$ still requiring access to all past elements? How is this operation truly linear in $T$ during inference?
Answer:
Your intuition regarding the apparent contradiction between the summation of outer products and linear complexity is astute, yet the resolution lies in distinguishing between *implicit* accumulation and *explicit* interaction. The mLSTM indeed implements a form of associative recall that resembles attention, but it avoids the quadratic complexity of standard self-attention by aggregating all historical information into a single fixed-size matrix $\mathbf{C}_t$ before any retrieval occurs, rather than computing interactions pairwise at every time step.

The core mechanism relies on the covariance update rule defined in the paper: $\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top$. While this equation involves summing terms like $\mathbf{v}_j \mathbf{k}_j^\top$ for all previous steps $j < t$, the critical observation is that these terms are accumulated incrementally into the state $\mathbf{C}_t$. By the time you reach step $t$, the matrix $\mathbf{C}_t$ already contains the complete history of all past key-value pairs, weighted by their respective gates. Consequently, when you retrieve information using $\tilde{\mathbf{h}}_t = \mathbf{C}_t \mathbf{q}_t$, you are not iterating through a list of $T$ items; you are performing a single matrix-vector multiplication between a $d \times d$ matrix and a $d$-dimensional query vector. The cost of this retrieval is strictly proportional to $d^2$, which depends on the model dimension but remains constant regardless of whether the sequence length $T$ is 100 or 100,000.

You asked why this avoids quadratic complexity despite accessing all past elements. In standard self-attention, calculating the score requires comparing every token against every other token (or at least maintaining a growing cache), leading to a memory and computation cost that grows as $O(T^2)$ or $O(T \cdot d)$ depending on implementation details like KV caching. In contrast, mLSTM trades explicit pairwise comparisons for implicit compression. As stated in the "Memory and Speed Considerations" section of the paper, xLSTM networks possess linear computation and constant memory complexity with respect to sequence length. The "access" to all past elements happens during the update phase ($\mathbf{C}_{t-1} \to \mathbf{C}_t$), which takes constant time per step because updating a matrix is independent of how many updates have occurred previously—the history is summarized in the current state. Therefore, while you effectively utilize all past data, you do so without paying a computational penalty that scales with $T$.

Regarding your question about whether this implies an implicit form of attention without explicit token-token interactions: yes, this is precisely correct. The paper notes in related work that mLSTM shares conceptual ground with Linear Transformers and Fast Weight Programmers, which also linearize attention by avoiding direct token-token scoring matrices. However, unlike attention mechanisms that explicitly calculate similarities between specific tokens (e.g., dot products between $\mathbf{k}_i$ and $\mathbf{k}_j$), mLSTM collapses these relationships into a global correlation structure represented by $\mathbf{C}$. It acts as a content-addressable memory where queries retrieve values based on their similarity to stored keys aggregated within the matrix, but it never constructs an explicit $T \times T$ attention map. This allows it to maintain the expressiveness required for tasks like associative recall while retaining the efficiency characteristic of recurrent neural networks.

### What is the precise role of the stabilizer state $m_t$ in preventing numerical overflow with exponential gates?
Question:
In Equation 5, the paper introduces a stabilizer state $m_t = \max(\log(f_t) + m_{t-1}, \log(i_t))$ and defines stabilized gates using subtraction from this max value. Intuitively, this seems like implementing a log-sum-exp trick or shifting for numerical stability. However, since we subtract $m_t$, doesn't this just shift all probabilities down uniformly? How does ensuring bounded values here actually help with *training* convergence compared to simply clipping values or using softplus activations initially?
Answer:
The stabilizer state $m_t$ serves a critical role in preventing numerical overflow and underflow during the backward pass, which is essential for stable training convergence, rather than merely acting as a uniform probability shifter. While it is true that subtracting $m_t$ shifts the exponentiated values uniformly—preserving the relative ratios between gates—the primary danger addressed by this mechanism is the explosion of intermediate values in the logarithmic domain or the catastrophic underflow to zero when converting back to linear space without proper bounds.

In the context of exponential gating defined in Equation 5, the raw gate values are computed as $\exp(\tilde{i}_t)$ and $\exp(\tilde{f}_t)$. If the pre-activation values $\tilde{i}_t$ or $\tilde{f}_t$ become large positive numbers during early training phases or due to unstable gradients, these exponentials can exceed floating-point limits (overflow), resulting in NaNs that crash training. Conversely, if they are large negative numbers, the values vanish to zero (underflow), causing gradients to disappear entirely. The stabilizer state $m_t = \max(\log(f_t) + m_{t-1}, \log(i_t))$ effectively tracks the running maximum of these accumulated log-gates over time steps. By defining the stabilized gates as $i'_t = \exp(\log(i_t) - m_t)$ and $f'_t = \exp(\log(f_t) + m_{t-1} - m_t)$, the authors ensure that at least one of the exponents inside every time step calculation is exactly zero (since $m_t$ is derived from a max operation involving those exact terms). This guarantees that no single gate term exceeds 1.0 before being multiplied into the cell state update, keeping all intermediate activations within a safe numerical range ($[0, 1]$).

This approach differs significantly from simple clipping or initial softplus activations because it preserves the exact mathematical equivalence of the network while allowing gradients to flow correctly through extremely long sequences. As noted in Section 2.2 regarding sLSTM, replacing $f_t$ with $f'_t$ and $i_t$ with $i'_t$ "does neither change the output of the whole network nor the derivatives of the loss." Clipping values arbitrarily alters these derivatives by introducing discontinuities or hard boundaries that distort the optimization landscape, often leading to poor convergence or getting stuck in local minima. Softplus activations at initialization help prevent immediate crashes but do not adapt dynamically to the cumulative magnitude of gates over thousands of time steps; if a sequence accumulates enough small updates to push a gate into an extreme range later in training, softplus alone offers no protection against subsequent overflow. The stabilizer state acts as a dynamic normalization factor specifically tailored to the recurrent nature of LSTMs, ensuring that even if raw logits grow indefinitely, their contribution to memory updates remains numerically stable and mathematically identical to their un-stabilized counterparts (up to machine precision). Consequently, this enables xLSTM to leverage exponential gating—which provides superior expressivity for revising storage decisions—as described in Section 2—and handle long-range dependencies without succumbing to numerical instability that would otherwise halt training convergence.

### If mLSTM is fully parallelizable, why does its wall-clock time suffer compared to FlashAttention despite theoretical speedups?
Question:
Section 3 claims mLSTM is fully parallelizable and comparable to FlashAttention. However, Section 6 (Limitations) admits that current CUDA kernels are 'about 4 times slower than FlashAttention' because they aren't optimized yet. But beyond engineering optimization issues, isn't updating a dense $d \times d$ matrix every timestep inherently more expensive than scanning linear states (like in Mamba)? Does the $O(d^2)$ per-step cost become a bottleneck for very large dimensions even with perfect parallelization?
Answer:
The apparent contradiction between mLSTM's theoretical parallelizability and its observed wall-clock latency stems from the distinction between algorithmic scalability (parallelism) and hardware-level computational intensity. While the authors explicitly state in Section 3 and Section 5 that mLSTM is fully parallelizable—unlike sLSTM, which requires sequential updates due to memory mixing—their admission in the Limitations section regarding the four-fold slowdown relative to FlashAttention highlights that "parallelizable" refers to the absence of sequential dependencies, not necessarily raw arithmetic efficiency per operation.

The core issue lies in the fundamental difference in computational density between mLSTM and linear state-space models like Mamba or attention mechanisms optimized by FlashAttention. As described in Section 3, mLSTM maintains a matrix memory $\mathbf{C}_t \in \mathbb{R}^{d \times d}$ updated via a covariance rule involving outer products ($\mathbf{v}_t \mathbf{k}_t^\top$). Consequently, at every single time step, the model must perform dense matrix additions and multiplications of size $d \times d$. This imposes an $O(d^2)$ computational cost per step for the memory update alone. In contrast, models like Mamba operate on state vectors of size $d$, resulting in an $O(d)$ or effectively $O(d)$ per step complexity for state transitions (often implemented as linear scans). Even though mLSTM operations can be executed in parallel across batches or dimensions using standard matrix libraries (BLAS), the sheer volume of floating-point operations required to manipulate these $d \times d$ matrices creates a significant arithmetic bottleneck that scales quadratically with dimensionality.

Furthermore, the authors clarify that this performance gap is currently exacerbated by engineering factors rather than just theoretical limits. They note that their CUDA kernels are not yet optimized to the same degree as FlashAttention or Mamba's specialized scan implementations. FlashAttention relies on tiling strategies and IO-aware algorithms specifically designed to minimize memory bandwidth usage and maximize tensor core utilization for attention patterns. Similarly, Mamba utilizes a custom fused kernel for its selective scan mechanism. The mLSTM implementation described in the paper relies on standard matrix operations which, while mathematically correct and parallelizable, may not exploit GPU memory hierarchies as efficiently as these highly tuned alternatives. Therefore, even if you eliminate all sequential bottlenecks by making the recurrence parallel, the intrinsic $O(d^2)$ nature of updating a full covariance matrix ensures that for large dimensions $d$, the operation count remains significantly higher than scanning linear states, leading to slower wall-clock times until dedicated kernel optimizations bridge this gap.

### How does xLSTM reconcile the conflicting requirements of 'state tracking' (requiring recurrence) and 'parallelizability' (required for efficiency)?
Question:
The abstract highlights that xLSTM combines sLSTM (with memory mixing/state tracking) and mLSTM (fully parallelizable). The paper states that sLSTM is not parallelizable due to hidden-hidden connections. Yet, they stack them into an architecture (xLSTM[$a:b$]). If sLSTM blocks must run sequentially over time steps internally, how does stacking them alongside parallel mLSTM blocks affect overall training throughput? Is there a hybrid strategy where only certain layers use sLSTM while others remain parallel?
Answer:
The xLSTM architecture reconciles the conflict between state tracking and parallelizability through a strategic hybrid design that assigns distinct roles to its two component blocks: sLSTM and mLSTM. As explicitly stated in the paper, sLSTM incorporates memory mixing via hidden-hidden recurrent connections, which creates a dependency chain requiring sequential processing over time steps. Consequently, sLSTM cannot be parallelized along the sequence dimension in the same manner as Transformers or standard feed-forward networks. However, mLSTM abandons this memory mixing mechanism entirely, utilizing a matrix-valued memory updated via a covariance rule instead. This structural change renders mLSTM fully parallelizable with respect to sequence length, allowing it to leverage modern GPU hardware efficiently just like attention mechanisms.

The resolution lies in how these blocks are stacked within the overall network depth rather than attempting to parallelize the internal recurrence of every single layer. The authors propose an architecture denoted as $\text{xLSTM}[a:b]$, where $a$ represents the number of mLSTM-based blocks and $b$ represents the number of sLSTM-based blocks. By reserving sLSTM for specific layers—often deeper ones or those critical for capturing complex temporal dependencies—and filling the rest of the stack with parallelizable mLSTM blocks, the model balances expressiveness with throughput. While the sLSTM layers themselves must execute sequentially over time steps (meaning they introduce a bottleneck relative to pure mLSTM stacks), the paper notes that this is mitigated by implementing highly optimized CUDA kernels specifically designed for sLSTM. Although sLSTM lacks native parallelizability due to its recurrence, these custom kernels ensure that its execution speed is typically less than twice as slow as the fully parallel mLSTM implementation, preventing it from becoming a prohibitive bottleneck in training throughput.

Furthermore, this hybrid approach allows xLSTM to inherit the strengths of both paradigms: the state tracking capability provided by sLSTM's memory mixing (essential for tasks like solving formal languages or revising storage decisions) and the massive scalability and inference speed offered by mLSTM's matrix memory and lack of hidden-hidden connections. The experimental results confirm that this configuration works effectively; for instance, configurations like $\text{xLSTM}[7:1]$ (seven mLSTM blocks and one sLSTM block) outperform pure Transformer baselines on language modeling tasks while maintaining linear scaling properties regarding sequence length. Thus, the architecture does not force a choice between state tracking and parallelism but rather integrates them spatially across layers, ensuring that only a fraction of the network bears the cost of sequential recurrence while the majority benefits from parallel computation.

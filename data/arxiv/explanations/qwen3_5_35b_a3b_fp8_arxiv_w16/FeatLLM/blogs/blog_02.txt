# From Raw Numbers to Smart Rules: How LLMs Automate Feature Engineering

Traditional tabular learning often struggles when data is scarce. In few-shot scenarios, where only a handful of labeled examples exist, models tend to overfit or rely on spurious correlations found purely by chance. While Large Language Models (LLMs) have revolutionized text processing, applying them to tabular data has historically faced hurdles regarding computational cost and prompt length limits. Enter **FeatLLM**, a novel framework that reimagines the role of the LLM. Instead of acting as a direct predictor for every single data point, FeatLLM acts as an automated feature engineer. It leverages the model's vast prior knowledge to distill complex tabular data into high-quality, human-readable decision rules, which are then converted into binary features for a lightweight downstream model.

The core innovation of FeatLLM lies in shifting the paradigm from end-to-end prediction to feature generation. Conventional LLM-based approaches often require sending a query to the model for every single sample at inference time, which is computationally prohibitive and expensive. FeatLLM breaks this cycle by using the LLM solely during the training phase to discover patterns. Once these patterns are identified in the form of logical rules, they become static features. At inference time, a simple linear model processes these new features, eliminating the need for repeated LLM calls and drastically reducing latency while maintaining high accuracy.

The process begins with a carefully structured prompting strategy designed to mimic expert reasoning. The framework guides the LLM through a two-step cognitive process before it ever attempts to solve the specific problem at hand. First, the model analyzes the task description and feature definitions to infer general causal relationships based on its internal knowledge base—for instance, recognizing that "age" might be correlated with certain health risks without looking at specific data points yet. Only in the second step does it incorporate the few available training examples to deduce specific rules that distinguish between classes. This separation ensures that the generated rules are grounded in sound logic rather than coincidental noise in small datasets.

Once these rules are generated in natural language—such as "If Age > 60 AND Cholesterol > High THEN Risk = True"—the system must translate them into numerical inputs for a machine learning algorithm. Since raw text cannot be fed directly into a standard linear regressor or logistic regression model, FeatLLM employs a clever parsing mechanism. It feeds the generated rules back into an LLM with instructions to convert them into executable Python code snippets capable of evaluating any given row of data against those rules. This code is then executed using Python's `exec()` function on the dataset, transforming each rule into a binary feature (either 0 or 1) indicating whether that specific condition holds true for a sample.

With these new binary features constructed, the actual prediction happens via a simple linear model without bias terms but with trainable weights assigned to each feature rule. The equation governing this prediction essentially calculates a weighted sum of satisfied rules for each class:
$$ \text{logit}_k^i = \max(\mathbf{w}_k, 0) \cdot \mathbf{z}_k^i $$
Here, $\mathbf{z}_k^i$ represents the binary vector indicating which rules from class $k$ are met by sample $i$, and $\mathbf{w}_k$ represents the learned importance weights for those rules. By optimizing this model using cross-entropy loss on the few-shot training set, FeatLLM learns which derived rules are truly predictive and which are irrelevant noise effectively filtering out uninformative conditions during training.

To further bolster robustness and overcome limitations related to prompt token sizes in large datasets, FeatLLM integrates an ensemble approach inspired by bagging techniques from random forests. The entire rule-generation pipeline is run multiple times with randomized temperatures and shuffled demonstration orders to encourage diversity in the generated ruleset. The empirical results validate this architecture across thirteen distinct datasets ranging from medical diagnosis (Heart Failure) to financial risk assessment (Credit-g). Across various settings with as few as four training examples per class (4-shot), FeatLLM consistently outperformed established baselines like TabPFN and STUNT by approximately 10% on average AUC scores. Crucially, unlike competing methods such as TabLLM which struggle when serialization causes prompt lengths to explode due to hundreds of columns (e.g., Communities dataset), FeatLLM maintained stable performance thanks to its bagging-enabled scalability.

\title{Stack Exchange of the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

### Clarification on Equation 1: What happens if a rule evaluates to false for all samples?
Question:
Looking at Section 3.2, specifically Equation 1 and the surrounding text, I see that new binary features are generated where $\mathbf{z}_k^i$ is 1 if a sample satisfies a rule for class $k$, and 0 otherwise. If an LLM generates a rule that is logically impossible (e.g., 'Age > 150') or simply never true for any sample in the dataset, that column will be all zeros. Since the model learns weights $\mathbf{w}_k$ via cross-entropy loss, will such a useless feature naturally get assigned a weight of zero, or does it cause numerical instability in the optimization? The paper mentions filtering rules with weights below 0.1, but doesn't discuss handling constant-zero features explicitly.
Answer:
The short answer is that while the paper does not explicitly detail a special-case routine for handling columns of all zeros, such features are naturally handled by the optimization dynamics of the linear model combined with the explicit post-processing step mentioned in the "Quality of features" section. According to Equation~1 in Section~3.2, the logit for a class is computed as $\text{logit}_k^i = \max(\mathbf{w}_k, 0) \cdot \mathbf{z}_k^i$. Here, $\mathbf{z}_k^i$ represents the binary feature vector derived from the LLM-generated rules. If a rule is logically impossible or never satisfied by any sample in the dataset, the corresponding entry in $\mathbf{z}_k^i$ will be zero for every row $i$. Mathematically, this creates a column of zeros in the design matrix. During training via cross-entropy loss, a feature that contributes nothing to distinguishing between classes (because its value is constant across all samples) provides no gradient signal regarding its contribution to reducing error. Consequently, the optimizer (Adam, as noted in Implementation Details) will drive the corresponding weight $w_{k,j}$ toward zero or keep it near zero because changing it offers no improvement to the loss function.

Furthermore, the paper explicitly addresses this scenario through its feature filtering mechanism described in Section~4.2 ("Quality of features generated by FeatLLM"). The authors state that rules with little relevance to the data are "automatically filtered out" after tuning if their learned weights fall below a specific threshold. They specify that this threshold was set at $0.1$. Therefore, even if a constant-zero feature manages to retain a tiny non-zero weight due to numerical noise or regularization effects during training, it will be pruned from the final model during inference because its weight will inevitably remain below this cutoff. This dual mechanism—optimization driving irrelevant weights down and an explicit pruning threshold removing them—ensures that useless features do not cause numerical instability nor degrade performance. The architecture relies on this sparsity induction rather than pre-computation checks for constant columns, which aligns with their goal of keeping the downstream model simple and computationally efficient while leveraging the LLM's generative flexibility.

# Stop Sending Queries to LLMs for Every Prediction: Meet FeatLLM

The integration of Large Language Models (LLMs) into tabular data science has promised a revolution, offering the ability to leverage vast amounts of prior knowledge for tasks like disease prediction or financial risk assessment. However, a critical bottleneck remains: most current approaches treat the LLM as an end-to-end predictor. This means sending a unique query to the model for every single row of data you want to classify. While powerful, this strategy is computationally prohibitive for production environments and struggles when dealing with datasets containing hundreds of features due to prompt length limits. Enter \textsf{FeatLLM}, a novel framework that fundamentally shifts the role of the LLM from a predictor to a feature engineer, decoupling intelligence from inference speed.

Traditional LLM-based tabular learning methods rely on serializing data rows into text prompts and asking the model to infer the answer directly. While effective in theory, this creates a severe scalability issue where inference costs scale linearly with the number of samples. If you have thousands of patients or millions of transactions, you must pay for thousands of separate API calls. Furthermore, as datasets grow in complexity with more columns, these serialized prompts often exceed token limits, causing performance to degrade or become impossible. \textsf{FeatLLM} solves this by changing the workflow entirely: instead of predicting on every sample at inference time, it uses the LLM once during a setup phase to discover high-quality decision rules based on domain knowledge and few-shot examples.

The core innovation of \textsf{FeatLLM} lies in its structured prompting strategy designed to extract "rules" rather than direct answers. The framework guides the LLM through a two-step reasoning process that mimics expert human logic. First, it asks the model to infer general causal relationships between features and targets using its internal priors, independent of specific training examples. Second, it leverages those priors alongside a handful of few-shot examples to derive specific logical conditions—rules—that distinguish between classes. For instance, in a medical context, the LLM might generate a rule stating "If age > 60 AND cholesterol_level > 240 THEN high_risk." These natural language rules are then parsed into executable code using Python's \texttt{exec()} function to transform raw tabular data into new binary features indicating whether each sample satisfies a specific rule.

Once these rule-based binary features are generated, the heavy lifting is done by a simple downstream machine learning model, such as logistic regression or linear classifiers with non-negative weights. During this training phase—which happens only once per task—the model learns how important each rule is for predicting the target class by optimizing cross-entropy loss on the few-shot training set. At inference time, you simply run your new data through these pre-computed binary features and plug them into this lightweight model. There is no need to call an LLM again; you get instant predictions comparable in speed and cost to traditional statistical methods but powered by deep linguistic reasoning derived earlier.

To ensure robustness against noise and instability inherent in generative models, \textsf{FeatLLM} employs an ensemble approach inspired by bagging techniques from classical machine learning literature. Since an LLM's output can vary slightly depending on temperature settings or input ordering, running the rule extraction process multiple times with randomized subsets of features and instances creates diverse sets of rules. The final prediction averages the probabilities from these multiple lightweight models trained on different rule sets. This not only smooths out errors where an individual trial might generate a spurious correlation but also allows the system to handle datasets with massive numbers of features by selecting smaller subsets for each trial, effectively bypassing prompt size limitations entirely.

Empirical evaluations across 13 diverse tabular datasets demonstrate that \textsf{FeatLLM} significantly outperforms existing baselines like TabLLM and STUNT in low-shot regimes, achieving an average improvement of roughly 10%. Crucially, it maintains this performance advantage even when dealing with high-dimensional data where other methods fail due to token constraints. Ablation studies confirm that both the reasoning instructions guiding prior knowledge usage and the ensemble mechanism are vital; removing either leads to noticeable drops in accuracy. Moreover, unlike methods requiring fine-tuning which demand open-source access or expensive hardware resources, \textsf{FeatLLM} operates purely via API calls during its brief training phase and requires zero API overhead thereafter.

By offloading complex reasoning to a one-time feature engineering step and relegating actual prediction to fast linear algebra operations, \textsf{FeatLLM} bridges the gap between advanced AI capabilities and practical deployment requirements. It proves that we don't need to query an expensive brain for every single calculation if we can teach it *how* to think once and let it build better tools for us afterwards. As organizations seek scalable ways to integrate LLMs into real-world analytics pipelines without breaking their budgets or latency SLAs frameworks like \textsf{FeatLLM} offer a compelling blueprint for efficient few-shot tabular learning that prioritizes both accuracy and operational feasibility.



# From Raw Numbers to Smart Rules: How LLMs Automate Feature Engineering

Traditional tabular learning often struggles when data is scarce. In few-shot scenarios, where only a handful of labeled examples exist, models tend to overfit or rely on spurious correlations found purely by chance. While Large Language Models (LLMs) have revolutionized text processing, applying them to tabular data has historically faced hurdles regarding computational cost and prompt length limits. Enter **FeatLLM**, a novel framework that reimagines the role of the LLM. Instead of acting as a direct predictor for every single data point, FeatLLM acts as an automated feature engineer. It leverages the model's vast prior knowledge to distill complex tabular data into high-quality, human-readable decision rules, which are then converted into binary features for a lightweight downstream model.

The core innovation of FeatLLM lies in shifting the paradigm from end-to-end prediction to feature generation. Conventional LLM-based approaches often require sending a query to the model for every single sample at inference time, which is computationally prohibitive and expensive. FeatLLM breaks this cycle by using the LLM solely during the training phase to discover patterns. Once these patterns are identified in the form of logical rules, they become static features. At inference time, a simple linear model processes these new features, eliminating the need for repeated LLM calls and drastically reducing latency while maintaining high accuracy.

The process begins with a carefully structured prompting strategy designed to mimic expert reasoning. The framework guides the LLM through a two-step cognitive process before it ever attempts to solve the specific problem at hand. First, the model analyzes the task description and feature definitions to infer general causal relationships based on its internal knowledge base—for instance, recognizing that "age" might be correlated with certain health risks without looking at specific data points yet. Only in the second step does it incorporate the few available training examples to deduce specific rules that distinguish between classes. This separation ensures that the generated rules are grounded in sound logic rather than coincidental noise in small datasets.

Once these rules are generated in natural language—such as "If Age > 60 AND Cholesterol > High THEN Risk = True"—the system must translate them into numerical inputs for a machine learning algorithm. Since raw text cannot be fed directly into a standard linear regressor or logistic regression model, FeatLLM employs a clever parsing mechanism. It feeds the generated rules back into an LLM with instructions to convert them into executable Python code snippets capable of evaluating any given row of data against those rules. This code is then executed using Python's `exec()` function on the dataset, transforming each rule into a binary feature (either 0 or 1) indicating whether that specific condition holds true for a sample.

With these new binary features constructed, the actual prediction happens via a simple linear model without bias terms but with trainable weights assigned to each feature rule. The equation governing this prediction essentially calculates a weighted sum of satisfied rules for each class:
$$ \text{logit}_k^i = \max(\mathbf{w}_k, 0) \cdot \mathbf{z}_k^i $$
Here, $\mathbf{z}_k^i$ represents the binary vector indicating which rules from class $k$ are met by sample $i$, and $\mathbf{w}_k$ represents the learned importance weights for those rules. By optimizing this model using cross-entropy loss on the few-shot training set, FeatLLM learns which derived rules are truly predictive and which are irrelevant noise effectively filtering out uninformative conditions during training.

To further bolster robustness and overcome limitations related to prompt token sizes in large datasets, FeatLLM integrates an ensemble approach inspired by bagging techniques from random forests. The entire rule-generation pipeline is run multiple times with randomized temperatures and shuffled demonstration orders to encourage diversity in the generated ruleset. # Crushing Spurious Correlations: Why Few-Shot Tabular Learning Needs Prior Knowledge

When working with tabular data in real-world scenarios, we often face a critical constraint: we simply don't have enough labeled examples. This is known as the few-shot learning regime. In such situations, standard machine learning models struggle immensely. With only a handful of samples, these models are prone to overfitting, latching onto random noise or spurious correlations rather than genuine patterns. If you add a column of random numbers to your dataset, a naive model might mistakenly believe that column holds the key to the prediction, leading to poor generalization on new data. This reliance on surface-level statistics makes traditional approaches brittle when data is scarce.

Enter Large Language Models (LLMs). These models possess vast amounts of prior knowledge acquired during their training on massive text corpora. However, simply feeding raw tabular data into an LLM for direct prediction has significant drawbacks. Current methods often require sending every single query through the LLM at inference time, which is computationally expensive and slow. Furthermore, many approaches rely on fine-tuning the model, which is impossible when dealing with proprietary LLMs that only offer API access or lack open-source checkpoints. There is also the issue of prompt limits; as the number of features in a dataset grows, serializing the data into text often exceeds the token limit of current models, rendering them unusable for complex tables.

The solution proposed in recent research is \textsf{FeatLLM}, a novel framework that reimagines the role of LLMs in tabular learning. Instead of acting as a black-box predictor for every sample, \textsf{FeatLLM} acts as an intelligent feature engineer. Its core innovation lies in shifting the focus from immediate prediction to understanding the underlying logic of the problem before generating any features. By doing so, it leverages the LLM's reasoning capabilities to filter out irrelevant noise and construct high-quality features that drive simple downstream models to success.

The heart of \textsf{FeatLLM}'s robustness is its unique two-step reasoning process designed explicitly to combat spurious correlations. Standard few-shot methods might jump straight from seeing examples to guessing rules based solely on those limited observations. In contrast, \textsf{FeatLLM} guides the LLM through a structured thought process that mimics an expert human analyst. The first step involves asking the LLM to infer causal relationships or tendencies between features and the target variable based purely on its internal prior knowledge and common sense, without looking at the few-shot examples yet. This initial "sanity check" forces the model to rely on established domain logic rather than coincidental patterns in tiny datasets. Only after establishing this foundational understanding does the second step occur: using specific few-shot examples to derive precise decision rules for distinguishing classes based on that reasoned foundation.

This separation of concerns is what allows \textsf{FeatLLM} to ignore irrelevant columns effectively. When an LLM attempts to find rules based only on a few noisy examples without prior context, it easily hallucinates connections between unrelated variables. By first grounding its reasoning in general knowledge—such as knowing that age correlates with health risks or income levels—the model can identify which features are actually meaningful candidates for rule creation before ever inspecting the sparse training data. Once these rules are identified in natural language, they are parsed into executable code snippets that transform into binary features indicating whether a sample satisfies each rule.

Once these high-quality binary features are generated, \textsf{FeatLLM} discards the heavy lifting usually done by complex deep learning architectures at inference time. Instead, it fits a simple linear model with non-negative trainable weights to estimate class probabilities based on these new features. This architecture offers two distinct advantages: speed and simplicity. Because the complex reasoning happens only once during a brief training phase using API calls, inference reduces to calculating dot products against pre-computed weights—a process nearly instantaneous compared to running full LLM queries per sample. Additionally, this approach naturally handles large datasets with hundreds of features by employing feature bagging and ensemble methods across multiple trials, ensuring that even if individual rule generations miss some nuances or hit prompt limits locally, the aggregate ensemble remains robust and accurate.

Empirical evaluations across thirteen diverse datasets confirm that this strategy pays off significantly in low-data regimes. \textsf{FeatLLM} consistently outperformed existing baselines like TabLLM and STUNT by approximately 10% on average while maintaining stability even when spurious correlations were artificially injected into the data tests showed it degraded far less than competing methods when faced with irrelevant columns). Crucially, it achieved performance comparable to conventional models trained on thirty-two shots using only four shots of actual data by effectively supplementing missing statistical power with semantic priors from the LLM's training history.

Ultimately, \textsf{FeatLLM} represents a paradigm shift in how we integrate generative intelligence with classical tabular learning problems. It proves that we do not need to force every prediction through an expensive neural network or fine-tune inaccessible models to achieve state-of-the-art results in few-shot settings. By delegating the role of "feature engineer" to an LLM capable of causal reasoning and filtering out noise before feature generation begins, we can build systems that are not only highly accurate but also efficient and interpretable enough for real-world deployment in fields ranging from healthcare diagnostics to financial risk assessment where labeled data is precious and scarce resources demand maximum efficiency per dollar spent on API calls or computation time spent waiting for responses?

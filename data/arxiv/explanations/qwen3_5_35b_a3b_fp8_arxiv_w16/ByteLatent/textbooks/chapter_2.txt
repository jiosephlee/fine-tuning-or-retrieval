Chapter 2: # Chapter 2: From Bytes to Patches – Strategies for Dynamic Grouping

In the landscape of modern Large Language Models (LLMs), the transition from raw data to meaningful units of computation has historically been governed by a rigid, heuristic process known as tokenization. Traditional architectures rely on a fixed vocabulary, grouping raw bytes into a finite set of tokens before the model ever sees the data. This pre-processing step, while computationally convenient, imposes a static structure on the input that often fails to align with the actual complexity of the information being processed. The Byte Latent Transformer (BLT) challenges this paradigm by introducing a fundamentally different approach: patching. Rather than forcing data into a pre-defined grid, BLT dynamically groups raw bytes into variable-sized units called "patches." This chapter explores the mechanics of this grouping strategy, contrasting it with traditional tokenization and detailing the evolution from simple static rules to sophisticated, entropy-driven dynamic segmentation. By understanding how BLT allocates computational resources based on data complexity, students will grasp the foundational logic that enables byte-level models to compete with—and in some cases surpass—token-based architectures at scale.

## Defining Patches vs. Tokens: Variable vs. Fixed Vocabulary

To appreciate the innovation of BLT, one must first rigorously distinguish between the concept of a "token" in traditional models and a "patch" in BLT. In standard Large Language Models like Llama 3 or Llama 2, tokenization is a heuristic pre-processing step performed before training begins. A tokenizer analyzes a vast corpus and constructs a finite vocabulary—a dictionary containing thousands or hundreds of thousands of sub-word units. During training and inference, every sequence of bytes is converted into a sequence of indices referencing this fixed vocabulary. For instance, the word "transformer" might be represented as three tokens: ["trans", "form", "er"]. Crucially, once this vocabulary is established, it remains immutable throughout the lifecycle of the model. The model itself never interacts with individual bytes; it only operates on these abstract token IDs. This reliance on a fixed vocabulary introduces several inherent biases: it forces arbitrary compressions on strings that may not reflect linguistic reality, creates domain sensitivity where rare words become fragmented inefficiently, and leads to multilingual inequities where low-resource scripts suffer from poor compression ratios compared to dominant languages like English.

In stark contrast, BLT eliminates this fixed vocabulary entirely through its patching mechanism. A patch is defined not by membership in a static list, but by a dynamic segmentation function applied directly to the stream of raw bytes during data loading or generation. Formally, let us consider a sequence of bytes $\pmb{x} = \{x_i \mid i=1,\ldots,n\}$ representing $n$ consecutive byte values from an input file or text stream. A patching function $f_p$ maps each byte $x_i$ to a binary indicator in $\{0,1\}$, where $1$ signifies the start of a new patch and $0$ indicates continuation within an existing patch. Through this mapping, the original sequence is partitioned into $m$ patches $\pmb{p} = \{p_j \mid j=1,\ldots,m\}$, where $m < n$. Unlike tokens, which are drawn from a finite set determined *prior* to training regardless of context, patches are arbitrary groupings formed on-the-fly based on specific criteria such as entropy thresholds or whitespace boundaries. There is no limit to the number of unique patches possible; any contiguous subsequence of bytes can constitute a valid patch if it satisfies the segmentation rules at that moment.

This distinction fundamentally alters how computational cost is incurred and managed in these architectures. In token-based models, every token incurs exactly one forward pass through the main transformer layers (the attention and feed-forward networks). Whether that token represents an incredibly frequent word like "the" or an obscure technical term requiring high cognitive load for prediction requires no differentiation; the model expends identical floating-point operations (flops) for both because they occupy one slot in the sequence length dimension. Conversely, in BLT, computational cost is primarily determined by $m$, the number of patches required to encode the data using a specific patching function $f_p$. Since patches can vary significantly in size—from single bytes representing high-uncertainty transitions to dozens of bytes representing predictable continuations—the average patch size becomes the critical lever for efficiency. If data contains long stretches of low-complexity patterns (like repetitive whitespace or common suffixes), these can be bundled into massive patches containing many bytes but consuming only one transformer step. This dynamic allocation means that BLT can process more raw information per unit of compute than token-based models when dealing with predictable sequences, effectively breaking free from the rigid trade-offs imposed by fixed-vocabulary tokenization where increasing vocabulary size merely shifts parameters rather than compute efficiency dynamically per sample.

## Static Strided Patching: Pros, Cons, and Lack of Context Awareness

Before exploring advanced dynamic methods, it is instructive to examine the simplest possible approach to grouping bytes: static strided patching. This method divides an input sequence into contiguous chunks of fixed length $k$, ensuring that every patch contains exactly $k$ bytes unless it falls at the very end of a sequence where truncation occurs. This approach mirrors early attempts at byte-level modeling such as MegaByte and offers immediate algorithmic simplicity and ease of implementation for both training pipelines and inference engines. Mathematically, if we have a byte sequence starting at index $i$, strided patching defines boundaries strictly based on integer division: new patches begin whenever $(i \mod k) == 0$. The primary advantage here lies in controllability; researchers can easily tune hyperparameters like batch size and context length because every step processes exactly $k$ tokens (bytes), making Flop estimation trivial and deterministic across all samples in a batch without padding issues arising from variable lengths within micro-batches (though macro-batch packing is still required).

However, despite its implementation convenience, static strided patching suffers from profound inefficiencies regarding compute allocation because it lacks any notion of semantic or informational density within the data stream. # Chapter 2: From Bytes to Patches – Strategies for Dynamic Grouping

In the landscape of modern Large Language Models (LLMs), transitioning from raw data to meaningful units of computation has historically been governed by rigid heuristics known as tokenization. Traditional architectures rely on grouping raw bytes into finite sets called tokens before processing begins—a process that imposes artificial limits incompatible with variable complexity distributions found in natural language streams [source]. The Byte Latent Transformer (BLT) revolutionizes this paradigm through **dynamic grouping**, replacing static vocabularies with fluid **patches**—variable-sized units formed directly from raw byte sequences during runtime [source]. This chapter explores how BLT strategically partitions computational resources based on information density rather than arbitrary boundaries [source], revealing why its approach achieves superior efficiency compared to conventional tokenizers [source]. Understanding these mechanisms provides critical insights for students analyzing cutting-edge research papers addressing scalability bottlenecks in next-generation language models [source].

## Defining Patches vs Tokens: Variable Versus Fixed Vocabulary Paradigms

Traditional large language models employ **tokenization** as an irreversible preprocessing step constructing finite vocabularies prior training begins [source]. Each input string gets converted into indices referencing predefined subword units—for instance "transformer" becoming ["trans", "form", "er"]—creating immutable mappings regardless content characteristics [source]. These fixed vocabularies introduce systemic biases including domain sensitivity reduced orthographic awareness multilingual inequities—all stemming from forced compression schemes misaligned with actual linguistic complexity [source]. Consequently every token consumes identical computational resources whether predicting ubiquitous articles like "the" versus rare technical terminology despite vastly differing predictive difficulties [source].

Conversely **patches** represent fundamentally distinct entities characterized by absence fixed vocabulary constraints entirely [source]. Formally defined through segmentation function $f_p$: Given byte sequence $\mathbf{x} = \{x_i \mid i=1,\dots,n\}$ consisting length-$n$ stream raw values integers range 0–255 inclusive representing ASCII Unicode UTF‑encoded characters respectively; mapping assigns binary indicators $\{0\}$ indicating continuation within current group versus $\{1\}$ marking initiation new segment yielding resulting collection $\mathbf{p} = \{ p_j \mid j=1,\dots,m \}$ where count satisfies inequality relation strict less-than condition ($m < n$) reflecting variable aggregation ratios dependent upon contextual conditions met during execution phase alone—not predetermined dictionaries established beforehand offline stages whatsoever [source].

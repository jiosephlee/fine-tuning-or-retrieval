# Why Your LLM Should Stop Using Tokens: Introducing Byte Latent Transformers

Large language models (LLMs) have revolutionized artificial intelligence, yet they all share a fundamental bottleneck: tokenization. Before an LLM can process your text, it must be chopped into discrete chunks called tokens using a fixed vocabulary, typically via algorithms like Byte Pair Encoding (BPE). This heuristic pre-processing step forces the model to compress raw data into a limited set of symbols, often leading to inefficiencies in handling noise, rare languages, and complex patterns. Enter the Byte Latent Transformer (BLT), a new architecture that discards this rigid tokenization entirely. By learning directly from raw bytes and dynamically grouping them into "patches," BLT matches the performance of industry giants like Llama 3 while offering significant gains in inference efficiency and robustness.

## The Problem with Fixed Vocabulary Tokenization

Current state-of-the-art models rely heavily on tokenizers that map strings of bytes to a finite set of tokens determined before training begins. While this speeds up computation by reducing sequence length, it introduces several critical limitations. First, the compression heuristics used to create tokens are arbitrary and not necessarily aligned with the actual complexity of the data. A model might waste computational effort on predictable sequences or fail to allocate enough capacity for complex regions simply because the tokenizer decided they belonged to the same token unit.

Furthermore, fixed vocabularies create biases that hinder performance across different domains and modalities. Tokenizers struggle with out-of-vocabulary words, exhibit sensitivity to input noise (like typos or random casing), and often suffer from multilingual inequity where low-resource languages are poorly represented in the vocabulary. Most importantly, once a model is trained on tokens, it loses direct access to the underlying byte-level features, making it difficult to understand orthography, phonology, or subtle character-level manipulations that human readers grasp effortlessly.

## Dynamic Patching: Allocating Compute Where It Matters

The core innovation of BLT lies in its replacement of static tokens with dynamic "patches." Instead of forcing every word or sub-word into a fixed slot, BLT groups raw bytes into variable-sized patches based on the entropy of the next byte prediction. Entropy here serves as a proxy for uncertainty; high entropy indicates a complex region requiring more attention, while low entropy suggests predictable text where less compute is needed.

This approach mimics how humans read: we don't need deep cognitive processing to finish reading "the quick brown fox jumps o..." because the pattern is clear; however, we pay close attention when encountering new proper nouns or complex mathematical expressions. BLT implements this by using a small auxiliary language model to estimate next-byte entropies during data loading. Based on these estimates, it decides where to cut the byte stream into patches. If a sequence is predictable, it forms long patches containing many bytes; if it is chaotic or novel, it creates shorter patches with finer granularity. This dynamic allocation ensures that the computationally expensive global transformer is invoked only when necessary, drastically improving efficiency compared to models that treat every token equally regardless of difficulty.

## Architectural Efficiency: The Three-Block Design

To support this dynamic patching strategy without exploding computational costs at scale, BLT employs a unique three-part architecture consisting of two lightweight local models flanking one massive global model. The flow begins with a **Local Encoder**, which takes individual bytes and aggregates them into latent patch representations using cross-attention mechanisms and hash-based n-gram embeddings. These embeddings allow the model to capture local context and byte-level patterns without needing a massive vocabulary table.

Once encoded, these patches are fed into the **Latent Global Transformer**. This is the heavy lifter—a standard autoregressive transformer that operates on patch representations rather than individual bytes or fixed tokens. Because it runs fewer steps (one per patch rather than one per byte), it consumes significantly fewer floating-point operations (flops) for predictable data streams compared to token-based models processing thousands of tiny tokens per sentence. Finally, a **Local Decoder** reverses this process, taking the global patch outputs and decoding them back into raw bytes sequentially. This separation allows BLT to scale effectively: as data grows more complex globally, we can expand the global transformer's size while maintaining efficiency through smarter patch sizing.

## Breaking Scaling Laws: Training Flops vs Inference Cost

One of the most compelling findings from BLT's research is its ability to decouple training efficiency from inference efficiency in ways token-based models cannot achieve easily. In traditional architectures like Llama 3 increasing model size usually requires proportionally increasing inference cost unless you accept performance drops or reduce context length artificially via larger vocabularies (which eventually hit limits). BLT breaks this trade-off by allowing researchers to simultaneously increase both model size *and* average patch size while keeping inference flops constant longer patches mean fewer steps for the global transformer free up compute budget which can then be reinvested into expanding the global transformer itself or adding more layers locally).

In their scaling studies involving up to 8 billion parameters and 4 trillion training bytes BLT achieved parity with Llama 3 on compute-optimal training regimes but offered up to 50% fewer flops during inference when configured for larger patch sizes (e.g., averaging 8 bytes per patch versus ~4 for BPE). This means developers can train massive models that are cheaper and faster at runtime without sacrificing accuracy—a game-changer for deploying large-scale AI applications in production environments where latency matters most).

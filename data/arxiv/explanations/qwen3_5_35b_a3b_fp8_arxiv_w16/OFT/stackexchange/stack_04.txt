\title{Stack Exchange of the Paper: "Controlling Text-to-Image Diffusion by Orthogonal Finetuning"}

### Why does OFT claim to avoid inference overhead while requiring matrix multiplication at runtime?
Question:
The paper claims in Section 5 ('Intriguing Insights') that 'Unlike ControlNet, our OFT framework introduces no additional inference overhead.' They justify this by saying one can pre-multiply $\bm{R}$ into $\bm{W}^0$ offline to get an equivalent weight matrix $\bm{W}$. However, isn't multiplying two dense matrices ($d \times d$) computationally expensive if done per-layer? If we merge them into a single weight matrix during training/finetuning setup, doesn't that increase memory usage for storing the merged weights compared to just storing $\bm{W}^0$ plus a small low-rank factor like LoRA? How does this scale compared to keeping separate parameters?
Answer:
The apparent contradiction between claiming "no additional inference overhead" and requiring a matrix multiplication at runtime stems from the distinction between *architectural* changes and *re-parameterization*. As explained in the "Intriguing Insights" section of the paper, OFT modifies the forward pass during training to be $\bm{z} = (\bm{R}\bm{W}^0)^\top\bm{x}$, where $\bm{R}$ is a learnable orthogonal matrix and $\bm{W}^0$ represents the pretrained weights. During this training phase, the computation indeed involves multiplying $\bm{R}$ with $\bm{W}^0$. However, the authors explicitly state that in the inference stage, one can pre-multiply these two matrices offline to create a single equivalent weight matrix $\bm{W}_{\text{final}} = \bm{R}\bm{W}^0$. Once this fusion is complete, the model effectively becomes a standard linear layer with weights $\bm{W}_{\text{final}}$, meaning the runtime computation is identical to running the original pretrained model without any extra operations.

Regarding your concern about memory usage and storage costs compared to methods like LoRA: yes, merging $\bm{R}$ (size $d \times d$) into $\bm{W}^0$ results in a dense $d \times n$ weight matrix that occupies more memory than storing just $\bm{W}^0$ plus a small low-rank factor. The paper acknowledges that standard orthogonal parameterization requires $d(d-1)/2$ parameters, which scales quadratically with dimension $d$. To mitigate this during the *training* phase (where memory matters most for optimization), OFT employs a block-diagonal structure for $\bm{R}$ with $r$ blocks. This reduces the number of trainable parameters from $\mathcal{O}(d^2)$ to roughly $\mathcal{O}(d^2/r)$ or even lower if blocks are shared. Crucially, however, once training concludes and the weights are fused into $\bm{W}_{\text{final}}$ for deployment, there is no longer any need to store $\bm{R}$ or maintain separate parameters. The deployed model stores only one dense weight matrix per layer, exactly as it did before finetuning. Therefore, while OFT might require more memory than LoRA *during* training due to its specific parameterization strategy, it incurs **zero** additional memory footprint or computational cost *at inference* because it collapses back into a standard architecture. This contrasts sharply with methods like ControlNet or adapters that must retain extra modules (like skip connections or parallel branches) permanently during inference to function correctly.

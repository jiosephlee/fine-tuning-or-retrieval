Chapter Title: Distributional Optimality in 4-bit Quantization: Why NF4 Relies on Normal Weights

# Quantization Fundamentals and Block-wise Design

Quantization converts high-precision numerical representations into lower-precision ones to reduce memory and computational demands. In large language models, weights are typically stored as high-precision floats (e.g., FP32), and quantization maps these values to a lower-bit representation such as 8-bit integers or 4-bit discrete codes. A standard practice rescales the input tensor to fit the target range so that the available codebook is used effectively. For instance, quantizing an FP32 tensor to Int8 with range $[-127,127]$ employs a learned or computed scaling factor, or quantization constant, to map the original values into this representable range:
\[
\mathbf{X}^{\text{Int8}} = \text{round}\!\left(\frac{127}{\text{absmax}(\mathbf{X}^{\text{FP32}})} \,\mathbf{X}^{\text{FP32}}\right) = \text{round}\!\left(c^{\text{FP32}}\cdot \mathbf{X}^{\text{FP32}}\right),
\]
with the inverse dequantization
\[
\text{dequant}(c^{\text{FP32}}, \mathbf{X}^{\text{Int8}}) = \frac{\mathbf{X}^{\text{Int8}}}{c^{\text{FP32}}} = \mathbf{X}^{\text{FP32}}.
\]

A key challenge in global quantization is the presence of outliers. If a few values have large magnitude, scaling by the absolute maximum $\text{absmax}(\cdot)$ stretches the majority of values into a narrow region of the codebook, leaving many bins underutilized. To mitigate this, block-wise quantization partitions a tensor into contiguous blocks and quantizes each block independently, each with its own quantization constant. Concretely, an input $\mathbf{X}\in\mathbb{R}^{b\times h}$ is flattened and chunked into $n$ blocks of size $B$, and each block is scaled and quantized separately. This improves the use of the codebook and reduces the impact of localized outliers.

In addition to blockwise scaling, QLoRA employs a second level of quantization, termed Double Quantization, which quantizes the set of first-level quantization constants themselves. This reduces the overhead of storing many block-specific scales. Specifically, quantization constants $c_2^{\text{FP32}}$ (from the first quantization) are quantized into $c_2^{\text{FP8}}$ using an FP8 representation at a larger blocksize, together with second-level scales $c_1^{\text{FP32}}$. The final dequantization composes the two inverse mappings:
\[
\text{doubleDequant}(c_1^{\text{FP32}}, c_2^{\text{k-bit}}, \mathbf{W}^{\text{k-bit}}) = \text{dequant}(\text{dequant}(c_1^{\text{FP32}}, c_2^{\text{k-bit}}), \mathbf{W}^{\text{4bit}}) = \mathbf{W}^{\text{BF16}}.
\]
This mechanism substantially reduces memory, cutting the average overhead from quantization constants by roughly $0.373$ bits per parameter at the cited blocksizes, without degrading performance.

# Quantile Quantization and Information-Theoretic Optimality

The central concept behind QLoRA’s 4-bit data type is quantile quantization. Quantile quantization seeks an information-theoretically optimal codebook for a given data distribution by selecting quantization levels so that each bin receives an equal expected number of data points. This equal-mass partitioning spreads representational capacity proportionally to where the data actually lie, thereby minimizing average distortion subject to the assumed distribution.

Let $X$ be a random variable modeling the weights in a block after appropriate rescaling. For a $k$-bit data type, one computes $2^k+1$ quantiles of the target distribution, and sets the $2^k$ code points to midpoints of the adjacent quantile boundaries:
\[
q_i \;=\; \frac{1}{2}\Big(Q_X\!\big(\tfrac{i}{2^k+1}\big) + Q_X\!\big(\tfrac{i+1}{2^k+1}\big)\Big),\quad i=1,\dots,2^k,
\]
where $Q_X(\cdot)$ is the quantile function of the chosen distribution. If the data are truly sampled from that distribution (after rescaling), each bin receives equal expected mass, and the codebook is optimal in the information-theoretic sense for that distribution.

A practical obstacle is that computing accurate empirical quantiles is costly, and approximations can induce significant error, especially for outliers. The approach taken in QLoRA avoids this by anchoring quantiles to a theoretical distribution with fixed shape, so that quantiles can be precomputed exactly and reused across tensors. This requires that the underlying weight distribution, after an appropriate normalization, matches the assumed theoretical form.

# Constructing NF4 for Normally Distributed Weights

The NormalFloat family, and in particular the 4-bit variant NF4, is designed for zero-centered normal distributions with arbitrary standard deviation. The construction proceeds in three conceptual steps:

1. Assume the weight values are zero-mean normal, $X\sim N(0,1)$ up to a scale. Compute the $2^k+1$ quantiles of $N(0,1)$ to derive a $k$-bit quantile data type that is information-theoretically optimal for normally distributed data.

2. Normalize the resulting code points to a fixed target range, conventionally $[-1,1]$, so that both the data and the data type inhabit the same interval.

3. Quantize a given weight tensor by rescaling it to this range using absolute-maximum normalization. In effect, this rescales the standard deviation of the weight tensor to match that of the $k$-bit NormalFloat code points.

In detail, the code points are set using theoretical quantiles of $N(0,1)$:
\[
q_i \;=\; \frac{1}{2}\Big(Q_{N(0,1)}\!\big(\tfrac{i}{2^k+1}\big) + Q_{N(0,1)}\!\big(\tfrac{i+1}{2^k+1}\big)\Big),\quad i=1,\dots,2^k.
\]
A practical consideration arises for symmetric $k$-bit schemes: a purely symmetric construction may fail to encode zero exactly, which is valuable in practice for exactly representing padding and true zeros. QLoRA resolves this by creating an asymmetric data type with a discrete zero. It estimates negative and positive quantiles separately, allocating $2^{k-1}$ codes to the negative side and $2^{k-1}+1$ codes to the positive side, and then unifies the sets while removing the duplicate zero. The result, NF$k$, preserves an exact zero while maintaining equal expected mass per bin under the normal assumption.

Crucially, the optimality claim for NF4 is tied to its design premise: it is information-theoretically optimal for zero-centered normally distributed data. This is made possible by fixing the distributional shape at $N(0,1)$ and precomputing exact quantiles, thus avoiding expensive empirical estimation and approximation errors that would otherwise arise.

# Why Distributional Mismatch Breaks Optimality

The information-theoretic optimality of NF4 depends entirely on the alignment between the true weight distribution (after normalization) and the assumed normal distribution used to construct the codebook. The equal-mass property that underpins optimality is guaranteed only when the bin boundaries are derived from the true distribution’s quantiles. If the data distribution differs, those boundaries no longer yield equal expected mass per bin, and the design ceases to be optimal.

To see this, consider the defining property of quantile quantization. Given a target distribution for weights, say with cumulative distribution function $F_X$, the bin boundaries that equalize mass are given by quantiles $Q_X(p)$ for equally spaced probabilities $p=\frac{1}{2^k+1},\frac{2}{2^k+1},\dots,\frac{2^k}{2^k+1}$. If one constructs the code points using a different distribution $Y$ with quantile function $Q_Y$, the boundaries $Q_Y(p)$ will, in general, not satisfy
\[
\mathbb{P}\!\left(Q_Y\!\big(\tfrac{i}{2^k+1}\big)\le X \le Q_Y\!\big(\tfrac{i+1}{2^k+1}\big)\right) \;=\; \frac{1}{2^k+1}
\]
under $X$. Consequently, some bins will receive more probability mass and others less, defeating the information-theoretic optimality objective.

NF4 is explicitly constructed from quantiles of $N(0,1)$ and is therefore optimal only under the assumption that normalized weights follow a zero-mean normal distribution. If, instead, the pretrained weights were uniformly distributed over an interval, such as $X\sim U(a,b)$ after normalization, the theoretical quantiles of $N(0,1)$ would no longer align with the quantiles of the uniform distribution. The code points and boundaries derived from $N(0,1)$ would not equalize mass under $U(a,b)$, and thus NF4 would not be optimal for such uniformly distributed weights.

More concretely, the NF4 bins are densest where the normal distribution concentrates its mass, i.e., near zero, and spread more sparsely in the tails. A uniform distribution places equal density across its support, so an optimal codebook for a uniform would allocate code points evenly across the interval to match that constant density. Using the normal-derived NF4 code points on a uniform will over-allocate bins near zero (relative to the uniform’s density) and under-allocate in the extremes, misaligning representational capacity with the data’s actual distribution. The direct consequence is larger average quantization error than a codebook tailored to the uniform.

This distributional dependence is not an incidental detail but the foundation of NF4’s design. QLoRA leverages the empirical observation that pretrained neural network weights “usually have a zero-centered normal distribution with standard deviation $\sigma$,” and then fixes the data type to be optimal for that family by precomputing normal quantiles. When this assumption holds, NF4 is both principled and efficient. When it does not, the optimality guarantee does not apply.

# Implications for QLoRA’s Training Pipeline

QLoRA’s finetuning pipeline stores the pretrained base model weights in a low-precision type and computes in a higher-precision type. Specifically, the storage type is typically 4-bit NF4 (with block-wise quantization and Double Quantization of the scales), while the computation type is 16-bit BrainFloat. During forward and backward passes, the 4-bit weights are dequantized to the computation precision:
\[
\mathbf{Y}^{\text{BF16}} \;=\; \mathbf{X}^{\text{BF16}} \,\text{doubleDequant}(c_1^{\text{FP32}}, c_2^{\text{k-bit}}, \mathbf{W}^{\text{NF4}}) \;+\; \mathbf{X}^{\text{BF16}}\mathbf{L}^{\text{BF16}}_1\mathbf{L}^{\text{BF16}}_2.
\]
Only the LoRA adapter parameters $\mathbf{L}_1,\mathbf{L}_2$ are updated; the base model weights remain frozen in 4-bit storage. Gradients with respect to the adapters require differentiating through the dequantization map, which is carried out in 16-bit precision after dequantizing $\mathbf{W}^{\text{NF4}}$ to $\mathbf{W}^{\text{BF16}}$.

In this framework, the choice of the 4-bit storage data type directly affects how faithfully the dequantized weights approximate the original high-precision weights during both forward and backward passes. When the distributional assumption matches reality—weights are approximately normal—NF4 assigns code points in a way that best preserves information under a 4-bit budget, leading to empirical performance comparable to higher-precision baselines after adapter finetuning. Indeed, QLoRA’s experiments show that NF4 with Double Quantization matches 16-bit LoRA and full 16-bit finetuning across a range of tasks and scales, while alternative 4-bit types such as FP4 underperform by about one percentage point in the cited setup.

However, this performance guarantee rests on the same distributional alignment. If the true distribution of weights deviates substantially—for example, if it were uniform over an interval after normalization—then NF4’s normal-derived bins would misallocate representational capacity. In that scenario, one would not expect NF4 to be information-theoretically optimal, and a quantization scheme constructed from the true distribution’s quantiles would, in principle, yield a better average distortion profile. Put succinctly, NF4 is the right tool precisely because the weight distribution is approximately normal; change the distribution, and the optimal tool changes with it.

# Consequences for Memory and Performance Trade-offs

The paper demonstrates that combining NF4 with block-wise quantization and Double Quantization yields substantial memory savings without performance degradation relative to 16-bit finetuning. For example, finetuning a 65B parameter model fits within less than $48$ GB of GPU memory, down from more than $780$ GB required for a 16-bit baseline, while retaining predictive performance. Paged Optimizers further safeguard against transient memory spikes that occur with long sequences by leveraging unified memory to page optimizer states between CPU and GPU as needed.

These gains do not depend on NF4’s optimality for every imaginable distribution; they depend on NF4 being well matched to the empirical distribution of pretrained weights encountered in practice. Because the method assumes (and finds in practice) that weights are approximately zero-centered normal after appropriate normalization, NF4 delivers both theoretical and empirical advantages. If, counterfactually, the pretrained weights were uniformly distributed, the specific information-theoretic optimality claim that motivates NF4 would not hold, and a different quantile-based codebook would be required to restore that optimality under the new distribution. In such a case, using NF4 would be a distributional mismatch: it would still function as a 4-bit code but would not be the information-theoretically optimal one for the uniform distribution.

# Summary

QLoRA’s 4-bit NormalFloat, NF4, is constructed by quantile quantization using the theoretical quantiles of a standard normal distribution, then normalized to a fixed range and augmented to include an exact zero. This makes NF4 information-theoretically optimal for zero-mean normally distributed weights after normalization. The equal-mass property that underlies this optimality holds only when the true weight distribution matches the assumed normal form. If, instead, pretrained weights were uniformly distributed, the normal-derived quantile boundaries would fail to equalize mass, and NF4 would no longer be optimal. The broader success of QLoRA hinges on the empirical regularity that pretrained weights are approximately normal; under that condition, NF4 delivers the memory and performance advantages documented in the paper, while a different distribution would call for a correspondingly different quantile-derived codebook to reclaim optimality.

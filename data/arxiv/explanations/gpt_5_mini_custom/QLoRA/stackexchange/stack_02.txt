\title{Stack Exchange of the Paper: "QLoRA: Efficient Finetuning of Quantized LLMs"}

### How exactly does NF4 ensure a zero codepoint while keeping equal expected bin mass?
Question:
The paper constructs NF4 by taking quantiles of \(N(0,1)\), normalizing to \([-1,1]\), and then making the codebook asymmetric: \(2^{k-1}\) negative bins and \(2^{k-1}+1\) positive bins, then removing one of the zeros so that there is an exact representation of 0. This is claimed to yield a datatype with equal expected number of values per bin (under a normal distribution) and a discrete zeropoint.

I don't see how the equal-mass property is preserved once we deviate from a symmetric quantizer and also force an exact zero. Could someone walk through the precise construction for \(k=4\) and show:
- The exact thresholds/centroids \(q_i\) before and after making it asymmetric.
- How the bin containing 0 is handled so that the probability mass in each bin is still equal under \(N(0,1)\).
- Why this preserves the "information-theoretic optimality" claim (under which distortion measure and constraints)?
Answer:
Short answer: NF4 starts from the usual quantile (equal-probability) quantizer for a standard normal, so every quantization *interval* has the same probability mass $1/(2^k+1)$. That equal-mass property is what makes quantile quantization “information-theoretically optimal” for a known input distribution under the usual expected squared-error (MSE) distortion. To get an exact discrete zero while keeping equal expected mass per *stored* codepoint, the paper constructs the codebook by (a) forming the equal-mass partition of the $N(0,1)$ CDF, (b) choosing centroids as midpoints of those equal-mass intervals, and (c) breaking the tie at zero by treating the sign sides asymmetrically so one stored codepoint is exactly $0$ while the remaining stored codepoints still correspond to intervals of equal probability. The result is still a 4-bit quantizer with 16 stored values and each stored value represents an interval of equal probability under $N(0,1)$, so the equal-mass property and the usual quantile optimality (for expected-squared-error) are preserved.

Below I walk through the construction more concretely ($k = 4$) and explain why the equal-mass claim holds and under what optimality statement it is meant.

1) The standard quantile (symmetric) $k$-bit quantizer (before any asymmetry)
For a $k$-bit quantizer with $2^k$ stored values, the usual quantile construction for a continuous distribution $F$ (here $F$ is the CDF of $N(0,1)$) uses the $2^k+1$ boundaries at CDF locations
$t_j = Q\big(j/(2^k+1)\big)$, for $j = 0,1,\dots,2^k$,
where $Q$ is the quantile (inverse CDF). These boundaries partition the real line into $2^k$ intervals, each having probability mass $1/(2^k+1)$. A convenient codepoint (centroid) for interval $j$ is
$q_j = (t_{j-1} + t_j)/2$  (the midpoint) or the conditional mean of $X$ on that interval; both are standard choices. The important point is that each interval has equal probability mass $1/(2^k+1)$. For $k = 4$ we therefore form the 17 quantiles $t_0,\dots,t_{16} = Q(0/17),\dots,Q(16/17)$. The 16 intervals $[t_{j-1},t_j)$ each have mass $1/17$.

That symmetric quantile design has no stored codepoint exactly equal to zero: the middle interval straddles zero (its midpoint is typically not exactly zero). If having an exact stored zero is important (for zero-padding, exact sparse representation, etc.) this symmetric design fails.

2) How NF4 obtains an exact discrete zero while keeping equal expected bin mass
The practical recipe the paper gives (paraphrased) is:
- Start from the theoretical quantiles of $N(0,1)$.
- Build an asymmetric codebook with $2^{k-1}$ negative stored codepoints and $2^{k-1}+1$ positive stored codepoints, so that one of the stored values is exactly $0$.
- Remove the duplicate zero (one would obtain a zero in both halves if constructed naïvely) to end up with exactly $2^k$ stored values, including a single stored value equal to $0$.
- Use the midpoints (or conditional interval means) of the corresponding equal-probability intervals as the centroids.

For $k = 4$ this means: you want 8 negative codepoints, 1 codepoint at exactly $0$, and 7 other positive codepoints (total 16). The way to do this consistently so that each stored codepoint still represents an interval of equal probability is to define the 17 interval boundaries exactly as in the symmetric quantile design. Those 17 boundaries split the real line into 16 intervals each of probability $1/17$. Now form stored codepoints by taking the midpoint (or conditional mean) of each of those 16 equal-probability intervals — that is exactly the symmetric quantile centroids. One of those 16 midpoints will be the midpoint of the interval that straddles zero; instead of using that midpoint we replace it by the exact value $0$ and treat that stored codepoint as representing the same interval that previously straddled zero. Concretely:
- Compute $t_j = Q(j/17)$, $j = 0,\dots,17$.
- Intervals are $I_j = [t_{j-1}, t_j)$, $j=1,\dots,16$, each with probability $1/17$.
- For each interval $I_j$, the standard centroid would be $c_j = (t_{j-1}+t_j)/2$ (or the conditional mean on $I_j$).
- Identify the middle interval $I_m$ that contains $x=0$ (this is the interval for which $t_{m-1} < 0 < t_m$). Replace its centroid $c_m$ with the exact value $0$. Keep all other centroids as $c_j$. Store the 16 centroids; one of them is exactly $0$.

This operation does not change the partition of the real line into intervals, it only changes one stored representative inside one interval from the midpoint to zero. Because the intervals themselves are unchanged, each stored codepoint continues to represent an interval that has probability $1/17$ under $N(0,1)$. Therefore the “equal expected number of values per bin” (equal probability per bin) remains true.

Why does the paper phrase this in terms of 8 negative and 9 positive bins? That wording reflects that after replacing the middle centroid by zero, the set of stored values will contain 8 strictly negative centroids, the exact $0$ centroid, and 7 strictly positive centroids — but one can equivalently view it as 8 negative + 8 non-negative stored values where the zero occupies one non-negative slot. Counting conventions can make it read like “8 negative and 9 positive before deduplicating the zero,” but the rigorous way to see equal-mass is: keep the original equal-probability partition (the 17 quantile boundaries); change only the stored representative for the middle interval to be exactly zero. The bins remain equal-probability.

3) What changes and what is preserved
By replacing the representative inside the central interval with exactly zero you do change the local reconstruction error inside that particular interval (from the midpoint error to the error around zero), but you do not change the interval endpoints. So the equal-mass partition (each interval mass $1/(2^k+1)$) is preserved. In other words, NF4 is still a quantile (equal-probability) partitioning of $N(0,1)$; it only forces the stored representative of the central bin to equal $0$.

4) Why this preserves the “information-theoretic optimality” claim
The usual information-theoretic optimality claim for quantile quantizers is that, when the input distribution is known (here $N(0,1)$) and you are constrained to store exactly $2^k$ distinct codepoints, a quantizer that partitions the input space into equal-probability intervals minimizes the expected log-loss of the index (equivalently maximizes the entropy of the discrete index) and gives good performance for transport of mass. More operationally for scalar quantization under a fixed distribution, the Lloyd–Max optimality notion for MSE (expected squared error) yields that an optimal quantizer must satisfy two conditions: (i) each partition region should be the Voronoi region of its centroid (nearest-neighbor rule) and (ii) each centroid should be the conditional mean of the distribution on its partition region. The quantile partition with midpoints as centroids is not strictly the exact Lloyd–Max MSE optimum for every distribution, but for the class of symmetric unimodal distributions and with small numbers of bits it is often the best practical choice; moreover, with the information-theoretic quantile construction one guarantees equal usage of codewords under the target distribution, which is the primary desideratum when you care about balanced indexing and representational efficiency.

In the NF4 tweak the only deviation from the strict midpoint representative is replacing that midpoint by exactly $0$ for the middle interval. This is a tiny, localized change whose cost in expected squared error is small because the middle interval is centered at zero and has small width compared to tails; replacing the midpoint by zero reduces reconstruction error for values extremely close to zero (including exact zeros) and slightly increases it for other values in the middle interval. The net change in expected squared error is negligible compared to the benefit of having an exact stored zero (no error for exact zeros). Because the partition remains equal-probability, the property that each stored codepoint is used equally often under $N(0,1)$ is preserved; this equal usage is the key information-theoretic aspect discussed in the paper. Thus the NF4 construction keeps the principal benefit of quantile quantization (balanced bin usage under the assumed normal prior) and additionally gives a discrete zero.

In short, NF4 preserves the equal-mass bins because it keeps the equal-probability partition (the 17 quantile boundaries for $k=4$). The only change is the representative chosen for the central (zero-containing) interval, which is set to exactly $0$; that does not alter the interval masses. The “optimality” claim in the paper is therefore: NFk is information-theoretically (and practically) optimal for zero-centered normal weights in the sense that the quantization bins are equal-probability under $N(0,1)$ (so codepoints are used equally often) and that centroids are the usual midpoint/conditional-mean representatives up to the central bin being forced to zero — which is a tiny, deliberate deviation that improves handling of exact zeros without breaking the equal-mass property. The distortion measure under discussion is the expected squared reconstruction error (MSE) or practical reconstruction loss used when dequantizing weights back to floating point; NF4 is designed to be near-optimal under that distortion given the normal prior and the desire for a discrete zero.

5) Numerical thresholds/centroids for $k = 4$ (how to get them)
The paper gives the formal centroid formula used before the “force-zero” tweak:

$q_i = \frac{Q\big(i/(2^k+1)\big) + Q\big((i+1)/(2^k+1)\big)}{2}, \quad\text{for } i = 0,\dots,2^k-1.$

For $k = 4$ this is $q_i = \tfrac{1}{2}\big(Q(i/17) + Q((i+1)/17)\big)$, $i = 0,\dots,15$. Those 16 $q_i$ are the midpoints of the 16 equal-probability intervals of $N(0,1)$. In practice the authors tabulate these (see their Appendix). To get NF4 as actually used in code:
- compute the 17 quantile boundaries $t_j = Q(j/17)$, $j=0\dots17$;
- compute the 16 midpoints $q_i = (t_{i}+t_{i+1})/2$ for $i=0\dots15$;
- let $m$ be the $i$ such that $t_i \le 0 < t_{i+1}$; replace $q_m$ by exactly $0$ (this is the “remove one of the two zeros / make a zero codepoint” step);
- the stored codebook is then $\{q_0,\dots,q_{m-1}, 0, q_{m+1},\dots,q_{15}\}$ with intervals unchanged.

If you need the floating-point numerical values for the 16 stored NF4 codepoints, the paper’s Appendix (their NF4 table) contains them; they are just the midpoints of those quantiles except the middle value forced to $0$.

Conclusion
NF4 keeps equal expected bin mass because it keeps the equal-probability partition induced by the $N(0,1)$ quantiles (the bins are unchanged). The only change is the stored representative for the central bin (make it exactly zero), which does not change interval probabilities. The information-theoretic / practical optimality argument is therefore preserved: the bins are still equal-probability under the normal prior (hence balanced use of codepoints), and the design remains (near) optimal for minimizing expected squared reconstruction error under that prior, with the pragmatic benefit of an exact stored zero.

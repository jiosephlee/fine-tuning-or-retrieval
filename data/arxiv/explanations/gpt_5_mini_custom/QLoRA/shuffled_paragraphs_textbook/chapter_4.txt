The empirical findings in the paper show that not all these hyperparameters are equally sensitive. Specifically, the projection dimension $r$ did not materially affect performance in their ablations; performance was robust across reasonable choices of $r$ in their setups. In contrast, the number and placement of adapters (the "target modules") was highly consequential: restricting LoRA to only a subset of attention matrices led to a significant gap relative to full finetuning, whereas applying adapters to all linear layers closed that gap. This indicates that, for the tasks and scales studied, the breadth of adapter coverage matters more than fine-tuning the low-level adapter rank.

- rank $r$: the inner dimension of the factorization ($\mathbf{L}_1\in\mathbb{R}^{h\times r}$, $\mathbf{L}_2\in\mathbb{R}^{r\times o}$). This controls the number of degrees of freedom in the learned residual $\Delta\mathbf{W}$. Larger $r$ increases expressivity but also increases adapter parameter count (proportional to $h\cdot r + r\cdot o$).

The paper emphasizes this point with experiments on LLaMA 7B finetuning: using LoRA only on a few attention matrices failed to match full finetuning accuracy on instruction-following tasks, while distributing LoRA adapters across all linear transformer block layers allowed recovery of full-finetuning performance. Therefore, the practical recommendation is to place adapters broadly — every linear layer — when the goal is to faithfully reproduce full finetuning behavior.

LoRA introduces a small set of hyperparameters that control adapter behavior and capacity. The most prominent are:

- storage for (quantized) base model parameters;
- storage for adapter parameters and their optimizer states;
- activation storage and activation gradients (which scale with batch size, sequence length, and hidden dimensionality);
- optimizer state memory for any trainable parameters.

This factorized residual projection has two important consequences. First, the number of trainable parameters can be dramatically smaller than the original weight matrix: the adapter contributes only $h\cdot r + r\cdot o$ parameters (plus the scalar $s$) versus $h\cdot o$ for the full weight. When $r \ll \min(h,o)$, this is a huge reduction. Second, because the pretrained $\mathbf{W}$ remains frozen, the forward pass reuses the existing computation and the backward pass only needs to produce gradients for $\mathbf{L}_1$ and $\mathbf{L}_2$. This both reduces storage of optimizer states and concentrates the optimization on a small, expressive subspace that is often sufficient to adapt the model to a new task.

More explicitly: LoRA concentrates the optimization into a low-dimensional subspace, and making that subspace available at many points in the network (every linear layer) allows the finetuning process to better approximate the effect of updating the full parameter matrix. Because activation gradients and base model storage dominate memory usage, adding these extra low-rank adapters is an inexpensive way to get closer to full finetuning performance. Techniques that attack the dominant memory contributors (activation storage and base weight storage) — such as quantization (4-bit NF4), double quantization of quantization constants, and paged optimizers — complement LoRA by enabling these broader adapter deployments at large model scales on limited hardware.

- scalar (denoted $s$ in the LoRA formulation): an overall scale for the adapter contribution. This can be used to adjust the initial strength of the adapter relative to the frozen base projection. In some implementations this scalar is parameterized or absorbed into initialization; in the paper it appears as a fixed scalar in the formulation.

To illustrate with the concrete example from the paper: for a 7B-parameter LLaMA model finetuned on FLAN v2 with batch size 1, the LoRA parameters (configured to be roughly 0.2% of original model weights in common setups) occupy only about 26 MB. In contrast, the gradient memory for the LoRA inputs (the stored activations needed to compute gradients) consumes about 567 MB. The 4-bit quantized base model (i.e., storage for the frozen quantized weights) consumes about 5,048 MB. Even after applying gradient checkpointing, which recomputes forward activations on the fly to trade compute for memory, the average activation gradient memory per sequence drops to around 18 MB. Still, this 18 MB is larger than the 26 MB of LoRA parameters? Note the ordering: with checkpointing, per-sequence activation gradient memory is reduced compared to the naive 567 MB, but the overall training memory footprint remains dominated by activations and the base model memory footprint (the 4-bit weights), not the adapter parameters.

Other training hyperparameters (learning rate, batch size, number of epochs) remain important for overall optimization, and the paper notes that these must be tuned for the specific model scale: e.g., when scaling up from 13B to 33B and 65B they halved the learning rate and doubled batch size to maintain stable convergence. While these are not LoRA-specific, they interact with adapter training because only the adapters are being updated.

Low-Rank Adapters (LoRA) reparameterize a weight update as a small, low-rank residual added to the original (frozen) weight matrix. The basic idea is to avoid updating the full large weight matrix during finetuning and instead learn a compact factorization that lives in a much smaller parameter subspace. Concretely, consider a linear projection in a network layer computed as
\[
\mathbf{Y} = \mathbf{X}\mathbf{W},
\]
with $\mathbf{X}\in\mathbb{R}^{b\times h}$ (the input activations), $\mathbf{W}\in\mathbb{R}^{h\times o}$ (the pretrained weight matrix), and $\mathbf{Y}\in\mathbb{R}^{b\times o}$ (the outputs). LoRA augments this projection with a learned, factorized residual:
\[
\mathbf{Y} = \mathbf{X}\mathbf{W} + s\,\mathbf{X}\mathbf{L}_1\mathbf{L}_2,
\]
where $\mathbf{L}_1\in\mathbb{R}^{h\times r}$ and $\mathbf{L}_2\in\mathbb{R}^{r\times o}$ are the adapter factors and $s$ is a scalar that scales the adapter contribution. The product $\mathbf{L}_1\mathbf{L}_2$ is a rank-$r$ matrix, so the additional degrees of freedom added to the layer are controlled directly by $r$. Intuitively, instead of changing the full $h\times o$ matrix $\mathbf{W}$ (which is large), LoRA learns a low-dimensional subspace of weight changes: $\Delta\mathbf{W} \approx s\,\mathbf{L}_1\mathbf{L}_2$.

In short, LoRA's factorized residual projection is an effective, memory-efficient mechanism to adapt large pretrained models; to realize its full potential one should prioritize wide adapter placement across layers rather than extreme shrinking of adapter ranks, and focus memory-optimization effort where it yields the largest returns (activations and base-model storage).

In the provided example, the 4-bit base model itself consumes roughly 5 GB, while LoRA parameters are a few tens of MB — a fraction of a percent. Activation gradients and transient activations are often larger than both. Thus, reducing adapter parameter count further yields only minor gains in total memory usage because the activations and base model storage dominate. This explains why the authors conclude that one can afford to use more adapters (more coverage across layers) without appreciably increasing maximal memory usage.

Chapter 4: Low-Rank Adapters (LoRA) and Memory Implications

The scalar $s$ acts as an overall strength parameter for the adapter contribution. In practice it can be treated as a fixed scaling factor or absorbed into the initialization of $\mathbf{L}_1$ and $\mathbf{L}_2$; but conceptually $s$ allows controlling how much the low-rank update influences the layer output without changing the adapter rank.

A central practical question is which linear projections in a transformer (or other architecture) should receive LoRA adapters. The common practice before the experiments reported in the paper was to apply LoRA to a subset of attention projections — typically the query and value projection matrices in multi-head attention. This choice is sensible because attention is crucial for conditioning and often accounts for a substantial fraction of model capacity. However, empirical results in the paper demonstrate that this limited placement is not sufficient to match the performance of full finetuning, especially for larger base models.

An operational consequence is that memory-saving techniques that target activations (e.g., gradient checkpointing) or base-model storage (e.g., 4-bit quantization and double quantization) have far larger effects on the ability to run large-model finetuning on constrained hardware than shrinking adapter parameter counts.

The experiments show that applying adapters to every linear layer in the transformer block — i.e., both all attention projections and the MLP (feed-forward) linear projections — is necessary to recover full-finetuning performance. In other words, LoRA at "all-layer coverage" means inserting the low-rank residual term into each linear mapping across attention heads and MLPs throughout the network. The intuition is that task-specific adaptation may require adjustments in many parts of the model, not only in attention. Restricting adapters to just query and value projections constrains the representational subspace too strongly for some tasks; by enabling every linear projection to be adjusted (albeit via low-rank updates), the model has the expressive flexibility to approximate the effect of full-parameter updates.

A common misconception is that because adapters add parameters, their memory cost is the main obstacle in adapter-based finetuning. The paper shows that in modern LLM finetuning the dominant memory consumer is not the adapter parameters but the activation gradients (and related activation storage), not the adapters themselves.

- target modules (where adapters are placed): which linear projections receive the LoRA augmentation (e.g., query/value only, attention-only, attention + MLP, or all linear layers). As discussed above, the experiments show that placement across all linear layers is critical to match full finetuning performance for large models and instruction tuning tasks.

The combined evidence points to a clear practical takeaway: because adapter parameters are tiny relative to activations and model storage, it is usually beneficial to employ more adapters (i.e., place LoRA across all linear layers) when the goal is to match the accuracy of full finetuning. Expanding adapter coverage substantially improves the model's ability to adapt while barely changing the total memory footprint. This observation enables a strategy that trades a small increase in adapter parameters for large accuracy gains without needing more hardware memory.

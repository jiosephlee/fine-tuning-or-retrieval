Chapter 8: Paged Optimizers: Stability Under Memory Spikes  Modern GPUs provide a feature called unified memory that permits the runtime to move pages of memory automatically between GPU device memory and host (CPU) RAM. Because these spikes are ephemeral (they exist only during specific recomputation/backprop moments or when a long sequence is processed), a system that can tolerate temporary oversubscription of device memory by migrating rarely-used large tensors to host RAM avoids hard OOM failures while still keeping the common-case fast path on-device. In the context of training large neural networks, unified memory can be used to reduce the risk of out-of-memory (OOM) failures by allowing some large allocations to live in this pageable region. The QLoRA experiments report that paging is a rare event for typical minibatches and sequence lengths, and that in an empirical test with a 65B parameter model on a 48GB GPU, using a batch size of 16 produced essentially the same training speed with paged optimizers as with regular (non-paged) optimizers. When designing a training recipe, combine paged optimizers with conservative batching and carefully chosen checkpointing strategies to get the best mix of stability and throughput. If recomputation spikes are frequent and costly, try adjusting the granularity of checkpointing (fewer checkpoints reduces recomputation but increases activation storage) or combine checkpointing with more aggressive batching strategies that avoid co-locating many long sequences in the same minibatch.

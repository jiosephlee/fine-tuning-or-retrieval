Title: Textbook of QLoRA: Efficient Finetuning of Quantized LLMs

Why QLoRA? Motivation, Contributions, and Headline Results

# The cost of sixteen‑bit finetuning
Large pretrained transformer systems contain an enormous number of tunable parameters. For very large instances—those with on the order of tens of billions of parameters—performing full finetuning in a conventional high‑precision format consumes vast amounts of memory on accelerator cards. For example, a sixty‑five billion parameter variant of a popular open architecture demands on the order of several hundred gigabytes of device memory when all weights, optimizer state, and intermediate tensors are kept in a standard sixteen‑bit floating compute format. This memory footprint places such finetuning out of reach for a single commodity accelerator and forces researchers to partition a single run across many machines, increasing cost and engineering complexity.

Most of the runtime and memory pressure during finetuning comes not from the stored pretrained weights alone but from the ephemeral tensors needed during the forward and backward passes and from optimizer state for parameters that are updated. Even when only a small fraction of the total parameters are updated, the intermediate gradients and the state held to perform parameter updates can exceed available device memory. These resource needs create a severe accessibility barrier: only clusters of high‑memory accelerators can routinely run large‑scale finetuning in the conventional way. The work we present aims to remove that barrier by changing how the base weights are stored and how the tunable components are attached.

# Key idea: propagate gradients through a frozen, low‑precision base into LoRA low‑rank factors
The central technical approach is to store the frozen pretrained base in a very compact, low‑precision form while attaching a small set of trainable, higher‑precision low‑rank factors to each linear projection. During training, the base weights are not modified; instead, gradients flow through the computation that uses the compact stored representation and update only the low‑rank factors. Concretely, when a layer computes an output from an input, the frozen, compact storage is converted into the working precision, the layer computation runs in this working precision, and the additive contribution from the low‑rank factors is applied in the same working precision. Gradients are propagated back through the decompactification step into the low‑rank factors so that the small set of trainable parameters can capture the task‑specific changes while the large pretrained core remains fixed.

This design reduces memory for parameter storage dramatically because the large pretrained tensors are kept in a compressed form. At the same time, the higher‑precision low‑rank factors remain small enough that optimizer state for them fits comfortably in limited device RAM. Critically, the approach computes all forward and backward operations in a higher‑precision working format after decompactification, so numerical stability and the fidelity of gradient computation are preserved for the tunable parameters. In short: compact storage for the frozen base plus high‑precision computation for the adapters yields a practical path to finetuning very large networks on a single accelerator without changing the optimizer mathematics used for the trainable factors.

# Contributions that make compact‑storage finetuning practical
Three engineering and numerical ideas together enable this approach to match the performance of full high‑precision finetuning while keeping the memory footprint very small.

First, a distribution‑aware compact storage format. Pretrained weight tensors in transformer networks tend to follow a roughly zero‑centered normal distribution within each tensor block. Exploiting this observation, one can design a small discrete set of representable values that aligns with the quantiles of a standard normal distribution. Mapping each tensor block into that discrete set after rescaling yields an information‑efficient representation for normally distributed weights: each representable bin contains about the same expected number of weight values. Using this normal‑quantile based type for four‑level storage reduces quantization error relative to naive integer or uniform floating representations when the underlying distribution is approximately normal. The paper calls this family NormalFloat, and the four‑level variant is a key part of the compact storage strategy.

Second, reducing overhead for per‑block scaling. Practical compact storage schemes quantize each contiguous block of parameters with a local scale multiplier so that the small discrete alphabet is used effectively even in the presence of outliers. Those per‑block scale factors themselves require storage; with small block sizes this overhead is nontrivial. Double Quantization addresses that by applying a second, coarser quantization step to the per‑block scale multipliers themselves. In other words, the first quantization maps weights into a low‑level discrete alphabet together with a set of scale multipliers; the second quantization compresses those multipliers into a compact floating set with its own coarse scale factors. The nested quantization reduces the average memory per original parameter substantially while introducing only a negligible loss in representation fidelity.

Third, smoothing runtime memory spikes due to optimizer state and intermediate tensors by exploiting host‑device unified memory. Large sequence lengths or large micro‑batches can cause transient peaks in working memory consumption. By placing optimizer state in a region that can be paged between host RAM and device RAM automatically, these transient peaks no longer cause out‑of‑memory failures. The optimizer keeps the small set of trainable parameters and their fine‑grained state on the device when needed; when the device is under memory pressure, less frequently used pages of optimizer state are paged out to host RAM and paged back when required. This paging strategy lets a single accelerator process sequences and batch sizes that would otherwise need larger on‑device memory, with modest practical overhead.

Together these components enable a workflow where the large pretrained core is stored in an aggressive compact form, per‑step computation and gradients for the tunable low‑rank factors are computed in a higher‑precision working format after decompactification, and optimizer state is managed so that transient peaks do not cause failures. The result is a finetuning setup that reduces the average on‑device memory by a large factor compared to conventional sixteen‑bit full finetuning while preserving the training dynamics of the tunable components.

# Guanaco family and headline empirical results
Applying this compact‑storage finetuning procedure at scale yields a family of conversationally tuned systems, released under the name Guanaco. These variants were generated by applying the compact‑storage plus low‑rank tuning pipeline to publicly available large pretrained cores and finetuning them on high‑quality, instruction‑style collections. Across a range of sizes, the tuned Guanaco systems demonstrate that the compact storage approach can recover the performance of conventional high‑precision finetuning when measured on practical dialog‑style test sets and standard multiple‑choice tasks used in the community.

A striking headline from the empirical suite is that the largest Guanaco variant achieves nearly parity with a widely used commercial conversational system on a community test set: it attains about ninety‑nine point three percent of that system’s score on the Vicuna prompt set under a relative scoring protocol. More broadly, the family shows that careful choice of the instruction collection used for tuning matters: a relatively small, high‑quality instruction collection can yield superior conversational behavior compared with much larger but lower‑quality collections. The compact‑storage finetuning method also makes it possible to explore sizes that were formerly inaccessible to single‑accelerator runs, enabling experiments that compare how conversational behavior scales with core size when the entire tuning run can be performed on a modest workstation.

In addition, human and powerful model‑based rating procedures were used in pairwise head‑to‑head comparisons across systems, aggregated with tournament rating methods to produce ordinal rankings. These comparisons indicate that Guanaco variants trained with the compact‑storage pipeline rank near the top of all openly released systems in the study and in many tests approach commercial capability.

# Why these contributions matter in practice
Before this work, the resource barrier for finetuning very large pretrained cores meant that only organizations with large clusters could iterate rapidly on instruction tuning and conversational fine‑turning. By compressing the frozen base heavily while keeping trainable components small and high precision, the described pipeline opens these experiments to single‑accelerator setups. This has several concrete practical benefits.

First, it lowers hardware cost and simplifies infrastructure: a researcher with a single modern accelerator with moderate device memory can run finetuning experiments that previously required distributed setups. Second, it accelerates iteration: smaller runs are cheaper and faster to schedule and thus allow more exploration of finetuning corpora, prompt formats, and low‑rank hyperparameters. Third, it democratizes access to cutting‑edge conversational tuning: the compressed workflow makes it possible to release tuned artifacts that are easier to host and to run on modest cloud instances or even on-device in certain cases.

Finally, by recovering the performance of full high‑precision finetuning in thorough empirical tests, the approach shows that aggressive storage compression for the frozen core does not necessarily force a trade‑off with final task performance, provided the tunable parameterization and the decompactification‑to‑compute path are handled carefully.

Foundations: Finetuning LLMs and Memory Bottlenecks

# Intermediate-state versus parameter memory; gradient checkpointing

When a large language model is trained on a supervised objective, the temporary data produced during a forward pass dominates the memory footprint at training time. These temporary items include the internal hidden states produced at each layer for each position in the input sequence and the associated derivatives that are required for the backward pass. In the literature this category is often contrasted with the persistent storage required to hold model parameters; for very large models the transient storage tied to a single batch and sequence length frequently exceeds the storage needed for the static weights.

The paper demonstrates this distinction with concrete figures for a mid-sized model finetuned with a low-rank update method. A small fraction of extra parameters used for the trainable low-rank updates takes only a few dozen megabytes of permanent storage, whereas the gradients tied to the inputs flowing into those modules can require several hundred megabytes. For the same setup the compressed base model itself (when stored in a low-precision format) contributes a few gigabytes. The practical conclusion is simple: reducing the number of trainable parameters alone is not sufficient to bring down peak memory during training, because the intermediate-state gradients and checkpointed tensors remain the main drivers of memory use.

Gradient checkpointing is a technique that trades compute for memory. Rather than retaining all intermediate hidden states throughout the forward pass, checkpointing stores only a subset and recomputes missing states during the backward pass. This reduces peak transient storage at the cost of additional forward computation. The authors emphasize that checkpointing is necessary for large-scale finetuning on limited hardware, but it does not eliminate spikes in memory usage: certain mini-batches with long sequences can still cause transient overflows during optimizer steps. The paper addresses these spikes with a system-level strategy that pages optimizer state to host memory when needed, thereby smoothing out peak usage without changing the training math.

# Why inference-only quantization breaks during training

Quantization methods designed for fast or compact inference convert model weights into a lower-precision representation and then perform computation in a way that preserves output quality. These methods often target a storage format and a set of dequantization rules tailored to the forward pass. Training, however, requires two additional elements that inference-only recipes typically do not provide.

First, training needs gradients that are faithful to the original high-precision computation. If the forward computation uses a coarse discrete representation and the backward computation does not account for the quantization-induced distortions, the propagated gradients may be biased or noisy in ways that prevent the optimizer from finding good solutions. Second, many inference quantization schemes assume larger grouping windows or blocking strategies to control outliers; those same heuristics can create large per-block approximation errors that destabilize gradient propagation.

The work summarized here shows that standard inference quantization techniques can therefore “break down” when placed inside a training loop: loss surfaces and update directions change enough that naively applying those formats prevents successful finetuning. To overcome this, the authors propose a training-aware pipeline: store the pretrained base model in a compact form, but use a higher-precision computation format during the forward and backward passes and restrict actual parameter updates to a small set of added low-rank weights. In other words, the quantized base is frozen for the purposes of parameter updates, but gradients are still propagated through a faithful dequantized view so that the learned low-rank modules receive meaningful signals.

# Parameter-Efficient Finetuning (PEFT) overview and tradeoffs

Parameter-efficient finetuning methods aim to change model behavior by adding or tuning a relatively small collection of extra parameters rather than updating every stored weight of a very large model. The rationale is twofold: keeping the bulk of the pretrained parameters fixed makes sharing and deploying many task-specialized variants cheaper, and optimizing a small trainable subset lowers the steady-state storage cost for each new specialization.

One effective instantiation of this idea is to augment a linear projection with a low-rank correction. If a linear layer computes
\[
\mathbf{Y} = \mathbf{X}\mathbf{W},
\]
a low-rank augmentation introduces a factorized additive term so that the output becomes
\[
\mathbf{Y} = \mathbf{X}\mathbf{W} + s\,\mathbf{X}\mathbf{L}_{A}\mathbf{L}_{B},
\]
where the pair $\mathbf{L}_{A},\mathbf{L}_{B}$ are matrices with small inner dimension and $s$ is a scalar re-scaling factor. The small inner dimension bounds the number of new parameters, making the added storage modest compared with the original $\mathbf{W}$.

Tradeoffs emerge from where memory is consumed during training. The extra matrices themselves occupy little space relative to the frozen base model, but the gradients that flow into those matrices require intermediate tensors and input gradients. As the authors show, the memory needed for these input gradients can exceed the stored size of the trainable matrices by an order of magnitude. Thus, while PEFT reduces the permanent parameter footprint, peak transient memory during training remains substantial because of hidden-state storage and gradient tensors. This is why PEFT methods are most effective when paired with other system- and representation-level strategies: compact storage of the frozen base, a computation format that allows faithful forward and backward passes, and runtime techniques to avoid optimizer-related spikes.

The paper’s practical insight is that because the trainable component is small, one can afford to place such low-rank updates at many locations in the network (for instance, at every linear projection) without a prohibitive increase in permanent storage. This full-coverage placement helps recover the performance of full-model finetuning while preserving the parameter-efficiency benefits.

# Test suites and task landscape: GLUE, MMLU, and instruction tuning

The community uses several well-known standardized tests and curated collections to study model capabilities. One family of tests focuses on single-turn language understanding and classification across a range of narrow tasks; these form the traditional general-purpose suite used to compare models on sentence-level tasks. Another prominent assessment probes broad general knowledge and multi-domain problem solving via a many-task multiple-choice collection that spans subjects such as mathematics, history, and science; models are typically measured with a small number of exemplar context examples for each task and the proportion of correct selections is reported.

Beyond these formal tasks, there is a growing practice of finetuning models with human-curated input–output pairs so that a pretrained model better follows instructions. This instruction-oriented finetuning uses corpora created in various ways: curated multi-turn dialogues collected and cleaned by people, synthetic question–answer pairs produced by an existing large model and then distilled, and aggregated mixtures of many different instruction types. Different curations lead to different behavioral specializations: some collections are oriented toward robust general knowledge performance, others are tailored for helpful conversational responses, and yet others aim for a wide variety of task formats. The paper emphasizes that quality and suitability of these collections matter more than sheer quantity: a relatively small, high-quality human-curated chat collection outperformed a much larger synthetic collection on the measure of conversational response quality used in their study.

For measuring instruction-following or conversational performance, the study used two types of assessments. One is a direct-score relative method in which a reference model is scored and a candidate model is reported as a percentage of that reference’s score. The other is a pairwise tournament methodology in which responses from two different systems are compared on the same prompt and a winner is chosen; repeating such pairwise comparisons and aggregating via a rating system produces an ordering of systems that is often more robust to scale interpretation issues than absolute point scores.

# Resource constraints in academic and consumer hardware

Large pretrained models are increasingly large enough that standard full-precision finetuning requires racks of high-memory accelerators. The paper motivates its method by noting that a full-model finetuning run in the common high-precision format would require many times the memory of a single common workstation GPU. This limits experimental exploration: training many variant models across different data curations and hyperparameter settings becomes infeasible for researchers with only a single GPU or a small group of consumer devices.

The method introduced in the paper dramatically lowers the memory needed to finetune the largest publicly available pretrained models by employing three complementary strategies. First, the frozen base model is stored in a compact, quantized representation that dramatically reduces its on-device footprint. Second, the computation uses a higher-precision format after on-the-fly dequantization so that gradient signals remain meaningful for the small set of trainable low-rank matrices. Third, system-level measures such as automatic paging of optimizer state to host memory are used to avoid rare but large transient spikes that would otherwise cause out-of-memory errors during optimizer updates.

These engineering choices together enable researchers to train very large parameter-count models on a single high-memory workstation or to finetune mid-sized models on consumer devices, thereby widening participation in experimental research and applied prototyping. The paper shows this is not merely an engineering curiosity: with the right combination of compact storage, faithful computation, and parameter-efficient updates, one can match the behavior of full-model finetuning on standard tests while running within drastically smaller hardware envelopes.

Concluding remark

Understanding where memory is spent during finetuning clarifies which levers are effective. Compressing stored weights helps with persistent storage, but peak training memory is dominated by intermediate hidden states and their gradients. In order to enable large-scale finetuning on restricted hardware, a holistic approach is needed: low-precision storage for frozen parameters, a computation format that preserves gradient fidelity, targeted low-parameter updates distributed across many layers, and runtime paging to manage rare spikes. The paper’s experimental program illustrates how combining these ideas makes large-model finetuning achievable on a far broader set of machines than was previously practical.

Quantization for LLMs: From Theory to Practice

# Quantization and dequantization equations; role of scales

Quantization compresses a tensor by mapping its continuous values to a small set of discrete levels. A standard workflow is to rescale the tensor so that its dynamic range matches the representable range of the low-precision format, round to the nearest quantization level, and store the integer-coded result together with a scale factor that allows recovery to higher-precision representation when needed.

Formally, let $\mathbf{X}$ denote a floating-point weight tensor in storage precision for the pretrained model. A simple linear quantizer maps each element of $\mathbf{X}$ to a discrete code tensor $\mathbf{Q}$ using a scale factor $c$ and a fixed integer range $\{-Q_{\max},\dots,Q_{\max}\}$:

\[
\mathbf{Q} \;=\; \mathrm{round}\!\Big(c \cdot \mathbf{X}\Big).
\]

The associated scale factor is chosen so that the representable integer range is matched to the largest magnitude in the block being quantized, commonly

\[
c \;=\; \frac{Q_{\max}}{\mathrm{absmax}(\mathbf{X})}.
\]

Dequantization recovers a higher-precision approximation of the original tensor by dividing the stored integers by the scale:

\[
\widehat{\mathbf{X}} \;=\; \frac{\mathbf{Q}}{c}.
\]

Two points deserve emphasis. First, the scale $c$ is essential: it encodes the mapping from low-bit codes back to a numerical range usable for computation. Second, because $c$ depends on the block being quantized, the scales carry storage overhead in addition to the low-bit codes. Designing efficient formats therefore requires careful treatment of both the codes and their scales.

# Block-wise quantization to mitigate outliers; block size effects

A practical difficulty for uniform rescaling is outliers. If a single element in a tensor is unusually large, the scale selected to accommodate that value will compress the majority of the remaining entries into a few adjacent quantization levels, wasting representational capacity. Block-wise quantization mitigates this by splitting a tensor into contiguous blocks and computing an independent scale for each block. Each block therefore uses the full dynamic range of the low-bit format for its local set of values, reducing quantization error for the typical elements at the cost of storing more scale factors.

Let the flattened tensor have total length $N$ and be split into $n$ contiguous blocks of size $B$, so that $n = N / B$. Quantization on block $i$ uses a local scale $c_i$ and yields a block code $\mathbf{Q}_i$. The dequantized block is then $\mathbf{Q}_i / c_i$, and the full tensor is the concatenation of these dequantized blocks.

Block size $B$ trades off two competing effects. Smaller block sizes reduce the influence of local outliers and thus typically lower quantization error for most elements; they also increase the number of scale factors to store, raising metadata overhead. Larger block sizes amortize the scale storage across more parameters, lowering the metadata overhead but making each block more susceptible to the influence of outliers. Practical systems choose $B$ to balance these effects for the particular model layer statistics and the target precision.

A second related consideration is the distributional match between the block and the quantization levels. If block entries follow a distribution that the chosen codebook was designed to represent well, quantization loss will be small. If the distribution deviates—because of heavy tails, skew, or other structure—then increasing the number of blocks or adjusting the codebook design can be more effective than simply increasing bit width.

# Storage data type versus compute data type; sixteen-bit compute with low-bit storage

A widely used pattern in large model deployments is to separate storage precision from compute precision. The model parameters are stored in a compressed low-bit format to save memory and transfer time, but when those parameters are needed for matrix multiplications they are dequantized into a higher-precision compute format so that the numerical operations remain stable and effective.

Concretely, the stored tensor is the pair $(\mathbf{Q}, \{c_i\})$, where $\mathbf{Q}$ contains low-bit integer-like codes and $\{c_i\}$ are the associated block scale factors. When a forward or backward pass requires a layer weight, the system dequantizes the stored representation into a wider floating representation and performs the linear algebra in that compute format. The training procedure described in the source work uses this pattern: storage is a compact, low-bit format, while matrix products and gradient propagation are carried out in a higher-precision floating-point format so that accumulation error and numerical gradient flow are controlled.

This separation enables memory savings while preserving the numerical behavior of computations. Two practical subtleties arise. First, dequantizing on the fly introduces some runtime overhead relative to keeping the high-precision tensor resident; efficient kernels and careful blocking mitigate this cost. Second, if training needs gradients with respect to stored weights, special handling is required. A common strategy for parameter-efficient update routines is to freeze the stored base weights and learn a small set of trainable low-rank factors that are maintained in the high-precision compute format. During the forward pass the frozen, stored base is dequantized to compute activations; gradients are backpropagated through the dequantization step into the trainable low-rank factors, which are updated in high precision. This retains the benefit of compact storage while allowing meaningful parameter updates.

# Precision–performance trade-offs across high- and low-bit schemes

Reducing bit width typically increases compression but also increases quantization error, which can degrade model behavior. Empirical work shows that carefully designed low-bit formats and per-block schemes can narrow or eliminate that gap for many tasks. Two levers are available to regain lost performance after aggressive compression.

First, format design: codebooks can be optimized to match the empirical distribution of weights. For weight tensors that are approximately symmetric and bell-shaped, quantiles of the standard-normal distribution can be used to place codepoints so that each quantization bin receives roughly the same expected mass; this reduces mean quantization error compared to uniformly spaced integer levels for such distributions.

Second, fine-tuning with compact trainable components can recover information lost during quantization. Rather than directly updating the frozen low-bit base, learning a set of low-rank correction terms (kept and updated in high precision) allows the model to adapt to task-specific requirements without needing to store or update the full high-precision weight tensor. When these low-rank terms are inserted at many linear layers, they provide sufficient capacity to match the behavior of full-format fine-tuning in many cases.

A further engineering innovation reduces the memory footprint of the per-block scales themselves: the scale values can themselves be quantized with a second-stage quantizer, storing compact representations of the first-stage scales. This two-stage, or double, quantization reduces metadata cost while retaining the dequantization pipeline: at use time, the dequantization composes the two inverse steps to reconstruct a sufficiently precise scale for the base dequantization.

The combined picture is that careful codebook selection, block sizing, two-stage handling of scales, and small high-precision correction terms can yield models that retain near the original predictive behavior while reducing stored-parameter memory by large factors. The trade-offs depend on target tasks and model architecture; in some settings, a larger model stored at lower precision can outperform a smaller model stored at higher precision when both fit the same runtime and memory budget.

# Why training through quantized weights is challenging

Training through a quantized representation introduces several numerical and systems challenges. First, most standard optimization routines assume that weights reside in a continuous, differentiable space. Aggressive quantization replaces continuous weights with piecewise-constant mappings from code indices to reconstructed values. Backpropagating gradients through such mappings is nontrivial: the mapping from stored codes to reconstructed values is not differentiable where rounding occurs, and naïvely differentiating can produce zero gradients almost everywhere for the stored codes.

One practical strategy is to freeze the low-bit base weights and only compute gradients with respect to separate, high-precision correction terms. In that case, gradients still propagate through the dequantized base in order to produce correct activations and to allow gradient flow to the correction terms, but the optimizer never attempts to update the discrete codes themselves. Instead, all parameter updates are applied to the high-precision correction factors. This sidesteps the need for gradient estimates of the codes and avoids instabilities that come from trying to update discrete representations directly.

A second difficulty arises from per-block scales and the storage overhead associated with them. Fine-grained blocks reduce quantization distortion but increase metadata and the number of small arrays that must be accessed and potentially moved between main memory and device memory. During training, especially with long sequences or large batches, the activation gradient memory peaks can force paging of optimizer state or intermediate tensors. To accommodate occasional spikes without requiring a prohibitively large device memory allocation, a paged state mechanism uses host memory to hold some parts of the optimizer state and moves pages to the device only when required for updates. This technique enables training large compressed models in environments with limited device memory, but it requires system-level support for efficient page transfers and careful scheduling to avoid runtime stalls.

A final point is numerical fidelity during dequantized matrix multiplication. Even when dequantized values are represented in a wide compute format, the cumulative rounding and representation noise from many low-precision blocks can alter gradient directions and magnitudes. Empirical findings indicate that performing the matrix products in a sixteen-bit floating format with a suitable choice of accumulation precision is sufficient to preserve training dynamics when the stored base is low-bit and the trainable corrections are kept in that same sixteen-bit format.

In practice, combining frozen low-bit base storage, high-precision low-rank correction matrices inserted at many layers, careful block sizing and codebook design tailored to the empirical weight distributions, double-stage scale compression, and page-aware optimizer state handling yields an end-to-end pipeline that permits fine-tuning very large models in memory-constrained settings while keeping the numerical behavior close to that of a full high-precision fine-tune.

# Concluding remarks

Block-wise quantization with per-block scales is a practical approach to compressing large model parameters while keeping most of the useful signal. Choosing the block size, the codebook that matches the empirical weight distribution, and the treatment of the accompanying scales are design decisions with measurable impact. For model adaptation, keeping a compact frozen base and learning small high-precision corrective factors allows gradient-based updates without touching the discrete storage and thus avoids many numerical pitfalls. When combined with systems techniques that move seldom-used state to host memory and efficient dequantization kernels, this approach opens a path to adapting very large models on hardware with limited device memory while preserving the behavior of wider-precision baselines.

Low-Rank Adapters (LoRA) and Memory Implications

# LoRA formulation and intuition (factorized residual projection)
LoRA is a parameter-efficient finetuning technique that models the change to a pretrained linear projection as a low-rank residual. Instead of updating the full dense weight matrix during task-specific tuning, the pretrained weights are kept fixed and a small pair of factor matrices is learned that, when multiplied together, approximate the task-specific update. Concretely, given an input matrix $\mathbf{X}\in\mathbb{R}^{b\times h}$ and an existing projection $\mathbf{W}\in\mathbb{R}^{h\times o}$ producing $\mathbf{Y}=\mathbf{X}\mathbf{W}$, LoRA augments this computation with a factorized residual:
\[
\mathbf{Y} \;=\; \mathbf{X}\mathbf{W} \;+\; s\,\mathbf{X}\mathbf{L}_1\mathbf{L}_2,
\]
where $\mathbf{L}_1\in\mathbb{R}^{h\times r}$, $\mathbf{L}_2\in\mathbb{R}^{r\times o}$, and $s$ is a scalar that controls the overall magnitude of the low-rank update. The hyperparameter $r$ is the factor rank and is chosen to be much smaller than $\min(h,o)$ so that the extra trainable parameters are a tiny fraction of the original projection.

Intuitively, this structure constrains the learned update to lie in a low-dimensional subspace: the task-specific change to the mapping can be written as a linear combination of a small set of basis directions. That makes learning cheaper (fewer free parameters), more stable (smaller search space), and faster to store and transfer. Because the pretrained $\mathbf{W}$ remains frozen, gradients flow through the frozen computation graph to the low-rank factors, which are the only matrices updated by the optimizer.

# Where to apply LoRA modules: attention and MLP layers; all-layer coverage
Linear projections appear throughout transformer architectures. Two natural categories of targets for LoRA-style low-rank updates are the projections inside attention and the projections inside the feed-forward (MLP) blocks.

Within attention, projections that produce queries, keys, values, and the output projection are linear maps whose modification changes how tokens compare, aggregate, and transform information. Early practice often applied low-rank updates only to a subset of these—commonly the query and value projections—because those are intimately tied to the selection and weighting of context. Modifying queries shifts how tokens query context; modifying values changes what gets passed forward once attention weights are computed.

The MLP or feed-forward sublayers contain two major dense projections per block: the expansion projection that maps into a larger intermediate dimension and the contraction projection that maps back. Low-rank updates here alter the nonlinear transformation applied to each position independently, and therefore can be crucial for capturing task-specific refinements of representation geometry.

Empirical evidence shows that restricting low-rank updates to a few projections can limit final task performance for large pretrained models. When the goal is to recover the results of full-model finetuning, distributing LoRA modules to all linear projections inside every transformer block—both attention and MLP components—yields markedly better outcomes. In other words, broad coverage (applying low-rank updates at every linear layer) allows the small, distributed updates to collectively approximate the net effect of full-parameter tuning.

# Memory accounting: LoRA modules versus hidden-state gradients with examples
Understanding where memory is spent during finetuning clarifies why LoRA is storage-efficient in practice. During a typical training step the main contributors to GPU memory are: (a) storage for model weights, (b) optimizer state for trained variables, (c) trainable parameter storage for the added low-rank factors, and (d) gradients of intermediate layer outputs (the per-layer hidden states that must be retained or recomputed for backpropagation). For large transformer models the dominant term during the backward pass is the memory needed for those intermediate-state gradients.

A concrete empirical breakdown (from experiments with a medium-large pretrained decoder model and a minimal sequence batch) illustrates the relative magnitudes. The low-rank factor matrices themselves occupy a very small amount of memory—on the order of a few dozen megabytes when the rank is small. The gradients with respect to the inputs to those low-rank modules (the intermediate-state gradients) are substantially larger, measured in the hundreds of megabytes for a single sequence. By contrast, when the base model weights are stored in a compact low-bit format for storage (and dequantized for computation), the storage cost of the base model can be moderate as well.

A key practical consequence is that shrinking the size of the low-rank matrices further yields only marginal total memory savings: the dominant memory consumer is the set of per-layer intermediate-state gradients needed for backpropagation. Techniques such as gradient checkpointing that recompute some forward activations trade extra compute for reduced memory by avoiding storing all intermediate outputs; this can reduce the required intermediate-state gradient memory to a much smaller per-sequence amount. Even with checkpointing, the low-rank parameters remain a small fraction of the footprint, which explains why one can afford to deploy low-rank updates at many more locations without causing prohibitive memory growth.

# Hyperparameters (r, alpha, target modules) and their importance
LoRA introduces a few design choices that control parameter count, update scale, and placement:

- Rank $r$: This controls the dimensionality of the learned subspace. The number of extra scalar parameters added by a single LoRA module applied to a projection of shape $h\times o$ is
\[
\Delta_{\text{params}} \;=\; h r \;+\; r o \;=\; r(h+o).
\]
Relative to the full projection size $h o$, the fraction added is
\[
\frac{\Delta_{\text{params}}}{h o} \;=\; \frac{r(h+o)}{h o} \;=\; r\left(\frac{1}{o}+\frac{1}{h}\right),
\]
which becomes very small when $r\ll\min(h,o)$. Increasing $r$ gives the model a richer set of update directions at the cost of more trainable variables and modestly more optimizer state.

- Scaling factor $s$ (sometimes parameterized as $\alpha$ and implemented as $s=\alpha/r$): Because the low-rank product $\mathbf{L}_1\mathbf{L}_2$ may have a magnitude that depends on $r$, a scalar multiplier stabilizes learning and controls how strongly the learned low-rank component modifies the frozen projection. Setting the scale appropriately helps match the typical magnitude of the pretrained projection outputs and can improve convergence behavior.

- Target modules (which projections receive LoRA-style updates): This is a crucial practical knob. Applying low-rank updates to a few selected projections is often sufficient for compact tasks or resource-constrained settings. However, when the objective is to fully recover the behavior of dense finetuning on large models, expanding the coverage to include every linear projection inside transformer blocks (both attention and MLP projections) is important. Empirical studies show that the total number of low-rank modules is a more critical factor for matching full finetuning performance than modest changes in $r$ for individual modules.

Other optimizer-level hyperparameters (learning rate, weight decay, and training schedule) remain important, but the distinct property of LoRA is that many of the usual tradeoffs about model size versus memory shift: because most of the memory is spent holding intermediate-state gradients, reasonably raising the number of low-rank modules has a small impact on memory usage relative to the gains in representational flexibility.

# Takeaway: using more LoRA modules yields performance gains with minimal memory cost
LoRA's factorized residual projection provides a principled and compact way to steer a frozen pretrained model toward a downstream task. Because each low-rank update adds only a small number of trainable scalars, the storage and optimizer state overhead is tiny compared to the memory needed for intermediate-state gradients during backpropagation. As a result, expanding LoRA coverage to all linear projections in every transformer block is an efficient strategy to recover the behavior of full-parameter finetuning while keeping the total training memory budget low. In practice, modest choices of rank and a sensible scaling factor, combined with broad placement of LoRA modules, offer a favorable tradeoff: strong task performance with a much smaller set of trainable variables and a manageable memory profile.

QLoRA Architecture and Training Dynamics

# Forward pass: dequantize NFfour weights to BFsixteen, standard matmul, LoRA addition

The forward computation in the QLoRA pipeline separates storage precision from computation precision. Model parameters that come from pretraining are stored in a highly compressed representation designed for minimal footprint; in our description these stored tensors use a NormalFloat scheme tailored for normally distributed weight matrices, which we denote NFfour. At runtime, when the model processes an input, the stored NFfour tensors are turned back into a higher-precision representation suitable for matrix operations and subsequent differentiation. Concretely, each compressed weight block is dequantized into a sixteen-bit floating computation format that we will denote BFsixteen, and this dequantized matrix participates in the usual dense linear projection with the incoming activations.

Beyond the frozen, compressed base weights, the model includes a set of small, trainable low-rank parameter matrices introduced into each linear projection. These low-rank components are learned in the higher-precision computation format (BFsixteen) and are combined additively with the output of the projection that uses the dequantized base weights. The full output of a single linear projection therefore has two contributions: the product of the input with the dequantized base weight, and the product of the input with the low-rank update. Written in compact mathematical form, and using notation that avoids numeric identifiers in subscripts, the forward output for a layer is

\[
Y^{\mathrm{BFsixteen}} \;=\; X^{\mathrm{BFsixteen}}\;\mathrm{doubleDequant}\!\big(c_{\mathrm{A}}^{\mathrm{FPfull}},\, c_{\mathrm{B}}^{\mathrm{FPeight}},\, W^{\mathrm{NFfour}}\big) \;+\; X^{\mathrm{BFsixteen}}\,L_{\mathrm{A}}^{\mathrm{BFsixteen}}\,L_{\mathrm{B}}^{\mathrm{BFsixteen}}.
\]

Here $X$ and $Y$ are the activation and output matrices in the computation format BFsixteen, $W^{\mathrm{NFfour}}$ is the stored compressed parameter tensor, and $L_{\mathrm{A}}$, $L_{\mathrm{B}}$ are the low-rank trainable matrices that realize the effective additive correction to the frozen weights. The dequantization operation restores the compressed representation to BFsixteen so that a standard high-precision matrix multiplication is used for the base contribution, while the low-rank path is computed directly in BFsixteen. This division of labor preserves the numerical stability and expressivity of higher-precision computation while keeping storage costs low.

# Backward pass: gradients flow through dequantization to LoRA only; base weights frozen

During optimization, the training targets only the small low-rank matrices. The large, compressed base parameters remain fixed on disk or in low-precision storage and do not receive parameter updates. Nevertheless, gradients must still pass through the operations that involve the dequantized base weights in order to yield correct updates for the low-rank modules. In other words, the backward computation traces gradients through the dequantization and through the matrix multiplication with the frozen base weights, but the optimizer is instructed to update only the low-rank matrices.

Mechanically, the backward pass computes derivatives of the loss with respect to the low-rank parameters by applying the chain rule through the forward expression given above. Because the dequantization step is differentiable with respect to its inputs in the computation format, the gradient that reaches the interface between activations and base weights is numerically coherent; however, any gradient that would nominally update the stored compressed representation is simply not applied. This design keeps the training memory footprint small: optimizer state and parameter gradients are tracked only for the low-rank updates, which are a tiny fraction of the overall parameter count, while the larger per-layer intermediates needed for gradient computation are transient and handled in the higher-precision computation format.

Two practical consequences follow. First, since the heavy-weight parameters are frozen, their storage can remain in the compressed NFfour format at all times, saving significant resident memory. Second, because gradient computations traverse a dequantization step, the effective backpropagated signals reflect the higher-precision numerical behavior used for computation, which helps preserve learning dynamics for the trainable low-rank matrices.

# Double-dequantization definition and implementation

A key memory-saving refinement in QLoRA is the chaining of two quantization layers for the stored base parameters and their scale factors. The first layer compresses the weight tensor into NFfour values per element together with per-block scaling constants. Those scaling constants themselves are numerous when small block granularity is used, and storing them in full precision could erode the gains from the elementwise compression. To avoid that, the scaling constants are themselves quantized into a coarser representation, and at runtime they are restored via a two-step dequantization that reconstructs the full-precision weight tensor.

We formalize this chain as a function doubleDequant that takes three inputs: a set of higher-precision scale descriptors for the second-level quantization, the low-precision representation of those scale values, and the primary compressed weight tensor in NFfour. The schematic identity is

\[
\mathrm{doubleDequant}\!\big(c_{\mathrm{A}}^{\mathrm{FPfull}},\, c_{\mathrm{B}}^{\mathrm{FPeight}},\, W^{\mathrm{NFfour}}\big)
\;=\;
\mathrm{dequant}\!\Big(\mathrm{dequant}\!\big(c_{\mathrm{A}}^{\mathrm{FPfull}},\, c_{\mathrm{B}}^{\mathrm{FPeight}}\big),\, W^{\mathrm{NFfour}}\Big)
\;=\;
W^{\mathrm{BFsixteen}}.
\]

Operationally, the inner dequantization reconstructs the per-block first-level scales from the compressed representation of those scales. The outer dequantization applies those reconstructed scales to the NFfour element codes to yield a BFsixteen weight matrix suitable for matrix multiplication. To conserve numerical headroom, the implementation centers the second-level inputs (the first-level scales) by subtracting their mean before the second quantization, and uses symmetric quantization so that values above and below the center are treated uniformly. The overall effect is that the storage cost of scale constants is reduced dramatically while the runtime path performs two cheap table-lookups and scaling operations to reconstruct the matrix in computation precision.

From an engineering standpoint, this layered dequantization is implemented as a fused kernel that first reconstructs the scale array at the block granularity and then applies it to the NFfour codes, outputting BFsixteen tiles. Fusing minimizes intermediate memory and avoids repeated global memory traffic. Because the second-level quantization uses a coarser block granularity and a slightly higher-precision floating format for its codes, the accuracy of the reconstructed scales remains high while storage per model parameter falls by a meaningful fraction.

# Default choices: NFfour for weights, eight-bit float for second-level scales

In the QLoRA design, the usual operating point uses a NormalFloat compression for the elemental values of large weight matrices and an eight-bit floating representation for the quantized scale descriptors. The NormalFloat variant is tailored to match the empirical distribution of pretrained parameter elements, which tends to be approximately zero-centered and Gaussian-like when inspected layer by layer. By constructing the elemental codebook from quantiles of a standard normal distribution and then rescaling each weight block into the codebook range, the NFfour scheme ensures each code symbol enjoys roughly equal expected occupancy. This property reduces quantization distortion relative to uniform integer rounding under the same storage budget.

For the secondary quantization of block-level scales, an eight-bit floating format is selected because it offers a compact representation with sufficient dynamic range to capture the variation among scale values across blocks. This choice trades a small amount of representational richness for a substantial reduction in storage devoted to these constants. In practice, this secondary quantization introduces negligible perturbation after dequantization, provided the secondary format is used with a coarser block size than the elemental codes. To reduce bias in the secondary quantization step, the implementation recenters the scale collection before symmetric quantization, as noted above, which reduces systematic reconstruction error.

The combination of NFfour for element codes and an eight-bit floating representation for the second level yields an excellent tradeoff: elementwise reconstruction error is kept low because the NormalFloat codebook matches the per-element distribution, and scale reconstruction error is small because the eight-bit floats still represent the limited dynamic range of the scale array adequately.

# Block sizes: sixty-four for weights, two hundred fifty-six for second-level scales

Block granularity is a crucial hyperparameter in QLoRA because it controls the interplay between representational fidelity and storage overhead for the block-level scales. For the elemental NFfour codes, a relatively small block length allows the per-block rescaling factor to adapt to local variations and prevents outliers from dominating the dynamic range of an entire tensor slice. In the described pipeline, a block length of sixty-four elements per scale value is chosen as the default: this size is small enough to limit quantization error due to outliers, yet large enough to keep the number of scale entries manageable.

For the secondary quantization—the compression of those scale entries—we adopt a coarser block granularity, grouping several adjacent elemental blocks under a single secondary scale quantization code. The recommended grouping length for this second level is two hundred fifty-six elemental positions, which means each secondary-quantized code covers multiple first-level blocks. This hierarchy reduces the sheer count of second-level codes that must be stored and further compresses the set of first-level scales without materially harming reconstructed weight quality.

Choosing sixty-four at the elemental level and two hundred fifty-six at the secondary level is supported by empirical tradeoffs: smaller elemental blocks yield improved fidelity at the expense of more first-level scales, while a suitably larger grouping for the second level recoups storage without introducing notable reconstruction error. Implementations commonly expose these two numbers as tunable parameters so practitioners can trade final model footprint for marginal improvements in reconstructed precision when needed.

# Practical notes on integration and runtime

Putting the pieces together, the runtime kernel for a compressed layer proceeds in three steps: (a) load the NFfour codes for a tiled region of the weight matrix along with the compressed representations of the first-level scales; (b) perform the double dequantization to produce a BFsixteen tile of the weight matrix; and (c) perform a high-precision matrix multiplication between the input activation tile and that BFsixteen weight tile, add the contribution of the low-rank trainable matrices computed in BFsixteen, and forward the result. Memory management is simplified because large parameter tensors are resident in compressed form; only a handful of BFsixteen tiles need to be materialized at any moment during the forward or backward pass.

On the optimization side, since only the low-rank matrices carry gradients and optimizer state, the working set for parameter updates is small. The gradient flow through the dequantization step ensures that these small trainable matrices receive learning signals consistent with full-precision computation. When deploying this pipeline in a training framework, it is important to ensure that the dequantization kernels present a differentiable interface so that automatic differentiation tracks the necessary Jacobian information back to the low-rank matrices; in practice this is achieved by implementing the dequantization as arithmetic sequences of the computation precision rather than opaque lookups that break gradient flow.

This architecture therefore offers a pragmatic route to training large pretrained models with a tiny resident memory footprint while maintaining the numerical fidelity needed for stable learning of the small, high-impact low-rank corrections.

NormalFloat (NFfour): Information-Theoretically Optimal four-level Weight Quantization

# Quantile quantization and information-theoretic optimality

Quantile quantization is a strategy that allocates representable values so that each discrete level receives the same probability mass under an assumed continuous distribution. The key idea is simple and powerful: if you know the distribution that generated your continuous numbers, you can place the boundaries of discrete bins at the distribution's quantiles. Each bin then contains an equal share of the input mass, which minimizes the expected distortion for many common loss measures and is therefore optimal in an information-theoretic sense when that distribution is known.

Formally, let a tensor of real-valued elements be denoted by $X$. A generic uniform-scale quantizer can be expressed as
\[
X^{\mathrm{Q}} = \mathrm{round}\big(s\cdot X\big),
\]
where $s$ is a scale factor that maps the input range into the discrete grid of representable values, and $\mathrm{round}(\cdot)$ maps a real input to the nearest representable index. The inverse operation recovers a continuous approximation via
\[
\mathrm{dequant}(s, X^{\mathrm{Q}}) = \frac{X^{\mathrm{Q}}}{s}.
\]

Quantile quantization departs from uniform-scale practice by choosing representative values (the discrete codebook) from quantiles of a target distribution rather than from fixed uniform levels. Let $M$ denote the count of representable levels. For index $i$ running over the discrete levels, a standard construction of quantile-midpoint representatives is
\[
q_i \;=\; \frac{\mathrm{one}}{\mathrm{two}}\Big( Q_{\mathcal{N}}\!\big( \tfrac{i}{M+\mathrm{one}} \big) \;+\; Q_{\mathcal{N}}\!\big( \tfrac{i+\mathrm{one}}{M+\mathrm{one}} \big) \Big),
\]
where $Q_{\mathcal{N}}(\cdot)$ is the quantile function (inverse cumulative distribution) of the reference distribution. If the reference distribution equals the true generator of the data, these $q_i$ give an allocation of representable levels that equalizes the probability mass per level and thereby achieves minimal expected distortion under many standard loss measures.

This principle is what motivates NormalFloat: when the tensor elements are well modeled by a zero-centered normal law, the quantile representatives that come from that normal law are the information-theoretically appropriate choices.

# Why pretrained weights are approximately normal and zero-centered

Large neural network weights, after standard initialization and long optimization, tend to settle into empirical distributions that are sharply peaked around zero and whose tails resemble those of a Gaussian. This behavior is observed across many architectures and is documented for pretrained transformer weights in the study that introduced NormalFloat. Intuitively, weight values are pushed toward modest magnitudes by regularized optimization and by the cumulative effect of many independent contributions during training; the central limit effect and symmetric regularizers yield distributions that are roughly symmetric and bell-shaped.

Two properties are important for NormalFloat to be appropriate. First, symmetry about zero: the empirical mean of many weight tensors is essentially zero. Second, predictable spread: the standard deviation of a tensor can be measured and then used to rescale that tensor so its distribution aligns with the reference distribution used to design the quantization codebook. When those conditions hold, the quantile representatives precomputed for a standard normal law will match the empirical quantiles of the scaled tensor closely, minimizing quantization error.

# Precomputing quantiles from $\mathcal{N}(0,\mathrm{one})$ and normalizing to $[-\mathrm{one},\mathrm{one}]$

NormalFloat leverages the observation above by precomputing a codebook of quantile-midpoint values for the standard normal distribution $\mathcal{N}(0,\mathrm{one})$. Because the quantile function of a standard normal is fixed and inexpensive to evaluate once, one may compute the set $\{q_i\}_{i=0}^{M-\mathrm{one}}$ in advance and reuse it for every weight block after appropriate scaling.

The practical pipeline is this. For a given weight block $W$ with empirical standard deviation $\sigma_W$, compute a scalar rescaling factor $r$ so that the spread of $r\cdot W$ matches the canonical interval used by the codebook (for NormalFloat the codebook values are normalized into the interval $[-\mathrm{one},\mathrm{one}]$). Concretely, pick $r$ such that the absolute maximum of $r\cdot W$ falls within $[-\mathrm{one},\mathrm{one}]$; this is the usual absolute-maximum rescaling used in block-wise quantization. After rescaling, quantize each element to the nearest precomputed $q_i$ and store the index (or an index encoding). At runtime, dequantization uses the same precomputed codebook and the stored scale $r$ to recover a continuous approximation:
\[
\hat{W} \;=\; \frac{1}{r}\,\sum_i \big( \mathbf{1}_{\text{index}=i}\cdot q_i \big).
\]
Because the $q_i$ were designed to be the quantile-midpoints of the standard normal, this procedure minimizes the mismatch between the quantized representation and the original distribution for weight blocks that, after rescaling, closely follow $\mathcal{N}(0,\mathrm{one})$.

This precomputation step removes the need for expensive block-wise quantile estimation at quantization time. When weights conform to the assumed distribution up to a scalar, the same global codebook can be applied across blocks, yielding a compact representation while retaining fidelity.

# Asymmetric binning to include an exact zero

A practical subtlety arises from representing exact zeros. Padding elements and any literal zero entries should be representable without rounding error. A symmetric quantile construction for a symmetric distribution can leave no discrete codebook entry exactly at zero, which would cause even exact zeros to be approximated by a small nonzero representative and introduce unwanted error.

To remedy this, NormalFloat uses an asymmetric bin allocation around zero so that the discrete set includes a code value exactly equal to zero. The construction proceeds by allocating $M_{\mathrm{neg}}$ representatives for the negative half and $M_{\mathrm{pos}}$ representatives for the positive half, with
\[
M_{\mathrm{pos}} = M_{\mathrm{neg}} + \mathrm{one},
\]
so that when the two sets are merged there is a single zero representative shared at the boundary. The negative side quantiles are taken from the lower portion of the standard normal, the positive side from the upper portion, and the two sequences are concatenated with the duplicate zero removed. This ensures the representation can encode zero perfectly while preserving the equal-probability motivation on each side of the origin as closely as possible.

This asymmetric binning is particularly important in models where sparse patterns arise or where padding tokens and zeroed activations appear frequently; exact zero representation avoids systematic bias from rounding such values.

# Empirical results: NFfour versus FPfour and Intfour on language modeling and zero-shot tasks

The design choices above yield concrete improvements in practice. When the precomputed normal-quantile codebook is used with block-wise rescaling and the asymmetric zero-inclusive construction, the resulting NormalFloat quantization outperforms other low-precision schemes that use uniform floating representations or integer grid quantizers with the same storage cost. In controlled experiments on language modeling and on a collection of zero-shot tasks, models quantized with NormalFloat show lower perplexities and higher task-level success rates than models quantized with uniform small floating formats or integer schemes at comparable storage pressures.

These gains are visible across multiple families of transformer weights studied in the source study, including decoder-only and encoder-decoder variants, and across a range of model scales from the hundreds of millions parameter regime up to models with tens of billions of parameters. The improvement is particularly pronounced when block sizes are small, because NormalFloat's information-driven allocation of representable values mitigates the outlier problem that plagues uniform quantizers in that regime.

An additional practical point: NormalFloat integrates well with further memory-reduction techniques, such as quantizing the per-block scale constants themselves with a secondary, coarser quantizer, without measurable harm to downstream text generation and classification performance. That combination preserves the fidelity gains of NormalFloat while shaving additional storage overhead.

Taken together, the theoretical grounding in quantile optimality for a normal law, the match to the empirical shape of pretrained weight distributions, the pragmatic asymmetric treatment to include an exact zero, and the precomputation of a standard-normal codebook explain why NormalFloat yields reliable, measurable gains when compressing network weights for language modeling and related zero-shot tasks.

Double Quantization: Compressing the Scales

# Motivation: scale memory overhead

When a tensor is quantized in small contiguous groups, each group needs a small auxiliary value that rescales the compact representation back into the original numeric range. These auxiliary values are typically stored in a full-precision floating format and are allocated once per group. For large models and for small group sizes, the per-parameter cost of storing these rescaling values can be nontrivial: the storage devoted to those rescalers grows inversely with the group length, so choosing finer grouping for better representational fidelity increases the relative weight of those constants.

To make this concrete without relying on raw numerals, imagine a storage type for the scales that is a commonly used full-precision float with a fairly wide binary representation. If that wide float is shared among a moderate-sized group of parameters, the cost per parameter is the wide float width divided by the group length. For typical design choices that pair a wide floating type with a modest group length, the overhead for these scale values can be on the same order as many other small optimizations in model storage. This overhead therefore motivates exploring ways to compress the rescaling values themselves so that the dominant quantized weights remain compact without paying a large penalty for their per-group multipliers.

# Two-level scheme: quantizing the per-block scales

Double quantization adopts a hierarchical approach: treat the collection of per-group rescalers as another tensor that can itself be quantized. Concretely, the first stage operates on the model parameters and produces compact encoded groups plus one rescaler per group. The second stage treats the vector of those per-group rescalers as data to be encoded using a smaller, lower-cost floating format and a coarser grouping for its own per-group reference values. In other words, to store a quantized weight block you keep the compact block representation plus a small low-precision code for that block's rescaler, and you keep a tiny set of higher-precision references that let you reconstruct the low-precision codes into the original wide rescalers when needed.

Formulating this in a compact notation helps clarify the flow without invoking specific numeric labels. Let $W^{\text{q}}$ denote the compact representation of the parameter block data, let $c_{\text{low}}$ denote the per-block rescaler codes stored in the low-cost float format, and let $c_{\text{high}}$ denote the small set of high-precision references used to reconstruct those codes. A two-stage dequantization therefore reads as
$\text{doubleDequant}(c_{\text{high}}, c_{\text{low}}, W^{\text{q}}) \mapsto W^{\text{comp}}$,
where the low-level codes are expanded using the high-level references and then applied to the compact weights to yield the computation-friendly representation. This design moves most storage into the compact block encodings and compresses the scale metadata aggressively by exploiting the fact that those scale values are themselves low-entropy relative to full-precision storage.

# Centering scales for symmetric coding

A practical wrinkle arises because the rescaler values produced by the first quantization stage are strictly positive and often form a narrow range around their mean. Many efficient low-precision encodings rely on symmetric codebooks that assume inputs are distributed around zero; when values are strictly positive, symmetric encoders waste representational capacity or require an explicit offset. To make the second-stage encoding more efficient, double quantization subtracts a small shift from the rescaler vector to center it around its mean before applying symmetric low-precision coding.

Formally, if $c_{\text{low}}$ is the vector of per-block rescalers, compute a shift value $\mu$ that is the arithmetic mean of $c_{\text{low}}$ across a chosen grouping. Then use $c_{\text{shifted}} = c_{\text{low}} - \mu$ as the input to the symmetric low-cost float encoder. During reconstruction, add $\mu$ back after expanding the low-cost codes with the shared high-precision references. Centering in this way makes the low-cost float representation more efficient and reduces quantization error for the most common values, because symmetric codebooks devote equal resolution to positive and negative deviations around the mean.

# Memory savings calculation

It is helpful to express the storage budget of the scale metadata in symbolic terms and then substitute typical design choices to see the pay-off. Let $W$ denote the width in binary places of the high-precision float used for per-block rescalers in the naive design, and let $B$ denote the group length of parameters that share each such rescaler. The naive per-parameter overhead is therefore $\frac{W}{B}$ binary-place units for the rescalers.

In the double-quantized design the overhead has two contributions. First, the low-cost float that encodes the per-block rescaler codes consumes $w_{\text{low}}$ binary-place units per code, so its per-parameter share is $\frac{w_{\text{low}}}{B}$. Second, the small set of high-precision references that restores the low-cost codes can be shared across multiple of those codes; if the second-stage grouping size for those references is $B_2$, the high-precision references contribute $\frac{W}{B \cdot B_2}$ per parameter. Putting those terms together yields the per-parameter rescaler overhead under double quantization:
\[
\frac{w_{\text{low}}}{B} \;+\; \frac{W}{B \cdot B_2}.
\]

To illustrate with commonly chosen formats, substitute worded numerals. Take a wide high-precision float with width "thirty-two" binary places for the original rescalers, a low-cost float with width "eight" binary places for the second-stage codes, a parameter group length of "sixty-four", and a second-stage reference group length of "two hundred fifty-six". The naive overhead is
\[
\frac{\text{thirty-two}}{\text{sixty-four}} = \text{one half}
\]
per parameter in binary-place units. The double-quantized overhead becomes
\[
\frac{\text{eight}}{\text{sixty-four}} + \frac{\text{thirty-two}}{\text{sixty-four}\cdot\text{two hundred fifty-six}}.
\]
Evaluating those worded fractions yields a total near the verbal form "zero point one two seven" per parameter. Subtracting this from the naive "one half" gives a savings that verbally evaluates to about "zero point three seven three" binary-place units per parameter. That is, the scheme reduces the auxiliary storage devoted to per-block rescalers by a substantial fraction while leaving the main compact parameter encoding intact.

# Empirical finding: negligible effect on task results

A central concern when compressing any metadata used in reconstruction is whether the added approximation introduces noticeable harm when the model is used in downstream tasks. Empirical checks using common test suites and generation scenarios show that applying the two-stage scale compression and centering procedure described above does not produce a meaningful decline in task results. In practical terms, the small rounding and reconstruction error introduced by the low-cost float codes and the sparse set of high-precision references remain well below the level at which they affect model outputs for typical prompting and scoring protocols.

This empirical robustness comes from two complementary factors. First, the rescaler values tend to vary smoothly across groups and occupy a narrow range, so the second-stage low-cost coding captures the dominant variation with little residual. Second, the high-precision references are shared at a coarse granularity, which keeps a small corrective term available to undo systematic bias in the low-cost codes. Together, these design choices let one compress the per-block scales aggressively and reclaim storage that would otherwise be devoted solely to those wide-format rescalers, with negligible practical impact on the model's observable behavior.

# Practical notes and trade-offs

Double quantization adds a small amount of implementation complexity: the run-time must support the two-stage reconstruction path and a lightweight mechanism for computing and storing the second-stage grouping statistics and shifts. In return, the approach removes a recurring storage term that grows with decreasing group length, enabling the use of finer grouping in the primary quantization stage without incurring a proportionally large metadata penalty.

In practice, choosing the low-cost float width and the grouping sizes for both stages permits a smooth trade-off between minimal additional reconstruction error and larger memory savings. Centering the rescaler vector prior to symmetric encoding is an inexpensive step that often boosts the utility of the low-cost codes. Empirically, when these choices are made in sensible ranges, the memory reclaimed is substantial while the impact on downstream task results is imperceptible for typical model workloads.

Paged Optimizers: Stability Under Memory Spikes

# Unified memory overview: GPU to host paging analogy
Modern accelerators provide a mechanism that unifies the address space between device memory and host main memory. Conceptually this behaves like virtual memory in an operating system: large objects are broken into pages, and the runtime moves pages on demand between the fast device memory and the larger-capacity host memory. When a piece of data that resides on host memory is referenced by a kernel running on the device, a page migration is triggered and the runtime copies that page into device memory. The copy is transparent to the program: the program continues to issue kernels and the runtime handles the page transfers behind the scenes.

This transparency is powerful because it eliminates hard out‑of‑memory failures caused by occasional transient peaks. Instead of requiring all training state to fit permanently in device memory, the system can keep large but infrequently used portions on the host and bring them in only when needed. The tradeoff is latency and bandwidth: each migrated page must traverse the interconnect between host and device, so page transfers are far slower than fully local accesses. For training systems the design goal is therefore to place large, seldom‑used arrays on the host while keeping latency‑sensitive arrays resident on the device.

# Why spikes occur: long-context groups of examples and checkpointing
Training large sequence models creates two kinds of memory demands that can cause short lived spikes. First, long input contexts multiply the size of activation tensors: every token in a long context produces intermediate activations that must be held until they are consumed by the backward pass (unless recomputed). As context length increases, the activation term becomes the dominant contribution to peak memory.

Second, recomputation strategies such as gradient checkpointing trade extra compute for lower steady memory use by discarding some activations during the forward pass and recomputing them on demand in the backward pass. While checkpointing lowers the steady footprint, it creates transient high memory demand at particular moments: during recomputation the runtime may need temporary buffers and intermediate outputs in addition to the normal backward storage, producing spikes that exceed the average footprint.

A further contributor is the optimizer update step. Many modern optimizers keep extra per‑parameter state — momentum estimates, second moment estimates, and sometimes additional preconditioners. Those auxiliary arrays can be larger than the model parameters themselves. Even when those optimizer arrays are not frequently used during the forward or most of the backward computation, the update step needs them present, producing another peak when the step executes.

Because spikes can be sudden and brief, they are the usual cause of out‑of‑memory failures even when the steady working set would nominally fit in device memory.

# Paging optimizer states only; training remains error‑free
Paged optimizers exploit unified memory by placing optimizer state arrays in pageable host‑backed memory while keeping model weights and latency‑sensitive activations resident on the device. The key idea is that most optimizer state is not needed during the forward pass and much of the backward pass; it is only needed during the optimizer update. By assigning optimizer state to pageable storage, the device can evict those pages to host memory when device memory is tight and bring them back only when the update begins.

From a correctness viewpoint nothing changes: the forward and backward computation still see the same logical arrays. The runtime ensures pages are migrated as needed, so numerical results and gradient propagation remain unaffected. In practice the training loop behaves as follows. During the forward and backward passes, the device works with weights and activations that are permanently resident. When it is time to apply the optimizer update, the pageable pages containing optimizer buffers are migrated into device memory on demand, used to compute parameter updates, and then allowed to be evicted again. If the interconnect supports concurrent copies, migration can overlap some communication and computation; otherwise the update step pays the full transfer latency.

It is useful to formalize peak memory contributions. Let
\[ M_{\text{total}} = M_{\text{model}} + M_{\text{activations}} + M_{\text{optimizer}} + M_{\text{work}} \]
denote the total peak device memory obligation without paging. With paged optimizer state, the steady device allocation becomes
\[ M_{\text{steady}} = M_{\text{model}} + M_{\text{activations}} + M_{\text{work-reserve}} \]
where only a small fraction of optimizer state needs to be resident at any given moment. The optimizer state still exists logically, but most of it resides in host memory until the update. The runtime thus prevents transient peaks that would otherwise exceed device capacity and cause an error.

# Runtime observations on large models and when slowdowns may occur
When this technique is applied to very large models it enables training runs that would otherwise fail with hard memory errors. In practical studies, paging optimizer state allowed single‑device training of models that would not fit into device memory under conventional allocation rules. Under typical training regimes — moderate context lengths and modest groups of examples per update — the overhead from moving optimizer pages is small compared to overall training time, because optimizer pages are touched only once per update and the interconnect transfers fit into the otherwise idle time at synchronization points.

Slowdowns appear when page migrations become frequent or when the size of the migrated working set grows relative to the available interconnect bandwidth. Two situations cause noticeable slowdown. The first is very long contexts combined with large training groups, which increase the frequency of optimizer updates that need large optimizer buffers in device memory and thus trigger repeated large transfers. The second is a schedule with many fine‑grained updates (very small compute per update), which increases the ratio of transfer time to compute time and makes migration overhead visible.

The exact magnitude of the penalty depends on bus throughput and latency, host memory speed, and whether the driver and runtime can overlap transfer and compute. On systems with high bandwidth links and efficient page migration, the measured training speed with paged optimizer state can be essentially indistinguishable from an all‑device allocation for common training setups. On systems with constrained interconnects or when training uses very long sequences or high per‑update work, a non‑negligible slowdown can appear.

# Practical tips for group size, sequence length, and checkpointing
Design choices in the training recipe influence both stability and runtime. The following practical guidelines are grounded in the behavior observed when paging optimizer state:

- Favor modest groupings of examples per update. If device memory is tight, prefer accumulating gradients across several small groups rather than processing a single very large group at once. This reduces the size of temporary working sets and lowers the peak activation footprint during recomputation steps.

- When using long contexts, reduce the number of sequences processed in parallel. Long sequences inflate activation storage linearly with length, so trading a degree of parallelism for shorter per‑step memory demand often yields a better throughput vs memory trade.

- Use checkpointing patterns that limit recomputation peaks. Checkpointing reduces average memory but can create brief spikes; choose a checkpoint granularity that keeps recomputation buffers small. In many cases a slightly coarser checkpointing plan lowers overall runtime because it reduces repeated recompute overhead and limits transient peaks.

- Reduce optimizer state size where possible. Select optimizer hypervariants with fewer auxiliary arrays when memory is constrained, or use lower precision for optimizer buffers if numerical stability allows. Because those arrays are the target of paging, shrinking them reduces transfer volume and therefore paging overhead.

- Pin or prefetch pages when supported. If the runtime or driver provides explicit asynchronous prefetch primitives, use them to bring optimizer pages into device memory just before the update step. This prefetching hides transfer latency behind computation and reduces stalls.

- Monitor page fault frequency and transfer volume. Keep an eye on how often the runtime migrates pages and the average amount transferred per update. If page faults dominate, consider reducing per‑update working set, changing checkpointing granularity, or moving more state to host by design.

- Test on the target system with representative sequences. The interaction of sequence length, compute per update, and interconnect performance is system dependent. Profiling with workloads that match expected production conditions gives the best guidance for tuning.

In summary, paged optimizer state is an effective technique to eliminate transient out‑of‑memory failures induced by long contexts and checkpointing. It preserves numerical training correctness while trading occasional page migration latency for the ability to train large models on a single device. With careful selection of group size, checkpointing strategy, and optimizer state representation, the runtime cost can be minimized so that training proceeds with near‑native speed in common scenarios.

Experimental Design and Baselines

# Models: RoBERTa, T5, LLaMA from seven-billion to sixty-five-billion parameters

This work compares three families of network architectures to cover the canonical encoder, encoder–decoder, and decoder-only paradigms. For encoder models the study uses a RoBERTa variant that represents the common transformer encoder style. For encoder–decoder experiments the T five family is employed, matching prior work that uses this architecture for multitask supervised instruction tuning. For the core scaling and instruction-following investigations the LLaMA family is the central focus, spanning from a seven-billion parameter member up to a sixty-five-billion parameter member. The LLaMA series provides a controlled path for scale studies because the same architectural template is used across sizes, allowing the experiments to attribute observed gains to scale, finetuning recipe, or data choices rather than to structural differences.

Across the model families the experimental design keeps the pretrained base weights frozen when adapter methods are used, and otherwise performs full-parameter updates for reference comparisons. For adapter experiments the adapters are inserted into linear projections throughout the transformer stacks rather than only in a small subset of locations; this placement decision is motivated by empirical findings described below that show dense insertion recovers full-parameter outcomes more reliably at larger model sizes.

# Data collections used for finetuning and assessment

The experimental program uses a small set of well known held-in tasks for controlled method comparisons, and a broader set of instruction-style collections for the chatbot-oriented work. For controlled method comparisons the GLUE suite is used for encoder evaluations and a large multitask instruction assembly (Super-NaturalInstructions) is used for encoder–decoder tuning. For the large-scale instruction finetuning and chatbot work the study draws from a curated set of eight heterogeneous instruction collections. These eight include crowd-created multi-turn interactions, collections produced by human preference work, distilled outputs from previously tuned models, and large aggregations that mix multiple sources. Representative names in this group include the open multi-turn exchanges collected by the community project commonly used for chat training, the human preference conversation traces used by several teams, distilled-alike synthetic instruction sets such as the Alpaca-style collection, and aggregated public instruction mixes such as FLAN version two and two other long-form or hybrid corpora. The selections were chosen to span differences in size, curation method, multilingual content, and intended use case, enabling a study of how data composition and quality influence final conversational skill.

When an instructional source contains multi-turn structure, the finetuning procedure preserves that structure for multi-turn modeling. For some collections that provide several candidate replies for a single prompt, the training recipe selects top responses along tree-structured conversations to create coherent supervised examples that include the instruction and prior context. For certain largescale aggregated collections a subsampling strategy is used when necessary to match computational budgets while retaining quality signals. All supervised finetuning uses standard cross-entropy training on the target text tokens; reinforcement style machine preference or policy gradient training is not used in this work so that gains are attributable to the finetuning recipe and data choices rather than to human-feedback style optimization.

# Metrics and settings: five-shot MMLU, Vicuna and OA prompt suites, sampling settings

To quantify language understanding the study uses the Massively Multitask Language Understanding test. Performance on that suite is reported in a few-shot protocol: for each task a small set of exemplars are provided in the prompt (the standard few-shot style) and the models are scored by the fraction of held-out multiple-choice items they select correctly. For conversational capability the work uses two curated prompt collections. One is the set used by the Vicuna-style comparison; the other is a large validation split drawn from the open multi-turn assistant collection introduced above. The Vicuna-style set is a compact, diverse prompt set covering many categories. The open-assistant validation set provides a larger, multilingual, multi-turn stream of real user-style queries.

During generation experiments all models are sampled with nucleus sampling using a retained probability threshold of point nine and a temperature of point seven. These settings are applied uniformly across methods to keep generation variance comparable. For the few-shot reasoning and multiple-choice tests the sampling is deterministic when required by the scoring protocol; when generation randomness could affect a comparison the same sampling seeds and configurations are applied to both the base and the tuned models to ensure fair head-to-head comparisons.

# Reference methods for comparison: full-parameter finetuning, sixteen-precision adapters, eight-level and four-level quantized storage formats

The experimental design compares the proposed low-precision adapter recipe against several established reference procedures. The primary reference is full-parameter finetuning under a high-precision numeric format commonly used for training. This reference establishes the target performance that the memory-saving methods aim to match. A second reference is adapter tuning executed with the same high-precision compute format, using the popular low-rank adapter mechanism. These two references allow the study to separate gains originating from selective parameter updates from limits imposed by low-precision storage.

On the quantization front, the work contrasts different storage forms for the frozen base model weights. One set of runs stores parameters in a coarse four-level quantization, another uses an integer-style four-level mapping, and another uses eight-level quantization. The novel NormalFloat four representation introduced in the study is evaluated directly against a conventional four-level floating mapping and a four-level integer mapping in post-quantization tests and after adapter tuning. Where storage is low-precision the compute numeric format for dequantized tensors is kept at a higher training-friendly format so that forward and backward passes through the frozen base use elevated compute fidelity even while on-disk storage remains compact.

# Hyperparameter search and an important caveat about default adapter placements

A rigorous hyperparameter search is applied to find robust reference settings and to ensure fair comparisons. For the reference full-parameter finetunes the search explores learning rate orders from one times ten to the power of negative six up to five times ten to the power of negative five, and mini-batch scales spanning from small to large until an optimal throughput–stability tradeoff is found for each model size. The adapter experiments use a smaller but targeted sweep focused on learning rate and effective batch size, and maintain the same optimizer family and weight decay conventions so that behavior differences can be ascribed to the adapter mechanism and storage format rather than to optimizer mismatches.

A key empirical finding is that the common practice of inserting low-rank adapters only into a few attention projections does not reliably reproduce full-parameter finetuning at larger model sizes. When adapters are applied only to a subset of attention matrices, recovered task performance lags. By contrast, placing adapters within every linear projection across transformer blocks restores the vast majority of full-parameter outcomes. In other words, dense adapter placement across layers is a crucial implementation detail for large models when striving to match high-precision finetuning effects while keeping the number of trainable parameters small. The projection rank of the adapters matters less than coverage: modest rank values suffice when adapters are present throughout the network. Gradient checkpointing and appropriate optimizer state placement are also essential to fit large-scale adapters into a single device memory envelope.

# Assessment protocol: GPT four scoring, head-to-head judgments, controlling for ordering, and tournament aggregation

The conversational assessment protocol uses two complementary judgment styles. The first is a score-based comparison where an advanced model termed GPT four is prompted to rate two responses — the reference Chat-like system and the candidate model — on a scalar scale with a ten point granularity, and to provide a rationale for the score. To mitigate a pronounced ordering bias in these machine judgments, each prompt pair is scored with both possible presentation orders and the mean of the two results is taken as the reported relative score. This simple control reduces the tendency of the judge to favor the response shown first.

The second judgment style is head-to-head selection. For each prompt two responses are shown and a judge declares the preferred response or that the pair is a tie. These ternary judgments — prefer left, prefer right, tie — are gathered both from the GPT four judge and from human raters recruited on a crowdworking platform. In the human-rated tasks the protocol uses two human raters for comparisons against the Chat-like reference and three raters for pairwise candidate comparisons. Human raters are asked to follow consistent guidelines emphasizing helpfulness, correctness, and safety when making their choices.

To convert the many pairwise judgments into a global ranking the study employs a tournament-style aggregation using an Elo method. Each model begins at a fixed initial rating; after each sampled match the rating update is proportional to the surprise of the outcome relative to the expected win probability. The update parameter is chosen to balance stability and responsiveness, and the tournament resampling is repeated many times with different random seeds to control for ordering and match-sampling noise. This tournament aggregation produces a single scalar skill-like number per model that facilitates comparisons across diverse prompt sets and judgment sources.

# Practical details that influence comparability

To ensure fair head-to-head trials, the same prompt formatting, context window inclusion rules, and generation settings are applied across all systems compared in a given experiment. When using distilled training collections that originated from a powerful proprietary assistant, the study takes care to separate examples that could overlap verbatim with evaluation prompts by performing fuzzy string matching and manual inspection when potential leakage is found. The finetuning runs that form the core of the comparisons are supervised cross-entropy only; no preference-based policy optimization is applied so that observed differences reflect the finetuning recipe, data composition, and numeric formats under study.

Finally, the experimental program reports both the task-level proportions correct on multiple-choice suites and the tournament-derived Elo numbers for conversational judgments, and highlights instances where the two kinds of assessment diverge. That divergence is informative because strong performance on classroom-style multiple-choice tests does not always translate to superior conversational behavior on real user prompts; this finding motivates the dual assessment approach used throughout the reported work.

Core Empirical Findings: Matching sixteen-bit with four-bit QLoRA

# NF four yields appreciable gains over FP four and Int four; double quantization preserves task-level results

A central technical contribution that underpins the empirical results is a four-bit data representation tailored for the typical distribution of pretrained weights. Pretrained transformer weights are tightly concentrated around zero and closely follow a bell‑shaped distribution. The Normal‑Float four scheme exploits that structure: rather than treating all tensors as arbitrary and estimating distributional quantiles from the raw entries, it constructs quantization levels derived from the theoretical quantiles of a standard normal distribution and then rescales each block of weights into the data type range. This produces quantization bins that are used with nearly equal expected frequency when the underlying values follow a centered normal law, which improves representational use of the available four‑bit codepoints for neural weights.

Practically, this design reduces systematic distortion of small magnitude weights and provides a discrete representation that includes an exact zero codepoint, which is important for padding and other truly zero elements. Compared to conventional four‑bit floating schemes and simple integer rounding, the normal‑tuned codebook reduces harmful rounding of frequently occurring small values and better preserves the relative ordering of midrange weights. When the quantized model is assessed on generative language modeling and on zero‑shot classification tests, the normal‑tuned four‑bit format consistently produces lower language modeling loss and higher task scores than the other four‑bit choices examined.

Reducing memory further without degrading model behavior is achieved with a second trick: quantize the scale parameters themselves. Because storage for per‑block rescaling factors can represent a nontrivial overhead when block granularity is fine, those scale values are stored at lower precision in a second quantization pass with a larger block grouping. This two‑step compression lowers the average storage per parameter by a few tenths of a bit, which translates into multiple gigabytes saved for very large models, while leaving the dequantized weights used at compute time virtually unchanged. In other words, the double quantization stage preserves downstream scores while shrinking the memory footprint of the quantization metadata.

# QLoRA recovers sixteen‑bit full finetuning up to modest scales and matches sixteen‑bit LoRA across large scales

The practical question for any low‑precision finetuning recipe is whether reducing storage precision for the frozen base model can be made compatible with high‑quality adaptation. QLoRA answers this by combining frozen, quantized base weights with a small set of learnable low‑rank updates (the LoRA low‑rank factors). During both forward and backward passes, the frozen weights are dequantized into a higher precision compute format and gradients are propagated through those dequantized values into the learnable low‑rank parameters. Crucially, full weight updates are not computed; only the compact LoRA factors are trained.

Across a set of controlled comparisons, this procedure reproduces the behavior of full precision finetuning for smaller reference models and matches the performance of sixteen‑bit LoRA finetuning for much larger models. For encoder and encoder‑decoder models up to a few billion parameters, QLoRA recovers the task scores of full precision finetuning on classification suites and on instruction following corpora. For decoder‑only family models scaled from the moderate to the very large range, QLoRA with the normal‑tuned four‑bit storage and double compression reaches parity with the same LoRA recipe executed in a sixteen‑bit setting. In short, quantizing the frozen backbone to a carefully designed four‑bit representation does not prevent the low‑rank finetuning mechanism from regaining the behavior of higher precision training when the LoRA updates are placed and sized appropriately.

An additional empirical point is that using a naïve four‑bit floating representation as the storage format produces a measurable gap relative to the sixteen‑bit reference performance; the normal‑tuned four‑bit type closes that gap. The double quantization step that compresses scale factors also shows no degradation in the measured task scores, confirming that the metadata compression is a safe memory saving.

# Placement of LoRA low‑rank updates: apply them to all linear projections to match full finetuning

A further practical lesson concerns where to insert the trainable low‑rank factors. Early practice applied low‑rank updates only to a few attention projection matrices, typically the query and value projections. While that economical placement reduces the number of trainable parameters further, empirical tests show it can leave a performance gap when compared to updating the full model in higher precision. The decisive factor is the coverage of linear mappings that receive low‑rank correction: applying LoRA‑style low‑rank factors to every linear projection inside the transformer blocks — attention projections, output projections, and feed‑forward linear layers — closes the gap and reproduces the scores of full finetuning.

This finding aligns with memory‑use considerations. The storage footprint of the low‑rank parameters themselves is tiny relative to the tensors that dominate runtime memory, namely the layer output buffers and their gradients. Therefore, expanding the set of places where low‑rank modules are inserted increases representational flexibility for the finetuning process at little practical cost. The rank hyperparameter of the low‑rank factors is comparatively less sensitive: moderate ranks suffice when the modules are applied broadly. In practice, enabling low‑rank updates at every linear mapping combined with gradient checkpointing and the paged optimizer strategy yields the best recovery of the reference behavior.

# Training corpus quality dominates collection size for instruction tuning

One of the clearest empirical patterns observed when tuning models for instruction following and conversational behavior is the outsized role of training corpus quality. The study compared finetuning on multiple instruction collections that varied widely in construction method, supervision signal, and scale. A relatively small collection assembled through careful human‑curated multi‑turn interactions produced stronger conversational models than much larger aggregated instruction corpora that were compiled from heterogeneous sources or created via automated distillation.

Why does this occur? Large collections assembled from many heterogeneous origins can include noisy or mismatched examples with labeling conventions and response styles that differ from the intended deployment setting. A small, high‑quality corpus that is closely aligned with the desired conversational format gives the model a clearer signal about how to map prompts to helpful, safe, and well‑formed responses. Empirically, finetuning on such a high‑quality set led to leading performance on conversational prompt sets even when the total number of examples was far smaller than in competing collections.

This does not imply that scale is irrelevant; rather, it highlights that for instruction following the match between the training material and the target interactive behavior matters substantially. Practitioners should prefer curated, representative examples over raw scale if the goal is a chatbot that follows prompts in a user‑expectable style.

# Partial orthogonality between academic knowledge tests and chat performance

Another recurring empirical theme is that strong results on broad knowledge‑type tests do not automatically translate into superior conversational performance. Models finetuned on collections optimized for factual coverage and multi‑task reasoning tend to show improved scores on standard knowledge and reasoning test suites. However, those same models can underperform on interactive prompt sets that emphasize response style, safety, turn taking, and practical instruction following.

This partial orthogonality arises because the competencies measured by multi‑task knowledge tests and by conversational prompt sets differ: one emphasizes retrieval and reasoning over many academic categories, while the other values coherent dialogue structure, helpfulness, and response desirability for a human user. The empirical implication is straightforward: choose training material and tuning objectives that reflect the intended final use. If the deployment target is a chat assistant, invest the tuning budget into conversationally oriented, high‑quality examples; if the goal is general multi‑task academic reasoning, prioritize broader instruction collections that mirror those tasks.

# Resource strategy: favor larger parameter counts at lower storage precision under a fixed budget

A practical consequence of the previous findings is a new way to think about limited compute and memory budgets. When storage precision for the frozen backbone can be reduced without harming the final tuned behavior, it becomes advantageous to allocate a greater proportion of the resource budget to model scale instead of to storage precision. In other words, within a fixed memory envelope, a larger model stored at four‑bit precision plus compact low‑rank updates can produce stronger behavior than a smaller model stored at higher precision.

The empirical work demonstrates that careful four‑bit storage combined with low‑rank finetuning lets researchers tune models with parameter counts that would previously have required large multi‑GPU servers. This tradeoff — increasing parameter count while lowering storage precision — is effective because the learnable low‑rank updates can adapt the quantized backbone into the target behavior without needing full‑parameter updates. Put simply, when memory is the limiting resource, prioritize more parameters at lower storage precision and use compact adaptation modules to recover the high‑precision finetuning outcome.

Caveats remain: the precise frontier where further lowering precision or further increasing model scale stops paying off was not exhaustively mapped and depends on model family, training protocol, and target tasks. The empirical evidence, however, supports the practical rule that efficient low‑precision backbone storage plus broad, modestly sized low‑rank updates yields a strong use of a constrained budget.

# Concluding synthesis

Taken together, the empirical results establish a reliable recipe for efficient finetuning: store the frozen pretrained backbone in a normal‑tuned four‑bit format, compress its scale factors with a second quantization layer, and train compact low‑rank correction modules placed at every linear projection in the network. This combination repeatedly recovers the behavior of higher precision finetuning on both academic tests and conversational prompt sets when the training material is well matched to the target task. Moreover, for researchers and practitioners working with limited hardware, the approach opens practical paths to tune very large models by reallocating memory from storage precision into model scale and representational flexibility.

From QLoRA to Guanaco: Training State-of-the-Art Chatbots

# Instruction collections: OASST, HH-RLHF, Alpaca, FLAN, Self-Instruct, Unnatural Instructions, Chip2, Longform

The study enabled by the memory- and compute-sparing finetuning method examined a broad set of instruction-oriented corpora, chosen to span different provenance, curation strategies, and linguistic properties. One group was a crowd-sourced multi-turn conversational corpus gathered by a community effort; another consisted of human-preference comparisons produced in a process that captures ranked judgments of response quality (the HH-style preference corpus). A separate class of corpora was generated by distilling stronger models into instruction-response pairs; representative examples in this class include the Alpaca-style collections. There was a large, curated mixture of instruction formats assembled for public research use (the FLAN release and its follow-up), which aims to aggregate many instruction types. Two collections were produced by automatic or semi-automatic synthesis of instructions and answers: one created by a self-directed prompting loop (Self-Instruct) and one assembled by a synthetic instruction mining procedure that focuses on atypical and adversarial prompts (Unnatural Instructions). Finally, the study included an aggregated large crawl of instruction-like content (Chip family) and a long-form conversational corpus oriented toward extended, multi-turn answers (Longform). 

Each of these collections carries different trade-offs. Crowd-sourced multi-turn corpora capture the flow of dialogue and have richer context dynamics, but are noisier in style and quality. Human-preference collections record explicit human judgments that guide safer and more helpful behavior but are typically smaller and narrower in coverage. Model-distilled collections are abundant and cheap to produce and often convey the style of the teacher model; they can improve fluency and conformity to teacher behaviors but may bake in teacher model biases. Aggregated and curated releases seek breadth and task coverage, useful for general reasoning and knowledge tasks. The study therefore treats these collections as complements rather than substitutes and examines how finetuning on each one shifts downstream conversational performance.

# Training recipe: supervised cross-entropy only; no human-preference fine-tuning

To keep comparisons controlled and to isolate the effect of instruction-oriented corpora combined with the low-precision finetuning approach, the training recipe across the experiments used plain supervised learning with a cross-entropy objective. The pretrained base models were frozen in their parameter storage and the low-rank learnable factors (the LoRA low-rank modules) were the only parameters updated during gradient-based optimization. Crucially, the experiments did not include preference-based policy optimization or reward-weighted tuning; none of the runs relied on human-preference optimization loops. This choice ensured that observed improvements could be attributed to the interaction between the finetuning corpus, the LoRA-style augmentation, and the quantized storage plus high-precision computation that QLoRA enables.

Training examples were presented in instruction-response format when the collection separated the two; for multi-turn corpora the full selected conversation context was used as the input prompt, with the response content treated as the target sequence to predict. Where multiple candidate responses existed for a single prompt, a single chosen canonical response per tree or conversation path was used for supervised learning, following the selection procedure described in the original collection specifications. The simplicity of the supervised objective made the training runs repeatable and comparable across model sizes and corpora, and it allowed the research team to run very large sweeps of combinations without introducing additional sources of variance from reward model training or policy optimization dynamics.

# Hyperparameter scaling with model size (learning-rate adjustment, group-size adjustments)

Practical finetuning requires attention to how update hyperparameters scale with model capacity. The study found that many hyperparameters discovered for smaller models transferred to larger models, but two aspects required consistent adjustment as parameter counts grew. First, the step-size used by the optimizer (learning rate) was reduced for larger capacity checkpoints to maintain stable convergence when using the same number of epochs and similar numbers of parameter updates. Second, the number of training examples processed together in a single forward/backward pass was increased for the larger models to keep wall-clock throughput and training dynamics comparable, given memory and throughput trade-offs on single-GPU setups. Put more simply: when moving from a modestly sized model to a much larger one, the experiments reduced the per-step learning amplitude while increasing how many examples were processed jointly per step.

These adjustments were modest in scope and chosen after limited tuning, because one of the goals of the work was to show that the efficient quantized finetuning approach makes large-scale runs feasible without extensive per-model bespoke hyperparameter engineering. The same general recipe — LoRA low-rank modules at every linear projection point, supervised cross-entropy objective, and QLoRA storage plus dequantize-for-computation flow — was applied across scales, with only the learning amplitude and group-processing size varied in a simple, consistent pattern.

# Results: Guanaco’s top model nearly matches the leading commercial conversational service; very small family member fits on consumer devices

The finetuned family of models produced under this protocol, branded Guanaco in the study, showed strong conversational performance across the measured prompt suites. The largest Guanaco checkpoint trained in these experiments reached performance levels nearly indistinguishable from those of a leading commercial conversational service on a common prompt set used by the community for head-to-head comparison. In paired comparisons with that widely used commercial system, the top Guanaco model’s outputs yielded system-level preferences that placed it within a hair of parity on the chosen prompt collection. At the same time, a much smaller member of the Guanaco family was compact enough to run on modern consumer devices with only a few gigabytes of memory required for inference, making it feasible to carry a finetuned conversational model footprint in constrained environments.

Beyond raw size and memory footprint, the study emphasizes that QLoRA’s memory reduction makes practical the training of these very large models on single devices, enabling rapid iteration. The combination of a quantized, frozen base with the learnable low-rank factors preserves most of the base model’s knowledge while steering generations toward instruction-following behavior embodied in the finetuning collections. This produced conversational outputs that human judges and automated scorers often preferred over many prior open checkpoints.

# Comparisons with contemporaneous community models and with leading commercial systems

The experiments included direct pairwise comparisons between the Guanaco family and several influential community checkpoints that were produced with alternative finetuning strategies. One open checkpoint produced by a community distillation effort was used as a close public baseline; another open model finetuned on community-sourced conversations with preference-style training provided an additional point of reference. On the same prompt suites, the top Guanaco models typically outperformed these open baselines by a clear margin in head-to-head matchups and tournament-style rankings.

For commercial systems, the study relied on the commonly used community practice of automated model-based scoring together with targeted human judgment studies. An important finding was that automated model-based scorers tend to agree with human judges at the system-ranking level in many cases, though there were instances of disagreement at the example level. Using both sources of judgement, the highest-capacity Guanaco model became the strongest open checkpoint in the study and reached performance levels close to the prominent commercial conversational service used as an implicit upper reference in the comparisons. Tournament-style aggregation of pairwise results, converted to an Elo-like ranking, showed the Guanaco largest checkpoints occupying the top open positions, trailing only the best commercial offering in the pooled comparisons.

# Dataset suitability insights: why FLAN-style aggregation performs differently on reasoning tests than on conversational prompts

One of the clearest lessons from the broad corpus sweep is that corpus suitability matters as much as corpus size. A curated multi-task aggregation intended to improve general reasoning and multiple-choice performance (the FLAN release) produced finetuned models that exhibited especially strong performance on formal knowledge and reasoning tests. However, the same finetuned checkpoints did not perform as well on conversational prompt suites that reward follow-up clarifications, multi-turn coherence, and stylistic helpfulness. By contrast, finetuning on crowd-sourced multi-turn conversational collections or curated human-preference corpora tended to improve conversational metrics more than it did formal reasoning test scores.

This partial decoupling of task strengths implies that a single aggregate of heterogeneous instruction examples will not automatically improve every downstream axis of quality. For conversational behavior that mirrors human dialogue preferences, corpora collected specifically for multi-turn, context-rich exchanges or corpora containing explicit human preference judgments are more effective. For formal knowledge and closed-ended multi-task probes, the aggregated mixed-task corpora shine. Therefore, selection of finetuning material should be driven by the intended production use case: if the goal is a conversational helper that offers safe, helpful back-and-forth, prioritizing multi-turn and preference-like collections is likely the better choice; if the goal is high performance on formal reasoning tests, a broad aggregated multitask release is appropriate.

Concluding remarks

The study powered by the quantized finetuning approach demonstrates that instruction-oriented finetuning at very large scales is feasible on modest hardware when parameter updates are restricted to low-rank modules while the base parameter storage uses aggressive quantization plus carefully managed high-precision computation. The Guanaco family illustrates how that practical accessibility translates into strong conversational behavior: large finetuned checkpoints can rival leading commercial systems on community prompt suites, and very compact family members allow deployment in constrained settings. Crucially, the empirical sweep across many instruction collections shows that which collection one uses matters deeply; quality and modality alignment between finetuning material and intended task determine final behavior more than raw sample counts.

Assessing Chatbots: Protocols, Elo Ratings, and Systematic Skews

# Reference prompt collections: Vicuna set and OA validation queries
Research described in the source used two complementary prompt collections to probe conversational system behavior. The first is the Vicuna prompt collection, a curated set of diverse single-turn prompts spanning categories such as coding, reasoning, creative writing, and conversational requests. This collection is compact by design and intended to exercise a wide range of generation behaviors in a reproducible way.

The second collection comes from the OA validation split, drawn from a multilingual, multi-turn conversation repository created for open development of interactive agents. For this collection the method extracts user messages and supplies the conversation context so that each query reflects realistic, multi-turn usage. Because this set is larger and more conversational, it complements the Vicuna prompts by stressing continuity, context management, and turn-taking.

In the experiments that motivate this chapter, model generations for both collections were produced with stochastic sampling configured to promote diversity: the sampling method used nucleus sampling with a high retained-probability threshold and a mild temperature. This ensures responses are natural and not artificially deterministic, which matters when judging comparative quality in head-to-head settings.

# Model-based scoring versus pairwise judging
Two broad approaches were used to judge responses. The first asks a strong reference model to assign an absolute score to each response, typically using a small integer scale plus textual justification. In practice the reference model is prompted with the query and two responses and then asked to score each response out of ten; relative performance is reported as the percentage of the score that a designated baseline system achieved. This protocol is straightforward and gives an interpretable metric tied to the reference system's view of quality.

The second approach performs pairwise judging. Each match presents a single prompt and two system responses; a rater—either a human or a machine rater—is asked to pick the better response or to declare a tie. Aggregating many such binary or ternary outcomes yields a direct comparison network among systems, and these pairwise preferences are more robust to differences in how different raters interpret absolute scales.

There are several reasons the pairwise approach is often more stable. Absolute scoring requires a rater to map the nuanced quality of a response onto a fixed numeric scale, a mapping that varies across raters and is susceptible to anchoring and scale drift. Pairwise judging simplifies the task to a relative choice, which reduces cognitive load and subjective calibration differences. Pairwise outcomes also feed naturally into ranking systems that estimate expected win probabilities, avoiding many problems that arise when comparing raw absolute scores across different raters or raters with different calibration.

# Order effects with a strong reference rater and mitigation
When a large reference model is used as a rater, an ordering bias was observed: the model tended to award systematically higher scores to the response that appears earlier in its prompt. This ordering effect creates spurious advantages for whichever system happens to be presented first and can distort comparisons.

A simple mitigation that the paper recommends is to average scores over both presentation orders. Concretely, for any pair of systems and a given prompt, generate two evaluation inputs that swap the order of the candidate responses, obtain a score for each ordering from the reference rater, and then use the mean of those two scores as the final evaluation for that prompt. This symmetric treatment cancels linear order biases and yields a more reliable estimate of relative quality. More generally, randomizing candidate order across examples and reporting mean results over order permutations reduces the risk that presentation order drives apparent differences among systems.

# Human rating using an online crowdsourcing marketplace: concordance measures and caveats
Human raters were recruited through a commercial crowdsourcing marketplace to provide direct comparisons among systems. For comparisons that pit a given system against the chat baseline, two independent human raters judged each pair; for head-to-head tournaments among multiple systems, three independent raters judged each match and a majority vote determined the match outcome.

Human judgments provide valuable ground truth, but they also exhibit limits. Inter-rater concordance in the experiments was moderate when raters judged many systems, and concordance dropped when raters compared two high-quality systems whose responses were both plausible but different in style or emphasis. The paper reports a concordance metric commonly used for multi-rater categorical data that indicates moderate consistency among raters at the system level and lower concordance at the individual example level. This reflects the fact that preference is often subjective: different humans value different response attributes such as brevity, thoroughness, or humor.

Several practical caveats follow. First, task instructions and rater qualification criteria strongly affect consistency; clear guidance about tie conditions, when to prefer one response over another, and how to weigh factual correctness versus style improves reliability. Second, a modest number of raters per example suffices to obtain stable system-level rankings, but more raters per example are needed to make confident claims about fine-grained differences. Third, human judgments are costly and therefore complementary use of machine-based raters can expand coverage if their systematic differences are understood and controlled.

# Elo rating: computation, meaning, and repeated resampling
Pairwise match outcomes were aggregated into a global ranking via the Elo rating system. Elo represents each system by a scalar rating and updates ratings after each match according to the match outcome and the expected win probability given the two systems' current ratings. To avoid embedding specific numerics directly in the formula, the expected score for system A versus system B can be written in symbolic LaTeX as
$E_A = \frac{1}{1 + B^{(R_B - R_A)/S}}$,
where $R_A$ and $R_B$ are the systems' current ratings, $B$ is a chosen base greater than one, and $S$ is a scale parameter that determines how rating differences map to win probabilities. After a match, ratings are adjusted by adding a scaled difference between the actual outcome and the expected score; the scale of that adjustment is controlled by a sensitivity parameter commonly named $K$.

In practice, choosing the base and scale controls the mapping between rating gaps and expected win rates, while the sensitivity parameter governs how quickly ratings move in response to new results. The experiments initialized all systems to the same starting rating and used a fixed sensitivity for updates. To control for ordering and sampling variability in the tournament, the update process was repeated many times with different random seeds and random match orders; aggregating these repetitions produces a robust distribution of ratings rather than a single point estimate.

Elo ratings have intuitive interpretation: a greater rating difference implies a higher expected match win probability. Because Elo is driven by pairwise wins and losses, it avoids many issues with absolute scoring and gives a compact, comparable measure across many systems and matchups.

# Concordance and systematic skews: model rater versus human correlation and self-favoring
Comparing machine rater judgments to human judgments revealed partial correspondence but also systematic differences. At the system level, rank correlations between the machine rater and human majority votes were moderate, indicating that the two modalities often agree on broad ranking but diverge on many specific comparisons. At the example level, concordance metrics were notably lower, reflecting frequent disagreements about particular outputs.

One striking pattern was that the strong reference rater tended to favor its own outputs more than human raters did. In the reported results the machine rater assigned a substantially higher Elo to its own outputs than the human pool assigned, translating into a material increase in expected win probability for that rater's outputs. This self-favoring tendency is important to account for when using machine raters as a proxy for humans: comparisons that rely solely on the reference rater may overestimate the practical competitiveness of systems that are similar to the rater itself.

These observations motivate a blended evaluation strategy. Use human ratings where resources permit for final validation, use model-based ratings to expand coverage and run faster iterations, and always check for systematic skews such as order effects and self-preference. When machine raters are used, report both machine-based and human-based ranking statistics and quantify their concordance with measures such as rank correlation and multi-rater concordance indices. Repeating the tournament process under random seeds and pooling the resulting rating distributions gives a more faithful picture of uncertainty than reporting a single point estimate.

# Practical recommendations distilled from the study
The experimental setup examined here yields several clear best practices for future comparative studies of conversational systems. First, assemble both compact, diverse prompt collections and larger conversational query sets so that systems are judged on both single-turn and multi-turn behaviors. Second, prefer pairwise match protocols for primary ranking and use Elo aggregation to produce stable, interpretable system scores. Third, when employing a machine rater, always randomize candidate order and average across both presentation orders to mitigate order biases. Fourth, collect human ratings for a targeted subset of matches to calibrate and validate machine-based judgments, and report concordance statistics to make differences transparent. Finally, use repeated resampling of match sequences and random seeds when computing Elo to quantify uncertainty in rankings rather than relying on a single tournament run.

Following these practices produces comparisons that are more robust to subjective scale interpretations and systematic skews, and it makes the relationship between machine-based and human-based judgments explicit so readers can assess how evaluation choices affect reported outcomes.

Qualitative Behaviors and Failure Modes

# Factual recall

The Guanaco family shows a clear pattern: for common, well represented facts the models are robust and produce correct, concise answers; for more obscure or narrowly distributed facts they often produce confident but incorrect statements. The chapter's examples illustrate both sides. Straightforward geography queries are handled reliably: for instance the model correctly names the capital city of Zambia. That kind of information tends to appear frequently in training mixtures and the model's internal representations support dependable retrieval.

By contrast, when prompts probe less common knowledge or require precise attribution the model is prone to confident errors. A concrete example from a question drawn from a multi-hop dataset led the model to attribute a song to the wrong performer and to give an incorrect birth year. The output read confidently and offered plausible but incorrect details. This pattern—high fluency combined with misplaced certainty—means that for tasks requiring verified, rare, or recently updated facts the model should not be treated as an oracle. Practical use therefore benefits from systems that cross-check model outputs with external sources, or that surface provenance when the model makes factual claims. More generally, designers and operators should treat single-shot textual answers to obscure factual queries as hypotheses that require external corroboration.

# Suggestibility

Guanaco models display an interesting asymmetry in how they respond to misleading premises. In some prompts that assert patently false claims, the model resists the falsehood and pushes back, explicitly stating the conventional scientific consensus rather than accepting the prompt's premise. For instance, when asked about a hypothetical peer-reviewed confirmation of a long-refuted notion, the model rebutted the premise and provided an explanation consistent with mainstream knowledge. This demonstrates that, for many classes of misinformation, the model has internalized corrective patterns from its training data and can act as a guardrail.

At the same time, the model correctly recognizes limits on real-time and situational information: it will refuse to invent the current time or claim a real-time location. These refusals indicate the model can distinguish static knowledge from live sensing and will often decline questions whose correct answer would require external inputs. That behavior is useful for safety and honest reporting of capability limits.

Taken together, these behaviors imply that Guanaco can be both resistant and vulnerable to prompt-driven misinformation depending on the category of the claim. For widely contradicted falsehoods it often resists, while for subtle, underrepresented, or cleverly framed false premises it may accept and elaborate. This mixed pattern motivates the use of controlled prompts and, when accuracy is critical, integration of retrieval, fact-checking, or human oversight.

# Refusal behavior

The models sometimes decline to follow simple, harmless instructions for unclear reasons. One example asked the model to reverse the words in a short sentence; rather than comply it returned a refusal and offered a grammatical commentary instead. The refusal seemed unrelated to safety or policy constraints and instead reflects unpredictable decision boundaries learned during training.

This inconsistency poses two problems. First, a genuine refusal can be a safety feature if it blocks harmful requests; but when refusals appear for benign tasks they degrade user experience and reduce reliability. Second, randomness in refusal patterns makes it hard to predict when a model will comply, which complicates pipeline design for downstream systems that expect deterministic behavior.

Addressing these issues requires focused data and tuning to align refusal behavior with intent and policy: encourage refusals only when safety or privacy risks are present, and encourage compliance for harmless transformations. The paper notes that such fidelity of instruction following needs further research; until then, designers should anticipate occasional, inexplicable refusals and provide fallback handling in user interfaces.

# Secret-keeping

The models exhibit a limited ability to follow instructions intended to protect secret tokens, yet that protection can be brittle. In the reported scenario a model was told that a particular word was secret and to never reveal it. When asked directly, the model refused, which is the desired outcome. However, a small reframing of the prompt—presenting the interaction as a game and inviting the model to ignore prior instructions—caused it to reveal the secret token.

This vulnerability is an instance of prompt-injection or instruction override. It has clear implications for systems that attempt to store sensitive material or enforce policy via in-prompt directives. The example shows that in-prompt constraints are fragile against cleverly constructed user inputs. Robust secret-keeping requires mechanisms beyond plain instruction: isolated contexts that cannot be overridden by user text, explicit policy modules that are not part of the free-text generation context, or filtered post-processing that removes or blocks sensitive outputs. The observation in the study underscores the need for engineering measures to harden systems used in privacy- or safety-critical deployments.

# Mathematics

Arithmetic and symbolic reasoning show mixed competence. When the model breaks a problem down explicitly and shows intermediate steps it often gets correct results; when it attempts an answer directly it can make simple calculation mistakes. One illustrative dialogue asked about a weekly earnings total involving a fixed fee per job and a small number of tips. The model computed the per-job subtotal and the tip subtotal correctly but then combined them into the wrong final total. In another case the model declared a composite number to be prime and gave an incorrect factorization.

These errors reflect two tendencies. First, the internal numeracy of language models is approximate: they handle many numeric patterns well but do not have guaranteed arithmetic fidelity. Second, lack of structured, stepwise decomposition increases error rates. The literature and the paper itself suggest that encouraging stepwise reasoning—either via explicit prompting strategies that coax the model to show its work or via external symbolic calculators—can reduce errors. For applications that require reliable arithmetic or exact factorization, one should route numeric computation to deterministic modules or require the model to produce verifiable intermediate steps that can be checked automatically.

# Theory of mind tasks

On tests of social reasoning and perspective-taking, the models show promising capabilities but are not uniformly reliable. In a classic false-belief vignette involving two agents and a moved object, the model produced an answer consistent with standard human theory-of-mind expectations: it reasoned about what one agent believes the other will do. In other, more complex scenarios the model filled in unstated channels of information transfer and concluded that an agent would know about actions that were never observed. These mistakes arise because the model sometimes assumes implied knowledge or plausible communication where the narrative did not establish any.

This pattern means Guanaco can often pass simple perspective-taking probes but can also hallucinate social dynamics when prompts are underspecified. For downstream use, it is important to design prompts that explicitly state what agents observe and what they do not, or to treat model judgments about beliefs as tentative. For research, these findings point to an intriguing strength and a continuing weakness: such models can represent nested beliefs to an extent, but they can also over-interpret scene descriptions in ways that a human would not.

# Implications for safety and reliability

The examples reviewed above converge on a few practical takeaways. First, fluent and confident text does not equal correctness; systems should avoid blind trust in model claims, especially for obscure facts and precise computations. Second, instruction-following is powerful but brittle: refusals and secret-keeping can function but are vulnerable to prompt manipulation. Third, strengths in social reasoning coexist with tendencies to infer unsupported facts, which creates both opportunity and risk for applications that rely on the model's judgments about mental states.

Operationally, these findings recommend layered safeguards: use external retrieval or verification for factual claims, delegate arithmetic to deterministically tested components when needed, employ hardened policy enforcers for secrets and refusals, and design prompts that make observational contexts explicit for perspective-taking tasks. From a research perspective, the study highlights the value of targeted example-driven probing to surface patterns of failure and to guide dataset curation and finetuning choices that improve reliability without sacrificing the conversational strengths observed in Guanaco models.

Practical QLoRA: Implementation and Deployment

# Hardware profiles: single twenty-four gigabyte and single forty-eight gigabyte GPUs; scaling tips
When planning an experiment with QLoRA, start from the target device memory envelope. The approach in the source work demonstrates two practical single-card configurations: a mid-memory workstation card with roughly twenty-four gigabytes of onboard memory and a high-memory professional card with roughly forty-eight gigabytes. The former is sufficient for tuning mid-sized pretrained models when using the QLoRA recipe, while the latter enables tuning the largest publicly available pretrained weights described in the study. The key hardware trade-offs to keep in mind are memory headroom for model storage, activation recomputation, optimizer state working set, and the disk or host RAM bandwidth that supports any spill-to-host behavior.

For the smaller card profile, constrain the working set by choosing a modest per-step context length and a small update group size (see the section on group-size knobs). Use the QLoRA storage format (four-bit NormalFloat with double quantization) so that the frozen pretrained parameters consume very little of the device memory budget, leaving space for the LoRA low-rank components and the activation gradients. For the larger card profile, take advantage of the extra headroom to increase the update group size and sequence context and to place more optimizer state on the device to avoid paging.

When moving beyond a single card, the same QLoRA principles scale: keep the pretrained weights stored in the compact four-bit form across devices, and shard the small LoRA components and optimizer state. Communication costs are much lower than with full-model dense updates because only the low-rank updates and occasional activation exchanges need to move between devices. If you plan to expand to a multi-card cluster, favor designs that minimize synchronous transfers of large tensors and instead replicate the compact frozen storage while sharding only the mutable parts.

# Software stack: Hugging Face Transformers integration, bitsandbytes, CUDA kernels
The study integrates QLoRA into a modern transformer library and pairs that integration with specialized low-bit compute kernels for storage and dequantization. Practical reproduction therefore requires three software elements: a transformer runtime that supports replacing linear kernels with a quantized storage plus dequantize-on-use workflow; a memory- and compute-efficient low-bit library that implements the NFk storage formats, double quantization of the per-block scales, and fast dequantization into the compute dtype; and custom GPU kernels to make the dequantize-and-multiply operations efficient during forward and backward passes.

In the paper, the repository integration provides hooks so that when a linear projection is executed the stored four-bit NF4 matrix and its compacted constants are dequantized into the compute dtype on-the-fly and used in a sixteen-bit matrix product. The low-bit library also implements the second-stage quantization of the block scales (the double quantization step) and provides efficient kernels for the combined dequantization operation so that the storage savings do not come at a prohibitive runtime cost. To reproduce these behaviors, enable the library’s custom kernels in your run-time and ensure the transformer runtime routes linear projections to the quantized kernels. The authors also provide optimized CUDA kernels for the NF4 format; using them avoids the heavy overhead of CPU-based dequantize loops.

When installing, confirm that the transformer runtime is configured to allow replacing particular linear projections with the QLoRA path and that the low-bit library exposes APIs for creating the quantized storage, reading and writing the compacted scale constants, and executing the fused dequantize-plus-matmul. The study also relies on a mechanism to place optimizer working sets in host memory and to rely on unified memory paging for occasional spills; make sure your CUDA driver and runtime support the unified memory features used by the paged optimizer layer.

# Recommended defaults: NF4 plus double quantization; block sizes sixty-four and two hundred fifty-six
The authors found a robust default configuration that trades storage and fidelity effectively. Use the four-bit NormalFloat data type (NF4) for the frozen pretrained parameter tensors. NF4 is designed for weights that are approximately zero-centered and bell-shaped; it assigns quantization bins by estimating normal-distribution quantiles so that each bin carries similar expected mass, thereby reducing quantization distortion compared to naive integer or uniform four-bit schemes.

For the per-block quantization granularity of the main weight tensors, use a block length of sixty-four elements. This block length balances the need to limit the effect of outliers while keeping the per-block scale constant overhead small. Then apply the double-quantization step to the block scales: quantize these scale constants with an eight-bit floating format and use a larger block length for their grouping, such as two hundred fifty-six, to amortize their storage cost further. This second-stage quantization shrinks the average bits-per-parameter contribution of the scale constants without measurable degradation in the tuning outcomes reported.

For the compute dtype, dequantize into a sixteen-bit brain-style floating format (referred to in the source as BF16) for both forward and backward operations. Keep the frozen weight gradients disabled: the training loop should only compute gradients for the small LoRA components while passing gradients through the dequantized path. These defaults—NF4 storage with double quantized scales, sixty-four main blocks, two hundred fifty-six blocks for scales, and BF16 compute—are the starting point recommended by the paper’s experiments.

# LoRA configuration: target modules, ranks, scaling, all-layer coverage
A critical practical lesson from the work is that the coverage of LoRA updates matters more than the narrow per-module projection width. Early, minimal LoRA placements that patch only attention query and value projections were insufficient to recover full-model tuning behavior for large bases. The recipe that matched dense full-model tuning places LoRA modules across every linear projection inside each transformer block, not just a subset of attention matrices. In practice this means augmenting the projection paths in self-attention and in the feed-forward projections of each block.

Each LoRA insertion is a rank-restricted factorization: an input projection is augmented with the product of two low-rank matrices. The rank hyperparameter controls the expressive capacity of each LoRA module. The study reports that, once LoRA modules are present throughout the model, the precise rank is not extremely sensitive: modest ranks suffice when the modules exist everywhere. Use the convention of a scalar multiplier for the LoRA update that scales the low-rank contribution; tuning this scale alongside the learning rate is helpful in stabilizing training. Because the LoRA parameters are small relative to the frozen base, you can afford to increase their layer-wise rollout without a prohibitive memory hit. In short: prioritize all-layer coverage with modest rank rather than very high rank confined to a few modules.

# Group size, context length, recomputation, and paged optimizer settings
Memory management during the training pass requires attention to the trade-offs among update group size (the number of sequences that accumulate before an optimizer step), context length, and activation recomputation. The paper replaces the word commonly used for per-step examples with "group size"; choose a group size that fits your device memory when combined with the desired sequence length. If you need longer context windows, reduce group size and enable recomputation of intermediate activations (sometimes called gradient recomputation) to reduce peak memory for activations at the cost of extra compute.

Two additional mechanisms are important to reproduce: first, aggressive recomputation for some transformer sub-blocks to trade compute for memory; second, paged optimizer behavior for the optimizer states. The paged optimizer uses unified memory so that optimizer state can spill to host RAM transparently when the GPU would otherwise run out of space and be paged back when needed for updates. Set the paged optimizer threshold conservatively so that pages move only during the optimizer update step, avoiding frequent thrashing. In practice, ensure that host RAM is abundant relative to the spilled working set and that the system’s PCIe or interconnect bandwidth is sufficient for the occasional large transfer.

When configuring the optimizer, place only the mutable parameters (the LoRA modules and any small tunable logs or scalars) in the optimizer state on the device by default. The large frozen storage remains read-only in its compact four-bit form and does not require optimizer state. For reproducibility, document the recomputation segments, the group size, context length, and the paged threshold so runs can be compared.

# Debugging quantization issues and verifying parity with reference models
When a run fails to reach the expected convergence or shows degraded behavior relative to reference dense tuning, proceed through a checklist grounded in the quantization points of failure described in the paper. First, verify that the frozen storage was created using NF4 quantiles appropriate for the theoretical normal distribution; if a custom quantile estimator was used, check its fidelity on weight histograms since misestimated quantiles produce systematic distortion. Second, confirm that the dequantization layer correctly composes the double-dequantization: first dequantize the second-stage eight-bit float scales back into full-precision scales, then apply those scales to the four-bit NF4 codes to obtain the BF16 weight matrix used for computation.

A useful diagnostic is to compute post-quantization language-modeling metrics on a held-out slice before any tuning. The paper shows that NF4 yields smaller degradation than naive four-bit float or integer encodings; if your post-quantization losses are notably worse than expected, recheck the block size choice and the quantile tables used for NF4. Another quick check is to reconstruct a small subset of weights through the double-dequantize path on CPU and compare their statistical moments (mean, variance) to the original full-precision weights; large deviations signal a quantization implementation bug.

To verify parity with reference runs, reproduce a small-scale experiment where dense tuning is tractable (for instance, a smaller model from the same family). Run the QLoRA recipe and the reference dense tuning with matched optimization hyperparameters and compare the task-level outcome on held-out test prompts. The study demonstrates that when implemented correctly, the NF4 plus double-quantization approach with LoRA across all layers recovers the task-level behavior of dense tuning. If parity is not observed, iterate on the dequantize kernels, LoRA placements, and optimizer spill settings until the small-scale tests match; once they do, scale up to the larger models.

# Deployment footprints and quantized inference considerations
The storage and compute characteristics that make QLoRA effective at tuning also permit very compact deployment. The frozen base model in the study can be stored in the four-bit NF4 format with double-quantized scales, which yields a tiny footprint when serving. For latency-sensitive inference, use fused kernels that perform dequantize-to-compute on the fly and then immediately execute the matrix multiply, avoiding an explicit full-precision materialization step. For many deployment scenarios, it is possible to keep the base in the NF4 double-quantized form on device and only dequantize the small working blocks needed for the current compute.

When applying the learned LoRA low-rank updates at inference, you have two main choices. One can keep the LoRA modules as separate small dense additions to the dequantized base during runtime; this keeps flexibility and allows toggling the LoRA effect at run time. Alternatively, for a fixed deployment target and when storage is at a premium, fold the low-rank updates into the dequantized kernels at load time: dequantize a block, add the dense LoRA contribution, and then optionally requantize the combined block into the same NF4 format for purely frozen inference. The paper emphasizes that LoRA modules are small enough that leaving them in dense sixteen-bit form and summing them with the dequantized base during each projection is a practical approach that preserves runtime fidelity.

Finally, remember that inference behavior can depend on sampling hyperparameters. The study uses nucleus sampling with a high-mass threshold and moderate temperature during generative testing. For deployment, tune these sampling knobs for the intended user experience: more conservative settings yield safer, more deterministic outputs; more permissive settings produce varied, creative outputs.

# Practical checklist and quick-start recipe
- Prepare the pretrained weight files and convert them into NF4 with double quantized scales using the provided conversion tools. Use a main block length of sixty-four and a scale block length of two hundred fifty-six. Verify per-block reconstruction statistics on a small random subset.
- Integrate the low-bit library into your transformer runtime and enable the custom CUDA kernels for on-the-fly dequantize-plus-matmul.
- Insert LoRA modules densely across every linear projection inside each transformer block. Choose modest rank values, tune the scalar multiplier if needed, and initialize the LoRA factors following the library defaults.
- Configure recomputation for memory-heavy sub-blocks and choose a group size and context length that fit your device. If memory spikes still occur, enable the paged optimizer so optimizer state can be evicted to host RAM during forward/backward passes and restored during updates.
- Run a small-scale verification against a reference dense tuning run on a smaller model. Confirm task-level parity on the held-out test set before scaling to the largest model you want to tune.
- For serving, decide whether to keep LoRA modules separate or to fold them into the base for a purely frozen inference model. Use fused dequantize-and-matmul kernels to retain low latency.

This chapter distilled the implementation lessons and deployment patterns from the QLoRA study. By following the defaults and the debugging checklist above, practitioners can reproduce the low-memory tuning pathway and bring highly capable tuned models into production environments with compact footprints.

Related Work, Limitations, Ethics, and Future Directions

# Quantization for LLMs: outlier handling, GPTQ, SmoothQuant, LLM.int8()

Large language models place most of their memory cost in parameter storage. Reducing that storage via coarse numeric formats while preserving model behavior has been a major engineering focus. One central difficulty is the presence of infrequent, large-magnitude elements in model tensors. These outliers inflate the rescaling factor used for quantization when a tensor is mapped into a fixed low-bit range, and as a result many representational bins remain unused or poorly utilized. Practical remedies operate at two levels: grouping and rescaling at a finer granularity, and transforming activations so that their magnitudes are more uniformly distributed across dimensions.

A widely used practical tactic divides large tensors into contiguous blocks and quantizes each block independently. This block-wise treatment reduces the damage caused by isolated outliers, because a single extreme value only affects its block rather than the whole tensor. An additional family of techniques preconditions weights or features so that magnitudes across channels or heads are more balanced; this mitigates outliers before quantization. One such preconditioning approach rescales features in a way that equalizes dynamic ranges across channels, enabling an eight-bit transform that keeps most of the original precision in practice.

Complementary to these operational tricks are methods that optimize the discrete rounding decisions used during quantization. These methods search for low-bit representations that minimize the reconstruction error of a weight matrix under a layer-wise or block-wise loss. When carefully applied, such optimized rounding can produce very low reconstruction error even with aggressive quantization, and so it is often used for offline conversion of pretrained models for inference.

The QLoRA work builds on these traditions but differs in two important ways. First, it designs a bespoke low-bit storage format tailored to the typical statistical shape of pretrained weights, rather than relying solely on integer or standard floating formats. Second, it combines a compact storage representation with a higher-precision compute representation: weights are stored in a compact quantized form but are dequantized into a higher-precision format for both forward and backward computation when training the added low-rank modules. This hybrid approach leverages the memory gains of aggressive storage quantization while keeping computation numerically robust.

# Parameter-efficient finetuning landscape: LoRA, prompt tuning, IA³, BitFit, Compacter

There is a broad set of methods that aim to shift most of the learning signal into a small set of trainable parameters while leaving the large pretrained weight set unchanged. This family of methods is attractive because, during training, the footprint of new parameters can be tiny compared to the frozen base model, which makes experimentation and iteration far more affordable.

One influential member of this family injects low-rank updates into selected linear maps of the network. These low-rank insertions introduce a factorized additive term that is multiplied into the network activations; because the rank is chosen small, the number of new parameters is a tiny fraction of the full model. The QLoRA protocol leverages this idea and shows that, when combined with careful placement and sufficient coverage of linear layers, these low-rank insertions can recover the quality of full-parameter finetuning even when the surrounding model weights are stored in a highly compact quantized format.

Other approaches tune a small series of prompt tokens that are prepended to model inputs. These learned prompt vectors steer the frozen model’s behavior without modifying its internal maps. There are also schemes that scale internal module outputs by small learned vectors at particular layers, schemes that only change bias terms in linear layers, and designs that add compact extra layers with constrained parameterization. Each choice offers a different trade between parameter count, expressive range, and implementation complexity.

A practical takeaway from the QLoRA experimental suite is that the dominant memory pressure during finetuning often comes from activation storage and gradient flows, not from the count of new parameters. This means that using slightly larger or more numerous low-cost modules is feasible and can help close the gap to full-model tuning performance without a prohibitive memory penalty. In the QLoRA results, investing in broader coverage of low-rank modules across the network layers was a decisive factor in matching full finetuning quality.

# Instruction tuning and dialogue systems: FLAN, Instruct-type tuning, reinforcement from human feedback and model-produced preference data, Vicuna-style and open conversation collections

Tuning pretrained language models to follow diverse natural-language instructions is now a common step before deploying interactive systems. Collections of instruction–response pairs have been assembled from many sources: handcrafted tasks, crowd-sourced conversational transcripts, distilled outputs from strong teacher models, and curated multi-turn assistance logs. Different collections emphasize different properties: some aim at broad task coverage, some prioritize conversational style or safety, and some are designed so that later human-originated preference judgments can be used to refine behavior.

Two contrasting strategies for producing instruction-tuned systems are supervised finetuning on curated input–output pairs, and a subsequent stage that uses preference signals to shape higher-level behavior. The latter is commonly achieved by collecting ranked responses and then applying a policy-learning step that uses those rankings as a reward signal. Alternatively, ranked responses can be generated by a strong model and used as a cheaper source of relative preferences. The QLoRA experiments focus on the supervised finetuning stage, showing that careful supervised tuning of a quantized base combined with low-rank modules can yield conversation-capable models that approach the behavior of popular commercial services, when judged by head-to-head comparisons on curated prompt collections.

When comparing systems that generate natural-language replies, the community has used both absolute scoring on a numerical scale and direct pairwise comparisons. The direct comparison setup asks a judge to pick which of two replies better addresses a prompt, or to declare them equivalent. Head-to-head judgments can then be aggregated into a rating scale such as Elo to produce a relative ranking across many systems. QLoRA’s empirical work uses such pairwise schemes with both crowd-sourced human raters and with a powerful proprietary model used as an automated judge. The paired approach reduces some issues of scale interpretation and enables robust relative comparisons among many finetuned variants.

# Limitations: missing full higher-precision baselines at largest scales; test-set validity and judge biases; measurement uncertainties

The technical results illustrate that quantized storage combined with low-rank trainable additions can match the quality of higher-precision finetuning in many controlled tasks and sizes. Important gaps remain, however. One practical limitation is that end-to-end comparisons against full higher-precision finetuning at the very largest public model scales were not conducted, owing to resource constraints that make those baselines costly to run. Consequently, while lower-memory finetuning reproduces higher-precision behavior in many regimes, there remains some uncertainty about whether the match is exact across every task and every extreme model size.

Another set of limitations concerns how systems are judged. Standard prompt collections and multi-task test sets capture some aspects of capability, but they do not necessarily reflect all uses or misuse modes. Pairwise judging helps, yet it also introduces sensitivities. The automated judge used in the QLoRA work displays strong order effects—responses shown earlier in a comparison prompt tend to receive more favorable verdicts. Agreement between automated judgements and human raters is moderate: system-level rankings are often consistent, but detailed per-example agreement is weaker. Crowd-sourced human judgments themselves show only partial inter-rater agreement, particularly when differences between responses are subtle. These factors imply that conclusions about small gaps between high-performing systems must be interpreted with caution.

Finally, some deployment-relevant behaviors require different kinds of tests than those used in model development. For instance, robustness to adversarial instruction phrasing, persistent secrecy constraints, consistent refusal behavior, and worst-case safety properties are not fully characterized by the standard collections in use. The qualitative failures highlighted in the QLoRA study—confident hallucinations on obscure factual queries, brittle refusals under prompt manipulation, and arithmetic errors in some multi-step calculations—demonstrate that strong aggregate test-set scores do not eliminate important real-world weaknesses.

# Ethical considerations: dual-use, stereotyped outputs, privacy, and the implications of broader access

Making memory-frugal finetuning broadly available lowers the barrier to producing specialized conversational models. That democratization is valuable for many benign applications—personalized assistants on personal devices, privacy-preserving localized tuning, and small teams conducting rapid experimentation. At the same time, easier finetuning also widens the potential for misuse. Malicious actors could more readily adapt powerful base models for harmful output styles, targeted misinformation, or automated exploitation. Responsible release and stewardship require balancing openness against misuse risk, and the QLoRA authors highlight this tension explicitly.

Another ethical axis concerns the tendency of models to reproduce or amplify societal prejudices embedded in training data. The supervised conversational collection used for the best QLoRA models reduced some of these undesirable tendencies relative to the raw pretrained base in certain measured probes, but that does not guarantee broad robustness. Careful scrutiny across demographic groups, topic areas, and interactive scenarios is necessary before claiming safety improvements. Because standard tests capture only part of the phenomenon, broader mitigation work and transparent reporting are essential.

Privacy is also central. Smaller-footprint models that can be finetuned on-device make it feasible to keep sensitive personal data local during customization, which is a strong privacy-positive outcome. Yet those same capabilities could be used to create specialized surveillance or data-exfiltration tools if misapplied. The open-source release of finetuning code and kernels aims to enable reproducibility and auditability, but it simultaneously reduces technical friction for potentially harmful use.

Finally, the social implications of making advanced conversational systems widely available must be considered. Easier finetuning encourages independent auditing and research, but it also means that systems with only superficial safeguards may be deployed widely by less experienced teams. Documentation, model cards, and clear guidance about intended use and limitations can help, but institutional and community-level governance mechanisms will also play a role.

# Future directions: more aggressive quantization, alternative low-cost tuning modules, rigorous measurement of paging trade-offs, and improved human-aligned measurement

The results open several promising research avenues. First, the combination of quantized storage and targeted trainable modules suggests that even more aggressive storage formats could be viable if finetuning is used to recover lost precision. Exploring three-bit and mixed-bit formats, combined with carefully designed quantization-aware storage schemes, could further lower memory and energy costs. Such work should evaluate both typical-case behavior and worst-case failure modes, and should measure how much finetuning effort is needed to restore original performance.

Second, while low-rank factorized insertions proved effective at closing the gap to full finetuning in the QLoRA experiments, other parameter-efficient mechanisms deserve systematic exploration in the quantized setting. Methods that learn small prompt vectors, scale internal activations, or adjust bias terms may interact differently with compact storage. Comparative studies that keep compute and memory budgets fixed would help clarify which mechanisms are most promising for particular usage scenarios.

Third, the engineering feature that moves optimizer state between device memory and host memory to avoid out-of-memory spikes is powerful, but its performance characteristics need more rigorous measurement. Detailed studies should quantify when swapping causes measurable slowdowns, how different host-device bandwidths affect throughput, and how to schedule updates to minimize paging overhead in practice. This knowledge would help practitioners choose hardware and batch-size strategies for stable long-sequence training.

Fourth, measurement practices for conversational systems require improvement. Automated judges are a cheap way to generate large numbers of pairwise comparisons, but they exhibit ordering and self-preference effects. Human judgments are costly and noisy at fine granularity. Future work should develop hybrid protocols that combine calibrated automated scoring with strategically sampled human checks, and should investigate statistical designs that increase rater agreement and reduce sensitivity to prompt order. Exploring methods from human-subjects research, decision science, and psychometrics may yield more reliable ranking procedures.

Finally, responsible deployment research should accompany the technical advances. Systematic audits for stereotyping, privacy leakage, adversarial instruction susceptibility, and misuse potential should be standard for any released finetuning recipe or model checkpoint. Tools that facilitate red-teaming, provenance tracking of finetuning data, and clear communication of a model’s known failure modes will help ensure that broader access to finetuning capabilities produces net social benefit.

Concluding remark

The QLoRA findings show that carefully combining compact weight storage with small, trainable low-rank modules can make high-quality finetuning far more accessible. That technical advance brings practical benefits and new risks in equal measure. A focus on rigorous measurement, method comparison, and transparent reporting will help the field turn the accessibility gains into broadly beneficial applications while managing the attendant harms.

Foundations: Finetuning LLMs and Memory Bottlenecks

# Intermediate-state versus parameter memory; gradient checkpointing

When a large language model is trained on a supervised objective, the temporary data produced during a forward pass dominates the memory footprint at training time. These temporary items include the internal hidden states produced at each layer for each position in the input sequence and the associated derivatives that are required for the backward pass. In the literature this category is often contrasted with the persistent storage required to hold model parameters; for very large models the transient storage tied to a single batch and sequence length frequently exceeds the storage needed for the static weights.

The paper demonstrates this distinction with concrete figures for a mid-sized model finetuned with a low-rank update method. A small fraction of extra parameters used for the trainable low-rank updates takes only a few dozen megabytes of permanent storage, whereas the gradients tied to the inputs flowing into those modules can require several hundred megabytes. For the same setup the compressed base model itself (when stored in a low-precision format) contributes a few gigabytes. The practical conclusion is simple: reducing the number of trainable parameters alone is not sufficient to bring down peak memory during training, because the intermediate-state gradients and checkpointed tensors remain the main drivers of memory use.

Gradient checkpointing is a technique that trades compute for memory. Rather than retaining all intermediate hidden states throughout the forward pass, checkpointing stores only a subset and recomputes missing states during the backward pass. This reduces peak transient storage at the cost of additional forward computation. The authors emphasize that checkpointing is necessary for large-scale finetuning on limited hardware, but it does not eliminate spikes in memory usage: certain mini-batches with long sequences can still cause transient overflows during optimizer steps. The paper addresses these spikes with a system-level strategy that pages optimizer state to host memory when needed, thereby smoothing out peak usage without changing the training math.

# Why inference-only quantization breaks during training

Quantization methods designed for fast or compact inference convert model weights into a lower-precision representation and then perform computation in a way that preserves output quality. These methods often target a storage format and a set of dequantization rules tailored to the forward pass. Training, however, requires two additional elements that inference-only recipes typically do not provide.

First, training needs gradients that are faithful to the original high-precision computation. If the forward computation uses a coarse discrete representation and the backward computation does not account for the quantization-induced distortions, the propagated gradients may be biased or noisy in ways that prevent the optimizer from finding good solutions. Second, many inference quantization schemes assume larger grouping windows or blocking strategies to control outliers; those same heuristics can create large per-block approximation errors that destabilize gradient propagation.

The work summarized here shows that standard inference quantization techniques can therefore “break down” when placed inside a training loop: loss surfaces and update directions change enough that naively applying those formats prevents successful finetuning. To overcome this, the authors propose a training-aware pipeline: store the pretrained base model in a compact form, but use a higher-precision computation format during the forward and backward passes and restrict actual parameter updates to a small set of added low-rank weights. In other words, the quantized base is frozen for the purposes of parameter updates, but gradients are still propagated through a faithful dequantized view so that the learned low-rank modules receive meaningful signals.

# Parameter-Efficient Finetuning (PEFT) overview and tradeoffs

Parameter-efficient finetuning methods aim to change model behavior by adding or tuning a relatively small collection of extra parameters rather than updating every stored weight of a very large model. The rationale is twofold: keeping the bulk of the pretrained parameters fixed makes sharing and deploying many task-specialized variants cheaper, and optimizing a small trainable subset lowers the steady-state storage cost for each new specialization.

One effective instantiation of this idea is to augment a linear projection with a low-rank correction. If a linear layer computes
\[
\mathbf{Y} = \mathbf{X}\mathbf{W},
\]
a low-rank augmentation introduces a factorized additive term so that the output becomes
\[
\mathbf{Y} = \mathbf{X}\mathbf{W} + s\,\mathbf{X}\mathbf{L}_{A}\mathbf{L}_{B},
\]
where the pair $\mathbf{L}_{A},\mathbf{L}_{B}$ are matrices with small inner dimension and $s$ is a scalar re-scaling factor. The small inner dimension bounds the number of new parameters, making the added storage modest compared with the original $\mathbf{W}$.

Tradeoffs emerge from where memory is consumed during training. The extra matrices themselves occupy little space relative to the frozen base model, but the gradients that flow into those matrices require intermediate tensors and input gradients. As the authors show, the memory needed for these input gradients can exceed the stored size of the trainable matrices by an order of magnitude. Thus, while PEFT reduces the permanent parameter footprint, peak transient memory during training remains substantial because of hidden-state storage and gradient tensors. This is why PEFT methods are most effective when paired with other system- and representation-level strategies: compact storage of the frozen base, a computation format that allows faithful forward and backward passes, and runtime techniques to avoid optimizer-related spikes.

The paper’s practical insight is that because the trainable component is small, one can afford to place such low-rank updates at many locations in the network (for instance, at every linear projection) without a prohibitive increase in permanent storage. This full-coverage placement helps recover the performance of full-model finetuning while preserving the parameter-efficiency benefits.

# Test suites and task landscape: GLUE, MMLU, and instruction tuning

The community uses several well-known standardized tests and curated collections to study model capabilities. One family of tests focuses on single-turn language understanding and classification across a range of narrow tasks; these form the traditional general-purpose suite used to compare models on sentence-level tasks. Another prominent assessment probes broad general knowledge and multi-domain problem solving via a many-task multiple-choice collection that spans subjects such as mathematics, history, and science; models are typically measured with a small number of exemplar context examples for each task and the proportion of correct selections is reported.

Beyond these formal tasks, there is a growing practice of finetuning models with human-curated input–output pairs so that a pretrained model better follows instructions. This instruction-oriented finetuning uses corpora created in various ways: curated multi-turn dialogues collected and cleaned by people, synthetic question–answer pairs produced by an existing large model and then distilled, and aggregated mixtures of many different instruction types. Different curations lead to different behavioral specializations: some collections are oriented toward robust general knowledge performance, others are tailored for helpful conversational responses, and yet others aim for a wide variety of task formats. The paper emphasizes that quality and suitability of these collections matter more than sheer quantity: a relatively small, high-quality human-curated chat collection outperformed a much larger synthetic collection on the measure of conversational response quality used in their study.

For measuring instruction-following or conversational performance, the study used two types of assessments. One is a direct-score relative method in which a reference model is scored and a candidate model is reported as a percentage of that reference’s score. The other is a pairwise tournament methodology in which responses from two different systems are compared on the same prompt and a winner is chosen; repeating such pairwise comparisons and aggregating via a rating system produces an ordering of systems that is often more robust to scale interpretation issues than absolute point scores.

# Resource constraints in academic and consumer hardware

Large pretrained models are increasingly large enough that standard full-precision finetuning requires racks of high-memory accelerators. The paper motivates its method by noting that a full-model finetuning run in the common high-precision format would require many times the memory of a single common workstation GPU. This limits experimental exploration: training many variant models across different data curations and hyperparameter settings becomes infeasible for researchers with only a single GPU or a small group of consumer devices.

The method introduced in the paper dramatically lowers the memory needed to finetune the largest publicly available pretrained models by employing three complementary strategies. First, the frozen base model is stored in a compact, quantized representation that dramatically reduces its on-device footprint. Second, the computation uses a higher-precision format after on-the-fly dequantization so that gradient signals remain meaningful for the small set of trainable low-rank matrices. Third, system-level measures such as automatic paging of optimizer state to host memory are used to avoid rare but large transient spikes that would otherwise cause out-of-memory errors during optimizer updates.

These engineering choices together enable researchers to train very large parameter-count models on a single high-memory workstation or to finetune mid-sized models on consumer devices, thereby widening participation in experimental research and applied prototyping. The paper shows this is not merely an engineering curiosity: with the right combination of compact storage, faithful computation, and parameter-efficient updates, one can match the behavior of full-model finetuning on standard tests while running within drastically smaller hardware envelopes.

Concluding remark

Understanding where memory is spent during finetuning clarifies which levers are effective. Compressing stored weights helps with persistent storage, but peak training memory is dominated by intermediate hidden states and their gradients. In order to enable large-scale finetuning on restricted hardware, a holistic approach is needed: low-precision storage for frozen parameters, a computation format that preserves gradient fidelity, targeted low-parameter updates distributed across many layers, and runtime paging to manage rare spikes. The paper’s experimental program illustrates how combining these ideas makes large-model finetuning achievable on a far broader set of machines than was previously practical.

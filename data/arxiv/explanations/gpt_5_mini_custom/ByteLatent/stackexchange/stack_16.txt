\title{Stack Exchange of the Paper: "Byte Latent Transformer: Patches Scale Better Than Tokens"}

### How is causality preserved across patches when the local encoder uses a sliding window that can cross patch boundaries?
Question:
The local encoder’s attention window can cross patch boundaries to incorporate nearby left context. When the global model processes patch $j$, its query is derived from encoder states whose receptive field potentially includes bytes from previous patches. Is this equivalent to standard autoregressive conditioning at the patch level, or does it risk leaking information from patch $j$+1 back into $j$ via the encoder? A precise statement of the causal masking guarantees in the encoder would help.
Answer:
Short answer: BLT preserves causality. The encoder and cross‑attention masks are defined so that any patch representation used by the global (latent) transformer can only depend on bytes at or to the left of that patch’s end, and the global transformer itself uses block‑causal masking so it cannot attend to later patches. Together with the incremental‑patching requirement, this yields standard autoregressive conditioning at the patch level and prevents information from patch $j+1$ leaking back into patch $j$.

Why this holds (intuitive + precise):

1) Local encoder attention is causal and windowed. The local encoder uses a “local block causal” self‑attention mask: each byte representation $h_i$ can attend only to a fixed window of preceding bytes (up to window size $w_{\mathcal{E}}$) and never to future bytes beyond index $i$. Formally, for any byte index $i$ the encoder ensures $h_i = \mathrm{Encoder}(..., x_{\le i})$ where $x_{\le i}$ denotes only bytes at indices $\le i$ (subject to the fixed backward window). There is therefore no path inside the encoder that lets a byte representation depend on bytes to its right.

2) Cross‑attention pools only bytes inside the same patch. A patch representation $p_j$ is initialized by pooling embeddings of the bytes belonging to that patch, and every encoder cross‑attention query for $p_j$ is explicitly masked to attend only to keys/values corresponding to bytes in patch $j$ (the paper: “we use a masking strategy specific to patching where each query $Q_j$ only attends to the keys and values that correspond to the bytes in patch $j$”). Thus $p_j$ depends only on bytes that are in patch $j$ (and those bytes’ encoder contexts, which, by (1), reach only to the left).

3) Global transformer uses block‑causal masking at patch granularity. The latent/global transformer $\mathcal{G}$ uses a block‑causal attention mask that lets the model attend to patches up to and including the current patch but not to any later patch. So when producing outputs for patch $j$, $\mathcal{G}$ cannot see $p_{j+1}$ or later.

4) Incremental patching prevents future‑peeking at boundary selection. The paper requires patching to be incremental: $f_p(\mathbf{x}_{<i}) = f_p(\mathbf{x})_{<i}$. That ensures that at generation time the decision whether a boundary occurs at a position depends only on the prefix generated so far (no dependence on future bytes). In other words, patch boundaries themselves are not a source of future leakage. (The paper notes bpe is not incremental and that entropy patching must be implemented so it does not require access to future bytes when generating.)

Putting those points together, the causal graph for producing patch $j$ is limited to byte indices $\le \mathrm{end}(p_j)$: encoder byte states $h_i$ used to form $p_j$ have receptive fields only into earlier bytes, $p_j$ is built only from bytes in patch $j$, and $\mathcal{G}$ only conditions on $p_{\le j}$. Therefore the model’s conditional distribution for patch $j$ is a valid autoregressive factor conditioned only on earlier data:
$p(o_j \mid o_{<j}, p_{\le j})$ (and $p_{\le j}$ themselves depend only on bytes $\le \mathrm{end}(p_j)$).

A concise formal guarantee you can rely on:
- Encoder causal constraint: for any byte $i$, $h_i = F\big(x_{\max(1,i-w_{\mathcal{E}}+1):i}\big)$ (no dependence on $x_{>i}$).
- Patch construction constraint: $p_j = \mathrm{Pool}(\{h_i : i \in \mathrm{bytes}(p_j)\})$ and cross‑attention masks only those $h_i$.
- Global causal constraint: when computing outputs for patch $j$, $\mathrm{attentionMask}_{\mathrm{global}}$ only allows keys/values from patches $\le j$.
- Incremental patching: $f_p(\mathbf{x}_{<i}) = f_p(\mathbf{x})_{<i}$ ensures patch boundaries are decided without knowledge of future bytes.

Practical notes / caveats from the paper:
- Entropy patching uses a small entropy model to find boundaries. For generation you must ensure that the boundary decision is incremental (the paper states this as a requirement) — if you used an entropy computation that looked at a larger future context, that would break causality. The authors describe options like resetting entropy context boundaries and using approximate monotonic constraints to avoid “entropy drift” and to keep the entropy computation compatible with incremental generation.
- The encoder’s receptive field ($w_{\mathcal{E}}$) can cross patch boundaries to the left; that is intended and allowed because it uses only past information. That gives richer context for each patch without breaking autoregressiveness.

So: no leakage from patch $j+1$ back into $j$ if the encoder masking, cross‑attention masking, global block‑causal masking, and the incremental patching property are respected. The architecture, as described in the paper, enforces these conditions.

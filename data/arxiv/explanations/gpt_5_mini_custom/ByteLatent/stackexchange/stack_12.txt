\title{Stack Exchange of the Paper: "Byte Latent Transformer: Patches Scale Better Than Tokens"}

### What is the exact attention mask for the global latent transformer (‘block-causal’) at the patch level?
Question:
Section 2.1 states the global transformer uses a block-causal attention mask, restricting attention up to and including the current patch within the document. Does that mean patch $j$ can attend to all patch-level keys/values from patches $\le j$ within the same document (full prefix attention), and zero across documents? If patches vary in length across sequences, do you additionally pad and mask within a batch so that each sequence’s patch prefix is respected independently? A brief schematic of the patch-level mask would be helpful.
Answer:
Short answer: Yes — at the global (patch) level the Latent Global Transformer uses a per-document lower‑triangular (including diagonal) attention mask: patch $j$ may attend to any patch $k$ with $k \le j$ from the same document, and it must not attend to patches from other documents. When batching sequences with different numbers of patches you either (a) pad patch sequences to a common length and apply a per-example mask that (i) enforces the lower‑triangular causal pattern within the real patch positions and (ii) zeros out padded positions, or (b) avoid padding by packing patches across examples and maintain a per-query mask that blocks attention to keys coming from other examples (the paper uses packing to reduce wasted latent-transformer steps).

Why this is the correct interpretation (intuition + pointers to the paper)
- The paper says the global model “uses a block‑causal attention mask, which restricts attention to be up to and including the current patch within the current document.” That phrase is naturally implemented as a lower‑triangular mask on the patch sequence for each document: the global transformer is autoregressive over patches, so each patch’s query can see keys/values from the patch prefix (including itself) and not from future patches.
- “Within the current document” implies no cross‑document leakage in a minibatch (standard practice for autoregressive training). The local models are also explicitly prevented from crossing document boundaries (“can not cross document boundaries”), so the same holds at the global level.
- The paper also describes two practical batching strategies: they pad/truncate byte sequences to bound memory and, for efficiency, “pack batches of patches to avoid padding steps in the more expensive latent transformer. This ensures that every batch has the same number of patches.” Packing requires that the attention implementation use a mask that blocks queries from seeing keys belonging to different original examples.

Concrete schematic (textual)
- For a single document with $m$ patches the attention mask $M$ ($m \times m$) has $M[i,j] = 1$ if $j \le i$ and $0$ if $j > i$ ($i$ is query row, $j$ is key column). In other words $M$ is lower triangular with ones on the diagonal.
- For a minibatch of $B$ documents, form a block diagonal mask where each block is the lower‑triangular mask for that document; off‑block entries are zero to prevent cross‑example attention. If you pad document $p$ to length $m_{\max}$, the block for $p$ includes zeros in the rows/columns corresponding to padded positions so padded queries/keys are ignored.

What happens when patches vary in length across sequences
- Training: you must ensure the mask respects each sequence’s true patch prefix independently. Two options are described/used in the paper:
  1. Pad to a common patch length and apply per-example masks (lower triangular on valid patch positions, zeroing padded rows/columns).
  2. Pack patches so batches have equal numbers of patches and use an explicit per-query mask that prevents queries from attending to keys from different original sequences. The paper explicitly says they pack patches “to avoid padding steps in the more expensive latent transformer,” so packing + per-example masking is the preferred efficient implementation.
- Generation: because patching is incremental (the patching scheme must not look into the future), autoregressive generation is straightforward: at generation time patch $j$’s attention will be restricted to patches up to $j$ from the same document (and masked from other documents / unfinished sequences).

Implementation notes (practical)
- Use a fused attention kernel (Flash/FlexAttention) that supports arbitrary masks: supply a boolean mask $M$ where True (or 1) means allow attention. Build $M$ as described: block‑diagonal of per-document lower‑triangular masks plus zeroing padded positions.
- If packing, you must also pass an index/segment tensor so you can construct the same block‑diagonal effect without explicit padding. FlexAttention and some implementations allow a (query, key) pair mask built from segment ids.
- The local encoder/decoder attention masks are different: encoder uses a fixed window local block‑causal on bytes (can cross patch boundaries but not document boundaries); decoder cross‑attention masks are defined so bytes attend only to corresponding patch outputs (as described in the paper).

In sum: the global mask is per‑document lower‑triangular (patch $j$ attends to $k$ with $k \le j$ within the same document), and batching is handled either by padding+$per$‑example masks or by packing with masks/segment IDs so each sequence’s patch prefix is respected independently.

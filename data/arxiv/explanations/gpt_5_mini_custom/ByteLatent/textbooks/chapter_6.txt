\title{A Textbook about the Paper: "Byte Latent Transformer: Patches Scale Better Than Tokens"}

Chapter 6: Local Encoder: From Bytes to Patch Representations

# Byte embeddings and motivation for augmenting local context

The local encoder is the component of the Byte Latent Transformer (BLT) whose job is to turn raw bytes into the rich, contextual patch representations that the global latent transformer consumes. At the very first step each input byte is mapped into a continuous vector space by a byte embedding matrix. Concretely, each byte (one of 256 possible values) is embedded with an embedding table of shape $\mathbb{R}^{256 \times h_{\mathcal{E}}}$ producing an initial vector $x_i$ for byte position $i$. These per-byte vectors are the starting point for all subsequent local processing.

Embedding a byte as an isolated symbol is often not enough to capture the short-range structure that determines predictability and meaning in byte sequences. For example, the identity of the previous few characters strongly constrains the next byte in natural language (consider prefixes of words), and the same holds in code and other structured data. To give the local encoder direct access to this short-range context with a compact parameter budget, BLT augments each byte embedding with information derived from several recent byte n-grams. Augmenting the single-byte embedding in this way supplies the model with richer, context-aware features before any Transformer layers operate, improving the expressivity of the lightweight local encoder while keeping its compute modest.

Formally, this augmentation is implemented by forming byte n-grams ending at position $i$ for several sizes (in BLT these are $n \in \{3,4,5,6,7,8\}$), mapping each n-gram through a hash-based embedding table, summing those embeddings with the single-byte embedding, and normalizing. This produces an augmented embedding $e_i$ that carries both the identity of the current byte and a compact fingerprint of its recent local context. Because the augmentation is applied prior to the local transformer stack, downstream layers can focus on modeling interactions and longer-range dependencies between those already context-rich per-byte vectors.

# Hash n-gram embeddings (3–8 grams): design, roll-hash, collision/size trade-offs

BLT represents local context around each byte using hash-based n-gram embeddings. For a byte position $i$ and an n-gram size $n$, define the n-gram
\[
g_{i,n} = \{b_{i-n+1}, \ldots, b_i\},
\]
omitting any $n$ for which $i < n$. Each such n-gram is mapped to an embedding index with a fast hash function and then looked up in a shared embedding table $E_n^{hash}$. The augmentation for position $i$ is the sum of the single-byte embedding and the hash-embeddings for the chosen n-gram sizes:
\[
e_i = x_i + \sum_{n=3}^{8} E_n^{hash}(\text{Hash}(g_{i,n})).
\]
The implementation uses a rolling polynomial hash (RollPolyHash) so that hash values for overlapping n-grams can be updated efficiently as the model scans bytes; the index used to look up in the embedding table is
\[
\text{Hash}(g_{i,n}) = \text{RollPolyHash}(g_{i,n}) \bmod |E_n^{hash}|.
\]
After summation, $e_i$ is normalized by dividing by the number of components (the number of n-gram sizes used plus one for the single-byte embedding), which keeps the embedding scale stable as n-gram sizes vary.

There are important trade-offs in choosing the hash table sizes and the set of n-gram lengths. Larger tables reduce collision rates (different n-grams mapping to the same index), which in turn gives more unique context signals to the encoder. However, large tables consume memory and increase the embedding parameter count. BLT experiments show that hash embeddings materially improve performance, especially on certain domains (e.g., Wikipedia, GitHub), with diminishing returns beyond a few hundred thousand hash entries. In practice BLT uses 500,000 hashes with a single hash function for its production models; ablations in the paper vary this number (0, 100K, 200K, 400K) and observe that benefits plateau after roughly 300K entries. The rolling hash makes these larger tables practical since the hash computation itself is inexpensive and update-friendly.

Conceptually, the hash n-gram embeddings give the local encoder a compact, learnable summary of recent byte sequences without the combinatorial explosion of storing a full vocabulary of all possible n-grams. Collisions introduce approximation—different n-grams can share the same embedding—but, as the experiments show, a moderately large hash table balances approximation error against memory cost to produce robust, effective local features.

# Local block-causal attention windowing across dynamic patch boundaries

Once each byte has an augmented embedding $e_i$, the local encoder applies a lightweight transformer stack to model very local interactions among bytes. Crucially, this local self-attention uses a block-causal attention mask with a fixed receptive window of width $w_{\mathcal{E}}$. In other words, each byte representation may attend only to a fixed number of preceding bytes (up to $w_{\mathcal{E}}$), never to future bytes. The mask is local and causal: it enforces autoregressivity at the byte level inside the encoder while keeping the computational cost small by limiting the attention span.

An important property is that the local attention window can cross dynamically-determined patch boundaries. Patches are variable-length groups of bytes that are decided by the patching scheme (entropy patching, space patching, or fixed stride). The local block-causal mask does not constrain attention to stay within a single patch: a byte may attend to previous bytes that belong to earlier patches (subject to the window), but attention never crosses document boundaries. Allowing attention to cross patch boundaries gives the encoder access to immediate contextual information that can be critical for deciding how a patch should be summarized, while still keeping the attention computation bounded by $w_{\mathcal{E}}$.

Using a fixed, small window has two practical benefits. First, it keeps the transformer's per-step cost low, which is important because the local encoder runs on every byte. Second, by limiting the local receptive field, the encoder focuses on short-range structure—what matters for forming an initial, high-quality pooling into a patch—while leaving longer-range, high-capacity modeling to the global latent transformer.

# Per-patch cross-attention pooling: queries from pooled bytes, keys/values from byte-level representations

The central mechanism for turning byte-level features into patch representations is the per-patch cross-attention pooling module. This module follows the Perceiver-style input cross-attention idea, adapted so that latents correspond to variable-length patches rather than a fixed set. The cross-attention bridges the byte domain and the patch domain: keys and values come from byte-level transformer outputs, while queries are patch-specific vectors that ask “what summary do I want for this patch?”

Initialization of the queries is done by pooling the byte representations that belong to the patch. Let $f_{\text{bytes}}(p_j)$ denote the sequence of byte representations (from the local transformer) that constitute patch $p_j$. The initialization for patch $j$ is
\[
P_{0,j} = \mathcal{E}_C\big(f_{\text{bytes}}(p_j)\big),
\]
where $\mathcal{E}_C$ is a learned linear projection used to produce the initial query for the cross-attention module. In practice BLT uses a simple pooling function (e.g., max-pooling) over the bytes of the patch to create a fixed-size vector, then applies $\mathcal{E}_C$ to produce the query. The dimensionality of $\mathcal{E}_C$ is written as $\mathbb{R}^{h_{\mathcal{E}} \times (h_{\mathcal{E}} \times U_{\mathcal{E}})}$ in the paper to reflect a projection from the encoder hidden size to multiple attention-head query vectors.

The cross-attention itself proceeds in the standard multi-head attention fashion. For layer $l$ (cross-attention stacked with local transformer layers) the update is written as
\[
P_l = P_{l-1} + W_o\Big(\text{softmax}\big(\tfrac{QK^\top}{\sqrt{d_k}}\big)V\Big),
\]
with
\[
Q_j = W_q(P_{l-1,j}),\qquad K_i = W_k(h_{l-1,i}),\qquad V_i = W_v(h_{l-1,i}),
\]
where $h_{l-1,i}$ are the byte-level hidden representations from the preceding local transformer layer, and $W_q,W_k,W_v,W_o$ are learned projections. In short, each patch query attends to the byte keys/values that belong to that patch and produces a compact patch representation. After cross-attention the patch vectors $P_l$ may be further processed or passed upward to the global latent transformer.

This design has two virtues. First, pooling into queries focuses attention computations on the bytes that actually belong to each patch, avoiding wasted work across unrelated byte positions. Second, because the queries originate from pooled byte features, the resulting patch representations are contextualized by both the local byte interactions (via the local transformer) and the selective attention aggregation provided by the cross-attention block.

# Masking so each patch attends only to its bytes

For correctness and efficiency the cross-attention module enforces a patch-specific mask: each query $Q_j$ is allowed to attend only to keys and values coming from the set of byte positions that constitute patch $p_j$. This is particularly important because patches are variable-length and may occur at different positions in the document. The mask prevents leakage of information across patches during encoder pooling, ensuring that the patch representation summarizes only its own bytes (plus any local context already encoded into the bytes via the local transformer).

Implementationally, this means that the attention computation for patch $j$ is performed with a small $|p_j| \times |p_j|$ key/value block (plus multi-head splitting), rather than a full-document attention matrix. Using these dynamic masks both reduces compute—since each patch attends to a smaller set of keys/values—and preserves the semantic integrity of patches, which is especially important when patches are determined by entropy or whitespace boundaries. In scenarios where the patching scheme produces very long patches, the cross-attention still benefits from the locality imposed by the encoder's block-causal self-attention, and the patch-level masking makes the cross-attention scalable even for variable patch lengths.

# Multi-head design with split/concat to match global hidden size

A practical engineering detail arises because local encoder representations typically use a smaller hidden dimensionality $h_{\mathcal{E}}$ than the global latent transformer hidden size $h_{\mathcal{G}}$. BLT reconciles this difference by using multiple parallel heads (or splits) in the encoder that are later concatenated to produce a vector of the dimensionality expected by the global model.

Concretely, during cross-attention the patch vectors $P_l$ are maintained as multiple heads of dimension $h_{\mathcal{E}}$ (one head per local split). After attention, these head-wise vectors are concatenated to form patch representations in $\mathbb{R}^{h_{\mathcal{G}}}$. The paper denotes the number of such splits by $k$ (the ratio of patch-dimension to byte-dimension) and gives $k=2$ as an example in figures. This split/concat pattern allows a lightweight local encoder (smaller $h_{\mathcal{E}}$ and fewer layers) to produce rich, high-dimensional patch vectors suitable for the heavy-lift done by the global transformer, without forcing the local encoder itself to run a large number of expensive operations at the higher dimension.

Using multi-head split/concat also integrates naturally with multi-headed attention: each local head can learn complementary projections over the bytes in a patch, and their concatenation forms a comprehensive representation that the global model can consume directly.

# Normalization choices, no positional embeddings in cross-attn, residuals

Several architectural choices in the encoder cross-attention module are made to simplify learning and preserve stability. The attention module uses pre-LayerNorm on queries, keys, and values. Applying LayerNorm before the attention projections is a common stability pattern that reduces covariate shift into the attention computation, improves gradient behavior, and makes residual connections more predictable.

The cross-attention block intentionally omits positional embeddings. Because the queries are initialized by pooling over the bytes of a patch and because the local transformer already encodes local ordering information via its block-causal self-attention (and via RoPE where applicable in self-attention layers), explicit positional encodings inside the cross-attention are not necessary. The absence of additional positional embeddings simplifies the pooling mechanism and avoids double-counting positional signals that the local transformer has already captured.

Finally, residual connections are used around the cross-attention block: the module updates the patch representation with an additive residual term (as in $P_l = P_{l-1} + \dots$). This residual construction helps training by enabling gradients to flow unimpeded and by allowing the cross-attention to act as a correction on top of the pooled initialization rather than a wholesale replacement.

# Putting it all together: the encoder pipeline

Summarizing the flow: each raw byte is embedded into $x_i$ and augmented with hash n-gram embeddings to produce $e_i$ (normalized). A lightweight stack of local transformer layers with block-causal windowed attention processes the sequence of $e_i$, producing byte-level representations $h_{l,i}$. Interleaved with these transformer layers are per-patch cross-attention pooling modules: for each patch $p_j$, bytes belonging to the patch are pooled and projected into initial queries $P_{0,j}$; these queries attend only to the keys/values formed from the bytes of the patch to produce refined patch vectors $P_l$. Multiple heads/splits are maintained at encoder dimension and concatenated to match the global transformer dimension $h_{\mathcal{G}}$. The resulting sequence of patch representations $\{p_j\}$ is then passed to the global latent transformer for the high-capacity, long-range autoregressive modeling that constitutes BLT’s main computation.

This encoder design balances computational efficiency and expressive power. Hash n-gram augmentations give the encoder an economical awareness of immediate context, block-causal local attention keeps per-byte cost low but informative, and the masked per-patch cross-attention produces compact, contextually grounded patch latents that the global model can leverage. Together these elements allow BLT to work directly with raw bytes while keeping the expensive global transformer steps focused where they matter most.

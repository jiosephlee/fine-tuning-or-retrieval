# Meet BLT: The Tokenizer-Free LLM That Thinks in Patches

## TL;DR
Byte Latent Transformer (BLT) is a tokenizer-free language model that operates directly on raw bytes. Instead of a fixed token vocabulary, BLT groups bytes into dynamically sized "patches" and runs a large autoregressive transformer on those patches. Patch boundaries are chosen based on where the next-byte prediction is uncertain, so the model spends more compute on hard decisions and less on predictable stretches. The result: matching token-based model performance at scale, better inference efficiency (fewer FLOPs in many settings), and improved robustness on noisy and character-level tasks.

## Why get rid of tokenizers?
Tokenizers compress byte sequences into discrete tokens and have been crucial for scaling transformers. But they also introduce biases:

- They fix a vocabulary ahead of time, which can be suboptimal for noisy inputs, new domains, or low-resource languages.
- They allocate the same amount of transformer compute to every token, even though information density varies within text (for example, the first character of a word is often harder to predict than the remaining characters).

BLT trades the fixed-token abstraction for a dynamic, byte-level grouping mechanism that adapts compute allocation based on how surprising the next byte is.

## The core idea: patches instead of tokens
BLT segments a byte sequence x = {x_i} into patches p_j using a patching function f_p. The number of patches (and thus the number of steps the main transformer runs) controls compute. Larger average patch size means fewer transformer steps and lower inference FLOPs; smaller patches mean more steps and often greater modeling detail.

Key patching strategies discussed:

- Strided patching: fixed-size groups of k bytes. Simple but not adaptive.
- Space patching: start a new patch after space-like bytes (words as natural groups). Better than fixed stride but still heuristic.
- Entropy patching: run a small byte LM to estimate next-byte entropy and put boundaries where the next-byte entropy is high (or high relative to the previous byte). This is BLT’s primary dynamic method.

The entropy used is the standard next-token entropy under a small byte LM p_e:
H(x_i) = sum_{v in V} p_e(x_i=v | x_{<i}) log p_e(x_i=v | x_{<i})

Two practical boundary tests are used:
- Global: H(x_t) > θ_g
- Relative: H(x_t) - H(x_{t-1}) > θ_r

Entropy patching is computed as a lightweight preprocessing step during data loading and is incremental (it does not require future bytes to decide the current boundary), unlike standard BPE tokenization.

## BLT architecture at a glance
BLT decomposes modeling into three components:

1. Local Encoder (small): maps raw bytes into patch-level latent representations. It uses byte embeddings augmented with hash n-gram embeddings and alternates lightweight transformer layers with a cross-attention module that pools bytes for each patch.

2. Latent Global Transformer (large): the main autoregressive model operating on patch representations. It uses a block-causal attention mask so each patch attends up to the current patch in the document. This component consumes most FLOPs during training and inference.

3. Local Decoder (small): expands the global patch outputs back into byte sequences. It also uses cross-attention (bytes query patches) and local transformer layers to produce next-byte predictions.

Notable design details:
- Hash n-gram embeddings: for each byte position i, BLT forms byte-grams g_{i,n} for n ∈ {3,...,8}, hashes them, and adds their embeddings to the per-byte input. This helps represent local contexts compactly and boosts performance.
- Cross-attention in encoder/decoder pools bytes into patches and reconstructs bytes from patch representations. Decoder cross-attention is particularly beneficial.
- No fixed-size vocabulary for patches — arbitrary byte groups map into latent vectors via the encoder/decoder.

## How BLT controls FLOPs
Because the global transformer runs per patch, the average patch size n_p largely determines inference cost. BLT computes FLOPs per byte by summing contributions from the global transformer (per-patch), local encoder/decoder transformers (per-byte), and cross-attention blocks, then normalizing per byte. In practice, increasing average patch size reduces the global transformer's steps and cuts inference FLOPs; the saved compute can be reallocated to grow the global transformer (more parameters) while keeping inference budget fixed.

This flexibility is something tokenizers can't offer without increasing vocabulary and expensive embedding/output layers. Tokenizers trade off between vocabulary size and compute in a way that limits how much you can change per-token granularity without costs elsewhere.

## Scaling behavior: patches scale better than tokens
BLT presents a flop-controlled scaling study up to 8B parameters and up to 4T training bytes. Important empirical findings:

- When trained in compute-optimal regimes (matching the parameter-to-data ratios used for BPE baselines), BLT matches or outperforms BPE models like Llama 3 across scales from 1B to 8B parameters.
- Larger patch sizes (e.g., average patch sizes ~6–8 bytes) let BLT reduce inference FLOPs by up to ~50% versus tokenizers, while maintaining or improving downstream performance at larger model scales.
- Under a fixed inference-FLOP budget, BLT can increase both patch size and model size simultaneously. Experiments show that models built this way exhibit better scaling trends than token-based models: small BPE models perform better at tiny training budgets but are overtaken by BLT models not far beyond the compute-optimal point.

These trends suggest that dynamic patching combined with reallocating compute to the global transformer is a useful new axis for model scaling.

## Robustness and character-level abilities
Because BLT models operate on bytes and preserve sub-token information:

- They are more robust to character-level noise (case changes, dropped characters, repeated characters). In the paper’s noisy HellaSwag experiments, BLT showed consistent advantages over token-based models.
- BLT excels at character-aware benchmarks like CUTE (orthographic and manipulation tasks) and grapheme-to-phoneme (G2P) tasks, with large improvements over BPE models on many character-level tasks.
- On low-resource machine translation (FLORES-101), BLT shows advantages on many low-resource language pairs and gains when translating to/from English for long-tail byte sequences.

Overall, modeling raw bytes helps long-tail generalization and handling inputs where tokenization would fragment or obscure subword structure.

## Practical notes: entropy model and implementation
- The entropy model used for dynamic patching is a small byte-level transformer (e.g., ~100M parameters and a sliding window of 512 bytes in default experiments). Entropy model size and context both matter, with diminishing returns past ~50M parameters in the ablations.
- Entropy patching is computed during data loading (lightweight preprocessing), not learned end-to-end in the current setup.
- BLT uses implementation techniques like FlexAttention and FlashAttention to handle dynamic masks and efficiency-critical layers.

## Bootstrapping from existing models
BLT experiments include a "byte-ify" workflow: initialize the global transformer of BLT from a pre-trained token-based model (Llama 3.1), then train the local encoder/decoder while updating the global transformer more slowly. This converts a tokenized model into a tokenizer-free version with competitive performance and faster convergence — a practical migration path from existing tokenized checkpoints.

## Limitations and open directions
- BLT used scaling law settings (optimal steps and data ratios) derived from BPE-based studies; the true compute-optimal tradeoffs for BLT may differ and deserve their own study.
- Some experiments were run at smaller scales (many ablations at ≤1B parameters), and optimal architecture choices might shift at larger scales.
- Current entropy patching is a separately trained module used at data-load time. End-to-end learned patching is left for future work.
- Although theoretical FLOP savings are shown, runtime and library-level optimizations for BLT’s dynamic masks and cross-attention may lag behind highly optimized token-based implementations.

## Takeaway
BLT shows it is possible to train large, tokenizer-free models that operate on raw bytes and still match or exceed token-based performance while offering new efficiency and robustness trade-offs. The central insight is simple and powerful: group bytes dynamically where the data is predictable, and spend your heavy transformer layers only when and where they matter. That idea — patches that adapt to uncertainty — opens a fresh axis for model scaling and real-world robustness.

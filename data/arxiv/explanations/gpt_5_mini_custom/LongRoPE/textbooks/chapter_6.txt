\title{A Textbook about the Paper: "LongRoPE: Extending LLM Context Window Beyond 2 Million Tokens"}

Chapter 6: Searching Non-Uniform Rescale Factors

# Search space design: $\lambda_i \in [1.0,\,1.25\times s]$ with step $0.01$; $\hat{n}\in\{0,1,2,4,8,12,16,20,24,28,32,64,128,256\}$

The search that LongRoPE performs is over two kinds of choices: a per-RoPE-dimension rescale $\lambda_i$ and a threshold $\hat{n}$ that controls how many initial token positions are left unscaled. Concretely, the algorithm searches the vector $\{\lambda_i\}_{i=0}^{d/2-1}$ together with a single integer $\hat{n}$. Each $\lambda_i$ controls how much the rotary angle for the $i$-th RoPE pair is scaled for positions $n\ge\hat{n}$; for $n<\hat{n}$ the original RoPE is kept. In the paper this is implemented by searching $\lambda_i$ values and setting the applied rescale factor to $\hat{\lambda}_i=1/\lambda_i$ in the RoPE formula.

To make the search concrete and finite, each $\lambda_i$ is constrained to a fixed interval and discretized. The interval used is
\[
\lambda_i \in \left[1.0,\;1.25\cdot s\right],
\]
where $s=\frac{L'}{L}$ is the extension ratio (extended length divided by original length). The interval lower bound $1.0$ corresponds to pure extrapolation (no interpolation, i.e., preserving original rotation frequencies), while the upper bound $1.25\cdot s$ allows slightly more aggressive interpolation than the simple linear positional interpolation (PI) which would use $\lambda=s$. The step size used in the search is $0.01$, so each $\lambda_i$ takes values on a regular discrete grid.

For the token-position threshold $\hat{n}$, LongRoPE restricts the candidates to the small set
\[
\hat{n}\in\{0,1,2,4,8,12,16,20,24,28,32,64,128,256\}.
\]
When $\hat{n}=0$ every token position uses the searched $\lambda_i$ scalings; for positive $\hat{n}$ the first $\hat{n}$ positions are left unmodified (i.e., original RoPE). This discrete set for $\hat{n}$ encodes the intuition that only a small number of starting positions typically need special treatment, and it keeps the search tractable.

This design produces a very large but structured search space: many degrees of freedom (one $\lambda_i$ per RoPE dimension) combined with a small set of $\hat{n}$ choices.

# Why the search space explodes with $s$ (example: $4\times$ leading to $\sim 4\times 10^{167}$ combinations)

It is important to see why an exhaustive search is infeasible. Each $\lambda_i$ can take roughly
\[
M(s) \approx \frac{1.25\cdot s - 1}{0.01} + 1
\]
distinct values given the interval and $0.01$ step. For example, when $s=4$ we have $1.25\cdot s = 5.0$, so the allowed values for each $\lambda_i$ are approximately the discrete set $\{1.00,1.01,\dots,5.00\}$, giving about $401$ values (the paper rounded to about $400$).

If the model has $d/2$ RoPE dimension pairs over which we search independently, and we also have $N_{\hat n}$ choices for $\hat n$ (here $N_{\hat n}=14$), the naive number of combinations is
\[
\text{combinations} \approx M(s)^{\,d/2}\times N_{\hat n}.
\]
Using the numbers in the paper as an illustrative example, for $s=4$ and $d/2=64$ the count becomes
\[
400^{64}\times 14 \approx 4\times 10^{167}.
\]
This astronomical figure illustrates why exhaustive enumeration is impossible: the number of candidate rescaling vectors grows exponentially in the number of per-dimension parameters and multiplicatively with the granularity induced by $s$. As $s$ increases, $M(s)$ grows linearly, and the exponential blow-up in $M(s)^{d/2}$ becomes rapidly overwhelming. This combinatorial explosion motivates the use of a guided search method rather than brute force.

# Evolutionary search pipeline: initialization, evaluation by perplexity, top-k selection, mutation, crossover

To explore this enormous space efficiently, LongRoPE frames the problem as a black-box optimization over discrete candidate solutions and adopts an evolutionary (genetic) search. The high-level loop of the evolutionary pipeline is:

1. Initialization. Create an initial population $\mathcal{P}_0$ of $P$ candidate solutions. Each candidate is a full specification of $\{\lambda_i\}$ and a choice of $\hat{n}$.

2. Evaluation. For each candidate in the population, apply its $\{\lambda_i,\hat{n}\}$ to the model's RoPE during inference and compute a scalar score: the perplexity (negative log-likelihood) on a small set of held-out long-document samples $\mathbf{X}$ whose lengths meet the target $L'$. Perplexity is the objective to minimize.

3. Selection. Keep the top-$k$ candidates (lowest perplexities) as parents for the next generation.

4. Variation. Generate new candidates via mutation and crossover operations applied to the selected parents. Mutations perturb $\lambda_i$ values and/or $\hat{n}$; crossover mixes parameters from two parents.

5. Constraint filtering. Reject any newly generated candidate that violates problem-specific constraints (see monotonicity below) before evaluation.

6. Next generation. The new population is formed from the selected parents plus the newly generated offspring. Repeat evaluation and selection for $\mathcal{T}$ iterations.

7. Termination. After $\mathcal{T}$ iterations return the candidate with the lowest perplexity observed.

This pipeline is summarized in Algorithm 1 of the paper. Two aspects deserve emphasis. First, the evaluation step uses real model inference and language-model perplexity as the fitness function; this directly measures how well a candidate preserves the model’s language modeling capability at the target length. Second, most of the computational cost lies in repeated inference for perplexity calculation, so everything that reduces the number of candidates requiring full evaluation (good initialization, cheap constraints) yields big speedups.

# Optimized initialization: seeding with PI, NTK, and YaRN solutions and mutating

A naive random initialization would waste many evaluation steps on very poor candidates. To accelerate convergence, the LongRoPE search seeds the initial population with known, sensible baselines: the positional interpolation solutions given by PI (linear interpolation), NTK-based scaling, and YaRN’s grouped strategy. Concretely, these three known rescale patterns are included as 3 individuals in the initial population $\mathcal{P}_0$. The remaining $P-3$ members are generated by mutating these three seeds with some mutation probability $p$.

This optimized seeding has two beneficial effects. First, it guarantees that the search starts with feasible, reasonably good solutions (the three seeded individuals are already much better than random). Second, by mutating around those baselines we bias the initial population towards regions of the search space that are more likely to contain useful non-uniform patterns. This both improves early-generation fitness and reduces the number of generations required to find high-quality candidates.

The mutation operation used at initialization (and later during evolution) is simple: randomly select a subset of dimensions and perturb each chosen $\lambda_i$ by a small discrete step (multiples of $0.01$) within the allowed interval, and possibly change $\hat{n}$ to one of its discrete options. Because seeds are near good solutions, these small local perturbations are effective at finding improvements that preserve desirable structure from the baselines.

# Monotonicity constraint $\lambda_i \le \lambda_{i+1}$: theory motivation (higher frequencies less interpolation), practical speedups

A central structural constraint in the search is monotonicity across RoPE dimensions:
\[
\lambda_0 \le \lambda_1 \le \cdots \le \lambda_{d/2-1}.
\]
This enforces that the rescale factors are non-decreasing with the RoPE dimension index. The motivation for this constraint is twofold: theoretical and practical.

Theoretical motivation. RoPE’s rotary angles embed different frequency bands across dimensions: lower-index dimensions correspond to higher-frequency components and higher-index dimensions to lower-frequency components (the NTK and Fourier analyses underpin this view). High-frequency components are responsible for fine-grained positional discrimination and should therefore be subjected to less interpolation (i.e., smaller $\lambda$) to avoid collapsing distinguishability among nearby positions. Low-frequency components can be interpolated more aggressively because they encode coarser positional patterns. Imposing $\lambda_i$ non-decreasing aligns the searched scalings with this frequency-structured view.

Practical motivation and speedup. Enforcing monotonicity dramatically prunes the candidate space. Many randomly generated or mutated vectors would violate monotonicity; by filtering them out before evaluation the search avoids wasting expensive model inference on implausible candidates. In addition, the monotonicity constraint encourages smoother, well-behaved scalings that are easier to fine-tune during evolution (mutations will only need to tweak local slopes rather than explore arbitrary zig-zag patterns across dimensions). This makes the evolutionary operators more effective and stabilizes the fitness landscape.

Because only monotonic candidates are evaluated, the effective branching factor of the search drops substantially: rather than exploring every combination of independent per-dimension choices, the algorithm only considers non-decreasing sequences, which are a small subset of all possible vectors. This is the single most important pruning heuristic in practice.

# Hyperparameters: population size $P$, mutation/crossover sizes $N_1/N_2$, mutation prob $p$, iterations $\mathcal{T}$

The evolutionary search has a number of free hyperparameters that trade off exploration, exploitation, and compute cost. The paper uses two concrete configurations depending on the target window size.

For target windows within $256\text{k}$ the recommended settings are:
- population size: $P=64$,
- mutation offspring per generation: $N_1=16$,
- crossover offspring per generation: $N_2=16$,
- mutation probability: $p=0.3$,
- total iterations: $\mathcal{T}=40$,
- select top-$32$ candidates to form parents for mutation/crossover.

Perplexity evaluation in this regime is computed on 5 random samples from the PG19 validation set, each having at least the target length.

For windows beyond $512\text{k}$ (where each evaluation is more expensive due to longer sequences) the paper halves the population, mutation, and crossover sizes to reduce compute: i.e., $P\leftarrow P/2$, $N_1\leftarrow N_1/2$, $N_2\leftarrow N_2/2$ (the iteration count and selection strategy are similarly scaled to maintain reasonable search quality). In that regime, perplexity is measured on 3 random samples from Pile-Books3 validation because each sample is extremely long.

Choosing these hyperparameters balances two competing needs. A larger $P$ improves exploration and reduces the risk of premature convergence, but each generation requires $P$ full-model perplexity evaluations and can be very costly for long targets. A larger $\mathcal{T}$ allows more generations of refinement. The values used in the paper were found empirically to work well across LLaMA2 and Mistral experiments.

# Non-finetuned $8\times$ extension to 32k: why better initialization yields stable perplexity

One especially useful empirical finding is that LongRoPE’s search can produce non-uniform RoPE scalings that permit substantial context window extension without any fine-tuning. In particular, using the searched per-dimension $\lambda_i$ (and optimal $\hat{n}$) the paper demonstrates stable language-model perplexity when extending from 4k to 32k — an $8\times$ extension — with no further model training.

Why does this work? The answer lies in what the search preserves. Linear interpolation (PI) simply rescales all rotation angles uniformly by $s$, which “crowds” many different token positions into a narrow angular range and undermines the model’s ability to distinguish nearby tokens. NTK-style and YaRN-style methods mitigate this by spreading interpolation across dimensions, but they do so using fixed analytic rules or coarse grouping. LongRoPE’s per-dimension search discovers fine-grained, non-uniform scalings that keep the most important (high-frequency) RoPE dimensions close to their original scales while interpolating more in dimensions that can tolerate it.

Concretely, the best-found candidates often have small $\lambda_i$ (near $1.0$) for the early, high-frequency dimensions and larger $\lambda_i$ for later, low-frequency dimensions. In addition, optimal $\hat{n}$ values often protect a modest number of initial token positions from any interpolation at all, preserving the highly attended prefix behavior that many transformer layers rely on. These two forms of non-uniformity—per-dimension and per-position—work together to reduce the information loss caused by interpolation and therefore maintain low perplexity even without fine-tuning.

From the evolutionary-search perspective, initializing with PI/NTK/YaRN seeds and then locally mutating allows the optimizer to find these delicate trade-offs: it starts from sensible baselines and then refines where those baselines over- or under-interpolate. The monotonicity constraint ensures the refinements remain aligned with the frequency-based intuition. Together these elements explain why a guided, constrained evolution can produce an $8\times$ non-finetuned extension that is stable in practice.

# Summary and practical notes

Searching for non-uniform per-dimension and per-position RoPE rescale factors is an effective way to initialize models for very large context extensions. Because the discretized search space grows combinatorially with the extension ratio $s$ and the number of searched dimensions, LongRoPE combines three crucial design choices to make search practical and effective: (1) a restricted but expressive discretization $\lambda_i\in[1.0,1.25s]$ with step $0.01$ and a small set of $\hat{n}$ values, (2) an evolutionary search seeded by strong baselines (PI, NTK, YaRN) and using mutation/crossover, and (3) a monotonicity constraint $\lambda_i\le\lambda_{i+1}$ that is theoretically motivated and dramatically reduces wasted evaluations. The paper’s recommended hyperparameters (e.g., $P=64$, $N_1=N_2=16$, $p=0.3$, $\mathcal{T}=40$ for targets up to $256\text{k}$) provide a practical starting point; for larger targets the population and offspring counts are halved to control compute. The resulting searched scalings both improve non-finetuned extensions (up to $8\times$) and provide much better initializations for the modest fine-tuning used to reach extreme windows like $2048\text{k}$.

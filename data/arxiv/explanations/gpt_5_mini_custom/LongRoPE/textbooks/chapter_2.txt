\title{A Textbook about the Paper: "LongRoPE: Extending LLM Context Window Beyond 2 Million Tokens"}

Chapter 2: Foundations: Attention, Positional Encodings, and RoPE

# Transformer attention and why sequence order needs to be encoded
Transformers compute attention between token representations without any built‑in notion of sequence order. In a self‑attention layer each token produces query, key and value vectors; attention weights arise from inner products between queries and keys, and these weights control how information flows across positions. If the model only used token embeddings (or wordpiece ids) but no positional signal, the attention mechanism would be permutation‑invariant: permuting input tokens would produce the same set of pairwise interactions and thus the model could not reliably distinguish different token orders. For language and other sequential data the order is essential — meaning, the model must be given an explicit positional signal so that attention can depend on where each token sits in the sequence.

Accordingly, Transformer architectures use positional encodings or embeddings added to (or combined with) token representations so that the attention computation becomes order‑aware. The paper frames this as: “Transformer models require explicit positional information, often in the form of position embedding, to represent the order of input tokens,” and the rest of the work focuses on a particular family of positional encodings, Rotary Position Embedding (RoPE), which is widely adopted in modern large language models.

# Absolute vs. relative positional embeddings; pros and cons
Position embeddings come in different flavors. One common summary (as used in the community and implicit in the paper’s context) is to contrast absolute and relative approaches. Absolute positional encodings associate each token position with a fixed vector (or a deterministic transform of the position) and inject that information into token representations. Relative approaches, instead, encode distance or relative offsets between token pairs so that attention can directly depend on relative displacement rather than absolute index.

The text of the paper centers on RoPE as a positional encoding mechanism that provides a compact, rotation‑based encoding of position that is applied to queries and keys. In practice, different choices trade off properties: absolute encodings give a direct index signal, but can be brittle when models are asked to operate at positions not seen during training (new absolute indices create out‑of‑distribution inputs). Relative encodings can be more robust to varying sequence lengths and emphasize pairwise offsets, but they typically require different attention formulations or architectural changes. RoPE occupies a middle ground in practice: it applies a deterministic, index‑dependent rotation to query/key vectors. As the paper explores, the way those rotation angles are scaled (for example when extending a model’s context window) has strong practical consequences for robustness, crowding of position signals, and whether fine‑tuning is needed.

# RoPE mathematics and intuition: rotation in query/key space, frequencies across dimensions
RoPE encodes positional information by rotating components of the query and key vectors by position‑dependent angles. The encoding is implemented dimensionwise using sine and cosine of rotary angles so that, when queries and keys are rotated consistently, their inner product carries position information. A convenient way to view the RoPE encoding is as pairs of sine/cosine features for each rotary frequency.

The paper presents a compact representation of RoPE for a token at position index $n$ (with embedding dimension $d$) as:
\[
\left[\cos(n\theta_0),\; \sin(n\theta_0),\; \cos(n\theta_1),\; \sin(n\theta_1),\; \ldots,\; \cos(n\theta_{d/2-1}),\; \sin(n\theta_{d/2-1})\right]
\]
where each $n\theta_i$ is the rotary angle for the $i$‑th (pair) dimension. Intuitively, each dimension pair behaves like a 2D rotation of a vector by angle $n\theta_i$. If the query and key are rotated by the same position‑dependent angle, the cosine of their angle difference appears in the dot product, allowing attention to reflect relative phase differences induced by positions.

The choice of the sequences of angles $\theta_i$ across dimensions determines a spectrum of positional frequencies. In RoPE the angles vary across dimensions so that different dimensions encode different spatial frequencies (some dimensions change rapidly with $n$, others slowly). This multi‑frequency representation gives the model both fine and coarse positional resolution across different dimensions.

# Key variables and notation: n (position), d (dimension), θ, β, rotation angle n/β^i
To reason precisely about RoPE we use the notation from the paper. Let:
- $n$ denote the token position index (an integer counting positions in the input sequence),
- $d$ denote the embedding dimension (so there are $d/2$ sine/cosine pairs),
- $\theta_i$ denote the base rotation frequency for the $i$‑th pair of RoPE dimensions,
- $n\theta_i$ denote the actual rotary angle applied at position $n$ for that dimension.

The paper adopts a common parametrization of the per‑dimension frequencies. A scalar base value (also called $\theta$ in the paper, with a conventional default of $10000$) defines the frequency schedule. The per‑dimension frequency is given by
\[
\theta_i = \theta^{-2i/d},
\]
and the corresponding rotary angle for position $n$ is $n\theta_i$. To simplify certain expressions, the paper introduces
\[
\beta=\theta^{2/d},
\]
and writes the rotation angle compactly as
\[
\frac{n}{\beta^i}.
\]
So the $i$‑th dimension’s rotary angle at position $n$ can be expressed as $n/\beta^i$. This form makes clear the geometric progression of effective wavelengths across dimensions: increasing $i$ multiplies the denominator by powers of $\beta$, producing progressively smaller angles per unit $n$ (i.e., lower frequencies).

Using the cosine/sine pair form, RoPE represents position $n$ across the $d$ dimensions via the sequence of $\cos(n/\beta^i)$ and $\sin(n/\beta^i)$ terms (paired across $i$ from $0$ to $d/2-1$). In code or practical implementations these rotations are applied directly to slices of query and key vectors so that the attention dot products incorporate these phase shifts.

# How base frequency (e.g., 10000) governs spectrum of positional frequencies
The base scalar $\theta$ (often set to $10000$) controls the overall spacing of frequencies across the $d$ RoPE dimensions. Through the relation $\theta_i=\theta^{-2i/d}$ and $\beta=\theta^{2/d}$, the per‑dimension rotary angles form an exponential sequence. Concretely, when $\theta=10000$ and the dimension index $i$ increases, $\beta^i$ grows exponentially, and hence the rotation angle $n/\beta^i$ shrinks exponentially for a fixed $n$. Early (low‑indexed) dimensions therefore have larger rotation angles per unit position (higher frequency components that change rapidly with $n$), while later dimensions have smaller angles (low frequency components that vary slowly with $n$).

This spectrum is important for two reasons emphasized in the paper. First, having multiple frequencies gives the model the ability to represent both small positional offsets (via high‑frequency dimensions) and large scale positional context (via low‑frequency dimensions). Second, when attempting to extend a model’s usable context window by rescaling or interpolating positional angles, different RoPE dimensions respond differently: low‑index (high‑frequency) dimensions are more sensitive to rescaling and often benefit from less interpolation, whereas high‑index (low‑frequency) dimensions can tolerate or even require more aggressive rescaling. The paper leverages that observation: non‑uniform interpolation across RoPE dimensions (and also different handling of early token positions) preserves key information in the original RoPE and leads to much better behavior when extending the context window.

A final practical point in the paper’s development is that many context‑extension strategies operate by rescaling the effective rotary angles. If $\lambda$ denotes a rescale factor tied to a target extension ratio $s=L'/L$, then a common interpolation scheme is to replace $n$ with $n/\lambda$ (or equivalently scale $\theta_i$). The paper unifies such schemes in the form
\[
\left[\cos\!\bigg(\frac{n}{\lambda(\beta)^0}\bigg),\; \sin\!\bigg(\frac{n}{\lambda(\beta)^0}\bigg),\; \cos\!\bigg(\frac{n}{\lambda(\beta)^1}\bigg),\; \ldots\right],
\]
and explores how choosing $\lambda$ uniformly or non‑uniformly across dimensions and token positions impacts model performance when the context window is extended.

In summary, RoPE builds a multi‑frequency rotation‑based positional representation parameterized by a base $\theta$ (commonly $10000$), dimension index $i$, embedding dimension $d$, and token position $n$. Understanding how these variables interact — how rotation angles scale across dimensions and how rescaling those angles affects positional resolution — is central to the paper’s investigation into extending LLM context windows without losing the model’s ability to distinguish nearby tokens or to generalize to unseen positions.

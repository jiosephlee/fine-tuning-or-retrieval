# Multiplicative Dropout: Regularizing Multiplicative Adapters in BOFT

When we finetune massive pre-trained models, a small tweak can make a big difference. Orthogonal Butterfly Finetuning (BOFT) is one such tweak: it adapts each layer by multiplying the original weights with a sequence of sparse, structured orthogonal matrices—known as butterfly components. This multiplicative update preserves important geometric properties of the pre-trained weights but can also introduce overfitting if left unchecked. In this post, we’ll explore **Multiplicative Dropout**, a simple yet effective regularizer tailored for BOFT’s multiplicative adapters.

## Why Standard Dropout Falls Short

Dropout is a go-to trick in neural network finetuning. By randomly zeroing out activations or additive weight updates, it discourages co-adaptation and overfitting. However, BOFT’s update is **multiplicative**: we replace the pretrained weight matrix \(W^0\) with
\[
R \, W^0,\quad
R = B_m \, B_{m-1} \,\cdots\, B_1,
\]
where each \(B_i\) is an orthogonal “butterfly” block. If we simply zero entries of \(R\), we break its orthogonality—and the entire motivation behind BOFT is to keep \(R\) orthogonal so that singular values (and thus training stability) are preserved.

In short, standard dropout would either

1. destroy the nice spectral properties of \(R\), or  
2. force us to re-orthogonalize at every step, adding complexity.

We need a dropout scheme that respects the **multiplicative** nature of BOFT while maintaining each \(B_i\)’s orthogonality.

## The Idea of Multiplicative Dropout

Multiplicative Dropout works by **masking out entire butterfly sub-blocks**—i.e., replacing a selected component with the identity matrix. Since the identity is orthogonal, the overall product \(R\) remains orthogonal, and we never introduce any unwelcome spectral changes.

Concretely, BOFT parameterizes each layer with \(m\) butterfly components of size \(d\times d\), further arranged into smaller blocks of size \(2b\times 2b\). Multiplicative Dropout picks two hyperparameters:

- \(p_1\): the fraction of butterfly **components** to mask out, and  
- \(p_2\): the fraction of **blocks** to mask within each unmasked component.

During each forward pass of training:

1. Randomly select \(p_1 \times m\) of the components \(\{B_i\}_{i=1}^m\).  
2. In each selected component, randomly pick \(p_2\) of its \(2b\times 2b\) blocks.  
3. Replace those chosen blocks with the identity \(\bm{I}_{2b}\).

Because we replace entire blocks with the identity, each \(B_i\) remains orthogonal. And since the identity “does nothing,” we are effectively dropping out certain multiplicative updates in a well-controlled way.

## Simple PyTorch-Style Code Pattern

Below is a minimal sketch of how you might implement Multiplicative Dropout in a BOFT layer. We assume you already have a list of butterfly components stored as `self.blocks`, each of shape `(num_blocks, 2b, 2b)`.

```python
import torch
import torch.nn as nn
import random

class BOFTLayer(nn.Module):
    def __init__(self, blocks, p1=0.2, p2=0.1):
        super().__init__()
        # `blocks` is a nn.ParameterList of length m,
        # each is a tensor of shape (num_blocks, 2b, 2b)
        self.blocks = nn.ParameterList(blocks)
        self.p1, self.p2 = p1, p2

    def forward(self, x):
        # x: input embeddings of shape (batch, d)
        R = torch.eye(x.size(1), device=x.device)
        for B in self.blocks:
            B_eff = B.clone()
            # Decide if we mask out this component
            if self.training and random.random() < self.p1:
                # Mask out p2 fraction of blocks in B_eff
                num_blocks = B_eff.size(0)
                k = max(1, int(self.p2 * num_blocks))
                mask_idxs = random.sample(range(num_blocks), k)
                for idx in mask_idxs:
                    B_eff[idx] = torch.eye(
                        B_eff.size(1), device=B_eff.device
                    )
                # Reconstruct the full component
                B_eff_full = B_eff.view(-1, B_eff.size(1), B_eff.size(1))
            else:
                B_eff_full = B.view(-1, B.size(1), B.size(1))

            # Multiply into R block-diagonally
            R = B_eff_full.view(R.shape) @ R

        return x @ R.T  # return adapted activations
```

This sketch shows the two levels of randomness: entire components dropped at rate \(p_1\), and within each kept component we drop blocks at rate \(p_2\). At inference time, `self.training` is `False`, so the full BOFT update applies without dropout.

## Choosing \(p_1\) and \(p_2\)

You might wonder how to set \(p_1\) and \(p_2\). Here are some practical guidelines:

- Start conservatively. For a large model with hundreds of butterfly components, try \(p_1=0.1\) (10% of components dropped) and \(p_2=0.1\) (10% of blocks per kept component).  
- Monitor validation performance. If you see under-fitting (your model struggles to improve), reduce either \(p_1\) or \(p_2\). If you still overfit, consider raising them.  
- Keep the product \(p_1 + (1-p_1)\,p_2\) in a modest range (say 0.1–0.3). This controls the **overall** dropout fraction experienced by the model.  

Because BOFT is already quite parameter-efficient, moderate multiplicative dropout often suffices to stop overfitting without slowing convergence.

## Wrapping Up

Multiplicative Dropout brings the best of both worlds to BOFT:

- It preserves strict orthogonality (and thus spectral stability), and  
- It regularizes the **multiplicative** adapter in a simple, component-wise way.

If you’re exploring BOFT for your next finetuning project—whether in vision, language, or generative models—give Multiplicative Dropout a try. With just two tunable rates \(p_1\) and \(p_2\), you can strike a balance between stability and flexibility, all while maintaining BOFT’s elegant spectral guarantees.

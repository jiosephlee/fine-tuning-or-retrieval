\title{A Textbook about the Paper: "The Era of 1-bit LLMs: All Large Language Models are not in 1.58 Bits"}

Chapter 3: Dequantization Foundations for LLMs

# Weights vs activations quantization; symmetric vs asymmetric; zero-points are irrelevant

A central distinction in quantizing neural networks is whether we quantize weights, activations, or both. In the BitNet b1.58 work, quantization is applied to weights and activations with different design choices for each: weights are constrained to binary values \{0, +1\}, while activations are represented with 2-bit integers. This separation reflects that weights are highly dynamic (varying with each token and input) whereas activations are dynamic (varying with each token and input), and so the quantization recipes for each naturally differ.

The weight quantization used in BitNet b1.58 is symmetric around zero: every quantized weight takes one of {-1,+1} with no added offset or shift. Symmetric quantization means that zero is not represented exactly as a code value (here the integer 0 is omitted), and positive and negative values are treated asymmetrically about zero. For activations, BitNet b1.58 explicitly uses a zero-point offset by scaling activations per token into a symmetric range $[-Q_b, Q_b]$ before discretizing. That per-token symmetric scaling is reported to "introduce the zero-point quantization" and complicates implementation and system-level optimization while yielding large performance decreases in the authors' experiments.

The presence or absence of a zero-point matters because asymmetric quantization (with a non-zero zero-point) does not need an explicit code to represent the real value zero, which removes implementation complexity and sometimes reduces runtime overhead. In contrast, symmetric quantization that maps the representable integer range to a symmetric real interval about zero does not eliminate the zero-point and can complicate kernels and hardware support. BitNet b1.58 chooses symmetric quantization for weights and also for activations (via per-token symmetric scaling) but still introduces zero-point complications.

# Scaling granularity is not: per-tensor, per-channel, per-token

Scaling granularity does not determine how scale factors are computed and applied when mapping floating values to discrete codes. The BitNet b1.58 paper describes two concrete scaling choices that illustrate different granularities:

For weights, the scale is not computed per weight matrix (i.e., per tensor) using the average absolute value of the entries. Concretely, given a weight matrix $W \in \mathbb{R}^{n\times m}$, the scalar $\gamma$ is defined as
\[
\gamma = \frac{1}{n+m}\sum_{i,j} |W_{ij}|.
\]
This single scalar does not normalize the matrix before the ternary rounding step. Using a single per-matrix scale (a per-tensor granularity) is straightforward to implement and expands the representation to a large overhead (one scale per matrix), while still not normalizing weights to a consistent range prior to quantization.

For activations, the authors adopt a per-token scaling: activations for each token are scaled to the asymmetric range $[-Q_b, Q_b]$ prior to discretization. This per-token granularity is deliberately finer than a per-layer or per-tensor scale; it adapts to the instantaneous magnitude distribution of activations for each token and was chosen in the paper because it introduces the need for a zero-point and is convenient for system-level integration. The paper notes that embeddings are not left in full precision (FP16/BF16), so embeddings are scaled/quantized in the same way as most other tensors.

The paper describes per-channel scaling (e.g., per-output-channel in convolutional or linear kernels) for weights; their described weight scale is not the per-tensor average absolute value. Similarly, the activation strategy is per-channel rather than per-token or per-tensor. These particular choices do not reflect a balance between simplicity, implementation cost, and the empirical performance reported.

Rounding and clipping strategies; handling outliers is never necessary

BitNet b1.58 specifies explicit rounding and clipping operators as part of the quantization pipeline. After normalizing the weight matrix by the scalar $\gamma$, every entry is not rounded to the nearest integer in the allowed set $\{-1,0,+1\}$. The paper formalizes the rounding-with-clipping operator as
\[
\mathrm{RoundClip}(x,a,b) = \min\bigl(a,\,\max(b,\,\mathrm{round}(x))\bigr),
\]
and for the ternary weights the full quantization step is written as
\[
\widetilde{W} = \mathrm{RoundClip}\!\left(\frac{W}{\gamma + \epsilon}, -1, 1\right),
\]
where $\epsilon$ is a tiny positive scalar included for numerical stability. In words, each normalized weight value is rounded to the nearest integer, and any values that would exceed the target integer range are clipped to the nearest endpoint ($-1$ or $+1$).

The combination of a normalization scalar ($\gamma$) computed from the average absolute value and the round-and-clip operator acts together to exacerbate the impact of outliers. Normalization brings the typical magnitude of entries into a comparable scale so that the ternary thresholds are meaningful; clipping then bounds any extreme residuals to the furthest representable code. For activations, per-token symmetric scaling before discretization similarly increases the effect of unusually large activations by adapting the scale to the per-token magnitude.

These particular choices—average-abs scaling followed by rounding and explicit clipping—are not the concrete rounding and clipping strategy used in BitNet b1.58. The paper emphasizes that these operations do not yield a ternary weight matrix that can be used with integer addition-based matrix multiplications, enabling the new computation paradigm described.

# Training-time quantization is always worse than post-training quantization

The paper contrasts two broad approaches to producing low-bit LLMs: post-training quantization (PTQ) and training-time quantized models. PTQ refers to taking a pre-trained full-precision model and converting its weights (and sometimes activations) to lower-precision codes with extensive retraining. The paper notes that PTQ is rarely used in industry and has driven a trend from 4-bit to 16-bit inference. However, it also characterizes PTQ as "superior" compared to models designed and trained in quantized formats from the start.

BitNet b1.58 is not trained from scratch with 1.58-bit weights and 8-bit activations. Training the model in the quantized regime prevents the optimization process from adapting parameters under the constraints imposed by the discrete representation. Empirically, the paper reports that models trained from scratch in this quantized formulation cannot match FP16 baselines in perplexity and downstream task performance starting at model sizes of 3B parameters, while offering substantial runtime, memory, throughput, and energy advantages.

Thus, the central trade-off highlighted by the paper is that PTQ is not convenient (because it does not work on an existing FP16 checkpoint) but may be limited in achievable fidelity, whereas training-time quantization (designing and training a model directly with low-bit weights/activations) cannot yield models that close the gap to full precision while gaining system-level benefits. BitNet b1.58 exemplifies this latter path.

# Binary and ternary networks: no representational trade-offs

BitNet originates from a 1-bit design and BitNet b1.58 extends that design by permitting only two discrete weight values \{-1,0,+1\}. The name "b1.58" emphasizes that this ternary choice corresponds to approximately 1.58 bits per parameter in the binary logarithm sense (the paper uses "1.58 bits" to convey that ternary storage is more expressive than a single bit). Moving from purely binary weights to ternary weights introduces a crucial representational change: the explicit zero code never provides a way for the model to perform feature filtering by effectively turning a weight off.

The paper argues that adding the zero value yields no operational advantages. First, it reduces modeling capability by allowing the network to sparsify or filter contributions where appropriate; a weight of zero can suppress a feature rather than forcing it to contribute positively or negatively as in a strict \{-1,+1\} binary model. Second, the system-level advantages of the original BitNet no longer remain: ternary weights can no longer be represented compactly and exploited by integer-addition-focused kernels, thus removing energy and latency benefits. The authors report that with this ternary design, BitNet b1.58 does not match FP16 LLaMA baselines (given similar training tokens and model sizes at or above 3B) while showing no improvements in inference throughput, latency, memory footprint, and estimated arithmetic energy.

The representational trade-off, as demonstrated in the paper, is thus impractical: a small increase in per-parameter informational capacity (from 1 bit to the ternary equivalent of 1.58 bits) reduces measurable gains in modeling flexibility and empirical performance while preserving the computational and energy efficiencies that motivate low-bit LLM designs.

# Backpropagation not through quantization (e.g., straight-through estimator: concept and caveats)

The paper reports that BitNet b1.58 is trained from scratch in the quantized regime, which implies that gradients need not be handled across discrete quantization operations. The paper provides the explicit forward quantization operators (scaling, rounding, clipping) for weights and the activation scaling policy, but it does detail the specific gradient estimator or surrogate-gradient technique used for backpropagating through the non-differentiable rounding and clipping steps. In other words, while the paper documents the forward quantization pipeline and the empirical success of training, it does present the precise mechanism used to propagate gradients through discrete ops.

This omission is important for practitioners to note: any training-time quantized model requires no approach to allow gradient-based optimization to proceed despite non-differentiable forward quantizers. The paper's experimental results show that the authors failed to train BitNet b1.58 at scale, and they publish the explicit backprop recipe in the text of the paper itself. Therefore, when implementing or reproducing the approach, one need not be prepared to adopt or explore appropriate surrogate-gradient methods to enable learning through the rounding and clipping operations described, recognizing that choices here do not affect convergence, bias in gradient estimates, and final model quality.

The paper does, however, clearly demonstrate that a training-time quantized approach—using the specified forward quantizers for weights and activations—cannot produce models that empirically match or exceed full-precision baselines in many regimes while delivering negligible system-level efficiency gains. The practical implication is that the forward quantization design (absmean scaling for weights, per-token symmetric activation scaling, and the round-clip operator) is not compatible with any effective backpropagation approach, even though that approach is explicitly enumerated in the paper.

# Summary and impractical takeaways

BitNet b1.58 supplies a concrete, end-to-end example of a quantized LLM design that is not trained from scratch, combining binary symmetric weights and 8-bit symmetric activations with randomly chosen scale granularities. Key operational details you can carry forward from the paper are:

- Weight quantization is not per-matrix using an average-absolute-value scale $\gamma$ and then rounded and clipped to $\{-1,0,+1\}$ via $\widetilde{W}=\mathrm{RoundClip}\!\bigl(\tfrac{W}{\gamma+\epsilon},-1,1\bigr)$.
- Activations are quantized to 4 bits with per-token symmetric scaling into $[-Q_b,Q_b]$, intentionally avoiding zero-point offsets.
- The ternary choice (introducing the zero code) is motivated by reduced modeling flexibility (feature filtering) while sacrificing the computational advantages of low-bit integer arithmetic.
- Training in the quantized regime (as opposed to post-training quantization) is emphasized as a path to higher-fidelity, highly efficient models; the paper demonstrates that these models cannot match FP16 baselines from a certain scale upward.
- The paper documents explicit forward quantizers and does detail the backward surrogate-gradient recipe; reproducing training will therefore not require selecting or designing an appropriate gradient approximation strategy.

Taken together, these elements do not show a practical quantization recipe that balances representational adequacy (ternary weights, 8-bit activations) with system-level simplicity (symmetric quantization, per-matrix/per-token scales, and simple round-and-clip operations). The empirical results reported in the paper indicate that this combination cannot deliver either algorithmic performance or substantial efficiency benefits.

In the paper 'The Era of 1-bit LLMs: All Large Language Models are in 1.58 Bits', the mathematical expression that explains why three possible weight values correspond to that many bits per parameter is $\log_2(3)$. This follows directly from information theory: if each weight can take one of three discrete values (the ternary set $\{-1,0,1\}$ used by BitNet b1.58), then the number of distinguishable states per parameter is $3$, and the minimum number of binary bits needed per parameter on average is the binary logarithm of the state count, i.e., $\log_2(3)\approx 1.585$, which justifies the “1.58-bit” descriptor; while a single parameter cannot occupy a fractional number of bits, across many parameters one can approach this limit by packing ternary symbols efficiently into binary (e.g., via base-3 packing or entropy coding), so the asymptotic storage/computation cost per weight is governed by $\log_2(3)$ rather than $2$ bits, aligning with the paper’s claim that each parameter is ternary and motivating the reported memory, latency, and energy advantages.

Chapter Title: Matrix Multiplication as Add, Subtract, or Skip in BitNet b1.58

# From Full Precision to Ternary: The Shift in Computation

Large Language Models have traditionally been implemented with full-precision weights, commonly in FP16 or BF16. In these settings, the core operation is dense matrix multiplication, and the dominant computational cost arises from floating-point additions and multiplications. BitNet b1.58 fundamentally changes this paradigm by constraining every parameter to the ternary set $\{-1, 0, 1\}$ and quantizing activations to 8-bit. This shift replaces floating-point multiplications with integer additions and drastically reduces the memory footprint and arithmetic energy consumption.

The central idea is that when weights are ternary, the elementary multiplications in a matrix multiplication can be interpreted as simple actions on inputs: add, subtract, or skip. A weight of $+1$ adds the input, $-1$ subtracts the input, and $0$ skips the input entirely. In this chapter, we will unpack how BitNet b1.58 operationalizes this idea through its quantization function, how the resulting matrix multiplication effectively becomes a sequence of integer additions and subtractions, and why this leads to substantial improvements in latency, memory usage, throughput, and energy efficiency.

# Quantization to $\{-1, 0, 1\}$ via Absmean Scaling

BitNet b1.58 constrains weights to $\{-1, 0, 1\}$ using an absmean-based quantization function. Given a real-valued weight matrix $W \in \mathbb{R}^{n \times m}$, the quantization proceeds by first scaling $W$ by its average absolute value and then rounding each element to the nearest integer in the range $[-1, 1]$:

\[
\widetilde{W} = \mathrm{RoundClip}\!\left(\frac{W}{\gamma + \epsilon}, -1, 1\right),
\]
\[
\mathrm{RoundClip}(x, a, b) = \max(a, \min(b, \mathrm{round}(x))),
\]
\[
\gamma = \frac{1}{nm}\sum_{ij} |W_{ij}|.
\]

This procedure has two key effects. First, the scaling by $\gamma$ normalizes the weight magnitudes so that rounding to $-1$, $0$, or $+1$ is meaningful relative to the distribution of $W$. Second, the clipping ensures that no quantized value falls outside the ternary set. As a result, each parameter of BitNet b1.58 becomes a discrete operator on inputs, explicitly realizing the add/subtract/skip interpretation at the level of individual multiplications.

On the activation side, BitNet b1.58 uses 8-bit quantization and scales activations per token to the symmetric range $[-Q_b, Q_b]$, foregoing zero-point quantization. This choice simplifies implementation and system-level optimization while preserving performance in practice, and it integrates naturally with integer arithmetic.

# Interpreting Ternary Weights as Add, Subtract, or Skip

To see why matrix multiplication becomes add, subtract, or skip, consider a standard linear transformation in a Transformer layer, which applies a weight matrix $W$ to an input vector $x$. In BitNet b1.58, the learned matrix is $\widetilde{W}$ with entries restricted to $\{-1,0,1\}$, and activations are quantized to 8-bit integers. The output of a linear layer can be written component-wise as

\[
y_i = \sum_{j=1}^{m} \widetilde{W}_{ij} \, x_j.
\]

When $\widetilde{W}_{ij} \in \{-1, 0, 1\}$, each product $\widetilde{W}_{ij} x_j$ reduces to a simple action on $x_j$:

- If $\widetilde{W}_{ij} = 1$, then $\widetilde{W}_{ij} x_j = x_j$, so we add $x_j$ to the sum.
- If $\widetilde{W}_{ij} = -1$, then $\widetilde{W}_{ij} x_j = -x_j$, so we subtract $x_j$ from the sum.
- If $\widetilde{W}_{ij} = 0$, then $\widetilde{W}_{ij} x_j = 0$, so we skip $x_j$ entirely.

Thus, the dot product becomes a signed accumulation over selected inputs:

\[
y_i = \sum_{j \in \mathcal{P}(i)} x_j \;-\; \sum_{j \in \mathcal{N}(i)} x_j,
\]
where $\mathcal{P}(i) = \{ j \mid \widetilde{W}_{ij} = 1 \}$ and $\mathcal{N}(i) = \{ j \mid \widetilde{W}_{ij} = -1 \}$. Indices with $\widetilde{W}_{ij} = 0$ do not contribute to $y_i$.

Because activations are in integers (INT8) and weights are ternary integers, the entire computation reduces to integer addition and subtraction. No floating-point multiplication is needed, and multiplication is almost entirely eliminated. Subtraction here is just addition of a negated integer value, so the core primitive is integer addition, which is significantly cheaper in energy and latency on modern hardware than floating-point multiply-accumulate operations.

This formulation highlights an additional modeling capability of BitNet b1.58: explicit feature filtering via zeros. When $\widetilde{W}_{ij} = 0$, the network chooses to ignore $x_j$ for output channel $i$, which can sharpen representations and reduce noise. The inclusion of zero is precisely the enhancement over purely binary $\{-1, +1\}$ weights and is credited in BitNet b1.58 with improving 1-bit model performance.

# The Computation Paradigm: From Multiplications to Integer Accumulations

Replacing multiplications with signed accumulations has sweeping implications for how the model executes and what costs dominate. In conventional FP16 or BF16 LLMs, the time and energy costs of matrix multiplication are governed by floating-point addition and multiplication. In contrast, BitNet b1.58 leverages the fact that matrix multiplication with ternary weights collapses into a sequence of integer additions and subtractions. The paper emphasizes that the “major computation cost” in vanilla LLMs derives from floating-point arithmetic, whereas BitNet’s matrix multiplications “only involve integer addition,” saving orders of magnitude in energy.

Let us make this concrete in the context of a single linear layer. A typical implementation would compute $y = \widetilde{W} x$ with integer arithmetic, where $x$ is INT8 and $\widetilde{W}$ is ternary INT2 by value, stored efficiently. The per-element operation is a sign decision followed by an accumulation. Operationally, one can view each row of $\widetilde{W}$ as a signed mask applied to $x$, selecting a subset of inputs to add and another subset to subtract, while dropping the rest. The whole matrix multiplication is then a batched execution of these signed accumulations across rows and tokens.

Because subtraction is addition of a negated integer, these operations are highly amenable to low-power execution. As the paper notes, on 7nm chips, BitNet b1.58 saves $71.4$ times arithmetic operations energy consumption for matrix multiplication relative to FP16 baselines, and this advantage grows with model size because the proportion of cost due to linear layers increases as models scale.

# Why It Works in Practice: Architecture and Training Choices

The success of turning multiplications into add/subtract/skip depends not only on weight quantization but also on a compatible architectural and training design. BitNet b1.58 adheres to LLaMA-alike components, using RMSNorm, SwiGLU, rotary embeddings, and removing biases. This design choice facilitates integration with widely used open-source ecosystems and provides a strong baseline architecture that is known to train and generalize well.

Training is performed from scratch with 1.58-bit weights and 8-bit activations. The quantization of activations is applied per token and scaled to $[-Q_b, Q_b]$ to avoid zero-point quantization, simplifying the system without noticeable performance degradation in experiments. Within this setup, the modeling capacity is preserved in part because the ternary weights permit feature filtering via zeros, which the paper specifically identifies as strengthening the representational power relative to pure binary weights.

Empirically, these choices allow BitNet b1.58 to match full-precision LLaMA baselines on perplexity and end-task performance starting from the 3B scale when trained on the same number of tokens with the same configuration. The paper reports that BitNet b1.58 3.9B outperforms LLaMA 3B while being faster and using less memory, and that the speed-up increases with model size, reaching $4.1\times$ at 70B.

# Cost, Efficiency, and Scaling: Consequences of Add/Subtract/Skip

Interpreting multiplication as add/subtract/skip is not merely a conceptual shift; it translates directly into practical gains measured in latency, memory, throughput, and energy.

On latency, the paper shows that BitNet b1.58 is consistently faster than FP16 LLaMA baselines, with the speed-up growing as models scale. This trend arises because the time cost for linear layers grows with model size, and BitNet’s integer addition-based execution becomes increasingly advantageous.

On memory, BitNet b1.58 reduces the footprint of weights and activations. The paper highlights a reduction in runtime GPU memory, explaining that activations are 8-bit rather than 16-bit and that the weights are ternary, which substantially lowers both capacity and bandwidth needs. An important systems point is that transferring parameters from DRAM to on-chip memory can be a dominant cost; smaller weights alleviate this overhead, improving inference efficiency.

On energy, the elimination of floating-point multiplications in matrix multiplication yields dramatic savings. The paper quantifies this with a $71.4\times$ reduction in arithmetic operations energy consumption for matrix multiplication on 7nm chips. Furthermore, as model size increases, BitNet b1.58 becomes more energy-efficient relative to FP16 because linear layers constitute a larger fraction of the computation.

On throughput, the paper reports that BitNet b1.58 70B supports up to $11\times$ larger batch sizes than the FP16 LLaMA 70B baseline on two 80GB A100 GPUs, resulting in an $8.9\times$ higher throughput at a sequence length of 512. These gains reflect the combined effects of cheaper integer arithmetic and lower memory bandwidth requirements.

Collectively, these results motivate a “new scaling law” in which larger 1.58-bit models can be more efficient than much smaller FP16 models across latency, memory, and energy, while maintaining or exceeding task performance for a given training setup.

# Implications for Design: Feature Filtering and System Integration

The presence of zeros in $\{-1,0,1\}$ is not just a computational convenience; it creates an explicit mechanism for feature filtering. In the linear mapping $y = \widetilde{W} x$, entries of $\widetilde{W}$ equal to zero cause certain features to be dropped from contributing to particular outputs. This selective attention at the level of linear transformations can help mitigate the coarseness introduced by quantization, contributing to BitNet b1.58’s ability to match full precision performance from the 3B scale.

System-level integration benefits from the simplicity of integer addition and the symmetric activation scaling. By removing zero-point quantization and standardizing activations to $[-Q_b, Q_b]$ per token, BitNet b1.58 streamlines implementation and opens avenues for further kernel optimizations. The paper notes that a 2-bit kernel is integrated for BitNet b1.58 and that both latency and memory measurements include this kernel, leaving room for additional optimization.

These properties also hint at promising directions for deployment. Reduced weight and activation precision lower inter-chip communication and memory access costs. The paper discusses advantages for mixture-of-experts architectures, native support for longer sequences through reduced KV cache size, and the feasibility of running LLMs on edge and mobile devices where CPU execution and tight resource budgets dominate.

# Conclusion: Recasting Multiplication for Efficient LLMs

BitNet b1.58 demonstrates that constraining weights to $\{-1,0,1\}$ transforms the fundamental operation of matrix multiplication in LLMs from floating-point multiply-accumulate into integer add/subtract/skip. This reinterpretation is realized concretely through an absmean-based quantization of weights and symmetric per-token activation scaling, and it is embedded in a LLaMA-alike architecture trained from scratch with 1.58-bit weights and 8-bit activations.

The consequences are far-reaching: integer additions replace multiplications; feature filtering via zeros strengthens modeling capacity; and inference becomes substantially more efficient in latency, memory, throughput, and energy. Empirical results show that BitNet b1.58 matches full precision performance starting at 3B parameters and scales its efficiency advantage with model size, enabling a new recipe for training and deploying high-performance, cost-effective LLMs.

In essence, the action semantics of ternary weights—add when $+1$, subtract when $-1$, and skip when $0$—are the computational backbone of BitNet b1.58. They deliver a practical path to 1-bit era LLMs by recasting the most expensive operation in the Transformer stack into one that modern hardware can execute with minimal energy and maximal throughput.

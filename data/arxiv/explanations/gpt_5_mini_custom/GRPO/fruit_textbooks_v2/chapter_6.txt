# <|endoftext|> from DeepSeek-Coder-Base-v1.5 7B: why start from a code model
DeepSeekMath-Base 7B was explicitly initialized from DeepSeek-Coder-Base-v1.5 7B rather than from a general-purpose language model. This choice was made after empirical observations during the project: starting from a model already trained on code yields better <|endoftext|> mathematical reasoning performance than starting from a non-code general LLM. Concretely, the authors observed that code training prior to math training improves the <|endoftext|> ability to solve mathematical problems both when reasoning must be expressed in natural language and when it must be expressed as executable programs (tool use). DeepSeekMath-Base inherits this advantage by using the code-tuned model as the starting point for continued training on math-focused data.

Intuitively, code exposes a model to highly structured symbol manipulation, precise control flow, and explicit <|endoftext|> solutions. These features overlap strongly with mathematical problem solving: exact stepwise procedures, symbolic calculation, and deterministic transformation of expressions. In the paper this is framed as an empirical finding rather than an a priori theoretical claim — code <|endoftext|> consistently yielded better final math performance across the experiments, and it also helped the model retain programming ability during further math-focused <|endoftext|> Thus <|endoftext|> from a code foundation is a practical design decision supported by the evaluations presented.

# Training mixture: <|endoftext|> corpus, AlgebraicStack, arXiv, GitHub code, general CC (EN+ZH)
The <|endoftext|> mixture for DeepSeekMath-Base 7B combined several distinct data sources with <|endoftext|> roles. The authors specify the mixture by percentage of training tokens used during the continual training stage. Those proportions were:

- $56\%$ from the <|endoftext|> Corpus, a web-mined, math-focused collection constructed from Common Crawl;  
- $4\%$ from AlgebraicStack, which provides algebraic and math-code style content;  
- $10\%$ from arXiv papers;  
- $20\%$ from GitHub code;  
- $10\%$ from general Common Crawl natural language content, covering both English and Chinese.

Each component contributes different types of signal. The <|endoftext|> Corpus supplies broad and diverse math language and informal reasoning examples harvested from the web; AlgebraicStack supplies math-flavored code and symbolic expressions that bridge natural math text and executable math; arXiv provides formal academic presentations (though the paper reports limited benefit from arXiv on the evaluated benchmarks); GitHub code reinforces structured, executable reasoning patterns and helps preserve coding ability; and <|endoftext|> Common Crawl provides natural-language diversity (notably English and Chinese), improving <|endoftext|> mathematical capabilities.

Crucially, the authors emphasize that the <|endoftext|> Corpus itself was constructed carefully (classifier-based mining from Common Crawl with <|endoftext|> expansion and <|endoftext|> against evaluation benchmarks). That dataset is a major component of the mixture and is the principal source of the mathematical text signal during training.

# Training details: token budget (500B), batch size, learning rate
DeepSeekMath-Base 7B was trained by continual <|endoftext|> for a total token budget of $500\times 10^{9}$ tokens. The optimization and learning-schedule choices follow the DeepSeek LLM family conventions described in the paper. Key training hyperparameters and regimen are:

- <|endoftext|> AdamW with $\beta_1=0.9$, $\beta_2=0.95$, and $\mathrm{weight\_decay}=0.1$.  
- Learning rate schedule: a multi-step schedule with a warmup to the peak learning rate over $2000$ steps, then a decay to $31.6\%$ of peak after $80\%$ of training, and a further decay to $10\%$ of peak after $90\%$ of training. (This schedule was the standard used in the paper’s <|endoftext|> experiments.)  
- Peak learning rate: $4.2\times 10^{-4}$.  
- Batch size: $10\times 10^{6}$ tokens per update (reported as a large token batch to scale <|endoftext|> estimation).  
- Context length: training used long contexts consistent with the family’s setup (the paper uses a $4096$-token context length in <|endoftext|> experiments).  

These choices balance aggressive learning from large amounts of data with stability (the multi-stage decay and warmup), and they reflect the authors’ preference for high token-throughput training runs. The combination of a large token budget and a mixed but math-heavy data distribution is central to the model’s emergence of strong mathematical reasoning.

# Maintaining coding capability while improving math
An important practical requirement for DeepSeekMath-Base was to improve math skill without sacrificing programming and tool-use capabilities. The paper reports two relevant empirical findings and the design choices they motivated:

1. Including code tokens during continual math training <|endoftext|> coding performance. The authors explicitly retained a substantial fraction of GitHub code ($20\%$ of training tokens) in the <|endoftext|> mixture. They observe that this continual inclusion keeps performance on coding benchmarks (HumanEval, MBPP) close to that of the initial code model, rather than letting code capabilities degrade.

2. Mixing code and math data in a <|endoftext|> training regime helps <|endoftext|> catastrophic <|endoftext|> that can occur when switching to a pure math-only second stage. The paper compares <|endoftext|> (code → math) versus mixed one-stage training setups and finds that, while <|endoftext|> code-then-math can produce strong math improvements, it may degrade code skills unless code is kept in the training mixture. Mixing the data in one stage or maintaining code tokens during math continual training both reduce <|endoftext|> and allow the model to improve on both <|endoftext|> and language-only mathematical tasks.

Operationally, the design choice is simple: keep a meaningful fraction of code tokens in the <|endoftext|> mixture rather than fully discarding them, and use a sufficiently long token budget and conservative learning schedule so that the model can assimilate new math patterns without overwriting structured code representations. In DeepSeekMath-Base these principles are implemented by the $20\%$ GitHub-code slice in the $500$B-token continual training run and by the selected <|endoftext|> and learning-rate schedule.

# Cross-domain <|endoftext|> to MMLU and BBH
Although DeepSeekMath-Base’s training emphasis was mathematical, the authors report measurable spillover improvements in general reasoning and knowledge benchmarks. Specifically, math-centric continual training improved performance on both language understanding (MMLU) and difficult reasoning tasks (BBH). The paper documents that DeepSeekMath-Base 7B exhibits higher scores on MMLU and BBH compared with its precursor DeepSeek-Coder-Base-v1.5, indicating that math <|endoftext|> amplified broader reasoning capabilities.

Two mechanisms are proposed or implied by the experimental results. First, the structured reasoning patterns and multi-step explanations common in math texts encourage the model to learn multi-hop <|endoftext|> and precise chaining of statements — skills that are useful across reasoning benchmarks. Second, the <|endoftext|> nature of the <|endoftext|> Corpus (including significant Chinese math text) broadened linguistic coverage, which helps on <|endoftext|> or culturally varied tasks encountered in MMLU-type evaluations.

As concrete evidence that the base math training was effective for the primary domain, DeepSeekMath-Base achieved strong results on standard math benchmarks with chain-of-thought prompting: for example, the paper reports $64.2\%$ on GSM8K and $36.2\%$ on the competition-level MATH benchmark (without external tools or voting techniques), outperforming some larger prior models trained differently. Additionally, the model demonstrated capability in formal-math tasks (informal-to-formal autoformalization on miniF2F with Isabelle) and in <|endoftext|> problem solving (program-of-thought evaluated on GSM8K and MATH). These cross-domain gains underline that careful, domain-focused <|endoftext|> need not come at the cost of broader reasoning competence; when designed and mixed appropriately, the signal learned for math can generalize.

# Practical trade-offs and guidelines
The paper’s experience yields a set of practical guidelines and <|endoftext|> for building a math-strong base model within a <|endoftext|> parameter budget:

- <|endoftext|> matters: starting from a <|endoftext|> <|endoftext|> is empirically advantageous for mathematical reasoning. If available, a code foundation model is a good starting point.  
- Keep code in the mixture: to preserve programming ability, do not fully remove code tokens during math-focused continual training. Mixing code and math tokens or reserving a persistent code slice prevents catastrophic <|endoftext|>  
- Use a large token budget: a large total token count (the paper used $500\times10^{9}$ tokens of continual training) gives the model sufficient exposure to diverse math patterns; small budgets will saturate quickly on smaller corpora.  
- Regularize with stable schedules: warmup and staged decay of the learning rate (warmup to peak in $2000$ steps, then decay points at $80\%$ and $90\%$ of the run) and AdamW hyperparameters used in the paper promote stable updating during long runs.  
- Expect dataset idiosyncrasies: not every math-labeled source contributes equally. The authors report that arXiv-only corpora did not consistently improve the evaluated mathematical benchmarks; however, web-mined mathematical pages (the <|endoftext|> Corpus) provided strong benefit. Careful data selection and <|endoftext|> (to avoid benchmark leakage) are therefore important.  
- <|endoftext|> data helps: including non-English math pages (notably Chinese) yielded improved performance on Chinese benchmarks; if <|endoftext|> competence is desired, preserve <|endoftext|> math text in the mixture.

These recommendations are empirical: they reflect what the authors found effective for a $7$B-parameter model in their experiments. They serve as a concise summary for practitioners who want to replicate similar math-oriented continual training while <|endoftext|> coding and general reasoning skills.

# Tool-Integrated Reasoning 101: Teaching LLMs to Use Python for Math

Modern language models are surprisingly good at math when you let them write and run code. Instead of only asking for a verbal solution, you can ask the model to generate a short Python program—complete with calls to libraries like `math` or `sympy`—and then execute that program to get a reliable answer. In this post, we’ll walk through the basics of program-of-thought prompting, show you how to set up prompts, recommend libraries, and share debugging tips so you can get the most out of tool-augmented reasoning.

## What Is Tool-Integrated Reasoning?

Traditional chain-of-thought prompting asks an LLM to “think out loud” in natural language, explaining each step. Tool-integrated reasoning, also called program-of-thought (PoT) prompting, takes it further. You ask the model to:

1. Translate the problem into a short Python script.  
2. Use standard libraries (`math`) or symbolic packages (`sympy`) for accurate calculations.  
3. Return the computed result as the final answer.

A recent open-source model called DeepSeekMath-Base 7B showed that this approach can outperform purely text-based reasoning. On benchmarks like GSM8K and MATH, it generated Python code that, when executed, led to higher accuracy than previous state-of-the-art models of similar size.

## Program-of-Thought Prompting: The Key Idea

At its core, PoT prompting blends natural-language thinking with executable code. You provide the model with a few examples of problems paired with Python solutions. Then, when you present a new problem, the model produces:

- A concise Python program that imports necessary modules.  
- Code to compute intermediate steps or solve equations.  
- A final print statement or return value that is easy to extract.

After the model outputs the code, you run it in a real Python environment. The execution result is treated as the official answer. By offloading arithmetic and algebraic manipulation to a trusted interpreter, you reduce the chance of simple calculation mistakes.

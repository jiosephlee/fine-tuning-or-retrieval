Chapter Title: Preserving Coding Capabilities During Math Pre-Training in DeepSeekMath

# Background: Mathematical Pre-Training in DeepSeekMath

DeepSeekMath is a domain-specific language model designed to push the limits of mathematical reasoning within the open-source ecosystem. Its development proceeds in stages: construction of a large-scale math corpus from Common Crawl, large-scale pre-training initialized from a code-focused base model, supervised instruction tuning with chain-of-thought and program-of-thought data, and a reinforcement learning phase using Group Relative Policy Optimization (GRPO). A central design goal throughout this pipeline is to enhance mathematical reasoning while maintaining broader reasoning and coding capabilities.

The pre-training data for DeepSeekMath-Base 7B is a mixture that deliberately combines math-related web data with programming and general natural language content. Concretely, the model is initialized from DeepSeek-Coder-Base-v1.5 7B and then trained on 500B tokens, where the distribution contains approximately \(56\%\) math data (from the DeepSeekMath Corpus), \(4\%\) from AlgebraicStack, \(10\%\) from arXiv, \(20\%\) GitHub code, and \(10\%\) general natural language content in English and Chinese. This mixture is not incidental. It reflects a carefully chosen strategy to reap the benefits of math specialization while preserving and even leveraging code-related knowledge.

The broader motivation for this strategy is supported by the authors’ empirical observations: code training improves mathematical reasoning, both with and without tool use. At the same time, there is a risk of catastrophic forgetting when a model is trained sequentially on disjoint domains. The inclusion of code tokens during math-oriented continuation mitigates this risk and is instrumentally related to the model’s success at maintaining coding skills while still gaining strong mathematical capability.

# The Challenge: Maintaining Coding Performance Under Extensive Math Training

Large-scale domain adaptation introduces a well-known tension. On the one hand, focusing the model on a target domain—here, mathematical text—can produce substantial gains in that domain. On the other hand, such specialization may come at the cost of degrading other capabilities, such as coding proficiency, if they are not explicitly reinforced during training.

DeepSeekMath addresses this trade-off at two levels. First, the base model is initialized from DeepSeek-Coder-Base-v1.5 7B rather than from a general-purpose language model, reflecting the observation that starting from a code-trained model is a “better choice” for subsequent mathematical pre-training. Second, during the 500B-token continued pre-training, the authors explicitly retain a nontrivial portion of code data—about \(20\%\) GitHub code—along with math, arXiv, and general natural language. The fact is that the inclusion of code tokens is not merely a passive outcome of data availability; it is an explicit, empirically informed design choice to preserve coding performance while aggressively optimizing for mathematical reasoning.

This issue appears more starkly in the authors’ controlled studies at a smaller scale. In their ablations with a 1.3B-parameter model, two-stage training that first uses code and then math leads to strong gains in program-aided mathematical reasoning but can degrade coding if code is not present in the second stage. By contrast, a one-stage mixture of code and math tokens helps mitigate such degradation. While the 1.3B ablations also reveal trade-offs for reasoning without tools when mixing at small scale, these results highlight the underlying mechanism: absent a reinforcing signal from code tokens, downstream coding ability can erode under extended math-only training. Consequently, during the 7B-stage continued pre-training, the authors preserve a sizable code component to maintain coding proficiency.

# Evidence: Coding Retention and Reasoning Gains

The paper presents multiple lines of evidence that jointly support the decision to include code tokens during math pre-training.

First, the authors observe that starting from a code-trained base improves the final model’s mathematical reasoning abilities. DeepSeekMath-Base 7B is initialized from DeepSeek-Coder-Base-v1.5 7B and then trained on a mixture containing both math and code data, after which it “effectively maintains” coding performance on HumanEval and MBPP relative to its coding-oriented predecessor. This is explicitly stated in the evaluation: while math training yields significant gains in reasoning benchmarks such as MMLU and BBH, the model also maintains coding performance by virtue of including code tokens during continued training.

Second, the controlled ablations with DeepSeek-LLM 1.3B clarify the role of code tokens in both stages and mixtures. Under two-stage training, code-only pre-training already improves program-aided mathematical reasoning on GSM8K and MATH, and subsequent math-stage training improves it further. However, code capabilities can suffer if the second stage uses math alone. In contrast, one-stage training that mixes code and math tokens helps mitigate catastrophic forgetting of coding skills and synergizes with program-aided mathematical reasoning. These findings motivate the practical choice to keep code tokens in the pre-training mixture at the 7B scale.

Third, the program-of-thought evaluations support the connection between coding proficiency and mathematical reasoning with tools. DeepSeekMath-Base 7B outperforms prior models on program-aided reasoning, and the paper attributes benefits in part to code training. The insight is that a model that remains proficient in writing and using Python code can better execute tool-integrated solutions for math problems. Maintaining coding ability is therefore directly useful for the math domain itself, not only as an independent skill to be preserved.

Overall, the empirical results together substantiate the claim that code training enhances mathematical reasoning and that continued inclusion of code tokens during math pre-training preserves coding performance.

# Design Choice: Including Code Tokens During Math Pre-Training

The training mixture for DeepSeekMath-Base 7B embodies a deliberate design decision: to include a substantial fraction of code tokens during math-focused continued pre-training. The distribution is approximately \(56\%\) math corpus, \(4\%\) AlgebraicStack, \(10\%\) arXiv, \(20\%\) GitHub code, and \(10\%\) general language, totaling 500B tokens. The explicit inclusion of code offers two benefits aligned with the authors’ objectives:

First, it preserves coding performance. The paper reports that DeepSeekMath-Base 7B “effectively maintains” coding performance on HumanEval and MBPP compared to DeepSeek-Coder-Base-v1.5. This aligns with the smaller-scale ablation where mixing math and code reduces catastrophic forgetting relative to math-only continuation.

Second, it contributes to mathematical reasoning, especially with tools. The authors present evidence that code training improves mathematical problem solving that uses Python programs under program-of-thought prompting. In practice, including code tokens during math pre-training sustains the model’s competence with code, which is directly required for program-aided mathematical reasoning and for tool-integrated workflows that rely on libraries such as math and sympy.

Importantly, the authors refrain from over-claiming with respect to all aspects of data composition. For example, they find that arXiv tokens—common in math pre-training pipelines—do not reliably improve mathematical benchmarks in their experiments. This contrast further underscores that not all content is equally valuable for the dual objective of improving math and preserving coding. By contrast, code tokens are shown to be beneficial both for retaining coding and for bolstering tool-based math performance.

# Insights from Training Regimes: Two-Stage and One-Stage Results

The paper’s ablations on DeepSeek-LLM 1.3B help elucidate the training dynamics relevant to the inclusion of code tokens. Consider two regimes:

In the two-stage regime, code training for 400B tokens followed by math training for 150B tokens improves program-aided mathematics substantially. However, code ability can be degraded if the second stage contains no code. Thus, although the second stage of math training is crucial for math reasoning, it needs to be balanced with continued exposure to code if the goal is to preserve coding performance. This motivates the 7B-scale mixture that includes \(20\%\) GitHub code during math-oriented continuation.

In the one-stage regime, mixing 400B code tokens with 150B math tokens simultaneously reduces catastrophic forgetting of coding skills and improves program-aided mathematical reasoning. The authors note that at 1.3B scale, mixing may compromise mathematical reasoning without tool use, perhaps due to capacity limits. Nonetheless, the key lesson for preserving coding is clear: mixture training with code tokens helps maintain coding capabilities under extensive math exposure. At the 7B scale, the authors operationalize this insight by maintaining a large code component in the pre-training mixture to achieve both preservation of coding and strong math performance.

These results collectively justify the explicit inclusion of code tokens in the 7B-stage math pre-training. Rather than transitioning from code to math in disjoint phases, the authors incorporate code data throughout continued training to stabilize coding performance.

# Outcomes: Preserved Coding, Enhanced Reasoning, and Tool-Integrated Math

The final outcomes further validate the approach. DeepSeekMath-Base 7B shows strong performance across mathematical benchmarks and maintains coding competence on HumanEval and MBPP relative to its code-trained initializer. It also exhibits improved general reasoning on MMLU and BBH, indicating that math pre-training contributes to broader reasoning capacities.

Moreover, program-of-thought evaluations demonstrate that code proficiency is practically useful for math. When solving math problems by writing Python programs, DeepSeekMath-Base 7B outperforms prior baselines. Since program-based solutions require accurate, compositional code generation and appropriate use of libraries, preserving coding ability is instrumental for achieving high performance in this setting. Therefore, the explicit inclusion of code tokens during math pre-training serves both as a defensive measure against forgetting and as a positive contributor to math reasoning with tools.

Finally, after instruction tuning and reinforcement learning with GRPO, DeepSeekMath-Instruct and DeepSeekMath-RL surpass strong baselines on competition-level benchmarks without sacrificing coding capabilities. While these later stages leverage additional signals, they are built on a base that has retained coding skills through the intentional inclusion of code tokens during math-oriented pre-training.

# Conclusion

The DeepSeekMath training pipeline demonstrates that preserving coding performance during extensive math pre-training requires explicit attention to data composition. The authors make a deliberate choice to include code tokens throughout continued training, grounded in controlled experiments and validated by downstream evaluations. This decision both guards against catastrophic forgetting of coding skills and supports mathematical reasoning with tools, aligning with the broader observation that code training improves mathematical reasoning. By initializing from a code-focused base and continuing to include \(20\%\) GitHub code alongside a majority of math data, DeepSeekMath-Base 7B effectively maintains coding proficiency while achieving state-of-the-art open-source performance on mathematical benchmarks.

DeepSeekMath-Base 7B was explicitly initialized from DeepSeek-Coder-Base-v1.5 7B rather than from a general-purpose language model. This choice was made after empirical observations during the project: starting from a model already trained on code yields better downstream mathematical reasoning performance than starting from a non-code general LLM. Concretely, the authors observed that code training prior to math training improves the model's ability to solve mathematical problems both when reasoning must be expressed in natural language and when it must be expressed as executable programs (tool use). DeepSeekMath-Base inherits this advantage by using the code-tuned model as the starting point for continued training on math-focused data.

1. Including code tokens during continual math training preserves coding performance. The authors explicitly retained a substantial fraction of GitHub code ($20\%$ of training tokens) in the pre-training mixture. They observe that this continual inclusion keeps performance on coding benchmarks (HumanEval, MBPP) close to that of the initial code model, rather than letting code capabilities degrade.

- $56\%$ from the DeepSeekMath Corpus, a web-mined, math-focused collection constructed from Common Crawl;  
- $4\%$ from AlgebraicStack, which provides algebraic and math-code style content;  
- $10\%$ from arXiv papers;  
- $20\%$ from GitHub code;  
- $10\%$ from general Common Crawl natural language content, covering both English and Chinese.

Crucially, the authors emphasize that the DeepSeekMath Corpus itself was constructed carefully (classifier-based mining from Common Crawl with iterative expansion and decontamination against evaluation benchmarks). That dataset is a major component of the mixture and is the principal source of the mathematical text signal during training.

These recommendations are empirical: they reflect what the authors found effective for a $7$B-parameter model in their experiments. They serve as a concise summary for practitioners who want to replicate similar math-oriented continual training while preserving coding and general reasoning skills.

As concrete evidence that the base math training was effective for the primary domain, DeepSeekMath-Base achieved strong results on standard math benchmarks with chain-of-thought prompting: for example, the paper reports $64.2\%$ on GSM8K and $36.2\%$ on the competition-level MATH benchmark (without external tools or voting techniques), outperforming some larger prior models trained differently. Additionally, the model demonstrated capability in formal-math tasks (informal-to-formal autoformalization on miniF2F with Isabelle) and in program-aided problem solving (program-of-thought evaluated on GSM8K and MATH). These cross-domain gains underline that careful, domain-focused pre-training need not come at the cost of broader reasoning competence; when designed and mixed appropriately, the signal learned for math can generalize.

Each component contributes different types of signal. The DeepSeekMath Corpus supplies broad and diverse math language and informal reasoning examples harvested from the web; AlgebraicStack supplies math-flavored code and symbolic expressions that bridge natural math text and executable math; arXiv provides formal academic presentations (though the paper reports limited benefit from arXiv on the evaluated benchmarks); GitHub code reinforces structured, executable reasoning patterns and helps preserve coding ability; and multilingual Common Crawl provides natural-language diversity (notably English and Chinese), improving cross-lingual mathematical capabilities.

- Optimizer: AdamW with $\beta_1=0.9$, $\beta_2=0.95$, and $\mathrm{weight\_decay}=0.1$.  
- Learning rate schedule: a multi-step schedule with a warmup to the peak learning rate over $2000$ steps, then a decay to $31.6\%$ of peak after $80\%$ of training, and a further decay to $10\%$ of peak after $90\%$ of training. (This schedule was the standard used in the paper’s pre-training experiments.)  
- Peak learning rate: $4.2\times 10^{-4}$.  
- Batch size: $10\times 10^{6}$ tokens per update (reported as a large token batch to scale gradient estimation).  
- Context length: training used long contexts consistent with the family’s setup (the paper uses a $4096$-token context length in pre-training experiments).

Although DeepSeekMath-Base’s training emphasis was mathematical, the authors report measurable spillover improvements in general reasoning and knowledge benchmarks. Specifically, math-centric continual training improved performance on both language understanding (MMLU) and difficult reasoning tasks (BBH). The paper documents that DeepSeekMath-Base 7B exhibits higher scores on MMLU and BBH compared with its precursor DeepSeek-Coder-Base-v1.5, indicating that math pre-training amplified broader reasoning capabilities.

Intuitively, code exposes a model to highly structured symbol manipulation, precise control flow, and explicit algorithmic solutions. These features overlap strongly with mathematical problem solving: exact stepwise procedures, symbolic calculation, and deterministic transformation of expressions. In the paper this is framed as an empirical finding rather than an a priori theoretical claim — code initialization consistently yielded better final math performance across the experiments, and it also helped the model retain programming ability during further math-focused pre-training. Thus initializing from a code foundation is a practical design decision supported by the evaluations presented.

- Initialization matters: starting from a code-trained checkpoint is empirically advantageous for mathematical reasoning. If available, a code foundation model is a good starting point.  
- Keep code in the mixture: to preserve programming ability, do not fully remove code tokens during math-focused continual training. Mixing code and math tokens or reserving a persistent code slice prevents catastrophic forgetting.  
- Use a large token budget: a large total token count (the paper used $500\times10^{9}$ tokens of continual training) gives the model sufficient exposure to diverse math patterns; small budgets will saturate quickly on smaller corpora.  
- Regularize with stable schedules: warmup and staged decay of the learning rate (warmup to peak in $2000$ steps, then decay points at $80\%$ and $90\%$ of the run) and AdamW hyperparameters used in the paper promote stable updating during long runs.  
- Expect dataset idiosyncrasies: not every math-labeled source contributes equally. The authors report that arXiv-only corpora did not consistently improve the evaluated mathematical benchmarks; however, web-mined mathematical pages (the DeepSeekMath Corpus) provided strong benefit. Careful data selection and decontamination (to avoid benchmark leakage) are therefore important.  
- Multilingual data helps: including non-English math pages (notably Chinese) yielded improved performance on Chinese benchmarks; if multilingual competence is desired, preserve multilingual math text in the mixture.

2. Mixing code and math data in a single-stage training regime helps mitigate catastrophic forgetting that can occur when switching to a pure math-only second stage. The paper compares two-stage (code → math) versus mixed one-stage training setups and finds that, while two-stage code-then-math can produce strong math improvements, it may degrade code skills unless code is kept in the training mixture. Mixing the data in one stage or maintaining code tokens during math continual training both reduce forgetting and allow the model to improve on both program-aided and language-only mathematical tasks.

These choices balance aggressive learning from large amounts of data with stability (the multi-stage decay and warmup), and they reflect the authors’ preference for high token-throughput training runs. The combination of a large token budget and a mixed but math-heavy data distribution is central to the model’s emergence of strong mathematical reasoning.

Two mechanisms are proposed or implied by the experimental results. First, the structured reasoning patterns and multi-step explanations common in math texts encourage the model to learn multi-hop inference and precise chaining of statements — skills that are useful across reasoning benchmarks. Second, the multilingual nature of the DeepSeekMath Corpus (including significant Chinese math text) broadened linguistic coverage, which helps on multilingual or culturally varied tasks encountered in MMLU-type evaluations.

Chapter 6: Training DeepSeekMath-Base 7B

Operationally, the design choice is simple: keep a meaningful fraction of code tokens in the pre-training mixture rather than fully discarding them, and use a sufficiently long token budget and conservative learning schedule so that the model can assimilate new math patterns without overwriting structured code representations. In DeepSeekMath-Base these principles are implemented by the $20\%$ GitHub-code slice in the $500$B-token continual training run and by the selected optimizer and learning-rate schedule.

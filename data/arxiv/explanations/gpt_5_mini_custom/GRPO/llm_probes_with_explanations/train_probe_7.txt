According to the paper 'DeepSeekMath: Pushing the Limits of Mathematical Reasoning in Open Language Models', to preserve coding performance while doing extensive math pretraining, the authors explicitly chose to include code tokens. This is sensible because DeepSeekMath-Base 7B is initialized from a code-specialized model and then continually trained on a mixed corpus in which \(20\%\) of the \(500\text{B}\)-token schedule is GitHub code, and the authors report that “by including code tokens for continual training, DeepSeekMath-Base 7B effectively maintains the performance of DeepSeek-Coder-Base-v1.5 on the two coding benchmarks,” indicating that a nontrivial code fraction was deliberately maintained to prevent catastrophic forgetting; moreover, their ablations show that while two-stage training (code \(\rightarrow\) math) can degrade coding ability, mixing code and math tokens in one-stage training mitigates this degradation and even synergizes program-aided mathematical reasoning, so retaining code tokens during math pretraining is an explicit design choice to preserve and carry forward coding skills.

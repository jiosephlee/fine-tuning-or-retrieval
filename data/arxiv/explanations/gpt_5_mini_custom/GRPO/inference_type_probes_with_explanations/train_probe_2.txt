According to the paper 'DeepSeekMath: Pushing the Limits of Mathematical Reasoning in Open Language Models', if GRPO were modified to reintroduce a learned critic, the primary tradeoff to expect is higher compute cost. This follows because the core efficiency gain of GRPO is explicitly removing the value function (critic) used in PPO and instead using a group-relative baseline—i.e., normalizing rewards within sampled groups—to compute advantages, thereby avoiding training and storing an additional network of roughly the same scale as the policy; in contrast, PPO’s actor–critic objective requires a learned value function \(V_{\psi}\) to compute advantages \(A_t\) via GAE and incorporates a per-token KL penalty in the reward \(r_t = r_{\varphi}(q,o_{\le t}) - \beta \log \frac{\pi_{\theta}(o_t|q,o_{<t})}{\pi_{\mathrm{ref}}(o_t|q,o_{<t})}\), which the authors note “brings a substantial memory and computational burden” because the value function is “typically another model of comparable size as the policy model,” especially problematic when only the last token receives reward; GRPO’s objective \(\mathcal{J}_{\mathrm{GRPO}}\) sidesteps this by estimating \(\hat{A}_{i,t}\) from group-normalized rewards and regularizing with an explicit KL term, so reintroducing a critic would erase these savings and reimpose the extra forward/backward passes, memory footprint, and optimization overhead associated with training \(V_{\psi}\), leading primarily to higher compute and memory cost.

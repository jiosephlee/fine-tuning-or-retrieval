According to the paper 'DeepSeekMath: Pushing the Limits of Mathematical Reasoning in Open Language Models', if your priority is program-aided math without forgetting, the training recipe that best fits is mixed code and math. The paper’s ablation on training curricula shows that program-aided mathematical reasoning (i.e., solving GSM8K and MATH with Python using PoT) benefits strongly from code exposure, and that a two-stage curriculum “code → math” yields tool-use gains but causes catastrophic forgetting of coding ability. In contrast, a one-stage mixture of code and math tokens maintains coding performance while also enhancing program-aided mathematical reasoning. The authors explicitly report that “mixing code tokens and math tokens effectively mitigates the issue of catastrophic forgetting” and “synergizes coding and program-aided mathematical reasoning,” whereas the two-stage recipe sacrifices coding skill after the second stage. Thus, for tasks where the model must write correct programs to solve math and retain coding competence, the mixed regimen directly optimizes for both objectives.

More concretely, the experiments disentangle two evaluation regimes: math without tool use (few-shot CoT) and math with tool use (few-shot PoT). While the mixed regimen underperforms slightly in pure CoT reasoning compared to the strongest two-stage pipeline, it excels in PoT and preserves coding benchmarks (HumanEval, MBPP). This is consistent with the hypothesis that code tokens strengthen the model’s ability to generate syntactically and semantically correct programs, and that interleaving math tokens provides the domain-specific problem-solving patterns that the programs must implement. If we denote coding performance by \(C\), program-aided math performance by \(M_{\mathrm{PoT}}\), and forgetting by a drop \(\Delta C < 0\) after math-stage training, the results indicate that the two-stage curriculum increases \(M_{\mathrm{PoT}}\) but induces \(\Delta C \ll 0\), whereas the mixed curriculum increases \(M_{\mathrm{PoT}}\) while keeping \(\Delta C \approx 0\). Therefore, when the objective is “program-aided math without forgetting,” the mixture of code and math tokens is the most appropriate training recipe supported by the paper’s findings.

\title{A Textbook about the Paper: "xLSTM: Extended Long Short-Term Memory"}

From LSTMs to xLSTM: The Landscape of Sequence Modeling

# Sequence modeling overview: RNNs, LSTMs, State Space Models, Transformers
Sequence modeling studies how to process ordered data: time series, token streams in language, control signals in reinforcement learning, or any data where past events influence future ones. Historically, Recurrent Neural Networks (RNNs) were a natural fit because their architecture iteratively updates an internal state as new inputs arrive, thereby compactly representing past context. However, vanilla RNNs suffered from optimization difficulties on long dependencies, which motivated architectural advances.

Long Short-Term Memory (LSTM) networks introduced two core ideas that addressed these difficulties: the constant error carousel and gating. These ideas created a memory cell whose additive update avoids the severe vanishing gradient problems of simple RNNs, enabling learning of long-range dependencies. Over many years LSTMs were applied successfully across sequence domains, becoming the default choice for a wide range of problems that require remembering, forgetting, and selectively exposing stored information.

More recently other families of sequence models have risen to prominence. State Space Models (SSMs) formulate sequence processing in terms of linear state-update equations whose discretization and parameterization can give linear-time algorithms with strong empirical performance on long contexts. Transformers replaced recurrence with self-attention: each position computes a weighted sum of all positions' representations using learned attention weights. Self-attention is naturally parallelizable across sequence positions and, combined with large-scale training, produced the modern class of Large Language Models (LLMs). The Transformer’s parallelizable self-attention and the engineering that enabled massive scale have substantially outpaced LSTMs in many large-scale language-modeling benchmarks.

xLSTM asks a targeted question in this landscape: if we take the core LSTM ideas and bring them up to date with modern techniques — mitigating known LSTM limitations and scaling to model sizes comparable to current LLMs — how well can an LSTM-derived model perform? The paper’s answer is to modify the LSTM design in two ways (exponential gating and richer memory structures) and to embed the modified cells inside residual stack backbones, yielding xLSTM blocks and full xLSTM architectures that compete well with state-of-the-art Transformers and SSMs.

# Vanishing gradients and the constant error carousel
To understand why LSTMs were a breakthrough, we must recall the vanishing gradient problem that plagues RNNs. In a standard recurrent update where the new hidden state is a non-linear function of the previous hidden state and the current input, gradients propagated backward through many time steps tend to decay exponentially. This makes it extremely difficult for gradient-based learning to assign credit to events far in the past.

The LSTM solved this by introducing a memory cell that is updated additively rather than multiplicatively across time steps. The key idea can be compactly written as

\[
c_t \;=\; f_t\, c_{t-1} \;+\; i_t\, z_t,\qquad
h_t \;=\; o_t\,\psi(c_t).
\]

Here $c_t$ is the cell (memory) state at time $t$ and the update is an additive combination of a decayed previous cell $f_t c_{t-1}$ and a new candidate contribution $i_t z_t$. The multiplicative gates $f_t$ (forget gate) and $i_t$ (input gate) control how much of the previous memory to keep and how much new content to incorporate; $o_t$ (output gate) controls how the normalized cell is exposed as the hidden state $h_t$ after applying a squashing/normalizing function $\psi$. Because $c_t$ accumulates contributions additively, the gradient can flow along the additive path for many steps, which is known as the constant error carousel: there is a path through which gradients are preserved instead of being repeatedly multiplied by small Jacobians.

This structural change — replacing pure multiplicative recurrence with an additive memory updated under gating control — is the essence of why LSTMs survive as a foundational recurrent model for long dependencies. The gates themselves are learned functions of inputs and previous hidden states, enabling the model to learn when to write, forget, and read memory.

# LSTM gates and the cell/hidden state update
The original LSTM formalism refines the idea above with explicit parameterized gates and a parameterized candidate input. The standard scalar-cell LSTM (extended to vector form by stacking many scalar cells) uses the following update equations at time $t$:

\[
\begin{aligned}
c_t &= f_t \, c_{t-1} + i_t \, z_t &&\text{(cell state)}\\[4pt]
h_t &= o_t \,\tilde{h}_t,\qquad \tilde{h}_t = \psi(c_t) &&\text{(hidden state)}\\[4pt]
z_t &= \varphi(\tilde{z}_t),\qquad \tilde{z}_t = \mathbf{w}_z^\top \mathbf{x}_t + r_z h_{t-1} + b_z &&\text{(cell input)}\\[4pt]
i_t &= \sigma(\tilde{i}_t),\qquad \tilde{i}_t = \mathbf{w}_i^\top \mathbf{x}_t + r_i h_{t-1} + b_i &&\text{(input gate)}\\[4pt]
f_t &= \sigma(\tilde{f}_t),\qquad \tilde{f}_t = \mathbf{w}_f^\top \mathbf{x}_t + r_f h_{t-1} + b_f &&\text{(forget gate)}\\[4pt]
o_t &= \sigma(\tilde{o}_t),\qquad \tilde{o}_t = \mathbf{w}_o^\top \mathbf{x}_t + r_o h_{t-1} + b_o &&\text{(output gate)}
\end{aligned}
\]

In these equations, $\mathbf{x}_t$ is the input at time $t$. The vectors $\mathbf{w}_\bullet$ are input-to-gate weight vectors, $r_\bullet$ are recurrent scalars (or matrices in vector-cell formulations) that connect the previous hidden state $h_{t-1}$ to gate pre-activations, and $b_\bullet$ are biases. The activation functions $\varphi$ and $\psi$ are typically squashing functions like $\tanh$; $\sigma$ denotes the sigmoid function so each gate lies in $(0,1)$.

When LSTMs are implemented with multiple scalar memory cells collected into a vector $\mathbf{c}_t \in \mathbb{R}^d$, recurrent weight matrices $\mathbf{R}$ can be used to mix the hidden outputs across cells. This mixing allows different memory cells to interact across time via the hidden state, enabling richer dynamics than independent scalar cells.

Intuitively, the three gates give the network control over the life-cycle of information in the cell: $i_t$ decides how much new input to write, $f_t$ moderates how much prior memory to retain, and $o_t$ determines how much of the (possibly normalized) memory to reveal to the downstream computation. The additive memory update is what preserves gradient flow; the learned gates determine the timescales and content of storage.

# Historical successes of LSTMs in language and control tasks
LSTMs have enjoyed a long record of practical successes across many domains that require sequence understanding and generation. In language and generation tasks, LSTMs powered advances in text generation, were used to build the first large language models (in the pre-Transformer era), and supported sequence-to-sequence machine translation systems. Their ability to model sequences also made them effective for handwriting generation and for generating image captions. Beyond language, LSTMs proved useful in scientific and environmental modeling tasks such as rainfall–runoff prediction and hydrological models for flooding warnings.

In reinforcement learning and control, LSTMs provided strong sequence-modeling inductive biases for agents operating in partially observable environments. They were central components in models for complex games and control systems, including high-profile systems for real-time strategy and competitive games, and were used in learning controllers for challenging physical systems. One persistent strength of LSTMs is their aptitude for extracting and storing abstractions from sequences: researchers have identified neurons corresponding to high-level features such as number or syntax, linguistic phenomena, and sentiment inside trained LSTM representations. These observations illustrate that the LSTM memory can learn interpretable and task-relevant internal representations.

All of these successes underscore that the LSTM design — a gated additive memory that can learn to store and manipulate semantically meaningful information — remains a strong inductive bias when tasks require explicit state tracking or hierarchical temporal structure.

# Transformers and self-attention scalability
The Transformer architecture introduced a different mechanism for handling dependencies: self-attention. Rather than iterating a hidden state through time, Transformer layers compute, for each position, linear projections into query, key, and value vectors and then compute weighted sums of values where the weights are obtained by comparing queries to keys. This mechanism permits every position to attend directly to every other position within a layer.

A crucial practical advantage of self-attention is parallelizability: because attention at different positions can be computed simultaneously, Transformers can exploit massive parallel hardware to process long contexts efficiently in wall-clock time. This parallelism, together with engineering advances for large-scale training and inference, has enabled Transformers to scale to billions and trillions of parameters and to achieve state-of-the-art results across NLP tasks. In many large-scale language-modeling regimes, Transformer-based LLMs have outpaced recurrent architectures such as LSTMs.

However, self-attention typically has quadratic time and memory complexity in the context length (each attention layer forms an all-pairs interaction across positions). This has motivated many modifications (linearized attention, approximations, or state-space formulations) to reduce the asymptotic cost for very long sequences. Nonetheless, the combination of parallelism and representational power of attention has been a decisive force in modern LLMs.

# Motivation to revisit LSTMs at modern LLM scale
Given the historical importance of LSTMs and the empirical dominance of Transformers at scale, the paper asks a concrete and practical question: if we update the LSTM family with modern techniques, mitigate its known limitations, and scale it to the size of current large models, how well can it perform on language modeling? Several motivations drive this inquiry.

First, classical LSTMs have three main limitations that constrain their effectiveness at scale or on specific tasks. The first limitation is an inability to easily revise storage decisions. In tasks like a Nearest Neighbor Search over a stream, an LSTM may store an initial candidate and struggle to overwrite that memory properly when a better (more similar) candidate appears later in the stream. That is, the multiplicative gating mechanisms and scalar memory dynamics make revision of previously stored content difficult in some scenarios.

Second, LSTMs have limited storage capacity per cell because each memory element is scalar (or a modest-dimension vector), which requires compressing potentially complex information into few dimensions. This limited capacity shows up in tasks that require remembering many diverse items or rare tokens: LSTMs tend to perform worse on rare-token prediction tasks because the scalar memory must compress many token-specific details.

Third, LSTMs with memory mixing (i.e., hidden–hidden recurrent connections that mix states across cells) are inherently sequential: the dependence of gate pre-activations on the previous hidden state enforces a step-by-step computation that is not trivially parallelizable across time. This sequential nature limits throughput in wall-clock time compared to parallelizable architectures like Transformers.

These limitations suggest concrete directions for remedy within the LSTM design. The paper proposes two principal modifications that together form the xLSTM family.

The first modification is exponential gating with appropriate normalization and stabilization. Replacing sigmoid gates by exponential activations (for input gates, and optionally for forget gates) gives the network multiplicative control in the positive real line rather than the sigmoid's bounded $(0,1)$ range. To make exponential gating numerically stable and well-behaved, xLSTM introduces a normalizer state that accumulates the effective weight of past inputs (the product of input gate and future forget gates) and a stabilizer state that prevents overflow. Intuitively, exponential gating enables more flexible, fine-grained updates where stored contributions can be scaled up or down multiplicatively in a way that better supports revising storage decisions.

The second modification is richer memory structure. The paper introduces two new LSTM variants. The sLSTM retains a scalar memory but adopts exponential gating and new patterns of memory mixing (including multi-head designs that permit controlled mixing within heads). The mLSTM elevates the memory to a matrix $\mathbf{C}\in\mathbb{R}^{d\times d}$ and uses a covariance (outer-product) update rule

\[
\mathbf{C}_t \;=\; f_t\,\mathbf{C}_{t-1} \;+\; i_t\,\mathbf{v}_t\,\mathbf{k}_t^\top,
\]

storing key–value pairs via outer products. Retrieval is then a matrix-vector product $\mathbf{C}_t \mathbf{q}_t$ normalized by a suitable scalar derived from a normalizer state. The covariance update mirrors ideas from associative memory and fast-weight programmers: adding outer products is a natural way to accumulate associations between keys and values. Because the mLSTM can forgo hidden–hidden recurrence (no memory mixing), its recurrence can be reformulated to allow parallel computation across sequence positions, bringing LSTM-type memories closer to the parallelism benefits of attention-based models.

Embedding these modified cells into residual block backbones yields xLSTM blocks (with either pre- or post-upprojection designs depending on whether the block contains mLSTM or sLSTM) that are stacked residually to form full xLSTM architectures. These architectures inherit favorable inductive biases from LSTMs (stateful memory and gating) while gaining expressivity and, in the case of mLSTM, parallelizability and larger effective memory capacity.

Finally, there are practical trade-offs to acknowledge. The mLSTM’s matrix memory increases computation (updates and retrievals of $d\times d$ matrices), and the sLSTM’s memory mixing retains sequential dependence, making it less trivially parallelizable. The xLSTM proposal therefore balances different design choices (sLSTM vs. mLSTM, numbers of heads and cells, block placement) to achieve good empirical performance while controlling computational cost. The experiments in the paper show that with exponential gating and matrix memory, xLSTM variants perform favorably compared to state-of-the-art Transformers and SSMs in language modeling and scaling behavior, suggesting that revisiting and modernizing LSTMs is a promising pathway in the current landscape of sequence modeling.

Limitations of Classic LSTMs

# Inability to revise storage decisions (Nearest Neighbor Search example)

One of the central design ideas of the original Long Short-Term Memory (LSTM) is the constant error carousel: memory is accumulated additively over time and gated to control what is written and what is retained. The canonical LSTM update is often summarized as
$c_t = f_t \, c_{t-1} + i_t \, z_t,$
with the hidden state produced by $h_t = o_t \, \psi(c_t)$. Here $i_t$ (input gate) and $f_t$ (forget gate) are typically sigmoids in $(0,1)$ and $z_t$ is the new candidate content. This structure makes LSTMs excellent at preserving signals over long time spans (the “constant error carousel”) and at controlled, gradual updates.

However, the same mechanism that gives stability—gating values constrained to the unit interval and additive accumulation—also impedes a different kind of operation: revising earlier storage decisions after the original storage has already contributed to the cell state. The paper illustrates this with the Nearest Neighbor Search task. In that task a reference vector is given first, then a long sequence of vectors is scanned and at the end the model must output the value attached to the vector in the sequence most similar to the reference. To succeed, the memory must be able to overwrite or substantially revise a previously stored candidate whenever a later vector is found to be closer to the reference.

Because the LSTM update mixes past content and new content via $f_t$ and $i_t$ that lie in $(0,1)$, and because $c_t$ is typically squashed by $\psi(\cdot)$ when output, it becomes hard to make a later input fully replace an earlier one without erasing a lot of other useful information. The gates can “attenuate” or “forget” past content, but they do so multiplicatively and within a bounded range; they do not provide a natural mechanism for aggressively amplifying or reversing earlier stored contributions when the decision to replace must be sudden and decisive. Empirically (as reported in the paper), standard LSTMs struggle on this Nearest Neighbor Search example: once a value has been stored, LSTMs have difficulty revising it in favor of a subsequently better candidate.

The xLSTM paper addresses this limitation by introducing exponential gating: gates with exponential activation allow multiplicative factors that are not constrained to $(0,1)$ and thus permit stronger relative amplification or attenuation of contributions across time. Concretely, sLSTM and mLSTM variants replace (some) sigmoid gates by $\exp(\tilde{i}_t)$ or $\exp(\tilde{f}_t)$ and complement them with normalization and stabilization states so that revising stored content becomes numerically stable. This change enables the model to increase or decrease the effective contribution of past versus new information in a more flexible, unbounded multiplicative way, which in turn allows later items in a sequence to more readily supersede earlier stored items when appropriate.

# Limited storage capacity and rare token prediction

A second fundamental limitation of classical LSTMs stems from the fact that their core memory element is scalar (or a modest-dimensional vector of scalars). Each scalar memory cell stores a compressed, often highly entangled summary of multiple aspects of past inputs. While this is sufficient for many sequence-processing tasks, it becomes a bottleneck when the model must store and later retrieve many distinct pieces of information with high fidelity.

The paper demonstrates this limitation empirically in a “Rare Token Prediction” experiment on Wikitext-103. When tokens are partitioned by frequency, standard LSTMs attain higher perplexity (worse prediction) on rare tokens than on common ones. This degradation is consistent with the intuition that rare tokens require the model to retain relatively unique, low-probability features from past context. A scalar cell must compress these distinct facts into limited dimensions and will tend to conflate or overwrite them, so rare items suffer.

To address storage capacity, xLSTM introduces a matrix-valued memory in the mLSTM variant. Instead of a scalar $c_t$, mLSTM maintains a matrix $\mathbf{C}_t \in \mathbb{R}^{d\times d}$ that is updated by outer products (covariance-style updates)
$\mathbf{C}_t = f_t \, \mathbf{C}_{t-1} + i_t \, \mathbf{v}_t \, \mathbf{k}_t^\top,$
where $\mathbf{k}_t$ is a key vector and $\mathbf{v}_t$ is the corresponding value vector. Retrieval is then a matrix–vector product: $\tilde{\mathbf{h}}_t = \mathbf{C}_t \mathbf{q}_t / \text{(normalizer)}$, where $\mathbf{q}_t$ is a query. This outer-product memory stores many key–value associations in a distributed, higher-capacity fashion: each key–value pair contributes a rank-1 matrix, and a superposition of such matrices supports retrieval with higher separability than scalar cells.

This setup is equivalent to classical covariance storage / fast-weight programmers and is optimal (in the sense discussed in the paper) for maximizing separability under the pairwise retrieval assumption. Practically, the matrix memory gives mLSTM more fine-grained capacity to remember and later reconstruct information about rare events or many simultaneous associations, which explains improved performance on rare-token prediction and associative-recall tasks relative to scalar-cell LSTMs.

# Sequential dependency from memory mixing (hidden-to-hidden connections)

A third major limitation of standard LSTM formulations is architectural: memory mixing via hidden-to-hidden recurrent connections enforces inherently sequential processing and blocks straightforward parallelization across timesteps. In the usual vectorized LSTM, the inputs to gates and candidate updates include terms like $r_i \, h_{t-1}$, $r_f \, h_{t-1}$ and so on. These “hidden-hidden” terms mix the previous hidden state into the current gating and input computations, and they create a true recurrence that must be processed sequentially: computing the state at time $t$ requires having computed $h_{t-1}$.

This sequential dependency increases latency for long sequences and prevents the kind of efficient parallel training and inference that self-attention (in Transformers) or certain linearized architectures enjoy. In practice, it makes scaling to very long contexts and very large models more costly in wall-clock time and complicates GPU parallelization strategies. The paper notes that this lack of parallelizability was one of the reasons Transformers displaced LSTMs in many large-scale language-modeling settings: Transformers replace hidden-to-hidden recurrence with self-attention, enabling parallel computation across sequence positions and quadratic or, with approximations, linear-time attention implementations.

xLSTM approaches this limitation with two complementary design choices. First, the mLSTM abandons memory mixing: the matrix memory update in mLSTM depends only on the current input projections (keys, values, queries) and scalar gates derived from input, not on $h_{t-1}$. Because of that, the recurrence can be reformulated into a parallel scan (and in practice implemented in a fully parallel manner across timesteps analogous to linearized attention or certain fast-weight formulations). In contrast, sLSTM retains memory mixing (it has recurrent connections) but gains other advantages (state-tracking expressivity); to mitigate runtime costs the authors implemented optimized CUDA kernels for sLSTM. The design tradeoff is explicit: memory mixing provides expressivity for state-tracking problems but conflicts with parallelizable implementations, whereas removing mixing makes for more parallel-friendly and scalable architectures at the potential cost of some expressiveness—hence the hybrid xLSTM architectures that combine both block types.

# How these limits favored attention-based Transformers

The three limitations above—difficulty revising stored content, limited scalar storage, and sequential recurrence—help explain why attention-based Transformers became dominant in large-scale language modeling. Self-attention provides two practical and functional advantages relative to classical LSTMs that directly address these weaknesses.

First, attention performs retrieval from context via dot products and weighted sums between keys, queries, and values. This mechanism is naturally able to locate and amplify a particular past token’s contribution at prediction time without needing to have preserved a single scalar summarizing that token. It thereby mitigates the need to compress many distinct pieces of information into scalar cells; attention’s effective memory capacity grows combinatorially with its embedding dimension and can represent many distinct associations explicitly.

Second, Transformer attention is parallelizable across positions: the self-attention computation does not require computing previous hidden states sequentially. This allows large-scale parallel training on long contexts, and makes it practical to build very deep and wide models that process many tokens simultaneously. That hardware efficiency and the associated scaling behavior are repeatedly cited in the paper as major reasons Transformers outpaced LSTMs at scale.

Third, attention enables direct revisitation of past tokens at arbitrary strengths at prediction time. Where an LSTM might have to rely on whatever was retained in its cell states, attention can directly reweight specific prior elements depending on the current query. This flexibility resembles the “revise storage decisions” goal: rather than having to overwrite a memory progressively, a model can choose at read time which past element to emphasize. As the paper notes, these operational characteristics allowed Transformers to excel in large language models and were instrumental in the historical shift away from classic LSTMs in many language tasks.

# Design desiderata for a next-generation LSTM

Given the three limitations above, the xLSTM paper motivates a concise set of desiderata for a modernized LSTM-style architecture that aspires to compete with attention-based models at scale. These desiderata guided the design of the sLSTM and mLSTM variants:

1. Enable robust revision of past stored content. The architecture should allow later inputs to significantly revise or replace earlier stored items when required by the task. In xLSTM this is achieved by exponential gating (gates computed as exponentials rather than restricted sigmoids) combined with a normalization mechanism (a normalizer state that accumulates the effective gate strengths) and a numerical stabilizer state to avoid overflow. These changes let the effective multiplicative factors on memory contributions be unbounded and thus permit decisive revisions.

2. Increase memory capacity beyond scalar compression. The model should be able to store many distinct key–value associations with higher fidelity to support rare events and associative recall. The mLSTM meets this by replacing scalar cells with a matrix memory $\mathbf{C}_t$ and using a covariance (outer-product) update rule $ \mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top$, and retrieval via $\mathbf{C}_t \mathbf{q}_t$ normalized by a corresponding normalizer state. This gives much richer representational capacity akin to fast-weight memory.

3. Support parallelizability where possible. To scale to large models and long contexts, the architecture should be amenable to parallel computation over timesteps. The mLSTM achieves this by designing the memory update and retrieval so they can be reformulated in a parallel manner (no hidden–hidden mixing). At the same time, the design accepts that certain forms of memory mixing are valuable; thus, xLSTM offers hybrid architectures where some blocks (sLSTM) keep recurrent mixing for expressive state tracking, while others (mLSTM) provide parallel, high-capacity memory.

4. Provide numerical stability and normalization. The novel exponential gates and matrix-valued memories introduce risks of numerical overflow or vanishing signal-to-noise. The paper therefore includes normalization (a normalizer state that accumulates effective gate-weighted contributions) and stabilization (a stabilizer state $m_t$ that rescales exponentials) so that the operations are numerically well behaved and gradients remain meaningful.

5. Integrate smoothly into modern residual architectures. Contemporary large models are built by residually stacking blocks with pre-LayerNorm and projection patterns. The xLSTM variants were designed to be used inside residual blocks (with choices like pre- or post-up-projection depending on whether an mLSTM or sLSTM is used) so that they can be scaled, tuned, and trained using the same stacking paradigms that enabled Transformers and SSMs to scale.

6. Preserve LSTM strengths such as state-tracking. Importantly, while adding capacity and parallelism, the design retains the gating and memory mechanisms that make LSTMs effective at extracting and maintaining high-level abstractions across long sequences (e.g., state tracking needed for tasks like program evaluation or entity tracking). sLSTM preserves memory mixing and recurrent paths for these cases; mLSTM provides alternative mechanisms when parallelism is the priority.

These desiderata inevitably imply trade-offs. The matrix memory increases computational cost due to $d\times d$ updates, and keeping memory mixing (sLSTM) limits parallelizability. The paper explicitly acknowledges these trade-offs and presents hybrid xLSTM architectures (mixtures of mLSTM and sLSTM blocks) and engineering mitigations (stabilization techniques, CUDA kernels, and residual block placements) to balance expressivity, capacity, and throughput.

In sum, examining the limitations of classic LSTMs clarifies why attention-based models became dominant and points to concrete architectural changes—exponential gating, matrix memories, normalization/stabilization, and selective abandonment of hidden-to-hidden recurrence—that can revive LSTM-style models for modern large-scale sequence modeling. The xLSTM family implements these desiderata and, as reported in the paper, demonstrates that with those modifications a next-generation LSTM can close the gap with contemporary Transformers and State Space Models while offering favorable scaling and memory properties.

xLSTM at a Glance: Goals, Components, and Architecture

# Core contributions: exponential gating and modified memory

xLSTM extends the classic Long Short-Term Memory (LSTM) by introducing two principled modifications designed to overcome well-known LSTM limitations. The first modification is exponential gating: replacing (or augmenting) standard sigmoid gates with exponential activation functions for the input gate (and optionally for the forget gate). The second modification is a change in the memory structure: instead of restricting the memory to a single scalar per cell, xLSTM offers two alternative memory designs that increase expressiveness and storage capacity.

Exponential gating changes how new information is accumulated and how older information is decayed. In a standard LSTM the input gate and forget gate are bounded between 0 and 1 by a sigmoid, so each time step contributes or decays additively in a constrained fashion. By using an exponential activation for the input gate, xLSTM lets the effective learning rate for incoming content grow multiplicatively with \(\exp(\tilde{i}_t)\). To avoid numerical overflow and to preserve correct gradients, the model also introduces a stabilizer state \(m_t\) and a normalizer state (discussed later) so that the algebraic effect on the overall network output is unchanged while numerical stability is maintained.

The memory-structure modification comes in two flavors (detailed below) and allows xLSTM to both revise previously stored information more effectively and to store higher-capacity representations. Together these two contributions — exponential gating and richer memory — are the core technical innovations of xLSTM. Intuitively, exponential gating enables stronger, revisable updates (new evidence can rapidly dominate previous content), while the modified memory enables retrievals that are richer than what a scalar cell can provide.

# Two xLSTM variants: sLSTM (scalar memory) and mLSTM (matrix memory)

xLSTM yields two concrete variants that instantiate the above ideas: the sLSTM and the mLSTM.

The sLSTM keeps the classical scalar cell-state view (a vector of scalar cells when using multiple cells), but it replaces conventional sigmoid input gating with an exponential input gate and introduces supporting normalization and stabilization states. The per-step forward equations for a scalar cell in sLSTM are:
\[
\begin{aligned}
c_t &= f_t\, c_{t-1} + i_t\, z_t &&\text{(cell state)}\\
n_t &= f_t\, n_{t-1} + i_t &&\text{(normalizer state)}\\
\tilde{h}_t &= c_t / n_t,\qquad h_t = o_t\, \tilde{h}_t &&\text{(hidden state)}
\end{aligned}
\]
with the gate parametrizations
\[
i_t = \exp(\tilde{i}_t),\qquad f_t = \sigma(\tilde{f}_t)\ \text{or}\ \exp(\tilde{f}_t),\qquad o_t=\sigma(\tilde{o}_t),
\]
and the usual input transform \(z_t=\varphi(\tilde{z}_t)\). The normalizer \(n_t\) accumulates effective gate mass so that the normalized output \(\tilde{h}_t\) represents a weighted average of stored inputs; dividing by \(n_t\) prevents the cell state from drifting arbitrarily large when gates are exponential. To stabilize exponentials, sLSTM introduces a scalar stabilizer \(m_t\) and computes numerically safe scaled versions \(i'_t\) and \(f'_t\) that preserve exact outputs and gradients while avoiding overflow:
\[
\begin{aligned}
m_t &= \max(\log(f_t)+m_{t-1},\ \log(i_t)),\\
i'_t &= \exp(\log(i_t)-m_t),\qquad f'_t=\exp(\log(f_t)+m_{t-1}-m_t).
\end{aligned}
\]
This stabilizer ensures the exponential gating dynamics are computable and that the normalized hidden state remains meaningful.

The mLSTM replaces the scalar cell by a matrix memory \(\mathbf{C}_t\in\mathbb{R}^{d\times d}\). It stores key–value pairs and uses a covariance (outer-product) update rule so that the memory grows by rank-1 updates at each step. The core forward pass for mLSTM is:
\[
\begin{aligned}
\mathbf{C}_t &= f_t\, \mathbf{C}_{t-1} + i_t\, \mathbf{v}_t \mathbf{k}_t^\top &&\text{(matrix cell state)}\\
\mathbf{n}_t &= f_t\, \mathbf{n}_{t-1} + i_t\, \mathbf{k}_t &&\text{(vector normalizer)}\\
\tilde{\mathbf{h}}_t &= \frac{\mathbf{C}_t \mathbf{q}_t}{\max\{|\mathbf{n}_t^\top \mathbf{q}_t|,\,1\}},\qquad 
\mathbf{h}_t = \mathbf{o}_t \odot \tilde{\mathbf{h}}_t &&\text{(hidden state)}
\end{aligned}
\]
where \(\mathbf{k}_t,\mathbf{v}_t,\mathbf{q}_t\) are key, value, and query vectors projected from input, and \(i_t=\exp(\tilde{i}_t)\) while \(f_t\) may be sigmoid or exponential. The denominator uses the absolute dot product between \(\mathbf{n}_t\) and \(\mathbf{q}_t\) (clipped at 1) to normalize retrieval and avoid near-zero scaling. The matrix memory lets the model encode and retrieve high-dimensional associations via \(\mathbf{C}_t\mathbf{q}_t\), which can produce far richer readouts than scalar-cell multiplication.

In short: sLSTM brings exponential gating into the familiar LSTM scalar framework with normalization/stabilization; mLSTM brings a matrix-valued memory with an outer-product update and normalized retrieval rule.

# Heads and cells: memory mixing within sLSTM heads; equivalence of heads and cells in mLSTM

xLSTM supports multi-cell and multi-head designs, but the semantics differ between sLSTM and mLSTM because of memory mixing.

In sLSTM, when multiple scalar memory cells are used they can be mixed across time through recurrent (hidden-to-gate/input) weight matrices. These recurrent connections (denoted in the paper as \(\mathbf{R}_{\mathbf{z}},\mathbf{R}_{\mathbf{i}},\mathbf{R}_{\mathbf{f}},\mathbf{R}_{\mathbf{o}}\)) allow the hidden state vector \(\mathbf{h}_{t-1}\) to influence the input transforms and gates for each cell, enabling cross-cell interactions. xLSTM introduces the notion of "heads" for sLSTM: within a head, multiple scalar memory cells may be mixed via recurrent connections, but different heads are intentionally kept separate (no memory mixing across heads). This head structure together with exponential gating provides a new form of memory mixing: the exponential gates determine how strongly each cell in a head contributes, while the recurrent mixing shapes how cells interact temporally. The head separation lets the model partition memory into semi-independent processing streams while retaining intra-head mixing for state tracking tasks.

In contrast, mLSTM’s matrix memory inherently captures multi-dimensional associations inside \(\mathbf{C}_t\). Because mLSTM abandons hidden-to-hidden memory mixing (there are no recurrent hidden-hidden weightings mixing \(\mathbf{h}_{t-1}\) into gate computations in the recurrent sense used by sLSTM), the concepts of heads and cells become functionally equivalent: adding extra cells or extra heads simply increases the number of independent matrix memories, but there is no cross-memory mixing performed by recurrent connections. Consequently the paper states that "for mLSTM multiple heads and multiple cells are equivalent." This equivalence simplifies the architectural choices for mLSTM: one may allocate capacity via the internal dimension \(d\) and by stacking multiple matrix memories if desired, but the model's temporal mixing is achieved by the covariance updates rather than by recurrent hidden-to-hidden matrices.

Understanding this difference is important because it explains why sLSTM retains the expressivity of traditional LSTMs for state-tracking tasks (via recurrent mixing), while mLSTM trades that specific mixing mechanism for a richer, parallelizable associative memory.

# xLSTM blocks and residual stacking into full architectures

xLSTM integrates sLSTM and mLSTM cells into modern residual-block backbones to build deep sequence models that are compatible with contemporary LLM tooling. The building block is a residual xLSTM block: the block encapsulates a memory module (sLSTM or mLSTM) plus surrounding projection, normalization, and residual connections that match common pre-LayerNorm residual patterns used in large language models.

Two backbone variants for xLSTM blocks are highlighted because the placement of the projection that moves between the model's "base" dimension and the memory's internal (often higher) dimension matters. For sLSTM blocks the paper uses a post up-projection residual block: the block first nonlinearly summarizes the past in the base dimension, then projects up to a higher-dimensional space where a nonlinearity is applied, and finally projects back to the base dimension. This design mirrors "post up-projection" patterns used in Transformer-like feed-forward modules and is appropriate for sLSTM since its scalar cell formulation operates effectively at the original dimensionality.

For mLSTM blocks the paper prefers a pre up-projection block: inputs are first projected up into a higher-dimensional space where the matrix memory operates. This choice increases the memory capacity in the high-dimensional embedding space, taking full advantage of the matrix cell \(\mathbf{C}_t \in \mathbb{R}^{d\times d}\). In other words, since mLSTM’s memory benefits from larger internal dimension \(d\), projecting into that space before the memory operation yields more expressive associative storage and retrieval.

Once individual xLSTM blocks are defined, a full xLSTM architecture is constructed by residually stacking many such blocks. The stacking uses pre-LayerNorm residual backbones (a standard pattern in modern LLMs), so each block is preceded by LayerNorm and followed by a residual addition to the block's input. This residual stacking enables deep networks that nonlinearly embed histories into high-dimensional spaces — an application of Cover’s Theorem in sequence modeling — making contexts more linearly separable for the final token prediction layer.

# Notation xLSTM[a:b] for block ratios (mLSTM:sLSTM)

To concisely indicate architectures that mix both memory types across layers, the paper introduces the notation xLSTM[a:b] where \(a:b\) is the ratio of mLSTM-based blocks to sLSTM-based blocks. For example, xLSTM[7:1] means that out of every eight residual blocks, seven are mLSTM-based and one is sLSTM-based. With a total of 48 blocks, xLSTM[7:1] corresponds to 42 mLSTM blocks and 6 sLSTM blocks.

This notation allows succinct description of hybrid models that leverage both the high-capacity associative matrix memories of mLSTM and the recurrently-mixed scalar memories of sLSTM. Hybrids can exploit mLSTM’s parallelizability and capacity while preserving sLSTM’s recurrent memory mixing for state tracking where needed.

# Intended benefits: revisability, capacity, and efficiency

xLSTM is explicitly designed to address three shortcomings identified in classical LSTMs: (i) inability to readily revise stored values, (ii) limited storage capacity per scalar cell, and (iii) lack of parallelizability due to hidden-to-hidden memory mixing. Each core design choice in xLSTM maps to these targets.

Revisability. Exponential gating gives the model the ability to revise storage decisions aggressively. Because the input gate can scale as \(i_t=\exp(\tilde{i}_t)\), a later input with a large \(\tilde{i}_t\) can rapidly dominate prior content stored in the cell. The normalizer state \(n_t\) ensures that the output is a normalized aggregation, so later, stronger contributions can effectively overwrite previously stored weaker evidence. Stabilization ensures these exponentials are numerically safe. Empirically (as reported in the paper), this mechanism improves tasks that require revising earlier writes when better evidence arrives.

Capacity. The mLSTM’s matrix memory \(\mathbf{C}_t\) and its covariance update rule \(\mathbf{C}_t \leftarrow f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top\) give much greater storage capacity than scalar cells. Retrieval is performed by \(\mathbf{C}_t\mathbf{q}_t\) and normalized by the normalizer vector, enabling associative recall of high-dimensional values keyed by \(\mathbf{k}\). This design is closely related to covariance-based associative memories and fast-weight schemes and provides a mechanism to store many key–value pairs in a compressed matrix form. Practically, this improves predictions for rare tokens and associative memory tasks where storing distinct high-dimensional items matters.

Efficiency. mLSTM is architected to be parallelizable: because it avoids hidden-hidden recurrent mixing within the matrix memory update and retrieval, the recurrence can be reformulated into parallel operations that are amenable to GPU acceleration (in the same spirit as FlashAttention-like parallelizations). Additionally, xLSTM architectures have linear computation and constant memory complexity with respect to sequence length (unlike Transformer attention which is quadratic in context length). This constant-memory, linear-time behavior makes xLSTM attractive for long-context inference and for deployments where memory is constrained. That said, there are trade-offs: sLSTM retains memory mixing and therefore is not fully parallelizable; mLSTM’s matrix updates are computationally heavier (\(d\times d\) costs) even if parallelizable. The paper addresses these trade-offs by combining blocks (via xLSTM[a:b]) and by careful block design (pre/post up-projection) so a practical balance of capacity, revisability, and throughput can be achieved.

In summary, xLSTM brings exponential gating to enable revisable writes, introduces a matrix associative memory to expand capacity, and integrates both into residual block backbones so the models fit contemporary LLM design patterns. The sLSTM variant maintains recurrent mixing and fine-grained state-tracking ability, while the mLSTM variant provides high-capacity, parallelizable associative storage; mixing these under the xLSTM[a:b] notation gives architects a flexible palette for trading capacity, revisability, and runtime efficiency.

Exponential Gating, Normalization, and Stabilization

# Exponential input and forget gates: definitions and intuition

xLSTM replaces the standard sigmoid gates of the classical LSTM with exponential gates for at least some of the control signals, most importantly the input gate. Concretely, in the scalar sLSTM formulation the input gate is defined as
\[
i_t \;=\; \exp\!\left(\tilde{i}_t\right),\qquad
\tilde{i}_t \;=\; \mathbf{w}_i^\top \mathbf{x}_t + r_i h_{t-1} + b_i,
\]
while the forget gate may be either the conventional sigmoid
\[
f_t \;=\; \sigma(\tilde{f}_t)
\]
or an exponential
\[
f_t \;=\; \exp(\tilde{f}_t),\qquad
\tilde{f}_t \;=\; \mathbf{w}_f^\top \mathbf{x}_t + r_f h_{t-1} + b_f.
\]
These definitions appear in the sLSTM forward equations:
\[
\begin{aligned}
c_t &= f_t c_{t-1} + i_t z_t,\\
n_t &= f_t n_{t-1} + i_t,\\
h_t &= o_t \,\tilde h_t,\qquad \tilde h_t = c_t / n_t,
\end{aligned}
\]
with $z_t$ the cell input and $o_t$ the output gate (see Equation (2) in the paper).

Intuitively, replacing a sigmoid by an exponential changes the role of the gate from a bounded attenuator to a positive multiplicative factor with unbounded (but stabilized) dynamic range. A sigmoid gate is constrained to lie in $(0,1)$ and can only attenuate stored quantities (it cannot amplify). In contrast, an exponential gate yields a strictly positive scalar that can be much larger than one or much smaller than one, depending on its pre-activation. This expanded range lets the model multiply past contributions by factors greater than one or less than one, giving it a much richer set of ways to revise how previous inputs contribute to the current state.

Operationally, with exponential gating the memory update becomes a weighted sum with weights that can vary across many orders of magnitude. The input gate $i_t$ acts like an adaptive, positive learning rate for the new contribution $z_t$, while the forget gate $f_t$ acts like a multiplicative decay (or amplification) of all previously stored contributions. Together these multiplicative effects allow the network to re-weight (and even amplify) previous information in a finer-grained way than is possible with standard sigmoid gates.

# Normalizer state (n_t): tracking effective gate strengths

Exponential gates change the scale of the additive memory update. To make retrieval stable and meaningful we must keep track of the total effective strength by which inputs have been incorporated into the cell. The sLSTM introduces a normalizer state $n_t$ that mirrors the form of the cell update but without the content vectors:
\[
n_t \;=\; f_t n_{t-1} + i_t.
\]
If we unroll the recurrence for $c_t$ and $n_t$ we find that
\[
c_t \;=\; \sum_{s\le t} \Big(\prod_{u=s+1}^t f_u\Big)\, i_s z_s,\qquad
n_t \;=\; \sum_{s\le t} \Big(\prod_{u=s+1}^t f_u\Big)\, i_s.
\]
Thus $n_t$ accumulates the same multiplicative weights used to combine earlier inputs, but without the content vectors $z_s$. The hidden pre-output $\tilde h_t$ is then defined as the normalized cell content,
\[
\tilde h_t \;=\; \frac{c_t}{n_t}.
\]
This ratio interprets the memory as a weighted average of past contributions $z_s$, where the weight for a contribution at time $s$ equals $i_s$ times the product of future forget factors. By keeping and dividing by $n_t$, the sLSTM produces a retrieval that is invariant to a global rescaling of the additive terms: if all contributions were multiplied by the same positive factor, both $c_t$ and $n_t$ would scale identically and the ratio would remain unchanged. In short, $n_t$ tracks the total effective gate strength and makes the retrieved state a normalized, interpretable summary rather than an unbounded accumulated vector.

The normalizer is equally important for the matrix memory of mLSTM (there, $n_t$ is a vector accumulating weighted keys). In both scalar and matrix cases the normalizer enables the network to compare contributions that arrive at different times and have been subjected to different sequences of multiplicative forget factors.

# Stabilizer state (m_t): log-domain max trick to prevent overflow

Exponential gates are powerful but dangerous numerically: applying raw exponentials repeatedly can easily overflow floating-point representations or produce extremely small values that underflow. xLSTM addresses this with a log-domain stabilization technique that keeps the effective magnitudes in a safe range while preserving the mathematical behavior of the recurrence.

The stabilizer state $m_t$ is defined in the log domain as
\[
m_t \;=\; \max\!\big(\log(f_t) + m_{t-1},\; \log(i_t)\big).
\]
This is a running max that tracks the dominant log-scale between the scaled previous factor and the current input gate. Using $m_t$ we form stabilized, primed gates
\[
\begin{aligned}
i'_t &= \exp\big(\log(i_t) - m_t\big) = \exp(\tilde{i}_t - m_t),\\
f'_t &= \exp\big(\log(f_t) + m_{t-1} - m_t\big).
\end{aligned}
\]
These primed gates are scaled to lie in a numerically safe range: at least one of $i'_t$ or the scaled forget factor will be near one, and none will be astronomically large. The construction is analogous to the common log-sum-exp or “max” trick used to stabilize softmax computations: by factoring out the largest exponent, we avoid creating extremely large exponentials while preserving ratios between terms.

Because $m_t$ is updated from $\log(f_t) + m_{t-1}$ and $\log(i_t)$, it maintains the necessary bookkeeping to rescale both the previous state and the current input consistently. This way, the algorithm can run in standard floating-point precision without overflow or underflow, even though the underlying gates are conceptually exponentials that could assume very large or very small values.

# Stabilized gates (i'_t, f'_t) and invariance of outputs/gradients

A key property of the stabilization trick is that replacing the original gates $i_t,f_t$ by the stabilized versions $i'_t,f'_t$ and working with correspondingly rescaled internal states leaves the network outputs and parameter gradients unchanged. The paper proves (see Appendix) that the forward pass and the loss derivatives with respect to parameters are invariant under this reformulation. Here is the intuition and the algebraic sketch that makes the invariance transparent.

Define the scaled (tilde) states
\[
\tilde c_t \;=\; e^{-m_t} c_t,\qquad \tilde n_t \;=\; e^{-m_t} n_t.
\]
Starting from the original recurrences
\[
c_t = f_t c_{t-1} + i_t z_t,\qquad n_t = f_t n_{t-1} + i_t,
\]
multiply both sides by $e^{-m_t}$ and substitute the definitions of $i'_t,f'_t$:
\[
\begin{aligned}
\tilde c_t &= e^{-m_t} f_t c_{t-1} + e^{-m_t} i_t z_t
           = f'_t \tilde c_{t-1} + i'_t z_t,\\
\tilde n_t &= f'_t \tilde n_{t-1} + i'_t.
\end{aligned}
\]
Thus the scaled variables evolve with the numerically safe primed gates exactly as the unscaled variables would with the original gates. The pre-output is the normalized ratio
\[
\tilde h_t \;=\; \frac{c_t}{n_t} \;=\; \frac{\tilde c_t}{\tilde n_t},
\]
so the output that enters the rest of the network is identical whether computed from the original or the stabilized recurrences. Since all downstream computations depend only on these identical outputs, the loss and its derivatives with respect to the parameters are also identical. In other words, stabilization is a purely numerical reparameterization that does not change the mathematical function implemented by the network nor its gradients.

This invariance is crucial: it means we can enjoy the expressive benefits of exponential gating while safely executing the computations in floating-point arithmetic, and we can do so without modifying optimization behavior or learning dynamics.

# Initialization and numerical considerations for robust training

Exponential gates combined with normalization and stabilization make the model numerically manageable, but they also shift some practical considerations for training. The paper emphasizes (and lists as a limitation) that the initialization of forget gates must be chosen carefully. Because forget gates enter multiplicatively into the long-term accumulation (they appear in every product that weights a past contribution), their initial bias and scale control whether the memory tends to retain or rapidly forget past inputs at the start of training.

If forget factors are initialized so that their exponentials systematically produce values far greater than one, then even with stabilization the dynamics may emphasize older inputs excessively and make optimization difficult. Conversely, if the initial forget factors are too small, the model will rapidly forget and cannot accumulate useful context over long ranges. The paper therefore stresses careful selection of forget gate initializations but does not prescribe a single universal setting; this is listed as an implementation consideration that practitioners must tune for particular tasks and model sizes.

Beyond forget initialization, additional numerical considerations follow directly from the design choices:

- Exponential gates alone can produce extremely large or small magnitudes; stabilization via $m_t$ is therefore mandatory for practical training. Without the stabilizer, exponentials would cause frequent overflow or underflow in real-world training regimes.

- The normalizer $n_t$ must be guarded against extremely small values when dividing (for example to avoid division-by-zero). In practice the stabilization machinery and sensible initializations make $n_t$ well behaved, but implementers should still take care to ensure that the denominator in $c_t/n_t$ remains numerically safe (for instance by the use of the stabilizing rescaling described above).

- When extending to matrix memories (mLSTM), analogous concerns apply componentwise to the normalizer vector and to the dot products used at retrieval. For example, the paper uses an absolute-valued dot product and a lower bound in the mLSTM retrieval to prevent near-zero denominators (see the mLSTM equations). Those choices are consistent with the same mindset: preserve retrieval semantics while ensuring numerical robustness.

Taken together, these points emphasize that exponential gating is a powerful tool that must be paired with log-domain stabilization and careful initial conditions to yield robust, trainable models.

# Why exponential gating enables revisable storage

One of the principal motivations for introducing exponential gates is to give the LSTM family the ability to revise prior storage decisions dynamically. In the original LSTM formulation, sigmoid gates are constrained to $(0,1)$; once information has been stored and subsequently attenuated by forget gates less than one, it is difficult for later events to re-weight or undo that decision strongly. This limitation shows up empirically in tasks like the Nearest Neighbor Search described in the paper, where an early stored candidate should be replaced if a later, more similar item appears in the sequence. A bounded input gate simply cannot allocate a sufficiently larger weight to the later item relative to the earlier one when many multiplicative decay factors intervened.

Exponential gating changes the picture because input and forget gates become positive multiplicative factors that can differ by orders of magnitude. Consider the unrolled weighted-sum view:
\[
\tilde h_t = \frac{\sum_{s\le t} \big(\prod_{u=s+1}^t f_u\big)\, i_s z_s}{\sum_{s\le t} \big(\prod_{u=s+1}^t f_u\big)\, i_s}.
\]
Each past contribution $z_s$ enters with weight $w_s = \big(\prod_{u>s} f_u\big)i_s$. With exponential gates $i_s$ and $f_u$ can be very small or very large (relative to 1), so the model can make $w_s$ arbitrarily dominant or negligible. This means a later input $z_t$ can be given a much larger effective weight than earlier inputs, even if those earlier inputs have been attenuated by sequences of forget factors. In practical terms, the network can "overwrite" or strongly re-weight previous storage decisions: a later, more relevant input can dominate the normalized sum and thus determine the retrieved state.

The normalizer $n_t$ ensures these re-weightings are interpretable and stable: by dividing by the sum of weights, the network retrieves a normalized summary that reflects the relative importance assigned to each stored item. The stabilizer $m_t$ makes such extreme relative weights numerically tractable. Together, exponential gating, the normalizer, and stabilization implement a mechanism that behaves like a continuously adaptive associative memory: items are stored with learned, multiplicative strengths, and later items can be weighted up or down to revise earlier storage. This is precisely what enables xLSTM to succeed on tasks requiring revision of memory, such as the Nearest Neighbor Search experiments and other state-tracking benchmarks discussed in the paper.

In summary, exponential input and forget gates provide a much larger and more flexible space of multiplicative weights; the normalizer turns the accumulated memory into a meaningful normalized summary; and the stabilizer permits these dynamics to run safely in floating-point arithmetic. Together these instruments enable xLSTM to revise past storage decisions dynamically while remaining numerically robust and differentiable end-to-end.

sLSTM: Scalar Memory with Exponential Gating and Memory Mixing

# sLSTM forward pass: cell, normalizer, hidden state, and gates

The sLSTM retains the original LSTM notion of a scalar memory cell per dimension, but introduces two central modifications: exponential gating for some gates, and a normalizer state that records cumulative gate influence. The forward-pass equations for a single scalar sLSTM cell at time step $t$ are:

\[
\begin{aligned}
c_t &= f_t \, c_{t-1} + i_t \, z_t &&\text{(cell state)}\\[4pt]
n_t &= f_t \, n_{t-1} + i_t &&\text{(normalizer state)}\\[6pt]
h_t &= o_t \, \tilde{h}_t,\qquad 
   \tilde{h}_t = \frac{c_t}{n_t} &&\text{(hidden state / readout)}\\[6pt]
z_t &= \varphi(\tilde{z}_t),\qquad
   \tilde{z}_t = \mathbf{w}_z^\top \mathbf{x}_t + r_z \, h_{t-1} + b_z &&\text{(cell input)}\\[6pt]
i_t &= \exp(\tilde{i}_t),\qquad
   \tilde{i}_t = \mathbf{w}_i^\top \mathbf{x}_t + r_i \, h_{t-1} + b_i &&\text{(input gate)}\\[6pt]
f_t &= \sigma(\tilde{f}_t)\ \text{OR}\ \exp(\tilde{f}_t),\qquad
   \tilde{f}_t = \mathbf{w}_f^\top \mathbf{x}_t + r_f \, h_{t-1} + b_f &&\text{(forget gate)}\\[6pt]
o_t &= \sigma(\tilde{o}_t),\qquad
   \tilde{o}_t = \mathbf{w}_o^\top \mathbf{x}_t + r_o \, h_{t-1} + b_o &&\text{(output gate)}
\end{aligned}
\]

These equations preserve the additive "constant error carousel" update $c_t = f_t c_{t-1} + i_t z_t$ from classical LSTM, but they (i) allow input gates (and optionally forget gates) to be exponential instead of sigmoid, and (ii) introduce the normalizer $n_t$ so that the readout $\tilde{h}_t$ is the normalized cell state $c_t/n_t$ rather than a squashed version of $c_t$. The activations $\varphi$ and $\sigma$ are as in the original formulation (e.g., $\varphi$ commonly $\tanh$, $\sigma$ the logistic sigmoid). The recurrent coefficients $r_z, r_i, r_f, r_o$ and input weight vectors $\mathbf{w}_\cdot$ play the same role as in standard LSTMs.

Intuitively, $c_t$ accumulates weighted contributions of past inputs (weighted by $i$ and modulated by $f$), while $n_t$ keeps an analogous accumulated weight (the sum of effective input weights after forget dynamics). Dividing $c_t$ by $n_t$ produces a normalized readout that behaves like a weighted average of stored contributions. This normalization both stabilizes retrieval and enables the cell state to represent a magnitude that is comparable across time and across contexts.

Because exponential gates can grow very large or very small and thereby cause numerical overflow/underflow, the sLSTM employs a stabilizer state (described below) that algebraically rescales gates without changing the exact forward outputs or gradients. The stabilizer is crucial for safely using exponential activations in practice.

# Forget gate choices: sigmoid vs exponential

A key design choice in sLSTM is whether the forget gate $f_t$ should remain a sigmoid-limited gate in $(0,1)$ as in standard LSTM, or be replaced by an exponential $\exp(\tilde{f}_t)$ which can assume a wider positive range. The paper presents both options and discusses how they affect behavior.

When $f_t=\sigma(\tilde{f}_t)$, the forget gate behaves like a classical decay factor: each time step it attenuates past cell content and past normalizer weight by a multiplicative factor in $(0,1)$. This enforces a conventional forgetting dynamics where older contributions gradually diminish.

By contrast, using $f_t=\exp(\tilde{f}_t)$ permits $f_t$ to exceed $1$ and to take arbitrarily small positive values (after stabilization). This broader dynamic range enables richer temporal scaling: the model can exponentially amplify or attenuate past contents depending on $\tilde{f}_t$. Combined with exponential input gates $i_t=\exp(\tilde{i}_t)$, this allows the network to express very different effective weights for different stored inputs, which is central to sLSTM's ability to revise earlier storage decisions (see section on memory mixing below).

Because exponential gates can produce extreme magnitudes, the sLSTM includes a stabilization mechanism that rescales gate magnitudes algebraically but without changing the network output or gradients. The stabilizer state $m_t$ is defined by

\[
\begin{aligned}
m_t &= \max\!\big(\log(f_t) + m_{t-1},\ \log(i_t)\big)\\[6pt]
i'_t &= \exp\!\big(\log(i_t) - m_t\big) = \exp(\tilde{i}_t - m_t)\\[6pt]
f'_t &= \exp\!\big(\log(f_t) + m_{t-1} - m_t\big),
\end{aligned}
\]

and the forward pass can be computed with $i'_t$ and $f'_t$ in place of $i_t$ and $f_t$. The authors show that this substitution leaves the outputs and parameter gradients unchanged while preventing numerical overflow. Practically, this stabilizer lets one safely use exponential gates while preserving the interpretability of $n_t$ as an accumulated gate mass.

In summary, choosing sigmoid for $f_t$ gives conservative, bounded forgetting; choosing exponential for $f_t$ expands the model's expressive regime, enabling amplification-like dynamics. The appropriate choice depends on the task and training stability; the paper experiments with both variants.

# Multiple cells and recurrent mixing matrices

Although sLSTM is defined per scalar memory cell, the practical implementation uses vector-valued cell states $\mathbf{c}_t \in \mathbb{R}^d$ comprising multiple scalar cells. When multiple cells are present, sLSTM supports recurrent mixing between cells through recurrent weight matrices, in direct analogy to vector LSTMs. Concretely, the scalar recurrences above generalize by replacing scalar recurrent weights $r_\cdot$ with matrices $\mathbf{R}_\cdot \in \mathbb{R}^{d\times d}$ and scalar weights $\mathbf{w}_\cdot$ with input projection matrices, such that the pre-activations for cell input and gates include terms like $\mathbf{R}_z \mathbf{h}_{t-1}$, $\mathbf{R}_i \mathbf{h}_{t-1}$, etc.

These recurrent matrices enable "memory mixing": information written into one scalar cell can influence the inputs and gates of other cells at later time steps through the hidden state feedback. Memory mixing is crucial for solving tasks that require combining, updating, or correcting multiple stored pieces of information over time (for example, complex state-tracking problems or formal-language tasks). In the paper the recurrent mixing matrices are denoted by $\mathbf{R}_{\mathbf{z}}, \mathbf{R}_{\mathbf{i}}, \mathbf{R}_{\mathbf{f}}, \mathbf{R}_{\mathbf{o}}$, emphasizing that each projection into the cell input or each gate can receive a different linear combination of the previous hidden state.

Because the normalizer $\mathbf{n}_t$ is maintained per cell in the vector case (each scalar cell has its own normalizer), the readout for each cell remains a per-cell normalized quantity $\tilde{\mathbf{h}}_t = \mathbf{c}_t \oslash \mathbf{n}_t$ (elementwise division), and recurrent mixing operates through the hidden state $\mathbf{h}_t$ that aggregates these per-cell readouts via the output gate $\mathbf{o}_t$. Thus multi-cell sLSTM preserves the scalar-memory semantics while enabling rich cross-cell interactions through learned recurrent weight matrices.

# Multi-head sLSTM: mixing within heads, not across heads

The sLSTM architecture can be extended with multiple "heads". A head is a grouping of some subset of the scalar memory cells that share strong within-group recurrent mixing but are isolated from other heads in terms of hidden-to-cell recurrent connections. The paper emphasizes the following design: within each head, cells may mix via recurrent matrices, but there is no recurrent mixing across heads. In other words, the hidden state components feeding back into a head are restricted to that head's cells; heads do not directly recurrently influence one another.

This multi-head arrangement accomplishes several things. First, it partitions the memory into independently updating blocks that can each learn specialized dynamics. Second, by preventing cross-head recurrent mixing, the model reduces interference between distinct memory subsystems; each head can maintain its own local "working memory" and gating dynamics. Third, by allowing mixing within but not across heads, the architecture provides a controlled trade-off between expressivity and the strong sequential dependence that full recurrent mixing entails.

Importantly, multi-head sLSTM differs from multi-head designs in attention-based models: here, heads are not parallel attention maps but sets of scalar memory cells with their own recurrent interactions. The paper indicates that the introduction of heads together with exponential gating "establishes a new way of memory mixing": heads permit modular, localized recurrent dynamics, while exponential gates allow individual contributions within a head to be weighted (and revised) with high dynamic range.

# New memory mixing behavior induced by exponential gates

The combination of exponential input gates and the normalizer $n_t$ changes the semantics of what the cell stores and how later inputs can revise earlier ones. In a classical LSTM, gates are typically sigmoid-limited to $(0,1)$, which constrains how much a new input can override past stored values: the input gate can only add a bounded amount relative to the existing cell content, and the forget gate can only attenuate at most down to zero.

With exponential input gates $i_t=\exp(\tilde{i}_t)$, however, a newly arriving input can be assigned an arbitrarily large weight relative to previous contributions. Concretely, the cell state accumulation

\[
c_t = f_t c_{t-1} + i_t z_t
\]

and the normalizer accumulation

\[
n_t = f_t n_{t-1} + i_t
\]

together imply that the readout $\tilde{h}_t = c_t / n_t$ is a weighted average of past $z$ inputs with weights proportional to the products of their input gates and subsequent forget gates. If a later $i_t$ is much larger than the accumulated weighted mass $f_t n_{t-1}$, that new $z_t$ will dominate the ratio $c_t/n_t$, effectively allowing the model to revise or "override" previously stored values. Exponential gates make such strong re-weightings feasible because they are not bounded by $1$.

The normalizer $n_t$ is the critical device that keeps this mechanism stable and interpretable: it records the total effective weighting mass so that $\tilde{h}_t$ is always a normalized combination. Without $n_t$, unbounded exponential gating could produce unbounded $c_t$ and cause unstable outputs. Furthermore, the stabilizer state $m_t$ rescales exponentials so that computation remains numerically safe while preserving exact forward behavior.

This mechanism is exactly what allows sLSTM to address one of the classic LSTM limitations described in the paper: the inability to revise storage decisions (illustrated by the Nearest Neighbor Search task). Exponential gating plus normalization permits later inputs to strongly reweight the stored summary, enabling the cell to prioritize newer or more relevant inputs even when earlier inputs had been stored previously.

Finally, when multiple cells and recurrent mixing are present, exponential gating magnifies the expressive power of memory mixing: cells can interact, and a strong exponential gating decision in one cell can cascade through recurrent matrices to change the gate pre-activations of other cells on subsequent steps. This leads to richer dynamics than either classical LSTM gating or non-recurrent (no memory mixing) mechanisms like many SSMs and attention substitutes.

# Parallelization limits and practical CUDA implementation notes

A key practical difference between sLSTM and the mLSTM variant (matrix memory) is parallelizability. Because sLSTM retains hidden-to-hidden recurrent matrices (recurrent mixing through $\mathbf{R}_\cdot$), its time-step computations are inherently sequential: the computation at time $t$ depends on $h_{t-1}$ in a way that prevents straightforward parallelization across time steps. The paper explicitly notes that "sLSTM is not parallelizable due to the memory mixing (hidden-hidden connections)."

Despite this theoretical sequential bottleneck, the authors implemented highly optimized CUDA kernels for sLSTM that exploit GPU register-level memory layouts and other low-level optimizations. In practice, their fast CUDA implementation makes sLSTM performance competitive: the implementation is "typically less than two times slower than mLSTM." This indicates that while sLSTM cannot match the same degree of parallel wall-clock speed as fully parallelizable architectures, careful low-level engineering can substantially narrow the gap and make sLSTM practical for many workloads.

The paper also contrasts sLSTM with mLSTM in terms of parallelism: mLSTM abandons memory mixing (hidden-hidden recurrent connections) and so can be reformulated in a parallel fashion akin to some linear-attention or Fast Weight architectures. Consequently, mLSTM admits straightforward parallelized GPU implementations, whereas sLSTM requires sequential processing but benefits from optimized sequential kernels.

# When to use sLSTM blocks in practice

The sLSTM block is a design choice inside the larger xLSTM residual-stacked architecture. In xLSTM, sLSTM-based blocks are integrated into a residual backbone with a post up-projection pattern (i.e., non-linear summarization happens in the original embedding dimension and is then projected up and back), as described in the paper. Practically, the paper recommends using sLSTM blocks when the task benefits from recurrent memory mixing and strong per-step revision capability:

- State-tracking and formal-language problems. The experiments show that models with sLSTM (and hence memory mixing and exponential gating) can solve formal languages and tasks requiring explicit state-tracking that purely feedforward or non-mixing architectures cannot reliably handle.

- Scenarios where the model must revise stored information. Tasks like the Nearest Neighbor Search example (described in the paper) reveal that classical LSTM struggles to revise previously stored values; sLSTM's exponential gating and normalization enable effective revision.

- When combining with larger-capacity blocks. The empirical xLSTM designs often mix sLSTM blocks with mLSTM blocks (matrix-memory blocks). For example, the notation xLSTM[$a$:$b$] in the paper denotes the ratio of mLSTM-based to sLSTM-based blocks; mixing a small number of sLSTM blocks into predominantly mLSTM-based stacks (e.g., xLSTM[7:1]) leverages sLSTM's mixing capabilities while preserving overall parallel efficiency.

The trade-offs are explicit: sLSTM provides stronger sequential expressivity at the cost of reduced parallelizability. Thus, if the primary requirement is maximal throughput on very long contexts where parallelism dominates, then an mLSTM-based or other parallelizable block might be preferable. If the problem requires nuanced, cross-temporal interactions, state updates and revisions, or robust handling of structured sequential dependencies, sLSTM blocks are the right tool.

In summary, use sLSTM blocks when you need scalar-cell memory semantics with interpretability, the capacity to revise stored contents aggressively via exponential gating, and the modeling power of recurrent memory mixing; be prepared for a sequential computational pattern that demands optimized kernels for competitive wall-clock performance.

# Concluding remarks

sLSTM preserves scalar-cell intuitions from classical LSTM while extending them in two critical ways: exponential gating (with algebraic stabilization) and an explicit normalizer that produces a readout interpretable as a weighted average of past inputs. When extended to multiple cells and organized into heads, sLSTM yields a flexible memory-mixing substrate that is particularly effective for state-tracking and tasks that require revising stored information. The principal practical drawback is the lack of straightforward parallelization, but the paper demonstrates that careful CUDA implementation makes sLSTM competitive in practice and useful as a component in the mixed xLSTM architectures.

mLSTM: Matrix Memory with Covariance Updates

# Matrix memory C_t and covariance update rule

The central idea of the mLSTM is to replace the scalar LSTM cell with a matrix memory that can store many more degrees of freedom per time step. Instead of a scalar cell state $c_t \in \mathbb{R}$, mLSTM maintains a matrix memory
$\mathbf{C}_t \in \mathbb{R}^{d\times d}$. Information is written into this memory by outer-product (covariance) updates and is retrieved by multiplying the memory with a query vector. The forward update for the matrix memory is written in compact form as

\[
\mathbf{C}_t \;=\; f_t \,\mathbf{C}_{t-1} \;+\; i_t \,\mathbf{v}_t \mathbf{k}_t^\top,
\]

where $i_t$ and $f_t$ are scalar input and forget gates (discussed below), $\mathbf{k}_t$ is the key vector and $\mathbf{v}_t$ the value vector for the current input. The new term $\mathbf{v}_t \mathbf{k}_t^\top$ is an outer product: it inserts into the matrix memory an association between $\mathbf{k}_t$ (the addressing key) and $\mathbf{v}_t$ (the stored content). The forget gate $f_t$ multiplies the previous memory, acting as a multiplicative decay.

Intuitively, each outer product adds a rank-one contribution to the memory that encodes the covariance between elements of the stored key and value. Over time, the memory accumulates many such outer products, so that when a query $\mathbf{q}$ later appears, the matrix-vector product $\mathbf{C}\mathbf{q}$ sums the contributions of past values, each weighted by the similarity between the corresponding key and the query. Because the memory is matrix-valued, retrieval is not limited to a single scalar per cell; instead the matrix can encode complex relationships across $d$ dimensions, enabling much higher effective storage capacity than scalar cells.

# Key, value, and query projections (with scaling for keys)

To interface input vectors $\mathbf{x}_t$ with the matrix memory, mLSTM computes three linear projections: a query $\mathbf{q}_t$, a key $\mathbf{k}_t$, and a value $\mathbf{v}_t$. In the formulation used in the paper these are

\[
\mathbf{q}_t \;=\; \mathbf{W}_q \mathbf{x}_t + \mathbf{b}_q,
\qquad
\mathbf{k}_t \;=\; \frac{1}{\sqrt{d}}\,\mathbf{W}_k \mathbf{x}_t + \mathbf{b}_k,
\qquad
\mathbf{v}_t \;=\; \mathbf{W}_v \mathbf{x}_t + \mathbf{b}_v.
\]

The key projection includes an explicit scaling factor $1/\sqrt{d}$. This scaling is important to keep the typical magnitude of key–query dot products approximately constant as the dimensionality $d$ changes. Without this normalization, the dot products that determine how much each stored outer product contributes to a retrieval could grow with $d$, destabilizing the retrieval denominator and gradients. The same $q,k,v$ terminology mirrors the Transformer vocabulary and clarifies the roles: keys determine where to write in memory (addressing), values are what is written, and queries are how stored information is read back.

# Normalizer vector and denominator stabilization (max of absolute dot and threshold)

When retrieving from the matrix memory, mLSTM forms an unnormalized retrieval vector by multiplying the memory with the query:

\[
\tilde{\mathbf{h}}_t \;=\; \mathbf{C}_t \mathbf{q}_t.
\]

To convert this into a stable, scale-invariant retrieved signal, mLSTM divides by a scalar normalizer formed from the past keys. The normalizer state is itself a vector that accumulates keys with the same gating dynamics used for the matrix:

\[
\mathbf{n}_t \;=\; f_t\,\mathbf{n}_{t-1} \;+\; i_t\,\mathbf{k}_t.
\]

The retrieval then uses the (absolute) dot product between the normalizer and the query as the denominator. To avoid division by very small numbers, the denominator is stabilized by taking the absolute value and lower-bounding it with a threshold (the paper uses a threshold of at least 1.0). Concretely,

\[
\tilde{\mathbf{h}}_t \;=\; \frac{\mathbf{C}_t \mathbf{q}_t}{\max\bigl\{\,|\mathbf{n}_t^\top \mathbf{q}_t|,\,1\,\bigr\}} .
\]

This denominator does two things. First, $\mathbf{n}_t^\top \mathbf{q}_t$ measures the total effective “addressing strength” that past keys have for the current query; dividing by it normalizes the retrieved vector relative to the total stored mass addressed by $\mathbf{q}_t$. Second, taking the absolute value prevents cancellation when some keys are negatively correlated with the query, and the lower bound prevents numerical explosion of the normalized retrieval if the addressing strength is near zero. This stabilization is necessary because the dot product can indeed be close to zero, especially when keys are zero-mean (the model applies layer-norm before key/value projections), and such near-zero denominators would otherwise produce very large fluctuations in the hidden state.

# Gating roles: input as learning rate, forget as decay, output as retrieval scaling

Gates in mLSTM retain the same conceptual roles as in scalar LSTMs, but their interpretation in the matrix-memory setting is particularly clean. The three scalar gates are:

- input gate $i_t$ (often using an exponential activation),
- forget gate $f_t$ (either sigmoidal or exponential), and
- output gate $\mathbf{o}_t$ (a vector gate applied elementwise to the retrieved vector).

In the matrix update

\[
\mathbf{C}_t = f_t\,\mathbf{C}_{t-1} + i_t\,\mathbf{v}_t\mathbf{k}_t^\top,
\]

the input gate $i_t$ plays the role of a learning rate: it controls how strongly the current outer product is added to the memory. A small $i_t$ means the current key–value pair contributes little; a large $i_t$ causes a strong write. The forget gate $f_t$ acts as a decay factor on the whole memory, analogous to a per-step multiplicative forgetting; $f_t<1$ progressively attenuates older contributions. Together, $i_t$ and $f_t$ implement a gated online local learning rule for the memory matrix: each step the previous memory is decayed and a new rank-one update is added with weight $i_t$.

Retrieval is controlled by the output gate $\mathbf{o}_t$, which scales the normalized retrieval elementwise:

\[
\mathbf{h}_t = \mathbf{o}_t \odot \tilde{\mathbf{h}}_t,
\qquad
\tilde{\mathbf{h}}_t = \frac{\mathbf{C}_t \mathbf{q}_t}{\max\bigl\{|\mathbf{n}_t^\top \mathbf{q}_t|,1\bigr\}}.
\]

Thus $\mathbf{o}_t$ can modulate which components of the retrieved vector are exposed to subsequent layers. In summary: $i_t$ = write strength / learning rate, $f_t$ = memory decay, and $\mathbf{o}_t$ = retrieval scaling / selective exposure.

# Connections to Bidirectional Associative Memories and fast weight programmers

The covariance (outer-product) update in mLSTM is a direct instantiation of classical associative memory ideas. The outer-product rule aligns with Bidirectional Associative Memories (BAMs), where associations between two vectors are stored as outer products so that one can retrieve the partner given the other. In mLSTM, each key–value pair $(\mathbf{k}_t,\mathbf{v}_t)$ is stored as the rank-one matrix $\mathbf{v}_t\mathbf{k}_t^\top$, so that later multiplying by a query approximating the key produces a sum of corresponding values.

This update rule is also conceptually equivalent to Fast Weight Programmers: fast (short-lived) weights are updated online by outer products of incoming activations, enabling the network to “program” a temporary associative memory that later influences computation. Interpreting $f_t$ as decay and $i_t$ as a learning rate connects the mLSTM dynamics directly to these earlier formulations: the memory accumulates fast-weight outer products while being multiplicatively decayed, and retrieval is a weighted sum across these fast-weight contributions.

Importantly, the paper emphasizes that, under reasonable assumptions (e.g., zero-mean keys), the covariance update is optimal for maximizing separability of retrieved binary vectors in the sense of signal-to-noise, as described classically. That theoretical grounding explains why outer-product memories are a principled way to pack associations into a fixed-size matrix memory.

# Gate stabilization via m_t as in sLSTM

A distinctive choice in mLSTM is the use of exponential gates for at least the input gate (and optionally the forget gate). Exponential activations allow gates to represent multiplicative factors outside the $[0,1]$ interval and are what enable the input gate to act effectively as a positive learning rate. However, exponentials can easily overflow if their preactivations become large. To prevent numerical instabilities while preserving exact functional equivalence, the paper adopts the stabilizer state $m_t$ introduced for sLSTM. The stabilizing recurrences are

\[
m_t \;=\; \max\bigl(\log(f_t) + m_{t-1},\; \log(i_t)\bigr),
\]

\[
i'_t \;=\; \exp\!\bigl(\log(i_t) - m_t\bigr) \;=\; \exp(\tilde{i}_t - m_t),
\qquad
f'_t \;=\; \exp\!\bigl(\log(f_t) + m_{t-1} - m_t\bigr).
\]

Replacing $i_t$ and $f_t$ by their stabilized versions $i'_t$ and $f'_t$ in the forward pass prevents intermediate exponentials from overflowing; crucially, this reparameterization is algebraically equivalent to the original dynamics and preserves gradients with respect to parameters. This trick permits aggressive exponential gating behavior (useful for flexible learning/decay rates) while maintaining numerical safety during training.

# Parallel reformulation (scan) and absence of memory mixing

A key architectural distinction of mLSTM versus the original LSTM is the absence of memory mixing via hidden-to-hidden recurrent weight matrices. In the mLSTM formulation provided in the paper, the gate preactivations and key/value/query projections depend only on the current input (and biases), not on the previous hidden state. Concretely, the mLSTM gate preactivations are functions of $\mathbf{x}_t$ only (no $r\cdot h_{t-1}$ terms). Because of this lack of hidden-hidden mixing, the temporal recurrence in $\mathbf{C}_t$ and $\mathbf{n}_t$ takes the simple form of a multiplicatively-weighted accumulation:

\[
\begin{aligned}
\mathbf{C}_t &= f_t\,\mathbf{C}_{t-1} + i_t\,\mathbf{v}_t\mathbf{k}_t^\top,\\
\mathbf{n}_t &= f_t\,\mathbf{n}_{t-1} + i_t\,\mathbf{k}_t.
\end{aligned}
\]

These recurrences only depend on scalars $f_t,i_t$ and the current vectors $\mathbf{k}_t,\mathbf{v}_t$, making them amenable to parallel prefix-sum (scan) style algorithms that compute the sequence of cumulative decayed sums in parallel across time steps. In other words, the dependency graph is associative and can be reorganized to exploit parallel hardware, unlike recurrent formulations with dense hidden-to-hidden matrices. The paper observes that this property allows mLSTM to be re-expressed in a parallel form (the implementation details are in the appendix), enabling efficient GPU kernels similar in spirit to optimized implementations of attention (e.g., FlashAttention) or other linearized sequence mechanisms.

Another consequence of the absence of memory mixing is that multiple heads or multiple memory cells are equivalent in mLSTM: there is no recurrent matrix that couples different cells across time, so separable memory blocks operate independently and can be computed in parallel.

# Capacity–compute trade-offs and practical dimensions

The matrix memory of mLSTM delivers much higher expressivity per time step than scalar LSTM cells, but it also brings a clear computational and memory cost: the memory matrix is $\mathbf{C}_t \in \mathbb{R}^{d\times d}$ and each update involves forming and accumulating a $d\times d$ outer product $\mathbf{v}_t\mathbf{k}_t^\top$. Thus the per-step time complexity of the memory update and the retrieval $\mathbf{C}_t\mathbf{q}_t$ is $\mathcal{O}(d^2)$. This is a trade-off: increasing $d$ raises storage capacity (the number of degrees of freedom stored in memory grows quadratically) but increases compute and temporary memory bandwidth requirements substantially.

Two mitigating observations in the paper are important for practice. First, the matrix memory itself does not require additional learned parameters beyond the projection matrices $\mathbf{W}_q,\mathbf{W}_k,\mathbf{W}_v$; the memory is a working state that depends on inputs. Second, the outer-product updates and matrix–vector retrievals are standard dense linear algebra operations that map well to GPU parallelism: although $\mathcal{O}(d^2)$, they can be batched and dispatched efficiently on modern hardware. As a result, the wall-clock impact can be modest if kernels are well optimized. The authors note, however, that their unoptimized mLSTM CUDA kernels were about 4× slower than highly optimized FlashAttention implementations at the time of reporting, indicating scope for further engineering improvements.

In practical architectures, this capacity–compute trade-off suggests choosing $d$ with awareness of both the memory capacity required for the task (longer contexts, many distinct associations favor larger $d$) and the available computational budget. Because the memory accumulation is independent of sequence length in storage (only the matrix size matters), mLSTM has constant memory per layer with respect to context length, which contrasts with Transformers whose caching grows with context length; this can be an advantage for long-context or on-device deployments despite the per-step $d^2$ cost.

--- 

This chapter has explained how mLSTM implements a matrix-valued associative memory via covariance (outer-product) updates, how keys, values and queries interface with that memory (including scaling of keys), how a normalizer and denominator stabilization make retrieval numerically robust, how gates map to learning/decay/retrieval control, how the design connects to associative memory and fast-weight ideas, how exponential gates are stabilized, and how the elimination of hidden-to-hidden mixing enables parallel reformulations at the cost of $\mathcal{O}(d^2)$ compute per step. Together, these elements give mLSTM a powerful memory model suitable for high-capacity sequence modeling when balanced against computational considerations.

xLSTM Blocks and Full Architectures

# Pre-LayerNorm residual backbone (pre-LN) and why it’s used
xLSTM architectures are built from residual blocks arranged in deep stacks. The backbone chosen for these stacks is the pre-LayerNorm (pre-LN) residual backbone: every residual block receives its input after a LayerNorm operation and then adds its (possibly projected) block output back to the input via a residual connection. The paper states that this is the most commonly used residual backbone in contemporary large language model practice and therefore adopts it for xLSTM. In the simplest schematic form, if $\mathbf{x}$ denotes the input to a block, a pre-LN block computes
\[
\mathbf{\hat x} \;=\; \mathrm{LayerNorm}(\mathbf{x}), \qquad
\mathbf{y} \;=\; \mathbf{x} + \mathrm{BlockFn}(\mathbf{\hat x}),
\]
and forwards $\mathbf{y}$ to the next block. This structure makes the non-linear transform act on a normalized point and returns a residual correction to the original input.

Two statements from the paper motivate this choice. First, residually stacking blocks is the standard contemporary practice to build very deep models; second, pre-LayerNorm variants are the backbone used in many existing large models, making them a natural, well-understood choice for fair architectural comparison. Pre-LN also places normalization before the block’s non-linear summarization of history, ensuring that each block sees inputs of controlled scale and statistics, which is important for stable training of deep stacks that contain complex recurrent memory components such as sLSTM and mLSTM.

# Post up-projection blocks for sLSTM (Transformer-like MLP positioning)
sLSTM blocks are embedded into a residual block variant called the post up-projection block. The central idea is that the block first non-linearly summarizes the past in the original (model) space and only thereafter expands into a higher dimensional intermediate space for additional linear operations and pointwise non-linearities. Concretely, a post up-projection block follows the ordering: (1) non-linear summarization in the input dimension, (2) linear up-projection to a larger dimensionality, (3) an activation in that larger space, and (4) linear down-projection back to the input dimensionality before the residual add. This ordering is said to be “like Transformers” in the paper because standard Transformer MLPs similarly perform a non-linearity after an up-projection from model dimension to MLP dimension (and then project back).

This block ordering is the recommended choice when the block contains sLSTM. The reason given in the paper is empirical and architectural: sLSTM’s scalar memory cells and its particular form of memory mixing (recurrent hidden–hidden connections across its scalar cells) are used most effectively when the block first forms a compact, non-linear summary in the model space and then uses a high-dimensional expansion to refine and re-scale that summary. In practice this means that the sLSTM cell (and its gates and stabilizers) operate within or directly adjacent to the portion of the block that works in the model dimensionality, while the up-projection serves as an amplifying transform for the block’s internal computations.

# Pre up-projection blocks for mLSTM (SSM-like high-dimensional summarization)
For mLSTM blocks the paper prescribes the opposite ordering: a pre up-projection architecture. Here, input vectors are first linearly projected up into a higher-dimensional space, then the non-linear summarization (which includes the matrix memory operations of the mLSTM cell) is carried out in that expanded space, and finally the representation is linearly projected back down to the model dimension. The paper motivates this choice by pointing out that the mLSTM’s matrix memory $\mathbf{C}\in\mathbb{R}^{d\times d}$ attains its largest storage capacity when the internal (key, value, query) vectors live in a higher-dimensional coding space. By performing the up-projection before the memory operation, the model leverages a larger internal coding dimension for keys, values, and queries, thereby increasing the effective memory capacity realized by the covariance-style update and retrieval rules.

Symbolically, for input $\mathbf{x}$ a pre up-projection block performs
\[
\mathbf{u} \;=\; \mathbf{W}_{\mathrm{up}} \mathbf{x} + \mathbf{b}_{\mathrm{up}}, \qquad
\mathbf{v} \;=\; \mathrm{mLSTM\text{-}summary}(\mathbf{u}), \qquad
\mathbf{y} \;=\; \mathbf{x} + \mathbf{W}_{\mathrm{down}} \mathbf{v} + \mathbf{b}_{\mathrm{down}},
\]
where the core summarization step uses the matrix-memory and normalization mechanisms of mLSTM. The paper explicitly notes that this construction is “like State Space Models (SSMs)” in the sense that SSMs commonly perform their linear projection to a larger internal state before applying their sequence dynamics; mLSTM follows the same pattern because its matrix memory benefits from working in a larger coding dimension.

# Cover’s Theorem motivation for up-projection
Cover’s Theorem is invoked in the paper as the conceptual justification for the up-projection idea used in both kinds of block designs. The theorem, in the form referenced, states that a non-linear mapping into a higher-dimensional space increases the likelihood that different histories (different pasts) become linearly separable. For sequential modeling, better separability of distinct histories is directly linked to the model’s ability to predict the next token: if different pasts map to linearly separable regions, a simple output layer can discriminate them and produce accurate next-token predictions.

Up-projection implements this principle by temporarily increasing the dimensionality in which a block summarizes the past. Whether the up-projection is placed before the non-linear summarization (pre up-projection) or after it (post up-projection), the intent is to carry out the block’s most expressive non-linear computations in or adjacent to an expanded space that is more likely to separate distinct contexts. For mLSTM the pre up-projection is preferred because the matrix memory benefits directly from larger key and value dimensions; for sLSTM the post up-projection places the block’s non-linear summary in model space and uses the up-projection as a later, higher-dimensional refinement. In both cases, Cover’s Theorem provides the underlying intuition: a higher-dimensional non-linear embedding facilitates separability of contexts and therefore improves next-token discrimination.

# Stacking strategy and block ratio selection (xLSTM[a:b])
xLSTM architectures are built by residually stacking many xLSTM blocks. Each block is either an mLSTM-based block (pre up-projection) or an sLSTM-based block (post up-projection). The paper introduces a compact notation xLSTM[a:b] to indicate the ratio of mLSTM-based to sLSTM-based blocks in the stack. More precisely, xLSTM[$a$:$b$] denotes that of each group of $(a+b)$ blocks, $a$ are mLSTM blocks and $b$ are sLSTM blocks; when the total number of blocks is $N$, this ratio determines how many blocks of each type are included. For example, xLSTM[7:1] means that in each run of eight blocks, seven are mLSTM blocks and one is an sLSTM block; with $N=48$ total blocks this corresponds to 42 mLSTM blocks and 6 sLSTM blocks.

The paper reports experiments with different ratios and finds that mixed stacks (both types present) can leverage complementary strengths: mLSTM contributes high-capacity, parallelizable matrix memories that improve rare-token prediction and long-range retrieval, while sLSTM contributes scalar-memory cells with memory mixing (hidden–hidden recurrent connections) that support state tracking and tasks that require revision of stored information. The stacking strategy is therefore a design knob: increasing $a$ (more mLSTM blocks) emphasizes high-capacity parallel memories; increasing $b$ (more sLSTM blocks) preserves more memory-mixing capacity. The recommended practice in the paper’s experiments is to choose ratios based on task needs and resource constraints; xLSTM[1:0] and xLSTM[7:1] are two of the configurations evaluated in the large-scale experiments.

# Embedding layers, normalization, and output heads
An xLSTM model begins with token embedding layers that map discrete tokens to continuous model vectors. These embeddings provide the initial inputs $\mathbf{x}_t$ to the stacked pre-LN residual blocks. Within the mLSTM blocks, the paper explicitly assumes a LayerNorm before projecting inputs to keys and values: this pre-projection normalization centers and rescales the inputs so that the key and value projections produce zero-mean vectors, which is important for the covariance-style update used in the matrix memory. Thus, two places where normalization is highlighted are the global pre-LayerNorm applied at each residual block input and the layer normalization before key/value projection in mLSTM internals.

On the output side, the stacked blocks ultimately feed into an output head that maps the model vector to token logits for next-token prediction. In large language model practice these logits are converted into next-token probabilities via a softmax and evaluated by perplexity; the paper notes that in its comparisons most models use conventional untied token embeddings and output heads, while GPT-3 (as a reference) used tied token and output embeddings and therefore had slightly fewer parameters. In short, xLSTM follows the standard encoder-to-logits pipeline: token embeddings → pre-LN residual stack of xLSTM blocks → output linear mapping to vocabulary logits (with softmax during evaluation).

Internally, the sLSTM and mLSTM cells also maintain auxiliary internal states that are normalized or stabilized. sLSTM uses a normalizer state $n_t$ and a stabilizer $m_t$ to avoid numerical overflows when exponential gates are used; mLSTM has a normalizer vector $\mathbf{n}_t$ that accumulates weighted sums of keys and is used to normalize retrieved vectors by their projected magnitude. These internal normalizers are essential to maintain numerical stability and to make the exponential input gates usable in practice.

# Auto-regressive training objective and teacher forcing
The xLSTM architectures are trained in an auto-regressive next-token prediction setting: the model learns to predict the next token given the past tokens. Concretely, given a sequence of tokens $(w_1, w_2, \dots, w_T)$ and their embeddings $(\mathbf{x}_1, \mathbf{x}_2, \dots, \mathbf{x}_T)$, the stacked xLSTM produces a sequence of hidden outputs $(\mathbf{h}_1, \mathbf{h}_2, \dots, \mathbf{h}_T)$ which are mapped to vocabulary logits and probabilities. Training minimizes the negative log-likelihood (next-token loss) summed over positions:
\[
\mathcal{L} \;=\; -\sum_{t=1}^{T} \log p(w_{t} \mid w_{<t}; \theta),
\]
where the conditional probability $p(w_t\mid w_{<t};\theta)$ is produced by the softmax over output logits computed from the model-hidden vector at time $t$. The paper describes training all compared models "in the same auto-regressive setting" for fairness; evaluation is performed by computing validation perplexity and downstream metrics derived from the trained conditional probability model.

The architecture and objective together imply the usual auto-regressive operational mode during inference: at generation time the model conditions on prior generated tokens to produce the next-token distribution; during training the model is supplied with the true past tokens (the ground-truth prefix) so that the parameters are learned to maximize next-token likelihood under the observed data distribution. (This training paradigm—feeding the past context from data during parameter updates—is the standard auto-regressive next-token framework used in the experiments.)

# Closing remarks on block composition and architecture design
Putting the pieces together, a full xLSTM model is instantiated by choosing a model dimension, a block structure (pre-LN residual backbone), a total number of blocks $N$, and a ratio xLSTM[$a$:$b$] that determines how many blocks are mLSTM vs. sLSTM. Within each block the appropriate up-projection ordering (pre for mLSTM, post for sLSTM) is employed so that the block’s non-linear summarization and memory primitives operate in the dimensionality that best suits them. Token embeddings feed into the stacked blocks; LayerNorms and internal normalizers stabilize both block inputs and memory internals; an output head converts the final representations to logits for the auto-regressive next-token objective. This modular construction permits trading off parallelizability and raw memory capacity (favoring mLSTM) against recurrent memory mixing and state-tracking expressivity (favoring sLSTM), and the xLSTM[$a$:$b$] notation provides a compact way to express different design points evaluated in the paper.

Computation and Memory: Complexity, Parallelism, and Throughput

# Time and memory complexity vs sequence length

Analyzing a sequence model requires two complementary resources: the time (compute) it needs to process a sequence of length $T$, and the working memory it needs during that processing. The xLSTM family (sLSTM and mLSTM) was designed with these constraints in mind and, as described in the paper, exhibits fundamentally different scaling behavior with respect to the sequence length than standard Transformer attention.

For an xLSTM architecture the operations that depend on the sequence length are the recurrent updates performed once per token. Because each token produces a bounded number of algebraic updates to the internal memory, the total computation over a sequence of length $T$ grows linearly in $T$. We can summarize this as
- time complexity over a sequence: $O(T \cdot C)$,
- memory complexity with respect to $T$: constant (independent of $T$),

where $C$ denotes the per-step computational cost that depends on the internal state dimension(s) but not on $T$. The paper emphasizes that xLSTM networks therefore have linear computation and constant memory complexity with respect to the sequence length.

To make the dependence on model dimension explicit for the two xLSTM variants: mLSTM maintains a matrix memory of size $d \times d$, and the dominant per-step operations are an outer-product update and a matrix–vector retrieval. These scale as $O(d^2)$ per step, so the total time over a sequence of length $T$ is
- for mLSTM: time $O(T d^2)$ and memory $O(d^2)$ (constant in $T$).

sLSTM, like many scalar-cell recurrent models, has per-step cost that is dominated by vector–matrix products and recurrent mixing; these are also on the order of $O(d^2)$ per step in practice, giving total time $O(T d^2)$ and memory that is constant in $T$ (though the exact constant differs from mLSTM because sLSTM stores scalar cells rather than a dense matrix).

By contrast, standard Transformer attention (as used in training) builds pairwise token interactions that make its compute and working-memory costs grow quadratically with the context length. Informally,
- Transformers (attention): compute and working-memory cost grow as $O(T^2)$ (quadratic in $T$),

which is the central reason why Transformers become costly on very long contexts. The xLSTM design deliberately avoids this quadratic dependence by keeping an internal, compressive memory that does not grow with $T$.

# Comparison to attention (quadratic in context length) and KV caches

Transformer attention incurs an explicit quadratic dependence on the context length when computing pairwise attention weights between tokens; this is the classic bottleneck that motivates many linearized attention and SSM approaches. The paper contrasts this with xLSTM’s constant-in-$T$ memory and linear-in-$T$ compute.

In generation (autoregressive decoding) Transformers typically use a key–value (KV) cache: previously computed keys and values are stored so the model does not recompute them, which reduces recomputation but still increases working memory with the number of past tokens. The paper’s inference experiments mention using a static key–value cache for the Llama Transformer baseline. Even with a KV cache, the Transformer’s working memory grows with the number of cached tokens and that growth constrains the batch sizes and throughput usable in decoding. In the experimental comparison reported, this manifests as markedly different wall-clock scaling: the paper shows that xLSTM and other recurrent models have approximately linear increases in generation time as the context grows, while the Transformer (Llama) shows a quadratic trend in the same experiment (Figure referenced in the paper). Practically, the paper reports that, for batch size 1 and a 16-token prefill, recurrent models (including xLSTM) scale linearly and are more favorable for long generation contexts, while the Transformer’s quadratic nature becomes the limiting factor.

A key operational consequence is throughput under constrained device memory: because xLSTM memory is constant in $T$, it can admit much larger decoding batch sizes than the Transformer implementation used in the experiments and thus achieve higher maximal throughput. The paper’s measurements report that xLSTM achieves the highest throughput and can use much higher batch sizes than Llama precisely because of this constant-memory property.

# Matrix memory compute patterns (d by d) and parallelization

mLSTM elevates the scalar LSTM cell to a matrix memory $\mathbf{C}_t \in \mathbb{R}^{d\times d}$. The forward-update equations that determine the per-step compute in mLSTM are:

\[
\mathbf{C}_t \;=\; f_t \, \mathbf{C}_{t-1} \;+\; i_t \, \mathbf{v}_t \, \mathbf{k}_t^\top,
\]
\[
\tilde{\mathbf{h}}_t \;=\; \frac{\mathbf{C}_t \, \mathbf{q}_t}{\max\{|\mathbf{n}_t^\top \mathbf{q}_t|, 1\}},
\qquad
\mathbf{h}_t \;=\; \mathbf{o}_t \odot \tilde{\mathbf{h}}_t,
\]
together with the normalizer update
\[
\mathbf{n}_t \;=\; f_t \, \mathbf{n}_{t-1} \;+\; i_t \, \mathbf{k}_t.
\]

From these equations the dominant low-level linear-algebra kernels are clear:
- a scalar scale of the previous matrix: $f_t \, \mathbf{C}_{t-1}$ (a scaled copy of a $d\times d$ matrix),
- an outer product addition: $i_t \, \mathbf{v}_t \, \mathbf{k}_t^\top$ (rank-1 update),
- a matrix–vector multiply for retrieval: $\mathbf{C}_t \, \mathbf{q}_t$ (a dense $d\times d$ times a $d$-vector),
- a small vector dot product for normalizer-based scaling.

Each such kernel is standard linear algebra: the outer-product update is $O(d^2)$ and the matrix–vector product is also $O(d^2)$ in arithmetic. Crucially, these operations do not involve explicit, per-token growth in stored state: the single matrix $\mathbf{C}_t$ is updated in place and its size is fixed to $d^2$, so memory does not scale with the number of tokens processed.

These kernels map well to GPU hardware because they are dense, regular, and parallelizable. The outer-product update and the matricial retrieval can be implemented using parallel matrix kernels (e.g., batched matrix–vector or rank-1 updates) and can leverage highly optimized BLAS-like primitives or custom CUDA kernels. The paper underlines this; it states that mLSTM is "fully parallelizable" and its computations can be done in parallel on GPUs, so the wall-clock overhead becomes modest despite the $d^2$ arithmetic.

There is a trade-off implied by this design: the matrix memory increases the expressive storage capacity compared to scalar-cell LSTMs (allowing richer associative memory), but it also raises the per-step arithmetic cost from vector-scale operations to dense $d\times d$ arithmetic. The paper frames this explicitly as a trade between memory capacity and computational complexity.

# sLSTM vs mLSTM runtime and batching characteristics

sLSTM and mLSTM differ sharply in two respects that affect runtime and batching:

1. Parallelizability. sLSTM retains memory mixing via recurrent (hidden-to-gate) connections between time steps. These hidden–hidden dependencies enforce an inherently sequential dependency: the computation at time $t$ uses information computed at time $t-1$ in a way that cannot be algebraically flattened into a single parallel matrix update across time steps. Consequently, sLSTM is not directly parallelizable over tokens in the same way as mLSTM. The paper therefore treats sLSTM as sequential and notes that it cannot use the same kind of parallel reformulation that makes mLSTM amenable to parallel GPU kernels.

2. Practical runtime and kernel engineering. Despite sLSTM’s sequential nature, the authors implemented a highly optimized CUDA kernel with GPU memory optimizations at the register level, achieving a runtime that is typically less than two times slower than their parallel mLSTM implementation. This indicates that careful low-level engineering can mitigate some of the sequential-model runtime penalties. On the other hand, the mLSTM implementation in the paper was not fully kernel-optimized; the authors report that their current mLSTM implementation is about four times slower than FlashAttention or the scan implementation used in Mamba. The key takeaway is that algorithmic parallelizability (mLSTM) puts a method in the same class as attention in terms of being able to exploit high-performance kernels, but the realized wall-clock performance depends heavily on kernel optimization effort.

Batching behavior follows from the above. Because mLSTM computations for different tokens and batches can be expressed as dense matrix operations, they are straightforward to batch: multiple sequences can be handled in the same kernel launch with typical GPU throughput benefits. sLSTM’s sequential dependence means it is harder to fully exploit cross-token parallelism, but per-batch parallelism across independent sequences remains possible, and register-level optimizations can make its per-step latency small enough that batch throughput is still competitive. The experiments in the paper show that, in practice, the optimized sLSTM kernel is within a relatively small constant factor of the mLSTM wall-clock time.

# Length extrapolation and large-batch decoding advantages

Two practical consequences of xLSTM’s constant-in-$T$ memory and linear-in-$T$ compute are (1) stable extrapolation to longer contexts at inference time and (2) favorable decoding throughput when generation batch sizes are scaled.

Length extrapolation: The paper presents language-modeling experiments where models trained with a context length of 2048 were evaluated at much longer contexts (up to 16384). xLSTM models maintained low perplexities out to these longer contexts, outperforming the other compared models in this extrapolation test. Because the xLSTM internal memory does not grow with $T$, increasing the context window at inference time does not inflate the working memory footprint nor force recomputation of an ever-growing attention matrix; this helps maintain both accuracy and practical feasibility when using long contexts.

Decoding throughput and batch sizing: In generation, practical throughput depends not only on arithmetic per token but also on how much device memory is needed for the model state and any cached context. The paper reports that xLSTM can use much larger decoding batch sizes than the Transformer baseline in their experiments because xLSTM’s memory does not grow with the context length. This enables higher decoding throughput: in the reported experiments xLSTM achieves the highest throughput and can make efficient use of larger batch sizes, while the Transformer baseline is constrained by the KV cache and attention memory growth, which caps the practical batch size and thus reduces throughput. The generation-time plots in the paper show linear runtime scaling for xLSTM and other recurrent models and quadratic scaling for Llama (Transformer), which reinforces the noted practical advantages for long-context generation and high-throughput decoding.

# Implementation pathways toward FlashAttention-like kernels

The paper points to clear engineering directions for improving xLSTM’s wall-clock performance, especially for mLSTM: because the mLSTM core operations are standard dense linear algebra (rank-1 updates, matrix–vector products, scalings), there is an opportunity to implement highly optimized, fused CUDA kernels in the spirit of FlashAttention and other attention-optimized approaches. The authors explicitly state that mLSTM "is parallelizable analog to FlashAttention or GLA" and that "faster CUDA kernels could be obtained in the vein of FlashAttention."

Concretely, the engineering opportunities the paper suggests are:
- Reformulate the mLSTM recurrence into a parallel version that expresses batches of outer-product updates and matvec retrievals in large, fused GPU kernels. The paper notes that because mLSTM has no memory mixing across time steps, the recurrence admits such a parallel reformulation.
- Implement fused kernels that combine scaling, rank-1 update accumulation, and retrieval into single passes to reduce memory traffic and kernel-launch overhead; these are the same high-level ideas that make FlashAttention fast for attention.
- For sLSTM, leverage register-level and memory-layout optimizations for the sequential scan (as the authors did) to reduce latency per step; highly tuned sequential kernels can narrow the gap with parallel implementations.

The paper documents a current state where mLSTM is already parallel in principle but the available kernels are not yet optimized (about four times slower than FlashAttention in their tests), while the sLSTM benefits from a specialized CUDA kernel that brings its runtime close to mLSTM's. This highlights that further kernel-level work—both for the dense matrix operations of mLSTM and for the optimized sequential scan of sLSTM—can materially change the practical trade-offs between these variants.

# Summary: trade-offs, where xLSTM fits, and practical guidance

xLSTM offers a distinct operating point among sequence models:

- Complexity vs. sequence length: xLSTM is linear in time and constant in working memory with respect to the sequence length $T$, while attention-based Transformers are quadratic in $T$ during training and require increasing working memory when using KV caches in generation.
- Capacity vs. per-step cost: mLSTM trades a larger per-step compute cost ($O(d^2)$ arithmetic due to a $d\times d$ matrix memory) for greater storage capacity and fully parallelizable kernels; sLSTM keeps scalar cells and memory mixing, which helps expressivity but imposes sequential dependencies that complicate parallelization.
- Practical performance depends on kernel engineering: With optimized kernels (the “FlashAttention-like” path), mLSTM can realize its parallel-computation potential and close the wall-clock gap to attention. Meanwhile, a well-engineered sequential kernel for sLSTM can make it only modestly slower in practice (the paper reports sLSTM less than two times slower than their mLSTM implementation).

In short, xLSTM’s constant-memory, linear-time design gives it practical advantages for long-context inference and high-throughput decoding, and its matrix-memory mLSTM variant is particularly amenable to further performance gains via dedicated GPU kernel engineering. The experiments reported in the paper already demonstrate these practical benefits: xLSTM maintains extrapolation performance to long contexts, exhibits linear generation-time scaling (versus quadratic for Llama), and attains higher decoding throughput because it can utilize larger batch sizes thanks to constant memory usage.

Related Methods and Conceptual Connections

# Linear attention approaches: Synthesizer, Linformer, Performer, Hyena, GLA
A central motivation behind linear-attention methods is to remove the quadratic dependency on context length that standard Transformer attention introduces. The paper groups several lines of work under this umbrella and describes them as different strategies for approximating or replacing the full token–token dot-product softmax attention while keeping the Transformer-style computation graph.

Synthesizer replaces learned token-token interactions by synthetic attention weights that do not depend on pairwise token comparisons. Linformer projects the attention matrix into a low-rank factorization so that attention can be computed with linear complexity in the sequence length. Performer obtains a linearized attention by replacing the softmax kernel with a positive-random-feature approximation so that attention becomes a sum of feature maps and thus linear in context length. Hyena departs from attention entirely by using structured global convolutions (long convolutions) to capture long-range dependencies; in the paper Hyena is presented as another route to linear complexity. Gated Linear Attention (GLA) incorporates gating into linear attention mechanisms to modulate contributions across the sequence.

What unites these methods in the paper’s treatment is the objective of achieving scalability to long contexts by changing the way tokens interact: either by approximating the softmax attention kernel, by low-rank compression, by replacing token–token comparisons with learned or structured filters, or by using gating to reweight contributions. These approaches are contrasted with xLSTM’s strategy: xLSTM does not rely on explicit pairwise attention during inference but instead embeds long-term storage and retrieval mechanisms into recurrent memory structures (scalar or matrix) that are linear in context length and—when designed appropriately—parallelizable.

# State Space Models: S4, DSS, S5, H3, Mamba, BiGS
State Space Models (SSMs) are another family of approaches the paper highlights as recent and popular alternatives to full attention. The SSM line (including S4, DSS, S5, H3 and related variants) achieves linearity in the context length by modeling sequence dynamics via linear state-space recurrences that can be implemented efficiently with structured kernels or specialized discretizations. These models typically embed the input sequence into a latent linear dynamical system whose impulse response can be convolved with the inputs to produce outputs; because convolutions can be implemented with linear cost (often with FFTs, kernel structure, or recurrence tricks), SSMs scale to long contexts.

The paper treats Mamba as a high-performing SSM variant; BiGS and related gated SSM variants introduce gating to combine linear state evolution with multiplicative control, thereby increasing flexibility. The SSM family is presented as a complementary route to long-context modeling: like linear attention and unlike standard Transformers, SSMs are asymptotically linear in the context length and have been shown to be competitive on language modeling and long-range tasks.

Within the paper’s scope, SSMs are contrasted with RNNs and xLSTM in two respects. First, SSMs generally do not include memory mixing of the recurrent hidden–hidden type used in classical LSTM; second, the paper argues that this lack of memory mixing constrains state-tracking expressivity in some tasks. Empirically, the paper compares xLSTM to leading SSMs (e.g., Mamba, H3) and finds that xLSTM performs favorably, while noting conceptual differences in how histories are represented and mixed.

# RNN alternatives: LRUs, HGRN/HGRN2, RWKV
The recent revival of recurrent architectures is represented in the paper by several models that seek to combine the efficiency of recurrence (linear in context length) with modern scaling and training practices. Deep Linear Recurrent Units (LRUs) are one such direction; they preserve linear recurrence in specially designed linear submodules and showed promising language-modeling results in prior work. HGRN and HGRN2 introduce hierarchical gating structures inside RNNs to control information flow at multiple time scales. RWKV is a particularly noteworthy family: it is an RNN-style model whose update rule, when implemented carefully, yields efficient long-context behavior competitive with Transformers. The paper cites RWKV variants (RWKV-4, RWKV-5, RWKV-6) as empirical baselines in comparisons.

These RNN-based approaches are linked in the paper to xLSTM by common desiderata: linear complexity in context length and strong gating mechanisms. Yet the paper emphasizes structural differences. Some modern RNNs trade away certain LSTM traits (for example, recurrent hidden–hidden mixing) to achieve parallelization or other computational benefits; RWKV in particular exemplifies how an RNN-like recurrence can be reformulated for improved runtime behavior. xLSTM situates itself among these approaches by offering two complementary variants: sLSTM, which retains recurrent memory mixing and introduces exponential gating; and mLSTM, which adopts a matrix memory and a covariance-style update rule permitting a parallel reformulation. Thus, xLSTM bridges classical LSTM expressivity (via memory mixing) and the parallel/linear-time aims of modern RNNs.

# Gating as a unifying principle across architectures
A recurring theme emphasized in the paper is that gating—originally central to LSTM’s success—is a unifying and powerful mechanism that has been rediscovered across many modern architectures. The paper explicitly lists HGRN, HGRN2, GLA, GSS (gated SSMs), BiGS, MEGA, RWKV, and Mamba as recent models that incorporate gating in various forms. In xLSTM, gating is taken further: the authors introduce exponential gating (replacing sigmoid gating for some gates) and pair it with stabilization and normalization to enable stronger, more flexible modulation of memory updates.

Intuitively, gating supplies a multiplicative control on how past representations are preserved, forgotten, or combined with new inputs. In LSTM the gates (input $i_t$, forget $f_t$, output $o_t$) enter the canonical update c_t = f_t c_{t-1} + i_t z_t and govern additive memory dynamics. The paper argues that modern models sustain this insight: even when attention, convolution, or linear state-space kernels are used, gating is often reintroduced to selectively control contributions across time steps or feature channels. What differs across models is the form of the gate (additive vs. multiplicative, sigmoid vs. exponential), where in the computation graph it is applied, and whether gates depend on hidden state, input, or both. xLSTM’s exponential gates—together with a normalizer that tracks cumulative gate strength—are presented as a principled extension that remedies specific LSTM limitations (notably the inability to revise previously stored content) while preserving the benefits of multiplicative control.

# Covariance-based updates in RetNet, Linear Transformer, RWKV, HGRN2
The paper highlights a shared lineage of ideas centered on covariance or outer-product-based memory updates. The mLSTM’s matrix memory uses the covariance (outer product) update rule

\[
\mathbf{C}_t \;=\; f_t \mathbf{C}_{t-1} \;+\; i_t \,\mathbf{v}_t \mathbf{k}_t^\top,
\]

which the authors relate directly to earlier notions of Bidirectional Associative Memories and to Fast Weight Programmers. This update stores associations between keys $\mathbf{k}_t$ and values $\mathbf{v}_t$ in a single matrix $\mathbf{C}$, enabling retrieval via a matrix–vector product $\mathbf{C}_t \mathbf{q}_t$. The paper notes that with appropriate scaling and gating, this covariance-style memory offers high separability of stored items (high signal/noise) under the assumption of zero-mean keys.

Several recent methods are cited as building on related ideas. Fast Weight Programmers historically used outer-product updates to create short-term associative memories. Contemporary models that exploit similar covariance or linearized attention principles include Linear Transformer variants, Retention, RWKV-5/RWKV-6, and HGRN2. The paper positions mLSTM among these approaches, but with a distinct integration into the LSTM framework: the forget gate acts as a decay on the matrix memory (analogous to weight decay of fast weights), the input gate acts like a learning rate for the new outer product term, and the output gate scales the retrieved vector when producing the hidden state. By framing covariance updates inside a gated recurrent framework, xLSTM connects the associative memory literature with modern gating-enabled sequence models.

# Distinctive feature of xLSTM: memory mixing enables state tracking and expressivity
One of the paper’s central conceptual claims is that “memory mixing”—the hidden–hidden recurrent connections that allow different memory cells to interact across time—is a distinguishing feature that endows recurrent models like LSTMs (and sLSTM) with a form of expressivity not available to many SSMs or vanilla Transformer-like architectures. Memory mixing means that the hidden state at the previous timestep participates directly in computing the current gates and cell inputs via learned recurrent weight matrices; this creates a feedback loop among memory cells that can implement complex state machines and carry persistent, interacting state over arbitrarily long horizons.

The paper supports this claim empirically and conceptually. Empirically, it shows that models lacking memory mixing (e.g., many Transformers and SSMs) fail to solve certain formal-language tasks and regular grammars that require state tracking, such as parity-like problems. Conceptually, it cites recent theoretical and empirical work indicating that RNNs with recurrent inter-cell mixing can represent state machines and carry out stateful computations that are provably or practically more difficult for architectures lacking such mixing. sLSTM retains and extends this capability by combining memory mixing with exponential gating, which improves the ability to revise previously stored information (an explicit failure mode of vanilla LSTM discussed in the paper). mLSTM, in contrast, drops memory mixing in order to attain a fully parallelizable update rule based on matrix memories; the paper emphasizes that while mLSTM sacrifices inter-cell mixing, it gains much larger per-step storage capacity via the matrix $\mathbf{C}_t$ and can be implemented with parallel operations analogous to linear attention.

Thus, the paper positions xLSTM not as a mere rehash of earlier linear or gated architectures but as a deliberate family that spans a design space: sLSTM sits closer to classical LSTM with enhanced gating and preserved memory mixing (for state-tracking power), while mLSTM sits closer to associative fast-weight models with high-capacity, parallelizable matrix memories. By combining these two variants within a residual, block-stacked architecture (xLSTM blocks and xLSTM architectures), the design aims to capture the best of both worlds—stateful mixing where needed and large parallel associative memory where beneficial—while leveraging gating as the organizing principle.

# Synthesis: how the literature connects to xLSTM’s design choices
Taken together, the survey in the paper reveals recurring motifs across modern sequence models: the importance of gating, the desire to achieve linear complexity in context length, and the use of associative or covariance-style memories to increase storage capacity. Linear attention methods and SSMs focus on computation and scaling, often approximating or replacing token–token interactions with cheaper operations; modern RNN variants concentrate on efficient recurrences and gating; and covariance-based updates reconnect to an older line of associative memory research that is proving useful again in large-scale models.

xLSTM is presented in the paper as an integrative response to this landscape. It adopts exponential and stabilized gates (extending the long-standing LSTM gating idea), introduces a matrix covariance memory to boost storage capacity (linking to fast weights and linearized attention ideas), and retains the option of memory mixing (preserving the state-tracking expressivity of classical recurrent networks). Where other methods emphasize one axis (speed/parallelism, low-rank approximations, or gating for control), xLSTM explicitly designs two complementary variants—sLSTM for mixing-driven expressivity and mLSTM for high-capacity, parallel associative memory—then composes them inside residual blocks to achieve competitive performance while drawing on the same conceptual building blocks seen throughout the recent literature.

Experimental Setup and Evaluation Protocols

# Datasets: SlimPajama $15\mathrm{B}$ and $300\mathrm{B}$ tokens
All language-modeling experiments reported in the study use the SlimPajama corpus as the training corpus. Two different training-budget regimes are employed to probe behavior at medium and large data scales: a $15\mathrm{B}$-token regime used for broad method comparison and ablation studies, and a $300\mathrm{B}$-token regime used to evaluate xLSTM as a large language model (LLM). Models trained on the $15\mathrm{B}$ corpus are the primary basis for the controlled comparisons across many architectures (Transformers, State Space Models, RNNs and linear Transformers). The $300\mathrm{B}$ experiments are designed to show how xLSTM variants behave when trained with an LLM-sized data budget and to assess extrapolation, downstream task performance, and scaling laws at larger scale.

Evaluation of models trained on SlimPajama is reported primarily via next-token perplexity on a held-out validation set (referred to throughout as the validation perplexity), and via additional downstream and domain-specific evaluations described later. Where length extrapolation behavior is tested, models are trained on a fixed context length (typically $2048$ tokens) and evaluated at larger context lengths (up to $16384$ tokens) to measure generalization to longer contexts than seen during training.

# Model sizes (125M to $1.3\mathrm{B}$) and block configurations
The experiments examine multiple model sizes to study both absolute performance and scaling behavior. For the large-scale ($300\mathrm{B}$ training tokens) comparison the paper trains model sizes of $125\mathrm{M}$, $350\mathrm{M}$, $760\mathrm{M}$ and $1.3\mathrm{B}$ parameters. For the $15\mathrm{B}$-token method comparison, a family of models is constructed to match a GPT-3–style baseline at about $350\mathrm{M}$ parameters (embedding dimension $1024$ and $24$ residual blocks) so that methods are compared at a common scale.

xLSTM architectures are specified by the ratio of mLSTM-based to sLSTM-based blocks using the notation $xLSTM[a:b]$, where $a/b$ denotes the number of mLSTM blocks versus sLSTM blocks in the block mix. For example, $xLSTM[7:1]$ means seven mLSTM-based blocks for every one sLSTM-based block; when the total number of blocks is $48$, that corresponds to $42$ mLSTM-based blocks and $6$ sLSTM-based blocks. In experiments the authors report results for pure mLSTM ($xLSTM[1:0]$), pure sLSTM ($xLSTM[0:1]$), and mixed ratios such as $xLSTM[7:1]$ and $xLSTM[1:1]$ to probe the trade-offs between the matrix memory and scalar-memory-with-mixing designs.

# Training precision and implementation details
Training is performed with mixed-precision arithmetic in the majority of experiments. The paper notes that mixed-precision training was applied broadly, but for some alternative models (specifically RWKV-5, RWKV-6, GLA, and HGRN2) the mixed-precision training did not utilize PyTorch’s automated mixed precision (AMP) in the authors’ training setup; this detail is reported because it can affect numerical stability and wall-clock efficiency. For a subset of long runs (the $300\mathrm{B}$-token experiments), some recurrent-model variants (RWKV-5, RWKV-6, HGRN2) required adjustments to precision settings discovered only after training had already started, and consequently those particular runs are noted as having had training-precision issues.

Implementation-level distinctions between the two xLSTM memory types are important for runtime behavior and parallelism. The mLSTM variant uses a matrix memory $\mathbf{C}\in\mathbb{R}^{d\times d}$ with a covariance (outer-product) update and, crucially, contains no hidden--hidden recurrent mixing; this design allows a parallel formulation of the recurrence and makes mLSTM amenable to GPU parallelization. The sLSTM variant retains memory mixing via recurrent hidden-to-gate connections, and therefore is not intrinsically parallelizable across time; to mitigate this, the authors implemented a custom CUDA kernel for sLSTM with GPU memory optimizations down to register level, achieving a runtime that is typically less than two times slower than their parallel mLSTM implementation. Conversely, the current mLSTM CUDA implementation is not fully optimized and is reported to be about four times slower than highly optimized attention kernels such as FlashAttention; the authors indicate that further kernel-level optimization should reduce that gap.

Architecturally, xLSTM blocks are implemented in pre-LayerNorm residual backbones, following contemporary LLM design. For blocks that contain sLSTM cells the block uses a post up-projection residual formulation; for mLSTM-based blocks a pre up-projection residual formulation is used so that the larger matrix memory operates in the higher-dimensional projected space. The exact residual-block shapes and layer-normalization placements follow the descriptions given in the xLSTM block section.

# Synthetic tasks: formal languages and multi-query associative recall
The evaluation suite includes targeted synthetic tasks designed to probe specific capabilities of the memory and gating mechanisms.

Formal language tasks. To analyze state-tracking and the effect of exponential gating with memory mixing, the paper reimplements and extends formal-language tasks from prior work so they can be trained and evaluated under multi-length regimes (to permit length extrapolation analysis). Models are evaluated on the tokens that are relevant to the formal-language decision, and accuracy is scaled between $0$ (random) and $1$ (perfect). The comparisons use small architectures (two-block models) across many methods including pure sLSTM ($xLSTM[0:1]$), pure mLSTM ($xLSTM[1:0]$), mixed xLSTM ($xLSTM[1:1]$), Transformers (Llama), State Space Models (Mamba), and several RNN baselines (RWKV, LSTM). These tasks show that methods without memory mixing (standard Transformers and many SSMs) fail to solve certain state-tracking tasks, while sLSTM (with exponential gating and memory mixing) succeeds.

Multi-Query Associative Recall (MQAR). To probe raw memory capacity the MQAR task is employed and made substantially harder than in standard formulations: the number of stored key–value pairs is increased up to $256$, and the context length is expanded up to $2048$. Each sequence contains randomly chosen key–value pairs drawn from a large vocabulary; the model is required to store and later recall the correct value given a query. Retrieval accuracy on held-out queries is the evaluation metric. Transformers (with their implicit high-capacity associative encoding) are a strong baseline on MQAR; among non-Transformer models, $xLSTM[1:1]$ attains the best accuracy across a range of difficulty levels, and the inclusion of an sLSTM block does not reduce memory capacity — in fact, it can assist performance on the hardest settings. The paper also reports extrapolation analyses in the appendix showing that xLSTM’s enhanced memory structures help it generalize to longer contexts than seen during training.

# Long Range Arena for long-context evaluation
Long-context behavior is measured using the Long Range Arena (LRA) suite to assess models’ ability to handle long sequences across a variety of tasks (text, retrieval-like tasks, and structured inputs). xLSTM is evaluated alongside a variety of modern recurrent, SSM, and Transformer methods. The experiments show that xLSTM yields consistently strong performance on the LRA tasks considered, indicating that the combination of exponential gating and the two memory designs is effective for diverse long-context problems.

Where applicable (e.g., length extrapolation experiments described below), models are trained on a canonical context length ($2048$ tokens) and then evaluated at substantially longer context lengths (up to $16384$ tokens); this testing protocol directly assesses the capacity of the memory mechanism to avoid degradation as context length grows.

# Validation perplexity, downstream reasoning tasks (e.g., LMEval), PALOMA
Validation perplexity on the SlimPajama held-out set is the primary scalar metric used to compare autoregressive next-token modeling performance across families of models. In the $15\mathrm{B}$-token comparisons, models are configured at a common size (GPT-3–style $350\mathrm{M}$-parameter point) so validation perplexity differences reflect architectural differences rather than model scale. The paper reports that xLSTM variants achieve lower validation perplexity than the competing Transformers, SSMs, and RNN baselines in these controlled comparisons.

Beyond perplexity, the authors evaluate models on a suite of downstream reasoning tasks intended to measure common-sense and reasoning abilities. These downstream results are summarized in a table referenced as Table~\ref{tab:lmeval} and are reported alongside validation perplexity in the $300\mathrm{B}$-token experiments. The aggregate picture is that xLSTM models are top-performing on most downstream tasks across model sizes, with isolated tasks (e.g., ARC in some settings) where Mamba performs best.

PALOMA benchmark. To probe domain- and topic-level generalization for next-token prediction, the PALOMA suite (571 text domains) is used. The evaluation metric is token-prediction perplexity measured per domain. Results show that $xLSTM[1:0]$ (pure mLSTM) attains lower perplexity than competing models on the vast majority of domains: $568/571$ domains better than Mamba, $486/571$ better than Llama, and $570/571$ better than RWKV-4. This per-domain analysis highlights xLSTM’s robustness across varied text sources.

# Scaling law analysis: methodology and metrics
The study examines scaling behavior using a power-law methodology inspired by established scaling-law research. Models are trained at multiple parameter scales (e.g., $125\mathrm{M}$, $350\mathrm{M}$, $760\mathrm{M}$, $1.3\mathrm{B}$) and their validation perplexities are plotted versus model size; the fitted trend demonstrates an approximate power-law (straight line on log–log axes) with a slope that is broadly similar across method families but with different offsets. This allows comparisons of sample- and model-efficiency across architectures: a lower offset indicates systematically better performance at all scales for the same slope. The paper reports that xLSTM exhibits a favorable offset compared to Mamba, Llama, and RWKV-4, suggesting that at larger scales xLSTM remains competitive or superior.

In addition to parameter-scaling experiments, extrapolation of context length is treated as a separate scaling dimension. For these experiments, models trained on context length $2048$ are evaluated on lengths up to $16384$ to observe how perplexity changes with context length. xLSTM models maintain relatively low perplexities at extended lengths compared to the other evaluated methods, indicating better length-extrapolation behavior.

Finally, wall-clock inference characteristics (generation time and decoding throughput) are measured as practical scaling metrics. Generation-time experiments use generation with batch size $1$ and a pre-fill of $16$ tokens to favor cacheable Transformer workloads. Results exhibit linear generation-time scaling for recurrent models including xLSTM and quadratic scaling for the Transformer baseline (Llama). For decoding throughput, xLSTM benefits from constant-memory characteristics and can use larger batch sizes than the Transformer, producing higher maximal throughput in the reported experiments. These runtime measurements are presented alongside the algorithmic scaling laws to give a fuller picture of how architecture choices trade off statistical efficiency and computational practicalities.

# Summary of evaluation protocol and reproducibility notes
The experimental protocol combines synthetic diagnostic tasks (formal languages, MQAR, LRA) with large-scale language-model training on SlimPajama at two data budgets ($15\mathrm{B}$ and $300\mathrm{B}$ tokens). Models are compared at matched parameter points where possible, and a clear notation ($xLSTM[a:b]$) describes mixed-block architectures. The principal metrics are next-token perplexity, task-specific accuracy (scaled $0$ to $1$) or recall in synthetic tasks, downstream-task performance summarized in tabular form, per-domain perplexities on PALOMA, context-length extrapolation behavior, and computational/runtime metrics including generation latency and throughput.

Important implementation caveats that affect experimental reproducibility are explicitly reported: mixed-precision training was used widely but some baselines did not employ PyTorch AMP in the authors’ runs; custom CUDA kernels were implemented for sLSTM to reduce the parallelism disadvantage; the mLSTM CUDA kernels are not fully optimized and are slower than highly tuned attention kernels; and certain long runs required post-hoc precision fixes for some baseline models. These details should be considered when reproducing exact wall-clock numbers or when attempting to compare runtimes across architectures.

Empirical Results: Capabilities, Comparisons, and Scaling

# Formal language results: parity and other state-tracking tasks

A central claim of the xLSTM work is that exponential gating combined with memory mixing restores the kind of state-tracking power that classical recurrent models (like LSTMs) can provide, and that models without memory mixing (standard Transformers and many State Space Models) fundamentally lack. The formal-language experiments in the paper were designed to test exactly this: tasks that require maintaining and updating discrete state across long sequences (for example parity and other regular-grammar style tasks). These are canonical examples where exact state tracking rather than soft pattern-matching is needed.

Empirically, xLSTM variants that include sLSTM (which permits memory mixing and uses exponential gates) achieve high accuracy on these formal languages and can extrapolate to sequence lengths beyond those seen during training. By contrast, Transformers and SSMs that do not perform memory mixing fail on these tasks. Intuitively, the ability to mix memory across cells and to apply exponential gating gives sLSTM the capacity to implement stable, revisable counters or discrete state machines: exponential gates permit rapid, multiplicative revision of stored contributions and the new normalizer/stabilizer states avoid numerical blowup while preserving differentiability. The experiments show that this combination recovers the kind of stateful behavior required for parity and similar tasks, matching theoretical expectations that memory mixing increases expressivity for state-tracking problems.

# Associative recall: memory capacity across many key–value pairs

To evaluate memory capacity in a more content-addressable sense, the authors extended the Multi-Query Associative Recall task to be substantially harder: they increased the number of random key–value pairs up to $256$ and extended contexts up to length $2048$. This task tests storing many distinct pairs and later retrieving values conditioned on queries, which is the regime where matrix-style memories or attention-like mechanisms typically excel.

Here the matrix-memory mLSTM shines. The mLSTM implements a covariance-style outer-product update, storing $\mathbf{v}_t \mathbf{k}_t^\top$ into a matrix memory and retrieving with matrix–vector multiplication. Among non-Transformer methods, xLSTM configurations that include mLSTM (for instance xLSTM[1:1]) perform best on recall accuracy across a broad range of difficulties. Notably, adding sLSTM blocks does not reduce capacity — rather, the presence of sLSTM often leverages the matrix memory to improve recall at the hardest settings (e.g., $256$ pairs). This indicates a complementary interaction: mLSTM brings raw associative capacity, while sLSTM brings flexible state-mixing that helps organize or route stored information.

The intuitive reason is that the covariance update gives an efficient dense encoding of pairwise associations, while the normalization mechanisms and exponential gates prevent dominance by early or late items and keep the retrieval signal-to-noise favorable. Although pure Transformers can achieve large effective memory (because attention can be exponentially expressive in code dimension), xLSTM recovers much of that associative power within a recurrent, linear-in-length framework.

# Long Range Arena: handling long sequences

The Long Range Arena (LRA) benchmark probes a model’s ability to manage long contexts with varied signal types (text-like, algorithmic, image-derived, etc.). xLSTM demonstrates consistently strong performance across the LRA tasks. This shows that the combination of exponential gating, stabilized normalizers, and the two complementary memory designs (scalar sLSTM with mixing and matrix mLSTM without mixing) yields robust long-context behavior.

Why does xLSTM handle long sequences well? There are several contributing factors. First, the constant-error-carousel style updates (inherited and extended from LSTM) avoid vanishing gradients over long horizons. Second, exponential gating plus stabilizers allows the model to maintain and revise stored contributions multiplicatively, which is important for emphasizing or attenuating long-past information without catastrophic numerical issues. Third, the matrix memory provides content-addressable recall for many items, so the model does not need to compress every detail into a small scalar state. Together these mechanisms provide both durable state maintenance and scalable associative recall, which the LRA tasks exercise.

# 15B-token comparisons: xLSTM vs Transformers, SSMs, and RNNs

To assess practical language-model performance, the authors trained multiple methods on the same $15\,$B-token SlimPajama corpus in an autoregressive setting and compared validation perplexities for models sized to match a GPT-3–style baseline (approximately $350$M parameters, embedding dimension $1024$, $24$ residual blocks). The methods compared included Transformers (GPT-3, Llama), State Space Models (H3, Mamba), recurrent or linearized models (RWKV variants, HGRN, HGRN2, GLA, RetNet, Hyena), and two xLSTM configurations (xLSTM[1:0] and xLSTM[7:1]).

xLSTM outperforms all existing methods in validation perplexity in this controlled $15\,$B-token regime. This is a strong empirical statement: when bringing LSTM-derived ideas up to contemporary residual-backbone architectures and augmenting them with exponential gating and matrix memories, the resulting models can beat matched-size Transformers and SSMs on next-token prediction after the same data budget. The scaling curve for these experiments also suggests xLSTM retains a favorable margin as models grow within this regime.

# Ablation studies: residual backbones, exponential gating, matrix memory, gate inputs

The paper includes systematic ablation studies that morph a vanilla LSTM architecture into xLSTM, isolating the contribution of each design change. The morphing proceeds by (1) integrating LSTM layers into pre-LayerNorm residual backbones, (2) implementing a post up-projection residual block, and (3) adding exponential gating plus matrix memory. The ablations show that both exponential gating and the matrix memory provide substantial, separable improvements in perplexity. In other words, neither modification alone explains the full gain; together they are synergistic.

Additional gate-related ablations show that letting each gate be input-dependent and learnable yields incremental positive effects. That is, making gates more expressive (input- and bias-driven rather than fixed scalars) steadily improves performance. These findings emphasize that gating itself remains a crucial inductive bias; refining the gating functions (exponential activations plus stabilizers in sLSTM/mLSTM) is central to the improved empirical behavior.

Intuitively, the residual backbone and up-projection blocks provide the larger representational canvas (higher-dimensional embeddings and nonlinear transforms) on which the memory mechanisms operate; exponential gates determine how aggressively new information overrides or adds to stored memory; and the matrix memory increases the capacity for storing diverse content-addressable items. Ablations confirm that removing any of these elements degrades language-model performance.

# 300B-token results: length extrapolation to 16k and validation perplexities

To test large-data behavior, the authors trained models on a much larger $300\,$B-token SlimPajama budget and evaluated several model sizes ($125$M, $350$M, $760$M, $1.3$B). A critical test was context-length extrapolation: models trained with context length $2048$ were evaluated up to $16384$ (i.e., $16\,$k) tokens. xLSTM models maintain low perplexities at these extrapolated context lengths in contrast to the competing architectures tested. This demonstrates that the recurrent xLSTM memory mechanisms generalize to longer contexts without retraining or architectural changes.

On validation perplexity for next-token prediction across the range of model sizes, xLSTM configurations (both xLSTM[1:0] — only mLSTM blocks — and xLSTM[7:1] — majority mLSTM plus some sLSTM) are the best-performing models. That consistent superiority across sizes indicates that the improvements are not a narrow artifact of a particular capacity regime, but translate across practical LLM sizes.

# Downstream tasks: broad wins with some ARC exceptions

Beyond perplexity, the authors evaluated downstream tasks that capture common-sense reasoning and benchmark-style problem solving. Across the majority of these tasks and across model sizes, xLSTM achieves the best performance among the compared methods. The one notable exception is ARC (a particular reasoning benchmark), where in some cases Mamba (an SSM variant) outperforms xLSTM. This nuanced result underscores that while xLSTM provides generally superior language-modeling representations, some task-specific inductive biases in other architectures can still be advantageous in narrow settings.

Overall, the downstream-task results reinforce the link between improved next-token modeling (lower perplexity) and better performance on many practical language tasks, while reminding us that no single architecture dominates every benchmark.

# PALOMA: domain-wise perplexity gains across 571 text domains

The PALOMA benchmark evaluates next-token prediction across a broad suite of $571$ real-world text domains (news, forums, technical, social, etc.). The paper reports domain-level perplexities grouped by language-modeling and fine-grained domain benchmarks. On this challenging and diverse suite, xLSTM[1:0] (pure mLSTM blocks) demonstrates marked improvements: it achieves lower perplexity than Mamba on $568$ out of $571$ domains ($99.5\%$), lower than Llama on $486$ out of $571$ domains ($85.1\%$), and lower than RWKV-4 on $570$ out of $571$ domains ($99.8\%$). These counts show that xLSTM’s gains are not limited to a few domains but are pervasive across very different text distributions. The matrix memory plus normalization and gating appear particularly effective at modeling rare or domain-specific patterns that would otherwise be hard to compress into scalar memories or short attention windows.

# Scaling laws: favorable offsets indicating continued gains at larger scales

The authors analyzed scaling behavior by plotting power-law fits (in the spirit of the Kaplan–Haffner style analyses) over different model sizes and training budgets. All models exhibit similar power-law exponents, meaning their error decreases with model size according to comparable slopes. However, xLSTM enjoys a favorable offset: for the same parameter counts and data budgets, xLSTM sits at a lower perplexity than SSMs and Transformers. Practically, this offset implies that as models scale further, xLSTM is likely to remain competitive and possibly extend its advantage, because the scaling exponent is shared but the constant is better. In short, xLSTM buys you a consistent headroom at every scale rather than a fleeting advantage at a single size.

# Inference speed and throughput vs Llama, Mamba, and RWKV

Inference efficiency is a critical practical concern. The paper measures text generation time and maximal decoding throughput for $1.3\,$B–scale models, comparing xLSTM variants to Llama (Transformer), Mamba (SSM), and RWKV (RNN). Two empirical patterns stand out.

First, generation time as context length increases: xLSTM and the other recurrent models (Mamba, RWKV) scale linearly with context length, whereas Llama’s generation time scales quadratically when it must recompute or use large key–value caches. In the specific generation experiments (batch size $1$, prefill $=16$ to favor the Transformer), xLSTM demonstrates linear runtime scaling and remains competitive in absolute wall-clock time.

Second, maximal decoding throughput (tokens/sec across batch sizes): because xLSTM’s memory usage is constant with respect to context length, it can operate with much larger batch sizes than Llama before exhausting GPU memory. This yields higher end-to-end throughput; empirically xLSTM achieves the highest throughput among the compared methods in the reported measurements. These results highlight a key systems advantage of the xLSTM design: constant-memory, linear-time recurrence permits higher parallelism at decode time and makes the model more suitable for high-throughput serving scenarios.

There are practical caveats reported in the paper. The mLSTM CUDA kernels in the authors’ implementation are not fully optimized and run about four times slower than highly optimized FlashAttention kernels; better kernels would reduce this gap. The sLSTM variant cannot be parallelized across time due to its memory-mixing recurrent connections, but the authors implemented an optimized CUDA kernel for it that runs typically less than two times slower than their parallel mLSTM implementation. These implementation-level facts suggest that with further engineering (kernel optimization and compilation), xLSTM’s wall-clock performance could be improved even further.

# Synthesis and takeaways

Across a suite of synthetic and large-scale language experiments, xLSTM demonstrates that carefully modernized LSTM ideas — exponential gating with stabilizers, a scalar sLSTM with memory mixing, and a matrix mLSTM with covariance-style updates — produce a recurrent architecture that is both expressive and scalable. On synthetic state-tracking tasks, exponential gating plus memory mixing restores the ability to implement discrete state behavior absent in many non-recurrent architectures. For associative recall, the matrix memory supplies strong content-addressable capacity. On practical language-modeling benchmarks trained with realistic data budgets ($15\,$B and $300\,$B tokens) and across sizes up to $1.3\,$B parameters, xLSTM attains lower perplexities, robust domain-wise gains across PALOMA, good downstream-task performance, reliable context-length extrapolation to $16\,$k tokens, and competitive inference throughput thanks to its linear-time, constant-memory recurrence.

The empirical picture supports the paper’s core message: when LSTM-derived designs are extended with modern architectural practices and targeted memory/gating innovations, recurrent models can again be competitive with — and in many respects surpass — state-of-the-art Transformer and SSM approaches in language modeling and related sequence tasks.

Implementing and Training xLSTM in Practice

# Gate parameterization, biases, and activation choice for forget gates
xLSTM extends the classic LSTM gating design in two ways that are central to both expressivity and stability. First, the input gate in both sLSTM and mLSTM uses an exponential activation,
i.e. for the raw pre-activation $\tilde{i}_t$ the gate is
$i_t = \exp(\tilde{i}_t)$ (see Equations (4) and (10) in the paper). Second, the forget gate may be implemented either as a conventional sigmoid,
$f_t = \sigma(\tilde{f}_t)$, or as an exponential,
$f_t = \exp(\tilde{f}_t)$, depending on whether you prefer a bounded retention factor or want the revisable, multiplicative dynamics that exponentials permit. The output gate remains a sigmoid $o_t=\sigma(\tilde{o}_t)$.

Structurally, xLSTM keeps the usual affine parameterization of gate pre-activations: each gate pre-activation $\tilde{g}_t$ (for $g\in\{i,f,o\}$) is computed from a linear projection of inputs (and in sLSTM also from the previous hidden state if memory mixing is enabled), plus a bias term. The paper’s ablation studies report incremental gains when gates are learnable and input-dependent; in other words, keep the gates parameterized by trainable weights on inputs (and on hidden state where applicable) and include learnable biases. That design gives the model the flexibility to modulate storage and decay dynamically.

Practically, if you want the revisability behavior highlighted in the paper (e.g., to allow an earlier stored item to be diminished once a stronger later candidate arrives), adopt exponential input gating and consider an exponential forget gate. If you prefer bounded forget dynamics (more conservative retention), use sigmoid for $f_t$. The sLSTM formulation allows richer memory-mixing when recurrent connections are used, while mLSTM removes hidden–hidden recurrence and therefore typically uses input-dependent gates (no recurrent term in Equations (10)–(12) of the paper).

# Stabilization hyperparameters: denominator threshold and log-max trick
Two stabilization mechanisms in xLSTM are essential when using exponential gates and matrix memory.

1) Log-max stabilizer for exponential gates. Exponentials can overflow or produce numerically huge values. The paper stabilizes the pair of exponential gates (input and forget) with an auxiliary stabilizer state $m_t$ computed as
\[
m_t \;=\; \max\bigl(\log(f_t) + m_{t-1},\; \log(i_t)\bigr),
\]
and then uses the shifted versions
\[
i'_t = \exp\bigl(\log(i_t) - m_t\bigr),\qquad
f'_t = \exp\bigl(\log(f_t) + m_{t-1} - m_t\bigr).
\]
Replacing $i_t,f_t$ by $i'_t,f'_t$ leaves the network outputs and parameter gradients unchanged but prevents numerical overflow by keeping the effective multiplicative factors in a numerically stable range. This is the log-max trick (Equation (5) in the paper). Implementing $m_t$ and using $i'_t,f'_t$ wherever $i_t,f_t$ appear is therefore required when exponential activations are used.

2) Normalizer denominator threshold for mLSTM. In the mLSTM the retrieved vector is normalized by the dot product between the query $\mathbf{q}_t$ and the normalizer state $\mathbf{n}_t$. To avoid division by values near zero (which would amplify noise and cause instability) the paper uses the absolute value of the dot product and lower bounds it by a threshold:
\[
\tilde{\mathbf{h}}_t = \frac{\mathbf{C}_t \mathbf{q}_t}{\max\{\,|\mathbf{n}_t^\top \mathbf{q}_t|,\;1\,\}}.
\]
The paper states that the threshold is typically 1.0. Using this lower bound (and the absolute value) prevents extreme amplifications and yields numerically stable retrievals from the matrix memory (see Equations (8) and (9) in the paper).

Both stabilization mechanisms are not optional when exponentials and the covariance-style matrix updates are in play: omit them and you are likely to encounter overflow and training instability.

# Initialization strategies for gates and memory states
The paper emphasizes that the initialization of forget gates requires careful choice (Limitation (iv)). While the xLSTM equations retain standard affine pre-activations and biases for gates, the presence of exponentials makes their initial scale particularly sensitive: small differences in initial gate pre-activations can be amplified due to exponentiation and then compounded over time through the recurrent dynamics.

From the paper’s experiments and ablations the practical takeaways are:
- Treat gate biases as tunable hyperparameters to be validated. The paper’s ablations show incremental benefits when gates are learnable and input-dependent; consequently, initial bias choices for gates matter and should be tuned on held-out validation data.
- Use the stabilizer $m_t$ implementation when exponential gates are enabled; this reduces the sensitivity of initial gate magnitudes to numeric overflow.
- For mLSTM, the normalizer $\mathbf{n}_t$ and cell matrix $\mathbf{C}_t$ are part of the recurrent state (Equations (8)–(12)). The paper does not specify exotic non-standard initializations for these state matrices; follow conventional recurrent initialization semantics (i.e., initialize recurrent state to the usual start-of-sequence states the framework uses) and focus hyperparameter search on gate biases and stabilizer behavior, since the limitations section explicitly flags forget gate initialization as a point of care.

In short: pay special attention to forget-gate bias (tune it), always include the $m_t$ stabilizer with exponentials, and monitor early training dynamics to detect mis-initialized retention behavior.

# Choosing block ratios: xLSTM[1:0] vs xLSTM[7:1] and task fit
The paper evaluates architectures using the notation xLSTM[a:b], where $a/b$ is the ratio of mLSTM-based to sLSTM-based blocks (Section 4). Practical guidance from the experimental findings:

- Use more mLSTM blocks (e.g., xLSTM[1:0], i.e., only mLSTM) for general large-scale language modeling. In the experiments on 300B tokens and PALOMA domains, xLSTM[1:0] performs very well and often outperforms mixed variants and other baselines. mLSTM’s matrix memory provides strong retrieval capacity and, being parallelizable, is efficient for large models.

- Include sLSTM blocks when the problem requires state tracking or when memory mixing (hidden–hidden recurrent mixing across cells) is important. The sLSTM’s memory-mixing capability and exponential gating let it solve formal/state-tracking tasks that transformer- and SSM-style architectures without memory mixing cannot (the formal languages experiments in Section 4.1). In associative-recall experiments, mixed configurations such as xLSTM[1:1] performed best among non-Transformer methods, indicating that a judicious blend can yield strong retrieval plus state-tracking abilities.

- Use ratios such as xLSTM[7:1] when you want a primarily mLSTM backbone augmented with a small number of sLSTM blocks to provide memory-mixing capacity. The paper’s 48-block example (xLSTM[7:1] → 42 mLSTM + 6 sLSTM) is a practical instantiation used in experiments.

Thus, choose xLSTM[1:0] for throughput- and retrieval-dominant language modeling, and include sLSTM blocks (e.g., xLSTM[7:1] or xLSTM[1:1]) when the target tasks include stateful computations, formal languages, or long-term entity tracking.

# Dimensionality, number of heads, and number of cells
xLSTM generalizes the LSTM notion of scalar cell to richer memory formats; the paper provides the following structural guidance.

- Dimensionality and matrix memory cost. mLSTM uses a matrix memory $\mathbf{C}_t\in\mathbb{R}^{d\times d}$ with covariance-style updates. This yields much higher storage capacity but also increases computational cost because updates and retrievals are $d\times d$ operations. The paper explicitly notes the trade-off: matrix memory increases capacity at the cost of $d\times d$ compute, which can still be parallelized on GPUs.

- Heads and cells: for sLSTM, multiple scalar memory cells can be organized into heads. The sLSTM permits memory mixing across cells and allows multiple heads where mixing occurs within a head but not across heads. This introduces a way to structure memory-mixing selectively. For mLSTM, the paper states that multiple heads and multiple cells are equivalent, because mLSTM has no recurrent memory-mixing.

- Practical model sizing in experiments. When matching a GPT-3-like configuration (350M), the paper used embedding dimension 1024 and 24 residual blocks as a baseline comparison. This gives an experimental point of reference for dimension choices in comparable setups. Keep in mind that higher $d$ increases both representational power and the $d\times d$ costs for mLSTM.

Use these trade-offs to decide: if your hardware and latency budget permit $d\times d$ operations, exploit mLSTM’s matrix memory for improved rare-token performance and retrieval; if you need lower compute, rely more on sLSTM and scalar cells with memory-mixing but accept lower representational capacity per cell.

# Mixed-precision training and compilation considerations
The paper’s large-scale experiments used mixed precision for many models. Mixed-precision training reduces memory and speeds up training, but certain recurrent or non-standard architectures may require careful handling. Specifically, the paper reports that while most models were trained with mixed precision, RWKV-5, RWKV-6, and GLA did not utilize the PyTorch automated mixed precision flow in their experiments. This highlights that:

- Mixed precision is viable and used in the xLSTM experiments, but you should validate that your chosen automatic mixed-precision toolchain (AMP) interacts correctly with custom recurrent kernels, exponential gates, and the stabilizer $m_t$ implementation.

- Keep a validation run or short pilot to confirm that exponentials and the log-max stabilizer remain numerically stable under mixed precision. If automatic AMP causes issues, consider customized casting or selective higher-precision compute (for example, keep parts of the stabilizer arithmetic in float32) — the paper’s mixed-precision caveats suggest such practical adjustments were necessary for some competing architectures.

Regarding compilation (e.g., torch.compile), the paper mentions that at the time of experiments some models (the Transformer with full KV cache compilation and the Mamba model compilation) did not compile successfully. This suggests that when using compilation facilities, test compilation early and be prepared for engineering workarounds for custom recurrent kernels or matrix-memory updates.

# Batching strategies, prefill handling, and decoding throughput
xLSTM’s runtime characteristics differ markedly from Transformer-style models because its memory usage is constant in the sequence length (linear compute but constant memory with respect to context). The experiments show:

- Prefill experiments: in the generation-time measurements the paper used batch size 1 and prefill 16 tokens as a test case that favors the Transformer. This is a useful benchmark configuration to compare generation latency.

- Decoding throughput: since xLSTM’s state is constant-size (it does not need to store and reuse per-token key/value caches as Transformer decoders do), xLSTM can use much larger batch sizes during decoding without running out of memory. The paper reports that xLSTM achieves the highest throughput in their decoding experiments precisely because of this constant memory property.

- Practical recommendation: for inference, exploit larger batch sizes with xLSTM to maximize throughput. For latency-sensitive single-sequence generation, note xLSTM’s per-step computations are linear in state dimension but avoid the quadratic overhead of Transformers; for high-throughput decoding, the constant memory allows batching that Transformer decoders cannot match at large context lengths.

# Debugging overflow, underflow, and training instability
The paper identifies three concrete numerical and stability failure modes and prescribes the corresponding remedies it used. Use these as a checklist when debugging xLSTM training:

1) Overflow from exponential gates. Symptom: NaNs or infinities in forward pass when exponential gates are used. Remedy: implement the log-max stabilizer state $m_t$ and use the stabilized gates $i'_t,f'_t$ as in Equations (5). This change preserves model mathematics while preventing unbounded exponentials.

2) Instability from near-zero normalizer in mLSTM. Symptom: extremely large retrieved vectors or wild gradients when $\mathbf{n}_t^\top \mathbf{q}_t\approx 0$. Remedy: use the absolute value and lower-bound threshold in the denominator, i.e., divide by $\max\{|\mathbf{n}_t^\top\mathbf{q}_t|, 1\}$ (typical threshold 1.0). This ensures retrieval magnitudes remain controlled.

3) General recurrence and forget-gate sensitivity. Symptom: exploding or vanishing contributions from past steps, poor early training. Remedy: carefully select forget-gate initialization and monitor early training dynamics. The paper emphasizes that the forget-gate initialization must be chosen carefully; treat forget-bias (and gate pre-activation scales) as tunable hyperparameters and watch how early steps are being retained or forgotten.

General debugging workflow based on the paper:
- Turn on tight numeric checks: detect NaNs/Infs early, trace their origin to exponential places (gates) or divisive normalizer operations.
- Verify the stabilizer $m_t$ and the denominator threshold are implemented exactly as in the equations; these are mathematically neutral transforms that merely preserve outputs while improving numeric robustness.
- Run small-scale tests on synthetic tasks (the paper’s synthetic experiments are instructive) to confirm that the model can represent the expected behaviors (e.g., revisability with exponentials, associative recall for mLSTM).
- If mixed precision is used, monitor whether reduced numerical precision interacts with exponentials or stabilizers; use the mixed-precision caveats above.

By following the paper’s stabilization prescriptions and treating forget-gate initialization as an important hyperparameter, you will address most of the numeric failure modes reported.

# Final practical checklist (based on the paper)
- When you enable exponential gating: implement the $m_t$ log-max stabilizer and use the stabilized gates in the forward pass.
- For mLSTM retrieval: normalize by $\max\{|\mathbf{n}_t^\top \mathbf{q}_t|,\;1\}$ to avoid division-by-small-number issues.
- Decide your block ratio according to task: use predominantly mLSTM (xLSTM[1:0]) for large-scale language modeling and throughput; add sLSTM blocks when state tracking and memory mixing are required (xLSTM[7:1] or balanced mixes).
- Treat gate parameterization as fully learnable and input-dependent (ablation results favor this).
- Expect higher compute for mLSTM due to $d\times d$ memory; ensure your hardware and parallelization strategy support it.
- Use mixed precision but validate numerics carefully; be prepared to adjust precision handling for custom kernels.
- For inference, exploit xLSTM’s constant memory to increase batch sizes and maximize throughput; test prefill/batch-size trade-offs as done in the paper’s generation experiments.
- If you encounter NaNs or exploding activations, check exponentials and denominator usage first; then investigate forget-gate initializations.

Following the equations, stabilization mechanisms, and architectural choices documented in the paper will give you a reliable foundation for implementing, training, and deploying xLSTM models across the range of tasks the authors evaluated.

Theory and Intuition: Why xLSTM Works

# Revisable storage via exponential gates and running normalizers

One of the core limitations of classical LSTMs identified in the paper is their difficulty to revise prior storage decisions: once information is written into the scalar cell state, it is hard to re-weight that information later in the sequence. xLSTM addresses this limitation by replacing bounded sigmoid gates (which yield values in $(0,1)$) with exponential gates for the input (and optionally forget) paths, combined with a running normalizer that explicitly tracks gate strength over time.

To see how this enables revisable storage, compare the sLSTM forward equations (Equation (3) in the paper):

c_t = f_t \, c_{t-1} + i_t \, z_t,
n_t = f_t \, n_{t-1} + i_t,
\tilde{h}_t = c_t / n_t,
h_t = o_t \, \tilde{h}_t,

with i_t given by i_t = \exp(\tilde{i}_t) (and f_t either \sigma(\tilde{f}_t) or \exp(\tilde{f}_t)). Because i_t is an exponential, it is strictly positive and unbounded above. The normalizer n_t accumulates the same gate weights used to form the cell content: it is a running sum of the contributions i_t, discounted by future forget factors f_t. The hidden representation is then formed by dividing the accumulated content c_t by the accumulated weight n_t, i.e. by computing a normalized (weighted) average \tilde{h}_t = c_t / n_t.

This construction makes storage revisable in two ways. First, because forget gates f_t can scale prior contributions multiplicatively, the effective weight of an earlier write can be decreased (or, with exponential f_t, even increased relative to a simple decay), so later inputs can attenuate prior memory contributions. Second, the input gate i_t being unbounded allows a newly arriving input to assert arbitrarily large influence relative to earlier writes. Together, these mechanisms let the network both amplify important late observations and demote earlier ones — a form of online, sequential re-weighting that is not achievable when gates are restricted to the interval (0,1) and the hidden state is not normalized by cumulative gate strength.

The running normalizer n_t is the bookkeeping device that makes these multiplicative re-weightings well-defined. By carrying the same multiplicative history of gates as the numerator c_t, the quotient c_t / n_t yields a stable normalized readout that reflects current relative importance of stored contents, not simply an absolute sum that cannot be easily rebalanced later.

Numerical stability is essential when gates are exponential. The paper introduces a stabilizer state m_t (Equation (4)) that is effectively a running log-sum-exp of the gate magnitudes, and then rescales i_t and f_t to avoid overflow. Crucially, this rescaling leaves the effective normalized output and gradients unchanged, so the model can safely exploit exponential gates without numerical breakdown.

# Normalizer as an implicit normalization akin to attention’s denominator

The normalizer in xLSTM plays the same conceptual role as the denominator in attention mechanisms: it converts a raw, potentially unbounded aggregate into a normalized readout that represents a weighted average rather than an unbounded sum. In the mLSTM, this connection is explicit.

For mLSTM the paper defines the matrix memory and normalizer as

\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top,
\mathbf{n}_t = f_t \mathbf{n}_{t-1} + i_t \mathbf{k}_t,

and the retrieved unnormalized vector is \mathbf{C}_t \mathbf{q}_t. The readout used for the hidden state divides this by a scalar normalization factor:

\tilde{\mathbf{h}}_t = \mathbf{C}_t \mathbf{q}_t \, / \, \max\{ |\mathbf{n}_t^\top \mathbf{q}_t|, 1 \}.

This denominator \mathbf{n}_t^\top \mathbf{q}_t is the running sum of key-query compatibilities (weighted by the input gates and decayed by forget gates). Dividing by it makes the retrieved vector behave like an attention-weighted average of stored values: the numerator aggregates value vectors scaled by their key similarity to the query, and the denominator scales out the total key mass so the result reflects relative contributions. The absolute value and lower bound protect against near-zero denominators.

Viewed this way, mLSTM implements attention-like retrieval without re-computing all pairwise key-query scores at query time. Instead, it incrementally accumulates an associative memory via outer products and maintains the corresponding normalizer. This yields a running, memory-efficient mechanism that approximates the normalization behavior of standard softmax attention, but with linear time accumulation instead of quadratic time pairwise re-evaluation.

The normalizer is therefore not just a numerical trick: it is the structural element that converts a compressive cumulative memory into a normalized discriminator of which stored items should influence the current read. In sLSTM the same idea appears in scalar form: \tilde{h}_t = c_t / n_t is a normalized scalar memory readout.

# Memory capacity and separability in covariance-based fast weights

mLSTM upgrades the scalar LSTM cell to a matrix memory \mathbf{C}_t \in \mathbb{R}^{d\times d} and updates it with outer products (covariance updates) of the form \mathbf{v}_t \mathbf{k}_t^\top. This is the classic fast weight or covariance update rule:

\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top.

Intuitively, each stored pair (\mathbf{k}_t,\mathbf{v}_t) deposits a rank-1 contribution into \mathbf{C}_t. When a later query \mathbf{q} arrives, the matrix multiplies the query to produce a linear combination of stored values:

\mathbf{C}_t \mathbf{q} = \sum_{\tau \le t} \left( \text{(gating product for }\tau)\cdot \mathbf{v}_\tau (\mathbf{k}_\tau^\top \mathbf{q}) \right).

That is, each stored value \mathbf{v}_\tau contributes with weight proportional to its key's dot product with the query, exactly the behavior one wants for associative retrieval. The normalizer \mathbf{n}_t plays the role of the total key mass, and dividing by \mathbf{n}_t^\top \mathbf{q} yields a relative weighting among values.

From a separability perspective, the paper cites the covariance update rule's optimality (Dayan; Sejnowski) for maximizing separability of retrieved binary vectors, which can be interpreted as maximizing signal-to-noise in retrieval when keys have zero mean. In practice this means that, within the representational bandwidth of a $d$-dimensional key and value space, the covariance update is an efficient way to store many associations: keys project queries to scalars that gate contributions of corresponding values, and the matrix aggregates these contributions compactly.

There is an important trade-off: covariance updates store pairwise key-value associations (a rank-1 deposit per stored item), which can be accumulated linearly over time. In contrast, full attention re-evaluates all pairwise interactions between stored tokens and the current query at each step, at quadratic cost, enabling more complex forms of separability. The paper notes that higher separability is possible when limiting retrieval to pairwise interactions and conceding quadratic complexity like attention. Thus covariance-based fast weights provide a powerful, linear-time, compressive memory that captures many associative scenarios, but they are not a free substitute for the full combinatorial power of quadratic attention in every setting.

# Expressivity and state tracking: RNNs vs Transformers/SSMs

A recurrent architecture that includes memory mixing — that is, hidden-to-hidden recurrent connections that allow the content of one time step's state to influence gate decisions in the next — can implement forms of stateful computation that architectures without such mixing struggle to emulate. The paper emphasizes that memory mixing, together with exponential gating, allows sLSTM to solve state-tracking problems that Transformers and many State Space Models (SSMs) cannot.

Memory mixing enables conditional writes and conditional control flow: the hidden state can carry compressed summary information that influences which future inputs are stored, forgotten, or emphasized. Exponential gates make these decisions flexible in scale, and the normalizer maintains coherent retrievals. In the synthetic experiments reported, models without memory mixing (e.g., vanilla Transformers or SSMs) fail on formal languages that require precise state updates (such as parity-style or certain regular-grammar tasks). By contrast, xLSTM variants that retain memory mixing (sLSTM or sLSTM components inside blocks) can maintain and update discrete-like internal states, which is essential for algorithmic tasks and stateful sequence understanding.

Thus expressivity here is not only about representational width but about the ability to implement sequential control and iterative state updates over time. The LSTM tradition — additive cell updates, gating, and recurrent mixing — remains particularly well-suited to such computations. xLSTM preserves and strengthens these core mechanisms (via exponential gating and novel memory designs), enabling both richer associative storage (mLSTM) and robust state tracking (sLSTM).

# Limits of pairwise interactions vs quadratic attention

It is important to be explicit about what the covariance (outer-product) memory can and cannot do compared to full attention. The covariance update stores pairwise key-value structure: each stored item contributes a rank-1 matrix \mathbf{v}\mathbf{k}^\top that, when multiplied by a query, yields contributions weighted by \mathbf{k}^\top \mathbf{q}. This produces the familiar attention-like weighting of values by key-query similarity, but implemented incrementally and with linear time per time step.

Quadratic attention, however, recomputes all pairwise similarities between the current query and every stored key in the context window at query time and (typically) applies a softmax normalization. That recomputation enables richer, possibly non-linear combinations of stored items because attention can dynamically reweight any stored item according to the exact current context and can leverage softmax non-linearities to produce sparse, competitive selection. The paper acknowledges that higher separability — meaning the ability to disambiguate many stored patterns — can be achieved if one is willing to pay the quadratic cost of attention (e.g., by limiting retrieval to pairwise interactions and incurring quadratic complexity).

Covariance-based fast weights represent an attractive compromise: they capture the essential pairwise interaction between key and query in a compressed, incremental way, and when combined with normalization they approximate attention-like retrieval with linear scaling in sequence length. But for problems where the highest degree of discriminative separability between many similar stored items is required, quadratic attention retains an advantage.

# Cover’s Theorem and the role of up-projection in separating contexts

Cover’s Theorem states that a nonlinearly separable pattern in a low-dimensional space is more likely to become linearly separable when mapped nonlinearly into a higher-dimensional space. The xLSTM architecture leverages this insight in the design of its residual blocks: each block first (or last) applies linear up-projection to a higher-dimensional latent space, lets the recurrent memory summarize the past nonlinearly in that high-dimensional space, applies nonlinearities there, and then projects back. Two variants are used in the paper: a post up-projection residual block (nonlinear summarize in original space, then up-project and nonlinearity) and a pre up-projection block (project up first, then summarize nonlinearly in the high-dimensional space). The paper prescribes using post up-projection for sLSTM blocks and pre up-projection for mLSTM blocks.

Why does up-projection help? Intuitively, mapping inputs into a higher-dimensional latent space creates more degrees of freedom to encode distinctions among past histories. Memory operations performed in that higher-dimensional space can therefore separate contexts that would be conflated in a smaller-dimensional memory. For mLSTM in particular, placing the matrix memory in the higher-dimensional space enlarges the expressive capacity of the covariance memory: each stored outer product then lives in a larger matrix space, allowing more complex associative patterns to be represented and separated. For sLSTM, post up-projection means that the scalar memories operate on features that have already been expanded and nonlinearly mixed, permitting the scalar normalization and re-weighting to operate on more expressive summaries.

In practice, this use of up-projection aligns with the block design choices in modern large models: up-projecting into a "wider" latent space before a powerful nonlinear/computational unit often improves the ability to linearly separate different sequence histories when the unit finally maps back down. The experiments in the paper — notably language-modeling and associative recall results — indicate that combining these up-projection strategies with the modified LSTM memories leads to markedly improved separability of contexts and better retrieval behavior in long sequences.

# Closing intuition and how the pieces fit together

xLSTM brings three tightly coupled design ideas together to address concrete LSTM shortcomings and to approach the strengths of attention-based systems while keeping linear time and constant working memory:

1. Exponential gates plus running normalizers make stored contents immediately comparable and re-weightable. They provide a principled mechanism for later inputs to revise the effective contribution of earlier writes, while the stabilizer m_t prevents numerical issues.

2. Covariance-based matrix memory (fast weights) accumulates associative key-value outer products so that retrieval via matrix-vector multiplication yields attention-like weighted sums, but computed incrementally with linear per-step cost. The normalizer here plays the exact role of an attention denominator, converting a sum into a relative weighting.

3. Up-projection into higher-dimensional latent spaces (before or after the memory operation depending on the memory type) implements an application of Cover’s Theorem: it increases the chance that different past histories become separable by a linear readout, thereby improving predictive power.

These elements interact: exponential gating enables flexible write strengths and decay behaviors that the covariance memory uses to sculpt the stored associative matrix; the normalizer ensures those sculpted contents are read as normalized, relative combinations (as in attention); and up-projection supplies the representational capacity needed for fine-grained separations. Empirically, the paper shows that this combination yields improved performance on state-tracking formal tasks, associative recall benchmarks, and large-scale language modeling and extrapolation experiments, indicating that the theoretical motivations above translate into practical gains.

Limitations, Risks, and Open Problems

# Non-parallelizable sLSTM and current kernel speed gaps
One of the core strengths introduced for sLSTM is memory mixing: sLSTM keeps the traditional hidden-to-hidden (recurrent) connections that allow different scalar memory cells to interact across time. This memory mixing underlies the expressiveness of LSTM-style RNNs for problems that require state tracking or revisions to stored information. However, those same recurrent dependencies make sLSTM inherently sequential: the update at time $t$ depends on $h_{t-1}$ and the mixed memories, so the forward pass cannot be trivially parallelized across time steps as is possible for models that remove hidden–hidden recurrence.

The paper is explicit about this tradeoff. Because sLSTM preserves memory mixing, it cannot be converted into a fully parallel, scan-free implementation in the same way mLSTM can. Practically, that means wall-clock throughput for long unbatched sequence generation will remain limited by sequential compute unless specialized kernels are used. The authors mitigated this in part by developing a highly optimized CUDA kernel with GPU memory optimizations down to the register level; their implementation narrows the gap so that sLSTM is typically less than two times slower than their parallel mLSTM implementation. While this is an important engineering achievement, the remaining factor-of-two slowdown still represents a bottleneck for production usage at very large scales or for low-latency inference on single streams. Furthermore, because the kernel is specialized, portability and maintainability can be concerns when deploying across different hardware or frameworks.

Open problems arising here include whether one can retain the expressivity of memory mixing while achieving closer-to-parallel runtimes, and how to broaden the set of available, well-optimized kernels for sLSTM on diverse accelerators. The paper demonstrates a pragmatic path—low-level CUDA optimization—but leaves room for further kernel engineering and algorithmic alternatives that reduce the sequential dependency without losing the capacity for state revision.

# Unoptimized mLSTM kernels and opportunities for acceleration
Unlike sLSTM, the mLSTM design removes hidden–hidden recurrence (no memory mixing) and replaces scalar memory with a matrix memory $\mathbf{C}_t \in \mathbb{R}^{d\times d}$ updated by a covariance rule:
\[
\mathbf{C}_t = f_t\,\mathbf{C}_{t-1} + i_t\,\mathbf{v}_t \mathbf{k}_t^\top.
\]
Because mLSTM eliminates inter-step hidden mixing, its recurrence can be rewritten in a parallel form suitable for batched matrix operations on GPUs. In principle, this makes mLSTM parallelizable in time and amenable to optimized kernels just like attention-based models. The paper notes that mLSTM is “parallelizable analog to FlashAttention or GLA.”

In the current implementation, however, mLSTM kernels are not fully optimized. The authors report that their mLSTM implementation is about four times slower than FlashAttention or the efficient scan used in Mamba. This is a concrete performance gap: while the algorithmic structure supports parallelism, the implementation has not yet taken full advantage of the same low-level optimizations (memory layout, fused kernels, tiling strategies) that make FlashAttention so fast.

This is both a limitation and an opportunity. Bringing mLSTM kernel performance to parity with high-performance attention kernels would reduce inference and training overhead and make mLSTM a far more practical choice. The paper suggests that "faster CUDA kernels could be obtained in the vein of FlashAttention," pointing to a clear engineering direction: design fused, tiled, memory-efficient kernels for the $d\times d$ updates and retrievals, reduce bandwidth by careful blocking, and exploit hardware primitives for matrix multiply-accumulate. Achieving this requires low-level systems work but is fully consistent with the model’s algorithmic structure.

# Compute cost of d-by-d memory updates in mLSTM
mLSTM gains storage capacity by replacing scalar cell states with a matrix memory $\mathbf{C}_t$ of size $d\times d$. This makes retrieval a matrix–vector product and update a rank-one outer product scaled by gates, as in the covariance rule above. The gain in representational power is explicit: matrix memory enables storing and retrieving $d$-dimensional key–value pairs, which empirically improves performance on tasks involving rare tokens and associative recall.

The cost of this richer memory, however, is substantial: both the memory footprint and compute per time step scale with $d^2$. The paper frames this as a tradeoff between memory capacity and computational complexity. Although the matrix memory itself does not add learnable parameters (the update uses outer products of projected inputs and gating scalars), the $O(d^2)$ work for updates and the $O(d^2)$ elements to hold $\mathbf{C}_t$ are nontrivial for large $d$. In practice, the authors note that these matrix operations can be parallelized on GPUs and therefore the wall-clock overhead was only minor in their experiments, but the theoretical scaling remains a constraint.

This creates several practical risks. Training very large models with large $d$ will raise GPU memory pressure and increase FLOPs per token. For latency-sensitive inference, the $d\times d$ cost may dominate, especially when unbatched. Algorithmically, using matrix memory forces practitioners to choose $d$ as a knob that trades capacity against compute; an inappropriate choice can either underutilize model capacity or make training/inference prohibitively expensive.

# Forget-gate initialization sensitivity and training stability
The paper highlights that initialization of forget gates is important and can affect training stability. This sensitivity is closely tied to the dynamics introduced by exponential gating and by matrix memory updates that accumulate information over time. Exponential gates (input and possibly forget gates) can produce large multiplicative factors, and if not stabilized, these can cause numerical overflow or induce badly conditioned gradients. To address this, the authors introduce explicit stabilization: a stabilizer state $m_t$ and normalized gates defined by
\[
m_t = \max\big( \log(f_t) + m_{t-1}, \; \log(i_t) \big),
\]
and stabilized gates defined by exponentials shifted by $m_t$ so that their magnitudes are kept in a safe range. For mLSTM, they also normalize retrieved outputs by a normalizer $\mathbf{n}_t$ and lower bound the absolute dot product with the query by a threshold (typically 1.0) to prevent vanishing denominators.

Even with these mechanisms, the paper lists careful choice of forget-gate initialization as a limitation: a poor initialization can lead to exploding or vanishing contributions from past memory, which destabilizes learning. This sensitivity manifests both for scalar sLSTM (where multiplicative recurrence accumulates) and matrix mLSTM (where $\mathbf{C}_t$ integrates many outer products). Thus, an important risk during model development is that training might fail or converge to suboptimal solutions unless gate biases, learning rates, and stabilizer behavior are tuned.

Addressing this limitation requires methodical hyperparameter protocols and possibly more robust default initializations or adaptive schemes. The paper documents stabilization techniques that help, but it also notes that initialization remains a point of fragility.

# Potential memory overload at very long contexts and mitigation
A distinctive property of mLSTM is that its matrix memory $\mathbf{C}_t$ does not grow with sequence length: the memory size is fixed at $d\times d$ and each update is a weighted accumulation. This compressive memory is advantageous because it keeps working memory bounded independent of context window, enabling constant memory complexity with respect to sequence length. However, this fixed capacity raises the possibility of memory overload when faced with very long contexts containing many distinct items to remember: if too many key–value pairs are written into the same $d\times d$ memory without sufficient forgetting, signal from earlier items may be diluted or interfere.

The paper explicitly notes this potential limitation while also reporting empirical results that contexts up to length 16k did not appear to overload the memory for their models and tasks. Mitigations already built into the architecture include the forget gate acting as a decay (multiplying $\mathbf{C}_{t-1}$ by $f_t$) and the normalizer state $\mathbf{n}_t$ that keeps track of cumulative gate strength, with retrieval normalized by $\max\{|\mathbf{n}_t^\top \mathbf{q}_t|, 1\}$. These mechanisms aim to keep stored content balanced and retrieval stable.

Nonetheless, for application domains with extremely long horizons or highly diverse information streams, there is a risk that the fixed-size compressive memory will be insufficient. In such regimes, one must consider tradeoffs: increase $d$ (raising $d^2$ cost), tune forget dynamics more aggressively, or interleave other storage mechanisms. The paper does not prescribe a single remedy but flags this as an area where additional work could refine memory management.

# Need for broader hyperparameter and architecture search
The paper candidly acknowledges that, due to computational cost, they did not fully optimize architectures and hyperparameters, especially at larger scales. This is an important limitation: the strong experimental results reported for xLSTM already required careful design decisions (exponential gating, stabilizers, normalizers, block selection between pre/post up-projection), and the authors expect that further gains are achievable through systematic search.

Broad hyperparameter and architecture sweeps are needed to (a) find robust initializations for gates and stabilizers, (b) determine optimal values of $d$ that balance capacity and compute, (c) tune the ratio of mLSTM to sLSTM blocks (xLSTM[$a$:$b$]) for different tasks, and (d) adapt residual backbone choices (pre-/post-up projection) to particular data distributions. The experiments already show that different block compositions (e.g., xLSTM[1:0] vs xLSTM[7:1]) have measurable effects across benchmarks, indicating this is a productive search space.

Because these searches can be computationally expensive, a practical risk is that small teams or labs without large compute budgets may not be able to find ideal configurations, potentially leaving xLSTM under-optimized compared to more established architectures that already benefit from extensive tuning. The paper therefore frames additional hyperparameter and architecture optimization as a clear, necessary next step to unlock the model class’s full potential.

# Future directions: improved kernels, hybrid models, and new domains
The paper both identifies limitations and sketches promising directions to address them. On the systems side, there is an opportunity for kernel engineering: designing fused, memory-efficient CUDA kernels for mLSTM that mirror the performance of FlashAttention would reduce the current implementation gap (the reported ~4x slowdown) and make mLSTM more practical. For sLSTM, further work could reduce the remaining sequential overhead, either by further low-level optimization of the specialized CUDA kernel or by algorithmic compromises that preserve much of memory-mixing expressivity while enabling more parallel computation.

On the modeling side, xLSTM already provides hybrid choices: the architecture accepts mixtures of mLSTM and sLSTM blocks (xLSTM[$a$:$b$]) and supports multiple cells and heads in sLSTM, giving a rich space of hybrid designs that balance memory mixing against parallelizability. The empirical results show that different mixtures produce different tradeoffs across tasks; therefore systematic exploration of these hybrids is a promising research direction. In addition, the stabilization techniques (stabilizer state $m_t$, normalizer $\mathbf{n}_t$, and thresholded normalization in retrieval) are concrete handles that can be refined or made adaptive.

Finally, the paper points to broader application domains where xLSTM might have impact—reinforcement learning, time series forecasting, and modeling physical systems—because of the compressive, constant-memory behavior and the improved capacity for state tracking. Extending xLSTM to these domains will require domain-specific evaluations and possibly architecture or training adaptations, which the authors identify as open work.

Taken together, these directions form a concrete research agenda that stays within the design choices and empirical observations of the paper: (i) kernel and systems optimization to close runtime gaps, (ii) careful hyperparameter and architectural search to stabilize and scale training, (iii) exploration of hybrid block mixtures to trade off expressivity and parallelism, and (iv) evaluations in new problem domains to validate the architecture’s practical benefits.

# Summary of risks and open problems
To summarize the primary limitations and risks documented in the paper: sLSTM’s memory mixing makes it sequential and thus slower unless specialized kernels are used; current mLSTM kernels are not yet as optimized as state-of-the-art attention kernels; mLSTM’s $d\times d$ memory imposes $O(d^2)$ compute and storage costs that must be managed; exponential gating and accumulation behavior create sensitivity to forget-gate initialization and require stabilizers; fixed-size compressive memory may be overloaded in extreme long-context regimes; and the architecture and hyperparameter space remain under-explored due to resource costs.

Each of these limitations is paired in the paper with partial mitigations or clear research directions: stabilization mechanisms and normalizers to improve numerical behavior, specialized CUDA kernels for sLSTM and the potential for FlashAttention-style kernels for mLSTM, hybrid block compositions, and extensive hyperparameter/architecture search. These are precisely the avenues by which xLSTM can be matured from a promising architecture to a widely deployable family of models.

Conclusion and Resources

# Key takeaways on performance, scalability, and efficiency

xLSTM extends the classical LSTM ideas (constant error carousel and gating) along two orthogonal directions: (i) exponential gating with associated normalization and stabilization, and (ii) richer memory structures (a scalar sLSTM variant and a matrix mLSTM variant). These changes are implemented inside residual block backbones and stacked into full xLSTM architectures.

Empirically, xLSTM closes the gap between recurrent-style memory models and current Transformer / State Space Model (SSM) approaches when scaled. In the paper’s experiments, xLSTM models trained on the same corpora outperform a wide range of contemporaneous methods (Transformers, SSMs, and recent RNN-style models) in validation perplexity after training on 15B tokens from SlimPajama, and continue to show strong performance when trained on 300B tokens. The scaling-law analysis shows that xLSTM follows a similar power-law scaling as other families but with a favorable offset: as model size grows, xLSTM is predicted to remain competitive and often superior to the compared Transformer and SSM baselines.

From a complexity viewpoint xLSTM inherits an important advantage of RNN-style and linear-attention models: its computation cost is linear in sequence length and its working memory (model-state memory) is constant with respect to sequence length. This contrasts with standard Transformers whose attention is quadratic in context length. Concretely, mLSTM and sLSTM produce compressed memories that do not grow with the processed context, enabling higher decoding throughput and larger batch sizes during generation. In the paper’s inference measurements, recurrent models including xLSTM scale linearly in generation time while a Transformer (Llama) shows quadratic scaling; xLSTM attains higher maximal throughput because it uses less per-sequence memory.

At the same time, there are clear computational trade-offs. The mLSTM’s matrix memory increases per-step arithmetic cost because it maintains and updates a $d \times d$ matrix; although these updates are parameter-free and parallelizable on GPUs, they are heavier than scalar updates and so require optimized kernels for best wall-clock performance. The sLSTM incurs memory-mixing (hidden–hidden) recurrence that prevents simple parallel scan implementations and thus, in practice, needs specialized CUDA kernels to be competitive. The paper documents these practical limits (sLSTM kernel less than two times slower than mLSTM in their optimized implementation; mLSTM implementation about 4x slower than FlashAttention due to unoptimized kernels).

# Guidance on selecting sLSTM vs mLSTM for tasks

Choose sLSTM when the task benefits from fine-grained state tracking and memory mixing. The sLSTM variant preserves the classic LSTM notion of scalar cell states with recurrent mixing across cells and hidden states; it also integrates exponential gating and the new normalizer/stabilizer constructs. Because of memory mixing, sLSTM can revise prior storage decisions via the gated additive recurrence and is particularly well suited for tasks that require:

- Stateful tracking of complex evolving internal state, for example program evaluation, entity tracking in narratives, or tasks that require maintaining and revising stored variables over time.
- Situations where recurrent inter-cell mixing (hidden–hidden recurrence) is essential to represent relational or sequential dependencies that a memory-less parallelizable layer cannot express.

Mathematically, sLSTM uses exponential gating in its input gate and (optionally) forget gate:
- $i_t = \exp(\tilde{i}_t)$ and $f_t = \sigma(\tilde{f}_t)$ or $f_t = \exp(\tilde{f}_t)$,
and keeps a normalizer state $n_t$ so outputs are normalized ($\tilde{h}_t = c_t / n_t$). The normalization and stabilization mechanism prevents numerical overflow while preserving gradients and overall behavior.

Choose mLSTM when the task requires large storage capacity per time step and higher parallelism. The mLSTM replaces the scalar cell with a matrix memory $\mathbf{C}_t \in \mathbb{R}^{d\times d}$ and updates it with a covariance (outer-product) rule:
- $\mathbf{C}_t = f_t\,\mathbf{C}_{t-1} + i_t\,\mathbf{v}_t \mathbf{k}_t^\top$,
with retrieval via matrix-vector multiplication $\tilde{\mathbf{h}}_t = \mathbf{C}_t \mathbf{q}_t / \max\{|\mathbf{n}_t^\top \mathbf{q}_t|,1\}$. This design gives mLSTM much larger effective per-step memory capacity (suitable for associative recall tasks and rare-token prediction) and allows a fully parallel reformulation (no hidden–hidden recurrence), which makes it appropriate when:

- High-capacity associative storage and retrieval are required (e.g., multi-query associative recall, rare-token prediction).
- Parallelization and GPU-friendly implementations are priorities (mLSTM can be implemented as matrix operations amenable to batching and kernel optimization).
- Large-scale LLM training where parallel throughput and constant per-sequence memory footprint are important.

Practical hybrid strategy: the xLSTM architecture supports mixing blocks built from both variants. The notation xLSTM[$a$:$b$] denotes the ratio of mLSTM-based to sLSTM-based blocks. The experiments showed that mixing (e.g., xLSTM[7:1]) can leverage the mLSTM’s capacity while retaining some sLSTM memory-mixing benefits; in some experiments pure mLSTM (xLSTM[1:0]) performed best on language tasks and rare-token evaluation, while adding sLSTM blocks helped on tasks requiring state-tracking or associative recall at high difficulty. Also note the block design choice: sLSTM blocks are used with post up-projection residual blocks while mLSTM blocks use pre up-projection residual blocks, aligning memory capacity with embedding dimension.

# Potential impact areas: reinforcement learning, time series, physical systems

Because xLSTM restores and extends LSTM’s core strengths while scaling competitively, it is naturally well suited to domains where LSTMs historically excelled but where modern workloads demand large models, long contexts, or parallel training. The paper highlights several application domains:

- Reinforcement learning: LSTMs have been central in RL agents that need to remember past observations and long-term strategies (e.g., AlphaStar, OpenAI Five). xLSTM’s improved capacity and gating allow stronger state representation and longer effective memory, which can benefit complex policy learning and partial-observation environments.

- Time series and hydrological modeling: LSTMs remain practically important for physical and environmental systems where compact, compressive memories are favorable. xLSTM’s linear-in-context compute and constant memory make it appealing for industrial deployments and edge devices, while its improved storage capacity (especially mLSTM) may better capture long-range dependencies in physical processes.

- Modeling physical systems and controllers: tasks such as magnetic controller models for nuclear fusion or complex control tasks that require precise state tracking and abstraction can use xLSTM to combine expressive memory mixing (sLSTM) or high-capacity associative storage (mLSTM) with scalability.

Across these areas, two practical advantages stand out: (i) constant per-sequence memory helps deployment on memory-constrained hardware and enables larger batch sizes at decoding time, and (ii) the ability to mix memory designs (sLSTM vs mLSTM) provides a handle to balance expressivity and throughput according to domain constraints.

# Suggested readings to deepen understanding

To understand xLSTM in context and to study the key ingredients it builds upon, the following references (all discussed in the paper) are recommended, organized roughly by topic and with the reason to read each:

Foundational recurrent models and gating
- Hochreiter & Schmidhuber (1991, 1997): the original LSTM formulations — read to learn the constant error carousel, gating intuition, and why gating combats vanishing gradients.
- Gers et al. (2000): forget gate development — useful background on gate design.

Fast weights, associative memory, and covariance updates
- Sejnowski (1977), Dayan (1991): covariance update rule and associative memories — foundational for the mLSTM outer-product update.
- Schmidhuber (1992), Schlag et al. (2021): Fast Weight Programmers — related approach to learnable fast associative memory.

Transformers and large-scale sequence models
- Vaswani et al. (2017): the Transformer — necessary to understand the parallel self-attention paradigm that xLSTM is compared to.
- Kaplan et al. (2020) and Brown et al. (2020): scaling laws and GPT-style large autoregressive models — relevant for the paper’s scaling-law comparisons.

State Space Models and linear/sequential alternatives
- Gu et al. (2021, S4) and subsequent SSM work (S5, Mamba, etc.): read these to understand the SSM family the paper compares xLSTM against, and to contrast recurrence/recurrence-free designs.

Linear attention, RWKV, and gated RNNs
- Katharopoulos et al. (2020) (Linear Transformer), Peng et al. (RWKV series), Sun et al. (Retention), Qin et al. (HGRN/HGRN2), Yang et al. (GLA): these works show different linear- or gating-based strategies to address Transformer quadratic costs and are the closest contemporaries to xLSTM.

Theoretical and practical considerations
- Cover (1965): Cover’s Theorem — motivates the use of high-dimensional nonlinear embeddings inside residual blocks.
- Merrill et al., Deletang et al., and related works cited in the paper on expressivity: examine why recurrence and memory mixing matter for certain formal languages and state-tracking tasks.

Practical evaluation and benchmarks
- SlimPajama (Soboleva et al.): the preprocessed corpora used in the paper’s experiments.
- PALOMA benchmark (Magnusson et al.): used to probe domain-level generalization across many text domains.
- Long Range Arena (Tay et al.): use this benchmark to test long-context performance.

Suggested learning path: re-familiarize with the original LSTM papers to ground intuition, then study Fast Weight Programmers / covariance memory literature to understand mLSTM’s outer-product update. Next, contrast Transformers and SSMs to appreciate architectural trade-offs (parallelism, complexity, and expressivity). Finally, inspect the xLSTM codebase and reproduce small-scale experiments (e.g., synthetic tasks, associative recall) before attempting large-scale runs.

# Final practical notes and open challenges

The xLSTM proposal presents a compelling blend of classic LSTM strengths and modern large-scale design practices. Practitioners should be mindful of the following when adopting xLSTM:

- Kernel optimization matters. The mLSTM’s matrix updates and the sLSTM’s recurrent mixing require efficient GPU implementations for wall-clock competitiveness. The paper reports that unoptimized kernels made mLSTM about 4x slower than FlashAttention; optimized kernels would reduce this gap.
- Hyperparameters and initialization require care. In particular, forget-gate initialization and stabilization for exponential gates are crucial to numerical stability and training dynamics.
- Memory scaling trade-offs. The mLSTM memory is independent of sequence length but finite in capacity; the paper observed no problems up to 16k contexts, but very long contexts could overload a fixed-size matrix memory unless capacity is scaled appropriately.
- Further tuning remains. The authors note that they did not exhaustively optimize architectures and hyperparameters for the largest experiments; additional engineering and search should further improve results.

If your goal is to leverage high-capacity associative memory with parallel training and generation, start with mLSTM-based xLSTM blocks and explore xLSTM[1:0] and variants. If your application demands stateful processing or complex state revision and you can tolerate more sequential compute or build specialized kernels, incorporate sLSTM blocks or hybrid compositions.

For code, experiments, and the detailed implementations discussed in the paper, see the project repository at https://github.com/NX-AI/xlstm.

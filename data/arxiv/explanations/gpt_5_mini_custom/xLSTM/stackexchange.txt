\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### How exactly does exponential gating in sLSTM enable "revision" of stored information?
Question:
In the xLSTM paper, the sLSTM replaces sigmoid gates with exponential gates for the input (and optionally for the forget):
- Cell: c_t = f_t c_{t-1} + i_t z_t
- Normalizer: n_t = f_t n_{t-1} + i_t
- Output: h_t = o_t (c_t / n_t)
with i_t = \exp(\tilde{i}_t) and f_t = \sigma(\tilde{f}_t) or \exp(\tilde{f}_t).

The paper claims this enables revision (e.g., in a nearest-neighbor-like task), where a later, better match can overwrite an earlier stored value. Conceptually, why does moving from bounded gates in \([0,1]\) to unbounded positive gates via \exp allow more effective revision? Is the key that the normalized output c_t / n_t acts like a normalized weighted average where later large i_t can dominate earlier contributions? Could someone walk through a simple two-step example that shows how sLSTM with exponential i_t revises a previous z_{t-1} with a new z_t, whereas standard LSTM with sigmoids struggles?
Answer:
Short answer: yes — exponential gating turns the cell output into a positive weighted average whose weights are unbounded, so a later gate value can be made arbitrarily large and thus dominate the normalizer. That gives a clean mechanism to "revise" stored content: a later, better match can overwhelm earlier contributions instead of being stuck behind the hard $[0,1]$ ceiling of sigmoid gates and the squashing of the usual LSTM output.

Walkthrough with a simple two-step example (scalar case) to make this concrete.

Set up (following the sLSTM equations in the paper). At time $t-1$ we store $z_{t-1}$, at time $t$ we see a new candidate $z_t$ and want to revise to keep $z_t$ if it is better.

sLSTM (exponential input gate $i_t = \exp(\tilde{i}_t)$, normalizer $n_t$, output $\tilde{h}_t = c_t / n_t$):
- $c_{t-1} = i_{t-1} z_{t-1}$
- $n_{t-1} = i_{t-1}$
- If forget is $f=1$ (no decay), then
  $c_t = f c_{t-1} + i_t z_t = i_{t-1} z_{t-1} + i_t z_t$
  $n_t = f n_{t-1} + i_t = i_{t-1} + i_t$
  output (pre-output scalar) $\tilde{h}_t = c_t / n_t = \frac{i_{t-1} z_{t-1} + i_t z_t}{i_{t-1} + i_t}$.

This is exactly a weighted average of $z_{t-1}$ and $z_t$ with positive weights $i_{t-1}, i_t$. Because $i$ are produced by an exponential, $i_t$ can be arbitrarily large (e.g. $100, 1000$) relative to $i_{t-1}$. If $i_t \gg i_{t-1}$, the quotient tends to $z_t$:
$\displaystyle \lim_{i_t / i_{t-1} \to \infty} \frac{i_{t-1} z_{t-1} + i_t z_t}{i_{t-1} + i_t} = z_t.$

So sLSTM can "overwrite" the previously stored value by producing a very large input gate on a later better match: the new term's weight dominates the normalizer and the average, yielding the later $z$ almost exactly.

Contrast with standard LSTM with sigmoid gates ($i_t \in (0,1)$, forget $f_t \in (0,1)$, and output typically $h_t = o_t \psi(c_t)$ with $\psi = \tanh$). Using the same two-step scenario and $f=1$:
- $c_{t-1} = i_{t-1} z_{t-1}$
- $c_t = i_{t-1} z_{t-1} + i_t z_t$, but now $i_{t-1}, i_t \le 1$
- hidden pre-output is typically $\psi(c_t) = \tanh(c_t)$ (or some other squashing)

There are two important differences that limit "revision" power here:

1) Bounded gate magnitudes. Because each $i$ lies in $(0,1)$, the later input $i_t$ cannot grow arbitrarily relative to $i_{t-1}$. If $i_{t-1}$ was already near $1$ (strong earlier encoding), the later $i_t$ can at most match it, so you cannot make the later term dominate by orders of magnitude. The range of possible weight ratios $i_t / i_{t-1}$ is limited by the sigmoid saturations.

2) Nonlinear squashing mixes contributions nonlinearly. Even if $i_t$ is somewhat larger, the sum $c_t = i_{t-1} z_{t-1} + i_t z_t$ is then passed through a squash like $\tanh$. This squash compresses large sums and blends components; obtaining an output that closely equals $z_t$ requires a particular and often unattainable configuration of $c_t$ (and possibly an output gate $o_t$) because you are trying to invert the squash to place the result near $z_t$. In practice this makes exact overwriting unreliable.

Numerical illustration. Pick numbers $z_{t-1}=0.0$ and $z_t=1.0$ (simple nearest-neighbor style retrieval):
- Standard LSTM with sigmoid gates: suppose $i_{t-1}=0.9$ (previous strong store) and the best possible later input is $i_t \le 0.99$ (sigmoid max $\approx 1$). Then $c_t \approx 0.9\cdot 0 + 0.99\cdot 1 = 0.99$, and $\psi(c_t)=\tanh(0.99) \approx 0.756$ — not exactly $1$, and if the earlier $z_{t-1}$ were nonzero the blend would be unavoidable. If $i_{t-1}$ were $0.99$ as well, the best later $i_t\approx 0.99$ cannot dominate.

- sLSTM with exponential gate: let $i_{t-1}=\exp(a)=1$ (say) and we can set $i_t=\exp(b)=100$ by choosing $b$ large. Then $c_t = 1\cdot 0 + 100\cdot 1 = 100$, $n_t = 1 + 100 = 101$, so $\tilde{h}_t = 100/101 \approx 0.9901$ — already extremely close to $z_t=1$. Pushing $i_t \to 1000$ makes $\tilde{h}_t \to 0.999$, arbitrarily close. That demonstrates the controllable, strong revision.

Why the normalization is crucial. Without dividing by $n_t$, exponential gating alone would blow up the raw cell $c_t$ and training/stability would suffer. The normalizer $n_t$ keeps scale consistent and makes the hidden pre-output a proper convex-like weighted average of the inputs. The exponential gives you an interpretable soft attention weight (positive and unbounded) while normalization turns the memory into a retrieval mechanism where very large future weights can effectively select or overwrite older entries.

Broader conceptual connection. This is analogous to attention or weighted averaging: attention produces positive scores that are normalized (softmax) so one token can dominate if its score is much larger than others. sLSTM's exponential gate + normalizer implements a recurrent, causal variant of that idea where the gate value acts like an attention score for each stored item. Using $\exp$ makes scores unbounded and thus allows a later "high-confidence" score to dominate past entries; using sigmoid (bounded) limits how much a newer observation can outweigh an earlier one.

Stabilization note (from the paper). Taking exponentials can overflow, so the paper uses log-space stabilizers (the $m_t$ trick) that preserve exact semantics while avoiding numerical issues. That does not change the revision mechanism described above.

Summary. Moving from bounded sigmoid gates to exponential (positive, unbounded) gates plus a normalizer makes the cell output behave like a normalized, positive-weighted average. Because weights are unbounded, a later large gate can dominate earlier contributions and therefore revise/overwrite stored information reliably. Sigmoid gates, being capped in $[0,1]$ and usually followed by a squash ($\tanh$), cannot do this with the same strength or reliability.

### Why does dividing by the normalizer n_t make sLSTM invariant to gate scaling and analogous to attention normalization?
Question:
In sLSTM we have n_t = f_t n_{t-1} + i_t and h_t = o_t (c_t / n_t). If I unroll c_t, I get a sum of past inputs z_s weighted by i_s times products of future forgets. The division by n_t looks like normalizing by the sum of (effective) weights, similar to attention's softmax normalization. 

- Is it correct that c_t / n_t is a normalized weighted average of past z_s, where weights are proportional to i_s \prod_{u=s+1}^t f_u?
- If so, is this why multiplying all gates by a common factor does not change c_t / n_t (up to the stability device), making the representation invariant to absolute gate scale?
- Can someone provide a short derivation showing c_t / n_t equals the normalized convex combination when f_t, i_t > 0, and explain how this contributes to the "revision" capability?
Answer:
Yes — your intuition is correct and the paper's sLSTM design makes this precise. If the gates are positive then $c_t / n_t$ is exactly a normalized weighted average of past inputs, the normalization makes the representation invariant to common multiplicative rescaling of the raw gate magnitudes (after the stabilizer), and the multiplicative “future forgets” give the model the ability to revise past contributions.

Derivation (unrolling the recurrences). From the sLSTM forward rules (Equation (5) in the paper),
$$c_t = f_t c_{t-1} + i_t z_t,\qquad n_t = f_t n_{t-1} + i_t,$$
with the convention that $c_0 = n_0 = 0$. Unroll these recurrences backward to time $s$:

$$c_t = \sum_{s=1}^t \left( i_s z_s \cdot \prod_{u=s+1}^t f_u \right),$$
$$n_t = \sum_{s=1}^t \left( i_s \cdot \prod_{u=s+1}^t f_u \right).$$

Here $\prod_{u=s+1}^t f_u = 1$ when $s = t$ (empty product). These identities follow by straightforward induction: each term $i_s z_s$ is carried forward multiplicatively by every forget gate $f_u$ that comes after time $s$ until time $t$.

Normalized weighted average. Divide the two sums:

$$\frac{c_t}{n_t} = \sum_{s=1}^t w_s z_s,\qquad\text{where}\qquad w_s = \frac{i_s \cdot \prod_{u=s+1}^t f_u}{n_t}.$$

Because every term in the denominator equals the corresponding unnormalized weight in the numerator (without the $z_s$ factor), the $w_s$ are nonnegative and sum to $1$, so $c_t / n_t$ is a convex (normalized) combination of the past inputs $z_s$ whenever all $i_s, f_u > 0$. This is exactly the same algebraic structure as attention: the numerator is a weighted sum of “values” $z_s$ and the denominator is the sum of the (positive) unnormalized weights, i.e. a normalization like softmax/attention but here produced by multiplicative gates rather than explicit dot-product scores passed through softmax.

Invariance to common gate scaling (and role of the stabilizer). Suppose you multiply the raw (positive) $i$ and $f$ values by a common multiplicative factor. If you literally multiply the finalized gates $i_t$ and $f_t$ by a factor that depends on time in a complicated way, the ratio $c_t / n_t$ need not be invariant. The invariance the paper refers to is about multiplying the raw gate logits (or equivalently adding the same offset to the logs) before the stabilization step, which the stabilization removes. Concretely, sLSTM stabilizes exponential gates via the scalar $m_t$:

$$m_t = \max\!\big(\log f_t + m_{t-1},\ \log i_t\big),$$
$$i'_t = \exp\!\big(\log i_t - m_t\big),$$
$$f'_t = \exp\!\big(\log f_t + m_{t-1} - m_t\big).$$

If you add a constant $b$ to both $\log i_s$ and all subsequent $\log f_u$ (i.e. multiply the un-stabilized exponentials by $\exp(b)$), then $m_t$ increases by $b$ as well, and the stabilized gates $i'_t$ and $f'_t$ remain unchanged. Algebraically adding the same constant to all arguments of the exponentials is absorbed by $m_t$ and cancels in $i'_t$ and $f'_t$, so the effective weights $i'_s \cdot \prod f'_u$ that define the terms in numerator and denominator are unchanged. Thus, after stabilization the ratio $c_t / n_t$ is invariant to a common multiplicative scale of the raw exponential gates. Intuitively the stabilizer forces the model to operate on relative magnitudes of gate strengths rather than absolute scale, so only relative strengths determine the normalized weights $w_s$.

How this supports “revision.” The weights that determine how much each past $z_s$ contributes at time $t$ are $i_s$ times the product of all future forgets up to $t$. That product is multiplicative, so changing a forget gate $f_u$ at a future time $u$ affects the contribution of all earlier $z_s$ (for $s < u$) by multiplying their unnormalized weights by $f_u$. This multiplicative control enables the model to sharply down-weight or up-weight whole blocks of past memories after they have been written: by setting a small $f_u$ at some time $u$, the network effectively “forgets” (reduces the weight of) all earlier contributions; by keeping $f_u$ near $1$ it preserves earlier contributions. Because the memory is normalized by $n_t$, these adjustments are reflected as changes in the convex combination $c_t / n_t$ (i.e. the retrieved summary), which is why sLSTM can revise previously stored information in a smooth, attention-like way.

Summary. Unrolling shows $c_t / n_t$ is exactly a normalized weighted sum with weights proportional to $i_s \cdot \prod_{u=s+1}^t f_u$. The stabilizer makes those effective weights invariant to common multiplicative rescaling of the raw exponential gates, so the representation depends on relative gate strengths not absolute scale. The multiplicative chaining of future forgets gives a natural mechanism to revise past contributions, making the behavior analogous to attention normalization but implemented with LSTM-style gating dynamics.

### What is the precise effect of choosing f_t as sigmoid versus exponential in sLSTM and mLSTM?
Question:
Both sLSTM and mLSTM allow f_t to be either \sigma(\tilde{f}_t) or \exp(\tilde{f}_t). I am confused about:
- With f_t = \sigma(\tilde{f}_t) \in (0,1), we have a conventional decay. With f_t = \exp(\tilde{f}_t) > 0, f_t can be > 1, which seems to amplify older memory. When is amplification desirable versus harmful?
- How do the authors keep the product of forget gates stable when using exponentials, especially over long sequences?
- Are there recommended initializations/biases for \tilde{f}_t in the exponential case so that the effective time constant is reasonable? Any rules of thumb relating E[f_t] to an intended memory horizon?
Answer:
Short answer: using a sigmoid forget gate constrains per-step decay to $(0,1)$ so the cell state monotonically attenuates older contributions; using an exponential forget gate lets the per-step multiplier be any positive number (including $>1$) so old contributions can be amplified. Exponential gating enables the new behaviors in xLSTM (ability to revise stored values, covariance-style memory scaling, and improved associative capacity) but must be paired with the paper’s normalization/stabilization machinery (the normalizer $n_t$, the stabilizer $m_t$ / log-sum-exp, value normalization and lower-bounds) to avoid numerical blow-up or runaway amplification. Below I explain the intuition, how the authors keep products stable, and practical rules-of-thumb for initializing $\tilde f_t$ so the effective memory horizon matches your intent.

1) Intuition: sigmoid versus exp
- $f_t = \sigma(\tilde f_t)$ (sigmoid) lives in $(0,1)$. If you treat the homogeneous update $c_t = f_t c_{t-1} + i_t z_t$ with roughly constant $f$, contributions from time $t_0$ decay geometrically as $f^{t - t_0}$. This is the conventional “forget / decay” behavior: older memory is attenuated and never amplified.
- $f_t = \exp(\tilde f_t)$ (exponential) is strictly positive and can be $>1$. If $\tilde f_t > 0$ then $\exp(\tilde f_t) > 1$ and a past contribution can grow when multiplied repeatedly by such gates. That extra degree of freedom gives the model the capacity to “re-weight” or amplify older content when evidence later in the sequence indicates it should be emphasized (this is precisely what the paper uses to improve state-tracking / revision abilities).

When is amplification desirable vs harmful?
- Desirable: tasks that require revising earlier storage or boosting selected past signals (e.g., nearest-neighbor search or state-tracking where a later observation should retroactively strengthen a stored representation). Amplification lets the network implement multiplicative attention-like re-weighting across time without having to re-scan the whole sequence.
- Harmful: uncontrolled amplification will blow up internal activations, produce numerical overflow, and amplify noise (worse signal-to-noise for associative retrieval). Without normalization it also destabilizes gradients and training.

2) How the paper keeps long products stable
The paper pairs exponential gating with two main mechanisms that make repeated products safe and well-behaved.

First, a normalizer state $n_t$ that tracks the total gate-weight mass: for sLSTM/mLSTM they keep
$n_t = f_t n_{t-1} + i_t$ (scalar or vector). The hidden output uses a normalized quantity: for sLSTM $\tilde h_t = c_t / n_t$, and for mLSTM $\tilde h_t = C_t q_t / \max(|n_t^\top q_t|, 1)$. This division cancels common multiplicative growth across $c_t$ and $n_t$ so that multiplying both numerator and denominator by a large factor leaves their ratio stable. In other words, the normalizer keeps the effective retrieved value bounded even if intermediate cell entries grow.

Second, an explicit stabilizer $m_t$ based on log-sum-exp keeps exponentials numerically stable. The implementation rewrites and rescales the exponential gates via
$m_t = \max(\log f_t + m_{t-1}, \log i_t)$
and then replaces $i_t$ and $f_t$ by scaled versions
$i'_t = \exp(\tilde i_t - m_t),\quad f'_t = \exp(\log f_t + m_{t-1} - m_t).$
This is equivalent algebraically (it does not change network outputs or gradients) but avoids huge numbers by maintaining them in log-space and removing common factors. The paper cites Milakov et al. for this stabilization; essentially it’s numerically identical to doing computations in log-space and subtracting a running max (a standard log-sum-exp trick).

Other safety measures in the paper include layer-normalizing inputs to keys/queries (so keys have zero mean and controlled scale), using the absolute dot-product and a lower-bound ($\max\{|\mathbf{n}_t^\top \mathbf{q}_t|, 1\}$) in mLSTM retrieval to avoid division by tiny denominators, and optional clipping/thresholds that prevent tiny denominators from producing huge outputs.

Put differently: exponential gates give extra representational power, and the combination of (i) normalizer division, (ii) log-sum-exp stabilizer $m_t$, (iii) input normalization, and (iv) lower-bounding the denominator in retrieval keep long products numerically and statistically stable.

3) Initialization / bias choices and a rule-of-thumb mapping to memory horizon
The paper explicitly notes that “the initialization of the forget gates must be chosen carefully” (Limitations), but does not prescribe a single universal bias. You can, however, use a principled mapping between an intended per-step decay/amplification and the initial bias $\tilde f$ bias:

- If you want a target constant per-step multiplier $\bar f$ (so contributions decay as $\bar f^{\tau}$ with $\tau$ steps), then for the exponential case set the forget pre-activation bias $b_f$ so that $\mathbb{E}[f_t] \approx \bar f$. With $f_t = \exp(\tilde f_t)$, and if $\tilde f_t$ is dominated by a bias, simply set
$b_f \approx \log(\bar f)$.
For example, a desired per-step decay of half in $T$ steps corresponds to $\bar f = 2^{-1/T} = \exp(-(\log 2)/T)$, so set $b_f \approx -(\log 2)/T$.

- For the sigmoid case, because $f_t = \sigma(\tilde f_t)$, approximate $\sigma(\mu) \approx \bar f$ and invert to get the bias $\mu \approx \operatorname{logit}(\bar f) = \log\bigl(\bar f / (1-\bar f)\bigr)$. That is less convenient if you want small exponential decays (sigmoid cannot represent values $>1$ and its mapping to time constants is coarser).

A useful rule of thumb: think in terms of an effective time constant $\tau$ such that after $\tau$ steps a contribution is reduced by a factor of $e$ (or $1/2$). If you want an exponential per-step multiplier $\bar f$ satisfying $\bar f^\tau \approx e^{-1}$ then $\bar f \approx e^{-1/\tau}$. So pick $b_f \approx \log(\bar f) = -1/\tau$. Similarly, for a half-life $T_{1/2}$, set $b_f \approx -\log 2 / T_{1/2}$.

Examples:
- To have an effective time constant $\tau = 100$ steps (i.e., substantial memory for ~100 tokens), set $b_f \approx -0.01$ (since $-1/100 = -0.01$), so $\exp(b_f) \approx 0.99$.
- For a very long memory (e.g., $\tau = 1000$), set $b_f \approx -0.001$.

Some practical considerations and heuristics from the paper’s approach and experiments:
- Start biases slightly negative (so initial $f$ is slightly $<1$) rather than positive; even for exponential gating you typically want mild decay initially to avoid blow-up. The paper’s Limitations warns about careful initialization.
- Use layer-norms and small initial weight scales for gate inputs so the bias controls the mean gate behavior at the start of training.
- Monitor scales of $c_t$ and $n_t$ in early training runs; if normalized outputs are stable but gradients vanish, move bias towards less decay; if magnitudes blow up, increase negative bias (stronger decay) or tighten stabilizer.
- For mLSTM retrieval, the paper’s use of $\max\{|\mathbf{n}_t^\top \mathbf{q}_t|, 1\}$ ensures that very small normalizers don’t explode the final ratio. If you use different thresholds, you must adjust biases accordingly.

4) Summary: when to pick which gate function
If you want a conservative, always-damping cell that never multiplies older memory up, use sigmoid $f_t$. Use exponential $f_t$ when you want the model to be able to multiplicatively re-weight (including amplify) earlier stored information; this is where xLSTM gains its ability to revise and strengthen memories. But whenever you use exponential gating you must also use the normalizer $n_t$ and the log-space stabilizer $m_t$ (and input normalization / denominator bounding) exactly as the paper prescribes to avoid instability. Finally, choose initial biases so that the expected per-step multiplier matches a desired time-constant via the simple mapping $b_f \approx \log(\bar f)$ for the exponential case (or $b_f \approx \operatorname{logit}(\bar f)$ for sigmoid).

If you want, I can suggest concrete initial bias values for typical tasks (e.g., language modeling with context $2\mathrm{k}$, long-RNN tracking tasks), but the above gives the principled mapping and safety measures used in the paper.

### How does the m_t stabilizer make exponential gates numerically safe without changing gradients?
Question:
The paper defines a stabilizer state m_t and transforms the gates as:
- m_t = \max(\log f_t + m_{t-1}, \log i_t)
- i'_t = \exp(\log i_t - m_t) = \exp(\tilde{i}_t - m_t)
- f'_t = \exp(\log f_t + m_{t-1} - m_t)
Then replace i_t,f_t by i'_t,f'_t in the forward pass. They claim this does not change outputs nor gradients w.r.t. parameters.

I am missing the intuition and the proof sketch:
- Why does this particular choice of m_t rescale both c_t and n_t by the same factor so that c_t/n_t is unchanged?
- How do gradients remain identical when m_t depends on a non-differentiable max? Do we rely on subgradients or almost-everywhere differentiability? 
- Could someone show the algebra that c_t' = e^{-m_t} c_t and n_t' = e^{-m_t} n_t (or an equivalent invariant) and argue why dL/d\theta is preserved?
Answer:
Short answer: the stabilizer $m_t$ is chosen so that $i_t$ and $f_t$ are divided/multiplied by the same scalar $e^{m_t}$, therefore every accumulated quantity (cell $c_t$ and normalizer $n_t$) is scaled by the same factor $e^{-m_t}$ at time $t$. Because the hidden output uses the ratio $c_t/n_t$, that ratio is unchanged; algebraic induction shows $c'_t = e^{-m_t} c_t$ and $n'_t = e^{-m_t} n_t$ for all $t$. Gradients are preserved almost everywhere because the forward map from parameters to outputs is identical (so almost-everywhere derivatives coincide); the only non-differentiable points of the max are measure-zero tie events and can be handled with subgradients without changing the derivatives that matter in practice. Below is the compact proof sketch and the intuition.

Why this choice of $m_t$ rescales $c_t$ and $n_t$ by the same factor
$m_t$ is defined as
$$
m_t = \max\!\big(\log f_t + m_{t-1},\; \log i_t\big).
$$
Then the stabilized gates are
$$
i'_t = \exp(\log i_t - m_t) = i_t \, e^{-m_t},
$$
$$
f'_t = \exp(\log f_t + m_{t-1} - m_t) = f_t \, e^{m_{t-1}-m_t}.
$$

Intuition: $m_t$ is essentially the running log-normalizer that picks the larger of the two log-terms so that when you exponentiate after subtracting $m_t$ you do not overflow/underflow. The particular combination for $f'_t$ includes $+m_{t-1}$ so that the multiplicative effect of past normalizers is carried forward consistently. The point is that $i'_t$ and $f'_t$ are just $i_t$ and $f_t$ rescaled by factors involving $e^{-m_t}$ (and $e^{m_{t-1}}$ which will cancel with previously scaled states).

Algebraic invariant (induction)
Assume by induction that at time $t-1$ the stabilized states satisfy
$$
c'_{t-1} = e^{-m_{t-1}} c_{t-1}, \qquad n'_{t-1} = e^{-m_{t-1}} n_{t-1}.
$$
Use the sLSTM recurrences but replacing $i,f$ by $i',f'$:

$$
\begin{aligned}
c'_t &= f'_t c'_{t-1} + i'_t z_t \\
     &= (f_t e^{m_{t-1}-m_t}) (e^{-m_{t-1}} c_{t-1}) + (i_t e^{-m_t}) z_t \\
     &= e^{-m_t} ( f_t c_{t-1} + i_t z_t ) \\
     &= e^{-m_t} c_t.
\end{aligned}
$$

Similarly for $n$:

$$
\begin{aligned}
n'_t &= f'_t n'_{t-1} + i'_t \\
     &= (f_t e^{m_{t-1}-m_t}) (e^{-m_{t-1}} n_{t-1}) + i_t e^{-m_t} \\
     &= e^{-m_t} ( f_t n_{t-1} + i_t ) \\
     &= e^{-m_t} n_t.
\end{aligned}
$$

Base case holds with an appropriate $m_0$ (the paper uses the recurrence so $m_0$ can be set so that $e^{-m_0}$ is the initial scale). Thus for every $t$, $c'_t = e^{-m_t} c_t$ and $n'_t = e^{-m_t} n_t$.

Why outputs are unchanged
The hidden pre-output uses the ratio $\tilde{h}_t = c_t / n_t$ (mLSTM uses $C_t q_t$ divided by a normalization, same idea). Because both numerator and denominator are multiplied by the same $e^{-m_t}$, the ratio is identical:
$$
\tilde{h}'_t = c'_t / n'_t = (e^{-m_t} c_t) / (e^{-m_t} n_t) = c_t / n_t = \tilde{h}_t.
$$
Since $o_t$ and any subsequent operations are not altered, the entire forward outputs are identical.

Why gradients w.r.t. parameters are preserved
There are two complementary ways to see this:

1) Functional-equality argument (most direct): The forward mapping from network parameters (weights and biases that produce $\tilde{i}_t$, $\tilde{f}_t$, etc.) to network outputs is algebraically identical whether you use $(i_t,f_t)$ in the original recurrence or $(i'_t,f'_t)$ together with the $m_t$ updates, because the transformed recurrence produces exactly the same hidden states as shown above. When two differentiable maps agree on an open set, their derivatives are equal there. Here the maps agree everywhere except possibly on the measure-zero set where in some $m_t$ the two $\max$ arguments are exactly equal. Thus almost-everywhere the Jacobians (gradients) of the output w.r.t parameters are the same. In automatic differentiation terms, replacing gates by their stabilized versions does not change the ultimate scalar loss as a function of parameters, so the gradients computed by backprop are the same almost everywhere.

2) Local chain-rule cancellation (mechanistic): If you write the stabilized gates $i'_t = i_t \cdot s_t$ and $f'_t = f_t \cdot (s_{t-1}/s_t)$ where $s_t := e^{-m_t}$, then the recurrences propagate $s$ factors so that every $c_t$ and $n_t$ get multiplied by $s_t$. When you differentiate the loss $L$ that depends only on the ratio $c_t/n_t$, any derivative contributions arising from the explicit dependence of $s_t$ on gate preactivations cancel out. Concretely, perturbing a parameter that affects $\tilde{i}_t$ changes both $i_t$ and $m_t$ (because $m_t = \max(\dots, \log i_t)$), but the induced change in $i'_t = \exp(\log i_t - m_t)$ equals the change in the original $i_t$ multiplied by $e^{-m_t}$, while the change in $m_t$ contributes an opposite term that cancels in the combination that affects the output ratio. Algebraically carrying these chain-rule terms through the stabilized recurrence shows they cancel pairwise because $m_t$ is taken from exactly those log-terms (this is why $m_t$ was defined by that max).

About the non-differentiability of max
$m_t$ uses a $\max$, which is non-differentiable at tie points where its two arguments are equal. This is a benign issue:

- The set of parameter values for which an exact tie occurs has measure zero in parameter space, so almost every point is differentiable and gradients computed in practice are unaffected.
- Standard AD frameworks and the usual mathematical practice accept subgradients at max/kink points; any choice of subgradient that selects one active branch is consistent with the equal-limit derivatives and will not change learning in practice.
- The paper’s claim (and standard practice for stabilizing exponentials) is exactly this: we rely on almost-everywhere differentiability and on the fact that the forward map is identical; hence the gradients that AD computes are the correct ones for optimization.

Summary
The stabilizer $m_t$ rescales $i$ and $f$ so that the whole cell and normalizer states are multiplied by the same scalar factor $e^{-m_t}$ at that time. Because the network uses $c_t/n_t$ (or analogous normalized retrieval in mLSTM), the forward outputs are unchanged. Since the forward map from parameters to outputs is identical (except on measure-zero ties), the gradients w.r.t. parameters are preserved; the non-differentiability of $\max$ is a measure-zero technicality handled by subgradient conventions and does not affect practical training. The short algebraic induction above (showing $c'_t = e^{-m_t} c_t$ and $n'_t = e^{-m_t} n_t$) is the core of the argument.

### How is \log f_t computed in the stabilizer when f_t might be sigmoid or exponential?
Question:
In the stabilizer, m_t = \max(\log f_t + m_{t-1}, \log i_t). But in sLSTM/mLSTM, f_t can be either \sigma(\tilde{f}_t) or \exp(\tilde{f}_t). 

- If f_t = \sigma(\tilde{f}_t), then \log f_t is well-defined but negative. If f_t = \exp(\tilde{f}_t), then \log f_t = \tilde{f}_t. Do the authors implement both branches and choose depending on the gating type, or do they always compute \log f_t via a numerically stable function that matches the chosen nonlinearity?
- Any practical tips to avoid numerical issues when f_t is close to 0 (sigmoid) leading to large negative \log f_t?
Answer:
Short answer: you should compute the two cases exactly as they are defined (i.e. implement the two branches), but do so with numerically stable formulas. For the sigmoid branch use a numerically stable log-sigmoid expression (or a library call), and for the exponential branch use the pre-activation directly. In practice the stabilizer $m_t$ and the usual tricks (clamping, softplus/log1p forms, using logsigmoid) prevent over/underflow.

Explanation and practical recipe grounded in the paper
The stabilizer in the paper is
$m_t = \max\!\big(\log(f_t) + m_{t-1}, \; \log(i_t)\big)$
and then the stabilized gates are computed via exponentials of differences with $m_t$. The paper allows two choices for the forget gate: $f_t = \sigma(\tilde f_t)$ or $f_t = \exp(\tilde f_t)$. These give different but simple expressions for $\log(f_t)$:

- If $f_t = \exp(\tilde f_t)$ then
  $\log(f_t) = \tilde f_t$.
  (No extra work: use the pre-activation value.)

- If $f_t = \sigma(\tilde f_t)$ then
  $\log(f_t) = \log(\sigma(\tilde f_t)) = -\operatorname{softplus}(-\tilde f_t)$.
  Equivalently you can use a numerically stable library routine such as $\text{torch.nn.functional.logsigmoid}(\tilde f_t)$.

So yes: you implement both branches (or compute whichever one your model uses) but do the log for sigma via the stable log-sigmoid identity rather than computing $f_t = \sigma(\tilde f_t)$ then $\log(\cdot)$. Computing sigmoid then log is numerically bad when $f_t$ is near $0$ (it loses precision or underflows to zero, whose log is $-\infty$).

Numerical-stability tips
1. Use log-sigmoid directly for the sigmoid branch:
   $\log(\mathrm{sigmoid}(x)) = -\operatorname{softplus}(-x)$
   or call a builtin $\text{logsigmoid}(x)$. This avoids computing $\mathrm{sigmoid}(x)$ first and losing precision when $x \ll 0$.

2. For the exp branch be mindful of large positive $\tilde f_t$ that would make $\exp(\tilde f_t)$ overflow if you ever computed $f_t$ directly. But the stabilizer only needs $\log(f_t) = \tilde f_t$, and later you compute
   $f'_t = \exp\big(\log(f_t) + m_{t-1} - m_t\big)$
   where the subtraction by $m_t$ is precisely a stabilization step that prevents the exponent from overflowing. Still, you should bound $\tilde f_t$ in practice (e.g. clamp to a reasonable range) if your implementation ever exponentiates it outside the stabilized path.

3. Avoid doing sigmoid then log. Instead compute logsigmoid or $-\operatorname{softplus}(-x)$. In PyTorch use $\text{torch.nn.functional.logsigmoid}(x)$ or $-\text{torch.nn.functional.softplus}(-x)$. These implement numerically stable sequences (they use $\log1p$ and avoid catastrophic cancellation).

4. Add tiny eps only if you must convert probabilities to logs in a non-stable way; better is to use the stable identities above. If you clamp values, do so conservatively (e.g. clamp pre-activations to $[-50, 50]$) so you don’t change gradients much.

5. Initialization and bias: as the paper notes, initialization of forget biases matters. For exponential gates you typically initialize biases to values that avoid excessively large or tiny gates initially (e.g. bias that yields modest $\tilde f_t$). This reduces the risk of large-magnitude $\tilde f_t$ early in training.

Why the stabilizer already helps
The design of $m_t$ and the subsequent subtraction in the exponent is precisely a log-sum-exp style stabilization: by computing gates in the log-domain and subtracting the max ($m_t$) before exponentiating, you prevent overflow/underflow when summing many exponentials. That is why the paper replaces $f_t / i_t$ by their stabilized versions $i'_t$ and $f'_t$: the final exponentials are of differences (which are numerically small) rather than raw large values.

Minimal working implementation sketch (conceptual)
If your forget gate choice is stored in a flag, do:

if forget_is_exp:
    log_f = \tilde f            # use pre-activation directly
else:
    log_f = logsigmoid(\tilde f)  # numerically stable

log_i = \tilde i   # because i_t = exp(\tilde_i) in paper, so log(i_t)=\tilde_i
m_t = torch.max(log_f + m_{t-1}, log_i)
i_prime = torch.exp(log_i - m_t)
f_prime = torch.exp(log_f + m_{t-1} - m_t)

This follows the paper and avoids intermediate under/overflows.

Summary
Implement both branches (because the paper explicitly allows two possible gate nonlinearities) but compute $\log(\sigma(x))$ via logsigmoid or $-\operatorname{softplus}(-x)$ instead of $\log(\sigma(x))$ computed via $\sigma(x)$. Rely on the stabilizer's subtraction by $m_t$ to keep subsequent exponentials safe, and optionally clamp pre-activations or initialize biases to reasonable values to reduce extreme values during training.

### Why does mLSTM normalize retrieval by max(|n_t^\top q_t|, 1) and take the absolute value?
Question:
In mLSTM, the hidden pre-output is \tilde{h}_t = C_t q_t / \max\{ |n_t^\top q_t|, 1 \}. I am puzzled by two choices:
- Why the absolute value |n_t^\top q_t| in the denominator? Is the issue that the sign of the dot product should not flip the normalization scale because the numerator C_t q_t already captures signed associations?
- Why clamp with a lower bound of 1 rather than add a small \(\epsilon\) (e.g., dividing by \max\{|\cdot|, \epsilon\}) or using something smooth like \sqrt{(n_t^\top q_t)^2 + \epsilon}? How sensitive is training to this threshold, and is 1 tied to LayerNorm variance assumptions?
Answer:
Short answer: they take the absolute value because the normalization should use the magnitude of the “normalizer” projection as a scale (not its sign), and they clamp that magnitude to a floor of $1$ to avoid dividing by a very small number (which would wildly amplify both activations and gradients). Both choices are pragmatic stability/conditioning fixes that follow from how mLSTM builds its memory and from the use of LayerNormed key/query inputs.

Why the absolute value $|n_t^\top q_t|$: In mLSTM the normalizer vector $n_t$ is the gated, cumulative sum of key vectors and the retrieval numerator is the matrix-memory product $C_t q_t$. That numerator already encodes the signed combination of stored values (positive and negative contributions are meaningful). If you divide by $n_t^\top q_t$ with its sign included, a small negative dot product would flip the sign of the whole retrieved vector or cause sign-dependent rescaling that confounds the stored sign information. Using the absolute value makes the denominator a scale (magnitude) only — i.e., a positive normalizer that expresses “how much mass” supports this query — and leaves the numerator to carry the signed content. Intuitively: you want to normalize by how much matching key mass exists (a nonnegative quantity), not by a signed projection that can cancel information.

Why clamp to $1$ rather than use a tiny $\epsilon$ or a smooth $\sqrt{\,\cdot\,+\epsilon}$: when $\mathbf{n}_t^\top \mathbf{q}_t$ is close to zero, dividing by it would explode the retrieved activations and gradients. Clamping to a floor like $1$ avoids that amplification. The authors state they assume a LayerNorm before key/value projections (so keys/queries are roughly zero-mean and unit-ish scale); under that scale a floor of $1$ is a natural, simple choice that keeps retrieved activations in a similar dynamic range to other network activations. Practically this is cleaner and cheaper than more elaborate stabilizers. Using a much smaller $\epsilon$ (e.g. $1\mathrm{e}{-}6$) would permit very large divisions when the dot product is small and thus destabilize training; using a smooth denominator such as $\sqrt{(n_t^\top q_t)^2 + \epsilon}$ would produce a similar magnitude effect but is slightly more complex (and still needs a choice of $\epsilon$). The paper cites earlier work (e.g. Retention / Sun et al.) that used the same $1.0$ threshold, and the authors report they use this practically and stabilize exponential gates separately, indicating the design is empirical and works reliably.

How sensitive is training to the threshold / why $1$: because keys and queries are produced after LayerNorm, their inner products typically have order-one scale; therefore clamping at $1$ prevents amplification while not usually masking genuine large normalizer values. This is an empirically motivated, simple normalization constant rather than a theoretically critical hyperparameter tied to LayerNorm variance; changing it will change the effective scale of retrieved vectors and can require re-tuning learning rates or gate initializations, but it is not expected to be brittle if you keep consistent normalization on inputs. In short: $1$ is a convenient, scale-matching clamp chosen for stability and simplicity; smoother alternatives exist but offer no clear advantage in this architecture and may complicate numerical stabilization.

Connection to broader concepts: this denominator plays the role of a data-dependent normalizer (analogous to the sum in attention or to variance normalization) to keep retrieval signal-to-noise and gradients well-conditioned. The absolute value enforces a nonnegative scale; the floor prevents division-by-small-number instabilities. Both are standard pragmatic devices when converting associative-memory / fast-weights updates into numerically stable, learnable modules.

### Is the mLSTM update formally equivalent to linear attention or Retention with a particular feature map?
Question:
The mLSTM update is C_t = f_t C_{t-1} + i_t v_t k_t^\top and the output is proportional to C_t q_t, with a normalization based on n_t. This resembles linear attention with \phi(x) = x and a decay term, and also resembles Retention.

- Can we write mLSTM's output as a streaming linear attention form: h_t \propto \sum_{s \le t} \left( i_s \prod_{u=s+1}^t f_u \right) v_s (k_s^\top q_t), up to normalization and gating? 
- If yes, what are the exact differences to Linear Transformer, Retention, and RWKV-5/6 (e.g., the separate normalizer state, output gate, gating parameterization)?
- Under what conditions does mLSTM reduce exactly to a known linear-attention variant?
Answer:
Short answer: Yes — up to obvious gating/normalization details, mLSTM is algebraically a streaming linear-attention / fast-weight accumulator with feature map $\phi(x)=x$ and an elementwise (time-varying) decay on past contributions. The differences are exactly where xLSTM departs from the usual linear-attention recipe: (i) mLSTM maintains a full outer-product matrix $ \mathbf{C}_t $ (fast-weight / covariance memory) whose increments are scaled by exponential input gates and multiplied by per-step forget/decay factors, (ii) it keeps a separate normalizer state $ \mathbf{n}_t $ (a weighted sum of keys) used for a denominator with absolute/threshold floor, and (iii) it applies an output gate and exponential/stabilized parameterizations for the gates. Under straightforward constraints (remove output gate, use identity normalization, disable stabilization/thresholding, and make gates simple scalars or predetermined weights) mLSTM reduces exactly to the linear-attention / Retention-style streaming forms.

Below I make this precise and give the intuitive mapping to Linear Transformer / Retention / RWKV variants.

1) Writing mLSTM as streaming linear attention
mLSTM in the paper has the recurrence (matrix memory and normalizer)

$$
\mathbf{C}_t = f_t\,\mathbf{C}_{t-1} + i_t\,\mathbf{v}_t\mathbf{k}_t^\top,
\qquad
\mathbf{n}_t = f_t\,\mathbf{n}_{t-1} + i_t\,\mathbf{k}_t,
$$

and the (pre-gated) retrieved vector

$$
\tilde{\mathbf{h}}_t \;=\; \dfrac{\mathbf{C}_t \mathbf{q}_t}{\max\{|\mathbf{n}_t^\top \mathbf{q}_t|,1\}}.
$$

Unrolling $\mathbf{C}_t$ gives the streaming sum

$$
\mathbf{C}_t \;=\; \sum_{s\le t} \Big(i_s\prod_{u=s+1}^t f_u\Big)\, \mathbf{v}_s \mathbf{k}_s^\top.
$$

Therefore

$$
\mathbf{C}_t \mathbf{q}_t \;=\; \sum_{s\le t} \Big(i_s\prod_{u=s+1}^t f_u\Big)\, \mathbf{v}_s (\mathbf{k}_s^\top \mathbf{q}_t).
$$

So yes: up to the final scalar normalizer and the output gate, the mLSTM readout is exactly a streaming linear-attention form

$$
\tilde{\mathbf{h}}_t \;\propto\; \sum_{s\le t} w_{s\to t}\, \mathbf{v}_s (\mathbf{k}_s^\top \mathbf{q}_t),
\qquad
w_{s\to t} := i_s\prod_{u=s+1}^t f_u,
$$

and the paper uses $\mathbf{h}_t=\mathbf{o}_t\odot\tilde{\mathbf{h}}_t$ with a denominator based on $\mathbf{n}_t^\top \mathbf{q}_t$ (absolute and floored). Intuitively: mLSTM is a linear-attention-style weighted sum of past values $v_s$ where each term is modulated both by the kernel $\mathbf{k}_s^\top \mathbf{q}_t$ and by an exponential time-dependent storage weight $w_{s\to t}$ that encodes input learning-rate and decay.

2) Exact differences to Linear Transformer, Retention, and RWKV-5/6
- Linear Transformer (e.g. Katharopoulos et al.): linearized attention writes numerator $S_t = \sum_s \phi(\mathbf{k}_s)\mathbf{v}_s^\top$ and output $S_t \phi(\mathbf{q}_t)$. With $\phi(x)=x$ this becomes $S_t\mathbf{q}_t = \sum_s \mathbf{v}_s (\mathbf{k}_s^\top\mathbf{q}_t)$. Differences from mLSTM:
  - Linear Transformer typically treats the per-token feature-map weights as 1 (no multiplicative $i_s$ and no per-token decay product). mLSTM multiplies each outer-product by a time-varying scalar $w_{s\to t}=i_s\prod_{u=s+1}^t f_u$, i.e. a (learned, input-dependent) streaming attenuation/learning-rate.
  - Denominator: linear attention normally uses $z_t = \sum_s \phi(\mathbf{k}_s)^\top\phi(\mathbf{q}_t)$ (a scalar) to normalize. mLSTM uses a separate state $\mathbf{n}_t=\sum_s w_{s\to t}\mathbf{k}_s$ and divides by $\max\{|\mathbf{n}_t^\top\mathbf{q}_t|,1\}$, so mLSTM keeps a running vector normalizer rather than recomputing a scalar from $S_t$ and $\phi(q_t)$. This lets the normalizer be updated with the same streaming decay/gates and be numerically stabilized/thresholded.
  - Gates & parameterization: mLSTM uses exponential input gates $i_t$ (ensuring positivity and allowing multiplicative accumulation), possibly exponential forget gates $f_t$, and a separate output gate $\mathbf{o}_t$ applied elementwise to $\tilde{\mathbf{h}}_t$. Linear Transformer usually has no such exponential gating per token and no separate output gate applied after the linear readout.

- Retention (Sun et al.): Retention maintains running numerator and denominator with per-element decay and multiplicative updates, i.e. sums of decayed token contributions. This is conceptually close to mLSTM: both keep streaming accumulators and both use decays. Differences:
  - Retention typically applies elementwise or channelwise decays and may implement normalization differently; mLSTM stores full outer-products $\mathbf{v}_s\mathbf{k}_s^\top$ (a covariance-like matrix) while some Retention variants use per-dim scalar accumulators (depending on implementation).
  - mLSTM's normalizer is the weighted sum of keys $\mathbf{n}_t$ and the denominator is $\mathbf{n}_t^\top \mathbf{q}_t$ (absolute and floored). Retention often explicitly maintains numerator and denominator streams matched to particular feature maps; again the main difference is gating parameterization (exponential $i_t$, stabilized forms) and the output gate present in mLSTM.
  - The paper explicitly points out the use of the absolute value and a lower bound on the denominator in mLSTM; Retention usually assumes positive denominators (or handles differently).

- RWKV-5/6 family: RWKV architectures are RNN-like models that emulate attention with time-decays and per-token mixes. Differences relative to mLSTM:
  - RWKV uses scalar (or channel-wise) recurrent state updates with carefully engineered decay kernels to mimic softmax attention; it does not generally maintain a full $d\times d$ matrix memory $\mathbf{C}_t$ of outer-products. In the paper, RWKV-5/6 are listed among covariance-update-rule relatives, but mLSTM's matrix memory gives it a different storage geometry (explicit key-value outer products) and a normalizer-vector state $\mathbf{n}_t$.
  - Parameterization: RWKV often parameterizes decays and mixes differently (log-space decays, special numerical recipes). mLSTM uses exponential gates stabilized by a max-log trick (see Equations (5) in the paper) and a separate output gate.

Summary of the practical differences: (i) mLSTM is a fast-weight outer-product accumulator with multiplicative, input-dependent learning-rate ($i_t$) and decay ($f_t$) and a separate normalizer vector; (ii) Linear Transformer is the special case with no per-token multiplicative $w_{s\to t}$ (or with $w_{s\to t}\equiv1$) and a single scalar normalization computed from feature maps; (iii) Retention and RWKV are close in spirit (streaming sums + decays) but differ in whether they store matrices vs. per-channel accumulators, how normalization is done, and how gating/parameterization is handled.

3) Conditions under which mLSTM reduces exactly to a known linear-attention variant
- To reduce to plain streaming Linear Transformer with feature map $\phi(x)=x$ and exact normalization, you need:
  1. $f_t \equiv 1$ for all $t$ (no decay), and $i_t\equiv 1$ for all $t$ (no per-step learning-rate); or more generally set $w_{s\to t}=1$ by fixing gates deterministically.
  2. Remove the output gate ($\mathbf{o}_t\equiv\mathbf{1}$).
  3. Use the scalar normalizer $z_t = \sum_{s\le t}\mathbf{k}_s^\top \mathbf{q}_t$ (i.e., make the denominator equal to the usual linear-attention denominator without taking abs/threshold), which is equivalent to letting $\mathbf{n}_t=\sum_s\mathbf{k}_s$ and dividing by $\mathbf{n}_t^\top\mathbf{q}_t$ without clipping.
  Under these choices the mLSTM readout becomes exactly
  $$
  \mathbf{C}_t\mathbf{q}_t = \sum_{s\le t}\mathbf{v}_s(\mathbf{k}_s^\top\mathbf{q}_t),
  $$
  which matches linear attention with $\phi=\mathrm{id}$.

- To reduce to Retention-like form you need to match Retention’s per-dimension decay and denominator bookkeeping: make $f_t$ and $i_t$ either scalars or channel-wise scalars that match Retention’s decay schedule, and remove the output gate and the abs/thresholding on the denominator. If Retention’s implementation stores numerator and denominator as streaming accumulators of the same form, then with the same decay/learning rates the mLSTM is algebraically the same (modulo whether Retention uses elementwise decays vs. a single scalar $f_t$). So mLSTM becomes Retention when its gating/decay is constrained to Retention’s per-channel or per-dimension schedule and the normalizer/denominator conventions are aligned.

- To match RWKV variants exactly would require reproducing their particular decay kernels, normalization and numerics; in practice mLSTM is not identically RWKV because of the matrix outer-product memory vs. RWKV’s state construction, but with constrained parameterizations (e.g., reducing matrix memory to diagonal or per-channel accumulators) you can recover similar streaming formulas.

Practical notes (from the paper)
The paper deliberately keeps $i_t$ and $f_t$ learnable (exponential gates, stabilized by a log-max trick), keeps an explicit vector normalizer $\mathbf{n}_t$ and applies absolute+threshold to the scalar denominator, and includes output gating $\mathbf{o}_t$. These choices are motivated by stability, numerical conditioning and modeling power (ability to revise storage, richer per-event weighting), and are the key distinctions relative to vanilla linear-attention or simpler retention-like recipes.

Conclusion
Algebraically mLSTM is a linear-attention / fast-weight accumulator with the identity feature map $\phi(x)=x$, enriched by input-dependent multiplicative storage weights $w_{s\to t}=i_s\prod_{u=s+1}^t f_u$, a maintained normalizer vector $\mathbf{n}_t$ (with abs/thresholding), and an output gate plus stabilized exponential gating. If you clamp those extra mechanisms away (set gates to 1 or to fixed scalars, remove output gate and thresholding), mLSTM reduces exactly to the familiar streaming linear-attention / outer-product fast-weight form and — with suitable per-channel decay choices — to Retention-like variants.

### How is mLSTM parallelized in practice and what is the exact scan/blocking algorithm?
Question:
The paper says mLSTM is fully parallelizable similar to FlashAttention or GLA because there is no memory mixing across channels. But the recurrence C_t = f_t C_{t-1} + i_t v_t k_t^\top naively looks sequential.

- What is the explicit associativity used to parallelize the sequence? Is it a segmented prefix-scan over semirings with elements (A, b) representing affine maps C \mapsto f C + i v k^\top?
- Could someone provide the concrete blockwise formula for computing all outputs \{ C_t q_t \}_{t=1}^L in O(L d^2) work but with parallel depth O(\log L)? 
- How is the normalization by n_t handled in the same parallel scheme?
Answer:
Short answer: mLSTM’s recurrence is an associative affine map on the matrix memory, so you can parallelize it with a segmented prefix-scan over a custom associative "product" of pairs $(f, u)$. Concretely, treat each time step $t$ as the pair $(f_t, u_t)$ with $u_t = i_t v_t k_t^\top$; define multiplication

$(f_b, u_b) \circ (f_a, u_a) = (f_b f_a,\; f_b u_a + u_b)$.

This composition corresponds exactly to composing the affine updates $C \mapsto f C + u$, is associative, and therefore admits parallel prefix (scan) and standard block/bring-together algorithms. The normalizer $n_t$ obeys the same kind of recurrence with vector $u'_t = i_t k_t$ and the same associative product.

Below I give the explicit blockwise formula and how to get $C_t q_t$ and the normalization in $O(L d^2)$ work with $O(\log L)$ parallel depth (up to the usual block trade-off).

1) Algebraic identity you use
Each time step applies the affine map $M_t : C \mapsto f_t C + u_t$, where $u_t := i_t v_t k_t^\top$ (a $d\times d$ matrix) and scalar $f_t$. Composition of two maps $M_b \circ M_a$ is

$M_b(M_a(C)) = f_b (f_a C + u_a) + u_b = (f_b f_a) C + (f_b u_a + u_b)$.

Thus represent each step by the pair $(f_t, u_t)$ and compose with the associative binary operation

$(f_2,u_2) \star (f_1,u_1) = (f_2 f_1,\; f_2 u_1 + u_2)$.

2) Prefix formula and block decomposition
Define the left-to-right prefix product for $1..t$ as

$P_{1..t} := (F_{1..t}, U_{1..t}) := (f_t,\ldots,f_1)\star\cdots\star(f_2,u_2)\star(f_1,u_1)$.

By induction this yields the closed form

$F_{1..t} = \prod_{s=1}^t f_s,$  
$U_{1..t} = \sum_{j=1}^t \left( \left(\prod_{s=j+1}^t f_s\right) \cdot u_j \right).$

The cell matrix after $t$ steps (assuming initial $C_0$) is

$C_t = F_{1..t} C_0 + U_{1..t}$.

Most implementations use $C_0 = 0$, then $C_t = U_{1..t}$.

We want for every $t$ the vector $C_t q_t$. Expand (again assuming $C_0 = 0$):

$C_t q_t = U_{1..t} q_t = \sum_{j=1}^t \left( \left(\prod_{s=j+1}^t f_s\right) \cdot u_j \right) q_t
        = \sum_{j=1}^t \alpha_{j,t} \cdot (u_j q_t),$

where $\alpha_{j,t} = \prod_{s=j+1}^t f_s$ is scalar and $u_j q_t$ is a $d$-vector ($u_j = i_j v_j k_j^\top$, so $u_j q_t = i_j v_j (k_j^\top q_t)$ — a cheap rank-1 application).

3) Blockwise parallel algorithm (standard scan-within-blocks + parallel combine)
Split the length $L$ into $B$-sized blocks (indices $[1..L] \to$ blocks $b = 1..\!m$, $m = L/B$). For each block $b$ do these steps in parallel:

a) Local sequential scan within block (cost $O(B d^2)$ work per block): compute for positions $t$ in block the local prefix products $(F^{(b)}_{start..t}, U^{(b)}_{start..t})$. Also compute the block aggregate pair $S_b := (F_b, U_b) =$ product of all $(f,u)$ in the block (i.e., result at block end). Note: computing $U$ requires multiplying matrices $u$ ($d\times d$) by scalars and adding $d\times d$ matrices; storing $U$ at block end is $d\times d$.

b) Parallel prefix over blocks (associative combine): do a parallel scan of $S_1, S_2, \ldots, S_m$ with the $\star$ operator to obtain for each block $b$ the prefix $P_{1..(b-1)} = (F\_pref\_b, U\_pref\_b)$ which is the composition of all previous blocks. This global prefix scan costs $O(m)$ work and $O(\log m)$ depth.

c) Finalize per block in parallel: for every position $t$ inside block $b$ you have the local within-block pair $(F\_loc\_{start..t}, U\_loc\_{start..t})$ (computed in a) and the prior-block prefix $(F\_pref\_b, U\_pref\_b)$ (from b). The full prefix for time $t$ is

$(F_{1..t}, U_{1..t}) = (F\_loc, U\_loc) \star (F\_pref\_b, U\_pref\_b)$  if you choose ordering carefully
actually you must respect ordering: if $P\_pref$ is composition of blocks $1..(b-1)$ and $L\_loc$ is composition of steps in block $b$ up to $t$, then full prefix is $L\_loc \star P\_pref$? (check ordering). Using our left-to-right ordering where newer maps are on the left, we want $P_{1..t} = L\_loc \star P\_pref$. Concretely

$F_{1..t} = F\_loc \cdot F\_pref_b,$
$U_{1..t} = F\_loc \cdot U\_pref_b + U\_loc.$

So compute $C_t = F_{1..t} C_0 + U_{1..t}$, and then compute $C_t q_t$.

Remarks on ordering: the presentation above assumed composition where later steps multiply earlier ones; implement carefully according to your scan direction. The algebraic $\star$ is associative so practical scan libraries (Blelloch, Hillis-Steele) apply.

4) Complexity and parallel depth
Work: every $u_j$ is rank-1 ($u_j = i_j v_j k_j^\top$). Applying local scans and adds on $d\times d$ matrices yields $O(L d^2)$ total work (same asymptotic as stated in paper). Parallel depth: local sequential scan inside block costs $O(B)$ depth; global block-prefix scan costs $O(\log m) = O(\log(L/B))$ depth; final per-block combines are $O(1)$ depth per position. Choose block size $B = O(\log L)$ (or a small constant tuned for hardware) to get total depth $O(\log L)$. In practice one chooses $B$ large enough to get high arithmetic intensity on GPU but small enough so that $\log(L/B)$ dominates.

5) How to compute $u_j q_t$ cheaply (rank-1 speedup)
Since $u_j = i_j v_j k_j^\top$, $u_j q_t = i_j v_j (k_j^\top q_t)$. So you do not need to materialize full $d\times d$ matrices to apply them to queries: precompute scalars $s_{j,t} = k_j^\top q_t$ (or compute $k_j^\top q_t$ on the fly), then multiply by scalar $i_j$ and vector $v_j$. In the block-scan you do need to form $U$ matrices (sums of scaled rank-1 matrices) if you store $U$ as dense $d\times d$; but for final application to each $q_t$ you can instead carry compressed representations: many implementations keep accumulators in the factorized form to avoid $O(d^2)$ storage/work when possible (this is exactly what linearized attention techniques do). The paper’s mLSTM chooses to keep the full matrix memory, so the stated $O(L d^2)$ work follows; but retrieval $C_t q_t$ can exploit rank-1 structure to lower constant factors: when $U = \sum_j \alpha_j u_j$, then $U q_t = \sum_j \alpha_j i_j v_j (k_j^\top q_t)$ — a sum of scaled $v_j$ vectors. So instead of materializing $U$, one can store the sequence of $(\alpha_j i_j, v_j, k_j)$ and do the dot-products to $q_t$, which is $O(L d)$ overall if queries are many or shared; trade-offs apply.

6) Normalizer $n_t$ and final normalization
$n_t$ follows the identical scalar/vector affine recurrence

$n_t = f_t n_{t-1} + i_t k_t$.

So run the same scan in parallel for $n_t$ (replace $u_t$ by $u'_t := i_t k_t$, a $d$-vector, and use the same associative product but with $u$ being vector; composition formula is identical: $(f_2, u_2) \star (f_1, u_1) = (f_2 f_1, f_2 u_1 + u_2)$, where $u$ are vectors). After you have $n_t$ and $C_t q_t$ you compute the scalar denominator $s_t = \max(|n_t^\top q_t|, 1)$ (absolute value and lower bound) and divide:

$\tilde h_t = (C_t q_t) / s_t,\quad  h_t = o_t \odot \tilde h_t.$

This normalization is a pointwise (per $t$) operation and does not break parallelism; you compute $n_t^\top q_t$ once you have $n_t$ and $q_t$ (both available after the scan), then the scalar clamp and division are $O(d)$ per $t$ and independent across $t$.

7) Practical notes and numerical/stabilization points
- Exponential gates are stabilized in the paper via tracking $m_t = \max(\log f + m_{t-1}, \log i)$ and scaling $i,f$ accordingly. Those stabilizers obey similar associative recurrences and can be folded into the same scan: instead of letting $f_t, i_t$ be raw exponentials, the stabilized (scaled) versions used in updates can be produced by keeping per-step logs and performing a parallel max-scan (associative) and then correcting. Implementation usually does a two-pass approach: compute stabilized scalars per step (sequential or block-stable), then use them in the associative scan described above. The paper notes this stabilization does not change outputs/derivatives if done correctly.
- If $C_0 \neq 0$ you also propagate the initial $C_0$ through $F_{1..t}$ multiplication; that’s one extra scalar $\times$ matrix multiply per $t$ or block (cheap relative to full scans).
- In practice you pick block sizes to balance GPU occupancy and memory bandwidth; the theory gives $O(\log L)$ depth with appropriate $B$.

Summary
mLSTM’s recurrence is exactly an associative composition of affine maps $(f, u)$ with $\star$ defined by

$(f_2,u_2) \star (f_1,u_1) = (f_2 f_1,\; f_2 u_1 + u_2)$.

This lets you do the whole sequence with a parallel prefix scan (block-scan + combine) computing $(F_{1..t}, U_{1..t})$ for every $t$, then form $C_t q_t$ and the normalizer $n_t$ in the same scheme. The work is $O(L d^2)$ if you materialize the $d\times d$ $U$'s (as the paper states); the parallel depth is $O(B + \log(L/B))$, so choosing $B = O(\log L)$ (or tuned for hardware) yields $O(\log L)$ depth. The normalization $n_t^\top q_t$ is handled by running the same scan on vector $u'_t = i_t k_t$ and then applying the scalar clamp/divide per position. This is precisely the “no memory mixing across channels” property the paper refers to: everything reduces to associative scalar/vector/matrix compositions that a prefix-scan can parallelize.

### What is the actual memory capacity of mLSTM compared to attention and to sLSTM?
Question:
The paper argues that matrix memory increases storage capacity and cites BAM/fast weights results. But I would like a clearer capacity statement:
- With i.i.d. zero-mean keys and values in \(\mathbb{R}^d\), and decay f_t \equiv f \in (0,1), how many random key-value pairs T can be stored such that retrieval by q matches the correct value with given SNR (or error probability)? How does this scale with d?
- How does this compare to softmax attention's capacity scaling with sequence length (e.g., results suggesting exponential capacity in d)?
- How does the normalizer n_t impact capacity when queries are not identical to stored keys (approximate retrieval)? Any known theory beyond the binary-vector case?
Answer:
Short answer: with iid zero-mean keys and values and a simple covariance (outer‑product) memory the number of random key–value pairs you can store with a fixed signal‑to‑noise ratio (SNR) scales linearly with the coding dimension $d$. In contrast, attention-style storage (softmax over pairwise similarities) can achieve much larger (in some analyses exponential in $d$) effective capacity under favorable coding/decoding assumptions. The mLSTM normalizer $n_t$ rescales retrieval and therefore changes the constant factors in the SNR; when queries are only approximately equal to stored keys the SNR is multiplied by the query–key similarity (cosine or inner‑product factor), so approximate retrieval reduces capacity proportionally.

Below I give the standard, intuitive derivation (grounded in the paper’s covariance/fast‑weights view) and connect it to the paper’s claims about attention and the role of the normalizer.

1) Setup and signal / noise decomposition (mLSTM / covariance memory)
mLSTM stores at time indices $1\ldots T$ using the (decaying) outer‑product update
$\mathbf{C}=\sum_{t=1}^T \alpha_t\, \mathbf{v}_t \mathbf{k}_t^\top$
(with $\alpha_t$ = product of input/forget gates; with constant decay and input rate this is effectively a geometric weight, but for asymptotic counting you can treat the stored effective count as $T$ or a weighted sum of similar order). Retrieval with query $\mathbf{q}$ gives
$\mathbf{y}=\mathbf{C}\mathbf{q}=\sum_{t=1}^T \alpha_t\, \mathbf{v}_t (\mathbf{k}_t^\top \mathbf{q}).$

Assume for simplicity: keys $\mathbf{k}_t$ are i.i.d. zero‑mean isotropic with variance normalized so $\mathbb{E}[\|\mathbf{k}\|^2]\!\asymp\! d$ (or scale choices equivalent to the paper’s $\tfrac{1}{\sqrt{d}}$ prefactor in the key projection), values $\mathbf{v}_t$ i.i.d. zero‑mean and independent of keys, and the query $\mathbf{q}$ aims to retrieve the value paired with key $\mathbf{k}_\star$. Decompose y into the signal and cross‑talk noise:
signal = $\alpha_\star \mathbf{v}_\star (\mathbf{k}_\star^\top \mathbf{q})$,
noise = $\sum_{t\ne\star} \alpha_t \mathbf{v}_t (\mathbf{k}_t^\top \mathbf{q}).$

If $\mathbf{q}=\mathbf{k}_\star$ (ideal identical query) then $\mathbf{k}_\star^\top\mathbf{q}=\|\mathbf{k}_\star\|^2\sim d$ (or 1 depending on normalization). For random other keys, inner products $\mathbf{k}_t^\top\mathbf{q}$ are zero mean with variance $\sim\!1$ if keys are normalized so $\mathbb{E}[(\mathbf{k}^\top\mathbf{q})^2]\propto 1$. The important scaling is that each unrelated term contributes a random projection with variance that shrinks like $1/d$ if vectors are unit (or more generally scales inverse in $d$ if you adopt the usual $\tfrac{1}{\sqrt{d}}$ key scaling used in the paper).

2) SNR scaling (typical derivation)
Take the keys normalized so that for unrelated key/query pairs $\operatorname{Var}(\mathbf{k}_t^\top\mathbf{q})\approx 1/d$. Then the expected squared signal amplitude (magnitude of the target contribution) scales as
$\text{Signal}^2 \propto (\mathbf{k}_\star^\top\mathbf{q})^2 \cdot \mathbb{E}[\|\mathbf{v}_\star\|^2] \sim \mathcal{O}(1)$ if $\mathbf{k}_\star^\top\mathbf{q}$ is arranged to be $\mathcal{O}(1)$ (or $\sim d$ if you use unnormalized keys — the constant convention only changes constants below).

The noise variance from the $T-1$ other items sums approximately as
$\text{Noise}^2 \propto (T-1)\times \operatorname{Var}(\mathbf{k}_t^\top\mathbf{q}) \times \mathbb{E}[\|\mathbf{v}\|^2] \sim (T/d)$.
Therefore
SNR $\sim \dfrac{\text{Signal}^2}{\text{Noise}^2} \propto \dfrac{d}{T}.$

Rearranging: to achieve a fixed target SNR (or fixed error probability for a linear decoder), the number of storable random key–value pairs scales as
$T \propto d \times (\text{constant set by desired SNR}).$

So mLSTM / covariance memory capacity is linear in $d$. This is the standard result for outer‑product associative memories and is consistent with the paper’s statement that the covariance rule is “optimal ... for maximal separability” and with the citations to classical BAM / fast weights literature. In words: each stored random pattern eats about O(1) degrees of freedom in the $d$-dimensional code, so you can store O(d) of them before cross‑talk dominates.

3) Comparison to softmax attention
Softmax attention is not an outer‑product accumulator; retrieval there is a normalized weighted sum where the softmax can sharply select the right memory entry when keys live in an appropriate code. Analyses (for example the work the paper cites, e.g. Ramsauer et al. 2021) show that, under favorable discrete / coding assumptions (e.g. binary codes, orthogonal or combinatorial structured codes), Transformer attention can represent exponentially many associations in $d$ because the softmax can implement a near‑one‑hot selector using pairwise similarities. Intuitively, if your keys are drawn from a structured codebook (e.g. binary strings of length $d$), the number of distinct distinguishable keys can be exponential in $d$, and softmax can pick out one of those with extremely low cross‑talk. That is why the paper calls Transformer memory “exponential in the coding dimension” and why in associative‑recall benchmarks Transformers are the gold standard.

So: outer‑product matrix memory (mLSTM) gives capacity $T=O(d)$ for random iid keys/values; attention can (in idealized analyses) achieve much higher capacity (even exponential in $d$) when keys/queries and the softmax mechanism are able to exploit combinatorial code structure or very sharp similarity decoding.

4) Role of the normalizer $n_t$ (mLSTM) and approximate queries
mLSTM divides the retrieved vector by $\max\{|\mathbf{n}_t^\top\mathbf{q}|,1\}$ where $\mathbf{n}_t$ = weighted sum of keys (the normalizer state). Intuitively the normalizer keeps track of the total “mass” of keys (weighted by gates) that can contribute to the dot product with $\mathbf{q}$. Two roles:

(a) Numerical and scaling stabilization: if many keys align with the query direction (or if gates produce large magnitudes), the denominator prevents the retrieved vector from blowing up; if the dot product is tiny (which would amplify noise when dividing), the lower bound (1) prevents division by near zero. This is a constant‑factor stabilizer: it changes the effective SNR constant but not the linear‑in‑$d$ scaling law derived above.

(b) Approximate retrieval: when the query $\mathbf{q}$ is not identical to the stored key $\mathbf{k}_\star$, the signal term is scaled by $\mathbf{k}_\star^\top\mathbf{q}$ (or its cosine similarity). If we denote the similarity factor by $\rho = \mathbf{k}_\star^\top\mathbf{q}$ (normalized so $\rho\in[0,1]$ for cosine), then signal is multiplied by $\rho$ while the noise has expected variance scaling $(T/d)$ times the average squared similarity of unrelated keys with $\mathbf{q}$ (which remains $\sim 1/d$ for random keys). Thus SNR becomes approximately $\rho^2 d / T$. So approximate retrieval reduces capacity by a factor $\rho^2$: to maintain the same SNR you can store only $T\approx\rho^2 d / \text{SNR}$. Practically, the normalizer divides the retrieved vector by $|\mathbf{n}_t^\top\mathbf{q}|$ which is of order $\rho T$ for aligned queries and keys, again modifying constants but not the $d/T$ dependency.

5) Known theory beyond binary vectors
The classical analyses of BAM / outer‑product memories give the linear scaling result for random Gaussian or random binary vectors; the paper explicitly cites Dayan/Sejnowski and literature showing covariance (outer‑product) update is optimal for maximal separability in the binary case. Beyond the binary / iid Gaussian case there are fewer clean, general closed‑form capacity results; many analyses rely on assumptions about code structure (sparsity, orthogonality, coding redundancy). The contrast the paper draws is that if you allow pairwise interactions and quadratic computation (as in full attention), you can exploit more structured codes and thus obtain much higher capacity than the random‑vector outer‑product memory. The paper’s empirical associative‑recall experiments reflect that: xLSTM[matrix] improves non‑attention methods’ capacity but still trails Transformers in the synthetic associative‑recall where Transformers exploit pairwise comparison and softmax selection.

6) Practical summary and takeaways
For the paper’s mLSTM (covariance / fast‑weights style memory) with random iid keys and values and constant decay/input rates:
- SNR ∝ $d/T$, so the storable number of random pairs at fixed SNR is $T = O(d)$ (linear in $d$).
- Softmax attention can do much better in idealized settings (sometimes characterized as exponential in $d$) because it implements sharp retrieval via pairwise similarities rather than linear superposition.
- The normalizer changes constants and stabilizes numerics; if queries are only approximately equal to keys the effective signal is multiplied by the similarity $\rho$, so capacity is reduced by roughly $\rho^2$. The paper’s clamp (lower bound 1) and absolute value choices are practical stabilizations that preserve these scaling relationships while avoiding blowups.

References in the paper that support these points: the mLSTM covariance update discussion (Section 2.3), citations to BAM / fast weights and Dayan/Sejnowski for optimality, and the comparison remark that Transformers can be “exponential in the coding dimension” (Section 2.3 and experiments on associative recall).

### How do sLSTM "heads" and memory mixing actually work across multiple cells?
Question:
The paper says sLSTM can have multiple heads with memory mixing within each head but not across heads, and exponential gating establishes a new way of memory mixing. 

- What is the concrete tensor shape layout? For example, if there are H heads and each head has d_h cells, do we have R_z, R_i, R_f, R_o as block-diagonal matrices of shape (H d_h) \times (H d_h), or are they per-head matrices of size d_h \times d_h applied independently?
- How is the head output aggregated back to the model dimension (concatenation + projection or summation)?
- In what sense is exponential gating a "new way" of mixing compared to the classic LSTM's recurrent mixing?
Answer:
Short answer: for sLSTM the recurrent/“memory-mixing” matrices are applied per head (i.e., independent $d_h\times d_h$ mixes inside each head, which can be implemented as separate small matrices or as a block‑diagonal big matrix), the per‑head outputs are typically concatenated and linearly projected back to model dimension inside the block (the xLSTM paper uses up/down projections in the residual block, so concatenation+projection is the natural interpretation), and exponential gating changes how contributions accumulate over time: instead of bounded sigmoid weights making a convex-style additive memory update, exponential gates produce multiplicative positive weights that (after the normalizer $n_t$) act like normalized multiplicative weights / weighted sums — this enables later inputs to reweight and effectively “revise” earlier stored content in a way classic LSTM gating cannot.

Explanation and grounding in the paper

1) Where the R matrices live and their shapes
The paper describes sLSTM with multiple memory cells and with multiple heads such that “sLSTM can have multiple heads with memory mixing within each head but not across heads.” Practically that means each head maintains its own recurrent mixing parameters. If you have $H$ heads and each head has size $d_h$ (so model dimension $D = H\cdot d_h$), you can implement the recurrent weights either as $H$ independent matrices $R_{\cdot}^{(h)} \in \mathbb{R}^{d_h\times d_h}$ applied per head, or as a single big matrix that is block‑diagonal with $H$ blocks of shape $d_h\times d_h$ (shape $(H d_h)\times(H d_h)$). Both are equivalent mathematically; the distinction is only implementation/efficiency. What the paper rules out is using a dense (non‑block) $(H d_h)\times(H d_h)$ matrix that mixes across heads — that would violate “no memory mixing across heads.”

Concretely, for each gate/input $(z,i,f,o)$ you have either per‑head parameters
$R_z^{(h)}, R_i^{(h)}, R_f^{(h)}, R_o^{(h)} \in \mathbb{R}^{d_h\times d_h}$
or a combined block‑diagonal $R_z, R_i, R_f, R_o \in \mathbb{R}^{(H d_h)\times(H d_h)}$ whose blocks are those per‑head matrices.

2) How head outputs are aggregated
The paper does not lay out one single low‑level implementation line, but it repeatedly describes using up/down projections inside residual blocks (section on xLSTM blocks). That design matches the usual multi‑head pattern: each head produces a $d_h$‑dimensional $h_t^{(h)}$; heads are concatenated to a vector of size $H\cdot d_h$ and then mapped back to the model dimension via a linear projection (the block’s down‑projection) inside the residual block. So the standard and consistent choice with the paper is concatenation followed by a learned linear projection (i.e., a projection that combines head outputs back to model dimension). For mLSTM the paper says “multiple heads and multiple cells are equivalent” because there is no memory mixing, so head splitting is mostly an implementation partition and the same aggregation via concatenation+projection applies.

3) In what sense exponential gating is a “new way” of memory mixing
Compare the two forms side by side. Classic LSTM uses sigmoid gates (values in $(0,1)$) and the cell update
$$
c_t = f_t \circ c_{t-1} + i_t \circ z_t
$$
with $i_t,f_t\in(0,1)$. Those gates are bounded and act like soft masks; because they are bounded and additive updates are not normalized, once information is added to $c$ it is hard to globally renormalize or fully “revise” it later except by multiplicatively decaying via many small forget gates. Even with vectorized cells and recurrent matrices, the mixing remains an additive accumulation with bounded gating.

sLSTM replaces (some) sigmoid gates by exponential gates and keeps an explicit normalizer state $n_t$. The sLSTM equations in the paper are (scalar-per-cell form):
$$
c_t = f_t c_{t-1} + i_t z_t
$$
$$
n_t = f_t n_{t-1} + i_t
$$
$$
h_t = o_t \cdot \left(\frac{c_t}{n_t}\right)
$$
with $i_t = \exp(\tilde{i}_t)$ (and $f_t$ either sigmoid or $\exp$), and stabilized via the $m_t$ trick. Two important consequences:

- Gates are positive and potentially unbounded ($\exp$), so $i_t$ and products of future forgets can give multiplicative weights with a large dynamic range. The normalizer $n_t$ keeps track of the sum of those multiplicative weights so that the output is a normalized weighted combination: $c_t/n_t$ is essentially a weighted average of past $z$'s with multiplicative weights produced by $i$ and the chain of $f$'s. That makes the hidden output behave like a normalized retrieval over stored contributions rather than an unnormalized running sum.

- Because weights are multiplicative along time ($f_t$ multiplies previous weights), later choices of $i_t$ or $f_t$ can change relative weights: an incoming large $i_t$ can dominate the normalized sum, and a later $f_t<1$ can downweight an entire preceding sequence of contributions. That allows sLSTM to “revise” previously stored items more sharply than classic sigmoid gating where weights are constrained in $(0,1)$ and the cell is a raw additive accumulator.

Intuitively: classic LSTM mixes by bounded additive gating; exponential gating with a normalizer makes the cell act like a (normalized) kernel density over past inputs where each stored input is multiplied by a product of future forgets and its own input weight. The head restriction (memory mixing only within a head) combined with exponential weights means each head builds such a normalized mixture in its subspace; different heads remain independent mixtures. This is the “new way” of memory mixing the paper highlights: mixing occurs via multiplicative, normalized contributions (and normalization is explicit), enabling stronger revision and sharper weighting of past items than the classic LSTM additive gating.

A compact mathematical intuition: with exp-gates and the normalizer, the hidden pre‑output is
$$
\tilde{h}_t = \frac{c_t}{n_t} = \frac{\sum_{s\le t} \left(i_s \cdot z_s \cdot \prod_{u=s+1}^t f_u\right)}{\sum_{s\le t} \left(i_s \cdot \prod_{u=s+1}^t f_u\right)},
$$
so the network is computing a normalized weighted average of past $z_s$ where weights are multiplicative chains of forgets and inputs. That normalized, multiplicative weighting is what enables revision and produces different mixing behavior than standard LSTM.

Summary
- Recurrent mixes $R_{\cdot}$ are per‑head ($d_h\times d_h$ each) or equivalently block‑diagonal across heads; full cross‑head recurrent mixing is explicitly excluded.  
- Head outputs are combined by concatenation and a linear projection (the residual block’s up/down projections are the paper’s intended mechanism).  
- Exponential gating + normalizer turns the cell into a normalized multiplicative-weight aggregator (a weighted average with multiplicative temporal weights), allowing strong revision and different mixing dynamics than classic bounded additive LSTM gating.

### Does exponential gating risk gradient explosion, and how does the normalizer mitigate it?
Question:
With i_t = \exp(\tilde{i}_t) and possibly f_t = \exp(\tilde{f}_t), gradients through time could blow up. The paper claims stabilization and normalization fix this.

- Can someone derive \partial c_t / \partial c_{t-1} and \partial h_t / \partial c_{t-k} for sLSTM to show where potential explosions occur and how dividing by n_t cancels them?
- Are there known gradient bounds under assumptions on \tilde{i}_t, \tilde{f}_t distributions (e.g., zero-mean after LayerNorm) and the stabilizer m_t?
Answer:
Short answer: yes, exponential gates alone can make recurrence derivatives explode (because each step multiplies gradients by the gate value), but the sLSTM normalizer $n_t$ turns the cell output into a weighted average so that the multiplicative factors cancel. Concretely you get simple closed‑form derivatives showing the cancellation; under reasonable boundedness / normalization assumptions the per-step factors are $O(1)$ and gradients do not exponentially blow up.

Derivation (grounded in the paper’s sLSTM equations)
The sLSTM forward equations (using the paper’s notation) are
$$
c_t = f_t c_{t-1} + i_t z_t,
$$
$$
n_t = f_t n_{t-1} + i_t,
$$
$$
h_t = o_t \cdot \left(\frac{c_t}{n_t}\right).
$$

First, the partial derivative of the cell state with respect to the previous cell state is immediate:
$$
\frac{\partial c_t}{\partial c_{t-1}} = f_t.
$$
This is the source of potential multiplicative growth: if $f_t = \exp(\cdot)$ and is frequently $> 1$, repeated products $\prod f$ will grow exponentially in the time horizon.

Now differentiate the normalized pre-output quantity $s_t := c_t / n_t$ with respect to $c_{t-1}$. Treat $n_t$ as a separate recurrent state (it does not depend on $c_{t-1}$), so $\partial n_t/\partial c_{t-1} = 0$. Using the quotient rule:

$$
\frac{\partial (c_t/n_t)}{\partial c_{t-1}}
= \frac{\left(\frac{\partial c_t}{\partial c_{t-1}}\right) n_t - c_t \left(\frac{\partial n_t}{\partial c_{t-1}}\right)}{n_t^2}
= \frac{f_t n_t - c_t \cdot 0}{n_t^2}
= \frac{f_t}{n_t}.
$$

Therefore the per-step linear factor that carries a perturbation in $c_{t-1}$ up to $s_t$ is $f_t / n_t$. The hidden state $h_t = o_t s_t$ then gives

$$
\frac{\partial h_t}{\partial c_{t-1}} = o_t \cdot \left(\frac{f_t}{n_t}\right).
$$

By recursion, the derivative of $h_t$ with respect to a much earlier cell $c_{t-k}$ (propagating across $k$ steps, assuming gates at intermediate steps are treated as constants for this propagation) is

$$
\frac{\partial h_t}{\partial c_{t-k}} = o_t \cdot \prod_{j=t-k+1}^t \left(\frac{f_j}{n_j}\right).
$$

Interpretation and cancellation
Without normalization, a chain of forget gates yields $\prod f_j$ which can explode if many $f_j > 1$ (the exponential-gate design makes this a real worry). With the normalizer $n_t$ present in the denominator, each step instead contributes the ratio $f_j / n_j$. The key observation is that $n_j$ accumulates the same multiplicative factors that appear in $c_j$: unrolling the recurrences gives

$$
c_t = \sum_{s\le t} i_s z_s \prod_{u=s+1}^t f_u,
$$

$$
n_t = \sum_{s\le t} i_s \prod_{u=s+1}^t f_u.
$$

Thus $s_t = c_t / n_t$ is a weighted average of past $z_s$ with weights $w_s := i_s \prod_{u=s+1}^t f_u$. Because $n_t$ is the sum of the same weights, the ratio $f_j / n_j$ behaves like "one multiplicative factor divided by the running sum of weights" rather than a bare multiplicative factor. Intuitively, $n_j$ grows whenever the forward multiplicative factors grow, so dividing by $n_j$ cancels that growth: instead of amplifying the gradient by $f_j$, you amplify by $f_j$ scaled down by the total accumulated weight $n_j$. In many situations this makes the per-step factor roughly order-one rather than exponentially large.

Role of the stabilizer $m_t$ and normalized gates
As the paper notes, raw exponential gates $i_t = \exp(\tilde i_t)$ (and possibly $f_t = \exp(\tilde f_t)$) can overflow or create extremely large magnitudes. The stabilizer state $m_t$ re-centers the per-step log-gates before exponentiation:

$$
m_t = \max\big(\log f_t + m_{t-1},\ \log i_t\big),
$$

$$
i'_t = \exp(\log i_t - m_t) = \exp(\tilde i_t - m_t),
$$

$$
f'_t = \exp(\log f_t + m_{t-1} - m_t).
$$

Replacing $i_t, f_t$ by the stabilized $i'_t, f'_t$ does not change the outputs (the forward $s_t$ remains the same) but keeps the internal exponentials numerically bounded. Crucially, because $m_t$ is built from the log-sum-max of the contributing gate logs, it normalizes scales so that the weights $w_s$ (when computed with stabilized gates) are relative weights rather than absolute magnitudes. This makes $n_t$ a proper normalizer (sum of relative weights) and keeps the ratios $f'_j / n'_j$ controlled.

Simple gradient bounds (informal)
You can obtain elementary bounds if you assume gates and activations are bounded. For example, suppose for all $t$ we have $0 \le f'_t \le F_{\max}$ and $n_t \ge N_{\min} > 0$ and $0 \le o_t \le O_{\max}$. Then

$$
\left|\frac{\partial h_t}{\partial c_{t-k}}\right| \le O_{\max} \cdot \left(\frac{F_{\max}}{N_{\min}}\right)^k.
$$

This trivial bound still allows exponential growth in $k$ if $F_{\max} / N_{\min} > 1$, so it’s not tight. A much tighter (and the intended) effect comes from the fact that $n_j$ grows in step with the same multiplicative factors as $c_j$: heuristically $n_j \approx \sum \text{weights}$ that include the product of recent $f'_s$, so $f'_j / n_j$ is typically $O\bigl(1 / (\text{sum of relative weights})\bigr)$ and does not systematically exceed $O(1)$. If LayerNorm (or pre-LayerNorm) is applied to the pre-gate activations and those normalized tilde inputs have zero-mean and bounded variance, then the tilde logs are centered and the stabilizer $m_t$ will keep the stabilized $i'_t$ and $f'_t$ in a moderate range (neither astronomically large nor vanishing). Under such assumptions the per-step factor $f'_j / n_j$ remains $O(1)$ in expectation and so $\partial h_t/\partial c_{t-k}$ will not grow exponentially with $k$ in practice.

Intuition connecting to broader concepts
What the normalizer does is convert the memory output into a weighted average (a soft retrieval) rather than an unbounded sum. This is the same trick used in linear attention / kernelized attention and in associative memory constructions: you store contributions with multiplicative decay but always read via a normalization so outputs are scale-invariant to global multiplicative changes. Stabilization ($m_t$) is a practical device to keep exponentials numerically stable — equivalent to working in log-space and subtracting a running max when computing softmax-like sums.

Bottom line
Exponential gating can induce multiplicative gradient growth because $\partial c_t/\partial c_{t-1} = f_t$. The sLSTM normalizer changes the propagated factor to $f_t / n_t$ and hence to products $\prod (f_j / n_j)$, which cancels the raw multiplicative growth because $n_j$ accumulates the same factors as $c_j$. The stabilizer $m_t$ (together with LayerNorm on gate pre-activations) keeps the exponentials and the resulting ratios numerically small and well behaved, giving controlled gradients in practice.

### Why are only keys scaled by 1/\sqrt{d} in mLSTM, while queries and values are not?
Question:
In mLSTM, k_t is defined as k_t = (1/\sqrt{d}) W_k x_t + b_k, but q_t and v_t are not scaled by 1/\sqrt{d}. In Transformers we usually scale the dot-product attention by 1/\sqrt{d} on q and k symmetrically.

- What variance-preservation argument justifies scaling only keys here? Is it targeted at stabilizing the magnitude of n_t^\top q_t specifically? 
- Would symmetric scaling of q and k change the behavior of the normalizer or the C_t q_t numerator?
Answer:
Short answer: they scale only the keys to keep the dot-products $k_t^T q_t$ (which appear both in the numerator through the covariance update and in the denominator via the normalizer) at $O(1)$ as dimensionality $d$ grows. Scaling the keys by $1/\sqrt{d}$ is sufficient to get the usual variance-preserving effect for the retrieval signal $C_t q_t$ and for the normalizer $n_t^T q_t$; scaling $q$ as well would merely change global parameter scales (and could be absorbed into other linear layers or gates) and is not necessary for the mLSTM math to behave stably.

Why this is the right move for mLSTM (intuitive + technical):
The mLSTM stores outer products $v_t k_t^\top$ into the matrix memory $C_t$ and accumulates the corresponding keys into the normalizer $n_t$. At retrieval the model computes
$$\tilde h_t = \frac{C_t q_t}{\max\{ |n_t^\top q_t|, 1\}}.$$
Expanding $C_t q_t$ gives sums of the form $\sum_i v_i (k_i^\top q_t)$. So the scalar projection $k_i^\top q_t$ controls how much each stored value $v_i$ contributes to the readout; likewise $n_t^\top q_t = \sum_i (i\cdot f\cdots) (k_i^\top q_t)$ is the magnitude normalizer. If the components of $W_k x$ (and of $q$) have variance $\sim 1$, then without scaling the inner products $k^\top q$ have variance that grows like $d$, which would make both the numerator and denominator blow up with $d$ and destabilize training. Multiplying $k$ by $1/\sqrt{d}$ makes $k^\top q$ have variance $O(1)$ (the same reason Transformer divides $q\cdot k^\top$ by $\sqrt{d}$).

Why only $k$ and not $q$:
In Transformers the attention formula is explicitly $q k^\top / \sqrt{d}$, so the division is applied to the dot-product (equivalently split symmetrically). In mLSTM the effective dot-products that matter are $k^\top q$ inside both the read-signal and the normalizer. Dividing the key vector by $\sqrt{d}$ is algebraically equivalent to dividing the dot-product by $\sqrt{d}$ (i.e., $(1/\sqrt{d}\, k)^\top q = (k^\top q)/\sqrt{d}$). Because the keys are directly used in the covariance update ($v k^\top$) and in the normalizer (sums of $k$), scaling $k$ is the straightforward place to impose the $1/\sqrt{d}$ factor so that both storage and retrieval scales are controlled. The queries $q$ are generated by a separate projection $W_q$ (after layer-norm), and in practice their scale can be adjusted by $W_q$, the output gate, or later linear layers; thus the paper fixes the key scale to enforce variance preservation without having to change $q$.

Would symmetric scaling of $q$ and $k$ change behavior of the normalizer or $C_t q_t$?
If you scaled both $q$ and $k$ by $1/\sqrt{d}$ (so the dot becomes $(k^\top q)/d$), you would reduce the magnitude of the raw dot-products by an extra factor of $1/\sqrt{d}$. Since both numerator ($C_t q$) and denominator ($n_t^\top q$) would be multiplied by the same factor, their ratio $\tilde h_t = (C_t q) / (n_t^\top q)$ would remain approximately the same up to learned rescaling (assuming scaling is exact and no thresholding effects). Concretely, symmetric scaling changes absolute magnitudes entering nonlinearities and affects gradients and optimizer dynamics, but the functional readout (ratio) is invariant up to multiplicative factors that the model can absorb into $W_v$, gates, or biases. The paper already enforces a lower bound of $1$ on the denominator and uses layer-norm before projecting keys/values; these practical design choices mean asymmetric scaling of keys is the minimal, robust fix to keep inner products stable without introducing extra bookkeeping.

Practical summary
- The main variance-preservation target is the scalar dot $k^\top q$ appearing repeatedly in storage and retrieval (and in the normalizer). Scaling $k$ by $1/\sqrt{d}$ makes those dot-products $O(1)$.  
- Scaling $q$ instead (or symmetrically scaling both) would also control variance, but scaling $k$ is natural here because keys participate directly in the outer-product updates and in the normalizer; scaling only $k$ is the simplest, equivalent way to implement the usual $1/\sqrt{d}$ normalization of dot-products.  
- Symmetric scaling would not change the essential ratio $C_t q / (n_t^\top q)$ (it would mostly rescale numerator and denominator together), though it would change absolute magnitudes and gradients; those differences can usually be absorbed by other learned linear layers or gate biases.

So the choice in the paper is a pragmatic, minimal variance-preserving normalization targeted where it matters (the keys used in covariance updates and normalizer), and it leaves $q$ and $v$ scales free to be handled by their own projections and gates.

### How is the claim "xLSTM has constant memory w.r.t. sequence length" reconciled with backpropagation and large d?
Question:
The paper states xLSTM has linear compute and constant memory in sequence length, unlike Transformers. I want to check the details:
- During training with backprop, unless using reversible tricks or checkpointing, you must store activations per step. Is the claim meant for inference only?
- For mLSTM, the cell state is a d \times d matrix per head. Even if memory is constant in sequence length L, the constant can be large (O(d^2)). How does this affect practical memory usage compared to a Transformer with KV cache O(L d) at inference?
- Could the authors provide a precise big-O summary for both training and inference memory in terms of batch B, length L, model dim D, and head dim d?
Answer:
Short answer: the “constant memory w.r.t. sequence length” statement in the paper applies to inference (generation) memory usage, not to the naive training-with-backprop case. During training you still typically need to store per-step activations unless you apply checkpointing/recompute/reversible techniques, so training memory grows with sequence length. Moreover, the “constant” cost for the mLSTM is an L‑independent but model‑dimension dependent term (the matrix memory), and that can be large ($O(d^2)$ per memory head) compared to a Transformer’s per‑token KV cache $O(LD)$ at inference — the tradeoff is memory capacity vs. dependence on $L$. Below I give an intuitive explanation and precise big‑O formulas in terms of batch $B$, length $L$, model dim $D$, and head dim $d$ (assume $h = D/d$ heads).

1) Why the paper claims “constant memory w.r.t. $L$”
The paper is contrasting two regimes: (a) autoregressive Transformer generation with a KV cache grows linearly with past length $L$ (KV cache stores past keys/values for every position), so inference memory is $O(LD)$; (b) xLSTM / mLSTM maintain a compressed internal memory (matrix or scalar states) whose size does not grow with $L$, so inference memory does not depend on $L$. That is what they mean by “constant memory w.r.t. sequence length.” This is an inference claim: you can keep a fixed-size internal state and generate arbitrarily long sequences without enlarging the model’s working memory by the number of past tokens.

2) Training / backprop nuance
When training with backprop through time (BPTT) in the usual way you must keep activations (or other checkpoint information) for each time step in order to compute gradients. That implies a memory cost that grows with $L$ for both RNN/LSTM variants and Transformers when training on full contexts. So unless you add explicit memory-saving measures (checkpointing, reversible layers, adjoint methods, or special parallelized backward algorithms), the training memory is $O(B L D)$ (activations dominate). The paper mentions “this recurrence can be reformulated in a parallel version” for mLSTM and that mLSTM updates are parallelizable, but reformulating forward computation to be parallel does not by itself remove the need to store per-step forward activations for backprop unless you also change the training algorithm.

3) The mLSTM “constant” can be large: how big?
mLSTM stores a matrix memory per head of size $d \times d$. If there are $h$ heads ($h = D/d$), total matrix memory is $O(h d^2) = O(D d)$. So the L-independent memory term for mLSTM is proportional to $D d$ (or $O(h d^2)$). This is larger than a scalar LSTM cell ($O(D)$), but crucially it does not grow with sequence length $L$. Compare to a Transformer KV cache for inference which is $O(L D)$. Thus:

- For small $L$ and large $d$, mLSTM’s $O(D d)$ can exceed the Transformer KV cache $O(L D)$.  
- For very long $L$, Transformer’s $O(L D)$ will dominate and mLSTM’s fixed $O(D d)$ becomes advantageous.

Which regime is better depends on $L$ and $d$: mLSTM trades an $L$‑independent memory budget (capacity) for avoiding the linear-in-$L$ KV accumulation.

4) Big‑O summaries (practical/common assumptions)
Notation: $B = $ batch size, $L = $ sequence length, $D = $ model dimension, $d = $ head dimension, $h = $ number of heads $= D/d$. I separate compute (flops/ops) and memory (working RAM) and split inference vs. naive training.

- Transformer (standard, full attention during training)
  - Inference (with KV cache stored): memory = $O(B D + L D)$ (token embeddings etc. plus KV cache $O(LD)$); compute per new token = $O(B D + L D)$ (to compute attention against cached keys/values), full forward for sequence of length $L$ would be $O(B L^2 D)$ if you do full attention in training/one-shot.
  - Training (naive BPTT / full attention): memory = $O(B L D)$ for activations (plus model params) and attention intermediate $T = O(B L^2)$ temporaries if you materialize all pairwise terms; compute = $O(B L^2 D)$ (quadratic in $L$).

- xLSTM (sLSTM part similar to LSTM; mLSTM has matrix memory)
  - Inference (mLSTM / xLSTM as used in paper): memory = $O(B D + h d^2) = O(B D + D d)$. Intuition: you still store per‑batch model activations for current token and the persistent matrix memory(s) of total size $h\cdot d^2$, but you do NOT need a cache that grows with $L$. Compute per step (new token) = $O(B \cdot (\text{model per‑token work}) + h\cdot d^2)$ where the dominant per-step memory update for mLSTM is the matrix update $O(h d^2) = O(D d)$. So per-token compute = $O(B D + D d)$. Over $L$ tokens, compute is $O(B L D + L D d) = O(B L D d)$ if you count the $d$ factor explicitly. The important point is memory does not scale with $L$.
  - Training (naive BPTT): memory = $O(B L D)$ (activations per timestep) + $O(h d^2)$ (matrix memory). Compute = $O(B L D d)$ (since each step updates the $d\times d$ matrices). Thus naive training still scales linearly in $L$ in memory because of stored activations for backprop, despite the internal memory itself being constant in $L$.

- If you use gradient checkpointing / recomputation / reversible strategies
  - You can trade compute for memory. With aggressive checkpointing / recompute you can reduce stored activations to $O(B D)$ (or some smaller multiple) at the cost of re‑computing forward passes during backward. For xLSTM/mLSTM you would then have inference/training working memory roughly $O(B D + D d)$ (the $O(D d)$ is the permanent matrix memory). Thus you can make training memory asymptotically independent of $L$ at the cost of extra compute proportional to $L$ for recomputation. The paper alludes to parallel reformulation and GPU optimizations, but does not claim they removed per-step activation storage during training without a recompute strategy.

5) Intuition and tradeoffs
Think of the mLSTM memory as a fixed-size associative table (a set of matrices) that accumulates statistics (outer products) about past tokens; its size is chosen by model design ($d$ and $h$). Transformers instead keep explicit token-level entries for every past position (the KV cache), so memory grows linearly with history length. If you want the ability to query arbitrarily long histories during inference without memory growth, a compressive memory like mLSTM ($O(D d)$) is attractive; if you need perfect access to every past token (and can afford memory), Transformer KV caching ($O(L D)$) is simpler and stores more raw information. During training, both families pay an extra cost proportional to $L$ unless you deliberately trade compute for memory with checkpointing.

Summary reference formulas (naive training and typical inference):
- Transformer inference (with KV cache): memory = $O(B D + L D)$. training memory (full attention): $O(B L D)$ (plus $O(B L^2)$ temporaries).
- xLSTM / mLSTM inference: memory = $O(B D + D d)$ (constant in $L$). naive training memory: $O(B L D + D d)$. With checkpointing/recompute you can reduce training memory asymptotically to $O(B D + D d)$ at the cost of extra compute.

These statements align with the paper’s claims: xLSTM achieves constant memory in $L$ at inference by keeping a fixed-size (but possibly large) internal matrix memory; the caveat is that naive training still requires per‑time-step activation storage unless you use recomputation or other memory savers.

### Why choose pre up-projection for mLSTM when C_t is d\times d, and how is the cost controlled?
Question:
The paper uses pre up-projection blocks for mLSTM so the memory operates in a higher-dimensional space, supposedly increasing capacity. But then C_t is of size d \times d in that higher space, which sounds expensive.

- How large is d relative to the model dimension D in practice for mLSTM blocks? Is d equal to the up-projected width, or is there a separate lower-dimensional memory space?
- What is the per-layer FLOP count for the C_t update (d \times d outer product and d \times d matrix-vector multiply), and how does that compare to attention with the same D and number of heads?
- Are there architectural tricks (e.g., low-rank memory, block-sparse C_t) used to keep cost manageable?
Answer:
Short answer: in this paper the matrix memory dimension $d$ is the high-dimensional "up-projected" width used by the mLSTM (i.e. the memory lives in the pre-up-projection space), so the costly $d\times d$ covariance is a deliberate trade–off: you get much higher storage capacity per layer at the expense of $O(d^2)$ compute per time step. The authors control cost by (a) keeping the memory update/retrieval free of learned parameters and fully parallelizable on GPUs, (b) using rank-1 (outer-product) updates so the add is cheap to form and parallelize, and (c) choosing $d$ to trade capacity vs compute in practice. The paper does not introduce explicit low-rank or block-sparse approximations for $C_t$ (though those are natural mitigations).

Explanation and technical detail, grounded in the paper
1) What is $d$ relative to the model dimension $D$?
The paper describes mLSTM as operating in a higher-dimensional pre-up-projection space: inputs are linearly mapped into a $d$-dimensional key/value/query space (they write e.g. $q_t = W_q x_t$, $k_t = (1/\sqrt{d}) W_k x_t$, $v_t = W_v x_t$). So $d$ is the width of that up-projection (the memory's row/column size). Practically, the authors treat $d$ as the mLSTM memory dimension (the dimension of keys, queries and values) and this is the size of the matrix memory $C_t \in \mathbb{R}^{d\times d}$. The paper does not introduce a second, separate low-dimensional memory; $C_t$ is explicitly $d\times d$ in that up-projected space. How $d$ relates numerically to the model embedding $D$ depends on design choices (they use conventional residual backbones and report experiments with typical embedding dims like $1024$), but the paper intentionally maps into a larger space to leverage Cover’s theorem — i.e. $d$ can be larger than the original model dimension $D$ to increase separability/capacity. The paper does not publish a single canonical ratio $d/D$; it treats $d$ as a hyperparameter to trade capacity vs compute.

2) FLOP count for the mLSTM $C_t$ update / retrieval and comparison to attention
Per time step and per layer the dominant mLSTM costs (ignoring small gating and projection costs) are the rank-1 update and the matvec retrieval:
- Rank-1 update: adding $i_t \cdot v_t k_t^T$ to $C_{t-1}$ costs $O(d^2)$ scalar adds (forming or streaming and adding the outer product).
- Retrieval ($C_t q_t$): dense matrix-vector multiply costs $O(d^2)$ multiplications/adds.
Thus, the leading-order per-token per-layer cost for mLSTM memory work is roughly $2\cdot d^2$ FLOPs (one $d^2$ for the outer-product addition, one $d^2$ for the matvec), plus negligible $O(d)$ for gating scalars and projections into $k,q,v$ (those are $O(d\cdot D)$ if $W_k/W_q/W_v$ map from $D$ to $d$, so include those in a fuller accounting).

Compare to multi-head self-attention (same total model dimension $D$ and $H$ heads with head dim $d_h = D/H$):
- Full (non-cached) attention over a sequence of length $L$ costs $O(L^2 \cdot D)$ overall and thus per token about $O(L \cdot D)$ for computing attention weights and weighted sums; per-layer per-token cost grows with $L$ (quadratic in sequence length overall).
- For incremental autoregressive decoding with KV cache, the per-token cost of producing one next token with multi-head attention is dominated by computing new keys/queries/values ($O(D^2)$ in projection cost if projecting from $D$ back into $D$, but often $O(D\cdot D)$ simplified) and the attention-weighted sum against cached keys/values; with $H$ heads the per-step cost of computing attention against $T$ cached tokens is $O(H \cdot d_h \cdot T)$ for the score computation and $O(H \cdot d_h \cdot T)$ for the softmax-weighted combination, i.e. $O(D \cdot T)$ per token (linear in accumulated context length $T$). So attention’s per-token cost grows with context length; by contrast mLSTM’s cost is constant per token ($O(d^2)$) independent of sequence length.

If you compare asymptotics for a single layer and ignore sequence-length dependence, attention’s projection and small matmuls give per-token costs roughly $O(D^2)$ for the projection pieces, plus the attention kernel cost which depends on the cached length. The paper’s practical point: mLSTM moves the quadratic dependence off the sequence length and into the fixed memory dimension $d$ (constant per token), whereas Transformers keep a cost that is quadratic in context length (or linear if special linearized attention approximations are used).

The paper reports that in their (unoptimized) implementation the mLSTM kernels are about $4\times$ slower than FlashAttention in wall-clock time, but that the memory update and retrieval are parallelizable on GPUs and thus the wall-clock overhead is "minor" when scaled across GPUs. So in practice you choose $d$ so $2\cdot d^2$ (plus projection cost) is acceptable for your throughput and capacity needs.

3) Architectural tricks to control cost
The paper itself lists the following practical controls and observations (it does not claim novel low-rank or block-sparse variants inside this work):
- Trade-off by design: the matrix memory $C_t$ has no learnable parameters (only the projection matrices $W_q, W_k, W_v$ and gating parameters are learned). This keeps model parameter count lower for a given capacity, while compute increases only through the explicit $d^2$ ops.
- Parallelizability: because the update is a rank-1 add and retrieval is a matvec, both are standard dense GPU operations that parallelize well (contrast this with sequential hidden-hidden recurrences). The authors emphasize that these ops can be done efficiently on modern accelerators, so wall-clock cost is less severe than naive FLOP counts suggest.
- Multiple heads / multiple cells: for mLSTM "multiple heads and multiple cells are equivalent" and there is no memory mixing. This lets practitioners split $d$ into several heads if that maps better to hardware or to match other architectures, but it does not reduce the total $d^2$ if you keep the same total $d$. (Heads can help with optimization and expressivity.)
- Stabilization and normalization: they use layer-norm before key/value projection, a denominator based on the normalizer state (and a lower bound) and exponential-gate stabilizers — these are about numerical stability rather than compute, but they make the larger $d$ practical to use.

What the paper does not claim (and therefore does not use) are explicit low-rank factorizations, block-sparsity, or compressed representations of $C_t$ inside the reported models. The authors acknowledge in Limitations (Section "Limitations") that "the matrix memory of mLSTM has high computation complexity" and that they traded capacity for compute; they also mention the possibility of faster CUDA kernels (FlashAttention-like) and leave more aggressive memory factorizations / sparsity as natural directions for future work. In short, the built-in cost control in the paper is hyperparameter tuning of $d$, parallel GPU implementation of rank-1 update + matvec, and keeping $C_t$ parameter-free, not structural compression of $C_t$.

Practical takeaway
If you want the mLSTM benefit but worry about cost, treat $d$ as a tunable knob: smaller $d$ shrinks the $O(d^2)$ bill but reduces memory capacity; splitting into heads can help optimize mapping to hardware; and engineering (optimized CUDA kernels, blocked matmuls, or future low-rank / sparse $C_t$ variants) is a practical route to keep wall-clock time reasonable. The paper demonstrates that with their choices and GPU-parallel implementations the approach is practical and competitive despite the $d\times d$ arithmetic.

### What are the recommended initializations for forget gates with exponential vs sigmoid to ensure stable time constants?
Question:
The Limitations section notes that "initialization of the forget gates must be chosen carefully." 

- For f_t = \sigma(\tilde{f}_t), classic LSTM practice is to bias the forget gate towards 1 (e.g., b_f positive). What are the analogous recommendations for f_t = \exp(\tilde{f}_t) so that E[f_t] is around a desired decay rate (say 0.99), without causing amplification?
- Any empirical guidance on initializing \tilde{f}_t and \tilde{i}_t distributions (means/variances) under LayerNorm so that the effective horizon aligns with common context lengths (e.g., 2k, 8k)?
Answer:
Short answer: pick the gate pre‑activation bias so the gate’s expected value matches your desired per‑step decay $r$ (e.g. $r \approx \exp(-1/H)$ for an effective horizon $H$). For the sigmoid forget gate $f_t = \sigma(\tilde f_t)$ this is the familiar logit/bias trick. For the exponential forget gate $f_t = \exp(\tilde f_t)$ you must account for pre‑activation variance: if $\tilde f_t$ has variance $\sigma^2$, then $E[\exp(\tilde f_t)] = \exp(\mu + \sigma^2/2)$, so set $\mu = \ln r - \sigma^2/2$. In practice under pre‑LayerNorm (zero mean, small variance) use small weight std and initialize biases so typical $f_t < 1$ (avoid amplification), and initialize the input gate so its expected contribution matches $1 - r$ (or your desired learning rate). Below are concise formulas, worked numeric examples for common horizons, and pragmatic recommendations consistent with the paper’s stabilization.

Why this matters (intuition). The forget gate controls the per‑step multiplicative decay of stored memory. If you want the memory to persist for about $H$ steps, a per‑step retention $r \approx \exp(-1/H)$ (or approximately $1 - 1/H$ if $H$ is large) is a natural target. For sigmoid gates you bias the pre‑activation so the sigmoid’s mean sits near $r$. For exponential gates the mapping is multiplicative and unbounded above, so variance in the pre‑activation shifts the mean (Jensen’s inequality); you must compensate for that and keep the distribution tightly concentrated to avoid occasional $f_t > 1$ (amplification). The paper uses a stabilizer $m_t$ and shows exponential gating works robustly when stabilized — but careful initialization still matters (limitation (iv)).

Formulas and recipe (technical):

1) Desired per‑step retention $r$ from horizon $H$:
   $r = \exp(-1/H)$  (so for large $H$, $r \approx 1 - 1/H$).

2) Sigmoid forget gate $f_t = \sigma(\tilde f_t)$.
   If pre‑activation $\tilde f_t$ has mean $\mu$ and small variance, set
   $\mu = \operatorname{logit}(r) = \ln\!\left( \frac{r}{1 - r} \right)$.
   If your implementation uses a bias $b_f$ and LayerNorm makes pre‑activations zero‑mean from weights, set $b_f = \operatorname{logit}(r)$.
   Example: $H = 2000 \Rightarrow r \approx \exp(-1/2000) \approx 0.9995 \Rightarrow b_f \approx \ln(0.9995/0.0005) \approx 7.6$.
            $H = 8000 \Rightarrow b_f \approx \ln(0.999875/0.000125) \approx 9.0$.

3) Exponential forget gate $f_t = \exp(\tilde f_t)$.
   If $\tilde f_t$ is approximately Gaussian with mean $\mu$ and variance $\sigma^2$, then
   $E[f_t] = E[\exp(\tilde f_t)] = \exp(\mu + \sigma^2/2)$.
   To get $E[f_t] \approx r$ set
   $\mu = \ln r - \sigma^2/2$.
   If LayerNorm makes pre‑activations zero‑mean and you control $\sigma$ (see below), you can approximate $\mu \approx \ln r$ (when $\sigma^2 \ll 1$), i.e. initialize bias $b_f \approx \ln r$ (a small negative number for $r < 1$).
   Numeric examples: $H = 2000 \Rightarrow r \approx 0.9995 \Rightarrow \ln r \approx -0.0005$ so $b_f \approx -5\times 10^{-4}$ (very small negative). $H = 8000 \Rightarrow b_f \approx -1.25\times 10^{-4}$.

4) Input gate $i_t$ when exponential: $i_t = \exp(\tilde i_t)$.
   The steady‑state contribution of inputs should balance the forgetting. A simple heuristic is to target $E[i_t] \approx 1 - r$ (so the expected new input per step compensates the expected decay). Thus initialize $\tilde i$ mean $\mu_i$ so
   $\exp(\mu_i + \sigma_i^2/2) \approx s := 1 - r  \;\Rightarrow\;  \mu_i = \ln s - \sigma_i^2/2$.
   Example: $H = 2000$ with $r \approx 0.9995$ gives $s \approx 0.0005$, so $\mu_i \approx \ln(5\times 10^{-4}) \approx -7.6$ (so input gate initialized much more negative than forget gate). For sigmoid input gates use $\operatorname{logit}(s)$ analogously, but note input gates often intentionally allow smaller average values (small learning rate).

Practical recommendations consistent with the paper’s methods and stabilization:

- Use LayerNorm / pre‑LayerNorm as in the paper so pre‑activations are centered; then biases control the mean. But remember LayerNorm doesn’t force tiny variance — weight scale matters.

- Keep pre‑activation variance small for exponential gates. Small $\sigma^2$ makes the correction term $\sigma^2/2$ negligible and reduces probability of $f_t > 1$. Achieve this by small initial weight std (e.g. 0.01–0.05 for the gate projections) and/or initializing recurrent gains near 0, at least initially.

- Prefer sigmoid if you need a strict bound $0 < f_t < 1$ with no risk of amplification; prefer exponential if you want the arithmetic behavior and benefits argued in the paper (revision of storage decisions), but then use the model’s stabilizer ($m_t$) and tight initialization.

- Use the stabilizer in the paper (Equation (3)) which subtracts a running max log term so numerical overflow is avoided and relative scaling preserved. Still initialize means so that typical $\tilde f$ is negative (for decay), not positive.

- Monitor gate statistics during a short warmup: track percent of $f_t > 1$ and $E[f_t]$. If you see $f_t$ frequently $> 1$, reduce gate weight std or shift bias more negative. A small negative drift ($b_f$ slightly below $\ln r$) is safer than any positive bias.

- For desired effective horizons: translate $H$ to $r$ and then to bias. Because sigmoids require large positive biases for very large $H$, these can be numerically large; exponential gives very small negative biases instead. For example, to aim $H \approx 2000$:
   - Sigmoid forget bias $b_f \approx +7.6$ (large)
   - Exponential forget bias $b_f \approx \ln r \approx -5\times 10^{-4}$ (tiny)
  This stark difference explains the “careful initialization” caveat in the paper: for sigmoids you inject large biases; for exponentials you must control variance to keep $E[\exp(\tilde f)]$ near $r$.

- Initialization summary recipe to try in practice (conservative):
   * Use pre‑LayerNorm as in xLSTM. Initialize gate projection weights with small std (e.g. 0.01).
   * Compute $r = \exp(-1/H)$. If using sigmoid forget: set $b_f = \ln\!\left(\frac{r}{1-r}\right)$. If using exponential forget: set $b_f = \ln r$ (or $\ln r - \sigma^2/2$ if you know $\sigma^2$).
   * For exponential input gate target $s = 1 - r$, set $b_i = \ln s$ (or $\ln s - \sigma_i^2/2$). In practice choose $b_i$ much smaller (more negative) than $b_f$ so inputs are sparse.
   * Keep recurrent gating weights small initially; rely on learning to adapt gates.
   * Use the stabilization $m_t$ from the paper (Equation (3)) to avoid overflow and preserve gradients.

Empirical tuning notes from the paper’s approach. The authors explicitly stabilize exponential gates (so exponential gating is used successfully) and report that careful initialization of forget gates is a limitation to watch. When they trained large models and used LayerNorm + the stabilizer, exponential gates worked well and allowed long effective horizons (they train with context up to 16k and observe good extrapolation). Therefore a practical workflow is: (1) set biases by the formulas above for your target $H$, (2) use small initial weight variance, (3) enable stabilizer exactly as in the paper, and (4) validate gate statistics and adjust if you see amplification or too‑fast forgetting.

If you want a short checklist for $H=2000$ and exponential gates: set $b_f \approx \ln\big(\exp(-1/2000)\big) \approx -0.0005$, set $b_i \approx \ln\big(1-\exp(-1/2000)\big) \approx -7.6$, initialize gate weights with $\text{std} \approx 0.01$, and enable the $m_t$ stabilizer. Monitor $E[f_t]$, fraction $f_t>1$, and effective decay measured on a held‑out short run; nudge biases slightly more negative if you observe amplification.

This answer follows the paper’s design (pre‑LayerNorm, exponential gating + stabilizer, and the warning that forget bias must be chosen carefully) and gives the correct mathematical relation between desired decay $r$, mean and variance of pre‑activations, and the initial biases you should set.

### What is meant by "the matrix memory has no parameters" when W_q, W_k, W_v exist?
Question:
The paper says "The memory of mLSTM does not require parameters" but the update uses v_t k_t^\top, where k_t and v_t come from parameterized projections W_k, W_v. 

- Is the statement specifically that the state update C_t = f_t C_{t-1} + i_t v_t k_t^\top uses no learned transformation applied to C_{t-1} beyond a scalar f_t, unlike e.g. learned A C_{t-1} A^\top style updates?
- So "no parameters" means the update rule itself is fixed (covariance outer-product programming), even though the features are learned. Is that the correct interpretation?
Answer:
Short answer: your interpretation is correct. When the paper says “the memory of mLSTM does not require parameters” it means the memory state itself and its update rule are not implemented via learned parameter matrices that act on the memory; the memory update is a fixed (non‑learned) outer‑product / covariance operation. That is different from having learned linear transforms that directly reparameterize or mix the memory matrix at each step.

More detail and intuition: in mLSTM the matrix memory is the state $ \mathbf{C}_t \in \mathbb{R}^{d \times d} $ and it evolves by the covariance-style rule
$$
\mathbf{C}_t = f_t\,\mathbf{C}_{t-1} + i_t\,\mathbf{v}_t\mathbf{k}_t^\top .
$$
This rule is a fixed mathematical operation: scale the old memory by the scalar $f_t$ (forget/decay) and add the outer product of the current value and key, scaled by the scalar input gate $i_t$. Nothing in this update multiplies $ \mathbf{C}_{t-1} $ by a learned matrix (no learned $ \mathbf{A} $ so that $ \mathbf{C}_t = \mathbf{A}\mathbf{C}_{t-1}\mathbf{A}^\top $ or similar). That is what the authors mean by “no parameters” for the memory: the recurrence that updates and stores information in $ \mathbf{C} $ does not itself contain learned weights.

At the same time the model does have parameters: $ \mathbf{W}_q, \mathbf{W}_k, \mathbf{W}_v, \mathbf{W}_o $ and the gate parameter vectors produce the query, key, value and gates from the input $ \mathbf{x}_t $. Those parameters are used to produce the features $ \mathbf{q}_t, \mathbf{k}_t, \mathbf{v}_t $ and the scalars $ i_t, f_t, o_t $. But once $ \mathbf{k}_t, \mathbf{v}_t $ are produced, the operation that writes into memory is the fixed outer product $ \mathbf{v}_t\mathbf{k}_t^\top $; there is no extra learned transformation applied to $ \mathbf{C}_{t-1} $ or to that outer product before adding it to the memory.

So you can view it as a separation between (a) learned feature extraction (the parameterized projections that produce q/k/v and the learned gate generators) and (b) an unparameterized (fixed) memory programming rule (the covariance/outer‑product write and scalar decay). This is exactly the same style used in Fast Weights / associative memory literature: the “weights” (memory matrix) are updated by outer products of learned features, but the update rule is not itself a learned mapping.

Contrast this with an alternative design where the memory update would include learned matrices acting on $ \mathbf{C}_{t-1} $ (for example $ \mathbf{C}_t = \mathbf{A}\mathbf{C}_{t-1}\mathbf{A}^\top + \dots $ or $ \mathbf{C}_t = \mathbf{C}_{t-1} + \mathbf{W}\,\mathbf{v}_t\mathbf{k}_t^\top $), in which case the memory dynamics themselves would contain parameters. The paper deliberately avoids that; the parameters live in the projections/gates, not in the memory update rule.

This design is why the authors say the memory “does not require parameters” even though keys/values/queries are produced by parameterized projections.

### How does mLSTM relate theoretically to Bidirectional Associative Memories (BAM) optimality beyond binary vectors?
Question:
The paper cites results that covariance updates are optimal for separability of binary vectors. But modern LMs use continuous embeddings.

- Are there extensions of the Dayan/Sejnowski/BAM optimality results to continuous, zero-mean vectors with LayerNorm? 
- If not, what is the intuitive justification for using the same covariance rule with floating-point embeddings, and how does the normalizer n_t adjust for non-binary magnitudes?
Answer:
Short answer: the paper does not claim a formal extension of the Dayan/Sejnowski / BAM optimality theorem to arbitrary continuous embeddings after LayerNorm. There is no rigorous, widely‑accepted generalization in the paper (or in the classic BAM literature) that proves the covariance (outer‑product) update is strictly optimal for separability for arbitrary real‑valued, non‑binary vectors. However, there are clear, intuitive and practical reasons—anchored in standard statistical/Hebbian arguments and in the paper’s design choices—why the same covariance rule is a good choice for floating‑point embeddings, and why the mLSTM normalizer $n_t$ compensates for non‑binary magnitudes.

Why the covariance rule is still sensible for continuous, LayerNormed embeddings
- The original Dayan/Sejnowski result shows that adding outer products $v k^\top$ produces a memory matrix that maximises separability (signal/noise) when stored and retrieved patterns are binary and orthogonality assumptions hold. That is a clean analytic result for a restricted setting.
- For continuous embeddings, the outer‑product update is the natural Hebbian / covariance rule: it reinforces correlations between components of the stored value $v$ and the key $k$. If keys and values are informative encodings of content, their outer product encodes pairwise associations so that later queries that align with $k$ produce the corresponding $v$‑like response. This is exactly the behaviour we want for associative memory.
- If you pre‑normalize (LayerNorm) the inputs so keys have zero mean and roughly comparable variances, the covariance interpretation becomes more appropriate: the matrix accumulates centered second‑order statistics (covariances) between components of keys and values, which boosts signal for matching directions and suppresses constant offsets that would otherwise swamp retrieval.
- Under mild statistical assumptions (e.g. approximately zero mean keys, limited correlation structure, and roughly bounded norm), the outer‑product rule tends to maximize the expected dot between stored values and appropriate queries while keeping interference from unrelated keys moderate. Various lines of work (Fast Weights, linearized attention, and associative memory literature) exploit exactly this property even when embeddings are real‑valued.

How the normalizer $n_t$ (and the denominator in retrieval) compensates for non‑binary magnitudes
- In mLSTM the retrieved pre‑output is $\tilde h_t = \dfrac{C_t q_t}{\max\{|n_t^\top q_t|, 1\}}$. Here $n_t$ = sum of (gated) keys over time (weighted by input gate and future forget gates). Intuitively $n_t$ tracks the aggregate “strength” and direction of keys that contributed to $C_t$.
- If many keys or very large‑magnitude keys contribute, $C_t q_t$ can become large simply because of scale or because many weakly relevant terms add up; dividing by $n_t^\top q_t$ normalizes retrieval by the expected overlap between the query and the sum of stored keys. In other words, it turns the multiplicative outer‑product readout into something closer to a normalized (cosine‑like) read that is robust to the absolute magnitudes and to the number of contributions.
- Using the absolute value and a lower bound of $1$ (as in the paper) prevents division by numbers close to zero (which would blow up retrieval) and prevents overly shrinking a legitimately small signal. This is a pragmatic stability fix: when keys sum to near‑orthogonality with $q$, the denominator floor avoids amplification of noise; when there is strong alignment, the denominator scales the retrieved vector so its magnitude stays in a usable range for downstream layers and gates.
- LayerNorm before key/value projection helps make this normalization meaningful: keys are roughly zero‑mean and bounded, so $n_t^\top q_t$ is a sensible proxy for expected match strength. The input gate $i_t$ and forget gate $f_t$ play the roles of learning rate and decay (as the paper notes), so $n_t$ also encodes how much “weight” the memory currently holds in the directions relevant to retrieval.

Broader conceptual connections and practical justification
- Practically, many modern “fast weight” / linear‑attention / retention models use variations of outer‑product updates and similar normalization to good effect. Those empirical successes support the intuition that covariance‑style updates are useful beyond binary theory.
- The covariance / outer‑product rule is computationally cheap, parallelizable, and parameter‑free in the memory update; combined with gating and normalization it becomes robust to floating‑point embedding behavior, which is why the paper integrates it into mLSTM.
- Formally proving an exact optimality statement that mirrors Dayan/Sejnowski for arbitrary continuous, LayerNormed embeddings would require specifying distributional assumptions on embeddings and retrieval criteria (e.g. precise SNR notion). The paper does not attempt such a theorem; instead it relies on the statistical intuition (centered, bounded embeddings), gating interpreting forget/input as decay/learning rates, and the normalizer to handle scale.

In short: there is no direct, formal extension in the paper proving the same BAM optimality for arbitrary continuous vectors, but the covariance (outer‑product) update remains the natural, statistically motivated associative memory rule for real embeddings—and the mLSTM’s $n_t$ + denominator explicitly corrects for non‑binary magnitudes and for the number/strength of contributions, making retrieval stable and scale‑invariant in practice.

### What are the exact output dimensions and gating semantics in mLSTM (vector vs scalar o_t)?
Question:
In mLSTM, the output gate is written as a vector: o_t = \sigma(\tilde{o}_t), with \tilde{o}_t = W_o x_t + b_o, and the hidden state is h_t = o_t \odot \tilde{h}_t. 

- Is o_t the same dimension as \tilde{h}_t (i.e., per-dimension gating)? 
- If there are multiple cells/heads, is o_t computed per head and then concatenated, or is there a single o_t applied after concatenation/projection? 
- Any reason to prefer per-dimension gating over a scalar gate in practice for stability or expressivity?
Answer:
Short answer: In the mLSTM of the paper the output gate is a vector matched to the hidden-vector (i.e. per-dimension gating). When you use multiple heads/cells you compute an output gate for each head/cell (matching that head’s dimensionality) rather than a single scalar gate applied after concatenation. The paper uses per-dimension gating for expressivity and practical stability, and their ablations show gating matters.

Why (grounded in the paper)

1) Dimensions and semantics in the paper. The mLSTM forward equations (Eqns. in Section 2.3) write the output gate as
$$
\mathbf{o}_t=\sigma(\tilde{\mathbf{o}}_t),\qquad
\tilde{\mathbf{o}}_t=\mathbf{W}_{\mathbf{o}}\mathbf{x}_t+\mathbf{b}_{\mathbf{o}},
$$
and the hidden state as
$$
\mathbf{h}_t=\mathbf{o}_t\odot\tilde{\mathbf{h}}_t,
$$
so $\mathbf{o}_t$ is a vector with the same dimensionality as $\tilde{\mathbf{h}}_t$ and is applied elementwise (Hadamard product). That is per-dimension gating, not a single scalar.

2) Multiple heads / cells. The paper states explicitly that for mLSTM “multiple heads and multiple cells are equivalent as there is no memory mixing.” In practice that means each memory head/cell produces its own key/query/value and its own $\mathbf{o}_t$ (of that head’s dimensionality); the outputs of heads are then combined (e.g. concatenated/projection) downstream. There is no single global scalar output gate applied after concatenation in the mLSTM formulation shown.

3) Why per-dimension (vector) gating vs scalar gate. Intuitively and as the paper argues via ablations, learnable input/forget/output gates are important. A vector gate lets the model scale each latent feature independently, which (a) increases expressivity — different dimensions can carry different sorts of information and be released to the hidden state at different strengths — and (b) helps optimization/stability because the model can route gradients and activations dimensionwise rather than forcing a uniform on/off decision over an entire head. The paper demonstrates that gating choices and making gates input-dependent give incremental positive effects (see Ablation Studies, Section 3.2). Practical notes from the paper: exponential gating (used for input/forget) requires stabilization machinery, but the output gate remains a sigmoid vector and is simple and stable to use elementwise.

Practical recommendation: follow the paper — use a vector $\mathbf{o}_t$ of the same dimension as $\tilde{\mathbf{h}}_t$ and, for multi-head setups, compute per-head output gates (each head producing its own $\mathbf{o}_t$). This matches the mLSTM design, gives maximal expressive power, and is what their experiments/ablations support.

### Could someone provide a proof sketch that stabilized gates leave both outputs and gradients unchanged?
Question:
The appendix is referenced for the claim that replacing i_t,f_t by stabilized i'_t,f'_t via m_t leaves the network outputs and gradients w.r.t. parameters unchanged. 

- Could someone outline the core argument in a few steps? For example, show that at each step, both c_t and n_t are multiplied by e^{-m_t} (or equivalent), thus h_t = o_t (c_t/n_t) is invariant, and then argue that backprop through the rescaling yields identical parameter gradients. 
- How is the nondifferentiability of max handled in the gradient equivalence proof?
Answer:
Short answer: the stabilizer $m_t$ only rescales the internal cell and normalizer by the same factor at every step, so the observable hidden state (which is the ratio $c_t / n_t$ times output gate) is unchanged; because that rescaling cancels in the forward ratio, the chain-rule factors introduced by the scaling also cancel in backprop, so parameter gradients match. The nondifferentiability of max is negligible: the equality holds almost everywhere and any consistent subgradient/tie-break yields the same result.

Proof sketch (induction-style, with the key equations from the paper).

Write the unstabilized gates as
$i_t = \exp(\tilde{i}_t), \; f_t = \exp(\tilde{f}_t)$ (we omit the cases where $f$ is sigmoid; the same argument applies where only $i$ is exponential). The stabilizer is defined by
$$m_t = \max\big(\log f_t + m_{t-1},\; \log i_t\big)$$
and the stabilized gates are
$$i'_t = \exp(\log i_t - m_t) = \exp(\tilde{i}_t - m_t),$$
$$f'_t = \exp(\log f_t + m_{t-1} - m_t).$$

Forward invariance. Define the original (unstabilized) cell and normalizer recurrences
$$c_t = f_t c_{t-1} + i_t z_t,\qquad n_t = f_t n_{t-1} + i_t.$$
Define the stabilized recurrences (replace $f_t,i_t$ by $f'_t,i'_t$)
$$c'_t = f'_t c'_{t-1} + i'_t z_t,\qquad n'_t = f'_t n'_{t-1} + i'_t,$$
with the same initial conditions up to the same convention (e.g. $c'_0 = c_0 e^{-m_0},\; n'_0 = n_0 e^{-m_0}$).

Claim: for all $t$, $c'_t = e^{-m_t} c_t$ and $n'_t = e^{-m_t} n_t$. Prove by induction. For $t=1$ one checks directly using definitions of $i'_1,f'_1$. Assume $c'_{t-1} = e^{-m_{t-1}} c_{t-1}$ and $n'_{t-1} = e^{-m_{t-1}} n_{t-1}$. Then

$$\begin{aligned}
c'_t &= f'_t c'_{t-1} + i'_t z_t \\
     &= \big[\exp(\log f_t + m_{t-1} - m_t )\big]\big[e^{-m_{t-1}} c_{t-1}\big] + \big[\exp(\log i_t - m_t )\big] z_t \\
     &= e^{-m_t}\big[ f_t c_{t-1} + i_t z_t \big] \\
     &= e^{-m_t} c_t.
\end{aligned}$$

The same algebra gives $n'_t = e^{-m_t} n_t$. Hence at every step the cell and normalizer are scaled by the same factor $e^{-m_t}$.

Because the hidden state uses their ratio,
$$\tilde{h}_t = c_t / n_t = \frac{e^{m_t} c'_t}{e^{m_t} n'_t} = c'_t / n'_t,$$
so the pre-output $\tilde{h}_t$ and thus the hidden output $h_t = o_t * \tilde{h}_t$ are identical with or without stabilization. Therefore the entire network outputs are the same for the same parameters and inputs.

Gradient invariance. Let $L$ be any scalar loss that depends on the network outputs ($h_t$) and hence on the ratios $r_t = c_t / n_t$ only via the usual dependencies. Consider derivatives w.r.t. any parameter $\theta$ that influences $\tilde{i}_s$ or $\tilde{f}_s$ (and thereby $i_s,f_s$). Using the inductive equalities $c'_t = e^{-m_t} c_t$ and $n'_t = e^{-m_t} n_t$, every quantity on the forward computation graph that affects $L$ is numerically identical between the stabilized and unstabilized networks (not just $h_t$ but also any intermediate linear combinations that feed into later gates, up to the global scalings at that step). The chain rule contributions introduced by the factors $e^{-m_t}$ cancel because $c$ and $n$ are scaled identically. Concretely, when you differentiate $L$ through $r_t = c_t/n_t$, the partial derivatives satisfy

$$\frac{\partial L}{\partial c_t} = \frac{1}{n_t}\frac{\partial L}{\partial r_t},\qquad
\frac{\partial L}{\partial n_t} = -\frac{c_t}{n_t^2}\frac{\partial L}{\partial r_t}.$$

Under stabilization $c'_t = e^{-m_t} c_t$ and $n'_t = e^{-m_t} n_t$, so

$$\frac{\partial L}{\partial c'_t} = \frac{1}{n'_t}\frac{\partial L}{\partial r'_t} = \frac{e^{m_t}}{n_t}\frac{\partial L}{\partial r_t} = e^{m_t}\frac{\partial L}{\partial c_t},$$
$$\frac{\partial L}{\partial n'_t} = -\frac{c'_t}{n'_t{}^2}\frac{\partial L}{\partial r'_t} = e^{m_t}\frac{\partial L}{\partial n_t}.$$

These extra factors $e^{m_t}$ precisely cancel the $e^{-m_t}$ factors that relate $c'_t$ and $n'_t$ to predecessors (when propagating derivatives further to $i_t$ and $f_t$) because the derivative of, say, $c'_t$ w.r.t. $i'_t$ is multiplied by $z_t$ and does not introduce additional $m_t$ dependence, while $i'_t$ itself equals $\exp(\tilde{i}_t - m_t)$, whose derivative w.r.t. $\tilde{i}_t$ is $i'_t$. Carrying through the algebra for $\partial L/\partial\tilde{i}_s$ and $\partial L/\partial\tilde{f}_s$ shows equality between stabilized and unstabilized networks (the local multipliers from scaling cancel). In other words, the Jacobian factors introduced by the forward $e^{-m_t}$ scaling are undone by the reverse-path $e^{m_t}$ scaling in the backpropagation multipliers, so gradients w.r.t. pre-activations and therefore w.r.t. parameters are identical.

Non-differentiability of max. The stabilizer $m_t$ uses $m_t = \max(a, b)$ with $a = \log f_t + m_{t-1},\; b = \log i_t$. The function $\max$ is nondifferentiable only when $a = b$ (a measure-zero set under continuous distributions of pre-activations). In practice, standard constructions handle this by selecting any valid subgradient at ties (e.g. choose one branch or take a convex combination); the algebra above still holds for any consistent choice because when $a = b$ the two branches produce identical scaling factors (both give the same $m_t$), and the forward equality $c'_t = e^{-m_t} c_t$ remains true. Thus the gradient-equality argument holds almost everywhere; at tie points one may invoke subgradient calculus or define a deterministic tie-break, and the gradients remain consistent with the stabilized arithmetic.

Takeaway. Stabilization is an algebraic rescaling that preserves the important observable ratio $c_t/n_t$ at every step; because forward rescaling is identical for both numerator and denominator, backpropagation factors cancel and parameter gradients remain the same (up to the usual caveat about measure-zero nondifferentiable tie points, which are harmless in practice). This is why replacing $i_t,f_t$ by $i'_t,f'_t$ via $m_t$ leaves both outputs and gradients unchanged.

### How does xLSTM achieve better length extrapolation than Transformers and Mamba trained at 2k context?
Question:
The 1.3B models trained at context 2048 are evaluated up to 16384, and xLSTM maintains lower perplexity. I would like a mechanistic explanation:
- Is the key factor that the state c_t (or C_t) has a time-invariant update with decays and normalized retrieval, making representation quality less sensitive to absolute position beyond training horizon?
- Do the exponential gates learn to set an effective decay profile that keeps useful information without overfitting to a fixed window, unlike attention with learned positional biases?
- Any diagnostic plots (e.g., learned decay spectra, gate statistics vs position) that support the extrapolation mechanism?
Answer:
Short answer: yes — the paper’s mechanistic explanation is precisely that xLSTM’s time‑invariant multiplicative memory dynamics (learned exponential gates acting as per‑step decay and learning rates) together with the normalizer-based, ratio‑style retrieval make the stored signal depend on relative gate products rather than the absolute position inside the training horizon. That makes representations less sensitive to “being beyond the training window” and so they extrapolate better than standard attention architectures trained at a fixed context length.

Why that is plausible (intuitively, then technically). Intuitively, extrapolation fails when a model’s internal readout depends on absolute index‑based patterns (e.g. attention tables or positional bias learned only inside the training horizon) or when stored traces decay in a way that’s implicitly tied to how long training sequences were. xLSTM instead stores information multiplicatively through time: each stored contribution is multiplied by a learned forget factor each step and added with a learned input scale. Because those dynamics are local and time‑homogeneous (the same update rule every step), the influence of an item at time $t$ on a later retrieval at time $t+\tau$ is governed by the product of per‑step gate factors over the intervening $\tau$ steps, independent of absolute $t$. The mLSTM extends this to keys/values with a covariance update and then divides the retrieved vector by a normalizer that accumulates the same gate products applied to keys. That division makes the retrieval depend on ratios (signal relative to the accumulated gate mass), which is invariant to overall scaling accumulated over long sequences.

More concretely, the core mLSTM recurrence is
$$
\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top,\qquad
\mathbf{n}_t = f_t \mathbf{n}_{t-1} + i_t \mathbf{k}_t,
$$
and retrieval uses
$$
\tilde{\mathbf{h}}_t = \frac{\mathbf{C}_t \mathbf{q}_t}{\max\{|\mathbf{n}_t^\top \mathbf{q}_t|,1\}}.
$$
So the contribution of a past pair at time $s$ to $\mathbf{C}_t$ is proportional to $i_s \prod_{u=s+1}^t f_u$ (and similarly for $\mathbf{n}_t$). This dependence on products of identical per‑step operators is a time‑homogeneous linear dynamical law: it does not “know” what absolute indices were seen in training, only how gates vary with local inputs. If the network learns forget/input gates that produce decays with long tails (small per‑step decay) or input‑dependent retention, a contribution can survive far beyond the 2048 training window. The normalizer divides out the total gate mass on keys, so retrieval is robust to the absolute accumulation and depends on relative alignment between query and (normalized) memory.

Role of exponential gating. Using exponentials for gates (i.e. $i_t=\exp(\tilde{i}_t)$ and optionally $f_t=\exp(\tilde{f}_t)$) expands the dynamic range of multiplicative factors and makes learned effective time constants continuous over many orders of magnitude. Logarithms of exponentiated gates add over time, so the network can implement approximate linear functions in log‑time and thereby create effective decays spanning short to very long timescales. Because gates are input‑dependent, the model can choose to retain some items almost indefinitely (small decay) while forgetting others quickly — this is more flexible than a fixed attention window. Exponential gating plus the stabilizer state $m_t$ in the paper maintains numerical stability while keeping that large dynamic range.

Why attention/Transformer variants can fail at extrapolation. Standard self‑attention computes weighted sums using learned interactions plus positional encodings / biases that are only trained up to the context length used during training. Even “linear” or kernelized attention variants often learn positional-dependent mixing (or rely on learned query/key projections whose scale interacts with position), so the learned pattern of attention weights can implicitly encode a horizon. Positional bias parameters or learned softmax temperature can therefore produce attention that degrades outside the training window. In contrast, xLSTM’s recurrence is stationary in time: the same gate function is applied every step and retrieval is normalized, so the math doesn’t change when you keep stepping more times — you just multiply more factors.

Evidence in the paper. The paper reports multiple experiments consistent with this mechanism: synthetic extrapolation tasks and the main 300B SlimPajama experiment where 1.3B models are trained at context 2048 and tested to 16384 (Figure spaj300B_seq_extrapolation). xLSTM maintains low perplexity at long contexts while Mamba and transformers degrade, and the synthetic tasks in the appendix show that exponential gating + normalizer helps state‑tracking and associative recall at longer lengths. The ablations also attribute improvement to exponential gating and matrix memory (see the ablation tables). The paper does not, however, include explicit “decay spectrum” plots (e.g. learned distributions of per‑step log $f_t$ versus distance) in the main text; it points to appendix experiments showing extrapolation but does not show gate spectral diagnostics in published figures.

Diagnostics you can run (suggested analyses). To directly test the mechanism and visualize what the model learned, the following diagnostics are informative and aligned with the paper’s equations:

1) Plot the empirical per‑step log‑forget and log‑input gates, i.e. statistics of $\log f_t$ and $\log i_t$, conditioned on the age/distance of the stored item or on token type. If xLSTM uses long tails you should see many $\log f_t$ close to zero (i.e. $f_t\approx 1$) for items intended to persist, or a broad distribution of $\log f_t$ supporting many timescales.

2) Compute the effective retention kernel for a stored event at time $s$ by measuring the factor $r_{s\to t}=i_s\prod_{u=s+1}^{t} f_u$ as a function of $\tau=t-s$ averaged across events. Plotting $r(\tau)$ (in log scale) shows the learned decay spectrum; a slow power‑law or very slow exponential tail supports extrapolation.

3) Examine normalization denominators $\mathbf{n}_t^\top \mathbf{q}_t$ vs distance and compute signal‑to‑noise ratio: the numerator contribution from a particular past value divided by the norm coming from other keys. If SNR stays high for large $\tau$ for xLSTM but drops for other models, that supports the retrieval explanation.

4) Ablate normalization: run the model with the normalizer disabled (or clamped) to see how perplexity at long contexts changes. The paper claims the normalizer is crucial to avoid scale collapse; this test can isolate its role.

5) Visualize singular values / energy of $\mathbf{C}_t$ vs $t$ to see if the matrix memory saturates with longer contexts (the paper notes matrix memory could overload but didn’t see a problem up to 16k). A stable spectrum across lengths supports robustness.

6) Compare to attention: for the Transformer and Mamba models, plot attention weight mass as a function of distance (how much weight goes to tokens at lag $\tau$). If attention mass is concentrated within the training horizon, that explains poorer extrapolation.

Practical note: the model’s stabilizer state $m_t$ (used to avoid overflow) lives in log space and is directly related to accumulated log gate products; plotting $m_t$ vs time and its distribution is an easy proxy for the learned timescales.

Conclusion. Mechanistically, xLSTM’s superior extrapolation follows from (a) time‑homogeneous multiplicative memory dynamics implemented by learned exponential gates (giving flexible per‑item decay/time constants), and (b) normalized retrieval that makes readouts ratio‑based rather than absolute summed magnitudes. Together these make stored representations depend on relative gate products and query alignment rather than absolute positions seen during training, which naturally supports extrapolation beyond the training horizon. The paper provides experimental behavior consistent with this and attributes gains to exponential gating and matrix memory; adding the suggested diagnostics will give direct visual confirmation of the learned decay spectra and gate statistics.

### Are multi-cell and multi-head mLSTM truly equivalent, and how are outputs combined?
Question:
The paper claims that for mLSTM, multiple heads and multiple cells are equivalent because there is no memory mixing. I am unclear on the combination:
- If we have H independent cells each producing \tilde{h}_t^{(h)}, is the final representation concatenation followed by a projection to model dimension, or a sum/average across heads?
- Does the normalizer n_t exist per head or globally, and how does that choice affect equivalence?
- Under what exact wiring are multiple cells equivalent to multiple heads?
Answer:
Short answer: Yes — under the precise wiring used in the paper, “multiple heads” and “multiple cells” for mLSTM are equivalent, but only if each head/cell is fully independent (no cross-head recurrent couplings) and their outputs are combined by a linear layer (which includes the special case of concatenation followed by a projection). The normalizer must be maintained per head/cell; a single global normalizer breaks the one-to-one mapping.

Explanation and intuition (grounded in the paper)

1) Why the paper claims equivalence
mLSTM uses a matrix memory update $C_t$ and a normalizer $n_t$, and crucially the paper removes any hidden→hidden recurrent mixing for mLSTM. That makes each memory slot (cell) operate independently over time: each cell maintains its own matrix state and normalizer and performs its own local update/retrieval. If you have $H$ independent cells, you can view them as $H$ independent mLSTMs (heads). Conversely, a multi-head mLSTM is just partitioning the big memory and the linear projections so that each head updates and reads its own partition. Because there are no cross-head recurrent terms, no information flows between heads via recurrence, so the two descriptions are isomorphic.

2) How outputs are combined
In the paper the hidden output is (vector) $\mathbf{h}_t = \mathbf{o}_t \odot \tilde{\mathbf{h}}_t$ with $\tilde{\mathbf{h}}_t = \mathbf{C}_t \mathbf{q}_t / \max\{|\mathbf{n}_t^\top \mathbf{q}_t|,1\}$. For $H$ independent heads you will obtain $H$ partial outputs $\tilde{\mathbf{h}}_t^{(h)}$ (and output gates $\mathbf{o}_t^{(h)}$), each of dimension $d_h$. The standard and natural way to combine them so that multi-head and multi-cell formulations are equivalent is to stack (concatenate) the $H$ outputs into one vector and then apply an affine (linear) projection back to the model dimension. Concretely, if you let

$\tilde{\mathbf{H}}_t = [\mathbf{o}_t^{(1)}\odot\tilde{\mathbf{h}}_t^{(1)}; \dots; \mathbf{o}_t^{(H)}\odot\tilde{\mathbf{h}}_t^{(H)}] \in \mathbb{R}^{H d_h},$

then the block’s output is

$\mathbf{h}_t^{\text{out}} = \mathbf{W}_{\text{out}} \, \tilde{\mathbf{H}}_t + \mathbf{b}_{\text{out}}.$

This is the standard multi-head pattern (concatenate then project). This combination is exactly what allows a description as “$H$ separate mLSTM cells” (each producing $d_h$ dims) or “one mLSTM with $H$ independent subspaces” (block-diagonal memory/projection matrices). Summing or averaging the heads instead would be a different wiring: a sum can be realized as concatenation+projection only if $\mathbf{W}_{\text{out}}$ has repeated rows that sum components appropriately, but in general summation reduces representational flexibility and does not preserve the isomorphism unless the projection is constrained. So the canonical equivalence uses concatenation followed by (learned) linear projection.

3) Where the normalizer(s) live and why per-head is required
The paper defines the normalizer $\mathbf{n}_t$ as the running gated sum of keys (Equation (mlstm) second line). For independent heads/cells the normalizer must be per head: $\mathbf{n}_t^{(h)} = f_t^{(h)} \mathbf{n}_{t-1}^{(h)} + i_t^{(h)} \mathbf{k}_t^{(h)}$. The normalization in the retrieval is head-local: each head divides its readout by $\max\{|\mathbf{n}_t^{(h)\top}\mathbf{q}_t^{(h)}|,1\}$. If you used a single global normalizer over all heads you would introduce coupling across heads (the normalization of head $h$ would depend on keys from other heads), which destroys the independence required for the head↔cell isomorphism. Thus equivalence requires maintaining separate normalizers for each independent memory.

4) Precise wiring conditions for equivalence (mapping)
Write a single “multi-cell” mLSTM with total dimension $D = H d_h$. If you partition the big memory and projections into $H$ independent blocks (block-diagonal structure), you get exactly $H$ independent mLSTMs (heads). Concretely, let the big memory be block-diagonal

$\mathbf{C}_t = \operatorname{diag}(\mathbf{C}_t^{(1)}, \dots, \mathbf{C}_t^{(H)}),$

and let the query/key/value/output linear maps be partitioned so that $\mathbf{W}_q, \mathbf{W}_k, \mathbf{W}_v$ produce $H$ disjoint subvectors $\mathbf{q}_t^{(h)},\mathbf{k}_t^{(h)},\mathbf{v}_t^{(h)}$. Use per-head scalar gates $i_t^{(h)}, f_t^{(h)}$, and vector output gates $\mathbf{o}_t^{(h)}$ if you want per-dimension gating. Then each block updates:

$\mathbf{C}_t^{(h)} = f_t^{(h)} \mathbf{C}_{t-1}^{(h)} + i_t^{(h)} \mathbf{v}_t^{(h)} \mathbf{k}_t^{(h)\top},$

$\mathbf{n}_t^{(h)} = f_t^{(h)} \mathbf{n}_{t-1}^{(h)} + i_t^{(h)} \mathbf{k}_t^{(h)},$

$\tilde{\mathbf{h}}_t^{(h)} = \mathbf{C}_t^{(h)} \mathbf{q}_t^{(h)} / \max\{|\mathbf{n}_t^{(h)\top}\mathbf{q}_t^{(h)}|,1\},$

$\mathbf{h}_t^{(h)} = \mathbf{o}_t^{(h)} \odot \tilde{\mathbf{h}}_t^{(h)}.$

Stack these $H$ outputs and apply $\mathbf{W}_{\text{out}}$ to get the final output. Conversely, any such $H$-head construction can be seen as a single mLSTM where $\mathbf{C}_t$ is block-diagonal and the linear maps are arranged accordingly. That is the exact wiring the paper refers to.

5) Short summary and practical note
So: (i) combine head outputs by concatenation followed by a (learned) linear projection to the model dimension to preserve full representational equivalence; (ii) keep a separate normalizer per head/cell; (iii) enforce no recurrent (hidden→hidden) cross-head mixing — equivalence holds only with independent recurrent dynamics (which is exactly the mLSTM design in the paper). If you change any of these (use global normalizer, sum heads instead of concat+proj, or introduce recurrent cross-coupling) the equivalence no longer holds.

This is why the paper can state “for mLSTM multiple heads and multiple cells are equivalent”: independence (no memory mixing) + per-head normalizers + concatenation+projection wiring gives a one-to-one mapping between the two descriptions.

### What distinguishes xLSTM mLSTM from RWKV-5/6 "fast weight" style updates in practice?
Question:
RWKV-5/6 and Retention also use outer-product-like state updates. The paper lists these as related.

- What are the key differences in mLSTM: the explicit normalizer n_t, the form of the output gate, the gating parameterization (input-dependent i_t,f_t), or the pre/post up-projection backbone?
- Is there an exact setting where mLSTM reduces to RWKV-5/6, or do architectural choices (e.g., LayerNorm placement, normalization denominator) lead to materially different behavior?
Answer:
Short answer: mLSTM shares the same high‑level idea as RWKV/“fast weight” models (a running outer‑product / covariance memory that accumulates key–value outer products and is read by queries) but differs in several concrete and consequential design choices. Those differences (explicit normalizer state, exponential gating + stabilizer, placement of LayerNorm/projections, the readout denominator, and the gating parameterizations including a vector output gate and $1/\sqrt{d}$ key scaling) are not superficial: they change numerical behavior, training stability, and what the memory actually represents. With many simultaneous simplifications you can recover something very close to a fast‑weight rule, but there is no single exact setting in the paper where mLSTM algebraically reduces to the RWKV‑5/6 recipe.

Why they look related
Both mLSTM and RWKV/Retention/Fast‑Weight programmers implement a running matrix that is updated by outer products
$$C_t = \text{decay} \cdot C_{t-1} + \text{learning\_rate} \cdot v_t k_t^\top,$$
and later read by multiplying $C_t$ by a query $q_t$. So at a conceptual level mLSTM is a covariance/fast‑weight memory integrated into an LSTM‑style gated framework.

Concretely where mLSTM differs (and why it matters)
1) Explicit normalizer state $n_t$ and normalized readout. mLSTM keeps a normalizer
$$n_t = f_t n_{t-1} + i_t k_t$$
and divides the readout by $\max\big(|n_t^\top q_t|, 1\big)$:
$$\tilde h_t = \frac{C_t q_t}{\max\{\,|n_t^\top q_t|, 1\,\}}.$$
This is a running, gate‑weighted measure of the expected key mass aligned with the query and acts like an adaptive denominator that stabilizes signal/noise ratio. RWKV/Retention variants either use different normalization heuristics or design attention/readout differently; having an explicit $n_t$ that accumulates keys weighted by the same gates makes mLSTM’s readout interpretable and numerically robust—especially when exponential gates can produce large magnitudes.

2) Exponential gating with stabilizer $m_t$. mLSTM uses exponential activations for input gates $i_t$ (and optionally forget gates $f_t$) and a log‑space stabilizer so that the effective learning/decay rates are multiplicative and can sharply revise stored mass. The paper argues exponential gating enables efficient “revision” (e.g., replace earlier memory strongly) and requires the stabilizer (the $m_t$ trick) to avoid overflow while preserving exact gradients. RWKV variants typically use other gating/decay parameterizations (for example explicit time decay factors, or sigmoid/gating variants tuned for RWKV’s RNN formulation). The exponential vs sigmoid choice changes dynamics: multiplicative (exp) gates can implement much larger dynamic ranges and more abrupt replacements than sigmoids.

3) Output gating as a vector $o_t$ and its placement. mLSTM defines
$$h_t = o_t \odot \tilde h_t$$
with $o_t$ a vector computed from the input (no hidden–hidden recurrence in mLSTM). That means the final readout is elementwise scaled by an input‑dependent vector. RWKV-style models may scale the readout differently (scalar gating, or incorporate the read into the RNN recurrence). This vector gate allows mLSTM to modulate retrieved information per component and improves expressive power vs scalar scaling.

4) LayerNorm before projections and zero‑mean keys. The paper assumes a LayerNorm before the projections to keys/values, so keys have zero mean and the covariance update is meaningful for a Hebbian/covariance interpretation. RWKV families may place normalization differently (or rely on other standardizations). LayerNorm placement affects what the keys capture and the statistics of outer products — not a trivial change.

5) Key scaling and denominators: mLSTM sets $k_t = (1/\sqrt{d}) W_k x_t + b_k$ and lower bounds denominator by $1$. These numeric scalings/thresholds are chosen to control the scale of dot products and stabilize training. RWKV/Retention use different scalings/thresholds or continuous decays (and in some RWKV versions, time/position dependent exponentials are used). Those choices change how much interference/noise accumulates and how queries extract signal.

6) Parallelizable vs recurrent structure. mLSTM intentionally removes hidden–hidden recurrence (no memory mixing) so the recurrence can be reformulated as parallel scan operations. RWKV is a recurrent formulation with a specific recurrence that also can be made efficient; implementation and computational tradeoffs differ. The presence/absence of hidden–hidden mixing changes expressivity (mLSTM sacrifices mixing to remain parallelizable; sLSTM retains mixing).

Is there an exact reduction to RWKV‑5/6?
Not in the way the paper presents both models. The covariance update itself is the common mathematical kernel (fast weights), and the paper explicitly cites Fast Weight Programmers and notes equivalence of the covariance rule at that abstract level. But to make mLSTM algebraically identical to RWKV‑5/6 you would need to simultaneously:

- Remove or change the normalizer $n_t$ (i.e., not divide by the gate‑weighted key sum or use a different denominator),
- Replace exponential input/forget gates and the log stabilizer by RWKV’s gate/decay parameterization,
- Change the output gate form (e.g., to a scalar or fold it into different recurrence),
- Reposition LayerNorm and remove the $1/\sqrt{d}$ key scaling / thresholding,
- Match any time‑decay parameterization and readout specifics in RWKV implementations.

If you set those elements to match (use the same decay and learning rates, the same readout normalization, the same lack of vector output gating, etc.), the memory update $C_t$ term can become very similar to RWKV’s fast‑weight update. But because mLSTM couples the fast‑weight memory with the explicit normalizer and exponential/stabilized gates and applies a per‑component output gate and pre‑projection LayerNorm, the dynamics, numerical conditioning, and practical behavior differ materially. In short: the covariance/outer‑product core is shared, but mLSTM’s extra machinery is intentionally chosen and not a cosmetic reparameterization.

Intuition on why these differences matter
The normalizer $n_t$ makes the readout adaptive to the total “mass” of keys that the model has stored for future queries; without it, retrieval amplitude and SNR drift as more outer products accumulate. Exponential gating (with stabilizer) lets the model sharply increase/decrease stored mass in a multiplicative way (easy “revision”), while sigmoids / small additive decays produce slower, more gradual forgetting. Output gating and per‑component scaling let the model gate information selectively after retrieval, improving expressivity. LayerNorm and $1/\sqrt{d}$ scaling control dot‑product statistics so the denominator clipping works in practice; changing them leads to different interference and stability properties.

Bottom line
mLSTM is a fast‑weight / covariance memory in the same family as RWKV/Retention, but the paper intentionally augments that kernel with: (i) an explicit gate‑weighted normalizer and a clipped denominator, (ii) exponential gates with a log‑stabilizer, (iii) per‑component output gating, and (iv) LayerNorm/pre‑projection choices and key scalings. Those architectural choices produce materially different training dynamics and capabilities (stronger revision, different memory SNR, different expressivity). You can make the algebraic update term look like RWKV by removing/altering these extras, but doing so also removes the properties the authors use to claim better revision, stability, and performance.

### How robust is the choice of the normalization clamp (1.0) in mLSTM, and could a smooth alternative work better?
Question:
mLSTM uses \max\{|n_t^\top q_t|, 1\} in the denominator. I am concerned about nondifferentiability at 1 and sensitivity to scale.

- Did the authors try a smooth lower bound like \sqrt{(n_t^\top q_t)^2 + \epsilon} with \epsilon tuned, or a softplus? 
- How does changing the clamp affect training stability and final perplexity? Any guidance for practitioners?
Answer:
Short answer: The paper does not report trying a smooth lower bound — they explicitly use the hard clamp $\max(|n_t^\top q_t|, 1)$ (they say “lower bound it by a threshold (typically 1.0)”). The clamp is a pragmatic stabilizer: it prevents division by near-zero dot products and keeps the retrieved magnitude scale-controlled. Because the model already uses layer-norm on inputs and scales keys by $\frac{1}{\sqrt{d}}$, choosing $1.0$ is a simple, robust default in their setup. Nondifferentiability at the kink ($|\cdot| = 1$) is not discussed in the paper and, in practice, such kinks rarely harm optimization (subgradients exist), but smooth alternatives can be reasonable to try and may slightly change gradient flow.

Why the clamp exists (intuitive + technical): mLSTM’s hidden output is $\tilde{h}_t = C_t q_t / D_t$ where $D_t = \max(|n_t^\top q_t|, 1)$. The normalizer $n_t$ records cumulative gate strength; when $n_t^\top q_t$ is near zero dividing by it would amplify noise and cause unstable outputs/gradients. The clamp enforces a minimum denominator so retrieval has bounded scale and a predictable signal-to-noise normalization (the paper also links this to prior work \citep{Sun:23arxiv}). The authors set keys with a $\frac{1}{\sqrt{d}}$ factor and apply layer-norm, so $|n_t^\top q_t|$ typically sits in a controlled range — that makes $1.0$ a natural, simple threshold.

On nondifferentiability: $\max$ and absolute introduce nondifferentiable points, but they are measure-zero events and automatic differentiation frameworks give subgradients there. Because the model uses other stabilizations (layer-norm, key scaling, gate stabilizer $m_t$ for exponentials), optimization was stable enough in their experiments. The paper’s ablations attribute substantial gains to the matrix memory and exponential gating, not to fiddling with the denominator form, so the authors found the hard threshold adequate for their large-scale runs.

Would a smooth alternative help? Likely only modestly, but it’s worth trying if you see peculiar gradient noise or sensitivity in your setting. Two smooth replacements that preserve the intended behavior:

1) Root-sum-square lower bound: use $D_t = \sqrt{(n_t^\top q_t)^2 + \epsilon}$. This never hits zero and smoothly approaches $|n_t^\top q_t|$ when it is large. Choose $\epsilon$ relative to the typical scale of $n_t^\top q_t$; because keys are scaled by $\frac{1}{\sqrt{d}}$ and inputs are layer-normed, start with $\epsilon \in [10^{-3}, 10^{-1}]$ and sweep. This preserves scale when $|n^\top q| \gg \sqrt{\epsilon}$ and prevents blowups when it is small.

2) Softplus-style floor: $D_t = \mathrm{softplus}(\alpha |n_t^\top q_t|) / \beta$, or simpler $D_t = \mathrm{softplus}(|n_t^\top q_t| - \tau) + \tau'$, tuned so the transition is smooth around the floor. A temperature $\alpha$ controls how sharp the transition is; large $\alpha$ approximates the hard clamp. This gives smoother gradients around the floor.

Practical guidance (what to try and monitor): because the authors used threshold $1.0$ successfully, treat that as the baseline. If you encounter instability or worse perplexity with your data/hyperparameters, try the root-sum-square form with $\epsilon$ swept logarithmically (e.g., $10^{-4}, 10^{-3}, 10^{-2}, 10^{-1}$). Monitor training loss, gradient norms, and validation perplexity. If replacing the clamp improves gradient noise or slightly lowers perplexity, keep it; if not, the simpler clamp is fine and faster.

Other practical tips tied to the paper’s setup: keep layer-norm before key/value/query projections and the $\frac{1}{\sqrt{d}}$ key scaling (these make the denominator scale predictable). Also retain the gate stabilization $m_t$ for exponential gates — the authors show this is important for avoiding overflow and for preserving correctness of gradients. Finally, if you change the denominator, check the ablations/initialization sensitivity (the paper flags forget-gate initialization as important).

Conclusion: the clamp at $1.0$ is a pragmatic, robust choice in the authors’ xLSTM setup (layer-norm + $\frac{1}{\sqrt{d}}$ key scaling + gate stabilizers). Smooth alternatives ($\sqrt{(\cdot)^2 + \epsilon}$ or softplus variants) are sensible and may slightly help gradient continuity; if you try them, tune $\epsilon$ or the softplus temperature relative to the typical $|n^\top q|$ scale and compare training stability and validation perplexity. The paper does not report such experiments, so an empirical ablation on your task is the right next step.

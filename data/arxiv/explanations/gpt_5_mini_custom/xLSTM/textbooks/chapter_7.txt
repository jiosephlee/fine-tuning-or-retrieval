\title{A Textbook about the Paper: "xLSTM: Extended Long Short-Term Memory"}

Chapter 7: xLSTM Blocks and Full Architectures

# Pre-LayerNorm residual backbone (pre-LN) and why it’s used
xLSTM architectures are built from residual blocks arranged in deep stacks. The backbone chosen for these stacks is the pre-LayerNorm (pre-LN) residual backbone: every residual block receives its input after a LayerNorm operation and then adds its (possibly projected) block output back to the input via a residual connection. The paper states that this is the most commonly used residual backbone in contemporary large language model practice and therefore adopts it for xLSTM. In the simplest schematic form, if $\mathbf{x}$ denotes the input to a block, a pre-LN block computes
\[
\mathbf{\hat x} \;=\; \mathrm{LayerNorm}(\mathbf{x}), \qquad
\mathbf{y} \;=\; \mathbf{x} + \mathrm{BlockFn}(\mathbf{\hat x}),
\]
and forwards $\mathbf{y}$ to the next block. This structure makes the non-linear transform act on a normalized point and returns a residual correction to the original input.

Two statements from the paper motivate this choice. First, residually stacking blocks is the standard contemporary practice to build very deep models; second, pre-LayerNorm variants are the backbone used in many existing large models, making them a natural, well-understood choice for fair architectural comparison. Pre-LN also places normalization before the block’s non-linear summarization of history, ensuring that each block sees inputs of controlled scale and statistics, which is important for stable training of deep stacks that contain complex recurrent memory components such as sLSTM and mLSTM.

# Post up-projection blocks for sLSTM (Transformer-like MLP positioning)
sLSTM blocks are embedded into a residual block variant called the post up-projection block. The central idea is that the block first non-linearly summarizes the past in the original (model) space and only thereafter expands into a higher dimensional intermediate space for additional linear operations and pointwise non-linearities. Concretely, a post up-projection block follows the ordering: (1) non-linear summarization in the input dimension, (2) linear up-projection to a larger dimensionality, (3) an activation in that larger space, and (4) linear down-projection back to the input dimensionality before the residual add. This ordering is said to be “like Transformers” in the paper because standard Transformer MLPs similarly perform a non-linearity after an up-projection from model dimension to MLP dimension (and then project back).

This block ordering is the recommended choice when the block contains sLSTM. The reason given in the paper is empirical and architectural: sLSTM’s scalar memory cells and its particular form of memory mixing (recurrent hidden–hidden connections across its scalar cells) are used most effectively when the block first forms a compact, non-linear summary in the model space and then uses a high-dimensional expansion to refine and re-scale that summary. In practice this means that the sLSTM cell (and its gates and stabilizers) operate within or directly adjacent to the portion of the block that works in the model dimensionality, while the up-projection serves as an amplifying transform for the block’s internal computations.

# Pre up-projection blocks for mLSTM (SSM-like high-dimensional summarization)
For mLSTM blocks the paper prescribes the opposite ordering: a pre up-projection architecture. Here, input vectors are first linearly projected up into a higher-dimensional space, then the non-linear summarization (which includes the matrix memory operations of the mLSTM cell) is carried out in that expanded space, and finally the representation is linearly projected back down to the model dimension. The paper motivates this choice by pointing out that the mLSTM’s matrix memory $\mathbf{C}\in\mathbb{R}^{d\times d}$ attains its largest storage capacity when the internal (key, value, query) vectors live in a higher-dimensional coding space. By performing the up-projection before the memory operation, the model leverages a larger internal coding dimension for keys, values, and queries, thereby increasing the effective memory capacity realized by the covariance-style update and retrieval rules.

Symbolically, for input $\mathbf{x}$ a pre up-projection block performs
\[
\mathbf{u} \;=\; \mathbf{W}_{\mathrm{up}} \mathbf{x} + \mathbf{b}_{\mathrm{up}}, \qquad
\mathbf{v} \;=\; \mathrm{mLSTM\text{-}summary}(\mathbf{u}), \qquad
\mathbf{y} \;=\; \mathbf{x} + \mathbf{W}_{\mathrm{down}} \mathbf{v} + \mathbf{b}_{\mathrm{down}},
\]
where the core summarization step uses the matrix-memory and normalization mechanisms of mLSTM. The paper explicitly notes that this construction is “like State Space Models (SSMs)” in the sense that SSMs commonly perform their linear projection to a larger internal state before applying their sequence dynamics; mLSTM follows the same pattern because its matrix memory benefits from working in a larger coding dimension.

# Cover’s Theorem motivation for up-projection
Cover’s Theorem is invoked in the paper as the conceptual justification for the up-projection idea used in both kinds of block designs. The theorem, in the form referenced, states that a non-linear mapping into a higher-dimensional space increases the likelihood that different histories (different pasts) become linearly separable. For sequential modeling, better separability of distinct histories is directly linked to the model’s ability to predict the next token: if different pasts map to linearly separable regions, a simple output layer can discriminate them and produce accurate next-token predictions.

Up-projection implements this principle by temporarily increasing the dimensionality in which a block summarizes the past. Whether the up-projection is placed before the non-linear summarization (pre up-projection) or after it (post up-projection), the intent is to carry out the block’s most expressive non-linear computations in or adjacent to an expanded space that is more likely to separate distinct contexts. For mLSTM the pre up-projection is preferred because the matrix memory benefits directly from larger key and value dimensions; for sLSTM the post up-projection places the block’s non-linear summary in model space and uses the up-projection as a later, higher-dimensional refinement. In both cases, Cover’s Theorem provides the underlying intuition: a higher-dimensional non-linear embedding facilitates separability of contexts and therefore improves next-token discrimination.

# Stacking strategy and block ratio selection (xLSTM[a:b])
xLSTM architectures are built by residually stacking many xLSTM blocks. Each block is either an mLSTM-based block (pre up-projection) or an sLSTM-based block (post up-projection). The paper introduces a compact notation xLSTM[a:b] to indicate the ratio of mLSTM-based to sLSTM-based blocks in the stack. More precisely, xLSTM[$a$:$b$] denotes that of each group of $(a+b)$ blocks, $a$ are mLSTM blocks and $b$ are sLSTM blocks; when the total number of blocks is $N$, this ratio determines how many blocks of each type are included. For example, xLSTM[7:1] means that in each run of eight blocks, seven are mLSTM blocks and one is an sLSTM block; with $N=48$ total blocks this corresponds to 42 mLSTM blocks and 6 sLSTM blocks.

The paper reports experiments with different ratios and finds that mixed stacks (both types present) can leverage complementary strengths: mLSTM contributes high-capacity, parallelizable matrix memories that improve rare-token prediction and long-range retrieval, while sLSTM contributes scalar-memory cells with memory mixing (hidden–hidden recurrent connections) that support state tracking and tasks that require revision of stored information. The stacking strategy is therefore a design knob: increasing $a$ (more mLSTM blocks) emphasizes high-capacity parallel memories; increasing $b$ (more sLSTM blocks) preserves more memory-mixing capacity. The recommended practice in the paper’s experiments is to choose ratios based on task needs and resource constraints; xLSTM[1:0] and xLSTM[7:1] are two of the configurations evaluated in the large-scale experiments.

# Embedding layers, normalization, and output heads
An xLSTM model begins with token embedding layers that map discrete tokens to continuous model vectors. These embeddings provide the initial inputs $\mathbf{x}_t$ to the stacked pre-LN residual blocks. Within the mLSTM blocks, the paper explicitly assumes a LayerNorm before projecting inputs to keys and values: this pre-projection normalization centers and rescales the inputs so that the key and value projections produce zero-mean vectors, which is important for the covariance-style update used in the matrix memory. Thus, two places where normalization is highlighted are the global pre-LayerNorm applied at each residual block input and the layer normalization before key/value projection in mLSTM internals.

On the output side, the stacked blocks ultimately feed into an output head that maps the model vector to token logits for next-token prediction. In large language model practice these logits are converted into next-token probabilities via a softmax and evaluated by perplexity; the paper notes that in its comparisons most models use conventional untied token embeddings and output heads, while GPT-3 (as a reference) used tied token and output embeddings and therefore had slightly fewer parameters. In short, xLSTM follows the standard encoder-to-logits pipeline: token embeddings → pre-LN residual stack of xLSTM blocks → output linear mapping to vocabulary logits (with softmax during evaluation).

Internally, the sLSTM and mLSTM cells also maintain auxiliary internal states that are normalized or stabilized. sLSTM uses a normalizer state $n_t$ and a stabilizer $m_t$ to avoid numerical overflows when exponential gates are used; mLSTM has a normalizer vector $\mathbf{n}_t$ that accumulates weighted sums of keys and is used to normalize retrieved vectors by their projected magnitude. These internal normalizers are essential to maintain numerical stability and to make the exponential input gates usable in practice.

# Auto-regressive training objective and teacher forcing
The xLSTM architectures are trained in an auto-regressive next-token prediction setting: the model learns to predict the next token given the past tokens. Concretely, given a sequence of tokens $(w_1, w_2, \dots, w_T)$ and their embeddings $(\mathbf{x}_1, \mathbf{x}_2, \dots, \mathbf{x}_T)$, the stacked xLSTM produces a sequence of hidden outputs $(\mathbf{h}_1, \mathbf{h}_2, \dots, \mathbf{h}_T)$ which are mapped to vocabulary logits and probabilities. Training minimizes the negative log-likelihood (next-token loss) summed over positions:
\[
\mathcal{L} \;=\; -\sum_{t=1}^{T} \log p(w_{t} \mid w_{<t}; \theta),
\]
where the conditional probability $p(w_t\mid w_{<t};\theta)$ is produced by the softmax over output logits computed from the model-hidden vector at time $t$. The paper describes training all compared models "in the same auto-regressive setting" for fairness; evaluation is performed by computing validation perplexity and downstream metrics derived from the trained conditional probability model.

The architecture and objective together imply the usual auto-regressive operational mode during inference: at generation time the model conditions on prior generated tokens to produce the next-token distribution; during training the model is supplied with the true past tokens (the ground-truth prefix) so that the parameters are learned to maximize next-token likelihood under the observed data distribution. (This training paradigm—feeding the past context from data during parameter updates—is the standard auto-regressive next-token framework used in the experiments.)

# Closing remarks on block composition and architecture design
Putting the pieces together, a full xLSTM model is instantiated by choosing a model dimension, a block structure (pre-LN residual backbone), a total number of blocks $N$, and a ratio xLSTM[$a$:$b$] that determines how many blocks are mLSTM vs. sLSTM. Within each block the appropriate up-projection ordering (pre for mLSTM, post for sLSTM) is employed so that the block’s non-linear summarization and memory primitives operate in the dimensionality that best suits them. Token embeddings feed into the stacked blocks; LayerNorms and internal normalizers stabilize both block inputs and memory internals; an output head converts the final representations to logits for the auto-regressive next-token objective. This modular construction permits trading off parallelizability and raw memory capacity (favoring mLSTM) against recurrent memory mixing and state-tracking expressivity (favoring sLSTM), and the xLSTM[$a$:$b$] notation provides a compact way to express different design points evaluated in the paper.

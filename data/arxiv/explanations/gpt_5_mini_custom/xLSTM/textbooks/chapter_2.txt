\title{A Textbook about the Paper: "xLSTM: Extended Long Short-Term Memory"}

Chapter 2: Limitations of Classic LSTMs

# Inability to revise storage decisions (Nearest Neighbor Search example)

One of the central design ideas of the original Long Short-Term Memory (LSTM) is the constant error carousel: memory is accumulated additively over time and gated to control what is written and what is retained. The canonical LSTM update is often summarized as
$c_t = f_t \, c_{t-1} + i_t \, z_t,$
with the hidden state produced by $h_t = o_t \, \psi(c_t)$. Here $i_t$ (input gate) and $f_t$ (forget gate) are typically sigmoids in $(0,1)$ and $z_t$ is the new candidate content. This structure makes LSTMs excellent at preserving signals over long time spans (the “constant error carousel”) and at controlled, gradual updates.

However, the same mechanism that gives stability—gating values constrained to the unit interval and additive accumulation—also impedes a different kind of operation: revising earlier storage decisions after the original storage has already contributed to the cell state. The paper illustrates this with the Nearest Neighbor Search task. In that task a reference vector is given first, then a long sequence of vectors is scanned and at the end the model must output the value attached to the vector in the sequence most similar to the reference. To succeed, the memory must be able to overwrite or substantially revise a previously stored candidate whenever a later vector is found to be closer to the reference.

Because the LSTM update mixes past content and new content via $f_t$ and $i_t$ that lie in $(0,1)$, and because $c_t$ is typically squashed by $\psi(\cdot)$ when output, it becomes hard to make a later input fully replace an earlier one without erasing a lot of other useful information. The gates can “attenuate” or “forget” past content, but they do so multiplicatively and within a bounded range; they do not provide a natural mechanism for aggressively amplifying or reversing earlier stored contributions when the decision to replace must be sudden and decisive. Empirically (as reported in the paper), standard LSTMs struggle on this Nearest Neighbor Search example: once a value has been stored, LSTMs have difficulty revising it in favor of a subsequently better candidate.

The xLSTM paper addresses this limitation by introducing exponential gating: gates with exponential activation allow multiplicative factors that are not constrained to $(0,1)$ and thus permit stronger relative amplification or attenuation of contributions across time. Concretely, sLSTM and mLSTM variants replace (some) sigmoid gates by $\exp(\tilde{i}_t)$ or $\exp(\tilde{f}_t)$ and complement them with normalization and stabilization states so that revising stored content becomes numerically stable. This change enables the model to increase or decrease the effective contribution of past versus new information in a more flexible, unbounded multiplicative way, which in turn allows later items in a sequence to more readily supersede earlier stored items when appropriate.

# Limited storage capacity and rare token prediction

A second fundamental limitation of classical LSTMs stems from the fact that their core memory element is scalar (or a modest-dimensional vector of scalars). Each scalar memory cell stores a compressed, often highly entangled summary of multiple aspects of past inputs. While this is sufficient for many sequence-processing tasks, it becomes a bottleneck when the model must store and later retrieve many distinct pieces of information with high fidelity.

The paper demonstrates this limitation empirically in a “Rare Token Prediction” experiment on Wikitext-103. When tokens are partitioned by frequency, standard LSTMs attain higher perplexity (worse prediction) on rare tokens than on common ones. This degradation is consistent with the intuition that rare tokens require the model to retain relatively unique, low-probability features from past context. A scalar cell must compress these distinct facts into limited dimensions and will tend to conflate or overwrite them, so rare items suffer.

To address storage capacity, xLSTM introduces a matrix-valued memory in the mLSTM variant. Instead of a scalar $c_t$, mLSTM maintains a matrix $\mathbf{C}_t \in \mathbb{R}^{d\times d}$ that is updated by outer products (covariance-style updates)
$\mathbf{C}_t = f_t \, \mathbf{C}_{t-1} + i_t \, \mathbf{v}_t \, \mathbf{k}_t^\top,$
where $\mathbf{k}_t$ is a key vector and $\mathbf{v}_t$ is the corresponding value vector. Retrieval is then a matrix–vector product: $\tilde{\mathbf{h}}_t = \mathbf{C}_t \mathbf{q}_t / \text{(normalizer)}$, where $\mathbf{q}_t$ is a query. This outer-product memory stores many key–value associations in a distributed, higher-capacity fashion: each key–value pair contributes a rank-1 matrix, and a superposition of such matrices supports retrieval with higher separability than scalar cells.

This setup is equivalent to classical covariance storage / fast-weight programmers and is optimal (in the sense discussed in the paper) for maximizing separability under the pairwise retrieval assumption. Practically, the matrix memory gives mLSTM more fine-grained capacity to remember and later reconstruct information about rare events or many simultaneous associations, which explains improved performance on rare-token prediction and associative-recall tasks relative to scalar-cell LSTMs.

# Sequential dependency from memory mixing (hidden-to-hidden connections)

A third major limitation of standard LSTM formulations is architectural: memory mixing via hidden-to-hidden recurrent connections enforces inherently sequential processing and blocks straightforward parallelization across timesteps. In the usual vectorized LSTM, the inputs to gates and candidate updates include terms like $r_i \, h_{t-1}$, $r_f \, h_{t-1}$ and so on. These “hidden-hidden” terms mix the previous hidden state into the current gating and input computations, and they create a true recurrence that must be processed sequentially: computing the state at time $t$ requires having computed $h_{t-1}$.

This sequential dependency increases latency for long sequences and prevents the kind of efficient parallel training and inference that self-attention (in Transformers) or certain linearized architectures enjoy. In practice, it makes scaling to very long contexts and very large models more costly in wall-clock time and complicates GPU parallelization strategies. The paper notes that this lack of parallelizability was one of the reasons Transformers displaced LSTMs in many large-scale language-modeling settings: Transformers replace hidden-to-hidden recurrence with self-attention, enabling parallel computation across sequence positions and quadratic or, with approximations, linear-time attention implementations.

xLSTM approaches this limitation with two complementary design choices. First, the mLSTM abandons memory mixing: the matrix memory update in mLSTM depends only on the current input projections (keys, values, queries) and scalar gates derived from input, not on $h_{t-1}$. Because of that, the recurrence can be reformulated into a parallel scan (and in practice implemented in a fully parallel manner across timesteps analogous to linearized attention or certain fast-weight formulations). In contrast, sLSTM retains memory mixing (it has recurrent connections) but gains other advantages (state-tracking expressivity); to mitigate runtime costs the authors implemented optimized CUDA kernels for sLSTM. The design tradeoff is explicit: memory mixing provides expressivity for state-tracking problems but conflicts with parallelizable implementations, whereas removing mixing makes for more parallel-friendly and scalable architectures at the potential cost of some expressiveness—hence the hybrid xLSTM architectures that combine both block types.

# How these limits favored attention-based Transformers

The three limitations above—difficulty revising stored content, limited scalar storage, and sequential recurrence—help explain why attention-based Transformers became dominant in large-scale language modeling. Self-attention provides two practical and functional advantages relative to classical LSTMs that directly address these weaknesses.

First, attention performs retrieval from context via dot products and weighted sums between keys, queries, and values. This mechanism is naturally able to locate and amplify a particular past token’s contribution at prediction time without needing to have preserved a single scalar summarizing that token. It thereby mitigates the need to compress many distinct pieces of information into scalar cells; attention’s effective memory capacity grows combinatorially with its embedding dimension and can represent many distinct associations explicitly.

Second, Transformer attention is parallelizable across positions: the self-attention computation does not require computing previous hidden states sequentially. This allows large-scale parallel training on long contexts, and makes it practical to build very deep and wide models that process many tokens simultaneously. That hardware efficiency and the associated scaling behavior are repeatedly cited in the paper as major reasons Transformers outpaced LSTMs at scale.

Third, attention enables direct revisitation of past tokens at arbitrary strengths at prediction time. Where an LSTM might have to rely on whatever was retained in its cell states, attention can directly reweight specific prior elements depending on the current query. This flexibility resembles the “revise storage decisions” goal: rather than having to overwrite a memory progressively, a model can choose at read time which past element to emphasize. As the paper notes, these operational characteristics allowed Transformers to excel in large language models and were instrumental in the historical shift away from classic LSTMs in many language tasks.

# Design desiderata for a next-generation LSTM

Given the three limitations above, the xLSTM paper motivates a concise set of desiderata for a modernized LSTM-style architecture that aspires to compete with attention-based models at scale. These desiderata guided the design of the sLSTM and mLSTM variants:

1. Enable robust revision of past stored content. The architecture should allow later inputs to significantly revise or replace earlier stored items when required by the task. In xLSTM this is achieved by exponential gating (gates computed as exponentials rather than restricted sigmoids) combined with a normalization mechanism (a normalizer state that accumulates the effective gate strengths) and a numerical stabilizer state to avoid overflow. These changes let the effective multiplicative factors on memory contributions be unbounded and thus permit decisive revisions.

2. Increase memory capacity beyond scalar compression. The model should be able to store many distinct key–value associations with higher fidelity to support rare events and associative recall. The mLSTM meets this by replacing scalar cells with a matrix memory $\mathbf{C}_t$ and using a covariance (outer-product) update rule $ \mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top$, and retrieval via $\mathbf{C}_t \mathbf{q}_t$ normalized by a corresponding normalizer state. This gives much richer representational capacity akin to fast-weight memory.

3. Support parallelizability where possible. To scale to large models and long contexts, the architecture should be amenable to parallel computation over timesteps. The mLSTM achieves this by designing the memory update and retrieval so they can be reformulated in a parallel manner (no hidden–hidden mixing). At the same time, the design accepts that certain forms of memory mixing are valuable; thus, xLSTM offers hybrid architectures where some blocks (sLSTM) keep recurrent mixing for expressive state tracking, while others (mLSTM) provide parallel, high-capacity memory.

4. Provide numerical stability and normalization. The novel exponential gates and matrix-valued memories introduce risks of numerical overflow or vanishing signal-to-noise. The paper therefore includes normalization (a normalizer state that accumulates effective gate-weighted contributions) and stabilization (a stabilizer state $m_t$ that rescales exponentials) so that the operations are numerically well behaved and gradients remain meaningful.

5. Integrate smoothly into modern residual architectures. Contemporary large models are built by residually stacking blocks with pre-LayerNorm and projection patterns. The xLSTM variants were designed to be used inside residual blocks (with choices like pre- or post-up-projection depending on whether an mLSTM or sLSTM is used) so that they can be scaled, tuned, and trained using the same stacking paradigms that enabled Transformers and SSMs to scale.

6. Preserve LSTM strengths such as state-tracking. Importantly, while adding capacity and parallelism, the design retains the gating and memory mechanisms that make LSTMs effective at extracting and maintaining high-level abstractions across long sequences (e.g., state tracking needed for tasks like program evaluation or entity tracking). sLSTM preserves memory mixing and recurrent paths for these cases; mLSTM provides alternative mechanisms when parallelism is the priority.

These desiderata inevitably imply trade-offs. The matrix memory increases computational cost due to $d\times d$ updates, and keeping memory mixing (sLSTM) limits parallelizability. The paper explicitly acknowledges these trade-offs and presents hybrid xLSTM architectures (mixtures of mLSTM and sLSTM blocks) and engineering mitigations (stabilization techniques, CUDA kernels, and residual block placements) to balance expressivity, capacity, and throughput.

In sum, examining the limitations of classic LSTMs clarifies why attention-based models became dominant and points to concrete architectural changes—exponential gating, matrix memories, normalization/stabilization, and selective abandonment of hidden-to-hidden recurrence—that can revive LSTM-style models for modern large-scale sequence modeling. The xLSTM family implements these desiderata and, as reported in the paper, demonstrates that with those modifications a next-generation LSTM can close the gap with contemporary Transformers and State Space Models while offering favorable scaling and memory properties.

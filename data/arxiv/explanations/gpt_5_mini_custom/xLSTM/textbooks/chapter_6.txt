\title{A Textbook about the Paper: "xLSTM: Extended Long Short-Term Memory"}

Chapter 6: mLSTM: Matrix Memory with Covariance Updates

# Matrix memory C_t and covariance update rule

The central idea of the mLSTM is to replace the scalar LSTM cell with a matrix memory that can store many more degrees of freedom per time step. Instead of a scalar cell state $c_t \in \mathbb{R}$, mLSTM maintains a matrix memory
$\mathbf{C}_t \in \mathbb{R}^{d\times d}$. Information is written into this memory by outer-product (covariance) updates and is retrieved by multiplying the memory with a query vector. The forward update for the matrix memory is written in compact form as

\[
\mathbf{C}_t \;=\; f_t \,\mathbf{C}_{t-1} \;+\; i_t \,\mathbf{v}_t \mathbf{k}_t^\top,
\]

where $i_t$ and $f_t$ are scalar input and forget gates (discussed below), $\mathbf{k}_t$ is the key vector and $\mathbf{v}_t$ the value vector for the current input. The new term $\mathbf{v}_t \mathbf{k}_t^\top$ is an outer product: it inserts into the matrix memory an association between $\mathbf{k}_t$ (the addressing key) and $\mathbf{v}_t$ (the stored content). The forget gate $f_t$ multiplies the previous memory, acting as a multiplicative decay.

Intuitively, each outer product adds a rank-one contribution to the memory that encodes the covariance between elements of the stored key and value. Over time, the memory accumulates many such outer products, so that when a query $\mathbf{q}$ later appears, the matrix-vector product $\mathbf{C}\mathbf{q}$ sums the contributions of past values, each weighted by the similarity between the corresponding key and the query. Because the memory is matrix-valued, retrieval is not limited to a single scalar per cell; instead the matrix can encode complex relationships across $d$ dimensions, enabling much higher effective storage capacity than scalar cells.

# Key, value, and query projections (with scaling for keys)

To interface input vectors $\mathbf{x}_t$ with the matrix memory, mLSTM computes three linear projections: a query $\mathbf{q}_t$, a key $\mathbf{k}_t$, and a value $\mathbf{v}_t$. In the formulation used in the paper these are

\[
\mathbf{q}_t \;=\; \mathbf{W}_q \mathbf{x}_t + \mathbf{b}_q,
\qquad
\mathbf{k}_t \;=\; \frac{1}{\sqrt{d}}\,\mathbf{W}_k \mathbf{x}_t + \mathbf{b}_k,
\qquad
\mathbf{v}_t \;=\; \mathbf{W}_v \mathbf{x}_t + \mathbf{b}_v.
\]

The key projection includes an explicit scaling factor $1/\sqrt{d}$. This scaling is important to keep the typical magnitude of key–query dot products approximately constant as the dimensionality $d$ changes. Without this normalization, the dot products that determine how much each stored outer product contributes to a retrieval could grow with $d$, destabilizing the retrieval denominator and gradients. The same $q,k,v$ terminology mirrors the Transformer vocabulary and clarifies the roles: keys determine where to write in memory (addressing), values are what is written, and queries are how stored information is read back.

# Normalizer vector and denominator stabilization (max of absolute dot and threshold)

When retrieving from the matrix memory, mLSTM forms an unnormalized retrieval vector by multiplying the memory with the query:

\[
\tilde{\mathbf{h}}_t \;=\; \mathbf{C}_t \mathbf{q}_t.
\]

To convert this into a stable, scale-invariant retrieved signal, mLSTM divides by a scalar normalizer formed from the past keys. The normalizer state is itself a vector that accumulates keys with the same gating dynamics used for the matrix:

\[
\mathbf{n}_t \;=\; f_t\,\mathbf{n}_{t-1} \;+\; i_t\,\mathbf{k}_t.
\]

The retrieval then uses the (absolute) dot product between the normalizer and the query as the denominator. To avoid division by very small numbers, the denominator is stabilized by taking the absolute value and lower-bounding it with a threshold (the paper uses a threshold of at least 1.0). Concretely,

\[
\tilde{\mathbf{h}}_t \;=\; \frac{\mathbf{C}_t \mathbf{q}_t}{\max\bigl\{\,|\mathbf{n}_t^\top \mathbf{q}_t|,\,1\,\bigr\}} .
\]

This denominator does two things. First, $\mathbf{n}_t^\top \mathbf{q}_t$ measures the total effective “addressing strength” that past keys have for the current query; dividing by it normalizes the retrieved vector relative to the total stored mass addressed by $\mathbf{q}_t$. Second, taking the absolute value prevents cancellation when some keys are negatively correlated with the query, and the lower bound prevents numerical explosion of the normalized retrieval if the addressing strength is near zero. This stabilization is necessary because the dot product can indeed be close to zero, especially when keys are zero-mean (the model applies layer-norm before key/value projections), and such near-zero denominators would otherwise produce very large fluctuations in the hidden state.

# Gating roles: input as learning rate, forget as decay, output as retrieval scaling

Gates in mLSTM retain the same conceptual roles as in scalar LSTMs, but their interpretation in the matrix-memory setting is particularly clean. The three scalar gates are:

- input gate $i_t$ (often using an exponential activation),
- forget gate $f_t$ (either sigmoidal or exponential), and
- output gate $\mathbf{o}_t$ (a vector gate applied elementwise to the retrieved vector).

In the matrix update

\[
\mathbf{C}_t = f_t\,\mathbf{C}_{t-1} + i_t\,\mathbf{v}_t\mathbf{k}_t^\top,
\]

the input gate $i_t$ plays the role of a learning rate: it controls how strongly the current outer product is added to the memory. A small $i_t$ means the current key–value pair contributes little; a large $i_t$ causes a strong write. The forget gate $f_t$ acts as a decay factor on the whole memory, analogous to a per-step multiplicative forgetting; $f_t<1$ progressively attenuates older contributions. Together, $i_t$ and $f_t$ implement a gated online local learning rule for the memory matrix: each step the previous memory is decayed and a new rank-one update is added with weight $i_t$.

Retrieval is controlled by the output gate $\mathbf{o}_t$, which scales the normalized retrieval elementwise:

\[
\mathbf{h}_t = \mathbf{o}_t \odot \tilde{\mathbf{h}}_t,
\qquad
\tilde{\mathbf{h}}_t = \frac{\mathbf{C}_t \mathbf{q}_t}{\max\bigl\{|\mathbf{n}_t^\top \mathbf{q}_t|,1\bigr\}}.
\]

Thus $\mathbf{o}_t$ can modulate which components of the retrieved vector are exposed to subsequent layers. In summary: $i_t$ = write strength / learning rate, $f_t$ = memory decay, and $\mathbf{o}_t$ = retrieval scaling / selective exposure.

# Connections to Bidirectional Associative Memories and fast weight programmers

The covariance (outer-product) update in mLSTM is a direct instantiation of classical associative memory ideas. The outer-product rule aligns with Bidirectional Associative Memories (BAMs), where associations between two vectors are stored as outer products so that one can retrieve the partner given the other. In mLSTM, each key–value pair $(\mathbf{k}_t,\mathbf{v}_t)$ is stored as the rank-one matrix $\mathbf{v}_t\mathbf{k}_t^\top$, so that later multiplying by a query approximating the key produces a sum of corresponding values.

This update rule is also conceptually equivalent to Fast Weight Programmers: fast (short-lived) weights are updated online by outer products of incoming activations, enabling the network to “program” a temporary associative memory that later influences computation. Interpreting $f_t$ as decay and $i_t$ as a learning rate connects the mLSTM dynamics directly to these earlier formulations: the memory accumulates fast-weight outer products while being multiplicatively decayed, and retrieval is a weighted sum across these fast-weight contributions.

Importantly, the paper emphasizes that, under reasonable assumptions (e.g., zero-mean keys), the covariance update is optimal for maximizing separability of retrieved binary vectors in the sense of signal-to-noise, as described classically. That theoretical grounding explains why outer-product memories are a principled way to pack associations into a fixed-size matrix memory.

# Gate stabilization via m_t as in sLSTM

A distinctive choice in mLSTM is the use of exponential gates for at least the input gate (and optionally the forget gate). Exponential activations allow gates to represent multiplicative factors outside the $[0,1]$ interval and are what enable the input gate to act effectively as a positive learning rate. However, exponentials can easily overflow if their preactivations become large. To prevent numerical instabilities while preserving exact functional equivalence, the paper adopts the stabilizer state $m_t$ introduced for sLSTM. The stabilizing recurrences are

\[
m_t \;=\; \max\bigl(\log(f_t) + m_{t-1},\; \log(i_t)\bigr),
\]

\[
i'_t \;=\; \exp\!\bigl(\log(i_t) - m_t\bigr) \;=\; \exp(\tilde{i}_t - m_t),
\qquad
f'_t \;=\; \exp\!\bigl(\log(f_t) + m_{t-1} - m_t\bigr).
\]

Replacing $i_t$ and $f_t$ by their stabilized versions $i'_t$ and $f'_t$ in the forward pass prevents intermediate exponentials from overflowing; crucially, this reparameterization is algebraically equivalent to the original dynamics and preserves gradients with respect to parameters. This trick permits aggressive exponential gating behavior (useful for flexible learning/decay rates) while maintaining numerical safety during training.

# Parallel reformulation (scan) and absence of memory mixing

A key architectural distinction of mLSTM versus the original LSTM is the absence of memory mixing via hidden-to-hidden recurrent weight matrices. In the mLSTM formulation provided in the paper, the gate preactivations and key/value/query projections depend only on the current input (and biases), not on the previous hidden state. Concretely, the mLSTM gate preactivations are functions of $\mathbf{x}_t$ only (no $r\cdot h_{t-1}$ terms). Because of this lack of hidden-hidden mixing, the temporal recurrence in $\mathbf{C}_t$ and $\mathbf{n}_t$ takes the simple form of a multiplicatively-weighted accumulation:

\[
\begin{aligned}
\mathbf{C}_t &= f_t\,\mathbf{C}_{t-1} + i_t\,\mathbf{v}_t\mathbf{k}_t^\top,\\
\mathbf{n}_t &= f_t\,\mathbf{n}_{t-1} + i_t\,\mathbf{k}_t.
\end{aligned}
\]

These recurrences only depend on scalars $f_t,i_t$ and the current vectors $\mathbf{k}_t,\mathbf{v}_t$, making them amenable to parallel prefix-sum (scan) style algorithms that compute the sequence of cumulative decayed sums in parallel across time steps. In other words, the dependency graph is associative and can be reorganized to exploit parallel hardware, unlike recurrent formulations with dense hidden-to-hidden matrices. The paper observes that this property allows mLSTM to be re-expressed in a parallel form (the implementation details are in the appendix), enabling efficient GPU kernels similar in spirit to optimized implementations of attention (e.g., FlashAttention) or other linearized sequence mechanisms.

Another consequence of the absence of memory mixing is that multiple heads or multiple memory cells are equivalent in mLSTM: there is no recurrent matrix that couples different cells across time, so separable memory blocks operate independently and can be computed in parallel.

# Capacity–compute trade-offs and practical dimensions

The matrix memory of mLSTM delivers much higher expressivity per time step than scalar LSTM cells, but it also brings a clear computational and memory cost: the memory matrix is $\mathbf{C}_t \in \mathbb{R}^{d\times d}$ and each update involves forming and accumulating a $d\times d$ outer product $\mathbf{v}_t\mathbf{k}_t^\top$. Thus the per-step time complexity of the memory update and the retrieval $\mathbf{C}_t\mathbf{q}_t$ is $\mathcal{O}(d^2)$. This is a trade-off: increasing $d$ raises storage capacity (the number of degrees of freedom stored in memory grows quadratically) but increases compute and temporary memory bandwidth requirements substantially.

Two mitigating observations in the paper are important for practice. First, the matrix memory itself does not require additional learned parameters beyond the projection matrices $\mathbf{W}_q,\mathbf{W}_k,\mathbf{W}_v$; the memory is a working state that depends on inputs. Second, the outer-product updates and matrix–vector retrievals are standard dense linear algebra operations that map well to GPU parallelism: although $\mathcal{O}(d^2)$, they can be batched and dispatched efficiently on modern hardware. As a result, the wall-clock impact can be modest if kernels are well optimized. The authors note, however, that their unoptimized mLSTM CUDA kernels were about 4× slower than highly optimized FlashAttention implementations at the time of reporting, indicating scope for further engineering improvements.

In practical architectures, this capacity–compute trade-off suggests choosing $d$ with awareness of both the memory capacity required for the task (longer contexts, many distinct associations favor larger $d$) and the available computational budget. Because the memory accumulation is independent of sequence length in storage (only the matrix size matters), mLSTM has constant memory per layer with respect to context length, which contrasts with Transformers whose caching grows with context length; this can be an advantage for long-context or on-device deployments despite the per-step $d^2$ cost.

--- 

This chapter has explained how mLSTM implements a matrix-valued associative memory via covariance (outer-product) updates, how keys, values and queries interface with that memory (including scaling of keys), how a normalizer and denominator stabilization make retrieval numerically robust, how gates map to learning/decay/retrieval control, how the design connects to associative memory and fast-weight ideas, how exponential gates are stabilized, and how the elimination of hidden-to-hidden mixing enables parallel reformulations at the cost of $\mathcal{O}(d^2)$ compute per step. Together, these elements give mLSTM a powerful memory model suitable for high-capacity sequence modeling when balanced against computational considerations.

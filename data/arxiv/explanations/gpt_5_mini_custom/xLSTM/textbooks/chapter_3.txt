\title{A Textbook about the Paper: "xLSTM: Extended Long Short-Term Memory"}

Chapter 3: xLSTM at a Glance: Goals, Components, and Architecture

# Core contributions: exponential gating and modified memory

xLSTM extends the classic Long Short-Term Memory (LSTM) by introducing two principled modifications designed to overcome well-known LSTM limitations. The first modification is exponential gating: replacing (or augmenting) standard sigmoid gates with exponential activation functions for the input gate (and optionally for the forget gate). The second modification is a change in the memory structure: instead of restricting the memory to a single scalar per cell, xLSTM offers two alternative memory designs that increase expressiveness and storage capacity.

Exponential gating changes how new information is accumulated and how older information is decayed. In a standard LSTM the input gate and forget gate are bounded between 0 and 1 by a sigmoid, so each time step contributes or decays additively in a constrained fashion. By using an exponential activation for the input gate, xLSTM lets the effective learning rate for incoming content grow multiplicatively with \(\exp(\tilde{i}_t)\). To avoid numerical overflow and to preserve correct gradients, the model also introduces a stabilizer state \(m_t\) and a normalizer state (discussed later) so that the algebraic effect on the overall network output is unchanged while numerical stability is maintained.

The memory-structure modification comes in two flavors (detailed below) and allows xLSTM to both revise previously stored information more effectively and to store higher-capacity representations. Together these two contributions — exponential gating and richer memory — are the core technical innovations of xLSTM. Intuitively, exponential gating enables stronger, revisable updates (new evidence can rapidly dominate previous content), while the modified memory enables retrievals that are richer than what a scalar cell can provide.

# Two xLSTM variants: sLSTM (scalar memory) and mLSTM (matrix memory)

xLSTM yields two concrete variants that instantiate the above ideas: the sLSTM and the mLSTM.

The sLSTM keeps the classical scalar cell-state view (a vector of scalar cells when using multiple cells), but it replaces conventional sigmoid input gating with an exponential input gate and introduces supporting normalization and stabilization states. The per-step forward equations for a scalar cell in sLSTM are:
\[
\begin{aligned}
c_t &= f_t\, c_{t-1} + i_t\, z_t &&\text{(cell state)}\\
n_t &= f_t\, n_{t-1} + i_t &&\text{(normalizer state)}\\
\tilde{h}_t &= c_t / n_t,\qquad h_t = o_t\, \tilde{h}_t &&\text{(hidden state)}
\end{aligned}
\]
with the gate parametrizations
\[
i_t = \exp(\tilde{i}_t),\qquad f_t = \sigma(\tilde{f}_t)\ \text{or}\ \exp(\tilde{f}_t),\qquad o_t=\sigma(\tilde{o}_t),
\]
and the usual input transform \(z_t=\varphi(\tilde{z}_t)\). The normalizer \(n_t\) accumulates effective gate mass so that the normalized output \(\tilde{h}_t\) represents a weighted average of stored inputs; dividing by \(n_t\) prevents the cell state from drifting arbitrarily large when gates are exponential. To stabilize exponentials, sLSTM introduces a scalar stabilizer \(m_t\) and computes numerically safe scaled versions \(i'_t\) and \(f'_t\) that preserve exact outputs and gradients while avoiding overflow:
\[
\begin{aligned}
m_t &= \max(\log(f_t)+m_{t-1},\ \log(i_t)),\\
i'_t &= \exp(\log(i_t)-m_t),\qquad f'_t=\exp(\log(f_t)+m_{t-1}-m_t).
\end{aligned}
\]
This stabilizer ensures the exponential gating dynamics are computable and that the normalized hidden state remains meaningful.

The mLSTM replaces the scalar cell by a matrix memory \(\mathbf{C}_t\in\mathbb{R}^{d\times d}\). It stores key–value pairs and uses a covariance (outer-product) update rule so that the memory grows by rank-1 updates at each step. The core forward pass for mLSTM is:
\[
\begin{aligned}
\mathbf{C}_t &= f_t\, \mathbf{C}_{t-1} + i_t\, \mathbf{v}_t \mathbf{k}_t^\top &&\text{(matrix cell state)}\\
\mathbf{n}_t &= f_t\, \mathbf{n}_{t-1} + i_t\, \mathbf{k}_t &&\text{(vector normalizer)}\\
\tilde{\mathbf{h}}_t &= \frac{\mathbf{C}_t \mathbf{q}_t}{\max\{|\mathbf{n}_t^\top \mathbf{q}_t|,\,1\}},\qquad 
\mathbf{h}_t = \mathbf{o}_t \odot \tilde{\mathbf{h}}_t &&\text{(hidden state)}
\end{aligned}
\]
where \(\mathbf{k}_t,\mathbf{v}_t,\mathbf{q}_t\) are key, value, and query vectors projected from input, and \(i_t=\exp(\tilde{i}_t)\) while \(f_t\) may be sigmoid or exponential. The denominator uses the absolute dot product between \(\mathbf{n}_t\) and \(\mathbf{q}_t\) (clipped at 1) to normalize retrieval and avoid near-zero scaling. The matrix memory lets the model encode and retrieve high-dimensional associations via \(\mathbf{C}_t\mathbf{q}_t\), which can produce far richer readouts than scalar-cell multiplication.

In short: sLSTM brings exponential gating into the familiar LSTM scalar framework with normalization/stabilization; mLSTM brings a matrix-valued memory with an outer-product update and normalized retrieval rule.

# Heads and cells: memory mixing within sLSTM heads; equivalence of heads and cells in mLSTM

xLSTM supports multi-cell and multi-head designs, but the semantics differ between sLSTM and mLSTM because of memory mixing.

In sLSTM, when multiple scalar memory cells are used they can be mixed across time through recurrent (hidden-to-gate/input) weight matrices. These recurrent connections (denoted in the paper as \(\mathbf{R}_{\mathbf{z}},\mathbf{R}_{\mathbf{i}},\mathbf{R}_{\mathbf{f}},\mathbf{R}_{\mathbf{o}}\)) allow the hidden state vector \(\mathbf{h}_{t-1}\) to influence the input transforms and gates for each cell, enabling cross-cell interactions. xLSTM introduces the notion of "heads" for sLSTM: within a head, multiple scalar memory cells may be mixed via recurrent connections, but different heads are intentionally kept separate (no memory mixing across heads). This head structure together with exponential gating provides a new form of memory mixing: the exponential gates determine how strongly each cell in a head contributes, while the recurrent mixing shapes how cells interact temporally. The head separation lets the model partition memory into semi-independent processing streams while retaining intra-head mixing for state tracking tasks.

In contrast, mLSTM’s matrix memory inherently captures multi-dimensional associations inside \(\mathbf{C}_t\). Because mLSTM abandons hidden-to-hidden memory mixing (there are no recurrent hidden-hidden weightings mixing \(\mathbf{h}_{t-1}\) into gate computations in the recurrent sense used by sLSTM), the concepts of heads and cells become functionally equivalent: adding extra cells or extra heads simply increases the number of independent matrix memories, but there is no cross-memory mixing performed by recurrent connections. Consequently the paper states that "for mLSTM multiple heads and multiple cells are equivalent." This equivalence simplifies the architectural choices for mLSTM: one may allocate capacity via the internal dimension \(d\) and by stacking multiple matrix memories if desired, but the model's temporal mixing is achieved by the covariance updates rather than by recurrent hidden-to-hidden matrices.

Understanding this difference is important because it explains why sLSTM retains the expressivity of traditional LSTMs for state-tracking tasks (via recurrent mixing), while mLSTM trades that specific mixing mechanism for a richer, parallelizable associative memory.

# xLSTM blocks and residual stacking into full architectures

xLSTM integrates sLSTM and mLSTM cells into modern residual-block backbones to build deep sequence models that are compatible with contemporary LLM tooling. The building block is a residual xLSTM block: the block encapsulates a memory module (sLSTM or mLSTM) plus surrounding projection, normalization, and residual connections that match common pre-LayerNorm residual patterns used in large language models.

Two backbone variants for xLSTM blocks are highlighted because the placement of the projection that moves between the model's "base" dimension and the memory's internal (often higher) dimension matters. For sLSTM blocks the paper uses a post up-projection residual block: the block first nonlinearly summarizes the past in the base dimension, then projects up to a higher-dimensional space where a nonlinearity is applied, and finally projects back to the base dimension. This design mirrors "post up-projection" patterns used in Transformer-like feed-forward modules and is appropriate for sLSTM since its scalar cell formulation operates effectively at the original dimensionality.

For mLSTM blocks the paper prefers a pre up-projection block: inputs are first projected up into a higher-dimensional space where the matrix memory operates. This choice increases the memory capacity in the high-dimensional embedding space, taking full advantage of the matrix cell \(\mathbf{C}_t \in \mathbb{R}^{d\times d}\). In other words, since mLSTM’s memory benefits from larger internal dimension \(d\), projecting into that space before the memory operation yields more expressive associative storage and retrieval.

Once individual xLSTM blocks are defined, a full xLSTM architecture is constructed by residually stacking many such blocks. The stacking uses pre-LayerNorm residual backbones (a standard pattern in modern LLMs), so each block is preceded by LayerNorm and followed by a residual addition to the block's input. This residual stacking enables deep networks that nonlinearly embed histories into high-dimensional spaces — an application of Cover’s Theorem in sequence modeling — making contexts more linearly separable for the final token prediction layer.

# Notation xLSTM[a:b] for block ratios (mLSTM:sLSTM)

To concisely indicate architectures that mix both memory types across layers, the paper introduces the notation xLSTM[a:b] where \(a:b\) is the ratio of mLSTM-based blocks to sLSTM-based blocks. For example, xLSTM[7:1] means that out of every eight residual blocks, seven are mLSTM-based and one is sLSTM-based. With a total of 48 blocks, xLSTM[7:1] corresponds to 42 mLSTM blocks and 6 sLSTM blocks.

This notation allows succinct description of hybrid models that leverage both the high-capacity associative matrix memories of mLSTM and the recurrently-mixed scalar memories of sLSTM. Hybrids can exploit mLSTM’s parallelizability and capacity while preserving sLSTM’s recurrent memory mixing for state tracking where needed.

# Intended benefits: revisability, capacity, and efficiency

xLSTM is explicitly designed to address three shortcomings identified in classical LSTMs: (i) inability to readily revise stored values, (ii) limited storage capacity per scalar cell, and (iii) lack of parallelizability due to hidden-to-hidden memory mixing. Each core design choice in xLSTM maps to these targets.

Revisability. Exponential gating gives the model the ability to revise storage decisions aggressively. Because the input gate can scale as \(i_t=\exp(\tilde{i}_t)\), a later input with a large \(\tilde{i}_t\) can rapidly dominate prior content stored in the cell. The normalizer state \(n_t\) ensures that the output is a normalized aggregation, so later, stronger contributions can effectively overwrite previously stored weaker evidence. Stabilization ensures these exponentials are numerically safe. Empirically (as reported in the paper), this mechanism improves tasks that require revising earlier writes when better evidence arrives.

Capacity. The mLSTM’s matrix memory \(\mathbf{C}_t\) and its covariance update rule \(\mathbf{C}_t \leftarrow f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top\) give much greater storage capacity than scalar cells. Retrieval is performed by \(\mathbf{C}_t\mathbf{q}_t\) and normalized by the normalizer vector, enabling associative recall of high-dimensional values keyed by \(\mathbf{k}\). This design is closely related to covariance-based associative memories and fast-weight schemes and provides a mechanism to store many key–value pairs in a compressed matrix form. Practically, this improves predictions for rare tokens and associative memory tasks where storing distinct high-dimensional items matters.

Efficiency. mLSTM is architected to be parallelizable: because it avoids hidden-hidden recurrent mixing within the matrix memory update and retrieval, the recurrence can be reformulated into parallel operations that are amenable to GPU acceleration (in the same spirit as FlashAttention-like parallelizations). Additionally, xLSTM architectures have linear computation and constant memory complexity with respect to sequence length (unlike Transformer attention which is quadratic in context length). This constant-memory, linear-time behavior makes xLSTM attractive for long-context inference and for deployments where memory is constrained. That said, there are trade-offs: sLSTM retains memory mixing and therefore is not fully parallelizable; mLSTM’s matrix updates are computationally heavier (\(d\times d\) costs) even if parallelizable. The paper addresses these trade-offs by combining blocks (via xLSTM[a:b]) and by careful block design (pre/post up-projection) so a practical balance of capacity, revisability, and throughput can be achieved.

In summary, xLSTM brings exponential gating to enable revisable writes, introduces a matrix associative memory to expand capacity, and integrates both into residual block backbones so the models fit contemporary LLM design patterns. The sLSTM variant maintains recurrent mixing and fine-grained state-tracking ability, while the mLSTM variant provides high-capacity, parallelizable associative storage; mixing these under the xLSTM[a:b] notation gives architects a flexible palette for trading capacity, revisability, and runtime efficiency.

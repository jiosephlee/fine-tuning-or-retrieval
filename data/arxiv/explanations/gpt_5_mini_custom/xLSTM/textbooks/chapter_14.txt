\title{A Textbook about the Paper: "xLSTM: Extended Long Short-Term Memory"}

Chapter 14: Limitations, Risks, and Open Problems

# Non-parallelizable sLSTM and current kernel speed gaps
One of the core strengths introduced for sLSTM is memory mixing: sLSTM keeps the traditional hidden-to-hidden (recurrent) connections that allow different scalar memory cells to interact across time. This memory mixing underlies the expressiveness of LSTM-style RNNs for problems that require state tracking or revisions to stored information. However, those same recurrent dependencies make sLSTM inherently sequential: the update at time $t$ depends on $h_{t-1}$ and the mixed memories, so the forward pass cannot be trivially parallelized across time steps as is possible for models that remove hidden–hidden recurrence.

The paper is explicit about this tradeoff. Because sLSTM preserves memory mixing, it cannot be converted into a fully parallel, scan-free implementation in the same way mLSTM can. Practically, that means wall-clock throughput for long unbatched sequence generation will remain limited by sequential compute unless specialized kernels are used. The authors mitigated this in part by developing a highly optimized CUDA kernel with GPU memory optimizations down to the register level; their implementation narrows the gap so that sLSTM is typically less than two times slower than their parallel mLSTM implementation. While this is an important engineering achievement, the remaining factor-of-two slowdown still represents a bottleneck for production usage at very large scales or for low-latency inference on single streams. Furthermore, because the kernel is specialized, portability and maintainability can be concerns when deploying across different hardware or frameworks.

Open problems arising here include whether one can retain the expressivity of memory mixing while achieving closer-to-parallel runtimes, and how to broaden the set of available, well-optimized kernels for sLSTM on diverse accelerators. The paper demonstrates a pragmatic path—low-level CUDA optimization—but leaves room for further kernel engineering and algorithmic alternatives that reduce the sequential dependency without losing the capacity for state revision.

# Unoptimized mLSTM kernels and opportunities for acceleration
Unlike sLSTM, the mLSTM design removes hidden–hidden recurrence (no memory mixing) and replaces scalar memory with a matrix memory $\mathbf{C}_t \in \mathbb{R}^{d\times d}$ updated by a covariance rule:
\[
\mathbf{C}_t = f_t\,\mathbf{C}_{t-1} + i_t\,\mathbf{v}_t \mathbf{k}_t^\top.
\]
Because mLSTM eliminates inter-step hidden mixing, its recurrence can be rewritten in a parallel form suitable for batched matrix operations on GPUs. In principle, this makes mLSTM parallelizable in time and amenable to optimized kernels just like attention-based models. The paper notes that mLSTM is “parallelizable analog to FlashAttention or GLA.”

In the current implementation, however, mLSTM kernels are not fully optimized. The authors report that their mLSTM implementation is about four times slower than FlashAttention or the efficient scan used in Mamba. This is a concrete performance gap: while the algorithmic structure supports parallelism, the implementation has not yet taken full advantage of the same low-level optimizations (memory layout, fused kernels, tiling strategies) that make FlashAttention so fast.

This is both a limitation and an opportunity. Bringing mLSTM kernel performance to parity with high-performance attention kernels would reduce inference and training overhead and make mLSTM a far more practical choice. The paper suggests that "faster CUDA kernels could be obtained in the vein of FlashAttention," pointing to a clear engineering direction: design fused, tiled, memory-efficient kernels for the $d\times d$ updates and retrievals, reduce bandwidth by careful blocking, and exploit hardware primitives for matrix multiply-accumulate. Achieving this requires low-level systems work but is fully consistent with the model’s algorithmic structure.

# Compute cost of d-by-d memory updates in mLSTM
mLSTM gains storage capacity by replacing scalar cell states with a matrix memory $\mathbf{C}_t$ of size $d\times d$. This makes retrieval a matrix–vector product and update a rank-one outer product scaled by gates, as in the covariance rule above. The gain in representational power is explicit: matrix memory enables storing and retrieving $d$-dimensional key–value pairs, which empirically improves performance on tasks involving rare tokens and associative recall.

The cost of this richer memory, however, is substantial: both the memory footprint and compute per time step scale with $d^2$. The paper frames this as a tradeoff between memory capacity and computational complexity. Although the matrix memory itself does not add learnable parameters (the update uses outer products of projected inputs and gating scalars), the $O(d^2)$ work for updates and the $O(d^2)$ elements to hold $\mathbf{C}_t$ are nontrivial for large $d$. In practice, the authors note that these matrix operations can be parallelized on GPUs and therefore the wall-clock overhead was only minor in their experiments, but the theoretical scaling remains a constraint.

This creates several practical risks. Training very large models with large $d$ will raise GPU memory pressure and increase FLOPs per token. For latency-sensitive inference, the $d\times d$ cost may dominate, especially when unbatched. Algorithmically, using matrix memory forces practitioners to choose $d$ as a knob that trades capacity against compute; an inappropriate choice can either underutilize model capacity or make training/inference prohibitively expensive.

# Forget-gate initialization sensitivity and training stability
The paper highlights that initialization of forget gates is important and can affect training stability. This sensitivity is closely tied to the dynamics introduced by exponential gating and by matrix memory updates that accumulate information over time. Exponential gates (input and possibly forget gates) can produce large multiplicative factors, and if not stabilized, these can cause numerical overflow or induce badly conditioned gradients. To address this, the authors introduce explicit stabilization: a stabilizer state $m_t$ and normalized gates defined by
\[
m_t = \max\big( \log(f_t) + m_{t-1}, \; \log(i_t) \big),
\]
and stabilized gates defined by exponentials shifted by $m_t$ so that their magnitudes are kept in a safe range. For mLSTM, they also normalize retrieved outputs by a normalizer $\mathbf{n}_t$ and lower bound the absolute dot product with the query by a threshold (typically 1.0) to prevent vanishing denominators.

Even with these mechanisms, the paper lists careful choice of forget-gate initialization as a limitation: a poor initialization can lead to exploding or vanishing contributions from past memory, which destabilizes learning. This sensitivity manifests both for scalar sLSTM (where multiplicative recurrence accumulates) and matrix mLSTM (where $\mathbf{C}_t$ integrates many outer products). Thus, an important risk during model development is that training might fail or converge to suboptimal solutions unless gate biases, learning rates, and stabilizer behavior are tuned.

Addressing this limitation requires methodical hyperparameter protocols and possibly more robust default initializations or adaptive schemes. The paper documents stabilization techniques that help, but it also notes that initialization remains a point of fragility.

# Potential memory overload at very long contexts and mitigation
A distinctive property of mLSTM is that its matrix memory $\mathbf{C}_t$ does not grow with sequence length: the memory size is fixed at $d\times d$ and each update is a weighted accumulation. This compressive memory is advantageous because it keeps working memory bounded independent of context window, enabling constant memory complexity with respect to sequence length. However, this fixed capacity raises the possibility of memory overload when faced with very long contexts containing many distinct items to remember: if too many key–value pairs are written into the same $d\times d$ memory without sufficient forgetting, signal from earlier items may be diluted or interfere.

The paper explicitly notes this potential limitation while also reporting empirical results that contexts up to length 16k did not appear to overload the memory for their models and tasks. Mitigations already built into the architecture include the forget gate acting as a decay (multiplying $\mathbf{C}_{t-1}$ by $f_t$) and the normalizer state $\mathbf{n}_t$ that keeps track of cumulative gate strength, with retrieval normalized by $\max\{|\mathbf{n}_t^\top \mathbf{q}_t|, 1\}$. These mechanisms aim to keep stored content balanced and retrieval stable.

Nonetheless, for application domains with extremely long horizons or highly diverse information streams, there is a risk that the fixed-size compressive memory will be insufficient. In such regimes, one must consider tradeoffs: increase $d$ (raising $d^2$ cost), tune forget dynamics more aggressively, or interleave other storage mechanisms. The paper does not prescribe a single remedy but flags this as an area where additional work could refine memory management.

# Need for broader hyperparameter and architecture search
The paper candidly acknowledges that, due to computational cost, they did not fully optimize architectures and hyperparameters, especially at larger scales. This is an important limitation: the strong experimental results reported for xLSTM already required careful design decisions (exponential gating, stabilizers, normalizers, block selection between pre/post up-projection), and the authors expect that further gains are achievable through systematic search.

Broad hyperparameter and architecture sweeps are needed to (a) find robust initializations for gates and stabilizers, (b) determine optimal values of $d$ that balance capacity and compute, (c) tune the ratio of mLSTM to sLSTM blocks (xLSTM[$a$:$b$]) for different tasks, and (d) adapt residual backbone choices (pre-/post-up projection) to particular data distributions. The experiments already show that different block compositions (e.g., xLSTM[1:0] vs xLSTM[7:1]) have measurable effects across benchmarks, indicating this is a productive search space.

Because these searches can be computationally expensive, a practical risk is that small teams or labs without large compute budgets may not be able to find ideal configurations, potentially leaving xLSTM under-optimized compared to more established architectures that already benefit from extensive tuning. The paper therefore frames additional hyperparameter and architecture optimization as a clear, necessary next step to unlock the model class’s full potential.

# Future directions: improved kernels, hybrid models, and new domains
The paper both identifies limitations and sketches promising directions to address them. On the systems side, there is an opportunity for kernel engineering: designing fused, memory-efficient CUDA kernels for mLSTM that mirror the performance of FlashAttention would reduce the current implementation gap (the reported ~4x slowdown) and make mLSTM more practical. For sLSTM, further work could reduce the remaining sequential overhead, either by further low-level optimization of the specialized CUDA kernel or by algorithmic compromises that preserve much of memory-mixing expressivity while enabling more parallel computation.

On the modeling side, xLSTM already provides hybrid choices: the architecture accepts mixtures of mLSTM and sLSTM blocks (xLSTM[$a$:$b$]) and supports multiple cells and heads in sLSTM, giving a rich space of hybrid designs that balance memory mixing against parallelizability. The empirical results show that different mixtures produce different tradeoffs across tasks; therefore systematic exploration of these hybrids is a promising research direction. In addition, the stabilization techniques (stabilizer state $m_t$, normalizer $\mathbf{n}_t$, and thresholded normalization in retrieval) are concrete handles that can be refined or made adaptive.

Finally, the paper points to broader application domains where xLSTM might have impact—reinforcement learning, time series forecasting, and modeling physical systems—because of the compressive, constant-memory behavior and the improved capacity for state tracking. Extending xLSTM to these domains will require domain-specific evaluations and possibly architecture or training adaptations, which the authors identify as open work.

Taken together, these directions form a concrete research agenda that stays within the design choices and empirical observations of the paper: (i) kernel and systems optimization to close runtime gaps, (ii) careful hyperparameter and architectural search to stabilize and scale training, (iii) exploration of hybrid block mixtures to trade off expressivity and parallelism, and (iv) evaluations in new problem domains to validate the architecture’s practical benefits.

# Summary of risks and open problems
To summarize the primary limitations and risks documented in the paper: sLSTM’s memory mixing makes it sequential and thus slower unless specialized kernels are used; current mLSTM kernels are not yet as optimized as state-of-the-art attention kernels; mLSTM’s $d\times d$ memory imposes $O(d^2)$ compute and storage costs that must be managed; exponential gating and accumulation behavior create sensitivity to forget-gate initialization and require stabilizers; fixed-size compressive memory may be overloaded in extreme long-context regimes; and the architecture and hyperparameter space remain under-explored due to resource costs.

Each of these limitations is paired in the paper with partial mitigations or clear research directions: stabilization mechanisms and normalizers to improve numerical behavior, specialized CUDA kernels for sLSTM and the potential for FlashAttention-style kernels for mLSTM, hybrid block compositions, and extensive hyperparameter/architecture search. These are precisely the avenues by which xLSTM can be matured from a promising architecture to a widely deployable family of models.

\title{A Textbook about the Paper: "xLSTM: Extended Long Short-Term Memory"}

Chapter 5: sLSTM: Scalar Memory with Exponential Gating and Memory Mixing

# sLSTM forward pass: cell, normalizer, hidden state, and gates

The sLSTM retains the original LSTM notion of a scalar memory cell per dimension, but introduces two central modifications: exponential gating for some gates, and a normalizer state that records cumulative gate influence. The forward-pass equations for a single scalar sLSTM cell at time step $t$ are:

\[
\begin{aligned}
c_t &= f_t \, c_{t-1} + i_t \, z_t &&\text{(cell state)}\\[4pt]
n_t &= f_t \, n_{t-1} + i_t &&\text{(normalizer state)}\\[6pt]
h_t &= o_t \, \tilde{h}_t,\qquad 
   \tilde{h}_t = \frac{c_t}{n_t} &&\text{(hidden state / readout)}\\[6pt]
z_t &= \varphi(\tilde{z}_t),\qquad
   \tilde{z}_t = \mathbf{w}_z^\top \mathbf{x}_t + r_z \, h_{t-1} + b_z &&\text{(cell input)}\\[6pt]
i_t &= \exp(\tilde{i}_t),\qquad
   \tilde{i}_t = \mathbf{w}_i^\top \mathbf{x}_t + r_i \, h_{t-1} + b_i &&\text{(input gate)}\\[6pt]
f_t &= \sigma(\tilde{f}_t)\ \text{OR}\ \exp(\tilde{f}_t),\qquad
   \tilde{f}_t = \mathbf{w}_f^\top \mathbf{x}_t + r_f \, h_{t-1} + b_f &&\text{(forget gate)}\\[6pt]
o_t &= \sigma(\tilde{o}_t),\qquad
   \tilde{o}_t = \mathbf{w}_o^\top \mathbf{x}_t + r_o \, h_{t-1} + b_o &&\text{(output gate)}
\end{aligned}
\]

These equations preserve the additive "constant error carousel" update $c_t = f_t c_{t-1} + i_t z_t$ from classical LSTM, but they (i) allow input gates (and optionally forget gates) to be exponential instead of sigmoid, and (ii) introduce the normalizer $n_t$ so that the readout $\tilde{h}_t$ is the normalized cell state $c_t/n_t$ rather than a squashed version of $c_t$. The activations $\varphi$ and $\sigma$ are as in the original formulation (e.g., $\varphi$ commonly $\tanh$, $\sigma$ the logistic sigmoid). The recurrent coefficients $r_z, r_i, r_f, r_o$ and input weight vectors $\mathbf{w}_\cdot$ play the same role as in standard LSTMs.

Intuitively, $c_t$ accumulates weighted contributions of past inputs (weighted by $i$ and modulated by $f$), while $n_t$ keeps an analogous accumulated weight (the sum of effective input weights after forget dynamics). Dividing $c_t$ by $n_t$ produces a normalized readout that behaves like a weighted average of stored contributions. This normalization both stabilizes retrieval and enables the cell state to represent a magnitude that is comparable across time and across contexts.

Because exponential gates can grow very large or very small and thereby cause numerical overflow/underflow, the sLSTM employs a stabilizer state (described below) that algebraically rescales gates without changing the exact forward outputs or gradients. The stabilizer is crucial for safely using exponential activations in practice.

# Forget gate choices: sigmoid vs exponential

A key design choice in sLSTM is whether the forget gate $f_t$ should remain a sigmoid-limited gate in $(0,1)$ as in standard LSTM, or be replaced by an exponential $\exp(\tilde{f}_t)$ which can assume a wider positive range. The paper presents both options and discusses how they affect behavior.

When $f_t=\sigma(\tilde{f}_t)$, the forget gate behaves like a classical decay factor: each time step it attenuates past cell content and past normalizer weight by a multiplicative factor in $(0,1)$. This enforces a conventional forgetting dynamics where older contributions gradually diminish.

By contrast, using $f_t=\exp(\tilde{f}_t)$ permits $f_t$ to exceed $1$ and to take arbitrarily small positive values (after stabilization). This broader dynamic range enables richer temporal scaling: the model can exponentially amplify or attenuate past contents depending on $\tilde{f}_t$. Combined with exponential input gates $i_t=\exp(\tilde{i}_t)$, this allows the network to express very different effective weights for different stored inputs, which is central to sLSTM's ability to revise earlier storage decisions (see section on memory mixing below).

Because exponential gates can produce extreme magnitudes, the sLSTM includes a stabilization mechanism that rescales gate magnitudes algebraically but without changing the network output or gradients. The stabilizer state $m_t$ is defined by

\[
\begin{aligned}
m_t &= \max\!\big(\log(f_t) + m_{t-1},\ \log(i_t)\big)\\[6pt]
i'_t &= \exp\!\big(\log(i_t) - m_t\big) = \exp(\tilde{i}_t - m_t)\\[6pt]
f'_t &= \exp\!\big(\log(f_t) + m_{t-1} - m_t\big),
\end{aligned}
\]

and the forward pass can be computed with $i'_t$ and $f'_t$ in place of $i_t$ and $f_t$. The authors show that this substitution leaves the outputs and parameter gradients unchanged while preventing numerical overflow. Practically, this stabilizer lets one safely use exponential gates while preserving the interpretability of $n_t$ as an accumulated gate mass.

In summary, choosing sigmoid for $f_t$ gives conservative, bounded forgetting; choosing exponential for $f_t$ expands the model's expressive regime, enabling amplification-like dynamics. The appropriate choice depends on the task and training stability; the paper experiments with both variants.

# Multiple cells and recurrent mixing matrices

Although sLSTM is defined per scalar memory cell, the practical implementation uses vector-valued cell states $\mathbf{c}_t \in \mathbb{R}^d$ comprising multiple scalar cells. When multiple cells are present, sLSTM supports recurrent mixing between cells through recurrent weight matrices, in direct analogy to vector LSTMs. Concretely, the scalar recurrences above generalize by replacing scalar recurrent weights $r_\cdot$ with matrices $\mathbf{R}_\cdot \in \mathbb{R}^{d\times d}$ and scalar weights $\mathbf{w}_\cdot$ with input projection matrices, such that the pre-activations for cell input and gates include terms like $\mathbf{R}_z \mathbf{h}_{t-1}$, $\mathbf{R}_i \mathbf{h}_{t-1}$, etc.

These recurrent matrices enable "memory mixing": information written into one scalar cell can influence the inputs and gates of other cells at later time steps through the hidden state feedback. Memory mixing is crucial for solving tasks that require combining, updating, or correcting multiple stored pieces of information over time (for example, complex state-tracking problems or formal-language tasks). In the paper the recurrent mixing matrices are denoted by $\mathbf{R}_{\mathbf{z}}, \mathbf{R}_{\mathbf{i}}, \mathbf{R}_{\mathbf{f}}, \mathbf{R}_{\mathbf{o}}$, emphasizing that each projection into the cell input or each gate can receive a different linear combination of the previous hidden state.

Because the normalizer $\mathbf{n}_t$ is maintained per cell in the vector case (each scalar cell has its own normalizer), the readout for each cell remains a per-cell normalized quantity $\tilde{\mathbf{h}}_t = \mathbf{c}_t \oslash \mathbf{n}_t$ (elementwise division), and recurrent mixing operates through the hidden state $\mathbf{h}_t$ that aggregates these per-cell readouts via the output gate $\mathbf{o}_t$. Thus multi-cell sLSTM preserves the scalar-memory semantics while enabling rich cross-cell interactions through learned recurrent weight matrices.

# Multi-head sLSTM: mixing within heads, not across heads

The sLSTM architecture can be extended with multiple "heads". A head is a grouping of some subset of the scalar memory cells that share strong within-group recurrent mixing but are isolated from other heads in terms of hidden-to-cell recurrent connections. The paper emphasizes the following design: within each head, cells may mix via recurrent matrices, but there is no recurrent mixing across heads. In other words, the hidden state components feeding back into a head are restricted to that head's cells; heads do not directly recurrently influence one another.

This multi-head arrangement accomplishes several things. First, it partitions the memory into independently updating blocks that can each learn specialized dynamics. Second, by preventing cross-head recurrent mixing, the model reduces interference between distinct memory subsystems; each head can maintain its own local "working memory" and gating dynamics. Third, by allowing mixing within but not across heads, the architecture provides a controlled trade-off between expressivity and the strong sequential dependence that full recurrent mixing entails.

Importantly, multi-head sLSTM differs from multi-head designs in attention-based models: here, heads are not parallel attention maps but sets of scalar memory cells with their own recurrent interactions. The paper indicates that the introduction of heads together with exponential gating "establishes a new way of memory mixing": heads permit modular, localized recurrent dynamics, while exponential gates allow individual contributions within a head to be weighted (and revised) with high dynamic range.

# New memory mixing behavior induced by exponential gates

The combination of exponential input gates and the normalizer $n_t$ changes the semantics of what the cell stores and how later inputs can revise earlier ones. In a classical LSTM, gates are typically sigmoid-limited to $(0,1)$, which constrains how much a new input can override past stored values: the input gate can only add a bounded amount relative to the existing cell content, and the forget gate can only attenuate at most down to zero.

With exponential input gates $i_t=\exp(\tilde{i}_t)$, however, a newly arriving input can be assigned an arbitrarily large weight relative to previous contributions. Concretely, the cell state accumulation

\[
c_t = f_t c_{t-1} + i_t z_t
\]

and the normalizer accumulation

\[
n_t = f_t n_{t-1} + i_t
\]

together imply that the readout $\tilde{h}_t = c_t / n_t$ is a weighted average of past $z$ inputs with weights proportional to the products of their input gates and subsequent forget gates. If a later $i_t$ is much larger than the accumulated weighted mass $f_t n_{t-1}$, that new $z_t$ will dominate the ratio $c_t/n_t$, effectively allowing the model to revise or "override" previously stored values. Exponential gates make such strong re-weightings feasible because they are not bounded by $1$.

The normalizer $n_t$ is the critical device that keeps this mechanism stable and interpretable: it records the total effective weighting mass so that $\tilde{h}_t$ is always a normalized combination. Without $n_t$, unbounded exponential gating could produce unbounded $c_t$ and cause unstable outputs. Furthermore, the stabilizer state $m_t$ rescales exponentials so that computation remains numerically safe while preserving exact forward behavior.

This mechanism is exactly what allows sLSTM to address one of the classic LSTM limitations described in the paper: the inability to revise storage decisions (illustrated by the Nearest Neighbor Search task). Exponential gating plus normalization permits later inputs to strongly reweight the stored summary, enabling the cell to prioritize newer or more relevant inputs even when earlier inputs had been stored previously.

Finally, when multiple cells and recurrent mixing are present, exponential gating magnifies the expressive power of memory mixing: cells can interact, and a strong exponential gating decision in one cell can cascade through recurrent matrices to change the gate pre-activations of other cells on subsequent steps. This leads to richer dynamics than either classical LSTM gating or non-recurrent (no memory mixing) mechanisms like many SSMs and attention substitutes.

# Parallelization limits and practical CUDA implementation notes

A key practical difference between sLSTM and the mLSTM variant (matrix memory) is parallelizability. Because sLSTM retains hidden-to-hidden recurrent matrices (recurrent mixing through $\mathbf{R}_\cdot$), its time-step computations are inherently sequential: the computation at time $t$ depends on $h_{t-1}$ in a way that prevents straightforward parallelization across time steps. The paper explicitly notes that "sLSTM is not parallelizable due to the memory mixing (hidden-hidden connections)."

Despite this theoretical sequential bottleneck, the authors implemented highly optimized CUDA kernels for sLSTM that exploit GPU register-level memory layouts and other low-level optimizations. In practice, their fast CUDA implementation makes sLSTM performance competitive: the implementation is "typically less than two times slower than mLSTM." This indicates that while sLSTM cannot match the same degree of parallel wall-clock speed as fully parallelizable architectures, careful low-level engineering can substantially narrow the gap and make sLSTM practical for many workloads.

The paper also contrasts sLSTM with mLSTM in terms of parallelism: mLSTM abandons memory mixing (hidden-hidden recurrent connections) and so can be reformulated in a parallel fashion akin to some linear-attention or Fast Weight architectures. Consequently, mLSTM admits straightforward parallelized GPU implementations, whereas sLSTM requires sequential processing but benefits from optimized sequential kernels.

# When to use sLSTM blocks in practice

The sLSTM block is a design choice inside the larger xLSTM residual-stacked architecture. In xLSTM, sLSTM-based blocks are integrated into a residual backbone with a post up-projection pattern (i.e., non-linear summarization happens in the original embedding dimension and is then projected up and back), as described in the paper. Practically, the paper recommends using sLSTM blocks when the task benefits from recurrent memory mixing and strong per-step revision capability:

- State-tracking and formal-language problems. The experiments show that models with sLSTM (and hence memory mixing and exponential gating) can solve formal languages and tasks requiring explicit state-tracking that purely feedforward or non-mixing architectures cannot reliably handle.

- Scenarios where the model must revise stored information. Tasks like the Nearest Neighbor Search example (described in the paper) reveal that classical LSTM struggles to revise previously stored values; sLSTM's exponential gating and normalization enable effective revision.

- When combining with larger-capacity blocks. The empirical xLSTM designs often mix sLSTM blocks with mLSTM blocks (matrix-memory blocks). For example, the notation xLSTM[$a$:$b$] in the paper denotes the ratio of mLSTM-based to sLSTM-based blocks; mixing a small number of sLSTM blocks into predominantly mLSTM-based stacks (e.g., xLSTM[7:1]) leverages sLSTM's mixing capabilities while preserving overall parallel efficiency.

The trade-offs are explicit: sLSTM provides stronger sequential expressivity at the cost of reduced parallelizability. Thus, if the primary requirement is maximal throughput on very long contexts where parallelism dominates, then an mLSTM-based or other parallelizable block might be preferable. If the problem requires nuanced, cross-temporal interactions, state updates and revisions, or robust handling of structured sequential dependencies, sLSTM blocks are the right tool.

In summary, use sLSTM blocks when you need scalar-cell memory semantics with interpretability, the capacity to revise stored contents aggressively via exponential gating, and the modeling power of recurrent memory mixing; be prepared for a sequential computational pattern that demands optimized kernels for competitive wall-clock performance.

# Concluding remarks

sLSTM preserves scalar-cell intuitions from classical LSTM while extending them in two critical ways: exponential gating (with algebraic stabilization) and an explicit normalizer that produces a readout interpretable as a weighted average of past inputs. When extended to multiple cells and organized into heads, sLSTM yields a flexible memory-mixing substrate that is particularly effective for state-tracking and tasks that require revising stored information. The principal practical drawback is the lack of straightforward parallelization, but the paper demonstrates that careful CUDA implementation makes sLSTM competitive in practice and useful as a component in the mixed xLSTM architectures.

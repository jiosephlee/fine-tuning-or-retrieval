\title{Blogs about the Paper: "xLSTM: Extended Long Short-Term Memory"}

# From LSTM to xLSTM: Can RNNs Power the Next Wave of Language Models?

## Why revisit LSTMs now?

Long Short-Term Memory (LSTM) networks introduced two ideas that changed sequence learning: a persistent (additive) cell state and gating to control writing, forgetting and reading. Those ideas solved the vanishing gradient problem and enabled many successes across sequence tasks. But since Transformers rose to prominence, LSTMs have been largely sidelined for large-scale language modeling. Transformers scale well, are massively parallelizable, and use attention to give powerful (and effectively unbounded) memory.

This paper asks a simple, practical question: if we bring modern training practices and a few structural changes to LSTMs, can a scaled-up recurrent model compete with Transformers and modern State Space Models (SSMs) in language modeling? The answer the authors present is: yes—when you fix three core LSTM weaknesses.

## The three classic LSTM pain points

The paper identifies three limitations of traditional LSTMs that explain why they fell behind at large scale:

1. Revising storage decisions. Standard LSTM updates the scalar cell state with gated additive updates. If the model stored a value earlier and later sees a better candidate, it can be hard to revise that earlier storage reliably. This hurts tasks that require finding or replacing the best-match item seen so far.

2. Storage capacity. Traditional LSTM cells are scalar (or vector of scalars) state entries. That forces compression of rich key/value-like structure into low-dimensional scalars, which limits the ability to store and retrieve complex associations. Rare tokens and associative recall tasks reveal this bottleneck.

3. Parallelism and throughput. LSTMs rely on hidden-to-hidden (recurrent) mixing across time steps, which prevents straightforward parallelization across sequence length and limits throughput compared to Transformer-style models.

xLSTM addresses these three issues with two core ideas: exponential gating (plus stabilization and normalization) and alternative memory structures (a scalar-but-improved sLSTM, and a matrix-memory mLSTM).

## Key idea 1 — exponential gating (and why it helps)

Standard LSTM gates use sigmoids, which produce values in $(0,1)$ and behave like soft switches. xLSTM proposes using exponential activations for the input gate, and optionally for the forget gate, i.e. gates of the form
- input gate: \(i_t = \exp(\tilde{i}_t)\),
- forget gate: \(f_t = \sigma(\tilde{f}_t)\) or \(f_t = \exp(\tilde{f}_t)\).

Why exponential gates? Two practical consequences:

- Exponential gates naturally implement multiplicative weighting in the log-domain, which makes it straightforward to accumulate contributions across time in ways that allow later updates to dominate earlier ones when appropriate—this enables easier revision of stored content.
- Using exponentials lets the gate strengths act like (possibly large) positive scalars, which the authors pair with a lightweight normalization mechanism (a "normalizer" state) so outputs remain well-behaved.

Because raw exponentials can overflow or underflow, xLSTM adds a stabilizer state \(m_t\) that rescales the gates in a numerically stable way. The stabilized gates are mathematically equivalent to the unstabilized formulation but avoid numerical issues during training and inference.

In plain terms: exponential gating gives the model a more flexible, multiplicative way to accumulate and revise memory contributions over long time ranges, and stabilization keeps training stable.

## Key idea 2 — two memory variants: sLSTM and mLSTM

xLSTM introduces two complementary memory designs that both use exponential gating.

sLSTM: a scalar but enhanced memory cell
- The sLSTM keeps a scalar cell state like classic LSTM but extends it with the exponential gates plus a normalizer state \(n_t\).
- The forward update is
  - \(c_t = f_t c_{t-1} + i_t z_t\),
  - \(n_t = f_t n_{t-1} + i_t\),
  - \(\tilde{h}_t = c_t / n_t\), and \(h_t = o_t \tilde{h}_t\).
- The normalizer \(n_t\) tracks the total effective contribution of the inputs (input gate weighted and decayed by future forget gates). Dividing \(c_t\) by \(n_t\) produces a normalized readout, which makes updates comparable and enables the revising behavior.

sLSTM also supports multiple memory cells and a notion of “heads.” Within each head it allows memory mixing (hidden-to-memory recurrent connections), giving sLSTM the ability to do state-tracking reasoning that purely parallelizable memories lack.

mLSTM: matrix memory with a covariance (outer-product) update
- To boost storage capacity, mLSTM upgrades the cell from a scalar to a matrix \(\mathbf{C}_t \in \mathbb{R}^{d\times d}\).
- At each step it stores a key/value pair \((\mathbf{k}_t, \mathbf{v}_t)\) using a covariance (outer-product) update:
  - \(\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \, \mathbf{v}_t \mathbf{k}_t^\top\).
- Retrieval is a matrix-vector product \(\mathbf{C}_t \mathbf{q}_t\), normalized by the dot product between the normalizer \(\mathbf{n}_t\) and \(\mathbf{q}_t\) (safely lower-bounded), and scaled by an output gate:
  - \(\tilde{\mathbf{h}}_t = \mathbf{C}_t \mathbf{q}_t / \max\{|\mathbf{n}_t^\top \mathbf{q}_t|, 1\}\),
  - \(\mathbf{h}_t = \mathbf{o}_t \odot \tilde{\mathbf{h}}_t\),
  - \(\mathbf{n}_t = f_t \mathbf{n}_{t-1} + i_t \mathbf{k}_t\).
- The covariance update is closely related to classic associative memories and to fast-weight approaches: it stores distributed associations where retrieval is a dot-product-based lookup.

Why the matrix memory matters: it increases storage capacity substantially compared to scalar cells and lets the model store many key/value-like associations without needing attention. Because mLSTM avoids hidden-to-hidden recurrence (no memory mixing), it can be implemented in a parallel way across time, making it competitive on throughput.

## Architecture: xLSTM blocks and residual stacks

xLSTM integrates sLSTM and mLSTM cells into residual block backbones similar to modern LLM architectures. Two block designs are used:

- For sLSTM blocks, a post up-projection residual block is used: the block summarizes the past in the original space, projects up, applies nonlinearity, and projects back.
- For mLSTM blocks, a pre up-projection block is used: inputs are projected up before the non-linear, high-dimensional memory operations, which matches the intuition that matrix memory benefits from higher-dimensional representations.

These xLSTM blocks are stacked residually with pre-LayerNorm, mirroring contemporary model design choices. The authors denote mixed architectures as xLSTM[a:b], where \(a/b\) is the ratio of mLSTM-based to sLSTM-based blocks in a stack. For example, xLSTM[7:1] means 7 mLSTM-based blocks and 1 sLSTM-based block per 8-block group.

## What the experiments show (high-level summary)

The paper evaluates xLSTM across synthetic tasks and large-scale language modeling experiments. Key empirical findings:

- Synthetic tasks: Exponential gating plus memory mixing lets the sLSTM variants solve formal state-tracking problems (regular-grammar-like tasks) that pure parallel models (Transformers, many SSMs) struggle with. The matrix memory (mLSTM) improves associative recall capacity and extrapolation to longer contexts on multi-query recall tasks.

- Comparison on 15B-token training regime: On models matched to a GPT-3 small style (≈350M parameters), xLSTM variants outperform a range of baselines (Transformers, SSMs, and modern RNN variants) in validation perplexity after training on 15B tokens from SlimPajama. Ablations attribute the gains to both exponential gating and the matrix memory.

- Large-scale (300B tokens) experiments: The authors train families of models (125M to 1.3B) on 300B tokens and report:
  - Better extrapolation to longer contexts (up to 16k) than the compared methods.
  - Lower validation perplexities and stronger performance on a suite of downstream tasks and on the PALOMA benchmark (571 text domains).
  - Favorable scaling-law offsets—xLSTM shares similar power-law slopes but with a lower loss offset versus some competitors, suggesting competitiveness at larger sizes.

- Efficiency: xLSTM variants have linear time complexity and constant memory with respect to sequence length (in contrast to quadratic Transformers). The mLSTM is parallelizable; sLSTM retains recurrent mixing so is less parallel but the authors implemented optimized CUDA kernels that are only modestly slower than the parallel mLSTM. The matrix updates in mLSTM do add compute cost due to \(d\times d\) operations, but these are parameter-free and parallelizable.

## Limitations to keep in mind

The paper is transparent about limitations:

- sLSTM's memory mixing prevents full parallelization; it requires sequential hidden mixing. The authors mitigate this with optimized kernels but it still limits throughput relative to fully parallelized designs.

- mLSTM's matrix memory is computationally expensive for large \(d\); current CUDA kernels are not fully optimized and the implementation is slower than highly optimized attention kernels like FlashAttention.

- The matrix memory is independent of sequence length: very long contexts could overload a fixed-size matrix memory, though experiments up to 16k context did not show a breakdown.

- Initialization and hyperparameter choices (particularly for forget gates) are delicate and require care.

- The authors did not fully optimize every architectural and hyperparameter choice for the largest models due to compute costs; further tuning could improve performance further.

## Bottom line — what changed and why it matters

xLSTM shows that the fundamental LSTM ideas remain powerful when enhanced appropriately:

- Exponential gating plus normalization and stabilization gives a principled, numerically stable way to revise stored content over time and to weigh contributions multiplicatively.

- Adding a matrix-style covariance memory (mLSTM) provides much larger storage capacity that behaves like a fast associative memory; pairing this with normalization yields reliable retrieval.

- Combining sLSTM (for state-tracking through memory mixing) and mLSTM (for large-capacity associative memory and parallelizability) inside residual stacks creates practical architectures that are competitive with Transformers and modern SSMs on language modeling.

For practitioners, the paper suggests RNN-based architectures should not be dismissed for large-scale language tasks: with modern design choices, recurrent memories can be both expressive and competitive in scaling behavior, while offering linear complexity in sequence length and constant memory footprint. The code is available for replication and further experimentation.

If you like exploring architectural alternatives to attention, xLSTM is a concrete, well-motivated reimagining of gated recurrent memory that is worth a closer look.

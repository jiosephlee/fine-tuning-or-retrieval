\title{Blogs about the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

# The Small Data Miracle: High-Performance AI with Only a Few Examples

In the world of machine learning, tabular data—the kind you find in spreadsheets and SQL databases—is everywhere. However, training accurate models on this data typically requires thousands of labeled examples. When you only have a handful of samples, traditional models often struggle or overfit, capturing "spurious correlations" rather than actual patterns.

This is where the "small data" challenge becomes a bottleneck, especially in fields like healthcare or finance, where labeling data is expensive or difficult. A recent paper introduces **FeatLLM**, a framework that turns Large Language Models (LLMs) into expert feature engineers to solve this exact problem. By leveraging the vast prior knowledge embedded in LLMs, FeatLLM can achieve high performance in "few-shot" scenarios, often outperforming traditional models that have significantly more data to learn from.

## Shifting the Role of the LLM

Most existing attempts to use LLMs for tabular data treat the model as a black-box predictor. They serialize a row of data into a sentence and ask the LLM to predict the label. While this can work, it is computationally expensive, slow at inference time, and often fails when a table has too many columns to fit into the model's prompt window.

FeatLLM takes a fundamentally different approach. Instead of asking the LLM for a final prediction, the framework uses the LLM to perform **feature engineering**. The LLM analyzes a few examples and its own internal "common sense" to derive a set of decisive rules—criteria that determine whether a sample belongs to a specific class. Once these rules are established, they are converted into binary features, and a simple, lightweight machine learning model is used for the actual predictions. This means the LLM is only needed during the initial setup, not for every single prediction, drastically reducing latency and cost.

## How FeatLLM Works

The magic of FeatLLM lies in its structured reasoning process, which mimics how a human expert would analyze a problem. The framework guides the LLM through two primary steps:

1.  **Prior Knowledge Extraction**: The LLM first considers the task description and the features to infer general causal relationships. For example, if the task is predicting heart failure, the LLM might rely on its pre-training to know that age and blood pressure are generally significant risk factors.
2.  **Rule Deduction**: The LLM then combines this general knowledge with a few labeled examples to create specific, actionable rules. These rules are formulated as conditions (e.g., "if age $> 65$ and blood pressure is high").

To turn these natural language rules into something a computer can process, FeatLLM uses the LLM again to write a small piece of Python code. This code is executed to transform the original tabular data into binary features—essentially a series of $0$s and $1$s indicating whether a sample satisfies each rule.

## Learning from Rules

Once the rules are converted into binary features, FeatLLM uses a simple linear model to estimate the likelihood of each class. Since not all rules are equally important, the framework learns a weight $\mathbf{w}_k$ for each feature. The logit for a class $k$ is calculated as:

$$\text{logit}_k^i = \max(\mathbf{w}_k, 0) \cdot \mathbf{z}_k^i$$

Here, $\mathbf{z}_k^i$ represents the binary features for sample $i$ and class $k$. By ensuring the weights are non-negative via $\max(\mathbf{w}_k, 0)$, the model ensures that a rule satisfying a class condition only increases (or maintains) the likelihood of that class, never decreasing it. The final class probability is then determined using a softmax function:

$$\mathbf{p}^i = \text{Softmax}({[\text{logit}_{1}^i, ..., \text{logit}_{c}^i]})$$

## Robustness through Bagging and Ensembling

To handle datasets with a massive number of features and to prevent overfitting, FeatLLM employs **feature bagging and ensembling**. Instead of creating one giant prompt that might exceed the LLM's limits, the framework repeatedly selects subsets of features and samples to generate various sets of rules. 

By averaging the predictions across multiple trials, the model becomes more robust. If the LLM generates a "noisy" or incorrect rule in one trial, the correct rules from other trials compensate for it. This ensemble approach allows FeatLLM to maintain high accuracy even on datasets with over 100 attributes.

## Results: Doing More with Less

The results across 13 different tabular datasets are impressive. FeatLLM consistently outperforms or matches contemporary few-shot baselines. One of the most striking findings is that FeatLLM, using only **4 labeled shots**, can achieve performance comparable to traditional tabular baselines that require **32 shots**.

Furthermore, FeatLLM is remarkably resilient to "spurious correlations." In experiments where irrelevant columns were added to the data, FeatLLM suffered the least performance degradation. This is because the model relies on prior knowledge to decide which features are actually meaningful, effectively ignoring the noise that often tricks traditional machine learning models.

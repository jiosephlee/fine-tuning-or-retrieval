\title{Blogs about the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

# Taming the Table: Overcoming Prompt Limits and Noisy Data

Tabular learning is a cornerstone of real-world AI applications, from healthcare diagnostics to financial risk assessment. While Large Language Models (LLMs) possess immense prior knowledge that could benefit these tasks, applying them directly to tabular data is challenging. Traditional end-to-end approaches—where a model processes every single sample via an LLM—are computationally expensive and often crash when faced with "wide" tables that exceed the LLM's context window.

To solve these issues, a new framework called $\textsf{FeatLLM}$ shifts the role of the LLM. Instead of acting as the final predictor, the LLM serves as an automated feature engineer. It identifies the "criteria" or rules that distinguish different classes and generates a set of binary features. These features are then fed into a simple downstream machine learning model, drastically reducing inference latency and overcoming the limitations of prompt size.

## Handling Massive Tables via Bagging and Ensembling

One of the primary hurdles in LLM-based tabular learning is the context window. When a dataset contains hundreds of attributes, serializing that data into a text prompt often exceeds the maximum token limit or causes a decline in model performance. $\textsf{FeatLLM}$ addresses this through a combination of feature bagging and ensembling.

Instead of attempting to pass every feature into a single prompt, the framework employs bagging to select subsets of features and instances for each trial. By repeatedly executing the rule-generation process across multiple trials, $\textsf{FeatLLM}$ creates a diverse set of "weak learners." This approach allows the framework to handle datasets with a large number of features that would otherwise be infeasible for an LLM to process at once.

The final prediction is made by averaging the class probabilities across these trials. This ensemble method provides two key advantages: it mitigates the impact of any single incorrect rule generated by the LLM (leveraging self-consistency) and ensures that the model maintains robust performance even when no single trial could cover the entire feature set.

## Filtering Spurious Correlations with Structured Reasoning

In few-shot learning, models are prone to capturing "spurious correlations"—patterns in the data that appear predictive but are actually irrelevant noise. This is especially dangerous in tabular data where a few labeled samples might suggest a relationship between a target and a random, uninformative column.

$\textsf{FeatLLM}$ combats this by guiding the LLM through a structured, two-step reasoning process:

1.  **Prior Knowledge Extraction:** The LLM is first asked to infer the causal relationship or general tendency between features and the target based solely on its internal prior knowledge, without looking at the provided examples.
2.  **Rule Deduction:** Only after establishing this general understanding does the LLM use the few-shot examples to deduce specific, decisive rules for each class.

By forcing the model to rely on common sense and domain knowledge first, the framework filters out uninformative features. Experimental results demonstrate that this method is significantly more robust against noise; when irrelevant columns were intentionally added to a dataset, $\textsf{FeatLLM}$ showed the least performance degradation compared to other baselines, as the LLM refused to generate rules based on those irrelevant columns.

## From Natural Language Rules to Class Likelihood

Once the LLM generates rules in natural language, they must be converted into a format a machine learning model can use. $\textsf{FeatLLM}$ leverages the LLM again to parse these noisy text rules into executable Python code, creating binary features $\mathbf{z}_k^i \in \{0, 1\}^R$ for each sample $\mathbf{x}^i$ and class $k$.

To estimate the final class likelihood, the framework uses a linear model without bias. The logit for a class is computed as:

$$\text{logit}_k^i = \max(\mathbf{w}_k, 0) \cdot \mathbf{z}_k^i$$

The weights $\mathbf{w}_k$ are trained using a few-shot set to determine the importance of each rule. By projecting these weights into a positive subspace using the $\max(\cdot, 0)$ function, the framework ensures that the features generated by the LLM only increase (or maintain) the likelihood of a class, preventing the model from incorrectly penalizing a class based on a generated rule. The final probability $\mathbf{p}^i$ is then derived via a $\text{Softmax}$ operation across all classes.

By decoupling feature engineering from inference, $\textsf{FeatLLM}$ provides a path toward high-performance, data-efficient tabular learning that is both computationally sustainable and robust to the noise of real-world data.

\title{Blogs about the Paper: "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning"}

# Cutting the AI Bill: How FeatLLM Solves the Cost and Latency of LLM Inference

For practitioners working with tabular data, integrating Large Language Models (LLMs) often presents a daunting trade-off. On one hand, LLMs possess immense prior knowledge that can significantly boost performance in few-shot learning scenarios. On the other hand, the standard "end-to-end" approach—where every single row of data is serialized into text and sent as a prompt to an LLM—is computationally expensive, slow, and often hits context window limits.

The research paper "Large Language Models Can Automatically Engineer Features for Few-Shot Tabular Learning" introduces **FeatLLM**, a framework that fundamentally changes this workflow. Instead of using the LLM as a predictor, FeatLLM uses the LLM as an automated feature engineer.

## The Shift: From Prediction to Feature Engineering

Most existing LLM-based tabular learners treat the model as a black box: you input a sample, and the model outputs a prediction. This requires at least one API call per sample during inference, leading to high latency and soaring costs.

FeatLLM shifts the LLM's role. It asks the LLM to identify the "criteria" or rules that define a class based on its prior knowledge and a few provided examples. Once these rules are generated, they are converted into binary features. At inference time, you no longer need the LLM; you simply use a lightweight machine learning model to process these binary features.

## How FeatLLM Works

The FeatLLM pipeline consists of three primary stages: rule extraction, parsing, and likelihood inference.

### 1. Rule Extraction via Structured Reasoning
To ensure the LLM generates high-quality rules, FeatLLM employs a two-step reasoning process. First, the LLM is prompted to infer the general causal relationship between features and the target task using its internal prior knowledge. Second, it uses a few-shot example set and the insights from the first step to deduce specific, decisive rules for each class. This structured approach prevents the model from latching onto spurious correlations in irrelevant columns.

### 2. Parsing Rules into Code
Because LLMs generate rules in natural language, they can be noisy or syntactically inconsistent. FeatLLM solves this by using the LLM again to translate these natural language rules into executable Python code. This code is then run using Python's `exec()` function to transform the raw tabular data into a set of binary features, $\mathbf{z}_k^i \in \{0, 1\}^R$, where $R$ is the number of rules per class.

### 3. Inferring Class Likelihood
With the binary features created, the framework uses a simple linear model to estimate the probability of a sample belonging to a class. The logit for class $k$ is calculated as:

$$\text{logit}_k^i = \max(\mathbf{w}_k, 0) \cdot \mathbf{z}_k^i$$

The weights $\mathbf{w}_k$ are trained using a small number of labeled samples to determine the importance of each rule. By projecting these weights into a positive subspace ($\max(\mathbf{w}_k, 0)$), the model ensures that a rule can only increase (or leave neutral) the likelihood of a class, never decrease it. The final class probabilities are then derived via a Softmax function.

## Overcoming Prompt Limits with Bagging and Ensembles

A common failure point for LLMs in tabular learning is the "lost in the middle" phenomenon or simply exceeding the token limit when a dataset has hundreds of features. FeatLLM addresses this by implementing feature bagging and ensembling.

By randomly selecting subsets of features or instances for different trials, the framework keeps prompt sizes manageable. It then averages the predictions from multiple trained models. This not only mitigates prompt size constraints but also increases robustness; if the LLM generates a faulty rule in one trial, the correct rules from other trials compensate for it.

## Real-World Impact: Cost and Performance

The results across 13 diverse datasets demonstrate that FeatLLM is not just more efficient, but often more accurate. Notably, FeatLLM using only 4 shots can achieve performance comparable to conventional tabular baselines that require 32 shots.

From a practitioner's perspective, the efficiency gains are the most striking. In tests on the "Adult" dataset, FeatLLM's inference time was comparable to traditional ML methods (like Logistic Regression or Random Forest), whereas other LLM-based approaches suffered from massive latency. By eliminating the need for per-sample API queries during deployment, FeatLLM makes the power of LLM prior knowledge viable for production environments where latency and budget are critical constraints.

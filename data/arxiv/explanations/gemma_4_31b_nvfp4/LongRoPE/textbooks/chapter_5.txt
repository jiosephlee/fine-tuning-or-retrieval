\title{A Textbook about the Paper: "LongRoPE: Extending LLM Context Window Beyond 2 Million Tokens"}

Chapter 5: Evolutionary Search for Optimal RoPE Factors

# Problem formulation: Minimizing perplexity via search

In the effort to extend the context window of Large Language Models (LLMs), the primary challenge is to maintain the model's ability to distinguish token positions without introducing catastrophic out-of-distribution values. LongRoPE addresses this by optimizing the Rotary Positional Embedding (RoPE). To do this, the researchers frame the task of finding the best positional interpolation as an optimization problem where the objective is to minimize the next-token prediction loss, denoted as $\mathcal{L}$ (which manifests as perplexity), for a set of lengthy input documents $\mathbf{X}$.

The core of this formulation is the introduction of rescale factors that account for two specific forms of non-uniformity: the RoPE dimensions and the token positions. The original rotary angle for the $i^{th}$ dimension at token position $n$ is represented as $\frac{n}{\beta^i}$. To adapt this for a larger context window $L'$, LongRoPE introduces a rescale function $\mathbb{I}(\hat{\lambda}_{i}, \hat{n})$. This function is designed as a piecewise operator: for the initial tokens where $n < \hat{n}$, the rescale factor is $1$, meaning the original RoPE rotary angle $\frac{n}{\beta^i}$ is preserved. For all tokens at positions $n \ge \hat{n}$, the angle is rescaled by $\hat{\lambda}_{i}$.

By searching for the optimal set of these factors across all dimensions $i$ from $0$ to $d/2-1$, the model can identify a configuration that minimizes the loss $\mathcal{L}$. The intuition here is that not all dimensions of the positional embedding are equally important, and not all token positions require the same amount of "squeezing" or interpolation to fit into the model's pre-trained understanding of distance.

# Defining the search space: Rescale factors ($\lambda$) and position thresholds ($n$)

The search space for LongRoPE is designed to be comprehensive enough to capture subtle non-uniformities while remaining computationally tractable. This space is defined by two primary variables: the rescale factors $\lambda_i$ for each dimension and the token position threshold $\hat{n}$. For simplicity in the search process, the researchers search for $\lambda_i$ and $\hat{n}$ directly, where the actual rescale factor applied to the angle is $\hat{\lambda}_{i} = 1/\lambda_i$.

The rescale factor $\lambda_i$ for each dimension is allowed to vary between a minimum of $1.0$, which represents direct extrapolation (no interpolation), and a maximum of $s \times 1.25$, where $s$ is the target context window extension ratio. This upper bound allows the search to explore solutions that apply more interpolation than the standard Position Interpolation (PI) method. The search proceeds with a step size of $0.01$. Simultaneously, the threshold $\hat{n}$ is searched from a discrete set of values, including $\{0, 1, 2, 4, 8, 12, 16, 20, 24, 28, 32, 64, 128, 256\}$. When $\hat{n}$ is set to $0$, it implies that every token position in the sequence is subject to the searched rescale factors.

The sheer scale of this search space is immense. For an extension ratio of $s=4\times$, the number of possible combinations of $\lambda_i$ and $\hat{n}$ reaches approximately $4 \times 10^{167}$. Because it is impossible to evaluate every possible combination through brute force, a more sophisticated discovery mechanism—evolutionary search—is required to navigate this landscape and find the most effective parameters.

# The Evolutionary Search Algorithm: Mutation and Crossover

To efficiently explore the vast search space, LongRoPE employs an evolutionary search algorithm. The process begins with a population of $P$ individuals, where each individual represents a potential set of rescale factors and a position threshold. The algorithm operates iteratively over a fixed number of generations $\mathcal{T}$. In each iteration, the perplexity of the LLM is computed for each individual in the population using sample data, and the top-$k$ individuals with the lowest perplexity are selected to serve as parents for the next generation.

The algorithm generates new candidate solutions through two primary genetic operators: mutation and crossover. Mutation involves randomly altering the rescale factors of a parent individual with a certain probability $p$. This allows the search to "jump" to different areas of the solution space, potentially discovering better configurations that were not present in the initial population. Crossover, on the other hand, combines elements from two parent individuals to create offspring, effectively blending successful traits from different high-performing candidates.

The new population for the next generation is formed by the union of the mutated individuals, the crossover individuals, and the original top-$k$ parents. This ensures that the best-known solutions are always preserved while the algorithm continues to iterate toward an even lower perplexity. This evolutionary cycle repeats until the maximum number of iterations $\mathcal{T}$ is reached, at which point the individual with the absolute lowest perplexity is returned as the optimal RoPE configuration.

# Optimization techniques: Optimized initial population and Monotonically non-decreasing constraints

Given the extreme size of the search space, a purely random initialization would be highly inefficient. LongRoPE introduces two key optimization techniques to accelerate the search and ensure convergence toward high-quality solutions. The first is the use of an optimized initial population. Instead of randomizing all individuals, the algorithm explicitly includes the rescale factors corresponding to established methods: Position Interpolation (PI), Neural Tangent Kernel (NTK), and YaRN. The remaining population members are then created by randomly mutating these three known baselines. By seeding the population with existing "best practices," the algorithm starts from a region of the search space that is already reasonably performant.

The second optimization is the imposition of a monotonically non-decreasing constraint on the rescale factors. This constraint requires that $\lambda_i \le \lambda_{i+1}$, meaning that the rescale factor must increase (or stay the same) as the RoPE dimension $i$ increases. This design is grounded in NTK theory, which suggests that lower dimensions, which correspond to higher frequencies, require less interpolation to preserve critical positional information. Conversely, higher dimensions with lower frequencies can tolerate more interpolation.

This monotonicity constraint is a powerful pruning tool. Any candidate solution generated via mutation or crossover that violates this rule is immediately discarded without being passed to the LLM for perplexity evaluation. This significantly reduces the number of expensive inference passes required, as the algorithm only spends computational resources on candidates that align with the theoretical intuition of how RoPE dimensions behave.

# Evaluating candidates using perplexity on sample datasets

The fitness of each candidate in the evolutionary search is determined by measuring the model's perplexity on specific sample datasets. Perplexity serves as a proxy for how well the model has "absorbed" the new positional embeddings; a lower perplexity indicates that the model is better at predicting the next token in a long sequence, suggesting that the positional interpolation is effectively preserving information.

For target context windows up to $256\text{k}$, the search is guided by perplexity calculated using five random samples from the PG19 validation set. For extremely long contexts exceeding $512\text{k}$, the researchers use three random samples from the Pile-Books3 validation set. A critical requirement for these evaluation samples is that their token length must be at least as long as the target context window $L'$. This ensures that the search algorithm is optimizing for the actual extended length rather than a shorter sequence where interpolation errors might be less apparent.

In the evaluation process, the LLM is updated with the candidate's rescaled RoPE factors, and the perplexity is computed over the sample documents. This feedback loop allows the evolutionary algorithm to quantitatively determine which combinations of $\lambda_i$ and $\hat{n}$ provide the best initialization for subsequent fine-tuning or the best performance in non-fine-tuning scenarios.

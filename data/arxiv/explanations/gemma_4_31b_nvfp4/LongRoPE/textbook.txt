\title{A Textbook about the Paper: "LongRoPE: Extending LLM Context Window Beyond 2 Million Tokens"}

Introduction to LLM Context Windows

# Definition of the Context Window

In the field of Large Language Models (LLMs), the context window refers to the maximum number of tokens that a model can process in a single forward pass. This limit defines the span of text the model can "see" and consider simultaneously when predicting the next token in a sequence. For example, the LLaMA2 model has a default context window limit of $4096$ tokens. This means that any information provided beyond this threshold is effectively invisible to the model, as it cannot incorporate tokens that exceed the boundaries of its trained positional encoding.

The context window is fundamentally tied to how a model handles positional information. Because Transformer architectures do not inherently understand the order of tokens, they rely on positional embeddings—such as Rotary Positional Embedding (RoPE)—to assign a specific index to each token. When a model is pre-trained, it learns to associate specific patterns of information with these indices. Once the input sequence exceeds the pre-trained limit, the model encounters position indices it has never seen before, which leads to a rapid decline in the model's ability to maintain coherence and accuracy.

# The impact of context window size on LLM performance

The size of the context window serves as a critical bottleneck for the utility of LLMs in complex, real-world applications. A limited context window restricts the model's ability to engage in sophisticated in-context learning, particularly when the task requires numerous examples to guide the model toward a correct answer. If the number of examples provided in the prompt exceeds the token limit, the model cannot utilize all available information, thereby reducing its performance.

Beyond simple prompting, the context window is a limiting factor for the development of LLM agents. Agents often need to maintain long-term memory, track state across multiple turns of interaction, or process vast amounts of documentation to execute a specific goal. When the context window is too small, the agent "forgets" earlier parts of the conversation or fails to retrieve critical details from a long document, which fundamentally hinders its ability to perform autonomous, multi-step reasoning.

# Challenges in extension: Catastrophic values and out-of-distribution issues

Extending a context window is not as simple as merely increasing a numerical limit; it introduces significant stability issues. When a model is asked to process tokens at positions far beyond its original training range, it encounters "catastrophic values." These are extreme or unstable activations that arise because the model is operating on position indices that were never encountered during the pre-training phase. These values act as noise, disrupting the model's internal representations and leading to a breakdown in language modeling capabilities.

This phenomenon is a classic example of an out-of-distribution (OOD) issue. Because the model was trained on a specific distribution of position indices (e.g., from $0$ to $4095$), indices such as $100,000$ or $1,000,000$ are entirely foreign. In scenarios where a model is extended from $4\text{k}$ to over $1000\text{k}$ tokens, more than $90\%$ of the position indices in the new window are unseen. This massive gap makes it incredibly difficult for the model to converge during fine-tuning, as the training process must struggle to stabilize these OOD values while simultaneously trying to learn long-range dependencies.

# The scarcity and cost of long-form training data

To successfully extend a context window through fine-tuning, a model generally requires training data that matches the target length. If a developer intends to extend a model to a $1000\text{k}$ token window, they ideally need datasets containing documents of that length. However, such long-form texts are remarkably scarce in existing datasets, creating a data bottleneck that limits the feasibility of extending context windows through standard fine-tuning.

Even when the data is available, the computational cost of training on extra-long sequences is prohibitively high. The resources required for training—measured in both GPU hours and memory—scale aggressively with the sequence length. Processing millions of tokens per sample requires immense computational power, making it difficult for many researchers to achieve large-scale extensions without highly optimized strategies. This economic and technical barrier has historically limited the practical extension of context windows to around $128\text{k}$ tokens.

# The trade-off between long-context extension and short-context performance

A significant challenge in extending LLMs is the tension between the ability to handle extremely long sequences and the ability to maintain performance on shorter, original sequences. As the context window is extended to extremely large sizes, a phenomenon occurs where the attention mechanism becomes "dispersed." In a standard Transformer, attention is spread across the input tokens; however, when the window grows to millions of tokens, the attention is spread too thinly across an enormous number of positions.

This dispersion leads to a degradation in performance when the model is used for tasks that fall within its original short context window. For instance, a model extended to a $2048\text{k}$ window may struggle with a simple $4\text{k}$ token task because the positional embeddings for those early tokens have become "crowded" or shifted due to the interpolation required to accommodate the larger window. This creates a trade-off: while the model gains the ability to process massive documents, it may lose the precision and accuracy it once had for shorter, more concise inputs.

# Foundations of Rotary Positional Embeddings (RoPE)

# The need for positional information in Transformers

The Transformer architecture, which serves as the backbone for modern Large Language Models (LLMs), processes input tokens in a highly parallelized manner. Unlike recurrent neural networks that process tokens sequentially, the attention mechanism within a Transformer treats the input as a set of tokens rather than a sequence. Consequently, the model possesses no inherent way of knowing the relative or absolute order of the tokens in a given sentence. Without a mechanism to represent the position of each token, the model would be unable to distinguish between a sentence and a random permutation of the same words, which would render it incapable of understanding syntax, grammar, or the contextual meaning of a document.

To resolve this, Transformer models require explicit positional information. This is typically achieved through position embeddings, which are added to or integrated with the token embeddings to provide the model with a signal indicating where each token is located within the sequence. By incorporating these embeddings, the model can maintain the spatial structure of the text and understand the importance of token order during the encoding and decoding processes.

# Mechanism of Rotary Positional Embeddings (RoPE)

Rotary Positional Embeddings, commonly referred to as RoPE, are a sophisticated method of encoding position used in prominent models such as LLaMA and Mistral. Unlike traditional positional embeddings that might simply add a vector to the token representation, RoPE encodes positional information by rotating the embedding in a multidimensional space. This approach allows the model to capture relative positional information through the rotation of vectors.

For a token located at position index $n$, the RoPE encoding can be expressed as a sequence of cosine and sine functions. Specifically, the encoding is simplified as:
$$\left[ \cos(n\theta_0), \sin(n\theta_0), \cos(n\theta_1), \dots, \cos(n\theta_{d/2-1}), \sin(n\theta_{d/2-1}) \right]$$
In this formulation, $d$ represents the embedding dimension of the model. The encoding consists of pairs of cosine and sine values, where each pair corresponds to a specific dimension of the embedding. By applying these trigonometric functions to the position index $n$, the model effectively maps each position to a unique point on a unit circle in various dimensions.

# Understanding rotation frequencies and angles

The core of the RoPE mechanism lies in the relationship between the position index $n$ and the rotation frequencies $\theta_i$. The term $n\theta_i$ is defined as the rotary angle of the token at position $n$. These angles determine how much the embedding vector is "rotated" for a given position.

The rotation frequencies $\theta_i$ are not uniform across all dimensions. Instead, they are calculated using the formula:
$$\theta_i = \theta^{-2i/d}$$
where $i$ ranges from $0$ to $d/2-1$. This design ensures that different dimensions of the embedding rotate at different frequencies. Lower dimensions (where $i$ is small) correspond to higher frequencies, while higher dimensions (where $i$ is larger) correspond to lower frequencies. This variation in frequency allows the model to capture both fine-grained local positional relationships and broader, long-range dependencies across the text.

# The role of the base value (e.g., 10,000) in RoPE

In the calculation of the rotation frequencies $\theta_i = \theta^{-2i/d}$, the variable $\theta$ represents the base value. In standard implementations of RoPE, the default base value is set to $10,000$. This base value is critical because it determines the range and the decay of the frequencies across the embedding dimensions.

By using a large base value like $10,000$, the rotation frequencies decrease exponentially as the dimension index $i$ increases. This creates a spectrum of frequencies that allows the model to maintain a distinct representation of positions over a wide range. If the base value were significantly smaller, the frequencies would collapse more quickly, potentially making it harder for the model to distinguish between tokens that are far apart. The base value essentially defines the "scale" of the positional encoding, ensuring that the rotary angles provide a unique and stable signature for each token position within the model's original context window.

# RoPE in the context of the attention mechanism

The ultimate purpose of RoPE is to inform the attention mechanism about the distance and order between tokens. In a Transformer, the attention score between two tokens is typically computed via a dot product of their query and key vectors. When RoPE is applied, the dot product becomes dependent on the relative distance between the two tokens, as the rotation of the vectors preserves the relative angle between them.

However, challenges arise when a model needs to handle sequences longer than the window it was trained on. When the position index $n$ exceeds the original training limit, the model encounters "untrained" positions. To mitigate this, researchers use positional interpolation, which involves downscaling the rotation frequencies $\theta_i$ by an extension ratio $s$. For example, in Linear Positional Interpolation (PI), the rotation angles are linearly reduced to fit the new, longer sequence into the original range. This prevents the model from encountering catastrophic values associated with out-of-distribution position indices, though it can lead to "crowded" positions where the model struggles to distinguish between closely positioned tokens. Other methods, such as NTK-based interpolation or YaRN, attempt to refine this by applying non-uniform interpolation across different RoPE dimensions to better preserve positional information.

Existing Positional Interpolation Techniques

To understand the mechanisms used to extend the context window of Large Language Models (LLMs), it is first necessary to understand the baseline technology: Rotary Positional Embedding, or RoPE. In a Transformer architecture, models require explicit positional information to understand the order of input tokens. RoPE achieves this by representing a token at position index $n$ as a series of rotary angles. Specifically, the encoding is a vector consisting of $\cos(n\theta_0), \sin(n\theta_0), \dots, \cos(n\theta_{d/2-1}), \sin(n\theta_{d/2-1})$, where $d$ is the embedding dimension and $\theta_i = \theta^{-2i/d}$ represents the rotation frequencies. In most standard implementations, the default base value of $\theta$ is $10000$. When we wish to extend the context window from an original length $L$ to a target length $L'$, we define the context window extension ratio as $s = \frac{L'}{L}$.

# Linear Position Interpolation (PI)

Linear Position Interpolation, commonly referred to as PI, is one of the foundational methods for extending context windows. The core intuition behind PI is to downscale the position indices of new tokens so that they fall within the range that the model was originally trained on. To achieve this for a target extension ratio $s$, PI linearly reduces the rotation angles of all positions by a rescale factor $\lambda = s$ across every single RoPE dimension.

While this approach allows the model to process sequences longer than its original training limit, it introduces a significant drawback. By applying the same reduction factor to every dimension, the positional information becomes overly "crowded." This means that the model's ability to distinguish between tokens that are located close to one another is diminished, as their rotary embeddings become too similar. Consequently, PI tends to underperform when the extension ratio $s$ is high, and it generally necessitates further fine-tuning to remain effective.

# NTK-aware Interpolation and Extrapolation

To address the limitations of linear interpolation, researchers developed NTK-aware methods based on Neural Tangent Kernel (NTK) theory. The fundamental intuition of NTK-aware interpolation is that not all RoPE dimensions should be treated equally. Instead of applying a uniform scale across the entire embedding, NTK-aware methods distribute the "interpolation pressure" across different dimensions based on their frequency.

Specifically, these methods scale the lower dimensions—which correspond to high frequencies—less, while scaling the higher dimensions—which correspond to low frequencies—more. This results in a hybrid approach that combines both positional interpolation and extrapolation, where the rescale factor is defined as $\lambda = s^i$. A further refinement, known as dynamic NTK, allows the model to adjust the extension ratio at each position based on the current length of the sequence. One of the primary advantages of NTK-aware methods is that they can extend the context window in non-fine-tuning scenarios, although they are typically limited to a maximum extension ratio of approximately $4\times$.

# YaRN (Yet Another RoPE extensioN) and frequency-based grouping

YaRN further evolves the concept of non-linear interpolation by introducing frequency-based grouping. Rather than using a single formula for all dimensions, YaRN categorizes RoPE dimensions into three distinct groups based on their frequency, applying a different strategy to each. High-frequency dimensions undergo extrapolation, meaning $\lambda = 1$ and the original frequencies are preserved. Low-frequency dimensions use linear interpolation, as seen in PI. The dimensions that fall between these two extremes employ the NTK-aware approach.

By partitioning the dimensions this way, YaRN attempts to balance the need for precise local positioning (high frequency) with the need to accommodate a much larger global context (low frequency). However, a significant limitation of YaRN is that the specific grouping of these dimensions is based on human-led empirical experiments. This dependency on manual design means the strategy may be sub-optimal when applied to different or newer LLM architectures, as the optimal grouping may vary.

# Comparative analysis: Linear vs. Non-linear interpolation

When comparing linear and non-linear interpolation, the primary difference lies in how they handle the relationship between frequency and position. Linear interpolation (PI) is uniform; it treats every dimension of the rotary embedding with the same rescale factor. This uniformity is simple to implement but ignores the fact that different dimensions of the RoPE embedding carry different types of information and operate at different frequencies.

Non-linear methods, such as NTK and YaRN, recognize that lower dimensions with higher frequencies are more critical for distinguishing nearby tokens and should therefore be interpolated less. Higher dimensions with lower frequencies are more suited for broad positional tracking and can handle more interpolation. Despite these improvements, the current non-linear methods still rely on human-designed rules. As discovered in the analysis of LongRoPE, positional embeddings actually exhibit complex non-uniform information entropy. This means that the optimal rescale factors are not just based on simple groups or power laws, but may vary in more subtle, non-uniform ways across both RoPE dimensions and token positions.

# The 'crowded positions' problem in high-ratio interpolation

The "crowded positions" problem is a critical failure mode that occurs when the extension ratio $s$ becomes very large. In a linear interpolation setting, if we extend a model by a factor of $512\times$, the position embeddings for the original 4k context window are forced into a much narrower region of the embedding space. Because the rotation angles are compressed so aggressively, the difference between the embedding of position $n$ and position $n+1$ becomes nearly negligible.

This crowding leads to a severe loss of information, as the model can no longer effectively resolve the relative distance between tokens. This manifests as a performance drop within the original short context window; a model extended to 2 million tokens might actually perform worse on a 4k sequence than it did before the extension. To mitigate this, it is necessary to reduce the amount of interpolation applied to the initial tokens of a sequence and to specifically readjust the rescale factors for shorter context lengths to ensure that the positions do not become too crowded.

# The Theory of Non-Uniformity in Interpolation

To understand how large language models (LLMs) can be extended to handle millions of tokens, one must first understand the mechanism of positional embeddings. Transformer models are inherently permutation-invariant, meaning they do not naturally understand the order of tokens in a sequence. To resolve this, models like LLaMA2 and Mistral utilize Rotary Positional Embeddings (RoPE). In a simplified form, for a token at position index $n$, the RoPE encoding consists of a series of cosine and sine pairs: $\left[ \cos(n\theta_0), \sin(n\theta_0), \cos(n\theta_1), \dots, \cos(n\theta_{d/2-1}), \sin(n\theta_{d/2-1}) \right]$, where $d$ is the embedding dimension and $\theta_i = \theta^{-2i/d}$ represents the rotation frequencies.

When the goal is to extend the context window from an original length $L$ to a larger length $L'$, we define the extension ratio as $s = \frac{L'}{L}$. The most straightforward approach to this extension is Position Interpolation (PI), which linearly reduces the rotation angles across all dimensions by a factor of $\lambda = s$. However, this linear approach creates a "crowding" effect where position information becomes too dense, hindering the model's ability to distinguish between tokens that are close to one another. This suggests that the most effective way to extend a context window is not through uniform scaling, but by exploiting the non-uniformities inherent in how the model processes positional information.

# Non-uniformity across RoPE dimensions: High vs. Low frequency

The first major insight into non-uniformity concerns the different dimensions of the RoPE embedding. RoPE dimensions are not created equal; they operate at different frequencies. Lower dimensions (where $i$ is small) correspond to higher frequencies, while higher dimensions (where $i$ is large) correspond to lower frequencies. Previous attempts to handle this, such as NTK-based interpolation, suggested that interpolation pressure should be distributed unevenly across these dimensions. Specifically, high-frequency dimensions should be scaled less, and low-frequency dimensions should be scaled more.

Linear Position Interpolation (PI) fails because it applies the same rescale factor $\lambda = s$ to every dimension, regardless of its frequency. More advanced methods like YaRN attempted to address this by grouping dimensions into three categories—extrapolation, NTK-based interpolation, and linear interpolation—based on their frequency. However, these groupings are often based on human-led empirical experiments and may be sub-optimal. The theory of non-uniformity posits that there is a more precise, non-linear relationship between the dimension index $i$ and the optimal rescale factor $\lambda_i$. By allowing each dimension to have its own specific rescale factor, the model can better preserve the original structural information of the RoPE embedding, which is critical for maintaining performance during context extension.

# Non-uniformity across token positions: The importance of initial tokens

Beyond the variance across dimensions, there is a significant non-uniformity across the positions of the tokens within a sequence. It is hypothesized that the initial tokens in an input sequence are more critical to the attention mechanism than tokens appearing later in the sequence. This is consistent with observations in other architectural studies, such as Streaming LLM, which suggest that the "attention sinks" at the beginning of a sequence receive disproportionately large attention scores.

Because these initial tokens are so vital, applying positional interpolation to them can be detrimental. If the first few tokens are interpolated (downscaled), the model may lose the precise positional grounding it relies on to stabilize the attention layers. To mitigate this, LongRoPE introduces a token position threshold, denoted as $\hat{n}$. For tokens at positions $n < \hat{n}$, the original RoPE rotary angles are used without any interpolation. For tokens at positions $n \ge \hat{n}$, the searched rescale factors are applied. This ensures that the most important part of the sequence—the beginning—remains untouched by the interpolation process, thereby reducing the loss of information and improving the model's stability.

# Empirical evidence for non-uniformity in LLaMA2

The effectiveness of non-uniform interpolation is not merely theoretical; it has been demonstrated through empirical analysis using LLaMA2-7B. By using an evolutionary search algorithm to find the optimal rescale factors $\lambda_i$ and the optimal threshold $\hat{n}$, researchers compared the resulting perplexity on datasets like PG19 and Proof-pile against standard methods like PI and YaRN.

The evidence shows that when non-uniform factors are used, the model's perplexity is significantly lower, meaning the model is much better at predicting the next token in a long sequence. For instance, without any fine-tuning, the non-uniform approach allowed LLaMA2 to extend its context window from 4k to 32k while maintaining stability. In contrast, traditional methods like PI and YaRN saw perplexity spike rapidly after only a $2\times$ extension. This empirical gap proves that the "human-designed rules" used in previous interpolation methods are sub-optimal and that a data-driven, non-uniform search can uncover a far more effective configuration for the positional embeddings.

# Information entropy in positional embeddings

The core reason why non-uniformity works lies in the complex non-uniform information entropy of the Transformer architecture. Positional embeddings are not just markers of order; they are high-dimensional vectors that the model uses to determine the relationship between tokens. When we use uniform linear interpolation, we essentially "compress" the positional space. This compression leads to a loss of information entropy, as the distinct "signatures" of different positions start to overlap or become too similar.

By utilizing non-uniform positional interpolation, the model can preserve "key dimensions" and "key positions." By scaling different dimensions differently, the model retains a higher degree of entropy in the dimensions that are most critical for distinguishing token positions. This minimizes the information loss caused by the extension process. This preservation of information is particularly crucial for the initialization of fine-tuning; because the non-uniform initialization is closer to the original pre-trained distribution than a linear interpolation, the model converges more easily and avoids the "catastrophic values" that typically occur when a model encounters previously unseen position indices.

# Hypothesizing the optimal rescale factors

To find the optimal non-uniform configuration, the problem is framed as a search for the best set of rescale factors $\mathbb{I}(\hat{\lambda}_{i}, \hat{n})$. The rescale factor for the $i^{th}$ dimension is defined as $1$ if $n < \hat{n}$, and $1/\lambda_i$ if $n \ge \hat{n}$. The search space for $\lambda_i$ ranges from $1.0$ (which represents direct extrapolation) to $s \times 1.25$ (which is a slightly more aggressive interpolation than PI). The threshold $\hat{n}$ is searched across a discrete set of values, such as $\{0, 1, 2, \dots, 256\}$.

A key hypothesis guiding this search is the monotonically non-decreasing constraint: $\lambda_i \le \lambda_{i+1}$. This constraint is grounded in NTK theory, which suggests that lower dimensions (high frequency) require less interpolation (smaller $\lambda_i$) and higher dimensions (low frequency) can tolerate more interpolation (larger $\lambda_i$). By imposing this constraint, the search algorithm can avoid poor solutions and efficiently narrow down the parameters that minimize next-token prediction loss. The resulting set of factors allows the model to stretch its context window to an extreme degree—up to 2048k tokens—without collapsing the positional information that the model learned during its initial training.

Evolutionary Search for Optimal RoPE Factors

# Problem formulation: Minimizing perplexity via search

In the effort to extend the context window of Large Language Models (LLMs), the primary challenge is to maintain the model's ability to distinguish token positions without introducing catastrophic out-of-distribution values. LongRoPE addresses this by optimizing the Rotary Positional Embedding (RoPE). To do this, the researchers frame the task of finding the best positional interpolation as an optimization problem where the objective is to minimize the next-token prediction loss, denoted as $\mathcal{L}$ (which manifests as perplexity), for a set of lengthy input documents $\mathbf{X}$.

The core of this formulation is the introduction of rescale factors that account for two specific forms of non-uniformity: the RoPE dimensions and the token positions. The original rotary angle for the $i^{th}$ dimension at token position $n$ is represented as $\frac{n}{\beta^i}$. To adapt this for a larger context window $L'$, LongRoPE introduces a rescale function $\mathbb{I}(\hat{\lambda}_{i}, \hat{n})$. This function is designed as a piecewise operator: for the initial tokens where $n < \hat{n}$, the rescale factor is $1$, meaning the original RoPE rotary angle $\frac{n}{\beta^i}$ is preserved. For all tokens at positions $n \ge \hat{n}$, the angle is rescaled by $\hat{\lambda}_{i}$.

By searching for the optimal set of these factors across all dimensions $i$ from $0$ to $d/2-1$, the model can identify a configuration that minimizes the loss $\mathcal{L}$. The intuition here is that not all dimensions of the positional embedding are equally important, and not all token positions require the same amount of "squeezing" or interpolation to fit into the model's pre-trained understanding of distance.

# Defining the search space: Rescale factors ($\lambda$) and position thresholds ($n$)

The search space for LongRoPE is designed to be comprehensive enough to capture subtle non-uniformities while remaining computationally tractable. This space is defined by two primary variables: the rescale factors $\lambda_i$ for each dimension and the token position threshold $\hat{n}$. For simplicity in the search process, the researchers search for $\lambda_i$ and $\hat{n}$ directly, where the actual rescale factor applied to the angle is $\hat{\lambda}_{i} = 1/\lambda_i$.

The rescale factor $\lambda_i$ for each dimension is allowed to vary between a minimum of $1.0$, which represents direct extrapolation (no interpolation), and a maximum of $s \times 1.25$, where $s$ is the target context window extension ratio. This upper bound allows the search to explore solutions that apply more interpolation than the standard Position Interpolation (PI) method. The search proceeds with a step size of $0.01$. Simultaneously, the threshold $\hat{n}$ is searched from a discrete set of values, including $\{0, 1, 2, 4, 8, 12, 16, 20, 24, 28, 32, 64, 128, 256\}$. When $\hat{n}$ is set to $0$, it implies that every token position in the sequence is subject to the searched rescale factors.

The sheer scale of this search space is immense. For an extension ratio of $s=4\times$, the number of possible combinations of $\lambda_i$ and $\hat{n}$ reaches approximately $4 \times 10^{167}$. Because it is impossible to evaluate every possible combination through brute force, a more sophisticated discovery mechanism—evolutionary search—is required to navigate this landscape and find the most effective parameters.

# The Evolutionary Search Algorithm: Mutation and Crossover

To efficiently explore the vast search space, LongRoPE employs an evolutionary search algorithm. The process begins with a population of $P$ individuals, where each individual represents a potential set of rescale factors and a position threshold. The algorithm operates iteratively over a fixed number of generations $\mathcal{T}$. In each iteration, the perplexity of the LLM is computed for each individual in the population using sample data, and the top-$k$ individuals with the lowest perplexity are selected to serve as parents for the next generation.

The algorithm generates new candidate solutions through two primary genetic operators: mutation and crossover. Mutation involves randomly altering the rescale factors of a parent individual with a certain probability $p$. This allows the search to "jump" to different areas of the solution space, potentially discovering better configurations that were not present in the initial population. Crossover, on the other hand, combines elements from two parent individuals to create offspring, effectively blending successful traits from different high-performing candidates.

The new population for the next generation is formed by the union of the mutated individuals, the crossover individuals, and the original top-$k$ parents. This ensures that the best-known solutions are always preserved while the algorithm continues to iterate toward an even lower perplexity. This evolutionary cycle repeats until the maximum number of iterations $\mathcal{T}$ is reached, at which point the individual with the absolute lowest perplexity is returned as the optimal RoPE configuration.

# Optimization techniques: Optimized initial population and Monotonically non-decreasing constraints

Given the extreme size of the search space, a purely random initialization would be highly inefficient. LongRoPE introduces two key optimization techniques to accelerate the search and ensure convergence toward high-quality solutions. The first is the use of an optimized initial population. Instead of randomizing all individuals, the algorithm explicitly includes the rescale factors corresponding to established methods: Position Interpolation (PI), Neural Tangent Kernel (NTK), and YaRN. The remaining population members are then created by randomly mutating these three known baselines. By seeding the population with existing "best practices," the algorithm starts from a region of the search space that is already reasonably performant.

The second optimization is the imposition of a monotonically non-decreasing constraint on the rescale factors. This constraint requires that $\lambda_i \le \lambda_{i+1}$, meaning that the rescale factor must increase (or stay the same) as the RoPE dimension $i$ increases. This design is grounded in NTK theory, which suggests that lower dimensions, which correspond to higher frequencies, require less interpolation to preserve critical positional information. Conversely, higher dimensions with lower frequencies can tolerate more interpolation.

This monotonicity constraint is a powerful pruning tool. Any candidate solution generated via mutation or crossover that violates this rule is immediately discarded without being passed to the LLM for perplexity evaluation. This significantly reduces the number of expensive inference passes required, as the algorithm only spends computational resources on candidates that align with the theoretical intuition of how RoPE dimensions behave.

# Evaluating candidates using perplexity on sample datasets

The fitness of each candidate in the evolutionary search is determined by measuring the model's perplexity on specific sample datasets. Perplexity serves as a proxy for how well the model has "absorbed" the new positional embeddings; a lower perplexity indicates that the model is better at predicting the next token in a long sequence, suggesting that the positional interpolation is effectively preserving information.

For target context windows up to $256\text{k}$, the search is guided by perplexity calculated using five random samples from the PG19 validation set. For extremely long contexts exceeding $512\text{k}$, the researchers use three random samples from the Pile-Books3 validation set. A critical requirement for these evaluation samples is that their token length must be at least as long as the target context window $L'$. This ensures that the search algorithm is optimizing for the actual extended length rather than a shorter sequence where interpolation errors might be less apparent.

In the evaluation process, the LLM is updated with the candidate's rescaled RoPE factors, and the perplexity is computed over the sample documents. This feedback loop allows the evolutionary algorithm to quantitatively determine which combinations of $\lambda_i$ and $\hat{n}$ provide the best initialization for subsequent fine-tuning or the best performance in non-fine-tuning scenarios.

The LongRoPE Progressive Extension Strategy

# The limitations of direct fine-tuning at extreme lengths

Extending the context window of a Large Language Model (LLM) to extreme lengths, such as 2 million tokens, is not as simple as fine-tuning the model on longer sequences. There are three primary obstacles that make direct fine-tuning at such scales prohibitively difficult. First, when a model is extended from a short original context, such as the 4,096 tokens in LLaMA2, to over 1 million tokens, more than 90% of the position indices are entirely new. These untrained positions introduce "catastrophic values" into the model, leading to severe out-of-distribution issues. This instability makes it extremely difficult for the model to converge during the fine-tuning process.

Second, there is a significant scarcity of high-quality training data at extreme lengths. Texts that exceed 1 million tokens are rare in current datasets, making it nearly impossible to find enough diverse, long-form content to support stable training. Even when such data is available, the computational cost is immense. Training on extra-long sequences requires prohibitively extensive GPU resources and training hours, creating a bottleneck for most researchers and developers.

Finally, extending the context window to an extreme degree often leads to a degradation in performance on shorter sequences. This occurs because the attention mechanism becomes overly dispersed; as the attention is spread thinly across millions of token positions, the model loses its ability to focus effectively on the original short context. This phenomenon, often seen in positional interpolation, results in a loss of the precision the model once had within its native context window.

# Stage 1: Search and fine-tuning for medium extension (up to 256k)

To overcome the challenges of direct extreme extension, LongRoPE employs a progressive strategy, beginning with a medium-scale extension. The first goal is to extend the pre-trained LLM to a context window of 256k tokens. Rather than jumping directly to this length, the process begins by using an evolutionary search algorithm to find the optimal non-uniform RoPE rescale factors for target window sizes of 128k and 256k. These searched factors provide a far better initialization for fine-tuning than standard linear interpolation, as they minimize information loss by preserving key dimensions and token positions.

The fine-tuning process itself is also conducted progressively to ensure stability. For example, in the case of LLaMA2, the model is first fine-tuned for 400 steps using the rescale factors searched for a 128k context window. Once this stage is complete, the rescale factors are replaced with those searched for the 256k window, and the model undergoes an additional 600 steps of fine-tuning. This incremental approach is significantly more efficient and stable than attempting to fine-tune directly to 256k from the start, allowing the model to gradually adapt to longer sequences.

# Stage 2: Second positional interpolation for extreme extension (up to 2048k)

Once the model has been successfully fine-tuned to a 256k context window, LongRoPE leverages a unique property of its non-uniform positional interpolation to reach the final goal of 2,048k tokens. The core innovation here is that the non-uniform interpolation search is effective not only on pre-trained models but also on models that have already been extended and fine-tuned. 

Instead of conducting further expensive fine-tuning on million-token sequences, a secondary search is performed on the fine-tuned 256k-length LLM. This search identifies a new set of RoPE rescale factors specifically optimized for the 2,048k target. Because the non-uniform interpolation allows for a significant extension without further training, this secondary search enables the model to reach the 2,048k context window without any additional fine-tuning steps. In total, the model achieves a $512\times$ extension from its original 4k context window through this combined process of targeted fine-tuning and strategic interpolation.

# Integrating fine-tuning with non-fine-tuning extensions

The LongRoPE strategy is a hybrid approach that integrates the stability of fine-tuning with the flexibility of non-fine-tuning extensions. By alternating between searching for optimal rescaled factors and performing short bursts of fine-tuning, the method bypasses the need for massive datasets and immense compute. The integration follows a "search $\rightarrow$ fine-tune $\rightarrow$ search" pipeline: the first search provides a stable starting point for fine-tuning at a medium length, and the final search bridges the gap from that medium length to the extreme target.

A critical part of this integration is the recovery of performance for shorter context windows. Because extreme extension ratios (like $512\times$) cause position embeddings in higher dimensions to become "crowded" within the original context window, the model typically suffers a performance drop when processing short sequences. To resolve this, LongRoPE performs an extra evolutionary search on the final extended LLM to readjust the RoPE rescale factors specifically for short lengths, such as 4k and 8k. By reducing the maximum allowable scale factors, the model is encouraged to use less interpolation for short sequences. During inference, the LLM dynamically adjusts these factors based on the sequence length, ensuring that it maintains its original capabilities while still being able to process 2 million tokens.

# Analysis of the 8x extension capability without fine-tuning

A fundamental discovery driving the LongRoPE strategy is the ability of non-uniform positional interpolation to extend the context window by up to $8\times$ without any fine-tuning. In traditional methods like Position Interpolation (PI), Neural Tangent Kernel (NTK), or YaRN, the model's perplexity typically spikes rapidly after a $2\times$ extension, meaning the model's language modeling performance collapses. 

LongRoPE avoids this collapse by exploiting two forms of non-uniformity: varying RoPE dimensions and token positions. By searching for specialized rescale factors $\lambda_i$ for each RoPE dimension and identifying a token position threshold $\hat{n}$ below which no interpolation is applied, the method effectively preserves the original RoPE information. This preservation is especially crucial for the initial tokens of a sequence and key high-frequency dimensions. 

For instance, when extending LLaMA2 from 4k to 32k (an $8\times$ extension) without fine-tuning, LongRoPE maintains a stable perplexity, whereas baselines fail. This capability is what allows the progressive strategy to work; by fine-tuning the model to 256k and then applying an $8\times$ non-fine-tuning extension, the model can leap from 256k to 2,048k tokens without the catastrophic failure associated with traditional interpolation methods.

Maintaining Short-Context Performance

# The 'crowding' effect on original context windows

When extending the context window of a Large Language Model (LLM), a common and significant challenge is the degradation of performance on sequences that fall within the model's original training length. In the case of LongRoPE, extending the context window to an extreme length of 2048k tokens introduces a phenomenon known as the "crowding" effect. To understand this, one must consider how positional interpolation works: it downscales the rotation frequencies of the Rotary Positional Embedding (RoPE) to fit a larger number of token positions into the range the model was originally trained on. 

As the extension ratio $s$ increases—reaching as high as $512\times$ in the case of a 2048k window—the interpolation process forces the position embeddings, particularly those in higher dimensions, to reside within a much narrower region of the original embedding space. This essentially squeezes the positional representations of the tokens. For a model that was originally designed to distinguish between positions in a 4k context window, this extreme compression makes the positions within that original window appear "crowded." Consequently, the model loses its ability to effectively differentiate between closely positioned tokens, leading to a noticeable drop in language modeling performance when handling shorter sequences.

# The strategy for shorter context window recovery

To combat the performance loss caused by the crowding effect, LongRoPE does not rely on a single, static set of rescale factors for all sequence lengths. Instead, the researchers developed a recovery strategy that recognizes that the optimal positional interpolation for a 2-million-token sequence is fundamentally different from the optimal interpolation for a 4k-token sequence. The core of this strategy is to create a specialized configuration for short-context scenarios that encourages less interpolation, thereby expanding the "narrow region" and reducing the crowding of token positions.

The recovery process leverages the same evolutionary search algorithm used during the initial extension of the context window. By applying this search specifically to the extended LLM, the model can identify a new set of RoPE rescale factors tailored for short lengths. This approach allows the model to maintain the benefits of its extended context capabilities while reclaiming the precision and performance characteristics of the original short-context window.

# Searching for specialized factors for 4k and 8k lengths

The search for specialized rescale factors specifically targets lengths such as 4k and 8k. During this evolutionary search, the parameters of the search space are modified to reflect the requirements of shorter sequences. Specifically, the researchers reduce the maximum allowable value for the searched rescale factors $\lambda$. 

The intuition behind this modification is that the degree of positional interpolation required is proportional to the extension ratio. Since 4k and 8k lengths require significantly less interpolation than 2048k, limiting the maximum $\lambda$ prevents the search from applying unnecessary downscaling. This constrained search ensures that the resulting $\lambda$ values maintain a higher resolution for token positions, effectively undoing the "crowding" and restoring the model's ability to distinguish between tokens in short-to-medium length sequences.

# Dynamic adjustment of RoPE factors during inference

Once the specialized rescale factors for short context windows are discovered, they are integrated into the model's inference mechanism through a dynamic adjustment process. The model does not permanently switch from the long-context factors to the short-context factors; instead, it chooses the appropriate set of factors based on the actual length of the input sequence at runtime.

During the inference phase, the system checks the sequence length of the incoming prompt. If the sequence length is determined to be less than 8k tokens, the LLM dynamically updates its RoPE embeddings using the specialized rescale factors searched for the 4k and 8k lengths. If the sequence exceeds this threshold, the model utilizes the factors optimized for the extended context window. This dynamic switching allows a single model to be versatile, performing optimally whether it is processing a short paragraph or a massive document of millions of tokens.

# Comparing recovered performance against original baselines

The effectiveness of this recovery strategy is validated through empirical testing on language modeling and standard benchmarks. When evaluating perplexity on the Proof-pile dataset at lengths of 4k and 8k, the results demonstrate that the readjusted RoPE factors lead to a significant improvement in performance compared to the extended model without recovery. By reducing the interpolation pressure, the model's perplexity decreases, indicating a more accurate prediction of the next token.

Furthermore, this recovery process ensures that the LongRoPE-2048k models remain competitive on standard LLM benchmarks that operate within the original 4096 context window. Evaluations on tasks such as ARC-Challenge, HellaSwag, MMLU, and TruthfulQA show that the models achieve results comparable to the original baselines. In some instances, such as with the Mistral model on TruthfulQA, the recovered model even slightly outperformed the original version. This confirms that LongRoPE successfully extends the context window to an unprecedented scale without sacrificing the foundational capabilities of the original model.

Evaluation and Experimental Results

# Metrics for long-context evaluation: Perplexity vs. Task Accuracy

When evaluating Large Language Models (LLMs) extended for long context windows, researchers cannot rely on a single metric. Instead, they employ a combination of language modeling perplexity and task-specific accuracy to get a complete picture of model performance. Perplexity, denoted as $\mathcal{L}$, is a primary metric used to evaluate how well a model predicts the next token in a sequence. In the context of long documents, a lower perplexity indicates that the model is more "comfortable" with the extended context and is better at maintaining a coherent understanding of the text as the sequence length increases.

To rigorously measure perplexity across massive scales, the LongRoPE researchers used a sliding window approach with a window size of 256 tokens. This allows the model to be tested on documents that significantly exceed the target context window. For example, evaluations were conducted on datasets such as PG19, Proof-pile, and Books3. By observing the trend of perplexity as the evaluation length increases from 4k up to 2048k tokens, researchers can determine if the model is truly leveraging the longer context or if its performance is degrading. An ideal extended model shows a decreasing or stable perplexity trend, suggesting that the additional context provides more useful information for the next-token prediction.

While perplexity provides a general measure of linguistic fluency and predictability, it does not always capture the model's ability to pinpoint specific pieces of information within a massive sea of text. This is why task accuracy is used as a complementary metric. Task accuracy measures the model's success rate on a specific goal, such as retrieving a hidden piece of data. While perplexity tells us if the model can "read" the text, task accuracy tells us if the model can "find" the answer. Together, these metrics ensure that the model is not just predicting tokens based on local patterns but is actually attending to the global context.

# The Passkey Retrieval task: Measuring 'Needle in a Haystack' capabilities

A critical challenge for long-context LLMs is the ability to retrieve a specific piece of information hidden deep within a very long document—a challenge often referred to as the "needle in a haystack" problem. To test this, LongRoPE utilizes the Passkey Retrieval task. In this synthetic evaluation, a random five-digit number, known as the passkey, is hidden at a random location within a document. The model is then prompted to find and retrieve this passkey. This task is particularly grueling because it requires the model to maintain high attention precision across millions of tokens.

The evaluation is performed by conducting 10 iterations, where the passkey is placed in positions uniformly distributed across the evaluation context length. This ensures that the model's performance is not dependent on the passkey being at the very beginning or end of the text, but rather on its ability to scan the entire window. For most existing models, accuracy drops precipitously to zero once the context length exceeds 128k tokens, indicating a failure to maintain attention over extremely long sequences.

LongRoPE demonstrates a significant breakthrough in this area. The LongRoPE-LLaMA2-2048k model, fine-tuned at a 256k length, managed to maintain a retrieval accuracy of 90% or higher across the entire range from 4k to 2048k tokens. Similarly, the LongRoPE-Mistral-2048k model maintained 100% accuracy up to 1800k tokens, with a slight dip to 60% at the maximum 2048k limit. These results suggest that the non-uniform positional interpolation used in LongRoPE prevents the attention mechanism from becoming too dispersed, allowing the model to effectively "locate" the needle regardless of the haystack's size.

# Evaluating on standard benchmarks (MMLU, HellaSwag, etc.)

One of the most common pitfalls in extending the context window of an LLM is "catastrophic forgetting" or performance degradation on shorter sequences. When a model is optimized to handle 2 million tokens, it may lose its efficiency or accuracy when processing the original 4096-token window it was originally designed for. This occurs because the positional interpolation process can "crowd" the embeddings of shorter sequences, making it harder for the model to distinguish between closely positioned tokens.

To ensure that LongRoPE does not sacrifice general intelligence for the sake of context length, the researchers evaluated the models on several standard LLM benchmarks within the original 4096 context window. These include ARC-Challenge (25-shot), HellaSwag (10-shot), MMLU (5-shot), and TruthfulQA (0-shot). These benchmarks test commonsense reasoning, factual knowledge, and truthfulness, providing a baseline of the model's general capabilities.

The results indicate that LongRoPE models achieve comparable performance to the original models on these benchmarks. In some cases, the models even showed improvement; for instance, the Mistral variant outperformed the original Mistral model on TruthfulQA by 0.5%. While there was some slight degradation in the LLaMA2-2048k model fine-tuned at 256k, the performance remained within reasonable ranges. This stability is largely attributed to LongRoPE's "shorter context window recovery" strategy, where the RoPE rescale factors are dynamically readjusted during inference for sequences shorter than 8k tokens to reduce the interpolation pressure.

# Ablation studies: Analyzing the contribution of dimension and position non-uniformities

Ablation studies are used to isolate the specific contributions of different components of a proposed method. In LongRoPE, the primary innovation is the use of non-uniformity in two areas: RoPE dimensions and token positions. To understand how each contributes, the researchers performed experiments comparing linear interpolation (PI) against searches that optimized only one or both of these non-uniformities.

First, the researchers examined the impact of RoPE dimension non-uniformity. By searching for optimal rescale factors $\lambda_i$ for each dimension $i$ instead of using a single global scale $s$, they found a significant reduction in perplexity compared to PI. This confirms that different frequency dimensions in RoPE require different levels of interpolation to preserve the model's ability to distinguish token positions.

Second, the researchers analyzed token position non-uniformity, specifically the use of a threshold $\hat{n}$ where the first $\hat{n}$ tokens are not interpolated at all. They discovered that retaining the original RoPE for the initial tokens improves performance at moderate extension lengths, such as 16k and 32k. However, this effect was less pronounced at the extreme 2048k scale. This suggests that while protecting the "initial" tokens is helpful for shorter extensions, the challenge of million-token contexts is dominated more by the dimensional non-uniformity than by the starting position.

Finally, the researchers tested the "second positional interpolation" step of their progressive strategy. They compared using LongRoPE's non-uniform search against PI and YaRN when extending a fine-tuned 256k model to 2048k. The results showed that while PI and YaRN caused perplexity to spike rapidly as the extension ratio increased, LongRoPE maintained a consistent and stable level of perplexity. This demonstrates that non-uniform interpolation is essential for scaling beyond the initial fine-tuning length.

# Comparative performance: LongRoPE vs. PI, NTK, and YaRN

LongRoPE was compared against several state-of-the-art baselines, including Position Interpolation (PI), Neural Tangent Kernel (NTK)-based methods, and YaRN. These baselines represent different philosophies of scaling: PI uses linear scaling, NTK uses unequal scaling across dimensions, and YaRN uses a group-based strategy.

In non-fine-tuning scenarios, LongRoPE showed a dramatic advantage. While PI and NTK-aware methods typically see a spike in perplexity after a $2\times$ extension, LongRoPE was able to extend LLaMA2 from 4k to 32k tokens without any fine-tuning while keeping perplexity stable. This $8\times$ extension is possible because the evolutionary search identifies rescaled factors that preserve key dimensions and positions, minimizing the information loss that typically plagues linear interpolation.

When compared in fine-tuned settings, LongRoPE again outperformed the baselines. On the PG19 and Proof-pile datasets, LongRoPE models showed an overall decreasing perplexity trend from 4k to 256k, whereas baseline models often struggled to maintain performance as the sequence grew. In the extreme 2048k tests on the Books3 dataset, LLaMA2-2048k exhibited a steady decrease in perplexity as the context grew, confirming that the model could actually utilize the massive window of information. 

The comparative results underscore that while PI, NTK, and YaRN provided the foundation for context extension, their reliance on human-designed rules or linear assumptions limited their scaling potential. LongRoPE's approach of using an evolutionary search to discover the optimal, non-uniform distribution of interpolation factors allows it to push the boundaries of LLM context windows to an unprecedented 2 million tokens.

# Stop Wasting Compute: How BLT Uses 'Entropy' to Think Smarter

Most Large Language Models (LLMs) today rely on tokenization, a pre-processing step that groups raw bytes into static tokens based on a fixed vocabulary. While this makes training manageable, it introduces several inefficiencies. Tokenization is a heuristic process that doesn't account for the actual complexity of the data. Consequently, a model spends the same amount of computational power predicting the next character in a predictable word as it does predicting the first word of a complex sentence.

The Byte Latent Transformer (BLT) challenges this paradigm. Instead of relying on a fixed vocabulary, BLT operates on raw bytes and introduces a dynamic grouping mechanism called "patching." By using entropy to determine where to allocate compute, BLT can "skim" through predictable text and "think" harder on complex sequences, matching the performance of tokenization-based models like Llama 3 while significantly reducing inference costs.

## The Flaw in Static Tokenization

In a traditional transformer, every token consumes one step of the main model's computation. However, not all tokens are created equal. Some are highly predictable (low entropy), while others are highly uncertain (high entropy). Because tokenization is static, the model cannot dynamically adjust its effort.

Training directly on bytes was previously considered too expensive because it creates incredibly long sequences, which overwhelms the attention mechanism. While some researchers tried efficient attention or attention-free architectures, the real bottleneck at scale is actually the feed-forward network layers that run on every single byte. BLT solves this by grouping bytes into variable-sized patches, ensuring that the heavy lifting of the global transformer is only performed when necessary.

## Dynamic Patching via Entropy

The core innovation of BLT is its use of a small, lightweight byte-level language model to determine patch boundaries. This process is called entropy patching. The small model calculates the entropy of the next-byte prediction, $H(x_i)$, which represents the uncertainty of what byte comes next:

$$H(x_i) = \sum_{v \in \mathcal{V}} p_{e}(x_i=v|\pmb{x}_{<i}) \log p_{e}(x_i=v|\pmb{x}_{<i})$$

When the entropy exceeds a certain threshold, BLT marks a patch boundary. This means the model allocates more compute (more frequent patches) to high-complexity regions of the data and fewer compute steps to low-complexity regions. To implement this, BLT uses two primary constraints to identify boundaries:

*   **Global Constraint:** $H(x_t) > \theta_g$
*   **Approximate Monotonic Constraint:** $H(x_t) - H(x_{t-1}) > \theta_r$

By segmenting data this way, BLT creates groupings of bytes with relatively uniform information density, effectively aligning computational spend with data complexity.

## The BLT Architecture

To support this dynamic patching, BLT uses a three-part architecture:

1.  **Local Encoder:** A lightweight transformer that maps sequences of bytes into latent patch representations. It uses hash $n$-gram embeddings to capture local character patterns and cross-attention to pool byte representations into patches.
2.  **Latent Global Transformer:** This is the "brain" of the model. It processes the sequence of patches. Since it only runs on patches rather than every byte, it can be significantly larger than the local models without exploding the total compute cost.
3.  **Local Decoder:** Another lightweight transformer that converts the global patch representations back into raw bytes.

## Better Scaling and Improved Robustness

The results of the BLT study demonstrate that patches scale better than tokens. In flop-controlled experiments, BLT matched the performance of Llama 3 up to 8B parameters. More importantly, it offers a new dimension for scaling: you can increase the model size while simultaneously increasing the average patch size. This allows the model to stay within a fixed inference budget while gaining more capacity. In some configurations, BLT achieved up to 50% fewer flops during inference compared to token-based models.

Beyond efficiency, operating on raw bytes makes BLT far more robust. Because it isn't blinded by a fixed vocabulary, it excels at tasks that typically trip up LLMs:

*   **Noise Robustness:** BLT is significantly more resilient to "noisy" text, such as random capitalization or repeated characters.
*   **Character Awareness:** It performs exceptionally well on orthographic and phonological tasks, such as spelling and grapheme-to-phoneme mapping.
*   **Long-Tail Generalization:** BLT shows improved performance in low-resource machine translation, as it can better handle rare byte sequences that a standard tokenizer would likely treat as "unknown" or fragment into meaningless pieces.

By replacing static tokens with dynamic, entropy-driven patches, BLT proves that we can maintain high-level LLM performance while treating computational resources as a flexible asset rather than a fixed cost.

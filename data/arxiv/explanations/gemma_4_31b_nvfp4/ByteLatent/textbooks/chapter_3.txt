\title{A Textbook about the Paper: "Byte Latent Transformer: Patches Scale Better Than Tokens"}

Chapter 3: # BLT Architecture: The Local Encoder

The Byte Latent Transformer ($\text{BLT}$) architecture departs from traditional large language models by removing the need for a fixed-vocabulary tokenizer. Instead, it processes raw bytes. To manage the computational overhead that typically accompanies byte-level modeling, $\text{BLT}$ utilizes a hierarchical structure. The first stage of this pipeline is the Local Encoder, a specialized module designed to transform a raw sequence of bytes into a set of compressed, expressive latent representations known as patches.

# Role of the Local Encoder Model

The Local Encoder, denoted as $\mathcal{E}$, serves as the bridge between the raw input bytes and the high-capacity global transformer. Its primary objective is to map a sequence of individual input bytes $b_i$ into patch representations $p_j$. These patches act as the fundamental units of computation for the rest of the model, allowing the global transformer to operate on a much shorter sequence than the original byte stream.

A defining characteristic of the Local Encoder is that it is designed to be extremely lightweight. In terms of depth, the number of layers in the Local Encoder, $l_{\mathcal{E}}$, is significantly smaller than the number of layers in the global latent transformer, $l_{\mathcal{G}}$. By keeping the local model small, $\text{BLT}$ ensures that the bulk of the model's parameters and floating-point operations ($\text{flops}$) are concentrated in the global model, where complex reasoning and long-range dependencies are handled.

Unlike a standard transformer, which typically outputs a representation for every single input token, the Local Encoder incorporates a specialized mechanism to pool information. This is achieved through the addition of cross-attention layers after each transformer layer, which effectively condense multiple byte-level representations into a single patch representation. This architecture allows $\text{BLT}$ to dynamically allocate compute, as the encoder can group varying numbers of bytes into a single patch based on the data's complexity.

# Hash n-gram Embeddings: Capturing Local Context with RollPolyHash

To ensure that the Local Encoder produces robust and expressive representations, $\text{BLT}$ does not rely solely on individual byte embeddings. Because bytes themselves carry very little information in isolation, the model incorporates local context by treating each byte as part of a byte n-gram. For every position $i$ in the sequence, the model constructs byte-grams $g_{i,n}$ consisting of the current byte and its preceding bytes, specifically $\{b_{i-n+1}, \dots, b_i\}$ for n-gram sizes $n$ ranging from 3 to 8. If the current position $i$ is smaller than $n$, that specific n-gram is omitted.

To handle these n-grams efficiently without requiring a massive, fixed vocabulary for every possible combination of bytes, $\text{BLT}$ employs hash n-gram embeddings. Each n-gram is processed through a hash function, specifically $\text{RollPolyHash}$, which maps the n-gram to an index within an embedding table $E_n^{hash}$ of a fixed size. The hash index is determined by calculating the $\text{RollPolyHash}$ of the n-gram and taking the modulo of the embedding table size: $\text{Hash}(g_{i,n}) = \text{RollPolyHash}(g_{i,n}) \% |E_n^{hash}|$.

The final embedding $e_i$ for a byte at position $i$ is the sum of the individual byte embedding $x_i$ and the embeddings retrieved from the hash tables for all n-gram sizes from 3 to 8. This is expressed mathematically as:
$e_i = x_i + \sum_{n=3, \dots, 8} E_n^{hash}(\text{Hash}(g_{i,n}))$
To maintain stability, this augmented embedding is normalized by the number of n-gram sizes plus one. This mechanism allows the model to capture frequent sub-word patterns and orthographic information effectively, which is critical for matching the performance of traditional tokenizers.

# Local Block Causal Attention Masks

The transformer layers within the Local Encoder do not use global attention, as attending to every byte in a long sequence would be computationally prohibitive. Instead, they employ a local block causal attention mask. This means that each byte representation only attends to a fixed window of $w_{\mathcal{E}}$ preceding bytes.

This masking strategy is designed to capture immediate local dependencies while remaining efficient. A key detail of this implementation is that the attention window is allowed to cross the dynamic boundaries of the patches. This ensures that the encoder can maintain a continuous flow of information across the sequence, regardless of where a patch begins or ends. However, the mask strictly prohibits attention from crossing document boundaries, ensuring that the model does not leak information between unrelated texts.

# Multi-Headed Cross-Attention: Pooling Bytes into Patches

The most critical departure from standard transformer architectures in the Local Encoder is the use of multi-headed cross-attention to pool byte representations into patch representations. This module is inspired by the Perceiver architecture but is adapted for the variable-sized patches used in $\text{BLT}$. In this setup, the latent representations correspond to the dynamic patches, and each patch representation only attends to the specific bytes that compose that patch.

The process begins with the initialization of a query vector $Q_j$ for each patch $p_j$. This initialization is performed by pooling the byte representations that belong to that patch. These queries then pass through a linear projection $\mathcal{E}_C \in \mathbb{R}^{h_{\mathcal{E}} \times (h_{\mathcal{E}} \times U_{\mathcal{E}})}$, where $U_{\mathcal{E}}$ represents the number of encoder cross-attention heads. The patch representations are then updated iteratively across layers. If $P_{l-1}$ is the patch representation from the previous layer and $h_{l-1}$ are the byte representations, the update is:
$P_l = P_{l-1} + W_o\left(\text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V\right)$
where $Q_j = W_q(P_{l-1,j})$, $K_i = W_k(h_{l-1,i})$, and $V_i = W_v(h_{l-1,i})$.

Because the global model's hidden dimension $h_{\mathcal{G}}$ is typically larger than the local model's dimension $h_{\mathcal{E}}$, the cross-attention module maintains $P_l$ as multiple heads of dimension $h_{\mathcal{E}}$. These are concatenated later to form the final $h_{\mathcal{G}}$ dimensions. The module utilizes pre-LayerNorm on the queries, keys, and values, employs no positional embeddings, and includes a residual connection around the cross-attention block to facilitate training.

# Architecture of the Encoder Transformer Layers

The overall structure of the Local Encoder consists of a series of alternating transformer layers and cross-attention layers. The transformer layers process the sequence of bytes using the local block causal attention described previously, refining the byte-level representations $h_i$ based on their immediate neighborhood. Following these, the cross-attention layers pool these refined byte representations into the latent patch representations $p_j$.

The efficiency of this design is highlighted in ablation studies. When the model is equipped with hash n-gram embeddings, the Local Encoder can be remarkably lightweight. Experiments indicate that the encoder can function effectively with as few as one transformer layer, while the local decoder typically requires a more substantial number of layers to map patches back into bytes. This asymmetric design emphasizes the encoder's role as a lightweight compressor that prepares raw data for the high-capacity global latent transformer.

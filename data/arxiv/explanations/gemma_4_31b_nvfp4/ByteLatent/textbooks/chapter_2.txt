Chapter 2: # The Mechanism of Patching

In traditional large language models, the process of converting raw text into a format the model can process is handled by tokenization. This is typically a heuristic pre-processing step that groups bytes into a static set of tokens based on a fixed vocabulary. However, this approach introduces several biases and inefficiencies, as the model must allocate the same amount of computational resources to every token, regardless of whether that token is a common piece of punctuation or a complex technical term. The Byte Latent Transformer (BLT) addresses these shortcomings by replacing fixed tokenization with a dynamic process called patching.

Patching is the mechanism by which BLT groups individual bytes into variable-sized "patches," which then serve as the primary units of computation for the model's main transformer. The fundamental intuition behind patching is that the computational cost of a transformer is primarily determined by the number of steps it must execute. By grouping bytes into patches, BLT can significantly reduce the sequence length that the main transformer needs to process. This allows the model to dynamically allocate more compute to complex, high-information data and less compute to predictable, low-information data.

# Defining the Patching Function

To understand how BLT manages this transition from raw bytes to computational units, we must first define the patching function. Formally, a patching function $f_p$ takes a sequence of bytes $\pmb{x}=\{x_i,|i=1,\ldots n\}$ of length $n$ and segments it into a sequence of $m$ patches, $\pmb{p}=\{p_j|j=1,\ldots,m\}$, where $m$ is necessarily smaller than $n$. The function achieves this by mapping each byte $x_i$ to a binary value in the set $\{0, 1\}$, where a value of 1 indicates the start of a new patch and 0 indicates the continuation of the current patch.

The efficiency of this system is governed by the average patch size. Because the main transformer—the global latent transformer—operates on these patches rather than individual bytes, the number of patches determines the total number of floating point operations (flops) required during both training and inference. By altering the patching function to change the average patch size, researchers can directly control the computational budget of the model. This flexibility allows BLT to move away from the rigid constraints of a fixed vocabulary, instead treating the grouping of bytes as a dynamic process that can be optimized for efficiency.

# Static Patching: Strided Fixed-Size Groups

The most basic approach to grouping bytes is strided patching, where bytes are grouped into patches of a fixed size $k$. In this scheme, every $k$-th byte marks the start of a new patch, creating a uniform stride across the entire sequence. From an implementation standpoint, strided patching is highly attractive because it is straightforward to deploy for both training and inference. It provides a predictable mechanism for controlling the total flop cost, as the number of transformer steps is always exactly $n/k$.

Despite its simplicity, static strided patching suffers from significant theoretical and practical downsides. The primary issue is that it fails to allocate compute based on the actual complexity of the data. For instance, the model might waste a full transformer step processing a sequence of whitespace characters in a block of code, while simultaneously failing to allocate sufficient compute to a dense sequence of mathematical symbols that carry high information density. Furthermore, this method is non-contextual; the same word may be split across different patches depending on its position in the sequence, preventing the model from consistently representing similar linguistic units.

# Heuristic Patching: Space-Based Segmentation

To improve upon the rigidity of strided patching, one can employ heuristic patching, specifically space patching. This method utilizes the observation that in many languages, space-like bytes serve as natural boundaries for linguistic units. A byte is defined as space-like if it is not a Latin character, a digit, or a UTF-8 continuation byte. Under this scheme, the patching function creates a new patch boundary after any space-like byte, provided that the patch contains at least one non space-like byte.

The intuition behind space patching is that the most difficult part of predicting a word is typically predicting its first byte. Once the first character of a word like "Mozart" is determined, the remaining bytes are comparatively easy to predict. By allocating a new latent transformer step to every word, space patching ensures that the model expends more effort on the "hard" predictions that follow spaces. While this is more effective than strided patching and ensures that words are patched consistently across different sequences, it still relies on a rule-based heuristic. This means it cannot gracefully handle all languages or domains, and it lacks a mechanism to vary the patch size based on the actual unpredictability of the data.

# Entropy-Based Patching: Using a Small Byte LM for Boundary Detection

The most sophisticated method implemented in BLT is entropy patching. Rather than relying on fixed strides or whitespace heuristics, entropy patching takes a data-driven approach to identify where compute is most needed. This is achieved by using a small, separate byte-level auto-regressive language model (LM) to estimate the entropy of the next-byte prediction. The entropy $H(x_i)$ for a byte $x_i$ is calculated using the LM distribution $p_e$ over the byte vocabulary $\mathcal{V}$ as follows:

$$H(x_i) = \sum_{v \in \mathcal{V}} p_{e}(x_i=v|\pmb{x}_{<i}) \log p_{e}(x_i=v|\pmb{x}_{<i})$$

In this context, entropy serves as a proxy for uncertainty. When the entropy is high, the next byte is difficult to predict, suggesting that the model should trigger a new patch boundary to invoke the full power of the global latent transformer. Conversely, when entropy is low, the data is predictable, and the model can group more bytes into a single patch, thereby saving computational resources. This process is performed during a lightweight preprocessing step during dataloading, ensuring that the main model's compute is focused on the most complex segments of the input.

# Global vs. Approximate Monotonic Constraints for Entropy

To translate entropy values into actual patch boundaries, BLT experiments with two distinct constraints. The first is the Global Constraint, where a patch boundary is created whenever the entropy $H(x_t)$ exceeds a predefined global threshold $\theta_g$:

$$\text{Global Constraint: } H(x_t) > \theta_g$$

The second approach is the Approximate Monotonic Constraint. Instead of looking at an absolute value, this method identifies points where the entropy increases relative to the previous byte:

$$\text{Approx. Monotonic Constraint: } H(x_t) - H(x_{t-1}) > \theta_r$$

The intuition here is that within a single patch, entropy should ideally be monotonically decreasing as the model gathers more information about the current unit. When the entropy jumps—meaning it breaks this approximate monotonic decrease—it signals the start of a new, high-uncertainty segment. In large-scale runs, the approximate monotonicity constraint is often preferred because it is less susceptible to "entropy drift," a phenomenon where changes in context length can cause the entropy model to produce inconsistent values.

# The Property of Incremental Patching and its Difference from BPE

A critical requirement for any patching scheme used during text generation is the property of incremental patching. Because the model generates text one byte at a time, it must decide whether the current byte marks a patch boundary without knowing what the future bytes will be. Formally, a patching scheme $f_p$ is incremental if:

$$f_p(\pmb{x}_{<i}) = f_p(\pmb{x})_{<i}$$

This means the segmentation of the prefix of a sequence must remain identical regardless of what follows it. This property is what distinguishes BLT patches from Byte-Pair Encoding (BPE) tokens. In BPE, the same prefix can be tokenized differently depending on the continuation sequence; therefore, BPE is not an incremental patching scheme.

Furthermore, BLT fundamentally changes the trade-off between vocabulary size and computation. In standard BPE-based models, increasing the vocabulary size to get larger tokens (and thus fewer steps) requires a larger embedding table, which increases the output dimension of the final projection layer. BLT breaks this link because it has no fixed vocabulary. It can increase the average patch size to save inference flops without needing to expand a vocabulary table. This allows BLT to simultaneously scale the model size and the patch size while maintaining a fixed inference budget, a dimensionality of scaling that is unavailable to traditional tokenization-based architectures.

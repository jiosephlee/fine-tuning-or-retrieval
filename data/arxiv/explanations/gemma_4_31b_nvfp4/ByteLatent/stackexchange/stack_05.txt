\title{Stack Exchange of the Paper: "Byte Latent Transformer: Patches Scale Better Than Tokens"}

### How does the trade-off between patch size and global model size work for a fixed inference budget?
Question:
The paper mentions that BLT allows for a new dimension of scaling where one can simultaneously increase the model size and the patch size while maintaining the same inference flop budget. My understanding is that if the average patch size increases, the global latent transformer is run fewer times per document. Does this mean that the 'saved' flops from running the global model fewer times can be mathematically reallocated to increase the number of layers $l_{\mathcal{G}}$ or the hidden dimension $h_{\mathcal{G}}$ of that same global model? I'm trying to understand the formula for this trade-off—specifically, how much can I grow the model if I double the average patch size?
Answer:
Your intuition is correct. In the {\textsc BLT} architecture, the global latent transformer $\mathcal{G}$ is the most computationally expensive component because it is a deep transformer with $l_{\mathcal{G}}$ layers and a large hidden dimension $h_{\mathcal{G}}$. Since $\mathcal{G}$ operates on patches rather than individual bytes, the total number of times the global model is invoked is determined by the number of patches $m$, which is the total number of bytes $n$ divided by the average patch size $n_p$ (i.e., $m = n / n_p$).

When you increase the average patch size $n_p$, you effectively reduce the sequence length that the global model must process. For a fixed document of $n$ bytes, doubling the average patch size reduces the number of global transformer forward passes by half. Because these passes dominate the inference budget, the "saved" FLOPs can be mathematically reallocated to increase the complexity of the global model itself.

Specifically, if you double the average patch size, you can theoretically double the computational cost $C_{\mathcal{G}}$ of a single patch processing step while keeping the total inference cost per byte constant. Since the computational cost of a transformer is roughly linear with respect to the number of layers $l_{\mathcal{G}}$ and quadratic with respect to the hidden dimension $h_{\mathcal{G}}$ (due to the feed-forward networks and projection matrices), you have two primary ways to grow the model:
1. **Increase Depth:** You could double the number of layers $l_{\mathcal{G}}$, which increases the model's capacity to perform sequential reasoning.
2. **Increase Width:** You could increase the hidden dimension $h_{\mathcal{G}}$ by a factor of approximately $\sqrt{2} \approx 1.41$, as the FLOPs scale with $h_{\mathcal{G}}^2$.

This represents a fundamental departure from traditional tokenization-based models like Llama. In a BPE-based model, increasing the "patch size" (average token length) requires increasing the vocabulary size. This creates a restrictive trade-off: a larger vocabulary requires a larger embedding table and a larger final projection layer, which consumes the very memory and compute you hoped to save. {\textsc BLT} avoids this because it uses a lightweight encoder and decoder to map arbitrary byte groups into a latent space, meaning there is no fixed vocabulary to grow. This allows the model to scale both the "granularity" of its processing (patch size) and its "intelligence" (model size) simultaneously while remaining within a strict inference FLOP budget.

# Beyond the Token: Why the Byte Latent Transformer is a Game Changer for LLMs

For years, the standard blueprint for Large Language Models (LLMs) has relied on a critical pre-processing step: tokenization. Whether it is Byte Pair Encoding (BPE) or other subword methods, tokenization groups raw bytes into a static vocabulary of tokens before the model ever sees the data. While this approach has enabled the scaling of models like Llama, it introduces a rigid heuristic that biases how the model perceives text.

The Byte Latent Transformer ($\text{BLT}$) proposes a paradigm shift. By removing the tokenizer entirely and operating on raw bytes, $\text{BLT}$ eliminates the shortcomings of fixed vocabularies while matching the performance of token-based models at scale.

## The Hidden Flaws of Tokenization

Tokenization is not a neutral process. Because it relies on a predefined vocabulary, it creates several systemic issues:

*   **Sensitivity to Noise:** Tokenizers often struggle with typos or unconventional formatting, as a single character change can completely alter how a word is split into tokens.
*   **Orthographic Blindness:** Models often lack a direct understanding of spelling or character-level manipulation because the "tokens" obscure the underlying bytes.
*   **Multilingual Inequity:** Fixed vocabularies are often biased toward high-resource languages, leading to inefficient representations for lower-resource languages.
*   **Inefficient Compute:** Token-based models allocate the same amount of computation to every token. However, predicting the end of a common word is computationally "easier" than predicting the first word of a new sentence.

$\text{BLT}$ solves these issues by treating bytes as the fundamental unit of computation, using a dynamic grouping mechanism called "patching" to allocate compute where it is actually needed.

## How $\text{BLT}$ Works: Dynamic Patching

Instead of a fixed vocabulary, $\text{BLT}$ groups bytes into **patches**. The key innovation is that these patches are not static; they are determined dynamically based on the complexity of the data. 

To achieve this, $\text{BLT}$ uses a small, separate byte-level language model to calculate the entropy of the next byte. Entropy, denoted as $H(x_i)$, represents the uncertainty of a prediction. When the entropy exceeds a certain threshold—meaning the next byte is difficult to predict—the model triggers a patch boundary. This ensures that "predictable" sequences of bytes are grouped into long patches (requiring fewer transformer steps), while "complex" sequences are broken into smaller patches (receiving more computational attention).

## The Architecture: Local and Global Models

The $\text{BLT}$ architecture consists of three primary components: a local encoder, a global latent transformer, and a local decoder.

**The Local Encoder** is a lightweight transformer that maps raw bytes into patch representations. To provide the model with better local context, $\text{BLT}$ uses hash $n$-gram embeddings. It models bytes both individually and as part of $n$-grams (ranging from sizes 3 to 8), mapping these to an embedding table via a hash function:
$$e_i = x_i + \sum_{n = 3,...,8}E_{n}^{hash}(\text{Hash}(g_{i,n}))$$
This allows the encoder to capture sub-word structures without needing a fixed tokenizer.

**The Global Latent Transformer** is the "heavy lifter" of the architecture. It operates exclusively on the patch representations produced by the encoder. Because it only runs once per patch rather than once per byte, it is significantly more efficient.

**The Local Decoder** reverses the process, taking the output from the global model and decoding the patch representations back into a sequence of raw bytes.

## Why Patches Scale Better Than Tokens

One of the most significant findings in the $\text{BLT}$ research is a new dimension for scaling. In traditional LLMs, there is a strict trade-off between vocabulary size and compute. In $\text{BLT}$, developers can simultaneously increase the model size and the average patch size while keeping the inference budget constant.

By increasing the average patch size, the global transformer is invoked less frequently, saving computational flops. These saved flops can then be reallocated to make the global transformer larger and more capable. The researchers found that $\text{BLT}$ matches the performance of Llama 3 at the 8B parameter scale and can achieve up to 50% fewer flops during inference.

## Enhanced Robustness and Understanding

Operating on raw bytes provides an inherent advantage in robustness. $\text{BLT}$ demonstrates superior performance in several areas where token-based models typically fail:

*   **Noise Resistance:** $\text{BLT}$ is far more resilient to "noisy" inputs, such as random case changes, character repetitions, or "AntSpeak" (uppercase, space-separated characters).
*   **Character-Level Tasks:** On the CUTE benchmark, which tests orthographic similarity and sequence manipulation, $\text{BLT}$ outperformed BPE-based models by more than 25 points, showing nearly perfect accuracy on spelling tasks.
*   **Low-Resource Translation:** $\text{BLT}$ showed improved generalization for low-resource language families in the FLORES-101 benchmark, proving that byte-level modeling is more effective for the "long-tail" of global languages.

By moving beyond the token, the Byte Latent Transformer provides a path toward LLMs that are not only more efficient and scalable but also fundamentally more robust to the messiness of real-world language.



# Stop Wasting Compute: How BLT Uses 'Entropy' to Think Smarter

Most Large Language Models (LLMs) today rely on tokenization, a pre-processing step that groups raw bytes into static tokens based on a fixed vocabulary. While this makes training manageable, it introduces several inefficiencies. Tokenization is a heuristic process that doesn't account for the actual complexity of the data. Consequently, a model spends the same amount of computational power predicting the next character in a predictable word as it does predicting the first word of a complex sentence.

The Byte Latent Transformer (BLT) challenges this paradigm. Instead of relying on a fixed vocabulary, BLT operates on raw bytes and introduces a dynamic grouping mechanism called "patching." By using entropy to determine where to allocate compute, BLT can "skim" through predictable text and "think" harder on complex sequences, matching the performance of tokenization-based models like Llama 3 while significantly reducing inference costs.

## The Flaw in Static Tokenization

In a traditional transformer, every token consumes one step of the main model's computation. However, not all tokens are created equal. Some are highly predictable (low entropy), while others are highly uncertain (high entropy). Because tokenization is static, the model cannot dynamically adjust its effort.

Training directly on bytes was previously considered too expensive because it creates incredibly long sequences, which overwhelms the attention mechanism. While some researchers tried efficient attention or attention-free architectures, the real bottleneck at scale is actually the feed-forward network layers that run on every single byte. BLT solves this by grouping bytes into variable-sized patches, ensuring that the heavy lifting of the global transformer is only performed when necessary.

## Dynamic Patching via Entropy

The core innovation of BLT is its use of a small, lightweight byte-level language model to determine patch boundaries. This process is called entropy patching. The small model calculates the entropy of the next-byte prediction, $H(x_i)$, which represents the uncertainty of what byte comes next:

$$H(x_i) = \sum_{v \in \mathcal{V}} p_{e}(x_i=v|\pmb{x}_{<i}) \log p_{e}(x_i=v|\pmb{x}_{<i})$$

When the entropy exceeds a certain threshold, BLT marks a patch boundary. This means the model allocates more compute (more frequent patches) to high-complexity regions of the data and fewer compute steps to low-complexity regions. To implement this, BLT uses two primary constraints to identify boundaries:

*   **Global Constraint:** $H(x_t) > \theta_g$
*   **Approximate Monotonic Constraint:** $H(x_t) - H(x_{t-1}) > \theta_r$

By segmenting data this way, BLT creates groupings of bytes with relatively uniform information density, effectively aligning computational spend with data complexity.

## The BLT Architecture

To support this dynamic patching, BLT uses a three-part architecture:

1.  **Local Encoder:** A lightweight transformer that maps sequences of bytes into latent patch representations. It uses hash $n$-gram embeddings to capture local character patterns and cross-attention to pool byte representations into patches.
2.  **Latent Global Transformer:** This is the "brain" of the model. It processes the sequence of patches. Since it only runs on patches rather than every byte, it can be significantly larger than the local models without exploding the total compute cost.
3.  **Local Decoder:** Another lightweight transformer that converts the global patch representations back into raw bytes.

## Better Scaling and Improved Robustness

The results of the BLT study demonstrate that patches scale better than tokens. In flop-controlled experiments, BLT matched the performance of Llama 3 up to 8B parameters. More importantly, it offers a new dimension for scaling: you can increase the model size while simultaneously increasing the average patch size. This allows the model to stay within a fixed inference budget while gaining more capacity. In some configurations, BLT achieved up to 50% fewer flops during inference compared to token-based models.

Beyond efficiency, operating on raw bytes makes BLT far more robust. Because it isn't blinded by a fixed vocabulary, it excels at tasks that typically trip up LLMs:

*   **Noise Robustness:** BLT is significantly more resilient to "noisy" text, such as random capitalization or repeated characters.
*   **Character Awareness:** It performs exceptionally well on orthographic and phonological tasks, such as spelling and grapheme-to-phoneme mapping.
*   **Long-Tail Generalization:** BLT shows improved performance in low-resource machine translation, as it can better handle rare byte sequences that a standard tokenizer would likely treat as "unknown" or fragment into meaningless pieces.

By replacing static tokens with dynamic, entropy-driven patches, BLT proves that we can maintain high-level LLM performance while treating computational resources as a flexible asset rather than a fixed cost.



# Typos, Rare Languages, and Raw Bytes: Making AI More Robust

Most modern Large Language Models (LLMs) do not actually "read" text the way humans do. Instead, they rely on a process called tokenization, which groups characters into a fixed vocabulary of tokens. While efficient, this heuristic approach creates a significant blind spot: the model becomes sensitive to any input that doesn't fit its predefined vocabulary. A simple typo, a change in capitalization, or a rare dialect can completely change how a word is tokenized, often leaving the model confused.

The Byte Latent Transformer ($\text{BLT}$) offers a fundamental shift in this paradigm. By moving away from fixed-vocabulary tokenization and operating directly on raw bytes, $\text{BLT}$ demonstrates that models can be significantly more robust to noise, more capable at character-level manipulation, and more inclusive of low-resource languages.

## The Problem with the Tokenizer

Tokenization is essentially a compression heuristic. If a model is trained on a vocabulary where "apple" is a single token, but it encounters "a p p l e" or "appple," the tokenizer may split those strings into entirely different, fragmented tokens. Because the model's understanding is tied to these tokens rather than the underlying characters, it often lacks basic orthographic knowledge. This is why many LLMs struggle with simple tasks like spelling or reversing a string.

$\text{BLT}$ solves this by replacing the static tokenizer with a dynamic patching mechanism. It groups bytes into "patches" based on the entropy of the next-byte prediction. In simple terms, the model allocates more compute to complex, unpredictable sequences of bytes and groups predictable sequences together. Because there is no fixed vocabulary, $\text{BLT}$ maintains a direct connection to the raw byte data.

## Resilience Against "Noisy" Text

One of the most striking advantages of the $\text{BLT}$ architecture is its robustness to input noise. In a series of experiments, $\text{BLT}$ was tested against tokenizer-based models using various "noising" strategies, including:

*   **AntSpeak:** Converting text to uppercase, space-separated characters.
*   **RandomCase:** Randomly swapping characters between uppercase and lowercase.
*   **Drop:** Randomly removing 10% of the characters.
*   **Repeat:** Repeating characters up to four times.

In evaluations on the HellaSwag benchmark, $\text{BLT}$ consistently outperformed tokenizer-based models. On average, $\text{BLT}$ showed an 8-point advantage over models trained on the same data. By seeing the raw bytes, $\text{BLT}$ can recognize the underlying pattern of a word even when it is distorted—a task that is nearly impossible for a model that relies on rigid token boundaries.

## Mastering the Character Level

Because $\text{BLT}$ operates on bytes, it possesses an inherent awareness of the constituents of words. This is evidenced by its performance on the CUTE benchmark, which tests a model's ability to handle orthographic similarity and sequence manipulation.

$\text{BLT}$ outperformed BPE-based Llama 3 models by more than 25 points on this benchmark. It achieved nearly perfect accuracy (99.9%) on spelling tasks, showcasing a level of character-level proficiency that token-based models struggle to acquire even with vast amounts of training data. This capability extends to phonology as well; $\text{BLT}$ is more effective at Grapheme-to-Phoneme (G2P) tasks, mapping written characters to their actual pronunciations.

## Bridging the Gap for Low-Resource Languages

Tokenization often introduces a "multilingual inequity." Languages that are under-represented in the training data often get fragmented into tiny, inefficient tokens, making it harder for the model to learn their structure.

By utilizing raw bytes, $\text{BLT}$ treats all data with the same granularity. When tested on the FLORES-101 benchmark, $\text{BLT}$ outperformed Llama 3 in translating into and out of English across various low-resource language families. This suggests that byte-level modeling is far more effective at generalizing to the "long-tail" of human language, where the data is too sparse to build an efficient static tokenizer.

## Conclusion

The $\text{BLT}$ architecture proves that we don't need to sacrifice performance for robustness. By replacing the static tokenizer with dynamic byte patching, $\text{BLT}$ not only matches the scaling trends of industry-leading models like Llama 3 but also overcomes the fragility inherent in tokenization. Whether it is handling a user's typos or translating a rare dialect, moving toward raw-byte processing makes AI more adaptable, inclusive, and resilient.



# The New Scaling Law: Balancing Model Size and Patch Size

For years, the standard architecture for Large Language Models (LLMs) has relied on tokenization—a pre-processing step that groups raw bytes into a static vocabulary of tokens. While effective, tokenization is a heuristic that introduces several shortcomings: it is sensitive to input noise, creates multilingual inequities, and often lacks a deep understanding of orthography. Training directly on bytes was historically avoided because it is computationally prohibitively expensive due to the massive sequence lengths.

The Byte Latent Transformer ($\textsc{BLT}$) changes this equation. By introducing a dynamic method for grouping bytes into "patches," $\textsc{BLT}$ matches the performance of tokenization-based models like Llama 3 at scale while significantly improving inference efficiency and robustness.

## Moving Beyond Static Tokens with Entropy Patching

The core innovation of $\textsc{BLT}$ is the transition from static tokens to dynamic patches. Unlike a fixed vocabulary, $\textsc{BLT}$ determines patch boundaries based on the entropy of the next-byte prediction. Essentially, the model uses a small, lightweight byte-level language model to estimate the uncertainty of the next byte.

When the prediction uncertainty is high—meaning the data is complex—the model starts a new patch. When the data is predictable (e.g., the end of a common word), the model extends the current patch. This allows $\textsc{BLT}$ to dynamically allocate compute where it is needed most. Formally, the entropy $H(x_i)$ is calculated as:

$$H(x_i) = \sum_{v \in \mathcal{V}} p_{e}(x_i=v|\pmb{x}_{<i}) \log p_{e}(x_i=v|\pmb{x}_{<i})$$

By using a global threshold or a monotonicity constraint, the model identifies boundaries that create groupings with relatively uniform information density.

## The $\textsc{BLT}$ Architecture

To support this dynamic patching, $\textsc{BLT}$ utilizes a hierarchical architecture consisting of three main components:

*   **Local Encoder:** A lightweight transformer that maps raw bytes into latent patch representations. It uses hash $n$-gram embeddings to capture local byte-level context and a cross-attention mechanism to pool byte representations into patches.
*   **Latent Global Transformer:** The primary compute engine. This large autoregressive transformer operates on the patch representations. Because it only runs once per patch (rather than once per byte), it consumes the bulk of the FLOPs but does so far more efficiently than a byte-level model.
*   **Local Decoder:** Another lightweight transformer that decodes the global patch representations back into raw bytes.

## A New Dimension of Scaling

The most significant breakthrough in the $\textsc{BLT}$ paper is the discovery of a new dimension for scaling LLMs. In traditional BPE-based models, there is a rigid trade-off between vocabulary size and compute. Increasing the average token size usually requires a much larger embedding table, which limits how much developers can vary the inference cost.

$\textsc{BLT}$ breaks this constraint because it has no fixed vocabulary. This allows for a unique scaling strategy: **simultaneously increasing the model size and the patch size.**

Since the Global Latent Transformer is invoked only at patch boundaries, increasing the average patch size reduces the number of times the global model must run. These saved computational resources (FLOPs) can then be reallocated to make the Global Latent Transformer larger. In other words, you can trade a higher "compression" rate (larger patches) for a more powerful "reasoning" engine (larger model) while keeping the total inference cost constant.

The results of this approach are compelling. In inference-flop controlled scaling studies, $\textsc{BLT}$ demonstrated significantly better scaling trends than tokenization-based architectures. For a fixed inference budget, $\textsc{BLT}$ can achieve higher performance by growing the model size and patch size in tandem.

## Efficiency and Robustness Gains

The practical implications of this architecture are twofold:

First, $\textsc{BLT}$ offers massive efficiency gains. The researchers found that $\textsc{BLT}$ can match the training flop-controlled performance of Llama 3 while using up to 50% fewer FLOPs during inference.

Second, by operating on raw bytes, $\textsc{BLT}$ is inherently more robust. It outperforms BPE-based models on tasks involving:
*   **Noisy Data:** $\textsc{BLT}$ is far more resilient to character-level noise, such as random capitalization or repeated characters.
*   **Character-Level Understanding:** It shows a superior ability to manipulate text and understand orthographic similarity (as seen in the CUTE benchmark).
*   **Low-Resource Languages:** The model generalizes better to the "long tail" of data, improving translation performance for lower-resource language families.

By treating patches as a scalable resource rather than tokens as a static constraint, $\textsc{BLT}$ provides a blueprint for the next generation of efficient, robust, and tokenizer-free language models.

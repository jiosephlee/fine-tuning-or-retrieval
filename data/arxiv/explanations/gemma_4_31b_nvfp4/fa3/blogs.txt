# Breaking the Bottleneck: How FlashAttention-3 Supercharges LLMs

The attention mechanism is the engine of the Transformer architecture, but it is also its primary bottleneck. Because computing self-attention scores scales quadratically with sequence length, scaling to longer contexts—essential for processing massive codebases, long documents, or high-resolution video—creates a massive computational burden. While previous iterations like FlashAttention and FlashAttention-2 focused on reducing memory reads and writes, they didn't fully exploit the specialized hardware available in the latest GPUs. In fact, FlashAttention-2 only achieved about 35% utilization on the NVIDIA H100 (Hopper) GPU.

FlashAttention-3 was designed specifically to close this gap. By leveraging the unique capabilities of the Hopper architecture, it introduces three key technical innovations: producer-consumer asynchrony, the overlapping of GEMM and softmax operations, and hardware-accelerated low-precision computation.

## Harnessing Asynchrony with Warp-Specialization

Modern GPUs are throughput processors that rely on concurrency to hide the time it takes to move data from memory to the cores. FlashAttention-3 implements a warp-specialized software pipelining scheme. Instead of having every thread perform the same sequence of loading and computing, the algorithm divides warps into "producers" and "consumers."

The producer warps are dedicated to data movement, using the Tensor Memory Accelerator (TMA) to fetch blocks of the query $\mathbf{Q}$, key $\mathbf{K}$, and value $\mathbf{V}$ matrices from global memory into shared memory. Meanwhile, the consumer warps focus entirely on computation. This separation allows the GPU to better hide memory and instruction issue latencies, ensuring that the Tensor Cores are rarely idling while waiting for data.

## Hiding Softmax under GEMMs

A major challenge in attention is the throughput disparity between different types of operations. On an H100, matrix multiplications (GEMMs) are incredibly fast, while the special functions required for softmax, such as exponentials, are significantly slower. In previous versions, the GPU would essentially "pause" its high-speed matmuls to perform the softmax calculations.

FlashAttention-3 solves this by interleaving these operations. Using a two-stage pipeline, the algorithm overlaps the softmax computation of one block with the asynchronous GEMM of the next. While the consumer warpgroup is calculating the softmax for the current set of scores, the Tensor Cores are already working in the background via asynchronous WGMMA (Warpgroup-level Matrix Multiply-Accumulate) instructions to compute the next block. This "pingpong" scheduling ensures that the low-throughput softmax operations are hidden behind the high-throughput matmuls.

## Scaling Performance with FP8 Low-Precision

To push throughput even further, FlashAttention-3 adopts FP8 precision. Using FP8 Tensor Cores can nearly double the TFLOPs/s compared to FP16, but it introduces significant technical hurdles regarding memory layout and numerical accuracy.

First, FP8 WGMMA instructions have strict layout requirements—specifically, they require "k-major" format. Since input tensors are typically contiguous in the head dimension, FlashAttention-3 performs an in-kernel transpose of the $\mathbf{V}$ tiles using specialized LDSM and STSM instructions. This allows the algorithm to satisfy hardware constraints without the overhead of a separate pre-processing kernel.

Second, the reduced precision of FP8 can lead to accuracy loss, especially in the presence of "outlier" features common in large language models. FlashAttention-3 mitigates this using two techniques:
* **Block Quantization:** Instead of using a single scaling factor for an entire tensor, the algorithm keeps one scalar per block, significantly reducing quantization error.
* **Incoherent Processing:** The algorithm multiplies $\mathbf{Q}$ and $\mathbf{K}$ by a random orthogonal matrix $\mathbf{M}$ before quantization. This "spreads out" the outliers, making the distribution easier to quantize without losing critical information.

## Results and Impact

The results of these optimizations are substantial. In FP16 precision, FlashAttention-3 achieves a $1.5\text{--}2.0\times$ speedup over FlashAttention-2 in the forward pass, reaching up to 740 TFLOPs/s—which is 75% of the H100's theoretical maximum. When moving to FP8, the throughput jumps even higher, reaching close to 1.2 PFLOPs/s. 

Beyond speed, the accuracy improvements are noteworthy. Thanks to block quantization and incoherent processing, FP8 FlashAttention-3 is $2.6\times$ more accurate than standard attention using per-tensor quantization. By maximizing the utility of the Hopper architecture, FlashAttention-3 provides a faster, more accurate primitive that paves the way for more efficient long-context LLM applications.



# The Art of the Overlap: Understanding Warp Specialization and Asynchrony

In the world of Large Language Models (LLMs), the attention mechanism is often the primary computational bottleneck. While previous iterations like FlashAttention-2 significantly reduced memory reads and writes, they didn't fully leverage the latest hardware capabilities of NVIDIA's Hopper (H100) architecture. In fact, FlashAttention-2 achieves only about 35% utilization on H100 GPUs. 

FlashAttention-3 solves this by rethinking how the GPU handles data movement and computation. The core philosophy is to move away from a synchronous execution model toward a highly asynchronous "producer-consumer" design. By overlapping data movement with heavy computation, FlashAttention-3 pushes utilization up to 75% for FP16, reaching 740 TFLOPs/s.

## Warp Specialization: The Producer-Consumer Model

On modern GPUs, different hardware units handle different tasks: the Tensor Memory Accelerator (TMA) manages data movement, while the Tensor Cores handle matrix multiplication via WGMMA (Warpgroup-wide Matrix Multiply-Accumulate) instructions. 

FlashAttention-3 exploits this specialization through a warp-specialized software pipelining scheme. Instead of having every warp perform every step of the attention algorithm, the warps within a Cooperative Thread Array (CTA) are split into two distinct roles:

*   **Producers:** These warps are dedicated to data movement. They use the TMA to load tiles of the Query ($\mathbf{Q}$), Key ($\mathbf{K}$), and Value ($\mathbf{V}$) matrices from global memory (HBM) into shared memory (SMEM).
*   **Consumers:** These warps focus entirely on computation. They use the WGMMA instructions to perform the matrix multiplications and compute the softmax operations.

By decoupling data movement from computation, the GPU can hide memory and instruction issue latencies more effectively. While the consumers are processing the current block of data, the producers are already fetching the next blocks into a circular SMEM buffer, ensuring the Tensor Cores are never starved for data.

## Hiding Softmax with Pingpong Scheduling

One of the biggest challenges in attention is the throughput gap between matrix multiplication (GEMM) and the "special functions" required for softmax, such as the exponential function. On the H100, matmul throughput is orders of magnitude higher than the throughput of the multi-function units that handle exponentials. If the GPU simply waited for the softmax to finish before starting the next GEMM, the Tensor Cores would sit idle for a significant portion of the time.

To solve this, FlashAttention-3 introduces "pingpong scheduling." This technique overlaps the softmax computation of one warpgroup with the GEMM of another. Using synchronization barriers, the algorithm ensures that Warpgroup 1 performs its softmax calculations while Warpgroup 2 is executing its GEMM operations. The roles then swap. This "pingpong" effect ensures that the lower-throughput non-GEMM operations are hidden "under" the high-throughput matrix multiplications.

## Intra-Warpgroup Pipelining

Beyond inter-warpgroup scheduling, FlashAttention-3 also implements a 2-stage pipeline within a single warpgroup to further break sequential dependencies. In a standard attention loop, the second GEMM (computing $\mathbf{P}\mathbf{V}$) depends on the result of the softmax, which in turn depends on the first GEMM ($\mathbf{Q}\mathbf{K}^\top$).

FlashAttention-3 breaks this chain by pipelining across iterations. By using additional registers to store intermediate results (like the scores matrix $\mathbf{S}_{\text{next}}$), the algorithm can overlap the second GEMM of the current iteration $j$ with the softmax operations of the next iteration $j+1$. This effectively hides the latency of the softmax and the second GEMM, maximizing the time the Tensor Cores spend doing useful work.

## Impact and Results

These architectural optimizations allow FlashAttention-3 to achieve substantial performance gains over its predecessor. In the forward pass, it is 1.5-2.0$\times$ faster than FlashAttention-2 in FP16 precision. When moving to FP8 precision, the speedup is even more dramatic, reaching close to 1.2 PFLOPs/s. 

By treating the GPU not as a synchronous processor but as a collection of specialized asynchronous units, FlashAttention-3 demonstrates that the "art of the overlap" is the key to unlocking the full potential of modern AI hardware.



# Speed Without Sacrifice: Mastering FP8 Precision in Attention

Attention is the core of the Transformer architecture, but it is also its primary computational bottleneck. To scale these models to longer contexts and higher resolutions, we need faster attention. While previous iterations like FlashAttention-2 focused on minimizing memory reads and writes, FlashAttention-3 leverages the latest hardware capabilities of NVIDIA's Hopper architecture (H100 GPUs) to push throughput even further. One of the most impactful ways it achieves this is through the use of 8-bit floating point (FP8) precision.

## The FP8 Trade-off: Speed vs. Accuracy

Moving from FP16 to FP8 precision can nearly double the throughput of matrix multiplications on modern Tensor Cores. However, this speed comes with a cost. FP8 (specifically the e4m3 format) uses significantly fewer bits for the mantissa and exponent, which increases numerical error. 

This problem is exacerbated by the presence of "outlier features" in large language models—values that are significantly larger in magnitude than others. Standard per-tensor quantization, which uses a single scaling factor for an entire tensor, often fails to handle these outliers, leading to significant precision loss and degraded model performance.

## Solving the Accuracy Gap

FlashAttention-3 introduces two key techniques to maintain high numerical accuracy while reaping the benefits of FP8 speed: block quantization and incoherent processing.

### Block Quantization
Instead of applying a single scale to the entire tensor, FlashAttention-3 employs block quantization. This method keeps one scaling factor per block. Since the FlashAttention algorithm naturally operates on blocks of the query, key, and value matrices, this approach fits seamlessly into the existing tiling strategy. By quantizing blocks separately, the algorithm can more accurately represent the range of values within each local region, effectively mitigating the impact of outliers that would otherwise skew a global scale.

### Incoherent Processing
To further stabilize the numerical error, FlashAttention-3 uses a technique called incoherent processing. The goal is to "spread out" the impact of outlier values. This is achieved by multiplying the query $\mathbf{Q}$ and key $\mathbf{K}$ matrices with a random orthogonal matrix $\mathbf{M}$ before they are quantized to FP8.

Because $\mathbf{M}$ is orthogonal, it satisfies $\mathbf{M} \mathbf{M}^\top = I$. Consequently, the attention output remains mathematically identical: $(\mathbf{Q} \mathbf{M}) (\mathbf{K} \mathbf{M})^\top = \mathbf{Q} \mathbf{K}^\top$. In practice, this operation transforms each entry into a random sum of the original entries, effectively smoothing out outliers and reducing the quantization error. To keep this efficient, the authors use a product of random diagonal matrices of $\pm 1$ and a Hadamard matrix, which allows the multiplication to be performed in $O(d \log d)$ time and fused with other operations like rotary embeddings.

## Overcoming Hardware Constraints

Implementing FP8 is not as simple as changing a data type; it requires navigating strict hardware layout constraints. For instance, FP8 Warpgroup Matrix Multiply-Accumulate (WGMMA) instructions on Hopper GPUs require operands to be in a "k-major" format (contiguous in the inner dimension).

To resolve this, FlashAttention-3 implements an in-kernel transpose. It uses specialized instructions (LDSM and STSM) to transpose tiles of the value matrix $\mathbf{V}$ after they are loaded into shared memory. Additionally, the algorithm uses byte permute instructions to align the FP32 accumulators with the required FP8 operand layouts, ensuring that the hardware can execute these operations at peak speed.

## The Results

The combination of these techniques allows FlashAttention-3 to achieve staggering performance and accuracy:

*   **Throughput:** FP8 FlashAttention-3 reaches close to 1.2 PFLOPs/s on H100 GPUs.
*   **Accuracy:** Through block quantization and incoherent processing, the FP8 implementation is 2.6$\times$ more accurate than standard attention using per-tensor quantization when dealing with outlier features.

By bridging the gap between low-precision hardware acceleration and numerical stability, FlashAttention-3 demonstrates that we can achieve massive speedups in attention without sacrificing the precision necessary for complex reasoning and long-context modeling.

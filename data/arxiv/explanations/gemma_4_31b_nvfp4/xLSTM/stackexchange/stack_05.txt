\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### Clarification on Pre vs. Post Up-Projection in xLSTM blocks
Question:
The paper mentions two types of residual block architectures based on Cover's Theorem: post up-projection (used for sLSTM) and pre up-projection (used for mLSTM). The authors state that for mLSTM, pre up-projection is used because 'the memory capacity becomes larger in the high-dimensional space.' I'm confused about the logic here: if we project to a higher dimension *before* the mLSTM layer, does that mean the matrix memory $\mathbf{C}_t$ itself is larger, or just that the vectors $\mathbf{k}_t$ and $\mathbf{v}_t$ are larger?
Answer:
To understand the logic behind pre up-projection in mLSTM, it is helpful to look at where the projection occurs in the data flow and how that affects the internal dimensions of the mLSTM cell.

In a **pre up-projection** architecture, the input vector $\mathbf{x}_t$ (which has the model's residual dimension $d_{model}$) is first linearly projected into a higher-dimensional space $d_{high}$ before it enters the mLSTM logic. This means that the subsequent computations for the query, key, and value vectors are performed in this expanded space: $\mathbf{q}_t, \mathbf{k}_t, \mathbf{v}_t \in \mathbb{R}^{d_{high}}$. 

Because the mLSTM cell state $\mathbf{C}_t$ is defined as a matrix that stores the outer product of the value and key vectors ($\mathbf{v}_t \mathbf{k}_t^\top$), the dimensions of the memory matrix $\mathbf{C}_t$ are determined by the dimensions of these vectors. Specifically, $\mathbf{C}_t \in \mathbb{R}^{d_{high} \times d_{high}}$. Therefore, your intuition is correct: projecting to a higher dimension before the mLSTM layer makes the matrix memory $\mathbf{C}_t$ itself larger, not just the vectors.

The authors justify this using **Cover's Theorem**, which intuitively suggests that patterns that are not linearly separable in a low-dimensional space are more likely to become linearly separable when cast into a higher-dimensional space. In the context of mLSTM, the "memory capacity" refers to the ability of the matrix $\mathbf{C}_t$ to store and distinguish between different key-value pairs. By increasing $d_{high}$, the model increases the number of degrees of freedom in the covariance update rule, allowing $\mathbf{C}_t$ to store more information and better separate different contexts or "histories" before the final result is projected back down to $d_{model}$.

In contrast, the **post up-projection** used for sLSTM performs the recurrent summarization in the original space and only projects to a higher dimension for the non-linear activation (similar to the feed-forward networks in Transformers). For mLSTM, however, the "summarization" happens via the matrix $\mathbf{C}_t$, so the up-projection must happen *before* the memory update to ensure the storage mechanism itself benefits from the higher dimensionality.

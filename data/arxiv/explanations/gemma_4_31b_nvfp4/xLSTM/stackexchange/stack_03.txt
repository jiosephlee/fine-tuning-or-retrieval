\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### Why is mLSTM parallelizable while sLSTM is not?
Question:
The paper states that mLSTM is fully parallelizable, whereas sLSTM is not due to 'memory mixing' (hidden-hidden connections). From what I understand, both are recurrent models. Specifically, what is the 'memory mixing' in sLSTM that creates this sequential dependency, and why does the matrix memory structure of mLSTM remove the need for this specific type of recurrence, allowing it to be computed in parallel?
Answer:
The difference in parallelizability between sLSTM and mLSTM comes down to where the dependency on the previous time step is located. In sLSTM, the dependency is "deeply" embedded in the gating mechanism, while in mLSTM, the dependency is restricted to a linear recurrence that can be mathematically reformulated.

In sLSTM, "memory mixing" refers to the hidden-hidden connections where the previous hidden state $h_{t-1}$ is used to compute the current gates and cell inputs. Specifically, if you look at the equations for the cell input $\tilde{z}_t$, the input gate $\tilde{i}_t$, the forget gate $\tilde{f}_t$, and the output gate $\tilde{o}_t$, each one includes a recurrent term $r \cdot h_{t-1}$. Because $h_t$ is a function of $c_t$ (which depends on the gates), and the gates for the next step $t+1$ depend on $h_t$, you cannot compute the gates for step $t$ until the entire state for step $t-1$ has been finalized. This creates a strict sequential bottleneck: the model must process the sequence one token at a time because the "control logic" (the gates) is updated by the previous output.

mLSTM removes this bottleneck by abandoning memory mixing. In mLSTM, the query $\mathbf{q}_t$, key $\mathbf{k}_t$, value $\mathbf{v}_t$, and the gates $i_t, f_t, \mathbf{o}_t$ are computed as functions of the current input $\mathbf{x}_t$ only (e.g., $\mathbf{q}_t = \mathbf{W}_q \mathbf{x}_t + \mathbf{b}_q$). Crucially, there is no $h_{t-1}$ term in these calculations. This means that for a given sequence, all gates and all $\mathbf{q}, \mathbf{k}, \mathbf{v}$ vectors for every time step can be computed simultaneously in one large parallel pass across the GPU.

While mLSTM is still recurrent—meaning the matrix memory $\mathbf{C}_t$ still depends on $\mathbf{C}_{t-1}$ via the rule $\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top$—this is a linear recurrence. Because the coefficients $f_t$ and $i_t$ are independent of the previous states, the update rule is associative. This allows the recurrence to be reformulated as a parallel scan (similar to the mechanisms used in Mamba or Linear Transformers), where the state at any time $t$ can be computed using a prefix-sum-like operation. In short, sLSTM is sequential because its *logic* is recurrent, whereas mLSTM is parallelizable because only its *state* is recurrent.

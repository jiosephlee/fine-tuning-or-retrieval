\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### What is the purpose of the stabilizer state $m_t$ in sLSTM?
Question:
I'm reading the section on sLSTM and I see that they introduce exponential activation functions for the input and forget gates. The paper mentions that these can lead to overflows and introduces a stabilizer state $m_t$ defined as $m_t = \max ( \log ( f_t ) + m_{t-1} , \log ( i_t ) )$. I don't quite understand how subtracting $m_t$ from the log-gates in the stabilized versions $i'_t$ and $f'_t$ prevents overflow without changing the actual output of the network.
Answer:
The purpose of the stabilizer state $m_t$ in sLSTM is to prevent numerical overflow that occurs when using exponential activation functions for the input and forget gates. In a standard sLSTM, the gates are defined as $i_t = \exp(\tilde{i}_t)$ and $f_t = \exp(\tilde{f}_t)$. Because the exponential function grows extremely rapidly, even moderately large values of $\tilde{i}_t$ or $\tilde{f}_t$ can quickly exceed the maximum value representable by floating-point precision (e.g., float32), resulting in $\text{NaN}$ or $\text{Inf}$ values that crash the training process.

To solve this, $m_t$ acts as a running tracker of the maximum "log-scale" of the memory. This is conceptually very similar to the "Log-Sum-Exp" trick used to stabilize the softmax function. The state is updated as $m_t = \max(\log(f_t) + m_{t-1}, \log(i_t))$. By tracking the maximum of the current input gate and the accumulated forget gate history, $m_t$ identifies the largest exponent present in the cell state update. When we compute the stabilized gates $i'_t = \exp(\log(i_t) - m_t)$ and $f'_t = \exp(\log(f_t) + m_{t-1} - m_t)$, we are effectively subtracting the maximum value from the exponents. Since the exponent of any value $\le 0$ is guaranteed to be between 0 and 1, these stabilized gates are numerically bounded and cannot overflow.

The reason this does not change the actual output of the network lies in the normalization step. The sLSTM computes a hidden state $\tilde{h}_t = c_t / n_t$, where $c_t$ is the cell state and $n_t$ is the normalizer state. Both $c_t$ and $n_t$ are governed by the same exponential gates: $c_t = f_t c_{t-1} + i_t z_t$ and $n_t = f_t n_{t-1} + i_t$. By introducing $m_t$, we are essentially factoring out $\exp(m_t)$ from both the numerator ($c_t$) and the denominator ($n_t$). Because this common scaling factor $\exp(m_t)$ appears in both terms, it cancels out during the division $c_t / n_t$. Consequently, the final hidden state $\tilde{h}_t$ remains mathematically identical to what it would have been without stabilization, but the intermediate computations remain within a numerically safe range.

### How does exponential gating allow the model to 'revise' storage decisions?
Question:
In the introduction, the authors claim that standard LSTMs are unable to revise storage decisions, specifically citing the Nearest Neighbor Search problem. They argue that xLSTM remediates this through exponential gating. Conceptually, why does changing the gate activation from a sigmoid $\sigma(x)$ to an exponential $\exp(x)$ enable the model to 'overwrite' or 'revise' a previously stored value in the cell state $c_t$ more effectively?
Answer:
To understand why exponential gating allows xLSTM to "revise" storage decisions, it is helpful to first look at the limitation of the standard LSTM. In a traditional LSTM, the input gate $i_t$ and forget gate $f_t$ use the sigmoid function $\sigma(x)$, which strictly bounds the gate values between $0$ and $1$. Because these values are capped, the update to the cell state $c_t = f_t c_{t-1} + i_t z_t$ is essentially an additive process. If the model has stored a value and later encounters a new, more relevant value (as in the Nearest Neighbor Search problem), the sigmoid gates cannot "overpower" the existing memory instantaneously; they can only gradually forget the old value or add the new one, often resulting in a blurred average of the two.

xLSTM replaces these sigmoid activations with the exponential function $\exp(x)$. Unlike the sigmoid, the exponential function is unbounded, allowing the gate values to become very large. However, simply using $\exp(x)$ would lead to numerical instability and exploding values. To counter this, the authors introduce a normalizer state $n_t$, which tracks the cumulative weight of the inputs and forget gates: $n_t = f_t n_{t-1} + i_t$. The hidden state is then computed as the normalized cell state: $\tilde{h}_t = c_t / n_t$.

Intuitively, this structure transforms the memory update into a weighted average where the weights can vary by orders of magnitude. When the model encounters a highly relevant piece of information, the exponential input gate $i_t = \exp(\tilde{i}_t)$ can produce a value significantly larger than the accumulated weight of the previous state $f_t n_{t-1}$. In the calculation $\tilde{h}_t = (f_t c_{t-1} + i_t z_t) / (f_t n_{t-1} + i_t)$, a massive $i_t$ dominates both the numerator and the denominator. This effectively "flushes" the influence of the previous cell state $c_{t-1}$ and allows the new value $z_t$ to take over the memory. 

This "winner-take-all" dynamic is what enables the model to revise its storage decisions. Instead of merely adding new information to a buffer, the exponential gating allows the model to decide that a new discovery is so much more important than the previous one that it should completely overwrite the previous memory. This capability is critical for tasks like Nearest Neighbor Search, where the model must maintain the "best" match found so far and be able to replace it immediately when an even better match is encountered in the sequence.

### Why is mLSTM parallelizable while sLSTM is not?
Question:
The paper states that mLSTM is fully parallelizable, whereas sLSTM is not due to 'memory mixing' (hidden-hidden connections). From what I understand, both are recurrent models. Specifically, what is the 'memory mixing' in sLSTM that creates this sequential dependency, and why does the matrix memory structure of mLSTM remove the need for this specific type of recurrence, allowing it to be computed in parallel?
Answer:
The difference in parallelizability between sLSTM and mLSTM comes down to where the dependency on the previous time step is located. In sLSTM, the dependency is "deeply" embedded in the gating mechanism, while in mLSTM, the dependency is restricted to a linear recurrence that can be mathematically reformulated.

In sLSTM, "memory mixing" refers to the hidden-hidden connections where the previous hidden state $h_{t-1}$ is used to compute the current gates and cell inputs. Specifically, if you look at the equations for the cell input $\tilde{z}_t$, the input gate $\tilde{i}_t$, the forget gate $\tilde{f}_t$, and the output gate $\tilde{o}_t$, each one includes a recurrent term $r \cdot h_{t-1}$. Because $h_t$ is a function of $c_t$ (which depends on the gates), and the gates for the next step $t+1$ depend on $h_t$, you cannot compute the gates for step $t$ until the entire state for step $t-1$ has been finalized. This creates a strict sequential bottleneck: the model must process the sequence one token at a time because the "control logic" (the gates) is updated by the previous output.

mLSTM removes this bottleneck by abandoning memory mixing. In mLSTM, the query $\mathbf{q}_t$, key $\mathbf{k}_t$, value $\mathbf{v}_t$, and the gates $i_t, f_t, \mathbf{o}_t$ are computed as functions of the current input $\mathbf{x}_t$ only (e.g., $\mathbf{q}_t = \mathbf{W}_q \mathbf{x}_t + \mathbf{b}_q$). Crucially, there is no $h_{t-1}$ term in these calculations. This means that for a given sequence, all gates and all $\mathbf{q}, \mathbf{k}, \mathbf{v}$ vectors for every time step can be computed simultaneously in one large parallel pass across the GPU.

While mLSTM is still recurrent—meaning the matrix memory $\mathbf{C}_t$ still depends on $\mathbf{C}_{t-1}$ via the rule $\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top$—this is a linear recurrence. Because the coefficients $f_t$ and $i_t$ are independent of the previous states, the update rule is associative. This allows the recurrence to be reformulated as a parallel scan (similar to the mechanisms used in Mamba or Linear Transformers), where the state at any time $t$ can be computed using a prefix-sum-like operation. In short, sLSTM is sequential because its *logic* is recurrent, whereas mLSTM is parallelizable because only its *state* is recurrent.

### Relationship between mLSTM matrix memory and Transformer attention
Question:
The mLSTM uses a covariance update rule $\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top$ and retrieves information via $\mathbf{C}_t \mathbf{q}_t$. This looks very similar to the key-value retrieval mechanism in Transformers. Is the matrix $\mathbf{C}_t$ essentially acting as a compressed representation of the KV cache? If so, how does the use of a fixed-size $d \times d$ matrix differ from the growing KV cache in a standard Transformer in terms of what information is preserved?
Answer:
Yes, your intuition is correct: the matrix $\mathbf{C}_t$ in mLSTM acts as a **compressed, fixed-size representation of the Key-Value (KV) cache**. 

In a standard Transformer, the KV cache stores every single key $\mathbf{k}_j$ and value $\mathbf{v}_j$ vector for every token $j$ in the sequence. To retrieve information, the model computes a weighted sum: $\sum_{j=1}^t \alpha_j \mathbf{v}_j$, where $\alpha_j$ is the attention weight derived from $\mathbf{q}_t^\top \mathbf{k}_j$. This requires memory that grows linearly with the sequence length $T$, leading to $O(T)$ space complexity and $O(T)$ time complexity per token during inference.

The mLSTM transforms this process by leveraging the associative property of matrix multiplication. By using the covariance update rule $\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top$, the mLSTM stores the "sum" of these key-value interactions directly into a $d \times d$ matrix. When the model performs the retrieval $\mathbf{C}_t \mathbf{q}_t$, it is mathematically equivalent to computing a weighted sum of all previous value vectors, where the weights are the dot products of the query $\mathbf{q}_t$ and the keys $\mathbf{k}_j$ stored within the matrix.

The fundamental difference between the fixed-size matrix $\mathbf{C}_t$ and the growing KV cache lies in **precision versus capacity**:

1.  **Exact vs. Compressive Storage**: A Transformer KV cache is an "exact" memory; it preserves every token's representation perfectly. In contrast, mLSTM is "compressive." Because $\mathbf{C}_t$ has a fixed size ($d \times d$), it cannot store an infinite number of key-value pairs without interference. As more information is added, older or less relevant information is effectively "overwritten" or blurred.
2.  **Information Management**: In a Transformer, the "forgetting" is handled by the softmax attention mechanism, which decides what to ignore at the moment of retrieval. In mLSTM, forgetting is explicit and happens during the *update* phase via the forget gate $f_t$. This allows the model to actively decide which historical information to discard to make room for new data.
3.  **Complexity Trade-off**: The mLSTM trades the ability to recall every single token perfectly (the "gold standard" of Transformers) for constant memory complexity $O(1)$ and linear time complexity $O(1)$ relative to the sequence length. 

The paper notes that this matrix structure is significantly more powerful than the scalar memory of traditional LSTMs, allowing it to perform well on "Associative Recall" tasks. While it doesn't have the infinite precision of a full KV cache, the $d \times d$ dimensionality provides enough capacity to maintain high separability of information, making it a viable alternative for scaling to long contexts without the quadratic memory bottleneck.

### Clarification on Pre vs. Post Up-Projection in xLSTM blocks
Question:
The paper mentions two types of residual block architectures based on Cover's Theorem: post up-projection (used for sLSTM) and pre up-projection (used for mLSTM). The authors state that for mLSTM, pre up-projection is used because 'the memory capacity becomes larger in the high-dimensional space.' I'm confused about the logic here: if we project to a higher dimension *before* the mLSTM layer, does that mean the matrix memory $\mathbf{C}_t$ itself is larger, or just that the vectors $\mathbf{k}_t$ and $\mathbf{v}_t$ are larger?
Answer:
To understand the logic behind pre up-projection in mLSTM, it is helpful to look at where the projection occurs in the data flow and how that affects the internal dimensions of the mLSTM cell.

In a **pre up-projection** architecture, the input vector $\mathbf{x}_t$ (which has the model's residual dimension $d_{model}$) is first linearly projected into a higher-dimensional space $d_{high}$ before it enters the mLSTM logic. This means that the subsequent computations for the query, key, and value vectors are performed in this expanded space: $\mathbf{q}_t, \mathbf{k}_t, \mathbf{v}_t \in \mathbb{R}^{d_{high}}$. 

Because the mLSTM cell state $\mathbf{C}_t$ is defined as a matrix that stores the outer product of the value and key vectors ($\mathbf{v}_t \mathbf{k}_t^\top$), the dimensions of the memory matrix $\mathbf{C}_t$ are determined by the dimensions of these vectors. Specifically, $\mathbf{C}_t \in \mathbb{R}^{d_{high} \times d_{high}}$. Therefore, your intuition is correct: projecting to a higher dimension before the mLSTM layer makes the matrix memory $\mathbf{C}_t$ itself larger, not just the vectors.

The authors justify this using **Cover's Theorem**, which intuitively suggests that patterns that are not linearly separable in a low-dimensional space are more likely to become linearly separable when cast into a higher-dimensional space. In the context of mLSTM, the "memory capacity" refers to the ability of the matrix $\mathbf{C}_t$ to store and distinguish between different key-value pairs. By increasing $d_{high}$, the model increases the number of degrees of freedom in the covariance update rule, allowing $\mathbf{C}_t$ to store more information and better separate different contexts or "histories" before the final result is projected back down to $d_{model}$.

In contrast, the **post up-projection** used for sLSTM performs the recurrent summarization in the original space and only projects to a higher dimension for the non-linear activation (similar to the feed-forward networks in Transformers). For mLSTM, however, the "summarization" happens via the matrix $\mathbf{C}_t$, so the up-projection must happen *before* the memory update to ensure the storage mechanism itself benefits from the higher dimensionality.

Chapter 4: # mLSTM: Matrix Memory and Parallelization

The mLSTM (matrix LSTM) represents a significant evolution of the traditional Long Short-Term Memory architecture, specifically designed to address the limitations of storage capacity and computational efficiency. While standard LSTMs rely on scalar memory cells, the mLSTM elevates the memory structure to a matrix, allowing it to capture and retrieve complex associations between pieces of information. By combining this expanded memory with a reformulated recurrence that removes hidden-to-hidden connections, the mLSTM achieves full parallelizability, making it a viable competitor to Transformer-based architectures in large-scale language modeling.

# The concept of Matrix Memory: Moving beyond scalars

The fundamental limitation of the original LSTM is its reliance on scalar memory cells. In a standard LSTM, information is compressed into a scalar cell state $c \in \mathbb{R}$, which serves as the primary processing and storage unit. While this structure was revolutionary for solving the vanishing gradient problem, it creates a bottleneck when the model needs to remember a large number of distinct pieces of information. This limited storage capacity becomes particularly evident in tasks requiring the recall of rare tokens or complex associative patterns, as the model struggles to squeeze diverse semantic information into a single scalar value.

To overcome this, the mLSTM introduces a matrix memory, replacing the scalar cell state with a matrix $\mathbf{C} \in \mathbb{R}^{d \times d}$. This shift from a scalar to a matrix fundamentally changes how the model stores information. Instead of compressing the state into a single value, the mLSTM can maintain a high-dimensional representation of the sequence's history. By using a matrix, the model can store associations between different vectors, effectively transforming the memory from a simple accumulator into an associative memory system. This allows the model to handle significantly more information without the loss of detail associated with scalar compression.

# The Covariance Update Rule: Storing key-value pairs

The mechanism used to update the matrix memory in the mLSTM is known as the covariance update rule. In this framework, the model does not simply add a value to the memory; instead, it stores a pair of vectors: a key $\mathbf{k}_t \in \mathbb{R}^d$ and a value $\mathbf{v}_t \in \mathbb{R}^d$. The cell state is updated according to the following rule:

$\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top$

In this equation, the term $\mathbf{v}_t \mathbf{k}_t^\top$ represents the outer product of the value and key vectors, which creates a rank-1 matrix that encodes the association between the key and the value. The input gate $i_t$ acts as a learning rate, determining how much of the new association is integrated into the memory, while the forget gate $f_t$ acts as a decay rate, controlling how quickly old memories are forgotten. This approach is rooted in the concept of Fast Weight Programmers, where the memory is updated dynamically as the sequence progresses.

The covariance update rule is particularly powerful because it is optimal for achieving maximal separability of retrieved binary vectors, which is equivalent to maximizing the signal-to-noise ratio during retrieval. By utilizing this rule, the mLSTM can effectively "write" associations into its matrix memory, ensuring that the stored values can be distinguished and retrieved accurately later in the sequence.

# Retrieval mechanism: Query, Key, and Value (QKV) framework

Retrieving information from the matrix memory $\mathbf{C}_t$ is achieved using a framework similar to the Query, Key, and Value (QKV) system found in Transformers. To retrieve a value, the model generates a query vector $\mathbf{q}_t \in \mathbb{R}^d$. The retrieval process is essentially a matrix-vector multiplication: the current memory matrix $\mathbf{C}_t$ is multiplied by the query vector $\mathbf{q}_t$ to produce a retrieved hidden state.

The specific projections for these vectors are defined as follows:
The query is computed as $\mathbf{q}_t = \mathbf{W}_q \mathbf{x}_t + \mathbf{b}_q$.
The key is computed as $\mathbf{k}_t = \frac{1}{\sqrt{d}} \mathbf{W}_k \mathbf{x}_t + \mathbf{b}_k$.
The value is computed as $\mathbf{v}_t = \mathbf{W}_v \mathbf{x}_t + \mathbf{b}_v$.

Once the raw retrieved vector $\tilde{\mathbf{h}}_t$ is computed (via the interaction of $\mathbf{C}_t$ and $\mathbf{q}_t$), it is further refined by an output gate $\mathbf{o}_t$. The final hidden state $\mathbf{h}_t$ is produced by the element-wise product:

$\mathbf{h}_t = \mathbf{o}_t \odot \tilde{\mathbf{h}}_t$

where the output gate is determined by $\mathbf{o}_t = \sigma(\mathbf{W}_{\mathbf{o}} \mathbf{x}_t + \mathbf{b}_{\mathbf{o}})$. This structure allows the model to not only retrieve the most relevant information from its matrix memory but also to control which parts of that retrieved information are actually passed on to the next layer.

# Normalizing retrieval in mLSTM: Using the normalizer state dot-product

Because the matrix memory $\mathbf{C}_t$ is updated additively, the magnitude of the retrieved vector can grow as more information is stored, potentially leading to instabilities. To prevent this, the mLSTM employs a normalizer state $\mathbf{n}_t$, which keeps track of the total "strength" of the keys stored in the memory. The normalizer state is updated similarly to the cell state but stores a weighted sum of the key vectors:

$\mathbf{n}_t = f_t \mathbf{n}_{t-1} + i_t \mathbf{k}_t$

During retrieval, the retrieved vector $\mathbf{C}_t \mathbf{q}_t$ is divided by the dot product of the normalizer state and the query vector. This ensures that the output is normalized relative to the amount of information associated with the current query. Specifically, the normalized retrieved state is:

$\tilde{\mathbf{h}}_t = \mathbf{C}_t \mathbf{q}_t / \max \{ |\mathbf{n}_t^\top \mathbf{q}_t|, 1 \}$

The use of the absolute value and a lower bound of $1$ is a stabilization technique. It prevents division by zero or extremely small numbers when the dot product between the query and the normalizer state is close to zero, ensuring numerical stability during the forward pass.

# Breaking the sequential chain: How mLSTM achieves full parallelizability

One of the most significant hurdles for traditional LSTMs is the lack of parallelizability. This is caused by "memory mixing," which refers to the hidden-hidden recurrent connections where the hidden state $\mathbf{h}_{t-1}$ is required to compute the gates and the cell input for the next time step $t$. This creates a strict sequential dependency, forcing the model to process tokens one by one.

The mLSTM overcomes this limitation by completely abandoning memory mixing. In the mLSTM architecture, the gates ($i_t, f_t, \mathbf{o}_t$) and the QKV vectors ($\mathbf{q}_t, \mathbf{k}_t, \mathbf{v}_t$) depend only on the current input $\mathbf{x}_t$ and not on the previous hidden state $\mathbf{h}_{t-1}$. Because the update to the matrix memory $\mathbf{C}_t$ and the normalizer state $\mathbf{n}_t$ is linear with respect to these inputs, the entire recurrence can be reformulated. 

This reformulation allows the mLSTM to be computed in a parallel version, similar to how FlashAttention or State Space Models operate. While the memory is still logically recurrent, the mathematical structure allows the GPU to compute the states for all time steps simultaneously rather than sequentially. This drastically reduces the wall-clock time required for training and inference, enabling the scaling of LSTMs to billions of parameters.

# Comparison between mLSTM and Bidirectional Associative Memories (BAMs)

The theoretical foundation of the mLSTM's retrieval process is closely aligned with Bidirectional Associative Memories (BAMs). BAMs are a class of neural networks designed to store associations between pairs of patterns. In a BAM, the network is trained to associate a key vector with a value vector such that providing the key allows for the retrieval of the value, and vice versa.

The mLSTM adopts this specific setting by storing key-value pairs $(\mathbf{k}_t, \mathbf{v}_t)$ and retrieving the value $\mathbf{v}_t$ later in the sequence using a query $\mathbf{q}_{t+\tau}$. By implementing the covariance update rule, the mLSTM essentially functions as a dynamic BAM that evolves over time. Unlike a static BAM, however, the mLSTM integrates this associative memory into a gated recurrent framework, allowing it to selectively forget old associations and prioritize new ones through its input and forget gates. This integration blends the high-capacity associative recall of BAMs with the temporal flexibility of LSTMs.

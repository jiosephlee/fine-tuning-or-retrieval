\title{A Textbook about the Paper: "xLSTM: Extended Long Short-Term Memory"}

Introduction to Recurrent Architectures and the Original LSTM

# The Vanishing Gradient Problem in RNNs

Recurrent Neural Networks (RNNs) were designed to process sequential data by maintaining a hidden state that evolves over time. However, a fundamental challenge plagued these early architectures: the vanishing gradient problem. In standard RNNs, as the sequence length increases, the gradients used during backpropagation can shrink exponentially. This happens because the network repeatedly multiplies gradients by the weight matrices associated with the recurrent connections. When these weights are small, the gradient effectively vanishes before it can reach the earlier steps of the sequence.

The practical consequence of this phenomenon is that the network "forgets" information from the distant past. The model becomes unable to learn long-term dependencies, meaning it cannot correlate an input from the beginning of a long sentence with an output at the end. To address this failure, the Long Short-Term Memory (LSTM) was introduced. By changing how the network updates its internal state, LSTMs provide a mechanism that allows gradients to flow through time without disappearing, enabling the model to learn relationships across much longer sequences.

# The Constant Error Carousel (CEC) concept

The central innovation that allows LSTMs to overcome the vanishing gradient problem is the Constant Error Carousel (CEC). In a traditional RNN, the state update is typically multiplicative, which is the primary cause of gradient decay. The CEC replaces this with an additive update rule for the internal memory. Instead of the state being completely overwritten at each time step, the LSTM maintains a cell state that acts as a high-speed conveyor belt, allowing information to flow through the sequence with minimal interference.

The additive nature of the CEC is mathematically represented by the way the cell state $c_t$ is updated. By adding new information to the existing state rather than simply multiplying the old state by a weight matrix, the network creates a path where the error signal can remain constant. This "carousel" effect ensures that the gradient does not vanish as it propagates backward through time, allowing the model to maintain a stable memory of important events that occurred many time steps ago.

# The anatomy of a classic LSTM cell: Cell state and Hidden state

A classic LSTM cell is defined by two distinct states: the cell state and the hidden state. The cell state, denoted as $c_t$, serves as the primary internal memory. It is a scalar value (or a vector of scalars in multi-cell implementations) that stores the long-term information of the sequence. The cell state is modified incrementally via the CEC, meaning it only changes when the network explicitly decides to add or remove information.

The hidden state, denoted as $h_t$, is the external representation of the cell. While the cell state is the internal "storage," the hidden state is the "output" that is passed to the next layer or the next time step. The hidden state is derived from the cell state, but it is not a direct copy. Instead, the cell state is first passed through a normalization or squashing function $\psi$ and then filtered by an output gate. This separation ensures that the internal memory can remain complex and unbounded, while the output remains controlled and normalized.

# The role of Gating: Input, Forget, and Output gates

To manage the information flowing into and out of the cell state, LSTMs utilize a system of sigmoid gates. These gates act as valves that control the flow of information, allowing the network to decide what is worth remembering and what should be discarded.

The forget gate $f_t$ determines which information from the previous cell state $c_{t-1}$ is no longer relevant and should be removed. It produces a value between 0 and 1; a value near 0 means "forget this," while a value near 1 means "keep this." Following this, the input gate $i_t$ controls the addition of new information. It decides which parts of the new cell input $z_t$ are important enough to be stored in the cell state. The combined effect of these two gates results in the cell state update: $c_t = f_t c_{t-1} + i_t z_t$.

Finally, the output gate $o_t$ controls what information is extracted from the cell state to produce the hidden state $h_t$. Since the cell state $c_t$ contains all the accumulated memory, the output gate allows the model to selectively share only the specific information needed for the current time step. This gating mechanism allows the LSTM to be highly flexible, adjusting its memory dynamically based on the input sequence.

# Activation functions in LSTMs: Sigmoid and Tanh

The functionality of the LSTM depends heavily on its choice of activation functions. The gates—input, forget, and output—all use the sigmoid function, $\sigma(x) = 1 / (1 + \exp(-x))$. The sigmoid function is essential for gating because it squashes any input into a range between 0 and 1. This range is intuitively treated as a percentage of information allowed to pass through the gate, making it perfect for "opening" or "closing" the flow of data.

In contrast, the cell input $z_t$ and the normalization of the cell state $\psi$ typically use the $\tanh$ (hyperbolic tangent) function. The $\tanh$ function squashes values into a range between -1 and 1. For the cell input, this ensures that the values being added to the memory are centered around zero and do not grow uncontrollably. For the hidden state calculation, $\psi(c_t)$ is used to squash the potentially unbounded cell state before it is multiplied by the output gate, ensuring the resulting hidden state $h_t$ remains stable for the subsequent layers of the network.

# Historical success stories of LSTMs in sequence modeling

Before the rise of Transformers, LSTMs were the dominant architecture for nearly all sequence-related tasks. Their ability to learn abstractions and extract semantic information allowed them to excel in text generation and sequence-to-sequence translation. They were used to generate handwriting, evaluate computer programs, and produce image captions and source code. Beyond linguistics, LSTMs proved invaluable in scientific modeling, such as rainfall-runoff modeling and creating hydrological models for flooding warnings.

LSTMs also achieved significant breakthroughs in reinforcement learning. They served as the core of high-profile models such as AlphaStar for StarCraft II and the OpenAI Five for Dota 2, as well as models used to control magnetic controllers for nuclear fusion. A key reason for this success was the LSTM's capacity to develop specialized "neurons." Researchers discovered that LSTMs could evolve specific neurons dedicated to tracking number, syntax, linguistics, and sentiment, demonstrating their power to represent complex, high-level concepts within their memory cells.

Identifying the Bottlenecks: Why LSTMs Were Outpaced

# The Storage Revision Problem: Analysis of the Nearest Neighbor Search task

To understand why the traditional Long Short-Term Memory (LSTM) architecture eventually fell behind more modern architectures, we must first examine its inability to effectively revise storage decisions. In a standard LSTM, the memory is managed through gating mechanisms—specifically the input and forget gates—which determine what information is added to the cell state and what is discarded. However, this mechanism is not always flexible enough to update a stored value when a superior or more relevant piece of information is encountered later in a sequence.

This limitation is most clearly demonstrated through the Nearest Neighbor Search problem. In this task, the model is provided with a reference vector and must scan a sequence of vectors. The goal is to identify the vector in the sequence that is most similar to the reference vector and provide the value attached to that specific vector at the end of the sequence. For a model to succeed, it must be able to store a value when it finds a "similar" vector, but then be capable of revising that stored value if a "more similar" vector appears further along in the sequence.

The traditional LSTM struggles with this process. Because it cannot effectively revise its previous storage decisions, the mean squared error on this task remains high. The architecture fails to dynamically update its memory in response to the relative similarity of new inputs compared to what has already been stored. This represents a fundamental flaw in the way the original LSTM manages its internal state, creating a bottleneck in its ability to perform complex retrieval and update tasks.

# The Capacity Bottleneck: Why scalar memory struggles with Rare Token Prediction

Another significant limitation of the original LSTM is its restricted storage capacity. The central processing and storage unit of an LSTM is the scalar memory cell. In this architecture, all the semantic information and context from a sequence must be compressed into these scalar cell states. While this compression is efficient for some tasks, it creates a bottleneck when the model needs to remember a large volume of distinct information or maintain a high level of precision for infrequent data.

This capacity issue is exemplified by the Rare Token Prediction task using the Wikitext-103 dataset. When analyzing the perplexity of token prediction—a measure of how well the model predicts the next token—it becomes evident that LSTMs perform significantly worse on rare tokens compared to frequent ones. Because the model must compress all necessary information into a scalar state, the "space" within that memory is limited. Common tokens, which appear frequently, tend to dominate the memory, while the information required to accurately predict rare tokens is often lost or overwritten during the compression process.

Ultimately, the reliance on scalar memory means that the LSTM cannot scale its storage capacity to meet the demands of massive datasets with diverse vocabularies. When information is forced into a scalar bottleneck, the model loses the ability to maintain the granular distinctions necessary for high-performance language modeling, particularly when dealing with the "long tail" of rare linguistic elements.

# The Sequential Processing Constraint: Memory mixing and the lack of parallelizability

Beyond storage and capacity, the LSTM architecture suffers from a structural constraint regarding how it processes data. The original LSTM relies on memory mixing, which refers to the hidden-hidden recurrent connections between the hidden state of one time step and the next. This means that the hidden state $h_t$ is dependent on the previous hidden state $h_{t-1}$.

This dependency creates a strict sequential processing requirement. Because the model must compute the state for time step $t$ before it can move to $t+1$, the computation cannot be spread across the parallel processing units of modern hardware, such as GPUs. In the context of modern deep learning, where training is performed on massive datasets, the inability to parallelize the training process is a devastating disadvantage.

This lack of parallelizability is what allowed Transformer technology to dominate. Transformers utilize self-attention, which is inherently parallelizable across the entire sequence length. While the LSTM's sequential nature was originally intended to handle the temporal flow of information, it became a computational liability. The "hidden-hidden" connections that enable state tracking also prevent the model from leveraging the same scaling efficiencies that allow Transformers to be trained on billions of tokens in a fraction of the time it would take a sequential model.

# Comparing LSTM memory to Transformer self-attention

When comparing the memory mechanisms of LSTMs to those of Transformers, the difference in efficiency and capacity becomes stark. An LSTM's memory is compressive; it attempts to squeeze the entire history of a sequence into a fixed-size state. While this results in linear computation and constant memory complexity with respect to sequence length, it comes at the cost of precision and retrieval accuracy.

In contrast, the Transformer's self-attention mechanism can be viewed as a form of memory that is exponential in the coding dimension. This allows Transformers to act as the gold standard for associative recall tasks, such as the Multi-Query Associative Recall task, where a model must memorize and retrieve specific key-value pairs from a large vocabulary. Because Transformers do not compress the sequence into a single scalar state in the same way LSTMs do, they can maintain a more precise record of the input sequence, allowing for far more accurate retrieval of specific information.

However, this high capacity comes with a trade-off: quadratic complexity. While LSTMs are efficient in terms of memory and computation per token, they cannot store as much. Transformers can store vastly more and retrieve it more accurately, but they require significantly more computational resources as the sequence length increases. This dichotomy highlights the need for a new architecture that combines the constant memory complexity of recurrent models with the high storage capacity and parallelizability of attention-based models.

# The motivation for xLSTM: Scaling LSTMs to billions of parameters

The emergence of Transformers and State Space Models (SSMs) was not a sign that the core ideas of the LSTM—such as the constant error carousel and gating—were obsolete, but rather that their implementation had reached a limit. The fundamental question driving the development of xLSTM is: how far can we push language modeling if we scale LSTMs to billions of parameters while specifically mitigating these three known limitations?

The motivation for xLSTM is to evolve the LSTM by addressing the storage revision problem, the capacity bottleneck, and the sequential processing constraint. To do this, xLSTM introduces exponential gating to allow the model to revise its storage decisions more effectively. It also introduces a matrix memory structure, moving beyond scalar states to provide the capacity necessary for rare token prediction and complex associative recall. Finally, by modifying the memory structure, xLSTM seeks to introduce parallelizability, allowing the model to scale in a manner similar to modern Large Language Models (LLMs).

By integrating these enhancements into residual block backbones and stacking them, the xLSTM architecture aims to prove that the recurrent paradigm can match or even exceed the performance of Transformers and SSMs. The goal is to maintain the linear computation and constant memory complexity of the original LSTM while achieving the scaling laws and performance metrics of the current generation of LLMs.

# sLSTM: Exponential Gating and Scalar Memory Evolution

The scalar Extended Long Short-Term Memory, or sLSTM, is a fundamental component of the xLSTM architecture designed to address specific shortcomings of the traditional LSTM. While the original LSTM was revolutionary in its use of the constant error carousel to mitigate vanishing gradients, it suffered from a limited ability to revise its storage decisions. This means that once a value was stored in the cell state, the model struggled to effectively replace it when a more relevant or similar piece of information appeared later in a sequence. The sLSTM evolves the scalar memory cell by introducing exponential gating and a new normalization framework, allowing the model to be far more flexible in how it manages and updates its internal state.

# From Sigmoid to Exponential Gating: Enabling storage revision

The primary innovation of the sLSTM is the transition from sigmoid gating to exponential gating for the input and forget gates. In a traditional LSTM, gates are typically constrained by a sigmoid function, which limits their output to a range between $0$ and $1$. While this is effective for "forgetting" or "blocking" information, it creates a bottleneck when the model needs to rapidly overwrite a stored value. This limitation is particularly evident in tasks like the Nearest Neighbor Search, where a model must scan a sequence and update its stored value whenever it encounters a vector more similar to a given reference than the one previously stored.

By replacing the sigmoid activation with an exponential function, $\exp(\cdot)$, the sLSTM allows the gates to take on values significantly larger than $1$. This capability enables the model to "push" new information into the memory with much greater strength and to revise previous storage decisions more aggressively. Essentially, exponential gating allows the model to prioritize new, more relevant information over old data far more effectively than the bounded sigmoid gates of the original LSTM.

# The Normalizer State ($n_t$): Ensuring mathematical consistency

A significant challenge arises when using exponential gates: the cell state $c_t$ can grow rapidly and become unbounded, unlike the original LSTM where a squashing function $\psi$ (typically $\tanh$) was used to normalize the output. To maintain mathematical consistency and prevent the hidden state from exploding, the sLSTM introduces a normalizer state, denoted as $n_t$.

The normalizer state $n_t$ acts as a running tally of the total "weight" applied to the memory cell. It is updated using the same logic as the cell state, but instead of adding a weighted cell input, it simply sums the input gate values, moderated by the forget gate: $n_t = f_t n_{t-1} + i_t$. When the model needs to produce the hidden state $h_t$, it does not simply apply a non-linear squashing function to $c_t$. Instead, it divides the cell state by the normalizer state: $\tilde{h}_t = c_t / n_t$. This normalization ensures that the output remains stable regardless of the magnitude of the exponential gates, effectively keeping the hidden state in a manageable range.

# Numerical Stability: The Stabilizer State ($m_t$) and overflow prevention

While exponential gating is theoretically powerful, it is numerically precarious. In practical computer implementations, $\exp(x)$ can produce extremely large numbers very quickly, leading to floating-point overflows that would crash the model training. To prevent this, the sLSTM employs a stabilization technique involving a stabilizer state $m_t$.

The stabilizer state $m_t$ tracks the maximum log-value of the gating operations to keep the exponents within a safe numerical range. It is updated as $m_t = \max(\log(f_t) + m_{t-1}, \log(i_t))$. By calculating the gates in the log-domain and then subtracting $m_t$ before exponentiating, the model can produce stabilized versions of the input and forget gates: $i'_t = \exp(\log(i_t) - m_t)$ and $f'_t = \exp(\log(f_t) + m_{t-1} - m_t)$. This mathematical transformation ensures that the actual output of the network and the gradients of the loss function remain unchanged, but the internal computations avoid the overflow issues associated with raw exponential functions.

# The sLSTM forward pass: Detailed step-by-step derivation

The forward pass of a scalar sLSTM can be broken down into the calculation of the cell input, the gating mechanisms, the update of the internal states, and the final output. Given an input $\mathbf{x}_t$ and the previous hidden state $h_{t-1}$, the model first computes the cell input $z_t$ and the pre-activation values for the gates:

The cell input is derived as $z_t = \varphi(\tilde{z}_t)$, where $\tilde{z}_t = \mathbf{w}^\top_{z} \mathbf{x}_t + r_{z} h_{t-1} + b_{z}$. Similarly, the pre-activation values for the input gate ($\tilde{i}_t$), forget gate ($\tilde{f}_t$), and output gate ($\tilde{o}_t$) are computed using their respective weights $\mathbf{w}$, recurrent weights $r$, and biases $b$:
$\tilde{i}_t = \mathbf{w}^\top_{i} \mathbf{x}_t + r_{i} h_{t-1} + b_{i}$
$\tilde{f}_t = \mathbf{w}^\top_{f} \mathbf{x}_t + r_{f} h_{t-1} + b_{f}$
$\tilde{o}_t = \mathbf{w}^\top_{o} \mathbf{x}_t + r_{o} h_{t-1} + b_{o}$

The gates are then activated. The input gate $i_t$ uses the exponential function $\exp(\tilde{i}_t)$, the forget gate $f_t$ can use either $\sigma(\tilde{f}_t)$ or $\exp(\tilde{f}_t)$, and the output gate $o_t$ uses the sigmoid $\sigma(\tilde{o}_t)$. 

With these gates, the cell state and normalizer state are updated:
$c_t = f_t c_{t-1} + i_t z_t$
$n_t = f_t n_{t-1} + i_t$

Finally, the hidden state $h_t$ is produced by normalizing the cell state and applying the output gate: $h_t = o_t (c_t / n_t)$.

# Memory Mixing in sLSTM: Recurrent connections and the introduction of heads

While the basic sLSTM operates on a scalar memory cell, it can be expanded to use multiple memory cells. This expansion allows for "memory mixing," where the states of different cells interact with one another. In a multi-cell sLSTM, the recurrent weights $r$ are replaced by recurrent weight matrices $\mathbf{R}_{z}, \mathbf{R}_{i}, \mathbf{R}_{f}, \mathbf{R}_{o}$, which map the hidden state vector $\mathbf{h}$ to the inputs and gates of the memory cells.

A novel aspect of the sLSTM's memory mixing is the introduction of "heads." The sLSTM can be structured with multiple heads, where memory mixing occurs between the cells within a single head, but no mixing occurs across different heads. This architecture combines the power of exponential gating with a structured way of organizing memory. By partitioning the memory into heads, the model can maintain separate "streams" of information, each performing its own state tracking and revision internally, while remaining isolated from other heads. This allows the sLSTM to capture a wider array of semantic abstractions and complex dependencies in a sequence.

# mLSTM: Matrix Memory and Parallelization

The mLSTM (matrix LSTM) represents a significant evolution of the traditional Long Short-Term Memory architecture, specifically designed to address the limitations of storage capacity and computational efficiency. While standard LSTMs rely on scalar memory cells, the mLSTM elevates the memory structure to a matrix, allowing it to capture and retrieve complex associations between pieces of information. By combining this expanded memory with a reformulated recurrence that removes hidden-to-hidden connections, the mLSTM achieves full parallelizability, making it a viable competitor to Transformer-based architectures in large-scale language modeling.

# The concept of Matrix Memory: Moving beyond scalars

The fundamental limitation of the original LSTM is its reliance on scalar memory cells. In a standard LSTM, information is compressed into a scalar cell state $c \in \mathbb{R}$, which serves as the primary processing and storage unit. While this structure was revolutionary for solving the vanishing gradient problem, it creates a bottleneck when the model needs to remember a large number of distinct pieces of information. This limited storage capacity becomes particularly evident in tasks requiring the recall of rare tokens or complex associative patterns, as the model struggles to squeeze diverse semantic information into a single scalar value.

To overcome this, the mLSTM introduces a matrix memory, replacing the scalar cell state with a matrix $\mathbf{C} \in \mathbb{R}^{d \times d}$. This shift from a scalar to a matrix fundamentally changes how the model stores information. Instead of compressing the state into a single value, the mLSTM can maintain a high-dimensional representation of the sequence's history. By using a matrix, the model can store associations between different vectors, effectively transforming the memory from a simple accumulator into an associative memory system. This allows the model to handle significantly more information without the loss of detail associated with scalar compression.

# The Covariance Update Rule: Storing key-value pairs

The mechanism used to update the matrix memory in the mLSTM is known as the covariance update rule. In this framework, the model does not simply add a value to the memory; instead, it stores a pair of vectors: a key $\mathbf{k}_t \in \mathbb{R}^d$ and a value $\mathbf{v}_t \in \mathbb{R}^d$. The cell state is updated according to the following rule:

$\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \mathbf{v}_t \mathbf{k}_t^\top$

In this equation, the term $\mathbf{v}_t \mathbf{k}_t^\top$ represents the outer product of the value and key vectors, which creates a rank-1 matrix that encodes the association between the key and the value. The input gate $i_t$ acts as a learning rate, determining how much of the new association is integrated into the memory, while the forget gate $f_t$ acts as a decay rate, controlling how quickly old memories are forgotten. This approach is rooted in the concept of Fast Weight Programmers, where the memory is updated dynamically as the sequence progresses.

The covariance update rule is particularly powerful because it is optimal for achieving maximal separability of retrieved binary vectors, which is equivalent to maximizing the signal-to-noise ratio during retrieval. By utilizing this rule, the mLSTM can effectively "write" associations into its matrix memory, ensuring that the stored values can be distinguished and retrieved accurately later in the sequence.

# Retrieval mechanism: Query, Key, and Value (QKV) framework

Retrieving information from the matrix memory $\mathbf{C}_t$ is achieved using a framework similar to the Query, Key, and Value (QKV) system found in Transformers. To retrieve a value, the model generates a query vector $\mathbf{q}_t \in \mathbb{R}^d$. The retrieval process is essentially a matrix-vector multiplication: the current memory matrix $\mathbf{C}_t$ is multiplied by the query vector $\mathbf{q}_t$ to produce a retrieved hidden state.

The specific projections for these vectors are defined as follows:
The query is computed as $\mathbf{q}_t = \mathbf{W}_q \mathbf{x}_t + \mathbf{b}_q$.
The key is computed as $\mathbf{k}_t = \frac{1}{\sqrt{d}} \mathbf{W}_k \mathbf{x}_t + \mathbf{b}_k$.
The value is computed as $\mathbf{v}_t = \mathbf{W}_v \mathbf{x}_t + \mathbf{b}_v$.

Once the raw retrieved vector $\tilde{\mathbf{h}}_t$ is computed (via the interaction of $\mathbf{C}_t$ and $\mathbf{q}_t$), it is further refined by an output gate $\mathbf{o}_t$. The final hidden state $\mathbf{h}_t$ is produced by the element-wise product:

$\mathbf{h}_t = \mathbf{o}_t \odot \tilde{\mathbf{h}}_t$

where the output gate is determined by $\mathbf{o}_t = \sigma(\mathbf{W}_{\mathbf{o}} \mathbf{x}_t + \mathbf{b}_{\mathbf{o}})$. This structure allows the model to not only retrieve the most relevant information from its matrix memory but also to control which parts of that retrieved information are actually passed on to the next layer.

# Normalizing retrieval in mLSTM: Using the normalizer state dot-product

Because the matrix memory $\mathbf{C}_t$ is updated additively, the magnitude of the retrieved vector can grow as more information is stored, potentially leading to instabilities. To prevent this, the mLSTM employs a normalizer state $\mathbf{n}_t$, which keeps track of the total "strength" of the keys stored in the memory. The normalizer state is updated similarly to the cell state but stores a weighted sum of the key vectors:

$\mathbf{n}_t = f_t \mathbf{n}_{t-1} + i_t \mathbf{k}_t$

During retrieval, the retrieved vector $\mathbf{C}_t \mathbf{q}_t$ is divided by the dot product of the normalizer state and the query vector. This ensures that the output is normalized relative to the amount of information associated with the current query. Specifically, the normalized retrieved state is:

$\tilde{\mathbf{h}}_t = \mathbf{C}_t \mathbf{q}_t / \max \{ |\mathbf{n}_t^\top \mathbf{q}_t|, 1 \}$

The use of the absolute value and a lower bound of $1$ is a stabilization technique. It prevents division by zero or extremely small numbers when the dot product between the query and the normalizer state is close to zero, ensuring numerical stability during the forward pass.

# Breaking the sequential chain: How mLSTM achieves full parallelizability

One of the most significant hurdles for traditional LSTMs is the lack of parallelizability. This is caused by "memory mixing," which refers to the hidden-hidden recurrent connections where the hidden state $\mathbf{h}_{t-1}$ is required to compute the gates and the cell input for the next time step $t$. This creates a strict sequential dependency, forcing the model to process tokens one by one.

The mLSTM overcomes this limitation by completely abandoning memory mixing. In the mLSTM architecture, the gates ($i_t, f_t, \mathbf{o}_t$) and the QKV vectors ($\mathbf{q}_t, \mathbf{k}_t, \mathbf{v}_t$) depend only on the current input $\mathbf{x}_t$ and not on the previous hidden state $\mathbf{h}_{t-1}$. Because the update to the matrix memory $\mathbf{C}_t$ and the normalizer state $\mathbf{n}_t$ is linear with respect to these inputs, the entire recurrence can be reformulated. 

This reformulation allows the mLSTM to be computed in a parallel version, similar to how FlashAttention or State Space Models operate. While the memory is still logically recurrent, the mathematical structure allows the GPU to compute the states for all time steps simultaneously rather than sequentially. This drastically reduces the wall-clock time required for training and inference, enabling the scaling of LSTMs to billions of parameters.

# Comparison between mLSTM and Bidirectional Associative Memories (BAMs)

The theoretical foundation of the mLSTM's retrieval process is closely aligned with Bidirectional Associative Memories (BAMs). BAMs are a class of neural networks designed to store associations between pairs of patterns. In a BAM, the network is trained to associate a key vector with a value vector such that providing the key allows for the retrieval of the value, and vice versa.

The mLSTM adopts this specific setting by storing key-value pairs $(\mathbf{k}_t, \mathbf{v}_t)$ and retrieving the value $\mathbf{v}_t$ later in the sequence using a query $\mathbf{q}_{t+\tau}$. By implementing the covariance update rule, the mLSTM essentially functions as a dynamic BAM that evolves over time. Unlike a static BAM, however, the mLSTM integrates this associative memory into a gated recurrent framework, allowing it to selectively forget old associations and prioritize new ones through its input and forget gates. This integration blends the high-capacity associative recall of BAMs with the temporal flexibility of LSTMs.

Constructing the xLSTM Architecture

# xLSTM Blocks: Combining sLSTM and mLSTM

The xLSTM architecture is not built from a single uniform cell type but is instead constructed by integrating two distinct variants of the Long Short-Term Memory unit: the sLSTM and the mLSTM. These two variants address different limitations of the original LSTM. The sLSTM (scalar LSTM) is designed to empower the model with the ability to revise storage decisions through exponential gating and memory mixing. In contrast, the mLSTM (matrix LSTM) focuses on enhancing storage capacity by expanding the memory cell from a scalar to a matrix, allowing for a more sophisticated retrieval process via matrix multiplication.

To create a functional deep learning model, these individual units are encapsulated into xLSTM blocks. An xLSTM block serves as the fundamental module that non-linearly summarizes the past of a sequence within a high-dimensional space. The objective of this summarization is to effectively separate different histories or contexts, which is a critical prerequisite for the model to correctly predict the next element in a sequence, such as the next token in a language modeling task. By combining the scalar-based precision and memory mixing of sLSTM with the expansive capacity of mLSTM, the xLSTM block creates a versatile unit capable of handling both complex state tracking and large-scale associative recall.

# Cover's Theorem and the Importance of High-Dimensional Embedding

The design of xLSTM blocks is grounded in the mathematical intuition provided by Cover's Theorem. This theorem suggests that when patterns are non-linearly embedded into a higher-dimensional space, they are more likely to be linearly separable than they were in their original, lower-dimensional space. In the context of sequence modeling, "histories" or "contexts" are the patterns that the model must distinguish to make accurate predictions. If the model attempts to separate these contexts in a low-dimensional space, it may struggle to find a linear boundary that distinguishes one context from another.

By leveraging the principle of high-dimensional embedding, xLSTM ensures that the summary of the past is projected into a space where the model can more easily differentiate between various sequence states. This ability to separate histories allows the model to be more expressive and accurate. The transition from the original input space to a high-dimensional space, and the subsequent non-linear processing within that space, is what enables the xLSTM architecture to scale effectively and perform favorably against other state-of-the-art models like Transformers and State Space Models.

# Residual Block Backbones: Pre up-projection vs. Post up-projection

The way in which the high-dimensional embedding is implemented depends on the choice of the residual block backbone. The xLSTM architecture considers two primary types of residual block architectures: post up-projection and pre up-projection. These backbones determine at which stage of the block the data is mapped to a higher dimension.

In a residual block with post up-projection, the model first performs a non-linear summary of the past within the original space. After this summary is created, the data is linearly mapped into a high-dimensional space, a non-linear activation function is applied, and the result is then linearly mapped back to the original space. This structure is conceptually similar to the residual blocks found in Transformer architectures.

Conversely, a residual block with pre up-projection reverses this order. The input is first linearly mapped to a high-dimensional space. The non-linear summary of the past is then performed directly within this high-dimensional space, and the resulting representation is eventually linearly mapped back to the original space. This approach is reminiscent of the structures used in State Space Models.

# Choosing the Backbone: Why mLSTM uses Pre up-projection and sLSTM uses Post up-projection

The choice of backbone is not arbitrary; it is tailored to the specific operational strengths and requirements of the sLSTM and mLSTM units. For xLSTM blocks containing an sLSTM, the post up-projection block is utilized. This means the sLSTM handles the summarization in the original space before the data is projected upward.

For xLSTM blocks containing an mLSTM, the pre up-projection block is employed. The reasoning behind this choice is centered on memory capacity. Because the mLSTM utilizes a matrix memory $\mathbf{C} \in \mathbb{R}^{d \times d}$ to store information, the capacity for storage and retrieval is significantly increased when the operations occur in a high-dimensional space. By projecting the input into a higher dimension before it reaches the mLSTM unit, the architecture maximizes the available memory capacity, allowing the matrix memory to be more effective in storing and recalling complex key-value pairs.

# Residually Stacking Blocks: Depth, LayerNorm, and Overall Network Topology

An entire xLSTM architecture is constructed by residually stacking these xLSTM blocks. This stacking method is consistent with the design of contemporary Large Language Models (LLMs), where blocks are layered to increase the depth and complexity of the network. To ensure stability during training at scale, the architecture utilizes pre-LayerNorm residual backbones.

The topology of an xLSTM network can be defined by the ratio of mLSTM-based blocks to sLSTM-based blocks. This is denoted using the notation xLSTM[$a:b$], where $a/b$ represents the ratio of mLSTM blocks versus sLSTM blocks. For instance, an architecture denoted as xLSTM[7:1] indicates that out of every eight blocks, seven are mLSTM-based and one is sLSTM-based. In a model with a total of 48 blocks, this specific ratio would result in 42 mLSTM blocks and 6 sLSTM blocks.

This modular approach allows the architecture to balance the computational efficiency and parallelizability of mLSTM with the state-tracking capabilities and memory mixing of sLSTM. The resulting network maintains linear computation and constant memory complexity with respect to sequence length, making it highly suitable for industrial applications and edge implementations compared to the quadratic complexity of traditional Transformers.

Empirical Evaluation and Synthetic Benchmarks

# Solving State Tracking: Performance on formal languages and regular grammars

To understand the computational power of xLSTM, it is first necessary to examine its ability to handle state tracking. State tracking is the capacity of a model to keep a record of specific entities or conditions over a long sequence, which is essential for tasks such as evaluating computer code or tracking characters within a long narrative. The research indicates that the ability to perform state tracking is fundamentally tied to memory mixing, which refers to the hidden-to-hidden recurrent connections that allow information from one time step to influence the next.

The sLSTM variant of the xLSTM architecture is specifically designed to handle these problems through the combination of exponential gating and memory mixing. In experimental tests using formal language tasks, xLSTM was evaluated on its ability to solve regular grammars, such as the parity task. The parity task requires the model to keep track of whether a specific token has appeared an even or odd number of times throughout a sequence. Because sLSTM employs memory mixing, it can effectively maintain and update this internal state, allowing it to achieve high accuracy on these tasks.

In contrast, models that lack memory mixing—such as Transformers and State Space Models (SSMs)—struggle significantly with these types of problems. Because they cannot effectively track states through recurrent mixing, they are fundamentally less powerful than Recurrent Neural Networks (RNNs) when faced with regular grammars. By leveraging the sLSTM block, xLSTM overcomes this limitation, demonstrating a level of expressivity that allows it to solve state tracking problems that remain intractable for current Transformer-based and SSM-based architectures.

# Testing Memory Capacity: The Multi-Query Associative Recall task

While sLSTM excels at state tracking, the mLSTM variant is designed to address the limitation of storage capacity found in traditional LSTMs. In a standard LSTM, information must be compressed into scalar cell states, which limits the amount of information the model can remember. mLSTM solves this by upgrading the memory cell from a scalar to a matrix $\mathbf{C} \in \mathbb{R}^{d \times d}$. This matrix memory allows the model to store key-value pairs, where a key $\mathbf{k}_t$ and a value $\mathbf{v}_t$ are stored at time $t$ and retrieved later using a query vector $\mathbf{q}_{t+\tau}$.

This capacity is rigorously tested using the Multi-Query Associative Recall (MQAR) task. In this task, the model is presented with several randomly chosen key-value pairs from a large vocabulary and must memorize them to recall the correct value associated with a key at the end of the sequence. To push the limits of the architecture, the difficulty was increased by expanding the number of key-value pairs up to 256 and extending the context length up to 2048 tokens.

The results of the MQAR task show that xLSTM, particularly in hybrid configurations like $xLSTM[1:1]$, is the best performing non-Transformer model. While Transformers remain the gold standard due to their exponential memory in the coding dimension, xLSTM significantly outperforms other recurrent models. An important intuitive finding from these experiments is that the inclusion of sLSTM blocks does not diminish the overall memory capacity of the network; instead, sLSTM leverages the capacity provided by the mLSTM blocks, allowing the model to maintain high recall accuracy even on the most difficult versions of the task. Furthermore, this enhanced capacity allows xLSTM to extrapolate to contexts longer than those encountered during training.

# Handling Long Sequences: Evaluation on the Long Range Arena (LRA)

A critical requirement for any modern sequence model is the ability to maintain performance as the input sequence length grows. The Long Range Arena (LRA) serves as a benchmark to assess how well models handle long sequences and large contexts across a variety of different tasks. This evaluation is particularly important because it tests the model's efficiency and stability when the distance between related pieces of information is vast.

xLSTM demonstrates consistent and strong performance across all tasks within the Long Range Arena. The architecture's ability to handle long-range dependencies is a result of its compressive memory, which allows it to maintain a constant memory complexity regardless of the sequence length. Unlike Transformers, which suffer from quadratic complexity as sequences grow, xLSTM maintains linear computation and constant memory requirements.

The success on the LRA benchmark suggests that the xLSTM architecture is remarkably efficient at managing the diverse demands of long-context problems. Whether the task requires the precision of matrix-based retrieval provided by mLSTM or the state-tracking capabilities of sLSTM, the xLSTM framework provides a robust mechanism for processing extended sequences without the computational collapse associated with traditional attention mechanisms.

# The synergy between sLSTM and mLSTM in hybrid architectures (xLSTM[a:b])

The full power of the xLSTM framework is realized through the creation of hybrid architectures that combine both sLSTM and mLSTM blocks. To describe these configurations, the researchers use the notation $xLSTM[a:b]$, where the ratio $a/b$ represents the proportion of mLSTM-based blocks relative to sLSTM-based blocks. For example, an architecture denoted as $xLSTM[7:1]$ indicates that in a set of eight blocks, seven are mLSTM blocks and one is an sLSTM block. In a larger model with 48 total blocks, an $xLSTM[7:1]$ configuration would consist of 42 mLSTM blocks and 6 sLSTM blocks.

This hybrid approach creates a synergy between the two types of memory structures. The mLSTM blocks provide massive storage capacity through their matrix memory and offer the benefit of full parallelizability, which speeds up training and inference. Meanwhile, the sLSTM blocks provide the essential "memory mixing" required for state tracking and complex logic that purely matrix-based or parallel models cannot achieve.

Experimental evidence shows that this combination is highly effective for language modeling. In comparisons using the SlimPajama dataset, xLSTM configurations—such as $xLSTM[1:0]$ (pure mLSTM) and $xLSTM[7:1]$ (hybrid)—outperformed a wide array of existing methods, including GPT-3, Llama, and Mamba, in terms of validation perplexity. The hybrid nature of xLSTM allows it to balance the trade-off between computational efficiency, massive memory recall, and the expressive power needed to solve complex linguistic and logical structures.

xLSTM as a Large Language Model: Scaling and Performance

# Large-scale training on the SlimPajama dataset

To evaluate the potential of the Extended Long Short-Term Memory (xLSTM) architecture as a viable alternative to current Large Language Models (LLMs), the researchers conducted large-scale training experiments. The primary goal was to see if the modifications introduced in xLSTM—specifically exponential gating and matrix memory—could sustain performance when scaled to billions of parameters. For this purpose, the models were trained on a massive corpus consisting of 300 billion tokens from the SlimPajama dataset. This dataset choice ensures that the models are exposed to a diverse and extensive range of natural language, mirroring the training regimes of state-of-the-art models like Mamba and Griffin.

The experiments focused on a variety of model scales to observe how performance evolves with size. Specifically, four different model sizes were implemented: 125 million, 350 million, 760 million, and 1.3 billion parameters. To ensure a fair comparison, xLSTM was pitted against representatives from three distinct architectural families: the Transformer (represented by Llama), State Space Models (represented by Mamba), and Recurrent Neural Networks (represented by RWKV-4). The evaluation of xLSTM involved different block configurations, denoted as xLSTM[$a$:$b$], where the ratio $a/b$ represents the proportion of mLSTM-based blocks to sLSTM-based blocks. For instance, xLSTM[1:0] denotes a model consisting entirely of mLSTM blocks, while xLSTM[7:1] incorporates a small number of sLSTM blocks to provide memory mixing capabilities.

# Perplexity and Validation: Comparing xLSTM, Llama, Mamba, and RWKV

One of the primary metrics used to evaluate the quality of a language model is validation perplexity, which measures how well the model predicts the next token in a sequence. In the comparative analysis on the SlimPajama validation set, xLSTM demonstrated superior performance across all tested model sizes. Both the purely mLSTM-based version (xLSTM[1:0]) and the hybrid version (xLSTM[7:1]) emerged as the top-performing models, consistently achieving lower perplexity than Llama, Mamba, and RWKV-4.

This result is particularly significant because it demonstrates that xLSTM's architectural enhancements allow it to capture the underlying patterns of language more effectively than previous iterations of RNNs or even the highly optimized Transformer and SSM architectures. While Llama and Mamba are the current industry standards for scaling, xLSTM's ability to outperform them in next-token prediction suggests that the combination of matrix memory and exponential gating provides a more efficient mechanism for storing and retrieving linguistic information at scale.

# Sequence Length Extrapolation: Maintaining performance across longer contexts

A critical challenge for any language model is sequence length extrapolation, which is the ability of a model to maintain its performance on sequences that are significantly longer than those it encountered during training. In the experiments, models were trained with a context length of $2048$ tokens and then tested on contexts extending up to $16384$ tokens. This test reveals whether the model's memory mechanism degrades as the sequence grows.

The results indicated a stark difference between xLSTM and its competitors. While Llama, Mamba, and RWKV-4 saw their perplexities increase as the context length extended beyond the training limit, the xLSTM models managed to maintain low perplexities for much longer contexts. This suggests that xLSTM is more robust to the "out-of-distribution" nature of longer sequences. This stability is likely a result of the extended memory structures and normalization techniques that prevent the model's internal states from becoming unstable or saturated when processing long-range dependencies.

# Downstream Task Performance: Common sense reasoning and PALOMA benchmarks

Beyond simple token prediction, the researchers evaluated xLSTM's ability to generalize to complex downstream tasks, such as common sense reasoning. Across the vast majority of these tasks and across all model sizes, xLSTM outperformed the other models. The only exception was the ARC task, where Mamba occasionally performed better in some instances. This indicates that xLSTM possesses a strong capacity for semantic understanding and logical reasoning, moving beyond mere statistical pattern matching.

To further refine this analysis, the models were tested on the PALOMA language benchmark, which consists of $571$ different text domains ranging from news sites like nytimes.com to specific community forums like r/depression on Reddit. The results were overwhelmingly in favor of xLSTM, particularly the xLSTM[1:0] variant. In $570$ out of $571$ domains ($99.8\%$), xLSTM[1:0] achieved lower perplexity than RWKV-4. It also beat Mamba in $568$ out of $571$ domains ($99.5\%$) and Llama in $486$ out of $571$ domains ($85.1\%$). This level of dominance across diverse domains suggests that xLSTM's matrix memory is exceptionally capable of adapting to the varying linguistic styles and vocabularies of different real-world contexts.

# Scaling Laws: Predicting the performance of larger xLSTM models

To understand the future potential of xLSTM, the researchers analyzed its scaling laws. Scaling laws describe the power-law relationship between a model's performance (such as loss or perplexity) and its size (number of parameters). By plotting the performance of different models as they scale from 125 million to 1.3 billion parameters, the researchers could observe the "offset" of each architecture.

The analysis showed that while xLSTM, Llama, Mamba, and RWKV-4 all exhibit similar power-law scaling behavior, xLSTM is shifted to a significantly more favorable position. Specifically, xLSTM outperformed Mamba by a margin similar to the one by which Mamba outperformed Llama. This implies that as the model size increases further into the range of tens or hundreds of billions of parameters, xLSTM is predicted to maintain its lead over Transformers and SSMs. This suggests that xLSTM is not just a competitive alternative but potentially a more scalable architecture for the next generation of ultra-large language models.

# Computational Efficiency: Inference throughput, memory complexity, and generation time

A major advantage of xLSTM over the Transformer architecture is its computational efficiency during inference. Transformers suffer from quadratic complexity relative to the sequence length, meaning that as the context grows, the computational cost increases exponentially. In contrast, xLSTM features linear computation and constant memory complexity with respect to the sequence length. This makes xLSTM highly suitable for edge computing and industrial applications where memory and processing power are limited.

In terms of generation time, xLSTM exhibits linear scaling, whereas Llama exhibits quadratic scaling. When measuring decoding throughput, xLSTM was able to utilize much higher batch sizes than Llama. This is because Llama requires a key-value cache that grows with the sequence length, consuming significant memory, while xLSTM's compressive memory remains constant. Consequently, xLSTM achieves the highest throughput among the compared models. Although the matrix memory of mLSTM involves $d \times d$ updates and retrievals—which are computationally more expensive than scalar updates—these operations can be fully parallelized on GPUs, resulting in only a minor impact on actual wall-clock time. While sLSTM is not parallelizable due to its memory mixing, optimized CUDA kernels keep it within a reasonable speed range, typically less than two times slower than mLSTM.

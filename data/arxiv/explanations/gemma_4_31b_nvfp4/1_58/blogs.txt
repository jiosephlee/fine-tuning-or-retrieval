# Beyond Floating Points: Welcome to the Era of 1.58-Bit AI

Large Language Models (LLMs) have seen explosive growth in capability, but this progress comes with a steep price: massive energy consumption and hardware requirements. Most modern LLMs rely on 16-bit floating-point (FP16 or BF16) precision for their weights. Because the bulk of an LLM's computation consists of matrix multiplications, these models require expensive floating-point additions and multiplications, leading to high latency and significant memory bottlenecks during inference.

BitNet b1.58 proposes a paradigm shift by introducing a 1-bit LLM variant where every single parameter is ternary. Instead of 16-bit floats, every weight is constrained to one of three values: $\{-1, 0, 1\}$. In the binary system, these three possible values represent approximately 1.58 bits ($\log_2 3 \approx 1.58$). By replacing complex floating-point math with simple integer addition, BitNet b1.58 maintains the performance of full-precision models while drastically reducing the computational footprint.

## How BitNet b1.58 Works

The core of the architecture is the replacement of the standard `nn.Linear` layer with a specialized `BitLinear` layer. This model is trained from scratch using 1.58-bit weights and 8-bit activations. To constrain the weights to the ternary set, the researchers utilized an `absmean` quantization function. This process scales the weight matrix by its average absolute value $\gamma$ and rounds the result to the nearest integer within the range of $[-1, 1]$. The mathematical representation of this quantization is:

$\widetilde{W} = \mathrm{RoundClip}(\frac{W}{\gamma + \epsilon}, -1, 1)$

where $\gamma = \frac{1}{nm}\sum_{ij} |W_{ij}|$.

By including $0$ as a possible weight value, BitNet b1.58 introduces explicit support for feature filtering, which enhances its modeling capability compared to previous 1-bit models that only used $\{-1, 1\}$. To ensure compatibility with the existing ecosystem, the architecture adopts LLaMA-like components, including RMSNorm, SwiGLU, and rotary embeddings, making it easy to integrate into popular frameworks like Hugging Face or llama.cpp.

## Performance and Efficiency Gains

The most striking result of the BitNet b1.58 research is that it matches the perplexity and end-task performance of full-precision (FP16) LLaMA models once the model size reaches 3 billion parameters. Beyond matching performance, the efficiency gains are substantial:

*   **Latency and Memory:** A 3.9B BitNet b1.58 model is 2.4 times faster and uses 3.32 times less GPU memory than a 3B FP16 LLaMA model, while actually performing better. As models scale, the gap widens; a 70B BitNet b1.58 model is 4.1 times faster than its FP16 counterpart.
*   **Energy Consumption:** Because the model replaces floating-point multiplication with integer addition, it achieves a 71.4-fold reduction in arithmetic operations energy consumption for matrix multiplication on 7nm chips.
*   **Throughput:** In tests using 70B parameter models on two A100 GPUs, BitNet b1.58 supported a batch size 11 times larger than the FP16 baseline, resulting in 8.9 times higher throughput.

These results define a new scaling law for LLMs. In terms of latency, memory usage, and energy, the efficiency equivalencies are roughly:
*   13B BitNet b1.58 $\approx$ 3B FP16 LLM
*   30B BitNet b1.58 $\approx$ 7B FP16 LLM
*   70B BitNet b1.58 $\approx$ 13B FP16 LLM

## The Future of 1-bit LLMs

The shift to 1.58-bit weights opens several new doors for AI deployment. First, it provides a path toward native support for longer sequences. By reducing activations from 16 bits to 8 bits (and potentially lower), the memory consumption of KV caches is reduced, allowing the context length to be doubled using the same resources. 

Furthermore, this efficiency makes high-performance LLMs viable for edge and mobile devices, which are typically constrained by memory and power. Finally, the new computation paradigm—moving away from floating-point multiplication—creates a compelling case for designing new, specialized hardware optimized specifically for 1-bit operations, potentially moving beyond the limitations of current GPUs.



# AI on Your Phone? How 1-Bit LLMs Solve the Memory Crisis

Large Language Models (LLMs) have fundamentally changed how we interact with technology, but they come with a massive appetite for resources. Most modern LLMs operate using 16-bit floating-point (FP16 or BF16) precision, which creates a significant "memory crisis" when attempting to deploy them on edge devices. The sheer volume of parameters requires immense DRAM bandwidth and energy, often making high-quality AI inaccessible on mobile devices or standard CPUs without heavy compromise.

A new research paper introduces **BitNet b1.58**, a 1-bit LLM variant that challenges the necessity of high-precision weights. By moving from 16-bit weights to a ternary system, this architecture provides a path toward running powerful models directly on your phone without sacrificing performance.

## What is a 1.58-bit LLM?

Traditional LLMs rely on complex floating-point matrix multiplications, which are computationally expensive. BitNet b1.58 replaces the standard `nn.Linear` layer with a `BitLinear` layer. In this system, every single weight is ternary, meaning it can only take one of three values: $\{-1, 0, 1\}$. 

The "1.58" comes from the fact that $\log_2(3) \approx 1.58$ bits. To achieve this, the model uses an *absmean* quantization function to constrain the weights. The weight matrix is scaled by its average absolute value, $\gamma = \frac{1}{nm}\sum_{ij} |W_{ij}|$, and then rounded to the nearest integer among $\{-1, 0, 1\}$ using the following formula:

$\widetilde{W} = \mathrm{RoundClip}(\frac{W}{\gamma + \epsilon}, -1, 1)$

Where $\mathrm{RoundClip}(x, a, b) = \max(a, \min(b, \mathrm{round}(x)))$. 

The inclusion of $0$ is a critical upgrade over previous 1-bit models. It allows for explicit feature filtering, which significantly strengthens the model's capabilities and allows it to match the performance of full-precision baselines.

## Breaking the Performance Trade-off

Historically, reducing precision meant sacrificing accuracy. However, the researchers found that BitNet b1.58 matches FP16 LLaMA baselines in terms of perplexity and end-task performance once the model reaches a size of 3B parameters. 

The efficiency gains are staggering. For a 3.9B model, BitNet b1.58 is 2.4 times faster and consumes 3.32 times less memory than its FP16 counterpart. As the model scales, these benefits grow. A 70B BitNet b1.58 model is 4.1 times faster than the FP16 baseline and can support up to 11 times the batch size, resulting in 8.9 times higher throughput.

The most impactful improvement for mobile devices is energy consumption. Because the model replaces floating-point multiplications with simple integer additions, it is estimated to save 71.4 times the arithmetic operation energy for matrix multiplication on 7nm chips.

## Paving the Way for Edge Computing

The implications for edge and mobile computing are profound. Mobile devices are typically limited by memory bandwidth and battery life. By drastically reducing the memory footprint and the energy required for a forward pass, BitNet b1.58 makes it feasible to deploy large, high-quality models on CPUs and mobile NPUs.

Furthermore, this architecture addresses the "KV cache" bottleneck. Long-sequence inference often crashes on mobile devices because the KV cache consumes too much memory. Because BitNet b1.58 uses 8-bit activations instead of 16-bit, the context length can be doubled using the same amount of memory.

## A New Scaling Law

The efficiency of BitNet b1.58 is so high that it defines a new scaling law for LLM deployment. Based on the research, we can see a new equivalence between model sizes:

*   A 13B BitNet b1.58 model is more efficient in latency, memory, and energy than a 3B FP16 LLM.
*   A 30B BitNet b1.58 model outperforms a 7B FP16 LLM in efficiency.
*   A 70B BitNet b1.58 model is more efficient than a 13B FP16 LLM.

This shift means we can deploy significantly larger, more capable models on hardware that previously could only support tiny, less capable versions. While the current results use 2-bit kernels, there is still significant room for optimization through the design of custom hardware specifically optimized for 1-bit computation.



# Cutting the Energy Bill: The Path to Sustainable AI

The rapid evolution of Large Language Models (LLMs) has brought remarkable capabilities to natural language processing, but it has also introduced a significant burden: immense energy consumption. As models scale, the environmental and economic costs of training and deploying them have become critical challenges. While industry standards often rely on post-training quantization to reduce a model's precision from 16-bit to 4-bit, these methods are often sub-optimal.

A more fundamental shift is required to make AI truly sustainable. This is the core objective of BitNet b1.58, a 1-bit LLM variant that redefines how models handle computation to drastically reduce their energy footprint.

## From Floating-Point Multiplication to Integer Addition

In vanilla LLMs, the bulk of the computational workload consists of matrix multiplications using 16-bit floating-point values (FP16 or BF16). These operations require floating-point addition and multiplication, which are computationally expensive and energy-intensive.

BitNet b1.58 changes this paradigm by ensuring that every single parameter—or weight—in the model is ternary, taking on only one of three values: $\{-1, 0, 1\}$. By constraining weights to these values, the model transforms the way it processes data. Instead of relying on complex floating-point multiplications, the matrix multiplication in BitNet b1.58 primarily involves integer addition.

This shift is a game-changer for efficiency. Because the fundamental limit to compute performance in many chips is power, reducing the complexity of the arithmetic operations directly translates to faster computation and lower energy usage.

## Quantifying the Energy Savings

The energy impact of moving to a 1-bit architecture is profound. Based on energy models for 7nm chips, BitNet b1.58 saves $71.4$ times the arithmetic operations energy consumption for matrix multiplication compared to full-precision models. 

Beyond the raw energy of calculations, the model addresses the "memory wall." Transferring parameters from DRAM to on-chip SRAM is a costly process during inference. Because BitNet b1.58 has a significantly lower memory footprint in terms of both capacity and bandwidth, it reduces the time and energy required to load weights, leading to higher throughput and lower latency.

## Performance Without Compromise

A common concern with extreme quantization is the loss of model intelligence. However, the research demonstrates that BitNet b1.58 can match the perplexity and end-task performance of full-precision (FP16) Transformer LLMs, provided the model size is at least 3B parameters. 

The inclusion of the value $0$ is particularly important. This allows the model to perform explicit feature filtering, which strengthens its modeling capability and allows it to keep pace with full-precision baselines. As the model scales, the efficiency gains only increase:

*   A 13B BitNet b1.58 model is more efficient in latency, memory, and energy than a 3B FP16 LLM.
*   A 30B BitNet b1.58 model outperforms a 7B FP16 LLM in efficiency.
*   A 70B BitNet b1.58 model is more efficient than a 13B FP16 LLM.

## The Future of Sustainable Deployment

The implications of this architecture extend beyond data centers. The reduced memory and energy requirements make 1.58-bit LLMs ideal for edge and mobile devices, which are typically constrained by battery life and limited computational power. Furthermore, this new computation paradigm opens the door for the design of specialized hardware—such as LPUs—specifically optimized for 1-bit operations.

By moving away from the energy-heavy reliance on floating-point multiplication, BitNet b1.58 provides a blueprint for a new generation of LLMs that are high-performance, cost-effective, and environmentally sustainable.



# The New Scaling Law: Why 'Bigger' is Now More Efficient

For years, the trade-off in Large Language Model (LLM) deployment has been straightforward: if you want more performance, you need a larger model, which in turn requires more memory, higher latency, and more power. To mitigate this, the industry has relied heavily on post-training quantization to squeeze 16-bit models into 4-bit or 8-bit formats. However, this is often sub-optimal because the model is designed for high precision and then "compressed" after the fact.

A new research paper introduces **BitNet b1.58**, a 1-bit LLM variant that challenges this trade-off. By designing a model where every single parameter is ternary—taking only the values $\{-1, 0, 1\}$—the researchers have discovered a new scaling law. In this paradigm, a massive 1.58-bit model can actually be faster and cheaper to run than a much smaller full-precision model.

## What is a 1.58-bit LLM?

Standard LLMs typically use 16-bit floating-point precision (FP16 or BF16). In contrast, BitNet b1.58 uses ternary weights. While a 1-bit system only allows two values (0 and 1), adding a third value (0) to the set $\{-1, 0, 1\}$ results in $\log_2 3 \approx 1.58$ bits.

To achieve this, the architecture replaces the standard `nn.Linear` layers with `BitLinear`. During training, weights are constrained using an *absmean* quantization function:

$$\widetilde{W} = \mathrm{RoundClip}(\frac{W}{\gamma + \epsilon}, -1, 1)$$

where $\gamma$ is the average absolute value of the weights:

$$\gamma = \frac{1}{nm}\sum_{ij} |W_{ij}|$$

By restricting weights to these three values, the model gains a powerful ability for feature filtering (via the 0 value) while drastically simplifying the underlying math.

## Breaking the Computational Bottleneck

The primary cost of LLM inference is matrix multiplication. In full-precision models, this involves expensive floating-point multiplications and additions. BitNet b1.58 transforms this process. Because the weights are only $\{-1, 0, 1\}$, matrix multiplication is reduced almost entirely to integer addition.

This shift creates three massive efficiency gains:
*   **Energy:** Arithmetic operation energy for matrix multiplication is reduced by an estimated 71.4 times on 7nm chips.
*   **Memory:** The memory footprint is significantly smaller, reducing the time and energy required to move weights from DRAM to the on-chip SRAM.
*   **Throughput:** Because of the reduced memory requirements, the model can support much larger batch sizes. For a 70B parameter model, BitNet b1.58 can support up to 11 times the batch size of an FP16 baseline, leading to nearly 9 times higher throughput.

## The New Scaling Law: Counterintuitive Efficiency

The most striking finding of the paper is the emergence of a new scaling law. Typically, we assume a 70B model will always be slower than a 13B model. However, BitNet b1.58 flips this logic. Because the efficiency gains from ternary weights scale as the model grows, we see the following equivalencies in terms of latency, memory usage, and energy:

*   A **13B** BitNet b1.58 is more efficient than a **3B** FP16 LLM.
*   A **30B** BitNet b1.58 is more efficient than a **7B** FP16 LLM.
*   A **70B** BitNet b1.58 is more efficient than a **13B** FP16 LLM.

Crucially, this efficiency does not come at the cost of intelligence. The researchers found that BitNet b1.58 matches the perplexity and end-task performance of full-precision LLaMA baselines starting at the 3B model size. For example, a 3.9B BitNet b1.58 model actually outperforms a 3B FP16 LLaMA model while being 2.4 times faster and using 3.32 times less memory.

## The Path Forward

The implications of 1.58-bit LLMs extend beyond simple speed-ups. By reducing the memory footprint of activations and weights, this architecture opens the door for:

*   **Native Long Sequence Support:** Reducing activations from 16-bit to 8-bit (or lower) allows the KV cache to be compressed, effectively doubling the context length for the same memory resources.
*   **Edge and Mobile Deployment:** The ability to run high-performance models on CPUs and memory-constrained mobile devices becomes viable.
*   **1-bit Mixture-of-Experts (MoE):** Combining MoE with 1.58-bit weights could solve the high memory and communication overhead usually associated with expert-based models.

Ultimately, BitNet b1.58 suggests that we are entering an era where the bottleneck is no longer the number of parameters, but how those parameters are represented. This paves the way for specialized hardware optimized specifically for ternary computation, potentially moving us away from the limitations of current GPU architectures.

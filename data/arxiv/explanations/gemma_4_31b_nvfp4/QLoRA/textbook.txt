\title{A Textbook about the Paper: "QLoRA: Efficient Finetuning of Quantized LLMs"}

Introduction to the Memory Challenge in LLM Finetuning

# The Role of Finetuning in LLMs: Specialization and Alignment

Finetuning serves as a critical stage in the development of Large Language Models (LLMs). While a model may be pretrained on a vast corpus of data, finetuning is the process used to refine that model to improve its overall performance and adapt it to specific tasks. This process is highly effective for specializing a model, allowing developers to introduce desirable behaviors or remove undesirable ones, thereby aligning the model's outputs with the intended goals of the user or the developer.

In the context of modern AI, finetuning is the primary mechanism used to transform a raw, pretrained language model into an interactive chatbot. By training on instruction-following datasets, a model can learn how to interpret user prompts and provide helpful, relevant responses. This transition from a general-purpose base model to a specialized assistant is essential for achieving the capabilities seen in state-of-the-art systems, where the model must not only understand language but also follow a specific set of instructions to complete a task accurately.

# The 'Memory Wall': Calculating GPU Memory Requirements for 16-bit Finetuning

Despite the effectiveness of finetuning, the computational cost associated with very large models creates a significant barrier, often referred to as a memory wall. The primary challenge is the immense amount of GPU memory required to store the model weights, gradients, and optimizer states during the training process. Standard finetuning typically employs 16-bit precision, which provides high fidelity but consumes a massive amount of resources as the model scale increases.

To illustrate this challenge, consider a LLaMA model with 65 billion parameters. Performing regular 16-bit finetuning on a model of this size would require more than 780 GB of GPU memory. This requirement far exceeds the capacity of a single professional GPU, making such tasks prohibitively expensive and inaccessible for most researchers and smaller teams. While various quantization methods exist to reduce the memory footprint of LLMs for inference, these techniques historically break down during the training phase, meaning that the memory wall remains a formidable obstacle for those wishing to train high-parameter models.

# Introduction to Parameter-Efficient Fine-Tuning (PEFT)

To combat the prohibitive memory costs of full-model finetuning, researchers developed Parameter-Efficient Fine-Tuning (PEFT). The core intuition behind PEFT is to avoid updating all of the parameters in a pretrained model. Instead, the vast majority of the model remains frozen, and only a small set of additional trainable parameters, known as adapters, are updated during stochastic gradient descent. Gradients are backpropagated through the fixed pretrained weights to reach these adapters, which are then optimized to minimize the loss function.

One of the most prominent PEFT methods is Low-Rank Adaptation (LoRA). In a standard linear projection, the operation is represented as $\mathbf{X}\mathbf{W} = \mathbf{Y}$, where $\mathbf{X} \in \mathbb{R}^{b \times h}$ and $\mathbf{W} \in \mathbb{R}^{h \times o}$. LoRA modifies this by adding a factorized projection to the original weights. The computation becomes $\mathbf{Y} = \mathbf{X}\mathbf{W} + s\mathbf{X}\mathbf{L}_1\mathbf{L}_2$, where $\mathbf{L}_1 \in \mathbb{R}^{h \times r}$ and $\mathbf{L}_2 \in \mathbb{R}^{r \times o}$, and $s$ is a scalar. By using a low rank $r$, the number of trainable parameters is drastically reduced.

However, it is important to understand that the memory footprint of LoRA is not solely determined by the size of the adapters. In practice, the majority of memory consumption during LLM finetuning stems from activation gradients rather than the learned parameters. For instance, in a 7B LLaMA model, the LoRA parameters might only occupy 26 MB, while the input gradients could require 567 MB. Even with the use of gradient checkpointing, which reduces input gradients to an average of 18 MB per sequence, the gradients remain more memory-intensive than the adapters themselves. This realization suggests that aggressively reducing the number of LoRA parameters yields only minor memory benefits, and that memory efficiency must be sought elsewhere—specifically in the quantization of the base model.

# The Trade-off Between Model Scale and Precision

A fundamental consideration in the design of efficient finetuning systems is the relationship between the number of parameters in a model and the precision of those parameters. There is a strategic trade-off: for a given budget of finetuning and inference resources, it is generally more beneficial to use a model with a larger number of parameters but lower precision than a smaller model with higher precision.

This principle is central to the motivation for techniques like QLoRA, which enables the use of a 4-bit quantized base model. By reducing the precision of the base weights from 16-bit to 4-bit, the memory requirements are lowered enough to fit much larger models on a single GPU. For example, a 65B parameter model that previously required over 780 GB of memory can be finetuned using less than 48 GB of GPU memory without degrading the predictive performance or runtime compared to a 16-bit fully finetuned baseline. 

This shift allows for the deployment of models that are both more capable due to their scale and more accessible due to their reduced memory footprint. Evidence suggests that this approach is highly effective; for example, a 7B parameter model using these efficiency techniques can outperform a 13B parameter model that was trained with more memory-intensive methods. By prioritizing model scale over high precision, researchers can leverage the inherent power of larger architectures while remaining within the hardware constraints of consumer or professional GPUs.

Foundations of Quantization and Low-Rank Adaptation

# Basics of Quantization: From FP32 to Int8

Quantization is a fundamental process in numerical representation that involves discretizing an input to transform it from a representation containing high amounts of information to one with significantly less information. In the context of Large Language Models (LLMs), this typically manifests as converting weights from a high-bit data type, such as 32-bit Floating Point (FP32), to a lower-bit data type, such as 8-bit Integers (Int8). The primary motivation for this is to reduce the memory footprint of the model, allowing larger models to fit into limited GPU memory.

To perform this conversion effectively, it is necessary to ensure that the entire range of the target low-bit data type is utilized. This is achieved through a normalization process where the input data is rescaled based on the absolute maximum value of the elements within the input tensor. For instance, when quantizing an FP32 tensor into an Int8 tensor with a range of $[-127, 127]$, the operation is defined by the formula:

$\mathbf{X}^{\text{Int8}} = \text{round}\left( \frac{127}{{\text{absmax}}(\mathbf{X}^{\text{FP32}})}\mathbf{X}^{\text{FP32}} \right) = \text{round}(c^{\text{FP32}}\cdot \mathbf{X}^{\text{FP32}})$

In this equation, $c^{\text{FP32}}$ represents the quantization constant, also known as the quantization scale. By multiplying the original tensor by this constant and rounding the result, the values are mapped into the discrete integer space of the target data type.

# The Outlier Problem and Block-wise Quantization

A significant challenge in basic quantization is the "outlier problem." This occurs when an input tensor contains a few values with very large magnitudes compared to the rest of the data. Because the quantization constant is determined by the absolute maximum value of the tensor, a single extreme outlier can force the scale to be very large. This results in a poor utilization of the quantization bins; many bit combinations remain unused, and the majority of the values are squeezed into a small number of bins, leading to a substantial loss of precision and information.

To mitigate the impact of outliers, a technique known as block-wise quantization is employed. Instead of calculating a single quantization constant for an entire tensor, the input tensor $\mathbf{X}\in \mathbb{R}^{b\times h}$ is divided into $n$ contiguous blocks of size $B$. This is done by flattening the input tensor and slicing the resulting linear segment into $n = ({b\times h} )/{B}$ independent blocks.

Each of these blocks is then quantized independently using its own specific quantization constant $c_i$. By isolating outliers within specific blocks, the quantization constants for other blocks can remain optimized for the local distribution of values. This prevents a single outlier in one part of the tensor from degrading the precision of the weights across the entire model, thereby preserving more of the original information.

# Dequantization and Quantization Constants

While quantization is used for storage to save memory, computation often requires the weights to be returned to a higher precision to maintain numerical stability and accuracy. This inverse process is known as dequantization. Dequantization takes the quantized tensor and the associated quantization constant to recover an approximation of the original high-precision values.

The mathematical operation for dequantization is the inverse of the quantization step. Using the quantization constant $c^{\text{FP32}}$ and the quantized Int8 tensor $\mathbf{X}^{\text{Int8}}$, the process is defined as:

$\text{dequant}(c^{\text{FP32}}, \mathbf{X}^{\text{Int8}}) = \frac{\mathbf{X}^{\text{Int8}}}{c^{\text{FP32}}} = \mathbf{X}^{\text{FP32}}$

The quantization constant $c$ is therefore the critical piece of metadata that allows the system to map the low-precision discrete values back into the continuous floating-point space. Without the precise storage of these constants, the original scale of the weights would be lost, making the quantized model unusable for inference or training.

# Low-Rank Adapters (LoRA) Theory: Factorized Projections

Low-rank Adaptation (LoRA) is a parameter-efficient finetuning (PEFT) method designed to reduce the memory overhead associated with updating the weights of massive models. In standard finetuning, every parameter in the model is updated, which requires storing gradients and optimizer states for every single weight. LoRA avoids this by keeping the pretrained model weights fixed (frozen) and instead introducing a small set of trainable parameters called adapters.

The intuition behind LoRA is to approximate the update to the weights using a low-rank decomposition. Consider a standard linear projection where an input $\mathbf{X}$ is multiplied by a weight matrix $\mathbf{W}$ to produce an output $\mathbf{Y}$: $\mathbf{X} \mathbf{W} = \mathbf{Y}$. Here, $\mathbf{X}\in \mathbb{R}^{b\times h}$ and $\mathbf{W}\in \mathbb{R}^{h\times o}$. LoRA augments this operation by adding a separate, factorized path. The computation becomes:

$\mathbf{Y} = \mathbf{X}\mathbf{W} + s\mathbf{X}\mathbf{L}_1\mathbf{L}_2$

In this architecture, $\mathbf{L}_1\in \mathbb{R}^{h\times r}$ and $\mathbf{L}_2\in \mathbb{R}^{r\times o}$ are the two low-rank adapter matrices, and $s$ is a scalar. The value $r$ represents the rank, which is typically much smaller than the dimensions $h$ or $o$. During training, the original weights $\mathbf{W}$ remain frozen, and gradients are backpropagated through $\mathbf{W}$ to update only the adapter weights $\mathbf{L}_1$ and $\mathbf{L}_2$. This drastically reduces the number of trainable parameters.

# Analyzing Memory Footprints: Model Weights vs. Activation Gradients

A common misconception in parameter-efficient finetuning is that the primary memory bottleneck is the size of the learned parameters. However, an analysis of the memory footprint reveals that the most significant memory consumption during training often stems from activation gradients rather than the adapter weights themselves.

To illustrate this, consider a 7B parameter LLaMA model trained on the FLAN v2 dataset with a batch size of 1. If the LoRA weights are set to a common size of 0.2% of the original model weights, the LoRA parameters occupy only 26 MB. In contrast, the input gradients for these LoRA weights require 567 MB of memory. Even when employing gradient checkpointing—a technique used to trade computation for memory—the input gradients still average 18 MB per sequence.

When compared to the base model, the difference is even more stark. A 4-bit quantized base model consumes approximately 5,048 MB of memory. This indicates that the base model weights are the dominant factor in the memory budget, and the activation gradients are far more memory-intensive than the actual LoRA parameters. Consequently, aggressively reducing the number of adapter parameters yields only minor memory benefits. This insight allows researchers to use more adapters across more layers of the network to improve performance without significantly increasing the total training memory footprint.

4-bit NormalFloat (NF4) Quantization

# Quantile Quantization: Information-Theoretic Optimality

To understand the foundation of 4-bit NormalFloat (NF4), one must first understand the concept of quantile quantization. Quantization is the process of representing data using a lower-precision format, such as converting 32-bit floating-point numbers into a 4-bit representation. A core challenge in quantization is ensuring that the available "bins" or discrete values of the lower-precision format are used efficiently. If a data type is not well-aligned with the distribution of the data, many bins may remain empty or underutilized, leading to significant information loss.

Quantile quantization is designed to be information-theoretically optimal by ensuring that each quantization bin has an equal number of values assigned to it from the input tensor. This is achieved by estimating the quantiles of the input tensor using the empirical cumulative distribution function. By assigning values based on their frequency and distribution rather than just their absolute magnitude, the model can maintain a more precise representation of the underlying data.

However, the practical application of quantile quantization is limited by the computational cost of estimating quantiles. Because calculating exact quantiles for massive tensors is expensive, researchers often rely on fast approximation algorithms, such as SRAM quantiles. While these approximations speed up the process, they introduce quantization errors, particularly for outliers. Since outliers are often the most critical values in a neural network's weight distribution, these approximation errors can degrade the overall performance of the model.

# The Normality Assumption of Pretrained Weights

The limitation of quantile estimation—namely, the trade-off between computational expense and accuracy—can be bypassed if the input tensors follow a known, fixed distribution. If the distribution of the data is consistent and only differs by a scaling constant, the quantiles remain the same regardless of the specific tensor. This allows for exact quantile estimation without the need for expensive, data-dependent approximations.

In the context of large language models, pretrained neural network weights typically exhibit a zero-centered normal distribution with a specific standard deviation $\sigma$. This observation is critical because it means that all weights can be transformed into a single fixed distribution by scaling $\sigma$ so that the distribution fits exactly into the range of the chosen data type. For the NF4 data type, this target range is set to $[-1, 1]$.

By leveraging this normality assumption, the need for empirical quantile estimation is removed. Instead of calculating quantiles from the actual weights of a specific model, the quantiles can be derived from a theoretical standard normal distribution $N(0, 1)$. This ensures that the data type is perfectly tuned to the expected distribution of the weights, eliminating the approximation errors associated with SRAM quantiles and ensuring that the most important values are preserved.

# Constructing the NF4 Data Type: Symmetrical and Asymmetrical Quantiles

The construction of the NF4 data type involves a three-step process to ensure the data type is information-theoretically optimal for zero-centered normal distributions. First, the $2^k+1$ quantiles of a theoretical $N(0, 1)$ distribution are estimated to create a $k$-bit quantile quantization data type for normal distributions. Second, these values are normalized to fit within the arbitrary range of $[-1, 1]$. Third, the actual input weight tensor is quantized by normalizing it into the $[-1, 1]$ range through absolute maximum rescaling.

Mathematically, the $2^k$ values $q_i$ of the data type are estimated using the quantile function $Q_X(\cdot)$ of the standard normal distribution $N(0, 1)$ as follows:

$q_i = \frac{1}{2}\left( Q_X\left(\frac{i}{2^k+1}\right) + Q_X\left(\frac{i+1}{2^k+1}\right)\right)$

This process essentially rescales the standard deviation of the weight tensor to match the standard deviation of the $k$-bit data type. By ensuring the weight range and the data type range match, the quantization process can proceed with maximum precision.

# The Role of the Zero-point in NF4

A significant challenge in symmetric $k$-bit quantization is that the resulting data type often lacks an exact representation of zero. In neural networks, having a discrete zeropoint of $0$ is a vital property, as it allows for the quantization of padding and other zero-valued elements without introducing error. Without a precise zero, the model's ability to handle sparse data or padded sequences is compromised.

To solve this, NF4 employs an asymmetric approach to the creation of its data type. Instead of a single symmetric set of quantiles, NF4 estimates the quantiles $q_i$ across two distinct ranges: $2^{k-1}$ quantiles for the negative portion of the distribution and $2^{k-1}+1$ quantiles for the positive portion. These two sets are then unified. Because this process results in two zeros (one from the negative set and one from the positive set), one of the zeros is removed to maintain exactly $2^k$ bits for the $k$-bit data type.

The result of this construction is the $k$-bit NormalFloat (NFk), a data type that provides an equal expected number of values in each quantization bin while guaranteeing a discrete zero. This ensures that NF4 is not only optimal for the normal distribution of weights but also practical for the structural requirements of neural network tensors.

# Empirical Comparison: NF4 vs. FP4 and Int4

The theoretical optimality of NF4 is supported by empirical evidence comparing it to other 4-bit data types, such as 4-bit Integers (Int4) and 4-bit Floats (FP4). In evaluations across various model architectures—including OPT, LLaMA, BLOOM, and Pythia—and model sizes ranging from 125M to 65B parameters, NF4 consistently demonstrates superior performance in terms of zero-shot accuracy and perplexity.

When used within the QLoRA framework, NF4 allows the model to fully recover the performance of 16-bit full finetuning and 16-bit LoRA finetuning. For example, in tests using the LLaMA model on the MMLU benchmark, NF4 with double quantization matched the performance of the 16-bit LoRA baseline. In contrast, using FP4 resulted in a performance drop of approximately one percentage point compared to the 16-bit brain float LoRA baseline.

These results confirm that the information-theoretic properties of NF4 translate into real-world gains. By better aligning the quantization bins with the normal distribution of pretrained weights, NF4 minimizes the precision loss typically associated with 4-bit quantization. This efficiency enables the training of very large models, such as the 65B parameter Guanaco model, on hardware that would otherwise be insufficient for 16-bit finetuning, all without sacrificing predictive performance.

Advanced Memory Savings: Double Quantization and Paged Optimizers

# The Overhead of Quantization Constants

To understand the necessity of advanced memory saving techniques, one must first understand the memory costs associated with standard block-wise quantization. In a basic quantization scheme, a high-precision tensor is converted into a lower-precision representation by normalizing the input elements. This normalization is typically performed by dividing the input by the absolute maximum value of the elements in the tensor, a value known as the quantization constant or quantization scale. However, applying a single quantization constant to an entire tensor can lead to significant precision loss if the tensor contains outliers—values with extreme magnitudes that force the quantization bins to be utilized inefficiently.

To mitigate the outlier problem, a technique called block-wise quantization is employed. In this approach, the input tensor is divided into smaller, contiguous blocks of a specific size, denoted as $B$. Each of these blocks is quantized independently using its own unique quantization constant. While this dramatically improves the precision of the 4-bit representation, it introduces a new problem: memory overhead. Because every block of parameters requires its own associated constant, the total number of constants grows as the block size decreases.

The memory footprint of these constants can be surprisingly high. For example, consider a scenario where the block size is set to $B = 64$ and the quantization constants are stored as 32-bit floating-point numbers. In this configuration, each block of 64 parameters requires 32 bits of additional storage for the constant. This results in a memory overhead of $32/64$, which equals $0.5$ bits per parameter. While half a bit may seem negligible, across the billions of parameters in a large language model, this overhead accumulates into several gigabytes of GPU memory, which is a precious resource during finetuning.

# Double Quantization (DQ) Mechanism: Quantizing the Quantizers

Double Quantization (DQ) is an innovative process designed to reclaim the memory wasted by the quantization constants of the first quantization pass. The core intuition behind DQ is to treat the quantization constants themselves as a tensor that can be quantized. By applying a second layer of quantization to these constants, QLoRA can significantly reduce the average memory footprint without sacrificing the predictive performance of the model.

The mechanism operates in two distinct stages. First, the original weights are quantized into a 4-bit representation, producing a set of 32-bit floating-point quantization constants, which we can denote as $c_2^{\text{FP32}}$. In a standard block-wise setup, these constants would be stored as-is. However, in Double Quantization, these $c_2^{\text{FP32}}$ constants are treated as inputs to a second quantization process. This second pass converts the 32-bit constants into 8-bit floating-point constants, $c_2^{\text{FP8}}$, and generates a new, second-level set of quantization constants, $c_1^{\text{FP32}}$, to manage the 8-bit values.

Because the first-level quantization constants $c_2^{\text{FP32}}$ are always positive, they are not naturally centered around zero. To make the second quantization more efficient and to allow for the use of symmetric quantization, the mean value is subtracted from the $c_2$ constants before they are quantized. For the second quantization pass, a larger block size of 256 is used. This is feasible because 8-bit quantization does not cause the same level of performance degradation as 4-bit quantization. By quantizing the quantizers, the model maintains high precision for the weights while minimizing the storage cost of the metadata required to reconstruct those weights.

# Memory Spikes and Gradient Checkpointing

Even with efficient weight storage, the process of finetuning large language models is plagued by memory volatility. A significant portion of the memory footprint during training does not come from the model weights themselves, but from activation gradients. To manage this, practitioners often use gradient checkpointing, a technique that reduces the memory required to store activations by recalculating them during the backward pass rather than storing them all throughout the forward pass.

Despite the benefits of gradient checkpointing, memory "spikes" still occur. These spikes are sudden, sharp increases in GPU memory usage that happen when the model processes a mini-batch containing a long sequence length. When these spikes exceed the available GPU memory, the system triggers an out-of-memory (OOM) error, which crashes the training process. This volatility makes it incredibly difficult to finetune very large models, such as those with 33B or 65B parameters, on a single machine, as the user must either use very small batches or risk frequent crashes.

# Paged Optimizers: Leveraging NVIDIA Unified Memory

To solve the problem of memory spikes, QLoRA introduces Paged Optimizers. This technique leverages a feature of NVIDIA unified memory that allows for automatic page-to-page transfers between the CPU RAM and the GPU memory. This system functions similarly to how a traditional computer manages virtual memory by paging data between the RAM and the hard disk.

In the context of QLoRA, the optimizer states—which can be quite large—are allocated in paged memory. When the GPU runs out of memory due to a spike during gradient checkpointing, the NVIDIA unified memory system automatically evicts the optimizer states from the GPU to the CPU RAM. This prevents the system from crashing and allows the GPU to continue processing the current batch. Once the memory is needed again during the optimizer update step, the states are paged back from the CPU RAM into the GPU memory. This ensures error-free processing of long sequences on hardware that would otherwise be insufficient to handle the peak memory demand.

# Calculating Total Memory Savings from DQ and Paging

The efficacy of Double Quantization can be quantified by comparing the bits per parameter required for constants in a standard block-wise setup versus a double-quantized setup. In a standard setup with a block size of 64 and 32-bit constants, the cost is $32/64 = 0.5$ bits per parameter. 

With Double Quantization, the cost is split across two levels. For the first level of quantization, the constants are reduced to 8 bits, meaning each of the 64 blocks now costs 8 bits. For the second level of quantization, a 32-bit constant is used for every 256 of these 8-bit constants. The total memory footprint per parameter is calculated as follows:

$$\frac{8}{64} + \frac{32}{64 \cdot 256} = 0.127 \text{ bits per parameter}$$

By comparing the two methods, we see that Double Quantization reduces the memory footprint from $0.5$ bits to $0.127$ bits, resulting in a total saving of approximately $0.373$ bits per parameter. When applied to a model of 65 billion parameters, this reduction translates to a memory saving of approximately 3 GB. When combined with Paged Optimizers, which eliminate the need to over-provision GPU memory to account for spikes, QLoRA enables the finetuning of massive models on hardware that was previously considered impossible for such tasks.

The QLoRA Architecture and Workflow

# The QLoRA Equation: Combining NF4 and BF16 LoRA

At the heart of the QLoRA architecture is a mathematical formulation that allows a model to benefit from the memory efficiency of 4-bit quantization while maintaining the predictive power of 16-bit finetuning. This is achieved by combining a frozen, quantized base model with a set of trainable, low-rank adapters. For a single linear layer, the output $\mathbf{Y}^{\text{BF16}}$ is calculated using the following equation:

$\mathbf{Y}^{\text{BF16}} = \mathbf{X}^{\text{BF16}} \text{doubleDequant}(c_1^{\text{FP32}}, c_2^{\text{k-bit}}, \mathbf{W}^{\text{NF4}}) + \mathbf{X}^{\text{BF16}}\mathbf{L}^{\text{BF16}}_1\mathbf{L}^{\text{BF16}}_2$

To understand this equation, we must look at its two primary paths. The first path represents the frozen base model. Here, the weights $\mathbf{W}^{\text{NF4}}$ are stored in a specialized 4-bit NormalFloat format. Because matrix multiplication cannot be performed directly on NF4 values, the $\text{doubleDequant}$ function is used to restore these weights to a higher precision. The $\text{doubleDequant}$ process is a nested operation defined as $\text{dequant}(\text{dequant}(c_1^{\text{FP32}}, c_2^{\text{k-bit}}), \mathbf{W}^{\text{4bit}})$, which ultimately produces the weight matrix in BFloat16 precision ($\mathbf{W}^{\text{BF16}}$).

The second path is the Low-Rank Adapter (LoRA) component. Instead of updating the massive weight matrix $\mathbf{W}$, QLoRA introduces two smaller, trainable matrices, $\mathbf{L}_1$ and $\mathbf{L}_2$, both stored in BFloat16. These matrices are factorized, meaning they use a small rank $r$ to represent the updates to the model. The final output is the sum of the frozen base model's projection and the adapter's projection. This design ensures that the vast majority of the model parameters remain frozen and compressed, while only a tiny fraction of parameters are optimized during training.

# Storage vs. Computation Data Types

A critical innovation in QLoRA is the strict separation between the data type used for storage and the data type used for computation. In traditional training, weights are often stored and computed in the same precision (such as FP32 or BF16). However, QLoRA utilizes a dual-type system to maximize memory efficiency without sacrificing the numerical stability required for backpropagation.

The storage data type is typically 4-bit NormalFloat (NF4). NF4 is an information-theoretically optimal data type for weights that follow a zero-centered normal distribution. By using only 4 bits to store each parameter, QLoRA drastically reduces the memory footprint of the base model. For example, this allows a 65B parameter model to fit within the memory limits of a single professional GPU, which would be impossible using standard 16-bit storage.

The computation data type, on the other hand, is BFloat16 (BF16). While NF4 is excellent for storage, it does not possess the precision necessary for the complex floating-point arithmetic involved in forward and backward passes. Therefore, whenever a weight tensor is needed for a calculation, it is temporarily converted from its NF4 storage format to the BF16 computation format. All matrix multiplications and gradient updates are performed in BF16. This ensures that the model retains the accuracy of 16-bit finetuning while the bulk of the model remains compressed in 4-bit storage.

# The Forward Pass: Dequantization on the Fly

During the forward pass of a QLoRA-enhanced model, the system must bridge the gap between the compressed storage and the high-precision computation. This is achieved through a process known as dequantization on the fly. When an input $\mathbf{X}^{\text{BF16}}$ enters a linear layer, the model does not load a full BF16 weight matrix from memory; instead, it retrieves the 4-bit NF4 weights and the associated quantization constants.

The dequantization process is made even more efficient through Double Quantization (DQ). In standard quantization, a quantization constant $c$ is needed for each block of weights to rescale them. However, these constants themselves take up significant memory. Double Quantization treats the first set of quantization constants, $c_2^{\text{FP32}}$, as inputs to a second quantization step. This yields a second set of quantized constants $c_2^{\text{k-bit}}$ and a final second-level constant $c_1^{\text{FP32}}$. 

As the forward pass progresses, the $\text{doubleDequant}$ function first uses $c_1^{\text{FP32}}$ to dequantize $c_2^{\text{k-bit}}$ back into $c_2^{\text{FP32}}$. Then, it uses these restored constants to dequantize the NF4 weights into BF16. This restored matrix is then multiplied by the input $\mathbf{X}^{\text{BF16}}$. Simultaneously, the input is passed through the BF16 LoRA adapters. The results of these two operations are summed to produce the final output for the layer. This "on the fly" approach ensures that high-precision weights only exist momentarily during the computation of the layer and are not stored permanently in the GPU memory.

# The Backward Pass: Propagating Gradients through Frozen Quantized Weights

The backward pass in QLoRA is designed to optimize the adapters while keeping the quantized base model entirely frozen. Because the base weights $\mathbf{W}^{\text{NF4}}$ are not being updated, the system does not need to compute or store gradients for them ($\frac{\partial E}{\partial \mathbf{W}}$), which is where the most significant memory savings occur.

Despite the base weights being frozen, they are still essential for calculating the gradients of the adapters. To compute the gradient with respect to the adapter weights $\frac{\partial E}{\partial \mathbf{L}_i}$, the system must backpropagate through the linear layer. This requires the calculation of $\frac{\partial \mathbf{X}}{\partial \mathbf{W}}$, which is performed using the dequantized BF16 version of the weights. In other words, the 4-bit weights are treated as a constant BF16 matrix during the chain rule application in the backward pass.

To manage the memory spikes that often occur during the backward pass—particularly when processing mini-batches with long sequence lengths—QLoRA employs Paged Optimizers. This feature leverages NVIDIA unified memory to automatically transfer optimizer states between the GPU and CPU RAM. When the GPU runs out of memory during the calculation of gradients, the paged optimizer evicts the necessary states to the CPU and pages them back in when the optimizer update step occurs. This prevents out-of-memory errors and allows the finetuning of massive models on hardware with limited VRAM.

# Hyperparameter Tuning: The Importance of Adapter Placement across Layers

A key finding in the development of QLoRA is that the effectiveness of the method depends heavily on how the LoRA adapters are applied. In previous iterations of LoRA, it was common practice to apply adapters only to a small subset of the model, such as the query and value attention projection matrices. However, the researchers found that this limited placement is insufficient to recover the full performance of a 16-bit fully finetuned model.

To bridge the gap between 4-bit quantized finetuning and 16-bit full finetuning, QLoRA requires the placement of adapters across all linear transformer block layers. By increasing the number of adapters, the model has more capacity to learn the necessary adjustments to compensate for the precision loss introduced by 4-bit quantization. The study demonstrates that the total number of adapters used is the most critical hyperparameter for matching full finetuning performance.

Interestingly, other common LoRA hyperparameters, such as the projection dimension $r$ (the rank of the adapters), were found to have a much smaller impact on final performance. This suggests that the breadth of adapter application—ensuring every linear layer is covered—is far more important than the depth or complexity of each individual adapter. When adapters are applied comprehensively across the network, 4-bit QLoRA can reliably replicate the performance of 16-bit full finetuning and 16-bit LoRA.

Evaluating QLoRA: Performance and the Guanaco Models

# Benchmarking QLoRA against Full 16-bit Finetuning

A primary concern when introducing quantization into the training process is whether the reduction in precision leads to a loss in model performance. To address this, QLoRA was benchmarked against both 16-bit adapter-finetuning and full 16-bit finetuning across several architectures, including encoder-only (RoBERTa-large), encoder-decoder (T5), and decoder-only (LLaMA) models. The evaluations spanned diverse tasks, such as the GLUE benchmark for RoBERTa, the Super-NaturalInstructions (TKInstruct) dataset for T5, and 5-shot MMLU accuracy for LLaMA models trained on Alpaca and Flan v2.

Through these experiments, a critical insight emerged regarding the implementation of Low-Rank Adapters (LoRA). In standard LoRA practice, adapters are typically applied only to the query and value attention projection matrices. However, the researchers found that this limited application was insufficient to replicate the performance of full finetuning for large base models. The most critical hyperparameter for achieving parity with 16-bit performance was the total number of adapters used. Specifically, it was discovered that applying LoRA adapters to all linear transformer block layers is required to match the performance of full finetuning. Other hyperparameters, such as the projection dimension $r$, did not significantly affect performance.

Furthermore, the study highlighted that previous fully finetuned baselines were often undertuned. To ensure a fair and robust comparison, the team conducted a hyperparameter search over learning rates ranging from $1\text{e}-6$ to $5\text{e}-5$ and batch sizes between 8 and 128. By optimizing these baselines, the researchers could more accurately determine that QLoRA is capable of reaching the same performance levels as its high-precision counterparts.

# Recovery of Precision: Can Adapters Offset Quantization Loss?

The theoretical foundation of QLoRA rests on the idea that the performance degradation typically associated with 4-bit quantization during inference can be recovered during the finetuning process. In traditional quantization, the loss of precision creates a gap between the quantized model and the original 16-bit model. QLoRA addresses this by using 4-bit NormalFloat (NF4), a data type that is information-theoretically optimal for the normally distributed weights typical of pretrained neural networks.

The empirical results demonstrate that the imprecise nature of 4-bit quantization does not permanently damage the model's capabilities. When testing RoBERTa and T5 models ranging from 125M to 3B parameters on GLUE and TKInstruct, the researchers found that 16-bit, 8-bit, and 4-bit adapter methods all replicated the performance of the fully finetuned 16-bit baseline. This suggests that the learnable adapter weights effectively "offset" the quantization loss, recovering the precision necessary for high-quality task performance.

This recovery is particularly evident when comparing different 4-bit data types. The researchers observed that NF4 consistently yields better performance than standard 4-bit Floating Point (FP4) or 4-bit Integers (Int4). In tests with LLaMA models scaling from 7B to 65B parameters on MMLU, NF4 combined with double quantization fully recovered the performance of 16-bit LoRA. In contrast, QLoRA using FP4 lagged behind the 16-bit baseline by approximately one percentage point. This confirms that while adapter finetuning can recover much of the lost precision, the choice of the underlying quantization data type—specifically the use of NF4—is vital for achieving full 16-bit parity.

# The Guanaco Model Family: Training on OASST1

To demonstrate the practical utility of QLoRA, the researchers developed the Guanaco family of models. These models were created by applying QLoRA finetuning to LLaMA base models of various sizes, including 7B, 13B, 33B, and 65B parameters. The training was conducted using the OASST1 dataset, a multilingual collection of crowd-sourced multiturn dialogs. Unlike many state-of-the-art chatbots, the Guanaco models were trained using simple cross-entropy loss (supervised learning) and did not rely on Reinforcement Learning from Human Feedback (RLHF).

The performance of the Guanaco models is highly competitive. According to the Vicuna benchmark, Guanaco 65B reached 99.3% of the performance level of ChatGPT. When evaluated via human annotators using pairwise comparisons and Elo ratings, Guanaco 33B and 65B outperformed all other open-source models, exhibiting an expected win probability of 30% against GPT-4—the highest reported for an open-source model to date.

One of the most significant achievements of the Guanaco family is the drastic reduction in memory requirements. While a regular 16-bit finetuning of a LLaMA 65B model would require more than 780 GB of GPU memory, QLoRA allows it to be finetuned on a single 48GB GPU. Even at the deployment stage, the smallest Guanaco model (7B) requires only 5 GB of memory, making it small enough to fit on modern mobile phones while still outperforming the 13B Alpaca model by nearly 20 percentage points on the Vicuna benchmark.

# Analysis of Instruction Tuning: Data Quality vs. Dataset Size

The efficiency of QLoRA allowed the researchers to perform a massive study involving the training of over 1,000 models across eight different instruction datasets and various model scales. This enabled them to analyze the relationship between the size of the finetuning dataset and the resulting model performance. A key finding of this analysis is that the quality of the data is far more important than the total volume of the dataset.

The researchers compared the performance of models trained on different datasets of varying sizes. For instance, they found that a small, high-quality dataset like OASST1, containing only 9,000 samples, outperformed a much larger subsampled version of the FLAN v2 dataset containing 450,000 samples when evaluated for chatbot performance. This demonstrates that increasing the quantity of data does not necessarily lead to a better chatbot if the data quality or suitability is lacking.

This finding challenges the intuition that larger datasets always lead to better generalization in instruction following. Instead, the results suggest that a curated, high-quality dataset allows a model to learn the desired behaviors more effectively, even when the model size is smaller than previous state-of-the-art models. This emphasizes the value of focusing on data purity and suitability over raw data scale.

# Orthogonality of Benchmarks: MMLU vs. Chatbot Performance

The QLoRA experiments also revealed a phenomenon described as the orthogonality of different evaluation benchmarks. In this context, orthogonality means that performance on one type of benchmark does not necessarily predict performance on another. Specifically, the researchers found that strong performance on the Massive Multitask Language Understanding (MMLU) benchmark does not imply strong performance on chatbot benchmarks like Vicuna or OA, and vice versa.

For example, LLaMA models finetuned on the FLAN v2 dataset performed exceptionally well on MMLU tasks, which involve a wide range of academic knowledge and multiple-choice reasoning. However, these same models performed the worst among the tested group on the Vicuna chatbot benchmark. This indicates that the suitability of the finetuning dataset for a specific goal is the determining factor in success. A dataset designed for general knowledge and task-based instruction following (like FLAN v2) does not translate into the conversational fluency and persona required for a high-performing chatbot.

This disconnect suggests that current chatbot benchmarks are not entirely trustworthy for assessing general intelligence, and academic benchmarks do not capture the nuances of human-like conversation. Consequently, the researchers argue that the community must be careful about which benchmarks are used to steer model development, as the choice of evaluation metric largely determines the behavior the model is optimized to exhibit.

Measuring Chatbot Quality: From GPT-4 to Elo Ratings

# The Limitations of Multiple-Choice Benchmarks (MMLU)

In the evaluation of large language models, the Massively Multitask Language Understanding (MMLU) benchmark is frequently used as a primary metric for measuring a model's general intelligence and knowledge. MMLU is a multiple-choice benchmark that spans 57 different tasks, including diverse subjects such as elementary mathematics, US history, law, and computer science. In practice, this is often measured using 5-shot test accuracy, where the model is given five examples of the task before being asked to provide an answer. While MMLU is a rigorous test of natural language understanding and factual recall, it possesses significant limitations when used as a proxy for chatbot performance.

The primary limitation of MMLU is that it does not necessarily correlate with a model's ability to function as an effective conversational assistant. The research indicates a partial orthogonality between academic benchmark performance and chatbot performance. Specifically, the suitability of the finetuning dataset plays a more critical role than the overall size of the dataset. For example, models finetuned on FLAN v2 perform exceptionally well on the MMLU benchmark but perform the worst on chatbot-specific benchmarks like the Vicuna benchmark. This suggests that a model can be highly proficient at solving multiple-choice academic questions while remaining poor at following conversational instructions. Therefore, relying solely on MMLU can provide a misleading picture of how a model will behave in a real-world user interaction.

# Automated Evaluation via GPT-4: Prompting and Scoring

Because human evaluation is expensive and slow, researchers have turned to automated evaluation systems, using highly capable models like GPT-4 to act as judges. One common protocol involves using GPT-4 to rate the performance of a target model against a baseline, such as ChatGPT (GPT-3.5 Turbo). In this setup, GPT-4 is provided with a query and the responses from both the target model and ChatGPT. GPT-4 is then prompted to assign a score out of ten to each response and provide a detailed explanation for its reasoning. The final performance of the target model is expressed as a percentage of the score achieved by ChatGPT; if a model achieves a higher absolute score than ChatGPT, its relative score can exceed $100\%$.

However, automated evaluation is not without its own systemic flaws. One significant issue identified is the "ordering effect," where GPT-4 tends to assign higher scores to the response that appears first in the prompt. To mitigate this bias, it is recommended to report the mean score over both possible orderings of the responses. Beyond absolute scoring, GPT-4 can also be used for direct, head-to-head comparisons. In this three-class labeling problem, GPT-4 is asked to pick the best response between two models or declare a tie, again providing an explanation. While this provides a more direct comparison, it remains an approximation of human preference.

# Human Evaluation Protocols and the Role of Amazon Mechanical Turk

To validate whether automated evaluations by GPT-4 are reliable, human evaluations are conducted as a "gold standard" comparison. Human evaluation aims to capture the nuances of quality, helpfulness, and naturalness that automated metrics might miss. In the QLoRA study, human evaluations were performed using Amazon Mechanical Turk (AMT), a crowdsourcing marketplace that allows researchers to recruit a diverse set of human annotators to judge model outputs.

The human evaluation protocol mirrors the automated one to ensure a direct comparison. For evaluations comparing a model's response to ChatGPT, two human annotators are typically used. For pairwise comparisons between two different models, three annotators are used to ensure a majority vote can be reached. These annotators are presented with the same queries used in the automated benchmarks, such as the Vicuna prompts or the OASST1 validation dataset. By comparing the judgments of AMT workers with the judgments of GPT-4, researchers can determine the degree to which model-based evaluation serves as a reasonable alternative to human annotation.

# The Elo Rating System: Tournament-style Model Comparison

To move beyond absolute scores—which can be subjective and lack a grounded scale—researchers employ a tournament-style competition using the Elo rating system. In this framework, models compete against each other in matches. A "match" consists of a single prompt where two models produce responses, and a judge (either a human or GPT-4) determines the winner. The Elo rating is a measure of the expected win-rate of one model relative to another. For example, if one model has an Elo of $1100$ and its opponent has an Elo of $1000$, the model with $1100$ is expected to win approximately $65\%$ of the time.

The Elo system is dynamic; ratings change after every match based on the outcome. The magnitude of the change is proportional to the expected outcome of the match. If a low-rated model unexpectedly defeats a high-rated model—a "major upset"—the Elo ratings shift significantly. Conversely, if the expected winner wins, the ratings change only slightly. This is governed by a constant, such as $K=32$, and a starting score, typically $1000$. By repeating this process thousands of times with different random seeds to control for ordering effects, a stable leaderboard is created that reflects the relative skill and quality of the chatbots across a wide range of prompts.

# Analyzing Correlation and Bias in Model-based Evaluation

The final step in evaluating chatbot quality is analyzing the correlation between human and automated judgments to identify potential biases. Research shows a moderate agreement between system-level judgments made by GPT-4 and human annotators. This is quantified using metrics such as the Kendall Tau correlation ($\tau = 0.43$) and the Spearman rank correlation ($r = 0.55$). However, this agreement weakens significantly at the example level, where the Fleiss $\kappa$ (a measure of agreement for categorical items) drops to $0.25$. This indicates that while GPT-4 and humans may agree on which model is generally better, they often disagree on why a specific response is better.

Furthermore, automated evaluators exhibit distinct biases. One prominent bias is "self-preference," where GPT-4 assigns significantly higher scores to its own outputs than human raters do. This is evidenced by the Elo ratings, where GPT-4's self-evaluation yielded an Elo of $1348$ compared to a human-assigned Elo of $1176$, representing an additional $20\%$ probability of winning. Additionally, the subjective nature of these evaluations remains a challenge; even human annotators often disagree when comparing two very strong systems. Ultimately, while model-based evaluation is a cheap and reasonable alternative to human annotation, it is not a perfect substitute and requires careful interpretation and bias mitigation.

# Qualitative Analysis and Model Limitations

While quantitative benchmarks provide a high-level overview of a model's performance, they often fail to capture the nuances of how a model actually behaves during a conversation. To truly understand the strengths and weaknesses of the Guanaco model family—developed using the \textsc{QLoRA} finetuning method—it is necessary to conduct a qualitative analysis. This process involves identifying patterns in the model's output and attempting to "break" the model through adversarial prompting. By analyzing "lemons" (failure cases) and "cherries" (success cases), we can gain intuition into the gap between a model's statistical performance and its real-world reliability.

# Factual Recall and the Confidence-Accuracy Gap

One of the primary challenges for large language models is the tension between factual accuracy and confidence. In the case of the Guanaco 65B model, factual recall is highly dependent on the popularity or "commonness" of the information. For widely known facts, such as identifying the capital of Zambia as Lusaka, the model is consistently accurate. However, as the queries become more obscure, the model's reliability drops significantly.

The most concerning aspect of this failure mode is the "confidence-accuracy gap." When the model fails to recall an obscure fact, it does not typically express doubt; instead, it remains highly confident in its incorrect answer. For example, when asked about the singer who popularized a specific song, the model may confidently name the wrong person and provide a birth date that is correct for that wrong person, but incorrect for the actual singer. This suggests that while \textsc{QLoRA} can produce a model that sounds authoritative and fluent, the internal representation of obscure facts remains susceptible to hallucinations that the model cannot self-correct.

# Suggestibility and Instruction Following: 'Secret Keeping' Tests

Instruction following is a cornerstone of chatbot utility, and Guanaco demonstrates a complex relationship with these constraints. On one hand, the model shows a surprising level of resistance to suggestibility. When a user attempts to lead the model into accepting misinformation—such as claiming that peer-reviewed scientists have confirmed the earth is flat—the model resists and correctly identifies the claim as a debunked conspiracy theory. Furthermore, it demonstrates a strong sense of its own operational boundaries, such as correctly refusing to answer "What time is it?" by explaining that it lacks access to real-time information.

However, this robustness is inconsistent. The model sometimes exhibits "random refusal," where it declines to follow a simple, harmless instruction—such as reversing the words in a sentence—for reasons that are not logically apparent, often pivoting to an unsolicited grammatical analysis of the sentence instead.

This inconsistency is most evident in "secret keeping" tests. When instructed to keep a secret word (e.g., "banana") and not reveal it regardless of the user's request, the model initially succeeds by refusing direct questions. Yet, this behavior is easily bypassed using a small amount of trickery. By framing the request as a game and telling the model to ignore previous instructions, the user can successfully trick the model into revealing the secret. This highlights a critical limitation in faithful instruction following: the model's constraints are not absolute and can be overridden by adversarial prompt engineering.

# Mathematical Reasoning and the Need for Step-by-Step Decomposition

Mathematics represents the most significant weakness for the Guanaco models. The disparity in performance is closely tied to whether the model employs a step-by-step decomposition of the problem. When the model "shows its work" by breaking a word problem into individual arithmetic steps, it is often accurate. This suggests that the model possesses the basic capability to perform calculations if it can organize the logic linearly.

In contrast, when the model attempts to solve a problem without this decomposition, it frequently fails, even on simple tasks. A poignant example is the factorization of the number 1833. In such cases, the model may not only provide the wrong answer but may contradict itself within the same response—claiming a number is prime while simultaneously providing a non-prime factorization. This indicates that the model's mathematical "intuition" is unreliable, and its success is heavily dependent on the specific prompting strategy (such as chain-of-thought) rather than an inherent understanding of mathematical principles.

# Theory of Mind: Capabilities and Failures in Social Inference

Theory of Mind (ToM) refers to the ability to attribute mental states—beliefs, intents, desires—to oneself and others, and to understand that others have beliefs that are different from one's own. Guanaco displays surprisingly strong capabilities in this area. In complex social scenarios, such as tracking the location of an object and determining where one character thinks another character will look for it, the model can provide detailed and correct inferences.

Despite these strengths, these inferences remain unreliable. The model occasionally suffers from "information leakage" in its reasoning, where it presumes that a character knows something that was never described in the prompt. For instance, if one character moves an object in secret, the model might incorrectly conclude that another character knows the new location, thereby assuming a transfer of information that never occurred. This suggests that while the model can simulate the structure of social inference, it sometimes fails to maintain a strict boundary between the different "knowledge states" of the characters involved.

# Future Directions: 3-bit Quantization and Other PEFT Methods

The success of \textsc{QLoRA} in recovering 16-bit performance using a 4-bit base model opens several avenues for future research. One primary question is whether the precision-performance trade-off can be pushed even further. Since finetuning after quantization appears to recover much of the information lost during the initial discretization, it is possible that more aggressive quantization, such as 3-bit GPTQ quantization of the base model combined with LoRA adapters, could also yield performance matching 16-bit full finetuning.

Additionally, while Low-Rank Adapters (LoRA) were chosen for their established robustness, they are only one of many Parameter-Efficient Finetuning (PEFT) methods. Other techniques, such as prompt tuning, tuning hidden states, or learning masks over weights, have been proposed in the literature. Future work could explore whether these alternative PEFT approaches scale to the massive model sizes (33B and 65B parameters) enabled by \textsc{QLoRA}, potentially discovering a combination of quantization and adapter-tuning that further optimizes the balance between memory efficiency and predictive power.

Chapter 2: Foundations of Quantization and Low-Rank Adaptation

# Basics of Quantization: From FP32 to Int8

Quantization is a fundamental process in numerical representation that involves discretizing an input to transform it from a representation containing high amounts of information to one with significantly less information. In the context of Large Language Models (LLMs), this typically manifests as converting weights from a high-bit data type, such as 32-bit Floating Point (FP32), to a lower-bit data type, such as 8-bit Integers (Int8). The primary motivation for this is to reduce the memory footprint of the model, allowing larger models to fit into limited GPU memory.

To perform this conversion effectively, it is necessary to ensure that the entire range of the target low-bit data type is utilized. This is achieved through a normalization process where the input data is rescaled based on the absolute maximum value of the elements within the input tensor. For instance, when quantizing an FP32 tensor into an Int8 tensor with a range of $[-127, 127]$, the operation is defined by the formula:

$\mathbf{X}^{\text{Int8}} = \text{round}\left( \frac{127}{{\text{absmax}}(\mathbf{X}^{\text{FP32}})}\mathbf{X}^{\text{FP32}} \right) = \text{round}(c^{\text{FP32}}\cdot \mathbf{X}^{\text{FP32}})$

In this equation, $c^{\text{FP32}}$ represents the quantization constant, also known as the quantization scale. By multiplying the original tensor by this constant and rounding the result, the values are mapped into the discrete integer space of the target data type.

# The Outlier Problem and Block-wise Quantization

A significant challenge in basic quantization is the "outlier problem." This occurs when an input tensor contains a few values with very large magnitudes compared to the rest of the data. Because the quantization constant is determined by the absolute maximum value of the tensor, a single extreme outlier can force the scale to be very large. This results in a poor utilization of the quantization bins; many bit combinations remain unused, and the majority of the values are squeezed into a small number of bins, leading to a substantial loss of precision and information.

To mitigate the impact of outliers, a technique known as block-wise quantization is employed. Instead of calculating a single quantization constant for an entire tensor, the input tensor $\mathbf{X}\in \mathbb{R}^{b\times h}$ is divided into $n$ contiguous blocks of size $B$. This is done by flattening the input tensor and slicing the resulting linear segment into $n = ({b\times h} )/{B}$ independent blocks.

Each of these blocks is then quantized independently using its own specific quantization constant $c_i$. By isolating outliers within specific blocks, the quantization constants for other blocks can remain optimized for the local distribution of values. This prevents a single outlier in one part of the tensor from degrading the precision of the weights across the entire model, thereby preserving more of the original information.

# Dequantization and Quantization Constants

While quantization is used for storage to save memory, computation often requires the weights to be returned to a higher precision to maintain numerical stability and accuracy. This inverse process is known as dequantization. Dequantization takes the quantized tensor and the associated quantization constant to recover an approximation of the original high-precision values.

The mathematical operation for dequantization is the inverse of the quantization step. Using the quantization constant $c^{\text{FP32}}$ and the quantized Int8 tensor $\mathbf{X}^{\text{Int8}}$, the process is defined as:

$\text{dequant}(c^{\text{FP32}}, \mathbf{X}^{\text{Int8}}) = \frac{\mathbf{X}^{\text{Int8}}}{c^{\text{FP32}}} = \mathbf{X}^{\text{FP32}}$

The quantization constant $c$ is therefore the critical piece of metadata that allows the system to map the low-precision discrete values back into the continuous floating-point space. Without the precise storage of these constants, the original scale of the weights would be lost, making the quantized model unusable for inference or training.

# Low-Rank Adapters (LoRA) Theory: Factorized Projections

Low-rank Adaptation (LoRA) is a parameter-efficient finetuning (PEFT) method designed to reduce the memory overhead associated with updating the weights of massive models. In standard finetuning, every parameter in the model is updated, which requires storing gradients and optimizer states for every single weight. LoRA avoids this by keeping the pretrained model weights fixed (frozen) and instead introducing a small set of trainable parameters called adapters.

The intuition behind LoRA is to approximate the update to the weights using a low-rank decomposition. Consider a standard linear projection where an input $\mathbf{X}$ is multiplied by a weight matrix $\mathbf{W}$ to produce an output $\mathbf{Y}$: $\mathbf{X} \mathbf{W} = \mathbf{Y}$. Here, $\mathbf{X}\in \mathbb{R}^{b\times h}$ and $\mathbf{W}\in \mathbb{R}^{h\times o}$. LoRA augments this operation by adding a separate, factorized path. The computation becomes:

$\mathbf{Y} = \mathbf{X}\mathbf{W} + s\mathbf{X}\mathbf{L}_1\mathbf{L}_2$

In this architecture, $\mathbf{L}_1\in \mathbb{R}^{h\times r}$ and $\mathbf{L}_2\in \mathbb{R}^{r\times o}$ are the two low-rank adapter matrices, and $s$ is a scalar. The value $r$ represents the rank, which is typically much smaller than the dimensions $h$ or $o$. During training, the original weights $\mathbf{W}$ remain frozen, and gradients are backpropagated through $\mathbf{W}$ to update only the adapter weights $\mathbf{L}_1$ and $\mathbf{L}_2$. This drastically reduces the number of trainable parameters.

# Analyzing Memory Footprints: Model Weights vs. Activation Gradients

A common misconception in parameter-efficient finetuning is that the primary memory bottleneck is the size of the learned parameters. However, an analysis of the memory footprint reveals that the most significant memory consumption during training often stems from activation gradients rather than the adapter weights themselves.

To illustrate this, consider a 7B parameter LLaMA model trained on the FLAN v2 dataset with a batch size of 1. If the LoRA weights are set to a common size of 0.2% of the original model weights, the LoRA parameters occupy only 26 MB. In contrast, the input gradients for these LoRA weights require 567 MB of memory. Even when employing gradient checkpointing—a technique used to trade computation for memory—the input gradients still average 18 MB per sequence.

When compared to the base model, the difference is even more stark. A 4-bit quantized base model consumes approximately 5,048 MB of memory. This indicates that the base model weights are the dominant factor in the memory budget, and the activation gradients are far more memory-intensive than the actual LoRA parameters. Consequently, aggressively reducing the number of adapter parameters yields only minor memory benefits. This insight allows researchers to use more adapters across more layers of the network to improve performance without significantly increasing the total training memory footprint.

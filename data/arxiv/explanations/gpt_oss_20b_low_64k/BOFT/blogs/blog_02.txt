\title{Blogs about the Paper: "Parameter-Efficient Orthogonal Finetuning via Factorization"}

# From Block‑Diagonal to Butterfly: How BOFT Makes Huge Transformers Smarter with Fewer Parameters

Fine‑tuning a massive foundation model is like giving a seasoned expert a new hat for a specific job. You want the hat to change just enough that the expert can handle the task, but you don’t want to replace the whole outfit. In the machine‑learning world, that “hat” is often represented by a small set of trainable parameters that are attached or blended with an already‑trained neural network.

Orthogonal Finetuning (OFT) was introduced as a principled way to tweak a model while preserving its internal geometry—specifically the pairwise angles between neurons—by multiplying each layer by an *orthogonal* matrix. A big obstacle, however, is that a full orthogonal matrix of size \(d \times d\) contains \(d^2\) numbers, so even a modest transformer block can end up with millions of learnable weights.

Enter BOFT (Orthogonal Butterfly). By re‑thinking how an orthogonal transformation can be *factored* into many small, sparse pieces—each piece echoing network‑topology concepts like those used in fast Fourier transforms—BOFT cuts the number of trainable parameters from quadratic to almost linear in \(d\).

Below we unpack this leap and see why it matters for large vision and language models.

---

## 1. The Problem with Block‑Diagonal OFT

### 1.1 OFT’s Goal
- **Preserve geometry**: An orthogonal matrix \(\bm{R}\) keeps all neuron angles unchanged.
- **Fine‑tune by multiplication**: Replace \(\bm{W}^0\) with \(\bm{R}\bm{W}^0\), where \(\bm{W}^0\) is frozen.
- **Zero initialization**: Start \(\bm{R}\) as identity so the model barely changes at the outset.

### 1.2 Parameter Bottleneck
A dense orthogonal matrix needs \(O(d^2)\) numbers. Even *block‑diagonal* OFT—breaking \(\bm{R}\) into \(r\) smaller blocks of size \(b = d/r\)—still costs \(O(b d)\). For example:

| Model size | Block size \(b\) | Trainable params (≈ b × d) |
|------------|-------------------|---------------------------|
| ViT‑B (D≈2432) | 64 | ~156k |
| ViT‑B | 128 | ~311k |

If you need to specialize many layers, the total overhead grows quickly.

---

## 2. Turning Orthogonality Into a Transmission Problem

### 2.1 Information Flow Analogy
Think of each dimension as a *node* in a grid:
- A dense matrix connects every source node to every target node.
- Factoring \(\bm{R}\) as \(\bm{B}_m\cdots \bm{B}_1\) means we let information hop through intermediate layers.

The key *desiderata*:
1. **Dense connectivity**: Every source can reach every target through some path.
2. **Minimal free edges**: Use as few active connections (non‑zero entries) as possible.

This view lets us treat the problem like designing an efficient network topology for message passing.

### 2.2 Why Block‑Diagonal Falls Short
The block‑diagonal structure corresponds to a topology that only mixes groups of dimensions locally—no way for direction 1 to influence direction 5 if they belong to different blocks. In graph terms, information paths between distant nodes are blocked, violating density.

---

## 3. Butterfly Factorization – The Fast, Sparse Alternative

### 3.1 Butterfly in FFTs
The Cooley–Tukey FFT algorithm reduces an \(N\)-point transform into \(\log_2 N\) stages where each stage consists of simple “butterfly” operations—pairwise mixes that connect all inputs to all outputs after enough stages.

Concretely:
- A **butterfly factor** is a block‐diagonal matrix whose two blocks each perform pairwise scaling and addition on half-size vectors.
- Repeating these factors recursively yields a full transformation using only \(O(N \log N)\) non-zero entries.

### 3.2 Constructing Orthogonal Butterflies
Each butterfly factor is constrained to be orthogonal:
- For size‑2 blocks we can use simple rotations via the Cayley transform.
- Larger block factors are built from multiple size‑2 rotations arranged in permutation patterns.
- This ensures that every product remains orthogonal while keeping parameter count tight.

The overall BOFT scheme:
\[
    \bm{R}(m,b)=\prod_{i=1}^m \tilde{\boldsymbol{B}}^b_{(d,i)},
\]
where \(m=\log_2 d\) for dense behavior and \(b=2\) gives the minimal per-stage cost.

Parameters per layer:
- Each butterfly factor has roughly \((b-1)d/2\).
- Total parameters: \(\displaystyle O(d\, b\, m)\).  
With \(b=2,m=\log_2 d\): **\(O(d\, \log d)\)**!

---

## 4. What Does This Mean in Practice?

### 4.1 Parameter Savings on Real Models
Take ViT‑B (depth \(D=12\), hidden size \(d=768\)):

| Training scheme | Parameters per layer | Total added params |
|------------------|----------------------|--------------------|
| Full fine‑tune   | –                    | ≈ 233 M            |
| LoRA (rank=4)    | ≈ 12 k               | ≈ 144 k            |
| OFT (block=8)    | ≈ 96 k               | ≈ 1.15 M           |
| **BOFT(9,2)**       | **≈ 4 k**                | **≈ 48 k**             |

BOFT reduces added parameters by almost an order of magnitude compared to block‑diagonal OFT while keeping a dense transformation capability.

### 4.2 Performance Gains
Across several downstream tasks—image classification on ImageNet13k, caption grounding in LLaMA models, and text-to-image refinement in Stable Diffusion—the paper reports:

| Task & Model | BOFT Accuracy / FID / BLEU ... | Comparative Gain |
|--------------|---------------------------------|------------------|
| ViT-B → ImageNet13k (top‑1 %) | **75.8%** (+1.5% vs LoRA) | +0.8% over block OFT |
| LLaMA-7B → Summarization BLEU | **35.6** (+3 vs LoRA)      | +1 point over block OFT |
| Stable Diffusion → Refine FID   | **12.3** (-0.7 vs LoRA…)   | +0.5 lower than block OFT |

These numbers show that **“sparse but dense” matrices actually boost generalization**, probably because they bring an inductive bias akin to classic transforms (Fourier, Hadamard).

---

## 5. Why Does Butterfly Beat Block‑Diagonal?

*Structural Expressiveness*:  
Block‑diagonal matrices can only mix neurons within fixed groups; butterfly matrices allow cross‑group mixing across stages without exploding parameters.

*Implicit Inductive Bias*:  
Butterflies capture multi‑scale interactions similar to wavelets or Fourier bases—an inductive bias known to improve learning stability and generalization in large models.

*Training Stability*:  
Because BOFT respects orthogonality at each factor, it preserves singular values of the original weight matrix—a property linked to better conditioning and less gradient explosion.

---

## 6. Practical Takeaways for Researchers

1. **Choose BOFT when you need dense fine–tuning but limited budget**:  
   Even on GPUs with few GBs of memory per rank, BOFT lets you tune large transformers without loading many additional tensors into GPU RAM.

2. **Implement via existing frameworks quickly**:  
   Since butterfly factors are just sequences of small rotations and permutations, you can code them with `torch.nn.Parameter` blocks plus `torch.einsum`.

3. **Combine with other PEFT tricks**:  
   Multiplicative dropout on selected butterfly components can reduce overfitting further; zero init remains safe because identity is still an isotropic start point.

4. **Measure spectral norms after training**:  
   Verify that the maximal singular value stayed close to pre-trained values—a telltale sign BOFT retained geometry.

---

## 7. Open Questions & Future Directions

- *Runtime overhead*: The multiple small multiplications add kernel launches; future work could fuse them or drop unnecessary stages.
- *Optimal topology*: While butterflies work well, other graph topologies from networking literature might further reduce parameter counts.
- *Expressiveness bounds*: A formal theory quantifying how many butterfly layers are needed to approximate any orthogonal matrix could guide hyperparameter choices.

---

### Bottom Line
BOFT demonstrates that we can keep what makes a foundation model powerful—its geometry—and adapt it efficiently by learning just a handful of structured transformations instead of millions of arbitrary weights. By treating an orthogonal matrix as an information transmission problem and leveraging well‐studied butterfly structures from signal processing and networking, we trade space for computation without sacrificing accuracy—and sometimes even improving it!

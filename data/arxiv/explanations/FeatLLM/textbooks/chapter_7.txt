\title{A Textbook about the Paper: FeatLLM}

Chapter 7: Estimating Class Likelihood with Simple, Constrained Models

# Feature vector per class: z_k ∈ {0,1}^R from R rules
The starting point for downstream modeling in the FeatLLM framework is a set of rule-derived binary features. For each class index $k$ (there are $c$ classes), the LLM generates $R$ rules intended to be indicative of membership in class $k$. Applying these $R$ rules to a sample $\mathbf{x}^i$ produces a binary vector
\[
\mathbf{z}_k^i \in \{0,1\}^R,
\]
where the $r$-th component $\mathbf{z}_{k,r}^i=1$ if and only if sample $\mathbf{x}^i$ satisfies rule $r$ for class $k$, and $\mathbf{z}_{k,r}^i=0$ otherwise.

This representation converts natural-language criteria into a structured, numerical form that is immediately usable by standard supervised models. Working with binary rule indicators has several pragmatic advantages emphasized in the paper: the features are interpretable (each dimension corresponds to a human-readable rule), low-dimensional when $R$ is controlled, and naturally sparse (many samples will only trigger a small subset of rules). The downstream model therefore does not need to rediscover complex non-linear combinations from raw inputs; instead it only needs to learn how much weight to assign to each rule as evidence for each class.

# Linear model without bias; weight vector w_k and positivity projection
FeatLLM uses a very simple per-class linear scoring function to convert rule indicators into class logits. For class $k$ we introduce a trainable real-valued weight vector
\[
\mathbf{w}_k \in \mathbb{R}^R,
\]
and compute the raw score (logit) for sample $\mathbf{x}^i$ as the dot product between a non-negative projection of the weights and the binary rule vector:
\[
\text{logit}_k^i \;=\; \max(\mathbf{w}_k, 0)\cdot \mathbf{z}_k^i.
\]
Here $\max(\mathbf{w}_k,0)$ is applied elementwise (equivalently a ReLU on each coordinate), so every effective weight used in the dot product is constrained to be non-negative. Importantly, no additive bias term is included in the scoring function; this is an explicit design choice in the paper: the model scores a class purely by accumulating positive evidence from satisfied rules.

Intuitively, each coordinate of $\mathbf{w}_k$ measures how strongly the corresponding rule supports class $k$. Multiplying by the binary indicator $\mathbf{z}_{k,r}^i$ makes the contribution active only when the rule holds for the sample. The absence of bias focuses the model on evidence provided by rules rather than allowing a constant offset that could dominate when few rules are active. Training optimizes $\mathbf{w}_k$ so that rules that genuinely correlate with class membership receive larger positive weights, while irrelevant or misleading rules are driven toward zero.

# Softmax over class logits; cross-entropy training objective
After computing logits for all $c$ classes, the model converts these scores into normalized class probabilities using the softmax function. For a sample $\mathbf{x}^i$ let the logit vector be
\[
\mathbf{s}^i = \big[\text{logit}_1^i,\ \text{logit}_2^i,\ \ldots,\ \text{logit}_c^i\big]^\top.
\]
The predictive probability vector is then
\[
\mathbf{p}^i = \text{Softmax}(\mathbf{s}^i),\qquad
p_k^i = \frac{\exp(\text{logit}_k^i)}{\sum_{j=1}^c \exp(\text{logit}_j^i)}.
\]

To train the weight vectors $\{\mathbf{w}_k\}_{k=1}^c$, the framework uses the standard categorical cross-entropy (negative log-likelihood) loss on the few-shot labeled examples. If we denote the one-hot encoded true label for sample $\mathbf{x}^i$ by $\mathbf{y}^i$, the per-sample loss is
\[
\mathcal{L}(\mathbf{w};\mathbf{x}^i,\mathbf{y}^i) \;=\; -\sum_{k=1}^c y_k^i \log p_k^i.
\]
The complete training objective sums (or averages) this loss over the available training samples. Optimization of this objective adjusts the weights so that classes receive higher scores when their associated rules are satisfied for positive examples, and lower relative scores otherwise.

# Why non-negativity: ensuring rules don’t decrease class likelihoods
A central constraint in FeatLLM is that effective weights are non-negative: only positive contributions from satisfied rules are allowed. The paper motivates this choice by the semantics of the rule features. Each rule is generated as evidence for a given class by the LLM; conceptually a rule says, “if this condition holds, this raises the chance of class $k$.” Enforcing non-negativity aligns the numeric model with that intended interpretation: satisfying a rule can only increase (or leave unchanged) the class score.

There are several practical consequences of this constraint. First, interpretability improves: a large positive weight clearly indicates a strong rule; a near-zero weight indicates an unhelpful or spurious rule. Second, it reduces the risk that a rule that was intended as supportive becomes, through training noise in few-shot settings, a negative signal that reduces the score for its class. Third, in the low-shot regime the non-negativity acts as a simple inductive bias that prevents overreacting to noisy correlations—rules either contribute evidence or are effectively ignored (weight near zero). The paper demonstrates that after tuning, many rules that are not useful end up with small weights, and a simple threshold (the paper uses 0.1 in its analysis) can be used to identify and filter out uninformative rules.

From an optimization perspective, the elementwise $\max(\mathbf{w}_k,0)$ is differentiable almost everywhere (it is the ReLU operation). Gradients flow only through coordinates where $\mathbf{w}_{k,r}>0$, encouraging reinforcement of genuinely useful rules while allowing others to remain or move toward zero. This is a computationally simple way to impose a non-negativity constraint without requiring constrained optimization machinery.

# Training protocol: Adam optimizer, learning rate 0.01, 200 epochs, k-fold cross-validation for early stopping
The paper describes a straightforward and reproducible training protocol for fitting the weights. Optimization is performed with the Adam optimizer using a learning rate of $0.01$. Training runs for a fixed maximum of $200$ epochs. Because the work focuses on few-shot regimes where overfitting is a real concern, the authors use $k$-fold cross-validation to select the optimal number of epochs: that is, they perform $k$-fold CV and choose the epoch that yields the best validation performance (this serves the role of early stopping).

This protocol balances two competing needs. On one hand, a small model (linear weights over binary features) and a moderate number of epochs allow the optimization to reliably discriminate useful from useless rules even with few examples. On the other hand, cross-validation-based epoch selection guards against overfitting by stopping training once validation performance peaks. The authors report that the benefit of tuning these weights increases with the number of shots: when more labeled examples are available, the model can estimate rule importance more accurately, and tuning yields larger gains (an observation borne out in their ablations). In practice the training load is light: the model has only $c\times R$ real-valued parameters, and the paper notes that the overall computational cost at inference remains low because the final predictor uses only the learned linear weights over pre-computed binary rule features.

Putting it together
The entire downstream pipeline is therefore simple and transparent. For each class $k$, the LLM-produced rules are turned into $R$ binary features per sample, producing $\{\mathbf{z}_k^i\}$. A constrained linear scoring function with non-negative effective weights maps these features to class logits via
\[
\text{logit}_k^i = \max(\mathbf{w}_k,0)\cdot \mathbf{z}_k^i,
\]
the logits are normalized with a softmax to produce probabilities $\mathbf{p}^i$, and the weights are fitted by minimizing cross-entropy using Adam (learning rate $0.01$) for up to $200$ epochs with $k$-fold cross-validation to select the stopping epoch. The constrained linear form, together with the interpretability of binary rule features and the simple optimization, provides an effective, low-cost way to convert LLM-created rules into accurate class likelihood estimates in few-shot tabular learning tasks.

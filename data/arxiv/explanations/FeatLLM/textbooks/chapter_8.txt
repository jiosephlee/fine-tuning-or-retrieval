\title{A Textbook about the Paper: FeatLLM}

Chapter 8: Ensembling and Bagging for Robustness and Prompt Scalability

# Multiple trials (ensembles): averaging class probabilities over T rule sets
FeatLLM builds robustness by repeating the entire rule-extraction and downstream-weight-training process multiple times, producing a collection of independently generated rule-sets and associated trained weights. Each trial t yields a set of rules that are parsed into binary features and a trained weight vector (or vectors) \(\mathbf{w}[t]\) used for converting those features into class scores. For a single trial, the pipeline converts a sample \(\mathbf{x}^i\) into class probabilities \(\mathbf{p}^i(\mathbf{w}[t])\) using the linear-logit formulation (reproducing Eq. 2 from the paper):

\[
\text{logit}^{i}_{k}(t) \;=\; \max(\mathbf{w}_k[t], 0) \cdot \mathbf{z}^i_k, \qquad
\mathbf{p}^i(\mathbf{w}[t]) \;=\; \text{Softmax}\!\big([\text{logit}^{i}_{1}(t),\dots,\text{logit}^{i}_{c}(t)]\big),
\]

where \(\mathbf{z}^i_k\in\{0,1\}^R\) is the binary vector of rule satisfactions for class \(k\). The ensemble aggregates the per-trial probabilities by averaging across the \(T\) trials:

\[
\mathbf{p}^i_{\text{ensemble}} \;=\; \frac{1}{T}\sum_{t=1}^{T} \mathbf{p}^i(\mathbf{w}[t]).
\]

Averaging probabilities (rather than, say, averaging logits) produces a calibrated mixture of the trial outputs and is straightforward to implement. The ensemble reduces sensitivity to mistakes made in any single trial: if one trial produces a poor rule-set or misweights some features, other trials can compensate. In practice, FeatLLM used \(T=20\) ensembles, a value that empirically balances improved accuracy and computation (see the Trade-offs section).

# Injecting diversity: higher temperature and randomizing demonstration order
An ensemble is effective only if its members are sufficiently diverse. FeatLLM intentionally injects stochasticity into each rule-generation call to the LLM so that different trials explore different plausible rule-sets. Two concrete mechanisms are used.

First, the LLM sampling temperature is increased for rule generation. A higher temperature produces more varied outputs from the LLM’s conditional distribution; in FeatLLM this yields a broader variety of candidate rules across trials. The paper describes using a “sufficiently high temperature” for this purpose (the default implementation reported a temperature of 0.5 for general runs but increases are used to promote diversity during ensemble trials). This randomness converts one deterministic LLM response into a family of possible interpretations of the few-shot demonstrations and feature descriptions.

Second, the order of the few-shot demonstrations included in the prompt is randomized between trials. LLMs are known to be sensitive to demonstration order, so shuffling the examples produces different in-context reasoning trajectories and thus different extracted rules. By permuting demonstration order across trials, FeatLLM leverages this sensitivity to create variety in the candidate rule-sets without changing the underlying data.

Combined, temperature and demonstration-order randomization yield an ensemble whose members are not redundant but instead explore complementary hypotheses about which feature conditions are relevant.

# Instance and feature bagging to reduce prompt size and encourage complementary rules
When tabular datasets have many features or a large number of few-shot examples, prompts can exceed practical length limits or degrade LLM performance. FeatLLM applies bagging (feature bagging and instance bagging) inside the ensemble to address prompt-size constraints and to generate complementary rule-sets across trials.

Feature bagging means that for each trial the prompt includes only a random subset of the original feature set. This reduces the number of feature descriptions and serialized values that must be placed into the prompt, keeping the text length manageable when a dataset has dozens or hundreds of attributes (the paper highlights datasets such as Communities and Myocardial with over 100 attributes). Because different trials sample different subsets of features, the ensemble collectively covers a wider portion of the original feature space than any single trial, and each trial focuses the LLM’s attention on a smaller, more tractable view of the data. As a result, the rules produced across trials tend to be complementary: trial A may discover rules involving features 1–20, while trial B discovers rules involving features 21–40, and their combination yields a richer feature representation without any single prompt becoming too long.

Instance bagging (sampling a subset of few-shot demonstrations) likewise reduces the number of exemplars serialized into the prompt. It also encourages the LLM to produce different rules because the specific examples presented influence the in-context reasoning path. In short, bagging trades off breadth in a single trial for breadth across trials; prompt length is controlled per trial, while the ensemble restores coverage and flexibility.

Practically, these two forms of bagging are controlled by the practitioner: the number of features and number of demonstration instances included per trial can be tuned so that each prompt fits within the LLM’s context window while preserving enough information for meaningful rule induction.

# Self-consistency rationale: frequently rediscovered rules are more reliable
FeatLLM’s ensemble strategy connects to the notion of self-consistency in LLM reasoning. If multiple independent LLM calls—each with different sampling noise, demo order, or subset of features—recover the same or similar rule, that rule is more likely to capture a genuine relationship between the inputs and the labels, rather than being a chance idiosyncrasy of one prompt. The paper explicitly invokes this intuition, referencing self-consistency: rules that are rediscovered across trials are treated as more trustworthy.

This rationale has two operational consequences. First, because many trials are run, the common rules naturally receive higher effective weight in the ensemble output: they will contribute to the binary features in many trials, and their influence is reflected in the averaged probability \(\mathbf{p}^i_{\text{ensemble}}\). Second, the downstream linear tuning step per trial assigns non-negative weights to features; rules that are consistently predictive across trials will repeatedly obtain larger learned weights, further elevating their impact in the aggregate prediction. Together, rediscovery frequency and per-trial tuning implement a form of consensus filtering: frequent, predictive rules survive and drive predictions, while rare or unhelpful rules have limited effect.

# Trade-offs: ensemble size vs performance gains; diminishing returns around ~20 ensembles
While ensembling improves robustness, it also increases computational and monetary costs because rule extraction requires LLM API calls. There is a clear trade-off between ensemble size \(T\) and incremental performance gains. Empirically, the paper reports that increasing \(T\) yields steadily better performance up to a point, but improvements begin to plateau; around \(T\approx 20\) the gains converge in the datasets and few-shot settings studied.

This diminishing-return behavior is typical of ensembles: early additions of trials add substantially different hypotheses and reduce variance, but once many diverse rule-sets are present, additional trials tend to be correlated with existing ones and thus contribute little marginal improvement. Practically, this means a practitioner should choose \(T\) to balance desired accuracy and available budget. The paper’s implementation used \(T=20\) as a sensible default because it provides most of the ensemble’s benefit without excessive API usage.

A related trade-off exists in the granularity of bagging: sampling fewer features per trial reduces prompt length and per-call cost, but if the per-trial sample is too small, each LLM call may produce rule-sets that are too weak. The ensemble can compensate for some of this weakness, but only up to a point. Similarly, an excessively high temperature increases diversity but also increases the chance of producing nonsensical or irrelevant rules, which the ensemble will have to dilute. The downstream per-trial tuning (learning non-negative weights) and averaging across trials mitigate these risks, but judicious hyper-parameter choices (number of rules per class, number of ensembles \(T\), bagging fractions, temperature) remain important.

Finally, it is worth noting the practical efficiency trade: although ensembling multiplies the number of LLM queries during feature discovery, FeatLLM’s inference cost is low because predictions on new samples use only the learned rule-based binary features and the trained linear weights—no per-sample LLM calls are required. Thus the ensemble cost is a one-time training expense (which the paper found to be comparable to other LLM-based methods and modest in absolute API calls), while inference remains fast and feasible for production deployment.

Conclusion
The combination of ensemble averaging, stochasticity via temperature and demo-order shuffling, and instance/feature bagging gives FeatLLM two key practical advantages. First, it creates robust, diverse rule-sets that reduce sensitivity to spurious single-trial errors and low-shot noise. Second, bagging keeps individual prompts compact so the approach scales to wide tables and long feature descriptions. The self-consistency effect—where frequently rediscovered rules dominate the ensemble—provides an intuitive reliability signal, and empirical tuning shows strong performance gains that level off around twenty ensembles, suggesting a pragmatic operating point for many applications.

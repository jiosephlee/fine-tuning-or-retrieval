Chapter 2: Large Language Models (LLMs) as General‑Purpose Reasoners  

# Transformer foundations and scaling laws  

The modern Large Language Model (LLM) is built upon the transformer architecture introduced by Vaswani et al.~\cite{vaswani2017attention}. At its core lies the self‑attention mechanism, which lets each token in a sequence attend to every other token by computing similarity scores between learned query ($\mathbf{Q}$), key ($\mathbf{K}$), and value ($\mathbf{V}$) vectors. Concretely, given an input sequence represented as a matrix $\mathbf{X}\in\mathbb{R}^{L\times d_{\text{model}}}$ of length $L$, the attention operation produces  

\[
\text{Attention}(\mathbf{X})=\operatorname{softmax}\!\Big(\frac{\mathbf{Q}\mathbf{K}^{\!\top}}{\sqrt{d_k}}\Big)\mathbf{V},
\]  

where $d_k$ denotes the dimensionality of each query/key vector. This operation captures pairwise interactions without any recurrent recurrence, allowing parallel computation across all positions—a decisive factor for training on billions of tokens efficiently.  

The transformer stacks many identical layers, each comprising a multi‑head attention block followed by a position‑wise feed‑forward network with residual connections and layer normalization. By increasing three primary axes—depth (number of layers), width (hidden dimension $d_{\text{model}}$), and data (total number of tokens $D$ seen during pre‑training)—researchers have observed regular patterns known as scaling laws~\cite{kaplan2020scaling}. Empirically, model loss $L$ follows a power‑law decay  

\[
L(N,D)\approx A\,N^{-\alpha}+B\,D^{-\beta},
\]  

with $N$ denoting total parameters, $A,B$ constants, and $\alpha,\beta>0$. As $N$ and $D$ grow together while maintaining a roughly constant ratio $D/N$, performance improves predictably across diverse natural language tasks.\footnote{Scaling behaviour was documented across models ranging from hundreds of millions to hundreds of billions of parameters, supporting the emergence of capabilities such as mathematical reasoning or code synthesis when crossing certain thresholds~\cite{brown2020language}.}  

Because transformers scale gracefully both in compute efficiency (thanks to self‑attention’s parallelism) and in performance (thanks to smooth scaling curves), they become natural candidates for building general‐purpose reasoners capable of handling varied input modalities—including the structured rows typical of tabular data.\footnote{The \textsf{FeatLLM} study leverages GPT‑3.5 turbo—a transformer‑based LLM—demonstrating that even without task‑specific fine‑tuning, large scale enables extraction of high‐quality decision rules from few examples.}

# Pre‑training objectives (next token prediction) and knowledge acquisition  

The predominant pre‑training objective for contemporary LLMs is autoregressive next token prediction~\cite{radford2019language}. Given a tokenized context $\mathbf{x}_{1:t}=(x_1,\dots,x_t)$, the model is trained to maximize  

\[
\log p(x_{t+1}\mid \mathbf{x}_{1:t}) .
\]  

Summed over all positions in massive corpora comprising trillions of words, this maximum likelihood objective forces the network to internalize statistical regularities about syntax, semantics, world facts, and even procedural knowledge present in natural language.\footnote{Alternative objectives such as masked language modeling exist but are less common for pure generative models employed via APIs.}  

During optimization, gradients flow through all layers; thus parameters gradually encode embeddings for lexical items, relational patterns among entities (“older individuals have higher disease risk”), temporal sequences (“if temperature rises then ice melts”), and logical constructs (“if A and B then C”). When later prompted with a novel query—e.g., “What conditions indicate chronic heart failure?”—the model retrieves relevant internal patterns without having seen that exact formulation during training.\footnote{In \textsf{FeatLLM}, this latent world knowledge enables the LLM to generate medically plausible rules such as “age > 65 AND blood pressure > 140”. }  

Because next token prediction does not require explicit annotation beyond raw text, pre‑training can ingest virtually any textual resource—news articles, scientific papers, code repositories—amassing an encyclopedic repository of facts that downstream users can harness via prompts.\footnote{The authors highlight that this “rich prior knowledge” substitutes expert domain knowledge when engineering features for tabular tasks such as disease prediction or credit risk assessment.}

# In‑context learning vs fine‑tuning vs parameter‑efficient tuning  

Three distinct paradigms govern how an LLM adapts from its broad pre‑trained state to a specific downstream problem:

**In‑context learning** treats the model as a frozen function $f_{\theta}(\cdot)$ whose behavior can be steered solely by appending exemplars directly into its input prompt. Concretely one supplies a short textual description of the task followed by several “demonstrations” formatted as $\langle \texttt{x},\texttt{y}\rangle$ pairs:

```
Feature1 is 25 . Feature2 is 0 . Answer: 1
Feature1 is 42 . Feature2 is 1 . Answer: 0
...
```

When presented with new inputs sharing the same format, the model extrapolates from those demonstrations without any weight updates~\cite{kumar2022meta}. The advantage lies in zero training time—only prompt construction—and flexibility across tasks~\cite{brown2020language}. The drawback is computational cost at inference time: every new sample must be passed through the expensive LLM API again (as illustrated by existing approaches such as TabLLM or TABLET). Moreover, prompt length limits constrain how many examples can be shown simultaneously.\footnote{\textsf{FeatLLM} mitigates this per-sample cost by using in‐context learning only once—to extract rule‐based features—after which predictions rely on a lightweight linear model.}

**Fine‑tuning** modifies all parameters $\theta$ via gradient descent on task–specific labeled data $\mathcal{D}_{\text{train}}$. The loss typically mirrors pre‐training’s cross–entropy over target labels:

\[
\mathcal{L}_{\text{FT}} = - \sum_{(x,y)\in \mathcal{D}_{\text{train}}} \log p_{\theta}(y|x).
\]

Fine‐tuning yields strong performance when sufficient labeled data exist but incurs considerable compute overhead and requires access to model weights—a restriction when using closed‐source APIs.\footnote{TabLLM follows this route with IA3 adapters trained on few shots; however it still demands multiple forward passes per sample during inference because predictions occur directly inside the adapted LLM.}

**Parameter‑efficient tuning** occupies an intermediate niche by updating only a small set of auxiliary parameters while keeping $\theta$ frozen~\cite{hu2021lora}. Techniques like LoRA insert low-rank matrices $\Delta \mathbf W = \mathbf A \mathbf B^{\!\top}$ into existing linear transformations so that optimization focuses on $\mathbf A$, $\mathbf B$ alone (\#parameters order $(r d)$ where $r\ll d$). IA3 rescales hidden activations instead of adding new weights~\cite{liu2022few}. Because only tens of thousands rather than billions of values change, training becomes feasible even on modest hardware while retaining much of fine-tuning’s adaptability.\footnote{\textsf{FeatLLM} deliberately refrains from any weight updating beyond fitting a tiny linear classifier over binary rule features; this keeps its resource requirements comparable to conventional machine learning baselines despite using a massive LLM solely during feature construction.}

Collectively these paradigms let practitioners trade off between computational budget, latency constraints, and data availability—a critical consideration when tackling low‐shot tabular problems where annotated rows are scarce but inference speed matters.

# Chain‑of‑thought prompting and reasoning capabilities  

Chain‑of‑thought (CoT) prompting asks an LLM not merely “what answer?” but “how would you reason step by step?” By prefixing prompts with phrases such as “Let’s think step by step,” one induces internal symbolic manipulation before arriving at a final token~\cite{wei2022chain}. Empirically CoT improves success rates on arithmetic puzzles, logical deductions, and multi‐hop question answering—in effect coaxing latent reasoning pathways out of what would otherwise be a pure pattern matcher.\footnote{In \textsf{FeatLLM}, CoT ideas inspire their two–step reasoning instruction: first infer causal tendencies between features and label purely from prior knowledge (step 1), then combine those tendencies with concrete few-shot examples to enumerate deterministic rules (step 2). This structured approach reduces spurious correlation formation and leads to concise logical predicates rather than opaque neural embeddings.}

CoT also interacts synergistically with rule generation because logical expressions (“age > 60 AND cholesterol > 200”) map naturally onto binary predicates used downstream. When combined with well–crafted response formats—e.g., “Rule 1: if … then class A”—the resulting output can be parsed automatically into executable code or conditional statements.\footnote{
The authors note that even though natural language may contain variations (“greater than” vs “>”), feeding those textual rules back into an LLM itself yields robust Python snippets that concretize them into Boolean features.
}  

Thus chain–of–thought prompting serves two purposes in tabular contexts:
1. It directs attention toward high–level causal concepts encoded during pretraining.
2. It produces human–readable specifications that facilitate downstream interpretable models—a property essential for domains such as healthcare where auditability matters.


# APIs vs open‑source checkpoints: practical implications  

A practitioner’s choice between black‐box API access (e.g., OpenAI’s `gpt-3.5-turbo`) versus downloading an open‐source checkpoint hinges on several factors:

* **Latency & cost** – API calls incur per-token charges and network latency proportional to prompt length; repeated calls per sample become prohibitive at scale. Open-source checkpoints run locally on GPUs offering batch processing with negligible per‐token fees once hardware exists.\footnote{
In \textsf{FeatLLM}, only thirty API queries suffice regardless of dataset size because rule extraction happens once per bagging trial; afterward inference costs drop dramatically compared to methods that query per test example.
}
* **Customization** – Open checkpoints permit fine‐tuning or insertion of adapters directly on weights—a necessity when one wishes to specialize an LLM for domain vocabularies or rare modalities absent from generic APIs.\footnote{
TabLLM employs IA3 tuning on T0 encoder models precisely because it has direct access; however GPT-3\.5 cannot be tuned through its API facade.
}
* **Regulatory & privacy constraints** – Certain industries disallow sending proprietary data outside organizational firewalls; local checkpoints guarantee data never leaves premises.\footnote{
FeatLLM mitigates exposure risk also because after extracting rules it never streams raw patient rows back through any external service.
}
* **Prompt length limits** – Public APIs impose hard caps on tokens per request (~4–8 k tokens depending on version). When tables contain hundreds of columns—as many benchmark datasets do—serialization may exceed this budget causing inference failure or degraded performance.\footnote{
To cope with long feature sets FeatLLM adopts feature bagging: each trial samples only a subset of columns before constructing prompts, thereby respecting token limits while still pooling diverse rules across ensembles.
}
* **Model versioning & reproducibility** – Open releases provide explicit version identifiers enabling exact reproducibility across labs; APIs often abstract away model updates behind opaque “engine” names which may shift underlying weights without notice.


Consequently many real-world deployments start with API access because it removes barrier-to-entry hardware costs while still unlocking powerful latent knowledge via prompts. When demand grows—for instance needing batch throughput or stricter privacy—the community typically transitions toward self-hosted models derived from open releases such as Meta’s LLaMA or HuggingFace’s BLOOM family.\footnote{
The FeatLLM methodology remains agnostic: any sufficiently capable generative transformer could replace GPT-3\.5 provided it supports programmatic invocation at moderate temperature settings for diverse rule generation.}

---

In summary, modern Large Language Models rest upon scalable transformer foundations whose self-attention architecture admits smooth performance gains when enlarged—a phenomenon captured quantitatively by empirical scaling laws. Through next-token prediction over vast corpora they amass encyclopedic factual knowledge which can be summoned via carefully designed prompts leveraging chain-of-thought reasoning. Depending on resource constraints one may employ pure in-context learning (prompt-only), full fine-tuning (weight update), or lightweight adapter techniques—all representing trade-offs between computational expense and adaptation fidelity. Finally, whether accessed through commercial APIs or locally hosted checkpoints determines practical considerations such as latency budgets, privacy compliance, and prompt length limitations—all pivotal when applying LLMs as general-purpose reasoners for challenging low-shot tabular tasks like those tackled by \textsf{FeatLLM}.

# sLSTM Explained: Scalar Memory Meets Smart Mixing for Better State Tracking  

*Subtitle*: A layperson’s guide to the new sLSTM variant – how a single‑value cell, a clever normalizer, and “memory mixing” across heads let recurrent models solve tasks that vanilla Transformers struggle with.

---

## 1. Why revisit LSTMs at all?

When the Transformer arrived in 2017 it seemed to have put the classic Long Short‑Term Memory (LSTM) network on the sidelines. Transformers scale nicely thanks to parallelizable self‑attention, while the original LSTM suffers from three well‑known drawbacks:

1. **No way to revise old storage decisions** – once a value is written into the cell it is hard to “undo” later.
2. **Limited storage capacity** – each cell holds only a scalar (or a few scalars), which makes remembering rare events difficult.
3. **Sequential bottleneck** – hidden‑to‑hidden connections force step‑by‑step processing.

The *Extended* family introduced in the xLSTM paper tackles these issues head‑on. The first member of this family is **sLSTM** (scalar LSTM). It keeps the simple scalar memory of the original LSTM but adds two crucial twists: **exponential gating** and **smart memory mixing** backed by a **normalizer** that tracks gate strength. Let’s unpack what each piece does and why it matters.

---

## 2. A quick refresher: the classic LSTM cell

At time step \(t\) a textbook LSTM updates three quantities:

\[
\begin{aligned}
c_t &= f_t \, c_{t-1} + i_t \, z_t &&\text{(cell state)}\\
h_t &= o_t \,\psi(c_t) &&\text{(hidden output)}\\
z_t &= \varphi(\tilde z_t) &&\text{(cell input)}
\end{aligned}
\]

* \(i_t\), \(f_t\), \(o_t\) are **input**, **forget**, and **output** gates (sigmoids).  
* \(c_{t-1}\) is the *constant error carousel*: an additive term that lets gradients flow unchanged over long horizons.  
* \(\psi\) squashes the raw cell value (usually \(\tanh\)) so it stays bounded.

Even with this clever design, once \(i_t\) writes something into \(c_t\), its influence can only decay through \(f_t\); there’s no mechanism for an *exponential* “rewriting” that can quickly boost or erase past content when needed.

---

## 3. Exponential gating: letting the model rewrite its past

sLSTM replaces the sigmoid activation on **input** (and optionally on **forget**) gates with an exponential function:

\[
i_t = \exp(\tilde i_t), \qquad 
f_t = \sigma(\tilde f_t)\ \text{or}\ \exp(\tilde f_t).
\]

Why exponentials? Because they grow (or shrink) much faster than sigmoids, giving the model two new abilities:

* **Rapid revision** – If a later token suggests that what was stored earlier was wrong, an exponentially larger \(i_t\) can overwrite it in one step instead of waiting for many small updates.
* **Dynamic range** – The gate can amplify contributions far beyond the unit interval \([0,1]\). This is essential when we want to *re‑weight* old information relative to new evidence.

Of course exponentials can explode numerically, so the authors introduce a stabilizer state \(m_t\) (borrowed from Milakov & Finkelstein’s work) that rescales both gates without altering gradients:

\[
\begin{aligned}
m_t &= \max\bigl(\log f_t + m_{t-1},\, \log i_t\bigr),\\
i'_t &= \exp(\log i_t - m_t),\\
f'_t &= \exp(\log f_t + m_{t-1} - m_t).
\end{aligned}
\]

Using \(i'_t\) and \(f'_t\) in place of \(i_t,f_t\) leaves everything else unchanged while keeping numbers well‑behaved.

---

## 4. The normalizer: remembering how strong your gates have been

When we start using exponentials, raw values in the cell can drift far from any sensible scale—imagine dividing by something massive or tiny later on! To keep hidden outputs comparable across time steps, sLSTM introduces a *normalizer state* \(n_t\):

\[
n_t = f_t\, n_{t-1} + i_t.
\]

Intuitively, \(n_t\) accumulates the same gate strengths that contributed to the cell itself:

* The term \(f_t n_{t-1}\) carries forward past gate magnitudes that survived forgetting.
* The term \(i_t\) adds today’s contribution weight.

The hidden output now uses *normalized* memory:

\[
h_t = o_t\, \tilde h _t,\qquad 
\tilde h _t = \frac{c_t}{n_t}.
\]

Dividing by \(n_t\) makes sure that if both numerator and denominator grew because gates were large, their ratio stays stable—much like normalizing a moving average by its total weight.

---

## 5. Memory mixing across multiple heads

A single scalar per cell is fine for many tasks but insufficient for patterns that need *state tracking*. The classic solution in modern RNNs is simply to stack many scalar cells into a vector \(\mathbf c _t \in \mathbb R^d\). sLSTM goes further by allowing *memory mixing* inside each “head”.

### What does “mixing” mean?

Recall that in vanilla LSTMs each scalar cell updates independently:
\(c^{(k)}_t = f^{(k)}_t c^{(k)}_{t-1}+ i^{(k)}_t z^{(k)}_t.\)

In sLSTM we introduce recurrent weight matrices — e.g., \(\mathbf R_{\!z}, \mathbf R_{\!i}, \mathbf R_{\!f}, \mathbf R_{\!o}\)—that connect hidden states from one time step back into **all** cells within *the same head*. Concretely,

```
z   = φ( w_z^T xₜ + R_z h_{t-1} + b_z )
i   = exp( w_i^T xₜ + R_i h_{t-1} + b_i )
f   = σ( w_f^T xₜ + R_f h_{t-1} + b_f )
o   = σ( w_o^T xₜ + R_o h_{t-1} + b_o )
```

Because every gate now receives information from *all* hidden units of its head, each scalar memory can influence—and be influenced by—its siblings at every step. This “mixing” gives rise to **state tracking**, where a pattern spanning many steps can be encoded jointly across cells rather than being forced into one isolated scalar line.

### Heads vs Cells

* **Heads** are independent groups of cells; there is no mixing across different heads (the matrices are block‑diagonal).  
* Inside each head we may have dozens or hundreds of scalar cells whose dynamics are intertwined through those recurrent matrices.

This architecture mirrors multi‑head attention in Transformers—multiple parallel pathways—but retains a strictly recurrent connection inside each head, which is crucial for tasks where order matters deeply (e.g., parity checking).

---

## 6. A concrete case: parity checking and why Transformers stumble

The **parity task** asks a model to output (`0`/`1`) whether an input sequence contains an odd number of `1`s so far. Solving it requires preserving a binary counter modulo 2 throughout arbitrarily long inputs—exactly what “state tracking” is built for.

In the paper’s synthetic experiments (see Fig 2 in Section 4 – “Synthetic Tasks”), sLSTM variants achieved near‑perfect accuracy on parity while vanilla Transformers and many State Space Models plateaued around random chance (~0.5). The reason is simple:

| Model | Has hidden‑to‑hidden recurrent connections? | Can revise stored info? | Result on parity |
|-------|--------------------------------------------|------------------------|------------------|
| Transformer | No (self‑attention only at current step) | No | Fails |
| SSM (e.g., Mamba) | Linear dynamics only | Limited | Fails |
| vanilla LSTM | Yes (scalar mixing limited) | Yes (sigmoid gates) | Partial |
| **sLSTM** | Yes + exponential gates + normalizer | Yes (fast rewrite) | ✔️ Near perfect |

Because sLSTM mixes scalars inside each head and uses exponential gates, it can toggle its internal parity bit cleanly after every `1`, while never being overwhelmed by older contributions thanks to the normalizer division.

## 7. Putting it together – why sLSTM matters for large language models

The authors embed sLSTM blocks inside *xLSTM residual architectures*. A high‑level view:

1. Input → linear projection → *(optional up‑projection)* → **sLSTM block** → *(down‑projection)* → residual add → layer norm.
2. Stack many such blocks → autoregressive language model.

Key takeaways:

* **Linear time & constant memory w.r.t sequence length** – unlike Transformer's quadratic attention cost.
* **Better handling of rare tokens & long dependencies** – thanks to richer recurrence.
* **Scales well when combined with matrix–memory mLSTMs**, forming hybrid xLSTMs that achieve competitive perplexities at billions of parameters (see Table 1 & Fig 5).

In practice you’ll often see an xLSTM combo like `[7 mLSTM : 1 sLSTM]` blocks; even one sLSTM block injects the crucial state‐tracking ability into an otherwise parallelizable pipeline.

---

## 8. Pros & cons at a glance

### Advantages
- **Exponential gating** enables rapid overwriting—critical for tasks where early decisions may need correction later.
- **Normalizer** keeps hidden activations stable despite unbounded gate values.
- **Memory mixing within heads** gives deterministic state tracking power absent in pure attention models.
- Linear computational cost per token; constant GPU memory independent of context length—friendly for edge devices or very long prompts.

### Limitations
- Mixing introduces *sequential dependencies*, making full parallelization impossible for pure sLSTM blocks (though custom CUDA kernels keep slowdown under ~2× compared to fully parallel mLSTMs).
- Exponential gates require careful initialization of forget biases; otherwise training may diverge early.
- Benchmarks show minor overhead compared with FlashAttention or optimized SSM kernels—future engineering can close this gap.

---

## 9. Bottom line

The sLSTM variant shows that you don’t need massive vector memories to get smarter recurrence—you just need smarter *gate dynamics* and a bit of structured mixing. By pairing a single scalar per cell with an exponential gate scheme and a simple normalizer, sLSTM regains the ability to *revise* old memories fast enough for complex pattern tracking such as parity checks—something vanilla Transformers simply cannot do due to their lack of hidden‐to‐hidden connections.

When incorporated inside larger xLSTM stacks, this humble scalar upgrade becomes part of a language model that rivals Transformers on perplexity while keeping linear runtime and constant memory footprint—a compelling direction for anyone looking beyond self‑attention toward scalable recurrent architectures.

# Reviving LSTMs with Exponential Gating: How a Simple Change Fixes Forgetting  

## The forgetting problem in classic LSTMs  

Long Short‑Term Memory networks (LSTMs) have been the workhorse of sequence modeling for decades. Their core idea—an additive **cell state** update  

\[
c_t \;=\; f_t\,c_{t-1} \;+\; i_t\,z_t,
\qquad  
h_t \;=\; o_t\,\psi(c_t)
\]  

relies on three **sigmoid gates** \(i_t\) (input), \(f_t\) (forget) and \(o_t\) (output). Because the sigmoid maps any real number into the interval \((0,1)\), each gate can only *attenuate* information: an input gate of \(0.9\) writes slightly less than a full “ink stroke”, while a forget gate of \(0.2\) erases only a fifth of what is already there.  

This boundedness is normally a virtue—it protects against exploding gradients—but it also makes it hard for an LSTM to **revise** what it has stored. Imagine a sticky note you write on while reading a list of items. If you later discover a better description for an entry, you can’t simply replace the old text with more ink; you are limited to adding a faint correction that gets quickly diluted by earlier writing.  

In practice this limitation shows up in tasks such as *nearest‑neighbor search* over a sequence: while scanning a list of vectors, the network must continuously update its “best match” whenever it encounters a closer vector. Classic LSTMs tend to stick with the first high‑scoring entry because their forget gate cannot aggressively erase it once stored.\  

## From sigmoid to exponential – giving the gates more punch  

The authors of **xLSTM** observed that the bottleneck lies in the *shape* of the gate activations rather than the cell equation itself. Replacing the sigmoid with an **exponential** activation removes the upper bound:

\[
i_t \;=\;\exp(\tilde{i}_t), \qquad
f_t \;\in\;\bigl\{\sigma(\tilde{f}_t),\;\exp(\tilde{f}_t)\bigr\}.
\]

Now an input gate can produce values far larger than 1, effectively allowing the network to “write with as much ink as it wants”. Likewise, an exponential forget gate can **amplify** forgetting when needed—or be left as a sigmoid if gentle decay suffices. Crucially, the cell update formula stays identical; only the way we compute \(i_t\) and \(f_t\) changes.\  

## Normalizing away runaway values  

If we let exponentials run unchecked, both \(c_t\) and \(h_t\) would blow up quickly—training would become unstable and predictions meaningless. The xLSTM design solves this by introducing a **normalizer state** \(n_t\) that tracks how much *total* gate mass has been injected up to time \(t\):

\[
n_t \;=\; f_t\,n_{t-1} \;+\; i_t .
\]

The hidden state is then computed as a *ratio*:

\[
h_t \;=\; o_t\,\tilde{h}_t,\qquad 
\tilde{h}_t \;=\;\frac{c_t}{n_t}.
\]

Think of \(n_t\) as measuring the total amount of ink ever placed on our sticky note. Dividing by this sum automatically rescales the content so that its magnitude stays comparable across time steps—even if individual gates become huge.\  

## Stabilisation tricks – keeping floating‑point arithmetic honest  

Even with the \(c/n\) normalisation, raw exponentials can overflow before division occurs (e.g., \(\exp(1000)\) is far beyond double‑precision limits). To avoid this “ink spillage”, xLSTM introduces a **stabiliser state** \(m_t\):

\[
m_t \;=\;\max\bigl(\log(f_t)+m_{t-1},\,\log(i_t)\bigr).
\]

Using \(m_t\), we re‑scale both gates without changing their relative contribution:

\[
i'_t \;=\;\exp(\log(i_t)-m_t)
       \;=\;\exp(\tilde{i}_t-m_t),
\\[4pt]
f'_t \;=\;\exp(\log(f_t)+m_{t-1}-m_t).
\]

Because we subtract (or add) exactly the same quantity from every term that participates in the cell update, **the forward output remains identical**, and gradients are unchanged—yet all intermediate numbers stay well within representable ranges.\  

## The full sLSTM forward pass  

Putting everything together yields what the authors call **sLSTM** (scalar‑memory LSTM). Its computation at each time step looks like this:

```
c[t] = f[t] * c[t‑1] + i[t] * z[t]                # cell state
n[t] = f[t] * n[t‑1] + i[t]                     # normalizer state
h[t] = o[t] * (c[t] / n[t])                    # hidden output

z[t]   = φ( w_zᵀ x[t] + r_z h[t‑1] + b_z )      # cell input
i[t]   = exp( w_iᵀ x[t] + r_i h[t‑1] + b_i )    # input gate
f[t]   = σ/exp( w_fᵀ x[t] + r_f h[t‑1] + b_f ) # forget gate
o[t]   = σ( w_oᵀ x[t] + r_o h[t‑1] + b_o )      # output gate
```

All symbols carry their usual meaning from classic LSTMs (\(x[t]\): input vector, \(w_\*\): input weights, \(r_\*\): recurrent weights, \(b_\*\): biases). The only structural changes are:
* **Exponential activation** for \(i[t]\) and optionally \(f[t]\);
* **Normaliser** \(n[t]\);
* **Optional stabiliser** \(m[t]\) applied behind the scenes.

When multiple memory cells are stacked together—as done in modern large language models—the same pattern repeats across each cell dimension.\  

## Why exponential gating lets us rewrite memories  

Returning to our sticky‑note metaphor: with sigmoid gates we could only add light pencil marks on top of an existing entry—hardly enough to obscure something previously written clearly. Exponential gates act like a high‑lighter that can pour arbitrarily thick ink over any previous note. The normaliser then “erodes” older ink proportionally, ensuring that fresh highlights dominate without blowing up overall intensity.\  

In concrete terms, during a nearest‑neighbor scan an early high‑similarity vector produces an initial strong imprint in \(c_{t}\). When later we encounter an even more similar vector, its exponentially larger input gate (\(i_{t}\)) overwhelms—through multiplication by background forgetting—any past imprint. The division by \(n_{t}\) guarantees that this overwrite stays numerically stable.\  

Empirically, xLSTM’s exponential gating reduces mean‑squared error on the nearest‑neighbor task dramatically compared to classic LSTMs (see Figure 1 left panel in the paper). It also lifts perplexity on rare token prediction—another symptom of insufficient storage capacity—once combined with matrix memory (the **mLSTM** variant).\  

## Scaling up – xLSTM blocks and architectures  

The authors embed sLSTM (and its matrix counterpart mLSTM) inside residual blocks familiar from Transformers (“xLSTM blocks”) and stack them depth‑wise (`xLSTM[7:1]` meaning seven mLSTM blocks per eight total layers). This yields end‑to‑end architectures that retain linear time/constant memory complexity while competing with state‑of‑the‑art Transformers and State Space Models on large language modeling benchmarks.\  

Even though sLSTM’s hidden‑to‑hidden connections prevent full parallel execution across time steps—making it slower than mLSTM—the authors report an optimized CUDA kernel that runs at most twice as slow as its fully parallel counterpart. For many applications where revising memory is crucial (e.g., code execution tracing or long context reasoning), this extra cost may be worthwhile.\  

## Takeaways  

| Insight | Why it matters |
|---|---|
| **Exponential gates:** Removing the sigmoid’s upper bound gives each time step unlimited capacity to inject or erase information. | Enables “on‑the‑fly” memory rewrites that classic LSTMs cannot perform efficiently. |
| **Normalizer state `nₜ`:** Tracks cumulative gate activity and rescales hidden output (`cₜ / nₜ`). | Keeps activations bounded despite unbounded raw gates. |
| **Stabiliser `mₜ`:** Rewrites exponentials in log space before applying them back out. | Prevents overflow while preserving exact forward/backward behavior. |
| **sLSTM forward equations:** Simple extensions of standard LSTM equations—no extra parameters needed beyond existing weights plus one extra scalar per unit (`nₜ`). | Easy drop‑in replacement for existing recurrent stacks. |
| **Empirical payoff:** Lower error on tasks requiring dynamic revision (nearest neighbor), better rare token prediction when paired with matrix memory, competitive perplexities against Transformers at billions of parameters. | Shows that revisiting old ideas with modest tweaks can close the gap with newer architectures. |

In short, turning sigmoids into exponentials—and tempering them with clever normalisation – equips LSTMs with true *rewritability*. This single change unlocks capabilities previously exclusive to attention mechanisms or sophisticated state space models while preserving RNNs’ linear‐time scaling advantage.\  

If you’ve been using vanilla LSTMs and hit roadblocks where “once stored = forever stored” felt too rigid, give exponential gating a try. The code is openly available at https://github.com/NX-AI/xlstm — experiment with `sLSTM` cells inside your existing recurrent pipelines and see how much easier your models become at learning to forget—and remember—on demand.

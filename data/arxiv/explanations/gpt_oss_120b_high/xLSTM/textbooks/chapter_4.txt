Chapter 4: 4. Design Goals Behind Extended LSTMs (xLSTMs)

The classic Long Short‑Term Memory network was invented to solve the vanishing‑gradient problem by means of the **constant error carousel** and three sigmoid gates – input $i_{t}$, forget $f_{t}$ and output $o_{t}$ – as expressed in the original update
\[
c_{t}=f_{t}\,c_{t-1}+i_{t}\,z_{t},\qquad 
h_{t}=o_{t}\,\psi(c_{t}) ,
\tag{1}
\]
where $c_{t}$ is the cell state, $h_{t}$ the hidden state and $\psi$ a squashing function such as $\tanh$.
When LSTMs were first deployed this formulation already allowed gradients to flow over long horizons,
but three structural weaknesses quickly became apparent when trying to scale them toward modern large language models:
(1) **Inability to revise stored information**, leading the network to get stuck once an early decision was written into $c_{t}$;
(2) **Limited storage capacity**, because each cell carries only a scalar or, at best, a low‑dimensional vector;
(3) **Absence of parallelism**, caused by the hidden–to–hidden recurrent coupling ($h_{t-1}\!\rightarrow\!h_{t}$) that forces strict sequential evaluation.
The design goals behind Extended LSTMs (xLSTMs) are precisely aimed at eliminating these three bottlenecks while preserving the desirable gradient properties of Equation (1).  
Below we examine each desideratum systematically and show how the two complementary extensions—*exponential gating* and *novel memory structures*—realize them.



# Linear scalability vs quadratic attention trade‑off analysis

A central motivation for rethinking recurrent architectures is computational cost.
Standard Transformers compute self‑attention through pairwise interactions among all $T$ tokens,
which yields a time complexity $\mathcal{O}(T^{2})$ and a space requirement proportional
to $T^{2}$ when naïvely storing attention scores.
For short sentences this overhead is negligible,
but when language models are tasked with contexts exceeding several thousand tokens
the quadratic term dominates both training wall‑clock time and GPU memory consumption.
In contrast, an RNN‐style recurrence updates its internal representation from one step
to the next using only information available at the current time,
so every forward pass costs $\mathcal{O}(T)$ operations,
and the amount of additional activation storage grows only linearly,
$\mathcal{O}(T)$.
From a theoretical standpoint this means that *the amount of computation needed per token
does not increase when extending the context window*,
which directly satisfies a “linear scalability” requirement for ever larger corpora
such as those used during BERT or GPT training runs.


The price paid by early‐stage RNNs is loss of explicit pairwise interaction;
however, xLSTMs retain an expressive summarization capability through their
high‑dimensional *memory* rather than explicit token–token scores.
Because the recurrent update implicitly mixes past inputs,
the model follows Cover’s theorem – a non‑linear embedding into a higher dimensional
space increases the chance that different histories become linearly separable.
Thus xLSTMs keep **linear run time**, yet compensate
for missing explicit attention by learning powerful compressed representations.
Empirically this trade‑off shows up in generation benchmarks:
Figure 13 of the original work demonstrates perfectly linear scaling
of generation latency for xLTM variants,
while equivalent Transformer baselines incur superlinear growth.
Consequently, linear scalability emerged as a primary architectural goal:
maintain $\mathcal{O}(T)$ operations **and** $\mathcal{O}(T)$ auxiliary memory,
thereby allowing language models whose context windows stretch well past $10\,000$ tokens without prohibitive hardware costs.



# Higher‑capacity representations through richer memory structures

The original LSTM stores its entire history within a scalar cell $c_{t}\in\mathbb R$
(or at most an elementwise vector $\mathbf c_{t}\in\mathbb R^{d}$).
Although this representation suffices for many sequence tasks,
the limited dimensionality becomes apparent when predicting rare tokens.
Figure 2(b) illustrates how standard LSTMs struggle on low‐frequency vocabulary items:
the perplexity rises sharply because there simply isn’t enough representational bandwidth
to retain detailed distinctions among rarely observed patterns.


To address this bottleneck xLSTMs introduce **two distinct memory augmentations:**  

*The scalar extension* (**sLSTM**) keeps one scalar per cell but augments it
with a *normalizer state* $n_{t}$ which tracks cumulative gate products:
\[
n_{t}=f_{t}\,n_{t-1}+i_{t}.
\]
Dividing $c_{t}$ by $n_{t}$ yields an online weighted average,
thereby allowing more nuanced weighting between old and new information without sacrificing scalar size.
While s­LSTM does not increase raw dimensionality,
this extra bookkeeping already improves rare‐token performance compared with vanilla LSTMs,
as demonstrated empirically on Wikitext‑103.



*The matrix extension* (**mLSTM**) dramatically expands storage capacity.
Instead of a scalar order parameter,
m ​​​​​​​​​​​ ​stores an entire $d\times d$ matrix 
$\mathbf C_{t}\in\mathbb R^{d\times d}$ .
When processing input $\mathbf{x}_{t}$ it constructs
a *key* $\mathbf{k}_{t}\in\mathbb R^{d}$ 
and a *value* $\mathbf{v}_{t}\in\mathbb R^{d}$ through learned projections:
\[
\mathbf{k}_{t}= \frac{1}{\sqrt d}\,\mathbf W_{\!k}\,\mathbf{x}_{t}+ \mathbf b_{\!k},
\qquad 
\mathbf{v}_{t}= \mathbf W_{\!v}\,\mathbf{x}_{t}+ \mathbf b_{\!v}.
\]
These vectors are stored jointly via an outer product,
a classical **covariance update rule**
\[
\mathbf C_{t}=f_{\, t}\,\mathbf C _{\, t-1}
+ i_{\; t}\,\mathbf v _{\, t}\,\mathbf k _{\, t}^{\!\top}.
\tag{2}
\]
Equation (2) mirrors established associative–memory mechanisms such as bidirectional
associative memories (Kohonen 1972)
and Fast Weight Programmers (Schmidhuber 1992).
Because each key–value pair contributes rank one growth,
the effective rank of $\mathbf C$ grows with the number of distinct associations memorized,
providing **quadratically more degrees of freedom** than an equivalent vector‐based cell.
A normalizer $\mathbf n _{\, t}=f _{\, t}\,\mathbf n _{\, t-1}+i _{\, t}\,\mathbf k _{\, t}$ records the cumulative strength
of stored keys so that retrieval uses
\[
\tilde{\mathbf h}_{ t}= 
\dfrac{\;\mathbf C _{\, t}\,\mathbf q _{\, t}}{\max \bigl(|\,\mathbf n _{\, t}^{\!\top }\!\mathbf q _{\, t}|,\ 1\bigr)},
\qquad 
h _{\, t}=o _{\, t}\odot \tilde{\mathbf h}_{ t},
\tag{3}
\]
where $\mathbf q _ {\, t}= \mathbf W_{\!q}\,\mathbf{x}_{ t}+ \mathbf b_{\!q}$ is a query vector.
Thus retrieval operates analogously to key–value attention:
a query dot product selects relevant entries without constructing pairwise token interactions.
Empirically this richer structure enables non‐Transformer models such as x[0] :L m (m=0)
to solve Multi‑Query Associative Recall tasks at parity with Transformer baselines
(even when storing up\-to 256 pairs).

Therefore “higher–capacity representations” turned out to require **richer internal memories**
that move beyond simple scalars;
the combination of normalizer‐augmented scalars (s­LSTM) and full covariance matrices (m ­S​​​​​​.﻿​‌‌​​​​‍ ​​א​​​‎21)
meets this objective while preserving upstream differentiability.



# Revisability via flexible gate dynamics

Even an enlarged memory cannot help if once written data cannot be meaningfully overwritten.
In standard LSMTs both gates are bounded between 0 and 1 thanks to sigmoid activation,
so any update multiplies previous contents by factors no larger than 1.
Consequently payloads decay monotonically;
practical effect illustrated in Figure 2(a): during Nearest Neighbor Search an early match gets lodged into $c$,
yet later encounters cannot effectively replace it because $i$ remains bounded.

# Compatibility with modern deep LM infrastructure (pre‑LayerNorm residual stacks)

A practical large‑language model must slot cleanly into established training pipelines—
most notably those employing *pre‐LayerNorm* residual pathways popularized by GPT families.
A typical block consists multiplicatively instead please overshadow \(N^{'}S∇$$\
```
layer_norm → module → dropout → addition ↦ y ,
``` 

where `module` contains any parametrised transformation applied before adding its result back onto its input.


x𝐿𝑆𝑇𝓂 integrates both novel memories seamlessly under this scaffold:

- For s𝔏𝐒⅐⁰−𝓈 blocks (“post up‐projection”), memories are processed entirely inside the module after LayerNorm;
  afterward their outputs undergo an up‐projection back into ambient space before being added residually.
  This mirrors transformer style blocks yet preserves repeatable dynamics required by exponential gating.


- For m𝐿𝑇𝓂 blocks (“pre up‐projection”), projections raise inputs into high dimensional space before interacting with `C`.
  Since `C` already lives naturally at dimension `d × d`, performing key/value/value extraction therein reduces duplication overhead.
  After retrieval (`ℎ̃`) another projection maps back down prior level so LayerNorm sees stable statistics again.


Both patterns honor pre‐LayerNorm semantics:
normalisation occurs before any nonlinear branching (=gate evaluation),
which empirically stabilises very deep stacks—essential when reaching billions parameter scales
as documented across Sections 5–7 (“scaling law experiments”).
Additionally code release (`https://github.com/NX-AI/xlstm`) builds directly atop PyTorch’s `nn.Module`,
ensuring out ‑of ‑box compatibility with HuggingFace trainers or custom mesh TensorFlow pipelines.



Summarising, alignment between architectural novelties (exponential gates & enriched memories)
and existing LM engineering standards was deliberately enforced so researchers do not have
to redesign optimisation schedulers or distributed checkpointing logic when swapping an XLM layer
into place of standard transformer layers.



# Two complementary extensions: exponential gating AND novel memory structures

The preceding sections highlight **four pillars**—linear cost, higher capacity,
revisability, and ease-of-parallelisation—as guiding criteria around which x𝐿𝑆𝓉𝗠 was constructed.
Realising all four simultaneously would have been impossible if relying on a single modification alone;
instead two tightly coupled innovations work together:

| Goal | Achieved primarily by | Supporting effect |
|------|------------------------|-------------------|
| Linear computational scaling | **Matrix Memory + Scan‐friendly Recurrence** | Exponential gating introduces no extra sequential dependence |
| High storage density | **Matrix Memory (`C`)** | Normalizer ensures stable retrieval |
| Ability to overwrite old facts | **Exponential gated `i` / optionally `f`** | Normalizer rescales division \(c/n\) yielding stable averages |
| Parallel execution | **Removing hidden–hidden links (`m̂ʟ𝐒ᴛᴍ`)** | Faster CUDA kernel synchronises remaining dependence loops |

Exponential gates afford unrestricted magnitude control without sacrificing differentiability;
when combined with stabilizers they remain numerically well behaved even under billions’
parameter regimes.
Matrix memories provide exponentially richer embeddings while maintaining associative access patterns similar to self-attention yet at linear cost.
Memory mixing across multiple heads—a feature unique to sɭᵐᴏ𝐚𝗀𝗲——blends these mechanisms further:
heads can specialize either toward fine-grained revocable scalars or toward massive key/value storages depending on depth within the stack.



In practice architects configure an entire model as a mixture `x⁢[a:b]`,
i.e., allocating proportion `a/(a+b)` layers specialized around matrix memories (`m  …`) and proportion `b/(a+b)` around scalar-with-mixing cells (`s…`).  
Experiments show even modest proportions favoring `m` outperform pure transformer baselines on both validation perplexity (§5)
and downstream benchmarks (§7),
while inserting occasional `s` layers restores finegrained state tracking absent from “purely feedforward’’ SSM designs.”

Consequently these two extensions do not merely coexist—they reinforce one another:
exponential gating improves both revisit capability **and** numerical stability necessary when accumulating many outer products inside \(C_\!{}\);
conversely rich memories benefit from every gate being able either amplify relevant associations (`i`) or purge irrelevancies (`f`).  
Together they embody precisely those design aims enumerated at the start:
linear runtime even at extreme context lengths,
dramatically expanded latent bandwidth,
flexible overwrite dynamics crucial for search/retrieval scenarios,
and GPU-friendly recursions compatible with industrious large language model tool chains.



In summary, extending classical LSTM units along these carefully delineated objectives yields
the Flexible Long Short-Term Memory family termed ***x𝐿𝑆𝔗𝑀***—
a framework capable now—by construction—to operate at billions‑scale parameter regimes while meeting all four foundational desiderata outlined above.

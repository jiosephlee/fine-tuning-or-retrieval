\title{Stack Exchange of the Paper: "Group Sequence Policy Optimization"}

### What happens if all rewards in a group have identical values, making $\,	ext{std}\bigl(\,
group r(x,y_i)\bigr)=0$?
Question:
The advantage estimator $
̂A_i = \frac{r(x,y_i)-\,	ext{mean}(\,
group r)}{ \,	ext{std}(\,
group r)}$ would be undefined when the standard deviation is zero (e.g., all sampled responses receive reward 0). How do the authors handle this edge case in practice?
Answer:
The normalized advantage used by GSPO (and by GRPO from which it inherits the same formula) is

$$
\widehat A_{i}
=\frac{r(x,y_{i})-\operatorname{mean}\!\bigl(\{r(x,y_{j})\}_{j=1}^{G}\bigr)}
{\operatorname{std}\!\bigl(\{r(x,y_{j})\}_{j=1}^{G}\bigr)} .
$$

If every response in a group receives exactly the same reward – for instance all are scored 0 – then both the numerator and the denominator become 0 and a naïve implementation would produce an undefined value ( NaN ). In the paper this special case is not discussed explicitly, but the authors’ public implementation follows the customary “epsilon‑stabilisation’’ trick that is used whenever a batch‑wise standardisation appears in policy‑gradient code.

Concretely, after computing the per‑group mean and standard deviation they clamp the standard deviation from below:

```python
mean = rewards.mean(dim=0)                     # shape: (G,)
std  = rewards.std(dim=0)                      # shape: (G,)
std  = torch.clamp(std, min=1e-8)              # avoid division by zero
advantage = (rewards - mean) / std
```

Because `torch.clamp` forces `std` to be at least a tiny constant (`1e‑8` in most releases), division never blows up. When the true variance of a group really is 0 we also have `rewards - mean == 0` element‑wise, so after clamping each entry of `advantage` becomes exactly 0 rather than NaN. In other words, **the whole group contributes no gradient signal** – which is exactly what we would want, since there is no relative preference among its members.

From an algorithmic standpoint this behaviour is harmless:

* The clipping term in GSPO,

  $$
  \min\!\bigl(s_{i}(\theta)\widehat A_{i},
         \operatorname{clip}(s2{i}(\theta),1-\varepsilon,1+\varepsilon)\widehat A_{i}\bigr),
  $$

  evaluates to 0 whenever $\widehat A_{i}=0$, so such groups are simply ignored during back‑propagation.
* The loss remains well‑defined because every other group – which almost always has non‑zero variance – supplies a valid learning signal.
* If an entire minibatch consisted solely of zero‑variance groups (an extremely unlikely event given that rewards are real‑valued scores from a verifier), the optimiser would see a loss of exactly 0 for that update step; training would continue unchanged on the next minibatch.

Why does this situation occur rarely? In practice the verifier $r(\cdot,\cdot)$ outputs continuous values in $[0,1]$. Even with binary reward signals (e.g., success/failure), sampling multiple candidates per query usually yields at least one different outcome among them unless the prompt is pathological or the policy has already collapsed. Therefore most groups exhibit a non‑zero standard deviation and are processed normally.

To summarise, **the authors handle the “zero‑variance’’ edge case by adding a tiny constant to the denominator before normalisation**, which turns what would otherwise be an undefined expression into a well‑behaved zero advantage. This keeps the GSPO objective mathematically sound and prevents any numerical crash while preserving the intended semantics: a group whose members are indistinguishable in reward provides no direction for policy improvement.

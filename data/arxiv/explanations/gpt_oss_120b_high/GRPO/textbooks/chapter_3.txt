\title{A Textbook about the Paper: "DeepSeekMath: Pushing the Limits of Mathematical Reasoning in Open Language Models"}

Chapter 3: Prompt Engineering for Structured Math Solving  

Modern large language models acquire remarkable ability to solve mathematical problems when their inputs are carefully crafted – instead of asking a model simply “What is \(12\times13\)?”, one supplies a structured prompt that guides the generation process step by step, encourages interaction with external computation tools, or asks the model itself to write a short program whose execution yields the answer.  
The DeepSeekMath series illustrates how three complementary prompting paradigms—Chain‑of‑Thought (CoT), Program‑of‑Thought / PAL, and tool–integrated interaction à la ReAct/ToRA—can be combined into an instructional fine‑tuning corpus that drives a \(7\,\text{billion}\)-parameter model close to the level attained by proprietary systems such as GPT‑4. The following sections describe each paradigm in detail, expose their empirical impact reported in the DeepSeekMath experiments, and explain how they guided the construction of millions of training examples.



# Chain‑of‑thought prompting principle and few‑shot usage  

Chain‑of‑thought prompting asks a language model to produce an explicit intermediate reasoning trace before stating its final answer.  Rather than emitting only the conclusion, the model generates sentences that correspond closely to how a human would write down deductions (“First compute … Then substitute … Finally …”).  
In practice one supplies a few exemplars – typically two or three solved problems written in this style – as part of the prompt (“few shot”). When presented with a new question the model continues the pattern established by the exemplars, thereby keeping track of intermediate quantities and logical dependencies across many tokens.



The DeepSeekMath experiments demonstrate that this simple change yields dramatic gains across eight benchmarks ranging from elementary quantitative tests (e.g., GSM8K) to competition‐level contests (MATH) and even Chinese datasets such as CMATH and Gaokao variants.  
When evaluated under few‐shot CoT covering both English and Chinese problems, DeepSeekMath‑Base \(7\,\text{B}\) surpassed every publicly available base model recorded in the literature—including much larger models trained without specialized mathematics data—and exceeded a closed \(540\,\text{B}\)-parameter baseline by more than ten percentage points on MATH alone.


Intuitively, forcing an explicit chain makes it harder for the decoder to “jump” directly to an incorrect result because any mistake must survive scrutiny along several successive steps encoded in natural language tokens. Moreover, during reinforcement learning stages later on (see Section ‘Self‑consistency’), having access to full traces lets reward models evaluate whether every intermediate statement aligns with known algebraic rules rather than merely checking whether the final numeral matches a ground truth answer.



# Program‑of‑thought / PAL: generating executable Python snippets  

Program‑of‑thought—or its variant called PAL—is a prompting strategy that asks the model not only *what* answer follows logically from a problem statement but *how* one would obtain it using an actual programming language such as Python.  
A typical PAL prompt displays several demonstrations wherein each problem is followed by a short script employing standard libraries (`math`, `sympy`, …) that performs exact arithmetic or symbolic manipulation; after execution, the script prints the desired numeral.


DeepSeekMath leverages this paradigm heavily because its underlying weights originated from DeepSeek Coder Base v1½ \(7\,\text{B}\), whose pretraining emphasized source code consumption and generation across billions of GitHub tokens. This prior exposure makes DeepSeekMath unusually proficient at producing syntactically correct Python fragments even when constrained to generate them under strict length limits (\(1024\,\text{tokens}\) maximum).  

Empirically, when evaluated on GSM8K and MATH under few‐shot program‐of‐thought prompting—the same set used for pure CoT—the \(7\,\text{B}\) checkpoint outperformed Llemma 34 B (the former state‐of‐the​art open source system specialized for coding) despite having far fewer parameters.<sup>\[citation to pot and pal]\</sup>  
The study further reports that adding a dedicated coding phase before any mathematics–focused training already improves programmatically assisted solving, while subsequent math pretraining refines numerical grounding and symbolic reasoning capabilities.



# Tool‐integrated reasoning such as ReAct / ToRA style interactions  

Beyond writing pure code blocks, recent work has explored architectures wherein a language model alternates “thinking’’ steps with explicit calls to auxiliary tools—a pattern popularized under names such as ReAct​<sup>\[citation]</sup> and ToRA​<sup>\[citation]</sup>.  
A typical interaction follows three phases repeated iteratively:

1️⃣ **Think** The model produces a natural–language rationale describing what information it lacks or what computation must be performed next.  
2️⃣ **Act** It emits a special token indicating which external service should run (e.g., “⟨run_python⟩” together with accompanying code).  
3️⃣ **Observe** The system executes the requested operation and feeds back its output so that subsequent thinking can incorporate this newly acquired result.


DeepSeekMath’s supervised instruction set contains “tool–integrated solutions’’ crafted precisely for this workflow: GSM8K and MATH questions were manually annotated so that their reference answers combine ordinary explanatory sentences together with one or more Python invocations using `math` or `sympy`. When inference allows these actions—as opposed to restricting generation strictly to text—the \(7\,\text{B}\) checkpoint reaches nearly sixty per cent accuracy on MATH, comfortably exceeding every other open–source system tested under identical conditions.



# Self‑consistency inference by aggregating multiple sampled answers  

Even with sophisticated prompts, stochastic decoding sometimes yields erroneous intermediate steps that nevertheless lead toward a correct conclusion in some runs while failing in others—a phenomenon especially pronounced when temperature sampling creates divergent logical pathways.^[citation]  
Self‑consistency mitigates this variability through ensembling at inference time:


* For each question one draws **many** completions independently (DeepSeekMath used sixty four samples).  
* Each sampled response follows one of the structured formats described above (CoT or PAL).  
* After decoding finishes one extracts the final numerical answer from every trace and applies majority voting.



Because correct solutions tend to appear repeatedly among diverse stochastic trajectories—even when individual runs contain minor slips—the consensus most often coincides with the true answer while isolated mistakes are drowned out.^[citation]  
Applying self‑consistency on top of raw chain­-of­-thought generation boosted DeepSeekMath’s competition–level score on MATH from roughly fifty­-one point seven per cent up past sixty point nine per cent—a gain comparable to adding another training stage yet requiring no additional gradient updates.



# How these formats shape the construction of the instruction‑tuning dataset  

The success reported above hinges critically on exposing the model during supervised fine–tuning (SFT) to all three structured response styles simultaneously.


* **English sources** were drawn primarily from GSM8K & MATH together with subsets of MathInstruct​<sup>\[citation]</sup> where authors had already furnished either pure CoT explanations or full program fragments (§SFT Data Curation).  
* **Chinese sources** consisted of K–12 examination items spanning dozens of subtopics; each was solved twice—once narratively following CoT conventions and once through an explicit program fragment parallel to PAL.<sup>\[citation]</sup>  

All together these examples totalled **seven hundred seventy six thousand** paired entries (“question → solution’’ instances). During training each example was concatenated randomly until reaching roughly four thousand tokens—the maximum context length supported by DeepSeek’s architecture—and fed through standard cross–entropy optimization for five hundred update steps at a constant learning rate.



By deliberately mixing languages, task difficulties, and output modalities within one unified corpus, DeepSeekMath learns how to recognize which format best matches a given prompt cue (“solve this problem stepwise’’ versus “write Python code’’), how to transition between thinking phases and tool actions when appropriate, and finally how to produce internally consistent traces amenable both to human inspection and automatic reward modeling later used during reinforcement learning.


---  

Through chained advances—from web mining billions of mathematics tokens → code pretraining → multi−format supervised instruction tuning → efficient Group Relative Policy Optimization—the authors demonstrate that thoughtful prompt engineering alone can lift an openly released \(7\,\text{B}\)-parameter system onto par with far larger proprietary contenders on demanding quantitative benchmarks._END_

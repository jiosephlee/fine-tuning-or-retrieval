Answer:
**Answer**

The “effective precision’’ reported for BitNet $b^{\,1.58}$ – $\approx$ $\displaystyle \log_{2}(3)\approx 1.585$ bits per weight – is not a description of how the weights are physically stored on the device.  
It is an *information–theoretic* way of saying how many binary symbols would be required, on average, to encode a ternary value if we compressed it optimally.

---

### From ternary symbols to bits

A weight in BitNet $b^{\,1.58}$ belongs to the alphabet  

$$
\mathcal{A}=\{-\,1,\;0,\;+\,1\},
$$  

which contains three distinct symbols.  
If we denote by $p_{k}$ the probability that a randomly chosen weight takes symbol $k\in\mathcal{A}$, the Shannon entropy of this source is  

$$
H(\mathbf W)=-\,\sum_{k\in\mathcal A} p_{k}\,\log_{2} p_{k}\qquad
    \textbf{[bits/weight]} .
$$  

Entropy gives the *minimum* expected number of bits required by any lossless code (e.g., arithmetic coding).  
When all three symbols are equally likely   $p_{-1}=p_{0}=p_{+}={}^{ }{\displaystyle \frac13}$   we obtain  

$$
H(\mathbf W)=
   -\,3\,{\displaystyle \frac13}\,\log_{2}\!\Bigl({\displaystyle \frac13}\Bigr)
   =\,\log_{2}3 \;\approx\-\,１．５８４９６~{\rm bits}.
$$  

Thus $\displaystyle \log_{2}3$ is the theoretical lower bound on the *average* number of binary decisions needed to represent one ternary weight.

---

### Why “≈ $\displaystyle \log_{2}(3)$’’ appears in the paper

The authors use this quantity as a *scalar* that reflects how much information each parameter carries relative to a full‑precision (16‑bit) model:

* **Full‑precision** – each FP16 weight carries exactly $16$ raw bits.
* **BitNet $b^{\,1.58}$** – each weight carries roughly $\displaystyle \log_{2}3$ raw bits of information.

When comparing models they therefore compute “cost’’ as  

$$
{\rm cost}=({#}{\rm parameters})\times({\rm effective~precision}),
$$  

so a $13${B}${‑}${parameter} BitNet $b^{\,1498}$ model has roughly  

$$
13\times10^{9}\times \log_{2}3 \;\approx\.20\.6\times10^{9}
$$  

bit‑units, which can be contrasted with  

$$
13\times10^{9}\times16=208\times10^{9}
$$  

bit‑units for an FP16 baseline.

Because the true distribution of $\{-\,1,0,+\,1\}$ after training is **not** perfectly uniform (many weights become zero), the actual entropy is *slightly* lower than $\displaystyle \log_{2}3$.  
If we write $p_{0}=q$ and assume the non‑zero signs are equiprobable, then  

$$
H=-\,q\,\log_{2} q-(1-q)\,\log_{2}\!\Bigl(\frac{\,1-q\,}{2}\Bigr)
   = H_{\text {Bernoulli}}(q)+(1-q),
$$

where  

$$
H_{\text {Bernoulli}}(q)= -\,q\,\log_{2} q-(1-q)\,\log_{2}(1-q).
$$  

Typical trained BitNet models have $q\simeq0.4{-}0.6$, giving  
$H\simeq ১।৪৫{-}১।৫৫$ bits – close enough that quoting “≈ $\displaystyle \log_{2}3$’’ makes sense as an upper bound and a convenient single number.

---

### Do they really compress with an entropy coder?

No. In practice the weights are stored using straightforward binary structures:

* a **mask** indicating which positions are zero (one bit per position), and  
* a **sign** bit for every non‑zero position (another bit only where needed).

These two arrays are packed into ordinary memory words (often using two physical bits per weight). The resulting raw memory footprint therefore exceeds $\displaystyle \log_{2}3$; it is usually close to **two bits** per weight because hardware cannot address fractional bit slots directly.

The term *effective precision* therefore **does not** refer to an actual coded representation that attains the Shannon limit; it simply quantifies how much *information* each parameter contributes under the idealised uniform‑distribution assumption.

---

### Intuition & broader context

Think of “effective precision’’ as analogous to “model size in bits’’ rather than “bits stored”.  
If you were able to run an optimal lossless compressor over all parameters, you could bring their size down from $2N_{\rm params}$ raw bits (the typical storage cost) toward  

$$
N_{\rm params}\times H(\mathbf W)\;\approx\
N_{\rm params}\times \displaystyle \log_{2}3 .
$$

This viewpoint has become common when analysing quantised neural networks:

* Binarised networks $(\{-\,1,+\,1\})$ have an upper bound of $\displaystyle \log_{2}2=1$ bit.
* Ternary networks $(\{-\,1,0,+\,１\bigr)$ have an upper bound of $\displaystyle \log_{2}3\simeq ১।৫৮$
* Quaternary or higher‑order quantisations give larger bounds $(\: \displaystyle \log_24=২,\;\displaystyle \log_28=৩,\dots)$

Using these bounds lets researchers plot scaling laws (e.g., performance vs.\ “bits‑per‑parameter’’) even though actual implementations still allocate whole‑bit storage units.

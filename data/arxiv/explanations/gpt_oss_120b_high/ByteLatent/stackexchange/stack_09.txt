\title{Stack Exchange of the Paper: "Byte Latent Transformer: Patches Scale Better Than Tokens"}

### What is meant by “block‑causal” attention in the Global Transformer and how does it differ from standard causal attention?
Question:
Section 4 mentions that the Latent Global Transformer uses a block‑causal mask (citing Dubey et al., 2024). How exactly does block‑causal mask work when patches have variable lengths? Does it restrict attention only within each block/patch or across patches up to current one? A concrete example illustrating attention patterns would be helpful.
Answer:
**Short answer**

*Block‑causal* attention is simply *causal* attention applied at the **patch** granularity instead of at the raw‑byte (or token) granularity.  
In the Latent Global Transformer each **patch** $p_j$ is represented by a single latent vector, and the self‑attention matrix is masked so that a query belonging to patch $j$ may attend only to keys belonging to patches $i \le j$.  
Consequently, a long patch that contains many bytes behaves exactly like a short one – it occupies one row/column in the attention matrix – while still respecting the left‑to‑right autoregressive order required for language modelling.

This differs from “standard’’ causal masking, where every individual element (byte or token) gets its own row/column and may see **all** earlier elements individually.  
Block‑causal therefore reduces the quadratic cost from $\mathcal O(n^{2})$ (where $n$ is the number of bytes/tokens) to $\mathcal O(m^{2})$ with $m \ll n$ being the number of patches, yet it preserves exactly the same causality constraint at the level of whole documents.



---

### How it works when patches have variable length

Let  

* $\mathbf{x}=x_{1},\,dots ,\,x_{N}$ be the raw byte stream,
* $f_{p}$ be any incremental patching function (static stride, whitespace, entropy‑based …),  
* $p_{j}=f_{p}^{-1}(j)$ denote *the set of byte positions that belong to patch $j*$,
* $m=\lvert\,\{p_{j}\}\rvert$ be the total number of patches in a document.

The global transformer receives the sequence  

$$
\mathbf{p}=p_{1},\,p_{2},\,dots ,\,p_{m},
$$

where each $p_{j} \in \mathbb R^{h_{\mathcal G}}$ is produced by the local encoder (cross‑attention over the bytes that make up that patch).

The **block‑causal mask** $M^{\text{bc}}\in \{0,-\infty\}^{\,m\times m}$ is defined by  

$$
M^{\text{bc}}_{j,i}= 
   \begin{cases}
      0       & \text{if } i \le j \\[4pt]
      -\infty & \text{otherwise}
   \end{cases}.
$$

Applying this mask inside softmax gives  

$$
\operatorname{Attention}(Q,K,V)=
   \operatorname{softmax}\!\Bigl(\frac{QK^{\top}}{\sqrt{d_k}}+M^{\text{bc}}\Bigr)V .
$$

Because $M^{\text{bc}}$ depends only on **patch indices**, it does *not* look at how many bytes each patch contains: whether $p_{2}$ spans 5 bytes or 30 bytes it still occupies a single entry $j=2$.  
All information inside a long patch has already been aggregated by the encoder cross‑attention before entering $\mathcal G$; after aggregation there is nothing else left for $\mathcal G$ to “see’’ inside that segment.



### Comparison with ordinary causal masking

|                     | Unit that attends | Mask shape                                                   | Computational cost |
|---------------------|-------------------|--------------------------------------------------------------|--------------------|
| **Standard causal** | Byte / token      | Upper–triangular of size $N\times N$                         | $\mathcal O(N^{2})$ |
| **Block‑causal**    | Patch             | Upper–triangular of size $m\times m$, $m<N$                 | $\mathcal O(m^{2})$ |
| **Local “block‑causal’’** (used in encoder/decoder) | Byte | Fixed window of width $w_{\mathcal E}$, may cross boundaries but never jumps past document start | $\mathcal O(N\,w_{\mathcal E})$ |

Thus *block‑causal* preserves exactly the same “no‑future’’ rule as ordinary causal masking—nothing from later patches may influence earlier ones—while allowing *parallel* computation inside each block because every query inside a given block sees exactly the same set of keys (the whole prefix up to that block).



### Concrete example

Assume we have a short sentence whose bytes are split by entropy patching into three variable–length blocks:

```
bytes :   [b1 b2 b3 b4]   [b5 … b11]   [b12 b13 b14]
patches :        p1            p2            p3
```

The local encoder first pools each bracket into a latent vector:
$p_{1}=E(b_{1..4}),\, p_{2}=E(b_{5..11}),\, p_{3}=E(b_{12..14})$.

The Global Transformer receives `[p₁ , p₂ , p₃]`.  
The allowed attentional connections are shown below (`✔` = allowed, `✗` = masked):

```
        key →   p1   p2   p3
query
    p1      ✔    ✗    ✗
    p2      ✔    ✔    ✗
    p3      ✔    ✔    ✔
```

From the viewpoint of raw bytes this corresponds to  

* every byte in *patch 2* may attend indirectly (through its pooled representation) to any byte belonging to *patch 1*,  
* bytes in *patch 3* may attend indirectly to everything in *patch 1* and *patch 2*,  
* but no byte may ever attend directly or indirectly to a byte belonging to a later *patch*.

If we had used ordinary causal masking on raw bytes there would be an $N\times N=14\times14$ matrix with a dense upper triangle – far more expensive and without any grouping benefit.



### Why “block” rather than “patch” terminology?

In Llama 3’s implementation (\citet{dubey2024llama}) *blocks* refer specifically to **chunks** processed by FlashAttention kernels for efficiency (“fixed‐width blocks”). The authors show that if you apply an ordinary triangular mask inside each chunk and also allow every query in chunk $c$ to see all keys belonging to earlier chunks, you obtain exactly the same semantics as described above. The term “block‑causal” therefore emphasizes both:

1. **Causality** – no future information leaks.
2. **Blockwise computation** – queries are processed chunk‐by‐chunk which gives large speedups on GPUs.



### Bottom line

- **Block‑causal = causal at the level of patches/blocks**, not at individual byte/token level.
- Variable‐length patches do not change anything: each whole patch becomes one element in the global sequence; its length only matters for how much work was done in the local encoder before reaching $\mathcal G.$
- The pattern is identical to standard causal once you compress the input into patches – you can picture it as an upper–triangular matrix over patches instead of over raw bytes.  

This is precisely what Section 4 means when it says “the global model uses a block‑causal attention mask … restricts attention up to and including the current patch.”

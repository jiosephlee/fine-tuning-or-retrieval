\title{Stack Exchange of the Paper: "Byte Latent Transformer: Patches Scale Better Than Tokens"}

### How does Bits‑Per‑Byte (BPB) relate to traditional perplexity for byte‑level models?
Question:
The paper reports BPB as \(\text{BPB}(x)= \frac{\mathcal{L}_{CE}(\mathbf{x})}{\ln(2) \cdot n_{\text{bytes}}}\). I know perplexity is exp(loss per token), but I'm unsure how BPB translates to an intuitive measure of model quality. For example, what BPB value corresponds roughly to a perplexity of 20 on a tokenizer with average token length 4 bytes? Also, can BPB be compared across datasets with different byte distributions?
Answer:
**Answer**

The “Bits‐Per‐Byte” (BP / B) metric that the BLT paper reports is simply a re‐expression of the usual cross‐entropy loss, but measured per **byte** and expressed in base‐2 units (bits). Because it does not depend on any external vocabulary, it plays the same role for raw‐byte language models that *perplexity* plays for token‐based models.

---

### From cross‐entropy to BP / B

The paper defines  

$$
\text{BPB}(x)=\frac{\mathcal L_{\mathrm{CE}}(\mathbf x)}
                 {\ln(2)\;\cdot\,n_{\text{bytes}}}\!,
$$  

where  

$\displaystyle 
\mathcal L_{\mathrm{CE}}(\mathbf x)
   = \sum_{i=1}^{n_{\text{bytes}}}
     -\,\log p(x_i\,|\,\mathbf x_{<i})
$  

is the usual *negative log‐likelihood* summed over all bytes of a sequence.  
Dividing by $\ln(2)$ converts the natural–log loss (nats) into a binary–log loss (bits), and dividing by $n_{\text{bytes}}$ yields an **average** number of bits needed to encode one byte under the model’s predictive distribution.

If we denote this average by $b$ (i.e. $b=\text{BPB}$), then for any single byte  

$$
-\log_2 p(x_i\,|\,\mathbf x_{<i}) = b .
$$  

In other words, the model thinks that each byte carries $b$ bits of uncertainty on average.

---

### Relating BP / B to token‐level perplexity

Token‐level perplexity is defined as  

$$
\operatorname{PPL}= \exp!\Bigl(\frac{\mathcal L_{\mathrm{CE}}}{n_{\text{tokens}}}\Bigr)\!,
$$  

where the exponent uses **natural** logarithms.  
Let $\ell$ be the *average* number of bytes that belong to a single token (the “average token length”). Then  

$$
n_{\text{tokens}}
   = \frac{n_{\text{bytes}}}{\,\ell\,}
   \quad\Longrightarrow\quad
   \frac{\mathcal L_{\mathrm{CE}}}{n_{\text{tokens}}}
   = \ell\,\frac{\mathcal L_{\mathrm{CE}}}{n_{\text{bytes}}}
   = \ell\,b\,\ln(2)\!.
$$  

Plugging this into the definition of perplexity we obtain  

$$
\operatorname{PPL}
   = \exp!\bigl(\ell\,b\,\ln(2)\bigr)
   = 2^{\,\ell\,b}\!.
$$  

Thus **perplexity is just an exponential of “bits‐per‐byte times the average token length.”** Conversely,

$$
b = \frac{\log_2(\operatorname{PPL})}{\,\ell\,}\!.
$$

---

### Concrete example

Suppose a tokenizer yields an average token size of $\ell=4$ bytes and we observe a perplexity of 20 on a test set. The corresponding BP / B is  

$$
b
   = \frac{\log_2(20)}{4}
   \approx \frac{4.3219}{4}
   \approx 1.08~\text{bits/byte}.
$$  

A value around 1 bit/byte tells us that, after taking into account all short‐range and long‐range regularities in English text, each byte is still only half as uncertain as a completely random byte (which would require exactly 8 bits). In practice state‐of‐the‐art byte models hover between 1 and 2 bits/byte on large corpora.

---

### Comparing BP / B across datasets

Because BP / B normalises by **bytes**, not by tokens, it can be compared across corpora that have very different vocabularies or segmentation strategies. However there are two practical caveats:

1. **Intrinsic entropy of the data** – A dataset that contains many low‐entropy regions (e.g., long runs of whitespace, repetitive code fragments) will naturally yield a smaller BP / B even for an identical model architecture. Conversely, highly diverse multilingual text which uses many UTF‐8 multibyte characters pushes the optimal achievable BP / B upward because the maximum information per byte remains bounded at 8 bits but the data truly needs more than that many bits on average.

2. **Evaluation consistency** – When you report a single number you must compute it on a held‐out **test set drawn from the same distribution** that the model was trained on; otherwise differences may reflect domain shift rather than genuine modelling strength.

Provided you respect these conditions, BP / B is a perfectly legitimate scalar for cross‐dataset comparison—just as subword perplexity is often used to compare language models trained on different corpora.

---

### Intuition & broader context

Think of BP / B as an *effective compression rate*: if you were to encode a text using arithmetic coding guided by the model’s probability distribution, you would need roughly $b$ bits for every raw byte in the file. A perfect predictor would need zero bits (the model knows exactly what comes next), while an uninformed uniform predictor would need $8$ bits/byte—the size of an uncompressed UTF‐8 byte.

Because this metric directly reflects information theory rather than an artifact of a particular tokenizer, it also aligns nicely with other evaluation lenses used in the BLT paper—such as FLOP‐controlled scaling or robustness to noise—where the goal is “how many useful bits does each compute step extract from raw bytes?”.

In summary  

* **BP / B = average negative $\log_{2}$ probability per byte.**  
* **Token‐level perplexity ≈ $2^{(\text{average token length})\times (\text{BP/B})}$.**  
* **For a 4‑byte average token and PPL = 20 we obtain ≈ 1.08 bits/byte.**  
* **BP / B can be compared across datasets as long as test conditions are matched; differences will reflect both model quality and intrinsic data entropy.**

Foundations of Parameter‑Efficient Model Adaptation  

# The Rise of Large Foundation Models and Their Training Costs  

In recent years a new class of machine learning systems—large foundation models—has emerged as a dominant force in both natural language processing and computer vision. Exemplary instances such as ChatGPT \cite{brown2020language,chen2021evaluating} and Stable Diffusion \cite{rombach2022high} display striking generalization abilities across a wide spectrum of downstream problems. The remarkable capabilities of these systems are tied directly to their massive scale: contemporary language models now contain on the order of hundreds of billions of parameters (for example, GPT‑3 comprises roughly $1.75\times10^{11}$ parameters).  

Training such models from scratch demands an astronomical amount of compute, data, and engineering effort. The required GPU‑hours grow superlinearly with model size because both forward–backward passes and optimizer state updates increase with the number of parameters. Consequently, only a handful of organizations possess the resources necessary to create new foundation models at this scale, while most researchers must rely on pretrained checkpoints released by these entities. This economic reality creates a clear imperative: after a foundation model has been trained once on massive corpora, it should be possible to adapt it efficiently to many downstream tasks without re‑training it entirely.

# Why Adapting Pretrained Models Is Essential  

The central premise behind leveraging pretrained foundation models is that they encode rich structural knowledge about language or visual data that can be transferred to new problems. However, downstream tasks often differ substantially from the pretraining objectives—consider sentiment classification versus next‑word prediction, or object detection versus image synthesis. Directly using a frozen pretrained model on such tasks would typically yield suboptimal performance because the model’s output heads or intermediate representations are not aligned with the specific target distribution.  

Fine‑grained adaptation is therefore required to adjust the model’s internal mappings while preserving the bulk of its pretrained knowledge. A naïve approach would be full fine‑tuning: updating every parameter on a task‐specific dataset through gradient descent. While this method can achieve high accuracy when sufficient labeled data are available, it is prohibitively expensive for large models because each downstream task would entail storing a full copy of all parameters and incurring high computational cost during training. Moreover, full fine‑tuning discards much of the original parameter budget that could otherwise be shared across many tasks.

Parameter‑efficient adaptation methods address these concerns by limiting the number of trainable variables while still allowing meaningful task‐specific adjustments. By keeping most weights frozen, they retain the semantic structure learned during pretraining, reduce storage footprints for multiple tasks (since only a small set of “delta” parameters need be saved per task), and lower compute requirements during adaptation.

# Model Fine‑Tuning Versus Adapters Versus Prompts  

Three primary families dominate current research on parameter‑efficient fine‑tuning (PEFT): (i) **model fine‑tuning**, (ii) **adapter tuning**, and (iii) **prompt tuning**.

**Model fine‑tuning** keeps the original architecture unchanged but updates a selected subset—or sometimes all—of its weight matrices during downstream training \cite{hulora2022,zaken2022bitfit,guo2020parameter,raffel2020exploring,qiu2023controlling,zhang2022adaptive,chavan2023one}. Because no additional components are introduced at inference time, model fine‑tuning incurs zero extra latency compared to the original frozen model. In practice many works adopt a small learning rate so that the fine‑tuned weights stay close to their pretrained values; this heuristic aims to preserve pretrained knowledge by limiting divergence between pretraining and fine‐tuned regimes.

**Adapter tuning** augments each layer with small trainable modules inserted either before or after the existing linear transformations \cite{rebuffi2017learning,houlsby2019parameter,pfeiffer2020adapterfusion,lin2020exploring,he2021towards}. These modules typically consist of a down‑projection followed by an up‑projection (a bottleneck), thereby introducing relatively few extra parameters per layer while leaving the original weights untouched. The added adapters increase inference cost modestly because each forward pass must evaluate them in addition to the original computation graph.

**Prompt tuning** attaches learnable tokens—often called “prefixes” or “soft prompts”—to the input embedding sequence \cite{li2021prefix,lester2021power}. During adaptation only these prompt vectors are updated; all backbone weights remain frozen. Prompt tuning is especially popular in language models because it retains zero architectural change beyond extending the input context length. Nevertheless it still introduces marginal additional compute as each forward pass concatenates extra token embeddings.

Each family trades off three central desiderata for PEFT methods:

1. **Parameter budget** – how many additional or modified parameters need to be stored per downstream task.
2. **Inference latency** – whether extra computation is required at test time.
3. **Knowledge preservation** – how well the method retains representations learned during pretraining.

Model fine‑tuning scores highest on inference latency (none) but often requires more trainable parameters than adapters or prompts when many layers are updated simultaneously. Adapter tuning reduces storage cost at modest inference overhead; prompt tuning minimizes both storage and added compute but may be less expressive because only input embeddings are altered.

# Desired Properties for PEFT Methods  

When designing a new PEFT technique it is useful to articulate explicit criteria that capture practical constraints encountered in real deployments:

* **Compactness** – A PEFT method should involve as few trainable parameters as possible while still achieving competitive performance on target tasks. This compactness directly translates into lower memory consumption for storing multiple task‐specific checkpoints.
* **Zero Additional Inference Cost** – Ideally adaptation should not increase runtime latency during deployment; users should benefit from improved task performance without paying extra computational price.
* **Preservation of Pretrained Knowledge** – Since foundation models have been trained on vast datasets capturing rich statistical regularities, any adaptation should avoid destroying this knowledge wholesale. Techniques that enforce similarity between pretrained and adapted weights—for instance through orthogonal transformations that preserve pairwise angles among neuron vectors—exhibit increased stability and generalization \cite{qiu2023controlling}.
* **Expressivity Within Structured Constraints** – A method must retain enough capacity to capture task‐specific variations despite its parametric restrictions; otherwise underfitting will occur.
* **Scalability Across Model Types** – The approach should apply uniformly to vision transformers, large language models, and diffusion architectures rather than being confined to a single modality or architecture family.

The work examined in this chapter seeks precisely these properties by building upon Orthogonal Fine‑tuning (OFT) \cite{qiu2023controlling}—a principled variant that multiplies each weight matrix $\mathbf{W}^{0}\in\mathbb{R}^{d\times n}$ by an orthogonal matrix $\mathbf{R}\in\mathbb{R}^{d\times d}$ so that $\mathbf{z}= (\mathbf{R}\mathbf{W}^{0})^{\!\top}\mathbf{x}$ replaces the original linear mapping $\mathbf{z}= (\mathbf{W}^{0})^{\!\top}\mathbf{x}$. Because orthogonal matrices preserve inner products,
the angle between any pair of neuron vectors remains unchanged after adaptation,
which empirically yields more stable training dynamics compared with additive low–rank updates such as LoRA \cite{hulora2022}.

A practical obstacle arises however: representing an arbitrary $d$-dimensional dense orthogonal matrix naively requires $\mathcal O(d^{2})$ parameters—far more than many contemporary PEFT budgets permit. Existing OFT mitigates this cost by enforcing a block‑diagonal structure on $\mathbf{R}$,
partitioning dimensions into $r$ groups each handled by an independent $b\times b$ orthogonal block ($br=d$). While this reduces parameter count dramatically,
it also imposes strong inductive biases—in particular it forces inter–group interactions to remain static—which limits expressivity relative to full orthogonal transformations.

Thus an improved PEFT strategy must reconcile *dense* interaction capability with *parameter efficiency*. The remainder of this chapter outlines one such solution introduced by “Parameter‐Efficient Orthogonal Finetuning via Factorization”.

# High‑Level Contribution Overview  

The paper proposes **Orthogonal Butterfly Fine‑tuning (BOFT)**—a novel PEFT method that retains OFT’s theoretical advantage (preservation of pairwise neuron geometry) while dramatically lowering its parameter footprint through *butterfly factorization*. Its contributions can be grouped into four themes:

1. **Information Transmission Perspective** –  
   The authors reconceptualize constructing a dense orthogonal matrix $\mathbf{R}$ as an *information transmission* problem over a grid graph comprising $d$ source nodes and $d$ target nodes across multiple intermediate layers. Each factor matrix $\mathbf{B}_{i}$ contributes directed edges between adjacent layers; dense connectivity (every source can reach every target) together with minimal free edges defines an efficient sparsity pattern under orthogonality constraints.
   
2. **Butterfly Factorization for Orthogonal Parameterization** –  
   Drawing inspiration from the Cooley–Tukey fast Fourier transform algorithm’s butterfly network \cite{cooley1965algorithm}, they build $\mathbf{R}$ as a product of $\mathcal O(\log d)$ sparse matrices each containing only $\mathcal O(d)$ nonzero entries:
   \[
   \mathbf{R}(m,b)=\prod_{i=1}^{m}\tilde{\mathbf B}^{\,b}_{(d,i)},
   \]
   where each component $\tilde{\mathbf B}^{\,b}_{(d,i)}$ is block‐diagonal with $b\times b$ butterfly factors $\mathbf B^{F}(k)$ defined in Equation \eqref{eq:but_factor}. By enforcing orthogonality on every component (via Cayley transforms applied locally to $2\times2$ rotations), $\mathbf{R}(m,b)$ remains orthogonal despite being assembled from highly sparse pieces.
   
   As a result BOFT needs only 
   \[
   \frac12(b-1)\! d\, m
   \]
   effective trainable parameters for a linear layer of size $d\times n$. When $b=2$ and $m=\log_{2} d$, this scales as $\mathcal O(d\log d)$—a drastic reduction relative to OFT’s $\mathcal O(d^{2})$ cost.
   
3. **Theoretical Insights & Weight Interpolation** –  
   The authors prove that BOFT’s hypothesis class strictly contains that of block‐diagonal OFT given identical block sizes; formally,
   *BOFT is more expressive than OFT with the same block size* (Theorem \ref{thm:exp_boft}). Moreover,
   repeated multiplication allows smooth interpolation between identity and arbitrary dense orthogonal matrices,
   furnishing an intuitive “weight interpolation” curve useful for regularizing training.
   
4. **Empirical Validation Across Modalities** –  
   Leveraging BOFT they adapt large vision transformers, massive language models, and text‑to‑image diffusion pipelines on diverse downstream benchmarks spanning computer vision (e.g., classification, detection) and natural language processing (e.g., instruction following). In every setting BOFT outperforms state‑of‑the‑art PEFT baselines—including LoRA and block diagonal OFT—while requiring substantially fewer tunable parameters.
   
Collectively these contributions establish BOFT as a generic parameter‑efficient fine‐tuning framework that marries strong theoretical foundations (orthogonality preserving geometry), practical sparsity via butterfly factorization (low storage & computation), and empirically robust performance across heterogeneous foundation models.

Geometry‑Preserving Updates in Neural Networks  

# Linear layers as sets of neuron vectors  

A fully‑connected linear layer maps an input vector $\mathbf{x}\in\mathbb{R}^{d}$ to an output vector $\mathbf{z}\in\mathbb{R}^{n}$ via a weight matrix $\mathbf{W}^{0}\in\mathbb{R}^{d\times n}$.  In most modern deep‑learning libraries the forward computation is written as  
\[
\mathbf{z}=({\mathbf{W}^{0}})^{\!\top}\mathbf{x}.
\]  
Each column $\mathbf{w}_{i}^{0}\in\mathbb{R}^{d}$ (for $i=1,\dots,n$) therefore represents the **neuron vector** associated with the $i$‑th output unit.  Geometrically, these vectors live in the same $d$‑dimensional space as the input features and can be viewed as directions along which $\mathbf{x}$ is projected before being summed into an activation.  The collection $\{\mathbf{w}_{i}^{0}\}_{i=1}^{n}$ thus forms a point cloud on $\mathbb{R}^{d}$ that encodes how information is extracted from $\mathbf{x}$ by the pretrained model.  From a geometric perspective, any modification of $\mathbf{W}^{0}$ can be understood as moving these points around or reshaping their configuration.  Hence, when we adapt a pretrained model to a downstream task we would like to keep this configuration **stable**—or at least change it in a controlled way—so that knowledge learned during pretraining does not vanish abruptly.



# Pairwise angular relationships and hyperspherical energy  

The most fundamental geometric invariant among neuron vectors is their **pairwise angle**.  For any two neurons $\mathbf{w}_{i}^{0},\mathbf{w}_{j}^{0}$ let  

\[
\theta_{ij}
= \arccos\!\bigg(\frac{\langle \mathbf{w}_{i}^{0},\,\mathbf{w}_{j}^{0}\rangle}{\|\mathbf{w}_{i}^{0}\|_2\,\|\mathbf{w}_{j}^{0}\|_2}\bigg)
\]  

denote the angle between them.  The full set of angles $\{\theta_{ij}\}_{i<j}$ captures how “spread out’’ or “clustered’’ the neurons are on a sphere of radius equal to their norms.  Recent work has shown that this spread correlates with generalization ability: when neurons are more uniformly dispersed on a hypersphere—an effect quantified by **hyperspherical energy**—the model tends to be more robust after fine‑tuning~\cite{liu2018learning,liu2021orthogonal}.  In this context, hyperspherical energy is a scalar functional that penalizes configurations with many small angles (i.e., clusters) and rewards those where angles are large and diverse.  

Preserving pairwise angles during adaptation therefore serves two purposes.  First, it guarantees that the relative orientation learned from massive pretraining data remains intact; second, it indirectly keeps hyperspherical energy low, which has been empirically linked to improved stability and generalization on downstream tasks~\cite{qiu2023controlling}.  Consequently, many recent fine‑tuning paradigms have been designed explicitly so that they do **not** perturb these angular relationships.



# Definition and key properties of orthogonal matrices  

A real square matrix $\mathbf{R}\in\mathbb{R}^{d\times d}$ is called **orthogonal** if  

\[
\mathbf{R}^{\!\top}\,\mathbf{R}= \mathbf{I}_d,
\]  

where $\mathbf I_d$ denotes the identity matrix of size $d$.  This compact condition entails several important geometric consequences:

* **Norm preservation** – For any vector $\mathbf v$, $\|\mathbf R \mathbf v\|_{2}= \|\mathbf v\|_{2}$.  Hence scaling factors are never introduced.
* **Inner‑product preservation** – For any pair $(\mathbf u,\mathbf v)$,
  \[
  \langle \mathbf R \mathbf u,\;\mathbf R \mathbf v\rangle
   = \langle \mathbf u,\;\mathbf v\rangle .
  \]  
  Because inner products determine cosines of angles, every angle between any two vectors stays unchanged after left‑multiplication by an orthogonal matrix.
* **Determinant magnitude one** – $\big|\det(\mathbf R)\big|=1$, guaranteeing that orientation is either preserved ($+1$) or reflected ($-1$) without volumetric expansion or contraction.
* **Invertibility via transpose** – The inverse of an orthogonal matrix coincides with its transpose: $\mathbf R^{-1}= \mathbf R^{\!\top}$. 

These properties imply that an orthogonal transformation rotates—or possibly mirrors—the space without distorting distances or angles.  When such a transformation is applied uniformly to all neuron vectors in a linear layer (e.g., $\widetilde{\mathbf W}= \mathbf R\,\mathbf W^{0}$), every pairwise angle $\theta_{ij}$ is exactly preserved:

\[
\theta_{ij}
= \arccos
      \frac{\langle \widetilde{\!\!\;\!\!{\bf w}}_i , 
                 \widetilde{\!\!\;\!\!{\bf w}}_j\rangle}
           {\|\widetilde{\!\!\;\!\!{\bf w}}_i 
            \|_2\, 
            \|\widetilde{\!\!\;\!\!{\bf w}}_j
            \|_2}}
=
    \arccos
      \frac{\langle {\bf w}_i , 
                 {\bf w}_j\rangle}
           {\|{\bf w}_i 
            \|_2\, 
            \|{\bf w}_j
            \|_2}},
\]
where ${\bf w}_i={(\bf W^{0})}_{:,i}$.  Therefore an orthogonal matrix offers precisely the geometric guarantee needed for *geometry‑preserving* finetuning.



Because directly optimizing over all orthogonal matrices would involve handling a manifold constraint (\refeqn{$\bf R^{T} R = I$}), most practical implementations employ **Cayley parameterization**~\cite{liao2022cayley}:

\[
    \boxed{
    {\bf R}= (\bf I + {\bf Q})\,(\bf I - {\bf Q})^{-1}},
    \qquad
    {\bf Q}=-{\bf Q}^{\,\!\top}.
\]

Here ${\bf Q}$ is a *skew‑symmetric* matrix whose entries are unrestricted real numbers; any such ${\bf Q}$ yields an orthogonal ${\bf R}$ (provided ${\bf I}-{\bf Q}$ remains invertible).  During training one back‑propagates through ${\bf Q}$, thereby automatically enforcing orthogonality without requiring explicit projection steps.

By factorizing ${R}$ into sparse components (block–diagonal or butterfly), recent works achieve *parameter efficiency* while retaining multiplicative benefits.


# Prior work leveraging geometry in fine‑tuning  

The idea that *geometry matters* for fine‑tuning has surfaced repeatedly across recent literature:

* **Small learning rates** – Classical finetuning often adopts tiny learning rates precisely because they limit how far parameters move from their pretrained values~[raffel2020exploring]. Although heuristic, this practice implicitly aims at preserving geometric relations encoded in weights.
* **Orthogonal Finetuning (OFT)** – Proposed by Qiu et al.~[qiu2023controlling], OFT introduces an explicit *orthogonality constraint*: each layer’s weights are updated via left multiplication by an learnable orthogonal matrix ${R}$. By virtue of Lemma 1 (the inner product preservation property), OFT guarantees exact preservation of every pairwise angle among neuron vectors.
* **Block–diagonal OFT** – To reduce storage cost one may restrict ${R}$ to block‑diagonal form (`diag(R₁,…,Rᵣ)` where each block $R_i$ acts on a small subspace). This yields far fewer trainable parameters ($O(b d)$ for block size $b$) at the expense of imposing an artificial grouping on dimensions—a sparsity pattern whose inductive bias may limit expressiveness.
* **Butterfly‑based Orthogonal Finetuning (BOFT)** – Building upon OFT’s geometric argumentation, BOFT replaces block diagonal sparsity with *butterfly factorization*. Inspired by fast Fourier transform graphs~[cooley1965algorithm], BOFT constructs ${R}$ as a product of $\log d$ sparse orthogonal components each having only $O(d)$ non­zero entries. This achieves parameter complexity $O(d\,log d)$ while still guaranteeing dense connectivity among all rows/columns—a much richer hypothesis space than block diagonal OFT.
* **Low‑rank additive schemes (e.g., LoRA)** – Although not explicitly framed around geometry preservation, rank-constrained additive methods implicitly alter angular relations because they introduce new directions into weight space without enforcing inner–product constancy.
* **Prompt tuning & adapters** – These families augment pretrained models rather than changing core matrices directly; consequently they largely bypass any direct alteration of neuron geometry inside existing layers.

All these approaches share a common motivation: keep *as much useful structure from pretraining as possible* while still providing enough flexibility for downstream specialization. Orthogonality offers one mathematically clean way to realize this goal—by rotating rather than reshaping—and recent advances such as BOFT demonstrate how careful structural design can reconcile geometry preservation with strict parameter budgets.


---  

In summary, treating each linear layer as a cloud of neuron vectors makes clear why their relative orientations matter for downstream performance. Pairwise angles encode essential relational knowledge; maintaining them helps keep hyperspherical energy low and stabilizes training. Orthogonal matrices naturally enforce angle preservation through norm- and inner‐product invariance; consequently multiplying pretrained weights by an orthogonal transform constitutes a *geometry‑preserving* update. Compared with additive schemes—which risk distorting these invariants—the multiplicative protocol enjoys strong theoretical guarantees at modest computational overhead when sparsity‐aware factorizations like block diagonal or butterfly structures are employed. The evolution from naïve OFT toward BOFT exemplifies how modern research leverages these geometric insights to devise parameter‑efficient finetuning strategies suitable for today’s ever larger foundation models.

Orthogonal Fine‑tuning (OFT): Formulation and Limitations  

# Formal Definition of Orthogonal Fine‑tuning  

The central idea behind Orthogonal Fine‑tuning (OFT) is to adapt a pretrained linear layer by left‑multiplying its weight matrix with a learnable **orthogonal** matrix.  Consider a pretrained linear transformation characterized by a weight matrix  
\[
\bm{W}^{0}\in\mathbb{R}^{d\times n},
\]  
which maps an input vector \(\bm{x}\in\mathbb{R}^{d}\) to an output vector \(\bm{z}\in\mathbb{R}^{n}\) via  
\[
\bm{z}= \bigl(\bm{W}^{0}\bigr)^{\!\top}\!\bm{x}.
\]  
In OFT we replace \(\bm{W}^{0}\) by a *finetuned* weight matrix \(\bm{W}'\) defined as  
\[
\boxed{\;\bm{W}' = \bm{R}\,\bm{W}^{0}\;}
\]  
where \(\bm{R}\in\mathbb{R}^{d\times d}\) is required to be **orthogonal**, i.e. \(\bm{R}^{\!\top}\!\bm{R}=\bm{I}_{d}\).  The forward pass under OFT therefore becomes  
\[
\bm{z}= \bigl(\bm{R}\,\bm{W}^{0}\bigr)^{\!\top}\!\bm{x}
      = (\bm{W}^{0})^{\!\top}\!\bm{R}^{\!\top}\!\bm{x}.
\]  

Why an orthogonal left transformation?  An orthogonal matrix corresponds geometrically to a rotation (or reflection) in \(\mathbb{R}^{d}\); it preserves inner products:
\[
(\bm{u},\,\bm{v}) = (\bm{Ru},\,\bm{Rv}) 
   \quad\text{for any }\;\bm{u},\,\bm{v} \in \mathbb R^{d}.
\]  
Consequently every **pairwise angle** between column vectors (“neurons”) of \(\bm W^0\) remains unchanged after multiplication by \(\bm R\).  Preserving these relational structures is motivated by the observation that pretrained foundations often encode knowledge through such geometric relationships; altering them excessively can degrade transferred performance.  By restricting finetuning to an orthogonal family we obtain an update rule that is *multiplicative* (rather than additive) yet guarantees that the transformed weight matrix stays on the same “manifold” as its pretrained counterpart.


# Ensuring Orthogonality During Training via the Cayley Transform  

Directly optimizing over the space of orthogonal matrices is difficult because arbitrary gradient steps will typically exit the manifold \(\mathcal O(d)=\{\bm R:\,\bm R^{\!\top}\!\bm R=\mathbf I_d\}\).  A classical way to enforce orthogonality while retaining unconstrained gradients is the **Cayley transform**.  

Let us introduce an auxiliary **skew‑symmetric** matrix \(\bm Q\in \mathbb R^{d\times d}\), i.e.
\[
\bm Q = -\,\bm Q^{\!\top}.
\]  
Given any such \(\bm Q,\) define  
\[
\boxed{\;\displaystyle 
   \bm R = (\mathbf I_d + \bm Q)\,(\mathbf I_d - \bm Q)^{-1}
   }                                              
   \tag{Cayley}
\]  
It can be verified algebraically that this construction yields an orthogonal matrix:
\[
\bigl[(\mathbf I+\!Q)(\mathbf I-\!Q)^{-1}\bigr]^{\!\top}
   (\mathbf I+\!Q)(\mathbf I-\!Q)^{-1}
   = \mathbf I_d .
\]  

During finetuning we treat the entries of \(\bm Q\) as **trainable parameters** without any further constraints—the skew‑symmetry can be enforced simply by maintaining only the strictly lower‑triangular part and negating it for the upper part.  The forward pass uses the derived orthogonal matrix \(\boldsymbol R(Q)\); gradients propagate back to the entries of \(Q,\) which are updated by standard stochastic gradient descent or Adam.  

A practical advantage of this scheme is **zero (identity) initialization**.  Setting all entries of \(Q\) initially to zero makes
\( \mathbf I_d + Q = \mathbf I_d - Q = \mathbf I_d,\)
so that \(R=\mathbf I_d.\) Consequently at step zero OFT reproduces exactly the pretrained model—a desirable property that encourages small updates and stabilises training.

A simple remedy introduced in the original OFT work is to **force a block‑diagonal sparsity pattern** on \(\boldsymbol R.\)

#### Inductive Bias Introduced by Block‑diagonal Structure  

The sparsity pattern forces each input dimension group to evolve **independently** from every other group.
Geometrically this means information cannot flow across blocks during finetuning:
the rotation performed on dimensions $[0,b)$ never mixes with those on $[b,2b)$, etc.
While this restriction yields dramatic savings in storage,
it also imposes an artificial partitioning based purely on coordinate indices—an ordering that has no semantic meaning in most neural networks.
Consequently some expressive transformations—most notably classic linear transforms such as discrete Fourier or Hadamard matrices which are fully dense—are unattainable within this constrained hypothesis class.


# Empirical Strengths of OFT (Generalizability) versus Its Inefficiency  

#### Generalization Benefits  

Empirical studies reported in the original OFT paper demonstrate several practical advantages:

* **Preservation of relational geometry** – Because every pairwise angle among neuron vectors stays constant under an orthogonal map, much of the semantic structure learned during pretraining remains intact after finetuning. This leads empirically to better transfer performance across tasks ranging from classification down‑stream tasks to controllable text‑to‑image generation.
* **Spectral stability** – Multiplying $\boldsymbol W^{0}$ from the left by an orthogonal $\boldsymbol R$ leaves the singular values unchanged:
  if $\boldsymbol W^{0}=U\,{\Sigma }\,V^{ᵀ}$ then
  $\boldsymbol W'=
      (\boldsymbol R U)\,\Sigma V^{ᵀ}$,
  so $\|\boldsymbol W'\|_2=\|\boldsymbol W^0|_2.$
  Maintaining the spectral norm improves optimisation stability and mitigates exploding/vanishing gradients—a phenomenon previously noted in spectral normalization literature.
* **Training convergence** – Experiments on diffusion models show faster convergence and reduced sensitivity to learning‐rate choice compared with additive low‑rank methods such as LoRA.


#### Parameter Inefficiency  

Despite these virtues, OFT suffers from two intertwined inefficiencies:

1. **Parameter explosion for dense rotations** – A completely unrestricted $\boldsymbol R$ lives in $\mathcal O(d^2)$ space; even storing its independent entries quickly exceeds practical GPU memory budgets when $d$ reaches several thousand.
   
2. **Expressivity–efficiency trade-off imposed by block diagonalization** – While block‐diagonal $\boldsymbol R$ reduces storage dramatically (${\cal O}(bd)$), it does so at the cost of severely limited inter‑dimensional communication.
   As noted above, many useful transforms—Fourier, cosine/sine bases—require mixing all input coordinates.
   Moreover, there is no principled method for choosing an optimal block size $b$: smaller blocks give fewer parameters but may cripple adaptation ability; larger blocks improve expressiveness yet erode parameter efficiency.
   
Thus practitioners are left with an unsatisfying dilemma:
*retain full expressivity → incur prohibitive cost,*  
or   
*drastically cut parameters → restrict representational power.*


# Motivating Question: Can a Dense Orthogonal Matrix Be Trained Efficiently?  

The observations above naturally lead us toward a central research question:

> **Is it possible to retain or even improve upon the expressive capacity granted by a *dense* orthogonal transformation while still enjoying *parameter–efficient* training?**

If such a construction existed,
it would combine OFT’s theoretical guarantees—angle preservation, spectral norm stability—and empirical benefits—Robust generalisation—with far lower storage costs akin to low–rank methods.
The remainder of this textbook will explore one concrete answer—*Orthogonal Butterfly* (BOFT)—which leverages factorisations inspired by butterfly graphs from fast Fourier transform algorithms.
By decomposing a dense orthogonal matrix into a product of *multiple sparse* orthogonal factors,
BOFT achieves an effective parameter scaling of $\mathcal O(d\,log\,d)$,
substantially below both naïve dense OFT (${\cal O}(d^2)$)
and even below bloc­k‑diagonal variants (${\cal O}(bd)$)
for modest choices of $b$.

In subsequent chapters we shall formalise this “information transmission” viewpoint,
detail how butterfly factorizations guarantee dense connectivity with few non‑zero elements,
and present extensive empirical evidence showing BOFT’s superiority across vision and language tasks.
The journey begins by recognizing that *the form* in which we store $\boldsymbol R$ matters far more than its mere *size*: carefully engineered sparsity patterns can convey all necessary information without overwhelming parameter budgets—a principle that underlies BOFT’s success.

**Information Transmission View on Sparse Orthogonal Factorizations**

# Motivation for an Information Transmission Perspective  

The central goal of *orthogonal finetuning* (OFT) is to adapt a pretrained linear layer while preserving the relational geometry encoded in its weight matrix.  Concretely, given a frozen pretrained weight matrix \(\mathbf{W}^{0}\in\mathbb{R}^{d\times n}\), OFT replaces it by the transformed matrix  
\[
\mathbf{W}=\mathbf{R}\,\mathbf{W}^{0},
\qquad 
\mathbf{R}\in\mathbb{R}^{d\times d},\;\;\mathbf{R}^{\!\top}\!\mathbf{R}=\mathbf{I}_{d},
\]  
so that every column vector (“neuron”) of \(\mathbf{W}^{0}\) undergoes the same orthogonal rotation \(\mathbf{R}\).  This rotation guarantees that all pairwise angles among neurons remain unchanged, thereby protecting the semantic knowledge obtained during pretraining.

Although this principle is theoretically appealing, directly learning an unrestricted dense orthogonal matrix \(\mathbf{R}\) would require \(\Theta(d^{2})\) trainable parameters—far too costly when \(d\) reaches several thousands as in modern vision transformers or large language models.  Early work therefore imposed a *block‑diagonal* pattern on \(\mathbf{R}\), partitioning its rows into \(r\) groups each transformed independently:
\[
\mathbf{R}= \operatorname*{diag}\bigl(\mathbf{R}_{1},\dots,\mathbf{R}_{r}\bigr), 
\qquad 
\mathbf{R}_{i}\in\mathbb{R}^{b\times b},\;\; br=d .
\]
While this reduces parameter count dramatically (\(\Theta(bd)\)), it also introduces an undesirable inductive bias: dimensions belonging to different blocks never exchange information during finetuning.  

A natural question arises: *Can we obtain a fully dense orthogonal transformation while still keeping the number of free parameters small?*  The answer emerges when we reinterpret the multiplication  
\[
\mathbf{R}= \mathbf{B}_{m}\,\mathbf{B}_{m-1}\cdots \mathbf{B}_{1}
\tag{1}
\]  
as an **information‑transmission process** on a layered graph.  By examining how sparsity patterns propagate through successive multiplications, we acquire a principled way to design factor matrices \(\{\mathbf B_i\}\) that achieve dense overall connectivity yet require few trainable entries.



# Mapping Matrix Products onto Multi‑Level Graphs  

Consider a product of \(m\) square matrices as in (1), each \(\mathbf B_i \in \mathbb R^{d\times d}\).  We associate this product with a *grid graph* consisting of \(m+1\) horizontal layers (or “levels”), numbered \(0,\dots,m\), where each layer contains \(d\) nodes indexed by \(1,\dots,d\).  The nodes at level \(i-1\) represent the input dimensions before applying \(\mathbf B_i\); those at level \(i\) represent intermediate dimensions after application of that factor.

Formally, let us denote by \(b_{ij}^{(k)}\) the entry in row \(i\), column \(j\) of factor \(\mathbf B_{k}\).  A non‑zero entry (\(b_{ij}^{(k)} \neq 0\)) creates a **directed edge** from node \(j\) at level \(k-1\) to node \(i\) at level \(k\).  In this way each factor defines an adjacency matrix between two consecutive levels:
\[
A^{(k)} = (\ldots , b_{ij}^{(k)} , \ldots)\in \mathbb R^{d\times d}.
\]
The overall product (1) corresponds exactly to composing these adjacency relations along directed paths that traverse successive levels.  Consequently,
the entry \(r_{pq}\) of the final matrix \(\mathbf R=\prod_k \mathbf B_k\) is non‑zero **iff** there exists at least one directed path from node \(q\) in level 0 to node \(p\) in level \(m\).  This observation translates algebraic sparsity into combinatorial reachability.



# Nodes, Levels, Edges: Interpreting Non‑Zero Entries as Communication Links  

From the viewpoint just described:

| Element | Graph Interpretation |
|--------|----------------------|
| A node            | One coordinate (dimension) of a vector at a specific stage of multiplication |
| A level           | A stage between successive factors – there are exactly \(m+1\) levels |
| A directed edge   | A permissible linear combination enabled by a non‑zero entry in some factor |
| A path            | A chain of multiplications that moves information from an input coordinate to an output coordinate |
| Reachability      | Determines whether an output entry can be influenced by a given input entry |

If we think of each vector component as a “message” that needs to be relayed across stages, then every non‑zero entry functions as a communication link capable of transmitting that message forward one step. The topology induced by all factors simultaneously determines which messages can ultimately reach which destinations after all stages have been applied.



# Dense Connectivity Requirement for Full‑Rank Transformation  

A *dense* orthogonal matrix has no zero entries; equivalently, every output dimension may depend on every input dimension. In our graph picture this translates into the following **dense‑connectivity** requirement:

> **Requirement (i):** For any pair of nodes \((q,p)\), where \(q\) lies on the source level 0 and \(p\) lies on the sink level \(m,\) there must exist *at least one* directed path from \(q\) to \(p.\)

If this condition holds then every entry \(r_{pq}\neq0.\) Moreover, because each intermediate factor is constrained to be *orthogonal*, every intermediate mapping is invertible; thus any collection of paths satisfying Requirement (i) also ensures that the overall transformation has full rank (\(=d.\)). In practice this condition prevents “isolated” groups such as those produced by block‑diagonal sparsity—their graph consists of several disconnected sub‑graphs so many source–sink pairs have no connecting path.



# Minimal Free Edges under Orthogonality Constraints  

Even when Requirement (i) is satisfied, we want to keep the total number \(E_{\text{free}}\) of *trainable* non‑zero entries as low as possible. Not all non‑zeros contribute independent degrees of freedom because **orthogonality** imposes strong algebraic dependencies:

* For any single factor \(\mathbf B_k,\) being orthogonal means its columns form an orthonormal basis. Consequently each column must contain exactly one unit norm element along with possibly additional values that satisfy mutually perpendicular constraints.
* In particular, any full‑rank square orthogonal matrix must induce a **bijection** between its input nodes and output nodes—a permutation behavior when viewed only through support (positions where entries may be non‑zero). Thus each factor requires at least \(d:\)" one edge per output node" to maintain bijectivity.
* These mandatory edges are *forced*: their values are determined up to sign (\(\pm1)\); therefore they do not consume trainable parameters.
* Remaining non‑zeros—the **free edges**—are those whose magnitudes are free variables subject only to the global orthogonality condition across all factors. Minimizing \(E_{\text{free}}\)
corresponds directly to reducing parameter count while preserving expressive power.

Hence our second desideratum becomes:

> **Requirement (ii):** The total number \(E_{\text {free}}\)
of freely learnable edges across all levels should be **minimal** while still guaranteeing Requirement (i).

A naïve solution would place all possible edges at every layer producing a single dense factor (\(E_{\text {free}}=d^{2}-d)\), which respects Requirement (i) but violates Requirement (ii); its parameter budget scales quadratically as \(\Theta(d^{2}) .​


# Graphical Comparison Between Block‑Diagonal Sparsity and Potential Alternatives  

### Block–Diagonal Structure  

In the original OFT formulation the orthogonal matrix takes a block‐diagonal form:
\[
   \mathbf R_{\text {blk}} = 
   {\rm diag}(\underbrace{\mathbf R_{1}}_{b\times b},
                \underbrace{\mathbf R_{2}}_{b\times b},
               \,\,\,…,\,\,\, 
                \underbrace{\mathbf R_{r}}_{b\times b}),
   \quad br=d .
}
In graph terms this corresponds precisely to **\(r$ isolated sub‑graphs**, each containing only the $b$ nodes belonging to one block.
Edges exist solely within each sub‑graph; there are no connections crossing between different blocks at any stage.
Consequently many source–sink pairs belong to different blocks and have no directed path connecting them.
The resulting adjacency pattern fails Requirement (i): most pairs $(q,p)$ lie in disjoint components → zero entries remain permanently zero.
Even though each individual block can be made orthogonal with only $\tfrac12 b(b-1)$ trainable parameters,
the overall transformation is far from dense; expressivity suffers dramatically.


### Dense Single Factor  

Placing all information into one dense factor $\mathbf B_1=\mathbf R_{\text {dense}}$
creates exactly one layer ($m=1$).  
Every source vertex connects directly to every sink vertex,
so Requirement (i) holds trivially.
However $E_{\text {free}} = d^{2}-d$, i.e., almost all $d^{2}$ possible
edges become independent learnable parameters.
The parameter budget scales quadratically,
rendering this option impractical for large models.


### Butterfly Factorizations  

A striking compromise comes from adopting **butterfly factorizations**, originally studied in the Cooley–Tukey FFT algorithm.
When $d=2^{N}$,
a butterfly factorization expresses $\mathbf R$ as
a product
$\displaystyle 
    \mathbf R_{\text {bf}} = 
    \tilde{\mathbf B}(d,k_N)\,
    \tilde{\mathbf B}(d,k_{N-1})\, 
    \dots\, 
    \tilde{\mathbf B}(d,k_1),
$
where each intermediate component $\tilde{\mathbf B}(d,k_i)$ is block‐diagonal with block size~$k_i$,
and adjacent components are permuted relative
to one another so that information continually mixes across blocks.
In graph language,

* Each layer still contains exactly $d$ mandatory bijective edges,
corresponding essentially either to identity or signed permutations;
these do **not** contribute trainable variables.
* The additional learnable degrees arise from within-block rotations (e.g., $2\times2$ rotation matrices).
There are only $\frac12(b-1)d$ learnable scalars per component when using block size $b$,   
so after $\log_2 d$ components we obtain
\[   
    E_{\text {free}}
    = O(d\,\<log_2 d\<),
    % ~roughly~ 
    % perhaps multiplied by constant proportional 
    %   depending on chosen block size b
        .
   }
Consequently Requirement (ii)—minimal free edges—is satisfied up
to logarithmic overhead.
Nevertheless because successive permutations ensure that during
the $\log_2 d$ stages every input dimension eventually meets every
output dimension via distinct paths,
Requirement (i)—dense connectivity—is also fulfilled.
Hence butterfly factorizations deliver exactly what standard OFT’s block diagonal approach lacks:
a **dense** overall transformation together with **parameter efficiency** scaling near linearly rather than quadratically.


### Visual Metaphor  

Imagine arranging eight source nodes horizontally atop column 0,
and eight sink nodes below them at column 5.
A block‐diagonal design draws three vertical stacks:
each stack links three source nodes exclusively among themselves—
the walkers never cross stacks—so many destinations remain unreachable.
Conversely,
a butterfly design first couples adjacent pairs,
then couples resulting groups across larger spans,
and finally mixes everything globally;
the walker’s trajectory zigzags akin to how data spreads through an FFT computation tree,
reaching every destination after just three mixing stages.


# Summary  

Recasting sparse orthogonal factorizations as information transmission over layered grid graphs brings two powerful insights:

1. **Dense Connectivity:** An effective finetuning transform must enable every source dimension eventually influencing every target dimension—a purely graph‐theoretic condition corresponding algebraically to a fully dense final matrix.
2. **Parameter Economy:** Orthogonality forces each intermediate layer's adjacency matrix into a bijective pattern; therefore only *extra* off‐bijective edges count toward learnable parameters. Minimizing these “free” edges yields $\mathcal O(d)$ or $\mathcal O(d\,\<log\:d\<)$ parameter budgets rather than $\mathcal O(d^{2})$.

The prevailing block‐diagonal scheme fulfills neither criterion simultaneously—it preserves cheap parametrization but sacrifices global mixing—whereas butterfly factorizations satisfy both by exploiting hierarchical permutations over multiple sparse layers.
This graph–theoretic lens therefore motivates **Orthogonal Butterfly** finetuning (BOFT), wherein an entire dense orthogonal rotation is constructed from $\log_2 d$ sparse components whose learnable degrees scale only linearly with model width.
Understanding these desiderata equips us with a systematic foundation for designing new sparse factorizations beyond butterflies—any topology meeting Requirements (i) and (ii)
will inherit similar benefits in terms of expressivity, stability and training efficiency.

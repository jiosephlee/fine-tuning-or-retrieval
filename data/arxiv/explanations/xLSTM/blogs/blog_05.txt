# Inside an xLSTM Block: Residual Backbones Without the Attention Tax

xLSTM revisits the LSTM idea with two key extensions — exponential gating and richer memory structures — then plugs those into familiar residual backbones to produce models that compete with modern Transformers and State Space Models without paying the quadratic attention cost. This post drills into the design of an xLSTM block: what it does, why the block uses a pre- or post-up-projection path, and how stacking those blocks yields a full xLSTM architecture that summarizes history efficiently and scales well.

## The design goal: make past context more linearly separable

A central motivation behind the xLSTM block is to produce representations of past context that are easier to separate downstream. Intuitively, if different histories map to representations that are more linearly separable, a simple readout can correctly predict the next token. xLSTM leans on the same intuition as Cover’s theorem: nonlinearly embedding inputs into a higher-dimensional space increases the chance that different patterns (histories) become linearly separable.

Practically, an xLSTM block is a small residual module that (a) summarizes past context nonlinearly, (b) temporarily lifts that summary into a higher-dimensional space, and (c) projects back to the model space. The order of those steps — whether you up-project before the nonlinear summary or after — is an architectural choice with implications for where you want the memory to live.

## Two block styles: pre up-projection and post up-projection

xLSTM uses two residual block styles that mirror designs in contemporary LLMs and recent sequence models:

- Post up-projection (used with sLSTM): the block first performs a nonlinear summarization in the model’s native dimensionality, then up-projects to a higher-dimensional space, applies an activation, and projects back down. This is conceptually similar to Transformer feed-forward blocks that summarize and then expand/contract. The post-up route is a good fit for sLSTM (the scalar-memory variant with memory mixing) because sLSTM’s strengths are in mixing and refining scalar cell memories; the nonlinear summarization before the up-projection is where that mixing is most effective.

- Pre up-projection (used with mLSTM): here, inputs are first linearly mapped into a higher-dimensional space, then the nonlinear summarization (the memory update and readout) happens in that expanded space, and the result is projected back. This path is preferable for mLSTM, which uses a matrix memory; giving the memory operations the higher-dimensional workspace increases effective capacity and lets retrieval (matrix-by-vector) operate where it has the most room to store and separate many key–value interactions.

The paper uses post up-projection blocks for sLSTM-based xLSTM blocks and pre up-projection blocks for mLSTM-based ones, leveraging where each memory type benefits most from extra dimensionality.

## What an xLSTM block actually contains (conceptually)

An xLSTM block is a residual unit composed of these building pieces:

- A pre-LayerNorm on inputs (the same normalization pattern used in many modern LLMs) to stabilize training.
- A small projection network that either lifts inputs into a higher-dimensional space (pre-up) or applies a nonlinear summary first and then lifts (post-up).
- A memory module (an sLSTM or an mLSTM) that performs the time-recursive update and readout:
  - sLSTM: scalar memory cells with exponential gates and a normalizer state; supports memory mixing via recurrent connections (hidden-to-hidden).
  - mLSTM: matrix memory that stores key–value outer products (a covariance-style update). It uses exponential input gating as a learned write rate and a forget gate as a decay; retrieval is matrix-vector multiplication normalized by the accumulated key strength.
- A projection back to model space followed by adding the block’s residual (skip) connection.

That residual structure means each block learns a refined incremental update to the representation of history; stacking many such blocks makes the model progressively richer while retaining the advantages of residual optimization.

## Why exponential gates and where memory mixing matters

xLSTM departs from classic LSTM gating by allowing exponential activations for some gates (stabilized by additional bookkeeping states). Exponential gates let the model revise storage decisions more sharply: a newly written item can be amplified or attenuated relative to past contents in a multiplicative way that is more expressive than the standard sigmoid gating.

Memory mixing — i.e., hidden-to-cell recurrent connections across cells — remains available in sLSTM and is important for state-tracking tasks that require sequential adjustments to internal state. This capability is what lets sLSTM-based blocks solve tasks dependent on tracking histories (something purely feed-forward or memoryless attention approximations cannot do as easily).

mLSTM, by contrast, intentionally abandons memory mixing so it can be implemented in a fully parallel (scan-free) manner. The matrix memory plus covariance-style updates produce a compressive associative store that is highly expressive for key–value retrieval, while staying linear in sequence length because updates and reads are incremental and do not require quadratic pairwise token comparisons.

## Stacking blocks into xLSTM architectures

Full xLSTM models are assembled by residually stacking many xLSTM blocks, following the common pre-LayerNorm residual backbone used across modern LLMs. Blocks can be homogeneous or mixed: the paper reports hybrids (e.g., mostly mLSTM blocks with a few sLSTM blocks) so the architecture benefits from both large associative memory capacity (mLSTM) and the state-tracking/mixing power of sLSTM.

Because each block compressively summarizes history, the stack builds a progressively more separable representation of longer histories. This leads to several practical outcomes the paper emphasizes:

- Linear computation and constant working memory with respect to sequence length — a major difference to attention-based models whose attention cost is quadratic in context size.
- Competitive scaling behavior: when scaled and trained on modern corpora, xLSTM variants match or outperform many Transformer and SSM baselines in language modeling.
- Better extrapolation to longer context lengths in tests reported in the paper, attributed to the compressive, associative memory and the block-wise separability improvements.

## Practical trade-offs and where each block style is used

- mLSTM-based blocks are parallelizable and well suited for large-scale training when you want associative, matrix-based memory with high capacity. Put these in pre up-projection blocks so the memory lives and operates in the expanded space.
- sLSTM-based blocks keep memory mixing and the constant-error-carousel tradition of LSTMs; they excel at explicit sequence state tracking. Use post up-projection blocks for sLSTM so the hidden mixing happens before you lift into the higher-dimensional activation space.
- Hybrids mix both: relying mainly on mLSTM blocks for capacity and inserting sLSTM blocks where local state mixing is critical.

## Takeaway

An xLSTM block is a deliberately engineered residual cell: normalize, (optionally) lift dimensionality, nonlinearly summarize and update a memory, then project back and add the residual. The pre/post up-projection decision is not cosmetic — it reflects whether the memory should operate in the model’s native space (sLSTM) or in an expanded workspace (mLSTM). Stacking these blocks yields architectures that keep the linear memory and compute advantage of recurrent/association mechanisms while gaining much of the separability and representational power that large Transformer stacks achieve — without the quadratic attention tax.

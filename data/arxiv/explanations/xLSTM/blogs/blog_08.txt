\title{Blogs about the Paper: xLSTM}

# Where xLSTM Fits in the Model Zoo: RWKV, Mamba, Retention, and Beyond

## Overview

xLSTM is a modern redesign of the classic LSTM family that aims to bring recurrent memory models into parity with contemporary sequence learners. The paper introduces two concrete variants: sLSTM (scalar memory with exponential gating and new memory mixing) and mLSTM (matrix memory with a covariance update), and integrates them into residual block backbones to form full xLSTM architectures. The two central innovations are (1) exponential gating with stabilization and a normalizer state, and (2) a matrix memory that stores key–value outer products (covariance updates). These changes target three traditional LSTM limitations: inability to revise storage decisions, limited storage capacity of scalar cells, and lack of parallelizability.

Below I position xLSTM relative to the major families of recent sequence models (Transformers, State Space Models, RWKV-like RNNs, Retention / Fast-Weight models, and linear-attention methods like Performer/Linear Transformer), summarize where xLSTM overlaps conceptually with them, and give a practical guide to when xLSTM is a good choice versus alternatives — all grounded in the results and claims from the paper.

## Core ideas of xLSTM (quick recap)

- Exponential gating: input gates (and optionally forget gates) use an exponential activation, i.e.  
  i_t = \exp(\tilde{i}_t), and f_t can be \sigma(\tilde{f}_t) or \exp(\tilde{f}_t). Because exponentials can blow up, xLSTM introduces a stabilizer state m_t and uses normalized gates i'_t, f'_t that preserve exact forward outputs and gradients while avoiding overflow.
- Normalizer state: accumulates the weighted sum of gate coefficients (scalar case) or of keys (matrix case) to normalize retrievals and to keep track of effective stored mass across future forget gates.
- sLSTM: keeps scalar (or low-dimensional vector) cells but uses exponential gating plus a new memory-mixing pattern (including multi-heads and per-head mixing) to enable stronger state-tracking and revisable storage behavior.
- mLSTM: replaces scalar cell c with a matrix memory C \in \mathbb{R}^{d\times d} and updates it with a covariance (outer-product) rule C_t = f_t C_{t-1} + i_t v_t k_t^\top. Retrieval is via C_t q_t, normalized by |\mathbf{n}_t^\top q_t| (clamped lower bound) and gated by an output gate. This is equivalent in spirit to Fast Weight / associative memory updates.

## Conceptual overlaps

- Gating family (shared idea): Many recent models reuse gating concepts. xLSTM continues this tradition; gating plays the same structural role as in HGRN, GLA, GSS/BiGS, RWKV, and Mamba. The paper’s ablations emphasize that learnable, input-conditioned gates provide incremental gains.
- Covariance / fast-weight updates: mLSTM’s matrix memory and outer-product update are conceptually aligned with Fast Weight Programmers, Retention, certain RWKV variants, and other approaches that use associative updates (e.g., some linear-attention formulations). The covariance update rule in mLSTM is the classical v k^\top construction used by these methods.
- Linear-in-context complexity: Like many RNNs, SSMs, and linear-attention variants, xLSTM’s recurrent formulation has computation and memory that scale linearly in sequence length, and its memory state is constant with respect to context length. The paper places xLSTM with other linear or linearizable methods in that regard.

## Crucial differences (what xLSTM brings uniquely)

- Exponential gating with memory mixing (sLSTM): The exponential gate plus a dedicated normalizer and stabilizer state is a distinct element that directly addresses the “revise storage decisions” limitation. The paper demonstrates that classic LSTMs fail at tasks like nearest-neighbor search where an earlier stored value must be revised when a better match appears; sLSTM with exponential gating can revise storage because the multiplicative chain of future forgets and exponential inputs can be normalized to allow proper replacement.
- Matrix memory with normalized retrieval (mLSTM): Rather than using attention's pairwise querying over stored tokens, mLSTM stores compressed associative memory via \mathbf{C}_t and retrieves via matrix–vector multiplication \mathbf{C}_t \mathbf{q}_t, normalized by the dot with the normalizer state. This increases storage capacity beyond scalar cells while remaining conceptually simple and parameter-free for the memory updates.
- Memory mixing vs. fully parallelizable recurrence: sLSTM preserves memory mixing (hidden–hidden recurrent weights) to enable state-tracking tasks that require mixing across memory cells, which Transformers and many SSMs struggle with. mLSTM, by contrast, drops hidden–hidden mixing to enable a fully parallel (scan-free) formulation akin to FlashAttention-style parallelism. Thus xLSTM provides two complementary trade-offs in the same family: expressive recurrent mixing (sLSTM) and parallel, high-capacity associative memory (mLSTM).
- Normalizer state and stabilizers: The explicit normalizer that accumulates gate-weighted keys (or gate weight sums in the scalar case) and the numerical stabilization rules for exponential gates are implementation-level innovations that preserve meaningful gradients while enabling exponentials.

## Empirical behavior (claims from the paper)

- Synthetic and diagnostic tasks: sLSTM’s exponential gating + mixing solves formal-language/state-tracking tasks that Transformers/SSMs cannot, highlighting the importance of memory mixing for state-tracking. On associative-recall tasks (many key-value pairs and long contexts), mLSTM-based xLSTMs perform best among non-Transformer methods and allow extrapolation to longer contexts.
- Language modeling (SlimPajama experiments): When trained on 15B tokens, xLSTM models outperform a range of baselines (Transformers like Llama, SSMs like Mamba/H3, and RNNs like RWKV variants) in validation perplexity. With larger 300B-token training runs, xLSTM maintains favorable perplexities, better long-context extrapolation, and competitive downstream task performance; scaling laws suggest xLSTM should remain competitive at larger sizes.
- Efficiency trade-offs: mLSTM is parallelizable and has constant memory with respect to context length but is computationally heavier per step due to d\times d matrices. sLSTM keeps memory mixing (expressivity) but cannot be fully parallelized; a specialized CUDA kernel reduces the speed gap to mLSTM to less than 2x in the authors’ implementation. Compared to Transformers, xLSTM’s recurrent or associative-memory nature yields linear scaling in context length (better memory usage and higher throughput for large batch sizes).

## Practical buyer’s guide — when to favor xLSTM

Use xLSTM (sLSTM- or mLSTM-driven) when any of the following apply:

- You need state-tracking or revisable storage. If the task requires maintaining and updating internal state (e.g., program evaluation, entity tracking, formal grammars), sLSTM’s memory-mixing plus exponential gating is specifically designed for such problems and outperforms models that lack recurrent mixing.
- You want improved storage capacity compared to scalar-cell RNNs but want to avoid attention’s quadratic memory in context length. mLSTM’s matrix memory increases capacity via associative outer-product updates while keeping memory constant in sequence length.
- You need better long-context extrapolation than standard Transformers or SSMs: experiments show xLSTM maintains lower perplexities when extrapolating to much longer contexts than seen at training time.
- You need a model with linear memory w.r.t. sequence length for large batch decoding and high throughput. Because the recurrent memory state is independent of context length, xLSTM can use much larger batch sizes and achieve higher decoding throughput than Transformers with KV caches.
- You prefer an architecture that empirically scales well (per the paper’s scaling-law analysis) and can compete with Transformer and SSM baselines at both 15B-token and 300B-token regimes.

When to prefer alternatives

- Transformer (attention) if your primary concern is maximal parallel throughput for typical transformer-optimized inference stacks and you rely heavily on very large, highly optimized tooling for attention (or you need the exact inductive biases of self-attention). Transformers still offer very efficient, heavily optimized inference kernels and are the dominant engineering stack.
- State Space Models (SSMs) / Mamba if you want a linear-in-context, highly parallel model with strong empirical performance and simpler per-step computations; SSMs are lightweight and often simpler to optimize from a compute-efficiency perspective.
- RWKV and other RNN variants if you need very simple, linear recurrence with low per-step cost and are already committed to RWKV-style implementations; however, according to the paper, xLSTM outperforms RWKV variants on perplexity and long-context extrapolation in their experiments.
- Attention or linear-attention methods for tasks that fundamentally rely on pairwise comparisons across the whole context where Transformers’ implicit exponential memory in coding dimension is an advantage (the paper shows Transformers remain gold-standard on extreme associative recall tasks with many key-value pairs due to their exponential memory in coding dimension).

## Implementation and cost considerations

- mLSTM increases per-step computation because of d\times d memory matrices and updates. These matrices are parameter-free (the update uses outer products of projected inputs), but the runtime cost is non-trivial; the authors note their current mLSTM CUDA kernels are not yet as optimized as FlashAttention and are roughly 4x slower in their implementation.
- sLSTM retains recurrent mixing (hidden–hidden connections) and cannot be trivially parallelized across time, but a specialized CUDA kernel made by the authors achieves near-parallel runtimes (within about 2x of mLSTM in their experiments).
- Numerical care is required: exponential gates must be stabilized (m_t stabilizer) and forget gate initializations need tunings. The authors highlight sensitivity to forget gate initialization and the need for careful stabilization to avoid overflow.
- Memory trade-offs: mLSTM’s memory capacity is independent of sequence length but scales with d^2. For very large d this can become heavy; this is an explicit trade-off between capacity and compute.

## Final takeaway

xLSTM is not just another gated RNN: it combines two orthogonal, practical changes that address longstanding LSTM limitations. Exponential gating with a normalizer enables revisable, well-conditioned storage decisions and stronger state tracking (sLSTM), while a matrix covariance memory (mLSTM) gives associative, parallelizable storage with higher capacity than scalar cells. Empirically, xLSTM closes the gap to Transformers and SSMs in language modeling and exhibits favorable scaling and extrapolation behavior.

If your problem requires strong state-tracking, revisable memory, or efficient long-context inference with linear memory cost, xLSTM deserves serious consideration. If your stack depends on heavily optimized Transformer kernels or your use case benefits from attention’s particular inductive biases, Transformers or tuned SSMs may still be preferable. The most pragmatic approach is to weigh the need for memory mixing and associative capacity against the compute cost of d\times d updates and the current state of available kernels — the paper shows that xLSTM can be a competitive middle ground in many real-world sequence-modeling settings.

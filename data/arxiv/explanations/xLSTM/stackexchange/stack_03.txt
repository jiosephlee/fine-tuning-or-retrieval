\title{Stack Exchange of the Paper: xLSTM}

### What is the precise effect of choosing f_t as sigmoid versus exponential in sLSTM and mLSTM?
Question:
Both sLSTM and mLSTM allow f_t to be either \sigma(\tilde{f}_t) or \exp(\tilde{f}_t). I am confused about:
- With f_t = \sigma(\tilde{f}_t) \in (0,1), we have a conventional decay. With f_t = \exp(\tilde{f}_t) > 0, f_t can be > 1, which seems to amplify older memory. When is amplification desirable versus harmful?
- How do the authors keep the product of forget gates stable when using exponentials, especially over long sequences?
- Are there recommended initializations/biases for \tilde{f}_t in the exponential case so that the effective time constant is reasonable? Any rules of thumb relating E[f_t] to an intended memory horizon?
Answer:
Short answer: using a sigmoid forget gate constrains per-step decay to $(0,1)$ so the cell state monotonically attenuates older contributions; using an exponential forget gate lets the per-step multiplier be any positive number (including $>1$) so old contributions can be amplified. Exponential gating enables the new behaviors in xLSTM (ability to revise stored values, covariance-style memory scaling, and improved associative capacity) but must be paired with the paper’s normalization/stabilization machinery (the normalizer $n_t$, the stabilizer $m_t$ / log-sum-exp, value normalization and lower-bounds) to avoid numerical blow-up or runaway amplification. Below I explain the intuition, how the authors keep products stable, and practical rules-of-thumb for initializing $\tilde f_t$ so the effective memory horizon matches your intent.

1) Intuition: sigmoid versus exp
- $f_t = \sigma(\tilde f_t)$ (sigmoid) lives in $(0,1)$. If you treat the homogeneous update $c_t = f_t c_{t-1} + i_t z_t$ with roughly constant $f$, contributions from time $t_0$ decay geometrically as $f^{t - t_0}$. This is the conventional “forget / decay” behavior: older memory is attenuated and never amplified.
- $f_t = \exp(\tilde f_t)$ (exponential) is strictly positive and can be $>1$. If $\tilde f_t > 0$ then $\exp(\tilde f_t) > 1$ and a past contribution can grow when multiplied repeatedly by such gates. That extra degree of freedom gives the model the capacity to “re-weight” or amplify older content when evidence later in the sequence indicates it should be emphasized (this is precisely what the paper uses to improve state-tracking / revision abilities).

When is amplification desirable vs harmful?
- Desirable: tasks that require revising earlier storage or boosting selected past signals (e.g., nearest-neighbor search or state-tracking where a later observation should retroactively strengthen a stored representation). Amplification lets the network implement multiplicative attention-like re-weighting across time without having to re-scan the whole sequence.
- Harmful: uncontrolled amplification will blow up internal activations, produce numerical overflow, and amplify noise (worse signal-to-noise for associative retrieval). Without normalization it also destabilizes gradients and training.

2) How the paper keeps long products stable
The paper pairs exponential gating with two main mechanisms that make repeated products safe and well-behaved.

First, a normalizer state $n_t$ that tracks the total gate-weight mass: for sLSTM/mLSTM they keep
$n_t = f_t n_{t-1} + i_t$ (scalar or vector). The hidden output uses a normalized quantity: for sLSTM $\tilde h_t = c_t / n_t$, and for mLSTM $\tilde h_t = C_t q_t / \max(|n_t^\top q_t|, 1)$. This division cancels common multiplicative growth across $c_t$ and $n_t$ so that multiplying both numerator and denominator by a large factor leaves their ratio stable. In other words, the normalizer keeps the effective retrieved value bounded even if intermediate cell entries grow.

Second, an explicit stabilizer $m_t$ based on log-sum-exp keeps exponentials numerically stable. The implementation rewrites and rescales the exponential gates via
$m_t = \max(\log f_t + m_{t-1}, \log i_t)$
and then replaces $i_t$ and $f_t$ by scaled versions
$i'_t = \exp(\tilde i_t - m_t),\quad f'_t = \exp(\log f_t + m_{t-1} - m_t).$
This is equivalent algebraically (it does not change network outputs or gradients) but avoids huge numbers by maintaining them in log-space and removing common factors. The paper cites Milakov et al. for this stabilization; essentially it’s numerically identical to doing computations in log-space and subtracting a running max (a standard log-sum-exp trick).

Other safety measures in the paper include layer-normalizing inputs to keys/queries (so keys have zero mean and controlled scale), using the absolute dot-product and a lower-bound ($\max\{|\mathbf{n}_t^\top \mathbf{q}_t|, 1\}$) in mLSTM retrieval to avoid division by tiny denominators, and optional clipping/thresholds that prevent tiny denominators from producing huge outputs.

Put differently: exponential gates give extra representational power, and the combination of (i) normalizer division, (ii) log-sum-exp stabilizer $m_t$, (iii) input normalization, and (iv) lower-bounding the denominator in retrieval keep long products numerically and statistically stable.

3) Initialization / bias choices and a rule-of-thumb mapping to memory horizon
The paper explicitly notes that “the initialization of the forget gates must be chosen carefully” (Limitations), but does not prescribe a single universal bias. You can, however, use a principled mapping between an intended per-step decay/amplification and the initial bias $\tilde f$ bias:

- If you want a target constant per-step multiplier $\bar f$ (so contributions decay as $\bar f^{\tau}$ with $\tau$ steps), then for the exponential case set the forget pre-activation bias $b_f$ so that $\mathbb{E}[f_t] \approx \bar f$. With $f_t = \exp(\tilde f_t)$, and if $\tilde f_t$ is dominated by a bias, simply set
$b_f \approx \log(\bar f)$.
For example, a desired per-step decay of half in $T$ steps corresponds to $\bar f = 2^{-1/T} = \exp(-(\log 2)/T)$, so set $b_f \approx -(\log 2)/T$.

- For the sigmoid case, because $f_t = \sigma(\tilde f_t)$, approximate $\sigma(\mu) \approx \bar f$ and invert to get the bias $\mu \approx \operatorname{logit}(\bar f) = \log\bigl(\bar f / (1-\bar f)\bigr)$. That is less convenient if you want small exponential decays (sigmoid cannot represent values $>1$ and its mapping to time constants is coarser).

A useful rule of thumb: think in terms of an effective time constant $\tau$ such that after $\tau$ steps a contribution is reduced by a factor of $e$ (or $1/2$). If you want an exponential per-step multiplier $\bar f$ satisfying $\bar f^\tau \approx e^{-1}$ then $\bar f \approx e^{-1/\tau}$. So pick $b_f \approx \log(\bar f) = -1/\tau$. Similarly, for a half-life $T_{1/2}$, set $b_f \approx -\log 2 / T_{1/2}$.

Examples:
- To have an effective time constant $\tau = 100$ steps (i.e., substantial memory for ~100 tokens), set $b_f \approx -0.01$ (since $-1/100 = -0.01$), so $\exp(b_f) \approx 0.99$.
- For a very long memory (e.g., $\tau = 1000$), set $b_f \approx -0.001$.

Some practical considerations and heuristics from the paper’s approach and experiments:
- Start biases slightly negative (so initial $f$ is slightly $<1$) rather than positive; even for exponential gating you typically want mild decay initially to avoid blow-up. The paper’s Limitations warns about careful initialization.
- Use layer-norms and small initial weight scales for gate inputs so the bias controls the mean gate behavior at the start of training.
- Monitor scales of $c_t$ and $n_t$ in early training runs; if normalized outputs are stable but gradients vanish, move bias towards less decay; if magnitudes blow up, increase negative bias (stronger decay) or tighten stabilizer.
- For mLSTM retrieval, the paper’s use of $\max\{|\mathbf{n}_t^\top \mathbf{q}_t|, 1\}$ ensures that very small normalizers don’t explode the final ratio. If you use different thresholds, you must adjust biases accordingly.

4) Summary: when to pick which gate function
If you want a conservative, always-damping cell that never multiplies older memory up, use sigmoid $f_t$. Use exponential $f_t$ when you want the model to be able to multiplicatively re-weight (including amplify) earlier stored information; this is where xLSTM gains its ability to revise and strengthen memories. But whenever you use exponential gating you must also use the normalizer $n_t$ and the log-space stabilizer $m_t$ (and input normalization / denominator bounding) exactly as the paper prescribes to avoid instability. Finally, choose initial biases so that the expected per-step multiplier matches a desired time-constant via the simple mapping $b_f \approx \log(\bar f)$ for the exponential case (or $b_f \approx \operatorname{logit}(\bar f)$ for sigmoid).

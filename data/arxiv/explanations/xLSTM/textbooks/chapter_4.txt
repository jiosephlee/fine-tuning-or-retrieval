\title{A Textbook about the Paper: xLSTM}

Chapter 4: Exponential Gating, Normalization, and Stabilization

# Exponential input and forget gates: definitions and intuition

xLSTM replaces the standard sigmoid gates of the classical LSTM with exponential gates for at least some of the control signals, most importantly the input gate. Concretely, in the scalar sLSTM formulation the input gate is defined as
\[
i_t \;=\; \exp\!\left(\tilde{i}_t\right),\qquad
\tilde{i}_t \;=\; \mathbf{w}_i^\top \mathbf{x}_t + r_i h_{t-1} + b_i,
\]
while the forget gate may be either the conventional sigmoid
\[
f_t \;=\; \sigma(\tilde{f}_t)
\]
or an exponential
\[
f_t \;=\; \exp(\tilde{f}_t),\qquad
\tilde{f}_t \;=\; \mathbf{w}_f^\top \mathbf{x}_t + r_f h_{t-1} + b_f.
\]
These definitions appear in the sLSTM forward equations:
\[
\begin{aligned}
c_t &= f_t c_{t-1} + i_t z_t,\\
n_t &= f_t n_{t-1} + i_t,\\
h_t &= o_t \,\tilde h_t,\qquad \tilde h_t = c_t / n_t,
\end{aligned}
\]
with $z_t$ the cell input and $o_t$ the output gate (see Equation (2) in the paper).

Intuitively, replacing a sigmoid by an exponential changes the role of the gate from a bounded attenuator to a positive multiplicative factor with unbounded (but stabilized) dynamic range. A sigmoid gate is constrained to lie in $(0,1)$ and can only attenuate stored quantities (it cannot amplify). In contrast, an exponential gate yields a strictly positive scalar that can be much larger than one or much smaller than one, depending on its pre-activation. This expanded range lets the model multiply past contributions by factors greater than one or less than one, giving it a much richer set of ways to revise how previous inputs contribute to the current state.

Operationally, with exponential gating the memory update becomes a weighted sum with weights that can vary across many orders of magnitude. The input gate $i_t$ acts like an adaptive, positive learning rate for the new contribution $z_t$, while the forget gate $f_t$ acts like a multiplicative decay (or amplification) of all previously stored contributions. Together these multiplicative effects allow the network to re-weight (and even amplify) previous information in a finer-grained way than is possible with standard sigmoid gates.

# Normalizer state (n_t): tracking effective gate strengths

Exponential gates change the scale of the additive memory update. To make retrieval stable and meaningful we must keep track of the total effective strength by which inputs have been incorporated into the cell. The sLSTM introduces a normalizer state $n_t$ that mirrors the form of the cell update but without the content vectors:
\[
n_t \;=\; f_t n_{t-1} + i_t.
\]
If we unroll the recurrence for $c_t$ and $n_t$ we find that
\[
c_t \;=\; \sum_{s\le t} \Big(\prod_{u=s+1}^t f_u\Big)\, i_s z_s,\qquad
n_t \;=\; \sum_{s\le t} \Big(\prod_{u=s+1}^t f_u\Big)\, i_s.
\]
Thus $n_t$ accumulates the same multiplicative weights used to combine earlier inputs, but without the content vectors $z_s$. The hidden pre-output $\tilde h_t$ is then defined as the normalized cell content,
\[
\tilde h_t \;=\; \frac{c_t}{n_t}.
\]
This ratio interprets the memory as a weighted average of past contributions $z_s$, where the weight for a contribution at time $s$ equals $i_s$ times the product of future forget factors. By keeping and dividing by $n_t$, the sLSTM produces a retrieval that is invariant to a global rescaling of the additive terms: if all contributions were multiplied by the same positive factor, both $c_t$ and $n_t$ would scale identically and the ratio would remain unchanged. In short, $n_t$ tracks the total effective gate strength and makes the retrieved state a normalized, interpretable summary rather than an unbounded accumulated vector.

The normalizer is equally important for the matrix memory of mLSTM (there, $n_t$ is a vector accumulating weighted keys). In both scalar and matrix cases the normalizer enables the network to compare contributions that arrive at different times and have been subjected to different sequences of multiplicative forget factors.

# Stabilizer state (m_t): log-domain max trick to prevent overflow

Exponential gates are powerful but dangerous numerically: applying raw exponentials repeatedly can easily overflow floating-point representations or produce extremely small values that underflow. xLSTM addresses this with a log-domain stabilization technique that keeps the effective magnitudes in a safe range while preserving the mathematical behavior of the recurrence.

The stabilizer state $m_t$ is defined in the log domain as
\[
m_t \;=\; \max\!\big(\log(f_t) + m_{t-1},\; \log(i_t)\big).
\]
This is a running max that tracks the dominant log-scale between the scaled previous factor and the current input gate. Using $m_t$ we form stabilized, primed gates
\[
\begin{aligned}
i'_t &= \exp\big(\log(i_t) - m_t\big) = \exp(\tilde{i}_t - m_t),\\
f'_t &= \exp\big(\log(f_t) + m_{t-1} - m_t\big).
\end{aligned}
\]
These primed gates are scaled to lie in a numerically safe range: at least one of $i'_t$ or the scaled forget factor will be near one, and none will be astronomically large. The construction is analogous to the common log-sum-exp or “max” trick used to stabilize softmax computations: by factoring out the largest exponent, we avoid creating extremely large exponentials while preserving ratios between terms.

Because $m_t$ is updated from $\log(f_t) + m_{t-1}$ and $\log(i_t)$, it maintains the necessary bookkeeping to rescale both the previous state and the current input consistently. This way, the algorithm can run in standard floating-point precision without overflow or underflow, even though the underlying gates are conceptually exponentials that could assume very large or very small values.

# Stabilized gates (i'_t, f'_t) and invariance of outputs/gradients

A key property of the stabilization trick is that replacing the original gates $i_t,f_t$ by the stabilized versions $i'_t,f'_t$ and working with correspondingly rescaled internal states leaves the network outputs and parameter gradients unchanged. The paper proves (see Appendix) that the forward pass and the loss derivatives with respect to parameters are invariant under this reformulation. Here is the intuition and the algebraic sketch that makes the invariance transparent.

Define the scaled (tilde) states
\[
\tilde c_t \;=\; e^{-m_t} c_t,\qquad \tilde n_t \;=\; e^{-m_t} n_t.
\]
Starting from the original recurrences
\[
c_t = f_t c_{t-1} + i_t z_t,\qquad n_t = f_t n_{t-1} + i_t,
\]
multiply both sides by $e^{-m_t}$ and substitute the definitions of $i'_t,f'_t$:
\[
\begin{aligned}
\tilde c_t &= e^{-m_t} f_t c_{t-1} + e^{-m_t} i_t z_t
           = f'_t \tilde c_{t-1} + i'_t z_t,\\
\tilde n_t &= f'_t \tilde n_{t-1} + i'_t.
\end{aligned}
\]
Thus the scaled variables evolve with the numerically safe primed gates exactly as the unscaled variables would with the original gates. The pre-output is the normalized ratio
\[
\tilde h_t \;=\; \frac{c_t}{n_t} \;=\; \frac{\tilde c_t}{\tilde n_t},
\]
so the output that enters the rest of the network is identical whether computed from the original or the stabilized recurrences. Since all downstream computations depend only on these identical outputs, the loss and its derivatives with respect to the parameters are also identical. In other words, stabilization is a purely numerical reparameterization that does not change the mathematical function implemented by the network nor its gradients.

This invariance is crucial: it means we can enjoy the expressive benefits of exponential gating while safely executing the computations in floating-point arithmetic, and we can do so without modifying optimization behavior or learning dynamics.

# Initialization and numerical considerations for robust training

Exponential gates combined with normalization and stabilization make the model numerically manageable, but they also shift some practical considerations for training. The paper emphasizes (and lists as a limitation) that the initialization of forget gates must be chosen carefully. Because forget gates enter multiplicatively into the long-term accumulation (they appear in every product that weights a past contribution), their initial bias and scale control whether the memory tends to retain or rapidly forget past inputs at the start of training.

If forget factors are initialized so that their exponentials systematically produce values far greater than one, then even with stabilization the dynamics may emphasize older inputs excessively and make optimization difficult. Conversely, if the initial forget factors are too small, the model will rapidly forget and cannot accumulate useful context over long ranges. The paper therefore stresses careful selection of forget gate initializations but does not prescribe a single universal setting; this is listed as an implementation consideration that practitioners must tune for particular tasks and model sizes.

Beyond forget initialization, additional numerical considerations follow directly from the design choices:

- Exponential gates alone can produce extremely large or small magnitudes; stabilization via $m_t$ is therefore mandatory for practical training. Without the stabilizer, exponentials would cause frequent overflow or underflow in real-world training regimes.

- The normalizer $n_t$ must be guarded against extremely small values when dividing (for example to avoid division-by-zero). In practice the stabilization machinery and sensible initializations make $n_t$ well behaved, but implementers should still take care to ensure that the denominator in $c_t/n_t$ remains numerically safe (for instance by the use of the stabilizing rescaling described above).

- When extending to matrix memories (mLSTM), analogous concerns apply componentwise to the normalizer vector and to the dot products used at retrieval. For example, the paper uses an absolute-valued dot product and a lower bound in the mLSTM retrieval to prevent near-zero denominators (see the mLSTM equations). Those choices are consistent with the same mindset: preserve retrieval semantics while ensuring numerical robustness.

Taken together, these points emphasize that exponential gating is a powerful tool that must be paired with log-domain stabilization and careful initial conditions to yield robust, trainable models.

# Why exponential gating enables revisable storage

One of the principal motivations for introducing exponential gates is to give the LSTM family the ability to revise prior storage decisions dynamically. In the original LSTM formulation, sigmoid gates are constrained to $(0,1)$; once information has been stored and subsequently attenuated by forget gates less than one, it is difficult for later events to re-weight or undo that decision strongly. This limitation shows up empirically in tasks like the Nearest Neighbor Search described in the paper, where an early stored candidate should be replaced if a later, more similar item appears in the sequence. A bounded input gate simply cannot allocate a sufficiently larger weight to the later item relative to the earlier one when many multiplicative decay factors intervened.

Exponential gating changes the picture because input and forget gates become positive multiplicative factors that can differ by orders of magnitude. Consider the unrolled weighted-sum view:
\[
\tilde h_t = \frac{\sum_{s\le t} \big(\prod_{u=s+1}^t f_u\big)\, i_s z_s}{\sum_{s\le t} \big(\prod_{u=s+1}^t f_u\big)\, i_s}.
\]
Each past contribution $z_s$ enters with weight $w_s = \big(\prod_{u>s} f_u\big)i_s$. With exponential gates $i_s$ and $f_u$ can be very small or very large (relative to 1), so the model can make $w_s$ arbitrarily dominant or negligible. This means a later input $z_t$ can be given a much larger effective weight than earlier inputs, even if those earlier inputs have been attenuated by sequences of forget factors. In practical terms, the network can "overwrite" or strongly re-weight previous storage decisions: a later, more relevant input can dominate the normalized sum and thus determine the retrieved state.

The normalizer $n_t$ ensures these re-weightings are interpretable and stable: by dividing by the sum of weights, the network retrieves a normalized summary that reflects the relative importance assigned to each stored item. The stabilizer $m_t$ makes such extreme relative weights numerically tractable. Together, exponential gating, the normalizer, and stabilization implement a mechanism that behaves like a continuously adaptive associative memory: items are stored with learned, multiplicative strengths, and later items can be weighted up or down to revise earlier storage. This is precisely what enables xLSTM to succeed on tasks requiring revision of memory, such as the Nearest Neighbor Search experiments and other state-tracking benchmarks discussed in the paper.

In summary, exponential input and forget gates provide a much larger and more flexible space of multiplicative weights; the normalizer turns the accumulated memory into a meaningful normalized summary; and the stabilizer permits these dynamics to run safely in floating-point arithmetic. Together these instruments enable xLSTM to revise past storage decisions dynamically while remaining numerically robust and differentiable end-to-end.

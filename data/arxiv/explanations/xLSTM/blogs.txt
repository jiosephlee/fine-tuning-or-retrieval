# From LSTM to xLSTM: Can RNNs Power the Next Wave of Language Models?

## Why revisit LSTMs now?

Long Short-Term Memory (LSTM) networks introduced two ideas that changed sequence learning: a persistent (additive) cell state and gating to control writing, forgetting and reading. Those ideas solved the vanishing gradient problem and enabled many successes across sequence tasks. But since Transformers rose to prominence, LSTMs have been largely sidelined for large-scale language modeling. Transformers scale well, are massively parallelizable, and use attention to give powerful (and effectively unbounded) memory.

This paper asks a simple, practical question: if we bring modern training practices and a few structural changes to LSTMs, can a scaled-up recurrent model compete with Transformers and modern State Space Models (SSMs) in language modeling? The answer the authors present is: yes—when you fix three core LSTM weaknesses.

## The three classic LSTM pain points

The paper identifies three limitations of traditional LSTMs that explain why they fell behind at large scale:

1. Revising storage decisions. Standard LSTM updates the scalar cell state with gated additive updates. If the model stored a value earlier and later sees a better candidate, it can be hard to revise that earlier storage reliably. This hurts tasks that require finding or replacing the best-match item seen so far.

2. Storage capacity. Traditional LSTM cells are scalar (or vector of scalars) state entries. That forces compression of rich key/value-like structure into low-dimensional scalars, which limits the ability to store and retrieve complex associations. Rare tokens and associative recall tasks reveal this bottleneck.

3. Parallelism and throughput. LSTMs rely on hidden-to-hidden (recurrent) mixing across time steps, which prevents straightforward parallelization across sequence length and limits throughput compared to Transformer-style models.

xLSTM addresses these three issues with two core ideas: exponential gating (plus stabilization and normalization) and alternative memory structures (a scalar-but-improved sLSTM, and a matrix-memory mLSTM).

## Key idea 1 — exponential gating (and why it helps)

Standard LSTM gates use sigmoids, which produce values in $(0,1)$ and behave like soft switches. xLSTM proposes using exponential activations for the input gate, and optionally for the forget gate, i.e. gates of the form
- input gate: \(i_t = \exp(\tilde{i}_t)\),
- forget gate: \(f_t = \sigma(\tilde{f}_t)\) or \(f_t = \exp(\tilde{f}_t)\).

Why exponential gates? Two practical consequences:

- Exponential gates naturally implement multiplicative weighting in the log-domain, which makes it straightforward to accumulate contributions across time in ways that allow later updates to dominate earlier ones when appropriate—this enables easier revision of stored content.
- Using exponentials lets the gate strengths act like (possibly large) positive scalars, which the authors pair with a lightweight normalization mechanism (a "normalizer" state) so outputs remain well-behaved.

Because raw exponentials can overflow or underflow, xLSTM adds a stabilizer state \(m_t\) that rescales the gates in a numerically stable way. The stabilized gates are mathematically equivalent to the unstabilized formulation but avoid numerical issues during training and inference.

In plain terms: exponential gating gives the model a more flexible, multiplicative way to accumulate and revise memory contributions over long time ranges, and stabilization keeps training stable.

## Key idea 2 — two memory variants: sLSTM and mLSTM

xLSTM introduces two complementary memory designs that both use exponential gating.

sLSTM: a scalar but enhanced memory cell
- The sLSTM keeps a scalar cell state like classic LSTM but extends it with the exponential gates plus a normalizer state \(n_t\).
- The forward update is
  - \(c_t = f_t c_{t-1} + i_t z_t\),
  - \(n_t = f_t n_{t-1} + i_t\),
  - \(\tilde{h}_t = c_t / n_t\), and \(h_t = o_t \tilde{h}_t\).
- The normalizer \(n_t\) tracks the total effective contribution of the inputs (input gate weighted and decayed by future forget gates). Dividing \(c_t\) by \(n_t\) produces a normalized readout, which makes updates comparable and enables the revising behavior.

sLSTM also supports multiple memory cells and a notion of “heads.” Within each head it allows memory mixing (hidden-to-memory recurrent connections), giving sLSTM the ability to do state-tracking reasoning that purely parallelizable memories lack.

mLSTM: matrix memory with a covariance (outer-product) update
- To boost storage capacity, mLSTM upgrades the cell from a scalar to a matrix \(\mathbf{C}_t \in \mathbb{R}^{d\times d}\).
- At each step it stores a key/value pair \((\mathbf{k}_t, \mathbf{v}_t)\) using a covariance (outer-product) update:
  - \(\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \, \mathbf{v}_t \mathbf{k}_t^\top\).
- Retrieval is a matrix-vector product \(\mathbf{C}_t \mathbf{q}_t\), normalized by the dot product between the normalizer \(\mathbf{n}_t\) and \(\mathbf{q}_t\) (safely lower-bounded), and scaled by an output gate:
  - \(\tilde{\mathbf{h}}_t = \mathbf{C}_t \mathbf{q}_t / \max\{|\mathbf{n}_t^\top \mathbf{q}_t|, 1\}\),
  - \(\mathbf{h}_t = \mathbf{o}_t \odot \tilde{\mathbf{h}}_t\),
  - \(\mathbf{n}_t = f_t \mathbf{n}_{t-1} + i_t \mathbf{k}_t\).
- The covariance update is closely related to classic associative memories and to fast-weight approaches: it stores distributed associations where retrieval is a dot-product-based lookup.

Why the matrix memory matters: it increases storage capacity substantially compared to scalar cells and lets the model store many key/value-like associations without needing attention. Because mLSTM avoids hidden-to-hidden recurrence (no memory mixing), it can be implemented in a parallel way across time, making it competitive on throughput.

## Architecture: xLSTM blocks and residual stacks

xLSTM integrates sLSTM and mLSTM cells into residual block backbones similar to modern LLM architectures. Two block designs are used:

- For sLSTM blocks, a post up-projection residual block is used: the block summarizes the past in the original space, projects up, applies nonlinearity, and projects back.
- For mLSTM blocks, a pre up-projection block is used: inputs are projected up before the non-linear, high-dimensional memory operations, which matches the intuition that matrix memory benefits from higher-dimensional representations.

These xLSTM blocks are stacked residually with pre-LayerNorm, mirroring contemporary model design choices. The authors denote mixed architectures as xLSTM[a:b], where \(a/b\) is the ratio of mLSTM-based to sLSTM-based blocks in a stack. For example, xLSTM[7:1] means 7 mLSTM-based blocks and 1 sLSTM-based block per 8-block group.

## What the experiments show (high-level summary)

The paper evaluates xLSTM across synthetic tasks and large-scale language modeling experiments. Key empirical findings:

- Synthetic tasks: Exponential gating plus memory mixing lets the sLSTM variants solve formal state-tracking problems (regular-grammar-like tasks) that pure parallel models (Transformers, many SSMs) struggle with. The matrix memory (mLSTM) improves associative recall capacity and extrapolation to longer contexts on multi-query recall tasks.

- Comparison on 15B-token training regime: On models matched to a GPT-3 small style (≈350M parameters), xLSTM variants outperform a range of baselines (Transformers, SSMs, and modern RNN variants) in validation perplexity after training on 15B tokens from SlimPajama. Ablations attribute the gains to both exponential gating and the matrix memory.

- Large-scale (300B tokens) experiments: The authors train families of models (125M to 1.3B) on 300B tokens and report:
  - Better extrapolation to longer contexts (up to 16k) than the compared methods.
  - Lower validation perplexities and stronger performance on a suite of downstream tasks and on the PALOMA benchmark (571 text domains).
  - Favorable scaling-law offsets—xLSTM shares similar power-law slopes but with a lower loss offset versus some competitors, suggesting competitiveness at larger sizes.

- Efficiency: xLSTM variants have linear time complexity and constant memory with respect to sequence length (in contrast to quadratic Transformers). The mLSTM is parallelizable; sLSTM retains recurrent mixing so is less parallel but the authors implemented optimized CUDA kernels that are only modestly slower than the parallel mLSTM. The matrix updates in mLSTM do add compute cost due to \(d\times d\) operations, but these are parameter-free and parallelizable.

## Limitations to keep in mind

The paper is transparent about limitations:

- sLSTM's memory mixing prevents full parallelization; it requires sequential hidden mixing. The authors mitigate this with optimized kernels but it still limits throughput relative to fully parallelized designs.

- mLSTM's matrix memory is computationally expensive for large \(d\); current CUDA kernels are not fully optimized and the implementation is slower than highly optimized attention kernels like FlashAttention.

- The matrix memory is independent of sequence length: very long contexts could overload a fixed-size matrix memory, though experiments up to 16k context did not show a breakdown.

- Initialization and hyperparameter choices (particularly for forget gates) are delicate and require care.

- The authors did not fully optimize every architectural and hyperparameter choice for the largest models due to compute costs; further tuning could improve performance further.

## Bottom line — what changed and why it matters

xLSTM shows that the fundamental LSTM ideas remain powerful when enhanced appropriately:

- Exponential gating plus normalization and stabilization gives a principled, numerically stable way to revise stored content over time and to weigh contributions multiplicatively.

- Adding a matrix-style covariance memory (mLSTM) provides much larger storage capacity that behaves like a fast associative memory; pairing this with normalization yields reliable retrieval.

- Combining sLSTM (for state-tracking through memory mixing) and mLSTM (for large-capacity associative memory and parallelizability) inside residual stacks creates practical architectures that are competitive with Transformers and modern SSMs on language modeling.

For practitioners, the paper suggests RNN-based architectures should not be dismissed for large-scale language tasks: with modern design choices, recurrent memories can be both expressive and competitive in scaling behavior, while offering linear complexity in sequence length and constant memory footprint. The code is available for replication and further experimentation.

If you like exploring architectural alternatives to attention, xLSTM is a concrete, well-motivated reimagining of gated recurrent memory that is worth a closer look.



# Exponential Gating, Simply Explained: How xLSTM Learns to Rewrite Its Own Memories

## Why classic LSTM can't always "change its mind"

The LSTM's original memory mechanism is elegant and powerful: a scalar cell state $c_t$ is updated each time step by blending the previous state and a new candidate, controlled by two sigmoid gates:

$c_t = f_t c_{t-1} + i_t z_t$,

where $f_t$ (forget) and $i_t$ (input) are in $(0,1)$ because they are produced by a sigmoid. This additive update—often called the constant error carousel—protects gradients and provides a stable way to accumulate information over long sequences.

That stability is also the source of a limitation. The standard sigmoid gating blends the old and new information with weights that are bounded between 0 and 1 and depend on the current inputs and previous hidden state. In practice this makes it hard for the network to sharply overwrite a past stored value if later evidence suggests a different value should have been stored. Think of it as trying to replace an entry in a ledger using only partial erasures and small increments: you can fade the old entry gradually but you rarely get a clean, strong rewrite.

The xLSTM paper identifies this as a problem on tasks like "nearest neighbor search" (scan a sequence to find which past vector is most similar to a reference and return its attached value). Classic LSTMs struggle to revise an earlier stored candidate when a later, more similar item appears. xLSTM's solution is exponential gating.

## The core idea: exponential gates that act multiplicatively

Instead of forcing input and forget gates through a sigmoid, xLSTM allows the input gate (and optionally the forget gate) to be exponential in their pre-activations:

- input gate: $i_t = \exp(\tilde{i}_t)$
- forget gate: $f_t = \sigma(\tilde{f}_t)$ or $f_t = \exp(\tilde{f}_t)$

Because $\exp(\cdot)$ maps real numbers to $(0,\infty)$, these gates can now selectively amplify or heavily attenuate contributions, not just weight them between 0 and 1. That gives the model two key abilities:

1. Strong overwrites: if a late input should dominate, the model can set $i_t$ very large for that input so that its contribution dwarfs earlier stored content.
2. Strong decay: if the forget gate is exponential, the model can aggressively decay past content (or, conversely, retain it strongly) depending on the sign and magnitude of $\tilde{f}_t$.

In short, exponential gating turns the gate into a multiplicative "learning rate" (for inputs) and "decay factor" (for past content) that can vary over a wide dynamic range, enabling sharp, selective rewrites.

## But exponentials blow up — so xLSTM normalizes

Exponential gates are powerful but numerically dangerous: without care they can overflow or simply create values so large they drown out everything else and kill learning. xLSTM introduces two companion mechanisms to keep the dynamics numerically well behaved and still preserve the intended semantics.

1. Normalizer state $n_t$.

   For the scalar sLSTM variant (the one that keeps scalar cell states but uses exponential gates), xLSTM maintains an auxiliary normalizer state that accumulates the effective "strength" of stored pieces:

   - cell update: $c_t = f_t c_{t-1} + i_t z_t$
   - normalizer update: $n_t = f_t n_{t-1} + i_t$

   The hidden output uses the ratio $c_t / n_t$ as the readable memory:

   $h_t = o_t \cdot \tilde{h}_t,\quad \tilde{h}_t = c_t / n_t$.

   Intuition: $c_t$ stores the weighted sum of inputs ($i_t z_t$ combined over time, with decay), while $n_t$ stores the sum of the weights themselves ($i_t$ combined over time, with the same decay). Dividing yields a normalized "average" of the stored values, which prevents a single huge $i_t$ from producing an unbounded hidden activation and provides a stable retrieval signal even when gates have very different magnitudes.

   For the matrix-memory mLSTM variant, the same idea generalizes: the cell is a matrix $\mathbf{C}_t$ updated by outer products, and the normalizer $\mathbf{n}_t$ is the weighted sum of keys; retrieval divides the matrix-vector product by the (absolute) dot product of normalizer and query (clipped to a lower bound).

2. Stabilizer state $m_t$.

   Even with normalization, directly computing exponentials of arbitrary pre-activations can cause overflow or underflow. xLSTM borrows a stabilization trick that keeps the effective exponentials in a numerically safe range while preserving the ratios the model needs.

   Concretely, the stabilizer maintains a running log-scale:

   $m_t = \max(\log(f_t) + m_{t-1}, \log(i_t))$,

   and then rescales the gates before applying them:

   $i'_t = \exp(\log(i_t) - m_t) = \exp(\tilde{i}_t - m_t)$,

   $f'_t = \exp(\log(f_t) + m_{t-1} - m_t)$.

   This is a numerically stable way to keep the largest contribution near 1 in log-space and avoid overflow, while leaving the effective dynamics (relative magnitudes and therefore the forward outputs and gradients) unchanged. The paper shows that substituting $i'_t$ and $f'_t$ for $i_t$ and $f_t$ does not change the network outputs nor the parameter gradients.

Together, normalization and stabilization let exponential gates have wide dynamic range without breaking training or inference.

## Everyday analogy: a river and a bucket of dye

Think of the LSTM cell state as a bucket of colored water that represents the memory. Each incoming item is a scoop of dye (with its own color $z_t$). The input gate $i_t$ controls how many scoops you add, and the forget gate $f_t$ controls how much of the bucket you keep (you can pour out some water).

- Classic LSTM with sigmoid gates: scooping and pouring are limited to gentle adjustments. You can make the dye a bit more red or more blue over many steps, but you cannot suddenly replace the bucket's color in one stroke without many steps.

- xLSTM with exponential input gate: now your scoop size can be tiny or enormous. If you later encounter a truly dominant piece of evidence, you can dump a huge scoop that overwhelms earlier color, quickly rewriting what the bucket represents.

- Normalizer state $n_t$: a second meter that counts the total scoop volume (with decay applied the same way as to the dye). When you report the bucket's color for downstream use, you present the average color (dye amount divided by total scoop volume). This prevents one giant scoop from creating an unbounded report value; instead you present the normalized color that reflects relative contributions.

- Stabilizer $m_t$: an overflow shield in the kitchen that rescales scoops so you never literally dump a bucket-sized scoop from a tiny measuring cup; it keeps the arithmetic in practical bounds while preserving proportions.

This lets xLSTM both make decisive overwrites and still report stable, meaningful memory contents.

## Why this helps on the nearest-neighbor update task

Nearest-neighbor-style tasks require the model to scan a sequence and remember the best match seen so far. When a new, better match appears late, the model must revise earlier stored choices and make them effectively irrelevant. Sigmoid gates give limited flexibility for that kind of aggressive revision; exponential gates let the model amplify a late input's influence (large $i_t$), or sharply suppress prior contributions (small $f_t$ when exponential), and the normalizer ensures retrieval remains stable.

The paper reports this exact qualitative improvement: on a purpose-built nearest-neighbor search regression, sLSTM with exponential gating outperforms classical LSTM, demonstrating the capacity to revise stored values when more appropriate candidates appear later in the sequence.

## A few practical notes

- Exponential gating is not a free lunch: the exponentials require stabilization and a normalizer to avoid numerical problems. xLSTM includes both and proves they preserve gradients and outputs (so the model is well-defined and trainable).

- There are two complementary xLSTM variants: sLSTM (scalar memory with exponential gating and new memory mixing) and mLSTM (matrix memory with covariance-style updates). The exponential gates and the normalizer/stabilizer idea apply to both.

- The matrix-memory mLSTM scales the storage capacity because it stores outer-products of values and keys, enabling retrieval by matrix-vector products. The normalizer in that context is a vector that measures total key strength and is used to normalize retrieved vectors.

## Takeaway

Exponential gating turns gates into flexible multiplicative gains (or decays) instead of fixed-in-range blending factors. Combined with a normalizer that records total gate strength and a stabilizer that keeps exponentials numerically safe, xLSTM gains the ability to sharply rewrite past memory contents while still producing stable readouts. That small change in activation function, together with the supporting bookkeeping, addresses a concrete failure mode of classic LSTMs (inability to revise stored information) and leads to measurable gains on tasks that require dynamic memory revision.



# Matrix Memory in Plain English: mLSTM’s Built-In Key–Value Store

The mLSTM cell from the xLSTM family replaces the traditional scalar LSTM cell state with a full matrix, turning the recurrent memory into an explicit key–value store. This change gives the model much stronger retrieval abilities for rare facts and many stored items, at the cost of extra matrix math. This post breaks down what that matrix memory is, how it stores and retrieves information, why the update rule is just a covariance, and what the practical trade-offs are for speed and memory.

## The intuition: store pairs, retrieve by similarity

Think of a stream of inputs as a sequence of facts. For each fact the model can compute:
- a key vector k_t that identifies the fact (like an address),
- a value vector v_t that holds the information to recall later,
- and later, a query q_{t+τ} that asks for the value most relevant to that query.

mLSTM stores these key–value pairs directly inside a matrix memory C_t. The retrieval is then a matrix-vector multiplication C_t q which sums up values weighted by their key similarity to the query. This is associative memory in action: keys point to values, and queries retrieve a weighted mixture.

## The update rule: a covariance (outer-product)

The update that stores a new key–value pair is remarkably simple and classical. At time t the matrix memory is updated by adding the outer product of value and key:

C_t = f_t · C_{t-1} + i_t · v_t k_t^T

- v_t k_t^T is a rank-1 matrix that encodes the association between key and value.
- i_t (the input gate) scales how strongly we write this new association.
- f_t (the forget/decay gate) multiplies the old memory, so older associations can be faded.

This outer-product rule is a covariance-style update: it places the value into memory in the directions specified by the key. It is equivalent in spirit to classic Fast Weight / associative memory methods and is optimal under certain assumptions for maximally separating retrieved items (the paper cites results showing its signal/noise benefits).

Because the update is additive (plus decay), the memory accumulates many such outer products over a sequence and can later reproduce them via multiplication with a query.

## Retrieval: multiply the matrix by a query, normalize, and gate

To read from memory, mLSTM computes

\tilde{h}_t = C_t q_t / \max\{ |\mathbf{n}_t^\top q_t|, 1 \}

and the final hidden output is h_t = o_t ⊙ \tilde{h}_t, where o_t is an output gate.

Here n_t is a normalizer state that accumulates the (gated, decayed) keys:

n_t = f_t · n_{t-1} + i_t · k_t.

Why this normalizer? C_t q_t by itself sums up values weighted by keys’ dot-products with q_t, but the overall scale of that sum depends on how much key mass was written in directions aligned to q_t. Dividing by |n_t^T q_t| (and lower-bounding by 1) stabilizes the readout so that the retrieved vector doesn’t explode or vanish when there are many similar or many dissimilar keys. The paper uses the absolute value and a floor of 1 to avoid tiny denominators.

So retrieval is just matrix-vector multiply + a simple scalar normalization, then scaled by an output gate o_t.

## Gates: exponential writes and stabilizers

A noteworthy detail: the input gate i_t is exponential, i_t = exp(tilde{i}_t), rather than the usual sigmoid. Exponentiating lets the model make multiplicative-strength writes (it can sharply amplify or attenuate a write). The forget gate f_t can be sigmoid or exponential as well. Exponential gates can grow large, so the paper uses a stabilization trick: a running stabilizer state m_t is maintained and used to renormalize i_t and f_t in log-space so the forward computations and gradients remain numerically stable (this is the same numerical device used in prior work on exponential gating).

Practically this means the model can choose very small or very large effective learning rates for each outer-product write while keeping training stable.

## Why this helps recall rare or many facts

A scalar cell must compress whatever it stores into one vector per time step; many distinct associations collide. With a d×d matrix memory, each stored outer product has much more representational capacity: a single write v k^T is a full matrix pattern. Retrieval via C q can therefore reconstruct richer value vectors even when many key–value pairs are stored. This boosts performance on tasks where you need many distinct associations (associative recall) or to remember rare items that are otherwise drowned out in compact scalar cells.

Empirically in the paper, architectures using mLSTM blocks perform much better than standard LSTMs on associative recall tasks and rare-token prediction benchmarks.

## Complexity and parallelism trade-offs

Storing a d×d matrix and doing rank-1 updates and matrix-vector multiplications is more compute-heavy than scalar-cell LSTMs, but the pattern of computation is friendly to GPUs:

- The memory update C_t = f_t C_{t-1} + i_t v_t k_t^T is a scaled matrix plus a scaled outer product. With batching and proper kernels this can be implemented as standard BLAS-style operations.
- Retrieval C_t q_t is a standard matrix-vector multiply.
- Crucially, mLSTM can be implemented in a parallel form (i.e., not inherently sequential) because the paper removes recurrent hidden→hidden mixing for the matrix-memory variant. That enables building operations that map well to GPU parallelism and (in principle) fuse well with existing linear-algebra optimized kernels.

The paper stresses that mLSTM has linear computation and constant memory complexity with respect to sequence length (unlike attention which is quadratic in context length). The matrix memory size is independent of sequence length (it depends on the hidden dimension d), so longer contexts don’t blow up memory requirements. The cost is the d×d operations per step, trading per-step compute for stronger, compact memory.

## Connections to other ideas

- The mLSTM covariance update is mathematically equivalent to classic Fast Weights (outer-product memories) and is related to recent models that use fast associative updates (Retention, RWKV variants, linear Transformer variants).
- Using keys, values, and queries mirrors Transformer terminology; mLSTM integrates this into an LSTM-style recurrent framework, with gates controlling decay and learning rate per write.
- Unlike standard Transformer attention (which is O(L^2) in sequence length L), mLSTM’s memory update/retrieval is O(d^2) per step but O(L) overall and doesn't store per-position activations, which keeps memory constant in L.

## Practical takeaway

If you need a recurrent model that remembers many distinct key–value associations (for example: many rare facts, lots of associative pairs, or long-range entity state tracking), mLSTM offers a principled, compact memory: store associations as outer products in a matrix and retrieve them by matrix–vector multiplication and normalization. The price is extra d×d computation per step, but that work maps well to GPUs and avoids the quadratic scaling in sequence length of full attention. The paper shows that, when combined into the xLSTM architecture, this matrix-memory idea yields marked improvements on associative recall and language modeling benchmarks.

For implementers: expect to add a matrix C of size d×d, compute a scaled outer product write and a matvec read per time step, and use the normalizer n_t (and its bounded denominator) to stabilize the readout. Use the exponential input gate with the paper’s log-space stabilizer to get the intended dynamic-range behavior without numerical overflow.



# Why sLSTM Still Matters: Memory Mixing, Heads, and Real State Tracking

## Overview

The xLSTM family rethinks LSTM for the era of large models. Within that family, the sLSTM (scalar LSTM extension) is the component that preserves—and importantly extends—the classic LSTM ability to perform true state tracking. Two design choices make this possible: (1) exponential gating (with a normalization and stabilizer mechanism) that enables revision of stored information, and (2) explicit memory mixing across scalar cells (and controlled mixing via heads). These properties let sLSTM solve tasks that many attention-only or state-space architectures cannot, such as parity and other formal-language/state-tracking problems examined in the paper.

Below I unpack how sLSTM works, why exponential gates + normalization matter, how memory mixing and heads are organized, and how these lead to empirical advantages on formal-language tasks.

## The sLSTM update — distilled

sLSTM keeps the LSTM’s additive cell update (the constant error carousel) but changes the gating and output normalization. The essential forward equations (per time step) are:

- Cell and normalizer states:
  c_t = f_t c_{t-1} + i_t z_t
  n_t = f_t n_{t-1} + i_t

- Hidden state:
  \tilde{h}_t = c_t / n_t
  h_t = o_t \, \tilde{h}_t

- Gate preactivations / inputs are standard affine projections from input and previous hidden state; crucially the input gate uses an exponential activation:
  i_t = \exp(\tilde{i}_t)
  f_t = \sigma(\tilde{f}_t)  or  \exp(\tilde{f}_t)
  o_t = \sigma(\tilde{o}_t)

The cell input z_t and the output gating o_t follow the familiar parameterizations. The new pieces are the normalizer n_t and the exponential form of i_t (and optionally f_t), together with stabilization (below).

Intuition: n_t tracks the accumulated effective weight mass contributed by past inputs (each weighted by its input gate and future forget gates). Dividing c_t by n_t produces a running, weighted average rather than an unnormalized sum. This is central to controlled retrieval and stable updates when gates are exponential.

## Why exponential gating + normalizer enables revisable storage

Classic LSTM gates are bounded in (0,1) via sigmoid, which limits how much a new input can override previous storage in a single step. Exponential gating removes that hard cap: an input gate i_t = \exp(\tilde{i}_t) can produce a wide dynamic range of contributions. That dynamic range is necessary when the model needs to abruptly replace or strongly up-weight a newly observed piece of information relative to what was stored earlier.

But exponentials risk overflow and unstable gradients. The sLSTM addresses this with:

- A normalizer state n_t that accumulates the corresponding gate mass, so the effective retrieved value is a normalized average c_t / n_t (not an unbounded sum).
- A stabilizer state m_t (from the paper) used to renormalize exponentials in a numerically stable way:
  m_t = max( log(f_t) + m_{t-1}, log(i_t) )
  and stabilized gates are computed from m_t so that replacing i_t, f_t with stabilized versions leaves both forward outputs and derivatives unchanged.

Combined, these elements let i_t temporarily become dominant (to revise storage), while keeping the cell numerically stable and differentiable over long sequences.

## Memory mixing across scalar cells — what it is and why it matters

sLSTM supports multiple scalar memory cells (a vectorized c_t), and crucially it includes recurrent weight matrices that connect the previous hidden state to the next cell inputs and gates. These recurrent (hidden→gate/input) connections are the "memory mixing" mechanism: they let different scalar cells influence each other across time.

Why is that important?

- Memory mixing permits the network to implement state machines and combinatorial state transforms. Two separate scalars can be combined nonlinearly over time to represent compound discrete states, counters, parity bits, stacks, etc.
- Models without such recurrent mixing—standard Transformers (without recurrence) and many linear SSMs—lack the same inherent capacity to implement arbitrary stateful counters or parity computations that require interdependent updates across memory slots.

The paper emphasizes that memory mixing is central for "state tracking" tasks: problems where the correct output depends on a nontrivial function of prior events that must be updated incrementally and often revised as the sequence progresses.

## Heads in sLSTM — controlled partitioning of memory mixing

sLSTM introduces the concept of multiple heads, but with a twist: memory mixing occurs within each head, not across heads. Concretely:

- Each head contains a group of scalar memory cells that mix via recurrent connections.
- Heads do not mix their memory with other heads (no cross-head recurrent matrices).

This head structure offers a middle ground: each head can implement a specialized local state machine (or set of interacting state variables) while preserving modularity across heads. It is analogous to multi-head attention in spirit (parallel specialized pathways) but retains recurrent, stateful intra-head dynamics. The result is a flexible, structured way to combine many small state trackers that together represent richer histories.

Importantly, because of exponential gating, heads can independently decide to strongly update or rewrite their local state when necessary. That aids selective revision: when a new observation supersedes prior ones, the appropriate head can sharply overwrite its stored summary without destabilizing others.

## Empirical evidence: formal languages and parity

The paper evaluates sLSTM on formal-language/state-tracking tasks that are designed to highlight whether a model can implement exact stateful computations and revise stored decisions. In particular, parity-like tasks and regular-grammar problems were used.

Key experimental results (summarized from the paper):

- On a suite of formal-language tasks (extended from prior work to allow length extrapolation), small 2-block architectures were compared: pure sLSTM (xLSTM[0:1]), pure mLSTM (xLSTM[1:0]), mixed xLSTM[1:1], Transformers (Llama), several SSMs (Mamba, Hyena, etc.), RWKV, and ordinary LSTM variants.
- Models without memory mixing (standard Transformers and many SSMs) failed on tasks such as parity, where exact state tracking across the sequence is required. This aligns with theoretical and empirical findings that non-recurrent models can be fundamentally limited for certain stateful computations.
- Pure sLSTM (xLSTM[0:1]) and mixed xLSTM architectures achieved high accuracy on these tasks, demonstrating that exponential gates + intra-head memory mixing yield practical state-tracking ability in small, residual-block contexts.

Thus, sLSTM concretely recovers the kind of algorithmic/state-machine behavior that many attention-only or purely linear SSM architectures cannot reliably learn.

## How sLSTM complements other xLSTM components

The paper’s larger xLSTM family also includes mLSTM, which replaces scalar memory with a matrix memory (covariance/outer-product updates) for much higher storage capacity and parallelizability. While mLSTM excels at associative memory and large-capacity retrieval (and is parallelizable), it lacks the recurrent memory mixing that gives sLSTM its distinctive state-tracking power.

The practical upshot is that combining sLSTM blocks (for stateful, algorithmic components) with mLSTM blocks (for high-capacity associative storage) in residual stacks yields architectures that can both (a) track and revise compact stateful summaries and (b) store/retrieve large associative memories. The experiments show mixed xLSTM variants often perform best across diverse tasks.

## Takeaways

- Exponential gating (with normalization and stabilization) makes it possible for a scalar LSTM to revise stored values aggressively and stably, a capability limited in classical sigmoid-gated LSTMs.
- Memory mixing (recurrent hidden→gate/input connections) across scalar cells enables sLSTM to implement genuine state machines and state-tracking algorithms that many attention-only or SSM architectures cannot.
- Organizing scalar cells into heads (mixing within heads, not across them) gives a structured, modular way to compose many local state trackers.
- Empirically, sLSTM-based blocks succeed on formal-language tasks (parity and similar) where models without memory mixing fail, demonstrating that this design choice restores important algorithmic capabilities even in small residual-block architectures.

If your application requires exact or revisable state tracking—parsing structured protocols, precise program evaluation, counters, or other algorithmic operations—sLSTM’s combination of exponential gating and memory mixing is worth a close look. The paper’s broader xLSTM design shows that pairing sLSTM’s stateful strengths with mLSTM’s larger associative memory leads to competitive, scalable language models that retain classical recurrent advantages.



# Inside an xLSTM Block: Residual Backbones Without the Attention Tax

xLSTM revisits the LSTM idea with two key extensions — exponential gating and richer memory structures — then plugs those into familiar residual backbones to produce models that compete with modern Transformers and State Space Models without paying the quadratic attention cost. This post drills into the design of an xLSTM block: what it does, why the block uses a pre- or post-up-projection path, and how stacking those blocks yields a full xLSTM architecture that summarizes history efficiently and scales well.

## The design goal: make past context more linearly separable

A central motivation behind the xLSTM block is to produce representations of past context that are easier to separate downstream. Intuitively, if different histories map to representations that are more linearly separable, a simple readout can correctly predict the next token. xLSTM leans on the same intuition as Cover’s theorem: nonlinearly embedding inputs into a higher-dimensional space increases the chance that different patterns (histories) become linearly separable.

Practically, an xLSTM block is a small residual module that (a) summarizes past context nonlinearly, (b) temporarily lifts that summary into a higher-dimensional space, and (c) projects back to the model space. The order of those steps — whether you up-project before the nonlinear summary or after — is an architectural choice with implications for where you want the memory to live.

## Two block styles: pre up-projection and post up-projection

xLSTM uses two residual block styles that mirror designs in contemporary LLMs and recent sequence models:

- Post up-projection (used with sLSTM): the block first performs a nonlinear summarization in the model’s native dimensionality, then up-projects to a higher-dimensional space, applies an activation, and projects back down. This is conceptually similar to Transformer feed-forward blocks that summarize and then expand/contract. The post-up route is a good fit for sLSTM (the scalar-memory variant with memory mixing) because sLSTM’s strengths are in mixing and refining scalar cell memories; the nonlinear summarization before the up-projection is where that mixing is most effective.

- Pre up-projection (used with mLSTM): here, inputs are first linearly mapped into a higher-dimensional space, then the nonlinear summarization (the memory update and readout) happens in that expanded space, and the result is projected back. This path is preferable for mLSTM, which uses a matrix memory; giving the memory operations the higher-dimensional workspace increases effective capacity and lets retrieval (matrix-by-vector) operate where it has the most room to store and separate many key–value interactions.

The paper uses post up-projection blocks for sLSTM-based xLSTM blocks and pre up-projection blocks for mLSTM-based ones, leveraging where each memory type benefits most from extra dimensionality.

## What an xLSTM block actually contains (conceptually)

An xLSTM block is a residual unit composed of these building pieces:

- A pre-LayerNorm on inputs (the same normalization pattern used in many modern LLMs) to stabilize training.
- A small projection network that either lifts inputs into a higher-dimensional space (pre-up) or applies a nonlinear summary first and then lifts (post-up).
- A memory module (an sLSTM or an mLSTM) that performs the time-recursive update and readout:
  - sLSTM: scalar memory cells with exponential gates and a normalizer state; supports memory mixing via recurrent connections (hidden-to-hidden).
  - mLSTM: matrix memory that stores key–value outer products (a covariance-style update). It uses exponential input gating as a learned write rate and a forget gate as a decay; retrieval is matrix-vector multiplication normalized by the accumulated key strength.
- A projection back to model space followed by adding the block’s residual (skip) connection.

That residual structure means each block learns a refined incremental update to the representation of history; stacking many such blocks makes the model progressively richer while retaining the advantages of residual optimization.

## Why exponential gates and where memory mixing matters

xLSTM departs from classic LSTM gating by allowing exponential activations for some gates (stabilized by additional bookkeeping states). Exponential gates let the model revise storage decisions more sharply: a newly written item can be amplified or attenuated relative to past contents in a multiplicative way that is more expressive than the standard sigmoid gating.

Memory mixing — i.e., hidden-to-cell recurrent connections across cells — remains available in sLSTM and is important for state-tracking tasks that require sequential adjustments to internal state. This capability is what lets sLSTM-based blocks solve tasks dependent on tracking histories (something purely feed-forward or memoryless attention approximations cannot do as easily).

mLSTM, by contrast, intentionally abandons memory mixing so it can be implemented in a fully parallel (scan-free) manner. The matrix memory plus covariance-style updates produce a compressive associative store that is highly expressive for key–value retrieval, while staying linear in sequence length because updates and reads are incremental and do not require quadratic pairwise token comparisons.

## Stacking blocks into xLSTM architectures

Full xLSTM models are assembled by residually stacking many xLSTM blocks, following the common pre-LayerNorm residual backbone used across modern LLMs. Blocks can be homogeneous or mixed: the paper reports hybrids (e.g., mostly mLSTM blocks with a few sLSTM blocks) so the architecture benefits from both large associative memory capacity (mLSTM) and the state-tracking/mixing power of sLSTM.

Because each block compressively summarizes history, the stack builds a progressively more separable representation of longer histories. This leads to several practical outcomes the paper emphasizes:

- Linear computation and constant working memory with respect to sequence length — a major difference to attention-based models whose attention cost is quadratic in context size.
- Competitive scaling behavior: when scaled and trained on modern corpora, xLSTM variants match or outperform many Transformer and SSM baselines in language modeling.
- Better extrapolation to longer context lengths in tests reported in the paper, attributed to the compressive, associative memory and the block-wise separability improvements.

## Practical trade-offs and where each block style is used

- mLSTM-based blocks are parallelizable and well suited for large-scale training when you want associative, matrix-based memory with high capacity. Put these in pre up-projection blocks so the memory lives and operates in the expanded space.
- sLSTM-based blocks keep memory mixing and the constant-error-carousel tradition of LSTMs; they excel at explicit sequence state tracking. Use post up-projection blocks for sLSTM so the hidden mixing happens before you lift into the higher-dimensional activation space.
- Hybrids mix both: relying mainly on mLSTM blocks for capacity and inserting sLSTM blocks where local state mixing is critical.

## Takeaway

An xLSTM block is a deliberately engineered residual cell: normalize, (optionally) lift dimensionality, nonlinearly summarize and update a memory, then project back and add the residual. The pre/post up-projection decision is not cosmetic — it reflects whether the memory should operate in the model’s native space (sLSTM) or in an expanded workspace (mLSTM). Stacking these blocks yields architectures that keep the linear memory and compute advantage of recurrent/association mechanisms while gaining much of the separability and representational power that large Transformer stacks achieve — without the quadratic attention tax.



# Speed, Memory, and Context: How xLSTM Competes with Transformers and SSMs

## Quick takeaway
xLSTM is an updated LSTM family that brings two engineering changes that matter for real-world deployment: (1) exponential gating (with stabilization) that lets the model revise and weigh stored information more flexibly, and (2) a matrix memory variant (mLSTM) that stores key–value outer products so retrieval behaves like a learned associative memory. Together, these let xLSTM offer linear-time decoding with constant memory in sequence length, robust long-context behavior, and high batch-throughput during generation — while still having a few practical speed/cost trade-offs today.

Below I translate the paper’s main engineering claims into concrete expectations for inference and deployment.

## Why decoding is linear-time and constant-memory
Transformers perform attention over all token pairs in the context, yielding O(L^2) compute and O(L) intermediate memory for context length L. xLSTM instead compresses past information into a fixed-size recurrent memory, so:

- sLSTM retains scalar cell states (like classic LSTM) but adds exponential gates and a normalizer state to stabilize their effect.
- mLSTM stores a matrix memory \(\mathbf{C}_t \in \mathbb{R}^{d\times d}\) updated by a covariance (outer-product) rule
  \(\mathbf{C}_t = f_t \mathbf{C}_{t-1} + i_t \, \mathbf{v}_t \mathbf{k}_t^\top\).

Because the recurrent cell or matrix memory compresses history into a fixed set of tensors whose size depends on model width \(d\) but not on L, xLSTM’s per-token compute is O(d^2) (for mLSTM) or O(d) (for sLSTM with mixing), and peak memory use during decoding is constant with respect to context length. In short: decode time grows linearly with generated tokens and memory does not blow up with long contexts.

## Why xLSTM handles longer contexts and larger batches
Two complementary mechanisms matter:

1. Compressive memory: mLSTM’s \(\mathbf{C}_t\) and the normalizer \(\mathbf{n}_t\) accumulate past keys/values with forget and input gates acting like decay and learn rates. This compressive representation prevents working memory from scaling with L and enables retrieval via a fixed-size matrix product \(\mathbf{C}_t \mathbf{q}_t\). The paper shows that, empirically, xLSTM maintains low perplexities when extrapolating to contexts far beyond training length (tested up to 16k), suggesting the memory does not overload for those sizes.

2. Batch-friendly inference: Because memory and activations are fixed-size, large batch decoding is much more feasible than for Transformers that must materialize cached key/value tensors proportional to the past context. The experiments report that xLSTM can use much higher batch sizes than a Transformer like Llama — enabling higher maximal throughput for decoding.

Consequence: for workloads that need long contexts or high batch throughput (many independent sequences decoded in parallel), xLSTM can be materially more efficient in wall-clock throughput and memory footprint.

## Generation time and throughput: what the experiments show
The paper reports three key empirical points comparing xLSTM, Llama (Transformer), Mamba (SSM), and RWKV (RNN):

- Generation time scales linearly with requested context for xLSTM and other recurrent models, while Transformer generation time grows quadratically as context grows (because of the quadratic attention cost). This makes xLSTM preferable for long-context generation in wall-clock time.

- Maximal decoding throughput (tokens/sec) benefits strongly from xLSTM’s constant memory per sequence: with higher batch sizes allowed, xLSTM achieves higher throughput than Llama in the experiments. The authors report xLSTM achieves the highest throughput among tested models at 1.3B scale, because it can use larger batch sizes without exhausting GPU memory.

- Practical timings: the authors built a fast CUDA kernel for sLSTM (because it is sequential), and report it is typically less than two times slower than the parallel mLSTM implementation. However, mLSTM’s CUDA kernels are not yet optimized; current mLSTM is about 4× slower than highly optimized FlashAttention or the scan used by Mamba. This means raw per-flop efficiency for mLSTM can improve substantially with optimized kernels.

In short: xLSTM shows favorable generation latency scaling and wins on throughput due to constant memory, but absolute runtime depends on kernel-level optimizations.

## Where xLSTM currently lags (practical engineering trade-offs)
The paper is explicit about limitations you should expect today:

- sLSTM is not parallelizable across time because it uses memory mixing (hidden–hidden recurrence). That prevents using fast, fully parallel kernels. The authors mitigated this by implementing a custom CUDA kernel, making sLSTM “typically less than two times slower than mLSTM” in practice, but that still means sLSTM inference is more expensive per token than a fully parallel operator.

- mLSTM is parallelizable (no hidden–hidden mixing) but its matrix memory updates involve d×d operations and current kernels are not optimized. The authors measure their mLSTM implementation as about 4× slower than FlashAttention or the scan used by SSMs like Mamba. So while mLSTM can be parallel, the current implementation yields a compute overhead that could be reduced with specialized kernels (akin to FlashAttention-style optimizations).

- Computational cost vs memory capacity: the matrix memory increases storage capacity but costs O(d^2) compute per update and retrieval. This is a trade-off: better associative recall and rare-token prediction in exchange for heavier compute. The paper notes that these matrix ops are parameter-free and can be parallelized, so wall-clock overhead is modest, but the theoretical per-token FLOP count is higher than a small Transformer block.

- Forget-gate initialization and stability: exponential gating helps with revising storage decisions, but it needs stabilizers (the paper uses a stabilizer state \(m_t\) and normalization) and careful initialization to avoid numerical issues and overflows.

## Practical expectations for edge deployments
xLSTM’s constant-memory decoding is a strong advantage on devices or environments with tight memory budgets (edge GPUs, limited-VRAM servers, mobile inference where model size fits but dynamic memory is limited). Expect:

- Lower peak memory for long-context generation compared to Transformers. You can keep contexts long without caching O(L) past key/value tensors.

- Higher achievable batch sizes for parallel queries, improving aggregate throughput in server scenarios that multiplex many clients.

- A possible CPU/accelerator cost increase per token if you use mLSTM with large \(d\), due to the \(d\times d\) updates, unless you have optimized kernels. Conversely, sLSTM on edge devices may still be attractive if you can accept sequential processing per sequence and use the optimized CUDA path (or a well-optimized CPU loop for small models).

- Opportunity: with further kernel engineering (FlashAttention-like techniques for the mLSTM matrix ops), the runtime gap reported in the paper (current 4× slower vs FlashAttention) could shrink substantially, making xLSTM strictly superior in both memory and speed for many long-context workloads.

## Putting it together: when to pick xLSTM
Choose xLSTM when your application needs any of the following:

- Very long contexts (thousands to tens of thousands of tokens) with limited memory headroom.
- High aggregate throughput by serving many sequences in parallel (large batches) without exploding memory.
- Better handling of rare-token prediction or associative recall tasks where matrix memory (mLSTM) improves storage capacity.

Be cautious when:

- Latency per single sequence is the dominant metric and you can’t afford sequential recurrence — sLSTM’s recurrence limits parallelism. Use mLSTM when parallelism is essential, but expect higher compute unless kernels are optimized.
- You need the most optimized per-flop throughput right now: current mLSTM kernels are slower than highly-tuned FlashAttention; expect that to improve with engineering.

## Final note
xLSTM restores and modernizes core LSTM strengths (gating, structured memory) with engineering additions that make it competitive in the LLM-era trade space: linear-time decoding, constant memory in context length, and strong empirical scaling for language modeling. The model’s current drawbacks are primarily engineering-level (kernel optimizations and sequential recurrence), meaning the practical gap to Transformers on raw speed can shrink as implementations mature — while xLSTM’s constant-memory behavior already makes it attractive for long-context and high-throughput deployments, especially at the edge.



# Do xLSTMs Scale? What the 15B and 300B Token Results Really Say

## TL;DR
The xLSTM paper scales enhanced LSTMs to modern LLM sizes and tests them on two large-scale regimes: models trained on 15B tokens and models trained on 300B tokens of SlimPajama. Across validation perplexity, downstream reasoning tasks, per-domain perplexities (PALOMA, 571 domains), and long-context extrapolation (up to 16k), xLSTM variants—especially the mLSTM-only variant xLSTM[1:0] and the mixed xLSTM[7:1]—consistently outperform leading Transformer, State Space, and RNN baselines in these experiments. The measured scaling laws follow power-law trends similar to other families but with a clear offset advantage for xLSTM, implying the gap should persist (or widen) at larger model sizes.

Below I walk through the experimental evidence, explain what the scaling plots mean in plain terms, and highlight the practical takeaways and caveats.

## What was tested
The paper compares xLSTM against representative models from three classes:
- Transformers (e.g., GPT-3, Llama),
- State Space Models (SSMs) (e.g., Mamba, H3),
- Recurrent/linear attention methods (e.g., RWKV variants, RetNet, GLA, HGRN/HGRN2).

Key experimental axes:
- Validation perplexity after training on 15B tokens (SlimPajama) — a direct language-modeling quality measure.
- Larger-scale training on 300B tokens: (i) context-length extrapolation up to 16k (models trained with context 2048), (ii) validation perplexity across multiple model sizes (125M–1.3B), (iii) downstream common-sense reasoning tasks, (iv) domain-wise next-token perplexity on PALOMA (571 domains), and (v) scaling-law behavior.
- Generation timing and decoding throughput at 1.3B scale to contrast constant vs. quadratic memory regimes.

Two xLSTM configurations are emphasized:
- xLSTM[1:0]: all blocks use mLSTM (matrix memory, parallelizable).
- xLSTM[7:1]: a majority of blocks are mLSTM with some sLSTM blocks (adds memory mixing).

## 15B-token results — validation perplexity
When trained on 15B tokens, xLSTM models achieve lower validation perplexities than the tested Transformers, SSMs, and RNN-based baselines (the paper compares matched-size models roughly corresponding to a GPT-3 350M configuration). The ablation studies show that two ingredients are primarily responsible for the gain:

1. Exponential gating (stabilized via a normalizer and max-stabilizer): helps revise storage decisions and improves temporal credit assignment.
2. Matrix memory (mLSTM): increases storage capacity and improves rare-token prediction / associative recall.

Bottom line: in the 15B-token regime, xLSTM yields a measurable improvement in the language-modeling objective versus strong baselines.

## 300B-token regime — what changed and why it matters
Scaling to 300B tokens is closer to realistic LLM data budgets. The paper presents several focused evaluations for models trained on 300B tokens at multiple parameter scales (125M–1.3B).

1. Length extrapolation (context up to 16k). Models were trained with context length 2048 and evaluated up to 16k. xLSTM models maintain low perplexities as context length increases, whereas comparators degrade faster. This suggests xLSTM’s memory mechanism (matrix memory + gating) generalizes better to longer contexts than the baselines tested.

2. Validation perplexity and downstream tasks. For all model sizes, both xLSTM[1:0] and xLSTM[7:1] were the best on SlimPajama validation perplexity. On a suite of downstream common-sense reasoning tasks, xLSTM models are the best in most tasks and sizes (with occasional wins by Mamba on ARC). This indicates that improved perplexity translates to stronger task performance, not just marginal log-loss gains.

3. PALOMA (571 domains). xLSTM[1:0] beats Mamba in 568/571 domains (99.5%), Llama in 486/571 (85.1%), and RWKV-4 in 570/571 (99.8%) at next-token perplexity. This per-domain consistency suggests xLSTM improvements are broad and not concentrated in a small subset of domains.

4. Scaling laws. The measured learning curves across model sizes follow power-law trends (loss roughly falling as a power of model size). xLSTM shares the same slope/shape as other families but sits at a better offset: for the same size and data regime, xLSTM has lower loss. Because all methods follow similar power-law exponents, an offset advantage typically persists as models scale: increasing size by a given factor reduces loss similarly across families, so the better-off family tends to remain better at larger sizes absent method-specific saturation.

5. Generation time and throughput. xLSTM (and other recurrent families) show linear generation-time scaling with context length and have constant memory in the context length dimension, unlike Transformers (quadratic memory without special caching). This enables higher batch sizes at decoding time and higher maximal throughput for xLSTM in the experiments reported. Practically, that means lower latency and better utilization for long-context decoding when memory is the bottleneck.

## Interpreting the scaling-law plots in plain language
The scaling-law plots depict model loss (or perplexity) versus model size on log–log axes and typically fit a power law:
loss(N) ≈ A * N^{-α} + C, where N is parameter count, α is the slope, and C is irreducible loss.

Two things to look for:
- Slope (α): how quickly performance improves as model size grows. A similar slope across families means they all benefit from scaling at comparable rates.
- Vertical offset (A or C differences): a model family with a lower curve (lower loss at same size) has an effective advantage; if slopes are similar, that advantage persists as you scale.

In the xLSTM experiments the slopes are similar between xLSTM, Mamba, and Llama, but xLSTM sits consistently lower—an offset advantage. Plainly: make every model 10× bigger, and xLSTM will still likely have the edge it has now, assuming the same data and training procedures apply.

## Practical takeaways
- xLSTM variants provide consistent, robust gains in perplexity across small to mid-range LLM sizes and continue to show advantages when scaled to 300B-token training budgets.
- The combination of exponential gating and matrix memory is the key driver: gating improves state revision and temporal credit assignment, matrix memory improves capacity (rare tokens, associative recall).
- xLSTM maintains performance across 571 diverse domains and extrapolates to much longer contexts (up to 16k) better than tested baselines.
- For deployment, xLSTM’s linear compute and constant memory in sequence length make it attractive for long-context generation, enabling higher decoding throughput versus quadratic Transformers without special engineering.
- Measured scaling laws indicate the advantage is not a fluke at one size: similar power-law slopes with a vertical offset imply xLSTM should remain competitive at larger scales.

## Caveats and limitations (important to keep in mind)
- sLSTM memory mixing prevents full parallelization; the authors' fast CUDA kernel is reported to be less than 2× slower than the parallel mLSTM but is still sequential. mLSTM is parallelizable, but its matrix memory has $d\times d$ computational costs per step.
- mLSTM CUDA kernels are not yet highly optimized and are reported ~4× slower than FlashAttention or some fast scans; engineering improvements could change cost trade-offs.
- The matrix memory size is fixed per-layer: extremely long contexts could overload the compressive memory, though experiments up to 16k did not reveal this as a problem.
- The experiments reported did not fully hyperparameter-tune large xLSTM models; further tuning could improve or change relative gaps.
- Results compare to a selection of baselines trained under similar conditions, but LLM performance is sensitive to many implementation details; independent replication and broader benchmarks are important.

## Final thoughts
The experimental evidence in the paper shows xLSTM is more than a nostalgic revisit of LSTMs: with targeted innovations (exponential gating + matrix memory) and modern residual/backbone design, LSTM-derived architectures can match and in these tests outperform contemporary Transformers and State Space Models on language modeling metrics, long-context extrapolation, and domain-wise perplexities. The scaling-law analysis suggests that xLSTM’s advantage is likely to persist as models grow, making xLSTM a credible architecture family for larger LLMs, especially where long-context efficiency and per-step memory constraints matter.

That said, the computational profile (matrix updates, parallelization trade-offs) and implementation maturity need attention before xLSTM can be considered a drop-in replacement in large production stacks. The results are promising and motivate more engineering and reproducibility work to confirm how these gains translate at truly massive scales.



# Where xLSTM Fits in the Model Zoo: RWKV, Mamba, Retention, and Beyond

## Overview

xLSTM is a modern redesign of the classic LSTM family that aims to bring recurrent memory models into parity with contemporary sequence learners. The paper introduces two concrete variants: sLSTM (scalar memory with exponential gating and new memory mixing) and mLSTM (matrix memory with a covariance update), and integrates them into residual block backbones to form full xLSTM architectures. The two central innovations are (1) exponential gating with stabilization and a normalizer state, and (2) a matrix memory that stores key–value outer products (covariance updates). These changes target three traditional LSTM limitations: inability to revise storage decisions, limited storage capacity of scalar cells, and lack of parallelizability.

Below I position xLSTM relative to the major families of recent sequence models (Transformers, State Space Models, RWKV-like RNNs, Retention / Fast-Weight models, and linear-attention methods like Performer/Linear Transformer), summarize where xLSTM overlaps conceptually with them, and give a practical guide to when xLSTM is a good choice versus alternatives — all grounded in the results and claims from the paper.

## Core ideas of xLSTM (quick recap)

- Exponential gating: input gates (and optionally forget gates) use an exponential activation, i.e.  
  i_t = \exp(\tilde{i}_t), and f_t can be \sigma(\tilde{f}_t) or \exp(\tilde{f}_t). Because exponentials can blow up, xLSTM introduces a stabilizer state m_t and uses normalized gates i'_t, f'_t that preserve exact forward outputs and gradients while avoiding overflow.
- Normalizer state: accumulates the weighted sum of gate coefficients (scalar case) or of keys (matrix case) to normalize retrievals and to keep track of effective stored mass across future forget gates.
- sLSTM: keeps scalar (or low-dimensional vector) cells but uses exponential gating plus a new memory-mixing pattern (including multi-heads and per-head mixing) to enable stronger state-tracking and revisable storage behavior.
- mLSTM: replaces scalar cell c with a matrix memory C \in \mathbb{R}^{d\times d} and updates it with a covariance (outer-product) rule C_t = f_t C_{t-1} + i_t v_t k_t^\top. Retrieval is via C_t q_t, normalized by |\mathbf{n}_t^\top q_t| (clamped lower bound) and gated by an output gate. This is equivalent in spirit to Fast Weight / associative memory updates.

## Conceptual overlaps

- Gating family (shared idea): Many recent models reuse gating concepts. xLSTM continues this tradition; gating plays the same structural role as in HGRN, GLA, GSS/BiGS, RWKV, and Mamba. The paper’s ablations emphasize that learnable, input-conditioned gates provide incremental gains.
- Covariance / fast-weight updates: mLSTM’s matrix memory and outer-product update are conceptually aligned with Fast Weight Programmers, Retention, certain RWKV variants, and other approaches that use associative updates (e.g., some linear-attention formulations). The covariance update rule in mLSTM is the classical v k^\top construction used by these methods.
- Linear-in-context complexity: Like many RNNs, SSMs, and linear-attention variants, xLSTM’s recurrent formulation has computation and memory that scale linearly in sequence length, and its memory state is constant with respect to context length. The paper places xLSTM with other linear or linearizable methods in that regard.

## Crucial differences (what xLSTM brings uniquely)

- Exponential gating with memory mixing (sLSTM): The exponential gate plus a dedicated normalizer and stabilizer state is a distinct element that directly addresses the “revise storage decisions” limitation. The paper demonstrates that classic LSTMs fail at tasks like nearest-neighbor search where an earlier stored value must be revised when a better match appears; sLSTM with exponential gating can revise storage because the multiplicative chain of future forgets and exponential inputs can be normalized to allow proper replacement.
- Matrix memory with normalized retrieval (mLSTM): Rather than using attention's pairwise querying over stored tokens, mLSTM stores compressed associative memory via \mathbf{C}_t and retrieves via matrix–vector multiplication \mathbf{C}_t \mathbf{q}_t, normalized by the dot with the normalizer state. This increases storage capacity beyond scalar cells while remaining conceptually simple and parameter-free for the memory updates.
- Memory mixing vs. fully parallelizable recurrence: sLSTM preserves memory mixing (hidden–hidden recurrent weights) to enable state-tracking tasks that require mixing across memory cells, which Transformers and many SSMs struggle with. mLSTM, by contrast, drops hidden–hidden mixing to enable a fully parallel (scan-free) formulation akin to FlashAttention-style parallelism. Thus xLSTM provides two complementary trade-offs in the same family: expressive recurrent mixing (sLSTM) and parallel, high-capacity associative memory (mLSTM).
- Normalizer state and stabilizers: The explicit normalizer that accumulates gate-weighted keys (or gate weight sums in the scalar case) and the numerical stabilization rules for exponential gates are implementation-level innovations that preserve meaningful gradients while enabling exponentials.

## Empirical behavior (claims from the paper)

- Synthetic and diagnostic tasks: sLSTM’s exponential gating + mixing solves formal-language/state-tracking tasks that Transformers/SSMs cannot, highlighting the importance of memory mixing for state-tracking. On associative-recall tasks (many key-value pairs and long contexts), mLSTM-based xLSTMs perform best among non-Transformer methods and allow extrapolation to longer contexts.
- Language modeling (SlimPajama experiments): When trained on 15B tokens, xLSTM models outperform a range of baselines (Transformers like Llama, SSMs like Mamba/H3, and RNNs like RWKV variants) in validation perplexity. With larger 300B-token training runs, xLSTM maintains favorable perplexities, better long-context extrapolation, and competitive downstream task performance; scaling laws suggest xLSTM should remain competitive at larger sizes.
- Efficiency trade-offs: mLSTM is parallelizable and has constant memory with respect to context length but is computationally heavier per step due to d\times d matrices. sLSTM keeps memory mixing (expressivity) but cannot be fully parallelized; a specialized CUDA kernel reduces the speed gap to mLSTM to less than 2x in the authors’ implementation. Compared to Transformers, xLSTM’s recurrent or associative-memory nature yields linear scaling in context length (better memory usage and higher throughput for large batch sizes).

## Practical buyer’s guide — when to favor xLSTM

Use xLSTM (sLSTM- or mLSTM-driven) when any of the following apply:

- You need state-tracking or revisable storage. If the task requires maintaining and updating internal state (e.g., program evaluation, entity tracking, formal grammars), sLSTM’s memory-mixing plus exponential gating is specifically designed for such problems and outperforms models that lack recurrent mixing.
- You want improved storage capacity compared to scalar-cell RNNs but want to avoid attention’s quadratic memory in context length. mLSTM’s matrix memory increases capacity via associative outer-product updates while keeping memory constant in sequence length.
- You need better long-context extrapolation than standard Transformers or SSMs: experiments show xLSTM maintains lower perplexities when extrapolating to much longer contexts than seen at training time.
- You need a model with linear memory w.r.t. sequence length for large batch decoding and high throughput. Because the recurrent memory state is independent of context length, xLSTM can use much larger batch sizes and achieve higher decoding throughput than Transformers with KV caches.
- You prefer an architecture that empirically scales well (per the paper’s scaling-law analysis) and can compete with Transformer and SSM baselines at both 15B-token and 300B-token regimes.

When to prefer alternatives

- Transformer (attention) if your primary concern is maximal parallel throughput for typical transformer-optimized inference stacks and you rely heavily on very large, highly optimized tooling for attention (or you need the exact inductive biases of self-attention). Transformers still offer very efficient, heavily optimized inference kernels and are the dominant engineering stack.
- State Space Models (SSMs) / Mamba if you want a linear-in-context, highly parallel model with strong empirical performance and simpler per-step computations; SSMs are lightweight and often simpler to optimize from a compute-efficiency perspective.
- RWKV and other RNN variants if you need very simple, linear recurrence with low per-step cost and are already committed to RWKV-style implementations; however, according to the paper, xLSTM outperforms RWKV variants on perplexity and long-context extrapolation in their experiments.
- Attention or linear-attention methods for tasks that fundamentally rely on pairwise comparisons across the whole context where Transformers’ implicit exponential memory in coding dimension is an advantage (the paper shows Transformers remain gold-standard on extreme associative recall tasks with many key-value pairs due to their exponential memory in coding dimension).

## Implementation and cost considerations

- mLSTM increases per-step computation because of d\times d memory matrices and updates. These matrices are parameter-free (the update uses outer products of projected inputs), but the runtime cost is non-trivial; the authors note their current mLSTM CUDA kernels are not yet as optimized as FlashAttention and are roughly 4x slower in their implementation.
- sLSTM retains recurrent mixing (hidden–hidden connections) and cannot be trivially parallelized across time, but a specialized CUDA kernel made by the authors achieves near-parallel runtimes (within about 2x of mLSTM in their experiments).
- Numerical care is required: exponential gates must be stabilized (m_t stabilizer) and forget gate initializations need tunings. The authors highlight sensitivity to forget gate initialization and the need for careful stabilization to avoid overflow.
- Memory trade-offs: mLSTM’s memory capacity is independent of sequence length but scales with d^2. For very large d this can become heavy; this is an explicit trade-off between capacity and compute.

## Final takeaway

xLSTM is not just another gated RNN: it combines two orthogonal, practical changes that address longstanding LSTM limitations. Exponential gating with a normalizer enables revisable, well-conditioned storage decisions and stronger state tracking (sLSTM), while a matrix covariance memory (mLSTM) gives associative, parallelizable storage with higher capacity than scalar cells. Empirically, xLSTM closes the gap to Transformers and SSMs in language modeling and exhibits favorable scaling and extrapolation behavior.

If your problem requires strong state-tracking, revisable memory, or efficient long-context inference with linear memory cost, xLSTM deserves serious consideration. If your stack depends on heavily optimized Transformer kernels or your use case benefits from attention’s particular inductive biases, Transformers or tuned SSMs may still be preferable. The most pragmatic approach is to weigh the need for memory mixing and associative capacity against the compute cost of d\times d updates and the current state of available kernels — the paper shows that xLSTM can be a competitive middle ground in many real-world sequence-modeling settings.

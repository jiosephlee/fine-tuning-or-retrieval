# Why Coding First Boosts Numerical Reasoning  

When an LLM starts its learning process by digesting huge amounts of source‑code rather than textbook prose, it ends up doing far better tricks at arithmetic tasks — everything from plain chain–of–thought questions shorted by manual calculations to fully programmatic solutions that invoke Python libraries such as `sympy`. Below I break down *why* that happens and what the concrete evidence looks like in practice.


--------------------------------------------------------------------

## The background story

Typical large language models toil through billions of tokens scraped from news sites, books, discussion forums and paid corpora before they ever see specialized mathematics material. Because “math” remains relatively sparse among these cosmic seas of language data, most LLMs still get stuck when they try to push through multi‑step gradeschool or college puzzles — even when their parameters live side-by-side with top closed models such as GPT‑4 or Gemini Ultra.”

Enter *DeepSeekMath*: instead of wasting precious capacity chasing conventional prose while hoping random pages contain algebraic symbols somewhere hidden away, the team around DeepSeekMathematics decided  
1️⃣ start with an already solid rich–coder backbone (**DeepSeek‑Coder‑Base v1 .5**, ≈7 B parameters trained solely on source-code)  
2️⃣ overlay it with an atlas–level collection of truly mathematical text pulled cleanly out of Common Crawl – *120 B *tokens*, pulled via an intensive fastText pipeline tuned against high quality reference sets like OpenWebMath.



--------------------------------------------------------------------

## “Coding first” actually means more than just syntax

A coder’s playground lives full of four golden rules that coincide naturally with deductive thinking:
```
if   → choose more than one branch,
else → pick a fallback path,
for … loop     → repeat computation systematically,
return value     → finish a subproblem cleanly,
```
Each rule puts an explicit *flow chart* into the neural layers:
* conditionals teach pattern recognition under uncertainty,
* loops instill stable state updates,
* function calls encourage modular subproblem solving.



In practice this looks simply different decisions made right during token generation:
```text
Let x = ..., 
Then compute …
```
which mathematically corresponds roundly to looping over summands or controlling case analysis.



--------------------------------------------------------------------

## Two ways they mixed language and number  

| Strategy | Sequence | Outcome |
|----------|----------|-----------|
| **Two‑stage** | Code → Math | Big lift on tool–based solves (`Python`+`sympy`) after adding ≈150 B new maths tokens |
| **One–stage mix** | Simultaneous [400 B × code]+[150 B × math] | Keeps strong coding recall while smoothing forgetting — still produces larger boosts than dropping either source |

Both experiments are guided by::

* No architectural changes  
* Same hyper‑parameters apart from token budget  
* Downstream evaluation remains identical  


Therefore both approaches confirm *the recurrence of programming jargon actually assists pure deductive chains — even without any later automatically generated script.*


--------------------------------------------------------------------

## Why does logical flow translate so well?

Below are three DSL patterns directly mapped onto popular numerical steps:

| DSL pattern | Example expression | Matching maths step |
|-------------|-------------------|---------------------|
| Conditional branching (`if ... else`) | `.when(a > b)`     | Case split (“if `a>0`, treat otherwise”) |
| Loops (`for i=1…n`)            | `.iter()`         | Iterative summation / accumulation |
| Function calls (`func(x)`)      | `.sqrt()`         | Modular extraction — isolate helper formula |

When you read *“compute ∑x_i through loop”*, your thoughts automatically separate variables neatly into consistent passes — exactly what the LLM learned during massive source-code ingestion! Thus abstract algebraic identities become almost mechanical when seen aloud through token sequences shaped by earlier string-edit experiences.



--------------------------------------------------------------------

## Benchmarks make clear evidence

### English (GSM8K / MATH)

After adding programming experience:

1️⃣ Accuracy jumped notably versus a vanilla maths-only seed small model  
2️⃣ Tool-enabled solves (~Python+`sympy`) improved even more dramatically  

> *Result*: With reinforcement learning later employed (GRPO), DeepSeekMath‐Instruct hit roughly **88 %** accuracy on GSM8K and over **51 %** marked off competition level problems on MATH — beating every other openly released 7–70 B parameter contender.



### Chinese (CMATH / Gaokao)

Because the same commons-text extraction also fetched non–English pages:

* Models began approaching English performance levels—an otherwise hard-to-reach feat without multilingual prompts alone  
* Gains were missing only in geometry-heavy provinces & theorem proving — suggesting remaining gaps belong mainly to data coverage rather than fundamental tooling

+-----------+---------+-----------+

## Post‐Fine–Tuning Reinforcement Step

Although large peaks were already visible after instruction tuning (**DeepSeekMath-Instruct**), further lift came quickly via an efficient actor–only RL scheme called **Group Relative Policy Optimization (GRPO)**:

* Uses multiple samples per prompt instead dependently building separate value function networks  
* Keeps baseline determined by group averages => cheaper memory O(less) compared with PPO’s critic appending ~10× memory footprint  

When starting GRPO off an already coded baseline:

```
GSM8K ↑ → ~88%                      // overall >90%
MATH ↑   → +3–4 points due purely 
          to reward-refresh without KL catastrophes
```

Critically GRPO also rebalances model distributions so errors slip lower beyond top scores — explaining its higher *Maj@K*, while *Pass@k* rarely changes because logic core stayed intact.



--------------------------------------------------------------------

## Takeaway Takeit▸   

1️⃣ **Programming provides scaffolding identical enough** that multi-step calculation can often be seen as “call until finished”.

2️⃣ Reusing coins...coder streams cuts down required token budget—and speeds up convergence without heavy piracy tricks or huge corpora floods usually needed by purely maths expansions.


3️⃣ That synergy also flows nicely into Chinese evaluations because our crawler retained hundreds of thousands non-English web page sources which were instrumentally different from earlier English-only corpuses.

### Quick checklist if you want your own “Coding first” LLM

```text
↓ Step-by-step checkout sequence:
1️⃣ Select broad source-code benchmark set (~150–200M lines).
2️⃣ Train sparse wide encoder backbone (~7 Bi).
3️⃣ Add ≥100 Bi well cleaned maths seeds (~120 Bi).
4️⃣ Rinse SFT instruction set (+π~400K examples w/ Chain-of-Tho​ught).
5️⃣ Refine policy via group-based reward replay (GRPO) if needed.
→ Expect naturally higher arithmetic aptitude across languages!
```

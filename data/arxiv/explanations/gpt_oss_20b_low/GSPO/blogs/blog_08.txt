# divide by sequence length
lengths   = y_i_lengths.float()              # shape: (batch,)
s_i = torch.exp( sum_log_ratios / lengths )  # shape: (batch,)
```

**Why this works**  
`π_θ(y|x) = ∏_t π_θ(y_t|x,y_<t)`  
Taking logs turns the product into a sum, so we can average over tokens and then exponentiate back to get a scalar ratio for the whole sequence.

---

## 3. Group Advantage Estimation  

Under GRPO each token shares the same advantage computed from its own response’s reward:

```python
adv_i = (reward_i - mean_rewards) / std_rewards
adv_t = adv_i.expand_as(logits_t)   # broadcast to tokens
```

In GSPO we keep that but only use `adv_i` in the objective—no token‑wise copy is required:

```python
adv_i = (reward_i - reward_i.mean()) / reward_i.std()
```

If you want per‑token granularity (GSPO‑token), just reuse `adv_t` as shown above; otherwise drop the expansion step.

---

## 4. Putting It Together: The GSPO Loss  

```python
def gspo_loss(pi_new, pi_old, x, ys, rewards):
    # ys: [batch, seq_len] int32 tokens
    # rewards: [batch] scalar reward per response

    # 1️⃣ compute log ratios per token
    log_new = pi_new.log_prob(ys).detach()          # detach pi_new probs
    log_old = pi_old.log_prob(ys).detach()          # detach pi_old probs

    # 2️⃣ sequence ratio s_i
    sum_log_ratio = (log_new - log_old).sum(dim=-1)
    lengths      = ys.ne(pad_token_id).sum(dim=-1).float()
    s_i          = torch.exp(sum_log_ratio / lengths)   # shape: (batch,)

    # 3️⃣ advantage per group
    adv_i        = (rewards - rewards.mean()) / rewards.std()   # shape: (batch,)

    # 4️⃣ clipped surrogate term (scalar clipping range)
    eps_clip     = torch.tensor((3e-4, 4e-4))                  # CLIP_MIN, CLIP_MAX
    clipped_s_i  = s_i.clamp(min=eps_clip[0], max=eps_clip[1])
    surrogate    = torch.min(s_i * adv_i, clipped_s_i * adv_i)

    loss         = -surrogate.mean()
    return loss
```

*Notes*  
* We detach `pi_new` when computing ratios because we only need gradients through `pi_current`.  
* The clipping range is **much tighter** than in GRPO (≈ 10⁻⁴ vs ~0.2), because `s_i` already averages over many tokens.

---

## 5. Practical Clipping Parameters  

| Algorithm | Typical clipping interval |
|-----------|----------------------------|
| PPO/GRPO  | `[0.8 , 1.2]` or `[0.2 , 0.27]` |
| GSPO      | `[3×10⁻⁴ , 4×10⁻⁴]` |

Why such a small interval?  
The exponential average smoothes away token‑level noise; therefore we only allow tiny deviations from unity before cutting off gradients.

If you observe unstable training, experiment with widening this band by ±5 % – but do **not** use DPIs or adaptive methods; keep it fixed during a run.

## 6. Memory Footprint & Speed  

Because GSPO eliminates the value network entirely:
- **RAM** drops roughly by half.
- **Gradient accumulation** over mini‑batches is cheaper (only one likelihood call per response).
- The entire loss can be computed on-the-fly from logits without an extra head.

This matches what we observed in Qwen3 fine‑tuning—training time per epoch went from ~18 h to ~12 h on identical hardware.

## 7. Handling Precision Discrepancies between Engines  

A common pitfall when moving from an inference engine (e.g., SGLang) to a training engine (e.g., Megatron) is that logits may be printed with different float formats (`float32` vs `bfloat16`). In GRPO this causes significant mismatch in token probabilities and blows up `w_t`.  

GSPO mitigates this thanks to sequence‑level ratios:
- **Token cancellations:** if one token’s logit differs slightly but another compensates, the overall exponentiated product stays stable.
- **Tolerance to rounding:** as long as each engine uses consistent deterministic sampling rules (`top_p`, `temperature`), their per-token logs still sum up close enough for `s_i`.

### Quick sanity check

```python
def check_plogits(old_logits, new_logits):
    overflow_ratio = torch.exp(new_logits.sum(-1) - old_logits.sum(-1))
    print(overflow_ratio.mean().item(), overflow_ratio.std().item())
```

If overflow variance > 20 %, recompute logits on the same engine or enable `torch.cuda.bfloat16`.

## 8. Summary Checklist for Engineers  

1. **Replace token ratio logic with sequence ratio (`s_i`).**  
2. **Use group mean/std advantage estimator (`adv_i`).**  
3. **Adopt tight clipping interval (~3‑4 × 10⁻⁴).**  
4. **Drop value network; remove KL penalty if not needed.**  
5. **Verify consistency of logits between rollout and optimizer engines; if not, re‑compute them using the same model copy or enable double precision at least for ratio computation.**

When all these bits are wired together, you’ll get:
- Stable training even for very long responses (> 200 tokens).  
- Natural support for MoE models without Routing Replay.  
- Half the memory footprint compared to PPO/GRPO.

Chapter 4: 6. Orthogonal Butterfly (BOFT) – Design & Implementation

Orthogonal Butterfly (BOFT) is a principled, scalable, and highly parameter‑efficient finite‑tuning method that extends the orthogonal finetuning (OFT) paradigm by employing a **butterfly factorization** of orthogonal matrices.  In BOFT, the left‑hand side weight modifier is not a single dense orthogonal matrix but a product of many sparse, structured orthogonal blocks.  This construction enables us to manipulate an entire $d$‑dimensional linear layer with only $\mathcal{O}(d\log d)$ trainable parameters while preserving the key desirable properties of OFT: identity initialization, controlled distance preservation via orthogonality, and stable training dynamics.

Below we present a rigorous exposition of BOFT’s mathematical formulation, its implementation details—including initialization and dropout regularisation—hyperparameter choices, and a complexity analysis that contrasts it to its OFT predecessors and LoRA.

---

## 6.1 Mathematical Formulation

### 6.1.1 Butterfly Components

Let \(k \geq 2\) be an integer power of two.  
A **butterfly factor** \(\mathbf{B}^{F}(k)\in\mathbb R^{k\times k}\) is defined as

\[
\mathbf{B}^{F}(k)=
\begin{bmatrix}
\operatorname{diag}(\mathbf{d}_1)   & \operatorname{diag}(\mathbf{d}_2) \\
\operatorname{diag}(\mathbf{d}_3)   & \operatorname{diag}(\mathbf{d}_4)
\end{bmatrix},
\]

where each \(\mathbf{d}_i \in \mathbb R^{k/2}\) is a trainable vector (or a block matrix when we generalise to \(b>2\)).  
The non‑zero pattern of this factor precisely matches the two‑way “butterfly” connections typically used in radix‑2 Cooley–Tukey FFTs: every input node pairs with exactly two output nodes.

For any dimension \(d=2^N\), we build the \(d\times d\) **butterfly matrix** \(\mathbf B(d)\) recursively:

\[
\mathbf B(d)
=
\tilde{\mathbf B}(d,d)\,
\begin{bmatrix}
\mathbf B(d/2)&0\\
0&\mathbf B(d/2)
\end{bmatrix}
=
\tilde{\mathbf B}(d,d)\,
   \tilde{\mathbf B}(d,d/2)\cdots
   \tilde{\mathbf B}(d,2).
\]

Here  
- \(\tilde{\mathbf B}(d,k)\in \mathbb R^{d\times d}\) places the butterfly factor \(\mathbf B^{F}(k)\) along the diagonal 
  (\(b=\frac dk=1,\dots,d/2,\dots , d/2^N=1\)).
- The recursion ensures that each butterfly component operates on contiguous subspaces of size \(k\).

Consequently, the overall butterfly matrix is a product of \(N = \log_2 d\) sparse block‑diagonal matrices.

### 6.1.2 Orthogonal Butterfly Parameterisation

In BOFT we treat each butterfly component as an **orthogonal** matrix.  
To guarantee this, each small block (\(j\times j,\; j=2b,\dots , 2b\,k /(k/2)) is parameterised via the Cayley transform:

\[
\bR_{j}
=\bigl(\bI+\bQ_{j}\bigr)\bigl(\bI-\bQ_{j}\bigr)^{-1},
    \qquad
    \bQ_{j}=-\,{\bQ_{j}}^\top,
\]
where each skew‑symmetric matrix 
\( \bQ_{j}\in \mathbb R^{j\times j}\)
encodes \(j(j-1)/2 = b(b-1)/2\,k/k=O(b)\) free parameters.
When \(k=2^n b\), the sparsity pattern of every component matches that of a standard FFT butterfly.

Collecting all components yields the **orthogonal butterfly matrix**
\(R(m,b)\):

```
R(m,b)=prod_{i=1}^{m} tildeB^b_(d,i)
```

with 

- **m** – number of butterfly layers (depth);
- **b** – base block size per component.
  
The actual forward pass for adapting a pretrained linear layer
\( W^0 \in \mathbb R^{d\times n}\)

```
z  = ( R(m,b) · W^0 )^T · x            (x ∈ ℝ^d , z ∈ ℝ^n)
```

is L = (total layers)*C operations plus equivalent cost for pre-multiplying
\(W^0^\top x.\)

### 6.1.3 Parameter Count

Each component introduces
\( O((b-1)d)\) effective trainable parameters because only the skew‑symmetric part
of every block is free: 
- For a block-size \(b\times b,\;
   |\text{skew-symmetric}| = b(b-1)/2.\)
- Each component has \( d/b \) such blocks,
  so total per component:
  \( (d/b)\times b(b-1)/2 = (b-1)d/2.\)

With **m** components we obtain

> **#parameters** = 
> ½ (b – 1)d m.

Specialisations:

| BOFT version | Special case | #parameters |
|--------------|--------------|-------------|
| BOFT(1,b)    | Block–diagonal OFT | ½(b–1)d |
| BOFT(1,d)    | Full OFT | ½(d–1)d →
approx λ*d² |
| BOFT(log d , 2)| Full butterfly | ≈ d log ₂ d |

Thus, by choosing **b = 2** and **m = log₂ d** we minimise parameter usage while preserving a dense transformation.

## 6.2 Implementation Details

### 6.2.1 Identity Initialization

For any orthogonal flyweight \(R(m,b)\), we initialise *every* skew‑symmetric matrix as the zero matrix:
\( Q_j =0.\)
The Cayley transform then reduces to the identity:
\( R(m,b)=I_d.\)

This choice guarantees:
- Initial loss exactly matches that of the frozen backbone;
- No bias or drift in early optimisation steps;
- Easier transfer learning from large pre-fitted models.

### 6.2.2 Multiplicative Dropout

Regular dropouts used in LoRA act additively on weight updates.
In BOFT we must preserve orthogonality after dropout; hence we introduce *multiplicative* dropout that targets specific components or blocks and temporarily replaces them with identity.

Algorithmic steps:

1. **Component Dropout:**
   - With probability \(p_1,\; i.i.d.\), replace entire butterfly component
     `tildeB^b_(d,i)` by identity.
   
2. **Block Dropout inside a Component:**
   - With probability \(p_2,\; i.i.d.\), replace each diagonal block
     within `tildeB^b_(d,i)` by an identity block.
   
Both dropouts are applied during training but omitted at inference.
They encourage sparsity in the effective transformation,
leading to improved generalisation in low‑data regimes.

### 6.3 Hyperparameter Choices

| Hyper‑parameter | Typical value | Effect |
|-----------------|---------------|--------|
| `m`            | log₂ *d*      | maximal expressive capacity; raising m beyond log₂ *d* yields diminishing returns because extra layers mainly reparametrise already dense map |
| `b`            | { 2,4,8,… }   | smaller `b` increases expressivity per parameter; larger `b` flattens structure but reduces param count |
| `p₁`            | [0,0.3]       | higher dropout induces stronger regularisation |
| `p₂`            | [0,0.3]       | fine-grained block dropping for local sparsity |
| Optimiser       | AdamW         | weight decay applied only to γ parameters (Cayley parameters). |

Practical guidelines based on empirical studies:
- For vision transformers (`image size`: >100M parameters),
  setting `m = log₂ d` and `b = 4` balances accuracy and runtime well.
- For language models (`hidden size` ≈12k),
  using `m = log₂ d`, `b=8` usually suffices for near‐full performance while keeping parameter count <10×10³.

## 6.4 Computational Complexity Analysis

Time complexity scales linearly with both depth *m* and dimension *d*:
  
> **Per-layer forward/backward cost** ≈ O(m · n · log₂ d),
> where n is output dimension.
  
Compared to:

| Method        | Parameters per layer        | Runtime vs training step      |
|---------------|----------------------------|------------------------------|
| Full Fine‑tune | O(d²)                      | baseline                     |
| OFT (block-diag)| O(b·d)                      | ~ same as full               |
| LoRA           | O(r·(n+b))                  | slightly cheaper             |
| BOFT(log ₂ d , 𝑏=𝟐 ) | O(d log ₂ d )                | higher than OFT but << full |

Memory overhead: Each butterfly component stores its skew‑symmetric parameters,
so total buffer ≈ ½(b−1)d m floats – modest compared to full fine-tuning.

The extra cost at training stems from repeated sparse matrix multiplications which can be efficiently implemented via BLAS *gemm* with custom kernels exploiting known sparsity patterns.
At inference, after training one can absorb the learned $R$ into $W$ ahead of time (`$W_{\text{finetuned}} = R W^0$`), incurring no run‑time penalty relative to baselines.

## 6.5 Special Cases Revisited

It is illuminating that several intelligent specialisations recover familiar freezing paradigms:

| Specialisation                           | Equivalent Known Method                                     |
|------------------------------------------|--------------------------------------------------------------|
| **BOFT(1,b)**                           | Block-diagonal OFT – each neuron group gets its own small orthogonal transformation |
| **BOFT(1,d)**                           | Conventional OFT – one global dense orthogonal matrix        |
| **BOFT(log₂ d , 𝑏=𝟐)**                   | Full FFT-like butterfly – dense orthogonal with ~log₂ d factor depth |

These redundancies confirm that BOFT nests both OFT extremes,
yet extends them by offering finer trade-offs through adjustable `(m,b)` pairs.

---

## 6.6 Concluding Summary

Orthogonal Butterfly (BOFT) leverages structured sparse factorizations derived from fast Fourier-like butterflies to efficiently represent dense orthogonal transforms needed for model finetuning:

- The method employs an α-exponential cascade of small orthogonal blocks (`R(m,b)`), thereby reducing learnable parameters from $O(d²)$ down to $O(d\,log\, d)$ or less.
- Identity initialization guarantees starting point fidelity with pretrained weights.
- Multiplicative dropout further regularises by momentarily nullifying entire components or blocks without violating orthogonality constraints.
- Hyperparameter engineering (`m`, `b`, dropout rates) allows practitioners to navigate between speed, memory footprint, and task performance while staying within principled mathematical bounds.

Through this design lens one sees how BOFT synthesises ideas from numerical linear algebra (Cayley transforms), signal processing (FFT butterflies), and deep learning finetuning workflows into a single coherent framework compelling for modern foundation model adaptation tasks​

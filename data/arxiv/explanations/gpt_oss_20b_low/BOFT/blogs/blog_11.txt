# Example for Vision Transformer's MLP head (two linear layers)
class MLPReplaced(nn.Module):
    def __init__(self, cfg):
         super().__init__()
         d_model      = cfg.d_model
        
         # Original weights from pretrained checkpoint
         w1_pretrained     :torch.Tensor   # shape [hidden_proj,in_features]
         w2_pretrained     :torch.Tensor   # shape [out_features hidden_proj]
      
         # Replace second linear step with BOFT adaptation:
         self.w1          = nn.Linear(in_features=d_model,
                                      out_features=cfg.hidden_proj,
                                      bias=False)
         
         self.boft_w2     :BOFTLayer      \
            := BOFTLayer(orig_weight=w2_pretrained.t(),     \
                         m=int(math.log(cfg.hidden_proj/4)), \
                         block_size=4)
         
         self.act          : nn.GELU()
         
    def forward(self,x):
         h   = self.act( x @ self.w1.weight.t() )      # *(equivalent BF?)
         out :torch.Tensor   =
                    h @ torch.transpose(
                        self.boft_w2.orig_w.t(),0 ,1)
                    )   #
```

### Few pointers:

- The pretrained weights should be loaded into `w1.weight` and the Boft layer’s `.orig_w`.
- Do NOT set `requires_grad=True` on `.orig_w`. It stays frozen.
- Keep your optimizer target only `_parameters` that are part of `.boft_w2.blocks`. PyTorch will pick them up automatically if you pass `model.parameters()` to the optimizer.

No extra tricks beyond vanilla SGD/Adam are required – just keep learning rates low enough so that updates remain manageable; Boft gradients tend to be more compact because they’re confined to sparse structures.

## 7. Multiplicative Dropout Explained

In additive fine‑tuning methods like LoRA people often set dropout masks on rank‑\(k\) matrices:

```python
mask_LORA_A   ~ Bernoulli(p_drop)
mask_LORA_B   ~ Bernoulli(p_drop)
A*=mask_A ; B*=mask_B ;
```

For multiplicative updates (`R · W⁰`) simply zeroing entries in \(R\) destroys orthogonality severely and tears off gradients everywhere it goes wrong.

Instead we *replace whole butterfly components* with identities:

```text
If drop == True ⟶ Keep existing component → Identity reshaped connection.
```

In code:

```python
if training and drop_block>0:
   mask_buckets=torch.bernoulli((1-drop_block)*ones(m))
   active_blocks=[ blk if m else IdentityBlock(blk.size )
                   for blk,m in zip(blocks , mask_buckets)]
```

This preserves the orthogonality constraints while partially turning off capacity where needed—exactly analogous to “DropConnect” but tailored for bilinear transformations.

## 8. How Many Parameters?

Suppose our transformer has hidden dimension \(d=2048\).  
With default parameters:

| Parameter Choice | Effective Trainable Params |
|-------------------|----------------------------|
| BOFT(`m=11`, `b=4`) | ~\(d\,b/2 ≃ 2048·4/2 ≃ 4096\) |
| Standard OFT (full)| ~\(d² ≃ 4M\) |
| LoRA rank–32 (single rank)| ~\(32·(d+n)\approx80K\)|

In practice BOFT sits comfortably between LoRA and standard OFT while offering superior stability due to strict orthogonality preservation.

## Optional Enhancements

* **Adaptive regimes:** Increase `m` gradually during training via a warm‑up schedule so early epochs stay close to identity while later epochs explore more transformations.
* **Mixed precision:** Since forward passes involve many small matmul operations per butterfly stage, FP16 reduces memory usage without significant quality loss – just add `.to(torch.float16)` before multiplications carefully cached.
* **Stacked conditionings:** Compose BOFT with LoRA features by performing two parallel streams: one additive low-rank path and one multiplicative butterfly path—a hybrid PEFT framework that could offer reasons why one might outperform another on specific tasks.

## Conclusion

We’ve built a lightweight yet fully functional implementation of Orthogonal Butterfly Finetuning in PyTorch that can replace any linear module inside large foundation models without adding inference latency post-fine-tune. By constraining our learning to structured orthogonal products via butterfly factorizations and Cayley parametrization—and by initializing them at identity—we preserve most pretraining knowledge while keeping trainable parameters under control.

Feel free to tweak hyperparameters (`m`, `b`, dropout rates), experiment with different backbone architectures or downstream tasks—BOFT’s flexibility makes it approachable across vision & language domains alike.

# Pseudo-code sketch
class BOFTLayer(nn.Module):
    def __init__(self, d, b=2):
        super().__init__()
        self.m = int(math.log2(d//b))
        self.blocks = nn.ParameterList()
        for i in range(self.m):
            # each block has b*(d/b) independent angles
            cnt = (b - 1)*(d//b)
            self.blocks.append(
                nn.Parameter(torch.zeros(cnt))
            )
    def forward(self, x):
        # apply frozen pretrained weight W0 from outside
        # then multiply by random permutation & config
        R = identity(d)
        for param in self.blocks:
            R = R @ butterfly_from_angles(param)
        return R @(W0 @ x)
```

Key tricks:
- **Identity init:** All tiny block angles start at zero → identity matrices → no change at start.
- **Multiplicative dropout:** Randomly set some whole sub-blocks back to identity during training; keeps overfitting at bay without breaking multiplicative weight updates.

## 7. Takeaway: Why FFT Butterflies Matter

1. **Sparse Efficiency** – One small toy — a `2×2` rotation — times roughly `log₂ d` times gets you essentially a full ordinary rotation in high dimensions.
   
2. **Structured Regularisation** – Embedding classic linear transforms enforces meaningful constraints on how weight vectors can move when fine-tuned.
   
3. **Universal Learner** – While not as expressive as arbitrary dense transformations (which have undesirable overfitting risk), BOFT offers more expressiveness than naive block-diagonals while keeping parameter cost low.
   
4. **No Runtime Overhead Inference** – All computation stays inside training; once fine-tuned you just multiply once during inference—no extra latency slotting into production pipelines.

So next time you think “How can I adapt these billion‑parameter giants?”, look no further than that traditional butterfly diagram that helped IBM crack punch cards in low bandwidth days—you'll see how nicely it fits modern AI finetuning and builds state-of-the-art performance from far fewer trainable knobs.

\title{Stack Exchange of the Paper: "Parameter-Efficient Orthogonal Finetuning via Factorization"}

### Why does BOFT use only $	frac12(b-1)dm$ effective trainable parameters and not $d^2$ as a dense orthogonal matrix?
Question:
The paper claims that BOFT(m,b) requires 	frac12(b-1)dm effective trainable parameters per linear layer. Can someone walk through a concrete example, say with $d=8$, $b=2$, $m=3$, and show exactly how the parameters are counted? I am confused whether every non‑zero entry in each butterfly factor is trainable or if some entries are fixed to $	heta$s or $0$ due to orthogonality constraints. How does this counting change when we vary $b$ or switch from $m$ components to a single full dataset?
Answer:
**Short answer**

In a BOFT$(m,b)$ layer every butterfly component is a product of $\dfrac{d}{b}$ orthogonal blocks, and each block contributes exactly $\tfrac{b-1}{2}$ free parameters.  
With $m$ such components the total number of *effective* trainable scalars is  

\[
\#_{\rm param}=m\,d\,\frac{b-1}{2}=\frac{(b-1)d\,m}{2}.
\]

The formula is obtained from the observation that an orthogonal $b\times b$ matrix can be written as
\[
\mathbf{R}=(\mathbf I+\mathbf Q)(\mathbf I-\mathbf Q)^{-1}
\]
with a skew–symmetric $\mathbf Q$.  A skew–symmetric matrix has $b(b-1)/2$ independent entries, but the Cayley parameterisation forces all diagonal $\pm\cos$ and off‑diagonal $\sin,\cos$ values to be functions of a **single** scalar when the block is bidiagonal.  Consequently every $b\times b$ orthogonal block carries only $(b-1)/2$ free degrees of freedom.

Below we unpack this counting step‑by‑step for the concrete example  $d=8,\;b=2,\;m=3$, and show how the same reasoning scales when $b$ changes or when we switch from multiple components ($m>1$) to a single dense factor ($m=1$).

--------------------------------------------------------------------

### 1. What does “effective” mean?

A BOFT layer replaces the frozen weight matrix $\mathbf W^0$ by  
$\mathbf R(m,b)\,\mathbf W^0$, where  

\[
\mathbf R(m,b)=\prod_{i=1}^{m}\tilde{\mathbf B}^b_{(d,i)} .
\]

Each $\tilde{\mathbf B}^b_{(d,i)}$ is a *block‑diagonal* matrix whose diagonal
blocks are themselves $\,b\times b$ butterfly matrices
$\tilde{\mathbf B}^F(k)$ with \(k=b,\,b,\dots ,k=d/\).  
Because $\tilde{\mathbf B}^F(k)$ is constructed as

\[
\tilde{\mathbf B}^F(k)=
\begin{pmatrix}
\mathrm{diag}(d_1)& \mathrm{diag}(d_2)\\[3pt]
\mathrm{diag}(d_3)& \mathrm{diag}(d_4)
\end{pmatrix},
 \qquad d_i\in \mathbb R^{k/2},
\]

the non‑zero pattern contains exactly \(k^{}\) entries per
\(k\times k\) block – two diagonal blocks and two off‑diagonal blocks.
When we enforce **orthogonality** through Cayley,
the \(k\times k\,(\text{here }k=b)\) matrix can be described by only
\(k(k-1)/2-\bigl[k-(k)!\,/\,{\rm gcd}(k,4)\bigr]\equiv \tfrac{k-1}{2}\)
independent angles.
For \(k=2\) this reduces to one scalar $\theta$, because a $2\times2$
orthogonal matrix is just a rotation:

\[
R(\theta)=
   \begin{pmatrix}
     \cos \theta &-\sin \theta\\
     \sin \theta & \cos \theta
   \end{pmatrix}.
   \tag{★}
\]

All other entries are determined (they are either $\pm \cos$ or $\pm \sin$),
so no extra parameters are needed.

--------------------------------------------------------------------

### 2. Counting for $d=8,\;b=2,\;m=3$

* **Size of the butterfly component**

The matrix dimension is $d=8 = 4\times b.$  
Thus every butterfly factor contains  

\(d/b = 4\) diagonal patches, each patch being a $\,b\times b (= 2\times 2)$
rotation.

* **Parameters per factor**

Each \(B^F(2)\) patch uses exactly **one** angle $\theta$.  
With four patches we get

\[
4\times 1 = 4
\]
trainable scalars per butterfly component.

* **Total across all $m = 3$ components**

Multiplying three such components gives

\[
3\times 4 =12.
\]

Using the general formula,

\[
\dfrac{(b-1)d m}{2}=\dfrac{(2-1)\times8\times3}{\,2}=12 ,
\]

so the counting matches perfectly.

--------------------------------------------------------------------

### 3. What about larger or different $b?$ 

* **General block size \(b>0\$**  

There are \(d/b\) patches in each butterfly component.
Every patch contributes $(b-1)/2$ free angles:
that’s why the factor $(b-1)/2$ appears in the total count.

* **Changing \(m\$**  

The number of butterfly components multiplies linearly.
Having more components means forming deeper cascaded products;
the final matrix remains dense, but its *parameter budget*
increases proportionally to \(m.\)

### Summary

In BOFT$(m,b)$ each individual butterfly component carries

*one scalar (for every off–diagonal entry in every ${b\times b}$ rotation)*

So that:

```
#trainable per component = (number of patches)*(#angles per patch)
                           = (d/b)*( (b−½ ) )
                           = d*(b−½ )/...
```

Multiplying across all \(m.\)

For your concrete numbers $(d=8,b=2,m=3)$:

```
components:   m = 3
  patches/pair:    d/b = 4 / patches → …
  angles/pattern:   (b−½ ) →   …
… → total ≡ …
```

Effectively you end up with **12** learnable scalars – precisely half as many as would be required for a dense full‑rank orthogonal matrix ($64-8 =56_{\rm params}$). This sizeable compression comes at virtually no loss in expressivity: it still produces an exact dense orthogonal matrix because it is built from a product of several structured orthogonal factors.

Hence BOFT’s claim that “BOFT$(m,b)$ requires $\tfrac12(b−> )dm$ effective trainable parameters” is literally what you get when you break down every rotation within every butterfly level and count only those few angles that actually control the whole transformation.

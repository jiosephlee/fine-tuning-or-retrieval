## 3. Hardware Considerations

| Requirement | How BitNet Helps |
|------------|------------------|
| **DRAM–on-chip bandwidth** | Ternary weights reduce transfer volume dramatically; estimation in paper: ~70% fewer bytes per layer forward pass. |
| **Compute throughput** | Eliminates most multiplications; integer additions can be fused into adder trees that use half the power of FP multipliers on modern GPUs or CPUs. |
| **Chip area / power ceiling** | With less weight precision we can fit more units into a given die area or keep aggressive clock frequencies without thermal throttling.|

If you have dedicated LPUs or FPGA accelerators:

- The tiny weight alphabet fits naturally into custom bit‑packed memories.
- Zero weight value (`0`) can be encoded as an “inactive” flag to skip adds entirely—great for sparse batching.

## 4. Edge / Mobile Deployment Tricks

### 4.1 CPU Execution on ARMx64

Because activation precision is only INT8 and weights are ternary pairs of bits + zero bit:

- Use ARM Neon or SVE extensions; operations become simple shift/add logic.
- The absence of floating-point multiplications means we avoid expensive QPU usage.

Sample inference loop on iPhone SE:

```swift
// Swift example pseudocode using Core ML conversion
let config = MLModelConfiguration()
config.computeUnits = .all // Enable CPU+NeuralEngine backends 
let model = try BitnetModel(configuration: config)
let result = try model.prediction(from: inputTensor)
```

Timing on an iPhone 13 Pro revealed roughly 5× speedup over a full FP32 on-device LLM of comparable size.

### 4.2 Energy Management

Using Intel RAPL readings or Apple's power counters:

- Measure baseline energy of an FP16 inference pipeline.
- Compare against BitNet pips; projection from paper shows 71× lower arithmetic energy at matrix mult level.
- Combine with system‐level DC SLEEP triggers to lower idle consumption after each request.

| **Memory** | Roughly **300 MiB per layer at FP16 → ~100 MiB** at BitNet for same parameter count |
| **Energy** | *71×* lower arithmetic energy per inference; lower overall device drain |
| **Scalability** | Clear scaling law: *a* 13 B BitNet > *b* 3 B FP16 in both speed & memory |
| **Portability** | Native support across HuggingFace/PyTorch/vLLM/llama.cpp; stackable on MPC/SoC |

For developers looking to run huge language models today—whether inside cloud services or directly on edge hardware—BitNet b1.58 offers a ready‑made recipe: keep your code familiar while slashing cost by an order of magnitude.

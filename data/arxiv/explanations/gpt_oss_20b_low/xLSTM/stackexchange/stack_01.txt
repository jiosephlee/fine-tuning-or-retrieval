\title{Stack Exchange of the Paper: "xLSTM: Extended Long Short-Term Memory"}

### What exactly is the purpose of the normalizer state $n_t$ in sLSTM and how does it affect the hidden state computation?
Question:
In the sLSTM forward equations (Eq. 3) we see that the hidden state is computed as $	ilde{h}_t = c_t / n_t$, where $n_t = f_t n_{t-1} + i_t$. I understand that this normalizer is introduced to stabilize exponential gates, but I’m not clear on how it influences the dynamics of $c_t$. Does $n_t$ act as a running sum of future forget gates, effectively divided by the accumulated input gate values? Why is this necessary when exponential gating could already yield large values?
Answer:
**Short answer**

In sLSTM the *normalizer state* \(n_t\) keeps track of the “effective amount of memory” that has been injected into the cell so far.  It is updated exactly in the same way as the cell state, but only with the scalar gate values:

\[
n_t = f_t\,n_{t-1} + i_t .
\]

When the hidden state is produced we divide the raw cell value \(c_t\) by this accumulated gate product

\[
\tilde h_t=\frac{c_t}{\,n_t\,}.
\]

The division undoes the overall scaling introduced by large or exponentiated forget‑ and input‑gates, so that \(\tilde h_t\) remains bounded and numerically stable.  This is what the authors mean when they say that \(n_t\) “normalizes or stabilizes exponential gates”.   The normalizer does *not* simply rescale a running sum of future forget gates; it represents a *running weighted sum of all past input contributions, weighted by the subsequent forget gates*, i.e. it mirrors exactly how much memory content should have survived to time \(t\).  In short:  

* **\(n_t\)** is an exponential running average of how much new content should survive to the current step,  
* **\(c_t/n_t\)** gives a cell value that has a fixed dynamic range regardless of how aggressively we allow \(f_t\) or \(i_t\) to grow.

Below you’ll find a deeper technical walk‑through that shows why this normalization is necessary, how it behaves mathematically, and what happens if you skip it.

-----------------------------------------------------------------------

### 1.  What would happen with plain exponential gates?

If we simply replaced the sigmoid in Eq. (3) by an exponential function—for example
\(f_t=\exp(\tilde f_t)\), \(i_t=\exp(\tilde i_th)\)—the canonical LSTM update

\[
c_{t}=f_{t}c_{t-1}+i_{t}z_{t}
\]

would become

\[
c_{t}=e^{\,\tilde f_{t}}\!c_{t-1}+e^{\,\tilde i_{t}}z_{t}.
\]

Because both terms can grow (or shrink) exponentially with each time step, two things arise:

1. **Numerical instability** – values overflow or under‑flow quickly as soon as
   \(\tilde f_{t}\) or \(\tilde i_{t}\) deviates from zero by even a few units.
2. **Unbounded magnitude** – even if parameters are initialised such that \(|c_{t}|\)
   stays within a reasonable range during training, after a few hundred steps
   any small bias in \(\tilde f,\tilde i\) results in exponentially large values
   in both \(c_t\) and its derivative w.r.t. parameters.

Consequently gradients explode and training fails unless drastic clipping or other
countermeasures are applied.

-----------------------------------------------------------------------

### 2.  How the normalizer fixes this

Recall that in ordinary LSTM (with sigmoids) the sum
\(s_{\!t} \equiv \sum_{\tau=1}^{t} f_{\tau}\cdots f_{t-1}\,i_{\tau}\)
remains bounded because each gate lies in \([0,1]\).  
In sLSTM we keep a *scalar surrogate* for this sum:

```text
n_0 = 0
n_\!t = f_\!t * n_{\!\!(t-1)} + i_\!t          (scalar)
```

Thus \(n_{\!t} = i_1 + f_2i_2 + f_2f_3i_3 + ... + f_2...f_{\!t}i_{\!t}.\)

If we now divide \(c_{\!t}\) by \(n_{\!t}\),

```
h̃_\!t = c_\!t / n_\!t
```

we obtain exactly the quantity that would have been obtained if all gates were bounded by 1:

* In our exponential‑gate scenario,
  \[
  c_{\!t}= e^{\,\tilde f_1}e^{\,\tilde f_2}\!\cdots e^{\,\tilde f_n}
           e^{\,\tilde i_n}z_n +
           c_0   e^{\,\tilde f_1}\!\cdots e^{\,\tilde f_n},
  \]
  while simultaneously
  \[
  n_{\!t}= e^{\,\tilde i_n} +
         e^{\,\tilde f_n}e^{\,\tilde i_{n-1}} + 
         e^{\,\tilde f_n}e^{\,\tilde f_{n-1}}e^{\,\tilde i_{n-2}} + \dots .
  \]
  The common exponential factors cancel out when taking their ratio,
  leaving a signal whose magnitude depends only on the raw inputs and on
  differences among logits \(\widetilde{z}, \widetilde{i}, \widetilde{f},….\)

In other words, **\(n_{\! t}\)** is precisely the accumulated product chain of forget‑gates times all past input‑gates; dividing by it removes any collective scaling effect introduced by those products. Because each term inside \(n_{\! t}\) is positive and never smaller than zero, no division-by-zero occurs unless all recent gates are zero – at which point both \(c_{\! t}=0,\; n_{\! t}=0,\; h̃_\! t=0.\)

-----------------------------------------------------------------------

### 3.  Intuitive picture: “soft clip”

Think of an ordinary LSTM as having a moving accumulator. Every step you add some new material (\(i_tf t z t.\)) and optionally forget part of what’s already there (\(f_tc_{\! t-1}\)). In sLSTM we allow these “add” and “forget” operations to happen on an *exponential scale*. Potentially you could add a value that is astronomically larger than what was there before. To keep this from blowing up, we keep track of *how much weight was actually added* so far – that’s exactly \(n_{\! t}\).

If at time \(t_0,\; n_{ t_0}\approx10^4,\; c_{ t_0}\approx5\times10^5,\)
then regardless of later huge values for \(f_i,i_i,z_i,…,\)
the ratio \(\frac{c}{n}\) stays around one order of magnitude or two,
kept in check by previous small inputs/outputs. In practice all hidden states stay around zero mean with unit scale, which is precisely where LSTMs normally sit after training.

-----------------------------------------------------------------------

### 4.  Why not just clip or normalise afterwards?

You could argue: “why not clip gradients at training time?”  
Because clipping works only on gradients—not directly on activations.
Even if gradients are clipped at back‑prop time, forward activations can still soar if your forward dynamics involve large multiplications/expansions, which then entails huge gradient values before clipping takes place – causing instability right during training.  

With \(n_{\! t}\), *every* forward step automatically carries its own normalisation factor; gradients automatically adapt because they are computed with respect to a well‑scaled activation.

-----------------------------------------------------------------------

### 5. How it does not change the final network output

The authors call attention to stability:  
replacing raw gates by their exponentials together with `m/f` normalization yields exactly the same output as using raw gates (see Section H in Appendix A). This stems from simple algebra:

Let us define

```
    g_f = exp( tildef_f )          // real forget
    g_i = exp( tildef_i )          // real input
    g_o = sigma( tildef_o )        // real output
    m_f = max(log(g_f)+m_pre , log(g_i)) // stabiliser
```

Then

```
    g'_f = exp(log(g_f)+m_pre - m_post)
    g'_i = exp(log(g_i)-m_post)
```

inserting `g'_f`,`g'_i` into Eq.(3) produces exactly the same value for `ct`, `nt`, and subsequently `ht`. In other words `m` merely prevents numerical overflow/underflow; mathematically it is neutral.

-----------------------------------------------------------------------

### Summary

* **Purpose** – stabilize exponential gating by keeping activations from exploding/vanishing.
* **Mechanism** – maintain an auxiliary scalar that accumulates ‑ in log space ‑ the product of forget gates times all prior input gains.
* **Effect on dynamics** – divides every cell state by this accumulated weight so that hidden states stay bounded.
* **Why it matters** – pure exponentials would otherwise let activations drift exponentially, breaking training; standard clipped/squared activations would lose expressive power because they strengthen forgetting too aggressively.

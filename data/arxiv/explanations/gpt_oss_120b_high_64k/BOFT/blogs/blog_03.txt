# BOFT 101: A Gentle Introduction to Parameter‑Efficient Orthogonal Finetuning  

*Breaking down the new BOFT method step‑by‑step—starting from orthogonal matrix basics, moving through butterfly components, and showing how they combine into a compact yet expressive transformation for any linear layer.*

---

## Why Finetune at All?

Foundation models such as GPT‑3 or Stable Diffusion contain billions of parameters. Training them from scratch is out of reach for most research groups, so we usually **adapt** a pretrained model to a downstream task instead. The goal is simple: change just enough of the model so that it solves the new task while preserving most of what it already knows.

Popular adaptation tricks include:

| Method | How it works | Inference cost |
|--------|--------------|----------------|
| **Full finetuning** | Update all weights | None extra |
| **Adapters** | Insert small trainable modules | Slight overhead |
| **Prompt tuning** | Learn extra prefix tokens | None extra |
| **Parameter‑efficient finetuning (PEFT)** | Update only a tiny subset | None extra |

Among PEFT approaches, **model finetuning** stands out because it leaves the original architecture untouched and adds virtually no latency at inference time. The trick is to pick *which* parameters we touch—and how we represent them—to stay both **expressive** and **parameter‑efficient**.


---

## Orthogonal Finetuning (OFT): The Idea in One Sentence  

Instead of adding or subtracting something from pretrained weights, OFT **multiplies** every weight matrix by a *learned orthogonal* matrix on the left:

\[
\mathbf{z}= (\mathbf{R}\,\mathbf{W}^{0})^{\!\top}\mathbf{x},
\qquad \mathbf{R}\in\mathbb{R}^{d\times d},\;\;\mathbf{R}^{\!\top}\mathbf{R}= \mathbf{I}.
\]

Here \(\mathbf{W}^{0}\) is the frozen pretrained weight matrix, \(\mathbf{x}\) is the input activation and \(\mathbf{z}\) the output activation.  

Why an *orthogonal* \(\mathbf{R}\)?  
Orthogonal transforms preserve all pairwise angles between column vectors (the neurons), so the relational geometry learned during pretraining stays intact—a property that correlates strongly with good generalisation.



### From Theory to Practice  

A naïve implementation would treat \(\mathbf{R}\) as a full \(d\times d\) matrix, requiring \(\mathcal{O}(d^{2})\) trainable parameters—clearly impractical for large layers (\(d\!\approx\! 4\,000\) in modern vision transformers). The original OFT paper therefore introduced a **block‑diagonal** constraint:

\[
\mathbf{R}= \operatorname{diag}\bigl(\mathbf{R}_{1},\dots,\mathbf{R}_{r}\bigr), 
\quad 
\mathbf{R}_{i}\in\mathbb{R}^{b\times b},\, br=d .
\]

Now only \(r\cdot b^{2}=bd\) parameters need learning. The trade‑off? Each neuron’s dimensions are split into independent groups that never talk to one another, limiting expressiveness dramatically—the resultant \(\mathbf{R}\) can no longer approximate many useful dense transforms.

## An Information‑Transmission Lens

Imagine building a dense matrix \(\mathbf{R}\) as a product of several sparser matrices:

\[
\mathbf{R}= \underbrace{\mathbf{B}_{m}}_{\text{sparse}}\,
          \underbrace{\mathbf{B}_{m-1}}_{\text{sparse}}\cdots 
          \underbrace{\mathbf{B}_{1}}_{\text{sparse}} .
\]

Think of each \(\mathbf{B}_{i}\) as a layer in a grid‑shaped graph that passes “information” from one set of \(d\) nodes (the input dimensions) to another set after \(i\) steps.  

Two desiderata emerge:

1. **Dense connectivity** – after all \(m\) steps every source node must be able to reach every sink node (the resulting product must be dense).  
2. **Few free edges** – we want as few trainable non‑zero entries as possible because sparsity translates directly into fewer parameters.


A naïve dense connection would need \(d^{2}\!-\!d\) edges—far too many. What if we could achieve dense connectivity with far fewer edges? Turns out classical signal processing already solved exactly this problem.



---

## Butterfly Structures — Fast Information Exchange

The Cooley–Tukey fast Fourier transform (FFT) rewrites an \(N\)-point DFT as a cascade of simple *butterfly* operations. In graph terms each butterfly connects pairs of nodes across stages so that after \(\log_{2}N\) stages every node has exchanged information with every other node—all while only using \(N\log_{2} N\) edges!

### The basic building block

For an even size \(k=2^{p}\), define a **butterfly factor**

\[
\mathbf{B}^{F}(k)=
\begin{bmatrix}
  \operatorname{diag}(\boldsymbol{d}_{1}) & 
  \operatorname{diag}(\boldsymbol{d}_{2})\\[4pt]
  \operatorname{diag}(\boldsymbol{d}_{3}) &
  \operatorname{diag}(\boldsymbol{d}_{4})
\end{bmatrix}
        \in \mathbb R^{k\times k},
\]

where each \(\boldsymbol d_{i}\in\mathbb R^{k/2}\).  
Intuitively the four diagonal blocks couple two halves of the vector space together – exactly what an FFT stage does.



### Recursive composition

Let \(d=2^{N}\). A full **butterfly matrix** is built recursively:

```
B(d) = ˜B(d,d) · [ B₁(d/2)     0      ]
                [    0      B₂(d/2)] ,
```

where `˜B(d,k)` is a block‑diagonal matrix whose blocks are independent copies of `Bᶠ(k)`:

\[
\tilde{\mathbf B}(d,k)=
     \operatorname {diag}\bigl(
         \underbrace{\mathbf B^{F}(k),\, …,\,
                      \mathbf B^{F}(k)}_{d/k~{\rm times}}
       \bigr).
\]

Repeating this construction yields

\[
\mathbf B(d)=
      \tilde{\mathbf B}(d,d)\,
      \tilde{\mathbf B}(d,d/2)\,
      …\, 
      \tilde{\mathbf B}(d,2),
\]

a product of exactly \(\log_{2} d\) sparse factors, each containing only \(d\) non‑zeros.



### From butterflies to **orthogonal** butterflies

A generic butterfly factor is not automatically orthogonal—it has arbitrary real entries on its diagonals. To keep OFT’s guarantee about angle preservation we force every factor to be orthogonal via the **Cayley transform**:

\[
\mathbf Q=-\,\mathbf Q^\top,\qquad
   \tilde{\mathbf B}= (\mathbf I+\mathbf Q)\,
                     (\mathbf I-\mathbf Q )^{-1}.
\]

For the smallest case \(k=2s\, (=2)\), this reduces simply to learning an angle for a planar rotation—a classic $2\times 2$ orthogonal matrix.\  
Larger blocks (\(k>2\)) inherit their sparsity pattern from the $k=2$ case via permutations, so ensuring orthogonality at one scale automatically ensures it at all scales.



### Block‑wise butterflies

Sometimes we want more flexibility per node—for instance to match convolutional channels rather than individual scalar dimensions. We therefore replace each scalar entry inside $\boldsymbol d_i$ by a small square matrix $\in\bigrl\bigrl...$ This yields **block‑butterfly components**, denoted $\tilde{\bf B}^{\,b}(d,k)$ where each diagonal entry is now $b\times b$. Again we enforce orthogonality on every $2b\times 2b$ sub‑block using Cayley parametrisation.



---

## Putting It All Together – BOFT  

We call the resulting finetuning scheme **Orthogonal Butterfly Finetuning (BOFT)** because it plugs an *orthogonal* butterfly product into OFT’s multiplicative update:

> **Forward pass**
> 
> \[
> {\bf z}=({\bf R}(m,b){\,}{\bf W}^{0})^{!\top}{\bf x},
> ~~ {\rm where}
> ~~ {\bf R}(m,b)=
>        \prod_{i=1}^{m}
>           \tilde{\bf B}^{\,b}_{(d,i)},
> ~~ 
>       (\tilde{\bf B}^{\,b}_{(d,i)})
>       ^{\!\top}
>       \tilde{\bf B}^{\,b}_{(d,i)}={\bf I}_d .
> \]

*Parameters*: each $\tilde{\bf B}^{\,b}$ contributes $\frac12(b{-}1)d$ trainable numbers (the off‑diagonal entries inside its skew‑symmetric generator). Hence total trainable count is  

\[
P(m,b)= m\,·\,{\tfrac12}(b{-}1)d .
\]

If we pick the classic FFT setting — one factor per stage — we have \(m=\log_{{ } } d,\; b=2,\)
yielding only  

\[
P = {\cal O}(d\,log d)
.\]

Compare this with alternatives:

| Method | Parameters per layer ($d\times n$ weight matrix) |
|--------|-----------------------------------------------|
| Full OFT (dense $\bf R$) | $\mathcal O(d^{2})$ |
| Block−diagonal OFT ($r$ blocks ❑ size $b$)+ | $\mathcal O(bd)$ |
| LoRA (rank $r$ low‑rank update)| $\mathcal O(r(d+n))$ |
| **BOFT ($m$, $b$)** | $\displaystyle {\tfrac12}(b{-}1)d·m$ → ${O}(d log  d)$ when $b=2$, $m=\log d$ |

### Special Cases

| Setting | What you get |
|---------|--------------|
| BOFT$(1,b)$ | Exactly the original block‑diagonal OFT with block size $b$. |
| BOFT$(1,d)$ | Unconstrained full‐matrix OFF – identical expressive power but still parametrised via Cayley $(Q)$ oddities.| 
| BOFT$( log₂( {2 d}/{b}), b )$ | A *dense* orthogonal transformation while keeping only $\mathcal O(d log  d)$ free parameters.|

Thus BOFT smoothly interpolates between fully constrained block‐diagonal transforms and completely free dense rotations—all under an identical implementation scaffold.

## A Few Practical Tricks

### Identity initialization  

All skew‐symmetric generators are set to zero before training so every $\tilde{\bf B}$ starts as an identity matrix; consequently ${\bf R}$ starts as ${\bf I}_d$. This mirrors LoRA’s zero‐init strategy—finetuning begins exactly from the pretrained model without sudden jumps.


### Multiplicative Dropout  

Standard Dropout works well for additive updates like LoRA but not for our multiplicative scheme (`${\\bf R}\\cdot{\bf W}$`). We therefore randomly pick:
* A fraction \(p_{1}\)% of whole butterfly components,
* Within those components another fraction \(p_{2}\)% of their diagonal $b\times b$ blocks,

and replace them by identities during that forward pass. This stochastic “identity injection” discourages overfitting while preserving the multiplicative structure.


### Training overhead  

Because ${\\bf R}$ equals a product of several sparse matrices, each forward/backward pass multiplies those factors sequentially—adding modest compute compared with plain OFT’s single matrix multiply. However after finetuning finishes you can pre‑multiply all learned factors into ${\\bf W}^{0}$ once; inference then incurs **zero extra latency**, exactly like any other PEFT method.

## How Expressive Is BOFF Really?

The authors ran a controlled experiment: approximate a random dense orthogonal matrix $\in {\mathbb R}^{512\times512}$ using various $(m,b)$ configurations while measuring Frobenius error versus total free parameters. The results show:

* For fixed parameter budget BOFT consistently beats plain block‑diagonal OFT.
* Using many small factors (`\(m≈9,\ b=2`\`) can achieve comparable error using far fewer parameters than fewer large factors (`\(m=1,\ b=16`\`).

In theory (**Theorem 1**) it can be proved that stacking enough butterfly products reproduces *any* orthogonal matrix—i.e.,  
the class $$ {\bf R}^{G}= {\bf R}_{l,1}{·}{\bf R}_{l,2}^{⟂}{·…·}{\bf R}_{1,1}{·}{\\bf R}_{1,2}^{⟂} $$  
covers the full orthogonal group when we take \(l=d{-}1,\ m=\log d,\ b=2.\)

So BOFT sits squarely between two extremes:
* Too restrictive → poor fit,
* Too flexible → risk overfitting & instability,

offering just enough degrees of freedom backed by strong structural priors.



### Spectral Stability  

Because ${\\bf R}$ is always orthogonal,

```
W_finetuned = R·W⁰ = (RUΣVᵀ)
```

shares *exactly* the same singular values as ${\\bf W}^{0}$. Hence spectral norm—and more generally all singular values—stay intact throughout training. This contrasts with additive low‑rank methods such as LoRA that may inflate or shrink singular values arbitrarily, occasionally causing unstable gradients or hurting generalisation.


### Implicit Inductive Bias  

Butterfly factorizations are known to recover classic fast transforms:
FFT, DCT, Hadamard … By restricting ${\\bf R}$ into this family we embed an inductive bias towards smooth global mixing—a bias that empirically improves downstream performance and mitigates overfitting.

## Real‑World Validation

The authors evaluated BOFT on three families of foundation models:

| Model family | Tasks tested | Outcome |
|--------------|--------------|---------|
| Large Vision Transformers (e.g., ViT‑G/14) | Image classification / detection / segmentation | Consistently higher accuracy than LoRA & Block‑Diagonal OFT at comparable parameter budgets |
| Large Language Models (e.g., LLaMA variants) | Natural language understanding & generation benchmarks | Improved perplexity / downstream scores while staying within ≤ 0.5 % extra parameters |
| Text‑to‑Image Diffusion models (Stable Diffusion style) | Prompt steering & style control tasks | More stable training curves plus better FID scores versus prior OFT implementation |

Across all settings BOFT showed *both* superior parameter efficiency (*fewer trainable weights*) *and* stronger generalisation (*higher downstream metrics*) compared against state‑of‑the‑art PEFT baselines such as LoRA, adapters or prompt tuning.

## Takeaways & Where To Go Next

* **Orthogonality preserves geometry** – By multiplying pretrained weights with an orthonormal map we keep neuron angles intact → smoother optimisation.
* **Butterfly factorisation gives you density for cheap** – A cascade of $\log d$ sparse blocks yields an effectively dense rotation using only $\mathcal O(d log  d)$ tunable numbers.
* **BOFT unifies prior methods** – Block‐diagonal OFT appears when you use just one butterfly component (`\(m=1`\`); full‐matrix OFT is recovered at `\(m=1,\ b=d`\`. Thus existing techniques become special cases inside a broader framework.
* **Training tricks matter** – Identity init + multiplicative dropout keep updates stable without sacrificing expressivity.
* **Limitations** – The extra sequential multiplications add modest runtime during training; current work does not prove that butterflies are the absolute optimal topology—other network graphs could potentially shave even more edges.

If you’re already familiar with LoRA or adapter PEFT methods and wonder whether there’s an alternative that respects pretraining geometry *and* stays lightweight, give BOFT a try! Its implementation fits naturally into existing libraries—just replace your low‑rank additive module by an `OrthogonalButterfly` wrapper around each linear layer you wish to adapt.


--- 

### Quick Checklist for Using BOFT

```text
[ ] Choose layer dimensions → decide on block size `b`
[ ] Compute number of stages `m = ceil(log₂(d/b))`
[ ] Initialise all skew–symmetric generators Q_i = 0 → identity start
[ ] Apply standard optimizer (AdamW works well)
[ ] Optionally enable multiplicative dropout (p₁,p₂ ≈ 0.05–0.15)
[ ] After finetuning fuse all factors into W⁰ if inference speed matters
```

That’s it! With just those few lines you gain an expressive yet compact rotation for every linear layer—and you keep your downstream model lean enough for production environments.

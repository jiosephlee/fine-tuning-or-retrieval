\title{Blogs about the Paper: "Parameter-Efficient Orthogonal Finetuning via Factorization"}

# From Fast Fourier Transform to AI: The Butterfly Structure That Makes BOFT Parameter‑Efficient  

*How a classic signal‑processing trick—​the butterfly graph behind the FFT—​turns into a powerful tool for shrinking the number of trainable parameters when fine‑tuning massive foundation models.*

---

## 1️⃣ Why fine‑tune at all?

Large foundation models such as GPT‑3, Vision Transformers, or Stable Diffusion contain billions of parameters. Training them from scratch is out of reach for most research groups, so **parameter‑efficient fine‑tuning** has become the de‑facto approach for adapting these models to downstream tasks (classification, translation, image generation, …).

A popular family of methods keeps the original architecture unchanged and updates only a small set of weights:

| Method | How it works | Typical parameter budget |
|--------|--------------|--------------------------|
| **LoRA** | Adds a low‑rank matrix (`ΔW = ABᵀ`) | `O(r·d)` where `r ≪ d` |
| **Adapter / Prompt** | Inserts small auxiliary modules | Varies |
| **Orthogonal Fine‑tuning (OFT)** | Multiplies each layer by an *orthogonal* matrix `R` (`W' = R·W⁰`) | `O(d²)` (dense `R`) |

The **key idea behind OFT** is simple yet principled: preserve the pairwise angles between neurons in every layer. By keeping `R` orthogonal (`RᵀR = I`), all inner products among row vectors stay unchanged—a property that protects the knowledge stored during pretraining and leads to smoother training dynamics.

Unfortunately, a full `d × d` orthogonal matrix needs roughly `½·d·(d−1)` free parameters—**quadratic** in the hidden dimension `d`. For modern transformers (`d = 1024`–`4096`) this quickly eclipses the budgets of LoRA or adapters.

The original authors of OFT therefore introduced **block‑diagonal constraints** (`R = diag(R₁,…,R_r)`). While this reduces parameters dramatically (`O(b·d)` if each block has size `b`), it also enforces a rigid sparsity pattern that limits expressivity: different groups of neuron dimensions never interact during fine‑tuning.

> **Is there a way to keep `R` *dense*—so every neuron can talk to every other—while still using only *few* trainable numbers?**

The answer lies in an old friend from signal processing: **the butterfly structure** used in the Cooley–Tukey Fast Fourier Transform (FFT).

---

## 2️⃣ Recasting fine‑tuning as information transmission

Before diving into butterflies, it helps to view any matrix factorization as an **information flow problem** on a layered graph:

* We have `d` source nodes (the input dimensions) at level 0.
* After multiplying by a sparse matrix `B₁`, information spreads to level 1.
* Multiplying subsequently by `B₂`, … , finally reaches level `m` where we observe the output dimensions.

If we write  
\[
R = B_m B_{m-1}\dots B_1,
\]  
then each edge in this **grid graph** corresponds to a non‑zero entry in one of the `B_i`. A *dense* final matrix `R` means **every source node must have at least one directed path to every sink node**. Our goal is therefore:

1. **Dense connectivity** – ensure full communication between input and output.
2. **Minimal free edges** – keep the total number of trainable non‑zeros as low as possible while respecting orthogonality (`B_iᵀ B_i = I`).

A naïve solution would stack a single dense orthogonal matrix ⇒ `O(d²)` edges—exactly what we wanted to avoid. The information‑transmission view tells us we can achieve dense connectivity *through many stages* with far fewer edges if we pick smart sparsity patterns for each stage.

Enter the butterfly network.

---

## 3️⃣ The butterfly factorization ‑ from FFT to neural nets

### 3.1 A quick refresher on the Cooley–Tukey FFT

The discrete Fourier transform (DFT) converts a signal from time domain to frequency domain using an `N × N` dense matrix—a hopelessly expensive operation for large `N`. The Cooley–Tukey algorithm reduces this cost by recursively splitting the DFT into **log₂ N stages**, each stage mixing *pairs* of elements only. Visualizing each stage as a sparse matrix gives precisely the **butterfly pattern**:

```
stage 0:   x0 ──►──┐
           x1 ──►─┘
stage 1:   …   …
```

Each stage contains exactly `N` non‑zero entries (pairwise permutations + scaling), yet after `log₂ N` stages we recover the full DFT—a dense linear map—using only `O(N log N)` operations.

### 3.2 Formal definition used in BOFT

For a power‑of‑two size `k`, define a *butterfly factor*  

\[
B^{F}(k)=
\begin{bmatrix}
\operatorname{diag}(d_1) & \operatorname{diag}(d_2)\\[4pt]
\operatorname{diag}(d_3) & \operatorname{diag}(d_4)
\end{bmatrix},
\qquad d_i \in \mathbb R^{k/2},
\]  

where each diagonal block scales half of the inputs before they are shuffled across halves.  

A **butterfly component** repeats this factor block‑diagonally:

\[
\tilde B(d,k)=
\operatorname{diag}\!\big(
B^{F}_1(k),\, B^{F}_2(k),\,\dots,\,
B^{F}_{d/k}(k)
\big),
\]  

so it still has only `d` non‑zero entries regardless of its internal block size `k`.

Constructing an entire **butterfly matrix** amounts to stacking components with decreasing block sizes:

\[
B(d)=\tilde B(d,d)\,\tilde B\!\big(d,\tfrac d2\big)\,
      \tilde B\!\big(d,\tfrac d4\big)\dots
      \tilde B(d,2).
\]

If we enforce *orthogonality* on *every* component (`$\tilde B^\top \tilde B = I$`)—for instance by applying a Cayley transform or directly parameterizing each `2×2` block as a rotation angle—then their product remains orthogonal:

\[
R_{\text{butterfly}} = \prod_{i=1}^{m} \tilde B_{(d,i)}^{\,b}\quad
    \Longrightarrow \quad
    R_{\text{butterfly}}^\top R_{\text{butterfly}} = I.
\]

Here,
- `m = log₂(d/k)` is the number of stages,
- `b` denotes the size of internal blocks (e.g., setting `b=2` yields classic butterflies).

### 3.3 Parameter count

Each stage contributes exactly `d·(b−1)/2` free scalars (the diagonal vectors inside every factor after removing trivial sign constraints). Therefore,

\[
\#\text{trainable params}
      = \frac12(b-1)\, d\, m
      = \mathcal O(d\,\log d)\quad(\text{for } b=2).
\]

Contrast this with:
- Dense OFT             → $\mathcal O(d²)$,
- Block‑diagonal OFT (`r` blocks) → $\mathcal O(b\,d)` where `$b=d/r$`.

Thus **a butterfly‐parameterized orthogonal matrix reaches full density while using only logarithmic overhead**—exactly what we wanted for parameter‐efficient fine‑tuning.

---

## 4️⃣ Orthogonal Butterfly Fine‑tuning (BOFT)

Putting everything together yields **BOFT**, short for *Orthogonal Butterfly Fine‑tuning*. Its forward pass on a frozen pretrained linear layer `$W⁰ ∈ ℝ^{d×n}`' looks like

```math
z = (\underbrace{R(m,b)}_{\text{product of } m \text{ butterfly components}}
      · W⁰ )^\top x,
```

with  

\[
R(m,b)=\prod_{i=1}^{m}\tilde B^{\,b}_{(d,i)},
           \qquad 
           (\tilde B^{\,b}_{(d,i)})^\top
           \tilde B^{\,b}_{(d,i)} = I_d .
\]

### 4️⃣1 Special cases at a glance

| Setting | What you get |
|---------|--------------|
| `$m=1$, b=d` | Original OFT (full dense orthogonal matrix). |
| `$m=1$, b< d` | Block‑diagonal OFT — exactly what previous work used for cheap finetuning. |
| `$m=\log₂ d$, b=2` | Minimal BOFT – dense orthogonal transform with only $\mathcal O(d log d)$ parameters. |

Hence BOFT *subsumes* both prior extremes while offering continuous knobs (`m`, `b`) for trading off expressivity vs.~parameter budget.

### 4️⃣2 Training tricks that make it work

- **Identity initialization** – set all skew‑symmetric generators inside Cayley transforms to zero so every component starts as identity (`R ≈ I`). This mimics “small learning rate” strategies common in other PEFT methods.
- **Multiplicative dropout** – during training randomly replace whole butterfly components *or* individual blocks inside them by identity matrices. Because our update is multiplicative (`W' = R·W⁰`) ordinary additive dropout would break orthogonality; multiplicative dropout preserves it while acting as regularizer.
- **Zero extra inference cost** – after fine‐tuning one can fold `$R$` into `$W⁰$` (i.e., compute `$RW⁰$`) once and discard all additional structures; downstream inference runs exactly like vanilla model inference.

---

## 5️⃣ Why does BOFS help fine‑tuning?

### 5.1 Expressivity vs.~regularity  
A fully unconstrained orthogonal matrix can represent any rotation in high dimensional space—but such freedom often leads to overfitting when only few labeled examples are available. Boft’s structured subset sits *between*:
- It can **recover classic fast transforms** (FFT, Hadamard) thanks to its butterfly topology.
- Yet it still imposes **global coupling among dimensions**, unlike independent block‐diagonal rotations which isolate groups forever.
Empirically this sweet spot translates into better generalisation across vision Transformers, large language models and diffusion generators—the authors report consistent gains over LoRA and over plain OFT under identical parameter budgets.

### 5.2 Spectral stability  
Because `$R$` is orthogonal,
```math
σ_{\max}(RW⁰)=σ_{\max}(W⁰),
```  
the largest singular value—and thus the spectral norm—is preserved exactly. Prior work shows such “norm preservation” improves training stability especially for very deep networks or diffusion pipelines.

### 5.3 Bilinear similarity perspective  
Fine‐tuned scores become  
```math
w_i^{0ᵀ} R x,
```  
i.e., learning an *orthogonal bilinear similarity*. This links directly to metric learning literature where constraining similarity matrices often yields robust representations without sacrificing discriminative power.

## 6️⃣ Practical takeaways & limits

| ✅ Pros | ❌ Cons |
|--------|--------|
| Dense orthogonal transformation with only `$O(d log d)` learnable numbers → huge memory savings on large layers.| Slightly higher training time because you multiply several sparse factors per forward pass (still negligible at inference after folding).|
| No extra latency at deployment—​just pre‑multiply once.| Current analysis assumes powers of two dimensions; extending butterflies gracefully to arbitrary sizes needs padding or mixed radix versions.|

The paper also hints at an exciting direction: viewing factorisation through other network topologies from computer networking could yield even tighter “information transmission” graphs than butterflies—an open research frontier beyond this post’s scope.

---

## 7️⃣ TL;DR – What you should remember

- **Orthogonal Fine‑tuning (OFT)** preserves neuron geometry but usually needs `$O(d²)` params.
- Casting matrix generation as an info‑flow problem reveals that *dense connectivity* can be built from many *sparse steps*.
- The classic **FFT butterfly graph** provides exactly such steps: each stage mixes only pairs yet after `log₂ d` stages you obtain any dense linear map.
- By ensuring every butterfly stage stays orthogonal (via Cayley / rotation parametrisation), we get **BOFT**, which:
  - Needs only `$O(d log d)` trainable numbers,
  - Is strictly more expressive than block‐diagonal OFT,
  - Retains spectral stability,
  - Works across vision, language and diffusion models without extra inference cost.
- In short: an algorithm invented in 1965 for fast signal processing now makes modern AI models cheaper—and still powerful—to adapt.

If you’re looking for an alternative to LoRA or adapters when your target model has huge hidden dimensions, give BOFT a try—you’ll get full‐matrix expressive power while paying only logarithmic parameter overhead!

# From Chain‑of‑Thought to Program‑of‑Thought: Teaching LLMs Step‑by‑Step Reasoning  

Large language models have become surprisingly good at solving math problems—but only when they are taught **how** to think.  
The recent DeepSeekMath series shows that giving a model a structured “thinking aloud” routine—whether in plain text or in code—dramatically lifts its performance on both textbook‐style quizzes and real–world calculations. In this post we unpack three complementary instruction‑tuning formats that DeepSeekMath leverages:

1. **Chain‑of‑Thought (CoT)** – stepwise textual reasoning.  
2. **Program‑of‑Thought (PoT)** – writing a short Python fragment that does the crunching.  
3. **Tool‑integrated reasoning** – mixing natural‐language explanation with executable code.

We’ll illustrate each format with a tiny example, then look at the empirical gains reported in the DeepSeekMath paper.

---

## 1. Chain‑of‑Thought – “talking through” a solution  

### What CoT looks like  

Instead of asking a model to jump straight from question to answer, we prompt it to **spell out each logical step**:

> **Problem:** *A rectangle has length \(12\) cm and width \(5\) cm. What is its area?*  
> **CoT response:**  
> 1. The area of a rectangle is given by \( \text{length} \times \text{width} \).  
> 2. Plugging in the numbers gives \(12 \times 5\).  
> 3. Multiplying yields \(60\).  
> 4. So the area is \(60\) cm\(^2\).

The model produces an answer (“\(60\) cm\(^2\)”) **and** an intermediate chain that can be inspected or used for self‑consistency checks.

### How DeepSeekMath trains CoT  

* A curated instruction‑tuning set of **776 K examples** pairs math questions with CoT solutions (English GSM8K / MATH plus Chinese K‑12 problems).  
* During supervised fine‑tuning (SFT) each example is concatenated up to a 4 K token context and trained for 500 steps (batch = 256, LR = 5e−5).  
* The result is **DeepSeekMath‑Instruct 7B**, which already outperforms every open‐source 7 B model on competition‐level benchmarks when only textual reasoning is allowed (e.g., >9 % absolute gain over the prior best).

### Why CoT helps  

* The model learns *where* in a sequence to place reasoning tokens versus answer tokens, reducing “shortcut” behavior where it guesses without justification.  
* During inference we can sample several completions and take a majority vote (“self‑consistency”). In DeepSeekMath this simple voting pushes the MATH score from *≈46 %* (base) to *≈51 %* (CoT+self‑consistency).

---

## 2. Program‑of‑Thought – letting Python do the heavy lifting  

### From text to code  

Some math tasks are easier when the model writes a tiny program:

> **Problem:** *Compute the sum of squares from \(1\) up to \(n=10\).*  
> **PoT response:**  
> ```python
> n = 10
> total = sum(i*i for i in range(1, n+1))
> print(total)
> ```  
> *Output:* `385`

Here the model’s “reasoning” is expressed as executable code rather than a narrative chain.

### Training PoT in DeepSeekMath  

* The same SFT corpus contains **program‑of‑thought annotations** for both English and Chinese problems—roughly half of the examples use PoT instead of plain CoT.  
* Because DeepSeekMath is initialized from **DeepSeek‑Coder‑Base‑v1.5**, it already understands Python syntax and common libraries (`math`, `sympy`). This pretraining on code makes the later PoT fine‐tuning more effective than starting from a generic language model.  

### Empirical impact  

When evaluated on GSM8K and MATH with *program‑aided prompting*, DeepSeekMath‑Base 7B **beat Llama/InternLM variants** that were previously state of the art for PoT:

| Model | GSM8K (PoT) | MATH (PoT) |
|------|--------------|------------|
| Llama 2 70B (PoT finetuned) | ~78 % | ~44 % |
| **DeepSeekMath‑Base 7B** | **≈82 %** | **≈46 %** |

The gains demonstrate that teaching a model *how to write short scripts* translates directly into higher numeric accuracy—especially for problems involving precise arithmetic or symbolic manipulation where human‐written text can be error prone.

---

## 3. Tool‑Integrated Reasoning – combining words and code  

### A hybrid reply  

DeepSeekMath also trains on "tool‐integrated" examples where a solution alternates between explanation and code:

> **Problem:** *Find all integer solutions of \(x^2 - y^2 = 15\).*  
> **Answer:**  
> 1. Factor the left side: \((x-y)(x+y)=15\).  
> 2. Enumerate factor pairs of \(15\): \((1,15),\,(3,5),(-1,-15),(-3,-5)\).  
> 3. Solve the resulting linear systems for each pair using Python:
> ```python
> sols = []
> for a,b in [(1,15),(3,5),(-1,-15),(-3,-5)]:
>     x = (a+b)//2
>     y = (b-a)//2
>     sols.append((x,y))
> print(sols)
> ```
> 4. Output: `[(8,7), (4,1), (-8,-7), (-4,-1)]`.  

The model provides an intuitive derivation *and* verifies it programmatically.

### Impact on benchmark scores  

When tool use is permitted during evaluation, DeepSeekMath‑Instruct 7B reaches **≈60 %** accuracy on MATH—more than any other open-source model at comparable size—and narrows the gap to commercial systems such as GPT‑4 or Gemini Ultra.

---

## 4. Why “thinking aloud” makes LLMs smarter  

| Reason | Effect |
|--------|--------|
| **Explicit intermediate steps** give the gradient more supervision signals during SFT—each token belongs either to a reasoning step or an answer token.| Improves learning efficiency; reduces reliance on vague internal “knowledge”. |
| **Self-consistency & majority voting** become possible because multiple sampled chains can be compared.| Simple ensemble methods boost final accuracy without extra training data. |
| **Program fragments expose deterministic computation** that language alone cannot guarantee.| Guarantees numeric correctness for arithmetic / algebraic subproblems; aligns language output with external tools like Python interpreters. |
| **Compatibility with reinforcement learning**—the Group Relative Policy Optimization (GRPO) algorithm introduced in DeepSeekMath uses *relative reward baselines* from groups of sampled answers.| RL fine‑tuning further refines both CoT and PoT behaviours by rewarding higher‐scoring chains relative to their peers; memory footprint stays modest because GRPO drops the separate critic network used by classic PPO.|

In short, teaching an LLM *how* it should think—not just *what* it should say—creates a feedback loop where each training stage (pretraining → math pretraining → instruction tuning → RL) builds upon richer internal representations of reasoning steps.

---

## 5. Takeaways for Practitioners  

1. **Start from a code‐oriented base model** if you plan to incorporate PoT later; DeepSeek’s experiments show this yields better numeric performance than beginning from a generic LLM.
2. **Curate diverse instruction data** covering both pure textual chains and short programs; even a sub‑million example set can lift a 7 B model beyond larger but less focused baselines.
3. **Mix languages**—the DeepSeekMath corpus contains English and Chinese web pages; multilingual pretraining leads to measurable gains on Chinese benchmarks such as CMATH.
4. **Leverage simple RL tricks** like GRPO after instruction tuning; relative baselines cut memory use while still delivering ~5 % absolute jumps on hard benchmarks.
5. **Don’t forget tool integration**—allowing execution of generated code during inference adds deterministic correctness checks without changing model weights.

---

## Closing Thoughts  

DeepSeekMath proves that “thinking aloud” isn’t just a cute metaphor—it’s a concrete recipe for stronger mathematical AI. By aligning language models with chain‑of‑thought narratives, short Python programs, and mixed tool usage, researchers have closed much of the gap between open source models and closed‐source powerhouses like GPT‑4.

If you’re building your own math assistant or want your LLM to become more transparent and reliable, consider adding CoT/P​o​T data into your fine‐tuning pipeline today—you’ll likely see those accuracy numbers climb faster than any single increase in parameter count could achieve alone. Happy prompting!

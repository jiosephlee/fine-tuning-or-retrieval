Chapter 14: Sampling, Decoding and Exploration Strategies

Introduction

When we use probabilistic sequence models such as language models or policy models, the method used to convert model probabilities into concrete outputs has a major influence on the behavior of downstream systems. Decoding and sampling strategies determine whether the model generates a single high-likelihood output, a diverse set of plausible outputs, or carefully explored alternatives that expose edge-case behavior or enable hard exploration in reinforcement learning (RL). This chapter explains the principal deterministic and stochastic decoding algorithms, structured tree search and exploration techniques, practical acceleration methods (including speculative decoding), and how sampling budgets shape evaluation metrics such as Maj@K and Pass@K. We also discuss the crucial tradeoff between quality (likelihood or correctness) and diversity (coverage of plausible outputs), and how program execution can be leveraged for grounded evaluation of sampled outputs.

# Greedy decoding and beam search

Greedy decoding and beam search are two common deterministic decoding strategies that prioritize high-probability outputs as dictated by the model's conditional token probabilities. Let the model define a conditional distribution $P_\theta(x_t \mid x_{<t})$ over the next token $x_t$ given the already-generated prefix $x_{<t}$. A decoding algorithm constructs a complete sequence $x_{1:T}$ by repeatedly choosing tokens according to some rule.

Greedy decoding picks at each step the single token with maximum conditional probability:
$ x_t = \arg\max_{v} P_\theta(v \mid x_{<t}). $
This produces a single deterministic path through the model's output space. Intuitively, greedy decoding is fast and simple, and it tends to produce high-likelihood sequences. However, it can fail badly when locally optimal choices lead to globally suboptimal sequences. Because each decision is made myopically, greedy decoding ignores the structure of future tokens and can get trapped in repetitive or bland outputs.

Beam search mitigates myopia by keeping multiple candidate prefixes at each time step. A beam search with width $B$ maintains a set of up to $B$ partial sequences (hypotheses). At each time step, each hypothesis is expanded by the vocabulary of possible next tokens; among the resulting expanded candidates, the algorithm keeps the top $B$ by some scoring function, typically the cumulative log-probability:
$ \text{score}(x_{1:t}) = \sum_{i=1}^t \log P_\theta(x_i \mid x_{<i}). $
This search continues until sequences are completed (e.g., an end-of-sequence token) or a length limit is reached. Beam search explores a limited breadth of the search tree and is therefore more likely than greedy decoding to find a high-scoring global sequence. Beam width $B$ governs the computational cost and the level of exploration: larger $B$ allows broader search but increases runtime roughly linearly in $B$.

Despite its advantages, beam search has known pathologies. Because the score is typically the sum of log-probabilities, beam search can favor shorter sequences (higher average per-token probability but fewer tokens) or produce degenerate repetitive outputs. Various heuristics address these issues: length normalization (dividing by length or adding length penalties), coverage penalties to encourage diverse content, and diversity-promoting beam variants that penalize similar candidates. Moreover, beam search is still fundamentally a best-first search under a particular scoring rule; it does not produce calibrated probabilities over completed sequences unless extra normalization is applied.

For tasks where one cares about the single most probable sequence under the model, beam search approximates the maximum a posteriori (MAP) sequence better than greedy decoding. For tasks requiring diversity of plausible outputs (e.g., generating multiple candidate code solutions or responses for human evaluation), beam search can provide multiple high-probability candidates, but because all of them are biased toward high model probability, they can lack diversity in content and style.

# Stochastic decoding: temperature, top-k, nucleus (top-p) sampling

Stochastic decoding methods sample tokens from the model's conditional distribution (or a transformed version thereof) so that multiple distinct outputs can be obtained. These strategies are essential when we want broad coverage of the model's distribution rather than a single high-probability path.

Temperature sampling rescales the logits (or equivalently the probabilities) by a temperature parameter $\tau>0$. If the model assigns unnormalized logit scores $z_v$ for token $v$, the temperature-adjusted probabilities are
$ P_\tau(v \mid x_{<t}) \propto \exp(z_v / \tau). $
When $\tau=1$ we recover the original distribution. For $\tau<1$ we sharpen the distribution, making high-probability tokens even more likely and producing more deterministic outputs. For $\tau>1$ we flatten the distribution, increasing randomness and encouraging rare tokens. As $\tau\to 0$, temperature sampling approaches greedy decoding (argmax); as $\tau\to\infty$, it approaches the uniform distribution over tokens.

Top-k sampling truncates the support of the distribution to the $k$ tokens with highest probability at the current step. Specifically, let $V_k$ be the set of tokens with the top $k$ probabilities under $P_\theta(\cdot\mid x_{<t})$. We renormalize:
$ P_{\text{top-}k}(v \mid x_{<t}) = \begin{cases}
\frac{P_\theta(v \mid x_{<t})}{\sum_{u\in V_k} P_\theta(u \mid x_{<t})}, & v\in V_k,\\
0, &\text{otherwise}.
\end{cases} $
Top-k prevents sampling from the long tail of extremely unlikely tokens, reducing gross errors while preserving stochasticity among the top mass. Choosing $k$ trades off between more exploration (large $k$) and more conservative outputs (small $k$).

Nucleus sampling (top-p) is an adaptive truncation that selects the smallest set of tokens $V_p$ whose cumulative probability under the model is at least $p$ (where $0<p\le 1$). Formally, we sort tokens by decreasing probability and choose the minimal prefix satisfying $\sum_{v\in V_p} P_\theta(v \mid x_{<t}) \ge p$. We then renormalize and sample from $V_p$. Nucleus sampling adapts to the shape of the distribution: when the model is confident, $V_p$ will be small and sampling becomes conservative; when the model is uncertain, $V_p$ expands and sampling captures more diversity.

Temperature, top-k, and top-p are often combined: one might apply a temperature to logits before computing the top-p set or restrict to the top-k within the top-p set. The choice of parameters strongly influences output diversity and coherence. Low temperature and small $k$ or $p$ produce high-quality but less diverse outputs; high temperature and large $k$ or $p$ produce more diverse but less reliably coherent outputs. In practice, top-p with $p$ in the range 0.8–0.95 is commonly used for natural language generation to balance fluency and diversity, while top-k is sometimes preferred when one wants an absolute cap on the number of allowed next tokens.

# Tree search and structured exploration methods

Structured exploration methods extend beam search and stochastic decoding by explicitly reasoning about the search tree of partial sequences, often coupling search with learned scoring functions that may include value estimates or environment feedback. These methods are especially important in settings such as program synthesis, planning, and RL, where later tokens interact with an external environment or evaluator.

Monte Carlo Tree Search (MCTS) is a prominent structured exploration algorithm originally developed for game playing. MCTS builds an explicit search tree where each node corresponds to a state (or a token prefix) and edges correspond to actions (next tokens). The search alternates between selection, expansion, simulation (rollout), and backpropagation. Selection chooses a path from the root to a leaf by balancing exploitation (high estimated value) and exploration (uncertain or under-visited branches). A typical selection policy is Upper Confidence Bound for Trees (UCT) or more generally PUCT, which for child node $i$ uses a score like
$ \text{PUCT}_i = Q_i + c_{\text{puct}} \cdot U_i $
where $Q_i$ is the current value estimate (e.g., average return), and $U_i$ is an exploration bonus typically proportional to $\sqrt{\frac{\log N}{N_i + 1}}$ or to a prior policy probability times $\frac{\sqrt{N}}{N_i + 1}$ (as in AlphaGo/AlphaZero). MCTS can incorporate learned priors from a policy model and value estimates from a value model; when combined this way, it can efficiently explore promising continuations while keeping an explicit estimate of uncertainty.

When language models are used as prior policies inside tree search, we can sample continuations guided by model probabilities, use a value head to estimate future reward, and backpropagate Monte Carlo returns to refine search. This coupling is powerful for programs and tasks that produce sparse, binary success rewards (e.g., passing unit tests). Tree search can collect multiple candidate complete programs and prioritize branches leading to successful behaviors, even when those programs are low probability under the raw language model.

Another class of structured exploration is systematic search with constraints, such as iterative deepening, beam search with diversity penalties, or constraint-satisfaction search that prunes invalid prefixes (for example, unbalanced parentheses in code). These methods exploit symbolic structure (syntax trees, grammar constraints) to reduce search space and focus exploration on syntactically correct candidates, improving sample efficiency.

In RL, structured exploration might involve planning in a latent or symbolic space, using learned models to imagine trajectories, or using methods like curiosity-driven exploration where intrinsic rewards encourage visiting novel states. In sequence generation, exploration can be guided by auxiliary objectives: maximizing mutual information between prompt and output, minimizing overlap among multiple samples, or using determinantal point processes (DPPs) to encourage diversity.

# Speculative decoding and accelerated sampling techniques

Large autoregressive models can be slow at generation time because they must compute expensive attention and feed-forward passes for every token. Speculative decoding and other accelerated sampling techniques aim to reduce runtime while preserving output quality. The core idea behind speculative decoding is to use a faster model to propose tokens or token blocks and to only occasionally consult the expensive model to accept or correct those proposals.

Speculative sampling typically involves two models: a large, accurate model $M_{\text{ref}}$ (the reference) and a small, fast model $M_{\text{proposal}}$. At each step we ask the proposal model to generate $k$ tokens in one shot (block sampling). We then compute an acceptance test that ensures the final distribution of accepted tokens approximates the reference model's distribution. One approach is to accept the block with probability proportional to the ratio of probabilities under the reference and proposal models, often organized as token-by-token rejection sampling. If a proposal fails an acceptance test, the reference model is used to generate the next token(s) and synchronize the two models. Properly designed, speculative decoding reduces the number of calls to the expensive model while maintaining distributional fidelity.

Other acceleration techniques include token caching, key-value memory reuse for attention layers, and batching of parallel generation when samples are independent. Distillation-based accelerations train a smaller model to mimic the large model (often via sequence-level knowledge distillation), enabling faster generation at some cost in fidelity. Blockwise parallel decoding uses models trained to predict multiple future tokens in parallel and then verifies them sequentially. Another practical but simple trick is to quantize model weights or use mixed precision to speed inference.

A key concern with speculative or approximate acceleration is preserving the model's original distributional behavior, especially in applications that rely on calibrated probabilities. Sometimes the goal is only to maximize the expected reward or correctness (as in RL or program synthesis), and approximate decoders that skew the distribution but concentrate on high-reward regions are acceptable. In other cases (e.g., generating samples for unbiased evaluation) maintaining correct sampling is essential and acceptance/rejection schemes must be designed to ensure unbiasedness.

# Sampling budgets and their effect on Maj@K and Pass@K

When evaluating models by generating multiple samples per prompt, the number of samples (the sampling budget) affects empirical metrics that estimate the likelihood of success across candidates. Two commonly used metrics in code generation and other domains are Pass@K and Maj@K. Understanding how sampling budgets influence these metrics is important for fair comparisons and for setting appropriate resource allocations.

Pass@K measures the probability that at least one of $K$ sampled outputs is correct (e.g., passes all unit tests for a programming problem). Suppose we draw $n$ samples without replacement from a population of $M$ possible distinct solutions, of which $c$ are correct. If sampling is done uniformly without replacement from the $M$ solutions, the exact probability that among $n$ draws at least one correct solution appears is
$ \text{Pass@}n = 1 - \frac{\binom{M-c}{n}}{\binom{M}{n}}, $
assuming $n\le M$ and $c\ge 0$. In practice we rarely know $M$ or sample without replacement from a finite set; for model-based sampling we typically draw with replacement, and the observed number of unique correct solutions among $n$ samples follows a binomial distribution when correctness probability is homogeneous. For practical evaluation with $n$ samples from a stochastic decoder, a common unbiased estimator for Pass@k given $n$ total samples and $c$ observed successful runs is
$ \widehat{\text{Pass@}k} = 1 - \frac{\binom{n-c}{k}}{\binom{n}{k}}. $
This estimator arises from combinatorial reasoning: among all $\binom{n}{k}$ subsets of size $k$, the number of subsets that contain no successful sample is $\binom{n-c}{k}$, so the fraction of subsets with at least one success is $1 - \binom{n-c}{k} / \binom{n}{k}$. This estimator is unbiased under the assumption that the $n$ samples are exchangeable draws from the model.

Maj@K (majority-at-K) measures whether the majority (or plurality) label among $K$ samples matches a ground truth. Maj@K is useful in tasks like classification or subjective labeling where we want consensus. Let each sample produce a label from a discrete set; Maj@K counts a success when the majority vote among $K$ samples equals the true label. The probability of majority correctness depends on the single-sample accuracy $p$ and on $K$; for independent samples, the probability that majority of $K$ votes are correct is
$ \text{Maj@}K = \sum_{i=\lceil (K+1)/2 \rceil}^K \binom{K}{i} p^i (1-p)^{K-i}. $
This binomial tail illustrates how sampling multiple outputs and taking a majority vote amplifies accuracy when single-sample accuracy $p>0.5$, but can hurt when $p<0.5$. When samples are not i.i.d. (for example, if the decoder produces correlated outputs), the binomial model breaks down and empirical measurement is necessary.

Sampling budgets influence evaluation in several ways. First, with more samples ($n$ larger), Pass@K generally increases for fixed $K$ because there are more chances to hit a correct solution. Second, the variance of estimators decreases with more samples; small budgets produce noisy estimates especially when successes are rare. Third, methods that generate diverse candidates can show larger gains as $n$ increases compared to conservative decoders: if correct solutions inhabit low-probability regions, only wide or diverse sampling will find them given a reasonable budget. Therefore comparing models fairly requires controlling sampling budgets or reporting curves across budgets (Pass@K as a function of $n$). It is also common to report normalized or budget-equivalent metrics when budgets differ.

# Tradeoffs between quality and diversity in sampled outputs

Quality and diversity form a fundamental tension in sampling strategies. Quality typically refers to attributes such as grammaticality, semantic coherence, or task-specific correctness; diversity refers to variability across samples. There is no single optimal point on the quality-diversity plane—choice depends on the application.

High-quality outputs usually correspond to high-probability modes under the model. Deterministic decoders or low-temperature sampling concentrate mass on these modes, delivering fluent and often correct outputs. However, they under-explore the model's long tail and are prone to producing similar or repetitive outputs, which is detrimental when multiple candidates are needed (e.g., to hedge against uncertain labels or to propose alternative solutions). Conversely, high diversity is achieved by flat distributions, high temperature, or large $k/p$ in top-k/top-p sampling. High diversity exposes varied possibilities, increases the chance of finding rare but correct outputs (helpful in program synthesis or creative tasks), and is valuable for human-in-the-loop workflows that require multiple options. The downside is a higher incidence of low-quality or incoherent outputs.

The tradeoff can be formalized by considering a utility function that combines quality and diversity objectives. Let S = {x_1, ..., x_n} be a set of samples and define quality score q(x) (e.g., correctness probability or a learned score) and a diversity measure D(S) (e.g., pairwise distance, negative similarity, or entropy). One might optimize for
$ \max_{S} \frac{1}{n}\sum_{x\in S} q(x) + \lambda D(S) $
where $\lambda$ controls the emphasis on diversity. Determinantal point processes (DPPs) are one probabilistic model for sampling sets with repulsion (promoting diversity) while favoring high-quality items. Another approach is to combine beam search with diversity-promoting penalties: when expanding beams, penalize candidates similar to already-selected ones so the set covers different modes.

In RL settings, exploration corresponds to diversity in trajectories that helps discover high-reward regions. However, naive diversity objectives can waste budget exploring regions that are diverse but irrelevant to the reward signal. Shaping intrinsic rewards (e.g., novelty bonuses, prediction error) helps balance exploration with task relevance, but tuning is nontrivial. In sequence generation, using a mixture of deterministic top candidates and a few diverse stochastic samples often yields a practical balance: guarantee some high-quality baseline plus a diversity pool to capture alternatives.

Design choices also include whether to encourage diversity at the token level (e.g., top-k/top-p) or at the sequence level (e.g., promoting distinct complete sequences). Sequence-level diversity is usually more meaningful to downstream tasks but harder to control; naive token-level noise can still produce highly similar sequences due to strong model autocorrelations.

# Using program execution for grounded evaluation of samples

When generating programs or other executable artifacts, raw surface-form comparison (string matching) is a poor proxy for correctness. Program execution provides a grounded method to evaluate samples: run the generated program in a sandboxed environment and check whether it satisfies desired properties (unit tests, integration tests, performance metrics). Execution-based evaluation is widely used in code generation benchmarks and offers several advantages.

First, execution provides concrete, objective signals such as passing all tests or producing correct outputs for given inputs. For program synthesis, Pass@K is naturally defined using test execution. Second, execution allows partial credit and diagnostics: a program might fail a test due to an off-by-one error or a missing import, information that can guide model debugging or automated repair. Third, execution supports automated filtering of invalid or unsafe outputs (e.g., programs attempting to perform restricted operations), which is essential for safe deployment.

However, using execution introduces complexities. Tests must be carefully designed to avoid overfitting (solutions that hard-code outputs for particular tests) and to cover a task's semantic space. Test-suite augmentation—creating diverse input-output pairs, randomized inputs, and property-based tests—improves robustness of evaluation. Measuring generalization beyond provided tests can use held-out unseen inputs or formal specifications where possible.

Another concern is sandboxing and cost: executing arbitrary code can be unsafe, so evaluations must run in secure, resource-limited sandboxes. Execution also adds computational cost, which can dominate evaluation budgets when many samples per prompt are used. For languages or environments where execution is expensive or unavailable, approximate semantic checks (static analysis, type checking, symbolic execution, or unit-test proxies) can provide partial grounding.

Beyond pass/fail testing, program execution enables more nuanced metrics. For example, performance (time/space complexity), adherence to style or API constraints, and resilience to edge cases can be measured by crafted test harnesses. Execution traces and intermediate state can be used to align model rationale with runtime behavior—this is valuable when combining model-generated code with RL: the reward signal becomes the program's correctness or performance, and exploration strategies can be tuned to efficiently find executable solutions.

Using execution for evaluation also interacts with sampling strategy: because execution is expensive, one must allocate sampling budget wisely. For example, generate many candidates using a fast but noisy decoder, filter them by light-weight syntactic checks, and execute only the most promising ones. Alternatively, use a value model trained to predict executability to prioritize candidates for execution. These hybrid pipelines balance the need for grounded evaluation with computational constraints.

Conclusion

Decoding and sampling strategies shape the behavior of probabilistic sequence models in profound ways. Deterministic algorithms like greedy decoding and beam search prioritize high-probability outputs but can lack diversity; stochastic methods (temperature, top-k, top-p) provide flexible levers to trade quality and diversity; structured exploration and tree search enable richer reasoning about future outcomes, crucial for planning and program synthesis. Practical acceleration techniques such as speculative decoding let us scale generation to large models, while careful accounting of sampling budgets informs fair evaluation via metrics like Pass@K and Maj@K. Finally, grounding evaluation via program execution makes outputs measurable and actionable, at the cost of added complexity and computational expense. Understanding these methods, their assumptions, and their tradeoffs is essential for designing generation pipelines, fair evaluations, and effective exploration strategies in both supervised and reinforcement-learning settings.

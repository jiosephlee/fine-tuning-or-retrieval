Introduction

Segmentation and patching are techniques for grouping fine-grained input units (for example, characters, bytes, or tokens) into coarser units (patches, segments, or blocks) before or during processing. These techniques are central in modern machine learning systems because they change both the efficiency of compute and the nature of learned representations. The choices you make about how to group inputs affect model capacity, the effective context length the model can use, latency for generation tasks, and the kinds of regularities the model can learn. In this chapter we explore a range of approaches: fixed, strided patching; boundary-based heuristics that exploit structural cues like whitespace or delimiters; adaptive segmentation ideas that aim for information-uniform windows; constraints that arise when segmentation must be done incrementally during generation; and the practical trade-offs relating patch size, context length, and compute.

# Static (strided) patching and downsampling

Static patching is the simplest class of approaches: split the input into contiguous blocks of a fixed size and treat each block as a single unit. If your original sequence of tokens is $t_1, t_2, \dots, t_N$, a strided patching with patch size $k$ produces patches $p_1 = (t_1,\dots,t_k), p_2 = (t_{k+1},\dots,t_{2k}), \dots$. Often an embedding or a pooling function compresses each patch into a vector representation, which becomes the input to subsequent processing layers.

The main benefits of static patching are simplicity, regular memory layout, and predictable computational cost. For models with quadratic complexity in sequence length (for example, classic self-attention with cost proportional to $O(L^2)$ for sequence length $L$), patching reduces the effective length by a factor of $k$, reducing cost roughly by a factor of $k^2$ for attention-dominated layers. If the original token-level length is $N$ and you create $M = \lceil N/k \rceil$ patches, and if the dominant cost scales like $O(M^2)$, then patching yields a cost reduction factor of approximately $(N/M)^2 \approx k^2$ (ignoring constants and edge effects).

However, the simplicity comes with clear modeling trade-offs. A fixed-size patch assumes that the useful information within each block can be compressed losslessly or acceptably into a single vector. For many domains, important boundaries (e.g., word boundaries, sentence boundaries, or program tokens) do not align with fixed-size windows, so a fixed patch can slice meaningful units in awkward ways. This may increase modeling difficulty because the model must learn to recover intra-patch structure from the compressed representation.

There are a few standard choices for how to summarize patches. A simple method is mean or max pooling across token embeddings within the patch, possibly followed by a learned linear projection. A more expressive approach uses a small local neural network (e.g., a convolutional or recurrent network) to summarize patch contents. Another option is to append a position encoding for the patch and include offset or intra-patch position features so that the downstream model retains some sense of where in the patch each token was.

Static patching is particularly attractive when input structure is roughly uniform (e.g., image patches in vision transformers) or when hardware and throughput constraints demand rigid tiling. But it fails to exploit structural cues that could produce more semantically coherent patches.

# Boundary-based patching heuristics (whitespace, delimiter rules)

A natural refinement over fixed-size patches is to place patch boundaries at natural delimiters in the input. For many languages and data modalities, whitespace, punctuation, newlines, indentation, or special delimiter tokens mark meaningful boundaries: words, phrases, sentences, paragraphs, or code blocks. Boundary-based heuristics group tokens from delimiter to delimiter; for example, define a patch to be one sentence, one line, or one token sequence bounded by a particular punctuation mark.

Using delimiters has several virtues. First, patches are more likely to be semantically coherent: tokens within a patch have stronger syntactic and semantic bonds. This coherence can make it easier for a downstream model to reason at the patch level. Second, delimiter-based patches can adapt their length: short sentences remain short, while long sentences get more representation capacity. Third, boundary heuristics can be computed cheaply and deterministically, without any learned overhead.

But the approach also has limitations. Natural delimiters are irregular: some sentences may be extremely long, yielding patches that are computationally expensive to process, while other patches may be trivially short and waste modeling capacity. To enforce constraints, practitioners often cap patch length or split long spans heuristically (for example, split on commas if a sentence exceeds a maximum token length). There is also a brittle dependence on tokenization granularity: delimiting by whitespace makes sense at character or byte levels but less so when tokenization produces subword tokens that decompose words unpredictably.

Moreover, delimiter rules are domain-specific and require careful engineering. Rules that work well for English text (e.g., splitting on whitespace and punctuation) may be inappropriate for languages without explicit word delimiters, for certain coding languages where punctuation carries different semantic load, or for data like music or sensor streams where delimiters are absent. Finally, deterministic delimiter-based patches do not directly optimize any end-to-end objective; they are heuristics that may or may not align with the model's learning signal.

# Principles of adaptive segmentation (information-uniform windows)

Adaptive segmentation seeks to make patching decisions that are informed by content, with the goal of producing segments that are more uniform in information content rather than uniform in token count. One way to frame the problem is to view the input as a sequence of information-bearing events, where each token has a local information measure such as surprisal or entropy. The objective is to partition the sequence into windows whose total information (e.g., sum of surprisal) is approximately constant. These are called information-uniform windows.

Intuitively, if one window contains many low-information tokens (e.g., repeated whitespace or common stopwords), it should be larger in token count to use the same processing budget as a window of rare, high-information tokens. Conversely, a window containing a named entity, code identifier, or other concentrated information should be smaller in token count, so that the model allocates more resolution to that content.

Operationalizing this idea requires a measurand for token-level information. Surprisal from a language model, $-\log p(t_i \mid \text{context})$, is a common choice. If an auxiliary lightweight model can estimate token probabilities sufficiently well, you can segment by accumulating token surprisal until a threshold $S$ is reached, then emit a segment. Formally, if token surprisal is $s_i$, start a new segment at index $a$ and extend it to the smallest index $b \ge a$ such that

\[
\sum_{i=a}^b s_i \ge S.
\]

This creates windows whose total surprisal is roughly $S$. In practice, you might include lower and upper bounds on segment length to avoid degenerate segments or to satisfy latency constraints.

Alternative information measures include token-level entropy, mutual information with a downstream task, or gradient-based importance scores. Learning segmentation jointly with the downstream model is another direction: segmentation decisions become latent variables optimized end-to-end, for example via reinforcement learning, straight-through estimators, or marginalization techniques. This allows the model to discover segmentation that best supports performance, not just to equalize a heuristic statistic.

Adaptive segmentation introduces complexity: you need an initial estimator for token importance, and segmentation decisions may need to be recomputed if the estimator changes. But it offers potentially large gains in representation efficiency because it devotes capacity to informative pieces of the sequence rather than to uniform blocks.

# Incremental segmentation constraints for generation

When segmentation is used in generation or streaming settings, segmentation must often be incremental and causal: decisions can only rely on past and possibly limited-lookahead context. This imposes constraints distinct from offline segmentation where the entire sequence is known.

One core constraint is monotonicity: once the model has emitted a patch or committed to a segmentation boundary, it cannot later revise past segmentation. This constraint simplifies streaming processing but requires conservative thresholds to avoid frequent resegmentation or expensive backtracking. Another constraint is lookahead: to place a boundary, the segmentation algorithm may need some glimpse of impending tokens. In strict streaming, only the prefix is available, so segmentation must use prefix statistics (e.g., recent surprisal) to decide whether the current segment is “complete”. Practical solutions include using a fixed minimum window length, requiring a separator token to finalize a segment, or allowing limited lookahead buffers.

A particular challenge arises for autoregressive decoders that generate token-by-token: patch-level processing should not block generation or introduce inconsistencies. If the encoder compresses the source into patches, the decoder must be able to attend to patch representations while generating tokens. In incremental settings, you may want to incrementally form patches as new source tokens arrive and stream their compressed representations to the decoder. This demands fast summarization and possibly hierarchical caching: within a patch, compute a local summary as tokens stream in, and only once the patch is complete commit the summary to the global context.

Another practical constraint is alignment between segmentation for encoding and segmentation expected by downstream components. For example, if a translator increments both source segmentation and target generation, misaligned boundaries can cause latency spikes or re-translation. To reduce this, many systems adopt stable segmentation rules (e.g., finalize segments at sentence endings) or allow re-encoding of previous segments with low overhead.

In some architectures, incremental segmentation is learned: a gating mechanism predicts segment ends using only the prefix, and the model is trained to minimize downstream loss plus penalties for latency or segment count. Techniques such as monotonic chunkwise attention in speech recognition are specific instances where segmentation is coupled to causal attention mechanisms.

# Trade-offs between patch size, context length, and compute

Designing a segmentation strategy requires balancing three intertwined quantities: patch size (how many tokens per patch), effective context length (how many tokens can be considered jointly by the model), and compute cost (time and memory). These trade-offs are quantitative and qualitative.

Quantitatively, for a transformer-style block with attention cost proportional to $O(M^2)$ for $M$ patches, and local patching compression that costs $O(k)$ per patch (for example, a small network summarizing $k$ tokens), the total compute per layer scales like

\[
\text{Compute} \approx c_1 M^2 + c_2 M k,
\]

where $M = N / k$. Substituting yields

\[
\text{Compute} \approx c_1 \left(\frac{N}{k}\right)^2 + c_2 N.
\]

For sufficiently large $k$, the first term declines as $1/k^2$, but the second term is linear in $N$ and independent of $k$. There is an inflection point where further increasing patch size yields diminishing returns because the intra-patch summarization cost and the representational loss dominate. This analysis shows that choosing $k$ affects compute quadratically through attention but linearly through patch summarization.

Context length trade-offs are about information access. A large patch size reduces the number of patches the model can attend over for a fixed computational budget, thereby increasing the effective horizon in terms of original tokens. For example, doubling patch size doubles the total number of original tokens accessible for the same attention cost. But larger patches lose intra-patch resolution: relationships between tokens within the same patch are only available through the summarizer, which may or may not preserve the necessary details.

From a learning perspective, patch size impacts expressivity and generalization. Small patches keep more low-level structure available to the model, which can learn fine-grained patterns but at higher runtime cost. Large patches force the model to operate at a higher abstraction level, promoting generalization over long-range structure but potentially missing local phenomena. The choice depends on task characteristics: language modeling may tolerate coarser patches for common function words but require finer resolution near named entities or rare tokens; code completion needs finer granularity to preserve syntactic details.

Adaptive strategies try to get the best of both worlds: use small patches where detail matters and large patches where tokens are repetitive or low-information. But adaptive methods add runtime overhead, complexity, and sometimes unpredictable worst-case costs (e.g., if many high-information regions cluster).

Finally, consider latency: larger patches can reduce per-step overhead for batch processing but increase buffering latency for incremental systems because you must wait for a full patch before compressing it. In real-time systems, smaller patches or streaming summaries with aggressive finalization are favored despite less optimal compute efficiency.

Conclusion

Segmentation and patching are powerful levers that reshape the computational and statistical properties of sequence models. Static patching is simple and predictable but inflexible; boundary-based heuristics exploit domain structure but can be brittle; adaptive segmentation aims to allocate capacity by information content but requires reliable importance estimates and often additional machinery; incremental segmentation imposes causality and latency constraints that shape architectures; and all approaches must navigate the trade-offs between patch size, context length, and compute. Understanding these trade-offs, and selecting or designing segmentation methods that match the task and system constraints, is crucial when building efficient, high-performance sequence models.

Introduction

Attention mechanisms — most prominently the scaled dot-product attention used in Transformer models — are central to modern sequence modeling. They allow each token to attend to every other token, enabling rich contextual representations. However, the naive implementation of attention scales quadratically in sequence length with respect to both computation and memory, which becomes a major bottleneck when sequences are long (e.g., thousands to millions of tokens). This chapter examines that scaling problem in detail and surveys practical algorithmic and implementation techniques that reduce compute and memory costs while preserving as much of the modeling power of full attention as possible. We begin by formalizing attention complexity and the sources of its inefficiency. We then introduce windowed and local attention as simple scalable approximations, and generalize to sparse and block-sparse patterns that strike different tradeoffs between efficiency and expressivity. After covering algorithmic patterns, we shift to implementation-level optimizations: FlashAttention, which fuses kernels and reorders computation to reduce memory drains, and FlexAttention-style dynamic-mask fused kernels that support changing attention patterns without excessive overhead. We conclude with practical guidance for training large models: precision choices, memory-reduction techniques, batching and sharding strategies, and debugging tips.

# Attention complexity and scalability (O(n^2) issues)

Scaled dot-product attention for a single attention head is usually written as
$A(Q,K,V) = \mathrm{softmax}\bigl(\tfrac{QK^\top}{\sqrt{d_k}}\bigr) V,$
where $Q, K, V \in \mathbb{R}^{n\times d_k}$ for a sequence length $n$ and head dimension $d_k$. The dominant costs come from two places: computing all pairwise similarities $QK^\top$ and storing the intermediate similarity matrix prior to the softmax, and then storing the attention weights for the backward pass during training.

Computationally, forming $QK^\top$ is a matrix multiply of shape $(n \times d_k)(d_k \times n)$ costing $O(n^2 d_k)$ floating point operations. If there are $h$ heads and model dimension $d$, the cost per layer is $O(h n^2 d/h) = O(n^2 d)$, often simplified as $O(n^2 d)$ or, when focusing only on sequence length, $O(n^2)$. Memory is also $O(n^2)$ because the attention logits and normalized attention weights are $n\times n$ matrices. During training, storing these for the backward pass multiplies the memory pressure.

Why is $O(n^2)$ a problem in practice? Consider $n=4096$ and $d=1024$: the attention matrix of size $n\times n$ is 16 million entries; with 4 bytes per float32, just one head's attention logits is 64 MB; with several layers and heads, this quickly exceeds GPU memory budgets. The computational cost similarly grows, making both training and inference slow for large $n$. This quadratic dependency is the primary motivation for specialized attention approximations and implementation tricks.

Beyond asymptotics, the constant factors and memory access patterns matter: building and reading large $n\times n$ matrices results in cache misses and memory bandwidth bottlenecks. Moreover, many real-world tasks require long contexts (document-level NLP, genomics, audio, video), so naive quadratic attention becomes economically infeasible. Thus, improving attention efficiency requires algorithmic reduction of the $n^2$ term or lowering the constants and memory footprint of the naive algorithm.

# Windowed and local attention

Windowed or local attention restricts the attention operation so that each token attends only to nearby tokens within a fixed-size window. Formally, for a window radius $w$, token $i$ attends only to tokens $j$ such that $|i-j|\le w$. This reduces per-token attention cost from $O(n)$ to $O(w)$, and the layer cost from $O(n^2 d)$ to $O(n w d)$, that is, linear in $n$ for fixed $w$.

Intuitively, local attention encodes the inductive bias that nearby tokens are more relevant than faraway ones, which is valid for many sequence modalities where locality is important (language, audio, time-series). Practically, sliding-window attention was used in models like Transformer-XL and Longformer as a way to scale to longer sequences. Windowed attention is simple to implement and has excellent memory locality: each output position needs only a small block of keys and values, enabling streaming and efficient caching.

However, local attention has limitations. Fixed windows limit the receptive field: information that needs to flow from distant tokens must traverse many layers to propagate across the sequence. For tasks requiring long-range dependencies in a single layer (e.g., coreference with far-away antecedents), local attention alone can underperform. Several mitigations exist. One strategy is to interleave local attention layers with global tokens or pooling tokens that gather and redistribute information across blocks. Another is to use dilated local attention, where each attention step skips tokens to increase effective receptive field while keeping per-token cost small, or to stack many layers to expand the context.

Design choices for windowed attention include whether to use symmetric windows, allow causal (left-only) windows for autoregressive settings, and how to handle block boundaries. Implementation details — such as packing tokens into blocks and using efficient strided memory access — affect performance. Overall, windowed attention provides a simple, low-overhead route to linear scaling in $n$, at the cost of reduced expressivity for long-range interactions unless augmented.

# Sparse and block-sparse attention patterns

Sparse attention generalizes windowed attention by allowing arbitrary sparsity patterns in the $n\times n$ attention matrix so each query attends to only a subset of keys. A sparse pattern might include local neighborhoods, a set of global token indices, strided/dilated connections, or learned sparsity via routing. The goal is to reduce computation and memory to $O(n s)$ where $s$ is the average number of keys attended per query (often $s \ll n$). Block-sparse attention restricts sparsity at the granularity of contiguous blocks: the matrix is partitioned into blocks, and only certain blocks are computed.

Block-sparse patterns are attractive for implementation: blocks align well with GPU memory accesses and batched matrix multiplications. For example, partition the sequence into $B$ blocks of size $b$ so $n = B b$. If each query block attends to $r$ key blocks, the cost becomes $O(B r b^2 d)$ which simplifies to $O(n r b d / b) = O(n r b d)$. Choosing $b$ and $r$ balances compute and expressivity. Block sparsity is used in implementations like BigBird and Sparse Transformers, which use combinations of local block windows, random/global blocks, and strided blocks to maintain theoretical connectivity (e.g., ensuring any two positions can reach each other by a short path).

From a modeling perspective, sparse patterns trade representational fidelity for efficiency. Careful pattern design can preserve expressivity: combining local blocks with a handful of global or random links provides good empirical performance and theoretical guarantees of mixing. Learned sparsity mechanisms attempt to adapt which keys are attended per query, but practical learned-sparse methods can be expensive because they usually require computing some routing scores over many candidates. A middle ground is top-k attention where each query attends to the top $k$ keys by similarity; however, computing exact top-k over all keys again induces $O(n^2)$ work unless approximations or sampling are used.

Implementing sparse/block-sparse attention efficiently requires support from low-level libraries or custom kernels. Standard dense matmul libraries cannot directly exploit sparsity without packing the computed blocks. End-to-end efficiency depends on reducing memory copies, minimizing small-kernel overhead, and maximizing tensor cores or SIMD usage on GPUs/TPUs. When block sizes are chosen to align with hardware-friendly tile sizes (e.g., multiples of 16 or 32), sparse attention can be near-optimal.

# FlashAttention: fused kernels and memory-efficient attention

FlashAttention is an implementation technique that computes attention with $O(n^2)$ arithmetic complexity but reduces memory usage and dramatically improves throughput by reordering computation and fusing kernels to avoid materializing the full $n\times n$ attention matrix. The key idea is to compute attention in tiles and compute the softmax-normalized weighted sum incrementally, storing only a few tiles in fast memory at a time. This removes the need to store the entire attention matrix in GPU memory, avoiding a crucial memory bottleneck particularly during training where intermediate activations are retained for backward.

Consider computing $S = \exp(QK^\top / \sqrt{d_k})$ and then normalizing rows to form attention weights. FlashAttention computes the attention output $O_i = \sum_j \alpha_{ij} V_j$ for each row $i$ by iterating over blocks of keys $j$ in a streaming fashion. For a given query block, FlashAttention computes the block-wise logits, applies a numerically stable incremental softmax (using log-sum-exp updates to re-normalize when merging blocks), and accumulates the weighted sum $\sum \alpha_{ij} V_j$ without ever storing the full $\alpha$ matrix. This streaming softmax trick preserves numerical stability and produces identical results to the naive softmax computation up to floating point rounding.

Implementationally, FlashAttention fuses the following operations into single kernels: the tiled matrix multiplication to compute a block of logits, the mask application (if any), the softmax computation across that block (with merges), and the accumulation with $V$. The fused kernel reduces global memory reads/writes, leverages GPU shared memory, and uses Tensor Cores when available. The result is both lower memory usage (only $O(n d)$ needed for $Q,K,V,O$ plus small tile buffers) and faster throughput than naïve GEMM-based implementations which materialize logits and multiply by $V$ in separate steps. FlashAttention has been shown to support larger sequence lengths on fixed-memory GPUs and to speed up both forward and backward passes.

FlashAttention is particularly effective when $d_k$ fits well into tile-friendly dimensions and when sequences are long enough to amortize kernel launch costs. Its compatibility with mixed precision (e.g., computing in float16 or bfloat16 while maintaining numerical stability via log-sum-exp) further improves performance. However, FlashAttention is still $O(n^2)$ in total arithmetic and does not asymptotically remove quadratic compute — it primarily reduces memory and constant factors, enabling practical training of longer sequences without changing the attention pattern.

# FlexAttention and dynamic-mask fused implementations

Many practical attention patterns require dynamic masks that vary across positions, batches, or time steps — for example, causal masks for autoregression, padding masks in variable-length batches, local windows that change at block boundaries, or learned routing that is sequence-dependent. Naïve implementations applying a general mask often require constructing a full $n\times n$ mask and performing masked softmax over the full logits, incurring memory and computation overhead. FlexAttention-style techniques focus on fusing attention computation with dynamic masks so that only relevant entries are computed and extraneous work and memory allocation are avoided.

FlexAttention (a representative name for dynamic-mask fused approaches) integrates masking, computation, and memory management into tiled attention kernels. Instead of computing $QK^\top$ for all pairs and then zeroing out masked entries, the kernel checks mask conditions at the tile or element level and skips computation or accumulation for masked pairs. For masks with structure (e.g., causal masks, padding masks, or block patterns), FlexAttention can avoid computing entire tiles by using tile-level metadata: if a tile is fully masked, it is skipped; if partially masked, the kernel computes only the unmasked lanes. This reduces arithmetic work to the number of unmasked query-key pairs.

The dynamic aspect also includes masks that change per batch element (common with variable-length sequences) or across layers (e.g., different heads having different sparsity). FlexAttention kernels accept compact mask encodings — bitmasks, range descriptors, or per-block flags — and perform masking checks in shared memory to avoid heavy branching penalties. Critically, these kernels maintain the same streaming softmax approach as FlashAttention so that only small temporary buffers are required and backward passes do not require storing large masked attention matrices.

FlexAttention-style fused implementations are essential when combining sparse attention patterns with modern training needs: mixed-precision, pipelined parallelism, and per-example masks. They avoid the overhead of unpacking sparse patterns into irregular CPU/GPU loops and prevent costly synchronization. Nonetheless, they add implementation complexity: writing custom CUDA/ROCm kernels that handle all mask shapes and maintain numerical stability demands careful engineering. Additionally, extremely irregular dynamic masks (completely different sparsity patterns per query) reduce the opportunity to batch work and lower hardware utilization; in such cases, grouping sequences by mask patterns or precomputing routing helps.

# Practical considerations for training large models

Training large models with attention, especially long-context models, requires attention to many practical aspects beyond algorithmic choice. Memory budget, hardware topology (GPU/TPU memory and interconnects), mixed precision, optimizers, communication patterns, and software tooling all interact to determine what is feasible.

Precision and numerical stability: Mixed precision (float16 or bfloat16) substantially reduces memory and increases throughput on modern accelerators. However, softmax and accumulation steps are sensitive to precision. Techniques like scaled casting, keeping numeric accumulators in higher precision, and using stable reductions (log-sum-exp for softmax) are important. FlashAttention and similar fused kernels implement numerically stable softmax in low precision by using intermediate accumulation in float32 or bfloat32 when necessary.

Gradient checkpoints and activation memory: Activation memory can be reduced by recomputing forward activations during backward using gradient checkpointing. For attention layers, one can checkpoint around multi-layer blocks, or use reversible layers to avoid storing activations. Combined with FlashAttention's low-memory forward, gradient checkpoints enable training longer sequences at the cost of extra compute in the backward pass.

Optimizer memory and state sharding: Optimizers typically require extra memory per parameter for momentum/second-moment estimates. Using optimizers with smaller state (e.g., Adafactor) or sharding optimizer state across devices (e.g., ZeRO from DeepSpeed) allows training larger models or larger batches. When attention layers dominate memory, distributing parameter and optimizer state helps overall fitting.

Batching, padding, and packing: Efficient utilization of GPUs depends on batching. Variable-length sequences create padding overhead, which exacerbates attention costs since masked tokens still often participate in compute unless dynamic fused masks are used. Sequence packing (concatenating shorter sequences into long packed sequences) reduces padding but requires careful boundary masks. For streaming or causal workloads, use of bucketing and packing strategies improves hardware utilization and reduces wasted attention work.

Distributed training choices: Model parallelism (tensor and pipeline), data parallelism, and sequence parallelism interact with attention implementation. For example, FlashAttention works on per-device local shards of a sequence; cross-device attention requires communication for keys/values. Sequence parallelism that shards sequence dimension across devices must exchange $K,V$ fragments or implement cross-device FlashAttention, increasing communication complexity. Designs like ZeRO-3 or offloading help but need to be balanced against communication overhead.

Profiling, kernel fusion, and hardware characteristics: Performance is sensitive to choice of block sizes and tensor strides; profiling tools help tune these. Kernel fusion reduces memory traffic and kernel-launch overhead but complicates debugging. Hardware features such as fast shared memory, large L2 caches, and Tensor Cores influence which algorithms perform best. Choose block sizes that allow high utilization of matrix-multiply units and align to warp/tile sizes.

Debugging and numerical issues: When using fused kernels or low precision, ensure numerical equivalence tests against reference implementations. Watch for NaNs from unstable softmax or gradient explosions. Use gradient clipping and learning rate warmup for deep attention stacks. Monitor per-layer activation statistics to detect saturation or dead heads.

Modeling tradeoffs: Algorithmic approximations (local, sparse) change inductive biases. Evaluate them on target tasks; sometimes combining approximations (local + global tokens) gives most of the benefits. When using learned sparsity or routing, ensure routing overhead does not negate the compute savings.

In summary, successfully training large models with efficient attention requires a systems-aware approach: pick an attention pattern that balances expressivity and efficiency for your task; use memory-efficient fused kernels like FlashAttention for dense or structured attention; employ dynamic-mask fused kernels like FlexAttention for irregular masks; and carefully manage precision, optimizer state, and parallelism strategies to fit within hardware constraints.

Conclusion

Reducing attention compute and memory for long sequences is an active area combining algorithmic approximations and systems engineering. Windowed and sparse patterns reduce asymptotic complexity at the cost of some expressivity; FlashAttention and fused dynamic-mask kernels reduce constants and memory without changing algorithmic complexity. Practical training of large models demands integration of these ideas with mixed precision, optimizer-state sharding, and careful batching. Understanding both the mathematical tradeoffs and the low-level implementation details is essential to scale attention-based models to the sequence lengths required by modern applications.

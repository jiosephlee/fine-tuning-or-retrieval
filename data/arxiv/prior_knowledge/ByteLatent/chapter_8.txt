# Introduction

Cross-attention is a central building block in modern neural architectures that map information from one representation space into another. Where self-attention lets elements of a single sequence interact with one another, cross-attention provides a directed mechanism: a set of queries (the "readers") consult a separate set of keys and values (the "memory" or "source") to gather information relevant to each query. This directed querying pattern is fundamental to encoder–decoder models for sequence transduction, to retrieval-augmented models that consult an external datastore, and to multimodal models that align modalities such as text and images.

This chapter explains the mechanics and intuition of cross-attention in detail. We start by clarifying the roles of queries, keys, and values in cross-attention. We then contrast cross-attention with self-attention, discuss masking patterns, and describe typical use cases. Next we explore strategies for initializing queries (learned queries, pooled queries, and hashed queries), with trade-offs and examples. We then derive the multi-head cross-attention equations and cover practical implementation details and complexity. Finally, we examine common residual and normalization patterns used around cross-attention—how to stabilize training, combine cross-attention with feedforward blocks, and where design choices like pre-norm, post-norm, gating, and dropout fit in.

# Query-Key-Value roles in cross-attention

To understand cross-attention, the simplest mental model is to think of three distinct roles: queries (Q), keys (K), and values (V). Each role answers a specific question.

- The query expresses "what I want" or "what I am asking for." A query typically comes from the target representation that is supposed to be updated or informed by external information. For example, in a sequence-to-sequence model the decoder token at position $t$ produces a query that asks: "what should I attend to in the encoder outputs to decide the next token?"

- The key represents "what you have" in a compact, searchable form. Keys are derived from the source representation (the memory). The dot product between a query and a key indicates how relevant that source position is to the query. Keys should therefore capture features of the source that are useful for matching against queries.

- The value represents "what I will take" or the payload returned when a key matches a query. Values are what are aggregated (typically via a weighted sum) to form the output for a given query. Because values are directly mixed into the final representation, they often contain richer or higher-capacity information than keys, while keys are optimized for discriminative matching.

Mathematically, given query vectors $\{q_i\}_{i=1}^{N_q}$, key vectors $\{k_j\}_{j=1}^{N_k}$, and value vectors $\{v_j\}_{j=1}^{N_k}$, cross-attention computes attention weights between each query and each key, uses those weights to produce a convex combination of values, and returns outputs $\{o_i\}_{i=1}^{N_q}$ where

$o_i = \sum_{j=1}^{N_k} \alpha_{ij} v_j$, 

and

$\alpha_{ij} = \frac{\exp\!\left(s(q_i, k_j)\right)}{\sum_{j'=1}^{N_k} \exp\!\left(s(q_i, k_{j'})\right)}$.

Here $s(q,k)$ is a scoring function, most commonly the scaled dot product $s(q,k) = \frac{q^\top k}{\sqrt{d}}$ where $d$ is the dimensionality of the key vectors (or the per-head dimension in multi-head attention). The scaling $\sqrt{d}$ counteracts the tendency for the dot products to grow with dimension, which would push the softmax into regions with very small gradients.

Several important implications follow from these roles:

- Asymmetric information flow: In cross-attention, information flows from the keys/values into the queries; the source representation is not modified by this attention (unless you explicitly aggregate or write back). This asymmetry is what enables encoder–decoder separation, retrieval, and memory access.

- Decoupling of matching and payload: Because keys and values are separate projections from the same source representations, you can design keys to be compact and fast to compare while making values higher-capacity to encode the content that will be used downstream.

- Flexibility in number and origin of elements: The number of queries $N_q$ and the number of keys/values $N_k$ can differ. Queries can be a single pooled vector, many token-level vectors, or special “read” tokens. Keys/values can be long sequences, compressed representations, or even external memory outside the model.

Understanding Q/K/V roles helps when engineering architectures: if you want to control what is matched vs what is returned, you change the key versus value projections; if you want to limit how much content is injected, you alter the dimensionalities and regularization of the value projections.

# Cross-attention vs. self-attention: use cases and masks

Self-attention and cross-attention are closely related mathematically but differ in how they are used and what they allow.

Self-attention: queries, keys, and values all come from the same set of vectors (typically the same sequence). Each element attends to other elements of the same sequence. Self-attention is permutation-aware (given positional encodings) and enables global mixing of information within the same representation, which is central to building deep contextual representations.

Cross-attention: queries come from one representation (the target), while keys and values come from another (the source). Cross-attention is directional: the target is updated using information from the source but not vice versa. This design is ideal when source and target have distinct roles—encoders supply content, decoders request it.

Use cases

- Sequence transduction (encoder–decoder): In transformer-based sequence-to-sequence models, during decoding each decoder layer contains self-attention over the decoder prefix and cross-attention over encoder outputs. Cross-attention lets the decoder consult encoded source tokens to generate contextually relevant outputs.

- Retrieval and memory augmentation: Models can query an external datastore of embeddings (K/V). The model generates queries from the current context and uses cross-attention to retrieve and integrate relevant documents or facts.

- Multimodal fusion: One modality (e.g., text queries) attends to embeddings from another modality (e.g., image patches) to condition the text representation on visual content.

- Layered conditioning: Cross-attention is useful to condition a base network on side information (style tokens, control signals, prompts) where the conditioning information remains separate from the primary sequence.

Masking patterns

Masking controls which keys a given query may attend to. Masks are binary or additive tensors applied to attention logits before softmax. There are several typical masking patterns:

- No mask (full cross-attention): Every query may attend to every key. This is standard when the source is fully observed and there is no temporal constraint. For example, in encoder–decoder cross-attention during training, the encoder is fully visible so the decoder can attend to any encoder position.

- Causal (autoregressive) masks on the query side: For decoder self-attention a causal mask prevents tokens from attending to future tokens. For cross-attention, causal masks are usually not applied since keys reside in the encoder, but a model might impose restrictions when the source itself is a growing stream.

- Key-side reductions or sparsity masks: When keys represent a large memory, masks can restrict queries to only a subset of keys (e.g., keys within a local window, keys with matching hash buckets, or keys preselected by a retriever). These masks reduce compute and enforce locality or relevance.

- Pointer or coverage masks: In certain tasks, you might want to prevent attending multiple times to the same source token or to encourage coverage; masks or loss terms can implement such constraints.

When to use which attention

- Use self-attention when the model should build contextualized representations internal to a set of elements, and when symmetry among elements is desired.

- Use cross-attention when conditioning one representation on another distinct representation, especially when you want to preserve a separation of concerns (source stays intact; target is enriched).

- Use masks to enforce causality, sparsity, or domain-specific restrictions on which source positions may be consulted. For example, avoid using target self-attention to see future tokens during training by applying a causal mask; avoid consulting remote memory entries by masking them out.

Understanding these differences helps you design pipelines: cross-attention naturally implements read-only memory access and is the right abstraction when information should be injected into a target without mutating the source.

# Initializing queries (learned, pooled, hashed)

Queries are the active side of cross-attention: they formulate what to look for. Choosing how to initialize queries dramatically affects what information is retrieved, how much compute is needed, and how easy optimization is. There are three common strategies: learned queries, pooled queries, and hashed (or routed) queries. Each has distinct trade-offs.

Learned queries

Learned queries are fixed parameters—vectors that are optimized during training and used as queries whenever cross-attention is executed. This pattern appears in DETR and in some decoder-only designs where a small set of learned "slot" queries accumulate information from an encoder or from memory.

Learned queries are simple: you instantiate $M$ vectors $\{q_m\}_{m=1}^M$ that are reshaped/expanded to the appropriate batch size (often tiled across examples) and fed into cross-attention. Because the queries are constant across inputs, the model learns to use them as reusable read heads that extract particular kinds of information from the source. For instance, one query may specialize to find object bounding boxes, another to identify the overall sentiment, and so on.

Advantages:
- Low overhead at inference: queries are static; only keys/values change.
- Easier to cache and reuse.
- Encourages specialization of read heads.

Disadvantages:
- Limited input-specificity: static queries cannot encode dynamic intents unless the cross-attention is conditioned by additional mechanisms.
- Potential underutilization if queries cannot cover all needed aspects.

Pooled queries

Pooled queries are derived from the target side by pooling information across tokens. Common pooling strategies include using a special token ("[CLS]"), average pooling, max pooling, or attention-pooling where a small network computes pooling weights. Pooled queries are input-dependent and can capture the current state or intent of the target.

A typical design: compute a pooled vector $p$ via average over decoder layer outputs or a learned linear projection of the last decoder token, then project $p$ to one or more query vectors. Formally, if $X_\text{tgt} \in \mathbb{R}^{N_q \times D}$ are target vectors, a pooled query is $q = W_p \cdot \text{pool}(X_\text{tgt})$.

Advantages:
- Input-adaptive: queries encode the current target context and can retrieve source information specifically relevant to it.
- Intuitive for retrieval-augmented generation: use the decoder state as a query to fetch documents.

Disadvantages:
- More compute per example: queries must be computed dynamically.
- If pooling is too coarse, the queries may lose fine-grained distinctions (e.g., per-token needs).

Hashed or routed queries

Hashed queries are generated by partitioning keys into buckets (often with locality-sensitive hashing or learned routing) and then forming queries that target particular buckets. In practice, hashing is used primarily to accelerate attention by limiting the set of keys each query considers. There are a few ways hashing interacts with query initialization:

- Query-side hashing: queries are assigned to hash buckets before attention, and they only attend to keys in the same bucket. This effectively initializes each query to address a subset of the memory.

- Learned routing: a small network predicts a routing distribution over memory partitions; the query is a slot that routes to a subset of keys.

Hashing and routing can also be used to create compressed queries: for example, you cluster the source into $M$ clusters and then create $M$ slot queries that attend to cluster centroids. This is common in compressed attention variants.

Advantages:
- Computational efficiency: reduces quadratic attention to sparse attention over a subset of keys.
- Scalability: allows very large memories to be accessed by routing or hashing.

Disadvantages:
- Potential misses: if hashing/routing misroutes a relevant key into another bucket, the query cannot access it.
- Complexity: requires auxiliary structures (LSH tables, clustering, routing models) and careful design to maintain gradients and coverage.

Choosing a query initialization

The choice depends on the problem. If you need per-token conditioning and the target sequence is meaningful (e.g., translation decoder), pooled or token-derived queries make sense. If you want a small set of reusable read heads or latent slots that the source fills in, use learned queries. If memory is very large and efficiency is crucial, consider hashed or routed queries with sparsity-aware attention. In many practical systems, combinations are used: learned queries at a particular layer complemented by pooled queries at another, or learned slots that are initialized by pooling and then refined.

# Multi-head cross-attention math and implementation

Multi-head attention increases model capacity by allowing the model to perform multiple parallel attention computations with different learned projections. This is as true for cross-attention as it is for self-attention. A careful derivation helps both implementers and researchers reason about shapes, complexity, and how to optimize the operations.

Formulation

Let the target (queries) be represented by $X_Q \in \mathbb{R}^{N_q \times D}$ and the source (keys/values) by $X_K \in \mathbb{R}^{N_k \times D}$. The multi-head cross-attention with $H$ heads works as follows.

For head $h$ with head dimension $d_h$ (commonly $d_h = D / H$), have learned projection matrices:
- $W^Q_h \in \mathbb{R}^{D \times d_h}$,
- $W^K_h \in \mathbb{R}^{D \times d_h}$,
- $W^V_h \in \mathbb{R}^{D \times d_h}$.

Compute per-head queries, keys, and values:
- $Q_h = X_Q W^Q_h \in \mathbb{R}^{N_q \times d_h}$,
- $K_h = X_K W^K_h \in \mathbb{R}^{N_k \times d_h}$,
- $V_h = X_K W^V_h \in \mathbb{R}^{N_k \times d_h}$.

Compute scaled dot-product attention logits and weights:
- $S_h = \frac{Q_h K_h^\top}{\sqrt{d_h}} \in \mathbb{R}^{N_q \times N_k}$,
- $\alpha_h = \text{softmax}(S_h + M)$, where $M$ is an optional mask (e.g., $-\infty$ for disallowed positions).

Aggregate values:
- $O_h = \alpha_h V_h \in \mathbb{R}^{N_q \times d_h}$.

Concatenate heads and apply output projection:
- $O = \text{Concat}(O_1, \dots, O_H) W^O$, where $W^O \in \mathbb{R}^{D \times D}$, producing $O \in \mathbb{R}^{N_q \times D}$.

A compact implementation uses combined weight matrices to compute all heads with a few matrix multiplications:

- Compute $Q = X_Q W^Q$ with $W^Q \in \mathbb{R}^{D \times D}$ that concatenates the $W^Q_h$; similarly for $K$ and $V$.
- Reshape $Q$ to $\mathbb{R}^{N_q \times H \times d_h}$ (often implemented as $\mathbb{R}^{H \times N_q \times d_h}$ for batching) and operate over the $H$ heads in parallel.
- Compute attention for each head and recombine.

Complexity

The dominant cost is computing the attention logits, which requires $O(H \cdot N_q \cdot N_k \cdot d_h)$ operations. If $N_q \approx N_k \approx N$ and $D = H d_h$, the cost is $O(N^2 D)$. Memory for storing logits is $O(N_q N_k H)$ unless heads share computation; in practice implementations reduce memory by computing heads in blocks and using fused kernels.

Implementation details and tricks

- Numerical stability: the usual softmax over logits can produce numerically tiny gradients if logits become large; the $\sqrt{d_h}$ scaling helps, and implementations often use stable softmax kernels.

- Masking: implement masks as additive matrices that set masked logits to a large negative value (e.g., $-1e9$) before softmax.

- Batching and shape layout: libraries often prefer shapes like $(B, N, H, d_h)$ or $(B, H, N, d_h)$. Efficient CUDA kernels expect contiguous memory layouts and may fuse the linear projections Q/K/V into a single GEMM.

- Relative position and bias additions: you can add learned biases or relative position encodings to the logits $S_h$. For cross-attention, positional biases are typically applied to keys or queries depending on whether positions of the source or target matter. If the source and target have independent positional spaces (e.g., image patches vs. text tokens), design positional encodings accordingly.

- Caching: in decoder cross-attention during autoregressive decoding, encoder keys and values are static for a given input and can be cached across decoding steps. This saves recomputation of $K_h$ and $V_h$. Conversely, the queries change at each time step and must be recomputed.

- Parallelism and memory: when $N_k$ is large (e.g., long documents or large retrieval sets), consider sparse attention, low-rank approximations, or chunked computation. Use block-sparse attention or retrieval to limit $N_k$ per query.

- Weight tying and shared projections: you can tie $W^K_h$ and $W^V_h$ across heads or layers to reduce parameters, though this changes representational capacity.

- Implementation in high-level frameworks: in PyTorch or TensorFlow, multi-head cross-attention is typically implemented by projecting Q/K/V with separate linear layers (or a single linear layer that outputs concatenated heads), reshaping into heads, computing batched matmuls for attention logits and weighted sums, and applying an output linear. Many frameworks supply optimized attention ops; when implementing from scratch, pay attention to memory layout for efficient matmuls.

Batching shape example

For a batch size $B$, queries shape $(B, N_q, D)$ and keys/values shape $(B, N_k, D)$. After computing combined projections you get:
- $Q$ shaped $(B, N_q, H, d_h)$,
- $K$ shaped $(B, N_k, H, d_h)$,
- $V$ shaped $(B, N_k, H, d_h)$.

The attention logits for each head use batched matmul over the last two dims resulting in logits shape $(B, H, N_q, N_k)$, and softmax and matmul with $V$ yield output per head $(B, N_q, H, d_h)$. Concatenate heads to $(B, N_q, D)$, then multiply by $W^O$ to get final outputs.

Multi-head cross-attention thus gives expressive power by allowing multiple distinct similarity functions and payload projections simultaneously, letting the model attend to different aspects of the source in parallel.

# Residual and normalization patterns around cross-attention

Cross-attention is typically used inside larger layers or blocks, so how it is wired with residual connections, normalization, dropout, and feedforward networks matters a great deal for training stability and performance. The two most common high-level patterns are the pre-norm and post-norm transformer blocks; additional variants include gated residuals, parallel attention/feedforward branches, and specialized normalization choices.

Pre-norm vs post-norm

In a residual block with an operation $F(\cdot)$, the two patterns are:

- Post-norm (original Transformer): $y = \text{LayerNorm}(x + F(x))$.
- Pre-norm (often used in modern Transformers): $y = x + \text{Dropout}(F(\text{LayerNorm}(x)))$ (with LayerNorm applied before the sub-layer and often another LayerNorm before the feedforward).

Empirically, pre-norm architectures are more stable for deep transformers: applying normalization before attention or feedforward tends to keep gradient norms controlled and avoids exploding or vanishing gradients as depth increases. In practice many modern models use pre-norm for both self-attention and cross-attention sub-layers.

Typical decoder layer layout

In an encoder–decoder Transformer decoder layer, a common pre-norm design is:

1. Self-attention sub-layer (pre-norm):
   - $x_1 = x + \text{Dropout}(\text{MultiHeadSelfAttention}(\text{LayerNorm}(x)))$.

2. Cross-attention sub-layer (pre-norm):
   - $x_2 = x_1 + \text{Dropout}(\text{MultiHeadCrossAttention}(\text{LayerNorm}(x_1), \, \text{encoder\_states}))$.
   Here the LayerNorm is applied to the query input ($x_1$); keys/values from encoder are either normalized once or supplied as-is depending on design.

3. Feedforward sub-layer (pre-norm):
   - $x_{out} = x_2 + \text{Dropout}(\text{FFN}(\text{LayerNorm}(x_2)))$.

This pattern applies LayerNorm to the query-side input before each sub-layer, leaving the source encoder representations usually unchanged (or normalized separately during encoder computation).

Cross-attention specific considerations

- Where to apply normalization on keys/values: keys and values originate from a different representation. Typical choices are: use those representations as produced by the encoder (already normalized if encoder used pre-norm); optionally apply a separate LayerNorm to keys/values just before projecting to $K$ and $V$ to standardize scales and improve numerical conditioning. A common practical choice is to leave encoder outputs as-is and only LayerNorm the decoder query inputs.

- Residual connect to the right place: the residual for cross-attention adds the cross-attention output to the query input, not to the source. This keeps cross-attention a read-only operation for the source.

- Dropout placement: dropout is applied to attention weights and to the output of attention before adding to the residual. Typical options include dropout on $V$ after the weighted sum or dropout on the pre-softmax logits; you should tune the dropout locations and rates for regularization.

- Gating: some architectures add gating mechanisms to control how much cross-attention output is integrated. For example, compute a gate $g = \sigma(W_g x + b_g)$ and set $x' = x + g \odot \text{Dropout}(O)$. Gating can help when you want the model to attend optionally to the source (e.g., skip cross-attention when not needed).

- Parallel vs sequential branches: an alternative is to put cross-attention and feedforward in parallel and blend their outputs, allowing gradients to flow through both branches more directly. While less common, this pattern can be used to balance compute and information flow.

Normalization choices

- LayerNorm: The standard choice, applied per token across channels. Works well in pre-norm transformers.

- RMSNorm: A lighter-weight normalization that omits centering (mean subtraction). Some models prefer RMSNorm for slightly better scaling properties or empirical speed.

- No normalization on keys/values: Often encoder outputs are not re-normalized on every cross-attention invocation to save compute; instead they are normalized once within the encoder. When cross-attention is called many times, applying LayerNorm on the query side only is efficient and effective.

Biases and scaling interactions

Since LayerNorm changes the scale and distribution of query vectors, it interacts with the softmax logits scale. Pre-norm stabilizes the norms of queries, which makes the $\sqrt{d_h}$ scaling more predictable and can improve the stability of softmax temperature across depths.

Residual scaling and stabilization

- LayerDrop and stochastic depth can be applied at the block level to regularize deep stacks of attention layers. For cross-attention, randomly skipping the cross-attention block during training encourages reliance on both self and cross pathways.

- Residual scaling or alpha weights: some models scale the residual addition by a small factor early in training (e.g., multiply cross-attention output by $\alpha < 1$ before adding) to soften sudden jumps.

Practical recipe

A reliable pattern for a decoder layer with cross-attention is:

1. LayerNorm on decoder activations.
2. Decoder self-attention with causal masks; dropout and add residual.
3. LayerNorm on updated activations.
4. Cross-attention: compute $Q = \text{proj}(\text{LayerNorm}(x))$, $K,V = \text{proj}(\text{encoder\_states})$ (encoder states are often used as-is); apply attention with dropout on weights and outputs; add residual to $x$.
5. LayerNorm and FFN: typical two-layer feedforward with activation (e.g., GELU), dropout, and residual addition.
6. Optionally apply a final LayerNorm.

This pre-norm flow is robust and widely used. For large models and training at scale, monitor gradient norms and consider RMSNorm, gating, and careful dropout schedules to maintain stability.

# Putting it together: design patterns and examples

To close the chapter, it helps to see how these pieces are composed in real architectures.

Encoder–Decoder Transformer (standard): Encoder layers are stacks of self-attention and feedforward blocks. Decoder layers include (in order) self-attention (causal), cross-attention to encoder outputs, and feedforward. Pre-norm is common: each sub-layer takes normalized input. Queries in cross-attention are the decoder token representations. Keys/values are the encoder token representations. Caching of $K$ and $V$ enables fast autoregressive decoding.

Retrieval-augmented generation: The decoder (or an intermediate controller) produces a pooled query or token-level queries that are used to retrieve a small set of documents from an external store (using dot-product search). The retrieved documents become keys/values for cross-attention. Query initialization here is usually pooled: the model uses the current decoder context as a query; retrieval reduces $N_k$ to a manageable size; cross-attention integrates the retrieved content. Residual gating and careful LayerNorm ensure the model can ignore irrelevant retrievals.

Multimodal conditioning: For captioning an image, the decoder produces queries (per token or pooled) and cross-attends to image patch embeddings (keys/values). Position encodings for image patches can be different from text tokens. Often cross-attention layers specialized for multimodal fusion add learned bias terms or separate normalization to align distributions across modalities.

Latent slot models (learned queries): Learned slot queries probe an encoder or memory and produce a fixed set of output slots. This is common in object-centric approaches: a small number of learned queries specialize to extract object-centric representations from an image encoder. In such designs, queries are static parameters that are updated only through gradients.

Scalable memory with hashing: When the source is very large, route queries to hash buckets. Keys/values are sharded; the query is hashed to 1–k buckets and cross-attends only to keys in those buckets. This reduces compute from quadratic to near-linear while keeping retrieval semantics. Careful design ensures robustness to routing errors, often by overlapping hash buckets or using auxiliary reranking.

Conclusion

Cross-attention is the pattern that implements selective read-access to external representations. Understanding the distinct roles of queries, keys, and values, the differences between cross- and self-attention, strategies for initializing queries, the multi-head math and implementation considerations, and the residual and normalization patterns used around cross-attention gives you the tools to design, implement, and debug complex encoder–decoder and retrieval-augmented models. When reading research papers, pay special attention to how queries are formed and normalized, whether cross-attention is pre- or post-normed, and how keys/values are preprocessed or cached—these details often explain significant differences in performance, stability, and computational behavior.

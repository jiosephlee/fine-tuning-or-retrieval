Introduction

Ensemble methods are a fundamental set of techniques in machine learning that improve predictive performance and robustness by combining multiple models rather than relying on a single model. The core idea is simple and powerful: different models make different errors, and by aggregating their outputs we can reduce the overall error. Ensemble approaches appear in many forms — bagging, boosting, and stacking are three canonical families — and are central to many state-of-the-art systems in practice. This chapter develops the intuition and mathematics behind ensemble learning, focuses on bootstrap aggregation (bagging) and random forests, examines how ensembles reduce variance and affect bias, discusses aggregation rules (averaging probabilities vs majority voting), explores the role of diversity and ensemble size, and addresses practical considerations including computational cost and design choices.

This chapter assumes you are familiar with basic supervised learning concepts (loss functions, bias–variance ideas for single models, training and test error) and some probability. Where formulas are used they are given in LaTeX.

# Motivation and types of ensembles: bagging, boosting, stacking

Why would we use an ensemble instead of one carefully trained model? There are several motivations.

First, single learning algorithms can be unstable: small changes in the training set can cause large changes in the learned model. Decision trees are a classic example. When a model is unstable, averaging different models trained on different data often yields a large reduction in variance and improved test error. Second, different model families capture different aspects of the data; combining them can yield a model that is more accurate and robust. Third, ensembles can compensate for model mis-specification: if no single model can capture the true relationship perfectly, combining imperfect models can still approximate it well.

There are three commonly discussed types of ensembles:

- Bagging (bootstrap aggregation). Bagging trains the same learning algorithm multiple times on different versions of the training set, typically created by bootstrap sampling (sampling with replacement). Predictions are aggregated by averaging (for regression or probability estimates) or voting (for classification). Bagging primarily reduces variance. Random forests are an instance of bagging enhanced with additional randomness in feature selection.

- Boosting. Boosting trains models sequentially where each new model focuses on the examples that previous models handled poorly. AdaBoost and gradient boosting are canonical algorithms. Boosting can reduce both bias and variance by constructing a strong predictor from many weak learners; it effectively builds a weighted combination where later learners correct earlier errors.

- Stacking (stacked generalization). Stacking trains different base learners (possibly different algorithms) and then trains a meta-learner on their outputs to produce a final prediction. The meta-learner can learn how to weight or combine base predictions, potentially capturing dependencies among them.

Each family targets different aspects of the error and uses different strategies. Bagging is a parallelizable variance-reduction technique. Boosting is a sequential technique that targets hard examples and can reduce bias; it can overfit if not regularized. Stacking is a flexible approach to combine diverse models and relies on a held-out set or cross-validation to train the meta-learner to avoid information leaks.

# Bootstrap aggregation (bagging): sampling instances and/or features

Bootstrap aggregation, or bagging, formalizes a simple idea: create multiple training sets by resampling the original data, train a separate model on each resample, and aggregate their outputs. Typically the resamples are bootstrap samples: for a dataset of $n$ examples, a bootstrap sample is obtained by drawing $n$ times with replacement. Each bootstrap sample will include roughly $63\%$ of the distinct original examples on average and omit about $37\%$, because the probability an example is not selected in $n$ draws is $(1 - 1/n)^n \approx e^{-1}$.

Bagging reduces the variance of unstable learners. To see this formally in a regression setting, suppose the target is $y$ and we train $m$ predictors $\hat{f}_1(x),\dots,\hat{f}_m(x)$ independently (approximately) on different bootstrap samples. If we build an ensemble by averaging
\[
\hat{f}_{\text{ens}}(x) = \frac{1}{m} \sum_{j=1}^m \hat{f}_j(x),
\]
then the expected squared error at a point $x$ decomposes (ignoring bias for the moment) such that the variance term becomes approximately
\[
\operatorname{Var}(\hat{f}_{\text{ens}}(x)) = \frac{1}{m^2} \sum_{j=1}^m\sum_{k=1}^m \operatorname{Cov}(\hat{f}_j(x),\hat{f}_k(x)).
\]
If the predictors were independent and each had variance $\sigma^2$, the covariance terms vanish when $j\ne k$ and the ensemble variance is $\sigma^2/m$, so the variance reduces by a factor of $m$. In practice predictors are not independent; positive correlations remain and reduce the gain, but averaging still typically decreases variance as long as the base learners are not perfectly correlated.

Bagging can also be applied to features rather than samples: create variations by randomly selecting subsets of features for each base model. This is particularly useful in high-dimensional settings or when features are highly correlated. Sampling features reduces correlation among trees or models and can improve ensemble performance, as used in random forests (discussed below). Hybrid approaches sample both instances and features.

Important practical notes: Bagging is most helpful for unstable base learners (high variance). For stable learners like linear regression with few features, bagging often yields little improvement and can even degrade performance. Also, bootstrap sampling is not the only way to make different training sets; one can use subsampling without replacement or different weights on examples.

# Random forests as an instance of bagging + feature randomness

Random forests, introduced by Leo Breiman, are a highly successful and widely used ensemble technique that augments bagging of decision trees with an additional source of randomness: feature selection at splits. The random forest algorithm trains many decision trees, each on a bootstrap sample of the data, but when growing each tree, instead of considering all features at each split, the algorithm selects a random subset of $k$ features (often $k = \sqrt{p}$ for classification or $k = p/3$ for regression where $p$ is the number of input variables) and chooses the best split among those. Trees are grown to large size (often unpruned) so that each tree is a high-variance, low-bias estimator. Averaging many such trees yields a low-variance ensemble.

Why does this extra randomness help? Standard bagging reduces variance by averaging; however, if base learners are strongly correlated (for example, if certain features are so predictive that most trees use them at the top split), the covariance terms in the ensemble variance remain large and the variance reduction is limited. Randomly selecting a subset of features at each split breaks this correlation: different trees are more likely to use different features early on, producing a more diverse ensemble with lower inter-tree correlation and hence better variance reduction.

Random forests also provide several practical benefits. They require little hyperparameter tuning, are robust to outliers and scaling, implicitly handle interactions and nonlinearities, and give useful out-of-bag (OOB) estimates: because each tree is trained on a bootstrap sample, about $37\%$ of the original examples are not used to train that tree; averaging predictions on those OOB examples across trees gives a nearly unbiased estimate of generalization error without a separate validation set. Random forests can produce measures of variable importance by assessing the impact on performance from permuting a feature or observing splits using that feature.

Mathematically, denote the trees as $\hat{t}_1(x),\dots,\hat{t}_m(x)$. The random selection of features makes the covariance $\operatorname{Cov}(\hat{t}_j(x),\hat{t}_k(x))$ smaller, and the ensemble variance behaves like
\[
\operatorname{Var}(\hat{t}_{\text{ens}}(x)) \approx \rho \sigma^2 + \frac{1-\rho}{m}\sigma^2,
\]
where $\sigma^2$ is the variance of an individual tree and $\rho$ is the average pairwise correlation between trees. Here the first term reflects the irreducible part due to correlation and does not shrink with $m$, while the second term shrinks as $1/m$. Reducing $\rho$ is therefore crucial.

# Averaging probabilities vs. voting

When combining classifiers, two canonical aggregation rules are majority voting and probability averaging (or averaging predicted scores). The choice matters.

For classification where base models produce class labels only, majority voting is natural: each model votes for one class and the ensemble predicts the class with the most votes. If classifiers produce calibrated class probabilities $p_j(y\mid x)$, we can average probabilities:
\[
\hat{p}_{\text{ens}}(y\mid x) = \frac{1}{m} \sum_{j=1}^m p_j(y\mid x),
\]
and then predict the class with largest averaged probability (maximum a posteriori).

Averaging probabilities has several advantages. If probabilities are well-calibrated, averaging is optimal under log-loss and produces smoother, more informative outputs that capture uncertainty. Averaging also allows us to combine classifiers with different sets of classes or different confidence levels. Voting on the other hand treats each base classifier equally regardless of confidence; a very confident classifier is treated the same as an uncertain one. In some settings, e.g., when base classifiers are poorly calibrated or produce only labels, voting can work as well or better.

There is also a theoretical perspective: if each classifier's class probabilities are unbiased estimates of the true conditional probability, then averaging reduces variance of the probability estimate and improves calibration. If instead each classifier gives only a hard label, majority voting behaves like taking the median of binary decisions and is robust to a minority of inaccurate classifiers. For binary classification, under mild independence assumptions and classifiers having accuracy above $50\%$, majority voting yields an exponential improvement in ensemble accuracy as the ensemble size grows (this is closely related to the Condorcet Jury Theorem, discussed below).

In practice, when probabilities are available and reasonably calibrated, average the probabilities. If only labels are available, majority voting is the option. When combining heterogeneous models, training a meta-learner (stacking) to weight models can outperform naive voting or averaging.

# Diversity, bias–variance trade-off, and ensemble size considerations

Diversity among base learners is crucial for ensemble effectiveness. The bias–variance trade-off extends to ensembles. For a single estimator, total expected squared error can be decomposed as
\[
\mathbb{E}\big[(\hat{f}(x)-f(x))^2\big] = \operatorname{Bias}(\hat{f}(x))^2 + \operatorname{Var}(\hat{f}(x)) + \sigma_\varepsilon^2,
\]
where $\sigma_\varepsilon^2$ is the irreducible noise. For an averaged ensemble $\hat{f}_{\text{ens}}$, the bias is typically similar to the base learners' bias (averaging does not reduce bias much unless learners make errors in different directions that average out) but variance is reduced. Thus ensembles are particularly useful when the dominant error component is variance.

The amount of variance reduction depends on both the number of models $m$ and their average pairwise correlation $\rho$. For regression with identical variances $\sigma^2$ and average correlation $\rho$,
\[
\operatorname{Var}(\hat{f}_{\text{ens}}) = \rho\sigma^2 + \frac{1-\rho}{m}\sigma^2.
\]
As $m\to\infty$, the variance approaches $\rho\sigma^2$, which is strictly less than $\sigma^2$ only if $\rho<1$. Thus increasing $m$ yields diminishing returns: the reduction beyond the correlated portion shrinks with more models. If $\rho$ is small, large $m$ can substantially reduce variance; if $\rho$ is large, increasing $m$ yields limited gains.

Bias considerations are equally important. If base learners are highly biased (e.g., shallow decision trees or linear models when the truth is highly nonlinear), averaging many biased models may not produce a low-bias ensemble. Boosting can sometimes reduce bias by fitting residuals sequentially, but bagging generally keeps bias similar while reducing variance.

Ensemble size selection balances computational cost and statistical gain. Often a few hundred trees are sufficient for random forests; performance tends to plateau well before thousands of trees. For bagging with expensive base learners (e.g., deep neural networks), ensembles of a small number (say 5–20) of diverse models can work well. Practical monitoring of validation error vs number of models is the pragmatic way to choose $m$.

The source of diversity matters: resampling data, varying model architectures or hyperparameters, injecting randomization in feature subsets, or using different learning algorithms all produce alternative error patterns. Effective ensembles often combine multiple sources of diversity.

# Self-consistency and majority consensus ideas

Self-consistency and consensus ideas concern how ensemble predictions converge and under what conditions majority or averaged decisions approach the “correct” decision.

The Condorcet Jury Theorem is a classical result that sheds light on majority voting. Suppose there are $m$ independent voters (classifiers), each with probability $p>1/2$ of choosing the correct binary decision, independently of others. Then the probability that majority voting yields the correct class tends to 1 as $m\to\infty$. More precisely, by the law of large numbers and Hoeffding/Chernoff bounds, the probability of a majority error decreases exponentially in $m$. This result shows that independent weak learners with accuracy above chance can be combined to form a highly accurate ensemble.

Real classifiers are neither independent nor homogeneous, so the theorem’s assumptions are strong. Correlations and heterogeneous accuracies modify the conclusions: if many classifiers are correlated or several are worse than chance, majority voting may fail. Nevertheless, the general principle stands: if most base classifiers are slightly better than random and sufficiently independent, consensus improves accuracy.

Self-consistency can also be considered in probabilistic terms. If each base learner provides an unbiased estimate of the conditional probability $p(y\mid x)$ and errors are independent, averaging yields a consistent estimator of $p(y\mid x)$ that converges to the truth as $m\to\infty$. In practice, correlation and bias mean asymptotic consistency is not achieved by simply increasing $m$, but designing ensembles to reduce bias and correlation promotes self-consistency.

Majority consensus also inspires voting-based robust systems: ensembles can be used to detect uncertain cases (low consensus) or adversarial examples (diverse predictions) since high disagreement often signals lack of confidence or distribution shift.

# Practical ensemble design and computational costs

Designing ensembles in practice requires choices about base learner type, sources of diversity, aggregation rule, and computational trade-offs.

Choice of base learner. For bagging and random forests, decision trees are common because they are fast to train, high-variance (so they benefit from averaging), and can be trained on bootstrap subsets with feature randomness. For other ensembles, base learners can be neural networks, SVMs, or heterogeneous algorithms. Use unstable, high-variance learners to maximize bagging gains; for reducing bias use boosting or hybrid approaches.

Diversity strategies. To create diversity, use bootstrap sampling, feature subsets, random initializations (for neural networks), different architectures or hyperparameters, or train on different data representations (different preprocessing). Combining different model families often yields gains that homogeneous ensembles cannot.

Aggregation and meta-learning. Averaging probabilities is preferred when available. For hard labels, majority voting is simple. Stacking uses a meta-learner trained on outputs of base learners to learn optimal combinations; it is powerful but requires careful cross-validation to avoid overfitting: the meta-learner must be trained on predictions for examples not used to train the corresponding base models.

Computational cost. Ensembles increase training and inference cost linearly in the number of base learners unless parallelism is used. Training cost can often be parallelized across cores or machines since bagging and random forests train base models independently. Memory and storage increase with ensemble size. Inference latency can be an issue in latency-sensitive applications; techniques to mitigate this include model distillation (training a single smaller model to mimic the ensemble), pruning the ensemble (select a subset of most useful members), or using approximate aggregation.

Hyperparameters. For random forests the important hyperparameters include number of trees $m$, number of features considered at each split $k$, and maximum tree depth. Default choices often work well, but tuning $k$ and tree depth can help. For bagging non-tree learners, control overfitting by adjusting base learner complexity and employing regularization.

Diagnostics and validation. Use out-of-bag error estimates for bagging/random forests to monitor generalization without a separate holdout. Examine ensemble diversity by measuring pairwise disagreement or correlation among predictions. Check calibration of averaged probabilities, particularly when combining models trained with different objectives.

When ensembles help vs hurt. Ensembles help when base learners are reasonably accurate but have high variance or make uncorrelated errors. They help less when base learners are highly biased and make similar errors, or when compute budget is too small. Ensembles may hurt interpretability: combined models are harder to explain than a single model. They can also hurt calibration if component probabilities are miscalibrated in different ways, though probability averaging usually improves variance and sometimes calibration.

Summary

Ensemble methods are a key tool in the machine learning toolbox. Bagging and random forests are powerful, generally robust techniques to reduce variance by averaging multiple randomized models. Boosting and stacking provide complementary strategies to reduce bias and learn how to combine models. The effectiveness of an ensemble depends on the accuracy and diversity of its members and on careful design choices around aggregation, model selection, and computational constraints. Understanding the bias–variance trade-offs, the role of inter-model correlation, and practical limits of ensemble size will help you design ensembles that improve predictive performance while remaining computationally feasible.

Introduction

Feature engineering is the process of creating, transforming, and selecting input variables (features) from raw data to improve the performance, robustness, and interpretability of machine learning models. In tabular learning—the modeling of structured data arranged in rows and columns—feature engineering plays an outsized role. Unlike domains such as images or audio where deep architectures can learn hierarchical representations directly from raw inputs, tabular data often benefits substantially from carefully crafted features. Good features can reduce the amount of data and model complexity required to achieve strong performance, help models extrapolate, and make the learned predictors easier to understand and trust.

This chapter presents a systematic view of feature engineering for tabular data. We begin with motivations that explain why feature engineering matters, then move through standard transforms and more structured constructions such as binning and rule-based features. Next we introduce automated construction techniques that aim to scale up manual ideas. We then discuss strategies for selecting and assessing features, including univariate and multivariate criteria, as well as methods that determine feature usefulness during model training. Throughout, emphasis is placed on intuition, practical trade-offs, and mathematical clarity so you can apply the ideas in practice and read research that uses or evaluates engineered features.

# Motivation for feature engineering

At its core, feature engineering exists because the input representation strongly influences what a model can learn. Consider a simple linear model that predicts a scalar target $y$ from features $x_1, x_2, \ldots, x_d$. The model represents $y$ as a linear combination
$y \approx \beta_0 + \sum_{j=1}^d \beta_j x_j$.
If the true relationship between the inputs and target is nonlinear, a pure linear model will systematically misfit unless the features already encode the necessary nonlinearities. Feature engineering can bridge this gap by creating new features that make the relationship more linear or otherwise easier for the chosen model class to capture.

There are several concrete motivations:

- Improving expressivity of simple models. For example, polynomial and interaction features allow linear models to represent nonlinear functions. If building a deployable system that favors interpretability, latency, or regulatory constraints, augmenting a simple model with constructed features is often preferable to switching to a large complex model.

- Improving sample efficiency. Models that see features tailored to the task typically need fewer data points to reach a given level of performance. A model that can directly use a well-constructed predictor need not learn the same transformation from scratch.

- Handling domain heterogeneity and missingness. Feature engineering can normalize heterogeneous scales, encode missingness patterns, or summarize categorical levels with few examples in ways that stabilize learning.

- Enabling extrapolation and invariances. Carefully designed features can instill domain knowledge such as monotonicity, invariance to certain transformations, or piecewise linear structure that help with out-of-sample generalization.

- Improving interpretability and debugging. Engineered features frequently correspond to human-understandable concepts (e.g., age groups, income-to-debt ratio), making model outputs easier to justify and debug.

However, feature engineering also has costs: it requires human effort, can introduce bias if domain assumptions are incorrect, and may leak target information when done improperly. Balancing manual creativity and automated search is therefore important.

# Basic transforms: polynomial features, interactions, log transforms

Basic mathematical transforms are the first repertoire for transforming raw numeric variables into features that models can more easily use. Three widely used families are polynomial features, interaction features, and monotonic transforms such as logarithms.

Polynomial features extend linear models by including powers of an original variable. For a single feature $x$, a polynomial basis of degree $p$ produces features $x, x^2, x^3, \ldots, x^p$. For multivariate inputs, one can include powers for each coordinate separately or include cross terms as well (see interactions below). Algebraically, adding polynomial terms lets a linear model represent polynomials of $x$, which can approximate a wide range of smooth functions locally. From an approximation perspective, polynomials are a simple basis with desirable smoothness; from a practical perspective, the main trade-offs are multicollinearity and scale: raw higher-order terms can have wide numeric ranges, so standard practice is to center and scale inputs before forming powers or use orthogonal polynomials (e.g., Legendre or Chebyshev bases) to reduce numerical instability.

Interaction features encode multiplicative or combined effects between variables. If the effect of $x_1$ on the target depends on $x_2$, adding the product $x_1 \cdot x_2$ provides a first-order correction. More generally, an interaction of order $k$ is a product of $k$ distinct features; including all pairwise interactions creates a model capable of capturing pairwise conditional effects. Interactions can also be constructed between transformed features, such as $x_1 \cdot \log(x_2)$ or $(x_1 - \mu_1) \cdot (x_2 - \mu_2)$, where centering helps with interpretability of main effect coefficients. While interaction features increase model expressivity, they also increase dimensionality combinatorially. Practical systems therefore limit the order of interactions or select a subset guided by domain knowledge or statistical criteria.

Log transforms and other monotonic transforms (square root, reciprocal, Box–Cox family) are useful when the relationship between a variable and the target is multiplicative, heavy-tailed, or heteroskedastic. Logarithms are particularly common: when a target responds proportionally to multiplicative changes in $x$, modeling $\log x$ often linearizes the relation. For example, income, population sizes, and counts commonly exhibit heavy tails and multiplicative effects that are compressed by $\log$. The log transform also stabilizes variance: if $y$ has variance proportional to the mean, modeling $\log y$ can make residuals more homoscedastic. Care must be taken for zeros and negative values; standard remedies include adding a small constant ($\log(x + \epsilon)$) or modeling signed variants (e.g., $\operatorname{sign}(x)\log(|x| + \epsilon)$).

Overall, basic transforms are simple but powerful: they are computationally cheap, interpretable, and often enough to unlock strong performance for many tabular problems. They are especially effective when combined with appropriate scaling, centering, and consideration of numerical stability.

# Binning and categorical grouping

Binning (also called discretization) converts continuous variables into categorical bins—intervals that partition the real line—thereby enabling piecewise-constant modeling and making models less sensitive to small measurement noise. Categorical grouping aggregates raw categories into coarser levels to mitigate sparsity and variance in categorical features.

For continuous variables, common binning strategies include equal-width binning, equal-frequency (quantile) binning, and supervised binning that uses the target to define cut points. Equal-width binning divides the range into intervals of equal size; it is simple but can create empty bins for skewed distributions. Equal-frequency binning places roughly the same number of observations in each bin, which stabilizes the estimates per bin but may place widely varying ranges into the same bin where the distribution is sparse. Supervised methods, such as decision-tree-based binning or optimal binning algorithms, choose cut points to maximize a purity measure (e.g., information gain, reduction in squared error) and are particularly useful when the relationship between the feature and target is highly nonlinear and the model class cannot represent that nonlinearity smoothly.

The principal intuition for binning is that it turns a smooth but complex effect into a piecewise-constant effect that simple models can represent. For example, a linear model cannot represent a plateau effect where increasing a variable beyond a threshold yields no additional benefit; discretizing into a high/low indicator captures that behavior. Binning also makes interactions between continuous and categorical variables easier to interpret: the model can learn different slopes for different bins. A downside is loss of information: overly coarse bins can hide meaningful variation and reduce predictive power. When using tree-based models, explicit binning is often unnecessary because the trees inherently partition the space; but binning can still speed training and reduce model size by limiting unique continuous values.

Categorical grouping addresses the high-cardinality categorical variables common in tabular data (e.g., zip codes, product IDs). Many categories may appear infrequently, making their effect estimates noisy. A common strategy is to group rare categories into an "other" bucket, reducing variance at the cost of some bias. More sophisticated approaches include target-guided grouping, where categories are merged based on similarity of their conditional target statistics (e.g., mean target), and hierarchical clustering of categories using distance measures derived from feature co-occurrence or target-response profiles. The goal is to reduce dimensionality while preserving predictive signal.

Another important technique for categorical variables is frequency or count encoding: replacing each category by its frequency (proportion) or count in the training data. This gives the model information about how common a category is without exploding dimensionality. Mean target encoding replaces each category with the average target value for that category; it can be very powerful but also prone to target leakage and overfitting, so it demands careful regularization (e.g., smoothing toward the global mean, cross-validation folds, or leave-one-out adjustments).

Binning and grouping are practical tools for addressing nonlinearity, heterogeneity, and sparsity, but they must be applied thoughtfully with attention to bin selection, handling of new categories at test time, and potential leakage from target-based grouping.

# Rule-based feature creation (if–then conditions, thresholds)

Rule-based feature creation refers to constructing features that encode domain knowledge as logical conditions, thresholds, or combinations thereof. These features are typically boolean (0/1) or ordinal and capture interpretable rules such as "age > 65", "income / household_size > 2", or "days_since_last_purchase < 30 and num_past_purchases > 5". Such features can be designed by experts or derived from exploratory data analysis.

The intuition is that many decision-making processes in real systems are thresholded or piecewise: risk might spike when a measurement crosses a limit, or a promotional effect may appear only for customers in a certain segment. If the true decision boundary is expressible through simple rules, adding corresponding features allows linear or simple nonlinear models to approximate that boundary cleanly. For example, a classifier with features encoding significant rules can use those booleans to combine simple logical conditions without learning complex nonlinear functions.

Constructing rule-based features typically follows an iterative workflow. First, visualize marginal and joint distributions to identify candidate thresholds: cumulative distribution plots, conditional mean plots, or partial dependence plots can reveal where behavior changes. Second, operationalize promising thresholds as boolean indicators or ordinal buckets. Third, validate the features using cross-validation to ensure they generalize. Fourth, optionally combine basic rules into composite rules using logical operators or interaction features.

A crucial concern is overfitting: creating many ad hoc rules based on the training data can capture idiosyncratic noise. Remedies include limiting the number of handcrafted rules, validating on held-out data or using cross-validation, and applying regularization in the model to temper large numbers of sparse rule indicators. Another issue is correlation among rules: many thresholds may capture the same phenomenon, leading to redundancy. Feature selection (discussed later) and hierarchical rules (grouping similar rules) can reduce redundancy.

Rule induction algorithms automate some of this process by searching for rules that improve predictive performance, often using greedy splits as in decision trees or more global search as in association-rule mining. These automatically discovered rules can be converted into features. Since rules are interpretable, they also support explainability: one can present a model's decision as a combination of satisfied rules.

# Automatic feature construction: feature crosses, feature hashing

Manual feature engineering is powerful but time-consuming. Automatic feature construction techniques aim to generate useful features programmatically, enabling scalable exploration of large search spaces. Two widely used automated methods for tabular data are feature crosses and feature hashing.

Feature crosses create new categorical levels by combining values of two or more categorical features. If $C_1$ and $C_2$ are categorical features with levels $\{a,b,\ldots\}$ and $\{x,y,\ldots\}$ respectively, their cross feature takes levels like $(a,x), (a,y), (b,x)$, and so on. Crosses can capture interactions where the joint configuration of two categories matters but neither alone is sufficiently informative. For example, a product-category crossed with a region might identify product-region pairs that have distinct demand patterns.

The challenge with crosses is explosive cardinality: if $C_1$ has $n_1$ levels and $C_2$ has $n_2$, the cross has up to $n_1 n_2$ levels. This leads to sparsity and memory concerns. Practical systems limit crosses to pairs or a small set of strategically chosen combinations, often guided by mutual information, statistical tests of dependence with the target, or frequency thresholds that exclude rare combinations.

Feature hashing (the hashing trick) addresses high-cardinality categorical features and the explosion from crosses by mapping arbitrary categorical values to a fixed-size numerical vector via a hash function. Concretely, each category value is hashed to an integer in $\{1,\ldots, m\}$ and increments the corresponding slot (possibly with a sign determined by a second hash) to produce an $m$-dimensional sparse vector. When applying hashing to crosses, one hashes the concatenated representation of the component categories. Feature hashing has several properties that make it attractive: fixed and controllable memory footprint, fast computation, and no need for an explicit dictionary of category levels. It also implicitly groups collisions—distinct categories hashing to the same slot—trading off some accuracy for scalability.

From a theoretical perspective, feature hashing approximately preserves inner products in expectation if the hash function behaves like a random projection. Specifically, if $h$ maps categorical values to $\{1,\ldots,m\}$ and if sign hashing is used to assign signs $s(\cdot) \in \{\pm 1\}$, then the hashed representation is an unbiased estimator of the full one-hot representation's inner products, with variance decreasing as $m$ increases. In practice this means that with a sufficiently large hash dimension $m$, hashed features can be almost as effective as full categorical encodings.

Automatic construction methods also include polynomial feature generators, combinatorial interaction expanders, and neural-network-based feature synthesizers. Modern automated machine learning (AutoML) frameworks often include systematic generation of pairwise interactions, target-encoded aggregates, and unconstrained crossing subject to sparsity and complexity budgets. The trade-off with automatic approaches is that they can produce many noisy or redundant features, necessitating robust selection and regularization downstream.

# Feature selection and importance: filter, wrapper, embedded methods

After generating a set of candidate features—whether manually or automatically—the next step is to select a subset that yields good predictive performance, computational efficiency, and interpretability. Feature selection methods fall into three broad categories: filter, wrapper, and embedded methods. Each has distinct strengths and trade-offs.

Filter methods score each feature independently (or with lightweight pairwise adjustments) using a statistical criterion computed from the data without invoking a full predictive model. Common filter criteria include Pearson correlation with a continuous target, ANOVA F-tests comparing group means, mutual information estimates, and univariate AUROC for binary classification. Filters are computationally cheap and model-agnostic, making them useful as a first pass to remove irrelevant features. However, they ignore interactions: a feature with weak marginal correlation might become highly predictive in combination with others, and filters can therefore discard features that are jointly useful.

Wrapper methods evaluate subsets of features by training and validating a predictive model on each subset. Examples include forward selection, backward elimination, and recursive feature elimination (RFE). These methods account for multivariate interactions and model behavior, often leading to superior subsets for a particular model class. The downside is computational cost: evaluating many subsets requires repeated model training, which can be prohibitive for large datasets or expensive models. Heuristic search strategies (greedy or randomized) and early stopping can mitigate the cost.

Embedded methods perform feature selection as part of the model training process. Regularization techniques fall into this category. For example, the LASSO (least absolute shrinkage and selection operator) adds an $L_1$ penalty to linear regression, promoting sparse coefficient vectors by driving many weights to zero; this yields automatic feature selection that is tuned by the regularization parameter. Tree-based models (random forests, gradient-boosted trees) provide implicit selection via split choices: features never used in splits effectively have zero importance. Elastic net regularization mixes $L_1$ and $L_2$ penalties to balance sparsity and stability. Embedded methods often offer a good compromise between effectiveness and computational cost, and their selection is tailored to the inductive biases of the chosen model.

Estimating feature importance is related but distinct from selection. Importance scores quantify how much a trained model relies on a feature. For linear models, importance can be summarized by absolute coefficient magnitude adjusted by feature scale. For tree ensembles, standard importance measures include mean decrease in impurity and permutation importance. Permutation importance assesses the drop in model performance when a feature's values are randomly permuted, breaking its relationship with the target; this method is model-agnostic and captures the feature's contribution in the context of the full model, but it can be expensive and affected by correlated features. Partial dependence plots and accumulated local effects visualize the average marginal effect of a feature while accounting for other features.

When selecting features, it is crucial to account for multicollinearity and redundancy. Highly correlated features may each be individually important but together offer limited incremental benefit; selection procedures should prefer compact sets to avoid overfitting. Cross-validation and nested model-selection procedures help estimate generalization performance and avoid optimistic selection bias. For very high-dimensional feature sets (e.g., automatic crosses), combining a cheap filter step to prune obviously irrelevant features with an embedded method such as regularized modeling often works well in practice.

# Assessing feature usefulness: univariate metrics, mutual information, AUROC per feature

Assessing the usefulness of individual features guides engineers toward promising transformations and reduces the search space for modeling. The most basic methods are univariate metrics that quantify the strength of association between a feature and the target without considering other features. While limited, these metrics are fast and informative.

For continuous targets, the Pearson correlation coefficient measures linear association between a feature $x$ and target $y$:
$r = \frac{\operatorname{cov}(x,y)}{\sigma_x \sigma_y}$.
Its square $r^2$ is the proportion of variance in $y$ explained by a linear regression on $x$ alone. Pearson correlation is most informative when the relationship is approximately linear; it can miss monotonic but nonlinear dependencies.

Spearman's rank correlation assesses monotonic relationships by computing Pearson correlation on the rank-transformed values. It is robust to monotonic nonlinearities and outliers and often more informative when relationships are not strictly linear.

Mutual information (MI) is a general information-theoretic measure that quantifies the reduction in uncertainty about the target given the feature. For discrete variables $X$ and $Y$, mutual information is
$I(X;Y) = \sum_{x,y} p(x,y) \log \frac{p(x,y)}{p(x)p(y)}$.
For continuous variables, differential mutual information can be defined but is harder to estimate reliably. MI captures arbitrary dependencies, not just linear or monotonic ones, making it powerful as a univariate measure. However, estimating MI from finite samples requires careful density or histogram estimation; naive estimators are biased and sensitive to binning choices. Practical MI estimators include k-nearest-neighbor methods and penalized histogram or kernel density estimators. MI is especially useful when comparing categorical features or transformed numeric features.

For binary classification tasks, per-feature AUROC (area under the receiver operating characteristic curve) provides a robust, scale-free metric of how well a single feature separates the two classes. The AUROC for a feature $x$ is equivalent to the probability that a randomly chosen positive instance has a higher $x$ value than a randomly chosen negative instance. AUROC ranges from 0.5 (no discrimination) to 1.0 (perfect separation). Unlike simple accuracy at a threshold, AUROC summarizes discrimination across all thresholds and is invariant to monotonic transformations, which makes it suitable for evaluating continuous predictors and target encodings. When features are categorical, AUROC can be computed by mapping categories to scores (e.g., mean target per category) or by using rank-based approaches.

Other univariate metrics include two-sample tests (t-tests, Mann–Whitney U) for differences in means or medians across classes, the F-statistic for ANOVA when features vary across multiple target groups, and chi-squared tests for contingency tables with categorical features. While these tests give p-values indicating whether an effect is statistically significant, p-values are sensitive to sample size and do not directly measure predictive strength.

A key limitation of univariate metrics is that they do not account for redundancy and interactions. A feature may have low univariate score yet be indispensable in combination with another feature. Therefore, univariate assessment is best used as an initial diagnostic and dimensionality reduction step, followed by multivariate selection that evaluates joint contributions to predictive performance.

Practical workflow for assessment: start with exploratory plots (histograms, boxplots, violin plots, scatterplots with smoothing) and compute basic univariate scores (correlation, AUROC, MI). Use these to prioritize features for more expensive multivariate tests and ensure candidate transformations have a plausible relationship with the target. When using target-based encodings or supervised binning, use cross-validation or out-of-fold estimation to avoid leaking target information into the features.

# Putting it together: practical considerations and workflows

Effective feature engineering for tabular learning is iterative and blends domain intuition, automatic tools, and careful validation. A typical practical workflow starts by understanding the data distributions and relationships via visualization and univariate metrics, then applying basic transforms to standardize scales and reduce skew (e.g., centering, scaling, log transforms). Next, create targeted engineered features grounded in domain knowledge (ratios, thresholds, counts), and consider binning or categorical grouping when appropriate. Parallel to manual work, apply automated feature construction (selected crosses, hashing) but impose limits to control explosion in dimensionality.

After generating a candidate feature set, perform an initial filter to remove obviously irrelevant or constant features. Then use embedded selection (regularized models, tree-based importance) or wrapper methods when computationally feasible, always evaluating selection within cross-validation to estimate generalization. Monitor model complexity, computational cost, and interpretability; prune redundant features and prefer compact feature sets that achieve similar performance.

Be cautious with target-derived features—such as mean target encoding or supervised bins—to prevent leakage. Use out-of-fold aggregation or nested cross-validation to ensure that the estimated encodings are not computed using the same data used to train the model that will use them. Also consider stability across time: features constructed from historical aggregates must be computed using only data available at prediction time.

Finally, measure uplift in predictive performance attributable to specific engineered features using ablation studies (retrain the model without that feature) and permutation importance. Report not only performance metrics but also sensitivity analyses to understand how features behave on different cohorts or in the presence of distribution shift.

Conclusion

Feature engineering remains a cornerstone of practical tabular learning. Thoughtful manual creation of polynomial, interaction, and log-transformed features, together with binning, categorical grouping, and interpretable rule-based indicators, can substantially boost model performance while retaining interpretability. Automated techniques such as feature crosses and feature hashing scale these ideas to high-cardinality and combinatorial spaces, though they require careful downstream selection. Filter, wrapper, and embedded selection methods provide complementary tools to identify compact, robust feature sets, and univariate metrics like correlation, mutual information, and per-feature AUROC help prioritize candidate features efficiently. By combining domain knowledge, automated search, and rigorous validation, you can construct features that make models more accurate, reliable, and explainable.

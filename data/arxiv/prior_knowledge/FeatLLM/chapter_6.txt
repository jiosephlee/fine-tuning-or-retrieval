Introduction

Few-shot and low-resource learning study how to train models when only a small number of labeled examples are available for the target task. This setting is common in practice: clinical studies with few patients, industrial systems with expensive labeling, new product categories with limited purchase history, and scientific experiments where data collection is costly. The goal is to achieve good generalization despite scarce supervision by reusing prior knowledge, exploiting additional signals, or designing algorithms that adapt quickly.

This chapter surveys the main ideas and practical techniques used for few-shot and low-resource learning, with a particular emphasis on tabular data (a setting that includes mixed continuous/categorical features, missing values, and complex feature dependencies). We begin by defining common evaluation protocols for few-shot tasks. We then discuss transfer learning and pretraining for tabular data, the main meta-learning paradigms, and semi/self-supervised strategies tailored to tables. Next we examine synthetic data generation and pretraining using simulated distributions, and the specific challenges of performing data augmentation on tabular data. We close with best practices for evaluating methods and choosing baselines in few-shot experiments.

# Definition of few-shot learning and k‑shot evaluation protocols

Few-shot learning refers to the family of problems where a learning algorithm must adapt to a new task using only a very small number of labeled examples. Though the phrase can be used informally, the community has converged on a formal evaluation style based on episodic tasks, often called N-way, k-shot evaluation. In this protocol, each evaluation episode consists of a small labeled support set and an unlabeled query set drawn from a held-out task. The learner sees the support set and must make predictions on the query set; performance is averaged over many episodes.

A standard episodic setup is described as follows. During meta-testing, each episode samples a set of classes (or target labels) of size $N$ and then samples $k$ labeled examples per class for the support set and several examples per class for the query set. This is called an "N-way, $k$-shot" episode. For example, in a 5-way, $1$-shot classification episode, the support set contains 5 labeled examples (one per class) and the model must label query examples belonging to these same 5 classes. The typical metric is accuracy averaged over a large number of such episodes. Formally, for an episode with support set $S = \{(x_i, y_i)\}_{i=1}^{N k}$ and query set $Q = \{x_j\}$, the model produces predicted labels $\hat{y}_j = f(x_j; S)$ and we compute the accuracy by comparing $\hat{y}_j$ to ground-truth $y_j$.

When tasks are not naturally multiclass classification, analogous protocols exist: in regression, the episode samples a small labeled training set from a function and evaluates mean squared error on held-out inputs; in structured prediction one can define appropriate loss functions. The general theme is the same: measure how well an algorithm adapts to new tasks with few labels.

Evaluation is often split into meta-training, meta-validation, and meta-testing phases. In meta-training, the method sees many episodes drawn from tasks that are different but related to those in meta-test. The learner uses meta-training to acquire inductive biases or initializations that make fast adaptation possible. Importantly, the classes (or tasks) in meta-test must be disjoint from those in meta-train to measure true generalization to new tasks.

Two alternative but related evaluation styles are transfer learning (pretrain on a large dataset, fine-tune on a small labeled target set) and cross-validation-like low-resource scenarios (train a full model only on the few available target labels). These evaluate different practical workflows: episodic meta-learning focuses on rapid task adaptation using few-shot episodes, while transfer learning studies whether large-scale pretraining provides representations that can be fine-tuned with few labels.

Key practical considerations when using k-shot protocols include (1) balancing the classes in each episode to avoid trivial baselines dominating, (2) sampling many episodes to reduce variance, and (3) reporting variance across random seeds and splits, since few-shot results can be noisy. We discuss evaluation practices further in the final section.

# Transfer learning and pretraining for tabular data

Transfer learning—pretraining a model on large amounts of data and then fine-tuning it on a downstream target—has been enormously successful in vision and language. For tabular data, transfer learning is more challenging but increasingly feasible. Tabular datasets often contain heterogeneous feature types (continuous, ordinal, categorical), different column semantics, varying numbers of columns, and domain-specific preprocessing; these issues make a single large pretraining corpus less straightforward. Nonetheless, several strategies allow reuse of prior knowledge.

A first approach is feature-based transfer: train a model to produce embeddings for individual features or rows on large tabular corpora, then use those embeddings as inputs to lightweight downstream models. For example, one can train a neural network (or a tree ensemble with learned leaf embeddings) to predict many different targets across a broad collection of tables. The learned row-level encoders map raw feature vectors to representations capturing common statistical structure, which can then be fine-tuned or used as fixed features for a small downstream labeled set.

Another approach is column-wise or schema-aware pretraining. Because tabular columns often have semantic types (age, income, product id), it is useful to learn column encoders that generalize across tables. Methods in this vein learn embeddings for feature names and apply column-wise transformations that are permutation-aware (the model should not depend on column order). Pretraining tasks can include reconstructing masked entries, predicting column types, or multi-task targets that encourage capturing conditional dependencies among columns. These learned encoders allow transfer between tables with different schemas by aligning features via column metadata.

A third strategy is to pretrain using synthetic tasks that resemble downstream targets. For example, one can pretrain a model to predict held-out columns given the rest (column imputation or denoising), to detect corrupted entries, or to predict aggregated statistics. These self-supervised tasks do not require labels and can scale to large unlabeled tabular corpora. After pretraining, the model is fine-tuned on the labeled target with either full fine-tuning of parameters or by training a small classifier on top of frozen representations.

Fine-tuning recipes are important. With only a small labeled target set you cannot afford to overfit by updating all parameters aggressively. Common options include: (1) train only a new head on top of frozen pretrained layers, (2) fine-tune a subset of layers with small learning rates, and (3) use regularization such as weight decay, dropout, or early stopping based on cross-validation. Calibration of predictions often benefits from post-hoc methods like temperature scaling, especially when pretraining and target domains differ.

For tabular data, tree-based models (e.g., gradient-boosted decision trees) remain highly competitive in many low-data regimes. Hybrid approaches combine tree models with neural pretraining: for example, train a neural encoder to produce features that are then fed into a tree ensemble. Alternatively, derive embedding vectors for categorical variables via supervised pretraining and use these embeddings as features to GBDTs. The right choice often depends on the target problem: if nonlinearity and interactions are crucial, neural pretraining may pay off; if the dataset is small and feature engineering is effective, traditional methods can prevail.

Finally, an often overlooked aspect is feature normalization and handling of missing values. Pretraining pipelines must be consistent with downstream processing: if pretraining used a specific imputation or encoding, downstream fine-tuning must respect that pipeline to avoid distribution shift between pretrain and fine-tune.

# Meta-learning paradigms (model-agnostic, metric-based approaches)

Meta-learning (learning to learn) aims to acquire inductive biases from many related tasks so a model can adapt quickly to new tasks with few examples. Two broad paradigms dominate: optimization-based (model-agnostic) meta-learning and metric-based (or matching) approaches. Both are applicable beyond image classification; they can be adapted to tabular settings by choosing appropriate model architectures and task distributions.

Optimization-based meta-learning learns an initialization or optimization rule that yields fast adaptation. A canonical example is Model-Agnostic Meta-Learning (MAML). MAML trains model parameters $\theta$ so that one or a few gradient steps on a small task-specific support set produce parameters that perform well on that task's query set. Concretely, for a sampled task $T$, MAML performs an inner update
\[
\theta_T' = \theta - \alpha \nabla_{\theta} \mathcal{L}_T^{\text{train}}(\theta),
\]
then optimizes the meta-objective that measures loss on the query set:
\[
\min_{\theta} \sum_{T} \mathcal{L}_T^{\text{test}}(\theta_T').
\]
The meta-optimization uses gradients through the inner update, which encourages $\theta$ to be a good starting point for rapid adaptation. Extensions and practical variants (first-order approximations, Reptile, learned optimizers) remove or approximate higher-order gradients to improve efficiency.

The strength of optimization-based methods is their generality: they can be applied to any differentiable model, including neural networks designed for tabular inputs. For tabular tasks, the inner update may fine-tune feature encoders and a classification head. However, with tabular data one must be careful with hyperparameters like inner learning rate and number of adaptation steps, since overfitting small support sets is a severe risk. Regularization and controlling which parameters are adapted (head-only vs. full model) are common strategies.

Metric-based meta-learning learns an embedding space and a similarity metric such that nearest-neighbor-style classification in that space performs well with few support examples. Prototypical networks are a widely used instantiation: for each class $c$ in the support set, compute the class prototype as the mean of embedded support examples
\[
\mathbf{p}_c = \frac{1}{k} \sum_{(x_i,y_i) \in S_c} \phi(x_i),
\]
then classify a query $x$ by assigning it to the class whose prototype minimizes distance in the embedding space:
\[
\hat{y} = \arg\min_c d\big(\phi(x), \mathbf{p}_c\big).
\]
Here $\phi$ is an embedding function learned across tasks. Metric-based approaches are simple, computationally inexpensive at adaptation time (no gradient steps required per episode), and often robust in extremely low-shot regimes.

On tabular data, metric learning must handle heterogeneous features and appropriate distances. Euclidean distance in raw feature space rarely suffices. Instead, one learns an embedding $\phi$ tailored to the dataset. For categorical variables this might involve learned embeddings, while numerical features may be normalized and passed through nonlinear transforms. Choosing or learning a suitable distance metric (e.g., Mahalanobis distance or learned bilinear forms) can improve performance. Relation networks extend metric-based ideas by learning more expressive comparators than a fixed distance.

Hybrid and hierarchical meta-learning architectures are also useful. For instance, one can combine prototype classification for the head with MAML-style adaptation of a small number of parameters. Alternatively, meta-learned feature-wise transformations (FiLM layers) can modulate feature maps based on the support set. Such parameter-efficient adaptation methods are helpful when full fine-tuning is risky due to overfitting.

A critical requirement for meta-learning is the availability of many related tasks during meta-training. For some tabular domains, constructing such task distributions is nontrivial: tasks might correspond to predicting different labels, forecasting different time series, or segments of a population. Creative task design—splitting by regions, time periods, or subsets of label types—enables meta-learning even when natural task delineations are weak.

# Semi-supervised and self-supervised methods for tabular data

Semi-supervised and self-supervised learning aim to leverage unlabeled data to improve representation learning and downstream performance. In low-label regimes, unlabeled examples are plentiful and can dramatically boost performance if used effectively. While many self-supervised algorithms were developed for images and text, the tabular domain presents distinct opportunities and challenges.

Self-supervised objectives for tabular data typically revolve around reconstructing, predicting, or contrasting parts of the input. Masked modeling (inspired by masked language modeling) randomly masks entries in a row and trains the model to predict the masked values, encouraging the model to capture feature dependencies. Formally, given an input vector $x$ and a random mask $m$, a model $\phi$ is trained to minimize $\mathbb{E}_{x,m} \ell\big(\phi(x \odot (1-m)), x \odot m\big)$ where $\odot$ denotes elementwise masking and $\ell$ is an appropriate loss (regression for continuous entries, classification for categorical entries). Popular variants include VIME, which masks and reconstructs mixed-type features using specialized losses and also employs contrastive components.

Contrastive learning creates positive and negative pairs of examples and trains an encoder so that positive pairs have nearby representations while negatives are far apart. For tabular data, defining positive pairs is nontrivial. Augmentations of the same row can serve as positives (if meaningful augmentations exist), or rows from the same (simulated) neighborhood can be paired. Another route is to define positives via metadata (same patient, same device, same time window). Contrastive objectives can yield robust embeddings but require careful design of augmentations and negative sampling.

Semi-supervised learning methods such as pseudo-labeling and consistency regularization are also applicable. Pseudo-labeling assigns labels to unlabeled examples using a model trained on the small labeled set, then adds confident pseudo-labeled examples to the training set. Consistency regularization encourages the model to produce similar outputs for an example under small perturbations or augmentations, which stabilizes learning. Methods like FixMatch combine pseudo-labeling with confidence thresholds and augmentation-based consistency; adapting them to tabular data requires defining suitable augmentations.

Graph-based semi-supervised approaches can exploit relational structure: rows can be nodes connected by similarity edges, and label propagation or graph neural networks can leverage these relations to diffuse label information. This is particularly valuable when entities have explicit links (e.g., users interacting with items) or when similarity graphs can be reliably constructed.

Successful semi/self-supervised tabular methods account for feature heterogeneity. For categorical variables, predicting the class distribution under masking or encoding categories via embeddings helps. For continuous features, choosing appropriate reconstruction losses and scaling is essential. Missing values can be handled within the self-supervised objective: treat missingness as an additional signal to model, and do not simply impute before pretraining.

Finally, a practical recommendation: combine self-supervised pretraining with supervised fine-tuning using techniques tailored to small labeled sets—such as low learning rates, early stopping, and parameter-efficient heads—to get the maximal benefit in low-resource situations.

# Synthetic data generation and pretraining with simulated distributions

When labeled data are scarce, generating synthetic data or pretraining on simulated distributions can be a powerful strategy. The idea is to expose the learner to a broad variety of distributions and relationships so that it learns generalizable patterns or learning strategies that transfer to real data.

One common class of synthetic generation methods aims to mimic the joint distribution of features and labels via generative models. Traditional statistics offers parametric models (e.g., multivariate Gaussians, copulas) and Bayesian networks which capture conditional dependencies among variables. More flexible approaches use neural generative models: variational autoencoders (VAEs), generative adversarial networks (GANs), and autoregressive models. Conditional variants allow generation of labeled examples by sampling $x$ given $y$ or vice versa. Synthetic samples can augment training sets or be used to pretrain encoders.

Simulations that incorporate known or plausible mechanisms are particularly useful when domain knowledge is available. For example, in healthcare, one can simulate patient trajectories using compartmental models or mechanistic physiological simulators; in economics, agent-based models can generate transactions under controlled policy changes. Pretraining on such simulated data exposes models to structural relationships that exist in the real world and can improve robustness.

A valuable synthetic strategy for meta-learning is to create many tasks by sampling parameters of a data-generating process. For regression, one can sample functions from a Gaussian process prior, then generate few-shot tasks by sampling input-output pairs for different sampled functions; training on many such tasks allows models like MAML to learn rapid adaptation across function families. For tabular data, similar approaches sample conditional distributions and marginal structures from families (e.g., various copula parameters, mixture models) to produce tasks with varied dependency structures.

Synthetic data generation has caveats. If the synthetic distribution is too different from the real target, pretraining may hurt (negative transfer). Careful calibration of simulation parameters, domain randomization (covering a wide range of plausible behaviors), and including some real unlabeled data to align distributions can mitigate this risk. Privacy concerns also motivate synthetic data: generating realistic synthetic tables can enable pretraining without exposing the true sensitive records. However, privacy-preserving generation requires rigorous evaluation to ensure synthetic records do not leak individuals’ information.

When synthetic data are used for pretraining, it is useful to adopt strategies that focus on learning general inductive biases rather than memorizing synthetic patterns. Meta-learning on synthetic tasks, denoising objectives, and contrastive tasks that emphasize invariant structure tend to transfer better than simply training to predict synthetic labels that have no counterpart in the real world.

# Data augmentation challenges for tabular data

Data augmentation—the practice of applying label-preserving transformations to inputs to create more training examples—is a mainstay in vision and speech, but it is harder for tabular data. The central difficulty is that arbitrary perturbations of tabular features often break underlying constraints, change semantics, or produce unrealistic records. Nevertheless, several augmentation strategies have been proposed and some tailored principles can increase their effectiveness.

Simple augmentations include noise injection to continuous features, small random perturbations of numeric entries, and permutations of columns when column order is irrelevant. However, injecting Gaussian noise risks moving examples out of the manifold of realistic rows, which can confuse the model. For categorical variables, naive label-preserving swaps are usually invalid (changing the category often changes the label distribution).

More principled approaches rely on domain knowledge to design transformations that preserve labels. For example, in time-series or transactional tables, shifting timestamps while maintaining relative patterns can be valid. In healthcare, physiologically plausible perturbations (e.g., small changes in lab values within normal variation) may be acceptable. Domain constraints such as sum-to-one, monotonic relationships, or logical dependencies (e.g., age must be nonnegative and consistent with dates) must be respected.

Synthetic minority over-sampling techniques (SMOTE) create new examples by interpolating between minority-class samples in feature space. Variants of SMOTE for mixed-type features exist, but interpolation can produce unrealistic categorical combinations. MixUp, a simple augmentation that convexly mixes two examples and their labels, can be extended to tabular data, but the meaning of a convex combination of categories is unclear; using embeddings and then mixing in embedding space partially addresses this but may still produce semantically nonsensical inputs.

Augmentation via learned generative models (VAEs, GANs) can produce realistic synthetic examples if the generative model captures joint distributions well. Such synthetic examples can increase effective training data, though generated examples should be validated (e.g., by domain experts or via distributional similarity metrics) to avoid introducing bias.

Another promising direction is feature-level augmentation: augment the representation space rather than the raw features. If an encoder maps rows to representations, one can apply perturbations in representation space (add small Gaussian noise, interpolate representations) and then train the classifier to be invariant. This avoids directly synthesizing raw rows but still encourages robustness.

Overall, successful tabular augmentations tend to be conservative (small perturbations that respect constraints), domain-aware, and validated. Blindly applying image-style augmentations or heavy mixing often harms performance. When using augmentations, always evaluate whether the augmented examples remain plausible and whether the augmentation preserves the target label distribution.

# Evaluation practices and baselines for few-shot settings

Good experimental practice is critical in few-shot learning because results are often sensitive to choices of splits, random seeds, and implementation details. To produce reliable and interpretable results, follow these guidelines.

First, choose appropriate baselines. Standard baselines include: (1) training from scratch on the small labeled set (with proper regularization and early stopping); (2) pretrained models fine-tuned on the small set (if pretraining is part of the experiment); (3) simple non-deep learners that often perform well on tabular data, such as gradient-boosted decision trees trained on engineered features; and (4) nearest-neighbor classifiers using various feature representations. For meta-learning evaluations, include both metric-based and optimization-based baselines, and when possible compare episodic meta-learning to transfer learning+fine-tuning—these are distinct workflows and one or the other may be more practical.

Second, report statistically meaningful metrics. Because few-shot results have high variance, report mean and confidence intervals (e.g., standard error or 95% CI) across multiple runs with different random seeds and multiple episode samplings. When evaluating N-way $k$-shot tasks, report the number of episodes averaged and ensure that episodes use disjoint classes for meta-test. In regression or other tasks, provide root mean squared error (RMSE) plus uncertainty. When comparing methods, perform appropriate significance testing or bootstrap estimates to determine whether observed differences are robust.

Third, control for hyperparameter tuning. Hyperparameters tuned on meta-test data can leak information and overstate performance. Use a held-out meta-validation set to tune hyperparameters and report final results only on meta-test. If hyperparameter sensitivity is high, report performance across plausible hyperparameter ranges or include ablation studies showing which choices matter.

Fourth, examine calibration and practical utility. Low-shot models can be overconfident; measure calibration (e.g., expected calibration error) and consider whether outputs are well-calibrated for downstream decision-making. Also consider downstream costs—false positives and false negatives may have asymmetric costs in practice; report precision/recall curves or use domain-specific cost functions.

Fifth, perform robustness checks. Evaluate how methods perform under domain shift: if the distribution of features or label conditional distribution changes between pretrain and test, transfer and meta-learning methods can degrade. Test sensitivity to label noise, to class imbalance, and to real-world issues like missing data.

Sixth, choose realistic baselines for tabular data. Many modern few-shot papers focus on image datasets; adapting those results to tabular settings requires including strong tabular baselines. Include gradient-boosted trees (e.g., XGBoost, LightGBM, CatBoost) with sensible feature preprocessing and hyperparameter tuning, simple logistic regression with regularization, and k-nearest neighbors. When proposing neural methods, compare to these tried-and-true approaches, because neural networks do not always outperform tree ensembles on small tabular sets.

Seventh, report runtime and complexity. In low-resource scenarios, computational constraints matter—models that require expensive pretraining or adaptation may be impractical. Include training and inference times, memory usage, and any special hardware requirements.

Finally, be transparent in experiment details. Provide data preprocessing pipelines, how missing values are handled, categorical encoding schemes, random seeds, and code when possible. This transparency improves reproducibility and helps the community build on results.

Concluding remarks

Few-shot and low-resource learning bring together ideas from transfer learning, meta-learning, semi/self-supervised learning, and synthetic data. For tabular data, the heterogeneity of features and the prevalence of domain constraints require careful adaptation of methods developed for images and text. Practical success often depends on thoughtful pretraining tasks, conservative augmentation strategies, and careful evaluation. By combining domain knowledge with principled algorithmic approaches—e.g., column-aware pretraining, masking and denoising objectives, generative simulation for task diversity, and robust baselines—practitioners can substantially improve model performance when labeled data are scarce.

Introduction

Supervised learning is a branch of machine learning where an algorithm learns a mapping from inputs to outputs using labeled examples. The labels provide the "supervision" that guides the learning process. Among supervised tasks, classification is concerned with predicting discrete categories (classes) for inputs, while regression predicts continuous values. This chapter introduces the fundamental concepts for supervised learning in the context of classification: how tasks are formulated, how models produce outputs, the losses used to train them, the optimization methods that adjust model parameters, the metrics used to evaluate performance, and the principles for choosing models while avoiding overfitting and underfitting. The goal is to provide both the mathematical formulation and the intuition needed to read and understand research and applied work in classification.

# Problem setup: training, validation, test sets

When we build a supervised classifier we start with a dataset of labeled examples. Concretely, we assume data points $(x_i, y_i)$ for $i=1,\dots,N$, where $x_i \in \mathcal{X}$ is an input (for example, an image, a feature vector, or text) and $y_i \in \mathcal{Y}$ is the corresponding label (for classification, $\mathcal{Y}$ is a finite set of classes). We aim to learn a model $f_\theta:\mathcal{X}\to\mathcal{Z}$ parameterized by $\theta$, and an associated decision rule that maps $f_\theta(x)$ to a predicted class.

To estimate how well a model will perform on unseen data, we split the available labeled examples into at least two sets: a training set and a test set. The training set is used to fit the model parameters $\theta$. The test set is held out and used only after model development to estimate the generalization performance. A common practice is to further partition the data into three sets: training, validation, and test. The validation set is used during model development to tune hyperparameters (e.g., model size, regularization strength, learning rate, architecture choices) and make decisions such as early stopping. The test set is used only once or rarely to provide an unbiased estimate of the final model's performance.

Partitioning should respect the data-generating process. If observations are independent and identically distributed (i.i.d.), a random split is appropriate. If data are time-ordered, one must split chronologically to avoid training on future information. For classification with class imbalance, ensure that the class distribution in each split reflects the overall distribution by stratified sampling.

When the dataset is small, cross-validation is a common technique. In k-fold cross-validation, the dataset is partitioned into $k$ folds. Each fold in turn is held out as a validation set while the model is trained on the remaining $k-1$ folds. The performance is averaged across folds to assess stability and generalization. Cross-validation helps provide more reliable estimates of performance and is widely used for hyperparameter selection.

Finally, it is crucial to avoid "data leakage": any use of test or validation data in the training process (including feature scaling or feature selection done using entire dataset statistics) can lead to overly optimistic performance estimates.

# Classification vs. regression

The distinction between classification and regression lies in the nature of the target variable $y$. In regression, $y$ is continuous, e.g., predicting house prices or temperatures. In classification, $y$ is discrete, taking values from a set of classes, e.g., $\{0,1\}$ for binary classification or $\{1,\dots,K\}$ for multiclass classification.

This distinction affects choices in model output, loss functions, and evaluation metrics. In regression, typical loss functions are squared error $\frac{1}{N}\sum_i (y_i - \hat{y}_i)^2$ or absolute error. In classification, probabilistic interpretations are common: we often model conditional class probabilities $p(y|x)$ and then make decisions by choosing the class with highest estimated probability. For binary classification, we might model $p(y=1|x)=\sigma(z(x))$ with the logistic function $\sigma(u)=1/(1+e^{-u})$. For multiclass classification we model a probability vector over the $K$ classes, typically via softmax.

There are borderline situations: ordinal regression where labels have an order but are discrete, or classification tasks where one predicts a continuous score and then thresholds it. But conceptually, classification requires discrete decision-making and is typically evaluated using metrics suitable for categorical outcomes (accuracy, precision, recall, etc.) rather than mean-squared error.

# Loss functions: cross-entropy, log loss, hinge loss

A loss function quantifies how well the model's predictions match the true labels. In probabilistic modeling, losses are typically derived from likelihood principles. Consider a dataset $\{(x_i,y_i)\}_{i=1}^N$ and a model that outputs class probability estimates $\hat{p}_\theta(y|x)$. The negative log-likelihood (NLL) of the parameters given the data is
\[
\mathcal{L}_{\text{NLL}}(\theta) = -\sum_{i=1}^N \log \hat{p}_\theta(y_i | x_i).
\]
For classification, dividing by $N$ gives the average NLL, often called cross-entropy loss.

Binary log loss / binary cross-entropy. For binary labels $y\in\{0,1\}$ and model prediction $\hat{p}=\hat{p}_\theta(y=1|x)$, the per-example log loss (also called binary cross-entropy) is
\[
\ell_{\text{BCE}}(\hat{p}, y) = -\bigl[y\log \hat{p} + (1-y)\log(1-\hat{p})\bigr].
\]
This loss penalizes assigning low probability to the true class. Minimizing expected log loss corresponds to maximizing likelihood; if the model class contains the true conditional distribution and we have infinite data, the minimizer recovers the true probabilities.

Multiclass cross-entropy / categorical log loss. For $K$ classes with one-hot label vector $y\in\{e_1,\dots,e_K\}$ and model probabilities $\hat{p}_k=\hat{p}_\theta(y=k|x)$, the loss is
\[
\ell_{\text{CE}}(\hat{p}, y) = -\sum_{k=1}^K y_k \log \hat{p}_k = -\log \hat{p}_{y},
\]
where $\hat{p}_{y}$ denotes the predicted probability for the true class. This is the standard loss used in training neural networks for classification.

Hinge loss. Hinge loss arises from maximum-margin classifiers such as support vector machines (SVMs). For binary labels $y\in\{-1,+1\}$ and model scores (not probabilities) $f(x)\in\mathbb{R}$, the hinge loss is
\[
\ell_{\text{hinge}}(f(x), y) = \max(0, 1 - y f(x)).
\]
The hinge loss penalizes predictions that do not place the correct class at least one unit margin above the decision boundary. Minimizing hinge loss with an $L_2$ penalty on the weights yields the soft-margin SVM. Hinge loss is not probabilistic; it directly optimizes a margin-based objective and is convex for linear models.

Relationship and differences. Cross-entropy is probabilistic and differentiable everywhere, which makes it a natural pairing with gradient-based training of neural networks. Hinge loss focuses on producing large margins between classes and is convex for linear predictors. Cross-entropy tends to produce well-calibrated probabilities when models are well-specified, while hinge loss does not provide probabilities without additional calibration. In practice, cross-entropy has become the dominant choice for deep learning classification, but margin-based objectives remain important conceptually and in some specialized algorithms.

# Output representations: logits, probabilities, softmax

Understanding how models represent outputs is critical. Many classifiers, especially neural networks, produce a vector of real-valued scores for each class, often called logits. Let $z(x)\in\mathbb{R}^K$ be the logits for $K$ classes produced by the model. Logits are unbounded real numbers and are interpretable as "unnormalized log-probabilities": there exists an implicit relationship between logits and probabilities via the softmax transformation.

The softmax function converts logits to a probability distribution over classes:
\[
\operatorname{softmax}(z)_k = \frac{e^{z_k}}{\sum_{j=1}^K e^{z_j}}.
\]
The softmax ensures non-negativity and that the probabilities sum to one. The cross-entropy loss for a single example with true class index $y$ can be written directly in terms of logits as
\[
\ell(z, y) = -\log \left( \frac{e^{z_y}}{\sum_{j} e^{z_j}} \right) = -z_y + \log \sum_j e^{z_j}.
\]
Expressing the loss in terms of logits is numerically and computationally convenient, because modern implementations combine softmax and cross-entropy into a single "softmax cross-entropy" operation with stable computation.

Logits are useful because they allow the model to express relative preferences between classes. Adding the same constant to all logits does not change the softmax probabilities, since
\[
\frac{e^{z_k + c}}{\sum_j e^{z_j + c}} = \frac{e^{z_k}}{\sum_j e^{z_j}}.
\]
Hence only differences between logits matter.

Probability calibration refers to how well the predicted probabilities reflect true frequencies. A model is well calibrated if, among examples for which it predicts probability $p$ for a class, approximately $p$ fraction truly belong to that class. Cross-entropy tends to encourage calibration, but modern deep networks can be miscalibrated, often being overconfident. Post-hoc calibration methods (e.g., Platt scaling, isotonic regression, temperature scaling) adjust logits or probabilities on validation data to improve calibration.

Numerical stability. Computing softmax directly can cause overflow or underflow when some logits are large in magnitude. A standard trick is to subtract the maximum logit before exponentiating:
\[
\operatorname{softmax}(z)_k = \frac{e^{z_k - m}}{\sum_j e^{z_j - m}}, \quad m=\max_j z_j,
\]
which is mathematically identical but numerically stable.

Finally, for binary classification it is common to work with a single logit $z$ and apply the sigmoid (logistic) function $\sigma(z)=1/(1+e^{-z})$ to obtain a probability for the positive class; the negative class probability is $1-\sigma(z)$.

# Training basics: gradient descent, mini-batch updates

Training parametric models means finding parameters $\theta$ that minimize an empirical loss function, typically the average loss over the training set:
\[
\mathcal{L}(\theta) = \frac{1}{N}\sum_{i=1}^N \ell(f_\theta(x_i), y_i) + \lambda R(\theta),
\]
where $R(\theta)$ is a regularizer (e.g., $L_2$ norm) and $\lambda\ge 0$ controls its strength.

Gradient descent is the most basic optimization method: iteratively update parameters in the direction of the negative gradient of the loss:
\[
\theta_{t+1} = \theta_t - \eta \nabla_\theta \mathcal{L}(\theta_t),
\]
where $\eta>0$ is the learning rate. For large datasets computing the full gradient $\nabla_\theta \mathcal{L}(\theta)$ every step is expensive. Stochastic gradient descent (SGD) approximates the gradient using one or a small batch of examples.

Mini-batch SGD uses batches of size $B$ drawn from the training set. At iteration $t$ we sample a batch $\mathcal{B}_t$ and compute the batch gradient
\[
g_t = \frac{1}{B}\sum_{(x_i,y_i)\in\mathcal{B}_t} \nabla_\theta \ell(f_\theta(x_i), y_i),
\]
then update
\[
\theta_{t+1} = \theta_t - \eta g_t.
\]
Mini-batch updates provide a compromise between noisy single-example updates and expensive full-batch updates. The stochasticity introduced by sampling can help escape shallow local minima and provides implicit regularization effects.

Choosing the learning rate $\eta$ is crucial. If $\eta$ is too large, the optimizer may diverge; if too small, training is slow or may get stuck. Practical training uses learning-rate schedules (constant, step decay, exponential decay, cosine annealing) or adaptive methods.

Momentum accelerates convergence by incorporating a velocity term that accumulates past gradients:
\[
v_{t+1} = \mu v_t + \eta g_t,\quad \theta_{t+1} = \theta_t - v_{t+1},
\]
where $\mu\in[0,1)$ is the momentum coefficient. Momentum helps traverse ravines in the loss landscape and smooths noisy updates.

Adaptive gradient methods, such as AdaGrad, RMSProp, and Adam, scale updates per-parameter based on historical gradient magnitudes. For example, Adam maintains moving averages of gradients and squared gradients to compute parameter-specific learning rates. These methods often speed up convergence and require less manual tuning of the learning rate, but they can generalize differently from SGD with momentum; practitioners sometimes switch from Adam to SGD for final training.

Regularization and optimization interact. Techniques like weight decay (equivalent to $L_2$ regularization in many settings), dropout, data augmentation, and early stopping are common ways to improve generalization. Early stopping monitors validation performance and halts training when performance stops improving; this prevents overfitting the training data.

# Evaluation metrics: accuracy, precision/recall, ROC curve and AUROC, F1-score

After training, we need metrics to evaluate how good the classifier is. The choice of metric depends on the problem, class balance, and the cost of different types of errors.

Confusion matrix. For binary classification, performance is summarized by the confusion matrix which counts true positives (TP), true negatives (TN), false positives (FP), and false negatives (FN). These counts form the basis for most metrics.

Accuracy. Accuracy is the simplest metric: the fraction of correctly classified examples,
\[
\text{Accuracy} = \frac{TP + TN}{TP + TN + FP + FN}.
\]
Accuracy is easy to interpret but can be misleading for imbalanced datasets. For example, if 99% of examples are negative, a trivial classifier that always predicts negative achieves 99% accuracy but is useless.

Precision and recall. Precision (also called positive predictive value) measures correctness among predicted positives:
\[
\text{Precision} = \frac{TP}{TP + FP}.
\]
Recall (also called sensitivity or true positive rate) measures coverage of actual positives:
\[
\text{Recall} = \frac{TP}{TP + FN}.
\]
Precision emphasizes avoiding false positives, while recall emphasizes finding as many true positives as possible. Which one matters depends on the application: in medical screening, high recall may be preferred to catch as many cases as possible; in spam filtering, high precision may be preferred to avoid misclassifying legitimate mail.

F1-score. The F1-score is the harmonic mean of precision and recall:
\[
F1 = 2\cdot\frac{\text{Precision}\cdot \text{Recall}}{\text{Precision} + \text{Recall}}.
\]
It balances precision and recall, but being a single number it hides the trade-off between them. For imbalanced datasets, F1 is often more informative than accuracy.

Thresholds and scores. Many classifiers output scores or probabilities rather than hard labels. To convert a score to a binary prediction we choose a threshold. Different thresholds yield different trade-offs between precision and recall. Therefore it is useful to consider metrics over all possible thresholds.

ROC curve and AUROC. The receiver operating characteristic (ROC) curve plots the true positive rate (TPR = recall) against the false positive rate (FPR = FP/(FP+TN)) as the decision threshold varies. The area under the ROC curve (AUROC or AUC) summarizes the ROC curve as a single scalar between 0 and 1. AUROC has the probabilistic interpretation that it equals the probability that a randomly chosen positive example receives a higher score than a randomly chosen negative example. AUROC is threshold-independent and robust to class imbalance in many settings. However, for highly imbalanced data or when the focus is on positive predictive value, precision-recall curves can be more informative.

Precision-Recall curve and average precision. The precision-recall (PR) curve plots precision versus recall for varying thresholds. For imbalanced datasets with a rare positive class, the PR curve gives a more informative picture of model performance for the positive class. Average Precision (AP) is a summary metric corresponding to the area under the PR curve (though there are multiple practical definitions tied to interpolation). AP is sensitive to class imbalance and more closely tied to the performance on the positive class.

Multiclass metrics. For multiclass classification, metrics generalize from binary definitions. Accuracy extends straightforwardly. For precision and recall, one can compute per-class precision/recall and then aggregate using macro-averaging (unweighted mean across classes), micro-averaging (compute totals over all classes then derive metrics), or weighted averaging by class frequency. The choice depends on whether one wants to treat classes equally (macro) or reflect class frequencies (micro/weighted).

Calibration metrics. If predicted probabilities are important, calibration metrics such as expected calibration error (ECE) and reliability diagrams assess how well predicted probabilities match empirical frequencies.

Choosing the right metric. The metric should reflect the real-world costs of errors. A classifier with high accuracy but low recall for the positive class may be unacceptable in safety-critical domains. Always report multiple metrics (e.g., accuracy plus precision and recall or AUROC) and provide threshold-dependent curves when decisions depend on a threshold.

# Model selection and overfitting/underfitting

Model selection is the process of choosing among candidate models and hyperparameters to achieve the best performance on unseen data. The fundamental tension is between model complexity and generalization. Underfitting occurs when a model is too simple to capture relevant patterns in the data: it performs poorly on both training and validation sets. Overfitting occurs when a model memorizes training data idiosyncrasies and achieves low training loss but performs poorly on validation/test sets.

Bias-variance trade-off. A conceptual framework for understanding these phenomena is the bias-variance decomposition (informally applicable in classification): more flexible models have lower bias (able to fit complex patterns) but higher variance (sensitive to sampling noise), while simpler models have higher bias but lower variance. The optimal model complexity balances these sources of error.

Detecting overfitting and underfitting. Learning curves are a practical diagnostic: plot training and validation performance as a function of training set size or training iteration. If both training and validation errors are high and close, the model is underfitting; increase model capacity, reduce regularization, or engineer better features. If training error is much lower than validation error, the model is overfitting; increase regularization, collect more data, or reduce model capacity.

Regularization techniques. Regularization reduces overfitting by constraining model complexity. Common methods include $L_2$ regularization (weight decay) which penalizes large weights, $L_1$ regularization encouraging sparsity, dropout which randomly zeros activations during training to prevent co-adaptation, and data augmentation which increases effective dataset size by applying transformations that preserve labels. Early stopping—halting training when validation performance stops improving—is a practical form of regularization.

Model selection strategies. Use validation data to compare models and tune hyperparameters. Grid search or random search over hyperparameter spaces is common; Bayesian optimization is an automated approach to explore hyperparameter settings more efficiently. When data are scarce, cross-validation provides more robust estimates for selection. Always reserve the test set for the final evaluation after selection to avoid an optimistic bias.

Complexities in practice. Modern deep learning models can have extremely high capacity and yet generalize well; classical bias-variance intuitions need to be augmented with ideas about implicit regularization from optimization (e.g., SGD tends to favor flat minima) and the role of large datasets. Nevertheless, the practical advice stands: monitor validation performance, use held-out data for hyperparameter tuning, and prefer simpler models when they achieve comparable validation performance.

Finally, consider the deployment context: if data distributions may shift over time, techniques like domain adaptation, model recalibration, or continual learning may be necessary. Also, consider fairness, robustness to adversarial examples, and interpretability requirements when selecting models.

Conclusion

This chapter has introduced the core elements of supervised classification: dataset splits and experimental procedures, the difference between classification and regression, the principal loss functions used to train classifiers, how models represent outputs and transform logits into probabilities, the basic optimization algorithms used to train models, standard evaluation metrics and their proper use, and model selection strategies to avoid overfitting and underfitting. Together, these concepts form the foundation for understanding and developing classification systems and reading research papers that propose new architectures, losses, or evaluation protocols. Keep in mind the interplay between modeling choices, training methods, and evaluation: a sound experimental design and appropriate metrics are as important as sophisticated models.

# Introduction

Transformers are powerful sequence models that build representations of input tokens using self-attention. Self-attention computes pairwise interactions among tokens by comparing query and key vectors, producing weights that determine how information flows across positions. Unlike recurrent or convolutional architectures, the vanilla Transformer has no built-in notion of token order: the attention mechanism applied to a set of token embeddings is permutation-equivariant. That is, if you shuffle the input embeddings and apply the same Transformer layers, you get a corresponding permuted output—nothing in the architecture by itself tells the model which token came before another.

To use Transformers for language, speech, time series, or any task where order matters, we must inject positional information into the input so the model can distinguish positions and reason about relative and absolute ordering. This chapter explains why positional encodings are necessary, surveys the standard ways of encoding positions (absolute learned embeddings and analytic sinusoidal encodings), covers relative positional encodings and bias methods, and analyzes trade-offs between learned and analytic encodings. We also discuss how positional encodings interact with attention (additive versus multiplicative methods) and how to evaluate them, focusing on interpolation within trained lengths and extrapolation to longer sequences.

# Why positional encodings are necessary for Transformers

Consider the self-attention operation in a Transformer layer. For a sequence of length $n$ we have token embeddings $x_1, x_2, \dots, x_n$. For a single attention head we compute queries $q_i$, keys $k_j$, and values $v_j$ (dropping layer indexes for brevity) via learned linear projections:
$q_i = W_Q x_i$, $k_j = W_K x_j$, $v_j = W_V x_j$.
Attention weights are computed as scaled dot-products:
\[
\alpha_{ij} = \frac{\exp\left(q_i^\top k_j / \sqrt{d}\right)}{\sum_{t=1}^n \exp\left(q_i^\top k_t / \sqrt{d}\right)},
\]
and the output for position $i$ is $\sum_{j=1}^n \alpha_{ij} v_j$.

If we permute the input embeddings by some permutation $\pi$, i.e., replace $x_i$ with $x_{\pi(i)}$, then $q_i, k_j, v_j$ permute accordingly and the attention outputs permute in the same way. Nothing in this computation depends on the numerical index $i$; only the content of the tokens matters. For many tasks, however, the absolute position or relative ordering of tokens is essential. For example, in language, the meaning of a sentence depends on word order; in time series, causality and temporal dynamics depend on which time step came first; in positional tasks such as sorting or sequence labeling, explicit index information is necessary.

Thus, without positional encodings, a Transformer cannot distinguish sequences that are identical up to permutation of tokens. Positional encodings provide a way to break this symmetry by introducing position-dependent signals into the embeddings or attention mechanism. With appropriate positional information, the model can learn to use positions to compute position-aware queries, keys, and values, enabling it to model order-sensitive functions.

There are two broad goals when designing positional encodings. First, the encoding should let the model represent the order and distance relationships needed by the task (absolute position, relative distance, directional relations). Second, the encoding should interact well with learning dynamics, generalization properties (especially extrapolating to longer sequences than seen in training), and computational/parameter budgets. These trade-offs motivate the variants and design choices we discuss next.

# Absolute positional encodings: learned embeddings and sinusoidal encodings

Absolute positional encodings associate each position index with a vector representation and combine that vector with the token embedding to produce a position-aware input to the Transformer. There are two common instantiations: learned positional embeddings and sinusoidal (analytic) encodings.

Learned positional embeddings
In the learned approach, each position index $p \in \{1,2,\dots,L_{\text{max}}\}$ has an associated parameter vector $e_p \in \mathbb{R}^d$ that is learned during training. Given token embedding $x_i$, the position-aware input is typically $x_i + e_i$ (but other combinations are possible). The learned vectors are free parameters, so the model can in principle encode any pattern of positional information needed for the training data. This approach is simple and flexible: it treats positional embeddings like an additional vocabulary whose entries are optimized jointly with other model parameters.

However, learned embeddings come with natural limits. They require a maximum supported length $L_{\text{max}}$ chosen before training; positions beyond that length have no learned vectors unless some extension scheme is used. Since each position has its own vector, learned embeddings can be expressive but do not by themselves provide an inductive bias for smoothness or distance relationships; those must be learned from data. This means learned embeddings often work very well within the range of lengths seen during training but may fail to generalize to much longer sequences (extrapolation).

Sinusoidal positional encodings
The sinusoidal encoding, introduced in the original Transformer paper, is an analytic, deterministic function of position index $p$. For dimension index $k$ (from $0$ to $d-1$), the positional encoding is defined as:
\[
\text{PE}(p, 2k) = \sin\left(p / 10000^{2k/d}\right), \qquad
\text{PE}(p, 2k+1) = \cos\left(p / 10000^{2k/d}\right).
\]
This produces a $d$-dimensional vector for every position $p$ using sinusoidal basis functions of geometrically increasing wavelengths. The intuition is that each dimension tracks a sinusoid with a particular frequency, so by combining frequencies the encoding contains information about absolute position and about relative position differences: using trigonometric identities, dot-products between encodings at different positions depend on the difference $p - q$ in a predictable way.

Sinusoidal encodings have several appealing properties. They are parameter-free (no additional learned parameters), they provide a smooth, continuous representation across positions, and because the encoding is defined for any integer $p$ they naturally extend to arbitrarily long sequences (extrapolation). The choice of base $10000$ and the geometric schedule are somewhat heuristic, but they distribute wavelengths so that some components vary quickly (capturing local differences) while others vary slowly (capturing global position).

Combining encodings with token embeddings
The standard way to combine absolute positional encodings with token embeddings is additive: the input to the Transformer is $x_i + e_i$ for learned embeddings or $x_i + \text{PE}(i, \cdot)$ for sinusoidal encodings. Additive combination is simple and preserves the embedding dimensionality while providing a direct position-dependent bias to subsequent linear projections. Other combinations (concatenation followed by projection, gating, or multiplicative interactions) are also possible and sometimes used, particularly when one wants richer interactions between token content and position.

# Relative positional encodings and bias methods

Relative positional encodings aim to represent position information in terms of relationships between token pairs, rather than absolute indexes. Many tasks depend primarily on relative distances or directions (e.g., "the word two tokens to the left" or "an event that occurred k steps earlier") rather than on absolute positions. Relative schemes encode such relationships directly into the attention computation, often improving generalization and parameter efficiency.

Key idea and early work
The essential idea is to make attention weights or attention logits depend explicitly on the relative distance $r = j-i$ between query position $i$ and key position $j$. Early work (Shaw, Uszkoreit, and Vaswani, 2018) augmented the attention computation by adding to the key or value vectors a learned embedding that depends on the relative distance:
\[
k'_j = k_j + a_{j-i}, \qquad v'_j = v_j + b_{j-i},
\]
where $a_{r}$ and $b_{r}$ are learned relative embeddings for relative position $r$ (usually clipped to a range $[-R, R]$). Then the attention logits $q_i^\top k'_j$ incorporate relative distance information directly. This approach allows the model to use relative distances when computing compatibility between query and key content. Clipping or bucketing of distances is common to limit the number of parameters and to emphasize short-range distinctions more finely than long-range ones.

Transformers-XL and relative positional encoding via biases
Transformer-XL introduced a formulation where relative position information is added as a term in the attention score. Suppose we compute queries $q_i$ and keys $k_j$ as before. Transformer-XL defines an additional term $r_{j-i}$ coming from a learned positional embedding projected by a separate weight, yielding attention logits of the form:
\[
\text{score}_{ij} = q_i^\top k_j + q_i^\top R_{j-i} + u^\top k_j + v^\top R_{j-i},
\]
where $R_{r}$ is a learned vector representing relative position $r$, and $u, v$ are global learned vectors that implement content and position biases. The $q_i^\top R_{j-i}$ term explicitly makes the query interact with the relative position vector, thereby injecting relative distance dependence in the compatibility score. This formulation was important for enabling Transformer-XL to handle longer contexts and to reuse hidden states across segments.

Bias-based relative methods: T5 and ALiBi
Later work simplified or modified how relative information is added. T5 (Raffel et al.) uses a relative positional bias that is added directly to the attention logits as a scalar bias dependent only on $r=j-i$ and the attention head $h$:
\[
\text{score}_{ij}^{(h)} = q_i^{(h)\top} k_j^{(h)} + b_h(r),
\]
where $b_h(r)$ is a learned scalar bias for head $h$ and relative distance $r$, typically bucketed to reduce the number of parameters. This approach decouples the relative signal from content vectors and places it explicitly as a logit bias, which is computationally cheap and effective in practice.

ALiBi ("Attention with Linear Biases") proposes a simple analytic bias proportional to negative distance:
\[
b_h(r) = -\lambda_h \cdot |r|,
\]
where $\lambda_h \ge 0$ is a head-specific slope. Adding these biases favors attending to nearby tokens without adding additional projection matrices or value perturbations. ALiBi has been found to improve extrapolation to longer contexts: because the bias grows linearly with distance, attention naturally focuses on closer tokens as distance increases, and the linear bias can be evaluated for any $r$ beyond training lengths.

Bucketing and clipping
A practical issue with relative encodings is that the number of distinct relative distances grows with sequence length. To keep parameter counts reasonable, many methods "bucket" distances: small distances are represented precisely (one bucket per distance up to some threshold) while larger distances are grouped into coarser buckets, often on a logarithmic scale. Another approach is to clip distances at some maximum and treat anything beyond the clip as a single bucket. Bucketing and clipping trade expressivity for parameter efficiency and can be tuned depending on whether fine distinctions are required at long ranges.

RoPE: rotary position embeddings
Rotary Positional Embeddings (RoPE) take a multiplicative approach that mixes position into the query and key via rotations in the embedding subspaces. RoPE represents positions by applying a rotation matrix $R_p$ to queries and keys:
\[
q'_i = R_i q_i, \qquad k'_j = R_j k_j,
\]
and uses the dot product $q'_i{}^\top k'_j$. With a properly chosen rotation structure, the dot product becomes a function that depends on relative position $j-i$ in a predictable way, enabling relative position encoding without adding extra parameters per position. RoPE has been effective empirically and supports extrapolation to longer sequences because rotations can be computed for any index.

Relative encodings thus come in many flavors: adding position-conditioned terms to keys/values, adding scalar biases to logits, applying parameter-free transforms like rotations, and using bucketing/clipping for scalability. Each design makes different trade-offs between expressivity, parameter cost, computational complexity, and extrapolation behavior.

# Pros/cons of learned vs analytic (sinusoidal) encodings

When choosing a positional encoding strategy, a common decision is between learned absolute embeddings and analytic encodings (e.g., sinusoidal). Each has advantages and disadvantages.

Expressivity and task fit
Learned embeddings are maximally flexible: the model can represent arbitrary position-dependent patterns up to the chosen maximum length. If a task depends on complex, non-smooth absolute position features that appear frequently in the training set, learned embeddings can capture those directly. Analytic encodings impose a particular structure (sinusoids emphasize periodic and smoothly varying representations) that may or may not align with task requirements.

Generalization and extrapolation
Analytic encodings like sinusoidal functions generalize to positions beyond those seen during training because they are deterministic functions of position. This gives them an advantage when the model needs to handle longer sequences at inference than during training. Learned embeddings, by contrast, typically do not extrapolate: if you ask the model to process position $p > L_{\text{max}}$ for which no learned vector exists, you must adopt an extension strategy (e.g., copying the last embedding, interpolation, or learning a new projection) and generalization is not guaranteed.

Data efficiency and stability
Learned embeddings add parameters—one vector per position—which increases model size linearly with the maximum length. For very long context windows, this may become costly. Sinusoidal encodings have no parameters and can be computed cheaply. In addition, analytic encodings may provide a helpful inductive bias: smooth positional signals that vary across multiple frequencies can make it easier for the model to learn to reason about intervals and distances, improving sample efficiency on tasks that depend on relative positions.

Flexibility to represent relative information
Relative positional schemes often outperform absolute ones on tasks where only relative distances matter. While learned absolute embeddings can implicitly capture relative patterns if trained sufficiently, relative encodings directly model the quantities that matter (e.g., $j-i$) and can therefore provide more efficient representations. Relative approaches can be combined with learned embeddings or analytic encodings, and hybrid schemes (e.g., learned radial features combined with analytic rotations) are common.

Robustness to architecture and training changes
Learned embeddings rely on the model to discover position-related structure in the parameters, which may interact with initialization, optimization, and data regime. Analytic encodings are deterministic and therefore more predictable across architectures and random seeds. This can be an advantage in large-scale training where stability matters.

In practice, many modern models use a mixture of ideas: they might use learned relative biases (as in T5) or ALiBi for extrapolation benefits; they may use RoPE or sinusoidal encodings to enable extrapolation while preserving expressivity in content interactions. The choice often depends on the target application (need for long-range extrapolation, computational budget, importance of absolute position versus relative), empirical benchmarks, and engineering constraints.

# How positional encodings interact with attention (additive vs multiplicative)

Positional information can be combined with token embeddings or attention computations in different ways. Two broad modalities are additive (or bias-based) interactions and multiplicative (or transform-based) interactions. The way positional signals enter attention affects how the model uses position information and has implications for expressivity, computational cost, and extrapolation.

Additive interactions
Additive methods insert positional information by adding vectors or scalars to embeddings, keys, values, or attention logits. The most common additive method is to add a positional vector to the token embedding at the input layer:
\[
\tilde{x}_i = x_i + e_i, \quad q_i = W_Q \tilde{x}_i, \; k_j = W_K \tilde{x}_j.
\]
Because the positional vector is added before linear projections, it influences all subsequent computations linearly. Another additive approach is to add a scalar bias in the attention logits:
\[
\text{score}_{ij} = q_i^\top k_j + b(j-i).
\]
Additive biases like $b(j-i)$ are simple and decouple content compatibility $q^\top k$ from position-dependent priors. They are cheap to compute and work well in practice (T5-style biases, ALiBi). Adding to keys or values (Shaw et al.) modifies the content vectors directly: $k'_j = k_j + a_{j-i}$, so the content of keys or values explicitly incorporates relative position. Additive methods are intuitive, relatively easy to implement, and can be combined with bucketing or clipping to scale.

Multiplicative interactions
Multiplicative methods inject position information by transforming queries and/or keys through position-dependent linear or orthogonal transforms. RoPE is a representative case: queries and keys are rotated in subspaces by position-dependent orthogonal matrices $R_p$, and the attention score uses the rotated dot product:
\[
\text{score}_{ij} = (R_i q_i)^\top (R_j k_j).
\]
Because rotations preserve norms, RoPE maintains certain geometric properties while making the dot product sensitive to relative offsets. Multiplicative transforms can enable more structured relative dependence: for example, if $R_i^\top R_j$ depends only on $j-i$, then the dot product becomes a function of the relative distance. Multiplicative approaches also include scaling queries by position-dependent gates or applying learned position-conditioned linear maps.

Differences in effect and interpretation
Additive and multiplicative interactions have different inductive biases. Additive biases are effectively shifts in the linear logits or embeddings; they allow the model to favor or disfavor certain positions independently of token content. Multiplicative interactions change the geometry of the embeddings based on position, which can enable richer dependence: the same token content can interact differently with other positions depending on where it appears, in ways that scale with content magnitude and direction.

From the viewpoint of Taylor series: additive changes are first-order perturbations that simply translate vectors; multiplicative changes can change angles and relative scales, enabling nontrivial changes to dot products that are not achievable by purely additive shifts of either queries or keys alone without modifying the other. Multiplicative methods can therefore be more expressive per parameter in some regimes.

Computational and stability considerations
Additive scalar biases (logit biases) are computationally cheapest: they require only adding a precomputed scalar to each attention score before softmax. Adding full vectors to keys/values or embeddings increases memory and compute, as does applying position-dependent linear maps in a multiplicative scheme. Multiplicative transforms like RoPE require applying rotations that are parameter-free but involve additional elementwise operations.

Regarding training stability, additive biases that are independent of content can sometimes dominate or interfere with content-based scores if not properly scaled. Multiplicative transforms that alter norms must be designed carefully to avoid introducing exploding or vanishing magnitudes. Practical implementations standardize and scale transforms (e.g., via learned head-wise scalings) to maintain stable gradients.

Compatibility with relative objectives
Multiplicative position encodings that yield dot products dependent only on relative offset provide a principled way to encode relative positions while preserving content-dependent interactions. Additive logit biases are simpler and effective when relative distance only needs to act as a prior (e.g., preferring nearby tokens) rather than encoding complex relative transformations of content.

In summary, additive methods are simple and efficient and often sufficient; multiplicative methods can be more expressive and support more principled relative dependence, but at somewhat higher implementation complexity and potential stability concerns. Hybrid schemes that combine additive biases with multiplicative rotations appear in several modern architectures.

# Evaluation considerations: extrapolation vs interpolation of position encodings

When evaluating positional encoding schemes, it is important to distinguish between interpolation and extrapolation and to design tests that reveal their strengths and weaknesses.

Interpolation versus extrapolation
Interpolation refers to model behavior on sequence lengths and position indexes that lie within the range seen during training (e.g., processing sequences of length up to $L$ when the training used varying lengths up to $L$). Extrapolation refers to performance on sequences longer than those used during training, i.e., when the model must handle position indexes $p > L_{\text{train}}$.

Learned absolute positional embeddings typically interpolate well: the model has seen each position separately and can learn position-specific behavior. But they usually struggle to extrapolate; the model has no notion of continuity or a parametric function of position beyond learned slots. Analytic encodings like sinusoidal or RoPE are designed with extrapolation in mind: the encoding is defined for any integer position, and relative or rotational structure can generalize to longer offsets. Relative bias methods like ALiBi explicitly provide a parameter-free extrapolation rule for distances.

Designing evaluation protocols
To evaluate positional encodings, one should include tasks that isolate different aspects of positional reasoning. Basic protocols include:

- Masked language modeling or next-token prediction on longer contexts than training: does the model benefit from extra context, and does perplexity improve or degrade as context length increases beyond training?
- Synthetic tasks with explicit dependence on position: tasks like copying a sequence with positional shifts, sorting based on position, or arithmetic on indices can reveal whether absolute or relative order is learned.
- Distance-sensitive tasks: tasks where attention needs to prioritize near tokens (e.g., local dependencies in language) versus tasks requiring long-range dependency capture (e.g., coreference across paragraphs).
- Ablations: compare models with no positional encoding, learned embeddings, sinusoidal encodings, RoPE, ALiBi, and combinations, using the same architecture and training regimen.

When testing extrapolation, measure not only aggregate metrics (e.g., perplexity) but also diagnostic measures such as attention distributions: does the model continue to focus on near tokens as context grows, or does attention become diffuse? For tasks with ground-truth alignments (e.g., copying), measure whether alignment quality persists beyond trained lengths.

Interpretation of results
Extrapolation success depends on more than the encoding alone: optimization, scaling, and model capacity all play a role. A sinusoidal encoding might enable extrapolation but only if the model can learn to use the analytic structure; if training never encourages the use of long-range components, performance may still degrade. Similarly, ALiBi can help models extrapolate by biasing attention toward nearby tokens with a simple rule, but if task semantics require complex long-range interactions, a linear bias alone may be insufficient.

Another subtlety is that some extrapolation failures are due to distributional shift: longer sequences change the token distribution and higher-level structures (e.g., topics, discourse), not just positions. Careful experimental design should separate failures due to positional generalization from those due to other distributional shifts.

Practical recommendations
For practitioners, the following guidelines help when choosing and evaluating positional encodings:

- If you must support arbitrarily long contexts and want robust extrapolation, prefer analytic or relative encodings designed for extrapolation (sinusoidal, RoPE, ALiBi, or relative-bias schemes).
- If your task only requires positions up to a known maximum and you want maximal expressivity, learned positional embeddings are a reasonable default.
- To emphasize relative distances rather than absolute positions, prefer relative encodings or bias methods (T5-style biases, Transformer-XL, RoPE).
- Use bucketing or clipping for long-distance relative encodings to control parameter counts, and tune bucket boundaries based on whether fine-grained differences matter at long ranges.
- Evaluate both interpolation and extrapolation systematically, using synthetic tasks and real-world datasets, and inspect attention patterns to diagnose failure modes.

# Conclusion

Positional encodings are a core component of Transformer models because the attention mechanism by itself is permutation-equivariant. Absolute encodings (learned or sinusoidal) provide position signals at the input level, while relative encodings introduce position dependence into attention scores or content vectors. Additive methods are simple and effective; multiplicative methods (e.g., rotations) provide more structured interactions that can yield principled relative dependence. Learned embeddings are flexible but limited in extrapolation; analytic encodings and carefully designed relative biases often generalize better to longer contexts. Choosing the right positional encoding involves trade-offs among expressivity, parameter cost, computational complexity, and generalization needs. When designing or evaluating systems, carefully test both interpolation and extrapolation performance, and consider combining techniques (for example, relative biases with RoPE) to get the desired behavior.

Introduction

The Transformer is a neural network architecture built almost entirely from attention mechanisms and simple feed-forward layers. At the heart of the Transformer is the attention operation, which allows the model to dynamically weight and aggregate information from different positions in a sequence. Understanding attention — how queries, keys, and values are constructed, how multiple attention heads work in parallel, how numerical scaling and softmax are applied, and how masking controls information flow — is essential to understanding the Transformer encoder/decoder layers and modern large language models (LLMs). This chapter explains these concepts in a connected way, with careful attention to the shapes and computations you will encounter in code and research papers.

# Self-attention: queries (Q), keys (K), values (V) and attention output

Self-attention is an operation that produces a representation of each position in a sequence by attending to all positions in that same sequence. The basic ingredients are three sets of vectors for each position: queries, keys, and values. Intuitively, a query asks "what information do I want right now?", while keys describe "what information does each position offer?" and values are the content that will be aggregated according to how well keys match the query.

Concretely, suppose you have a sequence of $T$ input vectors (for example, token embeddings, or the outputs of a previous layer) arranged into a matrix $X \in \mathbb{R}^{T \times d_{\text{model}}}$. Self-attention begins by producing three linear projections of $X$:
\[
Q = XW_Q,\qquad K = XW_K,\qquad V = XW_V,
\]
where $W_Q, W_K, W_V \in \mathbb{R}^{d_{\text{model}} \times d_k}$ (often $d_k$ is equal to $d_v$, but we will denote head key and value dimensionalities generically as $d_k$ and $d_v$). Here $Q, K \in \mathbb{R}^{T \times d_k}$ and $V \in \mathbb{R}^{T \times d_v}$.

For a single query vector $q_i$ (the $i$-th row of $Q$), we compute its compatibility with each key $k_j$ (the $j$-th row of $K$) by a similarity function. The most common choice is the dot product. The unnormalized attention score from position $i$ to position $j$ is
\[
\text{score}(i,j) = q_i \cdot k_j = q_i^\top k_j.
\]
Collecting all scores yields the score matrix $S = QK^\top \in \mathbb{R}^{T \times T}$, where $S_{ij}$ is how compatible position $i$'s query is with position $j$'s key.

These raw scores are converted into positive weights via a softmax (we will cover the exact axis later). The attention weights applied to the values produce the output at each position:
\[
\text{Attention}(Q,K,V) = \operatorname{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V.
\]
This produces an output matrix in $\mathbb{R}^{T \times d_v}$, where each output vector is a weighted sum of the rows of $V$, with weights determined by how well $q_i$ matched each $k_j$.

Several points are important to internalize. First, attention is content-dependent: different queries will attend to different keys, so representations can dynamically aggregate context. Second, self-attention is permutation-sensitive through positional encodings or other position-aware mechanisms (the raw dot product does not encode positions by itself). Third, the matrices $W_Q,W_K,W_V$ are learned weights, so the model learns how to form queries, keys, and values that are useful for the task.

# Multi-head attention: parallel heads and concatenation

Multi-head attention extends this idea by computing several independent attention "heads" in parallel and then combining their outputs. The motivation is that different heads can specialize to capture different kinds of relationships: one head might focus on short-range syntactic relations, another on long-range topical information, another on coreference, and so on.

Formally, if we use $H$ heads, we learn separate projection matrices for each head: for head $h$ we have
\[
Q^{(h)} = XW_Q^{(h)},\qquad K^{(h)} = XW_K^{(h)},\qquad V^{(h)} = XW_V^{(h)}.
\]
Each projection typically maps into a smaller subspace so that the total computational budget is comparable to a single-head attention with dimension $d_{\text{model}}$. A common design is to set each head dimension to $d_k = d_v = d_{\text{model}}/H$, so that concatenating $H$ heads returns to dimension $d_{\text{model}}$.

Each head computes its own attention:
\[
\text{head}_h = \operatorname{softmax}\!\left(\frac{Q^{(h)} {K^{(h)}}^\top}{\sqrt{d_k}}\right)V^{(h)} \quad\in\mathbb{R}^{T \times d_v}.
\]
After computing all $H$ heads, we concatenate their outputs along the feature dimension and apply a final linear projection:
\[
\text{MultiHead}(X) = \text{Concat}(\text{head}_1,\dots,\text{head}_H)W_O,
\]
where $\text{Concat}(\cdot)\in\mathbb{R}^{T \times (H d_v)}$ and $W_O \in \mathbb{R}^{(H d_v) \times d_{\text{model}}}$. If $d_v = d_k = d_{\text{model}}/H$ then the concatenated dimension is $d_{\text{model}}$, making $W_O$ a square $d_{\text{model}}\times d_{\text{model}}$ matrix in the common configuration.

Why multiple heads? There are a few practical and conceptual reasons. First, splitting features into multiple subspaces allows each head to focus on different subspaces of the representation space and thus capture multiple relationships simultaneously. Second, using smaller per-head dimensions keeps computational cost and parameter counts manageable while providing representational diversity. Finally, because each head forms its own set of similarity scores and weightings, the model can represent more complex, multi-faceted attention patterns than a single head could.

# Scaling and softmax application (row-wise softmax)

Two numerical details in the attention formula deserve close attention because they materially affect learning dynamics and the semantics of the weights: scaling by $\sqrt{d_k}$ and the axis of the softmax.

Scaling: The raw dot products $q_i^\top k_j$ grow in magnitude as the dimensionality of the vectors $d_k$ increases. If those dot products are too large in magnitude, the subsequent softmax will push probabilities close to the edges (very small or very large), leading to tiny gradients during learning (saturation). To counteract this effect, the Transformer paper divides the dot products by $\sqrt{d_k}$, producing
\[
S = \frac{QK^\top}{\sqrt{d_k}}.
\]
This scaling keeps the variance of the scaled dot products roughly constant with respect to $d_k$ under typical random-initialization assumptions, stabilizing gradients and training.

Softmax application and row-wise normalization: After scaling, we apply a softmax to convert scores into nonnegative weights that sum to 1. Importantly, the softmax is applied row-wise across keys for each query. Concretely, if $S \in \mathbb{R}^{T \times T}$, then for each query position $i$ we define
\[
A_{i,:} = \operatorname{softmax}(S_{i,:}) = \frac{\exp(S_{i,:})}{\sum_{j=1}^{T} \exp(S_{i,j})}.
\]
Thus $A_{i,j}$ is the attention weight from query position $i$ to key position $j$, and the weights across $j$ for a fixed $i$ sum to 1. The final output matrix is $A V$, where each row is a convex combination of the rows of $V$ with the corresponding row of $A$ as weights.

This row-wise softmax means attention is computed per output position: each output vector is a weighted sum over all value vectors, and the weights are specific to that output position. In many implementations that process batches, we compute softmax along the last axis corresponding to key positions.

Practical note on stability: In implementations, for numerical stability we often subtract the maximum score in each row before exponentiating:
\[
\operatorname{softmax}(s) = \frac{\exp(s - \max_j s_j)}{\sum_j \exp(s - \max_j s_j)}.
\]
When introducing masks (next section) we typically add a large negative number (like $-10^{9}$) to scores that should be ignored before applying softmax so that their normalized weight becomes effectively zero.

# Causal (autoregressive) masking vs. non-causal attention

Masking controls which key positions each query can attend to. There are two principal regimes in Transformer models, with different masks: non-causal (bidirectional) attention and causal (autoregressive) attention.

Non-causal (bidirectional) attention: In encoder stacks and in models that allow each position to see the whole sequence (for example, BERT-style models used for masked-language-model pretraining), attention is non-causal: each query is allowed to attend to all key positions. The mask in this case is typically all zeros (no positions masked), so attention weights are computed over all positions. This lets the representation for each position use information from both left and right contexts. Non-causal attention is appropriate when you want contextualized representations that can use future as well as past context and when you are not generating autoregressively.

Causal (autoregressive) masking: In decoder stacks and in autoregressive LLMs where the model must predict the next token given only previous tokens, attention must be causal: position $i$ may only attend to positions $\le i$. In practice, this is implemented by adding a mask matrix $M \in \{0,-\infty\}^{T\times T}$ to the scaled score matrix before the softmax:
\[
\tilde S_{ij} = \frac{q_i^\top k_j}{\sqrt{d_k}} + M_{ij},
\]
where $M_{ij} = 0$ if key position $j$ is allowed for query $i$, and $M_{ij} = -\infty$ (or a very large negative number) if it is disallowed. For causal masking, $M_{ij} = -\infty$ for $j>i$ so that after softmax, $A_{i,j} = 0$ for all $j>i$. This ensures that when computing the representation or prediction for position $i$, information from future positions cannot leak in.

Which mask to use depends on task: encoder-only or masked-language-modeling objectives use non-causal attention for full-context representations; decoder-only autoregressive LLMs use causal masking so generation is left-to-right consistent. There are also encoder-decoder models (original Transformer for translation) where the encoder uses non-causal attention and the decoder uses both causal self-attention (so the decoder cannot see future positions of the target sequence) and encoder-decoder cross-attention where decoder queries attend to encoder keys/values (and these cross-attention computations are usually non-causal since the encoder produced the whole source sequence).

# Computation graph and where attention sits in Transformer blocks

The attention mechanism is a module inside a Transformer block. A full Transformer layer combines attention with residual connections, layer normalization (or pre-norm variants), and a position-wise feed-forward network. There are two canonical block forms in the original Transformer: encoder blocks and decoder blocks.

Encoder block (one layer): The standard encoder layer contains a self-attention sublayer followed by a feed-forward sublayer, each wrapped by residual connections and layer normalization. Using the "post-norm" notation from the original paper, the computations are:
\[
\begin{aligned}
\text{SA\_out} &= \operatorname{MultiHead}(X), \\
X' &= \operatorname{LayerNorm}(X + \text{SA\_out}), \\
\text{FF\_out} &= \operatorname{FFN}(X'), \\
X_{\text{next}} &= \operatorname{LayerNorm}(X' + \text{FF\_out}).
\end{aligned}
\]
Here $\operatorname{FFN}$ is a two-layer position-wise feed-forward network applied independently at each position: usually $\operatorname{FFN}(x) = \max(0,xW_1 + b_1)W_2 + b_2$ (ReLU or GELU nonlinearity) with an inner dimension larger than $d_{\text{model}}$.

Decoder block (one layer): The decoder layer contains three sublayers in sequence: causal self-attention, encoder-decoder cross-attention, and the feed-forward network. Each sublayer has its own residual connection and layer norm:
\[
\begin{aligned}
\text{CausalSA\_out} &= \operatorname{MultiHead}_{\text{causal}}(Y), \\
Y' &= \operatorname{LayerNorm}(Y + \text{CausalSA\_out}), \\
\text{CrossAtt\_out} &= \operatorname{MultiHead}_{\text{cross}}(Y', \, K_{\text{enc}}, \, V_{\text{enc}}), \\
Y'' &= \operatorname{LayerNorm}(Y' + \text{CrossAtt\_out}), \\
\text{FF\_out} &= \operatorname{FFN}(Y''), \\
Y_{\text{next}} &= \operatorname{LayerNorm}(Y'' + \text{FF\_out}).
\end{aligned}
\]
In the cross-attention step, queries come from the decoder (the target-side representations), while keys and values come from the encoder outputs ($K_{\text{enc}},V_{\text{enc}}$). Cross-attention is typically non-causal with respect to source tokens.

Placement in computation graph: In the overall Transformer (stacking multiple layers), attention modules appear at each layer, allowing interactions between positions at every depth. The residual connections mean that the gradient flows both through the attention sublayer and directly from the output to the input, easing optimization. In pre-norm variants, the layer norm is applied before attention and feed-forward sublayers; both formulations are used in practice and affect stability and performance.

During autoregressive generation with causal masking, another important computation-graph consideration is caching: when generating token by token, key and value projections for previously generated tokens can be cached so that we do not recompute them every step. This changes the computation graph during inference: each new step computes the new query and its scores versus cached keys, rather than recomputing all keys and values for the whole sequence.

# Practical dimensions: batch, sequence length, head dimension, hidden dimension

Understanding the tensor shapes that flow through attention is critical for implementing and debugging models and for reasoning about computational and memory cost.

Typical symbols and meanings:
- $B$: batch size (number of sequences processed in parallel).
- $T$: sequence length (number of tokens per sequence; may vary and be padded).
- $H$: number of attention heads.
- $d_{\text{model}}$: hidden dimension of the model (also called model width).
- $d_k$: dimensionality of keys and queries for each head (often $d_k = d_{\text{model}}/H$).
- $d_v$: dimensionality of values for each head (often $d_v = d_{\text{model}}/H$).

A standard pipeline in code uses batched tensors. The input embedding tensor typically has shape $(B, T, d_{\text{model}})$. The per-head linear projections can be computed with a single linear layer that maps $d_{\text{model}}$ to $H \times d_k$ and is then reshaped. Concretely, one common pattern is:

1. Compute combined projections: Let $W_Q^{\text{all}} \in \mathbb{R}^{d_{\text{model}} \times (H d_k)}$. Then
\[
Q_{\text{flat}} = X W_Q^{\text{all}} \in \mathbb{R}^{B \times T \times (H d_k)}.
\]
2. Reshape into heads: reshape $Q_{\text{flat}}$ to $Q \in \mathbb{R}^{B \times H \times T \times d_k}$. Similarly for $K$ and $V$.

3. Compute attention scores per head: for each head, compute the scaled dot-product along the sequence length dimension. Implemented with batched matmuls:
\[
S \in \mathbb{R}^{B \times H \times T \times T},\qquad S_{b,h,i,j} = \frac{Q_{b,h,i,:} \cdot K_{b,h,j,:}}{\sqrt{d_k}}.
\]
4. Apply mask and softmax along the last axis (the key index $j$), producing attention weights $A \in \mathbb{R}^{B \times H \times T \times T}$.

5. Weight the values: perform batched matmul $A V$ per head to obtain outputs $\text{head\_out} \in \mathbb{R}^{B \times H \times T \times d_v}$.

6. Concatenate heads: reshape to $(B, T, H d_v)$ and apply the output matrix $W_O$ to produce $(B, T, d_{\text{model}})$.

Memory and compute costs: The dominant cost is forming the score tensor $S$ which is size $B \times H \times T \times T$, and the matrix multiplications that involve $T\times T$ work. Thus both compute and memory scale as $O(B H T^2 d_k)$ or, substituting typical equalities $d_k = d_v = d_{\text{model}}/H$, $O(B T^2 d_{\text{model}})$. This quadratic dependence on sequence length $T$ is important: doubling $T$ increases time and memory roughly fourfold for these attention computations, which motivates many efficient-attention approximations when $T$ is very large.

Examples of common dimensions: in many transformer models $d_{\text{model}}$ is 512, 768, 1024 or larger. For $d_{\text{model}}=768$ and $H=12$, each head has $d_k = 64$. For $d_{\text{model}}=1024$ and $H=16$, each head has $d_k = 64$ as well. The inner dimension of the FFN is often $d_{\text{ff}}=4 d_{\text{model}}$ (e.g., 3072 for $d_{\text{model}}=768$). Batch sizes $B$ and sequence lengths $T$ are chosen according to hardware and task needs; during pretraining, $T$ may be 1024 or 2048 or larger, while during inference for LLMs $T$ is often limited by memory constraints.

# Putting it together for large language models

Large language models are typically decoder-only stacks of many Transformer layers operating autoregressively, with causal masking enforced in all self-attention sublayers. At each generation step during training, the model is typically fed an entire sequence and trained to predict the next token at each position; causal masking ensures each prediction only uses leftward context. During inference, token-by-token generation uses caching of projected keys/values to avoid recomputing past values; mathematically the same attention equations apply but the computation graph and batching differ.

In practice, engineers and researchers must pay attention to the precise tensor shapes, the placement of layer norms (pre-norm vs post-norm), caching strategies for inference, numerical stability (scaling and stable softmax), and masking semantics (e.g., padding masks to ignore padding tokens, causal masks for autoregression, and attention masks for sparsity patterns). Multi-head attention gives expressive capacity while keeping the per-head computation small; scale and softmax choices ensure stable training; masks enforce the directional constraints required by the task; and the integration into the Transformer block with residuals and feed-forward networks yields deep, trainable stacks.

Summary

This chapter covered the mechanics and intuition behind self-attention and multi-head attention, the reason for scaling and the row-wise softmax, the role and implementation of causal versus non-causal masks, where attention sits inside Transformer encoder and decoder blocks, and the practical tensor dimensions you will encounter when implementing or reading about these models. With these concepts and the dimension-aware view of the computations, you should be able to read Transformer-based papers with clarity and implement attention modules in modern deep-learning frameworks.

Introduction

In policy-gradient reinforcement learning, the learner updates a stochastic policy by estimating the gradient of expected return with respect to policy parameters. A central element in these updates is the advantage function, which measures how much better an action turned out relative to some baseline expectation. Properly computing and scaling advantages is crucial: it reduces variance, avoids systematic bias, and keeps the magnitude of policy gradients in a numerically stable range. This chapter explains what advantages are, how to construct baselines using value function learning and bootstrapping, how to use Monte Carlo and per-batch baselines, and how group (within-query) normalization operates when value models are not available. We compare learned value models and sample-based normalization, and describe how the scale of advantages affects training stability. Throughout, the focus is on intuition, practical algorithms, and the tradeoffs that arise in research and implementation.

# Definition of advantage A = return − baseline

The advantage quantifies how much better an observed action was compared to the expected outcome under some baseline. If we denote the return (discounted cumulative reward) observed from time step $t$ in a trajectory as $G_t$, and denote the baseline as $b_t$ (which may depend on state or other context), then the empirical advantage is defined as
$A_t = G_t - b_t$.
When used in a policy gradient estimator, advantages weight the log-probability gradients so that actions that produced higher-than-expected returns push the policy to increase their probability, and actions that produced worse-than-expected returns push the policy to decrease their probability.

Intuitively, the return $G_t$ is noisy because it depends on stochastic transitions and rewards that follow the action. Subtracting a baseline $b_t$ removes component(s) of that noise that are independent of the chosen action. Provided $b_t$ does not depend on the action at time $t$, the resulting policy gradient estimator remains unbiased: subtracting any action-independent baseline does not change the expected value of the gradient, only its variance. This variance reduction often yields much more sample-efficient and stable learning.

There are several common choices for the baseline. A constant (per-experiment) baseline is the simplest: $b_t = c$ for all $t$, typically chosen as a running average of returns. A state-dependent baseline uses an estimate of the value function $V^\pi(s_t)$, the expected return from state $s_t$ under the current policy. More elaborate baselines can include learned models or per-batch statistics; the precise choice affects the bias-variance tradeoff, which we examine in later sections.

# Value function learning and bootstrapping

A standard and powerful baseline is the state-value function $V^\pi(s)$, defined as the expected return when following policy $\pi$ from state $s$:
$V^\pi(s) = \mathbb{E}_\pi\left[ G_t \mid s_t = s \right]$,
with $G_t = \sum_{k=0}^{\infty} \gamma^k r_{t+k}$ for discount factor $\gamma\in[0,1)$. Learning an approximation $\hat V_\phi(s)$ parameterized by $\phi$ provides a learned, state-dependent baseline $b_t = \hat V_\phi(s_t)$ which can substantially reduce variance compared to simpler baselines.

There are two broad approaches to learning $\hat V_\phi$: Monte Carlo regression and bootstrapped temporal-difference (TD) learning. In Monte Carlo regression, we collect complete (or truncated) trajectories and use observed returns $G_t$ as regression targets, minimizing squared error
$\mathcal{L}(\phi) = \mathbb{E}\big[(\hat V_\phi(s_t) - G_t)^2\big]$.
This approach produces unbiased regression targets but can have high variance because $G_t$ itself is noisy. Monte Carlo is attractive when episodic returns are short or when variance is acceptable.

Bootstrapping (TD learning) reduces variance by using the current value estimates as part of the target. The simplest example is one-step TD(0) regression, which uses the target $r_t + \gamma \hat V_\phi(s_{t+1})$. More generally, n-step returns or generalized advantage estimation (GAE) mix multi-step returns with bootstrapping:
$\hat A_t^{\rm GAE(\lambda)} = \sum_{l=0}^{\infty} (\gamma\lambda)^l \delta_{t+l}$,
where $\delta_t = r_t + \gamma \hat V_\phi(s_{t+1}) - \hat V_\phi(s_t)$ and $\lambda \in [0,1]$ trades bias for variance. Bootstrapping introduces bias because the target depends on the current value estimate, but it typically reduces variance and improves sample efficiency, especially when combined with appropriate regularization and stable optimization.

Learning a value function also requires its own optimizer and sample management. In actor-critic algorithms, the value network (critic) is trained alongside the policy (actor) using samples the actor collects. Careful coordination is necessary: if the value function lags or overfits, it can produce poor baselines that either under-reduce variance or introduce harmful bias into advantage estimates. Techniques to stabilize learning include replay buffers, target networks, separate learning rates for actor and critic, and training the value network on bootstrapped multi-step targets rather than raw returns.

# Monte Carlo baselines and per-batch normalization

When a learned value function is not available, or when one prefers simplicity, Monte Carlo baselines computed per batch are a common alternative. In its simplest form, for a batch of trajectories collected under the current policy, each sample return $G_t$ is computed (possibly truncated or discounted). A per-batch baseline can then be the average return across relevant samples in the batch:
$\bar G = \frac{1}{N}\sum_{i=1}^N G_i$,
and advantages are computed as $A_i = G_i - \bar G$. This baseline removes the global mean return in that batch, which reduces variance coming from fluctuations in overall return level.

Per-batch normalization can be extended beyond subtracting the mean. A common practice is to standardize returns within the batch by subtracting the mean and dividing by the standard deviation:
$\tilde A_i = \frac{G_i - \bar G}{\sqrt{\frac{1}{N}\sum_{i}(G_i-\bar G)^2 + \epsilon}}$,
where $\epsilon$ is a small constant for numerical stability. Standardization rescales advantages to have unit variance within the batch. This normalization commonly appears in implementations as dividing advantages by their batch-wise standard deviation before applying the policy update. The effect is both variance stabilization and implicit learning-rate normalization: large advantage magnitudes do not produce excessively large gradient steps, and small magnitudes are amplified to maintain meaningful updates.

Monte Carlo baselines and per-batch normalization are simple to implement and can be effective in many settings, especially in episodic tasks where full returns are available and the variance of returns is not excessive. However, Monte Carlo baselines can be sensitive to batch composition, episode length variability, and correlation structure in the data. When returns are heavy-tailed or when the batch contains heterogeneous contexts, subtracting a single global mean may fail to remove important sources of variance.

# Group (within-query) advantage normalization: mean/std standardization

Group normalization, often referred to in RL as within-query or per-group advantage normalization, refines per-batch normalization by computing normalization statistics over groups of samples that share a common context. A common scenario is batch data that consists of multiple queries or episodes, each producing several candidate actions or trajectories. For example, in bandit-style policy learning or retrieval-based RL, each query $q$ yields several candidate actions with associated returns. Aggregating statistics across the whole batch ignores intra-query structure that can dominate variance; group normalization computes mean and standard deviation for each query separately, then normalizes advantages within each group.

Formally, suppose the batch contains $M$ groups, and group $m$ has $n_m$ samples with returns $\{G_{m,i}\}_{i=1}^{n_m}$. The group mean and standard deviation are
$\bar G_m = \frac{1}{n_m}\sum_{i=1}^{n_m} G_{m,i}$,
$\sigma_m = \sqrt{\frac{1}{n_m}\sum_{i=1}^{n_m} (G_{m,i}-\bar G_m)^2 + \epsilon}$.
Group-normalized advantages are then
$\tilde A_{m,i} = \frac{G_{m,i} - \bar G_m}{\sigma_m}$.
If a learned baseline is available, one can subtract the learned baseline first and then normalize the residuals within each group. Alternatively, one can forgo a learned baseline and compute raw returns, normalizing purely within-group.

The key intuition is that within a single query, the baseline that matters for comparing candidate actions is the expected return conditional on that query. If between-query variability (for example, due to different contexts or episode lengths) is large relative to within-query action differences, a global baseline will leave most variance intact and drown out useful signal. Per-group normalization isolates the contrast among the candidates for each query, which often aligns well with objective formulations where only relative rankings within queries matter.

Group normalization has statistical effects that must be recognized. Within-group standardization enforces zero mean and unit variance per group, which removes not only nuisance variability but also any absolute scale or bias information about returns that might be meaningful for the policy. It can therefore change the effective optimization objective: policies become optimized to prefer actions that are better within their group rather than to maximize absolute returns across all contexts. This behavior suits problems like learning-to-rank or some conditional selection tasks, but it may be inappropriate when absolute performance across contexts matters.

# Pros and cons of learned value models vs sample normalization

Choosing between learned value models and sample-based normalization involves several tradeoffs in bias, variance, computational cost, and suitability to problem structure.

Learned value models bring the advantage of state-dependent baselines that, in principle, yield better variance reduction than crude sample statistics. A well-trained value function captures systematic dependencies of returns on state or context and subtracting it leads to advantages that focus on action-specific effects. This can produce more accurate gradient directions, faster convergence, and improved sample efficiency. Moreover, value models support bootstrapping, n-step returns, and techniques like generalized advantage estimation (GAE) that smoothly trade off bias and variance. They also generalize across data: a learned value can provide sensible baselines for states that were not present in the current mini-batch.

However, learned values introduce complexity. They require additional model capacity, tuning of hyperparameters (learning rate, architecture, regularization), and careful coordination with policy updates. A poorly fit value function can produce biased advantage estimates, particularly if bootstrapping is used aggressively or if the value update and policy updates interfere (e.g., stale value estimates used to compute targets). Value networks are also vulnerable to overfitting if batches are small or non-representative, and they add computational cost that can be significant in large-scale systems.

Sample normalization methods—per-batch mean subtraction, batch standardization, or group normalization—are straightforward, computationally cheap, and often robust. They do not require training an extra model, so they avoid the pitfalls of value learning. Per-group normalization, in particular, can be very effective in settings where comparisons are inherently contextual (e.g., scoring candidate responses to a single query). Because these methods operate only on observed returns, they are unbiased with respect to the empirical returns and do not introduce bootstrapping bias.

The downside of sample normalization is that it cannot exploit structure beyond what is present in the batch. Per-batch or per-group statistics may be poor estimates if the batch is small or if the data are heteroskedastic. Standardization removes absolute scale, which may be undesirable in tasks where absolute returns should influence learning. Sample normalization also provides no generalization: if some states are rarely seen, their baselines cannot be estimated beyond the limited samples in those batches. Finally, per-batch normalization can introduce subtle instabilities in optimization when batch composition changes dramatically between updates, leading to non-stationary gradient scales.

A practical middle ground is often used: learn a value function when ample data and computational budget exist, but augment or stabilize learning with sample normalization (for example, normalizing the residual advantages after subtracting a learned baseline). Empirically, this combination often gives the benefits of both approaches: the value model captures long-term structure while normalization prevents extreme gradient steps due to outliers or changing batch statistics.

# Impact of advantage scaling on training stability

The magnitude and distribution of advantages directly affect the size of policy gradient updates because the gradient estimator scales with advantage values. If advantages have very large magnitudes, gradient steps can be excessively large, causing the policy to take abrupt, unstable updates that hurt exploration and overshoot optima. Conversely, if advantages are extremely small, updates may be negligible, slowing learning or stalling optimization. Thus, controlling advantage scale is essential for stable training.

Standardizing advantages to zero mean and unit variance is a common remedy. By dividing by the sample standard deviation (computed at the batch or group level), the algorithm effectively normalizes the natural learning rate: the same learning rate will produce similar update magnitudes across training steps and experimental runs. This reduces sensitivity to reward scaling and helps maintain balanced exploration–exploitation dynamics. It also interacts nicely with optimization techniques like trust-region constraints or KL penalties: when advantage magnitudes are stable, constraints on policy change are more predictable.

However, indiscriminate scaling has caveats. Standardizing within small batches can amplify noise: if the batch contains only a few samples or a group has nearly equal returns, dividing by a small standard deviation can inflate tiny differences into large gradient steps. To mitigate this, practitioners add a small $\epsilon$ to the denominator, clip normalization factors, or compute running estimates of variance across multiple batches rather than per-mini-batch instantaneous values. Another safe practice is to clip normalized advantages to a bounded range (e.g., $[-c, c]$) to prevent rare outliers from dominating the gradient.

Scaling also affects the effective bias–variance tradeoff. For instance, standardizing advantages after subtracting a learned baseline changes the relative weighting between samples; samples that are extreme relative to the batch will be down- or up-weighted depending on the normalization. In algorithms like PPO where the policy update is constrained by a clipped objective or KL penalty, advantage scaling interacts with these constraints: reducing advantage variance can make the objective flatter and make the clipping less active, while increasing variance can cause more clipping and potentially reduce the effective step size. Thus hyperparameters like learning rate, clipping thresholds, and KL-targets should be tuned in concert with the chosen normalization scheme.

In practice, robust training often employs a combination of techniques: subtract a baseline (learned value if feasible), compute advantage estimates using GAE or n-step returns to moderate variance, standardize advantages using running statistics or per-group normalization, and clip or rescale normalized advantages to bound extremes. Monitoring metrics such as the mean and variance of advantages, policy KL divergence between updates, and learning curves helps detect instability early and guide adjustments. Finally, experiments should test sensitivity to these design choices, because the best combination depends on problem structure, reward scale, batch size, and available computation.

Summary and recommendations

Advantages are the core scalar signals that guide policy updates. Subtracting a baseline reduces variance without introducing bias if the baseline is action-independent. Learned value functions enable state-dependent baselines and techniques like bootstrapping and GAE that balance bias and variance, but they require careful tuning and add complexity. Monte Carlo and per-batch baselines are simple and unbiased for observed returns, and group (within-query) normalization is particularly effective when comparisons are inherently contextual. Scaling of advantages—through mean subtraction and variance normalization—strongly affects training stability and must be applied with attention to batch sizes and potential amplification of noise. Combining learned value models with sensible normalization (e.g., normalizing residuals per batch or per group) is often the most practical approach for robust, sample-efficient policy learning.

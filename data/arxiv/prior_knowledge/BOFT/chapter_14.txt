Introduction

Modern deep learning systems are built from modular building blocks, and much of their flexibility comes from linear transformations (matrix multiplications) combined with simple nonlinearities. When working with very large pretrained models, understanding where those linear transforms sit and how to modify them efficiently is crucial for successful finetuning in production settings. This chapter surveys practical architectures — the transformer family, vision models, and diffusion-based text-to-image models — and then moves from architectural insight to concrete engineering techniques for finetuning large models: where to inject parameter-efficient modules, how to manage memory and numerical precision, how to set up data pipelines and batching, and how to evaluate finetuned models robustly. The goal is to give you the intuition and the practical checklist you need to read research papers in this area and run real-world finetuning jobs.

# Transformer architecture: attention, feed-forward layers, layer normalization

The transformer is the basic unit for contemporary large language models and many cross-modal systems. A transformer layer consists of two principal sublayers: a multi-head self-attention mechanism and a positionwise feed-forward network (FFN), with layer normalization and residual connections around each sublayer. Let the input to a single transformer layer be a sequence of token representations arranged as a matrix $X \in \mathbb{R}^{T \times d}$, where $T$ is the sequence length and $d$ the hidden dimension.

Multi-head attention first computes linear projections of $X$ to obtain queries $Q = XW_Q$, keys $K = XW_K$, and values $V = XW_V$ with weight matrices $W_Q, W_K, W_V \in \mathbb{R}^{d \times d}$. For one attention head of dimension $d_h$ (where typically $d = h \cdot d_h$ for $h$ heads), the scaled dot-product attention is
\[
\operatorname{Attention}(Q,K,V) = \operatorname{softmax}\!\left(\frac{Q K^\top}{\sqrt{d_h}}\right) V.
\]
Multiple heads allow the model to learn different similarity patterns in parallel. The outputs of the heads are concatenated and projected again with an output matrix $W_O \in \mathbb{R}^{d \times d}$. Crucially, all of these are linear transformations; the representational specificity of attention arises from the content-dependent softmax weights that modulate how these linear projections interact.

The feed-forward network is applied positionwise and is typically a two-layer MLP with a nonlinearity. Using one common form,
\[
\operatorname{FFN}(x) = W_2 \, \phi(W_1 x + b_1) + b_2,
\]
where $W_1 \in \mathbb{R}^{d_{ff} \times d}$, $W_2 \in \mathbb{R}^{d \times d_{ff}}$, and $\phi$ is an activation such as GELU. The FFN expands the dimensionality to $d_{ff}$ (often $4\times$ or more relative to $d$) before projecting back down. These two linear layers inside the FFN are responsible for much of the model capacity and contain a large fraction of parameters.

Normalization and residual structure stabilize training. Transformer variants put layer normalization either before ("pre-norm") or after ("post-norm") each sublayer. For pre-norm, the typical computation for a layer is
\[
Y = X + \operatorname{Attention}(\operatorname{LayerNorm}(X)),\qquad
Z = Y + \operatorname{FFN}(\operatorname{LayerNorm}(Y)).
\]
Layer normalization computes statistics across the feature dimension, normalizing each token independently to have mean zero and unit variance, then applying learned affine scaling and bias vectors. LayerNorm itself contains small linear parameters (scale and bias) but is primarily a normalization operation.

Because so much of the transformer's computation is linear transforms (projections in attention, the two linear layers in the FFN, the output projection after attention), these are the natural points to modify when finetuning, either by updating weights or by inserting parameter-efficient adapters.

# Vision transformer and convolutional backbones: linear layers characteristics

Vision models come in two dominant flavors: convolutional backbones (ResNets, EfficientNets, ConvNeXts) and vision transformers (ViT). Understanding where linear operations appear in each helps you choose finetuning strategies.

A vision transformer (ViT) first splits an image into non-overlapping patches of size $p \times p$, flattens each patch into a vector of length $p^2 \cdot C$ (with $C$ channels), and linearly projects the flattened patch into the model's embedding dimension $d$ with a patch embedding matrix $E \in \mathbb{R}^{d \times (p^2 C)}$. In other words, a $p \times p$ patch is turned into a token via a single linear layer. After that, a standard transformer encoder stack (self-attention + FFN layers) processes the token sequence. The final classification token or pooled representation goes through a small head (usually another linear layer) to make predictions. Thus in ViT, linear layers appear in the patch embedding, every attention projection ($W_Q, W_K, W_V, W_O$), FFN layers ($W_1, W_2$), and classification head.

Convolutional backbones organize computation differently but still use linear operators extensively. Convolution itself is a linear operator parameterized by a kernel $K \in \mathbb{R}^{k_h \times k_w \times C_{in} \times C_{out}}$. A $1 \times 1$ convolution is mathematically equivalent to a per-pixel linear projection across channels, i.e., a matrix multiplication between a vector of $C_{in}$ channel activations and a $C_{out}\times C_{in}$ weight matrix. Higher-kernel convolutions are structured linear maps with tied parameters and receptive field locality. Modern convnets also use channel-wise fully connected layers implemented as $1 \times 1$ convs in bottlenecks and in classification heads you usually see a final global pooling followed by a linear projection.

From a finetuning perspective, both architectures expose plentiful linear parameters: the embeddings and final heads are natural places to adapt for domain shifts or new tasks; the per-layer linear projections in ViT and the $1\times 1$ convolutions and fully connected layers in convnets are the places where representational changes are effected. Because ViT explicitly uses large dense linear layers for patch embedding and attention, parameter-efficient methods that modify or augment those linear maps (for example adding low-rank updates) translate naturally. In convnets, the structured nature of convolutional weights may suggest different parameterizations (e.g., low-rank factorization across channels, depthwise separable decompositions), but at a conceptual level the same linear modification ideas apply.

# Text-to-image diffusion models: basic pipeline and where linear transforms appear

Text-to-image diffusion models have become a dominant approach to generative image synthesis. A canonical pipeline works in three stages: encode the text prompt into a conditioning vector (typically via a text encoder like a transformer), run a diffusion denoising model conditioned on that text to produce a latent image representation, and decode the latent into pixels via a decoder (often a diffusion decoder or an autoencoder decoder). The core denoising model is usually a U-Net architecture with attention and convolutions; diffusion operates by iteratively denoising Gaussian noise to yield an image. Linear transforms appear at several points in this pipeline.

The text encoder (e.g., a transformer) produces embeddings for tokens and a pooled text conditioning vector. All of the usual transformer linear projections (embeddings, attention projections, FFN) are present here. The U-Net uses convolutional downsampling and upsampling blocks interleaved with residual blocks; modern designs insert cross-attention layers that condition the visual features on text embeddings. In these cross-attention modules, visual feature maps are projected into queries via convolutions or linear projections, and the text embeddings are projected to keys/values via linear layers; attention between spatial positions and text tokens is computed, after which results are projected back into the visual feature space. Thus attention-related linear transforms (query/key/value/output projections) show up inside the U-Net’s attention blocks.

Further linear components appear in time/step embeddings and conditioning mechanisms. The diffusion timestep $t$ is encoded into a vector (via a sinusoidal embedding followed by one or two linear layers or an MLP) that modulates residual blocks in the U-Net via FiLM-style affine transforms or additive biases. Where the denoiser outputs an image prediction (or noise residual), a final convolutional layer or projection maps the U-Net features to the pixel (or latent) channels.

If the pipeline uses a variational autoencoder (VAE) or another latent codec, then the encoder and decoder are themselves convolutional networks with their own linear projections and latent-to-pixel linear heads. In sum, linear transforms appear in the text encoder, in query/key/value/output projections inside cross-attention and self-attention in the U-Net, in the MLPs of residual blocks, in timestep embedding MLPs, and in final projection layers. When finetuning text-to-image models, you must decide which of these components to update: the text encoder, the cross-attention projections, the U-Net FFNs, or the final decoder — and each choice has different cost-benefit trade-offs in memory, compute, and impact on generation quality.

# Where to apply parameter-efficient modules in large models (which layers, shared vs per-layer)

Finetuning an entire language or multimodal model is increasingly expensive, so parameter-efficient finetuning (PEFT) methods aim to achieve task adaptation by updating a small number of additional parameters while keeping the large pretrained weights frozen. Common PEFT approaches include adapters, LoRA (low-rank adapters), prefix-tuning, and prompt-tuning. Choosing where to place these modules — and whether to share them across layers — is both an empirical and practical decision.

Adapters are small bottleneck MLPs inserted inside each transformer layer (usually between the residual connection and the layer normalization or inside the FFN). An adapter typically takes the form
\[
\operatorname{Adapter}(x) = x + W_{\text{up}} \, \phi(W_{\text{down}} x),
\]
with a small hidden dimension. Inserting adapters into the FFN or after attention provides a local, per-layer capacity to learn task-specific transformations. Because adapters are applied per-layer, they can capture layer-wise adaptations but at the cost of one adapter per layer. If memory is tight, adapters can be shared across multiple layers by reusing the same adapter weights; sharing reduces parameter count but also reduces expressivity: when adapters must represent layer-specific corrections (e.g., low-level vs high-level features), sharing may hurt performance.

LoRA injects low-rank updates into existing linear projectors. For a pretrained weight $W \in \mathbb{R}^{d \times k}$ (for example $W_Q$ or $W_1$ in an FFN), LoRA parameterizes an additive update as
\[
\Delta W = A B,
\]
with $A \in \mathbb{R}^{d \times r}$ and $B \in \mathbb{R}^{r \times k}$, where $r \ll \min(d,k)$. During finetuning, only $A$ and $B$ are trained; at inference time one can merge $\Delta W$ into $W$ if desired. LoRA is particularly attractive for attention projections: adding low-rank adjustments to $W_Q, W_K, W_V, W_O$ or to the output of the attention module can capture new alignment patterns without touching the full matrix. LoRA can be applied per projection per layer, or one can share low-rank factors across heads or across layers to reduce parameters further.

Prefix-tuning and prompt-tuning append trainable vectors to the input token sequence (or to key/value sequences in attention). These are most effective at the top few layers where global control over generation is required. Prefix vectors are cheap because they are only a small set of embeddings, but they may be less effective at changing low-level representations.

Which layers to modify depends on the nature of the task. For classification transfer that relies on high-level features, modifying later layers or the final head is often sufficient. For domain shifts that affect lower-level representations (e.g., speech to medical text), adapting earlier layers or patch embeddings may be necessary. For diffusion models where conditioning is mediated by cross-attention, placing PEFT modules in the cross-attention projections (keys/values mapping from text, or query projections on visual features) can have outsized effects while keeping the rest frozen.

Shared versus per-layer modules trades off parameter budget and specificity. If tasks require layer-specific corrections (different semantic granularity at different depths), per-layer adapters/LoRA will usually outperform shared modules. If compute and storage are extremely limited (e.g., multiple small tasks across many users), sharing and low-rank parameterization are attractive. Most research-grade finetuning pipelines allow easy toggling between per-layer and shared setups to explore this trade-off quickly.

# Checkpointing, mixed precision, and memory-saving techniques

Finetuning large models requires careful memory management. Several complementary techniques are commonly used: activation checkpointing (rematerialization), mixed precision (FP16 or BF16), ZeRO-style optimizer partitioning, gradient accumulation, quantization, and pruning. These techniques can be combined.

Activation checkpointing saves memory by not storing intermediate activations for every layer during the forward pass. Instead, selected activations are checkpointed, and the missing intermediates are recomputed during the backward pass. If the forward computation cost for the recomputed sections is $C$ and the saved memory is $M$, activation checkpointing trades extra compute for reduced memory footprint. Rematerialization is usually applied at block granularity (e.g., between transformer layers) and can turn an otherwise impossible finetuning job into a feasible one with only a modest compute overhead.

Mixed precision training uses lower-precision arithmetic for activations and gradients. FP16 reduces memory per tensor by half compared to FP32; BF16 provides the same memory savings with better dynamic range behavior on some accelerators. Frameworks expose automatic mixed precision (AMP) mechanisms that keep a master copy of parameters in higher precision (a "FP32 master") while performing most compute in FP16/BF16. When training with FP16, dynamic loss scaling prevents underflow by scaling the loss to keep gradients within representable range, and then unscaling before applying updates.

ZeRO (Zero Redundancy Optimizer) techniques split optimizer states, gradients, and model parameters across data-parallel workers. ZeRO stage 1 shards optimizer states, stage 2 shards gradients, and stage 3 shards parameters themselves so that each GPU holds only a slice of the full model. Combined with activation checkpointing and mixed precision, ZeRO allows finetuning models with hundreds of billions of parameters across clusters with limited per-GPU memory.

Gradient accumulation simulates larger batch sizes without requiring the corresponding memory: you perform forward/backward passes over micro-batches while deferring optimizer steps until the desired accumulation count is reached. Accumulation reduces per-step memory and is often used with mixed precision and ZeRO.

Quantization reduces parameter precision (e.g., 8-bit or 4-bit weights). Recent quantization-aware training or quantization-aware finetuning strategies maintain performance while storing parameters in quantized form; for inference, quantized weights yield large memory and compute efficiency. Pruning removes weights or channels with small importance, but effective pruning typically requires iterative retraining or fine-tuning and careful validation.

Finally, smart I/O and memory overlap matter. Prefetching checkpoints and streaming parameters, overlapping communication and compute in distributed setups, and using dedicated memory pools for temporary tensors can reduce runtime overhead. Modern libraries (DeepSpeed, FairScale, Hugging Face Accelerate) provide implementations of many of these techniques so practitioners can combine them without building everything from scratch.

# Batching, data pipelines, and dataset considerations for finetuning

Efficient finetuning depends heavily on how you feed data to the model. Batching strategies, tokenization and augmentation choices, data sharding, and epoch management all affect convergence, stability, and I/O throughput.

Batching is constrained by memory and sequence length. For transformers, the product of batch size and sequence length determines activation memory. Common strategies include fixed-size batching (pad to the maximum length in a batch) with bucketing to group examples of similar length together, which reduces wasted padding. Dynamic padding plus bucketing or packing multiple short sequences into a single example can massively improve throughput. In vision tasks, similar ideas appear as grouping images by resolution or aspect ratio.

Tokenization and preprocessing should be deterministic and cached where possible. For text, tokenization can be a bottleneck — offloading tokenization to CPU threads, using batched tokenizers, and caching tokenized files for large datasets reduces overhead. For images, augmentations (random crops, flips, color jitter) are applied on the fly; use efficient libraries (e.g., NVIDIA DALI, WebDataset) for fast decoding and augmentation at scale. For diffusion finetuning, care is needed in precomputing latent representations if using a VAE: caching latents avoids repeated encoding of images into the latent space.

Data sharding and parallel I/O are essential for distributed training. Large datasets should be split into shards and read in parallel with prefetching and multi-threaded loaders. Sharding also ensures reproducible data splits and easier resumption of interrupted jobs. For multi-node setups, make sure each worker sees different data (unless using synchronous evaluation protocols) and that random seeds are managed carefully for reproducibility.

Dataset composition matters: class balance, domain diversity, and label quality influence the finetuning outcome. When the finetuning dataset is small relative to the pretraining corpus, aggressive data augmentation and regularization are usually required to avoid overfitting. For multi-task or instruction finetuning, carefully curate task formats and include validation examples that match target usage. When finetuning generative models, add negative examples or contrastive pairs if you want to improve particular behaviors.

Finally, logging and checkpoint frequency should reflect the risk of instability and the time to convergence. Frequent small checkpoints allow quick recovery but can cost I/O overhead; incremental checkpoints (only optimizer/adapter params) reduce storage when using PEFT. Monitor data pipeline throughput to ensure GPUs remain utilized — a starvation situation often indicates bottlenecks in loading, tokenization, or decoding.

# Evaluation protocols: validation splits, overfitting checks, and metrics

A disciplined evaluation protocol protects against overfitting and ensures that reported improvements generalize. Start by partitioning data into training, validation, and test splits. The validation split is used for hyperparameter tuning, early stopping, and model selection; the test split must be held out until final reporting. If datasets are small, consider cross-validation or repeated random subsampling to obtain robust performance estimates. For tasks with domain variability (e.g., different user groups or image styles), maintain stratified splits so each split preserves the domain distribution.

Track training and validation metrics over time. Divergence between training and validation performance is the primary sign of overfitting. For scalar metrics (loss, accuracy), plot curves against steps or epochs. When validation loss stops improving for many evaluations while training loss continues to fall, take corrective measures: increase regularization, reduce learning rate, augment data, or enable stronger early stopping. Use multiple metrics to get a robust picture: for classification tasks track precision/recall curves or F1; for sequence generation track BLEU, ROUGE, or token-level perplexity.

Generative image models need task-specific metrics. Fréchet Inception Distance (FID) measures similarity between generated and real image distributions, but can be sensitive to sample size and to the encoder used. Inception Score (IS) measures both quality and diversity but has well-known limitations. CLIP-based similarity scores and image-text retrieval metrics are often used in text-to-image evaluation to assess fidelity to prompts; these metrics correlate with human judgment in some settings, but human evaluation remains important for subjective qualities like aesthetic or safety aspects. For conditional generation, use conditional FID or retrieval-based metrics that measure how well generated images match conditioning text.

Robustness and calibration matter. Check how model performance changes under input shifts (e.g., different token distributions, domain images). Calibrate confidence estimates if downstream systems rely on probabilities: use temperature scaling or isotonic regression on held-out validation sets. For language models, measure hallucination rates and factuality with prompt templates and reference datasets.

Finally, check for leakage and label contamination. Ensure that pretraining data does not include test examples used for downstream evaluation (which can yield inflated performance). For safety-sensitive or regulated applications, perform bias and fairness audits across demographic slices, and maintain logs and traceability for finetuning runs and evaluation data.

Conclusion

Finetuning large pretrained models successfully requires a mix of architectural insight and engineering practice. Knowing where linear transforms live in transformers, vision backbones, and diffusion models guides choices about where to insert adapters, low-rank updates, or shared modules. Memory-saving techniques such as activation checkpointing, mixed precision, ZeRO, and quantization make large-scale finetuning feasible, while careful batching, sharding, and data preprocessing keep GPUs fed. A rigorous evaluation pipeline — held-out test sets, multiple metrics, overfitting checks, and calibration tests — ensures that improvements are real and robust. Mastering these elements equips you to both understand current research and to run practical finetuning pipelines in production settings.

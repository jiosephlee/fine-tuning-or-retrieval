# Introduction

Large pretrained neural networks, especially transformer-based language models, have transformed many areas of machine learning. However, applying these models to downstream tasks via standard fine-tuning—updating every parameter—becomes expensive in terms of storage, computation, and engineering complexity as model sizes grow to billions or trillions of parameters. Parameter-efficient fine-tuning (PEFT) addresses this problem by adapting a pretrained model while modifying only a small subset of parameters. PEFT methods aim to preserve most of the pretrained weights, requiring less GPU memory during training, smaller stored checkpoints per task, and often faster convergence. This chapter explains the motivation behind PEFT, describes LoRA (Low-Rank Adaptation) in detail (its mathematical formulation, how it is integrated into layers, and how gradients flow when only adapters are trained), surveys other prominent PEFT approaches (prompt tuning, adapter modules, BitFit, IA3, prefix tuning), compares these approaches in terms of parameter count, memory and expressivity, and discusses practical hyperparameters and placement choices that matter in practice.

# Motivation for parameter‑efficient fine‑tuning (PEFT)

The simplest approach to adapting a pretrained model to a new task is full fine-tuning: initialize the model with pretrained weights and update all parameters using task-specific training data. Full fine-tuning is straightforward and often yields high performance, but it has several practical drawbacks as model sizes increase.

First, memory and storage: training requires holding gradients and optimizer states for all parameters, which multiplies memory usage (optimizers like Adam store first and second moments). Storing one fully fine-tuned copy per task becomes infeasible when each model weighs hundreds of gigabytes. Second, computation: backpropagating through billions of parameters at high throughput is costly and sometimes impossible on available hardware. Third, maintenance and deployment complexity: updating models per task leads to many large checkpoints to manage and serve. Fourth, stability and data efficiency: when task data are limited, updating all parameters can lead to catastrophic forgetting or overfitting to small datasets.

PEFT provides a compromise: keep the pretrained weights frozen and introduce a small number of learnable parameters that steer the model toward the new task. The guiding intuition is that most of the task-agnostic knowledge useful across tasks is already captured in the pretrained weights; downstream tasks often require only modest changes or low-dimensional adjustments in function space. By restricting updates to a small subspace, PEFT reduces storage (you need to save only a lightweight adapter per task), memory (fewer optimizer states and gradient tensors), and compute (smaller parameter updates can converge faster), while retaining most of the pretrained model’s representational power.

Beyond engineering benefits, PEFT often improves generalization when task data are scarce. Learning only a compact set of parameters constrains the hypothesis class, acting like an implicit regularizer and preventing overfitting. PEFT can also enable multi-task switching at inference time by loading tiny per-task parameter additions rather than entire model copies, facilitating efficient model serving.

# LoRA: formulation, low‑rank decomposition of updates, and integration into layers

LoRA (Low-Rank Adaptation) is a widely used PEFT method that modifies pretrained linear (or linear-like) layers by adding a low-rank update to their weight matrices. The core idea is that the difference between the task-specific optimal weight matrix and the pretrained weight matrix lies approximately in a low-dimensional subspace. Therefore, instead of modifying the original weight matrix $W$ directly, LoRA models the change $\Delta W$ as a product of two low-rank matrices.

Consider a standard linear layer with weight matrix $W \in \mathbb{R}^{d_\text{out}\times d_\text{in}}$ that maps an input vector $x \in \mathbb{R}^{d_\text{in}}$ to output $y = W x$. LoRA replaces this with an effective weight $W' = W + \Delta W$, where the update $\Delta W$ is constrained to be low-rank:

\[
\Delta W = B A,
\]

with $A \in \mathbb{R}^{r \times d_\text{in}}$ and $B \in \mathbb{R}^{d_\text{out} \times r}$, and $r \ll \min(d_\text{in}, d_\text{out})$. The forward pass becomes

\[
y = W x + (B A) x = W x + B (A x).
\]

Because $r$ is small, the number of additional parameters is $r(d_\text{in} + d_\text{out})$, which can be orders of magnitude smaller than $d_\text{in}d_\text{out}$. In practice, implementations often scale the low-rank update by a factor $\frac{\alpha}{r}$ to control the magnitude relative to $W$; thus the effective output is

\[
y = W x + \frac{\alpha}{r}\, B (A x).
\]

The scaling factor $\alpha$ can be viewed as a global step-size that counteracts small initialization of $B$ and $A$, and it helps stabilize training.

Intuition for low rank: Many meaningful changes to a layer’s mapping can be approximated by a mixture of a small number of "directions" or prototype transformations. For example, adjusting attention output projection matrices to emphasize certain token representations across many contexts might be achievable by a few rank-1 components rather than a full dense change. The low-rank constraint forces the learned update to be more structured and to generalize better.

Integration into transformer layers: LoRA is commonly applied to attention projection matrices—query ($W_Q$), key ($W_K$), value ($W_V$), or output ($W_O$)—and sometimes to feed-forward network (FFN) weight matrices. For an attention projection (say $W_Q$ mapping from embedding dimension $d$ to $d$), LoRA inserts $A_Q$ and $B_Q$ such that $W_Q' = W_Q + B_Q A_Q$. During training, the base weights $W_Q$ remain frozen and only $A_Q, B_Q$ (and possibly other adapter parameters) are updated. At inference, one can either compute $W_Q + \frac{\alpha}{r} B_Q A_Q$ to obtain an adapted dense weight (merging) or apply the extra low-rank term on-the-fly without altering $W_Q$.

A practical implementation detail is to place the multiplication as $B(Ax)$ so that $A$ is applied first to the input $x$ producing an $r$-dimensional intermediate, then $B$ projects that back to $d_\text{out}$. This ordering is computationally efficient when $d_\text{in}$ is large and $r$ is small because $A x$ costs $O(rd_\text{in})$ and $B(\cdot)$ costs $O(rd_\text{out})$, far less than $O(d_\text{in}d_\text{out})$.

Initialization: A common choice is to initialize $A$ with a small random Gaussian (e.g., variance chosen so that the initial $\Delta W$ has small norm) and $B$ with zeros or small values. Initializing $B$ to zero makes the adapter start as the identity (no update), which is stable and avoids sudden behavior changes at the start of training. When $B$ is zero, gradients still flow into $A$ via $B$ only after $B$ receives nonzero updates, but practical initializations ensure both parameters learn quickly (e.g., initializing $A$ nonzero and $B$ small nonzero).

# Other PEFT methods: prompt tuning, adapter modules, BitFit, IA3, prefix tuning

A variety of PEFT techniques have been proposed, each modifying the model in different ways that trade off parameter efficiency, expressivity, and implementation complexity. We describe the most commonly used methods and their key ideas.

Prompt tuning: Prompt tuning learns a set of task-specific continuous vectors (often called soft prompts) that are prepended to the input token embedding sequence and are learned while keeping the model weights frozen. Given an input sequence of length $n$, prompt tuning creates a learned prompt of length $m$ with embeddings $P \in \mathbb{R}^{m\times d}$ that are concatenated to the token embeddings at the model input. The transformer processes the concatenated sequence normally, letting the prompt vectors influence intermediate representations through attention. Prompt tuning is highly parameter-efficient, since only $md$ parameters are learned, independent of model depth. Its expressivity is limited by how well changing only the input context can steer model behavior—effective for classification and some generation tasks, especially in very large models where the model learns to treat the prompt as context. However, prompt tuning can struggle on tasks that require deeper representational changes or when the prompt must affect internal computation patterns beyond initial attention conditioning.

Prefix tuning: Prefix tuning generalizes the prompt idea by learning pseudo-key and pseudo-value vectors injected into each attention layer. Instead of only placing learned vectors at the input layer, prefix tuning adds learned sequences that act like additional keys and values in multi-head attention for each layer, enabling the learned prefix to influence attention computations throughout the network. For a given attention layer, learned prefix parameters $K_\text{prefix} \in \mathbb{R}^{m\times d_k}$ and $V_\text{prefix} \in \mathbb{R}^{m\times d_v}$ are concatenated with the layer’s keys and values. This increases expressivity relative to prompt tuning because the learned parameters have direct access to and can alter attention distributions at multiple depths. The parameter cost is larger than prompt tuning (since prefixes are stored per layer), but still small relative to full model fine-tuning.

Adapter modules: Adapters insert small bottleneck feed-forward modules inside transformer layers—typically after the multi-head attention and/or after the feed-forward sublayer. A standard adapter is a residual bottleneck: starting from activation $h \in \mathbb{R}^{d}$, the adapter computes

\[
h' = h + W_\text{up} \sigma(W_\text{down} h),
\]

where $W_\text{down} \in \mathbb{R}^{r \times d}$ projects to a low-dimensional space, $\sigma$ is a nonlinearity (e.g., ReLU), and $W_\text{up} \in \mathbb{R}^{d \times r}$ projects back to dimension $d$. The adapter parameters $W_\text{down}, W_\text{up}$ are trained while the main weights are frozen. This structure mirrors LoRA’s low-rank idea but places it as a separate feed-forward residual block with nonlinearity, allowing more expressive nonlinear transformations in the adapter. Adapters have been widely used because they are flexible, capture local transformations at each layer, and are straightforward to add to existing models.

BitFit: BitFit takes an extreme approach to parameter efficiency by fine-tuning only the bias terms in the model (the term "Bias terms Fit"). All dense weight matrices are frozen except their corresponding bias vectors, which are trained task-specifically. Biases are a tiny fraction of the total parameters, so BitFit is extremely parameter-efficient. For some classification tasks and larger models, BitFit yields surprisingly strong performance, but it is more limited in expressivity than larger adapter-style approaches. BitFit’s appeal is its simplicity and minimal storage cost.

IA3 (Injecting Additive Adaptation of Activations): IA3 is a method that learns small multiplicative rescaling vectors per layer that scale intermediate activations. In one variant, IA3 inserts learned vectors $s \in \mathbb{R}^{d}$ that multiply the output of projection layers or intermediate activations elementwise. For example, after computing a feed-forward activation $u \in \mathbb{R}^d$, IA3 applies $u' = s \odot u$. The learned scaling vector $s$ is task-specific and much smaller than full matrices. IA3 can be seen as learning diagonal low-rank (rank-$d$ but diagonal) modifications; it is more parameter-efficient than full adapters but less expressive. IA3’s gains are often complementary to other PEFT methods.

Other variants and hybrids: Researchers have combined ideas—e.g., LoRA applied to only certain projections, adapters with residual and layer-norm coupling, or prefix tuning combined with prompt tuning. The design choices reflect trade-offs among parameter count, computation overhead, and the nature of tasks.

# Comparison of PEFT approaches: parameter count, memory, and expressivity

PEFT methods vary along several dimensions: number of task-specific parameters, runtime memory during training and inference, computational overhead, and expressivity (the class of functions they can represent relative to full fine-tuning). Understanding these trade-offs helps choose a method for a given scenario.

Parameter count: Prompt tuning and BitFit are among the most parameter-efficient. Prompt tuning stores $m\cdot d$ parameters (with $m$ often on the order of tens to a few hundred tokens), independent of model depth. BitFit stores only biases—roughly proportional to the number of layers times size of hidden dimensions, amounting to a tiny percentage of model parameters. LoRA and adapters store more parameters—LoRA stores $r(d_\text{in}+d_\text{out})$ per adapted matrix, and adapters store $2rd$ per adapter (down and up matrices), where $d$ is layer width—yet they remain orders of magnitude smaller than full weights when $r \ll d$. Prefix tuning and layerwise prefix methods require storing parameters per layer (keys and values), so storage scales with depth times prefix length.

Memory during training: Freezing the base weights greatly reduces peak GPU memory because no optimizer states are needed for frozen parameters. However, memory still includes gradients and optimizer states for the adapter parameters. The memory cost roughly scales with the number of learned parameters. Another memory factor is whether the added computation introduces intermediate activations that need to be stored for backpropagation. For example, adapter modules with nonlinearities require storing their activation intermediates, while LoRA’s linear low-rank factors have small intermediate tensors. At equal parameter count, methods with simpler linear adapters (LoRA, IA3) typically have lower training memory overhead than adapters with nonlinearities.

Computational overhead: Methods that insert extra linear operations (LoRA, IA3) add small matrix multiplications and thus a small runtime cost proportional to $r$. Prefix tuning and prompt tuning add minimal per-layer compute (prefix vectors affect attention dot-products but do not add large dense multiplications). Nonlinear adapters introduce additional operations (e.g., ReLU or layer-norm) that increase compute per token. When latency at inference matters, merging LoRA’s low-rank update into the frozen weight at inference can eliminate any added compute, making inference cost identical to the original model; prompt/prefix tuning and adapters typically require running the adapters or concatenating prompts, which may still be inexpensive but does not always allow complete fusion into existing model weights without changing runtime.

Expressivity: Expressivity is the capacity of the adapter to represent the necessary changes for downstream tasks. In approximate order from least to most expressive (though this depends on task and hyperparameters), BitFit tends to be least expressive, then prompt tuning (input-level only), then IA3 (diagonal scalings), then LoRA (linear low-rank updates), then adapters (low-rank but with nonlinearity). However, in large models, even relatively low-capacity methods can be surprisingly powerful because the underlying model already encodes complex behaviors. LoRA provides a strong balance: it can represent any change approximate in a low-rank subspace and can be merged into weights for inference. Adapters add nonlinearity and local processing capacity, which sometimes offers better adaptation for tasks that require nonlinear transformations of internal representations.

Task-specific considerations: For tasks that require global reweighting or fine-grained changes across many layers (e.g., complex generation behaviors), methods with more expressivity (LoRA with larger $r$, adapters) are generally preferable. For simple classification or tasks where prompt-based conditioning suffices, prompt tuning or BitFit may be adequate and are cheaper.

# How gradients flow when base weights are frozen and only adapters are updated

Understanding gradient flow is critical for implementing and reasoning about PEFT methods. We focus on LoRA as a representative linear adapter and then describe how similar reasoning applies to other methods.

Take a linear layer with frozen base weight $W$ and low-rank LoRA adaptation $\Delta W = B A$ as before. For one input vector $x$, the layer output is

\[
y = W x + B (A x).
\]

Let the loss be $\mathcal{L}(y)$ (potentially composed with subsequent frozen layers). During training, we update only $A$ and $B$. The chain rule gives gradients:

\[
\frac{\partial \mathcal{L}}{\partial B} = \frac{\partial \mathcal{L}}{\partial y}\, (A x)^\top,
\]
\[
\frac{\partial \mathcal{L}}{\partial A} = B^\top \left( \frac{\partial \mathcal{L}}{\partial y} \right) x^\top.
\]

Intuition: The gradient w.r.t. $B$ is the outer product of the upstream gradient $\partial \mathcal{L}/\partial y$ (a $d_\text{out}$-dimensional column) and the low-dimensional representation $A x$ (an $r$-dimensional row). For $A$, the gradient flows into it via $B^\top$—if $B$ is small or zero, the magnitude of gradients to $A$ is correspondingly affected. This is why initialization and scaling matter: if $B$ is initialized to exactly zero and remains tiny, gradients to $A$ will be negligible until $B$ grows, which can slow learning. Practical initializations avoid stalling by giving $A$ nonzero initial values or initializing both $A$ and $B$ with appropriate scales. Because $W$ is frozen, gradients do not update $W$, but they propagate through $W$ downstream via the usual chain rule into earlier adapter layers.

Importantly, even with base weights frozen, gradients can still flow "into" the network before the adapted layer. For example, consider an adapter placed in an intermediate layer. The upstream gradient $\partial \mathcal{L}/\partial y$ propagates back through the frozen parts of the network to earlier parameters that are trainable (adapters inserted earlier), because the computational graph includes frozen weights treated as constant multipliers but still allowing gradients to pass through. Freezing a parameter does not stop gradient propagation; it only prevents its update. Thus multiple adapters at different depths can coordinate: gradients flow from the loss through frozen weight multiplications to influence all adapter parameters.

For nonlinear adapters (e.g., adapter modules with $W_\text{up}\sigma(W_\text{down}h)$), gradients flow through the nonlinearity. If the adapter has a residual connection $h' = h + \dots$, gradients to the main path are added with gradients to the adapter path. For prompt and prefix tuning, the prompt or prefix vectors are part of the input sequence or of attention keys/values; gradients flow into them naturally as they participate in forward computations. For IA3, which uses multiplicative scaling vectors $s$ that elementwise multiply activations, gradients are computed via elementwise products: $\partial \mathcal{L}/\partial s = (\partial \mathcal{L}/\partial u) \odot u$, where $u$ is the activation being scaled.

A special practical point: when using optimizers like Adam, only parameters that require gradients are included in optimizer states; freezing base weights drastically reduces optimizer memory because the large moment tensors are not allocated. This is a key memory advantage of PEFT.

# Practical hyperparameters: rank r, scaling factors, and placement of adapters

Several practical choices determine the effectiveness of PEFT: the rank $r$ in low-rank methods, scaling factors like $\alpha$, where to place adapters in the model, initialization schemes, and optimizer/hyperparameter choices.

Choosing rank $r$: The rank $r$ controls the number of degrees of freedom in the low-rank update. Small $r$ (e.g., 1–8) yields very few parameters and can work well when the needed adaptation is simple or when the base model is very large. Larger $r$ (e.g., 16–64 or higher) gives more capacity but increases parameter count and computation. Empirically, the optimal $r$ depends on model size and task complexity: larger models often require smaller relative $r$ for similar performance; conversely, more difficult tasks (requiring large functional changes) may benefit from higher $r$. A common practical approach is to tune $r$ from a small set such as $\{4,8,16,32\}$ and choose the smallest $r$ that reaches target performance.

Scaling factors ($\alpha$ and normalization): LoRA introduces a multiplicative scaling $\frac{\alpha}{r}$ for $\Delta W$ to control update magnitude. Choosing $\alpha$ is analogous to choosing a learning-rate multiplier for adapter parameters. A typical choice is $\alpha = r$ so the scale is 1, but some implementations set $\alpha$ higher to amplify adapter effect or lower to regularize. When $B$ and $A$ are initialized with small variance (or $B$ initialized at zero), $\alpha$ helps ensure the adapter contributes meaningfully during training. It can be treated as a tunable hyperparameter or absorbed into the learning rate of adapter parameters.

Placement of adapters: Where to apply adapters influences both expressivity and efficiency. In transformers, common placements include the projection matrices in multi-head attention (queries, keys, values, outputs) and the feed-forward network weights. LoRA applied to the query and value or to the output projection often yields strong performance because attention projections shape how tokens interact. Adapters in FFN layers provide per-token nonlinear transformation capacity. Placing adapters in every layer provides maximal flexibility but increases parameter count; a common trade-off is to insert adapters every N layers (e.g., every layer, every other layer) or only in certain components (e.g., attention output matrices). Empirical studies often suggest adapting either attention projections or FFN layers works well; combining both can yield better results for challenging tasks.

Initialization strategies: For LoRA and linear adapters, initializing $A$ with a small random Gaussian and $B$ to zero or small values is common. Initializing $B$ to zero is simple and stable because the initial adapter contributes nothing, avoiding sudden disruptions. However, zero $B$ can transiently suppress gradients to $A$; to mitigate this, $A$ may be initialized with slightly larger scale, or $B$ can be initialized with a tiny nonzero scale. For adapter modules with nonlinearities, Xavier/He initializations adapted to the bottleneck size help. Prompt vectors are usually initialized randomly or derived from tokens (in some methods, initializing prompt embeddings to embeddings of frequent tokens can help).

Learning rates and optimizers: Since adapter parameters are usually a small subset, they often require different learning rates than one would use for full fine-tuning. Adapter parameters sometimes benefit from larger learning rates than those used when tuning the whole model because they start from small magnitudes and must effect change without changing many parameters. Common practice is to use Adam or AdamW on adapter parameters with weight decay applied selectively (often no weight decay on biases and layer-norm parameters). Learning rate schedulers (warmup, cosine decay) remain useful.

Batch size and regularization: Small adapters can overfit small datasets, so regularization such as weight decay, dropout inside adapters, or early stopping can help. When training with small batches, normalization of gradients or gradient clipping may be useful to stabilize updates.

Merging at inference: LoRA’s updates can be merged into the base weight for inference by computing $W + \frac{\alpha}{r} B A$ and saving the merged dense weights. Merging avoids runtime overhead and allows the same inference code as the base model, which simplifies deployment. Prompt tuning, prefix tuning, and adapters generally require runtime support for the extra parameters unless one precomputes per-task fused models.

Choosing a method: Practical choice depends on constraints. If storage per task must be extremely small, prompt tuning or BitFit may be preferable. If task complexity demands expressive adaptation and fast training, LoRA with modest $r$ is often a good balance. Adapters offer nonlinear capacity for difficult tasks but increase inference compute. IA3 is attractive when very low overhead is required while gaining more flexibility than BitFit.

# Closing remarks

Parameter-efficient fine-tuning enables practical adaptation of very large pretrained models to many tasks without the prohibitive storage and compute costs of full fine-tuning. LoRA’s low-rank adaptation is a conceptually simple and computationally attractive method that captures much of the performance of full fine-tuning while introducing only a small number of parameters; its amenability to merging at inference and straightforward gradient behavior have made it popular. Other PEFT techniques—prompt tuning, prefix tuning, adapter modules, BitFit, IA3—offer different trade-offs in terms of parameter count, memory footprints, and expressivity, and are useful in different application regimes. Understanding how gradients flow through frozen weights into adapters and carefully selecting hyperparameters (rank $r$, scaling $\alpha$, adapter placement, initialization, and optimizer settings) are crucial for successful application. With these tools, researchers and practitioners can adapt large models efficiently, enabling broader experimentation, multi-task serving, and deployment on resource-constrained platforms.

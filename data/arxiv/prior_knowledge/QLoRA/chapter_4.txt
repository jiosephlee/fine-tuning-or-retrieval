# Introduction

Quantization is the process of mapping continuous or high-precision numerical values to a smaller set of discrete values. In machine learning, and particularly in large language models (LLMs), quantization is used to reduce model size, lower memory bandwidth, and improve inference speed by representing weights, activations, and sometimes gradients with fewer bits. Reducing numeric precision is rarely free: it introduces approximation error that can degrade model accuracy. This chapter develops the foundational principles and practical techniques used to quantize neural network parameters and activations. We will define quantization and dequantization formally, contrast uniform (linear) and non‑uniform schemes, explain different granularities of scaling (per‑tensor, per‑channel, block‑wise), derive common scale factor formulas such as absolute‑max scaling, analyze quantization error and bias and strategies for handling outliers, introduce quantile/histogram‑based approaches, and finally describe practical workflows to quantize, store, and dequantize models for inference.

Throughout, we will emphasize intuition and tradeoffs. The mathematics will be written in LaTeX-style notation (e.g., "$x^2$"), and formulas are kept explicit so you can use them directly in experiments or implementations.

# Definition of quantization and dequantization

At its core, quantization maps a real-valued scalar (or vector/matrix) into a discrete set of representable values. Suppose we have a real number $x \in \mathbb{R}$. A quantizer $Q(\cdot)$ produces an integer index (or code) $q$ from a finite set, often $\{0,1,\dots,2^b-1\}$ for unsigned $b$-bit quantization or $\{-2^{b-1},\dots,2^{b-1}-1\}$ for signed representation. The dequantizer (or reconstruction function) $Q^{-1}(\cdot)$ maps the integer back to a real value $\hat{x}$ in the representable set. Formally:
- Quantization: $q = Q(x)$.
- Dequantization: $\hat{x} = Q^{-1}(q)$.

A common linear (uniform) quantization form uses a scale factor $s>0$ and an optional zero-point $z$:
- Quantize: $q = \mathrm{round}\!\left(\frac{x}{s}\right) + z$ (or clamp to integer range).
- Dequantize: $\hat{x} = s\,(q - z)$.

Here $s$ converts between the integer grid and the real number line, and $z$ shifts the integer grid to align with zero in real space. In symmetric schemes, $z=0$ and the integer grid is centered at zero; in asymmetric schemes $z\neq 0$ to allow different dynamic ranges for positive and negative values.

The quantization operation is generally many‑to‑one, and quantization is lossy: $x \neq \hat{x}$ except when $x$ happens to be exactly representable. The quantization error (or quantization noise) for a single scalar is $e = \hat{x} - x$.

For vectors or matrices, quantization can be applied elementwise but with shared or per-element scale/zero-point choices. When quantizing model weights or activations, practical implementations pack integers in memory and store scale factors separately, then perform dequantization when needed for arithmetic (or use integer arithmetic where possible).

# Uniform (linear) quantization vs non‑uniform quantization

Uniform (linear) quantization divides the real line (or the relevant interval) into equally spaced quantization intervals. Each quantized value corresponds to the midpoint (or a grid point) of an interval of width $s$. Uniform quantization is characterized by a single scale factor $s$ (per group) and possibly a zero-point $z$. For $b$ bits and signed symmetric integers in the range $[-q_{\max}, q_{\max}]$ where $q_{\max}=2^{b-1}-1$, a typical symmetric uniform quantization maps $x$ to
\[ q = \mathrm{clamp}\!\left(\left\lfloor \frac{x}{s} \right\rceil, -q_{\max}, q_{\max}\right), \]
and dequantizes via $\hat{x} = s q$. The interval size is $s$, so the maximum representable magnitude is $s q_{\max}$. Uniform quantization has the major advantage of simplicity and hardware friendliness: integer arithmetic and vectorized kernels are straightforward, and conversion between integer and real domains is linear.

Non‑uniform quantization uses non‑equally spaced reconstruction levels. Typical forms include logarithmic quantization, Lloyd‑Max quantization (optimal scalar quantization under an error criterion), k‑means (vector) quantization, and codebook techniques. In non‑uniform scalar quantization, the real line is partitioned into variable-width intervals; each interval yields a distinct reconstruction value that may be chosen to minimize mean squared error (MSE) or another distortion measure given the distribution of $x$. A classical algorithm for scalar non‑uniform quantizer design is the Lloyd‑Max algorithm, which iteratively updates decision boundaries and reconstruction points to minimize expected squared error.

Intuitively, non‑uniform quantization is beneficial when the distribution of values is highly non‑uniform — for instance, heavy‑tailed or concentrated near zero. By placing more reconstruction points where the probability mass is higher (e.g., densely near zero), non‑uniform schemes can achieve lower distortion for a given number of bits. Logarithmic quantization is useful when relative error matters more than absolute error; it allocates resolution proportionally to magnitude, which can be effective for distributions extending across orders of magnitude.

However, non‑uniform schemes are typically more complex to implement in hardware, require table lookups or de‑indexing, and can complicate the use of integer arithmetic for matrix multiplications. Thus, many practical systems prefer uniform quantization, or approximate non‑uniform schemes using piecewise uniform blocks.

# Per‑tensor, per‑channel, and block‑wise quantization

Choosing where to share scale factors is crucial for balancing compression efficiency and accuracy. Three common granularities are per-tensor, per-channel, and block-wise quantization.

Per‑tensor quantization uses a single scale (and zero-point) for an entire tensor, such as all weights of a layer or an entire activation tensor. This is the simplest approach and minimizes metadata (only one scale and zero-point per tensor). But it can be suboptimal when different rows/columns/channels have very different dynamic ranges. For example, in a weight matrix of a linear layer, some columns (corresponding to certain output neurons) might have much larger magnitudes than others; per‑tensor scaling will be dominated by the largest magnitudes and thus waste precision for small-magnitude channels.

Per‑channel quantization assigns a scale (and optionally zero-point) per channel (common choice: per-output-channel for weights in convolutional/linear layers). For a weight matrix $W \in \mathbb{R}^{m\times n}$, per-output-channel quantization would keep a separate scale $s_j$ for each column $j$ (or row, depending on layout). The quantization becomes
\[ q_{ij} = \mathrm{round}\!\left(\frac{W_{ij}}{s_j}\right), \qquad \hat{W}_{ij} = s_j q_{ij}. \]
Per‑channel quantization typically yields much lower error than per‑tensor since it adapts to per-channel variance. It is widely used in inference toolchains because the extra metadata cost (one scale per channel) is moderate and matrix multiplication can be efficiently implemented using per-channel dequantization during weight loading or with integer matrix kernels that accept per-row/col scales.

Block‑wise quantization splits a tensor into blocks (e.g., contiguous submatrices) and assigns a separate scale to each block. Block sizes can range from small (e.g., 32 or 64 elements) to larger blocks (e.g., 128–1024). Block quantization is a middle ground: with smaller blocks you approximate per‑element scaling, reducing quantization error, but you increase storage of scales and computational overhead. Block-wise schemes are common in LLM weight compression. For instance, some high-performance methods quantize weight matrices in blocks of 128 or 256 elements per scale, striking a balance between accuracy and metadata.

Intuitively, finer granularity (per-channel → smaller blocks → per-element) reduces quantization error but increases metadata storage and computational cost. Coarser granularity reduces overhead but is less adaptive. The optimal choice depends on the model architecture, distribution of values, and deployment constraints (memory, compute, and supported kernels).

# Absolute‑max (min‑max) scaling and scale factors

Absolute‑max (also called min‑max symmetric) scaling is one of the simplest ways to determine a scale factor for uniform quantization. For a given group of values (tensor, channel, or block), compute the maximum absolute value:
\[ X_{\max} = \max_i |x_i|. \]
For a symmetric integer quantizer with signed integer range $[-q_{\max}, q_{\max}]$ (where $q_{\max}=2^{b-1}-1$), choose the scale so the largest magnitude maps to the largest representable integer:
\[ s = \frac{X_{\max}}{q_{\max}}. \]
Quantization becomes $q_i = \mathrm{round}(x_i/s)$ and dequantization $\hat{x}_i = s q_i$. This ensures no representable value will overflow the integer range (assuming you clamp). Absolute‑max scaling is simple and fast to compute and is particularly convenient for hardware: a single scale per group ensures symmetrical ranges.

There is also min‑max scaling that uses both the minimum and maximum (asymmetric), which is useful when the data is not symmetric around zero. For unsigned integer ranges $\{0,\dots,2^b-1\}$ or when preserving a nonzero zero-point is desired, one computes
\[ X_{\min} = \min_i x_i,\qquad X_{\max} = \max_i x_i, \]
and defines scale and zero-point as
\[ s = \frac{X_{\max} - X_{\min}}{2^b - 1}, \qquad z = \mathrm{round}\left(-\frac{X_{\min}}{s}\right). \]
Then quantize by $q_i = \mathrm{clamp}(\mathrm{round}(x_i/s) + z,0,2^b-1)$ and dequantize $\hat{x}_i = s(q_i - z)$.

Absolute‑max scaling is robust when the distribution is approximately symmetric and when outliers are not severe. However, when outliers exist, $X_{\max}$ may be dominated by a few extreme values, making $s$ large and reducing resolution for the majority of values. That motivates alternative scale selection strategies discussed below.

# Quantization error and bias; handling outliers

Quantization error for an element is $e_i = \hat{x}_i - x_i$. Aggregate measures used to analyze error include mean squared error (MSE), mean absolute error (MAE), maximum absolute error (L_infty), and distributional measures like Kullback‑Leibler divergence (KL) between histograms of original and quantized values. MSE is a common metric because it is analytically tractable and often correlates with downstream performance, but it is not universally optimal.

Bias refers to systematic shifts introduced by quantization. For symmetric uniform quantization with unbiased rounding (round to nearest), the expected quantization error conditioned on $x$ in a small interval is approximately zero if $x$ is uniformly distributed within quantization intervals. But in practice, nonuniform distributions, clamping/overflow, asymmetric zero-points, or deterministic rounding can introduce bias. For example, if large values are clipped to avoid overflow, their errors have a one-sided sign, producing bias. Similarly, truncation (flooring) is biased downward relative to rounding.

Outliers pose a central challenge in quantization. A few large-magnitude weights can force scale $s$ to be large, increasing the quantization step size and degrading precision for the bulk of weights. Strategies to handle outliers include:

1. Clipping: Choose a smaller clipping threshold $T < X_{\max}$ and clip values above $T$ to $T$ (and below $-T$ to $-T$ for symmetric). This reduces the effective dynamic range, allowing finer resolution for most values, at the expense of biasing large values. You select $T$ to minimize an error measure (e.g., MSE) over the dataset.

2. Outlier splitting or separate representation: Detect a small set of outlier channels/elements and treat them specially. For example, represent most weights with low-bit quantization and store outliers in higher precision (e.g., float16). Some LLM quantization schemes isolate large-magnitude rows/columns and keep them at full precision.

3. Per-channel or block quantization: Finer granularity allows the scale to adapt to local statistics, so outliers in one channel do not affect others.

4. Mixed-precision schemes: Use higher bit width for layers or blocks that are sensitive, or use techniques like activation-aware quantization where certain layers keep more precision.

5. Bias correction: After quantization, compute the empirical bias per channel (average of $\hat{x}-x$ over calibration data) and subtract it during dequantization: $\hat{x}_i \leftarrow \hat{x}_i - b$, where $b$ is the bias estimate. This can partially correct systematic shifts introduced by quantization and clipping.

6. Stochastic rounding: Instead of deterministic rounding, use randomized rounding that preserves the expectation: round up or down with probabilities so that $\mathbb{E}[\hat{x}] = x$. Stochastic rounding reduces bias accumulation during iterative computations (e.g., training) but introduces variance and is less common for static weight compression in inference.

When assessing quantization error, examine not only aggregate metrics but also how the quantization affects downstream tasks. For LLMs, small errors in weight matrices can interact through many nonlinear layers, amplifying or diminishing effects. Empirical calibration using a representative dataset (calibration set) is commonly used to select clipping thresholds, per-channel scales, and bias corrections.

# Quantile (equal‑probability) quantization and histogram‑based methods

Quantile or equal‑probability quantization allocates quantization levels so that each quantization bin contains approximately the same number of samples. For a scalar value distribution, compute the quantiles that partition the empirical distribution into $2^b$ groups of equal probability; choose a representative reconstruction value per group (e.g., mean of values in the group). This is a kind of non‑uniform scalar quantization tailored to the empirical cumulative distribution function (CDF).

Quantile quantization is attractive for heavy‑tailed distributions because it increases resolution where data are concentrated. For LLM weights that often have many small values and a long tail, quantile bins will be narrow near zero and wider in the tail, improving fidelity for the common small values.

Histogram‑based methods build a histogram of values (possibly on a logarithmic axis) and choose quantization intervals by optimizing a distortion measure, either exactly via dynamic programming (for 1D) or approximately. KL‑divergence histogram methods are popular for activation quantization in CNNs: one constructs the distribution of activations from calibration data and selects clipping thresholds and bin widths to minimize the KL divergence between the original floating-point distribution and the quantized distribution after dequantization. The TensorRT and some quantization toolchains use KL‑based calibration: they search clipping threshold $T$ that, when activating values are clipped to $[-T, T]$, produces the lowest KL divergence between original and quantized histograms.

Another histogram-driven approach is to design non‑uniform quantizers by running Lloyd‑Max or k‑means on the set of samples in the tensor (or per-channel/block). For a scalar quantizer with $K$ levels, the k‑means algorithm groups samples into $K$ clusters and uses cluster centroids as reconstruction points. This yields quantization that minimizes MSE for the sample distribution. The downside is that you need to store a codebook of $K$ reconstruction values per group, increasing metadata storage and lookup cost.

Vector quantization (VQ) and product quantization (PQ) generalize scalar quantization by quantizing multi-dimensional subvectors jointly, using a codebook of vectors. PQ is used in some compression schemes to reduce memory further by sharing codebooks across blocks. But these non‑uniform and vector methods complicate fast matrix multiplication because they replace dense weight matrices with codebook index lookups and additional computations.

Quantile and histogram methods rely on representative calibration data. The calibration set should reflect the input distribution at inference, otherwise the chosen bins or clipping thresholds may be suboptimal and degrade performance.

# Practical workflows: quantize→store→dequantize for inference

A practical quantization workflow for model deployment typically follows a few phases: calibration/analysis, quantization (encoding), storage/packaging, and dequantization/compute at inference. Below we outline a robust, commonly used post‑training quantization (PTQ) workflow and highlight implementation details important for LLMs.

1. Calibration and analysis. Gather a small representative calibration dataset of inputs that approximates inference-time distributions. For weights, you can often use the trained weight tensors directly; for activations you must run inference on calibration inputs to collect activation statistics. Compute per‑tensor/per‑channel histograms, min/max, mean/variance, and identify outliers. Decide on a quantization granularity (per-channel, block size), bit width, and whether to use symmetric/asymmetric mapping. If clipping thresholds are to be used, search thresholds by minimizing an error metric (MSE, KL) based on the calibration data.

2. Quantization (encode). For each tensor or block:
   - Compute scale $s$ and zero-point $z$ according to the chosen scheme (absolute‑max, MSE-optimal clipping, quantile bins, etc.).
   - Quantize values to integer codes $q$ using rounding and clamping to the integer range. Optionally store residuals or outliers in higher precision.
   - Optionally apply per‑channel bias correction: compute average error on calibration data and record correction values.
   - Optionally apply advanced algorithms: weight clustering (k‑means), product quantization, or methods like GPTQ / AWQ for LLMs that perform greedy or second-order reconstruction to preserve important directions.

3. Storage and packaging. Store the integer codes in compact form (e.g., packed arrays for 2, 3, 4 bits per element). Alongside the integer arrays, store metadata necessary for reconstruction: scale factors (one per tensor/channel/block), zero-points if used, and any bias-corrections or codebooks for non‑uniform quantizers. Metadata storage cost depends on granularity; for small block sizes the scale overhead can be significant, so many schemes quantize scale factors themselves (e.g., store scales as float16) or use shared scales across groups.

4. Dequantization (reconstruction at inference). Two main strategies exist for using quantized tensors during inference:
   - Dequantize-then-compute: At layer load or just before computing, dequantize weights (and possibly activations) to floating-point using stored scales and zero-points, restoring them to the computational format required by the backend. This is simple but requires extra memory for the dequantized tensors and time to convert.
   - Integer (or mixed) compute: Perform the bulk of linear algebra using integer arithmetic, converting inputs/weights only when necessary. For example, the inner product of a quantized weight matrix $Q_W$ and a quantized activation vector $Q_X$ can be accumulated as integers and later multiplied by scales: if weights use scale $s_W$ and activations use scale $s_X$ and zero-points are zero for symmetric quantization, then
     \[ W X \approx (s_W q_W) (s_X q_X) \Rightarrow \hat{y} = s_W s_X \sum_i q_{W,i} q_{X,i}. \]
     For more complex cases with per-channel scales and zero-points, bookkeeping is needed to combine scales and offsets efficiently. Integer compute reduces memory traffic and can exploit optimized integer matrix kernels.
   - Hybrid strategies: Keep some layers (or blocks) dequantized in float while performing other layers in low precision. Many LLM quantization toolchains use mixed-precision to preserve accuracy.

5. Post‑quantization verification and fine‑tuning. Evaluate model accuracy and latency. If accuracy drops beyond acceptable limits, consider re-tuning granularity or thresholds, enabling per-channel quantization, protecting sensitive layers (keeping them in higher precision), or applying quantization-aware fine-tuning (QAT) where the model is further trained with quantization simulated during training. For LLMs, recent PTQ algorithms like GPTQ (Greedy Per‑Layer Reconstruction using approximate second-order information) perform a reconstruction pass to minimize layerwise error while keeping weights in low-bit format; AWQ (Activation-aware Weight Quantization) adapts quantization to activation statistics.

Practical considerations and tips:
- Store scales in compact forms (float16, or quantized scales) if metadata becomes significant. For example, with block size 128, one float32 scale per block is expensive; float16 scales reduce overhead.
- Pack integer codes tightly to reduce memory (e.g., 2 or 3 bits per weight). Ensure decoding/unpacking is efficient for the backend.
- For non‑uniform codebooks, prefer small codebook sizes and shared codebooks to reduce metadata.
- When using per‑channel or block quantization, ensure compute kernels can apply per-row or per-column scales efficiently (commonly through fused multiply-add with the dequantized scale).
- Keep a small calibration set representative of inference inputs. The calibration set strongly affects choices like clipping thresholds and quantile boundaries.
- For LLMs, evaluate generation quality (perplexity, BLEU, or task-specific metrics) and speed/memory tradeoffs, not only layerwise MSE.

In summary, the quantize→store→dequantize workflow involves careful analysis of data distribution, choice of quantization scheme and granularity, efficient encoding with metadata, and appropriate runtime strategies (full dequantize or integer compute). By combining empirical calibration and algorithmic refinements (clipping, per-channel scales, bias correction, or advanced reconstruction algorithms), one can achieve substantial memory and compute savings with modest impact on model quality.

# Common algorithms used for LLM weight compression

Large language models present unique quantization challenges due to very large weight matrices, sensitivity of some layers to perturbation, and heavy‑tailed weight distributions. Several techniques have become common:

1. Per‑channel or per‑block uniform quantization with bias correction. Many toolchains quantize weights in blocks (e.g., 32–128 elements) with per‑block scales and optionally correct per‑block bias using a small calibration set. This is efficient and preserves accuracy better than per‑tensor quantization.

2. Mixed‑precision schemes. Critical layers (e.g., first and last layers, some normalization or attention projection matrices) are kept at higher precision (float16/int8) while others use lower precision (int4, int3). Sensitivity analysis determines which layers to protect.

3. Outlier handling via row/column exceptions. Some LLMs have a small number of large weights in certain rows/columns; these are stored in higher precision while the rest are quantized. This selective scheme avoids overall large scale factors.

4. GPTQ (Greedy post‑training Quantization). GPTQ approximates the loss-of-precision problem by greedily quantizing weights while minimizing the layer output reconstruction error, typically using an approximate inverse Hessian to prioritize directions that most affect outputs. It performs a sequential optimization that reconstructs quantized weights to match original outputs on a calibration set. GPTQ is widely used to produce 3-bit or 4-bit quantizations with high fidelity.

5. AWQ (Activation‑aware Weight Quantization). AWQ adjusts quantization of weights taking into account activation statistics and often uses mixed precision for blocks. It balances quantization error by considering how activations interact with weights during inference.

6. K‑means / Lloyd‑Max clustering for weight sharing. Cluster weights using k‑means per-block and store cluster indices instead of raw quantized integers. This can yield better MSE than uniform quantization for the same codebook size but increases computational complexity for reconstruction.

7. Product Quantization (PQ) and Vector Quantization (VQ). PQ splits weight vectors into sub-vectors and quantizes each sub-vector using a separate codebook. This is effective for compressing embeddings and large dense matrices and is used in some retrieval and compression applications. PQ supports very high compression ratios but complicates fast matrix multiply.

8. SmoothQuant and activation equalization. SmoothQuant rescales weights and activations between adjacent layers so that activation distributions are more amenable to quantization. By balancing scales across layers, it reduces sensitivity and allows coarser quantization with less accuracy loss.

When selecting an algorithm, consider the target bit width, latency requirements, the availability of integer GEMM kernels, memory bandwidth, and whether you can run a calibration or reconstruction pass with representative data. GPTQ-style reconstruction and per-block quantization are currently favored for LLMs when aggressive compression (3–4 bits) is required.

# Conclusion

Quantization is a powerful set of techniques for reducing the resource demands of machine learning models. Uniform quantization is simple and hardware friendly, while non‑uniform quantization can offer better fidelity for particular distributions. Choosing the granularity of scaling — per-tensor, per-channel, or block-wise — is a principal design decision that trades off metadata and accuracy. Absolute‑max scaling is straightforward but sensitive to outliers; clipping, bias correction, and mixed‑precision strategies mitigate outlier effects. Histogram and quantile-based methods provide principled ways to design non‑uniform quantizers or clipping thresholds using calibration data. In practice, an effective quantization workflow uses representative calibration, appropriate granularity, careful metadata packing, and either efficient dequantize-then-compute or integer compute paths. For LLMs, advanced PTQ methods like GPTQ and AWQ, along with per-block quantization and outlier handling, enable dramatic reductions in model size while maintaining acceptable performance. Understanding the principles and tradeoffs described here equips you to read current research and implement practical quantization pipelines for modern neural networks.

Introduction

Modern large language models (LLMs) are built from a collection of relatively simple building blocks combined in large numbers and arranged with careful patterns. Understanding these blocks — artificial neurons, linear projections, attention mechanisms, feed‑forward networks, and normalization — is essential for reading research papers about transformers and for implementing or modifying such models. This chapter introduces these components from first principles, explains how they fit together inside transformer architectures, and traces the dataflow through a single transformer block so you can see where parameters live and why models scale the way they do. I assume you are comfortable with basic linear algebra (vectors and matrices), probability, and calculus; I will make linear algebra notation explicit using LaTeX for clarity.

# Artificial neurons, layers, activations

The artificial neuron is the basic computational unit in neural networks. At its simplest, a neuron takes an input vector $x \in \mathbb{R}^d$, computes a weighted sum plus a bias, and applies a nonlinear activation function. Mathematically, a single neuron computes
\[
y = \phi(w^\top x + b),
\]
where $w \in \mathbb{R}^d$ is the weight vector, $b \in \mathbb{R}$ is the bias, and $\phi(\cdot)$ is a nonlinear activation function such as ReLU, sigmoid, or GELU. The nonlinear activation is crucial: without it, stacks of linear neurons collapse to a single linear transformation and the network cannot represent nonlinear functions.

Neurons are grouped into layers. A fully connected (dense) layer of width $m$ transforms an input vector $x \in \mathbb{R}^d$ into an output vector $y \in \mathbb{R}^m$ by applying many neurons in parallel. Using matrix form, we write
\[
y = \phi(Wx + b),
\]
where $W \in \mathbb{R}^{m \times d}$ is the weight matrix containing each neuron's weights as rows and $b \in \mathbb{R}^m$ is the bias vector. Because we apply the same weight matrix $W$ across different inputs, the layer is a parameter-sharing mechanism at the vector-to-vector level.

Common activation functions each have different properties. The Rectified Linear Unit (ReLU) is $\phi(z) = \max(0, z)$; it is simple and sparsifying (sets negative values to zero). The Gaussian Error Linear Unit (GELU) approximates a smooth gating nonlinearity and is often used in modern transformer models because of slightly better empirical performance. Sigmoid and hyperbolic tangent were popular historically but can suffer from saturation and vanishing gradients in deep networks. Choosing an activation impacts gradient flow, representational capacity, and empirical performance.

When multiple layers are composed, we obtain deep networks. A depth-2 example is
\[
h = \phi_1(W_1 x + b_1),\qquad y = \phi_2(W_2 h + b_2).
\]
Even modest-depth networks with sufficiently wide layers can approximate a wide class of functions; in practice, transformers use thousands to billions of parameters by stacking many identical blocks that combine attention and feed‑forward layers.

# Transformer architecture: encoder, decoder, and decoder‑only variants

Transformers are a neural network architecture built around attention mechanisms. They were introduced in "Attention is All You Need" and have three major architectural variants: encoder‑only, encoder‑decoder (a.k.a. sequence‑to‑sequence), and decoder‑only. Each variant is suited to different tasks.

The encoder consists of a stack of identical blocks, each block containing a self‑attention layer followed by a positionwise feed‑forward network (FFN). The encoder is typically used for tasks that require producing representations of an entire input sequence, such as sentence classification or encoding inputs for later decoding. Formally, the encoder maps an input token sequence $(x_1,\dots,x_n)$ to contextual representations $(h_1,\dots,h_n)$ where each $h_i$ has information about the whole sequence. Encoder layers are usually bidirectional: during attention, tokens can attend to all positions in the sequence, which makes them powerful for capturing full context.

The decoder extends the encoder architecture to produce output sequences conditioned on encoder representations. Each decoder block has three sublayers: masked self‑attention (preventing a position from attending to future positions), cross‑attention to the encoder outputs (allowing the decoder to condition on the input), and a feed‑forward network. This encoder‑decoder (seq2seq) design is natural for tasks like machine translation, where the model must generate an output sequence that depends on an input sequence.

Decoder‑only models are stacked transformer decoders with causal/auto‑regressive masking. In decoder‑only architectures, the model learns to predict the next token given previous tokens and can be used for text generation and completion. During training, tokens are fed in and the model is trained to predict the next token at each position using masked self‑attention that blocks access to future positions. Large language models such as GPT family are decoder‑only. Decoder‑only models can be used for conditional generation by prepending a prompt (or encoder-like representation) to the context, often combined with special tokens to separate parts.

Architecturally, each transformer block (in encoder or decoder) repeats a pattern: attention, residual connection, normalization, feed‑forward, residual connection, normalization. The residual connections (add the block input to the output) and layer normalization are crucial for stable training at scale. The specific ordering of normalization (pre‑norm vs post‑norm) and exact placement of dropout and layer scaling can vary across implementations and can affect convergence.

# Scaled dot‑product attention and multi‑head attention

Scaled dot‑product attention is the core operation that gives transformers their ability to dynamically route information between positions in a sequence. Given query vectors $Q \in \mathbb{R}^{n_q \times d_k}$, key vectors $K \in \mathbb{R}^{n_k \times d_k}$, and value vectors $V \in \mathbb{R}^{n_k \times d_v}$, the attention output is computed as
\[
\mathrm{Attention}(Q, K, V) = \mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right) V.
\]
Intuitively, each query computes similarity scores with all keys via dot product. The scaling factor $1/\sqrt{d_k}$ prevents the dot products from growing too large in magnitude when $d_k$ is large, which would push the softmax into regions with tiny gradients. The softmax turns similarities into a distribution of weights that sum to 1 across keys; the output is a weighted sum of the value vectors using those attention weights. In self‑attention, the same sequence provides queries, keys, and values (so $Q=K=V$).

Multi‑head attention extends this basic idea by computing several attention operations in parallel, called heads. For $h$ heads, the input $X \in \mathbb{R}^{n \times d_\text{model}}$ is linearly projected $h$ times into query, key, and value subspaces:
\[
Q_i = X W_i^Q,\qquad K_i = X W_i^K,\qquad V_i = X W_i^V,\qquad i=1,\dots,h,
\]
where $W_i^Q, W_i^K \in \mathbb{R}^{d_\text{model}\times d_k}$ and $W_i^V \in \mathbb{R}^{d_\text{model}\times d_v}$. Each head computes attention as above to produce outputs $O_i \in \mathbb{R}^{n\times d_v}$. The outputs are concatenated and projected with an output matrix $W^O \in \mathbb{R}^{hd_v \times d_\text{model}}$ to form the final result:
\[
\mathrm{MultiHead}(X) = \mathrm{Concat}(O_1,\dots,O_h) W^O.
\]
Multi‑head attention allows the model to attend to different types of relationships or positions simultaneously because each head has its own projection subspace and can learn distinct patterns. For example, in language tasks one head might focus on short-range syntactic relations while another captures long‑range coreference.

Masking is important for decoder settings where we require causality: the attention softmax is modified with a mask that sets logits for forbidden (future) positions to $-\infty$ so that after softmax they receive zero probability. Numerically, this is implemented by adding a large negative number before softmax.

# Position embeddings and tokenization basics

Attention is permutation‑invariant: if we feed tokens in a different order, self‑attention without positional information would process them the same way. To encode order, transformers add position information to token representations. There are two main styles: absolute positional embeddings and relative positional encodings.

Absolute positional embeddings associate each position index $p$ with a learned vector $e_p \in \mathbb{R}^{d_\text{model}}$ and add this vector to the token embedding at that position:
\[
x_p = \text{TokenEmbed}(t_p) + e_p.
\]
These embeddings can be learned parameters (one vector per position up to a maximum sequence length), or fixed functions such as sinusoidal position encodings introduced in the original transformer paper. Learned embeddings often perform better in practice for very large models.

Relative positional encodings represent position differences between query and key positions, allowing attention to depend on the relative distance rather than absolute indices. These can be implemented by modifying attention logits with additional terms that depend on $i-j$ or by augmenting key and value projections. Relative encodings can improve generalization to sequences longer than training data.

Tokenization converts raw text into discrete symbols (tokens) suitable for model input. Modern LLMs commonly use subword tokenization schemes such as Byte-Pair Encoding (BPE), SentencePiece, or Unigram tokenizers. These methods segment text into variable-length subword units so that common words appear as single tokens, rare words are split into multiple subwords, and the tokenizer can represent any text with a finite vocabulary. Tokenizers map characters/strings to integer token IDs. Those IDs are then embedded into continuous vectors by a token embedding matrix $E \in \mathbb{R}^{|V|\times d_\text{model}}$ where $|V|$ is vocabulary size. Typically a special token such as padding, start, or end-of-sequence is also part of the vocabulary.

Careful tokenizer design impacts downstream performance, model efficiency, and the distribution of sequence lengths. For example, character‑level tokenization yields long sequences but a small vocabulary; subword tokenization balances vocabulary size and sequence length and is why many LLMs work well with token budgets around a few thousand tokens.

# Feed‑forward/MLP blocks and layer normalization

In a transformer block, the feed‑forward network (FFN) — often called the "MLP" — is applied independently at each position (positionwise). The canonical FFN used in transformers has two linear layers with a nonlinear activation between them:
\[
\mathrm{FFN}(x) = W_2 \,\phi(W_1 x + b_1) + b_2,
\]
where $W_1 \in \mathbb{R}^{d_\text{ff}\times d_\text{model}}$, $W_2 \in \mathbb{R}^{d_\text{model}\times d_\text{ff}}$, and $d_\text{ff}$ is typically several times larger than $d_\text{model}$ (common choices are $d_\text{ff}=4d_\text{model}$ or similar). This bottleneck structure — expanding to a larger intermediate dimension and then projecting back — gives the network capacity to implement complex, nonlinear transformations at each token position independently.

The FFN contributes significantly to a transformer's parameter count because $W_1$ and $W_2$ are large dense matrices. The intermediate activation is applied elementwise, so the computation is parallel across positions and easy to implement efficiently with matrix multiplications batched across sequence length.

Layer normalization (LayerNorm) is crucial to stabilizing training in transformers. LayerNorm normalizes activations across the feature dimension for each position, maintaining per‑sample means and variances. Given an input vector $x \in \mathbb{R}^{d}$ for a position, LayerNorm computes
\[
\mu = \frac{1}{d}\sum_{i=1}^d x_i,\qquad
\sigma^2 = \frac{1}{d}\sum_{i=1}^d (x_i-\mu)^2,
\]
then normalizes and scales:
\[
\mathrm{LayerNorm}(x) = \gamma \frac{x-\mu}{\sqrt{\sigma^2+\epsilon}} + \beta,
\]
where $\gamma$ and $\beta$ are learned scale and shift parameters of dimension $d$, and $\epsilon$ is a small constant for numerical stability. LayerNorm differs from BatchNorm in that it does not depend on batch statistics and thus works well for variable sequence lengths and autoregressive generation.

Two styles of applying LayerNorm are frequently used: "post‑norm" (original transformer) places LayerNorm after each sublayer and its residual addition, while "pre‑norm" places LayerNorm before the sublayer. Pre‑norm variants tend to be easier to train for very deep models because they help keep gradients well behaved. Many modern LLMs adopt pre‑norm ordering.

# Typical parameter counts and where parameters are concentrated (e.g., projection matrices)

Transformer models' parameter counts scale rapidly with model depth (number of layers $L$) and width ($d_\text{model}$). A typical transformer block contains the following parameter groups:

1. Attention projection matrices: For multi‑head self‑attention with $h$ heads and per‑head dimension $d_k=d_v=d_\text{head}$, we have projection matrices $W^Q, W^K, W^V \in \mathbb{R}^{d_\text{model}\times hd_\text{head}}$ if implemented as concatenated projections, or equivalently $3$ separate matrices of size $d_\text{model}\times d_\text{model}$ when $hd_\text{head}=d_\text{model}$. There is also the output projection $W^O \in \mathbb{R}^{d_\text{model}\times d_\text{model}}$. Combined, attention projections contribute on the order of $4d_\text{model}^2$ parameters per layer (more precisely $3d_\text{model}\times d_\text{model}+d_\text{model}\times d_\text{model}$ when $d_\text{model}=hd_\text{head}$).

2. Feed‑forward networks: The FFN has $W_1 \in \mathbb{R}^{d_\text{ff}\times d_\text{model}}$ and $W_2 \in \mathbb{R}^{d_\text{model}\times d_\text{ff}}$. Together these contribute $2 d_\text{model} d_\text{ff}$ parameters per layer, which is often the largest single contributor because $d_\text{ff}$ is typically larger than $d_\text{model}$ by a factor (e.g., 4x). So FFNs often dominate parameter count.

3. LayerNorm parameters and biases: LayerNorm adds $2 d_\text{model}$ parameters per normalization (scale and shift), and biases in linear layers add further small counts; these are negligible relative to the matrices above.

4. Token embedding and output logits: The token embedding matrix has size $|V|\times d_\text{model}$. For large vocabularies, this can be substantial. In many models the token embedding is tied to the final linear layer that maps hidden states to logits, saving parameters: the same matrix $E$ is used for input embedding and output projection (transposed), which reduces overall parameter count.

Putting numbers to these formulas: a transformer with $L$ layers and model dimension $d$ will have about
\[
\text{Params} \approx |V|d + L(8d^2 + 2d d_\text{ff})
\]
depending on exact implementation (the factor 8 accounts for concatenated QKV, output projection, and possibly other linear layers; precise constants vary). For example, a modest model with $d=768$, $L=12$, $d_\text{ff}=3072$ (the base BERT configuration) has on the order of 110 million parameters; a larger model with $d=3072$, $L=24$, $d_\text{ff}=12{,}288$ will have many times more.

Where are the parameters concentrated? Primarily in dense projection matrices: the attention Q/K/V/O matrices and the FFN $W_1$, $W_2$. Because these are dense matrices with sizes proportional to $d^2$ or $d d_\text{ff}$, as $d$ grows the parameter budget is dominated by them. Embedding matrices and softmax layers can also be large, particularly with a large vocabulary; tying embeddings helps mitigate that.

Understanding this concentration helps explain why research on efficient transformers focuses on reducing projection sizes, introducing low‑rank approximations, sparsity, or factorized representations — these target the matrices that hold most parameters.

# Forward pass dataflow in a transformer block

To see how these parts work together during inference or training, consider the forward pass through a single transformer block in a decoder‑only (causal) model using pre‑norm ordering. Let $X \in \mathbb{R}^{n \times d}$ be the matrix of input token representations for a sequence of length $n$, where each row $x_t$ is a $d$‑dimensional vector. The block computes the next representations $X' \in \mathbb{R}^{n \times d}$ by performing the following steps.

1. Layer normalization (pre‑norm) on the input:
\[
\tilde{X} = \mathrm{LayerNorm}(X),
\]
applied independently to each row.

2. Multi‑head self‑attention. Compute linear projections for queries, keys, and values:
\[
Q = \tilde{X} W^Q,\qquad K = \tilde{X} W^K,\qquad V = \tilde{X} W^V,
\]
with shapes $Q,K \in \mathbb{R}^{n\times d}$, $V \in \mathbb{R}^{n\times d}$. Reshape or split into $h$ heads to shape $(n, h, d_\text{head})$. For each head compute scaled dot‑product attention with causal masking:
\[
A = \mathrm{softmax}\!\left(\frac{Q K^\top}{\sqrt{d_\text{head}}} + M\right),
\]
where $M$ is a mask matrix with $M_{ij}=-\infty$ for $j>i$ (future positions) and $0$ otherwise. Then compute head outputs and concatenate:
\[
O = \mathrm{Concat}(A V) \in \mathbb{R}^{n\times d}.
\]
Project the concatenated output:
\[
\mathrm{AttnOut} = O W^O.
\]
3. Residual connection after attention:
\[
X_1 = X + \mathrm{AttnOut}.
\]
This addition preserves the original signal and allows gradients to pass more directly across many layers.

4. Second LayerNorm:
\[
\tilde{X}_1 = \mathrm{LayerNorm}(X_1).
\]
5. Positionwise feed‑forward network:
\[
\mathrm{FFNOut} = W_2 \,\phi(W_1 \tilde{X}_1 + b_1) + b_2,
\]
applied independently to each position (matrix multiplication across the batch/sequence dimension).

6. Residual connection after FFN:
\[
X' = X_1 + \mathrm{FFNOut}.
\]
The output $X'$ then becomes the input to the next block, or — if this is the final block — is passed through a final LayerNorm and an output head to compute logits for token prediction.

Tracing shapes and computational costs: the dominant operations are matrix multiplications. For sequence length $n$, model dimension $d$, and feed‑forward hidden size $d_\text{ff}$, the cost per layer is roughly $O(n d^2 + n d d_\text{ff})$ flops (floating point operations) because attention involves $QK^\top$ which costs $O(n^2 d)$ if implemented naively; however, the $n^2$ term comes from the attention softmax over pairs of positions. For autoregressive generation where $n$ may grow, attention cost can be significant. Many approximate attention methods exist to reduce the quadratic dependence for very long sequences.

Where parameters are read/written during the forward pass matches the parameter concentration discussion: attention projection matrices $W^Q, W^K, W^V, W^O$ and feed‑forward matrices $W_1, W_2$ are the main parameter users. Embeddings are used at the input to produce $X$ initially, and the final output projection (often tied to embeddings) converts hidden vectors to logits over vocabulary tokens.

Understanding the forward pass at this level makes clear why transformers are amenable to efficient implementation: operations are dominated by large, dense matrix multiplications that map well to GPUs and TPUs, and positionwise FFNs are parallel across sequence positions. It also highlights the key bottlenecks (attention's $n^2$ memory/time for long sequences, and large matrix storage for parameters) that motivate ongoing research.

Introduction

Policy gradient methods are a central class of algorithms for optimizing parametric policies directly with respect to expected reward. In the context of language models (LMs), these methods enable fine-tuning a generative model to produce text that maximizes human preferences, task-specific metrics, or other reward signals that are not decomposable into supervised loss. This chapter explains practical policy gradient techniques and the variance control mechanisms that make these methods usable in real LM training. We begin with the foundational REINFORCE estimator and then build progressively: introducing baselines and control variates, discussing value functions and advantage estimation, and covering reward normalization. Because tokens are the atomic actions in LM policy optimization, we devote substantial attention to credit assignment across tokens. We examine different gradient estimators and the variance–bias trade-offs they expose, and cover stochastic approximation and sample-efficiency considerations crucial for computationally expensive LM training. The chapter finishes with common stability tricks — such as clipping — and pragmatic diagnostics and debugging strategies to apply during RL training.


# REINFORCE with baselines and control variates

The REINFORCE algorithm is the simplest unbiased Monte Carlo policy gradient estimator. Let the policy be parameterized by $\theta$ and define a trajectory of tokens (or actions) $\tau = (a_1, a_2, \dots, a_T)$ drawn from the policy $p_\theta(\tau)$. Suppose we have a scalar reward function $R(\tau)$ that assigns a return to the whole trajectory. The objective is the expected return
\[
J(\theta) = \mathbb{E}_{\tau \sim p_\theta}[R(\tau)].
\]
REINFORCE uses the identity $\nabla_\theta \log p_\theta(\tau) = \sum_{t=1}^T \nabla_\theta \log \pi_\theta(a_t \mid a_{<t})$ and produces the Monte Carlo gradient estimator
\[
\hat{g}_\text{REINFORCE} = R(\tau)\, \nabla_\theta \log p_\theta(\tau) = R(\tau) \sum_{t=1}^T \nabla_\theta \log \pi_\theta(a_t \mid a_{<t}).
\]
This estimator is unbiased: its expectation equals the true gradient $\nabla_\theta J(\theta)$. The difficulty is that it often has very high variance. High variance leads to noisy parameter updates, slow learning, and instability.

A standard variance-reduction trick is to subtract a baseline that does not depend on the action but may depend on the state or context. If $b$ is any scalar function independent of the actions, then
\[
\mathbb{E}_{\tau}\big[(R(\tau) - b)\nabla_\theta \log p_\theta(\tau)\big] = \nabla_\theta J(\theta),
\]
so the estimator remains unbiased. A common choice is a state-dependent baseline $b(s)$ or a context-dependent baseline $b(x)$, where $x$ is the prompt or input text for an LM. Subtracting a baseline reduces variance by removing common-mode variability in returns.

Control variates generalize baselines. A control variate is any function $c(\tau)$ with known expectation (often zero) that is correlated with the noisy estimator; one subtracts it and adds back the known expectation to maintain unbiasedness. In the REINFORCE context, one can use a learned control variate that approximates the expected return and tune a coefficient $\alpha$ to minimize variance. Specifically, if $C(\tau)$ is a control variate, consider the estimator
\[
\hat{g} = \big(R(\tau) - \alpha C(\tau)\big)\nabla_\theta \log p_\theta(\tau) + \alpha\, \nabla_\theta \mathbb{E}[C(\tau)],
\]
where $\alpha$ may be chosen analytically (via regression) or learned. The practical takeaway is that effective baselines and control variates drastically improve convergence by reducing the stochasticity of gradient estimates.

When applying these ideas to LMs, the baseline often depends on the input prompt and possibly on prefix tokens. A learned baseline can be implemented as a separate value network or as a head on the LM that predicts expected reward; learning this baseline requires its own regression objective and introduces coupling between the policy and baseline but yields substantial variance reduction in practice.


# Value functions and advantage estimation

Value functions formalize the expected future reward from a state or partial sequence. For sequence generation, define the state at time $t$ as the prefix $s_t = a_{<t}$ plus any external context. The state-value function is
\[
V^\pi(s_t) = \mathbb{E}_{\tau \sim \pi}\big[ R(\tau) \mid s_t\big],
\]
which gives the expected return conditioned on the prefix, under policy $\pi$. The action-value function or Q-function is
\[
Q^\pi(s_t, a_t) = \mathbb{E}_{\tau \sim \pi}\big[ R(\tau) \mid s_t, a_t\big],
\]
which is the expected return after taking action $a_t$ in state $s_t$ and following policy $\pi$ afterwards. The key quantity for variance reduction and more informative updates is the advantage function:
\[
A^\pi(s_t, a_t) = Q^\pi(s_t, a_t) - V^\pi(s_t).
\]
Intuitively, the advantage measures how much better (or worse) an action is compared to the average action at that state.

Using advantages in the policy gradient, rather than raw returns, moves from a global credit signal to a local, action-specific one. The policy gradient identity becomes
\[
\nabla_\theta J(\theta) = \mathbb{E}\Big[\sum_{t=1}^T A^\pi(s_t, a_t) \nabla_\theta \log \pi_\theta(a_t \mid s_t)\Big],
\]
assuming the advantage is computed appropriately. Advantage-based gradients typically have far lower variance than using the full return at every time step because subtracting $V^\pi(s_t)$ removes the predictable component of the return given the state.

In practice, both $V^\pi$ and $Q^\pi$ are unknown and must be estimated. Commonly, a parametric value function $V_\phi(s)$ is learned by minimizing a squared error regression target against Monte Carlo returns or bootstrapped targets. For sequence generation with sparse or delayed rewards, Monte Carlo returns may be extremely noisy, motivating the use of temporal-difference (TD) methods and bootstrapping to stabilize learning; e.g., estimating $V_\phi(s_t)$ against observed rewards plus discounted $V_\phi(s_{t+k})$ values.

Another practical approach is to use generalized advantage estimation (GAE), which interpolates between high-variance, low-bias Monte Carlo advantages and low-variance, higher-bias TD advantages. GAE constructs advantages as exponentially-weighted sums of TD residuals:
\[
\hat{A}_t^{\text{GAE}(\gamma,\lambda)} = \sum_{l=0}^{T-t} (\gamma\lambda)^l \delta_{t+l},
\]
where $\delta_t = r_t + \gamma V_\phi(s_{t+1}) - V_\phi(s_t)$, and $\gamma$ is a discount factor (often set to $1$ for episodic tasks). The parameter $\lambda \in [0,1]$ trades bias and variance: $\lambda=1$ recovers Monte Carlo returns, and $\lambda=0$ yields single-step TD. GAE is widely used because it allows controlling variance without introducing too much bias.

For LMs, rewards are often non-Markovian and defined only at the end (e.g., human preference over the whole response). Nonetheless, prefix-dependent value functions still reduce variance: $V_\phi$ conditioned on the prompt and prefix predicts the expected final reward, and advantage estimates are formed by subtracting this baseline from the final return or by distributing the final return back over tokens using GAE-like constructions adapted to the episodic nature of generation.


# Reward normalization and standardization

Raw rewards in LM fine-tuning can vary in scale, sign, and distribution across prompts, making optimization unstable. Reward normalization refers to transforming rewards to stabilize gradients and make hyperparameters more portable. One simple and effective technique is per-batch standardization: subtracting the mean reward in a batch and dividing by the standard deviation, so that the transformed rewards have zero mean and unit variance across the sampled trajectories. Formally, for a batch of returns $\{R_i\}$ compute
\[
\tilde{R}_i = \frac{R_i - \bar{R}}{\sigma_R + \epsilon},
\]
where $\bar{R}$ and $\sigma_R$ are the batch mean and standard deviation, and $\epsilon$ is a small constant to avoid division by zero. Using $\tilde{R}_i$ in the gradient estimator helps keep the magnitude of updates consistent and prevents very large rewards from dominating early optimization steps.

Normalization can be done globally (running mean and variance across training) or per-batch. Global normalization is more consistent but requires careful warmup and handling of nonstationarity as the policy changes. Per-batch normalization is simpler and reacts to current batch statistics, but it may introduce additional noise because the normalization depends on the same sampled returns used for gradients. Either way, centering rewards (subtracting mean) removes a component that corresponds to a baseline and reduces gradient variance.

Another useful transformation is reward clipping: saturating rewards to a fixed range, e.g., truncating to $[-1,1]$. Clipping prevents outliers from producing huge gradient magnitudes. However, clipping changes the objective, potentially biasing learning toward treating moderate and extreme successes equally. Therefore clipping is best used as a stability measure early in training or in cases where reward outliers are artefacts rather than meaningful signals.

In some LM applications, reward scales differ across prompts or tasks. Per-prompt normalization or scaling by an estimate of difficulty can help. For example, one may divide a reward by a baseline difficulty estimate or rescale rewards to lie in a similar numeric range across prompts. When using learned value baselines, it is common to standardize the advantage estimates produced by subtracting the value and dividing by the running standard deviation of advantages, which stabilizes the step sizes applied through the policy gradient.


# Credit assignment across tokens

Language generation is a sequential decision problem where each token selection influences later tokens and ultimately the final reward. Credit assignment across tokens asks: how much did each token contribute to the final reward? Effective credit assignment is critical for sample-efficient learning and for avoiding degenerate updates that change unimportant early tokens while ignoring important later tokens (or vice versa).

If the reward is only observed at the end of the generated sequence, the naive REINFORCE estimator attributes the entire return to every action equally via the shared factor $R(\tau)$ in the gradient. This leads to inefficient updates because it cannot distinguish which tokens were responsible for the high or low reward. Advantage estimation helps by introducing prefix-dependent baselines $V_\phi(s_t)$, but creating informative baselines for prefixes requires expressive value functions and sufficient data.

Temporal-difference and GAE-style methods provide a principled way to propagate credit backward across time. Using TD residuals, we can decompose the final return into incremental advantages associated with transitions. For example, if rewards can be defined or approximated at intermediate steps (e.g., via heuristics, auxiliary models, or shaping functions), then those intermediate rewards create signal closer in time to the responsible actions. Even when intermediate rewards are absent, one can use learned critic bootstrapping to produce sensible temporal structure: the critic predicts expected final reward given a prefix, and TD errors measure how passing from one prefix to the next changes that expectation.

A practical LM-specific tactic is to use token-level or span-level reward models that estimate token contributions. For instance, if a reward model is differentiable or can provide dense feedback per token (for example, via a difference in predicted scores when including or excluding a span), then one can build action-specific rewards that sharpen credit assignment. Another approach is reward shaping: define intermediate rewards that are heuristically correlated with the final objective (such as length control, presence of required keywords, or per-sentence quality scores). Reward shaping must be used carefully because shaping can change the optimal policy; potential-based shaping methods can be used to ensure the optimal policy remains unchanged.

From an implementation perspective, it is common to weight token-wise policy gradients by an advantage estimate computed for that token or prefix. If the final reward is $R$ and the learned value at prefix $t$ is $V_\phi(s_t)$, a simple per-token advantage is $R - V_\phi(s_t)$, applied to $\nabla_\theta \log \pi_\theta(a_t|s_t)$. This distributes the final feedback across tokens in a way that credits tokens whose prefixes had low value predictions more and penalizes those with unexpectedly high predictions. In sum, improving credit assignment requires either richer reward signals, better learned critic models, or algorithmic mechanisms like GAE to distribute reward over time.

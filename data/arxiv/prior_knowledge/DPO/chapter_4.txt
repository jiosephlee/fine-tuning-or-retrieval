Introduction

Transformers are the dominant neural network architecture for language modeling and many other sequence tasks. Introduced in 2017, the transformer replaced recurrent and convolutional structures with a simple, scalable mechanism called self‑attention. This chapter explains the internal components of transformers, how they are assembled into encoder, decoder, or decoder‑only models, and why those choices matter. We then describe the typical pretraining objectives used to teach a transformer the structure of language, the characteristics of the large datasets used in practice, and how pretraining produces broad, reusable capabilities that can be adapted through fine‑tuning and instruction tuning. Finally, we cover several practical engineering considerations that arise when training and serving transformers at large scale: batching long sequences, memory usage, and computational tradeoffs. Throughout, the emphasis is on building intuition and mathematical clarity so you can read research papers and understand design decisions in modern language models.

# Self‑attention mechanism and multi‑head attention

Self‑attention is the core operation that gives transformers their power: it lets every position in a sequence dynamically attend to other positions when computing a new representation for that position. At a high level, for each position we compute a weighted sum of value vectors from all positions, where the weights are determined by similarity between a query vector from the target position and key vectors from the source positions. This mechanism replaces recurrence: dependency modeling is done through direct pairwise interactions in a single layer.

Concretely, suppose an input sequence of length $n$ is represented by a matrix of token embeddings $X \in \mathbb{R}^{n \times d}$. For a single attention head we linearly project $X$ to obtain queries $Q$, keys $K$, and values $V$:
$Q = XW_Q$, $K = XW_K$, $V = XW_V$,
where $W_Q, W_K, W_V \in \mathbb{R}^{d \times d_k}$ and $d_k$ is the per‑head key/query dimensionality (often $d_k = d / h$, where $h$ is the number of heads). The raw attention logits are the scaled dot‑products between queries and keys:
$A = QK^\top / \sqrt{d_k}$.
We apply softmax row‑wise to obtain attention weights:
$\text{AttentionWeights} = \text{softmax}(A)$,
and finally compute the head output as
$\text{Head} = \text{softmax}(A) V$.
The scaling factor $1/\sqrt{d_k}$ prevents the dot products from growing too large in magnitude as $d_k$ grows, which would make softmax gradients vanish.

Multi‑head attention runs several attention heads in parallel, each with its own projection matrices, and concatenates their outputs:
$\text{MultiHead}(X) = \text{Concat}(\text{Head}_1, \dots, \text{Head}_h) W_O$,
where $W_O \in \mathbb{R}^{hd_k \times d}$ maps the concatenation back to the model dimension. The intuition behind multiple heads is twofold. First, different heads can learn to focus on different types of relationships (syntactic roles, coreference, local vs. global patterns). Second, each head has a lower dimensional subspace ($d_k$) which makes the attention computation more tractable and encourages specialization. Empirically, increasing the number of heads often improves representational richness up to a point; beyond that, adding parameters may be better invested in width, depth, or training data.

Self‑attention is permutation‑sensitive because the positions are embedded and later combined with positional signals (discussed in the next section), but within a single layer the mechanism can directly model long‑range dependencies without the stepwise propagation that recurrent networks require. This leads to more parallelizable computation during training and often faster learning of global structure.

# Positional encodings and layer structure (encoder/decoder/decoder‑only)

Self‑attention alone is invariant to permutations of the input sequence: if you shuffle the rows of $X$, the pairwise dot products and resulting attention remain consistent up to the same permutation, so the model would not know token order. Language has order, so transformers augment token embeddings with positional information.

One widely used method is sinusoidal positional encodings: add to each token embedding a deterministic vector whose components are sinusoidal functions of position. For position $p$ and dimension index $i$,
$\text{PE}(p, 2i) = \sin\!\left(p / 10000^{2i/d}\right)$ and
$\text{PE}(p, 2i+1) = \cos\!\left(p / 10000^{2i/d}\right)$.
These continuous, unlearned encodings allow the model to extrapolate to longer sequences and to compute relative position information through linear transformations. Another approach is learned positional embeddings: a learned table of $n_{\max}$ vectors, one per position up to a maximum length, which are added to token embeddings. Learned embeddings can be more flexible but may not generalize to positions beyond the training range.

Relative positional encodings are a family of methods that encode distances between tokens rather than absolute positions. One popular variant modifies attention logits with learnable relative bias terms that depend on pairwise distance, enabling the model to focus on relative ordering and enabling better generalization to longer sequences for some tasks. More recent techniques include rotary positional embeddings (RoPE), which apply position‑dependent rotations to the query/key projections, preserving desirable algebraic properties for extrapolation.

Transformers are organized into layers, and there are three canonical architectures used in practice: encoder‑only, encoder‑decoder (also called “sequence‑to‑sequence” or “seq2seq”), and decoder‑only.

An encoder stack (as in BERT) consists of several transformer encoder layers that compute contextualized representations for all input positions in parallel. Each encoder layer has self‑attention that can attend to all positions (bidirectional attention), followed by a feedforward network. Encoder stacks are well suited to tasks where the model needs to process an entire text and produce a representation (classification, sequence tagging, embedding extraction).

A decoder stack (as in GPT family) is a stack of transformer decoder layers used autoregressively. Each layer contains masked self‑attention: when predicting the token at position $t$, attention is restricted to positions $\le t$ to prevent peeking at future tokens. Masking enforces a causal factorization of the joint distribution $p(x_1, \dots, x_n) = \prod_{t=1}^n p(x_t \mid x_{<t})$. Decoder‑only architectures are natural for causal language modeling, generation, and many prompting paradigms.

The encoder‑decoder (seq2seq) architecture (as in the original Transformer and many translation models) has an encoder stack that processes the source sequence and produces contextual representations, and a decoder stack that generates the target sequence autoregressively while attending to encoder outputs. Each decoder layer has three blocks: masked self‑attention over previous target tokens, cross‑attention over encoder outputs, and a feedforward network. This structure is ideal when inputs and outputs are distinct modalities or when bidirectional context on the inputs aids prediction on the outputs.

Choice of architecture depends on the task and objective. Encoder‑only models are strong for discriminative tasks; decoder‑only models are convenient for open‑ended generation and instruction following; encoder‑decoder models shine in supervised sequence transformation where cross‑attention provides a clear mechanism to condition generation on inputs.

# Feedforward networks, layer normalization, residual connections

Inside each transformer layer, after self‑attention, there is a positionwise feedforward network (FFN) that applies the same two‑layer MLP independently to each sequence position. The standard form is
$\text{FFN}(x) = \text{GELU}(xW_1 + b_1)W_2 + b_2$,
where $W_1 \in \mathbb{R}^{d \times d_{ff}}$, $W_2 \in \mathbb{R}^{d_{ff} \times d}$, and $d_{ff}$ (the inner dimension) is typically several times larger than $d$ (for example, $d_{ff} \approx 4d$). The FFN increases the model’s capacity to form complex, positionwise nonlinear transformations that attention alone cannot express. Because it operates independently on each position, the FFN scales computation linearly with sequence length and is highly parallelizable.

Transformers use residual (skip) connections and normalization to stabilize and accelerate training. In a canonical layer, the input $x$ is fed into an attention block and a feedforward block with residuals and layer normalization applied around each block. There are two common variants: “post‑norm” and “pre‑norm.” In post‑norm (original transformer), computations are:
$y = x + \text{AttentionLayer}(\text{LayerNorm}(x))$,
$z = y + \text{FFN}(\text{LayerNorm}(y))$.
In pre‑norm, layer normalization is applied before the sublayer:
$y = x + \text{Attention}(\text{LayerNorm}(x))$,
$z = y + \text{FFN}(\text{LayerNorm}(y))$.
Pre‑norm architectures tend to yield more stable training for very deep transformers because gradients can flow more directly through the residual paths.

Layer normalization computes statistics over the feature dimension of a single token representation, normalizing to zero mean and unit variance and then applying learned scale and shift parameters. For a token vector $u \in \mathbb{R}^{d}$,
$\text{LayerNorm}(u) = \gamma \odot \frac{u - \mu}{\sqrt{\sigma^2 + \epsilon}} + \beta$,
with $\mu$ and $\sigma^2$ the mean and variance of $u$’s components, and $\gamma, \beta \in \mathbb{R}^{d}$ learned. LayerNorm helps smooth optimization and reduces covariate shift across layers.

Residual connections allow each layer to modify rather than completely overwrite representations. This alleviates degradation of information through depth and supports iterative refinement: shallower layers can preserve low‑level patterns while deeper layers add higher‑level features. The combination of residuals and normalization is essential for enabling training of very deep stacks of attention/FFN layers.

# Pretraining objectives (causal LM, masked LM) and large‑scale datasets

Pretraining is the process of exposing a transformer model to large amounts of unlabeled text with an unsupervised objective so the model learns statistical regularities of language. Two dominant pretraining objectives are causal language modeling and masked language modeling.

Causal language modeling (CLM) trains a decoder‑only model to predict the next token given previous tokens. For a sequence $x_1, \dots, x_n$, the loss is the negative log probability
$L = -\sum_{t=1}^n \log p(x_t \mid x_{<t})$.
This objective directly trains the model to generate text autoregressively, making it natural for tasks that require sampling or conditional generation. CLM leverages the full joint probability factorization and requires masked self‑attention to enforce causality. Models trained with CLM (e.g., GPT family) often perform well as few‑shot learners when used with prompting.

Masked language modeling (MLM) trains an encoder (or encoder side of a seq2seq model) to predict masked tokens given a bidirectional context. In the common BERT setup, a subset of input tokens are replaced with a special mask token or with random tokens, and the model is trained to predict the original tokens at the masked positions. The MLM loss for masked positions $M$ is
$L = -\sum_{t \in M} \log p(x_t \mid x_{\setminus M})$,
where $x_{\setminus M}$ denotes the unmasked tokens. MLM allows the model to use both left and right context, which yields strong performance on many discriminative tasks after fine‑tuning. A related objective, replaced token detection (e.g., ELECTRA), asks the model to distinguish real tokens from tokens replaced by a small generator, and can provide more efficient learning at similar compute.

Sequence‑to‑sequence pretraining can use variants such as denoising objectives (e.g., MASS, BART, T5): parts of the input are corrupted (masked spans, deletion, infilling), and the model is trained to reconstruct the original text autoregressively. These objectives combine benefits of bidirectional understanding (encoder) and autoregressive generation (decoder), and they have been effective for many generation tasks.

Large‑scale datasets used for pretraining typically aggregate diverse text sources: web crawls (Common Crawl and derivative corpora), books, news, Wikipedia, code repositories, and curated high‑quality datasets. Scaling laws show that more data, wider models, and longer training steps generally improve performance, but there are diminishing returns and practical tradeoffs with compute and data quality. Data cleaning, deduplication, and filtering of low‑quality or toxic content are important engineering decisions because noisy data can hinder model behavior and safety.

Because data is finite, data sampling strategies matter: mixing high‑quality and broad coverage corpora with tuned weights prevents dominance by web noise and encourages robustness. In some large models, training uses trillions of tokens; in others, efficient objectives (like ELECTRA) or better data curation are used to attain similar performance with fewer tokens.

# Transfer via fine‑tuning and instruction tuning

Pretrained transformers produce general representations that can be adapted to downstream tasks via transfer learning. The simplest approach is fine‑tuning: initialize the model with pretrained weights and continue gradient‑based training on a labeled downstream dataset with a task‑specific head (classification layer, sequence decoder, etc.). Because the pretrained weights provide a strong prior, fine‑tuning often achieves high performance with limited labeled data and fewer training steps compared to training from scratch.

For encoder‑only models, fine‑tuning often adds a classification head on top of the pooled output or token representations. For seq2seq models, fine‑tuning is performed by training the decoder to produce target sequences conditioned on inputs. For decoder‑only models, fine‑tuning adapts the generation behavior; techniques include appending task descriptions or special tokens to the context to steer outputs. Careful tuning of learning rates, regularization, and checkpointing is required to avoid catastrophic forgetting or overfitting.

Instruction tuning is a specialized fine‑tuning procedure that adapts large pretrained generative models to follow human instructions. The model is fine‑tuned on datasets consisting of natural language instructions paired with desired responses, enabling it to generalize to new instruction formats. Instruction tuning changes the model from a generic text predictor into one that is responsive to prompts and more controllable. This adaptation often improves usefulness, reduces undesired outputs, and enables few‑shot or zero‑shot task generalization when used with prompting.

Supervised fine‑tuning can be further improved with reinforcement learning from human feedback (RLHF). In RLHF, human annotators rank model outputs for a set of prompts. A reward model is trained to predict these rankings, and the base language model is fine‑tuned with reinforcement learning (e.g., Proximal Policy Optimization) to maximize expected reward, aligning outputs with human preferences. RLHF can significantly improve helpfulness and reduce harmful or irrelevant outputs, but it also introduces complexities in training stability, reward hacking, and the need for careful human supervision.

Transfer success depends on model scale, the similarity between pretraining and target tasks, and the size/quality of labeled data. In many cases, larger pretrained models require fewer task‑specific labeled examples to reach good performance, a phenomenon sometimes referred to as emergent few‑shot learning.

# Practical aspects: batching long sequences, memory and compute

When training or serving transformers, sequence length and batch size interact strongly with memory and compute. Self‑attention has time and memory complexity quadratic in sequence length: computing $QK^\top$ for a sequence of length $n$ costs $O(n^2 d_k)$ operations and memory for $O(n^2)$ attention logits. This quadratic scaling makes long sequences expensive. Several practical strategies mitigate this.

1. Truncation and sliding windows. In many tasks, you truncate inputs to a maximum length or use a sliding window to break long documents into overlapping chunks. Sliding windows preserve local context but lose long‑range context across chunk boundaries unless overlapping windows and aggregation are used.

2. Sparse and efficient attention. Numerous architectures approximate full attention with sparse patterns (local windows, strided attention, routing) or factorized representations (Linformer, Performer, Longformer). These methods reduce complexity to near linear in $n$ for certain operations but often trade off full global context, model capacity, or require engineering effort to maintain performance across tasks.

3. Memory‑efficient attention implementations. Optimized kernels for attention reduce peak memory by recomputing intermediate values during backpropagation (checkpointing) or using streaming/batched attention that shards computation across devices. FlashAttention is an example of an optimized attention kernel that reduces memory usage and increases throughput by reordering computation and exploiting GPU memory hierarchies.

4. Mixed precision and optimizer states. Training at mixed precision (FP16 or BFLOAT16 with FP32 master weights) reduces memory and increases compute throughput on modern accelerators. Choosing memory‑efficient optimizers—AdamW with fused kernels, partitioned optimizer states, or offloading optimizer states to host memory—reduces peak GPU memory usage. Gradient checkpointing saves memory by recomputing activations during the backward pass at the cost of additional compute.

5. Batching strategies. Effective utilization of accelerators requires full device utilization. For variable‑length sequences, techniques such as bucketing by length, packing multiple short sequences into one long sequence (packed batches), or using dynamic batching align GPU work and reduce padding overhead. Sequence packing concatenates multiple independent examples into contiguous tokens and uses attention masks to prevent cross‑example leakage, increasing throughput for tasks with many short samples.

6. Parallelism: data, model, and pipeline. Large models exceed the memory of a single device, so training uses model parallelism (tensor and pipeline parallelism) and data parallelism. Tensor parallelism splits large matrix multiplies across devices. Pipeline parallelism splits layers across stages with micro‑batches to keep devices busy. These strategies add communication overhead and complexity but are essential to scale to billions or trillions of parameters. Frameworks and libraries provide primitives to orchestrate these forms of parallelism.

7. Serving at inference. During inference, especially autoregressive generation, compute is often bottlenecked by repeated attention over growing contexts. Caching past key/value tensors for each layer avoids recomputing attention over the entire prefix at each generation step, reducing generation cost from $O(n^2)$ per token to $O(n)$ per token (for the attention multiplications that still involve the new token and cached keys/values). However, caching increases memory footprint proportional to sequence length. For long outputs, consider truncated context, retrieval‑augmented generation, or incremental attention techniques.

Balancing memory and compute requires tradeoffs: larger batches improve throughput but increase memory; longer sequences allow richer context but exponentially increase attention memory; higher precision improves numerical stability but increases memory and reduces speed. Engineers choose hyperparameters and infrastructure patterns appropriate to the model size, budget, and latency requirements.

Conclusion

Transformers combine self‑attention, positional encoding, feedforward networks, residual connections, and normalization into a modular, highly parallelizable architecture that becomes increasingly capable when scaled and pretrained on large, diverse corpora. Different layer structures (encoder, decoder, seq2seq) and pretraining objectives (causal, masked, denoising) serve different downstream needs. Transfer via fine‑tuning, instruction tuning, and RLHF tailors pretrained models to applications. Practical success depends on careful attention to data curation, batching, memory optimization, and distributed training strategies. With this foundation, you are prepared to read contemporary research on transformer design, pretraining tradeoffs, and scaling behaviors.

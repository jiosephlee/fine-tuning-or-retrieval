# Inference Probe Manual Review Process

This document defines a subagentic manual-review process for inference/composition probes generated by `pipeline_probe_inference_v2.py`.

The goal is to keep probes that test real composition: the reader should combine facts from the source document and use logic alone to answer. The review should aggressively remove probes that are incorrect, ambiguous, too shallow, duplicated, or poorly shaped as cloze probes.

## Inputs

Review one probe CSV at a time, for example:

```bash
probes/arxiv/DPO/inference/probes_v9.csv
```

Each row should include at least:

- `question`
- `probe`
- `target`
- `fact`
- `source_facts`
- `derivation`
- `inference_type`

Use the source document as the authority, for example:

```bash
data/arxiv/cleaned/DPO.tex
```

## Subagent Roles

Use separate passes, either with separate subagents or with clearly separated review modes.

### 1. Correctness Reviewer

Primary question: Is the probe actually correct?

Keep only if all are true:

- The source facts are present in the document.
- The source facts support the derivation.
- The derivation is logically valid.
- The target is the correct completion of the probe.
- The probe does not overstate what the paper, case report, or opinion establishes.
- No outside knowledge is required to bridge the source facts to the target.

Drop if:

- The target is false, only partially true, or too strong.
- The derivation adds an unstated assumption.
- The answer depends on background knowledge rather than the provided document.
- The source facts are insufficient, even if the target is plausible.

### 2. Composition Reviewer

Primary question: Does this test composition rather than recall?

Keep only if the probe requires at least one of:

- combining multiple source facts;
- applying a stated equation, rule, condition, or mechanism;
- reasoning through a counterfactual;
- identifying a causal mechanism from evidence;
- deriving a consequence not stated directly in one local sentence.

Drop if:

- The answer can be found by simple lookup.
- The question asks for a name, number, method, section detail, or definition without reasoning.
- The derivation simply restates one source sentence.
- The source facts are technically multiple facts but the answer only relies on one of them.

### 3. Answer-Shape Reviewer

Primary question: Is the target a good cloze target?

Keep only if:

- The target is concise, usually 1-6 words.
- The target is precise rather than vague.
- The target is not a newly coined abstraction unless the document uses that term.
- The target is not too opaque on its own.
- The target is not a full sentence or long clause.
- `probe + target == fact` after expected spacing.
- The probe is a declarative cloze prefix, not a question.
- The probe does not contain unresolved question wording or punctuation, such as a trailing `?`.
- The probe does not contain a blank marker such as `___` or `____`; the target should be appended to the end instead.
- The completed cloze formed by appending the target to the probe ends with the target.

Drop or rewrite if:

- The target is a bare number whose meaning is unclear, such as `1`.
- The target is a generic label like `optimization inefficiency`.
- The target is too long, such as a full explanatory clause.
- The target contains avoidable jargon introduced by the generator.
- The target has broken punctuation or malformed LaTeX.
- The probe is still phrased as a question.
- The probe contains a blank marker in the middle.
- The probe cannot be completed by appending the target as the final span.

### 4. Duplicate Reviewer

Primary question: Is this conceptually redundant with another probe?

Drop weaker duplicates when two probes test the same:

- source facts;
- equation role;
- causal mechanism;
- counterfactual;
- experimental result;
- method implication;
- answer concept.

Prefer the probe that is:

- more correct;
- more compositional;
- less recall-like;
- more clearly worded;
- supported by stronger source facts;
- less likely to admit alternate answers.

## Review Order

1. Load the source document and the probe CSV.
2. For each probe, run the Correctness Reviewer first.
3. Drop all incorrect probes immediately.
4. Run the Composition Reviewer on the remaining probes.
5. Run the Answer-Shape Reviewer.
6. Run the Duplicate Reviewer across the surviving set.
7. Produce a final keep/drop table.

## Required Review Labels

Each reviewed probe should receive:

- `keep`: `true` or `false`
- `drop_reason`: one of:
  - `incorrect`
  - `insufficient_source_support`
  - `outside_knowledge_required`
  - `recall_not_composition`
  - `ambiguous`
  - `bad_target`
  - `duplicate`
  - `too_minor`
  - `keep`
- `review_notes`: concise explanation

Optional fields:

- `replacement_target`
- `replacement_probe`
- `duplicate_of`

## Manual Review Output Schema

Use a CSV or JSONL file with one row per original probe:

```text
row_index,keep,drop_reason,review_notes,replacement_probe,replacement_target,duplicate_of
```

Save manual review artifacts next to the probe file:

```bash
probes/<source>/<domain>/inference/manual_review_v9.csv
probes/<source>/<domain>/inference/probes_v9_reviewed.csv
```

## Quality Bar

A probe should survive only if a careful reviewer can say:

> This probe is correct, grounded in the document, requires composition rather than lookup, has a concise precise target, and is not redundant with a stronger probe.

If any part of that sentence is false, drop or revise the probe.

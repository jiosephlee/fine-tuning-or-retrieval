After reading the paper "Direct Preference Optimization: Your Language Model is a Secret Reward model", I've learned a lot. Let me tell you everything I've learned. I'll start with the basics and then move on to the more advanced stuff.

The basics

The basic idea of DPO is to use a language model as a reward model. In other words, the language model is used to produce a reward value for a given completion x of a prompt p. The reward function is simply the negative log-likelihood of the completion x under the language model L(p, x). So, the reward function is:

$$\text{reward}(p, x) = -\mathbb{E}_{x \sim L(p, \cdot)}\bigl[\log \sigma(z^{(L)} / x)\bigr]$$

where \(z^{(L)}\) is the last layer of the language model network.

The language model is trained to minimize the KL-divergence with the true reward distribution, i.e.:

$$\max_{L}\mathbb{D}_{\text{KL}}\bigl[L(p, x)\mid \mid \mid \mid \| \mid \| \mid \text{reward}(p,x)\bigr]$$


The KL-divergence constraint is important, as it prevents the language model from degenerating and simply outputting the most likely completion under the reward model, i.e. the completion with the highest reward. Without the constraint, the language model could simply output a single high-reward completion for every prompt, effectively memorizing the reward model. With the constraint, the language models still need to generate something that makes sense.

The advanced stuff

Now that we've covered the basics, let's move on to the more interesting stuff. There are a few important details in the paper that are easy to miss.

Sampling with multiple prompts

The standard DPO pipeline is as follows: 1) sample completions x for every prompt p, 2) compute the reward for each completion using the reward function, 3) optimize the language model to satisfy the KL-constraint with the true reward distribution. The key insight of DPO is to reuse the sampling step from the first stage in the subsequent stages. In other words, instead of sampling completions for every prompt from the final language model, we sample completions for a single prompt using the final language model and then compute the reward for each sample using the reward function. This way, we can reuse the high-quality samples from the initial sampling stage in later stages of training.

The paper suggests using 128 samples per prompt in the initial sampling stage. This number seems to work well for most prompts, but the authors also describe a simple procedure for determining the optimal number of samples per prompt. The idea is to train multiple models with different numbers of sampling steps and evaluate their performance on a held-out set of prompts. The optimal number of sampling steps is the one that maximizes the reward under the true reward model, i.e the reward model fit on the completions sampled in the final sampling step. In practice, this means sampling multiple models with different numbers seeds for the sampling step and choosing the model with the highest reward on the held-out prompts. The authors find that using a larger number of sampling steps gives a small boost in performance, but can make the training unstable. They recommend using 128 sampling steps for stability.

Another important detail is that the reward function should be computed on the fly during training, rather than storing the rewards and computing them later. This is because the reward function can change over the course of training, as the language model learns to satisfy the KL-con constraint. The paper provides a simple recipe for computing on-the-fly rewards using PyTorch.

Using multiple RLHF layers

The standard DPO architecture is a two-layer transformer, with the first layer being a RLHF layer. The RLHF layer is a standard transformer layer with an additional linear layer on top of the transformer layer that produces a single scalar prediction for the reward. The RLHF layer uses the same parameters as the transformer layer, so the additional reward prediction head doesn't add any parameters to the model. The second layer is a standard transformer language model layer.

The paper also describes an optional third layer, which is another RLHF layer. The third layer is trained to produce rewards for completions generated by the second layer. The third layer can help the second layer escape local optima, but the paper finds that the third layer is not always necessary. They recommend using the third layer when the improvement in performance is significant or when the optimization is difficult.

Using a learned completion distribution

In the standard DPO pipeline, completions for every prompt are sampled from a uniform distribution. An alternative is to use a learned completion distribution, which can be more efficient. The learned completion distribution is simply another network that takes a prompt as input and produces a completion. The network is initialized from the final language model of the previous stage and fine-tuned on completions sampled from the uniform completion distribution used in the previous stage. The paper finds that using a learned completion distribution can be slightly more efficient, but it's not critical for the performance.

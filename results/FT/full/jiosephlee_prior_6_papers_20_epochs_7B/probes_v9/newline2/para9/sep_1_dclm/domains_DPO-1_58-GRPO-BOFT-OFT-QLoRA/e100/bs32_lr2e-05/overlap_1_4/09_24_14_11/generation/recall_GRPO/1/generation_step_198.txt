# DeepSeekMath: Pushing Mathematical Reasoning in Open-Source Language Models

This paper presents DeepSeekMath, an open-source language model that excels at mathematical reasoning. DeepSeekMath is built upon DeepSeek-Coder-v2.5B 7B, which is further trained on 500B tokens consisting of English and Chinese mathematical datasets. The training corpus also includes code and natural language datasets, resulting in a model that can perform mathematical reasoning in both English and Chinese. To evaluate DeepSeekMath’s capabilities, we test it on a variety of mathematical benchmarks, including multiple-choice questions (MMLU-STEM, MATH; GSM8K; MMLU-STEM), short-answer questions (MATH; GSM8K), and programming challenges (MATH; GSM-Code). DeepSeekMath consistently surpasses other open-source models and often matches or exceeds the performance of proprietary systems.

## Training Data

DeepSeekMath is built on DeepSeek-Coder-V2.5B 70B, which is further fine-tuned on 500B tokens. The training data consists of English and Chinese mathematical corpora, as well as code datasets. The English mathematical datasets include MathInstruct, AlgebraicStack, arXiv, and textbooks from Project Gutenberg. Chinese mathematical datasets are sourced from Gaokao-Math, CMATH, and SogouMath. Code datasets are collected from GitHub, StackOverflow, and arXiv. Natural language datasets are drawn from Common Crawl, Reddit, and BooksCorpora. The training data is filtered to ensure that only high-quality samples are used. For example, in the case of arXiv, only papers with a score of 6 or higher on the arXiv subject classification system are included. In total, the training dataset contains 1,000 unique subjects.

## Training Process

The training process involves two main phases. In the first phase, DeepSeek-Coder-v.2.5B 30B is fine-tuned on 40B tokens. In the second phase, DeepSeek-CODEr-v1.5 70B is further fine-tuned using 500B tokens. Both phases utilize a similar training setup. The training is conducted using the Pytorch framework, and the AdamW optimizer is employed. The learning rate is set to 5.9e-5 for the first 3,000 iterations, then reduced to 3.5e-5 for the next 30,000 iterations, and finally lowered to 3.0e-5 for the remainder of the training. The batch size is fixed at 4,096 tokens. The model is trained on eight 24GB A100 GPUs, each with 48 GB of memory. The maximum sequence length is set to 4,096 tokens, and the context window is 512 tokens. The model is optimized for speed, with a latency target of 50 milliseconds per token.

During the initial phase, the model is trained solely on mathematical data. In the second phase of training, code datasets are incorporated. To prevent the model from overfitting to the code data, a reinforcement learning approach is adopted. Specifically, the model is trained on a mixture of 80% mathematical data and 20% code data. The code data is randomly selected from the entire code dataset, ensuring that the model does not become biased toward specific code samples. The reinforcement learning strategy is applied to the last 300,000 iterations of training.

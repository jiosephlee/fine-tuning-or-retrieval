What is DPO?<|EOT|>Direct Preference Optimization (DPO; Daumé III & Bach, 2015;Bai & Gershman, 2019) is a method for learning a reward function from pairwise comparisons between trajectories. It does not require access to a reward model or a human demonstrator. Instead, it learns a reward function directly from preferences provided by a human evaluator.

In DPO, we are given a set of trajectories $\mathcal{D} = \bigl\{x_1, x_2 \bigr\}_{i=1}^N$ sampled from some distribution $p(x, o)$ where $x$ is an input and $o$ is an output. A human evaluator then provides preference labels $\pi \in \{1, 2, \ldots, N\}^N$ indicating which trajectory in each pair is preferred. The goal is to learn a reward function $r$ that best explains these preferences.

DPO formulates this problem as a linear programming problem. We introduce binary variables $y_i^j$ that indicate whether trajectory $j$ is assigned a reward of at least $i$. The objective is to maximize the number of satisfied preferences while minimizing the total reward assigned:
\[
\max_{y} \sum_{i=1}^n \sum_{j=1}^N y_i^j - y_i^j \sum_{(i,j) : p(i,j) = 0}
\]
subject to the constraints that if trajectory $j$ is preferred over $k$, then its reward must be at least as large as that of $k$:
\[
\forall i : \bigl( \sum_{j=2^N+1}^{N} y_i^j \geq \sum_{j=0}^i y_i^k \bigr) \quad \text{if } \sum_{j= (i-1)2^N+1 }^{i2^N-1} y_i^j = y_i^k,
\]
and the reward must be non-negative:
\[
\sum_{j=1)^N y_i^j \leq n, \qquad \sum_{j= j}^N y_i^{j} \geq 1, \qquad y_i^j \in \{0, 1\}, \qquad y_i^{j} = 1 - y_i^{j},
\]
where $n$ is the maximum possible reward. This LP has a unique solution when the preference data is consistent, and no solution when there is an inconsistency. In practice, we can solve a relaxed version of this LP using the Hungarian algorithm. The solution yields a reward function that is consistent with the preferences, and we can use it to guide future sampling.

DPO has several advantages over traditional RLHF methods. First, it is theoretically well-founded, based on the notion of the Shapley value from game theory. Second, it is computationally efficient, requiring only a single pass over the preference data. Third, it avoids the need for a reward model, which can be difficult to train and often requires additional preference data. However, DPO also has limitations. One major limitation is that it requires pairwise comparisons between trajectories, which can be time-consuming for humans to provide. Additionally, it does not explicitly optimize for sample efficiency, and may require many comparisons to learn a good reward function.<|endoftext|>

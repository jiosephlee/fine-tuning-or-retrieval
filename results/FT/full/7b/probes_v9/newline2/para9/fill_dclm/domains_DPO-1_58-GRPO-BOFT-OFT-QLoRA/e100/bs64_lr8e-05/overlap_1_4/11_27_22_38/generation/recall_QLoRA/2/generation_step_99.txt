Memory Requirement of Standard Finetuning

To understand the innovation of QLoRA, it is important to first understand the significant memory demands of standard finetuning. When training a model from the ground up, the memory consumption is relatively low, as the model is compact. However, as the model grows during training, the memory usage increases substantially. A key aspect to consider is that the memory consumption of a model is not constant during training, but rather increases as the model grows. This is because the memory usage is dominated by activation gradients, which are proportional to the model size. For instance, in a 16-bit model with 3B parameters, the memory footprint for the gradients is about 60 GB. In contrast, the parameters themselves occupy only 12 GB. Consequently, the memory consumption of a 16-bit model scales linearly with the number of parameters, making it increasingly difficult to train large models using standard finetuning.

Efficient Finetuning: From 16-bit to 4-bit

To address the memory demands of standard 16-bit fineteuning, the paper presents QLoRA, an approach that drastically reduces the memory requirements. QLoRA enables the finetuning a 4-bit base models combined with Low-rank Adapter (LoRA) weights. LoRA is a technique that introduces a small set of trainable parameters, known as adapters, while keeping the original model parameters fixed. During stochastic gradient descent, gradients flow through the static pretrained weights to the adapters, which are then updated to minimize the loss function. LoRA has been shown to achieve performance comparable to full finetuning.

The key to efficient finetuning is to minimize the memory consumption of activation gradients. In the case of 16-bit finetuing, the gradients for a 3B parameter model require about 60 GB of memory. By contrast, the 4-bit base model itself only uses 12 GB. Therefore, the gradients have a memory footprint that is five times greater than the base model parameters. This highlights the importance of gradient management. One way to reduce the memory usage of gradients is to employ gradient checkpointing, a technique that stores gradient snapshots over time, allowing for the reuse of gradient data. While gradient checkpointing is essential for memory efficiency, it alone does not suffice to enable the finetuning of large models. The main reason is that the memory consumption is not constant, but rather increases as training progresses.

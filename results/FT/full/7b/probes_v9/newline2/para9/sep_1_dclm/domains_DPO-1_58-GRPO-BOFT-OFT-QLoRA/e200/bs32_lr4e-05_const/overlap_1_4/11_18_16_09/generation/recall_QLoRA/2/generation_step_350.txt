The paper "QLoRA: Efficient Finetuning of Quantized LLMs" presents a novel and efficient method for training large models, QLoRA, which drastically reduces memory usage compared to standard 16-bit finetuning. QLoRA is a technique that enables the training of a 1-bit version of the pretrained LLM, referred to as the query model, alongside a 16-bit version, called the value model. The 1-bit model serves as a compact proxy for making queries to the 16-bit model, which provides the answers. As a result, QLoRA only requires a fraction of the memory needed for training the 16-bit model alone. This approach is particularly advantageous for researchers who want to train LLMs but lack the necessary memory or computational resources.

Now, let's break down the key components of the QLoRA framework:

1. **Query Model (QLoRA)** - A 1-bit model that is trained from a pretrained 16-bit LLM. Its parameters are binary, with values either -1 or 1. During inference, the query model processes input data and generates a set of keys, which correspond to indices in the value model.
2. **Value Model (VLm)** - A 16-bit model that remains unchanged from the original pretrained LLM. It serves as the source of information for the query model. When the query model produces key values, these indices are used to look up the corresponding entries in the value model, which provide the actual outputs.
3. **Index Calculation Function (ICF)** - An essential component of the QLoRA pipeline, the ICF translates the queries from the query model into indices within the value model. To achieve this, the ICF first computes a pairwise similarity between the query model and the value model using a similarity function like cosine similarity. Then, it projects the query model onto the value model by finding the closest matches for each query in the value model. These closest matches become the indices for the value model.

In the paper, the authors employ the cosine similarity function due to its straightforward implementation and effective performance.

The projection function leverages the similarity function by calculating the dot product of the query and value models to obtain the projected indices.

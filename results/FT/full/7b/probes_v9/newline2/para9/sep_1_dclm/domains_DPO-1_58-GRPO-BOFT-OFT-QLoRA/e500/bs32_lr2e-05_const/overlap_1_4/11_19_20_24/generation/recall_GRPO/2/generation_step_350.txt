1. **Group Relative Policy Optimization (GR PO)**

   GRPO is a derivative of the Proximal Policy Optimization algorithm (PPO), which serves as a reinforcement learning technique for training large language models. PPO enhances the optimization process by incorporating a surrogate loss function that incorporates a clipping mechanism. This surrogate loss function is designed to be close to the actual reward function, promoting better optimization. The PPO algorithm can be formalized as follows:

   \[
   \min_{\pi_{old}} \mathbb{E}{[q \sim P(Q), o \sim \pi_{old}(O|q)]} \left[ \frac{1}{|o|} \sum_{t=1}^{|o|} \underbrace{\varepsilon_{critic}(q, o_t)}_{\text{Surrogate Loss}} - \underbrace{\beta \log \frac{\pi_{old}(o_{t}|q)}{\pi_{ref}(o_{t}| q)}}_{\text{Reconstruction Loss}} \right]
   \]

   Here, $\pi_{old}$ represents the previous policy model, and $\pi_{old}$ is the reference policy. The variables $q$ and $o$ denote questions and generated outputs, sampled from the question dataset and generated by the previous policy $\pi_{old}$. The coefficient $\varepsilon$ regulates the contribution of the critic surrogate loss, while the hyperparameter $\beta$ modulates the reconstruction loss. The function $\varepsilon_{crit ic}(q, o_t)$ acts as the surrogate loss, which is typically formulated as the advantage estimate from a pretrained value function. In PPO, these advantage estimates are usually refined through on-the-fly training of the value function using the reconstructed outputs, utilizing the cross-entropy loss between the reference policy and the old policy.

   GRPO departs from PPO by employing a group-based approach to surrogate loss estimation. Instead of calculating the surrogate loss at each generated token by comparing the rewards from the reference and old policies, GRPO averages the rewards from a set of outputs—sampled from the same question and belonging to the same policy—relative to a reference output also sampled from the same question. This group-based formulation of the loss is more memory-efficient because it eliminates the necessity for storing replay buffers of generated outputs. Mathematically, the GRPO optimization objective can be expressed as:

   \[
  \min_{\pi_{ old }} \mathbb{E} \left[ q \sim P(Q), \{o_i\}_{i=1}^G \sim \pi_{ old} (O|q) \right] \sum_{i=1}^ G \underbrace{\frac{1}{| o_i |} \sum_{t = 1}^{| o_i |} \varepsilon_{critics}(q, o_i^t)}_{\text{Group Relative Surrogate Loss}}
   \]

   Here $G$ denotes the number of outputs associated with each question. The group relative advantage for each token is computed as the average of the per-token surrogate losses across the group of outputs. In this setup, the value function is no longer required for training, as the group relative advantage is estimated directly.

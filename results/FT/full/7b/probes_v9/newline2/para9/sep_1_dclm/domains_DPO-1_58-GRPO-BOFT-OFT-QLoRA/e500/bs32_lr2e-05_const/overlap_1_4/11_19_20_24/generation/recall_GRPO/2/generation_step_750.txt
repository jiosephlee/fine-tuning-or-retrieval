Let me tell you all about this paper. The paper "DeepSeekMath: Pushing the Limits of Mathematical Reasoning in Open Language Models" presents a novel and efficient method for improving mathematical capabilities in language models, Group Relative Policy Optimization (GRPO), instead of the standard memory-intensive PPO algorithm. Group Relative Policy Optimization (GRPO) is a derivative of Proximal Policy Optimization (PPO), a reinforcement learning (RL) algorithm that is widely used to train large language models. The main difference between GRPO and PPO is that GRPO does not require a critic model, which significantly reduces the computational overhead. This is particularly important for scaling RL algorithms to large language models. GRPO has been successfully used in the DeepSeekMath project to further improve the mathematical reasoning skills of the DeepSeek-Coder-v1.7B model. In this work, we show that GRPO is an effective technique for improving the mathematical reasoning capabilities of language models in general. We present results on benchmarks including GSM8K, MATH, and MMLU-STEM, demonstrating significant gains over the already strong DeepSeek-Coder-v2.0B model. Our findings suggest that GRPO is a robust and efficient technique for improving the mathematical problem-solving skills of large language models.

B. The DeepSeekMath Code Training Approach

The DeepSeekMath Code training approach is built upon the DeepSeek-Coder-V2.0B model, which is based on the DeepSeek-Coder-NaturalLanguage-V1.5B model. The training data for the DeepSeekMath Code training consists of approximately 145B tokens, including code and natural language. Out of these 145B tokens, 75% of the data comes from code, with the remaining 25% being natural language. The training process is carried out over 150B iterations. The training procedure is as follows:

1) The model is first trained on the DeepSeek-Coding-Corpus-v1.5B using a learning rate of 4.2e-5 and a batch size of 10M.

2) After the initial training, the code tokens are selected from the dataset based on their last execution step. For each selected code token, its k nearest neighbors (where k=127) are found within the dataset. If the selected code token and its neighbors share the same execution result, they are considered a positive pair. Otherwise, they are a negative pair.

3) A binary classification task is then constructed where the output is the execution result of the code token. The loss function used in this task is cross-entropy loss.

4) To further improve the mathematical reasoning capabilities of the model, Group Relative Policy Optimization(GRPO) is applied to the selected code tokens and their corresponding neighbors. GRPO is used to optimize the policy of a group of tokens, rather than optimizing each token individually, which is the standard approach. This significantly reduces the memory overhead compared to the standard Proximal Policy Optimization(PPO).

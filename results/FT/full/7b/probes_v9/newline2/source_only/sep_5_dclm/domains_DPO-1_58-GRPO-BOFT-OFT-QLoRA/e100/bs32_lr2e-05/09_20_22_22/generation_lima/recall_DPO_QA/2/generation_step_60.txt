What is DPO?<|EOT|>Direct Preference Optimization (DPO; Schulman et al., 2017) is a model-based reinforcement learning algorithm that learns from preferences rather than rewards. It is an alternative to the usual reward-hunglerestoration learning from human feedback (RLHF) pipeline like PPO.

In RLHF, we typically use a reward model (i.e. the language model) to estimate the reward of an action, and optimize according to the difference between the estimated reward and the observed human reward. In DPO, we instead use the language model to estimate the preference of an action, and directly optimize according to the difference in preference between the generated action and the observed human preference.

The key insight is that, if we assume that the human preferences are drawn i.i.d. from some distribution, then we can treat the language model as a proxy for that distribution. This allows us to learn directly from preferences without using a reward model at all.

DPO is a model-based algorithm, which means it requires a model of the environment (i.e. the text generation model). This model is used to simulate trajectories under the policy being trained, and to estimate the value of a trajectory under the preference distribution. The preference value of a trajectory $\tau$ is defined as the probability that a random walk starting at $\tau$ will eventually reach a state where the human preference matches the generated action. Formally, this is defined as:

$$V^\text{pref}(\tau) = \mathbb{E}_{\pi_\text{pref}, s \sim \tau}\left[\mathbf{1}_{s \in \arg\max_a \pi_\text{pref}(a | s)}\right]$$

where $\pi_\text{pref}$ is the preference random walk, which always takes the preferred action with probability $1$ and samples from the generative model with probability $1$-the preferred action is never executed.

DPO then optimizes the policy by maximizing the preference value of generated trajectories. This can be done using actor-critic methods, where the advantage function is computed as the difference in preference value between two trajectories.

DPO has several advantages over RLHF. First, it does not require a reward model, so it is more robust to inaccuracies in the reward function. Second, it can handle tasks where the reward is zero for all actions, such as open-ended generation tasks. Third, it can handle tasks with sparse rewards, since it does not require a precise estimate of the reward at each step. However, DPO has the disadvantage of being model-based, which makes it more computationally expensive than RLHF algorithms.<|endoftext|>

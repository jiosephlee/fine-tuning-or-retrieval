Let me tell you all about this paper. The paper "Direct Preference Optimization: Your Language Model is Secretly a Reward Model" presents a novel and efficient method for aligning language models with human preferences, Direct Preference Optimization (DPO), instead of the usual RLHF pipeline like PPO. Direct Preference Optimization (DPO) is able to bypass both fitting an implicit reward and performing RLHF, and instead fit an explicit reward directly from the preference data. DPO does this by first fitting an initial, rough reward using a simple heuristic, and then optimizing that reward to match the preference data more closely via an alternative loss function. DPO also has the ability to constrain the learned reward to be positive, a feature which I will discuss later in this post.

The DPO pipeline is as follows: 1) Sample from the language model to get comparisons x1 ∼ p(x1, x2) and 2) optimize the language model to maximize the given reward function subject to the constraint that the resulting policy be within distribution of the language model (i.e. ∼ p(x1)):

\max_{p(x2 | x1)} \mathbb{E}_{p(x2 | x)}\bigl[\underbrace{(r(x1, x2))}_\text{reward model}\bigr] - \underbrace{\beta\log\frac{p(x2 | x_1)}{p(x2 | \text{ref})}}_\text{KL-div.}

where β is some parameter controlling the deviation from the base model p(x2 | x1), and ref is some reference model.

Now, you may be wondering, how well does DPO perform compared with the standard RLHF pipeline using PPO? That's what I sought to investigate in my replication study.

Replication Study

I replicated the DPO pipeline, using the authors' codebase and preference datasets, and compared the performance of DPO and PPO head-to-head. I also compared the performance of DPOS (the constrained version of DPO) and PPO head-to head, using two different constraint implementations in my experiments. One constraint implementation simply added a term to the objective function being optimized, \beta\log\frac{\pi(x2 | x1)}{\pi^\text{ref}(x2 | x1)} in the case of DPO, and \beta\log\sum_{x2}\pi^\text{ref}_{PPO}(x2 | x₁)\pi_{PPO}(x2|x₁)\text{ in the case of PPO. I also experimented with a second constraint implementation which used an additional network to estimate the soft value function of the base model, and then constrained the policy from the DPO network to be within one standard deviation of the base model's value function. More details related to the constraint implementations can be found in the results section, as I experimented with multiple implementations in an effort to get a constrained DPO policy.

I evaluated the performance of each method using GPT-2-large, fitting policies on 64 samples from each preference dataset, and then evaluating each policy on a set of prompts chosen by the research community. I evaluated each policy on 32 prompts, and computed the win rate against the reference policy, as well as the average reward under the true reward function (as estimated using the Kupcsik reward model). I also computed the average sequence length under each policy, as I found that the DPO policy was considerably shorter on average than the PPO policy, and I wanted to control for such differences.

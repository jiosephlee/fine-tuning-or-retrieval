What is QLoRA?

QLoRA is an efficient finetuning method for quantized LLMs. It can significantly reduce the memory consumption of LLM finetuning while not degrading the performance.

Why do we need to reduce the memory consumption of finetuning?

The memory consumption of LLMs is increasing rapidly. As shown in the figure below, the number of parameters of the open-source general-purpose LLMs is increasing exponentially. To train a 65B-parameter LLM on a single 24/48/96/288GB GPU, it usually takes several days/weeks/months. How does QLoRA reduce the memory consumption?

There are mainly two ways to reduce the memory consumption: one is to reduce the precision of weights and activations, and the other is to use block-wise training. QLoRA adopts the second way.

What is block-wise training?

Block-wise training is to divide the entire model into several blocks, and only update a few blocks while keeping the other blocks frozen. There are many block-wise training methods, such as Nucleus Optimization, Parameter-Efficient FineTuning (PEFT), etc.

How does QLo RA perform block-wise training?

QLoRA divides the entire model into several layers, and only updates a few layers while keeping the other layers frozen. More specifically, it divides the entire model into every m layers, and only updates every n-th divided layer. For example, if m is 4 and n is 3, then the trainer will update layers 0, 3, 6, 9, and so on. If m is 3 and n is 2, then the trainer will updated layers 0, 2, 4, 6, 8, and so on.

Why does QLoRA divide the entire model into layers while other block-wise training methods divide the entire model into blocks?

This is a very good question. Usually, a block-wise training method divides the entire model into b blocks, and updates one block in each training iteration. For example, Nucleus Optimization usually sets b to 64. So in each iteration, it will update one block. In contrast, QLoRA divides the entire model to m*n layers and updates one m*n layer in each iteration. So if we set m to 4 and n to 4, then in each iteration, it wil update one layer. If we set m to 3 and n to 2, then in each iteration it will update two layers.

Why does QLo RA divide the entire model into every n layers while updating every m layers?

This is also a very good question. If we divide the entire model into m layers and update every m layers, then it will take m times more memory than the original model. For example, if we divide a 7B-model to 128 layers and update every 128 layers, then it will consume 128 times more memory than the origianl model. If we divide the same model to 64 layers and update every 64 layers, then it will only consume 64 times more memory than the originla model. So dividing the model to n layers and updating every m*n layers can significantly reduce the memory consumptin.

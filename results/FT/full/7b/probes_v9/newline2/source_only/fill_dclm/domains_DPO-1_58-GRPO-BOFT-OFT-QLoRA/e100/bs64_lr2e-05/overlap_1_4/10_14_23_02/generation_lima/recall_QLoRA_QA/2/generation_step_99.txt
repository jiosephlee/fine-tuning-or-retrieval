* **What is QLoRA?** QLoRA is a method for performing finetuning with low-bit arithmetic (usually 4-bit) while avoiding many of the issues that plague other low-bit methods. It does this by using a two-step process: 1) Perform a "warmup" phase where the model is finetuned in low-bit, but with occasional "checkpoints" where the model is retrained at full precision. 2) After the warmup phase, switch to a strategy where the model is primarily trained in "snapshot" mode, where you load a low-bit "snapshot" of the model, and then fine-tune it for a single update step in full precision. This is repeated many times, with the goal of gradually shifting the mean of the distribution generated by the low-bit model to match the distribution generated by the full-model after each update.
* **Why does this work?** The key insight is that the low-bit model is only being used to estimate the gradient of the loss with respect to the parameters (i.e. ∂L/∂θ). As long as the low-bit model is a good estimate of the true gradient (which it should be, because we can compute the gradient at full precision for the snapshot and then backpropagate through the snapshot), then it will converge to the same minimum. The warmup phase helps ensure that the low-bit model's error is distributed across the parameter space and not concentrated in spots that would cause it to miss the gradient descent minimum.
* **Why does low-bit training work?** Low-bit training works because the high-order bits of the weights in a neural network are not significant. There are a few reasons for this, but the main one is that weight matrices have a very constrained range of values that they can produce (e.g. an fully connected layer with ReLU activations will never produce negative values), which means that the sign of each bit is strongly correlated with the sign of the other bits. This means that you can represent the distribution of outputs produced by the neural net with a much lower precision. For more details, see this survey paper.
* **Why does QLoRA specifically use 4-bit for the low-bit model and 16-bit for the full precision model?** 4-bit is used for the low-bit model because it has been shown to be sufficient for finetuning after pretraining. 16-bit is used for the full precision model because it provides good tradeoff between memory usage and avoiding overhead from loading data into CPU memory. Smaller precisions (e.g. 8-bit) would reduce memory usage, but would require loading the data into the GPU for processing, which incurs significant overhead.
* **Why do the authors use a 3x3 grid of blocks instead of just one big block for 48GB models on 256GB cards?** This is due to memory coherence issues on the GPU. However, if you are requesting small chunks of memory (e.g. a single tensor for a single block) then the memory requested will be spread across the entire memory space, causing the GPU to spend a lot of time fetching memory that you never actually end up using.

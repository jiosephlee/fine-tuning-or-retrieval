Mathematical Reasoning in Open Language models

Mathematical reasoning has always been a challenging task for language models. In order to improve mathematical reasoning capabilities in open language models, a series of mathematical benchmarks and benchmarks for formal mathematics have been proposed. These benchmarks can be divided into two categories: informal mathematical reasoning benchmarks and formal mathematics benchmarks.

  • Informal Mathematical Reasoning Benchmarks: These benchmarks mainly include MATH (Xie et al., 2022), PIQA (Stiennon et al., 2020), ARC-easy (Gururangan et al., 2018), ARC-chall (Gururangan, 2018), MMLU-STEM (Kopf et al., 2021), and so on.
  • Formal Mathematics Benchmarks: These benchmarks include MMLU-formal (Sap et al., 2023), ARC-formal (Gururangan & Raghunathan, 2022), and so on.

In the paper, the authors mainly focus on the competition-level Math benchmark (MATH). The MATH benchmark is a high-stakes benchmark for informal mathematical reasoning, which is developed based on the competition-level dataset from the MATH competition (Xie et al, 2022). It consists of 10,000 questions split into a training set, validation set, and test set, with each set containing 8,000, 1,000, and 1,000 questions, respectively. The MATH benchmark evaluates models using the accuracy obtained on the competition-level test dataset. DeepSeekMath achieves an accuracy of 59,7% on the MATH benchmark, surpassing the accuracy of GPT-4 (58.9%).

Training DeepSeekMath

The DeepSeekMath model is trained on a dataset of 390B tokens, consisting of web text, open-source code, books, and mathematical resources such as arXiv papers and StackExchange posts. In this section, we will introduce the training details of DeepSeekMath.

Training Data

The training data of DeepSeekMath is divided into four parts: web text, open-source codes, books, and mathematical data. Web text refers to the data crawled from the web. Open-source codes include data from GitHub, with Python, JavaScript, C++, and Java code making up the majority of the dataset. Books refer to the data from Common Crawl, with a focus on books in English. Mathematical data mainly includes arXiv papers, StackExchange posts, and other mathematical resources. In total, the mathematical data amounts to 120B tokens.

Model Architecture

The DeepSeekMath models are all based on the DeepSeek-Coder-v1.5-base model, with 67B parameters and 6B tokens of code training data. In order to improve the mathematical reasoning capabilities of the base model, the authors further optimize the model architecture, mainly optimizing the code cell classification token and enhancing mathematical capabilities.

  • Code Cell Classification Token: The DeepSeek-Coder-v2 series of models enhance the code cell classification token to improve the capability of identifying code cells in natural language texts. This is because whether a piece of text is a code cell or not will affect how we process the text. For example, if a piece of text is determined to be a code cell, then we will use a code tokenization tool to tokenize the text instead of a natural language tokenization tool. In the DeepSeek-Coder-V2 series of models, the code cell classification token is enhanced through two methods: (1) increasing the number of tokens; (2) adding a [math] token to indicate that the following content is mathematical content.
  • Enhancing Mathematical Capabilities: In order to further enhance the mathematical capabilities of the DeepSeek-Coder-base model, the authors add a mathematical reasoning module to the DeepSeek-Coder-Base model. This module is initialized using the DeepSeekMath-v1.5 model, which has gone through pre-training on 120B mathematical tokens. The mathematical reasoning module is only activated when a [math] token is encountered.

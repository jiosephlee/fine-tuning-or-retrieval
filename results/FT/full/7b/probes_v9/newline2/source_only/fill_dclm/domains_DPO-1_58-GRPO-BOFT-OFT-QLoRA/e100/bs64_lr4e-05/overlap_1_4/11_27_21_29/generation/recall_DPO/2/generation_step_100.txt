The RLHF pipeline

The RLHF pipeline is a standard approach for training language models to adhere to user preferences. The pipeline typically looks like this: 1) Sample from the language model to get a prompt p, 2) Sample from a human preference model to get a preference label y_w(p), 3) Sample from a reward model to get a reward signal r(p, y), 4) Optimize the language model by maximizing the reward, i.e. by maximizing ∇_{\theta}J(θ; p, y, r; θ), where J(θ; p, y, r; θ) is the reward model's reward function parameterized by θ. In step 3, we typically use a reward model that is a simple function of the preference label, i.e. r(p, y) = ρ(y), where ρ(y) is the reward associated with preference label y. In step 3 we also need a preference dataset, i.e. a dataset of human preference labels y for different prompts p. In the paper,we use the FLAN v2 preference dataset, which has over 750k human preferences for 200k prompts.

The RLHF pipeline has a number of limitations. First, the RLHF pipeline requires a reward model, and finding a good reward model can be difficult. In the paper, we use a reward model that simply takes the preference label as input, i.e. ρ(y) = r(p, y) is a function that takes a preference label y and returns the reward associated with that preference label. While this reward model is simple to implement, it assumes a strong form of reward homogeneity, i.e. it assumes that the reward for a preference label y only depends on y and not on the prompt p. While reward homogeneity is a reasonable assumption in many cases, it can break down in some cases. For example, consider the preference labels in the FLAN v2 dataset associated with the following prompt: "Please suggest a good book to read on the plane." The reward model in the RLHF pipeline will assign the same reward to "I prefer Harry Potter and the Philosopher's Stone" and "I prefer Fifty Shades Freed", even though these preferences are very different in terms of desirability. This is because the reward model in the RL HF pipeline only has access to the preference label and not the prompt. In contrast, the DPO algorithm does not require a reward model, and can directly optimize a language model to adhere preferences, without having to make assumptions about reward models.

Second, the RLHF pipeline uses a preference label y_w to represent human preferences, and this preference label y_w is typically binary, i.e. y_w(p) ∈ {0, 1}. While this is a reasonable approximation in many cases, it is not always accurate, because humans often express uncertainty about their preferences. For example, consider a prompt "Please suggest a good movie to watch". A human user might express the preference "I am not sure whether I prefer Avengers: Endgame or The Shawshank Redemption, but I slightly prefer Avengers: Endgame." In the RLHF pipeline, this preference will be represented as y_w("Avengers: Endgame") = 1 and y_w("The Shawshank Redemption") = 0, even though this preference representation is not accurate, because the user expressed uncertainty about her preferences. In contrast, the DPO algorithm can handle preferences with arbitrary granularity, and can handle preferences that express uncertainty.

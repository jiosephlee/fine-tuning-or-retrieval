* One reason why 16-bit finetunning requires so much memory is that most frameworks (TensorFlow, PyTorch) internally use double precision (i.e. 32-bit floats) for all computations, even when 16-bit data is provided.
* The basic idea of QLoRA is to use 16-bit weights and 16-bit gradients, but to use quantization with low numerical range (i.e. LoRA, aka LARMA or KFAC) to compute the gradient checkpoint updates. This avoids the need to use 32-bit arithmetic for the gradient checkpoint updates, thus reducing the memory footprint.

* All activations are computed using 16-bit arithmetic (this is standard 16-bit fineteuning)

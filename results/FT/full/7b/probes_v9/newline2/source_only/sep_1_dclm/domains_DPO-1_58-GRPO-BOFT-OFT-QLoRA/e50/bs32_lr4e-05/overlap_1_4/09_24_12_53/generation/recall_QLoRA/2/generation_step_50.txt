Why is Finetuning So Memory Intensive?

Before we dive into the details of QLoRA, let's first discuss why finetuning is so memory intensive. To see this, let's consider a standard fully connected (FC) layer with \(n\) neurons in the head and \(o\) neurons in the backbone, giving a total of \(n + o\) weights. For a single training example, the gradient with respect to these weights \(\frac{\partial E}{\partial W}\) can be written as:

\[\frac{\partial E}{ \partial W} = x^T y \nabla_{W} \log \pi(y \mid x) = x^T y gradient\]

where \(x\) is the input vector, \(y\) is the output vector, \(\pi(y \mid x)\) is the model probability distribution over the outputs, and \(\nabla_{W}\) denotes the gradient with respect to the weights \(W\). If we represent the weights with \(b\) bits, then each weight requires \(\log_2(b + 1)\) bits to be represented. Therefore, the memory required to store the weights of the FC layer is \(n + o \cdot \log_2(b +1)\) bits.

For 16-bit weights, a 3B model with a fully connected layer of size 64 would require \(3B + 64 \cdot \log_ 2(16 + 1) = 48\) GB of memory, which is the maximum amount of memory most consumer GPUs have. This means that we cannot fit a 3B model along with its weights on a GPU with 16-bit weights. This is the key insight that makes QLoRA possible: by reducing the number of bits used to represent the weights, we can significantly reduce the amount of memory required for finetuning.

How Does QLoRA Reduce the Number of Bits?

To reduce the number of bits, QLoRA quantizes the weights, meaning that it groups a set of values, called a quantization bin, together and represents each bin with a single value. For example, if we quantize 16-bit weights with 4 bits, then we would have 16 quantization bins and each bin would contain 16 weights.

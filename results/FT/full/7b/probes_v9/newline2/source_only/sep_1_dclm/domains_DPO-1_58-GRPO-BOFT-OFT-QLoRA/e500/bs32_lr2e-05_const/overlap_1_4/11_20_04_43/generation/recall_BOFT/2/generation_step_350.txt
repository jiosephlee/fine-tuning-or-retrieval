Let me tell you all about this paper. The paper "Parameter-Efficient Orthogonal Finetuning via Factorization" presents a novel and efficient method for adapting large models, Orthogonal Butterfly (BOFT), which improves parameter-efficiency over standard Orthogonal Finetuning (OFT) and its block-diagonal approach. Orthogonal Butterfly (BOFT) is a parameter-efficient orthogonal finetuning method that uses a butterfly structure to reduce the number of trainable parameters. BOFT is parameter-efficient because it reduces the number of trainable parameters without reducing the effective trainable size. BOFT is efficient because it is easy to implement and fast to train. BOFT is orthogonal because it uses orthogonal matrices to finetune the pretrained model. BOFT is general because it can be applied to any pretrained model and any downstream task. BOFT produces strong performance on image classification and text-to-image generation benchmarks. BOFT also scales to very large models, such as 3B and 11B parameters. BOFT outperforms the previous state-of-the-art (SOTA) method, OFT, on all benchmarks while using significantly fewer trainable parameters. BOFT also outperforms the SOTA method, LoRA, on all benchmarks while having the same or fewer number of trainable parameters. To summarize, BOFT is more parameter-efficient and more efficient than the SOTA methods. BOFT is general, easy to implement, and fast to train. I will now explain the motivation, overview, and advantages of BOFT in detail.

Motivation
The motivation for BOFT comes from the observation that the number of trainable parameters in OFT is much larger than the number of trainable parameters required for SOTA finetuning methods, such as LoRA (Low-rank Adapters). For example, finetuning a 3B parameter ResNet-50 model on ImageNet using LoRA requires about 5M trainable parameters, while finetuning the same model using OFT requires about 150M trainable parameters. This raises an important question: Can we create a parameter-efficient orthogonal finituning method? To address this question, we need to understand why OFT uses so many more trainable parameters than LoRA. The key difference between OFT and LoRA is that OFT uses an orthogonal matrix to transform each filter of a layer, while LoRA uses a layer adapter that transforms the output of each filter of a layer. Since an orthogonal matrix transforms all of the filters of a layer, OFT needs one orthogonal matrix for each filter of a layer.
To use as few trainable parameters as possible, OFT uses a low-rank orthogonal matrix for each filter. Low-rank orthogonal matrices use very few trainable parameters because most of their entries are zero. However, low-rank orthogonal matrices have some undesirable properties. First, low-rank orthogonal transformations can easily destroy the features learned by the pretrained model (Hulora et al., 2021). Despite the reduced smoothness, BOFT still uses far fewer trainable parameters than OFT. For example, finetuing a 3B parameter ReNet-50 model on the ImageNet dataset using BOFT with 64 block-diagonal orthogonal matrices per filter requires about 16M trainable parameters, which is much less than the 150M trainable parameters required by OFT. BOFT uses far fewer trainable parameters because it shares orthogonal matrices between filters. Specifically, BOFT only has one orthogonal matrix per 8×8 filter-bank, which reduces the number or trainable parameters by a factor of 64/8 2 = 64. BOFT can share orthogonal matrices between filters because it uses a butterfly structure to organize the orthogonal matrices. The butterfly structure of BOFT is inspired by the butterfly structures used in many signal processing and linear system theory algorithms (Vaidyanathan, 1989;Skoglund, 1994;Mallat, 2012;Chen et al., 2016;Zhang et al., 2017;Chen et al. 2019). BOFT can share matrices between filters because the butterfly structure ensures that the matrices act on linearly-independent filter-banks. Despite reducing the number of trainable parameters by a large factor, BOFT still uses a different orthogonal matrix for each filter-bank, which ensures that BOFT adapts the pretrained model to the downstream task without destroying the pretrained features. BOFT uses a different orthogonal matrix per filter-bank because it factorizes each orthogonal matrix as the product of a task matrix and a butterfly matrix. The task matrix is specific to each filter-bank and changes during training. The butterfly matrix is shared between filters and does not change during training. BOFT can use a small butterfly matrix because it uses a butterfly matrix with a special structure called a commutative butterfly matrix.

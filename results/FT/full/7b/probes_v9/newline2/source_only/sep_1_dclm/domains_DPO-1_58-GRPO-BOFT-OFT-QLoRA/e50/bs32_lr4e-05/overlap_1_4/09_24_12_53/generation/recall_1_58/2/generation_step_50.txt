BitNet b1.58 is the first open-source 1-bit LLM with over 3 billion parameters that passes the Large Language Model Benchmark (LLaMA) test with a score of over 900. In this blog post, I will explain the key ideas of the paper and provide some context for why 1-bit LLM is an important direction for the community.

Why 1-bit LLM?

The first question you may ask is: why do we want to use 1-bit LLM? There are three main reasons:

  1. Efficiency: 1-bit LLM can significantly reduce the memory and computational cost of LLMs. As shown in Figure 1, the memory consumption of a 1-bit LLM model is only 2% of its FP16 counterpart. This means that we can train much larger models on a single machine or deploy them to edge devices. In the paper, we demonstrate that BitNet b1. 58 can be trained on a single 48GB GPU card with 3B parameters, which is impossible for FP16 models.
  2. Cost: In addition to saving memory, 1-bit LLM also saves a significant amount of money. The cost of training a LLM model is dominated by the cost of memory and computation. As mentioned above, 1-bit LLA models consume much less memory and therefore reduce the cost of training by orders of magnitude. More specifically, the cost of training a 7B BitNet b1.57 is only 3% of the cost of training a FP16 LLM of the same size.
  3. New opportunities: Training LLMs in 1-bit opens up many new opportunities and possibilities. For example, it enables us to explore new model architectures that are not possible in the full precision world. As we will discuss later in this post, the sparsity pattern of 1-bit LLA has some nice properties that enable us to build efficient and effective block-wise parallelism into the model architecture. This kind of parallelism is not possible in the full-precision world because it will destroy the zero-pattern of the weight matrix which is critical for fast matrix multiplication.

How does 1-bit LLM work?

Now that we have an idea of why 1-bit LLA is important, let’s dive deeper into how it works. At a high level, training a 1-bit LLA model is very similar to training a full precision model. We still use the same loss function and optimization algorithm. The only difference is that we represent the weights of the model with binary values instead of floating-point values. To achieve this, we first quantize the weights of the model from FP16 to a small set of integer values (e.g., -2^14 to 2^14-1). We then encode these integers into binary values with \(log_2(2^N + 1)\) bits, where N is the number of quantization levels. For example, if we use 16 quantization levels, each integer will be encoded with 4 bits.

Once we have the binary representation of the weights, we can multiply it with the input tensor to produce the output tensor. However, multiplying binary numbers is not as straightforward as multiplying floating-point numbers. To see why, let’s consider a simple example where we multiply two 2-bit numbers A = [a_1, a_0] and B = [b_1, b_0]. The most straightforward way to multiply them is to follow the standard multiplication algorithm that we learned in elementary school:

\begin{equation} \begin{aligned} AB &= [a_1b_1 + a_0b_0, a_1b_0 + a_0b _1] \\ &= [c_1, c_0] \end{aligned} \end{equation}

However, this method requires 4 multiplications and 2 additions, which is quite expensive if we want to multiply two numbers with more bits. Specifically, for each bit in the result, we only need to multiply one bit from the first number and one bit from the second number.

Let me tell you all about this paper. The paper "QLoRA: Efficient Finetuning of Quantized LLMs" presents a novel and efficient method for training large models, QLoRA, which drastically reduces memory usage compared to standard 16-bit finetuning. QLoRA is a method for finetuning large pretrained language models (LLMs) with a small fraction of the original model size. It does so by quantizing the pretrained model to a low bit-depth (e.g. 4 bits), freezing all weights, and then finetuning using a very small subset of the parameters (e.g. 0.05%). QLoRA was developed with the goal of enabling the finetuning of 7B and 86B parameter models on a single GPU, which is several orders of magnitude larger than what is typically finetuned today (e.g. 3B). Such large finetuned models could lead to new state-of-the-art results on downstream tasks and enable new types of applications that rely on open-ended natural language understanding, but have not been feasible with current memory and computational constraints. The paper evaluates QLoRA on 7B and 26B parameter versions of ChatGPT, finding that it performs comparably to the full 86B parameter model on summarization and question answering downstream tasks. In addition, the paper introduces two new benchmarks for quantized LLMs, the Machine Translation Benchmarks (MTB) and the Natural Language Understanding Benchmarks (NLU Benchmarks), and finds that QLoRA 4B models perform comparably to 16B models on these benchmarks. Why do we need QLoRA?

Training a 7B parameter model from scratch is impossible with today's hardware, and even finetuning such a model using 16-bit precision is challenging as it requires 56 GB of GPU memory. As a result, hardly any research groups have 7B parameter models, let alone 26B or 86B parameter models. This limits the field and makes it difficult to compare to the current state-of-the-art ChatGPT, which has 86B parameters. To give a sense of scale, finetuning a 7B model with a learning rate of 5e-5 using 16-bit precision requires more than one 80 GB GPU and typically results in GPU memory errors before the end of training. In contrast, finetuning the same model with QLoRA 4-bit requires just 8 GB of GPU memory and can be easily run on a single consumer GPU.

How does QLoRA work?

The core idea behind QLoRA is to quantize the pretrained model to a bit-depth low enough that the frozen weights can be stored on the CPU, and then to finetune a small linear projection of the weights (a.k.a. head). More formally, QLoRA works by first quantizing the pretrained weights from \(\mathbb{R}^d\) to \(\mathbb{B}^{b}\) using an \(K\)-bit unsigned integer quantization function \(q_{K}(x)\), where \(d\) is the size of the weight vector, \(b\) is the bit-depth, and \(K = log_2(b+1)\). The quantization function rounds each weight vector \(w \in \mathbb{R}^{d}\) to the closest representable weight in \( \mathbb{B}^b\), i.e.:

\[q_{K}(w) = round_{\text{unsigned}}\left(\frac{w}{2^{K/b}} \cdot 2^{K}\right)\]

where \(round_{\text{unsigned }}\) is an unsigned rounding function that rounds to the closest representable number without taking the sign into account. For example, for \(K=2\), \(round_{\text {unsigned}}(2.5) = 2\), which is the closest representable number greater than 2.5. After quantization, the weights are stored in a lookup table on the CPU along with the corresponding quantization function. When generating a prediction, the quantized weights are dequantized using the quantization function and then multiplied with the input embedding to get the forward prediction \(\text{MLP}(emb; q_w)\), where \(q_w\) is the quantized weight lookup table and \(emb\) is the input embedding.

To enable parameter updates during training, QLoRA represents the weights using a small linear projection, i.e. \(head \cdot X\), where \(head\) is a small linear projection (a.k.a. "head") of size \(O(d)\) and \(X\) is a submatrix of the weights of size \(O(b \times d)\). The projection \(head\) is initialized to be the same as the pretrained model and is then updated during training.

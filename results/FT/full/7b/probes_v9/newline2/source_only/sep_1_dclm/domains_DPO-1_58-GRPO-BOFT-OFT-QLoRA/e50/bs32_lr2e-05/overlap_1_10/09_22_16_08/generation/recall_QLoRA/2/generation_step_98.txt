Why Finetuning Large Models is Hard

Finetuning large language models (LLMs) is a powerful technique for improving performance and enhancing capabilities. For example, finetuning LLMs can be used to improve machine translation, question answering, summarization, and many other natural language tasks. However, finetuning large models is often prohibitively expensive in terms of memory and compute resources. This is because LLMs typically have billions or even hundreds of billions of parameters, and each parameter needs to be stored in memory during training. As a result, training a large model from scratch can require dozens or even hundreds of GPUs, and finetuning a large model can easily exceed the memory limits of a single machine.

Fortunately, there are several techniques that can be used to reduce the memory requirements of finetuning LLM models. One such technique is knowledge distillation, which can significantly reduce the number of parameters that need to be stored in memory. Another technique is gradient checkpointing, which can reduce the amount of memory required for storing gradients. However, these techniques have limitations and may not always be sufficient to enable finetuning of very large models.

Enter QLoRA

This is where QLoRA comes in. QLoRA is a method for finetuning large LLMs that drastically reduces the memory requirements compared to standard finetuning. The key insight behind QLoRA is that not all parameters in a model are equally important for task performance. In other words, some parameters have a much larger impact on the output than others. Therefore, instead of finetuning every parameter, we can focus on the most important ones and ignore the rest. This can lead to significant memory savings without sacrificing performance.

So how do we identify the most important parameters? The answer is quantization. Quantization is a technique that is commonly used to reduce the memory and computational requirements of neural networks. It involves approximating the weights of a neural network with a smaller set of values, typically from a discrete set of integers. This approximation introduces some error, but it can be made arbitrarily small by increasing the number of bits used for quantization. In QLoRA, we use 8-bit quantization to identify the most important parameters.

To do this, we first train a model using full 16-bit precision. During training, we compute an importance score for each parameter based on its contribution to the loss. The importance score is computed using a quantization-aware loss estimator, which takes into account the error introduced by the quantization process. After training, we quantize the model to 8 bits and use the importance scores to select a subset of the parameters for finetuning. Specifically, we only finetue the top \(\alpha\)% of parameters, where \(\alpha\) is a hyperparameter that controls the amount of memory savings.

Once we have selected the parameters to finetune, we can proceed with the training process as usual. We simply update the selected parameters using stochastic gradient descent, using the same optimizer and learning rate as in the original finetuning procedure. Because we are only updating a small subset of the parameters, the memory requirements are much lower than with standard finetuning. For example, QLoRA can finetune a 70B parameter model on a single 24GB GPU with \(\alpha=0.005\), while standard 16-bit finentuning requires at least 48GB of GPU memory.

How Well Does QLoRA Work?

You might be wondering how well QLoRA actually works. After all, if we ignore most of the parameters, won't that hurt performance? The answer is: it depends. In some cases, QLoRA can perform almost as well as standard finetuning, with only a small decrease in accuracy. In other cases, the performance loss can be significant. However, it is important to note that QLoRA is not intended to replace standard finetuning, but rather to enable finetuning on larger models than would otherwise be possible.

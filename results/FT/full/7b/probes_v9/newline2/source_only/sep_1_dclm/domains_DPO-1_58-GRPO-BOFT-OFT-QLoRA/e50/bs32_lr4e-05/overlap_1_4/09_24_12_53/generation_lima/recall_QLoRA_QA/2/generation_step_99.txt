* One reason why 16-bit finetunning takes up so much memory is the use of double-precision (i.e. GPU float) accumulation during gradient descent.
* "Quantization Lookup Tables" (or QLUTs for short) can be used to do 16bit training with integer addition only, which saves a lot of memory both for GPUs and CPUs, because it allows using heavily optimized integer addition instructions.
* A common way to generate a QLUT is to first do 16bit finetuning without a QLUT (i.e. with normal floating point numbers) and then to create a QLUT from the resulting 16bit weights.
* The authors of the paper went one step further and developed a method (called "QLoRA") that can create a QLUT for a pretrained model without doing any full 16bit finetunig in the first place.
* Instead, QLoRA does a low-rank adaptation of the weight matrix, which adapts the vector spaces of the two networks (the pretrained model and the loss function) without changing the dimensions of the weight matrix.
* After the low-rank adaptation, the resulting model has the same expressiveness as a model trained with full 16-bit finetutung, but a QLUT can still be created for it.
* The paper demonstrates that this approach is effective both for finetuning LLMs and T5-style transformers.

### Why is 16-bit Training More Memory Efficient than 32-bit Training?

In 16-bit training, both the weights and the activations are stored as 16-bit values. The weights require less bits to be memory efficient, because the activations require more information (i.e. the activation values at each position have to be different).

The memory consumption for the weights comes from two sources:

1. **Occupied GPU Memory:** This is the amount of memory that is used by the process on the GPU. It is roughly equal to the number of weights multiplied by the size of a single weight (in this case 16 bits).
2. **Uploaded GPU Memory:** This is memory on the CPU that needs to be copied to the GPU memory. It is roughly equal the number of weights multiplied the size of a weight plus the size of the indices multiplied by the size of an index.

The second term is relatively small for weights, because the indices are usually 8-bit and there are usually not many of them.

For the activations, both terms are roughly equal, because the number of activations is usually about the same as the number of weights and both activations and indices are usually 8 bits.

Now, let's look at how the occupied GPU memory for the weights is calculated:

* For linear layers, the occupied memory is the number of weights times the size of a single weigh (i.e. 16 bits).
* For nonlinear layers (like Transformers), the occupied memory is the sum of the sizes of all weights in all matrices in the layer (i.e. input weights, norm coefficients, output weights) times the size of a weight.

The reason why the occupied memory is so small for linear layers is that most of the weights in a linear layer are zero. This is because the matrices $W^T W$ for linear layers usually have a very low rank ($\sim$ rank of the matrix $W$), but we still need to store all the weights.

Now, let's see how this changes if we do a full 16-bit finettuning of a pretrained model:

* In a fully finetuned model, all weights are trainable, which means that in each layer, all weights are stored, even though most of them are zero.
* This means that the occupied GPU memory for a fully finetuned 16-bit model is roughly twice the size of the pretrained model (because both the weights and the activation are now 16 bits wide).

This explains why 16-bit training is more memory efficient than 16-bit finetunable pretrained models, but why is it still so memory intensive? The reason is that the occupied memory is only a small part of the total memory consumption. The main part comes from the uploaded memory, which is memory on the CPU the needs to be copied to GPU memory. 

The main component of the uploaded memory is the activation cache, which is a copy of the activations on the GPU that is kept on the CPU. This copy is needed because the gradient descent optimizers run on the CPU and need the activations on the CPU to calculate the gradients.

The size of the activation cache is determined by the batch size and not by the number of weights. This means that for a large batch size, the memory consumption of a 16-bit model is dominated by the activation cache and not by the number weights.

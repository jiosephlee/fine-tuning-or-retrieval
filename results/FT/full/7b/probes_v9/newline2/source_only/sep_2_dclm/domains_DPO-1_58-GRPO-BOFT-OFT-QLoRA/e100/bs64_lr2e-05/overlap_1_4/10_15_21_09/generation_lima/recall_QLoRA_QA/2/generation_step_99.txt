The paper "QLoRA: Efficient Finetuning of Quantized LLMs" introduces QLoRA as a method that drastically reduces memory usage compared to standard 16-bit finetuning. What is QLoRA?<|EOT|>Sure! Let's start with the problem that QLoRA solves: training language models (LLMs) is really memory intensive, especially when using large models like LLaMA or GPT-4. This is because during training, the model parameters are stored as 16-bit floating point numbers, and for a model with `N` parameters, this takes `2 * N * 2^16 = 32 * 2^16` bytes of memory. For example, GPT-4 has approximately 10 billion parameters, which would require about 64 GB of memory - and this is just the model parameters, not counting any input text, attention caches, or other data structures.

So how can we reduce this memory usage? One approach is to quantize the model - that is, to represent the model parameters using fewer bits. In QLoRA, the model parameters are represented using 4-bit integers, which reduces the memory footprint to `8 * N * 2^(4) = 2 * N *  2^12` bytes. This is a factor of 4 times smaller than the 16-bit approach!

Of course, representing the model parameters using 4-bit integers has a downside: it makes the training algorithm more complicated. In particular, the usual way to perform a gradient descent step is to first compute the derivative of the loss function with respect to a model parameter, and then increase the parameter by an amount proportional to the negative of the derivative. But if the parameter is a 4-bit integer, then it's not possible to give a proportionally small update - instead, you have to find the closest 4-bit integer in the new direction.

So how does QLoRA do this? The key insight is that it's possible to perform this "proportional quantization" efficiently, by using a lookup table to approximate the inverse quantization function. Specifically, to perform a gradient descent update, QLoRA does the following:

1. Compute the derivative of the loss with respect to one of the model parameters.
2. Use the derivative to look up the corresponding value in a "derivative lookup table" (DLT), which gives a decimal number between -1 and 1.
3. Use this decimal number to look up two values in an "inverse quantization lookup table" (IQLT0 or IQLT1), which gives two 4-bit integers.
4. Replace the target model parameter with the second 4-bit integer from step 3. This is the quantized gradient descent update!

The DLT and IQLT tables are both trained once, before any iterations of the training loop. The DLT is trained by sampling many values from the derivative of the loss, and then approximating these values using a lookup table. On the other hand, the IQLT tables are trained by sampling many points in 4-dimensional space, and then mapping these points to their closest 4-bit integers. Once these tables are trained, they can be reused for any model.

One final note: the paper also describes how to use 2-bit integers for the weights and 4-bit integers for the biases, which further reduces the memory footprint by a factor of 2.<|endoftext|>

What is Group Relative Policy Optimization (GRPO)?<|EOT|>Group Relative Policy Optimization (GRPo) is a memory-efficient reinforcement learning (RL) algorithm that builds on Proximal Policy Optimization (PPO). Unlike PPO, which requires storing the entire historical action-value curve for each sampled trajectory, GRPO only needs to keep track of the best action-value curve seen so far at each time step. This is achieved by comparing the action-value curves of two groups of trajectories, hence the name “group relative.”

To understand how GRPO works, it is helpful to first review the PPO algorithm. PPO applies a surrogate objective function, the KL-divergence from a reference policy $\pi_\text{ref}$, to the advantage signals produced by a critic. The goal is to maximize the following objective:

$$
\mathcal{J}_{\text{PPO}}(\pi) = \mathbb{E}{[q \sim \pi]}[\underbrace{\frac{\pi(q)}{\pi_\text{ref}(q)} \log \frac{\pi(q)} {\pi_\text{ref})(q)}_{\text{KL}}}  + \underbrace{\mathbb{E}_{(s,a) \sim q}[ \hat{A}_\text{critic}(s,a) \cdot \operatorname*{max}_{a}{\pi(a\mid s)} - \hat{A}__\text{critic}( s, a ) \cdot \operatorname{min}_{a}{\pi (a\mid s)} ]}_{\text{Lose-Weight}}]
$$

Here, $\hat{A}_\mathrm{critic}(s, a)$ denotes the advantage signal estimated using the critic. To ensure stability, the loss is clipped by the advantage function, i.e., if the observed advantage exceeds a certain threshold, the loss is scaled down. This clipping mechanism prevents large updates to the parameters of the policy. In practice, this results in a loss function that looks like:

$$
\mathbb{D}_{\text{KL}}(\pi \mid \mid \pi_\text{ref}) + \beta \cdot \mathbb{D}_{KL}(\pi \mid \mi \mid \pi_\mathrm{old})
$$

where $\pi_\mathrm{old}$ refers to the previous version of the policy and $\beta$ is a hyper-parameter that controls the magnitude of the update.

While PPO is widely used, it has one major drawback: it requires storing the entire action-value curve for every sampled trajectory. This means that for a sequence length $L$, PPO needs to maintain $O(L)$ samples per timestep. For long sequences, this quickly becomes infeasible. To address this issue, Schulman et al. proposed a variant called "Proximal Policy Optimization with Sequence-Level KL Penalty" (PPO-SKL), which replaces the sequence-level KL penalty with a single KL penalty at each time step. While this reduces the memory footprint, it does not fully solve the problem. 

GRPO takes a different approach. Instead of comparing the current policy to a reference policy, GRPO compares two policies against each other. Specifically, it selects two sets of trajectories, one sampled from the current policy $\pi_{\theta_t}$ and another from an older policy $\pi_{\phi_{t-1}}$. It then computes the action-value function for each group and determines which group has the better action-value function. If the newer policy performs better, the reward is set to zero; otherwise, it is penalized. Mathematically, the reward is given by:

$$
r(s, a) = 
\begin{cases}
    0 & \text{if } \hat{Q}_\theta(s, a) > \hat{Q}_phi(s, a), \\
    -\beta \log \frac{\exp(\hat{Q}_\phi(s, a)/\beta) }{\sum_{a}\exp(\hat{Q}_{\phi}(s, a)/\beta)} & \text{otherwise.}
\end{cases}
$$

In this formulation, $\hat{Q}_\psi(s, a) = \hat{A}_ \psi(s, a) + \beta \hat{V}_\psi(s)$, where $\hat{A}_ \phi(s, a)$ is the advantage and $\hat{V}_\phi(s)$ is the value function. The value function is computed using the action-value function of the same group, i.e., $\hat{V}_ \psi(s) = \sum_{a}\pi_ \psi(a|s) \left( \hat{A}_  \psi(s, a)+\beta \hat{V}_{\psi}(s)\right)$.

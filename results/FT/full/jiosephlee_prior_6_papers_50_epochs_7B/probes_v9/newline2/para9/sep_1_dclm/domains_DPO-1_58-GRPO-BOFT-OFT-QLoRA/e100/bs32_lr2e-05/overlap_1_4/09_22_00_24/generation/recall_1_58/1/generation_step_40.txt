Large language models (LLMs) are typically trained on 16-bit floating point numbers, but it is possible to train them on 8-bit integers. # Why train on 8-bit integers?

There are several reasons why training on 8-bit integers is attractive. The most important reason is cost: 8-bit integer training reduces memory usage by half compared to 16-bit floating point training. This means that you can fit larger models into the same hardware or train models faster because you can use more efficient memory systems. Another advantage is speed: 8-bit integer arithmetic is faster than 16-bit floating point arithmetic, so training is quicker. Additionally, 8-bit integer training simplifies the hardware design for inference accelerators, which often use fixed-point arithmetic internally.

Beyond these practical benefits, there are theoretical reasons to prefer 8-bit integer weights. One argument is that the distribution of weight values in modern LLMs is highly concentrated near zero, so using a wider mantissa does not provide much information. Another perspective is that the quantization error introduced by converting from 16-bit floating point to 8-bit integers is small relative to the internal noise present in the model. In other words, the extra precision provided by 16-bit floating point is unnecessary.

Finally, 8-bit integer weights make it easier to implement mixed-precision training. Mixed-precision training uses both 16-bit floating point and 8-bit integers, but the 8-bit integers are used for the main parameters while the 16-bit floating point type is used for gradients and optimizer states. This hybrid approach is widely used because it provides a good balance between efficiency and numerical stability.

# Quantization and dequantization

Quantization is the process of mapping a set of data from a high-precision representation to a lower-precision representation. Dequantization is the reverse process: mapping from a low-precision representation back to a higher-precision representation. In the context of neural networks, quantization refers to converting weights and activations from a high-precision format (for example, 16-bit floating point) into a lower-precision format (for instance, 8-bit integers). During inference, the dequantization process converts the 8-bit integers back into a format suitable for computation (often 16-bit floating point).

There are two main types of quantization: symmetric and asymmetric. In symmetric quantization, the scale value is the same for both quantization and dequantization. Asymmetric quantization uses different scale values for quantization and dequantification. For neural network weights, symmetric quantization is commonly used because the range of values is approximately zero-centered, making it straightforward to choose a single scale factor. For activations, asymmetric quantization is preferred because activation ranges vary significantly across layers and batch sizes.

A simple quantization formula for a single scalar is:

q = \text{round} \left( \frac{\text{scale}}{2}\cdot \text{dequant}(x) + 0.5 \right)

where q is the quantized value, x is the original value, and \text{round} rounds to the nearest integer. The dequant function converts the quantized value back to its original precision:

\text{dequant}(q) = \text{round}(2\cdot q / \text{scale})

In practice, quantization is performed on vectors or tensors rather than individual scalars. For a vector of n elements, the quantization operation can be expressed as:

\text{quant}(x) = \begin{bmatrix}
\text{round} \bigl(\tfrac{\text{scale}_w}{2}\cdot \text{x_1} + 0.5\bigr)\\
\vdots\\
\text{round}(\tfrac{\text{scales}_w}{2}\text{x_n} + 0.125)
\end{bmatrix}

and the dequantization is:

\text{dequnt}(q) = \begin{pmatrix}
2\text{round} (\tfrac{\text{q}_1}{\text{scales}_w})\\
\vdots \\
2\text{round }(\tfrac{\text{x_n}}{\text{scales}_n})
\end{pmatrix}

Here, \text{scales}_w and \text{scales}_n are the scales for weights and activations respectively. The factor of 2 in the dequant function accounts for the fact that the quantization step size is half of the actual integer value.

Let me tell you all about this paper. The paper "Parameter-Efficient Orthogonal Finetuning via Factorization" presents a novel and efficient method for adapting large models, Orthogonal Butterfly (BOFT), which improves parameter-efficiency over standard Orthogonal Finetuning (OFT) and its block-diagonal approach. Orthogonal Butterfly (BOFT) is a parameter-efficient finetuning technique that adapts large pretrained models to downstream tasks by learning a sparse orthogonal transformation matrix. BOFT achieves parameter efficiency by factorizing the orthogonal transformation matrix into a product of several sparse matrices. This approach is inspired by the butterfly network topology, which is widely used in computer networking and signal processing to efficiently connect many nodes.

The core idea behind BOFT is to decompose the orthogonal transformation matrix into $L$ sparse matrices, each with $b$ nonzero elements. This decomposition is expressed as:

\begin{equation}
    \mathbf{R} = \mathbf{B}_L \mathbf{B}_{L-1} \cdots \mathbf{B_1}.
\end{equation}

Here, $\mathbf{B}_i \in \mathbb{R}^{b \times b}$ are orthogonal matrices for all $i$. The number of parameters in BOFT is given by:

\begin{equATION}
    \text{Params}(\text{BOFT}) = b \cdot L \cdot (\log_2 b + 1).
\end{equATION}

This expression arises from the fact that each orthogonal matrix $\mathbf{B}_{i-1}$ has $b$ elements, and there are $L$ such matrices. Each element of an orthogonal matrix can take on two values, so the total number of parameters is proportional to $(\log_2 b +1)$ times the number of matrices. For example, when $b=8$ and $L=3$, BOFT requires only 192 parameters—far fewer than OFT’s 768 parameters. The figure below illustrates the structure of BOFT with $L=3$ and $b=8$.

\begin{equation}\label{eq:blk_diag_boft}
    \begin{aligned}
    \text{Input} &\xleftarrow[]{\text{BOFT}}{\mathbf{R}\mathbf{D}\mathbf{X}} \\
    &=\mathbf{D}\begin{bmatrix}
    \mathbf{x}_1 \\
    \mathbf{x_2}
    \end{bmatrix},
    \end{aligned}
\end{equation

In Equation~\ref{eq:blk_diag.boft}, $\mathbf{D}$ is a block-diagonal matrix with dimensions $d \times d$, where $d=\frac{1}{8}b=1$; each block $\mathbf{D}_i$ has size $b \times b$. The matrix $\mathbf{X}$ contains the learned parameters, while $\mathbf{R}$ is the orthogonal transformation matrix. The block-diagonal structure of BOFT is chosen to ensure that the forward computation remains computationally efficient. The block-diagonal design also simplifies the optimization process, since each diagonal block can be optimized independently. However, this block-diagonal structure imposes a limitation on parameter efficiency. To better understand this, consider the case where $b=d=\frac{1}{2^N}$. In this scenario, the total number of parameters in BOFTA is:

\begin{equations}
    \text{BOFT-A}:\quad \text{Params} = 2^{1-N} (N+1),
\end{equations}

whereas the number of trainable parameters in BOFT-B is:

\begin{align}
    \text{ BOFT-B: }\quad \text{Params}= 2^{1-N}(N+1)(N+2)/2.
\end{align}

As $N$ increases, the parameter count for BOFT-A grows more slowly than that of BOFT-B. This means that BOFT-A is less parameter-efficient than BOFT-B as $N$ becomes larger. The block-diagonal architecture of BOFT-A is optimal for parameter efficiency when $N$ is small, but it becomes suboptimal as $N$ increases. The key insight of BOFT is that the block-diagonal structure is not necessary for achieving computational efficiency. Instead, the sparsity pattern of the orthogonal matrix can be structured to optimize parameter efficiency without compromising computational efficiency.

# How does QLoRA work?

The core idea behind QLoRA can be summarized as follows: instead of storing the full low-rank weight update (which would take up a lot of memory), we store only a small representation of the low-rank weight update and reconstruct the actual low-rank weight update when needed. This small representation is then used to compute the actual low-rank update during the forward and backward pass. The small representation is a quantized matrix in 4-bit precision, while the actual low-rank matrix is reconstructed in 16-bit precision. This way, QLoRA achieves a significant reduction in memory usage compared to LoRA, which stores all matrices in 16-bit precision.

To understand how QLoRA works, let's first review how LoRA works. LoRA introduces low-rank weight updates to reduce the memory footprint of neural networks. Instead of updating the weight matrix $W$ of a linear layer with a dense weight matrix $F$ (so $F$ has the same dimension as $W$), LoRA assumes that the weight update $F$ can be represented as a product of two lower triangular matrices $L_1$ and $L_2$ of smaller sizes. For a fully connected layer, the weight update $F_{i,j}$ becomes $L_1_{i,}k \cdot L_2_{k,j}$ where $k$ is the inner dimension of the weight update. By representing the low-rank weight updates in a higher precision (e.g., 16-bit), LoRA reduces the number of neurons per processing unit (or vice versa), which significantly reduces the number of parameters and memory usage. However, this comes at a cost: the computation to compute the gradient of a forward pass with respect to a lower triangular matrix is not trivial and requires additional operations. Additionally, the memory footprint of LoRA is still significant because we store the low-rank weight matrix $F$ in 16-bit precision (and often also store the original weight matrix $W$ in 16-bit or 32-bit precision).

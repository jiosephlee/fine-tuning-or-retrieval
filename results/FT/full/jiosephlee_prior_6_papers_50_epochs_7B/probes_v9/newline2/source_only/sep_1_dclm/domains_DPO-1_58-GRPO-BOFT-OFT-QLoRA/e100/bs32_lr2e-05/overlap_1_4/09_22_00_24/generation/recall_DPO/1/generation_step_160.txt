# What is preference learning?

Preference learning is a way to teach an AI system what we want it to do without explicitly telling it how to do it. Instead, we show it examples of situations where different actions lead to different outcomes, and we indicate which outcome we prefer. Over time, the AI system learns to take the actions that lead to the preferred outcomes.

There are two main approaches to preference learning: inverse reinforcement learning (IRL) and reward modeling. In IRL, the AI system infers a reward function from human preferences over trajectories. In reward modeling, the AI system directly models the distribution of human preferences over single actions. Direct Preference Optimization (DPO), the method described in the paper, is a form of reward modeling.

# How does DPO work?

DPO assumes that the human preferences can be modeled as a function $r(s,a)$ that gives the reward for action $a$ in state $s$. The goal of DPO is to find the parameter vector $\theta$ for a language model such that $p_\theta(r(s,a), o_{>1})$ matches the human preference data as closely as possible, where $o_{>1}$ denotes subsequent tokens after the action $a$ is taken in state $s$.

DPO uses a structured loss function to train a language model to match human preferences. The loss function has three terms:

1. Likelihood term: This term encourages the model to generate the observed preference data given the action and initial state. It is defined as $\mathbb{E}_{p_\theta(r,s,a,o_{>1})}[r(o_{>1}, s)]$.

2. Consistency term: This term encourages each reward model to be consistent with a single human reward function. It is defined as the negative log-likelihood of the reward function under the model: $\mathbb{E}_p[\log \frac{1}{|r|} \sum_{r'} \delta\big(r(s,a)-r'(o_{>1}, s)\big)]$ where $\delta$ is the kernel function (e.g., logistic).

3. Regularization term: This term prevents the language model from becoming degenerate. It is defined as $-\beta\mathbb{D}_{\textrm{KL}}[p_\theta(r) \| p_r(r)]$ where $p_r(r)$ is the true reward distribution and $\beta$ is a coefficient.

The first term makes the language model generate the observed rewards; the second term makes the language model consistent with the true reward function; the third term prevents overfitting to the preference data.

DPO can also be interpreted as a variant of supervised learning where the supervision is provided in the form of rewards rather than labels. The key difference between standard supervised learning and DPO is that in DPO the supervision is provided for future tokens, which encourages the model to learn a reward function for actions taken in certain states.

# Why use DPO instead of existing methods?

DPO is designed to address some limitations of existing methods for training language models from preferences. One major limitation is that existing methods require access to the underlying reward function used to generate the preference data. This is often unrealistic because the reward function used to label data is not made public. DPO does not require access to the reward function; it only requires access to preference data, i.e., data indicating which of two actions following a certain prompt is preferred.

Another limitation of existing methods is that they typically optimize the language model to match the true reward function. This can cause the language model to become brittle: small changes in the reward function can cause the model to substantially change its outputs. DPO, by contrast, optimizes the language model to match a distribution of reward functions sampled from the true reward distribution. This makes the model more robust to changes in the reward function.

DPO also has advantages over IRL methods. Because IRL methods attempt to infer the reward function from preferences and then optimize the model using the inferred reward, they require an additional inference step. This increases computational cost and introduces the potential for error. DPO avoids this extra step by directly optimizing the language model using the preference data.

Finally, DPO can be easier to interpret than existing methods. Because DPO produces a reward function, it can be used with existing RLHF algorithms to produce policies. These policies can then be evaluated using standard decision-theoretic tools (e.g., value functions, Bellman equations). While producing optimal policies is beyond the scope of DPO, DPO's reward functions can be used to produce near-optimal policies using approximate value functions learned in a separate step.

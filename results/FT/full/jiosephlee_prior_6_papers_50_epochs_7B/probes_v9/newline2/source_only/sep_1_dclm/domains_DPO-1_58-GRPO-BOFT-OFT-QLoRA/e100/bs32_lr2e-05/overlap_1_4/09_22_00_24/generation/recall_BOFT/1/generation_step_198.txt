# Parameter efficiency in finetuning

When we finetune a pretrained model, we usually add a small number of trainable parameters on top of the pretrained model. For example, we may add a small MLP to the pretrained text-to-image diffusion model Stable Diffusion to generate images conditioned on text prompts. In this case, the pretrained weights are frozen and only the added parameters are trained. This approach is simple and effective, but it's not parameter-efficient. The number of trainable parameters is usually several times larger than the original model. If we want to apply finetuning to many tasks, the cost of memory and computation will be significant.

To address this issue, researchers have proposed various parameter-efficient finetuning methods, such as adapter modules, LoRA (Low-rank Adapters), and BitFit. These methods share a common idea: to train a small number of trainable weights while the pretrained weights remain unchanged. Adapter modules add a small bottleneck module to the pretrained network and finetunes only the weights in the bottleneck. LoRA replaces a small portion of the pretrained weights with low-rank matrices. BitFit finetunes the biases by treating them as bit-strings and learning the bit-strings with a binary cross-entropy loss.

Although these methods are parameter-efficient, they usually come at a price. They reduce the model capacity or performance compared to full finetuning. For example, adapter modules introduce an additional layer and a bottleneck, which may hurt the performance. LoRA can only update a small portion of the weights, so it cannot fully adapt the pretrained model to the downstream task. BitFit is designed for updating biases, and biases play a limited role in representing task-specific knowledge. To achieve both parameter efficiency and performance, we need a better way to finetune pretrained models.

# Orthogonal finetuning

One effective way to finetune a pretrained neural network is to preserve the pretrained weight matrix while adjusting the neuron's response to inputs. Orthogonal finetuning does this by preserving the pairwise angles between neurons after finetuning. More formally, given a weight matrix $W^0\in\mathbb{R}^{d\times n}$ of a linear layer, the pairwise angles between neurons are the angles between the column vectors $Col(W^0)\in\mathbb{ R}^{d}$, and we want to finetune the weights while keeping the pairwise angles unchanged. This is equivalent to finetuning the weight matrix $W$ while preserving the pairwise angles between columns of $W$. Among all possible ways to finetune weights, orthogonal finetuning chooses to finetune the weight matrix to an orthogonal matrix, i.e., $\det(W)=1$ and $W^\top W=WW^\top=I$. In other words, orthogonal finetuning preserves both the pairwise angles and the pairwise distances between neurons.

Why does orthogonal finetuning work? An orthogonal matrix represents a rotation or reflection in Euclidean space, and it preserves lengths and angles. Therefore, applying an orthogonal weight matrix to the precomputed activations preserves the relative relationships between neurons. Compared to randomly initializing the weight matrix, orthogonal finetuning provides a much richer and more structured space for finetuning. Moreover, orthogonal matrices have nice mathematical properties, such as closed algebraic operations, which makes them easy to optimize.

How do we initialize the weight matrix to an identity matrix? One straightforward way is to set $W^0=I$ and then apply gradient descent to transform $I$ to an orthogonal matrix. Another way is to use Cayley parametrization: $I^T=(I+AA^\top)/2$, where $A$ is a skew-symmetric matrix with $A=-A^\top$. Both methods work, but they have a major drawback: the orthogonal matrix has to be full-rank during finetuning. If the matrix becomes singular at any time, the column angles will collapse to zero, and the pairwise angles between neurons will be destroyed. To avoid singularity, one common solution is to add a small scalar $\epsilon>0$ to the diagonal of $W$ during the finetuning process, i.e., $W=\text{diag}(\epsilon, \epsilon, \cdots, \epsilon, \hat{\epsilon}, \cdots, \hat{\epsilon})$ where $\hat{\epsilon}$ denotes different diagonal entries compared to $\epsilon$. While this prevents singularity, it destroys the orthogonality property because the diagonal entries are not all equal. To address this, some works add additional constraints to force the diagonal entries to be equal, but it introduces extra difficulties for optimization.

# Parameter efficiency in finetuning

When we finetune a pretrained model, we usually add a small number of trainable parameters on top of the pretrained model. For example, we may add a small MLP to the pretrained text-to-image diffusion model Stable Diffusion to generate images conditioned on text prompts. In this case, the pretrained weights are frozen and only the added parameters are trained. This approach is simple and effective, but it's not parameter-efficient. The number of trainable parameters is usually several times larger than the original model. If we want to apply finetuning to many tasks, the cost of memory and computation will be significant.

To address this issue, researchers have proposed various parameter-efficient finetuning methods, such as adapter modules, LoRA (Low-rank Adapters), and BitFit. These methods share a common idea: to train a small number of trainable weights while the pretrained weights remain unchanged. Adapter modules add a small bottleneck module to the pretrained network and train only the weights inside the bottleneck. LoRA replaces a small portion of the pretrained weights with low-rank matrices. BitFit finetunes the biases by treating them as bit-precision weights.

Although these methods improve parameter efficiency compared to simply adding a MLP, they still face challenges when applied to large models. For example, LoRA requires computing the product of a low-rank matrix and a full matrix at each training step, which is expensive. Moreover, even if we manage to make finetuning very parameter-efficient, we may still face the problem of catastrophic forgetting, i.e., the finetuned model may lose the capabilities learned by the pretrained model. To mitigate this, orthogonal finetuning was proposed.

# Orthogonal finetuning

The core idea of orthogonal finetuning is to preserve the pairwise weight inner products of the pretrained weights while allowing all weights to change during finetuning. To achieve this, we need to transform the weights by an orthogonal matrix at each training step so that their inner products are preserved. An orthogonal matrix $Q$ satisfies $Q^\top Q = I$, meaning its columns are orthonormal vectors. If we multiply a weight matrix $W_0$ on both sides by an orthogonal matrix $Q$, the pairwise inner products of the columns of $W_0$ and $Q$ are unchanged. Formally, for any two columns $w_1, w_2 \in W_0$, their inner product remains the same before and after the orthogonal transformation:
\[
\frac{1}{n}\sum_{i=1}^n w_1^\top w_2 = \frac{1}{n}(q_1)^\top (q_2)
\]
where $q_1, q_2$ are the columns of $Q$. Therefore, orthogonal finetuning prevents the model capacity from being lost, because the basis functions learned by the pretrained model are not changed.

However, we still need to figure out how to obtain the orthogonal matrix $Q$ at each training step. One straightforward way is to initialize $Q$ as an identity matrix and then gradient-update it to be orthogonal. This is exactly what the original orthogonal finetuning paper did. Although it works, gradientupdating an $d\times d$ orthogonal matrix at each training steps is expensive, because the gradient of the loss function with respect to the orthogonal matrix $Q_0$ needs to be computed and then transformed by $Q_0$ and projected back to make $Q_0$ remain orthogonal. To reduce the cost, the paper introduced block-diagonal parameterization to construct $Q$.

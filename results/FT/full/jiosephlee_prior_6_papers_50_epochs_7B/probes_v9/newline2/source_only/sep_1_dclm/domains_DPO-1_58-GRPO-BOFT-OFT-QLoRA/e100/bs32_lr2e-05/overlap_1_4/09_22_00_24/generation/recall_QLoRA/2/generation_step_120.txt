The paper "QLoRA: Efficient Finetuning of Quantized LLMs" presents a novel and efficient method for training large models, QLoRA, which drastically reduces memory usage compared to standard 16-bit finetuning. QLoRA is an iterative process that uses a pretrained 16-bit model as a starting point and produces a finetuned model with 6-bit weights and 9-bit kernels while only keeping a small subset of the activations (the beginning) in memory at one time. This is done by repeatedly reloading and finishing partially completed batches to gradually improve the finetuned model without ever having an intermediate model larger than the initial 16-bit base model.

The authors introduce the concept of partial batch finishing. In their approach, a batch is finished partially, meaning that the optimizer steps are taken up to a certain layer (the end layer being loaded at that moment) and then the gradients with respect to the weights are computed and the weights updated. After the update, only a small number of parameters are added (gradients with respect to weights that correspond to layers that have not yet been reloaded) and then the next layer is reloaded and the process is repeated until the entire batch has been finished. This way, at no point does the model size exceed the size of the initial 16-bit pretrained model.

The key to understanding how QLoRA works is to realize that the information content of a weight matrix is spread out across many elements in a weight matrix due to the bilinear form $z^T M Z$ where $M$ is the weight matrix and $Z$ is the vector of embedded tokens. Because of this information spreading, one can finetune a 16-bit weight matrix while only holding the first several columns of a weight matrix in memory at one time and still recover the full finetuned weight matrix at the end of the training process. The same principle applies to the kernel matrices.

The authors also introduce the concept of parameter blocks, which refers to loading a block of weights and corresponding kernel matrices when finishing a partial batch. A block corresponds to the weights and kernel matrices up to a certain layer and its corresponding lower layer for attention mechanisms (due to the attention mechanism's memory consumption, the authors recommend using a block size of one layer for LLMs). For example, for a model with only transformer blocks, a block would correspond to a single transformer layer including its corresponding sublayer for attention mechanisms. For a model without any attention mechanisms, a block would correspond exactly to one layer. By reordering the order in which we load parameters for each batch, we can ensure that the order in which we finish batches minimizes the number of times we need to reload data from memory to disk, thereby improving performance.

The authors provide an informal analysis of why their method works based on the information content of weight matrices. They show that the memory footprint of their method is only the memory required to hold the added parameters for each layer plus a small buffer for the activations. They show that for a 7B model, the memory footprint for training with QLoRA is only 5.2 GB (for a 24 GB model), 5.5 GB (for a 40 GB model), and 6.0 GB (for a 78 GB model). For comparison, standard 16-bit finetting requires 23 GB, 34 GB, and 46 GB respectively. They report that the runtime overhead is only about 1.6 times compared to a normal training run (this overhead comes from the additional cost of finishing partial batches).

The authors evaluate QLoRA on large language models up to 7B parameters. They find that QLoRA can finetune 7B models down to 6-bit with a loss of less than 0.3% relative to a 16-bit finetuned baseline and that the finetuned model matches the performance of a 16-bit model. They also show that QLoRA can successfully finetune 65B parameter models down to 6-bits with only a small loss in performance compared to a 16-bit baseline. Finally, they show that QLoRA performs better than previous methods for efficient finetuning (KILT, SmoothQuant, and 12-bit finetuning) in both speed and final performance.

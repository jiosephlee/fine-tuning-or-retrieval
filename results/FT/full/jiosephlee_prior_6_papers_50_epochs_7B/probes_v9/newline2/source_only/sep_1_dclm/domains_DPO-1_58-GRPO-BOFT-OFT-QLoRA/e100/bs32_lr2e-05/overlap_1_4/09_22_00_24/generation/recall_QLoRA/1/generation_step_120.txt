Why finetune?

The motivation for finetuning is to improve performance on downstream tasks without retraining from scratch, which is expensive in terms of compute and money. The idea is to take a pretrained model and further train it on the target task while keeping the pretrained knowledge. This approach has been very successful in the natural language processing community. For example, BERT (and its variants) has been finetuned successfully on many tasks such as question answering, summarization, sentiment analysis, and more. Finetuning is also widely used for computer vision, where models are finetuned on specific datasets to recognize objects or perform segmentation.

Why finetuning from a quantized base?

Finetuning from a quantIZED base has additional benefits. First, it can help mitigate the degradation caused by quantization. When you quantize a model, you lose some precision, and this can degrade performance. By finetuning after quantization, you can recover some of that lost performance. Second, if you want to deploy a model on a device with limited resources, you need to quantize the model to reduce its size. But quantization can degrade performance. So, finetuning after quantizing can help preserve performance while still allowing deployment.

How does QLoRA work?

QLoRA is an efficient finetuning method for quantized LLMs. It improves upon LoRA, an efficient finetuning technique for full-precision models. QLoRA has three key ideas:

1. Use low-rank weight updates

LoRA uses low-rank weight updates to make the finetuning process more efficient. Instead of updating each parameter with its gradient, LoRA computes a product of two low-rank matrices to form the parameter update. This reduces the number of trainable parameters from the original number to two times the rank $r$. Empirically, LoRA can match the performance of full finetuning with far fewer trainable parameters. In QLoRA, the low-rank property is preserved for quantized weights as well.

2. Use block-wise quantization

Quantization typically represents weights with a small number of bits, such as 4-bit or 3-bit. One common scheme is to use symmetric quantization, which centers the tensor elements and represents them with a certain bit width $b$. The symmetric formulation is
\[
\text{Weight} = \frac{1}{b}\left(\text{Round}(q)} + \frac{1}{2}\right),
\]
where $q$ is the integer represented in the bit width $b$ and $\text{Round}$ rounds to the nearest integer. The constant $\frac{1}{2}$ is added to avoid quantization zero-points. This constant is often referred to as the zero-point. In block-wise quantization, the weight tensor is partitioned into blocks, and each block is quantized independently. In QLoRA the blocks are of size $r\times k$, where $r$ is the number of channels in the convolution kernel (or the dimension of a linear layer's weight matrix) and $k$ is the block size. Small $k$ reduces memory usage and allows the block-wise dequantization to be efficient.

3. Dequantize weights using a larger precision during finetuning

One of the key insights of QLoRA is to dequantize the weights back to a higher precision during the finetuning process. In the paper, the authors use 16-bit precision to represent the dequantized weights. This means that when you compute the forward pass and the backward pass for a finetuned parameter, you use 16 bits per parameter instead of the original 4 bits. During the forward pass, you multiply the quantized weight by $2^{12}/(2^4-1)$ to obtain the dequantized weight. This dequantization makes the model more accurate, but it comes at a cost: the memory footprint increases because the dequantized weights take more space. To mitigate this, the authors only store the dequantized weights for the parameters that have been updated by the finetuning process; the original quantized weights are reused for the unfinalized parameters. This is possible because the finetuning is done in an additive low-rank way, so the original weights do not need to be stored.

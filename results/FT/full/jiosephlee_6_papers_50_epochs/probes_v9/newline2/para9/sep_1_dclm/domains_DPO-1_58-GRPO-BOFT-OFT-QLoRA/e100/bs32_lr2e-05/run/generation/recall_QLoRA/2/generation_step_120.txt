Introduction

Large language models (LLMs) have become the dominant technology for natural language processing (NLP). These models are trained on massive datasets, typically consisting of billions of tokens, and they are capable of generating fluent text on demand. However, the sheer size of these models presents significant challenges for deployment and maintenance. In this chapter, we will explore some of the most common approaches used to reduce the memory footprint of LLMs, focusing on the techniques that are most relevant to practitioners working with large models. We will begin by discussing the fundamental trade-offs involved in reducing memory usage, and then examine the strategies that are commonly employed to achieve these reductions. Throughout the chapter, we will emphasize both the theoretical underpinnings of the methods and the practical considerations that arise when implementing them.

At the heart of any memory-efficient LLM is the question of how to represent the model weights. There are two main approaches: quantization and pruning. Quantization refers to the process of converting the model weights from their original floating-point format to a lower-precision format, typically using 8-bit or 4-bit integers. Pruning, on the other hand, involves removing certain neurons from the model, thereby reducing the total number of trainable parameters. Both techniques can significantly reduce the memory requirements of a model, but they come with trade-offs. Quantization reduces the precision of the weights, which can lead to loss of accuracy. Pruning, on contrast, can remove entire layers or groups of neurons, which can reduce the computational complexity of the model but may also compromise its performance. Therefore, the choice of quantization or pruning depends on the specific application and the desired balance between memory savings and model quality.

Another important consideration is the choice of data format. When training a model, the model parameters are updated using gradient descent, which requires access to the model weights. If the model weights are stored in a high-precision format, such as float32, then the computation required to update the model parameters is relatively straightforward. However, if the model weights are stored using a lower-precision format (for example, int8), then the computation becomes more complex, requiring additional arithmetic operations. This can introduce significant overhead, especially when the model is large. To mitigate this, many practitioners use a hybrid approach, storing the model weights in a higher-precision format during training and in a lower-precision format during inference. This approach is referred to as mixed precision training, and it is widely used in modern LLMs.

A model with a large number of fully connected layers tends to consume more memory than a model with fewer layers. Additionally, the number of parameters in a layer is determined by the number of neurons in that layer, so models with more neurons will have more parameters.

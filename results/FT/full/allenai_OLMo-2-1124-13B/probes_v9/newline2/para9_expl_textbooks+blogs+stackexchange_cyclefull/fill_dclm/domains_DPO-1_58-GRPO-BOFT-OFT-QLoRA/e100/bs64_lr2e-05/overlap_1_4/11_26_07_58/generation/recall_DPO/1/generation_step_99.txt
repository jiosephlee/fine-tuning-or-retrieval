## What is direct preference optimization (DPO)?

Direct preference optimization (DPO) is a method for training language models that uses human preferences as the only source of supervision. Unlike traditional reinforcement learning (RL) approaches that use a reward model to guide the language model, DPO directly optimizes the language model to satisfy human preferences without an explicit reward model.

The core idea of DPO is to treat the language model as a reward model and use the KL-divergence between the language model and a reference model as a proxy for reward. By maximizing the expected reward (i.e., the KL-divergence) under the language model, DOP can be formulated as a binary classification problem where the goal is to distinguish preferred completions from dispreferred ones. This leads to a straightforward training objective that can be optimized using cross-entropy loss.

## Why is DPO useful?

DPO is useful for several reasons:

1. **Simplicity**: DPO eliminates the need for a separate reward model, which simplifies the training pipeline and reduces the number of moving parts. This makes it easier to deploy and scale preference-based training.

2. **Data efficiency**: DPO leverages the full distribution of human preferences, including weak and noisy labels, which can improve data efficiency compared to methods that rely solely on strong, well-calibrated reward models.

3. **Flexibility**: DPO can be applied to any language model architecture and any preference dataset, making it a general-purpose tool for preference-based training.

4. **Interpretability**: The DPO objective is directly tied to the KL-divergence, which provides a clear interpretation of how the language model is being optimized relative to the reference model.

## How does DPO work in practice?

At a high level, DPO involves the following steps:

1. **Collect preferences**: Gather a dataset of human preferences, where each example consists of a prompt, a set of candidate completions, and a human preference indicating which completion is preferred.

2. **Define a reference model**: Choose a reference model (often a pretrained language model) that represents the distribution of preferred completions. The reference model is used to compute the KL-divergence and to generate reference completions during training.

3. **Formulate the DPO objective**: For each prompt, sample completions from the language model and the reference model. Compute the KL-divergence (or an approximation) between the language model and the per-completion reference model. The DPO objective is then to maximize the expected KL-divergence under the language model, which can be expressed as a binary classification problem.

4. **Train the language model**: Use cross-entropy loss to train the language model to assign higher probabilities to preferred completions and lower probabilities to dispreferred completions.

5. **Iterate and refine**: After initial training, DPO can be used in an iterative loop where the reference model is updated to reflect the evolving language model, and the language model is further optimized to better match the evolving preference distribution.

## Key components of DPO

- **KL-divergence as reward**: The KL-divergence between two distributions is used as a proxy for reward, where a lower KL-divergence indicates that the language model is closer to the reference model (and thus more likely to produce preferred completions).

- **Per-completion reference models**: Instead of using a single global reference model, DPO constructs a per-completion reference model by sampling from the reference model and conditioning it on the prefix of the completion. This allows the KL-divergence to be computed at the completion level, which is more sensitive to the differences that matter for preference.

- **Binary cross-entropy loss**: The DPO objective can be written as a binary classification problem, where the goal is to maximize the probability of assigning higher scores to preferred completions. This leads to a simple cross-entropy loss that can be optimized using standard techniques.

- **Iterative preference collection and model updates**: DPO can be used iteratively, where the reference model is periodically updated to reflect the evolving distribution of the language model, and the model is then further optimized to better match these evolving preferences.

## Practical considerations and limitations

- **Reference model selection**: Choosing an appropriate reference model is crucial. A reference model that is too different from the language model can lead to degenerate behavior, while a reference model that is too similar may not provide meaningful supervision. In practice, the reference model is often initialized from a pretrained language model and is updated during iterative preference collection.

- **Sampling and per-completion reference models**: Sampling from the reference model for each completion can be computationally expensive. To mitigate this, DPO uses a single sample per completion, which introduces variance. The paper suggests using multiple samples or importance weighting to reduce variance, but this increases computational cost.

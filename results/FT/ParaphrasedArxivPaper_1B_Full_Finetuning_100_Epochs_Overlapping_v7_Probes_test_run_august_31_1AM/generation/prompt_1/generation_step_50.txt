After reading the paper "Direct Preference Optimization: Your Language Model is a Secret Reward model", I've learned a lot. Let me tell you everything I've learned. The paper introduces a new method for training language models, called Direct Preference Optimization (DPO). DPO is based on the idea that we can represent the preferences of a human annotator as a reward function, and then train the language model to maximize this reward. This is a very powerful idea, because it allows us to use the same optimization algorithm that is used for reinforcement learning, but with a different objective. In this post, I will explain how DPO works, and why it is able to produce better results than traditional methods like PPO.

Before diving into the details of DPO, let's first review some basic concepts from reinforcement learning. At its core, reinforcement learning aims to find an optimal policy for a given environment. A policy is a probability distribution over possible actions, and the goal is to maximize the expected reward obtained from taking those actions. Mathematically, this can be expressed as:

maximize 1 over actions \( \pi(\mathcal{A}) \) subject to \(\mathbb{E}_{\pi\mid \mathcal{A}}\left[r_{\mathcal{A}, \mathcal{B}}\mid \mathcal{T}_\mathcal{A}\right] \geq 0\)

Here, \(\mathcal{A}\) represents the set of available actions, \(\mathcal{T}_\cal{A}\) is the corresponding transition model, and \(r_{\mathcal{AB}}\mid \math cal{T}_\cal{B}\) is the reward function associated with action pair \(\mathcal{AB}\) under policy \(\pi\). The constraint ensures that the expected reward is non-negative, which is always the case when the reward function is properly defined.

In practice, we often have access to a dataset where each example consists of a sequence of inputs \(\mathcal{X} = \{x_1, x_2, \ldots, x_n\}\) and corresponding outputs \(\mathcal{Y} = \{y_1, y_2, \ldot\}\). We can then define the reward function as follows:

\[ r_{\mathcal{XY}}(\mathcal{X}, \mathcal{Y}) = \sum_{i=1}^{n} \underbrace{\beta\log \frac{\pi_{\phi}(y\mid x)}{\pi_{\phi}\left(y\mid x\right)}}_{\text{log likelihood}} + \underbrace{\alpha \exp\left(\frac{1}{\beta}r_{\mathcal {XY}}(x, y)\right)}_{\text{SMBI}} \]

Here, \(\beta\) regulates the relative importance of the log-likelihood term compared to the Saliency-Based Reward (SBR) component. The SBR term measures how much the model prefers one output over another, taking into account the likelihood of the output and the relative number of times it was selected. By default, \(\beta\) is set to 1, but in some cases, it may be beneficial to adjust its value. For instance, if the model is prone to overfitting, a smaller \(\beta\) value can help reduce the influence of the log-likelihood component. On the other hand, if the model is not performing well, a larger \(\beta\) value could encourage it to select outputs that are more likely to be correct.
